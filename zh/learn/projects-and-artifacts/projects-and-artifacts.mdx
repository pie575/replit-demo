**项目**是你在 Replit 上构建的一切内容的容器。**构建产物**是其中可发布的成果，包括 web 应用、移动应用、幻灯片演示文稿、动画、数据可视化、3D 游戏和设计。

当你要构建多个内容时，有两种选择：在一个项目中添加多个构建产物，或创建多个独立项目。应如何选择，取决于你的应用是否共享数据、逻辑和部署生命周期。本页将深入介绍这两个术语，并说明何时应将构建产物保留在同一项目中，以及何时应创建独立项目。

<div id="whats-a-project">
  ## 什么是项目？
</div>

项目是存放代码、数据和所有构建产物的容器。当您告诉 Agent 您想要什么时，它会创建一个项目，并在其中构建这些产物。

您可以把项目想象成桌面上的一个工作区。所有内容都集中在一处，可以共享相同的信息，但每个部分都有不同的用途。

例如，如果您让 Agent 构建一款健身追踪移动应用，它会创建一个项目，其中包含移动应用构建产物，以及让它正常运行所需的后端、数据库和存储。

关键概念：

* **Project**：容纳所有内容的容器，包括您的代码、数据和所有构建产物。
* **构建产物**：项目中可发布的输出 (例如 Web 应用、幻灯片演示文稿、视频等) 。
* **资源**：每个构建产物都会自动获得后端、数据库和文件存储，无需进行任何设置。

如需了解项目支持的所有操作——管理、筛选、置顶和排序——请参阅 [Projects](/zh/features/projects-and-artifacts/projects)。

<div id="whats-an-artifact">
  ## 什么是构建产物？
</div>

构建产物是你可以在 Replit 上发布的内容。每个构建产物都是完整、独立的成品，发布后都会拥有专属的可分享 URL。

项目中的其他内容——文件、图片、CSV 和代码——都为构建产物提供支持，但无法单独发布。

<div id="what-artifacts-share-in-a-project">
  ## 构建产物在项目中共享的资源
</div>

当 [构建产物](/zh/features/projects-and-artifacts/artifacts) 位于同一[项目](/zh/features/projects-and-artifacts/projects)中时，它们会自动共享：

* **数据库**：一个构建产物写入数据后，其他构建产物可立即读取。
* **后端和 API**：共享服务器端逻辑，无需重复编写代码。
* **文件存储**：可跨构建产物访问图片、文档和已上传的文件。
* **部署**：Publishing 会将所有内容同步发布上线。

这意味着你无需在构建产物之间配置连接，也无需重复编写代码。但这也意味着，你无法在不发布其他构建产物的情况下单独发布某个构建产物。

<div id="quick-guide">
  ## 快速指南
</div>

决定是向现有项目添加构建产物，还是创建单独项目时，可参考以下关键场景。

| **在同一项目中使用多个构建产物**        | **使用单独的项目**          |
| ------------------------- | -------------------- |
| App 共享相同的数据和后端            | App 不共享底层逻辑或数据       |
| 你希望所有内容一起发布               | 你需要独立的发布周期           |
| 它们相互配套 (例如客户 App 和管理仪表板)  | 它们是彼此无关的产品，或面向不同客户   |
| 你希望一个构建产物中的更改自动同步到其他构建产物  | 项目是短期项目，例如营销落地页或活动网站 |

<div id="examples">
  ## 示例
</div>

<div id="same-project-web-app-mobile-app-for-one-product">
  ### 同一项目：同一产品的 Web 应用 + 移动应用
</div>

一家餐厅为顾客打造了用于浏览菜单的 Web 应用，并为员工打造了用于管理订单的移动应用。两者都连接到同一个包含菜单项、订单和客户信息的数据库。

**为何使用同一项目：** 两个应用共享相同的数据和后端。顾客通过 Web 应用下单后，员工会立即在移动应用中看到订单。

<div id="same-project-app-admin-dashboard-investor-pitch-deck">
  ### 同一项目：App + 管理仪表板 + 投资者路演演示文稿
</div>

一家初创公司在同一个项目中构建其核心产品、用于管理内容的内部管理面板，以及用于融资的演示文稿。

**为何使用同一个项目：** 管理仪表板管理 App 所展示的数据，路演演示文稿则可引用共享后端中的实时指标。

<div id="separate-projects-two-unrelated-client-apps">
  ### 独立项目：两个互不相关的客户应用
</div>

一名自由职业者为一位客户开发电商网站，为另一位客户开发预约系统。

**为何使用独立项目：**这两个应用没有共享的数据或逻辑。每位客户都需要独立发布，你也不希望对其中一个应用的更改影响另一个。

<div id="separate-projects-campaign-landing-page-alongside-a-main-product">
  ### 独立项目：营销活动落地页与主产品并行
</div>

你有一个全年运行的正式应用，以及一个短期营销活动落地页。

**为何使用独立项目：**活动页面有自己的生命周期——启动后运行几周，再将其下线。将其独立出来可避免主产品变得杂乱，也便于你单独发布或移除它。

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<Accordion title="我可以将构建产物移至其他项目吗？">
  暂不支持。如果你需要将构建产物拆分出来，请创建一个新的[项目](/zh/features/projects-and-artifacts/projects)，然后让 Agent 在其中重新构建。
</Accordion>

<Accordion title="一个项目可包含的构建产物数量是否有限制？">
  一个项目最多可包含 7 个构建产物，每个项目最多只能有 **1 个移动应用**。这是因为额外的构建产物会占用更多内存，可能导致 Preview 变慢。如果你需要更多构建产物，请创建另一个[项目](/zh/features/projects-and-artifacts/projects)。
</Accordion>

<Accordion title="我可以只发布项目中的一个构建产物吗？">
  暂不支持。Publishing 会将所有内容一并上线。如果你需要独立发布，请使用不同的项目。
</Accordion>

<Accordion title="构建产物之间会共享数据吗？">
  会。项目中的所有构建产物共享同一个数据库和后端服务。如果你的 Web 应用写入数据，移动应用和数据仪表板可以立即读取。
</Accordion>

<Accordion title="构建产物和文件有什么区别？">
  构建产物是可以发布的内容，例如 App、幻灯片和视频。文件 (如 CSV、图片或代码) 是项目中的资源，用于支持构建产物，但本身无法发布。
</Accordion>
