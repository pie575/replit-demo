};

有效的提示词就像向一位得力助手清晰地说明要求。只要正确引导 [**Agent**](/zh/ko/features/agent/overview)，就能快速将创意变成应用。

<div id="section">
  ## 快速示例
</div>

看看模糊提示词与有效提示词之间的差别：

<AccordionGroup>
  <Accordion title="代码修改" icon="bug">
    **模糊示例：**“修复代码。”

    **有效示例：**“处理用户输入时，脚本会出错。我认为验证函数可能有问题。您能帮我调试 `validate_input` 部分吗？错误信息如下：[详细信息]”

    有效的提示词会明确说明问题所在、疑似函数和上下文。
  </Accordion>

  <Accordion title="功能实现" icon="hammer">
    **模糊示例：**“创建一个网站。”

    **有效示例：**“请创建一个简单的作品集网站，包含首页、个人介绍和联系表单部分。使用简洁现代的设计主题和占位内容。”

    有效的提示词会明确定义目标、核心功能和所需设计。
  </Accordion>

  <Accordion title="性能改进" icon="gauge-high">
    **模糊示例：**“不要让它变慢。”

    **有效示例：**“重构数据处理函数，使其能够更高效地处理更大的输入。可以使用不同的算法或数据结构吗？”

    与其给出负面限制，不如告诉 Agent *如何*改进。
  </Accordion>

  <Accordion title="UI 更改" icon="paintbrush">
    **模糊示例：**“添加动画。”

    **有效示例：**“请为着陆页的主图添加动画，使其在页面首次加载时平滑淡入，营造欢迎感。”

    明确说明具体元素、所需效果、时机和预期体验。
  </Accordion>

  <Accordion title="复杂系统" icon="server">
    **模糊示例：**“创建后端。”

    **有效示例：**“设置服务器端逻辑。实现用户身份验证 (注册/登录) ，并创建可安全检索用户个人资料数据的 API 端点。”

    将大型任务拆分为具体功能。
  </Accordion>
</AccordionGroup>

<div id="section-3">
  ### 先做好规划
</div>

<Tip>输入提示词前，先梳理应用的功能和用户流程。清晰的规划能让提示词更聚焦。</Tip>

像产品经理一样思考应用的结构。将整体目标拆分为逻辑清晰的步骤。

**不要这样：**“帮我创建一个任务管理应用。”

**应该这样：**“1. 创建包含输入字段和任务列表的基本 HTML 结构。2. 添加用于新增任务的 JavaScript。3. 使用数据库存储任务。4. 添加将任务标记为完成的功能。”

然后针对每个步骤向 Agent 提供提示词。

<div id="section-4">
  ### 逐步构建
</div>

每完成一个成功的步骤后，使用 [**checkpoint**](/zh/ko/features/agent/overview#checkpoints) 保存进度。如果出现问题，你可以回滚到可正常运行的状态，再尝试其他方法。

**不要这样：**“帮我创建一个完整的电商平台。”

**应这样：**“为使用 Replit Auth 实现用户注册和登录的电商网站搭建一个基础全栈项目。”然后依次添加商品列表、购物车和支付功能。

<div id="section-5">
  ### 说清楚具体要求
</div>

明确说明输出格式、约束条件和边界情况。

**不要这样说：**“添加一个联系表单。”

**应该这样说：**“请在 `/contact` 创建一个包含以下字段的联系表单页面：

* 姓名 (必填)
* 电子邮箱 (必填，格式必须有效)
* 留言 (必填，至少 10 个字符)

提交时，请将表单数据发送至 `contact@mydomain.com`。”

<div id="section-6">
  ### 使用正向语言
</div>

说明你*想要的效果*，而不是你想避免的问题。

**不要这样说：**“不要让用户个人资料页面显得杂乱。”

**这样说：**“设计一个简洁的用户个人资料页面。突出显示用户名，并在下方显示电子邮箱和注册日期。添加一个‘编辑个人资料’按钮。”

<div id="section-7">
  ### 保持简洁
</div>

使用清晰、直接的语言。将复杂请求拆分成项目符号。

**不要这样写：**“实现支持动态创建和检索用户生成内容工件所需的服务器端基础设施。”

**这样写：**“创建一个后端功能，让用户提交博客文章。用户需要输入标题和正文。将文章保存到数据库中。”

<div id="section-8">
  ## 使用上下文
</div>

<div id="section-9">
  ### 提供相关文件
</div>

与其附上整个项目，不如提及具体文件。

**不要这样：** (附上所有内容) “按照设计系统实现用户资料页面。”

**应该这样：**“创建用户资料页面。从服务器端点获取用户数据。按照 [设计文档 URL] 进行样式设计，并与此模型图保持一致：[`profile_mockup.jpg` 已附上]。”

<Tip>切换到无关任务时，请开启新对话。这样可以避免累积上下文造成混乱。</Tip>

<div id="section-10">
  ### 展示示例
</div>

提供代码片段、示例数据、截图等具体示例，减少歧义。

**不要这样：**“让商品卡片更好看。”

**应该这样：**“请重新设计购物页面中的商品卡片。每张卡片应包含商品图片、名称、价格和‘加入购物车’按钮。请参考以下布局：[附上截图]。使用浅灰色边框。”

<div id="section-11">
  ## 高效调试
</div>

出现错误时，请提供：

* **完整准确的**错误信息
* 相关代码片段
* 出错的文件名
* 你想实现的目标
* 你已尝试过的步骤

**不要这样说：** “我的登录页面无法正常工作。”

**应该这样说：** “在 `/login` 页面使用正确的凭据登录时，浏览器控制台显示‘找不到用户’错误。数据库查询似乎没有正常执行。以下是 `auth.js` 中处理登录的代码。”

<div id="section-12">
  ## 寻求建议
</div>

<Tip>开始构建前，先切换到 Plan 模式，探索各种方案。向 Agent 询问可用的素材库、实现方式及其取舍。</Tip>

**不要这样说：**“帮我添加支付功能。”

**这样说：**“在 Replit 上构建的 Web 应用中，接受信用卡付款有哪些好的选择？我需要一种相对容易集成的方案。”

<div id="section-13">
  ## 迭代优化提示词
</div>

第一个提示词不必一开始就很完美——这很正常。如果结果不符合预期：

* 添加更多细节
* 提供示例
* 简化指令
* 换一种方式说明

**初始：**“帮我创建一个网站页眉。”

**改进：**“请创建一个固定页眉组件，网站徽标位于左侧，导航链接 (首页、关于、联系) 位于右侧。”

<div id="section-14">
  ## 总结
</div>

编写有效提示词的关键：

* 编写提示词前先**规划**
* 利用 checkpoint **循序渐进地构建**
* **明确说明**需求
* 通过示例和相关文件**提供上下文**
* 结果不符合预期时**反复迭代**

掌握这些原则后，你就能使用 Agent 更快地构建应用。
