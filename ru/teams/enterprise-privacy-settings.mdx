Как администратор Enterprise вы можете настраивать параметры на уровне организации, определяющие, как участники команды работают с кодом, deployment&#39;ами и внешними платформами. Эти настройки помогают поддерживать стандарты безопасности, защищать интеллектуальную собственность и обеспечивать соответствие корпоративным политикам.&quot;

<div id="accessing-privacy-settings">
  ## Доступ к настройкам конфиденциальности
</div>

<Accordion title="Как открыть настройки конфиденциальности">
  1. Перейдите в Workspace Enterprise
  2. Выберите **Settings**
  3. Выберите **Дополнительно**, чтобы просмотреть все доступные настройки
</Accordion>

<div id="privacy-settings">
  ## Настройки конфиденциальности
</div>

Настройки конфиденциальности определяют, как приложения публикуются и кто может получать к ним доступ в вашей организации.

  <Card title="Приватные deployments" icon="lock">

  <Card title="Deployments с защитой паролем" icon="key">

<div id="private-deployments">
  ### Приватные deployments
</div>

Если параметр включён, все новые приложения должны публиковаться как приватные. Приватные приложения доступны только аутентифицированным участникам вашей организации.

**Когда использовать этот параметр:**
**Когда использовать этот параметр:**

* Организация работает с конфиденциальными данными или проприетарными приложениями
* Нужно исключить случайную публикацию приложений в открытом доступе
* Требования комплаенса предписывают ограниченный доступ к опубликованным приложениям
* Нужно исключить случайную публикацию приложений в открытом доступе
* Требования комплаенса предписывают ограниченный доступ к опубликованным приложениям

<Note>
  Этот параметр применяется только к вновь публикуемым приложениям. Уже опубликованные приложения сохраняют текущие настройки видимости.
</Note>

<div id="password-protected-deployments">
  ### Deployment&#39;ы, защищённые паролем
</div>

Укажите, могут ли участники команды создавать deployment&#39;ы, защищённые паролем. Если включить этот параметр, разработчики смогут добавить дополнительный уровень защиты, установив пароль для доступа к опубликованным приложениям.

**Когда использовать этот параметр:**

* Вы хотите делиться приложениями с внешними заинтересованными сторонами, не делая их полностью общедоступными
* Командам нужно демонстрировать приложения клиентам перед более широким запуском
* Вам требуется более детальный контроль доступа, чем обеспечивает членство в организации

<div id="require-private-development-urls">
  ### Требовать приватные URL-адреса разработки
</div>

Если параметр включён, все URL-адреса разработки приложений требуют аутентификации. Если в вашей организации включён SAML, для URL-адресов разработки потребуется аутентификация через SSO.

**Когда использовать этот параметр:**
**Когда использовать этот параметр:**

* Вам нужно закрыть посторонним доступ к приложениям, находящимся в разработке
* Политики безопасности требуют защиты всех сред разработки
* Вы хотите, чтобы превью разработки могли просматривать только аутентифицированные участники команды
* Ваша политика безопасности требует защиты всех сред разработки
* Вы хотите, чтобы превью разработки могли просматривать только аутентифицированные участники команды

<Warning>
  Этот параметр применяется задним числом ко всем существующим приложениям в вашей организации.
</Warning>

<div id="ban-source-code-export">
  ### Запрет на экспорт исходного кода
</div>

Если эта настройка включена, участники команды не смогут экспортировать исходный код App в виде zip-архива. Это не позволит скачивать код и передавать его за пределы платформы Replit.

**Когда использовать эту настройку:**
**Когда использовать эту настройку:**

* Вам необходимо строго контролировать, где хранится исходный код
* Политики безопасности запрещают локальные копии кода
* Вы хотите, чтобы вся разработка велась в управляемых средах
* Ваша политика безопасности запрещает локальные копии кода
* Вы хотите, чтобы вся разработка велась в вашей управляемой среде

<div id="security-settings">
  ## Настройки безопасности
</div>

Настройки безопасности позволяют принудительно включить сканирование уязвимостей и другие меры защиты.

<div id="require-security-scan">
  ### Требовать сканирование безопасности
</div>

Настройте, должны ли все приложения проходить сканирование безопасности перед публикацией. Сканирование безопасности выявляет уязвимости, раскрытые секреты и другие проблемы безопасности в вашем коде.

Доступные варианты:

| Настройка     | Описание                                                                 |
| ------------- | ------------------------------------------------------------------------ |
| **Выкл.**     | Сканирование безопасности необязательно                                  |
| **Требовать** | Все приложения должны пройти сканирование безопасности перед публикацией |

**Когда следует использовать эту настройку:**
**Когда следует использовать эту настройку:**

* Необходимо соблюдать требования безопасности
* Вы хотите предотвратить случайное раскрытие ключей API или секретов
* Вам необходимо обеспечить единые стандарты безопасности для всех опубликованных приложений
* Вы хотите предотвратить случайное раскрытие ключей API или секретов
* Вам необходимо обеспечить единые стандарты безопасности для всех опубликованных приложений

<Note>
  Эта настройка не применяется к приложениям, опубликованным до её включения.
</Note>

<div id="source-control-settings">
  ## Настройки контроля версий
</div>

Настройки контроля версий помогают обеспечивать соблюдение правил управления версиями и защищать репозитории кода вашей организации.

<div id="require-git-remote">
  ### Требовать удалённый репозиторий Git
</div>

Если этот параметр включён, перед публикацией все локальные изменения в App необходимо отправить в удалённый репозиторий Git. Это гарантирует, что все изменения кода отслеживаются в системе контроля версий вашей Organization.

**Когда следует использовать этот параметр:**
**Когда следует использовать этот параметр:**

* Весь код должен быть сохранён в Git
* Вам необходим журнал аудита всех изменений кода
* Workflows требуют проверки кода перед публикацией
* Вам необходим журнал аудита всех изменений кода
* Ваш рабочий процесс требует проверки кода перед публикацией

<Note>
  Этот параметр не применяется к App, опубликованным до включения этого параметра.
</Note>

<div id="private-remotes">
  ### Приватные удалённые репозитории
</div>

Определяет, могут ли участники команды использовать публичные репозитории Git. Если включено требование приватных удалённых репозиториев, участники команды смогут отправлять изменения только в приватные репозитории на платформах вроде GitHub.

Доступные варианты:

| Настройка                            | Описание                                                                                  |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| **Выключено**                        | Участники команды могут использовать публичные или приватные репозитории                  |
| **Требовать для не-администраторов** | Участники команды без прав администратора должны использовать приватные репозитории       |
| **Требовать для всех**               | Все участники команды, включая администраторов, должны использовать приватные репозитории |

**Когда использовать эту настройку:**
**Когда использовать эту настройку:**

* Публичные репозитории кода запрещены
* Нужно исключить случайную отправку проприетарного кода в публичные репозитории
* Требования комплаенса предписывают использовать приватный контроль версий
* Нужно исключить случайную отправку проприетарного кода в публичные репозитории
* Требования комплаенса предписывают использовать приватный контроль версий
