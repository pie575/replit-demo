Utilisez ce guide pour déplacer une application [Replit Auth](/fr/features/auth-and-identity/authentication) existante vers [Clerk Auth](/fr/features/auth-and-identity/clerk-auth). Agent gère la migration pour les applications éligibles, afin que les utilisateurs récurrents conservent l'accès à leurs données existantes.

<Note>
  Cette migration automatisée concerne les applications qui utilisent Replit Auth. Si votre application utilise un système d'authentification différent, n'utilisez pas ce flux.
</Note>

## Démarrer la migration

Les migrations Agent doivent toujours s'exécuter dans une nouvelle tâche.

Vous pouvez démarrer la migration de l'une de ces deux façons :

### Examiner le plan de migration

Quelle que soit la méthode de démarrage choisie, Agent crée la tâche **Migrer de Replit Auth vers Clerk** et prépare le plan de migration. Sélectionnez **Voir le plan** et examinez le plan avant que la tâche ne se poursuive.

Ne modifiez pas le code d'authentification de votre application ni les identifiants Clerk pendant qu'Agent travaille.

## Ce que fait Agent

Agent effectue la migration dans cet ordre :

1. Il déplace les données utilisateurs de Replit Auth vers Clerk, y compris les détails d'identité du compte et les identifiants de connexion pris en charge.
2. Il attend que la migration des données soit terminée avant de modifier votre application.
3. Il met à jour la logique de connexion et de session de votre application, redémarre l'application et exécute les vérifications automatisées disponibles.

## Les données de votre application restent en place

Agent modifie uniquement le code d'authentification de votre application. Il ne met pas à jour les données ou le schéma existants de la base de données de votre application. Vos tables et relations restent intactes.

Vos utilisateurs existants restent connectés aux enregistrements qu'ils possèdent déjà, tels que les profils, le travail enregistré et les autorisations.

## Durée du processus

Attendez-vous à ce qu'Agent travaille pendant 10 minutes à une heure. La migration des données elle-même peut prendre plusieurs minutes pour les petites applications et jusqu'à quelques heures pour les applications comptant de nombreux utilisateurs. Agent ne commence à modifier le code de votre application qu'une fois cette migration terminée.

## Après la migration

Avant de publier, testez l'application mise à jour en Développement :

1. Connectez-vous avec un compte existant et confirmez que ses données enregistrées sont disponibles.
2. Déconnectez-vous puis reconnectez-vous.
3. Créez un nouveau compte de test et confirmez qu'il peut utiliser l'application comme prévu.
