Agent поддерживает четыре типа интеграций, чтобы вы могли быстро воплощать идеи в App:

* **Управляемые Replit**: Встроенные интеграции, которые работают автоматически. Создайте App, и ваш Agent сможет сразу ими пользоваться.
* **Коннекторы**: Интеграции от Replit. Войдите в аккаунт один раз. Agent может напрямую обращаться к этим сервисам из чата: получать данные, создавать записи, отправлять сообщения — и использовать их при разработке ваших App.
* **Внешние интеграции**: Надёжные сторонние сервисы, которые можно использовать при разработке. Попросите Agent настроить их; вам потребуется предоставить API-ключи.
* **Сервисы Agent**: Платные сторонние API, которые Agent использует в фоновом режиме — API-ключи не требуются. Использование оплачивается кредитами Replit.

<Note>
  **Доступность по тарифам**: Для большинства коннекторов требуется подписка Core, Pro или Enterprise, а некоторые доступны на тарифе Free. В каталоге коннекторов вашего рабочего пространства указано, какие коннекторы доступны на вашем текущем тарифе. Разработчики на тарифе Free всегда могут использовать управляемые Replit интеграции, например базы данных, аутентификацию и другие.
</Note>

  ## Начало работы
</div>

Чтобы использовать интеграцию, упомяните нужный сервис или функцию. Например:

  Создай веб-приложение, использующее Stripe для приема платежей и SendGrid для отправки писем с подтверждением

<div id="let-agent-suggest-a-connector">
  ### Позвольте Agent предложить интеграцию
</div>

Иногда одну и ту же задачу могут выполнять несколько сервисов, например хранение файлов или отправку электронной почты. Если вы запрашиваете возможность, не указывая провайдера, Agent показывает краткий список подходящих интеграций. Выберите нужную.

Выберите провайдера, затем один раз войдите в систему, чтобы подключить аккаунт. Agent будет использовать ваш выбор при создании приложения. Также можно указать конкретный сервис по имени, чтобы пропустить список.

<div id="connectors">
  ## Коннекторы
</div>

Коннекторы позволяют Agent напрямую читать и записывать данные в ваших сервисах. Это поддерживаемые Replit собственные интеграции. Войдите на странице Коннекторы в Project Editor один раз, а затем используйте эти подключения повторно в разных приложениях.

<Note>
  Подключения привязаны к вашей учётной записи Replit и доступны во всех ваших приложениях. Подключите сервис один раз и используйте его в любом созданном вами приложении.
</Note>

<div id="use-slack-with-agent">
  ### Использование Slack с Agent
</div>

Подключите Slack, чтобы Agent мог использовать контекст из доступных вам бесед. Попросите Agent найти сообщения, файлы, каналы или людей, а затем использовать результаты для ответов на вопросы или продолжения работы.

С вашего разрешения Agent может:

* Читать закрытые каналы, личные и групповые личные сообщения, в которых вы участвуете.
* Читать все ответы в треде, когда нужен контекст обсуждения.
* Отправлять сообщения от вашего имени.
* Создавать, читать и обновлять Canvas в Slack.

<div id="configuring-oauth-app-with-replit">
  ### Настройка OAuth-приложения в Replit
</div>

<Note>
  **Только для Enterprise**: для настройки собственного OAuth-приложения требуется подписка Enterprise.
</Note>

На тарифе Enterprise вы можете использовать собственное OAuth-приложение для коннектора вместо стандартного приложения Replit. Это позволяет вашей организации самостоятельно управлять OAuth-клиентом, использовать собственный брендинг на экране согласия и точно определять области действия, которые могут запрашивать ваши разработчики.

Чтобы настроить коннектор с собственным OAuth-приложением, вам понадобятся три вещи от провайдера: **Client ID**, **Client Secret** и **области действия**, которые вы хотите авторизовать. Также необходимо зарегистрировать у провайдера URL обратного вызова Replit, чтобы завершить аутентификацию.

  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Диалог настройки OAuth для коннектора с полями Client ID, Client Secret и Connector Scopes, а также Redirect URL, заданным как https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Создайте OAuth-приложение у провайдера">
    Войдите в консоль разработчика или настройки администратора провайдера и создайте новое OAuth 2.0-приложение. У разных провайдеров этот шаг называется по-разному — ищите такие варианты, как **Создать OAuth-приложение**, **Зарегистрировать приложение** или **Создать учётные данные клиента**.
  </Step>

  <Step title="Укажите URL перенаправления">
    Когда провайдер запросит **авторизованный URI перенаправления** (иногда называемый **URL обратного вызова** или **URL перенаправления**), введите:

    ```
    https://replit.com/connectors/oauth/callback
    ```

    По этому URL провайдер возвращает разработчиков в Replit после авторизации приложения. Он должен совпадать в точности: важны завершающие слеши, протокол и поддомен. Если вы добавляете несколько URI перенаправления, этот URI должен быть среди них.
  </Step>

  <Step title="Скопируйте Client ID и Client Secret">
    После создания приложения провайдер покажет **Client ID** и **Client Secret**.

    * **Client ID**: публичный идентификатор вашего OAuth-приложения. Его можно безопасно использовать в URL и коде на стороне клиента.
    * **Client Secret**: конфиденциальное значение, подтверждающее, что запрос исходит от вашего приложения. Обращайтесь с ним как с паролем — никогда не добавляйте его в репозиторий и не публикуйте. Replit надёжно хранит его от вашего имени.

    Некоторые провайдеры показывают Client Secret только один раз — при создании. Сразу скопируйте его и сохраните в безопасном месте, пока не вставите в Replit.
  </Step>

  <Step title="Выберите области действия">
    **Области действия** — это разрешения, определяющие, что ваше OAuth-приложение может читать или записывать от имени разработчика. Каждый провайдер публикует собственный список областей действия в документации API.

    При настройке коннектора в Replit введённые области действия должны **в точности совпадать** (символ в символ, включая префиксы URL) с областями действия, зарегистрированными у провайдера. Распространённые причины ошибок несоответствия:

    * Отсутствует полный префикс URL (например, `https://www.googleapis.com/auth/drive.file` вместо `drive.file`).
    * Лишние пробелы или завершающие запятые.
    * Запрос области действия в Replit, которая не включена в приложении провайдера.

    Начните с минимальных областей действия, необходимых вашим разработчикам, и при необходимости добавьте другие позже — большинство провайдеров позволяют обновлять области действия без повторного создания приложения.
  </Step>

  <Step title="Настройте коннектор в Replit">
    На странице **Коннекторы** вашей организации выберите **Добавить новую интеграцию**, выберите сервис и вставьте **Client ID**, **Client Secret** и **области действия**, полученные от провайдера. Чтобы сохранить настройки, выберите **Настроить**.
  </Step>
</Steps>

<Note>
  Если после настройки аутентификация не выполняется, ещё раз проверьте, что URL перенаправления у провайдера в точности совпадает с `https://replit.com/connectors/oauth/callback`, а каждая область действия, введённая в Replit, также авторизована в приложении провайдера.
</Note>

<div id="reconnecting-integrations">
  ## Повторное подключение интеграций
</div>

Если подключённый сервис перестаёт работать — например, истекает срок действия сеанса или меняются разрешения, — Replit отображает в Project Editor уведомление о необходимости повторного подключения. Выберите уведомление, чтобы повторно подключить интеграцию, не выходя из редактора.

<div id="debugging-connectors">
  ## Отладка коннекторов
</div>

Не удаётся подключить сервис? В этих руководствах описаны распространённые ошибки и способы их устранения.

<AccordionGroup>
  <Accordion title="Google Workspace: &#x22;Это приложение заблокировано&#x22;">
    Если при подключении Google Drive, Docs, Sheets, Calendar или Gmail появляется сообщение **&quot;Это приложение заблокировано&quot;**, вероятно, Google Workspace вашей организации ограничивает использование сторонних OAuth-приложений. Ознакомьтесь с подробным руководством по устранению неполадок.

    [Как устранить ошибку «Это приложение заблокировано» для коннекторов Google](/ru/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce: &#x22;Срок действия подключения истёк&#x22;">
    Если ваш коннектор Salesforce перестал работать с ошибкой **&quot;Срок действия подключения истёк&quot;**, вероятно, политика refresh token в вашей организации Salesforce настроена на истечение срока действия токенов через определённый период. Ознакомьтесь с подробным руководством по устранению неполадок, чтобы обновить настройки Connected App.

    [Устранение ошибок истечения срока действия подключения Salesforce](/ru/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
