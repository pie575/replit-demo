Поскольку Replit запускает ваши проекты в облачной среде, порты здесь работают иначе, чем на локальном компьютере. (Если вам нужно более простое объяснение того, что такое TCP-порты, [начните отсюда](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

На компьютере есть только один уровень управления портами: программы задают порт, который они прослушивают, и когда на этот порт приходит трафик из интернета, он направляется соответствующему процессу.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="компьютер" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

Часть `0.0.0.0` — это адрес, или хост. Если процесс прослушивает `0.0.0.0`, значит, он слушает все сетевые интерфейсы: если другой компьютер (из интернета) отправит запрос на IP-адрес вашего компьютера, процесс его получит. Иными словами, прослушивание 0.0.0.0 означает, что эти процессы доступны из публичного интернета (если ваш компьютер к нему подключён).

Большинство фреймворков во время разработки *не* прослушивают `0.0.0.0`: вряд ли вы захотите, чтобы ваша работа была доступна всем, пока вы над ней работаете, — из соображений приватности и безопасности. Вместо этого они слушают другой адрес — `127.0.0.1`, также известный как `localhost`. Это значит, что обращаться к такому порту может только сам компьютер.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Порты localhost видны только на том компьютере, который их обслуживает." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

В Replit, чтобы запущенный вами процесс был доступен в webview или по внешнему запросу, для него должен быть задан **внешний порт**. Дело в том, что «внутренний порт», который обычно используют процессы, виден только внутри изолированной облачной среды Replit. Этот внутренний порт нужно связать с внешне доступным портом, чтобы нужный трафик попадал в ваши программы. Даже если ваш процесс прослушивает порт, обычно открытый для всех, например 0.0.0.0, его всё равно нужно привязать к внешнему порту.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Внешние порты перенаправляют трафик на внутренние порты, которые прослушивают программы." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit делает это, привязывая внешние порты к конкретным внутренним — например, на схеме выше внешний порт `:80` привязан к внутреннему порту `:3000`. Это значит, что весь трафик, который Replit App получает на порт 80, уйдёт на внутренний порт 3000.

Эта конфигурация описывается в разделе [[ports]] файла конфигурации .replit.

По умолчанию Replit привязывает первый открытый вами порт к внешнему порту 80 — благодаря этому процесс доступен по домену без указания порта (например, customdomain.com/ вместо customdomain.com:3000/). Остальные открываемые внутренние порты привязываются к другим свободным внешним портам (полный список см. ниже).

<div id="default-port">
  ## Порт по умолчанию
</div>

Порт :80 — это «порт по умолчанию» для http-трафика, поэтому http-трафик, направленный на корневой домен, автоматически маршрутизируется на порт 80. По этой причине номер порта 80 не отображается в URL. Порты, отличные от :`80`, будут отображаться в адресе домена (например, customdomain.com:4200/). (Replit по умолчанию предоставляет TLS, поэтому технически соединение будет идти через порт 443 — порт по умолчанию для https. На практике их можно считать взаимозаменяемыми.)

<div id="publishing">
  ## Publishing
</div>

Развертывания Autoscale и Reserved VM поддерживают публикацию только одного внешнего порта, причём соответствующий внутренний порт не должен использовать `localhost`. Если открыть больше портов или открыть один порт на localhost, опубликованное приложение работать не будет. Чтобы развертывания Autoscale работали как ожидается, проще всего удалить из конфигурации все записи `externalPort`, *кроме* записи для порта того сервиса, с которым вы хотите взаимодействовать из интернета.

<div id="debugging">
  ## Отладка
</div>

Частая причина, по которой что-то работает не так, как ожидается: конфигурация портов выглядит верной, но программа на самом деле слушает другой порт. Например, если ваша конфигурация выглядит так:

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Тогда интернет-трафик на порт 80 будет направляться на внутренний порт 3000. Однако если ваша программа на самом деле прослушивает не порт 3000, а какой-то другой (например, 8080), то будет казаться, что трафик вообще не проходит. Такое случается, если вы меняете порт в коде, но забываете изменить соответствующий порт в конфигурации, или копируете конфигурацию из одного проекта в другой.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Программы могут менять порты, которые они прослушивают." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

У каждого фреймворка свои порты по умолчанию — например, у Flask это 5000, у react — 3000, а у laravel — 8000. Убедитесь, что указан правильный порт!

<div id="preferences">
  ## Настройки
</div>

Replit автоматически привязывает порты, открытые в вашем Replit App, к доступным внешним портам в момент их открытия и записывает эту привязку в файл конфигурации .replit.

Однако по умолчанию этого не происходит для внутренних портов, открываемых на localhost: службы, которые обычно работают на localhost, как правило, рассчитаны на то, что будут доступны только на том компьютере, где выполняется процесс (порты localhost видны только этому компьютеру). Поэтому такие службы часто защищены хуже, чем службы, изначально рассчитанные на доступность из публичного интернета.

Вы всегда можете изменить это поведение, задав параметру конфигурации `exposeLocalhost` значение `true` для порта, который хотите открыть.

Если вы хотите, чтобы порты localhost открывались *всегда* по умолчанию, задайте настройке «automatic port forwarding» в инструменте User Settings значение «All ports».

Если вы хотите, чтобы конфигурация для открываемых портов *никогда* не создавалась автоматически, и предпочитаете вручную управлять настройками портов во всех своих Replit App, задайте этому параметру значение «never».

<div id="supported-ports">
  ## Поддерживаемые порты
</div>

При открытии первого порта Replit App по умолчанию назначает внешним портом порт 80. В качестве дополнительных внешних портов Replit App может использовать порты 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080, 8081.

Порты 22 и 8283 перенаправить нельзя — они используются внутри системы.

<div id="ports-replit-config">
  ## Конфигурация `[[ports]]` в .replit
</div>

Тип: `{localPort, externalPort, exposeLocalhost}`

Конфигурация `[[ports]]` позволяет указать, какой HTTP-порт открывать для веб-вывода. По умолчанию любой открытый HTTP-порт с хостом 0.0.0.0 становится веб-выводом вашего Replit App.

Дополнительные порты можно обслуживать, не переопределяя порт по умолчанию, — для этого добавьте новую запись [[ports]] в файл .replit. Указать нужно обе записи: localPort и externalPort. Чтобы добавить сразу несколько дополнительных портов, укажите несколько записей [[ports]] в файле .replit, как показано ниже.

<div id="localport">
  ### localPort
</div>

Определяет, какой порт Replit привяжет к внешнему порту.

<div id="externalport">
  ### externalPort
</div>

Определяет, какой порт будет доступен извне для соответствующего локального порта.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Если вы *никогда* не хотите открывать определённый порт, можно оставить настройку `localPort`, но просто не добавлять `externalPort`:

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Определяет, можно ли привязать внутренний порт, использующий `localhost`, к внешнему порту. Может принимать значения `true`, `false` или null.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
