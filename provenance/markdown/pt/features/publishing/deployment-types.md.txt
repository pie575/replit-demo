# Deployment types

> Compare os deployments Autoscale, Static, Reserved VM e Scheduled e saiba quando escolher cada um para o seu app publicado.

O tipo de deployment é a tecnologia que o Replit usa para publicar seu app. Você o escolhe na ferramenta Publishing em **Adjust settings**, no menu suspenso **Deployment type**. **Autoscale** é a opção padrão e recomendada, e a maioria dos criadores nunca precisa alterá-la.

## Comparar tipos de deployment

| Tipo            | Ideal para                                          | Como funciona                                                           | Como é cobrado                                          |
| :-------------- | :-------------------------------------------------- | :---------------------------------------------------------------------- | :------------------------------------------------------ |
| **Autoscale**   | Apps web e APIs com tráfego variável                | Adiciona servidores quando está ocupado, escala para zero quando ocioso | Você paga enquanto as requisições estão sendo atendidas |
| **Static**      | Landing pages, portfólios, sites de documentação    | Serve arquivos a partir de um servidor de nuvem em cache, sem backend   | Você paga apenas pelos dados que seu site serve         |
| **Reserved VM** | Bots, trabalho em segundo plano, APIs sempre ativas | Um servidor dedicado que nunca dorme                                    | Custo mensal fixo                                       |
| **Scheduled**   | Tarefas periódicas como backups e notificações      | Executa um comando em um agendamento e depois para                      | Você paga pela duração de cada execução                 |

## Autoscale

Os Autoscale Deployments são executados em servidores que escalam para cima e para baixo com o tráfego do seu app. Quando seu app está ocupado, o Replit adiciona servidores para lidar com a carga. Quando está ocioso, a quantidade cai até chegar a zero, para que você não pague pelos períodos de baixa.

Ideal para:

* Aplicações web com tráfego variável, como sites de e-commerce
* APIs e serviços

A configuração fica em **Adjust settings**: [poder da máquina e o número máximo de servidores](/pt/features/publishing/machine-configuration).

## Static

Os Static Deployments hospedam os arquivos do seu app, como HTML, CSS e JavaScript, em um servidor de nuvem que usa cache para entregar conteúdo de forma rápida e econômica. Não há servidor backend.

Ideal para:

* Landing pages de marketing
* Sites de portfólio
* Sites de documentação de produtos e APIs

<Note>
  Os Static Deployments não são compatíveis com Replit Apps criados usando o Agent. O Agent constrói apps full-stack que precisam de um servidor backend, então use Autoscale ou Reserved VM para esses casos.
</Note>

A configuração inclui o diretório público a ser servido e um comando de build opcional. Para cabeçalhos de resposta, reescritas de URL e redirecionamentos, veja a [configuração avançada de Static](/pt/features/deployment-customization/static-deployments-advanced).

## Reserved VM

Os Reserved VM Deployments executam seu app em uma máquina virtual dedicada que nunca dorme. Você obtém desempenho consistente e um custo mensal fixo e previsível.

Ideal para:

* Tarefas em segundo plano com uso intenso de memória
* Chat bots que precisam permanecer conectados
* Servidores de API sempre ativos

A configuração inclui [poder da máquina](/pt/features/publishing/machine-configuration), comandos de build e execução, mapeamentos de porta, e se o app é executado como servidor web ou worker em segundo plano.

## Scheduled

Os Scheduled Deployments executam um comando em um agendamento no ambiente do seu app e depois param até a próxima execução. Descreva o agendamento em linguagem simples, como "todo dia da semana às 9h", e o Replit o converte automaticamente em um agendamento. Você recebe um alerta se uma execução falhar.

Ideal para:

* Verificações de status e relatórios de saúde
* Envio de notificações
* Início de backups

A configuração inclui o agendamento, um timeout de job e comandos de build e execução. Os Scheduled Deployments não servem uma página web, então não têm URL pública.
