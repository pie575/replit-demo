Workspace Security Center доступен на всех тарифах. Используйте его, чтобы сканировать [зависимости](/ru/pt/core-concepts/security/concepts#dependency) проектов во всём workspace и просматривать результаты по [CVE](/ru/pt/core-concepts/security/concepts#cve) с разбивкой по [уровню серьёзности](/ru/pt/core-concepts/security/concepts#severity). Вы можете устранять проблемы с помощью Replit Agent, [повторно публиковать](/ru/pt/core-concepts/security/concepts#republish) затронутые проекты и экспортировать отчёты Software Bill of Materials ([SBOM](/ru/pt/core-concepts/security/concepts#sbom)) для соответствия требованиям.

<Note>
  Чтобы просканировать отдельный проект, откройте [Project Security Center](/ru/pt/core-concepts/security/project-security-center)
  на панели **Security** внутри этого проекта.
</Note>

<Note>
  Впервые сталкиваетесь с безопасностью зависимостей? Загляните в раздел [Концепции безопасности](/ru/pt/core-concepts/security/concepts) — там приведены определения CVE, SBOM, экспозиции, Fix with Agent, Republish и Auto-Protect.
</Note>

  ## Ресурсы
</div>

<div id="deteco-de-cve">
  ### Обнаружение CVE
</div>

Просматривайте уязвимости во всех проектах вашего workspace:

* Выявляйте уязвимые проекты с приоритизацией по [экспозиции](/ru/pt/core-concepts/security/concepts#exposure) (статус публикации и видимость)
* Смотрите названия затронутых пакетов, версии и уровень серьёзности (critical, high, medium и low)
* Получайте рекомендации по устранению уязвимостей для каждого проекта

<div id="visualizao-de-projetos-afetados">
  ### Просмотр затронутых проектов
</div>

Определите, в каких проектах есть уязвимости, и решите, что исправлять в первую очередь:

* Смотрите общую сводку по уязвимым проектам с группировкой по экспозиции: всего проектов, опубликованные проекты и общедоступные опубликованные проекты
* Изучайте детализацию по затронутым Replit projects
* Ищите по идентификатору CVE или названию проекта и фильтруйте по уровню серьёзности, владельцу, статусу публикации (Published / Not published) и видимости (Public / Private)
* Разверните любую строку проекта, чтобы увидеть все найденные CVE (уровень серьёзности, пакет, версия, идентификатор CVE), не покидая страницу

<div id="fix-with-agent-e-republicao">
  ### Fix with Agent и повторная публикация
</div>

Устраняйте уязвимости и заново развёртывайте приложения, не покидая Security Center:

* Выберите **[Fix with Agent](/ru/pt/core-concepts/security/concepts#fix-with-agent)** в любом затронутом проекте, чтобы создать исправление в виде фоновой задачи в этом проекте. Просмотрите и примените предложенные изменения перед повторной публикацией.
* Отслеживайте ход устранения по этапам **Task in progress**, **Apply changes**, **Republish** и по итоговым состояниям **Republished** или **Failed**.
* Выполняйте **Republish** одним щелчком: после применения исправления в диалоге подтверждения сборка будет заново развёрнута с существующей конфигурацией.
* Выполняйте массовые действия — например, отменяйте публикацию или уведомляйте владельцев об уязвимостях в их проектах.

<div id="exportao-de-sbom">
  ### Экспорт SBOM
</div>

Экспортируйте Software Bill of Materials для целей соответствия требованиям и аудита:

* Скачивайте SBOM в стандартных форматах ([SPDX](/ru/pt/core-concepts/security/concepts#spdx-and-cyclonedx), [CycloneDX](/ru/pt/core-concepts/security/concepts#spdx-and-cyclonedx))
* Формируйте отчёты по отдельным проектам или по всему workspace
* Просматривайте SBOM, сгруппированные по запускам сканирования, с указанием времени, количества проектов и пользователя, инициировавшего запуск
* Скачивайте все SBOM одного запуска сканирования в едином zip-архиве
* Соблюдайте требования к прозрачности цепочки поставок программного обеспечения

<Note>
  Массовая загрузка SBOM доступна на тарифах Enterprise. В workspace на других тарифах в разделе SBOM отображается предложение перейти на Enterprise.
</Note>

<div id="acessar-o-workspace-security-center">
  ## Доступ к Workspace Security Center
</div>

Чтобы открыть Workspace Security Center:

1. Перейдите на [replit.com](https://replit.com) и войдите в свою учётную запись.
2. На главной странице выберите **Security** в левой панели навигации.

<div id="escanear-o-workspace">
  ## Сканирование workspace
</div>

<Frame>
  <img src="/assets/mirror/security-overview-b37f090f236c.png" alt="Начальный экран Workspace Security Center с общим числом сканирований, общим числом уязвимостей и CVE, сгруппированными по уровню серьезности" width="3438" height="1984" data-path="images/workspace-security-center/security-overview.png" />
</Frame>

1. Откройте Workspace Security Center.
2. Выберите **Run security scan**, чтобы запустить сканирование всего workspace.
3. Изучите результаты, сгруппированные по затронутым проектам, уровню серьезности и экспозиции deployment.
4. В любом затронутом проекте выберите **Fix with Agent**, а после применения исправления — **Republish**.

Сканирование анализирует зависимости в Replit projects вашего workspace и выявляет известные уязвимости по публичным реестрам уязвимостей.

<div id="auto-protect">
  ## Auto-Protect
</div>

Администраторы могут подключить для аккаунта **[Auto-Protect](/ru/pt/core-concepts/security/concepts#auto-protect)** — эта функция непрерывно отслеживает вновь опубликованные CVE и сопоставляет их с зависимостями всех проектов. При обнаружении совпадения Replit Agent готовит проверенный патч, а разработчики получают письмо с прямой ссылкой для его применения.

Полное описание рабочего процесса и шаги настройки, включая доступный только администраторам порог серьёзности в **Settings** &gt; **Account** &gt; **Advanced**, см. в разделе [Auto-Protect](/ru/pt/core-concepts/security/project-security-center#auto-protect).

<Note>
  За помощью в настройке Workspace Security Center или во внедрении экспорта SBOM в процессы обеспечения соответствия требованиям обращайтесь к своему персональному менеджеру аккаунта.
</Note>
