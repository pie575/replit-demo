title: "Publications planifiées"
description: "Découvrez comment exécuter des tâches selon une planification avec les Scheduled Deployments."
---

Définissez une opération en ligne de commande et une planification : Replit l&#39;exécute automatiquement
dans l&#39;environnement de votre Replit App. Une fois l&#39;opération terminée, elle s&#39;arrête jusqu&#39;à la prochaine
exécution planifiée.

Les deployments planifiés, également appelés tâches planifiées, sont particulièrement adaptés aux tâches périodiques,
comme la vérification de statuts, l&#39;envoi de notifications ou le lancement de sauvegardes. Ils ne sont pas conçus
pour des tâches continues ou de longue durée, comme les applications web.

<div id="recursos">
  ## Fonctionnalités
</div>

Les deployments planifiés offrent les fonctionnalités suivantes :

* **Planification automatique** : planifiez votre tâche, et Replit l&#39;exécute automatiquement.
* **Planification en langage naturel** : décrivez la planification en langage courant, et l&#39;IA la convertit en expression cron, un format de planification lisible par une machine.
* **Alertes d&#39;erreur** : recevez une notification en cas d&#39;échec de votre tâche planifiée.
* **Surveillance** : consultez les logs et suivez l&#39;état de votre deployment planifié.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder aux deployments planifiés depuis l&#39;outil Publishing du Project Editor.

Les sections suivantes vous guident dans la configuration et la gestion de vos deployments planifiés.

<Accordion title="Comment accéder aux Scheduled Deployments">
  Dans le **Tool dock** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône de tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône de Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Scheduled**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut pour ouvrir l&#39;outil de recherche
  2. Saisissez « Publishing » pour retrouver l&#39;outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l&#39;option **Scheduled**, puis **Set up your published app**.
</Accordion>

<div id="configurao-da-mquina">
  ### Configuration de la machine
</div>

Ce champ vous permet de consulter le processeur, la mémoire vive et le coût d&#39;utilisation de la machine de votre deployment planifié.

<div id="campos-de-agendamento">
  ### Champs de planification
</div>

* **Schedule description** : saisissez une description de la planification en langage naturel, par exemple « Every Monday and Wednesday at 10 AM » ou « March 24th, 2024 at 3 PM ».
* **Cron expression** : saisissez éventuellement une chaîne lisible par une machine qui définit le moment d&#39;exécution de la tâche.
* **Timezone selection** : sélectionnez le fuseau horaire de la planification dans le menu déroulant.

Lorsque vous saisissez une valeur dans le champ **Schedule description** ou **Cron expression**, l&#39;IA la convertit automatiquement dans l&#39;autre format.
Pour en savoir plus sur les expressions cron, consultez la page Wikipédia consacrée à <a href="https://en.wikipedia.org/wiki/Cron" target="_blank">cron</a>.

<div id="tempo-limite-do-job">
  ### Délai d&#39;expiration de la tâche
</div>

Saisissez la durée maximale d&#39;exécution de la tâche avant que le planificateur ne l&#39;interrompe. Sélectionnez « minutes » ou « hours » dans le menu déroulant des unités de temps.

<Tip>
  Les tâches planifiées peuvent s&#39;exécuter plus lentement que dans le Project Editor. Testez le
  deployment et ajustez le délai d&#39;expiration si nécessaire.
</Tip>

<div id="build-command">
  ### Build command
</div>

Dans le champ **Build command**, saisissez la commande Shell qui compile ou configure votre app avant l&#39;exécution du Run command.
Par exemple, pour installer les dépendances de votre app Node.js, vous pouvez ajouter la build command `npm install`.

La durée de la build command n&#39;est pas comptabilisée dans votre utilisation et n&#39;est pas déduite de la limite de temps du job.

<div id="run-command">
  ### Run command
</div>

Saisissez dans le champ **Run command** la commande Shell qui lance votre tâche.
Par exemple, pour exécuter un script Python, vous pouvez indiquer `python app.py` comme run command.

Le planificateur de Replit exécute le run command aux heures programmées.
La durée d&#39;exécution de la commande est comptabilisée dans votre utilisation. Pour en savoir plus sur la facturation à l&#39;usage,
consultez la [section Scheduled Deployments](/fr/pt/billing/deployment-pricing#scheduled-deployments) de notre documentation sur les tarifs.

<div id="deployment-secrets">
  ### Secrets de deployment
</div>

Sélectionnez **Add deployment secret** pour ajouter les variables d&#39;environnement ou les secrets dont votre app a besoin pour s&#39;exécuter en toute sécurité.

Si votre Replit App contient des variables d&#39;environnement ou des secrets, l&#39;outil Publishing les ajoute automatiquement à la liste.

Pour modifier les valeurs d&#39;une variable d&#39;environnement, sélectionnez les

<img class="icon-svg" src="/assets/mirror/vertical-dots-032f1c99d22e.svg" width="16" height="16" alt="icône de trois points verticaux" data-path="images/icons/vertical-dots.svg" /> trois points verticaux, puis choisissez **Edit** dans le menu. Le gestionnaire de Secrets applique la
valeur uniquement au deployment et ne modifie pas les variables d&#39;environnement définies dans votre
Replit App.
