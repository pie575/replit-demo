每周从 GitHub 和 Linear 拉取变更，生成面向客户的发布说明，按新增、改进和修复分类，并发布到 Notion。跳过纯内部的琐碎事务，并标出任何疑似破坏性变更的内容，让产品、支持团队和客户按固定节奏了解同一份信息。

<div id="before-you-start">
  ## 开始之前
</div>

为 Agent 指定对应的代码仓库和 Linear 团队。连接 Notion，用于发布页面。说明每周在
星期几运行。

<div id="prompt-the-agent">
  ## 向 Agent 提出 prompt
</div>

<AiPrompt>
  创建一个 Routine，每周一 9:00 运行。从 GitHub 和 Linear 拉取上周的变更，生成面向客户的发布说明，按「新增」「改进」「修复」分组，并发布到 Notion。跳过纯内部的杂项事务。标记出任何看起来属于破坏性变更的内容。
</AiPrompt>

<div id="what-to-expect">
  ## 预期效果
</div>

Agent 会根据拉取请求和议题起草上周的发布说明，然后写入 Notion 页面。
在发送给客户前调整语气。略过看起来像内部事务的内容，并将破坏性变更置于最前。在 Publish 前，
请将该页面与上周已合并的拉取请求核对。

<div id="make-it-work-for-you">
  ## 按你的需求灵活运用
</div>

<AiPrompt>
  撰写两个版本：一个面向客户，一个用于内部 changelog。将它们保留在同一个 Notion 页面中。
</AiPrompt>

<AiPrompt>
  在 #ship 发布一条 Slack 帖子，链接到 Notion 页面并列出 3 个亮点。
</AiPrompt>

<div id="troubleshooting">
  ## 故障排查
</div>

* **内部杂务出现在发布说明里：** 让 Agent 指向正确的代码仓库和 Linear 团队，并再次要求它跳过那些不会交付给客户的杂务。
* **破坏性变更被淹没了：** 告诉 Agent 对你而言什么算“重大” (登录、billing 或必须执行的 migration) ，并要求它把这些条目置顶并加上标记。
* **写到了错误的 Notion 页面：** 提供确切的页面或数据库链接，并说明是覆盖上周的发布说明，还是每次运行都新建一个页面。
