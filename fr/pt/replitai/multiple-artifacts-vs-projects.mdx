---
title: "Plusieurs artefacts ou projets distincts"
description: "Découvrez quand regrouper des artefacts dans un même projet et quand créer des projets distincts sur Replit."
---

Un [projet](/fr/pt/replitai/projects) est le conteneur de tout ce que vous créez sur Replit. Un projet regroupe vos designs, applications, diapositives, données et toutes les productions que vous réalisez.
Les [artefacts](/fr/pt/replitai/artifacts) sont les éléments publiables au sein d&#39;un projet : applications web, applications mobiles, présentations et vidéos.

Lorsque vous développez plusieurs éléments, deux options s&#39;offrent à vous :

* ajouter plusieurs artefacts à un même projet,
* ou créer des projets distincts.

Le bon choix dépend de la question de savoir si vos applications partagent des données, une logique et un cycle de vie de déploiement. Ce guide explique quand conserver les artefacts dans un seul projet et quand créer des projets distincts.

<div id="o-que-os-artefatos-compartilham-em-um-projeto">
  ## Ce que les artefacts partagent au sein d&#39;un projet
</div>

Lorsque les [artefacts](/fr/pt/replitai/artifacts) se trouvent dans le même [projet](/fr/pt/replitai/projects), ils partagent automatiquement :

* **Base de données** : un artefact écrit des données, les autres les lisent instantanément
* **Backend et API** : logique serveur partagée, sans code dupliqué
* **Stockage de fichiers** : images, documents et fichiers téléversés accessibles d&#39;un artefact à l&#39;autre
* **Déploiement** : la publication déploie l&#39;ensemble de façon synchronisée

Vous n&#39;avez donc pas à configurer de connexions ni à dupliquer du code entre les artefacts. En revanche, vous ne pouvez pas publier un artefact sans publier les autres.

<div id="guia-rpido">
  ## Guide rapide
</div>

Voici les principaux cas de figure à prendre en compte pour décider s&#39;il vaut mieux ajouter des artefacts à un projet existant ou en créer un distinct.

| **Utiliser plusieurs artefacts dans un projet**                                                            | **Utiliser des projets distincts**                                                           |
| ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Les applications partagent les mêmes données et le même backend                                            | Les applications ne partagent ni logique ni données sous-jacentes                            |
| Vous souhaitez que tout soit déployé ensemble                                                              | Vous avez besoin de cycles de déploiement indépendants                                       |
| Elles sont complémentaires (par exemple une application client et un tableau de bord d&#39;administration) | Ce sont des produits sans lien entre eux ou destinés à des clients différents                |
| Vous souhaitez que les modifications apportées à un artefact se répercutent automatiquement sur les autres | Le projet est de courte durée, comme une page de destination de campagne ou un site d&#39;événement |

<div id="exemplos">
  ## Exemples
</div>

<div id="mesmo-projeto-aplicativo-web-aplicativo-mobile-para-um-produto">
  ### Même projet : application web + application mobile pour un seul produit
</div>

Un restaurant crée une application web permettant aux clients de consulter la carte et une application mobile permettant à l&#39;équipe de gérer les commandes. Les deux se connectent à la même base de données, qui regroupe les plats de la carte, les commandes et les informations clients.

**Pourquoi un seul projet :** les applications partagent les mêmes données et le même backend. Lorsqu&#39;un client passe une commande depuis l&#39;application web, l&#39;équipe la voit immédiatement dans l&#39;application mobile.

<div id="mesmo-projeto-aplicativo-dashboard-admin-pitch-deck-para-investidores">
  ### **Même projet** : Application + tableau de bord d’administration + pitch deck pour les investisseurs
</div>

Une startup développe son produit principal, un tableau de bord d’administration interne pour gérer le contenu et une présentation destinée à lever des fonds — le tout dans un même projet.
Une startup développe son produit principal, un tableau de bord d’administration interne pour gérer le contenu et une présentation destinée à lever des fonds — le tout dans un même projet.

**Pourquoi un même projet :** Le tableau de bord d’administration gère les mêmes données que l’application affiche, et la présentation peut s’appuyer sur des métriques en temps réel provenant du backend partagé.

<div id="projetos-separados-dois-aplicativos-de-clientes-no-relacionados">
  ### **Projets distincts** : deux applications clientes sans lien entre elles
</div>

Un freelance développe une boutique e-commerce pour un client et un système de réservation pour un autre.

**Pourquoi des projets distincts :** les applications ne partagent ni données ni logique. Chaque client a besoin d&#39;un déploiement indépendant, et vous ne voulez pas que les modifications apportées à l&#39;une affectent l&#39;autre.

<div id="projetos-separados-landing-page-de-campanha-ao-lado-de-um-produto-principal">
  ### **Projets distincts** : Page de destination de campagne à côté d’un produit principal
</div>

Vous avez une application de production qui fonctionne toute l’année et une page de destination temporaire pour une campagne marketing.

**Pourquoi des projets distincts :** La page de campagne a son propre cycle de vie : vous allez la créer, la mettre en ligne pendant quelques semaines, puis la retirer. La garder séparée évite d’encombrer votre produit principal et vous permet de la publier ou de la retirer indépendamment.

<div id="perguntas-frequentes">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artefact vers un autre projet ?">
  Pas pour le moment. Si vous devez isoler un artefact, créez un nouveau [projet](/fr/pt/replitai/projects) et demandez à Agent de le reconstruire à cet endroit.
</Accordion>

<Accordion title="Y a-t-il une limite au nombre d'artefacts qu'un projet peut contenir ?">
  Un projet peut contenir au maximum 7 artefacts. Cette limite existe car chaque artefact supplémentaire consomme davantage de mémoire, ce qui peut ralentir l&#39;aperçu. Si vous avez besoin de plus d&#39;artefacts, démarrez un autre [projet](/fr/pt/replitai/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artefact d'un projet ?">
  Pas pour le moment. La publication déploie l&#39;ensemble en une seule fois. Si vous avez besoin d&#39;un déploiement indépendant, utilisez des projets distincts.
</Accordion>
