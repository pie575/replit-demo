Le pare-feu de paquets bloque les paquets malveillants et compromis au niveau du réseau, avant même qu&#39;ils ne soient installés dans votre app. Il fait partie de [Replit Auto-Protect](/fr/features/security/concepts#auto-protect), l&#39;ensemble des protections activées par défaut pour chaque créateur, et il est propulsé par [Socket](https://socket.dev), une entreprise spécialisée dans la sécurité de la chaîne d&#39;approvisionnement logicielle.

Lorsque vous ou l&#39;Agent exécutez une commande d&#39;installation comme `npm install` ou `pip install`, la requête passe d&#39;abord par le pare-feu de paquets. Les paquets sains s&#39;installent normalement, sans que vous remarquiez quoi que ce soit. Ceux que Socket a signalés comme malveillants ou compromis sont bloqués avant que le moindre code n&#39;atteigne votre environnement.

Le pare-feu de paquets est **activé par défaut pour chaque créateur, sans rien à installer ni à migrer**. Il protège aussi bien les nouvelles apps que les apps existantes, et aucun paramètre n&#39;est à configurer.

<div id="why-install-time-protection-matters">
  ## Pourquoi la protection au moment de l&#39;installation est essentielle
</div>

La plupart des outils de sécurisation de la chaîne d&#39;approvisionnement n&#39;analysent les dépendances qu&#39;au moment de la publication, bien après l&#39;installation d&#39;un paquet. Pour des vulnérabilités ordinaires, cela peut suffire. Les logiciels malveillants, eux, fonctionnent différemment : ils causent des dégâts dès l&#39;instant où ils sont installés — vol de secrets, ouverture de portes dérobées ou exfiltration de vos variables d&#39;environnement. Quand une analyse au moment de la publication les signale, l&#39;attaque a déjà eu lieu.

Package Firewall referme cette fenêtre. En bloquant les paquets malveillants avant leur téléchargement, il stoppe l&#39;attaque avant qu&#39;une seule ligne de code malveillant ne s&#39;exécute.

<div id="how-it-works">
  ## Fonctionnement
</div>

1. Vous ou l&#39;Agent exécutez une commande d&#39;installation, par exemple `npm install <package>` ou `pip install <package>`.
2. La requête transite par Package Firewall, qui compare le paquet aux renseignements sur les menaces de Socket.
3. Si le paquet est sain, l&#39;installation se déroule normalement, sans différence perceptible.
4. Si le paquet est malveillant ou compromis, l&#39;installation est bloquée avant que le moindre code n&#39;atteigne votre environnement.

En cas de blocage, vous recevez un message clair indiquant ce qui a été stoppé et pourquoi, avec la vulnérabilité ou la règle à l&#39;origine du blocage. L&#39;Agent reçoit le même signal : il peut donc proposer une alternative sûre — comme corriger un nom de paquet mal orthographié — ou vous laisser trancher.

<div id="supported-package-managers">
  ### Gestionnaires de paquets pris en charge
</div>

Package Firewall protège les installations pour :

* **JavaScript** — npm, yarn et pnpm
* **Python** — pip
* **Go** — modules Go

<div id="what-package-firewall-catches">
  ## Ce que détecte Package Firewall
</div>

Package Firewall bloque aussi bien les logiciels malveillants avérés que les versions compromises ou connues comme vulnérables de paquets par ailleurs légitimes — y compris les plus répandus. Bon nombre de ces vulnérabilités ont été divulguées après la date de fin d&#39;entraînement des modèles qui les recommandent : un modèle peut donc suggérer en toute confiance une version de dépendance réputée sûre dans ses données d&#39;entraînement, mais signalée depuis. Ces risques ont chacun leur nom dans le milieu :

* **Typosquats** — un paquet malveillant dont le nom ne diffère d&#39;un nom réel que d&#39;une frappe, comme `reqeusts` au lieu de `requests`. Vous demandez le mauvais paquet et téléchargez un logiciel malveillant.
* **Slopsquats** — un modèle invente un nom de paquet qui n&#39;existe pas, un attaquant enregistre ce nom exact, puis attend que le prochain agent l&#39;installe.
* **Recommandations obsolètes** — un paquet bien réel, mais affecté par une vulnérabilité divulguée, que le modèle recommande parce qu&#39;il était réputé sûr avant sa date de fin d&#39;entraînement.

C&#39;est cette dernière catégorie qui rend Package Firewall particulièrement utile pour les applications créées par IA : un agent peut se tourner en toute confiance vers une dépendance qui n&#39;est plus sûre, et Package Firewall interrompt l&#39;installation avant que ce code ne s&#39;exécute.

<div id="how-package-firewall-fits-with-replits-other-security-tools">
  ## Comment Package Firewall s&#39;intègre aux autres outils de sécurité de Replit
</div>

Package Firewall est l&#39;une des trois couches complémentaires. Chacune protège un point différent du cycle de vie de votre app : utilisez-les donc ensemble plutôt que de choisir entre elles.

| Couche                                    | Quand elle s&#39;exécute             | Ce qu&#39;elle fait                                                                                                                                                                                                                              |
| ----------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Package Firewall**                      | Au moment de l&#39;installation      | Bloque les paquets malveillants et compromis avant leur téléchargement (prévention).                                                                                                                                                             |
| **Analyses automatiques des dépendances** | Après l&#39;installation, en continu | Détectent les CVE nouvellement divulguées dans vos dépendances installées, avec des correctifs préparés par Agent en option. Consultez le [Centre de sécurité du projet](/fr/features/security/project-security-center#automatic-dependency-scans). |
| **Security Agent**                        | Avant la publication                 | Audite l&#39;ensemble de votre base de code à la recherche de vulnérabilités de code, de dépendances et de confidentialité. Consultez [Analyses de sécurité d&#39;Agent](/fr/features/security/agent-security-scans).                               |
