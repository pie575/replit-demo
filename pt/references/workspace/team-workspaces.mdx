## Workspace pessoal vs. workspace de equipe

Um **workspace** é a estrutura que organiza seus apps, membros, configurações e faturamento. O Replit tem dois tipos:

* Workspace pessoal
* Workspace de equipe

Abaixo está a diferença entre os Workspaces Pessoais e de Equipe:

|                              | Workspace pessoal                                 | Workspace de equipe                                    |
| ---------------------------- | ------------------------------------------------- | ------------------------------------------------------ |
| **Funções**                  | Admin, convidados no nível do projeto             | Admin, Membros, convidados no nível do projeto         |
| **Modelo de acesso**         | Você convida convidados para projetos individuais | Os membros têm acesso a todos os projetos no workspace |
| **Faturamento**              | Sua conta                                         | Créditos agrupados da conta do admin                   |
| **Gerenciamento de membros** | Por projeto (Links de ingresso)                   | Centralizado nas Configurações do workspace            |

O **workspace pessoal** é melhor quando você está trabalhando sozinho ou compartilhando projetos individuais com outras pessoas. Você é o único admin, e outras pessoas só podem acessar projetos específicos aos quais você as convidou como convidados no nível do projeto.

O **workspace de equipe** é melhor quando você está criando com um grupo regular — uma equipe de startup, uma turma ou um projeto de cliente com vários colaboradores. Os membros têm acesso a todos os projetos no workspace, então você não precisa convidá-los um por um para cada projeto. Os membros são gerenciados centralmente em **Configurações**.

### Quando convidar para o workspace vs. para um projeto

| Cenário                                                         | O que fazer                                           |
| --------------------------------------------------------------- | ----------------------------------------------------- |
| Colaborador contínuo que precisa de acesso a tudo               | Convidar para o workspace                             |
| Prestador de serviços ou convidado que só precisa de um projeto | [Convidar para o projeto](/pt/build/invite-teammates) |
| Novo membro da equipe que está entrando na sua empresa          | Convidar para o workspace                             |
| Amigo ajudando a depurar um app específico                      | [Convidar para o projeto](/pt/build/invite-teammates) |

## Criar um workspace de equipe

  <video autoPlay muted loop playsInline>
    <source src="/assets/mirror/create_new_team_workspace-f665bec18450.mp4" type="video/mp4" />
  </video>

<Steps>
  <Step title="Abra o seletor de workspace">
    Na página inicial, clique no nome do seu workspace no canto superior esquerdo.
  </Step>

  <Step title="Crie um novo workspace">
    Selecione **Criar workspace** e escolha um nome para seu workspace de equipe.
  </Step>

  <Step title="Convide membros">
    Insira um ou mais endereços de e-mail (separados por vírgula) no campo de convite. Os convidados recebem um convite e obtêm acesso a todos os projetos no workspace assim que o aceitam.
  </Step>
</Steps>

## Gerenciando membros

Se você não convidou membros durante a configuração ou precisa adicionar mais tarde, acesse **Configurações** no seu workspace de equipe e convide membros por e-mail ou nome de usuário do Replit.

<Frame>
  <video autoPlay muted loop playsInline>
    <source src="/assets/mirror/add_team_to_workspace_compressed-41d8163607d2.mp4" type="video/mp4" />
  </video>
</Frame>

Na página **Configurações** você também pode:

* **Remover membros** para revogar o acesso deles a todos os projetos do workspace
* **Transferir apps** de workspaces pessoais para o workspace de equipe — veja [Transferir app para equipes](/pt/teams/identity-and-access-management/transfer-app-to-teams)

Para gerenciamento avançado de identidade, controle de acesso baseado em funções e permissões de grupo, consulte [Teams](/pt/category/teams).
