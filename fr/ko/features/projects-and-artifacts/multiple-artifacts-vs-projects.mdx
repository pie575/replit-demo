---
title: "Plusieurs artefacts ou projets distincts"
description: "Découvrez quand regrouper des artefacts dans un même projet et quand créer des projets distincts dans Replit."
---

Les [projets](/fr/ko/features/projects-and-artifacts/projects) sont les conteneurs de tout ce que vous créez dans Replit. Un projet regroupe les conceptions, les applications, les diapositives, les données et tous les éléments que vous créez.
Les [artefacts](/fr/ko/features/projects-and-artifacts/artifacts) sont des éléments publiables au sein d’un projet : applications web, applications mobiles, présentations, vidéos, etc.

Lorsque vous créez deux éléments ou plus, vous avez deux possibilités :

* ajouter plusieurs artefacts à un même projet ;
* créer des projets distincts.

Le bon choix dépend de la question de savoir si vos applications partagent des données, de la logique et un cycle de déploiement. Ce guide explique quand regrouper des artefacts dans un même projet et quand les créer séparément.

<div id="section">
  ## Ce que les artefacts partagent au sein d&#39;un projet
</div>

Lorsque des [artefacts](/fr/ko/features/projects-and-artifacts/artifacts) se trouvent dans le même [projet](/fr/ko/features/projects-and-artifacts/projects), ils partagent automatiquement les éléments suivants :

* **Base de données** : dès qu&#39;un artefact écrit des données, les autres les lisent immédiatement
* **Backend et API** : la logique serveur étant partagée, inutile de dupliquer le code
* **Stockage de fichiers** : les images, documents et fichiers téléversés sont accessibles depuis tous les artefacts
* **Déploiement** : à la publication, tout est synchronisé et mis en ligne d&#39;un seul coup

Autrement dit, vous n&#39;avez pas besoin d&#39;établir des connexions entre les artefacts ni de dupliquer du code. Mais cela signifie aussi que vous ne pouvez pas publier un seul artefact : les autres doivent être publiés en même temps.

<div id="section-2">
  ## Guide rapide
</div>

Voici les principaux cas à prendre en compte pour décider d&#39;ajouter un artefact à un projet existant ou de créer un projet distinct.

| **Plusieurs artefacts dans un seul projet**                                                                 | **Projets distincts**                                                                             |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Les applications partagent les mêmes données et le même backend                                             | Les applications ne partagent ni logique métier ni données                                        |
| Vous souhaitez tout publier en même temps                                                                   | Des cycles de publication indépendants sont nécessaires                                           |
| Elles sont complémentaires (par exemple, une application client et un tableau de bord d&#39;administration) | Ce sont des produits sans lien entre eux ou destinés à des clients différents                     |
| Vous voulez que les modifications apportées à un artefact se répercutent automatiquement sur les autres     | Le projet est de courte durée (par exemple, une landing page de campagne ou un site événementiel) |

<div id="section-3">
  ## Exemple
</div>

<div id="section-4">
  ### Un même projet : une application web et une application mobile pour un même produit
</div>

Un restaurant crée une application web permettant aux clients de consulter le menu et une application mobile permettant au personnel de gérer les commandes. Toutes deux sont connectées à la même base de données de plats, de commandes et d&#39;informations sur les clients.

**Pourquoi les créer dans un même projet :** les applications partagent les mêmes données et le même back-end. Lorsqu&#39;un client passe une commande via l&#39;application web, le personnel peut immédiatement la consulter dans l&#39;application mobile.

<div id="section-5">
  ### **Un même projet** : application + tableau de bord d’administration + présentation aux investisseurs
</div>

Une startup crée son produit principal, un panneau d’administration interne pour gérer le contenu et une présentation destinée à lever des fonds, le tout au sein d’un même projet.

**Pourquoi les créer dans un même projet :** le tableau de bord d’administration gère les mêmes données que celles affichées par l’application, et la présentation peut s’appuyer sur des indicateurs en temps réel issus du back-end partagé.

<div id="section-6">
  ### **Projets distincts** : deux applications clientes sans lien
</div>

Un freelance crée une boutique e-commerce pour un client et un système de réservation pour un autre.

**Pourquoi créer des projets distincts :** les applications ne partagent ni données ni logique. Chaque client a besoin d’un déploiement indépendant et ne souhaite pas que les modifications apportées à une application affectent l’autre.

<div id="section-7">
  ### **Projet distinct** : page de destination de campagne en complément du produit principal
</div>

Vous avez une application de production utilisée toute l’année et une page de destination temporaire pour une campagne marketing.

**Pourquoi créer un projet distinct :** la page de campagne a son propre cycle de vie : vous la créez, l’exploitez pendant quelques semaines, puis la retirez. La gérer séparément vous permet de la publier ou de la supprimer indépendamment, sans compliquer votre produit principal.

<div id="section-8">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artefact vers un autre projet ?">
  Ce n&#39;est pas possible pour le moment. Si vous devez isoler un artefact, créez un nouveau [projet](/fr/ko/features/projects-and-artifacts/projects) et demandez à Agent de le recréer à cet endroit.
</Accordion>

<Accordion title="Le nombre d'artefacts qu'un projet peut contenir est-il limité ?">
  Un projet peut contenir jusqu&#39;à 7 artefacts. Cette limite existe car plus il y a d&#39;artefacts, plus la mémoire utilisée est importante, ce qui peut ralentir l&#39;aperçu. Si vous avez besoin de davantage d&#39;artefacts, démarrez un nouveau [projet](/fr/ko/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artefact d'un projet ?">
  Ce n&#39;est pas possible pour le moment. Lors de la publication, tout est mis en ligne ensemble. Si vous avez besoin de publier des éléments indépendamment, utilisez des projets distincts.
</Accordion>
