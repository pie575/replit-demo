Replit Agent propose deux modes d’interaction : **Plan Mode** et **Mode Build**. Utilisez-les conjointement pour réfléchir à vos idées avant de les mettre en œuvre en toute confiance.

<div id="what-is-plan-mode">
  ## Qu’est-ce que Plan Mode ?
</div>

[Plan Mode](/fr/features/agent/plan-mode) vous permet de faire du brainstorming, de poser des questions et de planifier votre travail avec Agent, sans modifier votre code. Considérez-le comme une séance de planification collaborative où vous pouvez explorer librement vos idées.

Plan Mode est idéal pour :

* **Faire du brainstorming** : explorer différentes approches avant d’en choisir une
* **Décomposer des projets complexes** : obtenir une liste de tâches structurée avant de développer
* **Apprendre et comprendre** : poser des questions sur des technologies, des modèles ou votre base de code
* **Planifier l’architecture** : concevoir la structure de votre application avant d’écrire du code

<Info>
  Dans Plan Mode, Agent lit votre projet et vous fournit des conseils, mais n’apporte aucune modification à vos fichiers. Lorsque vous êtes prêt à passer à l’implémentation, basculez vers le Mode Build ou approuvez un plan pour commencer automatiquement le développement.
</Info>

<div id="what-is-build-mode">
  ## Qu’est-ce que le mode Build ?
</div>

Le mode Build est le mode par défaut dans lequel Agent écrit du code, modifie des fichiers et implémente directement des fonctionnalités dans votre projet. C’est là que les idées prennent vie.

Utilisez le mode Build lorsque vous êtes prêt à :

* **Créer de nouvelles fonctionnalités** : laissez Agent écrire le code de votre prochaine fonctionnalité
* **Configurer votre app** : installez des dépendances, configurez des bases de données et connectez des services
* **Résoudre des problèmes** : laissez Agent déboguer et corriger les problèmes dans votre base de code
* **Refactoriser le code** : améliorez la structure et l’organisation du code existant

<div id="using-both-modes-together">
  ## Utiliser les deux modes ensemble
</div>

**Plan Mode et Mode Build sont plus efficaces lorsqu&#39;ils sont utilisés à la suite.** Commencez par planifier pour clarifier vos idées, puis développez en suivant une direction claire.

<Steps>
  <Step title="Commencer dans Plan Mode">
    Passez à Plan Mode et décrivez ce que vous souhaitez créer. Agent vous aidera à réfléchir aux exigences, à suggérer des approches et à identifier les difficultés potentielles, le tout sans modifier votre code.
  </Step>

  <Step title="Générer une liste de tâches">
    Demandez à Agent de créer un plan de développement. Il décomposera votre projet en tâches précises et réalisables, avec des priorités et des dépendances clairement définies.

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="Liste de tâches générée avec priorités et dépendances" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="Réviser et affiner">
    Examinez le plan proposé. Posez des questions complémentaires, demandez des modifications ou explorez d&#39;autres approches. Continuez à l&#39;affiner jusqu&#39;à ce qu&#39;il corresponde à votre vision.
  </Step>

  <Step title="Commencer à développer">
    Lorsque le plan vous convient, sélectionnez **Start building**. Agent passe automatiquement en Mode Build et commence à mettre en œuvre les tâches approuvées.

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="Sélecteur de mode affichant les options Plan Mode et Mode Build" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="Suivre la progression">
    Suivez la progression d&#39;Agent à mesure qu&#39;il traite la liste des tâches. Chaque tâche terminée crée un checkpoint, ce qui vous permet d&#39;examiner les modifications et de revenir en arrière si nécessaire.
  </Step>
</Steps>

<div id="when-to-use-each-mode">
  ## Quand utiliser chaque mode
</div>

<CardGroup cols={2}>
  <Card title="Utilisez Plan Mode si" icon="lightbulb">
    * Vous démarrez un nouveau projet et avez besoin d&#39;être guidé
    * Vous souhaitez explorer différentes approches
    * La tâche est complexe et doit être décomposée
    * Vous souhaitez en apprendre davantage avant de vous lancer
    * Vous n&#39;êtes pas sûr de la meilleure solution
  </Card>

  <Card title="Utilisez le Mode Build si" icon="hammer">
    * Vous savez exactement ce que vous voulez
    * Vous avez un plan clair prêt à être exécuté
    * Vous apportez des corrections rapides ou de petites modifications
    * Vous suivez une liste de tâches approuvée
    * La rapidité d&#39;implémentation est prioritaire
  </Card>
</CardGroup>

<Tip>
  **Vous ne savez pas lequel choisir ?** Si votre demande implique plusieurs fonctionnalités ou des modifications importantes, commencez par Plan Mode. Pour les tâches simples et bien définies, passez directement au Mode Build.
</Tip>

<div id="key-differences">
  ## Principales différences
</div>

| Fonctionnalité            | Plan Mode                                            | Mode Build                                |
| ------------------------- | ---------------------------------------------------- | ----------------------------------------- |
| **Objectif**              | Réfléchir, planifier et apprendre                    | Mettre en œuvre et développer             |
| **Modifications du code** | Aucune — lecture seule                               | Écrit et modifie les fichiers             |
| **Résultat**              | Idées, listes de tâches, conseils                    | Code et fonctionnalités opérationnels     |
| **Idéal pour**            | Projets complexes, exploration                       | Tâches clairement définies, mise en œuvre |
| **Transition**            | Cliquez sur « Start building » pour passer à ce mode | Déjà en mode de mise en œuvre             |

<div id="best-practices">
  ## Bonnes pratiques
</div>

<div id="getting-the-most-from-plan-mode">
  ### Tirer le meilleur parti de Plan Mode
</div>

* **Soyez précis dans vos exigences** : plus vous fournissez de détails, meilleur sera le plan
* **Posez des questions complémentaires** : demandez des précisions sur les suggestions que vous ne comprenez pas
* **Demandez des exemples** : demandez à Agent de vous montrer des extraits de code ou des modèles
* **Discutez des compromis** : examinez les avantages et les inconvénients des différentes approches
* **Affinez les idées** : améliorez le plan jusqu’à ce qu’il vous convienne

<div id="seamless-transitions">
  ### Transitions fluides
</div>

* **Vérifiez avant de créer** : examinez toujours la liste des tâches avant d’approuver
* **Commencez petit** : commencez par un sous-ensemble de tâches si le plan complet vous semble trop ambitieux
* **Utilisez les checkpoints** : Agent crée des checkpoints au fur et à mesure qu’il avance, afin que vous puissiez toujours revenir en arrière
