Package Firewall блокирует вредоносные и скомпрометированные пакеты на сетевом уровне — ещё до их установки в ваше приложение. Это часть [Replit Auto-Protect](/ru/ko/features/security/concepts#auto-protect), набора средств защиты, включённых по умолчанию для всех разработчиков; функция работает на основе решения [Socket](https://socket.dev) — компании, специализирующейся на безопасности цепочки поставок программного обеспечения.

Когда вы или Agent выполняете команду установки, например `npm install` или `pip install`, запрос сначала проходит через Package Firewall. Безопасные пакеты устанавливаются как обычно, и вы не заметите никакой разницы. Пакеты, помеченные Socket как вредоносные или скомпрометированные, блокируются до того, как хоть какой-то код попадёт в вашу среду.

Package Firewall **включён по умолчанию для всех разработчиков: ничего настраивать или переносить не нужно**. Он одинаково защищает новые и существующие приложения, и никаких параметров настраивать не требуется.

<div id="section">
  ## Почему важна защита на этапе установки
</div>

Большинство инструментов безопасности цепочки поставок сканируют зависимости только на этапе публикации — то есть спустя долгое время после того, как пакет уже установлен. Для обычных уязвимостей этого может быть достаточно, но с вредоносным кодом всё иначе: он наносит ущерб сразу же при установке — крадёт секреты, открывает бэкдоры, сливает переменные окружения. К тому моменту, когда сканирование на этапе публикации его обнаружит, атака уже состоялась.

Package Firewall закрывает этот пробел. Блокируя вредоносные пакеты ещё до загрузки, он останавливает атаку прежде, чем выполнится хотя бы одна строка вредоносного кода.

<div id="section-2">
  ## Как это работает
</div>

1. Вы или Agent выполняете команду установки, например `npm install <package>` или `pip install <package>`.
2. Запрос проходит через Package Firewall, который проверяет пакет по данным threat intelligence от Socket.
3. Если пакет безопасен, установка проходит как обычно, без каких-либо заметных отличий.
4. Если пакет вредоносный или скомпрометирован, установка блокируется ещё до того, как хоть какой-то код попадёт в вашу среду.

Если что-то заблокировано, вы получите понятное сообщение о том, что и почему было остановлено, а также сведения об уязвимости или политике, вызвавшей блокировку. Agent видит те же сигналы, поэтому может предложить безопасную альтернативу — например, исправить опечатку в имени пакета — или снова передать решение вам.

<div id="section-3">
  ### Поддерживаемые менеджеры пакетов
</div>

Package Firewall защищает установку пакетов для:

* **JavaScript** — npm, yarn, pnpm
* **Python** — pip
* **Go** — модули Go

<div id="package-firewall">
  ## Что обнаруживает Package Firewall
</div>

Package Firewall блокирует не только откровенно вредоносный код, но и версии обычных пакетов — в том числе широко используемых, — которые оказались скомпрометированы или содержат известные уязвимости. Многие из этих уязвимостей были раскрыты уже после даты отсечения обучающих данных модели, которая рекомендует такой пакет, поэтому модель может уверенно предложить версию зависимости, безопасную на момент обучения, но признанную проблемной позже. У таких рисков есть свои названия.

* **Тайпосквоттинг (Typosquats)** — вредоносные пакеты, имена которых отличаются от настоящих на одну букву, например `reqeusts` вместо `requests`. Вы запрашиваете не тот пакет и скачиваете вредоносный код.
* **Слопсквоттинг (Slopsquats)** — модель выдумывает имя несуществующего пакета, а злоумышленник регистрирует пакет ровно с таким именем и ждёт, пока его установит следующий агент.
* **Устаревшие рекомендации (Stale recommendations)** — реальные пакеты, которые модель рекомендует, потому что до даты отсечения обучающих данных они были безопасны, но позже в них нашли уязвимости.

Именно последний тип и объясняет, почему Package Firewall особенно важен для приложений, созданных с помощью ИИ. Агент может уверенно выбрать зависимость, которая уже небезопасна, а Package Firewall остановит установку до того, как этот код будет выполнен.

<div id="package-firewall-replit">
  ## Как Package Firewall связан с другими инструментами безопасности Replit
</div>

Package Firewall — один из трёх взаимодополняющих уровней защиты. Каждый из них защищает приложение на разных этапах жизненного цикла, поэтому используйте их вместе, а не выбирайте какой-то один.

| Уровень                                      | Когда применяется          | Что делает                                                                                                                                                                                                        |
| -------------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Package Firewall**                         | Во время установки         | Блокирует вредоносные и скомпрометированные пакеты до их скачивания (предотвращение).                                                                                                                             |
| **Автоматическое сканирование зависимостей** | После установки, постоянно | Выявляет новые CVE в установленных зависимостях и при необходимости Agent подготавливает исправления. См. [Project Security Center](/ru/ko/features/security/project-security-center#automatic-dependency-scans). |
| **Security Agent**                           | Перед публикацией          | Проверяет всю кодовую базу на уязвимости в коде, зависимостях и обработке персональных данных. См. [Сканирование безопасности Agent](/ru/ko/features/security/agent-security-scans).                                 |
