由于 Replit 会在云环境中运行你的项目，因此端口在 Replit 上的工作方式与本地计算机不同。 (如果你想先了解 TCP 端口的基本概念，请[从这里开始](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/)。) 

在计算机上，端口管理只有一层：程序会定义其监听的端口，当来自互联网的流量到达计算机上的该端口时，就会被路由到相应的进程。

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="计算机" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` 是地址，也称为主机地址。如果某个进程正在监听 `0.0.0.0`，意味着它会在所有网络接口上监听——也就是说，如果另一台计算机通过互联网向你的计算机 IP 地址发送请求，该进程就能接收到请求。因此，监听 `0.0.0.0` 表示这些进程可供公网访问 (前提是你的计算机已联网) 。

出于隐私和安全考虑，大多数编程框架在开发时*不会*监听 `0.0.0.0`，因为你未必希望在工作期间将内容暴露给公众。相反，它们会监听另一个地址——`127.0.0.1`，也称为 `localhost`。这意味着只有这台计算机可以向该端口发出请求。

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Localhost 端口仅对托管它们的计算机可见。" width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

在 Replit 上，要让正在运行的进程能通过 webview 或外部请求访问，必须定义一个**外部端口**。这是因为进程通常使用的“内部端口”只能在 Replit 提供的沙盒云环境内部访问。内部端口必须连接到一个可从外部访问的端口，才能将流量正确地转发到你的程序。即使进程监听的是通常可公开访问的地址 (如 `0.0.0.0`) ，仍需要绑定到外部端口。

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="外部端口会将流量转发到程序监听的内部端口。" width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit 通过将外部端口绑定到特定的内部端口来实现这一点——例如，在上图中，外部端口 `:80` 绑定到内部端口 `:3000`。这意味着 Replit App 在端口 80 收到的所有流量都会转发到内部端口 3000。

此配置记录在 .replit 配置文件的 [[ports]] 部分中。

默认情况下，Replit 会将你打开的第一个端口绑定到默认外部端口 80，使该进程可通过不带端口号的域名访问 (例如 customdomain.com/，而不是 customdomain.com:3000/) 。之后打开的内部端口会绑定到其他可用的外部端口 (完整列表见下方。)

<div id="default-port">
  ## 默认端口
</div>

端口 :80 是 HTTP 流量的“默认端口”，因此发送到根域名的 HTTP 流量会自动路由到端口 80。因此，端口 80 不会显示在 URL 中。除 :`80` 以外的端口会显示在域名路径中 (例如 customdomain.com:4200/) 。 (Replit 默认提供 TLS，因此从技术上讲实际使用的是端口 443，即 HTTPS 的默认端口。你可以将两者视为等同。)

<div id="publishing">
  ## Publishing
</div>

自动扩缩容部署和预留 VM 部署仅支持暴露一个外部端口，且对应的内部端口不能使用 `localhost`。如果暴露多个端口，或在 localhost 上暴露单个端口，已发布的 App 将无法正常运行。要确保自动扩缩容部署按预期运行，可移除配置中所有端口的 `externalPort` 条目，*仅保留*希望通过互联网访问的服务所对应端口的条目。

<div id="debugging">
  ## 调试
</div>

某项功能未能按预期运行的常见原因是：尽管 port 配置 看起来正确，但程序实际监听的却是另一个端口。例如，如果你的配置如下：

```
[[ports]]
internalPort = 3000
externalPort = 80
```

这样，发往 80 端口的互联网流量就会转发到内部的 3000 端口。但如果你的程序实际上并没有监听 3000 端口，而是监听了其他端口 (比如 8080) ，看起来就会像是完全没有流量进来。如果你在代码中改了端口，却没有同步修改配置中对应的端口，或者把配置从一个 project 直接复制粘贴到另一个 project，就可能出现这种情况。

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="程序可能会更改其监听的端口。" width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

不同框架监听的默认端口各不相同——例如 Flask 是 5000，react 是 3000，laravel 是 8000。请确保配置的端口正确！

<div id="preferences">
  ## 偏好设置
</div>

在 Replit App 中打开端口时，Replit 会自动将其绑定到可用的外部端口，并将该绑定记录在 .replit 配置文件中。

不过，默认不会对在 localhost 上打开的内部端口执行此操作，因为通常在 localhost 上运行的服务会假定它们只能由运行该进程的同一台计算机访问 (localhost 端口仅对运行该进程的同一台计算机可见) 。这意味着，与假定可从公共互联网访问而构建的服务相比，这些服务通常安全性较低。

你随时可以通过将要公开的端口的 `exposeLocalhost` 配置选项设为 `true` 来覆盖此设置。

如果想默认*始终*公开 localhost 端口，可以在用户设置工具中将“自动端口转发”设置设为“所有端口”。

如果想*永不*为打开的端口创建配置，并手动控制所有 Replit App 的端口配置，可以将该设置设为“从不”。

<div id="supported-ports">
  ## 支持的端口
</div>

第一个端口开放时，Replit App 默认会将端口 80 设为外部端口。Replit App 还可将 3000、3001、3002、3003、4200、5000、5173、6000、6800、8000、8008、8080、8081 公开为额外的外部端口。

端口 22 和 8283 供内部使用，无法转发。

<div id="ports-replit-config">
  ## `[[ports]]` .replit 配置
</div>

类型：`{localPort, externalPort, exposeLocalhost}`

通过 `[[ports]]` 配置，你可以指定要为 Web 输出暴露的 HTTP 端口。默认情况下，主机为 0.0.0.0 的任何已暴露 HTTP 端口都会作为 Replit App 的 Web 输出。

在 .replit 文件中添加新的 [[ports]] 条目，即可提供额外端口而不覆盖默认端口。必须同时指定 localPort 和 externalPort 条目。按照下方定义，在 .replit 文件中添加多个 [[ports]] 条目即可添加多个额外端口。

<div id="localport">
  ### localPort
</div>

指定 Replit 要绑定到外部端口的本地端口。

<div id="externalport">
  ### externalPort
</div>

指定要为该本地端口公开暴露的端口。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

如果你希望*始终不*暴露某个端口，可以保留 `localPort` 配置，但不添加 `externalPort`：

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

决定使用 `localhost` 的内部端口能否绑定到外部端口。可设为 `true`、`false` 或 null。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
