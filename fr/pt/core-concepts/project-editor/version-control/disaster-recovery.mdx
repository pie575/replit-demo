Replit sauvegarde automatiquement votre dépôt Git pour vous aider à résoudre des problèmes tels que des dossiers `.git` corrompus ou un historique de commits perdu. Ce système de sauvegarde fonctionne en arrière-plan : votre travail est donc protégé sans effort supplémentaire.

<div id="como-funciona">
  ## Comment ça fonctionne
</div>

Chaque Replit App conserve une sauvegarde sécurisée de son dépôt Git. Lorsque Replit Agent modifie le code ou que vous publiez votre app, les modifications sont automatiquement synchronisées avec cette sauvegarde. Si votre dépôt Git local est corrompu ou inutilisable, vous pouvez restaurer l’intégralité de l’historique de vos commits à partir de cette sauvegarde.

<Info>
  Le dépôt distant de sauvegarde s’appelle `gitsafe-backup` et est géré automatiquement par Replit. Vous n’avez rien à configurer : il fonctionne déjà en arrière-plan.
</Info>

<div id="visualizando-seu-histrico-de-backup">
  ## Afficher votre historique de sauvegardes
</div>

Le moyen le plus simple d’afficher votre historique de commits consiste à utiliser le [Git Pane](/fr/pt/core-concepts/project-editor/version-control/git-interface). Ouvrez-le dans la section Tools du Project Editor : il affiche l’intégralité de votre historique de commits, y compris tous les checkpoints d’Agent. Cette méthode convient à la plupart des cas et ne nécessite aucune commande.

Si vous devez inspecter directement le dépôt distant gitsafe-backup, vous pouvez utiliser le Shell :

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

Cela affiche l’historique complet de vos commits, y compris tous les checkpoints de l’Agent et les commits manuels. Vous pouvez l’utiliser pour vérifier que votre travail est bien sauvegardé ou pour retrouver un commit spécifique à restaurer.

<div id="recuperando-de-problemas-no-git">
  ## Résoudre des problèmes Git
</div>

Si vous rencontrez des erreurs Git ou si votre dépôt est corrompu, commencez par le [Git Pane](/fr/pt/core-concepts/project-editor/version-control/git-interface). Il permet de résoudre la plupart des problèmes courants — par exemple, revenir à un commit antérieur ou récupérer les modifications depuis un dépôt distant — sans utiliser de commandes Shell.

Si le Git Pane ne peut pas vous aider, par exemple si le dossier `.git` est entièrement corrompu, suivez les étapes ci-dessous dans le Shell.

<div id="verificar-se-o-backup-est-disponvel">
  ### Vérifier la disponibilité de la sauvegarde
</div>

Commencez par vérifier que le dépôt distant de sauvegarde existe :

```bash theme={null}
git remote -v
```

Recherchez `gitsafe-backup` dans la sortie. S’il est présent, vous pouvez procéder à la récupération.

<div id="restaurar-seu-repositrio">
  ### Restaurer votre dépôt
</div>

<Warning>
  Ce processus remplace votre dossier `.git` actuel par la version sauvegardée. Vos fichiers de travail restent inchangés, mais votre historique Git local sera remplacé par celui de la sauvegarde.
</Warning>

<Steps>
  <Step title="Sauvegarder votre configuration Git actuelle">
    Sauvegardez le fichier de configuration Git si vous utilisez des paramètres personnalisés :

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Cloner le dépôt de sauvegarde">
    Créez un clone temporaire à partir de la sauvegarde :

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Remplacer votre dossier Git">
    Mettez de côté votre dossier `.git` corrompu, puis remplacez-le par la sauvegarde :

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Restaurer votre configuration">
    Restaurez votre configuration Git :

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

Une fois ces étapes terminées, exécutez `git status` pour vérifier que votre dépôt fonctionne correctement.

<div id="soluo-de-problemas-comuns">
  ## Résolution des problèmes courants
</div>

<div id="fatal-repository-not-found-ou-remote-de-backup-ausente">
  ### &quot;fatal: repository not found&quot; ou dépôt distant de sauvegarde manquant
</div>

Le système de sauvegarde peut ne pas être activé pour les projets plus anciens. Contactez l’assistance si vous avez besoin d’aide pour récupérer un projet plus ancien.

<div id="a-recuperao-no-incluiu-commits-recentes">
  ### La restauration n’a pas inclus les commits récents
</div>

Les sauvegardes sont synchronisées après chaque commit effectué par Agent. Si vous avez apporté des modifications sans les commiter, elles ne figureront pas dans la sauvegarde. Vérifiez votre répertoire de travail pour repérer les fichiers non commités.

<div id="operaes-git-esto-lentas-ou-travadas">
  ### Les opérations Git sont lentes ou bloquées
</div>

Si les opérations Git ne répondent plus, il se peut qu’un fichier de verrouillage obsolète soit présent. Vous pouvez le supprimer en toute sécurité :

```bash theme={null}
rm -f .git/index.lock
```

<div id="prevenindo-perda-de-dados">
  ## Prévenir la perte de données
</div>

Bien que le système de sauvegarde protège automatiquement votre historique Git, vous pouvez prendre des mesures supplémentaires pour protéger votre travail :

* **Effectuez des commits régulièrement** : effectuez des commits petits et fréquents afin que votre progression soit continuellement sauvegardée.
* **Utilisez des checkpoints** : lorsque vous travaillez avec [Replit Agent](/fr/pt/core-concepts/agent), les checkpoints créent automatiquement des commits aux étapes importantes.
* **Connectez GitHub** : pour les projets critiques, [connectez votre app à GitHub](/fr/pt/getting-started/quickstarts/import-from-github) afin d&#39;ajouter une couche de sauvegarde supplémentaire.
