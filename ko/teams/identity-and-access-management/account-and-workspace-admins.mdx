<Info>
  **이 페이지는 Enterprise plan에만 해당합니다.** account admin과 workspace admin이 별도의 역할로 구분되는 것은 Enterprise에서만 적용됩니다.

  **Core** 및 **Pro** plan에서는 계정에 **account admin**(일반적으로 계정 소유자) 한 명만 있으며, 별도의 workspace admin 역할은 없습니다. Core나 Pro를 사용 중이라면 [멤버 관리](/ko/teams/identity-and-access-management/managing-members)와 [역할, 그룹 및 액세스](/ko/teams/identity-and-access-management/groups-and-permissions)를 참고하세요. 해당 문서에서 설명하는 **Admin** 역할이 곧 account admin입니다.
</Info>

Enterprise plan에서 Replit은 관리 책임을 **account admin**과 **workspace admin**이라는 두 가지 역할로 분리합니다. 이렇게 역할을 나누면 billing과 계정 전체에 대한 권한까지 넘기지 않고도 특정 workspace 하나에 대한 전체 제어 권한을 부여할 수 있습니다. 이 페이지에서는 각 역할의 기능과 차이점, 그리고 설정 방법을 설명합니다.

<div id="how-the-two-roles-relate">
  ## 두 역할의 관계
</div>

Replit **account**는 구독, 좌석, 그리고 하나 이상의 **workspaces**(조직)를 소유하는 billing 주체입니다. Enterprise 계정은 workspace를 두 개 이상 포함할 수 있습니다. 두 관리자 역할은 이 두 가지 범위에 각각 대응합니다.

* **Account admin**은 계정 전체를 관리합니다. billing을 관리하며, 계정에 속한 모든 workspace에 대한 관리 권한을 가집니다.
* **Workspace admin**은 자신이 속한 특정 workspace만 관리합니다. billing 권한이 없고 다른 workspace도 제어할 수 없습니다.

모든 account admin은 계정에 속한 모든 workspace에서 자동으로 관리자가 되므로, account admin은 사실상 workspace admin의 상위 집합이라고 할 수 있습니다. 반면 workspace admin은 account admin이 아니므로 billing이나 다른 workspace를 관리할 수 없습니다.

<CardGroup cols={2}>
  <Card title="Account admin" icon="building-shield">
    계정 전체 범위. billing, 좌석, 보안 설정과 계정에 속한 모든 workspace를 관리합니다.
  </Card>

  <Card title="Workspace admin" icon="user-shield">
    Workspace 범위. 자신이 속한 workspace 내의 멤버와 리소스만 관리합니다.
  </Card>
</CardGroup>

<div id="what-each-role-can-do">
  ## 각 역할이 할 수 있는 일
</div>

두 역할 모두 workspace를 관리하지만, *어떤* workspace를 관리하는지가 다릅니다. account admin은 계정에 속한 모든 workspace를 관리하고, workspace admin은 자신이 속한 workspace만 관리합니다.

| 기능                                | Account admin | Workspace admin |
| --------------------------------- | :-----------: | :-------------: |
| 관리 대상 workspace의 멤버 관리            |       예       |        예        |
| 관리 대상 workspace의 앱, group, 리소스 관리 |       예       |        예        |
| billing, 결제 수단, 인보이스 조회 및 수정      |       예       |       아니요       |
| 구독 수정, 취소, 복원                     |       예       |       아니요       |
| 좌석 추가, 제거, 할당                     |       예       |       아니요       |
| 지출 및 usage limit 설정               |       예       |       아니요       |
| 새 workspace 생성                    |       예       |       아니요       |
| 다른 account admin 관리               |       예       |       아니요       |
| 계정에 속한 모든 workspace 관리            |       예       |       아니요       |
| SAML, SCIM, audit logs, 보안 담당자 구성 |       예       |       아니요       |

workspace admin의 관리 권한은 자신의 workspace로 한정되는 반면, account admin은 계정 전체에 대한 모든 관리 권한을 갖습니다.

<Note>
  billing, 좌석 관리, 구독 변경, 계정 전체 보안 설정에는 account admin 권한이 필요합니다. workspace admin은 자신의 workspace 안에서도 이러한 작업을 수행할 수 없습니다.
</Note>

<div id="configuring-account-admins">
  ## account admin 구성
</div>

account admin은 설정의 **Seats** tab에서 관리합니다. account admin을 추가하면 계정 전체에 대한 관리 권한이 부여되며, 해당 사용자는 계정에 속한 모든 workspace에서 자동으로 admin이 됩니다.

<div id="promote-a-member-to-account-admin">
  ### 멤버를 account admin으로 승격하기
</div>

<Steps>
  <Step title="Seats 탭 열기">
    설정에서 **Seats** 탭을 엽니다. 이 탭에는 계정에 속한 사용자와 각자의 현재 역할이 표시됩니다.
  </Step>

  <Step title="멤버 승격하기">
    승격할 멤버를 찾아 작업 메뉴를 열고 **Promote to account admin**을 선택합니다. 변경 사항은 즉시 적용됩니다.
  </Step>
</Steps>

<div id="demote-an-account-admin">
  ### account admin 강등
</div>

account admin을 강등하면 계정 전체 권한과 billing 접근 권한이 사라집니다. 기본적으로 강등하더라도 해당 사용자가 workspace에서 제거되지는 않으며, account admin 여부와 관계없이 workspace 접근 권한은 그대로 유지됩니다.

<Steps>
  <Step title="Seats 탭 열기">
    설정에서 **Seats** tab을 엽니다.
  </Step>

  <Step title="account admin 강등하기">
    해당 account admin을 찾아 작업 메뉴를 열고 **Demote from account admin**을 선택합니다. 변경 사항은 즉시 적용됩니다.
  </Step>
</Steps>

계정이 관리 권한을 잃지 않도록 다음과 같은 규칙이 적용됩니다.

* 자기 자신은 강등할 수 없습니다.
* 마지막 남은 account admin은 제거할 수 없습니다. 계정에는 항상 account admin이 최소 한 명 있어야 합니다.
* 개인 계정의 소유자는 강등할 수 없습니다.

<div id="scim-provisioned-admins">
  ### SCIM으로 프로비저닝된 관리자
</div>

[SCIM](/ko/teams/identity-and-access-management/scim)을 통해 사용자를 프로비저닝하는 경우, ID 제공업체에서 **Admin** 역할이 할당된 사용자는 **account admin**이 됩니다. workspace 범위로 한정된 관리자를 만들려면 ID 제공업체가 아닌 Replit에서 **Workspace admin** 역할을 할당하세요.

<div id="configuring-workspace-admins">
  ## workspace admin 설정
</div>

계정 전체 권한이나 billing 접근 권한 없이 특정 workspace에 대한 전체 관리 권한만 부여하려면 workspace admin 역할을 할당하세요. 팀 리더가 자신의 workspace는 직접 운영하되 구독이나 다른 팀은 관리하지 않도록 할 때 유용합니다.

<Steps>
  <Step title="workspace 멤버 목록 열기">
    관리자를 지정할 workspace를 연 다음 해당 workspace의 **Members** 페이지로 이동합니다.
  </Step>

  <Step title="멤버의 역할을 Workspace admin으로 설정">
    해당 멤버를 찾아 역할 선택기를 열고 **Workspace admin**을 선택합니다. 그러면 해당 멤버는 그 workspace로만 범위가 한정된 관리 권한을 갖게 됩니다.
  </Step>
</Steps>

<Note>
  workspace admin의 권한은 본인이 속한 workspace까지만 적용됩니다. billing에 접근하거나 좌석을 관리하거나 다른 workspace를 관리할 수는 없으며, 이러한 작업에는 account admin 권한이 필요합니다.
</Note>

<div id="choosing-the-right-role">
  ## 적합한 역할 선택하기
</div>

* billing을 담당하거나 구독과 좌석을 관리하는 사람, 보안 설정을 구성하는 사람, 또는 모든 workspace를 총괄해야 하는 사람에게는 **account admin**을 할당하세요.
* 단일 팀이나 workspace를 운영하면서 billing이나 다른 workspace에는 관여하지 않고 해당 workspace의 멤버와 리소스만 관리하면 되는 사람에게는 **workspace admin**을 할당하세요.
