App Testing 让 Agent 能够在真实浏览器中测试自己构建的应用。Agent 会像真实用户一样浏览你的应用，点击操作并验证各项功能。这种自我测试能力有助于确保应用正常运行，也让 Agent 能够自动发现并修复问题。

启用 App Testing 后，Agent 会定期判断是否需要测试：当它认为改动已积累到值得测试时才会执行。Agent 不会在每条用户消息之后都进行测试，而是智能判断何时测试最有价值。

<Note>
  目前，App Testing 支持 JavaScript 全栈 Web 应用和 Python Streamlit Web 应用。
</Note>

<div id="principais-benefcios">
  ### 主要优势
</div>

* **更长的自主运行时间**：让 Agent 无需人工干预即可持续工作更长时间
* **更高的质量**：及早发现并解决问题，产出错误更少的应用
* **节省成本**：在开发过程中就发现问题，免去额外的调试环节
* **交互式复查**：提供视频回放和逐节浏览功能，便于详细分析结果

<div id="o-processo-de-teste">
  ### 测试流程
</div>

当 Agent 决定进行测试时，会发生以下情况：

1. **浏览器预览**：你会在 Agent 面板中看到一个浏览器预览窗口
2. **可视化测试**：你可以看到 Agent 的光标在应用中逐一点击，测试各项功能
3. **真实用户模拟**：Agent 会像真实用户一样浏览应用，并在需要时填入模拟数据
4. **自动分析**：Agent 会分析测试结果，找出存在的问题
5. **自动修复**：Agent 会汇报测试结果摘要，并自动修复发现的问题

<div id="principais-capacidades">
  ## 核心能力
</div>

Agent 会像真实用户一样浏览你的应用，智能地完成测试，涵盖：

* **用户界面验证**：按钮、表单、导航和视觉元素
* **功能验证**：核心功能和用户流程
* **集成测试**：API 调用、数据库交互和第三方服务
* **性能与无障碍**：加载时间、响应速度和无障碍标准

<div id="uso">
  ## 使用
</div>

App Testing 位于 Chat 输入框中 Agent 设置下拉菜单的**高级设置**内。使用 Economy 或 Power 模式时可将其启用。Lite 模式下 App Testing 始终处于关闭状态。

<Note>
  App Testing 是 Agent 自主能力的一部分。详细了解[代码审查](/zh/pt/features/agent/agent-modes#code-review)和其他 [Agent 功能](/zh/pt/features/agent/overview)。
</Note>

<div id="assumir-controle">
  ## 接管控制
</div>

有时 Agent 在测试过程中会遇到障碍，需要你的帮助才能继续。大多数情况下是需要登录某个用户账户 (例如 Gmail) 。此时，Agent 会显示一个「开始接管」按钮。

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="App Testing 的接管界面，显示「跳过」和「开始接管」按钮，以及处理错误和 CAPTCHA 的说明" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

点击「开始接管」后，你可以在测试预览中进行操作，完成所需步骤，再让 Agent 继续。你也可以点击「跳过」以跳过接管；如果 Agent 缺少你的帮助便无法继续，App Testing 就会结束。如果你在 10 分钟内没有响应，Agent 会按你点击了「跳过」来继续。

<div id="o-que-esperar">
  ### 预期效果
</div>

* **跳过选项**：如有需要，可点击跳过按钮略过测试，继续进行开发
* **交互式视频回放**：测试完成后，点击视频即可回放整个测试会话
* **分段导航**：使用底部的滑块可跳转到测试的特定环节

<div id="soluo-de-problemas">
  ## 故障排除
</div>

**测试意外失败**

* 尝试跳过后重新发起测试请求
* 检查是否存在可能影响测试时序的动态内容
* 复查测试场景是否准确

**测试覆盖不全**

* 更详细地描述你的应用功能
* 明确指出必须测试的关键用户流程

**App Testing 无法运行？**

* 目前 App Testing 仅支持 Web 应用[*](#how-app-testing-works)

<div id="preos-e-uso">
  ## 定价与使用
</div>

App Testing 包含在 Agent 基于工作量的定价模式中，但有几点重要的成本注意事项：

* **按用量计费**：测试按实际消耗的工作量计费 (越简单的测试费用越低)
* **成本与收益**：测试虽然会产生费用，但能更早发现错误，省去额外的 prompt 和 Agent 的额外工作，从而节省成本
* **高效开发**：自动化方式减少了手动调试和返工

<Tip>
  **经济高效的测试**：App Testing 虽然会增加你的使用成本，但总体上通常更省钱，因为它免去了为修复本可在测试阶段发现的问题而额外调用 Agent 的开销。
</Tip>

<div id="prximos-passos">
  ## 后续步骤
</div>

准备好在你的项目中使用 App Testing 了吗？

1. **开始构建**：用 Agent 创建应用，测试会自动启用
2. **查看结果**：查阅测试报告，并落实其中的改进建议
3. **迭代优化**：根据测试反馈完善你的应用
4. **规模扩展**：将 App Testing 用于更大、更复杂的项目
