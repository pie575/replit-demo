이 답변은 프로젝트 및 파일 작업을 다룹니다. 관련 참조는 [시크릿](/ko/core-concepts/project-editor/app-setup/secrets), [체크포인트 및 롤백](/ko/features/version-control/checkpoints-and-rollbacks), [통합 개요](/ko/features/integrations/overview)를 참조하세요.

<AccordionGroup>
  <Accordion title="Replit 앱에 Resend 또는 다른 이메일 서비스를 어떻게 연결하나요?">
    프로젝트를 열고 **도구 → 커넥터**로 이동하여 서비스(예: Resend)를 찾아 연결하세요. 인증 후 API 키가 프로젝트의 시크릿으로 저장됩니다. 커스텀 이메일 도메인을 설정하는 경우 서비스에서 보여주는 DNS 레코드를 DNS 제공업체에 추가하세요.

    사용 가능한 커넥터는 [통합 개요](/ko/features/integrations/overview) 및 [통합 추가](/ko/build/add-integrations)를 참조하세요.
  </Accordion>

  <Accordion title="실수로 프로젝트를 삭제했습니다—복구할 수 있나요?">
    삭제된 프로젝트는 제한된 시간 동안 복원할 수 있습니다. 프로젝트의 Shell을 열고 실행하세요:

    ```bash theme={null}
    trash view
    trash restore your-project-name
    ```

    보존 기간이 지나면 삭제된 프로젝트는 영구적으로 제거됩니다. 기간이 지난 경우 [Replit 지원팀에 문의](https://replit.com/support)하세요.
  </Accordion>

  <Accordion title="Replit 프로젝트를 어떻게 다운로드하거나 내보내나요?">
    파일 트리 상단의 세 점 메뉴를 선택하고 **zip으로 다운로드**를 선택하세요. 대형 프로젝트의 경우 다운로드가 잠시 걸릴 수 있습니다. 실패하면 Shell을 열고 `zip -r project.zip .`를 실행한 다음 파일 트리에서 `project.zip`을 다운로드하세요.
  </Accordion>

  <Accordion title="프로젝트를 공유하거나 협력자를 추가하려면 어떻게 하나요?">
    세 가지 옵션이 있습니다:

    * **읽기 전용**—프로젝트 개인 정보 보호를 공개로 설정하면 링크가 있는 누구나 볼 수 있습니다.
    * **초대로 편집 액세스**—**초대**를 선택하고 사용자 이름 또는 이메일을 입력하여 권한 수준을 설정합니다.
    * **참여 링크**—**초대**에서 참여 링크를 만들면 링크가 있는 누구나 참여하고 편집할 수 있습니다.

    Core는 최대 5명, Pro는 최대 15명의 협력자를 지원합니다. 협력자는 프로젝트를 편집하는 데 유료 플랜이 필요하지 않습니다. [워크스페이스](/ko/features/collaboration/workspaces)를 참조하세요.
  </Accordion>

  <Accordion title="Replit에 GitHub 저장소를 어떻게 연결하나요?">
    계정의 연결된 서비스에서 GitHub 계정을 연결한 다음 프로젝트에서 [Git 도구](/ko/features/workspace-tools/git-interface)를 열고 저장소를 연결하세요. 양방향 동기화를 위해 Git 창에서 자동 동기화를 켜세요. 기존 저장소를 가져오려면 [제공업체에서 가져오기](/ko/build/import-from-providers)를 참조하세요.

    Git 동기화가 중단되면 연결된 서비스에서 GitHub를 다시 연결하세요. 세분화된 개인 액세스 토큰을 사용하면 더 안정적인 연결이 제공됩니다.
  </Accordion>

  <Accordion title="Repl이 느리게 실행되거나 편집기가 지연됩니다—무엇을 시도해 볼 수 있나요?">
    편집기 지연의 경우 다음을 시도하세요:

    * Mac은 `Cmd+Shift+R`, Windows는 `Ctrl+Shift+R`로 강제 새로고침하세요.
    * 사용하지 않는 파일 탭을 닫으세요.
    * `Cmd+K`(Mac) 또는 `Ctrl+K`(Windows)로 명령 팔레트를 열고 **Restart compute**를 검색하여 선택하세요.
    * 다른 브라우저를 시도하여 확장 프로그램을 배제하세요.

    편집기 지연이 아닌 느린 코드 실행의 경우 무거운 루프나 메모리 제한을 확인하세요. 편집기 하단의 리소스 패널에서 CPU 및 메모리 사용량을 확인할 수 있습니다.
  </Accordion>

  <Accordion title="프로젝트에서 환경 변수와 시크릿을 어떻게 사용하나요?">
    **시크릿** 도구(잠금 아이콘)를 열고 **+ 새 시크릿**을 선택한 다음 키와 값을 입력하세요. 코드에서 `process.env.API_KEY`(Node.js) 또는 `os.environ["API_KEY"]`(Python)으로 읽으세요.

    개발 [시크릿](/ko/core-concepts/project-editor/app-setup/secrets) 창의 시크릿은 편집기에서만 사용 가능합니다. 배포된 앱의 경우 동일한 키를 배포 시크릿에 추가하세요—설계상 별도로 유지됩니다.
  </Accordion>

  <Accordion title="계정 시크릿(Vault)을 어떻게 사용하나요?">
    [계정 시크릿](/ko/core-concepts/project-editor/app-setup/secrets)은 모든 프로젝트에서 사용 가능합니다—재사용하는 키에 유용합니다. 계정 설정에서 추가하면 모든 프로젝트에서 사용 가능합니다. 계정 시크릿과 프로젝트 시크릿 창 모두에 동일한 키가 있는 경우 프로젝트 수준 값이 우선합니다.
  </Accordion>

  <Accordion title="Git 병합 충돌이나 손상된 Git 상태에서 어떻게 복구하나요?">
    Shell을 열고 `git status`를 실행하여 충돌을 확인하세요.

    <Warning>다음 두 명령은 커밋되지 않은 변경 사항을 삭제하며 취소할 수 없습니다. 먼저 보관하고 싶은 것을 저장하세요—예를 들어 편집된 파일을 프로젝트 밖으로 복사하세요.</Warning>

    로컬 변경 사항을 버리고 마지막으로 정리된 상태로 돌아가려면 `git checkout -- .`를 실행하고, 마지막 커밋으로 재설정하려면 `git reset --hard HEAD`를 실행하세요.

    `.git` 폴더가 손상되어 Git 명령이 실패하면 새 Agent 채팅을 열고 오류를 붙여넣으세요—Agent가 저장소를 복구할 수 있는 경우가 많습니다. [재해 복구](/ko/features/version-control/disaster-recovery)를 참조하세요.
  </Accordion>

  <Accordion title="프로젝트를 이전 체크포인트로 롤백하려면 어떻게 하나요?">
    Replit은 Agent가 작업하는 동안 [체크포인트](/ko/features/version-control/checkpoints-and-rollbacks)를 저장합니다. Agent 패널에서 취소하려는 변경 이전의 메시지를 찾아 옆의 롤백 옵션을 선택한 다음 확인하세요.

    <Note>
      Replit은 게시된 앱을 이전 버전으로 롤백하는 기능을 더 이상 지원하지 않습니다. 게시된 앱을 되돌리려면 (위에서 설명한 대로) 프로젝트를 이전 체크포인트로 롤백한 다음 다시 게시하여 해당 상태를 재배포하세요. 단일 파일을 복구하려면 파일을 열고 파일 이름을 선택한 다음 **히스토리 보기**를 사용하여 이전 버전을 복원하세요. [파일 히스토리](/ko/features/version-control/file-history)를 참조하세요.
    </Note>
  </Accordion>

  <Accordion title="다른 Replit 계정으로 프로젝트를 이동하려면 어떻게 하나요?">
    프로젝트는 직접 이전할 수 없지만 복사할 수 있습니다. 가장 쉬운 방법은 대상 계정과 프로젝트를 공유하고 그곳에서 포크하는 것입니다. 또는 프로젝트를 zip으로 다운로드하여 다른 계정의 새 Repl에 다시 업로드하세요.

    복사 후 새 프로젝트에서 시크릿, 데이터베이스, 배포 설정을 설정하세요—이것들은 복사본에 포함되지 않습니다. 데이터베이스 데이터를 이전하는 방법을 포함한 단계별 지침은 [다른 워크스페이스로 프로젝트를 수동으로 복사하기](/ko/teams/identity-and-access-management/manually-copy-projects)를 참조하세요.
  </Accordion>
</AccordionGroup>
