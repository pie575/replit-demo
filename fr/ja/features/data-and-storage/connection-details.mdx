Votre application se connecte à la base de données à l’aide d’identifiants gérés par Replit. Pour les consulter, sélectionnez la base de données dans l’outil **Database**, puis ouvrez l’onglet **paramètres**. La chaîne de connexion, l’espace de stockage utilisé et des informations détaillées sur la connexion s’affichent.

<div id="section">
  ## Variables d&#39;environnement
</div>

Les variables d&#39;environnement suivantes permettent de se connecter à la base de données de développement.

* `DATABASE_URL` : la méthode de connexion et d&#39;authentification à la base de données

Votre application l&#39;utilise automatiquement. Comme `DATABASE_URL` est propre à chaque application, la base de données de développement n&#39;est accessible ni depuis d&#39;autres applications (même celles qui vous appartiennent), ni depuis un visualiseur de bases de données externe. Même en cas de fuite, personne ne pourrait s&#39;en servir pour accéder à la base de données ou la modifier.

<Info>
  Si votre base de données de développement se trouve encore sur [l&#39;ancienne infrastructure Neon](/fr/ja/features/data-and-storage/development-and-production#legacy-development-database), les variables supplémentaires `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` et `PGPORT` sont également disponibles. Elles ne sont **pas** fournies pour les bases de données hébergées sur l&#39;infrastructure actuelle de Replit. Dans ce cas, utilisez `DATABASE_URL`.
</Info>

<Warning>
  Si vous utilisez encore une ancienne base de données de développement Neon, ne partagez pas `DATABASE_URL`. Elle contient les identifiants de la base de données, ce qui permet à quiconque d&#39;y accéder et de la modifier. Ne la collez pas dans un espace public ni dans un ticket de support.
</Warning>

<div id="section-2">
  ## Connecter des outils externes
</div>

Vous pouvez vous connecter à la base de données **production** depuis un client SQL compatible avec PostgreSQL à l’aide de la chaîne de connexion disponible dans l’onglet **paramètres** de la base de données **production**.

<div id="section-3">
  ## Sécurité
</div>

Lorsque vous ajoutez une intégration de base de données avec Agent, un ORM (Object-Relational Mapper) est ajouté pour gérer l&#39;ensemble des communications avec la base de données, ce qui offre une sécurité intégrée :

* **Validation du schéma** : vérifie que les données respectent le format attendu
* **Nettoyage des données** : nettoie automatiquement les entrées du builder afin de prévenir les attaques par injection SQL

<div id="section-4">
  ## Régénérer les identifiants de la base de données de production
</div>

Si votre chaîne de connexion de production a été compromise, régénérez les identifiants dans l’outil Database. Cette opération crée un nouveau mot de passe pour la base de données de production Neon. Les chaînes de connexion de production existantes cessent immédiatement de fonctionner.

Vous pouvez régénérer les identifiants si toutes les conditions suivantes sont remplies :

* L’application possède une base de données de production Neon.
* Vous êtes propriétaire de l’application ou administrateur de l’espace de travail propriétaire.
* Vous utilisez Replit dans un navigateur web.
* Aucun déploiement n’est en cours.
* Si l’application dispose d’un déploiement en ligne, sa dernière compilation s’est terminée avec succès et utilise [Autoscale ou Reserved VM](/fr/ja/features/publishing/deployment-types).

<Warning>
  Cette opération est irréversible. Les chaînes de connexion existantes cessent immédiatement de fonctionner. Si l’application dispose d’un déploiement en ligne, elle peut être temporairement indisponible pendant son redéploiement.
</Warning>

<div id="section-5">
  ### Régénérer les identifiants
</div>

1. Dans le panneau Tools, sélectionnez **Database**.

2. Sélectionnez **Production Database**, puis l&#39;onglet **paramètres**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="Onglet paramètres de la base de données de production affichant la section Advanced avec la chaîne de connexion, l'utilisation du stockage et la ligne Regenerate credentials" width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. Sous **Advanced**, développez la ligne **Regenerate credentials**.

4. Sélectionnez le bouton **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Ligne Regenerate credentials développée dans la section Advanced, affichant le bouton Regenerate credentials" width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. Dans la boîte de dialogue de confirmation, sélectionnez **Regenerate credentials** pour valider.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="Boîte de dialogue de confirmation Regenerate credentials avertissant que cette action est irréversible et que les chaînes de connexion existantes deviennent immédiatement inutilisables" width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Sélectionnez **Refresh** pour charger la nouvelle chaîne de connexion.

7. Si votre application dispose d&#39;un déploiement en ligne, ouvrez **Publishing** pour vérifier l&#39;état du redéploiement.

8. Remplacez toutes les chaînes de connexion que vous avez copiées dans des outils externes ou des intégrations personnalisées.

<div id="section-6">
  ### Éléments modifiés
</div>

La régénération des identifiants crée un nouveau mot de passe pour la base de données de production. Seule la partie correspondant au mot de passe de la chaîne de connexion est modifiée. L’hôte, le nom de la base de données et le rôle ne changent pas.

Pour les déploiements en ligne pris en charge, Replit redéploie la dernière version compilée avec succès à l’aide de la chaîne de connexion mise à jour.
