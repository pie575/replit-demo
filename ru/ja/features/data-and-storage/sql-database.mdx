База данных Replit — это полностью управляемая база данных SQL, которая позволяет добавить постоянное хранилище данных в Replit App прямо из редактора проекта.

<Note>
  Проще всего начать так: попросите **Agent** добавить базу данных в ваше приложение. Agent настроит интеграцию, создаст схему базы данных и обновит приложение так, чтобы оно сохраняло и считывало данные.
</Note>

<div id="section">
  ## Возможности
</div>

Инструменты Replit для работы с базами данных предоставляют следующие возможности:

* **Инструменты баз данных**: выполняйте запросы во встроенном SQL-инструменте, управляйте схемой базы данных и визуализируйте данные
* **Путешествие во времени**: восстанавливайте базу данных до любого чекпоинта **Agent**. Подробнее см. в разделе [Восстановление данных](/ru/ja/features/data-and-storage/data-recovery)
* **Бесплатное хранилище**: каждое Replit App включает 20 ГБ бесплатного хранилища
* **Переменные окружения**: безопасно обращайтесь к базе данных из Replit App с помощью переменных окружения

<Info>
  До 4 декабря 2025 года базы данных разработки размещались в Neon и имели ряд важных отличий.
  Подробнее см. в разделе [Разработка и продакшн](/ru/ja/features/data-and-storage/development-and-production#legacy-development-database).
</Info>

<div id="section-2">
  ## Как использовать
</div>

<YouTubeEmbed videoId="zbyRuoPNIc8" title="Как работать с базами данных в Replit" />

Открыть инструмент баз данных Replit можно прямо из редактора проекта.
В следующих разделах описано, как настраивать базы данных и управлять ими.

<Accordion title="Как открыть инструмент баз данных">
  1. Откройте панель **Tools** и выберите **Database** в разделе **Replit Cloud**.
  2. На стартовом экране отображается список баз данных. Выберите нужную, например **Development Database**, чтобы открыть её.
</Accordion>

Инструмент баз данных построен вокруг списка баз данных. На стартовом экране показан объём хранилища, используемый каждой базой данных, а также текущие **Billing Period** и **Hours of Compute Used**. При открытии базы данных доступны три вкладки:

* **Overview** — таблицы в базе данных.
* **My Data** — просмотр и редактирование строк, выполнение SQL-запросов.
* **Settings** — строка подключения, объём хранилища и параметры подключения.

<div id="section-3">
  ### Добавление базы данных
</div>

Каждое Replit App по умолчанию поставляется с базой данных. Получить к ней доступ можно с помощью инструмента <img class="icon-svg" src="/assets/mirror/postgres-c4cb2a1e2de3.svg" alt="Значок базы данных PostgreSQL" width="24" height="24" data-path="images/icons/postgres.svg" /> **База данных** в редакторе проекта.

Чтобы интегрировать базу данных, попросите **Agent** добавить базу данных PostgreSQL в ваше Replit App и укажите, какие данные должно хранить приложение. Agent создаст схему базы данных и обновит приложение так, чтобы оно взаимодействовало с базой данных.

<div id="section-4">
  ### Функции безопасности
</div>

Когда вы добавляете интеграцию с базой данных с помощью **Agent**, вместе с ней добавляется объектно-реляционный преобразователь (ORM), который отвечает за обмен данными с базой данных и обеспечивает встроенную защиту.

Слой ORM в сочетании с рекомендуемыми практиками безопасности, которые применяет Agent, защищает ваше приложение от атак за счёт следующих возможностей:

* **Проверка схемы**: данные проверяются на соответствие ожидаемому формату
* **Очистка данных**: вводимые в конструкторе данные автоматически очищаются, что предотвращает атаки с внедрением SQL-кода

<div id="section-5">
  ## Дальнейшие шаги
</div>

До 4 декабря 2025 года базы данных разработки размещались на <a href="https://neon.com/" target="_blank">Neon</a>.
Эти базы данных выводятся из эксплуатации, и все новые базы данных разработки размещаются на собственной инфраструктуре баз данных Replit.

Проверить, размещена ли ваша база данных разработки на Neon, можно по [переменной окружения](#view-connection-credentials-and-usage) `DATABASE_URL`.

<Info>
  Если `DATABASE_URL` содержит `neon.tech/neondb`, ваша база данных разработки всё ещё размещена на Neon.
  Если она содержит `helium/heliumdb`, база данных разработки размещена на Replit.
</Info>

Ниже приведены основные различия между устаревшими базами данных разработки Neon и новыми базами данных разработки Replit:

| **Возможность**                | **Replit (сейчас)**                                                                                                                                              | **Neon (устаревшее решение)**                                                                                                          |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Хостинг**                    | Размещается на собственной инфраструктуре Replit                                                                                                                 | Размещается на Neon (сторонний поставщик)                                                                                              |
| **Оплата**                     | Бесплатно включена в каждое Replit App                                                                                                                           | Оплата по использованию. Подробнее см. [Публикация и оплата баз данных](/ru/ja/billing/about-usage-based-billing#databases).              |
| **Возможности восстановления** | С помощью [функции отката](/ru/ja/features/version-control/checkpoints-and-rollbacks/) можно восстановить базу данных до любого чекпоинта                           | Восстановление на момент времени (PITR) — до любой точки в пределах срока хранения резервных копий.                                    |
| **Безопасность подключения**   | Доступ возможен только изнутри приложения, база данных никогда не публикуется в открытом доступе.                                                                | Используется полная строка подключения — при её утечке любой может получить доступ к базе данных и изменить её.                        |
| **Поведение при ремиксе**      | При [ремиксе](/ru/ja/features/projects-and-artifacts/remix-an-app) создаётся новая база данных разработки с копией данных — для изоляции и безопасности.            | Ремикс использует одну и ту же базу данных во всех копиях, поэтому изменения в ремиксе могут повлиять на исходное приложение.          |
| **Создание базы данных**       | Создаётся автоматически для каждого Replit App.                                                                                                                  | Требовалась отдельная настройка.                                                                                                       |
| **Процесс публикации**         | Для развёртывания или публикации требуется создать [производственную базу данных](/ru/ja/features/data-and-storage/development-and-production) для разделения сред. | Разработка и продакшен использовали одну базу данных, поэтому случайные изменения при разработке могли повлиять на рабочее приложение. |

<Warning>
  Если ваше приложение было форкнуто или ремикшено во время использования устаревшей базы данных Neon, опубликованное приложение может по-прежнему ссылаться на URL базы данных исходного приложения. После [обновления базы данных](/ru/ja/features/data-and-storage/development-and-production) это общее подключение перестанет работать. О том, как обновить опубликованное приложение, см. [Исправление опубликованных приложений с общей базой данных](/ru/ja/features/data-and-storage/shared-database-migration).
</Warning>
