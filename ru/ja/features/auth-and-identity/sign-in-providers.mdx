title: "Провайдеры входа"
description: "Настройте собственные учётные данные OAuth для входа через Google, GitHub, Apple и X в приложениях, использующих Clerk Auth."
---

Если ваш App использует [Clerk Auth](/ru/ja/features/auth-and-identity/clerk-auth), посетители могут входить через социальных провайдеров. Replit предоставляет общие учётные данные, готовые к работе сразу, но на этой странице описано, как подключить **собственные** учётные данные OAuth для каждого провайдера. Тогда на экране входа будут отображаться название и фирменный стиль вашего App.

Порядок действий одинаков для всех провайдеров: создайте приложение OAuth в консоли провайдера, скопируйте URL-адреса, которые показывает Replit, и вставьте полученные учётные данные в панель редактирования провайдера.

<Note>
  Собственные учётные данные OAuth доступны только в среде **Production**, поэтому App нужно предварительно [опубликовать](/ru/ja/features/publishing/overview). Панель редактирования каждого провайдера открывается на вкладке **Configure** инструмента **Users &amp; Auth**, в разделе **SSO providers**. Выберите среду **Production**, затем нажмите **Edit** рядом с нужным провайдером. Общий обзор процесса см. в разделе [Настройка учётных данных OAuth для провайдера SSO](/ru/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
</Note>

<div id="google">
  ## Google
</div>

В этом руководстве описано, как создать приложение Google OAuth в Google Cloud Console. Вы получите **Client ID** и **Client Secret**, а также настроите источники JavaScript и URI перенаправления, необходимые для Clerk.

Что понадобится: доступ к [Google Cloud Console](https://console.cloud.google.com/).

<div id="1-google-oauth">
  ### Шаг 1. Создайте OAuth-приложение Google
</div>

Перейдите в [Google Cloud Console](https://console.cloud.google.com/).

<div id="section">
  #### Создайте или выберите проект
</div>

1. Выберите существующий проект в раскрывающемся списке проектов или создайте новый
2. Вы будете перенаправлены на панель управления проектом

<div id="oauth">
  #### Настройка экрана согласия OAuth
</div>

1. На левой боковой панели выберите значок меню (≡), затем — **APIs &amp; Services**
2. Выберите **OAuth consent screen**
3. Настройте экран согласия приложения, указав необходимые сведения
4. Сохраните изменения

<div id="oauth-2">
  #### Создание учетных данных OAuth
</div>

1. В разделе **APIs &amp; Services** выберите **Credentials**
2. В верхней части страницы выберите **Create Credentials**, затем — **OAuth client ID**
3. В качестве типа приложения выберите **Web application**
4. Введите точные значения из раздела **Provider setup** в **Auth pane** в поля **Authorized JavaScript origins** и **Authorized redirect URIs**. Добавьте все перечисленные значения, включая домен публикации и собственный домен. О том, как найти эти значения, см. в разделе [Настройка учетных данных OAuth для провайдера SSO](/ru/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Выберите **Create**
6. Сохраните **Client ID** и **Client Secret**

<Warning>
  Храните Client Secret в безопасности и не коммитьте его в систему контроля версий.
</Warning>

<Warning>
  Вход через Google не работает во встроенных браузерах и WebView внутри приложений. Пользователям необходимо использовать стандартный веб-браузер.
</Warning>

<div id="section-2">
  ### Устранение неполадок
</div>

<div id="uri">
  #### несовпадение URI перенаправления
</div>

* Убедитесь, что URI перенаправления в Google Cloud Console точно совпадает со значением, указанным в разделе **Provider setup** панели **Auth pane**
* Проверьте, нет ли лишнего слеша в конце URI или опечаток
* Подождите несколько минут, пока изменения в настройках Google вступят в силу

<div id="section-3">
  #### недействительный клиент
</div>

* Ещё раз проверьте, правильно ли скопированы Client ID и Client Secret
* Проверьте, нет ли лишних пробелов
* Проверьте, настроен ли экран согласия OAuth

<div id="section-4">
  #### Не работает с собственным доменом
</div>

* Добавьте собственный домен, указанный в разделе **Provider setup** на **панели Auth**, в оба поля: Authorized JavaScript origins и Authorized redirect URIs

<div id="github">
  ## GitHub
</div>

В этом руководстве рассказывается, как создать OAuth-приложение GitHub в GitHub Developer Settings. Получите **Client ID** и **Client Secret**, затем укажите их в **Auth pane**.

Необходимо: [аккаунт GitHub](https://github.com).

<div id="1-github-oauth">
  ### Шаг 1: создание OAuth-приложения GitHub
</div>

1. Перейдите в [GitHub Developer Settings](https://github.com/settings/developers)
2. На боковой панели выберите **OAuth Apps**
3. Выберите **New OAuth App**
4. Укажите данные приложения.

**Application name:**

Введите название приложения.

**Homepage URL** и **Authorization callback URL:**

Для обоих полей укажите в точности те значения, которые отображаются в разделе **Provider setup** панели **Auth pane**. О том, как найти эти значения, см. [Настройка учетных данных OAuth для провайдера SSO](/ru/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

5. Выберите **Register application**

<div id="2">
  ### Шаг 2. Создайте учетные данные клиента
</div>

1. На странице настроек приложения отобразится **Client ID** — скопируйте его
2. Выберите **Generate a new client secret**
3. Сразу же скопируйте **Client Secret**

<Warning>
  Храните Client Secret в надежном месте. После перехода с этой страницы посмотреть его снова будет невозможно. Если вы его потеряете, придется создать новый.
</Warning>

<div id="section-5">
  ### Устранение неполадок
</div>

<div id="uri-2">
  #### Несовпадение URI перенаправления
</div>

* Убедитесь, что Authorization callback URL в точности совпадает со значением, показанным в разделе **Provider setup** на панели **Auth pane**
* Проверьте, нет ли опечаток и правильно ли указан протокол
* Не ставьте слеш в конце

<div id="section-6">
  #### Недействительный клиент
</div>

* Ещё раз проверьте, правильно ли скопированы Client ID и Client Secret
* Убедитесь, что при вставке не появились лишние пробелы

<div id="section-7">
  #### Не работает с собственным доменом
</div>

* Обновите Homepage URL и Authorization callback URL, указав значения для собственного домена, которые отображаются в разделе **Provider setup** панели **Auth pane**

<div id="apple">
  ## Apple
</div>

В этом руководстве описано, как создать Apple App ID, Services ID и приватный ключ, необходимые для Sign in with Apple. Вы получите **Team ID**, **Services ID**, **Key ID** и **приватный ключ** и укажете их в панели **Auth pane**.

Что потребуется: [аккаунт Apple Developer](https://developer.apple.com/account) (требуется регистрация в Apple Developer Program).

<div id="1-apple-app-id">
  ### Шаг 1: Создайте Apple App ID
</div>

1. Перейдите на [портал Apple Developer](https://developer.apple.com/account)
2. В разделе **Certificates, IDs &amp; Profiles** откройте **Identifiers**
3. Выберите **App IDs** в выпадающем списке
4. Нажмите значок **+**, чтобы зарегистрировать новый идентификатор
5. Выберите **App IDs**, затем — **Continue**
6. Выберите **App**, затем — **Continue**
7. Заполните следующие поля:
   * **Description**: имя App ID
   * **Bundle ID**: уникальный идентификатор
8. В разделе Capabilities включите **Sign In with Apple**
9. Выберите **Continue**, затем — **Register**
10. Сохраните значение **App ID Prefix** (отображается вверху) — это ваш **Team ID**

<div id="2-apple-services-id">
  ### Шаг 2: Создайте Apple Services ID
</div>

1. На странице Identifiers выберите **Services IDs** в выпадающем списке
2. Нажмите **+**, чтобы зарегистрировать новый идентификатор
3. Выберите **Services IDs**, затем нажмите **Continue**
4. Введите следующие данные:
   * **Description**: название Services ID
   * **Identifier**: уникальный идентификатор (сохраните его — это ваш **Services ID**)
5. Нажмите **Continue**, затем **Register**

<div id="services-id">
  #### Настройка Services ID
</div>

1. Выберите созданный Services ID
2. Включите **Sign In with Apple**
3. Выберите **Configure**
4. Задайте следующие значения:

   * **Primary App ID**: выберите App ID, созданный на шаге 1
   * **Domains and Subdomains**: скопируйте значение из раздела **Provider setup** на панели **Auth pane** (без префикса протокола `https://`)
   * **Return URLs**: скопируйте значение из раздела **Provider setup** на панели **Auth pane**

   О том, как найти эти значения, см. [Настройка учётных данных OAuth для провайдера SSO](/ru/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Последовательно выберите **Next**, **Done**, **Continue** и **Save**

<div id="3-apple-private-key">
  ### Шаг 3: Создайте приватный ключ Apple
</div>

1. На боковой панели портала Apple Developer выберите **Keys**
2. Выберите **+**, чтобы зарегистрировать новый ключ
3. Введите **Key Name**
4. Включите **Sign In with Apple**
5. Выберите **Configure** и укажите App ID, созданный на шаге 1
6. Последовательно выберите **Save**, **Continue** и **Register**
7. Сохраните **Key ID**
8. Нажмите **Download**, чтобы скачать файл закрытого ключа (.p8)

<Warning>
  Закрытый ключ можно скачать только один раз. Храните его в надежном месте — повторно скачать его не получится.
</Warning>

<div id="4-apple-private-email-relay">
  ### Шаг 4: настройка Apple Private Email Relay
</div>

Функция Apple «Скрыть мою почту» позволяет пользователям входить, не раскрывая настоящий адрес электронной почты. Чтобы отправлять письма таким пользователям, необходимо зарегистрировать источник отправки почты.

1. На боковой панели портала Apple Developer выберите **Services**
2. В разделе **Sign in with Apple for Email Communication** выберите **Configure**
3. Выберите **+**, чтобы добавить Email Source
4. Введите значение Email Source, указанное в разделе **Provider setup** панели **Auth pane**
5. Последовательно выберите **Next**, **Register** и **Done**
6. Дождитесь проверки DNS (зелёный значок галочки)

<Info>
  В некоторых регионах (например, в Китае и Индии) Apple ID может быть привязан к номеру телефона, а не к адресу электронной почты. Если ваше приложение требует адрес электронной почты от всех пользователей, вход через Sign in with Apple у пользователей из этих регионов может завершиться ошибкой.
</Info>

<div id="section-8">
  ### Устранение неполадок
</div>

<div id="section-9">
  #### Недействительный клиент
</div>

* Убедитесь, что все учётные данные введены правильно
* Убедитесь, что приватный ключ содержит строки BEGIN и END
* Убедитесь, что Services ID указан правильно

<div id="uri-3">
  #### Недопустимый URI перенаправления
</div>

* Убедитесь, что Return URL в настройках Apple Services ID в точности совпадает со значением, указанным в разделе **Provider setup** панели **Auth pane**
* Убедитесь, что домен в Domains and Subdomains совпадает с опубликованным доменом (без `https://`)

<div id="section-10">
  #### Почтовый ретранслятор не работает
</div>

* Убедитесь, что на портале Apple Developer рядом с Email Source стоит зелёная галочка
* Если вы добавили его недавно, дождитесь обновления DNS

<div id="section-11">
  #### Не работает с собственным доменом
</div>

* Добавьте собственный домен, указанный в **Provider setup** на **Auth pane**, в Domains and Subdomains (без `https://`) и Return URLs

<div id="x-twitter">
  ## X (Twitter)
</div>

В этом руководстве описано, как создать OAuth-приложение X в X Developer Portal. Получите **Client ID** и **Client Secret**, затем введите их в **Auth pane**.

Необходимо: [аккаунт разработчика X](https://developer.twitter.com/) (доступен бесплатный план).

<div id="1-x-developer">
  ### Шаг 1: Настройте App в разделе X Developer
</div>

<div id="section-13">
  #### Создайте аккаунт разработчика (при необходимости)
</div>

1. Перейдите на [портал разработчиков X](https://developer.twitter.com/en/portal/dashboard)
2. Если у вас ещё нет аккаунта, подайте заявку на создание аккаунта разработчика
3. Заполните форму заявки, указав цель использования

<div id="section-14">
  #### Создайте или выберите App
</div>

1. Перейдите в раздел **Projects &amp; Apps** на портале для разработчиков X
2. Используйте существующий App или выберите **Add App**
3. Введите название App и выберите **Next**
4. Выберите **App settings**

<div id="2-2">
  ### Шаг 2: Настройте аутентификацию
</div>

1. Прокрутите до раздела **User authentication settings**
2. Выберите **Set up**

**App permissions:**

Выберите минимально необходимый уровень разрешений.

* **Read** — доступ к профилю пользователя (минимальный уровень)
* **Write** — публикация от имени пользователя (необязательно)
* **Direct Messages** — доступ к личным сообщениям (необязательно)

<Warning>
  Разрешения должны соответствовать запрашиваемым областям доступа. Если приложение запрашивает `tweet.write`, но включён только Read, аутентификация завершится ошибкой.
</Warning>

**Type of app:**

Выберите **Web App, Automated App or Bot**

**App info:**

* **Callback URI / Redirect URL**: скопируйте значение из раздела **Provider setup** в **Auth pane**
* **Website URL**: скопируйте значение из раздела **Provider setup** в **Auth pane**

О том, как найти эти значения, см. в разделе [Настройка учетных данных OAuth для провайдера SSO](/ru/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

3. Выберите **Save**
4. **Сохраните Client ID и Client Secret**

<Warning>
  Храните Client Secret в безопасном месте. Если вы его потеряете и создадите новый, старый секрет станет недействительным.
</Warning>

<div id="section-15">
  ### Устранение неполадок
</div>

<div id="uri-4">
  #### Несовпадение URI перенаправления
</div>

* Убедитесь, что URI обратного вызова точно совпадает со значением, указанным в **Provider setup** на **Auth pane**
* Проверьте, нет ли опечаток или ошибок в протоколе
* Не добавляйте слеш в конце

<div id="section-16">
  #### недействительный клиент
</div>

* Ещё раз проверьте Client ID и Client Secret
* Убедитесь, что в них нет лишних пробелов
* Убедитесь, что используются учётные данные OAuth 2.0, а не OAuth 1.0a

<div id="section-17">
  #### Ошибки со scope/разрешениями
</div>

* Убедитесь, что scope соответствует разрешениям, включённым в X Developer Portal
* Убедитесь, что включено как минимум разрешение Read

<div id="section-18">
  #### Приложение X находится в режиме разработки
</div>

* Приложение X запускается в режиме разработки с ограниченным числом пользователей
* Для использования в рабочей среде может потребоваться запросить расширенный доступ

<div id="section-19">
  #### Не работает с собственным доменом
</div>

* Обновите Website URL и Callback URI, указав значения собственного домена из раздела **Provider setup** на панели **Auth pane**
