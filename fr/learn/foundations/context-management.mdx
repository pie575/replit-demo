Le contexte est l'information qu'un modèle IA utilise pour produire sa prochaine réponse. La gestion du contexte est la pratique consistant à fournir au modèle les bonnes informations au bon moment.

Cela est important car l'IA ne travaille pas uniquement à partir de votre intention. Elle travaille à partir du texte, des fichiers, des captures d'écran, des journaux, des exemples et de l'historique de conversation disponibles dans sa fenêtre de contexte.

## Qu'est-ce qu'une fenêtre de contexte ?

Un modèle IA a une limite sur la quantité d'informations qu'il peut considérer à la fois. Cette limite est appelée la fenêtre de contexte.

La fenêtre de contexte peut inclure :

* Votre prompt
* Les messages précédents dans la conversation
* Les fichiers ou le code que le modèle peut voir
* Les messages d'erreur et les journaux
* Les captures d'écran, images ou références de design
* Les instructions du projet, telles que `replit.md`
* Les résultats des outils des étapes précédentes

Le modèle utilise ce contexte pour décider quoi générer ensuite.

## Pourquoi les fenêtres de contexte sont importantes

Si les détails importants ne sont pas dans le contexte, le modèle peut deviner. Si trop d'informations non pertinentes se trouvent dans le contexte, le modèle peut se concentrer sur la mauvaise chose.

Par exemple, ce prompt donne peu de contexte :

```text theme={null}
Improve the signup page.
```

Ce prompt donne un contexte utile :

```text theme={null}
Improve the signup page for first-time founders who are deciding whether to join the waitlist.
Keep the current fields. Make the value proposition clearer above the form.
Do not change the pricing section.
```

Le deuxième prompt indique au modèle pour qui est la page, ce qu'il faut améliorer, ce qu'il faut préserver et ce qui est hors périmètre.

## Les tailles de fenêtres de contexte varient

Différents modèles IA peuvent gérer différentes quantités de contexte. Les fenêtres de contexte plus grandes peuvent considérer plus de texte à la fois, mais plus grand n'est pas toujours mieux. Un contexte pertinent est toujours plus important que de déverser chaque détail dans la conversation.

Exemples de tailles de fenêtres de contexte publiques :

| Famille de modèles | Exemple de fenêtre de contexte |
| ------------------ | ------------------------------ |
| GPT-4.1            | Jusqu'à 1 million de tokens    |
| Claude Sonnet 4.5  | Jusqu'à 200 000 tokens         |
| Gemini 2.5 Pro     | Jusqu'à 1 million de tokens    |

Ces chiffres changent avec le temps et ne garantissent pas que chaque produit expose la limite complète du modèle. La leçon pratique reste stable : gardez les informations importantes claires et ciblées.

## Types de contexte

| Type de contexte          | Exemple                                                                            |
| ------------------------- | ---------------------------------------------------------------------------------- |
| **Objectif**              | « Cette page de destination doit collecter des inscriptions sur liste d'attente. » |
| **Audience**              | « C'est pour les propriétaires de restaurants occupés. »                           |
| **Contraintes**           | « Conservez la palette de couleurs actuelle et les champs du formulaire. »         |
| **Non-objectifs**         | « N'ajoutez pas encore les paiements. »                                            |
| **Exemples**              | Une capture d'écran, une maquette, des données d'exemple ou une page concurrente.  |
| **État du projet**        | Le fichier actuel, le composant, le message d'erreur ou le flux utilisateur.       |
| **Définition de terminé** | « Un visiteur peut soumettre le formulaire et voir un message de remerciement. »   |

## Contexte frais et contexte persistant

Certains contextes appartiennent à la conversation actuelle. Utilisez-le lorsque vous demandez une modification spécifique, déboguez un problème ou donnez un retour sur un résultat récent.

D'autres contextes doivent persister tout au long du projet. Utilisez le contexte persistant pour le style de codage, les directives de marque, les conventions de nommage, les règles de produit réutilisables et les contraintes que l'Agent doit mémoriser entre les sessions de travail. Sur Replit, [replit.md](/fr/features/project-setup/replit-dot-md) est une façon de donner à l'Agent un contexte de projet persistant.

## Quand le contexte devient bruyant

Les longues conversations peuvent dériver. Si un fil a mélangé trop de décisions non liées, l'Agent peut prêter attention à un ancien contexte qui n'est plus pertinent.

Démarrez un nouveau fil lorsque :

* Vous passez à une fonctionnalité non liée
* La conversation comporte de nombreuses directions abandonnées
* L'Agent continue d'appliquer d'anciennes contraintes
* Vous souhaitez un plan propre pour une nouvelle zone

Lorsque vous recommencez, résumez le contexte important au lieu de supposer que l'Agent sait ce qui est encore pertinent.

```text theme={null}
Context: this project is a waitlist app for local fitness coaches.
The main flow is landing page → signup form → confirmation message.
For this thread, only improve the confirmation message and follow-up copy.
```

## Idées reçues courantes

* **« Plus de contexte est toujours mieux. »** Un contexte pertinent est mieux. Trop de contexte non pertinent peut distraire le modèle.
* **« Le modèle se souvient parfaitement de tout. »** L'IA utilise le contexte disponible, mais vous devez réitérer les contraintes importantes lorsqu'elles comptent.
* **« Le contexte n'est que du texte. »** Les captures d'écran, les fichiers, les données, les designs, les journaux et les exemples peuvent tous être du contexte.
