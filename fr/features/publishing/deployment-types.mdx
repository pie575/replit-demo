Le type de déploiement est la technologie que Replit utilise pour publier votre application. Vous le choisissez dans l'outil Publication sous **Ajuster les paramètres**, dans le menu déroulant **Type de déploiement**. **Autoscale** est le choix par défaut et recommandé, et la plupart des développeurs n'ont jamais besoin de le changer.

## Comparer les types de déploiement

| Type            | Idéal pour                                                | Fonctionnement                                                                    | Facturation                                                   |
| :-------------- | :-------------------------------------------------------- | :-------------------------------------------------------------------------------- | :------------------------------------------------------------ |
| **Autoscale**   | Applications web et API avec un trafic variable           | Ajoute des serveurs en cas de forte activité, s'adapte à zéro en cas d'inactivité | Vous payez pendant que les requêtes sont traitées             |
| **Statique**    | Pages d'accueil, portfolios, sites de documentation       | Sert des fichiers depuis un serveur cloud mis en cache, sans backend              | Vous payez uniquement pour les données servies par votre site |
| **VM réservée** | Bots, tâches en arrière-plan, API toujours actives        | Un serveur dédié qui ne s'arrête jamais                                           | Coût mensuel fixe                                             |
| **Planifié**    | Tâches périodiques comme les sauvegardes et notifications | Exécute une commande selon un calendrier, puis s'arrête                           | Vous payez pour la durée de chaque exécution                  |

## Autoscale

Les déploiements Autoscale s'exécutent sur des serveurs qui s'adaptent à la hausse et à la baisse selon le trafic de votre application. Lorsque votre application est très sollicitée, Replit ajoute des serveurs pour gérer la charge. Lorsqu'elle est inactive, le nombre descend jusqu'à zéro, afin que vous ne payiez pas pendant les périodes calmes.

Idéal pour :

* Les applications web à trafic variable, comme les sites e-commerce
* Les API et services

La configuration se trouve dans **Ajuster les paramètres** : [la puissance de la machine et le nombre maximal de serveurs](/fr/features/publishing/machine-configuration).

## Statique

Les déploiements statiques hébergent les fichiers de votre application, tels que HTML, CSS et JavaScript, sur un serveur cloud qui utilise la mise en cache pour livrer le contenu rapidement et économiquement. Il n'y a pas de serveur backend.

Idéal pour :

* Les pages d'accueil marketing
* Les sites web de portfolio
* Les sites de documentation produit et API

<Note>
  Les déploiements statiques ne sont pas compatibles avec les Applications Replit créées avec l'Agent. L'Agent construit des applications full-stack qui nécessitent un serveur backend, alors utilisez Autoscale ou VM réservée pour celles-ci.
</Note>

La configuration inclut le répertoire public à servir et une commande de build optionnelle. Pour les en-têtes de réponse, les réécritures d'URL et les redirections, consultez la [configuration statique avancée](/fr/features/deployment-customization/static-deployments-advanced).

## VM réservée

Les déploiements sur VM réservée exécutent votre application sur une machine virtuelle dédiée qui ne s'arrête jamais. Vous obtenez des performances constantes et un coût mensuel fixe et prévisible.

Idéal pour :

* Les tâches en arrière-plan gourmandes en mémoire
* Les chatbots qui doivent rester connectés
* Les serveurs API toujours actifs

La configuration inclut la [puissance de la machine](/fr/features/publishing/machine-configuration), les commandes de build et d'exécution, les mappages de ports, et si l'application fonctionne comme un serveur web ou un worker en arrière-plan.

## Planifié

Les déploiements planifiés exécutent une commande selon un calendrier dans l'environnement de votre application, puis s'arrêtent jusqu'à la prochaine exécution. Décrivez le calendrier en langage naturel, comme « chaque jour de semaine à 9h », et Replit le convertit automatiquement en planification. Vous recevez une alerte si une exécution échoue.

Idéal pour :

* Les vérifications d'état et rapports de santé
* L'envoi de notifications
* Le lancement de sauvegardes

La configuration inclut le calendrier, un délai d'expiration de tâche, et les commandes de build et d'exécution. Les déploiements planifiés ne servent pas de page web, ils n'ont donc pas d'URL publique.
