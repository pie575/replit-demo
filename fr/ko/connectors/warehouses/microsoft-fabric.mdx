Créez dans Replit des applications basées sur l’IA et publiez-les directement dans Microsoft Fabric, avec une gouvernance et une sécurité de niveau entreprise. L’intégration Microsoft Fabric transforme les données d’entreprise gouvernées en outils internes, tels que des tableaux de bord, des flux de travail et des applications d’IA. Teams passe plus rapidement du prompt à la production, tandis que les politiques d’authentification et d’accès restent dans l’environnement Fabric auquel elles font déjà confiance.

<div id="fabric">
  ## Qu&#39;est-ce qu&#39;une application de données Fabric
</div>

Une application de données Fabric est une application React statique qui affiche des graphiques Power BI en exécutant des requêtes [Data Analysis Expressions (DAX)](https://learn.microsoft.com/en-us/dax/) sur un [modèle sémantique Power BI](https://learn.microsoft.com/en-us/power-bi/connect-data/service-datasets-understand). Plusieurs caractéristiques déterminent la façon dont vous la construisez :

* **Le modèle sémantique Power BI est la source de données.** Les graphiques sont alimentés par des requêtes DAX exécutées sur le modèle sémantique (jeu de données) connecté.
* **L&#39;application est en lecture seule par conception.** Elle lit les données avec `EVALUATE` en DAX et n&#39;écrit rien dans Power BI. Si vous avez besoin d&#39;un état modifiable, utilisez une base de données applicative distincte, en complément du tableau de bord.
* **Le rendu passe par le portail Fabric.** La couche de données s&#39;exécute au sein du portail Microsoft Fabric : elle exécute les requêtes sur le modèle sémantique et renvoie les résultats à l&#39;application. Les données restent dans l&#39;environnement Fabric.
* **L&#39;hébergement repose sur l&#39;infrastructure Microsoft.** Vous pouvez publier l&#39;application de données finalisée sur l&#39;hébergement Microsoft afin qu&#39;elle s&#39;exécute aux côtés du reste de votre environnement Fabric.

<Note>
  Les applications de données Microsoft Fabric nécessitent l&#39;accès à un locataire Microsoft Fabric doté d&#39;un modèle sémantique Power BI et, pendant la période de préversion, l&#39;adhésion au programme de testeurs approuvés.
</Note>

En coulisses, [Rayfin](https://github.com/microsoft/rayfin) (un SDK et une CLI open source pour construire des backends d&#39;application) permet à Agent de définir et de publier des applications prêtes pour la production à partir des données Fabric.

Tout se déroule dans un flux de travail unique : vous décrivez l&#39;application, Agent en crée la structure, la connecte à des données Fabric gouvernées et la publie pour qu&#39;elle s&#39;exécute au sein du locataire Fabric de votre organisation.

Ce guide couvre le parcours du créateur Replit, la façon dont l&#39;application se connecte aux données Fabric, ainsi que les options Teams et d&#39;automatisation. Pour les tableaux de bord de données génériques reposant sur d&#39;autres entrepôts, consultez [Visualisation de données](/fr/ko/features/artifact-types/data-apps).

<div id="section">
  ## Cas d&#39;usage
</div>

Pour les organisations qui ont déjà investi dans l&#39;écosystème de données Microsoft, c&#39;est une voie bien plus rapide vers le développement de logiciels internes. Au lieu de passer des semaines à relier l&#39;authentification, les API, les outils de déploiement et les politiques de gouvernance, Teams décrit ce qu&#39;elles veulent et laisse Agent le construire.

Cas d&#39;usage courants :

* Outils de productivité par service
* Tableaux de bord opérationnels
* Outils d&#39;exploration de données
* Applications d&#39;automatisation de flux de travail
* Interfaces de reporting

Pour les services informatiques d&#39;entreprise, la gouvernance, l&#39;authentification et la sécurité restent au sein de l&#39;environnement Fabric que l&#39;organisation gère déjà : la création rapide d&#39;applications ne se fait donc pas au détriment du contrôle centralisé.

<div id="fabric-2">
  ## Créer une application de données Fabric
</div>

Le processus de création est conversationnel. Vous travaillez dans Replit, et l’authentification ainsi que l’accès aux données s’effectuent via Microsoft lorsque vous y êtes invité.

<Steps>
  <Step title="Commencer avec le template Fabric">
    Depuis la page d’accueil de Replit, ouvrez le menu déroulant **Templates** et sélectionnez **Microsoft Fabric App** sous **Org templates**. Agent ouvre alors un flux de travail de création d’application de données avec les outils Fabric préchargés.

    <Frame caption="Sélection du template d’organisation Microsoft Fabric App sur la page d’accueil de Replit (interface d’aperçu privé).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Page d’accueil de Replit avec le menu déroulant Templates ouvert et Microsoft Fabric App mis en évidence sous Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Décrire le tableau de bord souhaité">
    Saisissez un prompt décrivant le tableau de bord ou l’outil de reporting à créer. Par exemple : « Créez un tableau de bord de croissance mensuelle du chiffre d’affaires à partir du modèle commercial Fabric. » Vous n’avez pas besoin d’écrire du DAX : Agent génère les requêtes.
  </Step>

  <Step title="Se connecter avec Microsoft">
    Lorsque vous y êtes invité, connectez-vous via Microsoft OAuth au tenant qui contient vos données Fabric. Vous autorisez ainsi Agent à lire les modèles sémantiques auxquels vous avez accès. L’identité utilisée doit avoir accès à l’espace de travail Fabric que vous souhaitez utiliser.
  </Step>

  <Step title="Ajouter une source de données">
    Lorsque Agent vous le demande, partagez le modèle sémantique Power BI / Fabric à utiliser. Vous pouvez fournir l’URL complète du jeu de données depuis le portail Fabric (par exemple, `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) ou l’ID de l’espace de travail et l’ID du jeu de données ou de l’élément. Agent les utilise pour identifier l’espace de travail et le modèle sémantique à interroger.

    Le modèle doit être **publié dans le service Power BI** : les fichiers `.pbix` locaux ne peuvent pas être utilisés.

    <Frame caption="Agent demandant un lien vers un modèle sémantique Power BI / Fabric (interface d’aperçu privé).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Panneau Agent demandant au créateur Replit de partager un modèle sémantique Power BI ou Fabric à l’aide de l’URL complète du portail Fabric, ou de l’ID de l’espace de travail et de l’ID du jeu de données ou de l’élément, et indiquant que le modèle doit être publié dans le service Power BI, les fichiers .pbix locaux ne pouvant pas être utilisés" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Laisser Agent créer et itérer">
    Agent explore le schéma du modèle sémantique, rédige des requêtes DAX et assemble le tableau de bord avec des graphiques adaptés. Examinez le résultat et demandez des modifications en langage naturel : ajoutez des filtres, changez le type de graphique ou ajoutez d’autres indicateurs.
  </Step>

  <Step title="Publier (facultatif)">
    Lorsque le tableau de bord est prêt, vous pouvez le publier sur l’hébergement Microsoft afin qu’il s’exécute dans l’environnement Fabric. La publication est traitée séparément ; ce guide se concentre sur la connexion aux données et la création de l’application.
  </Step>
</Steps>

<div id="fabric-3">
  ## Connecter les données Fabric
</div>

Pour lire les données, votre application doit disposer d&#39;une connexion autorisée à Microsoft Fabric. Replit établit cette connexion de l&#39;une des deux façons suivantes.

<div id="fabric-4">
  ### Connexion Fabric au niveau de l’application (observateur)
</div>

Les observateurs d’une application de données publiée ne configurent pas de connecteur. Ils s’authentifient via l’authentification unique Microsoft Fabric intégrée à l’application, qui accède aux données avec cette identité via le portail Fabric. L’accès est régi par les autorisations Fabric existantes.

<div id="microsoft-fabric">
  ### Connecteur Microsoft Fabric (la voie simple pour les créateurs Replit)
</div>

Pour les créateurs Replit, le **connecteur Microsoft Fabric** offre un moyen pratique d&#39;autoriser l&#39;accès aux données pendant le développement. Son usage est facultatif : c&#39;est une voie simple, pas une obligation.

* Le créateur Replit qui réalise la configuration initiale effectue un **OAuth unique** avec Microsoft.
* **Les autres collaborateurs du même projet** héritent de cette connexion.
* **Les autres espaces de travail** doivent activer le connecteur et effectuer leur propre OAuth.
* L&#39;identité authentifiée via OAuth doit disposer d&#39;un accès à l&#39;espace de travail Fabric cible.

Le connecteur s&#39;appuie sur Microsoft Entra OAuth et sa portée est limitée à votre locataire. Comme les autres connecteurs Replit, il se gère depuis la page [Intégrations](/fr/ko/features/integrations/overview) de votre projet. Pour une vue d&#39;ensemble des concepts liés aux connecteurs, consultez [Gérer les connecteurs](/fr/ko/replitai/managing-connectors).

<Note>
  Pendant la période d&#39;aperçu privé, aucun identifiant partagé géré par Replit n&#39;est disponible pour le connecteur Microsoft Fabric. Les créateurs Replit autorisent l&#39;accès sur leur propre locataire Microsoft Entra.
</Note>

<div id="section-2">
  ## Teams et automatisation
</div>

Pour un usage partagé dans Teams ou dans des environnements non interactifs (comme la CI), l&#39;OAuth interactif n&#39;est pas toujours pratique. Dans ce cas, plutôt que de vous connecter de manière interactive, fournissez un jeton de **principal de service** via les [Secrets](/fr/ko/core-concepts/project-editor/app-setup/secrets) du projet. L&#39;app utilise alors l&#39;identité du principal de service pour lire les données Fabric.

C&#39;est la configuration qui se rapproche le plus d&#39;un fonctionnement machine à machine : une identité non humaine, provisionnée dans Microsoft Entra et autorisée à accéder à l’espace de travail Fabric, authentifie l&#39;app sans intervention humaine. Vérifiez que le principal de service dispose bien des droits d&#39;accès aux espaces de travail et aux modèles sémantiques que l&#39;app interroge.

<div id="section-3">
  ## Résolution des problèmes
</div>

<AccordionGroup>
  <Accordion title="Les données ne se chargent pas dans l'aperçu d'application">
    La couche de données Fabric s&#39;exécute via le portail Microsoft Fabric. Si les graphiques sont vides ou si l&#39;aperçu d&#39;application ne parvient pas à charger les données, vérifiez que vous êtes bien connecté à Microsoft et que l&#39;identité utilisée dispose des droits d&#39;accès à l&#39;espace de travail et au modèle sémantique associés.
  </Accordion>

  <Accordion title="Agent ne trouve pas le modèle sémantique">
    Vérifiez que vous avez collé le lien du jeu de données Power BI depuis le portail Fabric et que l&#39;identité (ou le principal de service) dispose au minimum d&#39;un accès en lecture à cet espace de travail. Si Agent indique qu&#39;il ne peut pas vérifier l&#39;espace de travail ou le modèle, partagez à nouveau le lien du jeu de données.
  </Accordion>

  <Accordion title="Le connecteur se déconnecte ou des invites de connexion s'affichent à répétition">
    Réauthentifiez le connecteur Microsoft Fabric depuis la page [Intégrations](/fr/ko/features/integrations/overview) du projet. Vérifiez que l&#39;identité OAuth dispose d&#39;un accès à l&#39;espace de travail Fabric. Pour les Teams ou une utilisation en CI, privilégiez les jetons de principal de service fournis via Secrets.
  </Accordion>
</AccordionGroup>
