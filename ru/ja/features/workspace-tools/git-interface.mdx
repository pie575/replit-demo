Панель Git в Replit предоставляет визуальный интерфейс для работы с Git, избавляя от необходимости вводить команды Git в терминале. Благодаря ей контроль версий становится доступным даже новичкам, а опытные разработчики получают все необходимые возможности.

<div id="section">
  ## Возможности
</div>

Панель Git предоставляет полноценные возможности контроля версий прямо в Project Editor, а удобный интерфейс упрощает сложные операции Git.

* **Управление репозиториями**: инициализация, подключение и управление репозиториями Git с интеграцией GitHub
* **Отслеживание коммитов**: индексирование, коммит и просмотр изменений во всех файлах
* **Работа с ветками**: наглядное создание, переключение и слияние веток
* **Разрешение конфликтов**: наглядное выявление и устранение конфликтов слияния
* **Интеграция с Shell**: синхронизация команд Git, выполненных в Shell, с панелью Git

<div id="section-2">
  ## Как использовать
</div>

<div id="section-3">
  ### Настройка репозитория
</div>

<Accordion title="Как открыть панель Git">
  1. Перейдите в раздел Tools вашего Replit App
  2. Нажмите значок **+**, чтобы добавить новый инструмент
  3. Выберите **Git** в списке доступных инструментов
</Accordion>

Панель Git помогает настроить и подключить репозиторий:

* **Инициализация репозитория**: создание нового репозитория Git для вашего Replit App
* **Подключение к провайдеру Git**: привязка репозитория к поддерживаемому облачному или自 self-hosted провайдеру для резервного копирования и совместной работы
* **Настройка удалённых репозиториев**: создание подключений к удалённым репозиториям и управление ими

<Note>
  **Поддержка self-hosted Git**: Replit поддерживает GitHub Enterprise Server, GitLab Self-Managed и Bitbucket Data Center на планах Enterprise. По вопросам внедрения, а также за помощью с настройкой и ошибками подключения [обратитесь в отдел продаж Replit](https://replit.com/enterprise). Кроме того, удалённый репозиторий можно [настроить командами git в Shell](#using-git-commands-in-shell).
</Note>

<div id="section-4">
  ### Управление изменениями
</div>

<Accordion title="Как просмотреть изменения">
  1. Внесите изменения в любой файл в Replit App
  2. Откройте панель Git в разделе Tools
  3. Просмотрите изменения в разделе **Review Changes**
</Accordion>

Панель Git предоставляет инструменты для управления изменениями в коде:

* **Просмотр изменений**: отображение изменённых файлов с подсветкой добавлений и удалений
* **Индексирование файлов**: выбор конкретных файлов для включения в следующий коммит
* **Коммит изменений**: сохранение изменений с понятным описанием
* **Отправка изменений**: отправка коммитов в GitHub одним щелчком

<div id="section-5">
  ### Управление ветками
</div>

<Accordion title="Как управлять ветками">
  1. Откройте панель Git в разделе Tools
  2. Нажмите на выпадающий список веток рядом с именем ветки
  3. Создайте новую ветку или выберите существующую
</Accordion>

Панель Git упрощает работу с несколькими версиями кода:

* **Создание ветки**: создавайте новые ветки, чтобы разрабатывать функции изолированно
* **Переключение веток**: переходите между разными версиями кода
* **Публикация ветки**: делитесь веткой в GitHub
* **Получение изменений**: синхронизируйте удалённые обновления от соавторов

<div id="section-6">
  ### Разрешение конфликтов слияния
</div>

<Accordion title="Как разрешить конфликты слияния">
  1. Попробуйте получить изменения при наличии конфликтов
  2. Панель Git подсветит конфликтующие файлы
  3. Откройте каждый конфликтующий файл, чтобы просмотреть и разрешить конфликты
  4. Сохраните файлы после разрешения конфликтов
  5. Нажмите **Pull**, чтобы завершить слияние
</Accordion>

Если код из разных источников конфликтует, панель Git поможет вам:

* **Найти конфликты**: точно показывает, в каких файлах есть конфликты
* **Увидеть различия**: сравните обе версии конфликтующего кода
* **Устранить проблемы**: выберите, какой код оставить, или отредактируйте конфликт вручную
* **Завершить слияние**: доведите слияние до конца после разрешения конфликтов

После разрешения конфликта в файле удалите строки, начинающиеся с символов конфликта, чтобы убрать маркеры конфликта, и сохраните файл.

<div id="shellgit">
  ### Использование команд Git в Shell
</div>

<Accordion title="Как открыть Shell">
  1. В доке инструментов слева выберите **All tools**
  2. Среди доступных инструментов выберите **Shell**
</Accordion>

<Tip>
  Панель Git предоставляет удобный интерфейс, но опытные пользователи могут выполнять более сложные операции с помощью стандартных команд Git в Shell. Изменения, внесённые любым из способов, отображаются в обоих местах.
</Tip>

Если вы предпочитаете работать с Git из командной строки:

* **Синхронизация команд**: команды Git, выполненные в Shell, автоматически синхронизируются с панелью Git
* **Полный набор возможностей Git**: доступ к расширенным функциям Git, которых нет на панели Git
* **Плавное переключение**: переключайтесь между командами Shell и панелью Git по мере необходимости

<Info>
  **Поддержка GitHub CLI и GitLab CLI**: помимо стандартных команд Git, в Shell можно использовать [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) и [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) для управления внешними репозиториями Git и подключения к ним. Эти инструменты расширяют возможности работы с репозиториями GitHub и GitLab: пул-реквесты, задачи (issues) и другие функции, специфичные для этих платформ.
</Info>

<div id="section-7">
  #### Операции с репозиторием
</div>

* **Клонирование репозитория**: `git clone <url-to-repository>`
* **Инициализация репозитория**: `git init`
* **Добавление удалённого репозитория**: `git remote add origin <url-to-repository>`

<div id="section-8">
  #### Внесение изменений
</div>

* **Проверка статуса**: `git status` (показывает изменённые, добавленные и удалённые файлы)
* **Индексирование файлов**: `git add <filename>` или `git add .` (все файлы)
* **Коммит изменений**: `git commit -m "your commit message"`
* **Отправка изменений**: `git push origin <branch-name>`
* **Получение изменений**: `git pull origin <branch-name>`

<div id="section-9">
  #### Аутентификация
</div>

При работе с приватными репозиториями требуется аутентификация:

* Для репозиториев на GitHub.com вместо пароля используйте персональный токен доступа
* Чтобы не вводить учётные данные каждый раз, сохраните их в Replit Secrets:
  1. Создайте новый секрет с ключом `GIT_URL`
  2. Укажите значение `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Используйте `git push $GIT_URL`, чтобы отправлять изменения без ввода учётных данных

<Note>
  Если учётные данные хранятся в виде секрета, любой, у кого есть доступ к вашему Replit App, потенциально может получить и ваши учётные данные Git. Для репозиториев с конфиденциальными данными лучше вводить учётные данные вручную каждый раз.
</Note>
