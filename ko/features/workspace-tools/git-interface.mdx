Replit의 Git pane은 Git 작업을 위한 시각적 인터페이스를 제공하므로 명령줄에서 Git 명령어를 입력할 필요가 없습니다. 이 기능 덕분에 초보자도 version control을 손쉽게 사용할 수 있으며, 숙련된 개발자에게도 충분히 강력합니다.

<div id="features">
  ## 기능
</div>

Git pane은 복잡한 Git 작업을 간소화하는 직관적인 인터페이스를 통해 Project Editor에서 바로 사용할 수 있는 종합적인 version control 기능을 제공합니다.

* **저장소 관리**: GitHub integration으로 Git 저장소를 초기화하고 연결하며 관리합니다
* **커밋 추적**: 모든 파일의 changes를 스테이징하고 커밋하며 확인합니다
* **브랜치 작업**: 브랜치를 시각적으로 생성하고 전환하며 병합합니다
* **충돌 해결**: 시각적 지원을 통해 병합 충돌을 파악하고 해결합니다
* **Shell integration**: Shell에서 실행한 Git 명령어와 Git pane 간의 동기화

<div id="usage">
  ## 사용량
</div>

<div id="repository-setup">
  ### 저장소 설정
</div>

<Accordion title="Git pane에 접근하는 방법">
  1. Replit App에서 Tools 섹션으로 이동합니다
  2. **+** 기호를 선택해 새 도구를 추가합니다
  3. 사용 가능한 도구 목록에서 **Git**을 선택합니다
</Accordion>

Git pane에서는 다음과 같이 저장소를 설정하고 연결할 수 있습니다:

* **저장소 초기화**: Replit App용 새 Git 저장소를 생성합니다
* **Git provider에 연결**: 백업과 협업을 위해 지원되는 호스팅형 또는 자체 호스팅형 provider에 저장소를 연결합니다
* **remote 구성**: remote 저장소와의 연결을 설정하고 관리합니다

<Note>
  **자체 호스팅 Git 지원**: Replit은 Enterprise plan에서 GitHub Enterprise Server, GitLab Self-Managed, Bitbucket Data Center를 지원합니다. 온보딩 안내, provider 구성, 연결 문제 디버깅이 필요하면 [Replit 영업팀에 문의](https://replit.com/enterprise)하세요. [Shell에서 Git 명령어로 remote를 구성](#using-git-commands-in-shell)할 수도 있습니다.
</Note>

<div id="change-management">
  ### 변경 사항 관리
</div>

<Accordion title="변경 사항 확인 방법">
  1. Replit App의 파일을 변경합니다
  2. Tools 섹션에서 Git pane을 엽니다
  3. **Review Changes** 섹션에서 변경 사항을 검토합니다
</Accordion>

Git pane에서는 코드 변경 사항을 관리할 수 있는 다음과 같은 도구를 제공합니다:

* **변경 사항 검토**: 추가 및 삭제된 부분이 강조 표시된 수정 파일 확인
* **파일 스테이징**: 다음 commit에 포함할 파일 선택
* **변경 사항 커밋**: 변경 내용을 설명하는 메시지와 함께 저장
* **업데이트 푸시**: 클릭 한 번으로 remote 저장소에 commit 전송

</Note>

<div id="branch-management">
  ### 브랜치 관리
</div>

<Accordion title="브랜치 관리 방법">
  1. Tools 섹션에서 Git pane을 엽니다
  2. 브랜치 이름 옆의 브랜치 드롭다운을 선택합니다
  3. 새 브랜치를 만들거나 기존 브랜치를 선택합니다
</Accordion>

Git pane을 사용하면 코드의 여러 버전을 손쉽게 다룰 수 있습니다:

* **브랜치 생성**: 새 브랜치를 만들어 기능을 별도로 개발합니다
* **브랜치 전환**: 코드의 여러 버전 사이를 오갑니다
* **브랜치 게시**: 브랜치를 Git provider에 공유합니다
* **변경 사항 pull**: 협업자가 올린 remote 업데이트와 동기화합니다

<div id="merge-conflict-resolution">
  ### 병합 충돌 해결
</div>

<Accordion title="병합 충돌을 해결하는 방법">
  1. 충돌이 있는 상태에서 변경 사항 pull을 시도합니다
  2. Git pane에서 충돌하는 파일이 강조 표시됩니다
  3. 충돌이 발생한 각 파일을 열어 충돌 내용을 확인하고 해결합니다
  4. 충돌을 해결한 후 파일을 저장합니다
  5. **Pull**을 선택해 병합을 완료합니다
</Accordion>

서로 다른 소스의 코드가 충돌할 때 Git pane에서는 다음과 같은 작업을 할 수 있습니다:

* **충돌 식별**: 어떤 파일에 충돌이 있는지 정확히 확인
* **차이점 시각화**: 충돌하는 코드의 두 버전을 모두 검토
* **문제 해결**: 유지할 코드를 선택하거나 충돌 부분을 직접 편집
* **병합 마무리**: 충돌 해결 후 병합 과정 완료

<Frame>
  <img src="/assets/mirror/11-merge-conflict-17b314f0e231.png" alt="병합 충돌 표시가 나타난 코드 에디터" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

충돌을 해결한 파일에서는 충돌 기호로 시작하는 줄을 삭제해 충돌 표시를 없앤 뒤 파일을 저장하면 됩니다.

<div id="using-git-commands-in-shell">
  ### Shell에서 Git 명령어 사용하기
</div>

<Accordion title="Shell에 접근하는 방법">
  1. 왼쪽 도구 dock에서 **All tools**를 선택하세요
  2. 사용 가능한 도구 중 **Shell**을 선택하세요
</Accordion>

<Tip>
  Git pane은 사용하기 쉬운 인터페이스를 제공하지만, 숙련된 사용자라면 더 복잡한 작업을 위해 Shell에서 표준 Git 명령어를 사용할 수 있습니다. 어느 방식으로 변경하든 양쪽 모두에 반영됩니다.
</Tip>

명령줄로 Git을 사용하려는 경우 다음을 참고하세요.

* **명령어 동기화**: Shell에서 실행한 Git 명령어는 Git pane에 자동으로 동기화됩니다
* **완전한 Git 기능**: Git pane에서 제공하지 않는 고급 Git 기능을 사용할 수 있습니다
* **자유로운 전환**: 필요에 따라 Shell 명령어와 Git pane을 오가며 사용할 수 있습니다

<Info>
  **GitHub 및 GitLab CLI 지원**: 표준 Git 명령어 외에도 Shell에서 [GitHub CLI](https://docs.github.com/en/github-cli)(`gh`)와 [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/)(`glab`)를 사용해 외부 Git 저장소를 관리하고 연결할 수 있습니다. 이러한 도구는 pull request, issues 등 플랫폼별 기능을 포함해 GitHub 및 GitLab 저장소 작업에 유용한 확장 기능을 제공합니다.
</Info>

<div id="repository-operations">
  #### 저장소 작업
</div>

* **저장소 복제**: `git clone <url-to-repository>`
* **저장소 초기화**: `git init`
* **remote 추가**: `git remote add origin <url-to-repository>`

<div id="making-changes">
  #### 변경 사항 작업하기
</div>

* **상태 확인**: `git status` (수정, 추가, 삭제된 파일 표시)
* **파일 스테이징**: `git add <filename>` 또는 `git add .` (모든 파일)
* **변경 사항 커밋**: `git commit -m "your commit message"`
* **변경 사항 푸시**: `git push origin <branch-name>`
* **변경 사항 풀**: `git pull origin <branch-name>`

<div id="authentication">
  #### 인증
</div>

비공개 저장소를 사용할 때는 인증이 필요합니다.

* GitHub.com 저장소에서는 비밀번호 대신 개인 액세스 토큰을 사용하세요
* 자격 증명을 매번 입력하지 않으려면 Replit Secrets에 저장해 두면 됩니다:
  1. 키가 `GIT_URL`인 새 secret을 생성합니다
  2. 값을 `https://<username>:<token>@<git-host>/<owner>/<repository>`로 설정합니다
  3. `git push $GIT_URL` 명령을 사용하면 자격 증명을 입력하지 않고 푸시할 수 있습니다

<Note>
  자격 증명을 secret으로 저장하면 Replit App에 접근할 수 있는 사람은 누구나 Git 자격 증명에 접근할 수 있습니다. 민감한 저장소라면 매번 자격 증명을 직접 입력하는 방식을 고려하세요.
</Note>
