上下文是 AI 模型用来生成下一条回复的信息。上下文管理是指在恰当的时机向模型提供恰当的信息。

这很重要，因为 AI 并非只根据你的意图工作，而是根据其上下文窗口中可用的文本、文件、截图、日志、示例和对话历史来工作。

<div id="what-is-a-context-window">
  ## 什么是上下文窗口？
</div>

AI 模型一次能处理的信息量有限，这个限度称为上下文窗口。

上下文窗口可以包括：

* 你的 提示词
* 对话中之前的消息
* 模型可以访问的文件或代码
* 错误消息和日志
* 截图、图片或设计参考资料
* 项目 指令，例如 `replit.md`
* 前几个步骤的工具结果

模型会根据这些上下文决定接下来生成什么内容。

<div id="why-context-windows-matter">
  ## 为什么上下文窗口很重要
</div>

如果上下文中缺少重要细节，模型可能会自行猜测。如果上下文中包含过多无关信息，模型可能会把注意力放在错误的内容上。

例如，以下提示词提供的上下文很少：

```text theme={null}
优化注册页面。
```

此提示词提供了有用的上下文：

```text theme={null}
优化面向首次创业者的注册页面，帮助他们决定是否加入候补名单。
保留现有字段。在表单上方更清晰地说明价值主张。
不要更改定价部分。
```

第二个提示词告诉模型该页面面向哪些用户、应改进哪些内容、应保留哪些内容，以及哪些内容不在范围内。

<div id="context-window-sizes-vary">
  ## 上下文窗口大小不一
</div>

不同的 AI 模型可处理的上下文量不同。更大的上下文窗口可以一次处理更多文本，但并非越大越好。相关的上下文仍然比把所有细节一股脑塞进对话更重要。

公开的上下文窗口大小示例：

| 模型系列              | 示例上下文窗口            |
| ----------------- | ------------------ |
| GPT-4.1           | 最多 100 万个 token    |
| Claude Sonnet 4.5 | 最多 200,000 个 token |
| Gemini 2.5 Pro    | 最多 100 万个 token    |

这些数字会随时间变化，也不能保证每个产品都会提供模型的完整上下文上限。但实际原则不变：让重要信息保持清晰、聚焦。

<div id="types-of-context">
  ## 上下文类型
</div>

| 上下文类型    | 示例                 |
| -------- | ------------------ |
| **目标**   | “此落地页应收集候补名单报名信息。” |
| **受众**   | “面向忙碌的餐厅老板。”       |
| **约束条件** | “保留当前的配色方案和表单字段。”  |
| **非目标**  | “暂时不要添加支付功能。”      |
| **示例**   | 截图、线框图、示例数据或竞品页面。  |
| **项目状态** | 当前文件、组件、错误消息或用户流程。 |
| **完成标准** | “访客可以提交表单并看到感谢消息。” |

<div id="fresh-context-and-persistent-context">
  ## 临时上下文与持久上下文
</div>

有些上下文仅适用于当前 Conversation。当你请求特定更改、调试某个问题或针对最近的结果提供反馈时，可使用这些信息。

其他上下文则应在整个项目中持续保留。持久上下文适用于编码风格、品牌指南、命名约定、可复用的产品规则，以及 Agent 应在不同工作会话间记住的约束条件。在 Replit 上，[replit.md](/zh/features/project-setup/replit-dot-md) 是向 Agent 提供持久项目上下文的一种方式。

<div id="when-context-gets-noisy">
  ## 当上下文变得混乱时
</div>

较长的对话可能会偏离主题。如果一个线程中混杂了过多不相关的决策，Agent 可能会关注已不再重要的旧上下文。

出现以下情况时，请新开一个线程：

* 你切换到不相关的功能
* 对话中有许多被放弃的思路
* Agent 不断沿用旧的约束条件
* 你想为新领域制定清晰的计划

重新开始时，请总结重要的上下文，不要假定 Agent 知道哪些内容仍然重要。

```text theme={null}
背景：此项目是面向本地健身教练的候补名单应用。
主要流程为落地页 → 注册表单 → 确认消息。
在此线程中，仅改进确认消息和后续文案。
```

<div id="common-misconceptions">
  ## 常见误区
</div>

* **“上下文越多越好。”** 相关的上下文才有帮助。过多无关的上下文可能会分散模型的注意力。
* **“模型能完美记住一切。”** AI 会利用可用的上下文，但在重要约束条件适用时，你仍应重申这些条件。
* **“上下文只有文本。”** 截图、文件、数据、Design、日志和示例都可以作为上下文。
