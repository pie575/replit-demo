<Info>
  Le connecteur Snowflake est disponible exclusivement avec le forfait **Enterprise**.
</Info>

Les connecteurs d’entrepôt de données permettent à Replit Agent d’interroger les entrepôts de données de votre organisation. Avec le connecteur Snowflake, les développeurs peuvent créer des tableaux de bord, des outils de reporting et des applications basées sur les données à l’aide du langage naturel, sans avoir besoin de connaître SQL.

La configuration ne doit être effectuée qu’une seule fois et requiert un administrateur Snowflake et un administrateur du workspace Replit. Une fois le connecteur configuré, tout membre de l’organisation peut se connecter et commencer à créer avec les données Snowflake.

Ce guide vous accompagne tout au long de la configuration. Trois rôles sont impliqués :

1. **Administrateur de compte Snowflake** — Crée l’intégration OAuth dans Snowflake
2. **Administrateur du workspace Replit** — Configure le connecteur dans Replit
3. **Développeur** — Se connecte et commence à créer

<div id="criar-a-integrao-oauth-no-snowflake">
  ## Créer l’intégration OAuth dans Snowflake
</div>

L’administrateur du compte Snowflake crée une intégration de sécurité OAuth permettant à Replit de s’authentifier auprès de Snowflake.

<div id="pr-requisitos">
  ### Prérequis
</div>

* Rôle `ACCOUNTADMIN` dans Snowflake
* Autorisation d’exécuter des requêtes SQL dans les feuilles de calcul Snowflake

<div id="executar-o-script-de-configurao">
  ### Exécuter le script de configuration
</div>

<Steps>
  <Step title="Se connecter à Snowflake">
    Ouvrez votre compte Snowflake et assurez-vous d&#39;utiliser le rôle `ACCOUNTADMIN`. Vous pouvez le vérifier dans le menu déroulant des rôles en haut à droite.
  </Step>

  <Step title="Ouvrir une feuille de calcul SQL">
    Cliquez sur **Feuilles de calcul** dans la barre latérale gauche et créez une nouvelle feuille de calcul.
  </Step>

  <Step title="Exécuter le script d'intégration OAuth">
    Copiez et collez le script SQL suivant, puis exécutez-le :

    ```sql Créer une intégration OAuth theme={null}
    -- Supprimer l'intégration existante, si nécessaire
    DROP INTEGRATION IF EXISTS REPLIT_OAUTH;

    -- Créer une intégration OAuth pour Replit
    CREATE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    <Warning>
      L&#39;URI de redirection doit être exactement `https://replit.com/connectors/oauth/callback`. Toute autre valeur provoque une erreur 404 lors de l&#39;authentification.
    </Warning>

    <Note>
      Définir `BLOCKED_ROLES_LIST = ()` garantit qu&#39;aucun rôle ne soit empêché d&#39;utiliser l&#39;intégration. Sans cela, vous pourriez recevoir des erreurs de « demande de consentement non valide » ou de « rôle bloqué » lorsque vous vous connectez.
    </Note>
  </Step>

  <Step title="Récupérer vos identifiants OAuth">
    Exécutez cette requête pour obtenir le Client ID et le Client Secret :

    ```sql Obtenir les identifiants OAuth theme={null}
    -- Afficher les détails de l'intégration
    DESCRIBE INTEGRATION REPLIT_OAUTH;

    -- Obtenir le Client ID et le Secret
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```

    Copiez le **Client ID** et le **Client Secret** dans le résultat. Vous aurez besoin de ces valeurs à l&#39;étape suivante.
  </Step>
</Steps>

<div id="configurar-o-conector-no-replit">
  ## Configurer le connecteur dans Replit
</div>

L’administrateur du workspace Replit ajoute les identifiants Snowflake dans Replit. Une fois configuré, toute personne de l’organisation peut se connecter.

<Note>
  Cette étape nécessite un forfait Enterprise avec un accès administrateur.
</Note>

<Steps>
  <Step title="Ouvrir les intégrations">
    Accédez aux paramètres de votre organisation et sélectionnez l’onglet **Intégrations**.
  </Step>

  <Step title="Ajouter le connecteur Snowflake">
    Cliquez sur **Ajouter un nouveau connecteur** et sélectionnez **Snowflake**.
  </Step>

  <Step title="Saisir les identifiants">
    Saisissez le **Client ID** et le **Client Secret** de l’étape précédente.
  </Step>

  <Step title="Définir la portée">
    Définissez la portée du connecteur sur `refresh_token`.

    <Warning>
      Utilisez uniquement la portée `refresh_token`. D’autres portées, comme `session:role-any` ou `session:role:PUBLIC`, peuvent entraîner une erreur de « portée non valide ».
    </Warning>
  </Step>

  <Step title="Enregistrer">
    Cliquez sur **Enregistrer** pour activer le connecteur.
  </Step>
</Steps>

<div id="fazer-login-no-snowflake">
  ## Se connecter à Snowflake
</div>

Tout membre de l’organisation ayant accès au connecteur peut se connecter. Connectez-vous d’abord depuis la page **Intégrations** pour vérifier la connexion avant de l’utiliser avec Agent.

<Steps>
  <Step title="Trouver le connecteur Snowflake">
    Accédez à **Intégrations** dans Replit. Dans **Connecteurs**, recherchez **Snowflake**.
  </Step>

  <Step title="Cliquer sur Se connecter">
    Cliquez sur **Se connecter** sur le connecteur Snowflake.
  </Step>

  <Step title="Saisir votre ID de compte Snowflake">
    L’invite OAuth vous demande votre ID de compte Snowflake.

    Pour trouver votre ID de compte, consultez l’URL de votre compte Snowflake :

    ```
    https://app.snowflake.com/minhaorg/minhaconta
    ```

    Prenez les deux parties après `app.snowflake.com/` et reliez-les par un trait d’union :

    ```
    minhaorg-minhaconta
    ```

    <Note>
      L’URL utilise `/` entre les deux parties, mais l’ID de compte utilise `-` à la place.
    </Note>
  </Step>

  <Step title="S’authentifier">
    Snowflake vous redirige vers la page de connexion. Saisissez vos identifiants Snowflake pour terminer le flux OAuth.
  </Step>
</Steps>

<div id="comear-a-criar-com-seus-dados-do-snowflake">
  ## Commencez à créer avec vos données Snowflake
</div>

Après vous être connecté, vous pouvez utiliser le connecteur Snowflake avec Agent de deux manières :

* **Commande à barre oblique** — Saisissez `/snowflake` dans le prompt pour utiliser le connecteur
* **Langage naturel** — Demandez directement à Agent d’utiliser vos données Snowflake

Voici un exemple de prompt :

```
Créez un tableau de bord à l’aide de mes données Snowflake. Affichez le chiffre d’affaires total
par région dans un graphique à barres, une courbe de tendance par trimestre et un tableau
des 10 principaux clients. Thème sombre, épuré et moderne.
```

Agent rédige et exécute des requêtes SQL sur vos données Snowflake, puis crée une application fonctionnelle.

<div id="soluo-de-problemas">
  ## Résolution des problèmes
</div>

<AccordionGroup>
  <Accordion title="Demande de consentement non valide ou rôle bloqué">
    Des rôles peuvent être bloqués par défaut dans votre intégration Snowflake.

    Vérifiez que l’intégration a été créée avec `BLOCKED_ROLES_LIST = ()`. Si vous l’avez déjà créée sans cette configuration, exécutez :

    ```sql Corriger les rôles bloqués theme={null}
    CREATE OR REPLACE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    Si l’erreur persiste, vérifiez que votre rôle par défaut n’est pas bloqué :

    ```sql Définir le rôle par défaut theme={null}
    ALTER USER "SEU_NOME_DE_USUARIO" SET DEFAULT_ROLE = 'PUBLIC';
    ```
  </Accordion>

  <Accordion title="Erreur 404 lors de l’authentification">
    Vérifiez que l’URI de redirection de votre intégration Snowflake est exactement :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    Toute différence entraîne une erreur 404 pendant le flux OAuth.
  </Accordion>

  <Accordion title="Erreur de portée non valide">
    Assurez-vous que la portée du connecteur dans Replit est définie uniquement sur `refresh_token`. Supprimez toutes les autres portées, comme `session:role-any` ou `session:role:PUBLIC`.
  </Accordion>

  <Accordion title="Échec de la connexion">
    Vérifiez que le Client ID et le Client Secret dans Replit correspondent à ceux générés par Snowflake. Pour vérifier, exécutez :

    ```sql Vérifier les identifiants theme={null}
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```
  </Accordion>
</AccordionGroup>
