⏰ *Temps estimé : 10 minutes*

À la fin de ce guide, vous aurez publié une petite application à une URL que vous pourrez partager.

<Frame>
  <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="Le template sélectionné créé sous forme de site web et ouvert à son URL Replit publique" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
</Frame>

Vous partirez d&#39;un template soigné, le transformerez en site web fonctionnel, puis le publierez. Les templates disponibles peuvent varier ; choisissez-en un qui correspond à ce que vous souhaitez créer.

<div id="before-you-start">
  ## Avant de commencer
</div>

Vous avez besoin d&#39;un [compte Replit](https://replit.com). Créer une nouvelle application à partir d&#39;une frame dans Design nécessite l’offre Core ou Pro. Consultez [Créer votre design](/fr/design/build-your-design) et [Facturation](/fr/billing/ai-billing) pour en savoir plus sur les offres.

L’objectif est d’effectuer un cycle complet :

* Choisissez un template dans [Replit Design](https://replit.com/design),
* Créez-le avec [Agent](/fr/features/agent/overview),
* Testez l’application,
* Publiez-la et partagez-la.

Agent est l’outil de création par IA de Replit. Vous décrivez ce que vous souhaitez, et Agent vous aide à créer, expliquer et corriger l’application.

<div id="choose-build-and-publish-a-template">
  ## Choisissez, créez et publiez un template
</div>

<Steps>
  <Step title="Parcourir les templates Design">
    Ouvrez [replit.com/design](https://replit.com/design). Parcourez les templates à la une ou filtrez par **Pages de destination**, **Mobile**, **Prototypes** et d&#39;autres formats.

    <Frame>
      <img src="/assets/mirror/01-design-gallery-5303cf1cf6d2.jpg" alt="La galerie Replit Design avec des templates à la une et des filtres par format" width="1280" height="720" data-path="images/first-app-template/01-design-gallery.jpg" />
    </Frame>
  </Step>

  <Step title="Prévisualiser et utiliser un template">
    Sélectionnez un template pour l’examiner, puis sélectionnez **Use template**. Replit crée un nouveau projet et place le template sur le Canvas Design. Si vous êtes plutôt parti de la page de présentation d’un template, consultez [Commencer à partir d’un template](/fr/design/start-from-a-template) pour découvrir le processus de remixage.

    <Frame>
      <img src="/assets/mirror/02-template-preview-facda2e40956.jpg" alt="Aperçu d’un template Replit Design avec le bouton Use template" width="1280" height="720" data-path="images/first-app-template/02-template-preview.jpg" />
    </Frame>

    Le template remixé s’ouvre sur le Canvas Design dans son nouveau projet.

    <Frame>
      <img src="/assets/mirror/03-remixed-design-35b051544510.jpg" alt="Le template sélectionné remixé sur le Canvas Design dans un nouveau projet Replit" width="1280" height="720" data-path="images/first-app-template/03-remixed-design.jpg" />
    </Frame>
  </Step>

  <Step title="Transformez le design en site web">
    Un template est d’abord une maquette. Avant de pouvoir le publier, passez à **Build** et demandez à Agent de transformer le design sélectionné en site web fonctionnel. Par exemple :

    > Crée ce template sélectionné sous la forme d’un site web fonctionnel. Préserve son design visuel et assure le bon fonctionnement de sa navigation et de ses actions de contact.

    Agent crée un artefact de site web dans le même projet en s’appuyant sur le design sélectionné.

    <Note>
      Le bouton **Publish** est également visible dans Design. Si le projet contient uniquement des maquettes, Publishing indique qu’il n’y a encore rien à déployer et vous invite à demander à Agent de créer une app. Une fois qu’un artefact Website existe, vous pouvez publier depuis Design ou Build.
    </Note>

    <Frame>
      <img src="/assets/mirror/04-build-request-d5a5a3428361.jpg" alt="L’espace de travail Build avec un design de portfolio sélectionné associé, la demande de création dans le Chat d’Agent et Publishing indiquant qu’un projet composé uniquement de maquettes n’a encore rien à déployer" width="1280" height="720" data-path="images/first-app-template/04-build-request.jpg" />
    </Frame>
  </Step>

  <Step title="Vérifiez le bon fonctionnement de l’app dans Preview">
    Une fois qu’Agent a terminé, ouvrez [Preview](/fr/features/editor/preview) et utilisez l’application comme le ferait un visiteur. Preview vous permet de tester l’application pendant que vous la créez, avant de la publier.

    Vérifiez que vous pouvez :

    * Naviguer à l’aide du menu principal.
    * Utiliser les boutons et les formulaires du template.
    * Voir un message clair de réussite ou de validation après une action.
    * Actualiser la page et réutiliser le site.
    * Redimensionner Preview à la largeur d’un téléphone.

    Si quelque chose ne fonctionne pas, décrivez le problème à Agent. Vous n’avez pas besoin de diagnostiquer le code vous-même.

    <Frame>
      <img src="/assets/mirror/05-preview-d5702e9d9ac8.jpg" alt="Le site web basé sur un template exécuté dans Preview du Project Editor" width="1280" height="720" data-path="images/first-app-template/05-preview.jpg" />
    </Frame>

    <Tip>
      Vous souhaitez explorer des variantes visuelles avant de publier ? Consultez [Explorer les suggestions](/fr/design/explore-suggestions) pour générer différentes apparences côte à côte et appliquer celle que vous préférez.
    </Tip>
  </Step>

  <Step title="Publiez votre application">
    Lorsque l’aperçu fonctionne, sélectionnez **Publier**. Confirmez le sous-domaine généré, choisissez qui peut accéder à l’app et vérifiez les paramètres de sécurité. Sélectionnez ensuite **Publier** dans la boîte de dialogue.

    La publication crée une version publique de votre app avec une URL que vous pouvez partager.

    <Frame>
      <img src="/assets/mirror/06-publish-dialog-2f79654c6dfb.jpg" alt="La boîte de dialogue Publier avec le sous-domaine généré, les paramètres d’accès et le bouton Publier" width="1280" height="720" data-path="images/first-app-template/06-publish-dialog.jpg" />
    </Frame>
  </Step>

  <Step title="Ouvrez votre app publiée">
    Ouvrez l’URL publique dans un nouvel onglet du navigateur et effectuez les mêmes vérifications. L’app doit fonctionner en dehors du Project Editor avant de la partager.

    Si l’app publiée se comporte différemment dans Preview, vérifiez les logs de publication et les paramètres de production dont elle a besoin. Pour les problèmes de publication courants, consultez [Résoudre les problèmes de publication](/fr/build/troubleshooting).

    <Frame>
      <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="Le site web final basé sur un template, ouvert à son URL Replit publique" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
    </Frame>
  </Step>
</Steps>

<div id="congratulations-you-shipped-your-first-app">
  ## 🎉 Félicitations — vous avez publié votre première app
</div>

Vous êtes passé d’un template de design à une URL publique et partageable. Au passage, vous avez :

* Choisi et remixé un template dans Replit Design.
* Demandé à Agent de transformer le design sélectionné en site web fonctionnel.
* Testé le résultat dans Preview.
* Publié l’app et l’avez ouverte à son URL publique.

Il s’agit d’un workflow Replit complet : choisissez un point de départ, créez, testez, améliorez et publiez.
