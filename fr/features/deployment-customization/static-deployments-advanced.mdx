<div id="add-response-headers">
  ## Ajouter des en-têtes de réponse
</div>

Les **en-têtes de réponse** personnalisés vous permettent d&#39;ajouter des instructions d&#39;en-tête HTTP aux requêtes correspondant à des chemins spécifiques.
Un en-tête de réponse est une paire nom-valeur qui indique aux navigateurs comment
interagir avec le contenu demandé.

Par exemple, vous pouvez utiliser l&#39;en-tête `Access-Control-Allow-Origin` pour préciser quels domaines le navigateur peut consulter pour cette page.
Pour créer cette entrée, ajoutez ce qui suit au fichier `.replit` situé à la racine de votre Replit App :

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

Cet en-tête de réponse comprend les paramètres suivants :

* **path** : modèle de chemin d&#39;URL correspondant aux ressources demandées
* **name** : nom de l&#39;en-tête HTTP
* **value** : valeur de l&#39;en-tête HTTP

Vous pouvez ajouter plusieurs entrées `deployment.responseHeaders` dans le fichier `.replit`.

Pour appliquer les modifications de configuration, republiez votre Replit App.

<div id="reserved-headers">
  #### En-têtes réservés
</div>

Age

Alt-Svc

Content-Encoding
Content-Length
Content-Range

<div id="create-a-custom-404-page">
  ## Créer une page 404 personnalisée
</div>

Une page 404 personnalisée s&#39;affiche lorsque les utilisateurs demandent des chemins d&#39;URL qui ne correspondent à aucun fichier ni à aucune règle de votre application publiée.

Pour ajouter une page 404 personnalisée, créez le contenu de la page dans un fichier nommé `404.html` placé à la racine de votre Replit App.

Lorsque les utilisateurs tentent d&#39;accéder à un chemin d&#39;URL inexistant, le HTML de la page 404 personnalisée s&#39;affiche.

<div id="define-url-path-rewrites">
  ## Définir des réécritures de chemin d&#39;URL
</div>

Vous pouvez définir des réécritures d&#39;URL afin de modifier le chemin d&#39;URL d&#39;une requête avant que votre Replit App ne la traite.
L&#39;URL d&#39;origine reste visible dans le navigateur, mais le serveur charge la ressource définie dans la règle de réécriture.

Par exemple, vous pouvez faire en sorte que toutes les requêtes commençant par `/app` chargent le contenu du fichier `/app/index.html`.
Pour créer cette entrée, ajoutez ce qui suit au fichier `.replit` situé dans le répertoire racine de votre Replit App :

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from** : modèle de chemin d&#39;URL correspondant aux ressources demandées
* **to** : chemin réécrit, qui correspond à un fichier de votre déploiement statique.

Vous pouvez ajouter plusieurs entrées `deployment.rewrites` au fichier `.replit`.
Le serveur interprète les entrées dans l&#39;ordre indiqué et ignore les doublons.

Pour appliquer les modifications de configuration, vous devez republier votre Replit App.

Les sections suivantes décrivent les contraintes applicables aux règles de réécriture d&#39;URL.

<div id="path-matching">
  ### Correspondance des chemins
</div>

Les contraintes suivantes s&#39;appliquent aux paramètres `from` et `to` des règles de réécriture :

* Les correspondances doivent être exactes, sauf en présence d&#39;un `*`
* Un `*` correspond au reste d&#39;un chemin
* Un `*` n&#39;est valide qu&#39;à la fin du chemin
* Si vous utilisez `*` dans le paramètre `from`, vous pouvez également l&#39;utiliser dans le paramètre `to` pour représenter la portion correspondante du chemin

Par exemple, si votre fichier `.replit` contient la réécriture suivante :

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

Lorsqu&#39;un utilisateur accède au chemin `/v1/about-us.html`, la réécriture renvoie le fichier situé à l&#39;emplacement `/v2/about-us.html`.

<div id="shadowing">
  ### Masquage
</div>

Le masquage se produit lorsqu&#39;une réécriture cible un chemin d&#39;URL qui correspond également à un fichier de votre déploiement statique.
Dans ce cas, le serveur cloud ignore la réécriture et sert le fichier directement.

Par exemple, supposons que votre application publiée contienne les fichiers suivants :

* `index.html`
* `about.html`

Le fichier `.replit` contient la réécriture suivante :

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

Lorsqu&#39;un utilisateur consulte `/register.html`, le serveur réécrit la requête vers `/index.html` et sert ce fichier.
En revanche, si un utilisateur consulte `/about.html`, le serveur ignore la règle de réécriture et sert le fichier `about.html`, puisque celui-ci existe dans votre déploiement statique.

<div id="domain-restrictions">
  ### Restrictions de domaine
</div>

Les réécritures ne fonctionnent que pour les requêtes adressées au domaine principal de votre déploiement statique et ne peuvent rediriger que vers des fichiers contenus dans ce déploiement.
