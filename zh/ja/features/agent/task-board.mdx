  ## 任务看板的运作方式
</div>

任务看板可让你集中查看、启动、监控和应用 Agent 任务。当 Agent 将大型请求拆分为多个部分、你想让任务在后台运行，或想了解项目中已有哪些更改时，可以使用它。

任务会按状态整理到不同列中。看板会显示 Agent 已规划的任务、正在执行的任务、等待审核的任务，以及已应用的任务。

每个任务会随进度从左向右移动：

* **草稿**：Agent 已规划但尚未开始的任务
* **进行中**：Agent 当前正在构建的任务 (包括因活跃任务数量限制而排队的任务)
* **准备就绪**：Agent 已完成且可供审核的任务
* **已完成**：已结束、归档或取消的任务

<div id="section-2">
  ## 草稿
</div>

**草稿**是 Agent 已规划但尚未开始构建的任务。每份草稿都包含标题、描述和分步计划。

使用草稿可在工作开始前查看 Agent 建议的处理方式。您可以查看计划、请 Agent 进行调整，或在准备就绪后启动任务。

如果您想在确定后台工作之前规划大型功能，草稿会很有帮助。例如，Agent 可能会将入门项目拆分为认证、个人资料设置、仪表板界面和部署收尾等独立草稿。

<div id="section-3">
  ## 进行中
</div>

批准任务后，任务会移入**进行中**列，Agent 随即开始构建。每个任务都在项目的独立副本中运行，因此在你应用相关改动之前，主版本不会发生任何变化。

有些任务可能依赖其他任务。例如，构建仪表板的任务可能需要先完成数据库架构的任务。存在依赖关系的任务会保持**已排队**状态，直到前置任务完成。当达到你所在套餐的后台任务并发上限时，任务同样会进入队列。

<div id="section-4">
  ## 准备就绪
</div>

任务构建完成后，会进入**准备就绪**状态。这表示工作已经完成，但主版本尚未发生任何更改。

应用更改有两种方式：

* **从会话中**：打开该任务的会话，选择**将更改应用到主版本**，把成果合入项目；或选择**放弃**，将其丢弃
* **从看板中**：点击准备就绪的任务卡片上的三点菜单，然后选择**应用更改**

应用来自多个任务的更改时，Agent 会自动处理冲突。如果发现有什么不对劲，可以让 Agent 进行修复。

<div id="section-6">
  ## 搜索和筛选任务
</div>

如果项目中有许多正在进行的任务，请使用任务看板。您可以按任务标题或任务编号进行搜索、筛选草稿，并通过编辑模式批量管理任务组。

例如，当任务在会话、评审或 Slack 对话中被提及时，可按任务编号搜索。若想专注于已计划的工作，而不必查看进行中或已完成的任务，可筛选草稿。

有关建议的后续任务，请参阅[后续任务](/zh/ja/features/agent/follow-up-tasks)。

<div id="section-7">
  ## 重命名任务
</div>

随着任务范围发生变化，长期运行的任务列表可能会变得难以浏览。要重命名任务，请打开任务卡片 (位于任务列表侧边栏或任务看板中) 的三点菜单，然后选择**重命名**。输入更清晰的标题，然后选择**保存**。

重命名任务只会更改你和团队成员看到的名称，不会影响 Agent 已完成的工作、任务历史记录或待处理的更改。

<div id="section-8">
  ## 每个任务的设置
</div>

每个任务的标题旁都有专属的设置下拉菜单。打开后，你可以控制 Agent 如何完成任务，以及结果如何应用到项目中：

* **自动应用更改** (草稿和进行中) ：任务准备就绪后，立即将更改应用到主版本，无需等待审核。
* **自动批准计划** (草稿) ：当 Agent 提出任务计划时，自动批准并开始构建。
* **应用更改** (准备就绪) ：将已完成的工作应用到主版本。
* **重命名**：更改卡片上显示的标题。
* **查看更改** (准备就绪) ：直接跳转到准备就绪任务的差异。
* **取消**：停止任务或删除草稿。

自动应用和自动批准并非持续开启的切换开关，而是一次性快速操作。菜单会保持固定宽度，因此即使打开不同的任务，标签也不会错位。
