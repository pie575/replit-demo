Agent prend en charge quatre types d&#39;intégrations pour passer rapidement de l&#39;idée à l&#39;application :

* **Gérées par Replit** : des intégrations natives qui fonctionnent automatiquement. Dès que vous créez une application, Agent peut les utiliser immédiatement.
* **Connecteurs** : des intégrations propriétaires prises en charge par Replit. Il vous suffit de vous connecter une fois pour qu&#39;Agent puisse lire et écrire dans ces services directement depuis la conversation — récupérer des données, créer des enregistrements, envoyer des messages — et les exploiter dans toute votre application.
* **Intégrations externes** : des services tiers fiables que vous pouvez utiliser pour créer vos applications. Demandez à Agent de les configurer et fournissez vos clés d&#39;API.
* **Services Agent** : des API tierces payantes qu&#39;Agent utilise en arrière-plan pour Build — aucune clé d&#39;API n&#39;est nécessaire. L&#39;utilisation est facturée sur vos crédits Replit.

<Note>
  **Disponibilité selon les plans** : la plupart des connecteurs nécessitent un abonnement Core, Pro ou Enterprise, et certains sont également disponibles avec le plan gratuit. Le catalogue de connecteurs de votre espace de travail indique ceux que vous pouvez utiliser avec votre plan actuel. Les créateurs sur le plan gratuit peuvent utiliser à tout moment les intégrations gérées par Replit, comme la base de données, l&#39;authentification, etc.
</Note>

<div id="section">
  ## Prise en main
</div>

Pour utiliser une intégration, mentionnez le service ou la fonctionnalité dont vous avez besoin. Par exemple :

<AiPrompt>
  Create a web app that uses Stripe to accept payments and SendGrid to send confirmation emails
</AiPrompt>

Agent détecte automatiquement ces mots-clés et met en place le code et la configuration nécessaires.

<div id="agent">
  ### Demander à Agent de suggérer des connecteurs
</div>

Pour enregistrer des fichiers ou envoyer des e-mails, par exemple, plusieurs services peuvent remplir le même rôle. Si vous demandez une fonctionnalité sans préciser de fournisseur, Agent affiche une courte liste de connecteurs adaptés. Sélectionnez celui que vous souhaitez utiliser.

Choisissez un fournisseur, puis connectez-vous une fois pour associer votre compte. Agent utilisera ensuite ce choix pour créer votre application. Vous pouvez aussi indiquer un service précis par son nom afin d&#39;éviter l&#39;affichage de la liste.

<div id="replitoauth">
  ### Configuration d&#39;une application OAuth dans Replit
</div>

<Note>
  **Enterprise uniquement** : la configuration d&#39;une application OAuth personnalisée nécessite un abonnement Enterprise.
</Note>

Avec un plan Enterprise, vous pouvez utiliser votre propre application OAuth pour les connecteurs plutôt que celle fournie par défaut par Replit. Votre organisation est ainsi propriétaire du client OAuth, affiche sa propre identité visuelle sur l&#39;écran de consentement et contrôle précisément les portées que les créateurs peuvent demander.

Pour configurer un connecteur avec votre propre application OAuth, vous avez besoin de trois éléments fournis par le fournisseur : un **identifiant client**, un **secret client** et les **portées** à autoriser. Vous devez également enregistrer l&#39;URL de rappel de Replit auprès du fournisseur afin que l&#39;authentification puisse aboutir.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Boîte de dialogue de configuration OAuth du connecteur avec les champs identifiant client, secret client et portées du connecteur, ainsi que l'URL de redirection définie sur https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Créer une application OAuth chez le fournisseur">
    Connectez-vous à la console développeur ou aux paramètres d&#39;administration du fournisseur, puis créez une nouvelle application OAuth 2.0. Le nom de cette étape varie selon le fournisseur — recherchez des options telles que **Créer une application OAuth**, **Enregistrer une application** ou **Créer des identifiants client**.
  </Step>

  <Step title="Configurer l'URL de redirection">
    Si le fournisseur demande une **URI de redirection autorisée** (parfois appelée **URL de rappel** ou **URL de redirection**), saisissez ce qui suit :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    C&#39;est à cette URL que le fournisseur renvoie les créateurs vers Replit une fois l&#39;application autorisée. Elle doit correspondre exactement, y compris la barre oblique finale, le protocole et le sous-domaine. Si vous ajoutez plusieurs URI de redirection, celle-ci doit en faire partie.
  </Step>

  <Step title="Copier l'identifiant client et le secret client">
    Après la création de l&#39;application, le fournisseur affiche un **identifiant client** et un **secret client**.

    * **Identifiant client** : identifiant public de votre application OAuth. Il peut être exposé sans risque dans les URL et le code côté client.
    * **Secret client** : valeur confidentielle qui prouve que les requêtes proviennent bien de votre application. Traitez-la comme un mot de passe — ne la validez jamais dans un dépôt et ne la publiez jamais. Replit la conserve en sécurité pour vous.

    Chez certains fournisseurs, le secret client n&#39;est affiché qu&#39;au moment de la création. Copiez-le immédiatement et conservez-le en lieu sûr jusqu&#39;à ce que vous le colliez dans Replit.
  </Step>

  <Step title="Choisir les portées">
    Les **portées** sont les autorisations qui définissent ce que votre application OAuth peut lire ou écrire au nom des créateurs. Chaque fournisseur publie sa propre liste de portées dans sa documentation d&#39;API.

    Les portées que vous saisissez lors de la configuration du connecteur dans Replit doivent correspondre **exactement** (caractère par caractère, préfixe d&#39;URL compris) à celles enregistrées chez le fournisseur. Causes courantes d&#39;erreurs de correspondance :

    * Absence du préfixe d&#39;URL complet (par exemple, `https://www.googleapis.com/auth/drive.file` au lieu de `drive.file`).
    * Espaces superflus ou virgules finales.
    * Demander dans Replit une portée qui n&#39;est pas activée dans l&#39;application du fournisseur.

    Commencez par le minimum de portées dont les créateurs ont besoin, puis ajoutez-en si nécessaire — la plupart des fournisseurs permettent de mettre à jour les portées sans recréer l&#39;application.
  </Step>

  <Step title="Configurer le connecteur dans Replit">
    Depuis la page **Connecteurs** de votre organisation, sélectionnez **Ajouter une nouvelle intégration**, choisissez le service, puis collez l&#39;**identifiant client**, le **secret client** et les **portées** obtenus auprès du fournisseur. Sélectionnez **Configurer** pour enregistrer.
  </Step>
</Steps>

<Note>
  Si l&#39;authentification échoue après la configuration, vérifiez que l&#39;URL de redirection du fournisseur correspond exactement à `https://replit.com/connectors/oauth/callback` et que toutes les portées saisies dans Replit sont également autorisées dans l&#39;application du fournisseur.
</Note>

<div id="section-9">
  ## Reconnecter une intégration
</div>

Si un service connecté cesse de fonctionner (par exemple, lorsque la session de connexion expire ou que les autorisations changent), Replit affiche une alerte de reconnexion dans l&#39;éditeur de projet. Sélectionnez cette alerte pour reconnecter directement l&#39;intégration, sans quitter l&#39;éditeur.
