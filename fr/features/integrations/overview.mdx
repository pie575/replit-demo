Agent prend en charge quatre types d&#39;intégrations pour passer rapidement de l&#39;idée à l&#39;application :

* **Gérées par Replit** : des intégrations natives qui fonctionnent automatiquement. Créez une application et votre Agent peut les utiliser immédiatement.
* **Connectors** : les intégrations propriétaires prises en charge par Replit. Connectez-vous une seule fois. Agent peut lire et écrire dans ces services directement depuis le chat — récupérer des données, créer des enregistrements, envoyer des messages — et s&#39;appuyer sur eux dans toutes vos applications.
* **Intégrations externes** : des services tiers de confiance avec lesquels vous pouvez développer. Demandez à Agent de les configurer ; vous devrez fournir des clés API.
* **Services Agent** : des API tierces payantes qu&#39;Agent utilise en arrière-plan — aucune clé API requise. L&#39;utilisation est facturée sur vos crédits Replit.

<Note>
  **Disponibilité selon le forfait** : la plupart des connectors nécessitent un abonnement Core, Pro ou Enterprise, et certains sont disponibles avec le forfait Free. Le catalogue de connectors de votre workspace indique quels connectors sont accessibles avec votre forfait actuel. Les créateurs du forfait Free peuvent toujours utiliser les intégrations gérées par Replit, comme les bases de données, l&#39;authentification, et bien plus encore.
</Note>

<div id="getting-started">
  ## Premiers pas
</div>

Pour utiliser une intégration, mentionnez le service ou la fonctionnalité dont vous avez besoin. Par exemple :

<AiPrompt>
  Crée une application web qui utilise Stripe pour accepter les paiements et SendGrid pour envoyer les e-mails de confirmation
</AiPrompt>

Agent détecte automatiquement ces mots-clés et met en place le code et la configuration nécessaires.

<div id="let-agent-suggest-a-connector">
  ### Laisser Agent suggérer un connector
</div>

Plusieurs services permettent parfois de remplir la même fonction, comme stocker des fichiers ou envoyer des e-mails. Lorsque vous demandez une fonctionnalité sans préciser de provider, Agent affiche une courte liste de connectors adaptés. Choisissez celui qui vous convient.

Sélectionnez un provider, puis connectez-vous une seule fois pour associer votre compte. Agent tient compte de votre choix pendant la création. Vous pouvez aussi indiquer directement le nom d&#39;un service précis pour ne pas passer par la liste.

<div id="configuring-oauth-app-with-replit">
  ### Configurer une application OAuth avec Replit
</div>

<Note>
  **Enterprise uniquement** : la configuration d&#39;une application OAuth personnalisée nécessite un abonnement Enterprise.
</Note>

Avec le plan Enterprise, vous pouvez utiliser votre propre application OAuth pour un connector plutôt que celle proposée par défaut par Replit. Votre organisation devient ainsi propriétaire du client OAuth, affiche sa propre identité visuelle sur l&#39;écran de consentement et contrôle précisément les portées que vos créateurs peuvent demander.

Pour configurer un connector avec votre propre application OAuth, trois éléments fournis par le provider vous sont nécessaires : un **Client ID**, un **Client Secret** et les **portées** que vous souhaitez autoriser. Vous devez également enregistrer l&#39;URL de rappel de Replit auprès du provider pour que l&#39;authentification puisse aboutir.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Boîte de dialogue de configuration OAuth du connector avec les champs Client ID, Client Secret et Connector Scopes, et une Redirect URL définie sur https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Créer une application OAuth auprès de votre provider">
    Connectez-vous à la console développeur ou aux paramètres d&#39;administration du provider et créez une nouvelle application OAuth 2.0. Chaque provider nomme cette étape différemment — cherchez des options telles que **Create OAuth app**, **Register application** ou **Create client credentials**.
  </Step>

  <Step title="Définir l'URL de redirection">
    Lorsque le provider demande une **Authorized redirect URI** (parfois appelée **Callback URL** ou **Redirect URL**), saisissez :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    C&#39;est vers cette URL que le provider renvoie les créateurs sur Replit après l&#39;autorisation de l&#39;application. Elle doit correspondre exactement : les barres obliques finales, le protocole et le sous-domaine comptent. Si vous ajoutez plusieurs URI de redirection, celle-ci doit en faire partie.
  </Step>

  <Step title="Copier le Client ID et le Client Secret">
    Une fois l&#39;application créée, le provider affiche un **Client ID** et un **Client Secret**.

    * **Client ID** : identifiant public de votre application OAuth. Il peut être exposé sans risque dans les URL et le code côté client.
    * **Client Secret** : valeur confidentielle qui prouve que la requête provient bien de votre application. Traitez-la comme un mot de passe — ne la publiez jamais dans un dépôt et ne la partagez jamais publiquement. Replit la stocke de façon sécurisée pour vous.

    Certains providers n&#39;affichent le client secret qu&#39;une seule fois, au moment de la création. Copiez-le immédiatement et conservez-le en lieu sûr jusqu&#39;à ce que vous le colliez dans Replit.
  </Step>

  <Step title="Choisir vos portées">
    Les **portées** sont les autorisations qui définissent ce que votre application OAuth peut lire ou écrire au nom du créateur. Chaque provider publie sa propre liste de portées dans sa documentation d&#39;API.

    Lorsque vous configurez le connector dans Replit, les portées que vous saisissez doivent **correspondre exactement** (caractère par caractère, préfixes d&#39;URL compris) à celles enregistrées auprès du provider. Causes fréquentes d&#39;erreurs de correspondance :

    * Absence du préfixe d&#39;URL complet (par exemple, `drive.file` au lieu de `https://www.googleapis.com/auth/drive.file`).
    * Espaces superflus ou virgules finales.
    * Demande dans Replit d&#39;une portée non activée sur l&#39;application du provider.

    Commencez par les portées minimales dont vos créateurs ont besoin, quitte à en ajouter d&#39;autres par la suite : la plupart des providers permettent de mettre à jour les portées sans recréer l&#39;application.
  </Step>

  <Step title="Configurer le connector dans Replit">
    Depuis la page **Connectors** de votre organisation, sélectionnez **Add new integration**, choisissez le service, puis collez le **Client ID**, le **Client Secret** et les **Scopes** fournis par le provider. Sélectionnez **Configure** pour enregistrer.
  </Step>
</Steps>

<Note>
  Si l&#39;authentification échoue après la configuration, vérifiez que l&#39;URL de redirection définie chez le provider correspond exactement à `https://replit.com/connectors/oauth/callback` et que chaque portée saisie dans Replit est également autorisée sur l&#39;application du provider.
</Note>
