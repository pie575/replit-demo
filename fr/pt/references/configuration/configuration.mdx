Les applications Replit se configurent à l’aide de deux fichiers : `.replit` et `replit.nix`. Ils déterminent le comportement de votre application Replit, de l’exécution du code aux outils et langages de développement.

Ces fichiers de configuration sont masqués par défaut. Affichez-les dans votre application Replit en sélectionnant &quot;Show hidden files&quot; dans le menu de l’arborescence des fichiers.

<div id="arquivo-replitnix">
  ## Fichier `replit.nix`
</div>

Replit utilise `Nix` pour gérer les paquets et les environnements. Le fichier `replit.nix` permet de :

**Spécifier les dépendances système :** définissez précisément les paquets logiciels requis par votre application Replit. Ils sont gérés par Nix, un gestionnaire de paquets.

**Créer des environnements reproductibles :** assurez-vous que votre environnement de développement est cohérent et reproductible, ce qui est idéal pour les projets collaboratifs et les tests sur plusieurs systèmes.

Vous pouvez gérer visuellement les paquets Nix à l’aide de l’outil `Dependencies`. Pour en savoir plus, consultez le guide des [Dépendances système](/fr/pt/references/workspace/dependency-management#system-dependencies).

Pour configurer des paquets avec le fichier `replit.nix`, vous pouvez répertorier des [paquets Nix](https://search.nixos.org/packages) dans le tableau `deps`, précédés de `pkgs.`. Toutes les modifications seront synchronisées après le rechargement de votre Shell.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="arquivo-replit">
  ## Fichier `.replit`
</div>

Le fichier `.replit` contrôle le comportement de votre application Replit. Il utilise le [format de configuration](https://toml.io/en/) `toml`. Voici quelques-uns des principaux aspects que vous pouvez configurer :

**Commande Run :** spécifiez la commande qui s&#39;exécute lorsque vous sélectionnez le bouton Run. Chaque template dispose d&#39;une commande run par défaut permettant d&#39;exécuter du code immédiatement. Pour les apps plus complexes et personnalisées, utilisez les [Workflows](/fr/pt/references/workspace/workflows).

**Language Server Protocol (LSP) :** fournit des fonctionnalités telles que l&#39;auto-complétion, la navigation dans le code, la coloration syntaxique ainsi que le linting et la détection d&#39;erreurs en temps réel.

**Variables d&#39;environnement :** définissez et gérez les variables d&#39;environnement indispensables au bon fonctionnement de vos applications.

**Dépendances et paquets :** gérez l&#39;installation des paquets et les configurations directement depuis le fichier `.replit`, afin que votre application Replit dispose de tous les outils nécessaires dès le démarrage. Vous pouvez gérer les dépendances visuellement grâce à l&#39;outil `Dependencies`. Pour en savoir plus, consultez le guide des [Modules système](/fr/pt/references/workspace/dependency-management#advanced-configuration).

Pour les applications Python, le fichier `.replit` par défaut est :

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

| **Clé de configuration**                        | **Valeur/Exemple**                     | **Description**                                                                                                                                                                                                                                     |
| ----------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a name="entrypoint" />`entrypoint`             | `main.py`                              | Spécifie le fichier principal à exécuter et à afficher par défaut à l’ouverture de l’éditeur. Vous pouvez renommer ce fichier en fonction de votre application.                                                                                     |
| <a name="modules" />`modules`                   | `["python-3.10:v18-20230807-322e88b"]` | Définit des versions précises des langages de programmation ou d’autres dépendances principales prises en charge par Replit.                                                                                                                        |
| <a name="nix" />`[nix]`                         |                                        | Spécifie les paramètres permettant d’utiliser Nix, un gestionnaire de paquets, pour gérer les dépendances système. Consultez la documentation sur la [gestion des dépendances](/fr/pt/references/workspace/dependency-management) pour en savoir plus. |
| <a name="channel" />`channel`                   | `stable-23_05`                         | Indique le canal Nix à utiliser, ce qui détermine les versions disponibles des dépendances système.                                                                                                                                                 |
| <a name="packages" />`packages`                 | `["cowsay", "htop"]`                   | Spécifie les paquets Nix à installer. Pour un contrôle plus précis, vous pouvez également utiliser `replit.nix`.                                                                                                                                    |
| <a name="unitTest" />`[unitTest]`               |                                        | Configure les paramètres liés aux tests unitaires dans l’application Replit.                                                                                                                                                                                  |
| <a name="language" />`language`                 | `python3`                              | Spécifie le langage utilisé pour les tests unitaires, indiquant que Python 3 est utilisé pour les écrire.                                                                                                                                           |
| <a name="gitHubImport" />`[gitHubImport]`       |                                        | Configure l’importation des projets depuis GitHub, notamment les fichiers à inclure.                                                                                                                                                                |
| <a name="requiredFiles" />`requiredFiles`       | `[".replit", "replit.nix"]`            | Liste les fichiers qui doivent être présents lors de l’importation du projet afin de garantir son bon fonctionnement.                                                                                                                               |
| <a name="deployment" />`[deployment]`           |                                        | Contient les paramètres nécessaires au déploiement de l’application Replit dans un environnement actif.                                                                                                                                         |
| <a name="run" />`run`                           | `["python3", "main.py"]`               | Commande exécutée pour démarrer l’application lors du déploiement.                                                                                                                                                                                  |
| <a name="deploymentTarget" />`deploymentTarget` | `cloudrun`                             | Spécifie la plateforme cible du déploiement qui héberge l’application.                                                                                                                                                                              |

Maintenant que vous avez un aperçu des paramètres par défaut du fichier `.replit`, consultez les sections suivantes pour découvrir comment configurer les options de base et avancées de votre application Replit.

<div id="configurando-definies-bsicas">
  ## Configuration des paramètres de base
</div>

<div id="entrypoint">
  ### Entrypoint
</div>

Il s&#39;agit du fichier principal de votre projet. Si vous ne définissez pas de propriété `run`, c&#39;est le fichier indiqué par `entrypoint` qui est exécuté par le runtime.

```toml theme={null}
entrypoint = "<nome-do-arquivo>.py"
```

<div id="comando-run">
  ### Commande `Run`
</div>

La propriété `run` du fichier `.replit` est un élément clé : elle détermine la commande initiale, ou la série de commandes, exécutée lorsque le bouton `Run` est sélectionné dans un environnement Replit. La commande `Run` peut être indiquée sous forme de chaîne représentant la commande à exécuter, ou sous forme de tableau de chaînes représentant la commande et ses différents arguments.

Voici quelques façons courantes de configurer la commande `Run` :

* **Commande unique :**
  Cet exemple montre comment transmettre une seule commande à exécuter directement dans l’application Replit. Avec cette ligne dans votre fichier `.replit`, appuyer sur le bouton `Run` affiche un message d&#39;accueil dans le panneau `Console` :
  **Exemple :** `run = "echo 'Hello, Replit!'"`

* **Arguments explicites :**
  Dans certains cas, il peut être utile d&#39;être plus explicite, ce qui évite d&#39;avoir à gérer les guillemets ou les règles d&#39;interpolation du Shell. Vous pouvez réécrire l&#39;exemple ci-dessus en séparant les arguments.
  Notez que vous n&#39;avez plus besoin de `'` ni de `"`, puisque vous transmettez explicitement le message d&#39;accueil comme premier et unique argument de `echo` :
  **Exemple :** `run = ["echo", "Hello, Replit!"]`

* **Commandes multiples :**
  Cet exemple montre comment exécuter simultanément plusieurs processus, par exemple un frontend et un backend. C&#39;est utile lorsque vous développez un backend Python et un frontend TypeScript, où chaque serveur écoute sur un port différent :
  **Exemple :** `run = "python -m app & npm run start & wait"`

<div id="gerenciamento-de-processos">
  #### Gestion des processus
</div>

Bien que plusieurs commandes puissent être exécutées simultanément avec `&`, vous souhaiterez peut-être mieux distinguer les logs des différents services. Vous pouvez [ajouter des dépendances système](/fr/pt/references/workspace/dependency-management#system-dependencies) telles que [`process-compose`](https://github.com/F1bonacc1/process-compose) afin de mieux orchestrer plusieurs processus.

<div id="fase-build">
  #### Phase `Build`
</div>

Pour certains langages ou environnements d&#39;exécution, une phase de compilation distincte est nécessaire avant que le code puisse être `exécuté`. Cela couvre aussi bien les langages compilés comme TypeScript, Golang ou Java, tout en offrant un paramètre qui vous permet de réinitialiser votre environnement, vos données ou votre configuration avant le prochain appel de `run`.

* **Compilation :**
  Dans un dépôt TypeScript, vous devrez peut-être exécuter `tsc` avant de lancer votre code.
  **Exemple :**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="incluindo-variveis-de-ambiente">
  #### Inclure des variables d&#39;environnement
</div>

Pour transmettre des variables d&#39;environnement à votre service avant son exécution, vous pouvez transformer la propriété `run` en [table](https://toml.io/en/v1.0.0#table).

Il s&#39;agit d&#39;une modification plus complexe, qui nécessitera probablement de déplacer votre propriété `run = "..."` dans le fichier `.replit`.

Le diff suivant illustre la définition de la commande via `args` dans `[run]`, ainsi que la variable `NAME` définie dans `[run.env]` :

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# Nous devons placer notre nouveau [run] après toutes les
+# propriétés de premier niveau qui ne commencent pas par `[` !
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="interatividade">
  #### Interactivité
</div>

Les programmes interactifs peuvent eux aussi être lancés à l&#39;aide du bouton `Run`, ce qui permet de distinguer votre environnement de développement du terminal dans lequel votre programme s&#39;exécute.
Prenons l&#39;exemple du script de comptage suivant :

**Exemple**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="opes-de-configurao-avanadas">
  ## Options de configuration avancées
</div>

Découvrez les options de configuration détaillées disponibles pour votre application Replit. Vous pouvez personnaliser votre environnement de développement, gérer les commandes run, intégrer des services de langage et gérer les dépendances.

| **Configuration** | **Clé**                             | **Valeur/Exemple**                          | **Description**                                                                                      |
| ----------------- | ----------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| onBoot            | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Commande exécutée au démarrage de l’application Replit.                                                     |
| compile           | <a name="compile" />`compile`       | (Aucun exemple par défaut)                  | Commande exécutée avant la commande `run`, utilisée pour les langages compilés comme le C++.         |
| language          | <a name="language" />`language`     | `language = "javascript"`                   | Spécifie le langage lors d&#39;une importation depuis GitHub ou de la création d&#39;une application Replit. |
| entrypoint        | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | Fichier principal à exécuter et à afficher à l&#39;ouverture de l&#39;éditeur.                       |
| hidden            | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | Fichiers ou dossiers masqués par défaut dans l&#39;arborescence latérale des fichiers.               |
| audio             | <a name="audio" />`audio`           | `audio = true`                              | Active l&#39;audio à l&#39;échelle du système lorsque la valeur est définie sur `true`.              |

<div id="notas-sobre-udio-em-todo-o-sistema">
  ### Notes sur l&#39;audio à l&#39;échelle du système
</div>

Lorsque vous définissez `audio = true` dans votre fichier `.replit`, il peut être nécessaire d&#39;exécuter `kill 1` dans un Shell pour que la nouvelle configuration prenne effet.

Lorsque vous exécutez une application graphique, une icône de casque audio accompagnée d&#39;une case à cocher apparaît en bas à droite du panneau `Output`.
En raison des restrictions du navigateur, cette option doit être réactivée à chaque actualisation.

```toml theme={null}
# Assurez-vous que cette ligne figure en haut de votre fichier `.replit`, en dehors de toute section entre crochets `[`
audio = true
```

<div id="configurao-do-packager">
  ## Configuration du gestionnaire de paquets
</div>

| **Configuration** | **Clé**                                           | **Valeur/Exemple**                            | **Description**                                                                                           |
| ----------------- | ------------------------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| packager          | <a name="language" />`language`                   | `packager.language = "python3"`               | Langage utilisé pour les opérations sur les paquets.                                                      |
| packager features | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Devine automatiquement les paquets à installer avant d&#39;exécuter l’application Replit.                        |
| packager features | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | Active la prise en charge du gestionnaire de paquets lorsque la valeur est `true`.                        |
| packager features | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Définit si l&#39;hébergement de l’application Replit nécessite l&#39;exécution d&#39;une installation de paquet. |
| packager          | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | Commande exécutée après l&#39;installation d&#39;un nouveau paquet via le gestionnaire de paquets.        |
| packager          | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | Chemins à ignorer lors de la détection automatique des paquets.                                           |
| packager          | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | Modules pour lesquels aucune détection automatique de paquet ne doit avoir lieu à l&#39;installation.     |

<div id="exemplo-de-configurao-replit-para-configurao-do-packager">
  ### Exemple de fichier `.replit` pour la configuration du gestionnaire de paquets
</div>

```toml theme={null}
# Définir le langage de la Replit App
packager.language = "python3"

# Activer les fonctionnalités de gestion automatique des paquets
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# Commande à exécuter après chaque installation de paquet
packager.afterInstall = "echo 'Package installed successfully'"

# Définir les chemins et les paquets que le gestionnaire de paquets doit ignorer
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# Paramètres de déploiement supplémentaires
[deployment]
run = ["python3", "app.py"]
```

<div id="configurao-de-deployment">
  ## Configuration du déploiement
</div>

| **Configuration** | **Clé**                               | **Valeur/Exemple**                   | **Description**                                                         |
| ----------------- | ------------------------------------- | ------------------------------------ | ----------------------------------------------------------------------- |
| déploiement        | <a name="run" />`run`                 | `deployment.run = "npm start"`       | Commande exécutée au démarrage d&#39;un conteneur de déploiement.        |
| déploiement        | <a name="build" />`build`             | `deployment.build = "npm run build"` | Commande exécutée avant le lancement d&#39;un déploiement.               |
| déploiement        | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | Si `true`, le déploiement peut réussir sans vérification de port ouvert. |

<div id="exemplo-de-configurao-replit-para-configurao-de-deployment">
  ### Exemple de fichier `.replit` pour la configuration du déploiement
</div>

```toml theme={null}

# Indique le point d’entrée principal du projet
entrypoint = "app.js"

# Paramètres de configuration du déploiement de l’application
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  **La configuration de l’interpréteur** est obsolète et n’est plus disponible sur Replit. Utilisez plutôt les commandes `Run` pour configurer l’exécution des scripts et des applications dans votre environnement d’application Replit.
</Note>

<div id="acessando-metadados-do-ambiente-do-replit-app">
  ## Accéder aux métadonnées d&#39;environnement de l&#39;application Replit
</div>

<div id="nodejs">
  ### Node.js
</div>

Pour accéder à toutes les variables d&#39;environnement :

`console.log(process.env);`

Pour accéder à une seule variable (REPL&#95;SLUG) :

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

Pour accéder à toutes les variables d’environnement :

```python theme={null}
import os
print(os.environ)
```

Pour accéder à une seule variable (REPL&#95;SLUG) :

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

Pour accéder à toutes les variables d&#39;environnement :

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

Pour accéder à une seule variable (REPL&#95;SLUG) :

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```
