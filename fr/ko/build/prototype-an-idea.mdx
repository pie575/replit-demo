I want a clean, modern web app where I can track my runs and see my progress at a glance — a friendlier, more visual version of a running journal like Strava or Nike Run Club, but simpler and prettier. It only needs to support one user (me) for now, and my profile name should be Alex Morgan. Pre-fill it with about a month of pretend running history so it looks alive from the moment I open it — runs through San Francisco, a mix of easy runs, tempo runs, long runs, and recovery runs, with at least 4–5 runs in the past week so the dashboard looks active.

The app should run in any modern browser, feel fast, and be fully responsive — great on desktop, tablet, and phone.

It should feel calm and uncluttered, not busy. Light mode by default. Smooth, subtle animations when pages transition, when cards appear, and when I click buttons — it should feel responsive and alive, not stiff.

Full list of all my runs, grouped by month (sticky month headers as I scroll). Each row like the recent-runs rows. A search input in the top-right filters by name or run type (Easy, Tempo, Long, Recovery, Interval). Click a row → run detail.

The Stats page — a scrollable view with:

- The greeting changes based on time of day.
- Hero "Start a Run" and the nav "Log a Run" both open the same Log a Run dialog.

export const PromptActions = ({prompt = "", campaign = "docs-prompt-actions"}) => {
  const LZ_SRC = "https://cdnjs.cloudflare.com/ajax/libs/lz-string/1.5.0/lz-string.min.js";
  const ensureLZString = () => {
    if (typeof document === "undefined") return;
    if (window.LZString) return;
    if (document.querySelector(`script[src="${LZ_SRC}"]`)) return;
    const s = document.createElement("script");
    s.src = LZ_SRC;
    s.async = true;
    document.head.appendChild(s);
  };
  const handleCopy = async e => {
    const btn = e.currentTarget;
    if (!prompt) return;
    try {
      await navigator.clipboard.writeText(prompt);
    } catch {
      const ta = document.createElement("textarea");
      ta.value = prompt;
      document.body.appendChild(ta);
      ta.select();
      try {
        document.execCommand("copy");
      } catch {}
      document.body.removeChild(ta);
    }
    const original = btn.dataset.label || btn.innerText;
    btn.dataset.label = original;
    btn.innerText = "Copié !";
    setTimeout(() => {
      if (btn.isConnected) btn.innerText = original;
    }, 1500);
  };
  const handleBuild = () => {
    if (!prompt || typeof window === "undefined") return;
    const utm = `utm_source=replit-docs&utm_medium=docs&utm_campaign=${encodeURIComponent(campaign)}&utm_content=prompt-actions`;
    let url;
    if (window.LZString) {
      const encoded = window.LZString.compressToEncodedURIComponent(prompt);
      url = `https://replit.com/?prompt=${encoded}&referrer=replit-docs&${utm}`;
    } else {
      url = `https://replit.com/?prompt=${encodeURIComponent(prompt)}&referrer=replit-docs&${utm}`;
    }
    window.open(url, "_blank", "noopener,noreferrer");
  };
  ensureLZString();
  const baseButtonStyle = {
    display: "inline-flex",
    alignItems: "center",
    gap: "6px",
    padding: "8px 16px",
    borderRadius: "8px",
    fontSize: "14px",
    fontWeight: 500,
    cursor: "pointer",
    lineHeight: 1.2,
    fontFamily: "inherit",
    textDecoration: "none"
  };
  return <div style={{
    display: "flex",
    gap: "12px",
    margin: "16px 0",
    flexWrap: "wrap",
    alignItems: "center"
  }}>
      <button type="button" onClick={handleCopy} style={{
    ...baseButtonStyle,
    background: "transparent",
    color: "inherit",
    border: "1px solid rgba(127,127,127,0.4)"
  }}>
        Copier le prompt
      </button>
      <button type="button" onClick={handleBuild} style={{
    ...baseButtonStyle,
    background: "#F26207",
    color: "#FFFFFF",
    border: "1px solid #F26207"
  }}>
        Créer sur Replit ↗
      </button>
    </div>;
};

<div id="section">
  ## Ce que vous apprendrez
</div>

Vous apprendrez à :

* transformer une idée de produit générale en un parcours testable.
* utiliser le mode Plan pour définir le périmètre d’un prototype avant de le développer.
* vérifier si le plan d’Agent est suffisamment restreint pour être testé.
* utiliser les annotations et les fonctionnalités de collaboration de Canvas pour recueillir des retours dans leur contexte.
* explorer en parallèle deux pistes de prototype lorsque l’orientation du produit n’est pas claire.

<div id="section-4">
  ### Développer en parallèle
</div>

Lorsque les questions d’orientation produit ne portent pas uniquement sur l’implémentation, explorer plusieurs idées simultanément vous permet de comparer les options plutôt que de vous engager trop tôt. Replit Agent prend en charge le travail en parallèle : vous pouvez demander à Agent de travailler simultanément sur plusieurs prototypes, fonctionnalités ou expériences, puis les examiner côte à côte.

<Frame>
  <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="Vue d’un fil de discussion montrant plusieurs tâches Agent exécutées en parallèle avec des indicateurs d’état" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
</Frame>

Pour savoir comment les tâches entrent dans la file d’attente, s’exécutent et se terminent, consultez le [système de tâches](/fr/ko/core-concepts/agent/task-system).

Lorsque vous ne savez pas quelle direction privilégier, demandez à Agent de créer deux tâches parallèles. Pour Pace, vous pouvez comparer :

* **Prototype axé sur la motivation** : séries, succès et recommandations encourageantes.
* **Prototype axé sur l’analyse** : statistiques plus détaillées, tendances d’une semaine à l’autre et records personnels.

Une fois les deux tâches terminées, comparez-les à l’aide de la même question :

> Quelle version est la plus susceptible de me faire revenir demain, et pourquoi ?

<div id="section-5">
  ## Besoin d’aide supplémentaire ?
</div>

* **Si votre prototype comporte trop de fonctionnalités :** demandez à Agent de le simplifier pour un seul utilisateur cible et un seul parcours.
* **Si la cible n’est pas clairement définie :** demandez à Agent de réécrire la section d’accueil pour un seul utilisateur cible.
* **Si les données fictives masquent les risques :** demandez à Agent de dresser la liste de ce qui est réel et de ce qui est fictif.
* **Si les retours sont vagues :** donnez à l’évaluateur une tâche et une question.
* **Si la publication échoue :** consultez le [dépannage de la publication](/fr/ko/build/troubleshooting).
