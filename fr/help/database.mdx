Ces réponses concernent la base de données de production. Pour en savoir plus, consultez [Bases de données de production](/fr/features/data-and-storage/development-and-production) et [Base de données SQL](/fr/features/data-and-storage/sql-database).

<AccordionGroup>
  <Accordion title="Mes points de terminaison de base de données sont désactivés : comment corriger l’erreur &#x22;endpoint has been disabled&#x22; ?">
    Cette erreur signifie que le point de terminaison de calcul de votre base de données a été mis en pause. Pour le réactiver :

    1. Ouvrez le volet **Database** et sélectionnez **Development** dans le menu déroulant.
    2. Si le bouton **Unpause database** apparaît, sélectionnez-le.
    3. Sélectionnez ensuite **Production** dans le menu déroulant, puis à nouveau **Unpause database** s’il apparaît.

    Si le bouton n’apparaît pas, un secret `DATABASE_URL` en conflit peut le masquer. Ouvrez le volet **Secrets**, comparez toute entrée `DATABASE_URL` avec la chaîne de connexion du volet **Database**, puis mettez à jour ou supprimez le secret en conflit pour qu’elles correspondent.

    Les causes courantes sont une facture impayée (réglez-la pour éviter que le problème ne se reproduise) ou une mise en pause temporaire pendant la publication (les étapes de réactivation ci-dessus résolvent le problème). Consultez [Bases de données de production](/fr/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="La page d’état indique une interruption de la base de données de production : dois-je créer un ticket ?">
    Non. Si l’interruption est déjà signalée sur [status.replit.com](https://status.replit.com), l’équipe travaille à sa résolution et un ticket n’accélérera pas les choses. Ouvrez l’incident en cours et abonnez-vous aux mises à jour pour être informé de son évolution.

    Si votre problème de base de données n’est *pas* signalé sur la page d’état, [contactez l’assistance Replit](https://replit.com/support).
  </Accordion>

  <Accordion title="Comment restaurer une table de base de données supprimée ?">
    Replit prend en charge la restauration à un instant donné des bases de données de production. La période de restauration dépend de votre forfait : 7 jours avec [Core](/fr/billing/plans/replit-core) et 28 jours avec [Pro](/fr/billing/plans/replit-pro).

    Pour restaurer une table, ouvrez le volet **Database**, accédez à la base de données, ouvrez ses paramètres de restauration, sélectionnez l’horodatage souhaité et confirmez. Si la période de restauration est expirée, [contactez l’assistance Replit](https://replit.com/support). Consultez [Bases de données de production](/fr/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="Ma base de données est bloquée et je ne vois pas de bouton Unpause">
    Une URL de base de données en conflit masque généralement le bouton **Unpause**. Ouvrez le volet **Secrets**, recherchez toute entrée `DATABASE_URL` et comparez-la avec la chaîne de connexion du volet **Database**. Si elles diffèrent, le secret remplace l’URL correcte : supprimez-le, actualisez la page et vérifiez à nouveau le volet **Database**.

    Si le bouton n’apparaît toujours pas après la suppression du secret en conflit, [contactez l’assistance Replit](https://replit.com/support) en indiquant l’URL de votre projet.
  </Accordion>

  <Accordion title="Mon application génère des erreurs &#x22;connection pool exhausted&#x22; : qu’est-ce que cela signifie ?">
    Votre application ouvre simultanément plus de connexions à la base de données que le pool ne l’autorise. Causes courantes :

    * Des connexions qui ne sont pas fermées après chaque requête
    * Un pic de trafic
    * Des requêtes lentes qui maintiennent les connexions ouvertes

    La plupart des frameworks utilisent un pool de connexions partagé unique plutôt qu’une nouvelle connexion par requête.

    Pour résoudre le problème rapidement, ouvrez un nouveau Chat Agent, décrivez l’erreur et demandez à Agent de vérifier comment votre application gère les connexions à la base de données.
  </Accordion>

  <Accordion title="Comment migrer de la base de données de développement vers la production ?">
    Replit sépare les bases de données de développement et de production afin que les modifications de test n’affectent pas les données en ligne. Pour exécuter des migrations en production, ajoutez votre commande de migration à l’étape de build ou de pré-déploiement de votre deployment afin qu’elle s’exécute à chaque déploiement. Par exemple, utilisez `drizzle-kit migrate` pour Drizzle. Vous pouvez également exécuter la migration manuellement depuis un Shell dans votre environnement de production.

    Consultez [Créer une base de données de production lors de la publication](/fr/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="Ma base de données affiche &#x22;endpoint disabled&#x22; alors que ma facturation est à jour">
    Cela peut parfois se produire indépendamment de la facturation. Essayez de la réactiver manuellement : ouvrez le volet **Database**, sélectionnez **Development**, puis **Unpause database** s’il apparaît, et répétez l’opération pour **Production**.

    Si le bouton n’apparaît pas ou si le problème se reproduit, [contactez l’assistance Replit](https://replit.com/support) en indiquant l’URL de votre projet : une réactivation manuelle peut être nécessaire. Consultez [Bases de données de production](/fr/features/data-and-storage/development-and-production).
  </Accordion>
</AccordionGroup>
