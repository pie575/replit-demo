Une application est un logiciel conçu pour accomplir une tâche précise au bénéfice d&#39;une personne ou d&#39;un groupe donné.

Les applications peuvent être simples comme complexes. Une calculatrice, un formulaire de réservation, un tableau de bord, un outil interne, une expérience mobile, une place de marché ou un portail client : tout cela constitue une application dès lors qu&#39;elle aide quelqu&#39;un à accomplir quelque chose d&#39;utile.

<div id="section">
  ## Une application, c&#39;est du code qui s&#39;exécute sur une infrastructure
</div>

Toute application repose sur deux éléments qui fonctionnent de pair :

* **Le code** — les instructions qui décrivent ce que fait l&#39;application : l&#39;interface que les gens voient, la logique qui répond aux clics et aux saisies, les règles qui déterminent la circulation des données.
* **L&#39;infrastructure** — les machines, les réseaux, le stockage et les services qui permettent au code de s&#39;exécuter et d&#39;être accessible aux autres depuis un navigateur ou un téléphone.

Écrire du code, c&#39;est la partie que la plupart des gens imaginent quand on parle de « créer une application ». L&#39;infrastructure, c&#39;est tout le reste, indispensable pour que ce code fonctionne réellement pour les utilisateurs : un serveur pour l&#39;exécuter, une base de données pour stocker les informations, un domaine pour que les gens vous trouvent, la sécurité pour vous protéger, et un moyen de mettre à jour l&#39;application sans casser ce qui fonctionne déjà.

Sur Replit, vous décrivez ce que vous voulez en langage naturel. Agent écrit le code et Replit fournit l&#39;infrastructure — hébergement, bases de données, secrets, domaines, déploiements — pour que vous puissiez publier une application fonctionnelle sans rien configurer vous-même.

<div id="section-2">
  ## Pourquoi créer une application ?
</div>

On crée parfois une application lorsque les outils existants fonctionnent presque, mais pas tout à fait.

Une application est utile lorsque :

* vous avez besoin d&#39;un flux de travail personnalisé
* vous atteignez les limites des feuilles de calcul, des formulaires ou des modèles
* vous avez besoin d&#39;un processus réutilisable
* vous souhaitez tester la demande pour une idée
* vous voulez que vos coéquipiers, vos clients ou vos utilisateurs interagissent avec quelque chose que vous maîtrisez

Par exemple, un entrepreneur peut créer une application de liste d&#39;attente pour tester la demande. Un spécialiste du marketing peut créer une page de destination de campagne assortie d&#39;un formulaire. Un analyste de données peut créer un tableau de bord qui rend une feuille de calcul plus facile à explorer.

<div id="section-3">
  ## Les applications résolvent des problèmes ciblés
</div>

Plus votre première application est ciblée, mieux c&#39;est : elle résout un problème précis pour un public précis.

Plutôt que de commencer ainsi :

```text theme={null}
ビジネス全体を管理するためのプラットフォーム。
```

Commencez comme suit :

```text theme={null}
Une page permettant aux clients de demander un devis de traiteur et de recevoir un message de confirmation.
```

Les versions plus petites sont plus faciles à créer, à tester, à publier et à améliorer.

<div id="section-4">
  ## Applications et artefacts
</div>

Sur Replit, une application est un type d&#39;artefact. Les artefacts sont les productions qu&#39;un projet permet de publier.

Les artefacts comprennent :

* les applications web
* les applications mobiles
* les tableaux de bord de données
* les présentations
* les vidéos animées
* les créations graphiques
* les expériences 3D

Une application est généralement interactive. Bien souvent, elle permet aux utilisateurs d&#39;envoyer des informations, d&#39;afficher des données, de se connecter, de faire des choix ou de mener à bien un flux de travail. D&#39;autres artefacts, comme les présentations ou les vidéos animées, mettent plutôt l&#39;accent sur la présentation et la narration.

<div id="section-5">
  ## Qu&#39;est-ce qui rend une application « réelle » ?
</div>

Une application commence à devenir réelle quand quelqu&#39;un peut l&#39;utiliser en dehors de votre imagination.

En général, cela signifie qu&#39;elle :

* a un objectif clair et unique
* permet à quelqu&#39;un d&#39;accomplir l&#39;action principale
* peut être testée dans l&#39;aperçu
* peut être publiée sur une URL partageable
* peut être améliorée à la suite des retours

La première version n&#39;a pas besoin de toutes les fonctionnalités. Il suffit qu&#39;elle fonctionne assez bien pour vous permettre d&#39;apprendre.

<div id="section-6">
  ## Idées reçues fréquentes
</div>

* **« Une application doit être ambitieuse »** — beaucoup d&#39;applications à forte valeur ajoutée sont de petits outils conçus pour une tâche précise.
* **« Une application doit être publique »** — certaines applications sont des outils privés, destinés à vous, à votre équipe ou à vos clients.
* **« Une application doit être parfaite avant sa publication »** — publier une première version ciblée vous permet de découvrir ce qu&#39;il faut améliorer.
