数据仓库连接器让 Replit Agent 能够安全地查询组织的数据仓库。开发者只需使用自然语言，即可创建仪表板、报表工具和数据应用，无需掌握 SQL。管理员则可通过基于角色的访问控制实现集中管理。

<div id="supported-warehouses">
  ## 支持的数据仓库
</div>

数据仓库连接器仅在 **Enterprise** 套餐中提供。

| 数据仓库             | 设置指南                                                                          |
| ---------------- | ----------------------------------------------------------------------------- |
| BigQuery         | 现已提供 — 设置指南编写中                                                                |
| Databricks       | [连接 Databricks](/zh/connectors/warehouses/databricks)                            |
| Microsoft Fabric | [在 Microsoft Fabric 上构建数据应用](/zh/connectors/warehouses/microsoft-fabric) (私有预览)  |
| Snowflake        | [连接 Snowflake](/zh/connectors/warehouses/snowflake)                              |

由于各数据仓库的 OAuth integration、身份模型和凭据格式不同，每个数据仓库的设置流程也各不相同。请选择你使用的数据仓库，并参照对应的专属指南进行操作。

<div id="analytics-and-data-platforms">
  ## 分析与数据平台
</div>

分析类连接器适用于 Core、Pro 和 Enterprise 方案。连接你的分析工具后，Agent 即可读取并处理你的产品数据：

* **Segment** — 来自 CDP 的客户数据、事件流和受众分群
* **Amplitude** — 产品分析、用户行为数据和参与度指标
* **Hex** — 协作式数据笔记本和查询结果

这些连接器的管理方式与其他 Replit 连接器相同。请参阅[管理你的连接器](/zh/replitai/managing-connectors)。

<div id="how-warehouse-connectors-work">
  ## 数据仓库连接器的工作原理
</div>

设置只需完成一次，涉及三种角色：

1. **数据仓库管理员** — 在数据仓库中创建 OAuth integration 或服务身份
2. **Replit 组织管理员** — 将凭据添加到 Replit 并配置访问权限
3. **构建者** — 登录并开始使用 Agent 进行构建

配置完成后，构建者只需让 Agent 使用该数据仓库，Agent 便会针对该仓库编写并执行 SQL。

<div id="building-with-warehouse-data">
  ### 使用数据仓库数据构建应用
</div>

连接完成后，你可以让 Agent 基于你的数据构建应用。Agent 可以：

* 构建可获取并展示实时数据的内部工具
* 创建以数据仓库为数据源的图表与可视化仪表板
* 生成 SQL 查询，为应用后端提供支持
* 讲解 schema 和表结构，帮助你明确该构建什么

<Note>
  虽然 Agent 可以随时回答与你的数据相关的问题，但数据仓库连接器的主要用途是让 Agent 能够构建充分利用组织数据的实用应用。数据仓库查询会直接在你的实例上执行，因此请确保 OAuth 权限范围和数据库用户权限允许所需的读写操作。
</Note>
