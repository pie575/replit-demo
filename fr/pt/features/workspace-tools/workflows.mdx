Il s&#39;agit d&#39;une séquence d&#39;étapes réutilisable et personnalisable qui peut être exécutée au sein de votre Replit App. Les workflows peuvent être aussi simples que l&#39;exécution de `python main.py` ou aussi complexes qu&#39;une procédure en plusieurs étapes.

<Frame>
  <img src="/assets/mirror/workflows-pane-e7d5e4251006.png" alt="image" width="525" height="622" data-path="images/workflows/workflows-pane.png" />
</Frame>

Exemples de cas d&#39;usage :

* Exécuter plusieurs services en parallèle (par exemple, frontend + backend)
* Exécuter des fichiers ou des commandes de manière séquentielle (par exemple, exécuter le linter → exécuter les tests, compiler → exécuter le code)

Pour commencer à [créer des workflows](#creating-workflows), ouvrez le panneau Workflows depuis le menu de la barre latérale d&#39;outils, ou recherchez-le avec `Command + K`.

<div id="tipos-de-tarefas-disponveis">
  ## Types de tâches disponibles
</div>

Il existe actuellement 3 types de tâches : `Execute Shell Command`, `Install Packages` et `Run Workflow`.

<div id="execute-shell-command">
  ### Execute Shell Command
</div>

`Execute Shell Command` enregistre une commande shell et l&#39;exécute dans le même environnement que le panneau Shell. Ce type de tâche couvre un large éventail de cas d&#39;usage, allant de l&#39;exécution de fichiers individuels :

```text theme={null}
python main.py
```

jusqu&#39;à l&#39;exécution de commandes complexes enregistrées pour interroger la base de données :

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Install Packages
</div>

`Install Packages` s&#39;appuie sur le système de gestion des dépendances intégré de Replit : il détecte automatiquement les dépendances de votre projet et installe les paquets nécessaires. Consultez [Gestion des dépendances](/fr/pt/features/project-setup/dependency-management#the-universal-package-manager) pour en savoir plus sur la façon dont UPM détermine en interne les paquets à installer pour votre projet.

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow` permet d&#39;exécuter un autre workflow depuis le workflow en cours. Vous pouvez ainsi réutiliser des workflows et les combiner pour en créer de plus complexes.

Exemple de cas d&#39;usage :

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

En utilisant ce type de tâche pour créer des dépendances entre workflows, vous pouvez modifier un workflow et faire en sorte que les autres workflows qui y font référence reprennent automatiquement les dernières modifications. Notez qu&#39;une limite de profondeur s&#39;applique aux appels de workflows fortement imbriqués.

<div id="modo-de-execuo-de-workflow">
  ## Mode d&#39;exécution des Workflows
</div>

Les Workflows proposent deux modes d&#39;exécution : séquentiel et parallèle.

<div id="sequencial">
  ### Séquentiel
</div>

L&#39;exécution séquentielle lance chaque tâche dans l&#39;ordre défini, en attendant qu&#39;une tâche se termine avant de passer à l&#39;étape suivante, et en interrompant la séquence si une tâche du workflow échoue.

Ce mode est utile pour définir des commandes logiquement liées entre elles, comme des commandes Git permettant de récupérer les dernières modifications de votre branche principale, puis de rebaser votre branche actuelle sur celle-ci :

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="image" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="paralelo">
  ### Parallèle
</div>

L&#39;exécution parallèle lance chaque tâche en parallèle : chaque tâche démarre et s&#39;exécute indépendamment des autres tâches du workflow. L&#39;échec d&#39;une tâche n&#39;interrompt pas l&#39;exécution des autres.

Ce mode est utile, par exemple, pour exécuter un projet fullstack qui doit démarrer à la fois le serveur frontend et le backend :

<div id="criando-workflows">
  ## Créer des workflows
</div>

Vous pouvez créer des workflows depuis le panneau des workflows, en cliquant sur le bouton `+ New Workflow`. Commencez par donner un nom descriptif à votre workflow, choisissez un mode d&#39;exécution adapté, puis ajoutez des tâches. Vous pouvez réorganiser les tâches par glisser-déposer pour obtenir l&#39;ordre souhaité.

<div id="atribuir-workflow-ao-boto-run">
  ## Associer un workflow au bouton Run
</div>

Vous pouvez également associer un workflow au bouton Run afin de remplacer son comportement par défaut (voir [Configurer une Replit App](/fr/pt/features/project-setup/configuration)). Pour conserver la commande d’exécution par défaut configurée dans `.replit`, sélectionnez l’option « Run Replit App » dans le menu déroulant.

Le workflow sélectionné dans le menu déroulant à côté du bouton Run s’exécute lorsque vous cliquez sur ce bouton. Pour modifier le workflow exécuté par le bouton Run, sélectionnez le workflow souhaité dans le menu déroulant.
