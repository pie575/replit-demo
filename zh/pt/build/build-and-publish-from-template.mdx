⏰ *预计用时：10 分钟*

完成本指南后，你将拥有一个已发布且可通过 URL 分享的小型 App。

<Frame>
  <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="选中的模板已构建为网站，并已在其公开的 Replit URL 中打开" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
</Frame>

你将从一个精美的模板开始，将其转换为可用的网站并发布。具体可用的模板可能会有所变化，请选择符合你要构建内容的模板。

<div id="before-you-start">
  ## 开始前准备
</div>

你需要一个 [Replit 账户](https://replit.com)。从 Design frame 创建新 App 需要 Core 或 Pro。有关套餐详情，请参阅[构建设计](/zh/design/build-your-design)和[计费](/zh/billing/ai-billing)。

目标是完成一个完整流程：

* 在 [Replit Design](https://replit.com/design) 中选择一个 template，
* 使用 [Agent](/zh/features/agent/overview) 进行构建，
* 测试 App，
* 发布并分享。

Agent 是 Replit 的 AI 构建助手。你只需描述想要实现的内容，Agent 就会帮助你创建、说明和修复 App。

<div id="choose-build-and-publish-a-template">
  ## 选择、构建并发布模板
</div>

<Steps>
  <Step title="浏览设计模板">
    打开 [replit.com/design](https://replit.com/design)。浏览精选模板，或按 **落地页**、**移动端**、**原型** 等格式筛选。

    <Frame>
      <img src="/assets/mirror/01-design-gallery-5303cf1cf6d2.jpg" alt="Replit Design 作品展厅，展示精选模板和格式筛选器" width="1280" height="720" data-path="images/first-app-template/01-design-gallery.jpg" />
    </Frame>
  </Step>

  <Step title="预览并使用模板">
    选择一个模板进行查看，然后选择**使用模板**。Replit 会创建一个新项目，并将该模板放到 Design Canvas 上。如果你是从模板封面页开始，请参阅[从模板开始](/zh/design/start-from-a-template)，了解 remix 流程。

    <Frame>
      <img src="/assets/mirror/02-template-preview-facda2e40956.jpg" alt="带有“使用模板”按钮的 Replit Design 模板预览" width="1280" height="720" data-path="images/first-app-template/02-template-preview.jpg" />
    </Frame>

    Remix 后的模板会在新项目的 Design Canvas 上打开。

    <Frame>
      <img src="/assets/mirror/03-remixed-design-35b051544510.jpg" alt="所选模板已 remix 到新 Replit 项目的 Design Canvas 上" width="1280" height="720" data-path="images/first-app-template/03-remixed-design.jpg" />
    </Frame>
  </Step>

  <Step title="将设计转为网站">
    模板最初是设计稿。在发布之前，请切换到 **Build**，让 Agent 将所选设计制作成功能完善的网站。例如：

    > 将这个选定模板制作成功能完善的网站。保留其视觉设计，并让导航和联系功能正常运作。

    Agent 会在同一项目中创建一个网站 artifact，并以所选设计为基础。

    <Note>
      **Publish** 按钮在 Design 中也可见。如果项目仅包含设计稿，Publishing 会提示目前没有可部署的内容，并引导你让 Agent 构建 app。创建 Website artifact 后，你可以在 Design 或 Build 中发布。
    </Note>

    <Frame>
      <img src="/assets/mirror/04-build-request-d5a5a3428361.jpg" alt="Build 工作区：已附加选定的作品集设计、Agent chat 中的构建请求，以及 Publishing 说明仅含设计稿的项目目前没有可部署内容" width="1280" height="720" data-path="images/first-app-template/04-build-request.jpg" />
    </Frame>
  </Step>

  <Step title="确认应用能在 Preview 中正常运行">
    当 Agent 完成后，打开 [Preview](/zh/features/editor/preview)，像访客一样体验应用。Preview 可让你在构建应用的过程中、发布前测试应用。

    确认你可以：

    * 使用主导航。
    * 使用模板中的按钮和表单。
    * 执行操作后看到明确的成功或验证状态。
    * 刷新页面后再次使用网站。
    * 将 Preview 调整为手机屏幕宽度。

    如果出现问题，请向 Agent 描述具体症状。你无需自行诊断代码。

    <Frame>
      <img src="/assets/mirror/05-preview-d5702e9d9ac8.jpg" alt="基于模板的网站正在 Project Editor 的 Preview 中运行" width="1280" height="720" data-path="images/first-app-template/05-preview.jpg" />
    </Frame>

    <Tip>
      想在发布前探索不同的视觉方案？请参阅 [探索建议](/zh/design/explore-suggestions)，并排生成不同的外观，然后应用你喜欢的方案。
    </Tip>
  </Step>

  <Step title="发布你的 App">
    当 Preview 正常运行后，选择 **发布**。确认自动生成的子域名，选择可访问该 App 的用户，并检查安全设置。然后在对话框中选择 **发布**。

    Publishing 会创建可公开访问的 App 版本，并生成可分享的 URL。

    <Frame>
      <img src="/assets/mirror/06-publish-dialog-2f79654c6dfb.jpg" alt="发布对话框，包含自动生成的子域名、访问设置和发布按钮" width="1280" height="720" data-path="images/first-app-template/06-publish-dialog.jpg" />
    </Frame>
  </Step>

  <Step title="打开已发布的应用">
    在新的浏览器标签页中打开公开 URL，并重复执行相同的检查。分享应用前，请确保它能在 Project Editor 外正常运行。

    如果已发布的应用与 Preview 中的表现不同，请检查发布日志以及应用所需的生产环境设置。有关常见的发布问题，请参阅[排查发布问题](/zh/build/troubleshooting)。

    <Frame>
      <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="已完成的基于模板构建的网站，已在其公开的 Replit URL 中打开" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
    </Frame>
  </Step>
</Steps>

<div id="congratulations-you-shipped-your-first-app">
  ## 🎉 恭喜你——你已发布第一个 App
</div>

你从设计模板出发，获得了一个可分享的线上 URL。在此过程中，你：

* 从 Replit Design 中选择并重新组合了一个模板。
* 请 Agent 将所选设计变成功能完整的网站。
* 在 Preview 中测试了结果。
* 发布了 App，并通过其公开 URL 打开它。

这就是完整的 Replit 工作流程——选择起点、构建、测试、改进并发布。
