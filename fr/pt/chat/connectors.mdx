Agent prend en charge quatre types d’intégrations pour vous permettre de passer rapidement de l’idée à l’application :

* **Gérées par Replit** : intégrations intégrées qui fonctionnent automatiquement. Créez une application et votre Agent peut les utiliser immédiatement.
* **Connectors** : intégrations propriétaires prises en charge par Replit. Connectez-vous une seule fois. Agent peut lire et écrire directement dans ces services depuis le Chat — extraire des données, créer des enregistrements, envoyer des messages — et les utiliser dans vos applications.
* **Intégrations externes** : services tiers fiables avec lesquels vous pouvez créer. Demandez à Agent de les configurer ; vous devrez fournir les clés API.
* **Services Agent** : API tierces payantes qu’Agent utilise en arrière-plan — aucune clé API requise. L’utilisation est facturée sur vos crédits Replit.

<Note>
  **Disponibilité selon le plan** : la plupart des connecteurs nécessitent un abonnement Core, Pro ou Enterprise, et certains sont disponibles avec le plan Free. Le catalogue de connecteurs de votre workspace indique ceux que vous pouvez utiliser avec votre plan actuel. Les créateurs Replit du plan Free peuvent toujours utiliser les intégrations gérées par Replit, comme les bases de données, l’authentification et bien plus encore.
</Note>

  ## Premiers pas
</div>

Pour utiliser une intégration, mentionnez le service ou la fonctionnalité dont vous avez besoin. Par exemple :

</AiPrompt>

<div id="let-agent-suggest-a-connector">
  ### Laissez Agent vous suggérer un connecteur
</div>

Plusieurs services peuvent parfois effectuer la même tâche, comme stocker des fichiers ou envoyer des e-mails. Lorsque vous demandez une fonctionnalité sans préciser de fournisseur, Agent affiche une courte liste de connecteurs adaptés. Choisissez celui que vous souhaitez.

Sélectionnez un fournisseur, puis connectez-vous une seule fois pour associer votre compte. Agent utilise votre choix lors de la création. Vous pouvez également demander un service précis par son nom pour ne pas afficher la liste.

<div id="configuring-oauth-app-with-replit">
  ### Configurer une application OAuth avec Replit
</div>

<Note>
  **Enterprise uniquement** : la configuration d&#39;une application OAuth personnalisée nécessite un abonnement Enterprise.
</Note>

Avec le plan Enterprise, vous pouvez utiliser votre propre application OAuth pour un connecteur au lieu de celle fournie par défaut par Replit. Votre organisation peut ainsi posséder le client OAuth, afficher sa propre identité visuelle sur l&#39;écran de consentement et contrôler précisément les scopes que vos créateurs Replit peuvent demander.

Pour configurer un connecteur avec votre propre application OAuth, vous devez obtenir trois éléments auprès du fournisseur : un **Client ID**, un **Client Secret** et les **scopes** que vous souhaitez autoriser. Vous devez également enregistrer l&#39;URL de rappel de Replit auprès du fournisseur afin que l&#39;authentification puisse aboutir.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Boîte de dialogue de configuration OAuth du connecteur avec des champs pour Client ID, Client Secret et Connector Scopes, ainsi qu'une Redirect URL définie sur https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Créer une application OAuth auprès de votre fournisseur">
    Connectez-vous à la console développeur ou aux paramètres d&#39;administration du fournisseur, puis créez une application OAuth 2.0. Les fournisseurs désignent cette étape différemment : recherchez des options telles que **Create OAuth app**, **Register application** ou **Create client credentials**.
  </Step>

  <Step title="Définir l'URL de redirection">
    Lorsque le fournisseur demande un **Authorized redirect URI** (parfois appelé **Callback URL** ou **Redirect URL**), saisissez :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    Cette URL permet au fournisseur de rediriger les créateurs Replit vers Replit après qu&#39;ils ont autorisé l&#39;application. Elle doit correspondre exactement : les barres obliques finales, le protocole et le sous-domaine sont tous importants. Si vous ajoutez plusieurs URI de redirection, celle-ci doit être incluse.
  </Step>

  <Step title="Copier le Client ID et le Client Secret">
    Une fois l&#39;application créée, le fournisseur affiche un **Client ID** et un **Client Secret**.

    * **Client ID** : identifiant public de votre application OAuth. Il peut être exposé sans risque dans les URL et le code côté client.
    * **Client Secret** : valeur confidentielle qui prouve que la requête provient de votre application. Traitez-le comme un mot de passe : ne l&#39;ajoutez jamais à un dépôt et ne le partagez jamais publiquement. Replit le stocke de manière sécurisée pour vous.

    Certains fournisseurs n&#39;affichent le secret client qu&#39;une seule fois, au moment de la création. Copiez-le immédiatement et conservez-le en lieu sûr jusqu&#39;à ce que vous le colliez dans Replit.
  </Step>

  <Step title="Choisir vos scopes">
    Les **scopes** sont des autorisations qui définissent ce que votre application OAuth peut lire ou écrire au nom de l&#39;utilisateur. Chaque fournisseur publie sa propre liste de scopes dans sa documentation API.

    Lorsque vous configurez le connecteur dans Replit, les scopes que vous saisissez doivent **correspondre exactement** (caractère par caractère, y compris les préfixes d&#39;URL) aux scopes enregistrés auprès du fournisseur. Causes fréquentes d&#39;erreurs de non-correspondance :

    * Omission du préfixe d&#39;URL complet (par exemple, `https://www.googleapis.com/auth/drive.file` au lieu de `drive.file`).
    * Espaces superflus ou virgules finales.
    * Demande dans Replit d&#39;un scope qui n&#39;est pas activé dans l&#39;application du fournisseur.

    Commencez avec les scopes minimaux dont vos créateurs Replit ont besoin, puis ajoutez-en d&#39;autres si nécessaire : la plupart des fournisseurs permettent de mettre à jour les scopes sans recréer l&#39;application.
  </Step>

  <Step title="Configurer le connecteur dans Replit">
    Depuis la page **Connectors** de votre organisation, sélectionnez **Ajouter une nouvelle intégration**, choisissez le service, puis collez le **Client ID**, le **Client Secret** et les **Scopes** fournis par le fournisseur. Sélectionnez **Configurer** pour enregistrer.
  </Step>
</Steps>

<Note>
  Si l&#39;authentification échoue après la configuration, vérifiez que l&#39;URL de redirection configurée chez le fournisseur correspond exactement à `https://replit.com/connectors/oauth/callback` et que chaque scope saisi dans Replit est également autorisé dans l&#39;application du fournisseur.
</Note>

<div id="reconnecting-integrations">
  ## Reconnexion des intégrations
</div>

Si un service connecté cesse de fonctionner — par exemple, si votre session expire ou si les autorisations changent — Replit affiche une alerte de reconnexion dans le Project Editor. Sélectionnez cette alerte pour reconnecter l’intégration directement, sans quitter l’éditeur.

<div id="debugging-connectors">
  ## Dépannage des connecteurs
</div>

Vous rencontrez des difficultés pour connecter un service ? Ces guides vous présentent les erreurs courantes et expliquent comment les résoudre.

<AccordionGroup>
  <Accordion title="Google Workspace : &#x22;Cette application est bloquée&#x22;">
    Si le message **&quot;Cette application est bloquée&quot;** s’affiche lorsque vous connectez Google Drive, Docs, Sheets, Calendar ou Gmail, votre organisation Google Workspace restreint probablement les applications OAuth tierces. Consultez le guide de dépannage complet pour résoudre ce problème.

    [Résoudre le problème « Cette application est bloquée » pour les connecteurs Google](/fr/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce : &#x22;Connexion expirée&#x22;">
    Si votre connecteur Salesforce cesse de fonctionner et affiche l’erreur **&quot;Connexion expirée&quot;**, la politique relative aux jetons d’actualisation de votre organisation Salesforce est probablement configurée pour faire expirer les jetons après une période définie. Consultez le guide de dépannage complet pour mettre à jour les paramètres de votre application connectée.

    [Corriger les erreurs d’expiration de connexion Salesforce](/fr/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
