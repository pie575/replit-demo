---
title: "Mettre à jour d'anciens projets pour la prise en charge de plusieurs artefacts"
description: "Ajoutez un second artefact à un ancien projet Replit grâce à une mise à jour structurelle unique qui préserve votre URL, vos données et votre déploiement."
---

Si votre projet a été créé avant le 11 mars 2026, Agent devra peut-être effectuer une mise à jour structurelle unique avant que vous puissiez y ajouter un second artefact. Cette page explique pourquoi, ce qui change et quels projets sont éligibles.

<div id="contexto">
  ## Contexte
</div>

Le **11 mars 2026**, Replit a lancé l&#39;[Agent 4](/fr/pt/updates/2026/03/13/changelog). L&#39;un des changements majeurs de cette version est la **prise en charge de plusieurs artefacts** : un même [projet](/fr/pt/features/projects-and-artifacts/projects) peut désormais contenir plusieurs [artefacts](/fr/pt/features/projects-and-artifacts/artifacts) (par exemple une application web, une application mobile et un pitch deck) qui partagent la même base de données, le même backend, les mêmes secrets et le même déploiement.

Avant le 11 mars 2026, chaque projet s&#39;articulait autour d&#39;une seule application, avec une organisation des fichiers différente. Cette ancienne structure n&#39;offre pas la séparation dont le backend a besoin pour héberger plusieurs artefacts. En raison de ces différences, les projets créés avant le 11 mars 2026 nécessitent une **mise à jour structurelle unique** avant que l&#39;Agent puisse y ajouter un deuxième artefact. Les projets créés à cette date ou après utilisent déjà la nouvelle organisation et n&#39;ont pas besoin de cette étape.

<div id="o-que-a-atualizao-faz">
  ## Ce que fait la mise à jour
</div>

Lorsque vous demandez à Agent d&#39;ajouter un deuxième artefact à un projet plus ancien (par exemple, ajouter une application mobile à une application web existante), Agent commence par réorganiser votre projet selon la nouvelle structure multi-artefacts. Votre URL, vos collaborateurs, vos secrets, votre base de données et vos domaines sont tous conservés. Seule l&#39;organisation interne change.

<div id="como-funciona">
  ## Fonctionnement
</div>

<Steps>
  <Step title="Demandez un nouvel artefact dans un projet plus ancien">
    Demandez à Agent quelque chose comme : « Crée une présentation de diapositives pour mon site. »
  </Step>

  <Step title="Vérifiez et approuvez">
    Agent marque une pause avant d&#39;effectuer la moindre modification et affiche une proposition dans le Chat. Pour un maximum de deux projets éligibles, vous verrez également une offre unique de **5 $ de crédit** pour démarrer la mise à jour du projet. Cliquez sur **Update project** pour continuer, ou sur **Not now** pour passer.

<div id="elegibilidade">
  ## Éligibilité
</div>

Tous les projets ne peuvent pas être mis à niveau pour le moment. Votre projet doit être de l&#39;un de ces types :

* **Application web** (JavaScript full-stack)
* **Maquettes Design pour application**
* **Application mobile** (Expo)

Les autres types de projets créés avant le 11 mars 2026, y compris Python, Flask, Streamlit, les stacks de jeux, les projets vidéo et les stacks d&#39;agents, ne sont pas pris en charge. Si vous avez besoin de plusieurs artefacts dans ces cas, [créez un nouveau projet](/fr/pt/features/projects-and-artifacts/projects).

Les ports et les workflows de votre projet doivent également correspondre à la configuration par défaut de son type. Si vous avez modifié manuellement le fichier `.replit`, ce message s&#39;affichera :

> *This project cannot be migrated automatically: workflow config does not match expected.*

Pour corriger cela, rétablissez les valeurs par défaut de vos personnalisations de ports ou de workflows, puis réessayez.

<div id="perguntas-frequentes">
  ## Foire aux questions
</div>

<AccordionGroup>
  <Accordion title="Pourquoi mon projet nécessite-t-il une mise à niveau ?">
    Les projets créés avant le 11 mars 2026 (date de sortie d&#39;Agent 4) reposaient sur une structure à application unique. C&#39;est la nouvelle structure de workspace partagé qui permet à une application web, une application mobile et un tableau de bord d&#39;administration de coexister en partageant la même base de données et le même backend. La mise à niveau est une étape unique qui vous permet d&#39;adopter cette structure.
  </Accordion>

  <Accordion title="Et si je ne souhaite pas effectuer la mise à niveau ?">
    Cliquez sur **Not now**. Agent poursuit le développement dans la structure existante à artefact unique. Vous pourrez revenir à cette proposition plus tard si vos besoins évoluent.
  </Accordion>

  <Accordion title="Puis-je effectuer la mise à niveau plusieurs fois ?">
    Non. Une fois votre projet passé à la nouvelle structure, aucune mise à niveau supplémentaire n&#39;est nécessaire. Les futurs artefacts sont ajoutés directement, sans autre étape de mise à niveau.
  </Accordion>

  <Accordion title="Mon projet n'est pas éligible. Quelles sont mes options ?">
    Créez un projet distinct pour le nouvel artefact, ou démarrez un nouveau projet prenant en charge plusieurs artefacts dès le départ.
  </Accordion>
</AccordionGroup>
