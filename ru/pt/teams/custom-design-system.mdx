Дизайн-система предоставляет Agent всё необходимое для создания UI, соответствующего бренду, во всём, что ваша организация создаёт в Replit: веб-приложениях, мобильных приложениях, презентациях и других артефактах. Настройте библиотеку компонентов, дизайн-токены, брендовые ассеты и правила использования в стандартном монорепозитории pnpm Replit — и Agent будет применять ваш визуальный язык с первого prompt.

<Note>
  Дизайн-системы доступны исключительно на тарифе **Enterprise**. Только администраторы организации могут настраивать дизайн-системы и управлять ими.
</Note>

<div id="por-que-configurar-um-sistema-de-design">
  ## Зачем настраивать дизайн-систему
</div>

Без дизайн-системы каждому разработчику приходится вручную объяснять Agent библиотеку компонентов, цветовые токены и правила раскладки. Настройка дизайн-системы позволяет:

* **Зафиксировать ваши визуальные стандарты**: Agent использует именно ваши компоненты, цвета и отступы, а не общие шаблоны
* **Обеспечить единообразие**: Все приложения следуют единому языку дизайна
* **Сократить время адаптации**: Новые разработчики сразу получают результаты, соответствующие бренду
* **Сохранить неявные знания**: Решения по дизайну и шаблоны использования компонентов, известные вашей команде, документируются для Agent

<div id="o-que-voc-vai-precisar">
  ## Что вам понадобится
</div>

* Библиотека компонентов фронтенда в виде tar-файла или набора tar-файлов
* Файлы шрифтов и значки, используемые в вашей дизайн-системе
* Любая документация по ИИ для вашей дизайн-системы (MCP, Agent Skills)

<div id="o-que-voc-pode-configurar">
  ## Что можно настроить
</div>

Настройка дизайн-системы включает три части:

1. **Пользовательские инструкции**. Файл `custom_instruction/instructions.md` задаёт для Agent правила верхнего уровня, применимые к каждому проекту: какую библиотеку компонентов использовать, на какие дизайн-токены ссылаться и каким шаблонам следовать. Этот файл всегда доступен Agent в контексте.

2. **Навыки**. Навыки в `.agents/skills/` содержат подробные справочные материалы, которые Agent загружает по запросу. Используйте их для документации API компонентов, руководств по темам, библиотек шаблонов раскладки и других подробных справочных материалов, слишком объёмных для основного файла инструкций.

3. **Ассеты дизайна и бренда**. Поместите логотипы, значки, шрифты и другие брендовые ассеты в отдельную папку (например, `src/assets/brand/`). Настройте псевдоним пути в Vite, чтобы Agent и разработчики могли обращаться к ним через понятные импорты, такие как `@brand/logo.svg`, вместо ненадёжных относительных путей. Это обеспечивает единообразие ссылок на ассеты во всём проекте.

<div id="guia-passo-a-passo">
  ## Пошаговое руководство
</div>

Это руководство поможет вам настроить дизайн-систему от начала до конца, используя существующую библиотеку компонентов, упакованную в tar-файлы:

1. **Создайте новое App в Replit** и загрузите tar-файлы.
2. **Попросите Replit Agent установить пакеты и отобразить все компоненты.** Agent настроит проект и визуализирует вашу библиотеку компонентов.
3. **Проверьте результат.** Убедитесь, что все компоненты выглядят корректно и соответствуют вашим ожиданиям. Затем перейдите к разделу [Создание skill для дизайн-системы](#criando-a-skill-do-sistema-de-design).

<div id="criando-a-skill-do-sistema-de-design">
  ### Создание навыка для дизайн-системы
</div>

Когда компоненты готовы, на последнем этапе создайте навык для дизайн-системы, чтобы Agent мог обращаться к вашим компонентам, токенам и рекомендациям по использованию в каждом проекте.

Скопируйте приведённый ниже prompt целиком и вставьте его в Agent. Замените `<nome-do-seu-sistema-de-design>` на название вашей дизайн-системы:

````
Create a `<nome-do-seu-sistema-de-design>` design system skill from the components and packages in this project.

Use the file structure shown below with a `SKILL.md` at the root, a `references/` directory for guides and component docs, and a `packages/` directory containing all dependencies needed to function.

Go through every component in the project and document each one in its own file under `references/components/`, including its props, variants, and example usage.

Format `SKILL.md` as an index that links out to the guide and component reference files, with a "General Guidance" section and a "Components" section, following the example shown below.

File structure:

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (Tar files or code components)

The `SKILL.md` file acts as an index that links out to separate markdown files for guides and component references. Each linked file covers one topic in detail. Here is an example of what the generated `SKILL.md` looks like:

```markdown
---
name: your-design-system
description: Use when building or modifying any UI. Provides component API references, layout guidance, and visual style rules for your design system.
---

# Your Design System

## General Guidance

- [Setup](references/guides/setup.md) — Installation, project configuration, and provider setup
- [Guardrails](references/guides/guardrails.md) — Hard rules that must never be broken (banned patterns, required tokens, accessibility minimums)
- [Layout & Spacing](references/guides/layout-and-spacing.md) — Grid system, spacing scale, responsive breakpoints, and page templates
- ...

## Components

- [Component Index](references/components/component-index.md) — Full list of available components with status and category

Individual component references (props, variants, examples):

- [Button](references/components/button.md)
- [Checkbox](references/components/checkbox.md)
- ...
```

Guide files cover one topic each — setup and installation steps, best practices and rules, reference tables for token values, and short code examples showing correct usage.

Component files document a single component each, including the component name, a brief description, a props table, usage examples, and any guidelines or constraints. The more complete these files are, the better Agent's output will be.
````

<div id="conecte-sua-skill-ao-agent">
  ### Подключите навык к Agent
</div>

После создания навыка убедитесь, что в файле `custom_instruction/instructions.md` есть ссылка на него для Agent:

```markdown theme={null}
# Дизайн-система

Ознакомьтесь с навыком для дизайн-системы в `.agents/skills/your-design-system/` и следуйте его инструкциям.
Всегда применяйте дизайн-систему при создании или изменении UI.
```

Наконец, добавьте в `replit.md` контекст, специфичный для вашей дизайн-системы, чтобы Agent с самого начала понимал ваши визуальные стандарты. Укажите общее описание проекта, предпочитаемую библиотеку компонентов, ключевые предпочтения в дизайне (шкалу отступов, требования к доступности) и архитектурный стек.

<div id="valide-sua-configurao">
  ### Проверьте конфигурацию
</div>

Перед запуском дизайн-системы убедитесь, что выполнены следующие условия:

* `custom_instruction/instructions.md` направляет Agent к навыку дизайн-системы
* `.agents/skills/` содержит навык со справочными материалами по компонентам, руководствами и пакетами
* `replit.md` предварительно заполнен обзором проекта, настройками и описанием архитектуры
* Файл дизайн-токенов добавлен (`tokens.css` или аналогичный)
* Пакет дизайн-системы предварительно установлен в `package.json`
* Создайте новое тестовое приложение и убедитесь, что Agent правильно использует дизайн-систему

<div id="fixe-o-sistema-de-design-na-sua-organizao">
  ### Закрепите дизайн-систему в своей организации
</div>

Когда дизайн-система будет готова, закрепите её, чтобы все участники организации могли ею пользоваться:

1. Перейдите в App дизайн-системы в своей организации
2. Откройте меню действий App (меню с тремя точками)
3. Выберите **Закрепить во входящих Agent**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий App с пунктом «Закрепить во входящих Agent»" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Только администраторы организации (участники роли `system_admins`) могут закреплять и откреплять дизайн-системы.
</Note>

Установите для участников доступ **Только для чтения**, чтобы они могли просматривать и использовать закреплённую дизайн-систему, не имея возможности её редактировать.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалог приглашения с доступом «Только для чтения» для участников" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Теперь дизайн-система отображается в виде выбираемой плашки под входящими Agent у всех участников вашей организации. Чтобы удалить её, откройте то же меню и выберите **Открепить из входящих Agent**.

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Дизайн-система в виде выбираемой плашки во входящих Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

<div id="mantenha-seu-sistema-de-design-atualizado">
  ## Поддерживайте дизайн-систему в актуальном состоянии
</div>

Дизайн-системы развиваются. Поддерживайте свою в актуальном состоянии:

* **Обновляйте файлы токенов**, когда в дизайн-системе появляются новые значения цветов, отступов или типографики
* **Обновляйте навыки**, когда у компонентов появляются новые props, варианты или паттерны использования
* **Обновляйте инструкции**, когда меняются принципы или паттерны дизайна
* **Обновляйте версии пакетов**, когда выходят новые версии вашей дизайн-системы
* **Регулярно тестируйте**, создавая новое App и проверяя, что Agent выдаёт правильный результат

<div id="sistemas-de-design-vs-templates-personalizados">
  ## Дизайн-системы и пользовательские шаблоны
</div>

Дизайн-системы и [пользовательские шаблоны](/ru/pt/teams/custom-templates) служат разным целям:

|                   | Дизайн-системы                                                                                | Пользовательские шаблоны                                                                |
| ----------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **Назначение**    | Заменить фронтенд-стек на стек вашей команды и использовать её программные компоненты          | Полностью заменить стандартный стек (например, Rust, Go, C++)                           |
| **Стек**          | Работает в стандартном монорепозитории Replit на pnpm                                          | Определяет полностью настраиваемую структуру проекта                                    |
| **Что включает**  | Правила библиотеки компонентов, токены дизайна, брендовые ассеты, визуальные навыки            | Полная заготовка: среда выполнения, конфигурация сборки, зависимости, структура проекта |
| **Применяется к** | Веб-приложениям, мобильным приложениям, презентациям, артефактам — ко всему, что создаёт Agent | Только приложениям, созданным на основе этого конкретного шаблона                       |

Используйте дизайн-систему, если хотите, чтобы Agent следовал вашим визуальным стандартам в обычном процессе работы с Replit. Используйте пользовательский шаблон, если вам нужен принципиально иной стек.
