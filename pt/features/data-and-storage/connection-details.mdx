Seu app se conecta ao banco de dados por meio de credenciais que o Replit gerencia para você. Encontre-as na ferramenta **Database**: selecione um banco de dados e depois abra a aba **Settings**. Ela mostra a string de conexão, o uso de armazenamento e os detalhes avançados de conexão.

## Variáveis de ambiente

A seguinte variável de ambiente está disponível para conectar-se ao seu banco de dados de desenvolvimento:

* `DATABASE_URL`: como conectar e autenticar no banco de dados

Seu app a usa automaticamente. Como `DATABASE_URL` é restrito ao seu app, seu banco de dados de desenvolvimento não pode ser acessado por outros apps, mesmo os que você possui, ou por visualizadores externos de banco de dados. Mesmo se exposto, ele não pode ser usado por mais ninguém para acessar e modificar seu banco de dados.

<Info>
  Se o seu banco de dados de desenvolvimento ainda estiver na [infraestrutura legada do Neon](/pt/features/data-and-storage/development-and-production#banco-de-dados-de-desenvolvimento-legado), as variáveis adicionais `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` e `PGPORT` também estão disponíveis. Essas **não** são fornecidas para bancos de dados hospedados na infraestrutura atual do Replit; use `DATABASE_URL` em vez disso.
</Info>

<Warning>
  Se você ainda estiver no banco de dados de desenvolvimento legado do Neon, não compartilhe seu `DATABASE_URL`. Ele contém as credenciais do seu banco de dados, que poderiam ser usadas por qualquer pessoa para acessar e modificar seu banco de dados. Nunca cole-o em locais públicos ou em tickets de suporte.
</Warning>

## Conectar uma ferramenta externa

Você pode se conectar ao seu banco de dados de **produção** a partir de qualquer cliente SQL compatível com PostgreSQL, usando a string de conexão da aba **Settings** do banco de dados de produção.

## Segurança

Quando você adiciona uma integração de banco de dados usando o Agent, ele adiciona um mapeador objeto-relacional (ORM) que gerencia todas as comunicações com o banco de dados com segurança integrada:

* **Validação de esquema**: verifica se os dados estão em conformidade com os formatos esperados
* **Sanitização de dados**: limpa automaticamente a entrada do criador para evitar ataques de injeção SQL

## Regenerar as credenciais do banco de dados de produção

Se uma string de conexão de produção foi exposta, regenere suas credenciais na ferramenta Database. Essa ação cria uma nova senha para o banco de dados de produção do Neon. As strings de conexão de produção existentes deixam de funcionar imediatamente.

Você pode regenerar as credenciais quando todas estas condições forem verdadeiras:

* Seu app tem um banco de dados de produção do Neon.
* Você é o proprietário do app ou administrador do workspace proprietário.
* Você está usando o Replit em um navegador web.
* Nenhuma implantação está em andamento.
* Se o seu app tiver uma implantação ativa, seu último build foi concluído com sucesso e usa [Autoscale ou uma VM Reservada](/pt/features/publishing/deployment-types).

<Warning>
  Essa ação não pode ser desfeita. As strings de conexão existentes deixam de
  funcionar imediatamente. Se o seu app tiver uma implantação ativa, ele pode
  ficar indisponível brevemente durante a reimplantação.
</Warning>

### Regenere as credenciais

1. No painel Tools, selecione **Database**.

2. Selecione **Production Database** e depois a aba **Settings**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="A aba Settings do banco de dados de produção mostrando a string de conexão, o uso de armazenamento e a seção Advanced com a linha Regenerate credentials." width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. Em **Advanced**, expanda a linha **Regenerate credentials**.

4. Selecione o botão **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="A linha Regenerate credentials expandida na seção Advanced, mostrando o botão Regenerate credentials." width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. Na caixa de diálogo de confirmação, selecione **Regenerate credentials** para confirmar.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="A caixa de diálogo de confirmação Regenerate credentials avisando que a ação não pode ser desfeita e que as strings de conexão existentes deixam de funcionar imediatamente." width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Selecione **Refresh** para carregar a nova string de conexão.

7. Se o seu app tiver uma implantação ativa, abra **Publishing** e acompanhe a reimplantação.

8. Substitua qualquer string de conexão que você tenha copiado para ferramentas externas ou integrações personalizadas.

### O que muda

Regenerar as credenciais cria uma nova senha para o banco de dados de produção. Apenas a parte da senha na string de conexão é alterada. O host, o nome do banco de dados e a role permanecem os mesmos.

Para uma implantação ativa suportada, o Replit reimplanta o último build bem-sucedido com a string de conexão atualizada.
