Project Security Center — единое место для поиска и устранения уязвимостей безопасности и конфиденциальности в Replit App. На панели **Инструменты** проекта выберите **Security Center**, чтобы запускать сканирования, просматривать результаты и отправлять принятые результаты в Agent для исправления.

<Note>
  Впервые работаете с безопасностью зависимостей? См. [основные понятия
  безопасности](/ru/features/security/concepts): определения CVE, SBOM, exposure,
  Fix with Agent, Republish и Auto-Protect.
</Note>

<div id="automatic-dependency-scans">
  ## Автоматическое сканирование зависимостей
</div>

Автоматическое сканирование зависимостей проверяет пакеты проекта по общедоступным сведениям об уязвимостях. Эти проверки бесплатны и запускаются автоматически. При публикации новой записи Common Vulnerabilities and Exposures (CVE) Replit сверяет её с зависимостями вашего проекта и показывает совпадения на панели **Security** без необходимости запускать повторное сканирование вручную.

Сканирование зависимостей поддерживает Node.js/npm, Python, Go, Rust, PHP и Ruby.

Автоматическое исправление зависимостей сейчас доступно только для Node.js/npm.

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect расширяет возможности автоматического сканирования зависимостей. Когда Replit обнаруживает соответствующую уязвимость, Agent подготавливает и тестирует исправление, а затем отправляет вам электронное письмо с прямой ссылкой. Исправление ожидает проверки на панели **Security**. После применения исправления повторно опубликуйте приложение, чтобы оно вошло в рабочую версию.

Auto-Protect распространяется только на CVE в зависимостях. Используйте [сканирование безопасности Agent](/ru/features/security/agent-security-scans), чтобы проверить код приложения.

Оба параметра Auto-Protect по умолчанию отключены:

<Steps>
  <Step title="Включить подготовку исправлений">
    Администратор Workspace переходит в **Settings** &gt; **Account** &gt; **Advanced**, затем
    выбирает минимальный уровень серьёзности (низкий, средний, высокий или
    критический), при котором Replit должен подготавливать исправления.
  </Step>

  <Step title="Включить уведомления по электронной почте">
    Перейдите в **Settings** &gt; **Personalization** &gt; **Email Notifications**, затем
    выберите минимальный уровень серьёзности, при котором хотите получать уведомления.
  </Step>
</Steps>

Для каждой новой уязвимости Replit отправляет не более одного электронного письма на Workspace с краткой информацией обо всех затронутых проектах. Нажмите **Go to Task**, чтобы проверить исправление, подготовленное Agent, перед его применением. После применения исправления уязвимость отображается как **pending republish**, пока вы не опубликуете новую версию.

<Note>
  Исправления, подготовленные Agent, оплачиваются так же, как и другая работа Agent, в том числе если
  Auto-Protect подготавливает их заранее.
</Note>

<div id="review-findings">
  ## Проверка результатов
</div>

Результаты проверки безопасности отображаются на панели **Security** и группируются по уровню серьёзности:

| Серьёзность             | Рекомендации                                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| Критическая             | Неотложные риски, которые необходимо устранить перед публикацией                               |
| Высокая                 | Серьёзные проблемы, которые при определённых условиях могут быть использованы злоумышленниками |
| Средняя                 | Потенциальные риски с меньшей вероятностью эксплуатации                                        |
| Низкая / Информационная | Незначительные проблемы и рекомендации по передовым практикам                                  |

Проверьте каждый результат, прежде чем принять, исправить или отклонить его. Передайте принятые проблемы Agent для устранения, затем после внесения исправлений повторно запустите соответствующую проверку.

<div id="security-checks-during-development-and-publishing">
  ## Проверки безопасности при разработке и публикации
</div>

<div id="security-scan-while-you-build">
  ### Сканирование безопасности в процессе разработки
</div>

При разработке с Agent Replit автоматически проверяет изменённые Agent файлы на распространённые небезопасные паттерны и жёстко заданные секреты. Это ранняя быстрая проверка в рабочем процессе Agent, а не комплексная проверка всей кодовой базы. Её результаты не отображаются отдельным отчётом на панели **Security**.

<div id="publish-checks">
  ### Проверки перед публикацией
</div>

Replit также выполняет сканирование безопасности перед публикацией. Настройка **Блокировать публикацию при критических уязвимостях** определяет, что произойдёт, если сканирование обнаружит критическую проблему:

* **Вкл.**: Публикация блокируется, пока проблема не будет устранена или отклонена.
* **Выкл.**: Публикация продолжается, а обнаруженный результат остаётся доступным для проверки.

Организации Enterprise могут сделать эту настройку обязательной для каждого App.

Эти проверки дополняют, но не заменяют полное [сканирование безопасности Agent](/ru/features/security/agent-security-scans) или [сканирование Level 3](/ru/features/security/black-box-pen-tests).
