---
title: "Surveillance des apps publiées"
description: "Suivez en temps réel l’état, les performances, l’utilisation des ressources et la disponibilité de votre app publiée."
---

La surveillance des apps publiées vous permet de suivre les métriques de performances, de modifier les paramètres et de vous assurer que vos apps publiées fonctionnent de manière optimale.

<div id="recursos">
  ## Fonctionnalités
</div>

* **Suivi en temps réel** : consultez le statut, les analyses et les détails de configuration de l&#39;app publiée
* **Analyse des performances** : surveillez les pages vues, les temps de réponse et les métriques d&#39;engagement des utilisateurs
* **Surveillance des apps** : vérifiez que votre app publiée est bien en ligne, grâce à une barre colorée qui indique d&#39;un coup d&#39;œil l&#39;uptime récent
* **Gestion de la configuration** : mettez à jour les commandes, les Secrets et les options de l&#39;app publiée en quelques clics

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder aux outils de surveillance dans l’onglet Publishing.

<Accordion title="Accéder à Publishing">
  Dans le **dock d’outils** situé à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône All tools" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez Publishing <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez **Overview** en haut.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut pour ouvrir l’outil de recherche.
  2. Saisissez « Publishing » pour trouver l’outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez **Overview** en haut.
</Accordion>

<div id="aba-overview">
  ### Onglet Overview
</div>

L&#39;onglet **Overview** vous permet de suivre l&#39;état et la configuration de votre application publiée. Il fournit les détails suivants :

* **Status** : état de l&#39;application publiée sur Replit, avec des informations sur les différentes étapes du processus.
* **Domain** : URL à laquelle vous pouvez accéder à votre Replit App
* **Deployment Type** : Autoscale, Reserved VM, Static ou Scheduled

<Frame caption="Onglet Overview de l'application publiée">
  <img src="/assets/mirror/overview-tab-d2623c2e674a.png" alt="Onglet Overview de l'application publiée" width="1828" height="604" data-path="images/deployments/overview-tab.png" />
</Frame>

Vous pouvez effectuer les actions suivantes dans l&#39;onglet **Overview** :

* **Republish** : remplacez l&#39;application actuellement publiée par un nouveau snapshot et de nouvelles options de publication. Vous pouvez suivre l&#39;état de l&#39;application publiée depuis cet onglet.
* **Edit Commands and Secrets** : modifiez le répertoire public, la commande de build et les secrets de l&#39;application publiée.
* **View publish logs** : consultez les logs de votre application publiée.
* **View published app** : ouvrez votre application publiée dans un nouvel onglet du navigateur.
* **QR code** : générez un QR code à scanner avec votre appareil mobile pour accéder à l&#39;application publiée.
* **Manage** : consultez ou modifiez les paramètres de l&#39;application publiée.
* **See all usage** : accédez à la page de facturation Usage.

<div id="aba-logs">
  ### Onglet Logs
</div>

L&#39;onglet **Logs** fournit les logs en temps réel de votre app publiée. Replit conserve les logs pendant 7 jours.

Vous pouvez filtrer les logs selon les catégories suivantes :

* **Errors only** : affichez uniquement les logs d&#39;erreurs
* **Search** : saisissez une expression à rechercher dans les logs
* **Date** : sélectionnez une plage de dates

L&#39;onglet **Resources** offre une vue détaillée de la consommation de ressources de votre app publié. Il regroupe les informations suivantes :

* **CPU Utilization** : pourcentage d&#39;utilisation du processeur au fil du temps
* **Memory Utilization** : pourcentage d&#39;utilisation de la mémoire au fil du temps

<div id="aba-analytics">
  ### Onglet Analytics
</div>

<Note>
  Analytics est disponible pour les déploiements Autoscale, Static et Reserved VM.
</Note>

L&#39;onglet **Analytics** affiche des statistiques sur les visites des pages web de votre app publiée.
Vous pouvez personnaliser la période à l&#39;aide du sélecteur de dates situé en haut.
Les métriques disponibles sont les suivantes :

* **Page Views** : nombre de requêtes HTTP reçues par votre Replit App chaque heure
* **Top URLs** : chemins d&#39;URL les plus visités
* **Top Referrers** : sources de trafic qui amènent les utilisateurs vers votre site
* **HTTP Statuses** : codes de réponse HTTP servis par votre Replit App
* **Request Durations** : temps de chargement côté serveur
* **Top Browsers** : navigateurs utilisés par vos visiteurs
* **Top Devices** : systèmes d&#39;exploitation et appareils utilisés pour accéder à votre Replit App
* **Top Countries** : répartition géographique de vos utilisateurs

<div id="monitoramento-de-apps">
  ### Monitoring des apps
</div>

<Note>
  Le Monitoring des apps est disponible avec les forfaits Replit Core, Pro, Teams et Enterprise. Il fonctionne avec tous les types de Deployment, à l’exception des Scheduled Deployments. Le bouton bascule **Enable app monitoring** apparaît dans la boîte de dialogue de publication lorsque votre app est éligible.
</Note>

Le Monitoring des apps indique si votre app publiée est en ligne. Replit vérifie régulièrement votre app et enregistre chaque résultat. Les résultats apparaissent à deux endroits : dans la vue **Publishing**, pour une vérification rapide de l’état de l’app, et dans l’onglet **Analytics**, pour un historique plus détaillé.

<div id="ativar-monitoramento-de-apps">
  #### Activer le monitoring des apps
</div>

Vous pouvez activer le monitoring des apps d’un projet existant dans la boîte de dialogue de publication de l’outil **Publishing**.

<Steps>
  <Step title="Ouvrir la boîte de dialogue de publication">
    Ouvrez l’outil **Publishing**, puis lancez une nouvelle publication ou republiez votre app.
  </Step>

  <Step title="Activer le bouton bascule">
    Dans **Monitoring tools**, activez **Enable app monitoring**, puis publiez votre app.
  </Step>

  <Step title="Consulter votre uptime">
    Après la publication, votre uptime s’affiche dans la vue **Publishing** et dans l’onglet **Analytics** au bout de quelques minutes.
  </Step>
</Steps>

<div id="ler-a-barra-de-uptime">
  #### Lire la barre d’uptime
</div>

Après la publication de votre app, la vue **Publishing** affiche une barre d’uptime compacte avec l’état, la visibilité, la géographie et le type de déploiement de votre app publiée. Utilisez-la pour vérifier si votre app est actuellement hors ligne ou si elle a récemment rencontré des problèmes — par exemple, pendant la nuit, alors que vous dormiez.

<Frame caption="Uptime récent dans la vue Publishing, avec le bouton Investigate recent downtime with Agent">
  <img src="/assets/mirror/app-monitoring-overview-ffdfc2d48fc2.png" alt="Vue Publishing d’un déploiement de production affichant 95,0 % d’uptime, une barre d’uptime colorée allant d’il y a un jour à maintenant, et le bouton Investigate recent downtime with Agent" width="863" height="295" data-path="images/deployments/app-monitoring-overview.png" />
</Frame>

Pour consulter un historique plus long, ouvrez l’onglet **Analytics**. L’onglet Analytics inclut un sélecteur de période, qui vous permet de remonter plus loin dans le temps et de corréler les périodes d’indisponibilité avec d’autres signaux — comme le volume de requêtes ou les pics de trafic — afin de déterminer si le trafic utilisateur provoque des problèmes avec la capacité provisionnée de votre app.

<Frame caption="Graphique Uptime Monitoring dans l’onglet Analytics avec le sélecteur de période Past one day">
  <img src="/assets/mirror/app-monitoring-analytics-07a11e4c2039.png" alt="Vue Uptime Monitoring dans l’onglet Analytics avec le sélecteur de période Past one day et une large barre d’uptime affichant 29,0 % d’uptime" width="991" height="205" data-path="images/deployments/app-monitoring-analytics.png" />
</Frame>

La barre d’uptime couvre jusqu’aux 15 dernières heures d’activité. Elle contient 90 segments, chacun couvrant 10 minutes.

Les couleurs des segments indiquent l’état de connexion de votre app :

* **Vert** signifie que l’app est en ligne.
* **Jaune** signifie que des erreurs intermittentes se produisent lors de la connexion à l’app.
* **Rouge** signifie que l’app est hors ligne.
* **Gris** signifie qu’aucune donnée n’est encore disponible pour ce créneau horaire.

Survolez un segment pour voir la plage horaire exacte.

<div id="investigar-indisponibilidade-com-o-agent">
  #### Enquêter sur une indisponibilité avec Agent
</div>

Pour approfondir l&#39;enquête, sélectionnez **Investigate recent downtime with Agent** sous la barre d&#39;uptime. Agent lance une nouvelle tâche en arrière-plan, collecte les plages horaires concernées et cherche à identifier la cause racine, par exemple en examinant les logs, le code et l&#39;état de la base de données, puis en proposant une correction.

<div id="causas-comuns-de-indisponibilidade">
  #### Causes courantes d&#39;indisponibilité
</div>

L&#39;indisponibilité d&#39;une application s&#39;explique généralement par l&#39;un des problèmes suivants :

* **L&#39;app a planté.** Ouvrez l&#39;onglet **Logs** et recherchez les erreurs survenues au moment où le segment est passé au rouge.
* **L&#39;app a manqué de CPU ou de mémoire.** Ouvrez l&#39;onglet **Resources** pour repérer d&#39;éventuels pics. Si l&#39;utilisation était élevée, choisissez une taille de machine supérieure dans l&#39;onglet **Manage**.
* **Une publication récente est à l&#39;origine du problème.** Comparez l&#39;horodatage des segments rouges avec l&#39;historique des publications et, si nécessaire, republiez une version fonctionnelle.
* **Les requêtes étaient trop lentes.** Des temps de réponse trop longs peuvent faire échouer les vérifications. Consultez **Request Durations** dans l&#39;onglet **Analytics**.
* **Une configuration est incorrecte.** Des Secrets expirés, des variables d&#39;environnement erronées ou une base de données inaccessible peuvent mettre votre app hors service. Vérifiez la configuration dans **Edit Commands and Secrets**, sous l&#39;onglet **Overview**.

Pour obtenir plus d&#39;aide, consultez [Résolution des problèmes de déploiement](/fr/pt/cloud-services/deployments/troubleshooting).

<div id="aba-schedule">
  ### Onglet Schedule
</div>

<Note>Les planifications sont disponibles uniquement pour les Scheduled Deployments.</Note>

L&#39;onglet **Schedule** permet de consulter l&#39;historique des exécutions de l&#39;app publiée et affiche les informations suivantes :

* Temps écoulé depuis la dernière exécution
* Date et heure de démarrage de l&#39;exécution
* Durée de l&#39;exécution
* Statut de l&#39;exécution

Vous pouvez effectuer les actions suivantes dans l&#39;onglet **Schedule** :

* **View logs** : sélectionnez l&#39;icône <img class="icon-svg" src="/assets/mirror/menu-a72ad731aff8.svg" alt="icône menu" width="16" height="16" data-path="images/icons/menu.svg" /> d&#39;affichage des logs en regard de l&#39;entrée pour consulter les messages de log.
* **Cancel run** : sélectionnez l&#39;icône <img class="icon-svg" src="/assets/mirror/cancel-2145d3814f60.svg" alt="icône annuler" width="16" height="16" data-path="images/icons/cancel.svg" /> d&#39;annulation en regard de l&#39;entrée pour interrompre une exécution en cours.
* **Start a run** : sélectionnez **Run Now** pour lancer manuellement une exécution sans modifier la planification.
* **Refresh** : utilisez l&#39;icône <img class="icon-svg" src="/assets/mirror/refresh-52703b8cfe91.svg" alt="icône actualiser" width="16" height="16" data-path="images/icons/refresh.svg" /> d&#39;actualisation pour mettre à jour l&#39;historique des exécutions.

<div id="aba-domains">
  ### Onglet Domains
</div>

<Note>
  L’onglet **Domains** est disponible pour les déploiements Autoscale, Reserved VM et Static
  Deployments. Les Scheduled Deployments ne disposent pas de l’onglet Domains.
</Note>

L’onglet **Domains** vous permet de connecter et de gérer des domaines personnalisés pour votre app publiée. Dans cet onglet, vous pouvez :

* **Link a domain** : connecter un domaine personnalisé dont vous êtes déjà propriétaire.
* **Purchase a domain** : acheter un nouveau domaine directement via Replit.
* **View domain status** : consulter l’état de vérification de chaque domaine connecté.

Pour obtenir des instructions de configuration étape par étape, consultez [Custom Domains](/fr/pt/cloud-services/deployments/custom-domains).

<div id="aba-manage">
  ### Onglet Manage
</div>

L&#39;onglet **Manage** regroupe les paramètres suivants pour votre app publiée :

* **Resource usage** : consultez le CPU, la RAM et le coût d&#39;utilisation de la machine pour votre app publiée.
* **Pause** : suspendez temporairement votre app publiée. L&#39;app devient alors inaccessible, mais la facturation se poursuit.
* **Change deployment type** : passez d&#39;un type de déploiement à un autre. Par exemple, si vous aviez d&#39;abord opté pour un déploiement statique, vous pouvez le remplacer par Reserved VM Deployments.
* **Shut Down** : supprimez votre app publiée et mettez fin à son cycle de facturation. Sélectionnez **Shut down** pour arrêter définitivement votre app publiée actuelle.
