# Mise à jour des anciens projets pour la prise en charge de plusieurs artefacts

> Ajoutez un deuxième artefact à un ancien projet Replit grâce à une mise à jour structurelle unique qui préserve votre URL, vos données et votre déploiement.

Si votre projet a été créé avant le 11 mars 2026, Agent devra peut-être effectuer une mise à jour structurelle unique avant de pouvoir y ajouter un deuxième artefact. Cette page explique pourquoi, ce qui change et quels projets sont éligibles.

## Contexte

Le **11 mars 2026**, nous avons publié [Replit Agent 4](/fr/updates/2026/03/13/changelog). L'un des changements les plus importants de cette version était la **prise en charge de plusieurs artefacts** : un seul [projet](/fr/replitai/projects) peut désormais contenir plusieurs [artefacts](/fr/replitai/artifacts) — par exemple, une application web, une application mobile et une présentation — qui partagent la même base de données, le même backend, les mêmes secrets et le même déploiement.

Avant le 11 mars 2026, chaque projet était construit autour d'une seule application avec une structure de fichiers plus simple. Cette ancienne structure ne dispose pas de la séparation dont le backend a besoin pour héberger plus d'un artefact. En raison de ces différences, les projets créés avant le 11 mars 2026 nécessitent une **mise à jour structurelle unique** avant qu'Agent puisse y ajouter un deuxième artefact. Les projets créés à partir de cette date utilisent déjà la nouvelle disposition et n'ont pas besoin de cette étape.

## Ce que la mise à jour fait

Lorsque vous demandez à Agent d'ajouter un deuxième artefact à un ancien projet — par exemple, ajouter une application mobile à une application web existante — Agent réorganise d'abord votre projet dans la nouvelle disposition multi-artefacts. Votre URL, vos collaborateurs, vos secrets, votre base de données et vos domaines sont tous préservés. Seule la structure interne des fichiers change.

## Comment ça fonctionne

  <Step title="Examiner et approuver">

## Éligibilité

Tous les projets ne peuvent pas être mis à jour pour le moment. Votre projet doit être de l'un de ces types :

* **Application web** — JavaScript fullstack
* **Maquette** — maquettes de design vers application
* **Application mobile** — Expo

Les autres types de projets créés avant le 11 mars 2026 — notamment Python, Flask, Streamlit, les projets de jeux, les projets vidéo et les piles d'agents — ne sont pas pris en charge. Si vous avez besoin de plusieurs artefacts dans ces cas, [créez un nouveau projet](/fr/replitai/projects) à la place.

Les ports et les workflows de votre projet doivent également correspondre à la configuration par défaut pour son type. Si vous avez modifié manuellement `.replit`, vous verrez ce message :

> *Ce projet ne peut pas être migré automatiquement : la configuration du workflow ne correspond pas à celle attendue.*

Pour y remédier, rétablissez vos personnalisations de port ou de workflow aux valeurs par défaut et réessayez.

## Foire aux questions

<AccordionGroup>
  <Accordion title="Pourquoi mon projet a-t-il besoin d'une mise à jour ?">
    Les projets créés avant le 11 mars 2026 — date du lancement d'Agent 4 — utilisaient une disposition plus simple à application unique. La nouvelle disposition d'espace de travail partagé est ce qui permet à une application web, une application mobile et un tableau de bord d'administration de coexister et de partager la même base de données et le même backend. La mise à jour est une étape unique pour adopter cette disposition.
  </Accordion>

  <Accordion title="Que faire si je ne veux pas mettre à jour ?">
    Cliquez sur **Pas maintenant**. Agent continue de construire dans la disposition existante à artefact unique. Vous pouvez revenir à l'offre ultérieurement si vos besoins changent.
  </Accordion>

  <Accordion title="Puis-je effectuer la mise à jour plusieurs fois ?">
    Non. Une fois que votre projet est dans la nouvelle structure, aucune autre mise à jour n'est nécessaire. Les futurs artefacts sont ajoutés directement sans autre étape de mise à jour.
  </Accordion>

  <Accordion title="Mon projet n'est pas éligible. Quelles sont mes options ?">
    Créez un projet séparé pour le nouvel artefact, ou démarrez un nouveau projet qui prend en charge plusieurs artefacts dès le départ.
  </Accordion>
</AccordionGroup>
