上下文是 AI 模型用来生成下一条回复的信息。上下文管理就是在恰当的时机向模型提供恰当信息的做法。

这一点之所以重要，是因为 AI 并不会仅凭你的意图来工作，而是依据上下文窗口中可用的文本、文件、截图、日志、示例和对话记录来工作。

<div id="section">
  ## 什么是上下文窗口？
</div>

AI 模型一次能够处理的信息量是有限的，这个上限就称为上下文窗口。

上下文窗口中可能包含：

* 你的提示词
* 对话中的历史消息
* 模型可以查看的文件或代码
* 错误消息和日志
* 截图、图片或设计参考
* 诸如 `replit.md` 之类的项目说明
* 前序步骤的工具运行结果

模型会依据这些上下文来决定接下来生成什么内容。

<div id="section-2">
  ## 上下文窗口为何重要
</div>

如果重要细节不在上下文中，模型就可能靠猜测来填补。而无关信息过多时，模型又可能把注意力放错地方。

例如，下面这个提示词几乎没有提供任何上下文：

```text theme={null}
Improve the signup page.
```

该提示词提供了有用的上下文：

```text theme={null}
Improve the signup page for first-time founders who are deciding whether to join the waitlist.
Keep the current fields. Make the value proposition clearer above the form.
Do not change the pricing section.
```

第二个提示词则说明了页面面向哪些用户、需要改进什么、需要保留什么，以及哪些内容不在范围之内。

<div id="section-3">
  ## 上下文窗口大小各不相同
</div>

不同的 AI 模型能处理的上下文量各不相同。更大的上下文窗口可以一次性纳入更多文本，但并非越大越好。相比把所有细节一股脑塞进对话，上下文是否相关仍然更为重要。

已公开的上下文窗口大小示例：

| 模型系列              | 示例上下文窗口    |
| ----------------- | ---------- |
| GPT-4.1           | 最高 100 万词元 |
| Claude Sonnet 4.5 | 最高 20 万词元  |
| Gemini 2.5 Pro    | 最高 100 万词元 |

这些数字会随时间变化，且并非所有产品都会开放模型的全部上限。但有一条实用经验始终不变：让重要信息保持清晰、聚焦。

<div id="section-4">
  ## 上下文类型
</div>

| 上下文类型    | 示例                   |
| -------- | -------------------- |
| **目标**   | “此着陆页需要收集候补名单注册信息。”  |
| **受众**   | “面向忙碌的餐厅老板。”         |
| **约束条件** | “请保留当前的配色方案和表单字段。”   |
| **非目标**  | “暂时不要添加支付功能。”        |
| **示例**   | 截图、模型图、示例数据或竞争对手的页面。 |
| **项目状态** | 当前文件、组件、错误消息或用户流程。   |
| **完成定义** | “访客可以提交表单并看到感谢信息。”   |

<div id="section-5">
  ## 即时上下文与持久上下文
</div>

有些上下文只属于当前对话。当你请求某项具体改动、调试某个问题，或对最近的结果给出反馈时，就使用这类上下文。

另一些上下文则需要在整个项目中长期保持。对于编码风格、品牌规范、命名约定、可复用的产品规则，以及 Agent 需要跨工作会话记住的约束条件，请使用持久上下文。在 Replit 中，[replit.md](/zh/ko/features/project-setup/replit-dot-md) 就是为 Agent 提供持久项目上下文的一种方式。

<div id="section-6">
  ## 当上下文变得混乱时
</div>

长时间的对话可能会偏离方向。如果线程中混入了过多不相关的决策，Agent 可能会继续关注已经不再重要的旧上下文。

请在以下情况下新建线程：

* 切换到不相关的功能时
* 对话中存在许多已放弃的思路时
* Agent 持续沿用旧的约束时
* 希望为新领域制定清晰计划时

重新开始时，请总结重要的上下文，而不要假定 Agent 仍然知道哪些内容重要。

```text theme={null}
背景：这个项目是为本地健身教练打造的候补名单应用。
主要流程：落地页 → 注册表单 → 确认消息。
在这个线程中，仅优化确认消息和后续文案。
```

<div id="section-7">
  ## 常见误解
</div>

* **“上下文越多越好。”** 相关的上下文才更有用。无关内容过多反而会分散模型的注意力。
* **“模型能完美记住一切。”** AI 会利用可用的上下文，但遇到关键约束时，你仍需再次重申。
* **“上下文只有文本。”** 截图、文件、数据、设计稿、日志、示例都可以作为上下文。
