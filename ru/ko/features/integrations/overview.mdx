Agent поддерживает четыре типа интеграций, чтобы вы могли быстрее воплощать идеи в приложения.

* **Управляемые Replit**: встроенные интеграции, которые работают автоматически. Agent может использовать их сразу после создания приложения.
* **Коннекторы (Connectors)**: собственные интеграции Replit. Достаточно войти в аккаунт один раз. Agent может прямо в чате читать и записывать данные в этих сервисах — получать данные, создавать записи и отправлять сообщения — и использовать их при разработке нескольких приложений.
* **Внешние интеграции (External integrations)**: надёжные сторонние сервисы, с которыми можно разрабатывать приложения. Попросите Agent настроить их, а затем предоставьте API-ключ.
* **Сервисы Agent (Agent services)**: платные сторонние API, которые Agent использует в фоновом режиме — API-ключ не требуется. Использование оплачивается кредитами Replit.

<Note>
  **Доступность по тарифам**: для большинства коннекторов требуется подписка Core, Pro или Enterprise, а некоторые также доступны на тарифе Free. В каталоге коннекторов рабочего пространства можно узнать, какие коннекторы доступны на вашем текущем тарифе. Разработчики на тарифе Free могут в любое время использовать управляемые Replit интеграции, например базы данных и аутентификацию.
</Note>

<div id="section">
  ## Начало работы
</div>

Чтобы использовать интеграции, укажите нужные сервисы или возможности. Например:

<AiPrompt>
  Создай веб-приложение, которое принимает платежи через Stripe и отправляет письма с подтверждением через SendGrid
</AiPrompt>

Agent автоматически распознает эти ключевые слова и добавит необходимый код и настройки.

<div id="agent">
  ### Разрешите Agent предлагать коннекторы
</div>

Иногда одну и ту же задачу, например сохранение файлов или отправку электронной почты, можно выполнить с помощью разных сервисов. Если запросить функцию без указания поставщика, Agent покажет краткий список подходящих коннекторов. Выберите нужный.

Выберите поставщика, затем однократно войдите в систему, чтобы подключить учётную запись. Agent будет использовать выбранный сервис в процессе сборки. Чтобы пропустить список, можно сразу запросить конкретный сервис по имени.

</Note>

<div id="replit-oauth">
  ### Настройка OAuth-приложения в Replit
</div>

<Note>
  **Только для Enterprise**: для настройки пользовательских OAuth-приложений требуется подписка Enterprise.
</Note>

Тариф Enterprise позволяет использовать для коннекторов собственные OAuth-приложения вместо стандартных приложений Replit. Это даёт организации возможность владеть OAuth-клиентами, отображать собственный брендинг на экране согласия и контролировать, какие именно области доступа могут запрашивать разработчики.

Чтобы настроить коннектор с собственным OAuth-приложением, вам понадобятся три вещи от поставщика: **Client ID**, **Client Secret** и **области доступа (scopes)**, которые вы хотите разрешить. Также необходимо зарегистрировать у поставщика URL обратного вызова Replit, чтобы завершить аутентификацию.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Диалоговое окно настройки OAuth для коннектора с полями Client ID, Client Secret и Connector Scopes, а также Redirect URL, установленным на https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Создайте OAuth-приложение у поставщика">
    Войдите в консоль разработчика или панель администратора поставщика и создайте новое приложение OAuth 2.0. У разных поставщиков этот шаг называется по-разному — ищите варианты вроде **Create OAuth app**, **Register application** или **Create client credentials**.
  </Step>

  <Step title="Настройте URL перенаправления">
    Когда поставщик запросит **Authorized redirect URI** (иногда также называемый **Callback URL** или **Redirect URL**), укажите следующее.

    ```
    https://replit.com/connectors/oauth/callback
    ```

    Этот URL определяет, куда поставщик перенаправит пользователя обратно в Replit после авторизации приложения. Он должен совпадать в точности — важны завершающий слеш, протокол и поддомен. Если вы добавляете несколько URI перенаправления, этот URL обязательно должен быть среди них.
  </Step>

  <Step title="Скопируйте Client ID и Client Secret">
    После создания приложения поставщик отобразит **Client ID** и **Client Secret**.

    * **Client ID**: публичный идентификатор OAuth-приложения. Его можно безопасно указывать в URL или клиентском коде.
    * **Client Secret**: конфиденциальное значение, подтверждающее, что запросы поступают от вашего приложения. Обращайтесь с ним как с паролем — никогда не коммитьте его в репозиторий и не публикуйте. Replit хранит его в защищённом виде.

    Некоторые поставщики показывают клиентский секрет только один раз при создании. Сразу скопируйте его и храните в безопасном месте, пока не вставите в Replit.
  </Step>

  <Step title="Выберите области доступа">
    **Области доступа (Scopes)** определяют разрешения, позволяющие OAuth-приложению читать или записывать данные от имени разработчика. Каждый поставщик публикует собственный список областей доступа в документации API.

    Области доступа, которые вы вводите при настройке коннектора в Replit, должны **в точности совпадать** (посимвольно, включая префиксы URL) с областями доступа, зарегистрированными у поставщика. Распространённые причины ошибок несоответствия:

    * Отсутствует полный префикс URL (например, `drive.file` вместо `https://www.googleapis.com/auth/drive.file`).
    * Лишние пробелы или завершающие запятые.
    * В Replit запрашиваются области доступа, которые не активированы в приложении поставщика.

    Начните с минимального набора областей доступа, необходимых разработчикам, и при необходимости добавьте новые позже — большинство поставщиков позволяют обновлять области доступа без повторного создания приложения.
  </Step>

  <Step title="Настройте коннектор в Replit">
    На странице **Connectors** вашей организации выберите **Add new integration**, выберите сервис, затем вставьте полученные от поставщика **Client ID**, **Client Secret** и **Scopes**. Выберите **Configure**, чтобы сохранить настройки.
  </Step>
</Steps>

  Если после настройки аутентификация не проходит, ещё раз проверьте, что URL перенаправления поставщика точно совпадает с `https://replit.com/connectors/oauth/callback` и что все области доступа, указанные в Replit, также одобрены в приложении поставщика.
</Note>

<div id="section-9">
  ## Повторное подключение интеграции
</div>

Если подключённый сервис перестаёт работать, например из-за истечения срока действия сеанса или изменения разрешений, Replit показывает в Project Editor уведомление о необходимости повторного подключения. Выберите уведомление, чтобы повторно подключить интеграцию, не выходя из редактора.

<div id="section-10">
  ## Отладка коннекторов
</div>

Возникли проблемы с подключением сервиса? Ниже приведены распространённые ошибки и способы их устранения.

<AccordionGroup>
  <Accordion title="Google Workspace: &#x22;This app is blocked&#x22;">
    Если при подключении Google Drive, Docs, Sheets, Calendar или Gmail отображается **&quot;This app is blocked&quot;**, вероятно, Google Workspace вашей организации ограничивает использование сторонних OAuth-приложений. Полное руководство по устранению этой проблемы приведено ниже.

    [Устранение ошибки &quot;This app is blocked&quot; для коннекторов Google](/ru/ko/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce: &#x22;Connection Expired&#x22;">
    Если коннектор Salesforce перестаёт работать с ошибкой **&quot;Connection Expired&quot;**, вероятно, политика токенов обновления в вашей организации Salesforce настроена так, что срок действия токенов истекает через определённый период. Сведения об обновлении настроек Connected App см. в полном руководстве по устранению неполадок.

    [Устранение ошибки истечения срока действия подключения Salesforce](/ru/ko/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
