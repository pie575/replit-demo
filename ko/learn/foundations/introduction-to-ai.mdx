AI 도구를 사용하면 자연어로 지시하고 유용한 결과물을 받아볼 수 있습니다. Replit에서는 그 결과물이 계획, 코드, 디자인, 설명, 디버깅 단계, project 변경 사항으로 이어집니다.

무언가를 만들기 전에 AI를 깊이 이해할 필요는 없습니다. 다만 몇 가지 개념을 알아두면 더 나은 지시를 내리고 결과를 자신 있게 평가할 수 있습니다.

<div id="large-language-models">
  ## 대규모 언어 모델
</div>

대부분의 AI builder는 흔히 LLM이라고 부르는 대규모 언어 모델로 작동합니다. LLM은 텍스트에서 패턴을 인식하고, 그 패턴에 맞는 텍스트를 생성하도록 학습된 model입니다.

여기서 텍스트란 산문, 코드, HTML, CSS, SQL, JSON, 터미널 명령어, 테스트 출력, 오류 메시지, 설정 파일 등을 모두 포함합니다. 같은 종류의 model이 문구를 작성하고, 버그를 설명하고, 코드를 만들고, 계획을 요약하는 일까지 두루 도울 수 있는 이유가 바로 여기에 있습니다.

<div id="text-generation">
  ## 텍스트 생성
</div>

LLM은 데이터베이스에서 정해진 답을 꺼내오지 않습니다. 사용자가 제공한 입력과 참조할 수 있는 context를 바탕으로 응답을 한 조각씩 생성해 나갑니다.

prompt를 작성하면 모델은 사용자의 표현, 대화 내용, 활용 가능한 project context를 종합해 유용한 다음 응답을 예측합니다. 그 응답은 설명일 수도, 계획일 수도, 다른 시스템이 작업을 수행하는 데 사용할 수 있는 텍스트일 수도 있습니다.

그만큼 입력의 품질이 중요합니다. 목표와 예시, constraints, context를 명확히 제시할수록 좋은 결과를 얻을 가능성이 높아집니다.

<div id="tokens">
  ## Tokens
</div>

AI 모델은 텍스트를 token이라는 작은 단위로 나누어 처리합니다. token은 단어, 단어의 일부, 문장 부호, 공백, 코드 조각 등이 될 수 있습니다.

token이 중요한 이유는 AI 모델이 한 번에 고려할 수 있는 정보의 양을 좌우하기 때문입니다. 긴 대화, 큰 파일, logs, 스크린샷, 지침은 모두 모델이 추론의 근거로 삼는 context에 포함됩니다.

앱을 만드는 동안 token 수를 일일이 셀 필요는 없습니다. 다만 중요한 정보가 명확하고 최신이며 핵심에 집중되어 있을 때 Agent가 더 잘 작동한다는 점은 알아두는 것이 좋습니다.

<div id="ai-can-vary">
  ## AI는 결과가 달라질 수 있습니다
</div>

AI의 출력이 항상 동일하지는 않습니다. 같은 요청이라도 표현, 디자인, 구현 방식, 절충안이 다르게 나올 수 있습니다.

이러한 변동성은 여러 가능성을 탐색할 때 유용하지만, 그만큼 중요한 작업은 반드시 검토해야 한다는 뜻이기도 합니다. Agent가 만든 결과를 테스트하고, 명확하지 않은 부분은 설명을 요청하고, 안전하게 되돌릴 지점이 필요할 때는 checkpoints를 활용하세요.

<div id="what-makes-ai-output-better">
  ## AI 결과물의 품질을 높이는 요소
</div>

Agent는 다음 정보가 주어질 때 가장 좋은 결과를 냅니다.

* 명확한 목표
* 대상 사용자 또는 사용자 요구 사항
* 제약 조건과 다루지 않을 범위
* 예시, 스크린샷, 파일, 데이터 또는 링크
* 현재 발생한 문제 또는 정확한 오류 내용
* &quot;완료&quot;로 판단할 수 있는 인수 조건

다음 두 prompt를 비교해 보세요.

* *&quot;웹사이트 코드를 작성해 줘.&quot;*
* *&quot;내 개인 메일링 리스트용 이메일 주소를 수집하는 웹사이트 코드를 작성해 줘. 제출된 내용은 Google Sheets에 저장해 줘.&quot;*

두 번째 prompt는 목표와 데이터, 저장 위치를 명시하므로 Agent가 추측할 필요 없이 바로 작업할 수 있습니다.

이러한 정보를 context라고 합니다. context가 중요한 이유는 [Context 관리](/ko/learn/foundations/context-management)를 참고하세요.

<div id="from-ai-to-ai-agents">
  ## AI에서 AI 에이전트로
</div>

채팅 model은 메시지에 답변하는 데 그칩니다. 반면 AI 에이전트는 model에 도구를 더해 여러 단계에 걸친 작업을 수행합니다. 목표를 스스로 판단하고, 필요한 도구를 고르고, 정보를 확인하고, 변경 사항을 적용하고, 결과를 검토하면서 task가 완료되거나 사용자의 입력이 필요한 시점까지 작업을 이어갑니다.

<div id="models-and-tools">
  ### 모델과 도구
</div>

에이전트는 두 가지 중요한 부분으로 구성됩니다:

| 부분        | 하는 일                                                                      |
| --------- | ------------------------------------------------------------------------- |
| **언어 모델** | 지시를 이해하고, 텍스트를 생성하며, 여러 선택지를 검토하고, 다음에 무엇을 할지 결정합니다.                      |
| **도구**    | 파일 읽기, 코드 편집, 명령 실행, 문서 검색, 앱 테스트, 변경 사항 게시 등 에이전트가 실제로 행동에 옮길 수 있게 해줍니다. |

모델은 어떤 행동이 도움이 될지 판단하고, 도구는 에이전트가 그 판단을 실행에 옮기게 해줍니다.

<div id="what-agents-can-do">
  ### 에이전트가 할 수 있는 일
</div>

에이전트는 다음과 같이 여러 단계를 거쳐야 하는 작업에 유용합니다.

* 기능 기획하기
* 파일과 코드 생성하기
* 기존 project 구조 파악하기
* 명령어 또는 테스트 실행하기
* 오류 디버깅하기
* designs 업데이트하기
* 서비스 연결하기
* 변경 사항 요약하기

에이전트는 단순히 답변만 하는 것이 아니라 task를 처음부터 끝까지 수행합니다.

<div id="replit-agent">
  ### Replit Agent
</div>

Replit Agent는 Replit에서 앱을 만들 때 사용하는 AI 에이전트입니다. 앱을 비롯한 artifact 제작, project 검토, 파일 편집, 명령 실행, 동작 테스트, 코드 설명, task 생성, 게시 workflow 안내까지 도와줄 수 있습니다.

예를 들어 Agent에게 다음과 같이 요청할 수 있습니다:

```text theme={null}
지역 모임 행사를 위한 간단한 참가 신청 앱을 만들어줘.
방문자가 행사 정보를 확인하고 이름과 이메일을 입력해 제출하면 확인 메시지를 받을 수 있어야 해.
오늘 바로 게시할 수 있게 첫 버전은 최대한 단순하게 만들어줘.
```

Agent는 이러한 요청을 project로 바꿔 첫 번째 버전을 만들고, 이를 다듬는 과정까지 도와줍니다.

<div id="you-still-lead-the-work">
  ### 작업을 주도하는 것은 여전히 여러분입니다
</div>

Agent는 빠르게 움직일 수 있지만, 중요한 결정은 여전히 여러분의 몫입니다.

* artifact가 무엇을 해야 하는지
* 누구를 위한 것인지
* 어디까지를 범위에 포함할지
* 무엇을 바꾸지 말아야 하는지
* 결과물이 제대로 동작하는지
* 언제 게시할 준비가 되었는지

그래서 context 관리와 검토가 중요합니다. Agent는 여러분이 명확한 방향을 제시하고 결과를 테스트할 때 가장 큰 힘을 발휘합니다.

<div id="common-misconceptions">
  ## 흔한 오해
</div>

* **&quot;AI가 내 의도를 알아서 파악할 것이다.&quot;** AI는 여러분이 제공한 정보만으로 작동합니다. 중요한 사항이 있다면 명확하게 말하세요.
* **&quot;첫 번째 답변이 최종 결과여야 한다.&quot;** AI로 만드는 과정은 반복적입니다. 검토하고, 테스트하고, 다듬으세요.
* **&quot;AI는 사람처럼 의도를 이해한다.&quot;** AI는 패턴을 유추할 수는 있지만, 여러분의 취향이나 사용자층, 제약 조건, 완료 기준까지 자동으로 알지는 못합니다.
* **&quot;에이전트는 그저 챗봇일 뿐이다.&quot;** 챗봇은 주로 응답만 합니다. 에이전트는 도구를 사용해 직접 작업을 수행할 수 있습니다.
* **&quot;Agent는 제품의 전체 목표를 자동으로 안다.&quot;** Agent는 여러분의 지시와 context를 바탕으로 작동합니다. 중요한 사항이 있다면 빠짐없이 포함하세요.
* **&quot;Agent가 있으면 검토할 필요가 없다.&quot;** Agent가 build할 수는 있지만, artifact가 의도한 대로 나왔는지는 여러분이 판단해야 합니다.
