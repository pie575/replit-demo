title: "Publication"
description: "Découvrez comment publier une Replit App avec l'outil de publication : gérez les domaines, les accès, les bases de données, le monitoring, la sécurité et les paramètres de déploiement au même endroit."
---

L&#39;outil de publication vous permet de déployer votre application et de gérer son exécution sur le web. Il regroupe dans un seul panneau les paramètres permettant de contrôler l&#39;adresse web de votre application, les autorisations d&#39;accès, la base de données de production, le monitoring, la sécurité et le mode d&#39;hébergement.

Pour ouvrir ce panneau, sélectionnez **Publishing** sous **Replit Cloud** dans le panneau **Tools**, ou sélectionnez **Publish** en haut à droite du Project Editor.

<div id="section">
  ## Publier votre application
</div>

Le panneau principal vous guide à travers tous les éléments nécessaires à la publication de votre application. Examinez chaque section, puis sélectionnez **Publier**.

<Frame>
  <img src="/assets/mirror/publish-your-app-851815208b8a.png" alt="Panneau Publish your app montrant le champ Domain, l'application à publier, les paramètres d'accès, les paramètres de base de données, le monitoring, la sécurité et les outils d'engagement au-dessus du bouton Publier" width="578" height="980" data-path="images/deployments/publish-pane/publish-your-app.png" />
</Frame>

* **Domain** : l&#39;adresse web de votre application. Replit suggère un nom en `.replit.app` et vérifie sa disponibilité. Après la publication, vous pouvez modifier cette adresse ou connecter un [domaine personnalisé](/fr/ko/features/publishing/custom-domains).
* **Ce que vous publiez** : affiche un aperçu de l&#39;application qui sera publiée et l&#39;URL utilisée.
* **Qui peut accéder à votre application** : choisissez parmi **Public**, **Protégé par mot de passe**, **Workspace uniquement** et **Sur invitation uniquement**. Les options privées limitent l&#39;accès à l&#39;application aux membres de votre workspace ou aux utilisateurs et groupes que vous avez invités. En savoir plus sur l&#39;[accès aux applications](/fr/ko/features/publishing/private-deployments).
* **Paramètres de la base de données** : gérez la façon dont la base de données de production de votre application est créée et remplie de données lors de la publication. En savoir plus sur les [bases de données de production](/fr/ko/features/data-and-storage/development-and-production).
* **Outils de Monitoring** : activez le monitoring de l&#39;application pour être averti dès qu&#39;elle est indisponible. Replit vérifie en continu si votre application est en ligne et vous avertit par e-mail en cas de problème. En savoir plus sur le [monitoring des applications](/fr/ko/features/publishing/monitoring-a-deployment).
* **Outils de sécurité** : exécutez une analyse de sécurité approfondie avant la publication. Security Agent combine l&#39;IA et des outils d&#39;analyse statique de pointe pour détecter les vulnérabilités dans votre projet. En savoir plus dans le [Centre de sécurité du projet](/fr/ko/features/security/project-security-center).
* **Outils d&#39;engagement** : activez le widget de feedback pour ajouter un bouton de feedback dans un coin de votre application publiée. Vous pouvez examiner les feedbacks reçus dans votre boîte de réception et les transmettre à Agent pour qu&#39;il apporte des corrections.

<div id="section-2">
  ## Ajuster les paramètres
</div>

Sélectionnez **Ajuster les paramètres** pour configurer vous-même l’hébergement de votre application. La plupart des créateurs n’ont pas besoin de modifier ces paramètres. Replit choisit des valeurs par défaut adaptées.

<Frame>
  <img src="/assets/mirror/adjust-settings-d6e124b2249f.png" alt="Section Ajuster les paramètres affichant le type de déploiement, la configuration de la machine, les secrets de déploiement, la région de déploiement et le bouton permettant de bloquer la publication en cas de vulnérabilités critiques" width="574" height="794" data-path="images/deployments/publish-pane/adjust-settings.png" />
</Frame>

* **Type de déploiement** : technologie utilisée pour publier votre application. **Autoscale** est recommandé pour la plupart des applications, car il s’adapte à tous les niveaux de demande, y compris en l’absence de trafic. Comparez les [types de déploiement](/fr/ko/features/publishing/deployment-types).
* **Configuration de la machine** : performances du serveur qui exécute votre application. Sélectionnez **Modifier** pour changer le processeur, la mémoire et le nombre maximal de machines. Le panneau affiche le coût par machine et le coût en cas de trafic maximal. Découvrez la [configuration de la machine](/fr/ko/features/publishing/machine-configuration).
* **Secrets de déploiement** : clés privées utilisées par votre application pour accéder aux API et aux services (un espace de stockage sécurisé et masqué pour les valeurs sensibles telles que les clés API). Les secrets sont automatiquement synchronisés de l’environnement de développement vers l’application publiée. Découvrez [Secrets](/fr/ko/core-concepts/project-editor/app-setup/secrets).
* **Zone géographique de déploiement** : emplacement où votre application est hébergée. Choisir une région plus proche de vos utilisateurs réduit la latence. Une fois publiée, votre application et les ressources associées sont liées à cette région. Pour changer de région ultérieurement, vous devez remixer votre application. Découvrez la [région du projet](/fr/ko/features/publishing/project-geography).
* **Bloquer la publication en cas de vulnérabilités critiques** : Replit exécute toujours une analyse de sécurité avant la publication. Ce paramètre détermine si la publication doit être bloquée lorsqu’une vulnérabilité critique est détectée. Découvrez le [Centre de sécurité du projet](/fr/ko/features/security/project-security-center).
