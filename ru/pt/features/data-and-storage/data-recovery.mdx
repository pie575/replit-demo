Ошибки случаются: неудачное изменение схемы, удалённые строки или сессия Agent, пошедшая не по плану. Replit предлагает способ восстановления для каждой базы данных.

| База данных | Способ восстановления                                            | Доступность                                                                  |
| ----------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Разработка  | Откат к checkpoint                                               | Все планы                                                                    |
| Продакшен   | Восстановление на момент времени и запланированные резервные копии | Core: история до 7 дней. Pro и Enterprise: до 28 дней (7 дней по умолчанию). |

<div id="restaure-seu-banco-de-dados-de-desenvolvimento">
  ## Восстановление базы данных разработки
</div>

Вы можете вернуть приложение и базу данных разработки к предыдущему состоянию с помощью [функции отката](/ru/pt/features/version-control/checkpoints-and-rollbacks/). Это позволяет восстановить базу данных до любого checkpoint, созданного Agent.

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="Интерфейс отката к checkpoint с параметрами отката" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

<Info>
  При восстановлении до состояния checkpoint обязательно выберите «Database» в разделе «Additional rollback options». Тогда база данных вернётся в то состояние, в котором она находилась на момент создания checkpoint.
</Info>

<div id="restaure-seu-banco-de-dados-de-produo">
  ## Восстановление продакшен-базы данных
</div>

Продакшен-базы данных можно восстановить на определённый момент времени (point-in-time restore).

<Frame>
  <img src="/assets/mirror/database-rollbacks-f13dd20874ae.jpg" alt="Интерфейс откатов базы данных с параметрами отката" width="1082" height="708" data-path="images/databases/database-rollbacks.jpg" />
</Frame>

Насколько далеко в прошлое можно откатиться, зависит от вашего плана и настроек срока хранения. План Core хранит историю до 7 дней, планы Pro и Enterprise — до 28 дней. На всех планах изначально доступно 7 дней, и это окно можно изменить в настройках продакшен-базы данных. Чем больше окно, тем больше занимаемого хранилища, поэтому увеличение срока хранения повышает расходы на использование. При переходе с Pro на Core окно хранения сокращается до 7 дней.

<Warning>
  Восстановление базы данных не восстанавливает код приложения, а откат приложения не восстанавливает базу данных. Чтобы вернуть и то и другое к одному моменту времени: восстановите базу данных, затем [выполните откат к соответствующему checkpoint](/ru/pt/features/version-control/checkpoints-and-rollbacks/) и снова опубликуйте приложение.
</Warning>

<div id="agende-backups-do-banco-de-dados-de-produo">
  ## Настройте расписание запланированных резервных копий продакшен-базы данных
</div>

Запланированные резервные копии создают одну полную точку восстановления в день. Replit выполняет копирование около полуночи по часовому поясу вашего браузера на момент включения или изменения расписания.

1. Откройте инструмент **Database** и выберите продакшен-базу данных.
2. Откройте **Settings**, затем разверните **Scheduled backups** в разделе **Advanced**.
3. Чтобы включить запланированные резервные копии, выберите срок хранения в поле **Keep backups for**.

Доступные сроки хранения зависят от вашего плана. Core поддерживает до 7 дней, Pro и Enterprise — до 28 дней.

<div id="custos-de-armazenamento">
  ### Стоимость хранения
</div>

Replit измеряет каждую категорию хранилища продакшен-базы данных отдельно:

| Категория хранилища                               | Цена за ГиБ в месяц |
| ------------------------------------------------- | ------------------: |
| Логическое хранилище базы данных                  |               $0.35 |
| Хранилище восстановления на момент времени (PITR) |               $0.20 |
| Хранилище запланированных резервных копий         |               $0.09 |

<Note>На хранение базы данных сейчас действует скидка 100%.</Note>

Плата $0.35 за логическое хранилище взимается независимо от того, используете ли вы PITR, запланированные резервные копии или и то и другое. Хранилище запланированных резервных копий стоит дешевле за ГиБ, чем хранилище PITR. Если ежедневных точек восстановления вам достаточно, запланированные резервные копии с более коротким окном PITR помогут снизить затраты на хранилище для восстановления. Общая стоимость резервного копирования зависит от объёма хранимых копий и срока их хранения.

PITR даёт больше точек восстановления в пределах вашего окна, а запланированные резервные копии — одну точку восстановления в день, поэтому выбирайте метод восстановления под свои задачи.

<Note>
  Расписание использует ваше текущее смещение UTC. Переход на летнее время
  может сдвинуть время резервного копирования на один час, пока вы не обновите
  расписание. Часовые пояса с дробным смещением используют ближайший час.
</Note>

<div id="restaure-um-backup-agendado">
  ### Восстановление запланированной резервной копии
</div>

1. Откройте **Scheduled backups** в настройках продакшен-базы данных.
2. Выберите **View all backups**.
3. Выберите **Restore** напротив нужной точки восстановления.
4. Введите `restore`, затем нажмите **Continue**.

При восстановлении база данных переключается на данные из выбранной резервной копии. Текущие данные при этом не удаляются, но подключённые сервисы могут ненадолго потерять соединение и переподключиться.

<div id="soluo-de-problemas-em-falhas-de-publicao">
  ## Устранение неполадок при сбоях публикации
</div>

Если публикация завершается сбоем из-за проблем с базой данных:

1. **Проверьте логи публикации** — найдите конкретные сообщения об ошибках, связанных с подключением к базе данных или конфликтами схемы
2. **Просмотрите недавние изменения схемы** на предмет возможных конфликтов с существующим кодом приложения
3. **Протестируйте изменения в предварительном просмотре развертывания**, прежде чем publikовать заново
