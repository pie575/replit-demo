<div id="section">
  ## 开始使用
</div>

Replit 是一个云端开发环境，可以编写并运行任何框架或技术栈。构建自定义模板有两条推荐路径：

1. **[从 Git 提供商导入](https://replit.com/import)** — 从 GitHub、GitLab 或 Bitbucket 导入现有的起始技术栈 (或任何你需要的技术栈) 。
2. **复刻 Blank 模板** — 复刻 [Blank 模板](https://replit.com/@replit/Nothing?v=1)，在完全空白的开发环境中从零开始。

已有客户成功构建出适用于 Rust、Python、Java、C++ 等各种技术栈的模板。只要能跑起来，就能在 Replit 上运行。

<Tip>
  构建第一个模板时，我们建议与 Replit 的 **Field Engineering 团队**合作。该团队在为各类技术栈配置自定义模板方面经验丰富，可以为你提供帮助。请联系你的 Account Executive 安排对接。
</Tip>

借助自定义模板，Enterprise 管理员可以为组织的所有成员创建预配置的起始点，并直接显示在 Agent 输入框中。当构建者选择某个自定义模板时，Agent 会将其复刻，并依据该模板的配置、说明和技能来指导后续的所有工作，无需额外设置。

<Note>
  自定义模板仅在 **Enterprise** 方案中可用。只有组织管理员可以固定和管理模板。
</Note>

<div id="section-2">
  ## 自定义模板的工作原理
</div>

自定义模板是**固定在 Agent 输入框中**的组织标准 Replit App。构建者选择后：

1. Agent 会复刻该模板并创建新应用 (复制全部文件)
2. Agent 会跳过规划阶段，直接开始构建
3. 模板中的 `custom_instruction/instructions.md` 文件会注入到 Agent 的上下文中
4. `.agents/skills/` 中的自定义 [技能](/zh/ko/features/agent/skills) 会被识别并可供使用
5. [`replit.md`](/zh/ko/features/project-setup/replit-dot-md) 文件提供持续的项目上下文

也就是说，从第一次交互开始，组织的标准、模式和工具就已内置其中。

<div id="section-3">
  ## 模板文件结构
</div>

自定义模板的推荐布局如下：

```
my-template/
├── .replit                              # 应用配置（运行命令、端口和模块）
├── replit.md                            # Agent 记忆：项目概览和默认设置
├── custom_instruction/
│   └── instructions.md                  # 注入 Agent 提示词的公司指引
├── .agents/
│   └── skills/
│       └── my-skill/
│           └── SKILL.md                 # Agent 可按需调用的自定义技能
└── ...                                  # 其余仓库结构
```

每个文件各司其职。下面几节将分别介绍如何配置这些文件。

<div id="section-4">
  ## 自定义模板设置
</div>

<div id="section-5">
  ### 创建基础应用
</div>

在您的组织中创建一个新的 Replit App。为项目配置好构建者起步所需的全部文件、依赖项和配置，其中包括：

* 源代码脚手架 (组件、工具函数、配置文件)
* 预装的依赖项 (`package.json`、`requirements.txt` 等)
* [`.replit` 文件](/zh/replit-app/configuration)中的环境配置

<div id="section-6">
  ### 配置共享 Secrets
</div>

如果模板依赖 API 密钥、令牌或其他凭据，请在固定模板前将其添加到模板的 **Secrets** (位于工具面板底部) 。当构建者基于模板创建新应用时，所有 Secrets 都会自动复制到新应用中，因此无需自行配置凭据即可开始使用。

在 `custom_instruction/instructions.md` (或专用技能) 中记录所有 Secrets，方便构建者了解有哪些 Secrets 以及每个密钥的用途。

<Warning>
  Secrets 会在复刻时复制，不会动态同步。如果你轮换密钥或向模板添加新的 Secrets，之前复刻的应用不会自动更新。构建者必须在这些应用中手动添加或更新 Secrets。
</Warning>

<div id="section-7">
  ### 编写自定义指令
</div>

在项目根目录中创建 `custom_instruction/instructions.md` 文件。这是模板中最重要的文件，用于告知 Agent 组织构建软件的方式。

<Warning>
  文件夹名称必须是 `custom_instruction` (单数) ，而不是 `custom_instructions` (复数) 。
</Warning>

Agent 会将此文件连同一段说明其为公司提供指令的前言，直接注入系统提示词。请使用 Markdown 编写，并包含以下内容：

* **架构模式**：应用的组织方式
* **编码规范**：命名约定、文件组织规则和代码检查要求
* **组件使用**：应使用 (以及应避免使用) 的素材库和组件
* **API 模式**：如何调用后端服务、处理身份验证和管理错误
* **测试要求**：需要哪些测试，以及如何运行
* **部署指令**：不同环境的配置和部署工作流

````markdown theme={null}
# 公司工程规范

## 架构
所有 Web 应用均使用 TypeScript 搭配 React。仅使用带 Hook 的
函数式组件。状态管理方面，本地状态使用 Zustand，
服务器状态使用 React Query。

## 组件素材库
使用内部设计系统包 `@acme/ui`。按钮、输入框、表单和
弹窗一律禁止使用原生 HTML 元素，始终使用 `@acme/ui` 中
对应的组件。

按如下方式导入组件：
```tsx
import { Button, TextField, Modal } from '@acme/ui';
```

## API 集成
所有 API 调用都通过 `@acme/api-client` 包进行。
绝不直接使用原生 fetch 或 axios。身份验证由客户端
自动处理。

## 测试
每个组件都必须有对应的测试文件。单元测试使用
Vitest，集成测试使用 Playwright。
````

**大小限制**：内容有约 25 KB 的软性限制，超出部分可能会被逐步截断。如果指令越来越多，不要把所有内容都堆在 `instructions.md` 里，而应将详细的参考资料迁移到 `.agents/skills/` 下，做成 [技能](/zh/ko/features/agent/skills)。技能只在相关时按需加载，因此不计入指令的大小限制，也能让主指令始终聚焦于高层级规则。

<div id="section-8">
  ### 添加自定义技能
</div>

针对需要 Agent 遵循的特殊工作流，在 `.agents/skills/` 目录中创建技能。每个技能都是一个目录，其中包含带有 YAML 前置元数据的 `SKILL.md` 文件。

```
.agents/skills/
├── use-design-system/
│   └── SKILL.md
├── api-integration/
│   └── SKILL.md
└── run-tests/
    └── SKILL.md
```

每个 `SKILL.md` 都必须在前言 (frontmatter) 中包含 `name` 和 `description`：

```markdown theme={null}
---
name: use-design-system
description: Use when building UI components. Provides component patterns, theming rules, and accessibility requirements for the Acme design system.
---

# Acme Design System

## Available components

- `Button` — Primary, secondary, and ghost variants
- `TextField` — Text input with validation support
- `Modal` — Dialog overlay with focus trapping
...
```

| 字段            | 是否必填 | 详细说明                               |
| ------------- | ---- | ---------------------------------- |
| `name`        | 是    | 最多 64 个字符。仅支持小写字母、数字和连字符。          |
| `description` | 是    | 最多 1,024 个字符。说明该技能的作用以及适用场景。  |
| `enabled`     | 否    | 默认值为 `true`。如需停用而不删除，请设置为 `false`。 |

**技能的加载方式**：Agent 在提示词中只能看到 `name` 和 `description`。只有当某个技能与当前任务相关时，才会按需读取完整的 `SKILL.md` 内容。因此，`description` 至关重要，请确保其描述与 Agent 应当使用该技能的场景相匹配。

除 `SKILL.md` 外，技能还可以包含支持文件：

```
.agents/skills/use-design-system/
├── SKILL.md
├── references/
│   └── component-api.md
└── assets/
    └── theme-tokens.json
```

有关技能的更多信息，请参阅 [Agent 技能](/zh/ko/features/agent/skills) 和 [使用技能](/zh/ko/build/use-agent-skills)。

<div id="replitmd">
  ### 配置 replit.md
</div>

在项目根目录的 `replit.md` 中预先填入模板的架构概述。该文件始终会加载到 Agent 的上下文中，作为持续保留的项目记忆。

文件应包含以下四个部分：

```markdown theme={null}
# 概述
使用 React、TypeScript 和 Acme 设计系统构建的任务管理应用。后端使用 Express.js，数据库为 PostgreSQL。

# 用户偏好
- 所有文件均使用 TypeScript
- 优先使用带 Hooks 的函数组件
- 遵循 Acme 编码规范

# 系统架构
- 前端：React + TypeScript + @acme/ui
- 后端：Express.js + TypeScript
- 数据库：PostgreSQL 搭配 Drizzle ORM
- 身份验证：通过 @acme/auth 使用 Acme SSO

# 外部依赖项
- @acme/ui：内部设计系统
- @acme/api-client：API 集成层
- @acme/auth：身份验证 SDK
```

Agent 会随着项目的演进不断更新 `replit.md`。当该文件超过约 4,000 个 token 时，Agent 会自动对其进行精简摘要，使内容始终重点突出、切实可用。

更多信息，请参阅 [replit.md](/zh/ko/features/project-setup/replit-dot-md)。

<div id="section-9">
  ### 将模板固定到组织
</div>

模板准备就绪后：

1. 前往组织的模板应用
2. 打开该应用的操作菜单 (三点菜单)
3. 选择**固定到 Agent 输入框**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="显示“固定到 Agent 输入框”选项的应用操作菜单" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  只有组织管理员 (拥有 `system_admins` 角色的成员) 才能固定或取消固定模板。
</Note>

将成员访问权限设置为**只读**，让成员可以查看和使用模板，但无法编辑。

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="成员访问权限设置为只读的邀请对话框" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

此时，该模板会以可选标签的形式显示在组织全体成员的 Agent 输入框下方。如需移除，请打开同一菜单并选择**从 Agent 输入框取消固定**。

<div id="section-10">
  ### 模板访问控制
</div>

固定后，模板将对所有组织成员可见。若需更有针对性地分发，可使用模板应用中的**邀请**按钮，将其分享给特定[群组或单个用户](/zh/ko/teams/identity-and-access-management/groups-and-permissions)。这样，你无需将模板固定到组织范围的输入框中，即可限制哪些团队或人员能够查看和复刻该模板。

<div id="section-11">
  ## 构建者选择模板后会发生什么
</div>

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="在 Agent 输入框中显示为可选项的模板" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

当组织成员在 Agent 输入框中选择已固定的模板时：

1. **复刻**：基于该模板创建一个包含全部文件的新应用副本
2. **跳过规划**：Agent 跳过初始的规划对话，直接进入构建模式
3. **加载指令**：读取 `custom_instruction/instructions.md`，作为公司提供的指令注入 Agent 的系统提示词
4. **发现技能**：识别 `.agents/skills/` 中的技能，并列入 Agent 的上下文，以便按需加载
5. **加载项目上下文**：读取 `replit.md` 并注入 Agent 的上下文 (若不存在则自动生成)
6. **继承配置**：`.replit` 文件、依赖项以及所有模板文件都会延续到新应用中

构建者可以立即根据具体需求向 Agent 输入提示词，而 Agent 会在模板设定的护栏范围内运行。

<div id="section-12">
  ## 文件如何协同工作
</div>

每个配置文件各司其职：

| 文件                                   | 用途        | Agent 何时读取    | Agent 是否可修改        |
| ------------------------------------ | --------- | ------------- | ------------------ |
| `custom_instruction/instructions.md` | 组织标准和规则   | 始终 (注入系统提示词)  | 否                  |
| `.agents/skills/*/SKILL.md`          | 专用工作流和模式  | 按需 (相关时)      | 是 (Agent 也可以创建技能)  |
| `replit.md`                          | 项目概述和基本设置 | 始终 (注入系统提示词)  | 是 (Agent 会随时间更新)   |
| `.replit`                            | 运行时配置     | 配置应用时         | 是                  |

**关键区别**：`custom_instruction/instructions.md` 是组织标准的静态权威来源。`replit.md` 是一份由 Agent 随项目发展持续维护的动态文档。技能是特定工作流所需时参考的资料。

<div id="section-13">
  ## 最佳实践
</div>

<div id="section-14">
  ### 保持指令聚焦
</div>

针对最重要的模式编写 `custom_instruction/instructions.md`。请重点关注：

* 难以逆转的决策 (架构、数据模型)
* 需要保持一致的模式 (组件用法、API 规范)
* 构建者可能不了解的标准 (内部素材库、团队规则)

请勿包含变更历史、实现细节或频繁变动的信息。

<div id="section-15">
  ### 编写便于发现的技能描述
</div>

`SKILL.md` 前置元数据中的 `description` 字段用于帮助 Agent 决定何时加载技能。请编写与技能适用任务相匹配的描述：

```yaml theme={null}
# 好的示例 —— 说明何时使用
description: Use when building forms or handling user input. Provides validation patterns, error display conventions, and accessible form layouts.

# 效果较差 —— 过于模糊
description: Form utilities and helpers.
```

<div id="section-16">
  ### 按工作流组织技能
</div>

围绕工作流而非技术类别来分组技能：

| 组织方式      | 示例                                         |
| --------- | ------------------------------------------ |
| **按工作流**  | `build-a-form`、`connect-to-api`、`add-auth` |
| **按技术领域** | `react-utils`、`api-helpers`、`auth-config`  |

按工作流组织有助于 Agent 在恰当的时机找到合适的技能。

<div id="section-17">
  ### 迭代改进模板
</div>

模板会在使用过程中不断完善。团队开始基于模板构建后：

1. 找出 Agent 处理不当的模式，并将其补充到 `instructions.md` 中
2. 当 Agent 出色地解决了某个问题时，创建新技能来沉淀该解决方案
3. 随着技术栈的演进，更新默认依赖项和配置
4. 从模板创建新应用来测试改动，确认实际体验

<div id="section-18">
  ### 模板更新与现有应用
</div>

对模板应用所做的更改只会体现在新创建的应用中。此前从模板复刻的现有应用是独立副本，不会收到这些更新。
