Поскольку Replit запускает проекты в облачной среде, порты работают иначе, чем на локальном компьютере. (Если вам нужно базовое объяснение того, что такое TCP-порты, [начните здесь](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

На компьютере существует только один уровень управления портами: программа определяет порт, на котором она ожидает соединения, и когда интернет-трафик поступает на этот порт компьютера, он направляется соответствующему процессу.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="Компьютер" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` — это адрес или хост. Если процесс прослушивает `0.0.0.0`, это означает, что он прослушивает все сетевые интерфейсы. Другими словами, если другой компьютер в интернете отправит запрос на IP-адрес вашего компьютера, процесс его получит. Поэтому прослушивание на 0.0.0.0 означает, что эти процессы доступны из публичного интернета, если компьютер подключён к сети.

Большинство фреймворков во время разработки &#95;не&#95; прослушивают `0.0.0.0`. Это связано с тем, что из соображений конфиденциальности и безопасности вы можете не захотеть публиковать свою работу в процессе разработки. Вместо этого они прослушивают другой адрес (`127.0.0.1`, также известный как `localhost`). Это означает, что отправлять запросы на этот порт может только данный компьютер.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Порты localhost видны только на компьютере, который их обслуживает." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

В Replit необходимо определить **внешний порт**, чтобы сделать запущенный процесс доступным из веб-представления или для внешних запросов. Это необходимо потому, что «внутренний порт», обычно используемый процессом, виден только внутри изолированной облачной среды Replit. Чтобы направлять нужный трафик программе, этот внутренний порт необходимо подключить к доступному извне порту. Даже если процесс прослушивает общедоступный адрес, например 0.0.0.0, его необходимо привязать к внешнему порту.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Внешний порт перенаправляет трафик на внутренний порт, который прослушивает программа." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit делает это, привязывая внешний порт к определённому внутреннему порту. Например, на изображении выше внешний порт `:80` привязан к внутреннему порту `:3000`. Это означает, что трафик, который Replit App получает на порту 80, отправляется на внутренний порт 3000.

Эта конфигурация записывается в разделе [[ports]] файла конфигурации .replit.

По умолчанию Replit сопоставляет первый открытый порт с внешним портом 80, используемым по умолчанию. Благодаря этому процесс доступен по домену без указания порта (например, customdomain.com/ вместо customdomain.com:3000/). Дополнительно открытые внутренние порты сопоставляются с другими доступными внешними портами (полный список приведён ниже).

<div id="section-2">
  ## Порт по умолчанию
</div>

Порт 80 — порт по умолчанию для HTTP-трафика, поэтому HTTP-трафик, отправляемый на корневой домен, автоматически направляется на порт 80. Поэтому в URL для порта 80 номер порта не отображается. Порты, отличные от `:80`, указываются в адресе домена (например: customdomain.com:4200/). (Поскольку Replit по умолчанию предоставляет TLS, технически используется порт 443 — порт по умолчанию для HTTPS. На практике их можно считать взаимозаменяемыми.)

<div id="section-4">
  ## Публикация
</div>

Деплои Autoscale и Reserved VM поддерживают публикацию только одного внешнего порта, при этом соответствующий внутренний порт не может использовать `localhost`. Публикация нескольких портов или одного порта через `localhost` приведёт к сбою опубликованного App. Чтобы деплой Autoscale работал как ожидается, удалите из конфигурации все записи `externalPort`, кроме порта сервиса, доступ к которому должен быть открыт из интернета.

<div id="section-5">
  ## Отладка
</div>

Одна из распространённых причин, по которой приложение работает не так, как ожидается: настройки порта могут выглядеть правильными, но программа фактически прослушивает другой порт. Например, если конфигурация выглядит следующим образом:

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Трафик из интернета, поступающий на порт 80, перенаправляется на внутренний порт 3000. Однако если программа фактически прослушивает другой порт (например, 8080), а не порт 3000, может показаться, что трафик не проходит. Это может произойти, если вы изменили порт в коде, но не обновили соответствующий порт в настройках, или скопировали настройки из одного проекта в другой.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Программа может изменить порт, который она прослушивает." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

У каждого фреймворка свой порт по умолчанию. Например, Flask использует порт 5000, react — 3000, а laravel — 8000. Убедитесь, что указан правильный порт!

<div id="section-6">
  ## Настройки
</div>

Когда в Replit App открывается порт, Replit автоматически сопоставляет его с доступным внешним портом и сохраняет это сопоставление в файле конфигурации .replit.

Однако по умолчанию это не происходит для внутренних портов, открытых на localhost. Обычно службы, работающие на localhost, рассчитаны на доступ только с того же компьютера, на котором запущен процесс (порты localhost видны только на этом компьютере). Это означает, что такие службы часто менее защищены, чем службы, изначально рассчитанные на доступ из общедоступного интернета.

Это можно переопределить, установив для портов, которые вы хотите опубликовать, параметр конфигурации `exposeLocalhost` в значение `true`.

Если вы хотите &#95;всегда&#95; публиковать порты localhost по умолчанию, в разделе «Пользовательские настройки» установите для параметра «Автоматическая переадресация портов» значение «Все порты».

Если вы хотите вручную управлять настройками портов для всех Replit App и &#95;никогда&#95; не создавать настройки для открытых портов, установите значение «Не выполнять».

<div id="section-7">
  ## Поддерживаемые порты
</div>

При открытии первого порта в приложении Replit внешний порт 80 назначается по умолчанию. Приложения Replit могут публиковать порты 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080 и 8081 как дополнительные внешние порты.

Порты 22 и 8283 используются внутри системы, поэтому их нельзя перенаправить.

<div id="ports-replit">
  ## Конфигурация `[[ports]]` в .replit
</div>

Тип: `{localPort, externalPort, exposeLocalhost}`

Настройка `[[ports]]` позволяет указать HTTP-порты, публикуемые в веб-выводе. По умолчанию HTTP-порты, доступные на хосте 0.0.0.0, публикуются как веб-вывод приложения Replit.

Чтобы добавить дополнительные порты, не переопределяя порт по умолчанию, добавьте новую запись [[ports]] в файл .replit. Необходимо указать оба параметра: localPort и externalPort. Можно добавить несколько дополнительных портов, указав в файле .replit несколько записей [[ports]], как показано ниже.

<div id="localport">
  ### localPort
</div>

Определяет порт, который Replit привязывает к внешнему порту.

<div id="externalport">
  ### externalPort
</div>

Определяет порт, который будет опубликован для общего доступа и сопоставлен с этим локальным портом.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Если вы&#95;совсем&#95;не хотите открывать определённый порт, просто оставьте настройку `localPort` и не добавляйте `externalPort`:

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Определяет, можно ли привязать внутренние порты, использующие `localhost`, к внешним портам. Может принимать значения `true`, `false` или null.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
