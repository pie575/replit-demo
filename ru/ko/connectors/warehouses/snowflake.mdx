<Info>
  Коннектор Snowflake доступен только на тарифе **Enterprise**.
</Info>

Коннекторы к хранилищам данных позволяют Replit Agent выполнять запросы к хранилищу данных вашей организации. С коннектором Snowflake разработчики могут создавать дашборды, инструменты отчётности и приложения для работы с данными на естественном языке — без знания SQL.

Настройка выполняется один раз и требует участия администратора Snowflake и администратора рабочего пространства Replit. После настройки все участники организации смогут войти в систему и начать создавать приложения на основе данных Snowflake.

Это руководство описывает весь процесс настройки. В нём участвуют три роли:

1. **Администратор учётной записи Snowflake** — создаёт интеграцию OAuth в Snowflake
2. **Администратор рабочего пространства Replit** — настраивает коннектор в Replit
3. **Разработчик** — входит в систему и начинает создавать приложения

<div id="snowflake-oauth">
  ## Создание интеграции OAuth в Snowflake
</div>

Администратор учётной записи Snowflake создаёт OAuth-интеграцию безопасности, которая позволяет Replit проходить аутентификацию в Snowflake.

<div id="section">
  ### Предварительные требования
</div>

* Роль `ACCOUNTADMIN` в Snowflake
* Права на выполнение SQL-запросов в рабочих листах Snowflake

<div id="section-2">
  ### Запуск скрипта настройки
</div>

<Steps>
  <Step title="Войдите в Snowflake">
    Откройте свою учетную запись Snowflake и убедитесь, что используете роль `ACCOUNTADMIN`. Это можно проверить в раскрывающемся списке ролей в правом верхнем углу.
  </Step>

  <Step title="Откройте SQL-рабочий лист">
    На левой боковой панели выберите **Рабочие листы** и создайте новый рабочий лист.
  </Step>

  <Step title="Запустите скрипт OAuth-интеграции">
    Скопируйте, вставьте и выполните следующий SQL-скрипт:

    ```sql Создание OAuth-интеграции theme={null}
    -- Удалите существующую интеграцию, если она есть
    DROP INTEGRATION IF EXISTS REPLIT_OAUTH;

    -- Создайте OAuth-интеграцию для Replit
    CREATE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    <Warning>
      URI перенаправления должен в точности совпадать с `https://replit.com/connectors/oauth/callback`. При использовании другого значения во время аутентификации возникнет ошибка 404.
    </Warning>

    <Note>
      Значение `BLOCKED_ROLES_LIST = ()` гарантирует, что ни одной роли не будет запрещено использовать интеграцию. Без этой настройки при подключении могут возникнуть ошибки «недопустимый запрос согласия» или «роль заблокирована».
    </Note>
  </Step>

  <Step title="Получите учетные данные OAuth">
    Выполните следующий запрос, чтобы получить идентификатор и секрет клиента:

    ```sql Получение учетных данных OAuth theme={null}
    -- Просмотрите сведения об интеграции
    DESCRIBE INTEGRATION REPLIT_OAUTH;

    -- Получите идентификатор и секрет клиента
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```

    Скопируйте **идентификатор клиента** и **секрет клиента** из результата. Они понадобятся на следующем шаге.
  </Step>
</Steps>

<div id="replit">
  ## Настройка коннектора в Replit
</div>

Администратор рабочего пространства Replit добавляет учётные данные Snowflake в Replit. После завершения настройки войти смогут все участники организации.

<Note>
  Для этого шага требуется тариф Enterprise с правами администратора.
</Note>

<Steps>
  <Step title="Откройте интеграции">
    Перейдите в настройки организации и выберите вкладку **Интеграции**.
  </Step>

  <Step title="Добавьте коннектор Snowflake">
    Нажмите **Добавить новый коннектор** и выберите **Snowflake**.
  </Step>

  <Step title="Введите учётные данные">
    Введите **идентификатор клиента** и **секрет клиента** из предыдущего шага.
  </Step>

  <Step title="Задайте область доступа">
    Укажите для коннектора область доступа `refresh_token`.

    <Warning>
      Используйте только область `refresh_token`. Другие области, например `session:role-any` или `session:role:PUBLIC`, могут вызвать ошибку «недопустимая область».
    </Warning>
  </Step>

  <Step title="Сохраните">
    Нажмите **Сохранить**, чтобы активировать коннектор.
  </Step>
</Steps>

<div id="snowflake">
  ## Вход в Snowflake
</div>

Войти может любой участник организации, у которого есть доступ к коннектору. Прежде чем использовать коннектор с Agent, войдите на странице **Интеграции** и проверьте подключение.

<Steps>
  <Step title="Найдите коннектор Snowflake">
    В Replit перейдите в раздел **Интеграции**. В разделе **Коннекторы** найдите **Snowflake**.
  </Step>

  <Step title="Нажмите «Войти»">
    В коннекторе Snowflake нажмите **Войти**.
  </Step>

  <Step title="Укажите идентификатор аккаунта Snowflake">
    В запросе OAuth потребуется указать идентификатор вашего аккаунта Snowflake.

    Чтобы найти его, посмотрите на URL Snowflake:

    ```
    https://app.snowflake.com/myorg/myaccount
    ```

    Соедините дефисом две части, которые идут после `app.snowflake.com/`:

    ```
    myorg-myaccount
    ```

    <Note>
      В URL эти две части разделяются символом `/`, а в идентификаторе аккаунта — `-`.
    </Note>
  </Step>

  <Step title="Пройдите аутентификацию">
    Snowflake перенаправит вас на страницу входа. Введите свои учётные данные Snowflake, чтобы завершить процесс OAuth.
  </Step>
</Steps>

<div id="snowflake-2">
  ## Начало разработки с данными Snowflake
</div>

После подключения коннектор Snowflake можно использовать с Agent двумя способами:

* **Слеш-команда** — введите `/snowflake` в промпте, чтобы задействовать коннектор
* **Естественный язык** — попросите Agent напрямую использовать данные Snowflake

Примеры промптов:

```
Создай дашборд на основе моих данных из Snowflake. Покажи общую выручку
по регионам в виде столбчатой диаграммы, поквартальную динамику — линейным
графиком, и таблицу с 10 крупнейшими клиентами. Тёмная тема, аккуратно и современно.
```

Agent пишет и выполняет SQL-запросы к данным в Snowflake, создавая работающие приложения.

<div id="section-3">
  ## Устранение неполадок
</div>

<AccordionGroup>
  <Accordion title="Ошибка недопустимого запроса согласия или блокировки роли">
    В интеграции Snowflake некоторые роли могут быть заблокированы по умолчанию.

    Убедитесь, что интеграция создана с параметром `BLOCKED_ROLES_LIST = ()`. Если она уже была создана без этого параметра, выполните следующее:

    ```sql изменение списка заблокированных ролей theme={null}
    CREATE OR REPLACE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    Если ошибка сохраняется, убедитесь, что роль по умолчанию не заблокирована:

    ```sql настройка роли по умолчанию theme={null}
    ALTER USER "YOUR_USERNAME" SET DEFAULT_ROLE = 'PUBLIC';
    ```
  </Accordion>

  <Accordion title="Ошибка 404 при аутентификации">
    Убедитесь, что URI перенаправления интеграции Snowflake точно соответствует следующему:

    ```
    https://replit.com/connectors/oauth/callback
    ```

    Любое несоответствие приведёт к ошибке 404 в процессе OAuth.
  </Accordion>

  <Accordion title="Ошибка недопустимой области действия">
    Убедитесь, что для коннектора Replit указана только область доступа `refresh_token`. Удалите другие области доступа, например `session:role-any` или `session:role:PUBLIC`.
  </Accordion>

  <Accordion title="Ошибка подключения">
    Убедитесь, что идентификатор клиента и секрет клиента в Replit совпадают с данными, сгенерированными Snowflake. Выполните следующее для повторной проверки:

    ```sql проверка учётных данных theme={null}
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```
  </Accordion>
</AccordionGroup>
