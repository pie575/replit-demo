Replit Agent 提供两种交互模式：**Plan 模式**和**Build 模式**。结合使用这两种模式，你可以先充分构思，再自信地实现。

<div id="plan">
  ## 什么是 Plan 模式？
</div>

使用[Plan 模式](/zh/ja/features/agent/plan-mode)，你可以与 Agent 头脑风暴、提问并规划工作，而无需改动任何代码。你可以将其视为一次协作式规划会话，自由探索各种想法。

Plan 模式最适合以下场景：

* **头脑风暴**：在决定采用某种方案前探索不同思路
* **拆解复杂项目**：在构建前获得结构化的任务清单
* **学习与理解**：就技术、模式或代码库提出问题
* **规划架构**：在编写代码前设计应用结构

<Info>
  在 Plan 模式下，Agent 会读取你的项目并提供指导，但不会对文件做任何更改。准备好实施后，你可以切换到 Build 模式，或批准计划以自动开始构建。
</Info>

<div id="build">
  ## 什么是 Build 模式？
</div>

Build 模式是默认模式，Agent 会在此编写代码、修改文件，并直接在项目中实现功能。创意在这里成为现实。

以下场景适合使用 Build 模式：

* **创建新功能**：让 Agent 编写 AgentNext 功能的代码
* **配置应用**：安装依赖项、设置数据库并连接服务
* **修复问题**：让 Agent 调试并解决代码库中的问题
* **重构代码**：改进现有代码的结构和组织方式

<div id="section">
  ## 结合使用两种模式
</div>

**按顺序使用 Plan 模式和 Build 模式效果最佳。** 先规划以理清思路，再带着明确的方向进行构建。

<Steps>
  <Step title="从 Plan 模式开始">
    切换到 Plan 模式，描述你想构建的内容。Agent 会帮助你梳理需求、提出方案并识别潜在挑战，全程无需编写代码。
  </Step>

  <Step title="生成任务清单">
    请 Agent 创建开发计划。它会将项目拆分为具体、可执行的任务，并明确其优先级和依赖关系。

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="已设置优先级和依赖关系的生成任务清单" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="审查并完善">
    审查建议的计划。你可以提出后续问题、要求修改，或探索其他方案。不断完善计划，直到它符合你的愿景。
  </Step>

  <Step title="开始构建">
    对计划满意后，选择 **开始构建**。Agent 会自动切换到 Build 模式，开始实施已批准的任务。

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="显示 Plan 模式和 Build 模式选项的模式选择器" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="跟踪进度">
    在 Agent 处理任务清单时监控进度。每完成一项任务都会创建一个检查点，以便你审查更改并在需要时回滚。
  </Step>
</Steps>

<div id="section-2">
  ## 何时使用哪种模式
</div>

<CardGroup cols={2}>
  <Card title="适合使用 Plan 模式的情况" icon="lightbulb">
    * 开始新项目，需要明确方向时
    * 想探索不同方案时
    * 任务复杂，需要拆分时
    * 想在实施前先了解相关内容时
    * 不确定最佳解决方案时
  </Card>

  <Card title="适合使用 Build 模式的情况" icon="hammer">
    * 已经明确知道自己想要什么时
    * 有清晰且可立即执行的计划时
    * 需要快速修复或进行小幅修改时
    * 正在遵循已批准的任务清单时
    * 优先考虑实施速度时
  </Card>
</CardGroup>

<Tip>
  **不确定该选哪个？** 如果你的请求包含多个功能或重大改动，请从 Plan 模式开始。对于简单且定义明确的任务，可直接进入 Build 模式。
</Tip>

<div id="section-3">
  ## 主要区别
</div>

| 功能       | Plan 模式      | Build 模式   |
| -------- | ------------ | ---------- |
| **目的**   | 头脑风暴、规划和学习   | 实现和构建      |
| **代码修改** | 无 — 只读       | 写入和修改文件    |
| **输出**   | 想法、任务清单和指导   | 可运行的代码和功能  |
| **适用场景** | 复杂项目和探索性工作   | 明确的任务和具体实现 |
| **切换方式** | 点击“开始构建”即可切换 | 已处于实现模式    |

<div id="section-4">
  ## 最佳实践
</div>

<div id="plan-2">
  ### 充分利用 Plan 模式
</div>

* **明确说明需求**：提供的细节越多，计划就越完善
* **提出后续问题**：澄清任何不理解的建议
* **请求示例**：让 Agent 展示代码片段或模式示例
* **讨论权衡取舍**：探索不同方法的优缺点
* **迭代完善想法**：不断完善计划，直到符合你的预期

<div id="section-5">
  ### 无缝迁移
</div>

* **构建前先审查**：在批准前务必审查任务清单
* **从小处着手**：如果完整计划让你感到难以应对，请先从部分任务开始
* **使用检查点**：Agent 会在构建过程中创建检查点，因此你可以随时回滚
