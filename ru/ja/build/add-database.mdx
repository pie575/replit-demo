В руководстве [Добавление входа](/ru/ja/build/add-login) вы добавили в Velocity функцию входа. Однако автомобили в автопарке и бронирования клиентов исчезают при обновлении страницы — они существуют только в браузере. Добавьте базу данных, чтобы сохранять все данные.

<div id="agent">
  ## Попросите Agent сохранять данные
</div>

Velocity использует Neon — управляемую базу данных Postgres от Replit. Neon корректно обрабатывает одновременные бронирования, масштабируется под реальный клиентский трафик, а Agent автоматически подготавливает среды разработки и продакшена. Не нужно регистрироваться в панели Neon или вставлять ключи.

<AiPrompt>
  Сохраняй данные Velocity в базе данных, чтобы автомобили, их доступность и бронирования не исчезали при обновлении страницы.<br />
  Используй Neon (Postgres).<br />
  Сохраняй данные о каждом автомобиле (марка, модель, год выпуска, дневной тариф, фото, местоположение), календарь доступности каждого автомобиля и данные о каждом бронировании (дата получения, дата возврата, автомобиль, клиент).<br />
  Привязывай каждое бронирование к вошедшему в систему клиенту, чтобы каждый видел только свои бронирования.<br />
  Не допускай бронирования одного автомобиля на пересекающиеся даты.<br />
  Сообщи, что мне следует протестировать после внесения изменений.
</AiPrompt>

Agent подготавливает базу данных Neon, переносит автопарк и бронирования из памяти в базу данных и добавляет проверку пересечений, чтобы один и тот же Lamborghini нельзя было забронировать дважды.

<div id="section">
  ## Проверка сохранности всех данных
</div>

1. Войдите в Velocity через Preview и забронируйте автомобиль на следующую субботу.
2. Обновите страницу. Убедитесь, что бронирование осталось в разделе «Мои бронирования».
3. Перезапустите App из чата Agent. Убедитесь, что сохранились и автопарк, и бронирования.
4. Попробуйте забронировать тот же автомобиль на ту же субботу из другой учётной записи. Velocity должен сообщить, что автомобиль недоступен, и предложить другую дату или автомобиль.
5. Выйдите из учётной записи и войдите снова. Убедитесь, что бронирование сохранилось.

Если на каком-либо этапе бронирование исчезнет, вставьте в Agent точное описание проблемы:

<AiPrompt>
  Я забронировал автомобиль в Velocity, но бронирование исчезает после обновления страницы.<br />
  Проверь, сохраняется ли бронирование в базе данных или хранится только на странице.<br />
  Исправь минимально необходимое и расскажи, как это проверить.
</AiPrompt>

Также можно попросить Agent создать простую страницу администратора для проверки содержимого базы данных:

<AiPrompt>
  Покажи мне простую страницу администратора в Velocity со списком всех автомобилей и всех бронирований в базе данных, сгруппированных по автомобилям.<br />
  Показывай её только мне как владельцу Project.
</AiPrompt>

<div id="url">
  ## Проверьте на публичном URL
</div>

Благодаря настройке Neon в Agent у Velocity с самого начала есть отдельные среды разработки и продакшена. Повторно опубликуйте Velocity через чат Agent или плитку Publishing, затем откройте публичный URL в новой вкладке. Replit автоматически применит учетные данные Neon для продакшена к опубликованному деплою — оформите бронирование на публичном URL и обновите страницу, чтобы убедиться, что оно сохранилось.

Теперь Velocity запоминает все автомобили, все доступные даты и все бронирования. При следующем обновлении страницы бронирование не исчезнет.

<div id="section-3">
  ## Нужна дополнительная помощь?
</div>

* **Бронирования сохраняются в Preview, но не по публичному URL:** попросите Agent проверить, применены ли учётные данные Neon для продакшена к опубликованному деплою.
* **Трудно проверить данные:** попросите Agent добавить простое административное представление со списком всего содержимого базы данных.
* **Хотите загрузить данные об автопарке:** попросите Agent добавить одноразовый скрипт для загрузки данных о реальных автомобилях в базу данных.
* **Нужна база данных без настройки для быстрого прототипирования:** используйте [Replit Database](/ru/ja/features/data-and-storage/sql-database) — она встроена в каждый Repl и не требует отдельного выделения ресурсов.
