你已在[添加登录功能](/zh/build/add-login)中为 Velocity 添加了登录功能。但车队中的车辆和客户创建的预订在页面刷新后仍会消失——它们只保存在浏览器中。添加数据库，让所有内容都能持久保存。

<div id="tell-agent-to-save-the-data">
  ## 让 Agent 保存数据
</div>

对于 Velocity，请使用 Neon——Replit 托管的 Postgres 数据库。Neon 能妥善处理并发预订记录，随着实际客户流量增长而扩展，且 Agent 会自动为其配置独立的开发环境与生产环境。无需注册 Neon 仪表板，也无需粘贴密钥。

<AiPrompt>
  将 Velocity 的数据保存到数据库中，这样刷新后车辆、可用状态和预订就不会消失。<br />
  使用 Neon (Postgres)。<br />
  保存：每辆车 (品牌、型号、年份、日租金、照片、地点) 、每辆车的可用日期日历，以及每条预订 (取车日期、还车日期、车辆、客户) 。<br />
  将每条预订关联到已登录的客户，以便每个人只能看到自己的预订。<br />
  防止同一辆车在日期重叠时被重复预订。<br />
  告诉我更改后需要测试什么。
</AiPrompt>

Agent 会配置 Neon 数据库，将车队和预订从内存数据迁移到其中，并添加日期重叠检查，确保同一辆 Lamborghini 不会被重复预订。

<div id="test-that-everything-sticks">
  ## 测试所有数据是否都能保留
</div>

1. 在 Preview 中登录 Velocity，并预订下周六的一辆车。
2. 刷新页面。该预订应仍显示在“我的预订记录”中。
3. 通过 Agent chat 重启应用。车队和预订都应仍然存在。
4. 使用第二个 Account 尝试在同一个周六预订同一辆车。Velocity 应提示该车不可预订，并提供其他日期或车辆选项。
5. 退出登录后重新登录。你的预订应仍然存在。

如果预订在任何一步消失，请将具体情况原样粘贴回 Agent：

<AiPrompt>
  我在 Velocity 中预订了一辆车，但刷新页面后预订消失了。<br />
  检查预订是已保存到数据库，还是仅存储在页面中。<br />
  修复最小的问题，并告诉我如何验证。
</AiPrompt>

你也可以让 Agent 创建一个简单的管理视图，以查看数据库中的内容：

<AiPrompt>
  在 Velocity 中创建一个简单的管理页面，按车辆分组列出数据库中的所有车辆和预订记录。<br />
  仅向我这个 Project 所有者显示该页面。
</AiPrompt>

<div id="publish-and-confirm-on-the-public-url">
  ## 发布并在公开 URL 上确认
</div>

Agent 的 Neon 设置会开箱即用地为 Velocity 提供独立的开发环境与生产环境。通过 Agent chat 或 Publishing 磁贴再次发布 Velocity，然后在新标签页中打开公开 URL。Replit 会自动将生产环境的 Neon 凭据接入已发布的 deployment——在公开 URL 上创建一条预订，刷新页面，确认记录仍然存在。

Velocity 现在会记住每辆车、每个可用日期和每条预订。之后刷新页面也不会丢失任何预订记录。

<div id="need-further-help">
  ## 还需要更多帮助？
</div>

* **预订在 Preview 中会保存，但在公开 URL 上无法显示：**请 Agent 确认生产环境的 Neon 凭据已配置到已发布的 deployment 中。
* **数据难以查看：**请 Agent 添加一个简单的管理视图，列出数据库中的全部内容。
* **想为车队导入初始数据：**请 Agent 添加一个一次性脚本，将真实车辆数据导入数据库。
* **想为快速原型使用无需配置的数据库：**请改用 [Replit Database](/zh/features/data-and-storage/sql-database)——它内置于每个 Repl，无需单独预配。
