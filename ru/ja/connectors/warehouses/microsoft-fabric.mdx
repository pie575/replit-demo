Создавайте ИИ-приложения в Replit и публикуйте их напрямую в Microsoft Fabric со встроенными средствами корпоративного уровня для управления и обеспечения безопасности. Интеграция с Microsoft Fabric превращает управляемые корпоративные данные во внутренние инструменты, такие как дашборды, рабочие процессы и ИИ-приложения. Команды быстро переходят от промпта к производственной среде, а политики аутентификации и доступа остаются в привычной среде Fabric.

<div id="fabric">
  ## Что такое приложения для работы с данными Fabric
</div>

Приложения для работы с данными Fabric — это статические React-приложения, которые выполняют запросы [DAX (Data Analysis Expressions)](https://learn.microsoft.com/en-us/dax/) к семантическим моделям Power BI и отображают диаграммы Power BI. При их создании следует учитывать следующие особенности:

* **Семантическая модель Power BI — источник данных.** Диаграммы строятся на основе запросов DAX к подключенной семантической модели (набору данных).
* **Только для чтения.** Приложения получают данные с помощью `EVALUATE` в DAX и не записывают их обратно в Power BI. Если требуется возможность записи, используйте отдельную базу данных приложения наряду с дашбордом.
* **Отрисовка через портал Fabric.** Уровень данных работает в портале Microsoft Fabric: он выполняет запросы к семантической модели и возвращает результаты приложению. Данные остаются в среде Fabric.
* **Хостинг в инфраструктуре Microsoft.** Готовое приложение для работы с данными можно опубликовать в хостинге Microsoft, чтобы оно работало вместе с остальными компонентами среды Fabric.

<Note>
  Для приложений Microsoft Fabric для работы с данными требуется доступ к клиенту Microsoft Fabric с семантической моделью Power BI, а в период предварительной версии — участие в утверждённой программе тестирования.
</Note>

В основе этого процесса лежит [Rayfin](https://github.com/microsoft/rayfin) — SDK с открытым исходным кодом и CLI для создания бэкендов приложений. Он позволяет Agent определять и публиковать готовые к эксплуатации приложения на основе данных Fabric.

Вы можете работать в едином процессе: описать приложение, поручить Agent создать его каркас, подключить управляемые данные Fabric и опубликовать приложение для работы в клиенте Fabric вашей организации.

В этом руководстве описываются процесс создания, способы подключения приложений к данным Fabric, а также возможности для команд и автоматизации. Сведения об обычных дашбордах данных на основе других хранилищ см. в разделе [Визуализация данных](/ru/ja/features/artifact-types/data-apps).

<div id="section">
  ## Варианты использования
</div>

Для организаций, уже инвестировавших в экосистему данных Microsoft, это позволяет гораздо быстрее создавать внутреннее ПО. Вместо того чтобы тратить недели на настройку аутентификации, API, инструментов деплоя и политик управления, команды описывают свои потребности и поручают Agent создать приложение.

Типичные варианты использования:

* Инструменты повышения производительности для отдельных подразделений
* Операционные дашборды
* Инструменты для исследования данных
* Приложения для автоматизации рабочих процессов
* Интерфейсы для отчетности

Для корпоративных ИТ быстрое создание приложений не требует жертвовать централизованным управлением: управление, аутентификация и безопасность остаются в существующей среде Fabric, которой они уже управляют.

<div id="fabric-2">
  ## Создание приложений для работы с данными Fabric
</div>

Процесс создания построен в формате диалога. Вы остаетесь в Replit на всех этапах, а аутентификация и доступ к данным выполняются через Microsoft по запросу.

<Steps>
  <Step title="Начните с шаблона Fabric">
    На главной странице Replit откройте раскрывающееся меню **Templates** и выберите **Microsoft Fabric App** в разделе **Org templates**. Agent предварительно загрузит инструменты Fabric и запустит рабочий процесс создания приложения для работы с данными.

    <Frame caption="Выбор организационного шаблона Microsoft Fabric App на главной странице Replit (интерфейс закрытого предварительного просмотра).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Главная страница Replit с открытым раскрывающимся меню Templates, где Microsoft Fabric App выделен в разделе Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Опишите нужный дашборд">
    Введите промпт с описанием дашборда или инструмента отчетности, который хотите создать. Например: «Создай дашборд с помесячным ростом продаж на основе модели продаж Fabric». Вам не нужно писать DAX — Agent сгенерирует запросы.
  </Step>

  <Step title="Войдите через Microsoft">
    Когда появится запрос, войдите через Microsoft OAuth в тенант, содержащий данные Fabric. Это предоставит Agent разрешение на чтение доступных семантических моделей. Используемая учетная запись должна иметь доступ к рабочему пространству Fabric, которое вы хотите использовать.
  </Step>

  <Step title="Добавьте источник данных">
    Когда Agent попросит, укажите семантическую модель Power BI / Fabric, которую хотите использовать. Можно предоставить полный URL набора данных из портала Fabric (например, `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) или идентификатор рабочего пространства и идентификатор набора данных/элемента. Agent использует их для определения рабочего пространства и семантической модели, к которым нужно выполнять запросы.

    Модель должна быть **опубликована** в службе Power BI — локальные файлы `.pbix` использовать нельзя.

    <Frame caption="Agent запрашивает ссылку на семантическую модель Power BI / Fabric (интерфейс закрытого предварительного просмотра).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Панель Agent предлагает пользователю предоставить семантическую модель Power BI или Fabric в виде полного URL из портала Fabric либо идентификатора рабочего пространства и идентификатора набора данных/элемента, с примечанием, что локальные файлы .pbix нельзя использовать, поскольку модель должна быть опубликована в службе Power BI" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Поручите Agent создание и доработку">
    Agent изучит схему семантической модели, напишет DAX-запросы и соберет дашборд с подходящими диаграммами. Просмотрите результат и запросите изменения на естественном языке — например, добавьте фильтры, измените тип диаграммы или добавьте другую метрику.
  </Step>

  <Step title="Опубликуйте (необязательно)">
    Когда дашборд будет готов, вы сможете опубликовать его в хостинге Microsoft и запускать в среде Fabric. Процесс публикации будет описан отдельно. Это руководство посвящено подключению к данным и созданию приложения.
  </Step>
</Steps>

<div id="fabric-3">
  ## Подключение к данным Fabric
</div>

Чтобы читать данные, приложению необходимо авторизованное подключение к Microsoft Fabric. Replit устанавливает его одним из двух способов.

<div id="fabric-4">
  ### Вход в Fabric на уровне приложения (для зрителей)
</div>

Зрителям опубликованного приложения для работы с данными не нужно настраивать коннектор. Они проходят аутентификацию через встроенный в приложение механизм единого входа Microsoft Fabric, а приложение считывает данные от имени зрителя через портал Fabric. Благодаря этому доступ по-прежнему регулируется существующими разрешениями Fabric.

<div id="microsoft-fabric">
  ### Коннектор Microsoft Fabric (простой вариант для разработчиков)
</div>

Для разработчиков **коннектор Microsoft Fabric** — удобный способ авторизовать доступ к данным на этапе разработки. Он необязателен: это простой вариант, а не требование.

* Разработчик, который первым выполняет настройку, проходит **однократную OAuth-авторизацию** в Microsoft.
* **Другие участники того же проекта** наследуют это подключение.
* **В других рабочих пространствах** необходимо включить коннектор и пройти собственную OAuth-авторизацию.
* Учётная запись, авторизованная через OAuth, должна иметь доступ к целевому рабочему пространству Fabric.

Коннектор использует Microsoft Entra OAuth и привязан к конкретному арендатору. Как и другие коннекторы Replit, им можно управлять на странице [Интеграции](/ru/ja/features/integrations/overview) проекта. Общие сведения о коннекторах см. в разделе [Управление коннекторами](/ru/ja/replitai/managing-connectors).

<Note>
  В период закрытого предварительного просмотра для коннектора Microsoft Fabric нет общих учетных данных, управляемых Replit. Разработчики авторизуются в собственном арендаторе Microsoft Entra.
</Note>

<div id="section-2">
  ## Команды и автоматизация
</div>

При совместной работе в команде или в неинтерактивных средах (например, CI) интерактивный OAuth не всегда удобен. В таких случаях вместо интерактивного входа укажите токен **субъекта-службы** через [Секреты](/ru/ja/core-concepts/project-editor/app-setup/secrets) проекта. Приложение использует учётную запись субъекта-службы для чтения данных Fabric.

Это наиболее близкий аналог настройки взаимодействия между машинами: нечеловеческая учётная запись, подготовленная в Microsoft Entra и получившая доступ к рабочему пространству Fabric, аутентифицирует приложение без участия человека. Убедитесь, что субъект-служба имеет доступ к рабочему пространству и семантическим моделям, которые запрашивает приложение.

<div id="section-3">
  ## Устранение неполадок
</div>

<AccordionGroup>
  <Accordion title="Данные не загружаются в предпросмотре приложения">
    Уровень данных Fabric работает через портал Microsoft Fabric. Если диаграммы отображаются пустыми или в предпросмотре приложения не загружаются данные, убедитесь, что вы вошли в Microsoft и что используемая учётная запись имеет доступ к связанным рабочему пространству и семантической модели.
  </Accordion>

  <Accordion title="Agent не может найти семантическую модель">
    Вставьте ссылку на набор данных Power BI из портала Fabric и убедитесь, что учётная запись (или субъект-служба) имеет как минимум доступ на чтение к этому рабочему пространству. Если Agent сообщает, что не может разрешить рабочее пространство или модель, повторно предоставьте ссылку на набор данных.
  </Accordion>

  <Accordion title="Коннектор зависает или запрос на подключение появляется снова и снова">
    Повторно авторизуйте коннектор Microsoft Fabric на странице [Интеграции](/ru/ja/features/integrations/overview) проекта. Убедитесь, что учётная запись, авторизованная через OAuth, имеет доступ к рабочему пространству Fabric. Для использования в команде или CI предпочтительнее использовать токены субъектов-служб, передаваемые через секреты.
  </Accordion>
</AccordionGroup>
