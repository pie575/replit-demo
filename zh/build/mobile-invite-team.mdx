PixelGames 不一定是单人 Project。邀请队友后，每个人都能同时运行自己的
Agent task，所有 task 都会在共享看板上统一跟踪，避免重复工作。

<div id="invite-a-teammate">
  ## 邀请队友
</div>

<Steps>
  <Step title="分享项目">
    在 PixelGames 应用中，打开 **Invite**，分享链接或通过电子邮件邀请他人。

    <Frame caption="打开 Invite，然后分享链接或通过电子邮件邀请队友。">
      <img src="/assets/mirror/invite-71cee8be2e0e.png" alt="PixelGames Invite dialog with share link and email invite highlighted" data-path="images/pixelgames/mobile/invite.png" width="1305" height="598" data-path="images/pixelgames/mobile/invite.png" />
    </Frame>
  </Step>

  <Step title="他们各自开始自己的任务">
    加入后，他们可以立即打开自己的 Agent 对话，无需等其他人先完成。
  </Step>
</Steps>

<div id="track-work-on-the-board">
  ## 在看板上跟踪工作
</div>

每个 Agent task 都会经历四个阶段：**Draft** (方案已生成，待审阅) 、**Active**
(Agent 正在构建) 、**Ready** (构建完成，等待应用) 和 **Done** (已合并到
PixelGames) 。

例如，一位队友构建贪吃蛇，另一位添加支付功能，两个 task 在看板上各自独立推进，
谁在做什么一目了然。

<Frame caption="共享看板会展示每位队友的 task 在 Drafts、Active、Ready 和 Done 各阶段的进展。">
  <img src="/assets/mirror/invite-kanban-a4133033bcfa.png" alt="PixelGames task board with Drafts, Active, Ready, and Done columns" data-path="images/pixelgames/mobile/invite-kanban.png" width="1303" height="597" data-path="images/pixelgames/mobile/invite-kanban.png" />
</Frame>

Agent 会在各自独立的 PixelGames 副本中构建每个 task，因此两人同时开发也不会影响
彼此的改动。只有当某个 task 真正被应用回主项目，并且它改动的代码与另一个已应用的 task
重叠时，才会产生冲突。
