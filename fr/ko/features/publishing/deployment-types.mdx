---
title: "Types de déploiement"
description: "Comparez les déploiements Autoscale, Static, Reserved VM et Scheduled, et découvrez quand utiliser chacun d'eux pour les applications que vous publiez."
---

Le type de déploiement correspond à la technologie que Replit utilise pour publier votre application. Vous pouvez le sélectionner dans la liste déroulante **Deployment type**, accessible depuis **Adjust settings** dans l&#39;outil Publishing. **Autoscale** est l&#39;option par défaut et recommandée : la plupart des créateurs n&#39;ont pas besoin de la modifier.

<div id="section">
  ## Comparaison des types de déploiement
</div>

| Type            | Idéal pour                                                         | Mode d&#39;exécution                                                                       | Facturation                                            |
| :-------------- | :----------------------------------------------------------------- | :----------------------------------------------------------------------------------------- | :----------------------------------------------------- |
| **Autoscale**   | Applications web et API au trafic variable                         | Ajoute des serveurs en cas de forte charge et redescend à zéro en période d&#39;inactivité | Vous ne payez que pendant le traitement des requêtes   |
| **Static**      | Landing pages, portfolios, sites de documentation                  | Sert les fichiers depuis des serveurs cloud mis en cache, sans backend                     | Vous ne payez que pour les données servies par le site |
| **Reserved VM** | Bots, tâches en arrière-plan, API toujours actives                 | Un serveur dédié unique qui ne se met jamais en veille                                     | Coût mensuel fixe                                      |
| **Scheduled**   | Tâches périodiques telles que les sauvegardes ou les notifications | Exécute une commande selon une planification définie, puis s&#39;arrête                    | Vous payez chaque durée d&#39;exécution                |

<div id="autoscale">
  ## Autoscale
</div>

Les déploiements Autoscale s&#39;exécutent sur des serveurs qui montent et descendent en capacité selon le trafic de votre application. Lorsque celle-ci est fortement sollicitée, Replit ajoute des serveurs pour absorber la charge. En période d&#39;inactivité, le nombre de serveurs peut descendre jusqu&#39;à zéro : vous ne payez donc rien pendant les heures creuses.

Cette option convient dans les cas suivants :

* Applications web au trafic variable, comme les sites d&#39;e-commerce
* API et services

Les paramètres se gèrent depuis **Adjust settings**. Consultez [Performance de la machine et nombre maximal de serveurs](/fr/ko/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Les déploiements Static hébergent les fichiers de votre application (HTML, CSS, JavaScript, etc.) sur des serveurs cloud qui, grâce à la mise en cache, servent le contenu rapidement et à moindre coût. Aucun serveur backend n&#39;est utilisé.

Ce type de déploiement convient dans les cas suivants :

* Pages de destination marketing
* Sites portfolio
* Sites de documentation produit et API

<Note>
  Les déploiements Static ne sont pas compatibles avec les Replit Apps créées avec Agent. Comme Agent développe des applications full-stack qui nécessitent un serveur backend, utilisez plutôt Autoscale ou Reserved VM dans ce cas.
</Note>

La configuration comprend le répertoire public à servir et, éventuellement, une commande de build. Pour en savoir plus sur les en-têtes de réponse, les réécritures d&#39;URL et les redirections, consultez [Configuration Static avancée](/fr/ko/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Un déploiement Reserved VM exécute votre application sur une machine virtuelle dédiée qui ne se met jamais en veille. Vous bénéficiez de performances constantes et d&#39;un coût mensuel fixe et prévisible.

Cette option convient dans les cas suivants :

* Tâches en arrière-plan gourmandes en mémoire
* Chatbots devant maintenir une connexion permanente
* Serveurs API fonctionnant en continu

La configuration comprend les [performances de la machine](/fr/ko/features/publishing/machine-configuration), les commandes de build et d&#39;exécution, le mappage des ports, ainsi que le choix entre exécuter l&#39;application comme serveur web ou comme worker en arrière-plan.

<div id="scheduled">
  ## Scheduled
</div>

Les déploiements Scheduled exécutent une commande dans l&#39;environnement de l&#39;application selon une planification définie, puis restent à l&#39;arrêt jusqu&#39;à l&#39;exécution suivante. Décrivez la planification en langage courant, par exemple « tous les jours ouvrés à 9 h », et Replit la convertit automatiquement en planification. Vous êtes averti en cas d&#39;échec d&#39;une exécution.

Ce type de déploiement convient aux cas suivants :

* Vérifications d&#39;état et rapports de santé
* Envoi de notifications
* Lancement de sauvegardes

La configuration comprend la planification, le délai d&#39;expiration de la tâche ainsi que les commandes de build et d&#39;exécution. Les déploiements Scheduled ne servent aucune page web : ils n&#39;ont donc pas d&#39;URL publique.
