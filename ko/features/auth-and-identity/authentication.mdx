Replit Auth를 사용하면 앱에서 개인화된 사용자 경험을 만들 수 있습니다. 사용자 계정을 활용해 사용자 환경설정을 저장하고, 맞춤형 대시보드를 만들고, 소셜 기능을 구축하고, 프리미엄 콘텐츠 접근을 제어하고, 사용자 활동을 추적할 수 있습니다. 앱을 매력적이고 가치 있게 만드는 기능을 모두 구현할 수 있습니다.

Replit Auth는 Replit 자체 로그인 시스템을 사용합니다. 누군가 여러분의 앱에 로그인하면 **Replit 계정**을 새로 만들거나 기존 계정을 사용하게 됩니다. 로그인 페이지에는 Replit 브랜드가 표시되며, 로그인 과정은 replit.com 전반에서 사용되는 것과 동일합니다.

<Note>
  **Replit Auth와 Clerk Auth 비교** — Replit은 두 가지 인증 옵션을 제공합니다. **Replit Auth**(이 페이지)는 Replit 자체 로그인 시스템을 사용하므로, 앱 사용자는 Replit 계정으로 로그인하고 Replit 브랜드의 로그인 페이지를 보게 됩니다. **[Clerk Auth](/ko/features/auth-and-identity/clerk-auth)**는 Clerk 기반의 전용 인증 tenant를 앱에 제공하며, 브랜딩을 완전히 맞춤 설정할 수 있고 Replit과는 별개인 사용자 계정을 사용합니다. 로그인 화면에 자체 브랜드를 적용해야 하거나 Replit에 종속되지 않는 사용자 계정이 필요하다면 Clerk Auth를 선택하세요.

  이미 Replit Auth를 사용하는 앱이라면 [Replit Auth에서 Clerk로 마이그레이션](/ko/features/auth-and-identity/migrate-auth-to-clerk)에서 자동화된 마이그레이션 과정과 기존 앱 데이터에 대한 접근을 유지하기 위한 테스트 단계를 확인하세요.
</Note>

인증 기능을 처음부터 구축하느라 몇 달을 들이는 대신, Replit Auth를 사용하면 Agent 프롬프트 하나로 엔터프라이즈급 기능을 갖출 수 있습니다. Fortune 500 기업과 동일한 인프라(Firebase, Google Cloud Identity Platform, reCAPTCHA, Stytch, Clearout)를 기반으로 하므로 전문가 수준의 보안, 사기 방지, 글로벌 확장성이 기본으로 내장되어 있습니다.

<div id="why-use-replit-auth">
  ## Replit Auth를 사용하는 이유
</div>

인증은 여러 회사가 전적으로 매달려 해결할 만큼 까다로운 문제입니다. 앱의 주된 목적은 인증이 아니라, 여러분이 만들고 있는 고유한 아이디어나 해결책일 것입니다.

Replit Auth가 제공하는 이점은 다음과 같습니다.

* **설정 불필요** — Agent에 프롬프트 하나만 입력하면 인증을 추가할 수 있습니다
* **Replit 계정 연동** — 사용자가 기존 Replit 계정으로 로그인하므로 별도의 계정 생성 단계가 없습니다
* **기본 제공 보안** — Replit 인프라를 활용해 일반적인 공격으로부터 앱을 보호합니다
* **사용자 관리** — Auth pane에서 사용자 관리를 간편하게 처리할 수 있습니다
* **데이터베이스 연동** — 데이터베이스에 사용자 항목이 자동으로 생성됩니다
* **로그인 페이지 사용자 지정** — 앱에 맞게 로그인 경험을 꾸밀 수 있습니다(Replit 브랜딩 포함)
* **비밀번호 재설정** — Replit이 비밀번호 재설정 이메일을 대신 보내주므로 별도의 이메일 발송 provider를 설정할 필요가 없습니다
* **추천 프로그램** — Replit Auth로 가입한 사용자는 대기 중인 Replit Referrals에 추가됩니다
* **개발 환경 및 published app** — Replit Auth는 개발 환경(replit.dev)과 published app(replit.app 및 커스텀 도메인) 전반에서 매끄럽게 작동합니다

<div id="enterprise-grade-infrastructure">
  ## Enterprise급 인프라
</div>

Replit Auth는 단순한 사용자 관리를 넘어, Enterprise급 인프라 위에 구축된 완전 관리형 인증 솔루션입니다. 이 강력한 조합을 통해 여러분의 App도 Fortune 500 기업이 사용하는 것과 동일한 인증 기능을 갖추게 됩니다.

* **Firebase 및 Google Cloud Identity Platform** - 검증된 Google의 인증 인프라와 Enterprise 등급 SLA
* **Advanced security scanning** - reCAPTCHA integration으로 봇과 악의적인 공격자를 자동으로 차단
* **사기 방지** - Clearout 기반의 email verification 및 유효성 검사로 가짜 계정 생성 차단
* **다중 요소 인증** - Stytch의 엔터프라이즈 인증 플랫폼이 뒷받침하는 안전한 login 옵션
* **글로벌 확장성** - 자동 확장과 높은 안정성으로 수백만 명의 사용자를 감당하도록 설계

이러한 엔터프라이즈급 기반 위에서, 수십억 달러 규모 기업을 지키는 것과 동일한 인프라가 여러분의 인증을 책임진다는 믿음을 갖고 App만의 고유한 기능을 만드는 데 집중할 수 있습니다. 여러 서비스를 연동하느라 몇 달을 쓸 필요 없이, Agent 프롬프트 하나로 이 모든 기능을 이용할 수 있습니다.

<div id="getting-started-with-replit-auth">
  ## Replit Auth 시작하기
</div>

Replit Auth를 구현하는 유일한 방법은 Agent를 사용하는 것입니다. 프롬프트에 Replit Auth를 요청하는 내용을 포함하기만 하면 됩니다:

```
[앱 아이디어]를 구현하는 앱을 만들어 주세요. Replit Auth 기능이 포함되어야 합니다.
```

Agent가 인증에 필요한 코드와 설정을 모두 구성해 줍니다. 복잡한 작업은 Agent가 알아서 처리하므로 직접 구현하는 방식은 지원되지 않습니다.

앱 브랜딩에 맞게 로그인 페이지를 사용자 지정할 수 있습니다.

1. Project Editor에서 Auth pane으로 이동합니다
2. **Configure**를 클릭합니다
3. 다음 요소를 사용자 지정합니다:
   * 앱 이름
   * 앱 아이콘
   * 로그인 방식(Google, GitHub, X, Apple, Email)

변경 사항은 앱의 로그인 페이지에 즉시 반영됩니다.

<div id="security-considerations">
  ## 보안 고려 사항
</div>

Replit Auth는 Replit의 인프라를 활용하여 일반적인 보안 위협에 대한 기본 보호 기능을 제공합니다. 그렇더라도 다음 모범 사례는 반드시 준수하세요.

* 민감한 작업을 수행하기 전에 항상 서버 측에서 사용자 인증을 검증하세요
* 비밀번호와 같은 민감한 정보는 코드에 저장하지 마세요
* API key나 secret은 환경 변수로 관리하세요
* 사용자 데이터에 적절한 access controls를 구현하세요

보안에 대한 자세한 내용은 다음을 참고하세요.

* [vibe coding을 위한 보안 체크리스트](/ko/learn/security-checklist)

<div id="referrals">
  ## Referrals
</div>

사람들에게 Replit을 알리는 앱을 장려하기 위해, Replit Auth로 가입한 사용자는 모두 자동으로 대기 중인 Replit Referrals 목록에 추가됩니다. 이후 해당 사용자가 Replit Core로 업그레이드하면, 현재 추천 프로그램 약관에 따라 지급 대상이 되는 추천 보너스를 받게 됩니다.

<div id="troubleshooting">
  ## 문제 해결
</div>

<div id="common-issues">
  ### 일반적인 문제
</div>

1. **로그인 후 사용자가 인식되지 않음**
   * 문제가 발생하면 [Replit Agent](/ko/features/agent/overview)에 인증 구현 디버깅을 도와달라고 요청하세요.

2. **사용자 지정 아이콘이 표시되지 않음**
   * 아이콘 URL에 접근할 수 있는지, 지원되는 형식(PNG 또는 JPG)인지 확인하세요.

3. **새로 연결한 커스텀 도메인이 작동하지 않음**
   * 다시 게시(Republish)하여 도메인 목록(REPLIT&#95;DOMAINS 환경 변수)을 새로 고치세요.
