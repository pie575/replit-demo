**项目**是你在 Replit 上构建的所有内容的容器，而**制品**则是项目中可发布的成果——Web 应用、移动应用、幻灯片、动画、数据可视化、3D 游戏以及设计。

如果你要构建多个东西，有两种选择：把多个制品放进同一个项目，或者分别创建独立的项目。哪种方式更合适，取决于这些应用是否共享数据、逻辑和部署生命周期。本页将详细介绍这两个术语，并说明什么情况下应把制品放在同一个项目中，什么情况下应创建独立的项目。

<div id="section">
  ## 什么是 项目？
</div>

项目 是存放代码、数据和你创建的所有制品的容器。只需告诉 Agent 你想构建什么，系统就会设置好 项目，并在其中构建制品。

项目 就像你的桌面工作空间：所有内容集中在一处并共享相同的信息，但各个部分各司其职。

例如，让 Agent 构建一个健身追踪应用时，它会创建一个 项目，其中包含移动应用制品，以及让其正常运行所需的后端、数据库和存储。

核心概念：

* **项目**：容纳所有内容的容器 — 代码、数据和所有制品。
* **制品**：项目 中可发布的成果，例如 Web 应用、幻灯片和视频。
* **资源**：所有制品都能自动访问后端、数据库和文件存储 — 无需配置。

有关可在 项目 中执行的操作 (如管理、筛选、置顶和排序) ，请参阅 [项目](/zh/ja/features/projects-and-artifacts/projects)。

<div id="section-2">
  ## 什么是 制品？
</div>

制品 是可在 Replit 上发布的内容。每个 制品 都是完整且独立的成果，发布后会获得可分享的 URL。

项目中的其他内容——文件、图片、CSV 和代码——都用于支持 制品，但无法单独发布。

<div id="section-3">
  ## 制品 在 项目 内共享的内容
</div>

当多个 [制品](/zh/ja/features/projects-and-artifacts/artifacts) 位于同一个 [项目](/zh/ja/features/projects-and-artifacts/projects) 中时，它们会自动共享以下内容：

* **数据库**：一个 制品 写入数据后，其他 制品 可立即读取。
* **后端与 API**：共享服务器逻辑，无需重复编写代码。
* **文件存储**：图片、文档和上传的文件可在各 制品 之间访问。
* **部署**：发布时，所有内容会同步部署。

也就是说，你无需在 制品 之间配置连接，也不必重复编写代码。不过，你也无法在不发布其他 制品 的情况下单独发布某一个 制品。

<div id="section-4">
  ## 快速指南
</div>

在决定是将制品添加到现有项目，还是新建一个独立项目时，可以参考以下主要场景。

| **一个项目包含多个制品**           | **拆分为独立项目**              |
| ------------------------ | ------------------------ |
| 应用共享同一套数据和后端             | 应用之间不共享底层逻辑或数据           |
| 希望所有内容一起部署               | 需要独立的部署周期                |
| 彼此互为补充 (例如面向客户的应用与管理后台)  | 互不相关的产品，或面向不同的客户         |
| 希望某个制品的改动自动同步到其他制品       | 项目是短期的 (例如营销活动落地页或活动网站)  |

<div id="section-5">
  ## 示例
</div>

<div id="1">
  ### 同一项目：同一产品的 Web 应用 + 移动应用
</div>

一家餐厅构建了一个供顾客浏览菜单的 Web 应用，以及一个供员工管理订单的移动应用。两者连接同一个数据库，共用菜单项、订单和顾客信息。

**为什么放在同一个项目中：** 这些应用共享同样的数据和后端。顾客在 Web 应用上下单后，员工可以立即在移动应用中看到该订单。

<div id="section-6">
  ### 同一项目：应用 + 管理后台 + 投资人路演材料
</div>

一家初创公司在同一个项目中构建主产品、用于内容管理的内部管理面板，以及用于融资的演示文稿。

**为什么放在同一个项目里：** 管理后台管理的正是应用所展示的数据，而路演材料可以从共享后端读取实时指标。

<div id="2">
  ### 独立项目：两个互不相关的客户应用
</div>

一位自由职业者为一个客户构建电商商城，同时为另一个客户构建预订系统。

**为什么要分成不同项目：** 这两个应用之间没有共享的数据或逻辑。每个客户都需要独立部署，一方的改动不应影响另一方。

<div id="section-7">
  ### 独立项目：与主产品并行的营销活动落地页
</div>

你有一个全年运行的生产应用，同时还需要一个用于营销活动的短期落地页。

**为什么要拆分为独立项目：** 活动页面有自己的生命周期——上线、运行几周、然后下线。将其拆分出来可以让主产品保持整洁，也便于独立发布或删除。

<div id="section-8">
  ## 常见问题
</div>

<Accordion title="可以将 制品 移动到其他 项目 吗？">
  目前不支持。如果需要拆分 制品，请新建一个 [项目](/zh/ja/features/projects-and-artifacts/projects)，并让 Agent 在其中重新构建。
</Accordion>

<Accordion title="一个 项目 中的 制品 数量有限制吗？">
  一个 项目 最多可包含 7 个 制品，其中**移动应用每个 项目 限 1 个**。设置该限制是因为 制品 越多，占用的内存越大，预览也可能变慢。如果需要更多 制品，请另建一个 [项目](/zh/ja/features/projects-and-artifacts/projects)。
</Accordion>

<Accordion title="可以只发布 项目 中的某一个 制品 吗？">
  目前不支持。发布时会将所有内容一起部署。如需独立部署，请使用各自独立的 项目。
</Accordion>

<Accordion title="制品 之间会共享数据吗？">
  会。同一 项目 内的所有 制品 共享同一套数据库和后端服务。Web 应用写入数据后，移动应用和数据仪表板可以立即读取到这些数据。
</Accordion>

<Accordion title="制品 与文件有什么区别？">
  制品 是可以发布的成果 —— 应用、幻灯片、视频等。文件 (CSV、图片、代码等) 则是 项目 内的素材，用于支撑 制品，但无法单独发布。
</Accordion>
