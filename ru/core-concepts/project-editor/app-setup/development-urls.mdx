URL-адреса для разработки позволяют просматривать и тестировать приложения в процессе создания. Они имеют формат `UUID.servername.replit.dev` и дают доступ к актуальной версии вашего приложения по мере разработки.

</Frame>

Чтобы открыть URL-адрес для разработки, нажмите текст `{...}.replit.dev` в адресной строке.

<div id="understanding-development-urls">
  ## Что такое URL-адреса для разработки
</div>

URL-адреса для разработки доступны, только пока вы активно работаете над Replit App. При каждом повторном открытии приложения URL-адрес может меняться. Они позволяют просматривать работу в браузере в процессе разработки и тестирования.

По умолчанию URL-адреса для разработки доступны всем в интернете. Любой, у кого есть URL-адрес, может просматривать ваше приложение, пока вы над ним работаете. Это позволяет легко делиться незавершённой работой с коллегами, тестировщиками или заинтересованными сторонами.

<Warning>
  URL-адреса для разработки временные и предназначены только для тестирования. Чтобы поделиться приложением с другими, рекомендуется [опубликовать его](/ru/learn/projects-and-artifacts/replit-deployments).
</Warning>

<div id="educational-banner">
  ### Информационный баннер

Когда вы открываете предпросмотр разработки в новой вкладке, в верхней части страницы появляется информационный баннер. Он помогает понять назначение URL-адресов `.replit.dev` при создании и тестировании приложений. Баннер поясняет, для чего нужны URL-адреса для разработки и как их следует использовать в процессе разработки.

<div id="making-development-urls-private">
  ## Как сделать URL-адрес для разработки приватным
</div>

Вы можете ограничить доступ к URL-адресу для разработки, чтобы защитить незавершённую работу.

Чтобы сделать URL-адрес для разработки приватным:

1. Откройте **Developer tools** в Project Editor.
2. Перейдите на вкладку **Networking**.
3. Включите переключатель **Private development URL**.

После включения для доступа к URL-адресу для разработки потребуется аутентификация. Просматривать незавершённую работу сможете только вы и авторизованные участники команды.

<Note>
  Клиенты Enterprise могут обязать использовать приватные URL-адреса для разработки для всех проектов, повышая безопасность и обеспечивая защиту работы над проектами в среде организации.
</Note>

<div id="best-practices">
  ## Рекомендации
</div>

* **Используйте приватные URL-адреса** для конфиденциальных или проприетарных приложений на этапе разработки
* **Используйте публичные URL-адреса**, чтобы делиться своей работой с внешними заинтересованными лицами во время активной разработки или тестировать App в другом браузере
