---
title: "Migrer de Replit Auth vers Clerk"
description: "Utilisez Agent pour migrer votre application Replit Auth existante vers Clerk Auth tout en conservant les données des utilisateurs."
---

Utilisez ce guide pour migrer votre application [Replit Auth](/fr/ko/features/auth-and-identity/authentication) existante vers [Clerk Auth](/fr/ko/features/auth-and-identity/clerk-auth). Agent effectue la migration des applications concernées afin que les utilisateurs existants puissent continuer à accéder à leurs données.

<Note>
  Cette migration automatisée est destinée aux applications qui utilisent Replit Auth. N&#39;utilisez pas ce processus si votre application utilise un autre système d&#39;authentification.
</Note>

<div id="section">
  ## Démarrer une migration
</div>

La migration avec Agent doit toujours être effectuée dans une nouvelle tâche.

Vous pouvez démarrer la migration de l’une des deux manières suivantes.

  ### Commencer avec Agent
</div>

<Steps>

<div id="section-2">
  ### Examiner le plan de migration
</div>

Quelle que soit la méthode choisie, Agent crée la tâche **Migrate from Replit Auth to Clerk** et prépare un plan de migration. Avant le début de la tâche, sélectionnez **View plan** pour examiner ce plan.

<Frame caption="La tâche Migrate from Replit Auth to Clerk commence par l’action View plan pour vous permettre d’examiner le guide de migration.">
  <img src="/assets/mirror/replit-auth-to-clerk-task-998d61b55c3d.png" alt="Tâche Agent intitulée Migrate from Replit Auth to Clerk, affichant le bouton View plan et l’activité d’examen du guide de migration" width="575" height="900" data-path="images/workspace/auth/replit-auth-to-clerk-task.png" />
</Frame>

Pendant qu’Agent travaille, ne modifiez ni le code d’authentification de l’application ni les identifiants Clerk.

<div id="agent-2">
  ## Ce qu’effectue Agent
</div>

Agent réalise la migration dans l’ordre suivant :

1. Il transfère les données utilisateur de Replit Auth vers Clerk, y compris les informations d’identité des comptes et les identifiants de connexion pris en charge.
2. Il attend que la migration des données soit terminée avant de modifier l’application.
3. Il met à jour la logique de connexion et de session de l’application, redémarre l’application et exécute les vérifications automatisées disponibles.

<div id="section-3">
  ## Les données de l’application restent intactes
</div>

Agent modifie uniquement le code d’authentification de l’application. Il ne met pas à jour les données ni le schéma de la base de données existante de l’application. Les tables et les relations restent inchangées.

Les utilisateurs existants restent associés aux enregistrements qu’ils possèdent déjà, tels que leurs profils, leurs travaux enregistrés et leurs autorisations.

<div id="section-4">
  ## Durée estimée
</div>

Comptez entre 10 minutes et 1 heure pour qu’Agent effectue cette tâche. La migration des données elle-même peut prendre quelques minutes pour les petites applications et jusqu’à plusieurs heures pour les applications comptant de nombreux utilisateurs. Agent ne commencera pas à modifier le code de l’application avant que cette migration ne soit terminée.

<div id="section-5">
  ## Après la migration
</div>

Avant de publier, testez l’application mise à jour dans l’environnement Development.

1. Connectez-vous à votre compte existant et vérifiez que vous pouvez accéder aux données enregistrées.
2. Déconnectez-vous, puis reconnectez-vous.
3. Créez un compte de test et vérifiez que vous pouvez utiliser l’application comme prévu.
