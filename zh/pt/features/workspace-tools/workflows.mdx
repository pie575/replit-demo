它是一系列可复用且可自定义的步骤，可在你的 Replit App 中运行。它可以像运行 `python main.py` 一样简单，也可以像执行多步骤流程一样复杂。

常见使用场景：

* 并行运行多个服务 (例如 frontend + backend)
* 按顺序运行文件或命令 (例如运行 linter → 运行测试，编译 → 运行代码)

要开始[创建工作流](#creating-workflows)，请通过工具侧边栏菜单打开 Workflows 面板，或使用 `Command + K` 搜索 Workflows 面板。

<div id="tipos-de-tarefas-disponveis">
  ## 可用任务类型
</div>

目前提供 3 种任务类型：`Execute Shell Command`、`Install Packages` 和 `Run Workflow`。

<div id="execute-shell-command">
  ### 执行 Shell 命令
</div>

`Execute Shell Command` 会保存 Shell 命令，并在与 Shell 面板相同的环境中运行。此类任务用途广泛，例如运行单个文件：

```text theme={null}
python main.py
```

甚至可以执行已保存的复杂数据库查询命令：

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### 安装软件包
</div>

`Install Packages` 使用 Replit 内置的依赖管理系统，自动检测项目依赖并安装所需的软件包。有关 UPM 如何识别并安装项目所需软件包的更多信息，请参阅[依赖管理](/zh/pt/features/project-setup/dependency-management#the-universal-package-manager)。

<div id="run-workflow">
  ### 运行工作流
</div>

`Run Workflow` 可让你从当前工作流中运行另一个工作流。这样，你可以复用工作流，并将它们组合起来创建更复杂的工作流。

使用场景示例：

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="图片" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

使用此类任务在工作流之间建立依赖关系后，你可以编辑某个工作流，所有引用它的其他工作流都会自动采用最新更改。请注意，深度嵌套的工作流调用设有嵌套深度限制。

<div id="modo-de-execuo-de-workflow">
  ## Workflow 执行模式
</div>

Workflows 提供两种执行模式：顺序执行和并行执行。

<div id="sequencial">
  ### 顺序执行
</div>

顺序执行会按照定义的顺序运行各项任务，并在每项任务完成后再继续下一步。若工作流中的某项任务失败，序列执行将停止。

这种模式适用于定义逻辑上相互关联的命令，例如先获取主分支的最新更改，再将当前分支变基到主分支上的 Git 命令：

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="图片" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="paralelo">
  ### 并行
</div>

并行执行模式会同时运行各个任务，每个任务都会启动并独立于工作流中的其他任务执行。某个任务失败不会中断其他任务的执行。

此模式的一个使用场景是运行全栈项目，该项目需要同时启动 frontend 和 backend 服务器：

<div id="criando-workflows">
  ## 创建 Workflows
</div>

你可以在工作流面板中点击 `+ New Workflow` 按钮来创建 Workflows。先为工作流设置一个描述性的名称，选择合适的执行模式，然后添加任务。你可以通过拖放任务，将其调整为所需顺序。

<div id="atribuir-workflow-ao-boto-run">
  ## 将 工作流 分配给 Run 按钮
</div>

你也可以将 工作流 分配给运行按钮，以替换 Run 按钮 的默认行为 (请参阅[配置 Replit App](/zh/pt/features/project-setup/configuration)) 。若要保留在 `.replit` 中配置的默认运行命令，请在下拉菜单中选择默认选项“Run Replit App”。

点击 Run 按钮时，将执行其旁边下拉菜单中选定的 工作流。要更改 Run 按钮执行的 工作流，请在下拉菜单中点击所需的 工作流。
