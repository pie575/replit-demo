Package Firewall блокирует вредоносные и скомпрометированные пакеты на сетевом уровне, не позволяя установить их в приложение. Он включён по умолчанию для всех пользователей в рамках [Replit Auto-Protect](/ru/ja/features/security/concepts#auto-protect) и предоставляется компанией [Socket](https://socket.dev), специализирующейся на безопасности цепочек поставки ПО.

Когда вы или Agent выполняете команду установки, например `npm install` или `pip install`, запрос сначала проходит через Package Firewall. Безопасные пакеты устанавливаются как обычно — вы ничего не заметите. Пакеты, помеченные Socket как вредоносные или скомпрометированные, блокируются до того, как их код попадёт в ваше окружение.

Package Firewall **включён по умолчанию для всех пользователей**: не требуется ни настройка, ни миграция. Он защищает как новые, так и существующие приложения, и вам ничего не нужно настраивать.

<div id="section">
  ## Почему защита на этапе установки так важна
</div>

Большинство инструментов для защиты цепочки поставок сканируют зависимости только при публикации — то есть уже после того, как пакеты установлены. Для обычных уязвимостей этого порой достаточно. С вредоносным ПО всё иначе: оно наносит ущерб в момент установки — крадёт секреты, открывает бэкдоры, отправляет переменные окружения наружу. К тому моменту, когда сканирование при публикации поднимет тревогу, атака уже состоялась.

Package Firewall закрывает это окно. Блокируя вредоносные пакеты ещё до загрузки, он останавливает атаку прежде, чем выполнится хотя бы одна строка вредоносного кода.

<div id="section-2">
  ## Как это работает
</div>

1. Вы или Agent выполняете команду установки, например `npm install <package>` или `pip install <package>`.
2. Запрос проходит через Package Firewall, который сверяет пакет с данными аналитики угроз Socket.
3. Если пакет безопасен, установка проходит как обычно, без каких-либо заметных отличий.
4. Если пакет вредоносный или скомпрометирован, установка блокируется до того, как код попадёт в вашу среду.

Если что-то заблокировано, вы увидите понятное сообщение о том, что именно остановлено и почему, включая уязвимость или политику, вызвавшую блокировку. Agent получает те же сигналы, поэтому может предложить безопасную альтернативу — например, исправить опечатку в названии пакета — или оставить решение за вами.

<div id="section-3">
  ### Поддерживаемые менеджеры пакетов
</div>

Package Firewall защищает установку пакетов для:

* **JavaScript** — npm, yarn, pnpm
* **Python** — pip
* **Go** — модули Go

<div id="package-firewall">
  ## Что обнаруживает Package Firewall
</div>

Package Firewall блокирует как откровенно вредоносное ПО, так и версии легитимных пакетов — в том числе широко используемых, — которые были скомпрометированы или имеют известные уязвимости. Многие из этих уязвимостей были раскрыты уже после завершения обучения моделей, которые рекомендуют эти пакеты. Поэтому модели могут уверенно предлагать версии зависимостей, считавшиеся безопасными в обучающих данных, но впоследствии помеченные как небезопасные. У этих рисков есть общепринятые названия:

* **Тайпосквоттинг** — вредоносные пакеты, названия которых отличаются от названия настоящего пакета на один символ, например `reqeusts` вместо `requests`. При запросе неправильного пакета вы скачиваете вредоносное ПО.
* **Слопсквоттинг** — модель выдумывает название несуществующего пакета, а злоумышленник регистрирует именно это название и ждёт, пока следующий Agent его установит.
* **Устаревшие рекомендации** — настоящие пакеты с раскрытыми уязвимостями, которые модель рекомендует, поскольку до завершения её обучения они считались безопасными.

Последняя категория — главная причина, по которой Package Firewall особенно важен для приложений, созданных с помощью ИИ: Agent может уверенно попытаться использовать уже небезопасную зависимость, а Package Firewall остановит установку до выполнения этого кода.

<div id="package-firewallreplit">
  ## Как Package Firewall связан с другими средствами безопасности Replit
</div>

Package Firewall — один из трёх взаимодополняющих уровней защиты. Каждый из них защищает свой этап жизненного цикла приложения, поэтому используйте их вместе, а не выбирайте что-то одно.

| Уровень                                      | Когда срабатывает          | Что делает                                                                                                                                                                                                                                   |
| -------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Package Firewall**                         | При установке              | Блокирует вредоносные и скомпрометированные пакеты ещё до загрузки (профилактика).                                                                                                                                                           |
| **Автоматическое сканирование зависимостей** | После установки, постоянно | Выявляет новые опубликованные CVE в установленных зависимостях и при необходимости предлагает исправления, подготовленные Agent. См. [Центр безопасности проекта](/ru/ja/features/security/project-security-center#automatic-dependency-scans). |
| **Security Agent**                           | Перед публикацией          | Проверяет всю кодовую базу на уязвимости в коде, зависимостях и в части конфиденциальности. См. [Сканирование безопасности Agent](/ru/ja/features/security/agent-security-scans).                                                               |
