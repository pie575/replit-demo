Тестирование App позволяет Agent проверять созданное им App в настоящем браузере. Agent перемещается по приложению и нажимает на элементы так же, как это делал бы реальный пользователь, проверяя работу функций. Благодаря самотестированию вы можете убедиться, что ваше App работает корректно, а Agent — самостоятельно находить и устранять проблемы.

Когда тестирование приложения включено, Agent периодически проводит самотестирование — как только сочтёт, что накопилось достаточно изменений. Agent тестирует не после каждого сообщения пользователя, а интеллектуально определяет момент, когда от проверки будет больше всего пользы.

<Note>
  В настоящее время тестирование приложения доступно для полностековых приложений на JavaScript и веб-приложений Streamlit на Python.
</Note>

<div id="section-2">
  ### Основные преимущества
</div>

* **Больше автономности**: Agent может работать дольше без участия человека
* **Выше качество**: раннее обнаружение и устранение проблем позволяет создавать App с меньшим числом ошибок
* **Экономия средств**: выявление проблем ещё на этапе разработки избавляет от дополнительных сеансов отладки
* **Интерактивный разбор**: видеозапись и навигация по разделам для детального анализа результатов

<div id="section-3">
  ### Процесс тестирования
</div>

Самотестирование Agent проходит следующим образом:

1. **Предпросмотр в браузере**: в панели Agent открывается предпросмотр в браузере
2. **Визуальное тестирование**: вы видите, как курсор Agent кликает по элементам App и проверяет работу функций
3. **Имитация реального пользователя**: Agent перемещается по приложению, как настоящий пользователь, и при необходимости вводит тестовые данные
4. **Автоматический анализ**: Agent анализирует результаты тестирования и выявляет проблемы
5. **Самостоятельное исправление**: Agent приводит сводку результатов тестирования и автоматически устраняет обнаруженные проблемы

<div id="section-4">
  ## Основные возможности
</div>

Agent интеллектуально тестирует приложение, перемещаясь по нему как реальный пользователь, и охватывает следующее:

* **Проверка пользовательского интерфейса**: кнопки, формы, навигация, визуальные элементы
* **Проверка функциональности**: ключевые функции и пользовательские рабочие процессы
* **Интеграционное тестирование**: вызовы API, операции с базой данных, сторонние сервисы
* **Производительность и доступность**: время загрузки, адаптивность, стандарты доступности

<div id="section-5">
  ## Как использовать
</div>

Тестирование App находится в разделе **Дополнительные настройки** выпадающего меню настроек Agent в поле чата. Включите его при работе в режиме Economy или Power. В режиме Lite тестирование App остаётся выключенным.

<Note>
  Тестирование App — одна из автономных возможностей Agent наряду со встроенной проверкой кода. Узнайте больше о других [возможностях Agent](/ru/ja/features/agent/overview).
</Note>

<div id="section-6">
  ## Передача управления
</div>

Во время тестирования Agent может столкнуться с препятствием, которое не сможет обойти без вашей помощи. Чаще всего это необходимость войти в учётную запись пользователя (например, Gmail). В таких случаях Agent покажет всплывающую кнопку «Начать передачу управления».

После нажатия кнопки «Начать передачу управления» вы сможете работать мышью в тестовом предпросмотре и выполнить необходимые действия, чтобы Agent мог продолжить работу. Можно также нажать «Пропустить», чтобы отказаться от передачи управления; если без вашей помощи Agent продолжить не сможет, тестирование приложения на этом завершится. Если вы не ответите в течение 10 минут, Agent продолжит так, как если бы вы нажали «Пропустить».

<div id="section-8">
  ## Устранение неполадок
</div>

**Если тесты неожиданно завершаются с ошибкой**

* Попробуйте пропустить тест и ввести промпт заново
* Проверьте, не влияет ли динамический контент на тайминг тестов
* Убедитесь в корректности тестовых сценариев

**Если покрытие тестами недостаточное**

* Подробно опишите функциональность вашего App
* Явно укажите ключевые пользовательские сценарии, которые нужно протестировать

**Если тестирование App не работает совсем**

* Тестирование App сейчас поддерживается только для веб-приложений[*](#アプリテストの仕組み)

<div id="section-9">
  ## Стоимость и использование
</div>

Тестирование App входит в модель оплаты Agent по затраченным усилиям, и здесь есть важные моменты, связанные со стоимостью:

* **На основе использования**: тестирование оплачивается исходя из объёма затраченной работы (чем проще тест, тем он дешевле)
* **Баланс затрат и выгоды**: тестирование стоит денег, но раннее обнаружение ошибок позволяет избежать лишних промптов и дополнительной работы Agent, а значит — сэкономить
* **Эффективная разработка**: автоматизированный подход снижает потребность в ручной отладке и доработках

<Tip>
  **Экономически выгодное тестирование**: тестирование App увеличивает расходы на использование, но в итоге часто позволяет сэкономить, поскольку исключает ситуации, когда на исправление проблем, которые можно было выявить тестами, приходится тратить дополнительные сессии Agent.
</Tip>
