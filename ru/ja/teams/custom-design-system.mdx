Дизайн-система предоставляет Agent знания, необходимые для создания UI в фирменном стиле во всём, что организация создаёт в Replit: веб- и мобильных приложениях, слайдах и других артефактах. Настроив библиотеку компонентов, дизайн-токены, брендовые ассеты и правила их использования в стандартном pnpm-монорепозитории Replit, вы позволите Agent применять ваш визуальный язык уже с первого промпта.

<Note>
  Дизайн-система доступна только в плане **Enterprise**. Настраивать дизайн-систему и управлять ею могут только администраторы организации.
</Note>

<div id="section">
  ## Зачем настраивать дизайн-систему
</div>

Без дизайн-системы каждому разработчику приходится вручную описывать Agent библиотеку компонентов, цветовые токены и правила раскладки. Настройка дизайн-системы избавляет от этой необходимости:

* **Закрепление визуальных стандартов**: Agent использует именно ваши компоненты, цвета и отступы, а не универсальные значения по умолчанию
* **Единообразие**: все приложения следуют одному дизайн-языку
* **Быстрое погружение в проект**: новые разработчики сразу получают результат, соответствующий бренду
* **Фиксация неявных знаний**: дизайнерские решения и сценарии использования компонентов, которые существуют только в головах участников команды, документируются для Agent

<div id="section-2">
  ## Необходимые материалы
</div>

* Библиотека фронтенд-компонентов в виде tar-файла или набора tar-файлов
* Шрифты и значки, используемые в дизайн-системе
* Документация по ИИ для дизайн-системы (MCP, навыки Agent)

<div id="section-3">
  ## Что можно настроить
</div>

Настройка дизайн-системы состоит из трёх частей:

1. **Пользовательские инструкции**. Файл `custom_instruction/instructions.md` задаёт Agent высокоуровневые правила, применяемые ко всем проектам: какую библиотеку компонентов использовать, на какие дизайн-токены ссылаться, каким паттернам следовать. Этот файл всегда находится в контексте Agent.

2. **Навыки**. Навыки в `.agents/skills/` содержат подробные справочные материалы, которые Agent загружает по мере необходимости. Используйте их для документации по API компонентов, руководств по темизации, библиотек шаблонов раскладки и другого детального справочного содержимого, слишком объёмного для основного файла инструкций.

3. **Дизайн- и брендовые ассеты**. Разместите логотипы, иконки, шрифты и другие брендовые ассеты в отдельной папке (например, `src/assets/brand/`). Настройте псевдонимы путей Vite, чтобы Agent и разработчик могли ссылаться на них через понятные импорты вроде `@brand/logo.svg` вместо хрупких относительных путей. Благодаря этому ссылки на ассеты остаются единообразными во всём проекте.

<div id="section-4">
  ## Пошаговое руководство
</div>

В этом руководстве описано, как с нуля настроить дизайн-систему, используя существующую библиотеку компонентов, упакованную в tar-файл:

1. **Создайте новое приложение Replit** и загрузите tar-файл.
2. **Попросите Replit Agent установить пакет и отобразить все компоненты.** Agent настроит проект и визуализирует библиотеку компонентов.
3. **Проверьте результат.** Убедитесь, что все компоненты отображаются корректно и соответствуют ожиданиям. Затем перейдите к разделу [Создание навыка дизайн-системы](#creating-the-design-system-skill).

<div id="section-5">
  ### Создание навыка дизайн-системы
</div>

Когда компоненты готовы, остаётся последний шаг — создать навык дизайн-системы, чтобы Agent мог обращаться к компонентам, токенам и шаблонам использования во всех проектах.

Скопируйте приведённый ниже промпт целиком и вставьте его в Agent. Замените `<your-design-system-name>` на название вашей дизайн-системы:

````
Создайте навык дизайн-системы `<your-design-system-name>` из компонентов и пакетов этого проекта.

Используйте следующую структуру файлов: `SKILL.md` в корне, директорию `references/` для руководств и документации по компонентам, а также директорию `packages/`, содержащую все зависимости, необходимые для работы.

Просмотрите все компоненты в проекте и задокументируйте каждый из них в отдельном файле в директории `references/components/`, включая свойства, варианты и примеры использования.

Отформатируйте `SKILL.md` как индексный файл, содержащий ссылки на руководства и файлы справочников по компонентам, и включите разделы «Общие рекомендации» и «Компоненты» в соответствии с приведенным ниже примером.

Структура файлов:

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (Tar-файл или кодовые компоненты)

Файл `SKILL.md` служит индексным файлом, содержащим ссылки на другие Markdown-файлы с руководствами и справочниками по компонентам. Каждый файл по ссылке подробно раскрывает одну тему. Ниже приведен пример сгенерированного `SKILL.md`:

```markdown
---
name: your-design-system
description: Используется при создании или изменении UI. Предоставляет справочник по API компонентов дизайн-системы, руководство по раскладке и правила визуального стиля.
---

# Your Design System

## Общие рекомендации

- [Настройка](references/guides/setup.md) — установка, конфигурация проекта, настройка провайдеров
- [Ограничения](references/guides/guardrails.md) — строгие правила, которые нельзя нарушать (запрещенные паттерны, обязательные токены, минимальные требования к доступности)
- [Раскладка и отступы](references/guides/layout-and-spacing.md) — сеточная система, шкала отступов, адаптивные контрольные точки, шаблоны страниц
- ...

## Компоненты

- [Индекс компонентов](references/components/component-index.md) — полный список доступных компонентов со статусами и категориями

Справочники по отдельным компонентам (свойства, варианты, примеры):

- [Кнопка](references/components/button.md)
- [Чекбокс](references/components/checkbox.md)
- ...
```

Каждый файл руководства охватывает одну тему: инструкции по настройке и установке, лучшие практики и правила, справочные таблицы значений токенов, короткие примеры кода, демонстрирующие правильное использование.

Каждый файл компонента описывает один компонент. Он включает имя компонента, краткое описание, таблицу свойств, примеры использования, рекомендации или ограничения. Чем полнее эти файлы, тем лучше будут результаты работы Agent.
````

<div id="agentxx">
  ### Подключение навыка к Agent
</div>

После создания навыка убедитесь, что файл `custom_instruction/instructions.md` указывает Agent на этот навык:

```markdown theme={null}
# Дизайн-система

Загрузи навык дизайн-системы из `.agents/skills/your-design-system/` и следуй ему.
Всегда применяй дизайн-систему при создании или изменении UI.
```

Наконец, заранее пропишите в `replit.md` контекст, относящийся к вашей дизайн-системе, чтобы Agent с самого начала понимал визуальные стандарты. Укажите описание проекта, предпочитаемую библиотеку компонентов, ключевые дизайнерские предпочтения (шкала отступов, требования к доступности) и архитектурный стек.

<div id="section-6">
  ### Проверка настройки
</div>

Прежде чем разворачивать дизайн-систему, убедитесь, что выполнены обязательные условия:

* `custom_instruction/instructions.md` направляет Agent к навыку дизайн-системы
* в `.agents/skills/` находится навык со справочником компонентов, руководствами и пакетами
* в `replit.md` заранее заданы описание проекта, предпочтения и архитектура
* включён файл дизайн-токенов (`tokens.css` или аналогичный)
* пакеты дизайн-системы предустановлены в `package.json`
* создайте новое тестовое приложение и убедитесь, что Agent корректно использует дизайн-систему

<div id="section-7">
  ### Закрепление дизайн-системы в организации
</div>

Когда дизайн-система будет готова, закрепите её, чтобы она стала доступна всем участникам организации:

1. Перейдите к приложению дизайн-системы в организации
2. Откройте меню действий приложения (меню с тремя точками)
3. Выберите **Закрепить в поле ввода Agent**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий приложения с опцией «Закрепить в поле ввода Agent»" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Закреплять и откреплять дизайн-системы могут только администраторы организации (участники с ролью `system_admins`).
</Note>

Настройте для участников доступ **только для чтения**, чтобы они могли просматривать и использовать закреплённую дизайн-систему, не редактируя её.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалог приглашения с доступом участников только для чтения" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Дизайн-система отображается у всех участников организации под полем ввода Agent в виде доступной для выбора кнопки. Чтобы удалить её, откройте то же меню и выберите **Открепить из поля ввода Agent**.

<div id="section-8">
  ## Постоянное сопровождение дизайн-системы
</div>

Дизайн-системы развиваются. Поддерживайте их в актуальном состоянии:

* **Обновляйте файлы токенов**, когда в дизайн-системе появляются новые значения цветов, отступов и типографики
* **Обновляйте навыки**, когда у компонентов появляются новые свойства, варианты и сценарии использования
* **Обновляйте инструкции**, когда меняются принципы дизайна или стандарты
* **Обновляйте версии пакетов**, когда выходят новые релизы дизайн-системы
* **Регулярно тестируйте**: создавайте новые приложения и проверяйте, что Agent выдаёт корректный результат

<div id="section-9">
  ## Сравнение дизайн-систем и пользовательских шаблонов
</div>

Дизайн-системы и [пользовательские шаблоны](/ru/ja/teams/custom-templates) предназначены для разных задач:

|                        | Дизайн-системы                                                                               | Пользовательские шаблоны                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Цель**               | Настроить фронтенд-стек для команды и использовать кодовые компоненты                        | Полностью заменить стандартный стек (например, на Rust, Go или C++)                          |
| **Стек**               | Работают в стандартном монорепозитории Replit на pnpm                                        | Определяют полностью индивидуальную структуру проекта                                        |
| **Что предоставляют**  | Правила для библиотек компонентов, дизайн-токены, брендовые ассеты и визуальные возможности | Полный стартовый шаблон: среда выполнения, настройки сборки, зависимости и структура проекта |
| **Область применения** | Веб-приложения, мобильные приложения, слайды, артефакты — всё, что создаёт Agent             | Только приложения, созданные на основе конкретного шаблона                                   |

Используйте дизайн-систему, если хотите, чтобы Agent соблюдал визуальные стандарты во всей работе с Replit. Используйте пользовательские шаблоны, если вам нужен принципиально иной стек.
