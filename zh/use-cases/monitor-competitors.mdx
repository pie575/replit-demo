监控竞争对手的定价、更新日志和功能页面。发生重大变更时，
总结变更内容，通知 Slack，并及时更新 Notion 中的竞争情报页面。
向销售团队简报前，请先在网站上确认变更。

<div id="best-for">
  ## 最适合
</div>

* 需要实时更新竞品信息页面的产品经理。
* 需要在交易生变前调整定价的客户经理。

<div id="before-you-start">
  ## 开始之前
</div>

向 Agent 提供竞争对手列表，并指定要关注的页面 (定价、更新日志、功能) 。
连接 Slack 和 Notion。

<div id="prompt-the-agent">
  ## 向 Agent 发送提示
</div>

<AiPrompt>
  创建一个每天早上 8:00 运行的 Routine。监控以下竞争对手：
  [列出 URL]。检测定价或功能变更，总结变更内容，在变更重大时通知
  Slack，并保持 Notion 中的竞争情报页面为最新状态。
</AiPrompt>

<div id="what-to-expect">
  ## 使用须知
</div>

Agent 会将每个页面与上一版本进行比较，简要说明“变更内容”，并
更新 Notion。在向销售团队说明前，请先确认线上网站确实发生了变更。若页面经过重新设计，最初几天可能会有较多提醒；请明确哪些变更属于实质性变更。收到 Slack 提醒后，请打开线上 URL，亲自核查变更后再转发。

<div id="make-it-work-for-you">
  ## 按你的需求定制
</div>

<AiPrompt>
  仅在定价或套餐发生变更时通知 Slack。其他页面编辑记录到
  Notion 中，无需通知。
</AiPrompt>

<AiPrompt>
  定价变更时，在 Notion 中起草一份 5 行销售简报：变更内容、受影响的对象，
  以及我们相比之下的优势。
</AiPrompt>

<div id="troubleshooting">
  ## 故障排除
</div>

* **每次改版都被判定为价格变更：**告诉 Agent 要监控哪些页面 (定价、更新日志、功能) ，以及哪些变化属于重大变更。在向销售团队通报前，先确认线上网站确实发生了变更。
* **始终没有收到提醒：**页面可能无法访问，或者竞争对手列表过于狭窄。提供完整的 URL，并要求 Agent 在无法加载页面时说明情况。
* **Notion 里堆满了零散笔记：**让 Agent 使用一个统一的竞争情报页面，并要求它直接更新该页面，而不是每天早上新建一个页面。
