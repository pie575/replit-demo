<div id="o-que-voc-far">
  ## Ce que vous allez faire
</div>

Dans ce tutoriel, vous allez :

* Créer une application mobile à partir d&#39;un prompt avec Agent
* La prévisualiser localement sur votre téléphone avec Expo Go
* Partager un aperçu dans Expo Go pour les tests et les retours
* La faire passer sur TestFlight pour les tests bêta
* La soumettre à l&#39;App Store pour un lancement public

<Note>
  Suivez ce tutoriel dans l&#39;éditeur de projet sur [replit.com](https://replit.com). Si vous utilisez l&#39;application Replit pour iOS, ouvrez le projet sur replit.com pour travailler sur des applications mobiles natives.
</Note>

<Note>
  Apple définit les exigences applicables aux soumissions sur TestFlight et l&#39;App Store. Vous utiliserez App Store Connect pour gérer les tests et les lancements.
</Note>

<div id="o-que-voc-precisar">
  ## Ce dont vous aurez besoin
</div>

* Un compte Replit avec accès à l&#39;éditeur de projet sur [replit.com](https://replit.com)
* Un téléphone sur lequel Expo Go est installé
* Un abonnement à l&#39;Apple Developer Program (exigé par Apple pour TestFlight et l&#39;App Store)

<div id="parte-1-crie-seu-aplicativo-com-o-agent">
  ## Partie 1 : créez votre application avec Agent
</div>

<Steps>
  <Step title="Créez une application mobile">
    Sur l&#39;écran d&#39;accueil de Replit, décrivez ce que vous souhaitez créer et sélectionnez **Application mobile** comme type d&#39;app.
  </Step>

  <Step title="Laissez Agent travailler">
    Agent structure votre projet et en crée une première version. Gardez le Chat ouvert pour suivre la progression et demander des modifications.
  </Step>
</Steps>

<div id="parte-2-teste-no-seu-celular-com-o-expo-go">
  ## Partie 2 : testez sur votre téléphone avec Expo Go
</div>

Expo Go exécute un aperçu natif de votre application sur votre appareil.

<Steps>
  <Step title="Installez Expo Go">
    Installez Expo Go sur votre iPhone ou votre appareil Android.
  </Step>

  <Step title="Ouvrez le QR code">
    Dans l&#39;éditeur de projet, sélectionnez **Prévisualiser sur appareil mobile** pour afficher un QR code.
  </Step>

  <Step title="Scannez et prévisualisez">
    Scannez le QR code avec votre téléphone pour ouvrir un aperçu natif dans Expo Go.
  </Step>
</Steps>

<Frame>
  <img src="/assets/mirror/mobile-screen-e5685fc26793.png" alt="Application mobile en cours d'exécution dans l'aperçu de l'éditeur de projet Replit avec le panneau Prévisualiser sur appareil et le QR code" width="1440" height="900" data-path="images/native-mobile-apps/mobile-screen.png" />
</Frame>

<Tip>
  Si votre aperçu ne semble pas à jour, actualisez-le dans Expo Go. Sur votre appareil, secouez le téléphone pour ouvrir le menu développeur et sélectionnez **Recharger**.
</Tip>

<div id="parte-3-compartilhe-uma-pr-visualizao-com-o-expo-go">
  ## Partie 3 : Partagez un aperçu avec Expo Go
</div>

Le partage via Expo Go crée un aperçu de développement destiné aux testeurs ayant installé Expo Go. Utilisez-le pour recueillir des retours avant de soumettre une build au processus de revue d&#39;Apple.

<Steps>
  <Step title="Publiez depuis l'Éditeur de projet">
    Ouvrez le panneau de publication et sélectionnez **Publier**. Cette action déploie votre application et son back-end sur l&#39;infrastructure de Replit.
  </Step>

  <Step title="Partagez votre application">
    Une fois l&#39;aperçu publié, les testeurs disposant d&#39;Expo Go peuvent l&#39;ouvrir grâce au lien de partage. Aucun compte Apple Developer n&#39;est nécessaire à cette étape.
  </Step>
</Steps>

<Tip>
  Utilisez les aperçus Expo Go pour partager rapidement des prototypes, recueillir les premiers retours et itérer avant de vous lancer dans le processus de l&#39;App Store.
</Tip>

<div id="parte-4-promova-para-o-testflight">
  ## Partie 4 : Publiez sur TestFlight
</div>

Après avoir partagé un aperçu dans Expo Go, vous pouvez publier votre application sur TestFlight pour des tests bêta plus formels. TestFlight nécessite un compte Apple Developer, mais offre une expérience d’application native sans Expo Go.

<div id="pr-requisitos-para-publicao-na-apple">
  ### Prérequis pour la publication chez Apple
</div>

Apple exige des comptes et des configurations spécifiques avant de pouvoir soumettre des builds. Effectuez ces étapes avant toute tentative de soumission.

<div id="entre-no-programa-de-desenvolvedor-da-apple">
  #### Inscrivez-vous au Apple Developer Program
</div>

Vous devez disposer d&#39;un abonnement au Apple Developer Program pour envoyer des builds vers TestFlight et l&#39;App Store.

<Callout type="note">
  Apple exige l&#39;authentification à deux facteurs sur votre compte Apple.
</Callout>

<div id="inscrio-individual-vs-organizacional">
  #### Inscription individuelle ou en tant qu&#39;organisation
</div>

* **Comptes individuels** : vous publiez sous votre nom légal en tant que vendeur.
* **Comptes d&#39;organisation** : vous publiez sous le nom de l&#39;organisation en tant que vendeur. Apple exige un numéro D‑U‑N‑S pour les organisations, dont l&#39;obtention peut prendre un certain temps.

<div id="etapas-tpicas-de-inscrio">
  #### Étapes d&#39;inscription habituelles
</div>

1. Rendez-vous sur `https://developer.apple.com/programs/enroll/`
2. Effectuez la vérification d&#39;identité
3. Acceptez le contrat de licence de l&#39;Apple Developer Program
4. Réglez les frais annuels fixés par Apple
5. Attendez l&#39;approbation d&#39;Apple (le délai varie selon le type de compte)

<div id="entenda-o-testflight-vs-a-app-store">
  ### Comprendre TestFlight par rapport à l&#39;App Store
</div>

TestFlight est le système de tests bêta d&#39;Apple. L&#39;App Store est la place de marché publique où n&#39;importe qui peut télécharger votre application.

| Aspect                       | TestFlight                                                   | App Store                                            |
| ---------------------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| **Public**                   | Testeurs invités (jusqu&#39;à 10 000 testeurs externes)      | Grand public                                         |
| **Objectif**                 | Tests bêta et retours                                        | Lancement public                                     |
| **Examen**                   | La première build d&#39;une version passe par un examen bêta | Chaque envoi passe par l&#39;examen des applications |
| **Durée de vie de la build** | Expire au bout de 90 jours                                   | Permanente jusqu&#39;à ce que vous la retiriez       |

<Tip>
  TestFlight est le moyen le plus rapide de détecter les plantages, les problèmes de performance et les problèmes propres à un appareil avant le lancement.
</Tip>

<Steps>
  <Step title="Ouvrez le panneau de publication">
    Une fois votre application partagée sous forme d&#39;aperçu Expo Go, ouvrez le panneau de publication dans l&#39;Éditeur de projet.
  </Step>

  <Step title="Sélectionnez la publication sur l'App Store">
    Sélectionnez **Publier sur l&#39;App Store** pour faire passer votre application sur TestFlight.
  </Step>

  <Step title="Connectez-vous à Apple et envoyez">
    Connectez-vous avec votre compte Apple Developer lorsque vous y êtes invité. Replit crée une application native dans le cloud et l&#39;envoie vers TestFlight.
  </Step>
</Steps>

<Note>
  La première build d&#39;une version nécessite généralement un examen bêta TestFlight. Une fois celle-ci approuvée, vous pouvez habituellement envoyer les builds suivantes aux testeurs plus rapidement.
</Note>

<div id="habilite-testes-externos">
  ### Activez les tests externes
</div>

Pour partager votre build TestFlight avec d’autres personnes, configurez les tests externes dans App Store Connect :

1. Dans App Store Connect, ouvrez votre app.
2. Accédez à **TestFlight**, puis à **Testeurs externes**.
3. Créez un groupe de testeurs et ajoutez votre build.
4. Soumettez-la à l’examen des apps bêta (requis par Apple pour les testeurs externes).
5. Partagez le lien public TestFlight après son approbation.

<div id="parte-5-envie-para-a-app-store">
  ## Partie 5 : Envoyez votre app sur l’App Store
</div>

Lorsque votre build est prête à être publiée, soumettez-la via App Store Connect :

1. Dans App Store Connect, ouvrez votre app.
2. Accédez à l’onglet **App Store**.
3. Renseignez les métadonnées requises (description, captures d’écran, catégorie, tarifs et informations sur la confidentialité).
4. Sélectionnez la build TestFlight à promouvoir.
5. Soumettez-la à la révision.

<div id="complete-sua-listagem-no-app-store-connect">
  ### Complétez votre fiche dans App Store Connect
</div>

Replit crée la fiche de votre application dans App Store Connect, mais vous devez encore renseigner les métadonnées requises avant qu&#39;Apple n&#39;accepte une soumission. Les champs suivants sont généralement obligatoires :

* **Nom et sous-titre de l&#39;application**
* **Catégorie** (principale, secondaire facultative)
* **Tarifs et disponibilité** (gratuite ou payante, et régions)
* **URL de la politique de confidentialité** (accessible publiquement)
* **Détails de confidentialité de l&#39;application** (« étiquettes nutritionnelles » de collecte de données)
* **Captures d&#39;écran** (obligatoires)
* **URL d&#39;assistance** (obligatoire)
* **Coordonnées pour l&#39;examen de l&#39;application** (obligatoires)

<Callout type="note">
  Si votre application nécessite une connexion, ajoutez des identifiants de démonstration destinés à l&#39;examen des applications dans App Store Connect afin qu&#39;Apple puisse la tester.
</Callout>

<div id="requisitos-de-privacidade">
  ### Exigences en matière de confidentialité
</div>

Apple exige que vous :

* Fournissiez une **URL publique de politique de confidentialité**
* Déclariez vos pratiques en matière de données dans la section **Confidentialité de l&#39;app** (y compris les SDK et services tiers que vous utilisez)

Si vous faites appel à des services tiers (analyse, paiements, rapports de plantage, publicités), consultez leurs déclarations de confidentialité et reprenez-les dans vos réponses relatives à la Confidentialité de l&#39;app.

<div id="capturas-de-tela">
  ### Captures d&#39;écran
</div>

Les captures d&#39;écran sont obligatoires et influencent fortement la conversion sur l&#39;App Store.

<Tip>
  Utilisez de véritables captures d&#39;écran de votre application. Assurez-vous qu&#39;elles correspondent à la build que vous soumettez.
</Tip>

<div id="motivos-comuns-de-rejeio">
  ### Motifs fréquents de rejet
</div>

| Problème                                                          | Comment l&#39;éviter                                                                               |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Plantages ou bugs évidents                                        | Testez d&#39;abord sur TestFlight et corrigez les problèmes avant l&#39;envoi                      |
| Politique de confidentialité absente                              | Ajoutez une URL publique de politique de confidentialité avant l&#39;envoi                         |
| Les captures d&#39;écran ne correspondent pas à l&#39;application | Importez des captures d&#39;écran de la build actuelle                                             |
| Les réviseurs ne peuvent pas accéder à l&#39;application          | Fournissez des identifiants de démonstration et des instructions dans les notes de révision        |
| Contenu incomplet ou factice                                      | Supprimez les parcours « bientôt disponible » et les écrans incomplets                             |
| Demandes d&#39;autorisation sans contexte                         | Expliquez pourquoi vous avez besoin de la caméra, de la localisation ou d&#39;autres autorisations |

<div id="prazos-esperados">
  ### Délais attendus
</div>

| Étape                                                     | Durée typique                                                                                |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Approbation de l&#39;Apple Developer Program              | Variable (généralement 1 à 2 jours pour les particuliers ; davantage pour les organisations) |
| Traitement de la build dans App Store Connect             | Généralement 10 à 15 minutes                                                                 |
| Examen bêta TestFlight (première build d&#39;une version) | Généralement environ un jour                                                                 |
| Examen de l&#39;App Store                                 | Généralement 1 à 2 jours                                                                     |

<div id="atualizando-seu-aplicativo-aps-o-lanamento">
  ### Mettre à jour votre application après le lancement
</div>

* **Mises à jour de l&#39;interface et du contenu** : republiez pour déployer rapidement les mises à jour.
* **Modifications natives** (par exemple, icônes d&#39;application ou autorisations) : soumettez une nouvelle build à l&#39;App Store.

<div id="lista-de-verificao">
  ## Liste de vérification
</div>

Utilisez cette liste de vérification pour confirmer que vous êtes prêt à chaque étape.

**Avant de partager un aperçu Expo Go :**

* Vous parvenez à exécuter l&#39;application sur un appareil réel via Expo Go
* Votre application ne présente pas de plantages évidents ni de parcours interrompus

**Avant de passer à TestFlight :**

* Votre application est publiée et fonctionne sur Replit
* Vous disposez d&#39;un abonnement à l&#39;Apple Developer Program
* Vous savez si votre compte Apple est individuel ou organisationnel

**Avant de soumettre à l&#39;App Store :**

* Les métadonnées App Store Connect sont complètes (nom, catégorie, régions et URL d&#39;assistance)
* L&#39;URL de la politique de confidentialité est publique et exacte
* Les informations de confidentialité de l’application sont complètes (y compris les services tiers)
* Les captures d&#39;écran sont téléversées et correspondent à la build soumise
* Les coordonnées pour l’examen de l’application sont renseignées
* Les identifiants de démonstration sont fournis (si votre application nécessite une connexion)
