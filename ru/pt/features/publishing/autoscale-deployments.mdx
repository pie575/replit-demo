Autoscale Deployments работают на облачных вычислительных ресурсах, которые масштабируются в обе стороны, чтобы эффективно справляться с сетевым трафиком и рабочей нагрузкой вашего Replit App. Когда приложение загружено, автомасштабирование добавляет серверы для обработки нагрузки. Когда приложение простаивает, число серверов сокращается до нуля — это позволяет экономить.

Autoscale Deployments идеально подходят для следующих сценариев:

* Веб-приложения с переменной нагрузкой и трафиком, например сайты электронной коммерции
* API и сервисы

<div id="recursos">
  ## Возможности
</div>

Autoscale Deployment включает следующие возможности:

* **Автоматическое масштабирование ресурсов**: ресурсы автоматически подстраиваются под характер трафика, что помогает оптимизировать расходы.
* **Собственные домены**: настройте собственный домен или используйте URL вида `<имя-приложения>.replit.app` для доступа к приложению.
* **Настраиваемые лимиты**: задайте максимальное число экземпляров, до которого может масштабироваться опубликованное приложение.
* **Гибкая конфигурация машины**: выберите параметры CPU и RAM, отвечающие потребностям вашего приложения.
* **Мониторинг**: просматривайте логи и отслеживайте состояние опубликованного приложения.

<div id="uso">
  ## Использование
</div>

Открыть Autoscale Deployment можно с помощью инструмента Publishing в Project Editor.

<Accordion title="Как открыть Autoscale Deployment">
  На панели **Tool dock** слева:

  1. Нажмите <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Значок всех инструментов" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools**, чтобы открыть список инструментов Project Editor.
  2. Выберите <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Значок Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Выберите вариант **Autoscale**, а затем — **Set up your published app**.

  Через **строку поиска**:

  1. Нажмите на <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="значок лупы" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> лупу вверху, чтобы открыть инструмент поиска
  2. Введите «Publishing», чтобы найти нужный инструмент, и выберите его в результатах.
  3. Выберите вариант **Autoscale**, а затем — **Set up your published app**.
</Accordion>

<div id="capacidade-da-mquina">
  ## Мощность машины
</div>

Выберите **Edit**, чтобы просмотреть и задать параметры мощности машины. С помощью ползунков выберите конфигурацию CPU и RAM
для каждого экземпляра сервера опубликованного приложения.

Стоимость конфигурации в **compute units** указана в строке **Total per machine**.
Compute unit — это единица измерения облачных вычислительных ресурсов, которая зависит от конфигурации памяти и CPU машины.

Подробнее о расчёте стоимости на основе Compute Units см. в разделе [Compute Units](/ru/pt/billing/about-usage-based-billing#2-compute-units).

<div id="nmero-mximo-de-mquinas">
  ## Максимальное количество машин
</div>

С помощью ползунка задайте максимальное количество машин. Это число — верхняя граница количества серверных
экземпляров, которые автомасштабирование может выделить, определив, что ваше приложение находится под нагрузкой.

В нижней строке показано эквивалентное количество compute units, рассчитанное по следующей формуле:

`Количество машин * compute units на машину`
