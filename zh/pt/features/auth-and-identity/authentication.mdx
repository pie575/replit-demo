Replit Auth 让你能够在应用中打造个性化的用户体验。有了用户账户，你可以保存用户偏好、创建个性化仪表板、构建社交功能、控制高级内容的访问权限、跟踪用户活动——正是这些功能让应用更具吸引力和价值。

Replit Auth 使用 Replit 自身的登录系统——当有人登录你的应用时，其实是在创建或使用已有的 **Replit 账户**。登录页面带有 Replit 品牌标识，登录流程也与 replit.com 全站一致。

<Note>
  **Replit Auth 与 Clerk Auth** — Replit 提供两种身份验证方案。**Replit Auth** (即本页介绍的方案) 使用 Replit 自身的登录系统，因此你的应用用户会使用 Replit 账户登录，并看到带有 Replit 品牌标识的登录页面。**[Clerk Auth](/zh/pt/features/auth-and-identity/clerk-auth)** 则为你的应用提供由 Clerk 驱动的专属身份验证租户，品牌形象可完全自定义，用户账户也独立于 Replit。如果你需要在登录体验中展示自己的品牌，或希望用户账户不与 Replit 绑定，请选择 Clerk Auth。

  如果你的应用已在使用 Replit Auth，请参阅[从 Replit Auth 迁移到 Clerk](/zh/pt/features/auth-and-identity/migrate-auth-to-clerk)，了解自动化迁移流程和测试步骤，以保留对现有应用数据的访问。
</Note>

无需花费数月从零构建身份验证系统，Replit Auth 只需在 Agent 中输入一个提示词，就能为你带来企业级能力。它采用与财富 500 强企业相同的基础设施——Firebase、Google Cloud Identity Platform、reCAPTCHA、Stytch 和 Clearout——内置专业级安全性、欺诈防护和全球化扩展能力。

<div id="por-que-usar-o-replit-auth">
  ## 为什么使用 Replit Auth
</div>

身份验证是一道颇具挑战的难题，甚至有整家公司专门致力于解决它。你的应用的核心目标很可能并不是身份验证，而是你正在构建的那个独特的想法或解决方案。

Replit Auth 提供：

* **零配置** — 在 Agent 中用一个提示词即可添加身份验证
* **与 Replit 账户集成** — 用户使用已有的 Replit 账户登录，无需单独注册
* **内置安全防护** — 依托 Replit 的基础设施，可抵御常见攻击
* **用户管理** — 通过 Auth 面板轻松管理用户
* **数据库集成** — 自动在你的数据库中创建用户记录
* **可自定义的登录页面** — 定制你的应用的登录体验 (带有 Replit 品牌标识)
* **密码重置** — Replit 会代你发送密码重置邮件，你无需自行配置邮件发送服务商
* **推荐计划** — 通过 Replit Auth 注册的用户会被加入你的待处理 Replit 推荐名单
* **开发中和已发布的应用** — Replit Auth 在开发环境 (replit.dev) 以及已发布的应用 (replit.app 和自定义域名) 中都能顺畅运行

<div id="infraestrutura-de-nvel-empresarial">
  ## 企业级基础设施
</div>

Replit Auth 不只是简单的用户管理，而是一套构建在企业级基础设施之上的全托管身份验证解决方案。这一强大组合让你的应用拥有与财富 500 强企业同等的身份验证能力：

* **Firebase 和 Google Cloud Identity Platform** —— 企业级 SLA，依托 Google 久经考验的身份验证基础设施
* **高级安全扫描** —— 集成 reCAPTCHA，自动防御机器人和恶意行为者
* **欺诈防范** —— 由 Clearout 提供技术支持的邮箱验证与校验，杜绝虚假账户
* **多因素身份验证** —— 由 Stytch 企业级身份验证平台支持的安全登录选项
* **全球规模** —— 具备自动伸缩与高可靠性，可支撑数百万用户

有了这一企业级基础，你可以放心专注于打造应用的独特功能，因为为你的身份验证提供支持的，正是守护着数十亿美元规模企业的同一套基础设施。无需耗费数月去集成各种服务，只需在 Agent 中输入一条提示词，即可获得以上全部能力。

<div id="comeando-com-o-replit-auth">
  ## 开始使用 Replit Auth
</div>

实现 Replit Auth 的唯一方式是使用 Agent。只需在提示词中提出使用 Replit Auth 的需求即可：

```
帮我创建一个应用，实现[你的应用创意]，并且要使用 Replit Auth。
```

Agent 会自动配置身份验证所需的全部代码和设置。由于 Agent 已为你处理好所有复杂环节，因此不支持手动实现。

<div id="personalizando-a-pgina-de-login">
  ## 自定义登录页面
</div>

<Frame>
  <img src="/assets/mirror/auth-login-1ee0460c3780.jpg" alt="Auth 配置" width="1920" height="1080" data-path="images/workspace/auth/auth-login.jpg" />
</Frame>

你可以自定义登录页面，使其与应用的品牌风格保持一致：

1. 在项目编辑器中打开 Auth 面板
2. 点击 **Configure**
3. 自定义以下元素：
   * 应用名称
   * 应用图标
   * 登录方式 (Google、GitHub、X、Apple、电子邮件)

更改会立即显示在应用的登录页面上。

<div id="consideraes-de-segurana">
  ## 安全注意事项
</div>

Replit Auth 依托 Replit 的基础设施，内置了针对常见安全威胁的防护。不过，你仍应遵循以下最佳实践：

* 执行敏感操作前，务必在服务器端对用户进行身份验证
* 切勿在代码中存储密码等敏感信息
* 使用环境变量保存任何 API 密钥或密钥信息
* 为用户数据设置适当的访问控制

有关安全的更多信息，请参阅：

* [Replit 内置安全功能](/zh/pt/features/security/overview)
* [vibe coding 安全检查清单](/zh/pt/learn/security-checklist)
* [Secrets 管理](/zh/pt/core-concepts/project-editor/app-setup/secrets)

  ## 推荐
</div>

<div id="soluo-de-problemas">
  ## 故障排查
</div>

<div id="problemas-comuns">
  ### 常见问题
</div>

1. **登录后无法识别用户**
   * 如果遇到问题，可以让 [Replit Agent](/zh/pt/features/agent/overview) 帮你调试身份验证的实现。

2. **自定义图标不显示**
   * 请确认图标 URL 可以访问，且格式受支持 (PNG 或 JPG) 。

3. **新绑定的自定义域名无法使用**
   * 重新发布以更新域名列表 (REPLIT&#95;DOMAINS 环境变量) 。
