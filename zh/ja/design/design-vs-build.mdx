每个 Replit 项目的页眉中都有两个入口：**Design** 和 **Build**。Design 用于塑造软件的外观，Build 则用于让它真正运行起来。两者都会打开同一个项目，因此你设计的内容不会被留在设计工具中。

</Frame>

<div id="design">
  ## 什么是 Design？
</div>

在 [Design](/zh/ja/design/what-is-replit-design) 中，你可以使用 Canvas 根据提示词生成设计画框、探索不同方案，并在将其转化为代码前完善最终设计。

Design 最适合用于以下场景：

* **快速验证想法**：在构建功能前，将应用设计可视化
* **创建精美的网站**：如落地页、作品集、餐厅菜单和活动页面
* **微调设计**：即时调整颜色、布局和内容

<Info>
  设计原型的外观和交互方式都类似真实页面，但尚无法保存数据或连接外部服务。当你满意设计效果后，只需单击一下即可将其转换为完整的应用。以下步骤将说明具体方法。
</Info>

<div id="build">
  ## 什么是 Build？
</div>

Build 可让你的作品成为能够保存数据、允许用户登录并连接其他服务的功能完善的应用。

适合使用 Build 的场景：

* **用户账户**：让用户能够创建账户并登录
* **保存信息**：存储订单、消息和用户设置等数据
* **连接其他服务**：处理付款、发送电子邮件，以及从其他应用导入数据
* **复杂任务**：运营在线商店、管理预约和提供控制台

<div id="designbuild">
  ## 结合使用 Design 和 Build
</div>

Design 和 Build 可在同一项目中配合使用，无需二选一。先从外观入手，再将其打造为完整的应用。

<Steps>
  <Step title="先从 Design 开始">
    从 Design 开始，快速将想法可视化。专注于应用的外观和体验，包括布局、颜色、按钮和用户体验。
  </Step>

  <Step title="改进与迭代">
    根据[建议](/zh/ja/design/explore-suggestions)探索所选画框的新方向，或选择 **Edit** 工具并点击元素，在[可视化编辑器](/zh/ja/design/visual-editor)中进行调整。你还可以[与 Agent 聊天](/zh/ja/design/chat-about-your-design)，描述想要进行的更改。

    <Frame>
      <img src="/assets/mirror/ambient-iq-0989ea31bce7.png" alt="已选中的 Website 画框展示 APEX X1 超级跑车的主视觉。旁边是 Suggested next steps 面板，显示 Explore different approaches、Try different layouts、Explore different vibes 和 Surprise me 等建议标签" width="2000" height="1254" data-path="images/design/replit-design/ambient-iq.png" />
    </Frame>
  </Step>

  <Step title="将设计 Build 为应用">
    当你对设计满意并准备添加实际功能时，在画框中选择**Build…**。你可以创建新的产物，或将设计应用到现有产物。Agent 会保留你的设计，同时添加数据存储、用户账户处理和服务连接等功能。

    <Frame>
      <img src="/assets/mirror/canvas-build-menu-f06b8b8b455f.png" alt="在已选中的 Design 画框（APEX X1 Exact Replica）中打开的 Build 菜单。标题为“Build or apply your designs”，显示用于创建新产物的“Build this design”，以及列出项目 APEX X1 Design System 和 Scroll Hero 网站的 Apply to an existing creation" width="2000" height="1153" data-path="images/replitai/canvas-build-menu.png" />
    </Frame>

    <Note>
      当你尝试为原型添加数据库或高级功能时，Agent 会提示你进行转换。
    </Note>
  </Step>

  <Step title="发布并分享">
    应用构建完成后，将其发布，让任何人都能在线访问。Replit 会处理所有技术基础设施，确保你的应用能够可靠地服务受众。
  </Step>
</Steps>

<div id="section">
  ## 何时该从 Design 或 Build 开始
</div>

<CardGroup cols={2}>
  <Card title="从 Design 开始" icon="paintbrush">
    * 外观是首要考虑因素
    * 想快速验证想法
    * 想探索并比较多种方向
    * 想优先追求速度
  </Card>

  <Card title="从 Build 开始" icon="cube">
    * 功能行为是首要考虑因素
    * 应用从一开始就需要存储数据
    * 用户需要登录
    * 需要连接其他服务
  </Card>
</CardGroup>

<Tip>
  **不确定该选哪个？** 从 Design 开始。它更快，而且之后随时都可以将设计构建为完整的应用。你的工作不会白费——构建后会保留这些内容。反过来也一样：你可以先在 Build 中让应用运行起来，再在 Design 中重新设计外观。
</Tip>

<div id="section-2">
  ## 主要区别
</div>

| 功能       | Design (原型)    | Build (应用)   |
| -------- | -------------- | ------------ |
| **速度**   | 几分钟            | 完整应用约 10 分钟  |
| **数据存储** | 仅视觉呈现 (不保存数据)  | 存储和获取真实数据    |
| **用户账户** | 显示登录界面         | 实际登录功能       |
| **服务集成** | 不支持            | 支付、电子邮件和外部数据 |
