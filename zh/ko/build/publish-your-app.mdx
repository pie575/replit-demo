如果你已在 **Preview** 中构建并测试了应用，现在可能希望让其他人也能使用它。Preview URL 是临时的，仅供开发使用，并非可公开部署的链接。打开 Preview 时，横幅会引导你发布应用，以便安全地与他人分享。

发布会创建一个**生产部署**。这是应用稳定、可分享的版本，可通过专属 URL 运行。开发 Preview 是你构建和测试应用的空间，而生产部署则是访客实际使用的版本。两者彼此独立，因此在再次发布之前，你可以继续工作而不会影响线上应用。

发布不只是将 Preview 设为公开。Replit 会打包你的应用、预配所需资源、验证发布版本，然后将域名路由到生成的部署。

<div id="section">
  ## 发布前
</div>

在按照横幅提示操作或打开 **Publish** 前，请使用 Preview 测试关键用户流程，检查所有支持的屏幕尺寸下的布局，并修复 Agent 报告的错误。发布后，当前版本将供其他人使用，因此请注意不要在应用中包含密钥或私密测试数据。

<div id="section-2">
  ## 发布应用
</div>

<Steps>
  <Step title="打开 Publish 对话框">
    在开发 Preview 横幅中选择 **Publish your app**，即可进入发布流程。或者，在 Build 或 Design 中工作时，您也可以直接打开项目，然后在 Project Editor 右上角选择 **Publish**。

    <Tip>
      您还可以在提示词框中向 Agent 发送以下请求：`Publish this app.` Agent 会准备发布，或引导您完成必要的确认步骤。
    </Tip>
  </Step>

  <Step title="选择域名和访问设置">
    **域名**是访客访问部署时使用的地址。确认自动生成的 `.replit.app` 域名，并可根据需要将其更改为可用名称。然后，选择决定哪些人可以打开应用的**访问级别**：

    * **Public**：拥有链接的任何人都可以使用应用。
    * **Password protected**：访客必须输入共享密码。
    * **Workspace only**：将访问权限限制为工作区成员。
    * **Invite only**：将访问权限限制为选定的人员或群组。

    有关各选项的详细信息，请参阅[应用访问权限](/zh/ko/features/publishing/private-deployments)。

    您还可以启用反馈小部件，让访客在已发布的应用中提交反馈。

    <Frame>
      <img src="/assets/mirror/01-publish-settings-733fb21c48f5.jpg" alt="Gather 的 Publish 对话框，显示生成的域名、公开访问设置、反馈小部件、安全审查和 Publish 按钮" width="1280" height="720" data-path="images/publish-gather/01-publish-settings.jpg" />
    </Frame>

    <PublishingPlanAvailability />
  </Step>

  <Step title="审查安全性并发布">
    选择 **Review security**，即可在发布上线前进行检查。域名、访问权限和安全设置准备就绪后，选择 **Publish**。

    Replit 会预配部署、运行安全检查、构建并打包应用，然后将发布版本推送为线上版本。预配是准备云资源的阶段；构建和打包是将项目转换为可在生产环境中使用的软件包的阶段；最后一步则是将该软件包设为线上版本。在所有阶段完成前，请保持项目处于打开状态。

    <Frame>
      <img src="/assets/mirror/02-publishing-progress-1eda9fe3099f.jpg" alt="Gather 项目，显示发布版本启动后正在进行的发布状态" width="1280" height="720" data-path="images/publish-gather/02-publishing-progress.jpg" />
    </Frame>
  </Step>

  <Step title="打开并验证线上应用">
    发布完成后，Replit 会显示部署状态和公开 URL。不要只在开发 Preview 中测试，也请打开该 URL 测试线上应用，并确认页面和关键功能是否按预期运行。

    <Frame>
      <img src="/assets/mirror/03-published-project-673907839521.jpg" alt="Gather 项目，显示发布后的成功生产状态和线上 URL" width="1280" height="720" data-path="images/publish-gather/03-published-project.jpg" />
    </Frame>

    <Frame>
      <img src="/assets/mirror/04-live-site-c16b8b42d58a.jpg" alt="在公开 replit.app URL 中打开的已发布 Gather 工作坊探索应用" width="1280" height="720" data-path="images/publish-gather/04-live-site.jpg" />
    </Frame>
  </Step>
</Steps>

<div id="section-3">
  ## 了解已发布的项目
</div>

发布之后，项目由两个相互关联的部分组成：一个是你持续构建的可编辑项目，另一个是当前面向访问者提供服务的生产部署。若要查看和管理该生产环境，请打开 **Tools**。

**Publishing** 面板会显示部署概览，包括最新发布是否成功、谁可以访问、在哪里运行、如何托管、可使用哪些资源，以及关联了哪些域名。

**部署类型**决定 Replit 运行应用的方式。**Autoscale** 会随流量变化启动更多机器；**Reserved VM** 会让机器始终保持可用；**Static** 用于提供无需后端运行的文件；**Scheduled** 则按计划运行程序。如需对比这几种类型，请参阅[部署类型](/zh/ko/features/publishing/deployment-types)。

**机器性能**指每个实例可使用的 CPU 和内存。最大机器数量决定了 Autoscale 的扩展上限。请参阅[机器配置](/zh/ko/features/publishing/machine-configuration)。提高资源配置可以提升承载能力，但也可能增加使用费用。

**部署地区**决定应用在哪个区域运行。选择靠近大多数访问者的区域可以降低延迟。请参阅[项目地理位置](/zh/ko/features/publishing/project-geography)。

根据应用和方案的不同，你可以在 **Adjust settings** 或 **Manage** 中访问这些设置，以及生产环境密钥和相关的部署选项。

这些属于可选的生产环境设置。分享普通应用时无需改动，而且部分改动可能会影响可用性或使用费用。

<div id="section-4">
  ### 监控已发布的应用
</div>

**Monitoring** 可帮助你了解生产环境中的情况：*应用是否运行正常、响应是否及时？* 在 **Tools** 面板的 **Replit Cloud** 下打开 **Monitoring**。你可以查看请求数、HTTP 状态、响应时间、CPU 使用率和内存使用率。状态码可反映失败的请求，响应时间可反映响应缓慢的情况。CPU 和内存图表可帮助你识别资源瓶颈。新发布的应用在开始接收流量前，可能几乎没有可显示的数据。有关详细信息，请参阅[监控应用](/zh/ko/features/publishing/monitoring-a-deployment)。

<Frame>
  <img src="/assets/mirror/05-monitoring-2da17ab4d843.jpg" alt="Gather 的 Monitoring 面板，显示应用请求指标以及基础设施的 CPU 和内存图表" width="1280" height="720" data-path="images/publish-gather/05-monitoring.jpg" />
</Frame>

<div id="section-5">
  ### 查看流量与增长
</div>

**Growth** 回答的是另一个问题：*用户是否正在发现并使用你的应用？* 在 **Tools** 面板的 **Replit Cloud** 下打开 **Growth**。基础指标包括访客数、热门页面、引荐来源、国家/地区、浏览器和设备。这些数据可帮助你了解用户从何而来，以及他们对什么感兴趣。[SEO 评分](/zh/ko/features/publishing/seo-rating)衡量已发布页面针对搜索引擎的优化程度。付费套餐的构建者可以使用 [SEO Agent](/zh/ko/features/publishing/seo-agent) 扫描可优化之处。已发布的应用获得流量后，分析数据便会逐渐显示。

<div id="section-6">
  ## 更新已发布的应用
</div>

在 Project Editor 中所做的更改不会自动替换线上版本。通过这种分离方式，你可以在不影响访客的情况下准备和测试更改。在 **Preview** 中测试更改后，准备就绪时选择 **Republish**。重新发布会在同一 URL 上创建新的生产版本，因此无需向访客发送新链接。

重新发布后，请重新打开公开 URL，确认更新后的应用行为是否符合预期。如果发布失败，请先查看发布状态和日志，确定失败的步骤后再重试。
