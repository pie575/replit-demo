Replit предлагает несколько способов установки пакетов и управления ими в приложениях Replit. Вы можете устанавливать пакеты через [Shell](/ru/ja/features/workspace-tools/shell), поручить это [Agent](/ru/ja/features/agent/overview/) либо позволить Replit автоматически находить и устанавливать недостающие зависимости при запуске приложения.

<div id="shell">
  ## Установка пакетов через Shell
</div>

Откройте инструмент **Shell** в редакторе проекта и выполните команду для менеджера пакетов используемого вами языка:

<CodeGroup>
  ```bash Node.js (npm) theme={null}
  npm install <package-name>
  ```

  ```bash Node.js (pnpm) theme={null}
  pnpm add <package-name>
  ```

  ```bash Python (poetry) theme={null}
  poetry add <package-name>
  ```

  ```bash Python (pip) theme={null}
  pip install <package-name>
  ```

  ```bash Ruby theme={null}
  bundle add <gem-name>
  ```
</CodeGroup>

Кроме того, для установки пакетов в любом из поддерживаемых языков можно использовать [универсальный менеджер пакетов (UPM)](https://github.com/replit/upm/) от Replit:

```bash theme={null}
upm add <package-name>
```

Чтобы установить определённую версию:

```bash theme={null}
upm add 'flask==2.3.3'
```

Полный список поддерживаемых языков и пакетных менеджеров см. в разделе [UPM: поддерживаемые языки](https://github.com/replit/upm/#supported-languages).

<div id="agent">
  ## Установка пакетов с помощью Agent
</div>

Вы можете попросить [Agent](/ru/ja/features/agent/overview/) установить пакеты прямо в чате. Например:

* «Установи пакет axios»
* «Добавь в проект Flask и SQLAlchemy»
* «Настрой TailwindCSS»

Agent установит пакеты с помощью подходящего для проекта менеджера пакетов и обновит соответствующие файлы конфигурации.

<div id="section">
  ## Автоматическое определение импортов
</div>

Replit автоматически анализирует ваш код при каждом нажатии **Run** и проверяет, не отсутствуют ли зависимости. Если в коде импортируется пакет, который ещё не установлен, Replit обнаружит это и автоматически установит его последнюю версию.

Например, если добавить `import flask` в `main.py`, то при следующем нажатии **Run** в **Console** появится сообщение об установке **Flask**.

<Note>
  Автоматическое определение импортов настраивается параметром `packager.features.guessImports` в файле [.replit](/ru/ja/features/project-setup/configuration#replit-file).
</Note>

<div id="section-2">
  ### Переопределение автоматического обнаружения
</div>

Если пакет определён неверно или нужна конкретная версия, выполните нужную команду установки в Shell. Например:

```bash theme={null}
upm add 'flask==2.3.3'
```

Кроме того, в файле [.replit](/ru/ja/features/project-setup/configuration#replit-file) можно исключить отдельные пакеты или пути из автоматического обнаружения:

<div id="python">
  ## Менеджер пакетов Python
</div>

При создании Python-приложения Replit менеджером пакетов по умолчанию становится **poetry**. Это значит, что `pip install` не управляет зависимостями. Вместо этого используйте в Shell команду `poetry add <package>` или `upm add <package>`.

<div id="poetrypip">
  ### Переход с poetry на pip
</div>

Если вы предпочитаете использовать `pip`, выполните следующие шаги:

<Steps>
  <Step>
    Откройте Shell и выполните:

    Удалите lock-файл, чтобы система управления пакетами переключилась на pip:

    ```bash theme={null}
    rm poetry.lock
    ```
  </Step>

  <Step title="Перенос зависимостей">
    Перенесите зависимости из раздела `[tool.poetry.dependencies]` файла `pyproject.toml` в `requirements.txt`. Например, `flask = "^3.0.2"` превращается в `flask>=3.0.2,<4`.
  </Step>

  <Step title="Очистка pyproject.toml">
    Удалите разделы `[tool.poetry...]` из `pyproject.toml`.
  </Step>
</Steps>

После этих изменений система управления пакетами будет использовать `pip` для всех последующих операций, а автоматическое определение импортов продолжит работать как обычно.

<div id="nixdependencies">
  ## Системные зависимости через Nix
</div>

Replit поддерживает все языки программирования благодаря интеграции с [Nix](https://nixos.org/). Если вам нужны системные зависимости, выходящие за рамки стандартных языковых пакетов, добавьте их в файл [replit.nix](/ru/ja/features/project-setup/configuration#replit-nix-file).

<div id="nix">
  ### Пакеты Nix
</div>

Отредактируйте файл `replit.nix` напрямую, чтобы добавить системные зависимости. Найти доступные пакеты можно на [search.nixos.org](https://search.nixos.org/packages).

<div id="section-3">
  ### Модули
</div>

Модуль объединяет поддержку языка программирования, форматировщика и пакетного менеджера. Он служит основой приложения Replit. При создании приложения Replit из шаблона или репозитория GitHub необходимые модули устанавливаются автоматически.

Модули и другие настройки Nix можно изменить в файле [.replit](/ru/ja/features/project-setup/configuration#replit-file).

<div id="section-4">
  ## Настройка packager
</div>

В файле [.replit](/ru/ja/features/project-setup/configuration#replit-file) можно тонко настроить поведение управления пакетами:

| Настройка                             | Описание                                                              | По умолчанию               |
| ------------------------------------- | --------------------------------------------------------------------- | -------------------------- |
| `packager.language`                   | Язык, используемый для операций с пакетами                            | Определяется автоматически |
| `packager.features.guessImports`      | Автоматически находить и устанавливать недостающие пакеты при запуске | `true`                     |
| `packager.features.packageSearch`     | Включить поддержку поиска пакетов                                     | `true`                     |
| `packager.features.enabledForHosting` | Требовать установку пакетов при хостинге                              | `false`                    |
| `packager.afterInstall`               | Команда, выполняемая после установки пакетов                          | —                          |
| `packager.ignoredPaths`               | Пути, игнорируемые при обнаружении импортов                           | `[]`                       |
| `packager.ignoredPackages`            | Пакеты, исключённые из автоматического обнаружения                    | `[]`                       |
