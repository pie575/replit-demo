Agent prend en charge quatre types d&#39;intégrations pour vous permettre de passer rapidement de l&#39;idée à l&#39;application :

* **Gérées par Replit** : intégrations natives qui fonctionnent automatiquement. Créez une application et Agent peut les utiliser immédiatement.
* **Connecteurs** : intégrations propriétaires prises en charge par Replit. Connectez-vous une seule fois. Agent peut lire et écrire dans ces services directement depuis le Chat — récupérer des données, créer des enregistrements, envoyer des messages — et les exploiter dans toutes vos applications.
* **Intégrations externes** : services tiers de confiance avec lesquels vous pouvez développer. Demandez à Agent de les configurer ; vous fournirez les clés d&#39;API.
* **Services d&#39;Agent** : API tierces payantes qu&#39;Agent utilise en arrière-plan — aucune clé d&#39;API nécessaire. L&#39;utilisation est déduite de vos crédits Replit.

<Note>
  **Disponibilité selon le plan** : la plupart des connecteurs nécessitent un abonnement Core, Pro ou Enterprise, et certains sont accessibles avec le plan gratuit. Le catalogue de connecteurs de votre workspace indique ceux que vous pouvez utiliser avec votre plan actuel. Les créateurs du plan gratuit peuvent toujours utiliser les intégrations gérées par Replit, comme les bases de données, l&#39;authentification et bien d&#39;autres.
</Note>

<div id="primeiros-passos">
  ## Premiers pas
</div>

Pour utiliser une intégration, mentionnez le service ou la fonctionnalité dont vous avez besoin. Par exemple :

<AiPrompt>
  Create a web app that uses Stripe to accept payments and SendGrid to send confirmation emails
</AiPrompt>

Agent détecte automatiquement ces mots-clés et met en place le code et la configuration nécessaires.

<div id="deixe-o-agent-sugerir-um-conector">
  ### Laissez Agent suggérer un connecteur
</div>

Parfois, plusieurs services permettent d&#39;accomplir la même tâche, comme stocker des fichiers ou envoyer des e-mails. Lorsque vous demandez une fonctionnalité sans préciser de fournisseur, Agent affiche une courte liste de connecteurs adaptés. Choisissez celui qui vous convient.

Sélectionnez un fournisseur et connectez-vous une seule fois pour relier votre compte. Agent tient compte de votre choix pendant la création. Vous pouvez aussi indiquer un service précis par son nom pour passer directement outre la liste.

<div id="configurando-um-app-oauth-com-o-replit">
  ### Configurer une application OAuth avec Replit
</div>

<Note>
  **Enterprise uniquement** : la configuration d&#39;une application OAuth personnalisée nécessite un abonnement Enterprise.
</Note>

Avec le plan Enterprise, vous pouvez utiliser votre propre application OAuth pour un connecteur au lieu de celle proposée par défaut par Replit. Votre organisation devient ainsi propriétaire du client OAuth, affiche sa propre marque sur l&#39;écran de consentement et contrôle les scopes exacts que vos créateurs peuvent demander.

Pour configurer un connecteur avec votre propre application OAuth, trois éléments vous seront fournis par le fournisseur : un **Client ID**, un **Client Secret** et les **scopes** que vous souhaitez autoriser. Vous devez également enregistrer l&#39;URL de callback de Replit auprès du fournisseur afin que l&#39;authentification puisse aboutir.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Boîte de dialogue de configuration OAuth du connecteur avec les champs Client ID, Client Secret et Scopes du connecteur, et une URL de redirection définie sur https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Créez une application OAuth chez votre fournisseur">
    Connectez-vous à la console développeur ou aux paramètres d&#39;administration du fournisseur et créez une nouvelle application OAuth 2.0. Les fournisseurs nomment cette étape différemment : recherchez des options telles que **Créer une application OAuth**, **Enregistrer une application** ou **Créer des identifiants client**.
  </Step>

  <Step title="Définissez l'URL de redirection">
    Lorsque le fournisseur demande un **URI de redirection autorisé** (parfois appelé **URL de callback** ou **URL de redirection**), saisissez :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    C&#39;est vers cette URL que le fournisseur renvoie les créateurs sur Replit après qu&#39;ils ont autorisé l&#39;application. Elle doit correspondre exactement : les barres obliques finales, le protocole et le sous-domaine comptent. Si vous ajoutez plusieurs URI de redirection, celui-ci doit en faire partie.
  </Step>

  <Step title="Copiez le Client ID et le Client Secret">
    Une fois l&#39;application créée, le fournisseur affiche un **Client ID** et un **Client Secret**.

    * **Client ID** : identifiant public de votre application OAuth. Il peut être affiché sans risque dans des URL et dans du code côté client.
    * **Client Secret** : valeur confidentielle qui prouve que la requête provient bien de votre application. Traitez-la comme un mot de passe : ne la commitez jamais dans un dépôt et ne la partagez jamais publiquement. Replit la stocke de manière sécurisée pour vous.

    Certains fournisseurs n&#39;affichent le client secret qu&#39;une seule fois, au moment de la création. Copiez-le immédiatement et conservez-le en lieu sûr jusqu&#39;à ce que vous le colliez dans Replit.
  </Step>

  <Step title="Choisissez vos scopes">
    Les **scopes** sont des autorisations qui définissent ce que votre application OAuth peut lire ou écrire au nom du créateur. Chaque fournisseur publie sa propre liste de scopes dans la documentation de son API.

    Lors de la configuration du connecteur dans Replit, les scopes que vous saisissez doivent **correspondre exactement** (caractère par caractère, préfixes d&#39;URL inclus) à ceux que vous avez enregistrés chez le fournisseur. Causes fréquentes d&#39;erreurs de non-correspondance :

    * Absence du préfixe d&#39;URL complet (par exemple, `https://www.googleapis.com/auth/drive.file` au lieu de `drive.file`).
    * Espaces superflus ou virgules en fin de valeur.
    * Demande dans Replit d&#39;un scope non activé dans l&#39;application du fournisseur.

    Commencez par les scopes minimaux dont vos créateurs ont besoin et ajoutez-en d&#39;autres plus tard si nécessaire : la plupart des fournisseurs permettent de mettre à jour les scopes sans recréer l&#39;application.
  </Step>

  <Step title="Configurez le connecteur dans Replit">
    Sur la page **Connecteurs** de votre organisation, sélectionnez **Ajouter une nouvelle intégration**, choisissez le service, puis collez le **Client ID**, le **Client Secret** et les **Scopes** fournis par le fournisseur. Sélectionnez **Configurer** pour enregistrer.
  </Step>
</Steps>

<Note>
  Si l&#39;authentification échoue après la configuration, vérifiez que l&#39;URL de redirection enregistrée auprès du fournisseur correspond exactement à `https://replit.com/connectors/oauth/callback` et que chaque scope saisi dans Replit est également autorisé dans l&#39;application du fournisseur.
</Note>

<div id="depurando-conectores">
  ## Débogage des connecteurs
</div>

Vous rencontrez des difficultés pour connecter un service ? Ces guides présentent les erreurs les plus courantes et la façon de les corriger.

<AccordionGroup>
  <Accordion title="Google Workspace : &#x22;This app is blocked&#x22;">
    Si le message **« This app is blocked »** s&#39;affiche lors de la connexion à Google Drive, Docs, Sheets, Calendar ou Gmail, le Google Workspace de votre organisation restreint probablement les applications OAuth tierces. Consultez le guide de dépannage complet pour résoudre ce problème.

    [Résoudre « This app is blocked » pour les connecteurs Google](/fr/pt/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce : &#x22;Connection Expired&#x22;">
    Si votre connecteur Salesforce cesse de fonctionner en affichant l&#39;erreur **« Connection Expired »**, la politique de refresh token de votre organisation dans Salesforce est probablement configurée pour faire expirer les tokens au bout d&#39;une certaine durée. Consultez le guide de dépannage complet pour mettre à jour les paramètres de votre Connected App.

    [Corriger les erreurs de connexion expirée Salesforce](/fr/pt/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
