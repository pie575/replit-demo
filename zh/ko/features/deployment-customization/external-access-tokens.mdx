---
title: "外部访问令牌"
description: "允许 CI 流水线、Webhook 和其他自动化服务无需登录即可访问私有 Replit App。"
---

外部访问令牌是为特定 Replit App 签发的持有者令牌。
它允许 CI 流水线、Webhook、运行状况检查程序、Slack 机器人和内部脚本等自动化
服务访问受[私有开发 URL](/zh/ko/features/publishing/private-deployments)或
[私有部署](/zh/ko/features/publishing/private-deployments)保护的 App。

请像保管密码一样保管每个令牌。任何持有令牌的人都可以访问该 App，直到令牌过期或
被撤销。

<Note>
  为 deployment 选择私有访问权限后，即可使用外部访问令牌。
  无需工作区选择加入。在 Enterprise 工作区中，只有
  工作区管理员可以管理令牌。
</Note>

<div id="section">
  ## 何时应使用令牌
</div>

当浏览器*外部*的服务需要调用私有 Replit App 时，请使用外部访问
令牌。常见场景包括：

* GitHub Actions 工作流在每次提交后对开发 URL 运行冒烟测试。
* 可用性监控服务 (Better Stack、Pingdom、
  UptimeRobot) 调用已发布 App 的健康检查端点。
* 向私有部署发送 POST 请求的 Webhook 接收器：Stripe、Slack、GitHub。
* 调试时从团队成员的计算机运行 `curl` 或 `fetch` 调用。

外部访问令牌专为 **API 流量**设计，而非用于在浏览器中打开界面。
单页应用 (Vite、Next.js 等) 会通过后续请求加载 JavaScript 包，但这些请求不包含令牌，因此会失败。
如需交互式浏览，请正常登录。

<div id="section-2">
  ## 令牌环境
</div>

每个令牌都绑定到一个环境。

| 环境            | 生效位置                                | 使用目的               |
| :------------ | :---------------------------------- | :----------------- |
| `Development` | App 工作区的开发 URL (`*.replit.dev`)     | 访问开发期间正在运行的 Repl 时 |
| `Production`  | App 的已发布部署 (`*.replit.app` 和自定义域名)  | 从外部服务访问私有部署时       |

`Production` 令牌在重新发布后仍会保留，包括发布新版本后。
在以下情况下，Replit 会撤销令牌：

* 取消发布部署时。
* 删除部署时。
* 将 App 的访问权限从私有更改为公开时。

令牌过期或被你手动撤销后，也会失效。

<div id="section-3">
  ## 创建外部访问令牌
</div>

<Steps>
  <Step>
    打开要公开的应用，然后打开**发布**工具。
  </Step>

  <Step>
    选择**调整设置**，展开重新部署选项。
  </Step>

  <Step>
    在**安全**部分找到**外部访问令牌**。
  </Step>

  <Step>
    选择**创建访问令牌**，然后填写以下内容。

    * **标签** (可选) ：用于日后识别令牌的简短名称，例如 `CI` 或
      `Stripe webhook`。最多可输入 120 个字符。
    * **环境**：根据调用服务需要从何处访问应用，选择 `Development`
      或 `Production`。
    * **过期时间**：从 `1小时`、`24小时`、`7天`、`30天`、`3个月`、`1年`
      或 `5年`中选择有效期。请选择适合任务的最短有效期。
      不提供“永不过期”选项。
  </Step>

  <Step>
    选择**创建**。
  </Step>
</Steps>

Replit **仅显示一次**令牌。请立即复制。关闭对话框后，
将无法再次查看令牌。如果丢失令牌，请撤销该令牌并
创建新令牌。

令牌显示页面提供两种复制方式。

* **复制查询参数** - 复制可附加到 URL 的
  `?project-protection-bypass=<token>`。适合进行简单的 `curl`
  验证。
* **仅复制令牌** - 复制适合通过 `Authorization: Bearer` 标头发送的原始
  令牌。

<Info>
  创建第一个令牌时，如果应用的外部访问尚未启用，系统会自动开启。
  如果没有保护措施，令牌就无从绕过。
</Info>

<div id="section-4">
  ## 使用令牌
</div>

请通过以下两种方式之一提供令牌。

<div id="authorization">
  ### Authorization 标头 (推荐)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

此方法几乎适用于所有场景，包括 Webhook、CI 脚本和后端之间的调用等。
令牌不会出现在记录 URL 的日志中，也不会留在浏览器历史记录中。

<div id="section-5">
  ### 查询参数
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

仅在无法设置请求头时才使用查询参数方式，例如服务只能接收 URL 时。
包含令牌的 URL 很容易被记录在代理日志、Shell 历史记录和截图中，因此应尽可能优先使用请求头方式。

<div id="section-6">
  ## 管理现有令牌
</div>

**外部访问令牌**部分按创建时间从新到旧列出你为应用创建的所有令牌，并显示其标签、环境、创建日期、到期日期和撤销状态。
令牌的完整值仅在创建时显示，因此每行会显示令牌末尾的几个字符，方便你区分不同令牌。

你只能查看*自己*创建的令牌。即使你拥有该应用，其他协作者也只能查看自己创建的令牌。

<div id="section-7">
  ## 撤销令牌
</div>

令牌不再需要或疑似泄露时，请立即撤销。请按以下步骤操作。

<Steps>
  <Step>
    在应用的发布设置中，打开 **外部访问令牌** 部分。
  </Step>

  <Step>
    在列表中找到令牌，然后选择垃圾桶图标。
  </Step>

  <Step>
    确认撤销。
  </Step>
</Steps>

撤销操作**立即生效且不可恢复**。使用该令牌的流量将在数秒内开始被拒绝。如果需要再次访问，请创建新令牌。

您只能撤销自己创建的令牌。将协作者从工作区中移除后，他们为该应用创建的令牌也会自动被撤销。

<div id="section-8">
  ## 安全保管令牌
</div>

外部访问令牌属于凭据。请像对待 API 密钥或密码一样谨慎
保管。

<div id="section-9">
  ### 应做事项
</div>

* **将令牌存储在密钥管理工具中**，例如 GitHub Actions 密钥、CI
  服务商的保险库、云服务商的密钥存储或密码
  管理器。切勿将其提交到仓库。
* 尽可能**使用有效期较短的令牌**。用于一次性集成的 7 天
  令牌比被遗忘的 5 年令牌更安全。
* **为所有令牌添加标签。** 这样日后就能了解令牌的用途，
  以及是否仍在使用。没有标签的令牌最先
  泄露，最后才被撤销。
* **为每个使用方签发独立令牌。** 每个 CI 作业一个、每个 webhook
  来源一个、每次运行状态检查一个。如果发生泄露，或不再需要某个
  服务商，只需撤销对应的令牌。
* 为防止令牌通过 URL 日志、浏览器历史记录和 referer 标头泄露，
  相比查询参数，**应优先使用 `Authorization` 标头**。
* 如果令牌可能已暴露，例如出现在泄露的日志、公开仓库提交、屏幕共享或离职员工的笔记本电脑中，
  **请立即撤销**。撤销会立即
  生效，之后再签发替代令牌。

<div id="section-10">
  ### 不要这样做
</div>

* **不要在团队成员或服务之间共享令牌。** 如果两个系统共用一个
  令牌，就无法在不危及一方的情况下撤销另一方的令牌。
* **不要将令牌粘贴到聊天、电子邮件、截图或议题跟踪器中。** 这些
  渠道可能会以意想不到的方式被存储、索引和共享。
* **不要将令牌放入客户端代码中** - 例如浏览器应用、移动应用和
  桌面二进制文件。任何部署到用户设备上的内容都应视为
  公开内容。
* **不要将令牌用于浏览器会话。** 令牌可用于 API 调用，
  但不能用于在浏览器标签页中加载 SPA。
  此时请使用常规的 Replit 登录方式。
* **不要默认选择 5 年有效期。** 请根据使用方实际需要访问的
  时长设置有效期。

<div id="section-11">
  ## 故障排除
</div>

<Accordion title="生产令牌突然失效">
  生产令牌在正常重新发布的过程中会保持有效。请检查令牌是否已过期或被撤销。
  还请检查是否取消发布或删除了部署，或者是否将应用从私有改为公开。如果应用
  不再有私有部署，请重新以私有方式发布。然后创建新令牌。已过期或被撤销的令牌
  无法恢复。
</Accordion>

<Accordion title="令牌在 `curl` 中有效，但浏览器仍显示登录页面">
  外部访问令牌用于 API 流量，而非浏览器会话。当单页应用在浏览器中加载时，
  初始 HTML 请求可以通过查询参数传递令牌，但后续对 JavaScript 包、CSS 和 API 的请求
  不会包含令牌，因此会被拒绝。若要以交互方式使用应用，请正常登录 Replit。
</Accordion>

<Accordion title="丢失了令牌，还能再次查看吗？">
  不能。Replit 仅在创建时显示一次令牌。列表视图会显示元数据 (标签、环境、
  到期日期和末尾几个字符) ，但不会显示完整的令牌值。如果丢失了令牌，请撤销
  该令牌并创建新令牌。
</Accordion>
