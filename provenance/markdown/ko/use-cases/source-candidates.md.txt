# 후보자 소싱하기

> 직무 기술서를 기반으로 GitHub에서 일치하는 엔지니어를 찾고, 이미 Ashby에 있는 사람은 건너뛰고, 아웃리치 초안을 작성합니다.

Ashby는 이미 인바운드 지원자를 심사합니다. 이 워크플로는 아웃바운드용입니다:
Drive의 직무 기술서를 읽고, GitHub에서 일치하는 엔지니어를 찾고, 이미 Ashby에
있는 사람은 건너뛰고, 여러분이 보낼 아웃리치 초안을 작성합니다. Agent는
새로운 사람을 짧은 적합성 이유와 후보자에 대한 초안과 함께 소싱됨으로
기록합니다. 여러분이 검토하고 발송합니다. 이것만으로 채용 결정을 내리지
마세요.

## 다음과 같은 경우에 적합합니다

* 인바운드 물량이 너무 적을 때 소싱된 목록이 필요한 테크니컬 리크루터.
* 하루 종일 검색만 하지 않고도 GitHub로 매칭된 엔지니어가 필요한 채용 매니저.

## 시작하기 전에

필수 조건과 우대 조건이 구분된 직무 기술서를 준비하세요. Drive, GitHub, Ashby를
연결하세요. 지역, 시니어리티, 원하는 인원수를 말해주세요. 이것만으로 채용
결정을 내리지 마세요.

<AiPrompt>

  마세요. 새로운 사람은 노트와 초안을 후보자에 담아 소싱됨으로 Ashby에
  추가해 주세요.
</AiPrompt>

## 예상 결과

Agent가 직무 기술서를 읽고, GitHub를 검색하고, 이미 Ashby에 있는 사람은
건너뛰고, 초안이 담긴 숏리스트를 반환합니다. 여러분이 검토하고 발송합니다.
첫 결과는 노이즈가 많을 수 있습니다. 확인 후 필수 조건을 조정하세요.
목록에서 GitHub 프로필 세 개를 열어 필수 조건과 일치하는지 확인하고, 무엇을
보내기 전에 그 사람들이 이미 Ashby에 없는지 확인하세요.

## 문제 해결

* **숏리스트에 노이즈가 많음:** 첫 결과를 본 후 필수 조건과 우대 조건을 조정하세요. 특정 언어나 저장소 유형의 최근 커밋을 요청하고, 현재 고객이나 경쟁사 직원처럼 보이는 사람은 제외하세요.
* **이미 Ashby에 있는 사람이 계속 나타남:** Ashby가 올바른 워크스페이스에 연결되어 있는지, Agent가 표시 이름뿐 아니라 이메일이나 GitHub 사용자명으로 매칭하고 있는지 확인하세요.
* **아웃리치가 발송됨:** 이 워크플로는 초안만 작성해야 합니다. 무언가 발송되었다면 루틴을 중지하고 후보자에게 이메일이나 메시지를 절대 보내지 말라고 Agent에게 알려주세요.
