Le Task board offre un espace unique pour examiner, démarrer, suivre et appliquer les tâches d’Agent. Utilisez-le lorsqu’Agent divise une demande importante en plusieurs tâches, lorsque vous souhaitez exécuter des tâches en arrière-plan ou lorsque vous devez vérifier les modifications déjà apportées à un projet.

Les tâches sont organisées en colonnes selon leur statut. Le tableau affiche ce qu’Agent a planifié, ce qui est en cours, ce qui est prêt à être examiné et ce qui a déjà été appliqué.

Chaque tâche se déplace de gauche à droite au fur et à mesure de son avancement :

* **Drafts** : tâches planifiées par Agent, mais pas encore commencées
* **Active** : tâches qu’Agent est en train de réaliser, y compris celles en attente en raison de la limite de tâches actives
* **Ready** : tâches terminées par Agent et en attente d’examen
* **Done** : tâches terminées, archivées ou annulées

<div id="drafts">
  ## Drafts
</div>

Les **Drafts** sont des tâches qu’Agent a planifiées, mais dont le build n’a pas encore commencé. Chaque brouillon comprend un titre, une description et un plan détaillé étape par étape.

Utilisez les Drafts pour examiner l’approche proposée par Agent avant de commencer une tâche. Vous pouvez consulter le plan, demander à Agent de le modifier ou démarrer le travail lorsque vous êtes prêt.

Les Drafts sont utiles lorsque vous souhaitez planifier des fonctionnalités plus importantes avant de valider des tâches en arrière-plan. Par exemple, Agent peut diviser un projet d’intégration en brouillons distincts pour l’authentification, la configuration du profil, l’UI du tableau de bord et les dernières étapes du déploiement.

<div id="active">
  ## Active
</div>

Lorsque vous approuvez une tâche, elle passe dans la colonne **Active** et Agent commence à la build. Chaque tâche s’exécute dans une copie indépendante du projet, sans incidence sur la version principale tant que vous n’appliquez pas les modifications.

Certaines tâches dépendent d’autres tâches. Par exemple, la création d’un tableau de bord peut nécessiter que le schéma de la base de données soit terminé au préalable. Les tâches dépendantes restent à l’état **Queued** jusqu’à ce que leurs prérequis soient remplis. Lorsque la limite de tâches actives en arrière-plan de votre forfait est atteinte, les tâches sont également placées en file d’attente.

</div>

Lorsqu’une tâche termine le build, elle passe à l’état **Ready**. Cela signifie que la tâche est terminée, mais qu’aucune modification n’a encore été apportée à la version principale.

Vous pouvez appliquer les modifications de deux façons :

* **Depuis le fil** : ouvrez le fil de la tâche et sélectionnez **Appliquer les modifications à la version principale** pour intégrer les modifications au projet, ou sélectionnez **Supprimer** pour les abandonner
* **Depuis le tableau** : sélectionnez le menu à trois points de la carte d’une tâche à l’état Ready, puis sélectionnez **Appliquer les modifications**

</div>

Utilisez le Task board lorsque votre projet comporte de nombreuses tâches en cours. Recherchez des tâches par titre ou numéro, filtrez les brouillons et utilisez le mode édition pour gérer plusieurs tâches à la fois.

Par exemple, recherchez une tâche par son numéro lorsqu&#39;elle est mentionnée dans un fil de discussion, une revue ou une conversation Slack. Filtrez les brouillons si vous souhaitez vous concentrer uniquement sur les tâches planifiées sans passer en revue les tâches actives ou terminées.

Pour les tâches de suivi suggérées, consultez [Tâches de suivi](/fr/ko/features/agent/follow-up-tasks).

<div id="section-2">
  ## Renommer une tâche
</div>

Lorsque le périmètre évolue, il peut devenir difficile d’identifier d’un coup d’œil les tâches en cours depuis longtemps. Pour renommer une tâche, ouvrez le menu à trois points de la carte (dans la barre latérale de la liste des tâches ou dans le Task board), puis sélectionnez **Renommer**. Saisissez un titre plus explicite, puis sélectionnez **Enregistrer**.

Renommer une tâche modifie uniquement la façon dont elle apparaît pour vous et les membres de votre équipe. Les tâches déjà effectuées par Agent, l’historique des tâches et les modifications en attente restent inchangés.

<div id="section-3">
  ## Paramètres de chaque tâche
</div>

Chaque tâche possède son propre menu déroulant de paramètres à côté de son titre. Ouvrez-le pour définir la façon dont Agent finalise la tâche et dont les résultats sont appliqués au projet :

* **Appliquer automatiquement les modifications** (Drafts et Active) : applique immédiatement les modifications à la version principale dès que la tâche est prête, sans attendre de révision.
* **Approuver automatiquement le plan** (Drafts) : approuve automatiquement le plan proposé par Agent pour la tâche et lance le build.
* **Appliquer les modifications** (Ready) : applique les modifications de la tâche terminée à la version principale.
* **Renommer** : modifie le titre affiché sur la carte.
* **Examiner les modifications** (Ready) : ouvre directement le diff de la tâche prête.
* **Annuler** : arrête la tâche ou supprime le brouillon.

L’application automatique et l’approbation automatique sont des actions rapides à effectuer une seule fois, et non des bascules qui restent activées. Le menu conserve une largeur fixe afin que les libellés ne changent pas de position lorsque vous ouvrez plusieurs tâches.
