<div id="section">
  ## Добавление заголовков ответа
</div>

Пользовательские **заголовки ответа** позволяют добавлять директивы HTTP-заголовков к запросам, которые соответствуют определённым путям.
Заголовки ответа — это пары «имя — значение», которые указывают браузеру, как обрабатывать запрошенное содержимое.

Например, с помощью заголовка `Access-Control-Allow-Origin` можно задать, каким доменам разрешён доступ к этой странице.
Чтобы создать такую запись, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App.

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

Этот заголовок ответа содержит следующие параметры:

* **path**: шаблон пути URL, которому соответствует запрошенный ресурс
* **name**: имя HTTP-заголовка
* **value**: значение HTTP-заголовка

В файл `.replit` можно добавить несколько записей `deployment.responseHeaders`.

Чтобы изменения конфигурации вступили в силу, опубликуйте Replit App заново.

<div id="404">
  ## Создание собственной страницы 404
</div>

Собственная страница 404 отображается, когда пользователь запрашивает URL-путь, который не соответствует ни одному файлу или правилу опубликованного приложения.

Чтобы добавить собственную страницу 404, создайте в корневом каталоге Replit App файл с именем `404.html` и заполните его содержимым страницы.

При переходе по несуществующему URL-пути пользователь увидит отрисованный HTML вашей страницы 404.

<div id="url">
  ## Определение перезаписи URL-путей
</div>

Вы можете задать правила перезаписи URL, которые изменяют URL-путь запроса до того, как Replit App обработает его.
Исходный URL по-прежнему отображается в браузере, но сервер загружает ресурс, указанный в правиле перезаписи.

Например, можно указать, что все запросы, начинающиеся с `/app`, загружают содержимое файла `/app/index.html`.
Чтобы создать такую запись, добавьте следующее в файл `.replit` в корневом каталоге Replit App.

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**: шаблон URL-пути, которому соответствует запрашиваемый ресурс
* **to**: переписанный путь к файлу внутри Static Deployment

В файле `.replit` можно указать несколько записей `deployment.rewrites`.
Сервер обрабатывает записи в порядке их перечисления и игнорирует дубликаты.

Чтобы изменения конфигурации вступили в силу, необходимо повторно опубликовать Replit App.

В следующих разделах описаны ограничения правил перезаписи URL.

<div id="section-3">
  ### Сопоставление путей
</div>

К параметрам `from` и `to` в правилах перезаписи применяются следующие ограничения:

* если `*` не указан, путь должен совпадать точно
* `*` соответствует всей оставшейся части пути
* `*` допускается только в конце пути
* если `*` указан в параметре `from`, его можно использовать и в параметре `to`, чтобы подставить совпавшую часть пути

Например, предположим, что файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

Когда пользователь переходит по пути `/v1/about-us.html`, правило перезаписи возвращает файл, расположенный по пути `/v2/about-us.html`.

<div id="section-4">
  ### Затенение
</div>

Затенение возникает, когда правило перезаписи совпадает с URL-путём, которому также соответствует файл внутри Static Deployment.
В этом случае облачный сервер игнорирует правило перезаписи и отдаёт файл напрямую.

Например, предположим, что опубликованное приложение содержит следующие файлы:

* `index.html`
* `about.html`

А файл `.replit` содержит такое правило перезаписи:

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

Когда пользователь открывает `/register.html`, сервер перенаправляет запрос на `/index.html` и отдаёт этот файл.
Однако если пользователь открывает `/about.html`, сервер игнорирует правило перезаписи и отдаёт файл `about.html`, поскольку такой файл существует в Static Deployment.

<div id="section-5">
  ### Ограничения по домену
</div>

Перезапись работает только для запросов к домену по умолчанию Static Deployment и может перенаправлять только на файлы внутри этого Static Deployment.
