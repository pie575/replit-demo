作为 Enterprise 管理员，你可以配置组织范围内的设置，控制团队成员与代码、部署及外部平台的交互方式。这些设置有助于维护安全标准、保护知识产权，并确保符合企业政策。

<div id="accessing-privacy-settings">
  ## 访问隐私设置
</div>

<Accordion title="如何访问隐私设置">
  1. 进入你的 Enterprise workspace
  2. 选择 **设置**
  3. 选择 **Advanced** 查看所有可用设置
</Accordion>

<div id="privacy-settings">
  ## 隐私设置
</div>

隐私设置可控制应用在组织内的发布和访问方式。

<CardGroup cols={2}>
  <Card title="私有部署" icon="lock">
    要求所有新应用均以私有方式发布，仅允许已通过身份验证的团队成员访问
  </Card>

  <Card title="密码保护的部署" icon="key">
    允许团队成员为已发布的应用添加密码保护
  </Card>

  <Card title="私有开发 URL" icon="shield-halved">
    要求所有应用开发 URL 均需进行身份验证；对于启用 SAML 的组织，还包括 SSO
  </Card>
</CardGroup>

<div id="private-deployments">
  ### 私有部署
</div>

启用后，所有新 App 都必须以私有方式发布。私有 App 仅限组织内已通过身份验证的成员访问。

**何时使用此设置：**
**何时使用此设置：**

* 组织处理敏感数据或专有应用
* 您需要确保 App 不会被意外公开
* 合规要求规定已发布应用必须限制访问
* 您需要确保 App 不会被意外公开
* 合规要求规定已发布应用必须限制访问

<Note>
  此设置仅适用于新发布的 App。现有已发布的 App 将保留当前的可见性设置。
</Note>

<div id="password-protected-deployments">
  ### 密码保护的部署
</div>

控制团队成员是否可以创建密码保护的部署。启用后，构建者可为已发布的应用设置访问密码，增加一层额外的安全保障。

**何时使用此设置：**

* 您希望与外部利益相关者共享应用，但不想将其完全公开
* Teams 需要在正式发布前向客户演示应用
* 您需要比组织会员资格更细粒度的访问控制

<div id="require-private-development-urls">
  ### 要求开发 URL 为私有
</div>

启用后，所有应用的开发 URL 都需要身份验证。如果你的组织已启用 SAML，开发 URL 将需要通过 SSO 进行身份验证。

**适用场景：**
**适用场景：**

* 你需要防止未经授权的用户访问正在开发中的应用
* 安全策略要求对所有开发环境进行保护
* 你希望确保只有通过身份验证的团队成员才能查看开发预览
* 你的安全策略要求对所有开发环境进行保护
* 你希望确保只有通过身份验证的团队成员才能查看开发预览

<Warning>
  此设置将追溯应用于组织中所有现有的应用。
</Warning>

<div id="ban-source-code-export">
  ### 禁止导出源代码
</div>

启用后，团队成员无法将 App 源代码导出为 zip 文件，从而防止代码被下载并在 Replit 平台外部共享。

**何时使用此设置：**
**何时使用此设置：**

* 您需要严格控制源代码的存放位置
* 安全策略禁止保留代码的本地副本
* 您希望确保所有开发工作都在受管理的环境中进行
* 您的安全策略禁止保留代码的本地副本
* 您希望确保所有开发工作都在您管理的环境中进行

<div id="security-settings">
  ## 安全设置
</div>

安全设置可帮助你强制执行漏洞扫描等防护措施。

<div id="require-security-scan">
  ### 要求安全扫描
</div>

设置是否要求所有 App 在发布前通过安全扫描。安全扫描可检测代码中的漏洞、暴露的 Secrets 及其他安全问题。

可用选项：

| 设置     | 描述                  |
| ------ | ------------------- |
| **关闭** | 安全扫描为可选项            |
| **要求** | 所有 App 在发布前必须通过安全扫描 |

**何时使用此设置：**
**何时使用此设置：**

* 必须满足安全合规要求
* 希望防止 API 密钥或 Secrets 被意外暴露
* 需要确保所有已发布 App 均符合统一的安全标准
* 希望防止 API 密钥或 Secrets 被意外暴露
* 需要确保所有已发布 App 均符合统一的安全标准

<Note>
  此设置不适用于启用该设置前已发布的 App。
</Note>

<div id="source-control-settings">
  ## 源代码管理设置
</div>

源代码管理设置可帮助你落实版本控制规范，并保护组织的代码仓库。

<div id="require-git-remote">
  ### 要求配置 Git 远程仓库
</div>

启用后，所有 App 必须先将本地更改推送到 Git 远程仓库，才能发布。这样可确保所有代码更改都在您组织的版本控制系统中得到跟踪。

**何时使用此设置：**
**何时使用此设置：**

* 所有代码都必须备份到 Git
* 您需要保留所有代码更改的审计记录
* 工作流程要求在发布前进行代码审查
* 您需要保留所有代码更改的审计记录
* 您的工作流程要求在发布前进行代码审查

<Note>
  此设置不适用于在启用该设置前已发布的 App。
</Note>

<div id="private-remotes">
  ### 私有远程仓库
</div>

控制团队成员能否使用公开的 Git 仓库。设置为要求使用私有远程仓库后，团队成员只能推送到 GitHub 等平台上的私有仓库。

可用选项：

| 设置            | 说明                       |
| ------------- | ------------------------ |
| **关闭**        | 团队成员可以使用公开或私有仓库          |
| **对非管理员强制要求** | 非管理员团队成员必须使用私有仓库         |
| **对所有人强制要求**  | 所有团队成员 (包括管理员) 都必须使用私有仓库 |

**适用场景：**
**适用场景：**

* 禁止使用公开代码仓库
* 需要确保专有代码不会被意外推送到公开仓库
* 合规要求强制使用私有版本控制
* 需要确保专有代码不会被意外推送到公开仓库
* 合规要求强制使用私有版本控制

<div id="best-practices">
  ## 最佳实践
</div>

<AccordionGroup>
  <Accordion title="默认设为私有" icon="shield">
    启用 **私有部署**，确保所有新发布的 App 均为私有，从而避免敏感应用意外暴露。
  </Accordion>

  <Accordion title="强制执行安全扫描" icon="magnifying-glass">
    启用 **要求安全扫描**，以便在 App 上线前发现漏洞。这有助于在整个组织内维持一致的安全标准。
  </Accordion>

  <Accordion title="保护开发环境" icon="code">
    启用 **要求开发 URL 为私有**，确保开发中的项目也受到保护。这对于处理敏感数据的组织尤为重要。
  </Accordion>

  <Accordion title="控制源代码访问" icon="code-branch">
    将 **禁止导出源代码** 与 **私有远程仓库** 要求结合使用，以全面掌控代码的存放位置和访问权限。
  </Accordion>
</AccordionGroup>
