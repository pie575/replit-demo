В этом руководстве представлен полный контрольный список безопасности, который поможет убедиться, что приложение, созданное с помощью вайб-кодинга, соответствует рекомендациям по безопасности.

Replit предоставляет множество функций безопасности [по умолчанию](/ru/ja/features/security/overview), однако важно понимать и внедрять дополнительные меры безопасности с учетом потребностей конкретного приложения.

<div id="section-2">
  ## Безопасность фронтенда
</div>

<AccordionGroup>
  <Accordion title="HTTPS везде" icon="lock">
    Replit по умолчанию использует HTTPS для всех приложений. Вам не о чем беспокоиться!
  </Accordion>

  <Accordion title="Валидация и очистка ввода" icon="shield-check">
    Всегда проверяйте и очищайте пользовательский ввод, чтобы предотвратить атаки межсайтового скриптинга (XSS):

    ```javascript theme={null}
    // Плохо: прямое использование пользовательского ввода
    element.innerHTML = userInput;

    // Хорошо: очистите ввод перед использованием
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    Спросите Agent:

    ```
    Help me validate and sanitize inputs to protect against XSS attacks
    ```
  </Accordion>

  <Accordion title="Не храните конфиденциальные данные в браузере" icon="eye-slash">
    Используйте Replit Secrets для хранения конфиденциальной информации, например ключей API.

    Не передавайте секреты на клиентскую сторону и не храните их в следующих местах:

    * Локальное хранилище
    * Хранилище сеансов
    * Клиентский JavaScript
    * Файлы cookie без необходимых атрибутов безопасности

    Спросите Agent:

    ```
    Help me keep sensitive data out of the browser. Am I doing this correctly?
    ```
  </Accordion>

  <Accordion title="Защита от CSRF" icon="shield">
    Реализуйте защиту от межсайтовой подделки запросов (CSRF) в формах:

    ```javascript theme={null}
    // Пример реализации CSRF-токена
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    Спросите Agent:

    ```
    Help me implement CSRF tokens for forms
    ```
  </Accordion>
</AccordionGroup>

  ## Безопасность бэкенда

<AccordionGroup>
  <Accordion title="Основы аутентификации" icon="key">
    При реализации аутентификации:

    * По возможности используйте Replit Auth
    * Для собственной системы аутентификации используйте проверенные библиотеки
    * Не храните пароли в открытом виде

    Спросите Agent:

    ```
    Help me implement authentication for my application with Replit Auth
    ```
  </Accordion>

  <Accordion title="Проверка авторизации" icon="user-lock">
    Всегда проверяйте права доступа перед выполнением действия:

    ```javascript theme={null}
    // Пример проверки авторизации
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    Спросите Agent:

    ```
    Help me implement authorization checks for my application
    ```
  </Accordion>

  <Accordion title="Защита API-эндпоинтов" icon="shield">
    Защитите API-эндпоинты:

    * Добавьте аутентификацию для конфиденциальных эндпоинтов
    * Настройте CORS должным образом
    * Рассмотрите возможность ограничения частоты запросов

    Спросите Agent:

    ```
    How do I properly authenticate endpoints in my app?
    ```
  </Accordion>

  <Accordion title="Защита от SQL-инъекций" icon="database">
    Agent по умолчанию использует ORM, что помогает предотвратить SQL-инъекции. Если вы пишете собственные запросы к базе данных:

    ```javascript theme={null}
    // Плохо: конкатенация строк в запросах
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // Хорошо: параметризованные запросы с ORM
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="Заголовки безопасности" icon="code">
    Добавьте в приложение важные заголовки безопасности:

    ```html theme={null}
    <!-- В index.html или через бэкенд -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    Просканируйте сайт на [securityheaders.com](https://securityheaders.com), чтобы получить рекомендации.

    Спросите Agent:

    ```
    Can you add the security headers to my application?
    ```
  </Accordion>
</AccordionGroup>

<div id="section-4">
  ## Постоянные меры безопасности
</div>

<AccordionGroup>
  <Accordion title="Поддерживайте зависимости в актуальном состоянии" icon="arrow-rotate-right">
    Регулярно проверяйте устаревшие пакеты на наличие потенциальных уязвимостей:

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="Корректная обработка ошибок" icon="exclamation">
    Не раскрывайте конфиденциальную информацию в сообщениях об ошибках:

    ```javascript theme={null}
    // Плохо: раскрытие конфиденциальных сведений
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // Хорошо: общее сообщение об ошибке
    catch (err) {
      console.error(err); // Логирование на сервере
      res.status(500).send('An error occurred');
    }
    ```

    Спросите Agent:

    ```
    Help me implement proper error handling for my application
    ```
  </Accordion>

  <Accordion title="Безопасность cookie" icon="cookie">
    При использовании cookie:

    * Установите флаг HttpOnly, чтобы запретить доступ из JavaScript
    * Используйте атрибут Secure, чтобы требовать HTTPS
    * Настройте атрибут SameSite для защиты от CSRF

    Спросите Agent:

    ```
    Help me secure my cookies for my application
    ```
  </Accordion>

  <Accordion title="Безопасность загрузки файлов" icon="upload">
    Если приложение позволяет загружать файлы:

    * Ограничьте типы и размеры файлов
    * По возможности проверяйте файлы на вредоносное ПО
    * Храните файлы в объектном хранилище Replit
    * Не используйте имена файлов, заданные пользователями; генерируйте новые

    Спросите Agent:

    ```
    Help me secure my file uploads for my application
    ```
  </Accordion>

  <Accordion title="Ограничение частоты запросов" icon="clock">
    Настройте ограничение частоты запросов, особенно для API-эндпоинтов, связанных с аутентификацией:

    ```javascript theme={null}
    // Пример промежуточного ПО для ограничения частоты запросов
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 минут
      max: 100 // ограничить каждый IP-адрес 100 запросами за windowMs
    });

    app.use('/api/', limiter);
    ```

    Спросите Agent:

    ```
    Help me implement rate limiting for my application
    ```
  </Accordion>
</AccordionGroup>
