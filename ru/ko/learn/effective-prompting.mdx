<div id="section-3">
  ### Сначала составьте план
</div>

<Tip>Прежде чем вводить промпт, продумайте функции приложения и пользовательские сценарии. Чёткий план помогает формулировать более точные промпты.</Tip>

Продумайте структуру приложения как продакт-менеджер. Разбейте общую цель на логические шаги.

**Вместо:** «Создай приложение для управления задачами».

**Лучше:** «1. Создай базовую HTML-структуру с полем ввода и списком задач. 2. Добавь JavaScript для добавления задач. 3. Используй базу данных для хранения задач. 4. Добавь возможность отмечать задачи как выполненные».

Затем формулируйте отдельный промпт для каждого шага в Agent.

<div id="section-4">
  ### Создавайте приложение поэтапно
</div>

После каждого успешного этапа используйте [**чекпоинты**](/ru/ko/features/agent/overview#checkpoints), чтобы сохранять прогресс. Если что-то пойдёт не так, вы сможете откатиться к рабочему состоянию и попробовать другой подход.

**Вместо этого:** «Создай полноценную платформу электронной коммерции».

**Так:** «Настрой базовый full-stack-проект сайта электронной коммерции с регистрацией и входом пользователей через Replit Auth». Затем поочерёдно добавляйте каталог товаров, корзину и возможность оплаты.

<div id="section-5">
  ### Формулируйте запросы конкретно
</div>

Чётко определяйте формат вывода, ограничения и граничные случаи.

**Вместо этого:** «Добавь форму обратной связи».

**Так:** «Создайте страницу формы обратной связи по адресу `/contact` со следующими полями:

* Имя (обязательно)
* Электронная почта (обязательно, в корректном формате)
* Сообщение (обязательно, минимум 10 символов)

При отправке отправляйте данные формы на `contact@mydomain.com`.»

<div id="section-6">
  ### Используйте позитивные формулировки
</div>

Говорите о том, *чего вы хотите*, а не о том, чего следует избегать.

**Вместо:** «Не делайте страницу профиля пользователя запутанной».

**Так:** «Создайте понятную страницу профиля пользователя. Крупно отобразите имя пользователя, а ниже укажите адрес электронной почты и дату регистрации. Добавьте кнопку „Редактировать профиль“».

<div id="section-7">
  ### Не усложняйте
</div>

Используйте ясный и понятный язык. Разбивайте сложные запросы на пункты.

**Вместо:** «Реализуйте серверную инфраструктуру для динамического создания и поиска артефактов пользовательского контента».

**Так:** «Создайте серверную функцию, которая позволит пользователям отправлять записи в блог. Пользователи должны указывать заголовок и текст. Сохраняйте записи в базе данных».

<div id="section-9">
  ### Предоставление нужных файлов
</div>

Вместо того чтобы прикреплять весь проект, укажите конкретные файлы.

**Вместо этого:** (прикрепить всё) «Создайте страницу профиля пользователя в соответствии с дизайн-системой».

**Лучше так:** «Создайте страницу профиля пользователя. Получите данные пользователя с серверного эндпоинта. Оформите её в соответствии с [URL дизайн-документа] и этим макетом: [прикреплён `profile_mockup.jpg`].»

<Tip>Если переходите к несвязанной задаче, начните новый чат. Это поможет избежать путаницы из-за накопленного контекста.</Tip>

<div id="section-10">
  ### Приводите примеры
</div>

Приводите конкретные примеры — фрагменты кода, образцы данных или скриншоты, — чтобы избежать неоднозначности.

**Вместо:** «Сделай карточки товаров лучше».

**Так:** «Переработайте дизайн карточек товаров на странице покупок. Каждая карточка должна содержать изображение товара, название, цену и кнопку „Добавить в корзину“. Сделайте примерно как на этом макете: [прикреплён скриншот]. Используйте светло-серую рамку».

<div id="section-11">
  ## Эффективная отладка
</div>

При возникновении ошибки предоставьте следующее:

* **Точное** сообщение об ошибке
* Соответствующий фрагмент кода
* Имя файла, в котором возникает ошибка
* Цель, которой вы хотите достичь
* Шаги, которые вы уже предприняли

**Вместо:** «Моя страница входа не работает».

**Так:** «При входе с правильными учётными данными на `/login` в консоли браузера появляется ошибка „Пользователь не найден“. Похоже, проверка базы данных работает некорректно. Вот код обработки входа из `auth.js`».

<div id="section-12">
  ## Получите совет
</div>

<Tip>Перед началом разработки переключитесь в режим Plan, чтобы изучить варианты. Спросите Agent о библиотеках, подходах и компромиссах.</Tip>

**Вместо этого:** «Добавь возможность принимать платежи.»

**Скажите так:** «Какие есть хорошие варианты для приёма платежей банковскими картами в веб-приложении, созданном в Replit? Мне нужно решение, которое будет относительно легко интегрировать.»

<div id="section-13">
  ## Итерации с промптом
</div>

Первый промпт не обязательно должен быть идеальным — это нормально. Если результат вас не устраивает:

* Добавьте больше деталей
* Приведите примеры
* Упростите инструкции
* Сформулируйте иначе

**Первый вариант:** &quot;Создай заголовок для сайта.&quot;

**Улучшенный вариант:** &quot;Создайте компонент фиксированной шапки сайта: логотип слева, а навигационные ссылки (Главная, О нас, Контакты) — справа.&quot;

<div id="section-14">
  ## Итоги
</div>

Ключевые принципы эффективной работы с промптами:

* **Планируйте** до написания промпта
* **Разрабатывайте приложение поэтапно**, используя чекпоинты
* **Чётко формулируйте** требования
* **Добавляйте контекст** с помощью примеров и связанных файлов
* **Повторяйте попытку**, если результат не соответствует ожиданиям

Освоив эти принципы, вы сможете быстрее создавать приложения с Agent.
