---
title: "Types de deployment"
description: "Comparez les deployments Autoscale, Static, Reserved VM et Scheduled et découvrez lequel choisir pour votre app publiée."
---

Le type de deployment correspond à la technologie que Replit utilise pour publier votre app. Vous le sélectionnez dans l&#39;outil Publishing, sous **Adjust settings**, via le menu déroulant **Deployment type**. **Autoscale** est l&#39;option par défaut et recommandée : la plupart des créateurs n&#39;ont jamais besoin de la modifier.

<div id="comparar-tipos-de-deployment">
  ## Comparer les types de deployment
</div>

| Type            | Idéal pour                                                    | Fonctionnement                                                                         | Facturation                                          |
| :-------------- | :------------------------------------------------------------ | :------------------------------------------------------------------------------------- | :--------------------------------------------------- |
| **Autoscale**   | Applications web et API à trafic variable                     | Ajoute des serveurs en cas de forte charge, descend à zéro en période d&#39;inactivité | Vous payez pendant le traitement des requêtes        |
| **Static**      | Pages d&#39;accueil, portfolios, sites de documentation       | Sert les fichiers depuis un serveur cloud mis en cache, sans backend                   | Vous ne payez que les données servies par votre site |
| **Reserved VM** | Bots, tâches en arrière-plan, API toujours actives            | Un serveur dédié qui ne se met jamais en veille                                        | Coût mensuel fixe                                    |
| **Scheduled**   | Tâches périodiques comme les sauvegardes et les notifications | Exécute une commande selon une planification, puis s&#39;arrête                        | Vous payez la durée de chaque exécution              |

<div id="autoscale">
  ## Autoscale
</div>

Les déploiements Autoscale s&#39;exécutent sur des serveurs qui évoluent à la hausse comme à la baisse en fonction du trafic de votre app. Lorsque votre app est très sollicitée, Replit ajoute des serveurs pour absorber la charge. Lorsqu&#39;elle est inactive, leur nombre diminue jusqu&#39;à zéro : vous ne payez donc pas pendant les périodes creuses.

Idéal pour :

* Les applications web au trafic variable, comme les sites d&#39;e-commerce
* Les API et les services

La configuration se trouve dans **Adjust settings** : [la puissance de la machine et le nombre maximal de serveurs](/fr/pt/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Les Static Deployments hébergent les fichiers de votre app, comme le HTML, le CSS et le JavaScript, sur un serveur cloud qui s&#39;appuie sur la mise en cache pour diffuser le contenu rapidement et à moindre coût. Aucun serveur backend n&#39;est utilisé.

Idéal pour :

* Les landing pages marketing
* Les sites portfolio
* Les sites de documentation de produits et d&#39;API

<Note>
  Les Static Deployments ne sont pas compatibles avec les Replit Apps créées avec Agent. Agent crée des apps full-stack qui nécessitent un serveur backend : dans ce cas, utilisez plutôt Autoscale ou Reserved VM.
</Note>

La configuration comprend le répertoire public à servir ainsi qu&#39;une commande de build facultative. Pour les en-têtes de réponse, les réécritures d&#39;URL et les redirections, consultez la [configuration avancée de Static](/fr/pt/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Les Reserved VM Deployments exécutent votre app sur une machine virtuelle dédiée qui ne se met jamais en veille. Vous bénéficiez de performances constantes et d&#39;un coût mensuel fixe et prévisible.

Idéal pour :

* Les tâches en arrière-plan gourmandes en mémoire
* Les chat bots qui doivent rester connectés
* Les serveurs d&#39;API toujours actifs

La configuration comprend la [puissance de la machine](/fr/pt/features/publishing/machine-configuration), les commandes de build et d&#39;exécution, les mappages de ports, et le mode d&#39;exécution de l&#39;app : serveur web ou worker en arrière-plan.

<div id="scheduled">
  ## Scheduled
</div>

Les Scheduled Deployments exécutent une commande selon une planification dans l&#39;environnement de votre app, puis s&#39;arrêtent jusqu&#39;à l&#39;exécution suivante. Décrivez la planification en langage courant, par exemple « tous les jours de la semaine à 9 h », et Replit la convertit automatiquement en planification. Vous recevez une alerte si une exécution échoue.

Idéal pour :

* Les vérifications d&#39;état et les rapports de santé
* L&#39;envoi de notifications
* Le lancement de sauvegardes

La configuration comprend la planification, un délai d&#39;expiration de job ainsi que les commandes de build et d&#39;exécution. Les Scheduled Deployments ne servent aucune page web : ils n&#39;ont donc pas d&#39;URL publique.
