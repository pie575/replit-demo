Ashby 已经在负责筛选主动投递 (inbound) 的应聘者。本工作流则面向主动寻访 (outbound) ：从 Drive 中读取职位描述，在 GitHub 上寻找符合条件的工程师，跳过已在 Ashby 中的人选，并生成可供你直接发送的触达文案。Agent 会将新发现的人才标记为“已寻访”，并附上简短的“为何合适”说明以及给候选人的文案草稿。由你确认后再发送。请勿将其作为招聘决策的唯一依据。

<div id="section">
  ## 适合人群
</div>

* 主动投递的简历较少，需要一份现成候选人名单的技术招聘专员。
* 不想整天耗在搜索上，却又希望在 GitHub 上找到匹配工程师的招聘经理。

<AiPrompt>

  跳过已经在 Ashby 中的人。为每个人写一段 3 行的「为何合适」说明，
  以及一份简短的外联文案草稿。不要发送任何内容。将新发掘的人才以“已寻访”状态
  添加到 Ashby，并为候选人附上备注和文案草稿。
</AiPrompt>

<div id="section-4">
  ## 预期结果
</div>

Agent 会读取职位描述、搜索 GitHub、跳过已在 Ashby 中的人员，并返回一份附带消息草稿的候选人列表。你需要审核后再发送。第一轮结果可能包含较多无关候选人。查看结果后，进一步收紧必备条件。打开列表中的 3 个 GitHub 个人资料，确认他们是否符合必备条件，并在发送任何内容前确认他们尚未在 Ashby 中。

<div id="section-6">
  ## 故障排除
</div>

* **候选人列表中干扰项过多：** 首轮筛选后，进一步收紧必备条件和优先条件。可要求候选人近期曾使用特定编程语言或在特定类型的仓库中提交，并排除疑似现有客户或竞争对手员工的人员。
* **已在 Ashby 中的人员仍然显示：** 确认 Ashby 已连接到正确的工作区，并确认 Agent 不仅按显示名称匹配，也会按电子邮件地址和 GitHub 用户名匹配。
* **外联信息已被发送：** 此工作流应仅创建文案草稿。如果发送了任何内容，请停止该流程，并告知 Agent 绝不能向候选人发送电子邮件或消息。
