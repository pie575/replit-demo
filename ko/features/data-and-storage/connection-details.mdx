앱은 Replit이 대신 관리하는 자격 증명을 통해 데이터베이스에 연결됩니다. **Database** 도구에서 확인할 수 있습니다. 데이터베이스를 선택한 다음 **Settings** 탭을 여세요. 연결 문자열, 스토리지 사용량, 고급 연결 정보가 표시됩니다.

<div id="environment-variables">
  ## 환경 변수
</div>

development 데이터베이스에 연결할 때 사용할 수 있는 환경 변수는 다음과 같습니다.

* `DATABASE_URL`: 데이터베이스에 연결하고 인증하는 방법

앱이 이 변수를 자동으로 사용합니다. `DATABASE_URL`은 해당 앱으로 범위가 제한되므로, 여러분이 소유한 다른 앱이나 외부 데이터베이스 뷰어에서는 development 데이터베이스에 접근할 수 없습니다. 유출되더라도 다른 사람이 이를 이용해 데이터베이스에 접근하거나 수정할 수 없습니다.

<Info>
  development 데이터베이스가 아직 [레거시 Neon 인프라](/ko/features/data-and-storage/development-and-production#legacy-development-database)에 있다면 `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `PGPORT` 변수도 추가로 사용할 수 있습니다. 이 변수들은 Replit의 현재 인프라에서 호스팅되는 데이터베이스에는 제공되지 **않으므로**, 대신 `DATABASE_URL`을 사용하세요.
</Info>

<Warning>
  아직 레거시 Neon development 데이터베이스를 사용 중이라면 `DATABASE_URL`을 공유하지 마세요. 여기에는 데이터베이스 자격 증명이 포함되어 있어 누구나 이를 이용해 데이터베이스에 접근하고 수정할 수 있습니다. 공개된 장소나 지원 티켓에는 절대 붙여넣지 마세요.
</Warning>

<div id="connect-an-external-tool">
  ## 외부 도구 연결
</div>

production 데이터베이스의 **Settings 탭**에서 연결 문자열을 가져오면, PostgreSQL과 호환되는 모든 SQL 클라이언트에서 **production** 데이터베이스에 연결할 수 있습니다.

<div id="security">
  ## 보안
</div>

Agent로 데이터베이스 integration을 추가하면 모든 데이터베이스 통신을 처리하는 ORM(Object-Relational Mapper)이 함께 추가되며, 다음과 같은 보안 기능이 기본으로 제공됩니다.

* **스키마 검증**: 데이터가 예상된 형식에 맞는지 확인합니다
* **데이터 정제**: builder의 입력을 자동으로 정리하여 SQL 인젝션 공격을 방지합니다

<div id="regenerate-production-database-credentials">
  ## production 데이터베이스 자격 증명 재생성
</div>

production 연결 문자열이 노출된 경우 Database tool에서 해당 자격 증명을 재생성하세요. 이 작업을 수행하면 Neon production 데이터베이스의 비밀번호가 새로 생성되며, 기존 production 연결 문자열은 즉시 작동을 멈춥니다.

다음 조건을 모두 충족하는 경우 자격 증명을 재생성할 수 있습니다.

* 앱에 Neon production 데이터베이스가 있는 경우
* 앱 소유자이거나 앱을 소유한 workspace의 관리자인 경우
* 웹 브라우저에서 Replit을 사용하는 경우
* 진행 중인 deployment가 없는 경우
* 앱에 live deployment가 있다면, 최신 빌드가 성공적으로 완료되었고 [Autoscale 또는 Reserved VM](/ko/features/publishing/deployment-types)을 사용하는 경우

<Warning>
  이 작업은 되돌릴 수 없습니다. 기존 연결 문자열은 즉시 작동을 멈춥니다.
  앱에 live deployment가 있는 경우 재배포가 진행되는 동안 잠시 접속이 불가능할 수 있습니다.
</Warning>

<div id="regenerate-the-credentials">
  ### 자격 증명 재생성
</div>

1. Tools pane에서 **Database**를 선택합니다.

2. **Production Database**를 선택한 다음 **Settings** 탭을 선택합니다.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="연결 문자열, 스토리지 사용량, 그리고 재생성 credentials 행이 있는 Advanced 섹션이 표시된 production 데이터베이스 Settings 탭." width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. **Advanced** 아래에서 **재생성 credentials** 행을 펼칩니다.

4. **재생성 credentials** 버튼을 선택합니다.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Advanced 섹션에서 재생성 credentials 행이 펼쳐져 재생성 credentials 버튼이 표시된 모습." width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. 확인 대화 상자에서 **재생성 credentials**를 선택해 확인합니다.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="이 작업은 되돌릴 수 없으며 기존 연결 문자열이 즉시 작동을 멈춘다고 경고하는 재생성 credentials 확인 대화 상자." width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. **Refresh**를 선택해 새 연결 문자열을 불러옵니다.

7. 앱에 live deployment가 있는 경우 **Publishing**을 열고 재배포 진행 상황을 확인합니다.

8. 외부 도구나 맞춤 integration에 복사해 둔 연결 문자열이 있다면 모두 교체합니다.

<div id="what-changes">
  ### 무엇이 바뀌나요
</div>

자격 증명을 재생성하면 production 데이터베이스의 비밀번호가 새로 생성됩니다. 연결 문자열에서는 비밀번호 부분만 바뀌고, 호스트와 데이터베이스 이름, 역할은 그대로 유지됩니다.

지원되는 live deployment의 경우, Replit이 업데이트된 연결 문자열을 사용해 마지막으로 성공한 build를 다시 배포합니다.
