---
title: "Аварийное восстановление Git"
description: "Узнайте, как восстановить историю Git и код с помощью системы автоматического резервного копирования Replit."
---

Replit автоматически создает резервные копии вашего репозитория Git, чтобы вы могли восстановить его после таких проблем, как повреждение папки `.git` или потеря истории коммитов. Эта система резервного копирования работает в фоновом режиме, поэтому ваша работа защищена без дополнительных усилий с вашей стороны.

<div id="como-funciona">
  ## Как это работает
</div>

Каждое App в Replit хранит защищённую резервную копию своего репозитория Git. Когда Replit Agent вносит изменения в код или вы публикуете приложение, они автоматически синхронизируются с этой резервной копией. Если ваш локальный репозиторий Git будет повреждён или станет непригодным для использования, вы сможете восстановить всю историю коммитов из резервной копии.

<Info>
  Удалённый репозиторий резервного копирования называется `gitsafe-backup` и автоматически управляется Replit. Вам не нужно ничего настраивать — он уже работает в фоновом режиме.
</Info>

<div id="visualizar-seu-histrico-de-backup">
  ## Просмотр истории резервного копирования
</div>

Самый простой способ просмотреть историю коммитов — открыть [панель Git](/ru/pt/features/workspace-tools/git-interface). Она находится в разделе Tools в Project Editor и показывает полную историю коммитов, включая все чекпоинты Agent. Этот способ подходит для большинства случаев и не требует выполнения команд.

Если нужно проверить удалённый репозиторий gitsafe-backup напрямую, используйте Shell:

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

Здесь отображается полная история ваших коммитов, включая все чекпоинты Agent и коммиты, созданные вручную. Используйте её, чтобы убедиться, что ваша работа محفوظена в резервной копии, или найти нужный коммит для восстановления.

<div id="recuperao-de-problemas-do-git">
  ## Устранение проблем с Git
</div>

Если вы столкнулись с ошибками Git или ваш репозиторий повреждён, начните с [панели Git](/ru/pt/features/workspace-tools/git-interface). С её помощью можно решить большинство распространённых проблем — например, сброситься к предыдущему коммиту или получить изменения из удалённого репозитория — без команд в Shell.

Если панель Git не поможет (например, если папка `.git` полностью повреждена), воспользуйтесь приведёнными ниже инструкциями для Shell.

<div id="verificar-se-o-backup-est-disponvel">
  ### Проверка доступности резервной копии
</div>

Сначала проверьте, существует ли удалённый репозиторий для резервной копии:

```bash theme={null}
git remote -v
```

Найдите `gitsafe-backup` в выводе. Если он есть, можно продолжить восстановление.

<div id="restaurar-seu-repositrio">
  ### Восстановление репозитория
</div>

<Warning>
  В ходе этого процесса текущая папка `.git` будет заменена версией из резервной копии. Рабочие файлы останутся без изменений, но локальная история Git будет восстановлена из резервной копии.
</Warning>

<Steps>
  <Step title="Сохраните текущую конфигурацию Git">
    Создайте резервную копию файла конфигурации Git, если у вас есть пользовательские настройки:

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Клонируйте резервный репозиторий">
    Создайте временный клон из резервной копии:

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Замените папку Git">
    Переместите повреждённую папку `.git` и замените её резервной копией:

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Восстановите конфигурацию">
    Верните сохранённую конфигурацию Git:

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

После выполнения этих шагов запустите `git status`, чтобы убедиться, что репозиторий работает корректно.

<div id="soluo-de-problemas-comuns">
  ## Устранение распространённых неполадок
</div>

<div id="fatal-repository-not-found-ou-remote-de-backup-ausente">
  ### „fatal: repository not found“ или отсутствует удалённый репозиторий для резервного копирования
</div>

Для старых проектов система резервного копирования может быть не включена. Если вам нужна помощь с восстановлением старого проекта, обратитесь в службу поддержки.

<div id="a-recuperao-no-incluiu-commits-recentes">
  ### При восстановлении не были учтены последние коммиты
</div>

Резервные копии синхронизируются после каждого коммита Agent. Если вы внесли изменения, но не закоммитили их, они не попадут в резервную копию. Проверьте рабочую директорию на наличие незакоммиченных файлов.

<div id="operaes-do-git-esto-lentas-ou-travadas">
  ### Операции Git выполняются медленно или зависают
</div>

Если операции Git не отвечают, возможно, остался устаревший файл блокировки. Его можно безопасно удалить:

```bash theme={null}
rm -f .git/index.lock
```

<div id="preveno-de-perda-de-dados">
  ## Предотвращение потери данных
</div>

Хотя система резервного копирования автоматически защищает историю Git, вы можете принять дополнительные меры для защиты своей работы:

* **Регулярно делайте коммиты**: Делайте небольшие коммиты часто, чтобы резервные копии вашего прогресса регулярно обновлялись
* **Используйте чекпоинты**: При работе с [Replit Agent](/ru/pt/features/agent/overview) чекпоинты автоматически создают коммиты на ключевых этапах
* **Подключите GitHub**: Для критически важных проектов [подключите App к GitHub](/ru/pt/build/import-from-providers), чтобы обеспечить дополнительный уровень резервного копирования
