Ashby는 이미 인바운드 지원서를 심사합니다. 이 workflow는 아웃바운드용입니다. Drive에 있는 채용
공고를 읽고, GitHub에서 조건에 맞는 엔지니어를 찾고, 이미 Ashby에 등록된 사람은 건너뛰고,
여러분이 보낼 outreach 초안을 작성합니다. Agent는 새로 찾은 인물을 sourced 상태로 기록하고,
적합한 이유를 간단히 정리한 뒤 해당 후보자에 초안을 남깁니다. 검토와 발송은 직접 하세요. 이
결과만으로 채용을 결정하지는 마세요.

<div id="what-to-expect">
  ## 예상되는 동작
</div>

Agent는 채용 공고를 읽고 GitHub를 검색한 뒤, 이미 Ashby에 등록된 사람은 건너뛰고
초안이 포함된 shortlist를 반환합니다. 검토한 다음 발송하면 됩니다. 첫 결과는 다소 정돈되지 않을 수 있습니다.
결과를 확인한 후 필수 요건을 더 좁혀 보세요. 목록에서 GitHub 프로필 세 개를 열어
필수 요건에 부합하는지 확인하고, 해당 인물이 아직 Ashby에 없는지 점검한 뒤에
발송하세요.

<div id="troubleshooting">
  ## 문제 해결
</div>

* **shortlist에 불필요한 후보가 많은 경우:** 1차 검토 후 필수 요건과 nice-to-haves의 기준을 더 엄격하게 나누세요. 특정 언어나 저장소 유형의 최근 commit을 요청하고, 현재 고객이거나 경쟁사 직원으로 보이는 사람은 제외하세요.
* **이미 Ashby에 있는 사람이 계속 나타나는 경우:** Ashby가 올바른 workspace에 연결되어 있는지, Agent가 표시 이름만이 아니라 이메일이나 GitHub 사용자 이름을 기준으로 매칭하는지 확인하세요.
* **outreach가 발송된 경우:** 이 workflow는 초안 작성까지만 수행해야 합니다. 실제로 발송된 것이 있다면 Routine을 중지하고, 후보자에게 이메일이나 메시지를 절대 보내지 말라고 Agent에 지시하세요.
