В этом руководстве описано, как вручную скопировать приложение в другой workspace или аккаунт. Вы копируете код, настраиваете новое приложение, переносите данные и затем переключаете пользователей на новое приложение.

Ничего при этом не перемещается и не удаляется. Старый проект остаётся на прежнем месте, а две копии между собой не синхронизируются. В конце вы сами решаете, сохранить старый проект или удалить его.

<Note>
  Ищете встроенный перенос в один клик? См. [Перенос App в Teams](/ru/teams/identity-and-access-management/transfer-app-to-teams). Используйте это руководство, если такой вариант недоступен или если нужно скопировать проект между аккаунтами.
</Note>

<div id="before-you-start">
  ## Прежде чем начать
</div>

Вам понадобится:

* Доступ и к старому project, и к новому workspace или аккаунту.
* Около часа непрерывной работы на финальное переключение. Предыдущие шаги можно растянуть на несколько дней.
* Если у вашего App есть собственный веб-адрес — доступ к сервису, где вы управляете этим доменом.

Автоматически не переносятся и требуют больше всего времени две вещи: **база данных** и **веб-адрес**. В этом руководстве рассмотрены обе.

<Note>
  Если администратор вашего workspace включил параметр [Ban source code export](/ru/teams/enterprise-privacy-settings#ban-source-code-export), скачать project в виде zip-архива не получится. Свяжитесь с администратором workspace заранее — он подтвердит, разрешено ли копирование вручную, и подскажет, как перенести код и базу данных.
</Note>

<div id="plan-for-downtime">
  ## Спланируйте простой
</div>

Представьте, что вы открываете второй магазин и закрываете первый. Есть короткий промежуток, когда старый магазин уже закрыт, а новый ещё не открыт. В это время никто не сможет пользоваться вашим приложением.

**Как долго приложение будет недоступно?** Обычно от 15 до 60 минут. Это зависит от объёма данных в вашей базе и от того, как быстро обновится ваш веб-адрес.

**Потеряю ли я данные?** Только если кто-то добавит данные в старое приложение после того, как вы скопируете базу данных. Чтобы этого не произошло, отключите старое приложение *до* создания финальной копии. Шаги в этом руководстве выстроены именно в таком порядке.

**Можно ли всё отменить?** Да. Старый project не удаляется. Если что-то пойдёт не так, опубликуйте старое приложение снова — оно будет работать точно так же, как раньше.

**Когда лучше это делать?** Выберите время, когда вашим приложением пользуется мало людей. По возможности предупредите пользователей заранее.

<div id="step-1-copy-the-code-to-a-new-project">
  ## Шаг 1. Скопируйте код в новый project
</div>

Выберите один из способов. Старое приложение на этом шаге продолжает работать. Оба способа переносят ваш код. GitHub всегда переносит историю коммитов, а zip-архив — только если в него включена папка `.git`:

|                              | Через GitHub                                                          | Через zip-файл                                                                                                                |
| ---------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **Файлы кода**               | Только файлы, которые вы закоммитили и отправили                      | Всё, что есть на диске, включая незакоммиченные изменения                                                                     |
| **История коммитов**         | Полная история в удалённом репозитории                                | Полная история, если в zip включена папка `.git`. Истории не будет, если вы исключили `.git`, чтобы уложиться в лимит импорта |
| **Папки зависимостей**       | Согласно вашему `.gitignore`                                          | Исключаются (`node_modules`, `.venv`, `build` и подобные); переустанавливаются при импорте                                    |
| **Требования**               | Аккаунт GitHub, подключённый к обоим аккаунтам Replit                 | Нет                                                                                                                           |
| **Постоянная синхронизация** | Обе копии могут отправлять и получать изменения из одного репозитория | Нет — разовый снимок                                                                                                          |
| **Лучше всего подходит для** | Проектов, для которых нужна долгосрочная резервная копия в Git        | Быстрых разовых копий                                                                                                         |

<div id="via-github">
  ### Через GitHub
</div>

<Steps>
  <Step title="Отправьте старый project в GitHub">
    В старом project откройте [панель Git](/ru/features/workspace-tools/git-interface), подключите репозиторий GitHub, затем сделайте коммит и отправьте изменения. Используйте приватный репозиторий, если не хотите публиковать код.
  </Step>

  <Step title="Предоставьте доступ новой учётной записи">
    Если новый workspace принадлежит другой учётной записи Replit, её учётной записи GitHub нужен доступ к репозиторию. Для приватного репозитория добавьте эту учётную запись GitHub как соавтора или используйте общую организацию GitHub.
  </Step>

  <Step title="Импортируйте в новый workspace">
    Войдите в новую учётную запись, откройте [replit.com/import](https://replit.com/import), выберите **GitHub**, подключите учётную запись GitHub и укажите репозиторий. Советы по устранению неполадок см. в разделе [Импорт от provider](/ru/build/import-from-providers).
  </Step>

  <Step title="Проверьте копию">
    Откройте новый project и убедитесь, что файлы и история коммитов на месте. Во время импорта Replit устанавливает зависимости и настраивает команды запуска.
  </Step>
</Steps>

<Warning>
  В GitHub попадает только то, что вы закоммитили и отправили. Файлы, подпадающие под `.gitignore`, и незакоммиченные изменения останутся в старом project. Никогда не коммитьте в репозиторий секретные значения или дампы базы данных.
</Warning>

<div id="via-zip-file">
  ### С помощью zip-файла
</div>

<Steps>
  <Step title="Скачайте старый project">
    В старом project откройте меню из трёх точек в верхней части дерева файлов и выберите **Download as zip**.

    Если скачивание прошло успешно и файл меньше 200 МБ, переходите к следующему шагу.

    Zip-файл больше 200 МБ может скачаться без ошибок. Однако [импорт ZIP](/ru/build/import-from-providers#limitations) отклоняет файлы объёмом более 200 МБ, поэтому Replit не сможет создать из него новый project. Если скачивание не удалось или архив превышает 200 МБ, создайте архив поменьше:

    1. В старом project откройте инструмент **Shell**.

    2. Вставьте эту команду и нажмите Enter. Она создаёт файл `project.zip` и исключает папки, которые Replit может восстановить самостоятельно:

       ```bash theme={null}
       zip -r project.zip . -x ".cache/*" "node_modules/*" ".venv/*" "venv/*" ".pythonlibs/*" "build/*" "target/*" ".next/*" "__pycache__/*"
       ```

    3. Проверьте размер. Вставьте эту команду и нажмите Enter. Она выведет размер в МБ, например `150M` для 150 МБ:

       ```bash theme={null}
       du -h project.zip
       ```

    4. Если размер превышает 200 МБ, уменьшите файл, исключив историю изменений. Вставьте обе строки и нажмите Enter:

       ```bash theme={null}
       rm project.zip
       zip -r project.zip . -x ".cache/*" ".local/*" ".git/*" "node_modules/*" ".venv/*" "venv/*" ".pythonlibs/*" "build/*" "target/*" ".next/*" "__pycache__/*"
       ```

       Исключайте `.local` и `.git` только в том случае, если нужно уменьшить архив до 200 МБ. Эти исключения не удаляют папки из старого project. Однако архив без `.git` не содержит истории коммитов project. Если историю нужно сохранить, используйте способ с GitHub.

    5. Найдите `project.zip` в дереве файлов, откройте меню из трёх точек рядом с ним и выберите **Download**.

    Папка `.cache` содержит внутреннее состояние Replit, включая кэшированные значения секретов. Всегда исключайте её из архивов, которые создаёте вручную. Если в вашем project есть другие крупные сгенерированные папки, добавьте их в список исключений.
  </Step>

  <Step title="Импортируйте в новый workspace">
    Войдите в новую учётную запись, откройте [replit.com/import](https://replit.com/import), выберите **ZIP** и загрузите файл.
  </Step>

  <Step title="Проверьте копию">
    Откройте новый project и убедитесь, что все файлы на месте. Если архив включает папку `.git`, история коммитов перенеслась вместе с ним. Если вы использовали команду для уменьшенного архива, новый project начнётся без истории коммитов. Исключённые зависимости Replit переустановит во время импорта.
  </Step>
</Steps>

<div id="step-2-set-up-the-new-app">
  ## Шаг 2: Настройте новое приложение
</div>

Старое приложение по-прежнему работает. На этом шаге настройте новое приложение, используя *тестовую копию* данных, чтобы позднее быстро выполнить окончательное переключение.

<Steps>
  <Step title="Добавьте Secrets">
    Значения Secrets (ключи API, пароли) не переносятся из старого проекта автоматически. Откройте инструмент [Secrets](/ru/core-concepts/project-editor/app-setup/secrets) в обоих проектах и вручную скопируйте каждое значение. Не забудьте Secrets для deployment.
  </Step>

  <Step title="Переподключите Connectors и другие сервисы">
    Переподключите каждую интеграцию через **Инструменты → Connectors** в новом проекте. Сведения об App Storage, соавторах и всём остальном см. в разделе [Воссоздайте то, что не переносится](#re-create-what-doesnt-copy-over).
  </Step>

  <Step title="Опубликуйте новое приложение">
    [Опубликуйте](/ru/features/publishing/overview) новый проект. Оно получит собственный веб-адрес `replit.app` и собственную пустую продакшен-базу данных. Пока не подключайте свой домен.
  </Step>

  <Step>
    Следуйте инструкциям в разделе [Скопируйте базу данных](#copy-the-database) ниже, указав **production** базу данных в новом проекте в качестве целевой. Так вы получите реальные данные для тестирования. На шаге 3 эта копия будет заменена актуальными данными.
  </Step>

  <Step>
    Откройте новое приложение по адресу `replit.app` и используйте его так, как это делали бы ваши пользователи. Исправьте всё, что не работает, прежде чем продолжить. Ваши пользователи пока не затронуты.
  </Step>
</Steps>

<div id="step-3-switch-your-users-to-the-new-app">
  ## Шаг 3: Переведите пользователей на новое приложение
</div>

На этом этапе приложение будет недоступно. Выполните все действия за один раз.

<Steps>
  <Step title="Отключите старое приложение">
    В старом проекте откройте инструмент **Publishing** и выберите **Unpublish**. Теперь ваше приложение недоступно. С этого момента никто не сможет добавлять новые данные, поэтому следующая копия будет полной.
  </Step>

  <Step title="Скопируйте базу данных в последний раз">
    Следуйте инструкциям в разделе [Копирование базы данных](#copy-the-database) ниже, указав базу данных **production** в новом проекте в качестве целевой. Эта копия содержит все актуальные данные.
  </Step>

  <Step title="Привяжите веб-адрес к новому приложению">
    Если ваше приложение использует собственный домен, в старом проекте откройте **Publishing → Domains** и отключите домен. В новом проекте откройте **Publishing → Domains** и [подключите его](/ru/features/publishing/custom-domains#connect-a-domain-you-already-own). Если Replit попросит, обновите записи у регистратора домена (например, GoDaddy или Namecheap).

    Новый адрес может стать доступен для всех через несколько минут или несколько часов. До этого некоторые посетители могут видеть ошибку.

    Если ваше приложение использует только адрес `replit.app`, сообщите пользователям новый адрес.
  </Step>

  <Step title="Убедитесь, что новое приложение доступно">
    Откройте веб-адрес и убедитесь, что новое приложение загружается с вашими данными. Ваше приложение снова доступно.
  </Step>
</Steps>

<div id="copy-the-database">
  ## Копирование базы данных
</div>

Копирование кода не затрагивает базу данных. Скопируйте данные с помощью инструментов PostgreSQL `pg_dump` и `pg_restore`, доступных в Shell обоих проектов. И Шаг 2, и Шаг 3 ссылаются на этот раздел. Команды каждый раз одни и те же — меняется только *целевая* база.

<Warning>
  Данные, записанные после запуска `pg_dump`, в копию не попадут. Перед финальным копированием на Шаге 3 сначала отключите старое приложение.
</Warning>

<Steps>
  <Step title="Экспорт данных из старого проекта">
    Откройте инструмент **Shell** в старом проекте. Вставьте эту команду и нажмите Enter. Она создаст в дереве файлов файл `backup.dump`:

    ```bash theme={null}
    pg_dump -Fc "$DATABASE_URL" --no-owner --no-privileges -f backup.dump
    ```

    Так экспортируется база данных **разработки**. Ваши рабочие данные обычно находятся в **продакшен**-базе данных. Чтобы экспортировать её:

    1. Откройте инструмент **Database**, выберите продакшен-базу данных и откройте **Settings**.
    2. Скопируйте строку подключения.
    3. В команде выше замените `"$DATABASE_URL"` на строку подключения, сохранив кавычки.

    Если не можете её найти, см. [Данные подключения](/ru/features/data-and-storage/connection-details).
  </Step>

  <Step title="Перенос файла дампа в новый проект">
    В дереве файлов старого проекта откройте меню из трёх точек рядом с `backup.dump` и скачайте файл. Затем загрузите его в новый проект через пункт **Upload files** в дереве файлов.

    Если вы копировали код через GitHub, не коммитьте дамп. Перенесите его отдельно, чтобы ваши данные никогда не попадали в репозиторий.
  </Step>

  <Step title="Импорт данных в новый проект">
    Откройте инструмент **Shell** в новом проекте. Вставьте эту команду и нажмите Enter:

    ```bash theme={null}
    pg_restore --clean --if-exists --single-transaction --no-owner --no-privileges --exit-on-error -d "$DATABASE_URL" backup.dump
    ```

    В таком виде импорт выполняется в базу данных **разработки** нового проекта. Именно это и нужно на Шаге 2.

    Для финального копирования на Шаге 3 нужна **продакшен**-база данных. В новом проекте откройте инструмент **Database**, выберите продакшен-базу данных, откройте **Settings**, скопируйте строку подключения и используйте её вместо `"$DATABASE_URL"`.

    Эта команда удаляет совпадающие объекты в целевой базе данных, а затем загружает данные. Если она завершилась без вывода, значит всё прошло успешно.
  </Step>
</Steps>

<Note>
  Если `pg_restore` завершается с ошибками ролей или политик, значит в вашей базе данных используются пользовательские роли PostgreSQL, которых пока нет в новом проекте. [Обратитесь в поддержку](https://replit.com/support) за помощью.
</Note>

<Note>
  Если в новом проекте используется [устаревшая база данных разработки Neon](/ru/features/data-and-storage/development-and-production#legacy-development-database), процесс публикации предложит вариант **Set up your production database with your current development data**. Он копирует то, что находится в базе данных разработки на момент публикации. Для тестирования это подходит, но для финального переключения используйте описанные выше шаги, чтобы получить самые свежие данные.
</Note>

<div id="re-create-what-doesnt-copy-over">
  ## Воссоздайте то, что не копируется
</div>

Остальная часть конфигурации проекта хранится за пределами файловой системы. Воссоздайте каждый элемент в новом проекте:

| Элемент             | Что делать                                                                                                                                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Secrets**         | Значения секретов никогда не покидают старый проект. Добавьте их заново в инструменте [Secrets](/ru/core-concepts/project-editor/app-setup/secrets) нового проекта, включая секреты для deployment.                                                             |
| **Account Secrets** | [Свяжите их](/ru/core-concepts/project-editor/app-setup/secrets#manage-account-secrets) с новым проектом. Если новый проект принадлежит другой учётной записи, сначала добавьте их в эту учётную запись.                                                        |
| **App Storage**     | Bucket не переносятся. В рамках одной учётной записи [добавьте существующий bucket](/ru/features/data-and-storage/object-storage#bucket-access-management) в новый проект. При переходе между учётными записями скачайте объекты и загрузите их в новый bucket. |
| **Connectors**      | Заново подключите каждую integration в разделе **Tools → Connectors** нового проекта. См. [обзор интеграций](/ru/features/integrations/overview).                                                                                                               |
| **Deployments**     | Копия не опубликована. [Опубликуйте](/ru/features/publishing/overview) её из нового workspace, как в [Шаге 2](#step-2-set-up-the-new-app).                                                                                                                      |
| **Custom Domains**  | Удалите домен из старого deployment, привяжите его к новому и обновите свои DNS-записи. Об этом — в [Шаге 3](#step-3-switch-your-users-to-the-new-app).                                                                                                      |
| **Collaborators**   | Пригласите соавторов заново и настройте [доступ](/ru/teams/identity-and-access-management/groups-and-permissions) в новом workspace.                                                                                                                            |
| **История Agent**   | Диалоги Agent и откаты по [checkpoint](/ru/features/version-control/checkpoints-and-rollbacks) остаются в старом проекте. Коммиты checkpoint переносятся вместе с историей Git, но откатиться к ним из копии не получится.                                      |

<div id="if-something-goes-wrong">
  ## Если что-то пошло не так
</div>

Старый project никуда не делся. Чтобы вернуться к нему:

1. В старом project откройте инструмент **Publishing** и выберите **Publish**.
2. Если вы переносили собственный домен, верните его обратно тем же способом.

Ваш App снова доступен — с теми данными, которые были на момент отключения. Ничего не потеряно.

<div id="clean-up">
  ## Очистка
</div>

Подождите около недели, чтобы убедиться, что новое приложение работает корректно. После этого:

* Удалите `backup.dump` из обоих проектов и со своего устройства. Каждая копия содержит полный экспорт ваших данных.
* При желании удалите старый проект.
