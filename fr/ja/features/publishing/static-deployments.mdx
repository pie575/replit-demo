title: "Déploiements statiques"
description: "Découvrez comment publier des sites web statiques et des applications frontend avec les déploiements statiques."
---

Les déploiements statiques hébergent les fichiers statiques de votre Replit App — HTML, CSS, JavaScript, etc. — sur un serveur cloud. Le serveur applique automatiquement des stratégies de mise en cache et de mise à l&#39;échelle afin de diffuser votre contenu rapidement et à moindre coût.

Les déploiements statiques conviennent parfaitement aux cas d&#39;usage suivants :

* Pages de destination marketing
* Sites portfolio
* Sites de documentation de produits et d&#39;API

<Note>
  Les déploiements statiques ne sont pas compatibles avec les Replit Apps créées avec Agent.
  Agent crée automatiquement des applications full-stack qui nécessitent un serveur backend.
  Pour les applications générées par Agent, utilisez l&#39;un des types de déploiement suivants :

  * [Déploiements Autoscale](/fr/ja/features/publishing/autoscale-deployments)
  * [Déploiements Reserved VM](/fr/ja/features/publishing/reserved-vm-deployments)
</Note>

<div id="section">
  ## Fonctionnalités
</div>

Les déploiements statiques incluent les fonctionnalités suivantes :

* **Hébergement économique** : vous ne payez que pour le volume de données diffusé par votre site web.
* **Options de routage HTTP** : configurez les en-têtes de réponse, les réécritures d&#39;URL et les redirections.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez l&#39;URL `<app-name>.replit.app` pour accéder à votre App.
* **Pages d&#39;erreur personnalisées** : créez et diffusez une page d&#39;erreur 404 personnalisée.
* **Surveillance** : consultez les journaux et suivez l&#39;état de vos Apps publiées.

<div id="section-2">
  ## Utilisation
</div>

Les déploiements statiques sont accessibles depuis l&#39;outil Publishing de l&#39;éditeur de projet.

<Accordion title="Comment accéder aux déploiements statiques">
  Depuis le **dock d&#39;outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône All tools" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils de l&#39;éditeur de projet.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Static**, puis **Set up your published app**.

  Depuis la **barre de recherche** :

  1. Sélectionnez la loupe <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> en haut pour ouvrir l&#39;outil de recherche
  2. Saisissez « Publishing » pour rechercher l&#39;outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l&#39;option **Static**, puis **Set up your published app**.
</Accordion>

<div id="section-3">
  ### Domaine principal
</div>

Indiquez la partie sous-domaine du nom d&#39;hôte de votre application publiée. Une fois la publication effectuée, votre app est accessible à l&#39;adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Domaines personnalisés](/fr/features/publishing/custom-domains).

<div id="section-4">
  ### プライベートデプロイ
</div>

<Info>
  La fonctionnalité d&#39;application publiée en privé est disponible avec les plans Pro et Enterprise.
</Info>

Les applications publiées en privé réservent l&#39;accès à votre application aux seuls membres de votre workspace, ou aux utilisateurs et groupes spécifiques que vous invitez.
Au moment de la publication, vous pouvez choisir entre les accès **Public**, **Password protected**, **Workspace only** et **Invite only**.

Pour savoir comment configurer un déploiement privé, consultez [Accès aux applications](/fr/features/publishing/private-deployments/).

<div id="section-5">
  ### Répertoire public
</div>

Indiquez le chemin du répertoire de base, dans votre Replit App, qui contient les fichiers statiques à diffuser publiquement.
Une fois le déploiement effectué, l&#39;hébergeur cloud diffuse toutes les pages et toutes les ressources de ce répertoire.

La valeur par défaut, `/`, correspond au répertoire racine de la Replit App.

<div id="section-6">
  ### Commande de build
</div>

Indiquez la commande de build à exécuter dans le shell de la Replit App lors de la création d&#39;un déploiement.

Par exemple, si vous générez un site statique avec <a href="https://gohugo.io/" target="_blank">Hugo</a>,
vous pouvez utiliser la commande `hugo --minify` pour générer les fichiers et optimiser la taille des fichiers d&#39;ressources.

<div id="section-7">
  ### Secrets de déploiement
</div>

Sélectionnez **Add deployment secret** pour ajouter les variables d&#39;environnement et les secrets nécessaires à l&#39;exécution sécurisée de vos commandes de build.

Par exemple, si votre générateur de site nécessite une clé API pour créer le site statique,
vous pouvez la transmettre sous la forme `API_KEY=<nom du secret>`.
