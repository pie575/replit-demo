---
title: "Replit 共同责任模型"
description: "了解在 Replit 上构建、部署和运营应用时，Replit 与您如何分担安全、合规和运营责任。"
---

在 Replit 上安全地构建和发布应用是双方的共同责任。Replit 负责保障 Replit Agent、平台以及运行客户工作负载的基础设施的安全。Replit 通过合理的控制措施和安全的默认设置来运营这些服务，并提供可用于保护应用和数据的工具。您则负责应用内容，以及使用和配置 Replit 提供的工具。

这是经过权衡的设计。Replit 希望您能够构建任何您能想象到的事物，而这种自由也意味着部分决策由您自行掌握。下表遵循现有的云和 AI 共同责任模式 ([Microsoft AI SRM](https://learn.microsoft.com/en-us/azure/security/fundamentals/shared-responsibility-ai)、[CSA AICM](https://cloudsecurityalliance.org/artifacts/ai-controls-matrix)) ，并以 [ISO/IEC 42001](https://www.iso.org/standard/42001) 和 [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) 为基础，概述了 Replit 的共同责任模型。

<div id="section-5">
  ## 责任划分方式
</div>

表中的大多数条目遵循以下三种模式之一。

* **机制与配置。** Replit 提供 RBAC、公开范围设置、MFA、SSO、数据驻留和保留期限等控制功能。您决定启用哪些功能以及如何配置。
* **检测与处置。** Replit 监控平台，并标记其能够发现的问题，例如存在漏洞的依赖项、滥用信号和平台异常。您负责监控和处置应用内部的问题，因为只有您知道“已解决”在您的具体情境中意味着什么。
* **Replit 提供与第三方。** 经 Replit 验证的 Skills、MCP 工具和 Connectors 由 Replit 审核。您自行连接、安装或配置的任何内容，均由您负责验证、配置、替换和取消。

有些条目完全由您负责：使用政策、访问控制、知识产权审查、最终用户隐私声明以及应用级渗透测试。这些事项取决于只有您才了解的具体情境。其他条目则由 Replit 管理，因为它们涉及您的应用构建和运行所依赖的平台本身。

这些模式会有意重复。因为在一个可以自由构建任何内容的平台上，这是划分责任唯一诚实的方式。

<div id="replit-agent-2">
  ## 与 Replit Agent 协作
</div>

您拥有 Agent 生成的代码，并对其负责。这意味着需要养成一些习惯。

1. **发布前请先审查。** Agent 能生成可运行的代码，但“能运行”和“正确”是两回事。请阅读 Agent 编写的代码，尤其是涉及身份验证、数据处理以及任何跨越信任边界的内容。让 Agent 编写测试并说明其推理过程，是在迭代过程中发现回归问题的好方法。
2. **不要在提示词中输入机密信息。** 请使用 Secrets 功能和 Connectors。不要将 API 密钥、令牌或凭据粘贴到聊天窗口中。Agent 无需以明文查看这些信息即可使用它们；一旦粘贴，原本受管理的机密信息就会变成未受管理的机密信息。
3. **说明业务逻辑和访问控制模型。** 请告知 Replit Agent 应用的哪些功能应允许哪些人访问。如果您的应用不应向所有人公开，请选择 Replit 的 Private 或 Password-protected 发布选项之一。
4. **谨慎批准敏感操作。** 当 Agent 建议发布应用、更改机密信息或发起外部调用时，human-in-the-loop 环节需要由您把关。请进行实际审查，而非形式上的点击。

<div id="section-6">
  ## 合规与事件响应
</div>

您有责任遵守 [Replit 服务条款](https://replit.com/terms-of-service)，并了解自身的合规和法律要求。若要了解 Replit 在合规方面提供或未提供的内容 (如 SOC 2 Type II、子处理者和认证) ，请访问 [replit.com/security](https://replit.com/security)。

如果您在 Replit 平台上发现漏洞，请按照 Replit 的[负责任披露](https://en.wikipedia.org/wiki/Coordinated_vulnerability_disclosure)流程，向 [security@replit.com](mailto:security@replit.com) 报告。如果您在自行构建的应用中发现漏洞，则需由您自行分类处理。平台事件将按照 Replit 的事件响应政策处理。对于发生在您的应用、数据和最终用户账户中的事件，您需要主动负责应对。
