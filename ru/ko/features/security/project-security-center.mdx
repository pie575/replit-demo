<div id="section-2">
  ## Автоматическое сканирование зависимостей
</div>

Автоматическое сканирование зависимостей сверяет пакеты проекта с общедоступными базами данных уязвимостей. Оно бесплатно и выполняется автоматически. Когда публикуются новые записи Common Vulnerabilities and Exposures (CVE), Replit сверяет их с зависимостями проекта и отображает совпадения на панели **Security** — повторное сканирование вручную не требуется.

Сканирование зависимостей поддерживает Node.js/npm, Python, Go, Rust, PHP и Ruby.

Автоматическое исправление зависимостей пока доступно только для Node.js/npm.

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect расширяет возможности автоматического сканирования зависимостей. Когда Replit обнаруживает соответствующую уязвимость, Agent подготавливает и тестирует исправление, а затем отправляет электронное письмо с прямой ссылкой. Исправление остаётся в ожидании проверки на панели **Security**. После применения исправления повторно опубликуйте App, чтобы изменения вошли в рабочую версию.

Auto-Protect охватывает только CVE в зависимостях. Для проверки кода приложения используйте [сканирование безопасности Agent](/ru/ko/features/security/agent-security-scans).

Обе настройки Auto-Protect по умолчанию отключены.

<Steps>
  <Step title="Включение подготовки исправлений">
    Администратор Workspace переходит в **Settings** &gt; **Account** &gt; **Дополнительно** и
    выбирает минимальный уровень критичности (low, medium, high, critical), начиная с которого
    Replit будет подготавливать меры по устранению уязвимостей.
  </Step>

  <Step title="Включение уведомлений по электронной почте">
    Перейдите в **Settings** &gt; **Personalization** &gt; **Email Notifications** и
    выберите минимальный уровень критичности, для которого хотите получать уведомления.
  </Step>
</Steps>

При появлении новой уязвимости Replit отправляет не более одного электронного письма на рабочее пространство со сводкой всех затронутых проектов. Перед применением исправления выберите **Go to Task**, чтобы проверить исправление, подготовленное Agent. После применения исправления уязвимость отображается как **pending republish**, пока вы не опубликуете новую версию.

<Note>
  За меры по устранению уязвимостей, подготовленные Agent, в том числе заранее с помощью
  Auto-Protect, взимается плата так же, как и за другие задачи Agent.
</Note>

<div id="section-3">
  ## Проверка обнаруженных проблем
</div>

Результаты проверки безопасности отображаются на панели **Security** и группируются по критичности.

| Критичность         | Описание                                                                      |
| ------------------- | ----------------------------------------------------------------------------- |
| Critical            | Непосредственная угроза, которую необходимо устранить перед публикацией       |
| High                | Серьёзная проблема, которая может быть использована при определённых условиях |
| Medium              | Потенциальная угроза с низкой вероятностью эксплуатации                       |
| Low / Informational | Незначительные проблемы и рекомендации по передовым практикам                 |

Проверяйте каждую обнаруженную проблему, прежде чем принять, исправить или проигнорировать её. Отправляйте принятые проблемы в Agent для устранения, а после внесения исправлений повторно запускайте соответствующее сканирование.

  ## Проверки безопасности при разработке и публикации
</div>

<div id="section-5">
  ### Сканирование безопасности во время сборки
</div>

Когда вы создаёте приложение с Agent, Replit автоматически проверяет файлы, изменённые Agent, на распространённые небезопасные шаблоны и жёстко закодированные секреты. Это не проверка всей кодовой базы, а первичная быстрая проверка в рамках рабочего процесса Agent. Её результаты не отображаются в виде отдельного отчёта на панели **Security**.

<div id="section-6">
  ### Проверки перед публикацией
</div>

Replit также выполняет сканирование безопасности перед публикацией. Настройка **Блокировать публикацию при критических уязвимостях** определяет, что произойдет, если сканирование выявит критические проблемы.

* **Вкл.**: публикация будет заблокирована, пока проблема не будет устранена или проигнорирована.
* **Выкл.**: публикация продолжится, а обнаруженные проблемы останутся для проверки.

Организации Enterprise могут сделать эту настройку обязательной для всех App.

Эти проверки дополняют, но не заменяют полное [сканирование безопасности Agent](/ru/ko/features/security/agent-security-scans) или [сканирование Level 3](/ru/ko/features/security/black-box-pen-tests).
