Replit에서 AI 기반 앱을 만들어 엔터프라이즈급 거버넌스와 보안이 내장된 채로 Microsoft Fabric에 바로 게시하세요. Microsoft Fabric integration은 거버넌스가 적용된 기업 데이터를 대시보드, 워크플로, AI 애플리케이션 같은 내부 도구로 바꿔 줍니다. 팀은 prompt에서 production까지 더 빠르게 도달하면서도, 인증과 접근 정책은 이미 신뢰해 온 Fabric 환경 안에 그대로 남습니다.

<div id="what-a-fabric-data-app-is">
  ## Fabric 데이터 앱이란
</div>

Fabric 데이터 앱은 [Power BI 시맨틱 모델](https://learn.microsoft.com/en-us/power-bi/connect-data/service-datasets-understand)에 [Data Analysis Expressions(DAX)](https://learn.microsoft.com/en-us/dax/) 쿼리를 실행해 Power BI charts를 렌더링하는 정적 React 앱입니다. 다음 몇 가지 특성이 개발 방식을 결정합니다.

* **Power BI 시맨틱 모델이 데이터 소스입니다.** charts는 연결한 시맨틱 모델(dataset)에 실행되는 DAX 쿼리로 구동됩니다.
* **설계상 읽기 전용입니다.** 앱은 DAX `EVALUATE`로 데이터를 읽을 뿐 Power BI에 다시 쓰지 않습니다. 쓰기 가능한 상태가 필요하다면 대시보드와 별도로 애플리케이션 database를 사용하세요.
* **Fabric 포털을 통해 렌더링됩니다.** 데이터 계층은 Microsoft Fabric 포털 내부에서 실행되며, 시맨틱 모델에 쿼리를 실행한 뒤 결과를 앱으로 반환합니다. 데이터는 사용자의 Fabric 환경 안에 그대로 유지됩니다.
* **Microsoft 인프라에서 호스팅됩니다.** 완성된 데이터 앱을 Microsoft 호스팅에 publish하면 Fabric 환경의 다른 구성 요소와 함께 실행할 수 있습니다.

<Note>
  Microsoft Fabric 데이터 앱을 사용하려면 Power BI 시맨틱 모델이 있는 Microsoft Fabric tenant에 대한 액세스 권한이 필요하며, preview 기간에는 승인된 테스터 프로그램 membership도 필요합니다.
</Note>

내부적으로는 [Rayfin](https://github.com/microsoft/rayfin)(애플리케이션 backend 구축용 오픈 소스 SDK 및 CLI)을 통해 Agent가 Fabric 데이터를 기반으로 production 수준의 앱을 정의하고 publish합니다.

모든 작업은 하나의 워크플로 안에서 이루어집니다. 앱을 설명하면 Agent가 뼈대를 만들고, 거버넌스가 적용된 Fabric 데이터에 연결한 다음, 조직의 Fabric tenant 안에서 실행되도록 publish하면 됩니다.

이 가이드에서는 빌더 흐름, 앱이 Fabric 데이터에 연결되는 방식, 팀과 자동화를 위한 옵션을 다룹니다. 다른 웨어하우스를 기반으로 하는 일반적인 data 대시보드는 [Data Visualization](/ko/features/artifact-types/data-apps)을 참고하세요.

<div id="use-cases">
  ## 활용 사례
</div>

이미 Microsoft 데이터 생태계에 투자한 조직이라면 내부 소프트웨어를 훨씬 빠르게 확보할 수 있습니다. 인증, API, 배포 도구, 거버넌스 정책을 일일이 연결하는 데 몇 주를 들이는 대신, 팀은 원하는 것을 설명하기만 하면 Agent가 대신 만들어 줍니다.

대표적인 활용 사례는 다음과 같습니다.

* 부서별 생산성 도구
* 운영 대시보드
* 데이터 탐색 도구
* 워크플로 자동화 앱
* 리포팅 인터페이스

엔터프라이즈 IT 관점에서는 거버넌스, 인증, 보안이 조직이 이미 관리 중인 Fabric 환경 안에 그대로 유지되므로, 빠른 앱 제작을 위해 중앙 집중식 통제를 포기할 필요가 없습니다.

<div id="build-a-fabric-data-app">
  ## Fabric 데이터 앱 만들기
</div>

빌더 워크플로는 대화형입니다. 전 과정을 Replit 안에서 진행하며, 인증과 데이터 접근은 필요한 시점에 Microsoft를 통해 이루어집니다.

<Steps>
  <Step title="Fabric template에서 시작하기">
    Replit 홈 페이지에서 **Templates** 드롭다운을 열고 **Org templates** 아래의 **Microsoft Fabric App**을 선택하세요. 그러면 Fabric 도구가 미리 로드된 상태로 Agent가 데이터 앱 워크플로로 전환됩니다.

    <Frame caption="Replit 홈 페이지에서 Microsoft Fabric App org template 선택하기(비공개 프리뷰 UI).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Templates 드롭다운이 열려 있고 Org templates 아래에 Microsoft Fabric App이 강조 표시된 Replit 홈 페이지" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="원하는 대시보드 설명하기">
    만들려는 대시보드나 보고 도구를 설명하는 prompt를 입력하세요. 예를 들면 &quot;우리 Fabric 매출 모델을 기반으로 전월 대비 매출 성장 대시보드를 만들어 줘.&quot;와 같이 입력합니다. DAX를 직접 작성할 필요는 없습니다. 쿼리는 Agent가 생성합니다.
  </Step>

  <Step title="Microsoft 계정으로 로그인하기">
    안내가 표시되면 Fabric 데이터가 있는 tenant에 Microsoft OAuth로 로그인하세요. 이렇게 하면 사용자가 접근 권한을 가진 시맨틱 모델을 Agent가 읽을 수 있도록 승인됩니다. 로그인에 사용하는 계정은 사용하려는 Fabric workspace에 접근할 수 있어야 합니다.
  </Step>

  <Step title="데이터 소스 추가하기">
    Agent가 요청하면 사용할 Power BI / Fabric 시맨틱 모델을 공유하세요. Fabric 포털의 전체 dataset URL(예: `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`)을 제공하거나, workspace ID와 dataset/항목 ID를 함께 제공하면 됩니다. Agent는 이 정보를 사용해 쿼리할 workspace와 시맨틱 모델을 식별합니다.

    해당 모델은 반드시 **Power BI 서비스에 게시**되어 있어야 하며, 로컬 `.pbix` 파일은 사용할 수 없습니다.

    <Frame caption="Power BI / Fabric 시맨틱 모델 링크를 요청하는 Agent(비공개 프리뷰 UI).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Agent 패널이 빌더에게 Power BI 또는 Fabric 시맨틱 모델을 전체 Fabric 포털 URL 또는 workspace ID와 dataset/항목 ID 형태로 공유해 달라고 요청하며, 모델이 Power BI 서비스에 게시되어 있어야 하므로 로컬 .pbix 파일은 사용할 수 없다고 안내하는 모습" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Agent가 만들고 개선하도록 하기">
    Agent는 시맨틱 모델의 schema를 살펴보고 DAX 쿼리를 작성한 뒤, 적절한 charts로 대시보드를 구성합니다. 결과를 검토한 다음 자연어로 변경을 요청하세요. filter 추가, chart 유형 변경, 지표 추가 등이 가능합니다.
  </Step>

  <Step title="게시하기(선택 사항)">
    대시보드가 준비되면 Microsoft 호스팅에 게시해 Fabric 환경 안에서 실행할 수 있습니다. 게시 과정은 별도로 다루며, 이 가이드는 데이터 연결과 앱 구축에 초점을 맞춥니다.
  </Step>
</Steps>

<div id="connecting-to-fabric-data">
  ## Fabric 데이터에 연결하기
</div>

데이터를 읽으려면 앱이 Microsoft Fabric에 인증된 방식으로 연결되어 있어야 합니다. Replit은 다음 두 가지 방법 중 하나로 이 연결을 설정합니다.

<div id="app-level-fabric-sign-in-viewers">
  ### 앱 수준 Fabric 로그인(Viewers)
</div>

게시된 데이터 앱의 Viewers는 connector를 직접 설정하지 않습니다. 앱에 내장된 Microsoft Fabric 통합 인증(SSO)으로 로그인하며, 앱은 Fabric 포털을 통해 해당 사용자의 ID로 데이터를 읽습니다. 이렇게 하면 기존 Fabric permissions에 따라 접근 권한이 그대로 관리됩니다.

<div id="the-microsoft-fabric-connector-the-easy-path-for-builders">
  ### Microsoft Fabric connector(빌더를 위한 손쉬운 방법)
</div>

빌더에게 **Microsoft Fabric connector**는 개발 중 데이터 접근 권한을 부여하는 편리한 방법입니다. 필수는 아니며, 반드시 거쳐야 하는 단계가 아닌 손쉬운 선택지입니다.

* 이를 가장 먼저 설정하는 빌더가 Microsoft와 **일회성 OAuth**를 완료합니다.
* **같은 project에 속한** 다른 협업자는 해당 연결을 그대로 **상속받습니다**.
* **다른 workspace**에서는 connector를 활성화하고 자체적으로 OAuth를 완료해야 합니다.
* OAuth를 수행한 계정은 대상 Fabric workspace에 접근할 수 있어야 합니다.

이 connector는 Microsoft Entra OAuth를 사용하며 사용 중인 tenant로 범위가 한정됩니다. 다른 Replit connector와 마찬가지로 project의 [Integrations](/ko/features/integrations/overview) 페이지에서 관리하세요. connector의 전반적인 개념은 [Managing your connectors](/ko/replitai/managing-connectors)를 참고하세요.

<Note>
  비공개 프리뷰 기간에는 Microsoft Fabric connector용으로 Replit이 관리하는 공유 자격 증명이 제공되지 않습니다. 빌더는 각자의 Microsoft Entra tenant를 통해 권한을 부여합니다.
</Note>

<div id="teams-and-automation">
  ## 팀 및 자동화
</div>

팀에서 함께 사용하거나 CI 같은 비대화형 환경에서는 대화형 OAuth가 항상 적합하지는 않습니다. 이런 경우에는 대화형으로 로그인하는 대신 프로젝트 [Secrets](/ko/core-concepts/project-editor/app-setup/secrets)에 **service principal** token을 저장해 사용하세요. 앱은 service principal의 ID로 Fabric 데이터를 읽습니다.

이는 머신 간(machine-to-machine) 구성에 가장 가까운 방식으로, Microsoft Entra에서 프로비저닝되고 Fabric workspace 접근 권한을 부여받은 비인간 ID가 사람의 개입 없이 앱을 인증합니다. 해당 service principal이 앱에서 쿼리하는 workspaces와 시맨틱 모델에 접근할 수 있는지 확인하세요.

<div id="troubleshooting">
  ## 문제 해결
</div>

<AccordionGroup>
  <Accordion title="app preview에서 데이터가 로드되지 않습니다">
    Fabric 데이터 계층은 Microsoft Fabric 포털을 통해 동작합니다. charts가 비어 있게 표시되거나 app preview에서 데이터를 불러오지 못한다면 Microsoft 로그인을 완료했는지, 로그인한 계정이 연결한 workspace와 시맨틱 모델에 접근할 수 있는지 확인하세요.
  </Accordion>

  <Accordion title="Agent가 시맨틱 모델을 찾지 못합니다">
    Fabric 포털에서 복사한 Power BI dataset 링크를 붙여넣었는지, 사용 중인 계정(또는 service principal)이 해당 workspace에 최소한 읽기 권한을 가지고 있는지 확인하세요. Agent가 workspace나 모델을 찾을 수 없다고 하면 dataset 링크를 다시 공유하세요.
  </Accordion>

  <Accordion title="connector가 멈추거나 연결을 반복해서 요청합니다">
    project의 [Integrations](/ko/features/integrations/overview) 페이지에서 Microsoft Fabric connector를 다시 승인하세요. OAuth로 인증한 계정이 Fabric workspace에 접근할 수 있는지 확인하세요. 팀이나 CI 환경에서는 Secrets를 통해 제공하는 service principal token 사용을 권장합니다.
  </Accordion>
</AccordionGroup>
