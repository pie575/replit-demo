<div id="o-que-o-sistema-de-tarefas">
  ## Что такое система задач?
</div>

**Задача** — это единица работы, которую Agent может спланировать и выполнить. Задачи позволяют Agent разбить более крупную цель на небольшие части, чтобы вы могли проверить каждую из них до внесения изменений в приложение.

Agent может работать в двух местах: в **основном потоке** и в **фоновых задачах**. Основной поток — это беседа, в которой вы описываете, чего хотите, уточняете направление и решаете, что применить к основной версии. Фоновые задачи — это отдельные ветки, в которых Agent независимо работает с изолированными копиями вашего проекта.

Используйте основной поток для определения направления и принятия решений. Используйте фоновые задачи для работы, которую можно выполнять параллельно. Фоновые задачи не изменяют основную версию, пока вы не проверите и не примените их.

Система задач помогает Agent организовывать эту работу. Когда вы описываете, что хотите создать, Agent может разбить ваш запрос на отдельные задачи и разместить их на доске со столбцами: **Черновики**, **Активные**, **Готовые** и **Завершённые**.

<Frame>
  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="Доска задач с задачами, распределёнными по столбцам «Черновики», «Активные», «Готовые» и «Завершённые»" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />
</Frame>

По мере выполнения каждая задача перемещается слева направо, поэтому вы сразу видите, что запланировано, над чем работает Agent, что готово к проверке и что завершено. Фоновые задачи автоматически ставятся в очередь на основе вашего плана, поэтому работа продолжается без перегрузки основного потока.

Когда задача готова, вы проверяете изменения и применяете их к основной версии или отклоняете их, если результат не соответствует вашим ожиданиям.

<div id="como-funcionam-as-tarefas-em-segundo-plano">
  ## Как работают фоновые задачи
</div>

<Steps>
  <Step title="Спланируйте задачи">
    Начните обсуждение в основном потоке или создайте новую ветку и спланируйте всё там. Agent изучает ваш проект, определяет, что даст наибольший эффект, и составляет подробный план для каждой задачи — включая то, что он сделает и что считается «готово».

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="Описание того, что нужно создать, в основном потоке; Agent предлагает и выполняет задачи" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="Просмотрите и примите">
    Agent предлагает набор задач — у каждой есть заголовок, описание и подробный план, который можно изучить через **Посмотреть план**. Просмотрите весь список и выберите:

    * **Принять задачи** — запустить все задачи и отправить их в фоновый режим
    * **Пересмотреть план** — попросить Agent скорректировать задачи перед стартом

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="Диалоговое окно созданных планов задач с четырьмя предложенными задачами и вариантами «Принять задачи» и «Пересмотреть план»" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="Задачи начинают выполняться">
    После принятия задачи начинают выполняться в изолированных копиях вашего проекта. Core выполняет 1 фоновую задачу за раз, а Pro поддерживает до 10 одновременных фоновых задач. Основная версия остаётся нетронутой, пока вы не решите применить изменения. Следить за ходом работы можно двумя способами:

    * **Просмотр по веткам** — каждая задача выполняется в собственной ветке с индикатором статуса в реальном времени, так что вы можете следить за любой задачей или подключиться к её обсуждению

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="Просмотр по веткам с несколькими задачами, выполняющимися параллельно, и индикаторами статуса" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **Просмотр в виде доски** — доска с колонками, где все задачи распределены по статусам: **Черновики**, **Активные**, **Готовые** и **Завершённые**

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="Просмотр в виде доски с задачами, распределёнными по колонкам «Черновики», «Активные», «Готовые» и «Завершённые»" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="Проверьте и примените">
    Когда задача завершается, Agent показывает, что он сделал — журнал работы, результаты тестов и живой предпросмотр изменений. Вы решаете, что делать дальше:

    * **Применить изменения к основной версии** — перенести результат задачи в ваш проект
    * **Отклонить** — отбросить изменения, если получилось не то, что вы хотели

    Agent автоматически разрешает конфликты при применении изменений из нескольких задач.

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="Экран проверки задачи с журналом работы Agent, результатами тестов и кнопкой «Применить изменения»" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="o-que-voc-pode-construir">
  ## Что можно создать
</div>

Система задач подходит для любого проекта. Вот несколько сценариев, где она особенно полезна:

* **Выпускайте крупные функции небольшими частями** — вынесите аутентификацию, дашборд и слой API в отдельные задачи, чтобы Agent работал над ними последовательно и без путаницы
* **Планируйте сложные проекты** — разбейте большую функцию на чётко очерченные задачи с зависимостями и уверенно приступайте к работе
* **Сравнивайте разные направления дизайна** — используйте отдельные задачи, чтобы опробовать несколько подходов к UI, и выберите лучший результат

<div id="perguntas-frequentes">
  ## Часто задаваемые вопросы
</div>

<Accordion title="Нужно ли мне менять подход к разработке?">
  Нет. Основной поток работает точно так же. Agent автоматически создаёт задачи в фоновом режиме по мере работы. Вы также можете использовать [режим Plan](/ru/pt/features/agent/plan-mode), чтобы просматривать задачи и управлять ими напрямую.
</Accordion>

<Accordion title="Почему мои задачи выполняются по одной?">
  Core выполняет по 1 фоновой задаче за раз. Pro поддерживает до 10 одновременных фоновых задач. Когда вы достигаете лимита своего тарифа, дополнительные задачи становятся в очередь и запускаются по мере освобождения мест.
</Accordion>

<Accordion title="Как Agent разрешает конфликты при применении фоновых задач?">
  Agent использует разрешение конфликтов с помощью ИИ. Он понимает, чего пыталась достичь каждая задача, и интеллектуально применяет изменения. Если что-то выглядит неправильно, вы можете попросить Agent исправить это в ветке.
</Accordion>

<Accordion title="Могут ли задачи зависеть друг от друга?">
  Да. Agent автоматически обнаруживает зависимости — например, задача, создающая дашборд, зависит от задачи, которая создаёт схему базы данных. Зависимые задачи ждут завершения необходимых предварительных задач.
</Accordion>

<Accordion title="В чём разница между архивированием и отменой задачи?">
  **Архивировать** применяется к сессиям планирования — черновикам, для которых разработка ещё не началась. Архивированные сессии планирования сохраняются и могут быть восстановлены в столбце **Завершённые**.

  **Отменить** применяется к задачам, которые уже перешли от планирования к разработке. Отмена останавливает задачу и удаляет результаты её работы, а отменённые задачи нельзя восстановить — вам потребуется создать новую задачу.
</Accordion>
