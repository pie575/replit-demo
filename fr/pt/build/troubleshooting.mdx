La publication transforme votre projet en app publique. Si la publication échoue ou si l’URL publique se comporte différemment du Preview, résolvez le problème dans l’ordre indiqué.

Cette page sert à la fois de guide de récupération Build et de référence pour résoudre les problèmes de déploiement. Commencez par la question la plus simple : l’app fonctionne-t-elle dans le Preview ?

<div id="o-que-voc-vai-conquistar">
  ## Ce que vous allez accomplir
</div>

À la fin de cette page, vous saurez si le problème vient de votre app, de la configuration de publication, des Secrets de production, du type de déploiement, de la configuration du port ou de l&#39;accès au réseau/DNS.

<div id="comece-com-o-preview">
  ## Commencez par le Preview
</div>

Avant de publier, vérifiez que l’app s’exécute correctement dans l’Éditeur de projet.

Sélectionnez **Run** en haut de l’Éditeur de projet et ouvrez le Preview. Si le Preview n’affiche pas votre app à une URL `replit.dev`, corrigez l’app avant de publier.

Demandez d’abord à Agent de diagnostiquer le Preview :

<AiPrompt>
  Cette app ne fonctionne pas dans le Preview.<br />
  Vérifiez la commande d’exécution, l’installation des dépendances, les erreurs de l’app, les ports et les Secrets manquants.<br />
  Corrigez d’abord le problème le plus simple et indiquez-moi comment vérifier que le Preview fonctionne avant de publier.
</AiPrompt>

Si le Preview ne fonctionne pas, la publication ne résoudra pas le problème.

<div id="se-o-preview-funciona-mas-a-publicao-falha">
  ## Si le Preview fonctionne mais que la publication échoue
</div>

Lorsque le Preview fonctionne mais que la publication échoue, vérifiez la configuration propre à la publication.

<div id="verificar-logs">
  ### Vérifier les logs
</div>

Ouvrez l&#39;onglet **Logs** dans le panneau **Publication**. Recherchez des stack traces, des paquets manquants, des commandes en échec, des variables d&#39;environnement manquantes ou des erreurs de démarrage.

Collez l&#39;erreur concernée dans Agent :

<AiPrompt>
  La publication a échoué avec cette sortie de log : [collez l&#39;erreur].<br />
  Explique la cause probable.<br />
  Dis-moi s&#39;il s&#39;agit d&#39;une erreur de commande, de dépendance, de Secret, de port, de build ou d&#39;app.<br />
  Recommande la correction la plus simple possible et explique-moi comment la vérifier.
</AiPrompt>

<div id="verificar-comandos-de-execuo-e-build">
  ### Vérifier les commandes d&#39;exécution et de build
</div>

Les erreurs les plus fréquentes sont les fautes de frappe, les flags incorrects, les mauvais fichiers d&#39;entrée ou les commandes qui ne fonctionnent qu&#39;en local.

Passez en revue les commandes dans le panneau **Publication**. Si l&#39;app nécessite une commande de build et une commande de démarrage, vérifiez que les deux sont correctes.

<div id="verificar-secrets-de-produo">
  ### Vérifier les Secrets de production
</div>

Les Secrets définis dans l&#39;Éditeur de projet ne sont pas transférés automatiquement vers l&#39;app publiée. Ajoutez tous les Secrets de production et les variables d&#39;environnement dans le panneau **Publication**.

L&#39;absence de Secrets peut entraîner des erreurs de valeurs indéfinies, l&#39;échec d&#39;appels d&#39;API, des échecs de connexion à la base de données, des erreurs de connexion utilisateur ou des échecs de paiement.

Consultez [Secrets](/fr/pt/core-concepts/project-editor/app-setup/secrets).

<div id="verificar-comportamento-de-processo-de-longa-durao">
  ### Vérifier le comportement du processus de longue durée
</div>

Les apps publiées attendent que le programme reste en cours d&#39;exécution. Si le programme s&#39;exécute une seule fois puis se termine, la plateforme le redémarre automatiquement.

Assurez-vous que votre application lance un processus de longue durée, tel qu&#39;un serveur web.

<div id="verificar-configurao-de-host-e-porta">
  ### Vérifier la configuration de l’hôte et du port
</div>

Si vous exécutez un serveur web, les déploiements peuvent détecter automatiquement le port utilisé par le serveur, mais celui-ci doit écouter sur `0.0.0.0`. Écouter uniquement sur `localhost` ou `127.0.0.1` ne fonctionne pas pour les apps publiées.

Si des [ports sont spécifiés dans la configuration `.replit`](/fr/pt/references/configuration/configuration), la détection automatique des ports est désactivée. Vous devez spécifier un port avec `externalPort` défini sur `80` pour que l’étape de promotion puisse se terminer. Vérifiez que le serveur écoute sur le `localPort` spécifié.

Demandez à Agent de vérifier attentivement les éléments suivants :

<AiPrompt>
  Vérifiez que cette app est correctement configurée pour la publication.<br />
  Confirmez que le serveur lance un processus de longue durée, écoute sur 0.0.0.0, utilise le port attendu et correspond à toute configuration de port dans le fichier .replit.<br />
  Ne modifiez pas le comportement de l’app au-delà des corrections nécessaires à la publication.
</AiPrompt>

<div id="verificar-tempo-de-health-check">
  ### Vérifier le temps du health check
</div>

Avant de marquer l&#39;app publié comme actif, Replit envoie une requête HTTP à l&#39;app. Si la page d&#39;accueil met plus de cinq secondes à répondre, le health check peut expirer et la publication peut échouer à l&#39;étape finale.

Si le démarrage est lent, demandez à Agent de réduire le travail effectué à l&#39;initialisation, de déclencher les traitements lourds uniquement après une action de l&#39;utilisateur ou de mettre les données en cache lorsque c&#39;est pertinent.

<div id="se-a-publicao-for-bem-sucedida-mas-a-url-pblica-estiver-quebrada">
  ## Si la publication réussit mais que l&#39;URL publique ne fonctionne pas
</div>

Si le Preview fonctionne et que la publication réussit, mais que l&#39;URL publique ne fonctionne pas, comparez le comportement du Preview avec celui de la production.

Vérifiez :

* Les Secrets de production et les variables d&#39;environnement.
* Les paramètres de connexion à la base de données.
* Les URL de callback ou de redirection de connexion.
* Les paramètres de webhook ou de redirection de paiement.
* Les listes d&#39;autorisation d&#39;API ou la configuration CORS.
* Les fichiers écrits localement au lieu d&#39;être stockés dans une base de données ou un service de stockage.
* La mise en page mobile et les différences entre navigateurs.

Demandez à l&#39;Agent de comparer les environnements :

<AiPrompt>
  L&#39;app fonctionne dans le Preview mais pas sur l&#39;URL publiée.<br />
  Aide-moi à comparer le comportement du Preview avec celui de la production.<br />
  Vérifie les Secrets, les paramètres de base de données, les appels d&#39;API, les redirections de connexion, les redirections de paiement, la sortie du build et les logs.<br />
  Indique-moi la prochaine vérification la plus sûre.
</AiPrompt>

<div id="problemas-com-implantaes-estticas">
  ## Problèmes liés aux déploiements statiques
</div>

Les déploiements statiques servent des fichiers statiques comme HTML, CSS et JavaScript.

Si votre app fait appel à des traitements côté serveur, des routes d&#39;API, des callbacks d&#39;authentification, des appels à une base de données depuis le serveur ou une logique backend de longue durée, elle n&#39;est sans doute pas un bon candidat pour les déploiements statiques. Modifiez le type de déploiement en Autoscale dans le panneau **Publication**.

Les problèmes liés aux déploiements statiques viennent le plus souvent d&#39;un répertoire public incorrect ou du choix du type Statique pour une app qui nécessite un serveur.

<div id="limites-de-arquivo-e-tamanho">
  ## Limites de fichiers et de taille
</div>

Les déploiements VM réservée et Autoscale prennent en charge les Apps Replit jusqu&#39;à 8 Go. Les déploiements statiques prennent en charge jusqu&#39;à 1 Go.

Pour réduire la taille de l&#39;App, supprimez les fichiers inutiles, évitez de committer les sorties générées ou utilisez un stockage externe pour les assets volumineux.

<Warning>
  Le système de fichiers des apps publiés n&#39;est pas persistant : il est réinitialisé à chaque publication. Pour conserver vos données, utilisez une base de données comme [SQL Database](/fr/pt/features/data-and-storage/sql-database).
</Warning>

Si des fichiers importés ou des données générées disparaissent après la publication, stockez-les dans une base de données ou un service de stockage plutôt que dans le système de fichiers de l&#39;App.

<div id="problemas-de-acesso-com-urls-replitapp-e-replitdev">
  ## Problèmes d’accès aux URL `replit.app` et `replit.dev`
</div>

Si vous avez des difficultés à accéder à l’app via le domaine `replit.app` ou `replit.dev`, des filtres web ou des restrictions réseau peuvent en être la cause.

Essayez d’utiliser des résolveurs DNS publics, tels que Google DNS (`8.8.8.8`) ou Cloudflare DNS (`1.1.1.1`).

<div id="alterar-configuraes-de-dns">
  ### Modifier les paramètres DNS
</div>

<Tabs>
  <Tab title="Windows">
    1. Ouvrez le **Panneau de configuration**.
    2. Accédez au **Centre Réseau et partage**.
    3. Sélectionnez **Modifier les paramètres de la carte** à gauche.
    4. Faites un clic droit sur la connexion réseau active et sélectionnez **Propriétés**.
    5. Sélectionnez **Protocole Internet version 4 (TCP/IPv4)**, puis **Propriétés**.
    6. Choisissez **Utiliser l&#39;adresse de serveur DNS suivante**.
    7. Saisissez l&#39;adresse IP d&#39;un serveur DNS public, par exemple `8.8.8.8` pour Google DNS ou `1.1.1.1` pour Cloudflare DNS.
    8. Sélectionnez **OK** pour enregistrer les modifications.

    Pour des instructions plus détaillées, consultez le [guide de configuration DNS de Microsoft](https://support.microsoft.com/en-us/windows/change-tcp-ip-settings-bd0a07af-15f5-cd6a-363f-ca2b6f391ace).
  </Tab>

  <Tab title="macOS">
    1. Ouvrez les **Préférences Système**.
    2. Sélectionnez **Réseau**.
    3. Sélectionnez votre connexion réseau active à gauche.
    4. Sélectionnez **Avancé** en bas à droite.
    5. Accédez à l&#39;onglet **DNS**.
    6. Sélectionnez le bouton **+** pour ajouter un serveur DNS.
    7. Saisissez l&#39;adresse IP d&#39;un serveur DNS public, par exemple `8.8.8.8` pour Google DNS ou `1.1.1.1` pour Cloudflare DNS.
    8. Sélectionnez **OK**, puis **Appliquer**.

    Pour des instructions plus détaillées, consultez le [guide de configuration DNS d&#39;Apple](https://support.apple.com/guide/mac-help/change-dns-settings-on-mac-mh14127/mac).
  </Tab>

  <Tab title="Linux">
    1. Modifiez le fichier `/etc/resolv.conf` pour y ajouter des serveurs DNS publics. La méthode exacte varie selon la distribution.
    2. Ajoutez les lignes suivantes :

    ```bash theme={null}
    nameserver 8.8.8.8
    nameserver 1.1.1.1
    ```

    Pour en savoir plus sur la configuration DNS dans les différentes distributions, consultez le [guide de configuration réseau du Wiki Debian](https://wiki.debian.org/NetworkConfiguration#Defining_the_.28DNS.29_Nameservers).
  </Tab>
</Tabs>

<div id="limpar-cache-de-dns">
  ### Vider le cache DNS
</div>

Après avoir modifié les paramètres DNS, videz le cache DNS pour appliquer la nouvelle configuration :

* **Windows** : exécutez `ipconfig /flushdns` dans l’invite de commandes.
* **macOS et Linux** : exécutez `sudo systemctl restart NetworkManager` dans le terminal. La commande exacte peut varier selon la distribution.

<Note>
  Afin d’améliorer les performances régionales et la stabilité, les URL `replit.dev` de
  vos apps Replit peuvent occasionnellement changer lors de migrations de cluster. Une fois
  la migration terminée, les URL restent stables pendant environ un an,
  sauf si vous demandez explicitement un changement d’emplacement.
</Note>

<div id="publicar-uma-aplicao-streamlit">
  ## Publier une application Streamlit
</div>

Les applications Streamlit sont compatibles avec les Déploiements Replit. Le plus simple pour démarrer est d&#39;utiliser le [template Streamlit](https://replit.com/@replit/Streamlit?v=1).

Vous pouvez également définir la commande d&#39;exécution pour la publication comme suit :

```bash theme={null}
streamlit run --server.address 0.0.0.0 --server.headless true --server.enableCORS=false --server.enableWebsocketCompression=false main.py
```

Si votre application utilise un autre fichier d&#39;entrée, remplacez `main.py` par le nom de votre fichier.

<div id="voc-terminou-quando">
  ## Vous avez terminé lorsque
</div>

* Le Preview fonctionne.
* La publication aboutit.
* L&#39;URL publique se charge.
* Le flux principal de l&#39;app fonctionne sur l&#39;URL publique.
* Les Secrets et les paramètres de production sont configurés.
* Les logs ne révèlent aucune erreur de démarrage masquée.
