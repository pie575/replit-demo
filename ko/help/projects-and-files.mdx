여기서는 project와 파일을 다루는 방법을 안내합니다. 관련 자료는 [Secrets](/ko/core-concepts/project-editor/app-setup/secrets), [Checkpoints와 rollback](/ko/features/version-control/checkpoints-and-rollbacks), [integration 개요](/ko/features/integrations/overview)에서 확인하세요.

<AccordionGroup>
  <Accordion title="Resend 또는 다른 이메일 서비스를 Replit App에 연결하려면 어떻게 해야 하나요?">
    project을 열고 **Tools → Connectors**로 이동한 뒤, 원하는 서비스(예: Resend)를 찾아 연결하세요. 승인이 완료되면 API key가 project에 secret으로 저장됩니다. 사용자 지정 이메일 도메인을 설정하려면, 해당 서비스가 안내하는 DNS 레코드를 DNS provider에 추가하세요.

    사용 가능한 connector는 [integrations 개요](/ko/features/integrations/overview)와 [Add integrations](/ko/build/add-integrations)에서 확인하세요.
  </Accordion>

  <Accordion title="실수로 project를 삭제했는데, 복구할 수 있나요?">
    삭제된 project는 일정 기간 동안 복원할 수 있습니다. 아무 project에서나 Shell을 열고 다음 명령을 실행하세요:

    ```bash theme={null}
    trash view
    trash restore your-project-name
    ```

    retention 기간이 지나면 삭제된 project는 영구적으로 삭제됩니다. 이미 기간이 지났다면 [Replit Support에 문의](https://replit.com/support)하세요.
  </Accordion>

  <Accordion title="Replit 프로젝트를 다운로드하거나 내보내려면 어떻게 해야 하나요?">
    파일 트리 상단의 점 세 개 메뉴를 선택한 다음 **Download as zip**을 선택하세요. 규모가 큰 project는 다운로드에 시간이 다소 걸릴 수 있습니다. 다운로드에 실패하면 Shell을 열고 `zip -r project.zip .`을 실행한 후, 파일 트리에서 `project.zip`을 다운로드하세요.
  </Accordion>

  <Accordion title="프로젝트를 공유하거나 공동 작업자를 추가하려면 어떻게 하나요?">
    세 가지 방법이 있습니다:

    * **읽기 전용**—project의 공개 설정을 공개로 지정하면 링크를 가진 누구나 볼 수 있습니다.
    * **초대를 통한 편집 권한**—**Invite**를 선택하고 사용자 이름이나 이메일을 입력한 뒤 권한 수준을 설정합니다.
    * **참여 링크**—**Invite**에서 참여 링크를 만들면 링크를 가진 누구나 참여해 편집할 수 있습니다.

    Core는 최대 5명, Pro는 최대 15명의 공동 작업자를 지원하며, 공동 작업자가 내 project를 편집하는 데 유료 plan은 필요하지 않습니다. [Workspaces](/ko/features/collaboration/workspaces)를 참조하세요.
  </Accordion>

  <Accordion title="GitHub 리포지토리를 Replit에 연결하려면 어떻게 하나요?">
    계정의 연결된 서비스에서 GitHub 계정을 연결한 다음, 프로젝트에서 [Git 도구](/ko/features/workspace-tools/git-interface)를 열고 저장소를 연결하세요. 양방향 동기화를 사용하려면 Git 창에서 자동 동기화를 켜세요. 기존 저장소를 가져오려면 [provider에서 가져오기](/ko/build/import-from-providers)를 참고하세요.

    Git 동기화가 작동하지 않으면 연결된 서비스에서 GitHub를 다시 연결하세요. 세분화된 개인용 액세스 토큰을 사용하면 연결이 더 안정적입니다.
  </Accordion>

  <Accordion title="Repl 실행 속도가 느리거나 편집기가 버벅일 때 어떻게 해야 하나요?">
    에디터가 느리다면 다음을 시도해 보세요.

    * `Cmd+Shift+R`(Mac) 또는 `Ctrl+Shift+R`(Windows)로 강력 새로고침합니다.
    * 사용하지 않는 파일 탭을 닫습니다.
    * `Cmd+K`(Mac) 또는 `Ctrl+K`(Windows)로 명령 팔레트를 열고 **Restart compute**를 검색해 선택합니다.
    * 확장 프로그램이 원인인지 확인하려면 다른 브라우저에서 실행해 봅니다.

    에디터 지연이 아니라 코드 실행 자체가 느린 경우에는 과도한 루프나 메모리 한도를 확인하세요. CPU와 메모리 사용량은 에디터 하단의 리소스 패널에서 확인할 수 있습니다.
  </Accordion>

  <Accordion title="프로젝트에서 환경 변수와 secret을 어떻게 사용하나요?">
    **Secrets** 도구(자물쇠 아이콘)를 열고 **+ New secret**을 선택한 다음 키와 값을 입력하세요. 코드에서는 `process.env.API_KEY`(Node.js) 또는 `os.environ["API_KEY"]`(Python)로 값을 읽을 수 있습니다.

    개발 환경의 [Secrets](/ko/core-concepts/project-editor/app-setup/secrets) 패널에 있는 secret은 에디터에서만 사용할 수 있습니다. published app에서 사용하려면 동일한 키를 deployment secrets에도 추가해야 합니다. 두 영역은 설계상 서로 분리되어 있습니다.
  </Accordion>

  <Accordion title="Account Secrets(볼트)는 어떻게 사용하나요?">
    [Account Secrets](/ko/core-concepts/project-editor/app-setup/secrets)는 모든 project에서 사용할 수 있어 여러 곳에서 재사용하는 키를 관리할 때 유용합니다. 계정 설정에서 추가해 두면 본인이 소유한 모든 project에서 사용할 수 있습니다. 동일한 키가 Account Secrets와 project의 Secrets pane에 모두 있는 경우에는 project 수준의 값이 우선 적용됩니다.
  </Accordion>

  <Accordion title="Git 병합 충돌이나 손상된 Git 상태를 어떻게 복구하나요?">
    Shell을 열고 `git status`를 실행해 충돌을 확인하세요.

    <Warning>다음 두 명령은 커밋하지 않은 변경 사항을 삭제하며, 되돌릴 수 없습니다. 보관하려는 내용이 있다면 먼저 저장하세요. 예를 들어 수정한 파일을 프로젝트 밖으로 복사해 두면 됩니다.</Warning>

    로컬 변경 사항을 버리고 마지막 정상 상태로 되돌리려면 `git checkout -- .`을, 마지막 커밋 시점으로 되돌리려면 `git reset --hard HEAD`를 실행하세요.

    `.git` 폴더가 손상되어 Git 명령이 실패한다면 새 Agent chat을 열고 오류 메시지를 붙여넣어 보세요. Agent가 저장소를 복구해 주는 경우가 많습니다. [재해 복구](/ko/features/version-control/disaster-recovery)를 참고하세요.
  </Accordion>

  <Accordion title="프로젝트를 이전 checkpoint로 어떻게 롤백하나요?">
    Replit은 Agent가 작업하는 동안 [checkpoint](/ko/features/version-control/checkpoints-and-rollbacks)를 저장합니다. Agent 패널에서 되돌리려는 변경 사항 직전의 메시지를 찾아 그 옆의 rollback 옵션을 선택한 다음 확인하세요.

    <Note>
      Replit은 더 이상 published app을 previous version으로 되돌리는 기능을 지원하지 않습니다. published app을 되돌리려면 위에서 설명한 대로 project를 이전 checkpoint로 rollback한 다음, 다시 Publish하여 해당 상태를 재배포하세요. 파일 하나만 복구하려면 해당 파일을 열고 파일 이름을 선택한 후 **Show history**로 previous version을 복원하세요. 자세한 내용은 [File history](/ko/features/version-control/file-history)를 참조하세요.
    </Note>
  </Accordion>

  <Accordion title="프로젝트를 다른 Replit 계정으로 어떻게 이전하나요?">
    project는 직접 이전할 수 없지만 복사는 가능합니다. 가장 쉬운 방법은 대상 계정에 project를 공유한 뒤 그 계정에서 fork하는 것입니다. 또는 project를 zip으로 download한 다음 다른 계정의 새 Repl에 다시 upload해도 됩니다.

    복사한 후에는 새 project에서 secret, database, deployment 구성을 다시 설정하세요. 이 항목들은 복사본에 포함되지 않습니다. database 데이터를 옮기는 방법을 포함한 단계별 안내는 [project를 다른 workspace로 수동 복사하기](/ko/teams/identity-and-access-management/manually-copy-projects)를 참고하세요.
  </Accordion>
</AccordionGroup>
