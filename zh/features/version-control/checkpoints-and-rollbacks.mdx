使用 Replit，你再也不用担心丢失工作成果。

Replit 的检查点和回滚系统为整个开发环境提供全面的版本控制和状态管理。

使用 Replit Agent 时，检查点会自动保存完整的项目状态。其中不仅包括代码更改，还包括项目文件、AI 对话上下文和已连接的数据库。

<div id="what-are-checkpoints">
  ## 什么是 checkpoint？
</div>

**checkpoint** 是 Agent 在关键开发节点自动创建的 Replit App 状态完整快照。传统版本控制只跟踪代码变更，而 Replit checkpoint 会保存完整的开发上下文。

你可以将 checkpoint 视为电子游戏中的存档点——随时都可以回到应用可正常运行的版本。

<Frame>
  <img src="/assets/mirror/agent-checkpoint-8e5b8b315c02.png" alt="显示 Rollback 选项的 Agent checkpoint 界面" width="1554" height="876" data-path="images/replitai/agent-checkpoint.png" />
</Frame>

<div id="complete-state-capture">
  ### 完整状态捕获
</div>

每个 checkpoint 都会保存：

* **Project 文件**：所有文件、目录、已安装的软件包和项目配置
* **AI 对话上下文**：形成当前状态的完整对话历史和上下文
* **环境配置**：运行时设置和发布配置
* **Agent 记忆**：AI 对您项目架构、偏好和模式的理解
* **数据库内容**：创建 checkpoint 时数据库中的数据和架构

这种全面的保存方式让您可以放心尝试各种更改，因为您不仅可以恢复代码，还能恢复整个开发上下文。

<div id="how-rollbacks-work">
  ## 回滚的工作原理
</div>

**Rollback** 功能让您只需单击一下，即可将 Replit App 恢复到任意先前的 checkpoint 状态。这比传统的 Git revert 操作强大得多。

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="显示回滚选项的 checkpoint 回滚界面" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

回滚操作安全且结果可预测：

* **非破坏性预览**：部分界面允许您在回滚前预览 checkpoint 状态
* **清晰的边界**：每个 checkpoint 都代表一个逻辑上的开发里程碑
* **Conversation 连续性**：系统会保留 AI 上下文，因此您可以从恢复后的状态继续构建
* **即时生效**：回滚会立即在整个开发环境中生效

<div id="rolling-back">
  ### 回滚
</div>

当你回滚到之前的 checkpoint 时，项目会恢复到当时的状态，包括：

1. **完整的项目状态**：所有项目文件恢复到所选 checkpoint 时的确切状态
2. **AI 对话上下文**：Agent 对话恢复到该 checkpoint 时的状态，保持上下文连贯
3. **项目配置**：依赖项、软件包和运行时配置
4. **开发环境**：工具配置和 Project Editor 设置
5. **数据库内容 (可选)&#x20;**：选择该项后，数据库将恢复到该 checkpoint 时的状态

<Info>
  默认情况下，回滚不会更改你的数据库。若要在回滚中一并恢复 development database，请在“其他回滚选项”中选择“数据库”。

  请注意，此回滚功能不会自动恢复你的 **[production database](/zh/features/data-and-storage/development-and-production)**。
  若要了解如何将 production database 恢复到过去的某个时间点，请参阅[执行时间点恢复的相关文档](/zh/features/data-and-storage/development-and-production)。
</Info>

<Warning>
  使用回滚功能会将 Replit App 恢复到之前的状态，该时间点之后的所有更改都会被移除，包括代码修改。如果你选择恢复数据库，数据库的更改同样会被还原。
</Warning>

<div id="rolling-forward">
  ### 向前恢复
</div>

Replit 中的检查点支持双向操作——你可以在 Project 历史记录中前后移动。
这样你可以灵活浏览开发时间线，无需担心丢失工作成果。

如果回滚过头，或想恢复较后检查点中的更改，可以通过**向前恢复**在检查点历史记录中继续前进。这样你便能在 Project 时间线上自由导航，而不会丢失工作成果。

要向前恢复，请在 Agent 标签页中点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="history icon" width="24" height="24" data-path="images/icons/history.svg" /> 以打开历史记录视图，然后选择当前所在位置之后的检查点。

<Info>
  只有当时间线上当前所在位置之后还有检查点时，才能向前恢复。回滚后创建新的更改时，这些后续检查点会成为另一条历史分支的一部分。
</Info>

这种双向导航让你可以完全掌控 Project 时间线，确保工作成果始终可以恢复。

<div id="checkpoint-creation">
  ## Checkpoint 创建
</div>

Checkpoint 由 Replit 的 AI 工具在开发过程中的关键节点自动创建。

<div id="agent-checkpoints">
  ### Agent checkpoint
</div>

[Replit Agent](/zh/features/agent/overview) 会在以下情况下创建 checkpoint：

* **功能完成**：成功实现所需功能后
* **重要里程碑**：复杂 task 取得重大进展时
* **稳定状态**：已实现的更改经过测试和验证后
* **错误恢复**：尝试修复关键问题前

<div id="checkpoint-characteristics">
  ### Checkpoint 特性
</div>

每个 checkpoint 都包含：

* **AI 生成的描述**：清晰概述已完成的工作
* **时间戳信息**：提供精确的创建时间，便于识别
* **变更范围**：标明已修改的文件、功能或系统
* **账单信息**：对于 Agent，按 checkpoint 透明追踪成本

<div id="using-checkpoints-and-rollbacks">
  ## 使用 checkpoint 和 Rollback
</div>

<div id="finding-checkpoints">
  ### 查找检查点
</div>

检查点会显示在 Project Editor 的多个位置：

**Agent 选项卡**：查看所有由 Agent 创建的检查点，包括说明和回滚选项
**Git 面板**：将检查点作为 Git 提交查看，并享受完整的版本控制集成
**历史记录视图**：在 Agent chat 中，点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" />，即可查看所有检查点及其进展的完整时间线

<div id="performing-rollbacks">
  ### 执行回滚
</div>

根据您从何处发起回滚，具体流程会略有不同：

<div id="from-agent-tab">
  #### 在 Agent 选项卡中
</div>

<Steps>
  <Step title="进入 Agent">
    在 Project Editor 中打开 **Agent** 选项卡，查看所有由 Agent 创建的 checkpoint。
  </Step>

  <Step title="选择 checkpoint">
    找到要恢复的 checkpoint，然后选择 **Rollback to here**。
  </Step>

  <Step title="确认回滚">
    查看回滚警告并确认，将您的 App 恢复到所选状态。
  </Step>

  <Step title="验证恢复结果">
    检查项目文件、数据库和 AI 上下文是否与恢复后的 checkpoint 状态一致。
  </Step>
</Steps>

<div id="best-practices">
  ### 最佳实践
</div>

**合理运用检查点**：

* 每个重要检查点后都应测试 App，确保其稳定性
* 除自动检查点外，还应创建手动 Git 提交，以便长期跟踪版本
* 查看检查点描述，了解具体变更内容

**Rollback 注意事项**：

* Rollback 前务必确认变更范围
* 考虑对数据库和外部集成的影响
* 将 Rollback 情况告知协作者，确保团队成员了解相关情况

**迭代开发**：

* 采用增量式 Build，充分利用频繁创建的检查点
* 使用 Rollback 安全地探索不同的实现方案
* 利用 AI 上下文保留功能，在 Rollback 后继续 Conversation

<div id="integration-with-version-control">
  ## 与版本控制的集成
</div>

Checkpoint 可与 Replit 更广泛的版本控制生态无缝协作：

<div id="git-integration">
  ### Git 集成
</div>

* **Git 提交生成**：每个 checkpoint 都会创建相应的 Git 提交
* **分支兼容性**：checkpoint 遵循分支结构和合并工作流
* **远程同步**：GitHub 集成可保持 checkpoint 同步
* **命令行访问**：可在使用 checkpoint 的同时继续使用完整的 Git 功能

<div id="collaboration-features">
  ### 协作功能
</div>

* **团队可见性**：所有项目协作者都能查看检查点
* **预防合并冲突**：检查点的创建时机可降低冲突发生的可能性
* **共享上下文**：AI 对话上下文可帮助团队成员理解变更
* **实时更新**：协作者可实时看到检查点创建

<div id="advanced-features">
  ## 高级功能
</div>

<div id="checkpoint-previews">
  ### Checkpoint 预览
</div>

部分界面支持 checkpoint 预览功能：

* **可视化对比**：查看应用在不同 checkpoint 状态下的外观
* **无损探索**：无需实际回滚即可预览
* **进度跟踪**：了解应用随时间推移的演变过程
* **迭代对比**：比较不同的实现方案

<div id="cross-session-rollbacks">
  ### 跨会话回滚
</div>

适用于高级构建者和团队管理员：

* **扩展历史记录**：可访问多个开发会话中的检查点
* **管理控制**：团队管理员可跨用户会话执行回滚
* **审计追踪**：完整记录检查点创建和回滚操作的历史

<div id="use-cases">
  ## 使用场景
</div>

<div id="experimental-development">
  ### 实验性开发
</div>

检查点让你可以放心大胆地进行实验：

* 尝试新功能，随时可以轻松回退
* 测试不同的架构方案
* 探索不同的界面设计或用户流程
* 借助安全保障实现复杂集成

<div id="debugging-and-recovery">
  ### 调试与恢复
</div>

出现问题时，checkpoint 可提供可靠的恢复能力：

* 引入 bug 后回滚到正常运行的状态
* 通过比较不同 checkpoint 的状态来定位问题
* 在数据损坏后恢复数据库完整性
* 恢复意外删除或修改的内容

<div id="learning-and-iteration">
  ### 学习与迭代
</div>

检查点支持教育场景下的开发：

* 比较不同的实现策略
* 通过检查点的推进过程了解 AI 的决策过程
* 探索功能的演变过程，加深理解
* 在可回滚的保障下练习新技术
