---

Каждое Replit App использует две базы данных. **База данных разработки** — это среда, в которой вы и Agent экспериментируете в процессе создания приложения. **Продакшен-база данных** хранит реальные данные, на которых работает ваше опубликованное приложение, и обеспечивает их сохранность, пока вы продолжаете разработку.

<div id="section">
  ## Сравнение
</div>

| Аспект         | База данных разработки                                 | Продакшен-база данных                                                       |
| -------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Назначение** | Эксперименты и разработка функций                          | Работа с реальными пользователями и хранение бизнес-данных                 |
| **Данные**     | Тестовые данные, фиктивные записи, небольшие наборы данных | Реальные пользовательские данные, критически важная для бизнеса информация |
| **Создание**   | Создаётся автоматически для каждого Replit App             | Создаётся при публикации приложения                                        |
| **Agent**      | Agent может создавать и изменять таблицы                   | Agent не имеет доступа                                                     |
| **Изменения**  | Частые изменения схемы, быстрые итерации                   | Продуманные, спланированные изменения, применяемые при публикации          |
| **Оплата**     | Бесплатно включена в каждый Replit App                     | Оплата по объёму использования                                             |

<Note>
  Agent не может изменять продакшен-базу данных. Это ограничение введено ради её безопасности.

  Agent может редактировать базу данных разработки. При публикации изменения её структуры, внесённые Agent (добавление или удаление столбцов и таблиц), применяются к продакшен-базе данных.

  Продакшн-данные всегда можно отредактировать вручную. Откройте инструмент **Database**, выберите продакшен-базу данных, откройте **My Data** и включите **Edit**.
</Note>

<div id="section-2">
  ## Создание продакшен-базы данных при публикации
</div>

У опубликованного приложения появляется отдельная продакшен-база данных, независимая от базы данных разработки, с которой вы работаете при создании приложения.

* **Текущая инфраструктура (Helium)**: Replit при необходимости создаёт продакшен-базу данных во время публикации. Дополнительная настройка не требуется.
* **Устаревшие базы данных разработки Neon**: продакшен-база данных создаётся в настройках публикации. Во время публикации откройте **Production database settings** и включите **Create production database**. При необходимости также включите **Set up your production database with your current development data**, чтобы скопировать текущие данные разработки.

<Frame caption="Production database settings в Publishing">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="Настройки публикации с параметром Create production database" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  Копируйте данные разработки в продакшен только в том случае, если их безопасно использовать в работающем приложении. Данные разработки могут содержать тестовые учётные записи, демонстрационные записи или незавершённый контент.
</Warning>

После публикации приложение использует продакшен-базу данных, а Project Editor продолжает работать с базой данных разработки, поэтому дальнейшие изменения в ходе разработки не затрагивают напрямую рабочие данные.

<div id="section-3">
  ## Пул соединений
</div>

По умолчанию в продакшен-базе данных пул соединений не включён. Приложение подключается к базе данных напрямую по строке подключения `DATABASE_URL`, поэтому большинству фреймворков приходится самостоятельно управлять пулом соединений на стороне клиента.

<Note>
  Каждый проект Neon содержит как строку прямого подключения, так и строку подключения через пул. Строка прямого подключения имеет вид `postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`.

  Чтобы использовать подключение через пул, добавьте к имени хоста `-pooler`: `postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`.
</Note>

Если строка подключения к продакшен-базе данных была скомпрометирована, [перевыпустите учётные данные продакшен-базы данных](/ru/ja/features/data-and-storage/connection-details#regenerate-production-database-credentials).

<div id="section-4">
  ## Безопасное внесение изменений в продакшен-базу данных
</div>

При публикации обновлений, затрагивающих базу данных, некоторые изменения требуют тщательного планирования, чтобы избежать простоя и потери данных.

<Info>
  Во время публикации в опубликованном приложении возможен кратковременный простой. При применении изменений базы данных приложение иногда приходится временно останавливать, чтобы предотвратить конфликты и защитить данные.
</Info>

Особого внимания обычно требуют следующие виды изменений:

* **Удаление столбцов базы данных**, на которые всё ещё ссылается код приложения
* **Изменение типа данных столбца** способом, который существующий код не может обработать
* **Добавление обязательных полей** в существующие таблицы без значения по умолчанию
* **Переименование таблиц или столбцов**, нарушающее существующие запросы
* **Изменение ограничений**, из-за которого может отклоняться существующая логика приложения

<div id="section-5">
  ### Тестирование изменений в предпросмотре развёртывания
</div>

Предпросмотр развёртывания — это временная изолированная копия рабочей среды, в которой можно протестировать изменения базы данных и обновления приложения до того, как они затронут реальных пользователей. Используйте его, чтобы:

* убедиться, что после применения изменений базы данных приложение корректно работает во всех ключевых пользовательских сценариях;
* проверить, что существующие данные перенесены правильно, а новые поля содержат ожидаемые значения;
* проверить, не ухудшилось ли время отклика запросов.

<div id="section-6">
  ## Оплата и использование ресурсов
</div>

Продакшен-база данных тарифицируется по фактическому использованию через Neon — провайдера бессерверных баз данных. После 5 минут простоя база данных переходит в режим ожидания, начисление за вычислительное время приостанавливается, а при поступлении запроса база мгновенно возобновляет работу.

На главном экране инструмента Database отображаются **Billing Period** и **Hours of Compute Used**. Чтобы посмотреть объём хранилища для конкретной базы данных, откройте вкладку **Settings** этой базы данных. Чтобы увидеть использование по всем Replit App, откройте **Settings** → **Account** → **Account usage** и разверните строки **PostgreSQL Storage** и **PostgreSQL Compute**.

Подробнее о том, как Replit тарифицирует использование баз данных, см. в разделе [Оплата развёртываний и баз данных](/ru/ja/billing/about-usage-based-billing#databases).

<div id="section-7">
  ## Удаление продакшн-базы данных
</div>

<Warning>
  Операцию удаления невозможно отменить после истечения 7-дневного периода хранения. Прежде чем продолжить, обязательно создайте резервную копию важных данных. Для баз данных действует 7-дневный период мягкого удаления, в течение которого базу можно восстановить. Если понадобится помощь, обратитесь в поддержку. По истечении 7 дней база данных удаляется безвозвратно и восстановить её уже нельзя.
</Warning>

<Accordion title="Как удалить базу данных">
  В инструменте **Database**:

  1. Выберите базу данных и откройте вкладку **Settings**
  2. Нажмите **Remove database**, затем подтвердите, выбрав **Yes, Remove database**
</Accordion>

<div id="section-8">
  ## Устаревшие базы данных разработки
</div>

До 4 декабря 2025 года базы данных разработки размещались на <a href="https://neon.com/" target="_blank">Neon</a>. Все новые базы данных разработки размещаются на собственной инфраструктуре Replit (Helium). Узнать, что именно использует ваше приложение, можно на вкладке **Settings**: если `DATABASE_URL` содержит `neon.tech` — это устаревший Neon, если `helium` — текущая инфраструктура.

| **Возможность**              | **Replit (текущая)**                                                                                                                            | **Neon (устаревшая)**                                                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **Хостинг**                  | Размещается на собственной инфраструктуре Replit                                                                                                | Размещалась на Neon (сторонний поставщик)                                                                                                  |
| **Оплата**                   | Бесплатно включена в каждое Replit App                                                                                                          | Оплата по фактическому использованию. Подробнее см. [Публикация и оплата баз данных](/ru/ja/billing/about-usage-based-billing#databases).     |
| **Восстановление**           | С помощью [функции отката](/ru/ja/features/data-and-storage/data-recovery) базу данных можно восстановить до любой контрольной точки               | Восстановление на момент времени (PITR): до любого момента в пределах срока хранения резервных копий.                                      |
| **Безопасность подключения** | Доступ возможен только изнутри приложения, база никогда не публикуется в открытом доступе.                                                      | Использовалась полная строка подключения. В случае утечки получить доступ к базе данных и изменить её мог кто угодно.                      |
| **Поведение при ремиксе**    | [Ремикс](/ru/ja/features/projects-and-artifacts/remix-an-app) создаёт новую базу данных разработки с копией данных — ради изоляции и безопасности. | При ремиксе все копии использовали одну и ту же базу данных, поэтому изменения в ремиксе могли повлиять на исходное приложение.            |
| **Создание базы данных**     | Создаётся автоматически для каждого Replit App.                                                                                                 | Требовалась явная настройка.                                                                                                               |
| **Процесс публикации**       | При публикации создаётся отдельная продакшен-база данных для изоляции сред.                                                                       | Разработка и рабочая среда использовали одну базу данных, поэтому случайные изменения при разработке могли повлиять на рабочее приложение. |

<div id="section-9">
  ## Обновление инфраструктуры базы данных
</div>

Replit переводит базы данных разработки с Neon на **Helium** — собственную управляемую инфраструктуру PostgreSQL от Replit. Обновление выполняется автоматически — один раз для каждого приложения при его открытии в Project Editor, при этом все данные сохраняются.

Что меняется:

* **Меньше задержка и больше места в хранилище**: база данных теперь работает на той же инфраструктуре Replit, что и ваше приложение, а лимит хранилища увеличивается с 10 ГБ до 20 ГБ.
* **Тот же движок базы данных**: Helium использует ту же версию PostgreSQL 16, что и Neon. Запросы, схемы и данные работают как прежде.
* **Автоматическое обновление данных подключения**: `DATABASE_URL` обновляется и указывает на Helium. Прежняя строка подключения Neon сохраняется в Secrets как `NEON_DATABASE_URL` — для справки.
* **Удаление отдельных переменных PG**: `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` удаляются. Используйте вместо них `DATABASE_URL`.

Во время обновления отображается экран прогресса **«Upgrading your database»**. Это может занять от нескольких минут до нескольких часов — для больших баз данных. Вкладку можно закрыть и вернуться позже. Если при обновлении возникнет проблема, оно будет автоматически пропущено и повторено при следующем открытии приложения. По завершении появится диалоговое окно с подтверждением.

Большинству разработчиков после обновления ничего делать не потребуется. Проверьте следующее, если это относится к вам:

* **Жёстко заданные строки подключения Neon**: обновите код, который ссылается на строки подключения `neon.tech`, чтобы вместо них использовалась переменная окружения `DATABASE_URL`.
* **Пользовательские роли PostgreSQL**: роли и права переносятся автоматически, но пароли ролей скопировать нельзя. Сбросьте пароли пользовательских ролей в новой базе данных.

<div id="ssl">
  ### Ошибки SSL-подключения после обновления
</div>

Если появляется ошибка вида `The server does not support SSL connections`, значит код подключения принудительно инициирует SSL-рукопожатие. Neon требовал SSL, а Helium работает локально рядом с приложением и SSL не использует. Задайте параметры SSL в зависимости от окружения:

<CodeGroup>
  ```js JavaScript theme={null}
  // До (перестанет работать после обновления)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // После (работает и в разработке, и в продакшене)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  Если вы используете ORM — Drizzle, Prisma, Sequelize и подобные, — посмотрите в их документации, как настроить SSL по условию. Принцип тот же: для базы данных разработки SSL отключается, а в продакшене включается.
</Tip>

<div id="section-10">
  ### Форкнутые приложения с общей базой данных
</div>

В устаревшей системе Neon при форке приложения копировался `DATABASE_URL` исходного приложения, поэтому оба приложения и их опубликованные версии подключались к одной и той же базе данных. Работа общих устаревших баз данных была прекращена **8 июня 2026 года**. Если опубликованное приложение перестало работать или вы потеряли доступ к данным, см. [Исправление опубликованных приложений с общей базой данных](/ru/ja/features/data-and-storage/shared-database-migration) или [обратитесь в поддержку](https://replit.com/support).
