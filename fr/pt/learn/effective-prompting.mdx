Un prompt efficace consiste à donner des instructions claires à un assistant compétent. Guidez bien l&#39;[**Agent**](/fr/pt/features/agent/overview) et passez rapidement de l&#39;idée à l&#39;app.

<div id="exemplos-rpidos">
  ## Exemples rapides
</div>

Découvrez la différence entre des prompts vagues et efficaces :

<AccordionGroup>
  <Accordion title="Corriger du code" icon="bug">
    **Vague :** &quot;Fix my code.&quot;

    **Efficace :** &quot;My script fails when processing user input. The error seems to be in the validation function. Can you help debug the `validate_input` part? Here&#39;s the error message: [details]&quot;

    Le prompt efficace précise la zone concernée, la fonction suspectée et fournit du contexte.
  </Accordion>

  <Accordion title="Créer des fonctionnalités" icon="hammer">
    **Vague :** &quot;Make a website.&quot;

    **Efficace :** &quot;Create a simple portfolio website with sections for Home, About Me, and Contact Form. Use a clean, modern design theme and placeholder content.&quot;

    Le prompt efficace définit l&#39;objectif, les principales fonctionnalités et l&#39;esthétique souhaitée.
  </Accordion>

  <Accordion title="Améliorer les performances" icon="gauge-high">
    **Vague :** &quot;Don&#39;t make it slow.&quot;

    **Efficace :** &quot;Refactor the data processing function to handle larger inputs more efficiently. Could we use a different algorithm or data structure?&quot;

    Indiquez à l&#39;Agent *comment* améliorer le code plutôt que d&#39;utiliser des contraintes négatives.
  </Accordion>

  <Accordion title="Modifications de l'interface" icon="paintbrush">
    **Vague :** &quot;Add animation.&quot;

    **Efficace :** &quot;Animate the main image on the landing page so it gently fades in when the page first loads to create a welcoming effect.&quot;

    Identifiez l&#39;élément précis, l&#39;effet souhaité, le moment et l&#39;expérience visée.
  </Accordion>

  <Accordion title="Systèmes complexes" icon="server">
    **Vague :** &quot;Build the backend.&quot;

    **Efficace :** &quot;Set up the server-side logic. Implement user authentication (signup/login) and create an API endpoint to retrieve user profile data securely.&quot;

    Divisez les grandes tâches en fonctionnalités précises.
  </Accordion>
</AccordionGroup>

<div id="planeje-primeiro">
  ### Planifiez d’abord
</div>

<Tip>Avant de créer un prompt, esquissez les fonctionnalités et les parcours utilisateurs de votre app. Un plan clair permet d’obtenir des prompts plus ciblés.</Tip>

Réfléchissez à la structure de votre application comme le ferait un chef de produit. Décomposez l’objectif global en étapes logiques.

**Au lieu de :** &quot;Créez une application de gestion des tâches.&quot;

**Essayez plutôt :** &quot;1. Créez la structure HTML de base avec un champ de saisie et une liste de tâches. 2. Ajoutez du JavaScript pour ajouter des tâches. 3. Utilisez une base de données pour stocker les tâches. 4. Ajoutez une fonctionnalité permettant de marquer les tâches comme terminées.&quot;

Ensuite, créez des prompts pour l’Agent à chaque étape.

<div id="construa-incrementalmente">
  ### Construisez progressivement
</div>

Utilisez les [**Checkpoints**](/fr/pt/features/agent/overview#checkpoints) pour enregistrer votre progression après chaque étape réussie. En cas de problème, vous pouvez revenir à un état fonctionnel et essayer une autre approche.

**Au lieu de :** &quot;Créez une plateforme e-commerce complète.&quot;

**Essayez :** &quot;Configurez un projet full-stack de base pour un site e-commerce avec l&#39;inscription et la connexion des utilisateurs à l&#39;aide de Replit Auth.&quot; Continuez ensuite avec des prompts pour les listes de produits, le panier et le checkout.

<div id="seja-especfico">
  ### Soyez précis
</div>

Définissez précisément vos besoins : formats de sortie, contraintes, cas limites.

**Au lieu de :** &quot;Add a contact form.&quot;

**Essayez :** &quot;Create a contact form page at `/contact` with fields for:

* Name (required)
* Email (required, must be valid format)
* Message (required, min 10 characters)

On submit, send the form data to `contact@mydomain.com`.&quot;

<div id="use-linguagem-positiva">
  ### Utilisez un langage positif
</div>

Dites ce que vous *voulez*, plutôt que ce qu’il faut éviter.

**Au lieu de :** &quot;Ne rendez pas la page de profil utilisateur confuse.&quot;

**Essayez :** &quot;Concevez une page de profil utilisateur claire et épurée. Affichez le nom d’utilisateur bien en évidence, suivi de l’adresse e-mail et de la date d’inscription. Ajoutez un bouton « Modifier le profil ».&quot;

<div id="mantenha-a-simplicidade">
  ### Restez simple
</div>

Utilisez un langage clair et direct. Décomposez les demandes complexes en listes à puces.

**Au lieu de :** &quot;Mettez en place l&#39;infrastructure côté serveur nécessaire pour générer et récupérer dynamiquement des artefacts de contenu créés par les utilisateurs.&quot;

**Essayez :** &quot;Créez des fonctionnalités backend permettant aux utilisateurs de soumettre des articles de blog. Les utilisateurs doivent saisir un titre et le contenu de l&#39;article. Stockez les articles dans la base de données.&quot;

<div id="trabalhando-com-contexto">
  ## Travailler avec le contexte
</div>

<div id="fornea-arquivos-relevantes">
  ### Fournissez les fichiers pertinents
</div>

Indiquez des fichiers précis plutôt que de joindre l’ensemble de votre projet.

**Au lieu de :** (Tout joindre) &quot;Implement the user profile page based on our design system.&quot;

**Essayez plutôt :** &quot;Create the user profile page. Fetch user data from the server endpoint. Style according to [URL to design docs] and match this mockup: [attach `profile_mockup.jpg`].&quot;

<Tip>Commencez un nouveau chat lorsque vous passez à des tâches sans rapport. Vous éviterez ainsi toute confusion liée au contexte accumulé.</Tip>

<div id="mostre-exemplos">
  ### Montrez des exemples
</div>

Réduisez l’ambiguïté en fournissant des exemples concrets — extraits de code, données d’exemple ou captures d’écran.

**Au lieu de :** &quot;Améliorez l’apparence des cartes produit.&quot;

**Essayez :** &quot;Redessinez les cartes produit sur la page de la boutique. Chaque carte doit afficher l’image, le nom et le prix du produit, ainsi qu’un bouton « Ajouter au panier », inspiré de cette mise en page : [joignez une capture d’écran]. Utilisez une bordure gris clair.&quot;

<div id="depurando-de-forma-eficaz">
  ## Déboguer efficacement
</div>

Lorsque des erreurs se produisent, fournissez :

* Le message d’erreur **exact**
* Les extraits de code pertinents
* Les noms des fichiers où l’erreur se produit
* Ce que vous tentiez de faire
* Les étapes que vous avez déjà suivies

**Au lieu de :** &quot;Ma page de connexion ne fonctionne pas.&quot;

**Essayez plutôt :** &quot;Lorsque je me connecte avec des identifiants corrects sur `/login`, j’obtiens une erreur « User not found » dans la console du navigateur. La vérification en base de données ne semble pas fonctionner. Voici le code de gestion de la connexion dans `auth.js`.&quot;

<div id="pea-orientao">
  ## Demandez conseil
</div>

<Tip>Passez en Plan mode pour explorer les options avant de vous lancer. Demandez à Agent quelles bibliothèques et approches envisager, ainsi que leurs compromis.</Tip>

**Au lieu de :** &quot;Ajoute les paiements.&quot;

**Essayez :** &quot;Quelles sont les meilleures options pour accepter les paiements par carte bancaire dans une web app propulsée par Replit ? J’ai besoin d’une solution relativement simple à intégrer.&quot;

<div id="itere-nos-seus-prompts">
  ## Itérez sur vos prompts
</div>

Votre premier prompt ne sera peut-être pas parfait — c’est normal. Si le résultat ne vous convient pas :

* Ajoutez davantage de détails
* Donnez un exemple
* Simplifiez l’instruction
* Essayez de l’expliquer autrement

**Initial :** &quot;Créez un en-tête pour mon site web.&quot;

**Affiné :** &quot;Créez un composant d’en-tête fixe avec le logo du site à gauche et des liens de navigation (Accueil, À propos, Contact) à droite.&quot;

<div id="resumo">
  ## Résumé
</div>

Pour être efficace, le prompting consiste à :

* **Planifier** avant de créer des prompts
* **Construire** progressivement avec des checkpoints
* **Être précis** quant aux exigences
* **Fournir du contexte** à l’aide d’exemples et de fichiers pertinents
* **Itérer** lorsque les résultats ne sont pas satisfaisants

Maîtrisez ces principes pour créer plus rapidement des apps avec Agent.
