<div id="o-que-um-remix">
  ## 什么是 Remix
</div>

**Remix** 是你基于自己有权访问的应用创建的一个全新 Replit App。当你 remix 一个公开应用或模板时，你会获得一份属于自己的副本，可以随意体验并不断迭代改进。你在 Remix 中所做的更改不会影响原始应用。

你的 Remix 会注明来源：页面上会显示一个指向原始应用的 **Remixed from** 链接，原始应用的构建 prompt 也会显示在你的封面页上。

<div id="o-que-seu-remix-inclui">
  ## Remix 包含哪些内容
</div>

Remix 是一份完整且可运行的副本，同时与原应用有明确的界限：

* **所有文件和设置**都会被复制，因此应用的运行效果与原应用完全一致。
* **原应用的 checkpoint 历史**会一并带过来，并标记为来源应用的历史记录。你可以回滚到其中任意一个 checkpoint；但生成这些 checkpoint 的对话仍保留在原应用中。
* **全新的 Agent。** 你的 Remix 从一个全新的 Agent 开始，不会继承任何聊天记录。
* **只有 secrets 的名称，没有值。** 如果应用使用了 secrets (例如 API 密钥) ，你的 Remix 会列出这些条目，让你知道需要填写哪些内容，但值为空。只有当你 remix 自己的应用时，才会一并复制值。
* **全新的数据库。** 你的 Remix 绝不会连接到原应用的数据库。如果原应用开放了该选项，**Copy data from original App** 可以复制数据本身；即便如此，你的改动也永远不会影响源应用。
* **全新的登录设置**，适用于使用 Replit Auth 的应用。

不会复制的内容：deployment、域名和连接器设置，这些需要你在自己的副本中重新设置。此外，Remix 默认为私有，因此在你决定发布之前不会向外分享任何内容。

  ## 如何 remix 一个应用
</div>

<Steps>
  <Step title="打开应用的封面页">
    找到一个你想 remix 的应用，例如[社区](https://replit.com/community/all)中的某个应用。它的封面页会显示实时预览和分享选项。
  </Step>

  <Step title="Remix 该应用">
    选择 **Remix this App**，开始创建属于你自己的版本。
  </Step>

  <Step title="填写应用详情">
    在 **Remix App** 对话框中，为你的副本命名，并填写可选的描述，然后选择 **Remix App**。这些信息之后可以随时修改。

<div id="continue-construindo-no-seu-remix">
  ## 在你的 Remix 上继续构建
</div>

Remix 在 workspace 中打开后，你可以使用 Agent 对其进行修改和扩展。在 **Agent** 标签页中输入 prompt，描述你想添加的功能。

若要撤销 Agent 的更改，请在此次更改后创建的 checkpoint 上选择 **Rollback to here**。详见 [checkpoint 与回滚](/zh/pt/features/version-control/checkpoints-and-rollbacks)。

<div id="remix-ou-construir-a-partir-de-um-prompt">
  ## 是 Remix 还是从 prompt 开始构建？
</div>

两条路径最终殊途同归：都会得到一个由 Agent 帮你持续演进的应用。区别只在起点：

|              | Remix           | 从 prompt 开始构建       |
| ------------ | --------------- | ------------------- |
| 起点           | 一个可运行的应用，原样复制而来 | Agent 根据你的描述创建的应用   |
| 首个结果         | 立即可得，且与源应用完全一致  | 耗时更长，结果也不尽相同        |
| Agent 的第一个动作 | 等待你的指示          | 根据你的 prompt 进行规划并构建 |

如果已经有接近你需求的应用，那就 remix 它：这样 Agent 的第一轮操作就是在一个真实可用的应用上展开，而不是从零开始。如果你的想法找不到任何相似的现成应用，就从 prompt 开始构建。
