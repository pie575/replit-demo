<Info>
  Snowflake connector 仅在 **企业版** 套餐中提供。
</Info>

Warehouse Connectors 让 Replit Agent 能够查询组织的数据仓库。借助 Snowflake connector，构建者只需使用自然语言即可创建仪表板、报表工具和数据应用，无需具备 SQL 专业知识。

设置只需完成一次，但需要一位 Snowflake 账户管理员和一位 Replit workspace 管理员共同参与。配置完成后，组织中的任何成员都可以登录并开始基于 Snowflake 数据进行构建。

本指南将带你完成完整的设置流程，其中涉及三种角色：

1. **Snowflake 账户管理员** — 在 Snowflake 中创建 OAuth 集成
2. **Replit Workspace 管理员** — 在 Replit 中配置 connector
3. **构建者** — 登录并开始构建

<div id="create-the-oauth-integration-in-snowflake">
  ## 在 Snowflake 中创建 OAuth 集成
</div>

由 Snowflake 账户管理员创建 OAuth 安全集成，使 Replit 能够通过 Snowflake 进行身份验证。

<div id="prerequisites">
  ### 前提条件
</div>

* 拥有 Snowflake 的 `ACCOUNTADMIN` 角色
* 有权限在 Snowflake 工作表中运行 SQL

<div id="run-the-setup-script">
  ### 运行设置脚本
</div>

<Steps>
  <Step title="登录 Snowflake">
    打开你的 Snowflake 账户，确保当前使用的是 `ACCOUNTADMIN` 角色。你可以在右上角的角色下拉菜单中确认。
  </Step>

  <Step title="打开 SQL 工作表">
    点击左侧边栏的 **Worksheets**，新建一个工作表。
  </Step>

  <Step title="运行 OAuth 集成脚本">
    复制并粘贴以下 SQL 脚本，然后运行：

    ```sql Create OAuth integration theme={null}
    -- 如有需要，删除已存在的集成
    DROP INTEGRATION IF EXISTS REPLIT_OAUTH;

    -- 为 Replit 创建 OAuth 集成
    CREATE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    <Warning>
      重定向 URI 必须与 `https://replit.com/connectors/oauth/callback` 完全一致。填写其他任何值都会在认证过程中导致 404 错误。
    </Warning>

    <Note>
      设置 `BLOCKED_ROLES_LIST = ()` 可确保没有角色被禁止使用该集成。若不设置，连接时可能会遇到 &quot;invalid consent request&quot; 或 &quot;role blocked&quot; 错误。
    </Note>
  </Step>

  <Step title="获取你的 OAuth 凭据">
    运行以下查询，获取 Client ID 和 Client Secret：

    ```sql Get OAuth credentials theme={null}
    -- 查看集成详情
    DESCRIBE INTEGRATION REPLIT_OAUTH;

    -- 获取 Client ID 和 Secret
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```

    从输出结果中复制 **Client ID** 和 **Client Secret**，下一步会用到。
  </Step>
</Steps>

<div id="configure-the-connector-in-replit">
  ## 在 Replit 中配置 connector
</div>

由 Replit Workspace 管理员将 Snowflake 凭据添加到 Replit。配置完成后，组织中的任何成员均可登录。

<Note>
  此步骤需要企业版并具备管理员权限。
</Note>

<Steps>
  <Step title="打开 Integrations">
    进入组织设置，选择 **Integrations** 标签页。
  </Step>

  <Step title="添加 Snowflake connector">
    点击 **Add New Connector**，然后选择 **Snowflake**。
  </Step>

  <Step title="输入凭据">
    填写上一步中获取的 **Client ID** 和 **Client Secret**。
  </Step>

  <Step title="设置 scope">
    将 connector 的 scope 设置为 `refresh_token`。

    <Warning>
      请仅使用 `refresh_token` scope。使用 `session:role-any` 或 `session:role:PUBLIC` 等其他 scope 可能会导致「invalid scope」错误。
    </Warning>
  </Step>

  <Step title="保存">
    点击 **Save** 以启用该 connector。
  </Step>
</Steps>

<div id="sign-in-to-snowflake">
  ## 登录 Snowflake
</div>

组织中任何有权访问该 connector 的成员都可以登录。建议先在 **Integrations** 页面登录，确认连接正常后再配合 Agent 使用。

<Steps>
  <Step title="找到 Snowflake connector">
    在 Replit 中打开 **Integrations**，在 **Connectors** 下找到 **Snowflake**。
  </Step>

  <Step title="点击 Sign In">
    在 Snowflake connector 上点击 **Sign In**。
  </Step>

  <Step title="输入你的 Snowflake Account ID">
    OAuth 授权页面会要求你输入 Snowflake Account ID。

    要查找 Account ID，请查看 Snowflake 的 URL：

    ```
    https://app.snowflake.com/myorg/myaccount
    ```

    取 `app.snowflake.com/` 后面的两部分，用连字符连接起来：

    ```
    myorg-myaccount
    ```

    <Note>
      URL 中这两部分之间用的是 `/`，而 Account ID 中要改用 `-`。
    </Note>
  </Step>

  <Step title="完成身份验证">
    Snowflake 会将你重定向到登录页面。输入你的 Snowflake 凭据即可完成 OAuth 流程。
  </Step>
</Steps>

<div id="start-building-with-your-snowflake-data">
  ## 开始基于你的 Snowflake 数据进行构建
</div>

连接完成后，你可以通过两种方式将 Snowflake connector 与 Agent 搭配使用：

* **斜杠命令** — 在 prompt 中输入 `/snowflake` 即可使用该 connector
* **自然语言** — 直接让 Agent 使用你的 Snowflake 数据

以下是一个 prompt 示例：

```
用我的 Snowflake 数据帮我做一个仪表板。用柱状图展示各地区的
总收入，加上按季度的趋势线，以及一个前 10 大客户的表格。
深色主题，简洁现代。
```

Agent 会针对你的 Snowflake 数据编写并执行 SQL 查询，并构建出可正常运行的应用。

<div id="troubleshooting">
  ## 故障排查
</div>

<AccordionGroup>
  <Accordion title="无效的授权请求或角色被阻止错误">
    你的 Snowflake 集成可能默认阻止了某些角色。

    请确认创建集成时包含 `BLOCKED_ROLES_LIST = ()`。如果创建时未包含该设置，请运行：

    ```sql Fix blocked roles theme={null}
    CREATE OR REPLACE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    如果错误仍未消失，请检查你的默认角色是否被阻止：

    ```sql Set default role theme={null}
    ALTER USER "YOUR_USERNAME" SET DEFAULT_ROLE = 'PUBLIC';
    ```
  </Accordion>

  <Accordion title="身份验证时出现 404 错误">
    请确认 Snowflake 集成中的重定向 URI 与下方完全一致：

    ```
    https://replit.com/connectors/oauth/callback
    ```

    只要有任何差异，都会在 OAuth 流程中导致 404 错误。
  </Accordion>

  <Accordion title="无效的 scope 错误">
    确保 Replit 中的 connector scope 仅设置为 `refresh_token`，并移除 `session:role-any`、`session:role:PUBLIC` 等其他 scope。
  </Accordion>

  <Accordion title="连接失败错误">
    请确认 Replit 中的 Client ID 和 Client Secret 与 Snowflake 生成的一致。可运行以下语句重新核对：

    ```sql Verify credentials theme={null}
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```
  </Accordion>
</AccordionGroup>
