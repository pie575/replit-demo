Le vibe coding permet de passer plus rapidement d&#39;une idée à un logiciel. Au lieu de commencer par le code, vous décrivez ce qui doit être créé, puis vous utilisez l&#39;IA pour concrétiser cette vision sous la forme d&#39;une application fonctionnelle que vous pouvez visualiser, tester et améliorer.

Replit est conçu pour cette boucle. Au même endroit, vous pouvez décrire une idée, prévisualiser le résultat, donner votre avis, apporter des modifications et publier.

Cette page porte sur l&#39;état d&#39;esprit du vibe coding. La page suivante, [Créer avec Agent](/fr/ko/learn/build-with-agent), montre comment Agent utilise ses outils. [Rédiger des prompts efficaces](/fr/ko/learn/effective-prompting) explique comment formuler des instructions plus claires.

<div id="section">
  ## La création de logiciels reposait sur une boucle d’équipe
</div>

Les logiciels sont généralement créés par des équipes.

Un responsable produit ou un fondateur définit quoi créer et pourquoi. Un designer façonne l’expérience. Un développeur transforme les idées en logiciels fonctionnels. Les membres de l’équipe testent, donnent leur avis, trouvent les bugs et décident de ce qui est prêt à être lancé.

Cette collaboration est puissante, car chaque rôle apporte un type de jugement différent. L’équipe produit détermine ce qui compte. La conception détermine l’expérience à offrir. L’ingénierie détermine le fonctionnement. Les tests déterminent si cela fonctionne vraiment.

Mais cette boucle peut être lente. Chaque modification doit passer de main en main : expliquer l’idée, concevoir le flux, écrire le code, examiner le résultat, tester et corriger.

Le vibe coding raccourcit cette boucle.

Avec Replit, vous pouvez gérer vous-même une plus grande partie du processus de création du produit. Vous pouvez définir l’objectif, générer la première version, tester, donner votre avis et améliorer, sans attendre que chaque étape soit transmise d’une personne ou d’un outil à l’autre.

<div id="section-2">
  ## Votre rôle évolue
</div>

Vous n&#39;avez pas besoin d&#39;être développeur pour commencer à créer.

Avec le vibe coding, votre rôle se rapproche davantage de celui d&#39;un responsable produit. Vous décidez de ce qui doit exister, à qui cela s&#39;adresse, de ce qui compte le plus et si le résultat est suffisamment satisfaisant.

Agent vous aide à concrétiser votre projet, mais c&#39;est toujours vous qui le pilotez.

Vous apportez :

* les objectifs
* le public cible
* vos préférences
* les contraintes
* les retours
* les décisions concernant ce qui sera publié

Agent vous aide à :

* transformer des idées en logiciels fonctionnels
* appliquer des modifications
* expliquer le fonctionnement
* déboguer les problèmes
* améliorer votre application au fil du temps

Plus vous pilotez efficacement le projet, mieux Agent peut le développer.

<div id="section-3">
  ## Cinq principes
</div>

Le vibe coding fonctionne mieux lorsqu’il repose sur cinq principes simples :

1. Commencez par un objectif.
2. Construisez par petites étapes.
3. Gérez le contexte.
4. Examinez et testez.
5. Améliorez grâce aux retours.

Le premier principe donne la direction. Les quatre suivants forment une boucle : construisez une étape, fournissez le bon contexte, examinez, améliorez, puis construisez l’étape suivante.

Ces principes sont plus importants que de rédiger un premier prompt parfait. Il est rare d’obtenir l’application finale en une seule étape. L’objectif est de maintenir une boucle claire et continue.

<div id="section-4">
  ## Commencez par l’objectif
</div>

Une bonne session de vibe coding commence comme une bonne discussion autour d’un produit :

À qui s’adresse-t-il ? Que doit-on pouvoir y faire ? Qu’est-ce qui le rend utile ?

Avant de demander à Replit de créer votre application, décrivez le résultat souhaité.

<AiPrompt>
  Créez un site web simple pour une boulangerie locale. Les clients doivent pouvoir voir les spécialités du jour, découvrir le service traiteur et envoyer une demande de prestation. Rendez-le chaleureux, soigné et facile à utiliser sur mobile.
</AiPrompt>

Cette approche fonctionne, car vous donnez à Replit un objectif produit plutôt qu’une simple tâche. Vous décrivez le public cible, les actions essentielles et l’impression que doit donner la première version.

Vous n’avez pas encore besoin de connaître les détails de l’implémentation technique. Commencez par définir ce qui devra être vrai une fois votre application opérationnelle.

<div id="section-5">
  ## Créez par petits modules
</div>

Un module est une petite partie du produit suffisamment aboutie pour être testée.

Pour un site de boulangerie, le premier module pourrait être :

* Une page d’accueil avec les spécialités du jour
* Un formulaire de demande de service traiteur
* Une mise en page adaptée aux mobiles

C’est suffisant pour tester l’idée. Vous pouvez l’ouvrir, cliquer et décider de ce qu’il faut améliorer ensuite.

Ne demandez pas l’ensemble du produit en une seule fois. Les demandes importantes sont difficiles à examiner et faciles à mal interpréter. Les petits modules vous permettent d’avancer sans perdre le contrôle.

Une fois le premier module fonctionnel, ajoutez le suivant.

<AiPrompt>
  Ajoutez un message de confirmation après l’envoi du formulaire de demande de service traiteur. Ne modifiez pas le reste de la page.
</AiPrompt>

L’instruction est courte, claire et testable.

<div id="section-6">
  ## Gérez le contexte
</div>

Le contexte désigne les informations que Replit utilise pour comprendre ce que vous voulez.

Un bon contexte peut inclure :

* à qui s’adresse l’application
* le problème qu’elle résout
* ce qui doit être inclus maintenant
* ce qui peut attendre
* ce qui ne doit pas être modifié
* des exemples, des captures d’écran, des croquis, des fichiers ou des données
* des notes sur le ton, le style et la marque

Gérer le contexte consiste à fournir les bonnes informations au bon moment.

Si vous continuez à travailler sur la même fonctionnalité, restez dans la même conversation afin que Replit puisse s’appuyer sur les décisions précédentes. Si vous commencez une autre fonctionnalité ou si la conversation devient trop confuse, il peut être préférable de repartir de zéro en résumant brièvement les éléments importants.

Par exemple :

<AiPrompt>
  Contexte : ce site de pâtisserie s’adresse à des parents occupés qui commandent des gâteaux d’anniversaire. Gardez le formulaire court, rendez les informations de retrait évidentes et évitez tout ce qui semble trop institutionnel. Pour cette modification, améliorez uniquement la section de demande de service traiteur.
</AiPrompt>

Il ne s’agit pas simplement d’ajouter davantage de mots. Vous aidez Replit à rester concentré.

<div id="section-7">
  ## Examinez et testez
</div>

Agent peut créer, mais c’est à vous de déterminer si le résultat fonctionne.

Après chaque modification importante, ouvrez l’application et utilisez-la comme le ferait son public cible. Ne vous contentez pas de lire ce qu’Agent indique avoir modifié. Testez les parcours.

Demandez-vous :

* Quelqu’un peut-il accomplir l’action principale ?
* La page est-elle compréhensible ?
* Fonctionne-t-elle sur mobile ?
* Quelque chose d’important est-il cassé ?
* Replit a-t-il modifié quelque chose qui aurait dû rester inchangé ?
* Est-ce suffisamment bon pour continuer à créer ?

C’est lors de l’examen et des tests que votre jugement produit compte le plus. Vous vérifiez que le logiciel correspond à votre intention.

<div id="section-8">
  ## Améliorez grâce aux retours
</div>

La première version d’un élément est un brouillon. C’est normal.

Le vibe coding s’améliore grâce aux retours. Indiquez à Replit ce qu’il faut conserver, modifier, supprimer et essayer ensuite.

Au lieu de :

<AiPrompt>
  Améliore-le.
</AiPrompt>

Essayez plutôt :

<AiPrompt>
  Rends le formulaire de demande de service traiteur plus facile à parcourir. Conserve les mêmes champs, mais améliore l’espacement, les libellés et le bouton d’envoi. Ne modifie pas la section des offres spéciales.
</AiPrompt>

De bons retours sont précis. Ils améliorent une partie de l’application tout en préservant ce qui fonctionne déjà.

Lorsqu’un élément fonctionne, reprenez ce cycle et créez le petit élément suivant.

Si les modifications vont dans la mauvaise direction, réduisez le périmètre.

<AiPrompt>
  Cela a trop changé. Conserve le nouveau style de bouton, mais restaure la disposition d’origine et mets à jour uniquement le formulaire de service traiteur.
</AiPrompt>

Améliorer grâce aux retours permet de faire avancer votre produit sans perdre le contrôle.

<div id="section-9">
  ## À quoi reconnaît-on un bon vibe coding ?
</div>

Vous êtes sur la bonne voie lorsque :

* vous pouvez décrire votre objectif en termes simples
* chaque modification est suffisamment limitée pour pouvoir être examinée
* vous savez quoi tester une fois qu’Agent a terminé le build
* vous fournissez du contexte à Agent plutôt que de deviner ce qu’il sait
* vous indiquez à Agent non seulement ce qu’il doit modifier, mais aussi ce qu’il doit préserver
* l’application devient plus utile après chaque itération

Le vibe coding ne consiste pas à transmettre une idée puis à disparaître. Il consiste à raccourcir la distance entre les idées, le logiciel, les retours et les améliorations.
