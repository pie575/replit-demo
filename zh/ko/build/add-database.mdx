你已在[添加登录](/zh/ko/build/add-login)中为 Velocity 添加了登录功能。但车辆列表中的车辆和客户创建的预订会在刷新页面后消失，因为它们只存在于浏览器中。添加数据库，让所有内容都能保留下来。

<div id="agent">
  ## 请求 Agent 存储数据
</div>

Velocity 使用 Neon——Replit 的托管式 Postgres 数据库。Neon 能够妥善处理并发预订，并可随实际客户流量扩展。Agent 会自动为开发和生产环境分别预配数据库，无需注册 Neon 控制台或粘贴密钥。

<AiPrompt>
  将 Velocity 的数据存储到数据库中，确保刷新后车辆、可用性和预订不会消失。<br />
  使用 Neon (Postgres)。<br />
  存储以下内容：每辆车 (制造商、型号、年份、每日费率、照片、位置) 、每辆车的可用性日历，以及每笔预订 (取车日期、还车日期、车辆、客户) 。<br />
  将每笔预订关联到已登录的客户，使每个人只能查看自己的预订。<br />
  防止在日期重叠时重复预订同一辆车。<br />
  告诉我更改后需要测试哪些内容。
</AiPrompt>

Agent 会预配 Neon 数据库，将车辆列表和预订从内存数据迁移到数据库，并添加重复检查，确保同一辆兰博基尼不会被重复预订。

<div id="section">
  ## 测试数据是否都能保留
</div>

1. 在 Preview 中登录 Velocity，并预订下周六的车辆。
2. 刷新页面。“My bookings”中的预订应仍然存在。
3. 在 Agent 聊天中重启应用。车辆列表和预订都应仍然存在。
4. 使用第二个账户尝试预订同一周六的同一辆车。Velocity 应提示该车辆不可用，并推荐其他日期或车辆。
5. 登出后重新登录。预订应仍然存在。

如果在任何步骤中预订消失，请将具体症状再次告知 Agent。

<AiPrompt>
  我在 Velocity 中预订了车辆，但刷新页面后预订消失了。<br />
  请检查预订是存储在数据库中，还是只保存在页面上。<br />
  请进行最小范围的修复，并告诉我如何验证。
</AiPrompt>

您还可以让 Agent 创建一个简单的管理员视图，以查看数据库中的内容。

<AiPrompt>
  请在 Velocity 中创建一个简单的管理员页面，按车辆分组列出数据库中的所有车辆和预订。<br />
  仅向作为项目所有者的我显示。
</AiPrompt>

<div id="url">
  ## 部署并通过公开 URL 验证
</div>

Agent 的 Neon 配置默认会为 Velocity 提供独立的开发和生产环境。在 Agent 聊天或 Publishing 磁贴中重新部署 Velocity，然后在新标签页中打开公开 URL。Replit 会自动将生产环境的 Neon 凭据连接到已部署的应用 — 在公开 URL 中创建预订，刷新页面，并确认预订仍然存在。

现在，Velocity 会记住所有车辆、所有可用日期和所有预订。即使再次刷新，预订也不会消失。

<div id="section-3">
  ## 需要更多帮助吗？
</div>

* **预约在 Preview 中能保存，但在公开 URL 中无法保存：**请让 Agent 确认生产环境的 Neon 凭据是否已连接到已部署的应用。
* **难以查看数据：**请让 Agent 添加一个简单的管理员视图，列出数据库中的所有内容。
* **想用初始数据填充车辆列表：**请让 Agent 添加一个一次性脚本，将实际车辆加载到数据库中。
* **想要一个无需配置、可快速制作原型的数据库：**请改用 [Replit Database](/zh/ko/features/data-and-storage/sql-database)——它内置于每个 Repl，无需单独预配。
