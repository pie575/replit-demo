---
title: "Внешние токены доступа"
description: "Открывайте доступ к приватным приложениям Replit из CI-конвейеров, вебхуков и других сервисов автоматизации без входа в систему."
---

Внешний токен доступа — это bearer-токен, который вы выпускаете для конкретного Replit App.
Даже если доступ по URL ограничен с помощью [приватного URL разработки](/ru/ja/features/publishing/private-deployments) или [приватных деплоев](/ru/ja/features/publishing/private-deployments), сервисы автоматизации — CI-конвейеры, вебхуки, пингеры проверки состояния, боты Slack и внутренние скрипты — смогут обращаться к вашему приложению.

Обращайтесь с каждым токеном как с паролем. Любой, у кого есть токен, получит доступ к вашему приложению, пока не истечёт срок его действия или пока вы его не отзовёте.

<Note>
  Внешние токены доступа становятся доступны, когда вы выбираете приватный доступ для деплоя. Отдельно включать эту возможность в рабочем пространстве не нужно. В рабочих пространствах Enterprise управлять токенами могут только администраторы рабочего пространства.
</Note>

<div id="section">
  ## Когда использовать токен
</div>

Если к приватному Replit App нужно обратиться чему-то за пределами браузера, используйте токен внешнего доступа. Типичные случаи:

* Рабочие процессы GitHub Actions, которые при каждом коммите прогоняют дымовые тесты по URL разработки.
* Мониторинг доступности (Better Stack, Pingdom, UptimeRobot и т. п.), обращающийся к эндпоинту проверки состояния опубликованного приложения.
* Приёмники вебхуков (Stripe, Slack, GitHub и т. п.), отправляющие POST-запросы в приватный деплой.
* Вызовы `curl` или `fetch` с машины коллеги во время отладки.

Токены внешнего доступа рассчитаны на **трафик API**, а не на открытие страниц интерфейса в браузере. Одностраничные приложения (Vite, Next.js и т. п.) подгружают JavaScript-бандлы последующими запросами, а к ним токен уже не добавляется — такие запросы завершатся ошибкой. Для интерактивного просмотра входите в систему обычным способом.

<div id="section-2">
  ## Среда токена
</div>

Каждый токен привязан к одной среде:

| Среда         | Область действия                                                                   | Назначение                                            |
| :------------ | :--------------------------------------------------------------------------------- | :---------------------------------------------------- |
| `Development` | URL разработки рабочего пространства приложения (`*.replit.dev`)                   | Доступ к запущенному Repl во время разработки         |
| `Production`  | Опубликованные деплои приложения (`*.replit.app` и пользовательские домены)        | Доступ к приватным деплоям из внешних сервисов        |

Токен `Production` продолжает действовать и после повторной публикации, в том числе при публикации новой версии. Replit отзывает токены в следующих случаях:

* Вы сняли деплой с публикации.
* Вы удалили деплой.
* Вы изменили настройки доступа приложения с приватных на публичные.

Токены также перестают работать по истечении срока действия или если вы их отозвали.

<div id="section-3">
  ## Создание токенов внешнего доступа
</div>

<Steps>
  <Step>
    Откройте приложение, которое хотите опубликовать, и запустите инструмент **Publishing**.
  </Step>

  <Step>
    Выберите **Adjust settings**, чтобы развернуть параметры повторной публикации.
  </Step>

  <Step>
    В разделе **Security** найдите пункт **External access tokens**.
  </Step>

  <Step>
    Выберите **Create access token** и заполните следующие поля:

    * **Label** (необязательно): задайте короткое имя вроде `CI` или `Stripe webhook`, чтобы позже было проще узнать токен. Не более 120 символов.
    * **Environment**: выберите `Development` или `Production` в зависимости от того, где вызывающему сервису нужен доступ к приложению.
    * **Expires after**: выберите срок действия — `1 hour`, `24 hours`, `7 days`, `30 days`, `3 months`, `1 year` или `5 years`. Указывайте минимальный срок, которого хватит для вашей задачи. Варианта «бессрочно» здесь нет.
  </Step>

  <Step>
    Выберите **Create**.
  </Step>
</Steps>

Replit показывает токен **только один раз**. Скопируйте его сразу — после закрытия диалогового окна посмотреть токен снова уже не получится. Если вы потеряли токен, отзовите его и выпустите новый.

На экране с токеном доступны два варианта копирования:

* **Copy query parameter** — копирует `?project-protection-bypass=<token>`, который можно добавить к URL. Удобно для быстрой проверки через `curl`.
* **Copy token only** — копирует сам токен. Подходит для отправки в заголовке `Authorization: Bearer`.

<Info>
  При создании первого токена внешний доступ к приложению включается автоматически, если он ещё не был включён. Без защиты токену просто нечего обходить.
</Info>

<div id="section-4">
  ## Использование токена
</div>

Токен можно передать одним из двух способов:

<div id="authorization">
  ### Заголовок Authorization (рекомендуется)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

Этот способ подходит практически для любых сценариев: вебхуков, CI-скриптов, вызовов между бэкендами и т. д. Токен не попадает в логи, куда записываются URL, и не сохраняется в истории браузера.

<div id="section-5">
  ### Параметры запроса
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

Формат с параметром запроса используйте только в тех случаях, когда задать заголовок невозможно — например, если сервис принимает только URL. URL с токеном часто оседают в логах прокси, в истории командной оболочки и на скриншотах, поэтому по возможности отдавайте предпочтение формату с заголовком.

<div id="section-6">
  ## Управление существующими токенами
</div>

В разделе **External access tokens** перечислены все созданные вами токены для этого приложения, начиная с самых новых, вместе с меткой, средой, датой создания, сроком действия и статусом отзыва. В каждой строке отображаются последние несколько символов токена, чтобы его было проще опознать: полное значение показывается только в момент создания.

Отображаются только те токены, которые создали *вы*. Даже если вы владелец приложения, токены других соавторов видны только им самим.

<div id="section-7">
  ## Отзыв токенов
</div>

Отзывайте токен сразу, как только он перестал быть нужен или вы заметили возможную утечку. Чтобы отозвать токен:

<Steps>
  <Step>
    Откройте раздел **External access tokens** в настройках публикации приложения.
  </Step>

  <Step>
    Найдите токен в списке и нажмите на значок корзины.
  </Step>

  <Step>
    Подтвердите отзыв.
  </Step>
</Steps>

Отзыв происходит **немедленно и необратимо**. Трафик, использующий этот токен, начнёт отклоняться в течение нескольких секунд. Если доступ снова понадобится, выпустите новый токен.

Отзывать можно только собственные токены. При удалении соавтора из рабочего пространства выпущенные им токены для этого приложения отзываются автоматически.

<div id="section-8">
  ## Безопасное управление токенами
</div>

Внешние токены доступа — это учётные данные. Обращайтесь с ними так же бережно, как с API-ключами или паролями.

<div id="section-9">
  ### Что следует делать
</div>

* **Храните токены в менеджере секретов** — например, в секретах GitHub Actions, Vault вашего CI-провайдера, хранилище секретов облачного провайдера или менеджере паролей. Не коммитьте их в репозиторий.
* По возможности **задавайте короткий срок действия**. Для разовой интеграции токен на 7 дней безопаснее, чем токен на 5 лет, о котором все забудут.
* **Помечайте каждый токен**, чтобы вы сами в будущем понимали, для чего он нужен и используется ли он ещё. Токены без меток обычно утекают первыми, а отзываются последними.
* **Выпускайте отдельный токен для каждого потребителя.** По одному на каждое CI-задание, на каждый источник вебхуков, на каждую проверку доступности и так далее. Если что-то будет скомпрометировано — или какой-то сервис перестанет быть нужен — достаточно будет отозвать всего один токен.
* **Отдавайте предпочтение заголовку `Authorization`**, а не параметрам запроса, чтобы токены не утекали через логи URL, историю браузера и заголовок Referer.
* **Немедленно отзывайте токен**, если он мог быть скомпрометирован — утечка логов, коммит в публичный репозиторий, демонстрация экрана, ноутбук бывшего сотрудника и тому подобное. Отзыв вступает в силу сразу, а новый токен вы выпустите уже после этого.

<div id="section-10">
  ### Чего делать нельзя
</div>

* **Не передавайте токены коллегам по команде и не используйте один токен сразу в нескольких сервисах.** Если две системы работают с общим токеном, отозвать доступ у одной, не сломав другую, не получится.
* **Не вставляйте токены в чаты, письма, скриншоты и трекеры задач.** Эти каналы архивируются, индексируются и расходятся непредсказуемым образом.
* **Не встраивайте токены в клиентский код** — всё, что попадает на устройства пользователей (браузерные и мобильные приложения, десктопные сборки), следует считать общедоступным.
* **Не используйте токены для сеансов в браузере.** Токены предназначены для вызовов API, а не для загрузки SPA во вкладке браузера. В таких случаях используйте обычный вход в Replit.
* **Не оставляйте срок действия 5 лет по умолчанию.** Задавайте срок исходя из того, насколько долго доступ действительно нужен потребителю.

<div id="section-11">
  ## Устранение неполадок
</div>

<Accordion title="Production-токен внезапно перестал работать">
  Production-токены продолжают действовать после обычных повторных публикаций. Проверьте, не истёк ли срок действия токена и не отозвали ли вы его сами. Также проверьте, не сняли ли вы деплой с публикации, не удалили ли его и не сделали ли приложение из приватного публичным. Если у приложения больше нет приватного деплоя, опубликуйте его заново как приватный. После этого выпустите новый токен. Восстановить токен с истёкшим сроком действия или отозванный токен невозможно.
</Accordion>

<Accordion title="Токен работает в `curl`, но в браузере открывается страница входа">
  Токены внешнего доступа рассчитаны на трафик API, а не на сеансы в браузере. Когда одностраничное приложение загружается в браузере, первый HTML-запрос может передать токен через параметр запроса, но последующие запросы к JavaScript-бандлам, CSS и вызовы API токен уже не содержат, поэтому их отклоняют. Чтобы работать с приложением в интерактивном режиме, войдите в Replit обычным способом.
</Accordion>

<Accordion title="Я потерял токен — можно посмотреть его ещё раз?">
  Нет. Replit показывает токен только один раз — в момент создания. В списке отображаются метаданные (метка, окружение, срок действия, последние несколько символов), но не полное значение токена. Если вы потеряли токен, отзовите его и создайте новый.
</Accordion>
