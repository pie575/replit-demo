本指南提供了一份全面的安全检查清单，帮助你确保通过氛围编程创建的应用遵循安全最佳实践。

虽然 Replit [开箱即用地提供了许多安全功能](/zh/features/security/overview)，但了解并根据具体应用需求实施更多安全措施仍然很重要。

<div id="front-end-security">
  ## 前端安全
</div>

<AccordionGroup>
  <Accordion title="全面使用 HTTPS" icon="lock">
    Replit 默认会为所有应用启用 HTTPS，因此无需额外担心！
  </Accordion>

  <Accordion title="输入验证与清理" icon="shield-check">
    始终验证并清理用户输入，以防止跨站脚本 (XSS) 攻击：

    ```javascript theme={null}
    // 不佳：直接使用用户输入
    element.innerHTML = userInput;

    // 推荐：使用前先清理输入
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    询问 Agent：

    ```
    帮我验证并清理输入，以防止 XSS 攻击
    ```
  </Accordion>

  <Accordion title="避免在浏览器中存放敏感数据" icon="eye-slash">
    应使用 Replit Secrets 存储 API 密钥等敏感信息。

    请确保不要将机密信息传递到客户端，也不要将其存放在以下位置：

    * 本地存储
    * 会话存储
    * 客户端 JavaScript
    * 未设置适当安全属性的 Cookie

    询问 Agent：

    ```
    帮我避免在浏览器中存放敏感数据。我这样做对吗？
    ```
  </Accordion>

  <Accordion title="CSRF 防护" icon="shield">
    为表单实施跨站请求伪造 (CSRF) 防护：

    ```javascript theme={null}
    // CSRF token 实现示例
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    询问 Agent：

    ```
    帮我为表单实现 CSRF token
    ```
  </Accordion>
</AccordionGroup>

<div id="back-end-security">
  ## 后端安全
</div>

<AccordionGroup>
  <Accordion title="身份验证基础" icon="key">
    实施身份验证时：

    * 尽可能使用 Replit Auth
    * 如果要构建自定义身份验证，请使用成熟的库
    * 切勿存储明文密码

    询问 Agent：

    ```
    帮我使用 Replit Auth 为我的应用实现身份验证
    ```
  </Accordion>

  <Accordion title="授权检查" icon="user-lock">
    执行操作前，务必验证权限：

    ```javascript theme={null}
    // 授权检查示例
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    询问 Agent：

    ```
    帮我为我的应用实现授权检查
    ```
  </Accordion>

  <Accordion title="API 端点保护" icon="shield">
    保护你的 API 端点：

    * 为敏感端点添加身份验证
    * 配置正确的 CORS 设置
    * 考虑实施速率限制

    询问 Agent：

    ```
    如何在我的应用中正确地对端点进行身份验证？
    ```
  </Accordion>

  <Accordion title="SQL 注入防护" icon="database">
    Agent 默认使用 ORM，这有助于防范 SQL 注入。如果需要编写自定义数据库查询：

    ```javascript theme={null}
    // 不佳：在查询中拼接字符串
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // 推荐：使用 ORM 进行参数化查询
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="安全标头" icon="code">
    为你的应用添加重要的安全标头：

    ```html theme={null}
    <!-- 在 index.html 中或通过后端添加 -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    你可以在 [securityheaders.com](https://securityheaders.com) 扫描网站，获取相关建议。

    询问 Agent：

    ```
    你能为我的应用添加安全标头吗？
    ```
  </Accordion>
</AccordionGroup>

<div id="ongoing-security-practices">
  ## 持续安全措施
</div>

<AccordionGroup>
  <Accordion title="及时更新依赖项" icon="arrow-rotate-right">
    定期检查可能存在漏洞的过时软件包：

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="妥善处理错误" icon="exclamation">
    不要在错误消息中暴露敏感信息：

    ```javascript theme={null}
    // 不佳：暴露敏感信息
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // 良好：使用通用错误消息
    catch (err) {
      console.error(err); // 在内部记录日志
      res.status(500).send('An error occurred');
    }
    ```

    询问 Agent：

    ```
    Help me implement proper error handling for my application
    ```
  </Accordion>

  <Accordion title="安全使用 Cookie" icon="cookie">
    使用 Cookie 时：

    * 设置 HttpOnly 标志，防止 JavaScript 访问
    * 使用 Secure 属性，强制采用 HTTPS
    * 设置 SameSite 属性，防止 CSRF

    询问 Agent：

    ```
    Help me secure my cookies for my application
    ```
  </Accordion>

  <Accordion title="文件上传安全" icon="upload">
    如果您的应用允许上传文件：

    * 限制文件类型和大小
    * 尽可能扫描恶意软件
    * 将文件存储在 Replit 的对象存储中
    * 生成新文件名，而非使用用户提供的文件名

    询问 Agent：

    ```
    Help me secure my file uploads for my application
    ```
  </Accordion>

  <Accordion title="速率限制" icon="clock">
    为 API 端点实施速率限制，尤其是与身份验证相关的端点：

    ```javascript theme={null}
    // 速率限制中间件示例
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 分钟
      max: 100 // 每个 IP 在每个 windowMs 内最多允许 100 个请求
    });

    app.use('/api/', limiter);
    ```

    询问 Agent：

    ```
    Help me implement rate limiting for my application
    ```
  </Accordion>
</AccordionGroup>

  ## 检查清单
</div>

以下检查清单可帮助你持续做好安全实践。

<div id="front-end-security-2">
  ## 前端安全
</div>

|   | 安全措施                      | 说明                         |
| - | ------------------------- | -------------------------- |
| ☐ | 全面使用 HTTPS                | 防范基本的窃听和中间人攻击              |
| ☐ | 输入验证和清理                   | 通过验证所有用户输入来防范 XSS 攻击       |
| ☐ | 不要在浏览器中存储敏感数据             | 不要在本地存储或客户端代码中保存 Secrets   |
| ☐ | CSRF 防护                   | 为表单和会更改状态的请求实施防 CSRF token |
| ☐ | 切勿在 frontend 中暴露 API 密钥 | API 凭据应始终保留在服务器端           |

<div id="back-end-security-2">
  ## 后端安全
</div>

|   | 安全措施     | 说明                                               |
| - | -------- | ------------------------------------------------ |
| ☐ | 身份验证基础   | 使用成熟的库，并妥善存储密码 (哈希加盐)                            |
| ☐ | 授权检查     | 执行操作前始终验证权限                                      |
| ☐ | API 端点保护 | 为每个 API 端点实施适当的身份验证                              |
| ☐ | SQL 注入防护 | 使用参数化查询或 ORM，切勿在原始 SQL 中直接使用用户输入                 |
| ☐ | 基本安全标头   | 实施 X-Frame-Options、X-Content-Type-Options 和 HSTS |
| ☐ | DDoS 防护  | 使用具备内置 DDoS 缓解功能的 CDN 或云服务                       |

<div id="practical-security-habits">
  ## 实用的安全实践
</div>

|   | 安全措施       | 说明                               |
| - | ---------- | -------------------------------- |
| ☐ | 及时更新依赖项 | 大多数漏洞源于过时的库                      |
| ☐ | 妥善处理错误     | 不要在错误消息中泄露敏感信息                   |
| ☐ | 安全使用 Cookie  | 设置 HttpOnly、Secure 和 SameSite 属性 |
| ☐ | 文件上传安全     | 验证文件类型和大小，并扫描恶意内容                |
| ☐ | 速率限制       | 在所有 API 端点上实施，尤其是与身份验证相关的端点      |
