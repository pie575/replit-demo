Replit App 내에서 실행할 수 있는 재사용 가능하고 사용자 지정 가능한 단계 시퀀스입니다. `python main.py`를 실행하는 정도로 단순할 수도 있고, 여러 단계로 이루어진 절차를 실행할 만큼 복잡할 수도 있습니다.

사용 사례 예시:

* 여러 서비스를 병렬로 실행(예: frontend + backend)
* 파일이나 명령을 순차적으로 실행(예: 린터 실행 → 테스트 실행, 컴파일 → 코드 실행)

[workflow 만들기](#creating-workflows)를 시작하려면 도구 사이드바 메뉴에서 Workflows 창으로 이동하거나, `Command + K`로 Workflows 창을 검색하세요.

<div id="available-task-types">
  ## 사용 가능한 task 유형
</div>

현재 사용할 수 있는 task 유형은 `Execute Shell Command`, `Install Packages`, `Run Workflow` 세 가지입니다.

<div id="execute-shell-command">
  ### Execute Shell Command
</div>

`Execute Shell Command`는 셸 명령을 저장한 뒤 Shell 창과 동일한 환경에서 실행합니다. 이 task 유형은 개별 파일 실행을 비롯해 다양한 용도로 활용할 수 있습니다:

```text theme={null}
python main.py
```

복잡한 저장 database 쿼리 명령 실행까지 가능합니다:

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Install Packages
</div>

`Install Packages`는 Replit에 내장된 dependency 관리 시스템을 활용해 project의 dependencies를 자동으로 감지하고 project에 필요한 packages를 설치합니다. UPM이 내부적으로 project에 설치할 packages를 판단하는 방식은 [Dependency Management](/ko/features/project-setup/dependency-management#the-universal-package-manager)에서 자세히 확인하세요.

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow`를 사용하면 현재 workflow에서 다른 workflow를 실행할 수 있습니다. 이를 통해 workflow를 재사용하고 서로 조합해 더 복잡한 workflow를 구성할 수 있습니다.

사용 사례 예시:

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

이 task 유형으로 workflow 간 dependencies를 구성하면, 하나의 workflow를 편집했을 때 이를 참조하는 다른 workflow들이 자동으로 최신 changes를 사용합니다. 단, 깊게 중첩된 workflow 호출에는 깊이 limit이 적용된다는 점에 유의하세요.

<div id="workflow-execution-mode">
  ## Workflow 실행 모드
</div>

Workflows는 순차 실행과 병렬 실행이라는 두 가지 실행 모드를 제공합니다.

<div id="sequential">
  ### 순차
</div>

순차 실행은 정의된 순서대로 각 task를 실행하며, 각 task가 끝날 때까지 기다린 후 다음 단계로 넘어갑니다. workflow 내의 task가 실패하면 해당 시퀀스의 실행을 중단합니다.

이 모드는 논리적으로 연결된 명령을 정의할 때 유용합니다. 예를 들어 main 브랜치에서 최신 changes를 가져온 다음, 현재 브랜치를 main 브랜치 위에 리베이스하는 Git 명령이 이에 해당합니다:

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="image" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="parallel">
  ### 병렬
</div>

병렬 실행은 각 task를 병렬로 실행하므로, 각 task는 workflow 내의 다른 task와 독립적으로 시작되고 실행됩니다. 하나의 task가 실패하더라도 다른 task의 실행은 중단되지 않습니다.

이 모드는 frontend와 backend 서버를 모두 시작해야 하는 풀스택 project를 실행할 때 사용할 수 있습니다:

<div id="creating-workflows">
  ## Workflow 만들기
</div>

Workflow는 Workflows pane에서 `+ New Workflow` 버튼을 클릭해 만들 수 있습니다. 먼저 workflow에 내용을 알 수 있는 이름을 지정하고, 적합한 실행 모드를 선택한 후 task를 추가하세요. task는 끌어다 놓아 원하는 순서로 재배치할 수 있습니다.

<div id="assign-workflow-to-run-button">
  ## 실행 버튼에 Workflow 할당하기
</div>

workflow를 실행 버튼에 할당하여 기본 실행 버튼 동작을 대체할 수도 있습니다([Replit App 구성하기](/ko/features/project-setup/configuration) 참고). `.replit`에 구성된 기본 Run 명령를 그대로 사용하려면 드롭다운에서 기본값인 &quot;Run Replit App&quot; 옵션을 선택하세요.

실행 버튼을 클릭하면 옆에 있는 드롭다운 메뉴에서 선택한 workflow가 실행됩니다. 실행 버튼으로 실행할 workflow를 변경하려면 드롭다운 메뉴에서 원하는 workflow를 클릭하세요.
