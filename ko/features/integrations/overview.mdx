Agent는 네 가지 유형의 통합을 지원하므로 아이디어를 앱으로 빠르게 구현할 수 있습니다:

* **Replit 관리형**: 자동으로 동작하는 내장 통합입니다. 앱을 만들면 Agent가 바로 사용할 수 있습니다.
* **Connectors**: Replit이 지원하는 자사 통합입니다. 한 번만 로그인하면 Agent가 채팅에서 바로 해당 서비스를 읽고 쓸 수 있으며 — 데이터 가져오기, 레코드 생성, 메시지 전송 등 — 여러 앱에서 이를 활용해 빌드할 수 있습니다.
* **외부 통합**: 함께 빌드할 수 있는 검증된 서드파티 서비스입니다. Agent에게 설정을 요청하면 되며, API 키는 직접 제공해야 합니다.
* **Agent 서비스**: Agent가 내부적으로 사용하는 유료 서드파티 API로, API 키가 필요하지 않습니다. 사용량은 Replit 크레딧에서 청구됩니다.

<Note>
  **plan 이용 가능 여부**: 대부분의 connector는 Core, Pro 또는 Enterprise 구독이 필요하며, 일부는 Free plan에서도 사용할 수 있습니다. workspace의 connector 카탈로그에서 현재 plan으로 사용할 수 있는 connector를 확인할 수 있습니다. Free plan builder도 데이터베이스, authentication 등 Replit 관리형 통합은 언제든 사용할 수 있습니다.
</Note>

<div id="getting-started">
  ## 시작하기
</div>

통합을 사용하려면 필요한 서비스나 기능을 언급하기만 하면 됩니다. 예를 들면 다음과 같습니다.

<AiPrompt>
  Stripe로 payments를 받고 SendGrid로 확인 이메일을 보내는 web app을 만들어 줘
</AiPrompt>

Agent가 이러한 키워드를 자동으로 감지해 필요한 코드와 configuration을 구현합니다.

<div id="let-agent-suggest-a-connector">
  ### Agent가 connector를 제안하도록 하기
</div>

파일 저장이나 이메일 발송처럼 여러 서비스가 같은 일을 처리할 수 있는 경우가 있습니다. 제공업체를 지정하지 않고 필요한 기능만 요청하면 Agent가 적합한 connector를 간단한 목록으로 보여줍니다. 원하는 항목을 선택하세요.

제공업체를 선택한 뒤 한 번만 로그인하면 계정이 연결됩니다. Agent는 여러분이 선택한 서비스를 사용해 앱을 만듭니다. 목록을 건너뛰려면 특정 서비스를 이름으로 직접 지정해 요청할 수도 있습니다.

<div id="connectors">
  ## Connectors
</div>

Connectors를 사용하면 Agent가 여러분의 서비스를 직접 읽고 쓸 수 있습니다. Connectors는 Replit이 공식 지원하는 자사 통합입니다. Project Editor의 Connectors 페이지에서 한 번만 로그인해 두면, 해당 연결을 여러 앱에서 재사용할 수 있습니다.

<Note>
  연결 정보는 Replit account에 연결되어 모든 앱에서 그대로 유지됩니다. 서비스를 한 번 연결해 두면 이후 만드는 어떤 앱에서든 사용할 수 있습니다.
</Note>

<div id="use-slack-with-agent">
  ### Agent와 함께 Slack 사용하기
</div>

Slack을 연결하면 사용자가 접근할 수 있는 대화를 Agent에게 context로 제공할 수 있습니다. Agent에게 메시지, 파일, 채널, 사람을 검색하도록 요청한 다음, 그 결과를 활용해 질문에 답하거나 작업을 이어가세요.

사용자가 권한을 허용하면 Agent는 다음 작업을 수행할 수 있습니다.

* 사용자가 속한 비공개 채널, 다이렉트 메시지, 그룹 다이렉트 메시지 읽기
* 앞뒤 context가 필요할 때 thread의 전체 답글 읽기
* 사용자 명의로 메시지 보내기
* Slack canvas 생성, 읽기, 업데이트

<AiPrompt>
  Alex와 나눈 다이렉트 메시지에서 launch plan에 대한 논의를 요약한 다음, follow-up 초안을 작성해 줘.
</AiPrompt>

<Info>
  Agent는 연결된 Slack 계정이 접근할 수 있는 Slack 대화와 콘텐츠에만 접근할 수 있습니다.
</Info>

<div id="configuring-oauth-app-with-replit">
  ### Replit에서 OAuth 앱 구성하기
</div>

<Note>
  **Enterprise 전용**: 사용자 지정 OAuth 앱을 구성하려면 Enterprise 구독이 필요합니다.
</Note>

Enterprise plan에서는 Replit의 기본 앱 대신 직접 만든 OAuth 앱을 connector에 사용할 수 있습니다. 이렇게 하면 조직이 OAuth 클라이언트를 직접 소유하고, 동의 화면에 자체 브랜딩을 표시하며, builder가 요청할 수 있는 scope를 정확하게 제어할 수 있습니다.

직접 만든 OAuth 앱으로 connector를 구성하려면 제공업체에서 세 가지를 준비해야 합니다. **Client ID**, **Client Secret**, 그리고 승인하려는 **scopes**입니다. 또한 authentication이 완료될 수 있도록 Replit의 콜백 URL을 제공업체에 등록해야 합니다.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Client ID, Client Secret, Connector Scopes 필드와 https://replit.com/connectors/oauth/callback으로 설정된 Redirect URL이 있는 connector OAuth 구성 대화 상자" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="제공업체에서 OAuth 앱 만들기">
    제공업체의 개발자 콘솔 또는 관리자 설정에 로그인해 새 OAuth 2.0 애플리케이션을 만듭니다. 제공업체마다 이 단계의 이름이 다르므로 **Create OAuth app**, **Register application**, **Create client credentials** 같은 옵션을 찾아보세요.
  </Step>

  <Step title="리디렉션 URL 설정하기">
    제공업체가 **Authorized redirect URI**(**Callback URL** 또는 **Redirect URL**이라고도 함)를 요청하면 다음을 입력하세요.

    ```
    https://replit.com/connectors/oauth/callback
    ```

    이 URL은 builder가 앱을 승인한 뒤 제공업체가 builder를 Replit으로 다시 보내는 주소입니다. 후행 슬래시, 프로토콜, 서브도메인까지 정확히 일치해야 합니다. 리디렉션 URI를 여러 개 추가하는 경우에도 이 주소는 반드시 포함해야 합니다.
  </Step>

  <Step title="Client ID와 Client Secret 복사하기">
    앱을 만들고 나면 제공업체가 **Client ID**와 **Client Secret**을 표시합니다.

    * **Client ID**: OAuth 앱의 공개 식별자입니다. URL이나 클라이언트 측 코드에 노출해도 안전합니다.
    * **Client Secret**: 요청이 해당 앱에서 온 것임을 증명하는 기밀 값입니다. 비밀번호처럼 다뤄야 하며, 저장소에 커밋하거나 공개적으로 공유해서는 안 됩니다. Replit이 이 값을 안전하게 대신 보관합니다.

    일부 제공업체는 생성 시점에 client secret을 한 번만 표시합니다. 즉시 복사한 뒤 Replit에 붙여넣을 때까지 안전한 곳에 보관하세요.
  </Step>

  <Step title="scope 선택하기">
    **Scope**는 OAuth 앱이 builder를 대신해 무엇을 읽고 쓸 수 있는지 정의하는 permissions입니다. 제공업체마다 자체 API 문서에 scope 목록을 공개합니다.

    Replit에서 connector를 구성할 때 입력하는 scope는 제공업체에 등록한 scope와 **정확히 일치**해야 합니다(URL 접두사를 포함해 문자 하나까지 동일해야 함). 불일치 오류가 발생하는 흔한 원인은 다음과 같습니다.

    * 전체 URL 접두사 누락(예: `https://www.googleapis.com/auth/drive.file` 대신 `drive.file` 입력).
    * 불필요한 공백이나 후행 쉼표.
    * 제공업체의 앱에서 활성화되지 않은 scope를 Replit에서 요청.

    builder에게 필요한 최소한의 scope로 시작하고, 필요하면 나중에 추가하세요. 대부분의 제공업체는 앱을 다시 만들지 않고도 scope를 업데이트할 수 있습니다.
  </Step>

  <Step title="Replit에서 connector 구성하기">
    조직의 **Connectors** 페이지에서 **Add new 통합**을 선택하고 서비스를 고른 다음, 제공업체에서 받은 **Client ID**, **Client Secret**, **Scopes**를 붙여넣습니다. **Configure**를 선택해 저장하세요.
  </Step>
</Steps>

<Note>
  구성 후에도 authentication에 실패한다면, 제공업체에 등록한 리디렉션 URL이 `https://replit.com/connectors/oauth/callback`과 정확히 일치하는지, 그리고 Replit에 입력한 모든 scope가 제공업체의 앱에서도 승인되어 있는지 다시 확인하세요.
</Note>

<div id="reconnecting-integrations">
  ## 통합 다시 연결하기
</div>

연결된 서비스가 작동을 멈추면(예: 로그인 세션이 만료되거나 권한이 변경된 경우) Replit이 Project Editor에 재연결 알림을 표시합니다. 이 알림을 선택하면 편집기를 벗어나지 않고 바로 통합을 다시 연결할 수 있습니다.

<div id="debugging-connectors">
  ## connector 디버깅
</div>

서비스 연결에 문제가 있나요? 다음 가이드에서 자주 발생하는 오류와 해결 방법을 안내합니다.

<AccordionGroup>
  <Accordion title="Google Workspace: &#x22;This app is blocked&#x22;">
    Google Drive, Docs, Sheets, Calendar 또는 Gmail을 연결할 때 **&quot;This app is blocked&quot;** 메시지가 표시된다면, 조직의 Google Workspace에서 서드파티 OAuth app을 제한하고 있을 가능성이 높습니다. 해결 방법은 전체 문제 해결 가이드를 참고하세요.

    [Google connector의 &quot;This app is blocked&quot; 오류 해결하기](/ko/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce: &#x22;Connection Expired&#x22;">
    Salesforce connector가 **&quot;Connection Expired&quot;** 오류와 함께 작동을 멈춘다면, Salesforce 조직의 refresh token 정책이 일정 기간이 지나면 token을 만료시키도록 설정되어 있을 가능성이 높습니다. Connected App 설정을 업데이트하는 방법은 전체 문제 해결 가이드를 참고하세요.

    [Salesforce 연결 만료 오류 해결하기](/ko/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
