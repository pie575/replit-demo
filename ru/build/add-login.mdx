Вы уже видели Velocity в разделе [Добро пожаловать в Replit](/ru/welcome) — приложение для аренды премиальных суперкаров. Сейчас любой, кто перейдёт по публичному URL, может увидеть все бронирования. Никто не бронирует Lamborghini анонимно. Добавьте вход в систему — и каждый клиент увидит только свои бронирования и сохранённые автомобили.

<div id="tell-agent-to-add-sign-in">
  ## Попросите Agent добавить вход
</div>

Для Velocity используйте Clerk. Интеграция Clerk в Replit предоставляет вашему приложению фирменный экран входа, клиентские учётные записи внутри Velocity (а не учётные записи Replit) и полный контроль над внешним видом — идеально для премиального бренда проката. Agent автоматически всё настроит, поэтому вам не нужно регистрироваться в Clerk Dashboard или вставлять ключи.

Agent создаст tenant Clerk для Velocity, добавит компоненты входа, ограничит доступ к процессу бронирования, привяжет каждое бронирование к вошедшему клиенту и добавит выход. Следите за сборкой в чате с Agent.

<div id="test-it-with-two-customers">
  ## Проверьте работу с двумя клиентами
</div>

Одной учётной записи недостаточно — нужны две, чтобы убедиться, что бронирования не смешиваются.

1. Откройте Velocity в Preview и просмотрите автомобили, не входя в систему. Автопарк должен быть виден.
2. Нажмите Reserve у автомобиля. Откроется экран входа Clerk.
3. Зарегистрируйтесь, указав свой адрес электронной почты, и оформите бронирование (например, 911 на выходные).
4. Выйдите из системы. Раздел «My bookings» должен исчезнуть, а процесс бронирования снова будет предлагать войти в систему.
5. Откройте Preview в окне инкогнито и зарегистрируйтесь с другим адресом электронной почты. Забронируйте другой автомобиль.
6. Вернитесь в первое окно, войдите в систему и убедитесь, что по-прежнему видите своё бронирование, а не бронирование второго клиента.

Если оба клиента видят одни и те же бронирования, значит, они ещё не привязаны к пользователю, вошедшему в систему. Сообщите Agent точное описание проблемы:

  <br />

<div id="publish-and-sign-in-on-the-public-url">
  ## Опубликуйте и войдите по публичному URL
</div>

Снова опубликуйте Velocity из чата с Agent или через плитку Publishing, затем откройте публичный URL в новой вкладке и войдите в систему. Clerk предоставляет отдельные среды Development и Production — Agent автоматически подключает учетные данные Production к опубликованному приложению, поэтому вход по публичному URL работает сразу.

Теперь у Velocity есть реальные клиенты. Каждый из них входит в личный раздел с бронированиями — никто другой их не видит.

<div id="need-further-help">
  ## Нужна дополнительная помощь?
</div>

* **Скрыто всё приложение:** попросите Agent оставить просмотр автомобилей общедоступным, а защиту включить только для страниц бронирования и аккаунта.
* **Клиенты видят бронирования друг друга:** попросите Agent привязать каждое бронирование и сохранённый автомобиль к выполнившему вход клиенту.
* **Вход работает в Preview, но не после публикации:** откройте публичный URL в новой вкладке и сообщите Agent точный текст ошибки. Убедитесь, что Agent подготовил среду Production Clerk.
* **Для прототипов нужен быстрый вход без настройки:** Replit Auth использует учётные записи Replit ваших клиентов, поэтому вам не нужно управлять tenant Clerk — см. [Replit Auth](/ru/features/auth-and-identity/authentication).
