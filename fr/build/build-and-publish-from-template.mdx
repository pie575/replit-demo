⏰ *Durée estimée : 10 minutes*

À la fin de ce guide, vous aurez publié une petite app à une URL que vous pourrez partager.

<Frame>
  <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="Le template sélectionné transformé en site web et ouvert à son URL Replit publique" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
</Frame>

Vous partirez d’un template soigné, le transformerez en site web fonctionnel, puis le publierez. Les templates disponibles peuvent changer : choisissez-en un qui correspond à ce que vous souhaitez créer.

<div id="before-you-start">
  ## Avant de commencer
</div>

Vous avez besoin d’un [compte Replit](https://replit.com). Pour développer une nouvelle application à partir d’une design frame, vous devez disposer de Core ou Pro. Consultez [Développer votre design](/fr/design/build-your-design) et [Facturation](/fr/billing/ai-billing) pour en savoir plus sur les forfaits.

L’objectif est de réaliser un cycle complet :

* Choisissez un template dans [Replit Design](https://replit.com/design),
* Développez-le avec [Agent](/fr/features/agent/overview),
* Testez l’application,
* Publiez-la et partagez-la.

Agent est l’assistant de développement IA de Replit. Décrivez ce que vous souhaitez, et Agent vous aide à créer, expliquer et corriger l’application.

<div id="choose-build-and-publish-a-template">
  ## Choisir, créer et publier un template
</div>

<Steps>
  <Step title="Parcourir les modèles de Design">
    Ouvrez [replit.com/design](https://replit.com/design). Parcourez les modèles à la une ou filtrez par **Pages de destination**, **Mobile**, **Prototypes** et d’autres formats.

    <Frame>
      <img src="/assets/mirror/01-design-gallery-5303cf1cf6d2.jpg" alt="La galerie Replit Design avec des modèles à la une et des filtres par format" width="1280" height="720" data-path="images/first-app-template/01-design-gallery.jpg" />
    </Frame>
  </Step>

  <Step title="Prévisualiser et utiliser un template">
    Sélectionnez un template pour l’examiner, puis sélectionnez **Use template**. Replit crée un nouveau projet et place le template sur le Canvas de Design. Si vous êtes plutôt parti de la page de présentation d’un template, consultez [Commencer à partir d’un template](/fr/design/start-from-a-template) pour découvrir le processus de remix.

    <Frame>
      <img src="/assets/mirror/02-template-preview-facda2e40956.jpg" alt="Aperçu d’un template Replit Design avec le bouton Use template" width="1280" height="720" data-path="images/first-app-template/02-template-preview.jpg" />
    </Frame>

    Le template remixé s’ouvre sur le Canvas de Design dans son nouveau projet.

    <Frame>
      <img src="/assets/mirror/03-remixed-design-35b051544510.jpg" alt="Le template sélectionné remixé sur le Canvas de Design dans un nouveau projet Replit" width="1280" height="720" data-path="images/first-app-template/03-remixed-design.jpg" />
    </Frame>
  </Step>

  <Step title="Transformez le design en site web">
    Un template commence par une maquette. Avant de pouvoir le publier, passez à **Build** et demandez à Agent de transformer la maquette sélectionnée en site web fonctionnel. Par exemple :

    > Transforme ce template sélectionné en site web fonctionnel. Préserve son design visuel et assure le bon fonctionnement de sa navigation et de ses actions de contact.

    Agent crée un artefact de site web dans le même projet et utilise la maquette sélectionnée comme base.

    <Note>
      Le bouton **Publier** est également visible dans Design. Si le projet ne contient que des maquettes, Publishing indique qu’il n’y a encore rien à déployer et vous invite à demander à Agent de créer une app. Une fois qu’un artefact de site web existe, vous pouvez publier depuis Design ou Build.
    </Note>

    <Frame>
      <img src="/assets/mirror/04-build-request-d5a5a3428361.jpg" alt="L’espace de travail Build avec une maquette de portfolio sélectionnée jointe, la demande de création dans le Chat Agent et Publishing indiquant qu’un projet ne contenant que des maquettes n’a encore rien à déployer" width="1280" height="720" data-path="images/first-app-template/04-build-request.jpg" />
    </Frame>
  </Step>

  <Step title="Vérifiez le bon fonctionnement de l’app dans Preview">
    Lorsque Agent a terminé, ouvrez [Preview](/fr/features/editor/preview) et utilisez l’app comme le ferait un visiteur. Preview vous permet de tester l’app pendant son développement, avant sa publication.

    Vérifiez que vous pouvez :

    * Naviguer dans les principales sections.
    * Utiliser les boutons et formulaires du template.
    * Voir un état clair de réussite ou de validation après une action.
    * Actualiser la page et réutiliser le site.
    * Redimensionner Preview à la largeur d’un téléphone.

    Si quelque chose ne fonctionne pas, décrivez le problème à Agent. Vous n’avez pas besoin de diagnostiquer le code vous-même.

    <Frame>
      <img src="/assets/mirror/05-preview-d5702e9d9ac8.jpg" alt="Le site web basé sur un template s’exécutant dans Preview du Project Editor" width="1280" height="720" data-path="images/first-app-template/05-preview.jpg" />
    </Frame>

    <Tip>
      Vous souhaitez explorer des variantes visuelles avant de publier ? Consultez [Explorer les suggestions](/fr/design/explore-suggestions) pour générer plusieurs apparences côte à côte et appliquer celle que vous préférez.
    </Tip>
  </Step>

  <Step title="Publier votre app">
    Lorsque l’aperçu fonctionne, sélectionnez **Publier**. Confirmez le sous-domaine généré, choisissez qui peut accéder à l’app et vérifiez les paramètres de sécurité. Sélectionnez ensuite **Publier** dans la boîte de dialogue.

    La publication crée une version publique de votre app avec une URL que vous pouvez partager.

    <Frame>
      <img src="/assets/mirror/06-publish-dialog-2f79654c6dfb.jpg" alt="La boîte de dialogue Publier avec le sous-domaine généré, les paramètres d’accès et le bouton Publier" width="1280" height="720" data-path="images/first-app-template/06-publish-dialog.jpg" />
    </Frame>
  </Step>

  <Step title="Ouvrez votre application publiée">
    Ouvrez l’URL publique dans un nouvel onglet du navigateur et effectuez les mêmes vérifications. L’application doit fonctionner en dehors du Project Editor avant de la partager.

    Si l’application publiée se comporte différemment dans Preview, vérifiez les logs de publication et les paramètres de production nécessaires à l’application. Pour les problèmes de publication courants, consultez [Résoudre les problèmes de publication](/fr/build/troubleshooting).

    <Frame>
      <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="Le site web final créé à partir du template, ouvert à son URL publique Replit" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
    </Frame>
  </Step>
</Steps>

<div id="congratulations-you-shipped-your-first-app">
  ## 🎉 Félicitations — vous avez publié votre première app
</div>

Vous êtes passé d’un template de conception à une URL publique partageable. Au passage, vous avez :

* Choisi et remixé un template dans Replit Design.
* Demandé à Agent de transformer la conception sélectionnée en site web fonctionnel.
* Testé le résultat dans Preview.
* Publié l’app et l’avez ouverte à son URL publique.

C’est un flux de travail Replit complet : choisir un point de départ, créer, tester, améliorer et publier.
