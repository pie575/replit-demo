Ваше приложение подключается к базе данных с помощью учётных данных, которыми управляет Replit. Чтобы их посмотреть, выберите базу данных в инструменте **Database** и откройте вкладку **Settings**. Там отображаются строка подключения, объём используемого хранилища и подробные сведения о подключении.

<div id="section">
  ## Переменные окружения
</div>

Для подключения к базе данных разработки доступны следующие переменные окружения.

* `DATABASE_URL` — способ подключения к базе данных и аутентификации в ней

Приложение использует её автоматически. Поскольку `DATABASE_URL` действует только в рамках одного приложения, база данных разработки недоступна из других приложений (даже ваших собственных) и из внешних средств просмотра баз данных. Даже если эта переменная случайно попадёт к посторонним, использовать её для доступа к базе данных и её изменения не получится.

<Info>
  Если ваша база данных разработки всё ещё размещена на [устаревшей инфраструктуре Neon](/ru/ja/features/data-and-storage/development-and-production#legacy-development-database), вам также доступны дополнительные переменные `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` и `PGPORT`. Для баз данных на актуальной инфраструктуре Replit они **не** предоставляются — в этом случае используйте `DATABASE_URL`.
</Info>

<Warning>
  Если вы всё ещё используете устаревшую базу данных разработки Neon, никому не передавайте `DATABASE_URL`. Она содержит учётные данные базы данных, и любой, у кого они окажутся, сможет получить доступ к базе данных и изменить её. Не публикуйте её в общедоступных местах и не вставляйте в обращения в службу поддержки.
</Warning>

<div id="section-2">
  ## Подключение внешних инструментов
</div>

Строка подключения на вкладке **Settings** **продакшен-базы данных** позволяет подключаться к ней из любого SQL-клиента, совместимого с PostgreSQL.

<div id="section-3">
  ## Безопасность
</div>

Когда вы добавляете интеграцию с базой данных с помощью Agent, добавляется ORM (Object-Relational Mapper), который обрабатывает всё взаимодействие с базой данных и обеспечивает встроенную защиту:

* **Проверка схемы**: убеждается, что данные соответствуют ожидаемому формату
* **Очистка данных**: автоматически очищает данные, вводимые в конструкторе, предотвращая атаки с использованием SQL-инъекций

<div id="section-4">
  ## Повторная генерация учётных данных продакшен-базы данных
</div>

Если строка подключения к продакшен-базе данных была скомпрометирована, повторно сгенерируйте учётные данные в инструменте Database. При этом создаётся новый пароль для продакшен-базы данных Neon. Прежняя строка подключения сразу перестаёт работать.

Повторно сгенерировать учётные данные можно при соблюдении всех следующих условий:

* У приложения есть продакшен-база данных Neon.
* Вы являетесь владельцем приложения или администратором рабочего пространства-владельца.
* Вы используете Replit в веб-браузере.
* В данный момент не выполняется деплой.
* Если у приложения есть работающий деплой, его последняя сборка завершилась успешно и используется [Autoscale или Reserved VM](/ru/ja/features/publishing/deployment-types).

<Warning>
  Это действие нельзя отменить. Прежняя строка подключения сразу перестаёт работать. Если у приложения есть работающий деплой, во время повторного деплоя возможна кратковременная недоступность.
</Warning>

<div id="section-5">
  ### Повторная генерация учётных данных
</div>

1. На панели Tools выберите **Database**.

2. Выберите **Production Database**, затем откройте вкладку **Settings**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="Вкладка Settings продакшен-базы данных с разделом Advanced, где показаны строка подключения, использование хранилища и строка Regenerate credentials" width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. В разделе **Advanced** разверните строку **Regenerate credentials**.

4. Нажмите кнопку **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Развёрнутая строка Regenerate credentials в разделе Advanced с отображаемой кнопкой Regenerate credentials" width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. В диалоговом окне подтверждения нажмите **Regenerate credentials**, чтобы подтвердить действие.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="Диалоговое окно подтверждения Regenerate credentials с предупреждением о том, что действие необратимо и существующие строки подключения сразу перестанут работать" width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Нажмите **Refresh**, чтобы загрузить новую строку подключения.

7. Если у приложения есть работающий деплой, откройте **Publishing** и проверьте состояние повторного развёртывания.

8. Замените все строки подключения, скопированные во внешние инструменты и пользовательские интеграции.

<div id="section-6">
  ### Что изменится
</div>

При повторной генерации учётных данных создаётся новый пароль для продакшен-базы данных. В строке подключения меняется только пароль. Хост, имя базы данных и роль остаются прежними.

Для подходящих активных деплойментов Replit повторно развернёт последнюю успешную сборку с обновлённой строкой подключения.
