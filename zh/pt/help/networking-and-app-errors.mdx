本文涵盖你可能在已部署应用中遇到的错误。若要进行更全面的故障排除，请参阅[部署故障排除](/zh/pt/build/troubleshooting)。

<AccordionGroup>
  <Accordion title="已部署的应用返回 403 禁止访问错误——如何解决？">
    已部署应用出现 403 通常是由以下原因之一造成的：

    * **请求标头过大**—Cookie 过多可能导致标头过大，从而在边缘节点被拒绝。请清除浏览器中该域名的 Cookie，然后重新测试。
    * **缺少身份验证**—请求未包含所需的登录或会话 token。
    * **访问限制**—你的应用可能配置为阻止某些流量。请参阅[私有部署](/zh/pt/features/publishing/private-deployments)和[外部访问 token](/zh/pt/features/deployment-customization/external-access-tokens)。

    如需进行详细诊断，请将部署日志粘贴到新的 Agent Chat 中。
  </Accordion>

  <Accordion title="我的应用显示“Application failed to respond”——这是什么意思？">
    你的应用进程未监听 Replit 所需的端口。Replit 会通过环境变量 `PORT` 提供正确的端口，因此请绑定到该变量，而不要使用硬编码的端口值：

    ```js theme={null}
    const PORT = process.env.PORT || 3000;
    ```

    ```python theme={null}
    port = int(os.environ.get("PORT", 3000))
    ```

    应用也可能在绑定端口前崩溃——请检查部署日志中是否有启动错误。使用 [Autoscale 部署](/zh/pt/features/publishing/deployment-types#autoscale) 时，空闲一段时间后的首次请求可能需要几秒钟 (即冷启动) ，这是正常现象。
  </Accordion>

  <Accordion title="如何修复我已部署的 Replit 应用中的 CORS 错误？">
    CORS 错误表示你的前端和后端位于不同的源，且后端未配置为允许跨源访问。如果它们属于同一个应用，请使用 `/api/endpoint` 这样的相对 URL，即可完全避免 CORS。

    否则，请将后端配置为允许来自前端源的请求。以 Express 为例：

    ```js theme={null}
    const cors = require("cors");
    app.use(cors({ origin: "https://seu-frontend.replit.app" }));
    ```

    部署前，请仅允许所需的特定来源。请参阅[部署故障排除](/zh/pt/build/troubleshooting)。
  </Accordion>

  <Accordion title="我的应用在本地运行正常，但部署后出现网络错误">
    已部署的应用在生产环境与本地配置不一致时可能会失败。请检查以下三项：

    1. **硬编码的 localhost URL**—将 `localhost:3000` 或 `127.0.0.1` 替换为相对路径或基于环境的 URL，然后重新部署。
    2. **缺少生产环境 Secrets**—确认部署 Secrets 中已设置所有必需的密钥。请参阅 [Secrets](/zh/pt/core-concepts/project-editor/app-setup/secrets)。
    3. **未在生产环境运行迁移**—请在部署前对生产数据库运行所有待执行的迁移。

    如果错误仍然存在，请[联系 Replit 支持](https://replit.com/support)，并提供错误信息和已尝试的步骤。
  </Accordion>

  <Accordion title="如何排查已部署应用中的 502 Bad Gateway 错误？">
    502 通常表示应用进程崩溃，或返回了服务器无法处理的输出。请检查部署日志，查看 502 出现前是否有崩溃错误——未处理的 Promise 拒绝和未捕获的异常可能会导致 Node.js 进程悄然崩溃。

    添加一个处理程序来暴露崩溃信息：

    ```js theme={null}
    process.on("uncaughtException", (err) => console.error("Uncaught:", err));
    ```

    在日志中找到根本原因错误后，将其粘贴到新的 Agent Chat 中以获取修复帮助。
  </Accordion>

  <Accordion title="我的应用无法向外部 API 发起请求——该检查什么？">
    首先确认请求是被拦截，而非代码本身执行失败。打开部署日志，查找有关出站请求被拦截或重定向的消息。

    常见原因及解决方法：

    * **自引用 URL**—如果后端调用自身的公开 URL (例如 `fetch("https://meuapp.replit.app/api/...")`) ，请使用相对路径，例如 `fetch("/api/...")`。
    * **构建阶段发起的请求**—请在运行时发起出站请求，而不是在构建期间。
    * **网络限制**—在企业或学校网络中，出站连接可能会被拦截；请向网络管理员确认。

    如果以上情况均不适用，但请求仍被拦截，请携带相关日志行[联系 Replit 支持](https://replit.com/support)。
  </Accordion>

  <Accordion title="重新发布后，我的应用网址变了——还能恢复原来的子域名吗？">
    `.replit.app` 子域名根据您的项目名称生成；取消发布后再重新发布时，无法保证其保持不变，尤其是在项目已重命名的情况下。

    永久解决方案是使用[自定义域名](/zh/pt/features/publishing/custom-domains)，它在重新部署后仍可保持不变。若要尝试恢复旧子域名，请确保项目名称与原名称一致 (如有需要，请改回原名) ，然后重新发布——Replit 无法手动重新分配已释放的子域名。请参阅[项目地理区域](/zh/pt/features/publishing/project-geography)。
  </Accordion>
</AccordionGroup>
