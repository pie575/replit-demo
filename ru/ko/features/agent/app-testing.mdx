App Testing позволяет Agent тестировать созданные App в реальном браузере. Agent взаимодействует с приложением как реальный пользователь: перемещается по нему, нажимает элементы и проверяет работу функций. Эта функция самостоятельного тестирования помогает убедиться, что App работает корректно, и позволяет Agent автоматически находить и исправлять проблемы.

Когда App Testing включён, Agent периодически решает самостоятельно запустить тестирование, если считает, что внесено достаточно изменений. Agent не тестирует приложение после каждого сообщения пользователя, а самостоятельно определяет, когда тестирование принесёт наибольшую пользу.

<Note>
  Сейчас App Testing доступен для полнофункциональных веб-приложений на JavaScript и Python с использованием Streamlit.
</Note>

<div id="section">
  ### Основные преимущества
</div>

* **Больше автономности**: Agent может работать дольше без участия человека
* **Более высокое качество**: помогает выявлять и устранять проблемы на ранних этапах, уменьшая количество ошибок в App
* **Экономичность**: снижает потребность в дополнительных сеансах отладки благодаря выявлению проблем в процессе разработки
* **Интерактивная проверка**: воспроизведение видео и навигация по отдельным фрагментам для тщательного анализа результатов

<div id="section-2">
  ### Процесс тестирования
</div>

Когда Agent решает провести самотестирование, происходит следующее:

1. **Предпросмотр в браузере**: в панели Agent отображается предпросмотр в браузере
2. **Визуальное тестирование**: наблюдайте, как курсор Agent кликает по элементам App и проверяет функциональность
3. **Имитация действий реального пользователя**: Agent взаимодействует с приложением как реальный пользователь и при необходимости вводит тестовые данные
4. **Автоматический анализ**: Agent анализирует результаты тестирования и выявляет все проблемы
5. **Самостоятельное исправление**: Agent предоставляет сводку тестирования и автоматически исправляет обнаруженные проблемы

<div id="section-3">
  ## Ключевые возможности
</div>

Agent взаимодействует с приложением как реальный пользователь и интеллектуально тестирует:

* **Пользовательский интерфейс**: кнопки, формы, навигацию и визуальные элементы
* **Функциональность**: основные функции и пользовательские сценарии
* **Интеграции**: вызовы API, взаимодействие с базами данных и сторонними сервисами
* **Производительность и доступность**: время загрузки, отзывчивость и соответствие стандартам доступности

<div id="section-4">
  ## Использование
</div>

App Testing находится в разделе **Расширенные настройки** раскрывающегося списка настроек Agent в поле ввода чата. Включайте его при использовании режима Economy или Power. В режиме Lite App Testing остаётся отключённым.

<Note>
  App Testing — одна из автономных возможностей Agent, которая поставляется вместе со встроенной проверкой кода. Подробнее о других [возможностях
  Agent](/ru/ko/features/agent/overview).
</Note>

<div id="section-5">
  ## Передача управления
</div>

Иногда во время тестирования Agent сталкивается с препятствиями, для преодоления которых нужна ваша помощь. Чаще всего это вход в учётную запись пользователя, например Gmail. В таком случае Agent отображает всплывающее окно с кнопкой «Начать передачу управления».

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="Интерфейс передачи управления в App Testing с инструкциями по устранению ошибок и CAPTCHA, а также кнопками Skip и Begin take over" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

Нажмите «Начать передачу управления», чтобы перейти к предпросмотру теста, выполнить необходимые действия и позволить Agent продолжить работу. Если Agent не может продолжить без вашей помощи, нажмите «Пропустить», чтобы пропустить передачу управления и завершить App Testing. Если вы не ответите в течение 10 минут, Agent продолжит работу так, как будто вы нажали «Пропустить».

<div id="section-6">
  ### Ожидаемое поведение
</div>

* **Пропуск**: При необходимости нажмите кнопку пропуска, чтобы пропустить тест и продолжить разработку
* **Интерактивное воспроизведение видео**: После теста нажмите видео, чтобы воспроизвести весь сеанс тестирования
* **Навигация по сегментам**: Используйте ползунок внизу, чтобы перейти к нужному сегменту теста

<div id="section-7">
  ## Устранение неполадок
</div>

**Тест неожиданно завершился с ошибкой**

* Пропустите тест, затем снова введите промпт, чтобы повторить попытку
* Проверьте, нет ли динамического контента, который может влиять на время выполнения теста
* Проверьте точность сценария тестирования

**Недостаточное тестовое покрытие**

* Более подробно опишите функции App
* Явно укажите важные пользовательские сценарии, которые необходимо протестировать

**App Testing вообще не работает?**

* Сейчас App Testing работает только с веб-приложениями[*](#how-app-testing-works)

<div id="section-8">
  ## Цены и Usage
</div>

App Testing входит в модель ценообразования Agent, основанную на затраченных усилиях, и имеет следующие важные особенности в отношении расходов:

* **В зависимости от использования**: стоимость тестирования зависит от затраченных усилий (более простые тесты стоят меньше)
* **Соотношение затрат и выгоды**: хотя тестирование требует затрат, оно может снизить общие расходы: раннее выявление ошибок позволяет избежать дополнительных промптов и работы Agent
* **Эффективная разработка**: автоматизированный подход сокращает потребность в ручной отладке и доработках

<Tip>
  **Экономичное тестирование**: хотя App Testing увеличивает расходы на использование, оно часто снижает общие затраты, позволяя избежать дополнительных сеансов Agent для устранения проблем, которые можно было выявить при тестировании.
</Tip>

<div id="section-9">
  ## Следующие шаги
</div>

Готовы использовать App Testing в своём проекте?

1. **Начните разработку**: создайте App с помощью Agent — тестирование включится автоматически

3. **Повторяйте**: используйте результаты тестирования, чтобы улучшать приложение
4. **Масштабируйте**: используйте App Testing в более крупных и сложных проектах
