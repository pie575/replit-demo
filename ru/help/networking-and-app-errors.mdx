Здесь собраны ответы по ошибкам, которые могут возникнуть в опубликованном приложении. Более общие рекомендации по устранению неполадок см. в разделе [Устранение неполадок развёртываний](/ru/build/troubleshooting).

<AccordionGroup>
  <Accordion title="Моё опубликованное приложение возвращает ошибку 403 Forbidden — как это исправить?">
    Ошибка 403 в опубликованном приложении обычно возникает по одной из следующих причин:

    * **Слишком большие заголовки запроса**—из-за слишком большого количества файлов cookie заголовки могут стать настолько большими, что будут отклонены на периферии сети. Очистите файлы cookie для этого домена в браузере и повторите попытку.
    * **Отсутствует аутентификация**—запрос не содержит необходимого токена входа или сессии.
    * **Ограничение доступа**—ваше приложение может быть настроено на блокировку части трафика. См. [приватные deployments](/ru/features/publishing/private-deployments) и [внешние токены доступа](/ru/features/deployment-customization/external-access-tokens).

    Для подробной диагностики вставьте логи развёртывания в новый чат с Agent.
  </Accordion>

  <Accordion title="В моём приложении отображается сообщение «Application failed to respond» — что это значит?">
    Процесс вашего приложения не прослушивает порт, который ожидает Replit. Replit передаёт нужный порт через переменную окружения `PORT`, поэтому используйте его вместо жёстко заданного значения:

    ```js theme={null}
    const PORT = process.env.PORT || 3000;
    ```

    ```python theme={null}
    port = int(os.environ.get("PORT", 3000))
    ```

    Возможно, ваше приложение аварийно завершилось ещё до привязки порта — проверьте логи развёртывания на наличие ошибок запуска. При использовании [Autoscale deployments](/ru/features/publishing/deployment-types#autoscale) первый запрос после периода простоя может обрабатываться несколько секунд (холодный старт) — это нормально.
  </Accordion>

  <Accordion title="Как исправить ошибки CORS в опубликованном App Replit?">
    Ошибка CORS означает, что ваш фронтенд и бэкенд находятся на разных источниках, а бэкенд не настроен на разрешение таких запросов. Если они входят в состав одного приложения, используйте относительные URL, например `/api/endpoint`, чтобы полностью избежать CORS.

    В противном случае настройте бэкенд так, чтобы он разрешал запросы с источника вашего фронтенда. Например, для Express:

    ```js theme={null}
    const cors = require("cors");
    app.use(cors({ origin: "https://your-frontend.replit.app" }));
    ```

    Перед публикацией разрешайте только те источники (origins), которые вам действительно нужны. См. [Устранение неполадок с развёртываниями](/ru/build/troubleshooting).
  </Accordion>

  <Accordion title="Моё приложение работает локально, но после публикации возникают ошибки сети">
    Опубликованные приложения перестают работать, когда продакшен-окружение отличается от локального. Проверьте три момента:

    1. **Жёстко прописанные адреса localhost** — замените `localhost:3000` или `127.0.0.1` относительными путями либо адресами из переменных окружения и выполните повторный деплой.
    2. **Отсутствующие продакшен-секреты** — убедитесь, что все необходимые ключи заданы в секретах деплоя. См. [Secrets](/ru/core-concepts/project-editor/app-setup/secrets).
    3. **Миграции не выполнены в продакшене** — примените ожидающие миграции к продакшен-базе данных перед публикацией.

    Если ошибки повторяются, [обратитесь в службу поддержки Replit](https://replit.com/support), указав текст ошибки и шаги, которые вы уже предприняли.
  </Accordion>

  <Accordion title="Как устранить ошибку 502 Bad Gateway в моём опубликованном App?">
    Ошибка 502 обычно означает, что процесс вашего приложения аварийно завершился или вернул данные, которые сервер не смог обработать. Проверьте логи deployment на наличие ошибок сбоя непосредственно перед появлением ошибок 502 — необработанные отклонения промисов и неперехваченные исключения могут незаметно «уронить» процесс Node.js.

    Добавьте обработчик, чтобы отслеживать сбои:

    ```js theme={null}
    process.on("uncaughtException", (err) => console.error("Uncaught:", err));
    ```

    Когда найдёте в логах исходную ошибку, вставьте её в новый чат с Agent, чтобы получить помощь в её исправлении.
  </Accordion>

  <Accordion title="Моё приложение не может отправлять запросы к внешним API — что проверить?">
    Сначала убедитесь, что запрос блокируется, а не завершается ошибкой в вашем коде. Откройте логи deployment и найдите сообщения о заблокированных или перенаправленных исходящих запросах.

    Распространённые причины и способы устранения:

    * **Самоссылочные URL-адреса**—если ваш бэкенд обращается к собственному публичному URL (например, `fetch("https://myapp.replit.app/api/...")`), используйте относительный путь, например `fetch("/api/...")`.
    * **Запросы на этапе сборки**—выполняйте исходящие запросы во время работы приложения, а не в процессе сборки.
    * **Сетевые ограничения**—в корпоративной или учебной сети исходящие подключения могут быть заблокированы; уточните у администратора сети.

    Если ничего из перечисленного не подходит, но запросы всё равно блокируются, [обратитесь в службу поддержки Replit](https://replit.com/support), приложив соответствующие строки логов.
  </Accordion>

  <Accordion title="URL моего приложения изменился после повторной публикации — можно ли вернуть прежний поддомен?">
    Поддомен `.replit.app` формируется из названия вашего project, и нет гарантии, что он останется прежним после отмены публикации и повторной публикации — особенно если project был переименован.

    Надёжное решение — [пользовательский домен](/ru/features/publishing/custom-domains): он сохраняется при повторных развёртываниях. Чтобы попытаться вернуть прежний поддомен, убедитесь, что название project совпадает с исходным (при необходимости переименуйте его обратно), и опубликуйте заново — вручную переназначить освободившийся поддомен Replit не может. См. [Project geography](/ru/features/publishing/project-geography).
  </Accordion>
</AccordionGroup>
