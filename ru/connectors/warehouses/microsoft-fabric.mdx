Создавайте приложения на базе ИИ в Replit и публикуйте их напрямую в Microsoft Fabric — со встроенными возможностями корпоративного управления и безопасности. Интеграция с Microsoft Fabric превращает управляемые корпоративные данные во внутренние инструменты: дашборды, рабочие процессы и ИИ-приложения. Команды быстрее переходят от prompt к готовому продукту, а политики аутентификации и доступа остаются в привычной для них среде Fabric.

<div id="what-a-fabric-data-app-is">
  ## Что представляет собой приложение для работы с данными Fabric
</div>

Приложение для работы с данными Fabric — это статическое React-приложение, которое отображает диаграммы Power BI, выполняя запросы [Data Analysis Expressions (DAX)](https://learn.microsoft.com/en-us/dax/) к [семантической модели Power BI](https://learn.microsoft.com/en-us/power-bi/connect-data/service-datasets-understand). Его разработка имеет несколько особенностей:

* **Семантические модели Power BI служат источником данных.** Диаграммы строятся на основе DAX-запросов к подключённым семантическим моделям (наборам данных).
* **По умолчанию доступно только чтение.** Приложение читает данные с помощью DAX `EVALUATE`, но не записывает их обратно в Power BI. Если вам требуется изменяемое состояние, используйте отдельную базу данных приложения наряду с дашбордом.
* **Отрисовка выполняется через портал Fabric.** Уровень данных работает в портале Microsoft Fabric, который выполняет запросы к семантической модели и возвращает результаты в приложение. Ваши данные остаются в среде Fabric.
* **Размещается в инфраструктуре Microsoft.** Готовое приложение для работы с данными можно опубликовать на хостинге Microsoft, чтобы оно работало вместе с остальными компонентами среды Fabric.

<Note>
  Для приложений для работы с данными Microsoft Fabric требуется доступ к тенанту Microsoft Fabric с семантическими моделями Power BI, а в период предварительного просмотра — участие в утверждённой программе тестировщиков.
</Note>

За кулисами [Rayfin](https://github.com/microsoft/rayfin) — SDK и CLI с открытым исходным кодом для создания бэкендов приложений — позволяет Agent определять и публиковать готовые к эксплуатации приложения на основе данных Fabric.

Весь процесс выполняется в едином рабочем процессе: опишите приложение, поручите Agent создать его каркас, подключитесь к управляемым данным Fabric и опубликуйте приложение для запуска в тенанте Fabric вашей организации.

В этом руководстве рассматриваются процесс разработки, подключение приложения к данным Fabric, а также возможности для команд и автоматизации. Сведения о дашбордах данных на основе других хранилищ см. в разделе [Визуализация данных](/ru/features/artifact-types/data-apps).

<div id="use-cases">
  ## Сценарии использования
</div>

Для организаций, уже работающих в экосистеме данных Microsoft, это гораздо более быстрый способ создавать внутренние программные решения. Вместо того чтобы тратить недели на настройку аутентификации, API, инструментов развертывания и политик управления, команды описывают свои потребности, а Agent всё создаёт.

Распространённые сценарии использования:

* Инструменты повышения производительности для отдельных отделов
* Операционные дашборды
* Инструменты для анализа данных
* Приложения для автоматизации рабочих процессов
* Интерфейсы для формирования отчётов

Для корпоративных ИТ-служб управление, аутентификация и безопасность остаются в среде Fabric, которой уже управляет ваша организация, поэтому быстрое создание приложений не происходит в ущерб централизованному контролю.

<div id="build-a-fabric-data-app">
  ## Создание приложения для работы с данными Fabric
</div>

Процесс разработки проходит в формате диалога. Вы всё время работаете в Replit; при необходимости Microsoft выполняет аутентификацию и предоставляет доступ к данным.

<Steps>
  <Step title="Начните с шаблона Fabric">
    На главной странице Replit откройте раскрывающееся меню **Templates** и выберите **Microsoft Fabric App** в разделе **Org templates**. Agent перейдёт в режим создания приложения для работы с данными, а инструменты Fabric будут уже загружены.

    <Frame caption="Выбор организационного шаблона Microsoft Fabric App на главной странице Replit (интерфейс закрытого предварительного просмотра).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Главная страница Replit с открытым меню Templates, где Microsoft Fabric App выделен в разделе Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Опишите нужный дашборд">
    Введите prompt с описанием дашборда или инструмента отчётности, который хотите создать. Например: &quot;Создай дашборд роста продаж месяц к месяцу на основе нашей модели продаж Fabric&quot;. Вам не нужно писать DAX — Agent сгенерирует запросы.
  </Step>

  <Step title="Войдите через Microsoft">
    Когда появится запрос, войдите через Microsoft OAuth в тенанте, где хранятся ваши данные Fabric. Это позволит Agent читать семантические модели, к которым у вас есть доступ. Учётная запись, с которой вы входите, должна иметь доступ к нужному рабочему пространству Fabric.
  </Step>

  <Step title="Добавьте источники данных">
    Когда Agent попросит, укажите семантическую модель Power BI / Fabric, которую хотите использовать. Можно предоставить полный URL набора данных из портала Fabric (например, `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) либо ID рабочего пространства и ID набора данных или элемента. Agent использует эти данные, чтобы определить рабочее пространство и семантическую модель для запросов.

    Модель должна быть **опубликована в службе Power BI** — локальные файлы `.pbix` использовать нельзя.

    <Frame caption="Agent запрашивает ссылку на семантическую модель Power BI / Fabric (интерфейс закрытого предварительного просмотра).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Панель Agent просит разработчика предоставить семантическую модель Power BI или Fabric в виде полного URL портала Fabric либо ID рабочего пространства вместе с ID набора данных или элемента и сообщает, что локальные файлы .pbix нельзя использовать, так как модель должна быть опубликована в службе Power BI" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Позвольте Agent создать и доработать приложение">
    Agent изучит schema семантической модели, напишет DAX-запросы и соберёт дашборд с подходящими диаграммами. Просмотрите результат и запросите изменения на естественном языке: добавьте filter, измените тип диаграммы или добавьте ещё одну метрику.
  </Step>

  <Step title="Publish (необязательно)">
    Когда дашборд будет готов, вы можете опубликовать его на хостинге Microsoft, чтобы он работал в вашей среде Fabric. Публикация рассматривается отдельно; это руководство посвящено подключению к данным и созданию приложения.
  </Step>
</Steps>

<div id="connecting-to-fabric-data">
  ## Подключение к данным Fabric
</div>

Для чтения данных приложению требуется авторизованное подключение к Microsoft Fabric. Replit устанавливает его одним из двух способов.

<div id="app-level-fabric-sign-in-viewers">
  ### Вход в Fabric на уровне App (для зрителей)
</div>

Зрителям опубликованного приложения для работы с данными не нужно настраивать коннектор. Они проходят аутентификацию через встроенный в приложение механизм единого входа Microsoft Fabric, а приложение получает данные от их имени через портал Fabric. Благодаря этому доступ регулируется существующими разрешениями Fabric.

<div id="the-microsoft-fabric-connector-the-easy-path-for-builders">
  ### Коннектор Microsoft Fabric (простой вариант для разработчиков)
</div>

Для разработчиков **коннектор Microsoft Fabric** — удобный способ предоставить доступ к данным во время разработки. Он необязателен: это удобный вариант, а не требование.

* Первый разработчик, настроивший его, один раз проходит **OAuth** с Microsoft.
* Другие участники **того же проекта наследуют** это подключение.
* В **другом рабочем пространстве** необходимо включить коннектор и пройти собственную OAuth-авторизацию.
* Учётная запись, используемая для OAuth, должна иметь доступ к целевому рабочему пространству Fabric.

Коннектор использует Microsoft Entra OAuth и действует в рамках вашего тенанта. Управлять им можно на странице [Интеграции](/ru/features/integrations/overview) вашего проекта, как и любым другим коннектором Replit. Дополнительные сведения о коннекторах см. в разделе [Управление коннекторами](/ru/replitai/managing-connectors).

<Note>
  В период закрытой предварительной версии для коннектора Microsoft Fabric нет общих учётных данных, управляемых Replit. Разработчики проходят авторизацию в собственном тенанте Microsoft Entra.
</Note>

<div id="teams-and-automation">
  ## Teams и автоматизация
</div>

При совместной работе в команде или в неинтерактивных средах (например, CI) интерактивный OAuth не всегда удобен. В таких случаях вместо интерактивного входа укажите токен **субъекта-службы** в [Secrets](/ru/core-concepts/project-editor/app-setup/secrets) вашего project. App использует удостоверение субъекта-службы для чтения данных Fabric.

Это наиболее близкий аналог настройки «машина — машина»: не связанное с человеком удостоверение, созданное в Microsoft Entra и получившее доступ к рабочему пространству Fabric, аутентифицирует App без участия человека. Убедитесь, что субъект-служба имеет доступ к рабочим пространствам и семантическим моделям, к которым обращается App.

<div id="troubleshooting">
  ## Устранение неполадок
</div>

<AccordionGroup>
  <Accordion title="Данные не загружаются в Preview приложения">
    Уровень данных Fabric работает через портал Microsoft Fabric. Если диаграммы отображаются пустыми или данные не загружаются в Preview приложения, убедитесь, что вы вошли в Microsoft и что у этой учётной записи есть доступ к связанным вами рабочему пространству и семантической модели.
  </Accordion>

  <Accordion title="Agent не может найти вашу семантическую модель">
    Убедитесь, что вы вставили ссылку на набор данных Power BI с портала Fabric и что у вашей учётной записи (или субъекта-службы) есть как минимум доступ на чтение к этому рабочему пространству. Если Agent сообщает, что не может определить рабочее пространство или модель, повторно предоставьте ссылку на набор данных.
  </Accordion>

  <Accordion title="Коннектор зависает или постоянно предлагает подключиться">
    Повторно авторизуйте коннектор Microsoft Fabric на странице [интеграций](/ru/features/integrations/overview) проекта. Убедитесь, что учётная запись, авторизованная через OAuth, имеет доступ к рабочему пространству Fabric. Для командного использования или CI рекомендуется токен субъекта-службы, передаваемый через Secrets.
  </Accordion>
</AccordionGroup>
