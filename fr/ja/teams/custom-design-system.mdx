Un design system fournit à Agent les connaissances nécessaires pour créer des interfaces conformes à votre marque dans tout ce que votre organisation produit sur Replit : applications web, applications mobiles, présentations et autres artefacts. Une fois votre bibliothèque de composants, vos design tokens, vos ressources de marque et vos règles d&#39;utilisation configurés dans un monorepo pnpm Replit standard, Agent applique votre langage visuel dès la première requête.

<Note>
  Les design systems sont réservés au plan **Enterprise**. Seuls les administrateurs de l&#39;organisation peuvent les configurer et les gérer.
</Note>

<div id="section">
  ## Pourquoi configurer un système de design
</div>

Sans système de design, chaque créateur doit décrire manuellement à Agent la bibliothèque de composants, les jetons de couleur et les conventions de mise en page. Configurer un système de design résout ce problème :

* **Encoder les standards visuels** : Agent utilise les composants, couleurs et espacements exacts plutôt que des valeurs par défaut génériques
* **Garantir la cohérence** : toutes les applications suivent le même langage de design
* **Réduire le temps d&#39;intégration** : les nouveaux créateurs produisent immédiatement des résultats conformes à la marque
* **Capturer les connaissances implicites** : documenter pour Agent les décisions de design et les habitudes d&#39;utilisation des composants qui n&#39;existent que dans la tête de votre équipe

<div id="section-2">
  ## Ce dont vous avez besoin
</div>

* Votre bibliothèque de composants front-end sous forme de fichier tar ou d&#39;ensemble de fichiers tar
* Les polices et les icônes utilisées par votre design system
* La documentation IA de votre design system (MCP, compétences Agent)

<div id="section-3">
  ## Ce que vous pouvez configurer
</div>

La configuration du système de design se compose de trois éléments :

1. **Instructions personnalisées**. Le fichier `custom_instruction/instructions.md` fournit à Agent des règles générales applicables à tous les projets : la bibliothèque de composants à utiliser, les jetons de design auxquels se référer et les modèles à suivre. Agent a toujours ce fichier dans son contexte.

2. **Compétences**. Les compétences dans `.agents/skills/` fournissent des ressources de référence détaillées qu’Agent charge à la demande. Utilisez-les pour la documentation des API de composants, les guides de thématisation, les bibliothèques de modèles de mise en page et tout autre contenu de référence détaillé trop volumineux pour le fichier d’instructions principal.

3. **Ressources de design et de marque**. Placez les logos, icônes, polices et autres ressources de marque dans un dossier dédié (par exemple, `src/assets/brand/`). Configurez des alias de chemin Vite afin qu’Agent et le builder puissent y faire référence via des importations propres telles que `@brand/logo.svg`, plutôt que par des chemins relatifs fragiles. Cela garantit la cohérence des références aux ressources dans l’ensemble du projet.

<div id="section-4">
  ## Guide étape par étape
</div>

Ce guide explique comment configurer un système de design de bout en bout à l’aide d’une bibliothèque de composants existante empaquetée dans un fichier tar :

1. **Créez une application Replit** et importez le fichier tar.
2. **Demandez à Replit Agent d’installer le package et d’afficher tous les composants.** Agent configurera le projet et affichera la bibliothèque de composants.
3. **Vérifiez le résultat.** Assurez-vous que tous les composants s’affichent correctement et répondent à vos attentes. Une fois cette vérification effectuée, passez à la section [Créer la compétence du système de design](#creating-the-design-system-skill).

<div id="section-5">
  ### Création d&#39;une skill de design system
</div>

Une fois les composants prêts, la dernière étape consiste à créer une skill de design system afin qu&#39;Agent puisse s&#39;appuyer sur vos composants, vos tokens et vos modèles d&#39;utilisation dans l&#39;ensemble de vos projets.

Copiez l&#39;intégralité du prompt ci-dessous et collez-le dans Agent. Remplacez `<your-design-system-name>` par le nom de votre design system :

````
Crée la compétence de design system `<your-design-system-name>` à partir des composants et des paquets de ce projet.

Utilise la structure de fichiers présentée ci-dessous : `SKILL.md` à la racine, un répertoire `references/` pour les guides et la documentation des composants, et un répertoire `packages/` contenant toutes les dépendances nécessaires au fonctionnement.

Passe en revue tous les composants du projet et documente chacun d'eux dans un fichier distinct sous `references/components/`, en incluant les propriétés, les variantes et des exemples d'utilisation.

Formate `SKILL.md` comme un index contenant des liens vers les guides et les fichiers de référence des composants, avec une section « Conseils généraux » et une section « Composants », en suivant l'exemple ci-dessous.

Structure des fichiers :

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (fichiers Tar ou composants de code)

Le fichier `SKILL.md` sert d'index contenant des liens vers des fichiers Markdown distincts pour les guides et les références de composants. Chaque fichier lié traite un seul sujet en détail. Voici un exemple de `SKILL.md` généré :

```markdown
---
name: your-design-system
description: À utiliser lors de la création ou de la modification d'interfaces. Fournit la référence de l'API des composants du design system, des conseils de mise en page et les règles de style visuel.
---

# Your Design System

## Conseils généraux

- [Installation](references/guides/setup.md) — installation, configuration du projet et mise en place des providers
- [Garde-fous](references/guides/guardrails.md) — règles strictes à ne jamais enfreindre (modèles interdits, tokens obligatoires, exigences minimales d'accessibilité)
- [Mise en page et espacements](references/guides/layout-and-spacing.md) — système de grille, échelle d'espacement, points de rupture responsives, gabarits de page
- ...

## Composants

- [Index des composants](references/components/component-index.md) — liste complète des composants disponibles, avec leur statut et leur catégorie

Références des composants individuels (propriétés, variantes, exemples) :

- [Bouton](references/components/button.md)
- [Case à cocher](references/components/checkbox.md)
- ...
```

Chaque fichier de guide traite un seul sujet : les étapes de configuration et d'installation, les bonnes pratiques et les règles, des tableaux de référence des valeurs de tokens et de courts exemples de code illustrant le bon usage.

Chaque fichier de composant documente un seul composant : le nom du composant, une brève description, un tableau des propriétés, des exemples d'utilisation ainsi que les recommandations ou les contraintes. Plus ces fichiers sont complets, meilleurs seront les résultats produits par Agent.
````

<div id="agentxx">
  ### Connecter la compétence à Agent
</div>

Une fois la compétence créée, vérifiez que `custom_instruction/instructions.md` oriente bien Agent vers celle-ci :

```markdown theme={null}
# Design system

Chargez la compétence design system située dans `.agents/skills/your-design-system/` et respectez-la.
Appliquez systématiquement le design system lors de la création ou de la modification de l'interface.
```

Enfin, préconfigurez dans `replit.md` le contexte propre à votre système de design afin qu&#39;Agent comprenne vos standards visuels dès le départ. Incluez la présentation du projet, la bibliothèque de composants privilégiée, les principales préférences de design (échelle d&#39;espacement, exigences d&#39;accessibilité) ainsi que la pile architecturale.

<div id="section-6">
  ### Validation de la configuration
</div>

Avant de déployer votre système de design, vérifiez les points indispensables suivants :

* `custom_instruction/instructions.md` oriente Agent vers la compétence du système de design
* `.agents/skills/` contient les compétences, avec les références de composants, les guides et les paquets
* `replit.md` est préconfiguré avec la présentation du projet, les préférences et l&#39;architecture
* Le fichier de tokens de design est inclus (`tokens.css` ou équivalent)
* Les paquets du système de design sont préinstallés dans `package.json`
* Créez une application de test pour vérifier qu&#39;Agent utilise correctement le système de design

<div id="section-7">
  ### Épingler un système de design à votre organisation
</div>

Une fois votre système de design prêt, épinglez-le pour que tous les membres de l’organisation puissent l’utiliser :

1. Accédez à l’application de système de design de votre organisation
2. Ouvrez le menu d’actions de l’application (menu à trois points)
3. Sélectionnez **Épingler au champ de saisie de l’Agent**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Menu d’actions de l’application affichant l’option Épingler au champ de saisie de l’Agent" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Seuls les administrateurs de l’organisation (membres ayant le rôle `system_admins`) peuvent épingler et désépingler des systèmes de design.
</Note>

Définissez l’accès des membres sur **lecture seule** afin qu’ils puissent consulter et utiliser le système de design épinglé sans pouvoir le modifier.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Boîte de dialogue d’invitation avec l’accès des membres défini sur lecture seule" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Le système de design apparaît sous forme de pastille sélectionnable sous le champ de saisie de l’Agent pour tous les membres de l’organisation. Pour le retirer, ouvrez le même menu et sélectionnez **Désépingler du champ de saisie de l’Agent**.

<div id="section-8">
  ## Maintenir votre design system dans la durée
</div>

Un design system évolue. Gardez-le toujours à jour :

* **Mettez à jour les fichiers de tokens** dès que votre design system publie de nouvelles valeurs de couleurs, d&#39;espacement ou de typographie
* **Mettez à jour les skills** lorsque de nouvelles propriétés, variantes ou pratiques d&#39;utilisation sont ajoutées aux composants
* **Mettez à jour les instructions** lorsque les principes ou les standards de design changent
* **Mettez à jour la version des paquets** à chaque nouvelle version de votre design system
* **Testez régulièrement** en créant de nouvelles applications et en vérifiant qu&#39;Agent génère bien les résultats attendus

<div id="section-9">
  ## Comparaison entre les systèmes de design et les templates personnalisés
</div>

Les systèmes de design et les [templates personnalisés](/fr/ja/teams/custom-templates) répondent à des besoins différents :

|                      | Système de design                                                                                     | Templates personnalisés                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Objectif**         | Adapter la stack front-end à celle de votre équipe et utiliser des composants de code                 | Remplacer entièrement la stack par défaut (par exemple : Rust, Go, C++)                                   |
| **Stack**            | Fonctionne dans le monorepo pnpm standard de Replit                                                   | Définit une structure de projet entièrement personnalisée                                                 |
| **Fournit**          | Règles de bibliothèque de composants, jetons de design, ressources de marque et compétences visuelles | Base complète : environnement d&#39;exécution, configuration de build, dépendances et structure du projet |
| **S&#39;applique à** | Applications web, applications mobiles, diapositives, artefacts — tout ce qu&#39;Agent crée           | Uniquement les applications créées à partir de ce template spécifique                                     |

Utilisez un système de design si vous souhaitez qu&#39;Agent crée des projets respectant vos standards visuels dans toute l&#39;expérience Replit. Utilisez des templates personnalisés si vous avez besoin d&#39;une stack fondamentalement différente.
