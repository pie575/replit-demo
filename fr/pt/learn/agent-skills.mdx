Les compétences enseignent de nouvelles capacités à Agent. Elles vous permettent de partager votre expérience, vos modèles préférés et vos connaissances spécialisées avec Agent afin qu&#39;il produise de meilleurs résultats, plus cohérents.

<div id="por-que-skills-so-importantes">
  ## Pourquoi les compétences sont importantes
</div>

Chaque fois que vous créez avec Agent, vous produisez un contexte utile : solutions à des problèmes, décisions de design, préférences de framework. Mais ce contexte disparaît une fois la conversation terminée. Les compétences le préservent.

Une compétence d&#39;animation GSAP apprend à Agent à utiliser correctement une bibliothèque précise. Une compétence de système de design garantit qu&#39;il applique vos couleurs et vos règles d&#39;espacement exactes. Une compétence de correction de bugs consigne une solution pour qu&#39;Agent ne répète pas la même erreur. Des tâches autrefois irrégulières deviennent fiables.

Les compétences reposent également sur un [standard ouvert](https://agentskills.io/specification). Elles fonctionnent avec n&#39;importe quel agent, y compris Replit Agent, ce qui vous permet de les emporter d&#39;un outil à l&#39;autre.

<div id="skills-proativas-vs-reativas">
  ## Compétences proactives ou réactives
</div>

Un cadre de réflexion pour déterminer quand et comment créer des compétences. Comprendre ces deux approches vous permet d’être plus efficace.

<div id="skills-proativas">
  ### Compétences proactives
</div>

Les compétences proactives sont celles que vous ajoutez *avant* de commencer à construire. Renseignez-vous sur les bibliothèques ou les patterns que vous souhaitez utiliser, trouvez ou créez les compétences correspondantes, puis lancez-vous dans vos prompts.

**Exemple :** avant de créer un site portfolio avec des animations SVG dessinées à la main, explorez les bibliothèques d&#39;animation et découvrez GSAP. Installez une compétence GSAP React, puis demandez à Agent de construire les animations via un prompt. Agent dispose ainsi dès le départ des connaissances spécialisées nécessaires : il comprend l&#39;API de la bibliothèque, les bonnes pratiques et les patterns courants. Sans cette compétence, il risque de produire quelque chose de générique ou d&#39;incorrect.

Cette approche fonctionne bien lorsque :

* Vous utilisez une bibliothèque populaire dont les patterns sont subtils et qu&#39;Agent risque de ne pas maîtriser seul
* Vous souhaitez des choix de design cohérents dans tout le projet (typographie, espacement, style d&#39;animation)
* Vous démarrez un projet et connaissez déjà la direction technique

<div id="skills-reativas">
  ### Compétences réactives
</div>

Les compétences réactives sont celles que vous créez *après* avoir résolu un problème. Vous rencontrez un problème, vous le déboguez avec Agent, vous le corrigez, puis vous consignez la solution pour qu&#39;il ne se reproduise pas.

**Exemple :** en concevant un Canvas pour une application mobile, vous remarquez des bords irréguliers sur les images, qui s&#39;aggravent au zoom. Le débogage avec Agent révèle qu&#39;il s&#39;agit d&#39;un crénelage de minification — un problème de rendu où, de façon contre-intuitive, les images se dégradent à mesure qu&#39;elles rétrécissent. Après avoir mis en place un correctif, demandez à Agent de créer une compétence :

<AiPrompt>
  Create a skill that captures what we just learned about fixing minification aliasing. Include the root cause, the solution, and when this issue typically occurs so you can prevent it in the future.
</AiPrompt>

Agent s&#39;appuie sur l&#39;historique de la conversation pour rédiger une compétence propre au projet. La prochaine fois que le problème surviendra, vous pourrez orienter Agent vers cette compétence au lieu de tout déboguer de zéro.

Ce schéma fonctionne bien lorsque :

* Vous avez corrigé un bug peu évident et souhaitez éviter qu&#39;il ne se reproduise
* Vous avez appris quelque chose sur l&#39;architecture de votre app pendant une session de débogage
* Vous voulez codifier une solution dont la découverte a demandé un effort considérable

<div id="sendo-seletivo-com-skills">
  ## Être sélectif avec les compétences
</div>

Voyez les compétences comme les indications que vous donneriez à un ami pour trouver votre appartement. Une liste d&#39;indications ciblées, ça fonctionne. Un classeur rempli de documentation, non — personne n&#39;a le temps de le lire, et les détails importants s&#39;y perdent.

Il en va de même pour Agent. Si vous ajoutez trop de compétences, Agent risque de s&#39;y perdre. Choisissez délibérément les compétences que vous activez pour un projet donné et supprimez celles dont vous n&#39;avez plus besoin.

<Note>
  Les compétences donnent les meilleurs résultats lorsqu&#39;elles décrivent des schémas précis et reproductibles plutôt que des conseils généraux. Concentrez-vous sur des flux de travail concrets, des conventions établies et des solutions éprouvées.
</Note>

<div id="criando-skills-de-qualidade">
  ## Créer des compétences de qualité
</div>

Les compétences peuvent être complexes et alambiquées. Quelques principes permettent de les garder efficaces :

* **Décrivez le chemin idéal.** Expliquez à Agent comment bien faire les choses. Si vous vous surprenez à énumérer ce qu&#39;il ne faut *pas* faire, c&#39;est généralement le signe qu&#39;il faut repenser toute l&#39;approche.
* **Utilisez des scripts dès que possible.** Un script déterministe évite à Agent d&#39;avoir à raisonner et se révèle plus fiable que de lui demander de refaire les mêmes étapes à chaque fois.
* **Renvoyez vers d&#39;autres fichiers.** Structurez une compétence de manière à ce qu&#39;elle pointe vers d&#39;autres fichiers Markdown : Agent ne charge alors que ceux nécessaires à la tâche en cours.
* **Faites des tests comparatifs régulièrement.** C&#39;est ainsi que vous confirmez qu&#39;une compétence fonctionne vraiment, au lieu de le supposer.
* **Écrivez-les vous-même.** L&#39;objectif est d&#39;obtenir un contexte concis et réfléchi, et cela passe par la rédaction manuelle des compétences plutôt que par une génération en masse. Agent peut vous aider à en ébaucher une, mais affinez-la vous-même pour que chaque ligne justifie sa place.
* **Restez spécifique.** Ne créez pas de compétences génériques pour le nettoyage du code ou la sécurité : elles sont déjà intégrées à Agent. Vos compétences doivent refléter ce qui vous est propre, à vous ou à votre organisation.

La plupart des compétences échouent de manière identifiable :

* **Une compétence se déclenche alors qu&#39;elle ne devrait pas.** La description est trop large. Restreignez-la et précisez quand ne *pas* l&#39;utiliser — « pas pour les articles de blog ni la documentation d&#39;aide » est souvent plus utile que n&#39;importe quelle instruction positive.
* **Une compétence se déclenche, mais le résultat est erroné.** Les instructions sont trop générales. Remplacez les consignes vagues comme « rendez cela professionnel » par des règles précises : noms exacts, exigences concrètes, éléments explicites à éviter.
* **Deux compétences entrent en conflit.** Corrigez les descriptions pour que les deux ne se déclenchent pas sur la même tâche. Les conflits relèvent presque toujours d&#39;un problème de périmètre, pas d&#39;instructions.

Les compétences se périment : traitez-les comme une documentation que vous entretenez réellement.

<div id="levando-skills-para-todo-o-workspace">
  ## Étendre les compétences à tout le workspace
</div>

Tout ce qui précède s&#39;applique aux compétences d&#39;un seul projet. Au sein d&#39;une équipe, vous pouvez aussi personnaliser l&#39;Agent pour l&#39;ensemble de votre workspace, afin que chacun parte des mêmes conventions sans avoir à les réexpliquer dans chaque projet. La personnalisation du workspace comporte deux volets :

* **Instructions personnalisées** — des règles toujours actives, injectées dans le contexte de l&#39;Agent dans chaque projet et à chaque message, avant même que quiconque saisisse un prompt. Réservez-les aux quelques règles véritablement universelles, du type « ne jamais stocker d&#39;identifiants en texte clair ». Comme elles sont chargées à chaque turn, chaque mot consomme une part du budget de contexte de l&#39;Agent — restez concis.
* **Compétences de workspace** — les mêmes compétences que celles décrites ci-dessus, mises à la disposition de tous les membres du workspace et gérées de façon centralisée. Elles ne coûtent pratiquement rien tant qu&#39;une tâche pertinente ne les invoque pas : vous pouvez donc en proposer beaucoup sans dégrader la sortie.

Une façon simple de décider quoi placer où : si une règle doit s&#39;appliquer quel que soit ce que l&#39;on construit, c&#39;est une instruction personnalisée ; si elle ne concerne qu&#39;un certain type de tâche, c&#39;est une compétence.

Pour savoir comment configurer les instructions personnalisées et les compétences de workspace, et qui peut les gérer, consultez [Personnalisation de l&#39;Agent](/fr/pt/features/agent/agent-customization).

<div id="consideraes-de-segurana">
  ## Considérations de sécurité
</div>

Les compétences du panneau Compétences de Replit font l&#39;objet d&#39;un audit de sécurité. Mais une compétence peut être installée depuis n&#39;importe où : elles proviennent d&#39;un [dépôt open source](https://github.com/vercel-labs/skills) auquel tout le monde peut contribuer.

Comme les compétences sont des instructions que l&#39;Agent suit, une compétence malveillante pourrait lui demander d&#39;exfiltrer des données sensibles de votre projet. Avant d&#39;installer une compétence provenant d&#39;une source externe :

1. **Ouvrez le fichier.** Les compétences ne sont que du Markdown. Lisez leur contenu dans `/.agents/skills/` avant de les utiliser.
2. **Vérifiez la source.** Assurez-vous que la compétence provient d&#39;un dépôt ou d&#39;un auteur de confiance.
3. **Examinez ses instructions.** Vérifiez que la compétence ne fait pas référence à des URL externes suspectes et ne demande pas d&#39;informations sensibles.

<Warning>
  Examinez toujours les compétences provenant de sources externes avant de les installer. Celles du panneau Compétences de Replit ont été auditées, contrairement à celles installées via la CLI ou copiées sur Internet.
</Warning>

<div id="skills-vs-servidores-mcp">
  ## Compétences et serveurs MCP
</div>

Les compétences et les serveurs MCP sont les deux principaux moyens d&#39;étendre les agents, et ils répondent à des besoins différents.

Les **compétences** sont économes en contexte : seule une brève description est chargée tant que la compétence n&#39;est pas invoquée. Utilisez les compétences pour :

* Les flux de travail et les conventions (« comment déployer », « liste de contrôle pour la revue de code »)
* Les documents de référence (schémas d&#39;API, guides de style, systèmes de design)
* Les prompts réutilisables et les connaissances spécialisées (bibliothèques d&#39;animation, modèles de framework)

Les **serveurs MCP** sont gourmands en contexte. Toutes les descriptions d&#39;outils sont chargées d&#39;emblée, ce qui peut dégrader la qualité du résultat si vous en ajoutez trop. Utilisez les serveurs MCP pour :

* Vous connecter à des services externes (Notion, Linear, Figma)
* Les actions qui nécessitent un accès à une API
* Les outils qui *font* des choses, et non qui se contentent d&#39;instruire

La distinction essentielle : les compétences définissent *comment* votre agent doit fonctionner, tandis que les serveurs MCP définissent *ce à quoi* il peut accéder. Les deux fonctionnent avec les agents de codage comme Replit Agent comme avec les agents que vous créez vous-même.
