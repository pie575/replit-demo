Ashby 已经筛选入站候选人。此工作流用于外联：
读取 Drive 中的职位描述，在 GitHub 上寻找匹配的工程师，跳过已在 Ashby 中
的人员，并起草待发送的外联内容。Agent 会将
新人员标记为已寻源，并附上简短的匹配理由和候选人外联草稿。您
审核后发送。请勿仅凭这些内容做出招聘决定。

<div id="section">
  ## 适合以下情况
</div>

* 入站候选人数量不足、需要寻源名单的技术招聘人员。
* 希望找到与 GitHub 匹配的工程师，又不想整天搜索的招聘经理。

  ## 开始前
</div>

准备一份明确区分必备条件和优先条件的职位描述。连接 Drive、GitHub 和 Ashby。
说明地区、资历级别和所需招聘人数。不要仅依据这些信息做出招聘
决定。

<div id="agent">
  ## 向 Agent 提出请求
</div>

<AiPrompt>
  请创建一个每周一上午 9 点运行的例程。根据这份职位描述 [Drive
  链接或粘贴内容]，在 GitHub 上寻找 30 名符合必备条件的工程师。跳过已在 Ashby 中的人员。为每个人撰写 3 行适配理由和一份简短的外联草稿。请勿发送任何内容。将新人员以“已寻源”状态添加到 Ashby，并在候选人资料中附上备注和草稿。
</AiPrompt>

<div id="section-4">
  ## 预期结果
</div>

Agent 会阅读职位描述、搜索 GitHub，并跳过已在 Ashby 中的候选人，
然后返回一份包含草稿的候选人短名单。您可以审核后发送。
首次结果可能包含较多噪声。请核查后调整必备条件。
从列表中打开三个 GitHub 个人资料，确认其是否符合必备条件，并在
发送任何内容之前确认这些人尚未在 Ashby 中。

  排除看起来像现有客户或竞争对手员工的人员。

<div id="section-6">
  ## 故障排查
</div>

* **候选人短名单中噪声过多：** 查看初步结果后，调整必备条件和优先条件。要求候选人近期有使用特定语言或特定类型仓库的提交记录，并排除看似为现有客户或竞争对手员工的人员。
* **已存在于 Ashby 中的人员反复出现：** 确认 Ashby 已连接到正确的工作区，并确认 Agent 除显示名称外，还会通过电子邮件或 GitHub 用户名进行匹配。
* **外联消息已发出：** 此工作流应仅创建草稿。如果已发出任何内容，请停止该例程，并告知 Agent 绝不要向候选人发送电子邮件或消息。
