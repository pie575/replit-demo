Le type de deployment désigne la technologie utilisée par Replit pour publier votre app. Vous le choisissez dans l&#39;outil Publishing, sous **Adjust settings**, dans la liste déroulante **Deployment type**. **Autoscale** est l&#39;option par défaut et recommandée : la plupart des créateurs n&#39;ont jamais besoin d&#39;en changer.

<div id="compare-deployment-types">
  ## Comparer les types de deployment
</div>

| Type            | Idéal pour                                                    | Fonctionnement                                                                       | Facturation                                              |
| :-------------- | :------------------------------------------------------------ | :----------------------------------------------------------------------------------- | :------------------------------------------------------- |
| **Autoscale**   | Web apps et API au trafic variable                            | Ajoute des serveurs en cas de forte charge, se réduit à zéro en cas d&#39;inactivité | Vous payez pendant le traitement des requêtes            |
| **Static**      | Pages d&#39;accueil, portfolios, sites de documentation       | Sert des fichiers depuis un serveur cloud mis en cache, sans backend                 | Vous payez uniquement les données servies par votre site |
| **Reserved VM** | Bots, tâches en arrière-plan, API toujours actives            | Un serveur dédié unique qui ne se met jamais en veille                               | Coût mensuel fixe                                        |
| **Scheduled**   | Tâches périodiques comme les sauvegardes et les notifications | Exécute une commande selon une planification, puis s&#39;arrête                      | Vous payez la durée de chaque exécution                  |

<div id="autoscale">
  ## Autoscale
</div>

Les déploiements Autoscale s&#39;exécutent sur des serveurs qui évoluent à la hausse comme à la baisse selon le trafic de votre application. Lorsque votre application est très sollicitée, Replit ajoute des serveurs pour absorber la charge. Lorsqu&#39;elle est inactive, leur nombre peut descendre jusqu&#39;à zéro : vous ne payez donc pas les périodes creuses.

Idéal pour :

* Les applications web au trafic variable, comme les sites de commerce en ligne
* Les API et les services

La configuration se trouve dans **Adjust settings** : [la puissance des machines et le nombre maximal de serveurs](/fr/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Les déploiements Static hébergent les fichiers de votre app, tels que HTML, CSS et JavaScript, sur un serveur cloud qui utilise la mise en cache pour diffuser le contenu rapidement et à moindre coût. Il n&#39;y a pas de serveur backend.

Idéal pour :

* Les pages de destination marketing
* Les sites portfolio
* Les sites de documentation produit et API

<Note>
  Les déploiements Static ne sont pas compatibles avec les Replit Apps créées avec Agent. Agent crée des apps full-stack qui nécessitent un serveur backend : privilégiez donc Autoscale ou Reserved VM dans ce cas.
</Note>

La configuration comprend le répertoire public à servir et une commande de build facultative. Pour les en-têtes de réponse, les réécritures d&#39;URL et les redirections, consultez la [configuration Static avancée](/fr/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Les déploiements Reserved VM exécutent votre app sur une machine virtuelle dédiée qui ne se met jamais en veille. Vous bénéficiez de performances constantes et d&#39;un coût mensuel fixe et prévisible.

Idéal pour :

* Les tâches en arrière-plan gourmandes en mémoire
* Les chatbots qui doivent rester connectés en permanence
* Les serveurs API toujours actifs

La configuration comprend la [puissance de la machine](/fr/features/publishing/machine-configuration), les commandes de build et d&#39;exécution, les mappages de ports, ainsi que le choix entre exécuter l&#39;app comme serveur web ou comme processus d&#39;arrière-plan.

<div id="scheduled">
  ## Scheduled
</div>

Les déploiements planifiés exécutent une commande selon une planification dans l&#39;environnement de votre app, puis s&#39;arrêtent jusqu&#39;à l&#39;exécution suivante. Décrivez la planification en langage naturel, par exemple « chaque jour de semaine à 9 h », et Replit la convertit automatiquement en planification. Vous recevez une alerte en cas d&#39;échec d&#39;une exécution.

Idéal pour :

* Les vérifications d&#39;état et les rapports de santé
* L&#39;envoi de notifications
* Le lancement de sauvegardes

La configuration comprend la planification, un délai d&#39;expiration de la tâche, ainsi que les commandes de build et d&#39;exécution. Les déploiements planifiés ne diffusent aucune page web : ils n&#39;ont donc pas d&#39;URL publique.
