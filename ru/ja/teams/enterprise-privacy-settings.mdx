Как администратор Enterprise, вы можете настроить общие для организации параметры, определяющие, как участники команды взаимодействуют с кодом, деплоями и внешними платформами. Эти настройки помогают поддерживать стандарты безопасности, защищать интеллектуальную собственность и обеспечивать соответствие политикам Enterprise.

<div id="section">
  ## Доступ к настройкам конфиденциальности
</div>

<Accordion title="Как открыть настройки конфиденциальности">
  1. Перейдите в рабочее пространство Enterprise
  2. Выберите **Настройки**
  3. Выберите **Дополнительно**, чтобы увидеть все доступные настройки
</Accordion>

<div id="section-2">
  ## Настройки конфиденциальности
</div>

Настройки конфиденциальности определяют, как приложения публикуются и кто может получать к ним доступ в вашей организации.

<CardGroup cols={2}>
  <Card title="Приватные деплои" icon="lock">
    Требуйте, чтобы все новые приложения публиковались как приватные, и ограничивайте доступ только прошедшими аутентификацию участниками команды
  </Card>

  <Card title="Деплои, защищённые паролем" icon="key">
    Разрешите участникам команды добавлять парольную защиту к опубликованным приложениям
  </Card>

  <Card title="Приватные URL-адреса для разработки" icon="shield-halved">
    Требуйте аутентификацию для всех URL-адресов разработки приложений, включая SSO для организаций с включённым SAML
  </Card>
</CardGroup>

<div id="section-3">
  ### Приватные деплои
</div>

При включении этой настройки все новые приложения должны публиковаться как приватные. Доступ к приватным приложениям имеют только аутентифицированные участники вашей организации.

**Используйте эту настройку, если:**

* ваша организация работает с конфиденциальными данными или проприетарными приложениями;
* необходимо предотвратить случайную публикацию приложений;
* требования соответствия обязывают ограничивать доступ к опубликованным приложениям.

<Note>
  Эта настройка применяется только к вновь опубликованным приложениям. Существующие опубликованные приложения сохранят текущие настройки публикации.
</Note>

<div id="section-4">
  ### Деплои, защищённые паролем
</div>

Определяет, могут ли участники команды создавать деплои, защищённые паролем. При включении этой настройки разработчики смогут добавить дополнительный уровень защиты, требуя пароль для доступа к опубликованным приложениям.

**Используйте эту настройку, если:**

* Вы хотите поделиться приложением с внешними пользователями, не делая его полностью общедоступным
* Вашей команде нужно продемонстрировать приложение клиентам перед более масштабным релизом
* Вам нужен детальный контроль доступа, выходящий за рамки членства в организации

<div id="url">
  ### Требовать аутентификацию для приватных URL-адресов разработки
</div>

При включении этого параметра аутентификация потребуется для всех URL-адресов приложений в разработке. Если в организации включён SAML, для доступа к URL-адресам разработки потребуется SSO-аутентификация.

**Используйте этот параметр, если:**

* необходимо предотвратить несанкционированный доступ к приложениям в разработке
* политики безопасности требуют защиты всех сред разработки
* вы хотите, чтобы просматривать предварительные версии в разработке могли только аутентифицированные участники команды

<Warning>
  Этот параметр применяется ко всем существующим приложениям в организации, включая уже созданные.
</Warning>

<div id="section-5">
  ### Запрет экспорта исходного кода
</div>

При включении этой настройки участники команды не смогут экспортировать исходный код приложения в виде ZIP-файла. Это предотвращает скачивание и передачу кода за пределами платформы Replit.

**Используйте эту настройку, если:**

* необходимо строго контролировать, где хранится исходный код
* политики безопасности запрещают хранить локальные копии кода
* вы хотите, чтобы вся разработка велась в контролируемой среде

<div id="section-6">
  ## Настройки безопасности
</div>

Настройки безопасности помогают проводить сканирование уязвимостей и применять другие меры защиты.

<div id="section-7">
  ### Требование сканирования безопасности
</div>

Укажите, должны ли все приложения проходить сканирование безопасности перед публикацией. Сканирование безопасности выявляет уязвимости в коде, раскрытые секреты и другие проблемы безопасности.

Доступные варианты:

| Настройка       | Описание                                                                 |
| --------------- | ------------------------------------------------------------------------ |
| **Выкл.**       | Сканирование безопасности необязательно                                  |
| **Обязательно** | Все приложения должны пройти сканирование безопасности перед публикацией |

**Когда использовать эту настройку:**

* Если необходимо соблюдать требования безопасности
* Если вы хотите предотвратить случайное раскрытие API-ключей или секретов
* Если необходимо обеспечить единые стандарты безопасности для всех опубликованных приложений

<Note>
  Эта настройка не применяется к приложениям, опубликованным до её включения.
</Note>

<div id="section-8">
  ## Настройки управления исходным кодом
</div>

Настройки управления исходным кодом помогают обеспечивать соблюдение практик контроля версий и защищать репозитории кода вашей организации.

<div id="git">
  ### Требование Git-репозитория
</div>

Если этот параметр включён, перед публикацией все приложения должны отправлять локальные изменения в удалённый Git-репозиторий. Это гарантирует отслеживание всех изменений кода в системе контроля версий организации.

**Используйте этот параметр, если:**

* весь код необходимо сохранять в Git
* вам нужен журнал аудита всех изменений кода
* ваш рабочий процесс требует проверки кода перед публикацией

<Note>
  Этот параметр не применяется к приложениям, опубликованным до его включения.
</Note>

<div id="section-9">
  ### Приватные удалённые репозитории
</div>

Определяет, могут ли участники команды использовать публичные Git-репозитории. Если включить требование использовать приватные удалённые репозитории, участники команды смогут отправлять изменения только в приватные репозитории на таких платформах, как GitHub.

Доступные параметры:

| Настройка                           | Описание                                                                                  |
| ----------------------------------- | ----------------------------------------------------------------------------------------- |
| **Выкл.**                           | Участники команды могут использовать публичные или приватные репозитории                  |
| **Требовать для неадминистраторов** | Участники команды без прав администратора должны использовать приватные репозитории       |
| **Требовать для всех**              | Все участники команды, включая администраторов, должны использовать приватные репозитории |

**Используйте эту настройку в следующих случаях:**

* Использование публичных репозиториев кода запрещено
* Нужно предотвратить случайную отправку проприетарного кода в публичные репозитории
* Требования соответствия обязывают использовать приватный контроль версий
