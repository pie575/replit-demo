<div id="replitmd">
  ## Как работает `replit.md`
</div>

Сначала Agent создаёт в корневом каталоге проекта файл `replit.md`, опираясь на лучшие практики. Этот файл содержит:

* базовую информацию о проекте
* рекомендуемые паттерны написания кода
* типовые настройки, подобранные под тип проекта

<YouTubeEmbed videoId="kYv525W-vaU" title="Как настроить ответы Replit Agent" />

При обработке запросов Agent автоматически считывает файл `replit.md` и использует его содержимое, чтобы:

* понимать архитектуру и соглашения проекта
* следовать предпочитаемым паттернам и стилю написания кода
* использовать указанный менеджер пакетов и зависимости

По мере того как Agent узнаёт больше о проекте и вносит изменения в приложение, он может обновлять файл `replit.md`.

<Note>
  Вы можете отредактировать файл `replit.md`, чтобы настроить поведение Agent.
</Note>

<div id="replitmd-2">
  ## Настройка `replit.md`
</div>

<div id="section">
  ### Автоматическая генерация
</div>

При создании нового проекта в Agent файл `replit.md` создаётся автоматически с учётом лучших практик. Этот файл появляется в корневом каталоге проекта и содержит:

* базовую информацию о проекте
* рекомендуемые паттерны написания кода
* типовые настройки, подобранные под тип проекта

<div id="section-2">
  ### Создание вручную
</div>

Вы можете создать собственный файл `replit.md`, добавив в корневой каталог проекта новый файл с именем `replit.md`. Agent автоматически обнаружит его и будет использовать в дальнейших диалогах.

<Note>
  Чтобы файл `replit.md` работал корректно, он должен находиться в корневом каталоге проекта.
</Note>

<div id="replitmd-3">
  ### Повторное создание `replit.md`
</div>

Если файл `replit.md` повреждён или вы хотите начать с нуля:

1. Удалите существующий файл `replit.md` из корня проекта
2. Начните новый диалог с Agent
3. Agent автоматически создаст новый файл `replit.md` на основе текущего проекта

<div id="section-3">
  ## Рекомендуемые практики
</div>

<div id="section-4">
  ### Формулируйте конкретно и однозначно
</div>

Пишите ясные и конкретные инструкции, чтобы Agent точно понимал, чего вы хотите:

```markdown theme={null}
## Стиль кода

- Используйте TypeScript для всех новых файлов JavaScript
- Отдавайте предпочтение функциональным компонентам с хуками, а не классовым
- Используйте Tailwind CSS для стилизации, избегайте инлайновых стилей
- Всегда указывайте типы TypeScript для параметров функций и возвращаемых значений
```

Подробное руководство по оформлению промптов см. в [руководстве Anthropic по промпт-инжинирингу](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags).

<div id="section-5">
  ### Используйте примеры
</div>

Примеры помогают Agent понять ваши предпочтения лучше, чем абстрактные описания:

````markdown theme={null}
## API Error Handling

When creating API endpoints, always use this error handling pattern:

```javascript
app.get("/api/users", async (req, res) => {
  try {
    const users = await getUsersFromDatabase();
    res.json({ success: true, data: users });
  } catch (error) {
    console.error("Error fetching users:", error);
    res.status(500).json({
      success: false,
      error: "Failed to fetch users",
    });
  }
});
```
````

<div id="replitmd-5">
  ## Сочетание веб-поиска и `replit.md`
</div>

Agent может выполнять веб-поиск, чтобы находить актуальную информацию, библиотеки и решения. В сочетании с файлом `replit.md` это даёт вам и свежие знания, и рекомендации, учитывающие специфику вашего проекта.

<div id="section-13">
  ### Рекомендации по интеграции веб-поиска
</div>

**Чётко указывайте, что именно должен изучить Agent:**

```markdown theme={null}
## Предпочтения по исследованию
- Всегда проверяй наличие последних версий зависимостей, прежде чем предлагать обновления
- Изучай актуальные лучшие практики реализации мер безопасности
- Ищи современные методы оптимизации производительности для нашего стека технологий
```

**Подскажите Agent, как использовать внешние знания:**

```markdown theme={null}
## Правила работы с внешними источниками
- Предлагая новые библиотеки, проверяй их совместимость с нашим текущим стеком
- Адаптируй внешние примеры под наши стандарты кода и структуру проекта  
- Убедись, что предложенные решения работают в нашей среде публикации
```

**Пример запроса, задействующего оба подхода:**
«Изучи새 новейшие техники оптимизации производительности React 18 и реализуй их, следуя шаблонам компонентов, описанным в `replit.md`»

Такой подход даёт актуальные решения, адаптированные под конкретные потребности вашего проекта.

<div id="section-14">
  ## Ограничения
</div>

<div id="section-15">
  ### Ограничения по размеру файла и содержимому
</div>

Для `replit.md` нет строгого ограничения на количество символов, но очень большие файлы могут обрабатываться не полностью. Для наилучшего результата сохраняйте `replit.md` кратким и сфокусированным на главном.

<div id="section-16">
  ### Требования к корневому каталогу
</div>

Файл `replit.md` должен находиться в корневом каталоге проекта. Agent не находит автоматически файлы, расположенные в подкаталогах.

<div id="section-17">
  ### Область действия контекста
</div>

Файл `replit.md` предоставляет контекст для диалогов с Agent, но не применяется автоматически к другим ИИ-инструментам.

<div id="section-18">
  ## Дальнейшие шаги
</div>

Готовы настроить Agent под свой проект?

1. **Начните с простого**: создайте базовый `replit.md` с ключевыми предпочтениями
2. **Улучшайте постепенно**: обновляйте `replit.md` по ходу работы с Agent
3. **Делитесь наработками**: применяйте удачные настройки `replit.md` в похожих проектах
4. **Следите за результатом**: обращайте внимание на то, насколько точно Agent следует указаниям, и корректируйте их при необходимости

Узнайте больше о [работе с Agent](/ru/ja/features/agent/overview) или познакомьтесь с другими [ИИ-инструментами](/ru/ja/build/welcome).

**Enterprise**: заранее пропишите `replit.md` в [пользовательских шаблонах](/ru/ja/teams/custom-templates), чтобы все разработчики в организации получали единый стартовый контекст. Рекомендации по дизайну см. в разделе [Настройка дизайн-системы](/ru/ja/teams/custom-design-system).
