---
title: "Configurer OAuth pour X (Twitter)"
description: "Configurez X (anciennement Twitter) comme fournisseur de connexion sociale pour l’authentification de votre app"
---

Ce guide explique comment créer une app OAuth pour X dans le portail des développeurs de X. Vous récupérerez un **Client ID** et un **Client Secret** à saisir dans le **panneau Auth**.

<Note>
  Cette page couvre uniquement la configuration côté fournisseur dans le portail des développeurs de X. Pour connaître le flux général de Clerk Auth — notamment l’activation de X et la saisie des identifiants dans le **panneau Auth** — consultez [Configuration des identifiants OAuth pour un fournisseur SSO](/fr/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) dans la documentation de Clerk Auth.
</Note>

<div id="pr-requisitos">
  ## Prérequis
</div>

* Un [compte développeur X](https://developer.twitter.com/) (niveau gratuit disponible)
* Une [App Replit publiée](/fr/category/replit-deployments) — les identifiants OAuth personnalisés sont disponibles uniquement dans l’environnement de **Production**
* Ouvrez le panneau d’édition du fournisseur **X** : **panneau Auth** → onglet **Configure** → section **fournisseurs SSO** → sélectionnez l’environnement **Production** → sélectionnez **Edit** à côté de **X**

<div id="passo-1-configurar-o-app-de-desenvolvedor-do-x">
  ## Étape 1 : Configurer l’application développeur de X
</div>

<div id="criar-uma-conta-de-desenvolvedor-se-necessrio">
  ### Créer un compte de développeur (si nécessaire)
</div>

1. Accédez au [portail des développeurs de X](https://developer.twitter.com/en/portal/dashboard)
2. Demandez un compte de développeur si vous n’en avez pas encore
3. Finalisez votre demande en décrivant votre cas d’utilisation

<div id="criar-ou-selecionar-um-app">
  ### Créer ou sélectionner une application
</div>

1. Dans le portail des développeurs de X, accédez à **Projects &amp; Apps**
2. Utilisez une application existante ou sélectionnez **Add App**
3. Saisissez un nom pour l’application, puis sélectionnez **Next**
4. Sélectionnez **App settings**

<div id="passo-2-configurar-a-autenticao">
  ## Étape 2 : Configurer l’authentification
</div>

1. Faites défiler jusqu’à **User authentication settings**
2. Sélectionnez **Set up**

**Autorisations de l’application :**

Sélectionnez le niveau d’autorisation minimal :

* **Read** — Requis pour le profil utilisateur (minimum)
* **Write** — Pour publier au nom des utilisateurs (facultatif)
* **Direct Messages** — Pour accéder aux messages directs (facultatif)

<Warning>
  Les autorisations doivent correspondre aux portées demandées. Si votre application demande `tweet.write`, mais que vous avez activé uniquement Read, l’authentification échouera.
</Warning>

**Type d’application :**

Sélectionnez **Web App, Automated App or Bot**

**Informations sur l’application :**

* **Callback URI / Redirect URL** : copiez la valeur affichée dans **Configuration du fournisseur** du **panneau Auth**
* **Website URL** : copiez la valeur affichée dans **Configuration du fournisseur** du **panneau Auth**

Consultez [Configuration des identifiants OAuth pour un fournisseur SSO](/fr/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) pour savoir comment trouver ces valeurs.

3. Sélectionnez **Save**
4. **Enregistrez votre Client ID et votre Client Secret**

<Warning>
  Conservez votre Client Secret dans un endroit sûr. Si vous le perdez, en générer un nouveau invalidera le précédent.
</Warning>

<div id="soluo-de-problemas">
  ## Dépannage
</div>

<div id="incompatibilidade-de-uri-de-redirecionamento">
  ### Incompatibilité de l’URI de redirection
</div>

* Vérifiez que l’URI de rappel correspond exactement à la valeur affichée dans **Configuration du fournisseur** du **panneau Auth**
* Vérifiez l’absence de fautes de frappe ou de protocoles incorrects
* N’ajoutez pas de barre oblique finale

<div id="cliente-invlido">
  ### Client non valide
</div>

* Vérifiez à nouveau le Client ID et le Client Secret
* Assurez-vous qu&#39;il n&#39;y a pas d&#39;espaces superflus
* Vérifiez que vous utilisez des identifiants OAuth 2.0 (et non OAuth 1.0a)

<div id="erros-de-escopopermisso">
  ### Erreurs d’étendue et d’autorisation
</div>

* Vérifiez que les étendues correspondent aux autorisations activées dans le portail des développeurs de X
* Assurez-vous qu’au minimum, l’autorisation Read est activée

<div id="app-em-modo-de-desenvolvimento">
  ### Application en mode développement
</div>

* Les applications X démarrent en mode développement avec un nombre limité d’utilisateurs
* Vous devrez peut-être demander un accès élevé pour une utilisation en production

<div id="no-est-funcionando-no-domnio-personalizado">
  ### Ne fonctionne pas avec le domaine personnalisé
</div>

* Mettez à jour l’URL du site Web et l’URI de rappel avec les valeurs du domaine personnalisé indiquées dans **Configuration du fournisseur** du **panneau Auth**
