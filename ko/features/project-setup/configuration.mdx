Replit Apps는 `.replit`과 `replit.nix` 두 개의 파일로 구성합니다. 이 파일들은 코드 실행부터 개발 도구와 언어에 이르기까지 Replit App의 동작 방식에 영향을 줍니다.

이 구성 파일들은 기본적으로 숨겨져 있습니다. 파일 트리 메뉴에서 &quot;Show hidden files&quot;를 선택하면 Replit App에서 확인할 수 있습니다.

<div id="replitnix-file">
  ## `replit.nix` 파일
</div>

Replit은 `Nix`를 사용하여 packages와 environments를 관리합니다. `replit.nix` 파일의 용도는 다음과 같습니다:

**시스템 dependencies 지정:** Replit App에 필요한 소프트웨어 packages를 package manager인 Nix를 통해 정확하게 정의합니다.

**재현 가능한 환경 구성:** 개발 환경을 일관되고 재현 가능하게 유지하여 협업 projects와 여러 시스템에서의 테스트에 적합합니다.

`Dependencies` 도구를 사용하면 Nix packages를 시각적으로 관리할 수 있습니다. 자세한 내용은 [System Dependencies](/ko/features/project-setup/dependency-management#system-dependencies) 가이드를 참고하세요.

`replit.nix` 파일로 packages를 구성하려면 `deps` 배열에 [Nix packages](https://search.nixos.org/packages)를 `pkgs.` 접두사와 함께 나열하세요. 변경 사항은 shell을 다시 로드한 후에 반영됩니다.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="replit-file">
  ## `.replit` 파일
</div>

`.replit` 파일은 Replit App의 동작을 제어하며, `toml` [구성 형식](https://toml.io/en/)을 사용합니다. 구성할 수 있는 주요 항목은 다음과 같습니다.

**Run 명령:** Run 버튼을 선택했을 때 실행할 명령을 지정합니다. 각 template에는 코드를 바로 실행할 수 있도록 기본 Run 명령가 설정되어 있습니다. 더 세밀한 맞춤 설정이 필요한 복잡한 앱에는 [Workflows](/ko/features/workspace-tools/workflows)를 사용하세요.

**Language Server Protocol (LSP)**: 자동 완성, 코드 탐색, 코드 강조, 실시간 린팅 및 오류 표시 같은 기능을 제공합니다.

**Environment variables:** 애플리케이션이 올바르게 실행되는 데 필요한 환경 변수를 설정하고 관리합니다.

**Dependencies와 packages:** `.replit` 파일에서 직접 package 설치와 configuration을 관리하여 Replit App이 시작될 때 필요한 모든 도구를 갖추도록 합니다. `Dependencies` 도구를 사용하면 dependencies를 시각적으로 관리할 수 있습니다. 자세한 내용은 [System Modules](/ko/features/project-setup/dependency-management#advanced-configuration) 가이드를 참고하세요.

Python 애플리케이션의 기본 `.replit` 파일은 다음과 같습니다.

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

다음 표는 `.replit` 파일 내 각 설정을 한눈에 보여주며, 각 구성이 하는 역할과 Replit App 환경에 미치는 영향을 설명합니다.

| **Configuration key**                           | **값/예시**                               | **설명**                                                                                                                                                    |
| ----------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a name="entrypoint" />`entrypoint`             | `main.py`                              | 에디터를 열 때 기본으로 실행되고 표시되는 main file을 지정합니다. 애플리케이션에 맞게 파일 이름을 변경할 수 있습니다.                                                                                   |
| <a name="modules" />`modules`                   | `["python-3.10:v18-20230807-322e88b"]` | Replit이 지원하는 프로그래밍 언어 또는 주요 dependencies의 특정 버전을 정의합니다.                                                                                                   |
| <a name="nix" />`[nix]`                         |                                        | 시스템 dependencies를 관리하기 위해 package manager인 Nix를 사용하는 설정을 지정합니다. 자세한 내용은 [Dependency Management](/ko/features/project-setup/dependency-management) 문서를 참고하세요. |
| <a name="channel" />`channel`                   | `stable-23_05`                         | 사용할 Nix 채널을 지정하며, 이에 따라 사용할 수 있는 시스템 dependencies의 버전이 달라집니다.                                                                                             |
| <a name="packages" />`packages`                 | `["cowsay", "htop"]`                   | 설치할 Nix packages를 지정합니다. 더 세밀하게 제어하려면 `replit.nix`를 사용할 수도 있습니다.                                                                                          |
| <a name="unitTest" />`[unitTest]`               |                                        | Replit App 내 단위 테스트 관련 설정을 구성합니다.                                                                                                                         |
| <a name="language" />`language`                 | `python3`                              | 단위 테스트에 사용할 언어를 지정합니다. 여기서는 테스트 작성에 Python 3을 사용한다는 의미입니다.                                                                                                |
| <a name="gitHubImport" />`[gitHubImport]`       |                                        | GitHub에서 projects를 가져오는 방식, 특히 어떤 파일이 반드시 포함되어야 하는지를 결정하는 설정입니다.                                                                                          |
| <a name="requiredFiles" />`requiredFiles`       | `[".replit", "replit.nix"]`            | project를 가져올 때 올바르게 동작하도록 반드시 있어야 하는 파일을 나열합니다.                                                                                                           |
| <a name="deployment" />`[deployment]`           |                                        | Replit App의 애플리케이션을 라이브 환경에 배포하기 위한 설정을 담고 있습니다.                                                                                                          |
| <a name="run" />`run`                           | `["python3", "main.py"]`               | deployment 중 애플리케이션을 시작할 때 실행되는 명령입니다.                                                                                                                    |
| <a name="deploymentTarget" />`deploymentTarget` | `cloudrun`                             | 애플리케이션을 호스팅할 deployment 대상 플랫폼을 지정합니다.                                                                                                                    |

이제 `.replit` 파일의 기본 구성을 파악했으니, 다음 섹션에서 Replit App의 기본 설정과 고급 설정을 구성하는 방법을 알아보세요.

<div id="configuring-basic-settings">
  ## 기본 설정 구성하기
</div>

<div id="entrypoint">
  ### Entrypoint
</div>

project의 main file입니다. `run` 속성을 정의하지 않으면 런타임이 `entrypoint`에 지정된 파일을 실행합니다.

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="run-command">
  ### `Run` 명령
</div>

`.replit` 파일의 `run` 속성은 Replit 환경에서 `Run` 버튼을 눌렀을 때 처음 실행되는 명령 또는 일련의 명령을 지정하는 핵심 기능입니다. `Run` 명령은 실행할 명령을 나타내는 문자열로 지정하거나, 명령과 그 명령의 개별 인자를 나타내는 문자열 배열로 지정할 수 있습니다.

`Run` 명령을 설정하는 일반적인 방법은 다음과 같습니다.

* **단일 명령:**
  Replit App에서 바로 실행할 단일 명령을 전달하는 방법을 보여주는 예시입니다. `.replit` 파일에 다음과 같이 작성하면 `Run` 버튼을 눌렀을 때 `Console` pane에 인사말이 표시됩니다.
  **예시:** `run = "echo 'Hello, Replit!'"`

* **명시적 인자:**
  경우에 따라 따옴표 파싱이나 셸 보간 규칙을 신경 쓰지 않도록 더 명시적으로 작성하는 편이 유리할 수 있습니다. 위 예시를 인자를 분리한 형태로 다시 작성할 수 있습니다.
  이 경우 인사말을 `echo`의 첫 번째이자 유일한 인자로 명시적으로 전달하므로 `'`와 `"`를 함께 쓸 필요가 없습니다.
  **예시:** `run = ["echo", "Hello, Replit!"]`

* **여러 명령:**
  frontend와 backend처럼 여러 프로세스를 동시에 실행하는 방법을 보여주는 예시입니다. 각 서버가 서로 다른 포트에 bind되는 python backend와 typescript frontend를 함께 개발할 때 유용합니다.
  **예시:** `run = "python -m app & npm run start & wait"`

<div id="process-management">
  #### 프로세스 관리
</div>

`&`를 사용해 여러 명령을 동시에 실행할 수 있지만, 서비스별로 logs를 더 명확하게 구분하고 싶을 수 있습니다. 이럴 때는 [`process-compose`](https://github.com/F1bonacc1/process-compose) 같은 [시스템 dependencies를 추가](/ko/features/project-setup/dependency-management#system-dependencies)하여 여러 프로세스를 더 효과적으로 오케스트레이션할 수 있습니다.

<div id="build-phase">
  #### `Build` 단계
</div>

일부 언어나 런타임에서는 코드를 `run`하기 전에 별도의 컴파일 단계가 필요합니다. 여기에는 TypeScript, Golang, Java와 같은 컴파일 언어가 해당되며, 다음 `run`이 호출되기 전에 환경, 데이터, 설정을 초기화하는 데 쓸 수 있는 매개변수를 제공하는 경우도 포함됩니다.

* **컴파일:**
  TypeScript 저장소에서는 코드를 실행하기 전에 `tsc`를 실행해야 할 수 있습니다.
  **예시:**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="including-environment-variables">
  #### 환경 변수 포함하기
</div>

실행 전에 서비스에 환경 변수를 전달하려면 `run` 속성을 [테이블](https://toml.io/en/v1.0.0#table) 형태로 확장하면 됩니다.

이는 비교적 큰 변경이며, `.replit` 파일 내에서 `run = "..."` 속성의 위치를 옮겨야 할 수도 있습니다.

다음 diff는 `[run]`의 `args`로 명령을 전달하고, `[run.env]`에서 변수 `NAME`을 전달하는 예시입니다:

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# 새로 추가한 [run]은 `[`로 시작하지 않는 모든
+# 최상위 속성보다 아래로 옮겨야 합니다!
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="interactivity">
  #### 상호작용
</div>

인터랙티브 프로그램도 `Run` 버튼으로 실행할 수 있으며, 이를 통해 개발 환경과 프로그램이 실행되는 터미널을 구분할 수 있습니다.
다음 집계 스크립트를 살펴보세요.

**예시**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="advanced-configuration-options">
  ## 고급 구성 옵션
</div>

Replit App에서 사용할 수 있는 세부 구성 옵션을 살펴보세요. 개발 환경을 사용자 지정하고, Run 명령을 관리하고, 언어 서비스를 연동하고, dependencies를 관리할 수 있습니다.

| **Configuration** | **Key**                             | **Value/Example**                           | **Description**                                   |
| ----------------- | ----------------------------------- | ------------------------------------------- | ------------------------------------------------- |
| onBoot            | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Replit App이 부팅될 때 실행되는 명령입니다.                     |
| compile           | <a name="compile" />`compile`       | (기본 예시 없음)                                  | `run` 명령보다 먼저 실행되는 명령으로, C++과 같은 컴파일 언어에서 사용합니다.  |
| language          | <a name="language" />`language`     | `language = "javascript"`                   | GitHub import 시 또는 Replit App 생성 시 사용할 언어를 지정합니다. |
| entrypoint        | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | 에디터를 열 때 실행되고 표시되는 main file입니다.                  |
| hidden            | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | 사이드 파일 트리에서 기본적으로 숨길 파일 또는 폴더입니다.                 |
| audio             | <a name="audio" />`audio`           | `audio = true`                              | `true`로 설정하면 시스템 전역 오디오를 활성화합니다.                  |

<div id="notes-about-system-wide-audio">
  ### 시스템 전역 오디오 관련 참고 사항
</div>

`.replit` 파일에 `audio = true`를 설정한 경우 개발 환경을 다시 시작해야 할 수 있습니다. `Cmd+K`(Mac) 또는 `Ctrl+K`(Windows)로 명령 팔레트를 열고 **Restart compute**를 검색해 선택하세요.

그래픽 애플리케이션을 실행하면 `Output` 창 오른쪽 아래에 체크박스가 있는 헤드폰 아이콘이 표시됩니다.
브라우저 제한으로 인해 페이지를 새로 고칠 때마다 다시 활성화해야 합니다.

```toml theme={null}
# 이 설정은 `.replit` 파일 맨 위, `[` 대괄호로 묶인 섹션 바깥에 두세요
audio = true
```

<div id="packager-configuration">
  ## packager 설정
</div>

| **Configuration** | **Key**                                           | **Value/Example**                             | **설명**                                       |
| ----------------- | ------------------------------------------------- | --------------------------------------------- | -------------------------------------------- |
| packager          | <a name="language" />`language`                   | `packager.language = "python3"`               | package 작업에 사용할 언어입니다.                       |
| packager features | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Replit App을 실행하기 전에 설치할 package를 자동으로 추론합니다. |
| packager features | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | `true`로 설정하면 packager 지원이 활성화됩니다.            |
| packager features | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Replit App 호스팅 시 package 설치가 필요한지 여부를 설정합니다. |
| packager          | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | packager로 새 package를 설치한 뒤 실행할 명령입니다.        |
| packager          | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | package를 추론할 때 무시할 경로입니다.                    |
| packager          | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | 설치 중 package 추론을 시도하지 않아야 할 모듈입니다.           |

<div id="example-replit-configuration-for-packager-configuration">
  ### packager 설정을 위한 `.replit` 구성 예시
</div>

```toml theme={null}
# Replit App에서 사용할 언어 정의
packager.language = "python3"

# 자동 패키지 관리 기능 활성화
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# 패키지를 설치할 때마다 실행할 명령
packager.afterInstall = "echo 'Package installed successfully'"

# package manager가 무시할 경로와 패키지 정의
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# 추가 deployment 설정
[deployment]
run = ["python3", "app.py"]
```

<div id="deployment-configuration">
  ## 배포 구성
</div>

| **구성**     | **키**                                 | **값/예시**                             | **설명**                                        |
| ---------- | ------------------------------------- | ------------------------------------ | --------------------------------------------- |
| deployment | <a name="run" />`run`                 | `deployment.run = "npm start"`       | 배포 컨테이너가 시작될 때 실행되는 명령입니다.                    |
| deployment | <a name="build" />`build`             | `deployment.build = "npm run build"` | 배포를 실행하기 전에 실행되는 명령입니다.                       |
| deployment | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | `true`이면 배포 성공 여부를 판단할 때 열린 포트 확인이 필요하지 않습니다. |

<div id="example-replit-configuration-for-deployment-configuration">
  ### 배포 설정을 위한 `.replit` 구성 예시
</div>

```toml theme={null}

# 프로젝트의 기본 진입점을 지정합니다
entrypoint = "app.js"

# 애플리케이션 배포를 위한 구성 설정
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  **인터프리터 구성**은 더 이상 지원되지 않으며 Replit에서 사용할 수 없습니다. 대신 `Run` 명령을 사용하여 Replit App 환경에서 스크립트와 애플리케이션이 실행되는 방식을 구성하시기 바랍니다.
</Note>

<div id="port-configuration">
  ## 포트 구성
</div>

| **구성** | **키**                                   | **값/예시**            | **설명**                                 |
| ------ | --------------------------------------- | ------------------- | -------------------------------------- |
| ports  | <a name="localPort" />`localPort`       | `localPort = 3000`  | Replit이 외부 포트에 바인딩하는 포트입니다.            |
| ports  | <a name="externalPort" />`externalPort` | `externalPort = 80` | `localPort`에 연결되어 외부에서 접근할 수 있는 포트입니다. |

<div id="example-replit-configuration-file-for-managing-ports">
  ### 포트 관리를 위한 `.replit` 구성 파일 예시
</div>

```toml theme={null}
# 애플리케이션을 특정 포트로 노출하는 네트워킹 구성
[[ports]]
localPort = 3000
externalPort = 80
```

<div id="accessing-replit-app-environment-metadata">
  ## Replit App 환경 메타데이터 액세스하기
</div>

<div id="nodejs">
  ### Node.js
</div>

모든 환경 변수에 접근하려면 다음과 같이 작성합니다.

`console.log(process.env);`

특정 변수 하나(REPL&#95;SLUG)에 접근하려면 다음과 같이 작성합니다.

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

모든 환경 변수에 접근하려면 다음과 같이 작성합니다.

```python theme={null}
import os
print(os.environ)
```

단일 변수(REPL&#95;SLUG)에 접근하려면 다음과 같이 사용합니다.

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

모든 환경 변수에 접근하려면 다음과 같이 작성합니다.

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

단일 변수(REPL&#95;SLUG)에 접근하려면 다음을 사용합니다:

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```

<div id="environment-variables">
  ## 환경 변수
</div>

다음은 Replit App 내부에서 접근할 수 있는 환경 변수입니다.

| key                                               | 설명                                                                                                                 |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| <a name="REPL_OWNER" />`REPL_OWNER`               | Replit App 소유자의 사용자 이름입니다. Replit App이 텍스트 기반이고 웹 서버가 없는 경우, `REPL_OWNER`에는 현재 해당 Replit App에 접근 중인 User의 값이 반영됩니다 |
| <a name="REPL_ID" />`REPL_ID`                     | Replit App의 고유 UUID 문자열                                                                                            |
| <a name="HOME" />`HOME`                           | Replit App의 홈 경로                                                                                                   |
| <a name="system" />`system`                       | Replit App에서 실행 중인 운영 체제                                                                                           |
| <a name="LANG" />`LANG`                           | Replit App의 언어와 문자 인코딩을 설정하며, 텍스트가 처리되고 표시되는 방식에 영향을 줍니다                                                           |
| <a name="REPL_IMAGE" />`REPL_IMAGE`               | Replit App에 해당하는 도커 이미지                                                                                            |
| <a name="REPL_LANGUAGE" />`REPL_LANGUAGE`         | Replit App에 설정된 프로그래밍 언어로, 런타임 환경과 도구를 결정하는 데 사용됩니다                                                                |
| <a name="REPL_PUBKEYS" />`REPL_PUBKEYS`           | 여러 공개 API keys가 담긴 문자열화된 JSON 객체                                                                                   |
| <a name="REPL_SLUG" />`REPL_SLUG`                 | Replit App 이름을 단순화한 기계 판독용 버전으로, URL과 파일 이름에 사용하기 적합합니다                                                            |
| <a name="PRYBAR_FILE" />`PRYBAR_FILE`             | Replit App의 메인/entrypoint 파일                                                                                       |
| <a name="REPLIT_DEV_DOMAIN" />`REPLIT_DEV_DOMAIN` | Project Editor에서 Replit App의 `replit.dev` URL을 제공합니다. 이 환경 변수는 Deployments에서는 사용할 수 없습니다            |
