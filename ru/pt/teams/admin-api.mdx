<Note>
  Admin API находится в стадии **беты**. Доступные эндпоинты и их поведение могут измениться.
</Note>

Admin API предоставляет администраторам аккаунтов Enterprise программный доступ к аналитике и ресурсам администрирования аккаунта с разграничением по областям доступа (scopes). Используйте API для создания внутренних отчётов, операционных процессов и интеграций для вашего аккаунта Enterprise.

<div id="quem-pode-acessar-a-admin-api">
  ## Кто может получить доступ к Admin API
</div>

Admin API доступен только **администраторам аккаунта** в аккаунтах Enterprise. Администраторы аккаунта могут создавать ключи API и управлять ими. Администраторы workspace и другие участники аккаунта не могут получать доступ к Admin API или создавать ключи API.

Подробнее о ролях администраторов Enterprise см. в разделе [Администраторы аккаунта и workspace](/ru/pt/teams/identity-and-access-management/account-and-workspace-admins).

<div id="criar-uma-chave-de-api">
  ## Создание ключа API
</div>

<Steps>
  <Step title="Откройте настройки разработчика">
    Откройте **Settings**. В разделе **Account** выберите **Developer**.
  </Step>

  <Step title="Создайте ключ API">
    Выберите **Create API key** и укажите доступ только для чтения или для чтения и записи.
  </Step>

  <Step title="Надёжно сохраните ключ">
    Скопируйте ключ, начинающийся с `rpl_`, и сохраните его в безопасном менеджере секретов. Относитесь к нему как к паролю и никогда никому не передавайте.
  </Step>

  <Step title="Настройте аутентификацию интеграции">
    Передавайте ключ как Bearer token в API-запросах.
  </Step>
</Steps>

<div id="o-que-voc-pode-fazer">
  ## Что можно делать
</div>

Admin API использует области доступа (scopes), чтобы определять, что может делать каждый ключ. Области чтения дают доступ к данным аккаунта для отчётности, а отдельные области записи позволяют выполнять действия — например, обновлять бюджеты.

* **Использование:** чтение данных об использовании аккаунта и валовых затрат в реестре с фильтрацией или группировкой по Workspace, участнику, проекту или периоду.
* **Workspaces:** чтение списков и сведений о Workspace, включая количество участников и проектов, администраторов и дату создания.
* **Участники:** чтение состава аккаунта и Workspace с фильтрацией по роли или поиском по имени, имени пользователя либо адресу электронной почты.
* **Проекты:** чтение проектов в Team workspaces с фильтрацией по видимости или статусу развёртывания либо поиском по названию, слагу или описанию.
* **Бюджеты:** чтение бюджетов аккаунта и их обновление с помощью области `write:budgets`.

Ответы API поддерживают курсорную пагинацию и содержат заголовки ограничения частоты запросов, а также `X-Request-Id` для отслеживания запросов.

<div id="crie-relatrios-e-fluxos-de-trabalho">
  ## Создавайте отчёты и рабочие процессы
</div>

Используйте данные Admin API там, где вы уже отслеживаете операции: во внутренней панели, в оповещениях Slack или в ежемесячном финансовом отчёте. Например, сгруппируйте данные об использовании по Workspace, чтобы отслеживать расходы каждого Workspace.

<div id="construindo-com-o-replit-agent">
  ## Создание с Replit Agent
</div>

Вы можете попросить Replit Agent создать пользовательскую панель мониторинга с помощью Admin API. Опишите данные аккаунта, которые хотите отслеживать, например использование по Workspace или расходы по проектам, и Agent создаст панель и интеграцию с API.

<Steps>
  <Step title="Откройте селектор навыков">
    В проекте Replit нажмите кнопку **+** рядом с полем ввода в чате и выберите **Use a skill**.
  </Step>

  <Step title="Выберите навык Admin API">
    В разделе **Replit skills** выберите **Admin API**, чтобы предоставить Agent контекст API и рекомендации по интеграции.
  </Step>

  <Step title="Опишите панель">
    Расскажите Agent, что вы хотите отслеживать и как хотите это визуализировать. Например, попросите Agent создать панель, которая показывает использование по Workspace и расходы по проектам.
  </Step>

  <Step title="Безопасно добавьте API-ключ">
    Когда Agent потребуется выполнять API-запросы, добавьте ключ Admin API в Secrets вашего проекта. Не вставляйте ключ в чат и не включайте его в коммиты проекта.
  </Step>
</Steps>
