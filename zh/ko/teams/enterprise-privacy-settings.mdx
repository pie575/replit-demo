企业版管理员可以配置组织级设置，控制团队成员与代码、部署及外部平台的交互方式。这些设置有助于维护安全标准、保护知识产权，并确保符合企业政策。

<div id="section">
  ## 访问隐私设置
</div>

<Accordion title="如何访问隐私设置">
  1. 进入企业版工作区
  2. 选择**设置**
  3. 选择**高级**，查看所有可用设置
</Accordion>

<div id="section-2">
  ## 隐私设置
</div>

隐私设置用于控制组织内应用的发布和访问方式。

<CardGroup cols={2}>
  <Card title="私有部署" icon="lock">
    要求所有新应用以私有方式发布，仅允许已通过身份验证的团队成员访问
  </Card>

  <Card title="密码保护部署" icon="key">
    允许团队成员为已发布的应用添加密码保护
  </Card>

  <Card title="私有开发 URL" icon="shield-halved">
    对于已启用 SAML 的组织，所有应用开发 URL 均需身份验证 (包括 SSO)
  </Card>
</CardGroup>

<div id="section-3">
  ### 私有部署
</div>

启用后，所有新应用都必须以私有方式发布。私有应用仅限组织中已通过身份验证的成员访问。

**适用场景：**

* 组织需要处理敏感数据或专有应用程序
* 需要确保应用不会被意外公开
* 合规要求规定必须限制对已发布应用程序的访问

<Note>
  此设置仅适用于新发布的应用。此前已发布的应用将保留当前的可见性设置。
</Note>

<div id="section-4">
  ### 密码保护部署
</div>

控制团队成员是否可以创建受密码保护的部署。启用后，构建者可以额外添加一层安全防护，要求输入密码才能访问已发布的应用。

**适用场景：**

* 希望与外部利益相关方共享应用，但不想完全公开
* 团队需要在更大范围上线之前向客户演示应用
* 需要比组织成员身份更精细的访问控制

<div id="url">
  ### 要求使用私有开发 URL
</div>

启用后，所有应用的开发 URL 都需要进行身份验证。如果您的组织已启用 SAML，则开发 URL 需通过 SSO 进行身份验证。

**适用场景：**

* 需要防止他人未经授权访问正在开发中的应用
* 安全策略要求保护所有开发环境
* 希望确保只有通过身份验证的团队成员才能查看开发预览

<Warning>
  此设置将追溯应用于组织中的所有现有应用。
</Warning>

<div id="section-5">
  ### 禁止导出源代码
</div>

启用后，团队成员将无法把应用源代码导出为 zip 文件，从而防止代码被下载并分享到 Replit 平台之外。

**适用以下场景：**

* 需要严格控制源代码的存放位置
* 安全策略禁止在本地保留代码副本
* 希望确保所有开发工作都在受管控的环境中进行

<div id="section-6">
  ## 安全设置
</div>

安全设置有助于实施漏洞扫描等各项保护措施。

<div id="section-7">
  ### 安全扫描要求
</div>

配置所有应用在发布前是否必须通过安全扫描。安全扫描会检测代码中的漏洞、泄露的密钥以及其他安全问题。

可用选项：

| 设置     | 说明               |
| ------ | ---------------- |
| **关闭** | 安全扫描为可选项         |
| **要求** | 所有应用必须在发布前通过安全扫描 |

**适用场景：**

* 需要满足安全合规要求
* 希望防止 API 密钥或其他密钥意外泄露
* 需要确保所有已发布应用遵循一致的安全标准

<Note>
  此设置不适用于在启用该设置之前已发布的应用。
</Note>

<div id="section-8">
  ## 源代码控制设置
</div>

源代码控制设置可帮助您落实版本控制规范，保护组织的代码仓库。

<div id="git">
  ### 要求推送到 Git 远程仓库
</div>

启用后，所有应用在发布前都必须将本地更改推送到 Git 远程仓库，从而确保所有代码更改都在组织的版本控制系统中得到追踪。

**适用场景：**

* 需要将所有代码备份到 Git
* 需要保留所有代码更改的审计记录
* 工作流程要求在发布前进行代码审查

<Note>
  此设置对启用之前已发布的应用不生效。
</Note>

<div id="section-9">
  ### 私有远程仓库
</div>

控制团队成员能否使用公开的 Git 仓库。启用私有远程仓库要求后，团队成员只能推送到 GitHub 等平台上的私有仓库。

可用选项：

| 设置           | 说明                      |
| ------------ | ----------------------- |
| **关闭**       | 团队成员可使用公开或私有仓库          |
| **仅对非管理员要求** | 非管理员的团队成员必须使用私有仓库       |
| **对所有人要求**   | 包括管理员在内的所有团队成员都必须使用私有仓库 |

**适用场景：**

* 组织禁止使用公开代码仓库
* 需要确保专有代码不会被误推送到公开仓库
* 合规要求必须使用私有版本控制

<div id="section-10">
  ## 最佳实践
</div>

<AccordionGroup>
  <Accordion title="默认保持私有" icon="shield">
    启用**私有部署**，确保所有新发布的应用默认处于私有状态。这有助于防止敏感应用被意外暴露。
  </Accordion>

  <Accordion title="实施安全扫描" icon="magnifying-glass">
    启用**安全扫描要求**，以便在应用上线前发现漏洞。这有助于在整个组织内保持一致的安全标准。
  </Accordion>

  <Accordion title="保护开发环境" icon="code">
    启用**要求使用私有开发 URL**，确保进行中的工作也受到保护。这对于处理敏感数据的组织尤为重要。
  </Accordion>

  <Accordion title="控制源代码访问" icon="code-branch">
    将**禁止导出源代码**与**要求使用私有远程仓库**相结合，全面掌控代码的位置和访问权限。
  </Accordion>
</AccordionGroup>
