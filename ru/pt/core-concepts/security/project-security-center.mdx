<div id="como-os-resultados-so-categorizados">
  ## Как классифицируются результаты
</div>

Результаты обоих типов сканирования отображаются на панели Security и распределяются по уровням серьёзности:

* **Critical**: уязвимости, которые несут непосредственный риск и должны быть устранены до публикации. Примеры: удалённое выполнение кода, SQL-инъекции в открытых эндпоинтах и утечка учётных данных.
* **High**: серьёзные проблемы, которые могут быть использованы при определённых условиях, — например межсайтовый скриптинг (XSS), небезопасные схемы аутентификации или необновлённые зависимости с известными эксплойтами.
* **Medium**: проблемы, которые создают потенциальный риск, но с меньшей вероятностью поддаются эксплуатации, — например отсутствующие заголовки безопасности или слишком свободные настройки CORS.
* **Low / Informational**: незначительные проблемы или рекомендации по передовым практикам — например использование устаревших API или подробные сообщения об ошибках в рабочей среде.

<div id="o-que-o-project-security-center">
  ## Что такое Project Security Center?
</div>

Project Security Center — это центр вашего проекта, где можно найти и устранить уязвимости безопасности и конфиденциальности ещё до публикации. Откройте панель **Security** в своём Project, чтобы запускать сканирование, просматривать результаты и передавать принятые проблемы Agent для устранения.

Project Security Center поддерживает два типа сканирования:

1. **Автоматическое сканирование зависимостей**: бесплатные лёгкие проверки, которые сверяют пакеты проекта с публичными реестрами уязвимостей
2. **Сканирование безопасности с помощью Agent**: проверки с поддержкой ИИ, которые сочетают анализ моделей с инструментами статического анализа кода для аудита всей кодовой базы

Результаты обоих типов сканирования отображаются в одной панели Security и сортируются по уровню серьёзности, чтобы вы могли сначала заняться наиболее критичными проблемами.

<div id="varreduras-automticas-de-dependncias">
  ## Автоматическое сканирование зависимостей
</div>

Автоматическое сканирование зависимостей сверяет пакеты, от которых зависит проект, с публичными базами уязвимостей. Такое сканирование **бесплатно** и выполняется автоматически. Как только публикуется новая запись Common Vulnerabilities and Exposures (CVE), Replit сопоставляет её с зависимостями вашего проекта и показывает все совпадения на панели **Security** — повторное ручное сканирование не требуется.

Сканирование зависимостей поддерживает Node.js/npm, Python, Go, Rust, PHP и Ruby. Например, оно может выявить известную уязвимость в устаревшем пакете вроде `express@4.18.2`.

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect расширяет возможности автоматического сканирования зависимостей. При обнаружении подходящей уязвимости Replit Agent готовит и тестирует патч, а затем отправляет прямую ссылку по электронной почте. Auto-Protect охватывает только CVE в зависимостях — для уязвимостей в коде вашего приложения используйте [сканирование безопасности с Agent](#agent-security-scans).

Для каждой новой уязвимости, затрагивающей зависимости вашего проекта, Replit:

1. Отправляет письмо с кратким описанием и прямой ссылкой на панель **Security** затронутого проекта.
2. Поручает Replit Agent подготовить и протестировать патч, устраняющий уязвимость.
3. Оставляет патч на панели **Security** в ожидании проверки.

Выберите **Go to Task**, чтобы изучить сгенерированные изменения перед их применением. После применения патча уязвимость получает статус **pending republish** — до тех пор, пока вы не опубликуете новую версию.

Всегда публикуйте приложение заново после применения патча, чтобы рабочая версия оставалась защищённой.

Replit отправляет не более одного письма на Workspace для каждой новой уязвимости. В письме перечислены все затронутые проекты в этом Workspace. Администраторы могут задать минимальный уровень серьёзности, при котором срабатывает Auto-Protect — например, только критический.

<div id="ativar-o-auto-protect">
  #### Включение Auto-Protect
</div>

Обе настройки Auto-Protect **по умолчанию отключены**. Для включения Auto-Protect потребуется задать две настройки: доступную только администраторам, которая разрешает Replit подготавливать патчи, и личную, определяющую, будете ли вы получать письма о новых уязвимостях.

<Steps>
  <Step title="Включите подготовку патчей (только для администраторов)">
    Перейдите в **Settings** &gt; **Account** &gt; **Advanced** и выберите минимальный уровень серьёзности (low, medium, high или critical), начиная с которого Replit должен автоматически готовить исправления. Чем выше порог, тем реже Replit готовит патчи — только для самых серьёзных уязвимостей.
  </Step>

  <Step title="Включите письма о безопасности">
    Перейдите в **Settings** &gt; **Personalization** &gt; **Email Notifications** и выберите минимальный уровень серьёзности, при котором вы хотите получать уведомления о новых проблемах безопасности. Обычно выбирают high или critical.
  </Step>
</Steps>

<Note>
  Исправления, подготовленные Agent, тарифицируются так же, как и любая другая работа Agent, даже если
  они подготовлены проактивно в рамках Auto-Protect.
</Note>

<div id="varreduras-de-segurana-com-agent">
  ## Сканирование безопасности с Agent
</div>

Сканирование безопасности с Agent не ограничивается анализом зависимостей — они проводят полный аудит всей кодовой базы. Security Agent сочетает проверку с помощью моделей со средствами статического анализа, такими как [Semgrep](https://semgrep.dev/) и [HoundDog.ai](https://hounddog.ai), чтобы находить уязвимости, которые не выявить одним лишь сопоставлением с шаблонами.

Сканирование безопасности с Agent доступны всем разработчикам с платными планами Replit. В крупных проектах глубокий аудит может занять до 15 минут — это нужно для полноценной оценки.

<div id="o-que-o-security-agent-faz">
  ### Что делает Security Agent
</div>

Когда вы запускаете сканирование безопасности с Agent, Security Agent проводит полный анализ вашей кодовой базы:

1. **Составляет карту архитектуры** — определяет маршруты, API, потоки данных и точки входа
2. **Строит модель угроз** — создаёт настраиваемый план моделирования угроз для вашего приложения
3. **Выполняет статический анализ** — использует Semgrep и HoundDog.ai для поиска уязвимостей в коде и проблем с конфиденциальностью
4. **Анализирует результаты с помощью ИИ** — оценивает, действительно ли выявленные проблемы можно эксплуатировать в контексте вашего приложения, что заметно снижает число ложных срабатываний
5. **Формирует отчёт о результатах** — представляет обнаруженные риски для дальнейшего разбора

Сканирование безопасности с Agent охватывают широкий круг категорий уязвимостей:

* **Проблемы статического анализа (SAST)**: небезопасные шаблоны кода, такие как SQL-инъекции, межсайтовый скриптинг (XSS) и подделка межсайтовых запросов (CSRF)
* **Проблемы конфиденциальности**: конфиденциальные данные, попадающие в небезопасные места — журналы, файлы или сторонние API
* **Архитектурные уязвимости**: недостатки безопасности в том, как устроены маршруты, API и потоки данных

Например, проверка может отметить непараметризованный запрос к базе данных:

```javascript theme={null}
const query = `SELECT * FROM users WHERE username = '${userInput}'`;
```

Или код, который логирует конфиденциальные данные пользователей:

```javascript theme={null}
logger.info("New signup", {
  email: user.email,
  phoneNumber: user.phoneNumber,
  address: user.address,
});
```

    <Frame>
      <img src="/assets/mirror/scan-options-c2cd398fa78b.png" alt="Всплывающее окно параметров проверки с полем Add context для ограничения проверки определёнными областями проекта" width="1440" height="900" data-path="images/project-security-center/scan-options.png" />

    Дождитесь завершения проверки. Обычно это занимает несколько минут, но для
    крупных проектов может потребоваться до 15 минут.
  </Step>
</Steps>

По завершении проверки Security Agent формирует отчёт о выявленных рисках. Вы можете изучить детали уязвимостей, отклонить те результаты, которые вам понятны и приемлемы, либо просмотреть результаты перед отправкой на устранение.

После просмотра результатов отправьте принятые проблемы в Replit Agent для устранения. Security Agent распределяет уязвимости по отдельным задачам, чтобы Agent мог работать над несколькими исправлениями параллельно. Когда исправления будут применены, запустите ещё одну проверку, чтобы убедиться, что проблемы устранены.

После исправления первой партии результатов запустите проверку повторно. В крупных проектах после устранения наиболее серьёзных проблем могут обнаружиться дополнительные.

<div id="limitaes-e-melhores-prticas">
  ## Ограничения и рекомендации
</div>

* **Конфиденциальность и обработка данных**: всё сканирование выполняется в инфраструктуре Replit. Ваш код и данные не передаются ни Semgrep, ни HoundDog.ai, ни третьим лицам. Настройки и результаты сканирования остаются привязанными к вашему Replit App.
* **Поддержка языков**:
  * Сканирование зависимостей поддерживает многие популярные экосистемы (включая **Node.js/npm**, **Python**, **Go**, **Rust**, **PHP** и **Ruby**).
  * Автоматическое исправление зависимостей пока ориентировано на **Node.js/npm**.
* **Это не полноценный аудит безопасности**: используйте сканирование вместе с код-ревью, тестированием, проверкой зависимостей и проверками работающего приложения.
* **Запускайте повторно после изменений**: выполняйте сканирование заново:
  * после добавления или обновления зависимостей
  * после существенных изменений в коде
  * перед публикацией новой версии

<div id="verificaes-de-publicao">
  ## Проверки при публикации
</div>

Настройка **Block publishing of critical vulnerabilities** находится в расширенных настройках вкладки Deploy (а также в процессе повторной публикации). Replit всегда выполняет проверку безопасности перед публикацией; этот переключатель определяет, что произойдёт, если проверка обнаружит проблему критического уровня:

* **Включено** — публикация блокируется, пока проблема не будет устранена или отклонена.
* **Выключено** — публикация продолжается, а результат выводится для ознакомления.

Включите эту настройку, чтобы ничего критического не публиковалось без вашей проверки. Организации с планами Enterprise могут сделать её обязательной для всех приложений.

<Note>
  Раньше эта настройка называлась «Security scan before publishing» и была помечена тегом **Beta**. Теперь она вышла из стадии Beta и переименована, чтобы её поведение было понятнее — сама проверка в любом случае выполняется всегда.
</Note>
