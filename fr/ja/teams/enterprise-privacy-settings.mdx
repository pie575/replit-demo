En tant qu&#39;administrateur Enterprise, vous pouvez configurer des paramètres à l&#39;échelle de l&#39;organisation qui déterminent la manière dont les membres de votre équipe interagissent avec le code, les déploiements et les plateformes externes. Ces paramètres vous aident à maintenir vos normes de sécurité, à protéger la propriété intellectuelle et à assurer la conformité aux politiques de votre entreprise.

<div id="section">
  ## Accès aux paramètres de confidentialité
</div>

<Accordion title="Comment accéder aux paramètres de confidentialité">
  1. Accédez à votre espace de travail Enterprise
  2. Sélectionnez **Paramètres**
  3. Sélectionnez **Avancé** pour afficher tous les paramètres disponibles
</Accordion>

<div id="section-2">
  ## Paramètres de confidentialité
</div>

Les paramètres de confidentialité contrôlent la façon dont les applications sont publiées et accessibles au sein de votre organisation.

<CardGroup cols={2}>
  <Card title="Déploiements privés" icon="lock">
    Exige que toutes les nouvelles applications soient publiées en tant qu’applications privées et limite l’accès aux membres authentifiés de l’équipe
  </Card>

  <Card title="Déploiements protégés par mot de passe" icon="key">
    Permet aux membres de l’équipe d’ajouter une protection par mot de passe aux applications qu’ils publient
  </Card>

  <Card title="URL de développement privées" icon="shield-halved">
    Exige une authentification pour toutes les URL de développement des applications, y compris via le SSO pour les organisations où SAML est activé
  </Card>
</CardGroup>

<div id="section-3">
  ### Déploiements privés
</div>

Lorsque ce paramètre est activé, toutes les nouvelles applications doivent être publiées en mode privé. Les applications privées sont accessibles uniquement aux membres authentifiés de l&#39;organisation.

**Quand utiliser ce paramètre :**

* Votre organisation traite des données confidentielles ou des applications propriétaires
* Vous devez éviter toute publication accidentelle d&#39;une application
* Des exigences de conformité imposent de restreindre l&#39;accès aux applications publiques

<Note>
  Ce paramètre s&#39;applique uniquement aux applications nouvellement publiées. Les applications déjà publiées conservent leurs paramètres de publication actuels.
</Note>

<div id="section-4">
  ### Déploiements protégés par mot de passe
</div>

Détermine si les membres de l&#39;équipe peuvent créer des déploiements protégés par mot de passe. Lorsque cette option est activée, les créateurs peuvent ajouter un niveau de sécurité supplémentaire en exigeant un mot de passe pour accéder aux applications publiées.

**Quand utiliser ce paramètre :**

* Lorsque vous souhaitez partager une application avec des parties prenantes externes sans la rendre totalement publique
* Lorsque votre équipe doit faire une démonstration d&#39;une application à des clients avant une diffusion plus large
* Lorsque vous avez besoin d&#39;un contrôle d&#39;accès précis, au-delà de la seule appartenance à l&#39;organisation

<div id="url">
  ### Exiger des URL de développement privées
</div>

Lorsque ce paramètre est activé, toutes les URL de développement des applications requièrent une authentification. Si SAML est activé dans votre organisation, les URL de développement nécessitent une authentification SSO.

**Quand utiliser ce paramètre :**

* Lorsque vous devez empêcher tout accès non autorisé aux applications en cours de développement
* Lorsque votre politique de sécurité impose la protection de tous les environnements de développement
* Lorsque vous souhaitez que seuls les membres authentifiés de l&#39;équipe puissent consulter les aperçus de développement

<Warning>
  Ce paramètre s&#39;applique rétroactivement à toutes les applications existantes de votre organisation.
</Warning>

<div id="section-5">
  ### Interdiction de l&#39;exportation du code source
</div>

Une fois ce paramètre activé, les membres de l&#39;équipe ne peuvent plus exporter le code source d&#39;une application sous forme de fichier zip. Cela empêche le téléchargement et le partage du code en dehors de la plateforme Replit.

**Quand utiliser ce paramètre :**

* Lorsque vous devez garder un contrôle strict sur l&#39;emplacement du code source
* Lorsque votre politique de sécurité interdit les copies locales du code
* Lorsque vous souhaitez que tout le développement se déroule dans un environnement contrôlé

<div id="section-6">
  ## Paramètres de sécurité
</div>

Les paramètres de sécurité vous aident à mettre en place l&#39;analyse des vulnérabilités et d&#39;autres mesures de protection.

<div id="section-7">
  ### Exiger une analyse de sécurité
</div>

Définissez si toutes les applications doivent réussir une analyse de sécurité avant leur publication. L&#39;analyse de sécurité détecte les vulnérabilités du code, les secrets exposés et d&#39;autres problèmes de sécurité.

Options disponibles :

| Paramètre       | Description                                                                              |
| --------------- | ---------------------------------------------------------------------------------------- |
| **Désactivé**   | L&#39;analyse de sécurité est facultative                                                |
| **Obligatoire** | Toutes les applications doivent réussir l&#39;analyse de sécurité avant leur publication |

**Quand utiliser ce paramètre :**

* Lorsque vous devez répondre à des exigences de conformité en matière de sécurité
* Lorsque vous souhaitez éviter l&#39;exposition accidentelle de clés API ou de secrets
* Lorsque vous devez garantir des normes de sécurité homogènes pour toutes les applications publiées

<Note>
  Ce paramètre ne s&#39;applique pas aux applications publiées avant son activation.
</Note>

<div id="section-8">
  ## Paramètres de gestion des sources
</div>

Les paramètres de gestion des sources vous permettent d&#39;imposer des pratiques de contrôle de version et de protéger les dépôts de code de votre organisation.

<div id="git">
  ### Exiger un dépôt distant Git
</div>

Lorsqu&#39;il est activé, chaque application doit envoyer ses modifications locales vers un dépôt distant Git avant d&#39;être publiée. Cela garantit que toutes les modifications de code sont suivies dans le système de gestion de versions de votre organisation.

**Utilisez ce paramètre lorsque :**

* Vous devez sauvegarder tout votre code dans Git
* Vous avez besoin d&#39;une piste d&#39;audit de toutes les modifications de code
* Votre workflow exige une révision du code avant la publication

<Note>
  Ce paramètre ne s&#39;applique pas aux applications publiées avant son activation.
</Note>

<div id="section-9">
  ### Dépôts distants privés
</div>

Contrôlez si les membres de l&#39;équipe peuvent utiliser des dépôts Git publics. Si vous exigez l&#39;utilisation de dépôts distants privés, les membres de l&#39;équipe ne peuvent pousser que vers des dépôts privés hébergés sur des plateformes comme GitHub.

Options disponibles :

| Paramètre                          | Description                                                                                         |
| ---------------------------------- | --------------------------------------------------------------------------------------------------- |
| **Désactivé**                      | Les membres de l&#39;équipe peuvent utiliser des dépôts publics ou privés                           |
| **Exiger des non-administrateurs** | Les membres de l&#39;équipe non administrateurs doivent utiliser des dépôts privés                  |
| **Exiger de tous**                 | Tous les membres de l&#39;équipe, y compris les administrateurs, doivent utiliser des dépôts privés |

**Quand utiliser ce paramètre :**

* Lorsque les dépôts de code publics sont interdits
* Lorsque vous devez empêcher que du code propriétaire soit poussé par erreur vers un dépôt public
* Lorsque des exigences de conformité imposent une gestion de versions privée

<div id="section-10">
  ## Bonnes pratiques
</div>

<AccordionGroup>
  <Accordion title="Commencer en mode privé par défaut" icon="shield">
    Activez les **déploiements privés** afin que toutes les nouvelles applications publiées soient privées. Vous évitez ainsi l&#39;exposition accidentelle d&#39;applications sensibles.
  </Accordion>

  <Accordion title="Imposer l'analyse de sécurité" icon="magnifying-glass">
    Configurez l&#39;option **Exiger une analyse de sécurité** pour détecter les vulnérabilités avant la publication d&#39;une application. Vous maintenez ainsi des normes de sécurité cohérentes dans toute l&#39;organisation.
  </Accordion>

  <Accordion title="Protéger l'environnement de développement" icon="code">
    Activez l&#39;option **Exiger des URL de développement privées** afin que le travail en cours soit lui aussi protégé. Ce point est particulièrement important pour les organisations qui traitent des données sensibles.
  </Accordion>

  <Accordion title="Contrôler l'accès au code source" icon="code-branch">
    Combinez l&#39;**Interdiction de l’exportation du code source** avec l&#39;exigence de **dépôts distants privés** pour garder un contrôle total sur l&#39;emplacement de votre code et l&#39;accès à celui-ci.
  </Accordion>
</AccordionGroup>
