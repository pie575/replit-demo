# Qu'est-ce qu'une application ?

> Découvrez ce que sont les applications, pourquoi elles sont utiles et comment les applications sont liées aux artefacts que vous pouvez créer et publier sur Replit.

Une application est un logiciel conçu pour accomplir une tâche spécifique pour une personne ou un groupe spécifique.

Les applications peuvent être simples ou complexes. Une calculatrice, un formulaire de réservation, un tableau de bord, un outil interne, une expérience mobile, un marché et un portail client sont tous des applications si elles aident quelqu'un à faire quelque chose d'utile.

## Les applications sont du code qui s'exécute sur une infrastructure

Chaque application est deux choses qui fonctionnent ensemble :

* **Le code** — les instructions qui décrivent ce que fait l'application : l'interface que quelqu'un voit, la logique qui répond aux clics et aux saisies, et les règles qui régissent le déplacement des données.
* **L'infrastructure** — les machines, les réseaux, le stockage et les services sur lesquels le code s'exécute pour que d'autres personnes puissent y accéder depuis un navigateur ou un téléphone.

Écrire le code est la partie que la plupart des gens imaginent lorsqu'ils pensent à « construire une application ». L'infrastructure, c'est tout ce qui doit être en place pour que ce code fonctionne réellement pour les utilisateurs : un serveur pour l'exécuter, une base de données pour stocker les informations, un domaine pour que les gens puissent le trouver, une sécurité pour le protéger et un moyen de le mettre à jour sans casser ce qui fonctionne déjà.

Sur Replit, vous décrivez ce que vous voulez en langage naturel. L'Agent écrit le code et Replit fournit l'infrastructure — hébergement, bases de données, secrets, domaines et déploiements — afin que vous puissiez publier une application fonctionnelle sans avoir à en configurer quoi que ce soit vous-même.

## Pourquoi créer une application ?

Vous pourriez créer une application lorsque les outils existants fonctionnent presque, mais pas tout à fait.

Une application est utile quand :

* Vous souhaitez un flux de travail personnalisé
* Vous avez atteint les limites d'une feuille de calcul, d'un formulaire ou d'un modèle
* Vous avez besoin d'un processus reproductible
* Vous voulez tester la demande pour une idée
* Vous souhaitez que vos coéquipiers, clients ou utilisateurs interagissent avec quelque chose que vous contrôlez

Par exemple, un entrepreneur pourrait créer une application de liste d'attente pour tester la demande. Un marketeur pourrait créer une page de destination de campagne avec un formulaire. Un analyste de données pourrait créer un tableau de bord qui facilite l'exploration d'une feuille de calcul.

## Les applications résolvent un problème ciblé

Les bonnes premières applications sont ciblées. Elles résolvent un problème clair pour un public clair.

Au lieu de commencer par :

```text theme={null}
Une plateforme pour gérer l'ensemble de mon entreprise.
```

Commencez par :

```text theme={null}
Une page où les clients peuvent demander un devis de traiteur et recevoir un message de confirmation.
```

La version plus petite est plus facile à construire, tester, publier et améliorer.

## Les applications et les artefacts

Sur Replit, une application est un type d'artefact. Un artefact est un résultat publiable d'un projet.

Les artefacts peuvent inclure :

* Des applications web
* Des applications mobiles
* Des tableaux de bord de données
* Des présentations de diapositives
* Des vidéos animées
* Des designs
* Des expériences 3D

Les applications sont généralement interactives. Elles permettent souvent aux personnes de soumettre des informations, d'afficher des données, de se connecter, de faire des choix ou de compléter un flux de travail. D'autres artefacts, comme des présentations ou des vidéos animées, peuvent se concentrer davantage sur la présentation ou la narration.

## Qu'est-ce qui rend une application réelle ?

Une application commence à sembler réelle quand quelqu'un peut l'utiliser en dehors de votre tête.

Cela signifie généralement :

* Elle a un but clair
* Quelqu'un peut accomplir l'action principale
* Vous pouvez la tester en Aperçu
* Vous pouvez la publier vers une URL partageable
* Vous pouvez l'améliorer après avoir reçu des retours

La première version n'a pas besoin de toutes les fonctionnalités. Elle doit fonctionner suffisamment bien pour en tirer des enseignements.

## Idées reçues courantes

* **« Une application doit être grande. »** De nombreuses applications précieuses sont de petits outils pour un travail spécifique.
* **« Une application doit être publique. »** Certaines applications sont des outils privés pour vous, votre équipe ou vos clients.
* **« Une application doit être parfaite avant d'être publiée. »** Publier une première version ciblée vous aide à apprendre ce qu'il faut améliorer.
