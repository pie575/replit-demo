Agent поддерживает четыре типа интеграций, чтобы вы могли быстро превратить идею в App:

* **Управляемые Replit**: Встроенные интеграции, которые работают автоматически. Создайте App, и Agent сможет сразу их использовать.
* **Connectors**: Собственные интеграции Replit. Войдите в систему один раз. Agent может напрямую из чата читать и записывать данные в этих сервисах — получать данные, создавать записи, отправлять сообщения — и использовать их при разработке ваших App.
* **Внешние интеграции**: Надёжные сторонние сервисы, которые можно использовать при разработке. Попросите Agent настроить их; вам потребуется предоставить API-ключи.
* **Сервисы Agent**: Платные сторонние API, которые Agent использует в фоновом режиме — API-ключи не требуются. Использование оплачивается кредитами Replit.

<Note>
  **Доступность по тарифам**: Для большинства коннекторов требуется подписка Core, Pro или Enterprise, а некоторые доступны на тарифе Free. В каталоге коннекторов в вашем рабочем пространстве указано, какие коннекторы доступны на вашем текущем тарифе. Разработчики на тарифе Free всегда могут использовать интеграции, управляемые Replit, например базы данных, аутентификацию и другие.
</Note>

<div id="getting-started">
  ## Начало работы
</div>

Чтобы использовать интеграцию, упомяните нужный сервис или функцию. Например:

<AiPrompt>
  Создай веб-приложение, которое принимает платежи через Stripe и отправляет письма с подтверждением через SendGrid
</AiPrompt>

Agent автоматически распознает эти ключевые слова и добавит необходимый код и настройки.

<div id="let-agent-suggest-a-connector">
  ### Позвольте Agent предложить коннектор
</div>

Иногда несколько сервисов могут выполнять одну и ту же задачу, например хранить файлы или отправлять электронную почту. Если вы запрашиваете нужную возможность, не указывая поставщика, Agent покажет краткий список подходящих коннекторов. Выберите нужный.

Выберите поставщика, затем один раз войдите в систему, чтобы подключить аккаунт. Agent будет использовать ваш выбор при создании приложения. Чтобы пропустить список, также можно указать конкретный сервис по имени.

<div id="connectors">
  ## Connectors
</div>

Connectors позволяют Agent напрямую читать данные из ваших сервисов и записывать в них. Это интеграции, поддерживаемые Replit. Войдите в систему один раз на странице Connectors в Project Editor, а затем используйте эти подключения в разных приложениях.

<Note>
  Подключения привязаны к вашей учётной записи Replit и доступны во всех ваших приложениях. Подключите сервис один раз и используйте его в любом созданном вами приложении.
</Note>

<div id="use-slack-with-agent">
  ### Использование Slack с Agent
</div>

Подключите Slack, чтобы предоставить Agent контекст из доступных вам бесед. Попросите Agent найти сообщения, файлы, каналы или людей, а затем использовать результаты, чтобы ответить на вопросы или продолжить работу.

С вашего разрешения Agent может:

* Читать закрытые каналы, личные и групповые личные сообщения, в которых вы участвуете.
* Читать все ответы в треде, когда требуется дополнительный контекст.
* Отправлять сообщения от вашего имени.
* Создавать, читать и обновлять Canvas в Slack.

<div id="configuring-oauth-app-with-replit">
  ### Настройка OAuth-приложения в Replit
</div>

<Note>
  **Только для Enterprise**: для настройки собственного OAuth-приложения требуется подписка Enterprise.
</Note>

На тарифе Enterprise вы можете использовать собственное OAuth-приложение для коннектора вместо стандартного приложения Replit. Это позволяет вашей организации владеть OAuth-клиентом, отображать собственный брендинг на экране согласия и контролировать точные области доступа, которые могут запрашивать ваши разработчики.

Чтобы настроить коннектор с собственным OAuth-приложением, вам понадобятся три вещи от поставщика: **Client ID**, **Client Secret** и **scopes**, которые вы хотите авторизовать. Также необходимо зарегистрировать у поставщика URL обратного вызова Replit, чтобы завершить аутентификацию.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Диалог настройки OAuth для коннектора с полями Client ID, Client Secret и Connector Scopes, а также Redirect URL со значением https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Создайте OAuth-приложение у поставщика">
    Войдите в консоль разработчика или настройки администратора поставщика и создайте новое OAuth 2.0-приложение. Поставщики могут по-разному называть этот шаг — ищите такие варианты, как **Create OAuth app**, **Register application** или **Create client credentials**.
  </Step>

  <Step title="Укажите URL перенаправления">
    Когда поставщик запросит **Authorized redirect URI** (иногда называется **Callback URL** или **Redirect URL**), введите:

    ```
    https://replit.com/connectors/oauth/callback
    ```

    На этот URL поставщик перенаправляет разработчиков обратно в Replit после авторизации приложения. Он должен совпадать в точности: важны завершающие слеши, протокол и поддомен. Если вы добавляете несколько URI перенаправления, этот URI должен быть среди них.
  </Step>

  <Step title="Скопируйте Client ID и Client Secret">
    После создания приложения поставщик покажет **Client ID** и **Client Secret**.

    * **Client ID**: публичный идентификатор вашего OAuth-приложения. Его можно безопасно указывать в URL и клиентском коде.
    * **Client Secret**: конфиденциальное значение, подтверждающее, что запрос исходит от вашего приложения. Обращайтесь с ним как с паролем — никогда не добавляйте его в репозиторий и не публикуйте. Replit надёжно хранит его от вашего имени.

    Некоторые поставщики отображают Client Secret только один раз — при создании. Сразу скопируйте его и храните в безопасном месте, пока не вставите в Replit.
  </Step>

  <Step title="Выберите области доступа">
    **Scopes** — это разрешения, определяющие, что ваше OAuth-приложение может читать или записывать от имени разработчика. Каждый поставщик публикует собственный список scopes в документации API.

    При настройке коннектора в Replit введённые scopes должны **совпадать в точности** — символ в символ, включая префиксы URL — со scopes, зарегистрированными у поставщика. Распространённые причины ошибок несоответствия:

    * Отсутствует полный префикс URL (например, `https://www.googleapis.com/auth/drive.file` вместо `drive.file`).
    * Лишние пробелы или завершающие запятые.
    * Запрошен scope в Replit, который не включён в приложении поставщика.

    Начните с минимальных scopes, необходимых вашим разработчикам, и при необходимости добавьте больше позже — большинство поставщиков позволяют обновлять scopes без повторного создания приложения.
  </Step>

  <Step title="Настройте коннектор в Replit">
    На странице **Connectors** вашей организации выберите **Add new integration**, выберите сервис и вставьте полученные от поставщика значения **Client ID**, **Client Secret** и **Scopes**. Чтобы сохранить настройки, выберите **Configure**.
  </Step>
</Steps>

<Note>
  Если после настройки аутентификация не проходит, ещё раз проверьте, что URL перенаправления у поставщика в точности совпадает с `https://replit.com/connectors/oauth/callback`, а каждый scope, введённый в Replit, также авторизован в приложении поставщика.
</Note>

<div id="reconnecting-integrations">
  ## Повторное подключение интеграций
</div>

Если подключённый сервис перестаёт работать — например, из-за истечения срока действия сеанса входа или изменения разрешений, — Replit показывает в Project Editor уведомление о необходимости повторного подключения. Выберите уведомление, чтобы повторно подключить интеграцию, не выходя из редактора.

<div id="debugging-connectors">
  ## Отладка коннекторов
</div>

Возникли проблемы с подключением сервиса? Эти руководства помогут разобраться с распространёнными ошибками и устранить их.

<AccordionGroup>
  <Accordion title="Google Workspace: &#x22;Это приложение заблокировано&#x22;">
    Если при подключении Google Drive, Docs, Sheets, Calendar или Gmail вы видите сообщение **&quot;Это приложение заблокировано&quot;**, вероятно, Google Workspace вашей организации ограничивает использование сторонних OAuth-приложений. Ознакомьтесь с подробным руководством по устранению этой неполадки.

    [Устранение ошибки «Это приложение заблокировано» для коннекторов Google](/ru/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce: &#x22;Срок действия подключения истёк&#x22;">
    Если коннектор Salesforce перестал работать с ошибкой **&quot;Срок действия подключения истёк&quot;**, вероятно, политика refresh token в вашей организации Salesforce настроена так, чтобы token истекали через определённый период. Ознакомьтесь с подробным руководством, чтобы обновить настройки Connected App.

    [Устранение ошибок истечения срока действия подключения Salesforce](/ru/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
