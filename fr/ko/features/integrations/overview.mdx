Agent prend en charge quatre types d&#39;intégrations pour passer rapidement de l&#39;idée à l&#39;application.

* **Gérées par Replit** : intégrations natives qui fonctionnent automatiquement. Dès que vous créez une application, Agent peut les utiliser.
* **Connecteurs (Connectors)** : intégrations propriétaires prises en charge par Replit. Une seule connexion suffit. Agent peut lire et écrire dans ces services directement depuis le chat — récupérer des données, créer des enregistrements, envoyer des messages — et vous pouvez vous appuyer dessus pour builder plusieurs applications.
* **Intégrations externes (External integrations)** : services tiers fiables avec lesquels vous pouvez builder. Demandez à Agent de les configurer, puis fournissez votre clé API.
* **Services Agent (Agent services)** : API tierces payantes qu&#39;Agent utilise en arrière-plan — aucune clé API n&#39;est nécessaire. L&#39;utilisation est facturée sur vos crédits Replit.

<Note>
  **Disponibilité selon le plan** : la plupart des connecteurs nécessitent un abonnement Core, Pro ou Enterprise, et certains sont également disponibles avec le plan Free. Consultez le catalogue de connecteurs de votre workspace pour voir ceux accessibles avec votre plan actuel. Les builders du plan Free peuvent utiliser à tout moment les intégrations gérées par Replit, comme les bases de données ou l&#39;authentification.
</Note>

<div id="section">
  ## Premiers pas
</div>

Pour utiliser une intégration, mentionnez le service ou la fonctionnalité dont vous avez besoin. Par exemple :

<AiPrompt>
  Crée une application web qui accepte les paiements via Stripe et envoie des e-mails de confirmation via SendGrid
</AiPrompt>

Agent détecte automatiquement ces mots-clés et implémente le code et la configuration nécessaires.

<div id="agent">
  ### Laisser Agent suggérer des connecteurs
</div>

Il arrive que plusieurs services remplissent le même rôle, par exemple pour enregistrer des fichiers ou envoyer des e-mails. Si vous demandez une fonctionnalité sans préciser de fournisseur, Agent vous présente simplement une liste de connecteurs adaptés. Choisissez celui qui vous convient.

Sélectionnez un fournisseur, puis connectez votre compte en vous authentifiant une seule fois. Agent utilise votre choix pendant le build. Pour ignorer la liste, vous pouvez aussi demander directement un service précis par son nom.

<div id="replit-oauth">
  ### Configurer une application OAuth avec Replit
</div>

<Note>
  **Enterprise uniquement** : un abonnement Enterprise est nécessaire pour configurer une application OAuth personnalisée.
</Note>

Avec le plan Enterprise, vous pouvez utiliser votre propre application OAuth pour les connecteurs à la place de celle fournie par défaut par Replit. Votre organisation peut ainsi être propriétaire du client OAuth, afficher sa propre image de marque sur l&#39;écran de consentement et contrôler précisément les portées que les builders peuvent demander.

Pour configurer un connecteur avec votre propre application OAuth, vous avez besoin de trois éléments fournis par le fournisseur : un **Client ID**, un **Client Secret** et les **portées (scopes)** que vous souhaitez autoriser. Vous devez également enregistrer l&#39;URL de rappel de Replit auprès du fournisseur afin de finaliser l&#39;authentification.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Boîte de dialogue de configuration OAuth du connecteur avec des champs Client ID, Client Secret, Connector Scopes et une Redirect URL définie sur https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Créer une application OAuth auprès du fournisseur">
    Connectez-vous à la console développeur ou aux paramètres d&#39;administration du fournisseur, puis créez une application OAuth 2.0. Le nom de cette étape varie selon le fournisseur — recherchez des options telles que **Create OAuth app**, **Register application** ou **Create client credentials**.
  </Step>

  <Step title="Définir l'URL de redirection">
    Lorsque le fournisseur demande un **Authorized redirect URI** (parfois également appelé **Callback URL** ou **Redirect URL**), saisissez l&#39;URL suivante :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    Il s&#39;agit de l&#39;URL vers laquelle le fournisseur redirige les builders vers Replit après qu&#39;ils ont autorisé l&#39;application. Elle doit correspondre exactement — la barre oblique finale, le protocole et le sous-domaine sont tous importants. Si vous ajoutez plusieurs URI de redirection, cette URL doit être incluse.
  </Step>

  <Step title="Copier le Client ID et le Client Secret">
    Une fois l&#39;application créée, le fournisseur affiche le **Client ID** et le **Client Secret**.

    * **Client ID** : l&#39;identifiant public de votre application OAuth. Vous pouvez l&#39;exposer sans risque dans des URL ou du code côté client.
    * **Client Secret** : une valeur confidentielle qui prouve que les requêtes proviennent de votre application. Traitez-la comme un mot de passe — ne l&#39;ajoutez jamais à un dépôt et ne la partagez jamais publiquement. Replit la stocke de manière sécurisée.

    Certains fournisseurs n&#39;affichent le secret client qu&#39;une seule fois, au moment de sa création. Copiez-le immédiatement et conservez-le dans un emplacement sécurisé jusqu&#39;à ce que vous le colliez dans Replit.
  </Step>

  <Step title="Sélectionner les portées">
    Les **portées (Scopes)** définissent les autorisations dont l&#39;application OAuth dispose pour lire ou écrire au nom des builders. Chaque fournisseur publie sa propre liste de portées dans sa documentation API.

    Les portées que vous saisissez lors de la configuration du connecteur dans Replit doivent correspondre **exactement** à celles enregistrées auprès du fournisseur, caractère par caractère, y compris les préfixes d&#39;URL. Les causes courantes d&#39;erreurs de non-correspondance incluent :

    * L&#39;absence du préfixe d&#39;URL complet (par exemple, `drive.file` au lieu de `https://www.googleapis.com/auth/drive.file`).
    * Des espaces supplémentaires ou des virgules finales.
    * La demande dans Replit de portées qui ne sont pas activées dans l&#39;application du fournisseur.

    Commencez par les portées minimales nécessaires aux builders, puis ajoutez-en davantage si nécessaire — la plupart des fournisseurs vous permettent de mettre à jour les portées sans recréer l&#39;application.
  </Step>

  <Step title="Configurer le connecteur dans Replit">
    Sur la page **Connectors** de votre organisation, sélectionnez **Add new integration**, choisissez le service, puis collez le **Client ID**, le **Client Secret** et les **Scopes** fournis par le fournisseur. Sélectionnez **Configure** pour enregistrer.
  </Step>
</Steps>

<Note>
  Si l&#39;authentification échoue après la configuration, vérifiez de nouveau que l&#39;URL de redirection du fournisseur correspond exactement à `https://replit.com/connectors/oauth/callback` et que toutes les portées saisies dans Replit sont également autorisées dans l&#39;application du fournisseur.
</Note>

<div id="section-9">
  ## Reconnecter une intégration
</div>

Lorsqu&#39;un service connecté cesse de fonctionner, par exemple parce que la session de connexion a expiré ou que les autorisations ont changé, Replit affiche une notification de reconnexion dans le Project Editor. Sélectionnez cette notification pour reconnecter aussitôt l&#39;intégration sans quitter l&#39;éditeur.

Pour savoir comment mettre à jour les paramètres de la Connected App, consultez le guide de dépannage complet.
