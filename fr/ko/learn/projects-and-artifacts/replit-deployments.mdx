Grâce à Publishing, partagez facilement votre application Replit avec le monde entier.

<Note>
  L’action de rendre une application accessible au public s’appelle « Publishing ». Cette page présente les différents types de déploiement disponibles.
</Note>

<div id="section">
  ## Qu’est-ce que Publishing ?
</div>

Publishing est une fonctionnalité qui enregistre un **instantané** de votre application Replit dans le cloud, afin que chacun puisse interagir avec elle. Un instantané capture l’état actuel des fichiers de votre application Replit.

Lorsque vous publiez une application Replit, une **application publiée** est créée. Une application publiée est une instance de votre application qui s’exécute sur l’infrastructure cloud de Replit. Votre application devient ainsi fiable et accessible sur Internet, indépendamment de la version dans le Project Editor.

<Info>
  L’infrastructure de Replit repose sur Google Cloud Platform (GCP). Toutes les
  applications publiées sont hébergées aux États-Unis. Les clients Enterprise peuvent
  contacter l’équipe commerciale pour demander l’hébergement de leurs applications publiées dans l’Union européenne.

  Tous les particuliers, organisations et entreprises bénéficient d’un projet GCP
  dédié et monolocataire pour leurs applications publiées. Cela signifie que les ressources de calcul,
  les secrets et le stockage de vos applications publiées sont entièrement isolés et ne sont pas partagés avec les applications d’autres clients.
</Info>

Publishing inclut des outils permettant de surveiller l’état des applications publiées et de consulter les analyses web.

<div id="section-2">
  ## Premiers pas
</div>

Pour publier une application Replit, suivez ces étapes :

1. Dans le Project Editor, sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="icône de publication" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publier** en haut de la page.
2. Dans l’onglet **Publishing**, choisissez une option de publication.
3. Si **Ajouter un moyen de paiement** s’affiche, suivez les instructions pour ajouter un moyen de paiement.

Replit sélectionne automatiquement l’option de publication la mieux adaptée à votre application en fonction du type et des besoins de votre projet.

Toutefois, si vous souhaitez choisir un autre type de déploiement, consultez les informations ci-dessous.

<div id="section-4">
  ## Fonctionnalités clés
</div>

Publishing offre les fonctionnalités pratiques suivantes :

* **Diverses options de publication** : sélectionnez ou mettez à jour le type de déploiement adapté à vos besoins en quelques clics.
* **Domaines personnalisés** : publiez votre application sur votre propre domaine web.
* **Analyses** : suivez les données des visiteurs et d’autres indicateurs de vos applications publiées.
* **Outils de surveillance** : vérifiez l’état et la configuration de vos applications publiées.
* **Contrôle d’accès** : contrôlez en un clic qui peut voir votre application. Disponible uniquement pour les membres **Pro** et **Enterprise**.
* **Paramètres du badge** : les utilisateurs Core peuvent gérer le badge « Made with Replit » dans les paramètres de Publishing. Si vous avez publié une application avec ce badge avec le plan Starter, sa suppression peut prendre quelques minutes après la mise à niveau.
* **Collecte de commentaires** : activez les commentaires dans les applications publiées afin de recueillir les avis des utilisateurs.

<div id="section-5">
  ## Fonctionnement
</div>

Lorsque vous publiez une application Replit, Replit crée un instantané des fichiers et des dépendances de l’application.
Cet instantané est envoyé vers l’infrastructure cloud de Replit, où il s’exécute comme une instance distincte de l’application.
Pour mettre à jour une application publiée avec les dernières modifications, publiez-la à nouveau afin de créer un nouvel instantané.

<Warning>
  N’écrivez pas de données dans le système de fichiers d’une application publiée et ne vous y fiez pas pour les stocker. Pour stocker des données, utilisez une option de stockage ou de base de données, comme le [stockage et les bases de données](/fr/ko/learn/projects-and-artifacts/storage-and-databases) de Replit.
</Warning>

<div id="section-6">
  ## Cas d’utilisation
</div>

Les exemples suivants présentent différents types d’applications publiées.

<div id="autoscale">
  ### Déploiement Autoscale : application de test de vitesse de frappe
</div>

Utilisez le cloud pour augmenter les ressources lorsque les utilisateurs effectuent un test de frappe et les réduire lorsqu’ils ne l’utilisent pas.

<div id="static">
  ### Déploiement statique : simulation du système solaire
</div>

Découvrez les planètes avec cette application Web de visualisation du système solaire.
Cette visualisation est affichée dans le navigateur et n’envoie aucune donnée saisie par l’utilisateur au serveur.

<div id="reserved-vm-discord">
  ### déploiement Reserved VM : bot Discord
</div>

Exécutez un bot Discord pour modérer et accueillir les membres.
Toujours en ligne, il échange avec les utilisateurs et répond aux commandes, avec un prix et des performances prévisibles.

<div id="scheduled">
  ### Déploiement planifié : déclencheur d&#39;automatisation domestique
</div>

Programmez des appels d’API pour démarrer et arrêter des appareils domotiques à des heures et dates précises.
