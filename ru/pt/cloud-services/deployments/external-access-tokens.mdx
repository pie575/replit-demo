---
title: "Токены внешнего доступа"
description: "Разрешите CI-конвейерам, вебхукам и другим автоматизированным сервисам получать доступ к вашему приватному Replit App без входа в систему."
---

Токены внешнего доступа — это bearer-токены, которые вы создаёте для конкретного Replit App.
Они позволяют автоматизированным сервисам — CI-конвейерам, вебхукам, проверкам доступности, ботам Slack,
внутренним скриптам — получать доступ к приложению, даже если его URL защищён
[приватным URL для разработки](/ru/pt/cloud-services/deployments/private-deployments)
или [Private Deployment](/ru/pt/cloud-services/deployments/private-deployments).

Обращайтесь с каждым токеном как с паролем: любой, у кого он есть, может получить доступ к вашему приложению, пока срок действия токена не истечёт или он не будет отозван.

<Note>
  Токены внешнего доступа доступны на тарифах Replit Core и Pro.
  Клиенты Enterprise должны запросить подключение к Replit, прежде чем эта функция будет
  включена для workspace. Токены появляются в настройках публикации
  только после того, как deployment станет приватным.
</Note>

<div id="quando-usar-um-token">
  ## Когда использовать токен
</div>

Используйте внешний токен доступа, если вашему частному Replit App требуется вызов откуда-то *за пределами* браузера. Типичные случаи:

* Workflow GitHub Actions, который запускает smoke-тест URL вашей среды разработки при каждом коммите.
* Сервис мониторинга доступности (Better Stack, Pingdom, UptimeRobot), обращающийся к эндпоинту проверки состояния опубликованного приложения.
* Получатель вебхука — Stripe, Slack, GitHub — отправляющий POST-запрос в Private Deployment.
* Вызов `curl` или `fetch` с машины коллеги во время отладки.

Внешние токены доступа предназначены для **API-трафика**, а не для открытия страниц интерфейса в браузере. Одностраничные приложения (Vite, Next.js и т. д.) загружают бандлы JavaScript в последующих запросах, в которых ваш токен не передаётся, поэтому такие запросы завершатся ошибкой. Для интерактивной работы в браузере войдите в систему обычным способом.

<div id="ambientes-de-tokens">
  ## Окружения токенов
</div>

Каждый токен привязан к определённому окружению:

| Окружение     | Где работает                                                                    | Использование                                   |
| :------------ | :------------------------------------------------------------------------------ | :---------------------------------------------- |
| `Development` | URL среды разработки workspace приложения (`*.replit.dev`)                      | Доступ к запущенному Repl во время разработки   |
| `Production`  | опубликованный deployment приложения (`*.replit.app` и пользовательские домены) | Доступ к Private Deployment из внешних сервисов |

Токен `Production` привязан к *текущему опубликованному* deployment. Если вы
опубликуете приложение в новом deployment, существующие production-токены перестанут работать,
и вам потребуется создать новые.

<div id="criar-um-token-de-acesso-externo">
  ## Создание токена внешнего доступа
</div>

<Steps>
  <Step>
    Откройте App, к которому хотите предоставить внешний доступ, затем откройте инструмент **Publishing**.
  </Step>

  <Step>
    Выберите **Adjust settings**, чтобы развернуть настройки повторной публикации.
  </Step>

  <Step>
    В разделе **Security** найдите **External access tokens**.
  </Step>

  <Step>
    Выберите **Create access token** и заполните:

    * **Label** (необязательно): короткое название, чтобы позже идентифицировать токен,
      например `CI` или `Stripe вебхук`. Не более 120 символов.
    * **Environment**: выберите `Development` или `Production` в зависимости от того,
      из какой среды вызывающему сервису нужен доступ к App.
    * **Expires after**: выберите срок действия — `1 hour`, `24 hours`, `7 days`,
      `30 days`, `3 months`, `1 year` или `5 years`. Выберите минимальный срок,
      соответствующий вашим потребностям. Вариант «никогда не истекает» отсутствует.
  </Step>

  <Step>
    Выберите **Create**.
  </Step>
</Steps>

Replit отображает токен **только один раз**. Скопируйте его сейчас: после закрытия диалогового окна просмотреть токен повторно будет нельзя. Если вы его потеряете, отзовите этот токен и создайте новый.

На экране доступны два варианта копирования:

* **Copy query parameter** — копирует `?project-protection-bypass=<token>` для
  добавления к URL. Полезно для быстрой проверки с помощью `curl`.
* **Copy token only** — копирует сам токен, который можно передать в
  заголовке `Authorization: Bearer`.

<Info>
  Создание первого токена автоматически включает внешний доступ для App, если
  он ещё не включён. Без защиты токену было бы нечего обходить.
</Info>

<div id="usar-um-token">
  ## Использование токена
</div>

Предоставьте токен одним из двух способов:

<div id="cabealho-authorization-recomendado">
  ### Заголовок Authorization (рекомендуется)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

Это оптимальный вариант почти для всего — вебхуков, CI-скриптов
и межсерверных вызовов. Токен никогда не попадёт в логи, фиксирующие URL,
и не будет сохранён в истории браузера.

<div id="parmetro-de-consulta">
  ### Параметр запроса
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

Используйте параметр запроса только в случаях, когда задать заголовки невозможно, например в
сервисе, принимающем только URL. URL с токеном часто попадают в logs прокси,
историю Shell и capturas de tela, поэтому по возможности используйте заголовок.

<div id="gerenciar-tokens-existentes">
  ## Управление существующими токенами
</div>

В разделе **External access tokens** перечислены все токены, созданные вами для
App, — от новых к старым — с указанием метки, среды, даты создания,
срока действия и статуса отзыва. В каждой строке отображаются последние символы токена,
чтобы их было проще различать, поскольку полное значение показывается
только при создании.

Вы видите только те токены, которые создали *вы*. Токены других участников остаются
для них недоступными, даже если вы являетесь владельцем App.

<div id="revogar-um-token">
  ## Отзыв токена
</div>

Отзовите токен, когда он больше не нужен или если подозреваете, что он мог быть скомпрометирован. Для этого:

<Steps>
  <Step>
    Откройте раздел **External access tokens** в настройках публикации App.
  </Step>

  <Step>
    Найдите токен в списке и нажмите значок корзины.
  </Step>

  <Step>
    Подтвердите отзыв.
  </Step>
</Steps>

Отзыв происходит **немедленно и необратимо**. Любой трафик, по-прежнему использующий
токен, будет отклонён в течение нескольких секунд. Если доступ снова понадобится, создайте новый
токен.

Вы можете отозвать только созданные вами токены. Удаление участника из
workspace автоматически отзывает токены, созданные им для этого App.

<div id="mantenha-seus-tokens-seguros">
  ## Храните токены в безопасности
</div>

Токены внешнего доступа — это учётные данные. Обращайтесь с ними так же
осторожно, как с ключом API или паролем.

<div id="o-que-fazer">
  ### Что делать
</div>

* **Храните токены в безопасном хранилище** — в Secrets GitHub Actions, хранилище вашего
  CI-провайдера, хранилище secrets облачного провайдера или менеджере паролей.
  Никогда не коммитьте их в репозиторий.
* **Используйте короткие сроки действия**, когда это возможно. Токен на 7 дней для
  разовой интеграции безопаснее, чем токен на 5 лет, оставленный без присмотра.
* **Присваивайте каждому токену метку**, чтобы понимать, для чего он нужен и используется ли до сих пор. Токены без меток первыми утекают и последними отзываются.
* **Создавайте отдельный токен для каждого потребителя.** Один токен для каждой задачи CI, один для
  каждого источника вебхука, один для проверки доступности. Если что-то будет скомпрометировано — или
  поставщик больше не потребуется — вы отзовёте только этот токен.
* **Предпочитайте заголовок `Authorization`** параметрам запроса, чтобы токен не
  утёк через URL-логи, историю браузера или заголовки Referer.
* **Немедленно отзывайте токен**, если он мог быть раскрыт — из-за утечки логов,
  коммита в публичный репозиторий, записи экрана или ноутбука бывшего сотрудника.
  Отзыв вступает в силу сразу; затем создайте замену.

<div id="o-que-no-fazer">
  ### Чего не следует делать
</div>

* **Не предоставляйте один токен нескольким коллегам или сервисам.** Если две системы используют
  один токен, вы не сможете отозвать его у одной, не нарушив работу другой.
* **Не вставляйте токены в чаты, электронные письма, скриншоты или трекеры задач.**
  Эти каналы архивируются, индексируются и могут быть переданы другим способами, которые невозможно предвидеть.
* **Не встраивайте токены в клиентский код** — браузерные приложения, мобильные приложения,
  приложения для настольных компьютеров. Всё, что передаётся на устройство пользователя, следует считать общедоступным.
* **Не используйте токены для сеансов в браузере.** Токены предназначены для вызовов API,
  а не для загрузки SPA на вкладке браузера. Для этого используйте обычный вход в Replit.
* **Не устанавливайте срок действия 5 лет по умолчанию.** Устанавливайте срок действия в зависимости от того,
  как долго потребителю действительно нужен доступ.

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

<Accordion title="Мой токен для production внезапно перестал работать">
  Токены для production привязаны к конкретному опубликованному deployment. Если вы
  повторно опубликовали приложение — например, изменив тип deployment или
  удалив и создав deployment заново, — существующие токены для production будут
  аннулированы. Создайте новый токен в настройках нового deployment.
</Accordion>

<Accordion title="Мой токен работает с `curl`, но браузер по-прежнему показывает страницу входа">
  Токены внешнего доступа предназначены для API-трафика, а не для сеансов в браузере. Когда одностраничное приложение загружается в браузере, первоначальный HTML-запрос может передать токен через параметр запроса, но последующие запросы JavaScript-бандлов, CSS и вызовы API не будут его включать и будут отклонены. Чтобы интерактивно работать с приложением, войдите в Replit обычным способом.
</Accordion>

<Accordion title="Я потерял токен — можно ли посмотреть его снова?">
  Нет. Replit показывает токен только один раз — в момент создания. В списке отображаются
  метаданные (метка, среда, срок действия, последние символы), но не полное значение токена. Если вы его потеряли, отзовите этот токен и создайте новый.
</Accordion>
