由于 Replit 在云环境中运行项目，端口的工作方式与本地计算机不同。 (如果你想先了解 TCP 端口的基本概念，请[从这里开始](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/)。) 

在计算机上，端口管理只有一个层级。也就是说，程序指定要监听的端口后，从互联网进入该计算机相应端口的流量会被路由到对应的进程。

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="计算机" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` 是地址，也就是主机。进程监听 `0.0.0.0` 意味着它会监听所有网络接口。换句话说，如果其他计算机通过互联网向你计算机的 IP 地址发送请求，进程就能接收到该请求。因此，监听 0.0.0.0 意味着，只要计算机已连接到互联网，该进程就能从公网访问。

大多数编程框架在开发时*不会*监听 `0.0.0.0`。这是因为出于隐私和安全考虑，你未必希望将正在开发的内容暴露给外部。它们会改为监听另一个地址 `127.0.0.1`，通常称为 `localhost`。这意味着只有同一台计算机才能向该端口发送请求。

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="localhost 端口仅对托管它的计算机可见。" width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

在 Replit 中，要让正在运行的进程能够通过网页视图或外部请求访问，必须定义**外部端口**。这是因为进程通常使用的“内部端口”仅在 Replit 提供的沙盒云环境中可见。要将正确的流量传递给程序，必须将该内部端口连接到可从外部访问的端口。即使进程监听的是通常会暴露到公网的地址 (如 0.0.0.0) ，仍必须绑定到外部端口。

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="外部端口会将流量传递到程序正在监听的内部端口。" width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit 通过将外部端口绑定到特定的内部端口来实现这一点。例如，在上图中，外部端口 `:80` 绑定到内部端口 `:3000`。这意味着该 Replit App 在端口 80 接收的所有流量都会被转发到内部端口 3000。

此配置记录在 .replit 配置文件的 [[ports]] 部分。

默认情况下，Replit 会将第一个打开的端口绑定到默认外部端口 80，这样你便可通过域名访问该进程，而无需指定端口号 (例如，使用 customdomain.com/ 而非 customdomain.com:3000/) 。之后打开的其他内部端口会绑定到其他可用的外部端口 (完整列表请参阅下文) 。

<div id="section-2">
  ## 默认端口
</div>

端口 :80 是 HTTP 流量的“默认端口”，因此发送到根域名的 HTTP 流量会自动路由到端口 80。正因如此，URL 中不会显示端口 80。除 :`80` 外，其他端口会显示在域名中 (例如 customdomain.com:4200/) 。 (Replit 默认提供 TLS，因此实际流量会通过 HTTPS 的默认端口 443 传输。实际上，可以认为这两个端口可以互换使用。)

<div id="section-4">
  ## 发布
</div>

Autoscale 和 Reserved VM 部署仅支持暴露一个外部端口，且相应的内部端口不能使用 `localhost`。暴露多个端口，或在 localhost 上暴露单个端口，都会导致已发布的应用无法正常运行。为确保 Autoscale 部署按预期运行，可从配置中移除除需通过互联网访问的服务端口外的所有 `externalPort` 条目。

<div id="section-5">
  ## 调试
</div>

程序未按预期运行的常见原因之一是：端口配置看似正确，但程序实际上监听的是其他端口。例如，配置如下：

```
[[ports]]
internalPort = 3000
externalPort = 80
```

来自互联网的端口 80 流量会被转发到内部端口 3000。但是，如果程序实际监听的是其他端口 (例如 8080) ，而不是端口 3000，流量就会看起来完全无法通过。这可能是因为你在代码中更改了端口，却没有同时更新配置中的对应端口；也可能是将一个项目的配置复制并粘贴到了另一个项目中。

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="程序可能会更改其监听的端口。" width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

不同框架默认监听的端口各不相同。例如，Flask 默认使用 5000，React 默认使用 3000，Laravel 默认使用 8000。请确认配置的是正确端口！

<div id="section-6">
  ## 配置
</div>

当 Replit App 中的端口打开时，Replit 会自动绑定到可用的外部端口，并将该绑定记录在 `.replit` 配置文件中。

但默认不会对 localhost 上打开的内部端口执行此操作，因为通常认为在 localhost 上运行的服务只能从运行该进程的同一台计算机访问 (localhost 端口只能在运行该进程的计算机上访问) 。也就是说，这类服务的安全性通常低于专为暴露在公共互联网中而设计的服务。

你可以随时将想要暴露的端口的 `exposeLocalhost` 配置选项设为 `true`，以覆盖此行为。

如果你希望默认*始终*暴露 localhost 端口，可以在用户设置中将“自动端口转发”设为“所有端口”。

如果你*绝不*希望为打开的端口自动创建配置，并希望自行管理 Replit App 的所有端口配置，可以将其设为“无”。

<div id="section-7">
  ## 支持的端口
</div>

第一个端口打开时，Replit App 默认将端口 80 设为外部端口。Replit App 还可将 3000、3001、3002、3003、4200、5000、5173、6000、6800、8000、8008、8080 和 8081 暴露为额外的外部端口。

端口 22 和 8283 用于内部用途，无法转发。

<div id="ports-replit">
  ## `[[ports]]` .replit 配置
</div>

类型：`{localPort, externalPort, exposeLocalhost}`

使用 `[[ports]]` 配置可设置要在 Web 输出中暴露的 HTTP 端口。默认情况下，所有主机为 0.0.0.0 的暴露 HTTP 端口都会显示在 Replit App 的 Web 输出中。

如需在不覆盖默认端口的情况下提供额外端口，请在 .replit 文件中添加新的 [[ports]] 条目。必须同时指定 localPort 和 externalPort 条目。您可以按如下定义，在 .replit 文件中添加多个 [[ports]] 条目，以提供多个额外端口。

<div id="localport">
  ### localPort
</div>

指定 Replit 要绑定到外部端口的端口。

<div id="externalport">
  ### externalPort
</div>

指定要为此本地端口公开的公网访问端口。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

如果您*绝不*希望暴露某个端口，请保留 `localPort` 配置，不要添加 `externalPort`。

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

指定是否可将使用 `localhost` 的内部端口绑定到外部端口。可设为 `true`、`false` 或 null。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
