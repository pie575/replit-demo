Панель Git в Replit предоставляет визуальный интерфейс для работы с Git — без команд в командной строке. Благодаря этому контроль версий становится доступным даже новичкам, оставаясь при этом мощным инструментом для опытных разработчиков.

<div id="section">
  ## Возможности
</div>

Панель Git предоставляет полноценные средства контроля версий прямо в Project Editor, а её удобный интерфейс упрощает сложные операции Git.

* **Управление репозиториями**: инициализация, подключение и управление репозиториями Git через интеграцию с GitHub
* **Отслеживание коммитов**: добавление в индекс, коммит и просмотр изменений во всех файлах
* **Работа с ветками**: наглядное создание, переключение и слияние веток
* **Разрешение конфликтов**: выявление и устранение конфликтов слияния с наглядными подсказками
* **Интеграция с Shell**: синхронизация команд Git, выполненных в Shell, с панелью Git

<div id="section-2">
  ## Использование
</div>

<div id="section-3">
  ### Настройка репозитория
</div>

<Accordion title="Как открыть панель Git">
  1. В Replit App перейдите в раздел Tools
  2. Нажмите значок **+**, чтобы добавить новый инструмент
  3. Выберите **Git** из списка доступных инструментов
</Accordion>

Панель Git помогает настраивать и подключать репозитории:

* **Инициализация репозитория**: создайте новый Git-репозиторий для вашего Replit App
* **Подключение к Git-провайдеру**: подключите репозиторий к поддерживаемому облачному или самостоятельно развёрнутому провайдеру для резервного копирования и совместной работы
* **Настройка удалённых репозиториев**: настройте подключения к удалённым репозиториям и управляйте ими

<Note>
  **Поддержка самостоятельно развёрнутого Git**: Replit поддерживает GitHub Enterprise Server, GitLab Self-Managed и Bitbucket Data Center в тарифе Enterprise. Если вам нужны инструкции по подключению, настройке провайдера или устранению неполадок с подключением, [обратитесь в отдел продаж Replit](https://replit.com/enterprise). Также можно [настроить удалённые репозитории с помощью команд Git в Shell](#using-git-commands-in-shell).
</Note>

<div id="section-4">
  ### Управление изменениями
</div>

<Accordion title="Как просмотреть изменения">
  1. Измените файлы в Replit App
  2. Откройте панель Git в разделе Tools
  3. Просмотрите изменения в разделе **Review Changes**
</Accordion>

Панель Git содержит инструменты для управления изменениями в коде:

* **Проверка изменений**: просматривайте изменённые файлы с выделенными добавлениями и удалениями
* **Добавление файлов в индекс**: выбирайте файлы, которые нужно включить в следующий коммит
* **Коммит изменений**: сохраняйте изменения с понятным сообщением
* **Отправка обновлений**: отправляйте коммиты в удалённый репозиторий одним нажатием

<Note>

<div id="section-5">
  ### Управление ветками
</div>

<Accordion title="Как управлять ветками">
  1. Откройте панель Git в разделе Tools
  2. Нажмите на раскрывающийся список веток рядом с именем ветки
  3. Создайте новую ветку или выберите существующую
</Accordion>

Панель Git упрощает работу с разными версиями кода:

* **Создание ветки**: создайте новую ветку, чтобы разрабатывать функцию отдельно
* **Переключение веток**: переходите между разными версиями кода
* **Публикация ветки**: поделитесь веткой с вашим Git-провайдером
* **Получение изменений**: синхронизируйтесь с удалёнными обновлениями от соавторов

<div id="section-6">
  ### Разрешение конфликтов слияния
</div>

<Accordion title="Как разрешить конфликты слияния">
  1. При наличии конфликтов попробуйте получить изменения
  2. Панель Git подсветит конфликтующие файлы
  3. Откройте каждый конфликтующий файл, изучите и разрешите конфликты
  4. После разрешения конфликтов сохраните файл
  5. Выберите **Pull**, чтобы завершить слияние
</Accordion>

Когда код из разных источников конфликтует, панель Git помогает:

* **Определить конфликты**: точно увидеть, в каких файлах есть конфликты
* **Наглядно сравнить различия**: изучить обе версии конфликтующего кода
* **Устранить проблемы**: выбрать, какой код оставить, или отредактировать конфликты вручную
* **Завершить слияние**: довести процесс слияния до конца после устранения конфликтов

<Frame>
  <img src="/assets/mirror/11-merge-conflict-17b314f0e231.png" alt="Редактор кода с маркерами конфликта слияния" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

Разрешив конфликт в файле, удалите маркеры конфликта — то есть строки, начинающиеся с символов конфликта, — и сохраните файл.

<div id="shell-git">
  ### Использование команд Git в Shell
</div>

<Accordion title="Как открыть Shell">
  1. На панели инструментов слева выберите **Все инструменты**
  2. Среди доступных инструментов выберите **Shell**
</Accordion>

<Tip>
  Панель Git предлагает удобный интерфейс, но опытные пользователи могут выполнять стандартные команды Git в Shell для более сложных задач. Изменения, внесённые любым из способов, отражаются в обоих.
</Tip>

Если вы предпочитаете работать с Git через командную строку:

* **Синхронизация команд**: все команды Git, выполненные в Shell, автоматически синхронизируются с панелью Git
* **Полные возможности Git**: доступ к продвинутым функциям Git, недоступным в панели Git
* **Плавное переключение**: переключайтесь между командами Shell и панелью Git по мере необходимости

<Info>
  **Поддержка GitHub и GitLab CLI**: помимо стандартных команд Git, в Shell можно использовать [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) и [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) для управления внешними репозиториями Git и подключения к ним. Эти инструменты расширяют возможности работы с репозиториями GitHub и GitLab: пул-реквесты, задачи и многое другое.
</Info>

<div id="section-7">
  #### Работа с репозиториями
</div>

* **Клонирование репозитория**: `git clone <url-to-repository>`
* **Инициализация репозитория**: `git init`
* **Добавление удалённого репозитория**: `git remote add origin <url-to-repository>`

<div id="section-8">
  #### Внесение изменений
</div>

* **Проверка статуса**: `git status` (показывает изменённые, добавленные и удалённые файлы)
* **Добавление файлов в индекс**: `git add <filename>` или `git add .` (все файлы)
* **Коммит изменений**: `git commit -m "your commit message"`
* **Отправка изменений**: `git push origin <branch-name>`
* **Получение изменений**: `git pull origin <branch-name>`

<div id="section-9">
  #### Аутентификация
</div>

При работе с приватными репозиториями требуется аутентификация:

* Для репозиториев GitHub.com используйте персональный токен доступа вместо пароля
* Чтобы не вводить учётные данные каждый раз, сохраните их в Replit Secrets:
  1. Создайте новый секрет с ключом `GIT_URL`
  2. Укажите значение `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Для отправки изменений без ввода учётных данных используйте `git push $GIT_URL`

<Note>
  Если хранить учётные данные в секрете, доступ к вашим учётным данным Git получит любой, у кого есть доступ к Replit App. Для репозиториев с конфиденциальными данными лучше вводить учётные данные вручную каждый раз.
</Note>
