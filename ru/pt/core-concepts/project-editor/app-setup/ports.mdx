Поскольку Replit запускает ваши проекты в облачной среде, порты в Replit работают иначе, чем на локальном компьютере. (Если вам нужно более простое объяснение того, что такое TCP-порты, [начните здесь](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

На компьютере есть только один уровень управления портами: программы назначают порт, который они прослушивают, и когда интернет-трафик поступает на этот порт, он направляется соответствующему процессу.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="компьютер" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` — это адрес, или хост. Если процесс прослушивает `0.0.0.0`, это означает, что он должен прослушивать все сетевые интерфейсы. То есть, если другой компьютер в интернете отправит запрос на IP-адрес вашего компьютера, процесс его получит. Таким образом, прослушивание на `0.0.0.0` означает, что эти процессы доступны из публичного интернета, если компьютер подключён к сети.

Большинство фреймворков *не* прослушивают `0.0.0.0` во время разработки, поскольку вы не всегда хотите открывать свою работу для общего доступа, пока работаете над ней, из соображений конфиденциальности и безопасности. Вместо этого они прослушивают другой адрес — `127.0.0.1`, также известный как `localhost`. Это означает, что отправлять запросы на этот порт может только этот компьютер.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Порты localhost видны только на компьютере, на котором они размещены." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

В Replit, чтобы запущенный процесс был доступен в веб-просмотре или через внешний запрос, для него должен быть задан **внешний порт**. Это связано с тем, что «внутренний порт», который обычно используют процессы, виден только внутри изолированной облачной среды Replit. Чтобы направлять нужный трафик вашим программам, внутренний порт необходимо связать с внешним доступным портом. Даже если процесс прослушивает обычно общедоступный адрес, такой как `0.0.0.0`, его всё равно нужно связать с внешним портом.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Внешние порты перенаправляют трафик на внутренние порты, где программы ожидают соединений." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit делает это, связывая внешние порты с конкретными внутренними портами. Например, на диаграмме выше внешний порт `:80` связан с внутренним портом `:3000`. Это означает, что весь трафик, полученный Replit App на порту 80, будет направлен на внутренний порт 3000.

Эта конфигурация записывается в разделе [[ports]] файла конфигурации .replit.

По умолчанию Replit связывает первый открытый порт с внешним портом по умолчанию 80, благодаря чему этот процесс доступен по домену без указания номера порта (например, customdomain.com/ вместо customdomain.com:3000/). Другие открытые внутренние порты связываются с другими доступными внешними портами (см. полный список ниже).

<div id="porta-padro">
  ## Стандартный порт
</div>

Порт :80 — стандартный порт для HTTP-трафика, поэтому HTTP-трафик, отправляемый на корневой домен, автоматически направляется на порт 80. Поэтому номер порта 80 не отображается в URL. Порты, отличные от `:80`, указываются в адресе домена (например, customdomain.com:4200/). (Replit по умолчанию предоставляет TLS, поэтому технически будет использоваться порт 443 — стандартный порт для HTTPS. На практике их можно считать взаимозаменяемыми.)

<div id="publicao">
  ## Публикация
</div>

Деплои Autoscale и Reserved VM поддерживают только один открытый внешний порт, при этом соответствующий внутренний порт не должен использовать `localhost`. Если открыть больше портов или открыть один порт на localhost, опубликованное приложение завершится с ошибкой. Чтобы деплои Autoscale работали корректно, удалите из конфигурации все записи `externalPort` для портов, *кроме* порта сервиса, к которому вы хотите обращаться через интернет.

<div id="depurao">
  ## Отладка
</div>

Распространённая причина неполадок — программа использует другой порт, хотя настройки порта кажутся правильными. Например, если ваша конфигурация выглядит так:

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Таким образом, интернет-трафик, поступающий на порт 80, будет перенаправляться на внутренний порт 3000. Однако если ваша программа на самом деле прослушивает не порт 3000, а другой порт (например, 8080), может показаться, что трафик вообще не поступает. Это может произойти, если вы измените порт в коде, но не измените соответствующий порт в конфигурации, или если скопируете конфигурацию из одного проекта в другой.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Программы могут изменять порты, которые они прослушивают." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

У каждого фреймворка свой порт по умолчанию — например, Flask использует 5000, React — 3000, а Laravel — 8000. Убедитесь, что настроен правильный порт!

<div id="preferncias">
  ## Предпочтения
</div>

При открытии портов в вашем Replit App Replit автоматически связывает их с доступными внешними портами и записывает эту связь в файл конфигурации .replit.

Однако для внутренних портов, открывающихся на localhost, это по умолчанию не происходит: службы, которые обычно работают на localhost, как правило, предполагают, что будут доступны только на том же компьютере, где запущен процесс (порты localhost видны только этому компьютеру). Это означает, что такие службы обычно менее безопасны, чем службы, разработанные с расчётом на доступ из публичного интернета.

Вы всегда можете изменить это поведение, задав для нужного порта параметру конфигурации `exposeLocalhost` значение `true`.

Если вы хотите *всегда* по умолчанию открывать порты localhost, в разделе Пользовательские настройки установите для параметра «автоматическое перенаправление портов» значение «All ports».

Если вы хотите *никогда* не создавать конфигурацию для открываемых портов и вручную управлять конфигурацией портов во всех ваших Replit App, установите для этого параметра значение «never».

<div id="portas-suportadas">
  ## Поддерживаемые порты
</div>

При открытии первого порта Replit App назначает порт 80 внешним портом по умолчанию. Replit App может предоставлять доступ к портам 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080, 8081 в качестве дополнительных внешних портов.

Порты 22 и 8283 нельзя перенаправлять, так как они используются внутри системы.

<div id="configurao-ports-do-replit">
  ## Конфигурация `[[ports]]` в .replit
</div>

Тип: `{localPort, externalPort, exposeLocalhost}`

Конфигурация `[[ports]]` позволяет указать, какой HTTP-порт следует открыть для веб-вывода вашего приложения. По умолчанию любой HTTP-порт, открытый на хосте 0.0.0.0, будет доступен как веб-вывод вашего Replit App.

Дополнительные порты можно обслуживать, не заменяя порт по умолчанию, добавив в файл .replit новую запись [[ports]]. Необходимо указать как `localPort`, так и `externalPort`. Вы можете добавить несколько дополнительных портов, включив в файл .replit несколько записей [[ports]], как описано ниже.

<div id="localport">
  ### localPort
</div>

Определяет, какой порт Replit будет сопоставлен с внешним портом.

<div id="externalport">
  ### externalPort
</div>

Определяет, какой локальный порт будет доступен извне.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Если вы хотите *никогда* не делать определённый порт доступным извне, можно оставить настройку `localPort`, не добавляя `externalPort`:

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Определяет, можно ли сопоставить внутренний порт, использующий `localhost`, с внешним портом. Может иметь значение `true`, `false` или null.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
