Replit은 손상된 `.git` 폴더나 유실된 commit history 같은 문제에서 복구할 수 있도록 Git 저장소를 자동으로 백업합니다. 이 백업 시스템은 백그라운드에서 실행되므로 별도의 조치 없이도 작업이 보호됩니다.

<div id="how-it-works">
  ## 작동 방식
</div>

모든 Replit App은 Git 저장소의 안전한 백업을 유지합니다. Replit Agent가 코드를 변경하거나 사용자가 앱을 게시하면 그 내용이 이 백업으로 자동 동기화됩니다. 로컬 Git 저장소가 손상되거나 사용할 수 없게 되더라도 백업에서 전체 commit history를 복원할 수 있습니다.

<Info>
  backup remote의 이름은 `gitsafe-backup`이며 Replit이 자동으로 관리합니다. 따로 설정할 필요 없이 이미 백그라운드에서 작동하고 있습니다.
</Info>

<div id="viewing-your-backup-history">
  ## 백업 기록 보기
</div>

commit history를 확인하는 가장 쉬운 방법은 [Git pane](/ko/features/workspace-tools/git-interface)을 이용하는 것입니다. Project Editor의 Tools section에서 열면 모든 Agent checkpoints를 포함한 전체 commit history를 볼 수 있습니다. 대부분의 경우 이 방법이면 충분하며, 별도의 명령어도 필요하지 않습니다.

gitsafe-backup remote를 직접 확인해야 한다면 Shell을 사용하세요:

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

모든 Agent checkpoint와 수동 commit을 포함한 전체 commit history가 표시됩니다. 이를 통해 작업이 제대로 백업되었는지 확인하거나 복원할 특정 commit을 찾을 수 있습니다.

<div id="recovering-from-git-issues">
  ## Git 문제 복구하기
</div>

Git 오류가 발생하거나 저장소가 손상된 경우 먼저 [Git pane](/ko/features/workspace-tools/git-interface)을 확인하세요. 이전 commit으로 되돌리거나 remote에서 pull하는 등 대부분의 일반적인 문제는 Shell 명령 없이도 해결할 수 있습니다.

Git pane으로 해결할 수 없는 경우(예: `.git` 폴더가 완전히 손상된 경우)에는 아래의 Shell 기반 단계를 따르세요.

<div id="check-if-backup-is-available">
  ### 백업 사용 가능 여부 확인
</div>

먼저 backup remote가 존재하는지 확인하세요:

```bash theme={null}
git remote -v
```

출력에서 `gitsafe-backup`이 있는지 확인하세요. 있다면 복구를 진행할 수 있습니다.

<div id="restore-your-repository">
  ### 저장소 복원하기
</div>

<Warning>
  이 과정에서는 현재 `.git` 폴더가 백업된 버전으로 교체됩니다. 작업 파일은 그대로 유지되지만, 로컬 Git 기록은 백업 내용으로 대체됩니다.
</Warning>

<Steps>
  <Step title="현재 Git 설정 저장하기">
    사용자 지정 설정이 있는 경우를 대비해 Git config 파일을 백업합니다:

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="백업 저장소 복제하기">
    백업에서 임시 복제본을 만듭니다:

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Git 폴더 교체하기">
    손상된 `.git` 폴더의 이름을 바꿔 옮긴 뒤 백업으로 교체합니다:

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="설정 복원하기">
    Git 설정을 다시 복사합니다:

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

위 단계를 모두 마친 후 `git status`를 실행하여 저장소가 정상적으로 작동하는지 확인하세요.

<div id="troubleshooting-common-issues">
  ## 일반적인 문제 해결
</div>

<div id="fatal-repository-not-found-or-backup-remote-missing">
  ### &quot;fatal: repository not found&quot; 오류 또는 backup remote 누락
</div>

오래된 project에서는 백업 시스템이 활성화되어 있지 않을 수 있습니다. 오래된 project 복구에 도움이 필요하면 지원팀에 문의하세요.

<div id="recovery-didnt-include-recent-commits">
  ### 복구에 최근 commit이 포함되지 않음
</div>

백업은 Agent가 commit할 때마다 동기화됩니다. 변경 사항을 적용했더라도 commit하지 않았다면 해당 변경 사항은 백업에 포함되지 않습니다. 작업 디렉터리에 commit되지 않은 파일이 있는지 확인하세요.

<div id="git-operations-are-slow-or-hanging">
  ### Git 작업이 느리거나 멈추는 경우
</div>

Git 작업이 응답하지 않는다면 오래된 잠금 파일이 남아 있을 수 있습니다. 다음과 같이 안전하게 제거할 수 있습니다:

```bash theme={null}
rm -f .git/index.lock
```

<div id="preventing-data-loss">
  ## 데이터 손실 방지
</div>

백업 시스템이 Git 기록을 자동으로 보호하지만, 작업물을 더욱 안전하게 지키려면 다음 조치를 함께 활용하세요:

* **자주 커밋하기**: 작은 단위로 자주 commit하면 진행 상황이 지속적으로 백업됩니다
* **checkpoint 사용하기**: [Replit Agent](/ko/features/agent/overview)를 사용하면 주요 단계마다 checkpoint가 자동으로 commit을 생성합니다
* **GitHub에 연결하기**: 중요한 project라면 [앱을 GitHub에 연결](/ko/build/import-from-providers)하여 백업 계층을 하나 더 확보하세요
