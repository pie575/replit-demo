---
title: "Аварийное восстановление Git"
description: "Узнайте, как восстановить историю Git и код с помощью системы автоматического резервного копирования Replit."
---

Replit автоматически создает резервные копии Git-репозиториев, чтобы вы могли восстановиться после таких проблем, как повреждение папки `.git` или потеря истории коммитов. Эта система резервного копирования работает в фоновом режиме, поэтому ваша работа защищена без дополнительных усилий с вашей стороны.

<div id="section">
  ## Как это работает
</div>

Для каждого приложения Replit создаётся безопасная резервная копия Git-репозитория. Когда Replit Agent изменяет код или вы публикуете приложение, изменения автоматически синхронизируются с этой резервной копией. Если локальный Git-репозиторий повреждён или недоступен, вы можете восстановить из резервной копии всю историю коммитов.

<Info>
  Удалённый репозиторий резервной копии называется `gitsafe-backup` и автоматически управляется Replit. Вам не нужно настраивать его отдельно — он уже работает в фоновом режиме.
</Info>

<div id="section-2">
  ## Просмотр истории резервных копий
</div>

Самый простой способ просмотреть историю коммитов — открыть [интерфейс Git](/ru/ko/features/workspace-tools/git-interface). Откройте его в разделе Tools Project Editor, чтобы увидеть всю историю коммитов, включая все чекпоинты Agent. В большинстве случаев команды не понадобятся.

Если нужно напрямую проверить удалённый репозиторий gitsafe-backup, используйте Shell:

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

При этом отобразится полная история коммитов, включая все чекпоинты Agent и коммиты, созданные вручную. Используйте её, чтобы убедиться, что ваши изменения сохранены в резервной копии, или найти нужный коммит для восстановления.

<div id="git">
  ## Восстановление после проблем с Git
</div>

Если возникают ошибки Git или репозиторий повреждён, начните с [интерфейса Git](/ru/ko/features/workspace-tools/git-interface). С его помощью можно устранить большинство распространённых проблем, например вернуться к предыдущему коммиту или получить изменения из удалённого репозитория, без команд Shell.

Если интерфейс Git не помогает решить проблему (например, при полном повреждении папки `.git`), выполните приведённые ниже действия в Shell.

<div id="section-3">
  ### Проверка доступности резервной копии
</div>

Сначала убедитесь, что удалённый репозиторий резервной копии существует:

```bash theme={null}
git remote -v
```

Найдите `gitsafe-backup` в выводе. Если он есть, можно приступить к восстановлению.

<div id="section-4">
  ### Восстановление репозитория
</div>

<Warning>
  В ходе этой процедуры текущая папка `.git` будет заменена резервной версией. Рабочие файлы не изменятся, но локальная история Git будет восстановлена из резервной копии.
</Warning>

<Steps>
  <Step title="Сохранение текущей конфигурации Git">
    На случай наличия пользовательских настроек создайте резервную копию файла конфигурации Git:

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Клонирование резервного репозитория">
    Создайте временный клон из резервной копии:

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Замена папки Git">
    Переместите повреждённую папку `.git` и замените её резервной копией:

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Восстановление конфигурации">
    Верните файл конфигурации Git на место:

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

После выполнения этих шагов запустите `git status`, чтобы убедиться, что репозиторий работает корректно.

<div id="section-5">
  ## Устранение распространённых проблем
</div>

<div id="fatal-repository-not-found">
  ### &quot;fatal: repository not found&quot; или не настроен удалённый репозиторий для резервного копирования
</div>

В старых проектах система резервного копирования могла быть не включена. Если вам нужна помощь с восстановлением старого проекта, обратитесь в службу поддержки.

<div id="section-6">
  ### Восстановление не включает последние коммиты
</div>

Резервные копии синхронизируются после каждого коммита Agent. Если вы внесли изменения, но не закоммитили их, они не будут включены в резервную копию. Проверьте рабочую директорию на наличие незакоммиченных файлов.

<div id="git-2">
  ### Операции Git выполняются медленно или зависают
</div>

Если операции Git не отвечают, возможно, остались устаревшие файлы блокировки. Их можно безопасно удалить:

```bash theme={null}
rm -f .git/index.lock
```

<div id="section-7">
  ## Предотвращение потери данных
</div>

Система резервного копирования автоматически сохраняет историю Git, но вы можете принять дополнительные меры для защиты своей работы:

* **Чаще создавайте коммиты**: создавайте небольшие коммиты чаще, чтобы ход работы регулярно сохранялся в резервных копиях
* **Используйте чекпоинты**: при работе с [Replit Agent](/ru/ko/features/agent/overview) чекпоинты автоматически создают коммиты на каждом важном этапе
* **Подключитесь к GitHub**: для важных проектов [подключите приложение к GitHub](/ru/ko/build/import-from-providers), чтобы обеспечить дополнительный уровень резервного копирования
