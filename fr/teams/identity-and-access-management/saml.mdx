<div id="introduction">
  ## Introduction
</div>

<Note>
  Vous souhaitez ajouter le SSO au flux de connexion d&#39;**une app que vous créez** sur Replit ? Consultez [Ajouter le SSO à votre app (Clerk)](/fr/features/auth-and-identity/single-sign-on). Cette page explique comment activer le SSO pour votre **organisation Replit**, c&#39;est-à-dire la façon dont votre équipe se connecte à replit.com.
</Note>

<Note>
  Seules les organisations disposant d&#39;un plan Enterprise peuvent utiliser le SSO SAML. Vous pouvez [acheter le plan Enterprise directement depuis la page des tarifs](https://replit.com/pricing) ou [nous contacter](https://replit.com/teams#inlineForm) pour un accompagnement personnalisé.
</Note>

Le SSO [SAML](https://en.wikipedia.org/wiki/Security_Assertion_Markup_Language) vous permet d&#39;utiliser votre fournisseur d&#39;identité (IdP) pour authentifier les utilisateurs qui se connectent à replit.com. Les utilisateurs de votre organisation sont redirigés vers votre IdP pour s&#39;authentifier, puis votre IdP renvoie à Replit une réponse qui vérifie l&#39;identité de l&#39;utilisateur et le connecte.

Les administrateurs Enterprise peuvent configurer le SSO SAML directement depuis **Paramètres Enterprise → Authentification**, sans contacter Replit. L&#39;assistant génère les valeurs de votre fournisseur de services (SP), accepte les identifiants de votre IdP et provisionne le SSO automatiquement. Ce même parcours en libre-service s&#39;applique lors de l&#39;inscription si vous achetez le plan Enterprise en ligne : vous serez donc guidé dans la configuration du SSO dès la prise en main.

<div id="set-up-saml-sso">
  ## Configurer le SSO SAML
</div>

<img src="/assets/mirror/saml-enterprise-settings-d2d44c2de846.png" alt="Configuration du SSO SAML dans les paramètres Enterprise" width="1024" height="613" data-path="images/teams/identity-and-access-management/saml-enterprise-settings.png" />

L&#39;assistant de configuration vous guide en cinq étapes. Vous devez disposer d&#39;un accès administrateur à la fois à votre organisation Replit et à votre fournisseur d&#39;identité.

<Steps>
  <Step title="Ouvrir les paramètres d'authentification">
    Ouvrez le sélecteur de workspace, choisissez votre workspace Enterprise, puis ouvrez **Settings**. Sélectionnez **Advanced**, développez la section **Authentication**, puis cliquez sur **Enable SSO** dans la carte **SAML single sign-on**.

    La pastille de statut passe à **In-progress** et l&#39;assistant affiche les valeurs dont vous avez besoin pour votre IdP.
  </Step>

  <Step title="Choisir votre fournisseur d'identité">
    Sélectionnez votre IdP sous **Configure your identity provider** :

    * **Microsoft Entra ID**
    * **Google Workspace**
    * **Okta**
    * **Other provider**

    Chaque option adapte les libellés des champs et fournit un lien direct vers la console d&#39;administration de votre IdP, ce qui vous permet de créer l&#39;application SAML dans un nouvel onglet.
  </Step>

  <Step title="Créer l'application SAML dans votre IdP">
    Dans la console d&#39;administration de votre IdP, créez une application SAML à partir des valeurs affichées par Replit :

    | Champ                       | Valeur                                                                                                                               |
    | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
    | Audience URI / SP entity ID | Copiez la valeur affichée dans l&#39;assistant (propre à votre organisation, sous la forme `https://replit.com/<tenant-id>/saml/sp`) |
    | SSO URL (ACS URL)           | `https://replit.com/__/auth/handler`                                                                                                 |
    | Name ID format              | Email Address                                                                                                                        |
    | Application username        | Email                                                                                                                                |
  </Step>

  <Step title="Saisir les valeurs de votre IdP">
    Une fois l&#39;application SAML créée dans votre IdP, reportez les valeurs suivantes dans la section **Enter the values from your provider** de Replit :

    * **IdP SSO URL** — l&#39;URL vers laquelle Replit redirige les utilisateurs lors de l&#39;authentification.
    * **IdP entity ID** — identifie votre IdP auprès de Replit.
    * **X.509 certificate** — le certificat de signature de l&#39;IdP au format PEM ou base64. Les marqueurs `BEGIN/END` sont facultatifs.
    * **Email domains** — liste des domaines utilisés par vos utilisateurs pour se connecter, séparés par des virgules (par exemple, `acme.com, acme.co.uk`). Incluez tous les alias et sous-domaines que votre IdP est susceptible de transmettre.

    Cliquez sur **Submit credentials**. Replit valide l&#39;URL de manière synchrone, analyse le certificat (en rejetant les certificats expirés ou pas encore valides) et vérifie les domaines de messagerie revendiqués. Chaque domaine doit correspondre à l&#39;adresse e-mail d&#39;au moins un administrateur de facturation de votre organisation, et les domaines publics (tels que `gmail.com`) ne peuvent pas être revendiqués.
  </Step>

  <Step title="Attendre le provisionnement">
    La pastille de statut passe à **Provisioning…** pendant que Replit crée le tenant SAML sous-jacent. Cette opération prend généralement une minute environ. Une fois terminée, la pastille de statut affiche **Active** et votre organisation peut se connecter via le SSO.

    Si le provisionnement échoue, la pastille de statut affiche **Setup failed** et Replit nettoie automatiquement tout état partiel. Cliquez sur **Try again** pour relancer l&#39;assistant.
  </Step>
</Steps>

<div id="choose-your-email-domains">
  ## Choisir vos domaines de messagerie
</div>

Vous pouvez revendiquer plusieurs domaines et sous-domaines de messagerie pour votre organisation. Tout utilisateur qui tente de s&#39;inscrire avec un domaine de messagerie correspondant à l&#39;un de vos domaines revendiqués doit obligatoirement utiliser le SSO SAML. Les domaines que vous revendiquez doivent correspondre à ceux que votre IdP transmet pour vos utilisateurs. Si vous utilisez des alias de domaines de messagerie, incluez-les également afin d&#39;empêcher les utilisateurs de s&#39;inscrire sans passer par le SSO.

Par exemple, si votre entreprise utilise les domaines de messagerie `acmeco.com`, `foo.acmeco.com` et `acmebiz.com`, revendiquez les trois lorsque vous soumettez vos identifiants.

Replit valide chaque domaine revendiqué à partir des adresses e-mail de vos administrateurs. Pour ajouter ou supprimer des domaines après l&#39;activation, modifiez le champ **Email domains** de la carte **Authentication**. Pour revendiquer un domaine qui ne correspond à l&#39;adresse e-mail d&#39;aucun administrateur existant, contactez [support@replit.com](mailto:support@replit.com).

<div id="using-saml-sso">
  ## Utiliser le SSO SAML
</div>

<Note>
  L&#39;inscription via SAML n&#39;invite pas automatiquement les utilisateurs dans votre organisation. Pour la gestion automatisée des utilisateurs et les opérations en masse, consultez plutôt [SCIM](/fr/teams/identity-and-access-management/scim).
</Note>

Une fois le SSO SAML **Active** (actif), vos utilisateurs peuvent se connecter à [replit.com](https://replit.com) à l&#39;aide du bouton **Continue with SSO**.

<div id="faq">
  ## FAQ
</div>

<div id="what-happens-to-users-who-already-have-accounts-on-replitcom-before-saml-sso-was-set-up">
  ### Qu&#39;advient-il des utilisateurs qui possédaient déjà un compte sur replit.com avant la configuration du SSO SAML ?
</div>

Une fois le SSO SAML activé pour votre organisation, tous les utilisateurs dont le domaine de messagerie a été revendiqué pour le SSO doivent se connecter via le SSO. Les utilisateurs existants ne peuvent plus recourir à leurs anciennes méthodes d&#39;authentification (e-mail ou connexion via un réseau social) si leur adresse e-mail correspond au domaine SSO. Ils ne sont pas ajoutés automatiquement à votre organisation.

<div id="are-users-automatically-deprovisioned-in-replit-when-my-idp-removes-access">
  ### Les utilisateurs sont-ils automatiquement déprovisionnés dans Replit lorsque mon IdP révoque leur accès ?
</div>

Non, le SSO SAML gère uniquement l&#39;authentification. Pour automatiser le provisionnement et le déprovisionnement des utilisateurs, vous pouvez utiliser l&#39;intégration [SCIM](/fr/teams/identity-and-access-management/scim), disponible pour les clients Enterprise. SCIM vous permet de synchroniser l&#39;annuaire de votre IdP afin de gérer automatiquement les rôles et le provisionnement des utilisateurs.

<div id="are-organization-seats-automatically-consumed-when-users-are-given-access-in-our-idp">
  ### Les sièges de l&#39;organisation sont-ils automatiquement consommés lorsqu&#39;un accès est accordé aux utilisateurs dans notre IdP ?
</div>

Non, un siège n&#39;est consommé que lorsque l&#39;utilisateur accepte l&#39;invitation à rejoindre votre organisation.

<div id="what-if-saml-setup-fails">
  ### Que faire si la configuration SAML échoue ?
</div>

L&#39;assistant signale l&#39;échec par une pastille **Setup failed**, et Replit annule automatiquement tout provisionnement partiel. Cliquez sur **Try again** pour relancer l&#39;assistant, vérifiez attentivement les valeurs de votre IdP, puis soumettez à nouveau les identifiants. Si l&#39;erreur persiste, contactez votre gestionnaire de compte.

<div id="how-do-i-disable-saml-sso">
  ### Comment désactiver le SSO SAML ?
</div>

La désactivation en libre-service n&#39;est pas encore prise en charge. Contactez votre gestionnaire de compte pour désactiver le SSO de votre organisation. Vous pouvez néanmoins modifier vous-même les domaines de messagerie revendiqués depuis la carte **Authentication** après l&#39;activation.
