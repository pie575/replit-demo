以下解答涵盖你可能在已发布的 App 中遇到的错误。有关更全面的故障排除信息，请参阅[部署故障排除](/zh/build/troubleshooting)。

<AccordionGroup>
  <Accordion title="我已发布的 App 出现 403 Forbidden 错误，该如何修复？">
    已发布应用出现 403 通常源于以下原因之一：

    * **请求标头过大**——Cookie 过多会导致标头体积过大，在边缘节点就被拒绝。请清除浏览器中该域名的 Cookie 后重试。
    * **缺少身份验证**——请求中未包含所需的登录令牌或会话。
    * **访问限制**——你的应用可能被配置为阻止部分流量。请参阅[私有部署](/zh/features/publishing/private-deployments)和[外部访问令牌](/zh/features/deployment-customization/external-access-tokens)。

    如需详细诊断，请将部署日志粘贴到新的 Agent 对话中。
  </Accordion>

  <Accordion title="我的 App 显示“Application failed to respond”，这是什么意思？">
    你的应用进程未监听 Replit 预期的端口。Replit 会通过 `PORT` 环境变量传递正确的端口，因此请绑定到该端口，而不要使用硬编码的端口值：

    ```js theme={null}
    const PORT = process.env.PORT || 3000;
    ```

    ```python theme={null}
    port = int(os.environ.get("PORT", 3000))
    ```

    你的应用也可能在绑定端口之前就已崩溃——请检查部署日志中是否有启动错误。使用[自动扩缩部署](/zh/features/publishing/deployment-types#autoscale)时，闲置一段时间后的首次请求可能需要几秒钟才能响应 (即冷启动) ，这属于正常现象。
  </Accordion>

  <Accordion title="如何修复已发布的 Replit App 中的 CORS 错误？">
    CORS 错误表示你的前端和 backend 位于不同的源，而 backend 未配置为允许来自该源的请求。如果它们属于同一个 App，请使用 `/api/endpoint` 这类相对 URL，完全避免 CORS 问题。

    否则，请将 backend 配置为允许你的前端源。以 Express 为例：

    ```js theme={null}
    const cors = require("cors");
    app.use(cors({ origin: "https://your-frontend.replit.app" }));
    ```

    在 Publishing 前，仅允许必要的特定来源。请参阅[部署故障排除](/zh/build/troubleshooting)。
  </Accordion>

  <Accordion title="我的 App 在本地运行正常，但发布后提示网络错误">
    已部署的 App 在生产环境与本地环境不一致时可能会失败。请检查以下三项：

    1. **硬编码的 localhost URL**—将 `localhost:3000` 或 `127.0.0.1` 替换为相对路径或基于环境的 URL，然后重新部署。
    2. **缺少生产环境 Secrets**—确认部署 Secrets 中已设置所有必需的密钥。请参阅 [Secrets](/zh/core-concepts/project-editor/app-setup/secrets)。
    3. **未在生产环境运行迁移**—请在发布前对生产数据库运行待执行的迁移。

    如果问题仍然存在，请[联系 Replit 支持团队](https://replit.com/support)，并提供错误信息及你已尝试的步骤。
  </Accordion>

  <Accordion title="如何调试已发布 App 出现的 502 Bad Gateway 错误？">
    502 通常意味着你的应用进程崩溃了，或者返回了服务器无法处理的输出。请查看 deployment 日志中 502 出现之前的崩溃错误——未处理的 Promise 拒绝和未捕获的异常可能会让 Node.js 进程悄无声息地崩溃。

    添加一个处理器来暴露崩溃信息：

    ```js theme={null}
    process.on("uncaughtException", (err) => console.error("Uncaught:", err));
    ```

    在日志中找到底层错误后，将其粘贴到新的 Agent Chat 中，以获取修复帮助。
  </Accordion>

  <Accordion title="我的 App 无法请求外部 API，该检查什么？">
    首先确认请求是被拦截了，还是代码本身出错。打开 deployment 日志，查找与出站请求被拦截或重定向相关的消息。

    常见原因及解决方法：

    * **自引用 URL**——如果 backend 调用了自己的公开 URL (例如 `fetch("https://myapp.replit.app/api/...")`) ，请改用相对路径，如 `fetch("/api/...")`。
    * **构建阶段发起的请求**——请在运行时发起出站调用，而不要在构建期间发起。
    * **网络限制**——在公司或学校网络中，出站连接可能被拦截；请咨询网络管理员。

    如果以上情况都不适用，请求仍被拦截，请[联系 Replit 支持团队](https://replit.com/support)并附上相关日志行。
  </Accordion>

  <Accordion title="重新发布后，我的 App URL 变了——能恢复原来的子域名吗？">
    `.replit.app` 子域名由你的 project 名称生成，取消发布后再重新发布时不保证保持不变，尤其是当 project 曾被重命名时。

    彻底的解决办法是使用[自定义域名](/zh/features/publishing/custom-domains)，它在多次重新部署后始终不变。若想尝试找回原来的子域名，请确保 project 名称与原先一致 (必要时改回原名) 后重新发布——Replit 无法手动重新分配已释放的子域名。参见 [Project 地理位置](/zh/features/publishing/project-geography)。
  </Accordion>
</AccordionGroup>
