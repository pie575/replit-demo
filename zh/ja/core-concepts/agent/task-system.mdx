<div id="section">
  ## 什么是任务系统？
</div>

**任务**是 Agent 可规划和执行的工作单元。借助任务，Agent 可以将较大的目标拆分为更小的部分，并在每个部分对应用作出更改前进行审核。

Agent 可以在两个位置工作：**主线程**和**后台任务**。主线程是你说明需求、明确方向，并决定将哪些内容应用到主版本的对话。后台任务则是另一个线程，Agent 会在项目的隔离副本中独立工作。

请使用主线程确定方向和作出决策。对于可并行执行的工作，请使用后台任务。后台任务在你审核并应用之前不会更改主版本。

任务系统是 Agent 用来组织工作的方式。当你描述想要构建的内容时，Agent 可以将请求拆分为独立任务，并将其放入包含**草稿**、**进行中**、**准备就绪**和**已完成**列的看板中。

<Frame>
  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="任务看板，其中任务按草稿、进行中、准备就绪和已完成列整理" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />
</Frame>

每个任务会随着进展从左向右移动，因此你可以一目了然地了解已计划的内容、Agent 正在处理的内容、等待审核的内容以及已完成的内容。后台任务会根据计划自动排队，让工作持续推进，同时不会占用主线程。

当任务准备就绪后，你可以审核更改并将其应用到主版本；如果不符合预期，也可以将其拒绝。

<div id="section-2">
  ## 后台任务的工作原理
</div>

<Steps>
  <Step title="规划任务">
    在主线程中开始对话，或创建新线程来规划任务。Agent 会审查项目，找出最具影响力的工作，并为每项任务制定详细计划 (包括要做什么，以及何种状态算“完成”) 。

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="在主线程中描述想要构建的内容，Agent 正在提议并执行任务" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="审核并批准">
    Agent 会提议一组任务，每项任务都包含标题、说明，以及可通过**查看计划**查看的详细计划。审核整个列表后进行选择：

    * **批准任务**：启动所有任务并将其转入后台运行
    * **修改计划**：让 Agent 在开始前调整任务

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="任务规划对话框，显示四项提议的任务，并提供“批准任务”和“修改计划”选项" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="任务开始运行">
    获得批准后，任务会在项目的隔离副本中开始运行。Core 一次运行一个后台任务，Pro 最多支持 10 个并发后台任务。在您应用更改之前，主版本不会受到影响。您可以通过两种方式跟踪进度：

    * **线程视图**：每项任务都会在线程中运行，并显示实时状态指示器，因此您可以跟踪或参与任意任务的对话

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="线程视图，多个任务正在并行运行并显示状态指示器" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **看板视图**：按列展示所有任务，并按**草稿**、**进行中**、**准备就绪**和**已完成**状态分类

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="看板视图，任务按草稿、进行中、准备就绪和已完成列整理" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="审核并应用">
    任务完成后，Agent 会显示执行结果 (工作日志、测试结果和更改的实时预览) 。然后决定下一步操作：

    * **将更改应用到主版本**：将任务产生的更改合并到项目中
    * **拒绝**：如果不需要，则丢弃更改

    当 Agent 应用多个任务的更改时，会自动处理冲突。

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="任务审核界面，显示 Agent 的工作日志、测试结果和应用更改按钮" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="section-4">
  ## 可构建的内容
</div>

任务系统适用于任何项目。以下是几种特别有效的模式：

* **将大型功能拆分为小部分并逐步发布**：将认证、仪表板和 API 层拆分为独立任务，让 Agent 能够清晰地推进
* **规划复杂项目**：将大型功能分解为范围明确、具有依赖关系的任务，并有把握地执行
* **比较不同的设计方向**：使用不同任务尝试多种界面方案，并选择最佳方案

<div id="section-5">
  ## 常见问题
</div>

<Accordion title="我需要改变构建方式吗？">
  不需要。主线程的运行方式完全相同。Agent 会在适当时自动在后台创建任务。您也可以使用 [Plan 模式](/zh/ja/features/agent/plan-mode) 明确查看和管理任务。
</Accordion>

<Accordion title="为什么任务一次只能运行一个？">
  Core 一次只能运行一个后台任务。Pro 最多支持 10 个并发后台任务。达到套餐上限后，额外任务会进入队列，并在有空闲槽位时开始运行。
</Accordion>

<Accordion title="应用后台任务时，Agent 如何处理冲突？">
  Agent 使用 AI 辅助的冲突解决功能。它会理解每个任务要实现的目标，并智能地应用更改。如果您觉得哪里不对，可以在线程中让 Agent 修复。
</Accordion>

<Accordion title="任务之间可以相互依赖吗？">
  可以。Agent 会自动检测依赖关系。例如，构建仪表板的任务可能依赖于创建数据库架构的任务。依赖任务会等待前置条件完成。
</Accordion>

<Accordion title="归档和取消有什么区别？">
  **归档**适用于计划会话：即尚未开始构建的草稿。已归档的计划会话会被保留，并可从**已完成**列中恢复。

  **取消**适用于已从计划阶段进入构建阶段的任务。取消会停止任务并丢弃其工作成果，且已取消的任务无法恢复。请改为创建一个新任务。
</Accordion>
