## Task board 작동 방식

Task board는 Agent 작업을 검토, 시작, 모니터링, 적용할 수 있는 하나의 공간을 제공합니다. Agent가 큰 요청을 여러 조각으로 나눌 때, 백그라운드에서 작업을 실행하고 싶을 때, 또는 프로젝트에서 이미 변경된 내용을 확인해야 할 때 사용하세요.

작업은 상태에 따라 열로 정리됩니다. 보드는 Agent가 계획한 것, 실행 중인 것, 검토 준비가 된 것, 이미 적용된 것을 보여줍니다.

각 작업은 진행되면서 왼쪽에서 오른쪽으로 이동합니다:

* **Drafts**: Agent가 계획했지만 아직 시작하지 않은 작업
* **Active**: Agent가 지금 빌드하고 있는 작업, 활성 작업 한도에 밀려 대기 중인 작업 포함
* **Ready**: Agent가 완료하여 검토를 기다리는 작업
* **Done**: 완료, 보관, 취소된 작업

## Drafts

**Drafts**는 Agent가 계획했지만 아직 빌드를 시작하지 않은 작업입니다. 각 초안에는 제목, 설명, 단계별 계획이 포함되어 있습니다.

작업이 시작되기 전에 Agent가 제안한 접근 방식을 검토하려면 Drafts를 사용하세요. 계획을 살펴보고, Agent에게 조정을 요청하거나, 준비가 되면 작업을 시작할 수 있습니다.

Drafts는 백그라운드 작업을 확정하기 전에 더 큰 기능을 계획하고 싶을 때 유용합니다. 예를 들어, Agent는 온보딩 프로젝트를 인증, 프로필 설정, 대시보드 UI, 배포 마무리 작업을 위한 별도의 초안으로 나눌 수 있습니다.

## Active

작업을 승인하면 **Active** 열로 이동하고 Agent가 빌드를 시작합니다. 각 작업은 프로젝트의 독립된 복사본에서 실행되므로, 변경 사항을 적용하기 전까지는 메인 버전에 아무런 영향이 없습니다.

일부 작업은 다른 작업에 의존합니다. 예를 들어, 대시보드를 빌드하는 작업은 데이터베이스 스키마 작업이 먼저 끝나야 할 수 있습니다. 종속된 작업은 전제 조건이 끝날 때까지 **Queued** 상태로 대기합니다. 플랜의 활성 백그라운드 작업 한도에 도달하면 작업도 대기열에 들어갑니다.

## Ready

작업이 빌드를 마치면 **Ready**로 이동합니다. 이는 작업이 완료되었지만 아직 메인 버전에는 아무것도 변경되지 않았다는 뜻입니다.

변경 사항을 적용하는 방법은 두 가지입니다:

* **스레드에서**: 작업의 스레드를 열고 **메인 버전에 변경 사항 적용**을 선택해 작업을 프로젝트에 반영하거나, **삭제**를 선택해 폐기합니다
* **보드에서**: Ready 상태인 작업 카드의 세 점 메뉴를 선택한 다음 **변경 사항 적용**을 선택합니다

<TaskReviewDrawer />

적용하기 전에 Ready 작업을 검토하세요. Agent가 무엇을 변경했는지 이해할 수 있도록 작업 로그, 테스트 출력, 프리뷰를 확인하세요.

## Done

적용이 완료되면 작업 카드는 **Done** 열로 이동합니다.

Done 열에는 보관된 계획 세션과 취소된 작업도 포함됩니다. 이를 통해 완료된 작업이 Drafts나 Active에 다시 섞이지 않으면서도 무슨 일이 있었는지 기록을 확인할 수 있습니다.

## 작업 찾고 필터링하기

프로젝트에 진행 중인 작업이 많을 때 Task board를 사용하세요. 작업 제목이나 작업 번호로 검색하고, 초안을 필터링하고, 편집 모드를 사용해 여러 작업을 한꺼번에 관리할 수 있습니다.

예를 들어, 누군가 스레드, 리뷰, Slack 대화에서 작업을 언급할 때 작업 번호로 검색하세요. 활성 작업이나 완료된 작업을 훑어보지 않고 계획된 작업에만 집중하고 싶을 때 초안을 필터링하세요.

제안된 후속 작업에 대해서는 [Follow-up tasks](/ko/features/agent/follow-up-tasks)를 참고하세요.

## 작업 이름 바꾸기

범위가 바뀌면서 오래 진행된 작업 목록은 한눈에 파악하기 어려워질 수 있습니다. 작업 이름을 바꾸려면 카드의 세 점 메뉴(작업 목록 사이드바 또는 Task board에서)를 열고 **이름 변경**을 선택하세요. 더 명확한 제목을 입력하고 **저장**을 선택하세요.

작업 이름을 바꾸는 것은 여러분과 팀원에게 보이는 방식만 바꿉니다. Agent가 이미 완료한 작업, 작업 기록, 대기 중인 변경 사항은 그대로 유지됩니다.

## 각 작업의 설정

모든 작업에는 제목 옆에 자체 설정 드롭다운이 있습니다. 이를 열어 Agent가 작업을 마무리하는 방식과 결과가 프로젝트에 반영되는 방식을 제어하세요:

* **변경 사항 자동 적용** (Drafts와 Active): 작업이 준비되면 검토를 기다리지 않고 즉시 메인 버전에 적용합니다.
* **계획 자동 승인** (Drafts): Agent가 작업에 대한 계획을 제안하면 자동으로 승인하고 빌드를 시작합니다.
* **변경 사항 적용** (Ready): 완료된 작업을 메인 버전에 적용합니다.
* **이름 변경**: 카드에 표시되는 제목을 변경합니다.
* **변경 사항 검토** (Ready): 준비된 작업의 diff로 바로 이동합니다.
* **취소**: 작업을 멈추거나 초안을 제거합니다.

자동 적용과 자동 승인은 한 번 선택하는 빠른 동작이며, 계속 켜두는 토글이 아닙니다. 메뉴는 여러 작업을 열어도 레이블이 흔들리지 않도록 일정한 너비를 유지합니다.
