App Testing은 Agent가 실제 브라우저를 사용하여 만든 앱을 테스트할 수 있게 합니다. Agent는 실제 사용자처럼 애플리케이션을 탐색하며 클릭하고 기능을 검증합니다. 이 자체 테스트 기능은 앱이 올바르게 작동하는지 확인하고 Agent가 문제를 자동으로 발견하고 수정할 수 있도록 도와줍니다.

App Testing이 활성화되면 Agent는 충분히 많은 변경이 있었다고 판단할 때 주기적으로 자체 테스트를 결정합니다. Agent는 사용자 메시지의 100%마다 테스트하지 않으며, 테스트가 가장 가치 있을 때를 지능적으로 판단합니다.

<Note>
  현재 App Testing은 풀스택 JavaScript 및 Streamlit Python 웹 애플리케이션에서 사용할 수 있습니다.
</Note>

### 주요 이점

* **확장된 자율성**: 사람의 개입 없이 Agent가 더 오랫동안 작업할 수 있게 합니다
* **더 높은 품질**: 문제를 조기에 파악하고 해결하여 실수가 적은 앱을 만듭니다
* **비용 효율성**: 개발 중에 문제를 잡아냄으로써 추가 디버깅 세션의 필요성을 줄입니다
* **대화형 검토**: 철저한 결과 분석을 위한 비디오 재생과 구간별 탐색을 제공합니다

### 테스트 과정

Agent가 자체 테스트를 결정하면 다음과 같은 일이 일어납니다:

1. **브라우저 미리보기**: Agent 패널 안에서 브라우저 미리보기가 표시됩니다
2. **시각적 테스트**: Agent의 커서가 앱을 클릭하며 기능을 테스트하는 모습을 지켜보세요
3. **실제 사용자 시뮬레이션**: Agent는 실제 사용자처럼 애플리케이션을 탐색하며, 필요할 경우 모의 데이터를 입력합니다
4. **자동 분석**: Agent는 테스트 결과를 분석하고 모든 문제를 파악합니다
5. **자가 수정**: Agent는 테스트 요약을 보고하고 발생한 문제를 자동으로 수정합니다

## 주요 기능

Agent는 실제 사용자처럼 애플리케이션을 탐색하며 다음을 포함하여 지능적으로 테스트합니다:

* **사용자 인터페이스 검증**: 버튼, 폼, 내비게이션, 시각적 요소
* **기능 확인**: 핵심 기능과 사용자 워크플로우
* **통합 테스트**: API 호출, 데이터베이스 상호작용, 서드파티 서비스
* **성능 및 접근성**: 로드 시간, 반응성, 접근성 표준

## 사용법

App Testing은 채팅 입력창의 Agent 설정 드롭다운 안에 있는 **고급 설정**에 있습니다. Economy 또는 Power 모드를 사용할 때 켜세요. Lite 모드는 App Testing을 꺼둔 상태로 유지합니다.

<Note>
  App Testing은 Agent의 자율 기능 중 하나이며, 내장된 코드 리뷰와 함께 제공됩니다. 다른 [Agent
  기능](/ko/features/agent/overview)에 대해 자세히 알아보세요.
</Note>

## 인계받기

때때로 Agent는 테스트 중 계속하기 위해 여러분의 도움이 필요한 장애물을 만납니다. 가장 흔한 경우는 사용자 계정(예: Gmail)에 로그인하는 것입니다. 이 경우 Agent는 "인계 시작" 버튼을 팝업으로 표시합니다.

"인계 시작"을 누르면 테스트 미리보기로 들어가 필요한 단계를 완료한 다음 Agent가 계속하도록 할 수 있습니다. Agent가 여러분의 도움 없이 진행할 수 없는 경우 "건너뛰기"를 눌러 인계를 건너뛰고 App Testing을 종료할 수도 있습니다. 10분 이내에 응답하지 않으면 Agent는 여러분이 "건너뛰기"를 누른 것처럼 계속 진행합니다.

### 예상되는 동작

* **건너뛰기 옵션**: 필요할 경우 건너뛰기 버튼을 사용하여 테스트를 우회하고 개발을 계속하세요
* **대화형 비디오 재생**: 테스트 후 비디오를 클릭하여 전체 테스트 세션을 재생하세요
* **구간 탐색**: 하단의 슬라이더를 사용하여 테스트의 특정 구간으로 이동하세요

## 문제 해결

**테스트가 예기치 않게 실패함**

* 건너뛴 다음 다시 프롬프트를 입력하여 테스트를 시도하세요
* 테스트 타이밍에 영향을 줄 수 있는 동적 콘텐츠를 확인하세요
* 테스트 시나리오의 정확성을 검토하세요

**테스트 커버리지 누락**

* 앱 기능에 대해 더 자세한 설명을 제공하세요
* 테스트해야 할 중요한 사용자 흐름을 명시적으로 언급하세요

**App Testing이 전혀 작동하지 않나요?**

* App Testing은 현재 웹 애플리케이션[\*](#how-app-testing-works)에서만 작동합니다

## 가격 및 사용량

App Testing은 Agent의 노력 기반 가격 모델의 일부로 포함되며 다음과 같은 중요한 비용 고려 사항이 있습니다:

* **사용량 기반**: 테스트는 소요된 노력에 따라 요금이 청구됩니다(더 간단한 테스트는 비용이 적게 듭니다)
* **비용 대비 이점**: 테스트에는 비용이 들지만, 실수를 조기에 잡아냄으로써 추가 프롬프트와 Agent의 추가 작업을 방지하여 전체 비용을 절감할 수 있습니다
* **효율적인 개발**: 자동화된 접근 방식은 수동 디버깅과 재작업의 필요성을 줄여줍니다

<Tip>
  **비용 효율적인 테스트**: App Testing이 사용 비용을 추가하지만, 테스트 중에 잡아낼 수 있었던 문제를 수정하기 위한 추가 Agent 세션의 필요성을 방지하여 전체적으로 비용을 절감하는 경우가 많습니다.
</Tip>

## 다음 단계

프로젝트에서 App Testing을 사용할 준비가 되셨나요?

1. **빌드 시작**: Agent로 앱을 만들고 테스트가 자동으로 활성화되도록 하세요
2. **결과 검토**: 테스트 보고서를 살펴보고 제안된 개선 사항을 구현하세요
3. **반복**: 테스트 피드백을 사용하여 애플리케이션을 개선하세요
4. **확장**: 더 크고 복잡한 프로젝트에 App Testing을 적용하세요
