Auth 是 **authentication** (身份验证) 的简称，它让你的应用具备&quot;用户&quot;的概念。没有身份验证，每位访客都是匿名的，应用无法区分不同用户。有了身份验证，每位访客都会登录，你的应用就能识别他们，并且可以保存与其相关的数据：预订记录、收藏的车辆、偏好设置和进度。

接入身份验证后，你可以：

* 按用户保存数据——预订记录、设置、内容和历史记录。
* 要求用户登录后才能使用某些功能 (如结账流程、个人资料页面或管理面板) 。
* 根据姓名、角色、套餐或过往行为提供个性化体验。
* 按个人而非会话跟踪活动和使用情况。

<div id="how-auth-works-in-a-replit-app">
  ## Replit App 中的身份验证工作原理
</div>

Replit 提供两种内置身份验证选项。两者都由 Agent 配置，无需单独注册仪表板，也无需复制粘贴 OAuth 密钥。

* **[Replit Auth](/zh/features/auth-and-identity/authentication)** — 用户可使用现有的 **Replit 账户**登录。登录页面采用 Replit 品牌样式。只需让 Agent 添加即可，无需其他设置。
* **[Clerk Auth](/zh/features/auth-and-identity/clerk-auth)** — 你的应用会获得专属的 **Clerk 租户**。用户会在*你的*应用内创建账户，而非在 Replit 中。你可以控制品牌、登录方式以及登录界面的外观和体验。

这两种方案都会处理繁琐的工作——登录页面、会话、安全的密码处理和社交登录——因此你的应用代码只需询问：“当前登录的用户是谁？”

<div id="replit-auth-vs-clerk-auth">
  ## Replit Auth 与 Clerk Auth
</div>

|            | Replit Auth                  | Clerk Auth                      |
| ---------- | ---------------------------- | ------------------------------- |
| **用户账户**   | 用户使用 Replit 账户登录             | 用户在你的 App 中创建账户 (无需 Replit 账户)  |
| **品牌**     | 带有 Replit 品牌的登录页面            | 可完全自定义，包括你的 App 名称、图标和颜色        |
| **SSO 凭据** | 使用 Replit 共享的 OAuth app      | 为每个身份提供方使用自己的 OAuth 凭据          |
| **环境**     | 单一环境                         | 独立的开发环境与生产环境                    |
| **适用场景**   | 快速设置、原型，以及可接受 Replit 品牌的 App | 具有独立品牌的 App、专业产品和商业产品           |

如果你要构建原型或内部工具，Replit Auth 是最快的选择。如果你要构建具有独立品牌形象的产品，尤其是面向客户或用于商业用途的产品，Clerk Auth 更适合。

<div id="add-auth-to-your-app">
  ## 为你的应用添加身份验证
</div>

无需一开始就做出选择——你可以先使用其中一种，之后再迁移。最快的方法是告诉 Agent 使用哪一种：

* *“为我的应用添加登录功能。使用 Replit Auth。”*
* *“为我的应用添加登录功能。使用 Clerk Auth。”*
