你的应用通过 Replit 代为管理的凭据连接到数据库。你可以在 **Database** 工具中找到这些凭据：先选择一个数据库，然后打开 **Settings** 标签页。该标签页会显示连接字符串、存储用量以及高级连接详情。

</Frame>

<div id="variveis-de-ambiente">
  ## 环境变量
</div>

以下环境变量可用于连接到你的开发数据库：

* `DATABASE_URL`：用于连接数据库并进行身份验证

你的应用会自动使用该变量。由于 `DATABASE_URL` 仅限当前应用使用，其他应用 (即使是你自己的应用) 或外部数据库查看工具都无法访问你的开发数据库。即使该变量泄露，他人也无法凭此访问或修改你的数据库。

<Info>
  如果你的开发数据库仍运行在 [Neon 旧版基础设施](/zh/pt/features/data-and-storage/development-and-production#banco-de-dados-de-desenvolvimento-legado)上，则还可使用 `PGHOST`、`PGUSER`、`PGPASSWORD`、`PGDATABASE` 和 `PGPORT` 这些额外变量。托管在 Replit 当前基础设施上的数据库**不会**提供这些变量，请改用 `DATABASE_URL`。
</Info>

<Warning>
  如果你仍在使用 Neon 旧版开发数据库，请勿分享你的 `DATABASE_URL`。它包含你的数据库凭据，任何人都可借此访问和修改你的数据库。切勿将其粘贴到公开场合或支持工单中。
</Warning>

<div id="conectar-uma-ferramenta-externa">
  ## 连接外部工具
</div>

你可以在任何兼容 PostgreSQL 的 SQL 客户端中，使用**生产数据库** **Settings** 标签页里的连接字符串来连接该数据库。

<div id="segurana">
  ## 安全性
</div>

当你使用 Agent 添加数据库集成时，它会添加一个对象关系映射器 (ORM) ，由其安全地管理与数据库之间的所有通信，并内置以下安全机制：

* **模式校验**：验证数据是否符合预期格式
* **数据清理**：自动清理创建者输入的内容，防止 SQL 注入攻击

<div id="regenerar-as-credenciais-do-banco-de-dados-de-produo">
  ## 重新生成生产数据库凭据
</div>

如果生产环境连接字符串已泄露，请在 Database 工具中重新生成其凭据。此操作会为 Neon 生产数据库创建新密码，现有的生产环境连接字符串将立即失效。

同时满足以下所有条件时，你才能重新生成凭据：

* 你的应用拥有 Neon 生产数据库。
* 你是该应用的所有者，或所属 workspace 的管理员。
* 你正在网页浏览器中使用 Replit。
* 当前没有正在进行的部署。
* 如果你的应用有正在运行的部署，其最近一次构建已成功完成，并使用 [Autoscale 或预留虚拟机](/zh/pt/features/publishing/deployment-types)。

<Warning>
  此操作无法撤销。现有的连接字符串将立即失效。如果你的应用有正在运行的部署，在重新部署期间可能会短暂不可用。
</Warning>

<div id="regenere-as-credenciais">
  ### 重新生成凭据
</div>

1. 在 Tools 面板中，选择 **Database**。

2. 选择 **Production Database**，然后打开 **Settings** 标签页。

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="生产数据库的 Settings 标签页，显示连接字符串、存储用量以及包含 Regenerate credentials 行的 Advanced 部分。" width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. 在 **Advanced** 下，展开 **Regenerate credentials** 行。

4. 选择 **Regenerate credentials** 按钮。

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Advanced 部分中展开的 Regenerate credentials 行，显示 Regenerate credentials 按钮。" width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. 在确认对话框中，选择 **Regenerate credentials** 进行确认。

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="Regenerate credentials 确认对话框，提示该操作无法撤销，且现有连接字符串会立即失效。" width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. 选择 **Refresh** 加载新的连接字符串。

7. 如果你的应用有正在运行的部署，请打开 **Publishing** 并关注重新部署的进度。

8. 将已复制到外部工具或自定义集成中的连接字符串全部替换为新的。

<div id="o-que-muda">
  ### 会发生哪些变化
</div>

重新生成凭据会为生产数据库创建一个新密码。连接字符串中只有密码部分会变化，主机、数据库名称和 role 保持不变。

对于受支持的正在运行的部署，Replit 会使用更新后的连接字符串重新部署最近一次成功的构建。
