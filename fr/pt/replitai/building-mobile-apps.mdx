    * **Sur un téléphone réel avec Expo Go** : installez [Expo Go](https://expo.dev/go) sur votre iPhone ou appareil Android. Dans le Project Editor, sélectionnez **Open in Expo Go** dans le panneau aperçu et scannez le code QR.

<div id="visualizao-em-um-simulador-ou-emulador">
  ## Aperçu sur un simulateur ou un émulateur
</div>

Replit vous permet d’exécuter et de tester vos applications mobiles sur votre téléphone avec Expo. Vous pouvez également diffuser un véritable **iOS Simulator** ou **Android Emulator** directement dans le panneau d’aperçu. <Note>
  Les aperçus iOS Simulator et Android Emulator sont disponibles pour les utilisateurs des forfaits Core, Pro et Enterprise. Uniquement pour les applications mobiles : l’option est masquée dans les projets exclusivement web.

<div id="suporte-a-navegadores">
  ### Prise en charge des navigateurs
</div>

* **Chrome**, **Safari** et les navigateurs basés sur Chromium sont entièrement pris en charge.

<div id="quando-usar-o-expo-go-em-vez-disso">
  ### Quand utiliser Expo Go à la place
</div>

Utilisez Expo Go sur un téléphone physique lorsque vous devez tester des fonctionnalités qui dépendent du matériel de l’appareil ou partager un aperçu avec une personne qui n&#39;est pas sur votre ordinateur :

* Appareil photo, microphone, retour haptique ou autres capteurs natifs
* Notifications push
* Géolocalisation GPS réelle
* Partage d&#39;un aperçu de développement avec un collègue, un testeur ou un investisseur

Pour ouvrir votre application dans Expo Go, ouvrez le projet sur [replit.com](https://replit.com), sélectionnez **Open in Expo Go** dans le panneau d&#39;aperçu du Project Editor, puis scannez le code QR avec l&#39;application [Expo Go](https://expo.dev/go) sur votre téléphone.

</div>

Dans une carte d’artefact mobile, sélectionnez **More actions** → **Open in iOS Simulator** ou **Open in Android Emulator** pour ouvrir le simulateur dans un onglet distinct et bénéficier d’une zone d’affichage plus grande.

<div id="por-que-criar-um-aplicativo-mobile">
  ## Pourquoi créer une application mobile ?
</div>

Créez une application mobile si vous souhaitez :

* **Une expérience native** : Des performances rapides, des interactions fluides et une UI adaptée à la plateforme.
* **Des fonctionnalités de l’appareil** : Appareil photo, notifications push, localisation et bien plus encore.
* **Une distribution sur l’App Store** : Une fiche partageable que les utilisateurs peuvent découvrir et installer après le processus d’examen des apps par Apple.

<div id="recursos-principais">
  ## Fonctionnalités principales
</div>

* **Création pilotée par l’IA ** : Décrivez votre application, et Agent crée une application mobile fonctionnelle.
* **Aperçu dans le Project Editor ** : Testez-la dans un iOS Simulator ou un Android Emulator sans quitter Replit, ou prévisualisez-la sur votre téléphone avec Expo Go.
* **Full-stack par défaut ** : Ajoutez des routes côté serveur, une base de données, App Storage, des connecteurs et des intégrations d’IA à mesure que votre application évolue.
* **Soumission guidée ** : Préparez des builds pour TestFlight et soumettez-les à l’App Store sans gérer de chaînes d’outils iOS locales.

<div id="fluxo-de-trabalho-de-desenvolvimento">
  ## Flux de travail de développement
</div>

Il existe trois étapes pour accéder à votre application, chacune s’adressant à un public et offrant des fonctionnalités différentes :

| Étape             | Qui peut y accéder         | Comment y accéder                                           | Idéal pour                                                        |
| ----------------- | -------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------- |
| **Développement** | Vous                       | Simulateur du Project Editor ou code QR pour Expo Go        | Création et itération                                             |
| **Déploiement**   | Testeurs utilisant Expo Go | URL publique avec code QR                                   | Prévisualisations de développement, prototypage et démonstrations |
| **App Store**     | Tout le monde              | Téléchargement depuis l’App Store après examen des apps | Mise en production                                                |

**Développement** : lorsque vous lancez votre application, vous pouvez la prévisualiser dans l’**iOS Simulator** ou l’**Android Emulator** du Project Editor, ou scanner un code QR depuis le panneau Aperçu pour l’ouvrir dans Expo Go sur votre téléphone.

**Déploiement** : lorsque vous cliquez sur **Publier**, Replit crée une URL publique avec un code QR pour Expo Go. Cette option est idéale pour les prévisualisations de développement et le prototypage : montrez votre application à des investisseurs, recueillez des retours ou testez-la avec des amis avant d’entamer le processus de publication sur l’App Store.

**App Store** : lorsque vous soumettez votre application à l’App Store, Apple l’examine. Après approbation, les utilisateurs peuvent la télécharger et l’installer depuis l’App Store. Cela nécessite un compte Apple Developer.

<div id="viso-geral-de-publicao">
  ## Vue d’ensemble de la publication
</div>

Lorsque vous préparez une version iOS, le processus suit généralement les étapes suivantes :

* Publier depuis le Project Editor
* Envoyer un build à TestFlight
* Promouvoir un build de TestFlight vers l’App Store dans App Store Connect

<Note>
  Pour envoyer des builds vers TestFlight et l’App Store, Apple exige un abonnement à l’Apple Developer Program.
</Note>

Pour un guide complet, consultez le tutoriel [Créer et lancer une application mobile](/fr/pt/tutorials/build-and-launch-a-mobile-app).

<div id="onde-criar-aplicativos-mobile-nativos">
  ## Où créer des applications mobiles natives
</div>

Votre environnement Replit s’exécute dans le cloud, et non sur votre machine locale. Pour créer une application mobile native, utilisez le Project Editor sur [replit.com](https://replit.com). Le flux de travail des applications mobiles — création avec Agent, aperçu avec Expo Go, tests sur simulateur et émulateur, builds pour TestFlight et soumission sur l’App Store — s’effectue dans le Project Editor.

La création d’applications mobiles natives est également disponible dans [l’application Replit pour Android](/fr/platforms/mobile-app), là où elle est prise en charge. Si vous utilisez l’application Replit pour iOS, ouvrez le projet sur [replit.com](https://replit.com) pour créer, prévisualiser, compiler ou soumettre des applications mobiles natives.

  ## Comment fonctionne la technologie
</div>

Votre application mobile repose sur un ensemble de technologies qui fonctionnent de concert. Cette section explique ce qui fait fonctionner votre application et comment les différents éléments s&#39;articulent.

<div id="a-pilha-de-tecnologia">
  ### La stack technique
</div>

* **React Native** est un framework open source qui permet d’écrire une seule base de code et de la compiler pour iOS, Android et le Web. Il affiche des composants d’interface utilisateur natifs, et non une webview.
* **Expo** simplifie le développement avec React Native en gérant les builds et les modules natifs, et en fournissant des outils comme Expo Go pour les prévisualisations.
* **Expo Go** est une application gratuite que vous installez sur votre téléphone. Elle lance la prévisualisation de développement afin que vous puissiez tester sur un appareil réel sans créer de binaire natif complet.

Lorsque vous exécutez votre application, le bundler Metro compile votre code et l’envoie à votre appareil. La première compilation est plus longue, car il n’y a pas encore de cache. Les suivantes sont plus rapides.

<div id="arquitetura-servidor-e-cliente">
  ### Architecture : serveur et client
</div>

Lorsque vous préparez une application mobile pour la prévisualiser ou la distribuer, vous travaillez avec deux éléments :

1. **Un serveur** qui s&#39;exécute dans le cloud sur Replit. Il gère votre base de données, vos routes d&#39;API, vos intégrations d&#39;IA et votre logique backend.
2. **Une application cliente** qui s&#39;exécute sur le téléphone de l&#39;utilisateur. Il s&#39;agit de l&#39;application native prévisualisée dans Expo Go pendant le développement ou distribuée via les boutiques d&#39;applications après validation.

<MobileArchitectureDiagram />

Cette séparation offre une certaine flexibilité. Vous pouvez exécuter une logique complexe sur le serveur (où vous avez accès à la base de données, à Object Storage et aux connecteurs Replit) tout en conservant un client léger. Lors de la création de votre application, réfléchissez à ce qui doit se produire sur le téléphone et à ce qui doit se produire dans le cloud.

<div id="consideraes">
  ## Considérations
</div>

* **Exigences de publication** : Apple définit les exigences pour TestFlight et l’App Store, et examine les apps iOS avant leur mise en ligne.
* **Publication sur Android** : Vous pouvez créer des apps multiplateformes pour iOS et Android. La publication sur Google Play n’est pas encore prise en charge par le biais d’une expérience guidée, mais elle peut être effectuée manuellement.
* **Modifications natives** : Les modifications telles que les icônes d’app ou les autorisations nécessitent généralement une nouvelle build avant la mise en ligne sur le store.

<div id="perguntas-frequentes">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Qu'est-ce qu'Expo ?">
    Expo est l&#39;outil qu&#39;utilise Agent pour créer votre application mobile sur Replit. Il s&#39;agit d&#39;une plateforme et d&#39;une chaîne d&#39;outils open source permettant de créer, d&#39;exécuter et de déployer des applications natives multiplateformes avec React Native. En savoir plus sur [https://expo.dev](https://expo.dev).
  </Accordion>

  <Accordion title="Qu'est-ce que React Native ?">
    React Native est un framework open source de Meta permettant de créer des applications iOS et Android natives avec React et JavaScript ou TypeScript. Il affiche des composants d&#39;interface natifs à la plateforme (et non une webview), afin que votre application ait l&#39;apparence et le comportement d&#39;une application native.
  </Accordion>

  <Accordion title="Qu'est-ce qu'Expo Go ?">
    Expo Go est une application gratuite que vous installez sur votre téléphone depuis l&#39;App Store ou Google Play. Elle vous permet de prévisualiser votre application mobile pendant le développement sans créer un binaire natif complet. Lorsque vous scannez le code QR dans le Project Editor, Expo Go télécharge et exécute le code de votre application.
  </Accordion>

  <Accordion title="Quelle est la différence entre Expo Go et un build de développement ?">
    **Expo Go** est une application précompilée qui exécute votre code. Elle est rapide à configurer, mais ne prend en charge que les modules inclus dans le SDK Expo.

    Les **builds de développement** sont des binaires natifs personnalisés pouvant inclure n&#39;importe quel module natif. Ils nécessitent davantage de configuration (EAS Build ou Xcode/Android Studio en local), mais offrent plus de flexibilité.

    Replit utilise Expo Go pour les prévisualisations de développement. Si vous avez besoin de modules natifs non pris en charge dans Expo Go, vous devrez peut-être explorer les builds de développement via la [documentation Expo](https://docs.expo.dev/develop/development-builds/introduction/).
  </Accordion>

  <Accordion title="En quoi cela diffère-t-il d'une application web adaptative pour mobile ?">
    Une application web adaptative pour mobile est un site web dont la mise en page s&#39;adapte dans le navigateur. Une application React Native est une application native installée sur l&#39;appareil qui utilise les API de la plateforme (appareil photo, retours haptiques, notifications push), offre un meilleur accès au matériel et des capacités hors ligne, et est distribuée via les boutiques d&#39;applications. Le web adaptatif peut être idéal pour toucher un large public sans installation ; le natif est préférable lorsque vous avez besoin de fonctionnalités de l&#39;appareil, de performances ou d&#39;une distribution sur l&#39;App Store.
  </Accordion>

  <Accordion title="Ai-je besoin d'un Mac ou de Xcode ?">
    Non. Replit et Expo gèrent le processus de build pour vous dans le cloud.
  </Accordion>

  <Accordion title="Puis-je prévisualiser sans compte Apple Developer ?">
    Oui. Vous pouvez prévisualiser dans l’iOS Simulator du Project Editor ou avec Expo Go sur votre téléphone. Vous avez seulement besoin d&#39;un compte développeur Apple lorsque vous êtes prêt à soumettre votre application à TestFlight ou à l&#39;App Store.
  </Accordion>

  <Accordion title="Android est-il pris en charge ?">
    Oui. Vous pouvez créer des applications multiplateformes pour iOS et Android à partir du même code source. Prévisualisez-les dans un Android Emulator du Project Editor ou sur un appareil Android avec Expo Go. La publication sur Google Play peut être effectuée manuellement.
  </Accordion>

  <Accordion title="Qu'en est-il des serveurs et des bases de données ?">
    Utilisez le PostgreSQL intégré à Replit, Object Storage, les Connecteurs et les intégrations d&#39;IA — aucune infrastructure distincte n&#39;est nécessaire. Votre serveur s&#39;exécute sur Replit et votre application mobile s&#39;y connecte.
  </Accordion>

  <Accordion title="Dois-je tester dans le simulateur du Project Editor ou sur un téléphone réel ?">
    Utilisez les deux à différents moments. Les **iOS Simulator** et **Android Emulator** du Project Editor affichent la version native de votre application et couvrent la plupart des tests quotidiens — disposition, navigation, composants natifs et styles de la plateforme. Passez à un téléphone réel avec **Expo Go** lorsque vous devez tester des fonctionnalités qui dépendent du matériel réel, comme l&#39;appareil photo, les retours haptiques, les notifications push ou la localisation GPS.
  </Accordion>
</AccordionGroup>
