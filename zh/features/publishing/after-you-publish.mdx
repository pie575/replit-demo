选择 **Publish** 会启动一条简短的流水线，让你的应用上线。本页介绍发布过程中会发生什么、如何更新应用，以及应用上线后在哪里管理它。

<div id="the-publishing-stages">
  ## 发布阶段
</div>

Publishing 会经历五个阶段，通常需要一两分钟。你可以在 Publishing 工具中查看进度条，选择 **View logs** 查看详细信息，或选择 **Cancel** 终止正在进行的发布。

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Publishing 概览页显示五阶段进度条，其中 Provision 已完成，Security checks 和 Build 正在进行，Bundle 和 Promote 处于等待中" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision**：Replit 准备好应用运行所需的云资源，例如服务器和你的 production database。
2. **Security checks**：应用上线前，Replit 会扫描其中的安全问题，例如不安全的依赖项或泄露的密钥。
3. **Build**：Replit 将你的 project 转换为应用的生产版本，也就是在 Web 上运行的优化形态。
4. **Bundle**：构建好的应用被打包成一个可直接运行的整体。
5. **Promote**：Replit 会在当前版本之外准备好新版本，然后将你的 URL 切换到新版本。

<Note>
  Publishing 作用于整个 project：其中的每个 artifact，例如应用、幻灯片和文档，都会一并发布。
</Note>

<Accordion title="幕后发生了什么">
  如果你想了解技术细节：Provision 会按你选择的 部署 类型和区域分配部署基础设施。Security checks 会运行依赖项和代码扫描，并可根据你的安全设置，在发现严重漏洞时阻止本次发布。Build 会执行你的构建命令，并为生产环境编译资源。Bundle 会将构建产物打包成可部署的镜像。Promote 负责完成切换：新版本开始在你的 URL 上提供服务，取代先前的 部署。
</Accordion>

各阶段全部完成后，你的应用便已上线。在 Publishing 工具中选择该 URL 即可打开。

<div id="update-your-app">
  ## 更新应用
</div>

修改完成后，再次选择 **Publish**。应用会在同一网址上更新，访问者下次加载时即可看到最新版本，你无需重新分享链接。

<div id="manage-your-live-app">
  ## 管理已上线的应用
</div>

应用上线后，你同样可以在 Publishing 工具中进行管理：

* **监控运行状况**：跟踪应用是否在线、查看日志、检查资源使用情况。详见[监控](/zh/features/publishing/monitoring-a-deployment)。
* **查看访问者**：请求和流量图表位于[监控](/zh/features/publishing/monitoring-a-deployment)中；访问者与用户洞察则在 **Growth** 面板中查看。
* **更改访问权限**：先取消发布，选择其他访问选项，然后重新发布。详见[应用访问权限](/zh/features/publishing/private-deployments)。
* **绑定域名**：为应用设置自定义网址。详见[自定义域名](/zh/features/publishing/custom-domains)。
