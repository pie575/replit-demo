Le sélecteur de modèle permet à Replit d'utiliser le routage de modèle intelligent, ou vous permet de sélectionner vous-même un modèle disponible.

## Routage de modèle intelligent

Le routage de modèle intelligent choisit un modèle approprié pour chaque tâche, en équilibrant qualité et coût. Lorsque vous voyez **Auto** dans le produit, Replit effectue un routage de modèle intelligent.

Le routage de modèle intelligent prend en compte le travail que vous demandez et sa complexité. Une requête ciblée peut utiliser un modèle à moindre coût, tandis qu'un travail complexe peut nécessiter un modèle plus performant. Replit peut sélectionner un modèle différent à mesure que la tâche évolue.

<Note>
  Free Mode utilise toujours le routage de modèle intelligent. Les développeurs en Free Mode ne peuvent pas utiliser le sélecteur de modèle ni choisir un modèle manuellement.
</Note>

## Choisir un modèle manuellement

Les développeurs sur les plans Core et Pro peuvent choisir un modèle disponible en Power Mode ou en Max Mode.

1. Dans la zone de saisie, sélectionnez **Agent Mode**. Le menu affiche les modes disponibles : **Free**, **Power** et **Max**.
2. Sélectionnez **Power** ou **Max**, puis repérez la section **Primary model**.
3. Ouvrez le menu du modèle principal, puis choisissez un modèle dans la liste.

## Effort

**L'Effort est un contrôle propre à chaque modèle, pas un mode séparé.** Il détermine la quantité de raisonnement que le modèle sélectionné consacre à chaque réponse, de **Low** à **Max**. Chaque modèle affiche son paramètre recommandé, et vous pouvez l'augmenter uniquement lorsqu'une tâche l'exige.

<Frame caption="Le curseur d'Effort sous la liste des modèles, réglé sur Medium.">
  <img src="/assets/mirror/model-selector-effort-bcffb01239a8.png" alt="La liste des modèles principaux avec Claude Fable 5 sélectionné et le curseur d'Effort réglé sur Medium, décrit comme un raisonnement équilibré pour les tâches quotidiennes" width="984" height="832" data-path="images/replitai/model-selector-effort.png" />
</Frame>

Utilisez les descriptions des niveaux comme guide :

| Effort         | À utiliser pour                                                                                                                              |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Low**        | Réponses les plus rapides avec un raisonnement minimal. Modifications routinières et bien définies où la vitesse compte le plus.             |
| **Medium**     | Raisonnement équilibré pour les tâches quotidiennes. Un bon choix par défaut lorsque le paramètre recommandé n'indique pas autre chose.      |
| **High**       | Raisonnement plus approfondi pour un travail plus complexe, comme les fonctionnalités à plusieurs étapes et les territoires moins familiers. |
| **Extra High** | Raisonnement étendu pour les problèmes les plus difficiles, comme les refactorisations importantes et les bugs délicats.                     |
| **Max**        | Profondeur de raisonnement maximale. Le coût le plus élevé et le plus lent, lorsque seul le meilleur résultat possible compte.               |

À un Effort plus élevé, Agent effectue un raisonnement plus approfondi et délibéré et invoque ses modèles frontières les plus performants, améliorant les résultats sur les tâches les plus complexes. Agent applique cette puissance supplémentaire de manière sélective — il ne fait appel aux modèles plus performants que lorsqu'une requête est véritablement difficile, pas à chaque exécution.

<Tip>
  Parce qu'Agent ne fait appel au modèle le plus performant que pour les travaux les plus difficiles, un Effort plus élevé ajoute un coût allant jusqu'à \~2x sur les tâches les plus complexes — et souvent peu ou rien sur les plus simples. Augmentez-le lorsque vous vous attaquez à des problèmes complexes, et gardez-le bas pour les modifications de routine.
</Tip>

## Comparer les modèles

**Comparer les modèles** exécute votre prochain prompt sur plusieurs modèles à la fois, afin que vous puissiez comparer les résultats côte à côte au lieu de deviner quel modèle convient. Cette fonctionnalité est en bêta.

Pour l'activer, développez les **Paramètres avancés** en bas du menu contextuel des modes Agent et activez **Comparer les modèles**.

<Note>La comparaison de modèles n'est prise en charge que dans Chat.</Note>

<Frame caption="Le bouton Comparer les modèles dans les Paramètres avancés.">
  <img src="/assets/mirror/compare-models-toggle-05429dc46d64.png" alt="Paramètres avancés développés avec le bouton bêta Comparer les modèles désactivé, décrit comme créant jusqu'à 4 variantes avec votre prochain prompt" width="1110" height="344" data-path="images/replitai/compare-models-toggle.png" />
</Frame>

Une fois le bouton activé, ajoutez jusqu'à **4 modèles** à la comparaison.

<Frame caption="Quatre modèles sélectionnés pour la comparaison, avec le bouton d'envoi affichant Compare 4.">
  <img src="/assets/mirror/compare-models-9f5bcecec727.png" alt="Le menu contextuel des modes Agent avec Comparer les modèles activé et quatre emplacements de modèles — Kimi K3, Claude Fable 5, Claude Opus 5 et GPT-5.6 Sol — chacun supprimable, et le bouton d'envoi du chat affichant Compare 4" width="1192" height="1930" data-path="images/replitai/compare-models.png" />
</Frame>

Votre prochain prompt s'exécute alors une fois par modèle sélectionné, et chacun produit sa propre variante à comparer.

<Note>
  Chaque modèle d'une comparaison exécute un agent distinct et utilise des crédits, donc une exécution Compare 4 coûte à peu près autant que quatre exécutions individuelles.
</Note>
