Replit 的 Git 窗口提供用于 Git 操作的可视化界面，无需使用命令行 Git 命令。它让初学者也能轻松使用版本控制，同时为经验丰富的开发者提供强大的工具。

<div id="section">
  ## 功能
</div>

Git 窗口可在 Project Editor 中直接提供全面的版本控制功能，并通过直观易用的界面简化复杂的 Git 操作。

* **仓库管理**：通过 GitHub 集成初始化、连接和管理 Git 仓库
* **提交跟踪**：暂存、提交和查看所有文件的更改
* **分支操作**：以可视化方式创建、切换和合并分支
* **冲突解决**：借助可视化工具识别并解决合并冲突
* **Shell 集成**：同步 Shell 中执行的 Git 命令与 Git 窗口

<div id="section-2">
  ## 使用方法
</div>

<div id="section-3">
  ### 设置仓库
</div>

<Accordion title="如何打开 Git 窗口">
  1. 在 Replit 应用中，前往 Tools 部分
  2. 选择 **+** 图标以添加新工具
  3. 在可用工具列表中选择 **Git**
</Accordion>

Git 窗口可帮助你设置和连接仓库：

* **初始化仓库**：为 Replit 应用创建新的 Git 仓库
* **连接 Git 提供商**：将仓库连接到受支持的托管或自托管提供商，以便备份和协作
* **配置远程仓库**：设置和管理与远程仓库的连接

<Note>
  **自托管 Git 支持**：Replit 的 Enterprise 套餐支持 GitHub Enterprise Server、GitLab Self-Managed 和 Bitbucket Data Center。如需获取入门指导、配置提供商或排查连接问题，请[联系 Replit 销售团队](https://replit.com/enterprise)。你也可以[在 Shell 中使用 Git 命令配置远程仓库](#using-git-commands-in-shell)。
</Note>

<div id="section-4">
  ### 管理更改
</div>

<Accordion title="如何查看更改">
  1. 修改 Replit 应用中的文件
  2. 在 Tools 部分打开 Git 窗口
  3. 在 **Review Changes** 部分查看更改
</Accordion>

Git 窗口提供了管理代码更改的工具：

* **查看更改**：查看已修改的文件，新增和删除的内容会高亮显示
* **暂存文件**：选择要包含在下一次提交中的特定文件
* **提交更改**：使用描述性消息保存更改
* **推送更新**：一键将提交推送到远程仓库

<Note>
  您可以使用 Replit AI 协助生成能准确描述更改内容的提交消息。

<div id="section-5">
  ### 分支管理
</div>

<Accordion title="管理分支">
  1. 在 Tools 部分打开 Git 窗口
  2. 选择分支名称旁的分支下拉菜单
  3. 创建新分支或选择现有分支
</Accordion>

Git 窗口可简化使用不同版本代码的操作：

* **创建分支**：创建新分支以独立开发功能
* **切换分支**：在不同版本的代码之间切换
* **发布分支**：与 Git 提供商共享分支
* **拉取更改**：同步协作者的远程更新

<div id="section-6">
  ### 解决合并冲突
</div>

<Accordion title="如何解决合并冲突">
  1. 在存在冲突时尝试拉取更改
  2. Git 窗口会突出显示冲突文件
  3. 打开每个冲突文件，查看并解决冲突
  4. 解决冲突后，保存文件
  5. 选择 **Pull** 完成合并
</Accordion>

当来自不同来源的代码发生冲突时，Git 窗口支持：

* **识别冲突**：准确查看哪些文件存在冲突
* **查看差异**：查看冲突代码的两个版本
* **解决冲突**：选择要保留的代码，或手动编辑冲突内容
* **完成合并**：解决冲突后完成合并流程

解决冲突文件后，删除以冲突标记开头的行即可移除冲突标记，然后保存文件。

<div id="shell-git">
  ### 在 Shell 中使用 Git 命令
</div>

<Accordion title="如何访问 Shell">
  1. 在左侧工具栏中选择 **所有工具**
  2. 从可用工具中选择 **Shell**
</Accordion>

<Tip>
  Git 窗口提供了易用的界面，但高级用户也可以在 Shell 中使用标准 Git 命令执行更复杂的操作。无论通过哪种方式进行更改，都会同步显示在两处。
</Tip>

如果你更喜欢通过命令行使用 Git：

* **命令同步**：在 Shell 中运行的所有 Git 命令都会自动同步到 Git 窗口
* **完整 Git 功能**：可使用 Git 窗口中未提供的高级 Git 功能
* **无缝切换**：可根据需要在 Shell 命令和 Git 窗口之间切换

<Info>
  **支持 GitHub 和 GitLab CLI**：除标准 Git 命令外，你还可以在 Shell 中使用 [GitHub CLI](https://docs.github.com/en/github-cli)(`gh`) 和 [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/)(`glab`) 管理并连接外部 Git 仓库。这些工具为处理拉取请求、议题等 GitHub 和 GitLab 仓库操作提供了更丰富的功能。
</Info>

<div id="section-7">
  #### 仓库操作
</div>

* **克隆仓库**：`git clone <url-to-repository>`
* **初始化仓库**：`git init`
* **添加远程仓库**：`git remote add origin <url-to-repository>`

<div id="section-8">
  #### 修改
</div>

* **查看状态**：`git status` (显示已修改、添加和删除的文件) 
* **暂存文件**：`git add <filename>` 或 `git add .` (暂存所有文件) 
* **提交更改**：`git commit -m "your commit message"`
* **推送更改**：`git push origin <branch-name>`
* **拉取更改**：`git pull origin <branch-name>`

<div id="section-9">
  #### 身份验证
</div>

使用私有仓库时需要进行身份验证：

* 对于 GitHub.com 仓库，请使用个人访问令牌代替密码
* 如需避免重复输入凭据，可使用 Replit Secrets 将其保存：
  1. 创建一个键为 `GIT_URL` 的新 Secrets
  2. 将其值设为 `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. 若要在不输入凭据的情况下推送，请使用 `git push $GIT_URL`

<Note>
  使用凭据 Secrets 意味着任何能够访问 Replit 应用的人都可以访问你的 Git 凭据。对于敏感仓库，请考虑每次手动输入凭据。
</Note>
