---
title: "多个 artifact 与独立项目的对比"
description: "了解何时将多个 artifact 合并到同一个项目，何时在 Replit 中创建独立的项目。"
---

[项目](/zh/pt/features/projects-and-artifacts/projects) 是你在 Replit 上构建的一切内容的容器，其中包含你的设计、应用、幻灯片、数据以及创建的所有产出。
[artifact](/zh/pt/features/projects-and-artifacts/artifacts) 则是项目内可发布的产出：网页应用、移动应用、幻灯片演示和视频。

当你要构建的内容不止一个时，有两种选择：

* 在同一个项目中添加多个 artifact；
* 或者创建多个独立的项目。

如何选择，取决于这些应用是否共享数据、逻辑和同一套部署生命周期。本指南将介绍何时把多个 artifact 放在同一个项目中，何时创建独立的项目。

<div id="o-que-os-artefatos-compartilham-em-um-projeto">
  ## 同一个项目中的 artifact 会共享哪些内容
</div>

当多个 [artifact](/zh/pt/features/projects-and-artifacts/artifacts) 位于同一个 [项目](/zh/pt/features/projects-and-artifacts/projects) 中时，它们会自动共享：

* **数据库**：一个 artifact 写入数据，其他 artifact 可立即读取
* **后端与 API**：共用服务器逻辑，无需重复编写代码
* **文件存储**：图片、文档和上传的文件可在各 artifact 之间互相访问
* **部署**：发布时所有内容会一同同步部署

也就是说，你无需在 artifact 之间配置连接，也不用重复写代码。但这同时意味着，你无法只发布其中一个 artifact 而不发布其他 artifact。

<div id="guia-rpido">
  ## 快速指南
</div>

在决定是将 artifact 添加到现有项目中，还是单独创建一个项目时，可以参考以下几种主要场景。

| **在一个项目中使用多个 artifact**              | **使用独立项目**            |
| ------------------------------------ | --------------------- |
| 各应用共享相同的数据和后端                        | 各应用不共享底层逻辑或数据         |
| 你希望所有内容一起发布                          | 你需要各自独立的发布周期          |
| 它们相辅相成 (比如一个面向客户的应用和一个管理后台)          | 它们是互不相关的产品，或面向不同的客户   |
| 你希望某个 artifact 的改动自动反映到其他 artifact 中 | 项目是短期的，比如营销活动落地页或活动网站 |

<div id="exemplos">
  ## 示例
</div>

<div id="mesmo-projeto-aplicativo-web-aplicativo-mobile-para-um-produto">
  ### 同一个项目：同一产品的 Web 应用 + 移动应用
</div>

一家餐厅构建了一个供顾客浏览菜单的 Web 应用，以及一个供员工管理订单的移动应用。两者连接到同一个数据库，共用菜品、订单和顾客信息。

**为什么放在同一个项目中：** 这两个应用共享相同的数据和后端。顾客通过 Web 应用下单后，员工会立即在移动应用中看到该订单。

<div id="mesmo-projeto-aplicativo-dashboard-admin-pitch-deck-para-investidores">
  ### **同一个项目**：应用 + 管理后台 + 投资人路演材料
</div>

一家初创公司构建自己的核心产品、用于管理内容的内部管理后台，以及用于融资的演示文稿——全部放在一个项目里。
一家初创公司构建自己的核心产品、用于管理内容的内部管理后台，以及用于融资的演示文稿——全部放在一个项目里。

**为什么用一个项目：** 管理后台管理的正是应用所展示的那份数据，而演示文稿可以引用共享后端的实时指标。

<div id="projetos-separados-dois-aplicativos-de-clientes-no-relacionados">
  ### **独立项目**：两个互不相关的客户应用
</div>

一位自由职业者为一个客户搭建电商商城，为另一个客户搭建预订系统。

**为什么要用独立项目：** 这两个应用之间没有共享的数据或逻辑。每个客户都需要独立发布，而且你也不希望改动其中一个时影响到另一个。

<div id="projetos-separados-landing-page-de-campanha-ao-lado-de-um-produto-principal">
  ### **独立项目**：营销活动落地页与主产品并存
</div>

你有一个常年运行的生产应用，还有一个为营销活动准备的短期落地页。

**为什么要分开建项目：** 活动页面有自己的生命周期——创建、上线运行几周，然后下线。把它单独拆出来，可以避免让主产品变得杂乱，也便于你独立地发布或下线它。

<div id="perguntas-frequentes">
  ## 常见问题
</div>

<Accordion title="可以把某个 artifact 移动到另一个项目吗？">
  暂时不行。如果需要拆分某个 artifact，请新建一个 [项目](/zh/pt/features/projects-and-artifacts/projects)，并让 Agent 在其中重新构建。
</Accordion>

<Accordion title="一个项目最多能包含多少个 artifact？">
  一个项目最多可包含 7 个 artifact。之所以设置该上限，是因为 artifact 越多占用的内存越多，可能导致预览变慢。如果需要更多 artifact，请另建一个 [项目](/zh/pt/features/projects-and-artifacts/projects)。
</Accordion>

<Accordion title="可以只发布项目中的某一个 artifact 吗？">
  暂时不行。发布时会将所有内容一起部署。如果需要单独发布，请使用相互独立的项目。
</Accordion>
