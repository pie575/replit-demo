Как администратор Enterprise, вы можете задавать настройки для всей организации, определяющие, как участники команды взаимодействуют с кодом, развертываниями и внешними платформами. Эти настройки помогают соблюдать стандарты безопасности, защищать интеллектуальную собственность и обеспечивать соответствие корпоративным политикам.

<div id="acessando-as-configuraes-de-privacidade">
  ## Доступ к настройкам конфиденциальности
</div>

<Accordion title="Как открыть настройки конфиденциальности">
  1. Перейдите в Workspace Enterprise
  2. Выберите **Configurações**
  3. Выберите **Расширенные**, чтобы просмотреть все доступные настройки
</Accordion>

<div id="configuraes-de-privacidade">
  ## Настройки конфиденциальности
</div>

Настройки конфиденциальности определяют, как App публикуются и становятся доступными в вашей организации.

<CardGroup cols={2}>
  <Card title="Приватный деплой" icon="lock">
    Требуйте, чтобы все новые App публиковались как приватные, предоставляя доступ только аутентифицированным участникам команды
  </Card>

  <Card title="Развертывания с защитой паролем" icon="key">
    Разрешите участникам команды добавлять защиту паролем к опубликованным App
  </Card>

  <Card title="Приватные URL-адреса для разработки" icon="shield-halved">
    Требуйте аутентификацию для всех URL-адресов App для разработки, включая SSO для организаций с включённым SAML
  </Card>
</CardGroup>

<div id="deployments-privados">
  ### Приватный деплой
</div>

При включении этого параметра все новые App будут публиковаться как частные. Частные App доступны только аутентифицированным участникам вашей организации.

**Когда использовать этот параметр:**

* Организация работает с конфиденциальными данными или проприетарными приложениями
* Вам нужно гарантировать, что App не будут случайно сделаны общедоступными
* Требования соответствия предписывают ограничить доступ к опубликованным приложениям

<Note>
  Этот параметр применяется только к новым опубликованным App. Уже опубликованные App сохраняют текущие настройки видимости.
</Note>

<div id="deployments-protegidos-por-senha">
  ### Deployments, защищённые паролем
</div>

Укажите, могут ли участники команды создавать deployments, защищённые паролем. Если этот параметр включён, разработчики могут добавить дополнительный уровень защиты, требующий пароль для доступа к опубликованным App.

**Когда следует использовать эту настройку:**

* Вы хотите предоставить внешним заинтересованным сторонам доступ к App, не делая их полностью общедоступными
* Командам нужно демонстрировать приложения клиентам перед более широким запуском
* Вам нужен детальный контроль доступа помимо членства в организации

<div id="exigir-urls-de-desenvolvimento-privadas">
  ### Требовать приватные URL-адреса разработки
</div>

Если этот параметр включён, для доступа ко всем URL-адресам разработки App требуется аутентификация. Если в вашей организации включён SAML, для URL-адресов разработки требуется аутентификация SSO.

**Когда использовать этот параметр:**

* Вам нужно предотвратить несанкционированный доступ к приложениям в разработке
* Политики безопасности требуют защитить все среды разработки
* Вы хотите, чтобы Preview разработки могли просматривать только аутентифицированные участники команды

<Warning>
  Этот параметр применяется ко всем существующим App в вашей организации.
</Warning>

<div id="proibir-exportao-de-cdigo-fonte">
  ### Запретить экспорт исходного кода
</div>

Если этот параметр включён, участники команды не смогут экспортировать исходный код App в ZIP-архив. Это предотвращает скачивание кода и его передачу за пределы платформы Replit.

**Когда следует использовать эту настройку:**

* Вам необходимо строго контролировать место хранения исходного кода
* Политики безопасности запрещают локальное хранение копий кода
* Вы хотите, чтобы вся разработка велась только в управляемых средах

<div id="configuraes-de-segurana">
  ## Настройки безопасности
</div>

Настройки безопасности позволяют включить сканирование уязвимостей и другие меры защиты.

<div id="exigir-verificao-de-segurana">
  ### Требовать проверку безопасности
</div>

Настройте, должны ли все App проходить проверку безопасности перед публикацией. Проверки безопасности выявляют уязвимости, раскрытые секреты и другие проблемы безопасности в вашем коде.

Доступные параметры:

| Конфигурация  | Описание                                                         |
| ------------- | ---------------------------------------------------------------- |
| **Отключено** | Проверки безопасности необязательны                              |
| **Требовать** | Все App должны проходить проверку безопасности перед публикацией |

**Когда использовать эту настройку:**

* Необходимо соблюдать требования к безопасности
* Вы хотите предотвратить случайное раскрытие ключей API или секретов
* Вам необходимо обеспечить единые стандарты безопасности для всех опубликованных App

<Note>
  Эта настройка не применяется к App, опубликованным до её включения.
</Note>

<div id="configuraes-de-controle-de-cdigo-fonte">
  ## Настройки контроля исходного кода
</div>

Настройки контроля исходного кода помогают обеспечивать соблюдение практик контроля версий и защищать репозитории кода вашей организации.

<div id="exigir-repositrio-git-remoto">
  ### Требовать удалённый репозиторий Git
</div>

Если этот параметр включён, перед публикацией все локальные изменения в App необходимо отправить в удалённый репозиторий Git. Это гарантирует, что все изменения кода отслеживаются в системе контроля версий вашей организации.

**Когда следует использовать этот параметр:**

* Весь код должен быть сохранён в Git
* Вам нужен журнал аудита всех изменений кода
* Рабочие процессы требуют проверки кода перед публикацией

<Note>
  Этот параметр не применяется к App, опубликованным до его включения.
</Note>

<div id="repositrios-privados">
  ### Частные репозитории
</div>

Настройте, могут ли участники команды использовать публичные Git-репозитории. Если включено требование использовать частные репозитории, участники команды могут отправлять изменения только в частные репозитории на таких платформах, как GitHub.

Доступные варианты:

| Настройка                           | Описание                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------ |
| **Отключено**                       | Участники команды могут использовать публичные или частные репозитории                     |
| **Требовать для неадминистраторов** | Участники команды, не являющиеся администраторами, должны использовать частные репозитории |
| **Требовать для всех**              | Все участники команды, включая администраторов, должны использовать частные репозитории    |

**Когда следует использовать эту настройку:**

* Публичные репозитории кода запрещены
* Необходимо исключить случайную отправку проприетарного кода в публичные репозитории
* Требования соответствия предусматривают использование частного контроля версий
