Replit Database — это полностью управляемая база данных SQL, которая позволяет добавить постоянное хранилище данных в ваш Replit App прямо из Project Editor.

<Note>
  Быстрее всего начать так: попросите **Agent** добавить базу данных в ваше приложение. Agent настроит интеграцию, создаст схему базы данных и обновит приложение, чтобы оно сохраняло и получало данные.
</Note>

<div id="recursos">
  ## Возможности
</div>

Инструмент Replit Database предоставляет следующие возможности:

* **Инструменты базы данных**: выполняйте запросы, управляйте схемой базы данных и просматривайте данные с помощью встроенных инструментов SQL
* **Путешествие во времени**: восстановите базу данных до любого checkpoint **Agent**. См. [Восстановление данных](/ru/pt/features/data-and-storage/data-recovery)
* **Бесплатное хранилище**: включает 20 ГБ бесплатного хранилища для каждого Replit App.
* **Переменные окружения**: используйте переменные окружения в своём Replit App для безопасного доступа к базе данных

<Info>
  До 4 декабря 2025 года база данных разработки размещалась в Neon и имела ряд принципиальных отличий. Подробности см. в разделе [Разработка и продакшен](/ru/pt/features/data-and-storage/development-and-production#banco-de-dados-de-desenvolvimento-legado).
</Info>

<div id="uso">
  ## Использование
</div>

<YouTubeEmbed videoId="zbyRuoPNIc8" title="Как использовать базы данных в Replit" />

Открыть инструмент Replit Database можно прямо в Project Editor.
Разделы ниже помогут вам настроить Database и управлять ею.

<Accordion title="Как открыть инструмент Database">
  1. Откройте панель **Tools** и выберите **Database** в разделе **Replit Cloud**.
  2. На начальном экране отображается список ваших баз данных. Выберите одну из них, например **Development Database**, чтобы открыть её.
</Accordion>

Инструмент Database построен вокруг списка ваших баз данных. На начальном экране для каждой базы данных показан объём используемого хранилища, а также текущие **Billing Period** и **Hours of Compute Used**. При открытии базы данных доступны три вкладки:

* **Overview**: таблицы вашей базы данных.
* **My Data**: просмотр и редактирование строк, а также выполнение SQL-запросов.
* **Settings**: строка подключения, используемое хранилище и параметры подключения.

<div id="adicionar-um-banco-de-dados">
  ### Добавление базы данных
</div>

Все Replit App по умолчанию поставляются с базой данных. Открыть её можно, выбрав инструмент <img class="icon-svg" src="/assets/mirror/postgres-c4cb2a1e2de3.svg" alt="Значок базы данных PostgreSQL" width="24" height="24" data-path="images/icons/postgres.svg" /> **Database** в Project Editor.

Чтобы интегрировать базу данных в свой Replit App, попросите **Agent** добавить базу данных PostgreSQL
и укажите, какие именно данные должен хранить ваш Replit App. Agent создаст схему базы данных
и обновит приложение, чтобы оно могло с ней работать.

<div id="recursos-de-segurana">
  ### Функции безопасности
</div>

Когда вы добавляете интеграцию с базой данных с помощью **Agent**, он подключает объектно-реляционный преобразователь (ORM),
который безопасно управляет всем обменом данными с базой данных за счёт встроенных механизмов защиты.

Этот слой ORM вместе с применяемыми Agent лучшими практиками безопасности защищает ваше приложение от
эксплойтов благодаря следующим возможностям:

* **Проверка схемы**: контролирует соответствие данных ожидаемым форматам
* **Санитизация данных**: автоматически очищает введённые создателем данные, предотвращая атаки SQL-инъекций

<div id="legacy-development-database">
  ## Legacy Development Database
</div>

До 4 декабря 2025 года база данных разработки размещалась в <a href="https://neon.com/" target="_blank">Neon</a>.
Сейчас эта база данных считается устаревшей, а все новые базы данных разработки размещаются в собственной инфраструктуре баз данных Replit.

Проверить, размещена ли ваша база данных разработки в Neon, можно по переменной окружения `DATABASE_URL` [environment variable](#ver-credenciais-de-conexão-e-uso).

<Info>
  Если `DATABASE_URL` содержит `neon.tech/neondb`, значит ваша база данных разработки всё ещё размещена в Neon.
  Если же она содержит `helium/heliumdb`, ваша база данных разработки теперь размещена в Replit.
</Info>

Ниже перечислены основные различия между устаревшей базой данных разработки в Neon и новой базой данных разработки Replit:

| **Возможность**                | **Replit (текущая)**                                                                                                                                       | **Neon (устаревшая)**                                                                                                                   |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Хостинг**                    | Размещается в собственной инфраструктуре Replit                                                                                                            | Размещалась в Neon (сторонний провайдер)                                                                                                |
| **Оплата**                     | Включена бесплатно в каждый Replit App                                                                                                                     | Оплата по факту использования. Подробнее см. [Publishing and Database Billing](/ru/pt/billing/about-usage-based-billing#databases).        |
| **Возможность восстановления** | Восстановите базу данных до любого checkpoint с помощью [функции отката](/ru/pt/features/version-control/checkpoints-and-rollbacks/)                          | Восстановление на момент времени (PITR) — откат к любой точке в пределах срока хранения резервных копий.                                |
| **Безопасность подключения**   | Доступна только из вашего приложения; никогда не публикуется в открытом доступе.                                                                           | Использовалась полная строка подключения — при её утечке кто угодно мог получить доступ к базе данных и изменить её.                    |
| **Поведение при ремиксе**      | [Ремикс](/ru/pt/features/projects-and-artifacts/remix-an-app) создаёт новую базу данных разработки с копией данных — для изоляции и безопасности.             | Ремикс использовал одну и ту же базу данных для всех копий, поэтому изменения в ремиксах могли повлиять на исходное приложение.         |
| **Создание базы данных**       | Создаётся автоматически для каждого Replit App.                                                                                                            | Требовалась явная настройка.                                                                                                            |
| **Процесс публикации**         | Для развёртывания или публикации нужно создать [производственную базу данных](/ru/pt/features/data-and-storage/development-and-production) для изоляции сред. | Разработка и продакшн использовали одну базу данных, поэтому случайные изменения в разработке могли повлиять на приложения в продакшне. |

<Warning>
  Если ваше приложение было форкнуто или ремикшировано в период использования устаревшей базы данных Neon, опубликованное приложение может по-прежнему ссылаться на URL базы данных исходного приложения. После [обновления базы данных](/ru/pt/features/data-and-storage/development-and-production) это общее подключение перестанет работать. О том, как обновить опубликованное приложение, см. [Fix a published app using a shared database](/ru/pt/features/data-and-storage/shared-database-migration).
</Warning>
