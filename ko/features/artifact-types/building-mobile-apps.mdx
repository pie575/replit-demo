<div id="preview-on-a-simulator-or-emulator">
  ## 시뮬레이터 또는 에뮬레이터에서 미리 보기
</div>

Replit에서는 Expo를 사용해 휴대폰에서 모바일 앱을 실행하고 테스트할 수 있습니다. 또는 Replit이 실제 **iOS Simulator**나 **Android Emulator**를 Preview 패널로 바로 스트리밍해 줍니다. Agent로 변경한 내용은 실제 기기에서와 마찬가지로 시뮬레이터에서도 즉시 반영됩니다.

<Note>
  iOS Simulator 및 Android Emulator 미리 보기는 Core, Pro, Enterprise plan 사용자만 이용할 수 있습니다. 모바일 앱에서만 지원되며, 웹 전용 project에서는 해당 옵션이 표시되지 않습니다.
</Note>

<div id="how-to-open-a-simulator">
  ### 시뮬레이터를 여는 방법
</div>

<Steps>
  <Step title="모바일 프로젝트 열기">
    모바일 artifact가 있는 project를 엽니다.
  </Step>

  <Step title="기기 선택">
    Preview 패널 상단의 기기 선택기에서 **iOS Simulator** 또는 **Android Emulator**를 선택합니다. 웹 preview 자리에 시뮬레이터가 실행됩니다.
  </Step>

  <Step title="실제 기기처럼 조작하기">
    마우스와 키보드로 탭, 스와이프, 입력, 화면 이동을 할 수 있습니다. 시뮬레이터를 재시작하지 않고 앱만 다시 불러오려면 툴바에서 **Restart**를 선택하세요.
  </Step>
</Steps>

<Tip>
  시뮬레이터는 클라우드에서 실행되어 브라우저로 스트리밍되므로 따로 다운로드하거나 설정할 것이 없습니다. project의 파일은 Replit에 그대로 유지됩니다.
</Tip>

<div id="browser-support">
  ### 브라우저 지원
</div>

* **Chrome**, **Safari** 및 Chromium 기반 브라우저를 완벽하게 지원합니다.
* **Firefox**는 지원되지 않습니다. Firefox에서 Replit을 열면 iOS 및 Android 옵션이 비활성화된 상태로 표시되며 &quot;Firefox not supported&quot; 안내가 나타납니다. 이는 시뮬레이터를 구동하는 스트리밍 기술의 제약 때문입니다.

<div id="when-to-use-expo-go-instead">
  ### Expo Go를 사용해야 하는 경우
</div>

실제 하드웨어가 필요한 기능을 테스트해야 하거나, 컴퓨터 앞에 없는 사람과 미리보기를 공유하려는 경우에는 실제 휴대폰에서 Expo Go를 사용하세요.

* 카메라, 마이크, 햅틱 등 네이티브 센서
* 푸시 알림
* 실제 GPS 위치
* 팀원, 테스터, 투자자와 개발 미리보기 공유

Expo Go에서 앱을 열려면 [replit.com](https://replit.com)에서 project를 열고, Project Editor의 Preview 패널에서 **Open in Expo Go**를 선택한 다음, 휴대폰의 [Expo Go](https://expo.dev/go) 앱으로 QR 코드를 스캔하세요.

<div id="fullscreen-simulator">
  ### 전체 화면 시뮬레이터
</div>

모바일 artifact 카드에서 **More actions** → **Open in iOS Simulator** 또는 **Open in Android Emulator**를 선택하면 시뮬레이터가 별도의 tab에서 열려 더 넓은 화면에서 확인할 수 있습니다.

<div id="why-build-a-mobile-app">
  ## 모바일 앱을 만드는 이유
</div>

다음과 같은 것이 필요하다면 모바일 앱을 만드세요:

* **네이티브 경험**: 빠른 성능, 매끄러운 상호작용, 플랫폼 네이티브 UI.
* **기기 기능**: 카메라, 푸시 알림, 위치 등.
* **App Store 배포**: Apple의 App Review 절차를 거친 후 사용자가 검색해 설치할 수 있는 공유 가능한 listing.

  ## 주요 기능
</div>

* **AI 우선 제작**: 앱을 설명하기만 하면 Agent가 실제로 동작하는 모바일 앱의 뼈대를 만들어 줍니다.
* **Project Editor 미리 보기**: Replit을 벗어나지 않고 iOS Simulator나 Android Emulator에서 테스트하거나, Expo Go로 휴대폰에서 미리 볼 수 있습니다.
* **기본으로 full-stack**: 앱이 커지면 서버 라우트, Database, App Storage, Connectors, AI integrations를 추가하세요.
* **가이드에 따른 제출**: 로컬 iOS 툴체인을 직접 관리하지 않고도 TestFlight 및 App Store 제출용 빌드를 준비할 수 있습니다.

<div id="development-workflow">
  ## 개발 workflow
</div>

앱에 접근하는 단계는 세 가지이며, 각 단계마다 접근 대상과 활용 범위가 다릅니다:

| 단계              | 접근 가능한 대상             | 접근 방법                                  | 적합한 용도                          |
| --------------- | --------------------- | -------------------------------------- | ------------------------------- |
| **Development** | 본인                    | Project Editor 시뮬레이터 또는 Expo Go용 QR 코드 | 빌드 및 반복 작업                      |
| **Deploy**      | Expo Go를 사용하는 testers | QR 코드가 포함된 public URL                  | development preview, 프로토타이핑, 데모 |
| **App Store**   | 누구나                   | App Review 후 App Store에서 download      | Production 릴리스                  |

**Development**: 앱을 실행하면 Project Editor의 **iOS Simulator** 또는 **Android Emulator**에서 preview하거나, Preview 패널의 QR 코드를 스캔해 휴대폰의 Expo Go에서 열 수 있습니다.

**Deploy**: **Publish**를 클릭하면 Replit이 Expo Go용 QR 코드가 포함된 public URL을 생성합니다. development preview와 프로토타이핑에 특히 유용하며, App Store 절차를 본격적으로 진행하기 전에 투자자에게 시연하거나 feedback을 수집하거나 친구들과 테스트해 볼 수 있습니다.

**App Store**: App Store에 제출하면 Apple이 앱을 review합니다. 승인되면 누구나 App Store에서 앱을 download하여 설치할 수 있습니다. 이를 위해서는 Apple developer account가 필요합니다.

<div id="publishing-overview">
  ## Publishing 개요
</div>

iOS release를 준비할 때의 flow는 일반적으로 다음과 같습니다.

* Project Editor에서 Publish
* TestFlight에 build 제출
* App Store Connect에서 TestFlight build를 App Store로 승격

<Note>
  TestFlight와 App Store에 build를 제출하려면 Apple Developer Program membership이 있어야 합니다.
</Note>

전체 과정은 [모바일 앱 Build 및 launch](/ko/build/mobile-app) 튜토리얼을 참조하세요.

<div id="where-to-build-native-mobile-apps">
  ## 네이티브 모바일 앱을 만드는 곳
</div>

Replit 환경은 로컬 컴퓨터가 아닌 클라우드에서 실행됩니다. 네이티브 모바일 앱을 만들려면 [replit.com](https://replit.com)의 Project Editor를 사용하세요. Agent 스캐폴딩, Expo Go 미리보기, 시뮬레이터 및 에뮬레이터 테스트, TestFlight 빌드, App Store 제출로 이어지는 모바일 앱 workflow는 모두 Project Editor에서 진행됩니다.

네이티브 모바일 앱 작업은 지원되는 범위 내에서 [Replit Android 앱](/ko/features/platforms/mobile-app)에서도 가능합니다. Replit iOS 앱을 사용 중이라면 [replit.com](https://replit.com)에서 project를 열어 네이티브 모바일 앱을 생성, 미리보기, 빌드 또는 제출하세요.

<div id="how-the-technology-works">
  ## 기술 작동 방식
</div>

모바일 앱은 서로 맞물려 동작하는 여러 기술 스택으로 만들어집니다. 이 섹션에서는 앱을 구동하는 요소와 각 구성 요소가 어떻게 어우러지는지 설명합니다.

<div id="the-technology-stack">
  ### 기술 스택
</div>

<MobileStackDiagram />

* **React Native**는 하나의 codebase만 작성하면 iOS, Android, 웹용으로 컴파일할 수 있는 오픈소스 프레임워크입니다. webview가 아닌 플랫폼 네이티브 UI 컴포넌트를 렌더링합니다.
* **Expo**는 빌드를 처리하고 네이티브 모듈을 관리하며 미리보기용 Expo Go 같은 도구를 제공해 React Native 개발을 간소화합니다.
* **Expo Go**는 휴대폰에 설치하는 무료 앱입니다. 개발 미리보기를 실행해 주므로 전체 native binary를 빌드하지 않고도 실제 기기에서 테스트할 수 있습니다.

앱을 실행하면 Metro bundler가 코드를 컴파일해 기기로 전송합니다. 첫 빌드는 cache가 없어 시간이 더 걸리며, 이후 빌드는 더 빨라집니다.

<div id="architecture-server-and-client">
  ### 아키텍처: 서버와 클라이언트
</div>

모바일 앱을 preview하거나 배포할 준비를 할 때는 다음 두 가지를 다루게 됩니다:

1. **서버**: 클라우드의 Replit에서 실행되며, database, API 라우트, AI integrations, backend 로직을 처리합니다.
2. **클라이언트 앱**: 사용자의 휴대폰에서 실행됩니다. 개발 중에는 Expo Go에서 preview하고, review를 거친 후에는 store를 통해 배포하는 네이티브 앱입니다.

<MobileArchitectureDiagram />

이렇게 역할을 나누면 유연하게 개발할 수 있습니다. 복잡한 로직은 Replit의 Database, Object Storage, Connectors에 접근할 수 있는 서버에서 실행하고, 클라이언트는 가볍게 유지하면 됩니다. 앱을 만들면서 어떤 작업을 휴대폰에서 처리하고 어떤 작업을 클라우드에서 처리할지 생각해 보세요.

<div id="considerations">
  ## 고려 사항
</div>

* **Publishing requirements**: TestFlight과 App Store의 requirements는 Apple이 정하며, Apple은 배포 전에 iOS apps를 review합니다.
* **Android publishing**: iOS와 Android용 크로스 플랫폼 apps를 build할 수 있습니다. Google Play에 publishing하는 과정은 아직 가이드형 환경으로 지원되지 않지만, 수동으로 진행할 수 있습니다.
* **네이티브 changes**: app icon이나 permissions 같은 changes는 대개 새로운 store build가 필요합니다.

<div id="faqs">
  ## FAQs
</div>

<AccordionGroup>
  <Accordion title="Expo란 무엇인가요?">
    Expo는 Agent가 Replit에서 여러분의 모바일 앱을 build할 때 사용하는 도구입니다. React Native로 크로스 플랫폼 네이티브 앱을 빌드하고 실행하고 배포할 수 있는 오픈 소스 플랫폼이자 툴체인입니다. 자세한 내용은 [https://expo.dev](https://expo.dev)에서 확인하세요.
  </Accordion>

  <Accordion title="React Native란 무엇인가요?">
    React Native는 React와 JavaScript 또는 TypeScript로 네이티브 iOS 및 Android 앱을 만들 수 있는 Meta의 오픈 소스 프레임워크입니다. webview가 아닌 플랫폼 네이티브 UI 컴포넌트를 렌더링하므로 앱이 네이티브처럼 보이고 동작합니다.
  </Accordion>

  <Accordion title="Expo Go란 무엇인가요?">
    Expo Go는 App Store나 Google Play에서 휴대폰에 설치하는 무료 앱입니다. 전체 native binary를 빌드하지 않고도 개발 중인 모바일 앱을 미리 볼 수 있습니다. Project Editor에서 QR 코드를 스캔하면 Expo Go가 앱 코드를 download해 실행합니다.
  </Accordion>

  <Accordion title="Expo Go와 dev build의 차이점은 무엇인가요?">
    **Expo Go**는 여러분의 코드를 실행해 주는 사전 빌드된 앱입니다. 설정은 빠르지만 Expo SDK에 포함된 모듈만 지원합니다.

    **Dev build**는 어떤 네이티브 모듈이든 포함할 수 있는 맞춤형 native binary입니다. 설정 과정(EAS Build 또는 로컬 Xcode/Android Studio)이 더 번거롭지만 그만큼 유연합니다.

    Replit은 development preview에 Expo Go를 사용합니다. Expo Go에서 지원하지 않는 네이티브 모듈이 필요하다면 [Expo 문서](https://docs.expo.dev/develop/development-builds/introduction/)를 참고해 dev build를 검토해 보세요.
  </Accordion>

  <Accordion title="모바일 반응형 web app과는 어떻게 다른가요?">
    모바일 반응형 web app은 브라우저에서 layout이 화면 크기에 맞춰 바뀌는 website입니다. 반면 React Native 앱은 기기에 설치되는 네이티브 애플리케이션으로, 플랫폼 API(camera, haptics, 푸시 알림)를 사용하고 하드웨어와 offline 기능을 더 폭넓게 활용할 수 있으며, 앱 store를 통해 배포됩니다. 반응형 웹은 도달 범위가 넓고 설치가 필요 없다는 점에서 유리하고, 네이티브는 기기 기능, 성능, App Store 배포가 필요할 때 가장 적합합니다.
  </Accordion>

  <Accordion title="Mac이나 Xcode가 필요한가요?">
    아니요. Replit과 Expo가 클라우드에서 빌드 과정을 대신 처리합니다.
  </Accordion>

  <Accordion title="Apple Developer 계정 없이도 미리 볼 수 있나요?">
    네. Project Editor의 iOS Simulator나 휴대폰의 Expo Go에서 미리 볼 수 있습니다. Apple Developer 계정은 TestFlight나 App Store에 제출할 때만 필요합니다.
  </Accordion>

  <Accordion title="Android도 지원되나요?">
    네. 동일한 codebase로 iOS와 Android용 크로스 플랫폼 앱을 build할 수 있습니다. Project Editor의 Android Emulator나 Expo Go를 설치한 Android 기기에서 미리 보세요. Google Play 게시는 수동으로 진행할 수 있습니다.
  </Accordion>

  <Accordion title="서버와 database는 어떻게 하나요?">
    Replit에 내장된 PostgreSQL, Object Storage, Connectors, AI integrations를 사용하세요. 별도의 인프라가 필요 없습니다. 서버는 Replit에서 실행되고, 모바일 앱이 여기에 연결됩니다.
  </Accordion>

  <Accordion title="Project Editor의 시뮬레이터와 실제 휴대폰 중 무엇으로 테스트해야 하나요?">
    상황에 따라 둘 다 사용하세요. Project Editor의 **iOS Simulator**와 **Android Emulator**는 앱의 네이티브 버전을 보여주며 layout, 내비게이션, 네이티브 컴포넌트, 플랫폼 스타일링 등 일상적인 테스트 대부분을 처리할 수 있습니다. camera, haptics, 푸시 알림, GPS location처럼 실제 하드웨어가 필요한 기능을 테스트할 때는 **Expo Go**를 사용해 실제 휴대폰으로 전환하세요.
  </Accordion>
</AccordionGroup>
