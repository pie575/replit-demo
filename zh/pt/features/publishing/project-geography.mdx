---
title: "项目地理区域"
description: "选择已部署 Project 的计算与存储的托管位置。"
---

项目地理区域即 Project 的部署地理区域。你在部署时选择该区域，它决定了已部署 Project 的计算和存储托管在哪里。

<Note>
  项目地理区域与 [workspace
  地理区域](/zh/features/collaboration/workspace-geography) 可以不同。workspace
  地理区域决定 Workspace 中新建 Project 的开发资源托管在哪里。
</Note>

<div id="o-que-a-geografia-do-projeto-controla">
  ## 项目地理区域控制哪些内容
</div>

默认情况下，Replit 会推荐离你最近的地理区域，这有助于降低应用访问者的延迟，并满足数据驻留要求。

选择地理区域后，你的 Project 中所有已发布的构件 (如计算资源、数据库和 Object Storage) 都会自动部署到同一区域。该地理区域专属的代理还能进一步降低应用访问者的延迟。

<div id="selecione-uma-geografia-de-projeto">
  ## 选择项目地理区域
</div>

如需选择推荐区域以外的地理区域：

<Steps>
  <Step>在你的 Replit Project 中打开 **Publishing** 工具。</Step>
  <Step>展开 **Advanced** 设置。</Step>
  <Step>在 **Geography** 下拉菜单中选择你需要的地理区域。</Step>

  <Step>
    选择 **Publish**，将 Project 发布到所选地理区域。
  </Step>
</Steps>

<div id="aplique-uma-geografia-obrigatria-para-projetos-publicados">
  ## 为已部署的项目强制指定地理区域
</div>

Enterprise 组织的管理员可以为组织内所有 Project 强制指定部署所在的地理区域。策略设置后，组织中的构建者只能部署到所配置的地理区域。该策略仅适用于尚未部署的 Project，已部署在其他地理区域的 Project 不受影响。

<Note>
  强制指定部署地理区域是 Enterprise 功能。
  如需了解 Enterprise 计划的更多信息，请参阅
  [Pricing](https://replit.com/pricing/)。
</Note>

<Steps>
  <Step>进入你的 **Account settings**。</Step>
  <Step>选择 **Advanced**。</Step>

  <Step>
    选择所有首次部署的 Project 需使用的地理区域。
  </Step>
</Steps>

<div id="disponibilidade-e-limites">
  ## 可用性与限制
</div>

| 地区                | 项目部署区域选择 |
| :---------------- | :------- |
| **北美**            | 支持       |
| **欧洲 (欧盟)&#x20;**&#x20;| 支持       |
| **亚洲**            | 支持       |
| **南美**            | 支持       |
| **澳大利亚**          | 支持       |

<Note>
  项目地理区域选择功能面向 Core、Pro 和 Enterprise 客户开放。免费套餐用户默认部署到北美地区。
</Note>

在选择项目地理区域之前，请注意以下限制：

* **部署后无法更改地区。** 将 Project 部署到某个地区后，该选择即永久生效，无法再将已部署的 Project 迁移到其他地区。
* **开发所在位置与部署位置可能不同。** Object Storage 等资源可能在你部署之前就已创建，因此可能与 Project 所在地区不一致。
