Поскольку Replit запускает ваши проекты в облачной среде, порты в Replit работают иначе, чем на локальном компьютере. (Если вам нужно более простое объяснение того, что такое TCP-порты, [начните здесь](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

На компьютере есть только один уровень управления портами: программы определяют порт, который они прослушивают, и, когда интернет-трафик поступает на этот порт, он направляется в соответствующий процесс.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="компьютер" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` — это адрес, или хост. Если процесс прослушивает `0.0.0.0`, это означает, что он прослушивает все сетевые интерфейсы. То есть, если другой компьютер в интернете отправит запрос на IP-адрес вашего компьютера, этот процесс его получит. Поэтому прослушивание на `0.0.0.0` означает, что процесс доступен из публичного интернета, если ваш компьютер подключен к сети.

Большинство фреймворков *не* прослушивают `0.0.0.0` во время разработки, поскольку вы не всегда хотите открывать свою работу для общего доступа — из соображений конфиденциальности и безопасности. Вместо этого они прослушивают другой адрес — `127.0.0.1`, также известный как `localhost`. Это означает, что отправлять запросы на этот порт может только этот компьютер.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Порты localhost доступны только на компьютере, который их размещает." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

В Replit, чтобы запущенный процесс был доступен в веб-просмотре или через внешний запрос, для него должен быть задан **внешний порт**. Это необходимо, поскольку «внутренний порт», который обычно используют процессы, виден только в изолированной облачной среде Replit. Чтобы направлять трафик в нужные программы, внутренний порт необходимо связать с доступным извне портом. Даже если процесс прослушивает общедоступный адрес, например `0.0.0.0`, его всё равно нужно привязать к внешнему порту.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Внешние порты перенаправляют трафик на внутренние порты, которые прослушивают программы." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit связывает внешние порты с конкретными внутренними портами. Например, на диаграмме выше внешний порт `:80` связан с внутренним портом `:3000`. Это означает, что весь трафик, который Replit App получает на порту 80, направляется на внутренний порт 3000.

Эта конфигурация задается в разделе [[ports]] файла конфигурации .replit.

По умолчанию Replit связывает первый открытый вами порт с внешним портом по умолчанию 80. Благодаря этому процесс доступен по домену без указания порта (например, customdomain.com/ вместо customdomain.com:3000/). Дополнительные открытые внутренние порты связываются с другими доступными внешними портами (полный список см. ниже).

<div id="porta-padro">
  ## Стандартный порт
</div>

Порт :80 — стандартный порт для HTTP-трафика, поэтому HTTP-трафик, отправляемый на корневой домен, автоматически направляется на порт 80. Поэтому номер порта 80 не отображается в URL. Порты, отличные от `:80`, отображаются в адресе домена (например, customdomain.com:4200/). (Replit по умолчанию предоставляет TLS, поэтому технически используется порт 443 — стандартный порт для HTTPS. На практике их можно считать взаимозаменяемыми.)

<div id="publicao">
  ## Публикация
</div>

Развёртывания Autoscale и Reserved VM поддерживают только один внешний порт, а соответствующий внутренний порт не может использовать `localhost`. Если вы откроете несколько портов или один порт на localhost, опубликованное приложение не запустится. Чтобы развёртывания Autoscale работали должным образом, удалите из конфигурации все записи `externalPort`, *кроме* записи для порта сервиса, к которому вы хотите обращаться из интернета.

<div id="depurao">
  ## Отладка
</div>

Частая причина, по которой что-то работает не так, как ожидается, заключается в том, что, хотя настройка порта выглядит правильной, программа на самом деле ищет другой порт. Например, если ваша конфигурация выглядит так:

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Тогда интернет-трафик, поступающий на порт 80, будет перенаправляться на внутренний порт 3000. Однако если ваша программа прослушивает не порт 3000, а другой порт (например, 8080), будет казаться, что трафик не поступает. Это может произойти, если вы измените порт в коде, не изменив соответствующий порт в конфигурации, или скопируете конфигурацию из одного проекта в другой.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Программы могут менять порты, которые они прослушивают." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

У каждого фреймворка свой порт по умолчанию: например, у Flask — 5000, у React — 3000, а у Laravel — 8000. Убедитесь, что настроен правильный порт!

<div id="preferncias">
  ## Настройки
</div>

Replit автоматически сопоставляет открытые порты в вашем Replit App с доступными внешними портами и записывает это сопоставление в файл конфигурации .replit.

Однако по умолчанию это не происходит для внутренних портов, открывающихся на localhost, поскольку службы, обычно работающие на localhost, как правило, предполагают, что будут доступны только на том же компьютере, где запущен процесс (порты localhost видны только на компьютере, где выполняется процесс). Это означает, что такие службы часто менее безопасны, чем службы, изначально рассчитанные на доступность из публичного интернета.

Вы всегда можете изменить это, установив для порта, который хотите открыть, значение `true` параметра конфигурации `exposeLocalhost`.

Если вы хотите *всегда* открывать порты localhost по умолчанию, в пользовательских настройках установите для параметра «автоматическое перенаправление портов» значение «Все порты».

Если вы хотите *никогда* не создавать конфигурацию для открывающихся портов и вручную управлять конфигурацией портов всех ваших Replit App, установите значение «Никогда».

<div id="portas-suportadas">
  ## Поддерживаемые порты
</div>

При открытии первого порта Replit App назначит порт 80 внешним портом по умолчанию. Replit App может предоставлять доступ к портам 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080, 8081 в качестве дополнительных внешних портов.

Порты 22 и 8283 нельзя перенаправить, поскольку они используются внутри системы.

<div id="configurao-ports-do-replit">
  ## Конфигурация `[[ports]]` в .replit
</div>

Тип: `{localPort, externalPort, exposeLocalhost}`

Конфигурация `[[ports]]` позволяет указать, какой HTTP-порт следует открыть для веб-вывода. По умолчанию любой HTTP-порт с хостом 0.0.0.0 будет доступен как веб-вывод вашего Replit App.

Дополнительные порты можно обслуживать, не заменяя порт по умолчанию: добавьте новую запись [[ports]] в файл .replit. Необходимо указать параметры localPort и externalPort. Чтобы добавить несколько дополнительных портов, добавьте в файл .replit несколько записей [[ports]], как описано ниже.

<div id="localport">
  ### localPort
</div>

Определяет, какой порт Replit будет привязан к внешнему порту.

<div id="externalport">
  ### externalPort
</div>

Определяет, какой локальный порт будет открыт для общего доступа.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Если вы хотите *никогда* не предоставлять доступ к определённому порту извне, можете оставить настройку `localPort`, но не добавлять `externalPort`:

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Определяет, можно ли перенаправить внутренний порт, использующий `localhost`, на внешний порт. Может иметь значение `true`, `false` или null.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
