---
title: "Corriger les applications publiées utilisant une base de données partagée"
description: "Procédure pour mettre à jour des applications publiées qui utilisent encore une base de données créée pour une autre application."
---

Certaines anciennes applications publiées peuvent encore être connectées à une base de données de développement initialement créée pour une autre application.

Cela peut se produire avec d&#39;anciennes applications forkées ou remixées dans Replit. Avec l&#39;ancienne configuration Neon, les forks pouvaient continuer à utiliser la connexion à la base de données de l&#39;application d&#39;origine. Dans le cadre de la migration de Replit visant à séparer complètement les bases de données de développement et de production, les anciennes bases de données de développement partagées sont supprimées et les applications publiées doivent être migrées vers leur propre base de données de production.

Utilisez ce guide si votre application publiée affiche des erreurs de connexion à la base de données ou si `DATABASE_URL` dans le panneau Secrets pointe encore vers `neon.tech`.

<Warning>
  Les anciennes bases de données partagées seront arrêtées le **8 juin 2026**. Mettez à jour vos applications publiées avant cette date afin d&#39;éviter toute interruption de service ou toute perte permanente de données.
</Warning>

<div id="section">
  ## Avant de commencer
</div>

Les applications publiées nécessitent leur propre **base de données de production**. La base de données de développement affichée dans le panneau **Base de données** ne doit pas être utilisée directement par une application publiée.

<Frame>
  <img src="/assets/mirror/dev-database-5c024a6c134e.png" alt="Panneau Base de données affichant la base de données de développement" width="955" height="767" data-path="images/databases/shared-database-migration/dev-database.png" />
</Frame>

Pour résoudre ce problème, commencez par identifier votre situation :

* **Cas 1 :** Les données nécessaires sont déjà affichées dans le panneau **Base de données** de votre application.
* **Cas 2 :** Les données nécessaires ne s’affichent pas dans le panneau **Base de données**, car votre application publiée utilise encore l’ancienne base de données de développement partagée.

<div id="section-2">
  ## Comment savoir si votre application publiée utilise une base de données partagée
</div>

Votre application publiée est concernée si l’un des cas suivants s’applique :

* Des erreurs de connexion à la base de données s’affichent dans votre application publiée après la mise à niveau de la base de données
* L’application a été remixée à partir d’une autre application contenant une base de données **avant le 9 janvier 2026**

<div id="section-3">
  ## Vérifier si une application publiée utilise la base de données partagée de l’application source
</div>

<div id="1">
  ### Étape 1 : ouvrez le panneau de base de données de l’application source
</div>

<Frame>
  <img src="/assets/mirror/secret-pane-showing-secrets-763dd4c4845f.png" alt="Panneau Secrets affichant DATABASE_URL" width="792" height="418" data-path="images/databases/shared-database-migration/secret-pane-showing-secrets.png" />
</Frame>

Récupérez la valeur de `NEON_DATABASE_URL` ou, si elle n’existe pas, utilisez `DATABASE_URL`.

<Info>
  Toutes les applications concernées ne disposent pas de `NEON_DATABASE_URL`. Si vous ne le trouvez pas, utilisez le `DATABASE_URL` actuel des Secrets de l’application publiée s’il pointe toujours vers `neon.tech`.
</Info>

<div id="2publish">
  ### Étape 2 : ouvrez le panneau Publier de l’application publiée
</div>

<Frame>
  <img src="/assets/mirror/production-app-secrets-e4da45c53e36.png" alt="Secrets de l’application publiée affichant DATABASE_URL" width="1385" height="1225" data-path="images/databases/shared-database-migration/production-app-secrets.png" />
</Frame>

Pour vérifier l’URL de la base de données de l’application publiée :

1. Ouvrez l’application avec l’IA dans Replit
2. Ouvrez le panneau **Publier**
3. Ouvrez **Ajuster les paramètres**
4. Ouvrez **Secrets**
5. Recherchez `DATABASE_URL`

<div id="312url">
  ### Étape 3 : Comparez les URL des bases de données de l’application source de l’étape 1 et de l’application remixée de l’étape 2
</div>

Si elles sont identiques, l’application publiée utilise la base de données de développement Neon partagée par l’application source.

<div id="section-4">
  ## Comment copier des données de l’application source vers l’application publiée
</div>

Après avoir vérifié que votre application publiée utilise la base de données de développement partagée de l’application source, l’étape suivante consiste à y transférer les données nécessaires. Deux cas de figure sont à considérer :

* Cas 1 : le panneau **Base de données** de l’application publiée contient déjà les données nécessaires.
* Cas 2 : le panneau **Base de données** de l’application publiée ne contient pas les données nécessaires.

<div id="1-2">
  ### Cas 1 : les données nécessaires sont déjà affichées dans le panneau Base de données
</div>

Si les données nécessaires sont déjà affichées dans le panneau **Base de données** de votre application, c’est la méthode la plus simple.

<div id="1-3">
  #### Étape 1 : Vérifier la présence des données
</div>

<Frame>
  <img src="/assets/mirror/my-data-12834f2ebfd6.png" alt="Panneau de base de données affichant des lignes de données" width="865" height="454" data-path="images/databases/shared-database-migration/my-data.png" />
</Frame>

Ouvrez le panneau **Base de données** de l’application publiée et vérifiez que les tables et les données nécessaires sont présentes.

Si les données nécessaires ne s’affichent pas dans le panneau de base de données, arrêtez-vous ici. Suivez les étapes du [cas 2](#case-2-the-database-panel-does-not-show-the-data-you-need) pour migrer correctement les données.

<div id="2">
  #### Étape 2 : publier ou republier avec une base de données de production
</div>

1. Ouvrez l’application dans l’éditeur de projet
2. Sélectionnez **Publier** ou **Republier**
3. Activez **Créer une base de données de production**
4. Activez **Configurer la base de données de production avec les données de développement actuelles**
5. Terminez le processus de publication

La publication crée une nouvelle version de l’application publiée et associe automatiquement `DATABASE_URL` à la nouvelle base de données de production. Il n’est pas nécessaire de mettre à jour manuellement ce secret au cours de ce processus.

<Frame>
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="Paramètres de publication affichant l’option de création d’une base de données de production" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  La copie vers la production écrase les données de production existantes. Pour en savoir plus, consultez [Bases de données de production](/fr/ja/features/data-and-storage/development-and-production).
</Warning>

<div id="3">
  #### Étape 3 : Vérifiez l’application publiée
</div>

Ouvrez l’application publiée et vérifiez que vous pouvez accéder aux données et qu’elle fonctionne correctement.

<div id="2-2">
  ### Cas 2 : les données nécessaires ne s’affichent pas dans le panneau de base de données
</div>

Si les données nécessaires ne s’affichent pas dans le panneau **Base de données** de l’application publiée, exportez-les en suivant les étapes ci-dessous.

Si l’application publiée est toujours connectée à la base de données d’une autre application, un avertissement indiquant « Base de données externe détectée » s’affiche dans le panneau de base de données.

<Frame>
  <img src="/assets/mirror/external-database-detected-489d99632e74.png" alt="Panneau de base de données indiquant qu’une base de données externe a été détectée" width="1403" height="1208" data-path="images/databases/shared-database-migration/external-database-detected.png" />
</Frame>

<Warning>
  Si des utilisateurs utilisent encore l’application pour enregistrer de nouvelles données, prévoyez une courte fenêtre de maintenance avant de les exporter.
</Warning>

<div id="1-4">
  #### Étape 1 : exporter les données de l’ancienne base de données
</div>

<Frame>
  <img src="/assets/mirror/pg-dump-example-54c6c790ccb1.png" alt="Exemple de pg_dump" width="1252" height="450" data-path="images/databases/shared-database-migration/pg-dump-example.png" />
</Frame>

Dans l’éditeur de projet, ouvrez le **Shell**, puis exécutez la commande suivante :

```bash theme={null}
pg_dump -Fc "database_url" --no-owner --no-privileges -f backup.dump
```

`database_url` est l’URL de la base de données récupérée à l’étape 1 : [ouvrir le panneau de la base de données de l’application source](#step-1-open-the-database-panel-in-the-source-app).

<div id="2secretsdatabase_url">
  ### Étape 2 : supprimer l’ancien `DATABASE_URL` des Secrets de l’application
</div>

<Frame>
  <img src="/assets/mirror/secret-pane-eb253120f8a6.png" alt="Exemple de panneau Secrets" width="1410" height="1184" data-path="images/databases/shared-database-migration/secret-pane.png" />
</Frame>

1. Ouvrez l’outil **Secrets** dans l’éditeur du projet
2. Repérez l’ancien `DATABASE_URL`
3. Supprimez-le
4. Actualisez la page ou rouvrez le panneau **Base de données**

L’application ne référencera alors plus l’ancienne base de données partagée et utilisera à nouveau la base de données de développement actuelle.

<div id="3-2">
  ### Étape 3 : importer les données dans la base de données de développement actuelle
</div>

<Frame>
  <img src="/assets/mirror/pg-restore-example-409ae4d7bf09.png" alt="Exemple de pg_restore" width="802" height="426" data-path="images/databases/shared-database-migration/pg-restore-example.png" />
</Frame>

Une fois l’ancien secret `DATABASE_URL` supprimé, la base de données de développement actuelle de l’application redevient disponible sous la forme de `$DATABASE_URL` dans l’éditeur du projet.

Revenez au **Shell** de l’éditeur du projet et exécutez la commande suivante :

```bash theme={null}
pg_restore --clean --if-exists --single-transaction --no-owner --no-privileges --exit-on-error -d "$DATABASE_URL" backup.dump
```

Les données exportées sont alors importées dans la base de données de développement actuelle de votre application.

<div id="51">
  ### Étape 5 : publier ou republier avec la base de données de production en suivant le cas 1
</div>

Lorsque les bonnes données s’affichent dans le panneau **Base de données**, suivez le [cas 1](#case-1-the-database-panel-already-shows-the-data-you-need) pour **créer la base de données de production**, y copier les données, puis publier ou republier.

<div id="6">
  ### Étape 6 : Vérifier l’application publiée
</div>

<Frame>
  <img src="/assets/mirror/successful-export-bfb997304cc1.png" alt="Exportation réussie" width="965" height="554" data-path="images/databases/shared-database-migration/successful-export.png" />
</Frame>

Ouvrez l’application publiée et vérifiez que vous pouvez accéder aux données et qu’elle fonctionne correctement.

<div id="section-5">
  ## Dépannage
</div>

<div id="section-6">
  ### L’importation échoue car la table existe déjà
</div>

La commande `pg_restore --clean --if-exists` ci-dessus supprime les objets correspondants avant de les restaurer à partir du dump.

<div id="section-7">
  ### L’importation échoue en raison d’erreurs de rôles ou de politiques
</div>

Si votre base de données utilise des rôles PostgreSQL personnalisés ou des politiques basées sur les rôles, l’importation peut échouer, car ces rôles n’existent pas encore dans la nouvelle base de données.

La migration automatique Helium de Replit tente de recréer les rôles fictifs avant la restauration, mais ce n’est pas le cas du processus manuel ci-dessus. Si vous rencontrez des erreurs liées aux rôles lors de `pg_restore`, [contactez le support](https://replit.com/support).

<div id="section-8">
  ### Si vous avez déjà corrigé votre application
</div>

Si votre application publiée dispose déjà de sa propre base de données de production et fonctionne correctement, vous n’avez rien d’autre à faire.

<div id="section-9">
  ## Si vous avez besoin d&#39;aide supplémentaire
</div>

Si vous ne savez pas quel cas s&#39;applique à votre application ou si vous rencontrez des problèmes lors de la migration, [contactez l&#39;assistance](https://replit.com/support).
