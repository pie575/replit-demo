<div id="section">
  ## Что такое система задач?
</div>

**Задача** — это единица работы, которую Agent может спланировать и выполнить. Задачи позволяют Agent разбить крупную цель на небольшие части, каждую из которых можно проверить до того, как изменения попадут в приложение.

Agent работает в двух местах: в **главном потоке** и в **фоновых задачах**. Главный поток — это диалог, в котором вы описываете, что хотите получить, уточняете направление и решаете, что применить к основной версии. Фоновая задача — это отдельный поток, в котором Agent работает самостоятельно с изолированной копией проекта.

Используйте главный поток для задания направления и принятия решений, а фоновые задачи — для работы, которую можно выполнять параллельно. Фоновые задачи не меняют основную версию, пока вы не проверите и не примените результат.

Система задач — это способ, которым Agent организует свою работу. Вы описываете, что хотите создать, а Agent разбивает запрос на отдельные задачи и размещает их на доске со столбцами **Черновик**, **В работе**, **Готово к проверке** и **Завершено**.

</Frame>

По мере продвижения каждая задача перемещается слева направо, поэтому вы сразу видите, что запланировано, над чем работает Agent, что ожидает проверки и что уже завершено. Фоновые задачи автоматически ставятся в очередь на основе плана, поэтому работа идёт, не перегружая главный поток.

Когда задача готова к проверке, вы просматриваете изменения и применяете их к основной версии либо отклоняете, если результат вас не устраивает.

<div id="section-2">
  ## Как работают фоновые задачи
</div>

<Steps>
  <Step title="Планирование задач">
    Начните разговор в основном потоке или создайте новый поток и спланируйте задачи в нём. Agent проанализирует проект, определит наиболее важные задачи и подготовит подробный план для каждой из них: что нужно сделать и каким будет результат.

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="Описание того, что нужно создать, в основном потоке, где Agent предлагает и выполняет задачи" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="Проверка и утверждение">
    Agent предложит набор задач — у каждой будут название, описание и подробный план, доступный по кнопке **Показать план**. Просмотрите список и выберите действие:

    * **Утвердить задачи**：запустить все задачи в фоновом режиме
    * **Изменить план**：попросить Agent скорректировать задачи перед запуском

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="Диалог планирования задач с четырьмя предложенными задачами и вариантами «Утвердить задачи» и «Изменить план»" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="Запуск задач">
    После утверждения задачи начинают выполняться в изолированных копиях проекта. Core позволяет одновременно выполнять одну фоновую задачу, а Pro поддерживает до 10 параллельных фоновых задач. Основная версия останется без изменений, пока вы не примените изменения. Отслеживать прогресс можно двумя способами:

    * **Представление потока**：каждая задача выполняется в отдельном потоке с индикатором статуса в реальном времени, поэтому вы можете отслеживать обсуждение любой задачи или участвовать в нём

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="Представление потока, в котором несколько задач выполняются параллельно с индикаторами статуса" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **Представление доски**：доска со столбцами, которая распределяет все задачи по статусам **Черновик**, **В процессе**, **Готово к проверке** и **Завершено**

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="Представление доски с задачами, упорядоченными по столбцам «Черновик», «В процессе», «Готово к проверке» и «Завершено»" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="Проверка и применение">
    Когда задача будет завершена, Agent покажет результаты работы: журнал, результаты тестов и предварительный просмотр изменений в реальном времени. Затем выберите дальнейшее действие:

    * **Применить изменения к основной версии**：объединить результаты работы задачи с проектом
    * **Отклонить**：отменить нежелательные изменения

    При применении изменений из нескольких задач Agent автоматически разрешает конфликты.

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="Экран проверки задач с журналом работы Agent, результатами тестов и кнопкой применения изменений" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="section-4">
  ## Что можно создать
</div>

Система задач подходит для любых проектов. Вот несколько особенно эффективных сценариев:

* **Разбивайте большие функции на небольшие части и выпускайте их поэтапно**: выделите аутентификацию, панель управления и API-слой в отдельные задачи, чтобы Agent мог последовательно их выполнять
* **Планируйте сложные проекты**: разбивайте большие функции на чётко определённые задачи с зависимостями и уверенно реализуйте их
* **Сравнивайте разные дизайн-направления**: используйте отдельные задачи, чтобы опробовать несколько подходов к UI и выбрать лучший вариант

<div id="section-5">
  ## Частые вопросы
</div>

<Accordion title="Нужно ли менять подход к разработке?">
  Нет. Главный поток работает точно так же. Agent автоматически создаёт задачи в фоне, когда это полезно. Вы также можете явно просматривать задачи и управлять ими в [режиме Plan](/ru/ja/features/agent/plan-mode).
</Accordion>

<Accordion title="Почему задачи выполняются по одной?">
  На плане Core одновременно выполняется только одна фоновая задача. Pro поддерживает до 10 параллельных фоновых задач. При достижении лимита плана дополнительные задачи помещаются в очередь и запускаются, как только освободится слот.
</Accordion>

<Accordion title="Как Agent обрабатывает конфликты при применении фоновых задач?">
  Agent использует разрешение конфликтов на базе ИИ. Он понимает, чего должна была добиться каждая задача, и применяет изменения осмысленно. Если что-то выглядит не так, попросите Agent исправить это прямо в треде.
</Accordion>

<Accordion title="Могут ли задачи зависеть друг от друга?">
  Да. Agent определяет зависимости автоматически. Например, задача по созданию панели управления зависит от задачи по созданию схемы базы данных. Зависимые задачи ждут, пока будут выполнены необходимые для них.
</Accordion>

<Accordion title="Чем архивирование отличается от отмены?">
  **Архивирование** применяется к сессиям планирования — черновикам, разработка по которым ещё не началась. Архивированные сессии планирования сохраняются, и их можно восстановить из столбца **Завершено**.

  **Отмена** применяется к задачам, которые перешли от планирования к разработке. Отмена останавливает задачу и отбрасывает результаты её работы; отменённые задачи восстановить нельзя. В этом случае запустите новую задачу.
</Accordion>
