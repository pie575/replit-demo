<div id="section">
  ## Введение
</div>

<Note>
  SCIM доступен только клиентам Enterprise. Чтобы включить эту функцию для вашей организации, обратитесь в отдел продаж по адресу [sales@replit.com](mailto:sales@replit.com).
</Note>

Система междоменного управления идентификацией ([SCIM](https://en.wikipedia.org/wiki/System_for_Cross-domain_Identity_Management)) — это стандартизированный протокол, автоматизирующий подготовку учётных записей и отмену подготовки учётных записей пользователей между корпоративным поставщиком удостоверений (IdP) и Replit.

После включения SCIM вы можете напрямую в Replit управлять сопоставлением синхронизированных групп и участников с рабочими пространствами и ролями Replit. Подробнее см. в разделе [Управление доступом к рабочему пространству](#managing-workspace-access).

<div id="section-3">
  ## Преимущества
</div>

Интеграция SCIM предоставляет командам Enterprise ряд преимуществ:

* **Повышенная безопасность**: используйте существующую систему управления идентификацией для надежного контроля доступа
* **Упрощённое управление**: автоматически управляйте участниками команды через поставщика удостоверений
* **Эффективное подключение новых сотрудников**: без ручного вмешательства легко выполняйте подготовку учётных записей для больших команд
* **Единообразный контроль доступа**: поддерживайте единые политики доступа во всей организации

    Откройте портал настройки SCIM прямо из настроек идентификации и управления. На портале представлены пошаговые инструкции для конкретного поставщика удостоверений по синхронизации каталога пользователей.
  </Step>

  <Step title="Протестируйте интеграцию">
    Создайте тестового пользователя, чтобы проверить подключение.
  </Step>

  <Step title="Перейдите к работе в рабочей среде">
    Начните использовать SCIM для автоматизированного управления участниками, а затем назначьте синхронизированные группы рабочим пространствам в разделе [Доступ к рабочему пространству через SCIM](#managing-workspace-access).
  </Step>
</Steps>

<div id="section-5">
  ## Лучшие практики
</div>

* Перед включением SCIM задокументируйте назначения ролей существующих участников Replit.
* Настройте рабочее пространство по умолчанию, чтобы все синхронизированные группы получали как минимум доступ **Наблюдатель**. Если рабочее пространство по умолчанию не задано, участники не получат ролей, пока вы не назначите группы рабочему пространству.
* Перед включением массовой подготовки учётных записей протестируйте её на небольшой группе участников.
* После первоначальной синхронизации проверьте и настройте разрешения пользовательских групп в соответствии с потребностями организации в контроле доступа.
* Используйте отдельные группы для управления ролями и уровнями доступа участников с подготовленными учётными записями, а другие push-группы — для категоризации и массового управления разрешениями.
* Задокументируйте настройки SCIM для дальнейшего использования.

<div id="section-6">
  ## Синхронизация групп
</div>

Все группы, переданные из IdP, синхронизируются с Replit вместе с участниками, которых IdP подготавливает для этих групп. При передаче группы «Инженеры» через SCIM Replit создаёт соответствующую группу с этими подготовленными участниками.

Состав групп автоматически обновляется в соответствии с составом групп в IdP. Эти синхронизированные группы можно использовать для массового изменения разрешений участников — например, чтобы предоставить доступ к приложению всем участникам группы «Инженеры».

<div id="microsoft-entra-id">
  ### Использование плоских групп в Microsoft Entra ID
</div>

<Warning>
  Microsoft Entra ID подготавливает только пользователей, которые являются непосредственными участниками явно назначенных групп. Вложенные группы не разворачиваются. Пользователи, состоящие только в подгруппах, не добавляются в родительскую группу Replit. Если пользователь не указан напрямую в другой назначенной группе, Microsoft Entra ID не подготовит его.
</Warning>

Используйте плоские группы для SCIM-подготовки, добавляя пользователей непосредственно в каждую группу, назначенную Replit. Если вам необходимо сохранить вложенные группы в Microsoft Entra ID, назначьте приложению Replit все группы, непосредственно содержащие пользователей. Подробнее см. в [руководстве Microsoft по области действия на основе назначений](https://learn.microsoft.com/en-us/entra/identity/app-provisioning/how-provisioning-works#assignment-based-scoping).

<div id="scim">
  ### Создание пользовательских групп наряду с SCIM
</div>

Вы можете создавать пользовательские группы в Replit, даже если SCIM включён. Используйте их, чтобы объединять участников по проектам, для разового назначения прав доступа и в других случаях, не отражённых в поставщике удостоверений.

* **Группы SCIM остаются заблокированными**. Группы, синхронизированные из IdP, можно редактировать или удалять только через поставщика удостоверений.
* **Пользовательские группы управляются в Replit**. Администраторы организации могут создавать, редактировать и удалять пользовательские группы непосредственно на странице групп.
* **Участники могут состоять в группах обоих типов**. Участников, подготовленных через SCIM, также можно добавлять в пользовательские группы, не затрагивая роли, управляемые IdP.

Подробнее о группах см. в разделе [Группы и разрешения](/ru/ja/teams/identity-and-access-management/groups-and-permissions).

<div id="section-7">
  ## Управление доступом к рабочему пространству
</div>

После включения SCIM используйте встроенную панель управления, чтобы просматривать и настраивать сопоставление синхронизированных групп с рабочими пространствами и ролями, а также назначать группу администраторов аккаунта. IdP остаётся достоверным источником данных о членстве и подготовке пользователей. На этом экране можно управлять сопоставлением синхронизированных групп и участников с рабочими пространствами и ролями Replit, но нельзя добавлять, удалять или повторно подготавливать пользователей.

<div id="section-8">
  ### Настройка рабочего пространства
</div>

Как правило, рекомендуется объединять участников в **одном рабочем пространстве** и создавать дополнительные рабочие пространства только при наличии веских причин не делить между ними участников, группы и бюджеты — например, для разных подразделений. Все участники, которым необходимо работать вместе, должны находиться в одном рабочем пространстве.

Вы можете назначать синхронизированные группы рабочему пространству. В рабочем пространстве назначенные группы отображаются как **пользовательские группы** и могут использоваться для управления на уровне рабочего пространства, например для настройки **бюджетов групп** (например, бюджета в 100 000 для команды Revenue).

<div id="scim-2">
  ### Открытие доступа SCIM к рабочему пространству
</div>

1. Откройте переключатель рабочих пространств и выберите рабочее пространство Enterprise.
2. Откройте **Настройки** и выберите **Расширенные настройки**.
3. Разверните раздел **Идентификация и управление** и найдите карточку **Автоматическое добавление участников (SCIM)**.
4. Когда SCIM станет **активным**, панель управления появится непосредственно в этой карточке.

<div id="section-9">
  ### Назначение группы администраторов аккаунта
</div>

Сначала настройте этот параметр. В верхнем блоке **Группа администраторов аккаунта** отображается синхронизированная с IdP группа, участники которой имеют роль администратора аккаунта во всех рабочих пространствах и доступ к настройкам на уровне аккаунта, включая разрешения на управление SCIM.

Выберите **Изменить**, чтобы назначить другую синхронизированную группу. При смене группы новая группа становится группой администраторов аккаунта, а роль администратора аккаунта у предыдущей группы отзывается. Администраторы аккаунта обладают широкими полномочиями, поэтому перед применением изменений потребуется подтверждение.

</Note>

<div id="section-10">
  ### Просмотр и управление назначениями рабочих пространств
</div>

На вкладке **Рабочие пространства** перечислены все рабочие пространства организации, назначенные синхронизированные группы и роли каждой группы.

**Рабочее пространство по умолчанию** — отмеченное меткой **По умолчанию** — является основой для предоставления доступа. Все синхронизированные группы автоматически получают в нём как минимум уровень доступа **Наблюдатель**, поэтому у участников всегда есть точка входа. Рабочее пространство становится рабочим пространством по умолчанию, только если его настроил администратор. До этого участники получают доступ только через назначенные вами группы.

* Используйте поле поиска, чтобы отфильтровать рабочие пространства по имени.
* В каждой строке **назначения групп** отображаются в виде меток в формате *группа · роль* (например, *Engineering · Admin*). Если назначения рабочего пространства не помещаются в одну строку, оставшиеся обозначаются меткой **+ N ещё**.
* Меню **⋮** в строке позволяет редактировать назначения, а также назначить рабочее пространство рабочим пространством по умолчанию для организации или отменить это назначение.

<div id="section-11">
  ### Назначение групп рабочему пространству и настройка ролей
</div>

В меню**⋮** в строке рабочего пространства выберите **Изменить назначения**, чтобы открыть диалоговое окно **Изменить доступ к рабочему пространству**. Здесь можно выбрать синхронизированные группы, которым доступно рабочее пространство, и назначить роль для каждой из них:

* **Администратор** — полный административный доступ к настройкам и ресурсам рабочего пространства.
* **Участник** — может создавать и редактировать Replit App.
* **Наблюдатель** — доступ только для чтения к App и деплоям.
* **Гость** — может получать доступ только к предоставленным App.

Разрешения группы администраторов аккаунта (обозначенные значком замка) заблокированы. Они управляются в рамках назначения администраторов аккаунта, а не отдельно для каждого рабочего пространства.

<div id="section-13">
  ## Ограничения
</div>

* **IdP остаётся источником достоверных данных.** Добавление, удаление и подготовка участников, а также изменение состава групп выполняются у поставщика удостоверений. Replit управляет *назначением* рабочих пространств и ролей группам, уже существующим в синхронизированном каталоге.
* **Microsoft Entra ID не разворачивает вложенные группы.** Используйте плоские группы, как описано в разделе [Использование плоских групп с Microsoft Entra ID](#use-flat-groups-with-microsoft-entra-id), или назначьте приложению Replit все группы, непосредственно содержащие пользователей.
* **Группу администраторов аккаунта можно изменить, но нельзя удалить.** Вы можете указать другую группу администраторов аккаунта, но нельзя оставить организацию без группы администраторов.

<div id="faq">
  ## Часто задаваемые вопросы
</div>

<div id="scimreplitcom">
  ### Что происходит с участниками, у которых уже есть аккаунт на replit.com до настройки SCIM?
</div>

После включения SCIM существующие участники обрабатываются двумя способами:

1. **Участники, подготовленные через SCIM**：
   * Их роли обновляются на основе данных, предоставленных IdP.
   * Добавлять и удалять этих участников, а также изменять их роли можно только через IdP.
   * Для поддержания синхронизации прав администраторы больше не смогут редактировать роли или приглашать новых участников в Replit.
2. **Участники, не подготовленные через SCIM**：
   * Эти участники не изменяются и считаются «устаревшими».
   * Их членство в организации и роли не удаляются автоматически, чтобы предотвратить ошибочную отмену подготовки.
   * При необходимости администраторы организации могут удалить устаревших участников через интерфейс Replit.

<Warning>
  После внедрения SCIM всеми участниками, подготовленными через IdP, необходимо управлять через IdP, чтобы поддерживать синхронизацию. Только для устаревших участников (не подготовленных через SCIM) можно отменить подготовку непосредственно в Replit.
</Warning>

<div id="scim-3">
  ### Какие роли можно назначить через SCIM?
</div>

Пользователям SCIM можно назначить одну из четырёх ролей:

* **Admin**: полный доступ к настройкам и ресурсам организации
* **Member**: стандартный доступ для создания и редактирования приложений Replit
* **Guest**: ограниченный доступ для внешних участников. Можно редактировать только приложения, к которым был явно предоставлен доступ
* **Viewer**: доступ к опубликованным приложениям только для чтения

Сопоставление групп IdP с ролями Replit настраивается отдельно для каждого рабочего пространства в разделе [Доступ к рабочему пространству через SCIM](#managing-workspace-access). Например, группе «Engineering» можно назначить роль Member в одном рабочем пространстве, а роль Viewer — в другом.

<div id="scim-4">
  ### Можно ли добавлять или удалять участников через Доступ к рабочему пространству через SCIM?
</div>

Нет. Членство и подготовка учётных записей управляются поставщиком удостоверений. На этом экране вы настраиваете сопоставление синхронизированных групп и участников с рабочими пространствами и ролями. О повседневном управлении участниками вне SCIM см. в разделе [Управление участниками](/ru/ja/teams/identity-and-access-management/managing-members).

<div id="section-14">
  ### Чем роли отличаются от групп?
</div>

Группы синхронизируются из IdP. Роли (администратор, участник, наблюдатель, гость) определяют, что группа может делать в конкретном рабочем пространстве. Одна и та же группа может иметь разные роли в разных рабочих пространствах: например, быть **участником** в одном рабочем пространстве и **наблюдателем** в другом.

<div id="section-15">
  ### Влияет ли изменение группы администраторов аккаунта на другие роли?
</div>

При назначении новой группы администраторов аккаунта изменяется только роль администратора аккаунта на уровне всей организации. Назначения других групп и рабочих пространств, а также связанные с ними роли остаются без изменений. Подробнее о ролях администраторов аккаунта см. в разделе [Администраторы аккаунта и рабочего пространства](/ru/ja/teams/identity-and-access-management/account-and-workspace-admins).
