Нажатие кнопки **Опубликовать** запускает короткий процесс, в результате которого ваше приложение становится доступным пользователям. На этой странице описано, что происходит во время публикации, как обновить приложение и где им управлять после публикации.

<div id="the-publishing-stages">
  ## Этапы публикации
</div>

Publishing проходит в пять этапов и обычно занимает минуту-две. Следить за ходом можно по индикатору выполнения в инструменте Publishing: выберите **View логи**, чтобы увидеть подробности, или **Cancel**, чтобы прервать текущую публикацию.

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Обзор Publishing с индикатором из пяти этапов: Provision завершён, Security checks и Build выполняются, Bundle и Promote ожидают" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision**: Replit готовит облачные ресурсы, на которых будет работать ваше приложение, — серверы и продакшен-базу данных.
2. **Security checks**: Replit проверяет приложение на проблемы безопасности — небезопасные зависимости или раскрытые секреты — ещё до запуска.
3. **Build**: Replit превращает ваш project в продакшен-версию приложения — оптимизированную сборку, которая работает в вебе.
4. **Bundle**: собранное приложение упаковывается в единый готовый к запуску пакет.
5. **Promote**: Replit готовит новую версию параллельно с текущей, а затем переключает на неё ваш URL.

<Note>
  Publishing охватывает весь ваш project: все artifact в нём — приложение, презентации, документы — публикуются вместе.
</Note>

<Accordion title="Что происходит за кулисами">
  Для тех, кому интересны технические подробности: Provision выделяет инфраструктуру deployment для выбранных вами типа deployment и региона. Security checks запускают сканирование зависимостей и кода и могут заблокировать публикацию при обнаружении критических уязвимостей — в зависимости от ваших настроек безопасности. Build выполняет вашу команду сборки и компилирует ресурсы для продакшена. Bundle упаковывает результат сборки в развёртываемый образ. Promote выполняет переключение: новая версия начинает обслуживать запросы по вашему URL, заменяя предыдущий deployment.
</Accordion>

После завершения всех этапов приложение работает вживую. Выберите URL в инструменте Publishing, чтобы открыть его.

<div id="update-your-app">
  ## Обновление приложения
</div>

После внесения изменений снова нажмите **Опубликовать**. Приложение обновится по тому же URL-адресу, и посетители увидят актуальную версию при следующей загрузке. Отправлять новую ссылку не придётся.

<div id="manage-your-live-app">
  ## Управление опубликованным приложением
</div>

Инструмент Publishing также позволяет управлять приложением после публикации:

* **Следите за состоянием**: проверяйте, работает ли приложение, просматривайте логи и отслеживайте использование ресурсов. Подробнее — в разделе [мониторинг](/ru/features/publishing/monitoring-a-deployment).
* **Смотрите, кто заходит**: графики запросов и трафика находятся в разделе [Мониторинг](/ru/features/publishing/monitoring-a-deployment), а данные о посетителях и пользователях — на панели **Growth**.
* **Меняйте права доступа**: отмените публикацию, выберите другой вариант доступа и опубликуйте приложение снова. Подробнее — в разделе [доступ к приложению](/ru/features/publishing/private-deployments).
* **Подключайте домен**: задайте приложению собственный веб-адрес. Подробнее — в разделе [пользовательские домены](/ru/features/publishing/custom-domains).
