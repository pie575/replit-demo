当你在 Replit 上发布 web app 时，系统会自动针对线上 URL 运行一次搜索引擎优化 (SEO) 审计，并在 Publishing 工具中给出 SEO 评分。如果评分还有提升空间，只需一次点击，即可把具体问题交给 Agent，几秒内就能修复。

对大多数开发者来说，整个流程就是：发布应用，看一眼评分，然后让 Agent &quot;优化我的 SEO&quot;。本页将介绍其背后的运作机制，以及如何充分利用这项功能。

<div id="what-is-seo-and-why-it-matters">
  ## 什么是 SEO，为什么它很重要
</div>

搜索引擎优化 (SEO) 是指按照一定的方式搭建网站，让 Google 等搜索引擎能够发现、理解并为它排名。SEO 做得好，意味着当人们搜索你所提供的内容时，你的应用就会出现在结果中——而且无需投放广告。

决定 SEO 效果的主要就是这么几件事：清晰的页面标题和描述、语义化的 HTML、快速的加载速度、适配移动端的布局、图片上具有描述性的替代文本，以及便于抓取的网站结构。搜索引擎更青睐那些对人和机器都易于读取的网站。

如果你要发布落地页、营销站点、博客、目录网站，或任何看重可发现性的内容，那么 SEO 就是你在早期最值得投入、回报最高的事情之一。

<div id="how-replit-improves-your-seo-out-of-the-box">
  ## Replit 如何开箱即用地提升你的 SEO
</div>

Replit 已为你打理好大量 SEO 基础工作，让你专注于内容和产品：

* **快速、全球分布式托管**：Replit Deployments 依托针对速度优化的基础设施运行你的应用，你还可以通过 [Project geography](/zh/features/publishing/project-geography) 选择应用的运行地区。
* **默认启用 HTTPS**：每个已发布的应用都会获得由 Replit 托管的 TLS 证书，这是搜索引擎的基础排名信号之一。
* **自定义域名**：接入你自己的域名，建立信任度与品牌权威。参见 [Custom Domains](/zh/features/publishing/custom-domains)。
* **面向内容站点的 Static Deployments**：对于营销页面、博客和文档，[Static Deployments](/zh/features/publishing/deployment-types#static) 提供预渲染的 HTML，便于搜索引擎抓取。
* **Agent 编写兼顾 SEO 的代码**：Agent 构建页面时，默认会生成语义化 HTML、无障碍标记和 meta 标签——正是 SEO 工具会检查的那些内容。
* **SEO 评分**：发布后自动进行审计，让你随时了解站点状况，还可一键交给 Agent 修复发现的问题。

<div id="where-to-find-it">
  ### 在哪里查看
</div>

在已发布的应用中打开 **Publishing** 工具。SEO 评分会与其他构建详情一起显示在 deployment 概览中。将鼠标悬停在评分上，即可查看 Lighthouse 针对每个页面标记出的具体改进事项。

<Note>
  如果没有看到 SEO 评分，很可能是因为你的应用为私有，或者近期未发布过。该评分仅对已发布的公开 Web 应用显示。
</Note>

<div id="how-to-read-your-rating">
  ### 如何解读评级
</div>

Replit 会根据 Lighthouse 审计结果给出以下三种评级之一：

| 评级   | 含义                            |
| :--- | :---------------------------- |
| 良好   | 你的应用符合 SEO 最佳实践。重大改动后请留意评级变化。 |
| 有待改进 | 存在若干问题，影响搜索引擎理解你的应用。          |
| 较差   | 缺少重要的 SEO 基础项，修复通常只需几分钟。      |

如果你的应用包含多个页面，徽章会显示 Replit 抓取的所有 URL 中**最低**的评级，这样表现最差的页面会优先暴露出来，而不会被平均值掩盖。

<div id="when-the-rating-is-calculated">
  ### 评分的计算时机
</div>

每次成功发布后，审查都会自动运行。评分通常会在 deployment 上线后的一两分钟内出现，结果一生成，Publishing 工具就会刷新徽章。

<div id="supported-deployment-types">
  ### 支持的部署类型
</div>

SEO 评分仅针对搜索引擎可抓取 URL 的公开 Web 部署计算：

* [Autoscale 部署](/zh/features/publishing/deployment-types#autoscale)
* [Reserved VM 部署](/zh/features/publishing/deployment-types#reserved-vm)
* [Static 部署](/zh/features/publishing/deployment-types#static)

定时部署和私有部署不会生成 SEO 评分，因为它们不承载公开的 Web 流量。

<div id="optimize-seo-with-agent">
  ## 使用 Agent 优化 SEO
</div>

评分旁边会出现一个 **Optimize SEO with Agent** 按钮。点击后会在 Growth 面板中打开 [SEO Agent](/zh/features/publishing/seo-agent)，你可以在其中运行技术性 SEO 审计、查看检测出的问题，并一键应用修复。

<Tip>
  你也可以完全不用这个按钮。打开 Agent，输入 **“optimize my
  SEO”** —— Agent 会读取你最新的检测结果并逐项处理。
</Tip>

Agent 完成修改后，请重新发布你的应用。SEO 评分会基于新的构建重新计算，徽章也会自动更新。

Agent 常见的修复包括：

* 添加或改写缺失、过于笼统的 `<title>` 标签，让每个页面都有独特且具描述性的标题
* 为每个页面添加 meta description
* 为图片添加描述性的 `alt` 文本
* 为 `<html>` 元素设置 `lang` 属性
* 确保链接文本含义明确 (避免“click here”或空锚文本)
* 添加 `robots.txt` 和 `sitemap.xml`
* 添加 viewport meta 标签以适配移动端渲染
* 改善未通过无障碍检查的文本颜色对比度
* 添加 Open Graph 和 Twitter card meta 标签，让指向你应用的链接在社交平台上有良好的预览效果

<div id="best-practices-for-an-seo-optimized-site-on-replit">
  ## 在 Replit 上打造 SEO 优化站点的最佳实践
</div>

无论你是让 Agent 代劳,还是自己动手编写,以下这些都是在 Replit 构建的应用中最值得做好的事项:

* **为每个页面设置独一无二的标题和 meta 描述。** 标题尽量控制在 60 个字符以内,描述保持在 150–160 个字符左右。
* **使用语义化 HTML。** 用 `<main>`、`<header>`、`<nav>` 和 `<footer>` 包裹页面布局。每个页面只使用一次 `<h1>`,并按顺序逐级使用标题层级。
* **为每张图片添加 alt 文本。** 描述图片呈现的内容,而不只是它是什么。
* **生成 `sitemap.xml` 和 `robots.txt`。** 让 Agent 创建这两个文件,以便搜索引擎知道该抓取哪些内容。
* **添加 Open Graph 和 Twitter card 标签。** 掌控应用分享到社交媒体时的呈现效果。
* **使用自定义域名。** 带有品牌的域名能同时赢得访客和搜索引擎的信任。参见[自定义域名](/zh/features/publishing/custom-domains)。
* **选择合适的 deployment 类型。** 对于内容密集型站点,[静态 Deployments](/zh/features/publishing/deployment-types#static) 提供预渲染的 HTML,搜索引擎可以即时解析。
* **添加结构化数据。** JSON-LD 标记能帮助搜索引擎为商品、文章、常见问题和活动展示丰富结果。
* **保持应用快速响应。** 优化图片、避免阻塞渲染的脚本,并借助 Replit 的托管能力降低响应时间。

想一次性搞定其中大部分事项,可以试试下面这个简单方法:

<AiPrompt>
  审查我的站点是否符合 SEO 最佳实践并应用修复。添加 sitemap、
  robots.txt、Open Graph 标签,在合适的地方加入结构化数据,并确保
  每个页面都有独一无二的标题和 meta 描述。
</AiPrompt>
