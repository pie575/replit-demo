Il s&#39;agit d&#39;une séquence d&#39;étapes réutilisable et personnalisable qui peut être exécutée au sein de votre Replit App. Elle peut être aussi simple que l&#39;exécution de `python main.py` ou aussi complexe qu&#39;une procédure en plusieurs étapes.

  <img src="/assets/mirror/workflows-pane-e7d5e4251006.png" alt="image" width="525" height="622" data-path="images/workflows/workflows-pane.png" />

Exemples de cas d&#39;usage :

* Exécuter plusieurs services en parallèle (ex. : frontend + backend)
* Exécuter des fichiers ou des commandes de manière séquentielle (ex. : lancer le linter → lancer les tests, compiler → exécuter le code)

Pour commencer à [créer des workflows](#creating-workflows), ouvrez le panneau Workflows depuis le menu de la barre latérale d&#39;outils ou recherchez-le avec `Command + K`.

<div id="tipos-de-tarefas-disponveis">
  ## Types de tâches disponibles
</div>

Il existe actuellement 3 types de tâches : `Execute Shell Command`, `Install Packages` et `Run Workflow`.

<div id="execute-shell-command">
  ### Execute Shell Command
</div>

`Execute Shell Command` enregistre une commande shell et l&#39;exécute dans le même environnement que le panneau Shell. Ce type de tâche couvre un large éventail de cas d&#39;usage, de l&#39;exécution de fichiers individuels :

```text theme={null}
python main.py
```

jusqu&#39;à l&#39;exécution de commandes complexes de requêtes sur des bases de données stockées :

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Install Packages
</div>

`Install Packages` s&#39;appuie sur le système intégré de gestion des dépendances de Replit : il détecte automatiquement les dépendances de votre projet et installe les packages nécessaires. Consultez [Gestion des dépendances](/fr/pt/references/workspace/dependency-management#the-universal-package-manager) pour en savoir plus sur la façon dont UPM détermine les packages à installer dans votre projet.

<div id="run-workflow">
  ### Exécuter un workflow
</div>

`Run Workflow` vous permet d&#39;exécuter un autre workflow à partir du workflow actuel. Vous pouvez ainsi réutiliser et combiner des workflows pour créer des workflows plus complexes.

Exemple de cas d&#39;utilisation :

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />

En utilisant ce type de tâche pour créer des dépendances entre les workflows, vous pouvez modifier un workflow et les autres workflows qui y font référence utiliseront automatiquement les dernières modifications. Notez qu&#39;il existe une limite de profondeur pour les appels de workflows fortement imbriqués.

<div id="modo-de-execuo-do-workflow">
  ## Mode d&#39;exécution des Workflows
</div>

Les Workflows offrent deux modes d&#39;exécution : séquentiel et parallèle.

<div id="sequencial">
  ### Séquentiel
</div>

L’exécution séquentielle lance chaque tâche dans l’ordre défini, en attendant la fin de chacune avant de passer à l’étape suivante. Elle s’interrompt si une tâche du workflow échoue.

Ce mode permet par exemple de définir des commandes liées logiquement, comme des commandes Git pour récupérer les dernières modifications de votre branche principale, puis rebaser votre branche actuelle sur celle-ci :

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="image" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="paralelo">
  ### Parallèle
</div>

L’exécution parallèle lance chaque tâche indépendamment des autres tâches du workflow. L’échec d’une tâche n’interrompt pas l’exécution des autres.

Ce mode est par exemple utile pour exécuter un projet full stack qui doit lancer à la fois le serveur frontend et le backend :

<div id="criando-workflows">
  ## Créer des Workflows
</div>

Vous pouvez créer des Workflows depuis le panneau des workflows en cliquant sur le bouton `+ New Workflow`. Commencez par donner un nom explicite à votre workflow, choisissez un mode d&#39;exécution adapté, puis ajoutez vos tâches. Vous pouvez réorganiser les tâches par glisser-déposer, dans l&#39;ordre souhaité.

<div id="atribuir-workflow-ao-boto-run">
  ## Associer un Workflow au bouton Run
</div>

Vous pouvez également associer un workflow au bouton Run afin de remplacer son comportement par défaut (voir [Configurer une Replit App](/fr/pt/references/configuration/configuration)). Pour conserver la commande d’exécution par défaut configurée dans `.replit`, sélectionnez l’option « Run Replit App » dans le menu déroulant.

Le workflow sélectionné dans le menu déroulant à côté du bouton Run s’exécute lorsque vous cliquez sur ce bouton. Cliquez sur le workflow souhaité dans le menu déroulant pour modifier celui exécuté par le bouton Run.
