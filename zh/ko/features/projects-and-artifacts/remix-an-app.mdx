<div id="section">
  ## 什么是 Remix
</div>

**Remix** 是基于你当前有权访问的应用创建的全新 Replit 应用。Remix 公开应用或模板后，你将获得一个可自行操作并持续改进的副本。你在 Remix 中所做的更改不会影响原始应用。

Remix 会标明来源。系统会显示指向原始应用的 **Remixed from** 链接，并在封面页上显示原始应用的构建提示词。

<div id="section-2">
  ## Remix 中包含的内容
</div>

Remix 是与原始版本明确分离、完整且可正常运行的副本：

* **所有文件和配置**都会原样复制，因此 App 的运行方式与原始版本完全相同。
* **原始版本的检查点记录**也会一并带入，并显示为原始 App 的记录。你可以使用这些检查点回滚，但创建这些检查点的对话仍保留在原始版本中。
* **全新的 Agent。** Remix 会使用全新的 Agent，不会继承之前的聊天记录。
* **仅复制密钥名称，不复制值。** 如果 App 使用密钥 (例如 API 密钥) ，Remix 中只会列出名称，方便你了解需要填写哪些内容；值则为空。只有在 Remix 自己拥有的 App 时，才会复制这些值。
* **全新的数据库。** Remix 不会连接到原始版本的数据库。如果原始版本提供该选项，你可以使用 **Copy data from original App** 选项复制数据本身，但即使如此，所做的更改也不会影响原始版本。
* 使用 Replit Auth 的 App 会采用**新的登录设置**。

不会复制的内容包括部署、域名和连接器配置；你需要在各自的副本中自行设置。此外，Remix 初始为私密状态，因此在发布前不会共享任何内容。

<div id="section-5">
  ## 在 Remix 基础上构建
</div>

在工作区中打开 Remix 后，你可以使用 Agent 对其进行修改和扩展。在 **Agent** 标签页中输入提示词，描述你想添加的功能。

如需撤销 Agent 所做的更改，请在更改后创建的 检查点 中选择 **Rollback to here**。有关详细信息，请参阅 [Checkpoints 和 Rollbacks](/zh/ko/features/version-control/checkpoints-and-rollbacks)。

<div id="section-6">
  ## Remix，还是用提示词构建？
</div>

两种方式最终都会通向同一个目标：打造一款在 Agent 帮助下不断完善的专属应用。区别只在于起步方式：

|             | Remix       | 用提示词构建          |
| ----------- | ----------- | --------------- |
| 起点          | 原样复制的可运行应用  | Agent 根据描述创建的应用 |
| 初始成果        | 立即生成，与原应用相同 | 耗时更长，结果也会不同     |
| Agent 的首次操作 | 等待你指明方向     | 根据提示词规划并构建      |

如果已有与你想法相似的应用，请使用 Remix。这样，Agent 的第一项工作将基于一个实际可运行的应用，而非空白状态。如果你的想法独一无二、无处可寻，请用提示词构建。

  ## 后续步骤
</div>

* **探索更多 Remix**：浏览[社区](https://replit.com/community/all)，寻找可 Remix 的应用并从中学习

* **发布为可 Remix**：分享改进后的版本，让其他人能在你的成果基础上继续构建
