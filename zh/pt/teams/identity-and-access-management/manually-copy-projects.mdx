本指南介绍如何手动将 App 复制到其他 工作区 或账户。您需要复制代码、配置新 App、复制数据，然后将用户引导至新 App。

不会移动或删除任何内容。旧项目会原封不动地保留在原处，两个副本不会保持同步。完成后，您可以选择保留或删除旧项目。

<Note>
  想使用内置的一键转移功能？请参阅[将 App 转移到团队](/zh/pt/teams/identity-and-access-management/transfer-app-to-teams)。如果该选项不可用，或您需要在不同账户之间复制，请使用本指南。
</Note>

<div id="antes-de-comear">
  ## 开始前
</div>

你需要：

* 同时拥有旧项目和新 工作区 或账户的访问权限。
* 预留大约一小时专门进行最终切换。前面的步骤可以分几天完成。
* 如果你的 App 使用自定义网址，需要能够访问管理该域名的地方。

有两项内容不会自动复制，并且会占用大部分时间：你的**数据库**和你的**网址**。本指南涵盖这两项内容。

<Note>
  如果你的 工作区 管理员启用了[禁止导出源代码](/zh/pt/teams/enterprise-privacy-settings#ban-source-code-export)，你无法将项目下载为 zip 文件。开始前请先与 工作区 管理员沟通——他们可以确认是否允许手动复制，以及如何迁移代码和数据库。
</Note>

<div id="planeje-o-tempo-de-inatividade">
  ## 规划停机时间
</div>

可以把这想象成开第二家店，然后关闭第一家店。会有一小段时间，旧店已经关门，新店还没开张。这段时间内，没人能使用你的 App。

**App 会离线多久？** 通常为 15 到 60 分钟，具体取决于数据库中的数据量，以及网址更新的速度。

**我会丢失数据吗？** 只有在复制数据库后，有人向旧 App 添加数据时才会丢失。为避免这种情况，请在最终复制*之前*让旧 App 下线。本指南的步骤安排可确保这一点。

**我可以撤销吗？** 可以。旧项目不会被删除。如果出现问题，重新发布旧 App，它就会完全恢复原样。

**我应该何时执行此操作？** 请选择较少人使用 App 的时间。如有可能，请提前通知用户。

<div id="etapa-1-copiar-o-cdigo-para-um-novo-projeto">
  ## 第 1 步：将代码复制到新项目
</div>

选择一种方法。在此步骤中，旧应用会继续保持运行。两种方法都会迁移你的代码。GitHub 始终会迁移提交历史，而 zip 文件仅在包含 `.git` 文件夹时才会迁移历史：

|           | 通过 GitHub                      | 通过 zip 文件                                                   |
| --------- | ------------------------------ | ----------------------------------------------------------- |
| **代码文件**  | 仅迁移已提交并推送的文件                   | 磁盘上的所有内容，包括未提交的更改                                           |
| **提交历史**  | 远程仓库中的完整历史                     | 如果 zip 文件包含 `.git` 文件夹，则保留完整历史。如果为满足导入大小限制而排除 `.git`，则不保留历史 |
| **依赖文件夹** | 遵循你的 `.gitignore`              | 已排除 (`node_modules`、`.venv`、`build` 等) ；导入时会重新安装            |
| **要求**    | 一个同时连接到两个 Replit 账户的 GitHub 账户 | 无                                                           |
| **持续同步**  | 两个副本都可以向同一仓库推送和拉取              | 无——仅复制一次                                                    |
| **适用场景**  | 希望长期在 Git 中保留备份的项目             | 快速的一次性复制                                                    |

<div id="via-github">
  ### 通过 GitHub
</div>

<Steps>
  <Step title="将旧项目推送到 GitHub">
    在旧项目中，打开 [Git 面板](/zh/pt/features/workspace-tools/git-interface)，关联 GitHub 仓库，然后提交并推送。除非你希望公开代码，否则请使用私有仓库。
  </Step>

  <Step title="授予新账户访问权限">
    如果新工作区属于其他 Replit 账户，该账户的 GitHub 账户需要有权访问此仓库。对于私有仓库，请将该 GitHub 账户添加为协作者，或使用共享的 GitHub 组织。
  </Step>

  <Step title="导入到新工作区">
    登录新账户，打开 [replit.com/import](https://replit.com/import)，选择 **GitHub**，关联 GitHub 账户并选择仓库。有关故障排除，请参阅 [从身份提供方导入](/zh/pt/build/import-from-providers)。
  </Step>

  <Step title="验证副本">
    打开新项目，确认文件和提交历史都已导入。Replit 会在导入过程中安装依赖项并配置运行命令。
  </Step>
</Steps>

<Warning>
  GitHub 只会接收你已提交并推送的内容。与 `.gitignore` 匹配的文件和未提交的更改不会包含在内。切勿将 Secrets 值或数据库转储提交到仓库。
</Warning>

<div id="via-arquivo-zip">
  ### 通过 zip 文件
</div>

<Steps>
  <Step title="下载旧项目">
    在旧项目中，点击文件树顶部的三点菜单，然后选择 **下载为 zip**。

    如果下载成功且文件小于 200 MB，请继续下一步。

    大于 200 MB 的 zip 文件可能可以成功下载，但[导入 ZIP](/zh/pt/build/import-from-providers#limitations)不接受超过 200 MB 的文件，因此 Replit 无法用它创建新项目。如果下载失败或 zip 文件超过 200 MB，请创建一个更小的文件：

    1. 在旧项目中，打开 **Shell** 工具。

    2. 粘贴以下命令并按 Enter。该命令会创建名为 `project.zip` 的文件，并排除 Replit 可自行重建的文件夹：

       ```bash theme={null}
       zip -r project.zip . -x ".cache/*" "node_modules/*" ".venv/*" "venv/*" ".pythonlibs/*" "build/*" "target/*" ".next/*" "__pycache__/*"
       ```

    3. 检查文件大小。粘贴以下命令并按 Enter。它会以 MB 为单位显示大小，例如 `150M` 表示 150 MB：

       ```bash theme={null}
       du -h project.zip
       ```

    4. 如果文件超过 200 MB，请排除编辑历史以缩小文件。粘贴以下两行并按 Enter：

       ```bash theme={null}
       rm project.zip
       zip -r project.zip . -x ".cache/*" ".local/*" ".git/*" "node_modules/*" ".venv/*" "venv/*" ".pythonlibs/*" "build/*" "target/*" ".next/*" "__pycache__/*"
       ```

       仅当需要将 zip 文件缩小到 200 MB 以下时，才排除 `.local` 和 `.git`。这些排除项不会删除旧项目中的任何文件夹。不过，不含 `.git` 的 zip 文件不会保留项目的提交历史。如果需要保留历史记录，请使用 GitHub 方法。

    5. 在文件树中找到 `project.zip`，点击其旁边的三点菜单，然后选择 **下载**。

    `.cache` 文件夹存储 Replit 的内部状态，包括缓存的 Secrets 值。手动创建 zip 文件时，务必将其排除在外。如果项目中还有其他较大的生成文件夹，请将它们添加到排除列表中。
  </Step>

  <Step title="导入到新工作区">
    登录新账户，打开 [replit.com/import](https://replit.com/import)，选择 **ZIP** 并上传该文件。
  </Step>

  <Step title="验证副本">
    打开新项目并确认文件是否齐全。如果 zip 文件包含 `.git` 文件夹，提交历史也会一并导入。如果使用了用于创建较小文件的命令，新项目将不包含提交历史。Replit 会在导入期间重新安装被排除的依赖项。
  </Step>
</Steps>

<div id="etapa-2-configurar-o-novo-app">
  ## 第 2 步：配置新应用
</div>

旧应用仍在运行。在这一步中，使用数据的*测试副本*让新应用完全正常运行，以便稍后能快速完成最终切换。

<Steps>
  <Step title="添加 Secrets">
    Secrets 值 (API 密钥、密码) 绝不会离开旧项目。请在两个项目中打开 [Secrets](/zh/pt/core-concepts/project-editor/app-setup/secrets) 工具，并逐一手动复制。还应包含所有 deployment Secrets。
  </Step>

  <Step title="重新连接 连接器 和其他服务">
    在新项目的 **Tools → 连接器** 中重新连接每项集成。有关 App Storage、协作者及其他所有内容，请参阅[重新创建未复制的内容](#recrie-o-que-nao-e-copiado)。
  </Step>

  <Step title="发布新应用">
    [发布](/zh/pt/features/publishing/overview)新项目。它会获得自己的 `replit.app` 网址和一个空的生产数据库。暂时不要连接自定义域名。
  </Step>

  <Step>
    请按照下方的[复制数据库](#copiar-o-banco-de-dados)操作，并将新项目中的**生产**数据库作为目标。这将为你提供可供测试的真实数据。第 3 步会用最新数据替换此副本。
  </Step>

  <Step>
    在 `replit.app` 地址打开新应用，并像用户一样使用它。继续前，请修复所有问题。你的用户尚未受到影响。
  </Step>
</Steps>

<div id="etapa-3-direcionar-seus-usurios-para-o-novo-app">
  ## 第 3 步：将用户迁移到新 App
</div>

这是需要停机的步骤，请在同一次操作中完成。

<Steps>
  <Step title="让旧 App 下线">
    在旧项目中，打开 **Publishing** 工具并选择 **Unpublish**。您的 App 现已离线。此后任何人都无法添加新数据，因此接下来创建的副本将是完整的。
  </Step>

  <Step title="最后一次复制数据库">
    按照下方的[复制数据库](#copiar-o-banco-de-dados)步骤操作，并将新项目中的**生产环境**数据库作为目标。此副本包含所有最新数据。
  </Step>

  <Step title="将您的网址指向新 App">
    如果您的 App 使用自定义域名：在旧项目中，打开 **Publishing → Domains** 并断开该域名。在新项目中，打开 **Publishing → Domains** 并[重新连接该域名](/zh/pt/features/publishing/custom-domains#connect-a-domain-you-already-own)。如果 Replit 提示您这样做，请在域名提供商 (例如 GoDaddy 或 Namecheap) 处更新记录。

    新地址可能需要几分钟到几小时才能对所有用户生效。在此之前，部分访问者可能会看到错误。

    如果您的 App 仅使用 `replit.app` 地址，请将新地址分享给用户。
  </Step>

  <Step title="确认新 App 已上线">
    打开您的网址，确认新 App 能够加载并显示您的数据。您的 App 已重新上线。
  </Step>
</Steps>

<div id="copiar-o-banco-de-dados">
  ## 复制数据库
</div>

复制代码不会影响数据库。请使用两个项目的 Shell 中提供的 PostgreSQL `pg_dump` 和 `pg_restore` 工具复制数据。第 2 步和第 3 步都会用到这里的说明。每次使用的命令都相同，只有*目标数据库*不同。

<Warning>
  在运行 `pg_dump` 后写入的数据不会包含在备份中。执行第 3 步的最终复制前，请先停止旧应用。
</Warning>

<Steps>
  <Step title="导出旧项目的数据">
    在旧项目中打开 **Shell** 工具。粘贴以下命令并按 Enter。该命令会在文件树中创建名为 `backup.dump` 的文件：

    ```bash theme={null}
    pg_dump -Fc "$DATABASE_URL" --no-owner --no-privileges -f backup.dump
    ```

    此操作会导出**开发数据库**。生产数据通常存储在**生产数据库**中。要导出生产数据库：

    1. 打开 **Database** 工具，选择生产数据库，然后打开 **Settings**。
    2. 复制连接字符串。
    3. 在上述命令中，将 `"$DATABASE_URL"` 替换为连接字符串，并保留引号。

    如果找不到连接字符串，请参阅[连接详情](/zh/pt/features/data-and-storage/connection-details)。
  </Step>

  <Step title="将 dump 文件移至新项目">
    在旧项目的文件树中，点击 `backup.dump` 旁的三点菜单并下载该文件。然后使用文件树中的 **Upload files** 选项将其上传到新项目。

    如果你是通过 GitHub 复制代码的，请勿提交 dump 文件。请单独移动该文件，确保数据不会进入仓库。
  </Step>

  <Step title="将数据导入新项目">
    在新项目中打开 **Shell** 工具。粘贴以下命令并按 Enter：

    ```bash theme={null}
    pg_restore --clean --if-exists --single-transaction --no-owner --no-privileges --exit-on-error -d "$DATABASE_URL" backup.dump
    ```

    按照当前写法，该命令会将数据导入新项目的**开发数据库**。这正是第 2 步所需的操作。

    对于第 3 步的最终复制，则应使用**生产数据库**。在新项目中，打开 **Database** 工具，选择生产数据库，打开 **Settings**，复制连接字符串，并用它替换 `"$DATABASE_URL"`。

    此操作会删除目标数据库中所有对应的对象，然后导入数据。命令完成且未输出任何内容，即表示操作成功。
  </Step>
</Steps>

<Note>
  如果 `pg_restore` 因 role 或策略错误而失败，说明你的数据库使用了新项目中尚不存在的自定义 PostgreSQL role。请[联系支持团队](https://replit.com/support)获取帮助。
</Note>

<Note>
  如果新项目使用[旧版 Neon 开发数据库](/zh/pt/features/data-and-storage/development-and-production#legacy-development-database)，部署流程会提供 **Set up your production database with your current development data**。该选项会复制部署时开发数据库中的数据。它适合测试，但在最终切换时，请按照上述步骤获取最新数据。
</Note>

<div id="recrie-o-que-no-copiado">
  ## 重新创建未复制的内容
</div>

其余项目配置位于文件系统之外。请在新项目中重新创建以下各项：

| 项目              | 操作                                                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Secrets**     | Secrets 值绝不会离开旧项目。请在新项目的 [Secrets](/zh/pt/core-concepts/project-editor/app-setup/secrets) 工具中重新添加，包括部署 Secrets。                                   |
| **账户 Secrets**  | 在新项目中[关联它们](/zh/pt/core-concepts/project-editor/app-setup/secrets#manage-account-secrets)。如果新项目属于其他账户，请先将它们添加到该账户。                                |
| **App Storage** | 存储桶不会被迁移。在同一账户内，请将[现有存储桶添加](/zh/pt/features/data-and-storage/object-storage#bucket-access-management)到新项目。在不同账户之间，请下载对象并上传到新的存储桶。                 |
| **连接器**         | 在新项目的 **Tools → Connectors** 中重新连接每个集成。请参阅[集成概览](/zh/pt/features/integrations/overview)。                                                          |
| **部署**          | 副本尚未发布。请按照[第 2 步](#etapa-2-configurar-o-novo-app)，从新的 工作区 [发布它](/zh/pt/features/publishing/overview)。                                       |
| **自定义域名**       | 从旧部署中移除域名，将其关联到新部署，并更新 DNS 记录。详见[第 3 步](#etapa-3-direcionar-seus-usuarios-para-o-novo-app)。                                                    |
| **协作者**         | 再次邀请协作者，并在新的 工作区 中配置[访问权限](/zh/pt/teams/identity-and-access-management/groups-and-permissions)。                                             |
| **Agent 历史记录**  | Agent Conversation 和 [checkpoint](/zh/pt/features/version-control/checkpoints-and-rollbacks) 回滚会保留在旧项目中。checkpoint 提交会随 Git 历史记录一同迁移，但无法在副本中将其还原。 |

<div id="se-algo-der-errado">
  ## 如果出现问题
</div>

旧项目仍然还在。若要恢复：

1. 在旧项目中，打开 **Publishing** 工具并选择 **Publish**。
2. 如果您迁移了自定义域名，请按相同方式将其迁回。

您的 App 将恢复上线，并保留您将其下线时的数据。不会丢失任何内容。

<div id="limpeza">
  ## 清理
</div>

等待约一周，确认新 App 运行正常后：

* 删除两个项目和您的设备上的 `backup.dump`。每个副本都包含完整的数据导出。
* 您也可以选择删除旧项目。
