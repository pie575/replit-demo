<div id="o-que-o-sistema-de-tarefas">
  ## 什么是任务系统？
</div>

**任务**是 Agent 可以规划并执行的工作单元。借助任务，Agent 能把较大的目标拆分成更小的部分，让你在每个部分改动应用之前先行审查。

Agent 可以在两个地方工作：**主线程**和**后台任务**。主线程是你描述需求、调整方向并决定哪些内容应用到主版本的对话。后台任务则是独立的线程，Agent 在其中基于项目的隔离副本独立开展工作。

用主线程来把握方向、做出决策，用后台任务来处理可以并行推进的执行工作。在你审查并应用之前，后台任务不会改动主版本。

任务系统就是 Agent 组织这些工作的方式。当你描述想要创建的内容时，Agent 会把你的请求拆分成一个个独立的任务，并放入包含以下几列的面板中：**草稿**、**进行中**、**就绪**和**已完成**。

<Frame>
  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="任务面板，展示按草稿、进行中、就绪和已完成各列组织的任务" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />
</Frame>

每个任务会随着进展从左向右移动，让你一眼就能看到哪些已在计划中、Agent 正在处理哪些、哪些已可供你审查，以及哪些已经完成。后台任务会根据你的计划自动排队，让工作持续推进，同时不会让主线程负担过重。

任务就绪后，你可以审查这些更改并将其应用回主版本——如果不符合预期，也可以直接舍弃。

<div id="como-funcionam-as-tarefas-em-segundo-plano">
  ## 后台任务的工作方式
</div>

<Steps>
  <Step title="规划任务">
    在主线程中发起对话，或创建一个新线程并在其中规划。Agent 会审查你的项目，找出最有影响力的工作，并为每项任务制定详细计划，包括具体要做什么以及“完成”的标准。

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="在主线程中描述要构建的内容，Agent 提出并执行任务" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="审核并接受">
    Agent 会提出一组任务，每项任务都包含标题、描述和详细计划，你可以通过 **查看计划** 查看详情。审核完整列表后，选择：

    * **接受任务** — 启动所有任务并将其置于后台运行
    * **审核计划** — 要求 Agent 在开始前调整任务

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="已创建的任务计划对话框，显示四项建议任务，以及接受任务和审核计划选项" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="任务开始执行">
    接受后，任务会在项目的隔离副本中执行。Core 一次可运行 1 个后台任务，Pro 最多可同时运行 10 个后台任务。在你决定应用更改之前，主版本不会受到影响。你可以通过两种方式跟踪进度：

    * **线程视图** — 每项任务都在各自的线程中执行，并显示实时状态指示器，因此你可以跟踪进度或加入任意任务的对话

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="线程视图，显示多个并行执行的任务及状态指示器" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **看板视图** — 以列展示的看板，按状态整理所有任务：**草稿**、**进行中**、**就绪**和**已完成**

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="看板视图，显示按草稿、进行中、就绪和已完成列组织的任务" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="审核并应用">
    任务完成后，Agent 会显示已完成的工作，包括工作记录、测试结果和更改的实时预览。你可以决定下一步操作：

    * **将更改应用到主版本** — 将任务成果合并到项目中
    * **丢弃** — 如果更改不符合预期，则丢弃这些更改

    应用多个任务的更改时，Agent 会自动解决冲突。

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="任务审核界面，显示 Agent 的工作记录、测试结果和应用更改按钮" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="o-que-voc-pode-construir">
  ## 你可以构建什么
</div>

任务系统适用于任何项目。以下是它表现尤为出色的几种场景:

* **把大型功能拆成小块交付** —— 将身份验证、仪表板和 API 层拆成独立的任务,让 Agent 能有条不紊地逐一处理
* **规划复杂项目** —— 把一个庞大的功能拆解为边界清晰、带依赖关系的任务,放心推进执行
* **比较不同的设计方向** —— 用独立的任务尝试多种界面方案,再从中选出最佳结果

<div id="perguntas-frequentes">
  ## 常见问题
</div>

<Accordion title="我需要改变构建方式吗？">
  不需要。主线程的工作方式完全不变。Agent 会在需要时自动在后台创建任务。你也可以使用 [Plan 模式](/zh/pt/features/agent/plan-mode)来显式查看和管理任务。
</Accordion>

<Accordion title="为什么我的任务一次只运行一个？">
  Core 每次只运行 1 个后台任务，Pro 最多支持 10 个并发后台任务。达到所在计划的上限后，后续任务会进入队列，等有空位时再开始执行。
</Accordion>

<Accordion title="Agent 在应用后台任务时如何处理冲突？">
  Agent 采用 AI 辅助的冲突解决机制。它会理解每个任务想要实现的目标，并智能地应用更改。如果结果看起来不对，你可以在线程中让 Agent 进行修正。
</Accordion>

<Accordion title="任务之间可以相互依赖吗？">
  可以。Agent 会自动检测依赖关系——例如，构建仪表板的任务依赖于创建数据库结构的任务。有依赖的任务会等前置任务完成后再执行。
</Accordion>

<Accordion title="归档任务和取消任务有什么区别？">
  **归档**适用于规划会话，也就是尚未开始构建的草稿。已归档的规划会话会被保留，可在 **已完成** 列中恢复。

  **取消**适用于已从规划进入构建阶段的任务。取消会中止该任务并丢弃其工作成果，且已取消的任务无法恢复——你需要重新启动一个新任务。
</Accordion>
