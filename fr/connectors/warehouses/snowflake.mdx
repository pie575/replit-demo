<Info>
  Le connecteur Snowflake est disponible exclusivement avec le plan **Enterprise**.
</Info>

Les Warehouse Connecteurs permettent à Replit Agent d&#39;interroger les entrepôts de données de votre organisation. Avec le connecteur Snowflake, les créateurs peuvent concevoir des tableaux de bord, des outils de reporting et des applications de données en langage naturel — aucune expertise SQL requise.

La configuration s&#39;effectue une seule fois et nécessite un administrateur Snowflake ainsi qu&#39;un administrateur de workspace Replit. Une fois en place, n&#39;importe quel membre de l&#39;organisation peut se connecter et commencer à créer avec les données Snowflake.

Ce guide vous accompagne tout au long de la configuration. Trois rôles interviennent :

1. **Administrateur de compte Snowflake** — Crée l&#39;intégration OAuth dans Snowflake
2. **Administrateur de workspace Replit** — Configure le connecteur dans Replit
3. **Créateur** — Se connecte et commence à créer

<div id="create-the-oauth-integration-in-snowflake">
  ## Créer l&#39;intégration OAuth dans Snowflake
</div>

L&#39;administrateur du compte Snowflake crée une intégration de sécurité OAuth qui permet à Replit de s&#39;authentifier auprès de Snowflake.

<div id="prerequisites">
  ### Prérequis
</div>

* Rôle `ACCOUNTADMIN` dans Snowflake
* Autorisation d&#39;exécuter des requêtes SQL dans les feuilles de calcul Snowflake

<div id="run-the-setup-script">
  ### Exécuter le script de configuration
</div>

<Steps>
  <Step title="Connectez-vous à Snowflake">
    Ouvrez votre compte Snowflake et assurez-vous d&#39;utiliser le rôle `ACCOUNTADMIN`. Vous pouvez le vérifier dans la liste déroulante des rôles, en haut à droite.
  </Step>

  <Step title="Ouvrez une feuille de calcul SQL">
    Cliquez sur **Worksheets** dans la barre latérale gauche, puis créez une feuille de calcul.
  </Step>

  <Step title="Exécutez le script d'intégration OAuth">
    Copiez-collez le script SQL suivant, puis exécutez-le :

    ```sql Create OAuth integration theme={null}
    -- Supprimer l'intégration existante si nécessaire
    DROP INTEGRATION IF EXISTS REPLIT_OAUTH;

    -- Créer l'intégration OAuth pour Replit
    CREATE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    <Warning>
      L&#39;URI de redirection doit être exactement `https://replit.com/connectors/oauth/callback`. Toute autre valeur provoque une erreur 404 lors de l&#39;authentification.
    </Warning>

    <Note>
      Définir `BLOCKED_ROLES_LIST = ()` garantit qu&#39;aucun rôle ne se voit refuser l&#39;utilisation de l&#39;intégration. Sans cela, des erreurs « invalid consent request » ou « role blocked » peuvent survenir lors de la connexion.
    </Note>
  </Step>

  <Step title="Récupérez vos identifiants OAuth">
    Exécutez cette requête pour obtenir le Client ID et le Client Secret :

    ```sql Get OAuth credentials theme={null}
    -- Afficher les détails de l'intégration
    DESCRIBE INTEGRATION REPLIT_OAUTH;

    -- Obtenir le Client ID et le Client Secret
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```

    Copiez le **Client ID** et le **Client Secret** affichés dans le résultat. Vous en aurez besoin à l&#39;étape suivante.
  </Step>
</Steps>

<div id="configure-the-connector-in-replit">
  ## Configurer le connecteur dans Replit
</div>

L&#39;administrateur du Workspace Replit ajoute les identifiants Snowflake à Replit. Une fois la configuration terminée, toute personne de l&#39;organisation peut se connecter.

<Note>
  Cette étape nécessite un plan Enterprise avec un accès administrateur.
</Note>

<Steps>
  <Step title="Ouvrir Integrations">
    Accédez aux paramètres de votre organisation, puis sélectionnez l&#39;onglet **Integrations**.
  </Step>

  <Step title="Ajouter le connecteur Snowflake">
    Cliquez sur **Add New Connector**, puis sélectionnez **Snowflake**.
  </Step>

  <Step title="Saisir les identifiants">
    Renseignez le **Client ID** et le **Client Secret** obtenus à l&#39;étape précédente.
  </Step>

  <Step title="Définir la portée">
    Définissez la portée du connecteur sur `refresh_token`.

    <Warning>
      Utilisez uniquement la portée `refresh_token`. Les autres portées, telles que `session:role-any` ou `session:role:PUBLIC`, risquent de provoquer une erreur « invalid scope ».
    </Warning>
  </Step>

  <Step title="Enregistrer">
    Cliquez sur **Save** pour activer le connecteur.
  </Step>
</Steps>

<div id="sign-in-to-snowflake">
  ## Se connecter à Snowflake
</div>

Tout membre de l&#39;organisation ayant accès au connecteur peut se connecter. Connectez-vous d&#39;abord depuis la page **Integrations** afin de vérifier la connexion avant de l&#39;utiliser avec Agent.

<Steps>
  <Step title="Trouver le connecteur Snowflake">
    Accédez à **Integrations** dans Replit. Sous **Connecteurs**, repérez **Snowflake**.
  </Step>

  <Step title="Cliquer sur Sign In">
    Cliquez sur **Sign In** dans le connecteur Snowflake.
  </Step>

  <Step title="Saisir votre Snowflake Account ID">
    Le prompt OAuth vous demande votre Snowflake Account ID.

    Pour trouver votre Account ID, regardez votre URL Snowflake :

    ```
    https://app.snowflake.com/myorg/myaccount
    ```

    Prenez les deux parties qui suivent `app.snowflake.com/` et reliez-les par un trait d&#39;union :

    ```
    myorg-myaccount
    ```

    <Note>
      L&#39;URL utilise un `/` entre les deux parties, alors que l&#39;Account ID utilise un `-`.
    </Note>
  </Step>

  <Step title="S'authentifier">
    Snowflake vous redirige vers la page de connexion. Saisissez vos identifiants Snowflake pour finaliser le flux OAuth.
  </Step>
</Steps>

<div id="start-building-with-your-snowflake-data">
  ## Commencez à créer avec vos données Snowflake
</div>

Une fois la connexion établie, vous pouvez utiliser le connecteur Snowflake avec Agent de deux façons :

* **Commande slash** — Saisissez `/snowflake` dans le prompt pour utiliser le connecteur
* **Langage naturel** — Demandez directement à Agent d&#39;utiliser vos données Snowflake

Voici un exemple de prompt :

```
Crée-moi un tableau de bord à partir de mes données Snowflake. Affiche le chiffre
d'affaires total par région sous forme de diagramme à barres, une courbe de tendance
par trimestre et un tableau des 10 meilleurs clients. Thème sombre, épuré et moderne.
```

Agent rédige et exécute des requêtes SQL sur vos données Snowflake, puis crée une application fonctionnelle.

<div id="troubleshooting">
  ## Dépannage
</div>

<AccordionGroup>
  <Accordion title="Erreur de demande de consentement non valide ou de rôle bloqué">
    Des rôles sont peut-être bloqués par défaut dans votre intégration Snowflake.

    Vérifiez que votre intégration a bien été créée avec `BLOCKED_ROLES_LIST = ()`. Si vous l&#39;avez déjà créée sans ce paramètre, exécutez :

    ```sql Fix blocked roles theme={null}
    CREATE OR REPLACE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    Si l&#39;erreur persiste, vérifiez que votre rôle par défaut n&#39;est pas bloqué :

    ```sql Set default role theme={null}
    ALTER USER "YOUR_USERNAME" SET DEFAULT_ROLE = 'PUBLIC';
    ```
  </Accordion>

  <Accordion title="Erreur 404 lors de l'authentification">
    Vérifiez que l&#39;URI de redirection de votre intégration Snowflake correspond exactement à :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    La moindre différence entraîne une erreur 404 pendant le flux OAuth.
  </Accordion>

  <Accordion title="Erreur de portée non valide">
    Assurez-vous que la portée du connecteur dans Replit est définie uniquement sur `refresh_token`. Supprimez toute autre portée telle que `session:role-any` ou `session:role:PUBLIC`.
  </Accordion>

  <Accordion title="Erreur d'échec de connexion">
    Vérifiez que le Client ID et le Client Secret renseignés dans Replit correspondent à ceux générés par Snowflake. Pour les contrôler, exécutez :

    ```sql Verify credentials theme={null}
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```
  </Accordion>
</AccordionGroup>
