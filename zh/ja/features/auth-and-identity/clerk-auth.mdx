Clerk Auth 基于 [Clerk](https://clerk.com) 为你的应用提供专属的身份验证系统。[Replit Auth](/zh/ja/features/auth-and-identity/authentication) 使用 Replit 的登录系统创建 Replit 账户，而 Clerk Auth 则会为你的应用单独预配一个**专属 Clerk 租户**。应用的用户不必注册 Replit 账户，可直接在应用内创建账户。品牌形象、登录方式和登录体验都由你完全掌控。

<Frame>
  <video autoPlay muted loop playsInline src="/assets/mirror/auth-vid-e89aaccd245e.mp4" />
</Frame>

<Note>
  **Clerk Auth 与 Replit Auth 的区别** —— 使用 **Clerk Auth** (本页介绍的方案) 时，你的应用会拥有独立的身份验证租户，品牌形象完全可自定义，用户账户也独立于 Replit。而使用 **[Replit Auth](/zh/ja/features/auth-and-identity/authentication)** 时，用户以 Replit 账户登录，看到的是带有 Replit 品牌的登录页面。如果你希望登录体验使用自有品牌，或需要独立于 Replit 的用户账户，请选择 Clerk Auth。
</Note>

<div id="clerk-auth-vs-replit-auth">
  ## Clerk Auth 与 Replit Auth 对比
</div>

|            | Clerk Auth                 | Replit Auth            |
| ---------- | -------------------------- | ---------------------- |
| **用户账户**   | 用户在应用内创建账户 (无需 Replit 账户)  | 用户使用 Replit 账户登录       |
| **品牌形象**   | 完全可自定义——应用名称、图标、配色         | Replit 品牌的登录页面         |
| **SSO 凭据** | 每个提供商使用各自的 OAuth 凭据        | 使用 Replit 的共享 OAuth 应用 |
| **环境**     | 开发环境与生产环境分离                | 单一环境                   |
| **推荐计划**   | 不与 Replit 推荐计划集成           | 注册计入 Replit Referrals  |
| **最适合的场景** | 自定义品牌应用、专业/商业产品            | 快速搭建、可接受 Replit 品牌的应用  |

<div id="section">
  ## 快速开始
</div>

在 Agent 提示词中加入以下内容，即可为应用添加 Clerk Auth：

```
Help me create an app that [your app idea] and should feature Clerk Auth.
```

Agent 会处理所有事务，包括创建 Clerk 租户、保存凭据、配置路由和添加中间件。无需 Clerk 账户，也无需手动设置。

<div id="clerk-authreplit">
  ## Clerk Auth 在 Replit 中的工作原理
</div>

当 Agent 为你的应用设置 Clerk Auth 时，会执行以下操作：

1. **创建专属 Clerk 租户** — 你的应用将拥有独立的 Clerk 应用，开发环境和生产环境彼此隔离
2. **配置凭据** — API 密钥和密钥将作为环境变量存储
3. **配置代理** — 身份验证可在已发布的域名上无缝运行
4. **设置登录和注册路由** — 预构建的 Clerk React 组件将添加到你的应用中
5. **添加服务端中间件** — API 路由将受到 Clerk Express 中间件的保护

<Note>
  你无需创建 Clerk 账户或管理基础设施。Replit 会自动管理所有内容。
</Note>

<div id="section-2">
  ## 功能
</div>

<div id="section-3">
  ### 支持的功能
</div>

Clerk Auth 为你的应用提供以下能力：

* **独立的用户账户** —— 应用的用户并非 Replit 用户，他们仅存在于应用的 Clerk 租户中
* **完全品牌化的登录页面** —— 在应用代码中配置应用名称、Logo、配色、字体和文案
* **自定义品牌 SSO** —— 为每个提供商配置专属的 OAuth 客户端，让提供商的 OAuth 授权页面显示应用的名称和品牌形象，而非默认信息
* **邮箱和密码认证** —— 内置的注册与登录流程，含邮箱验证
* **社交登录 (SSO)&#x20;**&#x20;—— 支持通过 Google、GitHub、Apple、X (Twitter) 登录
* **用户管理** —— 在 Auth 面板中查看、搜索和管理用户
* **会话管理** —— 自动管理的安全会话令牌
* **开发环境与生产环境** —— 在发布前于开发环境中测试认证

<Note>
  Clerk Auth 的大部分配置都可以在 Project Editor 的 Auth 工具中管理。无需注册 Clerk 账户，也无需打开 Clerk 控制台。
</Note>

<div id="section-4">
  ### 不支持的功能
</div>

目前，Clerk Auth 不支持以下功能 (相较于自行设置的外部 Clerk App) 。如需了解详细差异，请参阅[此常见问题](#how-does-clerk-auth-compare-to-external-clerk)。

* **使用电话号码登录** — 基于 SMS 的登录和验证
* **MFA 支持** — 面向最终用户的多因素身份验证
* **全面支持 SSO 身份提供方** — 目前仅支持 Google、GitHub、Apple 和 X
* **组织租户** — Clerk 的组织和团队成员管理功能

<div id="section-5">
  ## 开发环境和生产环境
</div>

所有使用 Clerk Auth 的应用都会获得两个完全隔离的 Clerk 环境：一个**开发**环境，用于运行正在构建的开发版/预览版应用；另一个**生产**环境，用于运行已发布的应用。这些环境在设计上彼此隔离，使用独立的 API 密钥和用户存储。

<div id="api">
  ### 独立的 API 密钥
</div>

每个环境都有各自的可发布密钥和 Secret API 密钥。应用使用的密钥会根据应用处于开发环境还是生产环境自动切换：

* 在 工作区 中，`CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY` 的 Secrets 包含指向开发环境的**测试密钥** (`pk_test...` 和 `sk_test...`) 。

<Frame>
  <img src="/assets/mirror/clerk-check-dev-keys-5a23f6b7dd0c.png" alt="工作区 的 Secrets 工具中显示带有 sk_test_ 和 pk_test_ 前缀的 CLERK_SECRET_KEY 和 CLERK_PUBLISHABLE_KEY" width="1946" height="402" data-path="images/workspace/auth/clerk-check-dev-keys.png" />
</Frame>

* 发布应用后，已发布的部署会使用指向生产环境的**正式密钥** (`pk_live...` 和 `sk_live...`) 运行。要查看前缀，请打开 **Publishing → 概览 → 调整设置**，然后查看 `CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY`。

<Frame>
  <img src="/assets/mirror/clerk-check-prod-keys-acccd7f68da1.png" alt="Publishing 概览中生产应用密钥显示带有 sk_live_ 和 pk_live_ 前缀的 CLERK_SECRET_KEY 和 CLERK_PUBLISHABLE_KEY" width="1924" height="1664" data-path="images/workspace/auth/clerk-check-prod-keys.png" />
</Frame>

<Note>
  无需执行任何操作来切换环境。Replit 会自动管理开发环境和生产环境的密钥。只需开发、测试并发布即可。
</Note>

<Warning>
  请勿将测试密钥替换为正式密钥、在 Secrets 面板中编辑它们，或在 Clerk 控制台中手动配置它们。否则会破坏开发环境与生产环境之间的自动切换，且不再受 Replit 管理的 Clerk Auth 支持。
</Warning>

<div id="section-6">
  ### 独立的用户存储
</div>

每个环境都有各自的用户存储。在开发环境中注册的账户在生产环境中**不存在**，反之亦然：

* 在开发/预览应用中测试时注册的用户仅会创建在开发环境的存储中。
* 在已发布的应用中注册的用户仅会创建在生产环境的存储中。
* 会话、用户元数据以及与 Clerk `userId` 关联的数据，同样仅限于创建该账户的环境。

这是预期行为。若要查看各环境中的用户，请在工作区中打开 **Auth 面板**，然后使用 **Users** 标签页中的环境切换器在开发环境和生产环境之间切换。

<Note>
  开发环境用于实验和构建，生产环境则面向线上应用的真实用户。两者经过有意隔离，因此在开发环境中创建的账户和数据不会显示在生产环境中。
</Note>

Project Editor 中的 Auth 面板提供已认证用户的完整视图。由于 Clerk Auth 会为应用创建专属的用户存储，这里列出的用户是应用自身的账户，而非 Replit 账户。

<Frame>
  <img src="/assets/mirror/clerk-users-4940ed365605.png" alt="在 Auth 面板中显示已认证用户的 Clerk Auth Users 标签页" width="2136" height="794" data-path="images/workspace/auth/clerk-users.png" />

在 **Users** 标签页中，你可以：

* **搜索和筛选**，快速找到特定用户
* **封禁和解封用户**，控制其对应用的访问权限
* 按不同条件**对用户排序**
* **切换环境** —— 在开发环境和生产环境之间切换，分别管理各环境的用户

<div id="section-8">
  ## 自定义登录页面
</div>

登录和注册页面的视觉品牌元素 (应用名称、徽标、颜色、字体和文案) 需在应用代码中设置，而非在 Auth 面板中设置。若要更改，请让 Agent 为你处理：

```
Update my sign-in page to use [your app name] as the title, [describe your logo], and match my site's colors.
```

在内部，这些内容由传递给 `<ClerkProvider>` 的 `appearance` 和 `localization` 属性，以及应用 `public/` 目录中的徽标文件控制。Agent 会让它们与应用主题保持同步。

<Note>
  **Google、Apple、GitHub 和 X 的 OAuth 同意页面** (用户点击“使用 Google 登录”等选项后显示的页面) 中显示的应用名称则是另一回事。它来自向身份提供方注册的 OAuth 应用，编辑登录页面代码也**不会更改**它。若要更改，需为该身份提供方[配置自定义 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
</Note>

<div id="section-9">
  ## 配置登录提供方
</div>

Clerk Auth 支持将 Google、GitHub、Apple、X 作为 SSO 身份提供方。在 Auth 面板的 Configure 标签页中，你可以控制登录页面上显示哪些身份提供方。此外，在生产环境中，你还可以设置各身份提供方使用 Replit 托管的 OAuth 凭据，还是使用你自己的凭据来实现品牌化登录。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" alt="显示 SSO 身份提供方的侧边栏，已选择 Production，Configure 标签页中的身份提供方列表显示启用开关和 Edit 操作" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

打开 **Configure** 标签页，在 **SSO providers** 侧边栏中选择 **Development** 或 **Production**。**Development** 用于 工作区 中的开发/预览应用，**Production** 用于已发布的应用。所选环境的列表会显示在主面板中，你可以在此进行以下操作：

* **启用/禁用身份提供方** — 使用开关控制该身份提供方是否显示在登录页面上。已禁用的身份提供方不会对用户显示。
* **配置自定义 OAuth 凭据 (仅限生产环境)&#x20;**&#x20;— 请参阅下方的[为 SSO 身份提供方配置 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。

<div id="ssooauth">
  ### 配置 SSO 身份提供方的 OAuth 凭据
</div>

默认情况下，身份提供方使用 **Replit 托管的凭据**。登录会立即生效，但 OAuth 同意页面上显示的是 Replit 的品牌标识。切换到 **Custom credentials** 后，你可以使用在身份提供方开发者控制台中创建的自有 OAuth 客户端，同意页面将显示你的应用名称和品牌标识，而不是默认内容。

1. 在 Project Editor 中打开 Auth 面板。切换到 Configure 标签页，在侧边栏的 **SSO providers** 下选择 **Production**。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

2. 选择要配置的身份提供方旁边的 **Edit** 图标。系统默认选中 **Replit-managed credentials**。

<Frame>
  <img src="/assets/mirror/clerk-sso-default-credentials-525090775408.png" alt="显示 Replit 托管凭据和自定义凭据选项的身份提供方编辑面板" width="1468" height="960" data-path="images/workspace/auth/clerk-sso-default-credentials.png" />
</Frame>

3. 选择 **Custom credentials**。面板随即展开，显示凭据字段，以及列出需在身份提供方一侧注册的各项值的 **Provider setup** 清单。

<Frame>
  <img src="/assets/mirror/clerk-sso-custom-credentials-f24112a5cf07.png" alt="显示 OAuth 客户端 ID 和密钥字段，以及包含重定向回调 URL 和 JavaScript 来源的 Provider setup 清单的 Custom credentials 面板" width="1468" height="2246" data-path="images/workspace/auth/clerk-sso-custom-credentials.png" />
</Frame>

4. 按照提示的步骤完成配置。这些步骤中包含指向控制台的直接链接和相关帮助文档。你也可以在 [Additional resources](#additional-resources) 中查看各身份提供方的帮助文档。
5. 填写所有必填的凭据值。
6. 在身份提供方的开发者控制台中，将 **Provider setup** 清单中列出的所有条目注册到身份提供方的开发者门户。使用复制图标准确复制每个值，完成一项即勾选一项，或在全部完成后选择 **Mark all as done**。
7. 选择 **Save changes**。

<div id="section-10">
  ### 更改域名后重新确认设置
</div>

新的外部域名链接或[通过 Replit 购买域名](/zh/ja/build/domain-purchasing)等域名相关操作，可能会更改应用的重定向回调 URL 和 JavaScript 来源。在这种情况下，使用自定义凭据配置的身份提供方需要在开发者控制台中登记新值。

更改域名后，返回 **Configure** 标签页。系统会在标签页、侧边栏以及 **SSO providers** 列表中身份提供方旁以警告图标的形式显示设置提醒。如果身份提供方旁显示警告图标和 **setup steps remaining**，则表示其 **Provider setup** 检查清单中有新的待完成项目。

<Frame>
  <img src="/assets/mirror/clerk-sso-setup-reminders-a5b092846006.png" alt="显示设置警告的 Configure 标签页和侧边栏，以及 SSO providers 列表中更改域名后身份提供方旁的警告图标和 setup steps remaining" width="923" height="378" data-path="images/workspace/auth/clerk-sso-setup-reminders.png" />
</Frame>

打开身份提供方的编辑面板，复制 **Provider setup** 中更新后的值，在身份提供方的开发者控制台中登记，然后选择 **Mark all as done**。

<div id="section-11">
  ## 邮件验证的域名设置
</div>

如果你的应用提供**邮箱加密码注册**，Clerk 会向每位新用户的收件箱发送验证码。为邮件投递配置域名后，验证码会从你的应用 URL 发出，不会被垃圾邮件过滤器延迟或拦截。

<div id="section-12">
  ### 何时需要进行此设置
</div>

仅当你的 App 使用由**其他服务商管理的外部域名**时，才需要配置这些 DNS 记录 (例如在 Cloudflare、GoDaddy、Namecheap 或类似服务商处注册的域名) 。

以下情况无需进行设置：

* 通过 `.replit.app` 子域名提供服务
* [通过 Replit 购买的](/zh/ja/build/domain-purchasing)域名

在这两种情况下，Replit 都会管理 DNS 记录。

<div id="dns">
  ### 添加用于发送邮件的 DNS 记录
</div>

要让应用能够从外部域名发送身份验证邮件，请在你的域名提供商处添加一组 DNS 记录。

1. 在 Project Editor 中打开 **Publishing**。
2. 选择 **Domains**。
3. 找到已关联的外部域名，然后选择 **Manage**。
4. 在 **Authentication DNS setup required** 下方，复制 Replit 显示的 CNAME 记录。Clerk 需要这些记录才能从你的域名发送身份验证邮件。
5. 登录你的 DNS 提供商 (如 Cloudflare、GoDaddy、Namecheap 等) ，按显示的内容逐条添加这些记录。

<Frame>
  <img src="/assets/mirror/clerk-domain-8797ea9f41fc.png" alt="显示 Authentication DNS setup required 部分（含用于 Clerk 邮件投递的 CNAME 记录）的 Domain Manage 面板" width="1156" height="1524" data-path="images/workspace/auth/clerk-domain.png" />
</Frame>

DNS 变更最多可能需要 48 小时才能生效。记录生效后，邮箱与密码注册流程会自动从你的域名发送验证码，无需在 Auth 面板中进行其他操作。

<div id="section-13">
  ### 故障排查
</div>

* **收不到身份验证邮件** —— 请确认已完全按照 Manage 面板中显示的内容逐条添加记录，并包含 DNS 提供商要求的结尾点号。同时检查收件人的垃圾邮件文件夹。
* **记录仍未被检测到** —— 请等待 DNS 生效 (最长 48 小时) ，然后重新检查 Manage 面板中标记为缺失的记录。

<div id="section-14">
  ## 安全最佳实践
</div>

* **始终在服务器端校验** —— 不要只依赖 UI，请在 API 路由中验证身份
* **使用环境变量** —— 不要将密钥或机密信息硬编码在代码中
* **将代理中间件放在最前面** —— 在 Express 应用中，Clerk 代理必须挂载在 body parser 之前
* **不要将主页重定向到登录页** —— 让未登录的访问者也能访问着陆页

<div id="faq">
  ## 常见问题
</div>

<div id="clerk-authclerk">
  ### 使用 Clerk Auth 是否需要 Clerk 账户？
</div>

不需要。Agent 设置应用时，Replit 会自动创建并管理 Clerk Auth 背后的 Clerk 租户。您无需注册 Clerk，也无需自行管理 Clerk 的基础设施。

<div id="replitclerkclerk">
  ### 我可以访问由 Replit 托管的 Clerk 实例的 Clerk 控制台吗？
</div>

不可以。由 Replit 托管的 Clerk 实例不会通过 Clerk 控制台开放访问。请改用 Project Editor 中的 Auth 工具进行管理，配置提供商、查看用户以及在开发环境与生产环境之间切换，都在这里完成。

<div id="clerkpk_test">
  ### 我的 Clerk 可发布密钥以 `pk_test` 开头，如何切换到正式密钥？
</div>

无需切换。工作区 Secrets 面板中显示的 `pk_test...` 和 `sk_test...` 密钥属于应用的 Clerk**开发**环境，供你在构建阶段使用。应用发布后，部署会自动使用生产环境的 `pk_live...` 和 `sk_live...` 密钥。若要确认，请在工作区中打开 **Publishing → Overview → Adjust settings**，查看已发布应用的 `CLERK_PUBLISHABLE_KEY` 值，它应以 `pk_live` 开头。请勿手动编辑这些密钥。详情请参阅[开发环境与生产环境](#development-and-production-environments)。

<div id="section-15">
  ### 为什么用开发过程中创建的账户无法登录已发布的应用？
</div>

Clerk Auth 的**开发**环境和**生产**环境各自拥有独立的用户存储。在开发/预览应用中创建的账户仅存在于开发环境，发布时不会复制到生产环境，因此你需要在已发布的应用中重新注册。与 Clerk `userId` 关联的数据同样如此。可在工作区中打开 **Auth 面板**，在 **Users** 标签页使用环境切换开关分别查看各环境的用户。详情请参阅[独立的用户存储](#separate-user-stores)。

<div id="clerk-auth">
  ### Clerk Auth 可以免费使用吗？
</div>

目前，Clerk Auth 可免费使用。与 Replit 上的其他按用量计费服务一样，未来可能会推出按用量计费。届时，相关费用将通过现有的 Replit 账单收取，无需单独处理 Clerk 的账单或付款方式。

<div id="clerk-authmau">
  ### Clerk Auth 是否有月活跃用户 (MAU) 限制？
</div>

没有。与外部 Clerk 套餐不同 (其 MAU 上限取决于套餐层级) ，Clerk Auth 不设 MAU 限制。

<div id="clerk-authexternal-clerk">
  ### Clerk Auth 与 External Clerk 有何区别？
</div>

Clerk Auth 背后的 Replit 托管 Clerk 租户，与您使用 Clerk 账户创建的 Clerk 应用 (**External Clerk**) 之间存在一些差异。下表列出了两者目前的区别。这反映了 Clerk Auth 的当前状态，支持的功能将持续扩展。

|                 | Clerk Auth                       | External Clerk |
| --------------- | -------------------------------- | -------------- |
| **设置**          | 由 Replit 自动预配                    | 自行设置           |
| **Clerk 租户所有权** | 由 Replit 管理，归应用所有                | 归 Clerk 账户所有   |
| **定价模式**        | 目前免费 (未来计划按使用量计费)                | 订阅费＋按使用量计费     |
| **账单**          | Replit 账单 (目前免费)                 | 通过 Clerk 账户计费  |
| **MAU 限制**      | 无限制                              | 取决于套餐          |
| **代理和域名设置**     | replit.app 和已购买的域名自动设置，关联域名需手动设置 | 手动             |
| **SSO 身份提供方**     | 仅支持特定提供商：Google、Apple、GitHub、X   | 支持更多提供商        |
| **用户管理界面**      | Project Editor 中的 Auth 工具        | Clerk 应用仪表板    |
| **SMS**         | 不支持                              | 支持             |
| **MFA**         | 不支持                              | 支持             |
| **组织租户**        | 不支持                              | 支持             |

<div id="clerk-auth-2">
  ### 哪些 Clerk Auth 配置需要手动设置？
</div>

Clerk Auth 的大部分设置均已自动完成，但有些配置需要在 Auth 工具之外进行：

* **SSO 身份提供方的自定义 OAuth 凭据** — 如果你希望身份提供方的同意页面显示应用的名称和品牌，而不是 Replit 的默认信息，请在身份提供方的开发者控制台注册 OAuth 应用，然后将凭据粘贴到 Auth 面板中。请参阅[配置 SSO 身份提供方的 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
* **外部域名电子邮件验证的 DNS 记录** — 如果你的应用关联了由其他提供方管理的外部域名，则需要添加 DNS 记录，以便验证邮件能以该域名发出。请参阅[电子邮件验证的域名设置](#domain-setup-for-email-verification)。

<div id="replitclerkclerk-2">
  ### 可以使用自己的 Clerk 应用来替代 Replit 管理的 Clerk 应用吗？
</div>

可以。如果你的应用已配置 Replit 管理的 Clerk 应用，请先将其删除，再连接自己的外部 Clerk 应用：

1. 打开 Project Editor 中的 Auth 面板。
2. 转到 Configure 标签页。
3. 滚动到页面底部，然后点击**Delete Clerk app**。

删除 Clerk 应用后，Replit 管理的 Clerk 租户及其关联域名将一并删除和释放。之后，你可以连接自己的 Clerk 应用，并重新使用这些域名。如果你的应用尚未配置 Replit 管理的 Clerk 应用，可以跳过此步骤，直接集成外部 Clerk 应用。
