description: "Узнайте, как настраивать сетевые порты в приложении Replit и управлять ими."
---

Поскольку Replit запускает ваши проекты в облачной среде, порты здесь работают иначе, чем на локальном компьютере. (Если вам нужно более простое объяснение того, что такое TCP-порты, [начните отсюда](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

На обычном компьютере есть только один уровень управления портами: программы задают порт, который они прослушивают, и когда трафик из интернета приходит на этот порт вашего компьютера, он направляется в соответствующий процесс.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="компьютер" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

Часть `0.0.0.0` — это адрес, или хост. Если процесс прослушивает `0.0.0.0`, значит он слушает все сетевые интерфейсы: если другой компьютер (из интернета) отправит запрос на IP-адрес вашего компьютера, процесс его получит. Иными словами, прослушивание 0.0.0.0 означает, что такие процессы доступны из публичного интернета (если ваш компьютер подключён к сети).

Большинство фреймворков во время разработки *не* прослушивают `0.0.0.0`, потому что вы вряд ли захотите, чтобы ваша работа была общедоступной, пока вы над ней трудитесь, — из соображений приватности и безопасности. Вместо этого они прослушивают другой адрес — `127.0.0.1`, также известный как `localhost`. Это означает, что отправлять запросы на такой порт может только сам этот компьютер.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Порты localhost видны только на том компьютере, который их размещает." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

Чтобы запущенный в Replit процесс был доступен в веб-просмотре или через внешний запрос, для него нужно задать **внешний порт**. Дело в том, что «внутренний порт», который обычно используют процессы, виден только изнутри изолированной облачной среды (песочницы), предоставляемой Replit. Этот внутренний порт нужно связать с внешне доступным портом, чтобы нужный трафик поступал в ваши программы. Даже если ваш процесс прослушивает порт, обычно доступный публично, например 0.0.0.0, его всё равно необходимо привязать к внешнему порту.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Внешние порты перенаправляют трафик на внутренние порты, которые прослушивают программы." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit делает это, привязывая внешние порты к конкретным внутренним — например, на схеме выше внешний порт `:80` привязан к внутреннему порту `:3000`. Это значит, что весь трафик, который Replit App получит на порт 80, будет направлен на внутренний порт 3000.

Эта конфигурация записывается в разделе [[ports]] файла конфигурации .replit.

По умолчанию Replit привязывает первый открытый вами порт к внешнему порту по умолчанию 80, благодаря чему этот процесс доступен по домену без указания порта (например, customdomain.com/ вместо customdomain.com:3000/). Остальные открытые внутренние порты привязываются к другим доступным внешним портам (полный список см. ниже).

<div id="porta-padro">
  ## Порт по умолчанию
</div>

Порт :80 — это «порт по умолчанию» для HTTP-трафика, поэтому HTTP-трафик, отправленный на корневой домен, автоматически направляется на порт 80. Поэтому для порта 80 номер порта в URL не отображается. Порты, отличные от :`80`, будут указываться в адресе домена (например, customdomain.com:4200/). (Replit по умолчанию предоставляет TLS, поэтому技 технически трафик пойдёт через порт 443 — стандартный порт для HTTPS. На практике их можно считать взаимозаменяемыми.)

<div id="publicao">
  ## Публикация
</div>

Публикации типа Autoscale и Reserved VM поддерживают только один внешний порт, причём соответствующий внутренний порт не должен использовать `localhost`. Если открыть больше портов или открыть единственный порт на localhost, опубликованное приложение работать не будет. Чтобы публикации Autoscale гарантированно работали как надо, проще всего удалить из конфигурации все записи `externalPort`, *кроме* порта того сервиса, с которым вы хотите взаимодействовать из интернета.

<div id="depurao">
  ## Отладка
</div>

Частая причина того, что что-то работает не так, как ожидается: настройка портов выглядит правильной, но программа на самом деле обращается к другому порту. Например, если у вас такая конфигурация:

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Тогда интернет-трафик с порта 80 будет направляться на внутренний порт 3000. Однако если ваша программа на самом деле слушает не порт 3000, а другой (например, 8080), будет казаться, что трафик вообще не проходит. Такое случается, если изменить порт в коде, но не изменить соответствующий порт в конфигурации, или скопировать конфигурацию из одного проекта в другой.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Программы могут менять порты, которые они слушают." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

У каждого фреймворка свои порты по умолчанию: например, Flask использует 5000, react — 3000, а laravel — 8000. Убедитесь, что указан правильный порт!

<div id="preferncias">
  ## Настройки
</div>

Replit автоматически привязывает порты, открываемые в вашем Replit App, к доступным внешним портам в момент их открытия и записывает эту привязку в файл конфигурации .replit.

Однако по умолчанию этого не происходит для внутренних портов, открываемых на localhost: службы, которые обычно работают на localhost, как правило, рассчитаны на доступ только с того же компьютера, где выполняется процесс (порты localhost видны только этому компьютеру). Поэтому такие службы обычно менее защищены, чем службы, изначально рассчитанные на доступность из публичного интернета.

Вы всегда можете изменить это поведение, задав параметру конфигурации `exposeLocalhost` значение `true` для нужного порта.

Если вы хотите *всегда* открывать порты localhost по умолчанию, задайте параметру «автоматическое перенаправление портов» в инструменте пользовательских настроек значение «All ports».

Если же вы хотите *никогда* не создавать конфигурацию для открываемых портов и управлять настройкой портов во всём вашем Replit App вручную, задайте значение «never».

<div id="portas-suportadas">
  ## Поддерживаемые порты
</div>

При открытии первого порта Replit App назначит порт 80 внешним портом по умолчанию. В качестве дополнительных внешних портов Replit App может использовать порты 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080, 8081.

Порты 22 и 8283 недоступны для перенаправления, так как используются внутренними службами.

<div id="configurao-ports-do-replit">
  ## Настройка `[[ports]]` в .replit
</div>

Тип: `{localPort, externalPort, exposeLocalhost}`

Настройка `[[ports]]` позволяет задать, какой HTTP-порт будет использоваться для веб-вывода вашего приложения. По умолчанию любой HTTP-порт, открытый на хосте 0.0.0.0, становится веб-выводом вашего Replit App.

Дополнительные порты можно обслуживать, не переопределяя порт по умолчанию: для этого добавьте новую запись [[ports]] в файл .replit. Указать нужно и localPort, и externalPort. Чтобы добавить несколько дополнительных портов, добавьте в файл .replit несколько записей [[ports]], как показано ниже.

<div id="localport">
  ### localPort
</div>

Определяет, к какому внешнему порту Replit привяжет данный порт.

<div id="externalport">
  ### externalPort
</div>

Определяет, какой порт будет использоваться как общедоступный порт для этого локального порта.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Если вы хотите, чтобы определённый порт *никогда* не был доступен извне, можно оставить настройку `localPort`, но просто не добавлять `externalPort`:

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Определяет, можно ли привязать внутренний порт, использующий `localhost`, к внешнему порту. Может принимать значения `true`, `false` или оставаться пустым.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
