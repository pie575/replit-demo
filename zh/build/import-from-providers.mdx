通过导入功能，你可以将现有代码或设计导入 Replit Apps，并继续使用 Agent 进行开发。

<div id="supported-sources">
  ## 支持的来源
</div>

| 来源           | 需要提供的内容                              | 适用场景                            |
| ------------ | ------------------------------------ | ------------------------------- |
| GitHub       | 仓库 URL 或仓库选择器                        | 导入公开和私有仓库                       |
| Bitbucket    | 仓库 URL 或仓库选择器                        | 导入 Bitbucket 托管的仓库              |
| Vercel       | Vercel 项目所对应的 GitHub 仓库              | 迁移 Vercel 应用                    |
| Figma        | frame URL                            | 将设计转换为 React 应用                 |
| Claude       | 从 Claude 发送的设计                       | 将 Claude 设计转换为可交互应用             |
| Bolt         | 从 Bolt 导出的 GitHub 仓库                 | 迁移 Bolt 项目                      |
| Lovable      | 从 Lovable 导出的 GitHub 仓库              | 迁移 Lovable 项目                   |
| Base44       | 从 Base44 导出的 GitHub 仓库               | 迁移 Base44 项目                    |
| ZIP          | 上传 `.zip` 文件                         | 导入本地项目压缩包                       |
| 电子表格         | `.xlsx`、`.csv` 文件或 Google Sheets URL | 基于电子表格数据构建应用                    |
| 此前的 Agent 导出 | 从此前的 Agent App 导出的 GitHub 仓库         | 重新导入此前的 Agent App               |
| 空白           | 无需提供                                 | 希望创建不使用 Agent 的空白 项目的进阶用户 |

<Note>Replit 会在导入开始前校验兼容性。</Note>

关于 Figma 设计，请参阅[将 Figma 设计导入 Replit Design](/zh/design/import-figma-designs-into-replit-design)。

关于从 Claude 发送的设计，请参阅[将 Claude 设计导入 Replit Design](/zh/design/import-claude-designs-into-replit-design)。

  <Tab title="GitHub">
    ⏰ *预计用时：两分钟*

    将 GitHub 仓库导入 Replit，更快地运行、测试和发布。

    **开始之前**

    * 一个 GitHub 仓库 URL
    * 该仓库的访问权限 (公开或私有)
    * 一个 Replit 账户

    **方式一：快速导入**

    快速导入适用于公开仓库。

    1. 复制 `github.com/` 之后的仓库路径。
    2. 打开 `https://replit.com/github.com/<owner>/<repo>`。
    3. 按 Enter 键开始导入。

    *示例*

    * GitHub URL：`https://github.com/exampleUser/my-app`
    * Replit 导入 URL：`https://replit.com/github.com/exampleUser/my-app`

    **方式二：引导式导入**

    引导式导入同时支持公开和私有仓库。

    1. 打开 [replit.com/import](https://replit.com/import)。
    2. 选择 **GitHub**。
    3. 连接你的 GitHub 账户。
    4. 选择一个仓库。
    5. 选择 **Import**。

    **会导入的内容**

    * 仓库中的文件和文件夹
    * 依赖文件
    * 常见的运行和构建配置

    **不会导入的内容**

    * 已有的密钥值和环境变量值
    * 默认无法在 Replit 中运行的特定平台服务

    **排查 GitHub 连接问题**

    如果你看到 `Failed to get repository, please re-authenticate with GitHub`，或者仓库下拉列表显示 `No repositories found`，这是因为 GitHub 导入流程所用的连接与 **Account → Connected Services** 页面中的连接彼此独立。仅在 Connected Services 中重新连接，并不能解决导入流程的问题。

    <Steps>
      <Step title="从 Git Providers 重新连接 GitHub">
        打开 Replit 账户设置中的 **Git Providers** 部分，断开 GitHub 连接，然后在同一页面重新连接。完成后，你的个人仓库应该会出现在导入下拉列表中。
      </Step>

      <Step title="为你的 GitHub 组织批准 Replit 应用">
        如果该仓库归某个 GitHub 组织所有，请打开 [https://github.com/settings/applications](https://github.com/settings/applications)，找到 Replit OAuth 应用，并在第三方应用访问设置中授予其访问该组织的权限。如果你不是组织所有者，可能需要由组织管理员执行此步骤。
      </Step>

      <Step title="重新尝试导入">
        打开 [replit.com/import](https://replit.com/import) 再次尝试导入，分别用仓库下拉列表和粘贴仓库 URL 两种方式各试一次。
      </Step>
    </Steps>

  <Tab title="ZIP">
    ⏰ *预计耗时：三分钟*

    通过上传 `.zip` 文件导入本地项目。

    **开始之前**

    * 一个包含项目内容的 `.zip` 文件，大小不超过 200 MB
    * 压缩包中有清晰的项目根目录
    * 一个 Replit 账户

    如果压缩包超过 200 MB，导入表单将无法接受。请排除依赖和构建文件夹 (例如 `node_modules`、`.venv` 或 `build`) 以减小体积。Replit 会在导入过程中重新安装依赖。

    **步骤**

    1. 打开 [replit.com/import](https://replit.com/import)。
    2. 选择 **ZIP**。
    3. 上传你的 `.zip` 文件。
    4. 按提示添加所需的 Secrets 和环境变量。
    5. 选择 **Import**。

    **会导入的内容**

    * 项目文件和目录结构
    * 依赖文件
    * Replit 的运行和构建默认配置

    **不会导入的内容**

    * 已有的环境变量值
    * 自定义域名
    * 需要手动配置的平台专属服务
    * 已有的数据库数据
    * 已有的第三方 connector 配置

<div id="other-sources">
  ## 其他来源
</div>

<div id="bitbucket">
  ### Bitbucket
</div>

* 粘贴 Bitbucket 仓库 URL，或连接你的 Bitbucket 账户来搜索你的仓库。
* 与托管在 GitHub 上的 项目 相比，导入过程中的 Agent 支持可能较为有限。

<div id="spreadsheet">
  ### 电子表格
</div>

* 上传 Excel (`.xlsx`) 或 CSV 文件，或粘贴公开的 Google Sheets URL。
* Agent 会读取电子表格结构，并构建一个全栈 App，同时使用你的数据初始化数据库。
* 包含用于查看、搜索和管理记录的 UI。

<div id="previous-agent-export">
  ### 此前导出的 Agent 应用
</div>

* 从 GitHub 仓库重新导入此前导出的 Agent App。
* Replit 会保留 Agent 特有的结构 (代码、数据库架构、backend 功能) 。
* 数据库中的数据和密钥的值不会被导入。

<div id="empty">
  ### Empty
</div>

* 从完全空白的 项目 开始——没有 Agent，不用选择框架，也没有任何脚手架代码。
* 适合希望完全掌控 项目 初始配置的高阶用户。

<div id="limitations">
  ## 限制
</div>

* 现有数据库中的数据不会被迁移。
* ZIP 上传大小上限为 200 MB。
* 某些复杂或专有的依赖项可能需要手动配置。
* 大型 项目 的处理时间可能较长。

<div id="best-practices">
  ## 最佳实践
</div>

* 导入前移除敏感凭据。
* 保持源 项目 的结构整洁。
* 导入后核对依赖项和运行命令。
* 在 Publishing 之前测试核心流程。

<div id="troubleshooting">
  ## 故障排查
</div>

如果导入失败，请先从以下几个方面排查：

* **兼容性错误**：检查是否具备必需的项目文件，以及框架是否受支持。
* **访问错误**：确认仓库或来源的访问权限。
* **处理错误**：简化项目结构或缩减项目体积后重试。

如果问题仍未解决，请访问 [Replit 社区中心](https://replit.com/community)或[联系支持团队](https://replit.com/support)。
