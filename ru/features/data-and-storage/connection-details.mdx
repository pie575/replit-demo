Ваше приложение подключается к своей базе данных с помощью учётных данных, которыми управляет Replit. Найти их можно в инструменте **Database**: выберите базу данных и откройте вкладку **Settings**. На ней отображаются строка подключения, объём используемого хранилища и дополнительные параметры подключения.

<div id="environment-variables">
  ## Переменные окружения
</div>

Для подключения к базе данных разработки доступна следующая переменная окружения:

* `DATABASE_URL`: как подключиться к базе данных и пройти аутентификацию

Ваше приложение использует её автоматически. Поскольку `DATABASE_URL` действует только в пределах вашего приложения, к базе данных разработки не могут обращаться другие приложения — даже те, что принадлежат вам, — а также внешние средства просмотра баз данных. Даже в случае утечки никто посторонний не сможет с её помощью получить доступ к вашей базе данных и изменить её.

<Info>
  Если ваша база данных разработки всё ещё работает на [устаревшей инфраструктуре Neon](/ru/features/data-and-storage/development-and-production#legacy-development-database), дополнительно доступны переменные `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` и `PGPORT`. Для баз данных, размещённых на текущей инфраструктуре Replit, они **не** предоставляются — используйте вместо них `DATABASE_URL`.
</Info>

<Warning>
  Если вы всё ещё используете устаревшую базу данных разработки на Neon, никому не передавайте свою `DATABASE_URL`. Она содержит учётные данные вашей базы данных, с помощью которых любой сможет получить к ней доступ и изменить её. Никогда не публикуйте её в общедоступных местах и не указывайте в обращениях в поддержку.
</Warning>

<div id="connect-an-external-tool">
  ## Подключение внешнего инструмента
</div>

К **продакшен**-базе данных можно подключиться из любого SQL-клиента, совместимого с PostgreSQL, — с помощью строки подключения на вкладке **Settings** продакшен-базы данных.

<div id="security">
  ## Безопасность
</div>

Когда вы добавляете интеграцию с базой данных с помощью Agent, он подключает Object-Relational Mapper (ORM), который берёт на себя всё взаимодействие с базой данных и обеспечивает встроенную защиту:

* **Проверка схемы**: контролирует, что данные соответствуют ожидаемым форматам
* **Очистка данных**: автоматически обрабатывает вводимые разработчиком данные, предотвращая атаки с SQL-инъекциями

<div id="regenerate-production-database-credentials">
  ## Перевыпуск учётных данных продакшен-базы данных
</div>

Если строка подключения к продакшену была скомпрометирована, перевыпустите её учётные данные в инструменте Database. При этом создаётся новый пароль для продакшен-базы данных Neon. Существующие строки подключения к продакшену сразу перестают работать.

Перевыпустить учётные данные можно, если выполнены все перечисленные условия:

* У вашего приложения есть продакшен-база данных Neon.
* Вы владелец приложения или администратор workspace, которому оно принадлежит.
* Вы используете Replit в веб-браузере.
* В данный момент не выполняется ни один deployment.
* Если у приложения есть работающий deployment, его последняя сборка завершилась успешно и использует [Autoscale или Reserved VM](/ru/features/publishing/deployment-types).

<Warning>
  Это действие нельзя отменить. Существующие строки подключения сразу
  перестают работать. Если у вашего приложения есть работающий deployment, оно может
  быть кратковременно недоступно во время повторного развёртывания.
</Warning>

<div id="regenerate-the-credentials">
  ### Перевыпуск учётных данных
</div>

1. На панели инструментов выберите **Database**.

2. Выберите **Production Database**, затем откройте вкладку **Settings**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="Вкладка Settings продакшен-базы данных со строкой подключения, объёмом занятого хранилища и разделом Advanced, в котором находится строка Regenerate credentials." width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. В разделе **Advanced** разверните строку **Regenerate credentials**.

4. Нажмите кнопку **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Развёрнутая строка Regenerate credentials в разделе Advanced с кнопкой Regenerate credentials." width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. В диалоговом окне подтверждения нажмите **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="Диалоговое окно подтверждения Regenerate credentials с предупреждением о том, что действие нельзя отменить и существующие строки подключения сразу перестанут работать." width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Нажмите **Refresh**, чтобы загрузить новую строку подключения.

7. Если у вашего приложения есть работающий deployment, откройте **Publishing** и следите за повторным развёртыванием.

8. Замените строки подключения везде, куда вы их копировали: во внешних инструментах и собственных integration.

<div id="what-changes">
  ### Что изменяется
</div>

При перегенерации учётных данных создаётся новый пароль для продакшен-базы данных. В строке подключения меняется только пароль. Хост, имя базы данных и роль остаются прежними.

Для поддерживаемого работающего deployment Replit повторно развернёт последнюю успешную сборку с обновлённой строкой подключения.
