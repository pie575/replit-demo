一个**项目**是你在 Replit 中构建的所有内容的容器。**产物**是其中可发布的输出，包括 web 应用、移动应用、幻灯片、动画、数据可视化、3D 游戏和 Design。

当你要构建多个内容时，有两种选择：在同一个项目中添加多个产物，或创建单独的项目。该如何选择取决于你的应用是否共享数据、逻辑和部署生命周期。本页将详细介绍这两个概念，并说明何时应将产物放在同一个项目中，何时应创建单独的项目。

<div id="o-que-um-projeto">
  ## 什么是项目？
</div>

项目是存放代码、数据和所有已创建产物的容器。当你告诉 Agent 想要实现什么时，它会设置一个项目，并在其中构建产物。

你可以把项目想象成桌面上的工作区。所有内容都集中在一处，可以共享相同的信息，但每个部分都有不同的用途。

例如，如果你让 Agent 创建一款健身追踪移动应用，它会创建一个项目，其中包含移动 App 产物，以及运行所需的 backend、数据库和存储空间。

核心概念：

* **项目**：存放所有内容的容器，包括代码、数据和所有产物。
* **产物**：项目中的可发布输出 (如 Web 应用、幻灯片演示文稿、视频等) 。
* **资源**：每个产物都可自动使用 backend、数据库和文件存储，无需配置。

如需了解可对项目执行的所有操作——管理、筛选、固定和排序——请参阅[项目](/zh/pt/features/projects-and-artifacts/projects)。

<div id="o-que-um-artefato">
  ## 什么是产物？
</div>

产物是你可以在 Replit 上发布的内容。每个产物都是完整、独立的输出，发布后都会获得专属的可分享 URL。

项目中的其他所有内容——文件、图片、CSV 和代码——都用于支撑你的产物，但无法单独发布。

<div id="o-que-os-artefatos-compartilham-em-um-projeto">
  ## 产物在同一项目中共享的内容
</div>

当[产物](/zh/pt/features/projects-and-artifacts/artifacts)位于同一[项目](/zh/pt/features/projects-and-artifacts/projects)中时，会自动共享：

* **数据库**：一个产物写入数据后，其他产物可立即读取。
* **后端和 API**：共享服务器端逻辑，无需重复编写代码。
* **文件存储**：所有产物都可访问图片、文档和上传的文件。
* **部署**：发布时会将所有内容一并同步部署。

这意味着你无需在产物之间配置连接或重复编写代码。但这也意味着，你无法在不发布其他产物的情况下单独发布某个产物。

<div id="guia-rpido">
  ## 快速指南
</div>

以下是在决定向现有项目添加产物还是创建单独项目时，需要考虑的主要情况。

| **在一个项目中使用多个产物**       | **使用单独的项目**            |
| ---------------------- | ---------------------- |
| 应用共享相同的数据和后端           | 应用不共享底层逻辑或数据           |
| 你希望所有内容一同部署            | 你需要独立的部署周期             |
| 它们相互配套 (例如客户端应用和管理面板)  | 它们是互不相关的产品，或面向不同客户     |
| 你希望一个产物中的更改自动反映到其他产物中  | 项目是临时性的，例如营销活动落地页或活动网站 |

<div id="exemplos">
  ## 示例
</div>

<div id="mesmo-projeto-web-app-app-mvel-para-um-produto">
  ### 同一项目：一个产品的 Web 应用 + 移动应用
</div>

一家餐厅构建了一个 Web 应用，供顾客浏览菜单；还构建了一个移动应用，供员工管理订单。两者都连接到同一个数据库，其中包含菜单项目、订单和客户信息。

**为什么使用同一个项目：**这些应用共享相同的数据和 backend。当顾客通过 Web 应用下单后，员工会立即在移动应用中看到该订单。

<div id="mesmo-projeto-app-painel-de-administrador-deck-de-pitch-para-investidores">
  ### 同一项目：App + 管理后台 + 面向投资者的融资幻灯片演示文稿
</div>

一家初创公司在同一项目中构建其核心产品、用于管理内容的内部管理后台，以及用于融资的幻灯片演示文稿。

**为何使用同一项目：**管理后台管理着 App 展示的同一份数据，演示文稿还可以引用共享 backend 中的实时指标。

<div id="projetos-separados-dois-apps-de-clientes-no-relacionados">
  ### 独立项目：两个互不相关客户的 App
</div>

一名自由职业者为一位客户搭建电商商店，并为另一位客户开发预约系统。

**为何使用独立项目：**这两个 App 不共享数据或逻辑。每位客户都需要独立部署，你也不希望对其中一个 App 的更改影响另一个。

<div id="projetos-separados-landing-page-de-campanha-ao-lado-de-um-produto-principal">
  ### 独立项目：与主产品配套的营销活动落地页
</div>

你有一个全年运行的正式应用，以及一个用于营销活动的临时落地页。

**为什么使用独立项目：** 活动页面有自己的生命周期——你会将其上线，运行数周后再下线。将其单独维护，既可避免影响主产品，也能让你独立发布或移除它。

<div id="perguntas-frequentes">
  ## 常见问题
</div>

<Accordion title="可以将产物移到其他项目吗？">
  目前不可以。如果您需要将产物拆分出来，请新建一个[项目](/zh/pt/features/projects-and-artifacts/projects)，然后让 Agent 在其中重新构建。
</Accordion>

<Accordion title="一个项目最多可以有多少个产物？">
  一个项目最多可包含 7 个产物，且**每个项目最多只能有 1 个移动应用**。之所以设置此限制，是因为额外的产物会占用更多内存，可能导致预览变慢。如果您需要更多产物，请新建另一个[项目](/zh/pt/features/projects-and-artifacts/projects)。
</Accordion>

<Accordion title="可以只发布项目中的一个产物吗？">
  目前不可以。发布会将所有产物一并部署。如果您需要独立部署，请使用单独的项目。
</Accordion>

<Accordion title="产物之间会共享数据吗？">
  会。一个项目中的所有产物共享同一个数据库和 backend 服务。如果您的 Web 应用写入数据，移动应用和数据仪表板可以立即读取这些数据。
</Accordion>

<Accordion title="产物和文件有什么区别？">
  产物是可以发布的内容，例如 App、幻灯片和视频等。文件 (如 CSV、图片或代码) 是项目中用于支持产物的资源，但无法单独发布。
</Accordion>
