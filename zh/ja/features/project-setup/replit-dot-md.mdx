<div id="replitmd">
  ## `replit.md` 的工作原理
</div>

Agent 会先按照最佳实践在项目根目录中创建一个 `replit.md` 文件。该文件包含以下内容：

* 基本的项目信息
* 推荐的编码模式
* 适配项目类型的常用配置

<YouTubeEmbed videoId="kYv525W-vaU" title="如何自定义 Replit Agent 的响应" />

Agent 在处理请求时会自动读取 `replit.md` 文件，并将其内容用于以下方面：

* 了解项目的架构与约定
* 遵循你偏好的编码模式和风格
* 使用你指定的包管理器和依赖项

随着 Agent 对项目的了解不断加深，以及对应用进行修改，它也可能会更新 `replit.md` 文件。

<Note>
  你可以编辑 `replit.md` 文件来自定义 Agent 的行为。
</Note>

<div id="replitmd-2">
  ## 设置 `replit.md`
</div>

<div id="section">
  ### 自动生成
</div>

使用 Agent 创建新项目时，系统会基于最佳实践自动生成 `replit.md` 文件。该文件位于项目的根目录中，包含以下内容：

* 基本的项目信息
* 推荐的编码模式
* 针对项目类型的常用配置

<div id="section-2">
  ### 手动创建
</div>

你可以在项目的根目录下新建一个名为 `replit.md` 的文件，来创建自己的 `replit.md`。Agent 会在后续对话中自动检测并使用该文件。

<Note>
  `replit.md` 必须放在项目的根目录下才能正常生效。
</Note>

<div id="replitmd-3">
  ### 重新生成 `replit.md`
</div>

如果 `replit.md` 文件已损坏，或者你想从头开始：

1. 从项目根目录中删除现有的 `replit.md` 文件
2. 与 Agent 开启一段新对话
3. Agent 会根据当前项目自动生成新的 `replit.md` 文件

<div id="section-3">
  ## 最佳实践
</div>

<div id="section-4">
  ### 描述要具体明确
</div>

编写清晰、具体的指令，让 Agent 准确理解你的需求：

```markdown theme={null}
## 代码风格

- 所有新建的 JavaScript 文件均使用 TypeScript
- 优先使用带 hooks 的函数式组件，而非类组件
- 使用 Tailwind CSS 编写样式，避免内联样式
- 始终为函数参数和返回值标注 TypeScript 类型
```

有关 prompt 格式的详细指南，请参阅 [Anthropic prompt 工程指南](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags)。

<div id="section-5">
  ### 使用示例
</div>

比起抽象的描述，示例能让 Agent 更好地理解你的偏好：

````markdown theme={null}
## API Error Handling

When creating API endpoints, always use this error handling pattern:

```javascript
app.get("/api/users", async (req, res) => {
  try {
    const users = await getUsersFromDatabase();
    res.json({ success: true, data: users });
  } catch (error) {
    console.error("Error fetching users:", error);
    res.status(500).json({
      success: false,
      error: "Failed to fetch users",
    });
  }
});
```
````

  ### Web 应用项目
</div>

```markdown theme={null}
# MyApp 项目指南

## 项目概览
一款使用 React 和 Express.js 构建的任务管理 web app。

## 技术偏好
- 前端：React + TypeScript、Tailwind CSS
- 后端：Express.js + TypeScript
- 数据库：Neon PostgreSQL + Drizzle ORM
- 包管理器：npm（不使用 yarn 或 pnpm）

## 编码规范
- 使用配合 hooks 的函数式组件
- 实现合理的错误边界
- 接口遵循 REST API 规范
- 变量名和函数名要有描述性

## 沟通方式
- 修改前先说明你的思路
- 为复杂逻辑添加代码注释
- 需求不明确时主动提问
```

<div id="section-9">
  ### 数据分析项目
</div>

```markdown theme={null}
# 数据分析项目指南

## 项目背景
分析客户行为数据，发现趋势与洞察。

## 技术偏好
- 使用 Python 搭配 Streamlit 构建交互式 web app
- 使用 pandas、numpy 和 matplotlib 进行数据分析

## 分析规范
- 为所有分析步骤提供清晰的文档说明
- 使用 Streamlit 组件创建交互式可视化
- 分析前先校验数据质量
- 将结果导出为 CSV 格式，并在 Streamlit 表格中展示

## 沟通风格
- 说明所用的统计方法及其假设前提
- 为分析结果和建议提供背景说明
- 用清晰、非技术性的语言表达业务洞察
- 为面向相关方的演示创建交互式仪表板
```

- 为所有端点编写单元测试

<div id="replitmd-5">
  ## 网页搜索与 `replit.md` 结合使用
</div>

Agent 可以通过网页搜索查找最新的信息、库和解决方案。将其与 `replit.md` 文件结合使用，你既能获取最新知识，又能获得针对项目的专属指导。

<div id="section-13">
  ### 网页搜索集成的最佳实践
</div>

**请明确指定希望 Agent 调研的内容：**

```markdown theme={null}
## 调研偏好
- 在建议更新之前，务必确认依赖项的最新版本
- 调研当前安全实现方面的最佳实践
- 查找适用于我们技术栈的最新性能优化技巧
```

**指导 Agent 如何运用外部知识：**

```markdown theme={null}
## External Research Guidelines
- When suggesting new libraries, ensure compatibility with our existing stack
- Adapt external examples to match our coding standards and project structure  
- Verify that suggested solutions work with our publishing environment
```

**同时利用两者的请求示例：**
“请调研最新的 React 18 性能优化技巧，并按照 `replit.md` 中定义的组件模式来实现。”

采用这种方式，你既能获得最新的方案，又能确保它贴合具体项目的需求。

<div id="section-14">
  ## 限制
</div>

<div id="section-15">
  ### 文件大小与内容限制
</div>

`replit.md` 没有严格的字数限制，但文件过大时可能无法被完整处理。为获得最佳效果，请让 `replit.md` 保持重点突出、简明扼要。

<div id="section-16">
  ### 根目录要求
</div>

`replit.md` 必须位于项目的根目录下。Agent 不会自动检测子目录中的该文件。

<div id="section-17">
  ### 上下文范围
</div>

`replit.md` 为 Agent 对话提供上下文，但不会自动应用于其他 AI 工具。

<div id="section-18">
  ## 后续步骤
</div>

准备好为你的项目定制 Agent 了吗？

1. **从简单开始**：创建一个包含关键偏好设置的基础 `replit.md`
2. **迭代改进**：在与 Agent 协作的过程中不断更新 `replit.md`
3. **共享模式**：将行之有效的 `replit.md` 配置复用到类似项目中
4. **关注效果**：留意 Agent 遵循指南的程度，并按需调整

进一步了解[如何使用 Agent](/zh/ja/features/agent/overview)，或探索其他 [AI 工具](/zh/ja/build/welcome)。

**Enterprise**：在[自定义模板](/zh/ja/teams/custom-templates)中预先配置 `replit.md`，为组织中的所有构建者提供一致的起始上下文。有关设计方面的具体指导，请参阅[设计系统设置](/zh/ja/teams/custom-design-system)。
