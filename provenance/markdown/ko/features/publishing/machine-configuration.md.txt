# 머신 구성

> 게시된 앱을 실행하는 서버의 성능과 비용을 설정하세요: CPU, 메모리, 최대 머신 수.

머신 구성은 게시된 앱을 실행하는 서버의 성능을 제어합니다. Replit은 합리적인 기본값을 선택하므로 대부분의 빌더는 이를 변경할 필요가 없습니다. 앱이 부하 상태에서 느려지거나 메모리에서 대량의 데이터를 다루는 경우 더 강력한 구성을 고려하세요.

변경하려면 Publishing 도구를 열고 **Adjust settings**를 선택한 다음 **Machine configuration** 옆의 **Edit**를 선택하세요.

## 설정 항목

* **CPU**: 각 서버가 동시에 처리할 수 있는 작업량입니다. vCPU가 많을수록 많은 사람이 동시에 앱을 사용할 때 도움이 됩니다.
* **메모리(RAM)**: 앱이 메모리에 보관할 수 있는 데이터의 양입니다. RAM이 많을수록 대용량 파일, 미디어, 데이터 집약적인 작업에 도움이 됩니다.
* **최대 머신 수**: Autoscale에만 적용됩니다. 앱이 바쁠 때 Replit이 추가할 수 있는 서버의 상한선입니다. 앱은 이 수치를 초과하여 확장되지 않으므로 최대 비용이 제한됩니다.

## 비용

패널에는 구성 시 두 가지 숫자가 표시됩니다.

* **머신당**: 선택한 구성으로 서버 하나를 운영할 때의 시간당 비용입니다.
* **최대 트래픽 시**: 앱이 최대 머신 수까지 모두 사용할 정도로 바쁠 때의 시간당 비용입니다.

비용은 컴퓨팅 유닛으로 측정되며, 이는 선택한 CPU와 메모리를 기준으로 한 클라우드 컴퓨팅 단위입니다. 현재 요금과 사용량 청구 방식을 확인하려면 [사용량 기반 결제](/ko/billing/about-usage-based-billing#2-compute-units)를 참고하세요.

## 배포 유형별 청구 방식 차이

동일한 구성이라도 [배포 유형](/ko/features/publishing/deployment-types)에 따라 청구 방식이 다릅니다.

* **Autoscale**: 요청이 처리되는 동안 비용이 발생합니다. 앱이 유휴 상태이면 0으로 축소되어 실행 비용이 들지 않습니다.
* **Reserved VM**: 서버가 항상 켜져 있으므로 선택한 구성에 대해 고정된 월 비용을 지불합니다.
* **Static**: 사이트를 실행하는 머신이 없으므로 머신 구성이 적용되지 않습니다.
* **Scheduled**: 예약된 실행마다 머신 비용을 지불합니다.

## 변경 사항 적용

구성을 변경한 후 앱을 다시 게시하세요. 새 머신 설정은 새 배포와 함께 적용됩니다.
