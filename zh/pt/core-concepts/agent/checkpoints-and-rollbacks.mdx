使用 Replit 时，你无需担心丢失工作成果。

Replit 的 checkpoints 和回滚系统可为整个开发环境提供全面的版本控制和状态管理。

使用 Replit Agent 时，checkpoints 会自动保存项目的完整状态。这不仅包括代码更改，还包括项目文件、与 AI 的对话上下文以及已连接的数据库。

<div id="o-que-so-checkpoints">
  ## 什么是 checkpoint？
</div>

**checkpoint** 是 Agent 在开发的关键节点自动创建的 Replit App 完整状态快照。与只跟踪代码变更的传统版本控制不同，Replit 的 checkpoint 会捕获整个开发上下文。

你可以将 checkpoint 视为电子游戏中的存档点——随时都能回到应用正常运行的版本。

  <img src="/assets/mirror/agent-checkpoint-8e5b8b315c02.png" alt="Agent 的 checkpoint 界面，显示 回滚 选项" width="1554" height="876" data-path="images/replitai/agent-checkpoint.png" />
</Frame>

<div id="captura-completa-de-estado">
  ### 完整状态捕获
</div>

每个 checkpoint 都会保存：

* **项目文件**：所有文件、目录、已安装的包和项目配置
* **AI 对话上下文**：完整的对话历史记录，以及形成当前状态的上下文
* **环境配置**：运行时配置和部署配置
* **Agent 记忆**：AI 对项目架构、偏好和模式的理解
* **数据库内容**：创建 checkpoint 时的数据库数据和数据库架构

这种全面的保存方式让您可以放心尝试各种更改，因为您不仅可以恢复代码，还能恢复整个开发上下文。

<div id="como-funcionam-os-rollbacks">
  ## 回滚的工作原理
</div>

**回滚**功能可让你一键将 Replit App 恢复到任意先前的 checkpoint 状态。这比 Git 中的传统撤销操作强大得多。

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="显示 checkpoint 回滚选项的界面" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

回滚设计得既安全又可预测：

* **非破坏性预览**：某些界面允许你在执行回滚前预览 checkpoint 状态
* **明确边界**：每个 checkpoint 都代表一个逻辑开发里程碑
* **对话连续性**：AI 上下文会被保留，因此你可以从恢复后的状态继续构建
* **即时生效**：回滚会立即应用于整个开发环境

<div id="realizando-rollbacks">
  ### 执行回滚
</div>

当您回滚到较早的 checkpoint 时，项目会恢复到当时的状态，包括：

1. **完整的项目状态**：所有项目文件都会恢复到所选 checkpoint 时的确切状态
2. **AI 对话上下文**：Agent 对话会恢复到 checkpoint 对应的位置，保持上下文的连续性
3. **项目配置**：依赖项、包和运行时配置
4. **开发环境**：工具配置和项目编辑器配置
5. **数据库内容 (可选)&#x20;**：选中后，您的数据库将恢复到 checkpoint 创建时的状态

<Info>
  默认情况下，回滚不会更改您的数据库。要在回滚中包含开发数据库，请在“其他回滚选项”中选择“数据库”。

  请注意，此回滚功能不会自动恢复您的 **[生产数据库](/zh/pt/features/data-and-storage/development-and-production)**。
  若要了解如何将生产数据库恢复到较早的时间点，请参阅[有关如何执行时间点恢复的文档](/zh/pt/features/data-and-storage/development-and-production/#point-in-time-restore)。
</Info>

<Warning>
  使用回滚功能时，您会将 Replit App 恢复到先前状态。这会移除该时间点之后所做的所有更改，包括代码编辑。如果您选择恢复数据库，数据库中的更改也会被还原。
</Warning>

<div id="avanando-no-histrico">
  ### 在历史记录中前进
</div>

Replit 中的 checkpoint 支持双向操作——您可以在项目历史记录中前进或后退。
这让您可以灵活浏览开发时间线，无需担心丢失工作内容。

如果您回退得太远，或想恢复后续 checkpoint 中的更改，可以**前进**到 checkpoint 历史记录中的后续位置。这样您就能自由浏览项目时间线，而不会丢失工作内容。

要前进，请在 Agent 标签页中点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" /> 以打开历史记录视图，然后选择当前所在位置之后的 checkpoint。

<Info>
  只有当前所在位置之后仍有 checkpoint 时，才能前进。回滚后如果进行了新的更改，这些后续 checkpoint 将成为历史记录中的另一个分支。
</Info>

这种双向导航让您能够完全掌控项目时间线，确保您的工作始终可以恢复。

<div id="criao-de-checkpoints">
  ## 创建 checkpoint
</div>

Replit 的 AI 工具会在开发过程中的关键节点自动创建 checkpoint。

<div id="checkpoints-do-agent">
  ### Agent checkpoint
</div>

[Replit Agent](/zh/pt/core-concepts/agent) 会在以下情况下创建 checkpoint：

* **功能完成后**：成功实现所需功能后
* **重要里程碑**：复杂任务取得重大进展时
* **稳定状态**：完成对已实施更改的测试和验证后
* **错误恢复**：尝试修复关键问题前

<div id="caractersticas-dos-checkpoints">
  ### checkpoint 的特性
</div>

每个 checkpoint 包含：

* **AI 生成的描述**：清晰说明已完成工作的摘要
* **时间戳信息**：精确的创建时间，便于识别
* **变更范围**：标明已修改的文件、功能或系统
* **计费信息**：Agent 可透明追踪每个 checkpoint 的费用

<div id="usando-checkpoints-e-rollbacks">
  ## 使用 checkpoint 和回滚
</div>

<div id="encontrando-checkpoints">
  ### 查找 checkpoint
</div>

checkpoint 会显示在项目编辑器的多个位置：

**Agent 标签页**：查看 Agent 创建的所有 checkpoint，包括说明和 回滚 选项
**Git 面板**：将 checkpoint 视为 Git 提交，并享受完整的版本控制集成
**历史记录视图**：在 Agent Chat 中，点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" />，即可查看所有 checkpoint 及其进展的完整时间线

<div id="realizando-rollbacks-2">
  ### 执行回滚
</div>

回滚流程会因启动位置不同而略有差异：

<div id="da-aba-do-agent">
  #### 在 Agent 选项卡中
</div>

<Steps>
  <Step title="前往 Agent">
    在项目编辑器中打开 **Agent** 选项卡，查看 Agent 创建的所有 checkpoint。
  </Step>

  <Step title="选择 checkpoint">
    找到要恢复的 checkpoint，然后选择 **回滚到此处**。
  </Step>

  <Step title="确认回滚">
    查看回滚提示并确认，将应用恢复到所选状态。
  </Step>

  <Step title="验证恢复结果">
    确认项目文件、数据库和 AI 上下文是否与已恢复的 checkpoint 状态一致。
  </Step>
</Steps>

<div id="melhores-prticas">
  ### 最佳实践
</div>

**策略性地使用 checkpoint**：

* 在每个重要 checkpoint 后测试应用，确保其稳定性
* 除自动 checkpoint 外，还应创建手动 Git 提交，以便长期跟踪版本
* 查看 checkpoint 描述，了解具体变更

**回滚 注意事项**：

* 执行 回滚 前，务必确认变更范围
* 考虑其对数据库和外部集成的影响
* 将 回滚 情况告知协作者，确保团队成员了解相关信息

**迭代式开发**：

* 采用增量式开发，充分利用频繁创建的 checkpoint
* 使用 回滚 安全地探索不同的实现方案
* 利用 AI 上下文保留功能，在 回滚 后继续对话

<div id="integrao-com-controle-de-verso">
  ## 与版本控制集成
</div>

checkpoint 可与 Replit 更广泛的版本控制生态系统无缝集成：

<div id="integrao-com-git">
  ### Git 集成
</div>

* **生成 Git 提交**：每个 checkpoint 都会创建对应的 Git 提交
* **分支兼容性**：checkpoint 遵循分支结构和合并工作流
* **远程同步**：与 GitHub 集成后，checkpoint 可保持同步
* **命令行访问**：可结合 checkpoint 使用完整的 Git 功能

<div id="recursos-de-colaborao">
  ### 协作功能
</div>

* **团队可见性**：所有项目协作者都能查看 checkpoint
* **减少合并冲突**：checkpoint 的创建时机可降低冲突发生的概率
* **共享上下文**：与 AI 的对话上下文有助于团队成员理解更改内容
* **实时更新**：协作者可以实时看到 checkpoint 被创建

<div id="recursos-avanados">
  ## 高级功能
</div>

<div id="pr-visualizaes-de-checkpoint">
  ### checkpoint 预览
</div>

部分界面支持 checkpoint 预览功能：

* **视觉对比**：查看应用在不同 checkpoint 状态下的呈现效果
* **非破坏性探索**：无需实际执行回滚即可预览
* **进度跟踪**：了解应用如何随时间演变
* **迭代对比**：比较不同的实现方案

<div id="rollbacks-entre-sesses">
  ### 跨会话回滚
</div>

适用于高级构建者和团队管理员：

* **扩展历史记录**：访问多个开发会话中的 checkpoint
* **管理控制**：团队管理员可跨用户会话执行回滚
* **审计追踪**：完整记录 checkpoint 的创建和回滚操作历史

<div id="casos-de-uso">
  ## 使用场景
</div>

<div id="desenvolvimento-experimental">
  ### 实验性开发
</div>

checkpoint 让你可以放心尝试：

* 尝试新功能，随时可以轻松回退
* 测试不同的架构方案
* 探索不同的界面设计或用户流程
* 在完善的保障下实施复杂集成

<div id="depurao-e-recuperao">
  ### 调试与恢复
</div>

出现问题时，checkpoint 可提供可靠的恢复机制：

* 引入 bug 后，回退到正常运行的状态
* 通过比较 checkpoint 状态定位问题
* 数据损坏后恢复数据库完整性
* 从意外删除或修改中恢复

<div id="aprendizado-e-iterao">
  ### 学习与迭代
</div>

checkpoint 有助于学习和迭代开发：

* 比较不同的实现策略
* 通过 checkpoint 的演进过程，了解 AI 的决策思路
* 通过探索功能的演变过程加深理解
* 借助 回滚 的保障练习新技术
