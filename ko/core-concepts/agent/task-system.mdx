<div id="what-is-the-task-system">
  ## Task 시스템이란?
</div>

**task**는 Agent가 계획하고 실행할 수 있는 작업 단위입니다. task를 활용하면 Agent가 큰 목표를 작은 단위로 나누기 때문에, 각 단위가 앱에 반영되기 전에 하나씩 검토할 수 있습니다.

Agent는 **main thread**와 **백그라운드 task**, 두 곳에서 작업할 수 있습니다. main thread는 원하는 바를 설명하고, direction을 다듬고, 메인 버전에 무엇을 적용할지 결정하는 conversa입니다. 백그라운드 task는 Agent가 project의 격리된 사본에서 독립적으로 작업하는 별도의 thread입니다.

direction을 잡고 결정을 내릴 때는 main thread를, 병렬로 진행할 수 있는 실행 작업에는 백그라운드 task를 사용하세요. 백그라운드 task는 직접 검토하고 적용하기 전까지는 메인 버전을 변경하지 않습니다.

Task 시스템은 Agent가 이러한 작업을 정리하는 방식입니다. 만들고 싶은 것을 설명하면 Agent가 요청을 개별 task로 나누어 **Drafts**, **Active**, **Ready**, **Done** 열로 구성된 board에 배치합니다.

<Frame>
  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="Drafts, Active, Ready, Done 열로 정리된 task를 보여주는 Task board" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />
</Frame>

각 task는 진행 상황에 따라 왼쪽에서 오른쪽으로 이동하므로, 무엇이 계획되어 있고, Agent가 무엇을 작업 중이며, 무엇이 검토를 기다리고 있고, 무엇이 완료되었는지 한눈에 파악할 수 있습니다. 백그라운드 task는 plan에 따라 자동으로 대기열에 들어가므로 main thread가 복잡해지지 않으면서도 작업이 계속 진행됩니다.

task가 준비되면 changes를 검토한 뒤 메인 버전에 적용하거나, 원하던 결과가 아니라면 무시하면 됩니다.

<div id="how-background-tasks-work">
  ## 백그라운드 task 작동 방식
</div>

<Steps>
  <Step title="task 계획하기">
    main thread에서 대화를 시작하거나, 새 thread를 만들어 그곳에서 계획하세요. Agent가 프로젝트를 검토해 가장 효과가 큰 작업을 파악하고, 각 task마다 무엇을 할지와 &quot;완료&quot;의 기준이 무엇인지를 담은 상세한 계획을 작성합니다.

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="main thread에서 만들 내용을 설명하고 Agent가 task를 제안하고 실행하는 모습" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="검토하고 수락하기">
    Agent는 제목, 설명, 그리고 **View plan**으로 확인할 수 있는 상세 계획이 포함된 task 목록을 제안합니다. 전체 목록을 검토한 후 다음 중에서 선택하세요:

    * **Accept tasks**: 모든 task를 시작해 백그라운드로 보냅니다
    * **Revise plan**: 시작하기 전에 Agent에게 task 조정을 요청합니다

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="제안된 네 개의 task와 Accept tasks, Revise plan 옵션이 표시된 task plan 생성 대화상자" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="task 실행 시작">
    수락하면 task는 프로젝트의 격리된 복사본에서 실행되기 시작합니다. Starter는 백그라운드 task를 지원하지 않습니다. Core는 한 번에 1개, Pro는 최대 10개, Enterprise는 최대 64개까지 실행할 수 있습니다. 변경 사항을 적용하기 전까지 main 버전은 그대로 유지됩니다. 진행 상황은 두 가지 방식으로 추적할 수 있습니다:

    * **Thread 보기**: 각 task는 실시간 status 표시와 함께 자체 thread에서 실행되므로, 진행 상황을 따라가거나 특정 task의 conversation으로 바로 이동할 수 있습니다

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="여러 task가 status 표시와 함께 병렬로 실행되는 thread 보기" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **Board 보기**: 모든 task를 status별로 정리해 보여주는 열 기반 board입니다: **Drafts**, **Active**, **Ready**, **Done**

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="Drafts, Active, Ready, Done 열로 task가 정리된 board 보기" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="검토하고 적용하기">
    task가 끝나면 Agent가 수행한 내용을 보여줍니다: 작업 로그, 테스트 결과, 변경 사항의 실시간 preview입니다. 다음에 무엇을 할지는 여러분이 결정합니다:

    * **Apply changes to main version**: task의 작업을 프로젝트에 merge합니다
    * **Dismiss**: 원하던 결과가 아니라면 변경 사항을 폐기합니다

    여러 task의 변경 사항을 적용할 때 발생하는 충돌은 Agent가 자동으로 해결합니다.

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="Agent의 작업 로그, 테스트 결과, Apply changes 버튼이 표시된 task 검토 화면" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="what-you-can-build">
  ## 무엇을 만들 수 있나요
</div>

Task 시스템은 어떤 project에서든 활용할 수 있습니다. 특히 다음과 같은 경우에 빛을 발합니다:

* **큰 기능을 작은 단위로 나눠 출시하기**: authentication, dashboard, API 계층을 각각 별도의 task로 나누면 Agent가 하나씩 깔끔하게 처리할 수 있습니다
* **복잡한 projects 계획하기**: 큰 기능을 dependencies가 명확하고 범위가 잘 잡힌 task로 나눈 뒤 자신 있게 실행하세요
* **여러 design direction 비교하기**: 별도의 task로 여러 UI 접근 방식을 시도해 보고 가장 좋은 결과를 선택하세요

<div id="frequently-asked-questions">
  ## 자주 묻는 질문
</div>

<Accordion title="빌드 방식을 바꿔야 하나요?">
  아닙니다. main thread는 이전과 똑같이 동작합니다. Agent는 필요할 때 백그라운드에서 자동으로 task를 생성합니다. [Plan mode](/ko/features/agent/plan-mode)에서 task를 직접 확인하고 관리할 수도 있습니다.
</Accordion>

<Accordion title="task가 왜 한 번에 하나씩만 실행되나요?">
  Starter는 백그라운드 task를 지원하지 않습니다. Core는 한 번에 1개, Pro는 최대 10개, Enterprise는 최대 64개까지 실행합니다. plan의 limit에 도달하면 추가 task는 대기열에 들어갔다가 자리가 나는 대로 시작됩니다.
</Accordion>

<Accordion title="백그라운드 task를 적용할 때 Agent는 충돌을 어떻게 처리하나요?">
  Agent는 AI 기반 충돌 해결을 사용합니다. 각 task가 무엇을 하려고 했는지 파악한 뒤 changes를 알아서 적절히 적용합니다. 결과가 이상해 보이면 thread에서 Agent에게 수정을 요청하세요.
</Accordion>

<Accordion title="task끼리 서로 의존할 수 있나요?">
  네. Agent가 dependencies를 자동으로 감지합니다. 예를 들어 dashboard를 만드는 task는 database schema를 생성하는 task에 의존합니다. 의존 관계가 있는 task는 선행 task가 완료될 때까지 대기합니다.
</Accordion>

<Accordion title="task를 보관하는 것과 취소하는 것의 차이는 무엇인가요?">
  **보관**은 아직 building을 시작하지 않은 초안 상태의 계획 session에 적용됩니다. 보관된 계획 session은 그대로 유지되며 **Done** 열에서 복원할 수 있습니다.

  **취소**는 계획 단계를 지나 이미 building에 들어간 task에 적용됩니다. 취소하면 task가 중단되고 작업 내용이 폐기되며, 취소된 task는 복원할 수 없습니다. 이 경우 새 task를 시작하세요.
</Accordion>
