应用测试让 Agent 能够在真实浏览器中测试它构建的应用。Agent 会像真实用户一样操作你的应用，逐处点击并验证各项功能。这种自我测试能力有助于确保应用正常运行，并让 Agent 自动发现并修复问题。

</div>

启用应用测试后，当 Agent 认为改动足够多、有必要测试时，就会适时自行执行测试。Agent 并不会在每一条用户消息后都进行测试，而是智能判断何时测试最有价值。

<Note>
  目前，应用测试适用于全栈 JavaScript 和 Streamlit Python web 应用。
</Note>

<div id="key-benefits">
  ### 主要优势
</div>

* **更强的自主性**：让 Agent 无需人工干预即可持续工作更长时间
* **更高的质量**：及早发现并解决问题，生成的应用错误更少
* **更省成本**：在开发阶段就发现问题，免去额外的调试环节
* **交互式回顾**：提供视频回放和分段导航，便于全面分析结果

<div id="the-testing-process">
  ### 测试流程
</div>

当 Agent 决定进行自测时，会发生以下过程：

1. **浏览器预览**：你会在 Agent 面板中看到一个浏览器预览窗口
2. **可视化测试**：你可以看到 Agent 的光标在应用中四处点击，逐一测试各项功能
3. **真实用户模拟**：Agent 会像真实用户一样浏览你的应用，并在需要时输入模拟数据
4. **自动分析**：Agent 会分析测试结果，找出存在的问题
5. **自我纠正**：Agent 会反馈一份测试摘要，并自动修复发现的问题

<div id="key-capabilities">
  ## 核心能力
</div>

Agent 会像真实用户一样操作你的应用，智能地完成测试，涵盖：

* **用户界面验证**：按钮、表单、导航和视觉元素
* **功能验证**：核心功能和用户流程
* **集成测试**：API 调用、数据库交互和第三方服务
* **性能与无障碍**：加载时间、响应速度和无障碍标准

<div id="usage">
  ## 使用方式
</div>

应用测试 位于聊天输入框中 Agent 设置下拉菜单的 **Advanced settings** 内。使用 Economy 或 Power 模式时，可将其开启；Lite 模式下 应用测试 始终处于关闭状态。

<Note>
  应用测试 与内置代码审查同属 Agent 的自主能力。进一步了解其他 [Agent
  功能](/zh/features/agent/overview)。
</Note>

<div id="take-over">
  ## 接管
</div>

有时 Agent 在测试过程中会遇到障碍，需要你的帮助才能继续。最常见的情况是需要登录某个用户账号 (例如 Gmail) 。遇到这类情况时，Agent 会弹出一个“开始接管”按钮。

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="应用测试接管界面，显示“跳过”和“开始接管”按钮，以及处理错误和验证码的说明" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

点击“开始接管”后，你可以在测试预览中进行操作，完成必要的步骤，然后交由 Agent 继续执行。你也可以点击“跳过”来跳过接管；此时如果 Agent 没有你的帮助就无法继续，应用测试将就此结束。如果你在 10 分钟内未做出响应，Agent 会视作你点击了“跳过”并继续执行。

<div id="what-to-expect">
  ### 预期效果
</div>

* **跳过选项**：如有需要，可点击跳过按钮略过测试，继续进行开发
* **交互式视频回放**：测试结束后，点击视频即可回放整个测试过程
* **分段导航**：使用底部的滑块可跳转到测试的特定环节

<div id="troubleshooting">
  ## 疑难解答
</div>

**测试意外失败**

* 尝试先跳过，然后再次发送 prompt 进行测试
* 检查是否存在可能影响测试时机的动态内容
* 检查测试场景是否准确

**测试覆盖不全**

* 更详细地描述应用的功能
* 明确指出需要测试的关键用户流程

**应用测试 完全无法使用？**

* 目前 应用测试 仅支持 web app[*](#how-app-testing-works)

<div id="pricing-and-usage">
  ## 价格与用量
</div>

应用测试属于 Agent 基于工作量的计费模式，使用时需注意以下成本因素：

* **按用量计费**：测试根据所耗费的工作量收费 (测试越简单，费用越低)
* **成本与收益**：测试虽然会产生费用，但能更早发现问题，避免额外的 prompt 和 Agent 的额外工作，反而更省成本
* **高效开发**：自动化方式减少了手动调试和返工

<Tip>
  **高性价比的测试**：应用测试虽然会增加用量成本，但整体上通常更省钱，因为它能避免为修复本可在测试阶段发现的问题而额外开启 Agent 会话。
</Tip>
