作为 Enterprise 管理员，您可以配置组织范围内的设置，控制团队成员与代码、部署和外部平台的交互方式。这些设置有助于维护安全标准、保护知识产权，并确保遵守 Enterprise 政策。

<div id="section">
  ## 访问隐私设置
</div>

<Accordion title="如何访问隐私设置">
  1. 前往企业工作区
  2. 选择**设置**
  3. 选择**高级**，查看所有可用设置
</Accordion>

<div id="section-2">
  ## 隐私设置
</div>

隐私设置可控制组织内应用的发布方式和访问权限。

<CardGroup cols={2}>
  <Card title="私有部署" icon="lock">
    要求将所有新应用以私有方式发布，并仅允许已认证的团队成员访问
  </Card>

  <Card title="密码保护部署" icon="key">
    允许团队成员为已发布的应用添加密码保护
  </Card>

  <Card title="私有开发 URL" icon="shield-halved">
    要求对所有应用开发 URL 进行认证，包括启用 SAML 的组织的 SSO
  </Card>
</CardGroup>

<div id="section-3">
  ### 私有部署
</div>

启用后，所有新应用都必须以私有方式发布。只有组织中已认证的成员才能访问私有应用。

**适用场景：**

* 组织处理敏感数据或专有应用
* 需要防止应用被意外发布
* 合规要求必须限制对已发布应用的访问

<Note>
  此设置仅适用于新发布的应用。现有已发布应用将保留当前的发布设置。
</Note>

<div id="section-4">
  ### 密码保护部署
</div>

控制团队成员能否创建密码保护部署。启用后，构建者可以为已发布的应用设置访问密码，增加一层额外的安全保障。

**适合使用此设置的情况：**

* 希望与外部相关方共享应用，但不想将其完全公开
* 团队需要在更广泛发布前向客户演示应用
* 需要在组织成员资格之外实施细粒度访问控制

<div id="url">
  ### 要求使用私有开发 URL
</div>

启用后，所有应用开发 URL 都必须经过认证。如果组织已启用 SAML，访问开发 URL 时还需要通过 SSO 认证。

**适合在以下情况下使用此设置：**

* 需要防止未经授权访问正在开发的应用
* 安全策略要求保护所有开发环境
* 希望仅允许已认证的团队成员查看开发预览

<Warning>
  此设置将追溯应用于组织中的所有现有应用。
</Warning>

<div id="section-5">
  ### 禁止导出源代码
</div>

启用后，团队成员将无法将应用源代码导出为 zip 文件，从而防止代码被下载或共享到 Replit 平台之外。

**建议在以下情况下使用此设置：**

* 需要严格控制源代码的存放位置
* 安全策略禁止保存代码的本地副本
* 希望确保所有开发工作都在受管控的环境中进行

<div id="section-6">
  ## 安全设置
</div>

安全设置可帮助你执行漏洞扫描并采取其他保护措施。

<div id="section-7">
  ### 要求进行安全扫描
</div>

设置是否要求所有应用在发布前通过安全扫描。安全扫描可检测代码中的漏洞、暴露的密钥及其他安全问题。

可用选项：

| 设置     | 说明               |
| ------ | ---------------- |
| **关闭** | 安全扫描为可选          |
| **必需** | 所有应用必须在发布前通过安全扫描 |

**以下情况适合使用此设置：**

* 需要满足安全合规要求时
* 希望防止 API 密钥或其他密钥意外泄露时
* 需要确保所有已发布应用遵循一致的安全标准时

<Note>
  此设置不适用于该设置生效前已发布的应用。
</Note>

<div id="section-8">
  ## 源代码管理设置
</div>

源代码管理设置有助于落实版本控制规范，并保护组织的代码仓库。

<div id="git">
  ### Git 远程仓库要求
</div>

启用后，所有应用都必须先将本地更改推送到 Git 远程仓库，才能发布。这可确保组织的版本控制系统能够追踪所有代码更改。

**在以下情况下使用此设置：**

* 需要将所有代码备份到 Git
* 需要保留所有代码更改的审计记录
* 工作流程要求在发布前进行代码审查

<Note>
  此设置不适用于启用前已发布的应用。
</Note>

<div id="section-9">
  ### 私有远程仓库
</div>

控制团队成员是否可以使用公开 Git 仓库。启用“要求使用私有远程仓库”后，团队成员只能推送到 GitHub 等平台上的私有仓库。

可用选项：

| 设置         | 说明                       |
| ---------- | ------------------------ |
| **关闭**     | 团队成员可以使用公开或私有仓库          |
| **要求非管理员** | 非管理员团队成员必须使用私有仓库         |
| **要求所有人**  | 所有团队成员 (包括管理员) 都必须使用私有仓库 |

**请在以下情况下使用此设置：**

* 禁止使用公开代码仓库时
* 需要防止专有代码被意外推送到公开仓库时
* 合规要求必须使用私有版本控制时

<div id="section-10">
  ## 最佳实践
</div>

<AccordionGroup>
  <Accordion title="默认设为私有" icon="shield">
    启用**私有部署**，确保所有新发布的应用均为私有。这有助于防止敏感应用被意外暴露。
  </Accordion>

  <Accordion title="强制执行安全扫描" icon="magnifying-glass">
    设置**要求进行安全扫描**，以便在应用发布前检测漏洞。这有助于在整个组织内保持一致的安全标准。
  </Accordion>

  <Accordion title="保护开发环境" icon="code">
    启用**要求使用私有开发 URL**，确保开发中的工作也受到保护。这对于处理敏感数据的组织尤为重要。
  </Accordion>

  <Accordion title="控制源代码访问" icon="code-branch">
    将**禁止导出源代码**与**私有远程仓库**要求结合使用，即可全面掌控代码的存储位置和访问权限。
  </Accordion>
</AccordionGroup>
