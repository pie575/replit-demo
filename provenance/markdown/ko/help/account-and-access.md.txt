# 계정 및 액세스

> 일반적인 계정 질문에 대한 답변—비밀번호 재설정, 액세스 복구, 이메일 또는 사용자 이름 변경, 계정 삭제, 정지 이의 제기, 기업 네트워크 액세스.

이 답변은 계정 액세스 및 보안을 다룹니다. 계정 삭제에 대한 자세한 내용은 [데이터 삭제](/ko/legal-and-security-info/deleting-your-data)를 참조하고, 정지에 대해서는 [제재 시스템 FAQ](/ko/legal-and-security-info/strike-system-faq)를 참조하세요.

<AccordionGroup>
  <Accordion title="비밀번호를 어떻게 재설정하나요?">
    1. [replit.com/forgot](https://replit.com/forgot)으로 이동합니다.
    2. 계정에 연결된 이메일을 입력합니다.
    3. `notifications@replit.com`에서 온 재설정 이메일을 여세요—보이지 않으면 스팸 폴더를 확인하세요.
    4. 링크를 선택하고 새 비밀번호를 만드세요.

    Google, GitHub, Facebook 또는 Apple로 가입한 경우 동일한 페이지에서 독립형 비밀번호를 만들 수 있습니다. 이메일이 도착하지 않으면 가입 시 사용한 정확한 이메일을 입력하고 있는지 확인하세요.
  </Accordion>

  <Accordion title="로그인할 수 없습니다—계정 액세스를 어떻게 복구하나요?">
    순서대로 시도하세요:

    1. [replit.com/forgot](https://replit.com/forgot)에서 비밀번호를 재설정하고 이메일의 스팸 폴더를 확인하세요.
    2. Google, GitHub 또는 Apple로 가입한 경우 이메일 및 비밀번호 양식 대신 **\[제공업체]로 계속** 버튼을 사용하세요.
    3. 가입 시 사용한 이메일을 사용하고 있는지 확인하세요—다른 이메일을 사용했을 수 있습니다.

    이 중 어느 것도 해결되지 않으면 [Replit 지원팀에 문의](https://replit.com/support)하세요.
  </Accordion>

  <Accordion title="다른 사람의 프로젝트가 보이거나 허가 없이 계정에 접근한 것 같습니다">
    빠르게 조치하세요:

    1. [replit.com/forgot](https://replit.com/forgot)에서 비밀번호를 재설정합니다.
    2. 계정 보안 설정에서 다른 활성 세션에서 로그아웃합니다.
    3. 발견한 내용을 포함하여 [Replit 지원팀에 문의](https://replit.com/support)하세요.

    본인 것이 아닌 프로젝트가 보인다면 다른 계정에 로그인되어 있을 수 있습니다—오른쪽 상단의 계정 이름을 확인하세요.
  </Accordion>

  <Accordion title="이메일 주소나 사용자 이름을 어떻게 변경하나요?">
    사용자 이름을 변경하려면 [CLUI](/ko/features/workspace-tools/clui-graphical-cli)에서 `account > change-username` 명령을 실행하고 새 사용자 이름을 제출하세요. 사용자 이름은 한 번만 변경할 수 있습니다.

    이메일을 변경하려면 **설정 → 프로필**로 이동하여 이메일을 편집하세요. 본인 인증을 완료할 수 없는 경우 현재 및 새 이메일 주소를 포함하여 [Replit 지원팀에 문의](https://replit.com/support)하세요.
  </Accordion>

  <Accordion title="Replit 계정을 영구적으로 삭제하려면 어떻게 하나요?">
    먼저 보관하고 싶은 것을 다운로드하세요—삭제는 취소할 수 없습니다. 웹에서 활성 구독을 취소한 다음 **설정 → 프로필**로 이동하여 계정 삭제를 요청하세요. 모바일에서는 Replit 앱에서 **계정 → 더 보기 → 계정 삭제**를 여세요. [데이터 삭제](/ko/legal-and-security-info/deleting-your-data)를 참조하세요.
  </Accordion>

  <Accordion title="동일한 이메일로 두 개의 Replit 계정이 있는 것 같습니다—어떻게 해결하나요?">
    이것은 한 가지 방법(예: 이메일)으로 가입하고 나중에 다른 방법(예: Google)으로 로그인하여 두 번째 계정이 생성될 때 발생합니다.

    1. 두 가지 방법으로 로그인하여 두 계정을 확인합니다.
    2. 어떤 계정을 유지할지 결정합니다.
    3. 닫으려는 계정의 프로젝트를 복사합니다—**zip으로 다운로드**를 사용하거나 포크하세요.
    4. **설정 → 프로필**에서 필요 없는 계정을 삭제합니다.

    어떤 계정에 구독이나 프로젝트가 있는지 확실하지 않다면 [Replit 지원팀에 문의](https://replit.com/support)하세요.
  </Accordion>

  <Accordion title="로그인 시 예상과 다른 계정으로 리디렉션됩니다">
    동일한 로그인 제공업체에 연결된 여러 계정이 있을 가능성이 높습니다. 원하는 계정에 접근하려면 다른 방법—이메일 및 비밀번호 또는 다른 제공업체—으로 로그인해 보세요. 어떤 방법이 어떤 계정에 연결되는지 확인하는 데 도움이 필요하면 사용자 이름과 함께 [Replit 지원팀에 문의](https://replit.com/support)하세요.
  </Accordion>

  <Accordion title="workspace.*.repl.co에 대한 SSH 연결이 더 이상 작동하지 않습니다">
    `workspace.*.repl.co` SSH 호스트명이 사용 중단되었습니다. 프로젝트에서 [SSH](/ko/features/workspace-tools/ssh) 창을 열고 현재 연결 명령을 복사하세요—`*.replit.dev` 주소를 사용합니다. 이전 `repl.co` 주소를 참조하는 스크립트나 SSH 설정을 업데이트하세요.
  </Accordion>

  <Accordion title="계정이 정지되었습니다—이유가 무엇이며 어떻게 이의를 제기하나요?">
    Replit은 서비스 약관 또는 커뮤니티 지침을 위반하는 계정을 정지하며, 결제 분쟁 또는 차지백이 자동 보류를 유발할 수 있습니다. 먼저 이유를 설명하는 메시지에 대해 이메일(스팸 포함)을 확인하세요.

    결제 관련인 경우 **설정 → 청구**에서 미결제 청구서를 해결하세요. 정지가 오류라고 생각하는 경우 사용자 이름, 등록된 이메일, 간단한 설명을 포함하여 [Replit 지원팀에 문의](https://replit.com/support)하세요. [제재 시스템 FAQ](/ko/legal-and-security-info/strike-system-faq) 및 [신뢰와 안전](/ko/legal-and-security-info/trust-and-safety)을 참조하세요.
  </Accordion>

  <Accordion title="회사 네트워크에서 가입할 수 없거나 워크스페이스가 로드되지 않습니다">
    기업 또는 학교 네트워크는 계정에 문제가 없어도 Replit을 차단할 수 있습니다. 흔한 증상은 계속 회전만 하는 가입 버튼, 빈 워크스페이스, 반복적인 연결 끊김, 또는 Cloudflare의 "Attention Required!" 403 페이지입니다. 이는 SSL/TLS 검사 장비, 헤더를 재작성하는 프록시, 평판이 낮은 공유 아웃바운드 IP 같은 기업 보안 도구가 Replit이 의존하는 연결을 방해할 때 발생합니다.

    먼저 네트워크가 원인인지 확인하세요:

    1. 개인 휴대폰 핫스팟과 같은 다른 네트워크에서 동일한 브라우저로 다시 시도합니다.
    2. 시크릿 모드나 비공개 창, 그리고 관리형 확장 프로그램이나 정책이 없는 브라우저로 시도합니다.

    회사 네트워크가 아닌 곳에서는 Replit이 작동하지만 회사 네트워크에서는 작동하지 않는다면, IT 팀에 Replit을 허용 목록에 추가해 달라고 요청하세요. Replit의 IP 주소는 변경되므로 IP 주소보다 도메인으로 허용 목록을 지정하는 것이 더 안정적입니다. 다음 도메인을 허용하도록 요청하세요:

    * `replit.com` 및 `*.replit.com`—메인 사이트 및 정적 자산
    * `*.replit.dev`—개발 URL
    * `*.replit.app`—게시된 앱
    * `*.repl.co`—레거시 개발 URL
    * `replit-com-static.b-cdn.net`—폰트
    * `replitcdn.b-cdn.net`—미디어

    Replit은 이러한 도메인에서 지속적인 WebSocket 연결, 빈번한 API 호출, 인증 토큰 교환을 사용하므로 IT 팀에 다음 사항도 확인하도록 요청하세요:

    * **SSL/TLS 검사**—위 도메인에 대해 인증서 검사 우회를 추가하세요. 검사 프록시는 Replit의 인증서에서 조용히 실패하여 눈에 보이는 오류 없이 페이지가 멈춘 상태로 남을 수 있습니다.
    * **헤더 재작성**—HTTP 헤더를 수정, 제거 또는 삽입하는 프록시 규칙은 도메인 간 API 및 인증 호출을 손상시킵니다.
    * **WebSocket 트래픽**—위 도메인에 대한 `wss://` 연결을 허용하세요.
    * **브라우저 정책**—허용 목록에 없는 도메인에 대해 쿠키 유지나 타사 쿠키를 차단하는 그룹 정책 또는 MDM 규칙은 로그인을 방해할 수 있습니다.
    * **DNS 리졸버**—`replit.com` 및 `*.replit.dev` 호스트명이 해석되는지 확인하고 `8.8.8.8` 또는 `1.1.1.1` 같은 공용 리졸버와 비교하세요. 분할 도메인(split-horizon) 또는 필터링 리졸버는 개발 URL에 대해 레코드를 반환하지 않는 경우가 있습니다.

    IT 팀이 이러한 변경 사항을 적용한 후에도 회사 네트워크에서 Replit이 계속 실패한다면, 사용자 이름과 표시되는 정확한 오류 또는 Cloudflare Ray ID를 포함하여 [Replit 지원팀에 문의](https://replit.com/support)하세요.
  </Accordion>

  <Accordion title="커넥터(Stripe, GitHub, Resend)가 작동을 멈췄습니다—어떻게 다시 연결하나요?">
    커넥터는 만료되거나 취소될 수 있는 OAuth 토큰을 사용합니다. 다시 연결하려면 **도구 → 커넥터**를 열고 손상된 커넥터를 연결 해제한 다음 다시 연결하고 다시 인증하세요. 토큰이 프로젝트 [시크릿](/ko/core-concepts/project-editor/app-setup/secrets)에 자동으로 업데이트됩니다.

    다시 연결하지만 여전히 실패한다면 타사 서비스의 계정이 활성 상태이고 올바른 권한이 있는지 확인하세요. [커넥터 관리](/ko/replitai/managing-connectors) 및 [통합 개요](/ko/features/integrations/overview)를 참조하세요.
  </Accordion>

  <Accordion title="Replit 계정을 다른 사람에게 이전할 수 있나요?">
    계정은 직접 이전할 수 없습니다—계정은 생성 시 사용된 자격 증명에 연결됩니다. 대신 특정 프로젝트를 넘기려면 새 소유자가 계정을 만들게 하세요. 프로젝트를 공유하고 그들의 계정으로 포크하도록 요청하세요. 현재 계정의 이메일을 변경하려면 **설정 → 프로필**로 이동하여 이메일을 편집하세요. 구독은 이전할 수 없습니다—새 소유자는 자체 구독이 필요합니다. 비즈니스 계정 이전의 경우 [Replit 지원팀에 문의](https://replit.com/support)하세요.
  </Accordion>
</AccordionGroup>
