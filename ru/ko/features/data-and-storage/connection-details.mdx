Приложения подключаются к базам данных с помощью учетных данных, которыми управляет Replit. Чтобы просмотреть эти сведения, выберите базу данных в инструменте **Database** и откройте вкладку **Settings**. На этой вкладке отображаются строка подключения, использование хранилища и расширенные сведения о подключении.

<div id="section">
  ## Переменные окружения
</div>

Для подключения к базе данных разработки доступны следующие переменные окружения.

* `DATABASE_URL`: строка подключения и аутентификации для базы данных

App автоматически использует её. `DATABASE_URL` привязана к App, поэтому база данных разработки недоступна для других ваших App, в том числе через внешние средства просмотра баз данных. Даже если она будет раскрыта, другие пользователи не смогут использовать её для доступа к базе данных или внесения изменений.

<Info>
  Если ваша база данных разработки всё ещё использует [устаревшую инфраструктуру Neon](/ru/ko/features/data-and-storage/development-and-production#legacy-development-database), также доступны дополнительные переменные `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `PGPORT`. Для баз данных, размещённых в текущей инфраструктуре Replit, эти переменные **не** предоставляются — вместо них необходимо использовать `DATABASE_URL`.
</Info>

<Warning>
  Если вы всё ещё используете устаревшую базу данных разработки Neon, не делитесь `DATABASE_URL`. Она содержит учётные данные базы данных, поэтому любой сможет использовать её для доступа к базе данных и внесения изменений. Никогда не вставляйте её в общедоступные места или тикеты поддержки.
</Warning>

<div id="section-2">
  ## Подключение внешних инструментов
</div>

Используйте строку подключения с вкладки **Settings** продакшн-базы данных, чтобы подключиться к **продакшн-базе данных** из любого SQL-клиента, совместимого с PostgreSQL.

<div id="section-3">
  ## Безопасность
</div>

При добавлении интеграции с базой данных с помощью Agent также добавляется ORM (Object-Relational Mapper) со встроенными средствами защиты, которая обрабатывает все взаимодействия с базой данных.

* **Проверка схемы**: проверяет соответствие данных ожидаемому формату
* **Очистка данных (Sanitization)**: автоматически очищает ввод разработчика, чтобы предотвратить SQL-инъекции

<div id="section-4">
  ## Повторная генерация учётных данных продакшн-базы данных
</div>

Если строка подключения к продакшн-базе данных была скомпрометирована, повторно сгенерируйте учётные данные в инструменте **Database**. При этом для продакшн-базы данных Neon будет создан новый пароль. Существующая строка подключения к продакшн-базе данных немедленно перестанет работать.

Вы можете повторно сгенерировать учётные данные, если выполнены все следующие условия:

* У App есть продакшн-база данных Neon.
* Вы являетесь владельцем App или администратором рабочего пространства владельца.
* Вы используете Replit в веб-браузере.
* Нет выполняющихся деплоев.
* Если у App есть опубликованный деплой, последняя сборка успешно завершена и используется [Autoscale или Reserved VM](/ru/ko/features/publishing/deployment-types).

<Warning>
  Это действие нельзя отменить. Существующая строка подключения немедленно перестанет работать. Если у App есть опубликованный деплой,
  он может быть временно недоступен во время повторного деплоя.
</Warning>

<div id="section-5">
  ### Повторная генерация учётных данных
</div>

1. На панели Tools выберите **Database**.

2. Выберите **Production Database**, затем вкладку **Settings**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="Вкладка Settings продакшен-базы данных: раздел Дополнительно со строкой подключения, сведениями об использовании хранилища и строкой Regenerate credentials" width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. В разделе **Дополнительно** разверните строку **Regenerate credentials**.

4. Нажмите кнопку **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Развернутая строка Regenerate credentials и кнопка Regenerate credentials в разделе Дополнительно" width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. В диалоговом окне подтверждения нажмите **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="Диалоговое окно подтверждения Regenerate credentials с предупреждением о том, что это действие нельзя отменить и существующая строка подключения немедленно перестанет работать" width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Нажмите **Refresh**, чтобы загрузить новую строку подключения.

7. Если у App есть опубликованный деплой, откройте **Publishing** и проверьте статус повторного деплоя.

8. Замените все строки подключения, скопированные во внешние инструменты или пользовательские интеграции.

<div id="section-6">
  ### Что изменится
</div>

При повторной генерации учетных данных для продакшн-базы данных будет создан новый пароль. В строке подключения изменится только пароль — хост, имя базы данных и роль останутся прежними.

Для поддерживаемых опубликованных деплоев Replit повторно развернёт последнюю успешную сборку с обновлённой строкой подключения.
