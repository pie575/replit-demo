选择 **Publish** 会启动一个简短的流程，将你的应用发布上线。本页介绍部署过程中会发生什么、如何更新应用，以及应用上线后在哪里管理它。

<div id="os-estgios-de-publicao">
  ## 部署阶段
</div>

部署会经历五个阶段，通常需要一到两分钟。你可以在 Publishing 工具中查看进度条，选择 **View logs** 查看详细信息，或选择 **Cancel** 取消正在进行的部署。

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Publishing 概览，显示五阶段进度条：Provision 已完成，Security checks 和 Build 正在进行，Bundle 和 Promote 等待中" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision**：Replit 会配置运行应用所需的云资源，例如服务器和生产数据库。
2. **Security checks**：Replit 会在应用上线前检查安全问题，例如不安全的依赖项或暴露的 Secrets。
3. **Build**：Replit 会将项目构建为应用的生产版本，即在 Web 上运行的优化版本。
4. **Bundle**：构建完成的应用会被打包成一个可运行的单一单元。
5. **Promote**：Replit 会先在当前版本旁准备新版本，然后将你的 URL 指向新版本。

<Note>
  部署涵盖整个项目：其中的每项内容，例如应用、幻灯片和文档，都会一并部署。
</Note>

<Accordion title="幕后发生了什么">
  如果你想了解技术细节：Provision 会为所选的部署类型和区域分配部署基础设施。Security checks 会执行依赖项和代码检查，并可能会根据你的安全设置，在发现严重漏洞时阻止部署。Build 会运行你的构建命令，并编译用于生产环境的资源。Bundle 会将构建结果打包为可部署的映像。Promote 会执行切换：新版本将开始通过你的 URL 提供服务，替代之前的部署。
</Accordion>

当所有阶段完成后，你的应用便已上线。选择 Publishing 工具中的 URL 将其打开。

<div id="atualize-seu-app">
  ## 更新你的应用
</div>

修改完成后，再次选择 **Publish**。你的应用会在同一个 URL 上完成更新，访问者下次加载时即可看到最新版本。你无需重新分享新链接。

<div id="gerencie-seu-app-ativo">
  ## 管理已上线的应用
</div>

应用上线后，同样在 Publishing 工具中进行管理：

* **监控运行状况**：跟踪应用是否在线、查看日志并检查资源使用情况。详细了解[监控](/zh/pt/features/publishing/monitoring-a-deployment)。
* **查看访问情况**：请求和流量图表位于 [Monitoring](/zh/pt/features/publishing/monitoring-a-deployment)；访问者和用户相关信息位于 **Growth** 面板。
* **更改访问权限**：先取消发布，选择其他访问方式，然后重新发布。详细了解[应用访问](/zh/pt/features/publishing/private-deployments)。
* **绑定域名**：为你的应用设置专属网址。详细了解[自定义域名](/zh/pt/features/publishing/custom-domains)。
