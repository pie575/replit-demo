Здесь собраны ответы на часто задаваемые вопросы о продакшен-базах данных. Подробные сведения см. в разделах [Продакшен-базы данных](/ru/ja/features/data-and-storage/development-and-production) и [SQL-базы данных](/ru/ja/features/data-and-storage/sql-database).

<AccordionGroup>
  <Accordion title="Эндпоинт базы данных отключён — как исправить ошибку «endpoint has been disabled»?">
    Эта ошибка означает, что вычислительный эндпоинт базы данных приостановлен. Чтобы возобновить его работу:

    1. Откройте панель **Database** и выберите **Development** в раскрывающемся списке.
    2. Если появится кнопка **Unpause database**, нажмите её.
    3. Переключитесь в раскрывающемся списке на **Production** и снова нажмите **Unpause database**, если она появится.

    Если кнопка не отображается, возможно, её скрывает конфликтующий секрет `DATABASE_URL`. Откройте панель **Secrets**, сравните запись `DATABASE_URL` со строкой подключения на панели **Database**, затем обновите или удалите конфликтующий секрет, чтобы значения совпадали.

    Распространённые причины — неоплаченные счета (оплатите их, чтобы избежать повторения) и временная приостановка при публикации (её можно устранить, выполнив описанные выше действия). См. [продакшен-базу данных](/ru/ja/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="На странице статуса указано о сбое продакшен-базы данных — нужно ли создавать тикет?">
    Нет. Если информация о сбое уже опубликована на [status.replit.com](https://status.replit.com), команда уже занимается его устранением, и обращение в поддержку не ускорит исправление. Откройте активный инцидент и подпишитесь на обновления, чтобы получать уведомления о ходе работ.

    Если проблема с базой данных *не указана* на странице статуса, [обратитесь в поддержку Replit](https://replit.com/support).
  </Accordion>

  <Accordion title="Как восстановить удалённую или удалённую командой DROP таблицу базы данных?">
    Replit поддерживает восстановление продакшен-баз данных на определённый момент времени. Окно восстановления зависит от тарифа: 7 дней для [Core](/ru/ja/billing/plans/replit-core) и 28 дней для [Pro](/ru/ja/billing/plans/replit-pro).

    Чтобы восстановить данные, откройте панель **Database**, перейдите к базе данных, откройте настройки восстановления, выберите нужную временную метку и подтвердите действие. Если нужная точка находится за пределами окна восстановления, [обратитесь в поддержку Replit](https://replit.com/support). См. [Продакшен-базы данных](/ru/ja/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="База данных приостановлена, но кнопка Unpause не отображается">
    Конфликтующие URL-адреса баз данных часто скрывают кнопку **Unpause**. Откройте панель **Secrets**, найдите запись `DATABASE_URL` и сравните её со строкой подключения на панели **Database**. Если они отличаются, секрет переопределяет правильный URL-адрес. Удалите его, обновите страницу и снова проверьте панель **Database**.

    Если после удаления конфликтующего секрета кнопка не появилась, [обратитесь в службу поддержки Replit](https://replit.com/support), указав URL проекта.
  </Accordion>

  <Accordion title="В App возникает ошибка «connection pool exhausted» — что это означает?">
    Количество одновременно открытых App подключений к базе данных превышает допустимый лимит пула. Распространённые причины:

    * Подключения не закрываются после каждого запроса
    * Резкий всплеск трафика
    * Медленные запросы, удерживающие подключения

    Большинство фреймворков предполагают использование одного общего пула подключений, а не создание нового подключения для каждого запроса.

    Чтобы быстрее всего решить проблему, откройте новый чат Agent, опишите ошибку и попросите Agent проверить, как App управляет подключениями к базе данных.
  </Accordion>

  <Accordion title="Как перенести данные из базы разработки в продакшен-базу данных?">
    Replit разделяет базу данных для разработки и продакшен-базу данных, поэтому изменения при тестировании не затрагивают рабочие данные. Чтобы выполнять миграции в продакшен-среде, добавьте команду миграции в этап билда или предварительного деплоя, чтобы она запускалась при каждом деплое. Например, для Drizzle используйте `drizzle-kit migrate`. Также можно вручную выполнить миграции из Shell в продакшен-среде.

    См. [Создание продакшен-базы данных при публикации](/ru/ja/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="Биллинг актуален, но для базы данных отображается «endpoint disabled»">
    Это может происходить по причинам, не связанным с биллингом. Попробуйте вручную возобновить работу базы данных. Откройте панель **Database**, выберите **Development** и, если отображается кнопка **Unpause database**, нажмите её. Затем повторите то же для **Production**.

    Если кнопка не отображается или проблема возникает повторно, [обратитесь в службу поддержки Replit](https://replit.com/support), указав URL проекта, — возможно, базу данных потребуется возобновить вручную. См. [продакшен-базу данных](/ru/ja/features/data-and-storage/development-and-production).
  </Accordion>
</AccordionGroup>
