完成此任务后，Velocity 客户可支付可退款的押金预订车辆，并在取车时支付尾款。

您已为 Velocity 添加了登录功能和数据库。现在，把它变成真正的车辆预约业务。通过**在预订时收取可退款的押金**预留每辆车，并在**取车时收取尾款**。Replit 通过 Stripe 处理付款，无需您亲自编写 Stripe 代码。

<div id="section">
  ## 确定押金与尾款金额
</div>

在让 Agent 开始构建之前，先把金额定下来。

* **预订时的押金：** 收固定金额还是按总额的百分比？固定 $500 更便于向客户说明，而 20% 会因车辆而异。
* **取车时的尾款：** 客户拿到钥匙时收取的剩余租赁费用。
* **可退款期限：** 提前多久取消才能退还押金？48 小时是常见的默认设置。

在本指南中，Velocity 在预订时收取固定 $500 的可退款押金，取车时收取尾款，提前 48 小时以上取消则全额退款。请根据你的实际业务进行调整。

<div id="section-2">
  ## 在测试模式下测试完整流程
</div>

Stripe 提供专用测试卡，让您无需使用真实资金即可模拟真实支付：`4242 4242 4242 4242`、未来的有效期以及任意 3 位 CVC。

1. 在 Preview 中登录 Velocity，预订下一个周六至周日的车辆。
2. 结账时应显示“今日押金：$500”和“取车时支付尾款：$1,900” (或计算出的金额) 。
3. 使用 `4242` 测试卡支付押金。您应返回确认页面，页面会显示押金支付已完成，且已保存用于支付尾款的支付方式。
4. 在“My bookings”中打开预订，通过管理员操作或取车操作收取尾款。确认尾款显示为已支付。
5. 创建第二笔预订，并在 48 小时之前取消。押金应退款至测试卡 (可在 Stripe 测试模式控制面板中确认) 。
6. 创建第三笔预订，并在 48 小时内取消。押金应被保留，并向客户明确说明。
7. 使用 Stripe 的拒付测试卡 (`4000 0000 0000 0002`) 尝试结账。预订不应被确认，并应向客户显示清晰的失败提示。

如果押金支付成功但预订未确认，请告知 Agent。

<div id="section-3">
  ## 切换到真实收款时
</div>

测试模式是给你自己用的，而实时模式面向的是真正付钱的真实客户。当 Velocity 准备就绪后：

1. 在 Stripe 中从测试模式切换到实时模式，并复制**实时**密钥。
2. 在应用设置中，将测试密钥替换为实时密钥。
3. 在 Agent 聊天中重新部署 Velocity。
4. 打开公开 URL，用你自己的真实银行卡预订一辆价格较低的测试车辆，确认押金和尾款流程都能正常运行。

在大范围分享公开 URL 之前，先用真实银行卡完整跑一遍测试。至此，Velocity 就可以接收真金白银的真实预订了。

<div id="section-5">
  ## 需要更多帮助？
</div>

* **押金支付成功但预订未确认：** 让 Agent 把 Stripe 的支付成功事件与数据库中的预订状态关联起来。
* **测试模式正常，实时模式不行：** 检查是否已在应用设置中把测试密钥替换为实时密钥。
* **想一次性付清全款，而不是押金 + 尾款：** 让 Agent 把 Velocity 改为预订时一次性全额付款。
* **想改用按月订阅的方案 (按月使用车辆列表) ：** Replit 也支持 RevenueCat——让 Agent 用它来替代 Stripe 即可。
