Создавайте приложения с помощью ИИ в Replit и публикуйте их прямо в Microsoft Fabric — со встроенными средствами управления и безопасности корпоративного уровня. Интеграция с Microsoft Fabric превращает управляемые корпоративные данные во внутренние инструменты: дашборды, рабочие процессы и приложения с ИИ. Команды быстрее проходят путь от prompt до продакшена, а политики аутентификации и доступа остаются в привычной и доверенной среде Fabric.

<div id="o-que-um-aplicativo-de-dados-fabric">
  ## Что такое приложение данных Fabric
</div>

Приложение данных Fabric — это статическое React-приложение, которое отображает графики Power BI, выполняя запросы [Data Analysis Expressions (DAX)](https://learn.microsoft.com/pt-br/dax/) к [семантической модели Power BI](https://learn.microsoft.com/pt-br/power-bi/connect-data/service-datasets-understand). Есть несколько особенностей, которые влияют на то, как вы его создаёте:

* **Источник данных — семантические модели Power BI.** Графики строятся на основе DAX-запросов к семантическим моделям (наборам данных), которые вы подключаете.
* **Только для чтения по своей природе.** Приложение читает данные с помощью DAX `EVALUATE` и не записывает их обратно в Power BI. Если вам нужно изменяемое состояние, используйте вместе с дашбордом отдельную базу данных приложения.
* **Отображение через портал Fabric.** Уровень данных работает внутри портала Microsoft Fabric: он выполняет ваши запросы к семантической модели и возвращает результаты приложению. Ваши данные остаются в вашей среде Fabric.
* **Размещение в инфраструктуре Microsoft.** Готовое приложение данных можно опубликовать на хостинге Microsoft, чтобы оно работало вместе с остальными компонентами вашей среды Fabric.

<Note>
  Для приложений данных Microsoft Fabric необходим доступ к тенанту Microsoft Fabric с семантическими моделями Power BI, а на этапе предварительной версии — участие в программе одобренных тестировщиков.
</Note>

Под капотом [Rayfin](https://github.com/microsoft/rayfin) (SDK и CLI с открытым исходным кодом для создания бэкендов приложений) позволяет Agent описывать и публиковать готовые к продакшену приложения поверх ваших данных Fabric.

Вы работаете в едином процессе: опишите приложение, дайте Agent создать его структуру, подключитесь к управляемым данным Fabric и опубликуйте приложение для работы в тенанте Fabric вашей организации.

Это руководство охватывает рабочий процесс разработчика, способ подключения приложения к данным Fabric и возможности для команд и автоматизации. Об общих дашбордах данных на основе других хранилищ читайте в разделе [Визуализация данных](/ru/pt/features/artifact-types/data-apps).

<div id="casos-de-uso">
  ## Сценарии использования
</div>

Организациям, уже вложившимся в экосистему данных Microsoft, это даёт гораздо более быстрый путь к созданию внутреннего ПО. Вместо того чтобы неделями связывать воедино аутентификацию, API, инструменты развёртывания и политики управления, команды просто описывают, что им нужно, а сборку берёт на себя Agent.

Типичные сценарии использования:

* Инструменты повышения продуктивности для отдельных отделов
* Операционные дашборды
* Инструменты исследования данных
* Приложения для автоматизации рабочих процессов
* Интерфейсы отчётности

Для корпоративного ИТ-отдела управление, аутентификация и безопасность остаются внутри среды Fabric, которой организация уже управляет, поэтому быстрая разработка приложений не идёт в ущерб централизованному контролю.

<div id="criar-um-aplicativo-de-dados-fabric">
  ## Создание приложения данных Fabric
</div>

Рабочий процесс разработчика построен на диалоге. Вы всё время остаётесь в Replit; аутентификация и доступ к данным выполняются через Microsoft по мере необходимости.

<Steps>
  <Step title="Начните с template Fabric">
    На главной странице Replit откройте выпадающее меню **Templates** и выберите **Microsoft Fabric App** в разделе **Org templates**. Так Agent переключится на рабочий процесс приложения данных с предзагруженными инструментами Fabric.

    <Frame caption="Выбор template организации Microsoft Fabric App на главной странице Replit (интерфейс закрытой предварительной версии).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Главная страница Replit с открытым выпадающим меню Templates, где выделен Microsoft Fabric App в разделе Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Опишите нужный вам дашборд">
    Введите prompt с описанием дашборда или инструмента отчётности, который нужно создать. Например: «Создай дашборд роста продаж по месяцам на основе нашей модели продаж Fabric». Писать DAX не требуется — Agent сам сгенерирует запросы.
  </Step>

  <Step title="Войдите через Microsoft">
    Когда появится запрос, войдите с помощью Microsoft OAuth в тенант, где хранятся ваши данные Fabric. Это разрешит Agent читать семантические модели, к которым у вас есть доступ. Учётная запись, под которой вы входите, должна иметь доступ к workspace Fabric, который вы хотите использовать.
  </Step>

  <Step title="Добавьте источники данных">
    Когда Agent попросит, укажите семантическую модель Power BI / Fabric, которую хотите использовать. Можно передать полный URL набора данных в портале Fabric (например, `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) либо ID workspace вместе с ID набора данных/элемента. По этим данным Agent определит workspace и семантическую модель для запросов.

    Модель должна быть **опубликована в службе Power BI** — локальные файлы `.pbix` использовать нельзя.

    <Frame caption="Agent запрашивает ссылку на семантическую модель Power BI / Fabric (интерфейс закрытой предварительной версии).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Панель Agent с просьбой к разработчику указать семантическую модель Power BI или Fabric в виде полного URL портала Fabric либо ID workspace вместе с ID набора данных или элемента, с примечанием, что локальные файлы .pbix использовать нельзя, поскольку модель должна быть опубликована в службе Power BI" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Дайте Agent построить и доработать дашборд">
    Agent изучает схему семантической модели, пишет запросы DAX и собирает дашборд с подходящими графиками. Просмотрите результат и запрашивайте изменения на естественном языке — добавьте фильтр, смените тип графика или добавьте ещё одну метрику.
  </Step>

  <Step title="Публикация (необязательно)">
    Когда дашборд готов, его можно опубликовать на хостинге Microsoft, чтобы он работал внутри вашей среды Fabric. Публикация рассматривается отдельно; это руководство посвящено подключению к данным и созданию приложения.
  </Step>
</Steps>

<div id="conectando-se-aos-dados-fabric">
  ## Подключение к данным Fabric
</div>

Чтобы читать данные, приложению требуется авторизованное подключение к Microsoft Fabric. Replit устанавливает такое подключение одним из двух способов.

<div id="login-no-fabric-no-nvel-do-aplicativo-visualizadores">
  ### Вход в Fabric на уровне приложения (для просматривающих)
</div>

Пользователи, которые просто просматривают опубликованное приложение данных, никогда не настраивают коннектор. Они проходят аутентификацию через встроенный в приложение SSO Microsoft Fabric, а приложение читает данные от их имени через портал Fabric. Благодаря этому доступ по-прежнему регулируется действующими разрешениями Fabric.

<div id="o-conector-microsoft-fabric-o-caminho-fcil-para-construtores">
  ### Коннектор Microsoft Fabric (простой путь для разработчиков)
</div>

Для разработчиков **коннектор Microsoft Fabric** — это удобный способ авторизовать доступ к данным во время разработки. Он необязателен: это простой путь, а не требование.

* Первый разработчик, который его настраивает, выполняет **однократную авторизацию OAuth** в Microsoft.
* Остальные участники **того же проекта наследуют** это подключение.
* В **другом workspace** нужно отдельно включить коннектор и выполнить собственную авторизацию OAuth.
* Учётная запись, прошедшая проверку через OAuth, должна иметь доступ к целевому workspace Fabric.

Коннектор использует Microsoft Entra OAuth и ограничен вашим тенантом. Управлять им можно на странице [Интеграции](/ru/pt/features/integrations/overview) вашего проекта — так же, как любым другим коннектором Replit. Общие сведения о коннекторах см. в разделе [Управление коннекторами](/ru/pt/replitai/managing-connectors).

<Note>
  В период закрытого предварительного доступа для коннектора Microsoft Fabric не предоставляются общие учётные данные, управляемые Replit. Разработчики авторизуются в собственном тенанте Microsoft Entra.
</Note>

<div id="equipes-e-automao">
  ## Команды и автоматизация
</div>

При совместной работе в команде или в неинтерактивных средах (например, CI) интерактивный OAuth не всегда удобен. В таких случаях вместо интерактивного входа передавайте токен **сервисного принципала** через [Secrets](/ru/pt/core-concepts/project-editor/app-setup/secrets) вашего проекта. Приложение читает данные Fabric от имени сервисного принципала.

Это наиболее близкий аналог схемы «машина — машина»: нечеловеческая учётная запись, созданная в Microsoft Entra и получившая доступ к workspace Fabric, аутентифицирует приложение без участия человека. Убедитесь, что у сервисного принципала есть доступ к тем workspace и семантическим моделям, к которым обращается приложение.

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

<AccordionGroup>
  <Accordion title="Данные не загружаются в предпросмотре приложения">
    Слой данных Fabric работает через портал Microsoft Fabric. Если графики отображаются пустыми или предпросмотр приложения не загружает данные, убедитесь, что вы выполнили вход в учётную запись Microsoft и что у подключённой учётной записи есть доступ к связанным workspace и семантической модели.
  </Accordion>

  <Accordion title="Agent не может найти вашу семантическую модель">
    Убедитесь, что вы вставили ссылку на набор данных Power BI в портале Fabric и что у вашей учётной записи (или сервисного принципала) есть как минимум доступ на чтение к этому workspace. Отправьте ссылку на набор данных повторно, если Agent сообщает, что не может определить workspace или модель.
  </Accordion>

  <Accordion title="Коннектор завис или постоянно запрашивает подключение">
    Повторно авторизуйте коннектор Microsoft Fabric на странице [Интеграции](/ru/pt/features/integrations/overview) проекта. Убедитесь, что у учётной записи, прошедшей проверку через OAuth, есть доступ к workspace Fabric. Для командной работы или CI лучше использовать токен сервисного принципала, предоставленный через Secrets.
  </Accordion>
</AccordionGroup>
