---
title: "Static Deployments"
description: "Découvrez comment publier des sites statiques et des applications frontend avec Static Deployments."
---

Les Static Deployments hébergent les fichiers statiques de votre Replit App, tels que les fichiers HTML, CSS et JavaScript,
sur un serveur cloud. Celui-ci utilise automatiquement des stratégies de mise en cache et de mise à l’échelle pour
servir votre contenu rapidement et à moindre coût.

Les Static Deployments sont idéaux pour les cas d’utilisation suivants :

* Pages de destination marketing
* Sites de portfolio
* Sites de documentation de produits et d’API

<Note>
  Les Static Deployments ne sont pas compatibles avec les Replit Apps créées avec Agent.
  Agent crée automatiquement des applications full-stack qui nécessitent un serveur backend. Pour les
  applications générées par Agent, utilisez l’un des types de déploiement suivants : - [Autoscale
  Deployment](/fr/pt/cloud-services/deployments/autoscale-deployments) - [Reserved VM
  Deployment](/fr/pt/cloud-services/deployments/reserved-vm-deployments)
</Note>

<div id="recursos">
  ## Fonctionnalités
</div>

Les Static Deployments incluent les fonctionnalités suivantes :

* **Hébergement économique** : payez uniquement en fonction de la quantité de données servies par votre site.
* **Options de routage HTTP** : configurez les en-têtes de réponse, les réécritures d’URL et les redirections.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez une URL `<nome-do-app>.replit.app` pour accéder à votre app.
* **Pages d’erreur personnalisées** : créez et servez une page d’erreur 404 personnalisée.
* **Surveillance** : consultez les logs et surveillez l’état de votre app publiée.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder aux Static Deployments depuis l’outil Publishing du Project Editor.

<Accordion title="Accéder aux Static Deployments">
  Dans le **dock d’outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône Tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l’option **Static**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut pour ouvrir l’outil de recherche.
  2. Saisissez « Publishing » pour trouver l’outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l’option **Static**, puis **Set up your published app**.
</Accordion>

<div id="domnio-principal">
  ### Domaine principal
</div>

Indiquez le sous-domaine de l’hôte de votre application publiée. Une fois l’application publiée, vous pourrez y accéder à l’adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Custom Domains](/fr/features/publishing/custom-domains).

<div id="deployment-privado">
  ### Déploiement privé
</div>

<Info>
  La fonctionnalité d&#39;application publiée privée est disponible avec les forfaits Pro et Enterprise.
</Info>

Les applications publiées privées ne sont accessibles qu&#39;aux membres de votre workspace, ainsi qu&#39;aux utilisateurs et groupes spécifiques que vous invitez.
Lors de la publication, vous pouvez choisir entre les options d&#39;accès **Public**, **Protégé par mot de passe**, **Workspace uniquement** ou **Sur invitation uniquement**.

Pour savoir comment configurer un déploiement privé, consultez [Accès à l&#39;application](/fr/features/publishing/private-deployments/).

<div id="diretrio-pblico">
  ### Répertoire public
</div>

Indiquez le chemin du répertoire de votre Replit App contenant les fichiers statiques que vous souhaitez rendre accessibles publiquement.
Après le déploiement, l’hôte cloud sert toutes les pages et ressources de ce répertoire.

La valeur par défaut, `/`, correspond au répertoire racine de votre Replit App.

<div id="build-command">
  ### Commande de build
</div>

Indiquez une commande de build à exécuter dans le Shell de votre Replit App lors de la création de votre déploiement.

Par exemple, si vous générez un site statique à l’aide de <a href="https://gohugo.io/" target="_blank">Hugo</a>,
vous pouvez utiliser la commande `hugo --minify` pour générer les fichiers et optimiser la taille des ressources.

<div id="secrets-do-deployment">
  ### Secrets de déploiement
</div>

Sélectionnez **Add deployment secret** pour ajouter des variables d’environnement ou des secrets nécessaires à l’exécution sécurisée de votre build command.

Par exemple, si le générateur de votre site a besoin d’une clé API pour créer le site statique, vous pouvez la fournir sous la forme
`API_KEY=<nom de votre secret>`.
