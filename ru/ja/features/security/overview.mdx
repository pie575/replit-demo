После публикации из Replit проект начинает принимать реальный трафик. Инструменты безопасности Replit помогают находить уязвимости, исправлять принятые в работу проблемы с помощью Agent и сохранять подтверждающие данные для аудита.

<div id="section">
  ## Почему безопасность важна
</div>

* Опубликованные проекты доступны из открытого интернета, включая публичные маршруты и API.
* Современные проекты зависят от множества пакетов, и уже после публикации могут появляться новые CVE.
* Код, сгенерированный ИИ, тоже нуждается в проверке безопасности — особенно там, где речь идёт об аутентификации, запросах к базе данных, секретах и обработке данных.
* Программы соответствия требованиям, как правило, предполагают инвентаризацию зависимостей, отслеживание уязвимостей и подтверждение выполненных исправлений.

<div id="section-2">
  ## С чего начать
</div>

* Устанавливаете пакеты? [Package Firewall](/ru/ja/features/security/package-firewall) блокирует вредоносные зависимости прямо при установке (включён по умолчанию).
* Если вы работаете с одним проектом, используйте [Центр безопасности проекта](/ru/ja/features/security/project-security-center).
* Если нужно проверить всё рабочее пространство, используйте [Центр безопасности рабочего пространства](/ru/ja/features/security/workspace-security-center).
* Если вы хотите выбрать, где выполняются ресурсы разработки, см. [geography для рабочего пространства](/ru/features/collaboration/workspace-geography). Если нужно выбрать, где работают опубликованные проекты, см. [geography для проекта](/ru/ja/features/publishing/project-geography).
* Если нужны определения терминов, см. [Концепции безопасности](/ru/ja/features/security/concepts).

Инструменты безопасности Replit защищают разные этапы жизненного цикла приложения и работают сообща:

* **При установке**: [Package Firewall](/ru/ja/features/security/package-firewall) блокирует вредоносные и скомпрометированные пакеты ещё до их загрузки.
* **После установки**: [автоматическое сканирование зависимостей](/ru/ja/features/security/project-security-center#automatic-dependency-scans) выявляет только что опубликованные CVE, а Auto-Protect может подготовить исправление силами Agent.
* **Перед публикацией**: [Security Agent](/ru/ja/features/security/agent-security-scans) проверяет кодовую базу на уязвимости в коде, зависимостях и в части конфиденциальности.

Большинство задач по безопасности укладывается в один и тот же цикл: сканирование, просмотр результатов, исправление с помощью Agent, повторная публикация и, при необходимости, экспорт подтверждающих данных.

<div id="section-3">
  ## Где найти настройки безопасности в продукте
</div>

<div id="section-4">
  ### Внутри проекта
</div>

На панели **Tools** проекта выберите **Security Center**, чтобы просмотреть результаты на уровне проекта, запустить сканирование безопасности Agent и проверить уязвимости зависимостей перед публикацией.

Для проверки исходного кода используйте [сканирование безопасности Agent](/ru/ja/features/security/agent-security-scans). Если необходимо проверить работающее приложение извне, воспользуйтесь [тестированием на проникновение методом чёрного ящика Level 3](/ru/ja/features/security/black-box-pen-tests).

<div id="section-5">
  ### В рабочем пространстве
</div>

Выберите **Security** на боковой панели главной страницы, чтобы просматривать уязвимости по всем проектам, расставлять приоритеты по степени уязвимости к внешнему доступу и отслеживать историю сканирований на уровне рабочего пространства.

<div id="section-6">
  ### Публикация и настройки
</div>

* В разделе **Publish** &gt; **Advanced** включите параметр **Block publishing of critical vulnerabilities**, чтобы блокировать выпуск при наличии критических уязвимостей.
* В разделе **Settings** &gt; **Account** &gt; **Advanced** задайте пороговый уровень серьёзности Auto-Protect для исправлений зависимостей, подготовленных Agent.
