URL для разработки позволяет просматривать и тестировать приложение прямо во время его создания. Такой URL имеет вид `UUID.servername.replit.dev` и открывает живой предпросмотр приложения в процессе разработки.

Чтобы увидеть URL для разработки, нажмите на текст `{...}.replit.dev` в адресной строке.

<div id="url">
  ## URL для разработки
</div>

URL для разработки активен только во время активной работы над Replit App. Он может меняться при каждом повторном открытии приложения. URL для разработки позволяет просматривать приложение в браузере во время разработки и тестирования.

По умолчанию URL для разработки доступен в интернете. Любой, у кого есть этот URL, может просмотреть разрабатываемое приложение. Это упрощает обмен текущей версией с соавторами, тестировщиками и заинтересованными лицами.

<Warning>
  URL для разработки является временным и предназначен только для тестирования. Чтобы поделиться приложением с другими, рекомендуется [опубликовать приложение](/ru/ko/learn/projects-and-artifacts/replit-deployments).
</Warning>

<div id="section">
  ### Информационный баннер
</div>

Если открыть предварительный просмотр разработки в новой вкладке, в верхней части страницы появится информационный баннер. Он помогает понять, для чего нужен URL `.replit.dev`, пока вы разрабатываете и тестируете приложение. Баннер поясняет, что представляет собой URL для разработки и как он используется в процессе работы над приложением.

<div id="url-2">
  ## Как сделать URL разработки приватным
</div>

Вы можете ограничить доступ к URL разработки, чтобы защитить работу, которая ещё не завершена.

Чтобы сделать URL разработки приватным:

1. В Project Editor откройте **Developer tools**.
2. Перейдите на вкладку **Networking**.
3. Включите переключатель **Private development URL**.

После этого для доступа к URL разработки потребуется аутентификация. Незавершённую работу увидите только вы и участники команды с соответствующими правами.

<Note>
  Клиенты Enterprise могут сделать приватные URL разработки обязательными для всех проектов — это повышает уровень безопасности и гарантирует, что разработка защищена внутри среды организации.
</Note>

<div id="section-2">
  ## Рекомендации
</div>

* Во время разработки **используйте приватный URL** для конфиденциальных или проприетарных приложений
* **Используйте публичный URL**, если в процессе активной работы над приложением нужно показать результат внешним заинтересованным лицам или протестировать приложение в другом браузере
