Le panneau Git de Replit offre une interface visuelle pour les opérations Git, sans avoir à utiliser de commandes Git en ligne de commande. Cette fonctionnalité rend le contrôle de version accessible aux débutants tout en restant puissante pour les développeurs expérimentés.

<div id="recursos">
  ## Fonctionnalités
</div>

Le panneau Git offre des fonctionnalités complètes de contrôle de version directement dans l’Éditeur de projets, grâce à une interface intuitive qui simplifie les opérations Git complexes.

* **Gestion des dépôts :** initialisez, connectez et gérez des dépôts Git grâce à l’intégration GitHub
* **Suivi des commits :** indexez (stage), validez et visualisez les modifications de tous vos fichiers
* **Opérations sur les branches :** créez, changez de branche et fusionnez des branches visuellement
* **Résolution des conflits :** identifiez et résolvez les conflits de fusion grâce à une assistance visuelle
* **Intégration avec le Shell :** synchronisation entre les commandes Git exécutées dans le Shell et le panneau Git

<div id="uso">
  ## Utilisation
</div>

<div id="configurao-do-repositrio">
  ### Configuration du dépôt
</div>

<Accordion title="Accéder au panneau Git">
  1. Accédez à la section Tools de votre Replit App
  2. Sélectionnez le signe **+** pour ajouter de nouveaux outils
  3. Sélectionnez **Git** dans la liste des outils disponibles
</Accordion>

Le panneau Git vous permet de configurer et de connecter votre dépôt :

* **Initialiser un dépôt** : créez un dépôt Git pour votre Replit App
* **Connect to a Git provider** : associez votre dépôt à un fournisseur Git compatible, hébergé ou auto-hébergé, pour la sauvegarde et la collaboration
* **Configure remote** : configurez et gérez la connexion à votre dépôt distant

<Note>
  **Prise en charge de Git auto-hébergé** : Replit prend en charge GitHub Enterprise Server, GitLab Self-Managed et Bitbucket Data Center avec le forfait Enterprise. [Contactez l’équipe commerciale de Replit](https://replit.com/enterprise) pour obtenir de l’aide concernant l’intégration, la configuration du fournisseur et le dépannage des connexions. Vous pouvez également [configurer un dépôt distant à l’aide de commandes Git dans le Shell](#usando-comandos-git-no-shell).
</Note>

<div id="gerenciamento-de-alteraes">
  ### Gestion des modifications
</div>

<Accordion title="Comment consulter les modifications">
  1. Modifiez n’importe quel fichier de votre Replit App
  2. Ouvrez le panneau Git dans la section Tools
  3. Consultez les modifications dans la section **Review Changes**
</Accordion>

Le panneau Git propose des outils pour gérer les modifications de votre code :

* **Review changes** : consultez les fichiers modifiés, avec les ajouts et suppressions mis en évidence
* **indexer des fichiers** : sélectionnez les fichiers à inclure dans votre prochain commit
* **Valider les modifications** : enregistrez vos modifications avec des messages descriptifs
* **Push updates** : envoyez vos commits vers votre dépôt distant en un clic

<Note>
  Vous pouvez utiliser Replit AI pour générer des messages de commit décrivant précisément vos modifications.

<div id="gerenciamento-de-branches">
  ### Gestion des branches
</div>

<Accordion title="Gérer les branches">
  1. Ouvrez le panneau Git dans la section Tools
  2. Sélectionnez le menu déroulant des branches à côté du nom de la branche
  3. Créez une branche ou sélectionnez-en une existante
</Accordion>

Le panneau Git simplifie la gestion de plusieurs versions de votre code :

* **Créer des branches** : créez des branches pour développer des fonctionnalités séparément
* **Changer de branche** : passez d’une version de votre code à une autre
* **Publier des branches** : partagez vos branches avec votre fournisseur Git
* **Récupérer les modifications** : synchronisez votre travail avec les mises à jour distantes de vos collaborateurs

<div id="resoluo-de-conflitos-de-merge">
  ### Résolution des conflits de fusion
</div>

<Accordion title="Comment résoudre les conflits de fusion">
  1. Essayez de récupérer les modifications lorsqu&#39;il y a des conflits
  2. Le panneau Git mettra en évidence les fichiers en conflit
  3. Ouvrez chaque fichier en conflit pour afficher et résoudre les conflits
  4. Enregistrez les fichiers après avoir résolu les conflits
  5. Terminez la fusion en sélectionnant **Pull**
</Accordion>

Lorsque des modifications provenant de différentes sources entrent en conflit, le panneau Git vous aide à :

* **Identifier les conflits** : voyez exactement quels fichiers contiennent des conflits
* **Visualiser les différences** : examinez les deux versions du code en conflit
* **Résoudre les problèmes** : choisissez le code à conserver ou modifiez manuellement les conflits
* **Finaliser les fusions** : terminez le processus de fusion après avoir résolu les conflits

<Frame>
  <img src="/assets/mirror/11-merge-conflict-17b314f0e231.png" alt="Éditeur de code affichant des marqueurs de conflit de fusion" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

Après avoir résolu un fichier en conflit, vous pouvez supprimer les marqueurs de conflit en supprimant les lignes commençant par les symboles de conflit et en enregistrant le fichier.

<div id="usando-comandos-git-no-shell">
  ### Utiliser les commandes Git dans le Shell
</div>

<Accordion title="Accéder au Shell">
  1. Sélectionnez **All tools** dans le dock d’outils à gauche
  2. Sélectionnez **Shell** parmi les outils disponibles
</Accordion>

<Tip>
  Bien que le panneau Git propose une interface intuitive, les utilisateurs avancés peuvent utiliser les commandes Git standard dans le Shell pour effectuer des opérations plus complexes. Les modifications effectuées par l’une ou l’autre méthode seront répercutées aux deux endroits.
</Tip>

Si vous préférez utiliser Git en ligne de commande :

* **Synchronisation des commandes** : toute commande Git exécutée dans le Shell est automatiquement synchronisée avec le panneau Git
* **Fonctionnalités Git complètes** : accédez aux fonctionnalités Git avancées non disponibles dans le panneau Git
* **Basculement fluide** : passez des commandes du Shell au panneau Git selon vos besoins

<Info>
  **Prise en charge des CLI GitHub et GitLab** : en plus des commandes Git standard, vous pouvez également utiliser la [CLI GitHub](https://docs.github.com/en/github-cli) (`gh`) et la [CLI GitLab](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) dans le Shell pour gérer des dépôts Git externes et vous y connecter. Ces outils offrent des fonctionnalités avancées pour travailler avec des dépôts GitHub et GitLab, notamment les pull requests, les issues et d’autres fonctionnalités propres à ces plateformes.
</Info>

<div id="operaes-de-repositrio">
  #### Opérations de dépôt
</div>

* **Cloner un dépôt** : `git clone <url-to-repository>`
* **Initialiser un dépôt** : `git init`
* **Ajouter un dépôt distant** : `git remote add origin <url-to-repository>`

<div id="fazendo-alteraes">
  #### Effectuer des modifications
</div>

* **Vérifier l’état** : `git status` (affiche les fichiers modifiés, ajoutés et supprimés)
* **Indexer des fichiers** : `git add <filename>` ou `git add .` (pour tous les fichiers)
* **Valider les modifications** : `git commit -m "your commit message"`
* **Envoyer les modifications** : `git push origin <branch-name>`
* **Récupérer les modifications** : `git pull origin <branch-name>`

<div id="autenticao">
  #### Authentification
</div>

Lorsque vous travaillez avec des dépôts privés, vous devez vous authentifier :

* Pour les dépôts GitHub.com, utilisez un jeton d’accès personnel plutôt que votre mot de passe.
* Pour éviter de ressaisir vos identifiants, vous pouvez les stocker dans Replit Secrets :
  1. Créez un nouveau secret avec la clé `GIT_URL`
  2. Définissez sa valeur sur `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Utilisez `git push $GIT_URL` pour effectuer un envoi sans saisir vos identifiants

<Note>
  Lorsque vous utilisez des secrets contenant des identifiants, toute personne ayant accès à votre Replit App peut potentiellement accéder à vos identifiants Git. Pour les dépôts sensibles, envisagez de saisir vos identifiants manuellement à chaque fois.
</Note>
