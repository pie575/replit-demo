Тип деплоя — это технология, с помощью которой Replit публикует ваше приложение. Выбрать его можно в разделе **Adjust settings** инструмента Publishing — в выпадающем списке **Deployment type**. Вариант **Autoscale** используется по умолчанию и рекомендуется большинству разработчиков: менять его не требуется.

<div id="section">
  ## Сравнение типов деплоя
</div>

| Тип             | Для чего подходит                                  | Как работает                                                                | Как оплачивается                          |
| :-------------- | :------------------------------------------------- | :-------------------------------------------------------------------------- | :---------------------------------------- |
| **Autoscale**   | Веб-приложения и API с переменным трафиком         | Добавляет серверы при высокой нагрузке и масштабируется до нуля при простое | Оплата только за время обработки запросов |
| **Static**      | Лендинги, портфолио, сайты документации            | Отдаёт файлы с кешированных облачных серверов, без бэкенда                  | Оплата только за данные, отданные сайтом  |
| **Reserved VM** | Боты, фоновые задачи, постоянно работающие API     | Один выделенный сервер, который не уходит в спящий режим                    | Фиксированная ежемесячная плата           |
| **Scheduled**   | Периодические задачи: резервные копии, уведомления | Выполняет команду по заданному расписанию, затем останавливается            | Оплата за время каждого запуска           |

<div id="autoscale">
  ## Autoscale
</div>

Деплой Autoscale работает на серверах, которые масштабируются в зависимости от трафика приложения. При высокой нагрузке Replit добавляет серверы, чтобы справиться с ней. В периоды простоя количество серверов сокращается вплоть до нуля, поэтому в часы затишья вы ничего не платите.

Подходит в следующих случаях:

* Веб-приложения с переменным трафиком, например сайты электронной коммерции
* API и сервисы

Настройки управляются в разделе **Adjust settings**. См. [производительность машины и максимальное количество серверов](/ru/ko/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Static-деплой размещает файлы приложения — HTML, CSS, JavaScript и другие — на облачных серверах, которые благодаря кешированию отдают контент быстро и экономично. Бэкенд-сервера при этом нет.

Такой вариант подойдёт в следующих случаях:

* маркетинговые лендинги;
* сайты-портфолио;
* сайты с документацией по продукту и API.

<Note>
  Static-деплой несовместим с Replit App, созданными с помощью Agent. Agent создаёт полностековые приложения, которым нужен бэкенд-сервер, поэтому в таких случаях используйте Autoscale или Reserved VM.
</Note>

В настройки входят публичная директория, из которой отдаётся контент, и необязательная команда сборки. Подробнее о заголовках ответа, перезаписи URL и перенаправлениях см. в разделе [Расширенные настройки Static](/ru/ko/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Деплой Reserved VM запускает приложение на выделенной виртуальной машине, которая не уходит в спящий режим. Вы получаете стабильную производительность и предсказуемую фиксированную ежемесячную стоимость.

Подходит в следующих случаях:

* фоновые задачи, требующие много памяти;
* чат-боты, которым нужно постоянно поддерживать соединение;
* API-серверы, работающие круглосуточно.

Настройки включают [производительность машины](/ru/ko/features/publishing/machine-configuration), команды сборки и запуска, сопоставление портов, а также то, работает ли приложение как веб-сервер или как фоновый обработчик.

<div id="scheduled">
  ## Scheduled
</div>

Деплой Scheduled выполняет команду в среде приложения по заданному расписанию, а между запусками остаётся остановленным. Опишите расписание обычными словами, например «каждый будний день в 9 утра», и Replit автоматически превратит это в расписание. Если запуск завершится неудачей, вы получите уведомление.

Подходит для таких задач:

* Проверка состояния и отчёты о работоспособности
* Отправка уведомлений
* Запуск резервного копирования

В настройки входят расписание, тайм-аут задачи, команды сборки и запуска. Деплой Scheduled не отдаёт веб-страницы, поэтому публичного URL у него нет.
