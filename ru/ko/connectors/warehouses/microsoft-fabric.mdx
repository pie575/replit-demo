Создавайте ИИ-приложения в Replit и публикуйте их напрямую в Microsoft Fabric, обеспечивая уровень управления и безопасности Enterprise. Интеграция с Microsoft Fabric превращает управляемые корпоративные данные во внутренние инструменты, такие как дашборды, рабочие процессы и ИИ-приложения. Команды быстрее проходят путь от промпта до запуска в production, а политики аутентификации и доступа остаются в привычной среде Fabric.

<div id="fabric">
  ## Что такое приложения для работы с данными Fabric
</div>

Приложения для работы с данными Fabric — это статические React-приложения, которые выполняют запросы [Data Analysis Expressions (DAX)](https://learn.microsoft.com/en-us/dax/) к [семантическим моделям Power BI](https://learn.microsoft.com/en-us/power-bi/connect-data/service-datasets-understand) и отображают диаграммы Power BI. Их устройство определяется несколькими особенностями:

* **Семантическая модель Power BI — источник данных.** Диаграммы строятся на основе DAX-запросов к подключенной семантической модели (набору данных).
* **Они изначально доступны только для чтения.** Приложение считывает данные с помощью DAX `EVALUATE` и не записывает их обратно в Power BI. Если вам требуется записываемое состояние, используйте отдельную базу данных приложения помимо дашборда.
* **Они отображаются через портал Fabric.** Уровень данных работает в портале Microsoft Fabric, выполняет запросы к семантической модели и возвращает результаты в приложение. Данные остаются в среде Fabric.
* **Они размещаются в инфраструктуре Microsoft.** Готовое приложение для работы с данными можно опубликовать на хостинге Microsoft, чтобы оно работало вместе с остальной средой Fabric.

<Note>
  Для приложений для работы с данными Microsoft Fabric требуется доступ к клиенту Microsoft Fabric с семантической моделью Power BI и — в период предварительной версии — участие в утвержденной программе тестирования.
</Note>

Внутри Agent с помощью [Rayfin](https://github.com/microsoft/rayfin) — SDK и CLI с открытым исходным кодом для создания серверной части приложений — позволяет определять и публиковать готовые к эксплуатации приложения на основе данных Fabric.

Всё происходит в рамках одного рабочего процесса: вы описываете приложение, Agent создаёт его каркас, подключает к управляемым данным Fabric и публикует для работы в клиенте Fabric вашей организации.

В этом руководстве рассматриваются процесс разработчика, способы подключения приложения к данным Fabric, а также возможности для команд и автоматизации. Сведения об обычных дашбордах данных на основе других хранилищ см. в разделе [Визуализация данных](/ru/ko/features/artifact-types/data-apps).

<div id="section">
  ## Сценарии использования
</div>

Для организаций, уже инвестировавших в экосистему данных Microsoft, это гораздо более быстрый путь к созданию внутреннего ПО. Вместо того чтобы тратить недели на подключение аутентификации, API, инструментов деплоя и политик управления, команды описывают, что им нужно, а Agent создаёт это.

Типичные сценарии использования:

* Инструменты повышения производительности для отделов
* Операционные дашборды
* Инструменты для исследования данных
* Приложения для автоматизации рабочих процессов
* Интерфейсы для подготовки отчётов

В Enterprise IT управление, аутентификация и безопасность остаются в среде Fabric, которой организация уже управляет, поэтому быстрое создание приложений не происходит в ущерб централизованному контролю.

<div id="fabric-2">
  ## Создание приложения для работы с данными Fabric
</div>

Процесс разработки интерактивный. Вы работаете в Replit, а аутентификация и доступ к данным выполняются через Microsoft, когда появляется соответствующий запрос.

<Steps>
  <Step title="Начните с шаблона Fabric">
    На главной странице Replit откройте раскрывающееся меню **Templates** и выберите **Microsoft Fabric App** в разделе **Org templates**. Agent откроет рабочий процесс создания приложения для работы с данными с предзагруженными инструментами Fabric.

    <Frame caption="Выбор организационного шаблона Microsoft Fabric App на главной странице Replit (интерфейс закрытого предварительного просмотра).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Главная страница Replit с открытым меню Templates, где Microsoft Fabric App выделен в разделе Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Опишите нужный дашборд">
    Введите промпт с описанием дашборда или инструмента отчётности, который хотите создать. Например: &quot;Создайте дашборд ежемесячного роста выручки на основе модели продаж Fabric.&quot; Вам не нужно писать DAX — Agent создаст запросы.
  </Step>

  <Step title="Войдите через Microsoft">
    Когда появится запрос, войдите через Microsoft OAuth в клиент, содержащий данные Fabric. Это позволит Agent читать семантические модели, к которым у вас есть доступ. Учётная запись, через которую вы входите, должна иметь доступ к нужному рабочему пространству Fabric.
  </Step>

  <Step title="Добавьте источник данных">
    Когда Agent попросит, предоставьте семантическую модель Power BI / Fabric, которую хотите использовать. Можно указать полный URL набора данных из портала Fabric (например, `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) или идентификатор рабочего пространства и идентификатор набора данных/элемента. Agent использует эти данные, чтобы определить рабочее пространство и семантическую модель для выполнения запросов.

    Модель должна быть **опубликована в службе Power BI** — локальные файлы `.pbix` использовать нельзя.

    <Frame caption="Agent запрашивает ссылку на семантическую модель Power BI / Fabric (интерфейс закрытого предварительного просмотра).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Панель Agent просит разработчика предоставить семантическую модель Power BI или Fabric с помощью полного URL портала Fabric либо идентификатора рабочего пространства и идентификатора набора данных или элемента, а также сообщает, что модель должна быть опубликована в службе Power BI, поэтому локальные файлы .pbix не поддерживаются" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Позвольте Agent создать и доработать приложение">
    Agent изучит схему семантической модели, напишет DAX-запросы и соберёт дашборд с подходящими диаграммами. Проверьте результат и запросите изменения на естественном языке — добавьте фильтры, измените тип диаграммы или добавьте другие показатели.
  </Step>

  <Step title="Опубликуйте приложение (необязательно)">
    Когда дашборд будет готов, вы можете опубликовать её на хостинге Microsoft, чтобы она работала в среде Fabric. Публикация рассматривается отдельно, а это руководство посвящено подключению данных и созданию приложения.
  </Step>
</Steps>

<div id="fabric-3">
  ## Подключение к данным Fabric
</div>

Чтобы читать данные, приложению требуется авторизованное подключение к Microsoft Fabric. Replit настраивает его одним из двух способов.

<div id="fabric-4">
  ### Вход в Fabric на уровне приложения (зритель)
</div>

Зрители опубликованного приложения с данными не настраивают коннектор. Они проходят аутентификацию через встроенную в приложение функцию единого входа Microsoft Fabric, а приложение получает данные от их имени через портал Fabric. Доступ регулируется существующими разрешениями Fabric.

<div id="microsoft-fabric">
  ### Коннектор Microsoft Fabric (упрощённый вариант для разработчиков)
</div>

Для разработчиков **коннектор Microsoft Fabric** — удобный способ предоставить доступ к данным во время разработки. Его использование необязательно: это упрощённый вариант, а не обязательное требование.

* Разработчик, который настраивает коннектор первым, проходит **однократную авторизацию OAuth** в Microsoft.
* **Другие участники того же проекта** наследуют это подключение.
* **Другие рабочие пространства** должны активировать коннектор и пройти собственную OAuth-авторизацию.
* Идентификатор, авторизованный через OAuth, должен иметь доступ к целевому рабочему пространству Fabric.

Коннектор использует Microsoft Entra OAuth и действует в пределах одного тенанта. Как и другие коннекторы Replit, он управляется на странице [Интеграции](/ru/ko/features/integrations/overview) проекта. Подробнее о коннекторах см. в разделе [Управление коннекторами](/ru/ko/replitai/managing-connectors).

<Note>
  В период закрытого предварительного просмотра для коннектора Microsoft Fabric недоступны общие управляемые Replit учетные данные. Разработчики проходят авторизацию в собственном тенанте Microsoft Entra.
</Note>

<div id="section-2">
  ## Команды и автоматизация
</div>

При работе с общей командой или в неинтерактивных средах (например, CI) интерактивный OAuth не всегда удобен. В таких случаях вместо интерактивного входа используйте токен **субъекта-службы**, сохранённый в [Secrets](/ru/ko/core-concepts/project-editor/app-setup/secrets) проекта. Приложение использует идентификатор субъекта-службы для чтения данных Fabric.

Это наиболее близкий подход к настройке межмашинного взаимодействия: неинтерактивная учётная запись, созданная в Microsoft Entra и получившая доступ к рабочему пространству Fabric, аутентифицирует приложение без участия пользователя. Убедитесь, что субъект-служба имеет доступ к рабочему пространству и семантической модели, к которым обращается приложение.

<div id="section-3">
  ## Устранение неполадок
</div>

<AccordionGroup>
  <Accordion title="Данные не загружаются в предпросмотре приложения">
    Уровень данных Fabric работает через портал Microsoft Fabric. Если диаграммы пусты или в предпросмотре приложения не загружаются данные, убедитесь, что вы вошли в учётную запись Microsoft и что используемая учётная запись имеет доступ к подключённому рабочему пространству и семантической модели.
  </Accordion>

  <Accordion title="Agent не может найти семантическую модель">
    Убедитесь, что вы вставили ссылку на набор данных Power BI на портале Fabric и что учётная запись (или субъект-служба) имеет хотя бы доступ на чтение к этому рабочему пространству. Если Agent сообщает, что не может найти рабочее пространство или модель, повторно предоставьте ссылку на набор данных.
  </Accordion>

  <Accordion title="Коннектор отключается или запросы на подключение появляются снова и снова">
    Повторно пройдите аутентификацию коннектора Microsoft Fabric на странице [Integrations](/ru/ko/features/integrations/overview) проекта. Убедитесь, что учётная запись, прошедшая аутентификацию OAuth, имеет доступ к рабочему пространству Fabric. Для командной работы или CI рекомендуется использовать токены субъектов-служб, предоставленные через Secrets.
  </Accordion>
</AccordionGroup>
