发布会创建一个 **生产环境 部署**：这是在专属 URL 上运行的稳定、可分享的应用版本。开发预览用于构建和测试；生产环境 部署 则是访客使用的版本。两者相互独立，因此在再次发布之前，你可以继续进行开发，而不会更改线上应用。

发布不仅仅是将预览公开。Replit 会打包应用、预配所需资源、检查发布版本，并将域名路由到生成的 部署。

<div id="before-you-publish">
  ## 发布前
</div>

在点击横幅提示或打开 **Publish** 前，请使用 Preview 测试主要用户流程，检查所支持屏幕尺寸下的布局，并修复 Agent 报告的错误。Publishing 会让其他人可以使用当前版本，因此请勿在 App 中包含 Secrets 或私密测试数据。

<div id="publish-your-app">
  ## 发布你的应用
</div>

<Steps>
  <Step title="打开 Publish 对话框">
    在开发预览横幅中选择 **Publish your app**，返回发布流程。你也可以自行打开项目，并在 Build 或 Design 中工作时，从 Project Editor 右上角选择 **Publish**。

    <Tip>
      你也可以在提示框中向 Agent 输入：`Publish this app.` Agent 可以为发布做好准备，或引导你完成必要的确认操作。
    </Tip>
  </Step>

  <Step title="选择域名和访问设置">
    **域名**是访客访问你的部署时使用的地址。查看自动生成的 `.replit.app` 域名，并在需要时更改可用名称。然后选择**访问级别**，以决定哪些人可以打开应用：

    * **Public** 允许任何拥有链接的人访问应用。
    * **Password protected** 要求访客输入共享密码。
    * **Workspace only** 将访问权限限制为你的 workspace 成员。
    * **Invite only** 将访问权限限制为你选择的人员或群组。

    有关各选项的详细信息，请参阅[应用访问权限](/zh/features/publishing/private-deployments)。

    你还可以启用反馈小组件，让访客从已发布的应用中提交反馈。

    </Frame>

    <PublishingPlanAvailability />
  </Step>

  <Step title="审查安全性并发布">
    选择 **Review security**，在应用上线前检查发布版本。域名、访问权限和安全设置准备就绪后，选择 **Publish**。

    Replit 会配置部署、运行安全检查、构建并打包应用，然后将发布版本推送上线。配置会准备云端资源；构建和打包会将项目转换为可用于生产环境的软件包；推送上线会使该软件包成为线上版本。请在各阶段完成期间保持项目打开。

  </Step>

  </Step>

<div id="understand-the-published-project">
  ## 了解已发布的项目
</div>

发布后，项目包含两个相互关联的部分：你可继续构建和编辑的项目，以及当前为访客提供服务的生产环境 部署。打开 **工具**，即可查看和管理该生产环境。

**Publishing** 窗格提供 部署 概览。它会显示最新版本是否发布成功、谁可以访问、应用运行在哪个位置、采用何种托管方式、可使用哪些资源，以及有哪些域名指向它。

**部署类型**说明 Replit 如何运行应用。**Autoscale** 会根据流量变化启动更多机器。**Reserved VM** 会始终保持一台机器可用。**Static** 用于提供无需运行 backend 的文件，**Scheduled** 则按预定时间运行程序。请参阅[部署类型](/zh/features/publishing/deployment-types)进行比较。

**机器性能**是每个实例可用的 CPU 和内存。最大机器数量限制了 Autoscale 的最大扩展规模。请参阅[机器配置](/zh/features/publishing/machine-configuration)。更多资源可以提升容量，但也会增加用量成本。

**部署地理位置**决定应用运行的区域。选择更接近大多数访客的区域可以降低延迟。请参阅[Project 地理位置](/zh/features/publishing/project-geography)。

根据你的应用和套餐，**调整设置**或**管理**会显示这些控件，以及生产环境 Secrets 和相关 部署 选项。

这些是可选的生产环境控件。分享常规应用时无需更改它们，但某些更改可能会影响可用性或用量成本。

<div id="monitor-the-release">
  ### 监控发布版本
</div>

**Monitoring** 可帮助回答生产环境中的一个问题：*应用是否运行正常、响应是否良好？* 在 **Tools** 窗格的 **Replit Cloud** 下打开 **Monitoring**。这里会显示请求、HTTP 状态、响应时长、CPU 利用率和内存利用率。状态代码可反映请求失败情况，而响应时长可反映响应是否缓慢。CPU 和内存图表可帮助识别资源瓶颈。新发布的版本在 线上应用 收到流量前可能几乎没有数据。完整介绍请参阅[监控你的应用](/zh/features/publishing/monitoring-a-deployment)。

<Frame>
  <img src="/assets/mirror/05-monitoring-2da17ab4d843.jpg" alt="Gather 的 Monitoring 窗格，显示应用请求指标以及基础设施 CPU 和内存图表" width="1280" height="720" data-path="images/publish-gather/05-monitoring.jpg" />
</Frame>

<div id="review-traffic-and-growth">
  ### 查看流量和增长情况
</div>

**Growth** 用于回答另一个问题：*用户是否找到了并在使用该应用？* 在 **Tools** 窗格的 **Replit Cloud** 下打开 **Growth**。基本指标包括访客、热门页面、引荐来源、国家/地区、浏览器和设备。这些指标可帮助你了解受众来自何处，以及哪些内容更受关注。[SEO 评级](/zh/features/publishing/seo-rating) 用于衡量已发布页面针对搜索引擎的优化程度。订阅付费套餐的构建者可以使用 [SEO Agent](/zh/features/publishing/seo-agent) 扫描可优化项。已发布的应用获得流量后，分析数据才会显示。

<div id="update-your-published-app">
  ## 更新已发布的 App
</div>

在 Project Editor 中所做的更改不会自动更新线上版本。通过这种分离机制，您可以准备和测试更改，而不会影响访客。请先在 **Preview** 中测试更改，准备就绪后选择 **重新发布**。重新发布会在同一 URL 上创建新的生产版本，因此无需向访客发送新链接。

重新发布后，请再次打开公共 URL，验证更改后的行为是否符合预期。如果发布失败，请先通过发布状态和日志确定失败阶段，再重试。
