게시에는 세 가지 유형의 사용량 기반 청구가 있습니다:

1. 아웃바운드 데이터 전송
2. Autoscale 컴퓨팅 유닛
3. 요청

**설정**의 **계정** → **계정 사용량**에서 사용량을 확인할 수 있습니다. 청구는 매월 또는 누적 비용이 월간 크레딧을 초과할 때 발생합니다. Replit Core 및 Pro 사용자는 이러한 리소스에 대한 월간 허용량을 받습니다.

월간 구독 허용량을 초과하는 추가 크레딧이 필요하면 청구 페이지에서 크레딧 팩을 구매할 수 있습니다. 크레딧 팩에 대한 자세한 내용은 [지출 관리](/ko/billing/managing-spend)를 참조하세요.

# 게시

## 1. 게시 아웃바운드 데이터 전송

이 유형의 사용량은 바이트당 청구되며 Replit Core 및 Pro 사용자는 월간 허용량을 받습니다. 이그레스(발신) 데이터만 이 허용량에 계산되어 초과분이 발생할 수 있습니다. 반대로 인그레스(수신) 데이터는 항상 무료입니다.

| 구독          | 허용량                                                |
| ----------- | -------------------------------------------------- |
| Replit Core | 100 GiB                                            |
| Replit Pro  | [Replit Pro 요금](https://www.replit.com/pricing) 참조 |

허용량은 [정적](/ko/features/publishing/deployment-types#static), [Autoscale](/ko/features/publishing/deployment-types#autoscale), [Reserved VM](/ko/features/publishing/deployment-types#reserved-vm) 및 [예약](/ko/features/publishing/deployment-types#scheduled) 배포에 적용됩니다.

아웃바운드 데이터 전송의 현재 요금은 [요금 페이지](https://www.replit.com/pricing)를 참조하세요.

***

## 2. 컴퓨팅 유닛

Autoscale 배포는 시간 경과에 따른 CPU 및 RAM 사용량을 모두 고려하는 컴퓨팅 유닛을 기반으로 청구됩니다.

초과분은 컴퓨팅 유닛을 기준으로 청구됩니다. 청구 단위는 개별 컴퓨팅 유닛까지 세분화됩니다. 컴퓨팅 유닛의 현재 요금은 [요금 페이지](https://www.replit.com/pricing)를 참조하세요.

다음은 Autoscale 배포의 RAM 및 CPU 초가 컴퓨팅 유닛으로 변환되는 방식입니다:

| 리소스    | 컴퓨팅 유닛 |
| ------ | ------ |
| RAM 1초 | 2 유닛   |
| CPU 1초 | 18 유닛  |

정적 배포는 컴퓨팅 유닛을 소비하지 않습니다. 청구는 [지정된 양](#)을 초과하는 아웃바운드 데이터 전송에 대해서만 이루어집니다.

[Autoscale 배포에 대해 자세히 알아보기](/ko/features/publishing/deployment-types#autoscale).

***

## 3. 요청

Autoscale 배포는 수행된 요청 수도 고려합니다.

요청의 현재 요금은 [요금 페이지](https://www.replit.com/pricing)를 참조하세요.

# 데이터베이스

Replit은 [프로덕션 데이터베이스](/ko/features/data-and-storage/development-and-production) 사용에 대해서만 요금을 청구합니다. 개발 데이터베이스는 항상 무료이며 모든 Replit 앱에 포함되어 있습니다. 개발 데이터베이스에 대한 자세한 내용은 [개발 데이터베이스](/ko/features/data-and-storage/sql-database)를 참조하세요.

Replit PostgreSQL은 완전 관리형 서버리스로, 손쉬운 고가용성과 유지보수 없는 운영을 제공합니다. 프로덕션 데이터베이스 청구는 실제 사용량을 기반으로 하여 상당한 비용 절감이 가능합니다.

프로덕션 PostgreSQL 데이터베이스는 두 가지 사용 지표를 기준으로 청구됩니다:

* **[컴퓨팅 시간](#compute-time)**: 시간당 소비된 컴퓨팅 리소스의 양.
* **[데이터 스토리지](#data-storage)**: 저장된 총 데이터 볼륨 (이력 데이터 포함).

**설정** → **계정** → **계정 사용량**에서 프로덕션 데이터베이스 사용량을 포함한 현재 리소스 사용량을 확인할 수 있습니다.

## 컴퓨팅 시간

컴퓨팅 시간은 주어진 청구 기간 동안 데이터베이스가 활성 상태를 유지하는 시간 수로 결정됩니다. 데이터베이스는 요청을 받을 때와 마지막 요청 후 추가 5분 동안 활성 상태로 간주됩니다. 데이터베이스가 5분 동안 유휴 상태로 유지되면 일시 중단되고 비활성 상태로 전환됩니다.

## 데이터 스토리지

데이터 스토리지는 계정의 모든 데이터베이스에 저장된 총 데이터 볼륨으로, 기비바이트(GiB) 단위로 측정됩니다. 스토리지는 월별 최대 사용 스토리지 양으로 계산됩니다. 각 PostgreSQL 데이터베이스는 데이터가 없더라도 33MB의 스토리지를 소비합니다. 이는 Postgres 서버의 기본 스토리지 공간입니다.

<Note>각 프로덕션 데이터베이스의 총 스토리지 한도는 10 기비바이트(GiB)입니다. 개발 데이터베이스에는 Replit 앱당 20 GiB의 무료 스토리지가 포함됩니다.</Note>
