AI 工具可帮助你用自然语言发出指令，并返回有用的结果。在 Replit 中，这些结果可以转化为计划、代码、设计、说明、调试步骤以及对项目的更改。

开始构建前，你无需深入了解 AI。一些基本概念能帮助你给出更好的指令，并自信地评估结果。

<div id="modelos-de-linguagem-de-grande-porte">
  ## 大型语言模型
</div>

大多数 AI 构建工具都由大型语言模型驱动，通常简称为 LLM。LLM 是经过训练、能够识别文本模式并生成符合这些模式的文本的模型。

文本可以是散文、代码、HTML、CSS、SQL、JSON、终端命令、测试输出、错误信息或配置。这就是为什么同一类模型既能帮助撰写文本、解释 bug、编写代码，也能总结计划。

<div id="gerao-de-texto">
  ## 文本生成
</div>

LLM 不会从数据库中检索固定答案。它会根据你提供的输入和可见的上下文，逐步生成回答。

当你编写 prompt 时，模型会利用你的文字、对话以及所有可用的项目上下文来预测有用的回答。回答可以是解释、计划，或供其他系统执行操作的文本。

这意味着输入质量至关重要。明确的目标、示例、约束条件和上下文，都能提高获得良好结果的可能性。

<div id="tokens">
  ## 词元
</div>

AI 模型会将文本处理成称为词元的小单位。一个词元可以是一个词、词的一部分、标点符号、空白字符或一段代码。

词元很重要，因为它们会影响 AI 模型一次能处理多少信息。长对话、大型文件、日志、截图和指令都会构成模型推理时所用的上下文。

构建时无需计算词元数量。你只需了解：当重要信息清晰、最新且重点明确时，Agent 的效果最佳。

<div id="a-ia-pode-variar">
  ## AI 的输出可能有所差异
</div>

AI 的输出并不总是完全相同。同一个请求可能会产生不同的措辞、设计、实现细节或权衡取舍。

这种差异有助于探索，但也意味着你应审查重要工作。测试 Agent 构建的内容，遇到不清楚的地方就请求解释，并在需要可靠的恢复点时使用 checkpoint。

<div id="o-que-torna-a-sada-da-ia-melhor">
  ## 如何让 AI 输出更好
</div>

提供以下信息时，Agent 的表现会更好：

* 明确的目标
* 目标受众或用户需求
* 约束条件和非目标
* 示例、截图、文件、数据或链接
* 当前遇到的问题或确切的错误信息
* 用于定义“就绪”的验收标准

比较以下两个提示词：

* *“为一个网站编写代码。”*
* *“为一个网站编写代码，用于收集电子邮件地址以建立我的个人邮件列表。将提交内容存储到 Google Sheets 中。”*

第二个提示词明确了目标、数据和存储位置，因此 Agent 无需猜测即可采取行动。

这些信息称为上下文。要了解上下文为何重要，请参阅[上下文管理](/zh/pt/learn/foundations/context-management)。

<div id="de-ia-a-agentes-de-ia">
  ## 从 AI 到 AI 智能体
</div>

聊天模型可以回复消息。AI 智能体则结合模型和工具来完成多步骤任务——它可以围绕目标进行推理、选择工具、查看信息、作出更改、验证结果，并持续执行，直到任务完成或需要你进一步输入。

<div id="modelos-e-ferramentas">
  ### 模型与工具
</div>

一个 Agent 由两个重要部分组成：

| 部分       | 作用                                                 |
| -------- | -------------------------------------------------- |
| **语言模型** | 理解指令、生成文本、权衡不同选项，并决定下一步该做什么。                       |
| **工具**   | 让 Agent 能够执行操作，例如读取文件、编辑代码、运行命令、搜索文档、测试 App 或发布更改。 |

模型决定哪项操作可能有帮助，工具则让 Agent 能够根据这一决定采取行动。

<div id="o-que-os-agentes-podem-fazer">
  ### Agent 可以做什么
</div>

Agent 适合处理需要多个步骤才能完成的任务，例如：

* 规划功能
* 创建文件和代码
* 读取现有项目结构
* 运行命令或测试
* 调试错误
* 更新设计
* 连接服务
* 总结变更内容

Agent 不只是回答问题；它会实际完成任务。

<div id="replit-agent">
  ### Replit Agent
</div>

Replit Agent 是一款可帮助您在 Replit 上构建应用的 AI 智能体。它可以帮助您创建应用和其他产物、检查项目、编辑文件、运行命令、测试功能、解释代码、创建任务，并引导您完成部署流程。

例如，您可以让 Agent：

```text theme={null}
创建一个简单的社区活动报名 App。
访客应能查看活动详情、提交姓名和电子邮件，并收到确认信息。
请让第一个版本保持简单，以便我今天就能发布。
```

Agent 可以将您的需求转化为项目，创建初始版本，并协助您进一步完善。

<div id="voc-ainda-lidera-o-trabalho">
  ### 您仍然主导整个工作
</div>

Agent 可以快速推进，但重要决策仍由您做出：

* 产物应具备哪些功能
* 面向哪些用户
* 哪些内容应纳入范围
* 哪些内容不应变更
* 结果是否正常运行
* 何时准备好发布

这就是为什么上下文管理和审查很重要。为 Agent 提供明确的方向并测试结果，能让它发挥最佳效果。

<div id="equvocos-comuns">
  ## 常见误区
</div>

* **“AI 应该知道我的意思。”** AI 只能根据你提供的信息来工作。如果某件事很重要，请明确说明。
* **“第一次回复就应该是最终结果。”** 使用 AI 构建是一个迭代过程。请审查、测试并不断完善。
* **“AI 像人一样理解意图。”** AI 可以推断模式，但不会自动了解你的偏好、受众、限制条件或对“就绪”的定义。
* **“智能体只是一个聊天机器人。”** 聊天机器人主要回答问题。智能体还可以使用工具并采取行动。
* **“Agent 会自动了解整个产品目标。”** Agent 会根据你的指令和上下文开展工作。如果某件事很重要，请将其纳入说明。
* **“Agent 无需审查。”** Agent 可以构建产物，但是否符合你的意图由你决定。
