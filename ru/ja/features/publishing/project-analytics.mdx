Project Analytics показывает, как люди находят и используют ваше опубликованное веб-приложение. Откройте панель **Growth**, чтобы посмотреть динамику посещаемости, источники трафика и пользовательские события.

Replit собирает базовые метрики трафика для поддерживаемых опубликованных приложений. На платных тарифах Agent может добавлять пользовательские события и отвечать на вопросы по аналитике.

<div id="section">
  ## Перед началом
</div>

Для Project Analytics необходимо следующее:

* **Опубликованный сайт.** Analytics работает с [артефактами](/ru/ja/features/projects-and-artifacts/artifacts) типа «сайт». События из мобильных приложений и артефактов других типов не собираются.
* **Поддерживаемый deployment.** Project Analytics работает с deployments типов [Autoscale](/ru/ja/features/publishing/deployment-types#autoscale), [Reserved VM](/ru/ja/features/publishing/deployment-types#reserved-vm) и [Static](/ru/ja/features/publishing/deployment-types#static).
* **Платный тарифный план для расширенной аналитики.** Пользовательские события и аналитические запросы через Agent доступны на платных тарифных планах.
* **Включение аналитики при следующей публикации.** Включите параметр **Enable analytics** и опубликуйте или переопубликуйте приложение — после этого Replit начнёт собирать события.

<div id="project-analytics">
  ## Как открыть Project Analytics
</div>

1. Откройте проект в Project Editor.
2. Выберите **Tools**.
3. В разделе **Replit Cloud** выберите **Growth**.

<Note>
  Панель **Growth** остаётся заблокированной, пока вы не опубликуете приложение. До публикации отображается сообщение с предложением перейти к **Go
  to Publishing**.
</Note>

Аналитические данные появляются после того, как опубликованное приложение начнёт получать трафик. У новых приложений график может оставаться пустым, пока на них никто не зайдёт.

<div id="section-2">
  ## Просмотр аналитики по умолчанию
</div>

Аналитика по умолчанию использует данные IP-трафика и отображает следующие показатели:

* **Visitors** — приблизительное количество уникальных посетителей за выбранный период.
* **Visitors over time (hour)** или **Visitors over time (day)** — как менялась активность посетителей в течение выбранного периода.
* **Top Pages** — страницы с наибольшим трафиком.
* **Top Referrers** — сайты, которые направляют трафик в ваше приложение.
* **Top Countries** — предполагаемые страны посетителей.
* **Top Browsers** — браузеры, которыми пользуются посетители.
* **Top Devices** — типы устройств, которыми пользуются посетители.

С помощью меню периода можно выбрать промежуток времени от 6 часов до 30 дней. Общее число посетителей сравнивается с предыдущим периодом такой же длительности.

Если ваше приложение использует [Replit Auth](/ru/ja/features/auth-and-identity/authentication), на панели также отображается показатель **Unique Logged in Users** за выбранный период.

<Note>
  Количество посетителей приблизительное. Оно основано на сетевых данных и данных браузера,
  поэтому один человек может учитываться как несколько посетителей, если он заходит с разных устройств или на стыке календарных месяцев.
</Note>

<div id="agent">
  ## Добавление пользовательских событий с помощью Agent
</div>

Пользовательские события измеряют действия, важные для вашего приложения. Например: завершение регистрации, выбор тарифа, отправка формы или совершение покупки.

<Steps>
  <Step title="Добавьте метрики с помощью Agent">
    Откройте **Growth**. В разделе **Advanced analytics** выберите **Add metrics with
    Agent**. Опишите Agent, какие действия вы хотите измерять. Agent добавит отслеживание событий в нужных местах приложения.
  </Step>

  <Step title="Включите аналитику и опубликуйте приложение">
    Откройте **Publishing** и начните новую публикацию или переопубликуйте приложение. В разделе **Suggested
    add-ons** включите **Enable analytics**. Затем опубликуйте приложение. Начиная с этого выпуска Replit будет собирать просмотры страниц и пользовательские события.
  </Step>
</Steps>

<Tip>
  Настроить аналитику можно и напрямую через чат с Agent. Если приложение или цели измерения изменились, вы в любой момент можете попросить Agent добавить или обновить события.
</Tip>

Replit сам добавляет трекер аналитики в опубликованное приложение. Вам не нужно вручную добавлять скрипт отслеживания, идентификатор сайта или переменные окружения для аналитики.

<Warning>
  Не указывайте в именах и свойствах пользовательских событий секреты, персональные данные и содержимое, введённое посетителями в произвольной форме.
</Warning>

<div id="agent-2">
  ## Спросите Agent об аналитике
</div>

Когда приложение начнёт собирать данные, воспользуйтесь чипами в разделе **Advanced analytics**:

* **Summarize my analytics** — Agent подготовит сводку по аналитике проекта за последние 7 дней.
* **Suggest project improvements** — Agent изучит данные аналитики и предложит, что стоит улучшить в проекте.

Вы также можете задавать Agent конкретные вопросы.

<AiPrompt>
  Compare visitors and completed sign-ups for the past seven days. Show the
  daily trend and identify the pages with the highest conversion rate.
</AiPrompt>

Agent может анализировать просмотры страниц, источники трафика, пользовательские события, свойства событий и воронки. Он использует данные аналитики проекта и возвращает сводные результаты.
