description: "Узнайте, как настраивать сетевые порты и управлять ими в Replit App."

Поскольку Replit запускает проекты в облачной среде, порты работают иначе, чем на локальном компьютере. (Если вам нужно более простое объяснение того, что такое TCP-порты, [начните отсюда](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

На компьютере существует только один уровень управления портами. То есть, когда программа указывает порт, на котором будет прослушивать соединения, интернет-трафик, поступающий на этот порт компьютера, направляется соответствующему процессу.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="Компьютер" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` — это адрес, то есть хост. Когда процесс прослушивает `0.0.0.0`, это означает, что он прослушивает все сетевые интерфейсы. Иными словами, если другой компьютер в интернете отправит запрос на IP-адрес вашего компьютера, процесс получит этот запрос. Поэтому прослушивание 0.0.0.0 означает, что, если компьютер подключён к интернету, соответствующий процесс доступен из публичного интернета.

Большинство фреймворков во время разработки *не* прослушивают `0.0.0.0`. В целях конфиденциальности и безопасности не всегда нужно открывать внешний доступ к тому, над чем вы работаете. Вместо этого они прослушивают другой адрес — `127.0.0.1`, часто называемый `localhost`. Это означает, что отправлять запросы на этот порт можно только с того же компьютера.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Порты localhost видны только на компьютере, на котором они размещены." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

В Replit для доступа к запущенному процессу через веб-просмотр или внешние запросы должен быть определён **внешний порт**. Это необходимо, поскольку «внутренний порт», обычно используемый процессом, виден только внутри предоставляемой Replit изолированной облачной среды. Чтобы направить нужный трафик в программу, внутренний порт необходимо подключить к доступному извне порту. Даже если процесс прослушивает адрес вроде 0.0.0.0, который обычно доступен из интернета, его всё равно нужно привязать к внешнему порту.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Внешние порты направляют трафик на внутренний порт, который прослушивает программа." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit обрабатывает это, привязывая внешний порт к определённому внутреннему порту. Например, на диаграмме выше внешний порт `:80` привязан к внутреннему порту `:3000`. То есть весь трафик, который это Replit App получает через порт 80, передаётся на внутренний порт 3000.

Эта конфигурация записывается в разделе [[ports]] файла конфигурации .replit.

По умолчанию Replit привязывает первый открытый порт к внешнему порту 80, чтобы соответствующий процесс был доступен по домену без указания номера порта (например, customdomain.com/ вместо customdomain.com:3000/). Дополнительные внутренние порты, открытые позже, привязываются к другим доступным внешним портам (полный список приведён ниже).

<div id="section-2">
  ## Порт по умолчанию
</div>

Порт :80 — это порт по умолчанию для HTTP-трафика, поэтому HTTP-трафик, направленный на корневой домен, автоматически маршрутизируется через порт 80. По этой причине номер порта 80 не отображается в URL. Порты, отличные от :`80`, указываются в адресе домена (например, customdomain.com:4200/). (Replit по умолчанию предоставляет TLS, поэтому трафик фактически передаётся через порт 443 — порт по умолчанию для HTTPS. На практике эти два порта можно считать взаимозаменяемыми.)

<div id="section-4">
  ## Публикация
</div>

Деплои Autoscale и Reserved VM поддерживают открытие только одного внешнего порта, при этом соответствующий внутренний порт не должен использовать `localhost`. Если открыть несколько портов или один порт через localhost, опубликованное приложение завершится с ошибкой. Чтобы деплой Autoscale работал как ожидается, удалите из конфигурации все записи `externalPort`, кроме записи для сервиса, к которому вы хотите предоставить доступ из интернета.

<div id="section-5">
  ## Отладка
</div>

Одна из распространённых причин неполадок — конфигурация порта выглядит правильной, но программа фактически использует другой порт. Например, если конфигурация выглядит так:

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Интернет-трафик, поступающий на порт 80, перенаправляется на внутренний порт 3000. Однако если программа фактически прослушивает другой порт (например, 8080), а не порт 3000, может показаться, что трафик вообще не проходит. Это может произойти, если вы изменили порт в коде, но не обновили соответствующий порт в конфигурации, или скопировали конфигурацию из одного проекта в другой.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Программа может изменить порт, который она прослушивает." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

Разные фреймворки по умолчанию прослушивают разные порты. Например, Flask использует порт 5000, React — 3000, а Laravel — 8000. Убедитесь, что настроен правильный порт!

<div id="section-6">
  ## Настройка окружения
</div>

Когда в Replit App открывается порт, Replit автоматически привязывает его к доступному внешнему порту и записывает это сопоставление в файл конфигурации .replit.

Однако для внутренних портов, открываемых на localhost, это по умолчанию не происходит. Это связано с тем, что обычно предполагается, что сервисы, работающие на localhost, доступны только с того же компьютера, на котором запущен процесс (порты localhost видны только на компьютере, где запущен соответствующий процесс). Иными словами, такие сервисы часто менее защищены, чем сервисы, изначально предназначенные для доступа из публичного интернета.

Вы можете в любой момент переопределить это поведение, установив для нужного порта параметр конфигурации `exposeLocalhost` в значение `true`.

Если вы хотите, чтобы порты localhost по умолчанию *всегда* были доступны извне, в настройках пользователя установите для параметра «Автоматическая переадресация портов» значение «Все порты».

Если вы *никогда* не хотите автоматически создавать конфигурацию для открытых портов и предпочитаете вручную управлять конфигурацией всех портов Replit App, установите значение «Нет».

<div id="section-7">
  ## Поддерживаемые порты
</div>

При открытии первого порта Replit App по умолчанию назначает порт 80 в качестве внешнего. Replit App может открывать доступ к портам 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080 и 8081 в качестве дополнительных внешних портов.

Порты 22 и 8283 используются внутри системы, поэтому их нельзя переадресовывать.

<div id="ports-replit">
  ## Конфигурация `[[ports]]` в .replit
</div>

Тип: `{localPort, externalPort, exposeLocalhost}`

Конфигурация `[[ports]]` позволяет указать HTTP-порты, которые будут доступны в веб-выводе. По умолчанию все открытые HTTP-порты с хостом 0.0.0.0 отображаются в веб-выводе Replit App.

Чтобы открыть дополнительные порты, не переопределяя порт по умолчанию, добавьте новую запись [[ports]] в файл .replit. Необходимо указать оба параметра: localPort и externalPort. Чтобы добавить несколько дополнительных портов, добавьте в файл .replit несколько записей [[ports]], как показано ниже.

<div id="localport">
  ### localPort
</div>

Определяет, какой порт Replit будет выполнять привязку к внешнему порту.

<div id="externalport">
  ### externalPort
</div>

Определяет порт, который будет открыт для общего доступа и сопоставлен с этим локальным портом.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Если вы *категорически* не хотите открывать определённый порт, сохраните конфигурацию `localPort` и не добавляйте `externalPort`.

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Определяет, можно ли привязать внутренний порт, использующий `localhost`, к внешнему порту. Возможные значения: `true`, `false` или null.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
