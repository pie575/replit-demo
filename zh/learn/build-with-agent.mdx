  const AGENT_INPUT_START_DELAY = 500;
  const getAgentInputTypewriterLoader = () => {
    if (typeof window === "undefined") {
      return null;
    }
    if (!window.__replitDocsAgentInputTypewriterLoader) {
      window.__replitDocsAgentInputTypewriterLoader = {};
    }
    return window.__replitDocsAgentInputTypewriterLoader;
  };
  const ensureAgentInputTypewriterCore = () => {
    if (typeof window === "undefined" || typeof document === "undefined") {
      return Promise.resolve(null);
    }
    if (window.Typewriter) {
      return Promise.resolve(window.Typewriter);
    }
    const loader = getAgentInputTypewriterLoader();
    if (loader.promise) {
      return loader.promise;
    }
    loader.promise = new Promise((resolve, reject) => {
      const handleLoad = () => {
        if (window.Typewriter) {
          resolve(window.Typewriter);
          return;
        }
        loader.promise = null;
        reject(new Error("Typewriter core loaded without a global Typewriter export."));
      };
      const handleError = () => {
        loader.promise = null;
        reject(new Error("Failed to load typewriter core."));
      };
      const existingScript = document.getElementById(AGENT_INPUT_TYPEWRITER_SCRIPT_ID);
      if (existingScript) {
        existingScript.addEventListener("load", handleLoad, {
          once: true
        });
        existingScript.addEventListener("error", handleError, {
          once: true
        });
        return;

      script.src = AGENT_INPUT_TYPEWRITER_SRC;
      script.async = true;
      script.addEventListener("load", handleLoad, {
        once: true
      });
      script.addEventListener("error", handleError, {
        once: true
      });
      document.head.appendChild(script);
    });
    return loader.promise;
  };

    if (typeof window === "undefined") {
      return null;

    startButton: container?.querySelector?.('[data-agent-input-role="start-button"]') || null,
    pillsContainer: container?.querySelector?.('[data-agent-input-role="pills"]') || null

    const {textarea} = getAgentInputElements(container);
    return textarea?.value?.trim() || "";

  const updateAgentInputButtonState = container => {
    const {startButton} = getAgentInputElements(container);
    if (!startButton) {
      return;

    const hasText = getAgentInputPromptValue(container).length > 0;
    startButton.style.opacity = hasText ? "1" : "0.4";
    startButton.style.cursor = hasText ? "pointer" : "not-allowed";
  };
  const stopAgentInputTypewriter = (textarea, {placeholder, clearDemo = false} = {}) => {
    if (typeof window === "undefined" || !textarea) {
      return;
    }
    const registry = getAgentInputTypewriterRegistry();
    const record = registry?.get(textarea);
    if (!record) {
      if (placeholder) {
        textarea.setAttribute("placeholder", placeholder);
      }
      return;
    }
    record.stopped = true;
    if (record.startTimer) {
      window.clearTimeout(record.startTimer);
    }
    if (record.writeFrame) {
      window.cancelAnimationFrame(record.writeFrame);
    }
    if (record.typewriter?.stop) {
      record.typewriter.stop();
    }

    textarea.removeEventListener("pointerdown", record.handlePointerDown);
    textarea.removeEventListener("input", record.handleInput);
    if (clearDemo && textarea.value === record.pendingValue) {
      textarea.value = "";

[Vibe coding 101](/zh/learn/foundations/vibe-coding-101) 讲的是思维方式，本页则讲如何在实践中与 Agent 协作。[高效提示词编写](/zh/learn/effective-prompting) 会告诉你如何写出更清晰的指令。

可以把 Agent 看作球场上的四分卫：它判断局势、选择路线、推进工作。而你是教练：制定策略、下达战术、复盘结果，并决定下一步怎么走。

Agent 能做的事很多，但只有在你主导流程时才能发挥出最佳状态：说清需求、规划工作、补充上下文、审查与测试，并在需要回退时使用 checkpoint。

<div id="five-tips-for-building-with-agent">
  ## 使用 Agent 构建的五个技巧
</div>

与 Agent 协作时，请养成以下习惯：

1. 描述要具体。
2. 提前规划工作。
3. 补充上下文。
4. 审查并测试。
5. 善用 checkpoint。

<div id="be-specific">
  ## 说明要具体
</div>

Agent 能处理复杂任务，但需要清晰的指引。

一条有效的请求应说明你想要什么、哪些内容最重要，以及哪些内容需要保持不变。无需描述每个实现细节，但应为 Agent 提供足够的指引，让它能做出恰当的决策。

不要这样写：

<AiPrompt>让我的 App 更好。</AiPrompt>

试试这样写：

<AiPrompt>
  改进注册页面，让访客在创建 Account 前了解产品的用途。

  <br />

  保持当前的配色方案和表单字段不变，并让主按钮更醒目。
</AiPrompt>

第二个 prompt 为 Agent 提供了目标、重点和约束条件。

当你的请求包含多个部分时，请说明最重要的是什么。

<AiPrompt>
  添加一个简单的管理员视图，用于管理餐饮请求。

  <br />

  最重要的是能够查看新请求、将其标记为已联系，并按状态筛选。

  <br />

  第一版保持简单即可。
</AiPrompt>

Agent 可以将这项工作拆分为多个步骤，但你的指引能让它了解成功的标准。

有关具体指令的更多示例，请参阅[高效提示词编写](/zh/learn/effective-prompting)。

在 Agent 开始构建前，先审查计划：

* 它解决的是不是正确的问题？
* 有没有遗漏什么？
* 有没有超出范围的内容？
* 是否可以先构建一个更小的版本？
* 它有没有说明你该如何测试结果？

如果计划过于宽泛，可以要求 Agent 缩小范围。

<AiPrompt>
  这个计划过于宽泛。

  <br />

  <br />

</AiPrompt>

* 别人能顺利完成主要操作吗？
* 你要求的改动实现了吗？
* 应用在移动端还能正常使用吗？
* 有没有重要功能被破坏？
* Agent 有没有改动无关的内容？
* 结果是否足够好，可以在其基础上继续构建？

如果哪里有问题，请描述你看到的现象。

不要这样说：

<AiPrompt>修复表单。</AiPrompt>

试试这样说：

<AiPrompt>
  当我提交餐饮预订表单时，成功提示出现了，但表单里仍然显示旧的文字。

  <br />

  请在提交后清空表单，并保持成功提示可见。
</AiPrompt>

具体的 feedback 能帮助 Agent 找准并修复真正的问题。

<div id="use-checkpoints">
  ## 使用 checkpoint
</div>

当改动走偏时，checkpoint 能帮你恢复到之前的状态。

如果结果已经比较接近预期，可以给出有针对性的反馈：

<AiPrompt>
  已经很接近了，但表单现在太长。

  <br />

  保留新的视觉风格，删除可选的备注字段，并让取件日期更醒目易读。
</AiPrompt>

当应用比之前更糟、重要功能被破坏，或者 Agent 的改动超出预期时，就该使用 checkpoint。

在 Agent 面板中打开 **History**，即可查看 checkpoint。每个 checkpoint 都会显示改动内容，并提供 **Rollback here** 和 **Changes** 控件。

<Frame>
  <img src="/assets/mirror/agent-checkpoints-history-c33b3b0dd592.png" alt="Agent History 面板，显示一个标记为“Transitioned from Plan to Build mode”的 checkpoint，并带有 Rollback here 和 Changes 按钮" width="720" height="450" data-path="images/fitstart/work-with-agent/agent-checkpoints-history.png" />
</Frame>

当你选择 **Rollback here** 时，Agent 会在执行回滚前确认将要恢复的内容。

<Frame>
  <img src="/assets/mirror/agent-checkpoints-rollback-dialog-28de278b44da.png" alt="Rollback to checkpoint 确认对话框，列出了目标 checkpoint 以及将受影响的内容：文件、Agent 记忆、task，以及一个 Database 复选框" width="900" height="880" data-path="images/fitstart/work-with-agent/agent-checkpoints-rollback-dialog.png" />
</Frame>

如果你不确定该继续修复还是直接回滚，可以让 Agent 帮你比较。

<AiPrompt>
  上一次改动让应用变得更糟了。

  <br />

  请将当前版本与上一个可用版本进行比较。

  <br />

  告诉我是继续修复更稳妥，还是回滚更稳妥，并说明原因。
</AiPrompt>

走弯路很正常。有了 checkpoint，你可以放心尝试，随时都能回到更安全的版本。

如需了解更多恢复相关指引，请参阅 [Checkpoint 与回滚](/zh/features/version-control/checkpoints-and-rollbacks)。

<div id="what-good-agent-collaboration-feels-like">
  ## 良好的 Agent 协作是什么样的
</div>

如果符合以下情况，说明你的方向是对的：

* 你的请求清楚说明了目标和约束条件
* Agent 的方案足够清晰，便于你审阅
* 文字说不清时，你会补充截图、文件或 Canvas 备注
* 你会在变更后测试关键流程
* 结果不理想时，你会给出有针对性的反馈
* 你会使用 checkpoint，而不是一直纠结于修补某个糟糕的改动
