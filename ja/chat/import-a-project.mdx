すでにアプリやプロジェクトに取り組んでいる場合は、それを Replit に持ち込んでプロジェクトの中で作業を続けられます。インポートは、Conversation の根拠やコンテキストとしてファイルを添付するのとは異なります。

## 対応するソースを選ぶ

ソースによって、何を提供するか、そして既存の作業がどのように Replit に取り込まれるかが決まります。現在のインポートガイドでは、次の経路が説明されています。

| 既存の作業            | 対応するソース                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------- |
| リポジトリとビルダープロジェクト | **GitHub**、**Bitbucket**、**Vercel**、**Bolt**、**Lovable**、**Base44**、および**以前の Agent エクスポート** |
| デザイン             | **Figma** および **Claude**                                                                    |
| ローカルファイルとデータ     | **ZIP** および**スプレッドシート**（`.xlsx`、`.csv`、または公開された Google Sheets の URL）                        |

一部のビルダーからのインポートでは、元のサービスからエクスポートされた GitHub リポジトリを使用します。インポートする前に、ソースごとのガイドを確認してください。設定、シークレット、データベースの値、またはプロバイダー固有のサービスは、後から追加の設定が必要になる場合があります。

プロンプト入力欄から**プラス**メニューを選び、**既存のプロジェクトをインポート**を選択するとインポートの流れが開きます。

## インポートか、添付か？

* 既存のコード、デザイン、または構造化されたプロジェクトの作業をもとに構築を続けたいときは**プロジェクトをインポート**します。
* ドキュメント、スプレッドシート、画像、スクリーンショットが現在の Conversation での質問やタスクのコンテキストになるときは**ファイルをアップロード**します。

後者については、[ファイルをアップロードして使用する](/ja/chat/upload-and-use-files)をご覧ください。
