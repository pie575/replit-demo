Model selector를 사용하면 Replit이 지능형 모델 라우팅으로 모델을 선택하도록 맡기거나, 사용 가능한 모델을 직접 고를 수 있습니다.

<div id="intelligent-model-routing">
  ## 지능형 모델 라우팅
</div>

지능형 모델 라우팅은 품질과 비용의 균형을 맞추면서 각 task에 적합한 모델을 선택합니다. 제품에 **Auto**라고 표시되어 있다면 Replit이 지능형 모델 라우팅을 수행하고 있다는 뜻입니다.

지능형 모델 라우팅은 요청한 작업과 그 복잡도를 함께 고려합니다. 범위가 좁은 요청에는 비용이 낮은 모델을 사용하고, 복잡한 작업에는 더 뛰어난 모델이 필요할 수 있습니다. 또한 task가 진행되면서 상황이 달라지면 Replit이 다른 모델을 선택할 수도 있습니다.

<Note>
  Free Mode는 항상 지능형 모델 라우팅을 사용합니다. Free Mode에서는 builder가 Model
  selector를 사용하거나 모델을 직접 선택할 수 없습니다.
</Note>

<div id="choose-a-model-manually">
  ## 모델 직접 선택하기
</div>

Core 및 Pro 요금제의 Builder는 Power Mode 또는 Max Mode에서 사용 가능한 모델을 선택할 수 있습니다.

1. prompt box에서 **Agent Mode**를 선택합니다. 메뉴에 사용 가능한 모드인 **Free**, **Power**, **Max**가 표시됩니다.
2. **Power** 또는 **Max**를 선택한 다음 **Primary 모델** 섹션으로 이동합니다.
3. primary 모델 메뉴를 열고 목록에서 모델을 선택합니다.

<div id="effort">
  ## Effort
</div>

**Effort는 별도의 모드가 아니라 모델별 설정입니다.** 선택한 모델이 각 응답에 추론을 얼마나 사용할지를 **Low**부터 **Max**까지 조절합니다. 모델마다 권장 설정이 표시되며, 작업에 필요한 경우에만 수준을 높이면 됩니다.

<Frame caption="모델 목록 아래의 Effort 슬라이더가 Medium으로 설정된 모습입니다.">
  <img src="/assets/mirror/model-selector-effort-bcffb01239a8.png" alt="Claude Fable 5가 선택된 Primary 모델 목록과 일상적인 작업에 적합한 균형 잡힌 추론으로 설명된 Medium으로 설정된 Effort 슬라이더" width="984" height="832" data-path="images/replitai/model-selector-effort.png" />
</Frame>

각 수준의 설명을 참고해 선택하세요.

| Effort         | 사용 상황                                                         |
| -------------- | ------------------------------------------------------------- |
| **Low**        | 최소한의 추론으로 가장 빠른 응답. 속도가 가장 중요한 일상적이고 명확한 변경 작업에 적합합니다.        |
| **Medium**     | 일상적인 작업에 알맞은 균형 잡힌 추론. 권장 설정에 별다른 안내가 없다면 무난한 기본값입니다.         |
| **High**       | 여러 단계로 이루어진 기능이나 익숙하지 않은 영역처럼 더 복잡한 작업을 위한 깊이 있는 추론.          |
| **Extra High** | 대규모 리팩터링이나 까다로운 버그처럼 가장 어려운 문제를 위한 확장된 추론.                    |
| **Max**        | 최대 수준의 추론 깊이. 비용이 가장 크고 속도도 가장 느리며, 최상의 결과가 무엇보다 중요할 때 사용합니다. |

Effort를 높이면 Agent가 더 깊고 신중하게 추론하며 가장 뛰어난 프런티어 모델을 활용해 복잡한 작업의 결과를 개선합니다. 다만 Agent는 이러한 성능을 선별적으로 사용합니다. 매 실행마다가 아니라 요청이 실제로 어려울 때만 더 뛰어난 모델로 라우팅합니다.

<Tip>
  Agent는 가장 어려운 작업에서만 최고 성능의 모델을 사용하므로, Effort를 높이면
  까다로운 작업에서는 비용이 최대 약 2배까지 늘어날 수 있습니다. 반면 단순한
  작업에서는 비용이 거의 또는 전혀 늘지 않습니다. 복잡한 문제에는 수준을 높이고,
  일상적인 변경 작업에는 낮게 유지하세요.
</Tip>

<div id="compare-models">
  ## 모델 비교하기
</div>

**모델 비교**를 사용하면 다음 prompt를 여러 모델에서 한꺼번에 실행하므로, 어떤 모델이 적합할지 추측하는 대신 결과를 나란히 놓고 판단할 수 있습니다. 현재 베타 기능입니다.

이 기능을 켜려면 Agent modes popover 하단의 **Advanced settings**를 펼친 뒤 **Compare models**를 켜세요.

<Note>모델 비교는 Chat에서만 지원됩니다.</Note>

<Frame caption="Advanced settings 아래의 Compare models 토글.">
  <img src="/assets/mirror/compare-models-toggle-05429dc46d64.png" alt="Compare models Beta 토글이 꺼진 상태로 펼쳐진 Advanced settings. 다음 prompt로 최대 4개의 변형을 생성한다고 설명되어 있음" width="1110" height="344" data-path="images/replitai/compare-models-toggle.png" />
</Frame>

토글을 켜면 비교할 모델을 최대 **4개**까지 추가할 수 있습니다.

<Frame caption="비교 대상으로 선택된 네 개의 모델, 전송 버튼에 Compare 4가 표시됨.">
  <img src="/assets/mirror/compare-models-9f5bcecec727.png" alt="Compare models가 켜져 있고 제거 가능한 네 개의 모델 슬롯(Kimi K3, Claude Fable 5, Claude Opus 5, GPT-5.6 Sol)이 있는 Agent modes popover. 채팅 전송 버튼에는 Compare 4가 표시됨" width="1192" height="1930" data-path="images/replitai/compare-models.png" />
</Frame>

이렇게 하면 다음 prompt가 선택한 모델마다 한 번씩 실행되고, 모델별로 비교할 수 있는 변형이 하나씩 만들어집니다.

<Note>
  비교에 포함된 각 모델은 별도의 agent로 실행되며 credits를 사용하므로,
  Compare 4 실행에는 단일 실행 4회와 비슷한 비용이 듭니다.
</Note>

<div id="model-selection-in-build-and-design">
  ## Build과 Design의 모델 선택
</div>

Build과 Design은 모델 선택을 각각 따로 유지합니다. 이 페이지에서는 Agent 빌드에 사용할 모델을 선택하는 방법을 설명합니다. Design의 Model selector로 비주얼 디렉션을 탐색하려면 [다양한 모델로 탐색하기](/ko/design/explore-with-different-models)를 참조하세요.
