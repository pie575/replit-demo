以安全的方式构建和发布应用是双方的共同责任。Replit 负责 Replit Agent、平台以及运行客户工作负载的基础设施的安全。Replit 通过合理的控制措施和安全的默认配置来运营这些服务，并提供可用于保护应用和数据的工具。您则负责应用的内容，以及正确使用和配置 Replit 提供的工具。

这是一种有意为之的平衡。Replit 希望您能构建任何您能想到的产品，而这种自由也意味着某些决策由您自行作出。下表概述了 Replit 的共同责任模型，其结构参考了既有的云和 AI 共同责任模型 ([Microsoft AI SRM](https://learn.microsoft.com/en-us/azure/security/fundamentals/shared-responsibility-ai)、[CSA AICM](https://cloudsecurityalliance.org/artifacts/ai-controls-matrix)) ，并以 [ISO/IEC 42001](https://www.iso.org/standard/42001) 和 [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) 为基础：

<div id="how-responsibility-is-divided">
  ## 责任如何划分
</div>

表中的大多数条目遵循以下三种模式之一：

* **机制与配置。** Replit 提供各项控制措施：RBAC、可见性设置、MFA、SSO、数据驻留和保留策略。由你决定启用哪些功能，以及如何配置。
* **检测与修复。** Replit 监控平台，并呈现其能够发现的问题：存在漏洞的依赖项、滥用信号和平台异常。你负责监控并修复应用内部的问题，因为只有你知道在具体场景中“修复”意味着什么。
* **第一方与第三方。** 经 Replit 审核的 Skills、MCP 工具和 Connectors 由 Replit 负责审查。任何由你自行连接、安装或集成的内容，都需要由你负责审核、配置、轮换和撤销。

有几项完全由你负责：使用政策、访问控制、IP 审查、最终用户隐私声明以及应用层渗透测试。这些事项取决于只有你才掌握的具体背景。其他项目则由 Replit 负责：Replit 是构建和运行你的应用的平台。

这些模式刻意反复出现。在一个以自由构建任何内容为核心的平台上，这是划分责任唯一诚实的方式。

<div id="working-with-replit-agent">
  ## 使用 Replit Agent
</div>

您拥有 Agent 生成的代码，并对其负责。实际操作中，这意味着要养成以下习惯：

1. **发布前审查。** Agent 会生成可运行的代码，但“能运行”和“正确”是两回事。请阅读它编写的内容，尤其是涉及身份验证、数据处理以及任何跨越信任边界的部分。在迭代过程中，让 Agent 编写测试并解释其推理过程，是发现回归问题的好方法。
2. **不要在提示词中包含密钥。** 请使用 Secrets 功能和 Connectors。不要将 API 密钥、token 或凭据粘贴到 Chat 中：Agent 无需以明文形式获取这些信息即可使用它们，而粘贴这些信息会将受管理的密钥变成不受管理的密钥。
3. **说明您的业务逻辑和访问控制模型。** 告知 Replit Agent 哪些用户应能访问您应用的哪些功能。如果您的应用并不希望全世界所有人都能查看，请选择 Replit 的 私有 或 密码保护 Publishing 选项之一。
4. **审慎批准敏感操作。** 当 Agent 提议发布应用、修改密钥或发起出站调用时，是否进行人工介入由您决定。应将其视为真正的审查，而不是简单地点击通过。

<div id="compliance-and-incident-response">
  ## 合规与事件响应
</div>

您有责任遵守 [Replit 服务条款](https://replit.com/terms-of-service)，也有责任了解自身的合规及法律要求。如需了解 Replit 在合规方面提供和不提供的内容 (如 SOC 2 Type II、子处理方、认证等) ，请访问 [replit.com/security](https://replit.com/security)。

如果您发现 Replit 平台存在漏洞，请按照 Replit 的[负责任披露](https://en.wikipedia.org/wiki/Coordinated_vulnerability_disclosure)流程向 [security@replit.com](mailto:security@replit.com) 报告。如果您在自己构建的 App 中发现漏洞，则由您负责自行分诊。平台事件将依据 Replit 的事件响应政策处理；源自您的应用、数据或最终用户账户的事件，则由您负责主导处理。
