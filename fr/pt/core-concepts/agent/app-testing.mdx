App Testing permet à Agent de tester les applications qu’il crée dans un navigateur réel. Agent parcourt votre application comme le ferait un utilisateur réel, en cliquant sur les éléments et en vérifiant les fonctionnalités. Cette fonctionnalité d’auto-test permet de garantir le bon fonctionnement de votre application et aide Agent à détecter et à corriger automatiquement les problèmes.

</div>

Découvrez App Testing en action pendant que l’Agent navigue dans votre application :

Lorsque App Testing est activé, l’Agent décide périodiquement s’il doit effectuer des tests lorsqu’il estime que les modifications sont suffisamment importantes pour le justifier. L’Agent n’effectue pas de tests après 100 % des messages utilisateur, mais détermine intelligemment à quel moment les tests seraient les plus utiles.

<Note>
  Actuellement, App Testing est disponible pour les applications web JavaScript full stack et les applications web Python Streamlit.
</Note>

<div id="principais-benefcios">
  ### Principaux avantages
</div>

* **Autonomie étendue** : permet à Agent de travailler plus longtemps sans intervention humaine
* **Qualité accrue** : produit des applications avec moins d’erreurs en détectant et en résolvant les problèmes dès le début
* **Rentabilité** : évite des sessions de débogage supplémentaires en détectant les problèmes pendant le développement
* **Révision interactive** : fournit des relectures vidéo et une navigation section par section pour analyser les résultats en détail

<div id="o-processo-de-teste">
  ### Le processus de test
</div>

Lorsque l’Agent décide d’effectuer des tests, voici ce qui se passe :

1. **Aperçu du navigateur** : vous verrez un aperçu du navigateur dans le panneau de l’Agent
2. **Test visuel** : observez le curseur de l’Agent cliquer dans l’application pour en tester les fonctionnalités
3. **Simulation d’un utilisateur réel** : l’Agent navigue dans l’application comme le ferait un utilisateur réel, en saisissant des données simulées si nécessaire
4. **Analyse automatique** : l’Agent analyse les résultats des tests et identifie les éventuels problèmes
5. **Correction automatique** : l’Agent fournit un récapitulatif des tests et corrige automatiquement les problèmes détectés

<div id="principais-capacidades">
  ## Principales capacités
</div>

L’Agent teste intelligemment votre application en y naviguant comme le ferait un véritable utilisateur, notamment :

* **Validation de l’interface utilisateur** : boutons, formulaires, navigation et éléments visuels
* **Vérification des fonctionnalités** : fonctionnalités principales et parcours utilisateur
* **Tests d’intégration** : appels d’API, interactions avec la base de données et services tiers
* **Performances et accessibilité** : temps de chargement, réactivité et normes d’accessibilité

<div id="uso">
  ## Utilisation
</div>

App Testing se trouve dans les **Paramètres avancés** du menu déroulant des paramètres d’Agent, dans le champ de saisie du Chat. Activez-le lorsque vous utilisez le mode Economy ou Power. Le mode Lite laisse App Testing désactivé.

<Note>
  App Testing fait partie des capacités autonomes d’Agent. Découvrez les [optimisations de code](/fr/pt/core-concepts/agent/code-optimizations) et les autres [fonctionnalités d’Agent](/fr/pt/core-concepts/agent).
</Note>

<div id="assumir-controle">
  ## Prendre le contrôle
</div>

Il arrive que l’Agent rencontre un obstacle lors des tests et ait besoin de votre aide pour continuer. Le plus souvent, cela implique de vous connecter à un compte utilisateur, par exemple Gmail. Dans ce cas, l’Agent affichera un bouton « Démarrer la prise de contrôle ».

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="Interface de prise de contrôle d’App Testing affichant les boutons Passer et Démarrer la prise de contrôle, avec des instructions pour gérer les erreurs et les CAPTCHA" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

Cliquez sur « Démarrer la prise de contrôle » pour interagir avec l’aperçu de test, effectuer les étapes nécessaires, puis laisser l’Agent continuer. Vous pouvez également cliquer sur « Passer » pour passer cette étape, ce qui mettra fin à App Testing si l’Agent ne peut pas continuer sans votre aide. Si vous ne répondez pas dans les 10 minutes, l’Agent continuera comme si vous aviez cliqué sur « Passer ».

<div id="o-que-esperar">
  ### À quoi s’attendre
</div>

* **Option pour passer** : Utilisez le bouton permettant de passer les tests si nécessaire afin de poursuivre le développement.
* **Relecture vidéo interactive** : Après les tests, cliquez sur la vidéo pour revoir l’intégralité de la session de test.
* **Navigation par section** : Utilisez les curseurs en bas pour accéder à des sections spécifiques du test.

<div id="soluo-de-problemas">
  ## Dépannage
</div>

**Échecs inattendus des tests**

* Essayez de passer cette étape, puis de relancer le test
* Vérifiez si du contenu dynamique peut affecter la durée d’exécution des tests
* Vérifiez l’exactitude des scénarios de test

**Couverture de test manquante**

* Fournissez des descriptions plus détaillées des fonctionnalités de votre App
* Mentionnez explicitement les parcours utilisateur critiques à tester

**App Testing ne fonctionne pas ?**

* App Testing ne fonctionne actuellement qu’avec les applications web[*](#how-app-testing-works)

<div id="preos-e-uso">
  ## Tarifs et utilisation
</div>

App Testing est inclus dans le modèle de tarification d’Agent basé sur l’effort, avec des implications importantes en matière de coûts :

* **Selon l’utilisation** : les tests sont facturés en fonction de l’effort requis (les tests plus simples sont moins coûteux)
* **Coût et avantages** : bien que les tests aient un coût, ils peuvent générer des économies en évitant des prompts supplémentaires et du travail additionnel pour Agent, grâce à une détection plus précoce des erreurs
* **Développement efficace** : l’approche automatisée réduit le besoin de débogage manuel et de retouches

<Tip>
  **Tests économiques** : bien qu’App Testing augmente vos coûts d’utilisation, il permet généralement de réaliser des économies globales en évitant des sessions supplémentaires avec Agent pour corriger des problèmes qui auraient pu être détectés lors des tests.
</Tip>
