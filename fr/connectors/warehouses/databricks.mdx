Les connecteurs Databricks permettent à Replit Agent d’interroger votre espace de travail Databricks. Les créateurs peuvent créer des tableaux de bord, des outils de reporting et des applications de données en langage naturel. Aucune expertise en SQL n’est requise.

Replit prend en charge deux types de connexion à Databricks. Choisissez celui qui convient en fonction de l’identité devant exécuter chaque requête.

<div id="choose-a-connection-type">
  ## Choisir un type de connexion
</div>

|                                     | **Utilisateur-à-machine (U2M)**                               | **Principal de service (M2M)**                    |
| ----------------------------------- | ------------------------------------------------------------- | ------------------------------------------------- |
| Nom du connector dans Replit        | Databricks pour les Databricks Apps (U2M)                     | Databricks (principal de service)                 |
| Identité utilisée pour les requêtes | Le créateur concerné                                          | Un principal de service partagé                   |
| Autorisations Databricks            | Les autorisations Unity Catalog de chaque créateur            | Les autorisations du principal de service         |
| Attribution de l’audit              | Le créateur ayant exécuté la requête                          | Le principal de service                           |
| Connexion du créateur               | Chaque créateur se connecte avec son propre compte Databricks | Aucune connexion individuelle à Databricks        |
| Idéal pour                          | Des autorisations par utilisateur et l’attribution de l’audit | Un accès partagé et des workflows non interactifs |

<div id="set-up-the-u2m-connector">
  ## Configurer le connector U2M
</div>

La configuration U2M implique trois rôles :

1. **Administrateur de compte Databricks** : crée une connexion d’application OAuth et fournit les informations relatives à SQL Warehouse.
2. **Administrateur de l’organisation Replit** : configure le connector avec les identifiants OAuth.
3. **Builder** : se connecte à son compte Databricks et commence à créer.

<div id="u2m-prerequisites">
  ### Prérequis U2M
</div>

Avant de commencer, vérifiez que vous disposez des éléments suivants :

* Un **administrateur de compte** Databricks. Les connexions d’App se configurent dans la console de compte, et non dans les paramètres d’administration du workspace.
* Un administrateur de l’organisation Replit.
* Un compte Databricks pour chaque builder qui utilisera le connector.
* Un accès au Workspace pour chaque builder, y compris l’autorisation **Peut utiliser** pour le SQL Warehouse et les autorisations Unity Catalog requises.

<div id="step-1-create-an-oauth-app-connection">
  ### Étape 1 : créer une connexion d&#39;application OAuth
</div>

<Note>Vous devez être administrateur du compte Databricks pour réaliser cette étape.</Note>

L&#39;administrateur du compte Databricks enregistre Replit en tant qu&#39;application OAuth. La connexion d&#39;application fournit le Client ID et le Client Secret utilisés pour configurer Replit.

<Steps>
  <Step title="Ouvrir la console de compte Databricks">
    Dans votre workspace Databricks, ouvrez le sélecteur de workspace en haut à droite et sélectionnez **Manage account**.

    <Frame>
      <img src="/assets/mirror/manage-account-6374ed6bf0f2.png" alt="Sélecteur de workspace Databricks ouvert avec l'option Manage account visible" width="2000" height="1144" data-path="images/connectors/databricks/u2m/manage-account.png" />
    </Frame>
  </Step>

  <Step title="Ouvrir App connections">
    Dans la console de compte, sélectionnez **Settings**, puis ouvrez l&#39;onglet **App connections**.

    <Frame>
      <img src="/assets/mirror/app-connections-96228e7f0f2e.png" alt="Page Settings du compte Databricks avec l'onglet App connections sélectionné et le bouton Add connection visible" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-connections.png" />
    </Frame>
  </Step>

  <Step title="Configurer la connexion Replit">
    Sélectionnez **Add connection**. Saisissez un nom d&#39;application identifiant Replit, par exemple `replit-u2m`.

    Sous **Redirect URLs**, saisissez :

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    Sous **Access scopes**, sélectionnez **All APIs**. Agent peut ainsi utiliser Databricks SQL et les API Databricks nécessaires pour créer et gérer des Databricks Apps.

    Sélectionnez **Generate a client secret**. Databricks ne peut pas ajouter de secret à une connexion déjà créée.

    Définissez les durées de vie des jetons conformément à la politique de sécurité de votre organisation. L&#39;exemple utilise un **Access token TTL** de `1440` minutes (24 heures) et un **Refresh token TTL** de `129600` minutes (90 jours), soit les valeurs maximales proposées par Databricks. Une durée de vie du refresh token plus courte peut obliger les créateurs à se reconnecter plus souvent.

    Sélectionnez **Add**.

    <Warning>
      **All APIs** accorde un accès plus large que SQL seul. Contrôlez l&#39;accès effectif du connector via les permissions Databricks de chaque créateur.
    </Warning>

    <Frame>
      <img src="/assets/mirror/app-configuration-6799b5769326.png" alt="Formulaire Add connection de Databricks configuré avec un nom d'application Replit, une URL de redirection, l'accès All APIs, la génération d'un client secret et les durées de vie des jetons" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-configuration.png" />
    </Frame>
  </Step>

  <Step title="Conserver les identifiants OAuth">
    Copiez le **Client ID** et le **Client Secret**, puis conservez-les dans le gestionnaire de secrets de votre organisation.

    <Warning>
      Databricks n&#39;affiche le client secret qu&#39;une seule fois. Notez sa date d&#39;expiration et effectuez la rotation de la connexion d&#39;application avant que le secret n&#39;expire.
    </Warning>

    <Frame>
      <img src="/assets/mirror/oauth-credentials-15b2e6c67309.png" alt="Boîte de dialogue Connection created de Databricks avec le client ID et le client secret masqués, ainsi que l'avertissement de secret unique et la date d'expiration" width="2000" height="1144" data-path="images/connectors/databricks/u2m/oauth-credentials.png" />
    </Frame>
  </Step>
</Steps>

<Note>
  Les connexions d&#39;application OAuth nouvelles ou mises à jour peuvent mettre jusqu&#39;à 30 minutes avant d&#39;être
  disponibles.
</Note>

<div id="step-2-share-the-sql-warehouse-details">
  ### Étape 2 : Partager les informations de l’entrepôt SQL
</div>

Chaque créateur renseigne les informations de l’entrepôt SQL lors de l’autorisation du connector U2M. Mettez ces valeurs à la disposition de vos créateurs, par exemple sur une page d’intégration interne.

<Steps>
  <Step title="Ouvrir les entrepôts SQL">
    Dans le workspace Databricks, sélectionnez **SQL Warehouses**, puis ouvrez l’entrepôt que les créateurs doivent utiliser.

    <Frame>
      <img src="/assets/mirror/sql-warehouses-cc178d18a33b.png" alt="Page Databricks SQL Warehouses affichant les entrepôts disponibles" width="3438" height="1984" data-path="images/connectors/databricks/sql-warehouses.png" />
    </Frame>
  </Step>

  <Step title="Copier les informations de connexion">
    Sélectionnez **Connection details**, puis copiez le **Server hostname** et le **HTTP path**.

    <Frame>
      <img src="/assets/mirror/connection-details-938b970b98e6.png" alt="Page des informations de connexion d’un entrepôt SQL Databricks avec le nom d’hôte du serveur et le chemin HTTP" width="3438" height="1984" data-path="images/connectors/databricks/connection-details.png" />
    </Frame>
  </Step>
</Steps>

<div id="step-3-enable-u2m-in-replit">
  ### Étape 3 : Activer U2M dans Replit
</div>

<Note>Vous devez être administrateur d&#39;une organisation Replit pour configurer des connecteurs.</Note>

<Steps>
  <Step title="Ouvrir et activer le connecteur U2M">
    Depuis l&#39;accueil de votre compte Replit, ouvrez **paramètres**, puis **Intégrations**. Recherchez `Databricks U2M`, trouvez **Databricks pour les Databricks Apps (U2M)**, puis sélectionnez **Activer**.

    Saisissez le **Client ID** et le **Client Secret** de la connexion à l&#39;application Databricks.

    Vérifiez que l&#39;URL de redirection affichée dans Replit correspond à l&#39;URL configurée dans Databricks :

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    Dans **Portées du connecteur**, activez `all-apis` et `offline_access`. La portée `offline_access` fournit à Replit un jeton d&#39;actualisation pour les sessions longue durée.

    Sélectionnez **Configurer**.

    <Frame>
      <img src="/assets/mirror/enable-connector-39c1eeebd230.png" alt="Paramètres d'Intégrations Replit filtrés sur Databricks U2M, avec le panneau d'activation affichant l'URL de redirection, les champs d'identifiants OAuth et les portées du connecteur" width="2000" height="1144" data-path="images/connectors/databricks/u2m/enable-connector.png" />
    </Frame>
  </Step>

  <Step title="Vérifier que le connecteur est activé">
    Vérifiez que **Databricks pour les Databricks Apps (U2M)** apparaît sous **Vos intégrations**.
  </Step>
</Steps>

<div id="step-4-sign-in-as-a-builder">
  ### Étape 4 : Se connecter en tant que créateur
</div>

Chaque créateur se connecte avec son propre compte Databricks avant d’utiliser le connecteur. Replit peut actualiser la session jusqu’à l’expiration du jeton d’actualisation.

<Steps>
  <Step title="Se connecter au connecteur">
    Sur la page **Intégrations**, recherchez **Databricks for Databricks Apps (U2M)** et sélectionnez **Sign in**. Vérifiez les informations de connexion, puis sélectionnez **Continue to Databricks for Databricks Apps**.

    <Frame>
      <img src="/assets/mirror/connect-modal-8ae2c2569658.png" alt="Fenêtre modale Connect Databricks for Databricks Apps expliquant la redirection, la confidentialité et les contrôles des autorisations" width="2000" height="1144" data-path="images/connectors/databricks/u2m/connect-modal.png" />
    </Frame>
  </Step>

  <Step title="Saisir les informations de SQL Warehouse">
    Saisissez le **chemin HTTP** de SQL Warehouse fourni par votre administrateur Databricks, puis sélectionnez **Next**.

    <Frame>
      <img src="/assets/mirror/http-path-9e8a8a14b6ab.png" alt="Boîte de dialogue Connect Databricks for Databricks Apps demandant le chemin HTTP de SQL Warehouse à l’étape 1 sur 2" width="2000" height="1144" data-path="images/connectors/databricks/u2m/http-path.png" />
    </Frame>

    Replit vous demande ensuite le **nom d’hôte du serveur** SQL Warehouse. Saisissez-le, puis poursuivez dans Databricks. Connectez-vous lorsque vous y êtes invité, vérifiez les accès demandés et approuvez la demande.

    Chaque requête exécutée par Agent via cette connexion utilise vos autorisations Databricks et vous est attribuée dans les logs d’audit Databricks.

    Après approbation, Databricks vous redirige vers Replit et le connecteur est prêt à l’emploi.
  </Step>
</Steps>

<div id="set-up-the-service-principal-connector">
  ## Configurer le connector de principal de service
</div>

La configuration du principal de service implique trois rôles :

1. **Administrateur Databricks** : crée le principal de service et lui accorde des autorisations dans Databricks.
2. **Administrateur de l’Organization Replit** : configure le connector et les accès dans Replit.
3. **Builder** : commence à créer à l’aide de l’identité Databricks partagée.

<div id="service-principal-prerequisites">
  ### Prérequis du principal de service
</div>

Avant de commencer, vérifiez que vous disposez des éléments suivants :

* d’un accès administrateur de compte Databricks ou administrateur de workspace.
* d’un accès administrateur de l’organisation Replit.

<div id="step-1-create-a-service-principal-in-databricks">
  ### Étape 1 : Créer un principal de service dans Databricks
</div>

<Note>
  Vous devez être administrateur de compte Databricks ou administrateur de workspace pour effectuer cette étape.
</Note>

L’administrateur Databricks crée une identité machine à machine, appelée [principal de service](https://docs.databricks.com/aws/en/admin/users-groups/service-principals), que Replit utilise pour se connecter à Databricks.

<Steps>
  <Step title="Ouvrir les paramètres">
    Dans Databricks, sélectionnez votre avatar dans l’angle supérieur droit, puis sélectionnez **Paramètres**.

    <Frame>
      <img src="/assets/mirror/settings-menu-8f2dcd4dbee3.png" alt="Menu du workspace Databricks avec Paramètres sélectionné" width="3438" height="1984" data-path="images/connectors/databricks/settings-menu.png" />
    </Frame>
  </Step>

  <Step title="Sélectionner Identité et accès">
    Dans la barre latérale des paramètres, sélectionnez **Identité et accès**.

    <Frame>
      <img src="/assets/mirror/settings-page-2a8bcd7c22a4.png" alt="Page Paramètres de Databricks avec Identité et accès dans la barre latérale" width="3438" height="1984" data-path="images/connectors/databricks/settings-page.png" />
    </Frame>
  </Step>

  <Step title="Gérer les principaux de service">
    Sous **Gestion et autorisations**, recherchez **Principaux de service** et sélectionnez **Gérer**.

    <Frame>
      <img src="/assets/mirror/identity-and-access-0e79404ed30f.png" alt="Page des paramètres Identité et accès affichant le bouton Gérer des principaux de service" width="3438" height="1984" data-path="images/connectors/databricks/identity-and-access.png" />
    </Frame>
  </Step>

  <Step title="Ajouter un principal de service">
    Sélectionnez **Ajouter un principal de service**, puis sélectionnez **Ajouter nouveau**.

    <Frame>
      <img src="/assets/mirror/add-service-principal-ac5b52f21f4c.png" alt="Boîte de dialogue Ajouter un principal de service avec le bouton Ajouter nouveau" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal.png" />
    </Frame>
  </Step>

  <Step title="Nommer le principal de service">
    Saisissez un nom explicite pour le principal de service, puis sélectionnez **Ajouter**.

    <Frame>
      <img src="/assets/mirror/add-service-principal-name-897df9e5f7ac.png" alt="Boîte de dialogue Ajouter un principal de service avec un nom de principal de service saisi" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal-name.png" />
    </Frame>
  </Step>

  <Step title="Confirmer les détails du principal de service">
    Une fois le principal de service créé par Databricks, vérifiez qu’il est actif. Gardez cette page ouverte si vous avez besoin des informations sur le principal de service lors de la configuration du connecteur Replit.

    <Frame>
      <img src="/assets/mirror/service-principal-details-15a381d388bc.png" alt="Page des détails d’un principal de service Databricks" width="3438" height="1984" data-path="images/connectors/databricks/service-principal-details.png" />
    </Frame>
  </Step>

  <Step title="Accorder l’accès">
    Ouvrez l’onglet **Autorisations**, sélectionnez **Accorder l’accès**, choisissez le principal de service, définissez l’autorisation sur **Gérer**, puis sélectionnez **Enregistrer**.

    <Frame>
      <img src="/assets/mirror/grant-access-edbaa2541a7d.png" alt="Boîte de dialogue Accorder l’accès pour un principal de service Databricks avec l’autorisation Gérer sélectionnée" width="3438" height="1984" data-path="images/connectors/databricks/grant-access.png" />
    </Frame>
  </Step>
</Steps>

<div id="step-3-create-the-databricks-connector-in-replit">

</div>

  <Step title="Accéder à Intégrations">

    <Frame>
      <img src="/assets/mirror/connector-http-path-5c8ae35516f8.png" alt="Étape 1 sur 2 de la boîte de dialogue Connect Databricks demandant le chemin HTTP du SQL Warehouse" width="3436" height="1978" data-path="images/connectors/databricks/connector-http-path.png" />

  <Step title="Saisir le nom d'hôte du serveur SQL Warehouse">

    <Frame>
      <img src="/assets/mirror/connector-server-hostname-b97fb74713f1.png" alt="Étape 2 sur 2 de la boîte de dialogue Connect Databricks demandant le nom d'hôte du serveur SQL Warehouse" width="3436" height="1978" data-path="images/connectors/databricks/connector-server-hostname.png" />
    </Frame>
  </Step>

  <Step title="Configurer l'accès">

  <Step title="Vérifier que le connecteur est actif">
    De retour sur la page **Intégrations**, vérifiez que **Databricks (Service Principal)** apparaît sous **Connectors** avec le statut de connexion **Active**.

    <Frame>
      <img src="/assets/mirror/integrations-page-d3e1d6b88376.png" alt="Page Intégrations de Replit affichant le connecteur Databricks (Service Principal) avec le statut de connexion Active" width="1680" height="1199" data-path="images/connectors/databricks/integrations-page.png" />
    </Frame>
  </Step>
</Steps>

<div id="build-with-agent">
  ## Créer avec Agent
</div>

Après vous être connecté par l’une ou l’autre méthode, vous pouvez créer avec Agent des applications qui utilisent les données Databricks.

<Steps>
  <Step title="Sélectionner le template Databricks App pour le déploiement">
    Sélectionnez le template **Databricks App** si vous souhaitez déployer l’application finalisée dans votre environnement Databricks. Ce template n’est pas nécessaire pour utiliser un connector configuré afin d’accéder aux données et ressources Databricks.

    Depuis la page d’accueil de Replit, ouvrez le sélecteur de templates et choisissez **Databricks App**.

    <Frame>
      <img src="/assets/mirror/databricks-template-cdfbbba1a2ab.png" alt="Page d’accueil de Replit avec le template Databricks App sélectionné au-dessus du champ de prompt" width="1200" height="400" data-path="images/connectors/databricks/u2m/databricks-template.png" />
    </Frame>
  </Step>

  <Step title="Décrire votre application">
    Ajoutez votre prompt après les instructions préremplies. Pour vous inspirer, consultez les [templates du Databricks Dev Hub](https://www.databricks.com/devhub/templates).
  </Step>

  <Step title="Examiner et itérer">
    Examinez le code SQL généré par Agent, les tables qu’il interroge et la structure de l’application. Demandez des modifications en langage naturel.
  </Step>
</Steps>

<div id="troubleshooting">
  ## Dépannage
</div>

<AccordionGroup>
  <Accordion title="Les requêtes renvoient des résultats vides">
    Vérifiez les autorisations Databricks de l&#39;identité qui exécute la requête. Avec
    le mode U2M, il s&#39;agit du créateur individuel. Avec le connector de principal de service,
    il s&#39;agit du principal de service partagé. L&#39;identité peut avoir accès aux métadonnées
    sans disposer d&#39;une autorisation de lecture sur les données. Accordez les autorisations requises au niveau du catalogue, du schema ou
    de la table, puis réessayez.
  </Accordion>

  <Accordion title="Le connector ne parvient pas à joindre le SQL Warehouse">
    Vérifiez que le **Server hostname** et le **HTTP path** correspondent aux informations de connexion
    du SQL Warehouse dans Databricks. Pour le mode U2M, contrôlez les valeurs saisies par le
    créateur concerné. Assurez-vous également que le warehouse est en cours d&#39;exécution et que l&#39;identité
    exécutant la requête est autorisée à l&#39;utiliser.
  </Accordion>

  <Accordion title="L'authentification échoue">
    Pour le mode U2M, vérifiez que la connexion d&#39;application Databricks comporte bien
    `https://replit.com/connectors/oauth/callback` sous **Redirect URLs**, sans
    barre oblique finale. Si l&#39;authentification échoue pour tous les créateurs, vérifiez le
    Client ID et le Client Secret partagés, assurez-vous que le secret n&#39;a pas expiré et
    que les portées définies dans Replit correspondent à celles de la connexion d&#39;application Databricks.

    Pour le connector de principal de service, vérifiez que les informations du principal de service
    saisies dans Replit correspondent au principal de service créé dans Databricks.
    Si les identifiants ont été renouvelés, mettez à jour le connector dans Replit.
  </Accordion>

    plus souvent que ne l&#39;exige votre politique de sécurité, examinez les durées de vie des
