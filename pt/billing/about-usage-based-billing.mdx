Existem três tipos de cobrança baseada em uso para publicação:

1. Transferência de Dados de Saída
2. Unidades de Computação com Autoescala
3. Requisições

Você pode ver seu uso em **Configurações** em **Conta** → **Uso da conta**. A cobrança ocorre mensalmente ou quando seus custos acumulados excedem seus créditos mensais. Usuários do Replit Core e Pro recebem cotas mensais para esses recursos.

Se você precisar de créditos adicionais além da sua cota de assinatura mensal, pode comprar pacotes de créditos na sua página de cobrança. Veja [Gerenciando Seus Gastos](/pt/billing/managing-spend) para mais informações sobre pacotes de créditos.

# Publicação

## 1. Transferência de Dados de Saída de Publicação

Este tipo de uso é cobrado por byte, com usuários do Replit Core e Pro recebendo cotas mensais. Apenas dados de egresso (saída) são contabilizados nessa cota, podendo gerar cobranças excedentes. Em contraste, dados de ingresso (entrada) são sempre gratuitos.

| Assinatura  | Cota                                                        |
| ----------- | ----------------------------------------------------------- |
| Replit Core | 100 GiB                                                     |
| Replit Pro  | Veja [preços do Replit Pro](https://www.replit.com/pricing) |

As cotas se aplicam a deployments [Estáticos](/pt/features/publishing/deployment-types#static), [com Autoescala](/pt/features/publishing/deployment-types#autoscale), [em VM Reservada](/pt/features/publishing/deployment-types#reserved-vm) e [Agendados](/pt/features/publishing/deployment-types#scheduled).

Veja a [página de preços](https://www.replit.com/pricing) para o preço atual da transferência de dados de saída.

***

## 2. Unidades de Computação

Os Deployments com Autoescala são cobrados com base em Unidades de Computação, que levam em conta tanto o uso de CPU quanto de RAM ao longo do tempo.

Os excessos são cobrados com base em Unidades de Computação. A granularidade da cobrança chega até cada unidade de computação individual. Veja a [página de preços](https://www.replit.com/pricing) para o preço atual das unidades de computação.

Veja abaixo como os segundos de RAM e CPU para um Deployment com Autoescala se traduzem em Unidades de Computação:

| Recurso          | Unidades de Computação |
| ---------------- | ---------------------- |
| 1 Segundo de RAM | 2 Unidades             |
| 1 Segundo de CPU | 18 Unidades            |

Os Deployments Estáticos não consomem Unidades de Computação. Sua cobrança é exclusivamente para Transferências de Dados de Saída além de um [valor especificado](#).

[Saiba mais sobre Deployments com Autoescala](/pt/features/publishing/deployment-types#autoscale).

***

## 3. Requisições

Os Deployments com Autoescala também consideram o número de requisições feitas.

Veja a [página de preços](https://www.replit.com/pricing) para o preço atual das requisições.

# Bancos de Dados

O Replit cobra apenas pelo uso de [bancos de dados de produção](/pt/features/data-and-storage/development-and-production) — bancos de dados de desenvolvimento são sempre gratuitos e incluídos em todos os Replit Apps. Para detalhes sobre bancos de dados de desenvolvimento, veja [Banco de Dados de Desenvolvimento](/pt/features/data-and-storage/sql-database).

O PostgreSQL do Replit é totalmente gerenciado e sem servidor, proporcionando alta disponibilidade sem esforço e zero manutenção. A cobrança para bancos de dados de produção é baseada no uso real, o que pode gerar economias significativas de custo.

Os bancos de dados PostgreSQL de produção são cobrados por duas métricas de uso:

* **[Tempo de Computação](#compute-time)**: A quantidade de recursos de computação consumidos por hora.
* **[Armazenamento de Dados](#data-storage)**: O volume total de dados (incluindo dados históricos) armazenados.

Você pode ver seu uso atual de recursos, incluindo o uso de banco de dados de produção, em **Configurações** → **Conta** → **Uso da conta**.

## Tempo de Computação

O tempo de computação é determinado pelo número de horas em que seu banco de dados permanece ativo durante um determinado período de cobrança. Os bancos de dados são considerados ativos quando recebem requisições e por um período adicional de 5 minutos após a última requisição. Se um banco de dados permanecer ocioso por 5 minutos, ele será suspenso e entrará em estado inativo.

## Armazenamento de Dados

O armazenamento de dados é o volume total de dados armazenados em todos os bancos de dados da sua conta, medido em gibibytes (GiB). O armazenamento é calculado como a quantidade máxima de armazenamento usada por mês. Cada banco de dados PostgreSQL consome 33 MB de armazenamento, mesmo que não contenha nenhum dado. Este é o espaço de armazenamento padrão do servidor Postgres.

<Note>O limite total de armazenamento para cada banco de dados de produção é de 10 gibibytes (GiB). Os bancos de dados de desenvolvimento incluem 20 GiB de armazenamento gratuito por Replit App.</Note>

# Notas Adicionais

Se houver um problema com seu método de pagamento, notificaremos você. Falhas contínuas de pagamento podem levar à suspensão dos seus apps publicados. Se isso acontecer, por favor [entre em contato com o suporte](https://replit.com/help) e atualize seus dados de pagamento para recuperar o acesso aos nossos serviços.
