Le Centre de sécurité du Workspace est disponible avec tous les forfaits. Utilisez-le pour analyser les [dépendances](/fr/ko/features/security/concepts#dependency) des projets de votre Workspace et examiner les constats de [CVE](/fr/ko/features/security/concepts#cve) par [gravité](/fr/ko/features/security/concepts#severity). Vous pouvez corriger les problèmes avec Replit Agent, [republier](/fr/ko/features/security/concepts#republish) les projets concernés et exporter des rapports Software Bill of Materials ([SBOM](/fr/ko/features/security/concepts#sbom)) à des fins de conformité.

<Note>
  Pour analyser un seul projet, ouvrez le [Centre de sécurité du projet](/fr/ko/features/security/project-security-center) depuis le panneau **Security** de ce projet.
</Note>

<Note>
  Vous découvrez la sécurité des dépendances ? Consultez les [concepts de sécurité](/fr/ko/features/security/concepts) pour connaître les définitions de CVE, SBOM, exposition, Fix with Agent, Republish et Auto-Protect.
</Note>

<div id="section">
  ## Fonctionnalités
</div>

<div id="cve">
  ### Détection des CVE
</div>

Vérifiez les vulnérabilités de tous les projets de votre workspace.

* Identifiez les projets vulnérables, classés par ordre de priorité selon leur [exposition](/fr/ko/features/security/concepts#exposure) (statut de publication et visibilité)
* Consultez, pour chaque constat, le nom et la version du package affecté, ainsi que le niveau de gravité (critical, high, medium, low)
* Consultez les instructions de correction pour chaque projet

</Frame>

<div id="section-2">
  ### Voir les projets concernés
</div>

Identifiez les projets présentant des vulnérabilités et déterminez les corrections à prioriser.

* Consultez une vue d’ensemble des projets vulnérables regroupés par niveau d’exposition : nombre total de projets, nombre de projets publiés et nombre de projets publiés publiquement
* Consultez les détails des projets Replit concernés
* Recherchez par ID CVE ou nom de projet, puis filtrez par gravité, propriétaire, état de publication (Published / Not published) et visibilité (Public / Private)
* Développez une ligne de projet pour consulter tous les constats CVE (gravité, package, version, ID CVE) sans quitter la page

<div id="fix-with-agent">
  ### Correction avec Agent et republication
</div>

Résolvez les vulnérabilités et redéployez sans quitter Security Center.

* Sélectionnez **[Fix with Agent](/fr/ko/features/security/concepts#fix-with-agent)** dans le projet concerné pour créer un correctif dans le cadre d’une tâche en arrière-plan. Examinez et appliquez les modifications générées avant de republier.
* Suivez l’état de la correction via **Tâche en cours**, **Appliquer les modifications**, **Republish**, puis l’état final **Republished** ou **Failed**.
* L’action **Republish** en un clic affiche une boîte de dialogue de confirmation, puis redéploie le build à l’aide de la configuration existante (après fusion des modifications).
* Effectuez des actions groupées, comme annuler la publication de projets ou avertir les propriétaires de projets des vulnérabilités.

<div id="sbom">
  ### Exporter des SBOM
</div>

Exportez des nomenclatures logicielles à des fins de conformité et d’audit.

* Téléchargez des SBOM dans des formats standard ([SPDX](/fr/ko/features/security/concepts#spdx-and-cyclonedx), [CycloneDX](/fr/ko/features/security/concepts#spdx-and-cyclonedx))
* Générez des rapports pour des projets individuels ou pour l’ensemble du workspace
* Consultez les SBOM regroupés par exécution d’analyse, avec l’horodatage, le nombre de projets et l’utilisateur ayant déclenché l’exécution
* Téléchargez tous les SBOM d’une exécution d’analyse dans un fichier ZIP unique
* Respectez les exigences de conformité en matière de transparence de la chaîne d’approvisionnement logicielle

<Note>
  Le téléchargement groupé de SBOM est disponible avec le plan Enterprise. Les workspaces bénéficiant d’autres plans peuvent consulter l’offre Enterprise dans la section SBOM.
</Note>

<div id="workspace-security-center">
  ## Accéder au Centre de sécurité du Workspace
</div>

Pour ouvrir le Centre de sécurité du Workspace :

1. Accédez à [replit.com](https://replit.com) et connectez-vous à votre compte.
2. Dans le menu de navigation à gauche de la page d’accueil, sélectionnez **Security**.

<div id="section-3">
  ## Analyser le workspace
</div>

<Frame>
  <img src="/assets/mirror/security-overview-b37f090f236c.png" alt="Page d’accueil du Centre de sécurité du Workspace affichant le nombre total d’analyses, le nombre total de vulnérabilités et les CVE regroupées par niveau de gravité" width="3438" height="1984" data-path="images/workspace-security-center/security-overview.png" />
</Frame>

1. Ouvrez le Centre de sécurité du Workspace.
2. Sélectionnez **Run security scan** pour lancer une analyse de l’ensemble du workspace.
3. Examinez les résultats classés par projet concerné, niveau de gravité et exposition du déploiement.
4. Dans chaque projet concerné, sélectionnez **Fix with Agent**, puis **Republish** une fois les corrections appliquées.

L’analyse examine les dépendances des projets Replit du workspace et affiche les vulnérabilités connues répertoriées dans les bases de données publiques de vulnérabilités.

<div id="auto-protect">
  ## Auto-Protect
</div>

Les administrateurs peuvent activer **[Auto-Protect](/fr/ko/features/security/concepts#auto-protect)** sur leur compte afin de surveiller en continu les CVE récemment publiées affectant les dépendances de tous les projets. Lorsqu’une correspondance est détectée, Replit Agent prépare un correctif testé, et le builder reçoit un e-mail contenant un lien direct pour l’appliquer.

Pour connaître le workflow complet et les étapes de configuration, y compris le seuil de gravité réservé aux administrateurs situé dans **Paramètres** &gt; **Compte** &gt; **Avancé**, consultez [Auto-Protect](/fr/ko/features/security/project-security-center#auto-protect).

<Note>
  Si vous avez besoin d’aide pour configurer le Centre de sécurité du Workspace ou intégrer des exportations de SBOM à vos workflows de conformité, contactez votre responsable de compte.
</Note>
