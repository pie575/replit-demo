发布会将项目变为公开应用。如果发布失败，或发布 URL 的运行方式与预览不同，请按步骤排查问题。

本页面既是 Build 恢复指南，也是部署故障排查参考。先从最简单的问题开始：应用能否在预览中正常运行？

<div id="section">
  ## 您将能够完成的操作
</div>

读完本页后，您将能够确定问题是否出在应用本身、发布设置、生产环境中的 Secrets、部署类型、端口设置或网络/DNS 访问。

<div id="section-2">
  ## 从 预览 开始
</div>

发布前，请确认应用能在项目编辑器中正常运行。

选择项目编辑器顶部的 **Run**，打开 预览。如果应用未通过 `replit.dev` URL 显示在 预览 中，请在发布前修复应用。

先请 Agent 诊断 预览：

<AiPrompt>
  此应用无法在 预览 中运行。<br />
  检查 Run 命令、依赖项安装、应用错误、端口和缺失的 Secrets。<br />
  请先修复最小的问题，并告诉我如何在发布前验证 预览 是否正常运行。
</AiPrompt>

如果 预览 无法正常运行，发布也无法解决问题。

<div id="section-3">
  ## 预览正常但发布失败
</div>

如果预览正常但发布失败，请检查发布相关的设置。

<div id="section-4">
  ### 检查日志
</div>

打开 **Publishing** 面板中的 **Logs** 标签页。查看是否有堆栈跟踪、缺少的软件包、命令执行失败、环境变量缺失或启动错误。

将相关错误粘贴给 Agent：

<AiPrompt>
  Publishing failed with this log output: [paste error].<br />
  Explain the likely cause.<br />
  Tell me whether this is a command, dependency, Secret, port, build, or app error.<br />
  Recommend the smallest fix and how I should verify it.
</AiPrompt>

<div id="section-5">
  ### 检查运行命令和构建命令
</div>

常见问题包括拼写错误、错误的标志、入口文件不正确，以及只能在本地运行的命令。

请在 **Publishing** 面板中检查这些命令。如果应用需要同时使用构建命令和启动命令，请确保两者都正确。

<div id="secrets">
  ### 检查生产环境中的 Secrets
</div>

在项目编辑器中设置的 Secrets 不会自动同步到已发布的应用。请在 **Publishing** 面板中添加生产环境所需的所有 Secrets 和环境变量。

缺少 Secrets 可能导致未定义值相关错误、API 调用失败、数据库连接失败、登录错误、支付失败等问题。

请参阅 [Secrets](/zh/ja/core-concepts/project-editor/app-setup/secrets)。

<div id="section-6">
  ### 确认长时间运行进程是否正常运行
</div>

已发布的应用要求程序持续运行。如果程序运行一次后即退出，平台会自动重启。

请确保应用会启动长时间运行的进程，例如 Web 服务器。

<div id="section-7">
  ### 检查主机和端口配置
</div>

如果应用正在运行 Web 服务器，Deployments 可以自动检测服务器使用的端口，但服务器必须监听 `0.0.0.0`。如果仅监听 `localhost` 或 `127.0.0.1`，已发布的应用将无法正常运行。

如果您在 [`.replit` 配置中指定了端口](/zh/ja/features/project-setup/configuration)，将禁用自动端口检测。要通过推广步骤，必须指定一个将 `externalPort` 设为 `80` 的端口。请确认服务器正在指定的 `localPort` 上监听。

让 Agent 进一步检查：

<AiPrompt>
  检查此应用是否已针对发布正确配置。<br />
  验证服务器会启动一个持续运行的进程、监听 0.0.0.0、使用预期端口，并与任何 .replit 端口配置相匹配。<br />
  除修复发布问题外，请勿更改应用行为。
</AiPrompt>

<div id="section-8">
  ### 检查健康检查时机
</div>

在将已发布的应用标记为在线前，Replit 会向应用发送 HTTP 请求。如果主页响应时间超过 5 秒，健康检查可能会超时，导致发布在最后一步失败。

如果应用启动较慢，请让 Agent 减少启动时的处理，将耗时较长的操作延后到用户执行操作后，或在适当位置缓存数据。

<div id="url">
  ## 发布成功但发布 URL 无法访问
</div>

如果应用在 预览 中运行正常且已成功发布，但发布 URL 无法访问，请对比 预览 与生产环境的行为。

检查以下事项：

* 生产环境中的 Secrets 和环境变量。
* 数据库连接设置。
* 登录回调或重定向 URL。
* 支付 Webhook 或重定向设置。
* API 允许列表或 CORS 设置。
* 写入本地文件系统而非数据库或存储服务的文件。
* 移动端布局与浏览器之间的差异。

请 Agent 帮助对比环境：

<AiPrompt>
  应用在 预览 中运行正常，但在发布 URL 上无法运行。<br />
  请帮我对比 预览 和生产环境的行为。<br />
  检查 Secrets、数据库设置、API 调用、登录重定向、支付重定向、构建输出和日志。<br />
  请告诉我下一步最安全的检查方式。
</AiPrompt>

<div id="section-9">
  ## 静态部署问题
</div>

静态部署会托管 HTML、CSS、JavaScript 等静态文件。

如果你的应用包含服务器端处理、API 路由、认证回调、由服务器发起的数据库调用或长时间运行的后端逻辑，则可能不适合使用静态部署。请改为在 **Publishing** 面板中将部署类型更改为 Autoscale。

静态部署问题通常是由于 public 目录配置错误，或为需要服务器的应用选择了 Static 所致。

<div id="section-10">
  ## 文件和大小限制
</div>

Reserved VM 和 Autoscale Deployments 支持最大 8 GB 的 Replit Apps。静态部署最多支持 1 GB。

如需减小应用大小，请删除不必要的文件，避免提交生成的输出文件，或为大型资源使用外部存储。

<Warning>
  已发布应用的文件系统并非持久存储，每次发布都会重置。要持久保存数据，请使用 [SQL Database](/zh/ja/features/data-and-storage/sql-database) 等数据库。
</Warning>

如果上传的文件或生成的数据在发布后消失，请将其保存到数据库或存储服务中，而不要保存到应用的文件系统中。

<div id="replitappreplitdev-url">
  ## 无法访问 `replit.app` 和 `replit.dev` URL
</div>

如果无法通过 `replit.app` 或 `replit.dev` 域名访问应用，可能是网络过滤或网络限制所致。

请尝试使用公共 DNS 解析器，例如 Google DNS (`8.8.8.8`) 或 Cloudflare DNS (`1.1.1.1`) 。

<div id="dns">
  ### 更改 DNS 设置
</div>

<Tabs>
  <Tab title="Windows">
    1. 打开**控制面板**。
    2. 前往**网络和共享中心**。
    3. 选择左侧的**更改适配器设置**。
    4. 右键点击当前使用的网络连接，然后选择**属性**。
    5. 选择**Internet 协议版本 4 (TCP/IPv4)**，然后点击**属性**。
    6. 选择**使用下面的 DNS 服务器地址**。
    7. 输入公共 DNS 服务器的 IP 地址，例如 Google DNS 的`8.8.8.8`或 Cloudflare DNS 的`1.1.1.1`。
    8. 选择**确定**以保存更改。

    有关详细步骤，请参阅 [Microsoft DNS 设置指南](https://support.microsoft.com/en-us/windows/change-tcp-ip-settings-bd0a07af-15f5-cd6a-363f-ca2b6f391ace)。
  </Tab>

  <Tab title="macOS">
    1. 打开**系统设置**。
    2. 选择**网络**。
    3. 在左侧选择当前使用的网络连接。
    4. 选择右下角的**详细信息**。
    5. 前往**DNS**标签页。
    6. 选择**+**按钮以添加 DNS 服务器。
    7. 输入公共 DNS 服务器的 IP 地址，例如 Google DNS 的`8.8.8.8`或 Cloudflare DNS 的`1.1.1.1`。
    8. 选择**确定**，然后点击**应用**。

    有关详细步骤，请参阅 [Apple DNS 设置指南](https://support.apple.com/guide/mac-help/change-dns-settings-on-mac-mh14127/mac)。
  </Tab>

  <Tab title="Linux">
    1. 编辑`/etc/resolv.conf`文件以添加公共 DNS 服务器。具体方法因发行版而异。
    2. 添加以下行：

    ```bash theme={null}
    nameserver 8.8.8.8
    nameserver 1.1.1.1
    ```

    有关不同发行版的 DNS 设置详情，请参阅 [Debian Wiki 网络配置指南](https://wiki.debian.org/NetworkConfiguration#Defining_the_.28DNS.29_Nameservers)。
  </Tab>
</Tabs>

<div id="dns-2">
  ### 清除 DNS 缓存
</div>

更改 DNS 设置后，请清除 DNS 缓存以使新设置生效：

* **Windows**：在命令提示符中运行 `ipconfig /flushdns`。
* **macOS 和 Linux**：在终端中运行 `sudo systemctl restart NetworkManager`。具体命令可能因所用发行版而异。

<Note>
  为提升所在地区的性能和稳定性，Replit Apps 的 `replit.dev`
  URL 可能会在集群迁移期间发生变化。迁移完成后，
  除非你明确请求更改位置，否则 URL 通常会在约一年内保持稳定。
</Note>

<div id="streamlit">
  ## 发布 Streamlit 应用
</div>

Streamlit 应用可通过 Replit Deployments 运行。最简单的入门方式是使用 [Streamlit 模板](https://replit.com/@replit/Streamlit?v=1)。

或者，按如下方式设置用于发布的运行命令：

```bash theme={null}
streamlit run --server.address 0.0.0.0 --server.headless true --server.enableCORS=false --server.enableWebsocketCompression=false main.py
```

如果您的应用使用其他入口文件，请将`main.py`替换为相应的文件名。

  ## 完成检查
</div>

* 预览正常运行。
* 已完成发布。
* 发布 URL 可正常加载。
* 主应用流程可在发布 URL 上正常运行。
* 已配置生产环境的 Secrets 和相关设置。
* 日志中未发现隐藏的启动错误。
