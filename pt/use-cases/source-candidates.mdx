O Ashby já faz a triagem das candidaturas recebidas. Este fluxo é outbound: lê a descrição
da vaga no Drive, encontra engenheiros compatíveis no GitHub, pula quem já está no Ashby e
redige uma abordagem para você enviar. O Agent registra as pessoas novas como buscadas com
um breve motivo do encaixe e um rascunho no candidato. Você revisa e envia. Não use isso
como a única decisão de contratação.

## Ideal para

* Recrutadores técnicos que precisam de uma lista buscada quando o volume de candidaturas recebidas é baixo demais.
* Gerentes de contratação que precisam de engenheiros compatíveis no GitHub sem passar o dia inteiro pesquisando.

## Antes de começar

Tenha uma descrição de vaga com requisitos obrigatórios vs. desejáveis. Conecte o Drive, o
GitHub e o Ashby. Diga a localização, a senioridade e quantos nomes você quer. Não use isso
como a única decisão de contratação.

## Dê o prompt ao agente

<AiPrompt>
  Crie uma rotina que rode toda segunda-feira às 9h. A partir desta descrição
  de vaga \[link do Drive ou cole o texto], encontre 30 engenheiros no GitHub
  que atendam aos requisitos obrigatórios. Pule quem já está no Ashby. Para
  cada pessoa, escreva um motivo do encaixe em 3 linhas e um breve rascunho de
  abordagem. Não envie nada. Adicione as pessoas novas ao Ashby como buscadas,
  com a nota e o rascunho no candidato.
</AiPrompt>

## O que esperar

O Agent lê a descrição da vaga, pesquisa no GitHub, pula quem já está no Ashby e retorna uma
lista com rascunhos. Você revisa e envia. A primeira passada será barulhenta. Ajuste os
requisitos obrigatórios depois de ver o resultado. Abra três perfis do GitHub da lista,
confira se atendem aos requisitos obrigatórios e confirme que essas pessoas ainda não estão
no Ashby antes de enviar qualquer coisa.

## Solução de problemas

* **A lista está barulhenta:** ajuste os requisitos obrigatórios vs. desejáveis depois da primeira passada. Peça commits recentes em uma linguagem ou tipo de repositório específico, e descarte quem parecer ser cliente atual ou funcionário de um concorrente.
* **Pessoas que já estão no Ashby continuam aparecendo:** confirme que o Ashby está conectado ao workspace certo e que o Agent está comparando por e-mail ou nome de usuário do GitHub, não só pelo nome de exibição.
* **A abordagem foi enviada:** este fluxo deveria apenas rascunhar. Se algo foi enviado, pare a rotina e diga ao Agent para nunca enviar e-mail ou mensagem a candidatos.
