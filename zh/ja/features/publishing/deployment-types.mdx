---
title: "部署类型"
description: "比较 Autoscale、Static、Reserved VM 和 定时部署，了解如何为要发布的应用选择合适的类型。"
---

部署类型是 Replit 用于发布应用的技术方案。你可以在 Publishing 工具的 **调整设置** 中，通过 **Deployment type** 下拉菜单选择部署类型。**Autoscale** 是默认且推荐的选项，大多数构建者无需更改。

<div id="section">
  ## 比较部署类型
</div>

| 类型              | 最适合的用途             | 运行方式              | 计费方式         |
| :-------------- | :----------------- | :---------------- | :----------- |
| **Autoscale**   | 流量波动的 Web 应用和 API  | 繁忙时增加服务器，空闲时缩减至零  | 仅在处理请求时计费    |
| **Static**      | 落地页、作品集和文档网站       | 从缓存的云服务器提供文件，无需后端 | 仅按网站提供的数据量计费 |
| **Reserved VM** | 机器人、后台任务和持续运行的 API | 一台不会休眠的专用服务器      | 固定月度费用       |
| **Scheduled**   | 备份和通知等定期任务         | 按计划运行命令，随后停止      | 按运行时间计费      |

<div id="autoscale">
  ## Autoscale
</div>

Autoscale 部署运行在可根据应用流量自动扩缩容的服务器上。应用繁忙时，Replit 会添加服务器以应对负载。应用空闲时，服务器数量会减少，最低可降至零，因此没有访问时不会产生费用。

最适合用于：

* 流量波动较大的 Web 应用，例如电商网站
* API 和服务

在 **调整设置** 中配置：[机器性能和最大服务器数量](/zh/ja/features/publishing/machine-configuration)。

<div id="static">
  ## Static
</div>

Static 部署会将 HTML、CSS、JavaScript 等 App 文件托管在云服务器上，并利用缓存快速、经济地交付内容。不需要后端服务器。

最适合用于：

* 营销落地页
* 作品集网站
* 产品或 API 文档网站

<Note>
  Static 部署与使用 Agent 创建的 Replit App 不兼容。Agent 会构建需要后端服务器的全栈 App，因此请使用 Autoscale 或 Reserved VM。
</Note>

配置包括要提供服务的公开目录以及可选的构建命令。有关响应标头、URL 重写和重定向的信息，请参阅 [Static 高级设置](/zh/ja/features/deployment-customization/static-deployments-advanced)。

<div id="reserved-vm">
  ## Reserved VM
</div>

Reserved VM 部署会在永不休眠的专用虚拟机上运行应用。它能提供稳定的性能以及可预测的固定月度成本。

最适合用于：

* 内存占用较高的后台任务
* 需要持续保持连接的聊天机器人
* 持续运行的 API 服务器

配置包括[机器性能](/zh/ja/features/publishing/machine-configuration)、构建命令和运行命令、端口映射，以及将应用作为 Web 服务器还是后台工作器运行。

<div id="scheduled">
  ## 定时
</div>

定时部署会在应用环境中按计划执行命令，并在下次运行前停止。你可以用“每个工作日上午 9 点”之类的自然语言描述计划，Replit 会自动将其转换为计划。如果运行失败，你会收到警报。

最适合用于：

* 状态检查和运行状况报告
* 发送通知
* 启动备份

配置包括计划、任务超时、构建命令和运行命令。定时部署不会提供网页，因此没有公开 URL。
