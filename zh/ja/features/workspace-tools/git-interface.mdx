Replit 的 Git 窗格提供用于执行 Git 操作的可视化界面，无需使用命令行 Git 命令。该功能让初学者也能轻松使用版本控制，同时为经验丰富的开发者提供强大的功能。

<div id="section">
  ## 功能
</div>

Git 窗格在 Project Editor 中直接提供全面的版本控制功能，并通过易用的界面简化复杂的 Git 操作。

* **仓库管理**：通过 GitHub 集成初始化、连接和管理 Git 仓库
* **提交跟踪**：暂存、提交和查看所有文件的更改
* **分支操作**：以可视化方式创建、切换和合并分支
* **冲突解决**：以可视化方式识别和解决合并冲突
* **Shell 集成**：同步 Shell 中执行的 Git 命令与 Git 窗格

<div id="section-2">
  ## 使用方法
</div>

<div id="section-3">
  ### 设置仓库
</div>

<Accordion title="访问 Git 窗格的方法">
  1. 前往 Replit App 的 Tools 区域
  2. 选择 **+** 图标以添加新工具
  3. 从可用工具列表中选择 **Git**
</Accordion>

Git 窗格可帮助你设置和连接仓库：

* **初始化仓库**：为 Replit App 创建新的 Git 仓库
* **连接 Git 提供商**：将仓库关联到受支持的托管或自托管提供商，以便备份和协作
* **配置远程仓库**：设置和管理与远程仓库的连接

<Note>
  **自托管 Git 支持**：Replit 在 Enterprise 计划中支持 GitHub Enterprise Server、GitLab Self-Managed 和 Bitbucket Data Center。如需部署指导或获取设置和连接错误方面的支持，请[联系 Replit Sales](https://replit.com/enterprise)。你也可以[在 Shell 中使用 git 命令配置远程仓库](#using-git-commands-in-shell)。
</Note>

<div id="section-4">
  ### 变更管理
</div>

<Accordion title="如何查看变更">
  1. 修改 Replit App 中的任意文件
  2. 在 Tools 部分打开 Git 窗格
  3. 在 **Review Changes** 部分查看变更
</Accordion>

Git 窗格提供了管理代码变更的工具：

* **查看变更**：查看高亮显示新增和删除内容的已修改文件
* **暂存文件**：选择要纳入下一次提交的特定文件
* **提交变更**：使用描述性消息保存变更
* **推送更新**：一键将提交推送到 GitHub

<div id="section-5">
  ### 分支管理
</div>

<Accordion title="管理分支">
  1. 在 Tools 区域中打开 Git 窗格
  2. 选择分支名称旁的分支下拉菜单
  3. 创建新分支或选择现有分支
</Accordion>

Git 窗格可让你轻松管理多个版本的代码：

* **创建分支**: 创建新分支，以便独立开发功能
* **切换分支**: 在不同版本的代码之间切换
* **发布分支**: 将分支发布到 GitHub
* **拉取更改**: 同步协作者推送的远程更新

<div id="section-6">
  ### 解决合并冲突
</div>

<Accordion title="如何解决合并冲突">
  1. 在存在冲突时尝试拉取更改
  2. Git 窗格会高亮显示发生冲突的文件
  3. 打开每个冲突文件，查看并解决冲突
  4. 解决冲突后保存文件
  5. 选择 **Pull** 完成合并
</Accordion>

当来自不同来源的代码发生冲突时，Git 窗格支持以下操作：

* **识别冲突**：准确显示哪些文件存在冲突
* **查看差异对比**：查看冲突代码的两个版本
* **解决问题**：选择要保留的代码，或手动编辑冲突内容
* **完成合并**：解决冲突后完成合并流程

解决冲突文件后，删除以冲突符号开头的行以移除冲突标记，然后保存文件。

<div id="shellgit">
  ### 在 Shell 中使用 Git 命令
</div>

<Accordion title="访问 Shell 的方法">
  1. 在左侧工具栏中选择 **All tools**
  2. 从可用工具中选择 **Shell**
</Accordion>

<Tip>
  Git 窗格提供了易用的界面，而高级用户也可以在 Shell 中使用标准 Git 命令执行更复杂的操作。无论通过哪种方式进行更改，都会在两处同步显示。
</Tip>

如果你希望通过命令行使用 Git：

* **命令同步**：在 Shell 中执行 Git 命令会自动同步到 Git 窗格
* **完整的 Git 功能**：可使用 Git 窗格中未提供的高级 Git 功能
* **无缝切换**：可根据需要在 Shell 命令和 Git 窗格之间切换

<Info>
  **支持 GitHub CLI 和 GitLab CLI**：除标准 Git 命令外，你还可以在 Shell 中使用 [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) 或 [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) 管理和连接外部 Git 仓库。这些工具增强了你与 GitHub 和 GitLab 仓库的协作能力，包括处理拉取请求、Issues 及其他平台特有功能。
</Info>

<div id="section-7">
  #### 仓库操作
</div>

* **克隆仓库**: `git clone <url-to-repository>`
* **初始化仓库**: `git init`
* **添加远程仓库**: `git remote add origin <url-to-repository>`

<div id="section-8">
  #### 进行更改
</div>

* **检查状态**: `git status` (显示已修改、添加或删除的文件) 
* **暂存文件**: `git add <filename>` 或 `git add .` (暂存所有文件) 
* **提交更改**: `git commit -m "your commit message"`
* **推送更改**: `git push origin <branch-name>`
* **拉取更改**: `git pull origin <branch-name>`

<div id="section-9">
  #### 认证
</div>

操作私有仓库时需要进行认证：

* 对于 GitHub.com 仓库，请使用个人访问令牌代替密码
* 为避免重复输入凭据，您可以使用 Replit Secrets 保存凭据：
  1. 创建一个键为 `GIT_URL` 的新 Secrets
  2. 将其值设置为 `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. 使用 `git push $GIT_URL` 推送，无需输入凭据

<Note>
  如果将凭据存储在 Secrets 中，任何能够访问您的 Replit App 的人都可能访问您的 Git 凭据。对于高度敏感的仓库，请考虑每次手动输入凭据。
</Note>
