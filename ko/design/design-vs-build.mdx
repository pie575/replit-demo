모든 Replit project에는 헤더에 나란히 놓인 두 개의 진입점이 있습니다. 바로 **Design**과 **Build**입니다. Design은 소프트웨어의 겉모습을 다듬는 곳이고, Build는 Agent가 그것을 실제로 동작하게 만드는 곳입니다. 둘 다 같은 project를 열기 때문에, 디자인한 결과물이 디자인 도구 안에만 갇혀 있는 일이 없습니다.

<div id="what-is-design">
  ## Design이란?
</div>

[Design](/ko/design/what-is-replit-design)은 canvas를 보여줍니다. canvas에서는 prompt로 design frame을 생성하고, 여러 변형을 살펴본 뒤 가장 마음에 드는 것을 다듬을 수 있습니다. 코드 작성에 들어가기 전에 이 모든 과정을 진행할 수 있습니다.

Design은 다음과 같은 작업에 적합합니다:

* **아이디어를 빠르게 검증하기**: 기능을 구현하기 전에 앱 디자인을 눈으로 확인
* **완성도 높은 website 만들기**: landing page, 포트폴리오, 레스토랑 메뉴, 행사 페이지
* **디자인 세부 조정하기**: color, layout, 콘텐츠를 즉시 수정

<Info>
  design mockup은 실제 페이지처럼 보이고 동작하지만, 아직 데이터를 저장하거나 외부 서비스에 연결되지는 않습니다. 전체적인 모습이 마음에 들면 클릭 한 번으로 해당 디자인을 완전한 앱으로 build할 수 있습니다. 아래 단계에서 그 방법을 안내합니다.
</Info>

<div id="what-is-build">
  ## Build란?
</div>

Build는 여러분이 만든 결과물이 데이터를 저장하고, 사용자 로그인을 지원하며, 다른 서비스와 연결되는 실제 동작하는 애플리케이션으로 실행되는 단계입니다.

앱에 다음이 필요할 때 Build를 사용하세요:

* **사용자 계정**: 사용자가 계정을 만들고 로그인할 수 있도록 합니다
* **정보 저장**: 주문, 메시지, 사용자 환경설정 같은 데이터를 저장합니다
* **다른 서비스와의 연결**: 결제를 처리하고, 이메일을 보내고, 다른 앱에서 데이터를 가져옵니다
* **복잡한 작업**: 온라인 스토어를 운영하고, 예약을 관리하고, 대시보드를 구동합니다

<div id="using-both-together">
  ## 함께 사용하기
</div>

Design과 Build는 동일한 project에서 작동하므로 둘 중 하나만 골라야 할 필요가 없습니다. 겉모습부터 만들기 시작해 완전한 앱으로 발전시켜 보세요.

<Steps>
  <Step title="먼저 디자인하기">
    Design에서 시작해 아이디어를 빠르게 시각화하세요. layout, color, 버튼, 사용자 경험 등 앱의 모양과 느낌에 집중하면 됩니다.
  </Step>

  <Step title="다듬고 반복하기">
    [suggestion](/ko/design/explore-suggestions)을 따라 선택한 frame의 새로운 direction을 탐색하거나, **Edit** 도구를 선택한 뒤 요소를 클릭해 [Visual Editor](/ko/design/visual-editor)에서 조정하세요. [Agent와 채팅](/ko/design/chat-about-your-design)하여 원하는 변경 사항을 설명할 수도 있습니다.

    <Frame>
      <img src="/assets/mirror/ambient-iq-0989ea31bce7.png" alt="APEX X1 슈퍼카 hero가 표시된 선택된 Website frame과, 그 옆에 Explore different approaches, Try different layouts, Explore different vibes, Surprise me 같은 suggestion chip을 제공하는 Suggested next steps 패널" width="2000" height="1254" data-path="images/design/replit-design/ambient-iq.png" />
    </Frame>
  </Step>

  <Step title="디자인 빌드하기">
    디자인이 마음에 들고 실제 기능을 추가할 준비가 되면 frame에서 **Build…**를 선택하세요. 새 artifact를 만들거나 기존 artifact에 디자인을 적용할 수 있습니다. Agent가 디자인을 그대로 유지한 채 데이터 저장, 사용자 계정 처리, 서비스 연결 기능을 추가해 줍니다.

    <Frame>
      <img src="/assets/mirror/canvas-build-menu-f06b8b8b455f.png" alt="선택된 Design frame(APEX X1 Exact Replica)에서 열린 Build 메뉴로, 'Build or apply your designs' 헤더 아래에 새 artifact를 생성하는 'Build this design'과, project의 APEX X1 Design System 및 Scroll Hero website를 나열하는 'Apply to an existing creation'이 표시됨" width="2000" height="1153" data-path="images/replitai/canvas-build-menu.png" />
    </Frame>

    <Note>
      mockup에 database나 고급 기능을 추가하려고 하면 Agent가 변환할지 물어봅니다.
    </Note>
  </Step>

  <Step title="게시하고 공유하기">
    앱을 빌드한 후에는 게시하여 누구나 온라인에서 접근할 수 있도록 하세요. Replit이 모든 기술 인프라를 처리하므로 앱이 사용자에게 안정적으로 작동합니다.
  </Step>
</Steps>

<div id="when-to-start-in-each">
  ## 각각 언제 시작하면 좋을까
</div>

<CardGroup cols={2}>
  <Card title="Design에서 시작하기" icon="paintbrush">
    * 겉모습이 가장 어려운 부분일 때
    * 아이디어를 빠르게 눈으로 확인하고 싶을 때
    * 여러 방향을 탐색하고 비교하고 싶을 때
    * 속도가 최우선일 때
  </Card>

  <Card title="Build에서 시작하기" icon="cube">
    * 동작이 가장 어려운 부분일 때
    * 앱이 처음부터 데이터를 저장해야 할 때
    * 사용자 로그인이 필요할 때
    * 다른 서비스와 연동해야 할 때
  </Card>
</CardGroup>

<Tip>
  **어느 쪽을 골라야 할지 모르겠나요?** Design에서 시작하세요. 더 빠르고, 나중에 언제든 그 디자인을 완전한 앱으로 만들 수 있습니다. 작업한 내용은 절대 낭비되지 않고 Build로 그대로 이어집니다. 반대 방향도 가능합니다. Build에서 앱을 동작하게 만든 다음, Design에서 스타일을 다시 다듬으면 됩니다.
</Tip>

<div id="key-differences">
  ## 주요 차이점
</div>

| 기능         | Design (mockup)   | Build (app)      |
| ---------- | ----------------- | ---------------- |
| **속도**     | 몇 분               | 완성된 앱까지 약 10분    |
| **데이터 저장** | 화면 표현만 (저장되지 않음)  | 실제 데이터를 저장하고 불러옴 |
| **사용자 계정** | login 화면의 모습만 보여줌 | 실제 login 기능 제공   |
| **서비스 연결** | 지원하지 않음           | 결제, 이메일, 외부 데이터  |
