<div id="section-2">
  ## 在模拟器或仿真器中预览
</div>

在 Replit 中，你可以使用 Expo 在智能手机上运行和测试移动应用。Replit 还会将真实的 **iOS 模拟器**或 **Android 模拟器**直接串流到预览面板。通过 Agent 所做的更改会热重载到模拟器中，其运行效果与真实设备相同。

<Note>
  Core、Pro 和 Enterprise 套餐的构建者可使用 iOS 模拟器和 Android 模拟器预览功能。仅适用于移动应用 — 纯 Web 项目不会显示此选项。
</Note>

<div id="expo-go">
  ### 改用 Expo Go
</div>

如果需要测试依赖真实硬件的功能，或想与不在电脑旁的人分享预览，请在真机上使用 Expo Go：

* 相机、麦克风、触觉反馈及其他原生传感器
* 推送通知
* 真实 GPS 位置信息
* 与团队成员、测试人员和投资者分享开发预览

要通过 Expo Go Build 应用，请在 [replit.com](https://replit.com) 中打开项目，在项目编辑器的预览面板中选择**在 Expo Go 中打开**，然后使用手机上的 [Expo Go](https://expo.dev/go) 应用扫描二维码。

在移动端产物卡片中选择**更多操作** → **在 iOS 模拟器中打开**或**在 Android 模拟器中打开**，即可在独立标签页中打开模拟器，以获得更大的视口。

<div id="section-6">
  ## 为什么要构建移动应用？
</div>

当你需要以下功能时，可以构建移动应用：

* **原生体验**：高性能、流畅交互以及符合平台风格的原生界面。
* **设备功能**：摄像头、推送通知、位置信息等。
* **App Store 分发**：通过 Apple 应用审核后，用户可发现并安装的可分享应用页面。

<div id="section-7">
  ## 主要功能
</div>

* **AI 优先构建**：描述你的 App，Agent 就会搭建一个可运行的移动 App。
* **项目编辑器预览**：无需离开 Replit，即可在 iOS 模拟器或 Android 模拟器中进行测试，或通过 Expo Go 在手机上预览。
* **默认全栈**：随着 App 的发展，可添加服务器路由、Database、App Storage、Connector 和 AI 集成。
* **引导式提交**：无需管理本地 iOS 工具链，即可准备提交到 TestFlight 和 App Store 的构建版本。

<div id="section-8">
  ## 开发工作流程
</div>

App 可通过三个阶段访问，每个阶段面向的用户和功能各不相同：

| 阶段            | 可访问人员            | 访问方式                   | 最适合的用途       |
| ------------- | ---------------- | ---------------------- | ------------ |
| **开发**        | 你                | 项目编辑器模拟器，或 Expo Go 二维码 | 构建和迭代        |
| **部署**        | 使用 Expo Go 的测试人员 | 带二维码的公开 URL            | 开发预览、原型设计和演示 |
| **App Store** | 任何人              | 通过应用审核后从 App Store 下载  | 正式发布         |

**开发**：启动 App 后，你可以在项目编辑器的 **iOS 模拟器**或 **Android 模拟器**中预览，也可以扫描预览面板中的二维码，在手机上的 Expo Go 中打开。

**部署**：点击 **发布** 后，Replit 会创建一个带有 Expo Go 二维码的公开 URL。这非常适合开发预览和原型设计 — 在进入 App Store 流程之前，你可以向投资者展示、收集反馈，或与朋友一起测试。

**App Store**：提交到 App Store 后，Apple 会审核你的 App。审核通过后，任何人都可以从 App Store 下载并安装。这需要 Apple Developer 账户。

<div id="section-9">
  ## 发布概览
</div>

准备发布 iOS 版本时，通常需要按以下流程操作：

* 从项目编辑器发布
* 向 TestFlight 提交构建版本
* 在 App Store Connect 中将 TestFlight 构建版本提交至 App Store

<Note>
  向 TestFlight 和 App Store 提交构建版本需要加入 Apple Developer Program。
</Note>

如需完整的操作指南，请参阅[构建和发布移动 App](/zh/ja/build/mobile-app)教程。

<div id="section-10">
  ## 在哪里构建原生移动应用
</div>

Replit 环境在云端运行，而不是在本地计算机上运行。要构建原生移动应用，请使用 [replit.com](https://replit.com) 上的项目编辑器。移动应用工作流——包括 Agent 脚手架搭建、Expo Go 预览、模拟器和仿真器测试、TestFlight 构建以及 App Store 提交——均在项目编辑器中完成。

也可以在受支持的 [Replit Android 应用](/zh/ja/features/platforms/mobile-app)中处理原生移动应用相关工作。如果您使用 Replit iOS 应用，请在 [replit.com](https://replit.com) 上打开项目，创建、预览、构建和提交原生移动应用。

<div id="section-11">
  ## 技术原理
</div>

移动应用由一系列协同工作的技术构成。本节将介绍驱动应用运行的技术，以及各部分如何协同配合。

<div id="section-12">
  ### 技术栈
</div>

<MobileStackDiagram />

* **React Native** 是一个开源框架，让你能够编写一套代码，并将其编译为 iOS、Android 和 Web 应用。它渲染的是平台原生界面组件，而不是网页视图。
* **Expo** 通过提供构建处理、原生模块管理以及用于预览的 Expo Go 等工具，简化了 React Native 开发。
* **Expo Go** 是一款可安装在智能手机上的免费应用。无需构建完整的原生二进制文件，即可在真机上运行开发预览。

运行应用时，Metro 打包器会编译代码并将其推送到设备。由于没有缓存，首次构建耗时较长，后续构建则会更快。

<div id="section-13">
  ### 架构：服务器与客户端
</div>

预览移动应用或准备分发时，您需要处理两个部分：

1. **服务器**：运行在云端的 Replit 上，负责处理数据库、API 路由、AI 集成和后端逻辑。
2. **客户端应用**：运行在用户的智能手机上。开发期间通过 Expo Go 预览，审核后作为原生应用经由应用商店分发。

<MobileArchitectureDiagram />

这种分离方式带来了灵活性。您可以在服务器上运行复杂逻辑 (并访问 Replit 的数据库、对象存储和 Connector) ，同时让客户端保持轻量。构建时，请思考哪些操作应在智能手机上进行，哪些应在云端进行。

<div id="section-14">
  ## 注意事项
</div>

* **发布要求**：Apple 制定了 TestFlight 和 App Store 的相关要求，并会在分发前审核 iOS 应用。
* **Android 发布**：您可以构建适用于 iOS 和 Android 的跨平台应用。引导式流程目前尚不支持发布到 Google Play，但您可以手动发布。
* **原生更改**：更改应用图标、权限等内容通常需要重新构建商店版本。

<div id="section-17">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="什么是 Expo？">
    Expo 是 Agent 在 Replit 上构建移动应用时使用的工具。它是一个开源平台和工具链，可用于借助 React Native 构建、运行和部署跨平台原生应用。详情请参阅[https://expo.dev。](https://expo.devをご覧ください。)
  </Accordion>

  <Accordion title="什么是 React Native？">
    React Native 是 Meta 的开源框架，可使用 React 和 JavaScript 或 TypeScript 构建原生 iOS 和 Android 应用。它渲染的是平台原生界面组件，而非网页视图，因此应用具有原生的外观和使用体验。
  </Accordion>

  <Accordion title="什么是 Expo Go？">
    Expo Go 是一款可从 App Store 或 Google Play 安装到智能手机上的免费 App。无需构建完整的原生二进制文件，即可在开发过程中预览移动应用。扫描项目编辑器中的二维码后，Expo Go 会下载应用代码并通过 Build 进行构建。
  </Accordion>

  <Accordion title="Expo Go 与开发构建有何区别？">
    **Expo Go** 是一款用于运行代码的预构建应用。它设置快速，但仅支持 Expo SDK 中包含的模块。

    **Dev 构建**是可包含任意原生模块的自定义原生二进制文件。它需要更多设置 (EAS Build 或本地 Xcode/Android Studio) ，但灵活性更高。

    Replit 使用 Expo Go 进行开发预览。如果需要 Expo Go 不支持的原生模块，你可能需要参考 [Expo 文档](https://docs.expo.dev/develop/development-builds/introduction/) 使用 Dev 构建。
  </Accordion>

  <Accordion title="与移动端自适应 Web 应用有什么区别？">
    移动端响应式 Web 应用是可在浏览器中自适应调整布局的网站。React Native 应用是安装在设备上的原生应用，可使用平台 API (相机、触觉反馈、推送通知) ，更好地访问硬件和离线功能，并可通过应用商店分发。响应式 Web 在覆盖面和无需安装方面表现出色；需要设备功能、更高性能或通过 App Store 分发时，原生应用是更佳选择。
  </Accordion>

  <Accordion title="需要 Mac 或 Xcode 吗？">
    不需要。Replit 和 Expo 会在云端管理构建过程。
  </Accordion>

  <Accordion title="没有 Apple Developer 账户也可以预览吗？">
    可以。你可以在项目编辑器的 iOS 模拟器中，或通过手机上的 Expo Go 进行预览。只有在准备提交至 TestFlight 或 App Store 时，才需要 Apple Developer 账户。
  </Accordion>

  <Accordion title="支持 Android 吗？">
    可以。您可以使用同一代码库构建适用于 iOS 和 Android 的跨平台应用。您可以在项目编辑器的 Android 模拟器中预览，也可以通过 Expo Go 在 Android 设备上预览。您可以手动发布到 Google Play。
  </Accordion>

  <Accordion title="服务器和数据库会怎么样？">
    使用 Replit 内置的 PostgreSQL、对象存储、Connector 和 AI 集成，无需额外基础设施。服务器运行在 Replit 上，移动应用则连接到服务器。
  </Accordion>

  <Accordion title="在项目编辑器中，应该使用模拟器还是真机进行测试？">
    请根据情况结合使用两者。项目编辑器中的**iOS 模拟器**和**Android 模拟器**可显示应用的原生版本，满足大多数日常测试需求 (布局、导航、原生组件和平台样式) 。如需测试依赖真实硬件的功能，例如相机、触觉反馈、推送通知和 GPS 定位，请使用 **Expo Go** 切换到真机。
  </Accordion>
</AccordionGroup>
