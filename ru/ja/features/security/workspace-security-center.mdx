Центр безопасности рабочего пространства доступен на всех планах. Используйте его, чтобы сканировать [зависимости](/ru/ja/features/security/concepts#dependency) проектов во всём рабочем пространстве и просматривать обнаруженные [CVE](/ru/ja/features/security/concepts#cve) по [уровню серьёзности](/ru/ja/features/security/concepts#severity). Вы можете устранять проблемы с помощью Replit Agent, [переопубликовывать](/ru/ja/features/security/concepts#republish) затронутые проекты и экспортировать отчёты Software Bill of Materials ([SBOM](/ru/ja/features/security/concepts#sbom)) для соответствия требованиям.

<Note>
  Чтобы просканировать отдельный проект, откройте [Центр безопасности проекта](/ru/ja/features/security/project-security-center) на панели **Security** внутри этого проекта.
</Note>

<Note>
  Если вы только начинаете знакомиться с безопасностью зависимостей, см. [Концепции безопасности](/ru/ja/features/security/concepts) — там приведены определения CVE, SBOM, степени открытости, исправления с помощью Agent, переопубликации и Auto-Protect.
</Note>

<div id="section">
  ## Возможности
</div>

<div id="cve">
  ### Обнаружение CVE
</div>

Проверяйте наличие уязвимостей во всех проектах рабочего пространства:

* Находите уязвимые проекты, отсортированные по [степени открытости](/ru/ja/features/security/concepts#exposure) (статус публикации и видимость)
* Просматривайте названия затронутых пакетов, версии и уровень серьёзности (критический, высокий, средний, низкий)
* Получайте рекомендации по устранению уязвимостей для каждого проекта

<div id="section-2">
  ### Представление затронутых проектов
</div>

Определяйте проекты с уязвимостями и расставляйте приоритеты их устранения:

* Просматривайте сводку по уязвимым проектам с группировкой по степени открытости (всего проектов, опубликованные проекты, публично опубликованные проекты)
* Изучайте подробную разбивку затронутых проектов Replit
* Выполняйте поиск по идентификатору CVE или названию проекта и фильтруйте по уровню серьёзности, владельцу, состоянию публикации (Published / Not published) и видимости (Public / Private)
* Разворачивайте строку проекта, чтобы увидеть все обнаруженные CVE (уровень серьёзности, пакет, версия, идентификатор CVE), не покидая страницу

<div id="agent">
  ### Исправление с помощью Agent и повторная публикация
</div>

Устраняйте уязвимости и заново развёртывайте приложения, не покидая Центр безопасности:

* Выберите **[Исправить с помощью Agent](/ru/ja/features/security/concepts#fix-with-agent)** в затронутом проекте, чтобы подготовить черновик исправления в виде фоновой задачи внутри проекта. Перед повторной публикацией проверьте и примените сгенерированные изменения.
* Отслеживайте ход исправления по этапам **Task in progress**, **Apply changes**, **Republish**, а также по конечным состояниям **Republished** или **Failed**.
* Кнопка **Republish** в одно нажатие и диалог подтверждения повторно развёртывают сборку с текущими настройками после того, как исправление будет объединено.
* Выполняйте массовые действия, например снятие проектов с публикации или уведомление владельцев проектов об уязвимостях.

<div id="sbom">
  ### Экспорт SBOM
</div>

Экспортируйте Software Bill of Materials для целей комплаенса и аудита:

* Загружайте SBOM в стандартных форматах ([SPDX](/ru/ja/features/security/concepts#spdx-and-cyclonedx), [CycloneDX](/ru/ja/features/security/concepts#spdx-and-cyclonedx))
* Формируйте отчёты по отдельным проектам или по всему рабочему пространству
* Просматривайте SBOM, сгруппированные по запускам сканирования, с указанием времени, количества проектов и пользователя, запустившего сканирование
* Загружайте все SBOM из одного запуска сканирования единым ZIP-архивом
* Выполняйте требования комплаенса к прозрачности цепочки поставок программного обеспечения

<Note>
  Массовая загрузка SBOM доступна в плане Enterprise. В рабочих пространствах на других планах в разделе SBOM отображается предложение перейти на Enterprise.
</Note>

<div id="section-3">
  ## Доступ к Центру безопасности рабочего пространства
</div>

Чтобы открыть Центр безопасности рабочего пространства:

1. Перейдите на [replit.com](https://replit.com) и войдите в свою учётную запись.
2. На главной странице в левой панели навигации выберите **Security**.

<div id="section-4">
  ## Сканирование рабочего пространства
</div>

<Frame>
  <img src="/assets/mirror/security-overview-b37f090f236c.png" alt="Начальный экран Центра безопасности рабочего пространства с общим количеством сканирований, общим числом уязвимостей и CVE, сгруппированными по уровню серьезности" width="3438" height="1984" data-path="images/workspace-security-center/security-overview.png" />
</Frame>

1. Откройте Центр безопасности рабочего пространства.
2. Выберите **Run security scan**, чтобы запустить сканирование всего рабочего пространства.
3. Просмотрите результаты, сгруппированные по затронутым проектам, уровню серьезности и доступности из развертываний.
4. В затронутом проекте выберите **Исправить с помощью Agent**, а после применения исправлений — **Republish**.

Сканирование анализирует зависимости проектов Replit в рабочем пространстве и отмечает известные уязвимости из публичных баз данных уязвимостей.

<div id="auto-protect">
  ## Auto-Protect
</div>

Администраторы могут подключить для аккаунта **[Auto-Protect](/ru/ja/features/security/concepts#auto-protect)**. В этом режиме ведётся непрерывный мониторинг новых CVE, затрагивающих зависимости всех проектов. При обнаружении совпадения Replit Agent готовит проверенный патч, а разработчик получает письмо с прямой ссылкой для его применения.

Полное описание рабочего процесса и инструкции по настройке (включая порог серьёзности, доступный только администраторам, в **Settings** &gt; **Account** &gt; **Advanced**) см. в разделе [Auto-Protect](/ru/ja/features/security/project-security-center#auto-protect).

<Note>
  По вопросам настройки центра безопасности рабочего пространства и интеграции экспорта SBOM в процессы обеспечения соответствия требованиям обращайтесь к своему персональному менеджеру аккаунта.
</Note>
