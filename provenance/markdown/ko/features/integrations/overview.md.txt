Agent는 아이디어에서 앱까지 빠르게 갈 수 있도록 네 가지 유형의 통합을 지원합니다.

* **Replit 관리형**: 자동으로 작동하는 내장 통합입니다. 앱을 만들면 Agent가 바로 사용할 수 있습니다.
* **커넥터(Connectors)**: Replit이 지원하는 퍼스트파티 통합입니다. 한 번만 로그인하면 됩니다. Agent는 채팅에서 바로 이러한 서비스에서 읽고 쓸 수 있습니다 — 데이터를 가져오고, 레코드를 생성하고, 메시지를 보내고 — 여러 앱에서 이를 활용해 빌드할 수 있습니다.
* **외부 통합(External integrations)**: 함께 빌드할 수 있는 신뢰할 수 있는 타사 서비스입니다. Agent에게 설정을 요청하면 여러분이 API 키를 제공합니다.
* **Agent 서비스(Agent services)**: Agent가 뒤에서 사용하는 유료 타사 API입니다 — API 키가 필요하지 않습니다. 사용량은 Replit 크레딧에서 청구됩니다.

<Note>
  **플랜별 이용 가능 여부**: 대부분의 커넥터는 Core, Pro, Enterprise 구독이 필요하며, 일부는 Free 플랜에서도 이용할 수 있습니다. 워크스페이스의 커넥터 카탈로그에서 현재 플랜으로 사용할 수 있는 커넥터를 확인할 수 있습니다. Free 플랜 빌더는 데이터베이스, 인증 등 Replit 관리형 통합을 언제든지 사용할 수 있습니다.
</Note>

## 시작하기

통합을 사용하려면 필요한 서비스나 기능을 언급하세요. 예를 들어:

<AiPrompt>
  Stripe로 결제를 받고 SendGrid로 확인 이메일을 보내는 웹 앱을 만들어줘
</AiPrompt>

Agent는 이러한 키워드를 자동으로 감지하고 필요한 코드와 구성을 구현합니다.

### Agent가 커넥터를 제안하도록 하기

때로는 파일 저장이나 이메일 전송처럼 여러 서비스가 같은 역할을 할 수 있습니다. 제공업체를 지정하지 않고 기능을 요청하면 Agent가 적합한 커넥터 목록을 간단히 보여줍니다. 원하는 것을 선택하세요.

제공업체를 선택한 다음 한 번만 로그인해서 계정을 연결하세요. Agent는 빌드하는 동안 선택한 항목을 사용합니다. 목록을 건너뛰려면 특정 서비스 이름을 직접 요청할 수도 있습니다.

## 커넥터

커넥터는 Agent가 서비스에서 직접 읽고 쓸 수 있게 해줍니다. Replit이 지원하는 퍼스트파티 통합입니다. Project Editor의 Connectors 페이지에서 한 번 로그인하면 모든 앱에서 해당 연결을 재사용할 수 있습니다.

<Note>
  연결은 Replit 계정에 연결되어 모든 앱에서 유지됩니다. 서비스를 한 번 연결하면 생성하는 어떤 앱에서도 사용할 수 있습니다.
</Note>

### Agent와 함께 Slack 사용하기

Slack을 연결하면 Agent가 접근할 수 있는 대화에서 맥락을 얻을 수 있습니다. Agent에게 메시지, 파일, 채널, 사람을 검색하도록 요청한 다음 결과를 사용해 질문에 답하거나 작업을 계속하세요.

여러분의 허락을 받으면 Agent는 다음을 할 수 있습니다.

* 여러분이 속한 비공개 채널, 다이렉트 메시지, 그룹 다이렉트 메시지 읽기
* 주변 맥락이 필요할 때 전체 스레드 답장 읽기
* 여러분을 대신해 메시지 보내기
* Slack 캔버스 생성, 읽기, 업데이트

<AiPrompt>
  Alex와의 다이렉트 메시지에서 출시 계획에 대한 논의를 요약한 다음 후속 조치 초안을 작성해줘.
</AiPrompt>

<Info>
  Agent는 연결된 Slack 계정이 접근할 수 있는 Slack 대화와 콘텐츠에만 접근할 수 있습니다.
</Info>

### 커넥터 접근하기

Project Editor의 사이드바에서 커넥터에 접근할 수 있습니다.

<Steps>
  <Step title="Project Editor 열기">
    Project Editor에서 앱을 여세요.
  </Step>

  <Step title="Connectors 선택">
    사이드바에서 **Connectors**를 선택하세요.
  </Step>

  <Step title="새 통합 추가">
    **Add new integration**을 선택해 사용 가능한 커넥터를 살펴보세요.
  </Step>

  <Step title="연결">
    통합하려는 서비스 옆의 **Connect**를 선택하세요.
  </Step>
</Steps>

<Tip>
  서비스 연결을 해제하려면 Connectors 패널로 돌아가서 연결된 서비스 옆의 **Manage**를 선택하세요.
</Tip>

  **Enterprise 전용**: 커스텀 OAuth 앱을 구성하려면 Enterprise 구독이 필요합니다.
</Note>

Enterprise 플랜에서는 Replit의 기본값 대신 커넥터를 위한 자체 OAuth 앱을 가져올 수 있습니다. 이를 통해 조직이 OAuth 클라이언트를 소유하고, 동의 화면에 자체 브랜딩을 표시하고, 빌더가 요청할 수 있는 정확한 스코프를 제어할 수 있습니다.

커넥터를 자체 OAuth 앱으로 구성하려면 제공업체로부터 세 가지가 필요합니다: **Client ID**, **Client Secret**, 승인하려는 \*\*스코프(scopes)\*\*입니다. 인증을 완료할 수 있도록 제공업체에 Replit의 콜백 URL도 등록해야 합니다.

<Frame>
  <img src="https://mintcdn.com/replit/4yzFNPCD7dvZeV3f/images/replitai/connector-oauth-configuration.png?fit=max&auto=format&n=4yzFNPCD7dvZeV3f&q=85&s=2bb8931dcd58c4fbad66b2de235bf0a1" alt="Client ID, Client Secret, Connector Scopes 입력란과 https://replit.com/connectors/oauth/callback으로 설정된 Redirect URL이 있는 커넥터 OAuth 구성 대화 상자" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="제공업체에서 OAuth 앱 생성">
    제공업체의 개발자 콘솔이나 관리자 설정에 로그인하고 새 OAuth 2.0 애플리케이션을 생성하세요. 제공업체마다 이 단계의 이름이 다릅니다 — **Create OAuth app**, **Register application**, **Create client credentials** 같은 옵션을 찾아보세요.
  </Step>

  <Step title="리디렉션 URL 설정">
    제공업체가 **Authorized redirect URI**(때때로 **Callback URL** 또는 **Redirect URL**이라고도 함)를 요청하면 다음을 입력하세요.

    ```
    https://replit.com/connectors/oauth/callback
    ```

    이 URL은 빌더가 앱을 승인한 후 제공업체가 Replit으로 되돌려 보내는 위치입니다. 정확히 일치해야 합니다 — 후행 슬래시, 프로토콜, 서브도메인 모두 중요합니다. 리디렉션 URI를 여러 개 추가하는 경우, 이 URL이 반드시 포함되어야 합니다.
  </Step>

  <Step title="Client ID와 Client Secret 복사">
    앱을 만들면 제공업체가 **Client ID**와 **Client Secret**을 표시합니다.

    * **Client ID**: OAuth 앱의 공개 식별자입니다. URL이나 클라이언트 측 코드에 노출해도 안전합니다.
    * **Client Secret**: 요청이 여러분의 앱에서 오는 것임을 증명하는 기밀 값입니다. 비밀번호처럼 다루세요 — 절대 저장소에 커밋하거나 공개적으로 공유하지 마세요. Replit은 이를 안전하게 저장합니다.

    일부 제공업체는 생성 시점에 클라이언트 시크릿을 한 번만 표시합니다. 즉시 복사해 Replit에 붙여넣을 때까지 안전한 곳에 보관하세요.
  </Step>

  <Step title="스코프 선택">
    \*\*스코프(Scopes)\*\*는 OAuth 앱이 빌더를 대신해 읽거나 쓸 수 있는 권한을 정의하는 항목입니다. 각 제공업체는 API 문서에 자체 스코프 목록을 게시합니다.

    Replit에서 커넥터를 구성할 때 입력하는 스코프는 제공업체에 등록한 스코프와 **정확히 일치**(URL 접두사를 포함해 문자 단위로)해야 합니다. 불일치 오류의 일반적인 원인은 다음과 같습니다.

    * 전체 URL 접두사가 누락됨(예: `drive.file` 대신 `https://www.googleapis.com/auth/drive.file`).
    * 여분의 공백이나 후행 쉼표.
    * 제공업체의 앱에서 활성화되지 않은 스코프를 Replit에서 요청함.

    빌더에게 필요한 최소한의 스코프부터 시작하고, 필요하면 나중에 더 추가하세요 — 대부분의 제공업체는 앱을 다시 만들지 않고도 스코프를 업데이트할 수 있게 해줍니다.
  </Step>

  <Step title="Replit에서 커넥터 구성">
    조직의 **Connectors** 페이지에서 **Add new integration**을 선택하고, 서비스를 선택한 후 제공업체로부터 받은 **Client ID**, **Client Secret**, **Scopes**를 붙여넣으세요. **Configure**를 선택해 저장하세요.
  </Step>
</Steps>

<Note>
  구성 후 인증이 실패하면, 제공업체의 리디렉션 URL이 `https://replit.com/connectors/oauth/callback`과 정확히 일치하는지, Replit에 입력한 모든 스코프가 제공업체의 앱에서도 승인되어 있는지 다시 확인하세요.
</Note>

</Note>

## Agent 서비스

일부 기능은 뒤에서 유료 타사 API를 사용합니다. Agent가 통합을 자동으로 처리합니다 — API 키나 설정이 필요하지 않습니다. 제공업체의 요율로 청구되며 Replit 크레딧에서 차감됩니다.

    <AiPrompt>내 앱의 온보딩 플로우에 음성 내레이션을 추가해줘</AiPrompt>

</Note>

## 통합 재연결하기

로그인 세션이 만료되거나 권한이 변경되는 등의 이유로 연결된 서비스가 작동을 멈추면, Replit은 Project Editor에 재연결 알림을 표시합니다. 알림을 선택하면 에디터를 벗어나지 않고 바로 통합을 재연결할 수 있습니다.

## 커넥터 디버깅

서비스를 연결하는 데 문제가 있으신가요? 다음 가이드에서 일반적인 오류와 해결 방법을 안내합니다.

<AccordionGroup>
  <Accordion title="Google Workspace: &#x22;This app is blocked&#x22;">
    Google Drive, Docs, Sheets, Calendar, Gmail을 연결할 때 \*\*"This app is blocked"\*\*가 표시되면, 조직의 Google Workspace가 타사 OAuth 앱을 제한하고 있을 가능성이 높습니다. 해결하려면 전체 문제 해결 가이드를 참고하세요.

    [Google 커넥터의 "This app is blocked" 해결하기](/ko/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce: &#x22;Connection Expired&#x22;">
    Salesforce 커넥터가 **"Connection Expired"** 오류와 함께 작동을 멈추면, Salesforce 조직의 새로고침 토큰 정책이 일정 기간 후 토큰을 만료시키도록 구성되어 있을 가능성이 높습니다. Connected App 설정을 업데이트하는 방법은 전체 문제 해결 가이드를 참고하세요.

    [Salesforce 연결 만료 오류 해결하기](/ko/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
