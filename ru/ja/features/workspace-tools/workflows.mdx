<div id="section">
  ## Доступные типы задач
</div>

Сейчас доступны три типа задач: `Execute Shell Command`, `Install Packages` и `Run Workflow`.

<div id="execute-shell-command">
  ### Execute Shell Command
</div>

`Execute Shell Command` сохраняет shell-команду и выполняет её в том же окружении, что и панель Shell. Этот тип задач подходит для самых разных сценариев — например, для запуска отдельных файлов:

```text theme={null}
python main.py
```

до выполнения сложных запросов к базе данных:

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Install Packages
</div>

`Install Packages` использует встроенную систему управления зависимостями Replit: она автоматически определяет зависимости проекта и устанавливает необходимые для него пакеты. Подробнее о том, как UPM определяет, какие пакеты нужно установить в проект, см. в разделе [Управление зависимостями](/ru/ja/features/project-setup/dependency-management#the-universal-package-manager).

<div id="run-workflow">
  ### Запуск Workflow
</div>

`Run Workflow` позволяет запускать другой Workflow из текущего. Это позволяет повторно использовать и комбинировать Workflow для создания более сложных процессов.

Пример использования:

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="Пример запуска Workflow" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

Создавая зависимости между Workflow с помощью этого типа задач, вы можете редактировать один Workflow, а другие Workflow, которые на него ссылаются, будут автоматически использовать последние изменения. Обратите внимание, что глубина вложенных вызовов Workflow ограничена.

<div id="section-2">
  ## Режимы выполнения Workflow
</div>

Workflows поддерживает два режима выполнения: последовательный и параллельный.

<div id="section-3">
  ### Последовательный
</div>

При последовательном выполнении задачи запускаются в заданном порядке: каждая следующая начинается только после завершения предыдущей, а если какая-либо задача Workflow завершается с ошибкой, выполнение прекращается.

Этот режим удобен, когда нужно задать логически связанные команды — например, команды git, которые получают последние изменения из основной ветки и выполняют перебазирование текущей ветки на основную:

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="Пример последовательного Workflow" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="section-4">
  ### Параллельный
</div>

В режиме параллельного выполнения все задачи запускаются одновременно и выполняются независимо друг от друга. Сбой одной задачи не останавливает выполнение остальных.

Например, этот режим можно использовать для запуска полностекового проекта, в котором нужно запустить и фронтенд-, и бэкенд-сервер:

<div id="section-5">
  ## Создание Workflow
</div>

Workflow можно создать, нажав кнопку `+ New Workflow` на панели Workflows. Сначала задайте Workflow понятное название, выберите подходящий режим выполнения и начните добавлять задачи. Задачи можно перетаскивать мышью, выстраивая их в нужном порядке.

<div id="run">
  ## Назначение workflow кнопке Run
</div>

Вы можете назначить workflow кнопке Run, заменив её поведение по умолчанию (см. [Настройка Replit App](/ru/ja/features/project-setup/configuration)). Чтобы сохранить команду запуска по умолчанию, заданную в `.replit`, выберите в выпадающем списке стандартный вариант «Run Replit App».

При нажатии на кнопку Run запускается тот workflow, который выбран в выпадающем меню рядом с ней. Чтобы изменить его, выберите нужный workflow в этом меню.
