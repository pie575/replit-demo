高效的提示词从你想要的结果出发。用清晰、简洁的要求引导 [**Agent**](/zh/pt/core-concepts/agent)，就能更快地把想法变成应用。

<div id="exemplos-rpidos">
  ## 快速示例
</div>

看看模糊的提示词和有效的提示词有什么区别：

<AccordionGroup>
  <Accordion title="修复代码" icon="bug">
    **模糊：**&quot;修复我的代码。&quot;

    **有效：**&quot;即使密码正确，登录表单也会失败。请修复登录流程。&quot;

    先说明出了什么问题。如果 Agent 需要更多上下文，再补充错误信息或文件。
  </Accordion>

  <Accordion title="构建功能" icon="hammer">
    **模糊：**&quot;创建一个网站。&quot;

    **有效：**&quot;构建一个简单的作品集网站，包含首页、关于和联系页面。&quot;

    聚焦于你想要的结果，再加上最关键的少数细节。
  </Accordion>

  <Accordion title="性能改进" icon="gauge-high">
    **模糊：**&quot;别让它变慢。&quot;

    **有效：**&quot;订单很多时，让仪表板加载得更快。&quot;

    描述你想要的改进效果。除非你有明确偏好，否则让 Agent 自行决定实现方式。
  </Accordion>

  <Accordion title="界面更改" icon="paintbrush">
    **模糊：**&quot;加个动画。&quot;

    **有效：**&quot;页面加载时，为主视觉图片添加轻微的淡入效果。&quot;

    指明应用中的具体部分以及你想要的效果。
  </Accordion>

  <Accordion title="复杂系统" icon="server">
    **模糊：**&quot;构建 backend。&quot;

    **有效：**&quot;添加登录、个人资料，以及让用户保存进度的方式。&quot;

    先说明你想要的产品效果，只有在技术细节确实重要时才补充。
  </Accordion>
</AccordionGroup>

<div id="planeje-primeiro">
  ### 先做规划
</div>

<Tip>在编写提示词之前，先想清楚怎样才算成功。一个简单的计划就能带来更好的提示词。</Tip>

先写下核心成果，再列出后续的里程碑。

**不要这样写：**“构建一个任务管理应用。”

**试试这样写：**“构建一个简单的任务管理器，让我可以添加、完成和删除任务。”

然后再用后续的提示词逐步完善它。

<div id="construa-incrementalmente">
  ### 逐步构建
</div>

Agent 工作时会自动创建 [**Checkpoint**](/zh/pt/core-concepts/agent/checkpoints-and-rollbacks)。如果出现问题，你可以回滚并尝试其他思路。

**不要这样说：**“构建一个完整的电商平台。”

**试试这样说：**“先做一个简单的在线商店，包含登录和商品页面。”然后在后续的提示词中逐步添加购物车、结账流程和管理工具。

<div id="seja-especfico">
  ### 描述要具体
</div>

说清楚你希望实现什么，并写明会影响结果的细节。

**不要这样说：** “添加一个联系表单。”

**试试这样说：** “添加一个联系页面，包含姓名、电子邮件和留言字段。将提交的内容发送到我的邮箱。”

<div id="use-linguagem-positiva">
  ### 使用正面表述
</div>

说明你*想要*什么，而不是要避免什么。

**不要这样说：** “不要把用户个人资料页做得很乱。”

**试试这样说：** “把个人资料页做得简洁、易于浏览。显示姓名、电子邮件、加入日期以及一个‘编辑资料’按钮。”

<div id="mantenha-simples">
  ### 保持简单
</div>

使用简短、直接的语言。只在确实有必要时才补充实现细节。

**不要这样写：** “实现必要的服务器端基础设施，以支持用户生成内容产物的动态生成与检索。”

**试试这样写：** “让用户能够撰写并发布博客文章。”

<div id="trabalhando-com-contexto">
  ## 使用上下文
</div>

<div id="fornea-arquivos-relevantes">
  ### 提供相关文件
</div>

只分享 Agent 需要的文件或参考资料。

**不要这样：** (附上所有内容) “根据我们的设计系统实现用户资料页面。”

**试试这样：** “创建用户资料页面，并与这个原型图保持一致：[附上 `profile_mockup.jpg`]。使用我们设计文档中的配色：[URL]。”

<Tip>切换到不相关的任务时，请开启新的对话。这样可以避免累积的上下文造成混淆。</Tip>

<div id="mostre-exemplos">
  ### 展示示例
</div>

用示例、截图或样本数据来减少歧义。

**不要说：**&quot;把产品卡片做得好看一点。&quot;

**试试这样说：**&quot;把产品卡片做成这张截图的样子：图片、名称、价格，以及一个&quot;加入购物车&quot;按钮。&quot;

<div id="depurando-de-forma-eficaz">
  ## 高效调试
</div>

出现问题时，请提供以下信息：

* **完整准确的**错误消息
* 相关代码片段
* 报错所在的文件名
* 你想要实现的目标
* 你已经尝试过的步骤

**不要这样说：**“我的登录页面坏了。”

**试试这样说：**“即使使用有效凭证，登录页面仍显示‘找不到用户’。问题出现在 `/login`。请帮忙修复。”

<div id="pea-orientao">
  ## 寻求建议
</div>

<Tip>动手构建之前，先切换到规划模式来探索不同方案。可以向 Agent 咨询有哪些库、实现思路以及各自的利弊。</Tip>

**不要这样说：**&quot;添加支付功能。&quot;

**试试这样说：**&quot;在 Replit 上，给我的应用添加信用卡支付最简单的方式是什么？&quot;

<div id="itere-nos-seus-prompts">
  ## 反复打磨提示词
</div>

第一次写的提示词未必完美。如果结果不理想：

* 补充更多细节
* 提供一个示例
* 简化指令
* 换一种表达方式

**初始版本：**“为我的网站添加一个页头。”

**优化版本：**“创建一个固定页头组件，左侧放置网站徽标，右侧放置导航链接 (首页、关于、联系) 。”

<div id="resumo">
  ## 总结
</div>

高效的提示词离不开这几点：

* 在编写提示词之前先**规划**
* **逐步构建**——Agent 工作时会自动创建 checkpoint
* 清晰地**描述预期结果**
* 通过示例和相关文件**提供上下文**
* 结果不够理想时及时**迭代**

让提示词保持简短、聚焦结果、易于执行，你就能借助 Agent 更快地完成构建。
