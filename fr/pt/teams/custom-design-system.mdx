Un système de design donne à l&#39;Agent les connaissances nécessaires pour construire une interface fidèle à la marque dans tout ce que votre organisation crée sur Replit : applications web, applications mobiles, diaporamas et autres artefacts. En configurant votre bibliothèque de composants, vos tokens de design, vos ressources de marque et vos règles d&#39;utilisation au sein du monorepo pnpm standard de Replit, vous permettez à l&#39;Agent d&#39;appliquer votre langage visuel dès le premier prompt.

<Note>
  Les systèmes de design sont disponibles exclusivement dans le plan **Enterprise**. Seuls les administrateurs de l&#39;organisation peuvent configurer et gérer les systèmes de design.
</Note>

<div id="por-que-configurar-um-sistema-de-design">
  ## Pourquoi mettre en place un système de design
</div>

Sans système de design, chaque développeur doit expliquer manuellement à Agent sa bibliothèque de composants, ses tokens de couleur et ses conventions de mise en page. Mettre en place un système de design résout ce problème en :

* **Codifiant vos conventions visuelles** : Agent utilise vos composants, couleurs et espacements exacts — pas des valeurs génériques par défaut
* **Garantissant la cohérence** : chaque application suit le même langage de design
* **Réduisant le temps d&#39;intégration** : les nouveaux développeurs produisent immédiatement des résultats conformes à la marque
* **Capturant les connaissances tacites** : les décisions de design et les usages des composants qui n&#39;existent que dans la tête de votre équipe sont documentés pour Agent

<div id="o-que-voc-vai-precisar">
  ## Ce dont vous aurez besoin
</div>

* Une bibliothèque de composants front-end sous forme de tarfile ou d&#39;un ensemble de tarfiles
* Les polices et icônes utilisées dans votre système de design
* Toute documentation destinée à l&#39;IA de votre système de design (MCP, Compétences Agent)

<div id="o-que-voc-pode-configurar">
  ## Ce que vous pouvez configurer
</div>

La configuration d&#39;un système de design comporte trois volets :

1. **Instructions personnalisées**. Votre fichier `custom_instruction/instructions.md` fournit à Agent les règles générales qui s&#39;appliquent à chaque projet : quelle bibliothèque de composants utiliser, quels tokens de design référencer et quels patterns suivre. Agent a toujours ce fichier dans son contexte.

2. **Compétences**. Les compétences placées dans `.agents/skills/` fournissent une documentation de référence détaillée qu&#39;Agent charge à la demande. Utilisez-les pour la documentation de l&#39;API des composants, les guides de thèmes, les bibliothèques de patterns de mise en page et tout autre contenu de référence approfondi qui serait trop volumineux pour le fichier d&#39;instructions principal.

3. **Ressources de design et de marque**. Placez vos logos, icônes, polices et autres ressources de marque dans un dossier dédié (par exemple, `src/assets/brand/`). Configurez un alias de chemin Vite afin qu&#39;Agent et les développeurs puissent les référencer avec des importations claires comme `@brand/logo.svg` plutôt qu&#39;avec des chemins relatifs fragiles. Les références aux assets restent ainsi cohérentes dans tout le projet.

<div id="guia-passo-a-passo">
  ## Guide pas à pas
</div>

Ce guide vous accompagne dans la mise en place d&#39;un système de design de bout en bout à partir de votre bibliothèque de composants existante, empaquetée sous forme de tarfiles :

1. **Créez une nouvelle app Replit** et téléversez vos tarfiles.
2. **Demandez à Replit Agent d&#39;installer les paquets et d&#39;afficher tous les composants.** Agent configurera le projet et affichera votre bibliothèque de composants.
3. **Vérifiez le résultat.** Assurez-vous que tous les composants s&#39;affichent correctement et correspondent à vos attentes. Une fois tout validé, passez à [Création de la compétence du système de design](#criando-a-skill-do-sistema-de-design).

<div id="criando-a-skill-do-sistema-de-design">
  ### Créer la compétence du système de design
</div>

Une fois vos composants prêts, la dernière étape consiste à créer une compétence pour votre système de design afin que l’Agent puisse s’appuyer sur vos composants, tokens et modèles d’utilisation dans chaque projet.

Copiez le prompt complet ci-dessous et collez-le dans l’Agent. Remplacez `<nome-do-seu-sistema-de-design>` par le nom de votre système de design :

````
Create a `<nome-do-seu-sistema-de-design>` design system skill from the components and packages in this project.

Use the file structure shown below with a `SKILL.md` at the root, a `references/` directory for guides and component docs, and a `packages/` directory containing all dependencies needed to function.

Go through every component in the project and document each one in its own file under `references/components/`, including its props, variants, and example usage.

Format `SKILL.md` as an index that links out to the guide and component reference files, with a "General Guidance" section and a "Components" section, following the example shown below.

File structure:

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (Tar files or code components)

The `SKILL.md` file acts as an index that links out to separate markdown files for guides and component references. Each linked file covers one topic in detail. Here is an example of what the generated `SKILL.md` looks like:

```markdown
---
name: your-design-system
description: Use when building or modifying any UI. Provides component API references, layout guidance, and visual style rules for your design system.
---

# Your Design System

## General Guidance

- [Setup](references/guides/setup.md) — Installation, project configuration, and provider setup
- [Guardrails](references/guides/guardrails.md) — Hard rules that must never be broken (banned patterns, required tokens, accessibility minimums)
- [Layout & Spacing](references/guides/layout-and-spacing.md) — Grid system, spacing scale, responsive breakpoints, and page templates
- ...

## Components

- [Component Index](references/components/component-index.md) — Full list of available components with status and category

Individual component references (props, variants, examples):

- [Button](references/components/button.md)
- [Checkbox](references/components/checkbox.md)
- ...
```

Guide files cover one topic each — setup and installation steps, best practices and rules, reference tables for token values, and short code examples showing correct usage.

Component files document a single component each, including the component name, a brief description, a props table, usage examples, and any guidelines or constraints. The more complete these files are, the better Agent's output will be.
````

<div id="conecte-sua-skill-ao-agent">
  ### Connectez votre compétence à Agent
</div>

Une fois la compétence créée, assurez-vous que votre fichier `custom_instruction/instructions.md` oriente bien Agent vers celle-ci :

```markdown theme={null}
# Système de design

Lisez et suivez la compétence de système de design située dans `.agents/skills/your-design-system/`.
Appliquez toujours le système de design lors de la création ou de la modification de l'interface.
```

Enfin, préremplissez le fichier `replit.md` avec du contexte propre à votre système de design afin qu&#39;Agent comprenne vos conventions visuelles dès le départ. Indiquez une vue d&#39;ensemble du projet, votre bibliothèque de composants préférée, vos principales préférences de design (échelle d&#39;espacement, exigences d&#39;accessibilité) ainsi que la stack d&#39;architecture.

<div id="valide-sua-configurao">
  ### Validez votre configuration
</div>

Avant de déployer votre système de design, vérifiez ces éléments essentiels :

* `custom_instruction/instructions.md` oriente Agent vers la compétence du système de design
* `.agents/skills/` contient la compétence avec les références de composants, les guides et les paquets
* `replit.md` est prérempli avec la vue d&#39;ensemble du projet, les préférences et l&#39;architecture
* Le fichier de tokens de design est inclus (`tokens.css` ou équivalent)
* Le paquet du système de design est préinstallé dans `package.json`
* Créez une nouvelle app de test et vérifiez qu&#39;Agent utilise correctement le système de design

<div id="fixe-o-sistema-de-design-na-sua-organizao">
  ### Épinglez le système de design dans votre organisation
</div>

Une fois votre système de design prêt, épinglez-le afin que tous les membres de l&#39;organisation puissent l&#39;utiliser :

1. Accédez à l&#39;app du système de design dans votre organisation
2. Ouvrez le menu d&#39;actions de l&#39;app (menu à trois points)
3. Sélectionnez **Épingler à la zone de saisie de l&#39;Agent**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Menu d'actions de l'app affichant l'option Épingler à la zone de saisie de l'Agent" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Seuls les administrateurs de l&#39;organisation (membres du rôle `system_admins`) peuvent épingler et désépingler des systèmes de design.
</Note>

Définissez l&#39;accès des membres sur **Lecture seule** afin qu&#39;ils puissent consulter et utiliser le système de design épinglé sans pouvoir le modifier.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Boîte de dialogue d'invitation affichant l'accès des membres défini sur Lecture seule" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Le système de design apparaît désormais sous forme de pastille sélectionnable sous la zone de saisie de l&#39;Agent pour tous les membres de votre organisation. Pour le retirer, ouvrez ce même menu et sélectionnez **Désépingler de la zone de saisie de l&#39;Agent**.

<div id="mantenha-seu-sistema-de-design-atualizado">
  ## Maintenez votre système de design à jour
</div>

Les systèmes de design évoluent. Gardez le vôtre à jour :

* **Mettez à jour les fichiers de tokens** lorsque votre système de design introduit de nouvelles valeurs de couleurs, d&#39;espacement ou de typographie
* **Mettez à jour les compétences** lorsque les composants reçoivent de nouvelles props, variantes ou modèles d’utilisation
* **Mettez à jour les instructions** lorsque les principes ou les standards de design évoluent
* **Mettez à jour les versions des paquets** lorsque de nouvelles versions de votre système de design sont publiées
* **Testez régulièrement** en créant une nouvelle app et en vérifiant qu&#39;Agent produit le résultat attendu

<div id="sistemas-de-design-vs-templates-personalizados">
  ## Systèmes de design ou templates personnalisés
</div>

Les systèmes de design et les [templates personnalisés](/fr/pt/teams/custom-templates) répondent à des besoins différents :

|                         | Systèmes de design                                                                                   | Templates personnalisés                                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Objectif**            | Remplacer la stack frontend par celle de votre équipe et utiliser vos composants de code             | Remplacer complètement la stack par défaut (par exemple Rust, Go, C++)                     |
| **Stack**               | Fonctionne au sein du monorepo pnpm standard de Replit                                               | Définit une structure de projet entièrement personnalisée                                  |
| **Ce que cela fournit** | Règles de bibliothèque de composants, tokens de design, ressources de marque, compétences visuelles  | Boilerplate complet : runtime, configuration de build, dépendances, organisation du projet |
| **S&#39;applique à**    | Applications web, applications mobiles, présentations, artefacts — tout ce que l&#39;Agent construit | Uniquement les apps créées à partir de ce template précis                                  |

Utilisez un système de design lorsque vous souhaitez que l&#39;Agent respecte vos standards visuels dans l&#39;expérience Replit habituelle. Optez pour un template personnalisé lorsque vous avez besoin d&#39;une stack fondamentalement différente.
