Каждое Replit App использует две базы данных. **База данных для разработки** — это пространство для экспериментов во время работы над App вместе с Agent. **Продакшн-база данных** хранит реальные данные опубликованного App и надёжно защищает их, пока вы продолжаете разработку.

<div id="section">
  ## Сравнение двух баз данных
</div>

| Аспект             | База данных для разработки                                 | Продакшн-база данных                                           |
| ------------------ | ---------------------------------------------------------- | -------------------------------------------------------------- |
| **Назначение**     | Эксперименты и разработка функций                          | Обслуживание реальных пользователей и хранение бизнес-данных   |
| **Данные**         | Тестовые данные, фиктивные записи, небольшие наборы данных | Данные реальных пользователей, важная для бизнеса информация   |
| **Время создания** | Автоматически создаётся для всех Replit App                | При публикации App                                             |
| **Agent**          | Agent может создавать и изменять таблицы                   | Agent не имеет доступа                                         |
| **Изменения**      | Частые изменения схемы и быстрые итерации                  | Тщательно спланированные изменения, применяемые при публикации |
| **Платёж**         | Бесплатно включена во все Replit App                       | В зависимости от использования                                 |

<Note>
  Agent не может изменять продакшн-базу данных. Это ограничение обеспечивает безопасность продакшн-базы данных.

  Agent может изменять базу данных для разработки. При публикации все изменения структуры базы данных для разработки, внесённые Agent (добавление и удаление столбцов и таблиц), также применяются к продакшн-базе данных.

  Вы можете вручную редактировать продакшн-данные в любое время: откройте инструмент **Database**, выберите продакшн-базу данных, затем откройте **My Data** и включите **Edit**.
</Note>

<div id="section-2">
  ## Создание продакшн-базы данных при публикации
</div>

У опубликованного App будет собственная продакшн-база данных, отдельная от базы данных для разработки, используемой при создании App.

* **Текущая инфраструктура (Helium)**: при необходимости Replit автоматически создаёт продакшн-базу данных в процессе публикации. Дополнительная настройка не требуется.
* **Устаревшая база данных для разработки Neon**: создайте продакшн-базу данных в настройках публикации. В процессе публикации откройте **Production database settings** и включите **Create production database**. Чтобы также скопировать данные разработки, включите **Set up your production database with your current development data**.

<Frame caption="Настройки продакшн-базы данных в Publishing">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="Настройки публикации с параметром Create production database" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  Копируйте данные разработки в продакшн только в том случае, если их безопасно использовать в опубликованном App. Данные разработки могут содержать тестовые учётные записи, примеры записей или незавершённый контент.
</Warning>

После завершения публикации опубликованный App использует продакшн-базу данных, а Project Editor продолжает использовать базу данных для разработки, поэтому последующие изменения в процессе разработки не будут напрямую затрагивать реальные данные.

<div id="section-3">
  ## Пулинг соединений
</div>

По умолчанию пулинг соединений для продакшн-базы данных отключён. App подключается к базе данных напрямую через строку подключения `DATABASE_URL`, поэтому большинству фреймворков необходимо самостоятельно управлять пулом соединений на стороне клиента.

<Note>
  Каждый проект Neon содержит как строку прямого подключения, так и строку подключения через пул. Строка прямого подключения выглядит так: `postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`.

  Чтобы использовать подключение через пул, добавьте `-pooler` к имени хоста: `postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`.
</Note>

Если строка подключения к продакшн-базе данных была скомпрометирована, [пересоздайте учётные данные продакшн-базы данных](/ru/ko/features/data-and-storage/connection-details#regenerate-production-database-credentials).

<div id="section-4">
  ## Безопасное изменение продакшн-базы данных
</div>

При публикации обновлений, включающих изменения в базе данных, некоторые из них требуют тщательного планирования, чтобы избежать простоя или потери данных.

<Info>
  Во время публикации в опубликованном App возможен кратковременный простой. Иногда App необходимо временно остановить, чтобы избежать конфликтов и защитить данные при применении изменений в базе данных.
</Info>

Следующие типы изменений обычно требуют особой осторожности:

* **Удаление столбцов базы данных**, на которые всё ещё ссылается код приложения
* **Изменение типа данных столбца** таким образом, что существующий код не сможет его обработать
* **Добавление обязательных полей** без значений по умолчанию в существующие таблицы
* **Переименование таблиц или столбцов**, нарушающее существующие запросы
* **Изменение ограничений**, которое может сделать существующую логику приложения недопустимой

<div id="section-5">
  ### Тестирование изменений с помощью предварительного деплоя
</div>

Предварительный деплой — это временная изолированная копия продакшен-окружения, в которой можно протестировать изменения в базе данных и обновления App до того, как они затронут реальных пользователей. Используйте его, чтобы:

* убедиться, что App продолжает корректно работать во всех ключевых пользовательских сценариях после внесения изменений в базу данных
* проверить, что существующие данные были корректно мигрированы, а новые поля содержат ожидаемые значения
* убедиться, что время ответа на запросы не увеличилось

<div id="section-6">
  ## Биллинг и использование ресурсов
</div>

Плата за продакшн-базы данных рассчитывается по факту использования через Neon — поставщика бессерверных баз данных. Если база данных неактивна в течение 5 минут, она переходит в режим простоя, и тарификация вычислительного времени приостанавливается. При поступлении запроса она немедленно активируется снова.

На главном экране инструмента Database отображаются **Billing Period** и **Hours of Compute Used**. Чтобы посмотреть использование хранилища для конкретной базы данных, откройте вкладку **Settings** этой базы данных. Чтобы проверить использование во всех Replit App, откройте **Settings** → **Account** → **Account usage** и разверните строки **PostgreSQL Storage** и **PostgreSQL Compute**.

Чтобы узнать, как Replit взимает плату за использование базы данных, см. [Тарифы на деплой и базы данных](/ru/ko/billing/about-usage-based-billing#databases).

<div id="section-7">
  ## Удаление продакшн-базы данных
</div>

<Warning>
  Через 7 дней удаление нельзя будет отменить. Перед продолжением обязательно создайте резервную копию важных данных. База данных будет находиться в состоянии мягкого удаления в течение 7 дней, и в этот период её можно восстановить. Если вам нужна помощь, обратитесь в службу поддержки. По истечении 7 дней база данных будет удалена без возможности восстановления.
</Warning>

<Accordion title="Как удалить базу данных">
  В инструменте **Database**:

  1. Выберите базу данных и откройте вкладку **Settings**
  2. Выберите **Remove database**, затем подтвердите действие, выбрав **Yes, Remove database**
</Accordion>

<div id="section-8">
  ## Устаревшие базы данных для разработки
</div>

До 4 декабря 2025 года базы данных для разработки размещались на <a href="https://neon.com/" target="_blank">Neon</a>. Все новые базы данных для разработки размещаются в собственной инфраструктуре Replit (Helium). Узнать, что использует ваш App, можно на вкладке **Settings**. Если `DATABASE_URL` содержит `neon.tech`, используется устаревшая инфраструктура Neon, а если `helium` — текущая инфраструктура.

| **Функция**                  | **Replit (текущая)**                                                                                                                        | **Neon (устаревшая)**                                                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Хостинг**                  | Размещается в собственной инфраструктуре Replit                                                                                             | Размещается на Neon (сторонний поставщик)                                                                                                               |
| **Биллинг**                  | Бесплатно включено для всех Replit App                                                                                                      | Оплата по факту использования. Подробнее см. в разделе [биллинга публикаций и баз данных](/ru/ko/billing/about-usage-based-billing#databases).             |
| **Восстановление**           | Восстановление базы данных до любого чекпоинта с помощью [функции отката](/ru/ko/features/data-and-storage/data-recovery)                      | Восстановление на определённый момент времени (PITR): восстановление до любого момента в пределах срока хранения резервных копий.                       |
| **Безопасность подключения** | Доступно только внутри App и никогда не раскрывается внешним пользователям.                                                          | Используется полная строка подключения. В случае утечки любой сможет получить доступ к базе данных и изменить её.                                       |
| **Поведение ремикса**        | [Ремикс](/ru/ko/features/projects-and-artifacts/remix-an-app) создаёт новую базу данных для разработки с копией данных для изоляции и безопасности | Ремикс повторно использует одну и ту же базу данных во всех копиях, поэтому изменения в ремиксе могут повлиять на исходный App.                  |
| **Создание базы данных**     | Автоматически создаётся для каждого Replit App.                                                                                             | Требуется явная настройка.                                                                                                                              |
| **Процесс публикации**       | При публикации создаётся отдельная продакшн-база данных для изоляции между окружениями.                                                     | Для разработки и продакшна использовалась одна база данных, поэтому непреднамеренные изменения при разработке могли повлиять на App в продакшне. |

<div id="section-9">
  ## Обновление инфраструктуры базы данных
</div>

Replit переводит базы данных для разработки с Neon на собственную управляемую инфраструктуру PostgreSQL **Helium**. Обновление выполняется автоматически, запускается один раз для каждого App при его открытии в Project Editor и сохраняет все данные.

Вот что изменится:

* **Меньше задержка и больше места для хранения**: база данных будет работать в инфраструктуре Replit вместе с вашим App, а лимит хранилища увеличится с 10 ГБ до 20 ГБ.
* **Тот же движок базы данных**: Helium использует PostgreSQL 16 — ту же версию, что и Neon. Запросы, схемы и данные будут работать так же.
* **Подключение обновляется автоматически**: `DATABASE_URL` будет обновлён и начнёт указывать на Helium. Предыдущая строка подключения Neon будет сохранена в Secrets как `NEON_DATABASE_URL` для справки.
* **Отдельные переменные PG удаляются**: `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` будут удалены. Вместо них используйте `DATABASE_URL`.

Во время обновления будет отображаться экран выполнения **«Обновление базы данных»**. Для крупных баз данных это может занять от нескольких минут до нескольких часов; вы можете закрыть вкладку и вернуться позже. Если во время обновления возникнет проблема, оно будет автоматически пропущено, а повторная попытка будет выполнена при следующем открытии App. После завершения появится диалоговое окно подтверждения.

Большинству разработчиков не потребуется предпринимать дополнительные действия. Проверьте следующее, если это относится к вам.

* **Жёстко заданные строки подключения Neon**: обновите код, который ссылается на строки подключения `neon.tech`, чтобы вместо них использовать переменную окружения `DATABASE_URL`.
* **Пользовательские роли PostgreSQL**: роли и разрешения будут перенесены автоматически, но пароли скопировать нельзя. Сбросьте пароли пользовательских ролей в новой базе данных.

<div id="ssl">
  ### Ошибка SSL-подключения после обновления
</div>

Если появляется ошибка вроде `The server does not support SSL connections`, значит код подключения принудительно выполняет SSL-рукопожатие. Neon требовал SSL, но Helium запускается локально вместе с вашим App и не использует SSL. Настраивайте SSL условно в зависимости от окружения.

<CodeGroup>
  ```js JavaScript theme={null}
  // До обновления (перестаёт работать после обновления)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // После обновления (работает и в среде разработки, и в продакшене)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  Если вы используете ORM, например Drizzle, Prisma или Sequelize, обратитесь к соответствующей документации, чтобы узнать, как настроить SSL условно. Применяется тот же принцип: отключайте SSL для базы данных для разработки и включайте его в продакшене.
</Tip>

<div id="section-10">
  ### Форкнутые App с общей базой данных
</div>

В устаревшей системе Neon при форке App копировалась переменная `DATABASE_URL` исходного App, поэтому оба App и их опубликованные версии подключались к одной базе данных. Поддержка общих устаревших баз данных была прекращена **8 июня 2026 года**. Если опубликованный App перестал работать или потерял доступ к данным, ознакомьтесь с разделом [Как исправить опубликованные App, использующие общую базу данных](/ru/ko/features/data-and-storage/shared-database-migration) или [обратитесь в службу поддержки](https://replit.com/support).
