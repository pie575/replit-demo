每次成功 Publish 后，Replit 都会执行 SEO 审计并显示 SEO 评级。如果评级还有提升空间，只需点击一下，即可将具体问题交给 Agent。对大多数构建者来说，工作流很简单：**发布 → 查看评级 → 请 Agent 优化**。

有关评级计算方式的详细信息 (Lighthouse 审计、各评级的含义以及支持的部署类型) ，请参阅 [SEO 评级](/zh/features/publishing/seo-rating)。

<div id="optimize-with-seo-agent">
  ## 使用 SEO Agent 优化
</div>

[SEO Agent](/zh/features/publishing/seo-agent) 会对已发布的 App 进行技术 SEO 审计，并将每项发现转化为一键修复。它位于 Project Editor 的 **Growth** 窗格中，付费套餐的构建者可使用。请按以下步骤扫描你的 App 并应用修复。

<Steps>
  <Step title="发布 App 以解锁 Growth">
    SEO Agent 适用于已发布的 App。在发布之前，**Growth** 窗格会被锁定，并提示你前往 **Go to Publishing**。通过 Agent chat 或 **Publishing** 工具发布后，再返回 Growth 窗格。

    <Frame caption="发布前，Growth 窗格会被锁定并显示 Go to Publishing 提示">

    </Frame>
  </Step>

  <Step title="使用 Agent 运行扫描">
    打开 **Growth** 窗格，找到 **SEO 评级** 卡片。选择 **Run scan with Agent**，对你的 project 开始进行技术 SEO 审计。扫描通常需要几分钟。

    <Frame caption="在 SEO 评级卡片中选择 Run scan with Agent 以开始审计">
      <img src="/assets/mirror/02-run-scan-94a2b8918fe9.png" alt="SEO 评级卡片的放大视图，红色矩形突出显示 Run scan with Agent 按钮" width="1656" height="946" data-path="images/deployments/seo-agent/02-run-scan.png" />
    </Frame>
  </Step>

  <Step title="使用 Agent 修复或使用 Agent 修复全部">
    扫描完成后，问题会显示在表格中，包含 **Severity** (Low、Medium 或 High) 和 **Status** (Unresolved) 列，并按 **AI Readiness**、**Crawlability &amp; Discovery**、**Landing Page Rendering &amp; Metadata** 和 **Performance Proxies** 等类别分组。展开任意问题即可查看 SEO Agent 的发现。

    你可以按需要的粒度应用修复：

    * 对单个问题使用 **Fix with Agent**，仅将该问题交给 Agent。
    * 对某个类别使用 **Fix with Agent**，可修复该组中的所有问题。
    * **Fix all with Agent** 会一次将所有问题交给 Agent。聊天中的 **Fix all issues** 按钮也能执行相同操作。

    Agent 会为每个问题创建一个修复 task，并在后台逐项处理，因此你可以继续构建。各行会更新为 **Fix in progress**，你可通过 **Go to task** 链接打开任意 task 并查看进度。

  <Step title="将更改应用到主版本">
    修复准备就绪后，task 会显示 **Ready for review** 状态。查看更改后，选择绿色的 **Apply changes to main version** 按钮，将修复合并到你的 App 中。重新发布，以根据新 build 刷新 SEO 评级。

<Tip>
  你也可以完全跳过扫描界面。打开 Agent 并说 **“优化我的
  SEO”**——Agent 会获取你最新的检测结果并开始逐项处理。
</Tip>

Agent 常见的修复包括：

* 添加或重写缺失或过于通用的 `<title>` 标签，确保每个页面都有唯一且描述清晰的标题。
* 为每个页面添加 meta description。
* 为图片添加描述性的 `alt` 文本。
* 在 `<html>` 元素上设置 `lang` 属性。
* 确保链接具有可辨识的文本 (不使用“点击这里”或空锚点) 。
* 添加 `robots.txt` 和 `sitemap.xml`。
* 添加用于移动端渲染的 viewport meta 标签。
* 改善未通过无障碍检查的文本颜色对比度。
* 添加 Open Graph 和 Twitter card meta 标签，让指向你的 App 的链接能在社交平台上获得良好的预览效果。

<div id="best-practices-for-an-seo-optimized-app">
  ## SEO 优化 App 的最佳实践
</div>

无论是让 Agent 帮你完成这些工作，还是自己编写，以下都是最需要优先做好的事项：

* **为每个页面设置唯一的标题和元描述。** 标题尽量控制在 60 个字符以内，描述控制在约 150–160 个字符。
* **使用语义化 HTML。** 使用 `<main>`、`<header>`、`<nav>` 和 `<footer>` 组织页面布局。每个页面只使用一次 `<h1>`，并按顺序设置标题层级。
* **为每张图片添加 alt 文本。** 描述图片呈现的内容，而不只是说明它是什么。
* **生成 `sitemap.xml` 和 `robots.txt`。** 请 Agent 创建这两个文件，让搜索引擎知道该抓取哪些内容。
* **添加 Open Graph 和 Twitter 卡片标签。** 控制你的 App 在社交媒体上分享时的显示效果。
* **使用自定义域名。** 品牌域名能同时赢得访客和搜索引擎的信任。请参阅[添加自定义域名](/zh/build/add-custom-domain)。
* **选择合适的部署类型。** 对于内容丰富的网站，[静态部署](/zh/features/publishing/deployment-types#static)可提供预渲染的 HTML，供搜索引擎即时解析。
* **添加结构化数据。** JSON-LD 标记可帮助搜索引擎为产品、文章、常见问题和活动展示富媒体搜索结果。
* **保持 App 快速运行。** 优化图片，避免使用阻塞渲染的脚本，并借助 Replit 的托管服务保持较低的响应时间。

以下是一种可一次性落实其中大部分实践的简单方法：

<div id="need-further-help">
  ## 还需要帮助？
</div>

* **重新发布后评级未更新：**请等待一两分钟——部署上线后会异步执行审计，结果出来后徽章会自动刷新。
* **Agent 修改后评级没有变化：**询问 Agent 具体处理了哪些 Lighthouse 项目，然后查看徽章的工具提示，了解哪些项目仍被标记。
* **某些页面的评级低于其他页面：**徽章会显示所有已爬取 URL 中的最低评级。请让 Agent 专注处理 Lighthouse 标记的特定页面。
* **已发布的 App 上未显示评级：**SEO 评级仅适用于面向公众的 Web 部署类型 (Autoscale、Reserved VM、Static) 。定时部署和私有部署不会生成评级。
