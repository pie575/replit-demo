    * **在真机上使用 Expo Go**：在 iPhone 或 Android 设备上安装 [Expo Go](https://expo.dev/go)。在 Project Editor 的 Preview 面板中选择 **Open in Expo Go**，然后扫描二维码。

  <Step title="与 Agent 一起迭代">

<Tip>

</Tip>

<div id="preview-on-a-simulator-or-emulator">
  ## 在模拟器或仿真器中预览
</div>

Replit 支持你使用 Expo 在手机上运行和测试移动应用。此外，Replit 还能将真实的 **iOS 模拟器** 或 **Android 模拟器** 直接投流到 Preview 面板中。你通过 Agent 所做的修改会在模拟器中热重载，与在真机上的效果一致。

<Note>
  iOS 模拟器 和 Android 模拟器 预览功能面向 Core、Pro 和 Enterprise 套餐的构建者开放。仅支持移动应用——纯 Web 的 project 不会显示该选项。
</Note>

<div id="browser-support">
  ### 浏览器支持
</div>

* 完全支持 **Chrome**、**Safari** 以及基于 Chromium 的浏览器。
* 不支持 **Firefox**。在 Firefox 中打开 Replit 时，iOS 和 Android 选项会呈灰色禁用状态，并显示“Firefox not supported”提示。这是模拟器所依赖的流式传输技术导致的限制。

<div id="when-to-use-expo-go-instead">
  ### 何时改用 Expo Go
</div>

当你需要测试依赖真实硬件的功能，或者想把预览分享给不在你电脑旁的人时，可以在真机上使用 Expo Go：

* 摄像头、麦克风、触感反馈或其他原生传感器
* 推送通知
* 真实环境下的 GPS 定位
* 与队友、测试人员或投资人分享开发预览

要在 Expo Go 中打开应用，请在 [replit.com](https://replit.com) 上打开该 project，在 Project Editor 的 Preview 面板中选择 **Open in Expo Go**，然后用手机上的 [Expo Go](https://expo.dev/go) 应用扫描二维码。

<div id="fullscreen-simulator">
  ### 全屏模拟器
</div>

在移动端 artifact 卡片上，选择 **More actions** → **Open in iOS 模拟器** 或 **Open in Android 模拟器**，即可在独立标签页中打开模拟器，获得更大的显示区域。

<div id="why-build-a-mobile-app">
  ## 为什么要构建移动应用？
</div>

当你有以下需求时，可以构建移动应用：

* **原生体验**：性能出色、交互流畅，界面符合平台原生风格。
* **设备能力**：相机、推送通知、定位等。
* **App Store 分发**：通过 Apple App Review 后，即可获得可分享的应用页面，供用户发现并安装。

<div id="key-features">
  ## 主要功能
</div>

* **AI 优先的创建方式**：只需描述你的应用，Agent 就能搭建出一个可运行的移动应用。
* **Project Editor 预览**：无需离开 Replit，即可在 iOS 模拟器或 Android 模拟器上测试，也可以用 Expo Go 在手机上预览。
* **默认 full-stack**：随着应用不断迭代，可随时添加服务器路由、Database、App Storage、Connectors 以及 AI 集成。
* **引导式提交**：无需管理本地 iOS 工具链，即可准备好用于 TestFlight 和 App Store 提交的构建版本。

<div id="development-workflow">
  ## 开发工作流
</div>

访问应用有三个阶段，每个阶段面向的用户和支持的功能各不相同：

| 阶段            | 谁可以访问            | 如何访问                                | 适用场景         |
| ------------- | ---------------- | ----------------------------------- | ------------ |
| **开发**        | 你本人              | Project Editor 模拟器，或用 Expo Go 扫描二维码 | 构建与迭代        |
| **部署**        | 使用 Expo Go 的测试人员 | 带二维码的公开 URL                         | 开发预览、原型演示与展示 |
| **App Store** | 所有人              | 通过 App Review 后从 App Store 下载       | 正式发布         |

**开发**：启动应用后，你可以在 Project Editor 的 **iOS 模拟器** 或 **Android 模拟器** 中预览，也可以扫描 Preview 面板中的二维码，在手机上用 Expo Go 打开。

**部署**：点击 **Publish** 后，Replit 会创建一个带 Expo Go 二维码的公开 URL。这非常适合开发预览和原型演示——在正式进入 App Store 流程之前，可以展示给投资人、收集反馈，或与朋友一起测试。

**App Store**：提交到 App Store 后，Apple 会审核你的应用。审核通过后，所有人都可以从 App Store 下载并安装。此方式需要 Apple Developer 账户。

<div id="publishing-overview">
  ## Publishing 概览
</div>

准备 iOS 发布时，通常的流程如下：

* 在 Project Editor 中发布
* 将构建版本提交到 TestFlight
* 在 App Store Connect 中将 TestFlight 构建版本发布到 App Store

<Note>
  要向 TestFlight 和 App Store 提交构建版本，Apple 要求你拥有 Apple Developer Program 会员资格。
</Note>

完整操作步骤请参阅[构建并发布移动应用](/zh/build/mobile-app)教程。

<div id="where-to-build-native-mobile-apps">
  ## 在哪里构建原生移动应用
</div>

你的 Replit 环境运行在云端，而非本地机器上。要构建原生移动应用，请在 [replit.com](https://replit.com) 使用 Project Editor。整个移动应用工作流——Agent 生成项目骨架、Expo Go 预览、模拟器与仿真器测试、TestFlight 构建以及提交到 App Store——都在 Project Editor 中完成。

在受支持的情况下，也可以在 [Replit Android 应用](/zh/features/platforms/mobile-app)中进行原生移动应用开发。如果你使用的是 Replit iOS 应用，请在 [replit.com](https://replit.com) 上打开 project，以创建、预览、构建或提交原生移动应用。

<div id="how-the-technology-works">
  ## 技术原理
</div>

你的移动应用由一系列协同工作的技术构建而成。本节将介绍支撑应用运行的技术，以及各部分之间如何协作。

<div id="the-technology-stack">
  ### 技术栈
</div>

<MobileStackDiagram />

* **React Native** 是一个开源框架，让你只需编写一套代码，即可编译到 iOS、Android 和 Web 平台。它渲染的是平台原生 UI 组件，而非 webview。
* **Expo** 负责处理构建、管理原生模块，并提供 Expo Go 等预览工具，从而简化 React Native 的开发流程。
* **Expo Go** 是一款安装在手机上的免费应用。它可以运行你的开发预览，让你无需构建完整的原生二进制包就能在真机上测试。

运行应用时，Metro 打包器会编译你的代码并推送到设备上。首次构建因为没有缓存，耗时会长一些，之后的构建则会快很多。

<div id="architecture-server-and-client">
  ### 架构：服务器与客户端
</div>

在准备预览或分发移动应用时，你需要面对两个部分：

1. **服务器**：运行在云端的 Replit 上，负责数据库、API 路由、AI 集成和后端逻辑。
2. **客户端应用**：运行在用户的手机上，即开发阶段在 Expo Go 中预览、审核通过后经由应用商店分发的原生应用。

<MobileArchitectureDiagram />

这种分离带来了灵活性：复杂逻辑可以放在服务器上运行 (在那里可以使用 Replit 的 Database、Object Storage 和 Connectors) ，客户端则保持轻量。在构建过程中，不妨想清楚哪些工作应该在手机上完成，哪些应该交给云端。

<div id="considerations">
  ## 注意事项
</div>

* **发布要求**：TestFlight 和 App Store 的要求由 Apple 制定，iOS 应用在分发前需经 Apple 审核。
* **Android 发布**：你可以构建同时支持 iOS 和 Android 的跨平台应用。目前还不支持通过引导式流程发布到 Google Play，但可以手动完成。
* **原生改动**：修改应用图标、权限等内容通常需要重新构建用于上架的版本。

<div id="faqs">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="什么是 Expo？">
    Expo 是 Agent 在 Replit 上构建移动应用时使用的工具。它是一个开源平台和工具链，用于基于 React Native 构建、运行和部署跨平台原生应用。了解更多请访问 [https://expo.dev](https://expo.dev)。
  </Accordion>

  <Accordion title="什么是 React Native？">
    React Native 是 Meta 推出的开源框架，可使用 React 和 JavaScript 或 TypeScript 构建 iOS 和 Android 原生应用。它渲染的是平台原生 UI 组件 (而非 webview) ，因此你的应用在外观和体验上都与原生应用无异。
  </Accordion>

  <Accordion title="什么是 Expo Go？">
    Expo Go 是一款免费应用，可从 App Store 或 Google Play 安装到手机上。借助它，你无需构建完整的原生二进制包即可在开发过程中预览移动应用。当你在 Project Editor 中扫描二维码时，Expo Go 会下载并运行你的应用代码。
  </Accordion>

  <Accordion title="Expo Go 与开发构建（dev build）有什么区别？">
    **Expo Go** 是一款预先构建好的应用，用于运行你的代码。它设置起来很快，但仅支持 Expo SDK 中包含的模块。

    **开发构建**是可包含任意原生模块的自定义原生二进制包。它需要更多配置 (EAS Build 或本地 Xcode/Android Studio) ，但灵活性更高。

    Replit 使用 Expo Go 进行开发预览。如果你需要 Expo Go 不支持的原生模块，可以查阅 [Expo 文档](https://docs.expo.dev/develop/development-builds/introduction/)了解开发构建。
  </Accordion>

  <Accordion title="这与移动端自适应的 web app 有什么区别？">
    移动端自适应的 web app 本质上是一个能在浏览器中自动调整布局的网站。而 React Native 应用是安装在设备上的原生应用，可调用平台 API (相机、触感反馈、推送通知) ，能更好地访问硬件、支持离线能力，并通过应用商店分发。自适应网页胜在触达范围广、免安装；而当你需要设备功能、性能或 App Store 分发时，原生应用是最佳选择。
  </Accordion>

  <Accordion title="我需要 Mac 或 Xcode 吗？">
    不需要。Replit 和 Expo 会在云端替你完成构建过程。
  </Accordion>

  <Accordion title="没有 Apple Developer 账户可以预览吗？">
    可以。你可以在 Project Editor 的 iOS 模拟器中预览，或在手机上使用 Expo Go 预览。只有当你准备提交到 TestFlight 或 App Store 时，才需要 Apple Developer 账户。
  </Accordion>

  <Accordion title="支持 Android 吗？">
    支持。你可以基于同一套代码库构建面向 iOS 和 Android 的跨平台应用，并在 Project Editor 的 Android 模拟器中预览，或在 Android 设备上使用 Expo Go 预览。发布到 Google Play 可手动完成。
  </Accordion>

  <Accordion title="服务器和数据库怎么办？">
    直接使用 Replit 内置的 PostgreSQL、Object Storage、Connectors 和 AI 集成——无需单独搭建基础设施。你的服务器在 Replit 上运行，移动应用连接到它即可。
  </Accordion>

  <Accordion title="我应该在 Project Editor 的模拟器中测试，还是在真机上测试？">
    两者要在不同场景下配合使用。Project Editor 中的 **iOS 模拟器**和 **Android 模拟器**会呈现应用的原生版本，足以覆盖大部分日常测试——布局、导航、原生组件和平台样式。当你需要测试依赖真实硬件的功能时，比如相机、触感反馈、推送通知或 GPS 定位，请切换到搭配 **Expo Go** 的真机。
  </Accordion>
</AccordionGroup>
