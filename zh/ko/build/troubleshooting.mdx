部署可将项目发布为公开应用。如果部署失败，或公开 URL 的行为与 Preview 不一致，请按顺序排查问题。

本页面既是构建恢复指南，也是部署故障排查参考文档。请从最简单的问题开始：应用能否在 Preview 中运行？

<div id="section">
  ## 您将掌握的内容
</div>

阅读完本页后，您将能够判断问题是否出在应用本身、部署设置、生产环境 Secrets、部署类型、端口配置，还是网络/DNS 访问。

<div id="preview">
  ## 从 Preview 开始
</div>

部署前，请确认应用能在 Project Editor 中正常运行。

在 Project Editor 顶部选择 **Run**，然后打开 Preview。如果应用未显示在 `replit.dev` URL 的 Preview 中，请先修复应用再进行部署。

首先，请让 Agent 诊断 Preview 问题。

<AiPrompt>
  此应用无法在 Preview 中运行。<br />
  请检查运行命令、依赖项安装、应用错误、端口以及缺失的 Secrets。<br />
  请先修复最小的问题，并告诉我如何确认 Preview 能在部署前正常运行。
</AiPrompt>

如果 Preview 无法运行，部署也无法解决问题。

<div id="preview-2">
  ## Preview 正常运行但部署失败
</div>

如果 Preview 正常运行但部署失败，请检查部署特定的设置。

<div id="section-2">
  ### 查看日志
</div>

打开 **Publishing** 面板中的 **Logs** 选项卡。查找堆栈跟踪、缺失的软件包、失败的命令、缺失的环境变量或启动错误。

将相关错误粘贴给 Agent。

<AiPrompt>
  部署失败，并出现以下日志输出：[粘贴错误]。<br />
  请说明最可能的原因。<br />
  请判断这是命令、依赖项、Secret、端口、构建还是应用错误。<br />
  请建议最小的修复方案以及验证方法。
</AiPrompt>

<div id="section-3">
  ### 检查运行和构建命令
</div>

常见问题包括拼写错误、使用了错误的标志、指定了错误的入口文件，或命令只能在本地运行。

请在 **Publishing** 面板中检查命令。如果应用需要同时使用构建命令和启动命令，请确保两者都正确。

<div id="secrets">
  ### 检查生产环境 Secrets
</div>

在 Project Editor 中设置的 Secrets 不会自动传递到已发布的 App。请在 **Publishing** 面板中添加所有生产环境 Secrets 和环境变量。

缺少 Secrets 可能会导致未定义值错误、API 调用失败、数据库连接失败、登录错误或支付失败。

请参阅 [Secrets](/zh/ko/core-concepts/project-editor/app-setup/secrets)。

<div id="section-4">
  ### 检查长期运行的进程
</div>

已部署的应用需要程序持续运行。如果程序运行一次后退出，平台会自动重启它。

请确认应用是否会启动 Web 服务器等长期运行的进程。

<div id="section-5">
  ### 检查主机和端口配置
</div>

如果你运行的是 Web 服务器，部署可以自动检测服务器使用的端口，但服务器必须监听 `0.0.0.0`。仅监听 `localhost` 或 `127.0.0.1` 无法在已部署的应用中正常运行。

如果你在 [`.replit` 配置中指定了端口](/zh/ko/features/project-setup/configuration)，将禁用自动端口检测。要通过部署推广阶段，你必须指定 `externalPort` 设为 `80` 的端口。请确认服务器正在指定的 `localPort` 上监听。

请让 Agent 仔细检查。

<AiPrompt>
  请检查此应用是否已正确配置为可部署。<br />
  确认服务器是否启动长期运行的进程、是否监听 0.0.0.0、是否使用预期端口，以及是否与 .replit 端口配置一致。<br />
  除修复部署问题外，请勿更改应用行为。
</AiPrompt>

<div id="section-6">
  ### 确认健康检查时机
</div>

在将已部署的应用标记为上线前，Replit 会向应用发送 HTTP 请求。如果首页响应时间超过 5 秒，健康检查可能会超时，导致部署在最后一步失败。

如果应用启动较慢，请让 Agent 减少启动时执行的任务、将高开销操作移至用户操作之后，或在适当情况下缓存数据。

<div id="url">
  ## 部署成功但公开 URL 无法访问
</div>

如果 Preview 可以正常运行且部署成功，但公开 URL 无法访问，请对比 Preview 与生产环境的行为。

请检查以下事项：

* 生产环境的 Secrets 和环境变量。
* 数据库连接配置。
* 登录回调或重定向 URL。
* 支付 Webhook 或重定向设置。
* API 允许列表或 CORS 设置。
* 写入本地文件而非数据库或存储服务的数据。
* 移动端布局和浏览器差异。

请 Agent 对比不同环境。

<AiPrompt>
  应用在 Preview 中可以正常运行，但在部署后的 URL 中无法运行。<br />
  请帮助我对比 Preview 与生产环境的行为。<br />
  请检查 Secrets、数据库设置、API 调用、登录重定向、支付重定向、构建输出和日志。<br />
  请告诉我下一步最安全的检查事项。
</AiPrompt>

<div id="static">
  ## Static 部署问题
</div>

Static 部署用于提供 HTML、CSS、JavaScript 等静态文件。

如果你的应用包含服务器端逻辑、API 路由、身份验证回调、从服务器调用数据库，或长时间运行的后端逻辑，则可能不适合 Static 部署。请改在 **Publishing** 面板中将部署类型更改为 Autoscale。

Static 部署问题通常是由于公共目录配置错误，或为需要服务器的应用选择了 Static 所致。

<div id="section-7">
  ## 文件与大小限制
</div>

Reserved VM 和 Autoscale 部署最多支持 8GB 的 Replit 应用。Static 部署最多支持 1GB。

要减小应用大小，请删除不必要的文件，避免提交生成的输出，或将大型资源存储在外部存储服务中。

<Warning>
  已部署应用的文件系统并非持久存储，每次部署都会重置。为确保数据持久性，请使用 [SQL Database](/zh/ko/features/data-and-storage/sql-database) 等数据库。
</Warning>

如果上传的文件或生成的数据在部署后消失，请将其存储在数据库或存储服务中，而非应用的文件系统中。

<div id="replitapp-replitdev-url">
  ## `replit.app` 和 `replit.dev` URL 访问问题
</div>

如果通过 `replit.app` 或 `replit.dev` 域名访问 App 时遇到问题，可能是网络过滤或网络限制导致的。

请尝试使用公共 DNS 解析器，例如 Google DNS (`8.8.8.8`) 或 Cloudflare DNS (`1.1.1.1`) 。

<div id="dns">
  ### 更改 DNS 设置
</div>

<Tabs>
  <Tab title="Windows">
    1. 打开**控制面板**。
    2. 前往**网络和共享中心**。
    3. 在左侧选择**更改适配器设置**。
    4. 右键点击当前使用的网络连接，然后选择**属性**。
    5. 选择**Internet 协议版本 4 (TCP/IPv4)**，然后选择**属性**。
    6. 选择**使用下面的 DNS 服务器地址**。
    7. 输入公共 DNS 服务器的 IP 地址，例如 Google DNS 的 `8.8.8.8` 或 Cloudflare DNS 的 `1.1.1.1`。
    8. 选择**确定**以保存更改。

    详细说明请参阅 [Microsoft DNS 配置指南](https://support.microsoft.com/en-us/windows/change-tcp-ip-settings-bd0a07af-15f5-cd6a-363f-ca2b6f391ace)。
  </Tab>

  <Tab title="macOS">
    1. 打开**系统设置**。
    2. 选择**网络**。
    3. 在左侧选择当前使用的网络连接。
    4. 在右下角选择**高级**。
    5. 前往**DNS**标签页。
    6. 点击**+**按钮添加 DNS 服务器。
    7. 输入公共 DNS 服务器的 IP 地址，例如 Google DNS 的 `8.8.8.8` 或 Cloudflare DNS 的 `1.1.1.1`。
    8. 选择**确定**，然后选择**应用**。

    详细说明请参阅 [Apple DNS 配置指南](https://support.apple.com/guide/mac-help/change-dns-settings-on-mac-mh14127/mac)。
  </Tab>

  <Tab title="Linux">
    1. 编辑 `/etc/resolv.conf` 文件以添加公共 DNS 服务器。具体操作因发行版而异。
    2. 添加以下行。

    ```bash theme={null}
    nameserver 8.8.8.8
    nameserver 1.1.1.1
    ```

    有关在不同发行版中配置 DNS 的详细信息，请参阅 [Debian Wiki 网络配置指南](https://wiki.debian.org/NetworkConfiguration#Defining_the_.28DNS.29_Nameservers)。
  </Tab>
</Tabs>

<div id="dns-2">
  ### 清除 DNS 缓存
</div>

更改 DNS 设置后，请清除 DNS 缓存以应用新配置。

* **Windows**：在命令提示符中运行 `ipconfig /flushdns`。
* **macOS 和 Linux**：在终端中运行 `sudo systemctl restart NetworkManager`。具体命令可能因所用发行版而异。

<Note>
  为提升当地的性能和稳定性，Replit Apps 的 `replit.dev` URL 在集群迁移期间可能偶尔发生变化。迁移完成后，除非您明确请求迁移到其他位置，否则该 URL 在约一年内将保持稳定。
</Note>

<div id="streamlit">
  ## 部署 Streamlit 应用
</div>

Streamlit 应用可在 Replit 部署中运行。最简单的入门方式是使用 [Streamlit 模板](https://replit.com/@replit/Streamlit?v=1)。

或者，将部署的运行命令设置为以下内容。

```bash theme={null}
streamlit run --server.address 0.0.0.0 --server.headless true --server.enableCORS=false --server.enableWebsocketCompression=false main.py
```

如果应用使用其他入口文件，请将 `main.py` 替换为对应的文件名。

<div id="section-8">
  ## 完成标准
</div>

* Preview 可正常运行。
* 部署已完成。
* 公开 URL 可正常加载。
* 基本应用流程可在公开 URL 上正常运行。
* 已配置生产环境的 Secrets 和设置。
* 日志中不存在被隐藏的启动错误。
