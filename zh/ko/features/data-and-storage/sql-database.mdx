Replit 数据库采用全托管 SQL 数据库，让你可以直接在 Project Editor 中为 Replit App 添加持久化数据存储。

<Note>
  最快的入门方式是让 **Agent** 为你的应用添加数据库。Agent 会设置集成、创建数据库架构，并更新应用以存储和查询数据。
</Note>

<div id="section">
  ## 功能
</div>

Replit 数据库工具提供以下功能：

* **数据库工具**：使用内置 SQL 工具执行查询、管理数据库架构并可视化数据
* **时间旅行**：可将数据库恢复到任意 **Agent** 检查点。详情请参阅[数据恢复](/zh/ko/features/data-and-storage/data-recovery)
* **免费存储空间**：每个 Replit App 均包含 20GB 免费存储空间。
* **环境变量**：在 Replit App 中使用环境变量安全访问数据库

<Info>
  在 2025 年 12 月 4 日之前，开发数据库由 Neon 托管，二者存在一些重要差异。
  详情请参阅[开发和生产环境](/zh/ko/features/data-and-storage/development-and-production#legacy-development-database)。
</Info>

<div id="section-2">
  ## 使用方法
</div>

<YouTubeEmbed videoId="zbyRuoPNIc8" title="如何在 Replit 中使用数据库" />

您可以直接在 Project Editor 中访问 Replit 数据库工具。
以下将介绍如何设置和管理数据库。

<Accordion title="如何访问数据库工具">
  1. 打开 **Tools** 面板，然后在 **Replit Cloud** 下选择 **Database**。
  2. 首页会显示数据库列表。选择并打开一个数据库，例如 **Development Database**。
</Accordion>

Database 工具围绕数据库列表构建。首页会显示每个数据库的存储空间使用量，以及当前的 **Billing Period** 和 **Hours of Compute Used**。打开数据库后，您可以使用三个标签页。

* **Overview**：数据库中的表
* **My Data**：浏览和编辑行，或运行 SQL 查询
* **Settings**：连接字符串、存储空间使用量和连接详情

<div id="section-3">
  ### 添加数据库
</div>

每个 Replit App 默认都配有一个数据库。你可以在 Project Editor 中选择 <img class="icon-svg" src="/assets/mirror/postgres-c4cb2a1e2de3.svg" alt="PostgreSQL 数据库图标" width="24" height="24" data-path="images/icons/postgres.svg" /> **数据库**工具来访问它。

让 **Agent** 为你的 Replit App 添加 PostgreSQL 数据库，并告知应用需要存储哪些数据的
详细信息，即可将数据库集成到应用中。Agent 会创建数据库架构，并
更新应用，使其能够与数据库通信。

<div id="section-4">
  ### 安全功能
</div>

使用 **Agent** 添加数据库集成时，系统会添加具备内置安全功能的 ORM (对象关系映射器) ，用于处理
所有数据库交互。

该 ORM 层结合 Agent 实施的安全最佳实践，通过以下功能保护 App 免受各类攻击。

* **模式验证**：确保数据符合预期格式
* **数据清理 (Sanitization)&#x20;**：自动清理构建者输入，防止 SQL 注入攻击

<div id="section-5">
  ## 后续步骤
</div>

在 2025 年 12 月 4 日之前，开发数据库由 <a href="https://neon.com/" target="_blank">Neon</a> 托管。
该数据库现已弃用，所有新的开发数据库均由 Replit 自有的数据库基础设施托管。

您可以查看 `DATABASE_URL` [环境变量](#view-connection-credentials-and-usage)，确认开发数据库是否由 Neon 托管。

<Info>
  如果 `DATABASE_URL` 包含 `neon.tech/neondb`，则开发数据库仍由 Neon 托管。
  如果包含 `helium/heliumdb`，则开发数据库现已由 Replit 托管。
</Info>

以下是旧版 Neon 开发数据库与新版 Replit 开发数据库之间的主要差异。

| **功能**       | **Replit (当前)&#x20;**&#x20;                                                                 | **Neon (旧版)&#x20;**&#x20;                                                     |
| ------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **托管**       | 由 Replit 自有基础设施托管                                                                      | 由 Neon (第三方服务商) 托管                                                       |
| **计费**       | 所有 Replit App 均免费提供                                                                    | 按使用量计费。详情请参阅[发布和数据库计费](/zh/ko/billing/about-usage-based-billing#databases)。 |
| **恢复功能**     | 使用[回滚功能](/zh/ko/features/version-control/checkpoints-and-rollbacks/)将数据库恢复到任意检查点          | 时间点恢复 (PITR) —可在备份保留期内恢复到任意时间点。                                          |
| **连接安全性**    | 仅可在 App 内访问，绝不会暴露到外部。                                                                  | 使用完整连接字符串—一旦泄露，任何人都能访问和修改数据库。                                            |
| **Remix 行为** | [Remix](/zh/ko/features/projects-and-artifacts/remix-an-app)会创建一个包含数据副本的新开发数据库，以实现隔离和安全   | Remix 会在所有副本中复用同一数据库，因此 Remix 中的更改可能会影响原始 App。                           |
| **数据库创建**    | 系统会自动为每个 Replit App 创建。                                                                | 需要显式配置。                                                                  |
| **发布工作流**    | 若要部署或发布，必须创建[生产数据库](/zh/ko/features/data-and-storage/development-and-production)，以隔离不同环境。 | 开发和生产环境共用同一数据库，因此意外的开发更改可能会影响生产 App。                                     |

<Warning>
  如果 App 在使用旧版 Neon 数据库期间被 Fork 或 Remix，已发布的 App 可能仍会引用原始 App 的数据库 URL。完成[数据库升级](/zh/ko/features/data-and-storage/development-and-production)后，此共享连接将不再有效。有关如何更新已发布的 App，请参阅[修改使用共享数据库的已发布 App](/zh/ko/features/data-and-storage/shared-database-migration)。
</Warning>
