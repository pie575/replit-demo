---
title: "Обновление старых проектов для поддержки нескольких артефактов"
description: "Добавьте второй артефакт в старый проект Replit с помощью разового структурного обновления, которое сохраняет URL, данные и деплои."
---

Если проект был создан до 11 марта 2026 года, то, прежде чем Agent сможет добавить второй артефакт, может потребоваться разовое структурное обновление. На этой странице объясняется, зачем оно нужно, что именно изменится и каких проектов это касается.

<div id="section">
  ## Предыстория
</div>

**11 марта 2026 года** Replit выпустил [Agent 4](/ru/ko/updates/2026/03/13/changelog). Одним из самых значимых изменений в этом релизе стала **поддержка нескольких артефактов**. Теперь один [проект](/ru/ko/features/projects-and-artifacts/projects) может содержать несколько [артефактов](/ru/ko/features/projects-and-artifacts/artifacts) (например, веб-приложение, мобильное приложение, питч-деку), которые используют общую базу данных, бэкенд, секреты и деплой.

До 11 марта 2026 года каждый проект создавался с другой структурой файлов, рассчитанной на одно приложение. В прежней структуре нет разделения, необходимого для того, чтобы бэкенд обслуживал два и более артефакта. Из-за этого различия проектам, созданным до 11 марта 2026 года, требуется **однократное обновление структуры**, прежде чем Agent сможет добавить второй артефакт. Проектам, созданным после этой даты, этот шаг не нужен: они уже используют новую структуру.

<div id="section-2">
  ## Что делает обновление
</div>

Если вы попросите Agent добавить второй артефакт в ранее созданный проект (например, добавить мобильное приложение к уже существующему веб-приложению), Agent сначала перестроит проект в новую структуру с несколькими артефактами. URL, участники совместной работы, секреты, базы данных и домены останутся прежними. Изменится только внутренняя структура.

<div id="section-3">
  ## Как это работает
</div>

<Steps>
  <Step title="Запросите новый артефакт в существующем проекте">
    Попросите Agent, например: «Создай слайд-дек с презентацией моего сайта».
  </Step>

  <Step title="Проверка и подтверждение">
    Прежде чем вносить изменения, Agent приостанавливается и показывает предложение в чате. Для двух подходящих проектов также отображается разовое предложение **кредита на 5 долларов**, который можно использовать для запуска обновления проекта. Нажмите **Обновить проект**, чтобы продолжить, или **Позже**, чтобы пропустить.

    <Frame>
      <img src="/assets/mirror/multi-artifact-update-approval-f6fa8b70a100.png" alt="Панель Agent чата с карточкой подтверждения «Обновить проект, чтобы создать мобильное приложение», предложением кредита на 5 долларов и кнопками «Позже» / «Обновить проект»" width="991" height="589" data-path="images/replitai/multi-artifact-update-approval.png" />
    </Frame>
  </Step>

  <Step title="Дождитесь реорганизации">
    Agent переводит проект на новую структуру в виде отдельной задачи — её ход виден в списке задач. Перед внесением изменений создаётся резервная копия существующего приложения, поэтому даже при сбое вы не потеряете проделанную работу.

    <Frame>

    </Frame>
  </Step>

  <Step title="Получите запрошенный новый артефакт">
    Как только существующее приложение заработает в новой структуре, Agent создаст артефакт, который вы запросили изначально.
  </Step>
</Steps>

<div id="section-4">
  ## Условия применимости
</div>

Пока обновление доступно не для всех проектов. Проект должен относиться к одному из следующих типов:

* **Веб-приложение** (fullstack JavaScript)
* **Макет из режима «дизайн в приложение»**
* **Мобильное приложение** (Expo)

Проекты других типов, созданные до 11 марта 2026 года, — Python, Flask, Streamlit, игровые стеки, видеопроекты, стек Agent — не поддерживаются. Если в таком случае вам нужно несколько артефактов, [создайте новый проект](/ru/ko/features/projects-and-artifacts/projects).

Порты и рабочие процессы проекта также должны соответствовать конфигурации по умолчанию для его типа. Если вы редактировали `.replit` вручную, появится такое сообщение:

> *Этот проект нельзя перенести автоматически: конфигурация рабочего процесса не соответствует ожидаемой.*

Чтобы решить эту проблему, верните настройки портов и рабочих процессов к значениям по умолчанию и повторите попытку.

<div id="section-5">
  ## Часто задаваемые вопросы
</div>

<AccordionGroup>
  <Accordion title="Почему моему проекту требуется обновление?">
    Проекты, созданные до 11 марта 2026 года (дата выхода Agent 4), использовали структуру с одним приложением. Новая структура общего рабочего пространства позволяет веб-приложению, мобильному приложению и панели администратора существовать вместе и использовать общую базу данных и бэкенд. Это обновление — разовый шаг для перехода к такой структуре.
  </Accordion>

  <Accordion title="Что будет, если я не захочу обновляться?">
    Нажмите **Позже**. Agent продолжит работу с прежней структурой из одного артефакта. Если ваши потребности изменятся, вы сможете вернуться к этому предложению позднее.
  </Accordion>

  <Accordion title="Можно ли обновиться более одного раза?">
    Нет. После перехода проекта на новую структуру дальнейшие обновления не требуются. Последующие артефакты добавляются сразу, без дополнительного шага обновления.
  </Accordion>

  <Accordion title="Мой проект не подходит под условия. Какие есть варианты?">
    Создайте отдельный проект для нового артефакта или начните новый проект, который изначально поддерживает несколько артефактов.
  </Accordion>
</AccordionGroup>
