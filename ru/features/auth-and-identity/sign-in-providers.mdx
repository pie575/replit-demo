Если ваше приложение использует [Clerk Auth](/ru/features/auth-and-identity/clerk-auth), посетители могут входить через социальные провайдеры. Replit сразу предоставляет общие учётные данные; на этой странице описано, как подключить **собственные** учётные данные OAuth для каждого провайдера, чтобы на экране входа отображались название и оформление вашего приложения.

Порядок действий одинаков для всех провайдеров: создайте OAuth-приложение в консоли провайдера, скопируйте URL-адреса, которые покажет Replit, и вставьте полученные учётные данные в панель редактирования провайдера.

<Note>
  Собственные учётные данные OAuth доступны только в окружении **Production**, поэтому приложение сначала нужно [опубликовать](/ru/features/publishing/overview). Откройте панель редактирования нужного провайдера в инструменте **Users &amp; Auth**: вкладка **Configure**, раздел **SSO providers**, выберите окружение **Production** и нажмите **Edit** рядом с провайдером. Общий порядок действий описан в разделе [Настройка учётных данных OAuth для провайдера SSO](/ru/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
</Note>

<div id="google">
  ## Google
</div>

В этом руководстве описано, как создать OAuth-приложение Google в Google Cloud Console. Вы получите **Client ID** и **Client Secret**, а также настроите источники JavaScript и URI перенаправления, которые требуются Clerk.

Что потребуется: доступ к [Google Cloud Console](https://console.cloud.google.com/).

<div id="step-1-create-a-google-oauth-app">
  ### Шаг 1. Создайте OAuth-приложение Google
</div>

Перейдите в [Google Cloud Console](https://console.cloud.google.com/):

<div id="create-or-select-a-project">
  #### Создайте или выберите проект
</div>

1. Выберите существующий проект или создайте новый в выпадающем списке проектов
2. Вы будете перенаправлены на панель управления проекта

<div id="configure-oauth-consent-screen">
  #### Настройка экрана согласия OAuth
</div>

1. На левой боковой панели нажмите значок меню (≡) и выберите **APIs &amp; Services**
2. Выберите **OAuth consent screen**
3. Настройте экран согласия своего приложения, указав необходимые сведения
4. Сохраните изменения

<div id="create-oauth-credentials">
  #### Создание учетных данных OAuth
</div>

1. В разделе **APIs &amp; Services** выберите **Credentials**
2. Нажмите **Create Credentials** вверху страницы, затем выберите **OAuth client ID**
3. В качестве типа приложения выберите **Web application**
4. В полях **Authorized JavaScript origins** и **Authorized redirect URIs** укажите точные значения из раздела **Provider setup** на **панели Auth**. Добавьте все перечисленные значения — в их число входят и ваш опубликованный домен, и любой пользовательский домен. О том, как их найти, см. [Настройка учетных данных OAuth для провайдера SSO](/ru/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Нажмите **Create**
6. Сохраните **Client ID** и **Client Secret**

<Warning>
  Храните Client Secret в безопасности и никогда не добавляйте его в систему контроля версий.
</Warning>

<Warning>
  Вход через Google не работает во встроенных браузерах и веб-представлениях внутри приложений. Пользователям необходимо использовать обычный веб-браузер.
</Warning>

<div id="troubleshooting">
  ### Устранение неполадок
</div>

<div id="redirect-uri-mismatch">
  #### Несовпадение URI перенаправления
</div>

* Убедитесь, что URI перенаправления в Google Cloud Console в точности совпадает со значением, указанным в разделе **Provider setup** на **панели Auth**
* Проверьте, что нет лишних слешей в конце и опечаток
* Подождите несколько минут, пока настройки Google вступят в силу

<div id="invalid-client">
  #### Недействительный клиент
</div>

* Ещё раз проверьте, правильно ли скопированы Client ID и Client Secret
* Убедитесь, что нет лишних пробелов
* Проверьте, настроен ли экран согласия OAuth

<div id="not-working-on-custom-domain">
  #### Не работает на пользовательском домене
</div>

* Добавьте записи пользовательского домена, указанные в разделе **Provider setup** на **панели Auth**, в поля Authorized JavaScript origins и Authorized redirect URIs

<div id="github">
  ## GitHub
</div>

В этом руководстве описано, как создать OAuth-приложение GitHub в разделе Developer Settings на GitHub. Вы получите **Client ID** и **Client Secret**, которые нужно указать на **панели Auth**.

Что понадобится: [учётная запись GitHub](https://github.com).

<div id="step-1-create-a-github-oauth-app">
  ### Шаг 1. Создайте OAuth-приложение GitHub
</div>

1. Перейдите в [настройки разработчика GitHub](https://github.com/settings/developers)
2. На боковой панели выберите **OAuth Apps**
3. Нажмите **New OAuth App**
4. Заполните данные приложения:

**Application name:**

Введите название приложения.

**Homepage URL** и **Authorization callback URL:**

В оба поля укажите точные значения из раздела **Provider setup** на **панели Auth**. О том, как их найти, см. [Настройка учётных данных OAuth для провайдера SSO](/ru/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

5. Нажмите **Register application**

<div id="step-2-generate-client-credentials">
  ### Шаг 2. Создайте учётные данные клиента
</div>

1. На странице настроек приложения вы увидите **Client ID** — скопируйте его
2. Нажмите **Generate a new client secret**
3. Сразу же скопируйте **Client Secret**

<Warning>
  Сохраните Client Secret в надёжном месте. Покинув страницу, вы больше не сможете его просмотреть. Если он будет утерян, придётся создать новый.
</Warning>

<div id="troubleshooting-2">
  ### Устранение неполадок
</div>

<div id="redirect-uri-mismatch-2">
  #### Несовпадение URI перенаправления
</div>

* Убедитесь, что Authorization callback URL в точности совпадает со значением, указанным в разделе **Provider setup** на **панели Auth**
* Проверьте, нет ли опечаток и верно ли указан протокол
* Не должно быть завершающих слешей

<div id="invalid-client-2">
  #### Недействительный клиент
</div>

* Убедитесь, что Client ID и Client Secret скопированы правильно
* Проверьте, что при вставке не появились лишние пробелы

<div id="not-working-on-custom-domain-2">
  #### Не работает на пользовательском домене
</div>

* Обновите Homepage URL и Authorization callback URL, указав значения для пользовательского домена, которые приведены в разделе **Provider setup** на **панели Auth**

<div id="apple">
  ## Apple
</div>

В этом руководстве описано, как создать App ID, Services ID и приватный ключ Apple, необходимые для входа через Apple. Вы получите **Team ID**, **Services ID**, **Key ID** и **Private Key**, которые нужно будет указать на **панели Auth**.

Что вам понадобится: [учётная запись Apple Developer](https://developer.apple.com/account) (требуется участие в Apple Developer Program).

<div id="step-1-create-an-apple-app-id">
  ### Шаг 1. Создайте Apple App ID
</div>

1. Перейдите на [портал Apple Developer](https://developer.apple.com/account)
2. Откройте **Certificates, IDs &amp; Profiles**, затем **Identifiers**
3. Выберите **App IDs** в раскрывающемся списке
4. Нажмите значок **+**, чтобы зарегистрировать новый идентификатор
5. Выберите **App IDs**, затем **Continue**
6. Выберите **App**, затем **Continue**
7. Заполните поля:
   * **Description**: название вашего App ID
   * **Bundle ID**: ваш уникальный идентификатор
8. Включите **Sign In with Apple** в разделе Capabilities
9. Нажмите **Continue**, затем **Register**
10. **Сохраните App ID Prefix** (указан вверху) — это ваш **Team ID**

<div id="step-2-create-an-apple-services-id">
  ### Шаг 2. Создайте Apple Services ID
</div>

1. На странице Identifiers выберите **Services IDs** в раскрывающемся списке
2. Нажмите **+**, чтобы зарегистрировать новый идентификатор
3. Выберите **Services IDs**, затем нажмите **Continue**
4. Заполните поля:
   * **Description**: название вашего Services ID
   * **Identifier**: ваш уникальный идентификатор (сохраните его — это и есть ваш **Services ID**)
5. Нажмите **Continue**, затем **Register**

<div id="configure-the-services-id">
  #### Настройка Services ID
</div>

1. Выберите созданный Services ID
2. Включите **Sign In with Apple**
3. Нажмите **Configure**
4. Задайте:

   * **Primary App ID**: выберите App ID из шага 1
   * **Domains and Subdomains**: скопируйте значение, указанное в разделе **Provider setup** на **панели Auth** (без префикса протокола `https://`)
   * **Return URLs**: скопируйте значение, указанное в разделе **Provider setup** на **панели Auth**

   О том, где найти эти значения, см. [Настройка учетных данных OAuth для провайдера SSO](/ru/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Нажмите **Next**, затем **Done**, затем **Continue** и **Save**

<div id="step-3-create-an-apple-private-key">
  ### Шаг 3. Создайте приватный ключ Apple
</div>

1. На боковой панели портала Apple Developer выберите **Keys**
2. Нажмите **+**, чтобы зарегистрировать новый ключ
3. Введите значение в поле **Key Name**
4. Включите **Sign In with Apple**
5. Нажмите **Configure**, затем выберите свой App ID из шага 1
6. Нажмите **Save**, затем **Continue** и **Register**
7. **Сохраните Key ID**
8. **Скачайте** файл приватного ключа (.p8)

<Warning>
  Приватный ключ можно скачать только один раз. Храните его в надёжном месте — повторно скачать его не получится.
</Warning>

<div id="step-4-configure-apple-private-email-relay">
  ### Шаг 4. Настройте службу приватной пересылки почты Apple
</div>

Функция Apple «Скрыть мою почту» позволяет пользователям входить, не раскрывая свой настоящий адрес электронной почты. Чтобы отправлять письма таким пользователям, зарегистрируйте источник писем.

1. На боковой панели портала Apple Developer выберите **Services**
2. В разделе **Sign in with Apple for Email Communication** выберите **Configure**
3. Нажмите **+**, чтобы добавить Email Source
4. Введите значение Email Source, указанное в разделе **Provider setup** на **панели Auth**
5. Нажмите **Next**, затем **Register** и **Done**
6. Дождитесь проверки DNS (зелёный значок галочки)

<Info>
  В некоторых регионах (Китай, Индия) Apple ID может быть привязан к номеру телефона, а не к адресу электронной почты. Если вашему приложению нужен адрес электронной почты для всех пользователей, вход через Apple для пользователей из этих регионов может не сработать.
</Info>

<div id="troubleshooting-3">
  ### Устранение неполадок
</div>

<div id="invalid-client-3">
  #### Недействительный клиент
</div>

* Убедитесь, что все учётные данные введены правильно
* Проверьте, что приватный ключ содержит строки BEGIN и END
* Убедитесь, что ваш Services ID настроен верно

<div id="invalid-redirect-uri">
  #### Недопустимый URI перенаправления
</div>

* Убедитесь, что Return URL в конфигурации Apple Services ID в точности совпадает со значением, указанным в разделе **Provider setup** на **панели Auth**
* Проверьте, что домен в разделе Domains and Subdomains совпадает с вашим опубликованным доменом (без `https://`)

<div id="email-relay-not-working">
  #### Не работает ретрансляция электронной почты
</div>

* Убедитесь, что напротив Email Source на портале Apple Developer отображается зелёная галочка
* Если запись добавлена недавно, дождитесь распространения DNS

<div id="not-working-on-custom-domain-3">
  #### Не работает на пользовательском домене
</div>

* Добавьте записи пользовательского домена, указанные в разделе **Provider setup** на **панели Auth**, в поля Domains and Subdomains (без `https://`) и Return URLs

<div id="x-twitter">
  ## X (Twitter)
</div>

В этом руководстве описано, как создать OAuth-приложение X в X Developer Portal. Вы получите **Client ID** и **Client Secret**, которые нужно указать на **панели Auth**.

Что потребуется: [аккаунт X Developer](https://developer.twitter.com/) (есть бесплатный тариф).

<div id="step-1-set-up-x-developer-app">
  ### Шаг 1. Настройте приложение в X Developer
</div>

<div id="create-a-developer-account-if-needed">
  #### Создайте аккаунт разработчика (при необходимости)
</div>

1. Перейдите на [портал разработчика X](https://developer.twitter.com/en/portal/dashboard)
2. Подайте заявку на создание аккаунта разработчика, если у вас его ещё нет
3. Заполните заявку, описав свой сценарий использования

<div id="create-or-select-an-app">
  #### Создание или выбор приложения
</div>

1. В X Developer Portal перейдите в раздел **Projects &amp; Apps**
2. Используйте существующее приложение или нажмите **Add App**
3. Введите название приложения и нажмите **Next**
4. Выберите **App settings**

<div id="step-2-configure-authentication">
  ### Шаг 2: Настройка аутентификации
</div>

1. Прокрутите страницу до раздела **User authentication settings**
2. Выберите **Set up**

**Разрешения приложения:**

Выберите минимальный уровень разрешений:

* **Read** — необходим для доступа к профилю пользователя (минимум)
* **Write** — для публикации от имени пользователей (необязательно)
* **Direct Messages** — для доступа к личным сообщениям (необязательно)

<Warning>
  Разрешения должны соответствовать запрашиваемым областям доступа (scopes). Если приложение запрашивает `tweet.write`, а включён только Read, аутентификация завершится ошибкой.
</Warning>

**Тип приложения:**

Выберите **Web App, Automated App or Bot**

**Информация о приложении:**

* **Callback URI / Redirect URL**: скопируйте значение, указанное в разделе **Provider setup** на **панели Auth**
* **Website URL**: скопируйте значение, указанное в разделе **Provider setup** на **панели Auth**

О том, как найти эти значения, см. [Настройка учётных данных OAuth для провайдера SSO](/ru/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

3. Выберите **Save**
4. **Сохраните Client ID и Client Secret**

<Warning>
  Храните Client Secret в надёжном месте. Если он утерян, при повторной генерации старое значение станет недействительным.
</Warning>

<div id="troubleshooting-4">
  ### Устранение неполадок
</div>

<div id="redirect-uri-mismatch-3">
  #### Несовпадение URI перенаправления
</div>

* Убедитесь, что Callback URI в точности совпадает со значением, указанным в разделе **Provider setup** на **панели Auth**
* Проверьте, нет ли опечаток и правильно ли указан протокол
* Без завершающих слешей

<div id="invalid-client-4">
  #### Недействительный клиент
</div>

* Перепроверьте Client ID и Client Secret
* Убедитесь, что в них нет лишних пробелов
* Проверьте, что вы используете учётные данные OAuth 2.0, а не OAuth 1.0a

<div id="scopepermission-errors">
  #### Ошибки областей доступа/разрешений
</div>

* Проверьте, что области доступа соответствуют разрешениям, включённым в X Developer Portal
* Убедитесь, что как минимум включено разрешение на чтение (Read)

<div id="app-in-development-mode">
  #### Приложение в режиме разработки
</div>

* Приложения X изначально работают в режиме разработки с ограниченным числом пользователей
* Для использования в продакшене может потребоваться подать заявку на расширенный доступ

<div id="not-working-on-custom-domain-4">
  #### Не работает на пользовательском домене
</div>

* Обновите Website URL и Callback URI, указав значения пользовательского домена из раздела **Provider setup** на **панели Auth**
