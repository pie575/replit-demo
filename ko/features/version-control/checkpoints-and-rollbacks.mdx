Replit을 사용하면 작업 내용을 잃어버릴 걱정을 하지 않아도 됩니다.

Replit의 체크포인트 및 롤백 시스템은 개발 환경 전체에 대한 포괄적인 버전 관리와 상태 관리를 제공합니다.

Replit Agent를 사용하면 체크포인트가 프로젝트 상태 전체를 자동으로 저장합니다. 여기에는 코드 변경 사항뿐만 아니라 프로젝트 파일, AI 대화 컨텍스트, 연결된 데이터베이스까지 포함됩니다.

<div id="what-are-checkpoints">
  ## checkpoint란?
</div>

**checkpoint**는 주요 개발 단계마다 Agent가 자동으로 생성하는 Replit App 상태의 완전한 snapshot입니다. 코드 변경 사항만 추적하는 기존 version control과 달리, Replit checkpoint는 개발 context 전체를 저장합니다.

checkpoint는 비디오 게임의 세이브 포인트와 같습니다. 언제든지 정상적으로 작동하던 앱 버전으로 되돌아갈 수 있습니다.

  <img src="/assets/mirror/agent-checkpoint-8e5b8b315c02.png" alt="rollback 옵션을 보여주는 Agent checkpoint 인터페이스" width="1554" height="876" data-path="images/replitai/agent-checkpoint.png" />
</Frame>

<div id="complete-state-capture">
  ### 전체 상태 캡처
</div>

각 checkpoint는 다음 항목을 보존합니다:

* **Project files**: 모든 파일과 디렉터리, 설치된 packages, project 구성
* **AI conversation context**: 현재 상태에 이르기까지의 전체 대화 기록과 context
* **환경 configuration**: 런타임 설정 및 publishing 구성
* **Agent 메모리**: project 아키텍처, 선호 사항, 패턴에 대한 AI의 이해
* **Database contents**: checkpoint 생성 시점의 database 데이터와 schema

이처럼 포괄적으로 저장하기 때문에 코드뿐만 아니라 개발 context 전체를 복원할 수 있다는 확신을 갖고 마음껏 변경을 시도해 볼 수 있습니다.

<div id="how-rollbacks-work">
  ## rollback 작동 방식
</div>

**Rollback** 기능을 사용하면 클릭 한 번으로 Replit App을 이전 checkpoint 상태로 복원할 수 있습니다. 이는 기존 Git revert 작업보다 훨씬 강력합니다.

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="rollback 옵션을 보여주는 checkpoint rollback 인터페이스" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

rollback은 안전하고 예측 가능하도록 설계되었습니다.

* **비파괴적 미리보기**: 일부 인터페이스에서는 rollback을 실행하기 전에 checkpoint 상태를 미리 확인할 수 있습니다
* **명확한 경계**: 각 checkpoint는 하나의 논리적인 개발 단계를 나타냅니다
* **Conversation 연속성**: AI context가 그대로 유지되므로 복원된 상태에서 이어서 개발할 수 있습니다
* **즉각적인 적용**: rollback은 전체 개발 환경에 즉시 반영됩니다

<div id="rolling-back">
  ### 롤백하기
</div>

이전 checkpoint로 롤백하면 프로젝트가 다음 항목을 포함해 그 시점의 상태로 되돌아갑니다.

1. **전체 프로젝트 상태**: 모든 프로젝트 파일이 선택한 checkpoint 시점의 상태 그대로 복원됩니다
2. **AI 대화 context**: Agent 대화가 해당 checkpoint 시점으로 복원되어 context 연속성이 유지됩니다
3. **프로젝트 구성**: 의존성, 패키지, 런타임 구성
4. **개발 환경**: 도구 구성 및 Project Editor 설정
5. **데이터베이스 내용(선택 사항)**: 선택하면 데이터베이스가 checkpoint 시점의 상태로 복원됩니다

<Info>
  기본적으로 롤백은 데이터베이스를 변경하지 않습니다. 롤백에 개발 데이터베이스를 포함하려면 &quot;추가 롤백 옵션&quot;에서 &quot;Database&quot;를 선택하세요.

  **[프로덕션 데이터베이스](/ko/features/data-and-storage/development-and-production)** 복원은 이 롤백 기능으로 자동 처리되지 않습니다.
  프로덕션 데이터베이스를 이전 시점으로 복원하는 방법은 [특정 시점 복원 수행 방법 문서](/ko/features/data-and-storage/development-and-production)를 참조하세요.
</Info>

<Warning>
  롤백 기능을 사용하면 Replit App이 이전 상태로 복원됩니다. 이때 해당 시점 이후에 이루어진 코드 편집을 비롯한 모든 변경 사항이 사라집니다. 데이터베이스 복원을 선택한 경우 데이터베이스 변경 사항도 함께 되돌아갑니다.
</Warning>

<div id="rolling-forward">
  ### 앞으로 이동하기
</div>

Replit의 checkpoints는 양방향으로 작동합니다. 즉, project 기록을 따라 뒤로도, 앞으로도 이동할 수 있습니다.
덕분에 작업 내용을 잃을 걱정 없이 개발 timeline을 자유롭게 오갈 수 있습니다.

너무 많이 rollback했거나 이후 checkpoint의 changes를 되살리고 싶다면, **앞으로 이동**해 checkpoint 기록의 앞쪽으로 넘어갈 수 있습니다. 이렇게 하면 작업 내용을 잃지 않고 project의 timeline을 자유롭게 오갈 수 있습니다.

앞으로 이동하려면 Agent tab에서 history icon <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="history icon" width="24" height="24" data-path="images/icons/history.svg" />을 클릭해 기록 보기를 연 다음, 현재 위치보다 이후에 생성된 checkpoint를 선택하세요.

<Info>
  앞으로 이동은 timeline에서 현재 위치보다 앞쪽에 checkpoints가 있을 때만 가능합니다. rollback한 뒤 새로운 changes를 만들면, 기존의 이후 checkpoints는 별도의 기록 분기에 속하게 됩니다.
</Info>

이러한 양방향 탐색 덕분에 project의 timeline을 완전히 제어할 수 있고, 작업 내용도 언제든 되살릴 수 있습니다.

<div id="checkpoint-creation">
  ## 체크포인트 생성
</div>

Replit의 AI 도구는 개발 과정의 주요 시점마다 체크포인트를 자동으로 생성합니다.

<div id="agent-checkpoints">
  ### Agent checkpoints
</div>

[Replit Agent](/ko/features/agent/overview)는 다음과 같은 경우에 checkpoint를 생성합니다.

* **기능 완료**: 요청한 기능이나 동작을 성공적으로 구현했을 때
* **주요 마일스톤**: 복잡한 task에서 상당한 진전이 있었을 때
* **안정 상태**: 구현한 changes를 테스트하고 검증한 후
* **오류 복구**: 심각한 문제를 수정하기 전

<div id="checkpoint-characteristics">
  ### 체크포인트의 특징
</div>

모든 체크포인트에는 다음 정보가 포함됩니다.

* **AI가 생성한 설명**: 어떤 작업이 완료되었는지 명확하게 설명하는 요약
* **타임스탬프 정보**: 쉽게 식별할 수 있는 정확한 생성 시각
* **변경 범위**: 수정된 파일, 기능, 시스템 표시
* **청구 정보**: Agent의 경우 체크포인트별 비용을 투명하게 추적

<div id="using-checkpoints-and-rollbacks">
  ## checkpoint 및 rollback 사용하기
</div>

<div id="finding-checkpoints">
  ### checkpoint 찾기
</div>

checkpoint는 Project Editor의 여러 위치에서 확인할 수 있습니다:

**Agent 탭**: Agent가 생성한 모든 checkpoint를 설명 및 rollback 옵션과 함께 확인합니다
**Git pane**: checkpoint를 Git commit 형태로 확인하며, version control과 완전히 통합됩니다
**History 보기**: Agent chat에서 기록 icon <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="history icon" width="24" height="24" data-path="images/icons/history.svg" />을 클릭하면 모든 checkpoint와 그 진행 과정을 담은 전체 timeline을 볼 수 있습니다

<div id="performing-rollbacks">
  ### rollback 수행
</div>

rollback 절차는 어디에서 시작하는지에 따라 조금씩 다릅니다:

<div id="from-agent-tab">
  #### Agent tab에서
</div>

<Steps>
  <Step title="Agent로 이동">
    Project Editor에서 **Agent** tab을 열어 Agent가 생성한 모든 checkpoint를 확인합니다.
  </Step>

  <Step title="checkpoint 선택">
    복원하려는 checkpoint를 찾아 **Rollback to here**를 선택합니다.
  </Step>

  <Step title="rollback 확인">
    rollback 경고 내용을 확인한 후 승인하면 앱이 선택한 상태로 복원됩니다.
  </Step>

  <Step title="복원 확인">
    project 파일, database, AI context가 복원된 checkpoint 상태와 일치하는지 확인합니다.
  </Step>
</Steps>

<div id="best-practices">
  ### 모범 사례
</div>

**checkpoint를 전략적으로 활용하세요**:

* 주요 checkpoint마다 앱을 테스트해 안정성을 확인하세요
* 자동 checkpoint와 별도로, 장기적인 버전 관리를 위해 수동 Git commit을 생성하세요
* checkpoint 설명을 살펴보며 무엇이 변경되었는지 파악하세요

**rollback 시 고려사항**:

* rollback하기 전에 항상 변경 범위를 확인하세요
* database와 외부 integration에 미치는 영향을 고려하세요
* 팀 전체가 상황을 파악할 수 있도록 협업자에게 rollback 사실을 공유하세요

**점진적 개발**:

* 잦은 checkpoint의 이점을 살릴 수 있도록 조금씩 나누어 Build하세요
* rollback을 활용해 여러 구현 방식을 안전하게 시도해 보세요
* AI context 보존 기능 덕분에 rollback 이후에도 대화를 이어갈 수 있습니다

<div id="integration-with-version-control">
  ## 버전 관리와의 통합
</div>

Checkpoints는 Replit의 전반적인 버전 관리 생태계와 매끄럽게 연동됩니다:

<div id="git-integration">
  ### Git 통합
</div>

* **Git commit 생성**: checkpoint가 생성될 때마다 이에 대응하는 Git commit이 함께 생성됩니다
* **브랜치 호환성**: checkpoint는 브랜치 구조와 병합 workflow를 그대로 따릅니다
* **remote 동기화**: GitHub 통합을 통해 checkpoint 동기화가 유지됩니다
* **명령줄 접근**: checkpoint와 함께 Git의 모든 기능을 그대로 사용할 수 있습니다

<div id="collaboration-features">
  ### 협업 기능
</div>

* **팀 가시성**: checkpoint는 모든 project 협업자에게 표시됩니다
* **merge 충돌 방지**: checkpoint 생성 시점 덕분에 충돌이 발생할 가능성이 줄어듭니다
* **context 공유**: AI conversation context 덕분에 팀원들이 changes를 쉽게 파악할 수 있습니다
* **실시간 업데이트**: 협업자는 checkpoint 생성을 실시간으로 확인할 수 있습니다

<div id="advanced-features">
  ## 고급 기능
</div>

<div id="checkpoint-previews">
  ### Checkpoint previews
</div>

일부 인터페이스에서는 checkpoint preview 기능을 지원합니다:

* **시각적 비교**: 각 checkpoint 시점의 앱 모습을 확인
* **비파괴적 탐색**: 실제로 롤백하지 않고 미리 보기
* **진행 상황 추적**: 앱이 시간에 따라 어떻게 발전해 왔는지 파악
* **반복 작업 비교**: 여러 구현 방식을 비교

<div id="cross-session-rollbacks">
  ### 세션 간 rollback
</div>

숙련된 builder와 팀 관리자를 위한 기능입니다:

* **확장된 기록**: 여러 개발 session에 걸친 checkpoint 접근
* **관리자 제어**: 팀 Admin이 여러 사용자 session에 걸쳐 rollback 수행 가능
* **audit 추적**: checkpoint 생성 및 rollback 작업의 전체 기록

<div id="use-cases">
  ## 활용 사례
</div>

<div id="experimental-development">
  ### 실험적 개발
</div>

Checkpoints를 활용하면 마음 놓고 실험할 수 있습니다:

* 언제든 되돌릴 수 있으니 부담 없이 새 기능을 시도해 보세요
* 다양한 아키텍처 접근 방식을 테스트해 보세요
* 다른 UI 디자인이나 사용자 flow를 살펴보세요
* 안전장치를 갖춘 상태에서 복잡한 integration을 구현해 보세요

<div id="debugging-and-recovery">
  ### 디버깅 및 복구
</div>

문제가 발생했을 때 checkpoint는 안정적인 복구 수단이 되어 줍니다:

* 버그가 발생하면 정상 작동하던 상태로 roll back
* checkpoint 상태를 비교해 문제 원인 격리
* 데이터가 손상된 경우 database 무결성 복원
* 실수로 삭제하거나 수정한 내용 복구

<div id="learning-and-iteration">
  ### 학습과 반복
</div>

Checkpoints는 학습 목적의 개발을 지원합니다:

* 다양한 구현 전략 비교하기
* checkpoint가 쌓이는 과정을 통해 AI의 의사 결정 과정 학습하기
* 기능이 어떻게 발전해 왔는지 살펴보며 이해도 높이기
* rollback이라는 안전장치를 믿고 새로운 기법 연습하기
