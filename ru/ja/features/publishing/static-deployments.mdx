description: "Узнайте, как публиковать статические сайты и фронтенд-приложения с помощью статического развёртывания."
---

При статическом развёртывании статические файлы Replit App — HTML, CSS, JavaScript и другие — размещаются на облачном сервере. Сервер автоматически применяет стратегии кеширования и масштабирования, чтобы доставлять контент быстро и экономично.

Статическое развёртывание идеально подходит для следующих сценариев:

* маркетинговые лендинги;
* сайты-портфолио;
* сайты с документацией по продуктам и API.

<Note>
  Статическое развёртывание несовместимо с Replit Apps, созданными с помощью Agent.
  Agent автоматически создаёт full-stack приложения, которым требуется бэкенд-сервер.
  Для приложений, созданных Agent, используйте один из следующих типов развёртывания:

  * [Автомасштабируемое развёртывание](/ru/ja/features/publishing/autoscale-deployments)
  * [Развёртывание на Reserved VM](/ru/ja/features/publishing/reserved-vm-deployments)
</Note>

<div id="section">
  ## Возможности
</div>

Статические развёртывания включают следующие возможности:

* **Экономичный хостинг**: вы платите только за объём данных, переданных вашим сайтом.
* **Параметры HTTP-маршрутизации**: настраивайте заголовки ответов, перезапись URL и перенаправления.
* **Пользовательские домены**: подключите собственный домен или используйте URL `<app-name>.replit.app` для доступа к приложению.
* **Пользовательские страницы ошибок**: создавайте и отдавайте собственную страницу ошибки 404.
* **Мониторинг**: просматривайте логи и отслеживайте состояние опубликованного приложения.

<div id="section-2">
  ## Использование
</div>

Статические развёртывания доступны через инструмент Publishing в редакторе проекта.

<Accordion title="Как открыть статическое развёртывание">
  На **панели инструментов** слева:

  1. Выберите <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Значок All tools" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools**, чтобы открыть список инструментов редактора проекта.
  2. Выберите <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Значок Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Выберите вариант **Static**, а затем — **Set up your published app**.

  Через **строку поиска**:

  1. Нажмите на <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Значок лупы" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" />лупу вверху, чтобы открыть инструмент поиска
  2. Введите «Publishing» и выберите инструмент в результатах поиска.
  3. Выберите вариант **Static**, а затем — **Set up your published app**.
</Accordion>

<div id="section-3">
  ### Основной домен
</div>

Укажите поддомен в имени хоста вашего опубликованного приложения. После публикации приложение будет доступно по адресу `https://<subdomain>.replit.app`.

О том, как использовать собственный домен, см. [Пользовательские домены](/ru/features/publishing/custom-domains).

<div id="section-4">
  ### Приватные развёртывания
</div>

<Info>
  Функция приватной публикации приложений доступна на планах Pro и Enterprise.
</Info>

Приватно опубликованные приложения доступны только участникам вашего workspace либо тем пользователям и группам, которых вы пригласите.
При публикации можно выбрать один из вариантов доступа: **Public**, **Password protected**, **Workspace only** или **Invite only**.

О том, как настроить приватное развёртывание, см. [Доступ к приложению](/ru/features/publishing/private-deployments/).

<div id="section-5">
  ### Публичный каталог
</div>

Укажите базовый путь к каталогу внутри Replit App, в котором находятся статические файлы для публичной раздачи.
После развёртывания облачный хостинг будет отдавать все страницы и ресурсы из этого каталога.

Значение по умолчанию `/` — это корневой каталог Replit App.

<div id="section-6">
  ### Команда сборки
</div>

Укажите команду сборки, которая будет выполняться в оболочке Replit App при создании развёртывания.

Например, если статический сайт генерируется с помощью <a href="https://gohugo.io/" target="_blank">Hugo</a>,
можно использовать команду `hugo --minify` — она создаёт файлы и оптимизирует размер файлов ресурсов.

<div id="section-7">
  ### Секреты развёртывания
</div>

Выберите **Add deployment secret**, чтобы добавить переменные окружения и секреты, необходимые для безопасного выполнения команды сборки.

Например, если вашему генератору сайтов требуется API-ключ для создания статического сайта,
его можно передать как `API_KEY=<имя секрета>`.
