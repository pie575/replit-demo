Package Firewall блокирует вредоносные и скомпрометированные пакеты на сетевом уровне — ещё до того, как они попадут в ваше приложение. Он входит в [Replit Auto-Protect](/ru/features/security/concepts#auto-protect) — набор средств защиты, включённых по умолчанию для каждого разработчика, — и работает на базе [Socket](https://socket.dev), компании, специализирующейся на безопасности цепочки поставок программного обеспечения.

Когда вы или Agent запускаете команду установки вроде `npm install` или `pip install`, запрос сначала проходит через Package Firewall. Безопасные пакеты устанавливаются как обычно, и вы ничего не заметите. Пакеты, помеченные Socket как вредоносные или скомпрометированные, блокируются до того, как их код попадёт в вашу среду.

Package Firewall **включён по умолчанию для каждого разработчика: ничего не нужно настраивать и ничего не нужно переносить**. Он одинаково защищает как новые, так и существующие приложения, и никаких параметров задавать не требуется.

<div id="why-install-time-protection-matters">
  ## Почему важна защита на этапе установки
</div>

Большинство инструментов защиты цепочки поставок проверяют зависимости только на этапе публикации — уже после того, как пакет установлен. Для обычных уязвимостей этого может быть достаточно. С вредоносным ПО всё иначе: оно наносит ущерб сразу при установке — крадёт секреты, открывает бэкдоры, выгружает переменные окружения. К моменту, когда проверка на этапе публикации его обнаружит, атака уже состоялась.

Package Firewall закрывает это окно уязвимости. Блокируя вредоносные пакеты ещё до загрузки, он останавливает атаку до того, как выполнится хотя бы одна строка вредоносного кода.

<div id="how-it-works">
  ## Как это работает
</div>

1. Вы или Agent выполняете команду установки, например `npm install <package>` или `pip install <package>`.
2. Запрос проходит через Package Firewall, который сверяет пакет с данными об угрозах от Socket.
3. Если пакет безопасен, установка проходит как обычно, без каких-либо заметных отличий.
4. Если пакет вредоносный или скомпрометирован, установка блокируется ещё до того, как какой-либо код попадёт в вашу среду.

При блокировке вы получаете понятное сообщение о том, что именно было остановлено и почему, с указанием уязвимости или политики, которая вызвала блокировку. Agent получает тот же сигнал, поэтому может предложить безопасную альтернативу — например, исправить опечатку в имени пакета — или оставить решение за вами.

<div id="supported-package-managers">
  ### Поддерживаемые менеджеры пакетов
</div>

Package Firewall защищает установку пакетов в следующих экосистемах:

* **JavaScript** — npm, yarn и pnpm
* **Python** — pip
* **Go** — модули Go

<div id="what-package-firewall-catches">
  ## Что перехватывает Package Firewall
</div>

Package Firewall блокирует как откровенно вредоносное ПО, так и скомпрометированные или содержащие известные уязвимости версии вполне легитимных пакетов — в том числе широко используемых. Многие из этих уязвимостей были раскрыты уже после даты окончания обучения моделей, которые рекомендуют такие пакеты, поэтому модель может уверенно предложить версию зависимости, считавшуюся безопасной в её обучающих данных, но с тех пор помеченную как опасная. У таких рисков есть устоявшиеся названия:

* **Тайпсквоттинг (typosquats)** — вредоносный пакет с именем, отличающимся от настоящего на один символ, например `reqeusts` вместо `requests`. Вы запрашиваете не тот пакет и загружаете вредоносное ПО.
* **Слопсквоттинг (slopsquats)** — модель выдумывает несуществующее имя пакета, злоумышленник регистрирует ровно это имя и ждёт, пока следующий агент его установит.
* **Устаревшие рекомендации** — реальный пакет с раскрытой уязвимостью, который модель рекомендует, потому что до окончания её обучения он считался безопасным.

Именно из-за последней категории Package Firewall особенно важен для приложений, созданных с помощью ИИ: агент может уверенно потянуться за зависимостью, которая больше не безопасна, а Package Firewall остановит установку до того, как этот код будет выполнен.

<div id="how-package-firewall-fits-with-replits-other-security-tools">
  ## Как Package Firewall соотносится с другими средствами безопасности Replit
</div>

Package Firewall — один из трёх взаимодополняющих уровней защиты. Каждый из них закрывает свой этап жизненного цикла приложения, поэтому используйте их вместе, а не вместо друг друга.

| Уровень                                  | Когда работает             | Что делает                                                                                                                                                                                                         |
| ---------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Package Firewall**                     | Во время установки         | Блокирует вредоносные и скомпрометированные пакеты до их загрузки (предотвращение).                                                                                                                                |
| **Автоматические проверки зависимостей** | После установки, постоянно | Выявляют недавно раскрытые CVE в установленных зависимостях; при необходимости Agent готовит исправления. См. [Центр безопасности проекта](/ru/features/security/project-security-center#automatic-dependency-scans). |
| **Security Agent**                       | Перед публикацией          | Проверяет всю кодовую базу на уязвимости в коде, зависимостях и в части конфиденциальности данных. См. [Проверки безопасности Agent](/ru/features/security/agent-security-scans).                                     |
