Ces réponses expliquent comment travailler avec les projets et les fichiers. Pour en savoir plus, consultez [Secrets](/fr/core-concepts/project-editor/app-setup/secrets), [Checkpoints et restaurations](/fr/features/version-control/checkpoints-and-rollbacks) et la [présentation des intégrations](/fr/features/integrations/overview).

<AccordionGroup>
  <Accordion title="Comment connecter Resend ou un autre service de messagerie à mon app Replit ?">
    Ouvrez votre projet, puis accédez à **Outils → Connectors**. Recherchez le service (comme Resend) et connectez-le. Une fois l’autorisation accordée, la clé API est enregistrée en tant que secret dans votre projet. Si vous configurez un domaine de messagerie personnalisé, ajoutez les enregistrements DNS indiqués par le service auprès de votre fournisseur DNS.

    Consultez la [présentation des intégrations](/fr/features/integrations/overview) pour découvrir les connecteurs disponibles et [Ajouter des intégrations](/fr/build/add-integrations).
  </Accordion>

  <Accordion title="J’ai supprimé un projet par erreur : puis-je le récupérer ?">
    Les projets supprimés peuvent être restaurés pendant une durée limitée. Ouvrez un Shell dans n&#39;importe quel projet et exécutez :

    ```bash theme={null}
    trash view
    trash restore your-project-name
    ```

    Une fois la période de conservation écoulée, les projets supprimés sont définitivement effacés. Si ce délai est dépassé, [contactez le support Replit](https://replit.com/support).
  </Accordion>

  <Accordion title="Comment télécharger ou exporter un projet Replit ?">
    Sélectionnez le menu à trois points en haut de l&#39;arborescence des fichiers, puis choisissez **Download as zip**. Pour les projets volumineux, le téléchargement peut prendre un certain temps. En cas d&#39;échec, ouvrez un Shell et exécutez `zip -r project.zip .`, puis téléchargez `project.zip` depuis l&#39;arborescence des fichiers.
  </Accordion>

  <Accordion title="Comment partager un projet ou ajouter un collaborateur ?">
    Vous disposez de trois options :

    * **Lecture seule**—rendez le projet public afin que toute personne disposant du lien puisse le consulter.
    * **Accès en modification sur invitation**—sélectionnez **Inviter**, saisissez un nom d’utilisateur ou une adresse e-mail, puis définissez le niveau d’autorisation.
    * **Lien d’accès**—créez un lien d’accès depuis **Inviter** afin que toute personne disposant du lien puisse rejoindre le projet et le modifier.

    Core permet jusqu’à 5 collaborateurs et Pro jusqu’à 15 ; les collaborateurs n’ont pas besoin d’un forfait payant pour modifier votre projet. Consultez les [Workspaces](/fr/features/collaboration/workspaces).
  </Accordion>

  <Accordion title="Comment connecter un dépôt GitHub à Replit ?">
    Associez votre compte GitHub dans les services connectés de votre compte, puis ouvrez l&#39;[outil Git](/fr/features/workspace-tools/git-interface) dans votre projet et connectez le dépôt. Activez la synchronisation automatique dans le volet Git pour synchroniser les modifications dans les deux sens. Pour importer un dépôt existant, consultez [Importer depuis des fournisseurs](/fr/build/import-from-providers).

    Si la synchronisation Git cesse de fonctionner, reconnectez GitHub dans vos services connectés. Un jeton d’accès personnel à granularité fine offre une connexion plus fiable.
  </Accordion>

  <Accordion title="Mon Repl est lent ou l’éditeur manque de réactivité : que puis-je faire ?">
    En cas de ralentissement de l’éditeur, essayez les solutions suivantes :

    * Effectuez une actualisation forcée avec `Cmd+Shift+R` (Mac) ou `Ctrl+Shift+R` (Windows).
    * Fermez les onglets de fichiers inutilisés.
    * Ouvrez la palette de commandes avec `Cmd+K` (Mac) ou `Ctrl+K` (Windows), recherchez **Restart compute**, puis sélectionnez cette option.
    * Essayez un autre navigateur pour exclure un problème lié aux extensions.

    Si l’exécution du code est lente, mais pas l’éditeur, vérifiez la présence de boucles gourmandes ou de limites de mémoire. Vous pouvez consulter l’utilisation du processeur et de la mémoire dans le panneau des ressources, en bas de l’éditeur.
  </Accordion>

  <Accordion title="Comment utiliser les variables d’environnement et les Secrets dans mon projet ?">
    Ouvrez l’outil **Secrets** (l’icône de cadenas), sélectionnez **+ New secret**, puis saisissez une clé et une valeur. Accédez-y dans votre code avec `process.env.API_KEY` (Node.js) ou `os.environ["API_KEY"]` (Python).

    Les Secrets du volet de développement [Secrets](/fr/core-concepts/project-editor/app-setup/secrets) sont uniquement disponibles dans l’éditeur. Pour les apps publiées, ajoutez les mêmes clés dans les secrets de votre deployment : elles sont volontairement stockées séparément.
  </Accordion>

  <Accordion title="Comment utiliser les Secrets du compte (le Vault) ?">
    Les [Account Secrets](/fr/core-concepts/project-editor/app-setup/secrets) sont accessibles depuis tous vos projects — pratique pour les clés que vous réutilisez. Ajoutez-les depuis les paramètres de votre compte : elles seront alors disponibles dans chaque project que vous possédez. Si la même clé existe à la fois dans les Account Secrets et dans le panneau Secrets d&#39;un project, c&#39;est la valeur définie au niveau du project qui l&#39;emporte.
  </Accordion>

  <Accordion title="Comment récupérer après un conflit de fusion Git ou un état Git corrompu ?">
    Ouvrez un Shell et exécutez `git status` pour voir les conflits.

    <Warning>Les deux commandes suivantes suppriment les modifications non validées, et cette opération est irréversible. Enregistrez d&#39;abord tout ce que vous souhaitez conserver — par exemple, copiez les fichiers modifiés en dehors du projet.</Warning>

    Pour annuler les modifications locales et revenir à votre dernier état sain, exécutez `git checkout -- .` ; pour revenir au dernier commit, exécutez `git reset --hard HEAD`.

    Si votre dossier `.git` est corrompu et que les commandes Git échouent, ouvrez un nouveau chat Agent et collez-y l&#39;erreur — Agent peut souvent réparer le dépôt. Consultez [Reprise après sinistre](/fr/features/version-control/disaster-recovery).
  </Accordion>

  <Accordion title="Comment revenir à un checkpoint antérieur de mon projet ?">
    Replit enregistre des [checkpoints](/fr/features/version-control/checkpoints-and-rollbacks) au fur et à mesure qu’Agent travaille. Dans le panneau Agent, repérez le message précédant la modification que vous souhaitez annuler, sélectionnez l’option d’annulation à côté, puis confirmez.

    <Note>
      Replit ne permet plus de restaurer une application publiée vers une version antérieure. Pour rétablir une application publiée, restaurez votre projet à un checkpoint antérieur (comme décrit ci-dessus), puis publiez-la à nouveau pour redéployer cet état. Pour récupérer un seul fichier, ouvrez-le, sélectionnez son nom et utilisez **Afficher l’historique** pour restaurer une version précédente. Consultez [Historique des fichiers](/fr/features/version-control/file-history).
    </Note>
  </Accordion>

  <Accordion title="Comment transférer un projet vers un autre compte Replit ?">
    Les projets ne peuvent pas être transférés directement, mais vous pouvez en copier un. Le plus simple consiste à partager le projet avec le compte de destination, puis à le forker depuis ce compte. Vous pouvez également télécharger le projet au format ZIP et le téléverser dans un nouveau Repl sur l’autre compte.

    Après la copie, configurez Secrets, la base de données et la configuration du déploiement dans le nouveau projet : ces éléments ne sont pas inclus dans la copie. Pour obtenir des instructions détaillées, notamment sur le transfert des données de votre base de données, consultez [Copier manuellement un projet vers un autre workspace](/fr/teams/identity-and-access-management/manually-copy-projects).
  </Accordion>
</AccordionGroup>
