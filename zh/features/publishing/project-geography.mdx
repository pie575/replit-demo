Project 地理位置即 Project 的发布地理位置。你在发布时选择该位置，它决定了已发布 Project 的计算与存储资源托管在何处。

<Note>
  Project 地理位置与 [Workspace
  地理位置](/zh/features/collaboration/workspace-geography) 可以不同。Workspace
  地理位置决定的是 Workspace 中新建 Project 的开发资源托管在何处。
</Note>

<div id="what-project-geography-controls">
  ## Project 地理位置决定哪些内容
</div>

默认情况下，Replit 会推荐离你最近的地理位置，这有助于降低应用访问者的延迟，并满足数据驻留要求。

选择地理位置后，该 Project 的所有已发布 artifact (如计算、数据库和对象存储) 都会自动部署在同一区域。此外，该地理位置专属的代理也有助于降低应用访问者的延迟。

<div id="select-a-project-geography">
  ## 选择 Project 地理位置
</div>

若要选择推荐区域以外的地理区域：

<Steps>
  <Step>在你的 Replit Project 中打开 **Publishing** 工具。</Step>
  <Step>展开 **Advanced** 设置。</Step>
  <Step>在 **Geography** 下拉菜单中选择你需要的地理区域。</Step>

  <Step>
    点击 **Publish**，将你的 Project 发布到所选地理区域。
  </Step>
</Steps>

<div id="enforce-a-geography-on-published-projects">
  ## 为已发布的 Project 强制指定地理区域
</div>

Enterprise 管理员可以为组织内的所有 Project 强制指定发布地理区域。策略生效后，组织中的构建者只能发布到所配置的地理区域。该策略仅适用于尚未发布的 Project，已发布到其他地理区域的 Project 不受影响。

<Note>
  强制指定发布地理区域是 Enterprise 功能。要详细了解
  Enterprise 方案，请参阅[定价](https://replit.com/pricing/)。
</Note>

<Steps>
  <Step>前往你的 **Account settings**。</Step>
  <Step>选择 **Advanced**。</Step>

  <Step>
    选择所有首次发布的 Project 必须使用的地理区域。
  </Step>
</Steps>

<div id="availability-and-limits">
  ## 可用性与限制
</div>

| 地区                | 是否支持选择 Project 发布地区 |
| :---------------- | :------------------ |
| **北美**            | 是                   |
| **欧洲 (欧盟)&#x20;**&#x20;| 是                   |
| **亚洲**            | 是                   |
| **南美**            | 是                   |
| **澳大利亚**          | 是                   |

<Note>
  Project 地理位置选择功能面向 Core、Pro 和 Enterprise
  用户开放。免费用户默认发布到北美。
</Note>

在选择 Project 地理位置之前，请注意以下限制：

* **发布后无法更改地区。** 一旦将 Project 发布到某个地区，该选择将永久生效，无法将已发布的 Project 迁移到其他地区。
* **开发位置与发布位置可能不同。** 对象存储等资源可以在发布前创建，因此可能与你的 Project 地理位置不一致。
