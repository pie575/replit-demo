description: "Configurez GitHub comme fournisseur de connexion sociale pour l’authentification de votre application"
---

Ce guide explique comment créer une application OAuth GitHub dans les paramètres développeur de GitHub. Vous y récupérerez un **Client ID** et un **Client Secret** à saisir dans le **panneau Auth**.

<Note>
  Cette page couvre uniquement la configuration côté fournisseur dans les paramètres développeur de GitHub. Pour connaître le processus général de Clerk Auth — notamment l’activation de GitHub et la saisie des identifiants dans le **panneau Auth** — consultez [Configurando identifiant OAuth para um fournisseur SSO](/fr/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) dans la documentation de Clerk Auth.
</Note>

<div id="pr-requisitos">
  ## Prérequis
</div>

* Un [compte GitHub](https://github.com)
* Une [App Replit publiée](/fr/category/replit-deployments) — les identifiants OAuth personnalisés sont disponibles uniquement dans l’environnement de **Production**
* Le panneau de modification du fournisseur **GitHub**, ouvert à l’emplacement suivant : **panneau Auth** → onglet **Configure** → section **SSO providers** → sélectionnez l’environnement **Production** → sélectionnez **Edit** à côté de **GitHub**

<div id="passo-1-criar-um-app-oauth-do-github">
  ## Étape 1 : Créer une application OAuth GitHub
</div>

1. Accédez aux [paramètres développeur de GitHub](https://github.com/settings/developers)
2. Sélectionnez **OAuth Apps** dans la barre latérale
3. Sélectionnez **New OAuth App**
4. Renseignez les informations de l’application :

**Nom de l’application :**

Saisissez un nom pour votre application.

**Homepage URL** et **Authorization callback URL :**

Définissez-les avec les valeurs exactes affichées dans **Provider setup** du **panneau Auth**. Consultez [Configuration des identifiants OAuth pour un fournisseur SSO](/fr/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) pour savoir comment les trouver.

5. Sélectionnez **Register application**

<div id="passo-2-gerar-as-credenciais-do-cliente">
  ## Étape 2 : Générez les identifiants du client
</div>

1. Votre **Client ID** s’affiche sur la page des paramètres de l’app : copiez-le.
2. Sélectionnez **Generate a new client secret**.
3. Copiez immédiatement votre **Client Secret**.

<Warning>
  Conservez votre Client Secret en lieu sûr. Vous ne pourrez plus l’afficher après avoir quitté la page. Si vous le perdez, vous devrez en générer un nouveau.
</Warning>

<div id="soluo-de-problemas">
  ## Résolution des problèmes
</div>

<div id="incompatibilidade-de-uri-de-redirecionamento">
  ### Incompatibilité d’URI de redirection
</div>

* Vérifiez que l’URL de rappel d’autorisation correspond exactement à la valeur affichée dans **Provider setup** du **panneau Auth**
* Vérifiez qu’il n’y a pas de fautes de frappe ni de protocoles incorrects
* N’ajoutez pas de barre oblique finale

<div id="cliente-invlido">
  ### Client non valide
</div>

* Vérifiez que le Client ID et le Client Secret ont été copiés correctement
* Assurez-vous qu&#39;il n&#39;y a pas d&#39;espaces supplémentaires lors du collage

<div id="no-est-funcionando-no-domnio-personalizado">
  ### Ne fonctionne pas avec le domaine personnalisé
</div>

* Mettez à jour les champs Homepage URL et Authorization callback URL avec les valeurs du domaine personnalisé affichées dans **Provider setup**, dans le **panneau Auth**
