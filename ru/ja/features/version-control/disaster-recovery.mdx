---
title: "Аварийное восстановление Git"
description: "Узнайте, как восстановить историю Git и код с помощью системы автоматического резервного копирования Replit."
---

Replit автоматически создаёт резервные копии репозиториев Git, чтобы вы могли восстановить проект после таких сбоев, как повреждение папки `.git` или потеря истории коммитов. Система резервного копирования работает в фоновом режиме, поэтому ваша работа защищена без каких-либо дополнительных действий с вашей стороны.

<div id="section">
  ## Как это работает
</div>

Для каждого Replit App поддерживается защищённая резервная копия Git-репозитория. Когда Replit Agent вносит изменения в код или вы развёртываете приложение, эти изменения автоматически синхронизируются с резервной копией. Если локальный Git-репозиторий окажется повреждён или непригоден к использованию, вы сможете восстановить полную историю коммитов из резервной копии.

<Info>
  Удалённый репозиторий для резервных копий называется `gitsafe-backup`, и Replit управляет им автоматически. Настраивать ничего не нужно — он уже работает в фоновом режиме.
</Info>

<div id="section-2">
  ## Просмотр истории резервных копий
</div>

Проще всего посмотреть историю коммитов через [панель Git](/ru/ja/features/workspace-tools/git-interface). Откройте её из раздела Tools в редакторе проекта — там отобразится полная история коммитов, включая все чекпоинты Agent. Этот способ подходит для большинства случаев и не требует ввода команд.

Если нужно обратиться к удалённому репозиторию gitsafe-backup напрямую, воспользуйтесь Shell:

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

Так вы увидите полную историю коммитов, включая все чекпоинты Agent и коммиты, созданные вручную. Это удобно, чтобы проверить, есть ли резервная копия вашей работы, или найти конкретный коммит для восстановления.

<div id="git">
  ## Восстановление после проблем с Git
</div>

Если возникла ошибка Git или репозиторий повреждён, сначала попробуйте [панель Git](/ru/ja/features/workspace-tools/git-interface). С её помощью можно решить большинство типичных проблем без команд Shell — например, откатиться к предыдущему коммиту или получить изменения из удалённого репозитория.

Если панель Git не помогает (например, папка `.git` повреждена полностью), воспользуйтесь приведёнными ниже действиями через Shell.

<div id="section-3">
  ### Проверьте, доступна ли резервная копия
</div>

Сначала убедитесь, что резервный удалённый репозиторий существует:

```bash theme={null}
git remote -v
```

Если в выводе есть `gitsafe-backup`, можно приступать к восстановлению.

<div id="section-4">
  ### Восстановление репозитория
</div>

<Warning>
  Этот процесс заменяет текущую папку `.git` резервной копией. Рабочие файлы останутся без изменений, но локальная история Git будет заменена историей из резервной копии.
</Warning>

<Steps>
  <Step title="Сохраните текущие настройки Git">
    Создайте резервную копию файла конфигурации Git — на случай, если в нём есть пользовательские настройки:

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Клонируйте резервный репозиторий">
    Создайте временный клон из резервной копии:

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Замените папку Git">
    Переместите повреждённую папку `.git` в другое место и замените её резервной копией:

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Восстановите настройки">
    Скопируйте настройки Git обратно:

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

После выполнения этих шагов запустите `git status`, чтобы убедиться, что репозиторий работает корректно.

<div id="section-5">
  ## Устранение распространённых проблем
</div>

<div id="fatal-repository-not-found">
  ### «fatal: repository not found» или резервный удалённый репозиторий не найден
</div>

В старых проектах система резервного копирования может быть отключена. Если вам нужна помощь с восстановлением старого проекта, обратитесь в службу поддержки.

<div id="section-6">
  ### Последние коммиты не вошли в восстановленную версию
</div>

Резервные копии синхронизируются при каждом коммите Agent. Если вы внесли изменения, но не зафиксировали их коммитом, в резервную копию они не попадут. Проверьте рабочий каталог на наличие незафиксированных файлов.

<div id="git-2">
  ### Операции Git выполняются медленно или зависают
</div>

Если операции Git перестали отвечать, возможно, остался устаревший файл блокировки. Его можно безопасно удалить:

```bash theme={null}
rm -f .git/index.lock
```

<div id="section-7">
  ## Предотвращение потери данных
</div>

Система резервного копирования автоматически защищает историю Git, но вы можете принять дополнительные меры для защиты своей работы:

* **Делайте коммиты чаще**: небольшие и частые коммиты обеспечивают непрерывное резервное копирование прогресса
* **Используйте чекпоинты**: при работе с [Replit Agent](/ru/ja/features/agent/overview) чекпоинты автоматически создают коммиты на важных этапах
* **Подключитесь к GitHub**: для важных проектов [подключите приложение к GitHub](/ru/ja/build/import-from-providers), чтобы получить дополнительный уровень резервного копирования
