<div id="suporte-a-navegadores">
  ### 浏览器支持
</div>

* **Chrome**、**Safari** 以及基于 Chromium 的浏览器均完全受支持。

<div id="quando-usar-o-expo-go-em-vez-disso">
  ### 何时改用 Expo Go
</div>

当你需要测试依赖真实硬件的功能，或想把预览分享给不在你电脑旁的人时，请在真机上使用 Expo Go：

* 摄像头、麦克风、触感振动或其他原生传感器
* 推送通知
* 真实环境中的 GPS 定位
* 与团队成员、测试人员或投资人分享开发预览

要在 Expo Go 中打开你的应用，请在 [replit.com](https://replit.com) 上打开项目，在 Project Editor 的预览面板中选择 **Open in Expo Go**，然后用手机上的 [Expo Go](https://expo.dev/go) 应用扫描二维码。

<div id="simulador-em-tela-cheia">
  ### 全屏模拟器
</div>

在移动应用产物的卡片上，选择 **More actions** → **Open in iOS Simulator** 或 **Open in Android Emulator**，即可在单独的标签页中打开模拟器，获得更大的视口。

<div id="por-que-construir-um-aplicativo-mobile">
  ## 为什么要构建移动应用？
</div>

当你有以下需求时，就可以构建移动应用：

* **原生体验**：性能流畅、交互顺滑，UI 符合平台原生风格。
* **设备能力**：摄像头、推送通知、定位等。
* **App Store 分发**：通过 Apple 的 App Review 审核后，即可获得一个可分享的应用页面，供用户发现并安装。

<div id="principais-recursos">
  ## 主要功能
</div>

* **AI 优先的构建方式**：描述你的应用，Agent 即可搭建出一个可运行的移动应用。
* **在 Project Editor 中预览**：无需离开 Replit，即可在 iOS Simulator 或 Android Emulator 中测试，也可以通过 Expo Go 在手机上查看。
* **默认 full-stack**：随着应用不断迭代，可随时添加服务器路由、Database、App Storage、Connectors 以及 AI 集成。
* **引导式提交**：无需管理本地 iOS 工具链，即可准备提交至 TestFlight 和 App Store 的构建版本。

<div id="fluxo-de-desenvolvimento">
  ## 开发流程
</div>

访问你的应用有三个阶段，每个阶段面向的用户和支持的能力各不相同：

| 阶段            | 谁可以访问           | 如何访问                                  | 最适合的场景       |
| ------------- | --------------- | ------------------------------------- | ------------ |
| **开发**        | 你自己             | Project Editor 中的模拟器，或用于 Expo Go 的二维码 | 构建与迭代        |
| **部署**        | 使用 Expo Go 的测试者 | 带二维码的公开 URL                           | 开发预览、原型验证与演示 |
| **App Store** | 任何人             | 通过 App Review 后从 App Store 下载         | 正式发布上线       |

**开发**：启动应用后，你可以在 Project Editor 的 **iOS Simulator** 或 **Android Emulator** 中预览，也可以扫描预览面板中的二维码，在手机上通过 Expo Go 打开。

**部署**：点击 **Publish** 后，Replit 会创建一个带有 Expo Go 二维码的公开 URL。这非常适合开发预览和原型验证——在正式走 App Store 流程之前，先展示给投资人、收集反馈，或与朋友一起测试。

**App Store**：提交到 App Store 后，Apple 会审核你的应用。审核通过后，任何人都可以从 App Store 下载并安装。这需要一个 Apple Developer 账户。

<div id="viso-geral-da-publicao">
  ## 发布概览
</div>

准备 iOS 上架时，流程通常如下：

* 从 Project Editor 发布
* 将构建版本提交到 TestFlight
* 在 App Store Connect 中将 TestFlight 的构建版本发布到 App Store

<Note>
  要向 TestFlight 和 App Store 提交构建版本，Apple 要求你订阅 Apple Developer Program。
</Note>

如需完整的分步说明，请参阅教程[构建并发布移动应用](/zh/pt/build/mobile-app)。

<div id="onde-construir-aplicativos-mobile-nativos">
  ## 在何处构建原生移动应用
</div>

你的 Replit 环境运行在云端，而不是本地计算机上。要构建原生移动应用，请在 [replit.com](https://replit.com) 中使用 Project Editor。移动应用的整个工作流程——由 Agent 搭建、在 Expo Go 中预览、在模拟器和仿真器中测试、在 TestFlight 中构建，以及提交至 App Store——都在 Project Editor 中完成。

在支持的情况下，你也可以在 [Replit Android 应用](/zh/pt/features/platforms/mobile-app)中进行原生移动应用的开发。如果你使用的是 Replit iOS 应用，请在 [replit.com](https://replit.com) 上打开项目，以创建、预览、构建或提交原生移动应用。

<div id="como-a-tecnologia-funciona">
  ## 技术原理
</div>

你的移动应用由一系列协同工作的技术构建而成。本节将介绍支撑应用运行的技术，以及各部分之间是如何配合的。

<div id="o-stack-de-tecnologia">
  ### 技术栈
</div>

<MobileStackDiagram />

* **React Native** 是一个开源框架，让你只需编写一套代码，即可编译到 iOS、Android 和 Web 平台。它渲染的是平台原生 UI 组件，而不是 webview。
* **Expo** 负责管理构建、处理原生模块，并提供 Expo Go 等预览工具，从而简化 React Native 的开发。
* **Expo Go** 是一款安装在手机上的免费应用。它可以运行你的开发预览，让你无需构建完整的原生二进制文件，就能在真机上测试。

运行应用时，Metro 打包器会编译你的代码并将其发送到设备上。首次构建耗时较长，因为此时还没有缓存；后续构建会快得多。

<div id="arquitetura-servidor-e-cliente">
  ### 架构：服务端与客户端
</div>

在准备移动应用的预览或分发时，你实际上要处理两部分内容：

1. **服务端**：运行在云端的 Replit 上，负责数据库、API 路由、AI 集成和后端逻辑。
2. **客户端应用**：运行在用户的手机上。它就是开发阶段在 Expo Go 中预览、审核通过后经应用商店分发的原生应用。

<MobileArchitectureDiagram />

这种分离带来了灵活性：复杂逻辑可以放在服务端运行 (在那里可以使用 Replit 的 Database、Object Storage 和 Connectors) ，客户端则保持轻量。构建时不妨想清楚，哪些事情该在手机上完成，哪些该交给云端。

<div id="consideraes">
  ## 注意事项
</div>

* **发布要求**：TestFlight 和 App Store 的相关要求由 Apple 制定，且 iOS 应用在分发前需经过 Apple 审核。
* **在 Android 上发布**：你可以构建同时支持 iOS 和 Android 的跨平台应用。目前还没有针对 Google Play 发布的引导式流程，但可以手动完成发布。
* **原生改动**：应用图标、权限等改动通常需要重新构建一个用于上架的 build。

<div id="perguntas-frequentes">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="什么是 Expo？">
    Expo 是 Agent 在 Replit 上构建移动应用时使用的工具。它是一个开源平台和工具链，用于基于 React Native 构建、运行和部署跨平台原生应用。详见 [https://expo.dev](https://expo.dev)。
  </Accordion>

  <Accordion title="什么是 React Native？">
    React Native 是 Meta 推出的开源框架，用于通过 React 以及 JavaScript 或 TypeScript 构建 iOS 和 Android 原生应用。它渲染的是平台原生 UI 组件 (而非 webview) ，因此你的应用在外观和使用体验上都与原生应用一致。
  </Accordion>

  <Accordion title="什么是 Expo Go？">
    Expo Go 是一款免费应用，你可以从 App Store 或 Google Play 安装到手机上。它让你在开发过程中预览移动应用，而无需构建完整的原生二进制文件。当你在 Project Editor 中扫描二维码时，Expo Go 会下载并运行你的应用代码。
  </Accordion>

  <Accordion title="Expo Go 和 dev build 有什么区别？">
    **Expo Go** 是一个预先构建好的应用，用于运行你的代码。它配置起来很快，但仅支持 Expo SDK 中包含的模块。

    **dev build** 是自定义的原生二进制文件，可以包含任意原生模块。它需要更多配置 (EAS Build 或本地的 Xcode/Android Studio) ，但灵活性更高。

    Replit 使用 Expo Go 进行开发预览。如果你需要 Expo Go 不支持的原生模块，可以通过 [Expo 文档](https://docs.expo.dev/develop/development-builds/introduction/)了解 dev build。
  </Accordion>

  <Accordion title="它与移动端响应式网页应用有什么区别？">
    移动端响应式网页应用是在浏览器中自适应布局的网站。React Native 应用则是安装在设备上的原生应用，可调用平台 API (摄像头、触感振动、推送通知) ，对硬件和离线能力的支持更好，并通过应用商店分发。响应式网页胜在覆盖面广、无需安装；而当你需要调用设备功能、追求性能或通过 App Store 分发时，原生应用更合适。
  </Accordion>

  <Accordion title="我需要 Mac 或 Xcode 吗？">
    不需要。Replit 和 Expo 会在云端为你处理构建流程。
  </Accordion>

  <Accordion title="没有 Apple Developer 账号也能预览吗？">
    可以。你可以在 Project Editor 的 iOS Simulator 中预览，或在手机上使用 Expo Go 预览。只有在准备提交到 TestFlight 或 App Store 时，才需要 Apple Developer 账号。
  </Accordion>

  <Accordion title="支持 Android 吗？">
    支持。你可以基于同一套代码库构建 iOS 和 Android 跨平台应用。可在 Project Editor 的 Android Emulator 中预览，或在装有 Expo Go 的 Android 设备上预览。发布到 Google Play 可以手动完成。
  </Accordion>

  <Accordion title="服务器和数据库怎么办？">
    使用 Replit 内置的 PostgreSQL、Object Storage、Connectors 和 AI 集成——无需单独搭建基础设施。你的服务器在 Replit 上运行，移动应用连接到它即可。
  </Accordion>

  <Accordion title="我应该在 Project Editor 的模拟器还是真机上测试？">
    两者在不同阶段各有用武之地。Project Editor 中的 **iOS Simulator** 和 **Android Emulator** 展示的是应用的原生版本，能覆盖大部分日常测试——布局、导航、原生组件和平台样式。当你需要测试依赖真实硬件的功能时，比如摄像头、触感振动、推送通知或 GPS 定位，就改用装有 **Expo Go** 的真机。
  </Accordion>
</AccordionGroup>
