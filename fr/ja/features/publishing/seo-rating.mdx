Lorsque vous publiez une application web sur Replit, un audit d&#39;optimisation pour les moteurs de recherche (SEO) est automatiquement exécuté sur l&#39;URL en ligne, et le score SEO s&#39;affiche dans l&#39;outil Publishing. Si le score est perfectible, il suffit d&#39;un clic pour transmettre les problèmes précis à Agent, qui les corrige en quelques secondes.

Pour de nombreux créateurs, le flux de travail se résume à ceci : publier l&#39;application, jeter un œil au score, puis demander à Agent d&#39;« optimiser le SEO ». Cette page explique ce qui se passe en coulisses et comment en tirer le meilleur parti.

<div id="seo">
  ## Qu&#39;est-ce que le SEO et pourquoi est-ce important ?
</div>

L&#39;optimisation pour les moteurs de recherche (SEO) consiste à concevoir votre site de manière que les moteurs de recherche comme Google puissent le trouver, le comprendre et le classer. Avec un bon référencement, votre application apparaît dans les résultats lorsque les internautes cherchent ce qu&#39;elle propose, sans que vous ayez à payer de publicité.

L&#39;essentiel des résultats en SEO tient à quelques éléments : des titres et des descriptions de page clairs, un HTML sémantique, des temps de chargement rapides, une mise en page adaptée aux mobiles, un texte alternatif descriptif pour les images et une structure de site explorable. Les moteurs de recherche privilégient les sites faciles à lire, aussi bien pour les humains que pour les machines.

Si vous publiez une page de destination, un site marketing, un blog, un annuaire ou tout autre projet dont la visibilité est déterminante, le SEO est l&#39;un des investissements les plus rentables à réaliser dès le départ.

<div id="replitseo">
  ## Améliorations SEO incluses par défaut avec Replit
</div>

Replit prend en charge de nombreux fondamentaux du SEO, pour vous permettre de vous concentrer sur votre contenu et votre produit.

* **Hébergement rapide et distribué à l&#39;échelle mondiale** : Replit Deployments diffuse votre application depuis une infrastructure optimisée pour la vitesse et vous permet de choisir où elle s&#39;exécute grâce à la [région du projet](/fr/ja/features/publishing/project-geography).
* **HTTPS par défaut** : toutes les applications publiées bénéficient de certificats TLS gérés par Replit. Il s&#39;agit d&#39;un signal de classement essentiel pour les moteurs de recherche.
* **Domaines personnalisés** : connectez votre propre domaine pour renforcer la confiance et l&#39;autorité de votre marque. Consultez les [domaines personnalisés](/fr/ja/features/publishing/custom-domains).
* **Static Deployments pour les sites de contenu** : pour les pages marketing, les blogs et la documentation, les [Static Deployments](/fr/ja/features/publishing/deployment-types#static) fournissent du HTML pré-rendu que les moteurs de recherche peuvent facilement explorer.
* **Agent génère du code optimisé pour le SEO** : lorsque Agent crée des pages, il génère par défaut du HTML sémantique, un balisage accessible et des balises méta. Ce sont les mêmes éléments que les outils SEO vérifient.
* **Score SEO** : des audits s&#39;exécutent automatiquement après la publication, ce qui vous permet de toujours connaître l&#39;état actuel et de transmettre les problèmes détectés à Agent en un clic.

<div id="seo-2">
  ## Score SEO
</div>

À chaque publication réussie, Replit exécute un audit Lighthouse sur les URL du déploiement et en enregistre les résultats. L&#39;outil Publishing affiche le score SEO global de l&#39;application.

<div id="section">
  ### Où le trouver
</div>

Ouvrez l&#39;outil **Publishing** dans une application publiée. Le score SEO s&#39;affiche dans le récapitulatif du déploiement, avec les autres détails de la build. Survolez le score pour connaître les points précis relevés par Lighthouse sur chaque page.

<Note>
  Si aucun score SEO n&#39;apparaît, votre application est peut-être privée ou n&#39;a pas été publiée récemment. Le score ne s&#39;affiche que pour les applications web accessibles publiquement.
</Note>

<div id="section-2">
  ### Comment lire le score
</div>

Replit affiche l&#39;un des trois scores suivants, à partir de l&#39;audit Lighthouse.

| Score      | Signification                                                                                                        |
| :--------- | :------------------------------------------------------------------------------------------------------------------- |
| Healthy    | Votre application respecte les bonnes pratiques SEO. Vérifiez-la attentivement après chaque modification importante. |
| Needs Work | Certains problèmes limitent la capacité des moteurs de recherche à comprendre votre application.                     |
| Weak       | Des fondamentaux SEO essentiels sont absents. La correction ne prend généralement que quelques minutes.              |

Si votre application comporte plusieurs pages, le badge affiche le score **le plus bas** parmi toutes les URL explorées par Replit. Les pages les plus problématiques ressortent ainsi en premier, sans être masquées par une moyenne.

<div id="section-3">
  ### Quand le score est-il calculé ?
</div>

L&#39;audit s&#39;exécute automatiquement après chaque publication réussie. Le score apparaît généralement une à deux minutes après la mise en ligne du déploiement, et l&#39;outil Publishing met à jour le badge dès réception des résultats.

<div id="section-4">
  ### Types de déploiement pris en charge
</div>

Le score SEO est calculé pour les déploiements web publics dont l&#39;URL peut être explorée par les moteurs de recherche.

* [Déploiements Autoscale](/fr/ja/features/publishing/deployment-types#autoscale)
* [Déploiements Reserved VM](/fr/ja/features/publishing/deployment-types#reserved-vm)
* [Static Deployments](/fr/ja/features/publishing/deployment-types#static)

Les déploiements planifiés et les déploiements privés ne traitent pas de trafic web public : aucun score SEO n&#39;est donc généré pour eux.

<div id="agentseo">
  ## Optimiser le SEO avec Agent
</div>

Un bouton **Optimize SEO with Agent** apparaît à côté du score. En le sélectionnant, vous ouvrez le [SEO Agent](/fr/ja/features/publishing/seo-agent) dans le panneau Growth : vous pouvez alors lancer un audit SEO technique, examiner les problèmes détectés et appliquer les corrections en un clic.

<Tip>
  Vous pouvez aussi vous passer du bouton. Ouvrez simplement Agent et demandez-lui **« Optimise le SEO »** : Agent récupère les résultats les plus récents et se met au travail.
</Tip>

Une fois qu&#39;Agent a terminé ses modifications, republiez votre app. Le score SEO est recalculé sur la nouvelle version et le badge se met à jour automatiquement.

Voici les corrections les plus courantes appliquées par Agent :

* Ajouter ou corriger les balises `<title>` manquantes ou génériques, afin que chaque page ait un titre unique et descriptif
* Ajouter une méta-description à toutes les pages
* Ajouter un texte `alt` descriptif aux images
* Définir l&#39;attribut `lang` sur l&#39;élément `<html>`
* Vérifier que les liens comportent un texte identifiable (pas de « cliquez ici » ni d&#39;ancres vides)
* Ajouter `robots.txt` et `sitemap.xml`
* Ajouter la balise méta viewport pour l&#39;affichage mobile
* Améliorer le contraste des couleurs du texte qui échoue aux contrôles d&#39;accessibilité
* Ajouter les balises méta Open Graph et Twitter Card pour que les liens vers votre app s&#39;affichent avec un aperçu soigné sur les réseaux sociaux

<div id="replitseo-2">
  ## Bonnes pratiques pour créer un site optimisé pour le SEO sur Replit
</div>

Que vous confiiez ces tâches à Agent ou que vous les réalisiez vous-même, voici les éléments les plus efficaces pour les applications créées avec Replit.

* **Donnez un titre et une méta-description uniques à chaque page.** Visez 60 caractères maximum pour le titre et environ 150 à 160 caractères pour la description.
* **Utilisez du HTML sémantique.** Structurez votre mise en page avec `<main>`, `<header>`, `<nav>` et `<footer>`. N&#39;utilisez `<h1>` qu&#39;une seule fois par page et respectez l&#39;ordre des niveaux de titre.
* **Ajoutez un texte alternatif à toutes les images.** Décrivez ce que l&#39;image montre, et pas seulement ce qu&#39;elle est.
* **Générez un `sitemap.xml` et un `robots.txt`.** Demandez à Agent de créer les deux afin que les moteurs de recherche sachent ce qu&#39;ils doivent explorer.
* **Ajoutez des balises Open Graph et Twitter Card.** Vous contrôlez ainsi l&#39;apparence de votre application lorsqu&#39;elle est partagée sur les réseaux sociaux.
* **Utilisez un domaine personnalisé.** Un domaine à votre image renforce la confiance des visiteurs comme des moteurs de recherche. Consultez [Domaines personnalisés](/fr/ja/features/publishing/custom-domains).
* **Choisissez le bon type de déploiement.** Pour les sites riches en contenu, les [Static Deployments](/fr/ja/features/publishing/deployment-types#static) fournissent un HTML pré-rendu que les moteurs de recherche peuvent analyser immédiatement.
* **Ajoutez des données structurées.** Le balisage JSON-LD permet aux moteurs de recherche d&#39;afficher des résultats enrichis pour les produits, les articles, les FAQ et les événements.
* **Gardez votre application rapide.** Optimisez les images, évitez les scripts qui bloquent le rendu et tirez parti de l&#39;hébergement Replit pour maintenir des temps de réponse faibles.

Voici un moyen simple d&#39;appliquer la plupart de ces recommandations en une seule fois.
