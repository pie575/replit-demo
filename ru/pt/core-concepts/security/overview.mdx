Когда вы публикуете проект через Replit, он может начать получать реальный трафик. Инструменты безопасности Replit помогают находить уязвимости, устранять подтверждённые проблемы с помощью Agent и сохранять подтверждения для аудита.

<div id="por-que-a-segurana-importa">
  ## Почему безопасность важна
</div>

* Опубликованные проекты доступны из открытого интернета, включая публичные маршруты и API.
* Современные проекты зависят от множества пакетов, и новые CVE могут появиться уже после публикации.
* Код, сгенерированный ИИ, всё равно требует проверки безопасности — особенно в части аутентификации, запросов к базе данных, secrets и обработки данных.
* Программы соответствия требованиям нередко требуют подтверждений: инвентаризации зависимостей, отслеживания уязвимостей и их устранения.

<div id="por-onde-comear">
  ## С чего начать
</div>

* Работаете над одним проектом? Используйте [Project Security Center](/ru/pt/core-concepts/security/project-security-center).
* Проводите аудит всего workspace? Используйте [Workspace Security Center](/ru/pt/core-concepts/security/workspace-security-center).
* Нужно определение? Прочитайте раздел [Концепции безопасности](/ru/pt/core-concepts/security/concepts).

Большая часть работы с безопасностью строится по одному и тому же циклу: сканирование, анализ результатов, исправление с помощью Agent, повторная публикация и экспорт подтверждающих данных при необходимости.

<div id="onde-fica-a-segurana-no-produto">
  ## Где в продукте находятся настройки безопасности
</div>

<div id="em-um-projeto">
  ### В проекте
</div>

Откройте панель **Security**, чтобы просмотреть результаты на уровне проекта, запустить сканирование безопасности с помощью Agent и проверить уязвимости зависимостей перед публикацией.

<div id="no-seu-workspace">
  ### В вашем workspace
</div>

Выберите **Security** на боковой панели главной страницы, чтобы просмотреть уязвимости во всех проектах, ранжировать результаты по уровню риска и отслеживать историю сканирований на уровне workspace.

<div id="na-publicao-e-nas-configuraes">
  ### При публикации и в настройках
</div>

* В разделе **Publish** &gt; **Advanced** включите параметр **Block publishing of critical vulnerabilities**, чтобы запретить публикацию при наличии критических уязвимостей.
* В разделе **Settings** &gt; **Account** &gt; **Advanced** задайте порог серьёзности для Auto-Protect применительно к исправлениям зависимостей, подготовленным Agent.
