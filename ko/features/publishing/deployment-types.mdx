배포 유형은 Replit이 앱을 게시할 때 사용하는 기술입니다. 게시 도구의 **Adjust settings**에 있는 **Deployment type** 드롭다운에서 선택할 수 있습니다. 기본값이자 권장 옵션은 **Autoscale**이며, 대부분의 builder는 이를 변경할 필요가 없습니다.

<div id="compare-deployment-types">
  ## 배포 유형 비교
</div>

| 유형              | 적합한 용도                  | 실행 방식                              | 과금 방식               |
| :-------------- | :---------------------- | :--------------------------------- | :------------------ |
| **Autoscale**   | 트래픽 변동이 큰 web app 및 API | 트래픽이 많으면 서버를 추가하고, 유휴 상태에서는 0으로 축소 | 요청을 처리하는 동안에만 과금    |
| **Static**      | 랜딩 페이지, 포트폴리오, 문서 사이트   | 캐시된 클라우드 서버에서 파일을 제공하며 backend 없음  | 사이트가 전송하는 데이터만큼만 과금 |
| **Reserved VM** | 봇, 백그라운드 작업, 상시 실행 API  | 절전되지 않는 전용 서버 1대                   | 고정 월 비용             |
| **Scheduled**   | 백업, 알림 등 주기적인 task      | 일정에 따라 명령을 실행한 후 종료                | 실행할 때마다 실행 시간만큼 과금  |

<div id="autoscale">
  ## Autoscale
</div>

Autoscale Deployments는 앱의 트래픽에 맞춰 확장하고 축소하는 서버에서 실행됩니다. 앱에 트래픽이 몰리면 Replit이 서버를 추가해 부하를 처리합니다. 앱이 유휴 상태일 때는 서버 수가 0까지 줄어들어, 사용하지 않는 시간에는 비용이 발생하지 않습니다.

다음과 같은 경우에 적합합니다:

* 전자상거래 사이트처럼 트래픽 변동이 큰 웹 애플리케이션
* API 및 서비스

구성은 **Adjust settings**에서 관리합니다: [머신 성능과 최대 서버 수](/ko/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Static Deployments는 HTML, CSS, JavaScript 같은 앱 파일을 캐싱 기반 클라우드 서버에 호스팅하여 콘텐츠를 빠르고 경제적으로 전달합니다. 백엔드 서버는 없습니다.

다음과 같은 용도에 적합합니다:

* 마케팅 랜딩 페이지
* 포트폴리오 웹사이트
* 제품 및 API 문서 사이트

<Note>
  Static Deployments는 Agent로 만든 Replit Apps와 호환되지 않습니다. Agent는 백엔드 서버가 필요한 full-stack 앱을 빌드하므로, 이러한 앱에는 Autoscale 또는 Reserved VM을 사용하세요.
</Note>

구성 항목에는 제공할 공개 디렉터리와 선택 사항인 빌드 명령이 포함됩니다. 응답 headers, URL rewrites, 리디렉션에 대해서는 [고급 Static 구성](/ko/features/deployment-customization/static-deployments-advanced)을 참고하세요.

<div id="reserved-vm">
  ## Reserved VM
</div>

Reserved VM Deployments는 절전 모드로 전환되지 않는 전용 가상 머신에서 앱을 실행합니다. 일관된 성능과 예측 가능한 고정 월 비용을 제공합니다.

다음과 같은 경우에 적합합니다:

* 메모리를 많이 사용하는 백그라운드 작업
* 연결을 계속 유지해야 하는 챗봇
* 항상 켜져 있는 API 서버

구성 항목에는 [머신 성능](/ko/features/publishing/machine-configuration), build 및 run 명령, 포트 매핑, 앱을 웹 서버로 실행할지 백그라운드 워커로 실행할지 여부가 포함됩니다.

<div id="scheduled">
  ## Scheduled
</div>

Scheduled Deployments는 앱 환경에서 지정한 schedule에 따라 명령을 실행한 뒤, 다음 run까지 중지 상태로 대기합니다. &quot;매주 평일 오전 9시&quot;처럼 일상적인 표현으로 schedule을 설명하면 Replit이 자동으로 schedule로 변환해 줍니다. run이 실패하면 alert을 받습니다.

다음과 같은 작업에 적합합니다:

* 상태 점검 및 헬스 report
* 알림 전송
* 백업 시작

구성에는 schedule, job 제한 시간, build 및 run 명령이 포함됩니다. Scheduled Deployments는 웹 페이지를 serve하지 않으므로 public URL이 없습니다.
