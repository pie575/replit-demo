本指南介绍如何手动将应用复制到其他工作区或账户。你需要复制代码、设置新应用、复制数据，然后将用户引导至新应用。

此过程不会移动或删除任何内容。旧项目仍保留在原处，两份副本之间也不会同步。完成后，你可以选择保留或删除旧项目。

<Note>
  想找内置的一键转移功能？请参阅[将应用转移到 Teams](/zh/ja/teams/identity-and-access-management/transfer-app-to-teams)。如果该选项不可用，或者你需要在不同账户之间复制，请使用本指南。
</Note>

<div id="section">
  ## 开始之前
</div>

你需要准备以下内容：

* 旧项目以及新工作区或账户的访问权限。
* 大约一小时不受打扰的时间来完成最终切换。在此之前的步骤可以分几天完成。
* 如果你的应用使用了自定义网址，还需要有权访问该域名的管理平台。

有两项内容不会自动复制，也最为耗时：**数据库**和**网址**。本指南会一并介绍这两部分。

<Note>
  如果工作区管理员启用了[禁止导出源代码](/zh/ja/teams/enterprise-privacy-settings#ban-source-code-export)，你将无法把项目下载为 ZIP 文件。开始之前请先咨询工作区管理员——他们可以确认是否允许手动复制，以及如何迁移代码和数据库。
</Note>

<div id="section-2">
  ## 规划停机时间
</div>

想象一下先开第二家店，再关掉第一家店。中间会有一小段时间，旧店已经关门，新店还没开张。在这段时间里，没有人能使用你的应用。

**应用会离线多久？** 通常是 15 到 60 分钟，具体取决于数据库中的数据量，以及网址更新的速度。

**数据会丢失吗？** 只有在你复制完数据库之后仍有人向旧应用写入数据时，才会发生数据丢失。为避免这种情况，请在进行最后一次复制*之前*先让旧应用下线。本指南就是按这个顺序编排的。

**可以撤销吗？** 可以。旧项目不会被删除。如果出现任何问题，只需重新发布旧应用，它就会和之前完全一样地运行。

**应该在什么时候操作？** 请选择使用应用的人较少的时段。如果条件允许，请提前通知用户。

<div id="1">
  ## 步骤 1：将代码复制到新项目
</div>

请选择一种方法。在此步骤期间，旧应用会继续运行。两种方法都会迁移代码，但 GitHub 始终会保留提交历史，而 ZIP 仅在包含 `.git` 文件夹时才会保留历史：

|            | 通过 GitHub                  | 通过 ZIP 文件                                                |
| ---------- | -------------------------- | -------------------------------------------------------- |
| **代码文件**   | 仅包含已提交并推送的文件               | 磁盘上的所有内容，包括未提交的更改                                        |
| **提交历史**   | 远程仓库的完整历史                  | 若 ZIP 中包含 `.git` 文件夹，则保留完整历史；若为满足导入大小限制而排除了 `.git`，则没有历史 |
| **依赖项文件夹** | 遵循 `.gitignore`            | 会被排除 (如 `node_modules`、`.venv`、`build` 等) ；导入时会重新安装      |
| **要求**     | 两个 Replit 账户均已连接 GitHub 账户 | 无                                                        |
| **持续同步**   | 两份副本可向同一个仓库推送和拉取           | 无——仅为一次性快照                                               |
| **最适合**    | 希望长期使用 Git 备份的项目           | 快速的一次性复制                                                 |

<div id="github">
  ### 通过 GitHub
</div>

<Steps>
  <Step title="将旧项目推送到 GitHub">
    在旧项目中打开 [Git 面板](/zh/ja/features/workspace-tools/git-interface)，连接 GitHub 仓库，然后提交并推送。如果不想公开代码，请使用私有仓库。
  </Step>

  <Step title="向新账户授予访问权限">
    如果新的 工作区 属于另一个 Replit 账户，则该 GitHub 账户需要拥有该仓库的访问权限。对于私有仓库，请将该 GitHub 账户添加为协作者，或使用共享的 GitHub 组织。
  </Step>

  <Step title="在新 工作区 中导入">
    登录新账户，打开 [replit.com/import](https://replit.com/import)，选择 **GitHub**，连接 GitHub 账户，然后选择仓库。故障排除方法请参阅[从身份提供方导入](/zh/ja/build/import-from-providers)。
  </Step>

  <Step title="确认副本">
    打开新项目，确认文件和提交历史均已存在。Replit 会在导入过程中安装依赖项并配置运行命令。
  </Step>
</Steps>

<Warning>
  GitHub 只会接收你已提交并推送的内容。与 `.gitignore` 匹配的文件以及未提交的更改会留在原处。请勿将密钥值或数据库转储提交到仓库中。
</Warning>

<div id="zip">
  ### 通过 ZIP 文件
</div>

<Steps>
  <Step title="下载旧项目">
    在旧 项目 中，选择文件树顶部的三点菜单，然后选择 **Download as zip**。

    如果下载成功且文件小于 200 MB，请继续下一步。

    超过 200 MB 的 ZIP 文件有时也能下载成功。但 [ZIP 导入](/zh/ja/build/import-from-providers#limitations)会拒绝大于 200 MB 的文件，因此 Replit 无法用它创建新 项目。如果下载失败，或 ZIP 超过 200 MB，请创建一个更小的压缩包：

    1. 在旧 项目 中打开 **Shell** 工具。

    2. 粘贴以下命令并按回车键。它会创建一个名为 `project.zip` 的文件，并排除 Replit 可以自行重建的文件夹：

       ```bash theme={null}
       zip -r project.zip . -x ".cache/*" "node_modules/*" ".venv/*" "venv/*" ".pythonlibs/*" "build/*" "target/*" ".next/*" "__pycache__/*"
       ```

    3. 检查文件大小。粘贴以下命令并按回车键。它会以 MB 为单位显示大小 (例如 150 MB 显示为 `150M`) ：

       ```bash theme={null}
       du -h project.zip
       ```

    4. 如果超过 200 MB，可排除编辑历史以进一步缩小文件。粘贴以下两行并按回车键：

       ```bash theme={null}
       rm project.zip
       zip -r project.zip . -x ".cache/*" ".local/*" ".git/*" "node_modules/*" ".venv/*" "venv/*" ".pythonlibs/*" "build/*" "target/*" ".next/*" "__pycache__/*"
       ```

       仅在需要将 ZIP 压缩到 200 MB 以下时才排除 `.local` 和 `.git`。排除这两个文件夹并不会将它们从旧 项目 中删除，但不含 `.git` 的 ZIP 也就不包含 项目 的提交历史。如果需要保留历史记录，请改用 GitHub 方法。

    5. 在文件树中找到 `project.zip`，选择其旁边的三点菜单，然后选择 **Download**。

    `.cache` 文件夹保存着 Replit 的内部状态，其中包含缓存的密钥值，手动创建 ZIP 文件时请务必将其排除。如果 项目 中还有其他体积较大的生成文件夹，也请一并加入排除列表。
  </Step>

  <Step title="在新工作区中导入">
    登录新账户，打开 [replit.com/import](https://replit.com/import)，选择 **ZIP**，然后上传文件。
  </Step>

  <Step title="确认复制结果">
    打开新 项目，确认文件都在。如果 ZIP 中包含 `.git` 文件夹，提交历史也会一并导入；如果使用的是更小的归档命令，新 项目 将从没有提交历史的状态开始。导入过程中，Replit 会重新安装被排除的依赖项。
  </Step>
</Steps>

<div id="2">
  ## 步骤 2：设置新应用
</div>

旧应用仍在运行。在这一步中，你将使用数据的*测试副本*让新应用完整运行起来，以便之后能快速完成最终切换。

<Steps>
  <Step title="添加 Secrets">
    Secrets 的值 (API 密钥、密码) 不会离开旧 项目。请在两个 项目 中分别打开 [Secrets](/zh/ja/core-concepts/project-editor/app-setup/secrets) 工具，逐个手动复制，别忘了部署所用的 Secrets。
  </Step>

  <Step title="重新连接 connector 和其他服务">
    在新 项目 的 **Tools → Connectors** 中重新连接各项集成。关于 App Storage、协作者以及其他所有内容，请参阅[重新创建无法复制的内容](#re-create-what-doesnt-copy-over)。
  </Step>

  <Step title="发布新应用">
    [发布](/zh/ja/features/publishing/overview)新 项目。系统会为其创建独立的 `replit.app` 网址和独立的空生产数据库。此时请先不要连接自定义域名。
  </Step>

  <Step>
    按照下方的[复制数据库](#copy-the-database)操作，将新 项目 的**生产**数据库作为目标。这样你就有了可用于测试的真实数据。在步骤 3 中，你会用最新数据替换这份副本。
  </Step>

  <Step>
    通过 `replit.app` 地址打开新应用，像用户那样实际使用一遍。在继续之前，修复发现的任何问题。此时还不会影响到用户。
  </Step>
</Steps>

<div id="3">
  ## 步骤 3：将用户切换到新 App
</div>

这一步会产生停机时间，请一次性集中完成。

<Steps>
  <Step title="让旧 App 下线">
    在旧项目中打开 **Publishing** 工具，选择 **Unpublish**。此时 App 即已下线。从这一刻起，任何人都无法再添加新数据，因此接下来创建的副本会是完整的。
  </Step>

  <Step title="再复制一次数据库">
    按照下面的[复制数据库](#copy-the-database)操作，并将新项目的**生产**数据库用作目标。这份副本将包含所有最新数据。
  </Step>

  <Step title="将网址指向新 App">
    如果你的 App 使用自定义域名：在旧项目中打开 **Publishing → Domains**，断开该域名；然后在新项目中打开 **Publishing → Domains** 并进行[连接](/zh/ja/features/publishing/custom-domains#connect-a-domain-you-already-own)。如果 Replit 提示你操作，请在域名服务商 (例如 GoDaddy 或 Namecheap) 处更新记录。

    新地址可能需要几分钟到几小时才能对所有人生效。在此期间，部分访问者可能会看到错误页面。

    如果你的 App 仅使用 `replit.app` 地址，则改为把新地址分享给用户即可。
  </Step>

  <Step title="确认新 App 正常运行">
    打开网址，确认新 App 能连同数据一起加载。至此，App 已重新上线。
  </Step>
</Steps>

<div id="section-3">
  ## 复制数据库
</div>

复制代码不会影响数据库。数据需要用 PostgreSQL 的 `pg_dump` 和 `pg_restore` 工具来复制，这两个工具在两个项目的 Shell 中都可以使用。步骤 2 和步骤 3 都会用到这里的内容，命令每次都一样，唯一变化的是*目标*。

<Warning>
  执行 `pg_dump` 之后写入的数据不会包含在副本中。在步骤 3 做最终复制时，请先让旧应用下线。
</Warning>

<Steps>
  <Step title="从旧项目导出数据">
    在旧项目中打开 **Shell** 工具，粘贴以下命令并按 Enter 键。该命令会在文件树中创建一个名为 `backup.dump` 的文件：

    ```bash theme={null}
    pg_dump -Fc "$DATABASE_URL" --no-owner --no-privileges -f backup.dump
    ```

    这会导出**开发**数据库。而线上运行的数据通常位于**生产**数据库中。要导出生产数据库：

    1. 打开 **Database** 工具，选择生产数据库并打开 **Settings**。
    2. 复制连接字符串。
    3. 在上述命令中，将 `"$DATABASE_URL"` 替换为该连接字符串，并保留引号。

    如果找不到，请参阅[连接详情](/zh/ja/features/data-and-storage/connection-details)。
  </Step>

  <Step title="将转储文件移动到新项目">
    在旧项目的文件树中，点击 `backup.dump` 旁边的三点菜单并下载该文件。然后使用文件树中的 **Upload files** 选项将其上传到新项目。

    如果你是通过 GitHub 复制代码的，请不要提交该转储文件。请单独移动它，以免数据进入仓库。
  </Step>

  <Step title="在新项目中导入数据">
    在新项目中打开 **Shell** 工具，粘贴以下命令并按 Enter 键：

    ```bash theme={null}
    pg_restore --clean --if-exists --single-transaction --no-owner --no-privileges --exit-on-error -d "$DATABASE_URL" backup.dump
    ```

    命令保持原样时，数据会导入到新项目的**开发**数据库中，这正是步骤 2 所需要的。

    而在步骤 3 做最终复制时，则需要导入到**生产**数据库。请在新项目中打开 **Database** 工具，选择生产数据库并打开 **Settings**，复制连接字符串，用它替换 `"$DATABASE_URL"`。

    该命令会先删除目标数据库中匹配的对象，然后载入数据。执行结束后没有任何输出，即表示成功。
  </Step>
</Steps>

<Note>
  如果 `pg_restore` 因角色或策略错误而失败，说明数据库使用了新项目中尚不存在的自定义 PostgreSQL 角色。请[联系支持团队](https://replit.com/support)。
</Note>

<Note>
  如果新项目使用的是[旧版 Neon 开发数据库](/zh/ja/features/data-and-storage/development-and-production#legacy-development-database)，发布流程会提供**使用当前开发数据设置生产数据库**的选项。它会复制发布那一刻开发数据库中的内容，用于测试没问题，但最终切换时请按上述步骤操作，以获取最新数据。
</Note>

<div id="section-4">
  ## 重新创建不会被复制的内容
</div>

项目的其余配置存在于文件系统之外。请在新项目中逐项重新创建：

| 项目                  | 处理方式                                                                                                                         |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Secrets**         | 密钥值不会从旧项目中带出。请在新项目的 [Secrets](/zh/ja/core-concepts/project-editor/app-setup/secrets) 工具中重新添加，包括部署密钥。                            |
| **Account Secrets** | 请在新项目中[关联](/zh/ja/core-concepts/project-editor/app-setup/secrets#manage-account-secrets)。如果新项目属于其他账户，请先将其添加到该账户。                |
| **App Storage**     | 存储桶不会一并迁移。在同一账户内，请[添加现有存储桶](/zh/ja/features/data-and-storage/object-storage#bucket-access-management)。若涉及不同账户，请先下载对象，再上传到新的存储桶。 |
| **Connectors**      | 请在新项目的 **Tools → Connectors** 中重新连接各项集成。参见[集成概览](/zh/ja/features/integrations/overview)。                                        |
| **Deployments**     | 副本处于未发布状态。请参照[步骤 2](#step-2-set-up-the-new-app)，从新工作区进行[发布](/zh/ja/features/publishing/overview)。                               |
| **Custom Domains**  | 请从旧的部署中删除域名，将其关联到新的部署，并更新 DNS 记录。详见[步骤 3](#step-3-switch-your-users-to-the-new-app)。                                         |
| **Collaborators**   | 请在新工作区中重新邀请协作者，并设置[访问权限](/zh/ja/teams/identity-and-access-management/groups-and-permissions)。                                   |
| **Agent history**   | Agent 的对话和[检查点](/zh/ja/features/version-control/checkpoints-and-rollbacks)回滚仍保留在旧项目中。检查点对应的提交会随 Git 历史一起迁移，但无法在副本中回滚到这些检查点。     |

<div id="section-5">
  ## 如果出现问题
</div>

旧项目仍然还在。要恢复它：

1. 在旧项目中打开 **Publishing** 工具，然后选择 **Publish**。
2. 如果你迁移过自定义域名，用同样的方法把它迁回去。

应用会以下线时的数据重新运行，不会丢失任何内容。

<div id="section-6">
  ## 清理
</div>

请等待一周左右，确认新应用运行正常。然后：

* 从两个项目和你的设备中删除 `backup.dump`，每份副本都包含完整的数据导出。
* 如有需要，删除旧项目。
