게시에 적용되는 usage-based billing에는 세 가지 유형이 있습니다.

1. Outbound Data Transfer
2. Autoscale Compute Units
3. 요청 수

usage는 **Settings**의 **Account** → **Account usage**에서 확인할 수 있습니다. 청구는 매월, 또는 누적 비용이 월별 credits을 초과하는 시점에 이루어집니다. Replit Core 및 Pro 사용자는 이러한 리소스에 대해 매월 allowance를 제공받습니다.

월 구독 allowance보다 많은 credits이 필요하다면 billing 페이지에서 credit packs을 구매할 수 있습니다. credit packs에 대한 자세한 내용은 [지출 관리](/ko/billing/managing-spend)를 참조하세요.

<div id="publishing">
  # 게시
</div>

<div id="1-publishing-outbound-data-transfer">
  ## 1. 게시 Outbound Data Transfer
</div>

이 유형의 usage는 바이트 단위로 청구되며, Replit Core 및 Pro 사용자에게는 매월 allowance가 제공됩니다. 이 allowance에는 이그레스(외부로 나가는) 데이터만 집계되며, 이를 초과하면 추가 요금이 발생할 수 있습니다. 반면 인그레스(들어오는) 데이터는 항상 무료입니다.

| 구독          | Allowance                                               |
| ----------- | ------------------------------------------------------- |
| Replit Core | 100 GiB                                                 |
| Replit Pro  | [Replit Pro pricing](https://www.replit.com/pricing) 참조 |

이 allowance는 [Static](/ko/features/publishing/deployment-types#static), [Autoscale](/ko/features/publishing/deployment-types#autoscale), [Reserved VM](/ko/features/publishing/deployment-types#reserved-vm), [Scheduled](/ko/features/publishing/deployment-types#scheduled) deployment에 적용됩니다.

Outbound Data Transfer의 현재 가격은 [요금제 페이지](https://www.replit.com/pricing)에서 확인하세요.

***

<div id="2-compute-units">
  ## 2. Compute Units
</div>

Autoscale Deployments는 시간에 따른 CPU 및 RAM 사용량을 함께 반영하는 Compute Units를 기준으로 요금이 청구됩니다.

초과 사용분도 Compute Units를 기준으로 청구되며, 청구는 개별 compute unit 단위까지 세분화되어 이루어집니다. compute units의 현재 가격은 [요금제 페이지](https://www.replit.com/pricing)에서 확인하세요.

Autoscale Deployment의 RAM 및 CPU 초가 Compute Units로 환산되는 방식은 다음과 같습니다.

| 리소스    | Compute Units |
| ------ | ------------- |
| RAM 1초 | 2 Units       |
| CPU 1초 | 18 Units      |

Static Deployments는 Compute Units를 소비하지 않으며, [지정된 용량](#)을 초과하는 Outbound Data Transfers에 대해서만 요금이 청구됩니다.

[Autoscale Deployments 자세히 알아보기](/ko/features/publishing/deployment-types#autoscale).

***

<div id="3-requests">
  ## 3. 요청
</div>

Autoscale Deployments는 처리한 요청 수도 함께 고려합니다.

현재 요청 가격은 [요금제 페이지](https://www.replit.com/pricing)에서 확인하세요.

<div id="databases">
  # 데이터베이스
</div>

Replit은 [production 데이터베이스](/ko/features/data-and-storage/development-and-production) 사용량에 대해서만 요금을 부과합니다. development 데이터베이스는 항상 무료이며 모든 Replit App에 기본 포함됩니다. development 데이터베이스에 대한 자세한 내용은 [Development Database](/ko/features/data-and-storage/sql-database)를 참조하세요.

Replit PostgreSQL은 완전 관리형 서버리스 서비스로, 고가용성을 손쉽게 제공하며 별도의 유지 관리가 필요 없습니다. production 데이터베이스의 billing은 실제 사용량을 기준으로 하므로 비용을 크게 절감할 수 있습니다.

Production PostgreSQL 데이터베이스는 다음 두 가지 usage 지표를 기준으로 청구됩니다.

* **[컴퓨팅 시간](#compute-time)**: 시간당 소비되는 컴퓨팅 리소스의 양입니다.
* **[데이터 저장 공간](#data-storage)**: 저장된 데이터(과거 데이터 포함)의 총 volume입니다.

**Settings** → **Account** → **Account usage**에서 production 데이터베이스 usage를 포함한 현재 resource usage를 확인할 수 있습니다.

<div id="compute-time">
  ## 컴퓨팅 시간
</div>

컴퓨팅 시간은 해당 billing period 동안 데이터베이스가 활성 상태로 유지된 시간에 따라 결정됩니다. 데이터베이스는 요청을 받는 동안과 마지막 요청 이후 5분간 활성 상태로 간주됩니다. 데이터베이스가 5분 동안 유휴 상태로 유지되면 일시 중단되어 비활성 상태로 전환됩니다.

<div id="data-storage">
  ## 데이터 저장 공간
</div>

데이터 저장 공간은 계정 내 모든 데이터베이스에 저장된 데이터의 총량이며, 기비바이트(GiB) 단위로 측정됩니다. 저장 공간은 월별 최대 사용량을 기준으로 계산됩니다. PostgreSQL 데이터베이스는 데이터가 전혀 없더라도 각각 33MB의 저장 공간을 사용합니다. 이는 Postgres 서버의 기본 저장 공간 사용량입니다.

<Note>production 데이터베이스의 총 저장 공간 한도는 데이터베이스당 10기비바이트(GiB)입니다. development 데이터베이스는 Replit App당 20GiB의 무료 저장 공간을 제공합니다.</Note>
