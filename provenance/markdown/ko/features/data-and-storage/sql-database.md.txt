# 데이터베이스

> Replit의 완전관리형 SQL 데이터베이스를 사용해 앱에 영구 데이터 저장 기능을 추가하는 방법을 알아보세요.

export const YouTubeEmbed = ({videoId, title = "YouTube video", startAt}) => {
  if (!videoId) {
    return null;
  }
  let url = "https://www.youtube.com/embed/" + videoId;
  if (startAt) {
    url = url + "?start=" + startAt;
  }
  return <Frame>
      <iframe src={url} title={title} allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" allowFullScreen></iframe>
    </Frame>;
};

Replit 데이터베이스는 완전관리형 SQL 데이터베이스를 사용하여 Project Editor에서 바로 Replit App에 영구 데이터 저장소를 추가할 수 있게 해줍니다.

<Note>
  가장 빠르게 시작하는 방법은 **Agent**에게 앱에 데이터베이스를 추가해 달라고 요청하는 것입니다. Agent가 통합을 설정하고, 데이터베이스 스키마를 생성하고, 데이터를 저장 및 조회하도록 앱을 업데이트합니다.
</Note>

## 기능

Replit 데이터베이스 도구는 다음 기능을 제공합니다.

* **데이터베이스 도구**: 내장 SQL 도구로 쿼리를 실행하고, 데이터베이스 스키마를 관리하고, 데이터를 시각화합니다
* **타임 트래블**: 데이터베이스를 어느 **Agent** 체크포인트로든 복원할 수 있습니다. 자세한 내용은 [데이터 복구](/ko/features/data-and-storage/data-recovery)를 참고하세요
* **무료 저장 공간**: 모든 Replit App에 20GB의 무료 저장 공간이 포함됩니다.
* **환경 변수**: Replit App에서 환경 변수를 사용해 데이터베이스에 안전하게 접근합니다

<Info>
  2025년 12월 4일 이전에는 개발 데이터베이스가 Neon에서 호스팅되었으며 몇 가지 중요한 차이점이 있습니다.
  자세한 내용은 [개발 및 프로덕션](/ko/features/data-and-storage/development-and-production#legacy-development-database)을 참고하세요.
</Info>

## 사용법

<YouTubeEmbed videoId="zbyRuoPNIc8" title="Replit에서 데이터베이스를 사용하는 방법" />

Project Editor에서 바로 Replit 데이터베이스 도구에 접근할 수 있습니다.
다음 섹션에서는 데이터베이스를 설정하고 관리하는 방법을 안내합니다.

<Accordion title="데이터베이스 도구에 접근하는 방법">
  1. **Tools** 패널을 열고 **Replit Cloud** 아래에서 **Database**를 선택하세요.
  2. 랜딩 화면에는 데이터베이스 목록이 표시됩니다. **Development Database**와 같은 데이터베이스를 선택해 엽니다.
</Accordion>

Database 도구는 데이터베이스 목록을 중심으로 구성되어 있습니다. 랜딩 화면에는 각 데이터베이스의 저장 공간 사용량과 함께 현재 **Billing Period**와 **Hours of Compute Used**가 표시됩니다. 데이터베이스를 열면 세 가지 탭을 사용할 수 있습니다.

* **Overview**: 데이터베이스의 테이블
* **My Data**: 행을 탐색하고 편집하거나 SQL 쿼리를 실행합니다
* **Settings**: 연결 문자열, 저장 공간 사용량, 연결 세부 정보

### 데이터베이스 추가

모든 Replit App에는 기본적으로 데이터베이스가 함께 제공됩니다. Project Editor에서 <img class="icon-svg" src="https://mintcdn.com/replit/rJldsgYVucXB_6kW/images/icons/postgres.svg?fit=max&auto=format&n=rJldsgYVucXB_6kW&q=85&s=68fc78519888560040eb7096f68e76df" alt="PostgresSQL 데이터베이스 아이콘" width="24" height="24" data-path="images/icons/postgres.svg" /> **데이터베이스** 도구를 선택하면 접근할 수 있습니다.

**Agent**에게 Replit App에 PostgreSQL 데이터베이스를 추가해 달라고 요청하고 앱이 어떤 데이터를 저장해야 하는지에 대한
세부 정보를 알려주면 데이터베이스를 앱에 통합할 수 있습니다. Agent가 데이터베이스 스키마를 생성하고
앱이 데이터베이스와 통신하도록 업데이트합니다.

### 보안 기능

**Agent**를 사용해 데이터베이스 통합을 추가하면, 내장 보안 기능을 갖춘 ORM(Object-Relational Mapper)이 추가되어
모든 데이터베이스 통신을 처리합니다.

이 ORM 계층은 Agent의 보안 모범 사례 구현과 결합되어 다음 기능을 통해 앱을 각종 공격으로부터 보호합니다.

* **스키마 검증**: 데이터가 예상된 형식을 따르는지 확인합니다
* **데이터 정제(Sanitization)**: SQL 인젝션 공격을 방지하기 위해 빌더 입력을 자동으로 정리합니다

## 다음 단계

2025년 12월 4일 이전에는 개발 데이터베이스가 <a href="https://neon.com/" target="_blank">Neon</a>에서 호스팅되었습니다.
이 데이터베이스는 이제 지원 종료(deprecated)되었으며, 모든 새로운 개발 데이터베이스는 Replit 자체 데이터베이스 인프라에서 호스팅됩니다.

`DATABASE_URL` [환경 변수](#view-connection-credentials-and-usage)를 확인해 개발 데이터베이스가 Neon에서 호스팅되고 있는지 확인할 수 있습니다.

<Info>
  `DATABASE_URL`에 `neon.tech/neondb`가 포함되어 있다면 개발 데이터베이스가 아직 Neon에서 호스팅되고 있는 것입니다.
  반대로 `helium/heliumdb`가 포함되어 있다면 개발 데이터베이스가 이제 Replit에서 호스팅되고 있는 것입니다.
</Info>

다음은 레거시 Neon 개발 데이터베이스와 새로운 Replit 개발 데이터베이스 간의 주요 차이점입니다.

| **기능**        | **Replit(현재)**                                                                                             | **Neon(레거시)**                                                                                |
| ------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **호스팅**       | Replit 자체 인프라에서 호스팅                                                                                        | Neon(타사 제공업체)에서 호스팅                                                                          |
| **결제**        | 모든 Replit App에 무료로 포함                                                                                      | 사용량 기반 결제. 자세한 내용은 [게시 및 데이터베이스 결제](/ko/billing/about-usage-based-billing#databases)를 참고하세요. |
| **복원 기능**     | [롤백 기능](/ko/features/version-control/checkpoints-and-rollbacks/)을 사용해 데이터베이스를 어느 체크포인트로든 복원                | 특정 시점 복원(PITR)—백업 보존 기간 내 어느 시점으로든 복구.                                                       |
| **연결 보안**     | 앱 내부에서만 접근 가능하며, 외부에 절대 노출되지 않음.                                                                           | 전체 연결 문자열을 사용—노출되면 누구든 데이터베이스에 접근하고 수정할 수 있음.                                                |
| **리믹스 동작**    | [리믹스](/ko/features/projects-and-artifacts/remix-an-app)는 격리와 보안을 위해 데이터가 복사된 새 개발 데이터베이스를 생성               | 리믹스가 모든 복제본에서 동일한 데이터베이스를 재사용하므로, 리믹스에서의 변경 사항이 원본 앱에 영향을 줄 수 있음.                            |
| **데이터베이스 생성** | 각 Replit App마다 자동으로 생성됨.                                                                                   | 명시적인 설정이 필요함.                                                                                |
| **게시 워크플로**   | 배포 또는 게시를 하려면 환경 간 격리를 위해 [프로덕션 데이터베이스](/ko/features/data-and-storage/development-and-production)를 생성해야 함. | 개발과 프로덕션이 동일한 데이터베이스를 공유하여, 의도치 않은 개발 변경 사항이 프로덕션 앱에 영향을 줄 수 있었음.                            |

<Warning>
  앱이 레거시 Neon 데이터베이스를 사용하는 동안 포크되거나 리믹스되었다면, 게시된 앱이 여전히 원본 앱의 데이터베이스 URL을 참조할 수 있습니다. [데이터베이스 업그레이드](/ko/features/data-and-storage/development-and-production) 이후에는 이 공유 연결이 더 이상 작동하지 않게 됩니다. 게시된 앱을 업데이트하는 방법은 [공유 데이터베이스를 사용하는 게시된 앱 수정하기](/ko/features/data-and-storage/shared-database-migration)를 참고하세요.
</Warning>
