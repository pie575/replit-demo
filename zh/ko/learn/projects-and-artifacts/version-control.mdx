借助 Replit 的版本控制功能，您可以放心地跟踪和管理代码库，并与他人协作。通过内置 Git 集成和 GitHub 连接，您可以：

* 跟踪代码变更并保留开发历史
* 与团队成员协作，避免代码冲突或工作丢失
* 在 Replit 和 GitHub 之间导入、修改和推送代码
* 使用分支安全地试验新功能

<div id="section">
  ## 什么是版本控制？
</div>

版本控制是一种记录文件随时间推移发生的变更的系统，可让您日后恢复到特定版本。在 Replit 中，版本控制由 Git 驱动。Git 是用于跟踪代码变更的行业标准工具，并提供直观的可视化界面，无需掌握命令行知识即可使用。

<div id="replit">
  ### Replit 中的版本控制如何运作
</div>

四种版本控制方式都基于同一个 Git 仓库：

1. **Agent 检查点**会在你使用 [Replit Agent](/zh/ko/features/agent/overview)构建应用时，于重要里程碑自动创建提交。[详细了解检查点和回滚](/zh/ko/features/version-control/checkpoints-and-rollbacks)。
2. **Git 面板**提供完整 Git 仓库的可视化操作界面。
3. **Git CLI**提供对全部 Git 功能的命令行访问。
4. **文件历史记录**跟踪单个文件中的细粒度更改。

根据自己的需求选择合适的界面，所有内容均由 Git 强大的版本控制系统提供支持。

| 功能            | Agent 检查点      | Git 提交         | 文件历史记录        |
| ------------- | -------------- | -------------- | ------------- |
| **创建方式**      | 在适当时机自动创建      | 手动或定时创建        | 自动            |
| **粒度**        | 功能级更改          | 任意规模的更改        | 字符级更改         |
| **说明**        | AI 生成的摘要       | 用户撰写的消息        | 自动时间戳         |
| **回滚**        | 一键恢复           | 需要 Git 知识      | 一键恢复          |
| **Git 功能**    | 完整 Git 功能      | 完整 Git 功能      | 不支持 Git 功能    |
| **GitHub 同步** | 完整 GitHub 同步功能 | 完整 GitHub 同步功能 | 不支持 GitHub 同步 |

<div id="section-2">
  ## 开始使用
</div>

在 Replit 应用中，将 Git 工具添加到 Project Editor，即可使用版本控制功能：

1. 前往 Replit 应用的 Tools 部分。
2. 选择 **+** 图标以添加新工具。
3. 在可用工具列表中选择 **Git**。

如需从 GitHub 导入现有项目，请参阅[从 GitHub 导入](/zh/ko/build/import-from-providers)。

<div id="section-4">
  ### 自动版本管理
</div>

<Accordion title="Agent 检查点">
  使用 [Replit Agent](/zh/ko/features/agent/overview) 进行 AI 辅助开发时自动创建的快照。

  **最适用场景**：使用 Replit Agent 开发

  **主要功能**：

  * 在逻辑里程碑自动创建
  * 一键回滚
  * 功能级快照
  * 跟踪进度
  * 无需配置
  * 开发进度的可视化时间线

  Agent 检查点存储在 Git 中，可通过 Git 面板或 Git CLI 访问。你还可以使用历史记录功能查看所有检查点，并可：

  * 按时间顺序查看检查点
  * 查看详细的检查点说明
  * 直接访问检查点状态
  * 一键回滚到任意检查点
</Accordion>

<Accordion title="文件历史记录">
  针对直接在编辑器中进行的非 Agent 更改，按文件自动保存并跟踪版本。

  **最适用场景**：快速恢复最近的文件更改

  **主要功能**：

  * 聚焦单个文件
  * 字符级更改
  * 可视化对比
  * 保留 30 天历史记录
  * 回放功能

  文件历史记录提供独立的界面，但底层更改属于 Git 历史记录的一部分。详细了解[文件历史记录](/zh/ko/features/version-control/file-history)。
</Accordion>

  ### 基于 Git 的界面

<Accordion title="Git 面板">
  用于 Git 操作的可视化界面，无需命令行知识即可进行版本控制。

  **最适合**：需要 GitHub 集成和可视化工作流程的大多数项目

  **主要功能**：

  * 跟踪整个仓库
  * 分支管理
  * 可视化查看 diff
  * 一键同步 GitHub
  * 团队协作

  有关使用 Git 面板的详细说明，请参阅 [使用 Git 面板](/zh/ko/features/workspace-tools/git-interface)。

<Accordion title="Git CLI">
  通过 [Shell](/zh/ko/features/workspace-tools/shell) 提供完整的 Git 命令行访问，满足高级操作需求。

  **最适合**：需要完整 Git 功能的高级用户

  **主要功能**：

  * 完整的 Git 命令集
  * 高级分支策略
  * 自定义工作流程
  * 脚本自动化
  * 对仓库的完全控制

  有关常用 Git 命令及其用法，请参阅 [使用 Git 面板](/zh/ko/features/workspace-tools/git-interface#using-git-commands-in-shell)。

<div id="section-5">
  ## 主要功能
</div>

* **可视化 Git 界面**：无需输入 Git 命令，即可管理仓库、提交和分支
* **GitHub 集成**：连接 GitHub 仓库，方便备份和协作
* **从 GitHub 导入**：只需点击几下，即可[将 GitHub 仓库转换为 Replit 应用](/zh/ko/build/import-from-providers)
* **分支管理**：直接在 Project Editor 中创建、切换和合并分支
* **冲突解决**：借助可视化指引识别并解决合并冲突

<div id="section-6">
  ## 使用场景
</div>

**跟踪个人项目**

在开发过程中跟踪代码更改，以便在需要时还原到历史版本。[Git 面板](/zh/ko/features/workspace-tools/git-interface)会直观地显示更改，让你轻松提交有意义的更新。

**团队协作**

多位开发者可以在同一代码库中协作，而不会覆盖彼此的更改。为新功能创建分支，并在准备就绪后进行合并。详细了解如何[邀请团队成员](/zh/ko/build/invite-teammates)。

<div id="agent">
  ## Agent 检查点
</div>

使用 [Replit Agent](/zh/ko/features/agent/overview)构建应用时，你可以利用检查点获得额外的版本管理保障。检查点会在 AI 辅助开发过程中的关键时刻自动捕获项目的完整状态，包括项目内容、AI 上下文和已连接的数据库。

<div id="section-7">
  ### 检查点的工作原理
</div>

Agent 检查点是整个 Replit 应用状态的完整快照：

* **自动创建**：Agent 会在开发过程中的适当时机创建检查点。
* **完整状态捕获**：每个检查点都会保留项目内容、AI 记忆和数据库状态。
* **实施计划**：在进行更改前，Agent 会先提供计划供你审核。
* **复杂任务跟踪**：对于较大型的任务，可能会创建多个检查点。

<div id="ai">
  ### AI 辅助开发的优势
</div>

使用 AI 构建时，Agent 检查点具有独特优势：

* **安全保障**：放心尝试，因为你可以轻松将整个开发环境恢复到之前的状态。
* **进度跟踪**：准确了解 Agent 如何逐步构建应用。
* **逻辑里程碑**：检查点代表完整的功能，而非任意保存点。
* **即时回滚**：只需单击一次，即可回到任意先前状态，包括恢复数据库和 AI 上下文。

<Info>
  有关检查点捕获的内容和全面回滚功能的详细信息，请参阅[检查点和回滚](/zh/ko/features/version-control/checkpoints-and-rollbacks)。
</Info>

<Tip>
  Agent 检查点非常适合 AI 辅助开发，但对于长期版本跟踪和协作，尤其是在使用外部存储库时，建议使用 Git 提交。
</Tip>
