---
title: "Jetons d'accès externes"
description: "Permettez aux pipelines CI, aux webhooks et aux autres services automatisés d'accéder aux Replit Apps privées sans connexion."
---

Un jeton d&#39;accès externe est un jeton porteur que vous émettez pour une Replit App donnée.
Il permet aux services automatisés — pipelines CI, webhooks, sondes de vérification d&#39;état,
bots Slack, scripts internes — d&#39;accéder à votre app, même lorsque celle-ci est protégée par
une [URL de développement privée](/fr/ko/features/publishing/private-deployments) ou un
[déploiement privé](/fr/ko/features/publishing/private-deployments).

Traitez chaque jeton comme un mot de passe : toute personne qui le détient peut accéder
à votre app jusqu&#39;à son expiration ou sa révocation.

<Note>
  Les jetons d&#39;accès externes sont disponibles dès que vous choisissez l&#39;accès privé pour un deployment.
  Aucune activation au niveau de l&#39;espace de travail n&#39;est nécessaire. Dans les espaces de travail Enterprise,
  seuls les administrateurs de l&#39;espace de travail peuvent gérer les jetons.
</Note>

<div id="section">
  ## Quand utiliser des jetons
</div>

Utilisez des jetons d’accès externe lorsqu’un service *extérieur* au navigateur doit appeler une App Replit privée. Voici quelques cas courants :

* Un workflow GitHub Actions qui exécute des tests de fumée sur une URL de développement à chaque commit.
* Un outil de surveillance de disponibilité (Better Stack,
  Pingdom, UptimeRobot) qui appelle le point de terminaison de vérification de l’état d’une app publiée.
* Un récepteur de webhook qui envoie des requêtes POST vers un déploiement privé : Stripe, Slack, GitHub.
* Des appels `curl` ou `fetch` exécutés depuis l’ordinateur d’un membre de l’équipe pendant le débogage.

Les jetons d’accès externe sont conçus pour le **trafic API**, et non pour ouvrir des pages d’interface utilisateur dans un navigateur. Les applications monopages (Vite, Next.js, etc.) chargent des bundles JavaScript lors de requêtes
ultérieures, mais ces requêtes n’incluent pas le jeton et échouent.
Pour naviguer de manière interactive, connectez-vous normalement.

<div id="section-2">
  ## Environnement du jeton
</div>

Chaque jeton est lié à un seul environnement.

| Environnement | Portée d&#39;exécution                                                     | Utilisation                                                              |
| :------------ | :------------------------------------------------------------------------- | :----------------------------------------------------------------------- |
| `Development` | URL de développement de l&#39;App dans l&#39;espace de travail (`*.replit.dev`)       | Pour accéder à un Repl en cours d&#39;exécution pendant le développement |
| `Production`  | Déploiement publié de l&#39;App (`*.replit.app` et domaines personnalisés) | Pour accéder à un déploiement privé depuis un service externe            |

Les jetons `Production` restent valides après une republication, y compris lorsque vous publiez une nouvelle version.
Replit révoque les jetons dans les cas suivants :

* Vous dépubliez le déploiement.
* Vous supprimez le déploiement.
* Vous faites passer l&#39;accès à l&#39;App de privé à public.

Un jeton cesse également de fonctionner s&#39;il expire ou si vous le révoquez vous-même.

<div id="section-3">
  ## Créer un jeton d&#39;accès externe
</div>

<Steps>
  <Step>
    Ouvrez l&#39;application que vous souhaitez exposer, puis ouvrez l&#39;outil **Publier**.
  </Step>

  <Step>
    Sélectionnez **Ajuster les paramètres** pour afficher les options de redéploiement.
  </Step>

  <Step>
    Dans la section **Sécurité**, recherchez **Jeton d&#39;accès externe**.
  </Step>

  <Step>
    Sélectionnez **Créer un jeton d&#39;accès**, puis renseignez les informations suivantes.

    * **Libellé** (facultatif) : un nom court, tel que `CI` ou
      `Stripe webhook`, qui vous permettra d&#39;identifier le jeton ultérieurement. Vous pouvez saisir
      jusqu&#39;à 120 caractères.
    * **Environnement** : sélectionnez `Development`
      ou `Production` selon l&#39;environnement dans lequel le service appelant doit accéder à l&#39;application.
    * **Expiration** : choisissez une durée de validité parmi `1 heure`, `24 heures`, `7 jours`, `30 jours`, `3 mois`, `1 an`
      et `5 ans`. Choisissez la durée la plus courte adaptée à votre tâche.
      L&#39;option « Sans expiration » n&#39;est pas proposée.
  </Step>

  <Step>
    Sélectionnez **Créer**.
  </Step>
</Steps>

Replit n&#39;affiche le jeton **qu&#39;une seule fois**. Copiez-le maintenant. Une fois la boîte de dialogue fermée,
vous ne pourrez plus l&#39;afficher. Si vous perdez le jeton, révoquez-le
et créez-en un nouveau.

L&#39;écran d&#39;affichage du jeton propose deux options de copie.

* **Copier le paramètre de requête** - copie
  `?project-protection-bypass=<token>`, que vous pouvez ajouter à une URL. Cette option est utile pour effectuer une vérification rapide avec `curl`.
* **Copier uniquement le jeton** - copie le jeton brut
  à envoyer dans l&#39;en-tête `Authorization: Bearer`.

<Info>
  Lorsque vous créez votre premier jeton, l&#39;accès externe de l&#39;application est
  automatiquement activé s&#39;il ne l&#39;était pas déjà. Sans mécanisme de protection, le jeton n&#39;a rien à contourner.
</Info>

<div id="section-4">
  ## Utiliser les jetons
</div>

Présentez le jeton de l&#39;une des deux manières suivantes.

<div id="authorization">
  ### En-tête Authorization (recommandé)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

Cette méthode convient à la quasi-totalité des cas : webhooks, scripts CI, appels entre services backend, etc. Le jeton n&#39;apparaît pas dans les journaux qui enregistrent les URL et ne subsiste pas non plus dans l&#39;historique du navigateur.

<div id="section-5">
  ### Paramètres de requête
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

N&#39;utilisez la méthode des paramètres de requête que si vous ne pouvez pas définir d&#39;en-têtes — par exemple, dans le cas d&#39;un service qui n&#39;accepte qu&#39;une URL. Les URL contenant un jeton se retrouvent facilement dans les journaux de proxy, l&#39;historique du shell ou les captures d&#39;écran : privilégiez donc toujours la méthode par en-tête lorsque c&#39;est possible.

<div id="section-6">
  ## Gérer les jetons existants
</div>

La section **Jetons d&#39;accès externes** répertorie tous les jetons que vous avez créés pour votre application, du plus récent au plus ancien, avec leur libellé, leur environnement, leur date de création, leur date d&#39;expiration et leur statut de révocation.
La valeur complète d&#39;un jeton ne s&#39;affiche qu&#39;au moment de sa création : chaque ligne en indique donc les derniers caractères, afin que vous puissiez le distinguer des autres.

Vous ne voyez que les jetons que *vous* avez créés. Même si vous êtes propriétaire de l&#39;application, les jetons des autres collaborateurs ne sont visibles que par eux.

<div id="section-7">
  ## Révoquer un jeton
</div>

Révoquez un jeton dès qu&#39;il n&#39;est plus nécessaire ou que vous soupçonnez une fuite. Pour cela,
suivez les étapes ci-dessous.

<Steps>
  <Step>
    Dans les paramètres de publication de votre application, ouvrez la section **Jetons d&#39;accès externes**.
  </Step>

  <Step>
    Repérez le jeton dans la liste et sélectionnez l&#39;icône de corbeille.
  </Step>

  <Step>
    Confirmez la révocation.
  </Step>
</Steps>

La révocation est **immédiate et irréversible**. Le trafic utilisant ce jeton
est refusé en l&#39;espace de quelques secondes. Si vous avez de nouveau besoin d&#39;un accès, émettez un nouveau
jeton.

Vous ne pouvez révoquer que les jetons que vous avez créés. Lorsqu&#39;un collaborateur est retiré de
l&#39;espace de travail, les jetons qu&#39;il a émis pour cette application sont également révoqués automatiquement.

<div id="section-8">
  ## Conserver les jetons en toute sécurité
</div>

Les jetons d&#39;accès externes sont des identifiants de connexion. Traitez-les avec
la même vigilance qu&#39;une clé API ou un mot de passe.

<div id="section-9">
  ### À faire
</div>

* **Stockez les jetons dans un gestionnaire de secrets** - secrets GitHub Actions, coffre-fort de votre
  fournisseur CI, magasin de secrets de votre fournisseur cloud ou gestionnaire de mots de
  passe. Ne les committez jamais dans un dépôt.
* Utilisez **des durées de validité courtes** lorsque possible. Un jeton de 7 jours pour une
  intégration ponctuelle est plus sûr qu’un jeton de 5 ans laissé à l’abandon.
* **Attribuez un libellé à tous les jetons.** Vous pourrez ainsi savoir plus tard à quoi ils servent
  et s’ils sont toujours utilisés. Les jetons sans libellé sont les premiers à
  être compromis et les derniers à être révoqués.
* **Émettez des jetons distincts pour chaque utilisation.** Créez-en un pour chaque tâche CI,
  chaque source de webhook et chaque vérification de disponibilité. Si quelque chose est compromis ou
  si un fournisseur n’est plus nécessaire, vous n’aurez qu’à révoquer ce seul jeton.
* Préférez l’en-tête **`Authorization`** aux paramètres de requête afin que les jetons ne
  soient pas exposés dans les journaux d’URL, l’historique du navigateur ou les en-têtes Referer.
* **Révoquez-les immédiatement** si un jeton a pu être exposé, par exemple dans des journaux divulgués,
  des commits dans des dépôts publics, des partages d’écran ou l’ordinateur portable d’un ancien employé. La révocation prend effet
  immédiatement ; émettez ensuite un jeton de remplacement.

<div id="section-10">
  ### À éviter
</div>

* **Ne partagez pas un jeton entre plusieurs membres de l&#39;équipe ou plusieurs services.** Si deux systèmes utilisent le même
  jeton, vous ne pourrez pas en révoquer un sans interrompre l&#39;autre.
* **Ne collez pas de jeton dans une messagerie, un e-mail, une capture d&#39;écran ou un outil de suivi des tickets.** Ces
  canaux sont archivés, indexés et partagés de façon imprévisible.
* **Ne placez pas de jeton dans du code côté client** : applications web, applications mobiles,
  binaires de bureau, etc. Tout ce qui est distribué sur l&#39;appareil d&#39;un utilisateur doit être
  considéré comme public.
* **N&#39;utilisez pas de jeton pour les sessions de navigateur.** Les jetons fonctionnent pour les appels
  API, mais ne permettent pas de charger une SPA dans un onglet de navigateur.
  Dans ce cas, utilisez la connexion Replit habituelle.
* **Ne retenez pas l&#39;expiration de cinq ans par défaut.** Définissez une durée de validité qui corresponde à la période
  pendant laquelle le consommateur a réellement besoin d&#39;un accès.

<div id="section-11">
  ## Résolution des problèmes
</div>

<Accordion title="Mon jeton de production a soudainement cessé de fonctionner">
  Les jetons de production restent valides lors des republications habituelles.
  Vérifiez si le jeton a expiré ou a été révoqué. Vérifiez également si vous avez
  annulé la publication ou supprimé le déploiement, ou si vous avez fait passer
  l&#39;application de privée à publique. Si l&#39;application n&#39;a plus de déploiement
  privé, publiez-la à nouveau en privé. Créez ensuite un nouveau jeton. Les
  jetons expirés ou révoqués ne peuvent pas être restaurés.
</Accordion>

<Accordion title="Le jeton fonctionne avec `curl`, mais le navigateur affiche toujours la page de connexion">
  Les jetons d&#39;accès externes sont destinés au trafic API, et non aux sessions de
  navigateur. Lorsqu&#39;une application monopage se charge dans le navigateur, la
  requête HTML initiale peut transmettre le jeton via des paramètres de requête,
  mais les requêtes suivantes pour le bundle JavaScript, le CSS et les appels API
  n&#39;incluent pas le jeton et sont donc refusées. Pour utiliser l&#39;application de
  manière interactive, connectez-vous normalement à Replit.
</Accordion>

<Accordion title="J'ai perdu mon jeton : puis-je le revoir ?">
  Non. Replit n&#39;affiche le jeton qu&#39;une seule fois, lors de sa création. La vue
  de liste affiche les métadonnées (libellé, environnement, date d&#39;expiration,
  derniers caractères), mais pas la valeur complète du jeton. Si vous avez perdu
  votre jeton, révoquez-le et créez-en un nouveau.
</Accordion>
