---
title: "端口"
description: "了解如何在您的 Replit App 中配置和管理网络端口。"
---

由于 Replit 在云环境中运行您的项目，端口在 Replit 中的工作方式与本地计算机有所不同。 (如果您想先了解 TCP 端口的基本概念，[请从这里开始](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/)。) 

在计算机上，端口管理只有一个层级：程序会指定要监听的端口，当来自互联网的流量到达计算机的该端口时，便会被路由到相应的进程。

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="计算机" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` 是地址或主机名部分。如果某个进程正在监听 `0.0.0.0`，意味着它会监听所有网络接口——也就是说，如果另一台计算机通过互联网向您计算机的 IP 地址发送请求，该进程就能收到请求。因此，监听 `0.0.0.0` 意味着这些进程可通过公共互联网访问 (前提是您的计算机已联网) 。

出于隐私和安全考虑，大多数编程框架在开发期间*不会*监听 `0.0.0.0`，因为您未必希望在开发过程中将内容公开。相反，它们会监听另一个地址——`127.0.0.1`，也称为 `localhost`。这意味着只有该计算机能够向该端口发出请求。

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="localhost 端口仅对托管它们的计算机可见。" width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

在 Replit 中，要让正在运行的进程能通过 webview 或外部请求访问，必须为其定义一个**外部端口**。这是因为进程通常使用的“内部端口”仅在 Replit 提供的隔离云环境内可见。内部端口必须连接到可从外部访问的端口，才能将流量正确地转发到您的程序。即使进程监听的是通常可公开访问的地址，例如 `0.0.0.0`，仍需将其绑定到外部端口。

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="外部端口将流量转发到程序正在监听的内部端口。" width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit 通过将外部端口绑定到特定的内部端口来实现这一点——例如，在上图中，外部端口 `:80` 绑定到内部端口 `:3000`。这意味着 Replit App 在端口 80 上接收的所有流量都会被转发到内部端口 3000。

此配置记录在 `.replit` 配置文件的 [[ports]] 部分。

默认情况下，Replit 会将第一个打开的端口绑定到默认外部端口 80，使该进程可通过不带端口号的域名访问 (例如，customdomain.com/ 而不是 customdomain.com:3000/) 。之后打开的其他内部端口会绑定到其他可用的外部端口 (请参阅下方完整列表) 。

<div id="porta-padro">
  ## 默认端口
</div>

端口 :80 是 HTTP 流量的“默认端口”，因此发送到根域名的 HTTP 流量会自动路由到端口 80。正因如此，端口 80 不会显示在 URL 中。除 `:80` 外的端口会显示在域名中 (例如 customdomain.com:4200/) 。 (Replit 默认提供 TLS，因此技术上实际使用的是端口 443，即 HTTPS 的默认端口。实际上，您可以将两者视为等同。)

<div id="publicao">
  ## 部署
</div>

Autoscale 和 Reserved VM 部署仅支持暴露一个外部端口，且对应的内部端口不得使用 `localhost`。如果暴露多个端口，或仅在 localhost 上暴露一个端口，已部署应用将无法运行。为确保 Autoscale 部署按预期运行，可从配置中移除所有端口的 `externalPort` 条目，*仅保留*要通过互联网访问的服务端口。

<div id="depurao">
  ## 调试
</div>

某项功能未能按预期运行，一个常见原因是：虽然端口配置看似正确，但程序实际使用的是其他端口。例如，如果你的配置如下：

```
[[ports]]
internalPort = 3000
externalPort = 80
```

因此，发往 80 端口的互联网流量会被转发到内部端口 3000。但是，如果你的程序实际并未监听 3000 端口，而是监听其他端口 (如 8080) ，就会看起来像没有任何流量到达。如果你在代码中修改了端口，却没有在配置中修改对应的端口，或者将配置从一个项目复制粘贴到另一个项目，就可能出现这种情况。

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="程序可能会更改其监听端口。" width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

不同框架监听的默认端口各不相同——例如，Flask 使用 5000，React 使用 3000，Laravel 使用 8000。请确保配置了正确的端口！

<div id="preferncias">
  ## 偏好设置
</div>

打开端口时，Replit 会自动将 Replit App 中开放的端口映射到可用的外部端口，并将此映射记录在 .replit 配置文件中。

不过，对于在 localhost 上开放的内部端口，默认不会这样做，因为通常运行在 localhost 上的服务一般假定只有运行该进程的同一台计算机能够访问 (localhost 端口仅对运行该进程的同一台计算机可见) 。这意味着，与假定可通过公共互联网访问的服务相比，这些服务通常不够安全。

你随时可以为要对外暴露的端口将配置选项 `exposeLocalhost` 设为 `true`，以覆盖此行为。

如果你希望默认*始终*对外暴露 localhost 端口，可以在用户设置工具中将“自动端口转发”配置设为“All ports”。

如果你希望*从不*为开放的端口创建配置，并手动控制所有 Replit App 的端口配置，可以将此选项设为“never”。

<div id="portas-suportadas">
  ## 支持的端口
</div>

首次打开端口时，Replit App 会将端口 80 设为默认的外部端口。Replit App 还可将 3000、3001、3002、3003、4200、5000、5173、6000、6800、8000、8008、8080、8081 作为额外的外部端口对外暴露。

端口 22 和 8283 供内部使用，无法转发。

<div id="configurao-ports-do-replit">
  ## .replit 的 `[[ports]]` 配置
</div>

类型：`{localPort, externalPort, exposeLocalhost}`

通过 `[[ports]]` 配置，您可以设置要为应用的 Web 输出对外暴露的 HTTP 端口。默认情况下，任何绑定到主机 0.0.0.0 的 HTTP 端口都会作为 Replit App 的 Web 输出对外暴露。

您可以在 .replit 文件中添加新的 [[ports]] 条目来提供额外端口，而不替换默认端口。必须同时指定 `localPort` 和 `externalPort` 条目。您可以按照下文所述，在 .replit 文件中添加多个 [[ports]] 条目，以添加多个额外端口。

<div id="localport">
  ### localPort
</div>

指定 Replit 要绑定到外部端口的本地端口。

<div id="externalport">
  ### externalPort
</div>

确定应将哪个端口公开为该本地端口可供公共访问的端口。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

如果你希望*永远不*对外暴露某个端口，可以保留 `localPort` 配置，而不添加 `externalPort`：

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

确定使用 `localhost` 的内部端口能否绑定到外部端口。可设为 `true`、`false` 或 null。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
