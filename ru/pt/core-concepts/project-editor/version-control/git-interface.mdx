Git Pane в Replit предоставляет визуальный интерфейс для операций Git, избавляя от необходимости использовать команды Git в командной строке. Эта функция делает контроль версий доступным для начинающих и при этом остаётся мощным инструментом для опытных разработчиков.

<div id="recursos">
  ## Возможности
</div>

Git Pane предоставляет все возможности контроля версий прямо в Project Editor благодаря удобному интерфейсу, упрощающему сложные операции Git.

* **Управление репозиториями**: Инициализируйте, подключайте репозитории Git и управляйте ими с интеграцией GitHub
* **Отслеживание коммитов**: Добавляйте изменения в индекс, создавайте коммиты и просматривайте изменения во всех файлах
* **Операции с ветками**: Создавайте ветки, переключайтесь между ними и выполняйте слияние в визуальном интерфейсе
* **Разрешение конфликтов**: Выявляйте и разрешайте конфликты слияния с помощью визуальных средств
* **Интеграция с Shell**: Синхронизация между командами Git, выполненными в Shell, и Git Pane

<div id="configurao-do-repositrio">
  ### Настройка репозитория
</div>

<Accordion title="Как открыть Git Pane">
  1. Перейдите в раздел Tools в Replit App
  2. Нажмите **+**, чтобы добавить новые инструменты
  3. Выберите **Git** в списке доступных инструментов
</Accordion>

Git Pane позволяет настроить и подключить репозиторий:

* **Инициализировать репозиторий**: Создайте новый Git-репозиторий для Replit App
* **Подключиться к GitHub**: Подключите репозиторий к GitHub для резервного копирования и совместной работы
* **Настроить удалённый репозиторий**: Настройте подключение к репозиторию GitHub и управляйте им

<div id="gerenciamento-de-alteraes">
  ### Управление изменениями
</div>

<Accordion title="Как просматривать изменения">
  1. Внесите изменения в любой файл вашего Replit App
  2. Откройте Git Pane в разделе Tools
  3. Просмотрите изменения в разделе **Review Changes**
</Accordion>

Git Pane предоставляет инструменты для управления изменениями в коде:

* **Просмотр изменений**: Просматривайте изменённые файлы с выделенными добавлениями и удалениями
* **Добавление файлов в индекс**: Выберите конкретные файлы, которые будут включены в следующий коммит
* **Создание коммита**: Сохраняйте изменения с информативными сообщениями
* **Отправка обновлений**: Отправляйте коммиты в GitHub одним щелчком

<div id="gerenciamento-de-branches">
  ### Управление ветками
</div>

<Accordion title="Как управлять ветками">
  1. Откройте Git Pane в разделе Tools
  2. Откройте выпадающее меню веток рядом с её названием
  3. Создайте новую ветку или выберите существующую
</Accordion>

Git Pane упрощает работу с несколькими версиями кода:

* **Создание веток**: Создавайте новые ветки для отдельной разработки функций
* **Переключение веток**: Переходите между разными версиями кода
* **Публикация веток**: Публикуйте свои ветки на GitHub
* **Получение изменений**: Синхронизируйтесь с удалёнными изменениями от соавторов

<div id="resoluo-de-conflitos-de-merge">
  ### Разрешение конфликтов при слиянии
</div>

<Accordion title="Как разрешить конфликты при слиянии">
  1. Попробуйте получить изменения при возникновении конфликтов
  2. Git Pane выделит файлы с конфликтами
  3. Откройте каждый конфликтующий файл, чтобы просмотреть и разрешить конфликты
  4. Сохраните файлы после разрешения конфликтов
  5. Завершите слияние, выбрав **Pull**
</Accordion>

Когда изменения кода из разных источников конфликтуют, Git Pane помогает:

* **Выявлять конфликты**: точно определять, в каких файлах есть конфликты
* **Просматривать различия**: сравнивать обе версии конфликтующего кода
* **Разрешать конфликты**: выбирать, какой код оставить, или вручную редактировать конфликтующие участки
* **Завершать слияния**: завершать процесс слияния после разрешения конфликтов

  <img src="/assets/mirror/11-merge-conflict-17b314f0e231.png" alt="Редактор кода с маркерами конфликтов слияния" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

После разрешения конфликта в файле удалите маркеры конфликта: удалите строки, начинающиеся с символов конфликта, и сохраните файл.

<div id="usando-comandos-git-no-shell">
  ### Использование команд Git в Shell
</div>

<Accordion title="Как открыть Shell">
  1. Выберите **All tools** на левой панели инструментов
  2. Выберите **Shell** из списка доступных инструментов
</Accordion>

<Tip>
  Хотя Git Pane предоставляет удобный интерфейс, опытные пользователи могут использовать стандартные команды Git в Shell для выполнения более сложных операций. Изменения, внесённые любым из этих способов, будут отображаться в обоих интерфейсах.
</Tip>

Если вы предпочитаете работать с Git через командную строку:

* **Синхронизация команд**: Любая команда Git, выполненная в Shell, автоматически синхронизируется с Git Pane
* **Полные возможности Git**: Используйте расширенные возможности Git, недоступные в Git Pane
* **Гибкое переключение**: При необходимости переключайтесь между командами в Shell и Git Pane

<Info>
  **Поддержка GitHub и GitLab CLI**: Помимо стандартных команд Git, в Shell можно использовать [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) и [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) для управления внешними Git-репозиториями и подключения к ним. Эти инструменты предлагают расширенные возможности для работы с репозиториями GitHub и GitLab, включая pull requests, issues и другие функции, характерные для этих платформ.
</Info>

<div id="operaes-de-repositrio">
  #### Операции с репозиторием
</div>

* **Клонировать репозиторий**: `git clone <url-do-repositório>`
* **Инициализировать репозиторий**: `git init`
* **Добавить удалённый репозиторий**: `git remote add origin <url-do-repositório>`

<div id="fazendo-alteraes">
  #### Внесение изменений
</div>

* **Проверить статус**: `git status` (показывает изменённые, добавленные и удалённые файлы)
* **Добавить файлы в индекс**: `git add <nome-do-arquivo>` или `git add .` (для всех файлов)
* **Создать коммит**: `git commit -m "sua mensagem de commit"`
* **Отправить изменения**: `git push origin <nome-da-branch>`
* **Получить изменения**: `git pull origin <nome-da-branch>`

<div id="autenticao">
  #### Аутентификация
</div>

При работе с приватными репозиториями необходимо пройти аутентификацию:

* Для репозиториев GitHub используйте персональный токен доступа вместо пароля
* Чтобы не вводить учётные данные повторно, сохраните их в Replit Secrets:
  1. Создайте новый secret с ключом `GIT_URL`
  2. Укажите значение `https://<имя-пользователя>:<токен>@github.com/<пользователь-или-организация>/<репозиторий>`
  3. Используйте `git push $GIT_URL` для отправки без ввода учётных данных

<Note>
  При использовании secrets с учётными данными любой, у кого есть доступ к вашему Replit App, потенциально может получить доступ к вашим учётным данным Git. Для конфиденциальных репозиториев рекомендуется каждый раз вводить учётные данные вручную.
</Note>
