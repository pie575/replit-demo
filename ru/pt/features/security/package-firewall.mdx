Брандмауэр пакетов блокирует вредоносные и скомпрометированные пакеты на сетевом уровне ещё до их установки в приложение. Он входит в [Replit Auto-Protect](/ru/pt/features/security/concepts#auto-protect) — набор средств защиты, включённых по умолчанию для всех пользователей, — и работает на базе [Socket](https://socket.dev), компании, специализирующейся на безопасности цепочек поставок ПО.

Когда вы или Agent выполняете команду установки, например `npm install` или `pip install`, запрос сначала проходит через брандмауэр пакетов. Безопасные пакеты устанавливаются как обычно, и вы не заметите никаких изменений. Пакеты, помеченные Socket как вредоносные или скомпрометированные, блокируются до того, как их код попадёт в вашу среду.

Брандмауэр пакетов **включён по умолчанию для всех пользователей: ничего не нужно настраивать или переносить**. Он одинаково защищает новые и существующие приложения и не требует дополнительной настройки.

<div id="por-que-a-proteo-no-momento-da-instalao-importante">
  ## Почему важна защита во время установки
</div>

Большинство инструментов защиты цепочки поставок проверяют зависимости только при публикации — спустя долгое время после установки пакета. Для распространённых уязвимостей этого может быть достаточно. Вредоносное ПО действует иначе: оно причиняет вред сразу при установке — похищает секреты, открывает бэкдоры или выводит ваши переменные окружения. Когда проверка при публикации его обнаруживает, атака уже произошла.

Брандмауэр пакетов закрывает это окно. Блокируя вредоносные пакеты до их загрузки, он предотвращает атаку ещё до выполнения хотя бы одной строки вредоносного кода.

<div id="como-funciona">
  ## Как это работает
</div>

1. Вы или Agent выполняете команду установки, например `npm install <package>` или `pip install <package>`.
2. Запрос проходит через брандмауэр пакетов, который проверяет пакет по данным Socket об угрозах.
3. Если пакет безопасен, установка выполняется как обычно, без заметных изменений.
4. Если пакет вредоносный или скомпрометирован, установка блокируется до того, как какой-либо код попадёт в вашу среду.

При блокировке вы получаете понятное сообщение о том, что именно было остановлено и почему, включая сведения об уязвимости или политике, вызвавшей блокировку. Agent получает тот же сигнал и может предложить безопасную альтернативу — например, исправить опечатку в имени пакета — или передать решение вам.

<div id="gerenciadores-de-pacotes-suportados">
  ### Поддерживаемые менеджеры пакетов
</div>

Брандмауэр пакетов защищает установку пакетов через:

* **JavaScript** — npm, yarn и pnpm
* **Python** — pip
* **Go** — модули Go

<div id="o-que-o-package-firewall-detecta">
  ## Что обнаруживает брандмауэр пакетов
</div>

Брандмауэр пакетов блокирует как очевидно вредоносное ПО, так и скомпрометированные или заведомо уязвимые версии легитимных пакетов, включая широко используемые. Многие из этих уязвимостей были раскрыты уже после завершения обучения моделей, которые рекомендуют такие пакеты. Поэтому модель может уверенно предложить версию зависимости, считавшуюся безопасной на момент обучения, но впоследствии признанную небезопасной. Эти риски имеют известные в отрасли названия:

* **Typosquats** — вредоносный пакет, название которого отличается от названия реального пакета всего на одну клавишу, например `reqeusts` вместо `requests`. Вы запрашиваете не тот пакет и скачиваете вредоносное ПО.
* **Slopsquats** — модель выдумывает несуществующее имя пакета, злоумышленник регистрирует именно это имя и ждёт, пока следующий Agent его установит.
* **Устаревшие рекомендации** — реальный пакет с раскрытой уязвимостью, который модель рекомендует, поскольку до завершения её обучения он считался безопасным.

Именно последняя категория делает брандмауэр пакетов особенно важным для приложений, созданных с помощью ИИ: Agent может уверенно выбрать зависимость, которая уже небезопасна, а брандмауэр пакетов предотвращает её установку до выполнения кода.

<div id="como-o-package-firewall-se-encaixa-com-as-outras-ferramentas-de-segurana-do-replit">
  ## Как брандмауэр пакетов дополняет другие инструменты безопасности Replit
</div>

брандмауэр пакетов — один из трёх взаимодополняющих уровней защиты. Каждый из них защищает свой этап жизненного цикла приложения, поэтому используйте их вместе, а не выбирайте один из них.

| Уровень                                  | Когда выполняется           | Что делает                                                                                                                                                                                                                       |
| ---------------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **брандмауэр пакетов**                     | Во время установки          | Блокирует вредоносные и скомпрометированные пакеты до их скачивания (предотвращение).                                                                                                                                            |
| **Автоматические проверки зависимостей** | После установки, непрерывно | Обнаруживают недавно опубликованные CVE в установленных зависимостях и предлагают исправления, подготовленные Agent. См. [Центр безопасности Project](/ru/pt/features/security/project-security-center#automatic-dependency-scans). |
| **Security Agent**                       | Перед публикацией           | Проверяет всю кодовую базу на уязвимости в коде, зависимостях и конфиденциальности. См. [Проверки безопасности Agent](/ru/pt/features/security/agent-security-scans).                                                               |
