Ce guide propose une checklist de sécurité complète pour vous assurer que vos applications créées par vibe coding respectent les bonnes pratiques de sécurité.

Bien que Replit propose de nombreuses fonctionnalités de sécurité [prêtes à l’emploi](/fr/features/security/overview), il est important de comprendre et de mettre en œuvre des mesures de sécurité supplémentaires adaptées aux besoins spécifiques de votre application.

<div id="prerequisites">
  ## Prérequis
</div>

* Un compte Replit
* Une connaissance de base de votre langage de programmation préféré
* Une familiarité avec le Project Editor
* Une application que vous développez sur Replit

<div id="front-end-security">
  ## Sécurité du front-end
</div>

<AccordionGroup>
  <Accordion title="HTTPS partout" icon="lock">
    Replit utilise HTTPS par défaut pour toutes les applications. Vous n’avez donc pas à vous en soucier !
  </Accordion>

  <Accordion title="Validation et assainissement des entrées" icon="shield-check">
    Validez et assainissez systématiquement les entrées utilisateur pour prévenir les attaques de type cross-site scripting (XSS) :

    ```javascript theme={null}
    // Mauvais : utilisation directe d'une entrée utilisateur
    element.innerHTML = userInput;

    // Bon : assainir l'entrée avant de l'utiliser
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    Demandez à Agent :

    ```
    Aide-moi à valider et assainir les entrées pour me protéger contre les attaques XSS
    ```
  </Accordion>

  <Accordion title="Ne stockez pas de données sensibles dans le navigateur" icon="eye-slash">
    Utilisez Replit Secrets pour stocker des informations sensibles, telles que des clés API.

    Veillez à ne pas transmettre de secrets côté client ni à les stocker aux emplacements suivants :

    * Stockage local
    * Stockage de session
    * JavaScript côté client
    * Cookies sans attributs de sécurité appropriés

    Demandez à Agent :

    ```
    Aide-moi à ne pas stocker de données sensibles dans le navigateur. Est-ce que je procède correctement ?
    ```
  </Accordion>

  <Accordion title="Protection CSRF" icon="shield">
    Mettez en œuvre une protection contre les falsifications de requêtes intersites (CSRF) pour les formulaires :

    ```javascript theme={null}
    // Exemple d'implémentation d'un jeton CSRF
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    Demandez à Agent :

    ```
    Aide-moi à mettre en œuvre des jetons CSRF pour les formulaires
    ```
  </Accordion>
</AccordionGroup>

<div id="back-end-security">
  ## Sécurité du back-end
</div>

<AccordionGroup>
  <Accordion title="Principes de base de l'authentification" icon="key">
    Lors de la mise en place de l&#39;authentification :

    * Utilisez Replit Auth lorsque c&#39;est possible
    * Si vous développez une solution d&#39;authentification personnalisée, utilisez des bibliothèques éprouvées
    * Ne stockez jamais les mots de passe en clair

    Demandez à Agent :

    ```
    Aide-moi à mettre en place l'authentification de mon application avec Replit Auth
    ```
  </Accordion>

  <Accordion title="Vérifications des autorisations" icon="user-lock">
    Vérifiez toujours les autorisations avant d&#39;effectuer une action :

    ```javascript theme={null}
    // Exemple de vérification des autorisations
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    Demandez à Agent :

    ```
    Aide-moi à mettre en place des vérifications des autorisations pour mon application
    ```
  </Accordion>

  <Accordion title="Protection des points de terminaison d'API" icon="shield">
    Sécurisez vos points de terminaison d&#39;API :

    * Ajoutez une authentification aux points de terminaison sensibles
    * Configurez correctement CORS
    * Envisagez de mettre en place une limitation du nombre de requêtes

    Demandez à Agent :

    ```
    Comment authentifier correctement les points de terminaison de mon application ?
    ```
  </Accordion>

  <Accordion title="Prévention des injections SQL" icon="database">
    Agent utilise des ORM par défaut, ce qui contribue à prévenir les injections SQL. Si vous écrivez des requêtes de base de données personnalisées :

    ```javascript theme={null}
    // Mauvais : concaténation de chaînes dans les requêtes
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // Bon : requêtes paramétrées avec un ORM
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="En-têtes de sécurité" icon="code">
    Ajoutez des en-têtes de sécurité importants à votre application :

    ```html theme={null}
    <!-- Dans index.html ou via votre back-end -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    Vous pouvez analyser votre site sur [securityheaders.com](https://securityheaders.com) afin d&#39;obtenir des recommandations.

    Demandez à Agent :

    ```
    Peux-tu ajouter les en-têtes de sécurité à mon application ?
    ```
  </Accordion>
</AccordionGroup>

<div id="ongoing-security-practices">
  ## Bonnes pratiques de sécurité continues
</div>

<AccordionGroup>
  <Accordion title="Maintenir les dépendances à jour" icon="arrow-rotate-right">
    Vérifiez régulièrement si des paquets obsolètes présentent des vulnérabilités :

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="Gestion appropriée des erreurs" icon="exclamation">
    N’exposez pas d’informations sensibles dans les messages d’erreur :

    ```javascript theme={null}
    // Mauvais : exposition de détails sensibles
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // Bon : message d’erreur générique
    catch (err) {
      console.error(err); // Journaliser en interne
      res.status(500).send('An error occurred');
    }
    ```

    Demandez à Agent :

    ```
    Aide-moi à mettre en place une gestion adéquate des erreurs pour mon application
    ```
  </Accordion>

  <Accordion title="Cookies sécurisés" icon="cookie">
    Lorsque vous utilisez des cookies :

    * Définissez l’attribut HttpOnly pour empêcher tout accès via JavaScript
    * Utilisez l’attribut Secure pour imposer HTTPS
    * Utilisez l’attribut SameSite pour prévenir les attaques CSRF

    Demandez à Agent :

    ```
    Aide-moi à sécuriser les cookies de mon application
    ```
  </Accordion>

  <Accordion title="Sécurité des téléversements de fichiers" icon="upload">
    Si votre application permet de téléverser des fichiers :

    * Limitez les types et la taille des fichiers
    * Analysez les fichiers à la recherche de logiciels malveillants lorsque possible
    * Stockez les fichiers dans Object Storage de Replit
    * Générez de nouveaux noms de fichiers plutôt que d’utiliser ceux fournis par les utilisateurs

    Demandez à Agent :

    ```
    Aide-moi à sécuriser les téléversements de fichiers de mon application
    ```
  </Accordion>

  <Accordion title="Limitation du débit" icon="clock">
    Mettez en place une limitation du débit pour les points de terminaison d’API, en particulier ceux liés à l’authentification :

    ```javascript theme={null}
    // Exemple de middleware de limitation du débit
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 minutes
      max: 100 // limite chaque IP à 100 requêtes par windowMs
    });

    app.use('/api/', limiter);
    ```

    Demandez à Agent :

    ```
    Aide-moi à mettre en place une limitation du débit pour mon application
    ```
  </Accordion>
</AccordionGroup>

<div id="checklist">
  ## Liste de contrôle
</div>

Voici les points ci-dessus sous forme de liste de contrôle pour vous aider à respecter vos bonnes pratiques de sécurité.

<div id="front-end-security-2">
  ## Sécurité du front-end
</div>

|   | Mesure de sécurité                                     | Description                                                                                    |
| - | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| ☐ | Utilisez HTTPS partout                                 | Prévient l&#39;interception de communications et les attaques de type « homme du milieu »      |
| ☐ | Validation et assainissement des entrées               | Prévient les attaques XSS en validant toutes les entrées utilisateur                           |
| ☐ | Ne stockez pas de données sensibles dans le navigateur | Aucun secret dans le stockage local ni dans le code côté client                                |
| ☐ | Protection CSRF                                        | Mettez en œuvre des jetons anti-CSRF pour les formulaires et les requêtes modifiant l&#39;état |
| ☐ | N&#39;exposez jamais les clés API dans le frontend     | Les identifiants API doivent toujours rester côté serveur                                      |

<div id="back-end-security-2">
  ## Sécurité du back-end
</div>

|   | Mesure de sécurité                                | Description                                                                                         |
| - | ------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| ☐ | Principes de base de l&#39;authentification       | Utilisez des bibliothèques éprouvées et stockez correctement les mots de passe (hachage+salage)     |
| ☐ | Vérifications d&#39;autorisation                  | Vérifiez toujours les autorisations avant d&#39;effectuer une action                                |
| ☐ | Protection des points de terminaison de l&#39;API | Mettez en place une authentification appropriée pour chaque point de terminaison de l&#39;API       |
| ☐ | Prévention des injections SQL                     | Utilisez des requêtes paramétrées ou des ORM, jamais de SQL brut avec des entrées utilisateur       |
| ☐ | En-têtes de sécurité de base                      | Mettez en place X-Frame-Options, X-Content-Type-Options et HSTS                                     |
| ☐ | Protection contre les attaques DDoS               | Utilisez un CDN ou un service cloud doté de capacités intégrées d&#39;atténuation des attaques DDoS |
