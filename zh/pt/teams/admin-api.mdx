<Note>
  Admin API 目前处于 **beta** 阶段，可用的 endpoints 及其行为可能会发生变化。
</Note>

Admin API 让 Enterprise 账户管理员能够基于作用域以编程方式访问账户的分析数据和管理功能。你可以使用该 API 为自己的 Enterprise 账户搭建内部报表、运维工作流和集成。

<div id="quem-pode-acessar-a-admin-api">
  ## 谁可以访问 Admin API
</div>

Admin API 仅向 Enterprise 账户中的**账户管理员**开放。账户管理员可以创建和管理 API 密钥。Workspace 管理员及账户中的其他成员既无法访问 Admin API，也无法创建自己的密钥。

要详细了解 Enterprise 管理员角色，请参阅[账户管理员与 Workspace 管理员](/zh/pt/teams/identity-and-access-management/account-and-workspace-admins)。

<div id="criar-uma-chave-de-api">
  ## 创建 API key
</div>

<Steps>
  <Step title="打开开发者设置">
    打开 **Settings**。在 **Account** 下选择 **Developer**。
  </Step>

  <Step title="创建 API key">
    选择 **Create API key**，然后选择只读或读写权限。
  </Step>

  <Step title="妥善保管密钥">
    复制以 `rpl_` 开头的密钥，并将其保存在安全的密钥管理器中。请像对待密码一样对待它，切勿泄露给他人。
  </Step>

  <Step title="为集成进行身份验证">
    在 API 请求中以 Bearer token 的形式发送该密钥。
  </Step>
</Steps>

<div id="o-que-voc-pode-fazer">
  ## 你可以做什么
</div>

Admin API 使用作用域来控制每个密钥可执行的操作。读取作用域提供用于报表的账户数据，而特定的写入作用域则支持更新预算等操作。

* **用量：**读取账本中的账户用量和总成本，可按 Workspace、成员、项目或时间段筛选或分组。
* **Workspaces：**读取 Workspace 列表和详情，包括成员数与项目数、管理员以及创建日期。
* **成员：**读取账户及 Workspace 的成员关系，可按角色筛选，或按姓名、用户名或电子邮件搜索。
* **项目：**读取团队 Workspace 中的项目，可按可见性或部署状态筛选，或按标题、slug 或描述搜索。
* **预算：**读取账户预算，并使用 `write:budgets` 作用域进行更新。

API 响应支持基于游标的分页，并包含速率限制标头以及用于请求追踪的 `X-Request-Id`。

<div id="crie-relatrios-e-fluxos-de-trabalho">
  ## 创建报表和工作流
</div>

在你现有的运营跟踪场景中使用 Admin API 数据，例如内部面板、Slack 提醒或月度财务报表。比如，可按 Workspace 汇总用量，统计各个 Workspace 的支出。

<div id="construindo-com-o-replit-agent">
  ## 使用 Replit Agent 构建
</div>

你可以让 Replit Agent 基于 Admin API 构建一个自定义面板。描述你想跟踪的账户数据，例如各 workspace 的用量或各项目的成本，Agent 即可为你构建面板及其 API 集成。

<Steps>
  <Step title="打开 skill 选择器">
    在 Replit 项目中，点击聊天输入框旁的 **+** 按钮，然后选择 **Use a skill**。
  </Step>

  <Step title="选择 Admin API skill">
    在 **Replit skills** 中选择 **Admin API**，为 Agent 提供该 API 的上下文和集成指引。
  </Step>

  <Step title="描述面板">
    告诉 Agent 你想跟踪哪些内容，以及希望如何呈现。例如，让 Agent 构建一个展示各 Workspace 用量和各项目成本的面板。
  </Step>

  <Step title="安全地添加你的 API 密钥">
    当 Agent 需要发起 API 请求时，请将你的 Admin API 密钥添加到项目的 Secrets 中。不要把密钥粘贴到聊天中，也不要将其提交到项目的代码中。
  </Step>
</Steps>
