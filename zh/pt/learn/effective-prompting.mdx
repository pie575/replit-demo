<div id="exemplos-rpidos">
  ## 快速示例
</div>

看看模糊提示词与有效提示词之间的区别：

<AccordionGroup>
  <Accordion title="修复代码" icon="bug">
    **模糊：**“修复我的代码。”

    **有效：**“我的脚本在处理用户输入时出错。问题似乎出在验证函数中。你能帮我调试 `validate_input` 部分吗？这是错误信息：[详细信息]”

    有效的提示词会明确问题所在、可疑函数，并提供上下文。
  </Accordion>

  <Accordion title="创建功能" icon="hammer">
    **模糊：**“创建一个网站。”

    **有效：**“创建一个简单的作品集网站，包含首页、关于我和联系表单等版块。使用简洁、现代的设计风格和占位内容。”

    有效的提示词会明确用途、核心功能和所需的美学风格。
  </Accordion>

  <Accordion title="性能优化" icon="gauge-high">
    **模糊：**“别让它变慢。”

    **有效：**“重构数据处理函数，使其能更高效地处理更大的输入。我们能否使用不同的算法或数据结构？”

    告诉 Agent *如何*改进，而非使用负面限制。
  </Accordion>

  <Accordion title="界面改动" icon="paintbrush">
    **模糊：**“添加动画。”

    **有效：**“为落地页上的主图添加动画，使其在页面首次加载时轻柔地淡入，营造友好的效果。”

    明确具体元素、所需效果、触发时机和预期体验。
  </Accordion>

  <Accordion title="复杂系统" icon="server">
    **模糊：**“构建后端。”

    **有效：**“设置服务器端逻辑。实现用户身份验证 (注册/登录) ，并创建一个 API 端点，以安全地获取用户个人资料数据。”

    将大型任务拆分为具体功能。
  </Accordion>
</AccordionGroup>

<div id="planeje-primeiro">
  ### 先做好规划
</div>

<Tip>在创建提示词之前，先梳理应用的功能和用户流程。清晰的规划能让提示词更聚焦。</Tip>

像产品经理一样思考应用的结构，将总体目标拆分为逻辑清晰的阶段。

**不要这样：**“构建一个任务管理应用。”

**尝试这样：**“1. 创建包含输入框和任务列表的基本 HTML 结构。2. 添加用于创建任务的 JavaScript。3. 使用数据库存储任务。4. 添加将任务标记为已完成的功能。”

然后，在每个阶段为 Agent 创建提示词。

<div id="construa-incrementalmente">
  ### 循序渐进地构建
</div>

使用 [**Checkpoints**](/zh/pt/features/agent/overview#checkpoints) 在每个步骤成功完成后保存进度。如果出了问题，你可以回滚到能正常运行的状态，再换一种思路尝试。

**不要这样：**&quot;Build a complete e-commerce platform.&quot;

**试试这样：**&quot;Set up a basic full-stack project for an e-commerce site with user sign-up and login using Replit Auth.&quot; 然后再用提示词逐步添加商品列表、购物车和结账流程。

<div id="seja-especfico">
  ### 尽量具体
</div>

明确说明你的需求：输出格式、限制条件和边界情况。

**不要这样写：**“添加一个联系表单。”

**可以这样写：**“在 `/contact` 创建一个联系表单页面，包含以下字段：

* 姓名 (必填)
* 电子邮箱 (必填，格式必须有效)
* 留言 (必填，至少 10 个字符)

提交后，将表单数据发送至 `contact@mydomain.com`。”

<div id="use-linguagem-positiva">
  ### 使用正面表述
</div>

说出你*想要*的效果，而不是要避免什么。

**不要这样写：** &quot;Don&#39;t make the user profile page confusing.&quot;

**试试这样写：** &quot;Design a clean user profile page. Display the username prominently, followed by email and join date. Include an &#39;Edit Profile&#39; button.&quot;

<div id="mantenha-a-simplicidade">
  ### 保持简洁
</div>

使用清晰、直接的语言。将复杂的请求拆分成要点列表。

**不要这样写：**&quot;Implement the necessary server-side infrastructure to facilitate the dynamic generation and retrieval of user-generated content artifacts.&quot;

**试试这样写：**&quot;Create backend functionality for users to submit blog posts. Users should enter a title and body content. Store posts in the database.&quot;

<div id="trabalhando-com-contexto">
  ## 使用上下文
</div>

<div id="fornea-arquivos-relevantes">
  ### 提供相关文件
</div>

指明具体的文件，而不是把整个项目都附上。

**不要这样：** (附加所有内容) &quot;Implement the user profile page based on our design system.&quot;

**试试这样：** &quot;Create the user profile page. Fetch user data from the server endpoint. Style according to [URL to design docs] and match this mockup: [attach `profile_mockup.jpg`].&quot;

<Tip>切换到不相关的任务时，请开启新的 Chat。这样可以避免上下文堆积造成混淆。</Tip>

<div id="mostre-exemplos">
  ### 展示示例
</div>

提供具体示例——代码片段、示例数据或截图——可减少歧义。

**不要这样说：**“让产品卡片看起来更好。”

**试试这样说：**“重新设计商店页面上的产品卡片。每张卡片应显示产品图片、名称、价格和‘加入购物车’按钮，布局类似这样：[附上截图]。使用浅灰色边框。”

<div id="depurando-de-forma-eficaz">
  ## 高效调试
</div>

出现错误时，请提供：

* **准确的**错误消息
* 相关代码片段
* 出错的文件名
* 你想要实现的目标
* 你已经尝试过的步骤

**不要说：**“My login page is broken.”

**换成：**“When I log in with correct credentials on `/login`, I get a &#39;User not found&#39; error in the browser console. The database check doesn&#39;t seem to work. Here&#39;s the login handling code in `auth.js`.”

<div id="pea-orientao">
  ## 寻求建议
</div>

<Tip>动手构建之前，先切换到 Plan 模式探索各种方案。可以向 Agent 咨询有哪些库可用、有哪些实现思路，以及各自的利弊权衡。</Tip>

**不要这样说：**&quot;Add payments.&quot;

**试试这样说：**&quot;What are some good options for accepting credit card payments in a web app built on Replit? I need something relatively simple to integrate.&quot;

<div id="itere-nos-seus-prompts">
  ## 迭代优化提示词
</div>

第一个提示词未必完美，这很正常。如果结果不符合预期：

* 添加更多细节
* 提供示例
* 简化指令
* 尝试换一种表达方式

**初始：** &quot;为我的网站创建一个页眉。&quot;

**优化后：** &quot;创建一个固定页眉组件，左侧放置网站徽标，右侧放置导航链接 (首页、关于、联系) 。&quot;

<div id="resumo">
  ## 总结
</div>

高效的提示词编写，关键在于：

* 编写提示词前先**做好规划**
* 借助 Checkpoint **逐步构建**
* 对需求**描述具体**
* 通过示例和相关文件**提供上下文**
* 结果不理想时**及时迭代**

掌握这些原则，你就能借助 Agent 更快地构建应用。
