Publishing 도구는 앱을 실제 서비스로 게시하고 웹에서 실행되는 방식을 관리하는 공간입니다. 앱의 웹 주소, 사용 권한, production database, 모니터링, 보안, 호스팅 방식을 제어하는 설정까지 하나의 pane에 모여 있습니다.

이 도구를 열려면 **Tools** pane의 **Replit Cloud** 아래에서 **Publishing**을 선택하거나, Project Editor 오른쪽 상단의 **Publish**를 선택하세요.

<div id="publish-your-app">
  ## 앱 게시하기
</div>

메인 pane에서 앱을 라이브로 전환하는 데 필요한 모든 항목을 안내합니다. 각 섹션을 검토한 후 **Publish**를 선택하세요.

<Frame>
  <img src="/assets/mirror/publish-your-app-851815208b8a.png" alt="Publish 버튼 위에 Domain 필드, 게시될 앱, 액세스 설정, 데이터베이스 설정, 모니터링, Security, 참여 도구가 표시된 Publish your app pane" width="578" height="980" data-path="images/deployments/publish-pane/publish-your-app.png" />
</Frame>

* **Domain**: 앱의 웹 주소입니다. Replit이 `.replit.app` 이름을 제안하고 사용 가능한지 확인해 줍니다. 이름을 변경하거나, 게시 후 [custom domain](/ko/features/publishing/custom-domains)을 연결할 수 있습니다.
* **What you&#39;re publishing**: 라이브로 전환될 앱의 미리보기와 사용될 URL입니다.
* **Who can access your app**: **Public**, **Password protected**, **Workspace only**, **Invite only** 중에서 선택합니다. 비공개 옵션을 선택하면 앱 이용 범위가 workspace 또는 초대한 사용자와 groups로 제한됩니다. [앱 액세스](/ko/features/publishing/private-deployments)에 대해 자세히 알아보세요.
* **Database settings**: 게시할 때 앱의 production database를 생성하고 데이터로 채우는 방식을 관리합니다. [production databases](/ko/features/data-and-storage/development-and-production)에 대해 자세히 알아보세요.
* **모니터링 tools**: 앱 모니터링을 켜면 앱이 다운되었을 때 가장 먼저 알 수 있습니다. Replit이 앱의 온라인 상태를 지속적으로 확인하고 문제가 발생하면 이메일로 알려줍니다. [앱 모니터링](/ko/features/publishing/monitoring-a-deployment)에 대해 자세히 알아보세요.
* **Security tools**: 게시하기 전에 심층 security scan을 실행하세요. Security Agent는 AI와 업계 최고 수준의 정적 분석 도구를 결합해 project의 취약점을 점검합니다. [Project Security Center](/ko/features/security/project-security-center)에서 자세히 알아보세요.
* **Engagement tools**: feedback widget을 켜면 published app의 모서리에 feedback 버튼이 추가됩니다. 제출된 내용은 Inbox에서 검토하고 Agent에 보내 수정할 수 있습니다.

<div id="adjust-settings">
  ## Adjust settings
</div>

앱이 호스팅되는 방식을 직접 설정하려면 **Adjust settings**를 선택하세요. 대부분의 builder는 이 설정을 변경할 일이 없습니다. Replit이 적절한 기본값을 알아서 선택합니다.

<Frame>
  <img src="/assets/mirror/adjust-settings-d6e124b2249f.png" alt="deployment type, 머신 구성, deployment secrets, deployment geography, 심각한 취약점 발견 시 게시 차단 토글을 보여주는 Adjust settings 섹션" width="574" height="794" data-path="images/deployments/publish-pane/adjust-settings.png" />
</Frame>

* **Deployment type**: 앱을 게시하는 데 사용하는 기술입니다. **Autoscale**은 트래픽이 없는 상태부터 어떤 수준의 수요까지 자동으로 확장되므로 대부분의 앱에 권장됩니다. [deployment type](/ko/features/publishing/deployment-types)을 비교해 보세요.
* **Machine configuration**: 앱을 실행하는 서버의 성능입니다. CPU, 메모리, 최대 머신 수를 변경하려면 **Edit**를 선택하세요. 이 pane에는 머신당 비용과 최대 트래픽 시 비용이 표시됩니다. [머신 구성](/ko/features/publishing/machine-configuration)에 대해 자세히 알아보세요.
* **Deployment secrets**: 앱이 API와 서비스에 접근할 때 사용하는 비공개 키입니다(API key처럼 민감한 값을 보관하는 안전하고 숨겨진 저장 영역). secret은 개발 환경에서 게시된 앱으로 자동 동기화됩니다. [Secrets](/ko/core-concepts/project-editor/app-setup/secrets)에 대해 자세히 알아보세요.
* **Deployment geography**: 앱이 호스팅되는 위치입니다. 사용자와 가까운 리전을 선택하면 지연 시간이 줄어듭니다. 게시하고 나면 앱과 해당 리소스는 이 리전에 고정됩니다. 나중에 리전을 바꾸려면 앱을 remix하세요. [Project geography](/ko/features/publishing/project-geography)에 대해 자세히 알아보세요.
* **Block publishing of critical vulnerabilities**: Replit은 게시 전에 항상 security scan을 실행합니다. 이 설정은 심각한 취약점이 발견되었을 때 게시를 차단할지 여부를 결정합니다. 자세한 내용은 [Project Security Center](/ko/features/security/project-security-center)를 참고하세요.
