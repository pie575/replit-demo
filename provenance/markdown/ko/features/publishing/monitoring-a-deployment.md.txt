# 앱 모니터링하기

> 게시된 앱이 정상적으로 작동하는지, 어떻게 응답하는지, 어떤 리소스를 사용하는지를 가동 시간, 요청, 사용량 차트로 확인하세요.

Monitoring 도구는 게시된 앱에 대한 세 가지 질문에 답합니다: 앱이 정상 작동 중인가, 어떻게 동작하고 있는가, 무엇을 사용하고 있는가? **Tools** 패널의 **Replit Cloud** 아래에서 **Monitoring**을 엽니다.

모니터링은 앱을 게시하면 시작됩니다. 게시 전에는 도구에 **No deployment yet** 메시지가 표시됩니다.

<Note>
  방문자 및 사용자 인사이트를 찾고 계신가요? **Growth** 패널에서 [Project
  Analytics](/ko/features/publishing/project-analytics)를 여세요.
</Note>

## Application monitoring

Application monitoring은 방문자의 관점에서 앱이 어떻게 동작하는지 보여줍니다. 상단에서 기간을 선택해 확대하거나 축소할 수 있습니다.

<Frame>
  <img src="https://mintcdn.com/replit/BUcQPNDB2pXU4rMm/images/deployments/monitoring/application-monitoring.png?fit=max&auto=format&n=BUcQPNDB2pXU4rMm&q=85&s=cd182ec7dc73b70af96180f05722847d" alt="가동 시간 모니터링, 고유 IP 주소를 포함한 요청 차트, HTTP 상태, 요청 시간을 보여주는 Application monitoring 화면" width="2000" height="1656" data-path="images/deployments/monitoring/application-monitoring.png" />
</Frame>

* **Uptime Monitoring**: 앱이 온라인 상태였던 시간의 비율을, 최근 기록을 보여주는 색상 막대와 함께 표시합니다. Replit은 정기적인 일정에 따라 앱을 확인하고, 앱이 다운되면 이메일로 알려줍니다.
* **Requests**: 시간에 따라 앱이 처리하는 트래픽 양과, 앱에 도달한 고유 IP 주소 수입니다.
* **HTTP Statuses**: 앱이 최근 요청에 어떻게 응답했는지를 보여줍니다. 성공 응답은 정상 상태를 의미하며, 오류가 급증하면 조사해야 할 신호입니다. 오류가 급증한 시간대를 Agent 채팅에 붙여넣고 로그를 확인해 달라고 요청하세요.
* **Request Durations**: 앱이 응답하는 데 걸리는 시간을 구간별로 그룹화하여 보여줍니다. 대부분의 요청이 가장 느린 구간에 몰려 있다면, 앱에 조치가 필요하거나 [더 강력한 머신](/ko/features/publishing/machine-configuration)이 필요할 수 있습니다.

### 가동 시간 모니터링 켜기

가동 시간 확인은 게시 설정에서 제어합니다.

<Steps>
  <Step title="게시 설정 열기">
    **Publishing** 도구를 열고 새 게시를 시작하거나 앱을 다시 게시합니다.
  </Step>

  <Step title="토글 활성화하기">
    **Monitoring tools** 아래에서 **Enable app monitoring**을 켠 다음 앱을 게시합니다.
  </Step>

  <Step title="가동 시간 확인하기">
    게시 후 몇 분 안에 Monitoring 도구에 가동 시간이 표시됩니다.
  </Step>
</Steps>

<Note>
  가동 시간 모니터링은 Replit Core, Pro, Enterprise 플랜에서 사용할 수 있습니다. 웹페이지를 제공하지 않는 Scheduled Deployments를 제외한 모든 배포 유형에서 작동합니다.
</Note>

## Infrastructure monitoring

Infrastructure monitoring은 앱이 내부적으로 무엇을 소비하고 있는지 보여줍니다.

<Frame>
  <img src="https://mintcdn.com/replit/BUcQPNDB2pXU4rMm/images/deployments/monitoring/infrastructure-monitoring.png?fit=max&auto=format&n=BUcQPNDB2pXU4rMm&q=85&s=60d6fea9e0ecb56c963462137d97ae77" alt="지난 1시간 동안의 CPU 사용률과 메모리 사용률 차트를 보여주는 Infrastructure monitoring 화면" width="2000" height="1513" data-path="images/deployments/monitoring/infrastructure-monitoring.png" />
</Frame>

* **CPU Utilization**: 앱이 사용하는 처리 능력입니다.
* **Memory Utilization**: 앱이 사용하는 메모리량입니다.

일시적인 급증은 정상입니다. 두 차트 중 하나라도 지속적으로 높은 상태를 유지한다면, 부하가 걸릴 때 앱의 응답이 느려질 수 있습니다. [더 강력한 머신 구성](/ko/features/publishing/machine-configuration)을 고려해 보세요.

## Logs

Logs는 오류와 앱이 실행 중에 출력하는 메시지 등, 앱이 실시간으로 하는 작업을 보여줍니다. Replit은 배포 로그를 30일 동안 보관합니다.

다음 필터로 로그를 좁혀볼 수 있습니다:

* **Errors only**: 오류 로그만 표시합니다.
* **Search**: 로그에서 검색할 문구를 입력합니다.
* **Date**: 날짜 범위를 선택합니다.

<Tip>
  앱에 문제가 있어 보여도 직접 로그를 읽을 필요는 없습니다. Agent에게 조사를 요청하면 대신 로그를 읽어줍니다.
</Tip>
