Project Analytics показывает, как люди находят и используют ваше опубликованное веб-приложение. Откройте панель **Growth**, чтобы посмотреть динамику посещаемости, источники трафика и пользовательские события.

Replit собирает базовые показатели трафика для поддерживаемых опубликованных приложений. На платных тарифах Agent может добавлять пользовательские события и отвечать на вопросы по аналитике.

<div id="section">
  ## Прежде чем начать
</div>

Для работы с Project Analytics вам понадобится следующее:

* **Опубликованный сайт.** Analytics поддерживает [артефакты](/ru/ko/features/projects-and-artifacts/artifacts) типа «сайт». В мобильных приложениях и артефактах других типов события не собираются.
* **Поддерживаемый тип деплоя.** Project Analytics работает с деплоями [Autoscale](/ru/ko/features/publishing/deployment-types#autoscale), [Reserved VM](/ru/ko/features/publishing/deployment-types#reserved-vm) и [Static](/ru/ko/features/publishing/deployment-types#static).
* **Платный тариф для расширенной аналитики.** Пользовательские события и аналитические запросы через Agent доступны на платных тарифах.
* **Включённая аналитика в следующем релизе.** Replit начинает собирать события только после того, как вы включите параметр **Enable analytics** и опубликуете или повторно опубликуете приложение.

<div id="project-analytics">
  ## Откройте Project Analytics
</div>

1. Откройте проект в Project Editor.
2. Выберите **Tools**.
3. В разделе **Replit Cloud** выберите **Growth**.

<Note>
  Панель **Growth** будет заблокирована, пока вы не опубликуете приложение. До публикации
  вы увидите предложение перейти в **Go to
  Publishing**.
</Note>

Данные аналитики появятся, когда опубликованное приложение начнёт получать трафик. В новых приложениях диаграммы могут быть пустыми, пока их не начнут посещать пользователи.

<div id="section-2">
  ## Обзор базовой аналитики
</div>

Базовая аналитика использует данные IP-трафика и отображает следующие показатели.

* **Посетители**: примерное число уникальных посетителей за выбранный период.
* **Посетители по времени (час)** или **Посетители по времени (день)**: показывают, как меняется активность посетителей за выбранный период.
* **Популярные страницы**: страницы с наибольшим трафиком.
* **Основные источники переходов**: веб-сайты, направляющие трафик в приложение.
* **Основные страны**: страны, из которых предположительно приходят посетители.
* **Популярные браузеры**: браузеры, которыми пользуются посетители.
* **Популярные устройства**: типы устройств, которыми пользуются посетители.

В меню периода можно выбрать период от 6 часов до 30 дней. Общее число посетителей сравнивается с предыдущим периодом той же продолжительности.

Если приложение использует [Replit Auth](/ru/ko/features/auth-and-identity/authentication), на панели также отображается **число уникальных вошедших пользователей** за выбранный период.

<Note>
  Число посетителей является приблизительным. Поскольку используются данные сети и
  браузера, один человек может отображаться как несколько посетителей при использовании
  разных устройств или в разных календарных месяцах.
</Note>

<div id="agent">
  ## Добавление пользовательских событий с помощью Agent
</div>

Пользовательские события позволяют измерять важные действия в приложении. Например, завершённые регистрации, выбранные тарифы, отправленные формы и совершённые покупки.

<Steps>
  <Step title="Добавление метрик с помощью Agent">
    Откройте **Growth**. В разделе **Advanced analytics** выберите **Add metrics with
    Agent**. Опишите Agent, какие действия вы хотите измерять. Agent
    добавит отслеживание событий в нужные места приложения.
  </Step>

  <Step title="Включение аналитики и публикация">
    Откройте **Publishing** и начните новую публикацию или опубликуйте приложение заново. В разделе **Suggested
    add-ons** включите **Enable analytics**. Затем опубликуйте
    приложение. Начиная с этого выпуска Replit будет собирать просмотры страниц и пользовательские события.
  </Step>
</Steps>

<Tip>
  Настроить аналитику можно и напрямую через чат с Agent. Всякий раз, когда меняется приложение или
  цели измерений, вы можете попросить Agent добавить или обновить
  события.
</Tip>

Replit сам добавляет трекер аналитики в опубликованное приложение. Вам не нужно вручную добавлять скрипт отслеживания, идентификатор сайта или переменные окружения для аналитики.

<Warning>
  Не указывайте в названиях и свойствах пользовательских событий секреты, персональные данные и произвольный
  контент, введённый посетителями.
</Warning>

<div id="agent-2">
  ## Задавайте Agent вопросы об аналитике
</div>

После того как приложение соберёт данные, используйте чипы **Advanced analytics**.

* **Summarize my analytics**: Agent суммирует аналитику проекта за последние 7 дней.
* **Suggest project improvements**: Agent проанализирует данные и порекомендует, что можно улучшить в проекте.

Вы также можете задавать Agent конкретные вопросы.

<AiPrompt>
  Сравните количество посетителей и завершённых регистраций за последние 7 дней.
  Покажите динамику по дням и укажите страницу с самым высоким коэффициентом конверсии.
</AiPrompt>

Agent может анализировать просмотры страниц, источники трафика, пользовательские события, свойства событий и воронки. Он использует аналитические данные проекта и возвращает агрегированные результаты.
