# 배포 유형

> Autoscale, Static, Reserved VM, Scheduled 배포를 비교하고 게시한 앱에 각각 언제 사용해야 하는지 알아보세요.

배포 유형은 Replit이 앱을 게시하는 데 사용하는 기술입니다. Publishing 도구의 **Adjust settings**에서 **Deployment type** 드롭다운을 통해 선택할 수 있습니다. **Autoscale**은 기본값이자 권장되는 선택이며, 대부분의 빌더는 이를 변경할 필요가 없습니다.

## 배포 유형 비교

| 유형              | 적합한 용도                 | 실행 방식                               | 요금 방식                     |
| :-------------- | :--------------------- | :---------------------------------- | :------------------------ |
| **Autoscale**   | 트래픽이 변동하는 웹 앱과 API     | 부하가 많을 때 서버를 추가하고, 유휴 상태일 때는 0까지 축소 | 요청이 처리되는 동안에만 비용 지불       |
| **Static**      | 랜딩 페이지, 포트폴리오, 문서 사이트  | 캐시된 클라우드 서버에서 파일을 제공, 백엔드 없음        | 사이트가 제공하는 데이터에 대해서만 비용 지불 |
| **Reserved VM** | 봇, 백그라운드 작업, 상시 실행 API | 절전 모드로 전환되지 않는 하나의 전용 서버            | 고정된 월 비용                  |
| **Scheduled**   | 백업, 알림 같은 주기적 작업       | 예약된 일정에 따라 명령을 실행한 후 중지             | 각 실행 시간에 대해 비용 지불         |

## Autoscale

Autoscale 배포는 앱의 트래픽에 따라 확장 및 축소되는 서버에서 실행됩니다. 앱에 부하가 많을 때는 Replit이 서버를 추가하여 부하를 처리합니다. 유휴 상태일 때는 서버 수가 최소 0까지 줄어들어 조용한 시간에는 비용을 지불하지 않습니다.

다음과 같은 경우에 적합합니다.

* 이커머스 사이트처럼 트래픽이 변동하는 웹 애플리케이션
* API 및 서비스

설정은 **Adjust settings**에서 관리합니다. [머신 성능 및 최대 서버 수](/ko/features/publishing/machine-configuration)를 참고하세요.

## Static

Static 배포는 HTML, CSS, JavaScript 등 앱의 파일을 캐싱을 사용하여 빠르고 경제적으로 콘텐츠를 제공하는 클라우드 서버에서 호스팅합니다. 백엔드 서버는 없습니다.

다음과 같은 경우에 적합합니다.

* 마케팅 랜딩 페이지
* 포트폴리오 웹사이트
* 제품 및 API 문서 사이트

<Note>
  Static 배포는 Agent를 사용하여 생성된 Replit Apps와 호환되지 않습니다. Agent는 백엔드 서버가 필요한 풀스택 앱을 빌드하므로, 이러한 경우에는 Autoscale 또는 Reserved VM을 사용하세요.
</Note>

설정에는 제공할 퍼블릭 디렉터리와 선택적인 빌드 명령이 포함됩니다. 응답 헤더, URL 재작성, 리디렉션에 대한 자세한 내용은 [고급 Static 설정](/ko/features/deployment-customization/static-deployments-advanced)을 참고하세요.

## Reserved VM

Reserved VM 배포는 절전 모드로 전환되지 않는 전용 가상 머신에서 앱을 실행합니다. 일관된 성능과 예측 가능한 고정 월 비용을 얻을 수 있습니다.

다음과 같은 경우에 적합합니다.

* 메모리를 많이 사용하는 백그라운드 작업
* 연결을 계속 유지해야 하는 챗봇
* 상시 실행되는 API 서버

설정에는 [머신 성능](/ko/features/publishing/machine-configuration), 빌드 및 실행 명령, 포트 매핑, 앱이 웹 서버로 실행되는지 또는 백그라운드 워커로 실행되는지 여부가 포함됩니다.

## Scheduled

Scheduled 배포는 앱 환경에서 예약된 일정에 따라 명령을 실행한 후, 다음 실행까지 중지 상태를 유지합니다. "매 평일 오전 9시"와 같이 일정을 평이한 언어로 설명하면 Replit이 이를 자동으로 일정으로 변환합니다. 실행이 실패하면 알림을 받습니다.

다음과 같은 경우에 적합합니다.

* 상태 확인 및 헬스 리포트
* 알림 전송
* 백업 시작

설정에는 일정, 작업 타임아웃, 빌드 및 실행 명령이 포함됩니다. Scheduled 배포는 웹 페이지를 제공하지 않으므로 퍼블릭 URL이 없습니다.
