<Note>
  Admin API 目前处于 **beta** 阶段，可用端点和行为可能会发生变化。
</Note>

Admin API 让 Enterprise 账户管理员能够基于作用域，以编程方式访问账户分析和管理功能。你可以使用该 API 为 Enterprise 账户构建内部报表、运维工作流和各类 集成。

<div id="who-can-access-the-admin-api">
  ## 谁可以访问 Admin API
</div>

Admin API 仅向 Enterprise 账户的**账户管理员**开放。账户管理员可以创建和管理 API 密钥。Workspace 管理员及其他账户成员无法访问 Admin API，也无法创建相关密钥。

如需详细了解 Enterprise 管理员角色，请参阅[账户与 Workspace 管理员](/zh/teams/identity-and-access-management/account-and-workspace-admins)。

<div id="create-an-api-key">
  ## 创建 API 密钥
</div>

<Steps>
  <Step title="打开开发者设置">
    打开 **Settings**。在 **Account** 下，选择 **Developer**。
  </Step>

  <Step title="创建 API 密钥">
    选择 **Create API key**，然后选择只读或读写权限。
  </Step>

  <Step title="安全存储密钥">
    复制以 `rpl_` 开头的密钥，并将其保存在安全的密钥管理器中。请像对待密码一样对待它，切勿泄露给他人。
  </Step>

  <Step title="为集成进行身份验证">
    在 API 请求中以 Bearer 令牌的形式发送该密钥。
  </Step>
</Steps>

<div id="what-you-can-do">
  ## 您可以执行的操作
</div>

Admin API 使用作用域来控制每个密钥可执行的操作。读取作用域可提供用于报告的账户数据，而特定写入作用域则支持更新预算等操作。

* **使用情况：**读取账户用量和总账成本，并可按 Workspace、成员、项目或时间段筛选或分组。
* **Workspaces：**读取 Workspace 列表和详细信息，包括成员数、项目数、管理员和创建时间。
* **成员：**读取账户成员资格和 Workspace 成员资格，可按角色筛选，或按姓名、用户名或电子邮件搜索。
* **项目：**读取 Team Workspaces 中的项目，可按可见性或 deployment 状态筛选，或按标题、slug 或描述搜索。
* **预算：**读取账户预算，并使用 `write:budgets` 作用域更新预算。

API 响应支持游标分页，并包含速率限制标头以及用于跟踪请求的 `X-Request-Id`。

<div id="build-reports-and-workflows">
  ## 构建报表与工作流
</div>

在你已有的运营跟踪场景中使用 Admin API 数据，例如内部仪表板、Slack 告警或月度财务报表。例如，可以按 Workspace 汇总用量，统计每个 Workspace 的支出。

<div id="building-with-replit-agent">
  ## 使用 Replit Agent 构建
</div>

你可以让 Replit Agent 基于 Admin API 构建自定义仪表板。描述你想追踪的账户数据，例如按 Workspace 统计的用量或按 项目 统计的成本，Agent 即可构建出该仪表板及其 API 集成。

<Steps>
  <Step title="打开 skill 选择器">
    在 Replit 项目 中，点击聊天输入框旁的 **+** 按钮，然后选择 **Use a skill**。
  </Step>

  <Step title="选择 Admin API skill">
    在 **Replit skills** 下选择 **Admin API**，为 Agent 提供 API 上下文和集成指引。
  </Step>

  <Step title="描述仪表板">
    告诉 Agent 你想追踪哪些内容，以及希望以何种方式查看。例如，让 Agent 构建一个按 Workspace 展示用量、按 项目 展示成本的仪表板。
  </Step>

  <Step title="安全地添加 API 密钥">
    当 Agent 需要发起 API 请求时，请将你的 Admin API 密钥添加到 项目 的 Secrets 中。不要把密钥粘贴到聊天中，也不要提交到 项目 里。
  </Step>
</Steps>
