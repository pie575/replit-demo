Эффективный промпт — это чёткие инструкции для способного помощника. Правильно направляйте [**Agent**](/ru/features/agent/overview), и вы быстро превратите идею в App.

<div id="quick-examples">
  ## Короткие примеры
</div>

Сравните расплывчатые и эффективные промпты:

<AccordionGroup>
  <Accordion title="Исправление кода" icon="bug">
    **Расплывчато:** «Исправь мой код».

    **Эффективно:** «Мой скрипт падает при обработке пользовательского ввода. Похоже, ошибка в функции валидации. Помоги отладить часть `validate_input`. Вот сообщение об ошибке: [подробности]»

    Эффективный промпт указывает на проблемную область, предполагаемую функцию и даёт контекст.
  </Accordion>

  <Accordion title="Создание функций" icon="hammer">
    **Расплывчато:** «Сделай сайт».

    **Эффективно:** «Создай простой сайт-портфолио с разделами «Главная», «Обо мне» и «Форма обратной связи». Используй лаконичную современную тему оформления и текст-заполнитель вместо реального контента».

    Эффективный промпт определяет цель, ключевые функции и желаемый стиль.
  </Accordion>

  <Accordion title="Улучшение производительности" icon="gauge-high">
    **Расплывчато:** «Не делай медленно».

    **Эффективно:** «Отрефактори функцию обработки данных, чтобы она эффективнее справлялась с большими объёмами данных. Можно ли использовать другой алгоритм или структуру данных?»

    Объясняйте Agent, *как* именно улучшить, а не формулируйте задачу через запреты.
  </Accordion>

  <Accordion title="Изменения интерфейса" icon="paintbrush">
    **Расплывчато:** «Добавь анимацию».

    **Эффективно:** «Анимируй главное изображение на лендинге так, чтобы при первой загрузке страницы оно плавно проявлялось и создавало приветливое впечатление».

    Укажите конкретный элемент, желаемый эффект, тайминг и задуманное впечатление.
  </Accordion>

  <Accordion title="Сложные системы" icon="server">
    **Расплывчато:** «Сделай бэкенд».

    **Эффективно:** «Настрой серверную логику. Реализуй аутентификацию пользователей (регистрация/вход) и создай эндпоинт API для безопасного получения данных профиля пользователя».

    Разбивайте крупные задачи на конкретные функции.
  </Accordion>
</AccordionGroup>

<div id="plan-first">
  ### Сначала планируйте
</div>

<Tip>Прежде чем писать промпт, опишите функции приложения и пользовательские сценарии. Чёткий план помогает формулировать более точные промпты.</Tip>

Продумайте структуру приложения так, как это сделал бы продакт-менеджер. Разбейте общую цель на логические этапы.

**Вместо:** «Создай приложение для управления задачами».

**Попробуйте:** «1. Создай базовую HTML-структуру с полем ввода и списком задач. 2. Добавь JavaScript для добавления задач. 3. Используй базу данных для хранения задач. 4. Добавь возможность отмечать задачи как выполненные».

Затем отправляйте Agent отдельный промпт для каждого шага.

<div id="build-incrementally">
  ### Стройте пошагово
</div>

Используйте [**чекпоинты**](/ru/features/agent/overview#checkpoints), чтобы сохранять прогресс после каждого успешного шага. Если что-то сломается, вы сможете откатиться к рабочему состоянию и попробовать другой подход.

**Вместо:** «Создай полноценную платформу электронной коммерции».

**Попробуйте:** «Создай базовый полностековый project для сайта электронной коммерции с регистрацией и входом пользователей через Replit Auth». А затем добавьте промпты для каталога товаров, корзины и оформления заказа.

<div id="be-specific">
  ### Будьте конкретны
</div>

Чётко укажите, что вам нужно: форматы вывода, ограничения, пограничные случаи.

**Вместо:** «Добавь форму обратной связи».

**Попробуйте:** «Создай страницу с формой обратной связи по адресу `/contact` со следующими полями:

* Имя (обязательное)
* Электронная почта (обязательное, в корректном формате)
* Сообщение (обязательное, минимум 10 символов)

После отправки отправляй данные формы на `contact@mydomain.com`».

<div id="use-positive-language">
  ### Используйте позитивные формулировки
</div>

Описывайте то, что вы *хотите получить*, а не то, чего следует избегать.

**Вместо:** «Не делай страницу профиля пользователя запутанной».

**Попробуйте:** «Спроектируй аккуратную страницу профиля пользователя. Размести имя пользователя на видном месте, ниже — адрес электронной почты и дату регистрации. Добавь кнопку „Редактировать профиль“».

<div id="keep-it-simple">
  ### Пишите проще
</div>

Используйте ясные и понятные формулировки. Разбивайте сложные запросы на пункты списка.

**Вместо:** «Реализуйте необходимую серверную инфраструктуру для обеспечения динамической генерации и получения артефактов пользовательского контента».

**Попробуйте:** «Создай бэкенд, который позволит пользователям публиковать записи в блоге. Пользователь вводит заголовок и текст. Сохраняй записи в базе данных».

<div id="working-with-context">
  ## Работа с контекстом
</div>

<div id="provide-relevant-files">
  ### Указывайте нужные файлы
</div>

Упоминайте конкретные файлы вместо того, чтобы прикреплять весь project целиком.

**Вместо:** (прикрепив всё подряд) «Реализуй страницу профиля пользователя на основе нашей дизайн-системы».

**Попробуйте:** «Создай страницу профиля пользователя. Данные пользователя получай с серверной конечной точки. Оформи её согласно [ссылка на документацию по дизайну] и в соответствии с этим макетом: [прикреплён `profile_mockup.jpg`]».

<Tip>Начинайте новый Chat, когда переходите к задачам из другой области. Так вы избежите путаницы из-за накопленного контекста.</Tip>

<div id="show-examples">
  ### Показывайте примеры
</div>

Устраняйте неоднозначность с помощью конкретных примеров — фрагментов кода, образцов данных или снимков экрана.

**Вместо:** «Сделай карточки товаров красивее».

**Попробуйте:** «Переработай карточки товаров на странице магазина. В каждой карточке должны отображаться изображение товара, название, цена и кнопка „Добавить в корзину“, по аналогии с этим макетом: [прикрепить снимок экрана]. Используй светло-серую рамку».

<div id="debugging-effectively">
  ## Эффективная отладка
</div>

При возникновении ошибок указывайте:

* **Точный** текст сообщения об ошибке
* Соответствующие фрагменты кода
* Имена файлов, в которых возникает ошибка
* Чего вы пытались добиться
* Что вы уже пробовали

**Вместо:** «У меня сломалась страница входа».

**Попробуйте:** «Когда я вхожу с правильными учётными данными на `/login`, в консоли браузера появляется ошибка &quot;User not found&quot;. Похоже, проверка по базе данных не срабатывает. Вот код обработки входа в `auth.js`».

<div id="ask-for-guidance">
  ## Запросите рекомендации
</div>

<Tip>Перед началом разработки переключитесь в режим Plan, чтобы изучить возможные варианты. Спросите Agent о библиотеках, подходах и компромиссах.</Tip>

**Вместо:** &quot;Добавь платежи.&quot;

**Попробуйте:** &quot;Какие есть хорошие варианты для приема платежей кредитными картами в веб-приложении, созданном на Replit? Мне нужно решение, которое будет относительно легко интегрировать.&quot;

<div id="iterate-on-your-prompts">
  ## Дорабатывайте свои промпты
</div>

Первый промпт может оказаться неидеальным — это нормально. Если результат вас не устраивает:

* Добавьте деталей
* Приведите пример
* Упростите формулировку
* Объясните по-другому

**Исходный вариант:** «Создай шапку для моего сайта».

**Доработанный вариант:** «Создай компонент закреплённой шапки с логотипом сайта слева и навигационными ссылками (Главная, О нас, Контакты) справа».

<div id="summary">
  ## Итог
</div>

Эффективная работа с промптами сводится к следующему:

* **Планируйте** перед отправкой промпта
* **Создавайте** приложение постепенно, используя чекпоинты
* **Чётко формулируйте** requirements
* **Добавляйте контекст** с помощью примеров и релевантных файлов
* **Итерируйте**, если результат не совсем соответствует ожиданиям

Освойте эти принципы — и вы будете быстрее создавать приложения с Agent.
