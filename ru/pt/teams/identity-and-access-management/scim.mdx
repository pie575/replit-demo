<div id="introduo">
  ## Введение
</div>

<Note>
  SCIM доступен исключительно клиентам Enterprise. Чтобы включить эту функцию в вашей организации, свяжитесь с нашим отделом продаж по адресу [sales@replit.com](mailto:sales@replit.com).
</Note>

Система междоменного управления идентификацией ([SCIM](https://en.wikipedia.org/wiki/System_for_Cross-domain_Identity_Management)) — стандартизированный протокол, автоматизирующий предоставление и отзыв доступа пользователей между вашим корпоративным провайдером идентификации (IdP) и Replit.

После активации SCIM вы можете управлять сопоставлением синхронизированных групп и участников с рабочими пространствами и ролями Replit непосредственно в Replit — см. раздел [Управление доступом к рабочему пространству](#managing-workspace-access).

<div id="benefcios">
  ## Преимущества
</div>

Интеграция SCIM предоставляет ряд преимуществ для команд Enterprise:

* **Повышенная безопасность**: Используйте существующие системы управления идентификацией для надежного контроля доступа
* **Упрощенное администрирование**: Автоматически управляйте участниками команды через своего провайдера идентификации
* **Эффективное подключение**: Легко предоставляйте доступ большим командам без ручного вмешательства
* **Единообразный контроль доступа**: Поддерживайте единые политики доступа во всей организации

<div id="primeiros-passos">
  ## Первые шаги
</div>

<Steps>
  <Step title="Включите SCIM">
    Откройте **Настройки** &gt; **Дополнительно** &gt; **Идентификация и управление**, чтобы включить SCIM для организации Enterprise.
  </Step>

  <Step title="Настройте IdP">
    Откройте портал интеграции SCIM в настройках раздела «Идентификация и управление». На портале вы найдёте пошаговые инструкции для своего провайдера идентификации по синхронизации каталога пользователей.
  </Step>

  <Step title="Протестируйте интеграцию">
    Проверьте подключение, подготовив тестового пользователя.
  </Step>

  <Step title="Перейдите в продакшен">
    Начните использовать SCIM для автоматизированного управления участниками, затем назначьте синхронизированные группы рабочим пространствам в разделе [Доступ к рабочему пространству через SCIM](#managing-workspace-access).
  </Step>
</Steps>

<div id="melhores-prticas">
  ## Рекомендации
</div>

* Задокументируйте назначенные роли существующих участников Replit, прежде чем включать SCIM.
* Укажите рабочее пространство по умолчанию, чтобы каждая синхронизированная группа получила в нём как минимум роль **Наблюдатель**; без рабочего пространства по умолчанию у участника не будет роли, пока вы не назначите его группу рабочему пространству.
* Протестируйте конфигурацию, назначив небольшую группу участников, прежде чем включать массовое предоставление доступа.
* После первоначальной синхронизации проверьте и настройте разрешения для пользовательских групп в соответствии с потребностями вашей организации в управлении доступом.
* Используйте группы управления ролями для контроля уровней доступа предоставленных участников, а другие push-группы — для категоризации и массового управления разрешениями.
* Задокументируйте конфигурацию SCIM для дальнейшего использования.

<div id="sincronizao-de-grupos">
  ## Синхронизация групп
</div>

Все группы, передаваемые из вашего IdP, синхронизируются с Replit вместе с участниками, которых ваш IdP назначает в эти группы. Когда вы передаёте группу «Инженерия» через SCIM, Replit создаёт соответствующую группу с этими назначенными участниками.

Состав группы автоматически обновляется в соответствии с данными вашего IdP. Вы можете использовать синхронизированные группы для массового изменения разрешений участников, например предоставить доступ к приложению всем участникам группы «Инженерия».

<div id="use-grupos-no-aninhados-com-o-microsoft-entra-id">
  ### Используйте невложенные группы с Microsoft Entra ID
</div>

<Warning>
  Microsoft Entra ID подготавливает только пользователей, которые являются прямыми участниками явно назначенной группы. Вложенные группы не разворачиваются. Пользователь, состоящий только в подгруппе, не добавляется в родительскую группу в Replit. Microsoft Entra ID не подготовит такого пользователя, если он не указан напрямую в другой назначенной группе.
</Warning>

Для подготовки через SCIM используйте невложенные группы, добавляя пользователей напрямую в каждую группу, назначенную Replit. Если необходимо сохранить вложенные группы в Microsoft Entra ID, назначьте приложению Replit все группы, в которых пользователи состоят напрямую. Подробнее см. в [руководстве Microsoft по определению области действия на основе назначений](https://learn.microsoft.com/en-us/entra/identity/app-provisioning/how-provisioning-works#assignment-based-scoping).

<div id="criando-grupos-personalizados-junto-com-o-scim">
  ### Создание пользовательских групп при использовании SCIM
</div>

Вы можете создавать пользовательские группы в Replit, даже если SCIM включён. Используйте пользовательские группы для объединения участников по проектам, разового предоставления разрешений или создания любых структур, не синхронизируемых с вашим провайдером идентификации.

* **Группы SCIM остаются заблокированными.** Группы, синхронизированные из вашего IdP, можно изменять или удалять только через провайдер идентификации.
* **Пользовательскими группами управляют в Replit.** Администраторы организации могут создавать, изменять и удалять пользовательские группы непосредственно на странице «Группы».
* **Участники могут состоять в группах обоих типов.** Участника, добавленного через SCIM, также можно включить в пользовательские группы, не затрагивая его роли, управляемые IdP.

Подробнее о группах см. в разделе [Группы и разрешения](/ru/pt/teams/identity-and-access-management/groups-and-permissions).

<div id="gerenciando-o-acesso-ao-workspace">
  ## Управление доступом к рабочему пространству
</div>

Когда SCIM активен, используйте встроенный интерфейс управления, чтобы просматривать и настраивать сопоставление синхронизированных групп с рабочими пространствами и ролями, а также назначать группу администраторов учётной записи. Ваш IdP остаётся источником достоверных данных о членстве и подготовке учётных записей; этот интерфейс определяет, как синхронизированные группы и участники сопоставляются с рабочими пространствами и ролями Replit, — он не добавляет, не удаляет и не подготавливает участников повторно.

<div id="estruture-seus-workspaces">
  ### Организуйте рабочие пространства
</div>

Как правило, рекомендуем размещать участников в **одном рабочем пространстве** и создавать дополнительные рабочие пространства только при наличии веской причины разделить их — например, для отдельных бизнес-подразделений, которые не должны совместно использовать участников, группы или бюджеты. Все, кому необходимо сотрудничать, должны находиться в одном рабочем пространстве.

Вы можете назначать синхронизированные группы рабочим пространствам. Внутри рабочего пространства назначенная группа отображается как **пользовательская группа**, которую можно использовать для управления на уровне рабочего пространства, например для **бюджетов по группам** — например, бюджет в 100 тыс. для команды Revenue.

<div id="abrir-o-acesso-ao-workspace-via-scim">
  ### Открытие доступа к рабочему пространству через SCIM
</div>

1. Откройте меню выбора рабочего пространства и выберите своё рабочее пространство Enterprise.
2. Откройте **настройки**, затем выберите **Avançado**.
3. Разверните раздел **Identidade e Governança** и найдите карточку **Provisionamento automático de membros (SCIM)**.
4. Когда SCIM имеет статус **Ativo**, интерфейс управления появится прямо в этой карточке.

<div id="designe-o-grupo-de-administrador-de-conta">
  ### Назначьте группу администраторов учётной записи
</div>

Настройте это в первую очередь. Блок **Группа администраторов учётной записи** вверху показывает, какая синхронизированная с IdP группа выполняет роль администратора учётной записи во всех ваших рабочих пространствах и имеет доступ к настройкам на уровне учётной записи, включая права на управление SCIM.

Выберите **Изменить**, чтобы назначить другую синхронизированную группу. Назначение группы — окончательное изменение: новая группа становится группой администраторов учётной записи, а роль администратора учётной записи у предыдущей группы отзывается. Поскольку администраторы учётной записи обладают широкими полномочиями, изменение необходимо подтвердить, прежде чем оно вступит в силу.

</Note>

<div id="visualize-e-gerencie-atribuies-de-workspace">
  ### Просмотр и управление назначениями рабочего пространства
</div>

На вкладке **Workspaces** перечислены все рабочие пространства вашей организации, а также назначенные им синхронизированные группы и роль каждой из них.

**Рабочее пространство по умолчанию** — отмеченное индикатором **По умолчанию** — служит основой для предоставления доступа: каждая синхронизированная группа автоматически получает в нём как минимум доступ уровня **Наблюдатель**, чтобы у участников всегда была отправная точка. Рабочее пространство становится рабочим пространством по умолчанию только после того, как его назначит администратор; до этого участники получают доступ только через созданные вами назначения групп.

* Используйте поле поиска, чтобы фильтровать рабочие пространства по названию.
* В каждой строке показаны **назначения групп** в виде меток формата *Группа · Роль* (например, *Engineering · Администратор*). Если у рабочего пространства больше назначений, чем помещается в одну строку, метка **+ N ещё** обозначает остальные.
* Меню **⋮** в строке позволяет редактировать назначения, а также назначить рабочее пространство рабочим пространством по умолчанию для организации или отменить этот статус.

<div id="atribua-grupos-a-workspaces-e-defina-funes">
  ### Назначение групп рабочим пространствам и настройка ролей
</div>

В меню **⋮** строки рабочего пространства выберите **Изменить назначения**, чтобы открыть диалоговое окно **Изменить доступ к рабочему пространству**. Здесь можно выбрать, какие синхронизированные группы имеют доступ к рабочему пространству и какую роль получит каждая из них:

* **Администратор** — полный административный доступ к настройкам и ресурсам рабочего пространства.
* **Участник** — может создавать и редактировать Apps в Replit.
* **Наблюдатель** — доступ к приложениям и развёртываниям только для чтения.
* **Гость** — может получать доступ только к приложениям, к которым ему предоставлен общий доступ.

Назначение группы администратора учётной записи заблокировано (обозначено значком замка), поскольку оно управляется в рамках назначения администратора учётной записи, а не на уровне рабочего пространства.

<div id="limitaes">
  ## Ограничения
</div>

* **Ваш IdP остаётся единым источником достоверных данных.** Добавление, удаление и подготовка участников, а также изменение состава групп выполняются в вашем провайдере идентификации. Replit управляет *назначениями* рабочих пространств и ролей для групп, уже существующих в синхронизированном каталоге.
* **Microsoft Entra ID не разворачивает вложенные группы.** Используйте невложенные группы или назначьте приложению Replit все группы, в которые пользователи входят напрямую, как описано в разделе [Использование невложенных групп с Microsoft Entra ID](#use-flat-groups-with-microsoft-entra-id).
* **Группу администраторов учётной записи можно изменить, но нельзя удалить.** Вы можете назначить другую группу администраторов учётной записи, но нельзя оставить организацию без такой группы.

<div id="perguntas-frequentes">
  ## Часто задаваемые вопросы
</div>

<div id="o-que-acontece-com-membros-que-j-tm-contas-no-replitcom-antes-de-o-scim-ser-configurado">
  ### Что происходит с участниками, у которых уже были учётные записи на replit.com до настройки SCIM?
</div>

После включения SCIM существующие участники делятся на две категории:

1. **Участники, provisioned через SCIM**:
   * Их роли обновляются в соответствии с ролями, назначенными в вашем IdP.
   * Добавлять и удалять этих участников, а также изменять их роли можно только через ваш IdP.
   * Для поддержания синхронизации разрешений администраторы больше не могут редактировать роли или приглашать новых участников в Replit.
2. **Участники, не provisioned через SCIM**:
   * Эти участники остаются без изменений и считаются устаревшими.
   * Их членство в организации и роли не удаляются автоматически, чтобы избежать случайного деактивирования.
   * При необходимости администраторы организации могут удалить устаревших участников через интерфейс Replit.

<Warning>
  После внедрения SCIM всеми участниками, provisioned вашим IdP, необходимо управлять через вашего провайдера идентификации для поддержания синхронизации. Только устаревших участников (тех, кто не provisioned через SCIM) можно деактивировать непосредственно в Replit.
</Warning>

<div id="quais-funes-podem-ser-provisionadas-com-o-scim">
  ### Какие роли можно назначать через SCIM?
</div>

Пользователям SCIM можно назначить четыре роли:

* **Администратор**: полный доступ к настройкам и ресурсам организации
* **Участник**: стандартный доступ для создания и редактирования Replit App
* **Гость**: ограниченный доступ для внешних участников; могут редактировать только приложения, к которым им явно предоставлен доступ
* **Наблюдатель**: доступ только для чтения к опубликованным приложениям

Сопоставление групп IdP с ролями Replit настраивается отдельно для каждого рабочего пространства в разделе [Доступ к рабочему пространству через SCIM](#managing-workspace-access). Например, группе «Engineering» можно назначить роль «Участник» в одном рабочем пространстве и роль «Наблюдатель» — в другом.

<div id="posso-adicionar-ou-remover-membros-pelo-acesso-ao-workspace-via-scim">
  ### Можно ли добавлять или удалять участников через доступ к рабочему пространству с помощью SCIM?
</div>

Нет. Управление членством и подготовкой учетных записей осуществляется в вашем провайдере идентификации. В этом интерфейсе настраивается сопоставление синхронизированных групп и участников с рабочими пространствами и ролями. Инструкции по повседневному управлению участниками вне SCIM см. в разделе [Управление участниками](/ru/pt/teams/identity-and-access-management/managing-members).

<div id="como-as-funes-diferem-dos-grupos">
  ### Чем роли отличаются от групп?
</div>

Группы синхронизируются с вашим IdP. Роли (администратор, Участник, Наблюдатель, Гость) определяют, что группа может делать в конкретном рабочем пространстве. Одна и та же группа может иметь разные роли в разных рабочих пространствах — например, быть **Участником** в одном рабочем пространстве и **Наблюдателем** в другом.

<div id="alterar-o-grupo-de-administrador-de-conta-afeta-outras-funes">
  ### Влияет ли изменение группы администраторов учётной записи на другие роли?
</div>

Назначение новой группы администраторов учётной записи изменяет только роль администратора учётной записи во всей организации. Другие назначения групп для рабочего пространства и связанные с ними роли не затрагиваются. Подробнее о роли администратора учётной записи см. в разделе [Администраторы учётных записей и рабочего пространства](/ru/pt/teams/identity-and-access-management/account-and-workspace-admins).
