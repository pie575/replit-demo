<div id="replitmd">
  ## Fonctionnement de `replit.md`
</div>

Agent crée d&#39;abord un fichier `replit.md` dans le répertoire racine de votre projet, en s&#39;appuyant sur des bonnes pratiques éprouvées. Ce fichier contient :

* Des informations de base sur le projet
* Des modèles de code recommandés
* Des préférences courantes pour ce type de projet

<YouTubeEmbed videoId="kYv525W-vaU" title="Personnaliser les réponses de Replit Agent" />

Lorsqu&#39;il traite vos demandes, Agent lit automatiquement le fichier `replit.md` et utilise son contenu pour :

* Comprendre l&#39;architecture et les conventions du projet
* Respecter vos modèles et styles de code préférés
* Utiliser le gestionnaire de paquets et les dépendances spécifiés

Agent peut également mettre à jour le fichier `replit.md` à mesure qu&#39;il en apprend davantage sur votre projet et qu&#39;il modifie votre application.

<Note>
  Vous pouvez personnaliser le comportement d&#39;Agent en modifiant le fichier `replit.md`.
</Note>

<div id="replitmd-2">
  ## Configurer `replit.md`
</div>

<div id="section">
  ### Génération automatique
</div>

Lorsque vous créez un projet avec Agent, un fichier `replit.md` est automatiquement généré selon des bonnes pratiques éprouvées. Ce fichier se trouve dans le répertoire racine du projet et contient :

* Informations de base sur le projet
* Modèles de code recommandés
* Préférences courantes pour ce type de projet

<div id="section-2">
  ### Création manuelle
</div>

Vous pouvez également créer ce fichier manuellement en ajoutant un fichier nommé `replit.md` dans le répertoire racine du projet. Agent détectera et utilisera automatiquement ce fichier dans les conversations suivantes.

<Note>
  Pour fonctionner correctement, `replit.md` doit se trouver dans le répertoire racine du projet.
</Note>

<div id="replitmd-3">
  ### Régénérer `replit.md`
</div>

Si le fichier `replit.md` est corrompu ou si vous souhaitez repartir de zéro :

1. Supprimez le fichier `replit.md` existant dans le répertoire racine du projet
2. Démarrez une nouvelle conversation avec Agent
3. Agent générera automatiquement un nouveau fichier `replit.md` en fonction du projet actuel

<div id="section-3">
  ## Bonnes pratiques
</div>

<div id="section-4">
  ### Soyez précis et clair
</div>

Formulez des instructions claires et précises afin qu’Agent comprenne exactement ce que vous souhaitez.

```markdown theme={null}
## Coding Style

- Use TypeScript for all new JavaScript files
- Prefer functional components with hooks over class components
- Use Tailwind CSS for styling, avoid inline styles
- Always include TypeScript types for function parameters and return values
```

Pour en savoir plus sur le formatage des prompts, consultez le [guide d’ingénierie des prompts d’Anthropic](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags).

<div id="section-5">
  ### Utiliser des exemples
</div>

Les exemples permettent à Agent de mieux comprendre vos préférences que des explications abstraites.

````markdown theme={null}
## Gestion des erreurs d’API

Lors de la création de points de terminaison d’API, utilisez toujours ce modèle de gestion des erreurs :

```javascript
app.get("/api/users", async (req, res) => {
  try {
    const users = await getUsersFromDatabase();
    res.json({ success: true, data: users });
  } catch (error) {
    console.error("Error fetching users:", error);
    res.status(500).json({
      success: false,
      error: "Failed to fetch users",
    });
  }
});
```
````

<div id="section-6">
  ### Définissez vos préférences de communication
</div>

Indiquez à Agent comment vous souhaitez recevoir les informations et les mises à jour.

```markdown theme={null}
## Style de communication

- Avant d’apporter des modifications, expliquez ce que vous allez faire et pourquoi
- Décomposez les tâches complexes en étapes claires
- Demandez des précisions si les exigences ne sont pas claires
- Expliquez brièvement vos décisions techniques
```

<div id="section-7">
  ### Préciser le contexte du projet
</div>

Aidez Agent à comprendre l’objectif et les contraintes de votre projet.

```markdown theme={null}
## Contexte du projet

Il s’agit d’une application de réseau social destinée aux amateurs de livres, où les utilisateurs peuvent :
- Créer des listes de lecture et partager des recommandations de livres
- Suivre d’autres lecteurs et voir leurs mises à jour
- Noter et rédiger des avis sur les livres qu’ils ont lus

Public cible : lecteurs occasionnels de 25 à 45 ans
Stack technique : frontend React, backend Node.js, base de données PostgreSQL
```

  ## Exemple de contenu pour `replit.md`

<div id="section-8">
  ### Projet d’application web
</div>

```markdown theme={null}
# Directives du projet MyApp

## Présentation du projet
Une application web de gestion des tâches développée avec React et Express.js.

## Préférences technologiques
- Frontend : React avec TypeScript, Tailwind CSS
- Backend : Express.js avec TypeScript
- Base de données : Neon PostgreSQL avec Drizzle ORM
- Gestionnaire de paquets : npm (et non yarn ou pnpm)

## Normes de codage
- Utiliser des composants fonctionnels avec des hooks
- Mettre en place des boundaries d'erreur appropriées
- Respecter les conventions des API REST pour les points de terminaison
- Utiliser des noms descriptifs pour les variables et les fonctions

## Style de communication
- Expliquer votre approche avant d’effectuer des modifications
- Ajouter des commentaires au code pour la logique complexe
- Poser des questions si les exigences sont ambiguës
```

<div id="section-9">
  ### Projet d’analyse de données
</div>

```markdown theme={null}
# Lignes directrices du projet d'analyse de données

## Contexte du projet
Analyse des données de comportement des clients pour identifier les tendances et les enseignements.

## Préférences technologiques
- Python avec Streamlit pour les applications web interactives
- pandas, numpy et matplotlib pour l'analyse de données

## Normes d'analyse
- Inclure une documentation claire pour toutes les étapes d'analyse
- Créer des visualisations interactives avec les composants Streamlit
- Valider la qualité des données avant l'analyse
- Exporter les résultats au format CSV et les afficher dans des tableaux Streamlit

## Style de communication
- Expliquer les méthodes statistiques et les hypothèses
- Fournir du contexte pour les constats et les recommandations
- Utiliser un langage clair et non technique pour les enseignements métier
- Créer des tableaux de bord interactifs pour les présentations aux parties prenantes
```

<div id="api">
  ### Projet de développement d’API
</div>

```markdown theme={null}
# Directives de développement d’API

## Présentation du projet
Création d’une API RESTful pour le backend d’une application mobile.

## Stack technologique
- Node.js avec Express.js
- MongoDB avec Mongoose
- JWT pour l’authentification
- Gestionnaire de paquets : npm

## Standards d’API
- Utiliser des codes d’état HTTP sémantiques
- Mettre en œuvre une validation appropriée des entrées
- Inclure une limitation du nombre de requêtes sur les points de terminaison publics
- Suivre la spécification OpenAPI pour la documentation

## Exigences de sécurité
- Valider toutes les entrées utilisateur
- Utiliser des variables d’environnement pour les données sensibles
- Mettre en œuvre des politiques CORS appropriées
- Inclure la journalisation des requêtes pour le débogage

## Approche de test
- Écrire des tests unitaires pour tous les points de terminaison
- Inclure des tests d’intégration pour les flux critiques
- Utiliser Jest comme framework de test
```

<div id="replitmd-5">
  ## Combiner la recherche sur le Web et `replit.md`
</div>

Agent peut effectuer des recherches sur le Web pour trouver des informations, bibliothèques et solutions à jour. En les associant au fichier `replit.md`, vous bénéficiez à la fois de connaissances actualisées et d&#39;instructions propres au projet.

<div id="section-13">
  ### Bonnes pratiques pour intégrer la recherche sur le Web
</div>

**Indiquez précisément ce qu’Agent doit rechercher.**

```markdown theme={null}
## Préférences de recherche
- Vérifiez toujours les dernières versions des dépendances avant de proposer des mises à jour
- Recherchez les bonnes pratiques actuelles en matière de sécurité
- Recherchez des techniques récentes d’optimisation des performances adaptées à notre stack technologique
```

**Indiquez à Agent comment exploiter les connaissances externes.**

```markdown theme={null}
## Directives pour la recherche externe
- Lorsque vous suggérez de nouvelles bibliothèques, assurez-vous de leur compatibilité avec notre stack existante
- Adaptez les exemples externes à nos normes de codage et à la structure de notre projet  
- Vérifiez que les solutions suggérées fonctionnent dans notre environnement de publication
```

**Voici un exemple de demande combinant les deux approches.**
&quot;Recherche les dernières techniques d&#39;optimisation des performances de React 18 et implémente-les en suivant les modèles de composants définis dans `replit.md`&quot;

Cette approche vous permet d&#39;obtenir des solutions à jour, adaptées à votre projet.

<div id="section-14">
  ## Limitations
</div>

<div id="section-15">
  ### Limites de taille et de contenu des fichiers
</div>

Il n&#39;existe pas de limite stricte du nombre de caractères pour `replit.md`, mais les fichiers très volumineux risquent de ne pas être entièrement traités. Pour de meilleurs résultats, gardez `replit.md` concis et centré sur l&#39;essentiel.

<div id="section-16">
  ### Exigences concernant le répertoire racine
</div>

`replit.md` doit se trouver dans le répertoire racine du projet. Agent ne détecte pas automatiquement les fichiers situés dans les sous-répertoires.

<div id="section-17">
  ### Portée du contexte
</div>

`replit.md` fournit du contexte aux conversations avec Agent, mais ne s’applique pas automatiquement aux autres outils d’IA.

<div id="section-18">
  ## Étapes suivantes
</div>

Prêt à personnaliser Agent pour votre projet ?

1. **Commencez simplement** : créez un fichier `replit.md` de base contenant vos principales préférences
2. **Itérez et améliorez** : mettez à jour `replit.md` au fil de votre travail avec Agent
3. **Partagez les bonnes pratiques** : réutilisez les configurations `replit.md` efficaces dans des projets similaires
4. **Surveillez les résultats** : vérifiez dans quelle mesure Agent suit vos instructions et ajustez-les en conséquence
