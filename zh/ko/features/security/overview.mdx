在 Replit 上发布后，项目即可接收真实流量。Replit 的安全工具可帮助您发现漏洞、使用 Agent 修复已批准的问题，并保留审计所需的证据。

<div id="section">
  ## 安全为何重要
</div>

* 已发布的项目可通过互联网访问，包括公开路由和 API。
* 现代项目依赖大量软件包，发布后仍可能出现新的 CVE。
* AI 生成的代码同样需要进行安全审查，尤其是涉及身份验证、数据库查询、密钥和数据处理时。
* 合规计划通常要求提供依赖项清单、漏洞跟踪和缓解措施的证明。

<div id="section-2">
  ## 入门
</div>

* 正在安装软件包？[软件包防火墙](/zh/ko/features/security/package-firewall)会在安装时阻止恶意依赖项，默认已启用。
* 正在处理单个项目？请使用 [Project Security Center](/zh/ko/features/security/project-security-center)。
* 正在审计整个工作区？请使用 [工作区安全中心](/zh/ko/features/security/workspace-security-center)。
* 需要选择开发资源的运行位置？请阅读[工作区地理位置](/zh/ko/features/collaboration/workspace-geography)。如需选择已发布项目的运行位置，请阅读[项目地理位置](/zh/ko/features/publishing/project-geography)。
* 需要了解术语定义？请阅读[安全概念](/zh/ko/features/security/concepts)。

Replit 的安全工具覆盖应用生命周期的不同阶段，并可协同工作。

* **安装时**：[软件包防火墙](/zh/ko/features/security/package-firewall)会在恶意或已遭入侵的软件包下载前将其拦截。
* **安装后**：[自动依赖项扫描](/zh/ko/features/security/project-security-center#automatic-dependency-scans)会检测新披露的 CVE，Auto-Protect 可为其准备 Agent 补丁。
* **发布前**：[Security Agent](/zh/ko/features/security/agent-security-scans)会审计代码库，发现代码、依赖项和隐私相关漏洞。

大多数扫描工作都遵循相同的流程：扫描、审查结果、使用 Agent 修复、重新发布，并在需要时导出证据。

<div id="section-3">
  ## 安全功能在产品中的位置
</div>

<div id="section-4">
  ### 项目中
</div>

打开 **Security** 面板，查看项目级发现的问题、运行 Agent 安全扫描，并在发布前检查依赖项中的漏洞。

使用 [Agent 安全扫描](/zh/ko/features/security/agent-security-scans)审查源代码。如果还需要从外部测试正在运行的应用，请使用 [Level 3 黑盒渗透测试](/zh/ko/features/security/black-box-pen-tests)。

<div id="section-5">
  ### 工作区内
</div>

在主页侧边栏中选择 **Security**，即可查看整个项目的漏洞，根据暴露程度确定发现的问题的优先级，并跟踪工作区级别的扫描历史记录。

<div id="section-6">
  ### 在 Publishing 和设置中
</div>

* 在 **Publish** &gt; **Advanced** 中，您可以启用 **Block publishing of critical vulnerabilities**，阻止发布存在严重 (critical) 发现的问题的部署。
* 在 **设置** &gt; **Account** &gt; **Advanced** 中，设置 Auto-Protect 的严重性阈值，以便 Agent 针对依赖项制定缓解措施。
