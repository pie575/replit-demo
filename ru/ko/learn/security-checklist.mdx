Это руководство содержит подробный чек-лист, который поможет вашим приложениям, созданным с помощью вайб-кодинга, соответствовать передовым практикам безопасности.

Хотя Replit [по умолчанию](/ru/ko/features/security/overview) предоставляет множество функций безопасности, важно понимать и внедрять дополнительные меры защиты в соответствии с требованиями конкретного приложения.

<div id="section-2">
  ## Безопасность фронтенда
</div>

<AccordionGroup>
  <Accordion title="Используйте HTTPS везде" icon="lock">
    Replit по умолчанию использует HTTPS для всех приложений. Беспокоиться не о чем!
  </Accordion>

  <Accordion title="Валидация и очистка входных данных" icon="shield-check">
    Чтобы предотвратить атаки межсайтового скриптинга (XSS), всегда проверяйте и очищайте пользовательский ввод:

    ```javascript theme={null}
    // Плохой пример: прямое использование пользовательского ввода
    element.innerHTML = userInput;

    // Хороший пример: очистка ввода перед использованием
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    Спросите у Agent:

    ```
    Помоги проверить и очистить вводимые данные для защиты от XSS-атак
    ```
  </Accordion>

  <Accordion title="Не храните конфиденциальные данные в браузере" icon="eye-slash">
    Для хранения конфиденциальной информации, например ключей API, следует использовать секреты Replit.

    Не передавайте и не храните секреты в следующих местах:

    * Локальное хранилище
    * Хранилище сессии
    * JavaScript на стороне клиента
    * Файлы cookie без надлежащих атрибутов безопасности

    Спросите у Agent:

    ```
    Помоги убрать конфиденциальные данные из браузера. Всё ли я делаю правильно?
    ```
  </Accordion>

  <Accordion title="Защита от CSRF" icon="shield">
    Реализуйте в формах защиту от межсайтовой подделки запросов (CSRF):

    ```javascript theme={null}
    // Пример реализации CSRF-токена
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    Спросите у Agent:

    ```
    Помоги реализовать CSRF-токены в формах
    ```
  </Accordion>
</AccordionGroup>

  ## Безопасность бэкенда
</div>

<AccordionGroup>
  <Accordion title="Основы аутентификации" icon="key">
    При реализации аутентификации:

    * По возможности используйте Replit Auth
    * Если создаёте собственную аутентификацию, используйте проверенные библиотеки
    * Не храните пароли в открытом виде

    Попросите Agent:

    ```
    Помогите реализовать аутентификацию в моём приложении с помощью Replit Auth
    ```
  </Accordion>

  <Accordion title="Проверка прав доступа" icon="user-lock">
    Всегда проверяйте права доступа перед выполнением операций:

    ```javascript theme={null}
    // Пример проверки прав доступа
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    Попросите Agent:

    ```
    Помогите реализовать проверку прав доступа в моём приложении
    ```
  </Accordion>

  <Accordion title="Защита эндпоинтов API" icon="shield">
    Обезопасьте эндпоинты API:

    * Добавьте аутентификацию для чувствительных эндпоинтов
    * Настройте корректную конфигурацию CORS
    * Рассмотрите ограничение частоты запросов

    Попросите Agent:

    ```
    Как правильно аутентифицировать эндпоинты в моём приложении?
    ```
  </Accordion>

  <Accordion title="Предотвращение SQL-инъекций" icon="database">
    Agent по умолчанию использует ORM для предотвращения SQL-инъекций. Если вы пишете собственные запросы к базе данных:

    ```javascript theme={null}
    // Неверно: конкатенация строк в запросе
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // Верно: параметризованный запрос с использованием ORM
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="Заголовки безопасности" icon="code">
    Добавьте в приложение важные заголовки безопасности:

    ```html theme={null}
    <!-- в index.html или через бэкенд -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    Вы можете просканировать свой сайт на [securityheaders.com](https://securityheaders.com) и получить рекомендации.

    Попросите Agent:

    ```
    Можете добавить заголовки безопасности в моё приложение?
    ```
  </Accordion>
</AccordionGroup>

<div id="section-4">
  ## Регулярные практики безопасности
</div>

<AccordionGroup>
  <Accordion title="Регулярно обновляйте зависимости" icon="arrow-rotate-right">
    Регулярно проверяйте, нет ли устаревших пакетов с уязвимостями:

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="Корректная обработка ошибок" icon="exclamation">
    Не раскрывайте конфиденциальную информацию в сообщениях об ошибках:

    ```javascript theme={null}
    // Плохой пример: раскрытие конфиденциальных деталей
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // Хороший пример: общее сообщение об ошибке
    catch (err) {
      console.error(err); // Логирование во внутренних системах
      res.status(500).send('An error occurred');
    }
    ```

    Попросите Agent:

    ```
    Помоги реализовать корректную обработку ошибок в моём приложении
    ```
  </Accordion>

  <Accordion title="Безопасные файлы cookie" icon="cookie">
    При использовании cookie:

    * Устанавливайте флаг HttpOnly, чтобы запретить доступ из JavaScript
    * Используйте атрибут Secure, чтобы требовать HTTPS
    * Применяйте атрибут SameSite для защиты от CSRF

    Попросите Agent:

    ```
    Помоги сделать cookie в моём приложении безопасными
    ```
  </Accordion>

  <Accordion title="Безопасность загрузки файлов" icon="upload">
    Если ваше приложение разрешает загрузку файлов:

    * Ограничивайте типы и размеры файлов
    * По возможности проверяйте файлы на наличие вредоносного ПО
    * Храните файлы в объектном хранилище Replit
    * Генерируйте новые имена файлов вместо тех, что указал пользователь

    Попросите Agent:

    ```
    Помоги сделать загрузку файлов в моём приложении безопасной
    ```
  </Accordion>

  <Accordion title="Ограничение частоты запросов" icon="clock">
    Реализуйте ограничение частоты запросов для API-эндпоинтов, особенно связанных с аутентификацией:

    ```javascript theme={null}
    // Пример middleware для ограничения частоты запросов
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 минут
      max: 100 // ограничить каждый IP до 100 запросов за windowMs
    });

    app.use('/api/', limiter);
    ```

    Попросите Agent:

    ```
    Помоги реализовать ограничение частоты запросов в моём приложении
    ```
  </Accordion>
</AccordionGroup>
