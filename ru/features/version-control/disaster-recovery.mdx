Replit автоматически создает резервные копии вашего Git-репозитория, чтобы вы могли восстановиться после таких проблем, как поврежденная папка `.git` или утраченная история коммитов. Эта система работает в фоновом режиме, поэтому ваша работа защищена без дополнительных действий с вашей стороны.

<div id="how-it-works">
  ## Как это работает
</div>

Каждое App в Replit автоматически создаёт защищённую резервную копию вашего репозитория Git. Когда Replit Agent вносит изменения в код или вы публикуете приложение, они автоматически синхронизируются с этой копией. Если ваш локальный репозиторий Git будет повреждён или станет непригодным для использования, вы сможете восстановить из резервной копии всю историю коммитов.

<Info>
  Удалённый репозиторий резервной копии называется `gitsafe-backup` и автоматически управляется Replit. Вам ничего не нужно настраивать — всё уже работает в фоновом режиме.
</Info>

<div id="viewing-your-backup-history">
  ## Просмотр истории резервных копий
</div>

Проще всего просмотреть историю коммитов в [Git Pane](/ru/features/workspace-tools/git-interface). Откройте её из раздела Tools в Project Editor — там отображается полная история коммитов, включая все чекпоинты Agent. Этот способ подходит для большинства случаев и не требует выполнения команд.

Если нужно напрямую проверить remote gitsafe-backup, используйте Shell:

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

Здесь отображается полная история коммитов, включая все чекпоинты Agent и коммиты, созданные вручную. С её помощью можно убедиться, что ваша работа сохранена в резервной копии, или найти конкретный коммит для восстановления.

<div id="recovering-from-git-issues">
  ## Восстановление после проблем с Git
</div>

Если вы столкнулись с ошибками Git или ваш репозиторий повреждён, начните с [Git pane](/ru/features/workspace-tools/git-interface). С его помощью можно устранить большинство распространённых проблем — например, вернуться к предыдущему коммиту или получить изменения из удалённого репозитория — без команд Shell.

Если Git pane не может помочь (например, если папка `.git` полностью повреждена), воспользуйтесь приведёнными ниже инструкциями для Shell.

<div id="check-if-backup-is-available">
  ### Проверьте наличие резервной копии
</div>

Сначала убедитесь, что remote репозитория резервной копии существует:

```bash theme={null}
git remote -v
```

Найдите `gitsafe-backup` в выводе. Если он есть, можно приступать к восстановлению.

<div id="restore-your-repository">
  ### Восстановление репозитория
</div>

<Warning>
  В ходе этого процесса текущая папка `.git` будет заменена резервной копией. Рабочие файлы останутся без изменений, но локальная история Git будет заменена данными из резервной копии.
</Warning>

<Steps>
  <Step title="Сохраните текущую конфигурацию Git">
    Создайте резервную копию файла конфигурации Git на случай, если у вас есть пользовательские настройки:

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Клонируйте резервный репозиторий">
    Создайте временный клон из резервной копии:

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Замените папку Git">
    Переместите повреждённую папку `.git` и замените её резервной копией:

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Восстановите конфигурацию">
    Восстановите конфигурацию Git из резервной копии:

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

После выполнения этих шагов выполните `git status`, чтобы убедиться, что репозиторий работает корректно.

<div id="troubleshooting-common-issues">
  ## Устранение распространённых проблем
</div>

<div id="fatal-repository-not-found-or-backup-remote-missing">
  ### «fatal: repository not found» или отсутствует удалённый репозиторий резервной копии
</div>

Для старых проектов система резервного копирования может быть недоступна. Если вам нужна помощь с восстановлением старого проекта, обратитесь в службу поддержки.

<div id="recovery-didnt-include-recent-commits">
  ### При восстановлении не были включены последние коммиты
</div>

Резервные копии синхронизируются после каждого коммита Agent. Если вы внесли изменения, но не закоммитили их, они не попадут в резервную копию. Проверьте рабочую директорию на наличие незафиксированных файлов.

<div id="git-operations-are-slow-or-hanging">
  ### Операции Git выполняются медленно или зависают
</div>

Если операции Git перестали выполняться, возможно, остался устаревший файл блокировки. Его можно безопасно удалить:

```bash theme={null}
rm -f .git/index.lock
```

<div id="preventing-data-loss">
  ## Предотвращение потери данных
</div>

Хотя система резервного копирования автоматически сохраняет историю Git, вы можете дополнительно защитить свою работу:

* **Чаще создавайте коммиты**: Создавайте небольшие коммиты регулярно, чтобы ваш прогресс постоянно сохранялся в резервных копиях
* **Используйте чекпоинты**: При работе с [Replit Agent](/ru/features/agent/overview) чекпоинты автоматически создают коммиты на ключевых этапах
* **Подключите GitHub**: Для особенно важных проектов [подключите App к GitHub](/ru/build/import-from-providers), чтобы обеспечить дополнительное резервное копирование
