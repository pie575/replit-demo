Auth (сокращение от **аутентификация**) — это то, что даёт приложению понятие «пользователь». Без аутентификации все посетители анонимны, и приложение не отличает одного человека от другого. С аутентификацией каждый посетитель входит в систему, приложение знает, кто это, и может хранить данные, относящиеся именно к нему: бронирования, сохранённые автомобили, настройки, прогресс.

Добавив аутентификацию, вы сможете:

* Хранить данные для каждого пользователя — бронирования, настройки, контент, историю.
* Закрывать функции за входом в систему (оформление заказа, страница профиля, панель администратора).
* Персонализировать работу с приложением по имени, роли, тарифу или прошлым действиям.
* Отслеживать активность и использование по людям, а не по сеансам.

<div id="replitauth">
  ## Как работает Auth в приложениях Replit
</div>

В Replit есть два встроенных варианта аутентификации. Оба настраиваются с помощью Agent — не нужно отдельно регистрироваться в какой-либо панели управления или копировать ключи OAuth.

* **[Replit Auth](/ru/ja/features/auth-and-identity/authentication)** — пользователи входят под своей существующей **учётной записью Replit**. Страница входа оформлена в фирменном стиле Replit. Достаточно попросить Agent добавить её — никакой настройки не требуется.
* **[Clerk Auth](/ru/ja/features/auth-and-identity/clerk-auth)** — у приложения есть собственный **тенант Clerk**. Пользователи создают учётные записи в *вашем* приложении, а не в Replit. Вы сами управляете брендингом, способами входа и внешним видом экрана входа.

Оба варианта берут всю тяжёлую работу на себя — страница входа, сессии, безопасная обработка паролей, вход через соцсети, — а коду вашего приложения остаётся лишь спросить: «Какой пользователь сейчас вошёл?».

<div id="replit-auth-vs-clerk-auth">
  ## Replit Auth vs. Clerk Auth
</div>

|                                  | Replit Auth                                                              | Clerk Auth                                                           |
| -------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| **Учётные записи пользователей** | Вход с помощью аккаунта Replit                                           | Создание аккаунта в самом приложении (аккаунт Replit не нужен)       |
| **Брендинг**                     | Страница входа с брендингом Replit                                       | Полностью настраивается — название, значок и цвета вашего приложения |
| **Учётные данные SSO**           | Используется общее приложение OAuth от Replit                            | Собственные учётные данные OAuth для каждого провайдера              |
| **Окружения**                    | Одно окружение                                                           | Разделение окружений разработки и продакшена                         |
| **Лучше всего подходит для**     | Быстрой настройки, прототипов и приложений, где брендинг Replit приемлем | Брендированных приложений, профессиональных и коммерческих продуктов |

Если вы создаёте прототип или внутренний инструмент, Replit Auth — самый быстрый вариант. Если же вы создаёте продукт с собственной айдентикой бренда, особенно для клиентов или коммерческого использования, лучше подойдёт Clerk Auth.

<div id="section">
  ## Добавление аутентификации в приложение
</div>

Выбирать заранее не обязательно — можно начать с одного варианта и позже перейти на другой. Быстрее всего просто сказать Agent, какой из них использовать:

* *«Добавь в приложение вход. Используй Replit Auth»*
* *«Добавь в приложение вход. Используй Clerk Auth»*
