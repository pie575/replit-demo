[Проект](/ru/features/projects-and-artifacts/projects) — это контейнер для всего, что вы создаёте в Replit. В проекте хранятся ваши дизайны, приложения, слайды, данные и все результаты работы.
[Артефакты](/ru/features/projects-and-artifacts/artifacts) — это публикуемые результаты внутри проекта: веб-приложения, мобильные приложения, презентации и видео.

Если вы создаёте сразу несколько продуктов, есть два варианта:

* добавить несколько артефактов в один проект,
* или создать отдельные проекты.

Выбор зависит от того, используют ли ваши приложения общие данные, логику и единый жизненный цикл развёртывания. В этом руководстве рассказывается, когда стоит держать артефакты в одном проекте, а когда создавать отдельные.

<div id="what-artifacts-share-in-a-project">
  ## Что артефакты используют совместно в рамках проекта
</div>

Когда [артефакты](/ru/features/projects-and-artifacts/artifacts) находятся в одном [проекте](/ru/features/projects-and-artifacts/projects), у них автоматически становятся общими:

* **База данных**: один артефакт записывает данные — остальные сразу их читают
* **Бэкенд и API**: общая серверная логика без дублирования кода
* **Файловое хранилище**: изображения, документы и загруженные файлы доступны всем артефактам
* **развёртывание**: при публикации всё выкладывается синхронно, одним разом

Это значит, что вам не нужно настраивать связи или дублировать код между артефактами. Но это также значит, что нельзя опубликовать один артефакт, не опубликовав остальные.

<div id="quick-guide">
  ## Краткое руководство
</div>

Ниже приведены основные сценарии, которые стоит учесть при выборе: добавить артефакт в существующий проект или создать отдельный.

| **Несколько артефактов в одном проекте**                                             | **Отдельные проекты**                                                                    |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Приложения используют общие данные и бэкенд                                        | Приложения не имеют общей логики или данных                                              |
| Вы хотите публиковать всё вместе                                                   | Вам нужны независимые циклы публикации                                                   |
| Они дополняют друг друга (например, клиентское приложение и панель администратора) | Это несвязанные продукты или продукты для разных клиентов                                |
| Вы хотите, чтобы изменения в одном артефакте автоматически отражались в остальных   | Проект рассчитан на короткий срок — например, лендинг для кампании или сайт мероприятия |

<div id="examples">
  ## Примеры
</div>

<div id="same-project-web-app-mobile-app-for-one-product">
  ### Один проект: веб-приложение + мобильное приложение для одного продукта
</div>

Ресторан создаёт веб-приложение, в котором посетители просматривают меню, и мобильное приложение, в котором сотрудники управляют заказами. Оба подключены к одной базе данных с позициями меню, заказами и информацией о клиентах.

**Почему один проект:** приложения используют одни и те же данные и общий бэкенд. Когда клиент оформляет заказ в веб-приложении, сотрудники сразу видят его в мобильном приложении.

<div id="same-project-app-admin-dashboard-investor-pitch-deck">
  ### **Один проект**: приложение + панель администратора + презентация для инвесторов
</div>

Стартап создаёт свой основной продукт, внутреннюю админ-панель для управления контентом и слайд-презентацию для привлечения инвестиций — всё в одном проекте.
Стартап создаёт свой основной продукт, внутреннюю админ-панель для управления контентом и слайд-презентацию для привлечения инвестиций — всё в одном проекте.

**Почему один проект:** админ-панель работает с теми же данными, которые отображает приложение, а презентация может использовать актуальные метрики из общего бэкенда.

<div id="separate-projects-two-unrelated-client-apps">
  ### **Отдельные проекты**: два несвязанных клиентских приложения
</div>

Фрилансер создаёт интернет-магазин для одного клиента и систему бронирования для другого.

**Почему нужны отдельные проекты:** у приложений нет ни общих данных, ни общей логики. Каждому клиенту нужна независимая публикация, и изменения в одном приложении не должны затрагивать другое.

<div id="separate-projects-campaign-landing-page-alongside-a-main-product">
  ### **Отдельные проекты**: лендинг кампании рядом с основным продуктом
</div>

У вас есть продакшн-приложение, работающее круглый год, и временный лендинг для маркетинговой кампании.

**Почему стоит разделить проекты:** у страницы кампании свой жизненный цикл — вы запустите её, покрутите несколько недель и отключите. Отдельный проект не будет захламлять основной продукт и позволит публиковать или удалять страницу независимо.

<div id="frequently-asked-questions">
  ## Часто задаваемые вопросы
</div>

<Accordion title="Можно ли переместить артефакт в другой проект?">
  Пока нет. Если артефакт нужно вынести отдельно, создайте новый [проект](/ru/features/projects-and-artifacts/projects) и попросите Agent пересобрать его там.
</Accordion>

<Accordion title="Есть ли ограничение на количество артефактов в одном проекте?">
  Один проект может содержать не более 7 артефактов. Ограничение связано с тем, что каждый дополнительный артефакт потребляет больше памяти, из-за чего Preview может работать медленнее. Если вам нужно больше артефактов, создайте ещё один [проект](/ru/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Можно ли опубликовать только один артефакт из проекта?">
  Пока нет. При публикации всё публикуется сразу. Если публиковать нужно по отдельности, используйте разные проекты.
</Accordion>
