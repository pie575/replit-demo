컨텍스트는 AI 모델이 다음 응답을 생성할 때 사용하는 정보입니다. 컨텍스트 관리란 적절한 시점에 적절한 정보를 모델에 제공하는 것을 말합니다.

이것이 중요한 이유는 AI가 여러분의 의도만으로 동작하지 않기 때문입니다. AI는 컨텍스트 윈도우에 담긴 텍스트, 파일, 스크린샷, 로그, 예시, 대화 기록을 바탕으로 동작합니다.

<div id="what-is-a-context-window">
  ## 컨텍스트 윈도우란?
</div>

AI 모델이 한 번에 고려할 수 있는 정보량에는 한계가 있습니다. 이 한계를 컨텍스트 윈도우라고 합니다.

컨텍스트 윈도우에는 다음이 포함될 수 있습니다:

* 사용자가 입력한 프롬프트
* 대화의 이전 메시지
* 모델이 볼 수 있는 파일이나 코드
* 오류 메시지와 로그
* 스크린샷, 이미지, 디자인 참고 자료
* `replit.md`와 같은 프로젝트 지침
* 이전 단계에서 나온 도구 실행 결과

모델은 이 컨텍스트를 바탕으로 다음에 무엇을 생성할지 결정합니다.

<div id="why-context-windows-matter">
  ## 컨텍스트 창이 중요한 이유
</div>

중요한 세부 정보가 컨텍스트에 없으면 모델이 추측으로 답할 수 있습니다. 반대로 관련 없는 정보가 컨텍스트에 너무 많으면 모델이 엉뚱한 부분에 집중할 수 있습니다.

예를 들어, 다음 프롬프트는 컨텍스트를 거의 제공하지 않습니다:

```text theme={null}
가입 페이지를 개선해 줘.
```

이 프롬프트는 유용한 컨텍스트를 제공합니다:

```text theme={null}
대기자 명단 등록을 고민 중인 초보 창업자를 위해 가입 페이지를 개선해 줘.
현재 입력 항목은 그대로 두고, 양식 위쪽의 가치 제안을 더 명확하게 다듬어 줘.
가격 섹션은 변경하지 마.
```

두 번째 프롬프트는 해당 페이지가 누구를 위한 것인지, 무엇을 개선하고 무엇을 유지해야 하는지, 그리고 어디까지가 작업 범위 밖인지를 모델에 알려줍니다.

<div id="context-window-sizes-vary">
  ## 컨텍스트 윈도우 크기는 모델마다 다릅니다
</div>

AI 모델마다 처리할 수 있는 컨텍스트의 양이 다릅니다. 컨텍스트 윈도우가 클수록 한 번에 더 많은 텍스트를 고려할 수 있지만, 크다고 항상 좋은 것은 아닙니다. 모든 세부 정보를 대화에 쏟아붓기보다는 관련성 있는 컨텍스트를 제공하는 것이 더 중요합니다.

공개된 컨텍스트 윈도우 크기의 예시는 다음과 같습니다.

| 모델 계열             | 컨텍스트 윈도우 예시       |
| ----------------- | ----------------- |
| GPT-4.1           | 최대 100만 tokens    |
| Claude Sonnet 4.5 | 최대 200,000 tokens |
| Gemini 2.5 Pro    | 최대 100만 tokens    |

이 수치는 시간이 지나면서 바뀌며, 모든 제품이 모델의 전체 limit을 그대로 제공한다는 보장도 없습니다. 하지만 실질적인 교훈은 변하지 않습니다. 중요한 정보를 명확하고 간결하게 유지하세요.

<div id="types-of-context">
  ## 컨텍스트의 유형
</div>

| 컨텍스트 유형      | 예시                                                 |
| --------------- | -------------------------------------------------- |
| **목표**          | &quot;이 landing page에서 waitlist 신청을 받아야 합니다.&quot; |
| **대상**          | &quot;바쁜 식당 사장님을 위한 것입니다.&quot;                    |
| **constraints** | &quot;현재 color 팔레트와 양식 필드를 그대로 유지하세요.&quot;        |
| **비목표**         | &quot;아직 payments는 추가하지 마세요.&quot;                 |
| **예시**          | 스크린샷, mockup, 샘플 데이터, 경쟁사 페이지 등.                   |
| **project 상태**  | 현재 파일, 컴포넌트, 오류 메시지 또는 사용자 flow.                   |
| **완료 기준**       | &quot;방문자가 양식을 제출하면 감사 메시지가 표시됩니다.&quot;           |

<div id="fresh-context-and-persistent-context">
  ## 새로운 컨텍스트와 지속되는 컨텍스트
</div>

어떤 컨텍스트는 현재 conversa 안에 두는 것이 적합합니다. 특정 변경을 요청하거나, 한 가지 문제를 디버깅하거나, 방금 나온 결과에 feedback을 줄 때가 그렇습니다.

반면 어떤 컨텍스트는 project 전체에 걸쳐 유지되어야 합니다. 코딩 스타일, brand guidelines, 명명 conventions, 반복해서 적용되는 제품 규칙, 그리고 Agent가 여러 작업 session에 걸쳐 기억해야 할 constraints에는 지속되는 컨텍스트를 사용하세요. Replit에서는 [replit.md](/ko/features/project-setup/replit-dot-md)가 Agent에게 지속적인 project 컨텍스트를 제공하는 한 가지 방법입니다.

<div id="when-context-gets-noisy">
  ## 컨텍스트가 지저분해질 때
</div>

대화가 길어지면 초점이 흐려질 수 있습니다. 하나의 thread에 서로 관련 없는 결정이 너무 많이 섞이면, Agent가 이미 의미 없어진 예전 컨텍스트를 참고할 수 있습니다.

다음과 같은 경우에는 새 thread를 시작하세요.

* 관련 없는 다른 기능으로 전환할 때
* 대화에 폐기된 direction이 많이 쌓였을 때
* Agent가 예전 constraints를 계속 적용할 때
* 새로운 영역에 대해 깔끔한 plan을 세우고 싶을 때

새로 시작할 때는 Agent가 무엇이 여전히 중요한지 알고 있으리라 가정하지 말고, 핵심 컨텍스트를 요약해서 전달하세요.

```text theme={null}
컨텍스트: 이 project는 지역 피트니스 코치를 위한 waitlist 앱입니다.
주요 flow는 landing page → 가입 양식 → 확인 메시지 순입니다.
이번 thread에서는 확인 메시지와 follow-up 문구만 개선해 주세요.
```

<div id="common-misconceptions">
  ## 흔한 오해
</div>

* **&quot;컨텍스트는 많을수록 좋다.&quot;** 양보다 관련성이 중요합니다. 관련 없는 컨텍스트가 너무 많으면 모델이 핵심을 놓칠 수 있습니다.
* **&quot;모델은 모든 것을 완벽하게 기억한다.&quot;** AI가 주어진 컨텍스트를 활용하기는 하지만, 중요한 constraints는 필요할 때마다 다시 짚어 주는 것이 좋습니다.
* **&quot;컨텍스트는 텍스트뿐이다.&quot;** 스크린샷, 파일, 데이터, designs, 로그, 예시 모두 컨텍스트가 될 수 있습니다.
