---
title: "端口"
description: "了解如何在 Replit App 中配置和管理网络端口。"
---

由于 Replit 在云环境中运行你的项目，端口在 Replit 上的工作方式与在本地计算机上有所不同。 (如果你想先了解 TCP 端口的基础知识，[可以从这里开始](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/)。) 

在一台计算机上，只有一层端口管理：程序指定一个监听端口，当来自互联网的流量到达计算机上的该端口时，就会被路由到相应的进程。

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="计算机" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

其中 `0.0.0.0` 是地址，也就是主机。如果某个进程在 `0.0.0.0` 上监听，就意味着它会监听所有网络接口——也就是说，当另一台计算机 (在互联网上) 向你计算机的 IP 地址发送请求时，该进程就能收到。换句话说，监听 0.0.0.0 意味着这些进程可以通过公共互联网访问 (前提是你的计算机已联网) 。

大多数编程框架在开发阶段*不会*监听 `0.0.0.0`，因为出于隐私和安全考虑，你未必希望正在进行的工作对外公开。它们会改为监听另一个地址——`127.0.0.1`，也称为 `localhost`。这意味着只有本机才能向该端口发出请求。

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="localhost 端口仅在托管它们的计算机上可见。" width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

在 Replit 上，若要让运行中的进程可以在 webview 中或通过外部请求访问，就必须为它设置一个**外部端口**。这是因为进程通常使用的“内部端口”仅在 Replit 提供的隔离 (沙盒) 云环境内部可见。该内部端口需要连接到一个可从外部访问的端口，才能把正确的流量发送到你的程序。即使你的进程监听在通常可公开访问的端口 (如 0.0.0.0) 上，仍然需要将其绑定到一个外部端口。

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="外部端口将流量转发到程序所监听的内部端口。" width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit 通过将外部端口绑定到特定的内部端口来实现这一点——例如在上图中，外部端口 `:80` 绑定到内部端口 `:3000`。这意味着 Replit App 在 80 端口收到的任何流量都会转发到内部的 3000 端口。

该配置记录在 .replit 配置文件的 [[ports]] 部分中。

默认情况下，Replit 会将你打开的第一个端口绑定到默认外部端口 80，这样该进程就能通过域名直接访问，而无需附带端口号 (例如 customdomain.com/ 而不是 customdomain.com:3000/) 。之后打开的其他内部端口会被绑定到其他可用的外部端口 (完整列表见下文) 。

<div id="porta-padro">
  ## 默认端口
</div>

:80 是 http 流量的“默认端口”，因此发送到根域名的 http 流量会自动路由到 80 端口。正因如此，URL 中不会显示 80 端口的端口路径。而非 `80` 的端口则会出现在域名路径中 (例如 customdomain.com:4200/) 。 (Replit 默认提供 TLS，因此严格来说流量会走 443 端口，也就是 https 的默认端口。在实际使用中，你可以将两者视为等同。)

<div id="publicao">
  ## 发布
</div>

Autoscale 和 Reserved VM 类型的发布仅支持对外暴露一个端口，且对应的内部端口不能使用 `localhost`。如果你暴露了多个端口，或者暴露的这个端口绑定在 localhost 上，发布的应用将会失败。要确保 Autoscale 发布按预期运行，一个简便的方法是：在配置中移除所有端口的 `externalPort` 条目，*仅保留*你希望从互联网访问的那个服务所对应的端口。

<div id="depurao">
  ## 调试
</div>

某些功能未按预期工作，一个常见原因是：端口配置看起来没问题，但程序实际监听的却是另一个端口。例如，如果你的配置是：

```
[[ports]]
internalPort = 3000
externalPort = 80
```

这样，来自互联网的 80 端口流量就会转发到内部的 3000 端口。但如果你的程序实际上并没有监听 3000 端口，而是监听了其他端口 (比如 8080) ，看起来就像完全没有流量进来一样。如果你在代码里改了端口却没有同步修改配置中对应的端口，或者把某个项目的配置直接复制粘贴到了另一个项目，就可能出现这种情况。

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="程序可能会更改其监听的端口。" width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

每种框架监听的默认端口各不相同——例如 Flask 使用 5000，react 使用 3000，laravel 使用 8000。请确认配置的端口是否正确！

<div id="preferncias">
  ## 偏好设置
</div>

当你的 Replit App 中有端口被打开时，Replit 会自动将其绑定到可用的外部端口，并把绑定关系记录到 .replit 配置文件中。

但对于在 localhost 上打开的内部端口，默认不会这样处理，因为运行在 localhost 上的服务通常假定只有运行该进程的同一台计算机才能访问它 (localhost 端口仅对运行该进程的同一台计算机可见) 。因此，这类服务往往不如那些一开始就按面向公共互联网设计的服务安全。

你随时可以覆盖这一行为：把想要暴露的端口的 `exposeLocalhost` 配置选项设置为 `true`。

如果你希望默认*始终*暴露 localhost 端口，可以在“用户设置”工具中将“端口自动转发”设为 “All ports”。

如果你希望*从不*为打开的端口自动生成配置，而是手动管理整个 Replit App 的端口配置，可以将其设为 “never”。

<div id="portas-suportadas">
  ## 支持的端口
</div>

首次打开端口时，Replit App 会将端口 80 设为默认的外部端口。Replit App 还可以将 3000、3001、3002、3003、4200、5000、5173、6000、6800、8000、8008、8080、8081 端口作为额外的外部端口对外暴露。

端口 22 和 8283 供内部使用，无法转发。

<div id="configurao-ports-do-replit">
  ## .replit 的 `[[ports]]` 配置
</div>

类型：`{localPort, externalPort, exposeLocalhost}`

`[[ports]]` 配置用于指定将哪个 HTTP 端口作为应用的 web 输出对外开放。默认情况下，任何绑定到 0.0.0.0 的 HTTP 端口都会作为你的 Replit App 的 web 输出对外开放。

在 .replit 文件中新增 [[ports]] 条目，即可在不覆盖默认端口的前提下开放额外的端口。其中必须同时指定 localPort 和 externalPort。如下方定义所示，在 .replit 文件中添加多个 [[ports]] 条目即可开放多个额外端口。

<div id="localport">
  ### localPort
</div>

决定 Replit 将该端口绑定到哪个外部端口。

<div id="externalport">
  ### externalPort
</div>

指定将该本地端口映射到哪个端口，作为可公开访问的端口对外暴露。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

如果你希望*永远不*对外暴露某个端口，可以保留 `localPort` 配置，但不添加 `externalPort`：

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

决定使用 `localhost` 的内部端口是否可以绑定到外部端口。可以为 `true`、`false` 或空值。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
