<div id="getting-started">
  ## Начало работы
</div>

Replit — это облачная среда разработки, в которой можно писать и запускать приложения с любым фреймворком или стеком. Для создания пользовательского шаблона есть два рекомендуемых способа:

1. **[Импортируйте](https://replit.com/import) из Git-провайдера** — импортируйте существующий стартовый стек (или стек, соответствующий вашим предпочтениям) из GitHub, GitLab или Bitbucket.
2. **Создайте форк шаблона Blank** — создайте форк [шаблона Blank](https://replit.com/@replit/Nothing?v=1), чтобы начать с нуля в полностью пустой среде разработки.

Пользователи успешно создавали шаблоны для Rust, Python, Java, C++ и многих других стеков — если что-то вообще запускается, оно может запускаться в Replit.

<Tip>
  При создании первых шаблонов рекомендуем работать с **командой Field Engineering** Replit. У неё большой опыт настройки пользовательских шаблонов для самых разных стеков, и она готова помочь. Чтобы связаться с командой, обратитесь к своему Account Executive.
</Tip>

Пользовательские шаблоны позволяют администраторам Enterprise создавать предварительно настроенные отправные точки, которые отображаются прямо в поле ввода Agent у каждого участника организации. Когда разработчик выбирает пользовательский шаблон, Agent создаёт его форк и использует конфигурацию, инструкции и навыки шаблона, чтобы направлять всю последующую работу. Дополнительная настройка не требуется.

<Note>
  Пользовательские шаблоны доступны исключительно на тарифе **Enterprise**. Закреплять шаблоны и управлять ими могут только администраторы организации.
</Note>

<div id="how-custom-templates-work">
  ## Как работают пользовательские шаблоны
</div>

Пользовательский шаблон — это обычное Replit App в вашей организации, **закреплённое в поле ввода Agent**. Когда разработчик выбирает такой шаблон:

1. Agent создаёт новое приложение, форкая шаблон (копируются все файлы)
2. Agent пропускает этап планирования и сразу приступает к созданию приложения
3. Файл шаблона `custom_instruction/instructions.md` добавляется в контекст Agent
4. Пользовательские [навыки](/ru/features/agent/skills) из `.agents/skills/` обнаруживаются и становятся доступными
5. Файл [`replit.md`](/ru/features/project-setup/replit-dot-md) обеспечивает постоянный контекст проекта

Это означает, что стандарты, шаблоны и инструменты вашей организации заложены с самого первого взаимодействия.

<div id="template-file-structure">
  ## Структура файлов шаблона
</div>

Ниже приведена рекомендуемая структура пользовательского шаблона:

```
my-template/
├── .replit                              # Конфигурация App (команды запуска, порты, модули)
├── replit.md                            # Память Agent: обзор проекта и предпочтения
├── custom_instruction/
│   └── instructions.md                  # Инструкции компании, добавляемые в промпт Agent
├── .agents/
│   └── skills/
│       └── my-skill/
│           └── SKILL.md                 # Пользовательские навыки, которые Agent может вызывать по мере необходимости
└── ...                                  # Остальная структура репозитория
```

Каждый файл имеет своё назначение. В следующих разделах описано, как настроить каждый из них.

<div id="set-up-a-custom-template">
  ## Настройте пользовательский шаблон
</div>

<div id="create-the-base-app">
  ### Создайте базовое приложение
</div>

Создайте новый Replit App в своей организации. Подготовьте Project со всеми файлами, зависимостями и конфигурацией, необходимыми вашим разработчикам для начала работы. В частности:

* Каркас исходного кода (компоненты, утилиты, файлы конфигурации)
* Предустановленные зависимости (`package.json`, `requirements.txt` и т. д.)
* Конфигурация среды в [файле `.replit`](/ru/replit-app/configuration)

<div id="configure-shared-secrets">
  ### Настройте общие Secrets
</div>

Если ваш шаблон использует ключи API, токены или другие учетные данные, добавьте их в **Secrets** шаблона (на панели Tools) перед закреплением. Когда разработчик создает новое App из шаблона, все секреты автоматически копируются в него, поэтому можно сразу приступить к работе, не настраивая учетные данные вручную.

Документируйте каждый секрет в `custom_instruction/instructions.md` (или в отдельном навыке), чтобы разработчики знали, какие секреты доступны и для чего используется каждый ключ.

<Warning>
  Secrets копируются при форке и не синхронизируются динамически. Если вы смените ключ или добавите новый секрет в шаблон, ранее созданные форки не обновятся. В таких App разработчикам нужно вручную добавить или обновить Secrets.
</Warning>

<div id="write-custom-instructions">
  ### Напишите пользовательские инструкции
</div>

Создайте файл `custom_instruction/instructions.md` в корне проекта. Это самый важный файл в вашем шаблоне: он объясняет Agent, как ваша организация разрабатывает ПО.

<Warning>
  Имя папки должно быть `custom_instruction` (в единственном числе), а не `custom_instructions`.
</Warning>

Agent напрямую добавляет содержимое этого файла в свой системный промпт с преамбулой, обозначающей его как рекомендации от компании. Напишите файл в Markdown и включите:

* **Архитектурные паттерны**: Как должны быть структурированы ваши приложения
* **Стандарты написания кода**: Соглашения об именовании, правила организации файлов, требования к линтингу
* **Использование компонентов**: Какие библиотеки и компоненты использовать, а каких избегать
* **Паттерны API**: Как вызывать бэкенд-сервисы, обрабатывать аутентификацию и управлять ошибками
* **Требования к тестированию**: Какие тесты требуются и как их запускать
* **Рекомендации по развертыванию**: Конфигурация для разных сред и процессы развертывания

````markdown theme={null}
# Company Engineering Standards

## Architecture
All web applications use React with TypeScript. Use functional components
with hooks exclusively. State management uses Zustand for local state
and React Query for server state.

## Component Library
Use our internal design system package `@acme/ui`. Never use raw HTML
elements for buttons, inputs, forms, or modals — always use the
corresponding component from `@acme/ui`.

Import components like this:
```tsx
import { Button, TextField, Modal } from '@acme/ui';
```

## API Integration
All API calls go through the `@acme/api-client` package. Never use
raw fetch or axios directly. Authentication is handled automatically
by the client.

## Testing
Every component must have a corresponding test file. Use Vitest
for unit tests and Playwright for integration tests.
````

**Ограничение размера**: Для содержимого установлено мягкое ограничение примерно в 25 КБ. Содержимое сверх этого лимита может постепенно обрезаться. По мере увеличения объёма инструкций переносите подробные справочные материалы в [навыки](/ru/features/agent/skills) в `.agents/skills/`, а не храните всё в `instructions.md`. Навыки загружаются по мере необходимости, поэтому они не учитываются в ограничении размера инструкций и позволяют сосредоточить основные инструкции на правилах высокого уровня.

<div id="add-custom-skills">
  ### Добавление пользовательских навыков
</div>

Создавайте навыки в каталоге `.agents/skills/` для специализированных рабочих процессов, которым должен следовать Agent. Каждый навык — это каталог с файлом `SKILL.md`, содержащим YAML-метаданные.

```
.agents/skills/
├── use-design-system/
│   └── SKILL.md
├── api-integration/
│   └── SKILL.md
└── run-tests/
    └── SKILL.md
```

В frontmatter каждого `SKILL.md` должны быть указаны `name` и `description`:

```markdown theme={null}
---
name: use-design-system
description: Use when building UI components. Provides component patterns, theming rules, and accessibility requirements for the Acme design system.
---

# Acme Design System

## Available components

- `Button` — Primary, secondary, and ghost variants
- `TextField` — Text input with validation support
- `Modal` — Dialog overlay with focus trapping
...
```

| Поле          | Обязательно | Описание                                                                           |
| ------------- | ----------- | ---------------------------------------------------------------------------------- |
| `name`        | Да          | Не более 64 символов. Только строчные буквы, цифры и дефисы.                       |
| `description` | Да          | Не более 1 024 символов. Описывает, что делает навык и когда его использовать.     |
| `enabled`     | Нет         | По умолчанию — `true`. Установите `false`, чтобы отключить навык без его удаления. |

**Как загружаются навыки**: Agent видит в своём промпте только `name` и `description`. Он читает полное содержимое `SKILL.md` по запросу, когда навык релевантен текущей задаче. Поэтому `description` крайне важно — сформулируйте его так, чтобы оно соответствовало сценариям, в которых Agent должен использовать навык.

Навыки также могут включать вспомогательные файлы рядом с `SKILL.md`:

```
.agents/skills/use-design-system/
├── SKILL.md
├── references/
│   └── component-api.md
└── assets/
    └── theme-tokens.json
```

Подробнее о навыках см. в разделах [Agent Skills](/ru/features/agent/skills) и [Use a skill](/ru/build/use-agent-skills).

<div id="configure-replitmd">
  ### Настройте replit.md
</div>

Добавьте в `replit.md` в корне проекта обзор архитектуры вашего шаблона. Этот файл всегда загружается в контекст Agent и служит постоянной памятью проекта.

Файл должен содержать следующие четыре раздела:

```markdown theme={null}
# Overview
Task management application built with React, TypeScript, and the Acme
design system. Uses Express.js backend with PostgreSQL.

# User Preferences
- Use TypeScript for all files
- Prefer functional components with hooks
- Follow Acme coding standards

# System Architecture
- Frontend: React + TypeScript + @acme/ui
- Backend: Express.js + TypeScript
- Database: PostgreSQL with Drizzle ORM
- Auth: Acme SSO via @acme/auth

# External Dependencies
- @acme/ui: Internal design system
- @acme/api-client: API integration layer
- @acme/auth: Authentication SDK
```

Agent обновляет `replit.md` по мере развития проекта. Если файл становится больше примерно 4 000 токенов, Agent автоматически его обобщает, чтобы он оставался кратким и полезным.

Подробнее см. в разделе [replit.md](/ru/features/project-setup/replit-dot-md).

<div id="pin-the-template-to-your-organization">
  ### Закрепите шаблон для своей организации
</div>

Когда шаблон будет готов:

1. Перейдите к App-шаблону в своей организации
2. Откройте меню действий App (меню с тремя точками)
3. Выберите **Pin to Agent input box**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий App с пунктом Pin to Agent input box" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Закреплять и откреплять шаблоны могут только администраторы организации — участники роли `system_admins`.
</Note>

Установите для участников уровень доступа **Read-only**, чтобы они могли просматривать и использовать закреплённый шаблон, но не редактировать его.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалог приглашения, в котором для участника выбран доступ Read-only" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Теперь у каждого участника вашей организации под полем ввода Agent отображается шаблон в виде выбираемой кнопки. Чтобы удалить его, откройте то же меню и выберите **Unpin from Agent input box**.

<div id="control-template-access">
  ### Управление доступом к шаблону
</div>

При закреплении шаблон становится виден всем участникам организации. Чтобы предоставить доступ только определённым пользователям, нажмите кнопку **Пригласить** в App шаблона и выберите конкретные [группы или отдельных пользователей](/ru/teams/identity-and-access-management/groups-and-permissions). Так вы сможете ограничить круг команд или пользователей, которые могут просматривать и форкать шаблон, не закрепляя его в общем поле ввода организации.

<div id="what-happens-when-a-builder-selects-a-template">
  ## Что происходит, когда разработчик выбирает шаблон
</div>

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Шаблон отображается в виде выбираемой метки в поле ввода Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

Когда участник организации выбирает закреплённый шаблон в поле ввода Agent:

1. **Форк**: создаётся новое приложение — копия шаблона со всеми его файлами
2. **Пропуск планирования**: Agent пропускает начальный диалог планирования и сразу переходит в режим Build
3. **Загрузка инструкций**: `custom_instruction/instructions.md` считывается и добавляется в системный промпт Agent как инструкции, предоставленные компанией
4. **Обнаружение навыков**: навыки в `.agents/skills/` обнаруживаются и перечисляются в контексте Agent для загрузки по мере необходимости
5. **Загрузка контекста проекта**: `replit.md` считывается и добавляется в контекст Agent (или создаётся автоматически, если отсутствует)
6. **Наследование конфигурации**: файл `.replit`, зависимости и все файлы шаблона переносятся в новое приложение

Разработчик может сразу отправлять Agent промпты с конкретными требованиями, а Agent действует в рамках ограничений, заданных шаблоном.

<div id="how-files-work-together">
  ## Как файлы взаимодействуют
</div>

Каждый файл конфигурации выполняет свою роль:

| Файл                                 | Назначение                                    | Когда Agent его читает                  | Может ли Agent его изменять             |
| ------------------------------------ | --------------------------------------------- | --------------------------------------- | --------------------------------------- |
| `custom_instruction/instructions.md` | Стандарты и правила Organization              | Всегда (добавляется в системный промпт) | Нет                                     |
| `.agents/skills/*/SKILL.md`          | Специализированные рабочие процессы и шаблоны | По мере необходимости (когда актуально) | Да (Agent также может создавать навыки) |
| `replit.md`                          | Обзор и настройки Project                     | Всегда (добавляется в системный промпт) | Да (Agent обновляет его со временем)    |
| `.replit`                            | Конфигурация среды выполнения                 | При настройке App                       | Да                                      |

**Ключевое различие**: `custom_instruction/instructions.md` — неизменяемый авторитетный источник организационных стандартов. `replit.md` — постоянно обновляемый документ, который Agent ведёт по мере развития Project. Навыки — справочные материалы, загружаемые по мере необходимости для конкретных рабочих процессов.

<div id="best-practices">
  ## Рекомендации
</div>

<div id="keep-instructions-focused">
  ### Формулируйте инструкции по существу
</div>

Включите в `custom_instruction/instructions.md` наиболее важные шаблоны. Сосредоточьтесь на следующем:

* Решения, которые сложно изменить (архитектура, модели данных)
* Шаблоны, которые должны быть единообразными (использование компонентов, соглашения API)
* Стандарты, о которых разработчик может не знать (внутренние библиотеки, командные соглашения)

Не включайте журналы изменений, детали реализации и информацию, которая часто меняется.

<div id="write-discoverable-skill-descriptions">
  ### Пишите описания навыков, которые легко находить
</div>

Поле `description` в метаданных `SKILL.md` помогает Agent определить, когда загружать навык. Пишите описания, соответствующие задачам, для которых навык применим:

```yaml theme={null}
# Хороший вариант — указано, когда использовать
description: Use when building forms or handling user input. Provides validation patterns, error display conventions, and accessible form layouts.

# Неудачный вариант — слишком расплывчато
description: Form utilities and helpers.
```

<div id="organize-skills-by-workflow">
  ### Организуйте навыки по рабочим процессам
</div>

Группируйте навыки по рабочим процессам, а не по техническим категориям:

| Подход                     | Пример                                       |
| -------------------------- | -------------------------------------------- |
| **По рабочему процессу**   | `build-a-form`, `connect-to-api`, `add-auth` |
| **По технической области** | `react-utils`, `api-helpers`, `auth-config`  |

Такой подход помогает Agent находить нужные навыки в нужный момент.

<div id="iterate-on-your-template">
  ### Совершенствуйте шаблон
</div>

Шаблоны становятся лучше по мере использования. Когда команда начнёт работать с шаблоном:

1. Отслеживайте типичные ошибки Agent и добавляйте соответствующие указания в `instructions.md`
2. Создавайте новые навыки, когда Agent успешно решает задачу, — сохраняйте найденное решение
3. Обновляйте базовые зависимости и конфигурации по мере развития вашего стека
4. Проверяйте изменения: создайте новое приложение из шаблона и убедитесь, что всё работает как ожидается

<div id="template-updates-and-existing-apps">
  ### Обновления шаблона и существующие приложения
</div>

Изменения в приложении-шаблоне применяются только к **новым** приложениям, созданным на его основе. Существующие приложения, ранее созданные как форки шаблона, являются независимыми копиями и не получают обновлений.
