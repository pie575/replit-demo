完成后，Velocity 客户将支付可退还的押金来预订车辆，并在取车时支付余款。

你已为 Velocity 添加了登录功能和数据库。现在，把它变成真正的车辆预订业务：在**预订时收取可退还的押金**以保留车辆，然后在**取车时收取尾款**。Replit 通过 Stripe 处理付款——你无需自行编写任何 Stripe 代码。

<div id="decide-the-deposit-and-balance-amounts">
  ## 确定押金和尾款金额
</div>

在让 Agent 开始 Build 之前，先确定计费规则：

* **预订时支付的押金：**收取固定金额，还是总价的百分比？固定 $500 更便于说明；20% 则会随车价变化。
* **取车时支付的尾款：**剩余租车费用，在客户领取钥匙时收取。
* **退款期限：**最晚可在何时取消，仍能退回押金？48 小时是常见的默认设置。

在本指南中，Velocity 会在预订时收取固定 $500 的可退押金，在取车时收取尾款；如果客户在取车前超过 48 小时取消，则全额退款。请根据实际业务情况进行调整。

<div id="test-the-full-flow-in-test-mode">
  ## 在测试模式下测试完整流程
</div>

Stripe 提供了一张专用测试卡，让你无需花费真实资金即可模拟真实支付：`4242 4242 4242 4242`、任意未来到期日和任意 3 位 CVC。

1. 在 Preview 中登录 Velocity，并预订下周六至周日的车辆。
2. 在结账流程中，你应该会看到“今日支付押金：$500”和“取车时支付尾款：$1,900” (或根据你的计算结果显示相应金额) 。
3. 使用 `4242` 测试卡支付押金。随后应跳转至确认页面，显示押金已支付，且已保存用于支付尾款的付款方式。
4. 从“我的预订”中打开该预订，然后通过管理员操作或取车操作收取尾款。确认尾款显示为已支付。
5. 创建第二个预订，然后在距离取车时间超过 48 小时时取消。押金应退回测试卡 (你可以在 Stripe 测试模式仪表板中验证) 。
6. 创建第三个预订，并在距离取车时间不足 48 小时时取消。应保留押金，并向客户明确说明原因。
7. 使用 Stripe 的拒付测试卡 (`4000 0000 0000 0002`) 尝试结账。预订不应被确认，客户应看到清晰的失败提示。

如果押金支付成功但预订未被确认，请告诉 Agent：

<AiPrompt>
  Velocity 的 Stripe 测试押金支付成功，但预订没有显示为已确认。<br />
  将押金支付成功事件关联到数据库中的预订状态。<br />
  告诉我如何通过另一个测试预订进行验证。
</AiPrompt>

<div id="switch-to-live-payments-when-youre-ready">
  ## 准备好后切换到正式收款
</div>

测试模式供你测试使用；正式模式则面向实际付款的真实客户。Velocity 准备就绪后：

1. 在 Stripe 中，从测试模式切换到正式模式，并复制**正式**密钥。
2. 在应用的设置中，用正式密钥替换测试密钥。
3. 通过 Agent chat 再次发布 Velocity。
4. 打开公开 URL，使用你自己的真实银行卡预订一辆低价测试车辆，并确认押金和尾款流程都能端到端正常运行。

在广泛分享公开 URL 之前，先进行一次真实银行卡测试。Velocity 现在可以接受真实付款的预订。

<div id="need-further-help">
  ## 还需要帮助？
</div>

* **押金支付成功，但预订未确认：**请 Agent 将 Stripe 的成功事件关联到数据库中的预订状态。
* **测试模式可用，但正式模式不可用：**请确保已在 App 的设置中将测试密钥替换为正式密钥。
* **想要一次性预付全款，而不是支付押金后再付余额：**告诉 Agent 将 Velocity 改为在预订时一次性全额付款。
* **想要按月订阅定价 (每月可使用车队) ：**Replit 也支持 RevenueCat——请 Agent 使用它替代 Stripe。
