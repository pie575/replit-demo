<div id="adicionar-cabealhos-de-resposta">
  ## Добавление заголовков ответа
</div>

Пользовательские **заголовки ответа** позволяют добавлять HTTP-заголовки к запросам, соответствующим определённым путям.
Заголовок ответа — это пара «имя-значение», которая сообщает браузеру, как
обрабатывать запрошенное содержимое.

Например, вы можете задать заголовок `Access-Control-Allow-Origin`, чтобы указать, к каким доменам браузер может обращаться для этой страницы.
Чтобы создать такую запись, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

Этот заголовок ответа включает следующие параметры:

* **path**: шаблон пути URL, которому соответствуют запрашиваемые ресурсы
* **name**: имя HTTP-заголовка
* **value**: значение HTTP-заголовка

В файл `.replit` можно добавить несколько записей `deployment.responseHeaders`.

Чтобы изменения конфигурации вступили в силу, опубликуйте свой Replit App заново.

<div id="criar-uma-pgina-404-personalizada">
  ## Создание собственной страницы 404
</div>

Собственная страница 404 отображается, когда пользователи запрашивают URL-пути, которым не соответствует ни один файл или правило в вашем опубликованном приложении.

Чтобы добавить собственную страницу 404, поместите её содержимое в файл с именем `404.html` в корневом каталоге вашего Replit App.

При попытке перейти по несуществующему URL-пути пользователи увидят отрисованный HTML вашей страницы 404.

<div id="definir-rewrites-de-caminho-de-url">
  ## Настройка правил перезаписи URL-путей
</div>

Вы можете настроить правила перезаписи URL, чтобы изменить путь запроса до того, как его обработает ваше приложение Replit.
Исходный URL остаётся видимым в браузере, но сервер загружает ресурс, указанный в правиле перезаписи.

Например, можно указать, что все запросы, начинающиеся с `/app`, загружают содержимое файла `/app/index.html`.
Чтобы создать это правило, добавьте следующее в файл `.replit` в корневом каталоге вашего приложения Replit:

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**: шаблон пути URL, которому соответствуют запрашиваемые ресурсы
* **to**: переписанный путь, указывающий на файл в вашем статическом развёртывании.

В файл `.replit` можно добавить несколько записей `deployment.rewrites`.
Сервер обрабатывает записи в указанном порядке и игнорирует дубликаты.

Чтобы изменения конфигурации вступили в силу, необходимо повторно опубликовать ваш Replit App.

В следующих разделах описаны ограничения правил перезаписи URL.

<div id="correspondncia-de-caminho">
  ### Сопоставление путей
</div>

К параметрам `from` и `to` в правилах перезаписи применяются следующие ограничения:

* Сопоставления должны быть точными, если не используется `*`
* `*` соответствует оставшейся части пути
* `*` допустим только в конце пути
* При использовании `*` в параметре `from` его можно указать и в параметре `to`, чтобы обозначить соответствующую часть пути

Например, если файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

Когда пользователь перейдёт по пути `/v1/about-us.html`, перезапись будет отдавать файл, расположенный по пути `/v2/about-us.html`.

<div id="shadowing">
  ### Перекрытие
</div>

Перекрытие возникает, когда правило перезаписи соответствует URL-пути, который также соответствует файлу в вашем статическом развёртывании.
В этом случае облачный сервер игнорирует правило перезаписи и отдает файл напрямую.

Например, предположим, что ваше опубликованное приложение содержит следующие файлы:

* `index.html`
* `about.html`

Файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

Когда пользователь переходит по адресу `/register.html`, сервер перенаправляет запрос на `/index.html` и отдаёт этот файл.
Однако если пользователь переходит по адресу `/about.html`, сервер игнорирует правило перезаписи и отдаёт файл `about.html`, поскольку он существует в вашем статическом развёртывании.

<div id="restries-de-domnio">
  ### Ограничения домена
</div>

Перезаписи работают только для запросов к основному домену вашего статического развёртывания и могут
перенаправлять только на файлы в его пределах.
