Um app é um software projetado para realizar uma tarefa específica para uma pessoa ou grupo específico.

Os apps podem ser simples ou complexos. Uma calculadora, formulário de reserva, dashboard, ferramenta interna, experiência móvel, marketplace e portal do cliente são todos apps se ajudarem alguém a fazer algo útil.

## Apps são código que roda em infraestrutura

Todo app é composto de duas coisas que funcionam juntas:

* **Código** — as instruções que descrevem o que o app faz: a interface que alguém vê, a lógica que responde a cliques e entradas, e as regras de como os dados circulam.
* **Infraestrutura** — as máquinas, redes, armazenamento e serviços nos quais o código roda para que outras pessoas possam acessá-lo de um navegador ou celular.

Escrever o código é a parte que a maioria das pessoas imagina quando pensa em "criar um app". A infraestrutura é tudo o que precisa estar no lugar para que esse código funcione de fato para os usuários: um servidor para executá-lo, um banco de dados para armazenar informações, um domínio para que as pessoas possam encontrá-lo, segurança para protegê-lo e uma forma de atualizá-lo sem quebrar o que já funciona.

No Replit, você descreve o que quer em linguagem natural. O Agent escreve o código, e o Replit fornece a infraestrutura — hospedagem, bancos de dados, secrets, domínios e implantações — para que você possa publicar um app funcional sem configurar nada disso por conta própria.

## Por que criar um app?

Você pode criar um app quando as ferramentas existentes quase funcionam, mas não completamente.

Um app é útil quando:

* Você quer um fluxo de trabalho personalizado
* Você atingiu os limites de uma planilha, formulário ou template
* Você precisa de um processo repetível
* Você quer testar a demanda por uma ideia
* Você quer que colegas, clientes ou usuários interajam com algo que você controla

Por exemplo, um empreendedor pode criar um app de lista de espera para testar a demanda. Um profissional de marketing pode criar uma landing page de campanha com um formulário. Um analista de dados pode criar um dashboard que facilita a exploração de uma planilha.

## Apps resolvem um problema focado

Os melhores primeiros apps são focados. Eles resolvem um problema claro para um público claro.

Em vez de começar com:

```text theme={null}
Uma plataforma para gerenciar todo o meu negócio.
```

Comece com:

```text theme={null}
Uma página onde os clientes podem solicitar um orçamento de catering e receber uma mensagem de confirmação.
```

A versão menor é mais fácil de criar, testar, publicar e melhorar.

## Apps e artefatos

No Replit, um app é um tipo de artefato. Um artefato é uma saída publicável de um projeto.

Os artefatos podem incluir:

* Apps web
* Apps móveis
* Dashboards de dados
* Apresentações de slides
* Vídeos animados
* Designs
* Experiências 3D

Os apps geralmente são interativos. Eles frequentemente permitem que as pessoas enviem informações, visualizem dados, façam login, façam escolhas ou concluam um fluxo de trabalho. Outros artefatos, como apresentações de slides ou vídeos animados, podem focar mais em apresentação ou narrativa.

## O que torna um app real?

Um app começa a parecer real quando alguém pode usá-lo fora da sua cabeça.

Isso geralmente significa:

* Tem um propósito claro
* Alguém pode concluir a ação principal
* Você pode testá-lo no Preview
* Você pode publicá-lo em uma URL compartilhável
* Você pode melhorá-lo após o feedback

A primeira versão não precisa de todos os recursos. Ela precisa funcionar bem o suficiente para aprender com ela.

## Equívocos comuns

* **"Um app precisa ser grande."** Muitos apps valiosos são pequenas ferramentas para um trabalho específico.
* **"Um app precisa ser público."** Alguns apps são ferramentas privadas para você, sua equipe ou seus clientes.
* **"Um app precisa ser perfeito antes de ser publicado."** Publicar uma primeira versão focada ajuda você a aprender o que melhorar.
