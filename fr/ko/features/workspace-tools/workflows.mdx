Il s’agit de séquences d’étapes réutilisables et personnalisables que vous pouvez exécuter dans votre application Replit. Elles peuvent être aussi simples que l’exécution de `python main.py` ou aussi complexes qu’un processus en plusieurs étapes.

  <img src="/assets/mirror/workflows-pane-e7d5e4251006.png" alt="Image" width="525" height="622" data-path="images/workflows/workflows-pane.png" />
</Frame>

Exemples de cas d’utilisation :

* Exécuter plusieurs services en parallèle (par exemple, front-end + back-end)
* Exécuter des fichiers ou des commandes de manière séquentielle (par exemple, exécuter le linter → exécuter les tests, compiler → exécuter le code)

Pour commencer à [créer un workflow](#creating-workflows), utilisez le menu de la barre latérale d’outils pour accéder au volet Flux de travail, ou utilisez `Command + K` pour rechercher le volet Flux de travail.

<div id="section">
  ## Types de tâches disponibles
</div>

Trois types de tâches sont actuellement disponibles : `Execute Shell Command`, `Install Packages` et `Run Workflow`.

<div id="execute-shell-command">
  ### Exécuter une commande Shell
</div>

`Execute Shell Command` enregistre des commandes shell et les exécute dans le même environnement que la fenêtre Shell. Ce type de tâche permet d’exécuter des fichiers individuels jusqu’à

```text theme={null}
python main.py
```

Ils couvrent un large éventail de cas d’utilisation, y compris l’exécution de requêtes complexes enregistrées dans une base de données :

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Installer des paquets
</div>

`Install Packages` détecte automatiquement les dépendances du projet et installe les paquets nécessaires à l’aide du système intégré de gestion des dépendances de Replit. Pour en savoir plus sur la façon dont UPM détermine les paquets à installer dans votre projet, consultez [Gestion des dépendances](/fr/ko/features/project-setup/dependency-management#the-universal-package-manager).

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow` vous permet d’exécuter un autre workflow depuis le workflow actuel. Vous pouvez ainsi réutiliser et combiner des workflows afin de créer des workflows plus complexes.

Exemple de cas d’utilisation :

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="Image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

En utilisant ce type de tâche pour créer des dépendances entre les workflows, lorsque vous modifiez un workflow, les autres workflows qui y font référence utilisent automatiquement les dernières modifications. Notez que les appels de workflows profondément imbriqués sont soumis à une limite de profondeur.

<div id="section-2">
  ## Modes d’exécution des Workflows
</div>

Workflows propose deux modes d’exécution : séquentiel et parallèle.

<div id="section-3">
  ### Exécution séquentielle
</div>

L’exécution séquentielle exécute chaque tâche dans l’ordre défini, attend qu’elle soit terminée avant de passer à l’étape suivante et interrompt l’exécution de la séquence si une tâche du workflow échoue.

Vous pouvez utiliser ce mode, par exemple, pour définir des commandes logiquement liées, comme récupérer les dernières modifications de la branche principale, puis rebaser la branche actuelle sur celle-ci :

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="Image" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="section-4">
  ### Exécution parallèle
</div>

L’exécution parallèle lance chaque tâche indépendamment des autres tâches du workflow. Si l’une d’elles échoue, l’exécution des autres ne s’arrête pas.

Par exemple, utilisez ce mode pour exécuter un projet full-stack nécessitant le démarrage des serveurs frontend et backend :

<div id="section-5">
  ## Créer un workflow
</div>

Cliquez sur le bouton `+ New Workflow` pour créer un workflow dans le volet Flux de travail. Donnez-lui un nom descriptif, sélectionnez le mode d’exécution approprié, puis ajoutez des tâches. Vous pouvez réorganiser les tâches par glisser-déposer dans l’ordre souhaité.

<div id="run">
  ## Associer un workflow au bouton Run
</div>

Vous pouvez également associer un workflow au bouton Run afin de remplacer son comportement par défaut (voir [Configuration de l’application Replit](/fr/ko/features/project-setup/configuration)). Pour conserver la commande d’exécution par défaut configurée dans `.replit`, sélectionnez l’option « Run Replit App » dans le menu déroulant.

Lorsque vous cliquez sur le bouton Run, le workflow sélectionné dans le menu déroulant s’exécute. Pour modifier le workflow exécuté par le bouton Run, sélectionnez le workflow souhaité dans le menu déroulant.
