<div id="section-2">
  ### Analyse de sécurité pendant le build
</div>

Dans le cadre de la révision du code, Agent vérifie désormais que les fichiers modifiés ne comportent pas de problèmes de sécurité courants. Cette analyse automatique par Semgrep recherche des schémas à haut risque et des secrets codés en dur, afin qu’Agent puisse résoudre les problèmes potentiels détectés avant de terminer une tâche.

Pour en savoir plus, consultez [Analyse de sécurité pendant le build](/fr/ja/features/security/project-security-center#security-scan-while-you-build).

<div id="section-4">
  ### Régénérer les identifiants de la base de données de production
</div>

Vous pouvez désormais régénérer les identifiants de la base de données de production concernée depuis l’outil **Base de données**. Replit met à jour les identifiants et, si l’application dispose de déploiements pris en charge en cours d’exécution, lance un redéploiement afin qu’ils continuent d’utiliser les nouveaux identifiants. Mettez à jour les outils externes qui utilisent l’ancienne chaîne de connexion.

<div id="sso">
  ### Créer avec le SSO
</div>

Les utilisateurs Pro peuvent désormais configurer le SSO Enterprise pour les applications Replit qui utilisent [Clerk Auth](/fr/ja/features/auth-and-identity/clerk-auth). Demandez à Agent d’apporter les modifications d’authentification nécessaires, puis Agent vous dirigera vers le tableau de bord Clerk. Vous pourrez y connecter Okta ou Microsoft Entra ID via OIDC ou SAML. Les connexions SSO Enterprise sont gratuites jusqu’au 1er octobre 2026. Après cette date, des frais de transfert Clerk s’appliqueront. Cette fonctionnalité sera bientôt disponible pour Enterprise.

<div id="section-6">
  ### Déplacer des projets entre les espaces de travail
</div>

Depuis la liste des **projets**, vous pouvez déplacer des projets entre les espaces de travail d&#39;équipe liés au même compte de facturation. Le transfert s&#39;effectue en arrière-plan et est irréversible. Les secrets de compte associés ne sont pas transférés avec le projet ; associez-les à nouveau dans l&#39;espace de travail de destination.

<Frame>
  <img src="/assets/mirror/transfer-project-to-workspace-menu-f3accf37a0d6.png" alt="Menu de la carte du projet avec l’action « Transférer vers l’espace de travail »" width="1218" height="1146" data-path="images/teams/transfer-project-to-workspace-menu.png" />
</Frame>

Pour en savoir plus, consultez [Transférer des projets entre les espaces de travail d&#39;équipe](/fr/ja/teams/identity-and-access-management/transfer-app-to-teams#transfer-between-team-workspaces).
