# 병렬로 빌드하기

> 병렬 작업으로 여러 기능을 동시에 빌드하는 방법을 알아보세요: 안전하게 위임하고, 작업을 작게 나누고, 예상치 못한 문제 없이 변경사항을 적용합니다.

한 번에 여러 작업을 처리하는 능력은 훌륭한 빌더와 탁월한 빌더를 가르는 스킬 중 하나입니다. 이 페이지에서는 이런 방식으로 작업해 본 적이 없더라도, 여러 기능을 안전하게 동시에 빌드하는 방법을 알려드립니다.

## Agent와 함께 일하는 새로운 방식

지금까지는 아마 옆에 앉은 파트너처럼 Agent와 작업했을 것입니다: 질문하고, 지켜보고, 응답하는 방식이죠. 병렬로 빌드하는 것은 다른 관계입니다. 기능을 \*\*작업(task)\*\*으로 Agent에게 넘기면, Agent는 당신이 다른 일을 하는 동안 백그라운드에서 그것을 빌드합니다.

사실 일상생활에서도 이미 이런 방식으로 일하고 있습니다. 세탁기가 끝날 때까지 그 앞에 서 있지는 않죠. 빨래를 시작하고, 요리를 하러 갑니다. 작업도 마찬가지로 동작합니다: 하나를 시작하고, 그것이 실행되는 동안 다른 것을 시작하거나, 다른 것을 검토하거나, 메인 대화에서 Agent와 계속 채팅할 수 있습니다.

이는 당신의 역할을 바꿔놓습니다. 하나의 빌드를 지켜보는 승객에서, 여러 빌드를 지휘하는 감독이 되는 것입니다.

## 작업이 실행되는 동안 앱은 안전합니다

모두가 가장 먼저 묻는 질문: *보고 있지 않는 사이 백그라운드 작업이 내 앱을 망가뜨리지는 않을까?*

아닙니다. 각 작업은 프로젝트의 자체 **복사본**에서 작업합니다. 작업의 결과물을 검토하고 적용하기로 선택하기 전까지는 앱이 변경되지 않습니다.

각 작업은 또한 자체 Agent를 가지며 프로젝트의 전체 컨텍스트를 물려받으므로, 같은 설명을 반복할 필요가 없습니다. 작업은 서로 독립적이므로, 첫 번째 작업이 실행 중인 순간에도 바로 다음 작업을 시작할 수 있습니다.

## 병렬로 빌드하기

  <Step title="프로젝트를 열고 사이드바 고정하기">
    기본 Build 레이아웃에서 시작하세요: 왼쪽에 Agent 채팅, 오른쪽에 Preview가 있습니다. 전역 사이드바를 펼치고 고정하여 프로젝트의 작업 컨트롤과 상태 업데이트가 계속 보이도록 하세요.
  </Step>

  <Step title="프로젝트에서 작업 만들기">
    사이드바에서 프로젝트를 펼친 다음, 이름 옆의 **+** 버튼을 선택하세요. 백그라운드 작업을 시작하는 가장 빠른 방법입니다.

    <Frame>
      <img src="https://mintcdn.com/replit/8QDFlk6htBpRrhp4/images/replitai/build-in-parallel-board-shortcuts.jpg?fit=max&auto=format&n=8QDFlk6htBpRrhp4&q=85&s=db4d2e8c3d22f511b04364f8fde22ff0" alt="Board, Open, New task 작업이 있는 프로젝트 보드 단축 메뉴" width="720" height="420" data-path="images/replitai/build-in-parallel-board-shortcuts.jpg" />

  </Step>

  <Step title="하나의 명확한 결과 설명하기">
    작업에 명확한 결과 하나를 부여한 다음 전송하세요. Agent는 프로젝트를 살펴보고 메인 버전을 변경하지 않은 채 계획을 제안합니다.
  </Step>

  <Step title="계획을 검토하고 승인하기">
    범위, 구현 단계, 완료 기준, 관련 파일, agent 모드를 확인하세요. 계획이 의도에 맞을 때만 **Start building**을 선택하세요.

    </Frame>

    **Start building**을 선택하면, 메인 버전에서 하던 작업을 그대로 유지한 채 작업이 백그라운드에서 시작됩니다.

    <Frame>
      <img src="https://mintcdn.com/replit/8QDFlk6htBpRrhp4/images/replitai/build-in-parallel-task-active.jpg?fit=max&auto=format&n=8QDFlk6htBpRrhp4&q=85&s=44f49a71773080b446c507d2827bb370" alt="빌드를 시작한 승인된 작업, Preview 옆에 작업 대화가 표시된 모습" width="1393" height="868" data-path="images/replitai/build-in-parallel-task-active.jpg" />
    </Frame>
  </Step>

  <Step title="나머지 작업 만들고 승인하기">
    한 번에 하나씩 이 과정을 반복하세요. 독립적인 작업에는 각각 별도의 결과를 부여하세요. 의존적인 작업은 필요로 하는 기능이나 프로젝트 구조를 기준으로 설명하여 Agent가 선행 작업을 인식할 수 있도록 하세요.

    새 작업이 다른 작업이 아직 빌드 중인 무언가를 필요로 하면, Agent는 계획에서 선행 작업을 명시하고 해당 작업이 완료되고 승인된 후에 새 작업을 시작하도록 예약합니다.

    <Frame>
      <img src="https://mintcdn.com/replit/8QDFlk6htBpRrhp4/images/replitai/build-in-parallel-dependent-plan.jpg?fit=max&auto=format&n=8QDFlk6htBpRrhp4&q=85&s=dbe27b07c12048468e494c55ec86abcf" alt="선행 작업을 명시하고 완료 후 시작하도록 예약한 Agent의 계획" width="1393" height="868" data-path="images/replitai/build-in-parallel-dependent-plan.jpg" />
    </Frame>
  </Step>

  <Step title="Agent가 작업 일정을 관리하게 하기">
    보드를 열어 **Drafts**, **Active**, **Ready**, **Done**을 확인하세요. 독립적인 작업은 여유가 있을 때 실행됩니다. 의존적인 작업은 무엇이 막고 있는지 표시하며 선행 작업이 적용될 때까지 대기 상태로 남습니다.
  </Step>

  <Step title="준비된 작업을 검토하고 적용하기">
    각 Ready 작업을 열어 결과와 테스트 결과를 확인하고 Preview에서 기능을 사용해 보세요. 기대에 부합하면 **Apply**를 선택하세요. 선행 작업을 적용하면 그것에 의존하는 작업들이 자동으로 잠금 해제됩니다.

    <Frame>
      <img src="https://mintcdn.com/replit/8QDFlk6htBpRrhp4/images/replitai/build-in-parallel-board-ready.jpg?fit=max&auto=format&n=8QDFlk6htBpRrhp4&q=85&s=bf19733bb8df2af8acc4eb6d9eaf84ee" alt="완료된 선행 작업이 Ready에 있고 Apply 및 Review 작업이 보이는 작업 보드" width="650" height="270" data-path="images/replitai/build-in-parallel-board-ready.jpg" />
    </Frame>

    선행 작업을 적용하면, 그에 의존하는 작업들이 자동으로 Active로 이동합니다.

    <Frame>
      <img src="https://mintcdn.com/replit/8QDFlk6htBpRrhp4/images/replitai/build-in-parallel-board-unlocked.jpg?fit=max&auto=format&n=8QDFlk6htBpRrhp4&q=85&s=d438bda8ed03c807c55570c5b2fa2ecd" alt="첫 번째 작업을 적용한 후 의존 작업들이 자동으로 활성화된 작업 보드" width="1393" height="868" data-path="images/replitai/build-in-parallel-board-unlocked.jpg" />

    <Frame>
      <img src="https://mintcdn.com/replit/8QDFlk6htBpRrhp4/images/replitai/build-in-parallel-verify-main-version.jpg?fit=max&auto=format&n=8QDFlk6htBpRrhp4&q=85&s=0f3d1461722baafbd1356484146bfda6" alt="메인 카페 사이트 Preview 옆에 Agent 채팅이 표시된 기본 Build 화면" width="1393" height="868" data-path="images/replitai/build-in-parallel-verify-main-version.jpg" />

  </Step>

## 실제 예시: 네 가지 기능을 동시에

카페 오픈 사이트를 상상해 보세요. 다음 네 가지 개선 사항을 집중적으로 추가하고 싶습니다:

* 접근성을 위한 skip link와 안정적인 랜드마크 ID
* 이 ID를 활용하는 간결한 섹션 내비게이션
* 접근성 기반 위에 구축되는, 개선된 뉴스레터 양식 피드백
* 문서 head만 변경하는 Open Graph 메타데이터

흥미로운 부분은 무엇이 무엇에 의존하는지 정하는 것입니다. 메타데이터 작업은 문서 head만 건드리므로 나머지 세 작업과 공유하는 부분이 없어 즉시 실행할 수 있습니다. 내비게이션과 뉴스레터 작업은 모두 랜드마크 작업이 만드는 안정적인 ID와 페이지 구조를 기반으로 하므로 그 작업을 기다려야 합니다 — 그 구조를 기준으로 설명하면 Agent가 스스로 선행 작업을 인식합니다.

이 일정을 직접 추적할 필요는 없습니다: 막혀 있는 카드는 보드에서 선행 작업을 명시하며, 관련 없는 작업은 Active 상태로 실행됩니다.

## 작업을 작게 나누기

병렬 빌드를 가능하게 하는 스킬은 기능을 작고 독립적인 작업으로 나누는 것입니다. 작은 작업은 더 빨리 끝나고, 검토하기 쉬우며, 서로 간섭할 가능성도 낮습니다.

유용한 규칙: **작업 설명에 "그리고"가 들어간다면 분할을 고려하세요.**

* 좋은 예: "이벤트 페이지 추가", "문의 양식 추가"
* 너무 큰 예: "이벤트와 등록과 이메일 알림과 관리자 화면 추가"

큰 버전이 틀린 것은 아니지만, 하나의 Agent가 모든 것을 순차적으로 처리하게 만듭니다. 네 개의 작은 작업으로 나누면 Agent가 그것들을 함께 실행할 기회가 생깁니다.

직접 시험해 보세요. 다음 중 병렬로 실행할 수 있는 것은 무엇일까요?

1. 다크 모드 토글 추가
2. 고객 리뷰 섹션 추가
3. 고객이 리뷰에 답글을 달 수 있게 하기
4. 앱을 프랑스어로 번역

<Accordion title="정답">
  작업 1, 2, 4는 서로 독립적이며 모두 동시에 실행할 수 있습니다. 작업 3은 작업 2에 의존합니다: 리뷰가 존재하지 않으면 답글을 달 대상이 없기 때문입니다. 이를 직접 알아챌 필요는 없습니다. Agent가 의존성을 감지해서 두 작업의 순서를 대신 정해줍니다.
</Accordion>

## 변경사항을 안전하게 적용하기

각 작업은 프로젝트의 격리된 사본에서 동작합니다. 하나의 작업을 적용하면 메인 버전은 변경되지만, 다른 작업들은 여전히 이전 버전을 기반으로 하고 있을 수 있습니다.

<Tip>
  여러 작업의 변경사항을 적용할 때 Agent가 충돌을 자동으로 처리합니다. 적용할 때마다 결과 앱을 검토하세요. 뭔가 잘못되어 보이면 작업 스레드나 메인 대화에서 Agent에게 수정을 요청하세요.
</Tip>

두 작업이 같은 파일을 변경하면, **Apply**를 선택한 후 Ready 카드에 일시적으로 **Resolving conflicts**가 표시될 수 있습니다. Agent가 병합과 결과 재확인을 마칠 때까지 기다리세요. 파일을 직접 해결할 필요는 없습니다.

## 매니저처럼 검토하기

병렬 빌드는 당신을 매니저로 만들며, 매니저가 흔히 저지르는 실수는 확인하지 않은 작업을 승인하는 것입니다. 지켜야 할 규율은 한 번에 하나씩 진행하는 단순한 루프입니다:

<Steps>
  <Step title="작업 결과 테스트하기">
    완료된 작업을 열고 기능을 사용해 보세요. 사용자처럼 클릭하며 살펴보세요.
  </Step>

  <Step title="적용하기">
    만족스럽다면 변경사항을 메인 앱에 적용하세요.
  </Step>

  <Step title="메인 버전 확인하기">
    적용된 기능이 앱에 이미 있는 변경사항과 함께 잘 작동하는지 확인하세요.
  </Step>

  <Step title="반복하기">
    모든 작업이 반영될 때까지 다음 준비된 작업을 테스트하고 적용하세요.
  </Step>
</Steps>

절대 한꺼번에 승인하지 마세요. 검토하지 않은 세 가지 기능을 한 번에 적용하면, 뭔가 이상할 때 용의자가 세 명이 됩니다.

## 순차적으로 진행해야 할 때

병렬 빌드는 도구이지 규칙이 아닙니다. 다음과 같은 경우에는 메인 대화에서 한 번에 하나씩 진행하세요:

* **두 아이디어가 같은 화면을 다룰 때.** "홈페이지 재설계"와 "내비게이션 변경"은 충돌합니다. 순서대로 진행하세요.
* **탐색 중일 때.** 디자인 작업에서는 한 번의 시도 결과가 다음에 원하는 것을 바꿔놓습니다. 탐색은 작업 지시가 아니라 대화입니다.
* **작업을 한 문장으로 설명할 수 없을 때.** 간단히 표현할 수 없다면, 아직 위임할 준비가 되지 않은 것입니다.

## 한계 안에서 작업하기

플랜에 따라 동시에 실행할 수 있는 백그라운드 작업 수가 결정됩니다. 추가 작업은 대기열에 들어가며 여유 슬롯이 생기면 시작됩니다. 현재 한도는 [작업 시스템](/ko/core-concepts/agent/task-system#availability)을 참고하세요.

주의력도 하나의 한계입니다. 작업 두 개로 시작하세요. 검토가 편하게 느껴지면 세 개를 시도해 보세요. 모든 단계를 감독할 필요는 없지만, 적용하기 전에 각 결과를 테스트해야 합니다.
