С Replit вам не нужно беспокоиться о потере результатов работы.

Система чекпоинтов и отката Replit обеспечивает комплексное управление версиями и состоянием всей среды разработки.

При работе с Replit Agent чекпоинты автоматически сохраняют полное состояние проекта. Они включают не только изменения в коде, но и файлы проекта, контекст диалогов с ИИ и подключённые базы данных.

<div id="section">
  ## Что такое чекпоинт?
</div>

**Чекпоинт** — это полный снимок состояния Replit App, который Agent автоматически создаёт на каждом ключевом этапе разработки. В отличие от традиционных систем контроля версий, которые отслеживают только изменения в коде, чекпоинты Replit сохраняют весь контекст разработки.

Представьте чекпоинт как точку сохранения в видеоигре. В любой момент вы можете вернуться к рабочей версии приложения.

</Frame>

<div id="section-2">
  ### Снимок полного состояния
</div>

Каждый чекпоинт сохраняет:

* **Файлы проекта**: все файлы, каталоги, установленные пакеты и конфигурацию проекта
* **Контекст диалога с ИИ**: всю историю диалога и контекст, предшествующие текущему состоянию
* **Конфигурация среды**: настройки среды выполнения и конфигурацию публикации
* **Память Agent**: понимание ИИ архитектуры проекта, предпочтений и шаблонов
* **Содержимое базы данных**: данные и схему базы данных на момент создания чекпоинта

Такой комплексный подход позволяет уверенно экспериментировать с изменениями, зная, что можно восстановить не только код, но и весь контекст разработки.

<div id="section-3">
  ## Как работает откат
</div>

Функция **отката** позволяет одним щелчком восстановить Replit App до состояния предыдущего чекпоинта. Она значительно мощнее обычной операции Git revert.

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="Интерфейс отката чекпоинта с параметрами отката" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

Откат спроектирован так, чтобы быть безопасным и предсказуемым:

* **Неразрушающий предпросмотр**: в некоторых интерфейсах перед откатом можно просмотреть состояние чекпоинта
* **Чёткие границы**: каждый чекпоинт соответствует логическому этапу разработки
* **Непрерывность диалога**: контекст ИИ сохраняется, поэтому после восстановления можно продолжить разработку
* **Мгновенное применение**: откат сразу применяется ко всей среде разработки

<div id="section-4">
  ### Выполнение отката
</div>

При откате к предыдущему чекпоинту проект возвращается к прежнему состоянию, включая:

1. **Полное состояние проекта**: все файлы проекта возвращаются точно к состоянию на момент выбранного чекпоинта
2. **Контекст диалога с ИИ**: диалог с Agent восстанавливается к состоянию на момент чекпоинта, сохраняя непрерывность контекста
3. **Конфигурация проекта**: зависимости, пакеты и конфигурация среды выполнения
4. **Среда разработки**: конфигурация инструментов и настройки Project Editor
5. **Содержимое базы данных (необязательно)**: если этот параметр выбран, база данных восстанавливается к состоянию на момент чекпоинта

<Info>
  По умолчанию откат не затрагивает базу данных. Чтобы включить базу данных разработки в откат, выберите «База данных» в разделе «Дополнительные параметры отката».

  Обратите внимание: восстановление **[производственной базы данных](/ru/ko/features/data-and-storage/development-and-production)** не выполняется автоматически с помощью этой функции отката.
  О том, как восстановить производственную базу данных на определённый момент времени, см. [документацию по восстановлению на определённый момент времени](/ru/ko/features/data-and-storage/development-and-production).
</Info>

<Warning>
  При использовании функции отката Replit App восстанавливается до предыдущего состояния. При этом удаляются все изменения, внесённые после этого момента, включая изменения кода. Если вы выбрали восстановление базы данных, изменения в ней также будут отменены.
</Warning>

<div id="section-5">
  ### Откат вперёд
</div>

Чекпоинты Replit работают в обоих направлениях — вы можете перемещаться по истории проекта как назад, так и вперёд.
Это позволяет свободно перемещаться по временной шкале разработки, не беспокоясь о потере работы.

Если вы откатились слишком далеко или хотите восстановить изменения из более позднего чекпоинта, используйте **откат вперёд**, чтобы перейти вперёд по истории чекпоинтов. Это позволяет свободно перемещаться по временной шкале проекта, не теряя работу.

Чтобы выполнить откат вперёд, нажмите иконку истории <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="Иконка истории" width="24" height="24" data-path="images/icons/history.svg" />, чтобы открыть историю на вкладке Agent, затем выберите чекпоинт, созданный после текущей позиции.

<Info>
  Откат вперёд возможен только при наличии чекпоинтов после текущей позиции. Если после отката внести новые изменения, последующие чекпоинты станут частью альтернативной ветви истории.
</Info>

Такая двунаправленная навигация даёт полный контроль над временной шкалой проекта и гарантирует, что работу всегда можно восстановить.

<div id="section-6">
  ## Создание чекпоинтов
</div>

ИИ-инструменты Replit автоматически создают чекпоинты на ключевых этапах разработки.

<div id="agent">
  ### Чекпоинты Agent
</div>

[Replit Agent](/ru/ko/features/agent/overview) создаёт чекпоинты в следующих случаях:

* **Завершение работы над функцией**: после успешной реализации запрошенной функции
* **Ключевые этапы**: при существенном продвижении в выполнении сложной задачи
* **Стабильное состояние**: после тестирования и проверки внесённых изменений
* **Восстановление после ошибок**: перед попыткой устранить серьёзную проблему

<div id="section-7">
  ### Особенности чекпоинтов
</div>

Каждый чекпоинт содержит:

* **Описание, сгенерированное ИИ**: понятное и содержательное резюме выполненной работы
* **Временная метка**: точное время создания для удобной идентификации
* **Область изменений**: сведения об изменённых файлах, функциях или системах
* **Платёжная информация**: прозрачное отслеживание затрат для Agent по каждому чекпоинту

<div id="section-8">
  ## Использование чекпоинтов и откат изменений
</div>

<div id="section-9">
  ### Поиск чекпоинтов
</div>

Чекпоинты доступны в нескольких разделах Project Editor:

**Вкладка Agent**: просмотр всех чекпоинтов, созданных Agent, с описаниями и вариантами отката
**Окно Git**: просмотр чекпоинтов в виде коммитов Git с полной интеграцией контроля версий
**Просмотр истории**: нажмите иконку истории <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="Иконка истории" width="24" height="24" data-path="images/icons/history.svg" /> в чате Agent, чтобы открыть полную временную шкалу всех чекпоинтов и хода их выполнения

<div id="section-10">
  ### Выполнение отката
</div>

Процесс отката немного различается в зависимости от того, с какой точки вы начинаете:

<div id="agent-2">
  #### На вкладке Agent
</div>

<Steps>
  <Step title="Перейдите в Agent">
    Откройте вкладку **Agent** в Project Editor, чтобы просмотреть все чекпоинты, созданные Agent.
  </Step>

  <Step title="Выберите чекпоинт">
    Найдите чекпоинт, к которому хотите вернуться, и выберите **Откатить к этому состоянию**.
  </Step>

  <Step title="Подтвердите откат">
    Ознакомьтесь с предупреждением об откате и подтвердите его, чтобы восстановить приложение до выбранного состояния.
  </Step>

  <Step title="Проверьте восстановление">
    Убедитесь, что файлы проекта, база данных и контекст ИИ соответствуют состоянию восстановленного чекпоинта.
  </Step>
</Steps>

<div id="section-11">
  ### Рекомендации
</div>

**Стратегически используйте чекпоинты**:

* После каждого важного чекпоинта тестируйте приложение, чтобы убедиться в его стабильности
* Наряду с автоматическими чекпоинтами создавайте ручные коммиты Git для долгосрочного отслеживания версий
* Просматривайте описания чекпоинтов, чтобы понимать, что изменилось

**Что учитывать при откате**:

* Перед откатом всегда проверяйте масштаб изменений
* Учитывайте влияние на базу данных и внешние интеграции
* Сообщайте соавторам об откате, чтобы все были в курсе

**Итеративная разработка**:

* Разрабатывайте постепенно, чтобы пользоваться преимуществами частых чекпоинтов
* Используйте откат, чтобы безопасно изучать разные подходы к реализации
* Используйте сохранение контекста ИИ, чтобы продолжать диалог даже после отката

<div id="section-12">
  ## Интеграция с системой контроля версий
</div>

Чекпоинты легко интегрируются с более широкой экосистемой контроля версий Replit:

<div id="git">
  ### Интеграция с Git
</div>

* **Создание Git-коммитов**: для каждого чекпоинта создаётся соответствующий Git-коммит
* **Совместимость с ветками**: чекпоинты учитывают структуру веток и процессы слияния
* **Удалённая синхронизация**: интеграция с GitHub поддерживает синхронизацию чекпоинтов
* **Доступ через командную строку**: вы по-прежнему можете использовать все возможности Git вместе с чекпоинтами

<div id="section-13">
  ### Функции совместной работы
</div>

* **Видимость для команды**: чекпоинты видны всем участникам проекта
* **Предотвращение конфликтов при слиянии**: выбор момента создания чекпоинтов снижает вероятность конфликтов
* **Общий контекст**: контекст диалога с ИИ помогает членам команды понимать изменения
* **Обновления в реальном времени**: участники совместной работы видят создание чекпоинтов в реальном времени

<div id="section-14">
  ## Расширенные возможности
</div>

<div id="section-15">
  ### Предпросмотр чекпоинтов
</div>

Некоторые интерфейсы поддерживают предпросмотр чекпоинтов:

* **Визуальное сравнение**: посмотрите, как выглядит приложение на разных чекпоинтах
* **Неразрушающее исследование**: просматривайте изменения без фактического отката
* **Отслеживание прогресса**: узнайте, как приложение развивалось с течением времени
* **Сравнение итераций**: сравнивайте разные подходы к реализации

<div id="section-16">
  ### Откат между сессиями
</div>

Функция для опытных разработчиков и администраторов команд:

* **Расширенная история**: доступ к чекпоинтам из нескольких сеансов разработки
* **Управление администратора**: администраторы команд могут выполнять откат между сеансами разных пользователей
* **Журнал аудита**: полная история создания чекпоинтов и операций отката

<div id="section-17">
  ## Примеры использования
</div>

<div id="section-18">
  ### Экспериментальная разработка
</div>

Чекпоинты позволяют экспериментировать без опасений:

* Пробуйте новые функции, зная, что всегда сможете легко откатить изменения
* Тестируйте различные архитектурные подходы
* Изучайте альтернативные варианты дизайна интерфейса или пользовательских сценариев
* Реализуйте сложные интеграции с надёжной подстраховкой

<div id="section-19">
  ### Отладка и восстановление
</div>

При возникновении проблем чекпоинты помогут надёжно восстановить данные и состояние проекта:

* Откатитесь к рабочему состоянию при возникновении ошибки
* Сравнивайте состояния чекпоинтов, чтобы локализовать проблему
* Восстановите целостность базы данных после повреждения данных
* Восстановите удалённые или изменённые по ошибке данные

<div id="section-20">
  ### Обучение и итерации
</div>

Чекпоинты помогают учиться в процессе разработки:

* Сравнивайте разные стратегии реализации
* Отслеживайте ход рассуждений ИИ по мере создания чекпоинтов
* Изучайте, как развиваются функции, и углубляйте понимание
* Осваивайте новые подходы, зная, что всегда можно безопасно откатиться
