Le [Claude Agent SDK](https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/sdk), c&#39;est Claude Code sous forme de bibliothèque. Il vous permet de créer par programmation les mêmes agents que ceux qui propulsent Claude Code, puis de les exécuter comme du code. Transformez vos tâches répétitives en flux de travail automatisés et publiez-les sur Replit.

<div id="como-o-claude-agent-sdk-funciona">
  ## Comment fonctionne le Claude Agent SDK
</div>

Un agent est une boucle : vous envoyez un prompt, l&#39;agent choisit les outils à exécuter, observe les résultats et recommence jusqu&#39;à ce que la tâche soit terminée.

Vous fournissez le prompt. Le SDK se charge de la boucle.

Mais le SDK va plus loin. Il vous permet de créer des **architectures multi-agents** dans lesquelles un agent orchestrateur délègue des tâches à des sous-agents spécialisés, chacun disposant de ses propres outils et de sa propre fenêtre de contexte.

<Tip>
  Les architectures multi-agents permettent à chaque agent de rester concentré sur sa tâche. Les sous-agents ne reçoivent que les outils et le contexte dont ils ont besoin, ce qui évite la surcharge de contexte et améliore les performances.
</Tip>

<div id="primitivas-principais">
  ### Primitives principales
</div>

| Primitive             | Rôle                                                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **Boucle de requête** | La base : prompt, choix des outils, exécution, observation, répétition                                                                |
| **Agents**            | Configurations spécialisées dotées de leurs propres outils et instructions                                                            |
| **Outils**            | Actions que les agents peuvent effectuer — exécuter des commandes, appeler des API, modifier des fichiers                             |
| **Serveurs MCP**      | Processus externes qui exposent des ensembles d&#39;outils (gourmands en contexte, chargés en amont)                                  |
| **Compétences**       | Fichiers d&#39;instructions en Markdown qui apprennent aux agents à accomplir des tâches (économes en contexte, chargés à la demande) |
| **Autorisations**       | Contrôles granulaires sur ce à quoi chaque agent peut accéder et sur ce qu&#39;il peut exécuter                                       |

<div id="skills-vs-servidores-mcp">
  ### Compétences ou serveurs MCP
</div>

Voici les deux principaux moyens d&#39;étendre vos agents :

**Les compétences** sont des fichiers markdown contenant des instructions que votre agent suit. Seule une brève description est chargée tant qu&#39;elles ne sont pas invoquées, ce qui allège la fenêtre de contexte. Utilisez les compétences pour :

* Les flux de travail et les conventions (« comment déployer », « checklist de revue de code »)
* Les documents de référence (normes d&#39;API, guides de style)
* Les prompts réutilisables déclenchés par leur nom

**Les serveurs MCP** sont des processus qui exposent des outils. Toutes les descriptions d&#39;outils sont chargées d&#39;emblée, ce qui les rend gourmands en contexte. Utilisez les serveurs MCP pour :

* Vous connecter à des services externes (Notion, Linear, bases de données)
* Les actions nécessitant un accès API (créer des tâches, interroger des données)
* Les outils qui *font* des choses, plutôt que de se contenter d&#39;instruire

<Info>
  Les compétences définissent *comment* votre agent doit travailler. Les serveurs MCP définissent *ce à quoi* votre agent peut accéder. Les deux fonctionnent avec les agents de codage (comme Replit Agent) et avec les agents que vous créez à l&#39;aide du SDK.
</Info>

<div id="quando-usar-o-sdk-vs-a-api">
  ### Quand utiliser le SDK plutôt que l&#39;API
</div>

| Cas d&#39;usage                            | Choix               |
| ------------------------------------------ | ------------------- |
| Automatiser des tâches en plusieurs étapes | Claude Agent SDK    |
| Flux de travail multi-agents               | Claude Agent SDK    |
| Applications de chat simples               | API d&#39;Anthropic |
| Tâches à tour unique                       | API d&#39;Anthropic |

<div id="crie-um-agente-organizador-do-todoist">
  ## Créez un agent organisateur Todoist
</div>

Ce guide s&#39;appuie sur un modèle Replit qui met en place un projet Claude Agent SDK avec la bonne structure : répertoires d&#39;agents, outils, serveurs MCP, compétences et autorisations sont déjà configurés.

<div id="etapa-1-faa-remix-do-template">
  ### Étape 1 : Remixez le modèle
</div>

<Steps>
  <Step title="Ouvrez le modèle">
    Ouvrez le [modèle Claude Agent SDK](https://replit.com/@matt/Claude-Agent-SDK) dans Replit et sélectionnez **Remix** pour créer votre propre copie.
  </Step>

  <Step title="Nommez votre projet">
    Donnez-lui un nom descriptif (par ex. « Mon agent Todoist ») et sélectionnez **Utiliser le modèle**.
  </Step>

  <Step title="Examinez la structure du projet">
    Une fois l’environnement chargé, ouvrez la barre latérale des fichiers. Activez **Afficher les fichiers cachés** si nécessaire pour voir la structure complète :

    * `.agents/skills/` — Compétences qui permettent à Replit Agent de créer des applications avec le Claude Agent SDK
    * `src/agents/` — Définitions des agents
    * `src/mcpServers/` — Configurations des serveurs MCP
    * `src/permissions/` — Définitions des autorisations
    * `src/skills/` — Compétences pour vos agents (fichiers Markdown)
    * `src/tools/` — Définitions d’outils personnalisés
  </Step>
</Steps>

<Tip>
  Le modèle inclut une compétence qui permet à Replit Agent de créer des applications avec le Claude Agent SDK. Cela signifie qu’Agent maîtrise déjà le framework lorsque vous lui fournissez un prompt.
</Tip>

<div id="etapa-2-conecte-o-todoist-via-integraes-do-replit">
  ### Étape 2 : connectez Todoist via les intégrations Replit
</div>

Avant de rédiger des prompts pour l&#39;Agent, connectez le service avec lequel votre agent doit interagir.

1. Rendez-vous sur **replit.com/integrations** depuis votre compte Replit.
2. Recherchez **Todoist** et connectez votre compte.
3. Autorisez Replit à accéder à vos données Todoist.

<Info>
  Les intégrations Replit gèrent OAuth et l&#39;authentification à votre place. Votre agent peut accéder à l&#39;API Todoist sans que vous ayez à gérer les jetons vous-même. C&#39;est plus simple que de configurer un serveur MCP distinct, qui nécessite son propre flux OAuth.
</Info>

<div id="etapa-3-crie-prompts-para-o-agent-construir-seu-agente">
  ### Étape 3 : Rédigez des prompts pour qu&#39;Agent construise votre agent
</div>

Passez Replit Agent en **mode Plan** pour de meilleurs résultats : il vous soumet le plan avant de construire, ce qui vous permet de valider l&#39;approche.

<AiPrompt>
  Utilise la compétence Claude Agent SDK. Crée un agent qui analyse ma boîte de réception Todoist et organise mes tâches en leur appliquant des étiquettes pertinentes ou des informations complémentaires.

  Tu dois créer des outils permettant à l&#39;agent d&#39;interagir avec Todoist via le SDK.

  Le résultat doit être un agent qui, lorsqu&#39;il est déclenché, charge toutes les tâches et tous les projets disponibles, les enrichit et les organise correctement.

  Veille à utiliser l&#39;intégration Replit avec Todoist pour toute l&#39;authentification. Utilise des outils personnalisés avec l&#39;API REST de Todoist plutôt que le serveur MCP de Todoist, car ce dernier nécessite OAuth, ce qui ne fonctionne pas dans ce contexte.

  L&#39;agent doit également récupérer une liste de projets et attribuer un projet pertinent à chaque élément de ma boîte de réception, de manière à la vider complètement.
</AiPrompt>

<Note>
  Les deux derniers paragraphes de ce prompt ont été ajoutés après le débogage. Préciser *comment* s&#39;authentifier (les intégrations Replit, et non OAuth MCP) et *quel* doit être l&#39;état final (une boîte de réception entièrement vide) fait gagner du temps d&#39;itération.
</Note>

<div id="etapa-4-revise-o-plano-e-construa">
  ### Étape 4 : Examinez le plan et lancez la construction
</div>

Lorsque l&#39;Agent présente son plan, vérifiez qu&#39;il comprend :

1. **Des outils personnalisés** pour l&#39;API Todoist (et non le serveur MCP Todoist)
2. **Un agent organisateur** qui récupère les tâches, les étiquettes et les projets
3. **Des autorisations adaptées**, limitées aux outils dont votre agent a besoin
4. **Un point d&#39;entrée** qui déclenche le flux de travail

Lorsque le plan vous convient, approuvez-le, réglez l&#39;Agent sur **autonomie élevée** et laissez-le construire.

<div id="etapa-5-adicione-sua-chave-de-api-da-anthropic">
  ### Étape 5 : Ajoutez votre clé API Anthropic
</div>

Le Claude Agent SDK nécessite une clé API Anthropic pour appeler Claude.

1. Ouvrez le panneau **Secrets** dans l&#39;éditeur de projet.
2. Ajoutez un secret nommé `ANTHROPIC_API_KEY` contenant la valeur de votre clé API.

<Info>
  Si vous avez enregistré votre clé API Anthropic dans votre [coffre-fort Replit, sous Paramètres](https://replit.com/settings), elle est automatiquement disponible dans tous vos projets.
</Info>

<div id="etapa-6-teste-e-depure">
  ### Étape 6 : Testez et déboguez
</div>

Exécutez l&#39;agent et vérifiez qu&#39;il traite correctement votre boîte de réception Todoist. Problèmes courants à surveiller :

* **« Boîte de réception vide » alors qu&#39;elle ne l&#39;est pas** — le format de réponse de l&#39;API utilisé pour détecter les tâches de la boîte de réception nécessite peut-être un ajustement. Vérifiez que l&#39;agent filtre les tâches selon le projet « boîte de réception », et non selon une autre propriété.
* **Les tâches reçoivent des étiquettes, mais ne sont pas déplacées vers des projets** — précisez explicitement dans votre prompt que l&#39;agent doit récupérer les projets disponibles et affecter chaque tâche à l&#39;un d&#39;eux.
* **Erreurs d&#39;authentification** — vérifiez que l&#39;intégration Todoist est bien connectée dans les Intégrations de Replit et que le code de votre agent l&#39;utilise (et non un flux OAuth distinct).

<Tip>
  Le débogage fait partie intégrante de la création avec l&#39;IA. Lorsque quelque chose ne fonctionne pas, observez la sortie, identifiez *ce que* l&#39;agent a fait différemment de ce que vous attendiez, puis formulez un prompt plus précis. Chaque correction vous apprend ce qu&#39;il faudra inclure d&#39;emblée la prochaine fois.
</Tip>

<div id="publique-seu-agente">
  ## Publiez votre agent
</div>

Lorsque votre agent fonctionne correctement, publiez-le pour qu&#39;il s&#39;exécute automatiquement.

<Steps>
  <Step title="Ouvrez l'onglet Publier">
    Dans l&#39;éditeur de projet, sélectionnez l&#39;onglet **Publier**.
  </Step>

  <Step title="Choisissez Déploiement planifié">
    Sélectionnez **Déploiement planifié** pour une automatisation basée sur le temps. Saisissez la planification souhaitée (par exemple, « tous les jours à 17 h PST »).
  </Step>

  <Step title="Vérifiez la configuration">
    Assurez-vous que la commande d&#39;exécution pointe vers le fichier de point d&#39;entrée principal et que votre secret `ANTHROPIC_API_KEY` figure parmi les secrets de déploiement.
  </Step>

  <Step title="Publiez">
    Sélectionnez **Publier**. Votre agent est désormais actif et s&#39;exécute selon la planification définie.
  </Step>
</Steps>

Pour les agents qui doivent réagir à des événements (webhooks, messages entrants), utilisez plutôt un [déploiement de VM réservée](/fr/pt/features/publishing/reserved-vm-deployments).

<div id="estenda-seu-agente">
  ## Étendez votre agent
</div>

Une fois les bases en place, vous pouvez créer des agents plus sophistiqués sur Replit :

* **Ajoutez une mémoire persistante** — Utilisez la [base de données Replit](/fr/pt/features/data-and-storage/sql-database) pour conserver l&#39;état d&#39;une exécution à l&#39;autre
* **Stockez des fichiers** — Utilisez le [stockage d&#39;application](/fr/pt/features/data-and-storage/object-storage) pour les données sous forme de fichiers
* **Connectez davantage de services** — Ajoutez d&#39;autres [intégrations](/fr/pt/features/integrations/overview) (Slack, Linear, GitHub, Notion) pour des flux de travail multiservices
* **Utilisez les compétences** — Ajoutez des fichiers de compétences en markdown pour doter vos agents de connaissances spécialisées et d&#39;instructions
