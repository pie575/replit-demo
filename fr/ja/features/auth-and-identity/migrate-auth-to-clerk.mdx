---
title: "Migrer de Replit Auth vers Clerk"
description: "Utilisez Agent pour migrer une application Replit Auth existante vers Clerk Auth tout en conservant les données utilisateur de l’application."
---

Utilisez ce guide pour migrer une application [Replit Auth](/fr/ja/features/auth-and-identity/authentication) existante vers [Clerk Auth](/fr/ja/features/auth-and-identity/clerk-auth). Agent effectue la migration de l’application afin que les utilisateurs existants conservent l’accès à leurs données.

<Note>
  Cette migration automatisée est destinée aux applications qui utilisent Replit Auth. N’utilisez pas cette procédure si votre application utilise un autre système d’authentification.
</Note>

<div id="section">
  ## Lancer une migration
</div>

Les migrations avec Agent doivent toujours être effectuées dans une nouvelle tâche.

Vous pouvez lancer une migration de l’une des manières suivantes.

<div id="agent">
  ### Commencer avec Agent
</div>

<Steps>
  <Step title="Créer une nouvelle tâche">

<div id="section-2">
  ### Vérifier le plan de migration
</div>

Quelle que soit la méthode choisie, Agent crée la tâche **Migrate from Replit Auth to Clerk** et prépare un plan de migration. Sélectionnez **View plan** pour consulter le plan avant que la tâche ne soit exécutée.

<Frame caption="La tâche Migrate from Replit Auth to Clerk commence par l’action View plan, qui vous permet de consulter le guide de migration.">
  <img src="/assets/mirror/replit-auth-to-clerk-task-998d61b55c3d.png" alt="Une tâche Agent nommée Migrate from Replit Auth to Clerk affichant un bouton View plan et une étape de révision du guide de migration" width="575" height="900" data-path="images/workspace/auth/replit-auth-to-clerk-task.png" />
</Frame>

Pendant qu’Agent travaille, ne modifiez ni le code d’authentification de l’application ni les identifiants d’authentification Clerk.

<div id="agent-2">
  ## Ce qu’Agent fait
</div>

Agent effectue la migration dans l’ordre suivant :

1. Il transfère vers Clerk les données utilisateur de Replit Auth, y compris les informations d’identité du compte et les identifiants de connexion pris en charge.
2. Il attend la fin de la migration des données avant de modifier votre application.
3. Il met à jour la logique de connexion et de gestion des sessions de votre application, redémarre l’application et exécute toutes les vérifications automatiques disponibles.

<div id="section-3">
  ## Les données de l’application restent intactes
</div>

Agent ne modifie que le code d’authentification de l’application. Les données et schémas existants de la base de données de l’application ne sont pas mis à jour. Les tables et les relations restent inchangées.

Les utilisateurs existants restent associés aux enregistrements qu’ils possèdent déjà, notamment leurs profils, leurs travaux enregistrés et leurs autorisations.

<div id="section-4">
  ## Durée estimée
</div>

Comptez entre 10 minutes et 1 heure pour qu’Agent effectue cette tâche. La migration des données peut prendre quelques minutes pour les petites applications et jusqu’à plusieurs heures pour les applications comptant de nombreux utilisateurs. Agent ne commencera pas à modifier le code de l’application tant que la migration des données ne sera pas terminée.

<div id="section-5">
  ## Après la migration
</div>

Avant de publier votre application, testez la version mise à jour dans Development.

1. Connectez-vous à l’aide d’un compte existant et vérifiez que les données enregistrées sont accessibles.
2. Déconnectez-vous, puis reconnectez-vous.
3. Créez un compte de test et vérifiez que vous pouvez utiliser l’application comme prévu.
