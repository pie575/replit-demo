Le sélecteur de modèles vous permet de laisser Replit choisir automatiquement un modèle ou de sélectionner vous-même un modèle disponible.

<div id="section">
  ## Routage intelligent des modèles
</div>

Le routage intelligent des modèles sélectionne le modèle le plus adapté à chaque tâche, en conciliant qualité et coût. Lorsque **Auto** s’affiche dans le produit, Replit utilise le routage intelligent des modèles.

Le routage intelligent des modèles prend en compte le travail demandé et sa complexité. Les demandes ciblées peuvent être traitées par des modèles moins coûteux, tandis que les tâches complexes peuvent nécessiter des modèles plus performants. Replit peut également sélectionner différents modèles à mesure que la tâche évolue.

<Note>
  Free Mode utilise toujours le routage intelligent des modèles. Les créateurs de Free Mode ne peuvent pas utiliser le sélecteur de modèles ni choisir manuellement un modèle.
</Note>

<div id="section-2">
  ## Sélectionner manuellement un modèle
</div>

Les créateurs Core et Pro peuvent sélectionner les modèles disponibles dans Power Mode ou Max Mode.

1. Dans la zone de saisie, sélectionnez **Agent Mode**. Le menu affiche les modes disponibles (**Free**, **Power**, **Max**).
2. Choisissez **Power** ou **Max**, puis repérez la section **modèle principal**.
3. Ouvrez le menu du modèle principal et sélectionnez un modèle dans la liste.

Votre sélection s’appliquera à votre prochain message. Vous pouvez la modifier à tout moment.

<div id="effort">
  ## Effort
</div>

**Effort est un paramètre propre à chaque modèle, et non un mode indépendant.** Il définit le niveau de raisonnement que le modèle sélectionné consacre à chaque réponse, de **Low** à **Max**. Chaque modèle affiche un paramètre recommandé, que vous ne pouvez augmenter que lorsque la tâche l’exige.

<Frame caption="Curseur Effort sous la liste des modèles, réglé sur Medium.">
  <img src="/assets/mirror/model-selector-effort-bcffb01239a8.png" alt="Liste des modèles principaux avec Claude Fable 5 sélectionné et le curseur Effort réglé sur Medium, décrit comme un raisonnement équilibré adapté aux tâches quotidiennes" width="984" height="832" data-path="images/replitai/model-selector-effort.png" />
</Frame>

Utilisez les descriptions de chaque niveau comme guide.

| Effort         | Utilisation                                                                                                                                        |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Low**        | Réponses les plus rapides avec un raisonnement minimal. Pour les modifications quotidiennes et clairement définies où la rapidité est essentielle. |
| **Medium**     | Raisonnement équilibré adapté aux tâches quotidiennes. Une valeur par défaut fiable lorsqu’aucune recommandation spécifique n’est indiquée.        |
| **High**       | Raisonnement plus approfondi pour les tâches plus complexes, comme les fonctionnalités en plusieurs étapes ou les domaines moins familiers.        |
| **Extra High** | Raisonnement étendu pour les problèmes les plus difficiles, comme les refactorisations à grande échelle ou les bugs épineux.                       |
| **Max**        | Profondeur de raisonnement maximale. Plus coûteux et plus lent, à utiliser lorsque seuls les meilleurs résultats possibles comptent.               |

Lorsque vous augmentez Effort, Agent raisonne plus en profondeur et avec davantage de rigueur, et fait appel aux modèles de pointe les plus performants, ce qui améliore les résultats pour les tâches les plus complexes. Agent applique cette puissance supplémentaire de manière sélective : il n’oriente votre requête vers des modèles plus performants que lorsqu’elle est réellement difficile et ne les utilise pas à chaque exécution.

<Tip>
  Comme Agent n’utilise les modèles les plus performants que pour les tâches les plus difficiles, augmenter Effort peut au maximum doubler les coûts pour les tâches les plus complexes, mais les augmente souvent peu, voire pas du tout, pour les tâches plus simples. Augmentez-le lorsque vous travaillez sur des problèmes complexes et maintenez-le à un niveau bas pour les modifications routinières.
</Tip>

<div id="section-4">
  ## Comparaison des modèles
</div>

Avec **Comparer les modèles**, vous pouvez exécuter le prompt suivant simultanément sur plusieurs modèles et comparer les résultats côte à côte, plutôt que de deviner lequel convient le mieux. Cette fonctionnalité est actuellement en bêta.

Pour l’activer, développez les **Paramètres avancés** en bas de la fenêtre contextuelle du mode Agent, puis activez **Comparer les modèles**.

<Note>La comparaison des modèles est prise en charge uniquement dans Chat.</Note>

<Frame caption="Le bouton bascule Comparer les modèles dans les Paramètres avancés.">
  <img src="/assets/mirror/compare-models-toggle-05429dc46d64.png" alt="Les Paramètres avancés sont développés et le bouton bascule bêta Comparer les modèles est désactivé. Une explication indique que le prompt suivant créera jusqu’à quatre variantes." width="1110" height="344" data-path="images/replitai/compare-models-toggle.png" />
</Frame>

Lorsque vous activez le bouton bascule, vous pouvez ajouter jusqu’à **4 modèles** à comparer.

<Frame caption="Quatre modèles sont sélectionnés pour la comparaison et le bouton d’envoi affiche « Comparer 4 ».">
  <img src="/assets/mirror/compare-models-9f5bcecec727.png" alt="Comparer les modèles est activé et la fenêtre contextuelle du mode Agent affiche quatre emplacements de modèles — Kimi K3, Claude Fable 5, Claude Opus 5 et GPT-5.6 Sol — chacun pouvant être supprimé, ainsi qu’un bouton d’envoi du chat affichant « Comparer 4 »." width="1192" height="1930" data-path="images/replitai/compare-models.png" />
</Frame>

Le prompt suivant est exécuté une fois pour chaque modèle sélectionné, chacun générant sa propre variante à comparer.

<Note>
  Chaque modèle de la comparaison exécute un Agent distinct et consomme des crédits. L’exécution de Comparer 4 coûte donc environ autant que quatre exécutions individuelles.
</Note>
