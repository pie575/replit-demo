Votre application se connecte à la base de données à l’aide d’identifiants gérés par Replit. Pour les consulter, sélectionnez votre base de données dans l’outil **Database**, puis ouvrez l’onglet **paramètres**. Cet onglet affiche la chaîne de connexion, l’espace de stockage utilisé et les informations de connexion avancées.

<div id="section">
  ## Variables d’environnement
</div>

Vous pouvez utiliser les variables d’environnement suivantes pour vous connecter à votre base de données de développement.

* `DATABASE_URL` : permet de se connecter à la base de données et de s’y authentifier

Votre application l’utilise automatiquement. `DATABASE_URL` est propre à l’application. Votre base de données de développement n’est donc pas accessible depuis d’autres applications, y compris celles dont vous êtes propriétaire, ni depuis des visualiseurs de bases de données externes. Même si elle est exposée, personne ne peut l’utiliser pour accéder à la base de données ou la modifier.

<Info>
  Si votre base de données de développement utilise encore l’[infrastructure Neon héritée](/fr/ko/features/data-and-storage/development-and-production#legacy-development-database), vous pouvez également utiliser les variables supplémentaires `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `PGPORT`. Ces variables ne sont **pas** fournies pour les bases de données hébergées sur l’infrastructure actuelle de Replit. Vous devez utiliser `DATABASE_URL` à la place.
</Info>

<Warning>
  Si vous utilisez encore une base de données de développement Neon héritée, ne partagez pas `DATABASE_URL`. Elle contient les identifiants de connexion à la base de données, ce qui permet à quiconque de l’utiliser pour y accéder et la modifier. Ne la collez jamais dans un espace public ou un ticket d’assistance.
</Warning>

<div id="section-2">
  ## Connexion à des outils externes
</div>

Utilisez la chaîne de connexion indiquée dans l’onglet **paramètres** de la base de données de production pour vous connecter à la base de données **de production** depuis n’importe quel client SQL compatible avec PostgreSQL.

<div id="section-3">
  ## Sécurité
</div>

Lorsque vous ajoutez une intégration de base de données avec Agent, un ORM (Object-Relational Mapper) doté de fonctionnalités de sécurité intégrées gère toutes les communications avec la base de données.

* **Validation du schéma** : vérifie que les données respectent le format attendu
* **Nettoyage des données (Sanitization)** : nettoie automatiquement les entrées utilisateur afin de prévenir les attaques par injection SQL

<div id="section-4">
  ## Régénération des identifiants de la base de données de production
</div>

Si votre chaîne de connexion de production a été exposée, régénérez les identifiants dans l’outil **Database**. Cette opération génère un nouveau mot de passe pour la base de données Neon de production. Les chaînes de connexion de production existantes cessent immédiatement de fonctionner.

Vous pouvez régénérer les identifiants si toutes les conditions suivantes sont remplies :

* L’application dispose d’une base de données Neon de production.
* Vous êtes propriétaire de l’application ou administrateur de l’espace de travail qui en est propriétaire.
* Vous utilisez Replit dans un navigateur web.
* Aucun déploiement n’est en cours.
* Si l’application dispose d’un déploiement en ligne, le dernier build s’est terminé avec succès et utilise [Autoscale ou Reserved VM](/fr/ko/features/publishing/deployment-types).

<Warning>
  Cette opération est irréversible. Les chaînes de connexion existantes cessent immédiatement de fonctionner. Si l’application dispose d’un déploiement en ligne,
  elle peut être temporairement indisponible pendant le redéploiement.
</Warning>

<div id="section-5">
  ### Régénérer les identifiants
</div>

1. Dans le panneau Tools, sélectionnez **Database**.

2. Sélectionnez **Production Database**, puis l’onglet **Paramètres**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="Onglet Paramètres de la base de données de production montrant la chaîne de connexion, l’utilisation de l’espace de stockage et la ligne Regenerate credentials dans la section Avancé" width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. Dans **Avancé**, développez la ligne **Regenerate credentials**.

4. Sélectionnez le bouton **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Écran montrant la ligne Regenerate credentials développée et le bouton Regenerate credentials dans la section Avancé" width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. Dans la boîte de dialogue de confirmation, sélectionnez **Regenerate credentials** pour confirmer.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="Boîte de dialogue de confirmation Regenerate credentials avertissant que cette action est irréversible et que les chaînes de connexion existantes cesseront immédiatement de fonctionner" width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Sélectionnez **Refresh** pour charger la nouvelle chaîne de connexion.

7. Si votre application dispose d’un déploiement en ligne, ouvrez **Publishing** et vérifiez l’état du redéploiement.

8. Remplacez toutes les chaînes de connexion que vous avez copiées dans des outils externes ou des intégrations personnalisées.

<div id="section-6">
  ### Ce qui change
</div>

La régénération des identifiants crée un nouveau mot de passe pour la base de données de production. Seule la partie correspondant au mot de passe dans la chaîne de connexion est modifiée ; l’hôte, le nom de la base de données et le rôle restent inchangés.

Pour les déploiements en ligne pris en charge, Replit redéploie le dernier build réussi avec la chaîne de connexion mise à jour.
