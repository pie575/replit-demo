В этом руководстве описано, как создать App ID, Services ID и приватный ключ Apple, необходимые для Sign in with Apple. Вам потребуется получить **Team ID**, **Services ID**, **Key ID** и **приватный ключ**, чтобы указать их в **панели Auth**.

<Note>
  Эта страница охватывает только настройку на стороне провайдера на портале Apple для разработчиков. Общий процесс Clerk Auth, включая включение Apple и ввод учетных данных в **панели Auth**, описан в разделе [Настройка учетных данных OAuth для поставщика SSO](/ru/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) документации Clerk Auth.
</Note>

<div id="pr-requisitos">
  ## Предварительные требования
</div>

* [Учётная запись разработчика Apple](https://developer.apple.com/account) (требуется участие в программе Apple Developer Program)
* [Развёрнутое App Replit](/ru/category/replit-deployments) — пользовательские учётные данные OAuth доступны только в среде **Production**
* Откройте панель редактирования провайдера **Apple**: **панель Auth** → вкладка **Configure** → раздел **SSO providers** → выберите среду **Production** → нажмите **Edit** рядом с **Apple**

<div id="passo-1-criar-um-apple-app-id">
  ## Шаг 1. Создайте Apple App ID
</div>

1. Перейдите на [портал Apple Developer](https://developer.apple.com/account)
2. Откройте **Certificates, IDs &amp; Profiles**, затем **Identifiers**
3. Выберите **App IDs** в раскрывающемся списке
4. Нажмите значок **+**, чтобы зарегистрировать новый идентификатор
5. Выберите **App IDs**, затем **Continue**
6. Выберите **App**, затем **Continue**
7. Заполните:
   * **Description**: название вашего App ID
   * **Bundle ID**: уникальный идентификатор
8. Включите **Sign In with Apple** в разделе Capabilities
9. Выберите **Continue**, затем **Register**
10. **Сохраните префикс App ID** (он указан вверху) — это ваш **Team ID**

<div id="passo-2-criar-um-apple-services-id">
  ## Шаг 2. Создайте Apple Services ID
</div>

1. На странице Identifiers в раскрывающемся меню выберите **Services IDs**
2. Нажмите **+**, чтобы зарегистрировать новый идентификатор
3. Выберите **Services IDs**, затем **Continue**
4. Заполните поля:
   * **Description**: название вашего Services ID
   * **Identifier**: ваш уникальный идентификатор (сохраните его — это ваш **Services ID**)
5. Выберите **Continue**, затем **Register**

<div id="configurar-o-services-id">
  ### Настройка Services ID
</div>

1. Выберите только что созданный Services ID
2. Включите **Sign In with Apple**
3. Выберите **Configure**
4. Укажите:

   * **Primary App ID**: выберите App ID, созданный на шаге 1
   * **Domains and Subdomains**: скопируйте значение из раздела **Provider setup** на **панели Auth** (без префикса протокола `https://`)
   * **Return URLs**: скопируйте значение из раздела **Provider setup** на **панели Auth**

   См. [Настройка учетных данных OAuth для поставщика SSO](/ru/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider), чтобы узнать, где найти эти значения.
5. Выберите **Next**, затем **Done**, затем **Continue** и наконец **Save**

<div id="passo-3-criar-uma-apple-private-key">
  ## Шаг 3: Создание приватного ключа Apple
</div>

1. На боковой панели портала Apple Developer выберите **Keys**
2. Выберите **+**, чтобы зарегистрировать новый ключ
3. Введите **Key Name**
4. Включите **Sign In with Apple**
5. Выберите **Configure**, затем выберите App ID, созданный на шаге 1
6. Выберите **Save**, затем **Continue**, а после этого — **Register**
7. **Сохраните Key ID**
8. **Скачайте** файл приватного ключа (.p8)

<Warning>
  Приватный ключ можно скачать только один раз. Храните его в безопасном месте — повторно скачать его нельзя.
</Warning>

<div id="passo-4-configurar-o-apple-private-email-relay">
  ## Шаг 4: Настройка Apple Private Email Relay
</div>

Функция Hide My Email от Apple позволяет пользователям входить в систему, не раскрывая свой настоящий адрес электронной почты. Чтобы отправлять письма таким пользователям, зарегистрируйте свой источник электронной почты.

1. На боковой панели портала Apple Developer выберите **Services**
2. В разделе **Sign in with Apple for Email Communication** выберите **Configure**
3. Нажмите **+**, чтобы добавить Email Source
4. Введите значение Email Source, указанное в **Provider setup** на **панели Auth**
5. Выберите **Next**, затем **Register**, а после этого — **Done**
6. Дождитесь проверки DNS (зелёный значок с галочкой)

<Info>
  В некоторых регионах (Китай, Индия) Apple ID могут быть привязаны к номерам телефонов, а не к адресам электронной почты. Если вашему приложению требуется адрес электронной почты для всех пользователей, Sign in with Apple может не работать для пользователей из этих регионов.
</Info>

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

<div id="cliente-invlido">
  ### Недействительный клиент
</div>

* Убедитесь, что все учётные данные введены верно
* Убедитесь, что приватный ключ содержит строки BEGIN и END
* Проверьте правильность настройки вашего Services ID

<div id="uri-de-redirecionamento-invlida">
  ### Недопустимый URI перенаправления
</div>

* Убедитесь, что Return URL в настройках Apple Services ID в точности совпадает со значением, указанным в разделе **Provider setup** на **панели Auth**
* Убедитесь, что домен в Domains and Subdomains совпадает с опубликованным доменом вашего приложения (без `https://`)

<div id="e-mail-relay-no-est-funcionando">
  ### Пересылка электронной почты не работает
</div>

* Убедитесь, что для Email Source на портале Apple для разработчиков отображается зелёная галочка
* Если DNS-запись была добавлена недавно, дождитесь её распространения

<div id="no-est-funcionando-no-domnio-personalizado">
  ### Не работает с пользовательским доменом
</div>

* Добавьте записи пользовательского домена из раздела **Provider setup** в **панели Auth** в Domains and Subdomains (без `https://`), а также в Return URLs
