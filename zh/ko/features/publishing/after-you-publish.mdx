选择 **Publish** 后，系统会启动一个简短的流程，将你的应用上线。本页介绍发布期间会发生什么、如何更新应用，以及应用上线后在哪里管理。

<div id="section">
  ## 发布阶段
</div>

发布分为五个阶段，通常需要 1~2 分钟。你可以在 Publishing 工具中查看进度条；如需查看详细信息，请选择 **View logs**；如需取消正在进行的发布，请选择 **Cancel**。

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Publishing 概览显示五阶段进度条：Provision 已完成，Security checks 和 Build 正在进行，Bundle 和 Promote 正在等待" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision**: Replit 会准备应用运行所需的云资源，例如服务器和生产数据库。
2. **Security checks**: 在将应用上线前，Replit 会检查不安全的依赖项、暴露的机密信息等安全问题。
3. **Build**: Replit 会将项目转换为生产版本，即经过优化、可在 Web 上运行的形式。
4. **Bundle**: 已构建的应用会被打包成可立即运行的单一单元。
5. **Promote**: Replit 会在当前版本旁准备新版本，然后将 URL 切换到新版本。

<Note>
  发布针对整个项目：项目中包含的所有工件，例如应用、幻灯片和文档，都会一同发布。
</Note>

<Accordion title="内部流程">
  面向希望了解技术细节的构建者：Provision 会根据所选的部署类型和区域分配部署基础设施。Security checks 会执行依赖项和代码扫描，并可能根据安全设置在发现严重漏洞时阻止发布。Build 会运行构建命令并编译生产环境所需的资源。Bundle 会将构建输出打包为可部署的镜像。Promote 会执行切换操作：新版本开始通过 URL 提供服务，并替换之前的部署。
</Accordion>

所有阶段完成后，应用即上线。选择 Publishing 工具中的 URL 以打开应用。

<div id="section-2">
  ## 更新应用
</div>

完成更改后，再次选择 **Publish**。应用会在同一 URL 上更新，访客下次加载页面时即可看到最新版本。无需分享新链接。

<div id="section-3">
  ## 管理在线应用
</div>

Publishing 工具还可用于管理已上线的应用：

* **监控状态**：检查应用是否在线、查看日志和资源使用情况。详细了解[监控](/zh/ko/features/publishing/monitoring-a-deployment)。
* **查看访客**：可在[监控](/zh/ko/features/publishing/monitoring-a-deployment)中查看请求和流量图表，并在 **Growth** 面板中查看访客和用户洞察。
* **更改访问权限**：停止发布，选择其他访问选项，然后重新发布。详细了解[应用访问权限](/zh/ko/features/publishing/private-deployments)。
* **连接域名**：为应用设置自定义网址。详细了解[自定义域名](/zh/ko/features/publishing/custom-domains)。
