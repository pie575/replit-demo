</Note>

<div id="section-2">
  ## 自动依赖项扫描
</div>

自动依赖项扫描会将项目的软件包与公开的漏洞记录进行比对。该扫描免费且自动运行。当新的 Common Vulnerabilities and Exposures (CVE) 条目公开时，Replit 会将其与项目的依赖进行比对，并在 **Security** 面板中显示匹配项，无需手动重新扫描。

依赖扫描支持 Node.js/npm、Python、Go、Rust、PHP 和 Ruby。

自动依赖修复目前主要针对 Node.js/npm。

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect 是自动依赖项扫描的扩展功能。当 Replit 发现匹配的漏洞时，Agent 会准备并测试补丁，然后向你发送一封包含直达链接的邮件。补丁会以待处理状态保留在 **Security** 面板中，供你审查。应用补丁后，请重新发布应用，确保生产版本包含该修复。

Auto-Protect 仅涵盖依赖项 CVE。如需审查应用程序代码，请使用 [Agent 安全扫描](/zh/ko/features/security/agent-security-scans)。

两项 Auto-Protect 设置默认均为关闭状态。

<Steps>
  <Step title="启用补丁准备">
    工作区管理员进入 **Settings** &gt; **Account** &gt; **Advanced**，
    选择 Replit 准备缓解措施的最低严重程度 (low、medium、high、critical) 。
  </Step>

  <Step title="启用安全邮件">
    进入 **Settings** &gt; **Personalization** &gt; **Email Notifications**，
    选择你希望收到通知的最低严重程度。
  </Step>
</Steps>

每当出现新漏洞时，Replit 会针对每个工作区最多发送一封邮件，汇总所有受影响的项目。在应用补丁前，请选择 **Go to Task** 查看 Agent 准备好的补丁。应用补丁后，该漏洞会一直标记为 **pending republish**，直到你发布新版本为止。

<Note>
  Agent 准备的缓解措施与其他 Agent task 一样计费，包括 Auto-Protect
  主动准备的情况。
</Note>

<div id="section-3">
  ## 发现的问题审查
</div>

安全结果会显示在 **Security** 面板中，并按严重程度分组。

| 严重程度    | 说明               |
| ------- | ---------------- |
| 严重      | 必须在发布前解决的紧急风险    |
| 高       | 在特定条件下可能被利用的严重问题 |
| 中       | 被利用可能性较低的潜在风险    |
| 低 / 信息性 | 轻微问题及最佳实践建议      |

在接受、修复或忽略每个发现的问题前，请先进行审查。将已批准的问题交由 Agent 解决，应用修复后重新运行相应的扫描。

<div id="section-4">
  ## 开发和发布期间的安全检查
</div>

<div id="section-5">
  ### 构建期间的安全扫描
</div>

在使用 Agent 构建的过程中，Replit 会自动检查 Agent 修改过的文件，查找常见的不安全模式和硬编码的密钥。这并不是对整个代码库的全面审查，而是 Agent 工作流中的一项轻量级初步检查。检查结果不会作为独立报告显示在 **Security** 面板中。

<div id="section-6">
  ### 发布检查
</div>

Replit 还会在发布前运行安全扫描。**Block publishing of critical vulnerabilities** 设置决定扫描发现严重问题时的处理方式。

* **On**：在问题解决或被忽略前，将阻止发布。
* **Off**：发布将继续进行，发现的问题会保留以供审核。

企业版组织可以要求所有应用启用此设置。

这些检查是对完整的 [Agent 安全扫描](/zh/ko/features/security/agent-security-scans) 或 [Level 3 扫描](/zh/ko/features/security/black-box-pen-tests) 的补充，不能替代它们。
