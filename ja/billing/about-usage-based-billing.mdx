公開の使用量ベース請求には3種類あります：

1. アウトバウンドデータ転送
2. オートスケールコンピュートユニット
3. リクエスト

使用量は**設定**の**アカウント** → **アカウント使用量**で確認できます。請求は毎月、または累積コストが月次クレジットを超えた時点で行われます。Replit CoreおよびProユーザーはこれらのリソースに月次上限が設定されています。

月次サブスクリプション上限を超えて追加クレジットが必要な場合は、請求ページでクレジットパックを購入できます。クレジットパックの詳細については[支出管理](/ja/billing/managing-spend)をご覧ください。

# 公開

## 1. 公開アウトバウンドデータ転送

この種類の使用量はバイト単位で課金され、Replit CoreおよびProユーザーには月次上限が設定されています。この上限に対してカウントされるのはエグレス（送信）データのみで、超過が発生する可能性があります。対照的に、イングレス（受信）データは常に無料です。

| サブスクリプション   | 上限                                                     |
| ----------- | ------------------------------------------------------ |
| Replit Core | 100 GiB                                                |
| Replit Pro  | [Replit Proの料金](https://www.replit.com/pricing)をご覧ください |

上限は[スタティック](/ja/features/publishing/deployment-types#static)、[オートスケール](/ja/features/publishing/deployment-types#autoscale)、[予約VM](/ja/features/publishing/deployment-types#reserved-vm)、および[スケジュール済み](/ja/features/publishing/deployment-types#scheduled)デプロイメントに適用されます。

アウトバウンドデータ転送の現在の価格については[料金ページ](https://www.replit.com/pricing)をご覧ください。

***

## 2. コンピュートユニット

オートスケールデプロイメントは、時間経過に伴うCPUとRAMの使用量の両方を考慮したコンピュートユニットに基づいて課金されます。

超過分はコンピュートユニットに基づいて課金されます。請求の粒度は個々のコンピュートユニットまで細かく設定されています。コンピュートユニットの現在の価格については[料金ページ](https://www.replit.com/pricing)をご覧ください。

オートスケールデプロイメントのRAMとCPU秒がコンピュートユニットにどのように変換されるかの内訳は以下の通りです：

| リソース   | コンピュートユニット |
| ------ | ---------- |
| 1 RAM秒 | 2ユニット      |
| 1 CPU秒 | 18ユニット     |

スタティックデプロイメントはコンピュートユニットを消費しません。その請求は[指定された量](#)を超えるアウトバウンドデータ転送のみに対して行われます。

[オートスケールデプロイメントについて詳しく学ぶ](/ja/features/publishing/deployment-types#autoscale)。

***

## 3. リクエスト

オートスケールデプロイメントはリクエスト数も考慮します。

リクエストの現在の価格については[料金ページ](https://www.replit.com/pricing)をご覧ください。

# データベース

Replitは[本番データベース](/ja/features/data-and-storage/development-and-production)の使用量のみ課金します—開発データベースは常に無料で、すべてのReplitアプリに含まれています。開発データベースの詳細については[開発データベース](/ja/features/data-and-storage/sql-database)をご覧ください。

Replit PostgreSQLはフルマネージドかつサーバーレスで、手間のかからない高可用性とゼロメンテナンスを提供します。本番データベースの請求は実際の使用量に基づいており、大幅なコスト削減につながる可能性があります。

本番PostgreSQLデータベースは2つの使用量メトリクスに基づいて課金されます：

* **[コンピュート時間](#compute-time)**: 1時間あたりに消費されるコンピュートリソースの量。
* **[データストレージ](#data-storage)**: 保存されたデータ（履歴データを含む）の総量。

本番データベースの使用量を含む現在のリソース使用量は、**設定** → **アカウント** → **アカウント使用量**で確認できます。

## コンピュート時間

コンピュート時間は、指定された請求期間中にデータベースがアクティブな状態を維持した時間数によって決まります。データベースはリクエストを受信した時点と、最後のリクエストから追加の5分間はアクティブとみなされます。データベースが5分間アイドル状態のままの場合、サスペンドされて非アクティブ状態に入ります。

## データストレージ

データストレージは、アカウント内のすべてのデータベースにわたって保存されたデータの総量で、ギビバイト（GiB）単位で測定されます。ストレージは月ごとに使用された最大ストレージ量として計算されます。各PostgreSQLデータベースは、データが含まれていない場合でも33MBのストレージを消費します。これはPostgresサーバーのデフォルトのストレージフットプリントです。

<Note>各本番データベースの合計ストレージ制限は10ギビバイト（GiB）です。開発データベースにはReplitアプリごとに20 GiBの無料ストレージが含まれています。</Note>

# 補足事項

支払い方法に問題がある場合は通知します。支払いの失敗が続くと、公開済みアプリが停止される可能性があります。この場合は[サポートに連絡](https://replit.com/help)し、サービスへのアクセスを回復するために支払い詳細を更新してください。
