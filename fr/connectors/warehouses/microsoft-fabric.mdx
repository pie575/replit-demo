Créez des applications propulsées par l&#39;IA dans Replit et publiez-les directement dans Microsoft Fabric, avec une gouvernance et une sécurité de niveau entreprise intégrées d&#39;emblée. L&#39;intégration Microsoft Fabric transforme des données d&#39;entreprise gouvernées en outils internes : dashboards, workflows et applications d&#39;IA. Les équipes passent du prompt à la production plus rapidement, tandis que l&#39;authentification et les politiques d&#39;accès restent au sein de l&#39;environnement Fabric auquel elles font déjà confiance.

<div id="what-a-fabric-data-app-is">
  ## Qu&#39;est-ce qu&#39;une application de données Fabric
</div>

Une application de données Fabric est une application React statique qui affiche des graphiques Power BI en exécutant des requêtes [Data Analysis Expressions (DAX)](https://learn.microsoft.com/en-us/dax/) sur un [modèle sémantique Power BI](https://learn.microsoft.com/en-us/power-bi/connect-data/service-datasets-understand). Quelques caractéristiques déterminent la façon dont vous la concevez :

* **Les modèles sémantiques Power BI constituent la source de données.** Les graphiques sont alimentés par des requêtes DAX exécutées sur les modèles sémantiques (jeux de données) que vous connectez.
* **En lecture seule par conception.** L&#39;application lit les données avec l&#39;instruction DAX `EVALUATE` ; elle n&#39;écrit rien dans Power BI. Si vous avez besoin d&#39;un état modifiable, utilisez une base de données applicative distincte, en complément du dashboard.
* **Rendu assuré par le portail Fabric.** La couche de données s&#39;exécute dans le portail Microsoft Fabric, qui exécute vos requêtes sur le modèle sémantique et renvoie les résultats à l&#39;application. Vos données restent dans votre environnement Fabric.
* **Hébergement sur l&#39;infrastructure Microsoft.** Une fois terminée, vous pouvez publier votre application de données sur l&#39;hébergement Microsoft afin qu&#39;elle s&#39;exécute aux côtés du reste de votre environnement Fabric.

<Note>
  Les applications de données Microsoft Fabric nécessitent l&#39;accès à un locataire Microsoft Fabric doté de modèles sémantiques Power BI et, pendant la préversion, l&#39;adhésion au programme de testeurs approuvés.
</Note>

En coulisses, [Rayfin](https://github.com/microsoft/rayfin) (un SDK et une CLI open source pour créer des backends d&#39;applications) permet à Agent de définir et de publier des applications prêtes pour la production à partir de vos données Fabric.

Tout se fait dans un seul flux de travail : décrivez l&#39;application, laissez Agent en générer la structure, connectez-vous à des données Fabric gouvernées, puis publiez pour une exécution au sein du locataire Fabric de votre organisation.

Ce guide couvre le parcours du builder, la façon dont l&#39;application se connecte aux données Fabric et les options pour les équipes et l&#39;automatisation. Pour les tableaux de bord de données généraux adossés à d&#39;autres entrepôts, consultez [Visualisation de données](/fr/features/artifact-types/data-apps).

<div id="use-cases">
  ## Cas d&#39;usage
</div>

Pour les organisations déjà investies dans l&#39;écosystème de données Microsoft, c&#39;est une voie beaucoup plus rapide vers les logiciels internes. Au lieu de passer des semaines à assembler l&#39;authentification, les API, les outils de déploiement et les politiques de gouvernance, les équipes décrivent ce qu&#39;elles veulent et laissent Agent le construire.

Voici quelques cas d&#39;usage courants :

* Des outils de productivité propres à un service
* Des tableaux de bord opérationnels
* Des outils d&#39;exploration de données
* Des applications d&#39;automatisation de workflows
* Des interfaces de reporting

Côté informatique d&#39;entreprise, la gouvernance, l&#39;authentification et la sécurité restent au sein de l&#39;environnement Fabric que votre organisation gère déjà : la création rapide d&#39;applications ne se fait donc pas au détriment du contrôle centralisé.

<div id="build-a-fabric-data-app">
  ## Créer une application de données Fabric
</div>

Le parcours de création se déroule sous forme de conversation. Vous restez dans Replit du début à la fin ; l&#39;authentification et l&#39;accès aux données se font via Microsoft, lorsque cela vous est demandé.

<Steps>
  <Step title="Partir du template Fabric">
    Sur la page d&#39;accueil de Replit, ouvrez le menu déroulant **Templates** et choisissez **Microsoft Fabric App** sous **Org templates**. Agent bascule alors dans le flux de création d&#39;applications de données, avec l&#39;outillage Fabric préchargé.

    <Frame caption="Sélection du template d'organisation Microsoft Fabric App sur la page d'accueil de Replit (interface en préversion privée).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Page d'accueil de Replit avec le menu déroulant Templates ouvert, montrant Microsoft Fabric App mis en évidence sous Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Décrire le dashboard souhaité">
    Rédigez un prompt décrivant le dashboard ou l&#39;outil de reporting à créer. Par exemple : « Crée un dashboard de croissance des ventes d&#39;un mois sur l&#39;autre à partir de notre modèle de ventes Fabric. » Nul besoin d&#39;écrire du DAX : Agent génère les requêtes.
  </Step>

  <Step title="Se connecter avec Microsoft">
    Lorsque vous y êtes invité, connectez-vous avec OAuth Microsoft sur le locataire qui héberge vos données Fabric. Agent est ainsi autorisé à lire les modèles sémantiques auxquels vous avez accès. L&#39;identité utilisée pour la connexion doit avoir accès au workspace Fabric que vous souhaitez utiliser.
  </Step>

  <Step title="Ajouter vos sources de données">
    Lorsque Agent vous le demande, partagez le modèle sémantique Power BI / Fabric que vous souhaitez utiliser. Vous pouvez fournir soit l&#39;URL complète du jeu de données depuis le portail Fabric (par exemple, `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`), soit l&#39;ID du workspace accompagné de l&#39;ID du jeu de données ou de l&#39;élément. Agent s&#39;en sert pour identifier le workspace et le modèle sémantique à interroger.

    Le modèle doit être **publié sur le service Power BI** : les fichiers `.pbix` locaux ne peuvent pas être utilisés.

    <Frame caption="Agent demandant le lien du modèle sémantique Power BI / Fabric (interface en préversion privée).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Panneau Agent demandant au builder de partager le modèle sémantique Power BI ou Fabric, sous forme d'URL complète du portail Fabric ou d'ID de workspace accompagné de l'ID de jeu de données ou d'élément, en précisant que les fichiers .pbix locaux ne peuvent pas être utilisés car le modèle doit être publié sur le service Power BI" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Laisser Agent construire et itérer">
    Agent explore le schema du modèle sémantique, écrit les requêtes DAX et assemble le dashboard avec les graphiques appropriés. Examinez le résultat et demandez des modifications en langage naturel : ajouter un filter, changer un type de graphique ou ajouter une autre métrique.
  </Step>

  <Step title="Publier (facultatif)">
    Une fois le dashboard prêt, vous pouvez le publier sur l&#39;hébergement de Microsoft afin qu&#39;il s&#39;exécute dans votre environnement Fabric. La publication fait l&#39;objet d&#39;un guide distinct ; celui-ci se concentre sur la connexion aux données et la création de l&#39;application.
  </Step>
</Steps>

<div id="connecting-to-fabric-data">
  ## Connexion aux données Fabric
</div>

Pour lire les données, l&#39;app a besoin d&#39;une connexion autorisée à Microsoft Fabric. Replit établit cette connexion de deux façons possibles.

<div id="app-level-fabric-sign-in-viewers">
  ### Connexion à Fabric au niveau de l&#39;App (observateurs)
</div>

Les observateurs d&#39;une App de données publiée n&#39;ont jamais à configurer de connecteur. Ils s&#39;authentifient via l&#39;authentification unique Microsoft Fabric intégrée à l&#39;App, et celle-ci lit les données sous leur identité par l&#39;intermédiaire du portail Fabric. L&#39;accès reste ainsi régi par vos autorisations Fabric existantes.

<div id="the-microsoft-fabric-connector-the-easy-path-for-builders">
  ### Le connecteur Microsoft Fabric (la solution la plus simple pour les créateurs)
</div>

Pour les créateurs, le **connecteur Microsoft Fabric** est le moyen le plus pratique d&#39;autoriser l&#39;accès aux données pendant le développement. Il reste facultatif : c&#39;est une facilité, pas une obligation.

* Le premier créateur qui le configure effectue une **authentification OAuth unique** auprès de Microsoft.
* Les autres collaborateurs **du même project héritent** de cette connexion.
* Un **autre workspace** doit activer le connecteur et effectuer sa propre authentification OAuth.
* L&#39;identité authentifiée via OAuth doit avoir accès au workspace Fabric cible.

Le connecteur utilise Microsoft Entra OAuth et est limité à votre locataire. Gérez-le depuis la page [Intégrations](/fr/features/integrations/overview) de votre project, comme n&#39;importe quel autre connecteur Replit. Pour approfondir les concepts liés aux connecteurs, consultez [Gérer vos connecteurs](/fr/replitai/managing-connectors).

<Note>
  Pendant la préversion privée, aucun identifiant partagé géré par Replit n&#39;est disponible pour le connecteur Microsoft Fabric. Les créateurs s&#39;authentifient auprès de leur propre locataire Microsoft Entra.
</Note>

<div id="teams-and-automation">
  ## Teams et automatisation
</div>

Pour un usage partagé en équipe ou dans des environnements non interactifs (comme la CI), l&#39;OAuth interactif n&#39;est pas toujours envisageable. Dans ce cas, fournissez un jeton de **principal de service** via les [Secrets](/fr/core-concepts/project-editor/app-setup/secrets) de votre project plutôt que de vous connecter de façon interactive. L&#39;app utilise l&#39;identité du principal de service pour lire les données Fabric.

C&#39;est l&#39;équivalent le plus proche d&#39;une configuration machine à machine : une identité non humaine, provisionnée dans Microsoft Entra et dotée d&#39;un accès au workspace Fabric, authentifie l&#39;app sans aucune intervention humaine. Vérifiez que le principal de service dispose bien d&#39;un accès aux workspace et aux modèles sémantiques interrogés par l&#39;app.

<div id="troubleshooting">
  ## Dépannage
</div>

<AccordionGroup>
  <Accordion title="Les données ne se chargent pas dans le Preview de l'app">
    La couche de données Fabric transite par le portail Microsoft Fabric. Si les graphiques s&#39;affichent vides ou si le Preview de l&#39;app ne parvient pas à charger les données, vérifiez que vous avez bien effectué la connexion Microsoft et que l&#39;identité connectée a accès au workspace et au modèle sémantique que vous avez liés.
  </Accordion>

  <Accordion title="Agent ne trouve pas votre modèle sémantique">
    Assurez-vous d&#39;avoir collé le lien du jeu de données Power BI depuis le portail Fabric et que votre identité (ou principal de service) dispose au minimum d&#39;un accès en lecture à ce workspace. Repartagez le lien du jeu de données si Agent signale qu&#39;il ne parvient pas à résoudre le workspace ou le modèle.
  </Accordion>

  <Accordion title="Le connecteur est bloqué ou demande sans cesse de se connecter">
    Réautorisez le connecteur Microsoft Fabric depuis la page [Intégrations](/fr/features/integrations/overview) du project. Vérifiez que l&#39;identité OAuth dispose bien d&#39;un accès au workspace Fabric. Pour une utilisation en équipe ou en CI, privilégiez un jeton de principal de service fourni via Secrets.
  </Accordion>
</AccordionGroup>
