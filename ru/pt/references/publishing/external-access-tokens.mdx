title: "Токены внешнего доступа"
description: "Разрешите CI-пайплайнам, вебхукам и другим автоматизированным сервисам получать доступ к вашему приватному приложению Replit без входа в систему."
---

Токены внешнего доступа — это bearer-токены, созданные для конкретного Replit App.
Они позволяют автоматизированным сервисам — CI-пайплайнам, вебхукам, средствам проверки статуса, ботам Slack,
внутренним скриптам — получать доступ к приложению, даже если его URL защищён
[приватным URL для разработки](/ru/pt/features/publishing/private-deployments)
или [приватным deployment](/ru/pt/features/publishing/private-deployments).

Относитесь к каждому токену как к паролю: любой, кто им владеет, может получать доступ к вашему приложению,
пока срок действия токена не истечёт или он не будет отозван.

<Note>
  Токены внешнего доступа доступны на тарифах Replit Core и Pro.
  Клиенты Enterprise должны запросить активацию у Replit, прежде чем эта функция будет
  включена в их workspace. Токены появляются в настройках публикации
  только после того, как deployment будет настроен как приватный.
</Note>

<div id="quando-usar-um-token">
  ## Когда использовать токен
</div>

Используйте внешний токен доступа, когда к вашему приватному Replit App должно
обращаться что-то *за пределами* браузера. Типичные случаи:

* Рабочий процесс GitHub Actions, который при каждом коммите выполняет smoke-тест
  по вашему dev-URL.
* Монитор доступности (Better Stack, Pingdom, UptimeRobot), обращающийся к
  эндпоинту проверки состояния опубликованного приложения.
* Приёмник вебхуков — Stripe, Slack, GitHub — отправляющий POST-запросы в приватный Deployment.
* Вызов `curl` или `fetch` с машины коллеги по команде во время отладки.

Токены внешнего доступа предназначены для **трафика API**, а не для открытия страниц
интерфейса в браузере. Одностраничные приложения (Vite, Next.js и т. д.) подгружают
JavaScript-бандлы последующими запросами, в которых токен не передаётся, поэтому такие запросы
завершатся ошибкой. Для интерактивной навигации выполняйте вход обычным способом.

<div id="ambientes-de-token">
  ## Среды токенов
</div>

Каждый токен привязан к определённой среде:

| Среда         | Где работает                                                             | Для чего использовать                               |
| :------------ | :----------------------------------------------------------------------- | :-------------------------------------------------- |
| `Development` | URL для разработки в workspace App (`*.replit.dev`)                      | Доступа к запущенному App во время разработки       |
| `Production`  | Опубликованный deployment App (`*.replit.app` и пользовательские домены) | Доступа к приватному deployment из внешних сервисов |

Токен `Production` привязан к *текущему опубликованному* deployment. Если вы
повторно опубликуете приложение в новом deployment, существующие Production-токены перестанут работать,
и вам потребуется создать новые.

<div id="criar-um-token-de-acesso-externo">
  ## Создание внешнего токена доступа
</div>

<Steps>
  <Step>
    Откройте приложение, которое хотите сделать доступным извне, а затем откройте инструмент **Publishing**.
  </Step>

  <Step>
    Выберите **Adjust settings**, чтобы развернуть параметры повторной публикации.
  </Step>

  <Step>
    В разделе **Security** найдите пункт **External access tokens**.
  </Step>

  <Step>
    Выберите **Create access token** и заполните поля:

    * **Label** (необязательно): короткое название, по которому вы позже узнаете токен,
      например `CI` или `Stripe webhook`. Максимум 120 символов.
    * **Environment**: выберите `Development` или `Production` в зависимости от того, откуда
      вызывающему сервису нужен доступ к приложению.
    * **Expires after**: выберите срок действия — `1 hour`, `24 hours`, `7 days`,
      `30 days`, `3 months`, `1 year` или `5 years`. Выбирайте наименьший срок,
      которого хватит для вашей задачи. Варианта «никогда не истекает» нет.
  </Step>

  <Step>
    Выберите **Create**.
  </Step>
</Steps>

Replit показывает токен **только один раз**. Скопируйте его сразу — после закрытия диалогового окна
посмотреть токен снова уже не получится. Если вы его потеряли, отзовите этот токен и создайте новый.

На экране с токеном доступны два варианта копирования:

* **Copy query parameter** — копирует `?project-protection-bypass=<token>`
  для добавления к URL. Удобно для быстрых проверок через `curl`.
* **Copy token only** — копирует сам токен, пригодный для передачи в
  заголовке `Authorization: Bearer`.

<Info>
  Создание первого токена автоматически включает внешний доступ для приложения, если
  он ещё не включён. Без защиты токену нечего обходить.
</Info>

<div id="usar-um-token">
  ## Использование токена
</div>

Передайте токен одним из двух способов:

<div id="cabealho-authorization-recomendado">
  ### Заголовок Authorization (рекомендуется)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

Это правильный выбор практически для всего — вебхуки, CI-скрипты,
вызовы между бэкендами. Токен никогда не попадает в логи, где записываются URL,
и не остаётся в истории браузера.

<div id="query-parameter">
  ### Параметр запроса
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

Используйте формат query parameter только в тех случаях, когда задать заголовки невозможно — например,
если сервис принимает лишь URL. URL-адреса с токенами часто попадают в логи прокси,
историю Shell и скриншоты, поэтому по возможности используйте вариант с заголовком.

<div id="gerenciar-tokens-existentes">
  ## Управление существующими токенами
</div>

В разделе **External access tokens** перечислены все токены, созданные вами для
приложения, — от новых к старым — с указанием метки, среды, даты создания,
срока действия и статуса отзыва. В каждой строке показаны последние символы токена,
чтобы вам было проще их различать, так как полное значение отображается только
в момент создания.

Вы видите только те токены, которые создали *вы*. Токены других участников доступны
только им, даже если вы владелец приложения.

<div id="revogar-um-token">
  ## Отзыв токена
</div>

Отзывайте токен, как только он становится не нужен, или сразу же при подозрении,
что он мог быть скомпрометирован. Чтобы отозвать токен:

<Steps>
  <Step>
    Откройте раздел **External access tokens** в настройках публикации приложения.
  </Step>

  <Step>
    Найдите токен в списке и нажмите значок корзины.
  </Step>

  <Step>
    Подтвердите отзыв.
  </Step>
</Steps>

Отзыв выполняется **немедленно и необратимо**. Весь трафик, который всё ещё
использует этот токен, начнёт отклоняться в течение нескольких секунд. Если доступ
понадобится снова, создайте новый токен.

Отзывать можно только те токены, которые вы создали сами. При удалении участника из
workspace все созданные им токены для этого приложения отзываются автоматически.

<div id="mantenha-seus-tokens-seguros">
  ## Храните токены в безопасности
</div>

Внешние токены доступа — это учётные данные. Обращайтесь с ними так же
осторожно, как с ключом API или паролем.

<div id="faa">
  ### Что делать
</div>

* **Храните токены в менеджере секретов** — секреты GitHub Actions, хранилище вашего
  CI-провайдера, репозиторий секретов облачного провайдера или менеджер паролей.
  Никогда не коммитьте их в репозиторий.
* **По возможности используйте короткий срок жизни.** Токен на 7 дней для разовой
  интеграции безопаснее, чем токен на 5 лет, оставленный без присмотра.
* **Помечайте каждый токен** ярлыком, чтобы позже вы могли понять, для чего он нужен и используется ли
  он до сих пор. Токены без ярлыка первыми утекают и последними отзываются.
* **Создавайте отдельный токен для каждого потребителя.** Один токен на CI-задачу, один на
  источник вебхуков, один на проверку доступности. Если что-то будет скомпрометировано — или
  подрядчик больше не нужен — вы отзовёте только этот токен.
* **Предпочитайте заголовок `Authorization`** параметрам запроса, чтобы токен
  не утёк через логи URL, историю браузера или заголовки referer.
* **Немедленно отзывайте токен**, если он мог быть раскрыт: утёкший лог,
  коммит в публичном репозитории, демонстрация экрана, ноутбук бывшего сотрудника.
  Отзыв вступает в силу сразу; замену создадите потом.

<div id="no-faa">
  ### Чего не делать
</div>

* **Не используйте один token совместно с коллегами или сервисами.** Если две системы
  используют один token, вы не сможете отозвать его для одной, не затронув другую.
* **Не вставляйте tokens в чат, электронную почту, снимки экрана или трекеры задач.**
  Эти каналы архивируются, индексируются и распространяются непредсказуемым образом.
* **Не встраивайте tokens в клиентский код** — браузерные приложения, мобильные приложения,
  десктопные бинарные файлы. Всё, что попадает на устройство пользователя, следует считать
  публичным.
* **Не полагайтесь на tokens для сессий в браузере.** Tokens подходят для вызовов API,
  а не для загрузки SPA во вкладке браузера. Для этого используйте обычный вход в Replit.
* **Не ставьте срок действия 5 лет по умолчанию.** Подбирайте время жизни под реальный
  период доступа, который нужен потребителю.

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

<Accordion title="Мой production-токен внезапно перестал работать">
  Production-токены привязаны к конкретному опубликованному deployment. Если вы
  опубликовали приложение заново — например, изменили тип deployment или
  удалили и создали deployment заново — существующие production-токены
  становятся недействительными. Создайте новый токен в настройках нового deployment.
</Accordion>

<Accordion title="Мой токен работает с `curl`, но в браузере по-прежнему открывается страница входа">
  Токены внешнего доступа предназначены для трафика API, а не для
  браузерных сеансов. Когда одностраничное приложение загружается в браузере, начальный
  HTML-запрос может передать токен через query parameter, но последующие запросы
  бандлов JavaScript, CSS и вызовы API его уже не содержат и будут
  отклонены. Чтобы работать с приложением интерактивно, войдите в Replit обычным способом.
</Accordion>

<Accordion title="Я потерял токен — можно посмотреть его снова?">
  Нет. Replit показывает токен только один раз — в момент создания. В списке отображаются
  метаданные (label, среда, срок действия, последние символы), но никогда — полное
  значение токена. Если вы его потеряли, отзовите этот токен и создайте новый.
</Accordion>
