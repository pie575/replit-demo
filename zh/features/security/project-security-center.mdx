Project Security Center 是查找并修复 Replit App 中安全和隐私漏洞的集中位置。在项目的 **Tools** 面板中，选择 **Security Center** 以运行扫描、查看发现项，并将已确认的问题发送给 Agent 修复。

<Note>
  刚接触依赖项安全？请参阅[安全
  概念](/zh/features/security/concepts)，了解 CVE、SBOM、暴露、使用 Agent 修复、重新发布和 Auto-Protect 的定义。
</Note>

<div id="automatic-dependency-scans">
  ## 自动依赖项扫描
</div>

自动依赖项扫描会将项目中的软件包与公开的漏洞记录进行比对。扫描免费且自动运行。当披露新的 Common Vulnerabilities and Exposures (CVE) 条目时，Replit 会将其与你的项目依赖项进行比对，并在 **Security** 窗格中显示匹配项，无需手动重新扫描。

依赖项扫描支持 Node.js/npm、Python、Go、Rust、PHP 和 Ruby。

自动修复依赖项目前主要支持 Node.js/npm。

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect 在自动依赖项扫描的基础上提供进一步保护。当 Replit 检测到相应漏洞时，Agent 会准备并测试补丁，并通过电子邮件向你发送直达链接。补丁会在 **Security** 窗格中处于待处理状态，等待你审核。应用补丁后，请重新发布 App，以确保生产版本包含该修复。

Auto-Protect 仅涵盖依赖项 CVE。请使用 [Agent 安全扫描](/zh/features/security/agent-security-scans) 审查应用代码。

两项 Auto-Protect 设置默认均处于关闭状态：

<Steps>
  <Step title="启用补丁准备">
    Workspace 管理员前往 **Settings** &gt; **Account** &gt; **Advanced**，然后
    选择 Replit 应开始准备修复措施的最低严重性级别 (低、中、高或严重) 。
  </Step>

  <Step title="启用安全邮件">
    前往 **Settings** &gt; **Personalization** &gt; **Email Notifications**，然后
    选择你希望接收通知的最低严重性级别。
  </Step>
</Steps>

对于每个新漏洞，Replit 每个 Workspace 最多发送一封邮件，汇总所有受影响的项目。选择 **Go to Task**，在应用前检查由 Agent 准备的补丁。应用补丁后，该漏洞会显示为 **待重新发布**，直到你发布新版本。

<Note>
  Agent 准备的修复措施与其他 Agent 工作一样计费，包括
  Auto-Protect 主动准备这些修复措施时。
</Note>

<div id="review-findings">
  ## 审查发现项
</div>

安全结果会显示在 **Security 窗格** 中，并按严重程度分组：

| 严重程度    | 说明                |
| ------- | ----------------- |
| 严重      | 应在发布前处理的紧急风险      |
| 高       | 在特定条件下可能遭到利用的严重问题 |
| 中       | 被利用可能性较低的潜在风险     |
| 低 / 信息性 | 次要问题和最佳实践建议       |

在接受、修订或忽略每项发现项之前，请先进行审查。将已接受的问题交给 Agent 修复，然后在应用修复后重新运行相关扫描。

<div id="security-checks-during-development-and-publishing">
  ## 开发和发布过程中的安全检查
</div>

<div id="security-scan-while-you-build">
  ### 构建过程中的安全扫描
</div>

使用 Agent 构建时，Replit 会自动检查 Agent 修改的文件，检测常见的不安全模式和硬编码的 Secrets。这是 Agent 工作流程中的一项早期轻量级检查，并非对整个代码库进行全面审查。检查结果不会以单独报告的形式显示在 **Security 窗格** 中。

<div id="publish-checks">
  ### 发布检查
</div>

Replit 还会在发布前执行安全扫描。**阻止发布存在严重漏洞的 App**设置决定了扫描发现严重问题时的处理方式：

* **开启**：在问题解决或被忽略前，发布将被阻止。
* **关闭**：发布将继续进行，且发现结果仍可供查看。

Enterprise 组织可以要求所有 App 启用此设置。

这些检查是对完整的 [Agent 安全扫描](/zh/features/security/agent-security-scans) 或 [Level 3 扫描](/zh/features/security/black-box-pen-tests)的补充，而非替代。
