通过导入功能，您可以将现有代码和设计导入 Replit Apps，并使用 Agent 继续构建。

<div id="section">
  ## 支持的来源
</div>

| 来源          | 所需内容                                 | 最适用场景                   |
| ----------- | ------------------------------------ | ----------------------- |
| GitHub      | 仓库 URL 或仓库选择器                        | 导入公开和私有仓库               |
| Bitbucket   | 仓库 URL 或仓库选择器                        | 导入 Bitbucket 托管的仓库      |
| Vercel      | Vercel 项目对应的 GitHub 仓库               | 迁移 Vercel 应用            |
| Figma       | 框架 URL                               | 将设计转换为 React 应用         |
| Claude      | 从 Claude 发送的设计                       | 将 Claude 设计转换为交互式应用     |
| Bolt        | 从 Bolt 导出的 GitHub 仓库                 | 迁移 Bolt 项目              |
| Lovable     | 从 Lovable 导出的 GitHub 仓库              | 迁移 Lovable 项目           |
| Base44      | 从 Base44 导出的 GitHub 仓库               | 迁移 Base44 项目            |
| ZIP         | 上传 `.zip` 文件                         | 导入本地项目存档                |
| 电子表格        | `.xlsx`、`.csv` 文件或 Google Sheets URL | 基于电子表格数据构建应用            |
| 早期 Agent 导出 | 从早期 Agent App 导出的 GitHub 仓库          | 重新导入早期的 Agent App       |
| 空白          | 无                                    | 希望不使用 Agent 创建空白项目的高级用户 |

<Note>Replit 会在开始导入前验证兼容性。</Note>

关于 Figma 设计，请参阅[将 Figma 设计导入 Replit Design](/zh/ja/design/import-figma-designs-into-replit-design)。

关于从 Claude 发送的设计，请参阅[将 Claude 设计导入 Replit Design](/zh/ja/design/import-claude-designs-into-replit-design)。

  <Tab title="GitHub">
    ⏰ *预计用时：2 分钟*

    将 GitHub 仓库导入 Replit，更快地运行、测试和发布。

    **开始前的准备**

    * GitHub 仓库 URL
    * 仓库访问权限 (公开或私有)
    * Replit 账户

    **方式一：快速导入**

    快速导入适用于公开仓库。

    1. 复制 `github.com/` 之后的仓库路径。
    2. 打开 `https://replit.com/github.com/<owner>/<repo>`。
    3. 按回车键开始导入。

    *示例*

    * GitHub URL：`https://github.com/exampleUser/my-app`
    * Replit 导入 URL：`https://replit.com/github.com/exampleUser/my-app`

    **方式二：引导式导入**

    引导式导入同时支持公开和私有仓库。

    1. 打开 [replit.com/import](https://replit.com/import)。
    2. 选择 **GitHub**。
    3. 连接 GitHub 账户。
    4. 选择仓库。
    5. 选择 **导入**。

    **会导入的内容**

    * 仓库文件和文件夹
    * 依赖文件
    * 常见的运行与构建配置

    **不会导入的内容**

    * 现有的 Secrets 值和环境变量值
    * 在 Replit 上默认无法运行的平台专属服务

    **排查 GitHub 连接问题**

    如果出现 `Failed to get repository, please re-authenticate with GitHub`，或仓库下拉列表显示 `No repositories found`，这是因为 GitHub 导入流程所用的连接与 **账户 → 已连接服务** 页面中的连接彼此独立。仅在已连接服务中重新连接，并不能解决导入流程的问题。

    <Steps>
      <Step title="从 Git 提供商重新连接 GitHub">
        打开 Replit 账户设置中的 **Git 提供商** 部分，断开 GitHub 连接，然后在同一页面重新连接。之后，导入时的下拉列表中应会显示你的个人仓库。
      </Step>

      <Step title="为 GitHub 组织授权 Replit 应用">
        如果仓库属于某个 GitHub 组织，请打开 [https://github.com/settings/applications](https://github.com/settings/applications)，找到 Replit OAuth 应用，并在第三方应用访问设置中授予对该组织的访问权限。如果你不是组织所有者，则需要由组织管理员完成此步骤。
      </Step>

      <Step title="重试导入">
        打开 [replit.com/import](https://replit.com/import)，分别通过仓库下拉列表和粘贴仓库 URL 两种方式重试导入。
      </Step>
    </Steps>

<div id="section-3">
  ## 其他来源
</div>

<div id="bitbucket">
  ### Bitbucket
</div>

* 粘贴 Bitbucket 仓库 URL，或连接 Bitbucket 账户以搜索仓库。
* 与 GitHub 托管的项目相比，导入过程中的 Agent 支持可能较为有限。

<div id="section-4">
  ### 电子表格
</div>

* 上传 Excel (`.xlsx`) 或 CSV 文件，或粘贴公开 Google Sheets 的 URL。
* Agent 会读取电子表格的结构，并构建一个全栈应用，其中的数据库将根据数据进行初始化。
* 包含用于查看、搜索和管理记录的界面。

<div id="agent">
  ### 之前导出的 Agent
</div>

* 重新导入之前从 GitHub 仓库导出的 Agent App。
* Replit 会保留 Agent 特有的结构 (代码、数据库架构和后端功能) 。
* 不会导入数据库值和密钥值。

<div id="section-5">
  ### 空白
</div>

* 从完全空白的项目开始：没有 Agent、无需选择框架、也不生成脚手架代码。
* 非常适合希望完全掌控项目配置的高级用户。

<div id="section-6">
  ## 限制
</div>

* 不会迁移现有数据库中的数据。
* ZIP 上传大小限制为 200 MB。
* 复杂或自定义的依赖项可能需要手动配置。
* 大型项目可能需要更长的处理时间。

<div id="section-7">
  ## 最佳实践
</div>

* 导入前请删除敏感信息。
* 保持源项目的结构整洁。
* 导入后请检查依赖项和运行命令。
* 发布前请测试核心流程。

<div id="section-8">
  ## 故障排查
</div>

如果导入失败，请先检查以下几个方面：

* **兼容性错误**：确认项目所需文件是否齐全，以及框架是否受支持。
* **访问错误**：检查代码仓库或来源的访问权限。
* **处理错误**：简化项目结构或缩减项目大小后重试。

如果问题仍未解决，请访问 [Replit 社区中心](https://replit.com/community)或[联系支持团队](https://replit.com/support)。
