Вы уже видели Velocity в разделе [Добро пожаловать в Replit](/ru/pt/build/welcome) — это премиальное приложение для аренды суперкаров. Сейчас любой, кто открывает публичный URL, видит все бронирования. Но никто не арендует Lamborghini анонимно. Добавьте вход в систему — и у каждого клиента появятся свои бронирования и сохранённые автомобили.

<div id="pea-ao-agent-para-adicionar-o-login">
  ## Попросите Agent добавить вход
</div>

Для Velocity используйте Clerk. Интеграция Clerk с Replit добавляет в ваше приложение экран входа в фирменном стиле, учётные записи клиентов внутри Velocity (а не учётные записи Replit) и полный контроль над внешним видом — всё, что нужно премиальному бренду аренды. Agent автоматически настроит всё необходимое: вам не потребуется регистрироваться в панели Clerk или вставлять ключи.

Agent создаст tenant Clerk для Velocity, добавит компоненты входа, защитит процесс бронирования, свяжет каждое бронирование с вошедшим клиентом и добавит выход. Следите за ходом работы в Chat Agent.

<div id="teste-com-dois-clientes">
  ## Проверка с двумя клиентами
</div>

Одной учётной записи мало — нужны две, чтобы убедиться, что бронирования не пересекаются.

1. Откройте Velocity в Preview и просмотрите автомобили, не выполняя вход. Автопарк должен оставаться видимым.
2. Нажмите «Забронировать» у любого автомобиля. Вы должны попасть на экран входа Clerk.
3. Зарегистрируйтесь по своему адресу электронной почты и оформите бронирование (например, 911 на выходные).
4. Выйдите из учётной записи. Раздел «Мои бронирования» должен исчезнуть, а при бронировании снова должен запрашиваться вход.
5. Откройте Preview в окне инкогнито и зарегистрируйтесь с другим адресом электронной почты. Забронируйте другой автомобиль.
6. Вернитесь в первое окно, войдите и убедитесь, что вы по-прежнему видите собственное бронирование, а не бронирование второго клиента.

Если оба клиента видят одни и те же бронирования, значит, бронирования пока не привязаны к вошедшему пользователю. Опишите Agent точный симптом:

<AiPrompt>
  Оба клиента видят бронирования друг друга в Velocity.<br />
  Привяжи каждое бронирование и каждый сохранённый автомобиль к вошедшему клиенту, чтобы каждый видел только свои.<br />
  Покажи, как это проверить с помощью двух тестовых учётных записей.
</AiPrompt>

<div id="publicar-e-entrar-na-url-pblica">
  ## Публикация и вход по публичному URL
</div>

Опубликуйте Velocity заново через Chat с Agent или через плитку публикации, затем откройте публичный URL в новой вкладке и войдите. Clerk разворачивается с раздельными окружениями Development и Production — Agent автоматически подключает учётные данные Production к опубликованному приложению, поэтому вход по публичному URL работает без дополнительной настройки.

Теперь у Velocity есть реальные клиенты. Каждый попадает в свой личный гараж бронирований — больше его никто не видит.

<div id="precisa-de-mais-ajuda">
  ## Нужна дополнительная помощь?
</div>

* **Скрыто всё приложение:** попросите Agent оставить каталог автомобилей общедоступным и закрыть доступ только к страницам бронирования и учётной записи.
* **Клиенты видят чужие бронирования:** попросите Agent привязать каждое бронирование и сохранённый автомобиль к текущему авторизованному клиенту.
* **Вход работает в Preview, но не после публикации:** откройте публичный URL в новой вкладке и сообщите Agent точный текст ошибки, которую видите. Убедитесь, что Agent подготовил production-окружение Clerk.
* **Нужен более быстрый вход без настройки — для прототипов:** Replit Auth использует учётные записи Replit ваших клиентов, и вам не придётся управлять тенантом Clerk — см. [Replit Auth](/ru/pt/features/auth-and-identity/authentication).
