Replit Agent 提供两种交互模式：**规划模式**和**构建模式**。结合使用这两种模式，先梳理想法，再自信地完成实现。

<div id="o-que-o-modo-de-planejamento">
  ## 什么是规划模式？
</div>

[规划模式](/zh/pt/features/agent/plan-mode) 让你可以与 Agent 一起头脑风暴、提问和规划工作，而无需修改任何代码。你可以将它视为一场协作式规划会议，在其中自由探索各种想法。

规划模式尤其适合：

* **头脑风暴**：在确定方案前探索不同思路
* **拆分复杂项目**：在开始构建前获得结构化的任务清单
* **学习与理解**：就技术、设计模式或代码提出问题
* **规划架构**：在编写代码前设计应用的结构

<Info>
  在规划模式下，Agent 会读取你的项目并提供指导，但不会对文件做出任何更改。准备实施时，请切换到构建模式，或批准一个计划以自动开始构建。
</Info>

<div id="o-que-o-modo-de-construo">
  ## 什么是构建模式？
</div>

构建模式是默认模式，Agent 会直接在您的项目中编写代码、修改文件并实现功能，让创意成为现实。

准备执行以下操作时，请使用构建模式：

* **创建新功能**：让 Agent 为您的下一个功能编写代码
* **配置您的 App**：安装依赖项、配置数据库并连接服务
* **修复问题**：让 Agent 调试并解决代码中的问题
* **重构代码**：改进现有代码的结构和组织

<div id="usando-ambos-os-modos-juntos">
  ## 同时使用两种模式
</div>

**规划模式和构建模式按顺序配合使用，效果最佳。**先通过规划理清思路，再带着明确的方向开始构建。

<Steps>
  <Step title="从规划模式开始">
    切换到规划模式，描述你想要构建的内容。Agent 会帮助你梳理需求、建议方案并识别潜在挑战，全程不会改动你的代码。
  </Step>

  <Step title="生成任务清单">
    请 Agent 创建开发计划。它会将你的项目拆分为具体、可执行的任务，并明确优先级和依赖关系。

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="包含优先级和依赖关系的任务清单" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="审核并完善">
    审核建议的计划。提出后续问题、请求修改，或探索替代方案。持续迭代，直到计划符合你的设想。
  </Step>

  <Step title="开始构建">
    当你对计划满意后，选择 **开始构建**。Agent 会自动切换到构建模式，并开始实施已批准的任务。

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="显示规划模式和构建模式选项的模式选择器" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="跟踪进度">
    在 Agent 处理任务清单时跟踪其进度。每完成一项任务，都会创建一个 checkpoint，以便你审核更改，并在需要时回滚。
  </Step>
</Steps>

<div id="quando-usar-cada-modo">
  ## 何时使用各个模式
</div>

<CardGroup cols={2}>
  <Card title="在以下情况下使用规划模式" icon="lightbulb">
    * 你正在启动新项目，需要明确方向
    * 你想探索不同的方案
    * 任务较复杂，需要拆分
    * 你想在实施前先了解相关内容
    * 你不确定哪种方案最佳
  </Card>

  <Card title="在以下情况下使用构建模式" icon="hammer">
    * 你确切知道自己想要什么
    * 你已有清晰的计划可供执行
    * 你正在进行快速修复或小幅更改
    * 你正在遵循已批准的任务清单
    * 实施速度是首要优先事项
  </Card>
</CardGroup>

<Tip>
  **不知道该选哪个？** 如果你的需求涉及多个功能或重大更改，请先使用规划模式。对于简单且定义明确的任务，可直接使用构建模式。
</Tip>

<div id="diferenas-principais">
  ## 主要区别
</div>

| 功能       | 规划模式         | 构建模式       |
| -------- | ------------ | ---------- |
| **用途**   | 头脑风暴、规划和学习   | 实现和构建      |
| **代码更改** | 无 — 仅可查看     | 编写和修改文件    |
| **输出**   | 想法、任务清单和指导   | 代码和可用功能    |
| **适用场景** | 复杂项目和探索      | 目标明确的任务和实现 |
| **切换**   | 点击“开始构建”即可切换 | 已处于构建模式    |

<div id="boas-prticas">
  ## 最佳实践
</div>

<div id="aproveitando-ao-mximo-o-modo-de-planejamento">
  ### 充分利用规划模式
</div>

* **明确需求**：提供的细节越多，计划就越完善
* **追问细节**：针对不理解的建议寻求澄清
* **请求示例**：请 Agent 展示代码片段或模式
* **讨论权衡**：探讨不同方法的优缺点
* **迭代完善思路**：不断优化计划，直到满意为止

<div id="transies-perfeitas">
  ### 顺畅衔接
</div>

* **构建前先审查**：批准前务必查看任务清单
* **从小处着手**：如果完整计划让你感到难以应对，先从一部分任务开始
* **使用 checkpoint**：Agent 会在构建过程中创建 checkpoint，因此你随时可以回滚
