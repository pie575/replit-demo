Une application est un logiciel conçu pour accomplir une tâche précise, au bénéfice d&#39;une personne ou d&#39;un groupe donné.

Une application peut être simple ou complexe. Une calculatrice, un formulaire de réservation, un tableau de bord, un outil interne, une expérience mobile, une place de marché ou un portail client : ce sont autant d&#39;applications dès lors qu&#39;ils aident quelqu&#39;un à faire quelque chose d&#39;utile.

<div id="section">
  ## Une application est du code exécuté sur une infrastructure
</div>

Toute application repose sur deux éléments qui fonctionnent ensemble :

* **Code** — les instructions qui décrivent ce que fait l’application : l’interface que les utilisateurs voient, la logique qui réagit aux clics et aux saisies, et les règles qui régissent la circulation des données.
* **Infrastructure** — les machines, réseaux, espaces de stockage et services sur lesquels le code s’exécute afin que d’autres personnes puissent y accéder depuis leur navigateur ou leur téléphone.

Écrire le code est ce à quoi les gens pensent lorsqu’ils parlent de « créer une application ». L’infrastructure regroupe tout ce dont le code a besoin pour fonctionner réellement pour les utilisateurs : des serveurs pour l’exécuter, des bases de données pour stocker les informations, un domaine permettant aux utilisateurs de la trouver, de la sécurité pour la protéger et un moyen de la mettre à jour sans perturber ce qui fonctionne déjà.

Dans Replit, vous décrivez ce que vous souhaitez en langage naturel. Agent écrit le code et Replit fournit l’infrastructure — hébergement, bases de données, secrets, domaines et déploiements. Vous pouvez ainsi publier une application fonctionnelle sans rien configurer vous-même.

<div id="section-2">
  ## Pourquoi créer une application ?
</div>

Vous pouvez créer une application lorsque les outils existants conviennent presque, mais pas tout à fait.

Une application est utile dans les cas suivants :

* Vous souhaitez un flux de travail personnalisé
* Vous atteignez les limites d&#39;un tableur, d&#39;un formulaire ou d&#39;un modèle
* Vous avez besoin d&#39;un processus reproductible
* Vous souhaitez tester la demande pour une idée
* Vous voulez que les membres de votre équipe, vos clients ou vos utilisateurs interagissent avec un outil que vous contrôlez directement

Par exemple, un fondateur peut créer une application de liste d&#39;attente pour tester la demande. Un responsable marketing peut créer une landing page de campagne avec un formulaire. Un analyste de données peut créer un tableau de bord qui facilite l&#39;exploration d&#39;un tableur.

<div id="section-3">
  ## Une application résout un problème ciblé
</div>

Une bonne première application est ciblée : elle résout un problème précis pour un public précis.

Au lieu de commencer par :

```text theme={null}
A platform for managing my entire business.
```

Commencez comme suit :

```text theme={null}
Une page où les clients peuvent demander un devis de traiteur et recevoir un message de confirmation.
```

Une version plus réduite est plus facile à créer, tester, publier et améliorer.

<div id="section-4">
  ## Applications et créations
</div>

Sur Replit, une application est un type de création. Une création est un contenu publiable issu d&#39;un projet.

Une création peut être :

* une application web
* une application mobile
* un tableau de bord de données
* une présentation (slides)
* une vidéo animée
* un design
* une expérience 3D

Les applications sont généralement interactives. Elles permettent aux utilisateurs de soumettre des informations, de consulter des données, de se connecter, de faire des choix ou de mener un flux de travail à son terme. D&#39;autres créations, comme une présentation ou une vidéo animée, sont davantage axées sur la présentation ou la narration.

<div id="section-5">
  ## Le moment où l&#39;application devient réelle
</div>

Une application commence à devenir réelle lorsque quelqu&#39;un d&#39;autre peut l&#39;utiliser, en dehors de votre imagination.

Concrètement, cela signifie généralement que :

* Elle poursuit un objectif clair
* Quelqu&#39;un peut réaliser l&#39;action principale
* Vous pouvez la tester dans le Preview
* Vous pouvez la publier sur une URL partageable
* Vous pouvez l&#39;améliorer après avoir recueilli des retours

La première version n&#39;a pas besoin de proposer toutes les fonctionnalités. Il suffit qu&#39;elle fonctionne assez bien pour vous permettre d&#39;en tirer des enseignements.

<div id="section-6">
  ## Idées reçues courantes
</div>

* **« Une application doit être ambitieuse. »** De nombreuses applications utiles sont de petits outils conçus pour une tâche précise.
* **« Une application doit être publique. »** Certaines applications sont des outils privés destinés à vous, à votre Team ou à vos clients.
* **« Une application doit être parfaite avant d&#39;être publiée. »** Publier une première version ciblée vous révèle ce qu&#39;il faut améliorer.
