Agent는 아이디어를 빠르게 앱으로 구현할 수 있도록 네 가지 유형의 integration을 지원합니다:

* **Replit 관리형**: 자동으로 동작하는 기본 제공 integration입니다. 앱을 만들면 Agent가 바로 사용할 수 있습니다.
* **Connectors**: Replit이 지원하는 자사 integration입니다. 한 번만 로그인하면 Agent가 채팅에서 곧바로 해당 서비스를 읽고 쓸 수 있으며(데이터 가져오기, 레코드 생성, 메시지 전송 등), 여러 앱에서 이를 활용해 개발할 수 있습니다.
* **외부 integration**: 함께 개발할 수 있는 신뢰할 수 있는 서드파티 서비스입니다. Agent에게 설정을 요청하면 되며, API 키는 직접 입력해야 합니다.
* **Agent 서비스**: Agent가 내부적으로 사용하는 유료 서드파티 API로, API 키가 필요 없습니다. 사용량은 Replit 크레딧에서 청구됩니다.

<Note>
  **플랜별 제공 여부**: 대부분의 connector는 Core, Pro 또는 Enterprise 구독이 필요하며, 일부는 Free 플랜에서도 사용할 수 있습니다. workspace의 connector 카탈로그에서 현재 플랜으로 사용 가능한 connector를 확인할 수 있습니다. Free 플랜 builder도 데이터베이스, 인증 등 Replit 관리형 integration은 언제든지 사용할 수 있습니다.
</Note>

<div id="getting-started">
  ## 시작하기
</div>

integration을 사용하려면 필요한 서비스나 기능을 언급하세요. 예를 들면 다음과 같습니다.

<AiPrompt>
  Stripe로 payments를 받고 SendGrid로 확인 이메일을 보내는 web app을 만들어 줘
</AiPrompt>

Agent가 이러한 키워드를 자동으로 감지해 필요한 코드와 configuration을 구현합니다.

<div id="let-agent-suggest-a-connector">
  ### Agent가 connector를 제안하도록 하기
</div>

파일 저장이나 이메일 발송처럼 여러 서비스가 같은 일을 처리할 수 있는 경우가 있습니다. provider를 지정하지 않고 필요한 기능만 요청하면, Agent가 적합한 connector를 짧은 목록으로 보여줍니다. 원하는 항목을 선택하세요.

provider를 선택한 다음 한 번만 로그인하면 계정이 연결됩니다. Agent는 앱을 만드는 동안 선택한 provider를 사용합니다. 목록을 건너뛰고 싶다면 특정 서비스를 이름으로 지정해 요청해도 됩니다.

<div id="connectors">
  ## Connectors
</div>

Connectors를 사용하면 Agent가 사용자의 서비스에서 직접 데이터를 읽고 쓸 수 있습니다. Connectors는 Replit이 공식 지원하는 자사 integration입니다. Project Editor의 Connectors 페이지에서 한 번만 로그인하면 해당 연결을 여러 앱에서 재사용할 수 있습니다.

<Note>
  연결은 사용자의 Replit account에 연결되어 모든 앱에서 유지됩니다. 서비스를 한 번만 연결해두면 이후에 만드는 모든 앱에서 사용할 수 있습니다.
</Note>

<div id="use-slack-with-agent">
  ### Agent에서 Slack 사용하기
</div>

Slack을 연결하면 사용자가 접근할 수 있는 대화를 Agent에 context로 제공할 수 있습니다. Agent에게 메시지, 파일, 채널, 사람을 검색하도록 요청하고, 그 결과를 활용해 질문에 답하거나 작업을 이어가세요.

사용자가 권한을 허용하면 Agent는 다음 작업을 수행할 수 있습니다.

* 사용자가 속한 비공개 채널, 다이렉트 메시지, 그룹 다이렉트 메시지 읽기
* 전후 context가 필요할 때 thread 답글 전체 읽기
* 사용자 명의로 메시지 보내기
* Slack 캔버스 생성, 읽기, 업데이트

<AiPrompt>
  launch plan에 대해 Alex와 나눈 다이렉트 메시지의 논의 내용을 요약한 다음, follow-up 메시지 초안을 작성해 줘.
</AiPrompt>

<Info>
  Agent는 연결된 Slack 계정이 접근할 수 있는 Slack 대화와 콘텐츠에만 접근할 수 있습니다.
</Info>

<div id="accessing-connectors">
  ### Connectors 사용하기
</div>

Project Editor의 사이드바에서 Connectors에 접근할 수 있습니다:

<Steps>
  <Step title="Project Editor 열기">
    Project Editor에서 앱을 엽니다.
  </Step>

  <Step title="Connectors 선택">
    사이드바에서 **Connectors**를 선택합니다.
  </Step>

  <Step title="새 integration 추가">
    **Add new integration**을 선택해 사용 가능한 connector를 살펴봅니다.
  </Step>

  <Step title="연결">
    연동하려는 서비스 옆의 **Connect**를 선택합니다.
  </Step>
</Steps>

<Tip>
  서비스 연결을 해제하려면 Connectors 패널로 돌아가 연결된 서비스 옆의 **Manage**를 선택하세요.

<div id="configuring-oauth-app-with-replit">
  ### Replit에서 OAuth app configuration하기
</div>

<Note>
  **Enterprise 전용**: 사용자 지정 OAuth app을 configuration하려면 Enterprise 구독이 필요합니다.
</Note>

Enterprise plan에서는 Replit의 기본 OAuth app 대신 직접 준비한 OAuth app을 connector에 사용할 수 있습니다. 이렇게 하면 조직이 OAuth 클라이언트를 직접 소유하고, 동의 화면에 자체 브랜딩을 표시하며, builder가 요청할 수 있는 scope를 정확하게 제어할 수 있습니다.

직접 준비한 OAuth app으로 connector를 configuration하려면 provider에서 세 가지, 즉 **Client ID**, **Client Secret**, 그리고 승인하려는 **scopes**를 받아야 합니다. 또한 authentication이 완료될 수 있도록 Replit의 콜백 URL을 provider에 등록해야 합니다.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Client ID, Client Secret, Connector Scopes 필드와 https://replit.com/connectors/oauth/callback으로 설정된 Redirect URL이 있는 connector OAuth configuration 대화 상자" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="provider에서 OAuth app 만들기">
    provider의 개발자 콘솔 또는 관리자 설정에 로그인해 새 OAuth 2.0 애플리케이션을 만듭니다. 이 단계의 명칭은 provider마다 다르므로 **Create OAuth app**, **Register application**, **Create client credentials** 같은 옵션을 찾아보세요.
  </Step>

  <Step title="리디렉션 URL 설정하기">
    provider가 **Authorized redirect URI**(**Callback URL** 또는 **Redirect URL**이라고도 함)를 요구하면 다음을 입력하세요.

    ```
    https://replit.com/connectors/oauth/callback
    ```

    이 URL은 builder가 app을 승인한 뒤 provider가 builder를 Replit으로 되돌려 보내는 주소입니다. 끝의 슬래시, 프로토콜, 하위 도메인까지 모두 정확히 일치해야 합니다. 리디렉션 URI를 여러 개 추가하더라도 이 주소는 반드시 포함되어야 합니다.
  </Step>

  <Step title="Client ID와 Client Secret 복사하기">
    app을 만들고 나면 provider가 **Client ID**와 **Client Secret**을 표시합니다.

    * **Client ID**: OAuth app의 공개 식별자입니다. URL이나 클라이언트 측 코드에 노출해도 안전합니다.
    * **Client Secret**: 요청이 해당 app에서 왔음을 증명하는 기밀 값입니다. 비밀번호처럼 취급하세요. 저장소에 커밋하거나 공개적으로 공유해서는 안 됩니다. Replit이 이를 대신 안전하게 보관합니다.

    일부 provider는 생성 시점에 client secret을 단 한 번만 표시합니다. 즉시 복사한 뒤 Replit에 붙여넣을 때까지 안전한 곳에 보관하세요.
  </Step>

  <Step title="scope 선택하기">
    **Scopes**는 OAuth app이 builder를 대신해 무엇을 읽고 쓸 수 있는지 정의하는 permissions입니다. provider마다 자체 scope 목록을 API 문서에 공개합니다.

    Replit에서 connector를 configuration할 때 입력하는 scope는 provider에 등록한 scope와 **정확히 일치**해야 합니다(URL 접두사를 포함해 문자 단위로 동일해야 함). 불일치 오류의 흔한 원인은 다음과 같습니다.

    * 전체 URL 접두사 누락(예: `https://www.googleapis.com/auth/drive.file` 대신 `drive.file`).
    * 불필요한 공백이나 끝에 붙은 쉼표.
    * provider의 app에서 활성화되지 않은 scope를 Replit에서 요청.

    builder에게 필요한 최소한의 scope로 시작하고, 필요하면 나중에 추가하세요. 대부분의 provider는 app을 다시 만들지 않고도 scope를 업데이트할 수 있습니다.
  </Step>

  <Step title="Replit에서 connector configuration하기">
    조직의 **Connectors** 페이지에서 **Add new integration**을 선택하고 서비스를 고른 다음, provider에서 가져온 **Client ID**, **Client Secret**, **Scopes**를 붙여넣습니다. **Configure**를 선택해 저장하세요.
  </Step>
</Steps>

<Note>
  configuration 후 authentication에 실패한다면, provider에 등록된 리디렉션 URL이 `https://replit.com/connectors/oauth/callback`과 정확히 일치하는지, 그리고 Replit에 입력한 모든 scope가 provider의 app에서도 승인되어 있는지 다시 확인하세요.
</Note>

    [Salesforce 연결 만료 오류 해결하기](/ko/features/troubleshooting/debugging-salesforce-connectors)
