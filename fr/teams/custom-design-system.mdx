Un design system donne à Agent les connaissances dont il a besoin pour créer une UI conforme à votre marque dans tout ce que votre organisation produit sur Replit : applications web, applications mobiles, diapositives et autres artefacts. En configurant votre bibliothèque de composants, vos design tokens, vos ressources de marque et vos règles d&#39;utilisation au sein du monorepo pnpm standard de Replit, vous permettez à Agent d&#39;appliquer votre langage visuel dès le premier prompt.

<Note>
  Les design systems sont disponibles exclusivement avec le forfait **Enterprise**. Seuls les admins de l&#39;organisation peuvent configurer et gérer les design systems.
</Note>

<div id="why-set-up-a-design-system">
  ## Pourquoi mettre en place un design system
</div>

Sans design system, chaque créateur doit expliquer manuellement à Agent votre bibliothèque de composants, vos jetons de couleur et vos conventions de disposition. Mettre en place un design system résout ce problème :

* **En codifiant vos standards visuels** : Agent utilise exactement vos composants, vos couleurs et votre spacing, et non des valeurs génériques par défaut
* **En garantissant la cohérence** : chaque app suit le même langage visuel
* **En réduisant le temps d&#39;intégration** : les nouveaux créateurs produisent immédiatement des résultats conformes à votre marque
* **En formalisant les savoirs implicites** : les décisions de design et les habitudes d&#39;utilisation des composants qui n&#39;existent que dans la tête de votre équipe sont documentées pour Agent

<div id="what-you-will-need">
  ## Ce dont vous aurez besoin
</div>

* Une bibliothèque de composants frontend sous forme de fichier tar (ou de plusieurs fichiers tar)
* Les polices et icônes utilisées dans votre design system
* Toute documentation IA de votre design system (MCP, Compétences Agent)

<div id="what-you-can-configure">
  ## Ce que vous pouvez configurer
</div>

La mise en place d&#39;un design system comporte trois volets :

1. **Instructions personnalisées**. Votre fichier `custom_instruction/instructions.md` fournit à Agent les règles générales qui s&#39;appliquent à tous les projets : quelle bibliothèque de composants utiliser, quels design tokens référencer et quels patterns suivre. Agent a toujours ce fichier dans son contexte.

2. **Compétences**. Les compétences placées dans `.agents/skills/` fournissent une documentation de référence détaillée qu&#39;Agent charge à la demande. Utilisez-les pour la documentation des API de composants, les guides de thématisation, les bibliothèques de patterns de mise en page et tout autre contenu de référence approfondi qui serait trop volumineux pour le fichier d&#39;instructions principal.

3. **Ressources de design et de marque**. Placez vos logos, icônes, polices et autres ressources de marque dans un dossier dédié (par exemple, `src/assets/brand/`). Configurez un alias de chemin Vite pour qu&#39;Agent et les créateurs puissent y faire référence via des imports clairs comme `@brand/logo.svg` plutôt que par des chemins relatifs fragiles. Les références aux ressources restent ainsi cohérentes dans l&#39;ensemble du projet.

<div id="step-by-step-guide">
  ## Guide étape par étape
</div>

Ce guide vous accompagne dans la mise en place complète d&#39;un design system à partir de votre bibliothèque de composants existante, empaquetée sous forme de tarfiles :

1. **Créez une nouvelle app Replit** et téléversez vos tarfiles.
2. **Demandez à Replit Agent d&#39;installer les paquets et d&#39;afficher tous les composants.** Agent configure alors le projet et effectue le rendu de votre bibliothèque de composants.
3. **Vérifiez le résultat.** Assurez-vous que tous les composants s&#39;affichent correctement et correspondent à vos attentes. Une fois tout validé, passez à [Créer la compétence design system](#creating-the-design-system-skill).

<div id="creating-the-design-system-skill">
  ### Création de la compétence design system
</div>

Vos composants étant prêts, la dernière étape consiste à créer une compétence design system afin qu&#39;Agent puisse s&#39;appuyer sur vos composants, vos jetons et vos conventions d&#39;usage dans chaque projet.

Copiez l&#39;intégralité du prompt ci-dessous et collez-le dans Agent. Remplacez `<your-design-system-name>` par le nom de votre design system :

````
Crée une compétence de design system `<your-design-system-name>` à partir des composants et des paquets de ce projet.

Utilise la structure de fichiers présentée ci-dessous, avec un `SKILL.md` à la racine, un répertoire `references/` pour les guides et la documentation des composants, et un répertoire `packages/` contenant toutes les dépendances nécessaires au fonctionnement.

Passe en revue chaque composant du projet et documente-le dans son propre fichier sous `references/components/`, en incluant ses props, ses variantes et un exemple d'utilisation.

Structure `SKILL.md` comme un index qui renvoie vers les fichiers de guides et de référence des composants, avec une section « General Guidance » et une section « Components », en suivant l'exemple présenté ci-dessous.

Structure de fichiers :

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (Tar files or code components)

Le fichier `SKILL.md` fait office d'index qui renvoie vers des fichiers markdown distincts pour les guides et les références de composants. Chaque fichier lié traite un sujet en détail. Voici un exemple de ce à quoi ressemble le `SKILL.md` généré :

```markdown
---
name: your-design-system
description: Use when building or modifying any UI. Provides component API references, layout guidance, and visual style rules for your design system.
---

# Your Design System

## General Guidance

- [Setup](references/guides/setup.md) — Installation, project configuration, and provider setup
- [Guardrails](references/guides/guardrails.md) — Hard rules that must never be broken (banned patterns, required tokens, accessibility minimums)
- [Layout & Spacing](references/guides/layout-and-spacing.md) — Grid system, spacing scale, responsive breakpoints, and page templates
- ...

## Components

- [Component Index](references/components/component-index.md) — Full list of available components with status and category

Individual component references (props, variants, examples):

- [Button](references/components/button.md)
- [Checkbox](references/components/checkbox.md)
- ...
```

Chaque fichier de guide traite un seul sujet : étapes de configuration et d'installation, bonnes pratiques et règles, tableaux de référence des valeurs de jetons, et courts exemples de code illustrant le bon usage.

Chaque fichier de composant documente un seul composant, avec son nom, une brève description, un tableau des props, des exemples d'utilisation, ainsi que les recommandations ou contraintes éventuelles. Plus ces fichiers sont complets, meilleur sera le résultat produit par Agent.
````

<div id="connect-your-skill-to-agent">
  ### Connectez votre compétence à Agent
</div>

Une fois la compétence créée, assurez-vous que votre fichier `custom_instruction/instructions.md` oriente bien Agent vers celle-ci :

```markdown theme={null}
# Design System

Lis et applique la compétence design system située dans `.agents/skills/your-design-system/`.
Applique toujours le design system lors du développement ou de la modification de l'UI.
```

Enfin, préremplissez `replit.md` avec le contexte propre à votre design system afin qu&#39;Agent comprenne vos standards visuels dès le départ. Incluez une présentation du projet, votre bibliothèque de composants préférée, vos principales préférences de conception (échelle d&#39;espacement, exigences d&#39;accessibilité) ainsi que la stack technique.

<div id="validate-your-setup">
  ### Valider votre configuration
</div>

Avant de déployer votre design system, vérifiez ces éléments essentiels :

* `custom_instruction/instructions.md` oriente Agent vers la compétence de votre design system
* `.agents/skills/` contient la compétence avec les références de composants, les guides et les paquets
* `replit.md` est pré-rempli avec la vue d&#39;ensemble du projet, les préférences et l&#39;architecture
* Le fichier de design tokens est inclus (`tokens.css` ou équivalent)
* Le paquet du design system est préinstallé dans `package.json`
* Créez une App de test et vérifiez qu&#39;Agent utilise correctement le design system

<div id="pin-the-design-system-to-your-organization">
  ### Épingler le design system à votre organisation
</div>

Une fois votre design system prêt, épinglez-le pour que tous les membres de l&#39;organisation puissent l&#39;utiliser :

1. Accédez à l&#39;app du design system dans votre organisation
2. Ouvrez le menu d&#39;actions de l&#39;app (menu à trois points)
3. Sélectionnez **Pin to Agent input box**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Menu d'actions de l'app affichant l'option Pin to Agent input box" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Seuls les admins de l&#39;organisation (membres du rôle `system_admins`) peuvent épingler et désépingler des design systems.
</Note>

Définissez l&#39;accès des membres sur **Read-only** afin qu&#39;ils puissent consulter et utiliser le design system épinglé sans pouvoir le modifier.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Boîte de dialogue d'invitation affichant l'accès des membres défini sur Read-only" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Le design system apparaît désormais sous forme de pastille sélectionnable sous la boîte de saisie de l&#39;Agent pour tous les membres de votre organisation. Pour le retirer, ouvrez ce même menu et sélectionnez **Unpin from Agent input box**.

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Design system apparaissant sous forme de pastille sélectionnable dans la boîte de saisie de l'Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

<div id="maintain-your-design-system-over-time">
  ## Maintenir votre design system dans la durée
</div>

Les design systems évoluent. Gardez le vôtre à jour :

* **Mettez à jour les fichiers de jetons** lorsque votre design system introduit de nouvelles couleurs, valeurs de spacing ou de typographie
* **Mettez à jour les compétences** lorsque les composants gagnent de nouvelles props, variantes ou modalités d&#39;utilisation
* **Mettez à jour les instructions** lorsque les principes ou les standards de design changent
* **Incrémentez les versions des paquets** à chaque nouvelle publication de votre design system
* **Testez régulièrement** en créant une nouvelle app et en vérifiant qu&#39;Agent produit le résultat attendu

<div id="design-systems-vs-custom-templates">
  ## Design systems et templates personnalisés
</div>

Les design systems et les [templates personnalisés](/fr/teams/custom-templates) répondent à des besoins différents :

|                          | Design systems                                                                                   | Templates personnalisés                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| **Objectif**             | Aligner le frontend sur celui de votre équipe et utiliser vos composants de code                 | Remplacer entièrement le stack par défaut (par exemple Rust, Go, C++)                   |
| **Stack**                | Fonctionne au sein du monorepo pnpm standard de Replit                                           | Définit une structure de projet entièrement personnalisée                               |
| **Ce qu&#39;il apporte** | Règles de bibliothèque de composants, design tokens, ressources de marque, compétences visuelles | Boilerplate complet : runtime, configuration de build, dépendances, structure du projet |
| **S&#39;applique à**     | Web apps, applications mobiles, diapositives, artefacts – tout ce qu&#39;Agent construit         | Uniquement les apps créées à partir de ce template précis                               |

Utilisez un design system lorsque vous souhaitez qu&#39;Agent respecte vos standards visuels dans le cadre de l&#39;expérience Replit habituelle. Optez pour un template personnalisé lorsque vous avez besoin d&#39;un stack fondamentalement différent.
