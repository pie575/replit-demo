빌드가 이미 App Store Connect에 올라가 있어야 합니다. 아직이라면
[앱 업로드하기](/ko/build/mobile-upload-ios)를 참고하세요. 이제 남은 것은 Apple이 플레이어에게
보여주는 리스팅과 심사 과정입니다.

<div id="1-complete-the-app-store-listing">
  ## 1. App Store 리스팅 완성하기
</div>

<Steps>
  <Step title="리스팅 작성">
    App Store Connect에서 기기 크기별 스크린샷, 설명, 키워드, 연령 등급 설문을 작성합니다. 필요하다면 [app icon 생성하기](/ko/build/mobile-app-icon)와
    [App Store 스크린샷 생성하기](/ko/build/mobile-store-screenshots)를 참고하세요.
  </Step>

  <Step title="개인정보 처리 정보 추가">
    Apple의 App Privacy 섹션에서는 PixelGames가 어떤 데이터를 수집하는지(Account, 위치, 사진 등)와
    그 데이터를 어떻게 사용하는지를 구체적으로 묻습니다. 정확하게 답변하세요. 실제 내용과 일치하지 않는 답변은 흔한 반려 사유입니다.
  </Step>
</Steps>

<div id="2-submit-for-review">
  ## 2. 심사 제출
</div>

리스팅 작성을 마쳤다면 버전 페이지 오른쪽 위의 **Add for Review**를 선택하세요.

<Frame caption="스크린샷과 메타데이터를 모두 입력한 후 iOS App Version 페이지에 표시된 Add for Review 버튼.">
  <img src="/assets/mirror/add-for-review-1d7b7c1dddbb.png" alt="Add for Review 버튼이 강조 표시된 App Store Connect 버전 페이지" data-path="images/pixelgames/mobile/add-for-review.png" width="1471" height="836" data-path="images/pixelgames/mobile/add-for-review.png" />
</Frame>

모든 제출물은 App Store에 공개되기 전에 Apple의 심사를 거칩니다. 보통 하루나 이틀이면
끝나지만, 특히 새 App을 처음 제출할 때는 더 오래 걸리기도 합니다.

거절되면 Apple이 무엇을 고쳐야 하는지 설명하는 안내를 보내줍니다. 그 내용을 Agent에 붙여넣고,
거절의 원인이 된 가장 작은 문제부터 수정한 뒤 다시 제출하세요. 거절은 흔한 일이고 곧바로 다시
제출할 수 있습니다.

<div id="troubleshooting">
  ## 문제 해결
</div>

* **Apple에서 거절된 경우:** 심사자의 의견을 Agent에 붙여넣고 거절 사유가 된 가장 작은 문제부터
  수정해 달라고 요청하세요.
* **심사가 계속 진행 중인 경우:** 심사 기간은 정해져 있지 않습니다. 다시 제출하지 말고 App Store Connect에서 현재
  상태를 확인하세요.
* **개인정보 처리 정보 불일치:** 리스팅을 작성한 뒤에 기능이 추가되었다면(새로운 권한, 새로 수집하는 데이터
  유형 등) 다시 제출하기 전에 개인정보 섹션을 업데이트하세요.
