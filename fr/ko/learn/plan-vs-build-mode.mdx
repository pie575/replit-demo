Replit Agent propose deux modes d&#39;interaction : le **mode Plan** et le **mode Build**. Combinez-les pour clarifier d&#39;abord vos idées, puis les mettre en œuvre en toute confiance.

<div id="plan">
  ## Qu&#39;est-ce que le mode Plan ?
</div>

Le [mode Plan](/fr/ko/features/agent/plan-mode) vous permet de réfléchir, de poser des questions et de planifier votre travail avec Agent, sans modifier le code. Voyez-le comme une séance de planification collaborative où vous explorez librement vos idées.

Le mode Plan est idéal pour :

* **Brainstorming des idées** : explorer différentes approches avant d&#39;en retenir une
* **Décomposer des projets complexes** : obtenir une liste de tâches structurée avant de vous lancer dans le build
* **Apprendre et comprendre** : poser des questions sur des technologies, des modèles ou une base de code
* **Planifier l&#39;architecture** : concevoir la structure de votre application avant d&#39;écrire la moindre ligne de code

<Info>
  En mode Plan, Agent lit votre projet et vous guide, mais ne modifie aucun fichier. Lorsque vous êtes prêt à passer à l&#39;implémentation, basculez en mode Build ou approuvez le plan pour lancer automatiquement le build.
</Info>

<div id="build">
  ## Qu&#39;est-ce que le mode Build ?
</div>

Le mode Build est le mode par défaut dans lequel Agent écrit du code, modifie des fichiers et implémente directement des fonctionnalités dans votre projet. C&#39;est là que vos idées prennent vie.

Utilisez le mode Build lorsque vous êtes prêt à :

* **Créer de nouvelles fonctionnalités** : Agent écrit le code de votre prochaine fonctionnalité
* **Configurer votre application** : installer des dépendances, configurer des bases de données, connecter des services
* **Corriger des tickets** : Agent débogue et résout les problèmes de votre base de code
* **Refactoriser le code** : améliorer la structure et l&#39;organisation du code existant

<div id="section">
  ## Utiliser les deux modes ensemble
</div>

**Le mode Plan et le mode Build donnent les meilleurs résultats lorsqu&#39;ils sont utilisés l&#39;un après l&#39;autre.** Commencez par planifier pour clarifier vos idées, puis lancez-vous dans le développement avec une direction claire.

<Steps>
  <Step title="Commencer en mode Plan">
    Passez en mode Plan et décrivez ce que vous souhaitez créer. Agent vous aide à réfléchir aux besoins, à proposer une approche et à identifier les difficultés potentielles, sans toucher au code.
  </Step>

  <Step title="Générer une liste de tâches">
    Demandez à Agent de créer un plan de développement. Il décompose le projet en tâches concrètes et réalisables, avec des priorités et des dépendances claires.

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="Liste de tâches générée avec priorités et dépendances" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="Examiner et affiner">
    Passez en revue le plan proposé. Posez des questions de suivi, demandez des modifications ou explorez d&#39;autres approches. Itérez jusqu&#39;à ce que le plan corresponde à votre vision.
  </Step>

  <Step title="Lancer le développement">
    Lorsque le plan vous convient, sélectionnez **Démarrer le build**. Agent passe automatiquement en mode Build et commence à implémenter les tâches approuvées.

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="Sélecteur de mode affichant les options mode Plan et mode Build" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="Suivre la progression">
    Surveillez l&#39;avancement pendant qu&#39;Agent progresse dans la liste de tâches. Chaque tâche terminée crée un checkpoint, ce qui vous permet d&#39;examiner les modifications et de faire un retour en arrière si nécessaire.
  </Step>
</Steps>

<div id="section-2">
  ## Quand utiliser chaque mode
</div>

<CardGroup cols={2}>
  <Card title="Quand utiliser le mode Plan" icon="lightbulb">
    * Lorsque vous démarrez un nouveau projet et cherchez une direction à prendre
    * Lorsque vous souhaitez explorer différentes approches
    * Lorsque la tâche est complexe et doit être décomposée
    * Lorsque vous souhaitez comprendre avant de passer à l&#39;implémentation
    * Lorsque vous ignorez quelle est la meilleure solution
  </Card>

  <Card title="Quand utiliser le mode Build" icon="hammer">
    * Lorsque vous savez exactement ce que vous voulez
    * Lorsque vous avez un plan clair, prêt à être exécuté
    * Lorsque vous effectuez des correctifs rapides ou de petites modifications
    * Lorsque vous suivez une liste de tâches approuvée
    * Lorsque la rapidité d&#39;implémentation prime
  </Card>
</CardGroup>

<Tip>
  **Vous hésitez entre les deux ?** Si votre demande implique plusieurs fonctionnalités ou des changements importants, commencez par le mode Plan. Pour les tâches simples et bien définies, passez directement au mode Build.
</Tip>

<div id="section-3">
  ## Principales différences
</div>

| Fonctionnalité            | Mode Plan                                       | Mode Build                            |
| ------------------------- | ----------------------------------------------- | ------------------------------------- |
| **Objectif**              | Brainstorming, planification, apprentissage     | Implémentation et développement       |
| **Modifications du code** | Aucune — lecture seule                          | Création et modification de fichiers  |
| **Résultat**              | Idées, listes de tâches, guides                 | Code et fonctionnalités opérationnels |
| **Idéal pour**            | Projets complexes, exploration                  | Tâches bien définies, implémentation  |
| **Basculement**           | Cliquez sur « Démarrer le build » pour basculer | Déjà en mode implémentation           |

<div id="section-4">
  ## Bonnes pratiques
</div>

<div id="plan-2">
  ### Tirer le meilleur parti du mode Plan
</div>

* **Soyez précis dans vos besoins** : plus vous donnez de détails, meilleur sera le plan.
* **Posez des questions de suivi** : faites clarifier les suggestions que vous ne comprenez pas.
* **Demandez des exemples** : demandez à Agent de vous montrer des extraits de code ou des patrons de conception.
* **Discutez des compromis** : explorez les avantages et les inconvénients des différentes approches.
* **Itérez sur vos idées** : affinez le plan jusqu&#39;à ce qu&#39;il vous convienne.

<div id="section-5">
  ### Transitions fluides
</div>

* **Vérifiez avant de lancer le build** : passez toujours en revue la liste des tâches avant de l&#39;approuver.
* **Commencez petit** : si le plan complet vous semble intimidant, démarrez avec quelques tâches seulement.
* **Utilisez les checkpoints** : au fil du build, Agent crée des checkpoints qui vous permettent de revenir en arrière à tout moment.
