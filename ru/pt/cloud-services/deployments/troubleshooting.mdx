На этой странице описаны распространённые проблемы, которые могут возникнуть при публикации вашего App, и способы их устранения.

<div id="problemas-comuns-de-publicao">
  ## Распространённые проблемы с публикацией
</div>

<div id="seu-app-no-funciona-no-project-editor">
  ### Ваше приложение не работает в Project Editor
</div>

Перед публикацией убедитесь, что приложение запускается корректно. Нажмите кнопку **Run** в верхней части Project Editor. Если в Preview не отображается ваше приложение по адресу `replit.dev`, в коде есть ошибка, которую необходимо исправить перед публикацией.

<div id="seu-programa-encerra-em-vez-de-rodar-continuamente">
  ### Программа завершается вместо непрерывной работы
</div>

Опубликованные apps рассчитаны на то, что программа работает непрерывно. Если программа выполняет свою задачу и завершается, платформа автоматически перезапускает её. Убедитесь, что приложение запускает長 длительно работающий процесс, например веб-сервер.

<div id="seu-servidor-no-est-ouvindo-em-0000">
  ### Ваш сервер не слушает `0.0.0.0`
</div>

Если вы запускаете веб-сервер, Deployments могут автоматически определить, какой порт он использует, но только если сервер слушает `0.0.0.0`. Если сервер слушает `localhost` или `127.0.0.1`, это не сработает.

<div id="sua-aplicao-tem-erros">
  ### В вашем приложении есть ошибки
</div>

Откройте вкладку **Logs** в верхней части панели **Publishing**, чтобы просмотреть вывод приложения. Обратите внимание на трассировки стека и исключения — они указывают на ошибки в коде, например на неинициализированные переменные или отсутствующие пакеты.

<div id="seus-comandos-de-execuo-ou-build-esto-incorretos">
  ### Команды запуска или сборки указаны неверно
</div>

Распространённые ошибки: опечатки, неверные флаги, неправильно указанные файл или каталог. Проверьте команды на панели **Publishing** и исправьте ошибки.

<div id="seus-secrets-no-esto-configurados-para-publicao">
  ### Secrets не настроены для публикации
</div>

Secrets, заданные в Project Editor, не переносятся автоматически в опубликованное приложение. Добавьте все Secrets и переменные окружения для продакшена на панели **Publishing**. Отсутствующие Secrets могут привести к сбою приложения при запуске из-за ошибок, связанных с неопределёнными значениями.

<div id="seu-replit-app-excede-o-limite-de-tamanho">
  ### Размер вашего Replit App превышает допустимый лимит
</div>

Reserved VM и Autoscale Deployments поддерживают Replit App размером до 8 ГБ. Static Deployments поддерживают размер до 1 ГБ. Чтобы уменьшить размер приложения, удалите ненужные файлы или используйте внешнее хранилище данных, например [SQL Database](/ru/pt/features/data-and-storage/sql-database/).

<div id="sua-pgina-inicial-demora-muito-para-carregar">
  ### Главная страница загружается слишком долго
</div>

Перед тем как пометить опубликованное приложение как активное, проверка работоспособности отправляет HTTP-запрос к вашему приложению. Если главная страница отвечает дольше пяти секунд, проверка завершается по тайм-ауту, и публикация завершается ошибкой на последнем этапе.

<div id="sua-configurao-de-porta-est-incorreta">
  ### Конфигурация порта неверна
</div>

Если в [конфигурации `.replit`](/ru/pt/references/configuration/configuration) указаны порты, автоматическое определение портов будет отключено. Для завершения этапа публикации необходимо указать порт с `externalPort`, равным `80`. Убедитесь, что сервер прослушивает указанный `localPort`.

<div id="seu-deployment-esttico-no-est-funcionando">
  ### Статическое развёртывание не работает
</div>

Обычно эта проблема возникает, если указан неверный публичный каталог или ваше приложение не подходит для Static Deployments. Static Deployment обслуживает статические файлы, например HTML, CSS и JavaScript.

Если в вашем приложении есть логика на стороне сервера, оно не подходит для Static Deployments. Измените тип развёртывания на Autoscale на панели **Publishing**.

<Warning>
  Файловая система в опубликованных приложениях не сохраняется и сбрасывается при каждой публикации. Для хранения данных используйте базу данных, например [SQL Database](/ru/pt/features/data-and-storage/sql-database).
</Warning>

<div id="problemas-de-acesso-com-urls-replitapp-e-replitdev">
  ## Проблемы с доступом к URL `replit.app` и `replit.dev`
</div>

Если у вас возникают трудности с доступом к вашему App по домену `replit.app` или `replit.dev` — в Preview или в отдельном окне браузера, — причиной могут быть веб-фильтры или сетевые ограничения.

Попробуйте использовать общедоступные DNS-резолверы, например Google DNS (`8.8.8.8`) или Cloudflare DNS (`1.1.1.1`), чтобы устранить эти проблемы.

<div id="alterar-as-configuraes-de-dns">
  ### Изменение настроек DNS
</div>

<Tabs>
  <Tab title="Windows">
    1. Откройте **Панель управления**.
    2. Перейдите в **Центр управления сетями и общим доступом**.
    3. Слева выберите **Изменение параметров адаптера**.
    4. Щёлкните правой кнопкой мыши по активному сетевому подключению и выберите **Свойства**.
    5. Выберите **Протокол TCP/IPv4**, затем — **Свойства**.
    6. Выберите **Использовать следующие адреса DNS-серверов**.
    7. Введите IP-адрес общедоступного DNS-сервера (например, `8.8.8.8` для Google DNS или `1.1.1.1` для Cloudflare DNS) в поля **Предпочитаемый DNS-сервер** и **Альтернативный DNS-сервер**.
    8. Выберите **ОК**, чтобы сохранить изменения.

    Более подробные инструкции см. в [руководстве Microsoft по настройке DNS](https://support.microsoft.com/en-us/windows/change-tcp-ip-settings-bd0a07af-15f5-cd6a-363f-ca2b6f391ace).
  </Tab>

  <Tab title="macOS">
    1. Откройте **Системные настройки**.
    2. Выберите **Сеть**.
    3. Слева выберите активное сетевое подключение.
    4. Выберите **Дополнительно** в правом нижнем углу.
    5. Перейдите на вкладку **DNS**.
    6. Нажмите кнопку **+**, чтобы добавить DNS-сервер.
    7. Введите IP-адрес общедоступного DNS-сервера (например, `8.8.8.8` для Google DNS или `1.1.1.1` для Cloudflare DNS).
    8. Выберите **ОК**, затем **Применить**.

    Более подробные инструкции см. в [руководстве Apple по настройке DNS](https://support.apple.com/guide/mac-help/change-dns-settings-on-mac-mh14127/mac).
  </Tab>

  <Tab title="Linux">
    1. Отредактируйте файл `/etc/resolv.conf`, чтобы добавить общедоступные DNS-серверы. Конкретный способ зависит от дистрибутива.
    2. Добавьте следующие строки:

    ```
    nameserver 8.8.8.8
    nameserver 1.1.1.1
    ```

    Подробнее о настройке DNS в разных дистрибутивах см. в [руководстве Debian Wiki по настройке сети](https://wiki.debian.org/NetworkConfiguration#Defining_the_.28DNS.29_Nameservers).
  </Tab>
</Tabs>

<div id="limpar-o-cache-dns">
  ### Очистка кеша DNS
</div>

После изменения настроек DNS очистите кеш DNS, чтобы применить новую конфигурацию:

* **Windows**: выполните `ipconfig /flushdns` в командной строке
* **macOS и Linux**: выполните `sudo systemctl restart NetworkManager` в терминале (точная команда может отличаться в зависимости от дистрибутива)

<Note>
  Для повышения производительности и стабильности в вашем регионе URL-адреса `replit.dev` ваших
  Replit App могут иногда меняться при миграции кластера. После завершения
  миграции URL-адреса остаются неизменными примерно в течение года, если только вы
  явно не запросите смену местоположения.
</Note>

<div id="publicar-uma-aplicao-streamlit">
  ## Публикация приложения Streamlit
</div>

Приложения Streamlit совместимы с Replit Deployments. Проще всего начать с [template Streamlit](https://replit.com/@replit/Streamlit?v=1).

Также можно задать следующую команду запуска для публикации:

```bash theme={null}
streamlit run --server.address 0.0.0.0 --server.headless true --server.enableCORS=false --server.enableWebsocketCompression=false main.py
```

Если в вашем приложении используется другой входной файл, замените `main.py` именем этого файла.

Если после выполнения этих шагов вам понадобится дополнительная помощь, посетите [Replit Community Hub](https://replit.com/community), где можно найти дополнительные ресурсы.
