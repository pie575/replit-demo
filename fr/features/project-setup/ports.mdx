Comme Replit exécute vos projets dans un environnement cloud, les ports n&#39;y fonctionnent pas de la même façon que sur votre ordinateur local. (Si vous avez besoin d&#39;une explication plus élémentaire de ce que sont les ports TCP, [commencez ici](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

Sur un ordinateur, il n&#39;existe qu&#39;une seule couche de gestion des ports : vos programmes définissent un port qu&#39;ils écoutent, et lorsqu&#39;un trafic provenant d&#39;internet atteint ce port sur votre ordinateur, il est acheminé vers le processus approprié.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="ordinateur" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

La partie `0.0.0.0` correspond à l&#39;adresse, ou hôte. Si un processus écoute sur `0.0.0.0`, cela signifie qu&#39;il écoute sur toutes les interfaces réseau — autrement dit, si un autre ordinateur (sur internet) envoie une requête à l&#39;adresse IP de votre ordinateur, elle lui parviendra. Écouter sur 0.0.0.0 signifie donc que ces processus sont accessibles depuis l&#39;internet public (si votre ordinateur est connecté).

La plupart des frameworks de programmation n&#39;écoutent *pas* sur `0.0.0.0` pendant le développement, car vous ne souhaitez pas forcément exposer votre travail au public tant qu&#39;il est en cours, pour des raisons de confidentialité et de sécurité. Ils écoutent plutôt sur une autre adresse — `127.0.0.1`, aussi appelée `localhost`. Seul cet ordinateur peut alors envoyer des requêtes à ce port.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Les ports localhost ne sont visibles que sur l'ordinateur qui les héberge." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

Sur Replit, pour qu&#39;un processus que vous exécutez soit accessible dans la webview ou via une requête externe, un **port externe** doit être défini. En effet, le « port interne » qu&#39;utilisent habituellement les processus n&#39;est visible que depuis l&#39;environnement cloud isolé fourni par Replit. Ce port interne doit être relié à un port accessible depuis l&#39;extérieur pour acheminer le bon trafic vers vos programmes. Même si votre processus écoute sur un port habituellement accessible au public comme 0.0.0.0, il doit tout de même être lié à un port externe.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Les ports externes transfèrent le trafic vers les ports internes, que les programmes écoutent." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Pour ce faire, Replit lie des ports externes à des ports internes précis — par exemple, dans le schéma ci-dessus, le port externe `:80` est lié au port interne `:3000`. Autrement dit, tout le trafic que cette Replit App reçoit sur le port 80 sera dirigé vers le port interne 3000.

Cette configuration est enregistrée dans la section [[ports]] du fichier de configuration .replit.

Par défaut, Replit lie le premier port que vous ouvrez au port externe 80, ce qui rend ce processus accessible sur le domaine sans adresse de port (par exemple customdomain.com/ au lieu de customdomain.com:3000/). Les ports internes supplémentaires que vous ouvrez sont liés à d&#39;autres ports externes disponibles (voir la liste complète ci-dessous).

<div id="default-port">
  ## Port par défaut
</div>

Le port :80 est le « port par défaut » du trafic http : le trafic http envoyé au domaine racine est donc automatiquement acheminé vers le port 80. C&#39;est pour cette raison que le numéro de port n&#39;apparaît pas dans l&#39;url pour le port 80. Les ports autres que :`80` apparaissent, eux, dans le chemin du domaine (par exemple customdomain.com:4200/). (Replit fournit TLS par défaut : techniquement, la connexion passe donc par le port 443, le port par défaut du https. En pratique, vous pouvez les considérer comme interchangeables.)

<div id="publishing">
  ## Publication
</div>

Les déploiements Autoscale et Reserved VM ne permettent d&#39;exposer qu&#39;un seul port externe, et le port interne correspondant ne doit pas utiliser `localhost`. Si vous exposez plusieurs ports, ou si vous exposez un port unique sur localhost, la publication de votre application échouera. Pour garantir le bon fonctionnement de vos déploiements Autoscale, le plus simple est de supprimer toutes les entrées `externalPort` des ports de votre configuration, *à l&#39;exception* de celui du service avec lequel vous souhaitez interagir depuis Internet.

<div id="debugging">
  ## Débogage
</div>

Si quelque chose ne fonctionne pas comme prévu, c&#39;est souvent parce que votre configuration de ports semble correcte, mais que votre programme écoute en réalité un autre port. Par exemple, si votre configuration est la suivante :

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Le trafic internet arrivant sur le port 80 sera alors redirigé vers le port interne 3000. En revanche, si votre programme n&#39;écoute pas réellement sur le port 3000, mais sur un autre (8080, par exemple), tout se passera comme si aucun trafic ne passait. Cela peut arriver si vous changez le port dans votre code sans modifier le port correspondant dans votre configuration, ou si vous copiez-collez la configuration d&#39;un projet à un autre.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Les programmes peuvent changer les ports sur lesquels ils écoutent." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

Chaque framework écoute par défaut sur des ports différents : par exemple, 5000 pour Flask, 3000 pour react et 8000 pour laravel. Vérifiez bien que le port configuré est le bon !

<div id="preferences">
  ## Préférences
</div>

Replit lie automatiquement les ports ouverts dans votre Replit App à des ports externes disponibles dès leur ouverture, et enregistre cette liaison dans le fichier de configuration .replit.

En revanche, ce n&#39;est pas le cas par défaut pour les ports internes ouverts sur localhost, car les services qui s&#39;exécutent habituellement sur localhost partent généralement du principe qu&#39;ils ne seront accessibles que depuis l&#39;ordinateur exécutant le processus (les ports localhost ne sont visibles que par cet ordinateur). Ces services sont donc souvent moins sécurisés que ceux conçus pour être accessibles depuis l&#39;internet public.

Vous pouvez à tout moment passer outre en définissant l&#39;option de configuration `exposeLocalhost` sur `true` pour le port que vous souhaitez exposer.

Si vous souhaitez exposer *systématiquement* les ports localhost par défaut, réglez le paramètre « redirection automatique des ports » sur « Tous les ports » dans l&#39;outil Paramètres utilisateur.

Si vous ne souhaitez *jamais* créer de configuration pour les ports ouverts et préférez contrôler manuellement la configuration des ports de toutes vos Replit App, réglez ce paramètre sur « jamais ».

<div id="supported-ports">
  ## Ports pris en charge
</div>

Une Replit App définit par défaut le port 80 comme port externe à l&#39;ouverture du premier port. Une Replit App peut exposer les ports 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080 et 8081 comme ports externes supplémentaires.

Les ports 22 et 8283 ne peuvent pas être redirigés, car ils sont utilisés en interne.

<div id="ports-replit-config">
  ## Configuration `[[ports]]` du fichier .replit
</div>

Type : `{localPort, externalPort, exposeLocalhost}`

La configuration `[[ports]]` vous permet de définir quel port HTTP exposer pour votre sortie web. Par défaut, tout port HTTP exposé sur l&#39;hôte 0.0.0.0 devient la sortie web de votre Replit App.

Vous pouvez servir des ports supplémentaires sans remplacer le port par défaut en ajoutant une nouvelle entrée [[ports]] à votre fichier .replit. Vous devez obligatoirement indiquer à la fois une entrée localPort et une entrée externalPort. Pour ajouter plusieurs ports supplémentaires, insérez plusieurs entrées [[ports]] dans votre fichier .replit, comme indiqué ci-dessous.

<div id="localport">
  ### localPort
</div>

Détermine quel port Replit liera à un port externe.

<div id="externalport">
  ### externalPort
</div>

Détermine le port à exposer publiquement pour ce port local.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Si vous ne voulez *jamais* exposer un port en particulier, vous pouvez conserver la configuration `localPort` sans ajouter d&#39;`externalPort` :

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Détermine si un port interne utilisant `localhost` peut être lié à un port externe. Peut valoir `true`, `false` ou null.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
