Un Reserved VM deployment s&#39;exécute sur une machine virtuelle (VM) qui fournit des ressources de calcul dédiées à
votre app. Ce type de deployment offre des coûts et des performances prévisibles, sans interruption.

Il est idéal pour les cas d&#39;usage suivants :

* Tâches en arrière-plan gourmandes en mémoire
* Bots de discussion devant rester connectés
* Serveurs d&#39;API toujours actifs

<div id="recursos">
  ## Fonctionnalités
</div>

Les Reserved VM Deployments offrent les fonctionnalités suivantes :

* **Ressources dédiées** : bénéficiez de performances constantes pour votre app grâce à des ressources de calcul réservées.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez une URL `<nom-de-l-app>.replit.app` pour accéder à votre app.
* **Options de ressources de calcul** : choisissez l&#39;option de VM adaptée aux besoins de performance de votre app.
* **Mappages de ports configurables** : définissez les ports que votre app expose sur internet.
* **Surveillance** : consultez les logs et suivez l&#39;état de votre app publiée.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder aux Reserved VM Deployments depuis l&#39;outil Publishing du Project Editor.

<Accordion title="Comment accéder aux Reserved VM Deployments">
  Dans le **Tool dock** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône de tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône de Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Reserved VM**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut de l&#39;écran pour ouvrir l&#39;outil de recherche
  2. Saisissez « Publishing » pour trouver l&#39;outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l&#39;option **Reserved VM**, puis **Set up your published app**.
</Accordion>

<div id="configurao-da-mquina">
  ### Configuration de la machine
</div>

Sélectionnez la configuration en CPU et en RAM de la machine qui héberge votre deployment. Le coût de l&#39;option s&#39;affiche à côté de la taille de machine sélectionnée.

<div id="domnio-principal">
  ### Domínio principal
</div>

Indiquez la partie sous-domaine du nom d&#39;hôte de votre application publiée. Une fois la publication effectuée, votre application est accessible à l&#39;adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Domaines personnalisés](/fr/features/publishing/custom-domains).

<div id="deployment-privado">
  ### Deployment privado
</div>

<Info>
  La fonctionnalité d&#39;application publiée en privé est disponible avec les forfaits Pro et Enterprise.
</Info>

Les applications publiées en privé ne sont accessibles qu&#39;aux membres de votre workspace, ou aux utilisateurs et groupes spécifiques que vous invitez.
Lors de la publication, vous pouvez choisir entre les accès **Public**, **Password protected**, **Workspace only** ou **Invite only**.

Pour savoir comment configurer un deployment privé, consultez [Accès à l&#39;application](/fr/features/publishing/private-deployments/).

<div id="build-command">
  ### Build command
</div>

Dans le champ **Build command**, saisissez la commande Shell qui compile ou configure votre app avant l&#39;exécution du Run command.
Par exemple, pour optimiser votre app JavaScript en vue d&#39;un environnement de production avec Vite, vous pouvez ajouter la commande `vite build`.

<div id="run-command">
  ### Run command
</div>

Saisissez dans le champ **Run command** la commande Shell qui lance votre tâche. Cette commande doit être semblable à celle que vous utilisez dans votre flux de travail. Par exemple, pour démarrer une application Flask nommée « myApp », vous pouvez ajouter la commande `flask --app myApp run`.

<div id="secrets-do-app-publicado">
  ### Secrets de l&#39;app publiée
</div>

Sélectionnez **Add published app secret** pour ajouter les variables d&#39;environnement ou les secrets dont votre app a besoin pour s&#39;exécuter en toute sécurité.

Si votre Replit App contient des variables d&#39;environnement ou des secrets, l&#39;outil Publishing les ajoute automatiquement à la liste.

<div id="opes-de-tipo-de-app">
  ### Options de type d&#39;app
</div>

Sélectionnez l&#39;une des options suivantes :

* **Web server** : sélectionnez cette option si vous publiez une app web ou une app à laquelle les utilisateurs peuvent se connecter via internet.
* **Background worker** : sélectionnez cette option si votre app n&#39;écoute sur aucun port et ne démarre pas de serveur.

Lorsque vous sélectionnez **Web Server**, vous pouvez choisir les ports à exposer en procédant comme suit :

1. Développez la section **Port configuration**.
2. Sélectionnez **Networking pane to configure** pour ouvrir l&#39;onglet **Networking**, où vous pouvez gérer les mappages de ports.

Pour plus d&#39;informations sur la configuration des ports, consultez [Ports](/fr/pt/features/project-setup/ports/).
