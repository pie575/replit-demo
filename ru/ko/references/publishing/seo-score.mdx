При публикации веб-приложения в Replit для его URL автоматически запускается SEO-аудит, а в инструменте публикации отображается оценка SEO по шкале от 0 до 100. Если оценку можно улучшить, одним щелчком передайте Агенту сведения о конкретных проблемах — и он исправит их за несколько секунд.

Для большинства разработчиков процесс выглядит так: опубликуйте App, проверьте оценку и попросите Агента выполнить &quot;SEO-оптимизацию&quot;. На этой странице рассказывается, что происходит в процессе и как извлечь из этого максимум пользы.

<div id="seo">
  ## Что такое SEO и почему оно важно
</div>

Поисковая оптимизация (SEO) — это подход к созданию сайта, который помогает поисковым системам, таким как Google, находить, понимать и ранжировать его. Хорошее SEO означает, что ваше App будет появляться в результатах поиска без расходов на рекламу.

На результаты SEO влияет несколько ключевых факторов: понятные заголовки и описания страниц, семантический HTML, быстрая загрузка, адаптированная для мобильных устройств верстка, описательный alt-текст изображений и доступная для сканирования структура сайта. Поисковые системы предпочитают сайты, которые легко читать как людям, так и машинам.

Если вы запускаете лендинг, маркетинговый сайт, блог, каталог или любой другой проект, для которого важна видимость в поиске, SEO — одно из самых эффективных направлений для инвестиций на раннем этапе.

<div id="replit-seo">
  ## Как Replit укрепляет основу SEO
</div>

Replit берёт на себя многие базовые аспекты SEO, чтобы вы могли сосредоточиться на контенте и продукте:

* **Быстрый глобально распределённый хостинг**: развёртывания Replit работают на инфраструктуре, оптимизированной для высокой скорости, а [регион публикации](/ru/ko/features/publishing/publishing-geography) позволяет выбрать место работы приложения.
* **HTTPS по умолчанию**: все опубликованные приложения получают TLS-сертификаты, которыми управляет Replit, — это базовый сигнал ранжирования для поисковых систем.
* **Пользовательские домены**: подключите собственный домен, чтобы укрепить доверие и авторитет бренда. См. [пользовательские домены](/ru/ko/features/publishing/custom-domains).
* **Статические развёртывания для контентных сайтов**: для маркетинговых страниц, блогов и документации [статические развёртывания](/ru/ko/features/publishing/static-deployments) предоставляют предварительно отрендеренный HTML, который поисковые системы легко сканируют.
* **Агент пишет код с учётом SEO**: при создании страниц Агент по умолчанию генерирует семантический HTML, доступную разметку и метатеги, которые проверяют SEO-инструменты.
* **Оценка SEO**: автоматические проверки после публикации позволяют всегда видеть текущее состояние, а одним щелчком можно попросить Агента исправить обнаруженные проблемы.

<div id="section">
  ### Как посмотреть
</div>

Откройте инструмент **Публикация** опубликованного App. Оценка SEO отображается в обзоре деплоя вместе с другими сведениями о сборке. Наведите курсор на оценку, чтобы увидеть конкретные рекомендации Lighthouse для каждой страницы.

<div id="section-2">
  ### Как интерпретировать оценки
</div>

Replit использует стандартные пороговые значения Lighthouse:

| Оценка | Статус              | Значение                                                                                    |
| :----- | :------------------ | :------------------------------------------------------------------------------------------ |
| 90–100 | Хорошо              | App соответствует рекомендациям по SEO. Продолжайте проверять после важных изменений.       |
| 50–89  | Требуется улучшение | Некоторые проблемы мешают поисковым системам понимать App.                                  |
| 0–49   | Плохо               | Отсутствуют важные базовые элементы SEO. Исправление обычно занимает всего несколько минут. |

Если в вашем App несколько страниц, значок показывает **самую низкую** оценку среди всех URL, просканированных Replit, поэтому в первую очередь отображается страница с худшим результатом, а не средний показатель.

<div id="section-3">
  ### Когда рассчитывается оценка
</div>

Аудит автоматически запускается после успешной публикации. Оценка обычно выполняется в течение 1~2 минут после начала деплоя, а инструмент публикации обновляет значок по получении результатов.

<div id="section-4">
  ### Поддерживаемые типы развёртываний
</div>

SEO-оценка рассчитывается для публичных веб-развёртываний, URL-адреса которых доступны для сканирования поисковыми системами:

* [Автомасштабируемые развёртывания](/ru/ko/features/publishing/autoscale-deployments)
* [Развёртывания Reserved VM](/ru/ko/features/publishing/reserved-vm-deployments)
* [Статические развёртывания](/ru/ko/features/publishing/static-deployments)

Для зарезервированных и частных развёртываний SEO-оценка не рассчитывается, поскольку они не обслуживают публичный веб-трафик.

<div id="seo-3">
  ## Оптимизация SEO с помощью Агента
</div>

Если оценка SEO ниже 90, рядом с ней появляется кнопка **Оптимизировать SEO с помощью Агента**. При ее нажатии список точных действий для всех URL, проверенных Lighthouse, вместе с инструкциями по исправлению отправляется в новый чат с Агентом.

<Tip>
  Можно вообще не использовать кнопку. Откройте Агента и напишите **&quot;Оптимизировать SEO&quot;** — Агент получит последние результаты Lighthouse и начнет работу.
</Tip>

Когда Агент завершит внесение изменений, заново опубликуйте App. Оценка SEO будет пересчитана для новой сборки, а значок обновится автоматически.

Типичные исправления, которые применит Агент:

* добавление или перезапись отсутствующих либо слишком общих тегов `<title>`, чтобы у каждой страницы был уникальный и описательный заголовок
* добавление метаописаний для всех страниц
* добавление описательного текста `alt` к изображениям
* настройка атрибута `lang` у элемента `<html>`
* проверка наличия у ссылок понятного текста (без «Нажмите здесь» и пустых ссылок)
* добавление `robots.txt` и `sitemap.xml`
* добавление метатега viewport для отображения на мобильных устройствах
* улучшение цветового контраста текста, не прошедшего проверку доступности
* добавление метатегов Open Graph и Twitter Cards, чтобы ссылки на App корректно отображались в предпросмотре на социальных платформах

<div id="replit-seo-2">
  ## Рекомендации по SEO-оптимизации сайтов в Replit
</div>

Независимо от того, поручаете ли вы эту работу Агенту или делаете всё вручную, вот наиболее важные моменты, которые нужно правильно настроить в приложениях, созданных в Replit:

* **Добавьте уникальные заголовки и метаописания для каждой страницы.** Заголовки должны быть короче 60 символов, а описания — примерно 150~160 символов.
* **Используйте семантический HTML.** Размечайте макет с помощью `<main>`, `<header>`, `<nav>`, `<footer>`. Используйте один `<h1>` на страницу и соблюдайте иерархию заголовков.
* **Добавляйте alt-текст ко всем изображениям.** Описывайте, что показывает изображение, а не просто что на нём изображено.
* **Создайте `sitemap.xml` и `robots.txt`.** Попросите Агента создать оба файла, чтобы поисковые системы знали, что нужно сканировать.
* **Добавьте теги Open Graph и Twitter Card.** Они позволяют управлять тем, как ваше приложение будет выглядеть при публикации в социальных сетях.
* **Используйте пользовательский домен.** Фирменный домен повышает доверие посетителей и поисковых систем. См. [Пользовательские домены](/ru/ko/features/publishing/custom-domains).
* **Выберите подходящий тип развёртывания.** Для сайтов с большим объёмом контента [статическое развёртывание](/ru/ko/features/publishing/static-deployments) предоставляет предварительно отрендеренный HTML, который поисковые системы могут сразу обработать.
* **Добавьте структурированные данные.** Разметка JSON-LD помогает поисковым системам отображать расширенные результаты для товаров, статей, FAQ и событий.
* **Обеспечьте высокую скорость работы приложения.** Оптимизируйте изображения, избегайте скриптов, блокирующих рендеринг, и используйте хостинг Replit, чтобы сократить время отклика.

Простой способ применить большинство этих рекомендаций сразу:

<AiPrompt>
  Проведите SEO-аудит моего сайта и внесите необходимые изменения. Добавьте карту сайта, robots.txt, теги Open Graph и структурированные данные, где это уместно, и убедитесь, что все страницы имеют уникальные заголовки и метаописания.
</AiPrompt>
