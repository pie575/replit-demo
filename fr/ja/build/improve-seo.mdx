Une fois ce guide terminé, votre application publiée gagnera en visibilité dans les moteurs de recherche, et ce résultat se reflétera également dans le score SEO de l&#39;outil Publishing.

À chaque publication réussie, Replit lance un audit SEO et affiche un score SEO. Si ce score peut être amélioré, il vous suffit d&#39;un clic pour transmettre les problèmes précis à Agent. Dans la plupart des cas, le processus est simple : **publier → consulter le score → demander à Agent de l&#39;optimiser**.

Pour en savoir plus sur le calcul du score (audit Lighthouse, signification de chaque score, types de déploiement pris en charge), consultez [Score SEO](/fr/ja/features/publishing/seo-rating).

<div id="seo-agentseo">
  ## Optimiser le SEO avec SEO Agent
</div>

[SEO Agent](/fr/ja/features/publishing/seo-agent) réalise un audit SEO technique de vos applications publiées et vous permet de corriger chaque point détecté en un clic. Intégré au panneau **Growth** du Project Editor, il est accessible aux créateurs disposant d&#39;un forfait payant. Pour analyser votre application et appliquer les correctifs, suivez les étapes ci-dessous.

<Steps>
  <Step title="Publiez votre application et débloquez Growth">
    SEO Agent fonctionne avec les applications publiées. Tant que vous n&#39;avez pas publié votre application, le panneau **Growth** reste verrouillé et l&#39;invite **Go to Publishing** s&#39;affiche. Après avoir publié votre application depuis le chat Agent ou l&#39;outil Publishing, revenez au panneau Growth.

    </Frame>
  </Step>

  <Step title="Lancer une analyse avec Agent">
    Ouvrez le panneau **Growth** et repérez la carte **SEO Rating**. Sélectionnez **Run scan with Agent** pour lancer un audit SEO technique de votre projet. L’analyse prend généralement quelques minutes.

    <Frame caption="Sélectionnez Run scan with Agent sur la carte SEO Rating pour lancer l’audit">

  <Step title="Corriger avec Agent ou tout corriger avec Agent">
    Une fois l’analyse terminée, les problèmes s’affichent dans un tableau avec les colonnes **Severity** (Low, Medium, High) et **Status** (Unresolved), regroupés en catégories telles que **AI Readiness**, **Crawlability &amp; Discovery**, **Landing Page Rendering &amp; Metadata** et **Performance Proxies**. Développez chaque problème pour consulter les éléments détectés par SEO Agent.

    * **Fix with Agent** pour un seul problème envoie uniquement cet élément à Agent.
    * **Fix with Agent** pour une catégorie corrige tous les problèmes de ce groupe.
    * **Fix all with Agent** envoie tous les problèmes à Agent en une seule fois. Le bouton **Fix all issues** dans le chat effectue la même action.

<Tip>
  Vous pouvez aussi ignorer l&#39;interface d&#39;analyse : ouvrez Agent et demandez-lui **« Optimise le SEO »**. Il récupérera les derniers résultats et se mettra au travail.
</Tip>

Correctifs courants appliqués par Agent :

* Ajouter ou réécrire les balises `<title>` manquantes ou génériques afin que chaque page ait un titre unique et descriptif.
* Ajouter une méta-description à toutes les pages.
* Ajouter un texte `alt` descriptif aux images.
* Définir l&#39;attribut `lang` sur l&#39;élément `<html>`.
* Donner aux liens un texte explicite (pas de « cliquez ici » ni d&#39;ancres vides).
* Ajouter `robots.txt` et `sitemap.xml`.
* Ajouter la balise méta viewport pour l&#39;affichage mobile.
* Améliorer le contraste des couleurs du texte qui échoue aux contrôles d&#39;accessibilité.
* Ajouter les balises méta Open Graph et Twitter Card pour optimiser les aperçus de liens sur les plateformes sociales.

<div id="seo">
  ## Bonnes pratiques pour une application optimisée pour le SEO
</div>

Que vous confiiez la tâche à Agent ou que vous la réalisiez vous-même, voici les points les plus efficaces :

* **Donnez à chaque page un titre et une méta-description uniques.** Visez 60 caractères maximum pour les titres et environ 150 à 160 caractères pour les descriptions.
* **Utilisez du HTML sémantique.** Structurez votre mise en page avec `<main>`, `<header>`, `<nav>` et `<footer>`. N&#39;utilisez `<h1>` qu&#39;une seule fois par page et respectez l&#39;ordre des niveaux de titres.
* **Ajoutez un texte alternatif à toutes les images.** Décrivez le contenu de l&#39;image (ce qu&#39;elle montre, et non ce qu&#39;elle est).
* **Générez `sitemap.xml` et `robots.txt`.** Demandez à Agent de créer les deux afin que les moteurs de recherche sachent quoi explorer.
* **Ajoutez des balises Open Graph et Twitter Card.** Contrôlez l&#39;apparence de votre application lorsqu&#39;elle est partagée sur les réseaux sociaux.
* **Utilisez un domaine personnalisé.** Un domaine à votre image renforce la confiance des visiteurs comme des moteurs de recherche. Consultez [Ajouter un domaine personnalisé](/fr/ja/build/add-custom-domain).
* **Choisissez le type de déploiement adapté.** Pour les sites riches en contenu, les [déploiements statiques](/fr/ja/features/publishing/deployment-types#static) sont idéaux : les moteurs de recherche peuvent analyser instantanément le HTML pré-rendu.
* **Ajoutez des données structurées.** Le balisage JSON-LD permet aux moteurs de recherche d&#39;afficher des résultats enrichis pour les produits, les articles, les FAQ et les événements.
* **Gardez votre application rapide.** Optimisez les images, évitez les scripts qui bloquent le rendu et tirez parti de l&#39;hébergement Replit pour maintenir des temps de réponse courts.

Un moyen simple d&#39;appliquer la plupart de ces points en une seule fois :

  sure every page has a unique title and meta description.
</AiPrompt>

<div id="section-2">
  ## Si vous avez besoin d&#39;aide supplémentaire
</div>

* **Le score n&#39;est pas mis à jour après une nouvelle publication :** patientez une à deux minutes — l&#39;audit s&#39;exécute de manière asynchrone après la publication du déploiement, et le badge se met à jour dès que les résultats sont disponibles.
* **Le score ne change pas après les modifications d&#39;Agent :** demandez à Agent quels éléments Lighthouse précis ont été traités, puis consultez l&#39;infobulle du badge pour voir ceux qui sont encore signalés.
* **Certaines pages ont un score faible :** le badge affiche le score le plus bas parmi toutes les URL explorées. Demandez à Agent de se concentrer sur les pages précises signalées par Lighthouse.
* **Aucun score n&#39;apparaît pour votre application publiée :** les scores SEO ne sont calculés que pour les types de déploiement web publiés (Autoscale, Reserved VM, Static). Les déploiements planifiés et privés ne génèrent pas de score.
