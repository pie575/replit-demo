Панель Git в Replit предоставляет визуальный интерфейс для работы с Git, избавляя от необходимости вводить команды Git в командной строке. Благодаря этому контроль версий становится доступным новичкам, оставаясь при этом мощным инструментом для опытных разработчиков.

<div id="recursos">
  ## Возможности
</div>

Панель Git предоставляет широкие возможности контроля версий прямо в Project Editor, а удобный интерфейс упрощает работу со сложными операциями Git.

* **Управление репозиторием**: Инициализируйте, подключайте и управляйте Git-репозиториями с интеграцией GitHub
* **Отслеживание коммитов**: Добавляйте изменения в индекс, создавайте коммиты и просматривайте изменения во всех файлах
* **Операции с ветками**: Визуально создавайте ветки, переключайтесь между ними и выполняйте слияние веток
* **Разрешение конфликтов**: Выявляйте и разрешайте конфликты слияния с помощью визуальных инструментов
* **Интеграция с Shell**: Синхронизация команд Git, выполняемых в Shell, с панелью Git

<div id="uso">
  ## Использование
</div>

<div id="configurao-do-repositrio">
  ### Настройка репозитория
</div>

<Accordion title="Как открыть панель Git">
  1. Перейдите в раздел Tools в вашем Replit App
  2. Нажмите значок **+**, чтобы добавить новые инструменты
  3. Выберите **Git** в списке доступных инструментов
</Accordion>

Панель Git помогает настроить и подключить репозиторий:

* **Initialize repository**: создайте новый репозиторий Git для своего Replit App
* **Connect to GitHub**: свяжите репозиторий с GitHub для резервного копирования и совместной работы
* **Configure remote**: настройте подключение к удалённому репозиторию GitHub и управляйте им

<div id="gerenciamento-de-alteraes">
  ### Управление изменениями
</div>

<Accordion title="Как просматривать изменения">
  1. Внесите изменения в любой файл вашего Replit App
  2. Откройте панель Git в разделе Tools
  3. Просмотрите изменения в разделе **Review Changes**
</Accordion>

Панель Git предоставляет инструменты для управления изменениями в коде:

* **Review changes**: просмотр изменённых файлов с подсветкой добавлений и удалений
* **Stage files**: добавление конкретных файлов в индекс для включения в следующий коммит
* **Commit changes**: создание коммитов с понятными описаниями
* **Push updates**: push коммитов в GitHub одним щелчком

<Note>
  Вы можете использовать Replit AI, чтобы сгенерировать сообщения коммитов, которые точно описывают ваши изменения.

<div id="gerenciamento-de-branches">
  ### Управление ветками
</div>

<Accordion title="Как управлять ветками">
  1. Откройте панель Git в разделе Tools
  2. Нажмите на выпадающий список рядом с названием ветки
  3. Создайте новую ветку или выберите существующую
</Accordion>

Панель Git упрощает работу с несколькими версиями кода:

* **Create branches**: создавайте новые ветки, чтобы разрабатывать функции по отдельности
* **Switch branches**: переключайтесь между разными версиями кода
* **Publish branches**: публикуйте свои ветки на GitHub
* **Pull changes**: выполняйте pull обновлений из удалённого репозитория от других участников

<div id="resoluo-de-conflitos-de-merge">
  ### Разрешение конфликтов слияния
</div>

<Accordion title="Как разрешать конфликты слияния">
  1. Попробуйте выполнить pull при наличии конфликтов
  2. Панель Git подсветит файлы с конфликтами
  3. Откройте каждый конфликтующий файл, чтобы просмотреть и разрешить конфликты
  4. Сохраните файлы после разрешения конфликтов
  5. Завершите слияние, выбрав **Pull**
</Accordion>

Когда код из разных источников конфликтует, панель Git помогает вам:

* **Identify conflicts**: увидеть, в каких именно файлах есть конфликты
* **Visualize differences**: сравнить обе версии конфликтующего кода
* **Resolve issues**: выбрать, какой код оставить, или отредактировать конфликты вручную
* **Finalize merges**: завершить слияние после разрешения конфликтов

После разрешения конфликта в файле удалите маркеры конфликта — строки, начинающиеся с символов конфликта, — и сохраните файл.

<div id="usando-comandos-git-no-shell">
  ### Использование команд Git в Shell
</div>

<Accordion title="Как открыть Shell">
  1. Выберите **All tools** в панели инструментов слева
  2. Выберите **Shell** из доступных инструментов
</Accordion>

<Tip>
  Хотя панель Git предоставляет удобный интерфейс, опытные пользователи могут использовать стандартные команды Git в Shell для более сложных операций. Изменения, внесённые любым из этих способов, будут отражаться в обоих местах.
</Tip>

Если вы предпочитаете работать с Git через командную строку:

* **Синхронизация команд**: Любые команды Git, выполненные в Shell, автоматически синхронизируются с панелью Git
* **Полный набор возможностей Git**: Используйте расширенные возможности Git, недоступные в панели Git
* **Удобное переключение**: При необходимости переключайтесь между командами в Shell и панелью Git

<Info>
  **Поддержка GitHub и GitLab CLI**: Помимо стандартных команд Git, вы также можете использовать [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) и [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) в Shell для управления внешними Git-репозиториями и подключения к ним. Эти инструменты предоставляют расширенные возможности для работы с репозиториями GitHub и GitLab, включая pull requests, issues и другие функции, специфичные для платформы.
</Info>

<div id="operaes-de-repositrio">
  #### Операции с репозиторием
</div>

* **Клонировать репозиторий**: `git clone <url-репозитория>`
* **Инициализировать репозиторий**: `git init`
* **Добавить удалённый репозиторий**: `git remote add origin <url-репозитория>`

<div id="fazendo-alteraes">
  #### Внесение изменений
</div>

* **Проверка статуса**: `git status` (показывает изменённые, добавленные и удалённые файлы)
* **Добавление файлов в индекс**: `git add <имя-файла>` или `git add .` (для всех файлов)
* **Коммит изменений**: `git commit -m "ваше сообщение коммита"`
* **Push изменений**: `git push origin <имя-ветки>`
* **Pull изменений**: `git pull origin <имя-ветки>`

<div id="autenticao">
  #### Аутентификация
</div>

При работе с приватными репозиториями потребуется пройти аутентификацию:

* Для репозиториев GitHub используйте персональный токен доступа вместо пароля
* Чтобы не вводить учётные данные каждый раз, сохраните их в Secrets в Replit:
  1. Создайте новый secret с ключом `GIT_URL`
  2. Укажите в качестве значения `https://<пользователь>:<токен>@github.com/<пользователь-или-организация>/<репозиторий>`
  3. Используйте `git push $GIT_URL`, чтобы выполнять push без ввода учётных данных

<Note>
  При хранении учётных данных в secrets любой, у кого есть доступ к вашему Replit App, потенциально может получить и ваши учётные данные Git. Для репозиториев с конфиденциальной информацией лучше каждый раз вводить учётные данные вручную.
</Note>
