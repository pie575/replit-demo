Администраторы Enterprise могут настраивать параметры для всей организации, определяющие, как участники команды взаимодействуют с кодом, деплоями и внешними платформами. Эти параметры помогают соблюдать стандарты безопасности, защищать интеллектуальную собственность и обеспечивать комплаенс с политиками Enterprise.&quot;

<div id="section">
  ## Доступ к настройкам конфиденциальности
</div>

<Accordion title="Как открыть настройки конфиденциальности">
  1. Перейдите в рабочее пространство Enterprise
  2. Выберите **Настройки**
  3. Выберите **Дополнительно**, чтобы просмотреть все доступные настройки
</Accordion>

<div id="section-2">
  ## Настройки конфиденциальности
</div>

Настройки конфиденциальности определяют, как приложения публикуются и как к ним открывается доступ внутри организации.

<CardGroup cols={2}>
  <Card title="Приватные деплои" icon="lock">
    Требовать, чтобы все новые приложения публиковались как приватные — доступ только для аутентифицированных участников команды
  </Card>

  <Card title="Деплои с защитой паролем" icon="key">
    Разрешить участникам команды защищать опубликованные приложения паролем
  </Card>

  <Card title="Приватные URL для разработки" icon="shield-halved">
    Для организаций с включённым SAML — требовать аутентификацию, включая SSO, для всех URL разработки приложений
  </Card>
</CardGroup>

<div id="section-3">
  ### Приватные деплои
</div>

Если параметр включён, все новые приложения должны публиковаться как приватные. Доступ к приватным приложениям есть только у аутентифицированных участников организации.

**Когда использовать этот параметр:**

* Организация работает с конфиденциальными данными или проприетарными приложениями
* Нужно исключить случайную публикацию приложений в открытом доступе
* Требования комплаенса предполагают ограниченный доступ к опубликованным приложениям

<Note>
  Этот параметр применяется только к вновь публикуемым приложениям. Ранее опубликованные приложения сохраняют текущие настройки доступа.
</Note>

<div id="section-4">
  ### Деплои с защитой паролем
</div>

Определяет, могут ли участники команды создавать деплои, защищённые паролем. Если параметр включён, разработчики смогут добавить дополнительный уровень защиты — доступ к опубликованному приложению будет требовать ввода пароля.

**Когда использовать этот параметр:**

* Нужно поделиться приложением с внешними заинтересованными сторонами, не делая его полностью общедоступным
* Команде нужно показать приложение клиентам до широкого запуска
* Требуется гибкий контроль доступа, выходящий за рамки членства в организации

<div id="url">
  ### Требовать приватные URL разработки
</div>

Если этот параметр включён, для всех URL разработки приложений требуется аутентификация. Если в организации включён SAML, для URL разработки потребуется аутентификация через SSO.

**Когда использовать этот параметр:**

* Нужно исключить несанкционированный доступ к приложениям, находящимся в разработке
* Политика безопасности требует защиты всех сред разработки
* Нужно гарантировать, что предварительный просмотр разработки доступен только аутентифицированным участникам команды

<Warning>
  Этот параметр применяется ко всем существующим приложениям организации, в том числе созданным ранее.
</Warning>

<div id="section-5">
  ### Запрет на экспорт исходного кода
</div>

Если этот параметр включён, участники команды не смогут экспортировать исходный код приложения в виде zip-файла. Это предотвращает загрузку и распространение кода за пределами платформы Replit.

**Когда использовать этот параметр:**

* Если требуется строго контролировать, где хранится исходный код
* Если политика безопасности запрещает локальные копии кода
* Если нужно гарантировать, что вся разработка ведётся в управляемой среде

<div id="section-6">
  ## Настройки безопасности
</div>

Настройки безопасности помогают выполнять сканирование уязвимостей и применять другие меры защиты.

<div id="section-7">
  ### Требовать сканирование безопасности
</div>

Настройте, должны ли все приложения проходить сканирование безопасности перед публикацией. Сканирование безопасности выявляет уязвимости в коде, раскрытые секреты и другие проблемы безопасности.

Доступные варианты:

| Настройка     | Описание                                                                 |
| ------------- | ------------------------------------------------------------------------ |
| **Выключено** | Сканирование безопасности необязательно                                  |
| **Требовать** | Все приложения должны пройти сканирование безопасности перед публикацией |

**Используйте эту настройку, если:**

* необходимо соблюдать требования безопасности
* вы хотите предотвратить случайное раскрытие API-ключей или секретов
* необходимо обеспечить единые стандарты безопасности для всех опубликованных приложений

<Note>
  Эта настройка не применяется к приложениям, опубликованным до её включения.
</Note>

<div id="section-8">
  ## Настройки контроля версий
</div>

Настройки контроля версий помогают внедрять практики управления версиями и защищать репозитории кода вашей организации.

<div id="git">
  ### Требование к удалённому репозиторию Git
</div>

При включении этой настройки перед публикацией приложения необходимо отправлять все локальные изменения в удалённый репозиторий Git. Это обеспечивает отслеживание всех изменений кода в системе контроля версий вашей организации.

**Используйте эту настройку, если:**

* Весь код должен быть сохранён в Git
* Необходим аудит всех изменений кода
* Рабочий процесс предусматривает проверку кода перед публикацией

<Note>
  Эта настройка не применяется к приложениям, опубликованным до её включения.
</Note>

<div id="section-9">
  ### Приватные удалённые репозитории
</div>

Определяет, могут ли участники команды использовать публичные репозитории Git. Если включить требование приватных удалённых репозиториев, участники команды смогут отправлять изменения только в приватные репозитории на платформах вроде GitHub.

Доступные варианты:

| Настройка                          | Описание                                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------------------------- |
| **Выключено**                      | Участники команды могут использовать публичные или приватные репозитории                  |
| **Требовать от неадминистраторов** | Участники команды без прав администратора должны использовать приватные репозитории       |
| **Требовать от всех**              | Все участники команды, включая администраторов, должны использовать приватные репозитории |

**Когда использовать эту настройку:**

* Публичные репозитории кода запрещены
* Необходимо исключить случайную отправку проприетарного кода в публичные репозитории
* Требования комплаенса предписывают использование приватного контроля версий

  ## Рекомендации
</div>

<AccordionGroup>
  <Accordion title="Начинайте с приватности по умолчанию" icon="shield">
    Включите **приватный деплой**, чтобы все новые публикуемые приложения были приватными. Это поможет избежать случайного раскрытия конфиденциальных приложений.
  </Accordion>

  <Accordion title="Включите сканирование безопасности" icon="magnifying-glass">
    Настройте **обязательное сканирование безопасности**, чтобы выявлять уязвимости до запуска приложения. Это поможет поддерживать единые стандарты безопасности во всей организации.
  </Accordion>

  <Accordion title="Защитите среду разработки" icon="code">
    Включите **обязательные приватные URL-адреса для разработки**, чтобы защитить даже незавершённые работы. Это особенно важно для организаций, работающих с конфиденциальными данными.
  </Accordion>

  <Accordion title="Контролируйте доступ к исходному коду" icon="code-branch">
    Сочетайте **запрет экспорта исходного кода** с требованием **приватного удалённого репозитория**, чтобы полностью контролировать размещение кода и доступ к нему.
  </Accordion>
</AccordionGroup>
