---
title: "Type de déploiement"
description: "Comparez les déploiements Autoscale, Static, Reserved VM et Scheduled, et découvrez comment choisir le type adapté à l’application que vous publiez."
---

Un type de déploiement désigne la technologie utilisée par Replit pour publier votre application. Sélectionnez-le dans le menu déroulant **Deployment type**, sous **Adjust settings** dans l’outil Publishing. **Autoscale** est l’option recommandée et sélectionnée par défaut. La plupart des créateurs n’ont pas besoin de la modifier.

<div id="section">
  ## Comparer les types de déploiement
</div>

| Type            | Idéal pour                                                         | Fonctionnement                                                                         | Facturation                                             |
| :-------------- | :----------------------------------------------------------------- | :------------------------------------------------------------------------------------- | :------------------------------------------------------ |
| **Autoscale**   | Applications web et API à trafic variable                          | Ajoute des serveurs en cas de forte activité et revient à zéro en période d’inactivité | Facturé uniquement pendant le traitement des requêtes   |
| **Static**      | Pages de destination, portfolios et sites de documentation         | Sert des fichiers depuis des serveurs cloud mis en cache, sans backend                 | Facturé uniquement pour les données servies par le site |
| **Reserved VM** | Bots, traitements en arrière-plan et API fonctionnant en continu   | Un serveur dédié qui ne se met jamais en veille                                        | Coût mensuel fixe                                       |
| **Scheduled**   | Tâches périodiques telles que les sauvegardes et les notifications | Exécute une commande selon une planification, puis s’arrête                            | Facturé selon la durée d’exécution                      |

<div id="autoscale">
  ## Autoscale
</div>

Les déploiements Autoscale s’exécutent sur des serveurs qui s’adaptent automatiquement au trafic de votre application. Lorsque votre application est sollicitée, Replit ajoute des serveurs pour gérer la charge. Lorsqu’elle est inactive, le nombre de serveurs peut être réduit jusqu’à zéro, afin que vous ne payiez rien pendant les périodes sans trafic.

Idéal pour :

* Les applications web dont le trafic varie, telles que les sites e-commerce
* Les API et les services

Les paramètres se trouvent dans **Adjust settings** : [performances de la machine et nombre maximal de serveurs](/fr/ja/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Les déploiements Static hébergent les fichiers de votre app, tels que des fichiers HTML, CSS et JavaScript, sur des serveurs cloud qui diffusent du contenu rapidement et à moindre coût grâce à la mise en cache. Ils n’utilisent pas de serveur backend.

Idéal pour :

* Les pages de destination marketing
* Les sites portfolio
* Les sites de documentation de produits et d’API

<Note>
  Les déploiements Static ne sont pas compatibles avec les Replit App créées à l’aide d’Agent. Agent crée des apps full stack nécessitant un serveur backend ; utilisez donc Autoscale ou Reserved VM dans ce cas.
</Note>

La configuration comprend le répertoire public à servir et une commande de build facultative. Pour les en-têtes de réponse, les réécritures d’URL et les redirections, consultez les [paramètres avancés de Static](/fr/ja/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Les déploiements Reserved VM exécutent votre application sur une machine virtuelle dédiée qui ne se met jamais en veille. Vous bénéficiez de performances stables et de coûts mensuels fixes et prévisibles.

Idéal pour :

* Les tâches d’arrière-plan gourmandes en mémoire
* Les chatbots qui doivent maintenir des connexions persistantes
* Les serveurs API fonctionnant en permanence

La configuration comprend les [performances de la machine](/fr/ja/features/publishing/machine-configuration), les commande de build et d’exécution, le mappage des ports, ainsi que le choix d’exécuter l’application comme serveur web ou worker d’arrière-plan.

<div id="scheduled">
  ## Scheduled
</div>

Les déploiements Scheduled exécutent des commandes dans l&#39;environnement de votre application selon une planification, puis s&#39;arrêtent jusqu&#39;à l&#39;exécution suivante. Décrivez une planification en langage naturel, par exemple « tous les jours ouvrés à 9 h », et Replit la convertira automatiquement. Vous recevrez une alerte en cas d&#39;échec d&#39;une exécution.

Idéal pour :

* Les vérifications d&#39;état et les rapports de santé
* L&#39;envoi de notifications
* Le lancement de sauvegardes

La configuration comprend une planification, le délai d&#39;expiration de la tâche, ainsi que les commandes de build et d&#39;exécution. Les déploiements Scheduled ne servent pas de pages web et ne disposent donc pas d&#39;URL publique.
