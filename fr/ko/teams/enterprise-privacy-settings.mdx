Les administrateurs Enterprise peuvent configurer des paramètres à l’échelle de l’organisation qui régissent la manière dont les membres de l’équipe interagissent avec le code, les déploiements et les plateformes externes. Ces paramètres contribuent au respect des normes de sécurité, à la protection de la propriété intellectuelle et à la conformité aux politiques Enterprise.

<div id="section">
  ## Accéder aux paramètres de confidentialité
</div>

<Accordion title="Accéder aux paramètres de confidentialité">
  1. Accédez à votre espace de travail Enterprise
  2. Sélectionnez **Paramètres**
  3. Sélectionnez **Avancé** pour afficher tous les paramètres disponibles
</Accordion>

<div id="section-2">
  ## Paramètres de confidentialité
</div>

Les paramètres de confidentialité contrôlent la façon dont les applications sont publiées et accessibles au sein de votre organisation.

<CardGroup cols={2}>
  <Card title="Déploiements privés" icon="lock">
    Exigez que toutes les nouvelles applications soient publiées en privé afin d’en limiter l’accès aux seuls membres authentifiés de l’équipe
  </Card>

  <Card title="Déploiements protégés par mot de passe" icon="key">
    Autorisez les membres de l’équipe à ajouter une protection par mot de passe aux applications publiées
  </Card>

  <Card title="URL de développement privées" icon="shield-halved">
    Exigez une authentification pour toutes les URL de développement des applications, y compris via le SSO, pour les organisations où SAML est activé
  </Card>
</CardGroup>

<div id="section-3">
  ### Déploiements privés
</div>

Lorsque cette option est activée, toutes les nouvelles applications doivent être publiées en mode privé. Seuls les membres authentifiés de votre organisation peuvent accéder aux applications privées.

**Utilisez ce paramètre si :**

* votre organisation traite des données sensibles ou des applications propriétaires
* vous devez vous assurer que les applications ne sont pas rendues publiques par inadvertance
* les exigences de conformité imposent un accès restreint aux applications publiées

<Note>
  Ce paramètre s’applique uniquement aux nouvelles applications publiées. Les applications déjà publiées conservent leurs paramètres de visibilité actuels.
</Note>

<div id="section-4">
  ### Déploiements protégés par mot de passe
</div>

Détermine si les membres de l’équipe peuvent créer des déploiements protégés par mot de passe. Lorsqu’il est activé, les créateurs peuvent ajouter une couche de sécurité supplémentaire exigeant un mot de passe pour accéder aux applications publiées.

**Utilisez ce paramètre lorsque :**

* vous souhaitez partager une application avec des parties prenantes externes sans la rendre entièrement publique
* votre équipe doit présenter une application à des clients avant un lancement plus large
* vous avez besoin d’un contrôle d’accès plus précis que la simple appartenance à l’organisation

<div id="url">
  ### Exiger des URL de développement privées
</div>

Lorsque ce paramètre est activé, l’authentification est requise pour toutes les URL de développement des applications. Si SAML est activé dans votre organisation, l’authentification SSO est requise pour accéder aux URL de développement.

**Utilisez ce paramètre dans les cas suivants :**

* vous devez empêcher tout accès non autorisé aux applications en cours de développement
* votre politique de sécurité exige la protection de tous les environnements de développement
* vous souhaitez garantir que seuls les membres authentifiés de l’équipe peuvent consulter les aperçus de développement

<Warning>
  Ce paramètre s’applique rétroactivement à toutes les applications existantes de l’organisation.
</Warning>

<div id="section-5">
  ### Interdire l’exportation du code source
</div>

Lorsqu’elle est activée, les membres de l’équipe ne peuvent pas exporter le code source de l’application sous forme de fichier zip. Cela empêche que le code soit téléchargé et partagé en dehors de la plateforme Replit.

**Utilisez ce paramètre dans les cas suivants :**

* Vous devez contrôler strictement l’emplacement du code source
* Votre politique de sécurité interdit les copies locales du code
* Vous souhaitez garantir que tout le développement s’effectue dans un environnement géré

<div id="section-6">
  ## Paramètres de sécurité
</div>

Les paramètres de sécurité vous aident à analyser les vulnérabilités et à mettre en place d’autres mesures de protection.

<div id="section-7">
  ### Exiger une analyse de sécurité
</div>

Déterminez si toutes les applications doivent passer une analyse de sécurité avant leur publication. L&#39;analyse de sécurité détecte les vulnérabilités dans le code, les secrets exposés et d&#39;autres problèmes de sécurité.

Options disponibles :

| Paramètres      | Description                                                                           |
| --------------- | ------------------------------------------------------------------------------------- |
| **Désactivé**   | Analyse de sécurité facultative                                                       |
| **Obligatoire** | Toutes les applications doivent passer une analyse de sécurité avant leur publication |

**Utilisez ce paramètre dans les cas suivants :**

* Vous devez respecter des exigences de conformité en matière de sécurité
* Vous souhaitez éviter l&#39;exposition accidentelle de clés API ou de secrets
* Vous devez garantir des normes de sécurité cohérentes pour toutes les applications publiées

<Note>
  Ce paramètre ne s&#39;applique pas aux applications publiées avant son activation.
</Note>

<div id="section-8">
  ## Paramètres de contrôle du code source
</div>

Les paramètres de contrôle du code source vous aident à appliquer les bonnes pratiques de contrôle de version et à protéger les dépôts de code de votre organisation.

<div id="git">
  ### Exigence de dépôt distant Git
</div>

Lorsqu&#39;elle est activée, toutes les applications doivent envoyer leurs modifications locales vers un dépôt distant Git avant leur publication. Cela garantit que toutes les modifications de code sont suivies dans le système de contrôle de version de votre organisation.

**Utilisez ce paramètre dans les cas suivants :**

* Vous devez sauvegarder tout votre code dans Git
* Vous avez besoin d&#39;une piste d&#39;audit de toutes les modifications de code
* Votre flux de travail exige une revue de code avant publication

<Note>
  Ce paramètre ne s&#39;applique pas aux applications publiées avant son activation.
</Note>

<div id="section-9">
  ### Dépôts distants privés
</div>

Déterminez si les membres de l’équipe peuvent utiliser des dépôts Git publics. Si vous exigez l’utilisation de dépôts distants privés, les membres de l’équipe ne peuvent effectuer des pushs que vers des dépôts privés sur des plateformes telles que GitHub.

Options disponibles :

| Paramètres                              | Description                                                                                     |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Désactivé**                           | Les membres de l’équipe peuvent utiliser des dépôts publics ou privés                           |
| **Exiger pour les non-administrateurs** | Les membres de l’équipe qui ne sont pas administrateurs doivent utiliser des dépôts privés      |
| **Exiger pour tous**                    | Tous les membres de l’équipe, y compris les administrateurs, doivent utiliser des dépôts privés |

**Utilisez ce paramètre dans les cas suivants :**

* Les dépôts de code publics sont interdits
* Vous devez vous assurer que du code propriétaire n’est pas accidentellement envoyé vers des dépôts publics
* Les exigences de conformité imposent l’utilisation d’un contrôle de version privé

<div id="section-10">
  ## Bonnes pratiques
</div>

<AccordionGroup>
  <Accordion title="Adopter le privé par défaut" icon="shield">
    Activez les **déploiements privés** pour garantir que toutes les nouvelles applications publiées restent privées. Vous éviterez ainsi toute exposition accidentelle d’applications sensibles.
  </Accordion>

  <Accordion title="Imposer des analyses de sécurité" icon="magnifying-glass">
    Configurez l’**exigence d’analyse de sécurité** pour détecter les vulnérabilités avant que les applications ne soient mises en ligne. Vous maintiendrez ainsi des normes de sécurité cohérentes dans toute votre organisation.
  </Accordion>

  <Accordion title="Protéger les environnements de développement" icon="code">
    Activez l’**exigence d’URL de développement privée** afin de protéger également les travaux en cours. Cette mesure est particulièrement importante pour les organisations qui traitent des données sensibles.
  </Accordion>

  <Accordion title="Contrôler l’accès au code source" icon="code-branch">
    Combinez les exigences **Interdire l’exportation du code source** et **dépôt distant privé** afin de garder un contrôle total sur l’emplacement du code et les personnes qui y ont accès.
  </Accordion>
</AccordionGroup>
