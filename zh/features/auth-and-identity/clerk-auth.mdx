Clerk Auth 由 [Clerk](https://clerk.com) 提供支持，为你的应用带来专属的身份验证系统。[Replit Auth](/zh/features/auth-and-identity/authentication) 使用 Replit 的登录系统并创建 Replit 账户，而 Clerk Auth 则会为你的应用单独开通一个**独立的 Clerk 租户**。应用的用户直接在你的应用内注册账户，而非注册 Replit 账户；品牌形象、登录方式和登录体验也完全由你掌控。

  <video autoPlay muted loop playsInline src="/assets/mirror/auth-vid-e89aaccd245e.mp4" />
</Frame>

<Note>
  **Clerk Auth 与 Replit Auth 的区别** —— 使用 **Clerk Auth** (即本页介绍的方案) 时，你的应用将拥有独立的身份验证租户，品牌形象可完全自定义，用户账户也与 Replit 无关。使用 **[Replit Auth](/zh/features/auth-and-identity/authentication)** 时，用户以 Replit 账户登录，看到的是带有 Replit 品牌的登录页面。如果你希望登录体验呈现自有品牌，或需要独立于 Replit 的用户账户，请选择 Clerk Auth。
</Note>

<div id="clerk-auth-vs-replit-auth-at-a-glance">
  ## Clerk Auth 与 Replit Auth 速览
</div>

|            | Clerk Auth                      | Replit Auth             |
| ---------- | ------------------------------- | ----------------------- |
| **用户账户**   | 用户在你的 App 内创建账户 (无需 Replit 账户)  | 用户使用 Replit 账户登录        |
| **品牌形象**   | 完全可自定义——使用你的 App 名称、图标和配色       | Replit 品牌的登录页面          |
| **SSO 凭据** | 每个身份提供方均可使用你自己的 OAuth 凭据        | 使用 Replit 的共享 OAuth 应用  |
| **环境**     | Development 与 Production 环境相互独立 | 单一环境                    |
| **推荐奖励**   | 不支持 Replit 推荐奖励集成               | 注册数计入 Replit Referrals  |
| **适用场景**   | 需要自定义品牌的 App、专业/商业产品            | 快速上手、可接受 Replit 品牌的 App |

<div id="getting-started">
  ## 快速开始
</div>

要为你的 App 添加 Clerk Auth，只需在 Agent prompt 中说明这一需求：

```
帮我创建一个 App，功能是 [你的应用创意]，并且要集成 Clerk Auth。
```

Agent 会全程代劳——创建 Clerk 租户、存储凭据、配置路由以及添加中间件。你无需拥有 Clerk 账户，也无需任何手动设置。

<div id="how-clerk-auth-works-with-replit">
  ## Clerk Auth 如何与 Replit 协同工作
</div>

当 Agent 为你的 App 配置 Clerk Auth 时，它会：

1. **创建专属的 Clerk 租户** —— 你的 App 将拥有独立的 Clerk 应用，并配备彼此隔离的开发环境和生产环境
2. **预置凭据** —— API 密钥和 Secrets 以环境变量的形式存储
3. **配置代理** —— 身份验证可在你已发布的域名上无缝运行
4. **设置登录和注册路由** —— 将预置的 Clerk React 组件添加到你的 App 中
5. **添加服务端中间件** —— 你的 API 路由由 Clerk 的 Express 中间件负责保护

<Note>
  你无需创建 Clerk 账户，也无需管理任何基础设施。一切都由 Replit 自动为你打理。
</Note>

<div id="capabilities">
  ## 功能
</div>

<div id="whats-supported">
  ### 支持的功能
</div>

Clerk Auth 为你的 App 提供：

* **独立的用户账户** — 你的 App 用户并非 Replit 用户，他们仅存在于你的 App 所属的 Clerk 租户中
* **完全品牌化的登录页面** — 登录和注册页面上的 App 名称、徽标、配色、字体和文案均在 App 代码中配置
* **自定义品牌的 SSO** — 为每个身份提供方配置你自己的 OAuth 凭据，让身份提供方的 OAuth 授权同意页面显示你的 App 名称和品牌，而非通用的默认内容
* **邮箱与密码认证** — 内置注册与登录，并支持邮件验证
* **社交登录 (SSO)&#x20;**&#x20;— 让用户使用 Google、GitHub、Apple 或 X (Twitter) 登录
* **用户管理** — 在 Auth 面板中查看、搜索和管理用户
* **会话处理** — 自动管理安全的会话令牌
* **开发和生产环境** — 在正式上线前于开发环境中测试认证

<Note>
  大部分 Clerk Auth 配置都可以在 Project Editor 的 **Auth** 工具中完成——无需 Clerk 账户，也无需打开 Clerk 控制台。
</Note>

<div id="whats-not-supported">
  ### 不支持的功能
</div>

以下功能目前在 Clerk Auth 中尚不可用 (与你自行搭建的外部 Clerk 应用相比) 。完整对比请参阅[此常见问题](#how-does-clerk-auth-compare-to-external-clerk)。

* **手机号登录** —— 基于短信的登录与验证
* **MFA 支持** —— 面向终端用户的多因素身份验证
* **完整的 SSO 身份提供方覆盖** —— 目前仅支持 Google、GitHub、Apple 和 X
* **组织租户** —— Clerk 的组织与团队成员管理功能

<div id="development-and-production-environments">
  ## 开发环境与生产环境
</div>

每个使用 Clerk Auth 的 App 都会获得两个完全独立的 Clerk 环境：**Development** 环境在你构建期间为开发/预览 App 提供支持，**Production** 环境则为已发布的 App 提供支持。这两个环境在设计上彼此隔离——各自拥有独立的 API 密钥和独立的用户存储。

<div id="separate-api-keys">
  ### 独立的 API 密钥
</div>

每个环境都有各自的公开密钥 (publishable key) 和私密密钥 (secret key) 。系统会根据应用运行在开发环境还是生产环境，自动切换向应用暴露的密钥：

* 在你的 workspace 中，`CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY` 这两个 Secrets 存放的是指向开发环境的**测试密钥** (`pk_test...` 和 `sk_test...`) 。

<Frame>
  <img src="/assets/mirror/clerk-check-dev-keys-5a23f6b7dd0c.png" alt="Workspace 中的 Secrets 工具，显示带有 sk_test_ 和 pk_test_ 前缀的 CLERK_SECRET_KEY 和 CLERK_PUBLISHABLE_KEY" width="1946" height="402" data-path="images/workspace/auth/clerk-check-dev-keys.png" />
</Frame>

* 发布应用后，已发布的 deployment 会使用指向生产环境的**正式密钥** (`pk_live...` 和 `sk_live...`) 运行。若要核对前缀，请打开 **Publishing → Overview → Adjust settings**，查看 `CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY`。

<Frame>
  <img src="/assets/mirror/clerk-check-prod-keys-acccd7f68da1.png" alt="Publishing 概览页显示生产环境应用的 Secrets，其中 CLERK_SECRET_KEY 和 CLERK_PUBLISHABLE_KEY 使用 sk_live_ 和 pk_live_ 前缀" width="1924" height="1664" data-path="images/workspace/auth/clerk-check-prod-keys.png" />
</Frame>

<Note>
  切换环境无需你做任何操作——Replit 会自动管理开发环境和生产环境的密钥。你只管开发、测试、发布即可。
</Note>

<Warning>
  请勿将测试密钥替换为正式密钥，也不要在 Secrets 面板中编辑它们，或在 Clerk 控制台中手动配置任何内容。这样做会破坏开发/生产环境的自动切换，Replit 托管的 Clerk Auth 也不支持此类操作。
</Warning>

<div id="separate-user-stores">
  ### 独立的用户存储
</div>

每个环境都有各自的用户存储。在 Development 环境中注册的账户在 Production 环境中并**不**存在，反之亦然：

* 在开发/预览应用中测试时注册的用户，只会创建在 Development 存储中。
* 在已发布应用上注册的用户，只会创建在 Production 存储中。
* 会话、用户元数据，以及任何以 Clerk `userId` 为键的数据，同样仅限于账户创建时所在的环境。

这是预期行为。要查看各环境中的用户，请在 Workspace 中打开 **Auth 面板**，然后用 **Users** 标签页上的环境切换开关在 Development 和 Production 之间切换。

<Note>
  Development 用于试验和构建；Production 面向线上应用的真实用户。两者是有意隔离的，因此在 Development 中创建的账户和数据不会出现在 Production 中。
</Note>

<div id="managing-users">
  ## 管理用户
</div>

Project Editor 中的 **Auth 面板**让你全面掌握已通过身份验证的用户。由于 Clerk Auth 会为你的 App 创建独立的用户存储，此处列出的用户是你 App 中的账户，而非 Replit 账户。

<Frame>
  <img src="/assets/mirror/clerk-users-4940ed365605.png" alt="Clerk Auth users tab showing authenticated users in the Auth pane" width="2136" height="794" data-path="images/workspace/auth/clerk-users.png" />
</Frame>

在 **Users** 标签页中，你可以：

* **查看所有用户**，包括电子邮件、姓名、最近登录时间和账户创建日期等详细信息
* **搜索和筛选**，快速找到特定用户
* **封禁或解封用户**，控制其对你 App 的访问权限
* **排序用户**，按不同条件排列
* **切换环境**——在 Development 和 Production 之间切换，分别管理各环境中的用户

<div id="customizing-your-sign-in-page">
  ## 自定义登录页面
</div>

登录和注册页面的视觉品牌元素——应用名称、徽标、颜色、字体和文案——是在 App 的代码中配置的，而非在 Auth 面板中配置。如需修改，可以这样告诉 Agent：

```
更新我的登录页面：标题使用 [你的应用名称]，logo 使用 [描述你的 logo]，整体配色与我的网站保持一致。
```

在底层，这是由传递给 `<ClerkProvider>` 的 `appearance` 和 `localization` 属性以及应用 `public/` 目录中的徽标文件控制的。Agent 会让它们与应用主题的其余部分保持一致。

<Note>
  在 **Google、Apple、GitHub 或 X 自己的授权确认页面** (即用户点击“使用 Google 登录”等按钮后出现的页面) 上显示的应用名称是另一回事——它来自在该身份提供方处注册的 OAuth 应用，**不会**因修改登录页面代码而改变。如需更改，请为该身份提供方配置[自定义 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
</Note>

<div id="configuring-login-providers">
  ## 配置登录身份提供方
</div>

Clerk Auth 支持 Google、GitHub、Apple 和 X 作为社交登录身份提供方。在 Auth 面板的 **Configure** 选项卡中，你可以控制登录页面上显示哪些身份提供方；在 Production 环境中，还可以决定每个身份提供方是使用 Replit 托管的 OAuth 凭据，还是使用你自己的自定义凭据以实现品牌化登录。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" alt="Configure 选项卡，侧边栏中显示 SSO 身份提供方，已选中 Production，身份提供方列表中显示启用开关和 Edit 操作" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

打开 **Configure** 选项卡。在侧边栏的 **SSO providers** 下，选择 **Development** 或 **Production**——**Development** 用于 Workspace 中的开发/预览应用，**Production** 用于已发布的应用。每个环境在主面板中都有各自的列表。在这里你可以：

* **启用或禁用身份提供方**——使用开关控制该身份提供方是否显示在登录页面上。已禁用的身份提供方对用户不可见。
* **配置自定义 OAuth 凭据 (仅限 Production)&#x20;**——参见下方的[为 SSO 身份提供方配置 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。

<div id="configuring-oauth-credentials-for-an-sso-provider">
  ### 为 SSO 身份提供方配置 OAuth 凭据
</div>

默认情况下，身份提供方使用 **Replit 托管的凭据**——登录开箱即用，但 OAuth 授权同意页面显示的是 Replit 的品牌信息。切换为 **自定义凭据** 后，即可使用你在身份提供方开发者控制台中创建的 OAuth 客户端，让同意页面显示你自己应用的名称和品牌信息。

1. 在 Project Editor 中打开 **Auth 面板**。切换到 **Configure** 选项卡，然后在侧边栏的 **SSO providers** 下选择 **Production**。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

2. 选择要配置的身份提供方旁边的 **Edit** 图标。系统默认选中 **Replit-managed credentials**。

<Frame>
  <img src="/assets/mirror/clerk-sso-default-credentials-525090775408.png" alt="身份提供方编辑面板，显示 Replit 托管凭据和自定义凭据两个选项" width="1468" height="960" data-path="images/workspace/auth/clerk-sso-default-credentials.png" />
</Frame>

3. 选择 **Custom credentials**。面板随即展开，显示各个凭据字段，以及一份 **Provider setup** 清单，其中列出了需要在身份提供方一侧注册的各项值。

<Frame>
  <img src="/assets/mirror/clerk-sso-custom-credentials-f24112a5cf07.png" alt="自定义凭据面板，显示 OAuth 客户端 ID 和密钥字段，以及包含重定向回调 URL 和 JavaScript 源的 Provider setup 清单" width="1468" height="2246" data-path="images/workspace/auth/clerk-sso-custom-credentials.png" />
</Frame>

4. 按照说明完成配置。说明中包含直达控制台和相关帮助文档的链接。你也可以在[其他资源](#additional-resources)中找到对应身份提供方的这些帮助文档。
5. 填写所有必填的凭据值。
6. 在身份提供方的开发者门户 (开发者控制台) 中，逐一注册 **Provider setup** 清单中列出的每一项。使用复制图标精确复制每个值，完成一项就勾选一项，或在全部完成后选择 **Mark all as done**。
7. 选择 **Save changes**。

<div id="rechecking-setup-after-domain-changes">
  ### 域名变更后重新检查设置
</div>

与域名相关的操作——例如关联新的外部域名或[通过 Replit 购买域名](/zh/build/domain-purchasing)——可能会改变应用的重定向回调 URL 和 JavaScript 来源。出现这种情况时，凡是使用自定义凭据配置的身份提供方，都可能需要在其开发者控制台中注册新的值。

域名变更后，请返回 **Configure** 标签页。设置提醒会以警告图标的形式显示在该标签页、侧边栏以及 **SSO providers** 列表中各身份提供方的旁边。若某个身份提供方旁出现警告图标和 **setup steps remaining** 字样，说明其 **Provider setup** 清单中有新增事项需要完成。

<Frame>
  <img src="/assets/mirror/clerk-sso-setup-reminders-a5b092846006.png" alt="Configure 标签页和侧边栏显示设置警告，域名变更后 SSO providers 列表中某个身份提供方旁边出现警告图标和“setup steps remaining”字样" width="923" height="378" data-path="images/workspace/auth/clerk-sso-setup-reminders.png" />
</Frame>

打开该身份提供方的编辑面板，复制 **Provider setup** 下更新后的值，在该身份提供方的开发者控制台中完成注册，然后选择 **Mark all as done**。

<div id="domain-setup-for-email-verification">
  ## 邮件验证的域名设置
</div>

如果你的 App 支持**邮箱和密码注册**，Clerk 会向每位新用户的收件箱发送验证码。为邮件投递配置域名，可确保这些验证码从你 App 的 URL 发出，而不会被垃圾邮件过滤器延迟或拦截。

<div id="when-you-need-this-setup">
  ### 何时需要此设置
</div>

只有当你的 App 关联了**由其他服务商管理的外部域名** (例如你在 Cloudflare、GoDaddy、Namecheap 等平台注册的域名) 时，才需要配置 DNS 记录。

如果你的 App 使用以下地址提供服务，则无需任何设置：

* `.replit.app` 子域名
* [通过 Replit 购买](/zh/build/domain-purchasing)的域名

这两种情况下，Replit 都会为你管理 DNS 记录。

<div id="add-dns-records-for-email-sending">
  ### 添加用于发送邮件的 DNS 记录
</div>

要授权你的应用从外部域名发送验证邮件，需要在域名服务商处添加一组 DNS 记录。

1. 在 Project Editor 中打开 **Publishing**。
2. 选择 **Domains**。
3. 找到已关联的外部域名，然后选择 **Manage**。
4. 在 **Authentication DNS setup required** 下，复制 Replit 显示的 CNAME 记录——Clerk 需要这些记录才能从你的域名发送验证邮件。
5. 登录你的 DNS 服务商 (Cloudflare、GoDaddy、Namecheap 等) ，严格按照显示的内容逐条添加记录。

<Frame>
  <img src="/assets/mirror/clerk-domain-8797ea9f41fc.png" alt="Domain Manage panel showing the Authentication DNS setup required section with CNAME records for Clerk email delivery" width="1156" height="1524" data-path="images/workspace/auth/clerk-domain.png" />
</Frame>

DNS 变更最多需要 48 小时才能全网生效。记录生效后，邮箱加密码注册流程会自动从你的域名发送验证码——无需在 Auth 面板中进行任何额外操作。

<div id="troubleshooting">
  ### 故障排查
</div>

* **收不到验证邮件** —— 请确认每条记录都与 Manage 面板中显示的内容完全一致，包括 DNS 服务商要求的结尾点号。另请检查收件人的垃圾邮件文件夹。
* **记录仍未被检测到** —— 请等待 DNS 解析生效 (最长 48 小时) ，然后重新查看 Manage 面板，确认是否仍有记录被标记为缺失。

<div id="security-best-practices">
  ## 安全最佳实践
</div>

* **始终在服务器端校验** — 要在 API 路由中检查身份验证，而不能只依赖 UI
* **使用环境变量** — 切勿将密钥或 Secrets 硬编码在代码中
* **代理中间件要放在最前面** — 在 Express 应用中，Clerk 代理必须挂载在 body 解析器之前
* **不要把主页重定向到登录页** — 保持着陆页对未登录访客可访问

<div id="faq">
  ## 常见问题
</div>

<div id="do-i-need-a-clerk-account-to-use-clerk-auth">
  ### 使用 Clerk Auth 需要 Clerk 账户吗？
</div>

不需要。Clerk Auth 背后的 Clerk 租户会在 Agent 搭建你的 App 时由 Replit 自动创建和管理——你无需注册 Clerk，也无需自行维护任何 Clerk 基础设施。

<div id="can-i-access-the-clerk-dashboard-for-the-replit-managed-clerk-instance">
  ### 我可以通过 Clerk 控制台访问 Replit 托管的 Clerk 实例吗？
</div>

不可以。Replit 托管的 Clerk 实例不会在 Clerk 控制台中开放。请改在 Project Editor 的 **Auth** 工具中进行管理——在那里可以配置身份提供方、查看用户，并在开发环境和生产环境之间切换。

<div id="my-clerk-publishable-key-starts-with-pk_test-how-do-i-switch-to-a-live-key">
  ### 我的 Clerk 公开密钥以 `pk_test` 开头。如何切换到正式密钥？
</div>

无需切换。你在 workspace 的 Secrets 面板中看到的 `pk_test...` 和 `sk_test...` 密钥属于应用的 **Development** Clerk 环境，仅在构建阶段使用。发布应用后，deployment 会自动使用 Production 环境的 `pk_live...` 和 `sk_live...` 密钥运行。如需确认，请在 Workspace 中依次打开 **Publishing → Overview → Adjust settings**，查看已发布应用的 `CLERK_PUBLISHABLE_KEY` 值——它会以 `pk_live` 开头。请勿手动修改这些密钥。完整说明请参阅 [Development 和 Production 环境](#development-and-production-environments)。

<div id="why-cant-i-sign-in-to-my-published-app-with-the-account-i-created-during-development">
  ### 为什么我无法用开发过程中创建的账户登录已发布的应用？
</div>

Clerk Auth 的 **Development** 和 **Production** 环境各自拥有独立的用户存储。你在开发/预览应用中创建的账户仅存在于 Development 环境中，发布时不会复制到 Production——你需要在已发布的应用上重新注册。以 Clerk `userId` 为键存储的数据也是如此。在 Workspace 中打开 **Auth 面板**，使用 **Users** 标签页上的环境切换开关，即可查看各环境中的用户。详情请参阅[独立的用户存储](#separate-user-stores)。

<div id="is-clerk-auth-free-to-use">
  ### Clerk Auth 可以免费使用吗？
</div>

Clerk Auth 目前免费。后续可能会引入按用量计费，与 Replit 上的其他按用量计费服务保持一致。未来产生的任何费用都会计入你现有的 Replit 账单，你无需单独处理 Clerk 的发票或付款方式。

<div id="does-clerk-auth-have-an-mau-limit-like-external-clerk-plans">
  ### Clerk Auth 是否像外部 Clerk 套餐那样有 MAU 限制？
</div>

没有。外部 Clerk 套餐会按层级限制月活跃用户 (MAU) 数量，而 Clerk Auth 不设 MAU 上限。

<div id="how-does-clerk-auth-compare-to-external-clerk">
  ### Clerk Auth 与外部 Clerk 有何区别？
</div>

Clerk Auth 背后由 Replit 托管的 Clerk 租户，与你在自己的 Clerk 账户中创建的 Clerk 应用 (**外部 Clerk**) 相比存在一些差异。下表列出了两者目前的不同之处——这反映的是 Clerk Auth 的当前状态，所支持的功能仍将持续扩展。

|                | Clerk Auth                       | 外部 Clerk        |
| -------------- | -------------------------------- | --------------- |
| **设置方式**       | 由 Replit 自动预配                    | 需自行设置           |
| **Clerk 租户归属** | 由 Replit 托管，归你的应用所有              | 归你的 Clerk 账户所有  |
| **费用结构**       | 目前免费 (未来计划支持按量付费)                | 订阅 + 按量付费       |
| **计费**         | 通过 Replit 计费 (目前免费)              | 在你的 Clerk 账户上计费 |
| **月活用户上限**     | 无限制                              | 按套餐层级设限         |
| **代理与域名配置**    | replit.app 域名和已购域名自动配置，关联域名需手动配置 | 手动配置            |
| **SSO 身份提供方**  | 支持部分身份提供方：Google、Apple、GitHub、X  | 支持更多身份提供方       |
| **用户管理入口**     | Project Editor 中的 Auth 工具        | Clerk 应用控制面板    |
| **短信**         | 不支持                              | 支持              |
| **MFA**        | 不支持                              | 支持              |
| **组织租户**       | 不支持                              | 支持              |

<div id="what-common-clerk-auth-setup-do-i-need-to-handle-manually">
  ### 哪些常见的 Clerk Auth 设置需要手动处理？
</div>

大部分 Clerk Auth 设置都会自动完成，但有几项配置需要你在 **Auth** 工具之外进行操作：

* **SSO 身份提供方的自定义 OAuth 凭据** — 如果你希望身份提供方的授权同意页面显示你的 App 名称和品牌标识 (而不是 Replit 的默认信息) ，请在该身份提供方的开发者控制台中注册一个 OAuth 应用，并将凭据粘贴回 Auth 面板。参见[为 SSO 身份提供方配置 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
* **外部域名邮件验证所需的 DNS 记录** — 如果你的 App 关联了由其他服务商管理的外部域名，则需要添加 DNS 记录，验证邮件才能从你的域名发出。参见[邮件验证的域名设置](#domain-setup-for-email-verification)。

<div id="can-i-bring-my-own-clerk-app-instead-of-using-the-replit-managed-one">
  ### 我可以使用自己的 Clerk 应用，而不用 Replit 托管的那个吗？
</div>

可以。如果你的应用已经预置了 Replit 托管的 Clerk 应用，请先将其删除，再接入你自己的外部 Clerk 应用：

1. 在 Project Editor 中打开 **Auth** 面板。
2. 切换到 **Configure** 标签页。
3. 滚动到页面底部，点击 **Delete Clerk app**。

删除 Clerk 应用会移除 Replit 托管的 Clerk 租户，并释放与之绑定的所有域名，这样你就可以接入自己的 Clerk 应用并复用这些域名。如果你的应用尚未预置 Replit 托管的 Clerk 应用，可以跳过此步骤，直接集成你的外部 Clerk 应用。
