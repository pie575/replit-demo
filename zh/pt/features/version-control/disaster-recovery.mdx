---
title: "Git 灾难恢复"
description: "了解如何使用 Replit 的自动备份系统恢复 Git 历史记录和代码。"
---

Replit 会自动备份你的 Git 仓库，帮助你从 `.git` 文件夹损坏、提交历史记录丢失等问题中恢复。该备份系统在后台运行，无需额外操作即可保护你的工作。

<div id="como-funciona">
  ## 工作原理
</div>

每个 Replit App 都会为其 Git 仓库维护一份安全备份。当 Replit Agent 修改代码或你发布 App 时，这些更改会自动同步到该备份。如果本地 Git 仓库损坏或无法使用，你可以通过备份恢复完整的提交历史。

<Info>
  备份远程仓库名为 `gitsafe-backup`，由 Replit 自动管理。无需进行任何配置——它已在后台运行。
</Info>

<div id="visualizar-seu-histrico-de-backup">
  ## 查看备份历史记录
</div>

查看提交历史最简单的方法是使用 [Git 面板](/zh/pt/features/workspace-tools/git-interface)。在 Project Editor 的 Tools 区域打开它，即可查看完整的提交历史记录，其中包括所有 Agent checkpoint。该方法适用于大多数情况，无需运行任何命令。

如果需要直接检查 gitsafe-backup 远程仓库，可以使用 Shell：

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

这会显示你的完整提交历史记录，包括所有 Agent checkpoint 和手动提交。你可以借此确认工作是否已备份，或查找需要恢复的特定提交。

<div id="recuperao-de-problemas-do-git">
  ## Git 问题修复
</div>

如果遇到 Git 错误或仓库损坏，请先查看 [Git 面板](/zh/pt/features/workspace-tools/git-interface)。无需在 Shell 中运行命令，它就能解决大多数常见问题，例如重置到之前的提交或从远程仓库拉取。

如果 Git 面板无法解决问题 (例如 `.git` 文件夹完全损坏) ，请按照下面基于 Shell 的步骤操作。

<div id="verificar-se-o-backup-est-disponvel">
  ### 检查备份是否可用
</div>

首先，检查备份远程仓库是否存在：

```bash theme={null}
git remote -v
```

在输出中查找 `gitsafe-backup`。如果找到，即可继续恢复。

<div id="restaurar-seu-repositrio">
  ### 恢复你的仓库
</div>

<Warning>
  此操作会用备份版本替换当前的 `.git` 文件夹。你的工作文件不会受到影响，但本地 Git 历史记录将被备份中的内容替换。
</Warning>

<Steps>
  <Step title="保存当前的 Git 配置">
    如果你有自定义配置，请备份 Git 配置文件：

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="克隆备份仓库">
    从备份创建一个临时克隆：

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="替换 Git 文件夹">
    将损坏的 `.git` 文件夹移至一旁，然后用备份替换它：

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="恢复配置">
    将 Git 配置文件移回原处：

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

完成这些步骤后，运行 `git status`，确认仓库是否正常工作。

<div id="soluo-de-problemas-comuns">
  ## 常见问题排查
</div>

<div id="fatal-repository-not-found-ou-remote-de-backup-ausente">
  ### “fatal: repository not found”或备份远程仓库缺失
</div>

较早创建的项目可能未启用备份系统。如果您需要协助恢复旧项目，请联系支持团队。

<div id="a-recuperao-no-incluiu-commits-recentes">
  ### 恢复内容未包含最近的提交
</div>

每次 Agent 提交后，系统都会同步备份。如果你进行了更改但尚未提交，这些更改不会包含在备份中。请检查工作目录中是否有未提交的文件。

<div id="operaes-do-git-esto-lentas-ou-travadas">
  ### Git 操作缓慢或卡住
</div>

如果 Git 操作无响应，可能是存在过期的锁定文件。您可以放心将其删除：

```bash theme={null}
rm -f .git/index.lock
```

<div id="preveno-de-perda-de-dados">
  ## 数据丢失防护
</div>

虽然备份系统会自动保护您的 Git 历史记录，但您还可以采取以下措施，进一步保护您的工作：

* **经常提交提交**：进行小而频繁的提交，持续备份您的进度
* **使用 checkpoint**：使用 [Replit Agent](/zh/pt/features/agent/overview) 时，checkpoint 会在关键节点自动创建提交
* **连接 GitHub**：对于关键项目，请[将您的 App 连接到 GitHub](/zh/pt/build/import-from-providers)，以增加一层备份保障
