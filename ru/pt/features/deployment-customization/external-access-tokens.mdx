title: "Токены внешнего доступа"
description: "Разрешите CI-конвейерам, вебхукам и другим автоматизированным сервисам обращаться к вашему приватному приложению Replit без входа в аккаунт."
---

Токены внешнего доступа — это bearer-токены, которые вы создаёте для конкретного Replit App.
Они позволяют автоматизированным сервисам — CI-конвейерам, вебхукам, сервисам проверки доступности, ботам Slack,
внутренним скриптам — обращаться к приложению даже тогда, когда его URL закрыт
[приватным Dev URL](/ru/pt/features/publishing/private-deployments)
или [приватным deployment](/ru/pt/features/publishing/private-deployments).

Относитесь к каждому токену как к паролю: любой, у кого он есть, получит доступ к вашему приложению, пока срок действия токена не истечёт или пока его не отзовут.

<Note>
  Токены внешнего доступа доступны, если для deployment выбран приватный
  доступ. Подключать workspace не требуется. В workspace уровня Enterprise
  управлять токенами могут только администраторы workspace.
</Note>

<div id="quando-usar-um-token">
  ## Когда использовать токен
</div>

Используйте внешний токен доступа, когда к вашему приватному Replit App обращается что-то *извне* браузера. Типичные случаи:

* Рабочий процесс GitHub Actions, который при каждом коммите выполняет smoke-тест по вашему dev-URL.
* Монитор доступности (Better Stack, Pingdom, UptimeRobot), обращающийся к эндпоинту проверки состояния в опубликованном приложении.
* Приёмник вебхуков — Stripe, Slack, GitHub — отправляющий POST-запрос в Private Deployment.
* Вызов `curl` или `fetch` с машины коллеги по команде во время отладки.

Внешние токены доступа рассчитаны на **трафик API**, а не на открытие страниц интерфейса в браузере. Одностраничные приложения (Vite, Next.js и др.) загружают JavaScript-бандлы последующими запросами, в которых ваш токен не передаётся, поэтому такие запросы завершатся ошибкой. Для интерактивной навигации выполняйте вход обычным способом.

<div id="ambientes-de-tokens">
  ## Окружения токенов
</div>

Каждый токен привязан к определённому окружению:

| Окружение     | Где работает                                                               | Для чего использовать                           |
| :------------ | :------------------------------------------------------------------------- | :---------------------------------------------- |
| `Development` | URL для разработки в workspace приложения (`*.replit.dev`)                 | Доступ к запущенному Repl во время разработки   |
| `Production`  | Опубликованный deployment приложения (`*.replit.app` и собственные домены) | Доступ к Private Deployment из внешних сервисов |

Токен `Production` сохраняется после повторной публикации, в том числе при
публикации новой версии. Replit отзывает его, когда вы:

* Снимаете deployment с публикации.
* Удаляете deployment.
* Меняете доступ к приложению с приватного на публичный.

Токен также перестаёт работать по истечении срока действия или после того, как вы его отзовёте.

<div id="criar-um-token-de-acesso-externo">
  ## Создание токена внешнего доступа
</div>

<Steps>
  <Step>
    Откройте приложение, к которому нужно открыть внешний доступ, а затем откройте инструмент **Publishing**.
  </Step>

  <Step>
    Выберите **Adjust settings**, чтобы развернуть параметры повторной публикации.
  </Step>

  <Step>
    В разделе **Security** найдите **External access tokens**.
  </Step>

  <Step>
    Выберите **Create access token** и заполните поля:

    * **Label** (необязательно): короткое имя, по которому вы позже узнаете токен,
      например `CI` или `Stripe webhook`. Не более 120 символов.
    * **Environment**: выберите `Development` или `Production` в зависимости от того, где
      вызывающему сервису нужен доступ к приложению.
    * **Expires after**: выберите срок действия — `1 hour`, `24 hours`, `7 days`,
      `30 days`, `3 months`, `1 year` или `5 years`. Выбирайте минимальный срок,
      которого достаточно для вашей задачи. Варианта «никогда не истекает» нет.
  </Step>

  <Step>
    Выберите **Create**.
  </Step>
</Steps>

Replit показывает токен **только один раз**. Скопируйте его сразу — после закрытия диалогового окна увидеть токен снова будет невозможно. Если вы его потеряете, отзовите этот токен и создайте новый.

На экране с токеном доступны два способа копирования:

* **Copy query parameter** — копирует `?project-protection-bypass=<token>`
  для добавления к URL. Удобно для быстрых проверок через `curl`.
* **Copy token only** — копирует сам токен, который можно передать в
  заголовке `Authorization: Bearer`.

<Info>
  Создание первого токена автоматически включает внешний доступ для приложения, если
  он ещё не включён. Без защиты токену было бы нечего обходить.
</Info>

<div id="usar-um-token">
  ## Использование токена
</div>

Передайте токен одним из двух способов:

<div id="cabealho-authorization-recomendado">
  ### Заголовок Authorization (рекомендуется)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

Это правильный выбор почти для всех случаев — вебхуки, CI-скрипты,
вызовы между бэкендами. Токен никогда не попадает в логи, где записываются URL,
и не остаётся в истории браузера.

<div id="parmetro-de-consulta">
  ### Параметр запроса
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

Используйте вариант с параметром запроса только в том случае, когда задать заголовки невозможно — например, в
сервисе, который принимает только URL. URL с токенами часто попадают в логи прокси,
историю Shell и на скриншоты, поэтому по возможности используйте заголовок.

<div id="gerenciar-tokens-existentes">
  ## Управление существующими токенами
</div>

В разделе **External access tokens** перечислены все токены, которые вы создали для
приложения — от новых к старым — вместе с меткой, средой, датой создания,
сроком действия и статусом отзыва. В каждой строке показаны последние символы токена,
чтобы вам было проще их различать, поскольку значение целиком отображается
только в момент создания.

Вы видите только те токены, которые создали *вы*. Токены других участников доступны
только им самим, даже если вы владелец приложения.

<div id="revogar-um-token">
  ## Отзыв токена
</div>

Отзывайте токен, как только он перестанет быть нужен, или сразу же, если подозреваете, что
он мог быть скомпрометирован. Чтобы отозвать токен:

<Steps>
  <Step>
    Откройте раздел **External access tokens** в настройках публикации приложения.
  </Step>

  <Step>
    Найдите токен в списке и нажмите на значок корзины.
  </Step>

  <Step>
    Подтвердите отзыв.
  </Step>
</Steps>

Отзыв выполняется **немедленно и необратимо**. Весь трафик, который всё ещё использует
токен, начнёт отклоняться уже через несколько секунд. Если доступ понадобится снова, создайте
новый токен.

Вы можете отзывать только те токены, которые создали сами. При удалении участника из
workspace токены, созданные им для этого приложения, отзываются автоматически.

<div id="mantenha-seus-tokens-seguros">
  ## Храните токены в безопасности
</div>

Внешние токены доступа — это учётные данные. Обращайтесь с ними так же
бережно, как с ключом API или паролем.

<div id="o-que-fazer">
  ### Что делать
</div>

* **Храните токены в менеджере секретов** — Secrets в GitHub Actions, хранилище вашего
  CI-провайдера, хранилище секретов облачного провайдера или менеджер паролей.
  Никогда не коммитьте их в репозиторий.
* **По возможности задавайте короткий срок жизни.** Токен на 7 дней для
  разовой интеграции безопаснее, чем токен на 5 лет, забытый где-то в настройках.
* **Помечайте каждый токен**, чтобы понимать, для чего он нужен и используется ли он до сих пор. Токены без меток утекают первыми, а отзываются последними.
* **Создавайте отдельный токен для каждого потребителя.** Один токен на CI-задачу, один на
  источник вебхуков, один на проверку доступности. Если что-то будет скомпрометировано — или
  подрядчик больше не понадобится — вы отзовёте только этот токен.
* **Используйте заголовок `Authorization`**, а не параметры запроса, чтобы токен не
  утёк через логи URL, историю браузера или заголовки referer.
* **Немедленно отзывайте токен**, если он мог быть раскрыт: утёкший лог,
  коммит в публичный репозиторий, запись экрана, ноутбук бывшего сотрудника.
  Отзыв действует сразу; замену создадите потом.

<div id="o-que-no-fazer">
  ### Чего делать не следует
</div>

* **Не используйте один токен совместно с коллегами или между сервисами.** Если две
  системы используют один токен, вы не сможете отозвать его для одной, не сломав другую.
* **Не вставляйте токены в чаты, письма, снимки экрана или трекеры задач.**
  Эти каналы архивируются, индексируются и распространяются непредсказуемым образом.
* **Не встраивайте токены в клиентский код** — браузерные приложения, мобильные приложения,
  десктопные бинарные файлы. Всё, что попадает на устройство пользователя, следует считать общедоступным.
* **Не полагайтесь на токены для браузерных сессий.** Токены предназначены для вызовов API,
  а не для загрузки SPA во вкладке браузера. Для этого используйте обычный вход в Replit.
* **Не выбирайте срок действия в 5 лет по умолчанию.** Задавайте время жизни исходя из того,
  как долго потребителю действительно нужен доступ.

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

<Accordion title="Мой производственный токен внезапно перестал работать">
  Производственные токены остаются действительными при обычных повторных публикациях. Проверьте,
  не истёк ли срок действия токена и не отзывали ли вы его. Также убедитесь, что вы не снимали
  публикацию, не удаляли deployment и не меняли доступ к приложению с приватного на публичный.
  Если у приложения больше нет приватного deployment, опубликуйте его снова как
  приватное. Затем создайте новый токен. Восстановить истёкший
  или отозванный токен невозможно.
</Accordion>

<Accordion title="Мой токен работает с `curl`, но в браузере всё равно отображается страница входа">
  Токены внешнего доступа предназначены для трафика API, а не для сессий браузера. Когда одностраничное приложение загружается в браузере, первоначальный запрос HTML может передать токен через параметр запроса, но последующие запросы бандлов JavaScript, CSS и вызовы API его уже не содержат и будут отклонены. Чтобы работать с приложением интерактивно, войдите в Replit обычным способом.
</Accordion>

<Accordion title="Я потерял токен — можно посмотреть его снова?">
  Нет. Replit показывает токен только один раз — в момент создания. В списке отображаются
  метаданные (метка, окружение, срок действия, последние символы), но никогда — полное значение токена. Если вы его потеряли, отзовите этот токен и создайте новый.
</Accordion>
