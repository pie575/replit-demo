Ошибки случаются: неудачное изменение схемы, удалённые строки или сессия Agent, которая пошла не по плану. Replit предлагает способы восстановления для каждой базы данных.

| База данных | Способ восстановления                                            | Доступность                                                             |
| ----------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Разработка  | Откат к чекпоинту                                                | Все тарифы                                                              |
| Продакшн    | Восстановление на момент времени и резервные копии по расписанию | Core: история до 7 дней. Pro и Enterprise: до 28 дней (по умолчанию 7). |

<div id="section">
  ## Восстановление базы данных разработки
</div>

С помощью [функции отката](/ru/ko/features/version-control/checkpoints-and-rollbacks/) вы можете вернуть приложение и базу данных разработки к предыдущему состоянию. Эта функция позволяет восстановить базу данных до любого чекпоинта, созданного Agent.

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="Интерфейс отката к чекпоинту с вариантами отката" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

<Info>
  При восстановлении состояния чекпоинта необходимо выбрать «Database» в разделе «Дополнительные параметры отката». После этого база данных вернётся к состоянию на момент создания чекпоинта.
</Info>

<div id="section-2">
  ## Восстановление продакшн-базы данных
</div>

Для продакшн-баз данных доступно восстановление на момент времени: базу данных можно вернуть к нужному моменту.

<Frame>
  <img src="/assets/mirror/database-rollbacks-f13dd20874ae.jpg" alt="Интерфейс отката базы данных с параметрами отката" width="1082" height="708" data-path="images/databases/database-rollbacks.jpg" />
</Frame>

Глубина восстановления зависит от тарифа. Тариф Core хранит историю до 7 дней, а тарифы Pro и Enterprise — до 28 дней. На всех тарифах срок хранения изначально составляет 7 дней, изменить его можно в настройках продакшн-базы данных. Чем дольше срок хранения, тем больше расходуется места в хранилище, поэтому его увеличение повышает стоимость использования. При переходе с Pro на Core срок хранения сокращается до 7 дней.

<Warning>
  Восстановление базы данных не затрагивает код приложения, а откат приложения не восстанавливает базу данных. Чтобы вернуть и то, и другое к одному моменту, восстановите базу данных, затем [откатитесь к соответствующему чекпоинту](/ru/ko/features/version-control/checkpoints-and-rollbacks/) и повторно опубликуйте приложение.
</Warning>

<div id="section-3">
  ## Планирование резервного копирования продакшн-базы данных
</div>

Запланированное резервное копирование создаёт одну точку полного восстановления в день. При включении или изменении расписания Replit назначает резервное копирование примерно на полночь по текущему часовому поясу вашего браузера.

1. Откройте инструмент **Database** и выберите продакшн-базу данных.
2. Откройте **Settings**, затем в разделе **Advanced** разверните **Scheduled backups**.
3. Чтобы включить запланированное резервное копирование, выберите срок хранения в поле **Keep backups for**.

Доступные сроки хранения зависят от тарифа. Core поддерживает до 7 дней, Pro и Enterprise — до 28 дней.

<div id="section-4">
  ### Стоимость хранилища
</div>

Replit тарифицирует каждую категорию хранилища продакшн-базы данных отдельно:

| Категория хранилища                               | Цена за ГиБ в месяц |
| ------------------------------------------------- | ------------------: |
| Логическое хранилище базы данных                  |               $0.35 |
| Хранилище восстановления на момент времени (PITR) |               $0.20 |
| Хранилище запланированных резервных копий         |               $0.09 |

<Note>В настоящее время на стоимость хранилища базы данных действует скидка 100%.</Note>

Тариф $0.35 за логическое хранилище применяется в любом случае: при использовании PITR, запланированных резервных копий или того и другого. Хранилище запланированных резервных копий обходится дешевле в расчёте на ГиБ, чем хранилище PITR. Если вам достаточно ежедневных точек восстановления, вы можете сократить расходы на хранилище для восстановления, установив более короткий период PITR и используя запланированные резервные копии. Общая стоимость резервного копирования зависит от объёма сохранённых копий и срока их хранения.

PITR предоставляет больше точек восстановления в пределах своего периода. Запланированные резервные копии дают одну точку восстановления в день, поэтому выбирайте тот способ восстановления, который отвечает вашим потребностям.

<Note>
  Это расписание основано на текущем смещении UTC. Из-за перехода на летнее время время резервного копирования может сместиться на час, пока вы не обновите расписание. Для часовых поясов со смещением в минутах используется ближайший час.
</Note>

<div id="section-5">
  ### Восстановление из запланированной резервной копии
</div>

1. В настройках продакшн-базы данных откройте раздел **Scheduled backups**.
2. Выберите **View all backups**.
3. Напротив нужной точки восстановления выберите **Restore**.
4. Введите `restore` и выберите **Continue**.

После восстановления база данных переключится на данные из выбранной резервной копии. Текущие данные не удаляются, но подключённым сервисам может потребоваться кратковременное переподключение.

<div id="section-6">
  ## Устранение ошибок публикации
</div>

Если публикация завершается ошибкой из-за проблем с базой данных:

1. **Проверьте журналы публикации** — в них будут конкретные сообщения об ошибках подключения к базе данных или конфликтах схемы
2. **Просмотрите последние изменения схемы** на предмет возможных конфликтов с существующим кодом приложения
3. **Протестируйте изменения в предпросмотре деплоя**, прежде чем публиковать снова
