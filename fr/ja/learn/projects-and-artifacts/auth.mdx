Auth (abréviation d’**authentification**) introduit la notion d’« utilisateur » dans votre application. Sans authentification, tous les visiteurs sont anonymes et votre application ne peut pas distinguer une personne d’une autre. Avec l’authentification, chaque visiteur se connecte, votre application sait qui il est et peut enregistrer des données propres à cette personne : réservations, voitures enregistrées, paramètres et progression.

L’intégration de l’authentification vous permet de :

* Enregistrer des données pour chaque utilisateur — réservations, paramètres, contenu et historique.
* Restreindre l’accès à des fonctionnalités aux utilisateurs connectés (paiement, pages de profil et panneaux d’administration).
* Personnaliser l’expérience en fonction du nom, du rôle, du forfait et des actions passées.
* Suivre l’activité et l’utilisation par personne, plutôt que par session.

<div id="replitauth">
  ## Comment fonctionne Auth dans une application Replit
</div>

Replit propose deux options d’authentification intégrées. Toutes deux sont provisionnées par Agent : pas besoin de s’inscrire séparément sur un tableau de bord ni de copier-coller des clés OAuth.

* **[Replit Auth](/fr/ja/features/auth-and-identity/authentication)** — Les utilisateurs se connectent avec leur **compte Replit** existant. La page de connexion est aux couleurs de Replit. Demandez simplement à Agent de l’ajouter : aucune configuration n’est nécessaire.
* **[Clerk Auth](/fr/ja/features/auth-and-identity/clerk-auth)** — Votre application dispose d’un **tenant Clerk** dédié. Les utilisateurs créent des comptes dans *votre* application, et non sur Replit. Vous contrôlez l’image de marque, les méthodes de connexion et l’apparence de l’écran de connexion.

Les deux options se chargent des tâches complexes — pages de connexion, sessions, gestion sécurisée des mots de passe, connexion via les réseaux sociaux — afin que le code de votre application n’ait plus qu’à demander : « Qui est l’utilisateur connecté ? »

<div id="replit-auth-vs-clerk-auth">
  ## Replit Auth vs. Clerk Auth
</div>

|                         | Replit Auth                                                                         | Clerk Auth                                                                       |
| ----------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **Comptes utilisateur** | Connexion avec un compte Replit                                                     | Création de comptes dans l’application (sans compte Replit)                      |
| **Image de marque**     | Page de connexion aux couleurs de Replit                                            | Entièrement personnalisable — nom, icône et couleurs de l’application            |
| **Identifiants SSO**    | Utilisation de l’application OAuth partagée de Replit                               | Utilisation de ses propres identifiants OAuth pour chaque fournisseur            |
| **Environnements**      | Environnement unique                                                                | Environnements de développement et de production séparés                         |
| **Idéal pour**          | Configuration rapide, prototypes et applications où la marque Replit est acceptable | Applications avec une identité de marque, produits professionnels et commerciaux |

Pour créer un prototype ou un outil interne, Replit Auth est l’option la plus rapide. Pour créer une application avec sa propre identité de marque, notamment destinée aux clients ou à un usage commercial, Clerk Auth est plus adapté.

<div id="section">
  ## Ajouter l’authentification à votre application
</div>

Vous n’avez pas besoin de faire votre choix à l’avance : vous pouvez commencer avec l’une ou l’autre, puis migrer ultérieurement. Le moyen le plus rapide est d’indiquer à Agent celle que vous souhaitez utiliser :

* *« Ajoute la connexion à mon application avec Replit Auth. »*
* *« Ajoute la connexion à mon application avec Clerk Auth. »*
