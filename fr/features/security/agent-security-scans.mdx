Les analyses de sécurité d&#39;Agent passent en revue l&#39;intégralité de votre base de code afin d&#39;y détecter les vulnérabilités de sécurité et de confidentialité. Security Agent associe une analyse fondée sur des modèles à des outils d&#39;analyse statique tels que [Semgrep](https://semgrep.dev/) et [HoundDog.ai](https://hounddog.ai), puis présente ses constats dans le Project Security Center.

Les analyses de sécurité d&#39;Agent sont accessibles à tous les créateurs Replit disposant d&#39;un abonnement payant. Sur les projets volumineux, un audit approfondi peut prendre jusqu&#39;à 15 minutes.

<div id="what-security-agent-reviews">
  ## Ce que Security Agent examine
</div>

Lorsque vous lancez une analyse, Security Agent :

1. Cartographie les routes, les API, les flux de données et les points d&#39;entrée.
2. Élabore un modèle de menaces pour l&#39;application.
3. Exécute une analyse statique sur la base de code.
4. Évalue les constats dans le contexte de l&#39;application.
5. Génère un rapport de constats que vous pouvez examiner.

Cet examen permet d&#39;identifier les modèles de code non sécurisés tels que l&#39;injection SQL, le cross-site scripting et la falsification de requête intersites, les problèmes de confidentialité comme des données sensibles transmises aux journaux ou à des API tierces, ainsi que les vulnérabilités architecturales dans les routes, les API et les flux de données.

<div id="start-an-agent-security-scan">
  ## Lancer une analyse de sécurité d&#39;Agent
</div>

<Steps>
  <Step title="Ouvrir le Security Center">
    Dans le volet **Tools** de votre projet, sélectionnez **Security Center**. Vous pouvez également
    sélectionner **Review security** depuis le flux de publication.

    <Frame>
      <img src="/assets/mirror/review-security-button-9331149c28f7.png" alt="Action Review security dans le flux de publication" width="1440" height="900" data-path="images/project-security-center/review-security-button.png" />
    </Frame>
  </Step>

  <Step title="Lancer l'analyse">
    Sélectionnez **Run scan with Agent**.

    <Frame>
      <img src="/assets/mirror/run-scan-with-agent-f54820ac154a.png" alt="Action Run scan with Agent dans le Project Security Center" width="1440" height="900" data-path="images/project-security-center/run-scan-with-agent.png" />
    </Frame>
  </Step>

  <Step title="Ajouter du contexte si nécessaire">
    Vous pouvez éventuellement ajouter du contexte pour cibler des parties précises de votre application dans le modèle de menaces, puis lancer l&#39;analyse de sécurité.

    <Frame>
      <img src="/assets/mirror/scan-options-c2cd398fa78b.png" alt="Options d'analyse de sécurité avec un champ Add context et l'action Start security scan" width="1440" height="900" data-path="images/project-security-center/scan-options.png" />
    </Frame>
  </Step>

  <Step title="Attendre le résultat de l'analyse">
    Attendez que Security Agent termine l&#39;analyse. Cela prend généralement quelques minutes, et jusqu&#39;à 15 minutes pour les projets les plus volumineux.
  </Step>
</Steps>

<div id="review-and-fix-findings">
  ## Examiner et corriger les constats
</div>

<Steps>
  <Step title="Examiner le rapport">
    Inspectez chaque constat et sa gravité dans le **Security Center**. Écartez
    les constats que vous comprenez et acceptez, ou modifiez-les avant de les
    envoyer en remédiation.
  </Step>

  <Step title="Corriger les constats acceptés avec Agent">
    Envoyez les problèmes acceptés à Agent. Security Agent répartit les vulnérabilités en
    tâches distinctes afin qu&#39;Agent puisse traiter plusieurs correctifs en parallèle.
  </Step>

  <Step title="Relancer l'analyse">
    Une fois les correctifs appliqués par Agent, lancez une nouvelle analyse pour vérifier que les problèmes sont
    résolus. Les projets plus volumineux peuvent révéler d&#39;autres problèmes une fois les constats
    de gravité élevée corrigés.
  </Step>
</Steps>

<div id="when-to-use-level-3">
  ## Quand utiliser Level 3
</div>

Une analyse de sécurité d&#39;Agent examine le code source. Si vous devez également inspecter l&#39;application en cours d&#39;exécution via des interactions avec le navigateur et le réseau, utilisez un [test d&#39;intrusion en boîte noire Level 3](/fr/features/security/black-box-pen-tests). Level 3 exécute en parallèle le test en boîte noire et la revue du code source.

<div id="limitations-and-best-practices">
  ## Limites et bonnes pratiques
</div>

* L&#39;analyse s&#39;exécute sur l&#39;infrastructure Replit. Replit n&#39;envoie ni votre code ni vos données à Semgrep, HoundDog.ai ou à d&#39;autres tiers.
* La configuration et les résultats de l&#39;analyse restent rattachés à votre Replit App.
* Une analyse ne remplace pas un audit de sécurité complet. Utilisez-la en complément de la revue de code, des tests, de la revue des dépendances et des vérifications sur l&#39;application en cours d&#39;exécution.
* Relancez une analyse après toute modification importante du code, après l&#39;ajout ou la mise à jour de dépendances, et avant de publier une nouvelle version.
