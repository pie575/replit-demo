# Geografia do projeto

> Escolha onde a computação e o armazenamento de um Project publicado são hospedados.

A geografia do projeto é a geografia de publicação de um Project. Você a seleciona ao publicar, e ela controla onde a computação e o armazenamento do Project publicado são hospedados.

<Note>
  A geografia do projeto e a [geografia do
  workspace](/features/collaboration/workspace-geography) podem ser
  diferentes. A geografia do workspace controla onde os recursos de
  desenvolvimento para novos Projects em um Workspace são hospedados.
</Note>

## O que a geografia do projeto controla

Por padrão, o Replit recomenda a geografia mais próxima de você. Isso ajuda a reduzir a latência para os visitantes do seu app e a atender requisitos de residência de dados.

Quando você seleciona uma geografia, todos os artefatos publicados do seu Project, como computação, banco de dados e Object Storage, são automaticamente colocados na mesma região. Um proxy específico da geografia também ajuda a reduzir a latência para os visitantes do seu app.

## Selecione uma geografia de projeto

Para escolher uma geografia diferente da recomendada:

<Steps>
  <Step>Abra a ferramenta **Publishing** no seu Replit Project.</Step>
  <Step>Expanda as configurações **Advanced**.</Step>
  <Step>Selecione sua geografia preferida no menu suspenso **Geography**.</Step>

  <Step>
    Selecione **Publish** para publicar seu Project na geografia selecionada.
  </Step>
</Steps>

## Aplique uma geografia obrigatória para projetos publicados

Administradores de organizações Enterprise podem aplicar uma geografia de publicação obrigatória para todos os Projects da organização. Quando uma política é definida, os builders da organização publicam na geografia configurada. Essa política se aplica somente a Projects que ainda não foram publicados. Projects já publicados em uma geografia diferente não são afetados.

<Note>
  Aplicar uma geografia de publicação obrigatória é um recurso Enterprise.
  Para saber mais sobre os planos Enterprise, veja
  [Pricing](https://replit.com/pricing/).
</Note>

<Steps>
  <Step>Acesse suas **Account settings**.</Step>
  <Step>Selecione **Advanced**.</Step>

  <Step>
    Escolha a geografia que todos os Projects publicados pela primeira vez
    devem usar.
  </Step>
</Steps>

## Disponibilidade e limites

| Geografia            | Seleção de publicação do projeto |
| :------------------- | :------------------------------- |
| **América do Norte** | Sim                              |
| **Europa (UE)**      | Sim                              |
| **Ásia**             | Sim                              |
| **América do Sul**   | Sim                              |
| **Austrália**        | Sim                              |

<Note>
  A seleção de geografia do projeto está disponível para clientes Core, Pro
  e Enterprise. Clientes do plano gratuito publicam na América do Norte por
  padrão.
</Note>

Antes de selecionar uma geografia de projeto, tenha em mente estas limitações:

* **A geografia não pode ser alterada após a publicação.** Depois que você publica seu Project em uma geografia, essa seleção é permanente. Você não pode migrar um Project publicado para uma geografia diferente.
* **Os locais de desenvolvimento e de publicação podem ser diferentes.** Recursos como o Object Storage podem ser criados antes de você publicar e podem não corresponder à geografia do seu Project.
