Дизайн-система даёт Agent знания, необходимые для создания интерфейсов в фирменном стиле во всём, что ваша организация создаёт на Replit: в веб-приложениях, мобильных приложениях, презентациях и других артефактах. Настройте библиотеку компонентов, дизайн-токены, брендовые ассеты и правила их использования в стандартном монорепозитории Replit на pnpm — и Agent будет применять ваш визуальный язык уже с первого prompt.

<Note>
  Дизайн-системы доступны исключительно на плане **Enterprise**. Настраивать дизайн-системы и управлять ими могут только администраторы организации.
</Note>

<div id="why-set-up-a-design-system">
  ## Зачем настраивать дизайн-систему
</div>

Без дизайн-системы каждому разработчику приходится вручную объяснять Agent, как устроены ваша библиотека компонентов, цветовые токены и правила вёрстки. Настройка дизайн-системы решает эту проблему:

* **Закрепляет ваши визуальные стандарты**: Agent использует именно ваши компоненты, цвета и отступы, а не универсальные значения по умолчанию
* **Обеспечивает единообразие**: каждый App следует единому языку дизайна
* **Сокращает время адаптации**: новые разработчики сразу выдают результат в фирменном стиле
* **Сохраняет неявные знания**: дизайн-решения и подходы к использованию компонентов, которые хранятся только в головах вашей команды, фиксируются в документации для Agent

<div id="what-you-will-need">
  ## Что вам понадобится
</div>

* Библиотека фронтенд-компонентов в виде tar-файла или набора tar-файлов
* Шрифтовые ассеты и иконки, используемые в вашей дизайн-системе
* Любая документация вашей дизайн-системы для ИИ (MCP, Agent Skills)

<div id="what-you-can-configure">
  ## Что можно настроить
</div>

Настройка дизайн-системы состоит из трёх частей:

1. **Пользовательские инструкции**. Файл `custom_instruction/instructions.md` задаёт для Agent общие правила, действующие для каждого проекта: какую библиотеку компонентов использовать, на какие дизайн-токены опираться и каким паттернам следовать. Этот файл всегда находится в контексте Agent.

2. **Навыки**. Навыки в `.agents/skills/` содержат подробные справочные материалы, которые Agent загружает по мере необходимости. Используйте их для документации по API компонентов, руководств по темизации, библиотек паттернов вёрстки и другого объёмного справочного материала, который был бы слишком велик для основного файла инструкций.

3. **Дизайн- и брендовые ассеты**. Разместите логотипы, иконки, шрифты и другие брендовые ассеты в отдельной папке (например, `src/assets/brand/`). Настройте псевдоним пути в Vite, чтобы Agent и разработчики могли ссылаться на них через аккуратные импорты вида `@brand/logo.svg`, а не через ненадёжные относительные пути. Так ссылки на ассеты останутся единообразными во всём проекте.

<div id="step-by-step-guide">
  ## Пошаговое руководство
</div>

Это руководство описывает полную настройку дизайн-системы на основе вашей существующей библиотеки компонентов, упакованной в tar-файлы:

1. **Создайте новое приложение Replit** и загрузите свои tar-файлы.
2. **Попросите Replit Agent установить пакеты и отобразить все компоненты.** Agent настроит проект и отрисует вашу библиотеку компонентов.
3. **Проверьте результат.** Убедитесь, что все компоненты отображаются корректно и соответствуют вашим ожиданиям. После проверки переходите к разделу [Создание skill для дизайн-системы](#creating-the-design-system-skill).

<div id="creating-the-design-system-skill">
  ### Создание навыка для дизайн-системы
</div>

Компоненты готовы, и остаётся последний шаг — создать навык для дизайн-системы, чтобы Agent мог обращаться к вашим компонентам, токенам и правилам их использования в каждом проекте.

Скопируйте весь prompt ниже и вставьте его в Agent. Замените `<your-design-system-name>` на название вашей дизайн-системы:

````
Создай навык дизайн-системы `<your-design-system-name>` на основе компонентов и пакетов этого проекта.

Используй показанную ниже структуру файлов: `SKILL.md` в корне, каталог `references/` для руководств и документации по компонентам и каталог `packages/` со всеми зависимостями, необходимыми для работы.

Пройди по всем компонентам проекта и опиши каждый в отдельном файле в каталоге `references/components/`, указав его пропсы, варианты и примеры использования.

Оформи `SKILL.md` как оглавление со ссылками на файлы руководств и справочников по компонентам, с разделом «General Guidance» и разделом «Components», следуя примеру ниже.

Структура файлов:

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (Tar files or code components)

Файл `SKILL.md` служит оглавлением со ссылками на отдельные markdown-файлы с руководствами и справочниками по компонентам. Каждый такой файл подробно раскрывает одну тему. Вот пример того, как выглядит сгенерированный `SKILL.md`:

```markdown
---
name: your-design-system
description: Use when building or modifying any UI. Provides component API references, layout guidance, and visual style rules for your design system.
---

# Your Design System

## General Guidance

- [Setup](references/guides/setup.md) — Installation, project configuration, and provider setup
- [Guardrails](references/guides/guardrails.md) — Hard rules that must never be broken (banned patterns, required tokens, accessibility minimums)
- [Layout & Spacing](references/guides/layout-and-spacing.md) — Grid system, spacing scale, responsive breakpoints, and page templates
- ...

## Components

- [Component Index](references/components/component-index.md) — Full list of available components with status and category

Individual component references (props, variants, examples):

- [Button](references/components/button.md)
- [Checkbox](references/components/checkbox.md)
- ...
```

Каждый файл руководства посвящён одной теме: шагам настройки и установки, лучшим практикам и правилам, справочным таблицам значений токенов и коротким примерам кода с правильным использованием.

Каждый файл компонента описывает один компонент: его название, краткое описание, таблицу пропсов, примеры использования, а также рекомендации и ограничения. Чем полнее эти файлы, тем лучше будет результат работы Agent.
````

<div id="connect-your-skill-to-agent">
  ### Подключите навык к Agent
</div>

После создания навыка убедитесь, что файл `custom_instruction/instructions.md` направляет Agent к нему:

```markdown theme={null}
# Дизайн-система

Изучи навык дизайн-системы в `.agents/skills/your-design-system/` и следуй ему.
Всегда применяй дизайн-систему при создании или изменении интерфейса.
```

Наконец, заранее заполните `replit.md` контекстом, специфичным для дизайн-системы, чтобы Agent с самого начала понимал ваши визуальные стандарты. Укажите обзор проекта, предпочитаемую библиотеку компонентов, ключевые предпочтения в дизайне (шкала отступов, требования к доступности) и архитектурный стек.

<div id="validate-your-setup">
  ### Проверьте настройку
</div>

Прежде чем разворачивать дизайн-систему, убедитесь, что всё необходимое на месте:

* `custom_instruction/instructions.md` указывает Agent на навык вашей дизайн-системы
* `.agents/skills/` содержит навык со ссылками на компоненты, руководствами и пакетами
* `replit.md` заранее заполнен обзором проекта, предпочтениями и описанием архитектуры
* Файл дизайн-токенов добавлен (`tokens.css` или аналогичный)
* Пакет дизайн-системы предустановлен в `package.json`
* Создайте новый тестовый app и проверьте, что Agent корректно использует дизайн-систему

<div id="pin-the-design-system-to-your-organization">
  ### Закрепите дизайн-систему в организации
</div>

Когда дизайн-система готова, закрепите её, чтобы ею мог пользоваться каждый участник организации:

1. Перейдите к App с дизайн-системой в вашей организации
2. Откройте меню действий App (меню с тремя точками)
3. Выберите **Pin to Agent input box**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий App с пунктом Pin to Agent input box" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Закреплять и откреплять дизайн-системы могут только администраторы организации (участники роли `system_admins`).
</Note>

Установите для участников доступ **Read-only**, чтобы они могли видеть и использовать закреплённую дизайн-систему, но не могли её редактировать.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалог приглашения с доступом участника Read-only" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Теперь дизайн-система отображается в виде плашки для выбора под полем ввода Agent у каждого участника вашей организации. Чтобы убрать её, откройте то же меню и выберите **Unpin from Agent input box**.

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Дизайн-система в виде плашки для выбора в поле ввода Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

<div id="maintain-your-design-system-over-time">
  ## Поддерживайте дизайн-систему в актуальном состоянии
</div>

Дизайн-системы развиваются. Следите за актуальностью своей:

* **Обновляйте файлы токенов**, когда в дизайн-системе появляются новые цвета, отступы или значения типографики
* **Обновляйте навыки**, когда у компонентов появляются новые пропсы, варианты или сценарии использования
* **Обновляйте инструкции**, когда меняются принципы или стандарты дизайна
* **Повышайте версии пакетов**, когда выходят новые релизы вашей дизайн-системы
* **Регулярно проверяйте результат**: создайте новый app и убедитесь, что Agent выдаёт корректный результат

<div id="design-systems-vs-custom-templates">
  ## Дизайн-системы и пользовательские шаблоны
</div>

Дизайн-системы и [пользовательские шаблоны](/ru/teams/custom-templates) служат разным целям:

|                   | Дизайн-системы                                                                         | Пользовательские шаблоны                                                                |
| ----------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **Назначение**    | Заменить фронтенд-стек на стек вашей команды и задействовать ваши компоненты           | Полностью заменить стек по умолчанию (например, Rust, Go, C++)                          |
| **Стек**          | Работает в рамках стандартного pnpm-монорепозитория Replit                             | Задаёт полностью пользовательскую структуру проекта                                     |
| **Что даёт**      | Правила библиотеки компонентов, дизайн-токены, брендовые ассеты, визуальные навыки     | Полную заготовку: среда выполнения, конфигурация сборки, зависимости, структура проекта |
| **Применяется к** | Веб-приложениям, мобильным приложениям, слайдам, артефактам — всему, что создаёт Agent | Только к приложениям, созданным из этого конкретного шаблона                            |

Используйте дизайн-систему, если хотите, чтобы Agent соблюдал ваши визуальные стандарты в рамках привычной работы с Replit. Используйте пользовательский шаблон, если вам нужен принципиально иной стек.
