Контекст — это информация, которую модель ИИ использует для формирования следующего ответа. Управление контекстом — это предоставление модели нужной информации в нужный момент.

Это важно, поскольку ИИ не может опираться только на ваши намерения. Он использует текст, файлы, снимки экрана, журналы, примеры и историю беседы, доступные в его контекстном окне.

<div id="what-is-a-context-window">
  ## Что такое контекстное окно?
</div>

У ИИ-модели есть ограничение на объём информации, которую она может учитывать одновременно. Это ограничение называется контекстным окном.

Контекстное окно может включать:

* Ваш промпт
* Предыдущие сообщения в беседе
* Файлы или код, доступные модели
* Сообщения об ошибках и журналы
* Снимки экрана, изображения или референсы дизайна
* Инструкции Project, например `replit.md`
* Результаты работы инструментов на предыдущих шагах

Модель использует этот контекст, чтобы решить, что сгенерировать дальше.

<div id="why-context-windows-matter">
  ## Почему важно контекстное окно
</div>

Если в контексте нет важных деталей, модель может начать догадываться. Если же контекст содержит слишком много не связанной с задачей информации, модель может сосредоточиться не на том.

Например, в этом prompt почти нет контекста:

```text theme={null}
Улучшите страницу регистрации.
```

Этот промпт содержит полезный контекст:

```text theme={null}
Улучшите страницу регистрации для тех, кто впервые запускает стартап и решает, стоит ли записаться в лист ожидания.
Сохраните текущие поля. Сделайте ценностное предложение над формой более понятным.
Не меняйте раздел с ценами.
```

Второй prompt сообщает модели, для кого предназначена страница, что следует улучшить, что сохранить и что выходит за рамки задачи.

<div id="context-window-sizes-vary">
  ## Размер контекстного окна зависит от модели
</div>

Разные модели ИИ могут работать с разным объёмом контекста. Окна большего размера позволяют учитывать больше текста одновременно, но больше — не всегда лучше. Релевантный контекст по-прежнему важнее, чем добавление в беседу всех деталей подряд.

Примеры размеров общедоступных контекстных окон:

| Семейство моделей | Пример размера контекстного окна |
| ----------------- | -------------------------------- |
| GPT-4.1           | До 1 миллиона токенов            |
| Claude Sonnet 4.5 | До 200 000 токенов               |
| Gemini 2.5 Pro    | До 1 миллиона токенов            |

Эти значения со временем меняются и не гарантируют, что каждый продукт предоставляет полный лимит модели. Практический вывод остаётся неизменным: важная информация должна быть ясной и сфокусированной.

<div id="types-of-context">
  ## Типы контекста
</div>

| Тип контекста           | Пример                                                                      |
| ----------------------- | --------------------------------------------------------------------------- |
| **Цель**                | «Эта посадочная страница должна собирать заявки в лист ожидания».           |
| **Аудитория**           | «Это предназначено для занятых владельцев ресторанов».                      |
| **Ограничения**         | «Сохраните текущую цветовую палитру и поля формы».                          |
| **Что не нужно делать** | «Пока не добавляйте оплату».                                                |
| **Примеры**             | Скриншот, макет, пример данных или страница конкурента.                     |
| **Состояние проекта**   | Текущий файл, компонент, сообщение об ошибке или пользовательский сценарий. |
| **Критерий готовности** | «Посетитель может отправить форму и увидеть сообщение с благодарностью».    |

<div id="fresh-context-and-persistent-context">
  ## Актуальный и постоянный контекст
</div>

Часть контекста относится к текущей беседе. Используйте её, когда запрашиваете конкретное изменение, отлаживаете одну проблему или оставляете отзыв о недавнем результате.

Другой контекст должен сохраняться на протяжении всей работы над проектом. Используйте постоянный контекст для стиля написания кода, рекомендаций по бренду, соглашений об именовании, повторно используемых правил продукта и ограничений, которые Agent должен помнить между рабочими сессиями. В Replit файл [replit.md](/ru/features/project-setup/replit-dot-md) — один из способов предоставить Agent постоянный контекст проекта.

<div id="when-context-gets-noisy">
  ## Когда контекст становится перегруженным
</div>

В длинных беседах можно потерять фокус. Если в ветке смешалось слишком много несвязанных решений, Agent может учитывать старый контекст, который уже не имеет значения.

Начните новую ветку, если:

* Вы переключаетесь на несвязанную функцию
* В беседе накопилось много заброшенных направлений
* Agent продолжает учитывать старые ограничения
* Вам нужен чёткий план для новой области

Начиная новую ветку, кратко изложите важный контекст, а не предполагайте, что Agent знает, что по-прежнему важно.

```text theme={null}
Контекст: этот проект — приложение для записи в лист ожидания к местным фитнес-тренерам.
Основной сценарий: лендинг → форма регистрации → сообщение с подтверждением.
В этой ветке улучшайте только текст сообщения с подтверждением и последующих сообщений.
```

<div id="common-misconceptions">
  ## Распространённые заблуждения
</div>

* **«Чем больше контекста, тем лучше».** Лучше предоставить релевантный контекст. Слишком много несвязанной информации может отвлекать модель.
* **«Модель идеально всё помнит».** ИИ использует доступный контекст, но важные ограничения следует повторять, когда это необходимо.
* **«Контекст — это только текст».** Контекстом могут быть скриншоты, файлы, данные, дизайны, журналы и примеры.
