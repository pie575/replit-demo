<div id="what-is-the-task-system">
  ## 什么是任务系统？
</div>

**任务**是 Agent 可以规划并执行的工作单元。借助任务，Agent 能把较大的目标拆解成更小的部分，让你在每个部分改动应用之前先行审阅。

Agent 可以在两个地方工作：**主线程**和**后台任务**。主线程就是你描述需求、调整方向、决定哪些内容应用到主版本的对话。后台任务则是独立的线程，Agent 在项目的隔离副本中自主开展工作。

主线程用于把握方向、做出决策，后台任务则用于可并行推进的执行工作。在你审阅并应用之前，后台任务不会改动你的主版本。

任务系统就是 Agent 组织这些工作的方式。当你描述想要构建的内容时，Agent 会把你的请求拆分成一个个独立任务，并放到看板上，看板包含以下几列：**Drafts**、**Active**、**Ready** 和 **Done**。

<Frame>
  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="任务看板，展示按 Drafts、Active、Ready 和 Done 各列组织的任务" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />
</Frame>

每个任务随着进展从左向右移动，你可以一眼看清哪些已规划、Agent 正在处理什么、哪些可供审阅、哪些已完成。后台任务会根据你的计划自动排队，工作持续推进的同时又不会挤占主线程。

任务就绪后，你可以审阅这些改动并将其应用回主版本；如果不符合预期，也可以直接舍弃。

<div id="how-background-tasks-work">
  ## 后台任务的工作方式
</div>

<Steps>
  <Step title="规划任务">
    在主线程中开启一段对话，或者新建一个线程并在其中规划。Agent 会审查你的 项目，找出最具影响力的改动，并为每项任务撰写详细计划，说明它将要做什么，以及怎样才算“完成”。

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="在主线程中描述要构建的内容，Agent 提出并运行任务" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="审查并接受">
    Agent 会提出一组任务，每项任务都有标题、描述以及可通过 **View plan** 查看的详细计划。查看完整列表后，选择：

    * **Accept tasks**：启动所有任务并将其转入后台运行
    * **Revise plan**：让 Agent 在开始前调整任务

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="任务计划已创建对话框，显示四项待办任务以及 Accept tasks 和 Revise plan 选项" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="任务开始运行">
    接受后，任务会在你 项目的隔离副本中开始运行。Starter 不支持后台任务；Core 一次运行 1 个，Pro 最多支持 10 个，Enterprise 最多支持 64 个。在你选择应用更改之前，主版本始终保持不变。你可以通过两种方式跟踪进度：

    * **线程视图**：每项任务在各自的线程中运行，并带有实时状态指示器，你可以随时关注进展，或进入任意任务的对话

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="线程视图显示多项任务并行运行，并带有状态指示器" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **看板视图**：以分栏看板展示按状态归类的所有任务：**Drafts**、**Active**、**Ready** 和 **Done**

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="看板视图显示任务分别归入 Drafts、Active、Ready 和 Done 列" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="审查并应用">
    任务完成后，Agent 会向你展示它做了什么：工作日志、测试结果以及更改的实时预览。接下来如何处理由你决定：

    * **Apply changes to main version**：将该任务的成果合并到你的 项目中
    * **Dismiss**：如果结果不符合预期，就放弃这些更改

    应用多项任务的更改时，Agent 会自动处理冲突。

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="任务审查界面，显示 Agent 的工作日志、测试结果和 Apply changes 按钮" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="what-you-can-build">
  ## 你可以构建什么
</div>

任务系统适用于任何 项目。以下几种场景尤其能体现它的价值:

* **将大型功能拆分成小块交付**:把身份验证、仪表板和 API 层拆成独立任务,让 Agent 能够条理清晰地逐一完成
* **规划复杂的 项目**:将大型功能拆解为范围明确、带依赖关系的任务,然后从容推进
* **对比不同的设计方向**:用不同的任务尝试多种 UI 方案,再挑选最佳结果

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<Accordion title="我需要改变构建方式吗？">
  不需要。主线程的使用方式完全不变。Agent 会在需要时自动在后台创建任务。你也可以使用 [Plan 模式](/zh/features/agent/plan-mode) 来显式查看和管理任务。
</Accordion>

<Accordion title="为什么我的任务是一个一个运行的？">
  Starter 不支持后台任务。Core 一次运行 1 个，Pro 最多支持 10 个，Enterprise 最多支持 64 个。达到所在套餐的上限后，其余任务会进入队列，并在有空位时开始运行。
</Accordion>

<Accordion title="Agent 在应用后台任务时如何处理冲突？">
  Agent 采用 AI 辅助的冲突解决方式。它会理解每个任务想要实现的目标，并智能地应用相应更改。如果发现有问题，你可以在线程中让 Agent 来修复。
</Accordion>

<Accordion title="任务之间可以相互依赖吗？">
  可以。Agent 会自动检测依赖关系。例如，构建仪表板的任务依赖于创建数据库架构的任务。有依赖关系的任务会等前置任务完成后再执行。
</Accordion>

<Accordion title="归档任务和取消任务有什么区别？">
  **归档**适用于规划会话，即尚未开始构建的草稿。归档后的规划会话会被保留，可从 **Done** 列中恢复。

  **取消**适用于已从规划阶段进入构建阶段的任务。取消会停止该任务并丢弃其工作成果，且已取消的任务无法恢复，只能新建一个任务。
</Accordion>
