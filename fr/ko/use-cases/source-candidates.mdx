Ashby examine déjà les candidatures entrantes. Ce workflow est destiné au recrutement proactif :
il lit les descriptions de poste dans Drive, trouve des ingénieurs correspondants sur GitHub, ignore les personnes déjà
présentes dans Ashby et rédige les brouillons de messages de prise de contact que vous enverrez. Agent
enregistre les nouvelles personnes comme sourcées, avec une brève explication de leur adéquation et un brouillon à l’intention du
candidat. Vous les examinez et les envoyez. Ne prenez pas de décisions de recrutement uniquement sur cette base.

* Les responsables du recrutement ayant besoin d&#39;ingénieurs identifiés sur GitHub sans passer toute la journée à chercher.

<div id="section-3">
  ## Avant de commencer
</div>

Préparez une description de poste distinguant les critères requis des critères
souhaitables. Connectez Drive, GitHub et Ashby. Indiquez la région, le niveau d’ancienneté et le nombre de personnes recherché. Ne prenez pas de
décisions de recrutement sur cette seule base.

<div id="agent">
  ## Demander à Agent
</div>

<AiPrompt>
  Créez une routine qui s’exécute chaque lundi à 9 h. À partir de cette description de poste [lien Drive
  ou texte collé], trouvez sur GitHub 30 ingénieurs répondant aux
  critères requis. Ignorez les personnes déjà présentes dans Ashby. Pour chaque personne, rédigez
  une justification de trois lignes et un court brouillon de prise de contact. N’envoyez
  rien. Ajoutez les nouvelles personnes à Ashby avec les notes et brouillons dans leur fiche candidat, en indiquant le statut « sourcé ».
</AiPrompt>

<div id="section-4">
  ## Résultats attendus
</div>

Agent lit la description de poste, effectue une recherche sur GitHub, ignore les personnes déjà présentes dans
Ashby et renvoie une liste restreinte avec des brouillons. Vous les examinez et les envoyez.
Les premiers résultats peuvent comporter beaucoup de bruit. Vérifiez-les, puis ajustez les critères requis.
Ouvrez trois profils GitHub de la liste pour vérifier qu’ils correspondent aux critères requis et, avant
d’envoyer quoi que ce soit, assurez-vous que ces personnes ne figurent pas déjà dans Ashby.

<div id="section-6">
  ## Résolution des problèmes
</div>

* **La présélection contient trop de bruit :** après avoir examiné les premiers résultats, ajustez les critères requis et souhaitables. Demandez des commits récents dans certains langages ou types de dépôts, et excluez les personnes qui semblent être des clients actuels ou des employés de concurrents.
* **Des personnes déjà présentes dans Ashby continuent d’apparaître :** vérifiez qu’Ashby est connecté au bon espace de travail et qu’Agent effectue la correspondance à partir de l’adresse e-mail ou du nom d’utilisateur GitHub, et pas uniquement du nom affiché.
* **Des messages de prospection ont été envoyés :** ce workflow ne doit créer que des brouillons. Si un message a été envoyé, arrêtez la routine et indiquez à Agent de ne jamais envoyer d’e-mail ou de message aux candidats.
