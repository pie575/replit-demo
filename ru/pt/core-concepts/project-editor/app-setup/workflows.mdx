Это многоразовая настраиваемая последовательность шагов, которую можно запускать в вашем Replit App. Она может быть как простой — например, запускать `python main.py`, — так и сложной, включающей многоэтапную процедуру.

Примеры использования:

* Параллельный запуск нескольких сервисов (например, фронтенда и бэкенда)

Чтобы [создать workflows](#creating-workflows), откройте панель Workflows в меню на боковой панели инструментов или найдите её с помощью `Command + K`.

<div id="tipos-de-tarefas-disponveis">
  ## Доступные типы задач
</div>

Сейчас доступно 3 типа задач: `Execute Shell Command`, `Install Packages` и `Run Workflow`.

<div id="execute-shell-command">
  ### Выполнение команды Shell
</div>

`Execute Shell Command` сохраняет команду оболочки и выполняет её в среде панели Shell. Этот тип задачи подходит для широкого спектра сценариев, включая выполнение отдельных файлов:

```text theme={null}
python main.py
```

до выполнения сложных команд запросов к базам данных:

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Установка пакетов
</div>

`Install Packages` использует встроенную систему управления зависимостями Replit: она автоматически определяет зависимости проекта и устанавливает необходимые пакеты. Подробнее о том, как UPM в фоновом режиме определяет пакеты, которые нужно установить для вашего проекта, см. в разделе [Управление зависимостями](/ru/pt/core-concepts/project-editor/app-setup/dependency-management#the-universal-package-manager).

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow` позволяет запускать другой workflow из текущего. Это позволяет повторно использовать workflows и комбинировать их для создания более сложных workflows.

Пример использования:

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

Используя этот тип задачи для создания зависимостей между workflows, вы можете редактировать один workflow, а другие workflows, которые на него ссылаются, будут автоматически использовать последние изменения. Обратите внимание, что для вызовов глубоко вложенных workflows действует ограничение глубины.

<div id="modo-de-execuo-do-workflow">
  ## Режимы выполнения Workflow
</div>

Workflow поддерживают два режима выполнения: последовательный и параллельный.

<div id="sequencial">
  ### Последовательный
</div>

При последовательном выполнении задачи запускаются в заданном порядке: следующая начинается только после завершения предыдущей. Если задача в workflow завершится с ошибкой, выполнение последовательности будет остановлено.

Этот режим удобно использовать для настройки логически связанных команд, например команд Git для получения последних изменений из основной ветки и последующего перебазирования текущей ветки на неё:

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="image" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="paralelo">
  ### Параллельный
</div>

В параллельном режиме каждая задача запускается и выполняется независимо от других задач в workflow. Сбой одной задачи не прерывает выполнение остальных.

Этот режим удобно использовать, например, для запуска fullstack-проекта, в котором нужно одновременно запустить фронтенд и бэкенд-сервер:

<div id="criando-workflows">
  ## Создание Workflows
</div>

Создать Workflow можно на панели workflows, нажав кнопку `+ New Workflow`. Для начала задайте Workflow понятное название, выберите подходящий режим запуска и добавьте задачи. Задачи можно менять местами, перетаскивая их в нужном порядке.

<div id="atribuir-workflow-ao-boto-run">
  ## Назначение Workflow кнопке Run
</div>

Workflow можно назначить кнопке Run, чтобы изменить её стандартное поведение (см. [Настройка Replit App](/ru/pt/core-concepts/project-editor/app-setup/configuration)). Чтобы сохранить стандартную команду run, заданную в `.replit`, выберите в раскрывающемся меню вариант по умолчанию «Run Replit App».

При нажатии кнопки Run будет запускаться Workflow, выбранный в раскрывающемся меню рядом с ней. Чтобы изменить Workflow, запускаемый кнопкой Run, выберите нужный Workflow в этом меню.
