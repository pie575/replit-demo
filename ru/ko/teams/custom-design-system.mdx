Дизайн-система предоставляет Agent знания, необходимые для создания соответствующего бренду UI во всём, что организация создаёт в Replit: веб-приложениях, мобильных приложениях, слайдах и других артефактах. Настройте библиотеку компонентов, дизайн-токены, бренд-ассеты и правила их использования в стандартном pnpm-монорепозитории Replit — и Agent будет применять ваш визуальный язык уже с первого промпта.

<Note>
  Дизайн-система доступна только на тарифе **Enterprise**. Настраивать дизайн-систему и управлять ею могут только администраторы организации.
</Note>

<div id="section">
  ## Зачем настраивать дизайн-систему
</div>

Без дизайн-системы каждому разработчику приходится вручную объяснять Agent, какие библиотеки компонентов, цветовые токены и правила компоновки использовать. Настройка дизайн-системы решает эту проблему следующим образом:

* **Кодирование визуальных стандартов**: Agent использует заданные компоненты, цвета и отступы вместо общих значений по умолчанию.
* **Обеспечение единообразия**: Все App используют единый язык дизайна.
* **Сокращение времени адаптации**: Новые разработчики сразу создают результаты, соответствующие бренду.
* **Фиксация неявных знаний**: Решения по дизайну и паттерны использования компонентов, известные членам команды, документируются для Agent.

<div id="section-2">
  ## Что потребуется
</div>

* Библиотека компонентов фронтенда, упакованная в tarfile или набор tarfile
* Шрифты и значки, используемые в дизайн-системе
* Документация для ИИ по дизайн-системе (MCP, Agent Skills)

<div id="section-3">
  ## Настраиваемые элементы
</div>

Настройки дизайн-системы состоят из трёх частей:

1. **Пользовательские инструкции**. Файл `custom_instruction/instructions.md` задаёт для Agent высокоуровневые правила, применимые ко всем проектам: какую библиотеку компонентов использовать, на какие дизайн-токены ориентироваться и каким паттернам следовать. Agent всегда учитывает этот файл в контексте.

2. **Навыки**. Навыки в `.agents/skills/` содержат подробные справочные материалы, которые Agent загружает по мере необходимости. Используйте их для документации API компонентов, руководств по темам, библиотек паттернов макетов и другого подробного справочного контента, который слишком велик для основного файла инструкций.

3. **Дизайн- и бренд-ассеты**. Размещайте логотипы, значки, шрифты и другие бренд-ассеты в отдельной папке (например, `src/assets/brand/`). Настройте псевдонимы путей Vite, чтобы использовать понятные импорты, такие как `@brand/logo.svg`, и поддерживать единообразные ссылки на ассеты вместо ненадёжных относительных путей.

<div id="section-4">
  ## Пошаговое руководство
</div>

В этом руководстве описано, как настроить дизайн-систему с нуля, используя существующую библиотеку компонентов, упакованную в tarfile:

1. **Создайте новый Replit App** и загрузите tarfile.
2. **Поручите Replit Agent установить пакет и отобразить все компоненты.** Agent настроит проект и отрендерит библиотеку компонентов.
3. **Проверьте результат.** Убедитесь, что все компоненты отображаются корректно и соответствуют ожиданиям. Когда всё будет готово, перейдите к разделу [Создание навыка для дизайн-системы](#creating-the-design-system-skill).

<div id="section-5">
  ### Создание навыка для дизайн-системы
</div>

Когда компоненты готовы, последний шаг — создать навык для дизайн-системы, чтобы Agent мог обращаться к компонентам, токенам и шаблонам использования во всех проектах.

Скопируйте приведённый ниже промпт целиком и вставьте его в Agent. Замените `<your-design-system-name>` названием вашей дизайн-системы:

````
Create a `<your-design-system-name>` design system skill from the components and packages in this project.

Use the file structure shown below with a `SKILL.md` at the root, a `references/` directory for guides and component docs, and a `packages/` directory containing all dependencies needed to function.

Go through every component in the project and document each one in its own file under `references/components/`, including its props, variants, and example usage.

Format `SKILL.md` as an index that links out to the guide and component reference files, with a "General Guidance" section and a "Components" section, following the example shown below.

File structure:

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (Tar files or code components)

The `SKILL.md` file acts as an index that links out to separate markdown files for guides and component references. Each linked file covers one topic in detail. Here is an example of what the generated `SKILL.md` looks like:

```markdown
---
name: your-design-system
description: Use when building or modifying any UI. Provides component API references, layout guidance, and visual style rules for your design system.
---

# Your Design System

## General Guidance

- [Setup](references/guides/setup.md) — Installation, project configuration, and provider setup
- [Guardrails](references/guides/guardrails.md) — Hard rules that must never be broken (banned patterns, required tokens, accessibility minimums)
- [Layout & Spacing](references/guides/layout-and-spacing.md) — Grid system, spacing scale, responsive breakpoints, and page templates
- ...

## Components

- [Component Index](references/components/component-index.md) — Full list of available components with status and category

Individual component references (props, variants, examples):

- [Button](references/components/button.md)
- [Checkbox](references/components/checkbox.md)
- ...
```

Guide files cover one topic each — setup and installation steps, best practices and rules, reference tables for token values, and short code examples showing correct usage.

Component files document a single component each, including the component name, a brief description, a props table, usage examples, and any guidelines or constraints. The more complete these files are, the better Agent's output will be.
````

<div id="agent">
  ### Подключение навыка к Agent
</div>

После создания навыка настройте `custom_instruction/instructions.md`, чтобы он направлял Agent к навыку:

```markdown theme={null}
# Дизайн-система

Прочитайте и следуйте инструкциям навыка дизайн-системы в `.agents/skills/your-design-system/`.
Всегда применяйте дизайн-систему при создании или изменении интерфейса пользователя.
```

Наконец, заранее добавьте в `replit.md` контекст, специфичный для вашей дизайн-системы, чтобы Agent с самого начала понимал визуальные стандарты. Включите описание проекта, предпочитаемую библиотеку компонентов, ключевые предпочтения в дизайне (шкалу отступов, требования к доступности) и архитектурный стек.

<div id="section-6">
  ### Проверка настройки
</div>

Перед деплоем дизайн-системы убедитесь, что выполнены следующие требования:

* `custom_instruction/instructions.md` направляет Agent к навыку дизайн-системы
* в `.agents/skills/` есть навыки с документацией по компонентам, руководствами и пакетами
* `replit.md` заранее заполнен описанием проекта, предпочтениями и архитектурой
* добавлены файлы дизайн-токенов (`tokens.css` или аналогичный файл)
* пакет дизайн-системы заранее установлен в `package.json`
* создайте новое тестовое App, чтобы убедиться, что Agent корректно использует дизайн-систему

<div id="section-7">
  ### Закрепление дизайн-системы в организации
</div>

Когда дизайн-система будет готова, закрепите её, чтобы ею могли пользоваться все участники организации:

1. Перейдите в приложение с дизайн-системой организации.
2. Откройте меню действий приложения (меню с тремя точками).
3. Выберите **Pin to Agent input box**.

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий приложения с пунктом Pin to Agent input box" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Закреплять и откреплять дизайн-системы могут только администраторы организации (участники с ролью `system_admins`).
</Note>

Установите для участников уровень доступа **Read-only**, чтобы они могли просматривать и использовать закреплённую дизайн-систему, но не редактировать её.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалоговое окно приглашения, в котором для участников установлен доступ Read-only" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Теперь дизайн-система отображается под полем ввода Agent в виде доступной для выбора плашки для всех участников организации. Чтобы удалить её, откройте то же меню и выберите **Unpin from Agent input box**.

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Дизайн-система, отображаемая в поле ввода Agent в виде доступной для выбора плашки" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

<div id="section-8">
  ## Поддержка дизайн-системы
</div>

Дизайн-системы развиваются. Поддерживайте их в актуальном состоянии:

* **Обновляйте файлы токенов**: при добавлении в дизайн-систему новых цветов, отступов или значений типографики
* **Обновляйте навыки**: при добавлении к компонентам новых props, вариантов или паттернов использования
* **Обновляйте инструкции**: при изменении принципов или стандартов дизайна
* **Обновляйте версии пакетов**: при выходе нового релиза дизайн-системы
* **Регулярно тестируйте**: создавайте новые App и проверяйте, что Agent генерирует корректный результат

<div id="vs">
  ## Дизайн-система и пользовательские шаблоны
</div>

Дизайн-система и [пользовательские шаблоны](/ru/ko/teams/custom-templates) предназначены для разных задач:

|                   | Дизайн-система                                                                        | Пользовательские шаблоны                                                                          |
| ----------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Назначение**    | Использование фронтенд-стека команды и компонентов кода                                | Полная замена базового стека (например, Rust, Go, C++)                                            |
| **Стек**          | Работает в стандартном монорепозитории Replit на pnpm                                  | Определяет полностью пользовательскую структуру проекта                                           |
| **Содержимое**    | Правила библиотеки компонентов, дизайн-токены, бренд-ассеты, визуальные навыки   | Полный шаблонный код, включая среду выполнения, настройки сборки, зависимости и структуру проекта |
| **Применяется к** | Веб-приложениям, мобильным приложениям, слайдам, артефактам — всему, что создаёт Agent | Только приложениям, созданным на основе конкретного шаблона                                       |

Используйте дизайн-систему, если хотите, чтобы Agent соблюдал визуальные стандарты во всей обычной работе с Replit. Используйте пользовательские шаблоны, если вам нужен принципиально другой стек.
