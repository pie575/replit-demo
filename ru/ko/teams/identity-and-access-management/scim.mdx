<div id="section">
  ## Введение
</div>

<Note>
  SCIM доступен только клиентам Enterprise. Чтобы включить эту функцию в организации, обратитесь в отдел продаж по адресу [sales@replit.com](mailto:sales@replit.com).
</Note>

System for Cross-domain Identity Management ([SCIM](https://en.wikipedia.org/wiki/System_for_Cross-domain_Identity_Management)) — стандартизированный протокол, который автоматизирует подготовку и отмену подготовки пользователей между корпоративным поставщиком удостоверений (IdP) и Replit.

После включения SCIM вы можете напрямую управлять в Replit сопоставлением синхронизированных групп и участников с рабочими пространствами и ролями Replit — см. [Управление доступом к рабочему пространству](#managing-workspace-access).

<div id="section-3">
  ## Преимущества
</div>

Интеграция SCIM предоставляет командам Enterprise ряд преимуществ:

* **Повышенная безопасность**: использование существующих систем управления идентификацией для надежного контроля доступа
* **Упрощенное администрирование**: автоматическое управление участниками команды через поставщика удостоверений
* **Эффективный онбординг**: быстрое предоставление доступа большим командам без ручного вмешательства
* **Единообразный контроль доступа**: поддержание единых политик доступа во всей организации

<div id="section-4">
  ## Начало работы
</div>

<Steps>
  <Step title="Включите SCIM">
    Перейдите в **Настройки** &gt; **Дополнительно** &gt; **Идентификация и управление**, чтобы включить SCIM для организации Enterprise.
  </Step>

  <Step title="Настройте IdP">
    Откройте портал подключения SCIM прямо из настроек идентификации и управления. Портал содержит пошаговые инструкции по синхронизации каталога пользователей для каждого поставщика удостоверений.
  </Step>

  <Step title="Протестируйте интеграцию">
    Подготовьте тестового пользователя, чтобы проверить подключение.
  </Step>

  <Step title="Начните работу">
    Начните использовать SCIM для автоматического управления участниками, затем назначьте синхронизированные группы рабочему пространству в разделе [Доступ SCIM к рабочему пространству](#managing-workspace-access).
  </Step>
</Steps>

<div id="section-5">
  ## Рекомендации
</div>

* Перед включением SCIM задокументируйте назначенные роли существующих участников Replit.
* Настройте рабочее пространство по умолчанию так, чтобы все синхронизированные группы получали как минимум доступ **Viewer**. Если рабочего пространства по умолчанию нет, у участников не будет ролей, пока вы не назначите группы рабочему пространству.
* Перед включением массовой подготовки протестируйте настройку на небольшой группе участников.
* После первоначальной синхронизации проверьте и настройте разрешения пользовательских групп в соответствии с требованиями организации к контролю доступа.
* Используйте отдельную группу управления ролями для контроля уровня доступа подготовленных участников, а другие push-группы — для классификации и массового управления разрешениями.
* Задокументируйте настройки SCIM для дальнейшего использования.

<div id="section-6">
  ## Синхронизация групп
</div>

Все группы, отправленные из IdP, синхронизируются с Replit вместе с участниками, которых IdP подготавливает для этих групп. Если отправить группу «Engineering» через SCIM, Replit создаст соответствующую группу с этими участниками.

Состав групп обновляется автоматически и отражает состав в IdP. Такие синхронизированные группы удобно использовать для массового изменения прав участников — например, чтобы открыть доступ к приложению всем, кто входит в группу «Engineering».

<div id="microsoft-entra-id">
  ### Использование плоских групп в Microsoft Entra ID
</div>

<Warning>
  Microsoft Entra ID подготавливает учётные записи только для пользователей, которые являются прямыми участниками явно назначенных групп. Вложенные группы не разворачиваются. Пользователи, входящие только в дочерние группы, не будут добавлены в родительскую группу в Replit. Если ни одна другая назначенная группа не содержит такого пользователя напрямую, Microsoft Entra ID не подготовит для него учётную запись.
</Warning>

Используйте плоские группы для подготовки учётных записей через SCIM: добавляйте пользователей напрямую в каждую группу, которую назначаете Replit. Если вложенные группы в Microsoft Entra ID нужно сохранить, назначьте приложению Replit все группы, которые содержат пользователей напрямую. Подробнее см. в [руководстве Microsoft по определению области на основе назначений](https://learn.microsoft.com/en-us/entra/identity/app-provisioning/how-provisioning-works#assignment-based-scoping).

<div id="scim">
  ### Создание пользовательских групп вместе с SCIM
</div>

Даже при включённом SCIM вы можете создавать в Replit пользовательские группы. Используйте их, чтобы объединять участников по работе над проектом, для разовой выдачи прав или под структуры, которых нет в поставщике удостоверений.

* **Группы SCIM заблокированы.** Группы, синхронизированные из IdP, можно редактировать или удалять только через поставщика удостоверений.
* **Пользовательскими группами управляют в Replit.** Администраторы организации могут создавать, редактировать и удалять пользовательские группы прямо на странице Groups.
* **Участник может состоять в группах обоих типов.** Участников, подготовленных через SCIM, можно добавлять в пользовательские группы, не затрагивая роли, управляемые IdP.

Подробнее о группах см. в разделе [Группы и права доступа](/ru/ko/teams/identity-and-access-management/groups-and-permissions).

<div id="section-7">
  ## Управление доступом к рабочему пространству
</div>

Когда SCIM включён, на странице управления можно просматривать и настраивать сопоставление синхронизированных групп с рабочим пространством и ролями, а также назначать группу администраторов аккаунта. IdP остаётся источником достоверных данных о членстве и подготовке пользователей, а на этой странице настраивается сопоставление синхронизированных групп и участников с рабочим пространством Replit и ролями — пользователи здесь не добавляются, не удаляются и не подготавливаются повторно.

<div id="section-8">
  ### Настройка структуры рабочего пространства
</div>

Как правило, участников лучше держать в **одном рабочем пространстве**, а дополнительные создавать только при наличии явной причины для разделения — например, если речь идёт о самостоятельных бизнес-подразделениях, которые не должны совместно использовать участников, группы и бюджеты. Все, кому нужно работать вместе, должны находиться в одном рабочем пространстве.

Синхронизированные группы можно назначать рабочим пространствам. Внутри рабочего пространства назначенные группы отображаются как **пользовательские группы** и могут использоваться в настройках уровня рабочего пространства, например в **бюджетах групп** — так, команде Revenue можно выделить бюджет в 100 000.

<div id="scim-2">
  ### Открытие доступа SCIM к рабочему пространству
</div>

1. Откройте переключатель рабочих пространств и выберите рабочее пространство Enterprise.
2. Откройте **Настройки** и выберите **Дополнительно**.
3. Разверните раздел **Идентификация и управление** и найдите карточку **Автоматическая подготовка участников (SCIM)**.
4. Если SCIM **активен**, экран управления откроется прямо в этой карточке.

<div id="section-9">
  ### Назначение группы администраторов аккаунта
</div>

Сначала выполните это действие. В блоке **Группа администраторов аккаунта** в верхней части страницы отображается синхронизированная с IdP группа, участники которой получают роль администратора аккаунта во всех рабочих пространствах и доступ к настройкам на уровне аккаунта, включая права на управление SCIM.

Выберите **Изменить**, чтобы назначить другую синхронизированную группу. Назначение группы выполняется по принципу переключения: новая группа становится группой администраторов аккаунта, а предыдущая лишается этой роли. Администраторы аккаунта обладают широкими правами, поэтому перед применением изменений требуется подтверждение.

<div id="section-10">
  ### Просмотр назначений рабочих пространств и управление ими
</div>

На вкладке **Рабочие пространства** перечислены все рабочие пространства организации, а также назначенные им синхронизированные группы и роль каждой группы.

**Рабочее пространство по умолчанию**, отмеченное значком **Default**, служит основой предоставляемого доступа: все синхронизированные группы автоматически получают как минимум доступ уровня **Viewer**, поэтому участникам всегда есть куда зайти. Рабочее пространство становится используемым по умолчанию только после того, как его назначит администратор; до этого момента участники получают доступ исключительно через заданные вами назначения групп.

* Используйте поле поиска, чтобы фильтровать рабочие пространства по имени.
* В каждой строке **назначения групп** отображаются в виде чипов формата *группа · роль* (например, *Engineering · Admin*). Если у рабочего пространства слишком много назначений, чтобы уместить их в одну строку, оставшиеся обозначаются чипом **+ ещё N**.
* Через меню **⋮** в строке можно изменить назначения, а также назначить рабочее пространство используемым по умолчанию для организации или отменить это.

<div id="section-11">
  ### Назначение групп рабочему пространству и настройка ролей
</div>

В меню **⋮** в строке рабочего пространства выберите **Редактировать назначения**, чтобы открыть диалоговое окно **Редактирование доступа к рабочему пространству**. Здесь вы выбираете, какие синхронизированные группы получают доступ к рабочему пространству и какую роль получает каждая группа:

* **Admin** — полный административный доступ к настройкам и ресурсам рабочего пространства.
* **Member** — может создавать и редактировать Replit App.
* **Viewer** — доступ к приложениям и деплоям только для чтения.
* **Guest** — доступ только к приложениям, которыми с ним поделились.

Права групп администраторов аккаунта заблокированы (обозначено значком замка), поскольку они управляются в рамках назначения администраторов аккаунта, а не отдельно для каждого рабочего пространства.

<div id="section-13">
  ## Ограничения
</div>

* **IdP остаётся источником достоверных данных.** Добавление, удаление и подготовка участников, а также изменение состава групп выполняются у поставщика удостоверений. Replit управляет *назначениями* рабочих пространств и ролей для групп, уже существующих в синхронизированном каталоге.
* **Microsoft Entra ID не разворачивает вложенные группы.** Используйте плоские группы, как описано в разделе [Использование плоских групп с Microsoft Entra ID](#use-flat-groups-with-microsoft-entra-id), либо назначьте приложению Replit все группы, непосредственно включающие пользователей.
* **Группу администраторов аккаунта можно изменить, но нельзя удалить.** Можно указать другую группу администраторов аккаунта, однако настроить организацию без группы администраторов аккаунта нельзя.

<div id="faq">
  ## Частые вопросы
</div>

<div id="scim-replitcom">
  ### Что произойдёт с участниками, у которых уже есть аккаунт replit.com до настройки SCIM?
</div>

После включения SCIM существующие участники делятся на две категории:

1. **Участники, подготовленные через SCIM**:
   * Их роли обновляются в соответствии с ролями, заданными в IdP.
   * Добавлять или удалять таких участников, а также изменять их роли можно только через IdP.
   * Чтобы права доступа оставались синхронизированными, администраторы больше не могут редактировать роли или приглашать новых участников в Replit.
2. **Участники, не подготовленные через SCIM**:
   * Они не меняются и считаются «устаревшими» участниками.
   * Их членство в организации и роли не удаляются автоматически, чтобы предотвратить случайную отмену подготовки.
   * При необходимости администраторы организации могут удалить устаревших участников через интерфейс Replit.

<Warning>
  После внедрения SCIM всеми участниками, подготовленными через IdP, необходимо управлять через поставщика удостоверений, чтобы синхронизация сохранялась. Отменить подготовку непосредственно в Replit можно только для устаревших участников, не подготовленных через SCIM.
</Warning>

<div id="scim-3">
  ### Какие роли можно назначать через SCIM?
</div>

Пользователям SCIM можно назначить четыре роли:

* **Admin**: полный доступ к настройкам и ресурсам организации
* **Member**: стандартный доступ для создания и редактирования Replit App
* **Guest**: ограниченный доступ для внешних участников; редактировать можно только приложения, к которым явно предоставлен доступ
* **Viewer**: доступ только для чтения к опубликованным приложениям

В разделе [доступ SCIM к рабочему пространству](#managing-workspace-access) настройте для каждого рабочего пространства сопоставление между группами IdP и ролями Replit. Например, группе &quot;Engineering&quot; можно назначить роль Member в одном рабочем пространстве и роль Viewer — в другом.

<div id="scim-4">
  ### Можно ли добавлять или удалять участников в разделе доступа SCIM к рабочему пространству?
</div>

Нет. Членство и подготовка управляются на стороне поставщика удостоверений. На этом экране настраивается сопоставление синхронизированных групп и участников с рабочими пространствами и ролями. О повседневном управлении участниками вне SCIM см. [Управление участниками](/ru/ko/teams/identity-and-access-management/managing-members).

<div id="section-14">
  ### Чем отличаются роли и группы?
</div>

Группы синхронизируются из IdP. Роли (Admin, Member, Viewer, Guest) определяют действия, доступные группе в конкретном рабочем пространстве. Одна и та же группа может иметь разные роли в разных рабочих пространствах — например, быть **Member** в одном рабочем пространстве и **Viewer** в другом.

<div id="section-15">
  ### Повлияет ли изменение группы администраторов аккаунта на другие роли?
</div>

При назначении новой группы администраторов аккаунта изменяется только роль администратора аккаунта во всей организации. Другие назначения групп рабочим пространствам и роли остаются без изменений. Подробнее о роли администратора аккаунта см. в разделе [Администраторы аккаунтов и рабочих пространств](/ru/ko/teams/identity-and-access-management/account-and-workspace-admins).
