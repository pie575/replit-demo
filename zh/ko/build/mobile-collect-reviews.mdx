评分越多，应用排名越高，也越能赢得新用户的信任。两个应用商店都提供了
用于此目的的原生提示词，即直接在应用内请求用户评分的弹窗。

<div id="section">
  ## 在恰当的时机请求评价
</div>

在获胜、创下最高分或升级时请求评价。请求的时机比请求频率更重要。

无论代码请求得多频繁，iOS 的 StoreKit 和 Android 的 Google Play 应用内评价 API 都会限制实际显示评价请求的频率。

<Note>
  请勿收买或强迫用户留下评价，例如要求用户留下五星评价才能解锁游戏。
  Apple 和 Google 均禁止激励性评价，违反规定可能导致 PixelGames 被拒绝或下架。
</Note>

<div id="section-2">
  ## 故障排查
</div>

* **提示词完全未出现：** 这是偶尔会发生的正常现象。无论代码调用 API 多少次，
  两个平台都会限制系统显示提示词的频率。
* **测试期间每次都会显示提示词：** 这在 TestFlight 或 Internal Testing 构建版本中属于正常现象。
  年度请求限制仅适用于实际的生产环境安装。
* **玩家抱怨收到请求过于频繁：** 请确认你调用的是原生 API，而不是每次运行时都会显示的自定义弹窗。
  自定义弹窗会绕过内置的请求限制。
