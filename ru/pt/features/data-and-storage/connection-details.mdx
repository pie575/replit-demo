Ваше приложение подключается к базе данных с помощью учётных данных, которыми управляет Replit. Найти их можно в инструменте **Database**: выберите базу данных, а затем откройте вкладку **Settings**. Там отображаются строка подключения, использование хранилища и дополнительные параметры подключения.

<div id="variveis-de-ambiente">
  ## Переменные окружения
</div>

Для подключения к базе данных разработки доступна следующая переменная окружения:

* `DATABASE_URL`: как подключиться к базе данных и пройти аутентификацию

Ваше приложение использует её автоматически. Поскольку `DATABASE_URL` доступна только вашему приложению, к базе данных разработки не могут обращаться другие приложения — даже те, которые принадлежат вам, — а также внешние средства просмотра баз данных. Даже если переменная окажется раскрыта, никто другой не сможет с её помощью получить доступ к вашей базе данных и изменить её.

<Info>
  Если ваша база данных разработки всё ещё работает на [устаревшей инфраструктуре Neon](/ru/pt/features/data-and-storage/development-and-production#banco-de-dados-de-desenvolvimento-legado), также доступны дополнительные переменные `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` и `PGPORT`. Для баз данных, размещённых на текущей инфраструктуре Replit, они **не** предоставляются — используйте вместо них `DATABASE_URL`.
</Info>

<Warning>
  Если вы всё ещё используете устаревшую базу данных разработки Neon, никому не передавайте свою переменную `DATABASE_URL`. Она содержит учётные данные вашей базы данных, с помощью которых кто угодно сможет получить к ней доступ и изменить её. Никогда не публикуйте её в общедоступных местах и не указывайте в обращениях в поддержку.
</Warning>

<div id="conectar-uma-ferramenta-externa">
  ## Подключение внешнего инструмента
</div>

К **production-базе данных** можно подключиться из любого SQL-клиента, совместимого с PostgreSQL, — с помощью строки подключения на вкладке **Settings** production-базы данных.

<div id="segurana">
  ## Безопасность
</div>

Когда вы добавляете интеграцию с базой данных с помощью Agent, он подключает объектно-реляционный преобразователь (ORM), который управляет всем взаимодействием с базой данных и обеспечивает встроенную защиту:

* **Проверка схемы**: контролирует соответствие данных ожидаемым форматам
* **Очистка данных**: автоматически обрабатывает вводимые создателем данные, предотвращая SQL-инъекции

<div id="regenerar-as-credenciais-do-banco-de-dados-de-produo">
  ## Перевыпуск учётных данных production-базы данных
</div>

Если строка подключения к production-базе данных была скомпрометирована, перевыпустите её учётные данные в инструменте Database. При этом для production-базы данных Neon создаётся новый пароль. Существующие строки подключения к production сразу перестают работать.

Перевыпустить учётные данные можно, если выполнены все следующие условия:

* У вашего приложения есть production-база данных Neon.
* Вы владелец приложения или администратор workspace, которому оно принадлежит.
* Вы используете Replit в веб-браузере.
* В данный момент не выполняется ни одно развёртывание.
* Если у приложения есть активное развёртывание, его последняя сборка завершилась успешно и использует [Autoscale или зарезервированную виртуальную машину](/ru/pt/features/publishing/deployment-types).

<Warning>
  Это действие нельзя отменить. Существующие строки подключения сразу
  перестают работать. Если у вашего приложения есть активное развёртывание, оно может
  ненадолго стать недоступным во время повторного развёртывания.
</Warning>

<div id="regenere-as-credenciais">
  ### Перевыпустите учётные данные
</div>

1. На панели Tools выберите **Database**.

2. Выберите **Production Database**, а затем вкладку **Settings**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="Вкладка Settings production-базы данных со строкой подключения, использованием хранилища и разделом Advanced со строкой Regenerate credentials." width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. В разделе **Advanced** разверните строку **Regenerate credentials**.

4. Нажмите кнопку **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="Развёрнутая строка Regenerate credentials в разделе Advanced с кнопкой Regenerate credentials." width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. В диалоговом окне подтверждения нажмите **Regenerate credentials**, чтобы подтвердить действие.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="Диалоговое окно подтверждения Regenerate credentials с предупреждением о том, что действие нельзя отменить и что существующие строки подключения сразу перестанут работать." width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Выберите **Refresh**, чтобы загрузить новую строку подключения.

7. Если у вашего приложения есть активное развёртывание, откройте **Publishing** и следите за ходом повторного развёртывания.

8. Замените все строки подключения, которые вы скопировали во внешние инструменты или пользовательские интеграции.

<div id="o-que-muda">
  ### Что меняется
</div>

При повторной генерации учётных данных создаётся новый пароль для production-базы данных. В строке подключения меняется только пароль. Хост, имя базы данных и роль остаются прежними.

Для поддерживаемого активного развёртывания Replit заново развернёт последнюю успешную сборку с обновлённой строкой подключения.
