# Mettre à jour les anciens projets pour la prise en charge de plusieurs artefacts

> Ajoutez un deuxième artefact à un ancien projet Replit grâce à une mise à jour structurelle unique qui préserve votre URL, vos données et votre déploiement.

Si votre projet a été créé avant le 11 mars 2026, Agent peut avoir besoin d'effectuer une mise à jour structurelle unique avant de pouvoir y ajouter un deuxième artefact. Cette page explique pourquoi, ce qui change et quels projets sont éligibles.

## Contexte

Le **11 mars 2026**, Replit a lancé [Agent 4](/fr/updates/2026/03/13/changelog). L'un des changements majeurs de cette version était la **prise en charge de plusieurs artefacts** : un seul [projet](/fr/features/projects-and-artifacts/projects) peut désormais contenir plusieurs [artefacts](/fr/features/projects-and-artifacts/artifacts) (par exemple, une application web, une application mobile et un pitch deck) qui partagent la même base de données, le même backend, les mêmes secrets et le même déploiement.

Avant le 11 mars 2026, chaque projet était construit autour d'une seule application avec une structure de fichiers différente. Cette ancienne structure n'a pas la séparation dont le backend a besoin pour héberger plus d'un artefact. En raison de ces différences, les projets créés avant le 11 mars 2026 ont besoin d'une **mise à jour structurelle unique** avant qu'Agent puisse y ajouter un deuxième artefact. Les projets créés à partir de cette date utilisent déjà la nouvelle structure et n'ont pas besoin de cette étape.

## Ce que fait la mise à jour

Lorsque vous demandez à Agent d'ajouter un deuxième artefact à un ancien projet (par exemple, ajouter une application mobile à une application web existante), Agent réorganise d'abord votre projet dans la nouvelle structure multi-artefacts. Votre URL, vos collaborateurs, vos secrets, votre base de données et vos domaines sont tous préservés. Seule la structure interne change.

  </Step>

  <Step title="Révisez et approuvez">

Cliquez sur **Mettre à jour le projet** pour continuer, ou sur **Pas maintenant** pour ignorer.

## Éligibilité

Tous les projets ne peuvent pas être mis à jour pour le moment. Votre projet doit être de l'un de ces types :

* **Application web** (JavaScript full-stack)
* **Maquettes design-to-app**
* **Application mobile** (Expo)

Les autres types de projets créés avant le 11 mars 2026, notamment Python, Flask, Streamlit, les stacks de jeux, les projets vidéo et les stacks d'agents, ne sont pas pris en charge. Si vous avez besoin de plusieurs artefacts dans ces cas, [créez un nouveau projet](/fr/features/projects-and-artifacts/projects) à la place.

Les ports et workflows de votre projet doivent également correspondre à la configuration par défaut pour son type. Si vous avez modifié manuellement `.replit`, vous verrez ce message :

> *Ce projet ne peut pas être migré automatiquement : la configuration du workflow ne correspond pas à ce qui est attendu.*

Pour corriger cela, revenez à vos personnalisations de port ou de workflow par défaut et réessayez.

## Foire aux questions

<AccordionGroup>
  <Accordion title="Pourquoi mon projet a-t-il besoin d'une mise à jour ?">
    Les projets créés avant le 11 mars 2026 (lors du lancement d'Agent 4) utilisaient une structure à application unique. La nouvelle structure d'espace de travail partagé est ce qui permet à une application web, une application mobile et un tableau de bord d'administration de coexister et de partager la même base de données et le même backend. La mise à jour est une étape unique pour adopter cette structure.
  </Accordion>

  <Accordion title="Que faire si je ne veux pas mettre à jour ?">
    Cliquez sur **Pas maintenant**. Agent continue à construire dans la structure existante à artefact unique. Vous pouvez revenir sur l'offre plus tard si vos besoins changent.
  </Accordion>

  <Accordion title="Puis-je mettre à jour plus d'une fois ?">
    Non. Une fois que votre projet est sur la nouvelle structure, aucune autre mise à jour n'est nécessaire. Les futurs artefacts sont ajoutés directement sans autre étape de mise à jour.
  </Accordion>

  <Accordion title="Mon projet n'est pas éligible. Quelles sont mes options ?">
    Créez un projet séparé pour le nouvel artefact, ou démarrez un nouveau projet qui prend en charge plusieurs artefacts dès le premier jour.
  </Accordion>
</AccordionGroup>
