title: "Analyse de sécurité d’Agent"
description: "Lancez un examen de sécurité du code source, évaluez les résultats, corrigez les vulnérabilités avec Agent, puis vérifiez les corrections."
---

L’analyse de sécurité d’Agent examine les vulnérabilités de sécurité et de confidentialité dans l’ensemble de la base de code. Security Agent combine une analyse basée sur des modèles et des outils d’analyse statique tels que [Semgrep](https://semgrep.dev/) et [HoundDog.ai](https://hounddog.ai), puis affiche les résultats dans le Centre de sécurité du projet.

L’analyse de sécurité d’Agent est accessible à tous les créateurs Replit disposant d’un abonnement payant. Pour les projets de grande taille, un audit approfondi peut prendre jusqu’à 15 minutes.

<div id="security-agent">
  ## Éléments examinés par Security Agent
</div>

Lorsque vous lancez une analyse, Security Agent effectue les actions suivantes :

1. Il cartographie les routes, les API, les flux de données et les points d’entrée.
2. Il élabore un modèle de menace pour votre application.
3. Il exécute une analyse statique sur l’ensemble de la base de code.
4. Il évalue les résultats dans le contexte de votre application.
5. Il génère un rapport des résultats à examiner.

Cet examen peut identifier des modèles de code non sécurisés, tels que les injections SQL, les scripts intersites et les falsifications de requêtes intersites, des problèmes de confidentialité, comme des données sensibles transmises vers des journaux ou des API tierces, ainsi que des vulnérabilités architecturales dans les routes, les API et les flux de données.

<div id="agent">
  ## Premiers pas avec l’analyse de sécurité d’Agent
</div>

<Steps>
  <Step title="Ouvrir le Security Center">
    Dans le panneau **Tools** de votre projet, sélectionnez **Security Center**. Vous pouvez également sélectionner **Review security** dans le processus de publication.

    <Frame>
      <img src="/assets/mirror/review-security-button-9331149c28f7.png" alt="Action Review security dans le processus de publication" width="1440" height="900" data-path="images/project-security-center/review-security-button.png" />
    </Frame>
  </Step>

  <Step title="Lancer une analyse">
    Sélectionnez **Run scan with Agent**.

    <Frame>
      <img src="/assets/mirror/run-scan-with-agent-f54820ac154a.png" alt="Action Run scan with Agent dans le Centre de sécurité du projet" width="1440" height="900" data-path="images/project-security-center/run-scan-with-agent.png" />
    </Frame>
  </Step>

  <Step title="Ajouter du contexte si nécessaire">
    Si nécessaire, ajoutez du contexte pour que le modèle de menace se concentre sur certaines parties de l’application, puis lancez l’analyse de sécurité.

    <Frame>
      <img src="/assets/mirror/scan-options-c2cd398fa78b.png" alt="Options d’analyse de sécurité avec le champ Add context et l’action Start security scan" width="1440" height="900" data-path="images/project-security-center/scan-options.png" />
    </Frame>
  </Step>

  <Step title="Attendre la fin de l’analyse">
    Attendez que l’Agent de sécurité termine son analyse. Cela prend généralement quelques minutes, mais peut prendre jusqu’à 15 minutes pour les grands projets.
  </Step>
</Steps>

<div id="section">
  ## Examiner et corriger les résultats
</div>

<Steps>
  <Step title="Examiner le rapport">
    Consultez chaque résultat et son niveau de gravité dans le **Security Center**. Vous pouvez ignorer les
    résultats que vous comprenez et acceptez, ou les corriger avant de les envoyer à Agent pour correction.
  </Step>

  <Step title="Corriger les résultats approuvés avec Agent">
    Envoyez les problèmes approuvés à Agent. Security Agent organise les vulnérabilités en tâches distinctes,
    ce qui permet à Agent d’effectuer plusieurs corrections simultanément.
  </Step>

  <Step title="Relancer l’analyse">
    Une fois les corrections appliquées par Agent, relancez l’analyse pour vérifier que les problèmes sont résolus.
    Dans les projets de grande envergure, des problèmes supplémentaires peuvent apparaître après la résolution des résultats les plus graves.
  </Step>
</Steps>

<div id="level-3">
  ## Quand utiliser Level 3
</div>

L’analyse de sécurité d’Agent examine le code source. Si vous devez également vérifier l’application en cours d’exécution au moyen d’interactions avec le navigateur et le réseau, utilisez les [tests d’intrusion en boîte noire de Level 3](/fr/ko/features/security/black-box-pen-tests). Level 3 exécute simultanément des tests en boîte noire et une revue du code source.

<div id="section-2">
  ## Limites et bonnes pratiques
</div>

* Les analyses s’exécutent sur l’infrastructure de Replit. Replit n’envoie ni votre code ni vos données à Semgrep, HoundDog.ai ou d’autres tiers.
* La configuration et les résultats des analyses restent associés à votre App Replit.
* Les analyses ne remplacent pas un audit de sécurité complet. Utilisez-les en complément des revues de code, des tests, de l’examen des dépendances et des vérifications de l’application en cours d’exécution.
* Relancez les analyses après des modifications majeures du code, après l’ajout ou la mise à jour de dépendances, et avant de publier une nouvelle version.
