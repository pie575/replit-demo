---
title: "Déploiement statique"
description: "Découvrez comment publier des sites web statiques et des applications frontend avec le déploiement statique."
---

Le déploiement statique héberge sur un serveur cloud les fichiers statiques de votre Replit App, tels que les fichiers HTML, CSS et JavaScript.
Le serveur applique automatiquement des stratégies de mise en cache et de mise à l&#39;échelle
afin de diffuser le contenu rapidement et à moindre coût.

Le déploiement statique est idéal pour les cas d&#39;usage suivants :

* Pages d&#39;atterrissage marketing
* Sites web de portfolio
* Sites de documentation produit et API

<Note>
  Le déploiement statique n&#39;est pas compatible avec les Replit Apps créées avec Agent.
  Agent génère automatiquement des applications fullstack qui nécessitent un serveur backend. Pour les applications
  créées par Agent, utilisez l&#39;un des types de déploiement suivants : - [Déploiement
  Autoscale](/fr/ko/features/publishing/autoscale-deployments) - [Déploiement
  Reserved VM](/fr/ko/features/publishing/reserved-vm-deployments)
</Note>

<div id="section">
  ## Fonctionnalités
</div>

Les déploiements statiques incluent les fonctionnalités suivantes :

* **Hébergement économique** : vous ne payez que pour le volume de données servi par votre site web.
* **Options de routage HTTP** : configurez les en-têtes de réponse, les réécritures d’URL et les redirections.
* **Domaines personnalisés** : configurez un domaine personnalisé ou accédez à votre app à l’aide de l’URL `<app-name>.replit.app`.
* **Pages d’erreur personnalisées** : créez et diffusez des pages d’erreur 404 personnalisées.
* **Surveillance** : consultez les journaux et surveillez l’état des apps publiées.

<div id="section-2">
  ## Utilisation
</div>

Vous pouvez accéder aux déploiements statiques depuis l’outil Publishing du Project Editor.

<Accordion title="Accéder aux déploiements statiques">
  Dans le **dock d’outils** à gauche :

  1. <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône Tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> Sélectionnez **Tous les outils** pour afficher la liste des outils du Project Editor.
  2. <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> Sélectionnez **Publishing**.
  3. Sélectionnez l’option **Static**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut de l’écran pour ouvrir l’outil de recherche.
  2. Saisissez « Publishing » pour trouver l’outil, puis sélectionnez-le dans les résultats de recherche.
  3. Sélectionnez l’option **Static**, puis **Set up your published app**.
</Accordion>

<div id="section-3">
  ### 기본 도메인
</div>

Indiquez la partie sous-domaine du nom d&#39;hôte de votre app publiée. Une fois la publication effectuée, votre app est accessible à l&#39;adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Domaines personnalisés](/fr/features/publishing/custom-domains).

<div id="section-4">
  ### 비공개 배포
</div>

<Info>
  La fonctionnalité de publication privée d&#39;application est disponible avec les plans Pro et Enterprise.
</Info>

Les applications publiées en privé ne sont accessibles qu&#39;aux membres de votre workspace ou aux utilisateurs et groupes spécifiques que vous invitez.
Au moment de la publication, vous pouvez choisir entre les accès **Public**, **Password protected**, **Workspace only** et **Invite only**.

Pour savoir comment configurer un deployment privé, consultez [Accès à l&#39;application](/fr/features/publishing/private-deployments/).

<div id="section-5">
  ### Répertoire public
</div>

Indiquez le chemin du répertoire par défaut, dans votre Replit App, qui contient les fichiers statiques à diffuser publiquement.
Lors du déploiement, l&#39;hôte cloud diffuse toutes les pages et toutes les ressources présentes dans ce répertoire.

La valeur par défaut, `/`, correspond au répertoire racine de la Replit App.

<div id="section-6">
  ### Commande de build
</div>

Lorsque vous créez un déploiement, indiquez la commande de build à exécuter dans le shell de votre Replit App.

Par exemple, si vous générez un site statique avec <a href="https://gohugo.io/" target="_blank">Hugo</a>,
vous pouvez utiliser la commande `hugo --minify` pour générer les fichiers et réduire la taille des ressources.

<div id="section-7">
  ### Secrets de déploiement
</div>

Pour ajouter les variables d&#39;environnement ou les secrets nécessaires à l&#39;exécution sécurisée de vos commandes de build, sélectionnez **Add deployment secret**.

Par exemple, si votre générateur de site a besoin d&#39;une clé API pour créer un site statique,
vous pouvez la transmettre sous la forme `API_KEY=<nom du secret>`.
