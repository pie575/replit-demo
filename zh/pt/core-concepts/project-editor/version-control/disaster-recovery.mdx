---
title: "Git 灾难恢复"
description: "了解如何使用 Replit 的自动备份系统恢复 Git 历史记录和代码。"
---

Replit 会自动备份你的 Git 仓库，帮助你从 `.git` 文件夹损坏、提交历史记录丢失等问题中恢复。该备份系统会在后台运行，无需额外操作即可保护你的工作。

<div id="como-funciona">
  ## 工作原理
</div>

每个 Replit App 都会安全备份其 Git 仓库。当 Replit Agent 修改代码或你发布 App 时，这些更改会自动同步到备份中。如果本地 Git 仓库损坏或无法使用，你可以从备份中恢复完整的提交历史。

<Info>
  备份远程仓库名为 `gitsafe-backup`，由 Replit 自动管理。无需进行任何配置，它会在后台自动运行。
</Info>

<div id="visualizando-seu-histrico-de-backup">
  ## 查看备份历史
</div>

查看提交历史最简单的方式是使用 [Git Pane](/zh/pt/core-concepts/project-editor/version-control/git-interface)。在 Project Editor 的 Tools 部分打开它，即可查看完整的提交历史，包括所有 Agent checkpoint。此方法适用于大多数情况，无需运行任何命令。

如果需要直接检查 gitsafe-backup 远程仓库，可以使用 Shell：

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

这里会显示你的完整提交历史，包括所有 Agent checkpoint 和手动提交。你可以据此确认工作内容是否已备份，或查找要恢复的特定提交。

<div id="recuperando-de-problemas-no-git">
  ## 从 Git 问题中恢复
</div>

如果遇到 Git 错误或仓库损坏，请先查看 [Git Pane](/zh/pt/core-concepts/project-editor/version-control/git-interface)。无需使用 Shell 命令，它就能解决大多数常见问题，例如重置到之前的提交或从远程仓库拉取。

如果 Git Pane 无法解决问题 (例如 `.git` 文件夹完全损坏) ，请按照以下基于 Shell 的步骤操作。

<div id="verificar-se-o-backup-est-disponvel">
  ### 检查备份是否可用
</div>

首先，确认备份远程仓库是否存在：

```bash theme={null}
git remote -v
```

在输出中查找 `gitsafe-backup`。如果找到，即可继续恢复。

<div id="restaurar-seu-repositrio">
  ### 恢复仓库
</div>

<Warning>
  此过程会用备份版本替换当前的 `.git` 文件夹。你的工作文件不会受到影响，但本地 Git 历史记录将替换为备份中的历史记录。
</Warning>

<Steps>
  <Step title="保存当前 Git 配置">
    如果你使用了自定义配置，请备份 Git 配置文件：

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="克隆备份仓库">
    从备份创建一个临时克隆：

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="替换 Git 文件夹">
    将损坏的 `.git` 文件夹移至一旁，然后用备份替换：

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="恢复配置">
    将 Git 配置复制回 `.git` 文件夹：

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

完成这些步骤后，运行 `git status`，确认仓库是否正常工作。

<div id="soluo-de-problemas-comuns">
  ## 常见问题排查
</div>

<div id="fatal-repository-not-found-ou-remote-de-backup-ausente">
  ### “fatal: repository not found”或缺少备份远程仓库
</div>

较早创建的项目可能未启用备份功能。如需协助恢复较早的项目，请联系支持团队。

<div id="a-recuperao-no-incluiu-commits-recentes">
  ### 恢复未包含最新提交
</div>

每次 Agent 提交后，备份都会同步。如果你进行了更改但未提交，这些更改不会包含在备份中。请检查工作目录中是否有未提交的文件。

<div id="operaes-git-esto-lentas-ou-travadas">
  ### Git 操作缓慢或卡住
</div>

如果 Git 操作无响应，可能是存在过期的锁定文件。您可以放心将其删除：

```bash theme={null}
rm -f .git/index.lock
```

<div id="prevenindo-perda-de-dados">
  ## 防止数据丢失
</div>

虽然备份系统会自动保护你的 Git 历史记录，但你还可以采取一些额外措施来保护自己的工作成果：

* **经常提交**：保持小步、频繁的提交，让进度持续得到备份
* **使用 checkpoint**：使用 [Replit Agent](/zh/pt/core-concepts/agent) 时，checkpoint 会在重要节点自动创建提交
* **连接到 GitHub**：对于重要项目，可以[将 app 连接到 GitHub](/zh/pt/getting-started/quickstarts/import-from-github)，多获得一层备份保障
