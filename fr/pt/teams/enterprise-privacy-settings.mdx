En tant qu&#39;administrateur Enterprise, vous pouvez configurer, à l&#39;échelle de l&#39;organisation, les paramètres qui déterminent la manière dont les membres de l&#39;équipe interagissent avec le code, les déploiements et les plateformes externes. Ces paramètres vous aident à maintenir vos standards de sécurité, à protéger la propriété intellectuelle et à garantir la conformité aux politiques de l&#39;entreprise.

<div id="acessando-as-configuraes-de-privacidade">
  ## Accéder aux paramètres de confidentialité
</div>

<Accordion title="Comment accéder aux paramètres de confidentialité">
  1. Rendez-vous dans votre workspace Enterprise
  2. Sélectionnez **Paramètres**
  3. Sélectionnez **Avancé** pour afficher tous les paramètres disponibles
</Accordion>

<div id="configuraes-de-privacidade">
  ## Paramètres de confidentialité
</div>

Les paramètres de confidentialité déterminent la façon dont les apps sont publiées et accessibles au sein de votre organisation.

<CardGroup cols={2}>
  <Card title="Déploiements privés" icon="lock">
    Exigez que toutes les nouvelles apps soient publiées de manière privée, en limitant l’accès aux seuls membres authentifiés de l’équipe
  </Card>

  <Card title="Deployments protégés par mot de passe" icon="key">
    Autorisez les membres de l’équipe à protéger leurs apps publiées par mot de passe
  </Card>

  <Card title="URL de développement privées" icon="shield-halved">
    Exigez une authentification pour toutes les URL de développement des apps, y compris via SSO pour les organisations où SAML est activé
  </Card>
</CardGroup>

<div id="deployments-privados">
  ### Déploiements privés
</div>

Lorsque cette option est activée, toutes les nouvelles apps doivent être publiées en mode privé. Les apps privées sont accessibles uniquement aux membres authentifiés de votre organisation.

**Quand utiliser ce paramètre :**

* Votre organisation traite des données sensibles ou des applications propriétaires
* Vous devez éviter que des apps soient rendues publiques par accident
* Vos exigences de conformité imposent un accès restreint aux applications publiées

<Note>
  Ce paramètre s&#39;applique uniquement aux apps nouvellement publiées. Les apps déjà publiées conservent leurs paramètres de visibilité actuels.
</Note>

<div id="deployments-protegidos-por-senha">
  ### Deployments protégés par mot de passe
</div>

Déterminez si les membres de l&#39;équipe peuvent créer des deployments protégés par mot de passe. Lorsque cette option est activée, les développeurs peuvent ajouter une couche de sécurité supplémentaire en exigeant un mot de passe pour accéder à leurs apps publiées.

**Quand utiliser ce paramètre :**

* Vous souhaitez partager des apps avec des parties prenantes externes sans les rendre totalement publiques
* Les équipes doivent faire des démonstrations d&#39;applications à des clients avant un lancement à plus grande échelle
* Vous avez besoin d&#39;un contrôle d&#39;accès précis, au-delà de la simple appartenance à l&#39;organisation

<div id="exigir-urls-de-desenvolvimento-privadas">
  ### Exiger des URL de développement privées
</div>

Lorsque cette option est activée, toutes les URL de développement des apps exigent une authentification. Si votre organisation a activé SAML, les URL de développement exigent une authentification SSO.

**Quand utiliser ce paramètre :**

* Vous devez empêcher tout accès non autorisé aux applications en cours de développement
* Vos politiques de sécurité imposent que tous les environnements de développement soient protégés
* Vous souhaitez garantir que seuls les membres authentifiés de l&#39;équipe puissent consulter les Preview de développement

<Warning>
  Ce paramètre s&#39;applique rétroactivement à toutes les apps existantes de votre organisation.
</Warning>

<div id="proibir-exportao-de-cdigo-fonte">
  ### Interdire l&#39;exportation du code source
</div>

Lorsque cette option est activée, les membres de l&#39;équipe ne peuvent pas exporter le code source de l&#39;app sous forme de fichier zip. Cela empêche le téléchargement et le partage du code en dehors de la plateforme Replit.

**Quand utiliser ce paramètre :**

* Vous devez garder un contrôle strict sur l&#39;emplacement du code source
* Vos politiques de sécurité interdisent les copies locales du code
* Vous souhaitez que tout le développement se déroule dans des environnements gérés

<div id="configuraes-de-segurana">
  ## Paramètres de sécurité
</div>

Les paramètres de sécurité permettent d&#39;imposer l&#39;analyse des vulnérabilités ainsi que d&#39;autres mesures de protection.

<div id="exigir-verificao-de-segurana">
  ### Exiger une analyse de sécurité
</div>

Définissez si toutes les apps doivent passer une analyse de sécurité avant la publication. Les analyses de sécurité détectent les vulnérabilités, les secrets exposés et d&#39;autres problèmes de sécurité dans votre code.

Options disponibles :

| Paramètre     | Description                                                                 |
| ------------- | --------------------------------------------------------------------------- |
| **Désactivé** | Les analyses de sécurité sont facultatives                                  |
| **Exiger**    | Toutes les apps doivent passer une analyse de sécurité avant la publication |

**Quand utiliser ce paramètre :**

* Vous devez respecter des exigences de conformité en matière de sécurité
* Vous souhaitez éviter l&#39;exposition accidentelle de clés d&#39;API ou de secrets
* Vous devez garantir des normes de sécurité homogènes sur l&#39;ensemble des apps publiées

<Note>
  Ce paramètre ne s&#39;applique pas aux apps publiées avant son activation.
</Note>

<div id="configuraes-de-controle-de-cdigo-fonte">
  ## Paramètres du contrôle du code source
</div>

Les paramètres du contrôle du code source permettent d&#39;appliquer des pratiques de gestion de versions et de protéger les dépôts de code de votre organisation.

<div id="exigir-repositrio-git-remoto">
  ### Exiger un dépôt Git distant
</div>

Lorsque cette option est activée, les modifications locales de tous les apps doivent être envoyées vers un dépôt Git distant avant la publication. Cela garantit que toutes les modifications de code sont suivies dans le système de contrôle de version de votre organisation.

**Quand utiliser ce paramètre :**

* Tout le code doit être sauvegardé dans Git
* Vous avez besoin d&#39;un journal d&#39;audit de toutes les modifications de code
* Vos flux de travail exigent une revue de code avant la publication

<Note>
  Ce paramètre ne s&#39;applique pas aux apps publiés avant son activation.
</Note>

<div id="repositrios-privados">
  ### Dépôts privés
</div>

Déterminez si les membres de l&#39;équipe peuvent utiliser des dépôts Git publics. Lorsque les dépôts privés sont obligatoires, les membres de l&#39;équipe ne peuvent envoyer leur code que vers des dépôts privés, sur des plateformes comme GitHub.

Options disponibles :

| Configuration                           | Description                                                                                   |
| --------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Désactivé**                           | Les membres de l&#39;équipe peuvent utiliser des dépôts publics ou privés                     |
| **Exiger pour les non-administrateurs** | Les membres de l&#39;équipe non administrateurs doivent utiliser des dépôts privés            |
| **Exiger pour tous**                    | Tous les membres de l&#39;équipe, administrateurs compris, doivent utiliser des dépôts privés |

**Quand utiliser cette configuration :**

* Les dépôts de code publics sont interdits
* Vous devez éviter que du code propriétaire soit envoyé par erreur vers des dépôts publics
* Les exigences de conformité imposent un contrôle de version privé

<div id="melhores-prticas">
  ## Bonnes pratiques
</div>

<AccordionGroup>
  <Accordion title="Commencez par rendre les apps privées par défaut" icon="shield">
    Activez les **déploiements privés** pour garantir que toutes les nouvelles apps publiées soient privées. Cela permet d’éviter l’exposition accidentelle d’applications sensibles.
  </Accordion>

  <Accordion title="Imposez une analyse de sécurité" icon="magnifying-glass">
    Définissez **Exiger une analyse de sécurité** pour détecter les vulnérabilités avant que les apps ne passent en production. Cela permet de maintenir des normes de sécurité cohérentes dans toute votre organisation.
  </Accordion>

  <Accordion title="Protégez les environnements de développement" icon="code">
    Activez **Exiger des URL de développement privées** afin de garantir que même le travail en cours soit protégé. Cela est particulièrement important pour les organisations qui traitent des données sensibles.
  </Accordion>

  <Accordion title="Contrôlez l’accès au code source" icon="code-branch">
    Combinez **Interdire l’exportation du code source** avec l’exigence de **Dépôts privés** afin de conserver un contrôle total sur l’emplacement et l’accès au code.
  </Accordion>
</AccordionGroup>
