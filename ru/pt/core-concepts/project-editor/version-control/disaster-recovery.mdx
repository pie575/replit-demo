---
title: "Восстановление Git после сбоев"
description: "Узнайте, как восстановить историю Git и код с помощью автоматического резервного копирования Replit."
---

Replit автоматически создает резервные копии вашего Git-репозитория, чтобы вы могли восстановиться после таких проблем, как поврежденная папка `.git` или утерянная история коммитов. Система резервного копирования работает в фоновом режиме, поэтому ваша работа защищена без дополнительных усилий с вашей стороны.

<div id="como-funciona">
  ## Как это работает
</div>

Для каждого Replit App автоматически создаётся защищённая резервная копия Git-репозитория. Когда Replit Agent вносит изменения в код или вы публикуете приложение, они автоматически синхронизируются с этой копией. Если локальный Git-репозиторий будет повреждён или станет непригодным для использования, вы сможете восстановить из резервной копии всю историю коммитов.

<Info>
  Удалённый репозиторий резервного копирования называется `gitsafe-backup` и управляется Replit автоматически. Вам ничего не нужно настраивать — он уже работает в фоновом режиме.
</Info>

<div id="visualizando-seu-histrico-de-backup">
  ## Просмотр истории резервных копий
</div>

Проще всего просмотреть историю коммитов в [Git Pane](/ru/pt/core-concepts/project-editor/version-control/git-interface). Откройте его в разделе Tools Project Editor — там отображается полная история коммитов, включая все чекпоинты Agent. В большинстве случаев этого достаточно и не требуется выполнять команды.

Если вам нужно напрямую проверить удалённый репозиторий gitsafe-backup, воспользуйтесь Shell:

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

Здесь показана полная история коммитов, включая все чекпоинты Agent и коммиты, созданные вручную. С её помощью можно убедиться, что у вашей работы есть резервная копия, или найти нужный коммит для восстановления.

<div id="recuperando-de-problemas-no-git">
  ## Восстановление после проблем с Git
</div>

Если вы столкнулись с ошибками Git или ваш репозиторий повреждён, начните с [Git Pane](/ru/pt/core-concepts/project-editor/version-control/git-interface). С его помощью можно устранить большинство распространённых проблем — например, вернуться к предыдущему коммиту или получить изменения из удалённого репозитория — без команд Shell.

Если Git Pane не может помочь (например, если папка `.git` полностью повреждена), выполните описанные ниже действия с помощью Shell.

<div id="verificar-se-o-backup-est-disponvel">
  ### Проверьте доступность резервной копии
</div>

Сначала убедитесь, что удалённый репозиторий резервного копирования существует:

```bash theme={null}
git remote -v
```

Найдите `gitsafe-backup` в выводе. Если он есть, можно продолжить восстановление.

<div id="restaurar-seu-repositrio">
  ### Восстановление репозитория
</div>

<Warning>
  В ходе этого процесса текущая папка `.git` будет заменена резервной версией. Рабочие файлы останутся без изменений, но локальная история Git будет восстановлена из резервной копии.
</Warning>

<Steps>
  <Step title="Сохранить текущую конфигурацию Git">
    Создайте резервную копию файла конфигурации Git, если вы используете пользовательские настройки:

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Клонировать резервный репозиторий">
    Создайте временный клон из резервной копии:

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Заменить папку Git">
    Переместите повреждённую папку `.git` и замените её резервной копией:

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Восстановить конфигурацию">
    Восстановите конфигурацию Git:

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

После выполнения этих шагов запустите `git status`, чтобы убедиться, что репозиторий работает корректно.

<div id="soluo-de-problemas-comuns">
  ## Устранение распространённых проблем
</div>

<div id="fatal-repository-not-found-ou-remote-de-backup-ausente">
  ### &quot;fatal: repository not found&quot; или отсутствует резервный удалённый репозиторий
</div>

Система резервного копирования может быть недоступна для старых проектов. Если вам нужна помощь с восстановлением старого проекта, обратитесь в службу поддержки.

<div id="a-recuperao-no-incluiu-commits-recentes">
  ### Восстановление не содержит последних коммитов
</div>

Резервные копии синхронизируются после каждого коммита Agent. Если вы внесли изменения, но не закоммитили их, они не попадут в резервную копию. Проверьте рабочий каталог на наличие незакоммиченных файлов.

<div id="operaes-git-esto-lentas-ou-travadas">
  ### Операции Git выполняются медленно или зависают
</div>

Если операции Git не отвечают, возможно, сохранился устаревший файл блокировки. Его можно безопасно удалить:

```bash theme={null}
rm -f .git/index.lock
```

<div id="prevenindo-perda-de-dados">
  ## Предотвращение потери данных
</div>

Хотя система резервного копирования автоматически сохраняет историю Git, вы можете дополнительно защитить свою работу:

* **Регулярно создавайте коммиты**: Создавайте небольшие коммиты, чтобы резервные копии вашего прогресса регулярно обновлялись
* **Используйте чекпоинты**: При работе с [Replit Agent](/ru/pt/core-concepts/agent) чекпоинты автоматически создают коммиты на важных этапах
* **Подключите GitHub**: Для критически важных проектов [подключите App к GitHub](/ru/pt/getting-started/quickstarts/import-from-github), чтобы обеспечить дополнительный уровень резервного копирования
