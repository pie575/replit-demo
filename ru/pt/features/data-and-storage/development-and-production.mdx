---

Каждый Replit App работает с двумя базами данных. **База данных разработки** — это среда, где вы и Agent экспериментируете в процессе создания. **База данных продакшена** хранит настоящие данные опубликованного приложения и надёжно защищает их, пока вы продолжаете разработку.

<div id="como-eles-se-comparam">
  ## Чем они отличаются
</div>

| Аспект         | База данных для разработки                                   | Продакшн-база данных                                                    |
| -------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **Назначение** | Эксперименты и разработка функций                            | Обслуживание реальных пользователей и хранение бизнес-данных            |
| **Данные**     | Тестовые данные, вымышленные записи, небольшие наборы данных | Реальные данные пользователей, критически важная для бизнеса информация |
| **Создание**   | Создаётся автоматически вместе с каждым Replit App           | При публикации приложения                                               |
| **Agent**      | Agent может создавать и изменять таблицы                     | Agent не может её изменять                                              |
| **Изменения**  | Частые изменения схемы, быстрые итерации                     | Продуманные, спланированные изменения, применяемые при публикации       |
| **Оплата**     | Бесплатно включена в каждый Replit App                       | По объёму использования                                                 |

<Note>
  Agent не может изменять продакшн-базу данных. Это ограничение защищает вашу продакшн-базу данных.

  Agent может вносить изменения в вашу базу данных для разработки. При публикации все изменения структуры базы данных для разработки, которые вы внесли с помощью Agent (добавление и удаление столбцов или таблиц), применяются к вашей продакшн-базе данных.

  Вы можете в любой момент вручную отредактировать продакшн-данные: откройте инструмент **Database**, выберите продакшн-базу данных, откройте **My Data** и включите **Edit**.
</Note>

<div id="crie-um-banco-de-dados-de-produo-ao-publicar">
  ## Создание продакшен-базы данных при публикации
</div>

Опубликованный app получает собственную продакшен-базу данных, отдельную от базы данных для разработки, которую вы используете в процессе создания приложения.

* **Текущая инфраструктура (Helium)**: Replit сам создаёт продакшен-базу данных, когда она нужна при публикации. Настраивать ничего не требуется.
* **Устаревшие базы данных для разработки на Neon**: продакшен-базу данных вы создаёте в настройках публикации. При публикации откройте **Production database settings**, включите **Create production database** и при желании — **Set up your production database with your current development data**, чтобы скопировать данные из среды разработки.

<Frame caption="Настройки продакшен-базы данных в Publishing">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="Настройки публикации с параметрами Create production database" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  Копируйте данные из разработки в продакшен только в том случае, если их безопасно использовать в вашем app в продакшене. Такие данные могут содержать тестовые учётные записи, примеры записей или незавершённый контент.
</Warning>

После завершения публикации опубликованный app работает с продакшен-базой данных. Project Editor по-прежнему использует базу данных для разработки, поэтому дальнейшие изменения при разработке не затрагивают данные в продакшене напрямую.

<div id="pooling-de-conexes">
  ## Пул соединений
</div>

По умолчанию в продакшн-базах данных пул соединений не включён. Ваш app подключается к базе данных напрямую по строке подключения `DATABASE_URL`, поэтому большинство фреймворков должны управлять собственным пулом соединений на стороне клиента.

<Note>
  Каждый проект Neon включает строку прямого подключения и строку подключения через пул. Строка прямого подключения выглядит так: `postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`.

  Чтобы использовать подключение через пул, добавьте `-pooler` к хосту: `postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`.
</Note>

Если строка подключения к продакшн-базе данных была раскрыта, [перевыпустите учётные данные продакшн-базы данных](/ru/pt/features/data-and-storage/connection-details#regenerar-as-credenciais-do-banco-de-dados-de-produção).

<div id="fazendo-alteraes-seguras-no-seu-banco-de-dados-de-produo">
  ## Безопасное внесение изменений в рабочую базу данных
</div>

При публикации обновлений, затрагивающих базу данных, некоторые изменения требуют тщательного планирования, чтобы избежать простоя или потери данных.

<Info>
  Во время публикации вы можете заметить кратковременный простой опубликованного приложения. Изменения в базе данных иногда требуют временной остановки приложения — это позволяет избежать конфликтов и защитить данные, пока изменения применяются.
</Info>

Особой осторожности обычно требуют следующие типы изменений:

* **Удаление столбцов базы данных**, на которые всё ещё ссылается код вашего приложения
* **Изменение типов данных столбцов** таким образом, что существующий код не может их обработать
* **Добавление обязательных полей** без значений по умолчанию в существующие таблицы
* **Переименование таблиц или столбцов**, нарушающее работу существующих запросов
* **Изменение ограничений**, из-за которых существующая логика приложения может быть отклонена

<div id="teste-as-alteraes-com-uma-prvia-de-implantao">
  ### Тестируйте изменения в предварительной версии развёртывания
</div>

Предварительная версия развёртывания — это временная изолированная копия вашей рабочей среды, в которой можно проверить изменения базы данных и обновления приложения до того, как они затронут реальных пользователей. Используйте её, чтобы:

* Убедиться, что ваш App по-прежнему работает после применения изменений в базе данных — во всех основных пользовательских сценариях
* Проверить, что существующие данные перенесены корректно, а новые поля содержат ожидаемые значения
* Заметить снижение производительности по времени выполнения запросов

<div id="faturamento-e-uso-de-recursos">
  ## Оплата и использование ресурсов
</div>

Продакшн-базы данных тарифицируются по факту использования через Neon — провайдера бессерверных баз данных. После пяти минут простоя база данных переходит в неактивное состояние, и тарификация вычислительного времени приостанавливается; при поступлении запроса база мгновенно возобновляет работу.

На стартовом экране инструмента Database отображаются **Billing Period** и **Hours of Compute Used**. Чтобы посмотреть объём хранилища по каждой базе данных, откройте вкладку **Settings** нужной базы. Чтобы увидеть использование в каждом Replit App, откройте **Settings** → **Account** → **Account usage** и разверните строки **PostgreSQL Storage** и **PostgreSQL Compute**.

О том, как Replit тарифицирует использование баз данных, читайте в разделе [Deployments and Database Billing](/ru/pt/billing/about-usage-based-billing#databases).

<div id="removendo-um-banco-de-dados-de-produo">
  ## Удаление продакшн-базы данных
</div>

<Warning>
  Удаление необратимо по истечении 7-дневного периода хранения. Обязательно создайте резервную копию всех важных данных, прежде чем продолжить. Для баз данных действует 7-дневный период мягкого удаления, в течение которого их можно восстановить; при необходимости обратитесь в службу поддержки. По истечении 7 дней база данных удаляется безвозвратно и восстановлению не подлежит.
</Warning>

<Accordion title="Как удалить базу данных">
  В инструменте **Database**:

  1. Выберите базу данных, затем откройте вкладку **Settings**
  2. Нажмите **Remove database** и подтвердите действие, выбрав **Yes, Remove database**
</Accordion>

<div id="banco-de-dados-de-desenvolvimento-legado">
  ## Устаревшие базы данных для разработки
</div>

До 4 декабря 2025 года базы данных для разработки размещались в <a href="https://neon.com/" target="_blank">Neon</a>. Все новые базы данных для разработки размещаются в собственной инфраструктуре Replit (Helium). Проверить, какую инфраструктуру использует ваше приложение, можно на вкладке **Settings**: `DATABASE_URL`, содержащий `neon.tech`, означает устаревший Neon; `helium` — текущую инфраструктуру.

| **Характеристика**           | **Replit (текущая)**                                                                                                                                      | **Neon (устаревшая)**                                                                                                                                                 |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Хостинг**                  | Размещается в собственной инфраструктуре Replit                                                                                                           | Размещается в Neon (сторонний провайдер)                                                                                                                              |
| **Оплата**                   | Бесплатно включено в каждое Replit App                                                                                                                    | Оплата по факту использования. Подробнее см. в разделе [Оплата Publishing и баз данных](/ru/pt/billing/about-usage-based-billing#databases).                             |
| **Восстановление**           | Восстановите базу данных до любого checkpoint с помощью [функции отката](/ru/pt/features/data-and-storage/data-recovery)                                     | Восстановление на определённый момент времени (PITR) — до любого момента в пределах срока хранения резервных копий.                                                   |
| **Безопасность подключения** | Доступна только из вашего приложения и никогда не открывается для публичного доступа.                                                                     | Использовалась полная строка подключения. Если она становилась доступна третьим лицам, любой мог получить доступ к вашей базе данных и изменить её.                   |
| **Поведение при ремиксе**    | [Ремикс](/ru/pt/features/projects-and-artifacts/remix-an-app) создаёт новую базу данных для разработки с копией данных, обеспечивая изоляцию и безопасность. | При ремиксе одна и та же база данных использовалась для всех копий, поэтому изменения в ремиксах могли повлиять на исходное приложение.                               |
| **Создание базы данных**     | Автоматически создаётся для каждого Replit App.                                                                                                           | Требовалась явная настройка.                                                                                                                                          |
| **Процесс публикации**       | Публикация создаёт отдельную базу данных для продакшена, обеспечивая изоляцию сред.                                                                       | Для разработки и продакшена использовалась одна и та же база данных, поэтому непреднамеренные изменения в среде разработки могли повлиять на приложения в продакшене. |

<div id="atualizao-da-infraestrutura-do-banco-de-dados">
  ## Обновление инфраструктуры базы данных
</div>

Replit переводит базы данных для разработки с Neon на **Helium** — собственную управляемую инфраструктуру PostgreSQL. Обновление выполняется автоматически при первом открытии каждого App в Project Editor и сохраняет все ваши данные.

Что изменится:

* **Меньшая задержка и больше места для хранения**: ваша база данных будет работать в инфраструктуре Replit вместе с вашим App, а лимит хранилища увеличится с 10 ГБ до 20 ГБ.
* **Тот же движок базы данных**: Helium использует PostgreSQL 16 — ту же версию, что и Neon. Ваши запросы, схемы и данные будут работать так же.
* **Автоматическое обновление подключения**: `DATABASE_URL` будет обновлён и укажет на Helium. Прежняя строка подключения Neon будет сохранена в Secrets как `NEON_DATABASE_URL` для справки.
* **Удаление отдельных переменных PG**: `PGHOST`, `PGPORT`, `PGUSER` и `PGPASSWORD` будут удалены. Вместо них используйте `DATABASE_URL`.

Во время обновления вы увидите экран выполнения **&quot;Upgrading your database&quot;**. Для больших баз данных процесс может занять от нескольких минут до нескольких часов; вы можете закрыть вкладку и вернуться позже. Если при обновлении возникнет проблема, оно будет автоматически пропущено и повторено при следующем открытии App. После завершения появится диалоговое окно подтверждения.

Для большинства пользователей никаких действий не потребуется. Ознакомьтесь со следующим, если это относится к вашему App:

* **Строки подключения Neon, жёстко заданные в коде**: обновите код, который напрямую использует строку подключения `neon.tech`, чтобы вместо неё использовать переменную среды `DATABASE_URL`.
* **Пользовательские роли PostgreSQL**: роли и разрешения будут перенесены автоматически, но пароли ролей скопировать нельзя. Сбросьте пароли всех пользовательских ролей в новой базе данных.

<div id="erros-de-conexo-ssl-aps-a-atualizao">
  ### Ошибки SSL-подключения после обновления
</div>

Если вы видите ошибки вида `The server does not support SSL connections`, значит ваш код подключения принудительно инициирует SSL-рукопожатие. Neon требовал SSL, а Helium работает локально вместе с вашим приложением и SSL не использует. Сделайте настройку SSL зависимой от окружения:

<CodeGroup>
  ```js JavaScript theme={null}
  // Before (breaks after upgrade)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // After (works in both development and production)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  Если вы используете ORM — например Drizzle, Prisma или Sequelize — обратитесь к его документации по условной настройке параметров SSL. Принцип тот же: отключите SSL для базы данных разработки и включите его для продакшена.
</Tip>

<div id="apps-bifurcados-que-compartilhavam-um-banco-de-dados">
  ### Форкнутые Apps с общей базой данных
</div>

В устаревшей системе Neon при форке App копировался `DATABASE_URL` исходного App, поэтому и сами Apps, и их опубликованные версии подключались к одной и той же базе данных. Устаревшие общие базы данных были отключены **8 июня 2026 года**. Если ваш опубликованный App перестал работать или потерял доступ к своим данным, см. [Fix a published app using a shared database](/ru/pt/features/data-and-storage/shared-database-migration) или [обратитесь в поддержку](https://replit.com/support).
