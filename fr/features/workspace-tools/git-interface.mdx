Le volet Git de Replit offre une interface visuelle pour les opérations Git, sans avoir à utiliser de commandes Git en ligne de commande. Cette fonctionnalité rend le contrôle de version accessible aux débutants tout en restant performante pour les développeurs expérimentés.

<div id="features">
  ## Fonctionnalités
</div>

Le volet Git offre des fonctionnalités complètes de contrôle de version directement dans le Project Editor, grâce à une interface intuitive qui simplifie les opérations Git complexes.

* **Gestion des dépôts** : initialisez, connectez et gérez des dépôts Git grâce à l&#39;intégration GitHub
* **Suivi des commits** : indexez, validez et consultez les modifications dans tous vos fichiers
* **Gestion des branches** : créez des branches, basculez entre elles et fusionnez-les visuellement
* **Résolution des conflits** : identifiez et résolvez les conflits de fusion à l&#39;aide d&#39;une assistance visuelle
* **Intégration du Shell** : synchronisation entre les commandes Git exécutées dans le Shell et le volet Git

<div id="usage">
  ## Utilisation
</div>

<div id="repository-setup">
  ### Configuration du dépôt
</div>

<Accordion title="Accéder au volet Git">
  1. Accédez à la section Tools de votre Replit App
  2. Sélectionnez le signe **+** pour ajouter de nouveaux outils
  3. Sélectionnez **Git** dans la liste des outils disponibles
</Accordion>

Le volet Git vous permet de configurer et de connecter votre dépôt :

* **Initialiser le dépôt** : créez un nouveau dépôt Git pour votre Replit App
* **Se connecter à un fournisseur Git** : associez votre dépôt à un provider hébergé ou auto-hébergé pris en charge pour la sauvegarde et la collaboration
* **Configurer le dépôt distant** : configurez et gérez la connexion à votre dépôt distant

<Note>
  **Prise en charge de Git auto-hébergé** : Replit prend en charge GitHub Enterprise Server, GitLab Self-Managed et Bitbucket Data Center avec le forfait Enterprise. [Contactez l&#39;équipe commerciale de Replit](https://replit.com/enterprise) pour obtenir de l&#39;aide concernant l&#39;intégration, la configuration du provider et le dépannage des connexions. Vous pouvez également [configurer un dépôt distant à l&#39;aide de commandes Git dans Shell](#using-git-commands-in-shell).
</Note>

<div id="change-management">
  ### Gestion des modifications
</div>

<Accordion title="Afficher les modifications">
  1. Modifiez n’importe quel fichier de votre Replit App
  2. Ouvrez le volet Git depuis la section Tools
  3. Consultez les modifications dans la section **Review Changes**
</Accordion>

Le volet Git propose des outils pour gérer les modifications apportées à votre code :

* **Examiner les modifications** : consultez les fichiers modifiés, avec les ajouts et les suppressions mis en évidence
* **Indexer des fichiers** : sélectionnez les fichiers à inclure dans votre prochain commit
* **Valider les modifications** : enregistrez vos modifications avec des messages descriptifs
* **Envoyer les mises à jour** : envoyez vos commits vers votre dépôt distant en un clic

<Note>
  Vous pouvez utiliser Replit AI pour générer des messages de commit décrivant précisément vos modifications.

<div id="branch-management">
  ### Gestion des branches
</div>

<Accordion title="Gérer les branches">
  1. Ouvrez le volet Git dans la section Tools
  2. Sélectionnez le menu déroulant à côté du nom de la branche
  3. Créez une branche ou sélectionnez-en une existante
</Accordion>

Le volet Git facilite le travail avec plusieurs versions de votre code :

* **Créer des branches** : créez des branches pour développer des fonctionnalités séparément
* **Changer de branche** : passez d’une version de votre code à une autre
* **Publier des branches** : partagez vos branches avec votre fournisseur Git
* **Récupérer les modifications** : synchronisez les modifications distantes de vos collaborateurs

<div id="merge-conflict-resolution">
  ### Résolution des conflits de fusion
</div>

<Accordion title="Comment résoudre les conflits de fusion">
  1. Tentez de récupérer les modifications lorsqu’il y a des conflits
  2. Le volet Git met en évidence les fichiers en conflit
  3. Ouvrez chaque fichier en conflit pour afficher et résoudre les conflits
  4. Enregistrez les fichiers après avoir résolu les conflits
  5. Terminez la fusion en sélectionnant **Pull**
</Accordion>

Lorsque du code provenant de différentes sources entre en conflit, le volet Git vous aide à :

* **Identifier les conflits** : voyez précisément quels fichiers contiennent des conflits
* **Visualiser les différences** : examinez les deux versions du code en conflit
* **Résoudre les problèmes** : choisissez le code à conserver ou modifiez manuellement le code en conflit
* **Finaliser les fusions** : terminez le processus de fusion après avoir résolu les conflits

<Frame>
  <img src="/assets/mirror/11-merge-conflict-17b314f0e231.png" alt="Éditeur de code affichant des marqueurs de conflit de fusion" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

Après avoir résolu un fichier en conflit, vous pouvez supprimer les marqueurs de conflit en supprimant les lignes qui commencent par des symboles de conflit, puis enregistrer le fichier.

<div id="using-git-commands-in-shell">
  ### Utiliser les commandes Git dans le Shell
</div>

<Accordion title="Accéder au Shell">
  1. Sélectionnez **All tools** dans le dock d’outils de gauche
  2. Sélectionnez **Shell** parmi les outils disponibles
</Accordion>

<Tip>
  Bien que le volet Git propose une interface conviviale, les utilisateurs expérimentés peuvent utiliser les commandes Git standard dans le Shell pour effectuer des opérations plus complexes. Les modifications apportées par l’une ou l’autre méthode seront visibles aux deux endroits.
</Tip>

Si vous préférez utiliser Git en ligne de commande :

* **Synchronisation des commandes** : toutes les commandes Git exécutées dans le Shell seront automatiquement synchronisées avec le volet Git
* **Fonctionnalités Git complètes** : accédez à des fonctionnalités Git avancées non disponibles dans le volet Git
* **Basculement fluide** : passez des commandes Shell au volet Git selon vos besoins

<Info>
  **Prise en charge des CLI GitHub et GitLab** : en plus des commandes Git standard, vous pouvez également utiliser la [CLI GitHub](https://docs.github.com/en/github-cli) (`gh`) et la [CLI GitLab](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) dans le Shell pour gérer des dépôts Git externes et vous y connecter. Ces outils offrent des fonctionnalités avancées pour travailler avec les dépôts GitHub et GitLab, notamment les pull requests, les tickets et d’autres fonctionnalités propres à chaque plateforme.
</Info>

<div id="repository-operations">
  #### Opérations sur les dépôts
</div>

* **Cloner un dépôt**: `git clone <url-to-repository>`
* **Initialiser un dépôt**: `git init`
* **Ajouter un dépôt distant**: `git remote add origin <url-to-repository>`

<div id="making-changes">
  #### Apporter des modifications
</div>

* **Vérifier l’état** : `git status` (affiche les fichiers modifiés, ajoutés et supprimés)
* **Indexer des fichiers** : `git add <filename>` ou `git add .` (pour tous les fichiers)
* **Valider les modifications** : `git commit -m "your commit message"`
* **Envoyer les modifications** : `git push origin <branch-name>`
* **Récupérer les modifications** : `git pull origin <branch-name>`

<div id="authentication">
  #### Authentification
</div>

Lorsque vous travaillez avec des dépôts privés, vous devez vous authentifier :

* Pour les dépôts GitHub.com, utilisez un jeton d’accès personnel plutôt que votre mot de passe.
* Pour éviter de ressaisir vos identifiants, vous pouvez les stocker dans Replit Secrets :
  1. Créez un secret avec la clé `GIT_URL`
  2. Définissez sa valeur sur `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Utilisez `git push $GIT_URL` pour effectuer un push sans saisir vos identifiants

<Note>
  Lorsque vous utilisez des secrets d’identification, toute personne ayant accès à votre Replit App peut potentiellement accéder à vos identifiants Git. Pour les dépôts sensibles, envisagez de saisir vos identifiants manuellement à chaque fois.
</Note>
