Agent prend en charge quatre types d’intégrations pour passer rapidement de l’idée à l’application :

* **Gérées par Replit** : intégrations intégrées qui fonctionnent automatiquement. Créez une application et Agent peut les utiliser immédiatement.
* **Connectors** : intégrations propriétaires prises en charge par Replit. Connectez-vous une seule fois. Agent peut lire et écrire directement dans ces services depuis Chat — récupérer des données, créer des enregistrements, envoyer des messages — et les utiliser dans toutes vos applications.
* **Intégrations externes** : services tiers fiables avec lesquels vous pouvez développer. Demandez à Agent de les configurer ; vous devrez fournir les clés API.
* **Services Agent** : API tierces payantes qu’Agent utilise en arrière-plan — aucune clé API requise. Leur utilisation est facturée sur vos crédits Replit.

<Note>
  **Disponibilité selon le forfait** : la plupart des connecteurs nécessitent un abonnement Core, Pro ou Enterprise, et certains sont disponibles avec le forfait Free. Le catalogue de connecteurs de votre workspace indique ceux que vous pouvez utiliser avec votre forfait actuel. Les créateurs utilisant le forfait Free peuvent toujours utiliser les intégrations gérées par Replit, comme les bases de données, l’authentification et bien plus encore.
</Note>

<div id="let-agent-suggest-a-connector">
  ### Laissez Agent vous suggérer un connecteur
</div>

Plusieurs services peuvent parfois effectuer la même tâche, comme stocker des fichiers ou envoyer des e-mails. Lorsque vous demandez une fonctionnalité sans préciser de fournisseur, Agent affiche une courte liste de connecteurs adaptés. Choisissez celui que vous préférez.

Sélectionnez un fournisseur, puis connectez-vous une seule fois pour associer votre compte. Agent utilise votre choix pendant la création. Vous pouvez également demander un service précis par son nom pour ignorer la liste.

<div id="configuring-oauth-app-with-replit">
  ### Configurer une application OAuth avec Replit
</div>

<Note>
  **Enterprise uniquement** : la configuration d&#39;une application OAuth personnalisée nécessite un abonnement Enterprise.
</Note>

Avec le forfait Enterprise, vous pouvez utiliser votre propre application OAuth pour un connecteur plutôt que celle fournie par défaut par Replit. Votre organisation peut ainsi être propriétaire du client OAuth, afficher sa propre image de marque sur l&#39;écran de consentement et contrôler précisément les portées que vos créateurs peuvent demander.

Pour configurer un connecteur avec votre propre application OAuth, vous devez obtenir trois éléments auprès du fournisseur : un **Client ID**, un **Client Secret** et les **portées** que vous souhaitez autoriser. Vous devez également enregistrer l&#39;URL de rappel de Replit auprès du fournisseur afin que l&#39;authentification puisse aboutir.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Boîte de dialogue de configuration OAuth du connecteur avec des champs pour le Client ID, le Client Secret et les portées du connecteur, ainsi qu'une URL de redirection définie sur https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Créer une application OAuth auprès de votre fournisseur">
    Connectez-vous à la console de développement ou aux paramètres d&#39;administration du fournisseur, puis créez une application OAuth 2.0. Les fournisseurs désignent cette étape différemment : recherchez des options telles que **Create OAuth app**, **Register application** ou **Create client credentials**.
  </Step>

  <Step title="Définir l'URL de redirection">
    Lorsque le fournisseur vous demande un **Authorized redirect URI** (parfois appelé **Callback URL** ou **Redirect URL**), saisissez :

    ```
    https://replit.com/connectors/oauth/callback
    ```

    C&#39;est vers cette URL que le fournisseur redirige les créateurs vers Replit après qu&#39;ils ont autorisé l&#39;application. Elle doit correspondre exactement : les barres obliques finales, le protocole et le sous-domaine ont tous leur importance. Si vous ajoutez plusieurs URI de redirection, celle-ci doit en faire partie.
  </Step>

  <Step title="Copier le Client ID et le Client Secret">
    Après avoir créé l&#39;application, le fournisseur affiche un **Client ID** et un **Client Secret**.

    * **Client ID** : un identifiant public pour votre application OAuth. Vous pouvez l&#39;exposer sans risque dans les URL et le code côté client.
    * **Client Secret** : une valeur confidentielle qui prouve que la demande provient de votre application. Traitez-la comme un mot de passe : ne la validez jamais dans un dépôt et ne la partagez jamais publiquement. Replit la stocke de manière sécurisée pour vous.

    Certains fournisseurs n&#39;affichent le secret client qu&#39;une seule fois, lors de sa création. Copiez-le immédiatement et conservez-le dans un endroit sûr jusqu&#39;à ce que vous le colliez dans Replit.
  </Step>

  <Step title="Choisir vos portées">
    Les **portées** sont des autorisations qui définissent ce que votre application OAuth peut lire ou écrire au nom du créateur. Chaque fournisseur publie sa propre liste de portées dans sa documentation API.

    Lorsque vous configurez le connecteur dans Replit, les portées que vous saisissez doivent **correspondre exactement** (caractère par caractère, y compris les préfixes d&#39;URL) aux portées que vous avez enregistrées auprès du fournisseur. Causes fréquentes d&#39;erreurs de non-correspondance :

    * L&#39;absence du préfixe d&#39;URL complet (par exemple, `https://www.googleapis.com/auth/drive.file` au lieu de `drive.file`).
    * Des espaces superflus ou des virgules finales.
    * La demande dans Replit d&#39;une portée qui n&#39;est pas activée dans l&#39;application du fournisseur.

    Commencez par les portées minimales dont vos créateurs ont besoin, puis ajoutez-en d&#39;autres si nécessaire : la plupart des fournisseurs vous permettent de mettre à jour les portées sans recréer l&#39;application.
  </Step>

  <Step title="Configurer le connecteur dans Replit">
    Depuis la page **Connectors** de votre organisation, sélectionnez **Add new integration**, choisissez le service, puis collez le **Client ID**, le **Client Secret** et les **portées** fournis par le fournisseur. Sélectionnez **Configure** pour enregistrer.
  </Step>
</Steps>

<Note>
  Si l&#39;authentification échoue après la configuration, vérifiez que l&#39;URL de redirection configurée chez le fournisseur correspond exactement à `https://replit.com/connectors/oauth/callback` et que chaque portée saisie dans Replit est également autorisée dans l&#39;application du fournisseur.
</Note>

<div id="reconnecting-integrations">
  ## Reconnexion des intégrations
</div>

Si un service connecté cesse de fonctionner — par exemple, si votre session expire ou si vos autorisations changent — Replit affiche une alerte de reconnexion dans le Project Editor. Sélectionnez l’alerte pour reconnecter l’intégration directement, sans quitter l’éditeur.

<div id="debugging-connectors">
  ## Débogage des connecteurs
</div>

Vous rencontrez des problèmes lors de la connexion à un service ? Ces guides vous présentent les erreurs courantes et expliquent comment les résoudre.

<AccordionGroup>
  <Accordion title="Google Workspace : &#x22;Cette application est bloquée&#x22;">
    Si le message **&quot;Cette application est bloquée&quot;** s&#39;affiche lorsque vous connectez Google Drive, Docs, Sheets, Calendar ou Gmail, votre Google Workspace limite probablement les applications OAuth tierces. Consultez le guide de dépannage complet pour résoudre ce problème.

    [Résoudre le problème « Cette application est bloquée » pour les connecteurs Google](/fr/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce : &#x22;Connexion expirée&#x22;">
    Si votre connecteur Salesforce cesse de fonctionner et affiche l&#39;erreur **&quot;Connexion expirée&quot;**, la politique relative aux jetons d&#39;actualisation de votre organisation Salesforce est probablement configurée pour faire expirer les jetons après un délai défini. Consultez le guide de dépannage complet pour mettre à jour les paramètres de votre Connected App.

    [Corriger les erreurs de connexion expirée dans Salesforce](/fr/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
