借助 Replit Auth，你可以在应用中打造个性化的用户体验。有了用户账户，你就能保存用户偏好设置、创建定制仪表板、构建社交功能、控制付费内容的访问权限、跟踪用户活动 —— 这些都能让你的应用更具吸引力和价值。

Replit Auth 使用 Replit 自有的登录系统 —— 当有人登录你的应用时，用的是已有的 **Replit 账户**，或者当场新建一个。登录页面采用 Replit 品牌样式，登录流程与 replit.com 全站保持一致。

<Note>
  **Replit Auth 与 Clerk Auth 对比** —— Replit 提供两种身份验证方案。**Replit Auth** (即本页介绍的方案) 使用 Replit 自有的登录系统，因此你的应用用户会使用 Replit 账户登录，并看到带有 Replit 品牌的登录页面。**[Clerk Auth](/zh/ko/features/auth-and-identity/clerk-auth)**则由 Clerk 提供支持，为你的应用配备专属的身份验证租户，品牌形象完全可自定义，用户账户也独立于 Replit。如果你希望登录体验使用自有品牌，或需要与 Replit 无关联的用户账户，请选择 Clerk Auth。

  如果你的应用已经在使用 Replit Auth，请参阅[从 Replit Auth 迁移到 Clerk](/zh/ko/features/auth-and-identity/migrate-auth-to-clerk)，了解自动化迁移流程，以及为保留对现有应用数据的访问权限所需执行的测试步骤。
</Note>

无需耗费数月从零搭建身份验证系统，Replit Auth 只需一条 Agent 提示词即可提供企业级能力。它构建在与财富 500 强企业相同的基础设施之上，包括 Firebase、Google Cloud Identity Platform、reCAPTCHA、Stytch、Clearout 等，专业级安全防护、防滥用机制和全球扩展能力开箱即用。

<div id="replit-auth">
  ## 为什么使用 Replit Auth
</div>

身份验证是一道难题,甚至有整家公司专门在解决它。而你的应用的核心通常并不是身份验证,而是你正在构建的那个独特创意或解决方案。

Replit Auth 提供:

* **无需配置** —— 只需向 Agent 输入一次提示词,即可添加身份验证
* **Replit 账户集成** —— 用户使用现有的 Replit 账户登录,无需单独注册
* **内置安全** —— 基于 Replit 基础设施,自带常见攻击防护
* **用户管理** —— 通过 Auth 面板轻松管理用户
* **数据库集成** —— 自动在数据库中创建用户条目
* **可自定义的登录页面** —— 可个性化应用的登录体验(含 Replit 品牌标识)
* **密码重置** —— Replit 代为发送密码重置邮件,无需自行配置邮件发送服务商
* **推荐计划** —— 通过 Replit Auth 注册的用户会被加入待处理的 Replit Referrals
* **开发中与已发布的应用** —— Replit Auth 在开发环境(replit.dev)和已发布应用(replit.app 及自定义域名)中都能顺畅运行

<div id="section">
  ## 企业级基础设施
</div>

Replit Auth 不只是用户管理——它是构建在企业级基础设施之上的全托管身份认证解决方案。这一强大组合让你的应用拥有与财富 500 强企业同等的认证能力。

* **Firebase 与 Google Cloud Identity Platform** —— Google 久经验证的认证基础设施，配备企业级 SLA
* **高级安全扫描** —— 通过集成 reCAPTCHA，自动抵御机器人与恶意行为者
* **防滥用机制** —— 由 Clearout 提供的邮箱认证与验证，杜绝虚假账户
* **多因素认证 (MFA)&#x20;**&#x20;—— 由 Stytch 企业认证平台支持的安全登录选项
* **全球可扩展性** —— 依托自动扩缩与稳定运行，专为承载数百万用户而设计

有了这一企业级基础，你可以专心打造应用的独有功能，认证环节则交由守护着数十亿美元规模企业的同一套基础设施。无需耗费数月去集成各种服务，只要一句 Agent 提示词，这一切便触手可得。

<div id="replit-auth-2">
  ## Replit Auth 入门
</div>

实现 Replit Auth 的唯一方式是使用 Agent。只需在提示词中提出 Replit Auth 的需求即可。

```
请帮我构建[你的应用创意]，并在应用中加入 Replit Auth 功能。
```

Agent 会自动配置身份验证所需的全部代码和设置。系统不支持手动实现，所有复杂工作均由 Agent 代为处理。

<div id="section-3">
  ## 自定义登录页面
</div>

<Frame>
  <img src="/assets/mirror/auth-login-1ee0460c3780.jpg" alt="Auth 配置" width="1920" height="1080" data-path="images/workspace/auth/auth-login.jpg" />
</Frame>

你可以自定义登录页面，使其符合应用的品牌风格。

1. 在 Project Editor 中打开 Auth 面板
2. 点击 **Configure**
3. 自定义以下元素：
   * 应用名称
   * 应用图标
   * 登录方式 (Google、GitHub、X、Apple、Email)

更改会立即生效并显示在应用的登录页面上。

<div id="section-5">
  ## 安全注意事项
</div>

Replit Auth 依托 Replit 的基础设施，针对常见安全威胁提供内置防护。但你仍应遵循以下最佳实践：

* 在执行敏感操作前，务必在服务器端验证用户身份
* 不要将密码等敏感信息硬编码在代码中
* 使用环境变量存储 API 密钥或 Secrets
* 为用户数据实施适当的访问控制

有关安全的更多信息，请参阅：

* [Replit 的内置安全功能](/zh/ko/features/security/overview)
* [氛围编程安全检查清单](/zh/ko/learn/security-checklist)
* [Secrets 管理](/zh/ko/core-concepts/project-editor/app-setup/secrets)

<div id="section-6">
  ## 推荐
</div>

为鼓励应用向外推广 Replit，所有通过 Replit Auth 注册的用户都会自动计入您的待处理 Replit Referrals。如果他们日后升级到 Replit Core，您将按照当前推荐计划条款获得相应的推荐奖励。

<div id="section-7">
  ## 故障排查
</div>

<div id="section-8">
  ### 常见问题
</div>

1. **登录后无法识别用户**
   * 如果遇到问题，可以请 [Replit Agent](/zh/ko/features/agent/overview) 帮你调试身份验证的实现。

2. **自定义图标不显示**
   * 请确认图标 URL 可正常访问，且格式受支持 (PNG 或 JPG) 。

3. **新绑定的自定义域名无法使用**
   * 重新发布应用，以刷新域名列表 (REPLIT&#95;DOMAINS 环境变量) 。
