⏰ *예상 소요 시간: 10분*

이 가이드를 마치면 공유할 수 있는 URL에 게시된 작은 앱이 완성됩니다.

<Frame>
  <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="선택한 템플릿이 website로 만들어져 공개 Replit URL에서 열린 모습" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
</Frame>

잘 다듬어진 템플릿에서 시작해 이를 작동하는 website로 만든 뒤 게시해 봅니다. 제공되는 템플릿은 달라질 수 있으니, 만들고 싶은 것에 맞는 템플릿을 선택하세요.

<div id="before-you-start">
  ## 시작하기 전에
</div>

[Replit 계정](https://replit.com)이 필요합니다. Design frame으로 새 앱을 빌드하려면 Core 또는 Pro 플랜이 필요합니다. 플랜에 대한 자세한 내용은 [디자인 빌드하기](/ko/design/build-your-design)와 [Billing](/ko/billing/ai-billing)을 참고하세요.

목표는 전체 과정을 한 바퀴 완주하는 것입니다.

* [Replit Design](https://replit.com/design)에서 템플릿 선택하기
* [Agent](/ko/features/agent/overview)로 Build하기
* 앱 테스트하기
* 게시하고 공유하기

Agent는 Replit의 AI builder입니다. 원하는 것을 설명하기만 하면 Agent가 앱을 만들고, 설명하고, 수정하는 것을 도와줍니다.

<div id="choose-build-and-publish-a-template">
  ## 템플릿 선택, 빌드, 게시하기
</div>

<Steps>
  <Step title="디자인 템플릿 둘러보기">
    [replit.com/design](https://replit.com/design)을 엽니다. 추천 템플릿을 둘러보거나 **Landing Pages**, **Mobile**, **Prototypes** 등 형식별로 필터링해 보세요.

    <Frame>
      <img src="/assets/mirror/01-design-gallery-5303cf1cf6d2.jpg" alt="추천 템플릿과 형식 필터가 표시된 Replit Design 갤러리" width="1280" height="720" data-path="images/first-app-template/01-design-gallery.jpg" />
    </Frame>
  </Step>

  <Step title="템플릿 미리보기 및 사용">
    template을 선택해 살펴본 뒤 **Use template**을 선택하세요. Replit이 새 project를 만들고 해당 template을 Design canvas에 배치합니다. 대신 template의 cover page에서 시작했다면, remix flow에 대한 내용은 [template에서 시작하기](/ko/design/start-from-a-template)를 참고하세요.

    <Frame>
      <img src="/assets/mirror/02-template-preview-facda2e40956.jpg" alt="Use template 버튼이 있는 Replit Design template 미리보기" width="1280" height="720" data-path="images/first-app-template/02-template-preview.jpg" />
    </Frame>

    remix된 template은 새 project의 Design canvas에서 열립니다.

    <Frame>
      <img src="/assets/mirror/03-remixed-design-35b051544510.jpg" alt="새 Replit project의 Design canvas에 remix된 선택한 template" width="1280" height="720" data-path="images/first-app-template/03-remixed-design.jpg" />
    </Frame>
  </Step>

  <Step title="디자인을 웹사이트로 만들기">
    template은 design mockup에서 시작합니다. 게시하려면 먼저 **Build**로 전환한 다음, 선택한 design을 실제로 동작하는 website로 만들어 달라고 Agent에 요청하세요. 예를 들면 다음과 같습니다.

    > 선택한 이 template을 동작하는 website로 빌드해 줘. 시각적 디자인은 그대로 유지하고, 내비게이션과 문의 관련 동작이 작동하도록 만들어 줘.

    Agent는 같은 project 안에 website artifact를 생성하며, 선택한 design을 원본으로 사용합니다.

    <Note>
      **Publish** 버튼은 Design에서도 보입니다. project에 design mockup만 있는 경우, Publishing은 아직 배포할 대상이 없다고 알리고 Agent에 앱을 빌드해 달라고 요청하도록 안내합니다. Website artifact가 만들어진 뒤에는 Design과 Build 어느 쪽에서든 게시할 수 있습니다.
    </Note>

    <Frame>
      <img src="/assets/mirror/04-build-request-d5a5a3428361.jpg" alt="선택한 포트폴리오 design이 첨부된 Build workspace, Agent chat의 빌드 요청, 그리고 design만 있는 project에는 아직 배포할 대상이 없다고 설명하는 Publishing" width="1280" height="720" data-path="images/first-app-template/04-build-request.jpg" />
    </Frame>
  </Step>

  <Step title="앱이 Preview에서 정상적으로 작동하는지 확인하세요">
    Agent가 작업을 마치면 [Preview](/ko/features/editor/preview)를 열고 방문자처럼 앱을 사용해 보세요. Preview는 publish하기 전, 앱을 만드는 도중에 테스트해 보는 공간입니다.

    다음 항목을 확인하세요.

    * 기본 내비게이션이 제대로 이동되는지 확인합니다.
    * template의 버튼과 양식을 사용해 봅니다.
    * 작업 후 성공 또는 유효성 검사 상태가 명확하게 표시되는지 확인합니다.
    * 페이지를 새로 고친 뒤 사이트를 다시 사용해 봅니다.
    * Preview 너비를 휴대폰 화면 크기로 조정해 봅니다.

    문제가 생기면 증상을 Agent에게 설명하세요. 직접 코드를 진단할 필요는 없습니다.

    <Frame>
      <img src="/assets/mirror/05-preview-d5702e9d9ac8.jpg" alt="Project Editor Preview에서 실행 중인 template 기반 website" width="1280" height="720" data-path="images/first-app-template/05-preview.jpg" />
    </Frame>

    <Tip>
      publish하기 전에 다양한 시각적 변형을 살펴보고 싶으신가요? [Explore suggestions](/ko/design/explore-suggestions)를 참고해 여러 대안을 나란히 생성하고 마음에 드는 것을 적용해 보세요.
    </Tip>
  </Step>

  <Step title="앱 게시하기">
    Preview가 정상적으로 동작하면 **Publish**를 선택하세요. 생성된 하위 도메인을 확인하고, 앱에 접근할 수 있는 대상을 선택한 뒤 보안 설정을 검토하세요. 그런 다음 대화 상자에서 **Publish**를 선택하세요.

    Publish하면 공유 가능한 URL이 포함된 앱의 공개 버전이 생성됩니다.

    <Frame>
      <img src="/assets/mirror/06-publish-dialog-2f79654c6dfb.jpg" alt="생성된 하위 도메인, 접근 설정, Publish 버튼이 있는 Publish 대화 상자" width="1280" height="720" data-path="images/first-app-template/06-publish-dialog.jpg" />
    </Frame>
  </Step>

  <Step title="게시한 앱 열기">
    새 브라우저 tab에서 public URL을 열고 동일한 확인 작업을 반복하세요. 공유하기 전에 앱이 Project Editor 밖에서도 제대로 동작하는지 확인해야 합니다.

    published app이 Preview와 다르게 동작한다면 publishing logs와 앱에 필요한 production 설정을 확인하세요. 자주 발생하는 publishing 문제는 [Publishing 문제 해결](/ko/build/troubleshooting)을 참고하세요.

    <Frame>
      <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="public Replit URL에서 열린 완성된 template 기반 website" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
    </Frame>
  </Step>
</Steps>

<div id="congratulations-you-shipped-your-first-app">
  ## 🎉 축하합니다 — 첫 번째 앱을 배포했습니다
</div>

디자인 템플릿에서 시작해 공유 가능한 shareable URL까지 완성했습니다. 그 과정에서 다음을 수행했습니다:

* Replit Design에서 템플릿을 골라 remix했습니다.
* Agent에게 선택한 디자인을 실제로 동작하는 website로 만들어 달라고 요청했습니다.
* Preview에서 결과를 테스트했습니다.
* 앱을 게시하고 public URL로 열어 보았습니다.

시작점 선택, build, 테스트, 개선, 게시까지 — 이것이 Replit workflow의 전체 흐름입니다.
