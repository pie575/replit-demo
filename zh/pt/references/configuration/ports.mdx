---
title: "端口"
description: "了解如何在你的 Replit App 中配置和管理网络端口。"
---

由于 Replit 在云端环境中运行你的项目，Replit 上的端口机制与本地计算机上有所不同。 (如果你想先了解 TCP 端口的基础知识，[请从这里开始](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/)。) 

在一台计算机上，端口管理只有一层：程序指定一个要监听的端口，当来自互联网的流量到达你计算机上的该端口时，就会被路由到相应的进程。

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="计算机" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` 这部分是地址，也就是主机。如果一个进程监听 `0.0.0.0`，表示它会在每一个网络接口上监听——也就是说，如果另一台计算机 (在互联网上) 向你计算机的 IP 地址发送请求，它就能收到。因此，监听 0.0.0.0 意味着这些进程可以被公共互联网访问 (前提是你的计算机已联网) 。

大多数编程框架在开发阶段*不会*监听 `0.0.0.0`，因为出于隐私和安全考虑，你不一定希望正在进行的工作被公开。它们通常会监听另一个地址——`127.0.0.1`，也就是 `localhost`。这意味着只有本机才能向该端口发出请求。

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="localhost 端口仅在托管它们的计算机上可见。" width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

在 Replit 上，要让运行中的进程能够通过网页预览或外部请求访问，就必须为它设置一个**外部端口**。这是因为进程通常使用的“内部端口”仅在 Replit 提供的隔离云端环境内可见。内部端口必须连接到一个可从外部访问的端口，才能把正确的流量转发给你的程序。即使进程监听的是 0.0.0.0 这类通常对公网开放的地址，仍然需要绑定到一个外部端口。

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="外部端口将流量转发到程序监听的内部端口。" width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit 的做法是把外部端口绑定到特定的内部端口——例如上图中，外部端口 `:80` 绑定到内部端口 `:3000`。这意味着 Replit App 在 80 端口上收到的任何流量都会转发到内部端口 3000。

该配置记录在 .replit 配置文件的 [[ports]] 部分中。

默认情况下，Replit 会把你打开的第一个端口绑定到默认外部端口 80，这样访问该进程时无需在域名后附加端口号 (例如 customdomain.com/ 而不是 customdomain.com:3000/) 。随后打开的其他内部端口会绑定到其他可用的外部端口 (完整列表见下文) 。

<div id="porta-padro">
  ## 默认端口
</div>

:80 是 HTTP 流量的“默认端口”，因此发送到根域名的 HTTP 流量会自动路由到 80 端口。正因如此，URL 中不会显示 80 端口的端口号。除 `:80` 以外的端口则会出现在域名路径中 (例如 customdomain.com:4200/) 。 (Replit 默认提供 TLS，因此严格来说流量走的是 443 端口，即 HTTPS 的默认端口。在实际使用中，你可以将两者视为等同。)

<div id="publicao">
  ## 部署
</div>

Autoscale 和 Reserved VM 部署仅支持暴露一个外部端口，且对应的内部端口不能使用 `localhost`。如果暴露多个端口，或仅在 localhost 上暴露一个端口，已部署的应用将无法正常运行。为确保 Autoscale 部署按预期运行，一个简单的做法是移除配置中所有端口的 `externalPort` 条目，*仅保留*您希望通过互联网访问的服务端口。

<div id="depurao">
  ## 调试
</div>

某项功能未能按预期运行的一个常见原因是：虽然端口配置看似正确，但程序实际上在查找另一个端口。例如，如果你的配置是：

```
[[ports]]
internalPort = 3000
externalPort = 80
```

这样，发往端口 80 的互联网流量将被转发到内部端口 3000。但是，如果你的程序监听的不是端口 3000，而是其他端口 (例如 8080) ，看起来就像没有任何流量到达。这可能发生在你修改了代码中的端口，却没有修改配置中对应的端口，或者将一个项目的配置复制粘贴到另一个项目时。

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="程序可能会更改其监听的端口。" width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

每个框架默认监听的端口各不相同——例如，Flask 为 5000，React 为 3000，Laravel 为 8000。请确保配置了正确的端口！

<div id="preferncias">
  ## 偏好设置
</div>

当你的 Replit App 中有端口打开时，Replit 会自动将其绑定到可用的外部端口，并把绑定关系记录到 .replit 配置文件中。

但对于在 localhost 上打开的内部端口，默认不会这样做。因为运行在 localhost 上的服务通常假定自己只会被运行该进程的同一台计算机访问 (localhost 端口仅对运行该进程的计算机可见) ，所以这类服务往往不如那些从一开始就面向公共互联网设计的服务安全。

你随时可以覆盖这一行为：将想要对外暴露的端口的 `exposeLocalhost` 配置选项设置为 `true`。

如果你希望默认*始终*对外暴露 localhost 端口，可以在“用户设置”工具中将“自动端口转发”设置为“所有端口”。

如果你希望*从不*为打开的端口创建配置，而是手动管理所有 Replit Apps 的端口配置，可以将其设置为“从不”。

<div id="portas-suportadas">
  ## 支持的端口
</div>

首次开放端口时，Replit App 会将端口 80 设为默认外部端口。Replit App 还可将 3000、3001、3002、3003、4200、5000、5173、6000、6800、8000、8008、8080、8081 作为额外的外部端口对外暴露。

端口 22 和 8283 供内部使用，无法转发。

<div id="configurao-ports-do-replit">
  ## .replit 的 `[[ports]]` 配置
</div>

类型：`{localPort, externalPort, exposeLocalhost}`

通过 `[[ports]]` 配置，你可以指定要为 Web 输出对外暴露的 HTTP 端口。默认情况下，任何绑定到主机 0.0.0.0 的 HTTP 端口都会作为 Replit App 的 Web 输出对外暴露。

你可以在 .replit 文件中添加新的 [[ports]] 条目来提供额外端口，而不会替换默认端口。必须指定 localPort 和 externalPort 条目。你可以按照下方定义，在 .replit 文件中添加多个 [[ports]] 条目，以添加多个额外端口。

<div id="localport">
  ### localPort
</div>

指定 Replit 要绑定到外部端口的本地端口。

<div id="externalport">
  ### externalPort
</div>

确定要将哪个端口公开为此本地端口的可访问端口。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

如果您希望*永不*对外暴露某个端口，可以保留 `localPort` 配置，只是不添加 `externalPort`：

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

确定使用 `localhost` 的内部端口能否绑定到外部端口。可以是 `true`、`false` 或 null。

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
