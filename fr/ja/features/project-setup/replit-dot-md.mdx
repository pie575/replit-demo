<div id="replitmd">
  ## Fonctionnement de `replit.md`
</div>

Agent commence par créer un fichier `replit.md` à la racine de votre projet, en s&#39;appuyant sur les bonnes pratiques. Ce fichier contient :

* Les informations de base du projet
* Les modèles de code recommandés
* Les configurations courantes adaptées au type de projet

<YouTubeEmbed videoId="kYv525W-vaU" title="Comment personnaliser les réponses de Replit Agent" />

Lorsqu&#39;il traite vos demandes, Agent lit automatiquement le fichier `replit.md` et en utilise le contenu pour :

* Comprendre l&#39;architecture et les conventions du projet
* Respecter vos modèles et votre style de code préférés
* Utiliser le gestionnaire de paquets et les dépendances que vous avez indiqués

À mesure qu&#39;il en apprend davantage sur votre projet et qu&#39;il apporte des modifications à votre application, Agent peut également mettre à jour le fichier `replit.md`.

<Note>
  Vous pouvez modifier le fichier `replit.md` pour personnaliser le comportement d&#39;Agent.
</Note>

<div id="replitmd-2">
  ## Configuration de `replit.md`
</div>

<div id="section">
  ### Génération automatique
</div>

Lorsque vous créez un projet avec Agent, un fichier `replit.md` est généré automatiquement selon les bonnes pratiques. Ce fichier apparaît à la racine du projet et contient :

* les informations de base du projet
* les modèles de code recommandés
* les configurations courantes adaptées au type de projet

<div id="section-2">
  ### Création manuelle
</div>

Vous pouvez créer votre propre fichier `replit.md` en ajoutant un nouveau fichier nommé `replit.md` à la racine de votre projet. Agent le détectera et l&#39;utilisera automatiquement lors de vos prochaines conversations.

<Note>
  Le fichier `replit.md` doit se trouver à la racine de votre projet pour fonctionner correctement.
</Note>

<div id="replitmd-3">
  ### Régénérer `replit.md`
</div>

Si votre fichier `replit.md` est corrompu ou si vous souhaitez repartir de zéro :

1. Supprimez le fichier `replit.md` existant à la racine de votre projet
2. Démarrez une nouvelle conversation avec Agent
3. Agent génère automatiquement un nouveau fichier `replit.md` à partir de votre projet actuel

<div id="section-3">
  ## Bonnes pratiques
</div>

<div id="section-4">
  ### Soyez précis et explicite
</div>

Rédigez des instructions claires et précises pour qu&#39;Agent comprenne exactement ce que vous souhaitez :

```markdown theme={null}
## Style de code

- Utiliser TypeScript pour tous les nouveaux fichiers JavaScript
- Privilégier les composants fonctionnels avec hooks plutôt que les composants de classe
- Utiliser Tailwind CSS pour la mise en forme, éviter les styles en ligne
- Toujours indiquer les types TypeScript des paramètres et des valeurs de retour des fonctions
```

Pour un guide détaillé sur la mise en forme des prompts, consultez le [guide d&#39;ingénierie des prompts d&#39;Anthropic](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags).

<div id="section-5">
  ### Utilisez des exemples
</div>

Les exemples aident Agent à mieux cerner vos préférences que des explications abstraites :

````markdown theme={null}
## Gestion des erreurs d'API

Lorsque vous créez des points de terminaison d'API, utilisez toujours ce modèle de gestion des erreurs :

```javascript
app.get("/api/users", async (req, res) => {
  try {
    const users = await getUsersFromDatabase();
    res.json({ success: true, data: users });
  } catch (error) {
    console.error("Error fetching users:", error);
    res.status(500).json({
      success: false,
      error: "Failed to fetch users",
    });
  }
});
```
````

<div id="section-6">
  ### Définir vos préférences de communication
</div>

Indiquez à Agent comment vous souhaitez recevoir les informations et les mises à jour :

```markdown theme={null}
## Style de communication

- Avant d'apporter des modifications, expliquez ce que vous allez faire et pourquoi
- Décomposez les tâches complexes en étapes claires
- Demandez des précisions si les exigences sont floues
- Justifiez brièvement vos décisions techniques
```

<div id="section-7">
  ### Précisez le contexte du projet
</div>

Aidez Agent à comprendre l&#39;objectif et les contraintes de votre projet :

```markdown theme={null}
## Contexte du projet

Il s'agit d'une application de réseau social pour les passionnés de lecture, où les utilisateurs peuvent :
- Créer des listes de lecture et partager des recommandations de livres
- Suivre d'autres lecteurs et consulter leurs actualités
- Noter et commenter les livres qu'ils ont lus

Public cible : lecteurs occasionnels de 25 à 45 ans
Pile technique : frontend React, backend Node.js, base de données PostgreSQL
```

<div id="replitmd-4">
  ## Exemple de configuration `replit.md`
</div>

<div id="section-8">
  ### Projet d&#39;application web
</div>

```markdown theme={null}
# Consignes du projet MyApp

## Aperçu du projet
Une application web de gestion de tâches développée avec React et Express.js.

## Préférences technologiques
- Frontend : React avec TypeScript, Tailwind CSS
- Backend : Express.js avec TypeScript
- Base de données : Neon PostgreSQL avec l'ORM Drizzle
- Gestionnaire de paquets : npm (ni yarn ni pnpm)

## Normes de codage
- Utiliser des composants fonctionnels avec des hooks
- Mettre en place des error boundaries adaptées
- Respecter les conventions d'API REST pour les endpoints
- Utiliser des noms de variables et de fonctions explicites

## Style de communication
- Expliquer votre approche avant d'apporter des modifications
- Commenter le code pour la logique complexe
- Poser des questions si les exigences sont ambiguës
```

<div id="section-9">
  ### Projet d&#39;analyse de données
</div>

```markdown theme={null}
# Consignes du projet d'analyse de données

## Contexte du projet
Analyse des données de comportement client afin de dégager des tendances et des enseignements.

## Préférences technologiques
- Python avec Streamlit pour les applications web interactives
- pandas, numpy et matplotlib pour l'analyse de données

## Normes d'analyse
- Documenter clairement toutes les étapes de l'analyse
- Créer des visualisations interactives avec les composants Streamlit
- Valider la qualité des données avant l'analyse
- Exporter les résultats au format CSV et les afficher dans des tableaux Streamlit

## Style de communication
- Expliquer les méthodes statistiques et les hypothèses retenues
- Replacer les constats et les recommandations dans leur contexte
- Employer un langage clair et non technique pour les enseignements métier
- Créer des tableaux de bord interactifs pour les présentations aux parties prenantes
```

<div id="api">
  ### Projet de développement d&#39;API
</div>

```markdown theme={null}
# Directives de développement d'API

## Présentation du projet
Développement d'une API RESTful pour le backend d'une application mobile.

## Pile technologique
- Node.js with Express.js
- MongoDB with Mongoose
- JWT pour l'authentification
- Gestionnaire de paquets : npm

## Normes de l'API
- Utiliser des codes d'état HTTP sémantiques
- Mettre en place une validation rigoureuse des entrées
- Appliquer une limitation de débit sur les points de terminaison publics
- Suivre la spécification OpenAPI pour la documentation

## Exigences de sécurité
- Valider toutes les entrées utilisateur
- Utiliser des variables d'environnement pour les données sensibles
- Mettre en place des politiques CORS adaptées
- Journaliser les requêtes pour faciliter le débogage

## Approche de test
- Écrire des tests unitaires pour tous les points de terminaison
- Prévoir des tests d'intégration pour les flux critiques
- Utiliser Jest comme framework de test
```

<div id="replitmd-5">
  ## Associer la recherche web et `replit.md`
</div>

Agent peut effectuer des recherches sur le web pour trouver des informations, des bibliothèques et des solutions à jour. En combinant cette capacité avec le fichier `replit.md`, vous bénéficiez à la fois de connaissances actualisées et de consignes propres à votre projet.

<div id="section-13">
  ### Bonnes pratiques pour l&#39;intégration de la recherche web
</div>

**Indiquez précisément ce que vous souhaitez qu&#39;Agent recherche :**

```markdown theme={null}
## Préférences de recherche
- Toujours vérifier les dernières versions des dépendances avant de proposer des mises à jour
- Rechercher les bonnes pratiques actuelles en matière de sécurité
- Consulter les techniques récentes d'optimisation des performances adaptées à notre stack technique
```

**Indiquez à Agent comment exploiter les connaissances externes :**

```markdown theme={null}
## Consignes de recherche externe
- Lorsque tu proposes de nouvelles bibliothèques, vérifie qu'elles sont compatibles avec notre stack existante
- Adapte les exemples externes à nos conventions de code et à la structure de notre projet  
- Vérifie que les solutions proposées fonctionnent avec notre environnement de publication
```

**Exemple de requête combinant les deux :**
« Recherche les dernières techniques d&#39;optimisation des performances de React 18 et implémente-les en suivant les modèles de composants définis dans `replit.md` »

Cette approche vous garantit des solutions à la fois à jour et adaptées aux besoins spécifiques de votre projet.

<div id="section-14">
  ## Limitations
</div>

<div id="section-15">
  ### Limites de taille de fichier et de contenu
</div>

Il n&#39;existe pas de limite stricte du nombre de caractères pour `replit.md`, mais les fichiers très volumineux risquent de ne pas être traités intégralement. Pour obtenir les meilleurs résultats, veillez à ce que votre fichier `replit.md` reste ciblé et concis.

<div id="section-16">
  ### Exigences relatives au répertoire racine
</div>

Le fichier `replit.md` doit se trouver à la racine du projet. Agent ne détecte pas automatiquement les fichiers situés dans des sous-répertoires.

<div id="section-17">
  ### Portée du contexte
</div>

`replit.md` fournit du contexte aux conversations avec Agent, mais ne s&#39;applique pas automatiquement aux autres outils d&#39;IA.
