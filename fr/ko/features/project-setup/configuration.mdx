Une application Replit est configurée à l’aide de deux fichiers : `.replit` et `replit.nix`. Ces fichiers déterminent le fonctionnement de votre application Replit, de l’exécution du code aux outils et langages de développement.

Les fichiers de configuration sont masqués par défaut. Sélectionnez « Afficher les fichiers masqués » dans le menu de l’arborescence des fichiers pour les afficher dans votre application Replit.

<div id="replitnix">
  ## Fichier `replit.nix`
</div>

Replit utilise `Nix` pour gérer les paquets et l’environnement. Le fichier `replit.nix` a les fonctions suivantes :

**Définir les dépendances système :** définit précisément les paquets logiciels nécessaires à votre application Replit via le gestionnaire de paquets Nix.

**Créer des environnements reproductibles :** garantit un environnement de développement cohérent et reproductible, idéal pour les projets collaboratifs et les tests sur plusieurs systèmes.

Vous pouvez gérer visuellement les paquets Nix à l’aide de l’outil `Dependencies`. Pour en savoir plus, consultez le guide sur les [dépendances système](/fr/ko/features/project-setup/dependency-management#system-dependencies).

Pour configurer des paquets avec le fichier `replit.nix`, vous pouvez lister les [paquets Nix](https://search.nixos.org/packages) dans le tableau `deps` en les préfixant par `pkgs.`. Les modifications sont synchronisées après le rechargement du Shell.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="replit">
  ## Fichier `.replit`
</div>

Le fichier `.replit` contrôle le comportement de votre application Replit. Il utilise le [format de configuration](https://toml.io/en/) `toml`. Voici les principaux éléments que vous pouvez configurer :

**Commande d’exécution :** définit la commande exécutée lorsque vous sélectionnez le bouton Run. Chaque modèle comporte une commande d’exécution par défaut qui vous permet d’exécuter immédiatement votre code. Pour les applications plus personnalisées et complexes, utilisez [Workflows](/fr/ko/features/workspace-tools/workflows).

**Protocole Language Server (LSP) :** fournit des fonctionnalités telles que la saisie semi-automatique, la navigation dans le code, la coloration syntaxique, l’analyse en temps réel et l’affichage des erreurs.

**Variables d’environnement :** configure et gère les variables d’environnement nécessaires au bon fonctionnement de votre application.

**Dépendances et paquets :** gérez directement l’installation et la configuration des paquets via le fichier `.replit` afin que tous les outils nécessaires soient prêts au démarrage de votre application Replit. Vous pouvez gérer visuellement les dépendances à l’aide de l’outil `Dependencies`. Pour en savoir plus, consultez le guide des [modules système](/fr/ko/features/project-setup/dependency-management#advanced-configuration).

Pour les applications Python, le fichier `.replit` par défaut est le suivant :

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

| **Clé de configuration**                        | **Valeur/exemple**                     | **Description**                                                                                                                                                                                                                       |
| ----------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a name="entrypoint" />`entrypoint`             | `main.py`                              | Spécifie le fichier principal qui s’exécute et s’affiche par défaut à l’ouverture de l’éditeur. Vous pouvez modifier le nom du fichier selon votre application.                                                                       |
| <a name="modules" />`modules`                   | `["python-3.10:v18-20230807-322e88b"]` | Définit une version spécifique d’un langage de programmation pris en charge par Replit ou d’une dépendance principale.                                                                                                                |
| <a name="nix" />`[nix]`                         |                                        | Spécifie les paramètres d’utilisation de Nix, le gestionnaire de paquets des dépendances système. Pour en savoir plus, consultez la documentation sur la [gestion des dépendances](/fr/ko/features/project-setup/dependency-management). |
| <a name="channel" />`channel`                   | `stable-23_05`                         | Indique le canal Nix à utiliser et affecte les versions disponibles des dépendances système.                                                                                                                                          |
| <a name="packages" />`packages`                 | `["cowsay", "htop"]`                   | Spécifie les paquets Nix à installer. Vous pouvez également utiliser `replit.nix` si vous avez besoin d’un contrôle plus précis.                                                                                                      |
| <a name="unitTest" />`[unitTest]`               |                                        | Configure les paramètres liés aux tests unitaires dans une application Replit.                                                                                                                                                                |

| <a name="requiredFiles" />`requiredFiles`       | `[".replit", "replit.nix"]`            | Liste des fichiers qui doivent obligatoirement être présents lors de l’importation pour que le projet fonctionne correctement.                                                                                                        |
| <a name="deployment" />`[deployment]`           |                                        | Contient les paramètres permettant de déployer une application depuis une application Replit vers un environnement de production.                                                                                                             |

| <a name="deploymentTarget" />`deploymentTarget` | `cloudrun`                             | Spécifie la plateforme cible de déploiement pour l’hébergement de l’application.                                                                                                                                                      |

Maintenant que vous comprenez la configuration de base du fichier `.replit`, découvrez dans la section suivante comment configurer les paramètres de base et avancés d’une application Replit.

<div id="section">
  ## Configuration des paramètres de base
</div>

<div id="entrypoint">
  ### Point d’entrée (Entrypoint)
</div>

Il s’agit du fichier principal du projet. Si vous ne définissez pas la propriété `run`, l’environnement d’exécution exécute le fichier désigné comme `entrypoint`.

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="run">
  ### Commande `Run`
</div>

La propriété `run` du fichier `.replit` est un élément essentiel : elle détermine la commande, ou la série de commandes, exécutée au démarrage lorsque vous cliquez sur le bouton `Run` dans l&#39;environnement Replit. La commande `Run` peut être définie sous la forme d&#39;une chaîne indiquant la commande à exécuter ou d&#39;un tableau de chaînes indiquant la commande et ses arguments individuels.

Façons courantes de configurer la commande `Run` :

* **Commande unique :**
  Exécutez directement une seule commande dans votre application Replit. En ajoutant ceci au fichier `.replit`, un message d&#39;accueil s&#39;affiche dans la fenêtre `Console` lorsque vous cliquez sur le bouton `Run` :
  **Exemple :** `run = "echo 'Hello, Replit!'"`

* **Arguments explicites :**
  Dans certains cas, il peut être préférable d&#39;adopter une syntaxe plus explicite afin d&#39;éviter les règles d&#39;analyse des guillemets ou d&#39;interpolation du Shell. Vous pouvez réécrire l&#39;exemple ci-dessus en séparant les arguments.
  Comme le message d&#39;accueil est explicitement transmis comme seul argument de `echo`, ni `'` ni `"` ne sont nécessaires :
  **Exemple :** `run = ["echo", "Hello, Replit!"]`

* **Plusieurs commandes :**
  Exécutez simultanément plusieurs processus, par exemple un frontend et un backend. Cette méthode est utile lorsque vous développez un backend Python et un frontend TypeScript, chaque serveur étant associé à un port différent :
  **Exemple :** `run = "python -m app & npm run start & wait"`

<div id="section-2">
  #### Gestion des processus
</div>

Vous pouvez exécuter plusieurs commandes simultanément avec `&`, mais vous souhaiterez peut-être mieux distinguer les journaux de chaque service. L&#39;ajout de [dépendances système](/fr/ko/features/project-setup/dependency-management#system-dependencies) telles que [`process-compose`](https://github.com/F1bonacc1/process-compose) permet de gérer plus efficacement plusieurs processus.

<div id="build">
  #### Étape `Build`
</div>

Les langages compilés comme TypeScript, Golang ou Java peuvent nécessiter une étape de compilation distincte avant d’exécuter le code. C’est également le cas lorsque vous devez réinitialiser l’environnement, les données ou la configuration avant le prochain `run`.

* **Compilation :**
  Dans les dépôts TypeScript, vous devrez peut-être exécuter `tsc` avant d’exécuter le code.
  **Exemple :**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="section-3">
  #### Inclure des variables d’environnement
</div>

Pour fournir des variables d’environnement au service avant son exécution, vous pouvez étendre la propriété `run` en [table](https://toml.io/en/v1.0.0#table).

Cette modification, plus complexe, peut nécessiter de déplacer la propriété `run = "..."` dans le fichier `.replit`.

Le diff suivant montre comment transmettre une commande via `args` dans `[run]` et définir la variable `NAME` dans `[run.env]` :

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# Le nouveau [run] doit se trouver après toutes les propriétés de niveau supérieur ne commençant pas par `[` !
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="section-4">
  #### Exécution interactive
</div>

Les programmes interactifs peuvent également être exécutés à l’aide du bouton `Run`, qui permet de séparer l’environnement de développement du terminal dans lequel le programme s’exécute.
Prenons l’exemple du script d’agrégation suivant :

**Exemple**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="section-5">
  ## Options de configuration avancées
</div>

Découvrez les options de configuration avancées disponibles dans une application Replit. Personnalisez l’environnement de développement, gérez les commandes d’exécution, intégrez des services de langage et adaptez la gestion des dépendances.

| **Configuration** | **Clé**                             | **Valeur/exemple**                          | **Description**                                                                              |
| ----------------- | ----------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------- |
| onBoot            | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Commande exécutée au démarrage de l’application Replit.                                              |
| compile           | <a name="compile" />`compile`       | (aucun exemple par défaut)                  | Commande exécutée avant la commande `run`, utilisée pour les langages compilés tels que C++. |
| language          | <a name="language" />`language`     | `language = "javascript"`                   | Définit le langage lors d’une importation depuis GitHub ou de la création d’une application Replit.  |
| entrypoint        | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | Fichier principal exécuté et affiché à l’ouverture de l’éditeur.                             |
| hidden            | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | Fichiers ou dossiers masqués par défaut dans l’arborescence des fichiers.                    |
| audio             | <a name="audio" />`audio`           | `audio = true`                              | Lorsqu’il est défini sur `true`, active l’audio système.                                     |

<div id="section-6">
  ### Remarques concernant l’audio système
</div>

Après avoir défini `audio = true` dans le fichier `.replit`, vous devrez peut-être redémarrer l’environnement de développement. Ouvrez la palette de commandes avec `Cmd+K` (Mac) ou `Ctrl+K` (Windows), puis recherchez et sélectionnez **Restart compute**.

Lorsque vous exécutez une application graphique, une icône de casque accompagnée d’une case à cocher s’affiche dans l’angle inférieur droit de la fenêtre `Output`.
En raison des limitations du navigateur, vous devez activer cette fonctionnalité après chaque rechargement.

```toml theme={null}
# Placez ceci tout en haut du fichier `.replit`, en dehors de toute section commençant par `[`
audio = true
```

<div id="section-7">
  ## Configuration du gestionnaire de paquets
</div>

| **Configuration**                          | **Clé**                                           | **Valeur/exemple**                            | **Description**                                                                            |
| ------------------------------------------ | ------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------ |
| gestionnaire de paquets                    | <a name="language" />`language`                   | `packager.language = "python3"`               | Langage utilisé pour les opérations sur les paquets.                                       |
| fonctionnalités du gestionnaire de paquets | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Détecte automatiquement les paquets à installer avant l’exécution de l’application Replit.         |
| fonctionnalités du gestionnaire de paquets | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | Active la prise en charge du gestionnaire de paquets lorsqu’il est défini sur `true`.      |
| fonctionnalités du gestionnaire de paquets | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Indique si l’installation des paquets est exécutée lors de l’hébergement de l’application Replit.  |
| gestionnaire de paquets                    | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | Commande exécutée après l’installation d’un nouveau paquet via le gestionnaire de paquets. |
| gestionnaire de paquets                    | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | Chemins à ignorer lors de la détection des paquets.                                        |
| gestionnaire de paquets                    | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | Modules pour lesquels aucune détection automatique n’est effectuée lors de l’installation. |

<div id="replit-2">
  ### Exemple de configuration `.replit` pour le gestionnaire de paquets
</div>

```toml theme={null}
# Définition du langage de l’application Replit
packager.language = "python3"

# Activation des fonctionnalités de gestion automatique des paquets
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# Commande à exécuter après l’installation de chaque paquet
packager.afterInstall = "echo 'Package installed successfully'"

# Chemins et paquets à ignorer par le gestionnaire de paquets
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# Paramètres de déploiement supplémentaires
[deployment]
run = ["python3", "app.py"]
```

<div id="section-8">
  ## Configuration du déploiement
</div>

| **Configuration** | **Clé**                               | **Valeur/exemple**                   | **Description**                                                                                              |
| ----------------- | ------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| deployment        | <a name="run" />`run`                 | `deployment.run = "npm start"`       | Commande exécutée au démarrage du conteneur de déploiement.                                                  |
| deployment        | <a name="build" />`build`             | `deployment.build = "npm run build"` | Commande exécutée avant le déploiement.                                                                      |
| deployment        | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | Si la valeur est `true`, aucune vérification des ports ouverts n’est requise une fois le déploiement réussi. |

<div id="replit-3">
  ### Exemple de configuration `.replit` pour le déploiement
</div>

```toml theme={null}

# Définir le point d’entrée principal du projet
entrypoint = "app.js"

# Paramètres de configuration pour le déploiement de l’application
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  La **configuration de l’interpréteur** est obsolète et n’est plus prise en charge par Replit. Utilisez plutôt la commande `Run` pour configurer la façon dont les scripts et applications s’exécutent dans l’environnement application Replit.
</Note>


<div id="replit-app">
  ## Accéder aux métadonnées d’environnement de l’application Replit
</div>

<div id="nodejs">
  ### Node.js
</div>

Pour accéder à toutes les variables d&#39;environnement :

`console.log(process.env);`

Pour accéder à une variable spécifique (REPL&#95;SLUG) :

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

Pour accéder à toutes les variables d’environnement :

```python theme={null}
import os
print(os.environ)
```

Pour accéder à une seule variable (REPL&#95;SLUG) :

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

Pour accéder à toutes les variables d’environnement :

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

Pour accéder à une variable unique (REPL&#95;SLUG) :

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```
