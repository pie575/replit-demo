---
title: "外部访问令牌"
description: "无需登录，即可从 CI 流水线、Webhook 及其他自动化服务访问私有 Replit App。"
---

外部访问令牌是你为特定 Replit App 签发的 Bearer 令牌。
即使应用的 URL 已被[私有开发 URL](/zh/ja/features/publishing/private-deployments) 或[私有部署](/zh/ja/features/publishing/private-deployments) 锁定，CI 流水线、Webhook、状态检查探测器、Slack 机器人、内部脚本等自动化服务依然可以访问你的应用。

请像对待密码一样对待每个令牌。在令牌过期或被你吊销之前，任何持有该令牌的人都能访问你的应用。

<Note>
  为 deployment 选择私有访问后，即可使用外部访问令牌，无需在工作区中额外开启。在 Enterprise 工作区中，只有工作区管理员可以管理令牌。
</Note>

<div id="section">
  ## 何时使用令牌
</div>

当浏览器之外的程序需要调用私有 Replit App 时，请使用外部访问令牌。常见场景包括：

* 在每次提交时针对开发 URL 运行冒烟测试的 GitHub Actions 工作流。
* 访问已发布应用健康检查端点的 uptime 监控服务 (如 Better Stack、Pingdom、UptimeRobot) 。
* 向私有部署发送 POST 请求的 Webhook 接收方 (如 Stripe、Slack、GitHub) 。
* 调试时从队友机器上执行的 `curl` 或 `fetch` 调用。

外部访问令牌是为 **API 流量**设计的，并不适用于在浏览器中打开 UI 页面。单页应用 (如 Vite、Next.js) 会在后续请求中加载 JavaScript 包，而这些请求不会携带令牌，因此会失败。如需交互式浏览，请照常登录。

<div id="section-2">
  ## 令牌的环境
</div>

每个令牌都会绑定到一个环境：

| 环境            | 有效范围                              | 用途                 |
| :------------ | :-------------------------------- | :----------------- |
| `Development` | 应用工作区的开发 URL (`*.replit.dev`)     | 在开发过程中访问正在运行的 Repl |
| `Production`  | 应用已发布的部署 (`*.replit.app` 及自定义域名)  | 从外部服务访问私有部署        |

`Production` 令牌在重新发布 (包括发布新版本) 后仍然有效。出现以下情况时，Replit 会吊销令牌：

* 你取消发布该部署。
* 你删除该部署。
* 你将应用的访问设置由私有改为公开。

此外，令牌过期或被你手动吊销后也将失效。

<div id="section-3">
  ## 创建外部访问令牌
</div>

<Steps>
  <Step>
    打开要发布的应用，然后打开 **Publishing** 工具。
  </Step>

  <Step>
    选择 **Adjust settings**，展开重新发布选项。
  </Step>

  <Step>
    在 **Security** 部分找到 **External access tokens**。
  </Step>

  <Step>
    选择 **Create access token**，并填写以下内容：

    * **Label** (可选) ：填写一个简短的名称，例如 `CI` 或 `Stripe webhook`，便于日后识别该令牌。最多 120 个字符。
    * **Environment**：根据调用方服务需要在哪里访问应用，选择 `Development` 或 `Production`。
    * **Expires after**：选择有效期——可选 `1 hour`、`24 hours`、`7 days`、`30 days`、`3 months`、`1 year`、`5 years`。请选择能满足用途的最短期限。没有&quot;永不过期&quot;选项。
  </Step>

  <Step>
    选择 **Create**。
  </Step>
</Steps>

Replit 只会显示令牌**一次**。请立即复制——关闭对话框后，就再也无法查看该令牌。如果令牌丢失，请将其吊销并重新签发一个。

显示界面提供了两种复制方式：

* **Copy query parameter** —— 复制可追加到 URL 的 `?project-protection-bypass=<token>`，便于用 `curl` 快速验证。
* **Copy token only** —— 复制原始令牌，适合通过 `Authorization: Bearer` 请求头发送。

<Info>
  创建第一个令牌时，如果应用尚未启用外部访问，系统会自动为其启用。若没有防护屏障，令牌也就无从绕过。
</Info>

<div id="section-4">
  ## 使用令牌
</div>

可以通过以下两种方式之一提供令牌：

<div id="authorization">
  ### Authorization 请求头 (推荐)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

这种方式几乎适用于所有场景，例如 Webhook、CI 脚本以及后端之间的调用。令牌不会出现在记录 URL 的日志中，也不会留在浏览器历史记录中。

<div id="section-5">
  ### 查询参数
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

仅在无法设置请求头时才使用查询参数形式，例如某些服务只接受 URL。包含令牌的 URL 往往会留存在代理日志、Shell 历史记录和截图中，因此请尽可能优先使用请求头形式。

<div id="section-6">
  ## 管理现有令牌
</div>

**External access tokens** 部分会按创建时间从新到旧列出你为该应用创建的所有令牌，并显示标签、环境、创建日期、过期时间和吊销状态。由于令牌的完整值只在创建时显示一次，每一行只会显示令牌末尾的几个字符，方便你识别。

这里只会显示*你自己*创建的令牌。即使你是该应用的所有者，其他协作者的令牌也仅对其本人可见。

<div id="section-7">
  ## 吊销令牌
</div>

当令牌不再需要，或者你发现它可能已泄露时，请立即吊销。吊销步骤如下：

<Steps>
  <Step>
    在应用的发布设置中打开 **External access tokens** 部分。
  </Step>

  <Step>
    在列表中找到该令牌，然后点击垃圾桶图标。
  </Step>

  <Step>
    确认吊销。
  </Step>
</Steps>

吊销**立即生效且不可恢复**。使用该令牌的流量将在数秒内被拒绝。如需重新获得访问权限，请签发新令牌。

你只能吊销自己创建的令牌。将协作者从工作区中移除后，该协作者为此应用签发的令牌会自动吊销。

<div id="section-8">
  ## 安全地管理令牌
</div>

外部访问令牌属于凭据，请像对待 API 密钥或密码一样谨慎处理。

<div id="section-9">
  ### 应该做的
</div>

* **将令牌存放在密钥管理工具中** —— 例如 GitHub Actions 的 secrets、CI 厂商的 Vault、云服务商的密钥存储或密码管理器。切勿提交到仓库中。
* 尽可能**缩短有效期**。对于一次性集成，7 天有效期的令牌比放着一个 5 年期令牌不管要安全得多。
* **为每个令牌添加标签**，让日后的自己能弄清它的用途以及是否仍在使用。没有标签的令牌往往最先泄露，也最晚被吊销。
* **为每个使用方单独签发令牌。** 每个 CI 任务一个、每个 Webhook 来源一个、每项运行状态检查一个，以此类推。这样一旦某处被入侵 —— 或某个厂商不再需要时 —— 只需吊销那一个令牌即可。
* **优先使用 `Authorization` 请求头**而非查询参数，避免令牌经由 URL 日志、浏览器历史记录和 Referer 请求头泄露。
* 一旦令牌可能已经泄露 —— 日志外流、提交到公开仓库、屏幕共享、前员工的笔记本电脑等 —— 请**立即吊销**。吊销会即时生效，之后再签发新令牌即可。

<div id="section-10">
  ### 不要这样做
</div>

* **不要在团队成员之间或服务之间共用令牌。** 如果两个系统共用同一个令牌，就无法在不影响其中一方的前提下单独吊销另一方。
* **不要把令牌粘贴到聊天、邮件、截图或问题跟踪系统中。** 这些渠道会被归档、索引，并以难以预料的方式扩散出去。
* **不要把令牌嵌入客户端代码** —— 浏览器应用、移动应用、桌面端二进制文件等一切分发到用户设备上的内容，都应视为公开信息。
* **不要把令牌用于浏览器会话。** 令牌用于 API 调用，而不是在浏览器标签页中加载 SPA。这类场景请使用常规的 Replit 登录方式。
* **不要默认选择 5 年有效期。** 请按照使用方实际需要的访问时长来设置有效期。

<div id="section-11">
  ## 故障排查
</div>

<Accordion title="Production 令牌突然无法使用">
  Production 令牌在常规的重新发布后仍然有效。请检查令牌是否已过期，或是否被你自己吊销。此外，还要确认你是否取消发布或删除了部署，或者是否将应用从私有改为了公开。如果应用已没有私有部署，请重新以私有方式发布，然后签发新的令牌。已过期或已吊销的令牌无法恢复。
</Accordion>

<Accordion title="令牌在 `curl` 中可用，但浏览器中却显示登录页面">
  外部访问令牌是为 API 流量设计的，而非用于浏览器会话。单页应用在浏览器中加载时，首个 HTML 请求可以通过查询参数传递令牌，但之后针对 JavaScript 包、CSS 和 API 调用的请求不会携带该令牌，因此会被拒绝。若要以交互方式浏览应用，请按常规方式登录 Replit。
</Accordion>

<Accordion title="我弄丢了令牌 — 还能再查看一次吗？">
  不能。Replit 只在创建时显示一次令牌。列表中会显示元数据 (标签、环境、有效期、末尾几个字符) ，但不会显示完整的令牌值。如果令牌丢失，请吊销该令牌并创建新令牌。
</Accordion>
