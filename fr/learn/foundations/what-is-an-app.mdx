Une app est un logiciel conçu pour effectuer une tâche précise pour une personne ou un groupe donné.

Les apps peuvent être simples ou complexes. Une calculatrice, un formulaire de réservation, un dashboard, un outil interne, une expérience mobile, une place de marché ou un portail client sont tous des apps s’ils aident quelqu’un à faire quelque chose d’utile.

<div id="apps-are-code-that-runs-on-infrastructure">
  ## Les Apps sont du code qui s&#39;exécute sur une infrastructure
</div>

Chaque app repose sur deux éléments qui fonctionnent ensemble :

* **Code** — les instructions qui décrivent le fonctionnement de l&#39;app : l&#39;interface visible par les utilisateurs, la logique qui réagit aux clics et aux saisies, et les règles qui régissent la circulation des données.
* **Infrastructure** — les machines, réseaux, systèmes de stockage et services sur lesquels le code s&#39;exécute, afin que d&#39;autres personnes puissent y accéder depuis un navigateur ou un téléphone.

Écrire le code est ce que la plupart des gens imaginent lorsqu&#39;ils pensent à la « création d&#39;une app ». L&#39;infrastructure comprend tout ce qui doit être en place pour que ce code fonctionne réellement pour les utilisateurs : un serveur pour l&#39;exécuter, une base de données pour stocker des informations, un domaine pour que les utilisateurs puissent la trouver, des mesures de sécurité pour la protéger et un moyen de la mettre à jour sans perturber ce qui fonctionne déjà.

Sur Replit, vous décrivez ce que vous voulez en langage naturel. Agent écrit le code et Replit fournit l&#39;infrastructure — hébergement, bases de données, Secrets, domaines et déploiements — afin que vous puissiez publier une app fonctionnelle sans avoir à tout configurer vous-même.

<div id="why-build-an-app">
  ## Pourquoi créer une application ?
</div>

Vous pourriez créer une application lorsque les outils existants répondent presque à vos besoins, mais pas tout à fait.

Une application est utile lorsque :

* Vous souhaitez un workflow personnalisé
* Vous avez atteint les limites d&#39;une feuille de calcul, d&#39;un formulaire ou d&#39;un template
* Vous avez besoin d&#39;un processus reproductible
* Vous souhaitez tester l&#39;intérêt suscité par une idée
* Vous souhaitez que vos collègues, clients ou utilisateurs interagissent avec quelque chose que vous contrôlez

Par exemple, un entrepreneur peut créer une application de liste d&#39;attente pour tester l&#39;intérêt suscité par son idée. Un spécialiste du marketing peut créer une page de destination de campagne avec un formulaire. Un analyste de données peut créer un dashboard qui facilite l&#39;exploration d&#39;une feuille de calcul.

<div id="apps-solve-a-focused-problem">
  ## Les apps répondent à un besoin précis
</div>

Les bonnes premières apps sont ciblées. Elles répondent à un besoin clair pour un public précis.

Au lieu de commencer par :

```text theme={null}
Une plateforme pour gérer l’ensemble de mon activité.
```

Commencez par :

```text theme={null}
Une page où les clients peuvent demander un devis de traiteur et recevoir un message de confirmation.
```

Une version plus modeste est plus facile à créer, tester, publier et améliorer.

<div id="apps-and-artifacts">
  ## Apps et artifacts
</div>

Sur Replit, une app est un type d’artifact. Un artifact est un résultat publiable d’un projet.

Les artifacts peuvent inclure :

* Web apps
* Mobile apps
* Tableaux de bord de données
* Slide Decks
* Vidéos animées
* Designs
* Expériences 3D

Les apps sont généralement interactives. Elles permettent souvent aux utilisateurs de soumettre des informations, de consulter des données, de se connecter, de faire des choix ou d’effectuer un processus. D’autres artifacts, tels que les Slide Decks ou les vidéos animées, peuvent davantage privilégier la présentation ou la narration.

<div id="what-makes-an-app-real">
  ## Qu’est-ce qui rend une app concrète ?
</div>

Une app commence à devenir concrète lorsque quelqu’un peut l’utiliser autrement que dans votre tête.

Cela signifie généralement :

* Elle a un objectif clair
* Quelqu’un peut effectuer l’action principale
* Vous pouvez la tester dans Preview
* Vous pouvez la publier à une URL partageable
* Vous pouvez l’améliorer grâce aux retours

La première version n’a pas besoin de toutes les fonctionnalités. Elle doit fonctionner suffisamment bien pour vous permettre d’en tirer des enseignements.

<div id="common-misconceptions">
  ## Idées reçues
</div>

* **« Une application doit être importante. »** Beaucoup d’applications utiles sont de petits outils conçus pour une tâche précise.
* **« Une application doit être publique. »** Certaines applications sont des outils privés pour vous, votre équipe ou vos clients.
* **« Une application doit être parfaite avant d’être publiée. »** Publier une première version ciblée vous aide à déterminer ce qui doit être amélioré.
