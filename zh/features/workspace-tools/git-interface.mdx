Replit 的 Git 面板为 Git 操作提供可视化界面，无需使用命令行 Git 命令。该功能让初学者也能轻松进行版本控制，同时为经验丰富的开发者提供强大的功能。

<div id="features">
  ## 功能
</div>

Git 面板在 Project Editor 中直接提供全面的版本控制功能，并通过易于使用的界面简化复杂的 Git 操作。

* **仓库管理**：通过 GitHub 集成初始化、连接和管理 Git 仓库
* **提交跟踪**：暂存、提交并查看所有文件的更改
* **分支操作**：以可视化方式创建、切换和合并分支
* **冲突解决**：借助可视化辅助识别并解决合并冲突
* **Shell 集成**：同步在 Shell 中运行的 Git 命令与 Git 面板

<div id="usage">
  ## 使用
</div>

<div id="repository-setup">
  ### 仓库设置
</div>

<Accordion title="如何访问 Git 面板">
  1. 前往 Replit App 中的工具区域
  2. 选择 **+** 号以添加新工具
  3. 在可用工具列表中选择 **Git**
</Accordion>

Git 面板可帮助你设置并连接仓库：

* **初始化仓库**：为你的 Replit App 创建新的 Git 仓库
* **连接到 Git 身份提供方**：将仓库关联到受支持的托管或自托管身份提供方，以便备份和协作
* **配置远程仓库**：设置并管理与远程仓库的连接

<Note>
  **自托管 Git 支持**：Replit 的 Enterprise 套餐支持 GitHub Enterprise Server、GitLab Self-Managed 和 Bitbucket Data Center。请[联系 Replit 销售团队](https://replit.com/enterprise)，获取入门指导、身份提供方配置和连接调试支持。你也可以[使用 Shell 中的 Git 命令配置远程仓库](#using-git-commands-in-shell)。
</Note>

<div id="change-management">
  ### 更改管理
</div>

<Accordion title="如何查看更改">
  1. 修改 Replit App 中的任意文件
  2. 在“工具”部分打开 Git 面板
  3. 在 **审查更改** 部分查看更改
</Accordion>

Git 面板提供了管理代码更改的工具：

* **审查更改**：查看已修改的文件，并高亮显示新增和删除的内容
* **暂存文件**：选择要纳入下次提交的文件
* **提交更改**：通过添加描述性消息保存更改
* **推送更新**：一键将提交推送到远程仓库

<div id="branch-management">
  ### 分支管理
</div>

<Accordion title="如何管理分支">
  1. 在“工具”部分打开 Git 面板
  2. 选择分支名称旁的分支下拉菜单
  3. 创建新分支或选择现有分支
</Accordion>

Git 面板可简化多版本代码的管理：

* **创建分支**：创建新分支，分别开发功能
* **切换分支**：在不同版本的代码之间切换
* **发布分支**：将分支共享到你的 Git 身份提供方
* **拉取更改**：同步协作者的远程更新

<div id="merge-conflict-resolution">
  ### 解决合并冲突
</div>

<Accordion title="如何解决合并冲突">
  1. 发生冲突时，尝试拉取更改
  2. Git 面板会突出显示存在冲突的文件
  3. 打开每个冲突文件，查看并解决冲突
  4. 解决冲突后保存文件
  5. 选择 **拉取** 完成合并
</Accordion>

当来自不同来源的代码发生冲突时，Git 面板可帮助你：

* **识别冲突**：准确查看哪些文件存在冲突
* **查看差异**：比较冲突代码的两个版本
* **解决冲突**：选择要保留的代码，或手动编辑冲突内容
* **完成合并**：解决冲突后完成合并流程

解决冲突文件后，删除以冲突符号开头的行即可移除冲突标记，然后保存文件。

<div id="using-git-commands-in-shell">
  ### 在 Shell 中使用 Git 命令
</div>

<Accordion title="如何打开 Shell">
  1. 在左侧工具停靠栏中选择 **所有工具**
  2. 在可用工具中选择 **Shell**
</Accordion>

<Tip>
  Git 面板提供了易用的图形界面，而高级用户也可以在 Shell 中使用标准 Git 命令执行更复杂的操作。无论通过哪种方式进行更改，都会同步显示在两处。
</Tip>

如果您更喜欢通过命令行使用 Git：

* **命令同步**：在 Shell 中执行的任何 Git 命令都会自动同步到 Git 面板
* **完整 Git 功能**：使用 Git 面板中未提供的高级 Git 功能
* **无缝切换**：可根据需要在 Shell 命令和 Git 面板之间切换

<Info>
  **GitHub 和 GitLab CLI 支持**：除标准 Git 命令外，您还可以在 Shell 中使用 [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) 和 [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) 管理和连接外部 Git 仓库。这些工具增强了您使用 GitHub 和 GitLab 仓库的功能，包括处理拉取请求、议题及其他平台特有功能。
</Info>

<div id="repository-operations">
  #### 仓库操作
</div>

* **克隆仓库**：`git clone <url-to-repository>`
* **初始化仓库**：`git init`
* **添加远程仓库**：`git remote add origin <url-to-repository>`

<div id="making-changes">
  #### 进行更改
</div>

* **查看状态**：`git status` (显示已修改、已添加和已删除的文件) 
* **暂存文件**：`git add <filename>` 或 `git add .` (暂存所有文件) 
* **提交更改**：`git commit -m "your commit message"`
* **推送更改**：`git push origin <branch-name>`
* **拉取更改**：`git pull origin <branch-name>`

<div id="authentication">
  #### 身份验证
</div>

使用私有仓库时，需要进行身份验证：

* 对于 GitHub.com 仓库，请使用个人访问令牌，而非密码
* 为避免重复输入凭据，您可以使用 Replit Secrets 存储凭据：
  1. 创建一个键为 `GIT_URL` 的新 Secret
  2. 将其值设为 `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. 使用 `git push $GIT_URL` 推送，无需输入凭据

<Note>
  使用凭据 Secret 时，任何有权访问您的 Replit App 的人都可能获取您的 Git 凭据。对于敏感仓库，建议每次手动输入凭据。
</Note>
