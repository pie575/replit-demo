<Info>
  Коннектор для Snowflake доступен только на плане **Enterprise**.
</Info>

Warehouse Connectors позволяют Replit Agent обращаться с запросами к хранилищам данных вашей организации. С помощью коннектора для Snowflake разработчики могут создавать дашборды, инструменты отчётности и приложения для работы с данными на естественном языке — знание SQL не требуется.

Настройка выполняется один раз и требует участия администратора Snowflake и администратора workspace в Replit. После этого любой участник организации может войти и начать создавать приложения на данных Snowflake.

В этом руководстве описан весь процесс настройки. В нём участвуют три роли:

1. **Администратор аккаунта Snowflake** — создаёт интеграцию OAuth в Snowflake
2. **Администратор workspace в Replit** — настраивает коннектор в Replit
3. **Разработчик** — выполняет вход и приступает к работе

<div id="create-the-oauth-integration-in-snowflake">
  ## Создание интеграции OAuth в Snowflake
</div>

Администратор учётной записи Snowflake создаёт интеграцию безопасности OAuth (OAuth Security Integration), которая позволяет Replit проходить аутентификацию в Snowflake.

<div id="prerequisites">
  ### Предварительные требования
</div>

* Роль `ACCOUNTADMIN` в Snowflake
* Доступ к выполнению SQL-запросов в рабочих листах Snowflake

<div id="run-the-setup-script">
  ### Запустите скрипт настройки
</div>

<Steps>
  <Step title="Войдите в Snowflake">
    Откройте свою учётную запись Snowflake и убедитесь, что используете роль `ACCOUNTADMIN`. Проверить это можно в выпадающем списке ролей в правом верхнем углу.
  </Step>

  <Step title="Откройте SQL-лист">
    Нажмите **Worksheets** на левой боковой панели и создайте новый лист.
  </Step>

  <Step title="Запустите скрипт создания OAuth-интеграции">
    Скопируйте и вставьте следующий SQL-скрипт, затем запустите его:

    ```sql Create OAuth integration theme={null}
    -- При необходимости удалите существующую интеграцию
    DROP INTEGRATION IF EXISTS REPLIT_OAUTH;

    -- Создайте OAuth-интеграцию для Replit
    CREATE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    <Warning>
      URI перенаправления должен быть в точности `https://replit.com/connectors/oauth/callback`. Любое другое значение приведёт к ошибке 404 при аутентификации.
    </Warning>

    <Note>
      Значение `BLOCKED_ROLES_LIST = ()` гарантирует, что ни для одной роли не будет заблокировано использование интеграции. Без этого при подключении могут возникнуть ошибки «invalid consent request» или «role blocked».
    </Note>
  </Step>

  <Step title="Получите учётные данные OAuth">
    Выполните этот запрос, чтобы получить Client ID и Client Secret:

    ```sql Get OAuth credentials theme={null}
    -- Просмотрите сведения об интеграции
    DESCRIBE INTEGRATION REPLIT_OAUTH;

    -- Получите Client ID и Secret
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```

    Скопируйте **Client ID** и **Client Secret** из результата запроса. Они понадобятся на следующем шаге.
  </Step>
</Steps>

<div id="configure-the-connector-in-replit">
  ## Настройка коннектора в Replit
</div>

Администратор Replit Workspace добавляет учётные данные Snowflake в Replit. После настройки войти сможет любой участник организации.

<Note>
  Для этого шага требуется план Enterprise с правами администратора.
</Note>

<Steps>
  <Step title="Откройте раздел Integrations">
    Перейдите в настройки организации и откройте вкладку **Integrations**.
  </Step>

  <Step title="Добавьте коннектор Snowflake">
    Нажмите **Add New Connector** и выберите **Snowflake**.
  </Step>

  <Step title="Введите учётные данные">
    Укажите **Client ID** и **Client Secret**, полученные на предыдущем шаге.
  </Step>

  <Step title="Задайте область доступа">
    Установите для коннектора область доступа `refresh_token`.

    <Warning>
      Используйте только область доступа `refresh_token`. Другие области, например `session:role-any` или `session:role:PUBLIC`, могут привести к ошибке «invalid scope».
    </Warning>
  </Step>

  <Step title="Сохраните">
    Нажмите **Save**, чтобы включить коннектор.
  </Step>
</Steps>

<div id="sign-in-to-snowflake">
  ## Вход в Snowflake
</div>

Войти может любой участник организации, у которого есть доступ к коннектору. Сначала выполните вход на странице **Integrations**, чтобы проверить подключение, прежде чем использовать его с Agent.

<Steps>
  <Step title="Найдите коннектор Snowflake">
    Перейдите в раздел **Integrations** в Replit. В блоке **Connectors** найдите **Snowflake**.
  </Step>

  <Step title="Нажмите Sign In">
    Нажмите **Sign In** у коннектора Snowflake.
  </Step>

  <Step title="Введите свой Snowflake Account ID">
    В окне OAuth потребуется указать ваш Snowflake Account ID.

    Чтобы узнать Account ID, посмотрите на URL вашего Snowflake:

    ```
    https://app.snowflake.com/myorg/myaccount
    ```

    Возьмите две части после `app.snowflake.com/` и соедините их дефисом:

    ```
    myorg-myaccount
    ```

    <Note>
      В URL эти две части разделены символом `/`, а в Account ID вместо него используется `-`.
    </Note>
  </Step>

  <Step title="Пройдите аутентификацию">
    Snowflake перенаправит вас на страницу входа. Введите свои учётные данные Snowflake, чтобы завершить процесс OAuth.
  </Step>
</Steps>

<div id="start-building-with-your-snowflake-data">
  ## Начните создавать приложения на основе данных Snowflake
</div>

После подключения коннектор Snowflake можно использовать с Agent двумя способами:

* **Слэш-команда** — введите `/snowflake` в промпте, чтобы обратиться к коннектору
* **Естественный язык** — просто попросите Agent использовать ваши данные из Snowflake

Пример промпта:

```
Создай мне дашборд на основе моих данных из Snowflake. Покажи общую выручку
по регионам в виде столбчатой диаграммы, линию тренда по кварталам и таблицу
с 10 крупнейшими клиентами. Тёмная тема, аккуратный и современный вид.
```

Agent пишет и выполняет SQL-запросы к вашим данным в Snowflake и создаёт работающее приложение.

<div id="troubleshooting">
  ## Устранение неполадок
</div>

<AccordionGroup>
  <Accordion title="Ошибка «Invalid consent request» или заблокированная роль">
    В вашей интеграции Snowflake роли могут быть заблокированы по умолчанию.

    Убедитесь, что интеграция создана с параметром `BLOCKED_ROLES_LIST = ()`. Если вы уже создали её без этой настройки, выполните:

    ```sql Fix blocked roles theme={null}
    CREATE OR REPLACE SECURITY INTEGRATION REPLIT_OAUTH
      TYPE = OAUTH
      ENABLED = TRUE
      OAUTH_CLIENT = CUSTOM
      OAUTH_CLIENT_TYPE = 'CONFIDENTIAL'
      OAUTH_REDIRECT_URI = 'https://replit.com/connectors/oauth/callback'
      OAUTH_ISSUE_REFRESH_TOKENS = TRUE
      OAUTH_REFRESH_TOKEN_VALIDITY = 7776000
      OAUTH_ALLOW_NON_TLS_REDIRECT_URI = FALSE
      BLOCKED_ROLES_LIST = ()
      COMMENT = 'OAuth integration for Replit connector';
    ```

    Если ошибка повторяется, проверьте, что ваша роль по умолчанию не заблокирована:

    ```sql Set default role theme={null}
    ALTER USER "YOUR_USERNAME" SET DEFAULT_ROLE = 'PUBLIC';
    ```
  </Accordion>

  <Accordion title="Ошибка 404 при аутентификации">
    Убедитесь, что URI перенаправления в интеграции Snowflake указан в точности так:

    ```
    https://replit.com/connectors/oauth/callback
    ```

    Любое несовпадение приводит к ошибке 404 в процессе OAuth.
  </Accordion>

  <Accordion title="Ошибка «Invalid scope»">
    Убедитесь, что для коннектора в Replit указана только область `refresh_token`. Удалите все остальные области, например `session:role-any` или `session:role:PUBLIC`.
  </Accordion>

  <Accordion title="Ошибка «Failed to connect»">
    Убедитесь, что Client ID и Client Secret в Replit совпадают с теми, которые сгенерировал Snowflake. Проверить их можно так:

    ```sql Verify credentials theme={null}
    WITH secrets AS (
      SELECT PARSE_JSON(
        SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('REPLIT_OAUTH')
      ) as creds
    )
    SELECT
      creds:OAUTH_CLIENT_ID::STRING as CLIENT_ID,
      creds:OAUTH_CLIENT_SECRET::STRING as CLIENT_SECRET
    FROM secrets;
    ```
  </Accordion>
</AccordionGroup>
