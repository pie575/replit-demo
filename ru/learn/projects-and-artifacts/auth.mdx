Auth — сокращение от **аутентификации** — позволяет вашему приложению работать с &quot;пользователями&quot;. Без аутентификации каждый посетитель остаётся анонимным, и ваше приложение не может отличить одного человека от другого. С аутентификацией каждый посетитель входит в систему, приложение знает, кто он, а вы можете сохранять данные, относящиеся именно к нему: бронирования, сохранённые автомобили, предпочтения, прогресс.

После настройки аутентификации вы сможете:

* Сохранять данные для каждого пользователя — бронирования, настройки, контент, историю.
* Ограничивать доступ к функциям входом в систему (оформление покупки, страница профиля, панель администратора).
* Персонализировать интерфейс по имени, роли, тарифу или предыдущим действиям.
* Отслеживать активность и использование по отдельным пользователям, а не по сеансам.

<div id="how-auth-works-in-a-replit-app">
  ## Как работает аутентификация в App Replit
</div>

Replit предлагает два встроенных варианта аутентификации. Оба подключаются через Agent — не нужно отдельно регистрироваться в дашборде или копировать и вставлять ключи OAuth.

* **[Replit Auth](/ru/features/auth-and-identity/authentication)** — ваши пользователи входят в систему с помощью своих существующих **учётных записей Replit**. Страница входа оформлена в стиле Replit. Никакой дополнительной настройки не требуется: просто попросите Agent добавить её.
* **[Clerk Auth](/ru/features/auth-and-identity/clerk-auth)** — ваше приложение получает собственный выделенный **тенант Clerk**. Пользователи создают аккаунты внутри *вашего* приложения, а не в Replit. Вы управляете оформлением, способами входа и внешним видом экрана входа.

Оба варианта берут на себя всю сложную работу — страницы входа, сеансы, безопасную обработку паролей, вход через социальные сети, — поэтому коду вашего приложения достаточно спросить: «Кто вошёл в систему?»

<div id="replit-auth-vs-clerk-auth">
  ## Replit Auth и Clerk Auth: сравнение
</div>

|                                  | Replit Auth                                                                      | Clerk Auth                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **Учётные записи пользователей** | Пользователи входят с помощью учётной записи Replit                              | Пользователи создают учётные записи в вашем приложении (учётная запись Replit не требуется) |
| **Брендинг**                     | Страница входа в стиле Replit                                                    | Полностью настраиваемая — название, иконка и цвета вашего приложения                        |
| **Учётные данные SSO**           | Использует общие OAuth-приложения Replit                                         | Используйте собственные учётные данные OAuth для каждого провайдера                         |
| **Среды**                        | Одна среда                                                                       | Отдельные среды разработки и продакшена                                                     |
| **Лучше всего подходит для**     | Быстрой настройки, прототипов и приложений, для которых приемлем брендинг Replit | Брендированных приложений, профессиональных и коммерческих продуктов                        |

Если вы создаёте прототип или внутренний инструмент, Replit Auth — самый быстрый вариант. Если вы создаёте продукт с собственным фирменным стилем, особенно для клиентов или в коммерческих целях, лучше подойдёт Clerk Auth.

<div id="add-auth-to-your-app">
  ## Добавьте аутентификацию в своё приложение
</div>

Необязательно выбирать заранее — можно начать с одного варианта, а позже перейти на другой. Быстрее всего — указать Agent, какой вариант использовать:

* *&quot;Добавь вход в моё приложение. Используй Replit Auth.&quot;*
* *&quot;Добавь вход в моё приложение. Используй Clerk Auth.&quot;*
