Replit sauvegarde automatiquement votre dépôt Git afin de vous aider à vous remettre d&#39;incidents tels qu&#39;un dossier `.git` corrompu ou un historique de commits perdu. Ce système de sauvegarde s&#39;exécute en arrière-plan : votre travail est donc protégé sans aucun effort supplémentaire de votre part.

<div id="how-it-works">
  ## Fonctionnement
</div>

Chaque Replit App conserve une sauvegarde sécurisée de votre dépôt Git. Lorsque Replit Agent modifie le code ou que vous publiez votre application, ces modifications sont automatiquement synchronisées avec cette sauvegarde. Si votre dépôt Git local est corrompu ou inutilisable, vous pouvez restaurer l’intégralité de votre historique de commits à partir de la sauvegarde.

<Info>
  Le dépôt distant de sauvegarde s’appelle `gitsafe-backup` et est géré automatiquement par Replit. Vous n’avez rien à configurer : il fonctionne déjà en arrière-plan.
</Info>

<div id="viewing-your-backup-history">
  ## Consulter l&#39;historique de vos sauvegardes
</div>

Le moyen le plus simple de consulter l&#39;historique de vos commits est le [Git Pane](/fr/features/workspace-tools/git-interface). Ouvrez-le depuis la section Tools du Project Editor : il affiche l&#39;intégralité de votre historique de commits, y compris tous les checkpoints d&#39;Agent. Cette méthode suffit dans la plupart des cas et ne nécessite aucune commande.

Si vous devez inspecter directement le dépôt distant gitsafe-backup, vous pouvez utiliser le Shell :

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

Vous voyez ainsi l&#39;historique complet de vos commits, y compris tous les checkpoints d&#39;Agent et les commits manuels. Cela vous permet de vérifier que votre travail est bien sauvegardé ou de retrouver un commit précis à restaurer.

<div id="recovering-from-git-issues">
  ## Résoudre les problèmes Git
</div>

Si vous rencontrez des erreurs Git ou si votre dépôt est corrompu, commencez par le [Git Pane](/fr/features/workspace-tools/git-interface). Il permet de résoudre la plupart des problèmes courants — comme revenir à un commit précédent ou récupérer les modifications d&#39;un dépôt distant — sans passer par des commandes Shell.

Lorsque le Git Pane ne suffit pas (par exemple si le dossier `.git` est entièrement corrompu), suivez les étapes ci-dessous depuis le Shell.

<div id="check-if-backup-is-available">
  ### Vérifier si une sauvegarde est disponible
</div>

Commencez par vérifier que le dépôt distant de sauvegarde existe :

```bash theme={null}
git remote -v
```

Recherchez `gitsafe-backup` dans la sortie. S&#39;il est présent, vous pouvez procéder à la récupération.

<div id="restore-your-repository">
  ### Restaurer votre dépôt
</div>

<Warning>
  Ce processus remplace votre dossier `.git` actuel par la version sauvegardée. Vos fichiers de travail restent inchangés, mais votre historique Git local est remplacé par celui de la sauvegarde.
</Warning>

<Steps>
  <Step title="Sauvegarder votre configuration Git actuelle">
    Sauvegardez votre fichier de configuration Git au cas où vous auriez des paramètres personnalisés :

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Cloner le dépôt de sauvegarde">
    Créez un clone temporaire à partir de la sauvegarde :

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Remplacer votre dossier Git">
    Mettez de côté votre dossier `.git` corrompu et remplacez-le par celui de la sauvegarde :

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Restaurer votre configuration">
    Restaurez votre configuration Git :

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

Après avoir suivi ces étapes, exécutez `git status` pour vérifier que votre dépôt fonctionne correctement.

<div id="troubleshooting-common-issues">
  ## Résolution des problèmes courants
</div>

<div id="fatal-repository-not-found-or-backup-remote-missing">
  ### « fatal: repository not found » ou dépôt distant de sauvegarde manquant
</div>

Le système de sauvegarde n&#39;est peut-être pas activé pour les projets plus anciens. Contactez le support si vous avez besoin d&#39;aide pour récupérer un ancien projet.

<div id="recovery-didnt-include-recent-commits">
  ### La récupération n&#39;inclut pas les commits récents
</div>

Les sauvegardes se synchronisent après chaque commit d&#39;Agent. Si vous avez effectué des modifications sans les commiter, elles ne figureront pas dans la sauvegarde. Vérifiez votre répertoire de travail pour repérer d&#39;éventuels fichiers non commités.

<div id="git-operations-are-slow-or-hanging">
  ### Les opérations Git sont lentes ou bloquées
</div>

Si les opérations Git ne répondent plus, un fichier de verrouillage obsolète est peut-être en cause. Vous pouvez le supprimer sans risque :

```bash theme={null}
rm -f .git/index.lock
```

<div id="preventing-data-loss">
  ## Prévenir la perte de données
</div>

Le système de sauvegarde protège automatiquement votre historique Git, mais vous pouvez prendre des mesures supplémentaires pour protéger votre travail :

* **Committez fréquemment** : effectuez des commits petits et fréquents afin que votre progression soit sauvegardée en continu
* **Utilisez les checkpoints** : lorsque vous travaillez avec [Replit Agent](/fr/features/agent/overview), les checkpoints créent automatiquement des commits aux étapes clés
* **Connectez-vous à GitHub** : pour les projets critiques, [connectez votre app à GitHub](/fr/build/import-from-providers) afin de bénéficier d&#39;un niveau de sauvegarde supplémentaire
