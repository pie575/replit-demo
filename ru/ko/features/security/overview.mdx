После публикации на Replit ваш проект начинает получать реальный трафик. Инструменты безопасности Replit помогают находить уязвимости, устранять с помощью Agent подтверждённые проблемы и сохранять доказательства, необходимые для аудита.

<div id="section">
  ## Почему безопасность важна
</div>

* Опубликованные проекты доступны из интернета, включая публичные маршруты и API.
* Современные проекты зависят от множества пакетов, и новые CVE могут появиться уже после публикации.
* Код, сгенерированный ИИ, тоже нуждается в проверке безопасности — особенно в части аутентификации, запросов к базе данных, секретов и обработки данных.
* Программы соответствия требованиям нередко требуют документального подтверждения: инвентаризации зависимостей, отслеживания уязвимостей и принятых мер по их устранению.

<div id="section-2">
  ## С чего начать
</div>

* Устанавливаете пакеты? [Package Firewall](/ru/ko/features/security/package-firewall) блокирует вредоносные зависимости прямо при установке и включён по умолчанию.
* Работаете над одним проектом? Используйте [Project Security Center](/ru/ko/features/security/project-security-center).
* Проводите аудит всего рабочего пространства? Используйте [Workspace Security Center](/ru/ko/features/security/workspace-security-center).
* Нужно выбрать, где будут работать ресурсы разработки? Прочитайте статью [Регион рабочего пространства](/ru/ko/features/collaboration/workspace-geography). А чтобы выбрать, где будет работать опубликованный проект, — [Регион проекта](/ru/ko/features/publishing/project-geography).
* Нужны определения терминов? Прочитайте [Концепции безопасности](/ru/ko/features/security/concepts).

Инструменты безопасности Replit защищают приложение на разных этапах его жизненного цикла и дополняют друг друга.

* **При установке**: [Package Firewall](/ru/ko/features/security/package-firewall) блокирует вредоносные и скомпрометированные пакеты ещё до их загрузки.
* **После установки**: [автоматическое сканирование зависимостей](/ru/ko/features/security/project-security-center#automatic-dependency-scans) выявляет недавно опубликованные CVE, а Auto-Protect может подготовить исправление силами Agent.
* **Перед публикацией**: [Security Agent](/ru/ko/features/security/agent-security-scans) проверяет кодовую базу и находит уязвимости в коде, зависимостях и обработке персональных данных.

Большинство сканирований построено по одному и тому же принципу: сканирование, изучение результатов, исправление с помощью Agent, повторная публикация и, при необходимости, экспорт доказательств.

<div id="section-3">
  ## Место безопасности в продукте
</div>

<div id="section-4">
  ### Внутри проекта
</div>

Откройте панель **Security**, чтобы просмотреть найденные проблемы на уровне проекта, запустить сканирование безопасности Agent и проверить уязвимости зависимостей перед публикацией.

Используйте [сканирование безопасности Agent](/ru/ko/features/security/agent-security-scans) для проверки исходного кода. Если нужно протестировать работающее приложение ещё и снаружи, воспользуйтесь [тестированием на проникновение методом чёрного ящика Level 3](/ru/ko/features/security/black-box-pen-tests).

<div id="section-5">
  ### Внутри рабочего пространства
</div>

Выберите **Security** в боковой панели главной страницы, чтобы просмотреть уязвимости по всем проектам, расставить приоритеты найденных проблем в зависимости от степени их доступности извне и отслеживать историю сканирований на уровне рабочего пространства.

<div id="section-6">
  ### В Publishing и настройках
</div>

* В разделе **Publish** &gt; **Advanced** включите параметр **Block publishing of critical vulnerabilities**, чтобы критические уязвимости не попадали в деплой.
* В разделе **Settings** &gt; **Account** &gt; **Advanced** задайте порог критичности для Auto-Protect, по которому Agent готовит исправления уязвимостей в зависимостях.
