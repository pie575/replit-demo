[Project Security Center](/ko/features/security/project-security-center)와 [Workspace Security Center](/ko/features/security/workspace-security-center)에서 사용되는 보안 용어의 정의입니다.

<div id="cve">
  ## CVE
</div>

Common Vulnerabilities and Exposures(공통 취약점 및 노출). CVE는 공개적으로 공표된 소프트웨어 취약점에 부여되는 `CVE-2024-12345`와 같은 고유 식별자입니다.

<div id="severity">
  ## Severity
</div>

취약점의 위험 등급으로 critical, high, medium, low 중 하나입니다. severity와 exposure를 함께 고려해 어떤 프로젝트를 먼저 수정할지 결정하세요.

<div id="dependency">
  ## Dependency
</div>

project가 의존하는 서드파티 패키지입니다. dependency의 취약점은 해당 dependency가 업데이트되거나 교체될 때까지 이를 사용하는 모든 project에 영향을 미칩니다.

<div id="sbom">
  ## SBOM
</div>

소프트웨어 자재 명세서(Software Bill of Materials). SBOM은 project에 포함된 패키지, 버전, 라이선스를 기계가 읽을 수 있는 형태로 정리한 목록입니다.

<div id="spdx-and-cyclonedx">
  ## SPDX 및 CycloneDX
</div>

보안 및 컴플라이언스 도구에서 사용하는 표준 SBOM 형식입니다. 사용 중인 audit, 컴플라이언스 또는 소프트웨어 구성 분석 도구가 요구하는 형식을 선택하세요.

<div id="exposure">
  ## Exposure
</div>

게시 상태와 공개 범위에 따라 발생하는 위험 노출면입니다. 공개로 게시된 project는 비공개이거나 게시되지 않은 project보다 exposure가 높습니다.

<div id="fix-with-agent">
  ## Fix with Agent
</div>

영향을 받은 project의 패치를 백그라운드 task로 작성하도록 Replit Agent에 요청하는 작업입니다. 생성된 변경 사항은 적용하기 전에 검토하세요.

<div id="republish">
  ## Republish
</div>

기존 deployment 구성을 사용해 project를 다시 배포합니다. 수정 사항을 적용한 후 패치된 버전을 release하려면 **Republish**를 사용하세요.

<div id="package-firewall">
  ## Package Firewall
</div>

악성 패키지나 침해된 패키지가 앱에 다운로드되기 전, 설치 시점에 차단하는 네트워크 수준의 보호 기능입니다. 기본으로 활성화되어 있으며 Socket을 기반으로 동작합니다. 자세한 내용은 [Package Firewall](/ko/features/security/package-firewall)을 참고하세요.

<div id="auto-protect">
  ## Auto-Protect
</div>

Replit이 여러분의 앱에 자동으로 적용하는 보호 기능을 아우르는 체계입니다. 모든 builder에게 기본으로 활성화되는 보호 기능으로는 설치 시점 차단을 수행하는 [Package Firewall](/ko/features/security/package-firewall), 웹 애플리케이션 방화벽(WAF), 자동 SSL/TLS 암호화가 있습니다. Admin은 자동 CVE remediation에 추가로 opt in할 수 있으며, 이 경우 Replit Agent가 새로 공개된 dependency 취약점에 대한 패치를 준비하고 project 소유자에게 알립니다. [Auto-Protect](/ko/features/security/project-security-center#auto-protect)를 참조하세요.
