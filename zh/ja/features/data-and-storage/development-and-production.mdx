description: "介绍应用的两个数据库：用于构建阶段的开发数据库，以及支撑已发布应用的生产数据库。"

每个 Replit App 都使用两个数据库。**开发数据库**供你和 Agent 在构建过程中自由试验。**生产数据库**则存储驱动已发布应用的真实数据，让你在持续构建的同时，真实数据始终安全无虞。

  <img src="/assets/mirror/production-databases-fed331a9f523.jpg" alt="生产数据库管理界面" width="1080" height="471" data-path="images/databases/production-databases.jpg" />
</Frame>

<div id="section">
  ## 比较
</div>

| 方面        | 开发数据库                | 生产数据库             |
| --------- | -------------------- | ----------------- |
| **用途**    | 实验与功能开发              | 面向真实用户提供服务并存储业务数据 |
| **数据**    | 测试数据、虚拟记录、小规模数据集     | 真实用户数据、业务关键信息     |
| **创建**    | 每个 Replit App 都会自动创建 | 发布应用时创建           |
| **Agent** | Agent 可以创建和修改表       | Agent 无法访问        |
| **变更**    | 频繁的架构变更、快速迭代         | 谨慎且有计划的变更，在发布时生效  |
| **计费**    | 每个 Replit App 免费包含   | 按使用量计费            |

<Note>
  Agent 无法修改生产数据库，此限制旨在保障生产数据库的安全。

  Agent 可以编辑开发数据库。发布时，Agent 对开发数据库结构所做的更改 (添加或删除列和表) 会同步应用到生产数据库。

  你可以随时手动编辑生产数据：打开 **Database** 工具，选择生产数据库并打开 **My Data**，然后开启 **Edit**。
</Note>

<div id="section-2">
  ## 发布时创建生产数据库
</div>

已发布的应用会拥有专属的生产数据库，与构建过程中使用的开发数据库相互独立。

* **当前基础设施 (Helium)&#x20;**：Replit 会在发布时按需创建生产数据库，无需任何额外设置。
* **旧版 Neon 开发数据库**：需在发布设置中创建生产数据库。发布过程中打开 **Production database settings**，并启用 **Create production database**。如有需要，还可启用 **Set up your production database with your current development data**，将当前的开发数据复制过去。

<Frame caption="Publishing 中的 Production database settings">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="显示 Create production database 选项的发布设置" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  只有确认开发数据可以安全地用于线上应用时，才将其复制到生产环境。开发数据中可能包含测试账户、示例记录或不完整的内容。
</Warning>

发布后，已发布的应用将使用生产数据库，而 Project Editor 仍继续使用开发数据库，因此后续开发中的改动不会直接影响线上数据。

<div id="section-3">
  ## 连接池
</div>

默认情况下，生产数据库未启用连接池。应用会使用 `DATABASE_URL` 连接字符串直接连接数据库，因此大多数框架需要自行管理客户端连接池。

<Note>
  每个 Neon 项目都包含直连字符串和连接池字符串。直连字符串的格式类似于 `postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`。

  如需通过连接池连接，请在主机名后添加 `-pooler`：`postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`。
</Note>

如果生产连接字符串泄露，请[重新生成生产数据库凭据](/zh/ja/features/data-and-storage/connection-details#regenerate-production-database-credentials)。

<div id="section-4">
  ## 安全地变更生产数据库
</div>

发布包含数据库变更的更新时，某些变更需要谨慎规划，以免造成停机或数据丢失。

<Info>
  发布过程中，已发布的应用可能出现短暂停机。应用数据库变更时，为避免冲突并保护数据，可能需要临时停止应用。
</Info>

以下类型的变更通常需要特别注意：

* 删除应用代码仍在引用的**数据库列**
* 以现有代码无法处理的方式**更改列的数据类型**
* 在没有默认值的情况下向现有表**添加必填字段**
* **重命名表或列**，导致现有查询失效
* **修改约束**，可能导致现有应用逻辑被拒绝

<div id="section-5">
  ### 在部署预览中测试更改
</div>

部署预览是生产环境的临时隔离副本，可让你在影响真实用户之前测试数据库变更和应用更新。它可用于：

* 确认应用数据库变更后，应用在各关键用户流程中仍能正常运行
* 确认现有数据已正确迁移，且新字段包含预期值
* 检查查询响应时间是否出现性能下降

<div id="section-6">
  ## 计费与资源用量
</div>

生产数据库通过无服务器数据库提供商 Neon 按使用量计费。数据库闲置 5 分钟后会进入空闲状态，计算时长计费随之暂停；一旦收到查询，会立即重新启动。

Database 工具的着陆视图会显示 **Billing Period** (计费周期) 和 **Hours of Compute Used** (已用计算小时数) 。要查看单个数据库的存储用量，请打开该数据库的 **Settings** 标签页。要查看所有 Replit App 的总体使用情况，请依次打开 **Settings** → **Account** → **Account usage**，然后展开 **PostgreSQL Storage** 和 **PostgreSQL Compute** 两行。

有关 Replit 如何对数据库用量计费，请参阅[部署与数据库计费](/zh/ja/billing/about-usage-based-billing#databases)。

<div id="section-7">
  ## 删除生产数据库
</div>

<Warning>
  删除操作在 7 天保留期结束后将无法撤销。继续操作前，请务必备份重要数据。数据库有 7 天的软删除期，在此期间仍可恢复数据库。如需协助，请联系我们。超过 7 天后，数据库将被永久删除，且无法恢复。
</Warning>

<Accordion title="如何删除数据库">
  在 **Database** 工具中：

  1. 选择数据库，然后打开 **Settings** 选项卡
  2. 选择 **Remove database**，再选择 **Yes, Remove database** 进行确认
</Accordion>

<div id="section-8">
  ## 旧版开发数据库
</div>

在 2025 年 12 月 4 日之前，开发数据库托管在 <a href="https://neon.com/" target="_blank">Neon</a> 上。所有新建的开发数据库均托管在 Replit 自有基础设施 (Helium) 上。你可以在 **Settings** 标签页中查看应用使用的是哪一种：如果 `DATABASE_URL` 中包含 `neon.tech`，则为旧版 Neon；若包含 `helium`，则为当前的基础设施。

| **功能**    | **Replit (当前)&#x20;**&#x20;                                                            | **Neon (旧版)&#x20;**&#x20;                                                    |
| --------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **托管**    | 托管在 Replit 自有基础设施上                                                                | 托管在 Neon (第三方提供商) 上                                                     |
| **计费**    | 所有 Replit App 均免费包含                                                               | 按用量计费。详情请参阅[发布与数据库计费](/zh/ja/billing/about-usage-based-billing#databases)。 |
| **恢复功能**  | 可使用[回滚功能](/zh/ja/features/data-and-storage/data-recovery)将数据库恢复到任意检查点                | 时间点恢复 (PITR) ：可恢复到备份保留期内的任意时间点。                                         |
| **连接安全性** | 仅可从应用内部访问，不会对外公开。                                                                 | 使用完整的连接字符串。一旦泄露，任何人都可以访问并修改数据库。                                         |
| **重混行为**  | [重混](/zh/ja/features/projects-and-artifacts/remix-an-app)会创建一个已复制数据的新开发数据库，以实现隔离与安全。 | 重混时所有副本共用同一个数据库，因此在重混中所做的更改可能影响原始应用。                                    |
| **数据库创建** | 为每个 Replit App 自动创建。                                                              | 需要显式配置。                                                                 |
| **发布工作流** | 发布时会创建独立的生产数据库，实现环境之间的隔离。                                                         | 开发与生产共用同一个数据库，因此无意的开发改动可能会影响生产应用。                                       |

<div id="section-9">
  ## 数据库基础设施升级
</div>

Replit 正在将开发数据库从 Neon 升级到 **Helium**——Replit 自研的托管式 PostgreSQL 基础设施。此次升级会自动进行，每个应用在 Project Editor 中打开时执行一次，所有数据都会完整保留。

变更内容：

* **更低延迟、更大存储空间**：数据库将与应用运行在同一套 Replit 基础设施上，存储上限从 10GB 提升至 20GB。
* **数据库引擎不变**：Helium 使用与 Neon 相同版本的 PostgreSQL 16，查询、模式和数据的行为均保持不变。
* **连接信息自动更新**：`DATABASE_URL` 将更新为指向 Helium。原有的 Neon 连接字符串会以 `NEON_DATABASE_URL` 的形式保存在 Secrets 中，供参考使用。
* **移除单独的 PG 变量**：`PGHOST`、`PGPORT`、`PGUSER`、`PGPASSWORD` 将被移除，请改用 `DATABASE_URL`。

升级过程中会显示 **“Upgrading your database”** 进度界面。耗时从几分钟到数小时不等，数据库越大耗时越久。你可以关闭标签页，稍后再回来查看。如果升级过程中出现问题，系统会自动跳过，并在下次打开应用时重试。完成后会弹出确认对话框。

对大多数构建者而言，升级后无需做任何特殊处理。但如果符合以下情况，请注意检查：

* **硬编码的 Neon 连接字符串**：请将代码中引用 `neon.tech` 连接字符串的部分改为使用 `DATABASE_URL` 环境变量。
* **自定义 PostgreSQL 角色**：角色和权限会自动迁移，但角色密码无法一并复制，请在新数据库中重置自定义角色的密码。

<div id="ssl">
  ### 升级后出现 SSL 连接错误
</div>

如果出现类似 `The server does not support SSL connections` 的错误，说明连接代码强制要求进行 SSL 握手。Neon 要求必须使用 SSL，而 Helium 与应用一同在本地运行，因此不使用 SSL。请根据运行环境有条件地设置 SSL：

<CodeGroup>
  ```js JavaScript theme={null}
  // 修改前（升级后将无法正常工作）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // 修改后（开发与生产环境均可正常工作）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  如果你使用 Drizzle、Prisma、Sequelize 等 ORM，请查阅其文档，了解如何按条件配置 SSL。原则是一样的：在开发数据库上禁用 SSL，在生产环境中启用。
</Tip>

<div id="section-10">
  ### 曾共享数据库的分叉应用
</div>

在旧版 Neon 系统中，分叉应用会复制原应用的 `DATABASE_URL`，导致两个应用及其已发布版本连接到同一个数据库。这些共享的旧版数据库已于 **2026 年 6 月 8 日**停止运行。如果你发布的应用无法正常运行，或者无法访问数据，请参阅[修复使用共享数据库的已发布应用](/zh/ja/features/data-and-storage/shared-database-migration)，或[联系支持团队](https://replit.com/support)。
