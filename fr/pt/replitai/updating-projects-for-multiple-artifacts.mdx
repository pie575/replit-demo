---
title: "Mettre à jour d’anciens projets pour prendre en charge plusieurs artefacts"
description: "Ajoutez un deuxième artefact à un ancien projet Replit grâce à une mise à jour unique de sa structure qui préserve son URL, ses données et son déploiement."
---

Si votre projet a été créé avant le 11 mars 2026, Agent devra peut-être effectuer une mise à jour unique de sa structure avant de pouvoir y ajouter un deuxième artefact. Cette page explique pourquoi, ce qui change et quels projets sont éligibles.

<div id="contexto">
  ## Contexte
</div>

Le **11 mars 2026**, Replit a lancé [Agent 4](/fr/pt/updates/2026/03/13/changelog). L’un des principaux changements de cette version est la **prise en charge de plusieurs artefacts** : un seul [projet](/fr/pt/replitai/projects) peut désormais contenir plusieurs [artefacts](/fr/pt/replitai/artifacts) (par exemple, une application web, une application mobile et une présentation) partageant la même base de données, le même backend, les mêmes secrets et le même déploiement.

Avant le 11 mars 2026, chaque projet était conçu autour d’une seule application, avec une structure de fichiers différente. Cette ancienne structure ne comporte pas la séparation nécessaire au backend pour héberger plusieurs artefacts. En raison de ces différences, les projets créés avant le 11 mars 2026 nécessitent une **mise à jour structurelle ponctuelle** avant qu’Agent puisse y ajouter un deuxième artefact. Les projets créés à partir de cette date utilisent déjà la nouvelle structure et n’ont pas besoin de cette étape.

<div id="o-que-a-atualizao-faz">
  ## Ce que fait la mise à jour
</div>

Lorsque vous demandez à Agent d’ajouter un second artefact à un ancien projet (par exemple, une application mobile à une application web existante), Agent réorganise d’abord votre projet selon la nouvelle structure à plusieurs artefacts. Votre URL, vos collaborateurs, vos secrets, votre base de données et vos domaines sont tous préservés. Seule la structure interne change.

<div id="como-funciona">
  ## Fonctionnement
</div>

<Steps>
  <Step title="Demandez un nouvel artefact dans un ancien projet">
    Demandez à Agent, par exemple : « Crée une présentation pour mon site web. »
  </Step>

  <Step title="Examinez et approuvez">
    Agent s’arrête avant d’apporter la moindre modification et affiche une proposition dans le Chat. Pour un maximum de deux projets éligibles, vous bénéficierez également d’une offre unique de **crédit de $5** pour lancer la mise à jour du projet. Cliquez sur **Mettre à jour le projet** pour continuer ou sur **Pas maintenant** pour ignorer.

  <Step title="Attendez la restructuration">
    Agent réorganise votre projet selon la nouvelle structure dans le cadre d’une tâche ; vous pouvez suivre sa progression dans la liste des tâches. Votre application d’origine est sauvegardée avant toute modification afin que vous ne perdiez pas votre travail précédent en cas de problème.

<div id="elegibilidade">
  ## Éligibilité
</div>

Tous les projets ne peuvent pas être mis à jour pour le moment. Votre projet doit appartenir à l’un des types suivants :

* **Application web** (JavaScript full-stack)
* **Maquettes de conception d’application**
* **Application mobile** (Expo)

Les autres types de projets créés avant le 11 mars 2026, notamment les projets Python, Flask, Streamlit, les stacks de jeux, les projets vidéo et les stacks d’agents, ne sont pas pris en charge. Si vous avez besoin de plusieurs artefacts dans ces cas, [créez un nouveau projet](/fr/pt/replitai/projects).

Les ports et flux de travail de votre projet doivent également correspondre à la configuration par défaut de ce type de projet. Si vous avez modifié manuellement le `.replit`, le message suivant s’affichera :

> *Ce projet ne peut pas être migré automatiquement : la configuration du flux de travail ne correspond pas à celle attendue.*

Pour résoudre ce problème, rétablissez les paramètres par défaut de vos ports ou flux de travail, puis réessayez.

<div id="perguntas-frequentes">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Pourquoi mon projet doit-il être mis à jour ?">
    Les projets créés avant le 11 mars 2026 (date de lancement d’Agent 4) utilisaient une structure à application unique. La nouvelle structure de workspace partagé permet à une application web, une application mobile et un tableau de bord d’administration de coexister et de partager la même base de données et le même backend. La mise à jour est une opération unique qui permet d’adopter cette structure.
  </Accordion>

  <Accordion title="Que se passe-t-il si je ne souhaite pas effectuer la mise à jour ?">
    Cliquez sur **Pas maintenant**. Agent continue de créer des applications dans la structure existante à artefact unique. Vous pourrez revenir sur cette option ultérieurement si vos besoins évoluent.
  </Accordion>

  <Accordion title="Puis-je effectuer la mise à jour plusieurs fois ?">
    Non. Une fois votre projet passé à la nouvelle structure, aucune mise à jour supplémentaire n’est nécessaire. Les futurs artefacts sont ajoutés directement, sans autre étape de mise à jour.
  </Accordion>

  <Accordion title="Mon projet n’est pas éligible. Quelles sont mes options ?">
    Créez un projet distinct pour le nouvel artefact ou démarrez un nouveau projet prenant en charge plusieurs artefacts dès le départ.
  </Accordion>
</AccordionGroup>
