使用 Replit，你无需再担心丢失工作成果。

Replit 的检查点和回滚系统为整个开发环境提供全面的版本控制和状态管理。

使用 Replit Agent 时，检查点会自动捕获项目的完整状态。这不仅包括代码更改，还包括项目文件、与 AI 的对话上下文以及已连接的数据库。

<div id="o-que-so-checkpoints">
  ## 什么是检查点？
</div>

**检查点**是 Agent 在开发关键阶段自动创建的 Replit App 当前状态的完整快照。与仅跟踪代码变更的传统版本控制不同，Replit 检查点会保留完整的开发上下文。

您可以将检查点视为电子游戏中的存档点——随时都能回到应用的可用版本。

  <img src="/assets/mirror/agent-checkpoint-8e5b8b315c02.png" alt="显示回滚选项的 Agent 检查点界面" width="1554" height="876" data-path="images/replitai/agent-checkpoint.png" />
</Frame>

<div id="captura-de-estado-completo">
  ### 完整状态快照
</div>

每个 checkpoint 都会保存：

* **项目文件**：所有文件、目录、已安装的包和项目配置
* **与 AI 的对话上下文**：完整的对话历史记录，以及形成当前状态的上下文
* **环境配置**：运行时设置和部署设置
* **Agent 记忆**：AI 对项目架构、偏好和模式的理解
* **数据库内容**：创建 checkpoint 时数据库中的数据和架构

这种全面的保存方式让您可以放心尝试，因为您不仅可以恢复代码，还能恢复整个开发上下文。

<div id="como-funcionam-os-rollbacks">
  ## 回滚的工作原理
</div>

**回滚**功能可让你一键将 Replit App 恢复到任意之前的 checkpoint 状态。这比传统的 git revert 操作强大得多。

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="显示 checkpoint 回滚选项的界面" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

回滚经过精心设计，确保安全且可预测：

* **非破坏性预览**：部分界面允许你在回滚前预览 checkpoint 状态
* **清晰的边界**：每个 checkpoint 都代表一个合乎逻辑的开发里程碑
* **对话连续性**：AI 上下文会得到保留，因此你可以从恢复后的状态继续构建
* **即时生效**：回滚会立即在整个开发环境中生效

<div id="executar-um-rollback">
  ### 执行回滚
</div>

当你回滚到之前的检查点时，项目会恢复到该检查点时的状态，包括：

1. **完整项目状态**：所有项目文件都会恢复到所选检查点时的确切状态
2. **与 Agent 的对话上下文**：Agent 对话会恢复到检查点所在的位置，保持上下文的连续性
3. **项目配置**：依赖项、包和运行时配置
4. **开发环境**：工具和 Project Editor 配置
5. **数据库内容 (可选)&#x20;**：选中后，数据库会恢复到检查点时的状态

<Info>
  默认情况下，回滚不会更改数据库。要在回滚中包含开发数据库，请在“其他回滚选项”中选择“数据库”。

  请注意，此回滚功能不会自动恢复你的**[生产数据库](/zh/pt/features/data-and-storage/development-and-production)**。
  如需了解如何将生产数据库恢复到较早的时间点，请参阅[时间点恢复文档](/zh/pt/features/data-and-storage/development-and-production)。
</Info>

<Warning>
  使用回滚功能时，Replit App 会恢复到之前的状态。这会删除该时间点之后的所有更改，包括代码编辑。如果你选择恢复数据库，数据库中的更改也会一并回滚。
</Warning>

<div id="avanar-no-histrico">
  ### 在历史记录中前进
</div>

Replit 中的检查点支持双向导航——你可以在项目历史记录中后退，也可以前进。
这让你能够灵活地浏览开发时间线，无需担心丢失工作内容。

如果回滚过头，或者想恢复后续检查点中的更改，可以通过**前进**继续在检查点历史记录中向前浏览。这样，你就可以自由浏览项目时间线，而不会丢失工作内容。

要前进，请在 Agent 选项卡中点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史图标" width="24" height="24" data-path="images/icons/history.svg" /> 以打开历史记录视图，然后选择当前位置之后的检查点。

<Info>
  只有当时间线上当前位置之后存在检查点时，才能在历史记录中前进。回滚后进行新的更改后，这些后续检查点会成为另一条历史分支的一部分。
</Info>

这种双向导航让你可以完全掌控项目时间线，确保工作内容始终可以恢复。

<div id="criao-de-checkpoints">
  ## 创建 checkpoint
</div>

Replit 的 AI 工具会在开发过程中的关键节点自动创建 checkpoint。

<div id="checkpoints-do-agent">
  ### Agent 检查点
</div>

[Replit Agent](/zh/pt/features/agent/overview) 会在以下情况下创建检查点：

* **功能完成**：成功实现所需功能后
* **重要里程碑**：在复杂任务中取得显著进展时
* **稳定状态**：完成测试并验证所作更改后
* **错误恢复**：尝试修复关键问题前

<div id="caractersticas-dos-checkpoints">
  ### checkpoint 的特点
</div>

每个 checkpoint 包含：

* **AI 生成的描述**：清晰概述已完成的工作
* **时间戳信息**：精确的创建时间，便于识别
* **变更范围**：标明已修改的文件、功能或系统
* **计费信息**：为 Agent 提供按 checkpoint 统计的透明成本追踪

<div id="usando-checkpoints-e-rollbacks">
  ## 使用检查点和回滚
</div>

<div id="encontrar-checkpoints">
  ### 查找 checkpoints
</div>

您可以在 Project Editor 的多个位置找到 checkpoints：

**Agent 标签页**：查看 Agent 创建的所有 checkpoints，包括说明和回滚选项
**Git 面板**：以 Git 提交的形式查看 checkpoints，并享受完整的版本控制集成
**历史记录视图**：在 Agent Chat 中，点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" />，即可查看所有 checkpoints 及其进展的完整时间线

<div id="executar-rollbacks">
  ### 执行回滚
</div>

回滚流程会因启动位置不同而略有差异：

<div id="na-aba-agent">
  #### 在 Agent 选项卡中
</div>

<Steps>
  <Step title="进入 Agent">
    在 Project Editor 中打开 **Agent** 选项卡，查看 Agent 创建的所有检查点。
  </Step>

  <Step title="选择检查点">
    找到要恢复的检查点，然后选择 **Rollback to here**。
  </Step>

  <Step title="确认回滚">
    查看回滚提示并确认，将您的 App 恢复到所选状态。
  </Step>

  <Step title="验证恢复结果">
    确认项目文件、数据库和 AI 上下文是否与恢复后的检查点状态一致。
  </Step>
</Steps>

<div id="melhores-prticas">
  ### 最佳实践
</div>

**合理使用 checkpoint**：

* 每次创建重要 checkpoint 后都测试 App，确保其稳定性
* 除自动 checkpoint 外，还应在 Git 中手动创建提交，以便长期跟踪版本
* 查看 checkpoint 描述，了解具体变更内容

**回滚注意事项**：

* 执行回滚前，务必确认变更范围
* 考虑对数据库和外部集成的影响
* 将回滚情况告知协作者，确保团队成员知悉

**迭代开发**：

* 采用增量方式构建，充分利用频繁创建的 checkpoint
* 使用回滚安全地探索不同的实现方案
* 利用 AI 上下文保留功能，在回滚后继续对话

<div id="integrao-com-controle-de-verso">
  ## 与版本控制集成
</div>

检查点可与 Replit 更广泛的版本控制生态系统无缝协同工作：

<div id="integrao-com-git">
  ### Git 集成
</div>

* **生成 Git 提交**：每个 checkpoint 都会创建对应的 Git 提交
* **分支兼容性**：checkpoint 遵循分支结构和合并工作流
* **远程同步**：与 GitHub 集成可保持 checkpoint 同步
* **命令行访问**：可在使用 checkpoint 的同时使用 Git 的所有功能

<div id="recursos-de-colaborao">
  ### 协作功能
</div>

* **团队可见性**：项目的所有协作者都能查看检查点
* **避免合并冲突**：检查点的创建时机可降低发生冲突的概率
* **共享上下文**：与 AI 的对话上下文可帮助团队成员理解变更
* **实时更新**：协作者可实时看到检查点的创建

<div id="recursos-avanados">
  ## 高级功能
</div>

<div id="visualizaes-de-checkpoint">
  ### checkpoint 预览
</div>

部分界面支持 checkpoint 预览功能：

* **直观对比**：查看您的 App 在不同 checkpoint 状态下的外观
* **非破坏性探索**：无需实际回滚即可查看
* **进度跟踪**：了解您的 App 如何随时间演变
* **迭代对比**：比较不同的实现方案

<div id="rollbacks-entre-sesses">
  ### 跨会话回滚
</div>

适用于高级开发者和团队管理员：

* **扩展历史记录**：可跨多个开发会话访问 checkpoint
* **管理控制**：团队管理员可跨用户会话执行回滚
* **审计记录**：完整记录 checkpoint 的创建历史和回滚操作

<div id="casos-de-uso">
  ## 使用场景
</div>

<div id="desenvolvimento-experimental">
  ### 实验性开发
</div>

借助 checkpoints，你可以放心地进行实验：

* 尝试新功能，必要时可轻松回滚
* 测试不同的架构方案
* 探索不同的界面设计或用户流程
* 在安全保障下实施复杂集成

<div id="depurao-e-recuperao">
  ### 调试与恢复
</div>

出现问题时，checkpoint 可提供可靠的恢复能力：

* 引入 bug 后，回滚到正常运行的状态
* 通过比较不同 checkpoint 的状态来定位问题
* 数据损坏后恢复数据库完整性
* 从意外删除或修改中恢复

<div id="aprendizado-e-iterao">
  ### 学习与迭代
</div>

checkpoint 有助于开展学习型开发：

* 比较不同的实现策略
* 通过 checkpoint 的推进过程，了解 AI 的决策过程
* 通过探索功能的演变过程加深理解
* 借助回滚机制安心练习新技术
