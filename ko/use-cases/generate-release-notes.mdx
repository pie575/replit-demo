매주 GitHub과 Linear에서 변경 사항을 pull하고, 신규·개선·수정으로 분류한 고객용 릴리스 노트를 생성한 뒤 Notion에 게시하세요. 내부 전용 작업은 제외하고 breaking change로 보이는 항목에는 표시를 남기면, 제품 팀과 지원 팀, 고객이 일정한 주기로 동일한 내용을 공유할 수 있습니다.

* 고객과 동일한 내용을 공유해야 하는 제품 마케팅 및 지원 담당자.

고객에게 보내기 전에 문체를 다듬으세요. 내부 잡무처럼 보이는 항목은 빼고,
breaking change는 맨 위에 배치하세요. publish하기 전에 지난주에 merge된 pull request와 페이지 내용을 비교해 보세요.

<div id="troubleshooting">
  ## 문제 해결
</div>

* **내부 작업 항목이 릴리스 노트에 포함되는 경우:** Agent가 올바른 저장소와 Linear 팀을 참조하도록 지정하고, 고객에게 전달되지 않는 내부 작업은 제외하도록 다시 요청하세요.
* **breaking change가 눈에 띄지 않게 묻힌 경우:** &quot;breaking&quot;이 무엇을 의미하는지(login, billing, 또는 필수 migration) Agent에게 알려주고, 해당 항목에 표시를 달아 맨 위에 배치하도록 요청하세요.
* **엉뚱한 Notion 페이지에 작성되는 경우:** 정확한 페이지 또는 database 링크를 알려주고, 지난주 노트를 덮어쓸지 아니면 run마다 새 페이지를 만들지 지정하세요.
