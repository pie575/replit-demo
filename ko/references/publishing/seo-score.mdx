대부분의 빌더에게 전체 워크플로는 다음과 같습니다: 앱을 게시하고, 점수를 확인하고, 에이전트에게 "SEO 최적화"를 요청하세요. 이 페이지에서는 내부적으로 무슨 일이 일어나는지와 최대한 활용하는 방법을 설명합니다.

## SEO란 무엇이며 왜 중요한가

검색 엔진 최적화(SEO)는 Google과 같은 검색 엔진이 사이트를 찾고, 이해하고, 순위를 매길 수 있도록 사이트를 구축하는 방법입니다. 강력한 SEO는 광고 비용을 지불하지 않고도 사람들이 검색할 때 앱이 표시된다는 것을 의미합니다.

SEO 결과의 대부분을 좌우하는 몇 가지 요소가 있습니다: 명확한 페이지 제목과 설명, 시맨틱 HTML, 빠른 로드 시간, 모바일 친화적 레이아웃, 이미지의 설명적인 alt 텍스트, 그리고 크롤 가능한 사이트 구조. 검색 엔진은 사람과 기계 모두가 읽기 쉬운 사이트를 선호합니다.

랜딩 페이지, 마케팅 사이트, 블로그, 디렉터리, 또는 검색 가능성이 중요한 모든 것을 출시하는 경우 SEO는 초기에 투자할 수 있는 가장 효과적인 방법 중 하나입니다.

## Replit이 SEO 기반을 개선하는 방법

Replit은 콘텐츠와 제품에 집중할 수 있도록 많은 SEO 기반을 처리합니다:

* **빠르고 전 세계적으로 분산된 호스팅**: Replit 배포는 속도에 최적화된 인프라에서 앱을 제공하며, [게시 지역](/ko/features/publishing/publishing-geography)을 통해 앱이 실행될 위치를 선택할 수 있습니다.
* **기본 HTTPS**: 모든 게시된 앱은 Replit이 관리하는 TLS 인증서를 받으며, 이는 검색 엔진의 기본 순위 신호입니다.
* **커스텀 도메인**: 신뢰와 브랜드 권위를 쌓기 위해 자신의 도메인을 연결하세요. [커스텀 도메인](/ko/features/publishing/custom-domains)을 참조하세요.
* **콘텐츠 사이트를 위한 정적 배포**: 마케팅 페이지, 블로그, 문서의 경우 [정적 배포](/ko/features/publishing/static-deployments)는 검색 엔진이 쉽게 크롤할 수 있는 사전 렌더링된 HTML을 제공합니다.
* **에이전트가 SEO를 고려한 코드 작성**: 에이전트가 페이지를 구축할 때 기본적으로 SEO 도구가 확인하는 것과 동일한 시맨틱 HTML, 접근 가능한 마크업, 메타 태그를 생성합니다.
* **SEO 점수 기능**: 게시 후 자동 감사를 통해 현재 위치를 항상 파악할 수 있으며, 에이전트에게 클릭 한 번으로 발견된 문제를 수정하도록 요청할 수 있습니다.

## SEO 점수 기능

성공적인 게시 후 Replit은 배포의 URL에 대해 Lighthouse 감사를 실행하고 결과를 저장합니다. 게시 도구에는 앱의 전체 SEO 점수가 표시됩니다.

### 찾는 방법

게시된 앱의 **게시** 도구를 여세요. SEO 점수는 다른 빌드 세부 정보와 함께 배포 개요에 표시됩니다. 점수 위에 마우스를 올리면 Lighthouse가 각 페이지에서 표시한 특정 조치 항목을 볼 수 있습니다.

### 점수 읽는 방법

Replit은 Lighthouse의 표준 임계값을 사용합니다:

| 점수     | 상태    | 의미                                             |
| :----- | :---- | :--------------------------------------------- |
| 90–100 | 좋음    | 앱이 SEO 모범 사례를 따릅니다. 주요 변경 후에도 계속 확인하세요.        |
| 50–89  | 개선 필요 | 몇 가지 문제가 검색 엔진이 앱을 이해하는 능력을 제한하고 있습니다.         |
| 0–49   | 나쁨    | 중요한 SEO 기본 요소가 누락되었습니다. 수정은 보통 몇 분밖에 걸리지 않습니다. |

앱에 여러 페이지가 있는 경우 배지는 Replit이 크롤한 모든 URL에서 **가장 낮은** 점수를 표시하므로 가장 나쁜 페이지가 평균화되지 않고 먼저 표시됩니다.

### 점수 계산 시점

감사는 성공적인 게시 후 자동으로 실행됩니다. 채점은 일반적으로 배포가 시작된 후 1\~2분 내에 완료되며 결과가 도착하면 게시 도구가 배지를 새로 고침합니다.

### 지원되는 배포 유형

SEO 점수는 검색 엔진이 URL을 크롤할 수 있는 공개 웹 대면 배포에 대해 계산됩니다:

* [오토스케일 배포](/ko/features/publishing/autoscale-deployments)
* [Reserved VM 배포](/ko/features/publishing/reserved-vm-deployments)
* [정적 배포](/ko/features/publishing/static-deployments)

예약된 배포와 비공개 배포는 공개 웹 트래픽을 제공하지 않으므로 SEO 점수가 생성되지 않습니다.

## 에이전트로 SEO 최적화

SEO 점수가 90 미만이면 점수 옆에 **에이전트로 SEO 최적화** 버튼이 표시됩니다. 이를 선택하면 Lighthouse가 확인한 모든 URL의 정확한 조치 항목이 수정 지시사항과 함께 새 에이전트 채팅으로 전송됩니다.

<Tip>
  버튼을 완전히 건너뛸 수도 있습니다. 에이전트를 열고 \*\*"SEO 최적화"\*\*라고 말하세요 — 에이전트가 최신 Lighthouse 결과를 가져와 작업을 시작합니다.
</Tip>

에이전트가 변경 사항을 완료한 후 앱을 재게시하세요. SEO 점수가 새 빌드에 대해 다시 계산되고 배지가 자동으로 업데이트됩니다.

에이전트가 적용할 일반적인 수정 사항:

* 각 페이지에 고유하고 설명적인 제목이 있도록 누락되거나 일반적인 `<title>` 태그 추가 또는 재작성
* 모든 페이지에 메타 설명 추가
* 이미지에 설명적인 `alt` 텍스트 추가
* `<html>` 요소에 `lang` 속성 설정
* 링크에 식별 가능한 텍스트 확인 ("여기를 클릭" 또는 빈 앵커 없음)
* `robots.txt` 및 `sitemap.xml` 추가
* 모바일 렌더링을 위한 viewport 메타 태그 추가
* 접근성 검사에 실패한 텍스트의 색상 대비 개선
* 소셜 플랫폼에서 앱 링크가 잘 미리보기 되도록 Open Graph 및 Twitter 카드 메타 태그 추가

## Replit에서 SEO 최적화 사이트를 위한 모범 사례

에이전트에게 처리를 요청하든 직접 작성하든, 다음은 Replit으로 만든 앱에서 올바르게 처리해야 할 가장 큰 영향을 미치는 사항들입니다:

* **모든 페이지에 고유한 제목과 메타 설명을 제공하세요.** 제목은 60자 미만, 설명은 약 150\~160자를 목표로 하세요.
* **시맨틱 HTML을 사용하세요.** 레이아웃을 `<main>`, `<header>`, `<nav>`, `<footer>`로 감싸세요. 페이지당 `<h1>`을 한 번 사용하고 제목 레벨을 순서대로 사용하세요.
* **모든 이미지에 alt 텍스트를 추가하세요.** 이미지가 무엇인지가 아니라 무엇을 보여주는지 설명하세요.
* **`sitemap.xml`과 `robots.txt`를 생성하세요.** 에이전트에게 둘 다 만들어 달라고 요청하면 검색 엔진이 크롤할 내용을 알 수 있습니다.
* **Open Graph 및 Twitter 카드 태그를 추가하세요.** 소셜 미디어에서 공유될 때 앱의 모습을 제어하세요.
* **커스텀 도메인을 사용하세요.** 브랜드 도메인은 방문자와 검색 엔진 모두에게 신뢰를 쌓습니다. [커스텀 도메인](/ko/features/publishing/custom-domains)을 참조하세요.
* **올바른 배포 유형을 선택하세요.** 콘텐츠가 많은 사이트의 경우 [정적 배포](/ko/features/publishing/static-deployments)는 검색 엔진이 즉시 파싱할 수 있는 사전 렌더링된 HTML을 제공합니다.
* **구조화된 데이터를 추가하세요.** JSON-LD 마크업은 검색 엔진이 제품, 기사, FAQ, 이벤트에 대한 리치 결과를 표시하는 데 도움이 됩니다.
* **앱을 빠르게 유지하세요.** 이미지를 최적화하고, 렌더링을 차단하는 스크립트를 피하고, Replit의 호스팅을 활용하여 응답 시간을 낮게 유지하세요.

한 번에 이러한 대부분을 적용하는 간단한 방법:

<AiPrompt>
  내 사이트를 SEO 모범 사례에 맞게 감사하고 수정 사항을 적용하세요. 사이트맵, robots.txt, Open Graph 태그, 적절한 경우 구조화된 데이터를 추가하고 모든 페이지에 고유한 제목과 메타 설명이 있는지 확인하세요.
</AiPrompt>
