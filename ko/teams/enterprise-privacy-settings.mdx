Enterprise 관리자는 팀 구성원이 코드, 배포, 외부 플랫폼과 상호작용하는 방식을 제어하는 조직 전체 설정을 구성할 수 있습니다. 이러한 설정을 활용하면 보안 표준을 유지하고, 지적 재산을 보호하며, 엔터프라이즈 정책을 준수할 수 있습니다.

  3. **Advanced**를 선택하여 사용 가능한 모든 설정을 확인합니다

<div id="privacy-settings">
  ## 개인정보 설정
</div>

개인정보 설정은 조직 내에서 앱을 게시하고 액세스하는 방식을 제어합니다.

<CardGroup cols={2}>
  <Card title="Private deployments" icon="lock">
    모든 새 앱을 비공개로 게시하도록 하여 인증된 팀 구성원만 액세스할 수 있도록 제한합니다
  </Card>

  <Card title="Password-protected deployments" icon="key">
    팀 구성원이 게시한 앱에 비밀번호 보호를 추가할 수 있도록 허용합니다
  </Card>

  <Card title="Private development URLs" icon="shield-halved">
    SAML이 활성화된 조직의 SSO를 포함해 모든 앱 개발 URL에 인증을 요구합니다
  </Card>
</CardGroup>

<div id="private-deployments">
  ### Private deployments
</div>

이 설정을 활성화하면 새로 만드는 모든 App을 비공개로 게시해야 합니다. 비공개 App은 조직의 인증된 멤버만 접근할 수 있습니다.

**이 설정을 사용하기 좋은 경우:**
**이 설정을 사용하기 좋은 경우:**

* 조직에서 민감한 데이터나 독점 애플리케이션을 다루는 경우
* App이 실수로 공개되는 일을 방지해야 하는 경우
* 규정 준수 요건에 따라 게시된 애플리케이션의 접근을 제한해야 하는 경우
* App이 실수로 공개되는 일을 방지해야 하는 경우
* 규정 준수 요건에 따라 게시된 애플리케이션의 접근을 제한해야 하는 경우

<Note>
  이 설정은 새로 게시되는 App에만 적용됩니다. 이미 게시된 App은 기존 공개 범위 설정을 그대로 유지합니다.
</Note>

<div id="password-protected-deployments">
  ### Password-protected deployments
</div>

팀 구성원이 password-protected deployments를 만들 수 있는지 여부를 제어합니다. 활성화하면 builder는 published app에 접근할 때 비밀번호를 요구하여 보안을 한층 강화할 수 있습니다.

**이 설정이 적합한 경우:**

* 앱을 완전히 공개하지 않고 외부 이해관계자와 공유할 수 있도록 허용하려는 경우
* 팀이 정식 release 전에 고객에게 애플리케이션을 시연해야 하는 경우
* Organization membership을 넘어서는 granular한 access control이 필요한 경우

<div id="require-private-development-urls">
  ### Require private 앱 개발 URL
</div>

활성화하면 모든 앱의 앱 개발 URL에 인증이 필요합니다. Organization에서 SAML을 활성화한 경우 앱 개발 URL에는 SSO 인증이 필요합니다.

**이 설정을 사용하면 좋은 경우:**
**이 설정을 사용하면 좋은 경우:**

* 개발 중인 애플리케이션에 대한 무단 접근을 차단해야 하는 경우
* 보안 정책상 모든 개발 environments를 보호해야 하는 경우
* 인증된 팀 구성원만 development previews를 볼 수 있도록 하려는 경우
* 보안 정책상 모든 개발 environments를 보호해야 하는 경우
* 인증된 팀 구성원만 development previews를 볼 수 있도록 하려는 경우

<Warning>
  이 설정은 Organization의 기존 apps 전체에 소급 적용됩니다.
</Warning>

<div id="ban-source-code-export">
  ### Ban source code export
</div>

이 설정을 활성화하면 팀 구성원이 앱 소스 코드를 zip 파일로 내보낼 수 없습니다. 이를 통해 코드가 Replit 플랫폼 외부로 다운로드되어 공유되는 것을 방지할 수 있습니다.

**이 설정을 사용해야 하는 경우:**
**이 설정을 사용해야 하는 경우:**

* 소스 코드가 저장되는 위치를 엄격하게 통제해야 하는 경우
* 보안 정책상 코드의 로컬 사본이 금지되는 경우
* 모든 개발이 관리되는 환경 내에서만 이루어지도록 하려는 경우
* 조직의 보안 정책상 코드의 로컬 사본이 금지되는 경우
* 모든 개발이 관리되는 환경 내에서만 이루어지도록 하려는 경우

<div id="security-settings">
  ## 보안 설정
</div>

보안 설정을 통해 취약점 검사와 기타 보호 조치를 의무화할 수 있습니다.

<div id="require-security-scan">
  ### Require 보안 검사
</div>

게시 전에 모든 apps가 보안 검사를 통과하도록 할지 설정합니다. 보안 검사는 코드에서 취약점, 노출된 secrets, 기타 보안 issues를 탐지합니다.

사용 가능한 옵션:

| 설정          | 설명                                     |
| ----------- | -------------------------------------- |
| **Off**     | 보안 검사가 선택 사항입니다                |
| **Require** | 게시 전에 모든 apps가 보안 검사를 통과해야 합니다 |

**이 설정을 사용하면 좋은 경우:**
**이 설정을 사용하면 좋은 경우:**

* 보안 규정 준수 requirements를 충족해야 하는 경우
* API keys나 secrets가 실수로 exposure되는 것을 방지하려는 경우
* 모든 published apps에 일관된 보안 표준을 적용해야 하는 경우
* API keys나 secrets가 실수로 exposure되는 것을 방지하려는 경우
* 모든 published apps에 일관된 보안 표준을 적용해야 하는 경우

<Note>
  이 설정은 설정을 활성화하기 전에 publish된 apps에는 적용되지 않습니다.
</Note>

<div id="source-control-settings">
  ## 소스 컨트롤 설정
</div>

소스 컨트롤 설정을 사용하면 version control 관행을 강제하고 Organization의 코드 저장소를 보호할 수 있습니다.

<div id="require-git-remote">
  ### Git remote 필수
</div>

이 설정을 활성화하면 모든 앱은 publish 전에 로컬 changes를 Git remote에 push해야 합니다. 이를 통해 모든 코드 changes가 조직의 version control 시스템에서 추적됩니다.

**이 설정이 적합한 경우:**
**이 설정이 적합한 경우:**

* 모든 코드를 Git에 백업해야 하는 경우
* 모든 코드 changes에 대한 audit 기록이 필요한 경우
* Workflows에서 publish 전에 코드 review가 필요한 경우
* 모든 코드 changes에 대한 audit 기록이 필요한 경우
* 사용 중인 workflow에서 publish 전에 코드 review가 필요한 경우

<Note>
  이 설정은 설정을 활성화하기 전에 publish된 앱에는 적용되지 않습니다.
</Note>

<div id="private-remotes">
  ### Private remotes
</div>

팀 구성원이 공개 Git 저장소를 사용할 수 있는지 여부를 제어합니다. private remote를 요구하도록 설정하면 팀 구성원은 GitHub와 같은 플랫폼의 비공개 저장소로만 push할 수 있습니다.

사용 가능한 옵션:

| 설정                         | 설명                                   |
| -------------------------- | ------------------------------------ |
| **Off**                    | 팀 구성원이 공개 또는 비공개 저장소를 사용할 수 있습니다     |
| **Require for non-admins** | 관리자가 아닌 팀 구성원은 비공개 저장소를 사용해야 합니다     |
| **Require for all**        | 관리자를 포함한 모든 팀 구성원이 비공개 저장소를 사용해야 합니다 |

**이 설정이 필요한 경우:**
**이 설정이 필요한 경우:**

* 공개 코드 저장소 사용이 금지된 경우
* 회사 소유 코드가 실수로 공개 저장소에 push되지 않도록 해야 하는 경우
* 규정 준수 requirements에 따라 비공개 version control이 필수인 경우
* 회사 소유 코드가 실수로 공개 저장소에 push되지 않도록 해야 하는 경우
* 규정 준수 requirements에 따라 비공개 version control이 필수인 경우
