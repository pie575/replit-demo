Replit 中的 Git 面板提供可视化界面，让你无需通过命令行执行 Git 命令即可完成 Git 操作。该功能让初学者也能轻松进行版本控制，同时满足经验丰富的开发者的需求。

<div id="recursos">
  ## 功能
</div>

Git 面板在 Project Editor 中提供全面的版本控制功能，通过易用的界面简化复杂的 Git 操作。

* **仓库管理**：通过 GitHub 集成初始化、连接和管理 Git 仓库
* **提交跟踪**：暂存、提交并查看所有文件的变更
* **分支操作**：以可视化方式创建、切换和合并分支
* **冲突解决**：借助可视化辅助识别并解决合并冲突
* **Shell 集成**：同步 Shell 中执行的 Git 命令与 Git 面板

<div id="uso">
  ## 使用方法
</div>

<div id="configurao-do-repositrio">
  ### 配置仓库
</div>

<Accordion title="如何访问 Git 面板">
  1. 前往 Replit App 的 Tools 部分
  2. 选择 **+** 图标以添加新工具
  3. 在可用工具列表中选择 **Git**
</Accordion>

Git 面板可帮助您配置和连接仓库：

* **Initialize repository**：为您的 Replit App 创建新的 Git 仓库
* **Connect to GitHub**：将仓库关联到 GitHub，以便备份和协作
* **Configure 远程仓库**：配置和管理与 GitHub 仓库的连接

<div id="gerenciamento-de-alteraes">
  ### 变更管理
</div>

<Accordion title="如何查看变更">
  1. 修改 Replit App 中的任意文件
  2. 在 Tools 部分打开 Git 面板
  3. 在 **Review Changes** 部分查看变更
</Accordion>

Git 面板提供了以下工具，帮助你管理代码变更：

* **Review changes**：查看已修改的文件，新增和删除的内容会高亮显示
* **Stage files**：选择要包含在下次提交中的文件
* **Commit changes**：填写描述性消息，保存你的变更
* **Push updates**：一键将提交推送到 GitHub

<Note>
  你可以借助 Replit AI 生成能准确描述本次变更的提交消息。

<div id="gerenciamento-de-branches">
  ### 分支管理
</div>

<Accordion title="如何管理分支">
  1. 在 Tools 部分打开 Git 面板
  2. 点击分支名称旁边的分支下拉菜单
  3. 创建新分支或选择已有分支
</Accordion>

Git 面板让你轻松管理代码的多个版本：

* **Create branches**：创建新分支，独立开发各项功能
* **Switch branches**：在代码的不同版本之间切换
* **Publish branches**：将分支共享到 GitHub
* **拉取 changes**：同步协作者的远程更新

<div id="resoluo-de-conflitos-de-merge">
  ### 解决合并冲突
</div>

<Accordion title="如何解决合并冲突">
  1. 在存在冲突时尝试执行拉取
  2. Git 面板会高亮显示存在冲突的文件
  3. 打开每个冲突文件，查看并解决冲突
  4. 解决冲突后保存文件
  5. 选择 **拉取** 完成合并
</Accordion>

当来自不同来源的代码发生冲突时，Git 面板可帮助你：

* **Identify conflicts**：准确查看哪些文件存在冲突
* **Visualize differences**：对比查看冲突代码的两个版本
* **Resolve issues**：选择保留哪部分代码，或手动编辑冲突内容
* **Finalize merges**：解决冲突后完成合并流程

解决冲突文件后，你可以删除以冲突符号开头的行来清除冲突标记，然后保存文件。

<div id="usando-comandos-git-no-shell">
  ### 在 Shell 中使用 Git 命令
</div>

<Accordion title="如何访问 Shell">
  1. 在左侧工具停靠栏中选择 **All tools**
  2. 在可用工具中选择 **Shell**
</Accordion>

<Tip>
  Git 面板提供了友好的操作界面，而高级用户可以在 Shell 中使用标准 Git 命令来完成更复杂的操作。无论使用哪种方式，所做的更改都会在两处同步体现。
</Tip>

如果你更喜欢通过命令行使用 Git：

* **命令同步**：在 Shell 中执行的任何 Git 命令都会自动同步到 Git 面板
* **完整的 Git 功能**：可使用 Git 面板中未提供的高级 Git 功能
* **无缝切换**：可根据需要在 Shell 命令与 Git 面板之间自由切换

<Info>
  **GitHub 和 GitLab CLI 支持**：除标准 Git 命令外，你还可以在 Shell 中使用 [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) 和 [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) 来管理和连接外部 Git 仓库。这些工具增强了处理 GitHub 和 GitLab 仓库的能力，包括 pull request、issue 以及其他平台特有的功能。
</Info>

<div id="operaes-de-repositrio">
  #### 仓库操作
</div>

* **克隆仓库**：`git clone <url-do-repositorio>`
* **初始化仓库**：`git init`
* **添加远程仓库**：`git remote add origin <url-do-repositorio>`

<div id="fazendo-alteraes">
  #### 进行变更
</div>

* **查看状态**：`git status` (显示已修改、已添加和已删除的文件) 
* **暂存文件**：`git add <文件名>` 或 `git add .` (暂存所有文件) 
* **提交变更**：`git commit -m "你的提交信息"`
* **推送变更**：`git push origin <分支名>`
* **拉取变更**：`git pull origin <分支名>`

<div id="autenticao">
  #### 身份验证
</div>

使用私有仓库时，你需要进行身份验证：

* 对于 GitHub 仓库，请使用个人访问 token，而不是密码
* 为避免反复输入凭证，你可以将其存储在 Replit 的 Secrets 中：
  1. 新建一个键名为 `GIT_URL` 的 secret
  2. 将值设置为 `https://<usuario>:<token>@github.com/<usuario-ou-org>/<repositorio>`
  3. 使用 `git push $GIT_URL` 即可免输凭证完成推送

<Note>
  使用凭证 secret 时，任何能访问你的 Replit App 的人都有可能获取你的 Git 凭证。对于敏感仓库，建议每次手动输入凭证。
</Note>
