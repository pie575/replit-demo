<div id="section">
  ## 简介
</div>

Replit 是一个云端开发环境，您可以在其中编写和运行任何框架或技术栈。构建自定义模板有两种推荐方式：

1. **[从 Git 提供商导入](https://replit.com/import)** — 从 GitHub、GitLab 或 Bitbucket 导入现有的入门 stack (或任何符合您需求的项目) 。
2. **Fork Blank 模板** — Fork [Blank 模板](https://replit.com/@replit/Nothing?v=1)，从完全空白的开发环境开始构建。

客户已成功构建了支持 Rust、Python、Java、C++ 及许多其他技术栈的模板——只要能运行，就能在 Replit 中运行。

<Tip>
  构建第一个模板时，我们建议与 Replit 的**现场工程团队**合作。他们在为各种技术栈设置自定义模板方面经验丰富，能够提供支持。请联系您的客户经理以获取引荐。
</Tip>

借助自定义模板，Enterprise 管理员可以创建预先配置的起点，并将其直接显示在组织所有成员的 Agent 输入框中。当构建者选择自定义模板时，Agent 会 Fork 该模板，并使用模板的配置、Instructions 和技能指导后续所有工作。无需额外设置。

<Note>
  自定义模板仅适用于 **Enterprise** 方案。只有组织管理员可以固定和管理模板。
</Note>

<div id="section-2">
  ## 自定义模板的工作原理
</div>

自定义模板是组织内部的标准 Replit App，并**固定在 Agent 输入框中**。构建者选择后：

1. Agent 会 fork 该模板并创建 New App (复制所有文件)
2. Agent 跳过规划阶段，直接进入构建模式
3. 模板中的 `custom_instruction/instructions.md` 文件会注入到 Agent 的上下文中
4. `.agents/skills/` 中的自定义[技能](/zh/ja/features/agent/skills)会被检测并可供使用
5. [`replit.md`](/zh/ja/features/project-setup/replit-dot-md) 文件持续提供项目上下文

如此一来，组织的标准、模式和工具从第一次交互起就已内置其中。

<div id="section-3">
  ## 模板文件结构
</div>

自定义模板的推荐布局如下：

```
my-template/
├── .replit                              # App 配置（Run 命令、端口、模块）
├── replit.md                            # Agent 记忆：项目概览与偏好设置
├── custom_instruction/
│   └── instructions.md                  # 注入到 Agent prompt 中的公司指令
├── .agents/
│   └── skills/
│       └── my-skill/
│           └── SKILL.md                 # Agent 可按需调用的自定义 skills
└── ...                                  # 仓库的其余结构
```

每个文件都有各自的用途。以下各节将分别介绍这些文件的配置方法。

<div id="section-4">
  ## 设置自定义模板
</div>

<div id="app">
  ### 创建基础 App
</div>

在组织内创建一个新的 Replit App。为项目配置好构建者作为起点所需的全部文件、依赖项和配置，其中包括：

* 源代码脚手架 (组件、工具函数、配置文件)
* 预装的依赖项 (`package.json`、`requirements.txt` 等)
* [`.replit` 文件](/zh/replit-app/configuration)中的环境配置

<div id="secret">
  ### 配置共享 Secrets
</div>

如果模板依赖 API 密钥、令牌或其他凭据，请在固定模板前将其添加到模板的 **Secrets** (位于工具面板中) 。当构建者基于模板创建 New App 时，所有 Secrets 都会自动复制到新 App 中，因此无需自行配置凭据即可立即开始工作。

请在 `custom_instruction/instructions.md` (或专用的 Skill) 中记录所有 Secret，以便构建者了解可用的 Secret 及每个密钥的用途。

<Warning>
  Secrets 会在 Fork 时复制，不会动态同步。即使你轮换模板中的密钥或添加新的 Secret，之前 Fork 的 App 也不会更新。构建者需要在这些 App 中手动添加或更新 Secrets。
</Warning>

<div id="instructions">
  ### 创建自定义 Instructions
</div>

在项目根目录下创建 `custom_instruction/instructions.md` 文件。这是模板中最重要的文件——它告诉 Agent 你的组织是如何构建软件的。

<Warning>
  文件夹名称是 `custom_instruction` (单数形式) ，而不是 `custom_instructions`。
</Warning>

Agent 会将该文件连同 Preamble 一起直接注入系统提示词，并将其作为公司提供的指导呈现。请使用 Markdown 编写，并包含以下内容：

* **架构模式**：如何组织 App 的结构
* **编码标准**：命名规范、文件组织规则、代码检查要求
* **组件使用**：应使用哪些库和组件 (以及应避免哪些)
* **API 模式**：如何调用后端服务、处理认证、管理错误
* **测试要求**：需要编写哪些测试以及如何运行
* **部署指南**：各环境的专属配置与部署工作流

````markdown theme={null}
# Company Engineering Standards

## Architecture
All web applications use React with TypeScript. Use functional components
with hooks exclusively. State management uses Zustand for local state
and React Query for server state.

## Component Library
Use our internal design system package `@acme/ui`. Never use raw HTML
elements for buttons, inputs, forms, or modals — always use the
corresponding component from `@acme/ui`.

Import components like this:
```tsx
import { Button, TextField, Modal } from '@acme/ui';
```

## API Integration
All API calls go through the `@acme/api-client` package. Never use
raw fetch or axios directly. Authentication is handled automatically
by the client.

## Testing
Every component must have a corresponding test file. Use Vitest
for unit tests and Playwright for integration tests.
````

**大小限制**：内容设有约 25 KB 的软性限制。超出此限制的内容可能会被逐步截断。如果 Instructions 变得过大，请将详细的参考资料移至 `.agents/skills/` 中的[技能](/zh/ja/features/agent/skills)，而非全部保留在 `instructions.md` 中。技能会在相关时按需加载，因此不会计入 Instructions 的大小限制，让主要 Instructions 能专注于高层规则。

<div id="section-5">
  ### 添加自定义技能
</div>

在 `.agents/skills/` 目录中为 Agent 需要遵循的专用工作流创建技能。每个技能都是一个目录，其中包含一个带有 YAML frontmatter 的 `SKILL.md` 文件。

```
.agents/skills/
├── use-design-system/
│   └── SKILL.md
├── api-integration/
│   └── SKILL.md
└── run-tests/
    └── SKILL.md
```

每个 `SKILL.md` 的 Frontmatter 中都必须包含 `name` 和 `description`：

```markdown theme={null}
---
name: use-design-system
description: Use when building UI components. Provides component patterns, theming rules, and accessibility requirements for the Acme design system.
---

# Acme Design System

## Available components

- `Button` — Primary, secondary, and ghost variants
- `TextField` — Text input with validation support
- `Modal` — Dialog overlay with focus trapping
...
```

| 字段            | 必填 | 详情                                 |
| ------------- | -- | ---------------------------------- |
| `name`        | 是  | 最多 64 个字符。仅限小写字母、数字和连字符。           |
| `description` | 是  | 最多 1,024 个字符。说明该 技能 的用途及适用场景。   |
| `enabled`     | 否  | 默认为 `true`。设为 `false` 可在不删除的情况下停用。 |

**技能 的加载方式**：Agent 在提示词中只能看到 `name` 和 `description`。当某个 技能 与当前任务相关时，才会按需加载完整的 `SKILL.md` 内容。因此 `description` 至关重要——请确保其内容能够准确对应 Agent 应当使用该 技能 的场景。

除了 `SKILL.md`，技能 中还可以包含配套文件：

```
.agents/skills/use-design-system/
├── SKILL.md
├── references/
│   └── component-api.md
└── assets/
    └── theme-tokens.json
```

有关 技能 的更多信息，请参阅 [Agent 技能](/zh/ja/features/agent/skills) 和[使用 技能](/zh/ja/build/use-agent-skills)。

<div id="replitmd">
  ### 配置 replit.md
</div>

在项目根目录的 `replit.md` 中预先填写模板的架构概览。该文件始终会加载到 Agent 的 上下文 中，充当持续的项目记忆。

该文件需要包含以下四个部分：

```markdown theme={null}
# 概述
使用 React、TypeScript 和 Acme design system 构建的任务管理应用。
后端采用 Express.js，数据库使用 PostgreSQL。

# 用户偏好
- 所有文件均使用 TypeScript
- 优先使用带 hooks 的函数式组件
- 遵循 Acme coding standards

# 系统架构
- 前端：React + TypeScript + @acme/ui
- 后端：Express.js + TypeScript
- 数据库：PostgreSQL，搭配 Drizzle ORM
- 身份验证：通过 @acme/auth 使用 Acme SSO

# 外部依赖项
- @acme/ui：内部 design system
- @acme/api-client：API integration 层
- @acme/auth：身份验证 SDK
```

Agent 会随着项目的演进更新 `replit.md`。当文件超过约 4,000 个词元时，Agent 会自动将其压缩为摘要，以保持重点并确保其实用性。

有关详细信息，请参阅 [replit.md](/zh/ja/features/project-setup/replit-dot-md)。

<div id="section-6">
  ### 将模板固定到组织
</div>

模板准备就绪后：

1. 进入组织中的模板 App
2. 打开该 App 的操作菜单 (三点菜单)
3. 选择**固定到 Agent 输入框**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="显示“固定到 Agent 输入框”选项的 App 操作菜单" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  只有组织管理员 (拥有 `system_admins` 角色的成员) 才能固定和取消固定模板。
</Note>

将成员访问权限设置为**只读**，这样成员可以查看和使用已固定的模板，但无法进行编辑。

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="显示成员访问权限设置为只读的邀请对话框" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

模板会以可选择的 Pill 形式显示在组织所有成员的 Agent 输入框下方。若要移除，请打开同一菜单并选择**从 Agent 输入框取消固定**。

<div id="section-7">
  ### 控制模板访问权限
</div>

固定模板后，所有 Org 成员都能看到它。若要更有针对性地分发，请使用模板 App 的 **Invite** 按钮，将其共享给特定[群组或个人用户](/zh/ja/teams/identity-and-access-management/groups-and-permissions)。这样，无需将模板固定在面向整个 Org 的输入框中，即可限制可查看和复刻该模板的团队或人员。

<div id="section-8">
  ## 构建者选择模板时的行为
</div>

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="在 Agent 输入框中作为可选 Pill 显示的模板" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

当组织成员从 Agent 输入框中选择已固定的模板时：

1. **Fork**：以该模板的完整副本 (包含所有文件) 创建一个 New App
2. **跳过规划**：Agent 跳过初始规划对话，直接进入构建模式
3. **加载 Instructions**：读取 `custom_instruction/instructions.md`，并作为公司提供的指导注入 Agent 的系统提示词
4. **检测技能**：识别 `.agents/skills/` 中的技能，并列入 Agent 的上下文，以便按需加载
5. **加载项目上下文**：读取 `replit.md` 并注入 Agent 的上下文 (若不存在则自动生成)
6. **继承 配置**：`.replit` 文件、依赖项以及所有模板文件都会带入 New App

构建者可以立即向 Agent 提出具体需求的提示词，而 Agent 将始终在模板设定的护栏范围内运行。

<div id="section-9">
  ## 各文件如何协同工作
</div>

各配置文件各司其职：

| 文件                                   | 用途                | Agent 读取时机    | 是否可由 Agent 修改         |
| ------------------------------------ | ----------------- | ------------- | --------------------- |
| `custom_instruction/instructions.md` | 组织标准与规则           | 始终 (注入系统提示词)  | 否                     |
| `.agents/skills/*/SKILL.md`          | 专项工作流与模式          | 按需 (相关时加载)    | 是 (Agent 也可创建 技能)  |
| `replit.md`                          | 项目概览与设置           | 始终 (注入系统提示词)  | 是 (Agent 会持续更新)       |
| `.replit`                            | 运行时 配置 | 配置 App 时      | 是                     |

**关键区别**：`custom_instruction/instructions.md` 是组织标准的静态权威来源；`replit.md` 是随项目演进由 Agent 持续维护的动态文档；技能 则是面向特定工作流的按需参考资料。

<div id="section-10">
  ## 最佳实践
</div>

<div id="instructions-2">
  ### 让 Instructions 保持聚焦
</div>

`custom_instruction/instructions.md` 应围绕最重要的模式来编写。请重点关注以下内容：

* 难以撤销的决策 (架构、数据模型)
* 需要保持一致的模式 (组件用法、API 规范)
* 构建者可能不了解的标准 (内部库、团队约定)

请避免添加 changelog、实现细节或频繁变动的信息。

<div id="description">
  ### 编写易于被发现的 技能 描述
</div>

`SKILL.md` frontmatter 中的 description 字段是 Agent 判断何时加载 技能 的依据。请编写与该 技能 适用任务相匹配的描述：

```yaml theme={null}
# 良好示例 —— 说明了何时使用
description: 在构建表单或处理用户输入时使用。提供 Acme 设计系统的校验模式、错误展示规范以及无障碍表单布局。

# 效果较差的示例 —— 过于含糊
description: 表单的实用工具与辅助函数。
```

<div id="section-11">
  ### 按工作流组织技能
</div>

按工作流而非技术类别对技能进行分组：

| 方法        | 示例                                         |
| --------- | ------------------------------------------ |
| **按工作流**  | `build-a-form`、`connect-to-api`、`add-auth` |
| **按技术领域** | `react-utils`、`api-helpers`、`auth-config`  |

采用工作流方式，Agent 能在恰当的时机发现技能。

<div id="section-12">
  ### 持续改进模板
</div>

模板会在使用过程中不断完善。团队开始基于模板进行构建后：

1. 留意 Agent 容易出错的模式，并将其添加到`instructions.md`
2. 当 Agent 成功解决问题时，创建新的 skill 来记录解决方案
3. 随着技术栈演进，更新基础依赖项和配置
4. 通过从模板创建新的 App 并体验整个流程来测试更改

<div id="app-2">
  ### 模板更新与现有 App
</div>

对模板 App 所做的更改会反映到基于该模板新建的**新** App 中。此前从模板 Fork 的现有 App 是独立副本，不会获得更新。
