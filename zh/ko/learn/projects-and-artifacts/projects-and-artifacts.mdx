**项目**是你在 Replit 中构建的一切内容的容器。**工件**是其中可发布的成果——Web 应用、移动应用、幻灯片、动画、数据可视化、3D 游戏和设计。

当你构建两项或更多内容时，有两种选择：在一个项目中添加多个工件，或创建单独的项目。正确的选择取决于这些应用是否共享数据、逻辑和部署周期。本页面将深入介绍这两个术语，并说明何时应将工件保留在同一个项目中，何时应创建单独的项目。

<div id="section">
  ## 什么是项目？
</div>

项目是存放代码、数据以及你创建的所有工件的容器。告诉 Agent 你想要什么，它就会设置项目并在其中构建工件。

你可以将项目视为桌面上的工作空间。所有内容都集中在一处，可以共享相同的信息，但各个部分的用途各不相同。

例如，如果你让 Agent 构建一款健身追踪应用，它会创建一个项目，其中包含移动应用工件以及所需的后端、数据库和存储。

核心概念：

* **项目**：存放代码、数据和所有工件的容器。
* **工件**：项目中可发布的成果 (Web 应用、幻灯片、视频等) 。
* **资源**：所有工件无需额外设置即可自动访问后端、数据库和文件存储。

如需了解可通过项目完成的所有操作 (管理、筛选、固定和排序) ，请参阅 [Projects](/zh/ko/features/projects-and-artifacts/projects)。

<div id="section-2">
  ## 什么是工件？
</div>

工件是在 Replit 中可发布的内容。每个工件都是完整且独立的成果，发布后都有自己的可分享 URL。

项目中的其他内容——文件、图片、CSV、代码——可为工件提供支持，但本身无法发布。

<div id="section-3">
  ## 项目中的工件共享哪些内容
</div>

当[工件](/zh/ko/features/projects-and-artifacts/artifacts)位于同一[项目](/zh/ko/features/projects-and-artifacts/projects)中时，它们会自动共享以下内容：

* **数据库**：一个工件写入数据后，其他工件可立即读取。
* **后端和 API**：共享服务器逻辑，无需重复编写代码。
* **文件存储**：所有工件均可访问的图片、文档和上传内容。
* **部署**：发布后，所有内容会同步更新，并实时生效。

换句话说，您无需在工件之间设置连接或重复编写代码。但您无法只发布一个工件而不发布其他工件。

<div id="section-4">
  ## 快速指南
</div>

以下是决定在现有项目中添加工件还是创建独立项目时需要考虑的主要场景。

| **在一个项目中使用多个工件**         | **使用独立项目**          |
| ------------------------ | ------------------- |
| 应用共享相同的数据和后端             | 应用不共享核心逻辑或数据        |
| 希望将所有内容一起发布              | 需要独立的发布周期           |
| 具有互补关系 (例如客户应用和管理员控制面板)  | 无关的产品，或面向不同客户端      |
| 希望一个工件的更改自动反映到其他工件       | 短期项目，例如营销活动着陆页或活动网站 |

<div id="section-5">
  ## 示例
</div>

<div id="section-6">
  ### 同一项目：同一产品的 Web 应用 + 移动应用
</div>

一家餐厅构建了一个供顾客查看菜单的 Web 应用，以及一个供员工管理订单的移动应用。两个应用都连接到同一个数据库，其中包含菜单项、订单和客户信息。

**之所以属于同一项目：**两个应用共享相同的数据和后端。顾客通过 Web 应用下单后，员工可以立即在移动应用中看到。

<div id="section-7">
  ### 同一项目：应用 + 管理控制面板 + 投资者路演幻灯片
</div>

初创公司在同一项目中构建核心产品、用于管理内容的内部管理面板，以及用于融资的幻灯片。

**之所以放在同一项目中：**管理控制面板可管理应用显示的数据，而路演幻灯片可引用共享后端的实时指标。

<div id="section-8">
  ### 独立项目：两个互不相关的客户端应用
</div>

一名自由职业者为一位客户构建电商店铺，为另一位客户构建预约系统。

**为何使用独立项目：**这些应用不共享数据或逻辑。每位客户都需要独立发布，也不希望一项更改影响另一项。

<div id="section-9">
  ### 独立项目：配合主产品的营销活动着陆页
</div>

除了全年运行的生产应用外，您还可以为营销活动创建短期着陆页。

**为何使用独立项目：** 活动页面有其独特的生命周期——上线、运行数周后再下线。将其独立维护，既能避免主产品变得复杂，也能单独发布或移除。

<div id="section-10">
  ## 常见问题
</div>

<Accordion title="可以将工件移至其他项目吗？">
  目前不支持。如果需要将工件拆分开来，请新建一个[项目](/zh/ko/features/projects-and-artifacts/projects)，然后让 Agent 重新构建。
</Accordion>

<Accordion title="项目中的工件数量有限制吗？">
  一个项目最多可包含 7 个工件，且**每个项目仅限 1 个移动应用**。这是因为额外的工件会占用更多内存，可能导致预览变慢。如果需要更多工件，请创建另一个[项目](/zh/ko/features/projects-and-artifacts/projects)。
</Accordion>

<Accordion title="可以只发布项目中的一个工件吗？">
  目前不支持。发布后，所有内容都会一同上线。如需单独发布，请使用独立的项目。
</Accordion>

<Accordion title="工件之间会共享数据吗？">
  会。项目中的所有工件共享同一个数据库和后端服务。Web 应用写入数据后，移动应用和数据控制面板可立即读取。
</Accordion>

<Accordion title="工件与文件有什么区别？">
  工件是可发布的内容，例如应用、幻灯片和视频。文件 (CSV、图片、代码等) 是项目中的资源，用于支持工件，但本身无法发布。
</Accordion>
