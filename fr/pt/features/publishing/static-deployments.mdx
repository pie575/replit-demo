---
title: "Déploiements statiques"
description: "Découvrez comment publier des sites statiques et des apps frontend avec les déploiements statiques."
---

Les déploiements statiques hébergent les fichiers statiques de votre app Replit, tels que HTML, CSS et JavaScript,
sur un serveur cloud. Le serveur utilise automatiquement des stratégies de mise en cache et de mise à l’échelle pour servir
votre contenu rapidement et à moindre coût.

Les déploiements statiques sont idéaux pour les cas d’utilisation suivants :

* Pages de destination marketing
* Sites de portfolio
* Sites de documentation de produits et d’API

<Note>
  Les déploiements statiques ne sont pas compatibles avec les apps Replit créées avec Agent.
  Agent crée automatiquement des apps full-stack qui nécessitent un serveur backend. Pour les
  apps générées par Agent, utilisez l’un des types de deployment suivants : - [Autoscale
  Deployment](/fr/pt/features/publishing/autoscale-deployments) - [Reserved VM
  Deployment](/fr/pt/features/publishing/reserved-vm-deployments)
</Note>

<div id="recursos">
  ## Fonctionnalités
</div>

Les déploiements statiques offrent les fonctionnalités suivantes :

* **Hébergement économique** : payez uniquement pour le volume de données servi par votre site.
* **Options de routage HTTP** : configurez les en-têtes de réponse, les réécritures d’URL et les redirections.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez une URL `<nome-do-app>.replit.app` pour accéder à votre App.
* **Pages d’erreur personnalisées** : créez et servez une page d’erreur 404 personnalisée.
* **Surveillance** : consultez les logs et surveillez l’état de votre App publiée.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder au déploiement statique dans l’outil Publishing du Project Editor.

<Accordion title="Accéder au déploiement statique">
  Dans le **dock d’outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône de tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône de Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l’option **Static**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez l’<img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> icône de loupe en haut pour ouvrir l’outil de recherche.
  2. Saisissez « Publishing » pour trouver l’outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l’option **Static**, puis **Set up your published app**.
</Accordion>

<div id="domnio-principal">
  ### Domaine principal
</div>

Indiquez le sous-domaine à utiliser pour le nom d’hôte de votre app publiée. Après la publication, votre app sera accessible à l’adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Domaines personnalisés](/fr/features/publishing/custom-domains).

<div id="deployment-privado">
  ### Déploiement privé
</div>

<Info>
  La fonctionnalité d&#39;app privée publiée est disponible avec les plans Pro et Enterprise.
</Info>

Les apps privées publiées permettent de limiter l&#39;accès à votre app aux membres de votre workspace, ou à des utilisateurs et groupes spécifiques que vous invitez.
Lors de la publication, vous pouvez choisir entre les accès **Public**, **Protégé par mot de passe**, **Workspace uniquement** ou **Sur invitation uniquement**.

Pour savoir comment configurer un déploiement privé, consultez [Accès à l&#39;app](/fr/features/publishing/private-deployments/).

<div id="diretrio-pblico">
  ### Répertoire public
</div>

Indiquez le chemin du répertoire de votre Replit App qui contient les fichiers statiques que vous souhaitez rendre publics.
Après le déploiement, l&#39;hébergeur cloud sert toutes les pages et tous les assets de ce répertoire.

La valeur par défaut, `/`, correspond au répertoire racine de votre Replit App.

<div id="build-command">
  ### Commande de build
</div>

Indiquez une commande de build à exécuter dans le Shell de votre App Replit lors de la création de votre déploiement.

Par exemple, si vous générez un site statique avec <a href="https://gohugo.io/" target="_blank">Hugo</a>,
vous pouvez utiliser la commande `hugo --minify` pour générer les fichiers et optimiser la taille des assets.

<div id="deployment-secrets">
  ### Deployment secrets
</div>

Sélectionnez **Add deployment secret** pour ajouter les variables d’environnement ou Secrets dont votre commande de build a besoin pour s’exécuter en toute sécurité.

Par exemple, si le générateur de votre site nécessite une clé API pour créer votre site statique, vous pouvez la transmettre sous la forme
`API_KEY=<nom de votre secret>`.
