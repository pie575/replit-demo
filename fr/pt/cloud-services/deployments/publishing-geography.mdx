---
title: "Géographie de publication"
description: "Choisissez où votre projet publié s’exécute et stocke ses données en sélectionnant une géographie de publication."
---

Lorsque vous publiez un projet sur Replit, vous pouvez choisir la région géographique dans laquelle les ressources de calcul et de stockage de votre projet sont hébergées. Par défaut, Replit recommande la géographie la plus proche de vous. Cela permet de réduire la latence pour les visiteurs de votre app et de respecter les exigences en matière de résidence des données.

<Note>
  La sélection d’une géographie de publication est disponible pour les créateurs disposant des forfaits Core, Pro et Enterprise.
  Les créateurs disposant du forfait gratuit publient par défaut dans la géographie d’Amérique du Nord.
</Note>

<div id="geografias-disponveis">
  ## Géographies disponibles
</div>

Replit prend en charge les géographies de publication suivantes :

| Géographie           | Description                                           |
| :------------------- | :---------------------------------------------------- |
| **Amérique du Nord** | Héberge votre projet en Amérique du Nord (par défaut) |
| **Europe (UE)**      | Héberge votre projet dans l’Union européenne          |
| **Amérique du Sud**  | Héberge votre projet en Amérique du Sud               |
| **Australie**        | Héberge votre projet en Australie                     |
| **Asie**             | Héberge votre projet en Asie                          |

<Note>
  L’Amérique du Nord et l’Europe (UE) sont disponibles pour tous les créateurs éligibles. L’Amérique
  du Sud, l’Asie et l’Australie sont déployées progressivement et peuvent ne pas encore être
  visibles dans le menu déroulant des géographies. Si vous ne trouvez pas la géographie dont vous avez besoin,
  contactez l’assistance Replit.
</Note>

Lorsque vous sélectionnez une géographie, tous les artefacts publiés de votre projet (comme les ressources de calcul, la base de données et Object Storage) sont automatiquement placés dans la même région. Un proxy propre à cette géographie contribue également à réduire la latence pour les visiteurs de votre app.

<div id="selecionando-uma-geografia">
  ## Sélectionner une région géographique
</div>

Par défaut, Replit recommande la région géographique la plus proche de vous. Pour en choisir une autre :

<Steps>
  <Step>
    Ouvrez l’outil **Publishing** dans votre projet Replit.
  </Step>

  <Step>
    Développez les paramètres **Advanced**.
  </Step>

  <Step>
    Sélectionnez la région géographique de votre choix dans le menu déroulant **Geography**.
  </Step>

  <Step>
    Sélectionnez **Publish** pour publier votre projet dans la région géographique sélectionnée.
  </Step>
</Steps>

<div id="impondo-uma-geografia-em-projetos-publicados">
  ## Imposer une géographie de publication aux projets
</div>

Les administrateurs Enterprise peuvent imposer une géographie de publication pour tous les projets de l&#39;organisation. Lorsqu&#39;une politique est définie, les créateurs de l&#39;organisation publient dans la géographie configurée. Cette politique s&#39;applique uniquement aux projets qui n&#39;ont pas encore été publiés — les projets déjà publiés dans une autre géographie ne sont pas concernés.

<Note>
  Imposer une géographie de publication est une fonctionnalité Enterprise. Pour en savoir plus sur les plans Enterprise, consultez [Tarifs](https://replit.com/pricing/).
</Note>

<Steps>
  <Step>
    Accédez à vos **Account settings**.
  </Step>

  <Step>
    Sélectionnez **Advanced**.
  </Step>

  <Step>
    Choisissez la géographie dans laquelle tous les projets doivent être publiés pour la première fois.
  </Step>
</Steps>

<div id="limitaes">
  ## Limitations
</div>

Avant de choisir une géographie, tenez compte des limitations suivantes :

* **La géographie ne peut pas être modifiée après la publication.** Une fois votre projet publié dans une géographie, ce choix est définitif. Il n’est pas possible de migrer un projet publié vers une autre géographie.
* **Les artefacts de l’environnement de développement peuvent ne pas correspondre à votre géographie de publication.** Des ressources comme l’Object Storage peuvent être créées avant la publication. Tous les environnements de développement s’exécutent actuellement en Amérique du Nord. La prise en charge de l’hébergement de votre environnement de développement dans la région de publication la plus proche sera bientôt disponible.
