---
title: "Миграция с Replit Auth на Clerk Auth"
description: "С помощью Agent перенесите существующее App с Replit Auth на Clerk Auth, сохранив пользовательские данные."
---

С помощью этого руководства перенесите существующее App с [Replit Auth](/ru/ja/features/auth-and-identity/authentication) на [Clerk Auth](/ru/ja/features/auth-and-identity/clerk-auth). Agent выполнит миграцию App, поэтому существующие пользователи сохранят доступ к своим данным.

<Note>
  Эта автоматическая миграция предназначена для App, использующих Replit Auth. Не используйте этот процесс, если ваше App использует другую систему аутентификации.
</Note>

  ### Проверка плана миграции
</div>

Независимо от выбранного способа Agent создаст задачу **Migrate from Replit Auth to Clerk** и подготовит план миграции. Прежде чем задача продолжит выполнение, выберите **View plan**, чтобы ознакомиться с планом.

Пока Agent работает, не изменяйте код аутентификации App или учётные данные Clerk.

<div id="agent-2">
  ## Что делает Agent
</div>

Agent выполняет миграцию в следующем порядке:

1. Переносит в Clerk пользовательские данные Replit Auth, включая сведения об идентификации аккаунта и поддерживаемые учетные данные для входа.
2. Дожидается завершения миграции данных, прежде чем вносить изменения в App.
3. Обновляет логику входа и сеансов в App, перезапускает App и запускает доступные автоматические проверки.

<div id="section-3">
  ## Данные App остаются без изменений
</div>

Agent изменяет только код аутентификации App. Существующие данные и схемы базы данных App не обновляются. Таблицы и связи сохраняются без изменений.

Существующие пользователи по-прежнему будут связаны с принадлежащими им записями, включая профили, сохранённые результаты работы и разрешения.

<div id="section-4">
  ## Необходимое время
</div>

Работа Agent может занять от 10 минут до часа. Сама миграция данных может занять несколько минут для небольших App и до нескольких часов для App с большим числом пользователей. Agent не начнёт вносить изменения в код App, пока миграция данных не завершится.

<div id="section-5">
  ## После миграции
</div>

Перед публикацией протестируйте App, обновлённое в Development.

1. Войдите в существующий аккаунт и убедитесь, что сохранённые данные доступны.
2. Выйдите из аккаунта и войдите снова.
3. Создайте новый тестовый аккаунт и убедитесь, что App работает должным образом.
