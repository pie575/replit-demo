title: "创建并发布移动应用"
description: "使用 Agent 创建原生 iOS 应用，通过 Expo Go 在手机上测试，然后经 TestFlight 分发并提交 App Store 审核。"
---

<div id="o-que-voc-far">
  ## 你将完成的内容
</div>

在本教程中，你将：

* 使用 Agent，通过一个 prompt 创建移动应用
* 使用 Expo Go 在手机上本地预览
* 在 Expo Go 中分享预览，用于测试和收集反馈
* 发布到 TestFlight 进行 Beta 测试
* 提交到 App Store 进行公开发布

<Note>
  请在 [replit.com](https://replit.com) 的项目编辑器中完成本教程。如果你使用的是 Replit iOS 应用，请在 replit.com 上打开项目来开发原生移动应用。
</Note>

<Note>
  提交到 TestFlight 和 App Store 的各项要求由 Apple 制定。你将使用 App Store Connect 来管理测试和发布。
</Note>

<div id="o-que-voc-precisar">
  ## 准备工作
</div>

* 一个 Replit 账户，并可在 [replit.com](https://replit.com) 上使用项目编辑器
* 一部安装了 Expo Go 的手机
* Apple 开发者计划订阅 (Apple 要求，使用 TestFlight 和 App Store 时必备)

<div id="parte-1-crie-seu-aplicativo-com-o-agent">
  ## 第 1 部分：使用 Agent 创建你的应用
</div>

<Steps>
  <Step title="创建移动应用">
    在 Replit 首页上，描述你想创建的内容，并选择**移动应用**作为应用类型。
  </Step>

  <Step title="让 Agent 开始构建">
    Agent 会搭建项目框架并生成第一个版本。保持 Chat 处于打开状态，即可随时跟进进度并提出修改要求。
  </Step>
</Steps>

<div id="parte-2-teste-no-seu-celular-com-o-expo-go">
  ## 第 2 部分：使用 Expo Go 在手机上测试
</div>

Expo Go 可在你的设备上运行应用的原生预览。

<Steps>
  <Step title="安装 Expo Go">
    在你的 iPhone 或 Android 设备上安装 Expo Go。
  </Step>

  <Step title="打开二维码">
    在项目编辑器中，选择**在移动设备上预览**以显示二维码。
  </Step>

  <Step title="扫码预览">
    用手机扫描二维码，即可在 Expo Go 中打开原生预览。
  </Step>
</Steps>

<Frame>
  <img src="/assets/mirror/mobile-screen-e5685fc26793.png" alt="移动应用在 Replit 项目编辑器预览中运行，显示设备预览面板和二维码" width="1440" height="900" data-path="images/native-mobile-apps/mobile-screen.png" />
</Frame>

<Tip>
  如果预览内容不是最新的，请在 Expo Go 中刷新：摇晃手机打开开发者菜单，然后选择**重新加载**。
</Tip>

<div id="parte-3-compartilhe-uma-pr-visualizao-com-o-expo-go">
  ## 第 3 部分：通过 Expo Go 分享预览版本
</div>

通过 Expo Go 分享可为已安装 Expo Go 的测试人员创建开发预览版本。你可以在通过 Apple 审核流程提交构建版本前，借此收集反馈。

<Steps>
  <Step title="通过项目编辑器部署">
    打开部署面板并选择 **部署**。这会将你的应用和后端部署到 Replit 的基础设施上。
  </Step>

  <Step title="分享你的应用">
    部署预览版本后，安装了 Expo Go 的测试人员可通过分享链接打开它。此步骤无需 Apple 开发者账户。
  </Step>
</Steps>

<Tip>
  使用 Expo Go 预览版本可快速分享原型、收集早期反馈，并在进入 App Store 流程前进行迭代。
</Tip>

<div id="parte-4-promova-para-o-testflight">
  ## 第 4 部分：发布到 TestFlight
</div>

在 Expo Go 中分享预览版后，您可以将 App 发布到 TestFlight，进行更正式的 Beta 测试。TestFlight 需要 Apple 开发者账户，但可提供无需 Expo Go 的原生 App 体验。

<div id="pr-requisitos-para-publicao-na-apple">
  ### 发布到 Apple 的前提条件
</div>

在提交构建版本之前，Apple 要求您拥有特定的账户并完成相关配置。请先完成以下步骤，再尝试提交。

<div id="entre-no-programa-de-desenvolvedor-da-apple">
  #### 加入 Apple 开发者计划
</div>

您需要订阅 Apple 开发者计划，才能将构建版本上传到 TestFlight 和 App Store。

<Callout type="note">
  Apple 要求您的 Apple 账户启用双重认证。
</Callout>

<div id="inscrio-individual-vs-organizacional">
  #### 个人注册与组织注册
</div>

* **个人账户**：以您的法定姓名作为销售方发布。
* **组织账户**：以组织名称作为销售方发布。Apple 要求组织提供 D‑U‑N‑S 编号，获取该编号可能需要一段时间。

<div id="etapas-tpicas-de-inscrio">
  #### 常见注册步骤
</div>

1. 访问 `https://developer.apple.com/programs/enroll/`
2. 完成身份验证
3. 接受 Apple 开发者计划许可协议
4. 支付 Apple 规定的年费
5. 等待 Apple 审核通过 (所需时间因账户类型而异)

<div id="entenda-o-testflight-vs-a-app-store">
  ### 了解 TestFlight 与 App Store 的区别
</div>

TestFlight 是 Apple 的 Beta 测试系统。App Store 则是面向所有人开放、任何人都能下载你的应用的公开市场。

| 方面        | TestFlight                | App Store    |
| --------- | ------------------------- | ------------ |
| **受众**    | 受邀测试人员 (最多 10,000 名外部测试人员)  | 公众用户         |
| **用途**    | Beta 测试与收集反馈              | 公开发布         |
| **审核**    | 每个版本的首个构建版本需经过 Beta 审核      | 每次提交都需经过应用审核 |
| **构建版本有效期** | 90 天后过期                   | 长期有效，直到你将其下架 |

<Tip>
  在正式发布前，TestFlight 是发现崩溃、性能问题和设备相关问题的最快途径。
</Tip>

<Steps>
  <Step title="打开部署面板">
    在应用已作为 Expo Go 预览分享的前提下，在项目编辑器中打开部署面板。
  </Step>

  <Step title="选择 App Store 部署">
    选择 **发布到 App Store**，将你的应用推送到 TestFlight。
  </Step>

  <Step title="连接 Apple 并提交">
    按提示使用你的 Apple 开发者账号登录。Replit 会在云端构建原生应用并将其提交到 TestFlight。
  </Step>
</Steps>

<Note>
  每个版本的首个构建版本通常需要经过 TestFlight 的 Beta 审核。审核通过后，后续构建版本通常可以更快地发布给测试人员。
</Note>

<div id="habilite-testes-externos">
  ### 启用外部测试
</div>

若要与他人共享你的 TestFlight 构建版本，请在 App Store Connect 中配置外部测试：

1. 在 App Store Connect 中打开你的应用。
2. 依次进入 **TestFlight** 和**外部测试**。
3. 创建测试群组并添加你的构建版本。
4. 提交 Beta 版应用审核 (Apple 要求外部测试人员必须经过此审核) 。
5. 审核通过后，共享 TestFlight 公开链接。

<div id="parte-5-envie-para-a-app-store">
  ## 第 5 部分：提交到 App Store
</div>

当你的构建版本准备好发布时，通过 App Store Connect 提交：

1. 在 App Store Connect 中打开你的应用。
2. 前往 **App Store** 标签页。
3. 填写必需的元数据 (描述、屏幕截图、类别、定价和隐私详情) 。
4. 选择要发布的 TestFlight 构建版本。
5. 提交审核。

<div id="complete-sua-listagem-no-app-store-connect">
  ### 在 App Store Connect 中完善你的应用信息
</div>

Replit 会在 App Store Connect 中创建你的应用条目，但在 Apple 受理提交之前，你仍需填写必要的元数据。以下字段通常为必填项：

* **应用名称和副标题**
* **类别** (主类别，次类别可选)
* **价格与销售范围** (免费或付费，以及地区)
* **隐私政策 URL** (可公开访问)
* **应用隐私详情** (数据收集的“营养标签”)
* **屏幕截图** (必填)
* **支持 URL** (必填)
* **应用审核联系信息** (必填)

<Callout type="note">
  如果你的应用需要登录，请在 App Store Connect 中为应用审核提供演示账号凭据，以便 Apple 进行测试。
</Callout>

<div id="requisitos-de-privacidade">
  ### 隐私要求
</div>

Apple 要求你：

* 提供一个公开的**隐私政策 URL**
* 声明你的**应用隐私**数据处理方式 (包括你使用的第三方 SDK 和服务)

如果你使用了第三方服务 (分析、支付、崩溃报告、广告) ，请查看它们的隐私披露说明，并将相关内容填入你的应用隐私问卷答复中。

<div id="capturas-de-tela">
  ### 屏幕截图
</div>

屏幕截图是必填项，对 App Store 中的转化率有显著影响。

<Tip>
  请使用 App 的真实屏幕截图。请确保截图与您正在提交的当前构建版本一致。
</Tip>

<div id="motivos-comuns-de-rejeio">
  ### 常见被拒原因
</div>

| 问题         | 如何避免                        |
| ---------- | --------------------------- |
| 明显的故障或 bug | 先在 TestFlight 中测试，并在提交前修复问题 |
| 缺少隐私政策     | 提交前添加公开的隐私政策 URL            |
| 截图与应用不符    | 上传当前构建版本的截图                 |
| 审核人员无法访问应用 | 在审核备注中提供演示账号和说明             |
| 内容不完整或仅为占位 | 移除“即将推出”的功能流程和不完整的页面        |
| 权限请求缺乏说明   | 说明你为何需要相机、位置或其他权限           |

<div id="prazos-esperados">
  ### 预计时间
</div>

| 阶段                                | 典型时长                     |
| --------------------------------- | ------------------------ |
| Apple 开发者计划审批                     | 不定 (个人通常为 1–2 天；组织通常更长)  |
| App Store Connect 构建版本处理            | 通常为 10–15 分钟             |
| TestFlight Beta 审核 (某个版本的首个构建版本)  | 通常约需一天                   |
| App Store 审核                      | 通常为 1–2 天                |

<div id="atualizando-seu-aplicativo-aps-o-lanamento">
  ### 发布后更新你的应用
</div>

* **界面与内容更新**：重新部署即可快速上线更新。
* **原生改动** (例如应用图标或权限) ：需向 App Store 提交新的 构建版本。

<div id="lista-de-verificao">
  ## 检查清单
</div>

使用此检查清单确认你已为各阶段做好准备。

**在分享 Expo Go 预览之前：**

* 你能通过 Expo Go 在真机上运行应用
* 应用没有明显的崩溃或断裂的流程

**在推进到 TestFlight 之前：**

* 应用已在 Replit 上发布并正常运行
* 你已订阅 Apple 开发者计划
* 你清楚自己的 Apple 账户是个人账户还是组织账户

**在提交到 App Store 之前：**

* App Store Connect 元数据已填写完整 (名称、类别、地区和支持 URL)
* 隐私政策 URL 可公开访问且内容准确
* 应用隐私信息已填写完整 (包括第三方服务)
* 截图已上传，且与所提交的构建版本一致
* 已填写应用审核联系信息
* 已提供演示账号凭据 (如果应用需要登录)
