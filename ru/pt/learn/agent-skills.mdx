Навыки наделяют Agent новыми возможностями. Они позволяют делиться с Agent вашим опытом, предпочтительными шаблонами и специализированными знаниями, чтобы он выдавал более качественные и стабильные результаты.

<div id="por-que-skills-so-importantes">
  ## Почему навыки важны
</div>

Каждый раз, когда вы работаете с Agent, вы создаёте полезный контекст: решения проблем, дизайнерские решения, предпочтения в выборе фреймворков. Но этот контекст исчезает после завершения чата. Навыки позволяют его сохранить.

Навык для анимации GSAP учит Agent правильно работать с конкретной библиотекой. Навык для дизайн-системы помогает ему применять ваши точные цвета и правила отступов. Навык для исправления ошибок сохраняет решение, чтобы Agent не повторял ту же ошибку. Задачи, которые раньше выполнялись непоследовательно, становятся надёжными.

Навыки также представляют собой [открытый стандарт](https://agentskills.io/specification). Они работают с любым агентом, включая Replit Agent, поэтому их можно переносить между инструментами.

<div id="skills-proativas-vs-reativas">
  ## Проактивные и реактивные навыки
</div>

Подход к определению того, когда и как создавать навыки. Понимание обоих подходов поможет вам работать эффективнее.

<div id="skills-proativas">
  ### Проактивные навыки
</div>

Проактивные навыки — это навыки, которые вы добавляете *до* начала разработки. Изучите библиотеки или паттерны, которые хотите использовать, найдите или создайте для них навыки, а затем начните писать промпты.

**Пример:** Прежде чем создавать сайт-портфолио с нарисованными вручную SVG-анимациями, изучите библиотеки для анимации и найдите GSAP. Установите навык GSAP React, а затем попросите Agent создать анимации. Agent с самого начала обладает необходимыми специализированными знаниями: он понимает API библиотеки, лучшие практики и распространённые паттерны. Без навыка он может создать что-то шаблонное или некорректное.

Этот подход хорошо работает, когда:

* Вы используете популярную библиотеку, особенности работы с которой Agent может не учесть самостоятельно
* Вы хотите обеспечить единообразие дизайна во всём проекте (типографика, отступы, стиль анимации)
* Вы начинаете проект и уже знаете, какое техническое направление выбрать

<div id="skills-reativas">
  ### Реактивные навыки
</div>

Реактивные навыки создаются *после* решения проблемы. Вы находите проблему, отлаживаете её с помощью Agent, исправляете, а затем фиксируете решение, чтобы она не возникла снова.

**Пример:** Работая над Canvas для мобильного приложения, вы замечаете зубчатые края изображений, которые становятся заметнее при увеличении масштаба. Отладка с Agent показывает, что это алиасинг при уменьшении — проблема рендеринга, из-за которой изображения, вопреки ожиданиям, выглядят хуже по мере уменьшения. После внедрения исправления попросите Agent создать навык:

<AiPrompt>
  Создай навык, в котором будет зафиксировано всё, что мы только что узнали об исправлении алиасинга при уменьшении. Включи первопричину, решение и типичные случаи возникновения этой проблемы, чтобы предотвратить её в будущем.
</AiPrompt>

Agent использует историю беседы, чтобы создать навык для конкретного проекта. В следующий раз, когда возникнет эта проблема, вы сможете направить Agent к навыку вместо того, чтобы начинать отладку с нуля.

Этот подход хорошо работает, когда:

* Вы исправили неочевидную ошибку и хотите предотвратить её повторное появление
* Вы узнали что-то об архитектуре своего приложения во время сеанса отладки
* Вы хотите зафиксировать решение, поиск которого потребовал значительных усилий

<div id="sendo-seletivo-com-skills">
  ## Используйте навыки избирательно
</div>

Представьте, что навыки — это инструкции, которые вы дали бы другу, чтобы он нашёл вашу квартиру. Краткий и чёткий список инструкций работает. Папка, полная документации, — нет: ни у кого нет времени всё это читать, а важные детали теряются.

То же касается Agent. Если добавить слишком много навыков, Agent может запутаться. Вдумчиво выбирайте навыки, которые активируете для конкретного проекта, и удаляйте те, которые больше не нужны.

<Note>
  Навыки работают лучше, когда описывают конкретные повторяемые шаблоны, а не содержат общие рекомендации. Сосредоточьтесь на чётких рабочих процессах, устоявшихся соглашениях и проверенных решениях.
</Note>

<div id="criando-skills-de-qualidade">
  ## Создание качественных навыков
</div>

Навыки могут быть сложными и многогранными. Несколько принципов помогут сделать их эффективными:

* **Опишите основной сценарий.** Объясните Agent, как поступить правильно. Если вы ловите себя на перечислении того, чего *не* следует делать, это обычно означает, что стоит пересмотреть весь подход.
* **По возможности используйте скрипты.** Детерминированный скрипт избавляет Agent от необходимости рассуждать и надёжнее, чем просить его каждый раз выполнять одни и те же действия.
* **Ссылайтесь на другие файлы.** Структурируйте навык так, чтобы он ссылался на другие файлы Markdown, и Agent будет загружать только те из них, которые нужны для текущей задачи.
* **Регулярно проводите бенчмарки.** Это позволяет убедиться, что навык действительно работает, а не просто предполагать это.
* **Пишите их сами.** Цель — лаконичный и продуманный контекст, и этого можно достичь, создавая навыки вручную, а не массово генерируя их. Agent может помочь вам подготовить черновик, но доработайте его самостоятельно, чтобы каждая строка была оправданна.
* **Делайте их конкретными.** Не создавайте универсальные навыки для очистки кода или безопасности — они уже встроены в Agent. Ваши навыки должны отражать специфику вас или вашей организации.

Большинство сбоев в навыках можно диагностировать:

* **Навык срабатывает, когда не должен.** Описание слишком широкое. Сузьте его и укажите, когда его *не* следует использовать: «не для постов в блоге или справочной документации» обычно полезнее любой положительной инструкции.
* **Навык срабатывает, но результат неверен.** Инструкции слишком общие. Замените расплывчатые указания вроде «сделайте профессионально» конкретными правилами: точными названиями, чёткими требованиями и явным перечнем того, чего следует избегать.
* **Два навыка конфликтуют.** Исправьте описания так, чтобы оба навыка не срабатывали для одной и той же задачи. Конфликты почти всегда связаны с областью применения, а не с инструкциями.

Навыки устаревают, поэтому относитесь к ним как к документации, которую действительно поддерживаете.

<div id="levando-skills-para-todo-o-workspace">
  ## Навыки для всего Workspace
</div>

Всё сказанное выше относится к навыкам в рамках одного проекта. В команде вы также можете настроить Agent для всего Workspace, чтобы все следовали одним и тем же соглашениям и не приходилось повторно объяснять их в каждом проекте. Настройка Workspace состоит из двух частей:

* **Пользовательские инструкции** — постоянно активные правила, добавляемые в контекст Agent в каждом проекте и с каждым сообщением ещё до того, как кто-либо введёт промпт. Оставьте в них лишь несколько действительно универсальных правил, например: «никогда не храните учётные данные в открытом виде». Поскольку они загружаются на каждом ходе, каждое слово занимает часть бюджета контекста Agent — делайте их краткими.
* **Навыки Workspace** — те же навыки, описанные выше, доступные всем в Workspace и централизованно управляемые. Они почти не расходуют ресурсы, пока не будут вызваны подходящей задачей, поэтому вы можете добавить много навыков, не ухудшая результат.

Простой способ решить, что куда поместить: если правило должно действовать независимо от того, что создаёт пользователь, это пользовательская инструкция; если оно важно только для определённого типа задач, это навык.

Чтобы узнать, как настроить пользовательские инструкции и навыки Workspace, а также кто может ими управлять, см. [Персонализация Agent](/ru/pt/features/agent/agent-customization).

<div id="consideraes-de-segurana">
  ## Соображения безопасности
</div>

Навыки на панели навыков Replit проходят проверку безопасности. Однако навыки можно устанавливать из любых источников — например, из [репозитория с открытым исходным кодом](https://github.com/vercel-labs/skills), в который может внести вклад любой пользователь.

Поскольку навыки содержат инструкции, которым следует Agent, вредоносный навык может указать Agent передать конфиденциальные данные из вашего проекта. Прежде чем устанавливать навык из внешнего источника:

1. **Откройте файл.** Навыки — это обычные файлы Markdown. Перед использованием ознакомьтесь с содержимым файлов в `/.agents/skills/`.
2. **Проверьте источник.** Убедитесь, что навык получен из надёжного репозитория или от проверенного автора.
3. **Проверьте инструкции.** Убедитесь, что навык не ссылается на подозрительные внешние URL-адреса и не запрашивает конфиденциальную информацию.

<Warning>
  Всегда проверяйте навыки из внешних источников перед установкой. Навыки на панели навыков Replit прошли проверку, но навыки, установленные через CLI или скопированные из интернета, её не проходили.
</Warning>

<div id="skills-vs-servidores-mcp">
  ## Навыки и серверы MCP
</div>

Навыки и серверы MCP — два основных способа расширить возможности агентов, и у них разные назначения.

**Навыки** экономно расходуют контекст. До вызова навыка загружается лишь его краткое описание. Используйте навыки для:

* Рабочих процессов и соглашений («как выполнить развёртывание», «чек-лист проверки кода»)
* Справочных материалов (стандарты API, руководства по стилю, дизайн-системы)
* Многоразовых промптов и специализированных знаний (библиотеки анимации, шаблоны фреймворков)

**Серверы MCP** требуют много контекста. Описания всех инструментов загружаются заранее, что при добавлении слишком большого числа серверов может ухудшить качество результата. Используйте серверы MCP для:

* Подключения к внешним сервисам (Notion, Linear, Figma)
* Действий, требующих доступа к API
* Инструментов, которые *выполняют* действия, а не просто предоставляют инструкции

Главное различие: навыки определяют, *как* должен работать ваш агент. Серверы MCP определяют, *к чему* ваш агент может получать доступ. Оба варианта подходят как для агентов программирования, таких как Replit Agent, так и для агентов, которых вы создаёте самостоятельно.
