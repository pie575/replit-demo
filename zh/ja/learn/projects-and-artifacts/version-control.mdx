借助 Replit 的版本控制功能，您可以放心地跟踪和管理代码库，并与他人协作。通过内置的 Git 集成和 GitHub 连接，您可以：

* 跟踪代码更改，保留开发历史
* 与团队成员协作，避免代码冲突或工作成果丢失
* 在 Replit 和 GitHub 之间导入、修改和推送代码
* 使用分支安全地试验新功能

<div id="section">
  ## 什么是版本控制？
</div>

版本控制是一种记录文件随时间推移所做更改的系统，以便日后调用特定版本。在 Replit 中，Git 提供版本控制功能。Git 是跟踪代码更改的行业标准工具，并提供易用的可视化界面，无需掌握命令行知识。

<div id="replitn">
  ### Replit 中的版本控制如何运作
</div>

4 种版本控制方式都基于同一个底层 Git 仓库：

1. **Agent 检查点**会在使用 [Replit Agent](/zh/ja/features/agent/overview) 进行构建时，自动在关键里程碑创建提交。[详细了解检查点和回滚](/zh/ja/features/version-control/checkpoints-and-rollbacks)。
2. **Git 窗格**提供完整 Git 仓库的可视化访问
3. **Git CLI**提供所有 Git 功能的命令行访问
4. **文件历史**跟踪单个文件中的详细更改

依托 Git 强大的版本控制系统，您可以放心选择最适合自己需求的界面。

| 功能            | Agent 检查点       | Git 提交          | 文件历史        |
| ------------- | --------------- | --------------- | ----------- |
| **创建**        | 在适当的节点自动创建      | 手动或按计划创建        | 自动          |
| **粒度**        | 功能级更改           | 任意大小的更改         | 字符级更改       |
| **说明**        | AI 生成的摘要        | 用户编写的消息         | 自动时间戳       |
| **回滚**        | 一键恢复            | 需要 Git 知识       | 一键恢复        |
| **Git 功能**    | 完整的 Git 功能      | 完整的 Git 功能      | 无 Git 功能    |
| **GitHub 同步** | 完整的 GitHub 同步功能 | 完整的 GitHub 同步功能 | 无 GitHub 同步 |

<div id="section-2">
  ## 入门
</div>

将 Git 工具添加到 Project Editor 后，您就可以在 Replit 应用中使用版本控制功能：

1. 前往 Replit 应用的 Tools 部分
2. 选择 **+** 图标以添加新工具
3. 在可用工具列表中选择 **Git**

如需从 GitHub 导入现有项目，请参阅[从 GitHub 导入](/zh/ja/build/import-from-providers)。

<div id="section-4">
  ### 自动版本管理
</div>

<Accordion title="Agent 检查点">
  使用 [Replit Agent](/zh/ja/features/agent/overview) 进行 AI 辅助开发时自动创建的快照。

  **最适用场景**：使用 Replit Agent 开发

  **主要功能**：

  * 在逻辑里程碑自动创建
  * 一键回滚
  * 功能级快照
  * 进度跟踪
  * 无需配置
  * 开发进度可视化时间线

  Agent 检查点会保存到 Git 中，可通过 Git 窗格或 Git CLI 访问。你还可以使用 History 功能直观地查看所有检查点：

  * 按时间顺序查看检查点
  * 详细的检查点说明
  * 直接访问检查点状态
  * 一键回滚到任意检查点
</Accordion>

<Accordion title="文件历史">
  自动按文件保存并跟踪直接在编辑器中进行的非 Agent 更改的版本。

  **最适用场景**：快速恢复最近的文件更改

  **主要功能**：

  * 聚焦单个文件
  * 字符级更改
  * 可视化比较
  * 30 天历史记录
  * 回放功能

  文件历史拥有独立的界面，但底层更改也是 Git 历史记录的一部分。详细了解[文件历史](/zh/ja/features/version-control/file-history)。
</Accordion>

<div id="git">
  ### 基于 Git 的界面
</div>

<Accordion title="Git 窗格">
  无需掌握命令行知识即可进行版本控制操作的 Git 可视化界面。

  **适用场景**：需要 GitHub 集成和可视化工作流的大多数项目

  **主要功能**：

  * 跟踪整个仓库
  * 分支管理
  * 可视化差异对比
  * 一键同步 GitHub
  * 团队协作

  有关 Git 窗格使用方法的详细信息，请参阅 [Git 窗格使用方法](/zh/ja/features/workspace-tools/git-interface)。
</Accordion>

<Accordion title="Git CLI">
  通过 [Shell](/zh/ja/features/workspace-tools/shell) 完整访问 Git 命令行，满足高级操作需求。

  **适用场景**：需要完整 Git 功能的高级用户

  **主要功能**：

  * 完整的 Git 命令集
  * 高级分支策略
  * 自定义工作流
  * 脚本自动化
  * 对仓库的完全控制

  有关常见 Git 命令及其用法，请参阅 [Git 窗格使用方法](/zh/ja/features/workspace-tools/git-interface#using-git-commands-in-shell)。
</Accordion>

<div id="section-5">
  ## 主要功能
</div>

* **可视化 Git 界面**：无需输入 Git 命令，即可管理仓库、提交和分支
* **GitHub 集成**：连接 GitHub 仓库，进行备份和协作
* **从 GitHub 导入**：只需几次点击，即可[将 GitHub 仓库转换为 Replit 应用](/zh/ja/build/import-from-providers)
* **分支管理**：直接在 Project Editor 中创建、切换和合并分支
* **冲突解决**：借助可视化辅助工具识别并解决合并冲突

<div id="section-6">
  ## 使用场景
</div>

**跟踪个人项目**

在开发过程中跟踪代码更改，并在需要时恢复到历史版本。[Git 窗格](/zh/ja/features/workspace-tools/git-interface)会直观地显示更改，让你轻松提交有意义的更新。

**团队协作**

多名开发者可在不覆盖彼此更改的情况下，共同处理同一代码库。为新功能创建分支，准备就绪后再进行合并。详细了解如何[邀请团队成员](/zh/ja/build/invite-teammates)。

<div id="agent">
  ## Agent 检查点
</div>

使用 [Replit Agent](/zh/ja/features/agent/overview) 构建应用时，检查点可提供额外的版本管理层。检查点会在 AI 辅助开发的关键节点自动捕获项目的完整状态，包括项目内容、AI 对话上下文和已连接的数据库。

<div id="section-7">
  ### 检查点的工作原理
</div>

Agent 检查点会保存 Replit 应用整体状态的完整快照：

* **自动创建**：Agent 会在开发过程中的适当节点创建检查点
* **完整状态捕获**：每个检查点都会保存项目内容、AI 记忆和数据库状态
* **实施计划**：在进行更改前，Agent 会提供 Plan 供你审核
* **复杂任务追踪**：对于大型任务，可能会创建多个检查点

<div id="ai">
  ### AI 辅助开发的优势
</div>

Agent 检查点为 AI 辅助构建带来独特优势：

* **安全网**：你可以放心尝试，因为随时都能轻松将整个开发环境恢复到之前的状态
* **进度跟踪**：你可以逐步了解 Agent 如何构建应用
* **逻辑里程碑**：检查点并非任意保存点，而是代表完整功能
* **即时回滚**：只需单击一下，即可恢复到任意先前状态，包括数据库和 AI 上下文

<Info>
  有关检查点捕获的内容及全面回滚功能的更多信息，请参阅[检查点和回滚](/zh/ja/features/version-control/checkpoints-and-rollbacks)。
</Info>

<Tip>
  Agent 检查点非常适合 AI 辅助开发；但对于长期版本跟踪和协作，尤其是使用外部仓库时，请考虑使用 Git 提交。
</Tip>
