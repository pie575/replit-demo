<div id="build-with-teammates">
  ## 팀원과 함께 빌드하기
</div>

Replit에서는 여러 사람이 같은 project에서 동시에 작업할 수 있습니다. 각자 Agent와 새로운 계획 thread를 시작할 수 있고, 모든 팀원의 task가 공유 board에 표시되므로 차례를 기다릴 필요 없이 팀이 함께 빌드할 수 있습니다.

<div id="start-building-with-teammates">

<div id="inviting-teammates">

</div>

2. **Invite**를 클릭하거나 project 링크를 공유합니다
3. 팀원이 참여해 Agent와 새 thread를 시작합니다

<div id="working-in-parallel">
  ### 병렬로 작업하기
</div>

각자 새로운 thread를 만들 수 있으므로 서로를 방해하지 않고 독립적으로 작업할 수 있습니다. 모든 구성원의 task가 공유 Kanban board에 표시되어 누가 무엇을 작업 중인지 한눈에 파악하고 작업이 서로 겹치는 일을 방지할 수 있습니다.

<Note>
  Core에서는 project 전체에서 한 번에 1개의 백그라운드 task만 실행할 수 있습니다. Pro에서는 최대 10개의 task를 병렬로 실행할 수 있어, 여러 사람이 동시에 Agent에게 project의 서로 다른 부분을 building하도록 맡길 수 있습니다.
</Note>

<div id="what-you-can-build-together">
  ## 함께 만들 수 있는 것
</div>

* **팀원끼리 기능 나눠 개발하기**: 한 사람은 frontend를, 다른 사람은 backend를 맡아 각자 자신의 Agent chat에서 작업합니다. Kanban board가 모두의 진행 상황을 한눈에 맞춰 줍니다.
* **새 팀원 온보딩하기**: 새 팀원은 자신의 Agent chat으로 project를 둘러보고, 작동 방식을 질문하고, 곧바로 기여를 시작할 수 있습니다. 다른 사람의 작업을 방해하지 않으면서 말이죠.
* **Pro에서 더 빠르게 출시하기**: 병렬 실행 덕분에 두세 명이 각자 task를 동시에 실행할 수 있습니다. 혼자라면 session 하나를 통째로 써야 할 project도 훨씬 짧은 시간에 끝낼 수 있습니다.

<div id="frequently-asked-questions">
  ## 자주 묻는 질문
</div>

<Accordion title="Agent를 통해 팀원에게 메시지를 보낼 수 있나요?">
  아니요. Agent는 메시징 도구가 아닙니다. 항상 입력을 듣고 있기 때문에 무엇을 입력하든 그대로 실행하려고 합니다. 팀 간 소통에는 Slack, Discord 등 별도의 도구를 사용하세요.
</Accordion>

<Accordion title="서로의 작업을 덮어쓰게 되나요?">
  task system은 각 task마다 격리된 복사본을 제공하면서도 다른 task의 존재를 인식하므로 이런 문제를 방지하는 데 도움이 됩니다. task가 완료되면 이를 메인 버전에 적용하며, 충돌은 이 단계에서 해결합니다.
</Accordion>

<Accordion title="팀원들이 무엇을 하고 있는지 어떻게 확인하나요?">
  Kanban board에서 진행 중인 task를 확인하세요. 커서 위치와 팀원이 보고 있는 파일도 확인할 수 있습니다.
</Accordion>

<Accordion title="project에서 특정 구성원을 제거할 수 있나요?">
  네. Project 소유자는 언제든지 팀원을 관리하고 접근 권한을 취소할 수 있습니다.
</Accordion>
