在 Replit 中，你无需担心丢失工作内容。

Replit 的检查点和回滚系统为整个开发环境提供全面的版本管理和状态管理。

使用 Replit Agent 时，检查点会自动捕获项目的完整状态。这不仅包括代码更改，还包括项目文件、AI 对话上下文和已连接的数据库。

<div id="section">
  ## 什么是检查点？
</div>

**检查点**是 Agent 在开发过程中的关键里程碑自动创建的 Replit App 当前状态的完整快照。与仅跟踪代码变更的传统版本控制不同，Replit 检查点会捕获完整的开发上下文。

检查点就像电子游戏中的存档点。你可以随时恢复到应用正常运行的状态。

<Frame>
  <img src="/assets/mirror/agent-checkpoint-8e5b8b315c02.png" alt="显示回滚选项的 Agent 检查点界面" width="1554" height="876" data-path="images/replitai/agent-checkpoint.png" />
</Frame>

<div id="section-2">
  ### 完整状态快照
</div>

每个检查点都会保存以下内容：

* **项目文件**：所有文件、目录、已安装的软件包和项目设置
* **AI 对话上下文**：通往当前状态的完整对话历史和上下文
* **环境设置**：运行时设置和发布设置
* **Agent 的记忆**：AI 对项目架构、偏好和模式的理解
* **数据库内容**：创建检查点时的数据库数据和架构

这种全面的方式让您可以放心尝试各种更改，因为您知道不仅能恢复代码，还能恢复完整的开发上下文。

<div id="section-3">
  ## 回滚的工作原理
</div>

借助**回滚**功能，只需单击一下，即可将 Replit App 恢复到任意先前的检查点状态。这比传统的 Git `revert` 操作强大得多。

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="显示回滚选项的检查点回滚界面" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

回滚经过精心设计，既安全又可预测：

* **非破坏性预览**：在某些界面中，您可以在实际回滚前预览检查点状态
* **清晰的边界**：每个检查点都代表一个逻辑上的开发里程碑
* **对话连续性**：AI 上下文会被保留，因此您可以从恢复后的状态继续构建
* **即时生效**：回滚会立即应用于整个开发环境

<div id="section-4">
  ### 执行回滚
</div>

回滚到先前的检查点会将项目恢复到该检查点时的状态，包括：

1. **完整的项目状态**：所有项目文件都会恢复到所选检查点时的准确状态
2. **AI 对话上下文**：Agent 对话会恢复到检查点时的状态，保持上下文的连续性
3. **项目设置**：依赖项、软件包和运行时设置
4. **开发环境**：工具设置和项目编辑器设置
5. **数据库内容 (可选)&#x20;**：如果选择此项，数据库将恢复到检查点时的状态

<Info>
  默认情况下，回滚不会更改数据库。若要在回滚中包含开发数据库，请在“Additional rollback options”中选择“Database”。

  **[生产数据库](/zh/ja/features/data-and-storage/development-and-production)**不会通过此回滚功能自动恢复。
  如需了解如何将生产数据库恢复到之前的时间点，请参阅[执行时间点恢复的文档](/zh/ja/features/data-and-storage/development-and-production)。
</Info>

<Warning>
  使用回滚功能会将 Replit App 恢复到之前的状态。这会删除之后进行的所有更改，包括代码编辑。如果选择恢复数据库，数据库变更也会被撤销。
</Warning>

<div id="section-5">
  ### 前滚
</div>

Replit 的检查点支持双向操作。您可以在项目历史记录中前后移动。
这样，您可以在开发时间线上自由往返，无需担心丢失工作内容。

如果回滚过多，或想恢复后续检查点中的更改，可以通过**前滚**将检查点历史记录向前推进。这样，您可以在项目时间线上自由移动，而不会丢失工作内容。

要前滚，请点击 Agent 标签页中的历史记录图标<img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" />，打开历史记录视图，然后选择当前位置之后的检查点。

<Info>
  只有当时间线上当前位置之后存在检查点时，才能前滚。如果您在回滚后进行了新的更改，之后的检查点将成为另一个历史记录分支的一部分。
</Info>

这种双向导航让您能够完全掌控项目时间线，并确保您的工作内容始终可以恢复。

<div id="section-6">
  ## 创建检查点
</div>

Replit 的 AI 工具会在开发过程中的关键节点自动创建检查点。

<div id="agent">
  ### Agent 检查点
</div>

[Replit Agent](/zh/ja/features/agent/overview)会在以下情况下创建检查点：

* **功能完成**：成功实现所请求的功能后
* **重要里程碑**：复杂任务取得重大进展时
* **稳定状态**：已实现的更改经过测试和验证后
* **错误恢复**：尝试修复严重问题前

<div id="section-7">
  ### 检查点的特点
</div>

所有检查点均包含以下内容：

* **AI 生成的说明**：清晰易懂地概述已完成的内容
* **时间戳信息**：便于识别的精确创建时间
* **变更范围**：列出已更改的文件、功能和系统
* **计费信息**：对于 Agent，可透明地追踪每个检查点的成本

<div id="section-8">
  ## 如何使用检查点和回滚
</div>

<div id="section-9">
  ### 查看检查点
</div>

检查点会显示在项目编辑器的多个位置：

**Agent 选项卡**：显示所有 Agent 创建的检查点，以及说明和回滚选项
**Git 窗格**：将检查点显示为 Git 提交，并与完整的版本控制功能集成
**历史记录视图**：在 Agent 对话中点击历史记录图标<img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" />，即可查看所有检查点和进展的完整时间线

<div id="section-10">
  ### 执行回滚
</div>

回滚流程会因从何处开始而略有不同：

<div id="agent-2">
  #### 通过 Agent 选项卡
</div>

<Steps>
  <Step title="前往 Agent">
    打开项目编辑器中的 **Agent** 选项卡，查看 Agent 创建的所有检查点。
  </Step>

  <Step title="选择检查点">
    找到要恢复的检查点，然后选择 **Rollback to here**。
  </Step>

  <Step title="确认回滚">
    查看回滚警告，并确认将应用恢复到所选状态。
  </Step>

  <Step title="确认恢复">
    确认项目文件、数据库和 AI 上下文均与已恢复的检查点状态一致。
  </Step>
</Steps>

<div id="section-11">
  ### 最佳实践
</div>

**策略性地使用检查点**：

* 在重要检查点后测试应用，确保稳定性
* 除自动检查点外，还应手动创建 Git 提交，以便长期跟踪版本
* 查看检查点说明，了解具体更改内容

**回滚注意事项**：

* 回滚前务必确认更改范围
* 考虑对数据库和外部集成的影响
* 将回滚情况告知协作者，确保团队成员了解相关变动

**迭代式开发**：

* 采用渐进式构建，充分利用频繁创建的检查点
* 使用回滚安全地尝试不同的实现方案
* 利用 AI 上下文保留功能，以便在回滚后继续对话

<div id="section-12">
  ## 与版本控制集成
</div>

检查点可与 Replit 更广泛的版本控制生态系统无缝集成：

<div id="git">
  ### Git 集成
</div>

* **创建 Git 提交**：每个检查点都会创建对应的 Git 提交
* **分支兼容性**：检查点遵循分支结构和合并工作流
* **远程同步**：通过 GitHub 集成保持检查点同步
* **命令行访问**：可在使用检查点的同时使用完整的 Git 功能

<div id="section-13">
  ### 协作功能
</div>

* **团队可见性**：所有项目协作者都能查看检查点
* **减少合并冲突**：合理设置检查点可降低发生冲突的可能性
* **共享上下文**：AI 对话上下文可帮助团队成员了解变更
* **实时更新**：协作者可实时查看检查点的创建

<div id="section-14">
  ## 高级功能
</div>

<div id="section-15">
  ### 检查点预览
</div>

部分界面支持检查点预览功能：

* **视觉对比**：查看应用在不同检查点状态下的外观
* **非破坏性探索**：无需实际回滚即可预览
* **跟踪进度**：了解应用的演变过程
* **迭代对比**：比较不同的实现方案

<div id="section-16">
  ### 跨会话回滚
</div>

适用于高级构建者和团队管理员：

* **扩展历史记录**：可访问跨多个开发会话的检查点
* **管理员控制**：团队管理员可跨用户会话执行回滚
* **审计追踪**：完整记录检查点的创建和回滚操作

<div id="section-17">
  ## 使用场景
</div>

<div id="section-18">
  ### 实验性开发
</div>

检查点让你能够大胆尝试：

* 尝试新功能，并且知道可以轻松回退
* 测试不同的架构方案
* 探索替代的界面设计和用户流程
* 在有安全保障的情况下实现复杂集成

<div id="section-19">
  ### 调试与恢复
</div>

发生问题时，检查点可提供可靠的恢复手段：

* 出现错误时回滚到正常运行的状态
* 比较检查点状态以定位问题
* 在数据损坏后恢复数据库完整性
* 从误删或错误修改中恢复

<div id="section-20">
  ### 学习与迭代
</div>

检查点支持学习和探索式开发：

* 比较不同的实现策略
* 通过检查点的演进过程，了解 AI 的决策逻辑
* 探索功能如何演进，加深理解
* 借助可回滚的保障练习新技术
