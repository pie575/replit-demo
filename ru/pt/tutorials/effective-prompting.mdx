<div id="exemplos-rpidos">
  ## Быстрые примеры
</div>

Посмотрите, чем расплывчатые промпты отличаются от эффективных:

<AccordionGroup>
  <Accordion title="Исправление кода" icon="bug">
    **Расплывчато:** &quot;Исправь мой код.&quot;

    **Эффективно:** &quot;Мой скрипт выдаёт ошибку при обработке пользовательского ввода. Похоже, проблема в функции валидации. Можешь помочь отладить часть `validate_input`? Вот сообщение об ошибке: [подробности]&quot;

    Эффективный промпт указывает проблемную область, предполагаемую функцию и предоставляет контекст.
  </Accordion>

  <Accordion title="Разработка функций" icon="hammer">
    **Расплывчато:** &quot;Сделай сайт.&quot;

    **Эффективно:** &quot;Создай простой сайт-портфолио с разделами «Главная», «Обо мне» и «Контактная форма». Используй современный, лаконичный дизайн и добавь примерное содержимое.&quot;

    Эффективный промпт определяет цель, основные функции и желаемую эстетику.
  </Accordion>

  <Accordion title="Улучшение производительности" icon="gauge-high">
    **Расплывчато:** &quot;Не давай ему тормозить.&quot;

    **Эффективно:** &quot;Переработай функцию обработки данных, чтобы она эффективнее работала с большими объёмами входных данных. Можем ли мы использовать другой алгоритм или структуру данных?&quot;

    Объясняйте Agent, *как* улучшить результат, а не задавайте ограничения в отрицательной форме.
  </Accordion>

  <Accordion title="Изменения интерфейса" icon="paintbrush">
    **Расплывчато:** &quot;Добавь анимацию.&quot;

    **Эффективно:** &quot;Анимируй главное изображение на главной странице так, чтобы при первой загрузке страницы оно плавно появлялось с эффектом затухания, создавая уютное впечатление.&quot;

    Укажите конкретный элемент, желаемый эффект, время и предполагаемое впечатление.
  </Accordion>

  <Accordion title="Сложные системы" icon="server">
    **Расплывчато:** &quot;Создай бэкенд.&quot;

    **Эффективно:** &quot;Настрой серверную логику. Реализуй аутентификацию пользователей (регистрация/вход) и создай API-эндпоинт для безопасного получения данных профиля пользователя.&quot;

    Разбивайте крупные задачи на конкретные функции.
  </Accordion>
</AccordionGroup>

<div id="planeje-primeiro">
  ### Сначала планируйте
</div>

<Tip>Прежде чем писать промпты, опишите функции и пользовательские сценарии вашего приложения. Чёткий план помогает формулировать более точные промпты.</Tip>

Продумайте структуру приложения так, как это сделал бы менеджер продукта. Разбейте общую цель на логические этапы.

**Вместо:** «Создай приложение для управления задачами».

**Попробуйте:** «1. Создай базовую HTML-структуру с полем ввода и списком задач. 2. Добавь JavaScript для добавления задач. 3. Используй базу данных для хранения задач. 4. Добавь возможность отмечать задачи как выполненные».

Затем составляйте промпты для Agent на каждом этапе.

<div id="construa-incrementalmente">
  ### Создавайте приложение постепенно
</div>

Используйте [**чекпоинты**](/ru/pt/core-concepts/agent#checkpoints), чтобы сохранять прогресс после каждого успешного этапа. Если что-то сломается, вы сможете вернуться к рабочему состоянию и попробовать другой подход.

**Вместо:** «Создайте полноценную платформу электронной коммерции».

**Попробуйте:** «Настройте базовый полностековый проект сайта электронной коммерции с регистрацией и входом пользователей через Replit Auth». Затем добавляйте промпты для каталога товаров, корзины и оформления заказа.

<div id="seja-especfico">
  ### Будьте конкретны
</div>

Точно опишите, что вам нужно: форматы результата, ограничения, пограничные случаи.

**Вместо:** «Добавь форму обратной связи».

**Попробуйте:** «Создай страницу с формой обратной связи по адресу `/contact` с полями:

* Имя (обязательное)
* Электронная почта (обязательное, в корректном формате)
* Сообщение (обязательное, минимум 10 символов)

При отправке отправляй данные формы на `contact@mydomain.com`».

<div id="use-linguagem-positiva">
  ### Используйте позитивные формулировки
</div>

Говорите о том, что вы *хотите* получить, а не о том, чего нужно избегать.

**Вместо:** «Не делайте страницу профиля пользователя перегруженной».

**Попробуйте:** «Создайте аккуратную страницу профиля пользователя. Выведите имя пользователя крупным шрифтом, ниже — электронную почту и дату регистрации. Добавьте кнопку „Редактировать профиль“».

<div id="mantenha-a-simplicidade">
  ### Не усложняйте
</div>

Используйте простые и понятные формулировки. Разбивайте сложные запросы на пункты списка.

**Вместо:** «Реализуйте необходимую серверную инфраструктуру для обеспечения динамической генерации и получения артефактов пользовательского контента».

**Попробуйте:** «Создайте в бэкенде функциональность для публикации постов блога пользователями. Пользователь вводит заголовок и текст поста. Сохраняйте посты в базе данных».

<div id="trabalhando-com-contexto">
  ## Работа с контекстом
</div>

<div id="fornea-arquivos-relevantes">
  ### Предоставляйте нужные файлы
</div>

Указывайте конкретные файлы вместо того, чтобы прикреплять весь проект целиком.

**Вместо:** (прикрепив всё) «Реализуй страницу профиля пользователя на основе нашей дизайн-системы».

**Попробуйте:** «Создай страницу профиля пользователя. Получи данные пользователя с серверного эндпоинта. Оформи в соответствии с [URL документации по дизайну] и приведи в соответствие с этим макетом: [прикрепите `profile_mockup.jpg`]».

<Tip>Начинайте новую беседу при переходе к несвязанным задачам. Это избавит от путаницы, вызванной накоплением контекста.</Tip>

<div id="mostre-exemplos">
  ### Показывайте примеры
</div>

Устраните неоднозначность с помощью конкретных примеров — фрагментов кода, образцов данных или скриншотов.

**Вместо:** «Улучши внешний вид карточек товаров».

**Попробуйте:** «Переделай карточки товаров на странице магазина. В каждой карточке должны отображаться изображение товара, название, цена и кнопка „Добавить в корзину“ — примерно как в этой раскладке: [прикрепите скриншот]. Используй светло-серую рамку».

<div id="depurao-eficaz">
  ## Эффективная отладка
</div>

При возникновении ошибок укажите:

* **Точный** текст сообщения об ошибке
* Соответствующие фрагменты кода
* Имена файлов, в которых возникает ошибка
* Что именно вы пытались сделать
* Шаги, которые вы уже предприняли

**Вместо:** «Моя страница входа не работает».

**Попробуйте:** «При входе с верными учётными данными на `/login` в консоли браузера появляется ошибка „User not found“. Похоже, проверка по базе данных не срабатывает. Вот код обработки входа в `auth.js`».

<div id="pea-orientao">
  ## Попросите совета
</div>

<Tip>Переключитесь в режим Plan, чтобы изучить варианты до начала разработки. Спросите у Agent о библиотеках, подходах и компромиссах.</Tip>

**Вместо:** «Добавь платежи».

**Попробуйте:** «Какие есть хорошие способы принимать платежи по кредитным картам в веб-приложении, созданном на Replit? Мне нужно что-то относительно простое в интеграции».

<div id="itere-nos-seus-prompts">
  ## Дорабатывайте свои промпты
</div>

Ваш первый промпт может оказаться неидеальным — это нормально. Если результат получился не таким, как нужно:

* Добавьте больше деталей
* Приведите пример
* Упростите формулировку
* Попробуйте объяснить иначе

**Исходный вариант:** «Создай шапку для моего сайта».

**Уточнённый вариант:** «Создай компонент фиксированной шапки с логотипом сайта слева и навигационными ссылками (Главная, О нас, Контакты) справа».

<div id="resumo">
  ## Итоги
</div>

Эффективный промптинг сводится к следующему:

* **Планируйте** заранее, до написания промптов
* **Стройте** приложение постепенно, используя checkpoints
* **Формулируйте требования** конкретно
* **Давайте контекст** — примеры и подходящие файлы
* **Повторяйте попытки**, если результат получился не совсем таким, как нужно

Освойте эти принципы — и вы будете создавать приложения с Agent гораздо быстрее.
