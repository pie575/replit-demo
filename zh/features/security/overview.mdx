从 Replit 发布后，你的 project 会面向真实流量。Replit 安全工具可帮助你发现漏洞、使用 Agent 修复已确认的问题，并留存证据以备审计。

<div id="why-security-matters">
  ## 安全为何重要
</div>

* 已发布的 project 可从公共互联网访问，包括公开路由和 API。
* 现代 project 依赖大量软件包，发布之后仍可能出现新的 CVE。
* AI 生成的代码同样需要安全审查，尤其是在身份验证、数据库查询、Secrets 和数据处理方面。
* 合规项目通常要求提供依赖清单、漏洞跟踪和修复情况的证据。

<div id="where-to-start">
  ## 从哪里开始
</div>

* 正在安装软件包？[包防火墙](/zh/features/security/package-firewall)会在安装时拦截恶意依赖，默认开启。
* 只在单个 project 中工作？请使用 [Project 安全中心](/zh/features/security/project-security-center)。
* 需要在整个 workspace 范围内审计？请使用 [Workspace 安全中心](/zh/features/security/workspace-security-center)。
* 想指定开发资源的运行地区？请阅读 [Workspace 地理位置](/zh/features/collaboration/workspace-geography)。若要指定已发布 Project 的运行地区，请阅读 [Project 地理位置](/zh/features/publishing/project-geography)。
* 需要查看术语定义？请阅读[安全概念](/zh/features/security/concepts)。

Replit 的安全工具覆盖应用生命周期中的不同环节，并相互协同：

* **安装时**：[包防火墙](/zh/features/security/package-firewall)会在软件包下载前拦截恶意和被篡改的软件包。
* **安装后**：[自动依赖扫描](/zh/features/security/project-security-center#automatic-dependency-scans)可检测新披露的 CVE，Auto-Protect 还能为其准备 Agent 补丁。
* **发布前**：[Security Agent](/zh/features/security/agent-security-scans) 会审计你的代码库，查找代码、依赖和隐私方面的漏洞。

大多数扫描工作都遵循同一个 loop：扫描、查看 findings、用 Agent 修复、重新发布，并在需要时导出证据。

<div id="where-security-lives-in-the-product">
  ## 安全功能在产品中的位置
</div>

<div id="in-a-project">
  ### 在 project 中
</div>

在 project 的 **Tools** 面板中选择 **安全中心**，即可在发布前查看 project 级别的 findings、运行 Agent 安全扫描并排查依赖漏洞。

使用 [Agent 安全扫描](/zh/features/security/agent-security-scans) 审查源代码；如果还需要从外部测试运行中的应用，请使用 [Level 3 黑盒渗透测试](/zh/features/security/black-box-pen-tests)。

<div id="in-your-workspace">
  ### 在 workspace 中
</div>

在主页侧边栏选择 **Security**，即可查看各个 project 的漏洞情况，按暴露程度对 findings 排定优先级，并追踪 workspace 级别的扫描历史。

</Frame>

<div id="in-publishing-and-settings">
  ### 在发布与设置中
</div>

* 在 **Publish** &gt; **Advanced** 中，使用 **Block publishing of critical vulnerabilities** (阻止发布严重漏洞) 阻止严重级别的 findings 上线。
* 在 **Settings** &gt; **Account** &gt; **Advanced** 中，为 Agent 准备的依赖修复方案设置 Auto-Protect 严重性阈值。
