La configuration des machines détermine la puissance des serveurs qui exécutent votre app publiée. Replit applique une valeur par défaut adaptée, si bien que la plupart des créateurs n&#39;ont jamais besoin de la modifier. Envisagez une configuration plus puissante si votre app devient lente en cas de forte charge ou si elle traite de grandes quantités de données en mémoire.

Pour la modifier, ouvrez l&#39;outil Publishing, sélectionnez **Adjust settings**, puis sélectionnez **Edit** en regard de **Machine configuration**.

<div id="the-settings">
  ## Les paramètres
</div>

* **Processeur** : la quantité de travail simultané que chaque serveur peut traiter. Un plus grand nombre de vCPU est utile lorsque de nombreuses personnes utilisent votre app en même temps.
* **Mémoire (RAM)** : la quantité de données que votre app peut conserver en mémoire. Davantage de RAM est utile pour les fichiers volumineux, les médias ou les traitements gourmands en données.
* **Nombre maximal de machines** : Autoscale uniquement. Le nombre maximal de serveurs que Replit peut ajouter lorsque votre app est très sollicitée. Votre app ne dépasse jamais ce nombre, ce qui plafonne votre coût maximal.

<div id="what-it-costs">
  ## Ce que cela coûte
</div>

Le volet affiche deux chiffres au fil de votre configuration :

* **Par machine** : le coût horaire d&#39;un serveur avec la configuration choisie.
* **En trafic maximal** : le coût horaire si votre app est suffisamment sollicitée pour utiliser toutes les machines jusqu&#39;à la limite que vous avez définie.

Les coûts sont exprimés en compute units, une unité de calcul cloud fondée sur le processeur et la mémoire que vous choisissez. Pour connaître les tarifs en vigueur et le mode de facturation de l&#39;utilisation, consultez la [facturation à l&#39;usage](/fr/billing/about-usage-based-billing#2-compute-units).

<div id="how-billing-differs-by-deployment-type">
  ## Différences de facturation selon le type de deployment
</div>

Une même configuration est facturée différemment selon votre [type de deployment](/fr/features/publishing/deployment-types) :

* **Autoscale** : vous payez uniquement pendant le traitement des requêtes. Lorsque votre app est inactive, elle descend à zéro instance et son exécution ne coûte rien.
* **Reserved VM** : votre serveur est toujours actif, vous payez donc un coût mensuel fixe pour la configuration choisie.
* **Static** : aucune machine n&#39;exécute votre site, la configuration de la machine ne s&#39;applique donc pas.
* **Scheduled** : vous payez la machine pendant chaque exécution planifiée.

<div id="apply-your-changes">
  ## Appliquez vos modifications
</div>

Republiez votre app après avoir modifié la configuration. Les nouveaux paramètres de machine prennent effet avec le nouveau deployment.
