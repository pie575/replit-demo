Replit Agent는 **Plan 모드**와 **Build 모드**라는 두 가지 상호작용 모드를 제공합니다. 두 모드를 함께 사용하면 아이디어를 먼저 충분히 정리한 다음 확신을 갖고 구현할 수 있습니다.

<div id="what-is-plan-mode">
  ## Plan 모드란?
</div>

[Plan 모드](/ko/features/agent/plan-mode)에서는 코드를 전혀 수정하지 않고 Agent와 함께 brainstorming하고, 질문하고, 작업을 계획할 수 있습니다. 아이디어를 자유롭게 탐색해 보는 협업 기획 session이라고 생각하면 됩니다.

Plan 모드는 다음과 같은 경우에 적합합니다:

* **아이디어 brainstorming**: 하나를 정하기 전에 다양한 접근 방식을 살펴봅니다
* **복잡한 project 나누기**: building을 시작하기 전에 구조화된 작업 목록를 받아봅니다
* **학습과 이해**: 기술, 패턴, codebase에 대해 질문합니다
* **아키텍처 설계**: 코드를 작성하기 전에 앱 구조를 설계합니다

<Info>
  Plan 모드에서 Agent는 project를 읽고 방향을 제안하지만, 파일을 변경하지는 않습니다. 구현할 준비가 되면 Build 모드로 전환하거나 plan을 승인해 자동으로 building을 시작하세요.
</Info>

<div id="what-is-build-mode">
  ## Build 모드란?
</div>

Build 모드는 Agent가 코드를 작성하고 파일을 수정하며 project에 기능을 직접 구현하는 기본 모드입니다. 아이디어를 현실로 만드는 공간입니다.

다음과 같은 작업을 할 준비가 되었다면 Build 모드를 사용하세요:

* **새 기능 만들기**: Agent에게 다음 기능의 코드 작성을 맡기세요
* **앱 설정하기**: dependencies를 설치하고, database를 구성하고, 서비스를 연결하세요
* **issues 해결하기**: Agent가 codebase의 문제를 디버깅하고 해결하도록 하세요
* **코드 리팩터링**: 기존 코드의 구조와 구성을 개선하세요

<div id="using-both-modes-together">
  ## 두 모드를 함께 사용하기
</div>

**Plan 모드와 Build 모드는 순서대로 사용할 때 가장 효과적입니다.** 먼저 계획을 세워 생각을 정리한 다음, 명확한 방향을 가지고 build하세요.

<Steps>
  <Step title="Plan 모드로 시작하기">
    Plan 모드로 전환한 뒤 무엇을 build하고 싶은지 설명하세요. Agent는 코드를 전혀 건드리지 않고 요구 사항를 함께 정리하고, 접근 방식을 제안하며, 발생할 수 있는 문제를 짚어 줍니다.
  </Step>

  <Step title="작업 목록 생성하기">
    Agent에게 개발 계획을 만들어 달라고 요청하세요. Agent는 project를 우선순위와 dependencies가 명확한 구체적이고 실행 가능한 task로 나눠 줍니다.

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="우선순위와 dependencies가 표시된 생성된 작업 목록" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="검토하고 다듬기">
    제안된 계획을 검토하세요. follow-up 질문을 하거나, changes를 요청하거나, 다른 접근 방식을 살펴볼 수 있습니다. 계획이 원하는 방향과 맞아떨어질 때까지 반복하세요.
  </Step>

  <Step title="build 시작하기">
    계획이 만족스러우면 **Start building**을 선택하세요. Agent가 자동으로 Build 모드로 전환해 승인된 task를 구현하기 시작합니다.

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="Plan mode와 Build mode 옵션이 표시된 모드 선택기" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="진행 상황 추적하기">
    Agent가 작업 목록를 처리해 나가는 동안 진행 상황을 확인하세요. task가 완료될 때마다 체크포인트가 생성되므로 changes를 검토하고 필요하면 roll back할 수 있습니다.
  </Step>
</Steps>

<div id="when-to-use-each-mode">
  ## 각 모드를 사용해야 할 때
</div>

<CardGroup cols={2}>
  <Card title="Plan 모드를 사용할 때" icon="lightbulb">
    * 새 project를 시작하면서 방향을 잡아야 할 때
    * 여러 접근 방식을 살펴보고 싶을 때
    * task가 복잡해서 잘게 나눠야 할 때
    * 구현하기 전에 먼저 이해하고 싶을 때
    * 어떤 방법이 최선인지 확신이 서지 않을 때
  </Card>

  <Card title="Build 모드를 사용할 때" icon="hammer">
    * 원하는 바가 무엇인지 정확히 알고 있을 때
    * 바로 실행할 수 있는 명확한 계획이 준비됐을 때
    * 간단한 수정이나 작은 changes를 적용할 때
    * 승인된 작업 목록를 따라 진행할 때
    * 구현 속도가 가장 중요할 때
  </Card>
</CardGroup>

<Tip>
  **어느 쪽을 골라야 할지 모르겠나요?** 요청에 여러 기능이나 큰 changes가 포함된다면 Plan 모드로 시작하세요. 단순하고 명확하게 정의된 task라면 바로 Build 모드로 진행하세요.
</Tip>

<div id="key-differences">
  ## 주요 차이점
</div>

| 기능         | Plan 모드                          | Build 모드   |
| ---------- | ---------------------------------- | ------------ |
| **목적**     | 브레인스토밍, 계획 수립, 학습                  | 구현 및 개발      |
| **코드 변경**  | 없음(읽기 전용)                          | 파일 생성 및 수정   |
| **결과물**    | 아이디어, 작업 목록, 가이드               | 동작하는 코드와 기능  |
| **적합한 상황** | 복잡한 project, 탐색                    | 명확한 task, 구현 |
| **전환**     | &quot;Start building&quot;을 클릭해 전환 | 이미 구현 모드     |

<div id="best-practices">
  ## 모범 사례
</div>

<div id="getting-the-most-from-plan-mode">
  ### Plan 모드 200% 활용하기
</div>

* **요구 사항을 구체적으로 작성하세요**: 자세히 설명할수록 더 나은 계획이 만들어집니다
* **추가 질문을 하세요**: 이해되지 않는 제안은 명확히 물어보세요
* **예시를 요청하세요**: Agent에게 코드 조각이나 패턴을 보여달라고 요청하세요
* **장단점을 논의하세요**: 여러 접근 방식의 장단점을 살펴보세요
* **아이디어를 다듬으세요**: 만족스러울 때까지 계획을 개선하세요

<div id="seamless-transitions">
  ### 매끄러운 전환
</div>

* **빌드 전 검토**: 승인하기 전에 항상 작업 목록을 검토하세요
* **작게 시작하기**: 전체 플랜이 부담스럽게 느껴진다면 일부 작업부터 시작하세요
* **체크포인트 활용**: Agent가 빌드하면서 체크포인트를 생성하므로 언제든 이전 상태로 되돌릴 수 있습니다
