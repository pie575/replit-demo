Lorsque vous développez des applications mobiles sur Replit, vous pouvez rencontrer des problèmes d&#39;aperçu, de regroupement ou de dépendances de packages. Ce guide vous aide à résoudre les problèmes courants, en commençant par des solutions rapides avant de passer à des étapes de débogage plus approfondies.

<div id="quick-fixes">
  ## Correctifs rapides
</div>

Essayez d’abord ces solutions : elles résolvent la plupart des problèmes :

| Problème                                                 | À essayer                                                                     |
| -------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Les modifications ne s’affichent pas sur votre téléphone | Secouez votre téléphone pour ouvrir le menu Expo, puis appuyez sur **Reload** |
| Les modifications ne s’affichent pas dans l’aperçu       | Appuyez sur **R** dans la console pour recréer le bundle                      |
| L’App est bloquée ou ne répond pas                       | Arrêtez, puis redémarrez l’App depuis la console                              |

<div id="common-issues">
  ## Problèmes courants
</div>

<AccordionGroup>
  <Accordion title="Les modifications n’apparaissent pas sur mon appareil">
    Si vous apportez des modifications, mais ne les voyez pas sur votre téléphone :

    1. **Secouez votre téléphone** pour ouvrir le menu développeur d’Expo
    2. Appuyez sur **Reload** pour retélécharger le bundle

    Dans l’aperçu web, appuyez sur **R** dans la console pour déclencher une nouvelle compilation du bundle.

    Si les modifications n’apparaissent toujours pas, essayez de vider le cache (voir [Vider le cache Metro](#clear-the-metro-cache) ci-dessous).
  </Accordion>

  <Accordion title="Écran d’erreur rouge dans Expo Go">
    Un écran d’erreur rouge indique généralement une erreur JavaScript ou un module manquant. Lisez le message d’erreur : il indique souvent le fichier et la ligne concernés.

    **Causes fréquentes :**

    * Un package n’est pas installé ou n’est pas à la bonne version
    * Un module fonctionne sur le web, mais pas en natif (ou inversement)
    * Une erreur de syntaxe dans votre code

    **À essayer :**

    1. Lisez attentivement le message d’erreur : il vous indique souvent exactement ce qui ne va pas
    2. Demandez à Agent de vous aider à corriger l’erreur en partageant le message
    3. Si l’erreur mentionne un package spécifique, essayez de réinstaller les dépendances (voir [Réinstaller les packages](#reinstall-packages))
  </Accordion>

  <Accordion title="L’App fonctionne sur le web, mais plante sur le téléphone (ou inversement)">
    Certains packages ou fonctionnalités se comportent différemment selon les plateformes. React Native compile pour trois cibles : iOS, Android et le web. Une bibliothèque qui fonctionne sur le web peut ne pas prendre en charge le natif ou nécessiter une configuration différente.

    **À essayer :**

    1. Vérifiez dans sa documentation si le package prend en charge votre plateforme
    2. Demandez à Agent : « Ce package est-il compatible avec Expo Go ? »
    3. Envisagez de déplacer cette fonctionnalité vers votre serveur si elle n’est pas prise en charge sur mobile

    <Tip>
      Lorsque vous recherchez des packages, cherchez « compatible avec Expo » ou consultez la [documentation du SDK Expo](https://docs.expo.dev/versions/latest/) pour connaître les modules pris en charge.
    </Tip>
  </Accordion>

  <Accordion title="Le code QR ne se scanne pas ou l’App ne se connecte pas">
    **Vérifiez votre réseau :**

    * Votre téléphone et votre ordinateur doivent être connectés au même réseau WiFi
    * Certains réseaux d’entreprise ou publics bloquent la connexion

    **Essayez le mode tunnel :**
    Si vous êtes sur un réseau restreint, le mode tunnel achemine le trafic via les serveurs d’Expo. Demandez à Agent de démarrer l’App en mode tunnel, ou exécutez `npx expo start --tunnel` dans le Shell.

    **Redémarrez Expo Go :**
    Fermez complètement Expo Go et rouvrez-le avant de scanner le code.
  </Accordion>

  <Accordion title="La compilation prend beaucoup de temps">
    La première compilation est toujours plus lente, car il n’y a pas de cache. Les compilations suivantes devraient être plus rapides.

    **Ce qui affecte le temps de compilation :**

    * Le nombre de packages dans votre projet
    * La première exécution après avoir vidé le cache
    * La vitesse du réseau lors du téléchargement des packages

    Si les compilations sont systématiquement lentes, vérifiez si vous avez des packages inutiles installés.
  </Accordion>

  <Accordion title="Erreurs de module introuvable">
    Lorsque vous voyez « Unable to resolve module » ou « Module not found » :

    1. Le package n’est peut-être pas installé : demandez à Agent de l’installer
    2. Le package est peut-être installé, mais le cache est obsolète : videz le cache
    3. Le package n’existe peut-être pas ou son nom est mal orthographié : vérifiez le nom du package

    Essayez de [réinstaller les packages](#reinstall-packages) si le module devrait exister.
  </Accordion>
</AccordionGroup>

<div id="debugging-commands">
  ## Commandes de débogage
</div>

Lorsque les solutions rapides ne suffisent pas, ces commandes permettent de réinitialiser différents caches et états. Exécutez-les dans le Shell.

<div id="clear-the-metro-cache">
  ### Vider le cache de Metro
</div>

Metro est le bundler qui compile votre code React Native. Vider son cache force une nouvelle compilation.

Dans le Shell, exécutez :

```bash theme={null}
npx expo start --clear
```

Cela vide le cache du bundler et redémarre le serveur de développement. Vous verrez « Le cache du bundler est vide. Reconstruction en cours. » dans la sortie.

<Tip>
  Si vous rencontrez souvent des problèmes de cache, vous pouvez ajouter `-c` à votre commande de démarrage. Demandez à Agent de mettre à jour la commande de développement pour y inclure l’indicateur d’effacement.
</Tip>

<div id="reinstall-packages">
  ### Réinstaller les packages
</div>

Si vous rencontrez des erreurs de module ou des incompatibilités de version, réinstaller les packages peut souvent résoudre le problème.

Dans le Shell, exécutez :

```bash theme={null}
rm -rf node_modules && npm install
```

Cette commande supprime tous les packages installés et les réinstalle à partir de zéro selon votre `package.json`.

<Note>
  Si votre projet utilise un autre gestionnaire de packages (comme `bun` ou `pnpm`), utilisez la commande d’installation appropriée : `bun install` ou `pnpm install`.
</Note>

<div id="check-for-version-mismatches">
  ### Vérifier les incompatibilités de versions
</div>

Expo Doctor analyse votre projet afin de détecter les problèmes courants, tels que les incompatibilités de versions entre les packages.

Dans le Shell, exécutez :

```bash theme={null}
npx expo-doctor
```

Examinez la sortie pour repérer les avertissements. Si elle propose des correctifs, évaluez-les attentivement : ne mettez pas les packages à niveau aveuglément, car cela pourrait entraîner de nouveaux problèmes.

<Warning>
  Ne mettez à jour les packages que s&#39;il y a une raison précise de le faire. Les mettre à niveau « juste parce que » peut casser votre App si la nouvelle version introduit des changements incompatibles.
</Warning>

<div id="full-reset">
  ## Réinitialisation complète
</div>

Lorsque rien d’autre ne fonctionne, une réinitialisation complète vide tous les caches et réinstalle tout.

<Accordion title="Option nucléaire : commande de réinitialisation complète">
  Cette commande supprime tous les caches et réinstalle les packages à partir de zéro. Utilisez-la en dernier recours.

  ```bash theme={null}
  rm -rf node_modules .expo && npm cache clean --force && npm install && npx expo start --clear
  ```

  **Cette commande :**

  1. `rm -rf node_modules` — Supprime les packages installés
  2. `rm -rf .expo` — Supprime le cache local d’Expo
  3. `npm cache clean --force` — Vide le cache global de npm
  4. `npm install` — Réinstalle tous les packages
  5. `npx expo start --clear` — Démarre avec un nouveau cache Metro

  Après avoir exécuté cette commande, votre prochaine compilation prendra plus de temps, car tout sera reconstruit à partir de zéro.
</Accordion>

<div id="clear-cache-on-your-device">
  ### Vider le cache de votre appareil
</div>

Si l’app sur votre téléphone semble toujours utiliser un ancien code même après son rechargement :

* **iOS** : dans Expo Go, accédez aux **paramètres** et appuyez sur **Vider le cache**
* **Android** : accédez à **Paramètres &gt; Apps &gt; Expo Go &gt; Stockage &gt; Vider le cache**

<div id="quick-reference">
  ## Référence rapide
</div>

| Problème                                    | À essayer en premier             | Ensuite                           |
| ------------------------------------------- | -------------------------------- | --------------------------------- |
| Modifications non visibles                  | Secouer le téléphone → Recharger | Vider le cache Metro              |
| Erreurs du bundler                          | `npx expo start --clear`         | Supprimer node&#95;modules        |
| Module introuvable                          | Réinstaller les dépendances      | Réinitialisation complète         |
| Avertissements d’incompatibilité de version | Exécuter `npx expo-doctor`       | Appliquer les correctifs suggérés |
| Nouveau package non fonctionnel             | Redémarrer le serveur            | Vider le cache Metro              |
| app.json modifié                            | Redémarrer le serveur            | —                                 |

<div id="getting-more-help">
  ## Obtenir de l’aide supplémentaire
</div>

Si le problème persiste :

* **Demandez à Agent** : Décrivez l’erreur et les solutions que vous avez déjà essayées. Agent peut souvent diagnostiquer et résoudre les problèmes.
* **Consultez la documentation d’Expo** : Le [guide de dépannage d’Expo](https://docs.expo.dev/troubleshooting/overview/) couvre d’autres scénarios.
* **Recherchez l’erreur** : Copiez le message d’erreur exact et recherchez-le : quelqu’un l’a probablement déjà rencontré.
