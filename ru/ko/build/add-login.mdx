Вы уже видели Velocity в разделе [Добро пожаловать в Replit](/ru/ko/welcome) — это приложение для аренды премиальных суперкаров. Сейчас любой, кто откроет публичный URL, видит все бронирования. Но вряд ли кто-то станет бронировать Lamborghini анонимно. Если добавить вход в систему, у каждого клиента появятся собственные бронирования и сохранённые автомобили.

<div id="agent">
  ## Просим Agent добавить вход
</div>

Для Velocity используем Clerk. Интеграция Clerk в Replit даёт приложению фирменный экран входа, учётные записи клиентов, которые живут внутри самого Velocity (а не учётные записи Replit), и полный контроль над внешним видом — как раз то, что нужно премиальному прокатному бренду. Agent всё подготовит автоматически, так что регистрироваться в панели Clerk и вставлять ключи не придётся.

  Требуйте входа перед бронированием автомобиля или добавлением в избранное.<br />

Agent подготовит тенант Clerk для Velocity, добавит компоненты входа, защитит аутентификацией процесс бронирования, свяжет каждое бронирование с вошедшим клиентом и добавит выход из учётной записи. Следите за ходом сборки в чате Agent.

<div id="section">
  ## Тестирование с двумя клиентами
</div>

Одной учётной записи недостаточно — чтобы убедиться, что бронирования разделены, нужны две.

1. Откройте Velocity в Preview и просмотрите автомобили, не выполняя вход. Список автомобилей должен по-прежнему отображаться.
2. Нажмите Reserve у автомобиля. Вас должно перенаправить на экран входа Clerk.
3. Зарегистрируйтесь со своей электронной почтой и завершите бронирование (например, забронируйте 911 на выходные).
4. Выйдите из учётной записи. Раздел «My bookings» должен исчезнуть, а процесс бронирования — снова запросить вход.
5. Откройте Preview в окне инкогнито и зарегистрируйтесь с другой электронной почтой. Забронируйте другой автомобиль.
6. Вернитесь в первое окно, войдите в систему и убедитесь, что видите только свои бронирования, а не бронирования второго клиента.

Если клиенты видят бронирования друг друга, значит, бронирования пока не привязаны к вошедшему пользователю. Опишите Agent точные симптомы.

  Свяжите каждое бронирование и сохранённый автомобиль с вошедшим клиентом, чтобы каждый видел только свои.<br />
  Расскажите, как это проверить с помощью двух тестовых учётных записей.
</AiPrompt>

<div id="url">
  ## Деплой и вход по публичному URL
</div>

Задеплойте Velocity заново из чата Agent или плитки Publishing, затем откройте публичный URL в новой вкладке и войдите. Clerk подготовлен в раздельных окружениях разработки и продакшена — Agent автоматически подключает продакшен-учётные данные к задеплоенному приложению, поэтому вход по публичному URL работает сразу.

Теперь у Velocity есть настоящие клиенты. Каждый входит в свой собственный гараж бронирований — и никто другой его не видит.

<div id="section-3">
  ## Нужна дополнительная помощь?
</div>

* **Скрыто всё приложение:** попросите Agent оставить каталог автомобилей общедоступным и защитить только страницы бронирований и учётной записи.
* **Клиенты видят чужие бронирования:** попросите Agent привязать каждое бронирование и сохранённый автомобиль к вошедшему в систему клиенту.
* **Вход работает в Preview, но не после деплоя:** откройте публичный URL в новой вкладке и сообщите Agent точный текст ошибки. Убедитесь, что Agent подготовил продакшн-окружение Clerk.
* **Нужен быстрый вход без настройки для прототипа:** Replit Auth использует существующую учётную запись Replit клиента и не требует тенанта Clerk — см. [Replit Auth](/ru/ko/features/auth-and-identity/authentication).
