Agent поддерживает четыре типа интеграций, чтобы вы могли быстро пройти путь от идеи до приложения:

* **Под управлением Replit**: встроенные интеграции, которые работают автоматически. Как только вы создаёте приложение, Agent сразу может их использовать.
* **Коннекторы**: собственные интеграции Replit с официальной поддержкой. Достаточно один раз войти в сервис — и Agent сможет читать и записывать данные прямо из чата: получать данные, создавать записи, отправлять сообщения — и использовать всё это в приложении.
* **Внешние интеграции**: надёжные сторонние сервисы, которые можно использовать при разработке. Попросите Agent настроить их и укажите ключи API.
* **Сервисы Agent**: платные сторонние API, которые Agent использует в фоновом режиме при Build, — ключи API не нужны. Стоимость использования списывается с ваших кредитов Replit.

<Note>
  **Доступность по планам**: для большинства коннекторов требуется подписка Core, Pro или Enterprise, но некоторые доступны и на бесплатном плане. В каталоге коннекторов вашего рабочего пространства показано, какие коннекторы доступны на текущем плане. Разработчикам на бесплатном плане всегда доступны интеграции под управлением Replit — база данных, аутентификация и другие.
</Note>

<div id="section">
  ## Начало работы
</div>

Чтобы воспользоваться интеграцией, просто упомяните нужный сервис или функцию. Например:

<AiPrompt>
  Create a web app that uses Stripe to accept payments and SendGrid to send confirmation emails
</AiPrompt>

Agent автоматически распознает эти ключевые слова и добавит необходимый код и настройки.

<div id="agent">
  ### Попросите Agent предложить коннектор
</div>

Одну и ту же задачу — например, сохранение файлов или отправку писем — нередко могут решать сразу несколько сервисов. Если запросить функцию, не указывая провайдера, Agent покажет короткий список подходящих коннекторов. Выберите тот, который хотите использовать.

Укажите провайдера и один раз войдите в систему, чтобы подключить аккаунт. Agent будет использовать этот выбор при создании приложения. Можно также сразу назвать нужный сервис по имени — тогда список не появится.

<div id="section-2">
  ## Коннекторы
</div>

Коннекторы позволяют Agent напрямую читать и записывать данные в сервисах. Это официальные интеграции, поддерживаемые Replit. Достаточно один раз войти в сервис на странице коннекторов в редакторе проекта — и это подключение можно будет использовать во всех приложениях.

<Note>
  Подключения привязываются к вашей учётной записи Replit и сохраняются для всех приложений. Подключившись к сервису один раз, вы сможете использовать его в любом создаваемом приложении.
</Note>

  ### Использование Slack вместе с Agent
</div>

Подключите Slack, чтобы передать Agent контекст из доступных вам бесед. Вы можете попросить Agent найти сообщения, файлы, каналы или людей и использовать результаты, чтобы ответить на вопросы или продолжить работу.

С вашего разрешения Agent может:

* читать закрытые каналы, личные и групповые сообщения, в которых вы состоите;
* читать все ответы в треде, если нужен окружающий контекст;
* отправлять сообщения от вашего имени;
* создавать, читать и обновлять холсты Slack.

<div id="replitoauth">
  ### Настройка OAuth-приложения в Replit
</div>

<Note>
  **Только для Enterprise**: для настройки собственного OAuth-приложения требуется подписка Enterprise.
</Note>

На плане Enterprise вы можете использовать для коннектора собственное OAuth-приложение вместо стандартного приложения Replit. Так организация становится владельцем OAuth-клиента, может показывать собственный брендинг на экране согласия и определять, какие именно области доступа вправе запрашивать разработчики.

Чтобы настроить коннектор с собственным OAuth-приложением, от провайдера вам понадобятся три вещи: **идентификатор клиента**, **секрет клиента** и **области доступа**, которые вы разрешаете. Кроме того, у провайдера нужно зарегистрировать URL обратного вызова Replit — без этого аутентификация не завершится.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Диалог настройки OAuth для коннектора с полями идентификатора клиента, секрета клиента и областей доступа, а также URL перенаправления, заданным как https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Создайте OAuth-приложение у провайдера">
    Войдите в консоль разработчика или в административные настройки провайдера и создайте новое приложение OAuth 2.0. У разных провайдеров этот шаг называется по-разному — ищите пункты вроде **Создать OAuth-приложение**, **Зарегистрировать приложение** или **Создать учётные данные клиента**.
  </Step>

  <Step title="Укажите URL перенаправления">
    Если провайдер запрашивает **разрешённый URI перенаправления** (иногда его называют **URL обратного вызова** или **URL перенаправления**), укажите следующий адрес:

    ```
    https://replit.com/connectors/oauth/callback
    ```

    По этому адресу провайдер возвращает разработчика в Replit после авторизации приложения. URL должен совпадать полностью, включая завершающую косую черту, протокол и поддомен. Если вы добавляете несколько URI перенаправления, этот адрес обязательно должен быть среди них.
  </Step>

  <Step title="Скопируйте идентификатор клиента и секрет клиента">
    После создания приложения провайдер покажет **идентификатор клиента** и **секрет клиента**.

    * **Идентификатор клиента**: публичный идентификатор вашего OAuth-приложения. Его безопасно раскрывать в URL и в клиентском коде.
    * **Секрет клиента**: конфиденциальное значение, которое подтверждает, что запрос поступает именно от вашего приложения. Обращайтесь с ним как с паролем — не сохраняйте его в репозитории и не публикуйте. Replit надёжно хранит его за вас.

    Некоторые провайдеры показывают секрет клиента только в момент создания. Скопируйте его сразу и храните в надёжном месте, пока не вставите в Replit.
  </Step>

  <Step title="Выберите области доступа">
    **Области доступа** — это разрешения, которые определяют, что OAuth-приложение может читать или записывать от имени разработчика. Каждый провайдер публикует собственный список областей доступа в документации API.

    Области доступа, которые вы указываете при настройке коннектора в Replit, должны **точно совпадать** (посимвольно, включая префиксы URL) с теми, что зарегистрированы у провайдера. Частые причины ошибок несовпадения:

    * Отсутствие полного префикса URL (например, `https://www.googleapis.com/auth/drive.file` вместо `drive.file`).
    * Лишние пробелы или завершающие запятые.
    * Запрос в Replit областей доступа, которые не включены в приложении у провайдера.

    Начните с минимального набора областей доступа, необходимых разработчикам, а остальные добавляйте позже по мере надобности — большинство провайдеров позволяют обновлять области доступа без пересоздания приложения.
  </Step>

  <Step title="Настройте коннектор в Replit">
    На странице **Коннекторы** вашей организации выберите **Добавить новую интеграцию**, укажите сервис и вставьте **идентификатор клиента**, **секрет клиента** и **области доступа**, полученные от провайдера. Выберите **Настроить**, чтобы сохранить.
  </Step>
</Steps>

<Note>
  Если после настройки аутентификация не проходит, проверьте, что URL перенаправления у провайдера в точности совпадает с `https://replit.com/connectors/oauth/callback`, а все области доступа, указанные в Replit, разрешены и в приложении у провайдера.
</Note>

<div id="section-9">
  ## Повторное подключение интеграции
</div>

Если подключённый сервис перестал работать (например, истёк срок сессии входа или изменились разрешения), Replit покажет в редакторе проекта оповещение о необходимости повторного подключения. Нажмите на него, чтобы переподключить интеграцию прямо на месте, не покидая редактор.

<div id="section-10">
  ## Отладка коннекторов
</div>

Возникли сложности с подключением сервиса? В этих руководствах разобраны типичные ошибки и способы их устранения.

<AccordionGroup>
  <Accordion title="Google Workspace: «Это приложение заблокировано»">
    Если при подключении Google Drive, Docs, Sheets, Calendar или Gmail появляется сообщение **«Это приложение заблокировано»**, возможно, Google Workspace вашей организации ограничивает доступ сторонним приложениям OAuth. Способы решения описаны в полном руководстве по устранению неполадок.

    [Устранение ошибки «Это приложение заблокировано» в коннекторах Google](/ru/ja/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce: «Срок действия подключения истёк»">
    Если коннектор Salesforce перестал работать с ошибкой «Срок действия подключения истёк», возможно, в вашей организации Salesforce политика токенов обновления настроена так, что срок действия токенов истекает через заданный период. О том, как изменить настройки Connected App, читайте в полном руководстве по устранению неполадок.

    [Исправление ошибки истечения срока действия подключения Salesforce](/ru/ja/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
