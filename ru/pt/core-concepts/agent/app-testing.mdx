App Testing позволяет Agent тестировать создаваемые приложения в реальном браузере. Agent взаимодействует с вашим приложением как реальный пользователь: нажимает на элементы и проверяет функции. Эта возможность автоматического тестирования помогает обеспечить корректную работу приложения и позволяет Agent автоматически обнаруживать и исправлять проблемы.

<div id="como-o-app-testing-funciona">
  ## Как работает App Testing
</div>

Посмотрите, как App Testing работает: Agent перемещается по вашему приложению.

  <video autoPlay muted loop playsInline src="/assets/mirror/app-testing-video-e723a2799692.mp4" />

Когда App Testing включён, Agent периодически решает, следует ли запускать тестирование, если считает, что накопилось достаточно изменений. Agent не тестирует приложение после каждого сообщения пользователя, а сам определяет, когда тестирование будет наиболее полезным.

<Note>
  Сейчас App Testing доступен для полнофункциональных веб-приложений на JavaScript и веб-приложений на Python Streamlit.
</Note>

<div id="principais-benefcios">
  ### Основные преимущества
</div>

* **Расширенная автономность**: Позволяет Agent работать дольше без вмешательства человека
* **Повышенное качество**: Помогает создавать приложения с меньшим количеством ошибок, выявляя и устраняя проблемы на ранних этапах
* **Экономия средств**: Позволяет избежать дополнительных сеансов отладки благодаря выявлению проблем в процессе разработки
* **Интерактивный обзор**: Предоставляет видеоповторы и навигацию по разделам для детального анализа результатов

<div id="o-processo-de-teste">
  ### Процесс тестирования
</div>

Когда Agent решает провести тестирование, происходит следующее:

1. **Предпросмотр в браузере**: На панели Agent появится предпросмотр в браузере
2. **Визуальное тестирование**: Наблюдайте за курсором Agent: он нажимает элементы приложения и тестирует его функции
3. **Имитация реального пользователя**: Agent взаимодействует с приложением так же, как реальный пользователь, и при необходимости вводит тестовые данные
4. **Автоматический анализ**: Agent анализирует результаты тестирования и выявляет возможные проблемы
5. **Автоматическое исправление**: Agent предоставляет сводку по результатам тестирования и автоматически исправляет все обнаруженные проблемы

<div id="principais-capacidades">
  ## Основные возможности
</div>

Agent интеллектуально тестирует ваше приложение, взаимодействуя с ним так же, как реальный пользователь, включая:

* **Проверку пользовательского интерфейса**: кнопок, форм, навигации и визуальных элементов
* **Проверку функциональности**: основных функций и пользовательских сценариев
* **Интеграционное тестирование**: вызовов API, взаимодействия с базой данных и сторонними сервисами
* **Производительность и доступность**: время загрузки, адаптивность и соответствие стандартам доступности

<div id="uso">
  ## Использование
</div>

App Testing находится в разделе **расширенные настройки** выпадающего меню настроек Agent в поле Chat. Включайте его при использовании режима Economy или Power. В режиме Lite App Testing остаётся отключённым.

<Note>
  App Testing входит в число автономных возможностей Agent. Подробнее об [оптимизации кода](/ru/pt/core-concepts/agent/code-optimizations) и других [возможностях Agent](/ru/pt/core-concepts/agent).
</Note>

<div id="assumir-controle">
  ## Взять управление
</div>

Иногда во время тестирования Agent сталкивается с препятствием, для преодоления которого требуется ваша помощь. Чаще всего это вход в учётную запись пользователя, например Gmail. В таких случаях Agent отображает кнопку «Начать управление».

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="Интерфейс управления App Testing с кнопками «Пропустить» и «Начать управление», а также инструкциями по устранению ошибок и прохождению CAPTCHA" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

Нажмите «Начать управление», чтобы взаимодействовать с тестовым предпросмотром, выполнить необходимые действия и позволить Agent продолжить работу. Вы также можете нажать «Пропустить», чтобы отказаться от управления. Если Agent не сможет продолжить без вашей помощи, App Testing будет завершён. Если вы не ответите в течение 10 минут, Agent продолжит работу так, как если бы вы нажали «Пропустить».

<div id="o-que-esperar">
  ### Чего ожидать
</div>

* **Возможность пропуска**: При необходимости нажмите кнопку пропуска, чтобы пропустить тесты и продолжить разработку
* **Интерактивный видеоповтор**: После тестирования нажмите на видео, чтобы воспроизвести весь сеанс
* **Навигация по разделам**: Используйте ползунки в нижней части экрана, чтобы перейти к нужным разделам теста

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

**Тесты неожиданно завершаются с ошибкой**

* Попробуйте пропустить тест и запустить его повторно
* Проверьте, нет ли динамического содержимого, которое может повлиять на время выполнения тестов
* Проверьте точность сценариев тестирования

**Недостаточное покрытие тестами**

* Подробнее опишите функциональность вашего приложения
* Явно укажите критически важные пользовательские сценарии, которые необходимо протестировать

**App Testing не работает?**

* В настоящее время App Testing работает только с веб-приложениями[*](#how-app-testing-works)

<div id="preos-e-uso">
  ## Цены и использование
</div>

App Testing входит в модель ценообразования Agent, основанную на затраченных усилиях. При этом важно учитывать следующее:

* **Оплата по факту использования**: Стоимость тестирования зависит от затраченных усилий: более простые тесты стоят дешевле.
* **Затраты и выгода**: Хотя тестирование платное, оно может снизить расходы благодаря раннему выявлению ошибок и сокращению количества дополнительных prompts и работы Agent.
* **Эффективная разработка**: Автоматизированный подход сокращает потребность в ручной отладке и доработках.

<Tip>
  **Экономичное тестирование**: Хотя App Testing увеличивает расходы, в целом оно обычно позволяет сэкономить, избавляя от необходимости проводить дополнительные сеансы Agent для исправления проблем, которые можно было выявить во время тестирования.
</Tip>
