Внешние токены доступа — это bearer-токены, которые вы выпускаете для конкретного Replit App.
Они позволяют автоматизированным сервисам — CI-конвейерам, вебхукам, сервисам проверки статуса, ботам Slack,
внутренним скриптам — обращаться к приложению, даже если доступ к его URL закрыт
[приватным Dev URL](/ru/features/publishing/private-deployments)
или [приватным deployment](/ru/features/publishing/private-deployments).

Относитесь к каждому токену как к паролю: любой, у кого он есть, сможет обратиться к вашему приложению, пока
не истечёт срок действия токена или пока вы его не отзовёте.

<Note>
  Внешние токены доступа доступны, если для deployment выбран приватный доступ.
  Отдельно включать эту возможность в workspace не нужно. В workspace Enterprise
  управлять токенами могут только администраторы workspace.
</Note>

<div id="when-to-use-a-token">
  ## Когда использовать токен
</div>

Токен внешнего доступа пригодится, когда к вашему приватному Replit App должно
обращаться что-то *за пределами* браузера. Типичные случаи:

* Workflow GitHub Actions, который при каждом коммите запускает дымовой тест
  по вашему dev-URL.
* Монитор доступности (Better Stack, Pingdom, UptimeRobot), опрашивающий
  эндпоинт проверки состояния опубликованного приложения.
* Приёмник вебхуков — Stripe, Slack, GitHub — отправляющий POST-запросы в приватный deployment.
* Вызов `curl` или `fetch` с машины коллеги во время отладки.

Токены внешнего доступа рассчитаны на **API-трафик**, а не на открытие
страниц интерфейса в браузере. Одностраничные приложения (Vite, Next.js и т. д.)
подгружают JavaScript-бандлы последующими запросами, а они уже не передают ваш токен,
поэтому такие запросы завершаются ошибкой. Для интерактивной работы в браузере просто войдите в аккаунт обычным способом.

<div id="token-environments">
  ## Окружения токенов
</div>

Каждый токен привязан к одному окружению:

| Окружение     | Где работает                                                               | Для чего использовать                                 |
| :------------ | :------------------------------------------------------------------------- | :---------------------------------------------------- |
| `Development` | Dev-URL приложения в workspace (`*.replit.dev`)                            | Обращений к запущенному Repl во время разработки      |
| `Production`  | Опубликованный deployment приложения (`*.replit.app` и собственные домены) | Обращений к приватному deployment из внешних сервисов |

Токен `Production` продолжает действовать после повторной публикации, в том числе при публикации новой версии.
Replit отзывает его, если вы:

* Снимаете deployment с публикации.
* Удаляете deployment.
* Меняете доступ к приложению с приватного на публичный.

Токен также перестаёт работать по истечении срока действия или после того, как вы его отзовёте.

<div id="create-an-external-access-token">
  ## Создание токена внешнего доступа
</div>

<Steps>
  <Step>
    Откройте приложение, к которому нужно открыть доступ, затем откройте инструмент **Publishing**.
  </Step>

  <Step>
    Выберите **Adjust settings**, чтобы развернуть параметры повторного развертывания.
  </Step>

  <Step>
    В разделе **Security** найдите **External access tokens**.
  </Step>

  <Step>
    Выберите **Create access token** и заполните поля:

    * **Label** (необязательно): короткое имя, по которому вы позже узнаете токен,
      например `CI` или `Stripe webhook`. Максимум 120 символов.
    * **Environment**: выберите `Development` или `Production` в зависимости от того,
      куда вызывающему сервису нужно обращаться.
    * **Expires after**: выберите срок действия — `1 hour`, `24 hours`, `7 days`,
      `30 days`, `3 months`, `1 year` или `5 years`. Выбирайте минимальный срок,
      которого хватит для задачи. Варианта «никогда не истекает» нет.
  </Step>

  <Step>
    Выберите **Create**.
  </Step>
</Steps>

Replit показывает токен **только один раз**. Скопируйте его сразу — после закрытия диалогового окна
посмотреть токен снова не получится. Если вы его потеряли, отзовите этот токен и создайте
новый.

На экране с токеном доступны два способа копирования:

* **Copy query parameter** — копирует `?project-protection-bypass=<token>` для
  добавления к URL. Удобно для быстрых проверок через `curl`.
* **Copy token only** — копирует сам токен в чистом виде, пригодный для отправки в заголовке
  `Authorization: Bearer`.

<Info>
  Создание первого токена автоматически включает внешний доступ для приложения, если
  он не был включен ранее. Без защиты токену нечего обходить.
</Info>

<div id="use-a-token">
  ## Использование токена
</div>

Передайте токен одним из двух способов:

<div id="authorization-header-recommended">
  ### Заголовок Authorization (рекомендуется)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

Это верный выбор почти для всех случаев — вебхуков, CI-скриптов,
вызовов между серверами. Токен не попадёт в логи, где записываются URL,
и не окажется в истории браузера.

<div id="query-parameter">
  ### Параметр запроса
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

Используйте вариант с параметром запроса, только если не можете задать заголовки, — например, когда сервис принимает исключительно URL. URL-адреса с токенами часто попадают в логи прокси, историю команд Shell и на скриншоты, поэтому по возможности выбирайте вариант с заголовком.

<div id="manage-existing-tokens">
  ## Управление существующими токенами
</div>

В разделе **External access tokens** перечислены все созданные вами токены для
приложения — сначала самые новые — с указанием метки, среды, даты создания,
срока действия и статуса отзыва. В каждой строке отображаются последние символы токена,
чтобы вы могли отличать токены друг от друга: полное значение показывается только в момент создания.

Вы видите только *свои* токены. Токены других соавторов доступны только
им, даже если приложение принадлежит вам.

<div id="revoke-a-token">
  ## Отзыв токена
</div>

Отзывайте токен, как только он становится ненужным, или сразу же, как только вы
заподозрите утечку. Чтобы отозвать токен:

<Steps>
  <Step>
    Откройте раздел **External access tokens** в настройках публикации приложения.
  </Step>

  <Step>
    Найдите токен в списке и нажмите на значок корзины.
  </Step>

  <Step>
    Подтвердите отзыв.
  </Step>
</Steps>

Отзыв выполняется **мгновенно и необратимо**. Весь трафик, который всё ещё
использует этот токен, начнёт отклоняться в течение нескольких секунд. Если доступ понадобится снова, создайте
новый токен.

Отзывать можно только те токены, которые вы создали сами. При удалении участника из
workspace токены, созданные им для этого приложения, отзываются автоматически.

<div id="keep-your-tokens-safe">
  ## Храните токены в безопасности
</div>

Токены внешнего доступа — это учётные данные. Обращайтесь с ними так же
осторожно, как с ключом API или паролем.

<div id="do">
  ### Что делать
</div>

* **Храните токены в менеджере секретов** — в Secrets GitHub Actions, хранилище
  вашего CI-сервиса, хранилище секретов облачного provider или менеджере паролей.
  Никогда не коммитьте их в репозиторий.
* **Задавайте короткий срок действия**, когда это возможно. Токен на 7 дней для разовой
  integration безопаснее, чем токен на 5 лет, о котором все забыли.
* **Давайте имя каждому токену**, чтобы вы в будущем понимали, для чего он нужен и
  используется ли он до сих пор. Токены без имени утекают первыми, а отзывают их
  последними.
* **Создавайте отдельный токен для каждого потребителя.** Один токен на CI-задачу, один на
  источник вебхуков, один на проверку доступности. Если что-то будет скомпрометировано — или
  сервис больше не нужен — вы отзовёте только этот токен.
* **Используйте заголовок `Authorization`** вместо параметров запроса, чтобы токен
  не утёк через логи URL, историю браузера или заголовки referer.
* **Немедленно отзывайте токен**, если он мог быть раскрыт: попал в лог,
  в коммит публичного репозитория, в демонстрацию экрана или на ноутбук бывшего сотрудника.
  Отзыв вступает в силу сразу; затем создайте новый токен на замену.

<div id="dont">
  ### Не делайте так
</div>

* **Не используйте один токен для нескольких коллег или сервисов.** Если две
  системы работают с одним токеном, вы не сможете отозвать его для одной, не
  сломав другую.
* **Не отправляйте токены в чатах, письмах, скриншотах или трекерах задач.**
  Эти каналы архивируются, индексируются и передаются способами, которые
  невозможно предугадать.
* **Не встраивайте токены в клиентский код** — браузерные приложения,
  мобильные приложения, десктопные сборки. Всё, что попадает на устройство
  пользователя, следует считать общедоступным.
* **Не полагайтесь на токены для браузерных сессий.** Токены подходят для
  вызовов API, а не для загрузки SPA во вкладке браузера. Для этого
  используйте обычный вход в Replit.
* **Не выбирайте срок действия в 5 лет по умолчанию.** Подбирайте срок
  жизни токена под то, насколько долго доступ действительно нужен потребителю.

<div id="troubleshooting">
  ## Устранение неполадок
</div>

<Accordion title="Мой production-токен внезапно перестал работать">
  Production-токены остаются действительными при обычных повторных публикациях.
  Проверьте, не истёк ли срок действия токена и не отозвали ли вы его. Также
  проверьте, не сняли ли вы приложение с публикации, не удалили ли deployment и
  не сделали ли приложение из приватного публичным. Если у приложения больше нет
  приватного deployment, опубликуйте его приватно, а затем выпустите новый токен.
  Восстановить истёкший или отозванный токен невозможно.
</Accordion>

<Accordion title="Токен работает с `curl`, но в браузере по-прежнему открывается страница входа">
  Токены внешнего доступа предназначены для трафика API, а не для сеансов в
  браузере. Когда одностраничное приложение загружается в браузере, первый
  HTML-запрос может передать токен через параметр запроса, но последующие
  запросы к JavaScript-бандлам, CSS и API его уже не содержат и будут отклонены.
  Чтобы работать с приложением в интерактивном режиме, войдите в Replit обычным
  способом.
</Accordion>

<Accordion title="Я потерял токен — можно ли посмотреть его снова?">
  Нет. Replit показывает токен только один раз — в момент создания. В списке
  отображаются метаданные (метка, окружение, срок действия, последние несколько
  символов), но никогда не полное значение токена. Если вы его потеряли,
  отзовите этот токен и создайте новый.
</Accordion>
