[project](/ko/features/projects-and-artifacts/projects)는 Replit에서 만드는 모든 것을 담는 컨테이너입니다. project에는 design, app, slides, 데이터 등 여러분이 만든 모든 결과물이 담깁니다.
[Artifact](/ko/features/projects-and-artifacts/artifacts)는 project 안에서 게시할 수 있는 결과물로, web app, mobile app, slide deck, 동영상 등이 여기에 해당합니다.

여러 가지를 만들고 있다면 두 가지 선택지가 있습니다.

* 하나의 project에 여러 artifact를 추가하거나,
* 별도의 project를 만드는 것입니다.

어떤 선택이 적합한지는 각 app이 데이터, 로직, deployment 수명 주기를 공유하는지에 따라 달라집니다. 이 가이드에서는 artifact를 한 project에 모아 두는 것이 좋은 경우와 별도로 나누는 것이 좋은 경우를 다룹니다.

<div id="what-artifacts-share-in-a-project">
  ## project에서 artifact가 공유하는 항목
</div>

[artifact](/ko/features/projects-and-artifacts/artifacts)가 동일한 [project](/ko/features/projects-and-artifacts/projects) 안에 있으면 다음 항목이 자동으로 공유됩니다:

* **Database**: 한 artifact가 데이터를 기록하면 다른 artifact가 즉시 읽을 수 있습니다
* **backend 및 API**: 서버 로직을 공유하므로 코드를 중복 작성할 필요가 없습니다
* **파일 저장소**: 이미지, 문서, upload한 파일을 artifact 간에 사용할 수 있습니다
* **deployment**: 게시하면 모든 항목이 동기화되어 함께 라이브로 전환됩니다

따라서 artifact 간에 별도로 연결을 설정하거나 코드를 중복해서 작성할 필요가 없습니다. 다만 나머지 artifact를 게시하지 않고 특정 artifact 하나만 게시할 수는 없습니다.

<div id="quick-guide">
  ## 빠른 안내
</div>

기존 project에 artifact를 추가할지, 별도의 project를 만들지 결정할 때 고려해야 할 주요 시나리오는 다음과 같습니다.

| **하나의 project에 여러 artifact 사용**                     | **별도의 project 사용**                             |
| --------------------------------------------------- | ---------------------------------------------- |
| App들이 동일한 데이터와 backend를 공유하는 경우                     | App들이 내부 로직이나 데이터를 공유하지 않는 경우                  |
| 모든 것을 한 번에 publish하려는 경우                            | 독립적인 게시 주기가 필요한 경우                     |
| 서로 보완적인 경우(예: 고객용 app과 admin dashboard)             | 서로 관련 없는 제품이거나 고객사가 다른 경우                      |
| 한 artifact의 changes가 다른 artifact에 자동으로 반영되기를 원하는 경우 | 캠페인 landing page나 이벤트 사이트처럼 project의 수명이 짧은 경우 |

<div id="examples">
  ## 예제
</div>

<div id="same-project-web-app-mobile-app-for-one-product">
  ### 같은 project: 하나의 제품을 위한 web app + mobile app
</div>

한 음식점에서 고객이 메뉴를 둘러보는 web app과 직원이 주문을 관리하는 mobile app을 만든다고 가정해 보겠습니다. 두 앱 모두 메뉴 항목, 주문, 고객 정보가 담긴 동일한 database에 연결됩니다.

**하나의 project로 만드는 이유:** 두 앱은 같은 데이터와 backend를 공유합니다. 고객이 web app에서 주문을 넣으면 직원은 mobile app에서 바로 확인할 수 있습니다.

<div id="same-project-app-admin-dashboard-investor-pitch-deck">
  ### **동일한 project**: App + admin dashboard + investor pitch deck
</div>

한 스타트업이 주력 제품, 콘텐츠 관리를 위한 내부 관리자 패널, 자금 조달용 slide deck을 모두 하나의 project에서 만듭니다.
한 스타트업이 주력 제품, 콘텐츠 관리를 위한 내부 관리자 패널, 자금 조달용 slide deck을 모두 하나의 project에서 만듭니다.

**하나의 project를 쓰는 이유:** admin dashboard가 App에 표시되는 것과 동일한 데이터를 관리하고, pitch deck은 공유 backend의 실시간 지표를 참조할 수 있기 때문입니다.

<div id="separate-projects-two-unrelated-client-apps">
  ### **project 분리**: 서로 관련 없는 두 고객사 앱
</div>

프리랜서가 한 고객사에는 전자상거래 스토어를, 다른 고객사에는 예약 시스템을 만들어 준다고 가정해 보겠습니다.

**project를 분리하는 이유:** 두 앱은 공유하는 데이터나 로직이 없습니다. 고객사별로 독립적인 게시가 필요하고, 한쪽의 변경 사항이 다른 쪽에 영향을 주지 않아야 합니다.

<div id="separate-projects-campaign-landing-page-alongside-a-main-product">
  ### **별도 project**: 메인 제품과 함께 운영하는 캠페인 landing page
</div>

연중 상시 운영되는 production 앱과 마케팅 캠페인용 단기 landing page가 있다고 가정해 보겠습니다.

**별도 project로 분리하는 이유:** 캠페인 페이지에는 고유한 수명 주기가 있습니다. 필요할 때 만들어 몇 주간 운영한 뒤 내리게 되죠. 별도로 분리해 두면 메인 제품이 복잡해지지 않고, 캠페인 페이지만 독립적으로 게시하거나 제거할 수 있습니다.

<div id="frequently-asked-questions">
  ## 자주 묻는 질문
</div>

<Accordion title="artifact를 다른 project로 옮길 수 있나요?">
  현재는 불가능합니다. artifact를 분리해야 한다면 새 [project](/ko/features/projects-and-artifacts/projects)를 만든 뒤 Agent에게 그곳에서 다시 만들어 달라고 요청하세요.
</Accordion>

<Accordion title="하나의 project에 담을 수 있는 artifact 수에 제한이 있나요?">
  project 하나에는 최대 7개의 artifact를 담을 수 있습니다. artifact가 많아질수록 메모리를 더 많이 사용해 Preview가 느려질 수 있어 이러한 제한을 두고 있습니다. artifact가 더 필요하다면 다른 [project](/ko/features/projects-and-artifacts/projects)를 새로 시작하세요.
</Accordion>

<Accordion title="project에서 artifact 하나만 게시할 수 있나요?">
  현재는 불가능합니다. Publishing을 실행하면 모든 항목이 함께 라이브로 배포됩니다. 개별적으로 게시해야 한다면 project를 따로 분리해서 사용하세요.
</Accordion>
