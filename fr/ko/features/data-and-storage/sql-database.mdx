La base de données Replit vous permet d’ajouter un stockage persistant à votre application Replit directement depuis le Project Editor, grâce à une base de données SQL entièrement gérée.

<Note>
  Pour démarrer le plus rapidement possible, demandez à **Agent** d’ajouter une base de données à votre app. Agent configure l’intégration, crée le schéma de la base de données et met à jour votre app afin qu’elle puisse stocker et récupérer des données.
</Note>

<div id="section">
  ## Fonctionnalités
</div>

Les outils de base de données de Replit offrent les fonctionnalités suivantes :

* **Outils de base de données** : exécutez des requêtes avec l&#39;outil SQL intégré, gérez le schéma de votre base de données et visualisez vos données
* **Voyage dans le temps** : restaurez votre base de données à partir de n&#39;importe quel point de contrôle **Agent**. Pour en savoir plus, consultez [Restauration des données](/fr/ko/features/data-and-storage/data-recovery)
* **Espace de stockage gratuit** : chaque application Replit comprend 20 Go d&#39;espace de stockage gratuit.
* **Variables d&#39;environnement** : accédez de manière sécurisée à votre base de données depuis votre application Replit à l&#39;aide de variables d&#39;environnement

<Info>
  Avant le 4 décembre 2025, les bases de données de développement étaient hébergées par Neon et présentaient quelques différences importantes.
  Pour en savoir plus, consultez [Développement et production](/fr/ko/features/data-and-storage/development-and-production#legacy-development-database).
</Info>

<div id="section-2">
  ## Utilisation
</div>

<YouTubeEmbed videoId="zbyRuoPNIc8" title="Comment utiliser les bases de données sur Replit" />

Vous pouvez accéder aux outils de base de données Replit directement depuis le Project Editor.
Les sections suivantes expliquent comment configurer et gérer vos bases de données.

<Accordion title="Comment accéder aux outils de base de données">
  1. Ouvrez le panneau **Tools** et sélectionnez **Database** sous **Replit Cloud**.
  2. L&#39;écran d&#39;accueil affiche la liste de vos bases de données. Sélectionnez une base de données, par exemple **Development Database**, pour l&#39;ouvrir.
</Accordion>

L&#39;outil Database s&#39;articule autour de la liste de vos bases de données. L&#39;écran d&#39;accueil indique l&#39;espace de stockage utilisé par chaque base de données, ainsi que la **Billing Period** en cours et les **Hours of Compute Used**. Lorsque vous ouvrez une base de données, trois onglets sont disponibles.

* **Overview** : les tables de la base de données
* **My Data** : parcourez et modifiez les lignes, ou exécutez des requêtes SQL
* **Settings** : chaîne de connexion, espace de stockage utilisé et détails de connexion

<div id="section-3">
  ### Ajouter une base de données
</div>

Chaque application Replit inclut une base de données par défaut. Vous pouvez y accéder en sélectionnant l’outil <img class="icon-svg" src="/assets/mirror/postgres-c4cb2a1e2de3.svg" alt="Icône de base de données PostgresSQL" width="24" height="24" data-path="images/icons/postgres.svg" /> **Base de données** dans le Project Editor.

Vous pouvez intégrer une base de données à votre application en demandant à **Agent** d’ajouter une base de données PostgreSQL à votre application Replit et en lui indiquant
quelles données l’application doit stocker. Agent crée le schéma de la base de données et
met à jour l’application pour qu’elle communique avec celle-ci.

<div id="section-4">
  ### Fonctionnalités de sécurité
</div>

Lorsque vous ajoutez une intégration de base de données avec **Agent**, un ORM (Object-Relational Mapper) doté de fonctionnalités de sécurité intégrées est ajouté et
gère l&#39;ensemble des communications avec la base de données.

Associée aux bonnes pratiques de sécurité mises en œuvre par Agent, cette couche ORM protège votre app contre différents types d&#39;attaques grâce aux fonctionnalités suivantes.

* **Validation du schéma** : vérifie que les données respectent le format attendu
* **Assainissement des données (Sanitization)** : nettoie automatiquement les entrées du builder afin de prévenir les attaques par injection SQL

<div id="section-5">
  ## Étapes suivantes
</div>

Avant le 4 décembre 2025, les bases de données de développement étaient hébergées par <a href="https://neon.com/" target="_blank">Neon</a>.
Ces bases de données sont désormais dépréciées et toutes les nouvelles bases de données de développement sont hébergées sur l&#39;infrastructure de bases de données de Replit.

Vous pouvez consulter la [variable d&#39;environnement](#view-connection-credentials-and-usage) `DATABASE_URL` pour savoir si votre base de données de développement est hébergée par Neon.

<Info>
  Si `DATABASE_URL` contient `neon.tech/neondb`, votre base de données de développement est encore hébergée par Neon.
  À l&#39;inverse, si elle contient `helium/heliumdb`, votre base de données de développement est désormais hébergée par Replit.
</Info>

Voici les principales différences entre les anciennes bases de données de développement Neon et les nouvelles bases de données de développement Replit.

| **Fonctionnalité**              | **Replit (actuel)**                                                                                                                                                                  | **Neon (ancien)**                                                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hébergement**                 | Hébergé sur l&#39;infrastructure de Replit                                                                                                                                           | Hébergé par Neon (fournisseur tiers)                                                                                                                                  |
| **Facturation**                 | Inclus gratuitement dans toutes les application Replit                                                                                                                                       | Facturation à l&#39;usage. Pour en savoir plus, consultez [Publication et facturation des bases de données](/fr/ko/billing/about-usage-based-billing#databases).         |
| **Fonction de restauration**    | Restaurez votre base de données à n&#39;importe quel checkpoint grâce à la [fonction de rollback](/fr/ko/features/version-control/checkpoints-and-rollbacks/)                           | Restauration à un instant précis (PITR) — récupération à n&#39;importe quel moment de la période de rétention des sauvegardes.                                        |
| **Sécurité des connexions**     | Accessible uniquement depuis votre app, jamais exposée à l&#39;extérieur.                                                                                                            | Utilise une chaîne de connexion complète — si elle est exposée, n&#39;importe qui peut accéder à la base de données et la modifier.                                   |
| **Comportement du remix**       | Le [remix](/fr/ko/features/projects-and-artifacts/remix-an-app) crée une nouvelle base de données de développement contenant une copie des données, pour l&#39;isolation et la sécurité | Le remix réutilise la même base de données pour toutes les copies : les modifications effectuées dans un remix peuvent donc affecter l&#39;app d&#39;origine.         |
| **Création de base de données** | Créée automatiquement pour chaque application Replit.                                                                                                                                        | Nécessite une configuration explicite.                                                                                                                                |
| **Flux de publication**         | Pour déployer ou publier, vous devez créer une [base de données de production](/fr/ko/features/data-and-storage/development-and-production) afin d&#39;isoler les environnements.       | Le développement et la production partageaient la même base de données : des modifications involontaires en développement pouvaient affecter l&#39;app en production. |

<Warning>
  Si votre app a été forkée ou remixée alors qu&#39;elle utilisait une ancienne base de données Neon, l&#39;app publiée peut encore pointer vers l&#39;URL de base de données de l&#39;app d&#39;origine. Après la [mise à niveau de la base de données](/fr/ko/features/data-and-storage/development-and-production), cette connexion partagée cesse de fonctionner. Pour savoir comment mettre à jour votre app publiée, consultez [Corriger une app publiée utilisant une base de données partagée](/fr/ko/features/data-and-storage/shared-database-migration).
</Warning>
