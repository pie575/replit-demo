<div id="section">
  ## Начало работы
</div>

Replit — это облачная среда разработки, в которой можно писать и запускать код на любом фреймворке и любом стеке. Для создания пользовательских шаблонов есть два рекомендуемых способа:

1. **[Импорт из Git-провайдера](https://replit.com/import)** — импортируйте готовый стартовый стек (или любой другой на ваш выбор) из GitHub, GitLab или Bitbucket.
2. **Форк шаблона Blank** — сделайте форк [шаблона Blank](https://replit.com/@replit/Nothing?v=1) и начните с нуля в полностью пустой среде разработки.

Клиенты успешно создавали шаблоны для Rust, Python, Java, C++ и множества других стеков. Если что-то работает в принципе, это будет работать и в Replit.

<Tip>
  При создании первого шаблона рекомендуем поработать вместе с командой **Field Engineering** в Replit. У этой команды богатый опыт настройки пользовательских шаблонов для самых разных стеков, и она готова помочь. Обратитесь к своему Account Executive, чтобы связаться с ней.
</Tip>

Пользовательские шаблоны позволяют администраторам Enterprise создавать преднастроенные отправные точки, которые отображаются прямо в поле ввода Agent у всех участников организации. Когда разработчик выбирает такой шаблон, Agent делает его форк и использует конфигурацию, инструкции и навыки шаблона во всей дальнейшей работе. Дополнительная настройка не требуется.

<Note>
  Пользовательские шаблоны доступны только на тарифе **Enterprise**. Закреплять шаблоны и управлять ими могут только администраторы организации.
</Note>

<div id="section-2">
  ## Как работают пользовательские шаблоны
</div>

Пользовательские шаблоны — это стандартные Replit App вашей организации, **закреплённые в поле ввода Agent**. Когда разработчик выбирает шаблон:

1. Agent создаёт новое приложение, форкая шаблон (копируются все файлы)
2. Agent пропускает этап планирования и сразу переходит к сборке
3. Файл `custom_instruction/instructions.md` из шаблона добавляется в контекст Agent
4. Пользовательские [навыки](/ru/ko/features/agent/skills) из `.agents/skills/` обнаруживаются и становятся доступными
5. Файл [`replit.md`](/ru/ko/features/project-setup/replit-dot-md) обеспечивает постоянный контекст проекта

Таким образом, стандарты, паттерны и инструменты вашей организации встроены в работу с первого же взаимодействия.

<div id="section-3">
  ## Структура файлов шаблона
</div>

Рекомендуемая структура пользовательского шаблона выглядит следующим образом:

```
my-template/
├── .replit                              # Конфигурация приложения (команда запуска, порты, модули)
├── replit.md                            # Память Agent: обзор проекта и базовые настройки
├── custom_instruction/
│   └── instructions.md                  # Корпоративные инструкции, добавляемые в промпт Agent
├── .agents/
│   └── skills/
│       └── my-skill/
│           └── SKILL.md                 # Пользовательский навык, который Agent может вызвать при необходимости
└── ...                                  # Остальная структура репозитория
```

Каждый файл выполняет свою роль. В разделах ниже описано, как настроить каждый из них.

<div id="section-4">
  ## Настройка пользовательского шаблона
</div>

<div id="section-5">
  ### Создание базового приложения
</div>

Создайте новый Replit App в своей организации. Настройте проект со всеми файлами, зависимостями и конфигурацией, которые понадобятся разработчикам в качестве отправной точки. Сюда входят:

* Каркас исходного кода (компоненты, утилиты, файлы конфигурации)
* Предустановленные зависимости (`package.json`, `requirements.txt` и т. д.)
* Конфигурация окружения в [файле `.replit`](/ru/replit-app/configuration)

<div id="section-6">
  ### Настройка общих секретов
</div>

Если шаблон использует ключи API, токены или другие учётные данные, добавьте их в **Secrets** шаблона (внизу панели инструментов) до его закрепления. Когда разработчик создаёт новое приложение из шаблона, все секреты копируются в него автоматически, так что можно сразу приступать к работе, не настраивая учётные данные вручную.

Опишите все секреты в файле `custom_instruction/instructions.md` (или в отдельном навыке), чтобы разработчики знали, какие секреты есть и для чего нужен каждый ключ.

<Warning>
  Секреты копируются в момент создания форка и не синхронизируются динамически. Если вы смените ключи или добавите в шаблон новые секреты, ранее созданные форки не обновятся. Разработчикам придётся добавить или обновить секреты в таких приложениях вручную.
</Warning>

<div id="section-7">
  ### Создание пользовательских инструкций
</div>

Создайте файл `custom_instruction/instructions.md` в корне проекта. Это самый важный файл шаблона: он сообщает Agent, как ваша организация разрабатывает программное обеспечение.

<Warning>
  Имя папки должно быть `custom_instruction` (в единственном числе), а не `custom_instructions` (во множественном числе).
</Warning>

Agent напрямую включает этот файл в системный промпт, добавляя преамбулу о том, что это инструкции от компании. Оформите файл в Markdown и включите в него следующее:

* **Архитектурные паттерны**: как организовано приложение
* **Стандарты кодирования**: соглашения об именовании, правила организации файлов, требования к линтингу
* **Использование компонентов**: библиотеки и компоненты, которые следует использовать (и которых следует избегать)
* **Паттерны API**: как вызывать серверные службы, обрабатывать аутентификацию и управлять ошибками
* **Требования к тестированию**: необходимые тесты и способы их запуска
* **Инструкции по деплою**: конфигурация для разных сред и рабочий процесс деплоя

````markdown theme={null}
# 회사 엔지니어링 표준

## 아키텍처
모든 웹 애플리케이션은 TypeScript와 함께 React를 사용합니다. 훅이 있는
함수형 컴포넌트만 사용합니다. 상태 관리는 로컬 상태에 Zustand를,
서버 상태에 React Query를 사용합니다.

## 컴포넌트 라이브러리
내부 디자인 시스템 패키지 `@acme/ui`를 사용합니다. 버튼, 입력, 폼,
모달에는 절대 원시 HTML 요소를 사용하지 말고 항상 `@acme/ui`의
해당 컴포넌트를 사용합니다.

다음과 같이 컴포넌트를 가져옵니다:
```tsx
import { Button, TextField, Modal } from '@acme/ui';
```

## API 통합
모든 API 호출은 `@acme/api-client` 패키지를 통해 이루어집니다.
절대 raw fetch나 axios를 직접 사용하지 않습니다. 인증은 클라이언트가
자동으로 처리합니다.

## 테스트
모든 컴포넌트에는 해당 테스트 파일이 있어야 합니다. 단위 테스트에는
Vitest를, 통합 테스트에는 Playwright를 사용합니다.
````

**Ограничение размера**: для содержимого действует мягкое ограничение около 25 КБ. Содержимое сверх этого объёма может постепенно обрезаться. Если инструкции разрастаются, переносите подробные справочные материалы в [навыки](/ru/ko/features/agent/skills) в каталоге `.agents/skills/`, вместо того чтобы держать всё в `instructions.md`. Навыки загружаются только тогда, когда они нужны для задачи, поэтому они не учитываются в ограничении размера инструкций, а основные инструкции остаются сосредоточенными на правилах высокого уровня.

<div id="section-8">
  ### Добавление пользовательских навыков
</div>

Создавайте навыки в каталоге `.agents/skills/` для особых рабочих процессов, которым должен следовать Agent. Каждый навык — это каталог с файлом `SKILL.md`, содержащим YAML-фронтматтер.

```
.agents/skills/
├── use-design-system/
│   └── SKILL.md
├── api-integration/
│   └── SKILL.md
└── run-tests/
    └── SKILL.md
```

В каждом файле `SKILL.md` во фронтматтере должны быть указаны `name` и `description`:

```markdown theme={null}
---
name: use-design-system
description: Use when building UI components. Provides component patterns, theming rules, and accessibility requirements for the Acme design system.
---

# Acme Design System

## Available components

- `Button` — Primary, secondary, and ghost variants
- `TextField` — Text input with validation support
- `Modal` — Dialog overlay with focus trapping
...
```

| Поле          | Обязательное | Подробности                                                                   |
| ------------- | ------------ | ----------------------------------------------------------------------------- |
| `name`        | Да           | До 64 символов. Допустимы только строчные буквы, цифры и дефисы.              |
| `description` | Да           | До 1024 символов. Описывает, что делает навык и когда его применять.          |
| `enabled`     | Нет          | По умолчанию — `true`. Укажите `false`, чтобы отключить навык, не удаляя его. |

**Как загружаются навыки**: в промпте Agent видит только `name` и `description`. Полное содержимое `SKILL.md` он читает при необходимости — когда навык относится к текущей задаче. Поэтому `description` играет ключевую роль: составьте его так, чтобы он соответствовал сценариям, в которых Agent должен использовать навык.

Помимо `SKILL.md`, навык может включать вспомогательные файлы:

```
.agents/skills/use-design-system/
├── SKILL.md
├── references/
│   └── component-api.md
└── assets/
    └── theme-tokens.json
```

Подробнее о навыках см. в разделах [Agent Skills](/ru/ko/features/agent/skills) и [Использование навыков](/ru/ko/build/use-agent-skills).

<div id="replitmd">
  ### Настройка replit.md
</div>

Заранее опишите архитектуру шаблона в файле `replit.md` в корне проекта. Этот файл всегда загружается в контекст Agent и служит постоянной памятью проекта.

Файл должен содержать следующие четыре раздела:

```markdown theme={null}
# Overview
Task management application built with React, TypeScript, and the Acme
design system. Uses Express.js backend with PostgreSQL.

# User Preferences
- Use TypeScript for all files
- Prefer functional components with hooks
- Follow Acme coding standards

# System Architecture
- Frontend: React + TypeScript + @acme/ui
- Backend: Express.js + TypeScript
- Database: PostgreSQL with Drizzle ORM
- Auth: Acme SSO via @acme/auth

# External Dependencies
- @acme/ui: Internal design system
- @acme/api-client: API integration layer
- @acme/auth: Authentication SDK
```

Agent обновляет `replit.md` по мере развития проекта. Если размер файла превышает примерно 4 000 токенов, Agent автоматически сокращает его, чтобы он оставался лаконичным и полезным.

Подробнее см. [replit.md](/ru/ko/features/project-setup/replit-dot-md).

<div id="section-9">
  ### Закрепление шаблона для организации
</div>

Когда шаблон готов:

1. Перейдите в приложение шаблона организации
2. Откройте меню действий приложения (меню с тремя точками)
3. Выберите **Закрепить в поле ввода Agent**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий приложения с пунктом «Закрепить в поле ввода Agent»" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Только администраторы организации (участники с ролью `system_admins`) могут закреплять и откреплять шаблоны.
</Note>

Установите для участников уровень доступа **Только для чтения**, чтобы они могли просматривать и использовать закреплённый шаблон, не редактируя его.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалоговое окно приглашения, в котором для участников установлен доступ «Только для чтения»" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Теперь шаблон отображается в виде выбираемой плашки под полем ввода Agent у всех участников организации. Чтобы убрать его, откройте то же меню и выберите **Открепить из поля ввода Agent**.

<div id="section-10">
  ### Управление доступом к шаблонам
</div>

После закрепления шаблон становится виден всем участникам организации. Для более точечного распространения используйте кнопку **Пригласить** в приложении-шаблоне, чтобы поделиться им с определёнными [группами или отдельными пользователями](/ru/ko/teams/identity-and-access-management/groups-and-permissions). Так вы сможете ограничить круг команд и людей, которые могут просматривать и форкать шаблон, не закрепляя его в поле ввода для всей организации.

<div id="section-11">
  ## Что происходит, когда разработчик выбирает шаблон
</div>

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Шаблон, отмеченный как доступный вариант в поле ввода Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

Когда участник организации выбирает закреплённый шаблон в поле ввода Agent:

1. **Форк**: создаётся новое приложение — копия шаблона со всеми файлами
2. **Пропуск планирования**: Agent пропускает начальный диалог планирования и сразу переходит в режим сборки
3. **Загрузка инструкций**: файл `custom_instruction/instructions.md` считывается, а инструкции компании добавляются в системный промпт Agent
4. **Обнаружение навыков**: навыки из `.agents/skills/` определяются и добавляются в контекст Agent для загрузки при необходимости
5. **Загрузка контекста проекта**: файл `replit.md` считывается и добавляется в контекст Agent (если его нет, он создаётся автоматически)
6. **Наследование конфигурации**: файл `.replit`, зависимости и все файлы шаблона переносятся в новое приложение

Разработчик может сразу отправить Agent промпт с конкретными требованиями, а Agent будет работать в пределах ограничений, заданных шаблоном.

<div id="section-12">
  ## Как файлы работают вместе
</div>

Каждый конфигурационный файл выполняет свою роль:

| Файл                                 | Назначение                             | Когда Agent его читает                 | Может ли Agent его изменять            |
| ------------------------------------ | -------------------------------------- | -------------------------------------- | -------------------------------------- |
| `custom_instruction/instructions.md` | Стандарты и правила организации        | Всегда (внедряется в системный промпт) | Нет                                    |
| `.agents/skills/*/SKILL.md`          | Специальные рабочие процессы и шаблоны | По необходимости (когда это уместно)   | Да (Agent тоже может создавать навыки) |
| `replit.md`                          | Обзор проекта и базовые настройки      | Всегда (внедряется в системный промпт) | Да (Agent обновляет его со временем)   |
| `.replit`                            | Конфигурация среды выполнения          | При настройке приложения               | Да                                     |

**Ключевое различие**: `custom_instruction/instructions.md` — это статичный и авторитетный источник стандартов организации. `replit.md` — живой документ, который Agent поддерживает по мере развития проекта. Навыки — это справочные материалы для конкретных рабочих процессов, к которым обращаются по мере необходимости.

<div id="section-13">
  ## Рекомендации
</div>

<div id="section-14">
  ### Не перегружайте инструкции
</div>

Записывайте в `custom_instruction/instructions.md` только самые важные паттерны. Сосредоточьтесь на следующем:

* решения, которые трудно откатить (архитектура, модели данных);
* паттерны, которые нужно соблюдать единообразно (использование компонентов, правила работы с API);
* стандарты, о которых разработчик может не знать (внутренние библиотеки, правила команды).

Не включайте историю изменений, детали реализации и часто меняющуюся информацию.

<div id="section-15">
  ### Как писать описания навыков, которые легко найти
</div>

Поле `description` во фронтматтере файла `SKILL.md` — именно то, на что опирается Agent, решая, когда загрузить навык. Составляйте описание так, чтобы оно совпадало с задачами, для которых этот навык актуален:

```yaml theme={null}
# Хорошо — указано, когда использовать
description: Use when building forms or handling user input. Provides validation patterns, error display conventions, and accessible form layouts.

# Менее эффективно — слишком расплывчато
description: Form utilities and helpers.
```

<div id="section-16">
  ### Организация навыков по рабочим процессам
</div>

Группируйте навыки вокруг рабочих процессов, а не технических категорий:

| Подход                      | Пример                                       |
| --------------------------- | -------------------------------------------- |
| **По рабочим процессам**    | `build-a-form`, `connect-to-api`, `add-auth` |
| **По техническим областям** | `react-utils`, `api-helpers`, `auth-config`  |

Такой подход помогает Agent находить нужный навык в нужный момент.

<div id="section-17">
  ### Дорабатывайте шаблон итеративно
</div>

Шаблоны совершенствуются по мере использования. После того как команда начнёт разработку на основе шаблона:

1. Отмечайте паттерны, которые Agent обрабатывает неверно, и добавляйте их в `instructions.md`
2. Когда Agent удачно решает задачу, создавайте новый навык и фиксируйте в нём это решение
3. По мере развития стека обновляйте зависимости и конфигурацию по умолчанию
4. Проверяйте изменения, создавая из шаблона новое приложение, чтобы оценить итоговый опыт

<div id="section-18">
  ### Обновления шаблонов и существующие приложения
</div>

Изменения в приложении-шаблоне отражаются только во вновь создаваемых приложениях. Существующие приложения, ранее созданные форком шаблона, представляют собой независимые копии и обновления не получают.
