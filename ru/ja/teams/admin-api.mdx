<Note>
  Admin API находится в **бета-версии**. Доступные эндпоинты и их поведение могут измениться.
</Note>

Admin API предоставляет администраторам аккаунтов Enterprise программный доступ к функциям аналитики и управления аккаунтом на основе областей действия. Большинство эндпоинтов предоставляют доступ к данным аккаунта на чтение, а области действия на запись позволяют выполнять определённые операции, например обновлять бюджеты. Используйте этот API для создания внутренних отчётов, операционных процессов и интеграций для аккаунтов Enterprise.

<div id="admin-api">
  ## Пользователи с доступом к Admin API
</div>

Admin API доступен только **администраторам аккаунта** Enterprise. Они могут создавать API-ключи и управлять ими. Администраторы рабочего пространства и другие участники аккаунта не могут получать доступ к Admin API или создавать ключи для него.

Подробнее о роли администратора Enterprise см. в разделе [Администраторы аккаунта и рабочего пространства](/ru/ja/teams/identity-and-access-management/account-and-workspace-admins).

<div id="api">
  ## Создание API-ключа
</div>

<Steps>
  <Step title="Откройте настройки разработчика">
    В аккаунте Enterprise откройте **Настройки** и выберите **Разработчик**.
  </Step>

  <Step title="Создайте API-ключ">
    Выберите **Создать API-ключ**, затем укажите доступ только для чтения либо для чтения и записи.
  </Step>

  <Step title="Безопасно храните ключ">
    Скопируйте ключ, начинающийся с `rpl_`, и сохраните его в надёжном менеджере секретов. Обращайтесь с ним как с паролем и никому не передавайте.
  </Step>

  <Step title="Аутентифицируйте интеграцию">
    Передавайте ключ в API-запросах в качестве Bearer-токена.
  </Step>
</Steps>

<div id="section">
  ## Возможности
</div>

Admin API использует области действия, чтобы определять возможности каждого ключа. Области действия для чтения предоставляют данные аккаунта для отчетов, а отдельные области действия для записи позволяют выполнять такие операции, как обновление бюджетов.

* **Использование:** Получайте данные об использовании аккаунта и общих затратах по главной книге с фильтрацией или группировкой по рабочим пространствам, участникам, проектам и периодам.
* **Рабочие пространства:** Получайте список и сведения о рабочих пространствах, включая количество участников и проектов, администраторов и дату создания.
* **Участники:** Получайте сведения об участии в аккаунте и рабочих пространствах с возможностью фильтрации по ролям и поиска по имени, имени пользователя или адресу электронной почты.
* **Проекты:** Получайте сведения о проектах во всех командных рабочих пространствах с возможностью фильтрации по видимости и статусу развертывания, а также поиска по названию, слагу и описанию.
* **Бюджеты:** Получайте данные о бюджетах аккаунта. Их можно обновлять с помощью области действия `write:budgets`.

Ответы API поддерживают пагинацию на основе курсора и включают заголовки ограничения частоты запросов, а также `X-Request-Id` для отслеживания запросов.

<div id="replit-agent">
  ## Создание с Replit Agent
</div>

Вы можете поручить Replit Agent создать пользовательский дашборд с помощью Admin API. Опишите данные аккаунта, которые хотите отслеживать, например использование по рабочим пространствам или расходы по проектам, — и Agent создаст дашборд и настроит его интеграцию с API.

<Steps>
  <Step title="Откройте выбор навыков">
    В проекте Replit нажмите кнопку **+** рядом с полем ввода чата и выберите **Использовать навыки**.
  </Step>

  <Step title="Выберите навык Admin API">
    В разделе **Навыки Replit** выберите **Admin API**, чтобы предоставить Agent контекст API и рекомендации по интеграции.
  </Step>

  <Step title="Опишите дашборд">
    Сообщите Agent, что вы хотите отслеживать и как это должно отображаться. Например, попросите создать дашборд, показывающий использование по рабочим пространствам и расходы по проектам.
  </Step>

  <Step title="Безопасно добавьте API-ключ">
    Если Agent потребуется выполнять API-запросы, добавьте ключ Admin API в Secrets проекта. Не вставляйте ключ в чат и не коммитьте его в проект.
  </Step>
</Steps>
