При разработке мобильных приложений на Replit вы можете столкнуться с проблемами в предпросмотре, сборке бандла или зависимостях пакетов. Это руководство поможет устранить распространённые неполадки: начиная с быстрых решений и переходя к более глубокой отладке.

<div id="quick-fixes">
  ## Быстрые решения
</div>

Начните с них — они устраняют большинство проблем:

| Проблема                              | Что попробовать                                                       |
| ------------------------------------- | --------------------------------------------------------------------- |
| Изменения не отображаются на телефоне | Встряхните телефон, чтобы открыть меню Expo, затем нажмите **Reload** |
| Изменения не отображаются в предпросмотре   | Нажмите **R** в Console, чтобы пересобрать бандл                      |
| App завис или не отвечает             | Остановите и снова запустите App из Console                           |

<div id="common-issues">
  ## Распространённые проблемы
</div>

<AccordionGroup>
  <Accordion title="Изменения не появляются на моём устройстве">
    Если вы вносите изменения, но не видите их на телефоне:

    1. **Встряхните телефон**, чтобы открыть меню разработчика Expo
    2. Нажмите **Reload**, чтобы заново скачать бандл

    В веб-предпросмотре нажмите **R** в Console, чтобы запустить пересборку бандла.

    Если изменения по-прежнему не появляются, попробуйте очистить кэш (см. [Очистка кэша Metro](#clear-the-metro-cache) ниже).
  </Accordion>

  <Accordion title="Красный экран ошибки в Expo Go">
    Красный экран ошибки обычно означает ошибку JavaScript или отсутствующий модуль. Прочитайте сообщение об ошибке — часто в нём указаны конкретный файл и строка.

    **Частые причины:**

    * Пакет не установлен или установлена не та версия
    * Модуль работает в вебе, но не на нативной платформе (или наоборот)
    * Синтаксическая ошибка в коде

    **Что попробовать:**

    1. Внимательно прочитайте сообщение об ошибке — часто в нём прямо сказано, что не так
    2. Попросите Agent помочь исправить ошибку, передав ему это сообщение
    3. Если в ошибке упоминается конкретный пакет, попробуйте переустановить зависимости (см. [Переустановка пакетов](#reinstall-packages))
  </Accordion>

  <Accordion title="App работает в вебе, но падает на телефоне (или наоборот)">
    Некоторые пакеты и функции работают на разных платформах по-разному. React Native компилируется под три платформы: iOS, Android и веб. Библиотека, работающая в вебе, может не поддерживать нативные платформы или требовать другой настройки.

    **Что попробовать:**

    1. Проверьте в документации пакета, поддерживает ли он вашу платформу
    2. Спросите Agent: «Совместим ли этот пакет с Expo Go?»
    3. Подумайте о переносе этой функциональности на сервер, если на мобильных устройствах она не поддерживается

    <Tip>
      При изучении пакетов ищите пометку «Expo compatible» или сверяйтесь со списком поддерживаемых модулей в [документации Expo SDK](https://docs.expo.dev/versions/latest/).
    </Tip>
  </Accordion>

  <Accordion title="QR-код не сканируется или App не подключается">
    **Проверьте сеть:**

    * Телефон и компьютер должны быть в одной сети WiFi
    * Некоторые корпоративные и публичные сети блокируют такое соединение

    **Попробуйте режим туннеля:**
    Если вы работаете в сети с ограничениями, режим туннеля направит трафик через серверы Expo. Попросите Agent запустить App в режиме туннеля или выполните `npx expo start --tunnel` в Shell.

    **Перезапустите Expo Go:**
    Полностью закройте Expo Go и откройте заново перед сканированием.
  </Accordion>

  <Accordion title="Сборка занимает много времени">
    Первая сборка всегда медленнее, потому что кэша ещё нет. Последующие сборки должны идти быстрее.

    **Что влияет на время сборки:**

    * Количество пакетов в вашем проект
    * Первый запуск после очистки кэша
    * Скорость сети при скачивании пакетов

    Если сборки стабильно медленные, проверьте, не установлены ли лишние пакеты.
  </Accordion>

  <Accordion title="Ошибки «модуль не найден»">
    Если вы видите «Unable to resolve module» или «Module not found»:

    1. Пакет может быть не установлен — попросите Agent установить его
    2. Пакет может быть установлен, но кэш устарел — очистите кэш
    3. Пакета может не существовать или его имя написано с ошибкой — проверьте название пакета

    Если модуль всё же должен быть на месте, попробуйте [переустановить пакеты](#reinstall-packages).
  </Accordion>
</AccordionGroup>

<div id="debugging-commands">
  ## Команды для отладки
</div>

Если быстрые решения не помогают, эти команды позволяют сбросить различные кеши и состояния. Выполните их в Shell.

<div id="clear-the-metro-cache">
  ### Очистка кэша Metro
</div>

Metro — это бандлер, который компилирует ваш код React Native. Очистка его кэша заставляет выполнить сборку с нуля.

Выполните в Shell:

```bash theme={null}
npx expo start --clear
```

Эта команда очищает кэш бандлера и перезапускает сервер разработки. В выводе появится сообщение «Bundler cache is empty. Rebuilding.».

<Tip>
  Если проблемы с кэшем возникают часто, добавьте `-c` в команду запуска. Попросите Agent обновить команду разработки, добавив в неё флаг очистки.
</Tip>

<div id="reinstall-packages">
  ### Переустановка пакетов
</div>

Если возникают ошибки модулей или несоответствие версий, часто помогает переустановить пакеты.

В Shell выполните:

```bash theme={null}
rm -rf node_modules && npm install
```

Это удалит все установленные пакеты и переустановит их с нуля на основе вашего `package.json`.

<Note>
  Если в вашем проекте используется другой менеджер пакетов (например, `bun` или `pnpm`), выполните соответствующую команду установки: `bun install` или `pnpm install`.
</Note>

<div id="check-for-version-mismatches">
  ### Проверка несоответствий версий
</div>

Expo Doctor проверяет ваш проект на наличие типичных проблем — например, несоответствий версий между пакетами.

В Shell выполните:

```bash theme={null}
npx expo-doctor
```

Проверьте вывод на наличие предупреждений. Если в нём предлагаются исправления, тщательно оцените их — не обновляйте пакеты бездумно, поскольку это может привести к новым проблемам.

<Warning>
  Обновляйте пакеты только при наличии конкретной причины. Обновление &quot;просто так&quot; может нарушить работу вашего приложения, если новая версия содержит несовместимые изменения.
</Warning>

<div id="full-reset">
  ## Полный сброс
</div>

Если ничего больше не помогает, полный сброс очистит все кэши и переустановит всё заново.

<Accordion title="Крайняя мера: команда полного сброса">
  Эта команда удаляет все кэши и переустанавливает пакеты с нуля. Используйте её как последнее средство.

  ```bash theme={null}
  rm -rf node_modules .expo && npm cache clean --force && npm install && npx expo start --clear
  ```

  **Что делает эта команда:**

  1. `rm -rf node_modules` — удаляет установленные пакеты
  2. `rm -rf .expo` — удаляет локальный кэш Expo
  3. `npm cache clean --force` — очищает глобальный кэш npm
  4. `npm install` — переустанавливает все пакеты
  5. `npx expo start --clear` — запускает проект с чистым кэшем Metro

  После её выполнения следующая сборка займёт больше времени, так как всё будет собрано заново.
</Accordion>

<div id="clear-cache-on-your-device">
  ### Очистка кэша на устройстве
</div>

Если приложение на телефоне будто «застряло» на старом коде даже после перезагрузки:

* **iOS**: в Expo Go откройте **Settings** и нажмите **Clear Cache**
* **Android**: перейдите в **Settings &gt; Apps &gt; Expo Go &gt; Storage &gt; Clear Cache**

<div id="getting-more-help">
  ## Дополнительная помощь
</div>

Если проблема всё ещё не решена:

* **Спросите Agent**: опишите ошибку и то, что вы уже пробовали. Agent часто способен найти причину и устранить проблему.
* **Загляните в документацию Expo**: [руководство Expo по устранению неполадок](https://docs.expo.dev/troubleshooting/overview/) описывает дополнительные сценарии.
* **Поищите ошибку в интернете**: скопируйте точный текст сообщения об ошибке и выполните поиск — скорее всего, кто-то уже сталкивался с ней раньше.
