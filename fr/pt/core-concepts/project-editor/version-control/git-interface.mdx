title: "Utiliser le Git Pane"
description: "Apprenez à utiliser le Git Pane pour le contrôle de version, la gestion des branches et la collaboration dans le Project Editor."
---

Le Git Pane de Replit offre une interface visuelle pour les opérations Git, ce qui évite de passer par des commandes Git en ligne de commande. Cette fonctionnalité rend le contrôle de version accessible aux débutants, tout en restant puissante pour les développeurs expérimentés.

<div id="recursos">
  ## Fonctionnalités
</div>

Le Git Pane offre des fonctionnalités complètes de contrôle de version directement dans le Project Editor, avec une interface intuitive qui simplifie les opérations Git complexes.

* **Gestion des dépôts** : Initialisez, connectez et gérez des dépôts Git avec intégration à GitHub
* **Suivi des commits** : Indexez, validez et visualisez les modifications apportées à tous vos fichiers
* **Opérations sur les branches** : Créez, changez de branche et fusionnez des branches visuellement
* **Résolution des conflits** : Identifiez et résolvez les conflits de fusion avec une assistance visuelle
* **Intégration avec Shell** : Synchronisation entre les commandes Git exécutées dans le Shell et le Git Pane

<div id="uso">
  ## Utilisation
</div>

<div id="configurao-do-repositrio">
  ### Configuration du dépôt
</div>

<Accordion title="Comment accéder au Git Pane">
  1. Rendez-vous dans la section Tools de votre Replit App
  2. Sélectionnez le signe **+** pour ajouter de nouveaux outils
  3. Sélectionnez **Git** dans la liste des outils disponibles
</Accordion>

Le Git Pane vous aide à configurer et à connecter votre dépôt :

* **Initialiser le dépôt** : créez un dépôt Git pour votre Replit App
* **Se connecter à GitHub** : liez votre dépôt à GitHub pour la sauvegarde et la collaboration
* **Configurer le dépôt distant** : paramétrez et gérez la connexion à votre dépôt GitHub

<div id="gerenciamento-de-alteraes">
  ### Gestion des modifications
</div>

<Accordion title="Comment visualiser les modifications">
  1. Modifiez n&#39;importe quel fichier de votre Replit App
  2. Ouvrez le Git Pane dans la section Tools
  3. Examinez les modifications dans la section **Review Changes**
</Accordion>

Le Git Pane offre des outils pour gérer les modifications de votre code :

* **Examiner les modifications** : consultez les fichiers modifiés, avec les ajouts et les suppressions mis en évidence
* **Indexer des fichiers** : sélectionnez les fichiers à inclure dans votre prochain commit
* **Valider les modifications** : enregistrez vos modifications avec des messages descriptifs
* **Envoyer les mises à jour** : poussez vos commits vers GitHub en un seul clic

<Note>
  Vous pouvez utiliser Replit AI pour générer des messages de commit qui décrivent précisément vos modifications.

<div id="gerenciamento-de-branches">
  ### Gestion des branches
</div>

<Accordion title="Comment gérer les branches">
  1. Ouvrez le Git Pane dans la section Tools
  2. Sélectionnez le menu déroulant situé à côté du nom de la branche
  3. Créez une nouvelle branche ou sélectionnez-en une existante
</Accordion>

Le Git Pane simplifie le travail avec plusieurs versions de votre code :

* **Créer des branches** : créez de nouvelles branches pour développer des fonctionnalités de façon isolée
* **Changer de branche** : passez d&#39;une version de votre code à une autre
* **Publier des branches** : partagez vos branches sur GitHub
* **Récupérer les modifications** : synchronisez votre travail avec les mises à jour distantes de vos collaborateurs

<div id="resoluo-de-conflitos-de-merge">
  ### Résolution des conflits de fusion
</div>

<Accordion title="Comment résoudre les conflits de fusion">
  1. Essayez de récupérer les modifications en cas de conflit
  2. Le Git Pane mettra en évidence les fichiers en conflit
  3. Ouvrez chaque fichier en conflit pour afficher et résoudre les conflits
  4. Enregistrez les fichiers après avoir résolu les conflits
  5. Terminez la fusion en sélectionnant **Pull**
</Accordion>

Lorsque du code provenant de différentes sources entre en conflit, le Git Pane vous aide à :

* **Identifier les conflits** : voyez exactement quels fichiers contiennent des conflits
* **Visualiser les différences** : examinez les deux versions du code en conflit
* **Résoudre les problèmes** : choisissez le code à conserver ou modifiez manuellement le code en conflit
* **Finaliser les fusions** : terminez le processus de fusion après avoir résolu les conflits

<Frame>
  <img src="/assets/mirror/11-merge-conflict-17b314f0e231.png" alt="Éditeur de code affichant des marqueurs de conflit de fusion" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

Après avoir résolu un fichier en conflit, vous pouvez supprimer les marqueurs de conflit en supprimant les lignes commençant par des symboles de conflit, puis en enregistrant le fichier.

<div id="usando-comandos-git-no-shell">
  ### Utiliser les commandes Git dans le Shell
</div>

<Accordion title="Comment accéder au Shell">
  1. Sélectionnez **All tools** dans la barre latérale des outils à gauche
  2. Sélectionnez **Shell** parmi les outils disponibles
</Accordion>

<Tip>
  Bien que le Git Pane offre une interface conviviale, les utilisateurs avancés peuvent recourir aux commandes Git standard dans le Shell pour des opérations plus complexes. Les modifications effectuées par l&#39;une ou l&#39;autre méthode sont répercutées des deux côtés.
</Tip>

Si vous préférez utiliser Git en ligne de commande :

* **Synchronisation des commandes** : toute commande Git exécutée dans le Shell est automatiquement synchronisée avec le Git Pane
* **Fonctionnalités Git complètes** : accédez aux fonctionnalités avancées de Git absentes du Git Pane
* **Bascule fluide** : passez des commandes du Shell au Git Pane selon vos besoins

<Info>
  **Prise en charge des CLI GitHub et GitLab** : en plus des commandes Git standard, vous pouvez également utiliser le [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) et le [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) dans le Shell pour gérer des dépôts Git externes et vous y connecter. Ces outils offrent des fonctionnalités enrichies pour travailler avec les dépôts GitHub et GitLab, notamment les pull requests, les issues et d&#39;autres fonctionnalités propres à chaque plateforme.
</Info>

<div id="operaes-de-repositrio">
  #### Opérations sur les dépôts
</div>

* **Cloner un dépôt** : `git clone <url-du-dépôt>`
* **Initialiser un dépôt** : `git init`
* **Ajouter un dépôt distant** : `git remote add origin <url-du-dépôt>`

<div id="fazendo-alteraes">
  #### Effectuer des modifications
</div>

* **Vérifier l&#39;état** : `git status` (affiche les fichiers modifiés, ajoutés et supprimés)
* **Indexer des fichiers** : `git add <nom-du-fichier>` ou `git add .` (pour tous les fichiers)
* **Valider les modifications** : `git commit -m "votre message de commit"`
* **Envoyer les modifications** : `git push origin <nom-de-la-branche>`
* **Récupérer les modifications** : `git pull origin <nom-de-la-branche>`

<div id="autenticao">
  #### Authentification
</div>

Lorsque vous travaillez avec des dépôts privés, vous devez vous authentifier :

* Pour les dépôts GitHub, utilisez un jeton d’accès personnel plutôt que votre mot de passe
* Pour éviter de ressaisir vos identifiants, vous pouvez les stocker dans Replit Secrets :
  1. Créez un secret avec la clé `GIT_URL`
  2. Définissez sa valeur sur `https://<nom-d'utilisateur>:<jeton>@github.com/<utilisateur-ou-organisation>/<dépôt>`
  3. Utilisez `git push $GIT_URL` pour effectuer un push sans saisir vos identifiants

<Note>
  Lorsque vous utilisez des secrets contenant des identifiants, toute personne ayant accès à votre Replit App peut potentiellement accéder à vos identifiants Git. Pour les dépôts sensibles, envisagez de saisir vos identifiants manuellement à chaque fois.
</Note>
