<div id="new-agent-modes-dropdown">
  ### 새로운 Agent 모드 드롭다운
</div>

채팅 입력창의 Agent 모드 선택기가 더 간단한 세그먼트 컨트롤로 바뀌었습니다. 툴바에서 바로 Lite, Economy, Power 중 하나를 고르고, 필요할 때는 Advanced settings에서 Turbo를 사용할 수 있습니다.

새로워진 점:

* **툴바의 세그먼트 컨트롤.** Lite, Economy, Power가 나란히 배치되어 지금 어떤 모드를 쓰고 있는지, 어떻게 전환하는지 한눈에 알 수 있습니다.
* **키보드 단축키.** **⌘+Shift+I**(Windows에서는 Ctrl+Shift+I)를 누르면 마우스 없이도 모드를 차례로 전환할 수 있습니다.
* **주황색으로 강조되는 Turbo.** Turbo는 가장 빠른 모드이지만 비용이 더 들기 때문에, 비용과의 트레이드오프가 드러나도록 UI에서 눈에 띄게 표시됩니다.
* **기본적으로 접혀 있는 Advanced settings.** 테스트, 코드 리뷰, Turbo 관련 컨트롤은 **Advanced settings** 안에 있어 기본 화면이 깔끔하게 유지됩니다.
* **Max 모드는 종료되었습니다.** 가장 뛰어난 성능이 필요한 빌드에는 Power를 사용하고, 가장 빠른 응답이 필요하면 Advanced settings에서 Turbo를 켜세요.

<div id="agent-suggests-follow-up-tasks">
  ### Agent가 후속 작업을 제안합니다
</div>

<Frame>
  <video autoPlay muted loop playsInline src="/assets/mirror/replit-suggested-tasks-b27620d93fd2.mp4" />
</Frame>

이제 Agent는 작업을 마치면 project의 전체 context를 바탕으로 다음에 만들면 좋을 **후속 작업**을 제안합니다. 완료된 각 task 아래에 세 가지 종류의 제안이 표시됩니다.

* **새로 만들 기능** — 방금 배포한 기능과 자연스럽게 어울리는 기능
* **성능 개선** — Agent가 task를 진행하면서 발견한 최적화 항목
* **사용자 경험 향상** — 기능의 완성도를 높이는 마무리 작업

각 제안을 검토한 뒤 원하는 항목에서 **Accept**를 선택하면, 여러분이 작업을 이어가는 동안 Agent가 백그라운드에서 해당 작업을 실행합니다. 필요 없는 제안은 Done 열의 **Hide suggested tasks**로 숨길 수 있고, 언제든 다시 표시할 수 있습니다.

[후속 작업 제안](/ko/features/agent/follow-up-tasks)에 대해 자세히 알아보세요.

<div id="projects-page-improvements">
  ### Projects 페이지 개선 사항
</div>

Projects 페이지에 편의성을 높여주는 세 가지 개선 사항이 추가되었습니다:

* **모든 카드에서 artifact 미리 보기.** 이제 각 project 카드에 그 안에 담긴 artifact가 작은 icon으로 표시됩니다. icon 위에 마우스를 올리면 project를 열지 않고도 해당 artifact의 스크린샷을 미리 볼 수 있습니다.
* **최근에 연 순서로 기본 정렬.** 이제 *본인*이 가장 최근에 작업한 project가 맨 위에 표시되므로, 바쁘게 돌아가는 team workspace에서도 현재 작업에 집중할 수 있습니다.
* **개인 pin 기능.** 자주 찾는 project를 pin해 두세요. pin은 본인에게만 적용되며, workspace의 다른 Member에게 보이는 화면에는 영향을 주지 않습니다.

<div id="custom-groups-for-scim-organizations">
  ### SCIM 조직을 위한 custom group
</div>

SCIM provisioning이 활성화된 Organization은 이제 IdP와 동기화된 groups 외에 Replit에서 custom group을 직접 만들 수 있습니다. project 단위 접근 권한, 일회성 권한 부여, 또는 identity provider에 반영되지 않은 구조가 필요할 때 custom group을 활용하세요.

SCIM으로 동기화된 groups는 계속 identity provider를 통해 관리되며, custom group은 Organization 관리자가 Replit에서 직접 관리합니다.

자세한 내용은 [SCIM](/ko/teams/identity-and-access-management/scim#creating-custom-groups-alongside-scim) 문서를 참조하세요.
