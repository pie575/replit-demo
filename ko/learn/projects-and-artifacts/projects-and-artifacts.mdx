**project**는 Replit에서 만드는 모든 것을 담는 컨테이너입니다. **artifact**는 그 안에 담기는 게시 가능한 결과물로, web app, mobile app, slide deck, 애니메이션, 데이터 시각화, 3D 게임, design 등이 있습니다.

한 가지 이상을 만들고 있다면 선택지는 두 가지입니다. 하나의 project에 여러 artifact를 추가하거나, 별도의 project를 만드는 것입니다. 어느 쪽이 적합한지는 앱들이 데이터와 로직, deployment 수명 주기를 공유하는지에 따라 달라집니다. 이 페이지에서는 두 용어를 자세히 살펴보고, artifact를 하나의 project에 모아 두는 것이 좋은 경우와 별도의 project로 나누는 것이 좋은 경우를 알려 드립니다.

<div id="whats-a-project">
  ## project란 무엇인가요?
</div>

project는 코드, 데이터, 그리고 여러분이 만드는 모든 artifact를 담는 컨테이너입니다. Agent에게 원하는 바를 알려주면 Agent가 project를 만들고 그 안에 artifact를 구축합니다.

project는 책상 위의 작업 공간이라고 생각하면 됩니다. 모든 것이 한곳에 모여 있어 같은 정보를 공유할 수 있지만, 각 요소는 저마다 다른 역할을 합니다.

예를 들어 Agent에게 피트니스 추적 앱을 만들어 달라고 하면, mobile app artifact와 함께 이를 구동하는 데 필요한 backend, database, 스토리지를 갖춘 project를 생성합니다.

핵심 개념:

* **Project**: 코드, 데이터, 모든 artifact 등 모든 것을 담는 컨테이너입니다.
* **Artifact**: project 안에서 게시할 수 있는 결과물입니다(web app, slide deck, 동영상 등).
* **리소스**: 모든 artifact는 별도의 설정 없이 backend, database, 파일 스토리지를 자동으로 사용할 수 있습니다.

project로 할 수 있는 모든 작업(관리, filter, pin, 정렬)은 [Projects](/ko/features/projects-and-artifacts/projects)를 참고하세요.

<div id="whats-an-artifact">
  ## artifact란?
</div>

artifact는 Replit에서 게시할 수 있는 결과물입니다. 각 artifact는 그 자체로 완결된 독립 산출물이며, 게시하면 고유한 shareable URL이 부여됩니다.

project에 있는 나머지 요소(파일, 이미지, CSV, 코드)는 artifact를 뒷받침하는 역할일 뿐, 그 자체로는 게시할 수 없습니다.

<div id="what-artifacts-share-in-a-project">
  ## project에서 artifact가 공유하는 항목
</div>

[artifact](/ko/features/projects-and-artifacts/artifacts)가 같은 [project](/ko/features/projects-and-artifacts/projects) 안에 있으면 다음 항목이 자동으로 공유됩니다:

* **Database**: 한 artifact가 데이터를 쓰면 다른 artifact가 즉시 읽을 수 있습니다.
* **backend 및 API**: 서버 로직을 공유하므로 코드를 중복 작성할 필요가 없습니다.
* **파일 스토리지**: 이미지, 문서, 업로드한 파일을 artifact 간에 함께 사용할 수 있습니다.
* **deployment**: 게시하면 모든 항목이 함께 동기화되어 라이브로 전환됩니다.

따라서 artifact 사이에 별도의 연결을 설정하거나 코드를 중복해서 작성할 필요가 없습니다. 다만 특정 artifact 하나만 따로 게시할 수는 없습니다.

<div id="quick-guide">
  ## 빠른 가이드
</div>

기존 project에 artifact를 추가할지, 별도의 project를 만들지 결정할 때 고려해야 할 주요 시나리오는 다음과 같습니다.

| **하나의 project에 여러 artifact 사용**                   | **별도의 project 사용**                           |
| ------------------------------------------------- | -------------------------------------------- |
| 앱이 동일한 데이터와 backend를 공유하는 경우                      | 앱이 내부 로직이나 데이터를 공유하지 않는 경우                   |
| 모든 것을 한 번에 게시하려는 경우                          | 독립적인 게시 주기가 필요한 경우                   |
| 서로 보완적인 경우(예: 고객용 앱과 admin dashboard)             | 서로 관련 없는 제품이거나 고객사가 다른 경우                    |
| 한 artifact의 변경 사항이 다른 artifact에 자동으로 반영되도록 하려는 경우 | 캠페인 landing page나 이벤트 사이트처럼 project가 단기성인 경우 |

<div id="examples">
  ## 예시
</div>

<div id="same-project-web-app-mobile-app-for-one-product">
  ### 같은 project: 하나의 제품을 위한 web app + mobile app
</div>

한 레스토랑에서 고객이 메뉴를 둘러보는 web app과 직원이 주문을 관리하는 mobile app을 만듭니다. 두 앱 모두 메뉴 항목, 주문, 고객 정보가 담긴 동일한 database에 연결됩니다.

**하나의 project로 만드는 이유:** 두 앱이 동일한 데이터와 backend를 공유하기 때문입니다. 고객이 web app에서 주문을 넣으면 직원은 mobile app에서 즉시 확인할 수 있습니다.

<div id="same-project-app-admin-dashboard-investor-pitch-deck">
  ### 동일한 project: 앱 + admin dashboard + investor pitch deck
</div>

한 스타트업이 주력 제품과 콘텐츠 관리를 위한 내부 관리자 패널, 그리고 자금 유치를 위한 slide deck을 모두 하나의 project 안에서 만듭니다.

**하나의 project로 묶는 이유:** admin dashboard가 앱에 표시되는 것과 동일한 데이터를 관리하고, pitch deck에서는 공유 backend의 실시간 지표를 참조할 수 있기 때문입니다.

<div id="separate-projects-two-unrelated-client-apps">
  ### 별도의 project: 서로 관련 없는 두 고객사 앱
</div>

한 프리랜서가 어떤 고객사를 위해 전자상거래 스토어를 만들고, 다른 고객사를 위해 예약 시스템을 만듭니다.

**별도의 project로 나누는 이유:** 두 앱은 공유하는 데이터나 로직이 없습니다. 고객사마다 독립적인 게시가 필요하고, 한쪽의 변경 사항이 다른 쪽에 영향을 주지 않아야 하기 때문입니다.

<div id="separate-projects-campaign-landing-page-alongside-a-main-product">
  ### project 분리: 메인 제품과 함께 운영하는 캠페인 landing page
</div>

연중 상시 운영되는 production 앱이 있고, 마케팅 캠페인용 단기 landing page를 함께 운영하는 경우입니다.

**project를 분리하는 이유:** 캠페인 페이지는 자체적인 수명 주기를 가집니다. 새로 만들어 몇 주간 운영한 뒤 내리게 됩니다. 분리해 두면 메인 제품이 불필요하게 복잡해지지 않고, 캠페인 페이지를 독립적으로 게시하거나 제거할 수 있습니다.

<div id="frequently-asked-questions">
  ## 자주 묻는 질문
</div>

<Accordion title="artifact를 다른 project로 옮길 수 있나요?">
  현재는 불가능합니다. artifact를 분리해야 한다면 새 [project](/ko/features/projects-and-artifacts/projects)를 만든 뒤 Agent에게 그곳에서 다시 만들어 달라고 요청하세요.
</Accordion>

<Accordion title="하나의 project에 담을 수 있는 artifact 수에 제한이 있나요?">
  project 하나에는 최대 7개의 artifact를 담을 수 있으며, **project당 mobile app은 1개**로 제한됩니다. artifact가 늘어날수록 메모리를 더 많이 사용해 preview 속도가 느려질 수 있어 이러한 제한을 두고 있습니다. 더 많은 artifact가 필요하다면 별도의 [project](/ko/features/projects-and-artifacts/projects)를 새로 시작하세요.
</Accordion>

<Accordion title="project에서 artifact 하나만 게시할 수 있나요?">
  현재는 불가능합니다. Publishing은 모든 항목을 한 번에 라이브로 전환합니다. 각각 따로 게시해야 한다면 project를 나누어 사용하세요.
</Accordion>

  네. 한 project 안의 모든 artifact는 동일한 database와 backend 서비스를 공유합니다. web app에서 데이터를 기록하면 mobile app과 data dashboard에서 곧바로 그 데이터를 읽을 수 있습니다.
</Accordion>

<Accordion title="artifact와 파일의 차이는 무엇인가요?">
  artifact는 앱, slides, 영상처럼 게시할 수 있는 결과물입니다. 파일(CSV, 이미지, 코드 등)은 artifact를 뒷받침하는 project 내 assets으로, 그 자체만으로는 게시할 수 없습니다.
</Accordion>
