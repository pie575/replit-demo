<div id="section">
  ## 什么是 task 系统？
</div>

**task** 是 Agent 可以规划和执行的工作单元。借助 task，Agent 可以将较大的目标拆分为更小的部分，以便在将每个部分应用到应用前进行审核。

Agent 可以在两个地方开展工作：**主会话**和**后台 task**。主会话是你描述需求、调整方向并决定哪些内容要应用到主版本的 Conversation。后台 task 则是独立的会话，Agent 会在项目的隔离副本中自行工作。

请使用主会话确定方向并做出决策。对于可并行开展的执行工作，请使用后台 task。在审核并应用之前，后台 task 不会更改主版本。

task 系统是 Agent 用来组织这些工作的方式。当你描述想要构建的内容时，Agent 可以将请求拆分为单独的 task，并将其放入包含**草稿**、**进行中**、**已就绪**和**Done**列的任务看板中。

<Frame>
  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="任务看板显示按草稿、进行中、已就绪和 Done 列组织的 task" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />
</Frame>

每个 task 会随着进展从左向右移动，因此你可以一目了然地查看已计划的内容、Agent 正在处理的内容、可供审核的内容以及已完成的内容。后台 task 会根据计划自动进入队列，让工作持续推进，而不会占满主会话。

task 完成后，你可以审核更改并将其应用到主版本；如果不符合预期，也可以取消。

<div id="section-2">
  ## 后台 task 的工作方式
</div>

<Steps>
  <Step title="规划 task">
    在会话中发起对话，或创建新会话并在其中规划。Agent 会审查你的项目，找出最具影响力的工作，并为每个 task 制定详细计划，包括需要执行的工作以及“完成”的标准。

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="在会话中描述要构建的内容，Agent 提议并运行 task" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="审查并接受">
    Agent 会提议一组 task，其中包含标题、描述，以及可通过**查看计划**查看的详细计划。审查完整列表后，选择：

    * **接受 task**：启动所有 task 并将其转入后台运行
    * **修改计划**：让 Agent 在开始前调整 task

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="task 计划创建对话框，显示四个提议的 task，以及“接受 task”和“修改计划”选项" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="开始运行 task">
    task 被接受后，会在项目的隔离副本中开始运行。Core 一次可运行 1 个后台 task，Pro 最多支持 10 个并发后台 task。在你选择应用更改之前，主版本将保持不变。你可以通过两种方式跟踪进度：

    * **会话视图**：每个 task 都会在各自的会话中运行，并显示实时状态指示器，因此你可以跟踪 task 的进度或参与对话。

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="会话视图，显示多个 task 正在并行运行并带有状态指示器" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **看板视图**：以列式看板按状态整理所有 task：**草稿**、**进行中**、**已就绪**、**Done**

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="看板视图，显示按草稿、进行中、已就绪和 Done 列组织的 task" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="审查并应用">
    task 完成后，Agent 会显示工作日志、测试结果以及更改的实时预览。接下来，你可以：

    * **将更改应用到主版本**：将 task 的工作合并到项目中
    * **取消**：如果结果不符合预期，则放弃更改

    应用多个 task 的更改时，Agent 会自动解决冲突。

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="task 审查屏幕，显示 Agent 的工作日志、测试结果和“应用更改”按钮" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="section-4">
  ## 可以构建的内容
</div>

任务系统适用于所有项目。以下是几种尤其有效的模式：

* **将大型功能拆分为小单元上线**：将身份验证、控制面板和 API 层拆分为独立task，让 Agent 可以有条不紊地处理
* **规划复杂项目**：将大型功能拆分为定义清晰的task和依赖关系，并自信地执行
* **比较不同的设计方向**：使用独立task尝试多种界面方案，并选择最佳结果

<div id="section-5">
  ## 常见问题
</div>

<Accordion title="我需要改变构建方式吗？">
  不需要。主会话的工作方式不变。Agent 会在需要时自动在后台创建task。您也可以使用 [Plan 模式](/zh/ko/features/agent/plan-mode) 显式查看和管理task。
</Accordion>

<Accordion title="为什么task一次只能运行一个？">
  Core 一次可运行 1 个后台task。Pro 最多支持 10 个并发后台task。达到套餐上限后，其他task会进入队列，并在有空余名额时启动。
</Accordion>

<Accordion title="Agent 在应用后台task时如何处理冲突？">
  Agent 使用 AI 辅助冲突解决功能。它会理解每个task要实现的目标，并智能地应用更改。如果有任何异常，您可以在会话中要求 Agent 修复。
</Accordion>

<Accordion title="task之间可以相互依赖吗？">
  可以。Agent 会自动检测依赖关系。例如，构建控制面板的task会依赖于创建数据库架构的task。依赖task会等待前置条件完成。
</Accordion>

<Accordion title="归档task和取消task有什么区别？">
  **归档**适用于计划会话：即尚未开始构建的草稿。已归档的计划会话会被保留，您可以在**已完成**列中恢复。

  **取消**适用于已从计划阶段进入构建阶段的task。取消会停止task并丢弃其工作内容，且无法恢复已取消的task。请改为启动新task。
</Accordion>
