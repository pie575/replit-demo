---
title: "Статические публикации"
description: "Узнайте, как публиковать статические сайты и фронтенд-приложения с помощью Static Deployments."
---

Static Deployments размещают статические файлы вашего Replit App — HTML, CSS и JavaScript —
на облачном сервере. Сервер автоматически применяет кеширование и масштабирование, чтобы доставлять
контент быстро и экономично.

Static Deployments идеально подходят для следующих сценариев:

* Маркетинговые лендинги
* Сайты-портфолио
* Сайты с документацией по продуктам и API

<Note>
  Static Deployments не поддерживаются для Replit App, созданных с помощью Agent.
  Agent автоматически создаёт полностековые приложения, которым нужен бэкенд-сервер. Для
  приложений, созданных Agent, используйте один из следующих типов deployment: - [Autoscale
  Deployment](/ru/pt/features/publishing/autoscale-deployments) - [Reserved VM
  Deployment](/ru/pt/features/publishing/reserved-vm-deployments)
</Note>

<div id="recursos">
  ## Возможности
</div>

Static Deployments включают следующие возможности:

* **Экономичный хостинг**: вы платите только за объём данных, которые отдаёт ваш сайт.
* **Гибкая HTTP-маршрутизация**: настраивайте заголовки ответов, правила перезаписи URL и перенаправления.
* **Пользовательские домены**: подключите собственный домен или используйте URL вида `<имя-приложения>.replit.app` для доступа к приложению.
* **Пользовательские страницы ошибок**: создайте собственную страницу ошибки 404 и отдавайте её посетителям.
* **Мониторинг**: просматривайте логи и отслеживайте состояние опубликованного приложения.

<div id="uso">
  ## Использование
</div>

Открыть Static Deployments можно в инструменте Publishing в Project Editor.

<Accordion title="Как открыть Static Deployments">
  На **Tool dock** слева:

  1. Выберите <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Значок всех инструментов" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools**, чтобы увидеть список инструментов Project Editor.
  2. Выберите <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Значок Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Выберите вариант **Static**, а затем — **Set up your published app**.

  Через **строку поиска**:

  1. Нажмите на <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="значок лупы" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> лупу вверху, чтобы открыть инструмент поиска
  2. Введите «Publishing», чтобы найти инструмент, и выберите его в результатах.
  3. Выберите вариант **Static**, а затем — **Set up your published app**.
</Accordion>

<div id="domnio-principal">
  ### Основной домен
</div>

Укажите поддомен в имени хоста для вашего опубликованного app. После публикации ваш app будет доступен по адресу `https://<subdomain>.replit.app`.

О том, как использовать собственный домен, читайте в разделе [Собственные домены](/ru/features/publishing/custom-domains).

<div id="deployment-privado">
  ### Приватный deployment
</div>

<Info>
  Функция приватной публикации приложения доступна в планах Pro и Enterprise.
</Info>

Приватно опубликованные приложения открывают доступ только участникам вашего workspace либо конкретным пользователям и группам, которых вы пригласите.
При публикации можно выбрать один из вариантов доступа: **Public**, **Password protected**, **Workspace only** или **Invite only**.

О том, как настроить приватный deployment, читайте в разделе [Доступ к приложению](/ru/features/publishing/private-deployments/).

<div id="diretrio-pblico">
  ### Публичный каталог
</div>

Укажите путь к базовому каталогу в вашем Replit App, где находятся статические файлы, которые нужно раздавать публично.
После деплоя облачный хост будет отдавать все страницы и ресурсы из этого каталога.

Значение по умолчанию `/` — это корневой каталог вашего Replit App.

<div id="build-command">
  ### Build command
</div>

Укажите команду сборки, которая будет выполнена в Shell вашего Replit App при создании deployment.

Например, если вы генерируете статический сайт с помощью <a href="https://gohugo.io/" target="_blank">Hugo</a>,
можно использовать команду `hugo --minify`, чтобы собрать файлы и уменьшить размер ресурсов.

<div id="deployment-secrets">
  ### Deployment secrets
</div>

Выберите **Add deployment secret**, чтобы добавить переменные окружения или Secrets, необходимые вашей команде сборки для безопасного выполнения.

Например, если генератору вашего сайта нужен ключ API для сборки статического сайта, вы можете передать его
как `API_KEY=<имя вашего secret>`.
