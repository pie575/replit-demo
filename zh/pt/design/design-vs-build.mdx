每个 Replit 项目都有两个入口，并排位于顶部标题栏中：**Design** 和 **Build**。Design 用来打磨软件的外观，Build 则由 Agent 让它真正运行起来。两者打开的是同一个项目，因此你设计的成果不会被锁死在某个设计工具里。

<div id="o-que-o-design">
  ## 什么是 Design？
</div>

[Design](/zh/pt/design/what-is-replit-design) 打开的是 Canvas，你可以在这里用 prompt 生成设计设计帧、探索多种变体，并打磨出最满意的那一版——这一切都无需先写代码。

Design 非常适合用来：

* **快速验证想法**：在开发功能之前先看到应用的设计效果
* **打造精致的网站**：landing page、作品集、餐厅菜单、活动页面
* **精细调整设计**：即时调整颜色、布局和内容

<Info>
  Design 中的原型稿在外观和交互上都与真实页面无异，但尚不能存储数据或连接外部服务。当你对整体效果满意后，只需一次点击即可将设计转化为完整的 App。下面的步骤将说明具体做法。
</Info>

<div id="o-que-o-build">
  ## 什么是 Build？
</div>

Build 是让你的创意真正变成一个可运行应用的地方——它可以保存数据、支持用户登录，并连接到其他服务。

当你的应用需要以下能力时，请使用 Build：

* **用户账户**：让用户注册账户并登录
* **数据留存**：存储订单、消息或用户偏好等信息
* **对接其他服务**：处理支付、发送邮件，或从其他应用获取数据
* **复杂任务**：运营在线商店、管理预订，或为面板提供数据支持

<div id="usando-os-dois-juntos">
  ## 两者结合使用
</div>

Design 和 Build 作用于同一项目，因此你无需二选一。先从外观入手，再逐步做成完整的应用。

<Steps>
  <Step title="先做设计">
    从 Design 开始，快速把你的想法可视化。专注于应用的外观和行为：布局、配色、按钮以及用户体验。
  </Step>

  <Step title="精修与迭代">
    采纳一条[建议](/zh/pt/design/explore-suggestions)，为选中的设计帧探索新的方向；也可以选择 **Edit** 工具并点击某个元素，在 [Visual Editor](/zh/pt/design/visual-editor) 中进行调整。你还可以[与 Agent 对话](/zh/pt/design/chat-about-your-design)，描述你想要的更改。

    <Frame>
      <img src="/assets/mirror/ambient-iq-0989ea31bce7.png" alt="选中的网站设计帧，展示 APEX X1 超级跑车主视觉，旁边的建议后续步骤面板提供了「探索不同方案」「尝试不同布局」「探索不同风格」和「给我惊喜」等建议标签" width="2000" height="1254" data-path="images/design/replit-design/ambient-iq.png" />
    </Frame>
  </Step>

  <Step title="构建设计">
    当你对设计满意，准备加入真实功能时，在设计帧上选择 **Build…**。你可以创建新的产物，也可以把设计应用到已有产物上；Agent 会加上保存数据、管理用户账户和连接服务的能力，同时完整保留你的设计。

    <Frame>
      <img src="/assets/mirror/canvas-build-menu-f06b8b8b455f.png" alt="在选中的 Design 设计帧（APEX X1 Exact Replica）上打开的 Build 菜单，标题为「Build or apply your designs」，显示用于创建新产物的「Build this design」，以及列出项目中 APEX X1 Design System 和 Scroll Hero 网站的「Apply to an existing creation」" width="2000" height="1153" data-path="images/replitai/canvas-build-menu.png" />
    </Frame>

    <Note>
      当你尝试向原型稿添加数据库或高级功能时，Agent 会提示你先进行转换。
    </Note>
  </Step>

  <Step title="发布与分享">
    应用构建完成后，将其发布，任何人都能在线访问。Replit 会处理全部技术基础设施，让你的应用稳定地服务于你的受众。
  </Step>
</Steps>

<div id="quando-comear-em-cada-um">
  ## 何时从哪个模式开始
</div>

<CardGroup cols={2}>
  <Card title="从 Design 开始" icon="paintbrush">
    * 外观是难点所在
    * 你想快速看到想法成型
    * 你想探索并比较不同方向
    * 速度是你的首要考量
  </Card>

  <Card title="从 Build 开始" icon="cube">
    * 功能行为是难点所在
    * 你的 App 从第一天起就需要保存数据
    * 用户需要登录
    * 你要接入其他服务
  </Card>
</CardGroup>

<Tip>
  **不确定该选哪个？** 从 Design 开始。它更快，而且你随时可以把设计稿变成完整的 App。你的成果绝不会白费，构建时都会被沿用。反过来同样可行：先在 Build 中做出可运行的 App，之后再到 Design 中重新调整样式。
</Tip>

<div id="principais-diferenas">
  ## 主要区别
</div>

| 功能       | Design (原型稿)  | Build (应用)  |
| -------- | ------------- | ----------- |
| **速度**   | 几分钟           | 完整应用约 10 分钟 |
| **数据存储** | 仅视觉呈现 (不保存)   | 保存并读取真实数据   |
| **用户账户** | 仅展示登录界面样式     | 真正可用的登录功能   |
| **连接服务** | 不支持           | 支付、邮件、外部数据  |
