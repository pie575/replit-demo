Les déploiements Reserved VM s&#39;exécutent sur une machine virtuelle (VM) qui fournit des ressources de calcul dédiées à votre application. Ce type de déploiement offre des coûts et des performances prévisibles, sans interruption de service.

Il convient parfaitement aux cas d&#39;usage suivants :

* Tâches en arrière-plan gourmandes en mémoire
* Bots d&#39;applications de messagerie nécessitant une connexion permanente
* Serveurs API actifs en permanence

<div id="section">
  ## Fonctionnalités
</div>

Les déploiements Reserved VM incluent les fonctionnalités suivantes :

* **Ressources dédiées** : des ressources de calcul réservées assurent des performances constantes à votre App.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez l&#39;URL `<app-name>.replit.app` pour accéder à votre App.
* **Options de ressources de calcul** : choisissez l&#39;option de VM adaptée aux besoins de performance de votre App.
* **Mappage de ports configurable** : définissez les ports que votre App expose sur Internet.
* **Surveillance** : consultez les journaux et suivez l&#39;état de vos Apps publiées.

<div id="section-2">
  ## Utilisation
</div>

Les déploiements Reserved VM sont accessibles depuis l&#39;outil Publishing de l&#39;éditeur de projet.

<Accordion title="Comment accéder aux déploiements Reserved VM">
  Depuis le **dock d&#39;outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône All tools" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils de l&#39;éditeur de projet.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Reserved VM**, puis **Set up your published app**.

  Depuis la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" />loupe en haut pour ouvrir l&#39;outil de recherche
  2. Saisissez « Publishing » pour rechercher l&#39;outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l&#39;option **Reserved VM**, puis **Set up your published app**.
</Accordion>

<div id="section-3">
  ### Configuration de la machine
</div>

Choisissez la configuration du processeur (CPU) et de la mémoire vive (RAM) de la machine qui héberge votre déploiement. Le coût correspondant s&#39;affiche à côté de chaque taille de machine sélectionnée.

<div id="section-4">
  ### Domaine principal
</div>

Indiquez la partie sous-domaine du nom d&#39;hôte de votre app publiée. Après la publication, votre app est accessible à l&#39;adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Domaines personnalisés](/fr/features/publishing/custom-domains).

<div id="section-5">
  ### プライベートデプロイ
</div>

<Info>
  La fonctionnalité d&#39;app publiée en privé est disponible avec les forfaits Pro et Enterprise.
</Info>

Les apps publiées en privé n&#39;autorisent l&#39;accès à votre app qu&#39;aux membres de votre workspace, ou aux utilisateurs et groupes spécifiques que vous invitez.
Au moment de la publication, vous pouvez choisir entre les accès **Public**, **Password protected**, **Workspace only** et **Invite only**.

Pour savoir comment configurer un déploiement privé, consultez [Accès à l&#39;app](/fr/features/publishing/private-deployments/).

<div id="section-6">
  ### Commande de build
</div>

Dans le champ **Build command**, saisissez la commande shell qui compile ou configure votre application avant l&#39;exécution de la commande Run.
Par exemple, pour optimiser une application JavaScript en vue de la production avec Vite, vous pouvez ajouter la commande `vite build`.

<div id="section-7">
  ### Commande d&#39;exécution
</div>

Dans le champ **Run command**, saisissez la commande shell qui lance votre tâche. Cette commande doit être similaire à celle que vous utilisez dans vos workflows. Par exemple, pour lancer une app Flask nommée « myApp », vous pouvez ajouter la commande `flask --app myApp run`.

<div id="section-8">
  ### Secrets de l&#39;application publiée
</div>

Sélectionnez **Add published app secret** pour ajouter les variables d&#39;environnement et les secrets nécessaires à l&#39;exécution sécurisée de votre application.

Si votre Replit App contient des variables d&#39;environnement ou des secrets, l&#39;outil Publishing les ajoute automatiquement à la liste.

<div id="section-9">
  ### Options de type d&#39;application
</div>

Sélectionnez l&#39;une des options suivantes :

* **Web server** : choisissez cette option pour publier une application web ou toute application à laquelle les utilisateurs peuvent se connecter via Internet.
* **Background worker** : choisissez cette option si votre application n&#39;écoute aucun port et ne démarre pas de serveur.

Si vous sélectionnez **Web Server**, vous pouvez personnaliser les ports à exposer en procédant comme suit :

1. Développez la section **Port configuration**.
2. Sélectionnez **Networking pane to configure** pour ouvrir l&#39;onglet **Networking** et gérer le mappage des ports.

Pour en savoir plus sur la configuration des ports, consultez [Ports](/fr/ja/features/project-setup/ports/).
