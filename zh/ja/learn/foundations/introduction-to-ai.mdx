借助 AI 工具，你可以用自然语言发出指令并获得有用的输出。在 Replit 中，这些输出可以是计划、代码、设计、说明、调试步骤，以及对项目所做的更改。

开始构建前，无需深入了解 AI。掌握一些基本概念可以帮助你给出更好的指令，并更有信心地评估结果。

<div id="section">
  ## 大语言模型
</div>

大多数 AI 构建工具的背后都是大语言模型，也就是通常所说的 LLM。LLM 是经过训练、能够识别文本中的模式并生成符合这些模式的文本的模型。

这里所说的文本，涵盖文章、代码、HTML、CSS、SQL、JSON、终端命令、测试输出、错误信息和配置。正因如此，同一类模型既能帮你撰写文案，也能解释 bug、编写代码、总结方案。

<div id="section-2">
  ## 文本生成
</div>

LLM 并不是从数据库里查出固定答案，而是根据你提供的输入和它所能看到的上下文，逐字逐句地生成回复。

当你写下提示词时，模型会结合你的措辞、对话内容和可用的项目上下文，预测接下来最有帮助的回复。这个回复可能是一段解释、一份计划，也可能是供其他系统据此执行操作的文本。

因此，输入的质量至关重要。目标明确、给出示例、说明约束和补充上下文，都能让结果更接近你的预期。

<div id="section-3">
  ## 令牌 (Token)
</div>

AI 模型以称为令牌 (token) 的小单位来处理文本。一个令牌可以是一个单词、单词的一部分、标点符号、空格，或是一小段代码。

令牌之所以重要，是因为它决定了 AI 模型一次能够处理的信息量。冗长的对话、大型文件、日志、截图和指令，都会占用模型用于推理的上下文。

构建应用时，你无需刻意去数令牌，只要明白一点：关键信息越清晰、越新、越聚焦，Agent 的表现就越好。

<div id="ai">
  ## AI 具有不确定性
</div>

AI 的输出并非每次都完全相同。同样的请求，可能生成不同的措辞、设计、实现细节和取舍方案。

这种不确定性有助于探索，但也意味着重要的工作需要你来把关。请测试 Agent 构建的内容，遇到不清楚的地方就让它解释，需要安全的回退点时使用检查点。

<div id="ai-2">
  ## 什么能让 AI 输出更出色
</div>

提供以下内容时，Agent 的表现最佳：

* 明确的目标
* 受众或用户的需求
* 约束条件与非目标
* 示例、截图、文件、数据、链接
* 当前的问题或具体的错误信息
* 界定「怎样才算完成」的验收标准

请比较下面这两条提示词：

* *「请写一个网站的代码。」*
* *「请写一个网站的代码，用来收集个人邮件列表的邮箱地址，并把提交的内容保存到 Google Sheets。」*

第二条提示词给出了目标、数据和去向，因此 Agent 有足够的信息可以直接动手，而不必靠猜。

这些信息就是所谓的上下文。想了解上下文为何如此重要，请参阅[上下文管理](/zh/ja/learn/foundations/context-management)。

<div id="aiai">
  ## 从 AI 到 AI 智能体
</div>

聊天模型只能回复消息。AI 智能体则在模型之上增加了工具，用来完成多步骤的任务——它可以围绕目标进行推理、选择工具、查找信息、做出更改、检查结果，并持续推进，直到任务完成或需要你提供输入为止。

<div id="section-4">
  ### 模型与工具
</div>

智能体包含两个关键部分：

| 部分       | 作用                                         |
| -------- | ------------------------------------------ |
| **语言模型** | 理解指令、生成文本、权衡各种方案，并决定下一步该做什么。               |
| **工具**   | 让智能体能够执行操作：读取文件、编辑代码、运行命令、搜索文档、测试应用、发布更改等。 |

模型负责判断哪些操作有用，工具则让智能体把这些判断付诸实施。

<div id="section-5">
  ### Agent 能做什么
</div>

Agent 可以帮你完成需要多个步骤的工作，例如：

* 规划功能
* 创建文件和代码
* 读取现有项目结构
* 运行命令或测试
* 调试错误
* 更新设计
* 连接服务
* 总结变更内容

Agent 不只是回答问题，而是推动任务真正落地。

<div id="replit-agent">
  ### Replit Agent
</div>

Replit Agent 是助你在 Replit 上进行构建的 AI 智能体。它可以帮你创建应用及其他制品、探索项目、编辑文件、运行命令、测试功能、讲解代码、创建任务，并引导你完成发布流程。

例如，你可以这样向 Agent 提出请求：

```text theme={null}
请为社区聚会构建一个简单的活动报名应用。
让访客可以查看活动详情，提交姓名和邮箱地址，并收到确认消息。
第一个版本请保持简单，以便今天就能发布。
```

Agent 能把你的需求变成项目，生成初始版本，并帮助你持续改进。

<div id="section-6">
  ### 由你主导工作
</div>

Agent 能够快速推进，但关键决策仍由你来做：

* 制品要实现什么
* 面向哪些人
* 范围包含哪些内容
* 哪些内容不能改动
* 结果是否可用
* 何时可以发布

正因如此，上下文管理和审查才格外重要。当你给出明确方向并对结果进行测试时，Agent 的能力才能发挥到极致。

<div id="section-7">
  ## 常见误解
</div>

* **“AI 应该明白我想说什么”** —— AI 只能依据你提供的信息工作。如果某件事很重要，就请明确说出来。
* **“第一个答案就该是最终答案”** —— 用 AI 构建是一个迭代的过程，要不断审查、测试和改进。
* **“AI 能像人一样理解意图”** —— AI 可以推断模式，但它不会自动知道你的偏好、受众、约束条件，以及怎样才算完成。
* **“智能体不过是聊天机器人”** —— 聊天机器人主要负责回应，而智能体可以调用工具采取行动。
* **“Agent 会自动知道整个产品的目标”** —— Agent 依据你的指令和上下文工作。如果某件事很重要，就把它写进去。
* **“有了 Agent 就不需要审查了”** —— Agent 可以负责构建，但制品是否符合你的意图，要由你来判断。
