在 Replit 中使用 AI 创建应用，并直接将其发布到 Microsoft Fabric，同时内置企业级治理与安全机制。Microsoft Fabric 集成可将受治理的企业数据转化为仪表板、工作流和 AI 应用等内部工具。团队可更快地从 prompt 推进到生产环境，同时身份验证和访问策略仍保留在他们已信赖的 Fabric 环境中。

<div id="o-que-um-aplicativo-de-dados-fabric">
  ## 什么是 Fabric 数据应用
</div>

Fabric 数据应用是一种静态 React 应用，通过对 [Power BI 语义模型](https://learn.microsoft.com/pt-br/power-bi/connect-data/service-datasets-understand)运行[数据分析表达式 (DAX)](https://learn.microsoft.com/pt-br/dax/) 查询来呈现 Power BI 图表。以下特性决定了其构建方式：

* **Power BI 语义模型是数据源。** 图表的数据来自您连接的语义模型 (数据集) 上的 DAX 查询。
* **设计为只读。** 应用使用 DAX `EVALUATE` 读取数据，不会将数据写回 Power BI。如果需要可写状态，请结合仪表板使用独立的应用数据库。
* **由 Fabric 门户呈现。** 数据层在 Microsoft Fabric 门户中运行，该门户会对语义模型执行查询，并将结果返回给应用。您的数据始终保留在 Fabric 环境中。
* **托管在 Microsoft 基础架构上。** 您可以将完成的数据应用发布到 Microsoft 托管服务，使其与 Fabric 环境中的其他资源一同运行。

<Note>
  Microsoft Fabric 数据应用需要访问包含 Power BI 语义模型的 Microsoft Fabric 租户；在预览期间，还需要加入获批准的测试人员计划。
</Note>

在幕后，[Rayfin](https://github.com/microsoft/rayfin) (一个用于创建应用后端的开源 SDK 和 CLI) 可让 Agent 基于您的 Fabric 数据定义和发布可用于生产环境的应用。

您可以始终在同一工作流程中完成操作：描述应用，让 Agent 搭建应用结构，连接受治理的 Fabric 数据，然后发布应用，使其在组织的 Fabric 租户中运行。

本指南涵盖构建者工作流程、应用如何连接到 Fabric 数据，以及团队协作和自动化选项。有关基于其他数据仓库的通用数据仪表板，请参阅[数据可视化](/zh/pt/features/artifact-types/data-apps)。

<div id="casos-de-uso">
  ## 使用场景
</div>

对于已采用 Microsoft 数据生态系统的组织来说，这是更快构建内部软件的途径。团队无需花费数周时间集成身份验证、API、部署工具和治理策略，只需描述需求，让 Agent 完成构建。

常见使用场景包括：

* 面向特定部门的生产力工具
* 运营仪表板
* 数据探索工具
* 工作流自动化应用
* 报表界面

对于企业 IT 而言，治理、身份验证和安全性仍处于组织已管理的 Fabric 环境中，因此快速创建应用无需以牺牲集中控制为代价。

<div id="criar-um-aplicativo-de-dados-fabric">
  ## 创建 Fabric 数据应用
</div>

构建流程以对话方式进行。您始终在 Replit 中操作；需要进行身份验证或访问数据时，会跳转到 Microsoft 完成。

<Steps>
  <Step title="从 Fabric 模板开始">
    在 Replit 主页，打开 **Templates** 下拉菜单，然后在 **Org templates** 中选择 **Microsoft Fabric App**。这样便会进入数据应用工作流，并预先加载 Fabric 工具。

    <Frame caption="在 Replit 主页选择 Microsoft Fabric App 组织模板（私人预览界面）。">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Replit 主页，Templates 下拉菜单已打开，显示在 Org templates 中高亮的 Microsoft Fabric App" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="描述您想要的仪表板">
    输入 prompt，描述要创建的仪表板或报表工具。例如：“根据我们的 Fabric 销售模型创建一个月度销售增长仪表板。”您无需编写 DAX——Agent 会生成查询。
  </Step>

  <Step title="使用 Microsoft 登录">
    出现提示时，使用包含 Fabric 数据的租户通过 Microsoft OAuth 登录。这会授权 Agent 读取您有权访问的语义模型。您用于登录的身份必须有权访问要使用的 Fabric 工作区。
  </Step>

  <Step title="添加数据源">
    当 Agent 提示时，分享您要使用的 Power BI / Fabric 语义模型。您可以提供 Fabric 门户中数据集的完整 URL (例如，`https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) ，或者提供 工作区 ID 和数据集/项目 ID。Agent 会利用这些信息识别要查询的 工作区 和语义模型。

    该模型必须已**发布到 Power BI 服务**——无法使用本地 `.pbix` 文件。

    <Frame caption="Agent 请求提供 Power BI / Fabric 语义模型链接（私人预览界面）。">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Agent 面板请求构建者分享 Power BI 或 Fabric 语义模型，例如完整的 Fabric 门户 URL，或 工作区 ID 加数据集或项目 ID，并说明模型必须发布到 Power BI 服务，因此不能使用本地 .pbix 文件" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="让 Agent 创建并迭代">
    Agent 会探索语义模型的架构、编写 DAX 查询，并使用合适的图表构建仪表板。查看结果后，您可以使用自然语言提出修改要求——添加筛选器、更改图表类型或添加其他指标。
  </Step>

  <Step title="部署（可选）">
    仪表板准备就绪后，您可以将其部署到 Microsoft 托管环境，使其在您的 Fabric 环境中运行。部署将在其他内容中单独介绍；本指南重点介绍数据连接和应用创建。
  </Step>
</Steps>

<div id="conectando-se-aos-dados-fabric">
  ## 连接到 Fabric 数据
</div>

要读取数据，应用需要已获授权连接到 Microsoft Fabric。Replit 会通过以下两种方式之一建立连接。

<div id="login-no-fabric-no-nvel-do-aplicativo-visualizadores">
  ### 应用级 Fabric 登录 (查看者)
</div>

已部署的数据应用的查看者无需配置连接器。他们通过集成在应用中的 Microsoft Fabric 单点登录进行身份验证，应用则通过 Fabric 门户以查看者的身份读取数据。这确保访问权限仍由现有的 Fabric 权限控制。

<div id="o-conector-microsoft-fabric-o-caminho-fcil-para-construtores">
  ### Microsoft Fabric 连接器 (面向构建者的便捷方式)
</div>

对于构建者而言，**Microsoft Fabric 连接器**是在开发期间授权访问数据的便捷方式。这是可选方案，并非必需。

* 首位进行配置的构建者只需完成一次与 Microsoft 的 **OAuth 授权**。
* **同一项目中的**其他协作者会继承此连接。
* **不同的 工作区** 必须启用该连接器，并完成各自的 OAuth 授权。
* 通过 OAuth 验证的身份必须有权访问目标 Fabric 工作区。

该连接器使用 Microsoft Entra OAuth，且仅限在您的租户范围内使用。您可以在项目的[集成](/zh/pt/features/integrations/overview)页面中，像管理其他 Replit 连接器一样管理它。有关连接器的更多概念，请参阅[管理您的连接器](/zh/pt/replitai/managing-connectors)。

<Note>
  在私密预览期间，Microsoft Fabric 连接器不提供由 Replit 管理的共享凭证。构建者需在自己的 Microsoft Entra 租户中完成授权。
</Note>

<div id="equipes-e-automao">
  ## 团队与自动化
</div>

对于团队共享使用或 CI 等非交互式环境，交互式 OAuth 并不总是适用。在这种情况下，请通过项目的 [Secrets](/zh/pt/core-concepts/project-editor/app-setup/secrets) 提供**服务主体**令牌，而非进行交互式登录。应用会使用服务主体身份读取 Fabric 数据。

这最接近于机器对机器配置：在 Microsoft Entra 中预配并获授 Fabric 工作区访问权限的非人类身份，可在无人干预的情况下对应用进行身份验证。请确认服务主体可以访问应用查询的工作区和语义模型。

<div id="soluo-de-problemas">
  ## 故障排除
</div>

<AccordionGroup>
  <Accordion title="应用预览中未加载数据">
    Fabric 数据层通过 Microsoft Fabric 门户运行。如果图表显示为空，或应用预览未加载数据，请确认您已完成 Microsoft 登录，且所连接的身份有权访问关联的 工作区 和语义模型。
  </Accordion>

  <Accordion title="Agent 找不到您的语义模型">
    请确保您已将 Power BI 数据集链接粘贴到 Fabric 门户中，并且您的身份 (或服务主体) 至少拥有该 工作区 的读取权限。如果 Agent 提示无法解析 工作区 或模型，请重新共享数据集链接。
  </Accordion>

  <Accordion title="连接器卡住或反复要求连接">
    请在项目的[集成](/zh/pt/features/integrations/overview)页面重新授权 Microsoft Fabric 连接器。确认通过 OAuth 身份验证的身份有权访问 Fabric 工作区。对于团队或 CI 使用场景，建议优先使用由 Secrets 提供的服务主体 token。
  </Accordion>
</AccordionGroup>
