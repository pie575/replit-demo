<div id="what-is-general-agent">
  ## General Agent란?
</div>

General Agent는 Replit Agent를 활용하는 가장 유연한 방법입니다. artifact 유형을 미리 고르거나 특정한 결과물을 만들겠다고 정해둘 필요가 없습니다. 그냥 대화를 시작하면 됩니다. CSV를 만들고, PDF를 생성하고, 주제를 조사하고, 준비가 되면 완성형 앱까지 만들 수 있습니다.

핵심 개념:

* **사전 선택 불필요**: artifact 유형을 미리 고르지 않고 바로 작업을 시작합니다
* **모든 형태의 결과물**: 파일(CSV, PDF, 문서) 생성, 리서치 수행, 앱 구축이 모두 가능합니다
* **Connectors**: BigQuery, Linear, Slack, Notion, Amplitude, Segment, Hex 등 외부 서비스에서 데이터를 읽고 쓸 수 있습니다
* **점진적 확장**: 가벼운 Chat으로 시작해 자연스럽게 완성형 앱 구축으로 넘어갈 수 있습니다

<div id="how-to-access-general-agent">
  ## General Agent 사용 방법
</div>

General Agent는 다음과 같은 여러 방법으로 사용할 수 있습니다:

1. Replit 홈 페이지에서 **프롬프트를 작성하기 전에 &quot;General&quot; 선택**
2. **기존 프로젝트를 열고** Agent와 바로 대화 시작
3. **GitHub에서 [Import](/ko/build/import-from-providers)** — GitHub에서 가져온 프로젝트에는 General Agent가 자동으로 적용됩니다

<div id="how-to-use-general-agent">
  ## General Agent 사용 방법
</div>

<div id="just-start-chatting">
  ### 그냥 대화를 시작하세요
</div>

프로젝트를 열고 대화를 시작하세요. 무엇을 만들지 미리 정해두지 않아도 됩니다. Agent는 현재 프로젝트 컨텍스트 안에서 작동하므로 어떤 요청이든 처리할 수 있습니다.

**프롬프트 예시:**

* &quot;이 문서의 핵심 내용을 요약해 줘&quot;
* &quot;매출 기준 상위 100개 기업 목록을 CSV로 만들어 줘&quot;
* &quot;내 Linear 티켓 중 상위 다섯 개는 뭐야?&quot;
* &quot;TypeScript로 Vue.js 프로젝트를 설정해 줘&quot;

Agent는 세션 중에 생성된 파일을 다루고, 단일 파일 결과물을 만들며, 추론 과정의 일부로 코드를 실행할 수 있습니다. 무언가를 만들기로 결정하기 전에도 이 모든 것이 가능합니다.

<div id="connecting-external-services">
  ### 외부 서비스 연결
</div>

도구를 연결하면 Agent가 데이터를 직접 읽고 쓸 수 있습니다.

1. 프로젝트 설정에서 **Connectors**로 이동합니다
2. 사용할 서비스를 연결합니다(BigQuery, Linear, Slack, Notion, Amplitude, Segment, Hex 등)
3. Agent에게 해당 서비스를 통해 데이터를 읽거나 쓰도록 요청합니다

**connector를 활용한 프롬프트 예시:**

* &quot;Linear에 열려 있는 티켓이 뭐가 있어?&quot;
* &quot;오늘 #engineering 채널의 Slack 메시지를 요약해줘&quot;
* &quot;BigQuery에서 지난달 매출 데이터를 가져와줘&quot;
* &quot;내 캘린더의 예정된 일정을 보여줘&quot;
* &quot;온보딩 버그에 대한 새 티켓을 Linear에 만들어줘&quot;
* &quot;Slack의 #engineering 채널로 요약을 보내줘&quot;

<div id="from-chat-to-full-app">
  ### 채팅에서 완성된 앱까지
</div>

빌드할 준비가 되면 말만 하세요. Agent는 가벼운 Chat에서 앱을 빌드하는 단계로 매끄럽게 넘어갑니다. 처음부터 다시 시작하거나 맥락을 바꿀 필요가 없습니다.

* &quot;이걸 web app으로 만들어줘&quot;
* &quot;이 데이터를 기반으로 앱을 빌드해줘&quot;
* &quot;이 지표들을 보여주는 dashboard를 만들어줘&quot;
* &quot;Rust CLI 도구를 설정해줘&quot;

주제를 조사하고, 보고서를 생성하고, 데이터를 살펴보는 것처럼 가볍게 시작한 뒤, 적절한 시점에 본격적인 애플리케이션 빌드로 넘어갈 수 있습니다.

<div id="what-you-can-build">
  ## 무엇을 만들 수 있나요
</div>

* **지식 작업**: 앱을 만들지 않고도 조사, 요약, 분석 수행
* **단일 파일 결과물**: CSV, PDF, 문서, 데이터 내보내기, 서식이 적용된 보고서
* **데이터 애플리케이션**: 연결된 서비스를 조회하고 결과를 대시보드로 시각화
* **모든 프레임워크와 언어**: Angular, Vue, Svelte, Rust, Go, C#, Python tkinter, Godot 게임, CLI 도구 등
* **Full-stack 앱**: 준비가 되면 Chat의 context를 바탕으로 완전한 애플리케이션 구축

<div id="what-to-expect">
  ## 무엇을 기대할 수 있나요
</div>

General Agent는 더 강력한 성능과 유연성을 제공하지만, 그만큼 결과에 편차가 생길 수 있습니다:

* **한 번에 설정**: 때로는 Agent가 모든 것을 한 번에 구성합니다
* **반복적인 협업**: 복잡한 설정은 여러 차례에 걸친 개선 작업이 필요할 수 있습니다
* **기술적 제약**: 일부 기술은 Nix 환경에서 완전히 지원되지 않을 수 있습니다

<Note>
  사전 구성된 환경을 사용하는 표준 Agent와 달리, General Agent는 요청 내용에 맞춰 자체 환경과 run command를 직접 설정합니다. 배포할 준비가 되면 Publishing을 구성해 달라고 요청해야 할 수도 있습니다.
</Note>

<div id="frequently-asked-questions">
  ## 자주 묻는 질문
</div>

<Accordion title="Agent가 제 다른 프로젝트를 볼 수 있나요?">
  아니요. 각 chat은 하나의 프로젝트 안에서만 이루어집니다. 프로젝트 A와 프로젝트 B가 서로 정보를 주고받게 할 수는 없습니다.
</Accordion>

<Accordion title="외부 도구에 아직 접근하지 못하는 이유는 무엇인가요?">
  먼저 Connectors를 통해 서비스를 연결해야 합니다. 연결하고 나면 Agent가 해당 서비스를 읽고 쓸 수 있으며, 연결 전에는 기본적으로 접근 권한이 없습니다.
</Accordion>

<Accordion title="어떤 connector를 사용할 수 있나요?">
  현재 BigQuery, Linear, Slack, Notion, Amplitude, Segment, Hex 등을 지원합니다. 새로운 connector도 꾸준히 추가되고 있습니다.
</Accordion>

<Accordion title="General Agent를 사용하려면 connector가 필요한가요?">
  아니요. Connectors는 선택 사항입니다. 외부 연결 없이도 General Agent로 지식 작업, 파일 생성, 앱 빌드를 할 수 있습니다.
</Accordion>
