Il s’agit d’une suite d’étapes réutilisable et personnalisable, que vous pouvez exécuter dans votre application Replit. Elle peut être aussi simple que l’exécution de `python main.py` ou aussi complexe qu’une procédure en plusieurs étapes.

Exemples de cas d’utilisation :

* Exécuter plusieurs services en parallèle (par exemple, frontend + backend)
* Exécuter des fichiers ou des commandes de façon séquentielle (par exemple, exécuter le linter → exécuter les tests, compiler → exécuter le code)

Pour [créer des Workflows](#creating-workflows), accédez au volet Workflows depuis le menu latéral des outils ou recherchez-le à l’aide de `Command + K`.

<div id="available-task-types">
  ## Types de tâches disponibles
</div>

Il existe actuellement 3 types de tâches : `Execute Shell Command`, `Install Packages` et `Exécuter un workflow`.

<div id="execute-shell-command">
  ### Execute Shell Command
</div>

`Execute Shell Command` enregistre une commande shell et l&#39;exécute dans le même environnement que le panneau Shell. Ce type de tâche couvre un large éventail de cas d&#39;usage, à commencer par l&#39;exécution de fichiers individuels :

```text theme={null}
python main.py
```

à l&#39;exécution de commandes de requêtes stockées complexes sur une base de données :

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Install Packages
</div>

`Install Packages` s&#39;appuie sur le système de gestion des dépendances intégré de Replit : il détecte automatiquement les dépendances de votre projet et installe les packages nécessaires. Consultez [Gestion des dépendances](/fr/features/project-setup/dependency-management#the-universal-package-manager) pour en savoir plus sur la façon dont UPM détermine, en coulisses, les packages à installer pour votre projet.

<div id="run-workflow">
  ### Exécuter un workflow
</div>

`Exécuter un workflow` permet d’exécuter un autre workflow depuis le workflow en cours. Vous pouvez ainsi réutiliser et combiner des workflows pour créer des workflows plus complexes.

Exemple de cas d’utilisation :

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

En utilisant ce type de tâche pour créer des dépendances entre les workflows, vous pouvez modifier un workflow, et les autres workflows qui y font référence utiliseront automatiquement les dernières modifications. Notez qu’une limite de profondeur s’applique aux appels de workflows très imbriqués.

<div id="workflow-execution-mode">
  ## Mode d&#39;exécution des Workflows
</div>

Les Workflows proposent deux modes d&#39;exécution : séquentiel et parallèle.

<div id="sequential">
  ### Séquentiel
</div>

L&#39;exécution séquentielle lance chaque tâche dans l&#39;ordre défini, attend la fin de chaque tâche avant de passer à l&#39;étape suivante et interrompt l&#39;exécution de la séquence si une tâche du workflow échoue.

Ce mode est par exemple utile pour définir des commandes logiquement liées, comme des commandes Git permettant de récupérer les dernières modifications de votre branche principale, puis de rebaser votre branche actuelle sur la branche principale :

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="image" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="parallel">
  ### Parallèle
</div>

L&#39;exécution parallèle lance chaque tâche en parallèle, de sorte que chaque tâche démarre et s&#39;exécute indépendamment des autres tâches du workflow. L&#39;échec d&#39;une tâche n&#39;interrompt pas l&#39;exécution des autres.

Ce mode est utile, par exemple, pour exécuter un project fullstack qui doit démarrer à la fois le frontend et le serveur backend :

<div id="creating-workflows">
  ## Créer des Workflows
</div>

Vous pouvez créer des Workflows depuis le volet Workflows en cliquant sur le bouton `+ New Workflow`. Commencez par donner un nom explicite à votre workflow, choisissez un mode d&#39;exécution adapté, puis ajoutez des tâches. Vous pouvez réorganiser les tâches par glisser-déposer, dans l&#39;ordre souhaité.

<div id="assign-workflow-to-run-button">
  ## Assigner un workflow au bouton Run
</div>

Un workflow peut également être assigné au bouton Run afin de remplacer son comportement par défaut (voir [Configurer une Replit App](/fr/features/project-setup/configuration)). Pour conserver la Run command définie par défaut dans `.replit`, sélectionnez l&#39;option « Run Replit App » dans le menu déroulant.

Le workflow sélectionné dans le menu déroulant situé à côté du bouton Run s&#39;exécute lorsque vous cliquez sur ce bouton. Pour changer le workflow lancé par le bouton Run, cliquez sur celui de votre choix dans le menu déroulant.
