URL для разработки позволяют просматривать и тестировать App в процессе создания. Эти URL имеют формат `UUID.servername.replit.dev` и предоставляют интерактивный предварительный просмотр разрабатываемого App.

<Frame>
  <img src="/assets/mirror/preview-dev-url-b36770b33769.png" alt="URL для разработки в адресной строке" width="1222" height="824" data-path="images/workspace/preview-dev-url.png" />
</Frame>

Чтобы открыть URL для разработки, нажмите на текст `{...}.replit.dev` в адресной строке.

<div id="url">
  ## Что такое URL для разработки
</div>

URL для разработки работает только тогда, когда вы активно работаете в App Replit. При каждом повторном открытии App URL может меняться. Он позволяет просматривать результаты работы в браузере во время разработки и тестирования.

По умолчанию URL для разработки доступен в интернете. Любой, у кого есть этот URL, может просмотреть создаваемое вами App. Это позволяет легко делиться текущей версией с соавторами, тестировщиками и заинтересованными лицами.

<Warning>
  URL для разработки временный и предназначен только для тестирования. Чтобы поделиться App с другими, рекомендуем [опубликовать App](/ru/ja/learn/projects-and-artifacts/replit-deployments).
</Warning>

<div id="section">
  ### Обучающий баннер
</div>

Когда вы открываете предпросмотр разработки в новой вкладке, в верхней части страницы появляется обучающий баннер. Он помогает понять назначение URL `.replit.dev` при создании и тестировании App. Баннер объясняет, что представляет собой URL для разработки и как его следует использовать в процессе разработки.

<div id="url-2">
  ## Сделать URL для разработки приватным
</div>

Чтобы обезопасить незавершённую работу, можно ограничить доступ к URL для разработки.

Чтобы сделать URL для разработки приватным:

1. Откройте **Инструменты разработчика** в редакторе проекта.
2. Выберите вкладку **Сеть**.
3. Включите переключатель **Приватный URL для разработки**.

После включения для доступа к URL для разработки потребуется аутентификация. Просматривать незавершённую работу сможете только вы и одобренные участники команды.

<Note>
  Клиенты Enterprise могут сделать приватные URL для разработки обязательными для всех проектов. Это повышает уровень безопасности и позволяет защитить процесс разработки в среде организации.
</Note>

<div id="section-2">
  ## Лучшие практики
</div>

* Используйте **приватный URL** для конфиденциальных или проприетарных App, находящихся в разработке
* Используйте **публичный URL**, если вы активно разрабатываете App и хотите поделиться им с внешними заинтересованными сторонами или протестировать его в другом браузере
