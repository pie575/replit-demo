从 Replit 发布后，你的项目就会开始接收真实流量。借助 Replit 的安全工具，你可以发现漏洞、通过 Agent 修复已确认的问题，并保留可用于审计的证据。

<div id="section">
  ## 安全为何重要
</div>

* 已发布的项目可从公共互联网访问，包括公开的路由和 API。
* 现代项目依赖大量软件包，发布之后仍可能出现新的 CVE。
* AI 生成的代码同样需要安全审查，尤其是涉及身份验证、数据库查询、密钥和数据处理的部分。
* 合规方案通常要求提供依赖项清单、漏洞跟踪记录以及修复证据。

<div id="section-2">
  ## 从何处开始
</div>

* 要安装软件包？[Package Firewall](/zh/ja/features/security/package-firewall) 会在安装时拦截恶意依赖项 (默认启用) 。
* 如果你在单个 项目 中工作，请使用 [项目 安全中心](/zh/ja/features/security/project-security-center)。
* 如果要审计整个 工作区，请使用 [工作区 安全中心](/zh/ja/features/security/workspace-security-center)。
* 如果想选择开发资源的运行位置，请参阅 [工作区 地理区域](/zh/features/collaboration/workspace-geography)；如果想选择已发布 项目 的运行位置，请参阅 [项目 地理区域](/zh/ja/features/publishing/project-geography)。
* 如果想查阅术语定义，请参阅[安全概念](/zh/ja/features/security/concepts)。

Replit 的安全工具分别守护应用生命周期中的不同环节，并协同发挥作用：

* **安装时**：[Package Firewall](/zh/ja/features/security/package-firewall) 会在下载前拦截恶意或已被入侵的软件包。
* **安装后**：[自动依赖项扫描](/zh/ja/features/security/project-security-center#automatic-dependency-scans)会检测新披露的 CVE，Auto-Protect 可准备好由 Agent 打补丁。
* **发布前**：[Security Agent](/zh/ja/features/security/agent-security-scans) 会针对代码、依赖项和隐私方面的漏洞审计代码库。

大多数安全工作都遵循同一套流程：扫描、查看结果、由 Agent 修复、重新发布，并在需要时导出证据。

<div id="section-3">
  ## 安全功能在产品中的位置
</div>

<div id="section-4">
  ### 在 项目 内
</div>

在 项目 的 **Tools** 窗格中选择 **Security Center**，即可查看 项目 级别的扫描结果、运行 Agent 安全扫描，并在发布前排查依赖项漏洞。

使用 [Agent 安全扫描](/zh/ja/features/security/agent-security-scans)审查源代码。如果需要从外部检查运行中的应用，请使用 [Level 3 黑盒渗透测试](/zh/ja/features/security/black-box-pen-tests)。

<div id="section-5">
  ### 工作区 内
</div>

在主页侧边栏中选择 **Security**，即可查看所有项目的漏洞情况、按暴露程度对发现项排定优先级，并追踪 工作区 级别的扫描历史。

<div id="section-6">
  ### 发布与设置
</div>

* 在 **Publish** &gt; **Advanced** 中，使用 **Block publishing of critical vulnerabilities** 阻止存在严重发现项的版本发布。
* 在 **Settings** &gt; **Account** &gt; **Advanced** 中，为 Agent 准备的依赖项修复设置 Auto-Protect 严重性阈值。
