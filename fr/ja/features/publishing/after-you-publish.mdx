Lorsque vous sélectionnez **Publish**, un court pipeline se met en route pour mettre votre application en ligne. Cette page explique ce qui se passe pendant la publication, comment mettre à jour votre application et où la gérer une fois qu&#39;elle est en ligne.

<div id="section">
  ## Les étapes de la publication
</div>

La publication se déroule en cinq étapes et prend généralement une à deux minutes. Vous pouvez suivre la barre de progression dans l&#39;outil Publishing, sélectionner **View logs** pour afficher les détails, ou **Cancel** pour interrompre une publication en cours.

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Aperçu de Publishing affichant une barre de progression en cinq étapes, avec Provision terminé, Security checks et Build en cours, et Bundle et Promote en attente" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision** : Replit prépare les ressources cloud sur lesquelles votre app s&#39;exécutera, comme les serveurs et la base de données de production.
2. **Security checks** : avant la mise en ligne, Replit recherche d&#39;éventuels problèmes de sécurité, tels que des dépendances non sécurisées ou des secrets exposés.
3. **Build** : Replit convertit votre projet en une version de production, c&#39;est-à-dire une forme optimisée qui fonctionne sur le Web.
4. **Bundle** : l&#39;app compilée est empaquetée en une seule unité prête à être exécutée.
5. **Promote** : Replit prépare la nouvelle version en parallèle de la version actuelle, puis bascule l&#39;URL vers celle-ci.

<Note>
  La publication porte sur l&#39;ensemble du projet. Tous les artefacts qu&#39;il contient (app, diapositives, documents, etc.) sont publiés ensemble.
</Note>

<Accordion title="Ce qui se passe en coulisses">
  Pour les builders qui souhaitent connaître les détails techniques : Provision alloue l&#39;infrastructure de déploiement correspondant au type de déploiement et à la région sélectionnés. Security checks analyse les dépendances et le code et peut, selon vos paramètres de sécurité, bloquer la publication en cas de vulnérabilité critique. Build exécute la commande de build et compile les assets pour la production. Bundle empaquette la sortie du build dans une image déployable. Promote effectue la bascule : la nouvelle version commence à répondre sur l&#39;URL et remplace le déploiement précédent.
</Accordion>

Une fois toutes les étapes terminées, votre app est en ligne. Sélectionnez l&#39;URL dans l&#39;outil Publishing pour l&#39;ouvrir.

<div id="section-2">
  ## Mettre à jour votre application
</div>

Après avoir apporté vos modifications, sélectionnez de nouveau **Publish**. Votre application est mise à jour sur la même URL et les visiteurs accèdent à la dernière version dès leur prochain chargement. Inutile de partager un nouveau lien.

<div id="section-3">
  ## Gérer votre application en ligne
</div>

L&#39;outil Publishing est également l&#39;endroit où vous gérez votre application une fois qu&#39;elle est en ligne :

* **Surveiller l&#39;état** : vérifiez si votre application est en ligne, consultez les logs et suivez l&#39;utilisation des ressources. En savoir plus sur le [Monitoring](/fr/ja/features/publishing/monitoring-a-deployment).
* **Consulter les visiteurs** : les graphiques de requêtes et de trafic se trouvent dans [Monitoring](/fr/ja/features/publishing/monitoring-a-deployment), tandis que les analyses relatives aux visiteurs et aux utilisateurs figurent dans le volet **Growth**.
* **Modifier les droits d&#39;accès** : arrêtez la publication, choisissez une autre option d&#39;accès, puis publiez à nouveau. En savoir plus sur l&#39;[accès aux applications](/fr/ja/features/publishing/private-deployments).
* **Connecter un domaine** : définissez une adresse web personnalisée pour votre application. En savoir plus sur les [domaines personnalisés](/fr/ja/features/publishing/custom-domains).
