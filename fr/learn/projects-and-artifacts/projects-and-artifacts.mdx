Un **projet** est le conteneur de tout ce que vous créez sur Replit. Les **artifacts** sont les productions publiables qu&#39;il contient : applications web, applications mobiles, présentations, animations, visualisations de données, jeux 3D et designs.

Lorsque vous créez plusieurs éléments, deux options s&#39;offrent à vous : ajouter plusieurs artifacts à un même projet, ou créer des projets distincts. Le bon choix dépend d&#39;une question : vos applications partagent-elles des données, une logique et un cycle de vie de déploiement ? Cette page détaille ces deux notions et vous indique quand regrouper vos artifacts dans un seul projet plutôt que d&#39;en créer plusieurs.

<div id="whats-a-project">
  ## Qu&#39;est-ce qu&#39;un projet ?
</div>

Un projet est le conteneur qui regroupe votre code, vos données et tous les artifacts que vous créez. Lorsque vous indiquez à Agent ce que vous souhaitez, il configure un projet et y crée les artifacts.

Considérez un projet comme un espace de travail sur votre bureau. Tout se trouve au même endroit et peut partager les mêmes informations, mais chaque élément a une fonction différente.

Par exemple, si vous demandez à Agent de créer une application de suivi de l&#39;activité physique, il crée un projet contenant un artifact d&#39;application mobile, ainsi que le backend, la base de données et l&#39;espace de stockage nécessaires à son fonctionnement.

Concepts clés :

* **Project** : Le conteneur qui regroupe tout — votre code, vos données et tous vos artifacts.
* **Artifact** : Un résultat publiable au sein d&#39;un projet (une web app, une présentation, une vidéo, etc.).
* **Ressources** : Chaque artifact a automatiquement accès à un backend, une base de données et un espace de stockage de fichiers — aucune configuration n&#39;est nécessaire.

Pour découvrir tout ce que vous pouvez faire avec un projet — gérer, filtrer, épingler, trier — consultez [Projects](/fr/features/projects-and-artifacts/projects).

<div id="whats-an-artifact">
  ## Qu&#39;est-ce qu&#39;un artifact ?
</div>

Les artifacts sont les éléments que vous pouvez publier sur Replit. Chacun constitue un résultat complet et autonome, doté de sa propre URL partageable dès sa publication.

Tout le reste de votre project — fichiers, images, CSV, code — sert de support à vos artifacts, mais ne peut pas être publié séparément.

<div id="what-artifacts-share-in-a-project">
  ## Ce que les artifacts partagent au sein d’un project
</div>

Lorsque des [artifacts](/fr/features/projects-and-artifacts/artifacts) se trouvent dans le même [project](/fr/features/projects-and-artifacts/projects), ils partagent automatiquement :

* **Base de données** : un artifact écrit des données, les autres y accèdent instantanément.
* **Backend et API** : une logique serveur partagée, sans duplication de code.
* **Stockage de fichiers** : images, documents et fichiers importés accessibles depuis tous les artifacts.
* **Déploiement** : Publishing met tout en ligne simultanément et de façon synchronisée.

Vous n’avez donc pas besoin de configurer des connexions ni de dupliquer du code entre les artifacts. En revanche, vous ne pouvez pas publier un artifact sans publier les autres.

<div id="quick-guide">
  ## Guide rapide
</div>

Voici les principaux cas de figure à examiner pour décider s&#39;il faut ajouter des artifacts à un project existant ou en créer un distinct.

| **Utiliser plusieurs artifacts dans un même project**                                                      | **Utiliser des projects distincts**                                                        |
| ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Les apps partagent les mêmes données et le même backend                                                    | Les apps ne partagent ni logique ni données sous-jacentes                                  |
| Vous souhaitez que tout soit publié en même temps                                                          | Vous avez besoin de cycles de publication indépendants                                     |
| Elles sont complémentaires (par exemple une app client et un tableau de bord d&#39;administration)         | Ce sont des produits sans lien entre eux ou destinés à des clients différents              |
| Vous souhaitez que les modifications apportées à un artifact se répercutent automatiquement sur les autres | Le project est éphémère, comme une page de destination de campagne ou un site événementiel |

<div id="examples">
  ## Exemples
</div>

<div id="same-project-web-app-mobile-app-for-one-product">
  ### Un même project : web app + application mobile pour un seul produit
</div>

Un restaurant crée une web app permettant aux clients de consulter la carte et une application mobile permettant au personnel de gérer les commandes. Les deux se connectent à la même base de données, qui regroupe les plats de la carte, les commandes et les informations clients.

**Pourquoi un seul project :** les apps partagent les mêmes données et le même backend. Lorsqu&#39;un client passe une commande via la web app, le personnel la voit immédiatement dans l&#39;application mobile.

<div id="same-project-app-admin-dashboard-investor-pitch-deck">
  ### Même project : app + tableau de bord d&#39;administration + présentation pour investisseurs
</div>

Une startup développe son produit principal, un panneau d&#39;administration interne pour gérer le contenu et une présentation destinée à une levée de fonds — le tout dans un seul project.

**Pourquoi un seul project :** le tableau de bord d&#39;administration gère les mêmes données que celles affichées par l&#39;app, et la présentation peut s&#39;appuyer sur les métriques en temps réel du backend partagé.

<div id="separate-projects-two-unrelated-client-apps">
  ### Projects distincts : deux applications clientes sans lien entre elles
</div>

Un freelance crée une boutique en ligne pour un client et un système de réservation pour un autre.

**Pourquoi des projects distincts :** les applications ne partagent ni données ni logique. Chaque client a besoin d&#39;une publication indépendante et vous ne voulez pas que les modifications apportées à l&#39;une se répercutent sur l&#39;autre.

<div id="separate-projects-campaign-landing-page-alongside-a-main-product">
  ### Projets distincts : une page de destination de campagne en parallèle d’un produit principal
</div>

Vous avez une application en production qui fonctionne toute l’année et une page de destination temporaire pour une campagne marketing.

**Pourquoi utiliser des projets distincts :** la page de campagne a son propre cycle de vie — vous la mettez en ligne, l’utilisez pendant quelques semaines, puis la retirez. La séparer évite d’encombrer votre produit principal et vous permet de la publier ou de la supprimer indépendamment.

<div id="frequently-asked-questions">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artifact vers un autre project ?">
  Pas pour le moment. Si vous devez isoler un artifact, créez un nouveau [project](/fr/features/projects-and-artifacts/projects) et demandez à Agent de le reconstruire à cet endroit.
</Accordion>

<Accordion title="Y a-t-il une limite au nombre d'artifacts qu'un project peut contenir ?">
  Un project peut contenir au maximum 7 artifacts, avec une limite d&#39;**1 application mobile par project**. Cette limite existe parce que chaque artifact supplémentaire consomme davantage de mémoire, ce qui peut ralentir le Preview. Si vous avez besoin de plus d&#39;artifacts, démarrez un autre [project](/fr/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artifact d'un project ?">
  Pas pour le moment. La publication met tout en ligne en même temps. Si vous avez besoin de publier des éléments indépendamment, utilisez des projects distincts.
</Accordion>

<Accordion title="Les artifacts partagent-ils des données entre eux ?">
  Oui. Tous les artifacts d&#39;un project partagent la même base de données et les mêmes services backend. Si votre web app écrit des données, votre application mobile et votre tableau de bord de données peuvent les lire immédiatement.
</Accordion>

<Accordion title="Quelle est la différence entre un artifact et un fichier ?">
  Les artifacts sont des éléments que vous pouvez publier : applications, présentations, vidéos, etc. Les fichiers (comme les CSV, les images ou le code) sont des assets de votre project qui accompagnent vos artifacts, mais ne peuvent pas être publiés isolément.
</Accordion>
