<div id="section">
  ## Добавление заголовков ответа
</div>

Пользовательские **заголовки ответа** позволяют добавлять HTTP-заголовки с инструкциями к запросам, которые соответствуют определённым путям.
Заголовок ответа — это пара «имя — значение», которая сообщает браузеру, как обрабатывать запрошенное содержимое.

Например, с помощью заголовка `Access-Control-Allow-Origin` можно указать, каким доменам браузер разрешит доступ к этой странице.
Чтобы создать такую запись, добавьте следующее в файл `.replit` в корневом каталоге Replit App:

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

Этот заголовок ответа содержит следующие параметры:

* **path**: шаблон URL-пути, соответствующий запрошенному ресурсу
* **name**: имя HTTP-заголовка
* **value**: значение HTTP-заголовка

В файл `.replit` можно добавить несколько записей `deployment.responseHeaders`.

Чтобы изменения настроек вступили в силу, опубликуйте Replit App повторно.

<div id="404">
  ## Создание собственной страницы 404
</div>

Собственная страница 404 отображается, когда пользователь запрашивает URL-путь, который не соответствует ни одному файлу или правилу в опубликованном приложении.

Чтобы добавить собственную страницу 404, создайте в корневом каталоге Replit App файл с именем `404.html` и поместите в него содержимое страницы.

При попытке перейти по несуществующему URL-пути пользователь увидит отрендеренный HTML вашей страницы 404.

<div id="url">
  ## Определение перезаписи URL-путей
</div>

Перезапись URL позволяет изменить URL-путь до того, как Replit App обработает запрос.
В браузере исходный URL отображается без изменений, но сервер загружает ресурс, указанный в правиле перезаписи.

Например, можно задать, чтобы все запросы, начинающиеся с `/app`, загружали содержимое файла `/app/index.html`.
Чтобы создать такую запись, добавьте следующие строки в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**: шаблон URL-пути, соответствующий запрошенному ресурсу
* **to**: путь после перезаписи. Соответствует файлу внутри статического развёртывания.

В файл `.replit` можно добавить несколько записей `deployment.rewrites`.
Сервер обрабатывает записи в порядке их следования и игнорирует дубликаты.

Чтобы изменения конфигурации вступили в силу, необходимо повторно опубликовать Replit App.

В следующих разделах описаны ограничения правил перезаписи URL.

<div id="section-3">
  ### Сопоставление путей
</div>

К параметрам `from` и `to` правила перезаписи применяются следующие ограничения:

* если `*` не указан, совпадение должно быть точным
* `*` соответствует оставшейся части пути
* `*` допускается только в конце пути
* если вы указываете `*` в параметре `from`, его можно указать и в параметре `to` — он обозначит совпавшую часть пути

Например, предположим, что файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

Когда пользователь обращается к `/v1/about-us.html`, правило перезаписи возвращает файл, расположенный по пути `/v2/about-us.html`.

<div id="section-4">
  ### Затенение
</div>

Затенение возникает, когда правило перезаписи совпадает с URL-путём, которому также соответствует файл в статическом развёртывании.
В этом случае облачный сервер игнорирует правило перезаписи и отдаёт файл напрямую.

Например, предположим, что опубликованное приложение содержит следующие файлы:

* `index.html`
* `about.html`

Файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

Когда пользователь обращается к `/register.html`, сервер перезаписывает запрос на `/index.html` и отдаёт этот файл.
Однако если пользователь обращается к `/about.html`, сервер игнорирует правило перезаписи и отдаёт файл `about.html`, поскольку такой файл присутствует в статическом развёртывании.

<div id="section-5">
  ### Ограничения по доменам
</div>

Правила перезаписи действуют только для запросов к основному домену статического развёртывания
и могут перенаправлять только на файлы внутри этого развёртывания.
