<div id="how-replitmd-works">
  ## `replit.md` 的工作原理
</div>

Agent 会首先依据经过验证的最佳实践，在项目根目录中创建一个 `replit.md` 文件。该文件包含：

* 基本的 project 信息
* 推荐的编码模式
* 该 project 类型的常用偏好设置

<YouTubeEmbed videoId="kYv525W-vaU" title="自定义 Replit Agent 的响应方式" />

Agent 在处理你的请求时，会自动读取 `replit.md` 文件，并根据其中的内容：

* 了解 project 的架构和约定
* 遵循你偏好的编码模式和风格
* 使用你指定的包管理器和依赖项

随着 Agent 对 project 的了解不断加深，以及对应用做出修改，它也会更新 `replit.md` 文件。

<Note>你可以编辑 `replit.md` 文件来自定义 Agent 的行为。</Note>

<div id="setting-up-replitmd">
  ## 设置 `replit.md`
</div>

<div id="automatic-generation">
  ### 自动生成
</div>

当你使用 Agent 创建新 project 时，它会依据经过验证的最佳实践自动生成一个 `replit.md` 文件。该文件位于项目根目录下，包含以下内容：

* project 的基本信息
* 推荐的编码模式
* 适用于该 project 类型的常见偏好设置

<div id="manual-creation">
  ### 手动创建
</div>

你也可以自己创建 `replit.md`：在项目的根目录中新建一个名为 `replit.md` 的文件即可。Agent 会在后续对话中自动检测并使用该文件。

<Note>
  `replit.md` 必须位于项目的根目录中才能正常生效。
</Note>

<div id="regenerating-replitmd">
  ### 重新生成 `replit.md`
</div>

如果你的 `replit.md` 文件已损坏，或者你想从头开始：

1. 从项目根目录删除现有的 `replit.md` 文件
2. 与 Agent 开启一段新对话
3. Agent 会根据你当前的项目自动生成新的 `replit.md` 文件

<div id="best-practices">
  ## 最佳实践
</div>

<div id="be-specific-and-clear">
  ### 具体且清晰
</div>

编写清晰、具体的指令，帮助 Agent 准确理解你的需求：

```markdown theme={null}
## 编码风格

- 所有新建的 JavaScript 文件一律使用 TypeScript
- 优先使用带 hooks 的函数式组件，而不是类组件
- 使用 Tailwind CSS 编写样式，避免内联样式
- 始终为函数参数和返回值标注 TypeScript 类型
```

如需更详细的 prompt 格式化指南，请参阅 [Anthropic prompt 工程指南](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags)。

<div id="use-examples">
  ### 使用示例
</div>

比起抽象的描述，示例更能帮助 Agent 理解你的偏好：

````markdown theme={null}
## API 错误处理

创建 API 端点时，请始终使用以下错误处理模式：

```javascript
app.get("/api/users", async (req, res) => {
  try {
    const users = await getUsersFromDatabase();
    res.json({ success: true, data: users });
  } catch (error) {
    console.error("Error fetching users:", error);
    res.status(500).json({
      success: false,
      error: "Failed to fetch users",
    });
  }
});
```
````

<div id="web-application-project">
  ### Web 应用项目

```markdown theme={null}
# MyApp 项目指南

## 项目概览

一个使用 React 和 Express.js 构建的任务管理 web app。

## 技术偏好

- 前端：React 搭配 TypeScript、Tailwind CSS
- 后端：Express.js 搭配 TypeScript
- 数据库：Neon PostgreSQL 搭配 Drizzle ORM
- 包管理器：npm（不使用 yarn 或 pnpm）

## 编码规范

- 使用配合 hooks 的函数式组件
- 实现完善的错误边界
- 端点遵循 REST API 约定
- 变量名和函数名要有描述性

## 沟通风格

- 改动前先说明你的思路
- 为复杂逻辑添加代码注释
- 需求不明确时主动提问
```

<div id="data-analysis-project">
  ### 数据分析项目
</div>

```markdown theme={null}
# 数据分析项目指南

## 项目背景

分析客户行为数据，发现趋势与洞察。

## 技术偏好

- 使用 Python 搭配 Streamlit 构建交互式 web app
- 使用 pandas、numpy 和 matplotlib 进行数据分析

## 分析规范

- 为所有分析步骤提供清晰的文档说明
- 使用 Streamlit 组件创建交互式可视化
- 分析前先校验数据质量
- 将结果导出为 CSV 格式，并在 Streamlit 表格中展示

## 沟通风格

- 说明统计方法及其前提假设
- 为分析结论和建议提供背景说明
- 用清晰、非技术性的语言表达业务洞察
- 为面向相关方的汇报创建交互式仪表盘
```

<div id="combining-web-search-with-replitmd">
  ## 将网络搜索与 `replit.md` 结合使用
</div>

Agent 可以通过网络搜索查找最新信息、库和解决方案。将其与你的 `replit.md` 文件结合使用，既能获得最新知识，又能获得针对项目的专属指导。

<div id="best-practices-for-web-search-integration">
  ### 网络搜索集成的最佳实践
</div>

**明确说明你希望 Agent 研究什么：**

```markdown theme={null}
## 调研偏好

- 在建议更新之前，务必先查看依赖项的最新版本
- 调研安全实现方面的当前最佳实践
- 查找适用于我们技术栈的最新性能优化技术
```

**指导 Agent 如何运用外部知识：**

```markdown theme={null}
## 外部研究指南

- 推荐新库时，确保与我们现有的技术栈兼容
- 调整外部示例，使其符合我们的编码规范和项目结构
- 验证所建议的方案能在我们的发布环境中正常运行
```

**同时结合两者的请求示例：**
“研究最新的 React 18 性能优化技术，并按照 `replit.md` 中定义的组件模式来实现”

这种方式能让你获得既紧跟前沿、又贴合具体项目需求的解决方案。

<div id="limitations">
  ## 限制
</div>

<div id="file-size-and-content-limits">
  ### 文件大小和内容限制
</div>

虽然 `replit.md` 没有严格的字符数限制，但文件过大可能无法被完整处理。请保持 `replit.md` 重点突出、简明扼要，以获得最佳效果。

<div id="root-directory-requirement">
  ### 根目录要求
</div>

`replit.md` 必须位于项目的根目录中。Agent 不会自动检测子目录中的该文件。

<div id="context-scope">
  ### 上下文范围
</div>

`replit.md` 为 Agent 对话提供上下文，但不会自动应用于其他 AI 工具。

<div id="next-steps">
  ## 后续步骤
</div>

准备好为你的项目定制 Agent 了吗？

1. **从简单开始**：先创建一个包含关键偏好设置的基础 `replit.md`
2. **迭代优化**：在与 Agent 协作的过程中持续更新 `replit.md`
3. **复用模式**：把行之有效的 `replit.md` 配置沿用到类似的项目中
4. **关注效果**：留意 Agent 对你所设规则的遵循情况，并据此调整

**Enterprise**：在[自定义模板](/zh/teams/custom-templates)中预先配置 `replit.md`，让组织中的每位构建者都拥有一致的起始上下文。有关设计方面的具体指导，请参阅[设置设计系统](/zh/teams/custom-design-system)。
