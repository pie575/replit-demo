<div id="primeiros-passos">
  ## Первые шаги
</div>

Replit — это облачная среда разработки, в которой можно писать и запускать код на любом фреймворке или стеке. Создать пользовательский шаблон можно двумя рекомендуемыми способами:

1. **[Импорт](https://replit.com/import) от Git-провайдера** — импортируйте свой существующий стартовый стек (или тот, который соответствует вашим предпочтениям) из GitHub, GitLab или Bitbucket.
2. **Форк пустого шаблона** — сделайте форк [пустого шаблона](https://replit.com/@replit/Nothing?v=1), чтобы начать с нуля в полностью пустой среде разработки.

Клиенты успешно создавали шаблоны для Rust, Python, Java, C++ и множества других стеков — если это работает где-то ещё, скорее всего, заработает и в Replit.

<Tip>
  При создании первых шаблонов рекомендуем обратиться к команде **Field Engineering в Replit**. У неё обширный опыт настройки пользовательских шаблонов для самых разных стеков, и она готова помочь. Чтобы связаться с ней, обратитесь к своему менеджеру по работе с клиентами.
</Tip>

Пользовательские шаблоны позволяют администраторам Enterprise создавать преднастроенные отправные точки, которые отображаются прямо во входящих Agent для всех участников вашей организации. Когда разработчик выбирает пользовательский шаблон, Agent делает его форк и использует конфигурацию, инструкции и навыки шаблона для всей дальнейшей работы. Никакой дополнительной настройки не требуется.

<Note>
  Пользовательские шаблоны доступны исключительно в плане **Enterprise**. Закреплять шаблоны и управлять ими могут только администраторы организации.
</Note>

<div id="como-os-templates-personalizados-funcionam">
  ## Как работают пользовательские шаблоны
</div>

Пользовательский шаблон — это обычный Replit App в вашей организации, закреплённый во входящих Agent. Когда разработчик выбирает его:

1. Agent создаёт новый app, делая форк шаблона (копируются все файлы)
2. Agent пропускает этап планирования и сразу переходит в режим сборки
3. Файл `custom_instruction/instructions.md` из шаблона добавляется в контекст Agent
4. Пользовательские [навыки](/ru/pt/features/agent/skills) из `.agents/skills/` обнаруживаются и становятся доступными
5. Файл [`replit.md`](/ru/pt/features/project-setup/replit-dot-md) даёт постоянный контекст проекта

Это значит, что стандарты, соглашения и инструменты вашей организации учитываются с самого первого взаимодействия.

<div id="estrutura-de-arquivos-do-template">
  ## Структура файлов шаблона
</div>

Ниже приведена рекомендуемая структура для пользовательского шаблона:

```
meu-template/
├── .replit                              # Конфигурация app (команды запуска, порты, модули)
├── replit.md                            # Память Agent: обзор проекта и предпочтения
├── custom_instruction/
│   └── instructions.md                  # Инструкции компании, добавляемые в prompt для Agent
├── .agents/
│   └── skills/
│       └── minha-skill/
│           └── SKILL.md                 # Пользовательские навыки, которые Agent вызывает по мере необходимости
└── ...                                  # Остальная структура вашего репозитория
```

Каждый файл выполняет свою задачу. В разделах ниже описано, как настроить каждый из них.

<div id="configurar-um-template-personalizado">
  ## Настройка пользовательского шаблона
</div>

<div id="criar-o-app-base">
  ### Создание базового приложения
</div>

Создайте новый Replit App в своей организации. Настройте проект, добавив все файлы, зависимости и параметры, которые нужны вашим разработчикам для старта. Сюда входят:

* Каркас исходного кода (компоненты, утилиты, файлы конфигурации)
* Предустановленные зависимости (`package.json`, `requirements.txt` и т. д.)
* Настройка окружения в [файле `.replit`](/ru/replit-app/configuration)

<div id="configurar-secrets-compartilhados">
  ### Настройка общих Secrets
</div>

Если ваш шаблон использует ключи API, токены или другие учётные данные, добавьте их в **Secrets** шаблона (на панели инструментов) перед его закреплением. Когда разработчик создаёт новый app на основе шаблона, все secrets копируются в новый app автоматически, поэтому можно сразу приступать к работе, не настраивая учётные данные.

Опишите каждый secret в файле `custom_instruction/instructions.md` (или в отдельном навыке), чтобы разработчики знали, что им доступно и для чего используется каждый ключ.

<Warning>
  Secrets копируются в момент форка и не синхронизируются динамически. Если вы смените ключ или добавите в шаблон новый secret, ранее созданные форки не обновятся. Разработчикам придётся добавить или обновить secrets в таких apps вручную.
</Warning>

<div id="escrever-instrues-personalizadas">
  ### Написание пользовательских инструкций
</div>

Создайте файл `custom_instruction/instructions.md` в корне проекта. Это самый важный файл вашего шаблона — именно он объясняет Agent, как в вашей организации принято разрабатывать программное обеспечение.

<Warning>
  Папка должна называться `custom_instruction` (в единственном числе), а не `custom_instructions`.
</Warning>

Agent подставляет содержимое этого файла прямо в свой системный prompt вместе с преамбулой, которая представляет его как указания компании. Пишите в формате Markdown и укажите:

* **Архитектурные паттерны**: как должны быть устроены ваши приложения
* **Стандарты кода**: соглашения об именовании, правила организации файлов, требования к линтингу
* **Использование компонентов**: какие библиотеки и компоненты применять (а каких избегать)
* **Паттерны API**: как обращаться к вашим бэкенд-сервисам, обрабатывать аутентификацию, работать с ошибками
* **Требования к тестированию**: какие тесты нужны и как их запускать
* **Рекомендации по deployment**: настройки для конкретных окружений и процессы развёртывания

````markdown theme={null}
# Стандарты разработки компании

## Архитектура
Все веб-приложения используют React с TypeScript. Применяйте только
функциональные компоненты с хуками. Для локального состояния используйте
Zustand, для серверного — React Query.

## Библиотека компонентов
Используйте наш внутренний пакет дизайн-системы `@acme/ui`. Никогда не применяйте
чистые HTML-элементы для кнопок, полей ввода, форм или модальных окон — всегда
берите соответствующий компонент из `@acme/ui`.

Импортируйте компоненты так:
```tsx
import { Button, TextField, Modal } from '@acme/ui';
```

## Интеграция с API
Все вызовы API идут через пакет `@acme/api-client`. Никогда не используйте
чистый fetch или axios напрямую. Аутентификацию клиент выполняет
автоматически.

## Тестирование
У каждого компонента должен быть свой файл тестов. Используйте Vitest
для модульных тестов и Playwright для интеграционных.
````

**Ограничение размера**: содержимое ограничено примерно 25 КБ. Всё, что выходит за этот предел, может постепенно усекаться. По мере роста инструкций переносите подробные справочные материалы в [навыки](/ru/pt/features/agent/skills) в папке `.agents/skills/`, а не храните всё в `instructions.md`. Навыки загружаются по требованию, когда они действительно нужны, поэтому не учитываются в лимите размера инструкций и позволяют оставить основные инструкции краткими и посвящёнными правилам высокого уровня.

<div id="adicionar-skills-personalizadas">
  ### Добавление собственных навыков
</div>

Создавайте навыки в каталоге `.agents/skills/` для специализированных рабочих процессов, которым должен следовать Agent. Каждый навык — это каталог с файлом `SKILL.md`, содержащим frontmatter в формате YAML.

```
.agents/skills/
├── usar-sistema-de-design/
│   └── SKILL.md
├── integracao-de-api/
│   └── SKILL.md
└── executar-testes/
    └── SKILL.md
```

Каждому файлу `SKILL.md` необходимы поля `name` и `description` во frontmatter:

```markdown theme={null}
---
name: use-design-system
description: Use when building UI components. Provides component patterns, theming rules, and accessibility requirements for the Acme design system.
---

# Sistema de Design Acme

## Componentes disponíveis

- `Button` — Variantes primária, secundária e ghost
- `TextField` — Input de texto com suporte à validação
- `Modal` — Overlay de diálogo com captura de foco
...
```

| Поле          | Обязательное | Подробности                                                               |
| ------------- | ------------ | ------------------------------------------------------------------------- |
| `name`        | Да           | Максимум 64 символа. Только строчные буквы, цифры и дефисы.               |
| `description` | Да           | Максимум 1024 символа. Описывает, что делает навык и когда его применять. |
| `enabled`     | Нет          | По умолчанию `true`. Укажите `false`, чтобы отключить без удаления.       |

**Как загружаются навыки**: в своём prompt Agent видит только `name` и `description`. Полное содержимое `SKILL.md` он читает по запросу, когда навык относится к текущей задаче. Поэтому `description` играет ключевую роль — составьте его так, чтобы он соответствовал сценариям, в которых Agent должен применять навык.

Навыки также могут включать вспомогательные файлы рядом с `SKILL.md`:

```
.agents/skills/usar-sistema-de-design/
├── SKILL.md
├── references/
│   └── component-api.md
└── assets/
    └── theme-tokens.json
```

Подробнее о навыках см. в разделах [Agent Skills](/ru/pt/features/agent/skills) и [Использование навыка](/ru/pt/build/use-agent-skills).

<div id="configurar-replitmd">
  ### Настройка replit.md
</div>

Заранее заполните файл `replit.md` в корне проекта общим описанием архитектуры вашего шаблона. Этот файл всегда загружается в контекст Agent и служит постоянной памятью проекта.

Файл должен содержать следующие четыре раздела:

```markdown theme={null}
# Обзор
Приложение для управления задачами на React, TypeScript и дизайн-системе
Acme. Использует бэкенд на Express.js с PostgreSQL.

# Предпочтения пользователя
- Использовать TypeScript для всех файлов
- Отдавать предпочтение функциональным компонентам с хуками
- Следовать стандартам кода Acme

# Архитектура системы
- Frontend: React + TypeScript + @acme/ui
- Backend: Express.js + TypeScript
- База данных: PostgreSQL с Drizzle ORM
- Аутентификация: Acme SSO через @acme/auth

# Внешние зависимости
- @acme/ui: внутренняя дизайн-система
- @acme/api-client: слой интеграции с API
- @acme/auth: SDK аутентификации
```

Agent обновляет `replit.md` по мере развития проекта. Если объём файла превысит примерно 4000 токенов, Agent автоматически сократит его, чтобы он оставался лаконичным и полезным.

Подробнее см. [replit.md](/ru/pt/features/project-setup/replit-dot-md).

<div id="fixe-o-template-na-sua-organizao">
  ### Закрепите шаблон в своей организации
</div>

Когда шаблон будет готов:

1. Перейдите к App шаблона в своей организации
2. Откройте меню действий App (меню с тремя точками)
3. Выберите **Закрепить во входящих Agent**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий App с пунктом «Закрепить во входящих Agent»" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Закреплять и откреплять шаблоны могут только администраторы организации (участники роли `system_admins`).
</Note>

Установите для участников уровень доступа **Только чтение**, чтобы они могли просматривать и использовать закреплённый шаблон, но не редактировать его.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалог приглашения с уровнем доступа участников «Только чтение»" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Теперь шаблон отображается как выбираемый ярлык под входящими Agent у всех участников вашей организации. Чтобы удалить его, откройте то же меню и выберите **Открепить от входящих Agent**.

<div id="controlar-o-acesso-ao-template">
  ### Управление доступом к шаблону
</div>

Закрепление делает шаблон видимым для всех участников организации. Для более точечного распространения используйте кнопку **Пригласить** в App шаблона, чтобы поделиться им с конкретными [группами или отдельными пользователями](/ru/pt/teams/identity-and-access-management/groups-and-permissions). Так вы ограничите круг команд и людей, которые могут просматривать шаблон и делать его форк, и при этом шаблон останется незакреплённым в общих входящих организации.

<div id="o-que-acontece-quando-um-desenvolvedor-seleciona-um-template">
  ## Что происходит, когда разработчик выбирает шаблон
</div>

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Шаблон отображается в виде выбираемой метки во входящих Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

Когда участник организации выбирает закреплённый шаблон во входящих Agent:

1. **Форк**: создаётся новый app — копия шаблона со всеми входящими в него файлами
2. **Пропуск планирования**: Agent пропускает начальное обсуждение плана и сразу переходит в режим сборки
3. **Загрузка инструкций**: файл `custom_instruction/instructions.md` считывается и добавляется в системный prompt Agent в качестве указаний от компании
4. **Обнаружение навыков**: навыки в `.agents/skills/` определяются и перечисляются в контексте Agent для загрузки по требованию
5. **Загрузка контекста проекта**: файл `replit.md` считывается и добавляется в контекст Agent (или создаётся автоматически, если отсутствует)
6. **Наследование конфигурации**: файл `.replit`, зависимости и все файлы шаблона переносятся в новый app

Разработчик может сразу начать отправлять Agent prompt со своими конкретными требованиями, а Agent будет работать в рамках правил, заданных шаблоном.

<div id="como-os-arquivos-funcionam-juntos">
  ## Как файлы работают вместе
</div>

Каждый файл конфигурации выполняет свою отдельную функцию:

| Файл                                 | Назначение                                    | Когда Agent его читает                 | Может изменять Agent                    |
| ------------------------------------ | --------------------------------------------- | -------------------------------------- | --------------------------------------- |
| `custom_instruction/instructions.md` | Стандарты и правила организации               | Всегда (внедряется в системный prompt) | Нет                                     |
| `.agents/skills/*/SKILL.md`          | Специализированные рабочие процессы и шаблоны | По запросу (когда это уместно)         | Да (Agent также может создавать навыки) |
| `replit.md`                          | Обзор проекта и предпочтения                  | Всегда (внедряется в системный prompt) | Да (Agent обновляет его со временем)    |
| `.replit`                            | Конфигурация среды выполнения                 | При настройке приложения               | Да                                      |

**Ключевое отличие**: `custom_instruction/instructions.md` — это ваш статичный и авторитетный источник организационных стандартов. `replit.md` — живой документ, который Agent поддерживает по мере развития проекта. Навыки — это справочный материал, подключаемый по запросу для конкретных рабочих процессов.

<div id="melhores-prticas">
  ## Рекомендации
</div>

<div id="mantenha-as-instrues-focadas">
  ### Не распыляйтесь в инструкциях
</div>

В файле `custom_instruction/instructions.md` описывайте только самые важные стандарты. Сосредоточьтесь на следующем:

* Решения, которые трудно отменить (архитектура, модели данных)
* Стандарты, которые нужно соблюдать единообразно (использование компонентов, соглашения по API)
* Стандарты, о которых разработчик может не знать (внутренние библиотеки, принятые в команде соглашения)

Не включайте списки изменений, детали реализации и информацию, которая часто меняется.

<div id="escreva-descries-de-skills-descobrveis">
  ### Пишите описания навыков так, чтобы их было легко найти
</div>

Поле `description` во frontmatter файла `SKILL.md` — это то, на что опирается Agent, решая, когда загрузить навык. Составляйте описания так, чтобы они соответствовали задачам, в которых навык действительно полезен:

```yaml theme={null}
# Хорошо — описывает, когда использовать
description: Use when building forms or handling user input. Provides validation patterns, error display conventions, and accessible form layouts.

# Менее эффективно — слишком расплывчато
description: Form utilities and helpers.
```

<div id="organize-skills-por-fluxo-de-trabalho">
  ### Организуйте навыки по рабочим процессам
</div>

Группируйте навыки по рабочим процессам, а не по техническим категориям:

| Подход                     | Пример                                       |
| -------------------------- | -------------------------------------------- |
| **По рабочему процессу**   | `build-a-form`, `connect-to-api`, `add-auth` |
| **По технической области** | `react-utils`, `api-helpers`, `auth-config`  |

Группировка по рабочим процессам помогает Agent находить нужные навыки в нужный момент.

<div id="itere-no-seu-template">
  ### Дорабатывайте шаблон
</div>

Шаблоны становятся лучше по мере использования. Когда ваша команда начнёт разрабатывать на основе шаблона:

1. Подмечайте закономерности в ошибках Agent и добавляйте их в `instructions.md`
2. Создавайте новые навыки, когда Agent удачно решает задачу, — фиксируйте решение
3. Обновляйте зависимости и базовые настройки по мере развития вашего стека
4. Проверяйте изменения, создавая новый app из шаблона, чтобы оценить опыт использования

<div id="atualizaes-de-templates-e-apps-existentes">
  ### Обновления шаблонов и существующих App
</div>

Изменения в App-шаблоне применяются только к **новым** App, созданным на его основе. Существующие App, ранее созданные форком шаблона, представляют собой независимые копии и обновления не получают.

<div id="recursos-relacionados">
