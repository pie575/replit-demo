  ## Быстрые примеры

Посмотрите, чем расплывчатые промпты отличаются от эффективных:

<AccordionGroup>
  <Accordion title="Исправление кода" icon="bug">

    Эффективный промпт указывает проблемную область, предполагаемую функцию и предоставляет контекст.
  </Accordion>

  <Accordion title="Создание функций" icon="hammer">
    **Расплывчато:** &quot;Создай веб-сайт.&quot;

    Эффективный промпт определяет назначение, основные функции и желаемый стиль.
  </Accordion>

  <Accordion title="Улучшение производительности" icon="gauge-high">
    **Расплывчато:** &quot;Не делай его медленным.&quot;

    Говорите Agent, *как* улучшить результат, а не используйте отрицательные ограничения.

    Укажите конкретный элемент, желаемый эффект, время и впечатление, которое он должен создавать.

<div id="planeje-primeiro">
  ### Сначала планируйте
</div>

<Tip>Прежде чем составлять промпт, набросайте функции и пользовательские сценарии вашего приложения. Чёткий план помогает формулировать более точные промпты.</Tip>

Продумайте структуру приложения так, как это сделал бы менеджер продукта. Разбейте общую цель на логические этапы.

**Вместо:** «Build a task manager app.»

**Попробуйте:** «1. Create the basic HTML structure with an input field and task list. 2. Add JavaScript to add tasks. 3. Use a database to store tasks. 4. Add functionality to mark tasks complete.»

Затем составляйте промпты для Agent на каждом этапе.

<div id="construa-incrementalmente">
  ### Разрабатывайте постепенно
</div>

Используйте [**чекпоинты**](/ru/pt/features/agent/overview#checkpoints), чтобы сохранять прогресс после каждого успешно выполненного этапа. Если что-то сломается, вы сможете вернуться к рабочему состоянию и попробовать другой подход.

**Вместо:** «Создай полноценную платформу для электронной коммерции».

**Попробуйте:** «Создай базовый полностековый проект сайта электронной коммерции с регистрацией и входом пользователей через Replit Auth». Затем используйте промпты, чтобы добавить списки товаров, корзину и оформление заказа.

<div id="seja-especfico">
  ### Будьте конкретны
</div>

Точно определите, что вам нужно: форматы результата, ограничения, пограничные случаи.

**Вместо:** «Add a contact form.»

**Попробуйте:** «Create a contact form page at `/contact` with fields for:

* Name (required)
* Email (required, must be valid format)
* Message (required, min 10 characters)

On submit, send the form data to `contact@mydomain.com`.»

<div id="use-linguagem-positiva">
  ### Используйте позитивные формулировки
</div>

Говорите, чего вы *хотите*, а не чего следует избегать.

**Вместо:** &quot;Не делайте страницу профиля пользователя непонятной.&quot;

**Попробуйте:** &quot;Создайте лаконичную страницу профиля пользователя. Разместите имя пользователя на видном месте, а затем укажите адрес электронной почты и дату регистрации. Добавьте кнопку «Редактировать профиль».&quot;

<div id="mantenha-a-simplicidade">
  ### Сохраняйте простоту
</div>

Используйте ясный и понятный язык. Разбивайте сложные запросы на пункты.

**Вместо:** &quot;Реализуйте необходимую серверную инфраструктуру для динамического создания и получения пользовательского контента.&quot;

**Попробуйте:** &quot;Добавьте на бэкенде возможность отправлять записи в блог. Пользователи должны указывать заголовок и текст записи. Храните записи в базе данных.&quot;

  ## Работа с контекстом
</div>

<div id="fornea-arquivos-relevantes">
  ### Предоставляйте нужные файлы
</div>

Указывайте конкретные файлы вместо того, чтобы прикреплять весь проект.

**Вместо:** (Прикрепить всё) &quot;Реализуйте страницу профиля пользователя на основе нашей дизайн-системы.&quot;

**Попробуйте:** &quot;Создайте страницу профиля пользователя. Получите данные пользователя через серверный эндпоинт. Оформите в соответствии с [URL документации по дизайну] и воспроизведите этот макет: [прикрепите `profile_mockup.jpg`].&quot;

<Tip>Начинайте новый чат, когда переходите к несвязанным задачам. Это помогает избежать путаницы из-за накопленного контекста.</Tip>

<div id="mostre-exemplos">
  ### Показывайте примеры
</div>

Устраняйте неоднозначность с помощью конкретных примеров — фрагментов кода, образцов данных или скриншотов.

**Вместо:** &quot;Make the product cards look better.&quot;

**Попробуйте:** &quot;Redesign the product cards on the shop page. Each card should display the product image, name, price, and an &#39;Add to Cart&#39; button, similar to this layout: [attach screenshot]. Use a light gray border.&quot;

<div id="depurando-de-forma-eficaz">
  ## Эффективная отладка
</div>

При возникновении ошибок укажите:

* **Точное** сообщение об ошибке
* Соответствующие фрагменты кода
* Имена файлов, в которых возникает ошибка
* Что вы пытались сделать
* Какие шаги вы уже предприняли

**Вместо:** «Моя страница входа не работает».

**Попробуйте:** «Когда я ввожу правильные учётные данные на `/login`, в консоли браузера появляется ошибка „Пользователь не найден“. Похоже, проверка базы данных не работает. Вот код обработки входа в `auth.js`».

<div id="pea-orientao">
  ## Попросите совета
</div>

<Tip>Переключитесь в Plan mode, чтобы изучить варианты до начала разработки. Расспросите Agent о библиотеках, подходах и компромиссах.</Tip>

**Вместо:** &quot;Add payments.&quot;

**Попробуйте:** &quot;What are some good options for accepting credit card payments in a web app built on Replit? I need something relatively simple to integrate.&quot;

<div id="itere-nos-seus-prompts">
  ## Совершенствуйте промпты итеративно
</div>

Первый промпт может получиться неидеальным — это нормально. Если результат вас не устраивает:

* Добавьте больше деталей
* Приведите пример
* Упростите инструкцию
* Попробуйте объяснить иначе

**Исходный:** &quot;Создай шапку для моего сайта.&quot;

**Уточнённый:** &quot;Создай закреплённый компонент шапки с логотипом сайта слева и навигационными ссылками (Главная, О нас, Контакты) справа.&quot;

<div id="resumo">
  ## Итоги
</div>

Эффективный промптинг сводится к следующему:

* **Планируйте** перед созданием промптов
* **Разрабатывайте** постепенно, используя чекпоинты
* **Чётко формулируйте** требования
* **Добавляйте контекст** с помощью примеров и релевантных файлов
* **Повторяйте попытки**, если результат вас не устраивает

Освойте эти принципы, и вы сможете создавать приложения с Agent быстрее.
