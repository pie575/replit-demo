Le contexte correspond aux informations qu’un modèle d’IA utilise pour générer sa prochaine réponse. La gestion du contexte consiste à fournir au modèle les bonnes informations au bon moment.

C’est important, car l’IA ne se base pas uniquement sur vos intentions. Elle s’appuie sur le texte, les fichiers, les captures d’écran, les journaux, les exemples et l’historique des conversations disponibles dans la fenêtre de contexte.

<div id="section">
  ## Qu’est-ce qu’une fenêtre de contexte ?
</div>

Les modèles d’IA ne peuvent prendre en compte qu’une quantité limitée d’informations à la fois. Cette limite est appelée fenêtre de contexte.

La fenêtre de contexte peut inclure :

* vos prompts
* les messages précédents de la conversation
* les fichiers ou le code auxquels le modèle a accès
* les messages d’erreur et les journaux
* des captures d’écran, des images ou des références de design
* des instructions de projet telles que `replit.md`
* les résultats des outils des étapes précédentes

Le modèle utilise ce contexte pour déterminer ce qu’il va générer ensuite.

<div id="section-2">
  ## Pourquoi la fenêtre de contexte est importante
</div>

Si des informations importantes ne figurent pas dans le contexte, le modèle risque de faire des suppositions. À l’inverse, si le contexte contient trop d’informations non pertinentes, le modèle risque de se concentrer sur les mauvaises.

Par exemple, ce prompt ne fournit presque aucun contexte :

```text theme={null}
Améliorez la page d’inscription.
```

Ce prompt fournit un contexte utile :

```text theme={null}
Améliorez la page d’inscription pour les nouveaux fondateurs qui envisagent de rejoindre la liste d’attente.
Conservez les champs actuels. Rendez la proposition de valeur plus claire au-dessus du formulaire.
Ne modifiez pas la section des tarifs.
```

Le deuxième prompt précise à qui s’adresse la page, ce qu’il faut améliorer, ce qu’il faut préserver et ce qui est hors périmètre.

<div id="section-3">
  ## La taille des fenêtres de contexte varie
</div>

Les différents modèles d&#39;IA peuvent traiter des quantités de contexte différentes. Les fenêtres de contexte plus grandes peuvent prendre en compte davantage de texte à la fois, mais plus grand n&#39;est pas toujours mieux. Un contexte pertinent reste plus important que de déverser tous les détails dans la conversation.

Exemples de tailles de fenêtres de contexte publiques :

| Famille de modèles | Exemple de fenêtre de contexte |
| ------------------ | ------------------------------- |
| GPT-4.1            | Jusqu&#39;à 1 million de jetons |
| Claude Sonnet 4.5  | Jusqu&#39;à 200 000 jetons      |
| Gemini 2.5 Pro     | Jusqu&#39;à 1 million de jetons |

Ces chiffres évoluent au fil du temps et tous les produits n&#39;exposent pas la limite complète du modèle. La leçon pratique reste la même : gardez les informations importantes claires et ciblées.

<div id="section-4">
  ## Types de contexte
</div>

| Type de contexte                   | Exemple                                                                                       |
| ---------------------------------- | --------------------------------------------------------------------------------------------- |
| **Objectif**                       | &quot;Cette page de destination doit recueillir des inscriptions à la liste d’attente.&quot;  |
| **Public cible**                   | &quot;Elle s’adresse aux restaurateurs très occupés.&quot;                                    |
| **Contraintes**                    | &quot;Conservez la palette de couleurs et les champs de formulaire actuels.&quot;             |
| **Hors périmètre**                 | &quot;N’ajoutez pas encore de paiements.&quot;                                                |
| **Exemples**                       | Captures d’écran, maquettes, données d’exemple ou pages de concurrents.                       |
| **État du projet**                 | Fichiers, composants, messages d’erreur ou parcours utilisateur actuels.                      |
| **Définition du résultat attendu** | &quot;Les visiteurs peuvent soumettre le formulaire et voir un message de remerciement.&quot; |

<div id="section-5">
  ## Contexte ponctuel et contexte permanent
</div>

Certains contextes concernent la conversation en cours. Utilisez-les pour demander des modifications précises, déboguer un problème ou donner votre avis sur des résultats récents.

D&#39;autres contextes doivent être conservés à l&#39;échelle du projet. Utilisez le contexte permanent pour le style de code, les directives de marque, les conventions de nommage, les règles produit réutilisables et les contraintes dont Agent doit se souvenir d&#39;une session de travail à l&#39;autre. Dans Replit, [replit.md](/fr/ko/features/project-setup/replit-dot-md) permet de fournir à Agent un contexte de projet permanent.

<div id="section-6">
  ## Lorsque le contexte devient confus
</div>

Les longues conversations peuvent perdre le fil. Si un fil de discussion regroupe trop de décisions sans lien entre elles, Agent risque de s’appuyer sur un ancien contexte qui n’est plus pertinent.

Commencez un nouveau fil de discussion lorsque :

* vous passez à une fonctionnalité sans rapport
* la conversation comporte de nombreuses pistes abandonnées
* Agent continue d’appliquer d’anciennes contraintes
* vous souhaitez disposer d’un plan clair pour un nouveau domaine

Lorsque vous repartez de zéro, résumez le contexte important au lieu de supposer qu’Agent sait encore ce qui compte.

```text theme={null}
Contexte : ce projet est une application de liste d’attente pour des coachs sportifs locaux.
Le parcours principal est le suivant : page de destination → formulaire d’inscription → message de confirmation.
Dans ce fil de discussion, améliorez uniquement le message de confirmation et les textes de suivi.
```

<div id="section-7">
  ## Idées reçues courantes
</div>

* **« Plus il y a de contexte, mieux c’est. »** Un contexte pertinent est préférable. Trop de contexte non pertinent peut distraire le modèle.
* **« Le modèle se souvient parfaitement de tout. »** L’IA utilise le contexte disponible, mais vous devez répéter les contraintes importantes lorsqu’elles sont essentielles.
* **« Le contexte se limite au texte. »** Les captures d’écran, les fichiers, les données, les designs, les journaux et les exemples peuvent tous constituer du contexte.
