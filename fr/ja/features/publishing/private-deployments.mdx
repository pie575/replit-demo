---
title: "Qui peut accéder à votre app"
description: "Contrôlez qui peut ouvrir votre app publiée : Public, Password protected, Workspace only, Invite only. Aucune modification de code n'est nécessaire."
---

Lorsque vous publiez une app, vous pouvez contrôler qui peut l&#39;ouvrir. Sélectionnez une option sous **Who can access your app** dans les paramètres de publication. Aucune modification de code n&#39;est nécessaire : Replit gère pour vous l&#39;écran de connexion et les vérifications d&#39;accès.

Restreindre l&#39;accès est utile pour des apps telles que :

* Les outils internes
* Les apps en phase de test bêta
* Les apps qui accèdent à des informations confidentielles

<div id="section">
  ## Options d&#39;accès
</div>

* **Public** : toute personne sur Internet connaissant l&#39;URL peut utiliser l&#39;application.
* **Password protected** : toute personne sur Internet connaissant le mot de passe peut utiliser l&#39;application. Les visiteurs saisissent le mot de passe partagé. Aucun compte Replit n&#39;est nécessaire.
* **Workspace only** : concerne tous les administrateurs, membres et lecteurs de l&#39;espace de travail. Replit affiche cette option sous le nom **Private**.
* **Invite only** : vous seul, les administrateurs, les groupes invités et les utilisateurs invités. Replit affiche cette option sous le nom **Private**. Il s&#39;agit de l&#39;option la plus restrictive.

La valeur par défaut dépend de l&#39;endroit où vous développez. Les applications d&#39;un espace de travail personnel sont **Public** par défaut, tandis que celles d&#39;un espace de travail d&#39;organisation utilisent par défaut une option privée.

<Note>
  Avec les deux options **Private**, les visiteurs qui ne disposent pas des droits d&#39;accès doivent se connecter via Replit avant de pouvoir afficher l&#39;application. Dans un espace de travail personnel dont vous êtes le seul membre, **Workspace only** et **Invite only** fonctionnent de façon identique. Cette distinction prend toute son importance lorsque vous travaillez dans un espace de travail partagé avec des collaborateurs.
</Note>

<div id="section-2">
  ## Choisir l&#39;accès lors de la publication
</div>

1. Sélectionnez **Publish** en haut à droite du Project Editor, ou ouvrez **Publishing** sous **Replit Cloud** dans le volet **Tools**.
2. Sous **Who can access your app**, choisissez **Public**, **Password protected**, **Workspace only** ou **Invite only**.
3. Sélectionnez **Publish**.

<Info>
  Les Scheduled Deployments ne diffusent pas de pages web : aucune option d&#39;accès n&#39;est donc proposée.
</Info>

<div id="section-3">
  ## Modifier l&#39;accès à une application en ligne
</div>

<Note>
  Pour modifier l&#39;accès, vous devez d&#39;abord dépublier l&#39;application. Dépubliez-la depuis l&#39;outil Publishing, sélectionnez une autre option sous **Who can access your app**, puis republiez-la.
</Note>

<div id="section-4">
  ## Gérer les utilisateurs invités
</div>

Avec **Invite only**, vous accordez l&#39;accès à des utilisateurs ou à des groupes précis depuis la gestion des accès de l&#39;espace de travail. Les administrateurs de l&#39;espace de travail y ont toujours accès. Pour en savoir plus, consultez [Gestion des accès](/fr/ja/teams/identity-and-access-management/repl-access-management).

<Note>
  Les administrateurs de l&#39;espace de travail peuvent restreindre les options d&#39;accès de l&#39;organisation, et notamment désactiver la publication protégée par mot de passe.
</Note>
