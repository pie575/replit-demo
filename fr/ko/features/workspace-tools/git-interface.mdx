Le panneau Git de Replit offre une interface visuelle pour vos opérations Git, sans avoir à passer par les commandes Git en ligne de commande. Cette fonctionnalité rend le contrôle de version accessible aux débutants tout en offrant des outils puissants aux développeurs expérimentés.

<div id="section">
  ## Fonctionnalités
</div>

Le panneau Git offre des fonctionnalités complètes de gestion de versions directement dans le Project Editor, avec une interface conviviale qui simplifie les opérations Git complexes.

* **Gestion des dépôts** : initialisez, connectez et gérez vos dépôts Git grâce à l&#39;intégration GitHub
* **Suivi des commits** : effectuez le staging, committez et vérifiez les modifications de tous vos fichiers
* **Opérations sur les branches** : créez, changez et fusionnez des branches visuellement
* **Résolution des conflits** : identifiez et résolvez les conflits de fusion avec une aide visuelle
* **Intégration Shell** : synchronisation entre les commandes Git exécutées dans le Shell et le panneau Git

<div id="section-2">
  ## Utilisation
</div>

<div id="section-3">
  ### Configuration du dépôt
</div>

<Accordion title="Comment accéder au panneau Git">
  1. Dans votre application Replit, rendez-vous dans la section Tools
  2. Sélectionnez le symbole **+** pour ajouter un nouvel outil
  3. Sélectionnez **Git** dans la liste des outils disponibles
</Accordion>

Le panneau Git vous aide à configurer et à connecter votre dépôt :

* **Initialiser un dépôt** : crée un nouveau dépôt Git pour votre application Replit
* **Se connecter à un fournisseur Git** : connecte votre dépôt à un fournisseur hébergé ou auto-hébergé pris en charge, à des fins de sauvegarde et de collaboration
* **Configurer le dépôt distant** : établit et gère les connexions vers les dépôts distants

<Note>
  **Prise en charge de Git auto-hébergé** : Replit prend en charge GitHub Enterprise Server, GitLab Self-Managed et Bitbucket Data Center sur le plan Enterprise. Si vous avez besoin d&#39;aide pour la mise en route, la configuration du fournisseur ou la résolution des problèmes de connexion, [contactez l&#39;équipe commerciale de Replit](https://replit.com/enterprise). Vous pouvez également [configurer le dépôt distant à l&#39;aide de commandes Git dans le Shell](#using-git-commands-in-shell).
</Note>

<div id="section-4">
  ### Gestion des modifications
</div>

<Accordion title="Comment consulter les modifications">
  1. Modifiez des fichiers dans votre application Replit
  2. Ouvrez le panneau Git depuis la section Tools
  3. Consultez vos modifications dans la section **Review Changes**
</Accordion>

Le panneau Git fournit des outils pour gérer les modifications de votre code :

* **Examiner les modifications** : consultez les fichiers modifiés, avec les ajouts et les suppressions mis en évidence
* **Indexer des fichiers** : sélectionnez les fichiers à inclure dans le prochain commit
* **Valider les modifications** : enregistrez vos modifications avec un message descriptif
* **Envoyer les mises à jour** : transférez vos commits vers le dépôt distant en un clic

<Note>
  Vous pouvez utiliser Replit AI pour générer des messages de commit qui décrivent précisément vos modifications.

<div id="section-5">
  ### Gestion des branches
</div>

<Accordion title="Comment gérer les branches">
  1. Ouvrez le panneau Git dans la section Tools
  2. Sélectionnez le menu déroulant des branches, à côté du nom de la branche
  3. Créez une nouvelle branche ou sélectionnez-en une existante
</Accordion>

Le panneau Git simplifie le travail sur plusieurs versions de votre code :

* **Créer une branche** : créez une branche pour développer une fonctionnalité à part
* **Changer de branche** : passez d&#39;une version du code à une autre
* **Publier une branche** : partagez la branche avec votre fournisseur Git
* **Récupérer les modifications** : synchronisez-vous avec les mises à jour distantes de vos collaborateurs

<div id="section-6">
  ### Résoudre les conflits de fusion
</div>

<Accordion title="Comment résoudre les conflits de fusion">
  1. Tentez de récupérer les modifications lorsqu&#39;il existe des conflits
  2. Le panneau Git met en évidence les fichiers en conflit
  3. Ouvrez chaque fichier en conflit pour examiner et résoudre les conflits
  4. Enregistrez les fichiers une fois les conflits résolus
  5. Sélectionnez **Pull** pour finaliser la fusion
</Accordion>

Lorsque du code provenant de sources différentes entre en conflit, le panneau Git vous permet de :

* **Identifier les conflits** : voir précisément quels fichiers présentent des conflits
* **Visualiser les différences** : comparer les deux versions du code en conflit
* **Résoudre les problèmes** : choisir le code à conserver ou modifier le conflit manuellement
* **Finaliser la fusion** : terminer le processus de fusion une fois les conflits résolus

Une fois le fichier en conflit résolu, vous pouvez supprimer les marqueurs de conflit en effaçant les lignes commençant par les symboles de conflit, puis enregistrer le fichier.

<div id="shell-git">
  ### Utiliser les commandes Git depuis le Shell
</div>

<Accordion title="Comment accéder au Shell">
  1. Dans le dock d&#39;outils à gauche, sélectionnez **Tous les outils**
  2. Parmi les outils disponibles, sélectionnez **Shell**
</Accordion>

<Tip>
  Le panneau Git offre une interface conviviale, mais les utilisateurs avancés peuvent recourir aux commandes Git standard dans le Shell pour les opérations plus complexes. Les modifications effectuées par l&#39;une ou l&#39;autre méthode se répercutent sur les deux.
</Tip>

Si vous préférez utiliser Git en ligne de commande :

* **Synchronisation des commandes** : toutes les commandes Git exécutées dans le Shell sont automatiquement synchronisées avec le panneau Git
* **Fonctionnalités Git complètes** : accédez aux fonctionnalités Git avancées indisponibles dans le panneau Git
* **Transition fluide** : alternez entre les commandes du Shell et le panneau Git selon vos besoins

<Info>
  **Prise en charge des CLI GitHub et GitLab** : outre les commandes Git standard, vous pouvez utiliser la [CLI GitHub](https://docs.github.com/en/github-cli) (`gh`) et la [CLI GitLab](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) dans le Shell pour gérer et connecter des dépôts Git externes. Ces outils offrent des fonctionnalités enrichies pour travailler avec les dépôts GitHub et GitLab : pull requests, tickets, etc.
</Info>

<div id="section-7">
  #### Opérations sur les dépôts
</div>

* **Cloner un dépôt** : `git clone <url-to-repository>`
* **Initialiser un dépôt** : `git init`
* **Ajouter un dépôt distant** : `git remote add origin <url-to-repository>`

<div id="section-8">
  #### Effectuer des modifications
</div>

* **Vérifier l&#39;état** : `git status` (affiche les fichiers modifiés, ajoutés et supprimés)
* **Indexer des fichiers** : `git add <filename>` ou `git add .` (tous les fichiers)
* **Committer les modifications** : `git commit -m "your commit message"`
* **Pousser les modifications** : `git push origin <branch-name>`
* **Récupérer les modifications** : `git pull origin <branch-name>`

<div id="section-9">
  #### Authentification
</div>

L&#39;authentification est requise lorsque vous travaillez avec des dépôts privés :

* Pour les dépôts GitHub.com, utilisez un jeton d&#39;accès personnel plutôt qu&#39;un mot de passe
* Pour éviter de ressaisir vos identifiants, vous pouvez les stocker dans les Secrets Replit :
  1. Créez un nouveau secret avec la clé `GIT_URL`
  2. Définissez sa valeur sur `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Utilisez `git push $GIT_URL` pour pousser vos modifications sans saisir vos identifiants

<Note>
  Si vous stockez vos identifiants dans un secret, toute personne ayant accès à votre application Replit pourra accéder à vos identifiants Git. Pour les dépôts sensibles, envisagez de saisir vos identifiants manuellement à chaque fois.
</Note>
