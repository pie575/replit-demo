Replit Database repose sur une base de données SQL entièrement gérée qui vous permet d&#39;ajouter un stockage de données persistant à votre Replit App directement depuis le Project Editor.

<Note>
  Le moyen le plus rapide de démarrer consiste à demander à **Agent** d&#39;ajouter une base de données à votre app. Agent configure l&#39;intégration, crée le schéma de la base de données et met à jour votre app pour qu&#39;elle stocke et récupère les données.
</Note>

<div id="recursos">
  ## Fonctionnalités
</div>

L&#39;outil Replit Database offre les fonctionnalités suivantes :

* **Outils de base de données** : exécutez des requêtes, gérez le schéma de la base de données et consultez vos données grâce aux outils SQL intégrés
* **Voyage dans le temps** : restaurez votre base de données à n&#39;importe quel checkpoint de l&#39;**Agent**. Voir [Récupération de données](/fr/pt/features/data-and-storage/data-recovery)
* **Stockage gratuit** : 20 Go de stockage gratuit inclus pour chaque Replit App.
* **Variables d&#39;environnement** : utilisez des variables d&#39;environnement dans votre Replit App pour accéder à la base de données en toute sécurité

<Info>
  Avant le 4 décembre 2025, la base de données de développement était hébergée sur Neon et présentait quelques différences majeures. Voir [Développement et production](/fr/pt/features/data-and-storage/development-and-production#banco-de-dados-de-desenvolvimento-legado) pour plus de détails.
</Info>

<div id="uso">
  ## Utilisation
</div>

<YouTubeEmbed videoId="zbyRuoPNIc8" title="Comment utiliser les bases de données sur Replit" />

Vous pouvez accéder à l&#39;outil Replit Database directement depuis le Project Editor.
Les sections suivantes vous guident dans la configuration et la gestion de votre Database.

<Accordion title="Comment accéder à l'outil Database">
  1. Ouvrez le panneau **Tools** et sélectionnez **Database** sous **Replit Cloud**.
  2. La vue initiale répertorie vos bases de données. Sélectionnez-en une, par exemple **Development Database**, pour l&#39;ouvrir.
</Accordion>

L&#39;outil Database s&#39;organise autour de votre liste de bases de données. La vue initiale affiche chaque base de données avec son utilisation du stockage, ainsi que vos **Billing Period** et **Hours of Compute Used** actuels. L&#39;ouverture d&#39;une base de données donne accès à trois onglets :

* **Overview** : les tables de votre base de données.
* **My Data** : parcourez et modifiez les lignes, ou exécutez des requêtes SQL.
* **Settings** : la chaîne de connexion, l&#39;utilisation du stockage et les détails de connexion.

<div id="adicionar-um-banco-de-dados">
  ### Ajouter une base de données
</div>

Toutes les Replit Apps incluent une base de données par défaut. Vous pouvez y accéder en sélectionnant l&#39;outil <img class="icon-svg" src="/assets/mirror/postgres-c4cb2a1e2de3.svg" alt="Icône de base de données PostgreSQL" width="24" height="24" data-path="images/icons/postgres.svg" /> **Database** dans le Project Editor.

Vous pouvez intégrer la base de données à votre Replit App en demandant à **Agent** d&#39;ajouter une base de données PostgreSQL à votre Replit App,
en précisant quelles données votre Replit App doit stocker. Agent créera le schéma de la base de données
et mettra à jour votre app pour qu&#39;elle communique avec celle-ci.

<div id="recursos-de-segurana">
  ### Fonctionnalités de sécurité
</div>

Lorsque vous ajoutez une intégration de base de données avec **Agent**, celui-ci met en place un mappeur objet-relationnel (ORM)
qui gère l&#39;ensemble des communications avec la base de données, avec une sécurité intégrée.

Cette couche ORM, associée aux bonnes pratiques de sécurité appliquées par Agent, protège votre app contre
les exploits grâce aux fonctionnalités suivantes :

* **Validation de schéma** : vérifie que les données respectent les formats attendus
* **Nettoyage des données** : assainit automatiquement les entrées du créateur afin de prévenir les attaques par injection SQL

<div id="legacy-development-database">
  ## Base de données de développement héritée
</div>

Avant le 4 décembre 2025, la base de données de développement était hébergée sur <a href="https://neon.com/" target="_blank">Neon</a>.
Cette base de données est désormais obsolète et toutes les nouvelles bases de données de développement sont hébergées sur l&#39;infrastructure de base de données propre à Replit.

Vous pouvez vérifier si votre base de données de développement est hébergée sur Neon en consultant la variable d&#39;environnement `DATABASE_URL` [environment variable](#ver-credenciais-de-conexão-e-uso).

<Info>
  Si `DATABASE_URL` contient `neon.tech/neondb`, votre base de données de développement est encore hébergée sur Neon.
  En revanche, si elle contient `helium/heliumdb`, votre base de données de développement est désormais hébergée sur Replit.
</Info>

Voici les principales différences entre l&#39;ancienne base de données de développement Neon et la nouvelle base de données de développement Replit :

| **Fonctionnalité**                   | **Replit (actuel)**                                                                                                                                                                        | **Neon (hérité)**                                                                                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hébergement**                      | Hébergée sur l&#39;infrastructure propre à Replit                                                                                                                                          | Hébergée sur Neon (fournisseur tiers)                                                                                                                                     |
| **Facturation**                      | Incluse gratuitement dans chaque Replit App                                                                                                                                                | Facturation à l&#39;usage. Voir [Publishing and Database Billing](/fr/pt/billing/about-usage-based-billing#databases) pour plus de détails.                                  |
| **Capacité de restauration**         | Restaurez votre base de données vers n&#39;importe quel checkpoint grâce à la [fonctionnalité de rollback](/fr/pt/features/version-control/checkpoints-and-rollbacks/)                        | Restauration à un instant précis (PITR) — récupérez n&#39;importe quel point dans la fenêtre de rétention des sauvegardes.                                                |
| **Sécurité de la connexion**         | Accessible uniquement depuis votre app ; jamais exposée publiquement.                                                                                                                      | Utilisait une chaîne de connexion complète — si elle était exposée, n&#39;importe qui pouvait accéder à votre base de données et la modifier.                             |
| **Comportement lors d&#39;un remix** | [Remixer](/fr/pt/features/projects-and-artifacts/remix-an-app) crée une nouvelle base de données de développement avec les données copiées, pour l&#39;isolation et la sécurité.              | Le remix réutilisait la même base de données pour toutes les copies : les modifications apportées aux remix pouvaient donc affecter l&#39;app d&#39;origine.              |
| **Création de la base de données**   | Créée automatiquement pour chaque Replit App.                                                                                                                                              | Nécessitait une configuration explicite.                                                                                                                                  |
| **Flux de publication**              | Le déploiement ou la publication nécessite la création d&#39;une [base de données de production](/fr/pt/features/data-and-storage/development-and-production) pour isoler les environnements. | Le développement et la production partageaient la même base de données : des modifications involontaires en développement pouvaient donc affecter les apps en production. |

<Warning>
  Si votre app a été forkée ou remixée alors qu&#39;elle utilisait l&#39;ancienne base de données Neon, votre app publiée peut encore faire référence à l&#39;URL de la base de données de l&#39;app d&#39;origine. Après la [mise à niveau de la base de données](/fr/pt/features/data-and-storage/development-and-production), cette connexion partagée cessera de fonctionner. Voir [Fix a published app using a shared database](/fr/pt/features/data-and-storage/shared-database-migration) pour savoir comment mettre à jour votre app publiée.
</Warning>

* [Développement et production](/fr/pt/features/data-and-storage/development-and-production) : vos deux bases de données, la mise à niveau de l&#39;infrastructure et la comparaison avec l&#39;ancien Neon.
* [Travaillez avec vos données](/fr/pt/features/data-and-storage/work-with-your-data) : parcourez, modifiez et interrogez vos données.
* [Détails de connexion](/fr/pt/features/data-and-storage/connection-details) : identifiants et outils externes.
* [Récupération de données](/fr/pt/features/data-and-storage/data-recovery) : restaurez les données de développement ou de production.
