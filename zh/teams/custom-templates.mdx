<div id="getting-started">
  ## 入门
</div>

Replit 是一个云端开发环境，支持编写和运行任何框架或技术栈。要构建自定义模板，推荐以下两种方式：

1. **从 [Git 提供商](https://replit.com/import)导入** — 从 GitHub、GitLab 或 Bitbucket 导入现有的起始技术栈 (或符合你偏好的技术栈) 。
2. **Fork Blank 模板** — Fork [Blank 模板](https://replit.com/@replit/Nothing?v=1)，从完全空白的开发环境开始。

客户已成功构建适用于 Rust、Python、Java、C++ 及许多其他技术栈的模板——只要能运行，就能在 Replit 上运行。

<Tip>
  建议你在构建首个模板时与 Replit 的 **Field Engineering 团队**合作。他们在为各种技术栈配置自定义模板方面经验丰富，可随时提供帮助。请联系你的客户经理进行对接。
</Tip>

自定义模板让 Enterprise 管理员能够创建预先配置的起点，并将其直接显示在组织中每位成员的 Agent 输入框中。当构建者选择自定义模板时，Agent 会 Fork 该模板，并使用模板的配置、说明和 skills 来指导后续所有工作。无需额外设置。

<Note>
  自定义模板仅适用于 **Enterprise** 计划。只有组织管理员可以固定和管理模板。
</Note>

<div id="how-custom-templates-work">
  ## 自定义模板的工作原理
</div>

自定义模板就是组织内一个标准的 Replit App，只不过它被**固定到了 Agent 输入框**。当构建者选择该模板时：

1. Agent 会复刻该模板以创建新应用 (所有文件都会被复制)
2. Agent 跳过规划阶段，直接开始构建
3. 模板中的 `custom_instruction/instructions.md` 文件会被注入 Agent 的上下文
4. `.agents/skills/` 中的自定义 [skills](/zh/features/agent/skills) 会被自动识别并可供调用
5. [`replit.md`](/zh/features/project-setup/replit-dot-md) 文件持续提供项目上下文

这意味着，从第一次交互开始，组织的标准、规范和工具链就已内置其中。

<div id="template-file-structure">
  ## 模板文件结构
</div>

以下是自定义模板的推荐目录结构：

```
my-template/
├── .replit                              # App 配置（运行命令、端口、模块）
├── replit.md                            # Agent 记忆：项目概览与偏好设置
├── custom_instruction/
│   └── instructions.md                  # 注入到 Agent prompt 中的公司指令
├── .agents/
│   └── skills/
│       └── my-skill/
│           └── SKILL.md                 # Agent 可按需调用的自定义 skills
└── ...                                  # 仓库的其余结构
```

每个文件都有各自的用途。以下各节将逐一介绍如何配置它们。

<div id="set-up-a-custom-template">
  ## 设置自定义模板
</div>

<div id="create-the-base-app">
  ### 创建基础应用
</div>

在你的组织中创建一个新的 Replit App。为该 project 准备好构建者作为起点所需的全部文件、依赖项和配置，包括：

* 源代码脚手架 (组件、工具函数、配置文件)
* 预装依赖项 (`package.json`、`requirements.txt` 等)
* [`.replit` 文件](/zh/replit-app/configuration)中的环境配置

<div id="configure-shared-secrets">
  ### 配置共享 Secrets
</div>

如果模板需要用到 API 密钥、令牌或其他凭据，请在固定模板之前，将它们添加到该模板的 **Secrets** (位于 Tools 面板中) 。当构建者基于该模板创建新 App 时，所有 Secrets 都会自动复制到新 App 中，构建者无需自行配置凭据即可直接开始工作。

请在 `custom_instruction/instructions.md` 中 (或在专门的 skill 中) 说明每一项 Secret，让构建者清楚有哪些凭据可用、每个密钥分别用于什么。

<Warning>
  Secrets 只在 fork 时复制一次，不会动态同步。如果你轮换了某个密钥，或向模板中新增了 Secret，此前已 fork 出的 App 不会随之更新，构建者必须在这些 App 中手动添加或更新 Secrets。
</Warning>

<div id="write-custom-instructions">
  ### 编写自定义指令
</div>

在项目根目录下创建 `custom_instruction/instructions.md` 文件。这是模板中最重要的文件——它用于告诉 Agent 你的组织如何开发软件。

<Warning>
  文件夹名称必须是 `custom_instruction` (单数) ，不能是 `custom_instructions`。
</Warning>

Agent 会将此文件直接注入其系统提示词，并添加一段前言，表明这是由公司提供的指导。请使用 Markdown 编写，其中包括：

* **架构模式**：应用应采用怎样的结构
* **编码规范**：命名约定、文件组织规则和代码检查要求
* **组件使用**：应使用哪些库和组件 (以及应避免哪些)
* **API 模式**：如何调用后端服务、处理身份验证和管理错误
* **测试要求**：需要哪些测试，以及如何运行测试
* **部署指南**：针对不同环境的配置和部署工作流

````markdown theme={null}
# 公司工程规范

## 架构
所有 web 应用均使用 React 和 TypeScript。一律使用配合 hooks 的
函数式组件。状态管理使用 Zustand 管理本地状态，
使用 React Query 管理服务端状态。

## 组件库
使用我们内部的设计系统包 `@acme/ui`。按钮、输入框、表单和弹窗
一律不要使用原生 HTML 元素——始终使用 `@acme/ui` 中
对应的组件。

按如下方式导入组件：
```tsx
import { Button, TextField, Modal } from '@acme/ui';
```

## API 集成
所有 API 调用都必须通过 `@acme/api-client` 包完成。不要直接使用
原生 fetch 或 axios。身份验证由客户端
自动处理。

## 测试
每个组件都必须有对应的测试文件。单元测试使用 Vitest，
集成测试使用 Playwright。
````

**大小限制**：内容的软性上限约为 25 KB。超出此限制的内容可能会逐步被截断。随着指令内容增多，请将详细的参考资料移至 `.agents/skills/` 中的 [skills](/zh/features/agent/skills)，而非将所有内容都保留在 `instructions.md` 中。Skills 会在相关时按需加载，因此不会计入指令大小限制，并能让主要指令专注于高层规则。

<div id="add-custom-skills">
  ### 添加自定义技能
</div>

在 `.agents/skills/` 目录中创建技能，为 Agent 提供应遵循的专用工作流。每个技能都是一个目录，其中包含带有 YAML 前置数据的 `SKILL.md` 文件。

```
.agents/skills/
├── use-design-system/
│   └── SKILL.md
├── api-integration/
│   └── SKILL.md
└── run-tests/
    └── SKILL.md
```

每个 `SKILL.md` 都需要在其 frontmatter 中包含 `name` 和 `description`：

```markdown theme={null}
---
name: use-design-system
description: Use when building UI components. Provides component patterns, theming rules, and accessibility requirements for the Acme design system.
---

# Acme 设计系统

## 可用组件

- `Button` — 主要、次要和幽灵三种变体
- `TextField` — 支持校验的文本输入框
- `Modal` — 带焦点锁定的对话框浮层
...
```

| 字段            | 是否必填 | 详情                                 |
| ------------- | ---- | ---------------------------------- |
| `name`        | 是    | 最多 64 个字符。仅支持小写字母、数字和连字符。          |
| `description` | 是    | 最多 1,024 个字符。说明该 skill 的用途及适用场景。   |
| `enabled`     | 否    | 默认为 `true`。设为 `false` 可在不删除的情况下禁用。 |

**skills 的加载方式**：Agent 在 prompt 中只能看到 `name` 和 `description`。只有当某个 skill 与当前任务相关时，它才会按需读取完整的 `SKILL.md` 内容。因此 `description` 至关重要——请围绕 Agent 应当使用该 skill 的场景来撰写。

除 `SKILL.md` 外，skills 还可以包含配套文件：

```
.agents/skills/use-design-system/
├── SKILL.md
├── references/
│   └── component-api.md
└── assets/
    └── theme-tokens.json
```

有关技能的更多信息，请参阅 [Agent Skills](/zh/features/agent/skills) 和 [使用技能](/zh/build/use-agent-skills)。

<div id="configure-replitmd">
  ### 配置 replit.md
</div>

在项目根目录的 `replit.md` 中预先填入模板的架构概览。该文件始终会加载到 Agent 的上下文中，作为项目的长期记忆。

该文件应包含以下四个部分：

```markdown theme={null}
# 概述
使用 React、TypeScript 和 Acme 设计系统构建的任务管理应用。
后端采用 Express.js，数据库为 PostgreSQL。

# 用户偏好
- 所有文件使用 TypeScript
- 优先使用带 hooks 的函数式组件
- 遵循 Acme 编码规范

# 系统架构
- 前端：React + TypeScript + @acme/ui
- 后端：Express.js + TypeScript
- 数据库：PostgreSQL，搭配 Drizzle ORM
- 认证：通过 @acme/auth 使用 Acme SSO

# 外部依赖
- @acme/ui：内部设计系统
- @acme/api-client：API 集成层
- @acme/auth：身份验证 SDK
```

Agent 会随着项目的推进更新 `replit.md`。如果该文件超过约 4,000 个 token，Agent 会自动对其进行总结，使内容保持聚焦且实用。

如需了解更多信息，请参阅 [replit.md](/zh/features/project-setup/replit-dot-md)。

<div id="pin-the-template-to-your-organization">
  ### 将模板固定到组织
</div>

模板准备就绪后：

1. 在组织中找到该模板 App
2. 打开 App 的操作菜单 (三点菜单)
3. 选择 **固定到 Agent 输入框**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="显示“固定到 Agent 输入框”选项的 App 操作菜单" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  只有组织管理员 (具有 `system_admins` 角色的成员) 可以固定或取消固定模板。
</Note>

将成员访问权限设为 **只读**，这样成员便可查看和使用已固定的模板，但无法编辑。

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="显示成员访问权限已设为“只读”的邀请对话框" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

现在，该模板会以可选标签的形式显示在组织中每位成员的 Agent 输入框下方。要移除它，请打开同一菜单并选择 **从 Agent 输入框取消固定**。

<div id="control-template-access">
  ### 控制模板访问权限
</div>

置顶后，模板会对组织内的所有成员可见。如果需要更有针对性的分发，可以点击模板 App 上的 **Invite** 按钮，将其分享给指定的[群组或个人用户](/zh/teams/identity-and-access-management/groups-and-permissions)。这样既能限制哪些团队或人员可以查看并复刻该模板，又无需将其置顶到组织范围的输入框中。

<div id="what-happens-when-a-builder-selects-a-template">
  ## 构建者选择模板后会发生什么
</div>

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="模板在 Agent 输入框中显示为可选择的标签" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

当组织成员从 Agent 输入框中选择已固定的模板时：

1. **复刻**：基于该模板创建一个新 App，包含全部文件
2. **跳过规划**：Agent 跳过初始的规划对话，直接进入构建模式
3. **加载指令**：读取 `custom_instruction/instructions.md`，作为公司提供的指导注入 Agent 的系统 prompt
4. **发现 skills**：识别 `.agents/skills/` 中的 skills，并列入 Agent 的上下文，以便按需加载
5. **加载项目上下文**：读取 `replit.md` 并注入 Agent 的上下文 (若缺失则自动生成)
6. **继承配置**：`.replit` 文件、依赖项以及所有模板文件都会一并带入新 App

构建者可以立即向 Agent 提出自己的具体 requirements，而 Agent 将在模板设定的护栏范围内运行。

<div id="how-files-work-together">
  ## 文件如何协同运作
</div>

每个配置文件各司其职：

| 文件                                   | 用途              | Agent 何时读取        | Agent 是否可修改            |
| ------------------------------------ | --------------- | ----------------- | ---------------------- |
| `custom_instruction/instructions.md` | 组织标准和规则         | 始终 (注入系统 prompt)  | 否                      |
| `.agents/skills/*/SKILL.md`          | 专用工作流和模式        | 按需 (相关时)          | 是 (Agent 也可以创建 skill)  |
| `replit.md`                          | Project 概述和偏好设置 | 始终 (注入系统 prompt)  | 是 (Agent 会随项目发展持续更新)   |
| `.replit`                            | 运行时配置           | 配置 App 时          | 是                      |

**关键区别**：`custom_instruction/instructions.md` 是组织标准的静态权威来源。`replit.md` 是 Agent 随着项目发展持续维护的动态文档。skills 是供特定工作流按需参考的资料。

<div id="best-practices">
  ## 最佳实践
</div>

<div id="keep-instructions-focused">
  ### 让说明聚焦重点
</div>

将最重要的规范写入 `custom_instruction/instructions.md`。重点包括：

* 难以更改的决策 (架构、数据模型)
* 必须保持一致的规范 (组件使用方式、API 约定)
* 构建者可能不了解的标准 (内部库、团队约定)

避免包含变更日志、实现细节或经常变动的信息。

<div id="write-discoverable-skill-descriptions">
  ### 编写便于发现的 skill 描述
</div>

`SKILL.md` 前置元数据中的 `description` 字段可帮助 Agent 判断何时加载 skill。请编写与 skill 适用任务相符的描述：

```yaml theme={null}
# 推荐：说明适用场景
description: Use when building forms or handling user input. Provides validation patterns, error display conventions, and accessible form layouts.

# 不够好：过于笼统
description: Form utilities and helpers.
```

<div id="organize-skills-by-workflow">
  ### 按工作流组织 skills
</div>

围绕工作流而非技术类别来划分 skills：

| 方式        | 示例                                         |
| --------- | ------------------------------------------ |
| **按工作流**  | `build-a-form`、`connect-to-api`、`add-auth` |
| **按技术领域** | `react-utils`、`api-helpers`、`auth-config`  |

按工作流组织有助于 Agent 在恰当的时机找到合适的 skills。

<div id="iterate-on-your-template">
  ### 迭代你的模板
</div>

模板会在使用中不断完善。当你的团队开始基于模板构建后：

1. 留意 Agent 出错的规律，并将其补充到 `instructions.md` 中
2. 当 Agent 出色地解决了某个问题时，创建新的 skill，把解决方案沉淀下来
3. 随着技术栈演进，更新基础依赖和配置
4. 从模板创建一个新的 App 来测试改动，验证实际体验

<div id="template-updates-and-existing-apps">
  ### 模板更新与现有 App
</div>

对模板 App 所做的更改会体现在基于该模板创建的**新** App 中。此前从该模板分叉的现有 App 均为独立副本，不会获得更新。
