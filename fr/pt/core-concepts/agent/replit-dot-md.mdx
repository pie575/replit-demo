<div id="como-o-replitmd-funciona">
  ## Comment fonctionne `replit.md`
</div>

L&#39;Agent commence par créer un fichier `replit.md` dans le répertoire racine de votre projet en s&#39;appuyant sur des bonnes pratiques éprouvées. Ce fichier contient :

* Les informations de base du projet
* Les conventions de programmation recommandées
* Les préférences courantes pour ce type de projet

<YouTubeEmbed videoId="kYv525W-vaU" title="Customize how Replit Agent responds" />

Lorsque l&#39;Agent traite vos demandes, il lit automatiquement le fichier `replit.md` et se sert de son contenu pour :

* Comprendre l&#39;architecture et les conventions de votre projet
* Respecter vos conventions et votre style de programmation
* Utiliser les gestionnaires de paquets et les dépendances que vous avez indiqués

L&#39;Agent peut également mettre à jour le fichier `replit.md` au fur et à mesure qu&#39;il en apprend davantage sur le projet et apporte des modifications à votre application.

<Note>
  Vous pouvez modifier le fichier `replit.md` pour personnaliser le comportement de l&#39;Agent.
</Note>

<div id="configurando-o-replitmd">
  ## Configuration du fichier `replit.md`
</div>

<div id="gerao-automtica">
  ### Génération automatique
</div>

Lorsque vous créez un nouveau projet avec Agent, celui-ci génère automatiquement un fichier `replit.md` en s&#39;appuyant sur des bonnes pratiques éprouvées. Ce fichier apparaît dans le répertoire racine de votre projet et contient :

* Les informations de base du projet
* Les conventions de programmation recommandées
* Les préférences courantes pour ce type de projet

<div id="criao-manual">
  ### Création manuelle
</div>

Vous pouvez créer votre propre fichier `replit.md` en ajoutant un fichier nommé `replit.md` dans le répertoire racine du projet. Agent détectera et utilisera automatiquement ce fichier lors de vos prochaines conversations.

<Note>
  Le fichier `replit.md` doit se trouver dans le répertoire racine du projet pour fonctionner correctement.
</Note>

<div id="regenerando-o-replitmd">
  ### Régénérer le fichier `replit.md`
</div>

Si votre fichier `replit.md` est corrompu ou si vous souhaitez repartir de zéro :

1. Supprimez le fichier `replit.md` existant à la racine du projet
2. Démarrez une nouvelle conversation avec Agent
3. Agent génère automatiquement un nouveau fichier `replit.md` à partir de votre projet actuel

<div id="melhores-prticas">
  ## Bonnes pratiques
</div>

<div id="seja-especfico-e-claro">
  ### Soyez précis et clair
</div>

Rédigez des instructions claires et précises pour aider Agent à comprendre exactement ce que vous souhaitez :

```markdown theme={null}
## Style de programmation

- Utilisez TypeScript pour tous les nouveaux fichiers JavaScript
- Préférez les composants fonctionnels avec des hooks aux composants de classe
- Utilisez Tailwind CSS pour le style et évitez les styles en ligne
- Incluez toujours des types TypeScript pour les paramètres de fonction et les valeurs de retour
```

Pour en savoir plus sur la mise en forme des prompts, consultez le [guide d’ingénierie des prompts d’Anthropic](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags).

<div id="defina-preferncias-de-comunicao">
  ### Définissez vos préférences de communication
</div>

Indiquez à Agent comment vous souhaitez recevoir les informations et les mises à jour :

```markdown theme={null}
## Style de communication

- Avant d'implémenter des modifications, explique ce que tu vas faire et pourquoi
- Décompose les tâches complexes en étapes claires
- Demande des précisions si les exigences ne sont pas claires
- Fournis de brèves explications pour les décisions techniques
```

<div id="especifique-o-contexto-do-projeto">
  ### Précisez le contexte du projet
</div>

Aidez Agent à comprendre l’objectif et les contraintes de votre projet :

```markdown theme={null}
## Contexte du projet

Il s’agit d’une application de réseau social destinée aux amateurs de livres, où les utilisateurs peuvent :
- Créer des listes de lecture et partager des recommandations de livres
- Suivre d’autres lecteurs et voir leurs mises à jour
- Noter et rédiger des critiques de livres qu’ils ont lus

Public cible : lecteurs occasionnels de 25 à 45 ans
Stack technologique : frontend en React, backend en Node.js, base de données PostgreSQL
```

<div id="projeto-de-aplicativo-web">
  ### Projet d&#39;application web
</div>

```markdown theme={null}
# Directives du projet MyApp

## Vue d'ensemble du projet
Une application web de gestion de tâches développée avec React et Express.js.

## Préférences technologiques
- Frontend : React avec TypeScript, Tailwind CSS
- Backend : Express.js avec TypeScript
- Base de données : Neon PostgreSQL avec Drizzle ORM
- Gestionnaire de paquets : npm (ni yarn ni pnpm)

## Conventions de programmation
- Utilisez des composants fonctionnels avec des hooks
- Mettez en place des limites d'erreur appropriées
- Suivez les conventions d'API REST pour les points de terminaison
- Utilisez des noms descriptifs pour les variables et les fonctions

## Style de communication
- Expliquez votre approche avant d'effectuer des modifications
- Ajoutez des commentaires dans le code pour la logique complexe
- Posez des questions si les exigences sont ambiguës
```

<div id="projeto-de-anlise-de-dados">
  ### Projet d&#39;analyse de données
</div>

```markdown theme={null}
# Directives du projet d'analyse de données

## Contexte du projet
Analyse des données comportementales des clients afin d'identifier les tendances et les enseignements clés.

## Préférences technologiques
- Python avec Streamlit pour les applications web interactives
- pandas, numpy et matplotlib pour l'analyse de données

## Règles d'analyse
- Fournir une documentation claire pour chaque étape de l'analyse
- Créer des visualisations interactives avec des composants Streamlit
- Valider la qualité des données avant l'analyse
- Exporter les résultats au format CSV et les afficher dans des tableaux Streamlit

## Style de communication
- Expliquer les méthodes et les hypothèses statistiques
- Replacer les conclusions et les recommandations dans leur contexte
- Utiliser un langage clair et non technique pour les enseignements métier
- Créer des tableaux de bord interactifs pour les présentations aux parties prenantes
```

<div id="projeto-de-desenvolvimento-de-api">

```markdown theme={null}
# Directives de développement d'API

## Vue d'ensemble du projet
Création d'une API RESTful pour le backend d'une application mobile.

## Stack technique
- Node.js avec Express.js
- MongoDB avec Mongoose
- JWT pour l'authentification
- Gestionnaire de paquets : npm

## Normes d'API
- Utilisez des codes de statut HTTP sémantiques
- Mettez en place une validation d'entrée adéquate
- Appliquez une limitation de débit sur les points de terminaison publics
- Suivez la spécification OpenAPI pour la documentation

## Exigences de sécurité
- Validez toutes les entrées utilisateur
- Utilisez des variables d'environnement pour les données sensibles
- Mettez en place des politiques CORS adéquates
- Ajoutez la journalisation des requêtes pour le débogage

## Approche de test
- Écrivez des tests unitaires pour tous les points de terminaison
- Incluez des tests d'intégration pour les flux critiques
- Utilisez Jest comme framework de test
```

<div id="combinando-pesquisa-na-web-com-o-replitmd">
  ## Associer la recherche web au fichier `replit.md`
</div>

L&#39;Agent peut effectuer des recherches sur le web pour trouver des informations récentes, des bibliothèques et des solutions. En les associant au fichier `replit.md`, vous bénéficiez à la fois de connaissances à jour et de consignes propres à votre projet.

<div id="melhores-prticas-para-integrao-de-pesquisa-na-web">
  ### Bonnes pratiques pour l&#39;intégration de la recherche web
</div>

**Soyez précis sur ce que vous souhaitez qu&#39;Agent recherche :**

```markdown theme={null}
## Préférences de recherche
- Vérifiez toujours les versions les plus récentes des dépendances avant de proposer des mises à jour
- Recherchez les bonnes pratiques actuelles en matière d'implémentation de la sécurité
- Recherchez les techniques récentes d'optimisation des performances adaptées à notre stack
```

**Indiquez à Agent comment utiliser les connaissances externes :**

```markdown theme={null}
## Directives de recherche externe
- Lorsque vous suggérez de nouvelles bibliothèques, assurez-vous de la compatibilité avec notre stack existante
- Adaptez les exemples externes pour correspondre à nos conventions de programmation et à la structure du projet
- Vérifiez que les solutions suggérées fonctionnent avec notre environnement de publication
```

**Exemple d&#39;invite qui combine les deux :**
&quot;Recherche les techniques d&#39;optimisation des performances les plus récentes pour React 18 et implémente-les en suivant les modèles de composants définis dans `replit.md`&quot;

Cette approche fournit des solutions à la fois à jour et adaptées aux besoins spécifiques de votre projet.

<div id="limitaes">
  ## Limitations
</div>

<div id="limites-de-tamanho-e-contedo-do-arquivo">
  ### Limites de taille et de contenu du fichier
</div>

Bien qu&#39;il n&#39;existe pas de limite stricte de caractères pour le fichier `replit.md`, les fichiers très volumineux risquent de ne pas être traités intégralement. Veillez à garder le fichier `replit.md` concis et centré sur l&#39;essentiel pour obtenir de meilleurs résultats.

<div id="requisito-de-diretrio-raiz">
  ### Exigence relative au répertoire racine
</div>

Le fichier `replit.md` doit se trouver dans le répertoire racine du projet. Agent ne détecte pas automatiquement les fichiers situés dans des sous-répertoires.

<div id="escopo-do-contexto">
  ### Portée du contexte
</div>

Le fichier `replit.md` fournit du contexte aux conversations avec l’Agent, mais ne s’applique pas automatiquement aux autres outils d’IA.

3. **Partagez vos standards** : réutilisez les configurations `replit.md` efficaces dans des projets similaires
4. **Mesurez l&#39;efficacité** : observez la façon dont Agent suit vos directives et ajustez si nécessaire
