É uma sequência reutilizável e personalizável de etapas que pode ser executada dentro do seu replit app. Elas podem ser tão simples quanto executar `python main.py` ou tão complexas quanto executar um procedimento de várias etapas.

Exemplos de casos de uso:

* Executar vários serviços em paralelo (por exemplo, frontend + backend)
* Executar arquivos ou comandos sequencialmente (por exemplo, executar linter → executar testes, compilar → executar código)

Para começar a [criar workflows](#creating-workflows), acesse o painel Workflows usando o menu da barra lateral de ferramentas, ou pesquise pelo painel Workflows usando `Command + K`.

## Tipos de tarefas disponíveis

Atualmente, existem 3 tipos de tarefas disponíveis: `Execute Shell Command`, `Install Packages` e `Run Workflow`.

### Execute Shell Command

`Execute Shell Command` armazena um comando de shell e o executa usando o mesmo ambiente do painel Shell. Esse tipo de tarefa oferece uma ampla gama de casos de uso, desde executar arquivos individuais:

```text theme={null}
python main.py
```

até executar comandos complexos armazenados de consulta ao banco de dados:

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

### Install Packages

`Install Packages` utiliza o sistema de gerenciamento de dependências integrado do Replit, detectando automaticamente as dependências do seu projeto e instalando os pacotes necessários para ele. Consulte [Gerenciamento de dependências](/pt/features/project-setup/dependency-management#the-universal-package-manager) para mais detalhes sobre como o UPM identifica os pacotes a serem instalados para seu projeto internamente.

### Run Workflow

`Run Workflow` permite executar outro workflow a partir do workflow atual. Isso possibilita reutilizar workflows e combiná-los para criar workflows mais complexos.

Exemplo de caso de uso:

Ao usar esse tipo de tarefa para criar dependências entre workflows, você pode editar um workflow e fazer com que outros workflows que o referenciam usem automaticamente as alterações mais recentes. Observe que há um limite de profundidade definido para chamadas de workflows profundamente aninhadas.

## Modo de execução de Workflow

Os Workflows oferecem dois modos diferentes de execução: sequencial e paralelo.

### Sequencial

A execução sequencial executa cada tarefa na ordem definida, esperando que cada tarefa termine antes de passar para a próxima etapa, e interrompendo a execução da sequência se uma tarefa dentro do workflow falhar.

Um exemplo de uso desse modo é definir comandos que estão logicamente conectados, como comandos git para buscar as alterações mais recentes do seu branch principal e, em seguida, fazer rebase do seu branch atual sobre o branch principal:

### Paralelo

A execução paralela executa cada tarefa em paralelo, de forma que cada tarefa é iniciada e é executada de forma independente das outras tarefas dentro do workflow. Uma tarefa falhar não interrompe a execução das outras tarefas.

## Criando Workflows

Os Workflows podem ser criados usando o painel de workflows, clicando no botão `+ New Workflow`. Comece dando ao seu workflow um nome descritivo, escolha um modo de execução adequado e comece a adicionar tarefas. As tarefas podem ser reordenadas arrastando e soltando-as na ordem desejada.

## Atribuir Workflow ao botão Run

Um workflow também pode ser atribuído ao botão de execução para substituir o comportamento padrão do botão run (consulte [Configurar um Replit App](/pt/features/project-setup/configuration)). Para manter o comando de execução padrão configurado dentro do `.replit`, selecione a opção padrão "Run Replit App" no menu suspenso.

O workflow selecionado no menu suspenso ao lado do botão run será executado quando o botão run for clicado. Clique no workflow desejado no menu suspenso para alterar qual workflow deve ser executado pelo botão run.
