能否同时推进多项工作，是区分优秀构建者与卓越构建者的技能之一。即使你从未这样工作过，本页也会教你如何安全地同时构建多个功能。

<div id="agent">
  ## 与 Agent 协作的全新方式
</div>

到目前为止，你与 Agent 的合作方式可能更像身边坐着一位搭档：你提问、观察、回应。而并行构建则是另一种关系。你把某个功能作为**任务 (task) **交给 Agent，它便会在后台完成构建，而你可以腾出手去做别的事。

其实在日常生活里，你早就是这么做事的。你不会站在洗衣机前干等它洗完，而是把衣服放进去启动，然后去做饭。任务也是同样的道理：启动一个任务，在它运行期间再启动另一个、检查其他内容，或者继续在主对话中与 Agent 聊天。

这也改变了你的角色。你不再是盯着单个构建过程的乘客，而是统筹多个构建的导演。

<div id="section">
  ## 任务运行期间，你的应用是安全的
</div>

大家最先问的问题往往是：*在我没盯着的时候，后台任务会不会把我的应用搞坏？*

不会。每个任务都在项目的独立**副本**上进行。在你审阅任务成果并选择应用之前，你的应用不会有任何更改。

每个任务还拥有自己的 Agent，并继承项目的完整上下文，因此你无需反复解释同样的内容。任务之间互相独立，所以第一个任务还在运行时，你就可以立刻启动下一个任务。

<div id="section-2">
  ## 并行构建
</div>

<Steps>
  <Step title="打开项目并固定侧边栏">
    从默认的 Build 布局开始：左侧是 Agent 聊天，右侧是 Preview。展开并固定全局侧边栏，让项目的任务控件和状态更新始终可见。
  </Step>

  <Step title="在项目中创建任务">
    在侧边栏中展开项目，然后选择名称旁边的 **+** 按钮。这是启动后台任务最快的方式。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-new-task-sidebar-9a67150bc66c.jpg" width="700" height="578" data-path="images/replitai/build-in-parallel-new-task-sidebar.jpg" />
    </Frame>

    创建任务的另一种方式是将鼠标悬停在项目旁边的看板图标上，然后选择 **New task**。你也可以从同一菜单打开看板，使用底部的 **Plan a new task…**。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-board-shortcuts-267b99f4d424.jpg" alt="包含 Board、Open、New task 操作的项目看板快捷菜单" width="720" height="420" data-path="images/replitai/build-in-parallel-board-shortcuts.jpg" />
    </Frame>
  </Step>

  <Step title="描述一个明确的预期结果">
    为任务设定一个明确的目标结果，然后发送。Agent 会先梳理项目，并在不改动主版本的前提下提出计划。
  </Step>

  <Step title="审查并批准计划">
    请确认范围、实现步骤、完成标准、相关文件以及 agent 模式。只有当计划符合你的意图时,才选择 **Start building**。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-plan-review-2a2e1322ab59.jpg" alt="等待 Start building 批准的建议后台任务计划" width="1393" height="868" data-path="images/replitai/build-in-parallel-plan-review.jpg" />
    </Frame>

    选择 **Start building** 后,任务会在后台启动,你在主版本中的工作则可照常继续。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-task-active-c991ee7b52ee.jpg" alt="已开始构建的已批准任务,任务对话显示在 Preview 旁边" width="1393" height="868" data-path="images/replitai/build-in-parallel-task-active.jpg" />
    </Frame>
  </Step>

  <Step title="创建并批准其余任务">
    每次重复一遍这个过程。为每个独立任务分别指定各自的产出结果。对于存在依赖关系的任务，请围绕它所需的功能或项目结构来描述，让 Agent 能够识别出前置任务。

    如果新任务依赖其他任务尚在构建中的内容，Agent 会在计划中标明前置任务，并将新任务安排在该任务完成并获批之后再启动。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-dependent-plan-232d5472df15.jpg" alt="标明前置任务并安排在其完成后启动的 Agent 计划" width="1393" height="868" data-path="images/replitai/build-in-parallel-dependent-plan.jpg" />
    </Frame>
  </Step>

  <Step title="让 Agent 管理任务计划">
    打开看板即可查看 **Drafts**、**Active**、**Ready** 和 **Done**。彼此独立的任务会在有空闲资源时运行；存在依赖关系的任务会显示被什么阻塞，并保持等待，直到前置任务完成应用。
  </Step>

  <Step title="查看并应用已准备好的任务">
    打开每个 Ready 任务，查看输出和测试结果，并在 Preview 中试用相应功能。如果符合预期，请选择 **Apply**。应用前置任务后，依赖它的任务会自动解锁。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-board-ready-71e960b13e34.jpg" alt="任务看板中已完成的前置任务位于 Ready，并显示 Apply 和 Review 操作" width="650" height="270" data-path="images/replitai/build-in-parallel-board-ready.jpg" />
    </Frame>

    应用前置任务后，依赖它的任务会自动移至 Active。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-board-unlocked-0ffa3861a9f2.jpg" alt="应用第一个任务后，依赖任务自动激活的任务看板" width="1393" height="868" data-path="images/replitai/build-in-parallel-board-unlocked.jpg" />
    </Frame>
  </Step>

  <Step title="检查主版本">
    每次应用更改后，请返回默认的 Build 界面。在 Preview 中试用主版本的效果，并在 Agent 聊天中查看实现摘要、检查项、警告，以及是否还有待处理的事项。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-verify-main-version-62016529b118.jpg" alt="默认 Build 界面，主咖啡馆网站 Preview 旁显示 Agent 聊天" width="1393" height="868" data-path="images/replitai/build-in-parallel-verify-main-version.jpg" />
    </Frame>
  </Step>
</Steps>

重复“检查、应用、确认”这一循环，直到所有已批准的任务都进入 **Done**。

<Frame>
  <img src="/assets/mirror/build-in-parallel-board-done-a4ef1c2f1e59.jpg" alt="四个已批准的任务全部位于 Done 中的任务看板" width="1393" height="868" data-path="images/replitai/build-in-parallel-board-done.jpg" />
</Frame>

<div id="section-3">
  ## 实际示例：四项功能并行推进
</div>

设想一个咖啡馆开业网站。你想重点添加以下四项改进：

* 用于提升无障碍性的跳过链接和稳定的地标 ID
* 利用这些 ID 的简洁分区导航
* 基于无障碍性改进的新闻通讯表单反馈
* 仅修改文档 head 的 Open Graph 元数据

关键在于确定各项任务之间的依赖关系。元数据任务只涉及文档 head，与另外三项任务没有交集，因此可以立即执行。导航和新闻通讯任务都依赖于地标任务创建的稳定 ID 和页面结构，因此需要等待该任务完成——按这种结构描述后，Agent 会自行识别前置任务。

你无需手动跟踪此计划：被阻塞的卡片会在看板上标明前置任务，而无关的任务会以 Active 状态执行。

<div id="section-4">
  ## 把任务拆小
</div>

实现并行构建的关键技巧，就是把功能拆分成小而独立的任务。小任务完成得更快、更容易审查，彼此干扰的可能性也更低。

一条实用的判断标准：**如果任务描述里出现了&quot;并且&quot;,就考虑拆分。**

* 好的例子:&quot;添加活动页面&quot;&quot;添加咨询表单&quot;
* 过大的例子:&quot;添加活动、注册、邮件通知以及管理后台界面&quot;

大任务本身并没有错,但它会让一个 Agent 按顺序逐项处理。拆成四个小任务,Agent 才有机会同时推进。

不妨自己试着判断一下:下列哪些可以并行执行?

1. 添加深色模式切换
2. 添加客户评价板块
3. 让客户可以回复评价
4. 将应用翻译成法语

<Accordion title="答案">
  任务 1、2、4 彼此独立,可以同时执行。任务 3 依赖任务 2:评价还不存在,自然也就没有可回复的对象。你不必自己察觉这一点,Agent 会检测依赖关系,并替你安排这两个任务的先后顺序。
</Accordion>

<div id="section-5">
  ## 安全地应用更改
</div>

每个任务都在项目的独立副本中运行。应用某个任务后,主版本会随之更新,但其他任务可能仍基于更新前的版本。

<Tip>
  应用多个任务的更改时,Agent 会自动处理冲突。每次应用后,请检查生成的应用。如果发现异常,可在任务线程或主对话中要求 Agent 进行修正。
</Tip>

如果两个任务修改了同一个文件,在选择 **Apply** 后,Ready 卡片上可能会短暂显示 **Resolving conflicts**。请等待 Agent 完成合并并重新验证结果,你无需手动解决文件冲突。

<div id="section-6">
  ## 像经理一样审查
</div>

并行构建会让你成为经理，而经理常犯的错误就是批准未经检查的任务。你需要遵循一个简单的循环：一次只处理一项：

<Steps>
  <Step title="测试任务成果">
    打开已完成的任务并试用其功能。像用户一样点击体验。
  </Step>

  <Step title="应用">
    如果满意，就将更改应用到主应用中。
  </Step>

  <Step title="检查主版本">
    确认应用后的功能能与应用中已有的更改良好配合。
  </Step>

  <Step title="重复">
    测试并应用下一个准备就绪的任务，直到所有任务都已整合。
  </Step>
</Steps>

绝不要一次性全部批准。如果一次应用三个未经审查的功能，出了问题时，你就会面对三个嫌疑对象。

<div id="section-7">
  ## 何时该按顺序推进
</div>

并行构建是一种手段，而非规则。遇到以下情况，请在主对话中一次只做一件事：

* **两个想法涉及同一个页面时。**&quot;重新设计主页&quot;和&quot;修改导航&quot;会相互冲突，请依次处理。
* **还在探索方案时。**在设计任务中，一次尝试的结果往往会改变你接下来想要的东西。探索是一场对话，而不是下达任务指令。
* **无法用一句话说清任务时。**如果说不简洁，说明它还没到可以交出去的时候。

<div id="section-8">
  ## 在限制范围内工作
</div>

你的方案决定了可以同时运行的后台任务数量。多出的任务会进入队列，等有空闲槽位时再启动。当前限额请参阅[任务系统](/zh/ko/core-concepts/agent/task-system#availability)。

注意力也是一种限制。先从两个任务开始，等你觉得审查起来游刃有余，再尝试三个。你不必监督每一个步骤，但在应用之前必须测试每一份结果。
