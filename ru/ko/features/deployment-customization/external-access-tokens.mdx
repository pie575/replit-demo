---
title: "Внешние токены доступа"
description: "Позволяют CI-конвейерам, вебхукам и другим автоматизированным сервисам обращаться к приватным Replit App без входа в систему."
---

Внешний токен доступа — это bearer-токен, который вы выпускаете для конкретного Replit App.
Он позволяет автоматизированным сервисам — CI-конвейерам, вебхукам, пингам проверки состояния,
ботам Slack и внутренним скриптам — обращаться к приложению, даже если оно закрыто
[приватным URL для разработки](/ru/ko/features/publishing/private-deployments) или
[приватным деплоем](/ru/ko/features/publishing/private-deployments).

Обращайтесь с каждым токеном как с паролем. Любой, у кого есть токен, получает доступ
к приложению, пока токен не истечёт или не будет отозван.

<Note>
  Внешние токены доступа доступны, если для деплоя выбран приватный доступ.
  Подключение на уровне рабочего пространства не требуется. В рабочих пространствах Enterprise
  управлять токенами могут только администраторы рабочего пространства.
</Note>

<div id="section">
  ## Когда использовать токен
</div>

Используйте внешний токен доступа, когда к приватному Replit App должно
обращаться что-то *за пределами* браузера. Типичные сценарии:

* Рабочий процесс GitHub Actions, который при каждом коммите запускает дымовые тесты по URL разработки.
* Мониторинг доступности (Better Stack, Pingdom, UptimeRobot), который обращается к
  эндпоинту проверки состояния опубликованного приложения.
* Приёмник вебхуков, отправляющий POST-запросы в приватный деплой — Stripe, Slack, GitHub.
* Вызовы `curl` или `fetch`, которые участник команды выполняет со своего компьютера во время отладки.

Внешние токены доступа рассчитаны на **API-трафик**, а не на открытие
страниц интерфейса в браузере. Одностраничные приложения (Vite, Next.js и т. д.)
подгружают JavaScript-бандлы последующими запросами, в которые токен не
попадает, поэтому такие запросы завершаются ошибкой. Если нужно
поработать с интерфейсом вручную, просто войдите обычным способом.

<div id="section-2">
  ## Среда токена
</div>

Каждый токен привязан к одной среде.

| Среда         | Где действует                                                               | Для чего использовать                               |
| :------------ | :-------------------------------------------------------------------------- | :-------------------------------------------------- |
| `Development` | URL разработки в рабочем пространстве приложения (`*.replit.dev`)           | Для доступа к запущенному Repl во время разработки  |
| `Production`  | Опубликованный деплой приложения (`*.replit.app` и пользовательские домены) | Для доступа к приватному деплою из внешних сервисов |

Токен `Production` сохраняется после повторной публикации, в том числе при публикации новой версии.
Replit отзывает токен в следующих случаях:

* Вы снимаете деплой с публикации.
* Вы удаляете деплой.
* Вы меняете доступ к приложению с приватного на публичный.

Токен также перестаёт работать, если истёк его срок действия или вы отозвали его вручную.

<div id="section-3">
  ## Создание внешнего токена доступа
</div>

<Steps>
  <Step>
    Откройте приложение, к которому хотите предоставить внешний доступ, и откройте инструмент **Публикация**.
  </Step>

  <Step>
    Выберите **Настроить параметры**, чтобы развернуть параметры повторного деплоя.
  </Step>

  <Step>
    В разделе **Безопасность** найдите **Внешние токены доступа**.
  </Step>

  <Step>
    Выберите **Создать токен доступа** и укажите следующее.

    * **Метка** (необязательно): короткое название, например `CI` или
      `Stripe webhook`, чтобы позже можно было легко распознать токен. Можно ввести до 120 символов.
    * **Среда**: выберите `Development` или `Production` в зависимости от того,
      где сервис, выполняющий запрос, должен получать доступ к приложению.
    * **Срок действия**: выберите срок действия: `1 час`, `24 часа`, `7 дней`, `30 дней`, `3 месяца`, `1 год`
      или `5 лет`. Выберите минимальный срок, подходящий для вашей задачи.
      Вариант «Без срока действия» недоступен.
  </Step>

  <Step>
    Выберите **Создать**.
  </Step>
</Steps>

Replit показывает токен **только один раз**. Скопируйте его сейчас. После закрытия
диалогового окна просмотреть токен повторно будет нельзя. Если вы потеряли токен,
отзовите его и создайте новый.

На экране токена доступны два варианта копирования.

* **Копировать параметр запроса** — копирует
  `?project-protection-bypass=<token>`, который можно добавить к URL. Это удобно
  для быстрой проверки с помощью `curl`.
* **Копировать только токен** — копирует сам токен, который можно отправить
  в заголовке `Authorization: Bearer`.

<Info>
  При создании первого токена внешний доступ к приложению автоматически включается,
  если он ещё не был включён. Без защиты токену нечего обходить.
</Info>

<div id="section-4">
  ## Использование токена
</div>

Передавать токен можно одним из двух способов.

<div id="authorization">
  ### Заголовок Authorization (рекомендуется)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

Этот способ подходит практически для всех случаев: вебхуков, CI-скриптов,
вызовов между бэкендами. Токен не попадает в логи, где записывается URL, и не
сохраняется в истории браузера.

<div id="section-5">
  ### Параметры запроса
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

Используйте способ с параметром запроса только в том случае, если задать заголовки невозможно — например, если сервис принимает лишь URL. URL с токеном легко попадает в логи прокси, историю командной оболочки и на скриншоты, поэтому по возможности всегда отдавайте предпочтение способу с заголовком.

<div id="section-6">
  ## Управление существующими токенами
</div>

В разделе **Внешние токены доступа** перечислены все токены, созданные для приложения, — от новых к старым, — с указанием метки, среды, даты создания, срока действия и статуса отзыва.
Полное значение токена показывается только при создании, поэтому в каждой строке выводятся последние несколько символов токена — чтобы вы могли отличать их друг от друга.

Вам видны только те токены, которые создали *вы сами*. Даже если приложение принадлежит вам, токены других соавторов доступны только им.

<div id="section-7">
  ## Отзыв токенов
</div>

Отзывайте токен сразу же, как только он перестал быть нужен или возникло подозрение на утечку. Чтобы отозвать токен,
выполните следующие шаги.

<Steps>
  <Step>
    В настройках публикации приложения откройте раздел **Внешние токены доступа**.
  </Step>

  <Step>
    Найдите токен в списке и нажмите значок корзины.
  </Step>

  <Step>
    Подтвердите отзыв.
  </Step>
</Steps>

Отзыв выполняется **мгновенно и необратимо**. Трафик, использующий этот токен,
начнёт отклоняться уже через несколько секунд. Если доступ понадобится снова, выпустите новый
токен.

Вы можете отзывать только те токены, которые создали сами. При удалении соавтора из рабочего пространства
выпущенные им токены для соответствующих приложений отзываются автоматически.

<div id="section-8">
  ## Безопасное хранение токенов
</div>

Внешние токены доступа — это учётные данные. Обращайтесь с ними так же
осторожно, как с API-ключами или паролями.

<div id="section-9">
  ### Что следует делать
</div>

* **Храните токены в менеджере секретов** — например, в секретах GitHub Actions, хранилище
  вашего CI-провайдера, хранилище секретов облачного провайдера или менеджере
  паролей. Никогда не коммитьте их в репозиторий.
* По возможности **используйте короткий срок действия**. Токен на 7 дней для разовой
  интеграции безопаснее забытого токена на 5 лет.
* **Добавляйте метки ко всем токенам.** Так позже вы сможете понять, для чего нужен токен
  и используется ли он до сих пор. Токены без меток первыми утекают
  и последними отзываются.
* **Выпускайте отдельные токены для каждого потребителя.** Создавайте по одному для каждой задачи CI, каждого источника вебхуков
  и каждой проверки доступности. Если что-то утечёт или поставщик больше не нужен,
  достаточно будет отозвать только этот токен.
* Чтобы токены не утекали через журналы URL, историю браузера и заголовки referer,
  предпочитайте **заголовок `Authorization`** параметрам запроса.
* Если токен мог быть скомпрометирован — например, из-за утечки журналов, коммитов в публичных репозиториях, демонстрации экрана или ноутбука уволившегося сотрудника, —
  **немедленно отзовите его**. Отзыв вступает в силу сразу, после чего выпустите
  заменяющий токен.

<div id="section-10">
  ### Чего делать не следует
</div>

* **Не передавайте токены другим участникам команды или сервисам.** Если две
  системы используют один токен, отозвать его для одной из них, не нарушив работу другой, невозможно.
* **Не вставляйте токены в чаты, письма, скриншоты и трекеры задач.** Такие
  каналы сохраняют, индексируют и распространяют данные самым неожиданным образом.
* **Не размещайте токены в клиентском коде** — в браузерных и мобильных приложениях,
  десктопных бинарных файлах и т. д. Всё, что попадает на устройство пользователя, следует считать
  общедоступным.
* **Не используйте токены для браузерных сессий.** Токены подходят для вызовов
  API, но не для загрузки SPA во вкладке браузера.
  В этом случае используйте обычный вход в Replit.
* **Не выбирайте срок действия 5 лет по умолчанию.** Задавайте срок действия исходя из того,
  как долго потребителю действительно нужен доступ.

<div id="section-11">
  ## Устранение неполадок
</div>

<Accordion title="Токен продакшена внезапно перестал работать">
  Токены продакшена остаются действительными при обычной повторной публикации.
  Проверьте, не истёк ли токен и не был ли он отозван. Также проверьте, не отменяли ли
  вы публикацию деплоя, не удаляли ли его и не меняли ли приложение с приватного на
  публичное. Если у приложения больше нет приватного деплоя, снова опубликуйте его как
  приватное. Затем создайте новый токен. Истёкшие или отозванные токены невозможно
  восстановить.
</Accordion>

<Accordion title="Токен работает в `curl`, но в браузере по-прежнему отображается страница входа">
  Внешние токены доступа предназначены для API-трафика, а не для сеансов браузера.
  Когда одностраничное приложение загружается в браузере, начальный HTML-запрос может
  передать токен через параметры запроса, однако последующие запросы к JavaScript-бандлам,
  CSS и API не содержат токен и поэтому отклоняются. Чтобы интерактивно
  работать с приложением, войдите в Replit обычным способом.
</Accordion>

<Accordion title="Я потерял токен — можно ли увидеть его снова?">
  Нет. Replit отображает токен только один раз — при его создании. В списке
  отображаются метаданные (метка, среда, срок действия, последние несколько символов),
  но полное значение токена не показывается. Если вы потеряли токен, отзовите его и
  создайте новый.
</Accordion>
