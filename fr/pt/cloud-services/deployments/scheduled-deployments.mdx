Définissez une opération en ligne de commande et une planification : Replit l&#39;exécute automatiquement
dans l&#39;environnement de votre Replit App. Une fois terminée, l&#39;opération s&#39;arrête jusqu&#39;à la prochaine exécution planifiée.

Les déploiements planifiés, également appelés tâches planifiées, conviennent particulièrement aux tâches périodiques
comme la vérification de statuts, l&#39;envoi de notifications ou le lancement de sauvegardes. Ils ne sont pas conçus
pour des tâches continues ou de longue durée, telles que les applications web.

<div id="recursos">
  ## Fonctionnalités
</div>

Les déploiements planifiés offrent les fonctionnalités suivantes :

* **Planification automatique** : planifiez votre tâche et Replit l&#39;exécute automatiquement.
* **Planification en langage naturel** : saisissez une description de la planification en langage courant, et l&#39;IA la convertit en expression cron, un format de planification lisible par une machine.
* **Alertes d&#39;erreur** : recevez une notification lorsque votre tâche planifiée échoue.
* **Surveillance** : consultez les logs et suivez l&#39;état de votre déploiement planifié.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder aux déploiements planifiés depuis l&#39;outil Publishing du Project Editor.

Les sections suivantes vous guident dans la configuration et la gestion de vos déploiements planifiés.

<Accordion title="Comment accéder aux déploiements planifiés">
  Dans le **Tool dock** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="All tools icon" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Publishing icon" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Scheduled**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="magnifying glass icon" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe située en haut pour ouvrir l&#39;outil de recherche
  2. Saisissez « Publishing » pour retrouver l&#39;outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l&#39;option **Scheduled**, puis **Set up your published app**.
</Accordion>

<div id="configurao-da-mquina">
  ### Configuration de la machine
</div>

Ce champ vous permet de consulter le processeur, la RAM et le coût d&#39;utilisation de la machine pour votre déploiement planifié.

<div id="campos-de-agendamento">
  ### Champs de planification
</div>

* **Schedule description** : saisissez une description de la planification en langage naturel, par exemple « Tous les lundis et mercredis à 10 h » ou « Le 24 mars 2024 à 15 h ».
* **Cron expression** : vous pouvez également saisir une chaîne de caractères lisible par machine qui définit le moment où la tâche doit s’exécuter.
* **Timezone selection** : sélectionnez le fuseau horaire de la planification dans le menu déroulant.

Lorsque vous saisissez une valeur dans le champ **Schedule description** ou **Cron expression**, l’IA la convertit automatiquement au format correspondant.
Pour en savoir plus sur les expressions cron, consultez la page Wikipédia consacrée à <a href="https://en.wikipedia.org/wiki/Cron" target="_blank">cron</a>.

<div id="tempo-limite-do-job">
  ### Délai d’exécution maximal de la tâche
</div>

Saisissez la durée maximale pendant laquelle la tâche peut s’exécuter avant que le planificateur ne l’arrête. Sélectionnez « minutes » ou « hours » dans le menu déroulant de l’unité de temps.

<Tip>
  Les tâches planifiées peuvent s’exécuter plus lentement que dans le Project Editor. Testez le
  déploiement et ajustez le délai d’exécution maximal en conséquence.
</Tip>

<div id="build-command">
  ### Build command
</div>

Dans le champ **Build command**, saisissez la commande Shell qui compile ou configure votre app avant d’exécuter le Run command.
Par exemple, pour installer les dépendances de votre app Node.js, vous pouvez ajouter la commande de build `npm install`.

Le temps d’exécution de la commande de build n’est pas comptabilisé dans votre utilisation et n’est pas déduit du délai maximal de la tâche.

<div id="run-command">
  ### Run command
</div>

Saisissez la commande shell qui démarre votre tâche dans le champ **Run command**.
Par exemple, pour exécuter un script Python, vous pouvez indiquer `python app.py` comme run command.

Le planificateur de Replit exécute la run command aux horaires planifiés.
La durée d&#39;exécution de la commande est décomptée de votre utilisation. Pour plus d&#39;informations sur la facturation à l&#39;usage,
consultez la [section déploiement planifié](/fr/pt/billing/deployment-pricing#scheduled-deployments) de notre documentation sur les tarifs.

<div id="secrets-do-deployment">
  ### Secrets de déploiement
</div>

Sélectionnez **Add deployment secret** pour ajouter les variables d’environnement ou les secrets dont votre app a besoin pour s’exécuter en toute sécurité.

Si votre Replit App contient des variables d’environnement ou des secrets, l’outil Publishing les ajoute automatiquement à la liste.

Pour modifier la valeur d’une variable d’environnement, sélectionnez

<img class="icon-svg" src="/assets/mirror/vertical-dots-032f1c99d22e.svg" width="16" height="16" alt="icône représentant trois points verticaux" data-path="images/icons/vertical-dots.svg" /> les trois points verticaux, puis choisissez **Edit** dans le menu. Le gestionnaire de Secrets applique la
valeur uniquement au déploiement et ne modifie pas les variables d’environnement définies dans votre
Replit App.
