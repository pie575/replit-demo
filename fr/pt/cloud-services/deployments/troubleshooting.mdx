Cette page présente les problèmes courants que vous pouvez rencontrer lors de la publication de votre app et explique comment les résoudre.

<div id="problemas-comuns-de-publicao">
  ## Problèmes courants de publication
</div>

<div id="seu-app-no-funciona-no-project-editor">
  ### Votre app ne fonctionne pas dans le Project Editor
</div>

Avant de publier, vérifiez que votre app s&#39;exécute correctement. Sélectionnez le bouton **Run** en haut du Project Editor. Si le Preview n&#39;affiche pas votre app avec une URL `replit.dev`, c&#39;est que votre code présente un problème à corriger avant de pouvoir publier.

<div id="seu-programa-encerra-em-vez-de-rodar-continuamente">
  ### Votre programme s’arrête au lieu de s’exécuter en continu
</div>

Les applications publiées doivent exécuter votre programme en continu. Si votre programme exécute une fonction puis s’arrête, la plateforme le redémarre automatiquement. Assurez-vous que votre application lance un processus de longue durée, tel qu’un serveur web.

<div id="seu-servidor-no-est-ouvindo-em-0000">
  ### Votre serveur n’écoute pas sur `0.0.0.0`
</div>

Si vous exécutez un serveur web, les déploiements peuvent détecter automatiquement le port utilisé par le serveur, mais uniquement s’il écoute sur `0.0.0.0`. Une écoute sur `localhost` ou `127.0.0.1` ne fonctionne pas.

<div id="sua-aplicao-tem-erros">
  ### Votre application comporte des erreurs
</div>

Consultez l’onglet **Logs** en haut du panneau **Publishing** pour voir la sortie de votre application. Recherchez des traces de pile ou des exceptions : elles indiquent des erreurs de code, comme des variables non initialisées ou des paquets manquants.

<div id="seus-comandos-de-execuo-ou-build-esto-incorretos">
  ### Vos commandes d’exécution ou de compilation sont incorrectes
</div>

Les erreurs courantes incluent des fautes de frappe, des options incorrectes ou l’indication du mauvais fichier ou répertoire. Vérifiez vos commandes dans le panneau **Publishing** et corrigez les éventuels problèmes.

<div id="seus-secrets-no-esto-configurados-para-publicao">
  ### Vos Secrets ne sont pas configurés pour la publication
</div>

Les Secrets que vous définissez dans le Project Editor ne sont pas automatiquement transférés vers votre app publiée. Ajoutez tous les Secrets de production et les variables d’environnement dans le panneau **Publishing**. Des Secrets manquants peuvent empêcher l’app de démarrer et provoquer des erreurs liées à des valeurs non définies.

<div id="seu-replit-app-excede-o-limite-de-tamanho">
  ### Votre Replit App dépasse la limite de taille
</div>

Les VM réservées et les déploiements Autoscale prennent en charge les Replit Apps d’une taille maximale de 8 Go. Les Static Deployments prennent en charge une taille maximale de 1 Go. Pour réduire la taille de votre app, supprimez les fichiers inutiles ou utilisez un stockage de données externe, comme la [SQL Database](/fr/pt/features/data-and-storage/sql-database/).

<div id="sua-pgina-inicial-demora-muito-para-carregar">
  ### Votre page d’accueil met trop de temps à charger
</div>

Avant de marquer votre app publiée comme active, une vérification d’intégrité envoie une requête HTTP à votre app. Si votre page d’accueil met plus de cinq secondes à répondre, la vérification expire et la publication échoue à la dernière étape.

<div id="sua-configurao-de-porta-est-incorreta">
  ### La configuration de votre port est incorrecte
</div>

Si vous avez des [ports spécifiés dans la configuration `.replit`](/fr/pt/references/configuration/configuration), la détection automatique des ports est désactivée. Vous devez spécifier un port avec `externalPort` défini sur `80` pour terminer l’étape de promotion. Vérifiez que le serveur écoute sur la `localPort` spécifiée.

<div id="seu-deployment-esttico-no-est-funcionando">
  ### Votre déploiement statique ne fonctionne pas
</div>

Ce problème survient généralement lorsque vous indiquez un répertoire public incorrect ou que votre app n’est pas adaptée aux Static Deployments. Un déploiement statique sert des fichiers statiques tels que des fichiers HTML, CSS et JavaScript.

Si votre app comporte une logique côté serveur, elle n’est pas adaptée aux Static Deployments. Remplacez le type de déploiement par Autoscale dans le panneau **Publishing**.

<Warning>
  Le système de fichiers des apps publiées n’est pas persistant et est réinitialisé chaque fois que vous publiez. Pour assurer la persistance des données, utilisez une base de données telle que [SQL Database](/fr/pt/features/data-and-storage/sql-database).
</Warning>

<div id="problemas-de-acesso-com-urls-replitapp-e-replitdev">
  ## Problèmes d’accès aux URL `replit.app` et `replit.dev`
</div>

Si vous avez des difficultés à accéder à votre app via son domaine `replit.app` ou `replit.dev`, que ce soit dans Preview ou dans une fenêtre de navigateur distincte, des filtres web ou des restrictions réseau peuvent en être la cause.

Essayez d’utiliser des résolveurs DNS publics, comme Google DNS (`8.8.8.8`) ou Cloudflare DNS (`1.1.1.1`), pour résoudre ces problèmes.

<div id="alterar-as-configuraes-de-dns">
  ### Modifier les paramètres DNS
</div>

<Tabs>
  <Tab title="Windows">
    1. Ouvrez le **Panneau de configuration**.
    2. Accédez au **Centre Réseau et partage**.
    3. Sélectionnez **Modifier les paramètres de la carte** dans le volet de gauche.
    4. Cliquez avec le bouton droit sur votre connexion réseau active, puis sélectionnez **Propriétés**.
    5. Sélectionnez **Protocole Internet version 4 (TCP/IPv4)**, puis **Propriétés**.
    6. Choisissez **Utiliser l’adresse de serveur DNS suivante**.
    7. Saisissez l’adresse IP d’un serveur DNS public (par exemple, `8.8.8.8` pour Google DNS ou `1.1.1.1` pour Cloudflare DNS) dans les champs **Serveur DNS préféré** et **Serveur DNS auxiliaire**.
    8. Sélectionnez **OK** pour enregistrer les modifications.

    Pour des instructions plus détaillées, consultez le [guide de configuration DNS de Microsoft](https://support.microsoft.com/en-us/windows/change-tcp-ip-settings-bd0a07af-15f5-cd6a-363f-ca2b6f391ace).
  </Tab>

  <Tab title="macOS">
    1. Ouvrez les **Préférences Système**.
    2. Sélectionnez **Réseau**.
    3. Sélectionnez votre connexion réseau active dans le volet de gauche.
    4. Sélectionnez **Avancé** dans l’angle inférieur droit.
    5. Accédez à l’onglet **DNS**.
    6. Sélectionnez le bouton **+** pour ajouter un serveur DNS.
    7. Saisissez l’adresse IP d’un serveur DNS public (par exemple, `8.8.8.8` pour Google DNS ou `1.1.1.1` pour Cloudflare DNS).
    8. Sélectionnez **OK**, puis **Appliquer**.

    Pour des instructions plus détaillées, consultez le [guide de configuration DNS d’Apple](https://support.apple.com/guide/mac-help/change-dns-settings-on-mac-mh14127/mac).
  </Tab>

  <Tab title="Linux">
    1. Modifiez le fichier `/etc/resolv.conf` pour ajouter des serveurs DNS publics. La méthode exacte varie selon la distribution.
    2. Ajoutez les lignes suivantes :

    ```
    nameserver 8.8.8.8
    nameserver 1.1.1.1
    ```

    Pour plus d’informations sur la configuration DNS dans différentes distributions, consultez le [guide de configuration réseau du wiki Debian](https://wiki.debian.org/NetworkConfiguration#Defining_the_.28DNS.29_Nameservers).
  </Tab>
</Tabs>

<div id="limpar-o-cache-dns">
  ### Vider le cache DNS
</div>

Après avoir modifié les paramètres DNS, videz le cache DNS pour appliquer la nouvelle configuration :

* **Windows** : exécutez `ipconfig /flushdns` dans l’Invite de commandes
* **macOS et Linux** : exécutez `sudo systemctl restart NetworkManager` dans le Terminal (la commande exacte peut varier selon la distribution)

<Note>
  Afin d’améliorer les performances régionales et la stabilité, les URL `replit.dev` de vos
  Replit Apps peuvent occasionnellement changer lors de migrations de cluster. Une fois la
  migration terminée, les URL restent stables pendant environ un an, sauf si vous demandez
  explicitement un changement de région.
</Note>

<div id="publicar-uma-aplicao-streamlit">
  ## Publier une application Streamlit
</div>

Les applications Streamlit sont compatibles avec les déploiements Replit. Le plus simple pour démarrer est d&#39;utiliser le [template Streamlit](https://replit.com/@replit/Streamlit?v=1).

Vous pouvez également définir la commande d&#39;exécution pour la publication comme suit :

```bash theme={null}
streamlit run --server.address 0.0.0.0 --server.headless true --server.enableCORS=false --server.enableWebsocketCompression=false main.py
```

Si votre application utilise un autre fichier d&#39;entrée, remplacez `main.py` par le nom de ce fichier.
