Le panneau Git de Replit offre une interface visuelle pour les opérations Git, ce qui vous évite de passer par les commandes Git en ligne de commande. Cette fonctionnalité rend le contrôle de version accessible aux débutants tout en restant suffisamment puissante pour les développeurs expérimentés.

<div id="section">
  ## Fonctionnalités
</div>

Le panneau Git offre des fonctionnalités complètes de contrôle de version directement dans le Project Editor, avec une interface conviviale qui simplifie les opérations Git complexes.

* **Gestion des dépôts** : initialisez, connectez et gérez vos dépôts Git grâce à l&#39;intégration GitHub
* **Suivi des commits** : indexez, validez et vérifiez toutes les modifications de fichiers
* **Gestion des branches** : créez, changez et fusionnez des branches de façon visuelle
* **Résolution des conflits** : identifiez et résolvez visuellement les conflits de fusion
* **Intégration au Shell** : synchronisez les commandes Git exécutées dans le Shell avec le panneau Git

<div id="section-2">
  ## Utilisation
</div>

<div id="section-3">
  ### Configuration du dépôt
</div>

<Accordion title="Comment accéder au panneau Git">
  1. Rendez-vous dans la section Tools de votre Replit App
  2. Sélectionnez l&#39;icône **+** pour ajouter un nouvel outil
  3. Choisissez **Git** dans la liste des outils disponibles
</Accordion>

Le panneau Git vous aide à configurer et à connecter votre dépôt :

* **Initialiser un dépôt** : créez un nouveau dépôt Git pour votre Replit App
* **Se connecter à un fournisseur Git** : liez votre dépôt à un fournisseur hébergé ou auto-hébergé pris en charge, à des fins de sauvegarde et de collaboration
* **Configurer les dépôts distants** : mettez en place et gérez les connexions aux dépôts distants

<Note>
  **Prise en charge de Git auto-hébergé** : Replit prend en charge GitHub Enterprise Server, GitLab Self-Managed et Bitbucket Data Center avec le plan Enterprise. Pour un accompagnement au déploiement ou une aide en cas d&#39;erreur de configuration ou de connexion, [contactez le service commercial de Replit](https://replit.com/enterprise). Vous pouvez également [configurer un dépôt distant à l&#39;aide des commandes git dans le Shell](#using-git-commands-in-shell).
</Note>

<div id="section-4">
  ### Gestion des modifications
</div>

<Accordion title="Comment consulter les modifications">
  1. Modifiez n&#39;importe quel fichier de votre Replit App
  2. Ouvrez le panneau Git depuis la section Tools
  3. Consultez les modifications dans la section **Review Changes**
</Accordion>

Le panneau Git met à votre disposition des outils pour gérer les modifications de votre code :

* **Consulter les modifications** : affiche les fichiers modifiés, avec les ajouts et les suppressions mis en évidence
* **Indexer des fichiers** : sélectionnez les fichiers à inclure dans le prochain commit
* **Valider les modifications** : enregistrez vos modifications avec un message descriptif
* **Envoyer les mises à jour** : transmettez vos commits vers GitHub en un seul clic

<Note>
  Vous pouvez faire appel à Replit AI pour générer des messages de commit qui décrivent précisément vos modifications.

<div id="section-5">
  ### Gestion des branches
</div>

<Accordion title="Comment gérer les branches">
  1. Ouvrez le panneau Git depuis la section Tools
  2. Sélectionnez la liste déroulante des branches, à côté du nom de la branche
  3. Créez une branche ou sélectionnez-en une existante
</Accordion>

Le panneau Git simplifie le travail sur plusieurs versions de votre code :

* **Créer une branche** : créez une branche pour développer une fonctionnalité de façon isolée
* **Changer de branche** : passez d&#39;une version du code à une autre
* **Publier une branche** : partagez une branche sur GitHub
* **Récupérer les modifications** : synchronisez les mises à jour distantes de vos collaborateurs

<div id="section-6">
  ### Résolution des conflits de fusion
</div>

<Accordion title="Comment résoudre les conflits de fusion">
  1. Tentez de récupérer les modifications alors que des conflits existent
  2. Le panneau Git met en évidence les fichiers en conflit
  3. Ouvrez chaque fichier en conflit pour examiner et résoudre le conflit
  4. Enregistrez les fichiers une fois les conflits résolus
  5. Sélectionnez **Pull** pour finaliser la fusion
</Accordion>

Lorsque du code provenant de sources différentes entre en conflit, le panneau Git vous aide à :

* **Identifier les conflits** : voir précisément quels fichiers présentent des conflits
* **Visualiser les différences** : comparer les deux versions du code en conflit
* **Résoudre les problèmes** : choisir le code à conserver ou modifier le conflit manuellement
* **Finaliser la fusion** : mener à terme le processus de fusion une fois les conflits résolus

Une fois le fichier en conflit résolu, vous pouvez supprimer les marqueurs de conflit en effaçant les lignes commençant par les symboles de conflit, puis enregistrer le fichier.

<div id="shellgit">
  ### Utiliser les commandes Git dans le Shell
</div>

<Accordion title="Comment accéder au Shell">
  1. Dans le dock d&#39;outils à gauche, sélectionnez **All tools**
  2. Parmi les outils disponibles, sélectionnez **Shell**
</Accordion>

<Tip>
  Le panneau Git offre une interface conviviale, mais les utilisateurs avancés peuvent réaliser des opérations plus complexes à l&#39;aide des commandes Git standard dans le Shell. Les modifications effectuées par l&#39;une ou l&#39;autre méthode se répercutent aux deux endroits.
</Tip>

Si vous souhaitez utiliser Git en ligne de commande :

* **Synchronisation des commandes** : les commandes Git exécutées dans le Shell sont automatiquement synchronisées avec le panneau Git
* **Fonctionnalités Git complètes** : accédez aux fonctionnalités Git avancées indisponibles dans le panneau Git
* **Basculement fluide** : passez des commandes du Shell au panneau Git selon vos besoins

<Info>
  **Prise en charge de GitHub CLI et GitLab CLI** : en plus des commandes Git standard, vous pouvez utiliser [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) et [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) dans le Shell pour gérer des dépôts Git externes et vous y connecter. Ces outils enrichissent l&#39;intégration avec les dépôts GitHub et GitLab, notamment pour les pull requests, les issues et d&#39;autres fonctionnalités propres à chaque plateforme.
</Info>

<div id="section-7">
  #### Opérations sur les dépôts
</div>

* **Cloner un dépôt** : `git clone <url-to-repository>`
* **Initialiser un dépôt** : `git init`
* **Ajouter un dépôt distant** : `git remote add origin <url-to-repository>`

<div id="section-8">
  #### Apporter des modifications
</div>

* **Vérifier l&#39;état** : `git status` (affiche les fichiers modifiés, ajoutés et supprimés)
* **Ajouter des fichiers à l&#39;index** : `git add <filename>` ou `git add .` (tous les fichiers)
* **Valider les modifications** : `git commit -m "your commit message"`
* **Envoyer les modifications** : `git push origin <branch-name>`
* **Récupérer les modifications** : `git pull origin <branch-name>`

<div id="section-9">
  #### Authentification
</div>

L&#39;utilisation de dépôts privés nécessite une authentification :

* Pour les dépôts GitHub.com, utilisez un jeton d&#39;accès personnel à la place du mot de passe
* Pour éviter de ressaisir vos identifiants, vous pouvez les enregistrer dans les Secrets Replit :
  1. Créez un nouveau secret avec la clé `GIT_URL`
  2. Définissez sa valeur sur `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Utilisez `git push $GIT_URL` pour pousser vos modifications sans saisir vos identifiants

<Note>
  Lorsque vos identifiants sont stockés sous forme de secret, toute personne ayant accès à votre Replit App peut potentiellement accéder à vos identifiants Git. Pour les dépôts sensibles, envisagez de saisir vos identifiants manuellement à chaque fois.
</Note>
