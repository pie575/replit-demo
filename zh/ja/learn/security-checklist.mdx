本指南提供一份全面的安全检查清单，帮助确认氛围编程应用是否遵循安全最佳实践。

Replit 默认提供多项安全功能，但了解并实施更多满足特定应用需求的安全措施同样重要。更多信息，请参阅 Replit 的[安全概述](/zh/ja/features/security/overview)。

<div id="section">
  ## 前提条件
</div>

* Replit 账户
* 具备所用编程语言的基础知识
* 熟悉项目编辑器的使用方法
* 一个正在使用 Replit 构建的应用

<div id="section-2">
  ## 前端安全
</div>

<AccordionGroup>
  <Accordion title="全程使用 HTTPS" icon="lock">
    Replit 默认对所有应用使用 HTTPS，无需额外操心！
  </Accordion>

  <Accordion title="输入验证与净化" icon="shield-check">
    请始终验证并净化用户输入，以防范跨站脚本 (XSS) 攻击：

    ```javascript theme={null}
    // 不佳：直接使用用户输入
    element.innerHTML = userInput;

    // 推荐：使用前净化输入
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    让 Agent 帮忙：

    ```
    Help me validate and sanitize inputs to protect against XSS attacks
    ```
  </Accordion>

  <Accordion title="不要将敏感数据存放在浏览器中" icon="eye-slash">
    请使用 Replit Secrets 存储 API 密钥等敏感信息。

    请勿将 Secrets 传递给客户端，也不要将其存放在以下位置：

    * 本地存储
    * 会话存储
    * 客户端 JavaScript
    * 未设置适当安全属性的 Cookie

    让 Agent 帮忙：

    ```
    Help me keep sensitive data out of the browser. Am I doing this correctly?
    ```
  </Accordion>

  <Accordion title="CSRF 防护" icon="shield">
    请为表单实施跨站请求伪造 (CSRF) 防护：

    ```javascript theme={null}
    // CSRF token 实现示例
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    让 Agent 帮忙：

    ```
    Help me implement CSRF tokens for forms
    ```
  </Accordion>
</AccordionGroup>

<div id="section-3">
  ## 后端安全
</div>

<AccordionGroup>
  <Accordion title="身份认证基础" icon="key">
    实施身份认证时：

    * 尽可能使用 Replit Auth
    * 如需构建自定义身份认证，请使用成熟的库
    * 切勿以明文存储密码

    询问 Agent：

    ```
    Help me implement authentication for my application with Replit Auth
    ```
  </Accordion>

  <Accordion title="授权检查" icon="user-lock">
    执行操作前，务必检查权限：

    ```javascript theme={null}
    // 授权检查示例
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    询问 Agent：

    ```
    Help me implement authorization checks for my application
    ```
  </Accordion>

  <Accordion title="保护 API 端点" icon="shield">
    确保 API 端点安全：

    * 为敏感端点添加身份认证
    * 配置适当的 CORS
    * 考虑实施速率限制

    询问 Agent：

    ```
    How do I properly authenticate endpoints in my app?
    ```
  </Accordion>

  <Accordion title="防范 SQL 注入" icon="database">
    Agent 默认使用 ORM，有助于防范 SQL 注入。如果需要编写自定义数据库查询：

    ```javascript theme={null}
    // 不佳：在查询中拼接字符串
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // 推荐：使用 ORM 的参数化查询
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="安全标头" icon="code">
    为应用添加重要的安全标头：

    ```html theme={null}
    <!-- 在 index.html 中或通过后端添加 -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    您可以在 [securityheaders.com](https://securityheaders.com) 扫描网站并查看建议。

    询问 Agent：

    ```
    Can you add the security headers to my application?
    ```
  </Accordion>
</AccordionGroup>

<div id="section-4">
  ## 持续开展安全实践
</div>

<AccordionGroup>
  <Accordion title="保持依赖项为最新状态" icon="arrow-rotate-right">
    定期检查可能存在漏洞的过时软件包：

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="妥善处理错误" icon="exclamation">
    不要在错误消息中泄露敏感信息：

    ```javascript theme={null}
    // Bad: Exposing sensitive details
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // Good: Generic error message
    catch (err) {
      console.error(err); // Log internally
      res.status(500).send('An error occurred');
    }
    ```

    询问 Agent：

    ```
    帮助我为我的应用实现妥善的错误处理
    ```
  </Accordion>

  <Accordion title="Cookie 安全" icon="cookie">
    使用 Cookie 时：

    * 设置 HttpOnly 标志，防止 JavaScript 访问
    * 使用 Secure 属性，强制使用 HTTPS
    * 设置 SameSite 属性，防止 CSRF

    询问 Agent：

    ```
    帮助我保障应用中的 Cookie 安全
    ```
  </Accordion>

  <Accordion title="文件上传安全" icon="upload">
    如果你的应用允许上传文件：

    * 限制文件类型和大小
    * 尽可能扫描恶意软件
    * 将文件存储在 Replit 的对象存储中
    * 不要使用用户提供的文件名，而应生成新文件名

    询问 Agent：

    ```
    帮助我确保应用中的文件上传安全
    ```
  </Accordion>

  <Accordion title="速率限制" icon="clock">
    请实施速率限制，尤其是认证相关的 API 端点：

    ```javascript theme={null}
    // Example rate limiting middleware
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 minutes
      max: 100 // limit each IP to 100 requests per windowMs
    });

    app.use('/api/', limiter);
    ```

    询问 Agent：

    ```
    帮助我为我的应用实现速率限制
    ```
  </Accordion>
</AccordionGroup>

  ## 检查清单
</div>

用于管理安全实践的检查清单。

<div id="section-6">
  ## 前端安全
</div>

|   | 安全措施          | 说明                         |
| - | ------------- | -------------------------- |
| ☐ | 全面使用 HTTPS    | 防范基本的窃听和中间人攻击              |
| ☐ | 输入验证与净化       | 验证所有用户输入，防范 XSS 攻击         |
| ☐ | 不在浏览器中存储敏感数据  | 不要将 Secrets 存储在本地存储或客户端代码中 |
| ☐ | CSRF 防护       | 为表单和状态更改请求实施 CSRF 防护令牌     |
| ☐ | 不在前端公开 API 密钥 | 始终将 API 凭据保留在服务端           |

<div id="section-7">
  ## 后端安全
</div>

|   | 安全措施      | 说明                                             |
| - | --------- | ---------------------------------------------- |
| ☐ | 认证基础      | 使用成熟的库，并妥善存储密码 (哈希 + 加盐)                       |
| ☐ | 授权检查      | 执行操作前始终检查权限                                    |
| ☐ | 保护 API 端点 | 为所有 API 端点实施适当的认证                              |
| ☐ | 防范 SQL 注入 | 使用参数化查询或 ORM，避免将用户输入直接拼接到原始 SQL 中              |
| ☐ | 基本安全标头    | 实施 X-Frame-Options、X-Content-Type-Options、HSTS |
| ☐ | DDoS 防护   | 使用具备内置 DDoS 缓解功能的 CDN 或云服务                     |

<div id="section-8">
  ## 实用安全实践
</div>

|   | 安全措施       | 说明                               |
| - | ---------- | -------------------------------- |
| ☐ | 保持依赖项为最新版本 | 大多数脆弱性源于过时的库                     |
| ☐ | 妥善处理错误     | 不要在错误消息中泄露敏感信息                   |
| ☐ | Cookie 安全 | 设置 HttpOnly、Secure 和 SameSite 属性 |
| ☐ | 文件上传安全    | 验证文件类型和大小，并扫描恶意内容                |
| ☐ | 速率限制       | 在所有 API 端点上实施，尤其是认证相关端点          |
