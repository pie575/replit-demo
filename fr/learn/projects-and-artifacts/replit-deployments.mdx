La publication vous permet de partager votre App Replit avec le monde entier grâce à un processus simplifié.

<Note>
  L’action qui consiste à mettre votre app en ligne s’appelle « publication ». Cette page présente les différents types de déploiements disponibles.
</Note>

<div id="what-is-publishing">
  ## Qu’est-ce que la publication ?
</div>

La publication est une fonctionnalité qui enregistre un **instantané** de votre App Replit dans le cloud,
avec lequel chacun peut interagir. Un instantané capture l’état actuel des fichiers de votre
App Replit.

Lorsque vous publiez votre App Replit, vous créez une **application publiée**. Une application publiée est une instance en cours d’exécution
de votre application sur l’infrastructure cloud de Replit. Votre application est ainsi disponible de manière fiable sur Internet,
indépendamment de la version présente dans le Project Editor.

<Info>
  L’infrastructure de Replit repose sur Google Cloud Platform (GCP). Toutes les
  applications publiées sont hébergées aux États-Unis. Les clients Enterprise peuvent
  contacter l’équipe commerciale afin de demander l’hébergement de leurs applications publiées dans l’Union
  européenne.

  Chaque client individuel, chaque organisation et chaque client Enterprise dispose d’un projet GCP dédié
  à locataire unique pour ses applications publiées. Ainsi, les ressources de calcul,
  les Secrets et le stockage des applications publiées sont entièrement isolés et ne sont jamais
  partagés avec les applications d’autres clients.
</Info>

La publication comprend des outils permettant de surveiller l’état de votre application publiée et de consulter les analyses web.

<div id="getting-started">
  ## Premiers pas
</div>

Suivez les étapes ci-dessous pour publier votre Replit App :

1. Dans votre Project Editor, sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publier" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publier** en haut de l’écran.
2. Dans l’onglet **publication**, sélectionnez l’option de publication souhaitée.
3. Si **Ajouter un mode de paiement** s’affiche, suivez les instructions pour ajouter un mode de paiement.

Replit sélectionne automatiquement l’option de publication la mieux adaptée à votre app en fonction du type de projet et de vos besoins.

Toutefois, si vous souhaitez choisir un autre type de déploiement, consultez les informations suivantes.

<div id="key-features">
  ## Fonctionnalités clés
</div>

La publication offre les fonctionnalités pratiques suivantes :

* **Plusieurs options de publication** : sélectionnez ou mettez à jour un type de déploiement adapté à vos besoins en quelques clics.
* **Domaines personnalisés** : servez votre app depuis votre propre domaine web.
* **Analyses** : suivez les données des visiteurs et d’autres indicateurs pour votre application publiée.
* **Outils de Monitoring** : consultez l’état et la configuration de votre application publiée.
* **Contrôles d’accès** : contrôlez qui peut voir votre app en un seul clic. Disponible uniquement pour les membres **Pro** et **Enterprise**.
* **Paramètres du badge** : les utilisateurs Core peuvent gérer le badge « Made with Replit » dans les paramètres de publication. Si vous avez publié une app avec le forfait Starter, qui inclut le badge, sa suppression de votre app peut prendre quelques minutes après votre passage à une offre supérieure.
* **Collecte de retours** : activez les retours sur votre application publiée afin de recueillir les avis de vos utilisateurs.

<div id="how-it-works">
  ## Fonctionnement
</div>

Lorsque vous publiez votre Replit App, Replit crée un instantané des fichiers et dépendances de votre application.
Cet instantané est ensuite envoyé vers l&#39;infrastructure cloud de Replit, où il s&#39;exécute en tant qu&#39;instance distincte de votre application.
Pour mettre à jour votre application publiée avec les dernières modifications, publiez-la à nouveau afin de créer un nouvel instantané.

<Warning>
  Évitez d&#39;enregistrer des données dans le système de fichiers d&#39;une application publiée ou de vous y fier. Pour
  stocker des données, utilisez une solution de stockage ou de base de données, telle que les offres [Storage and
  Database](/fr/learn/projects-and-artifacts/storage-and-databases) de Replit.
</Warning>

<div id="use-cases">
  ## Cas d’utilisation
</div>

Les exemples suivants présentent différents types d’applications publiées.

<div id="autoscale-deployment-typing-speed-assessment-app">
  ### Déploiement Autoscale : application d’évaluation de la vitesse de frappe
</div>

Laissez le cloud augmenter les ressources lorsque les utilisateurs passent des tests de frappe, puis les réduire lorsqu’elles ne sont plus utilisées.

<div id="static-deployment-solar-system-simulation">
  ### Déploiement statique : simulation du système solaire
</div>

Découvrez les planètes grâce à une application web de visualisation du système solaire.
Cette visualisation s&#39;affiche dans le navigateur et ne transmet aucune donnée saisie par l&#39;utilisateur à un serveur.

<div id="reserved-vm-deployment-discord-bot">
  ### Déploiement VM réservée : bot Discord
</div>

Exécutez un bot Discord pour vous aider à modérer et à accueillir les membres.
Toujours en ligne, il échange avec les utilisateurs et répond aux commandes, avec des tarifs et des performances prévisibles.

<div id="scheduled-deployment-home-automation-triggers">
  ### Déploiement planifié : déclencheurs de domotique
</div>

Planifiez des appels API pour démarrer et arrêter vos appareils domotiques à des heures et des jours précis.
