Replit은 클라우드 환경에서 프로젝트를 실행하기 때문에 포트가 로컬 컴퓨터에서와는 다르게 동작합니다. (TCP 포트가 무엇인지 더 기초적인 설명이 필요하다면 [여기에서 시작하세요](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

일반 컴퓨터에서는 포트 관리 계층이 하나뿐입니다. 프로그램이 수신할 포트를 지정하고, 인터넷에서 컴퓨터의 해당 포트로 트래픽이 들어오면 알맞은 프로세스로 라우팅됩니다.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="computer" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` 부분은 주소, 즉 호스트입니다. 프로세스가 `0.0.0.0`에서 수신 중이라면 모든 네트워크 인터페이스에서 수신한다는 뜻입니다. 즉, 인터넷상의 다른 컴퓨터가 여러분 컴퓨터의 IP 주소로 요청을 보내면 그 요청이 전달됩니다. 따라서 0.0.0.0에서 수신한다는 것은 (컴퓨터가 연결되어 있다면) 해당 프로세스에 공개 인터넷에서 접근할 수 있다는 의미입니다.

대부분의 프로그래밍 프레임워크는 개발 중일 때 `0.0.0.0`에서 수신하지 *않습니다*. 개인 정보 보호와 보안을 위해, 작업 중인 결과물이 외부에 노출되는 것을 원하지 않는 경우가 많기 때문입니다. 대신 `localhost`라고도 불리는 `127.0.0.1`이라는 다른 주소에서 수신합니다. 이 경우 해당 컴퓨터에서만 그 포트로 요청을 보낼 수 있습니다.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Localhost 포트는 이를 호스팅하는 컴퓨터에서만 확인할 수 있습니다." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

Replit에서는 실행 중인 프로세스에 webview나 외부 요청으로 접근하려면 **외부 포트**가 정의되어 있어야 합니다. 프로세스가 일반적으로 사용하는 &quot;내부 포트&quot;는 Replit이 제공하는 sandbox 클라우드 환경 안에서만 보이기 때문입니다. 프로그램으로 올바른 트래픽을 전달하려면 이 내부 포트를 외부에서 접근 가능한 포트에 연결해야 합니다. 프로세스가 0.0.0.0처럼 통상 공개적으로 접근 가능한 주소에서 수신하더라도, 외부 포트에 bind되어야 한다는 점은 동일합니다.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="외부 포트는 프로그램이 수신하는 내부 포트로 트래픽을 전달합니다." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit은 외부 포트를 특정 내부 포트에 bind하는 방식으로 이를 처리합니다. 예를 들어 위 다이어그램에서 외부 포트 `:80`은 내부 포트 `:3000`에 bind되어 있습니다. 즉, 해당 Replit App이 포트 80으로 받는 모든 트래픽은 내부 포트 3000으로 전달됩니다.

이 구성은 .replit config 파일의 [[ports]] 섹션에 기록됩니다.

기본적으로 Replit은 여러분이 처음 여는 포트를 기본 외부 포트 80에 bind합니다. 덕분에 해당 프로세스는 포트 번호 없이 도메인만으로 접근할 수 있습니다(예: customdomain.com:3000/ 대신 customdomain.com/). 이후에 열리는 추가 내부 포트는 사용 가능한 다른 외부 포트에 bind됩니다(전체 목록은 아래 참고).

<div id="default-port">
  ## 기본 포트
</div>

:80 포트는 http 트래픽의 &quot;기본 포트&quot;이므로, 루트 도메인으로 전송된 http 트래픽은 자동으로 80 포트로 라우팅됩니다. 이 때문에 80 포트는 URL에 포트 경로가 표시되지 않습니다. `80`이 아닌 포트는 도메인 경로에 표시됩니다(예: customdomain.com:4200/). (Replit은 기본적으로 TLS를 제공하므로 엄밀히 말하면 https의 기본 포트인 443 포트가 사용됩니다. 실질적으로는 두 포트를 같은 것으로 봐도 무방합니다.)

<div id="publishing">
  ## Publishing
</div>

Autoscale 및 Reserved VM deployments는 외부 포트를 하나만 노출할 수 있으며, 이에 대응하는 내부 포트가 `localhost`를 사용해서는 안 됩니다. 포트를 여러 개 노출하거나 localhost에서 단일 포트를 노출하면 published app이 실패합니다. Autoscale deployments를 의도대로 동작시키는 가장 간단한 방법은, 인터넷에서 접근하려는 서비스의 포트만 남기고 config에 있는 나머지 포트의 `externalPort` 항목을 모두 제거하는 것입니다.

<div id="debugging">
  ## 디버깅
</div>

기대한 대로 동작하지 않는 흔한 원인 중 하나는 port config는 올바른 것처럼 보이지만 실제로 program은 다른 포트를 바라보고 있는 경우입니다. 예를 들어 config가 다음과 같다면:

```
[[ports]]
internalPort = 3000
externalPort = 80
```

그러면 포트 80으로 들어오는 인터넷 트래픽이 내부 포트 3000으로 전달됩니다. 하지만 프로그램이 실제로는 포트 3000이 아니라 다른 포트(예: 8080)에서 수신 대기 중이라면, 트래픽이 전혀 전달되지 않는 것처럼 보입니다. 코드에서 포트를 변경하면서 config의 해당 포트를 함께 변경하지 않았거나, 한 project의 config를 다른 project로 복사해 붙여넣은 경우에 이런 일이 발생할 수 있습니다.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="프로그램은 수신 대기하는 포트를 변경할 수 있습니다." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

프레임워크마다 기본으로 수신 대기하는 포트가 다릅니다. 예를 들어 Flask는 5000, react는 3000, laravel은 8000입니다. 올바른 포트가 설정되어 있는지 꼭 확인하세요!

<div id="preferences">
  ## 환경설정
</div>

Replit은 Replit App에서 포트가 열리면 해당 포트를 사용 가능한 외부 포트에 자동으로 bind하고, 그 바인딩 정보를 .replit config 파일에 기록합니다.

다만 localhost에서 열리는 내부 포트에는 기본적으로 이 동작이 적용되지 않습니다. localhost에서 실행되는 서비스는 대개 프로세스가 실행 중인 컴퓨터에서만 접근할 수 있다고 가정하기 때문입니다(localhost 포트는 프로세스를 실행하는 컴퓨터에서만 보입니다). 그래서 이러한 서비스는 공용 인터넷에 공개된다는 전제로 만들어진 서비스만큼 안전하지 않은 경우가 많습니다.

노출하려는 포트에 `exposeLocalhost` config 옵션을 `true`로 설정하면 언제든지 이 동작을 재정의할 수 있습니다.

localhost 포트를 기본적으로 *항상* 노출하려면 User Settings 도구에서 “automatic port forwarding” 설정을 “All ports”로 지정하세요.

열린 포트에 대해 config를 *절대* 생성하지 않고 모든 Replit App의 port config를 직접 제어하려면 이 설정을 “never”로 지정하세요.

<div id="supported-ports">
  ## 지원 포트
</div>

Replit App은 첫 번째 포트가 열릴 때 기본적으로 포트 80을 외부 포트로 지정합니다. Replit App은 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080, 8081번 포트를 추가 외부 포트로 노출할 수 있습니다.

22번과 8283번 포트는 내부적으로 사용되므로 포워딩할 수 없습니다.

<div id="ports-replit-config">
  ## `[[ports]]` .replit config
</div>

타입: `{localPort, externalPort, exposeLocalhost}`

`[[ports]]` config를 사용하면 웹 출력으로 노출할 HTTP 포트를 지정할 수 있습니다. 기본적으로 호스트가 0.0.0.0인 노출된 HTTP 포트는 Replit App의 웹 출력으로 노출됩니다.

.replit 파일에 새 [[ports]] 항목을 추가하면 기본 포트를 재정의하지 않고도 추가 포트를 serve할 수 있습니다. 이때 localPort와 externalPort 항목을 모두 지정해야 합니다. 아래 정의된 것처럼 .replit 파일에 [[ports]] 항목을 여러 개 추가하면 추가 포트도 여러 개 사용할 수 있습니다.

<div id="localport">
  ### localPort
</div>

Replit이 외부 포트에 바인딩할 포트를 결정합니다.

<div id="externalport">
  ### externalPort
</div>

해당 로컬 포트를 외부에 공개할 때 사용할 포트를 지정합니다.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

특정 포트를 *절대* 노출하지 않으려면, `localPort` config는 그대로 두고 `externalPort`만 추가하지 않으면 됩니다:

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

`localhost`를 사용하는 내부 포트를 외부 포트에 바인딩할 수 있는지 여부를 결정합니다. `true`, `false` 또는 null을 지정할 수 있습니다.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
