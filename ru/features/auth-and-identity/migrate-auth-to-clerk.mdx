Воспользуйтесь этим руководством, чтобы перевести существующее приложение с [Replit Auth](/ru/features/auth-and-identity/authentication) на [Clerk Auth](/ru/features/auth-and-identity/clerk-auth). Для подходящих приложений Agent выполняет миграцию самостоятельно, поэтому вернувшиеся пользователи сохраняют доступ к своим данным.

<Note>
  Эта автоматическая миграция предназначена для приложений, использующих Replit Auth. Если в вашем приложении используется другая система аутентификации, не применяйте этот способ.
</Note>

<div id="start-the-migration">
  ## Запуск миграции
</div>

Миграции Agent всегда следует запускать в новой задаче.

Начать миграцию можно одним из следующих способов:

<div id="start-from-agent">
  ### Начните с Agent
</div>

<Steps>
  <Step title="Создайте новую задачу">

</div>

<div id="what-agent-does">
  ## Что делает Agent
</div>

Agent выполняет миграцию в следующем порядке:

1. Переносит данные пользователей Replit Auth в Clerk, включая сведения об учётных записях и поддерживаемые учётные данные для входа.
2. Дожидается завершения миграции данных и только затем вносит изменения в приложение.
3. Обновляет логику входа и сессий, перезапускает приложение и выполняет доступные автоматические проверки.

<div id="your-app-data-stays-in-place">
  ## Данные вашего приложения остаются на месте
</div>

Agent изменяет только код аутентификации приложения. Существующие данные и схему базы данных он не затрагивает. Ваши таблицы и связи между ними остаются нетронутыми.

Существующие пользователи по-прежнему связаны с принадлежащими им записями — профилями, сохранёнными результатами работы и правами доступа.

<div id="how-long-it-takes">
  ## Сколько это занимает времени
</div>

Agent будет работать от 10 минут до часа. Сама миграция данных может занять несколько минут для небольших приложений и до пары часов для приложений с большим числом пользователей. Agent не начнёт вносить изменения в код вашего приложения, пока миграция не завершится.

<div id="after-the-migration">
  ## После миграции
</div>

Перед публикацией протестируйте обновлённое приложение в режиме разработки:

1. Войдите под существующей учётной записью и убедитесь, что сохранённые в ней данные доступны.
2. Выйдите из учётной записи и войдите снова.
3. Создайте новую тестовую учётную запись и убедитесь, что из-под неё приложение работает как ожидается.
