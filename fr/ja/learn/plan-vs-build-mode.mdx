Replit Agent propose deux modes d&#39;interaction : le **mode Plan** et le **mode Build**. En les combinant, vous pouvez d&#39;abord mûrir votre idée, puis la mettre en œuvre en toute confiance.

<div id="plan">
  ## Qu&#39;est-ce que le mode Plan ?
</div>

Le [mode Plan](/fr/ja/features/agent/plan-mode) vous permet de faire du brainstorming avec Agent, de poser des questions et de planifier votre travail sans modifier la moindre ligne de code. Voyez-le comme une séance de planification collaborative où vous explorez librement vos idées.

Le mode Plan est idéal pour :

* **Faire du brainstorming** : explorer différentes approches avant d&#39;en retenir une
* **Décomposer des projets complexes** : obtenir une liste de tâches structurée avant de passer à la construction
* **Apprendre et comprendre** : poser des questions sur des technologies, des modèles ou une base de code
* **Planifier l&#39;architecture** : concevoir la structure de votre application avant d&#39;écrire la moindre ligne de code

<Info>
  En mode Plan, Agent lit votre projet et vous fournit des conseils, mais n&#39;apporte aucune modification à vos fichiers. Lorsque vous êtes prêt à passer à l&#39;implémentation, basculez en mode Build ou approuvez le plan pour lancer automatiquement la construction.
</Info>

<div id="build">
  ## Qu’est-ce que le mode Build ?
</div>

Le mode Build est le mode par défaut dans lequel Agent écrit du code, modifie des fichiers et implémente directement des fonctionnalités dans votre projet. C’est là que vos idées prennent vie.

Utilisez le mode Build pour :

* **Créer de nouvelles fonctionnalités** : demandez à Agent d’écrire le code d’une nouvelle fonctionnalité
* **Configurer votre application** : installez des dépendances, configurez des bases de données et connectez des services
* **Résoudre des problèmes** : demandez à Agent de déboguer et de résoudre les problèmes de votre base de code
* **Refactoriser le code** : améliorez la structure et l’organisation du code existant

<div id="section">
  ## Combiner les deux modes
</div>

**Le mode Plan et le mode Build donnent leur pleine mesure lorsqu&#39;on les utilise l&#39;un après l&#39;autre.** Commencez par planifier pour clarifier vos idées, puis développez avec une direction claire.

<Steps>
  <Step title="Commencer par le mode Plan">
    Passez en mode Plan et décrivez ce que vous souhaitez créer. Agent vous aide à définir les exigences, propose une approche et identifie les difficultés potentielles — sans toucher au code.
  </Step>

  <Step title="Générer une liste de tâches">
    Demandez à Agent de créer un plan de développement. Il décompose votre projet en tâches concrètes et réalisables, avec des priorités et des dépendances claires.

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="Liste de tâches générée avec priorités et dépendances" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="Vérifier et affiner">
    Passez en revue le plan proposé. Vous pouvez poser des questions complémentaires, demander des modifications ou explorer d&#39;autres approches. Affinez le plan par itérations jusqu&#39;à ce qu&#39;il corresponde à votre vision.
  </Step>

  <Step title="Lancer la construction">
    Une fois le plan satisfaisant, sélectionnez **Start building (Lancer la construction)**. Agent bascule automatiquement en mode Build et commence à implémenter les tâches approuvées.

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="Sélecteur de mode affichant les options mode Plan et mode Build" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="Suivre la progression">
    Surveillez l&#39;avancement pendant qu&#39;Agent déroule la liste de tâches. Chaque tâche terminée crée un point de contrôle, ce qui vous permet de vérifier les modifications et de revenir en arrière si nécessaire.
  </Step>
</Steps>

<div id="section-2">
  ## Quel mode utiliser et quand
</div>

<CardGroup cols={2}>
  <Card title="Quand utiliser le mode Plan" icon="lightbulb">
    * Lorsque vous démarrez un nouveau projet et avez besoin d&#39;une orientation
    * Lorsque vous souhaitez explorer différentes approches
    * Lorsque la tâche est complexe et doit être décomposée
    * Lorsque vous souhaitez vous informer avant de passer à l&#39;implémentation
    * Lorsque vous ne connaissez pas la meilleure solution
  </Card>

  <Card title="Quand utiliser le mode Build" icon="hammer">
    * Lorsque vous savez précisément ce que vous voulez
    * Lorsque vous avez un plan clair prêt à être exécuté
    * Lorsque vous devez effectuer des correctifs rapides ou de petites modifications
    * Lorsque vous suivez une liste de tâches approuvée
    * Lorsque vous privilégiez la rapidité d&#39;implémentation
  </Card>
</CardGroup>

<Tip>
  **Vous hésitez entre les deux ?** Si votre demande comprend plusieurs fonctionnalités ou des modifications importantes, commencez par le mode Plan. Pour les tâches simples et clairement définies, passez directement au mode Build.
</Tip>

<div id="section-3">
  ## Principales différences
</div>

| Fonctionnalité            | Mode Plan                                    | Mode Build                            |
| ------------------------- | -------------------------------------------- | ------------------------------------- |
| **Objectif**              | Brainstorming, planification, apprentissage  | Mise en œuvre et développement        |
| **Modifications du code** | Aucune — lecture seule                       | Écriture et modification de fichiers  |
| **Résultat**              | Idées, listes de tâches, conseils            | Code et fonctionnalités opérationnels |
| **Idéal pour**            | Projets complexes, exploration               | Tâches bien définies, mise en œuvre   |
| **Transition**            | Cliquez sur « Start building » pour basculer | Déjà en mode d’implémentation         |

<div id="section-4">
  ## Bonnes pratiques
</div>

<div id="plan-2">
  ### Tirer le meilleur parti du mode Plan
</div>

* **Exprimez clairement vos exigences** : plus vous fournissez de détails, meilleur sera le plan
* **Posez des questions de suivi** : demandez des précisions sur les suggestions que vous ne comprenez pas
* **Demandez des exemples** : demandez à Agent d’afficher des extraits de code ou des exemples de modèles
* **Discutez des compromis** : examinez les avantages et les inconvénients des différentes approches
* **Affinez vos idées** : améliorez le plan jusqu’à ce qu’il vous convienne

<div id="section-5">
  ### Transition fluide
</div>

* **Vérifiez avant de créer** : examinez toujours la liste des tâches avant de l’approuver
* **Commencez modestement** : commencez par un sous-ensemble de tâches si le plan complet vous semble trop ambitieux
* **Utilisez les points de contrôle** : Agent crée des points de contrôle tout au long de la création, ce qui vous permet de revenir en arrière à tout moment
