<div id="section">
  ## 什么是 Remix
</div>

**Remix** 是基于你当前有权访问的应用创建的新 Replit App。对已发布的应用或模板进行 Remix 后，你会获得自己的副本，可在此基础上逐步修改和完善。你在 Remix 中所做的更改不会影响原始应用。

Remix 会明确注明原始应用：页面会显示指向原始应用的 **Remixed from** 链接，原始应用的构建提示词也会显示在封面页面上。

<div id="section-2">
  ## Remix 包含哪些内容
</div>

Remix 是一个可完全正常运行的副本，与原始 App 完全分离。

* **所有文件和设置**都会被复制，因此 App 的运行方式与原始 App 完全相同。
* **原始 App 的检查点历史记录**也会一并保留，并标记为原始 App 的历史记录。你可以随时回滚到这些检查点，但生成这些检查点的对话仍会保留在原始 App 中。
* **全新的 Agent**。Remix 会从新的 Agent 开始，不会继承聊天记录。
* **仅复制密钥名称，不复制值**。如果 App 使用密钥 (例如 API 密钥) ，Remix 中会列出这些密钥，让你知道需要输入什么，但其值将为空。只有 Remix 自己的 App 时，密钥值才会被复制。
* **新的数据库**。Remix 不会连接到原始 App 的数据库。如果原始 App 有数据库，你可以使用 **Copy data from original App** 选项复制数据本身，但所做的更改不会影响原始 App。
* 对于使用 Replit Auth 的 App，**新的登录设置**。

不会被复制的内容包括：部署、域名和连接器设置，需要你在自己的副本中单独配置。此外，Remix 初始为非公开状态，因此在你选择发布之前，不会共享任何内容。

  ## 如何 Remix 应用
</div>

<Steps>
  <Step title="打开应用的封面页面">
    在[社区](https://replit.com/community/all)等位置找到你想要 Remix 的应用。封面页面会显示实时预览和分享选项。
  </Step>

  <Step title="Remix 应用">

  <Step title="填写应用详情">

<div id="section-5">
  ## 在 Remix 的基础上继续构建
</div>

在工作区中打开 Remix 后，可使用 Agent 进行修改和扩展。在 **Agent** 标签页中输入提示词，描述您想添加的功能。

要撤销 Agent 所做的更改，请在更改后创建的检查点中选择 **Rollback to here**。有关详细信息，请参阅[检查点和回滚](/zh/ja/features/version-control/checkpoints-and-rollbacks)。

<div id="section-6">
  ## 选择 Remix 还是从提示词开始构建？
</div>

这两种方式最终都能让你拥有自己的应用，并由 Agent 帮助你持续完善。不同之处在于起点。

|             | Remix            | 从提示词开始构建          |
| ----------- | ------------- | ----------------- |
| 起点          | 原样复制的可运行应用    | Agent 根据你的描述创建的应用 |
| 初始结果        | 立即获得，与原应用完全相同 | 耗时更长，每次生成的结果都不同   |
| Agent 的初始操作 | 等待你的指示        | 根据你的提示词进行规划和构建    |

如果已经有一个应用接近你的需求，就 Remix 它。这样无需从零开始，Agent 的第一步就能基于一个实际可运行的应用。如果找不到与你的想法相似的应用，就从提示词开始构建。
