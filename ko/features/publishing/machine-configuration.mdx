머신 구성은 게시된 앱을 실행하는 서버의 성능을 결정합니다. Replit이 적절한 기본값을 자동으로 선택하므로 대부분의 builder는 이 값을 변경할 필요가 없습니다. 부하가 걸릴 때 앱이 느려지거나 메모리에서 대량의 데이터를 처리해야 한다면 더 높은 성능의 구성을 고려해 보세요.

변경하려면 게시 도구를 열고 **Adjust settings**를 선택한 다음, **Machine configuration** 옆의 **Edit**를 선택하세요.

<div id="the-settings">
  ## 설정 항목
</div>

* **CPU**: 각 서버가 동시에 처리할 수 있는 작업량입니다. 여러 사용자가 동시에 앱을 사용할 때는 vCPU가 많을수록 유리합니다.
* **메모리(RAM)**: 앱이 메모리에 담아 둘 수 있는 데이터의 양입니다. 대용량 파일, 미디어, 데이터 집약적인 작업에는 RAM이 많을수록 유리합니다.
* **최대 머신 수**: Autoscale 전용 설정입니다. 앱에 부하가 몰릴 때 Replit이 추가할 수 있는 서버 수의 상한입니다. 앱은 이 수를 넘어 확장되지 않으므로 비용의 최대치가 정해집니다.

<div id="what-it-costs">
  ## 비용
</div>

설정하는 동안 pane에 두 가지 숫자가 표시됩니다.

* **머신당**: 선택한 구성으로 서버 한 대를 운영할 때의 시간당 비용입니다.
* **최대 트래픽 시**: 앱의 트래픽이 많아 최대 개수까지 모든 머신을 사용할 경우의 시간당 비용입니다.

비용은 compute units로 측정되며, 이는 선택한 CPU와 메모리를 기준으로 한 클라우드 컴퓨팅 단위입니다. 현재 요금과 usage 청구 방식은 [usage-based billing](/ko/billing/about-usage-based-billing#2-compute-units)을 참조하세요.

<div id="how-billing-differs-by-deployment-type">
  ## 배포 유형별 billing 차이
</div>

동일한 구성이라도 [배포 유형](/ko/features/publishing/deployment-types)에 따라 요금이 다르게 청구됩니다:

* **Autoscale**: 요청을 처리하는 동안에만 요금이 발생합니다. 앱이 유휴 상태일 때는 0으로 축소되어 실행 비용이 들지 않습니다.
* **Reserved VM**: 서버가 항상 켜져 있으므로 선택한 구성에 대해 고정된 월 비용을 지불합니다.
* **Static**: 사이트를 실행하는 머신이 없으므로 머신 구성이 적용되지 않습니다.
* **Scheduled**: 예약된 run이 실행되는 동안 사용한 머신에 대해 요금을 지불합니다.

<div id="apply-your-changes">
  ## 변경 사항 적용하기
</div>

구성을 변경한 후 앱을 다시 Publish하세요. 새 머신 설정은 새로운 deployment부터 적용됩니다.
