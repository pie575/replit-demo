Plan mode는 질문하기, 브레인스토밍, 작업 계획 수립에 초점을 맞춘 새로운 방식으로 Replit Agent와 대화할 수 있는 기능입니다.

<div id="what-is-plan-mode">
  ## Plan Mode란?
</div>

Plan mode에서는 다음과 같은 작업을 할 수 있습니다.

* **아이디어를 브레인스토밍**하고 project에 적용할 다양한 접근 방식 살펴보기
* 구조화된 task list로 **개발 작업 계획하기**
* project 아키텍처와 기능 기획에 대해 **AI와 협업하기**
* project의 코드나 데이터를 변경하지 않고 **전략적인 조언을 얻고** 질문하기
* 구현할 준비가 되면 Build mode로 **매끄럽게 전환하기**

기본 모드는 이제 **Build** mode라고 부릅니다.

Build mode와 달리 Plan mode는 기획과 아이디어 구상에 초점을 맞추므로, 코드를 작성하기 전에 project를 충분히 고민해 볼 수 있습니다.

<div id="getting-started">
  ## 시작하기
</div>

<div id="accessing-plan-mode">
  ### Plan Mode 사용하기
</div>

Plan mode는 Agent가 활성화된 모든 Replit App에서 사용할 수 있습니다. 사용 방법은 다음과 같습니다.

1. Project Editor에서 **Replit App을 엽니다**
2. 채팅 입력창 왼쪽 하단에서 **모드 선택기를 찾습니다**
3. 드롭다운에서 **Plan mode를 선택합니다**

  ### 협업 브레인스토밍
</div>

AI와 함께 다양한 접근 방식을 탐색해 보세요:

* 복잡한 문제를 위한 **여러 가지 해결 방안**
* 접근 방식별 **장단점 분석**
* **위험 평가** 및 완화 전략

<div id="workflow-from-planning-to-building">
  ## 워크플로우: 계획에서 빌드까지
</div>

<div id="1-planning-phase-plan-mode">
  ### 1. 계획 단계(Plan Mode)
</div>

Plan mode에서 개발 프로세스를 시작하세요.

* **프로젝트 범위와 목표 정의하기**
* **요구 사항을 구체적인 기능으로 세분화하기**
* **아키텍처와 기술 스택 설계하기**
* **마일스톤이 포함된 개발 로드맵 작성하기**

<div id="2-task-approval">
  ### 2. 작업 승인
</div>

Agent가 task list를 생성하면 다음을 수행하세요:

* 제안된 task를 **검토**합니다
* **Start building**을 선택해 plan을 승인합니다

또는 계속 대화하면서 plan을 다듬을 수도 있습니다.

<div id="3-transition-to-build-mode">
  ### 3. Build mode로 전환
</div>

구현을 시작할 준비가 되면:

* **&quot;Start building&quot; 클릭**으로 계획 승인
* **Agent가 자동으로** Build mode로 전환
* **Agent가 승인된 task 구현 시작**
* 개발 단계 전반에 걸쳐 **진행 상황 추적**

Plan Mode 사용량에는 다른 Agent 상호작용과 동일한 effort-based pricing이 적용됩니다. 질문에 대한 답변, 안내 제공, task list 생성 등 Plan Mode에서 이루어지는 모든 Agent 작업에 요금이 부과됩니다. 요청이 복잡할수록, 또는 context가 긴 conversa에서의 요청일수록 요금이 올라갑니다.

**모든 Agent 상호작용에는 요금이 부과됩니다** - Agent가 텍스트로 안내를 제공하든 코드를 변경하든 항상 요금이 발생하며, 다만 요청이 작을수록 비용은 적습니다.

<div id="effective-prompting">
  ### 효과적인 prompting
</div>

Plan mode를 최대한 활용하려면 다음을 참고하세요.

* project requirements를 **구체적으로 설명하세요**
* AI suggestions를 명확히 파악하기 위해 **follow-up 질문을 하세요**
* 복잡한 개념을 논의할 때는 **예시를 요청하세요**
* 여러 접근 방식의 **장단점을 비교해 보세요**
* 구현에 착수하기 전에 **아이디어를 여러 번 다듬으세요**
* 중요한 결정은 이후 대화에서 언급해 **기록으로 남기세요**
