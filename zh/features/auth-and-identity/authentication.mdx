Replit Auth 让你能够在应用中打造个性化的用户体验。有了用户账户，你可以保存用户偏好、创建自定义仪表板、构建社交功能、控制付费内容的访问权限、跟踪用户活动 —— 这些功能正是让应用变得有吸引力、有价值的关键。

Replit Auth 使用 Replit 自有的登录系统 —— 当有人登录你的应用时，他们注册的或使用的都是 **Replit 账户**。登录页面带有 Replit 品牌标识，登录流程也与 replit.com 上的完全一致。

<Note>
  **Replit Auth 与 Clerk Auth 的区别** —— Replit 提供两种身份验证方案。**Replit Auth** (即本页介绍的方案) 使用 Replit 自有的登录系统，因此你的应用用户会使用 Replit 账户登录，看到的是带 Replit 品牌标识的登录页面。**[Clerk Auth](/zh/features/auth-and-identity/clerk-auth)** 则由 Clerk 提供支持，为你的应用提供专属的身份验证租户，品牌样式完全可自定义，用户账户也独立于 Replit 之外。如果你希望登录体验使用自己的品牌，或希望用户账户不与 Replit 绑定，请选择 Clerk Auth。

  如果你的应用已在使用 Replit Auth，请参阅[从 Replit Auth 迁移到 Clerk](/zh/features/auth-and-identity/migrate-auth-to-clerk)，了解自动化迁移流程，以及如何通过测试步骤确保现有应用数据依然可访问。
</Note>

无需耗费数月从零构建身份验证，Replit Auth 只需一条 Agent prompt 就能为你带来企业级能力。它采用与财富 500 强企业相同的基础设施 —— Firebase、Google Cloud Identity Platform、reCAPTCHA、Stytch 和 Clearout —— 专业级安全防护、欺诈防范和全球规模支撑均已内置。

<div id="why-use-replit-auth">
  ## 为什么使用 Replit Auth
</div>

身份验证是一个颇具挑战的难题，甚至有整家公司专门致力于解决它。而你的应用的核心目的多半并不是身份验证，而是你正在打造的那个独特创意或解决方案。

Replit Auth 提供：

* **零配置** —— 在 Agent 中用一句 prompt 即可添加身份验证
* **Replit 账户集成** —— 用户使用已有的 Replit 账户登录，无需单独注册账户
* **内置安全防护** —— 基于 Replit 的基础设施，可防范常见攻击
* **用户管理** —— 通过 Auth 面板简化用户管理
* **数据库集成** —— 自动在你的数据库中创建用户记录
* **可自定义的登录页面** —— 为你的应用打造个性化登录体验 (含 Replit 品牌标识)
* **密码重置** —— Replit 代你发送密码重置邮件，你无需自行搭建邮件发送服务
* **推荐计划** —— 通过 Replit Auth 注册的用户会计入你待处理的 Replit Referrals
* **开发环境与已发布应用** —— Replit Auth 在开发环境 (replit.dev) 和已发布应用 (replit.app 及自定义域名) 中均可无缝使用

<div id="enterprise-grade-infrastructure">
  ## 企业级基础设施
</div>

Replit Auth 不只是简单的用户管理，而是构建在企业级基础设施之上的全托管身份验证方案。这一强大组合让你的应用拥有与财富 500 强企业同等的身份验证能力：

* **Firebase 与 Google Cloud Identity Platform** —— 企业级 SLA，依托 Google 久经考验的身份验证基础设施
* **高级安全扫描** —— 集成 reCAPTCHA，自动防御机器人与恶意攻击者
* **欺诈防护** —— 由 Clearout 提供邮箱验证与校验，杜绝虚假账户
* **多因素身份验证** —— 基于 Stytch 企业级身份验证平台的安全登录选项
* **全球规模** —— 支持自动扩缩容与高可靠性，可承载数百万用户

有了这一企业级基础，你可以专心打造应用的特色功能，同时确信支撑你身份验证的，正是守护着千亿级企业的那套基础设施。无需耗费数月对接多项服务，一条 Agent prompt 即可获得上述全部能力。

<div id="getting-started-with-replit-auth">
  ## Replit Auth 入门
</div>

实现 Replit Auth 的唯一方式是使用 Agent。只需在 prompt 中提出使用 Replit Auth 的需求即可：

```
帮我创建一个应用，实现 [你的应用创意]，并且需要使用 Replit Auth。
```

Agent 会为身份验证配置好所有必要的代码和设置。目前不支持手动实现，因为 Agent 已为你处理了所有复杂环节。

<div id="customizing-the-login-page">
  ## 自定义登录页面
</div>

<Frame>
  <img src="/assets/mirror/auth-login-1ee0460c3780.jpg" alt="Auth configuration" width="1920" height="1080" data-path="images/workspace/auth/auth-login.jpg" />
</Frame>

你可以自定义登录页面，使其与应用的品牌风格保持一致：

1. 在 Project Editor 中打开 Auth 面板
2. 点击 **Configure**
3. 自定义以下元素：
   * 应用名称
   * 应用图标
   * 登录方式 (Google、GitHub、X、Apple、电子邮件)

所做更改会立即在应用的登录页面上生效。

<div id="security-considerations">
  ## 安全注意事项
</div>

Replit Auth 依托 Replit 的基础设施，内置了针对常见安全威胁的防护。不过，你仍应遵循以下最佳实践：

* 执行敏感操作前，务必在服务端验证用户身份
* 切勿在代码中存储密码等敏感信息
* 使用环境变量保存 API 密钥等各类密钥
* 为用户数据设置恰当的访问控制

有关安全的更多信息，请参阅：

* [Replit 内置的安全功能](/zh/features/security/overview)
* [氛围编程安全清单](/zh/learn/security-checklist)
* [Secrets 管理](/zh/core-concepts/project-editor/app-setup/secrets)

<div id="referrals">
  ## 推荐奖励
</div>

为鼓励开发能让更多人了解 Replit 的应用，任何通过 Replit Auth 注册的用户都会自动进入你的待确认 Replit Referrals。如果他们之后升级到 Replit Core，你将按照推荐计划的现行条款获得相应的推荐奖励。

<div id="troubleshooting">
  ## 故障排查
</div>

<div id="common-issues">
  ### 常见问题
</div>

1. **登录后无法识别用户**
   * 如果遇到问题，可以请 [Replit Agent](/zh/features/agent/overview) 帮你调试身份验证的实现。

2. **自定义图标不显示**
   * 请确认图标 URL 可正常访问，且格式受支持 (PNG 或 JPG) 。

3. **新关联的自定义域名不生效**
   * 重新发布以刷新域名列表 (REPLIT&#95;DOMAINS 环境变量) 。
