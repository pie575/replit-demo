<Note>
  Административный API находится в стадии **бета-тестирования**. Набор доступных эндпоинтов и их поведение могут измениться.
</Note>

Административный API предоставляет администраторам аккаунтов Enterprise программный доступ к аналитике и функциям управления аккаунтом с разграничением по областям доступа (scopes). С его помощью можно строить внутреннюю отчетность, операционные рабочие процессы и интеграции для аккаунтов Enterprise.

<div id="api">
  ## Пользователи с доступом к административному API
</div>

Административный API доступен только **администраторам аккаунта** Enterprise. Они могут создавать API-ключи и управлять ими. Администраторы рабочих пространств и другие участники аккаунта не могут получить доступ к административному API или создавать такие ключи.

Подробнее о роли администратора Enterprise см. в разделе [Администраторы аккаунта и рабочего пространства](/ru/ko/teams/identity-and-access-management/account-and-workspace-admins).

<div id="api-2">
  ## Создание API-ключа
</div>

<Steps>
  <Step title="Откройте настройки разработчика">
    Откройте **Settings**. В разделе **Account** выберите **Developer**.
  </Step>

  <Step title="Создайте API-ключ">
    Выберите **Generate API key** и укажите тип доступа: только чтение либо чтение и запись.
  </Step>

  <Step title="Сохраните ключ в безопасном месте">
    Скопируйте ключ, начинающийся с `rpl_`, и сохраните его в надёжном менеджере секретов. Относитесь к нему как к паролю и никогда никому его не передавайте.
  </Step>

  <Step title="Аутентификация интеграции">
    Передавайте ключ в API-запросах как Bearer-токен.
  </Step>
</Steps>

<div id="section">
  ## Что можно сделать
</div>

Административный API использует области доступа (scopes), чтобы определять, какие действия доступны каждому ключу. Области чтения дают доступ к данным аккаунта для отчётности, а отдельные области записи позволяют выполнять такие операции, как обновление бюджетов.

* **Usage:** чтение данных об использовании аккаунта и общих расходов по журналу с фильтрацией или группировкой по рабочим пространствам, участникам, проектам или периодам времени.
* **Рабочие пространства:** чтение списка и сведений о рабочих пространствах, включая количество участников и проектов, администраторов и время создания.
* **Участники:** чтение членства в аккаунте и рабочих пространствах с фильтрацией по ролям или поиском по имени, имени пользователя и адресу электронной почты.
* **Проекты:** чтение проектов во всех рабочих пространствах команды с фильтрацией по публичности или статусу деплоя, а также поиском по названию, слагу и описанию.
* **Бюджеты:** чтение бюджетов аккаунта и их обновление с помощью области `write:budgets`.

Ответы API поддерживают курсорную пагинацию и содержат заголовки ограничения частоты запросов, а также `X-Request-Id` для отслеживания запросов.

<div id="section-2">
  ## Создание отчетов и рабочих процессов
</div>

Используйте данные административного API везде, где вы уже отслеживаете работу: во внутренних панелях управления, в уведомлениях Slack, в ежемесячных финансовых отчетах. Например, можно группировать Usage по рабочим пространствам и отчитываться о расходах каждого из них.

<div id="replit-agent">
  ## Создание с помощью Replit Agent
</div>

Вы можете попросить Replit Agent создать собственную панель управления на основе административного API. Опишите данные аккаунта, которые хотите отслеживать, — например, Usage по рабочим пространствам или расходы по проектам, — и Agent создаст панель и необходимую интеграцию с API.

<Steps>
  <Step title="Откройте инструмент выбора навыков">
    В проекте Replit нажмите кнопку **+** рядом с полем ввода чата и выберите **Use skill**.
  </Step>

  <Step title="Выберите навык административного API">
    В разделе **Replit skills** выберите **административный API**, чтобы предоставить Agent контекст по API и руководство по интеграции.
  </Step>

  <Step title="Опишите панель управления">
    Расскажите Agent, что вы хотите отслеживать и в каком виде это должно отображаться. Например, попросите Agent создать панель с Usage по рабочим пространствам и расходами по проектам.
  </Step>

  <Step title="Безопасно добавьте API-ключ">
    Когда Agent потребуется выполнять запросы к API, добавьте API-ключ административного API в секреты проекта. Не вставляйте ключ в чат и не коммитьте его в проект.
  </Step>
</Steps>
