Suivez ce guide pour migrer une application existante de [Replit Auth](/fr/features/auth-and-identity/authentication) vers [Clerk Auth](/fr/features/auth-and-identity/clerk-auth). Agent se charge de la migration pour les applications éligibles : les utilisateurs qui reviennent conservent ainsi l&#39;accès à leurs données existantes.

<Note>
  Cette migration automatisée est réservée aux applications qui utilisent Replit Auth. Si votre application utilise un autre système d&#39;authentification, n&#39;utilisez pas cette procédure.
</Note>

<div id="start-the-migration">
  ## Démarrer la migration
</div>

Les migrations Agent doivent toujours s&#39;exécuter dans une nouvelle tâche.

Vous pouvez démarrer la migration de deux façons :

  ### Démarrer depuis Agent

<Steps>

<div id="review-the-migration-plan">
  ### Examiner le plan de migration
</div>

Quelle que soit la méthode choisie, Agent crée la tâche **Migrate from Replit Auth to Clerk** et prépare le plan de migration. Sélectionnez **View plan** et examinez le plan avant de laisser la tâche se poursuivre.

<Frame caption="La tâche Migrate from Replit Auth to Clerk débute par une action View plan qui vous permet d'examiner le playbook de migration.">
  <img src="/assets/mirror/replit-auth-to-clerk-task-998d61b55c3d.png" alt="Tâche Agent intitulée Migrate from Replit Auth to Clerk avec un bouton View plan et une activité d'examen du playbook de migration" width="575" height="900" data-path="images/workspace/auth/replit-auth-to-clerk-task.png" />
</Frame>

Ne modifiez pas le code d&#39;authentification de votre application ni vos identifiants Clerk pendant qu&#39;Agent travaille.

<div id="what-agent-does">
  ## Ce que fait Agent
</div>

Agent effectue la migration dans cet ordre :

1. Il transfère vos données utilisateur Replit Auth vers Clerk, y compris les informations d&#39;identité des comptes et les identifiants de connexion pris en charge.
2. Il attend la fin de la migration des données avant de modifier votre app.
3. Il met à jour la logique de connexion et de session de votre app, redémarre l&#39;app et exécute les vérifications automatisées disponibles.

<div id="your-app-data-stays-in-place">
  ## Les données de votre app restent en place
</div>

Agent modifie uniquement le code d&#39;authentification de votre app. Il ne touche ni aux données ni au schéma de la base de données existante de votre app. Vos tables et vos relations restent intactes.

Vos utilisateurs existants restent rattachés aux enregistrements qui leur appartiennent déjà, comme les profils, le travail enregistré et les permissions.

<div id="how-long-it-takes">
  ## Durée de l&#39;opération
</div>

Prévoyez entre 10 minutes et une heure de travail pour Agent. La migration des données à elle seule peut prendre quelques minutes pour les petites applications, et jusqu&#39;à deux ou trois heures pour celles comptant de nombreux utilisateurs. Agent ne commence à modifier le code de votre application qu&#39;une fois cette migration terminée.

<div id="after-the-migration">
  ## Après la migration
</div>

Avant de publier, testez l&#39;application mise à jour dans l&#39;environnement de développement :

1. Connectez-vous avec un compte existant et vérifiez que ses données enregistrées sont bien disponibles.
2. Déconnectez-vous, puis reconnectez-vous.
3. Créez un compte de test et vérifiez qu&#39;il permet d&#39;utiliser l&#39;application comme prévu.
