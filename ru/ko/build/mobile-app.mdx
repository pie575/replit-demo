      return null;

  };
  const ensureAgentInputTypewriterCore = () => {
    if (typeof window === "undefined" || typeof document === "undefined") {
      return Promise.resolve(null);
    }
    if (window.Typewriter) {
      return Promise.resolve(window.Typewriter);
    }
    const loader = getAgentInputTypewriterLoader();
    if (loader.promise) {
      return loader.promise;
    }
    loader.promise = new Promise((resolve, reject) => {
      const handleLoad = () => {
        if (window.Typewriter) {
          resolve(window.Typewriter);
          return;
        }
        loader.promise = null;
        reject(new Error("Typewriter core loaded without a global Typewriter export."));
      };

        loader.promise = null;
        reject(new Error("Failed to load typewriter core."));

* Не закрывает ли клавиатура важные поля.
* Остаётся ли приложение понятным и полезным на маленьком экране.

Если что-то кажется неудобным, попросите Agent исправить конкретную часть, а не полностью перерабатывать приложение.

<AiPrompt>
  Улучши Pace Mobile для использования одной рукой на телефоне.<br />
  Сделай кнопку Save Run более доступной, при необходимости увеличь области нажатия и сохрани простоту формы пробежки.<br />
  Не добавляй новые функции.<br />
  После изменения проверь, что сохранение пробежки по-прежнему обновляет сегодняшнюю сводку.
</AiPrompt>

<div id="section-9">
  ## Поделитесь приложением для сбора обратной связи
</div>

Когда мобильный сценарий будет готов, опубликуйте приложение, чтобы создать версию для Expo Go, которой можно поделиться для сбора первых отзывов.

Поделитесь им, предложив выполнить одну конкретную задачу:

> Откройте Pace Mobile на телефоне, сохраните одну пробежку и сообщите, если что-то неудобно нажимать, читать или понимать.

Сфокусированную обратную связь проще использовать, чем общие впечатления. Если отзыв указывает на одну конкретную проблему, попросите Agent внести минимальное исправление и снова протестируйте приложение на телефоне.

<div id="section-10">
  ## Публикация в App Store
</div>

Протестировав Pace Mobile в симуляторе и на телефоне с помощью Expo Go, вы можете отправить это же приложение в TestFlight и App Store. Для этого потребуется учётная запись участника **Apple Developer Program** с включённой двухфакторной аутентификацией. Подробнее о регистрации, личных и организационных учётных записях, проверке в TestFlight и App Store, а также внешнем тестировании см. в разделе [Создание и выпуск мобильных приложений](/ru/ko/build/mobile-app).

<Steps>
  <Step title="Откройте вкладку Publishing и начните публикацию в App Store">

    </Frame>
  </Step>

  <Step title="Выберите проект Expo">
    Replit откроет **Launch** — встроенный в Replit процесс Expo. Введите или проверьте название и слаг проекта Expo, затем нажмите **Continue**. Если у вас уже есть проект Expo, выберите **Use existing**.

      <img src="/assets/mirror/app-store-03-choose-expo-project-4707fafffafe.png" alt="Диалоговое окно Launch с активным шагом Choose Expo project: поля названия и слага проекта, предварительно заполненные значением Pace, кнопка Continue и вариант Use existing" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-03-choose-expo-project.png" />
    </Frame>
  </Step>

  <Step title="Вход через Apple">
    Подключите учётную запись Apple Developer, которая будет владеть карточкой приложения в App Store. Учётная запись должна быть зарегистрирована в Apple Developer Program. Apple использует двухфакторную аутентификацию, поэтому будьте готовы подтвердить код на доверенном устройстве.

    <Frame>
      <img src="/assets/mirror/app-store-04-sign-in-apple-459dfc9b84ba.png" alt="Диалоговое окно Launch на этапе «Войти с Apple» — поля для электронной почты или номера телефона Apple Developer и пароля, примечание о том, что пароль не покидает устройство, а учётная запись должна быть зарегистрирована в Apple Developer Program" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-04-sign-in-apple.png" />

  </Step>

<Note>
  Первая сборка новой версии обычно должна пройти бета-проверку TestFlight, прежде чем её смогут установить тестировщики. После одобрения последующие сборки обычно быстрее становятся доступны тестировщикам. Чтобы поделиться приложением с внешними тестировщиками или отправить его на публикацию в App Store, заполните страницу приложения в **App Store Connect**. Полный контрольный список для App Store Connect см. в разделе [Создание и выпуск мобильных приложений](/ru/ko/build/mobile-app).
</Note>

<div id="section-13">
  ## Нужна дополнительная помощь?
</div>

* **Если Agent создаёт веб-приложение:** начните заново и перед сборкой выберите тип приложения **Mobile app**.
* **Если предпросмотр Expo Go устарел:** встряхните телефон, откройте меню разработчика и выберите **Refresh**.
* **Если области касания кажутся слишком маленькими:** попросите Agent увеличить их и разместить основные действия в зоне досягаемости большого пальца.
* **Если навигация кажется сложной:** попросите Agent сократить приложение до минимального набора экранов для основного сценария.
* **Если симулятор работает, а телефон — нет:** протестируйте функции, зависящие от аппаратного обеспечения, на реальном устройстве и ознакомьтесь с разделом [нативные мобильные приложения](/ru/ko/features/artifact-types/building-mobile-apps).
* **Если публикация не удаётся:** ознакомьтесь с разделом [устранение неполадок мобильных приложений](/ru/ko/features/troubleshooting/mobile-app).
