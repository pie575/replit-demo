Сбои случаются: неудачное изменение схемы, удалённые строки, сессия Agent, которая пошла не по плану. Replit предлагает подходящий способ восстановления для каждой базы данных.

| База данных | Способ восстановления                                            | Доступно в тарифах                                                            |
| ----------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Разработка  | Откат к чекпоинту                                                | Все тарифы                                                                    |
| Рабочая     | Восстановление на момент времени и резервные копии по расписанию | Core: история до 7 дней. Pro и Enterprise: до 28 дней (по умолчанию 7 дней). |

<div id="section">
  ## Восстановление базы данных разработки
</div>

С помощью [функции отката](/ru/ja/features/version-control/checkpoints-and-rollbacks/) вы можете вернуть приложение и базу данных разработки к предыдущему состоянию. База данных будет восстановлена до состояния любого чекпоинта, созданного Agent.

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="Интерфейс отката к чекпоинту с отображением параметров отката" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

<Info>
  При откате к состоянию чекпоинта обязательно выберите «Database» в разделе «Additional rollback options». Это вернёт базу данных к состоянию на момент создания чекпоинта.
</Info>

<div id="section-2">
  ## Восстановление продакшен-базы данных
</div>

Продакшен-базу данных можно восстановить на определённый момент времени с помощью функции восстановления на момент времени (point-in-time restore).

<Frame>
  <img src="/assets/mirror/database-rollbacks-f13dd20874ae.jpg" alt="Интерфейс отката базы данных с параметрами отката" width="1082" height="708" data-path="images/databases/database-rollbacks.jpg" />
</Frame>

Глубина восстановления зависит от вашего тарифного плана и настроек хранения. Core хранит историю до 7 дней, Pro и Enterprise — до 28 дней. На всех планах по умолчанию установлено 7 дней, и этот период можно изменить в настройках продакшен-базы данных. Чем больше срок хранения, тем больше используется хранилища, а значит, и выше стоимость. При переходе с Pro на Core срок хранения сокращается до 7 дней.

<Warning>
  Восстановление базы данных не восстанавливает код приложения, а откат приложения не восстанавливает базу данных. Чтобы вернуть и то и другое к одному и тому же моменту времени, восстановите базу данных, затем [выполните откат к соответствующему чекпоинту](/ru/ja/features/version-control/checkpoints-and-rollbacks/) и заново опубликуйте приложение.
</Warning>

<div id="section-3">
  ## Планирование резервного копирования по расписанию продакшен-базы данных
</div>

Резервное копирование по расписанию создаёт одну полную точку восстановления в день. При включении или изменении расписания Replit назначает резервное копирование на время около полуночи по текущему часовому поясу браузера.

1. Откройте инструмент **Database** и выберите продакшен-базу данных.
2. Откройте **Settings** и разверните раздел **Scheduled backups** в блоке **Advanced**.
3. Чтобы включить резервное копирование по расписанию, выберите срок хранения в поле **Keep backups for**.

Доступные сроки хранения зависят от тарифного плана: Core поддерживает до 7 дней, а Pro и Enterprise — до 28 дней.

<div id="section-4">
  ### Стоимость хранения
</div>

Replit тарифицирует использование отдельно по каждой категории хранилища продакшен-базы данных:

| Категория хранилища                               | Стоимость за ГиБ в месяц |
| ------------------------------------------------- | -----------------------: |
| Логическое хранилище базы данных                  |                    $0.35 |
| Хранилище восстановления на момент времени (PITR) |                    $0.20 |
| Хранилище резервных копий по расписанию           |                    $0.09 |

<Note>В настоящее время на хранилище базы данных действует скидка 100%.</Note>

Тариф $0.35 за логическое хранилище применяется при использовании PITR, резервных копий по расписанию или того и другого одновременно. Хранилище резервных копий по расписанию обходится дешевле за ГиБ, чем хранилище PITR. Если вам достаточно ежедневных точек восстановления, сократите окно PITR и используйте резервные копии по расписанию — это снизит затраты на хранилище для восстановления. Итоговая стоимость резервного копирования зависит от объёма хранимых копий и срока их хранения.

PITR даёт больше точек восстановления в пределах своего окна, а резервные копии по расписанию — одну точку восстановления в сутки, поэтому выбирайте способ восстановления, который отвечает вашим задачам.

<Note>
  Расписание использует текущее смещение UTC. Из-за перехода на летнее время резервное копирование может выполняться на час раньше или позже, пока вы не обновите расписание. Для часовых поясов с дробным смещением используется ближайший час.
</Note>

<div id="section-5">
  ### Восстановление из резервной копии по расписанию
</div>

1. В настройках продакшен-базы данных откройте **Scheduled backups**.
2. Выберите **View all backups**.
3. Выберите **Restore** рядом с нужной точкой восстановления.
4. Введите `restore` и выберите **Continue**.

После запуска восстановления база данных переключится на данные из выбранной резервной копии. Текущие данные не удаляются, но подключённым сервисам может потребоваться временное переподключение.

<div id="section-6">
  ## Устранение неполадок при сбое публикации
</div>

Если публикация завершилась сбоем из-за проблем с базой данных:

1. **Проверьте журналы публикации** на наличие конкретных сообщений об ошибках подключения к базе данных или конфликтов схемы
2. **Просмотрите последние изменения схемы**, чтобы выявить возможные конфликты с существующим кодом приложения
3. **Протестируйте изменения в предпросмотре развертывания**, прежде чем publishing снова
