Ashby filtre déjà les candidatures entrantes. Ce flux de travail, lui, est sortant : lire la description
du poste dans Drive, trouver des ingénieurs correspondant au profil sur GitHub, écarter les personnes
déjà présentes dans Ashby et rédiger un message de prospection que vous n&#39;aurez plus qu&#39;à
envoyer. Agent enregistre chaque nouvelle personne comme sourcée, avec une courte explication de
son adéquation et un brouillon rattaché au candidat. Vous relisez et vous envoyez. N&#39;en faites
pas votre unique critère de recrutement.

<div id="best-for">
  ## Idéal pour
</div>

* Les recruteurs techniques qui ont besoin d&#39;une liste de candidats sourcés lorsque le volume de candidatures entrantes est trop faible.
* Les responsables du recrutement qui recherchent des ingénieurs correspondant à leurs critères sur GitHub, sans y passer leurs journées.

<div id="before-you-start">
  ## Avant de commencer
</div>

Préparez une description de poste distinguant les critères indispensables des critères souhaitables. Connectez Drive, GitHub et Ashby. Précisez le lieu,
le niveau d&#39;expérience et le nombre de profils souhaités. Ne fondez pas votre décision d&#39;embauche uniquement sur cet outil.

<div id="prompt-the-agent">
  ## Créez un prompt pour l&#39;agent
</div>

<AiPrompt>
  Crée une Routine qui s&#39;exécute chaque lundi à 9h00. À partir de cette fiche de
  poste [lien Drive ou copier-coller], trouve 30 ingénieurs sur GitHub qui
  correspondent aux critères indispensables. Ignore les personnes déjà présentes
  dans Ashby. Pour chaque personne, rédige 3 lignes expliquant pourquoi son
  profil convient, ainsi qu&#39;un court brouillon de message de prospection.
  N&#39;envoie rien. Ajoute les nouvelles personnes dans Ashby avec le statut sourcé,
  en joignant la note et le brouillon à la fiche du candidat.
</AiPrompt>

<div id="what-to-expect">
  ## À quoi s&#39;attendre
</div>

Agent lit la description de poste, effectue des recherches sur GitHub, écarte les personnes déjà présentes dans Ashby et
renvoie une liste restreinte accompagnée de brouillons. Vous relisez et vous envoyez. Le premier résultat manquera de précision.
Affinez les critères indispensables après l&#39;avoir consulté. Ouvrez trois profils GitHub de la liste, vérifiez qu&#39;ils
correspondent aux critères indispensables et assurez-vous que ces personnes ne figurent pas déjà dans Ashby avant d&#39;envoyer
quoi que ce soit.

<div id="troubleshooting">
  ## Dépannage
</div>

* **La liste restreinte manque de précision :** resserrez la distinction entre critères indispensables et critères souhaitables après le premier passage. Demandez des commits récents dans un langage ou un type de dépôt précis, et écartez les personnes qui semblent être des clients actuels ou des employés de concurrents.
* **Des personnes déjà présentes dans Ashby apparaissent encore :** vérifiez qu&#39;Ashby est bien connecté au bon workspace et qu&#39;Agent effectue la correspondance sur l&#39;adresse e-mail ou le nom d&#39;utilisateur GitHub, et pas uniquement sur le nom affiché.
* **Des messages de prospection sont partis :** ce flux de travail doit uniquement rédiger des brouillons. Si quoi que ce soit a été envoyé, arrêtez la routine et indiquez à Agent de ne jamais envoyer d&#39;e-mail ni de message aux candidats.
