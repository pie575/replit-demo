description: "了解 Clerk Auth 如何为 Replit 应用提供支持自定义品牌形象、独立用户账户和 SSO 身份提供方的专用身份验证系统。"
---

Clerk Auth 为你的应用提供由 [Clerk](https://clerk.com) 提供支持的专用身份验证系统。与使用 Replit 登录系统并创建 Replit 账户的 [Replit Auth](/zh/ko/features/auth-and-identity/authentication) 不同，Clerk Auth 会为你的应用预配**独立的 Clerk 租户**。应用用户直接在应用内创建账户，而不是使用 Replit 账户；你可以完全掌控品牌形象、登录方式和登录体验。

  <video autoPlay muted loop playsInline src="/assets/mirror/auth-vid-e89aaccd245e.mp4" />
</Frame>

<Note>
  **Clerk Auth 与 Replit Auth 对比** — 使用 **Clerk Auth** (本页面) 时，你的应用将获得专用身份验证租户，并拥有可完全自定义的品牌形象以及独立于 Replit 的用户账户。使用 **[Replit Auth](/zh/ko/features/auth-and-identity/authentication)** 时，用户通过 Replit 账户登录，并会看到带有 Replit 品牌形象的登录页面。如果你希望为登录体验应用自己的品牌形象，或需要独立于 Replit 的用户账户，请选择 Clerk Auth。
</Note>

<div id="clerk-auth-replit-auth">
  ## Clerk Auth 与 Replit Auth 对比一览
</div>

|            | Clerk Auth                      | Replit Auth                 |
| ---------- | ------------------------------- | --------------------------- |
| **用户账户**   | 用户在应用内创建账户 (无需 Replit 账户)       | 用户使用 Replit 账户登录            |
| **品牌形象**   | 可完全自定义 — 应用名称、图标和颜色             | Replit 品牌登录页面               |
| **SSO 凭据** | 使用各提供商自己的 OAuth 凭据              | 使用 Replit 的共享 OAuth 应用      |
| **环境**     | 独立的 开发环境与生产环境 | 单一环境                        |
| **推荐**     | 不支持 Replit Referrals 集成         | 注册会计入 Replit Referrals      |
| **适用对象**   | 定制品牌应用、专业或商业产品                  | 希望快速完成设置且可接受 Replit 品牌形象的应用 |

<div id="section">
  ## 开始使用
</div>

要为应用添加 Clerk Auth，请在 Agent 提示词中包含它。

```
请创建一个实现[您的应用创意]并包含 Clerk Auth 功能的应用。
```

Agent 会处理所有事项，包括创建 Clerk 租户、保存凭据、配置路由和添加中间件。无需 Clerk 账户，也无需手动设置。

<div id="clerk-auth-replit">
  ## Clerk Auth 如何与 Replit 配合使用
</div>

当 Agent 为你的应用配置 Clerk Auth 时，会执行以下操作：

1. **创建专用 Clerk 租户** — 你的应用将拥有自己的 Clerk 应用，并配备独立的 开发环境与生产环境
2. **预配凭据** — API 密钥和机密信息会存储为环境变量
3. **配置代理** — 确保身份验证可在已发布的域名上顺畅运行
4. **设置登录和注册路由** — 将预构建的 Clerk React 组件添加到你的应用中
5. **添加服务端中间件** — 使用 Clerk 的 Express 中间件保护 API 路由

<Note>
  你无需创建 Clerk 账户或管理基础设施。一切均由 Replit 自动管理。
</Note>

<div id="section-2">
  ## 功能
</div>

<div id="section-3">
  ### 支持的功能
</div>

Clerk Auth 为 App 提供以下功能：

* **独立的用户账户** — App 用户并非 Replit 用户，仅存在于该 App 的 Clerk 租户中
* **完全品牌化的登录页面** — 可在 App 代码中配置登录和注册页面的 App 名称、徽标、颜色、字体和文案
* **自定义品牌 SSO** — 为各提供商提供自己的 OAuth 凭据后，提供商的 OAuth 同意页面将显示 App 的名称和品牌形象，而非通用默认值
* **电子邮件和密码认证** — 内置注册和登录功能，包括电子邮件验证
* **社交登录 (SSO)** — 可通过 Google、GitHub、Apple 和 X (Twitter) 登录
* **用户管理** — 在 Auth 面板中查看、搜索和管理用户
* **会话管理** — 自动管理的安全会话令牌
* **开发环境与生产环境** — 在正式上线前，在开发环境中测试认证

<Note>
  大多数 Clerk Auth 配置都可在 Project Editor 的 **Auth** 工具中管理 — 无需 Clerk 账户，也无需使用 Clerk 控制台。
</Note>

<div id="section-4">
  ### 暂不支持的功能
</div>

与自行配置的外部 Clerk 应用相比，Clerk Auth 目前不支持以下功能。完整对比请参阅[此常见问题](#how-does-clerk-auth-compare-to-external-clerk)。

* **使用电话号码登录** — 基于短信的登录和身份验证
* **支持 MFA** — 面向终端用户的多重身份验证
* **支持所有 SSO 身份提供方** — 目前仅支持 Google、GitHub、Apple 和 X
* **组织租户** — Clerk 的组织和团队成员资格功能

<div id="development-production">
  ## 开发环境与生产环境
</div>

所有启用了 Clerk Auth 的应用都会拥有两个完全隔离的 Clerk 环境：用于在构建期间运行开发版/预览版应用的 **Development** 环境，以及用于运行已发布应用的 **Production** 环境。这些环境有意保持隔离——各自拥有独立的 API 密钥和用户存储。

<div id="api">
  ### 独立的 API 密钥
</div>

每个环境都有各自的可发布密钥和 secret API 密钥。应用使用的密钥会根据其是在开发环境还是生产环境中运行而自动切换。

* 在 workspace 中，`CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY` Secrets 存储的是指向 Development 环境的**测试密钥** (`pk_test...` 和 `sk_test...`) 。

<Frame>
  <img src="/assets/mirror/clerk-check-dev-keys-5a23f6b7dd0c.png" alt="workspace 的 Secrets 工具中显示带有 sk_test_ 和 pk_test_ 前缀的 CLERK_SECRET_KEY 和 CLERK_PUBLISHABLE_KEY" width="1946" height="402" data-path="images/workspace/auth/clerk-check-dev-keys.png" />
</Frame>

* 发布应用后，已发布的部署会使用指向 Production 环境的**正式密钥** (`pk_live...` 和 `sk_live...`) 运行。要检查前缀，请打开 **Publishing → Overview → Adjust settings**，然后查看 `CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY`。

<Frame>
  <img src="/assets/mirror/clerk-check-prod-keys-acccd7f68da1.png" alt="Publishing Overview 中 Production 应用的 Secrets，显示带有 sk_live_ 和 pk_live_ 前缀的 CLERK_SECRET_KEY 和 CLERK_PUBLISHABLE_KEY" width="1924" height="1664" data-path="images/workspace/auth/clerk-check-prod-keys.png" />
</Frame>

<Note>
  无需额外操作即可切换环境 — Replit 会自动管理 Development 和 Production 的密钥。只需开发、测试并发布即可。
</Note>

<Warning>
  请勿将测试密钥替换为正式密钥、在 Secrets 面板中修改密钥，或直接在 Clerk 控制台中更改设置。否则会破坏开发/生产环境的自动切换，且 Replit 管理的 Clerk Auth 不支持此操作。
</Warning>

<div id="section-5">
  ### 独立的用户存储
</div>

每个环境都有各自的用户存储。在 Development 环境中注册的账户**不会**出现在 Production 环境中，反之亦然。

* 在开发/预览应用中测试时注册的用户，只会创建在 Development 存储中。
* 在已发布的应用中注册的用户，只会创建在 Production 存储中。
* 会话、用户元数据，以及所有以 Clerk `userId` 为键的数据，同样仅限于账户创建时所在的环境。

这是预期行为。要查看各环境中的用户，请在 Workspace 中打开 **Auth 面板**，然后使用 **Users** 标签页中的环境切换开关，在 Development 和 Production 之间切换。

<Note>
  Development 用于实验和构建，Production 则用于为真实应用用户提供服务。两者有意相互隔离，因此在 Development 中创建的账户和数据不会出现在 Production 中。
</Note>

<div id="section-6">
  ## 用户管理
</div>

Project Editor 的 **Auth 面板**可让您全面查看已通过身份验证的用户。Clerk Auth 会为应用创建独立的用户存储，因此此处列出的用户属于应用账户，而非 Replit 账户。

<Frame>
  <img src="/assets/mirror/clerk-users-4940ed365605.png" alt="Auth 面板中的 Clerk Auth Users 选项卡显示已通过身份验证的用户" width="2136" height="794" data-path="images/workspace/auth/clerk-users.png" />
</Frame>

在 **Users** 标签页中，您可以：

* 查看**所有用户**及其详细信息，包括电子邮件、姓名、上次登录时间和账户创建日期
* **搜索和筛选**特定用户
* **阻止或解除阻止用户**，以控制应用访问权限
* 按不同条件**对用户排序**
* **切换环境** — 在 Development 和 Production 之间切换，管理各环境中的用户

<div id="section-7">
  ## 自定义登录页面
</div>

登录和注册页面的视觉品牌形象 (包括应用名称、徽标、颜色、字体和文案) 在应用代码中配置，而不是在 Auth 面板中。若要更改，请向 Agent 提出请求。

```
将登录页面的标题改为[应用名称]，使用[徽标说明]，并调整为与网站配色相协调的样式。
```

在内部，这是通过传递给 `<ClerkProvider>` 的 `appearance` 和 `localization` prop，以及应用 `public/` 目录中的徽标文件实现的。Agent 会让这些内容与应用其余部分的主题保持同步。

<Note>
  **Google、Apple、GitHub、X 自身的授权同意页面** (用户点击“Sign in with Google”等选项后显示的页面) 中显示的应用名称是单独设置的——它来自在相应身份提供方处注册的 OAuth 应用，修改登录页面代码也**不会更改**它。要更改此名称，请为相应身份提供方配置[自定义 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
</Note>

<div id="section-8">
  ## 配置登录身份提供方
</div>

Clerk Auth 支持将 Google、GitHub、Apple 和 X 用作社交登录身份提供方。在 Auth 面板的 **Configure** 标签页中，你可以控制登录页面显示哪些身份提供方，以及 — 在 Production 环境中 — 每个身份提供方是使用由 Replit 管理的 OAuth 凭据，还是使用你自己的自定义凭据实现品牌化登录。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" alt="Configure 标签页，侧边栏显示 SSO providers 且已选择 Production，主面板列出身份提供方并提供启用开关和 Edit 操作" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

打开 **Configure** 标签页。在侧边栏的 **SSO providers** 下，选择 **Development** 或 **Production** — **Development** 用于 Workspace 中的开发和预览 App，**Production** 用于已发布的 App。每个环境都会在主面板中显示各自的列表。你可以在此执行以下操作：

* **启用或停用身份提供方** — 使用开关控制身份提供方是否显示在登录页面上。停用的身份提供方将对用户隐藏。
* **配置自定义 OAuth 凭据 (仅限 Production)&#x20;**&#x20;— 请参阅下方的[为 SSO 身份提供方配置 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。

<div id="sso-oauth">
  ### 配置 SSO 身份提供方的 OAuth 凭据
</div>

默认情况下，身份提供方使用 **Replit-managed credentials**。登录无需额外配置即可使用，但 OAuth 同意页面会显示 Replit 品牌形象。若要使用在身份提供方开发者控制台中创建的 OAuth 客户端，请切换至 **Custom credentials**，以便在同意页面显示应用名称和品牌形象。

1. 在 Project Editor 中打开 **Auth 面板**。前往 **Configure** 标签页，然后在侧边栏的 **SSO providers** 中选择 **Production**。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

2. 选择要配置的身份提供方旁的 **Edit** 图标。默认选中 **Replit-managed credentials**。

<Frame>
  <img src="/assets/mirror/clerk-sso-default-credentials-525090775408.png" alt="显示 Replit-managed credentials 和 Custom credentials 选项的身份提供方编辑面板" width="1468" height="960" data-path="images/workspace/auth/clerk-sso-default-credentials.png" />
</Frame>

3. 选择 **Custom credentials**。面板将展开，显示凭据字段和 **Provider setup** 检查清单，其中包含需要在身份提供方处注册的值。

<Frame>
  <img src="/assets/mirror/clerk-sso-custom-credentials-f24112a5cf07.png" alt="显示 Custom credentials 面板，其中包含 OAuth 客户端 ID 和密钥字段，以及列出重定向回调 URL 和 JavaScript 源的 Provider setup 检查清单" width="1468" height="2246" data-path="images/workspace/auth/clerk-sso-custom-credentials.png" />
</Frame>

4. 按照说明完成设置。说明中包含可直接前往控制台和相关帮助文档的链接。你也可以在该身份提供方的[其他资源](#additional-resources)部分找到这些帮助文档。
5. 输入所有必需的凭据值。
6. 在身份提供方的开发者控制台中，将 **Provider setup** 检查清单列出的所有项目注册到身份提供方的开发者门户。使用复制图标准确复制每个值，并勾选已完成的项目，或完成后选择 **Mark all as done**。
7. 选择 **Save changes**。

<div id="section-9">
  ### 更改域名后重新检查设置
</div>

连接新的外部域名或进行[通过 Replit 购买域名](/zh/ko/build/domain-purchasing)等域名相关操作，可能会更改应用的重定向回调 URL 和 JavaScript 源。在这种情况下，使用自定义凭据配置的身份提供方可能需要在开发者控制台中重新登记这些新值。

更改域名后，请返回 **Configure** 标签页。设置提醒会显示在标签页和侧边栏中，以及 **SSO providers** 列表内身份提供方旁的警告图标上。如果身份提供方旁显示警告图标和 **setup steps remaining** 文案，表示该身份提供方的 **Provider setup** 检查清单中有新的待完成项目。

<Frame>
  <img src="/assets/mirror/clerk-sso-setup-reminders-a5b092846006.png" alt="显示设置提醒的 Configure 标签页和侧边栏，以及更改域名后 SSO providers 列表中显示警告图标和“setup steps remaining”文案" width="923" height="378" data-path="images/workspace/auth/clerk-sso-setup-reminders.png" />
</Frame>

打开身份提供方的编辑面板，复制 **Provider setup** 下更新后的值，并在身份提供方的开发者控制台中登记，然后选择 **Mark all as done**。

<div id="section-10">
  ## 配置用于电子邮件验证的域名
</div>

如果您的应用提供**电子邮件和密码注册**功能，Clerk 会向新用户的收件箱发送验证码。将域名配置为电子邮件发送域名，可确保这些验证码显示为来自您应用的网址，且不会延迟送达或被垃圾邮件筛选器拦截。

<div id="section-11">
  ### 何时需要进行此设置
</div>

仅当你的应用使用由其他服务商管理的**外部域名** (例如在 Cloudflare、GoDaddy、Namecheap 等平台注册的域名) 时，才需要配置 DNS 记录。

如果你的应用通过以下方式提供服务，则无需进行设置：

* `.replit.app` 子域名
* [通过 Replit 购买的](/zh/ko/build/domain-purchasing) 域名

在这两种情况下，Replit 都会代为管理 DNS 记录。

<div id="dns">
  ### 添加用于发送电子邮件的 DNS 记录
</div>

要允许您的应用通过外部域名发送身份验证电子邮件，请在域名服务商处添加一组 DNS 记录。

1. 在 Project Editor 中打开 **Publishing**。
2. 选择 **Domains**。
3. 找到已连接的外部域名，然后选择 **Manage**。
4. 在 **Authentication DNS setup required** 下，复制 Replit 显示的 CNAME 记录 — 这是 Clerk 通过您的域名发送身份验证电子邮件所需的记录。
5. 登录您的 DNS 服务商 (如 Cloudflare、GoDaddy 或 Namecheap) ，并严格按照显示的信息添加每条记录。

<Frame>
  <img src="/assets/mirror/clerk-domain-8797ea9f41fc.png" alt="Domain Manage 面板，其中 Authentication DNS setup required 部分显示了 Clerk 发送电子邮件所需的 CNAME 记录" width="1156" height="1524" data-path="images/workspace/auth/clerk-domain.png" />
</Frame>

DNS 更改最多可能需要 48 小时才能完成传播。记录生效后，用户通过电子邮件和密码注册时，会自动通过您的域名发送身份验证代码 — 无需在 Auth 面板中进行其他操作。

<div id="section-12">
  ### 故障排查
</div>

* **未收到身份验证电子邮件** — 请确认已完全按照 Manage 面板中的说明准确添加所有记录，包括 DNS 提供商要求的末尾点号 (trailing dot) 。同时请检查收件人的垃圾邮件文件夹。
* **仍未检测到记录** — 请等待 DNS 传播完成 (最长可能需要 48 小时) ，然后再次检查 Manage 面板，确认是否仍有记录显示为缺失。

<div id="section-13">
  ## 安全最佳实践
</div>

* **始终在服务端进行验证** — 不仅要在界面中检查身份验证，也要在 API 路由中检查
* **使用环境变量** — 不要在代码中硬编码密钥或机密信息
* **确保代理中间件最先挂载** — 在 Express 应用中，Clerk 代理必须在 body parser 之前挂载
* **不要将首页重定向到登录页面** — 确保未经身份验证的访客也能访问着陆页

<div id="faq">
  ## 常见问题
</div>

<div id="clerk-auth-clerk">
  ### 使用 Clerk Auth 是否需要 Clerk 账户？
</div>

不需要。Agent 在配置应用时，Replit 会自动创建并管理支持 Clerk Auth 所需的 Clerk 租户——无需注册 Clerk，也无需自行管理 Clerk 基础设施。

<div id="replit-clerk-clerk">
  ### 我可以访问由 Replit 管理的 Clerk 实例的 Clerk 控制台吗？
</div>

不可以。由 Replit 管理的 Clerk 实例不会显示在 Clerk 控制台中。请改用 Project Editor 中的 **Auth** 工具进行管理；您可以在其中配置提供商、查看用户，并在 Development 和 Production 环境之间切换。

<div id="clerk-publishable-pk_test">
  ### Clerk 可发布密钥以 `pk_test` 开头。如何切换到正式密钥？
</div>

无需切换。Workspace 的 Secrets 面板中显示的 `pk_test...` 和 `sk_test...` 密钥属于应用的 **Development** Clerk 环境，用于构建过程。发布应用后，部署会自动使用 Production 环境的 `pk_live...` 和 `sk_live...` 密钥。若要确认，请在 Workspace 中打开 **Publishing → Overview → Adjust settings**，查看已发布应用的 `CLERK_PUBLISHABLE_KEY` 值 — 它会以 `pk_live` 开头。请勿手动编辑这些密钥。详见 [Development 和 Production 环境](#development-and-production-environments)。

<div id="section-14">
  ### 为什么无法使用开发期间创建的账户登录已发布的应用？
</div>

Clerk Auth 的 **Development** 和 **Production** 环境拥有彼此独立的用户存储。在开发/预览应用中创建的账户仅存在于 Development 环境中，发布时不会复制到 Production 环境中——你需要在已发布的应用中重新注册。所有以 Clerk `userId` 为键的数据也是如此。在 Workspace 中打开 **Auth 面板**，然后使用 **Users** 标签页中的环境切换按钮查看各环境中的用户。有关详细信息，请参阅[独立的用户存储](#separate-user-stores)。

<div id="clerk-auth">
  ### Clerk Auth 免费吗？
</div>

Clerk Auth 目前免费。与 Replit 的其他按用量计费服务一样，未来可能会引入按用量计费。届时产生的费用将通过现有的 Replit 账单收取，无需单独的 Clerk 账单或付款方式。

<div id="clerk-auth-clerk-mau">
  ### Clerk Auth 是否也像外部 Clerk 플랜一样有 MAU 限制？
</div>

没有。与按套餐限制 MAU 的外部 Clerk 플랜不同，Clerk Auth 不设月活跃用户 (MAU) 限制。

<div id="clerk-auth-clerk-2">
  ### Clerk Auth 与外部 Clerk 相比如何？
</div>

为 Clerk Auth 提供支持的 Replit 托管 Clerk 租户，与您在自己的 Clerk 账户中创建的 Clerk 应用 (**外部 Clerk**) 之间存在一些差异。下表列出了两者当前的区别——这反映了 Clerk Auth 目前的状态，支持的功能范围将持续扩展。

|                 | Clerk Auth                       | 外部 Clerk     |
| --------------- | -------------------------------- | ------------ |
| **设置**          | 由 Replit 自动预配                    | 自行设置         |
| **Clerk 租户所有权** | 由 Replit 管理，归 App 所有             | 归 Clerk 账户所有 |
| **定价结构**        | 当前免费 (未来将按使用量收费)                 | 订阅费 + 按使用量收费 |
| **计费**          | 由 Replit 计费 (当前免费)               | 由 Clerk 账户计费 |
| **MAU 限制**      | 无限制                              | 因套餐而异        |
| **代理和域名配置**     | replit.app 和已购买域名自动配置，已连接域名需手动配置 | 手动           |
| **SSO 身份提供方**     | 仅支持特定提供商：Google、Apple、GitHub、X   | 支持更多提供商      |
| **用户管理界面**      | Project Editor 中的 Auth 工具        | Clerk 应用仪表板  |
| **SMS**         | 不支持                              | 支持           |
| **MFA**         | 不支持                              | 支持           |
| **组织租户**        | 不支持                              | 支持           |

<div id="clerk-auth-2">
  ### 哪些常见的 Clerk Auth 设置需要手动完成？
</div>

大多数 Clerk Auth 设置都已自动完成，但有些配置需要你在 **Auth** 工具之外手动操作。

* **用于 SSO 身份提供方的自定义 OAuth 凭据** — 如果你希望身份提供方的同意页面显示应用的名称和品牌形象 (而不是 Replit 的默认值) ，请在身份提供方的开发者控制台中注册 OAuth 应用，然后将凭据填入 Auth 面板。请参阅[为 SSO 身份提供方配置 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
* **为外部域名的电子邮件验证添加 DNS 记录** — 如果你的应用连接了由其他提供方管理的外部域名，则需要添加 DNS 记录，以便验证邮件能通过该域名发送。请参阅[为电子邮件验证设置域名](#domain-setup-for-email-verification)。

<div id="replit-clerk-clerk-2">
  ### 可以使用自己的 Clerk 应用，而非 Replit 托管的 Clerk 吗？
</div>

可以。如果你的应用已预配 Replit 托管的 Clerk 应用，请先将其删除，再连接自己的外部 Clerk 应用。

1. 在 Project Editor 中打开 **Auth** 面板。
2. 前往 **Configure** 标签页。
3. 滚动至页面底部，然后点击 **Delete Clerk app**。

删除 Clerk 应用后，Replit 托管的 Clerk 租户将被移除，与其关联的域名也会被释放。之后，你可以连接自己的 Clerk 应用并复用该域名。如果你的应用尚未预配 Replit 托管的 Clerk 应用，可以跳过此步骤，直接集成外部 Clerk 应用。
