Вход в Velocity вы добавили в разделе [Добавление входа](/ru/build/add-login). Но автомобили в автопарке и бронирования, которые оформляют клиенты, по-прежнему исчезают при обновлении страницы — они существуют только в браузере. Добавьте базу данных, чтобы всё сохранялось.

<div id="tell-agent-to-save-the-data">
  ## Попросите Agent сохранить данные
</div>

Для Velocity используйте Neon — управляемую базу данных Postgres от Replit. Neon корректно обрабатывает одновременные бронирования, масштабируется под реальный поток клиентов, а Agent разворачивает её автоматически с раздельными окружениями Development и Production. Регистрироваться в дашборде Neon и вставлять ключи не нужно.

<AiPrompt>
  Сохрани данные Velocity в базу данных, чтобы автомобили, их доступность и бронирования не пропадали при обновлении страницы.<br />
  Используй Neon (Postgres).<br />
  Сохраняй: каждый автомобиль (марка, модель, год, суточная ставка, фото, местоположение), календарь доступности каждого автомобиля и каждое бронирование (дата получения, дата возврата, автомобиль, клиент).<br />
  Привяжи каждое бронирование к вошедшему в аккаунт клиенту, чтобы каждый видел только свои.<br />
  Не допускай бронирования одного и того же автомобиля на пересекающиеся даты.<br />
  Расскажи, что нужно протестировать после этих изменений.
</AiPrompt>

Agent развернёт базу данных Neon, перенесёт в неё автопарк и бронирования из данных в памяти и добавит проверку пересечений, чтобы одну и ту же Lamborghini нельзя было забронировать дважды.

<div id="test-that-everything-sticks">
  ## Проверьте, что всё сохраняется
</div>

1. Войдите в Velocity в Preview и забронируйте машину на следующую субботу.
2. Обновите страницу. Бронирование должно остаться в разделе «Мои бронирования».
3. Перезапустите приложение из чата с Agent. И автопарк, и бронирование должны сохраниться.
4. Попробуйте забронировать ту же машину на ту же субботу со второго аккаунта. Velocity должен сообщить, что машина недоступна, и предложить другую дату или другую машину.
5. Выйдите из аккаунта и войдите снова. Ваше бронирование должно остаться на месте.

Если на каком-то из шагов бронирование пропадает, опишите Agent проблему в точности так, как она проявляется:

<AiPrompt>
  Я забронировал машину в Velocity, но после обновления страницы бронирование пропадает.<br />
  Проверь, сохраняется ли бронирование в базе данных или только хранится на странице.<br />
  Исправь минимально необходимое и объясни, как это проверить.
</AiPrompt>

Также вы можете попросить Agent сделать простую административную страницу, чтобы посмотреть содержимое базы данных:

<AiPrompt>
  Сделай в Velocity простую административную страницу со списком всех машин и всех бронирований из базы данных, сгруппированных по машинам.<br />
  Показывай её только мне как владельцу project.
</AiPrompt>

<div id="publish-and-confirm-on-the-public-url">
  ## Опубликуйте приложение и проверьте его по публичному URL
</div>

Благодаря настройке Neon, которую выполнил Agent, у Velocity сразу появляются отдельные окружения Development и Production. Опубликуйте Velocity ещё раз из чата с Agent или через плитку Publishing, а затем откройте публичный URL в новой вкладке. Replit автоматически подставляет учётные данные Neon для Production в опубликованный deployment — создайте бронирование по публичному URL, обновите страницу и убедитесь, что оно на месте.

Теперь Velocity помнит каждый автомобиль, каждую доступную дату и каждое бронирование. Следующее обновление страницы не потеряет ни одной брони.

<div id="need-further-help">
  ## Нужна дополнительная помощь?
</div>

* **Бронирования сохраняются в Preview, но не на публичном URL:** попросите Agent проверить, что учётные данные Production Neon подключены к опубликованному deployment.
* **Данные неудобно просматривать:** попросите Agent добавить простую административную страницу со списком всего содержимого базы данных.
* **Нужно заполнить автопарк:** попросите Agent добавить одноразовый скрипт, который загрузит ваши реальные автомобили в базу данных.
* **Нужна база данных без настройки для быстрого прототипа:** используйте [Replit Database](/ru/features/data-and-storage/sql-database) — она встроена в каждый Repl и не требует отдельной подготовки.
