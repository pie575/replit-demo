<div id="add-response-headers">
  ## Добавление заголовков ответа
</div>

Пользовательские **заголовки ответа** позволяют добавлять HTTP-заголовки с инструкциями к запросам, которые соответствуют определённым путям.
Заголовок ответа — это пара «имя—значение», которая сообщает браузеру, как
обрабатывать запрошенное содержимое.

Например, с помощью заголовка `Access-Control-Allow-Origin` можно указать, к каким доменам браузер может обращаться для этой страницы.
Чтобы создать такую запись, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

Этот заголовок ответа включает следующие параметры:

* **path**: шаблон пути URL, которому соответствуют запрашиваемые ресурсы
* **name**: имя HTTP-заголовка
* **value**: значение HTTP-заголовка

В файл `.replit` можно добавить несколько записей `deployment.responseHeaders`.

Чтобы изменения конфигурации вступили в силу, опубликуйте Replit App заново.

<div id="reserved-headers">
  #### Зарезервированные заголовки
</div>

Replit резервирует следующие HTTP-заголовки, и настроить их вручную нельзя.

```text [expandable] theme={null}

Age
Allow
Alt-Svc
Connection
Content-Encoding
Content-Length
Content-Range
Date
Location
Server
Set-Cookie
Trailer

```

<div id="create-a-custom-404-page">
  ## Создание собственной страницы 404
</div>

Собственная страница 404 отображается, когда пользователи запрашивают URL-пути, которые не соответствуют ни одному файлу или правилу в опубликованном приложении.

Чтобы добавить собственную страницу 404, поместите её содержимое в файл `404.html` в корневом каталоге вашего Replit App.

При переходе по несуществующему URL-пути пользователи увидят отрисованный HTML собственной страницы 404.

<div id="define-url-path-rewrites">
  ## Настройка перезаписи путей URL
</div>

Вы можете настроить перезапись URL, чтобы изменить путь запроса до того, как ваше приложение Replit App его обработает.
Исходный URL остаётся видимым в браузере, но сервер загружает ресурс, указанный в правиле перезаписи.

Например, можно указать, что все запросы, начинающиеся с `/app`, загружают содержимое файла `/app/index.html`.
Чтобы создать такое правило, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**: шаблон пути URL, которому соответствуют запрашиваемые ресурсы
* **to**: перезаписанный путь, соответствующий файлу в вашем статическом развёртывании.

В файл `.replit` можно добавить несколько записей `deployment.rewrites`.
Сервер обрабатывает записи в указанном порядке и игнорирует дубликаты.

Чтобы изменения конфигурации вступили в силу, необходимо повторно опубликовать ваше приложение Replit App.

В следующих разделах описаны ограничения правил перезаписи URL.

<div id="path-matching">
  ### Сопоставление путей
</div>

К параметрам `from` и `to` в правилах перезаписи применяются следующие ограничения:

* Совпадение должно быть точным, если не используется `*`
* `*` соответствует оставшейся части пути
* `*` допустим только в конце пути
* Если вы используете `*` в параметре `from`, его можно указать и в параметре `to` — он обозначит совпавшую часть пути

Например, если файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

Когда пользователь открывает путь `/v1/about-us.html`, правило перезаписи отдаёт файл, расположенный по пути `/v2/about-us.html`.

<div id="shadowing">
  ### Затенение
</div>

Затенение возникает, когда правило перезаписи совпадает с путём URL, которому также соответствует файл в вашем статическом развёртывании.
В этом случае облачный сервер игнорирует правило перезаписи и отдаёт файл напрямую.

Например, предположим, что ваше опубликованное приложение содержит следующие файлы:

* `index.html`
* `about.html`

Файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

Когда пользователь открывает `/register.html`, сервер перезаписывает запрос на `/index.html` и отдаёт этот файл.
Однако если пользователь открывает `/about.html`, сервер игнорирует правило перезаписи и отдаёт файл `about.html`, поскольку он существует в вашем статическом развёртывании.

<div id="domain-restrictions">
  ### Ограничения по доменам
</div>

Перезаписи работают только для запросов к основному домену вашего статического развёртывания и могут
перенаправлять только на файлы внутри этого статического развёртывания.
