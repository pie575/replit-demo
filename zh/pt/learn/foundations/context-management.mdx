上下文是 AI 模型用来生成下一条回复的信息。上下文管理是指在恰当的时机向模型提供恰当的信息。

这很重要，因为 AI 并非只根据你的意图运作。它还会依据其上下文窗口中可用的文本、文件、截图、日志、示例和对话历史来运作。

<div id="o-que-uma-janela-de-contexto">
  ## 什么是上下文窗口？
</div>

AI 模型一次能处理的信息量有限。这个限制称为上下文窗口。

上下文窗口可能包括：

* 您的 提示词
* 对话中的历史消息
* 模型可以看到的文件或代码
* 错误消息和日志
* 截图、图像或设计参考
* 项目说明，例如 `replit.md`
* 前面步骤中的工具结果

模型会利用这些上下文来决定接下来生成什么内容。

<div id="por-que-as-janelas-de-contexto-so-importantes">
  ## 为什么上下文窗口很重要
</div>

如果上下文中缺少重要细节，模型可能会自行猜测。如果上下文中包含过多无关信息，模型可能会关注错误的内容。

例如，这个提示词提供的上下文很少：

```text theme={null}
改进注册页面。
```

以下提示词提供了有用的上下文：

```text theme={null}
针对正在决定是否加入候补名单的初次创业者，改进注册页面。
保留现有字段。在表单上方更清晰地展示价值主张。
不要更改定价部分。
```

第二个提示词会告知模型页面面向的用户、需要改进和保留的内容，以及哪些内容不在范围内。

<div id="os-tamanhos-das-janelas-de-contexto-variam">
  ## 上下文窗口大小不尽相同
</div>

不同的 AI 模型可处理的上下文量各不相同。更大的上下文窗口可以一次处理更多文本，但并非越大越好。相关的上下文仍然比把所有细节一股脑塞进对话中更重要。

公开的上下文窗口大小示例：

| 模型系列              | 上下文窗口示例            |
| ----------------- | ------------------ |
| GPT-4.1           | 最多 100 万个 token    |
| Claude Sonnet 4.5 | 最多 200,000 个 token |
| Gemini 2.5 Pro    | 最多 100 万个 token    |

这些数字会随时间变化，也不保证每个产品都会提供模型的完整上下文窗口。实用原则始终不变：保持重要信息清晰、聚焦。

<div id="tipos-de-contexto">
  ## 上下文类型
</div>

| 上下文类型    | 示例                  |
| -------- | ------------------- |
| **目标**   | “此落地页应收集候补名单报名信息。”  |
| **受众**   | “面向忙碌的餐厅业主。”        |
| **约束条件** | “保留当前的配色方案和表单字段。”   |
| **非目标**  | “暂时不要添加支付功能。”       |
| **示例**   | 截图、模型图、示例数据或竞争对手页面。 |
| **项目状态** | 当前文件、组件、错误消息或用户流程。  |
| **完成定义** | “访客可以提交表单并看到感谢消息。”  |

<div id="contexto-fresco-e-contexto-persistente">
  ## 临时上下文和持久上下文
</div>

有些上下文仅适用于当前对话。当你需要请求特定更改、调试问题，或针对最近的结果提供反馈时，请使用这类上下文。

另一些上下文则应在整个项目中持续保留。对于代码风格、品牌指南、命名约定、可复用的产品规则，以及 Agent 应在不同工作会话之间记住的约束条件，请使用持久上下文。在 Replit 中，[replit.md](/zh/pt/features/project-setup/replit-dot-md) 是向 Agent 提供项目持久上下文的一种方式。

<div id="quando-o-contexto-fica-ruidoso">
  ## 当上下文变得混乱时
</div>

长时间的对话可能会逐渐偏离主题。如果一个线程混杂了许多不相关的决策，Agent 可能会关注已经不再重要的旧上下文。

请在以下情况下新建线程：

* 切换到不相关的功能
* 对话中包含许多已放弃的思路
* Agent 持续沿用旧的限制条件
* 想为新领域制定一个清晰的计划

重新开始时，请总结重要的上下文，不要假设 Agent 知道哪些内容仍然重要。

```text theme={null}
上下文：此项目是一款面向本地私人教练的候补名单应用。
主要流程为：落地页 → 注册表单 → 确认消息。
在此线程中，请仅优化确认消息和后续跟进文案。
```

<div id="equvocos-comuns">
  ## 常见误区
</div>

* **“上下文越多越好。”** 相关的上下文才有帮助。过多且无关的上下文可能会分散模型的注意力。
* **“模型能完美记住一切。”** AI 会利用可用的上下文，但重要的约束条件仍应在必要时重申。
* **“上下文只是文本。”** 截图、文件、数据、Design、日志和示例也都可以作为上下文。
