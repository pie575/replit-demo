Les Replit Apps se configurent au moyen de deux fichiers : `.replit` et `replit.nix`. Ceux-ci déterminent le comportement de votre Replit App, de l&#39;exécution du code aux outils de développement et aux langages.

Ces fichiers de configuration sont masqués par défaut. Pour les afficher dans votre Replit App, sélectionnez « Show hidden files » dans le menu de l&#39;arborescence des fichiers.

<div id="arquivo-replitnix">
  ## Fichier `replit.nix`
</div>

Replit utilise `Nix` pour gérer les paquets et les environnements. Le fichier `replit.nix` sert à :

**Spécifier les dépendances système :** définissez précisément les paquets logiciels requis par votre Replit App, gérés par Nix, un gestionnaire de paquets.

**Créer des environnements reproductibles :** garantissez la cohérence et la reproductibilité de votre environnement de développement, idéal pour les projets collaboratifs et les tests sur plusieurs systèmes.

Vous pouvez gérer les paquets Nix visuellement avec l&#39;outil `Dependencies`. Pour en savoir plus, consultez le guide sur les [dépendances système](/fr/pt/features/project-setup/dependency-management#system-dependencies).

Pour configurer des paquets avec le fichier `replit.nix`, listez des [paquets Nix](https://search.nixos.org/packages) dans le tableau `deps`, en les préfixant par `pkgs.`. Toute modification est synchronisée après le rechargement de votre shell.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="arquivo-replit">
  ## Fichier `.replit`
</div>

Le fichier `.replit` contrôle le comportement de votre Replit App. Il utilise le [format de configuration](https://toml.io/en/) `toml`. Voici quelques-uns des principaux aspects configurables :

**Commande d&#39;exécution (Run) :** spécifiez la commande à exécuter lorsque le bouton Run est sélectionné. Chaque template possède une commande d&#39;exécution par défaut qui permet de lancer le code immédiatement. Pour des apps plus complexes et personnalisées, utilisez les [Workflows](/fr/pt/features/workspace-tools/workflows).

**Language Server Protocol (LSP)** : fournit des fonctionnalités telles que l&#39;autocomplétion, la navigation dans le code, la coloration syntaxique ainsi que le linting et la détection d&#39;erreurs en temps réel.

**Variables d&#39;environnement :** définissez et gérez les variables d&#39;environnement indispensables au bon fonctionnement de vos applications.

**Dépendances et paquets :** gérez l&#39;installation et la configuration des paquets directement depuis le fichier `.replit`, afin que votre Replit App dispose de tous les outils nécessaires dès le démarrage. Vous pouvez également gérer les dépendances de façon visuelle avec l&#39;outil `Dependencies`. Pour en savoir plus, consultez le guide des [Modules système](/fr/pt/features/project-setup/dependency-management#advanced-configuration).

Pour les applications Python, le fichier `.replit` par défaut ressemble à ceci :

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

| **Clé de configuration**                        | **Valeur/Exemple**                     | **Description**                                                                                                                                                                                                                                            |
| ----------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a name="entrypoint" />`entrypoint`             | `main.py`                              | Spécifie le fichier principal à exécuter et à afficher par défaut à l’ouverture de l’éditeur. Vous pouvez renommer ce fichier en fonction de votre application.                                                                                            |
| <a name="modules" />`modules`                   | `["python-3.10:v18-20230807-322e88b"]` | Définit des versions spécifiques de langages de programmation ou d’autres dépendances importantes prises en charge par Replit.                                                                                                                             |
| <a name="nix" />`[nix]`                         |                                        | Spécifie les paramètres permettant d’utiliser Nix, un gestionnaire de paquets, pour gérer les dépendances système. Consultez la documentation sur la [gestion des dépendances](/fr/pt/features/project-setup/dependency-management) pour plus d’informations. |
| <a name="channel" />`channel`                   | `stable-23_05`                         | Indique le canal Nix à utiliser, ce qui influe sur les versions des dépendances système disponibles.                                                                                                                                                       |
| <a name="packages" />`packages`                 | `["cowsay", "htop"]`                   | Spécifie les paquets Nix à installer. Pour un contrôle plus précis, vous pouvez également utiliser `replit.nix`.                                                                                                                                           |
| <a name="unitTest" />`[unitTest]`               |                                        | Configure les paramètres liés aux tests unitaires dans Replit App.                                                                                                                                                                                         |

| <a name="requiredFiles" />`requiredFiles`       | `[".replit", "replit.nix"]`            | Liste les fichiers qui doivent être présents lors de l’importation du projet afin d’en garantir le bon fonctionnement.                                                                                                                                     |
| <a name="deployment" />`[deployment]`           |                                        | Contient des paramètres permettant de déployer l’application Replit App dans un environnement de production.                                                                                                                                               |

| <a name="deploymentTarget" />`deploymentTarget` | `cloudrun`                             | Spécifie la plateforme de déploiement cible pour héberger l’application.                                                                                                                                                                                   |

Maintenant que vous connaissez les paramètres par défaut du fichier `.replit`, consultez les sections suivantes pour savoir comment configurer les paramètres de base et avancés de votre Replit App.

<div id="configurando-ajustes-bsicos">
  ## Configuration des paramètres de base
</div>

<div id="entrypoint">
  ### Entrypoint
</div>

Il s&#39;agit du fichier principal de votre projet. Si vous ne définissez pas de propriété `run`, c&#39;est l&#39;`entrypoint` qui est exécuté par le runtime.

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="comando-run">
  ### Commande `Run`
</div>

La propriété `run` du fichier `.replit` est un élément essentiel : elle détermine la commande initiale, ou la série de commandes, exécutée lorsque le bouton `Run` est sélectionné dans un environnement Replit. La commande `Run` peut être indiquée sous forme de chaîne représentant la commande à exécuter, ou sous forme de tableau de chaînes représentant la commande et chacun de ses arguments.

Voici quelques façons courantes de configurer la commande `Run` :

* **Commande unique :**
  Cet exemple montre comment transmettre une commande unique à exécuter directement dans le Replit App. Avec ceci dans votre fichier `.replit`, un appui sur le bouton `Run` affiche un message d&#39;accueil dans le panneau `Console` :
  **Exemple :** `run = "echo 'Hello, Replit!'"`

* **Arguments explicites :**
  Dans certains cas, il peut être avantageux d&#39;être plus explicite, ce qui évite d&#39;avoir à interpréter les guillemets ou les règles d&#39;interpolation du Shell. Vous pouvez réécrire l&#39;exemple ci-dessus en séparant les arguments.
  Notez que les caractères `'` et `"` ne sont plus nécessaires, puisque vous transmettez explicitement le message d&#39;accueil comme premier et unique argument de `echo` :
  **Exemple :** `run = ["echo", "Hello, Replit!"]`

* **Plusieurs commandes :**
  Cet exemple montre comment exécuter plusieurs processus simultanément, par exemple un frontend et un backend. C&#39;est utile si vous développez un backend en python et un frontend en typescript, où chaque serveur est lié à un port différent :
  **Exemple :** `run = "python -m app & npm run start & wait"`

<div id="gerenciamento-de-processos">
  #### Gestion des processus
</div>

Bien que plusieurs commandes puissent être exécutées simultanément avec `&`, vous préférerez peut-être un moyen plus pratique de distinguer les logs de chaque service. Vous pouvez [ajouter des dépendances système](/fr/pt/features/project-setup/dependency-management#system-dependencies) telles que [`process-compose`](https://github.com/F1bonacc1/process-compose) pour mieux orchestrer plusieurs processus.

<div id="fase-de-build">
  #### Phase de `Build`
</div>

Pour certains langages ou environnements d&#39;exécution, une phase de compilation distincte est nécessaire avant de pouvoir exécuter le code (`run`). Cela couvre à la fois les langages compilés comme TypeScript, Golang ou Java, et offre un paramètre qui vous permet de réinitialiser votre environnement, vos données ou votre configuration avant l&#39;appel du prochain `run`.

* **Compilation :**
  Dans un dépôt TypeScript, vous devrez peut-être exécuter `tsc` avant de lancer votre code.
  **Exemple :**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="incluindo-variveis-de-ambiente">
  #### Inclure des variables d&#39;environnement
</div>

Pour transmettre des variables d&#39;environnement à votre service avant son exécution, vous pouvez transformer la propriété `run` en [table](https://toml.io/en/v1.0.0#table).

Il s&#39;agit d&#39;une modification plus complexe, qui nécessite probablement de déplacer votre propriété `run = "..."` dans votre fichier `.replit`.

Le diff suivant montre comment indiquer la commande via `args` dans `[run]`, ainsi que la variable `NAME` définie dans `[run.env]` :

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# Nous devons placer notre nouveau [run] après toutes les
+# propriétés de premier niveau qui ne commencent pas par `[` !
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="interatividade">
  #### Interactivité
</div>

Les programmes interactifs peuvent eux aussi être lancés à l&#39;aide du bouton `Run`, ce qui permet de distinguer votre environnement de développement du terminal dans lequel votre programme s&#39;exécute.
Prenons l&#39;exemple du script de comptage suivant :

**Exemple**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="opes-de-configurao-avanada">
  ## Options de configuration avancées
</div>

Découvrez les options de configuration détaillées disponibles pour votre Replit App. Vous pouvez personnaliser votre environnement de développement, gérer les commandes d&#39;exécution, intégrer des services de langage et gérer les dépendances.

| **Configuration** | **Clé**                             | **Valeur/Exemple**                          | **Description**                                                                                     |
| ----------------- | ----------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| onBoot            | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Commande exécutée au démarrage du Replit App.                                                       |
| compile           | <a name="compile" />`compile`       | (Aucun exemple par défaut)                  | Commande exécutée avant la commande `run`, utilisée pour les langages compilés comme le C++.        |
| language          | <a name="language" />`language`     | `language = "javascript"`                   | Spécifie le langage lors d&#39;une importation depuis GitHub ou de la création d&#39;un Replit App. |
| entrypoint        | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | Fichier principal à exécuter et à afficher à l&#39;ouverture de l&#39;éditeur.                      |
| hidden            | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | Fichiers ou dossiers masqués par défaut dans l&#39;arborescence de fichiers latérale.               |
| audio             | <a name="audio" />`audio`           | `audio = true`                              | Active l&#39;audio système lorsque la valeur est `true`.                                            |

<div id="notas-sobre-o-udio-do-sistema">
  ### Remarques sur l&#39;audio système
</div>

Lorsque vous définissez `audio = true` dans votre fichier `.replit`, il peut être nécessaire de redémarrer l&#39;environnement de développement. Ouvrez la palette de commandes avec `Cmd+K` (Mac) ou `Ctrl+K` (Windows), recherchez **Restart compute** et sélectionnez cette option.

Lorsque vous exécutez une application graphique, une icône de casque audio accompagnée d&#39;une case à cocher apparaît dans le coin inférieur droit du panneau `Output`.
En raison des restrictions du navigateur, vous devrez l&#39;activer à chaque actualisation de la page.

```toml theme={null}
# Veillez à placer cette ligne en haut de votre fichier `.replit`, en dehors de toute section délimitée par `[`
audio = true
```

<div id="configurao-do-packager">
  ## Configuration du packager
</div>

| **Configuration** | **Clé**                                           | **Valeur/Exemple**                            | **Description**                                                                                            |
| ----------------- | ------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| packager          | <a name="language" />`language`                   | `packager.language = "python3"`               | Langage utilisé pour les opérations sur les paquets.                                                       |
| packager features | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Détecte automatiquement les paquets à installer avant d&#39;exécuter la Replit App.                        |
| packager features | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | Active la prise en charge du packager lorsque la valeur est `true`.                                        |
| packager features | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Indique si l&#39;hébergement de la Replit App nécessite l&#39;exécution d&#39;une installation de paquets. |
| packager          | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | Commande exécutée après l&#39;installation d&#39;un nouveau paquet via le packager.                        |
| packager          | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | Chemins à ignorer lors de la détection des paquets.                                                        |
| packager          | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | Modules pour lesquels aucune détection de paquet ne doit être tentée lors de l&#39;installation.           |

<div id="exemplo-de-configurao-replit-para-configurao-do-packager">
  ### Exemple de fichier `.replit` pour la configuration du packager
</div>

```toml theme={null}
# Définit le langage de la Replit App
packager.language = "python3"

# Active les fonctionnalités de gestion automatique des paquets
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# Commande à exécuter après chaque installation de paquet
packager.afterInstall = "echo 'Package installed successfully'"

# Définit les chemins et paquets que le gestionnaire de paquets doit ignorer
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# Paramètres supplémentaires de déploiement
[deployment]
run = ["python3", "app.py"]
```

<div id="configurao-de-publicao-deployment">
  ## Configuration du déploiement
</div>

| **Configuration** | **Clé**                               | **Valeur/Exemple**                   | **Description**                                                                             |
| ----------------- | ------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------- |
| deployment        | <a name="run" />`run`                 | `deployment.run = "npm start"`       | Commande exécutée au démarrage d&#39;un conteneur de Deployment.                            |
| deployment        | <a name="build" />`build`             | `deployment.build = "npm run build"` | Commande exécutée avant le lancement d&#39;un Deployment.                                   |
| deployment        | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | Si `true`, la réussite du déploiement ne nécessite pas la vérification d&#39;un port ouvert. |

<div id="exemplo-de-configurao-replit-para-configurao-de-publicao">
  ### Exemple de fichier `.replit` pour la configuration de déploiement
</div>

```toml theme={null}

# Spécifie le point d'entrée principal du projet
entrypoint = "app.js"

# Paramètres de déploiement de l'application
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  La **configuration `interpreter`** est obsolète et n&#39;est plus disponible sur Replit. Il est recommandé d&#39;utiliser à la place les commandes `Run` pour définir la façon dont les scripts et les applications s&#39;exécutent dans l&#39;environnement de votre Replit App.
</Note>

<div id="acessando-os-metadados-do-ambiente-do-replit-app">
  ## Accéder aux métadonnées de l&#39;environnement de la Replit App
</div>

<div id="nodejs">
  ### Node.js
</div>

Pour accéder à toutes les variables d&#39;environnement :

`console.log(process.env);`

Pour accéder à une seule variable (REPL&#95;SLUG) :

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

Pour accéder à toutes les variables d&#39;environnement :

```python theme={null}
import os
print(os.environ)
```

Pour accéder à une seule variable (REPL&#95;SLUG) :

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

Pour accéder à toutes les variables d&#39;environnement :

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

Pour accéder à une seule variable (REPL&#95;SLUG) :

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```
