Le sélecteur de modèles permet à Replit de choisir automatiquement un modèle, ou vous permet d’en sélectionner un parmi les modèles disponibles.

<div id="section">
  ## Routage intelligent des modèles
</div>

Le routage intelligent des modèles sélectionne le modèle le plus adapté à chaque tâche en conciliant qualité et coût. Lorsque le produit affiche **Auto**, Replit utilise le routage intelligent des modèles.

Le routage intelligent des modèles tient compte de la tâche demandée et de sa complexité. Il peut utiliser des modèles moins coûteux pour les demandes ciblées, tandis que les tâches complexes peuvent nécessiter des modèles plus puissants. Si la tâche change, Replit peut également sélectionner un autre modèle.

<Note>
  Le routage intelligent des modèles est toujours utilisé dans Free Mode. Les utilisateurs de Free Mode ne peuvent pas utiliser le sélecteur de modèles ni sélectionner directement un modèle.
</Note>

<div id="section-2">
  ## Sélectionner manuellement un modèle
</div>

Les utilisateurs des forfaits Core et Pro peuvent sélectionner un modèle disponible en mode Power ou Max.

1. Dans le champ de saisie du prompt, sélectionnez **Agent Mode**. Le menu affiche les modes disponibles (**Free**, **Power**, **Max**).
2. Sélectionnez **Power** ou **Max**, puis recherchez la section **modèle principal**.
3. Ouvrez le menu du modèle principal et sélectionnez un modèle dans la liste.

<div id="effort">
  ## Effort
</div>

**Effort n’est pas un mode distinct, mais un réglage propre à chaque modèle.** Il permet de définir, de **Low** à **Max**, le niveau de raisonnement que le modèle sélectionné consacre à chaque réponse. Chaque modèle affiche un réglage recommandé, que vous ne devez augmenter que lorsque la tâche l’exige.

<Frame caption="Le curseur Effort sous la liste des modèles, réglé sur Medium.">
  <img src="/assets/mirror/model-selector-effort-bcffb01239a8.png" alt="Liste de modèles avec Claude Fable 5 sélectionné comme modèle principal et curseur Effort réglé sur Medium, décrit comme offrant un raisonnement équilibré pour les tâches quotidiennes" width="984" height="832" data-path="images/replitai/model-selector-effort.png" />
</Frame>

Consultez les descriptions des niveaux ci-dessous :

| Effort         | Quand l’utiliser                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Low**        | Réponses les plus rapides avec un raisonnement minimal. Idéal pour les modifications simples et courantes où la rapidité est primordiale.                           |
| **Medium**     | Raisonnement équilibré pour les tâches quotidiennes. Valeur par défaut appropriée lorsqu’aucune instruction particulière n’est indiquée dans le réglage recommandé. |
| **High**       | Raisonnement approfondi pour les tâches plus complexes, telles que les fonctionnalités en plusieurs étapes ou les domaines peu familiers.                           |
| **Extra High** | Raisonnement étendu pour les problèmes les plus difficiles, comme les refactorisations à grande échelle ou les bugs complexes.                                      |
| **Max**        | Profondeur de raisonnement maximale. C’est l’option la plus coûteuse et la plus lente lorsque seuls les meilleurs résultats comptent.                               |

Plus Effort est élevé, plus Agent effectue un raisonnement approfondi et minutieux, et utilise les modèles de pointe les plus puissants pour améliorer les résultats des tâches les plus complexes. Agent applique cette puissance supplémentaire de manière sélective : il n’achemine pas chaque exécution vers un modèle plus puissant, mais uniquement lorsque votre demande est réellement difficile.

<Tip>
  Comme Agent n’utilise les modèles les plus puissants que pour les tâches les plus difficiles, augmenter Effort peut faire grimper jusqu’à environ deux fois le coût des tâches les plus exigeantes — tandis que les tâches plus simples n’entraînent souvent que peu ou pas de coût supplémentaire. Augmentez Effort lorsque vous traitez des problèmes complexes et maintenez-le bas pour les modifications quotidiennes.
</Tip>

<div id="section-4">
  ## Comparer les modèles
</div>

**Compare models** exécute votre prochain prompt simultanément sur plusieurs modèles afin que vous puissiez comparer les résultats côte à côte, plutôt que de devoir deviner quel modèle convient le mieux. Il s’agit d’une fonctionnalité bêta.

Pour activer cette fonctionnalité, développez les **Paramètres avancés** en bas du popover du mode Agent, puis activez **Compare models**.

<Note>La comparaison de modèles est disponible uniquement dans Chat.</Note>

<Frame caption="Le commutateur Compare models sous les paramètres avancés.">
  <img src="/assets/mirror/compare-models-toggle-05429dc46d64.png" alt="Paramètres avancés développés avec le commutateur Compare models Beta désactivé, indiquant que jusqu’à 4 variantes sont créées pour votre prochain prompt" width="1110" height="344" data-path="images/replitai/compare-models-toggle.png" />
</Frame>

Une fois le commutateur activé, vous pouvez ajouter jusqu’à **4 modèles** à la comparaison.

<Frame caption="Quatre modèles sélectionnés pour la comparaison, avec Compare 4 affiché sur le bouton d’envoi.">
  <img src="/assets/mirror/compare-models-9f5bcecec727.png" alt="Popover du mode Agent avec Compare models activé et quatre emplacements de modèles (Kimi K3, Claude Fable 5, Claude Opus 5, GPT-5.6 Sol), chacun pouvant être supprimé, ainsi que le bouton d’envoi du Chat indiquant Compare 4" width="1192" height="1930" data-path="images/replitai/compare-models.png" />
</Frame>

Votre prochain prompt s’exécute ensuite une fois sur chaque modèle sélectionné, chacun générant sa propre variante que vous pouvez comparer.

<Note>
  Chaque modèle inclus dans la comparaison s’exécute comme un agent distinct et utilise des crédits. Une exécution Compare 4 coûte donc approximativement autant que quatre exécutions uniques.
</Note>
