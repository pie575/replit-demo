Каждое Replit App работает с двумя базами данных. **База данных для разработки** — это среда, где вы и Agent экспериментируете во время создания приложения. **Продакшен-база данных** хранит реальные данные, на которых работает ваше опубликованное приложение, — так рабочие данные остаются в безопасности, пока вы продолжаете разработку.

<div id="how-they-compare">
  ## Сравнение
</div>

| Аспект         | База данных для разработки                                 | Продакшн-база данных                                                       |
| -------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Назначение** | Эксперименты и разработка функций                          | Обслуживание реальных пользователей и хранение бизнес-данных               |
| **Данные**     | Тестовые данные, фиктивные записи, небольшие наборы данных | Реальные пользовательские данные, критически важная для бизнеса информация |
| **Создание**   | Автоматически вместе с каждым Replit App                   | При публикации приложения                                                  |
| **Agent**      | Agent может создавать и изменять таблицы                   | Agent не имеет к ней доступа                                               |
| **Изменения**  | Частые изменения схемы, быстрые итерации                   | Продуманные, спланированные изменения, применяемые при публикации          |
| **Оплата**     | Бесплатно с каждым Replit App                              | По факту использования                                                     |

<Note>
  Agent не может изменять продакшн-базу данных. Это ограничение действует для того, чтобы ваша продакшн-база данных оставалась в безопасности.

  При этом Agent может вносить изменения в базу данных для разработки. В момент публикации все изменения структуры базы данных для разработки, внесённые с помощью Agent (добавление и удаление столбцов или таблиц), применяются к продакшн-базе данных.

  Редактировать продакшн-данные вручную можно в любой момент: откройте инструмент **Database**, выберите продакшн-базу данных, откройте **My Data** и включите режим **Edit**.
</Note>

<div id="create-a-production-database-when-you-publish">
  ## Создание рабочей базы данных при публикации
</div>

Опубликованное приложение получает собственную рабочую базу данных — отдельную от базы данных для разработки, с которой вы работаете при создании приложения.

* **Текущая инфраструктура (Helium)**: Replit сам создаёт рабочую базу данных, когда это требуется при публикации. Настраивать ничего не нужно.
* **Устаревшие базы данных для разработки на Neon**: рабочую базу данных вы создаёте в настройках публикации. В процессе публикации откройте **Production database settings**, включите **Create production database** и при необходимости — **Set up your production database with your current development data**, чтобы скопировать туда данные из среды разработки.

<Frame caption="Настройки рабочей базы данных в разделе Publishing">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="Настройки публикации с параметрами создания рабочей базы данных" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  Копируйте данные из среды разработки в рабочую базу только в том случае, если их безопасно использовать в работающем приложении. Такие данные могут содержать тестовые аккаунты, примеры записей или незавершённый контент.
</Warning>

После публикации приложение работает с рабочей базой данных, а Project Editor продолжает использовать базу данных для разработки, поэтому дальнейшие изменения в ходе разработки напрямую не затрагивают рабочие данные.

<div id="connection-pooling">
  ## Пул соединений
</div>

По умолчанию для рабочих баз данных пул соединений отключён. Приложение подключается к базе данных напрямую по строке подключения `DATABASE_URL`, поэтому пулом соединений на стороне клиента, как правило, управляет сам фреймворк.

<Note>
  Каждый проект Neon включает прямую строку подключения и строку подключения через пул. Прямая строка подключения выглядит так: `postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`.

  Чтобы подключаться через пул, добавьте `-pooler` к имени хоста: `postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`.
</Note>

Если строка подключения к рабочей базе данных была раскрыта, [перевыпустите учётные данные рабочей базы данных](/ru/features/data-and-storage/connection-details#regenerate-production-database-credentials).

<div id="making-safe-changes-to-your-production-database">
  ## Безопасное внесение изменений в рабочую базу данных
</div>

Когда вы публикуете обновления, затрагивающие базу данных, некоторые изменения требуют тщательного планирования, чтобы избежать простоя или потери данных.

<Info>
  Во время публикации возможен кратковременный простой опубликованного приложения. Изменения базы данных иногда требуют временной остановки приложения — это позволяет предотвратить конфликты и защитить данные, пока изменения применяются.
</Info>

Как правило, особого внимания требуют следующие типы изменений:

* **Удаление столбцов базы данных**, на которые всё ещё ссылается код вашего приложения
* **Изменение типов данных столбцов** так, что существующий код не может их обработать
* **Добавление обязательных полей** без значений по умолчанию в существующие таблицы
* **Переименование таблиц или столбцов**, нарушающее существующие запросы
* **Изменение ограничений**, из-за которых существующая логика приложения может отклоняться

<div id="test-changes-with-a-deployment-preview">
  ### Тестирование изменений в предпросмотре deployment
</div>

Предпросмотр deployment — это временная изолированная копия вашей продакшен-среды, в которой можно протестировать изменения базы данных и обновления приложения до того, как они затронут реальных пользователей. Используйте его, чтобы:

* Убедиться, что приложение по-прежнему работает после применения изменений в базе данных — во всех основных пользовательских сценариях
* Проверить, что существующие данные перенесены корректно, а новые поля содержат ожидаемые значения
* Отследить возможное снижение производительности по времени отклика запросов

<div id="billing-and-resource-usage">
  ## Оплата и использование ресурсов
</div>

Продакшн-базы данных оплачиваются по факту использования через Neon — провайдера бессерверных баз данных. После пяти минут бездействия база переходит в режим ожидания, тарификация вычислительного времени приостанавливается, а при поступлении запроса база мгновенно возобновляет работу.

На стартовом экране инструмента Database отображаются **Billing Period** и **Hours of Compute Used**. Чтобы посмотреть объём хранилища конкретной базы, откройте вкладку **Settings** этой базы. Чтобы увидеть использование по всем Replit App, откройте **Settings** → **Account** → **Account usage** и разверните строки **PostgreSQL Storage** и **PostgreSQL Compute**.

О том, как Replit тарифицирует использование баз данных, см. [Deployments and Database Billing](/ru/billing/about-usage-based-billing#databases).

<div id="removing-a-production-database">
  ## Удаление продакшн-базы данных
</div>

<Warning>
  Удаление необратимо по истечении 7-дневного периода хранения. Перед продолжением обязательно создайте резервную копию всех важных данных. Для баз данных действует 7-дневный период мягкого удаления, в течение которого их можно восстановить; при необходимости обратитесь в службу поддержки. Через 7 дней база данных удаляется окончательно и восстановлению не подлежит.
</Warning>

<Accordion title="Как удалить базу данных">
  В инструменте **Database**:

  1. Выберите базу данных, затем откройте вкладку **Settings**
  2. Нажмите **Remove database** и подтвердите, выбрав **Yes, Remove database**
</Accordion>

<div id="legacy-development-database">
  ## Устаревшая база данных разработки
</div>

До 4 декабря 2025 года база данных разработки размещалась в <a href="https://neon.com/" target="_blank">Neon</a>. Все новые базы данных разработки размещаются в собственной инфраструктуре Replit (Helium). Проверить, какая из них используется вашим приложением, можно на вкладке **Settings**: если `DATABASE_URL` содержит `neon.tech` — это устаревший вариант Neon; `helium` — текущая инфраструктура.

| **Возможность**                | **Replit (текущая)**                                                                                                 | **Neon (устаревшая)**                                                                                                                    |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **Размещение**                 | В собственной инфраструктуре Replit                                                                                  | В Neon (сторонний provider)                                                                                                              |
| **Оплата**                     | Бесплатно входит в каждое Replit App                                                                                 | Оплата по использованию. Подробнее см. [Оплата Publishing и баз данных](/ru/billing/about-usage-based-billing#databases).                   |
| **Возможность восстановления** | Восстановление базы данных до любого checkpoint с помощью [функции отката](/ru/features/data-and-storage/data-recovery) | Восстановление на момент времени (PITR): возврат к любой точке в пределах срока хранения резервных копий.                                |
| **Безопасность подключения**   | Доступна только изнутри вашего приложения и никогда не открыта публично.                                             | Использовалась полная строка подключения. При её утечке любой мог получить доступ к базе данных и изменить её.                           |
| **Поведение при ремиксе**      | [Ремикс](/ru/build/remix-an-app) создаёт новую базу данных разработки с копией данных — для изоляции и безопасности.    | Ремикс использует одну и ту же базу данных для всех копий, поэтому изменения в ремиксах могли затронуть исходное приложение.             |
| **Создание базы данных**       | Создаётся автоматически для каждого Replit App.                                                                      | Требовалась явная настройка.                                                                                                             |
| **Процесс publishing**         | Publishing создаёт отдельную рабочую базу данных, изолируя среды друг от друга.                                      | Разработка и рабочая среда использовали одну базу данных, поэтому случайные изменения при разработке могли затронуть рабочие приложения. |

<div id="database-infrastructure-upgrade">
  ## Обновление инфраструктуры баз данных
</div>

Replit переводит базы данных для разработки с Neon на **Helium** — собственную управляемую инфраструктуру PostgreSQL от Replit. Обновление выполняется автоматически, один раз для каждого приложения при его открытии в Project Editor, и все ваши данные сохраняются.

Что меняется:

* **Меньше задержки, больше места**: ваша база данных работает на инфраструктуре Replit рядом с приложением, а лимит хранилища увеличивается с 10 ГБ до 20 ГБ.
* **Тот же движок базы данных**: Helium использует PostgreSQL 16 — ту же версию, что и Neon. Ваши запросы, схемы и данные работают точно так же.
* **Подключение обновляется автоматически**: `DATABASE_URL` обновляется и указывает на Helium. Прежняя строка подключения к Neon сохраняется в Secrets как `NEON_DATABASE_URL` — на случай, если она понадобится.
* **Отдельные переменные PG удаляются**: `PGHOST`, `PGPORT`, `PGUSER` и `PGPASSWORD` удаляются. Используйте вместо них `DATABASE_URL`.

Во время обновления вы увидите экран с индикатором выполнения **«Upgrading your database»**. Для больших баз данных это может занять от нескольких минут до нескольких часов; вкладку можно закрыть и вернуться позже. Если при обновлении возникнет проблема, оно автоматически пропускается и повторяется при следующем открытии приложения. По завершении появится диалоговое окно с подтверждением.

Большинству разработчиков после этого ничего делать не нужно. Проверьте следующее, если это к вам относится:

* **Жёстко прописанные строки подключения к Neon**: обновите код, в котором используется строка подключения `neon.tech`, чтобы вместо неё применялась переменная окружения `DATABASE_URL`.
* **Пользовательские роли PostgreSQL**: роли и разрешения переносятся автоматически, но пароли ролей скопировать нельзя. Сбросьте пароли пользовательских ролей в новой базе данных.

<div id="ssl-connection-errors-after-the-upgrade">
  ### Ошибки SSL-подключения после обновления
</div>

Если вы видите ошибки вида `The server does not support SSL connections`, значит ваш код подключения принудительно инициирует SSL-рукопожатие. Neon требовал SSL, а Helium работает локально рядом с вашим приложением и SSL не использует. Сделайте настройку SSL зависимой от окружения:

<CodeGroup>
  ```js JavaScript theme={null}
  // До (перестаёт работать после обновления)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // После (работает и в разработке, и в продакшене)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  Если вы используете ORM — например Drizzle, Prisma или Sequelize — обратитесь к его документации, чтобы узнать, как настроить параметры SSL в зависимости от окружения. Принцип тот же: отключите SSL для базы данных разработки и включите для продакшена.
</Tip>

<div id="forked-apps-that-shared-a-database">
  ### Форкнутые приложения с общей базой данных
</div>

В прежней системе Neon при форке приложения копировался `DATABASE_URL` исходного приложения, поэтому оба приложения и их опубликованные версии подключались к одной и той же базе данных. Общие устаревшие базы данных были отключены **8 июня 2026 года**. Если ваше опубликованное приложение перестало работать или потеряло доступ к своим данным, см. [Исправление опубликованного приложения, использующего общую базу данных](/ru/features/data-and-storage/shared-database-migration) или [обратитесь в поддержку](https://replit.com/support).
