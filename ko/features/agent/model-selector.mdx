Model selector를 사용하면 Replit이 자동으로 모델을 선택하게 하거나, 사용 가능한 모델을 직접 선택할 수 있습니다.

## 지능형 모델 라우팅

지능형 모델 라우팅은 품질과 비용의 균형을 맞추면서 각 작업에 적합한 모델을 선택합니다. 제품에서 **Auto**로 표시되어 있다면 Replit이 지능형 모델 라우팅을 실행하고 있는 것입니다.

지능형 모델 라우팅은 요청한 작업과 그 복잡도를 고려합니다. 범위가 좁은 요청에는 비용이 더 낮은 모델을 사용할 수 있고, 복잡한 작업에는 더 강력한 모델이 필요할 수 있습니다. 작업이 바뀌면 Replit이 다른 모델을 선택할 수도 있습니다.

<Note>
  Free Mode에서는 항상 지능형 모델 라우팅이 사용됩니다. Free Mode의 빌더는 Model selector를 사용하거나 모델을 직접 선택할 수 없습니다.
</Note>

## 모델 수동으로 선택하기

Core 및 Pro 플랜의 빌더는 Power Mode 또는 Max Mode에서 사용 가능한 모델을 선택할 수 있습니다.

1. 프롬프트 입력창에서 **Agent Mode**를 선택합니다. 메뉴에 사용 가능한 모드(**Free**, **Power**, **Max**)가 표시됩니다.
2. **Power** 또는 **Max**를 선택한 다음 **Primary model** 섹션을 찾습니다.
3. 프라이머리 모델 메뉴를 열고 목록에서 모델을 선택합니다.

</Note>

## Effort

**Effort는 별도의 모드가 아니라 모델별 컨트롤입니다.** 선택한 모델이 각 응답에 얼마나 많은 추론을 사용할지를 **Low**부터 **Max**까지 설정합니다. 각 모델은 권장 설정을 표시하며, 작업에 필요할 때만 이를 높이면 됩니다.

<Frame caption="모델 목록 아래에 있는 Effort 슬라이더, Medium으로 설정된 모습.">
  <img src="/assets/mirror/model-selector-effort-bcffb01239a8.png" alt="Claude Fable 5가 선택된 Primary model 목록과 Medium으로 설정된 Effort 슬라이더, 일상적인 작업을 위한 균형 잡힌 추론으로 설명됨" width="984" height="832" data-path="images/replitai/model-selector-effort.png" />
</Frame>

다음 레벨 설명을 참고하세요:

| Effort         | 사용 시점                                                 |
| -------------- | ----------------------------------------------------- |
| **Low**        | 최소한의 추론으로 가장 빠른 응답. 속도가 가장 중요한 일상적이고 명확한 변경에 적합합니다.   |
| **Medium**     | 일상적인 작업을 위한 균형 잡힌 추론. 권장 설정에 특별한 지시가 없을 때 적합한 기본값입니다. |
| **High**       | 다단계 기능이나 익숙하지 않은 영역 같은 더 복잡한 작업을 위한 심층 추론.            |
| **Extra High** | 대규모 리팩터링이나 까다로운 버그 같은 가장 어려운 문제를 위한 확장된 추론.           |
| **Max**        | 최대 수준의 추론 깊이. 최상의 결과만이 중요할 때 가장 비용이 높고 가장 느립니다.       |

Effort가 높을수록 Agent는 더 깊고 신중한 추론을 수행하고 가장 강력한 프런티어 모델을 사용하여 가장 복잡한 작업의 결과를 개선합니다. Agent는 이 추가적인 성능을 선택적으로 적용합니다 — 매 실행마다가 아니라 요청이 실제로 어려울 때만 더 강력한 모델로 라우팅합니다.

<Tip>
  Agent는 가장 어려운 작업에서만 가장 강력한 모델을 사용하기 때문에, Effort를 높이면 가장 까다로운 작업에서 비용이 최대 약 2배까지 늘어날 수 있으며 — 더 간단한 작업에서는 비용이 거의 또는 전혀 늘지 않는 경우가 많습니다. 복잡한 문제를 다룰 때는 Effort를 높이고, 일상적인 변경에는 낮게 유지하세요.
</Tip>

## 모델 비교

**Compare models**는 다음 프롬프트를 여러 모델에서 동시에 실행하여, 어떤 모델이 적합한지 추측하는 대신 결과를 나란히 비교할 수 있게 해줍니다. 베타 기능입니다.

이 기능을 켜려면 Agent 모드 팝오버 하단의 **고급 설정**을 펼치고 **Compare models**를 켜세요.

<Note>모델 비교는 Chat에서만 지원됩니다.</Note>

<Frame caption="고급 설정 아래에 있는 Compare models 토글.">
  <img src="/assets/mirror/compare-models-toggle-05429dc46d64.png" alt="Compare models Beta 토글이 꺼진 상태로 펼쳐진 고급 설정, 다음 프롬프트로 최대 4개의 변형을 생성한다고 설명됨" width="1110" height="344" data-path="images/replitai/compare-models-toggle.png" />
</Frame>

토글을 켜면 비교에 최대 **4개의 모델**을 추가할 수 있습니다.

<Frame caption="비교를 위해 선택된 네 개의 모델, 전송 버튼에 Compare 4라고 표시됨.">
  <img src="/assets/mirror/compare-models-9f5bcecec727.png" alt="Compare models가 켜져 있고 네 개의 모델 슬롯(Kimi K3, Claude Fable 5, Claude Opus 5, GPT-5.6 Sol)이 각각 제거 가능하게 표시된 Agent 모드 팝오버, Compare 4라고 표시된 채팅 전송 버튼" width="1192" height="1930" data-path="images/replitai/compare-models.png" />
</Frame>

이후 다음 프롬프트는 선택한 각 모델에서 한 번씩 실행되며, 각각 비교할 수 있는 자체 변형을 생성합니다.

<Note>
  비교에 포함된 각 모델은 별도의 에이전트로 실행되며 크레딧을 사용하므로, Compare 4 실행은 단일 실행 네 번과 비슷한 비용이 듭니다.
</Note>

## Build와 Design의 모델 선택
