Каждую неделю получайте изменения из GitHub и Linear, формируйте клиентские заметки о выпуске,
сгруппированные по категориям «Новое», «Улучшения» и «Исправления», и публикуйте их в Notion. Пропускайте задачи только для внутреннего использования
и отмечайте всё, что похоже на обратно несовместимое изменение, чтобы у продукта, службы поддержки и
клиентов было единое понимание происходящего на регулярной основе.

<div id="best-for">
  ## Для кого
</div>

* Продакт-менеджеров, которым нужен еженедельный changelog без ожидания тега версии.
* Специалистов по продуктовому маркетингу и поддержке, которым нужна та же информация, что и клиентам.

<div id="what-to-expect">
  ## Чего ожидать
</div>

Agent готовит черновик заметок за прошлую неделю на основе pull requests и задач, а затем создаёт страницу в Notion.
Отредактируйте стиль изложения, прежде чем отправлять их клиентам. Пропустите всё, что выглядит как
внутренняя рутина, и вынесите обратно несовместимые изменения в начало. Сравните страницу с объединёнными
pull requests за прошлую неделю, прежде чем нажать Publish.

<div id="troubleshooting">
  ## Устранение неполадок
</div>

* **В заметки попадают внутренние задачи:** укажите Agent нужный репозиторий и команду Linear, затем снова попросите его пропускать задачи, которые не выпускаются для клиентов.
* **Важное несовместимое изменение осталось незамеченным:** объясните Agent, что для вас означает «несовместимое» (вход в систему, биллинг или обязательная миграция), и попросите вынести такие пункты наверх и пометить их.
* **Выбрана не та страница Notion:** укажите точную ссылку на страницу или базу данных и сообщите, нужно ли перезаписывать заметки прошлой недели или создавать новую страницу при каждом запуске.
