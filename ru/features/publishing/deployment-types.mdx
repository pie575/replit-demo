Тип развёртывания — это технология, с помощью которой Replit публикует ваше приложение. Он выбирается в инструменте Publishing в разделе **Adjust settings**, в выпадающем списке **Deployment type**. Вариант по умолчанию и рекомендуемый — **Autoscale**; большинству создателей менять его не приходится.

<div id="compare-deployment-types">
  ## Сравнение типов развёртывания
</div>

| Тип             | Для чего лучше всего                               | Как работает                                                        | Как тарифицируется                            |
| :-------------- | :------------------------------------------------- | :------------------------------------------------------------------ | :-------------------------------------------- |
| **Autoscale**   | Веб-приложения и API с переменным трафиком         | Добавляет серверы при нагрузке и масштабируется до нуля при простое | Вы платите, пока обрабатываются запросы       |
| **Static**      | Лендинги, портфолио, сайты документации            | Отдаёт файлы с кешированного облачного сервера, без бэкенда         | Вы платите только за переданные сайтом данные |
| **Reserved VM** | Боты, фоновые задачи, постоянно доступные API      | Один выделенный сервер, который никогда не засыпает                 | Фиксированная ежемесячная стоимость           |
| **Scheduled**   | Периодические задачи: резервные копии, уведомления | Запускает команду по расписанию, затем останавливается              | Вы платите за длительность каждого запуска    |

<div id="autoscale">
  ## Autoscale
</div>

Развёртывания Autoscale работают на серверах, которые масштабируются в зависимости от трафика вашего приложения. Когда нагрузка растёт, Replit добавляет серверы, чтобы с ней справиться. Когда приложение простаивает, их число сокращается вплоть до нуля, поэтому за время бездействия вы не платите.

Идеально подходит для:

* веб-приложений с переменным трафиком, например интернет-магазинов;
* API и сервисов.

Настройки задаются в разделе **Adjust settings**: [мощность машины и максимальное количество серверов](/ru/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Развёртывания Static размещают файлы вашего приложения — HTML, CSS и JavaScript — на облачном сервере, который использует кэширование для быстрой и экономичной доставки контента. Бэкенд-сервер при этом отсутствует.

Идеально подходит для:

* Маркетинговых лендингов
* Сайтов-портфолио
* Сайтов с документацией по продукту и API

<Note>
  Развёртывания Static несовместимы с Replit App, созданными с помощью Agent. Agent создаёт полностековые приложения, которым нужен бэкенд-сервер, поэтому для них используйте Autoscale или Reserved VM.
</Note>

В конфигурации указывается публичный каталог для раздачи файлов и, при необходимости, команда сборки. О заголовках ответов, перезаписи URL и перенаправлениях см. [расширенную настройку Static](/ru/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Развёртывание типа Reserved VM запускает ваш app на выделенной виртуальной машине, которая никогда не переходит в спящий режим. Вы получаете стабильную производительность и предсказуемую фиксированную ежемесячную стоимость.

Идеально подходит для:

* Фоновых задач, требовательных к памяти
* Чат-ботов, которые должны постоянно оставаться на связи
* Круглосуточно работающих API-серверов

Конфигурация включает [мощность машины](/ru/features/publishing/machine-configuration), команды сборки и запуска, сопоставление портов, а также режим работы приложения — веб-сервер или фоновый обработчик.

<div id="scheduled">
  ## Scheduled
</div>

Запланированные развёртывания выполняют команду по расписанию в среде вашего App, а затем останавливаются до следующего запуска. Опишите расписание обычными словами, например «каждый будний день в 9 утра», и Replit автоматически преобразует это в расписание. Если запуск завершится ошибкой, вы получите оповещение.

Идеально подходит для:

* проверок состояния и отчётов о работоспособности;
* отправки уведомлений;
* запуска резервного копирования.

В настройки входят расписание, таймаут задачи, а также команды сборки и запуска. Запланированные развёртывания не обслуживают веб-страницы, поэтому публичного URL у них нет.
