Package Firewall bloque les paquets malveillants ou compromis au niveau du réseau, avant qu&#39;ils ne soient installés dans votre application. Intégré à [Replit Auto-Protect](/fr/ja/features/security/concepts#auto-protect), il est activé par défaut pour tous les créateurs et propulsé par [Socket](https://socket.dev), entreprise spécialisée dans la sécurité de la chaîne d&#39;approvisionnement logicielle.

Lorsque vous ou Agent exécutez une commande d&#39;installation telle que `npm install` ou `pip install`, la requête passe d&#39;abord par Package Firewall. Les paquets sains s&#39;installent normalement, sans que vous remarquiez quoi que ce soit. Les paquets signalés comme malveillants ou compromis par Socket sont bloqués avant que leur code n&#39;atteigne votre environnement.

Package Firewall est **activé par défaut pour tous les créateurs** : aucune configuration ni migration n&#39;est nécessaire. Il protège aussi bien les nouvelles applications que les applications existantes, et vous n&#39;avez rien à paramétrer.

<div id="section">
  ## Pourquoi la protection au moment de l&#39;installation est essentielle
</div>

La plupart des outils de sécurité de la chaîne d&#39;approvisionnement n&#39;analysent les dépendances qu&#39;à la publication, une fois les paquets déjà installés. Cela peut suffire pour les vulnérabilités ordinaires. Les logiciels malveillants, eux, sont différents : ils font des dégâts dès l&#39;instant où ils sont installés — vol de secrets, ouverture de portes dérobées, exfiltration de variables d&#39;environnement. Quand l&#39;analyse à la publication signale le problème, l&#39;attaque a déjà eu lieu.

Package Firewall referme cette fenêtre. En bloquant les paquets malveillants avant leur téléchargement, il stoppe l&#39;attaque avant qu&#39;une seule ligne de code malveillant ne soit exécutée.

<div id="section-2">
  ## Fonctionnement
</div>

1. Vous ou Agent exécutez une commande d&#39;installation telle que `npm install <package>` ou `pip install <package>`.
2. La requête passe par le Package Firewall, qui vérifie le paquet auprès des renseignements sur les menaces de Socket.
3. Si le paquet est sain, l&#39;installation se déroule normalement, sans différence perceptible.
4. Si le paquet est malveillant ou compromis, l&#39;installation est bloquée avant que le code n&#39;atteigne votre environnement.

En cas de blocage, un message clair vous indique ce qui a été bloqué et pourquoi, y compris la vulnérabilité ou la politique à l&#39;origine du blocage. Agent reçoit les mêmes signaux : il peut donc proposer une solution de rechange sûre, comme corriger une faute de frappe dans le nom du paquet, ou vous laisser trancher.

<div id="section-3">
  ### Gestionnaires de paquets pris en charge
</div>

Package Firewall sécurise les installations suivantes :

* **JavaScript** — npm, yarn, pnpm
* **Python** — pip
* **Go** — modules Go

<div id="package-firewall">
  ## Ce que détecte le Package Firewall
</div>

Le Package Firewall bloque à la fois les logiciels malveillants avérés et les versions de paquets légitimes compromises ou présentant des vulnérabilités connues (y compris pour des paquets très répandus). Beaucoup de ces vulnérabilités ayant été divulguées après la date limite d&#39;entraînement des modèles qui les recommandent, ces derniers peuvent suggérer avec assurance des versions de dépendances jugées sûres dans leurs données d&#39;entraînement, mais signalées depuis. Ces risques portent des noms bien établis dans le secteur :

* **Typosquattage** — un paquet malveillant dont le nom ne diffère que d&#39;une frappe de celui d&#39;un paquet authentique, par exemple `reqeusts` au lieu de `requests`. Il suffit de demander le mauvais paquet pour télécharger un logiciel malveillant.
* **Slopsquattage** — un modèle hallucine un nom de paquet inexistant, puis un attaquant enregistre ce nom exact et attend que le prochain Agent l&#39;installe.
* **Recommandations obsolètes** — de véritables paquets présentant des vulnérabilités divulguées, qu&#39;un modèle recommande parce qu&#39;ils étaient sûrs avant sa date limite d&#39;entraînement.

Cette dernière catégorie explique pourquoi le Package Firewall est si important pour les applications créées par IA : l&#39;Agent peut tenter d&#39;utiliser en toute confiance une dépendance devenue dangereuse, et le Package Firewall bloque l&#39;installation avant que ce code ne s&#39;exécute.

<div id="package-firewallreplit">
  ## Relation entre le Package Firewall et les autres outils de sécurité de Replit
</div>

Le Package Firewall est l&#39;une des trois couches complémentaires. Chacune protège une étape différente du cycle de vie de l&#39;application : utilisez-les donc conjointement plutôt que d&#39;en choisir une seule.

| Couche                                  | Moment d&#39;exécution               | Fonction                                                                                                                                                                                                                                                 |
| --------------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Package Firewall**                    | À l&#39;installation                 | Bloque les paquets malveillants ou compromis avant leur téléchargement (prévention).                                                                                                                                                                     |
| **Analyse automatique des dépendances** | Après l&#39;installation, en continu | Détecte les CVE nouvellement divulguées dans les dépendances installées et propose, en option, des correctifs préparés par Agent. Consultez le [Centre de sécurité du projet](/fr/ja/features/security/project-security-center#automatic-dependency-scans). |
| **Security Agent**                      | Avant la publication                 | Audite l&#39;ensemble de la base de code à la recherche de vulnérabilités liées au code, aux dépendances et à la confidentialité. Consultez les [analyses de sécurité d&#39;Agent](/fr/ja/features/security/agent-security-scans).                          |
