Databricks 커넥터를 사용하면 Replit Agent가 Databricks 워크스페이스를 쿼리할 수 있습니다. 빌더는 자연어를 사용하여 대시보드, 보고 도구 및 데이터 애플리케이션을 만들 수 있습니다. SQL 전문 지식이 필요하지 않습니다.

Replit은 두 가지 Databricks 연결 유형을 지원합니다. 각 쿼리를 실행할 ID에 따라 하나를 선택하세요.

## 연결 유형 선택

|                | **User-to-machine (U2M)**           | **Service principal (M2M)** |
| -------------- | ----------------------------------- | --------------------------- |
| Replit의 커넥터 이름 | Databricks for Databricks Apps(U2M) | Databricks(서비스 주체)          |
| 쿼리 ID          | 개별 빌더                               | 공유 서비스 주체                   |
| Databricks 권한  | 각 빌더의 Unity Catalog 권한              | 서비스 주체의 권한                  |
| 감사 속성          | 쿼리를 실행한 빌더                          | 서비스 주체                      |
| 빌더 로그인         | 각 빌더가 자신의 Databricks 계정으로 로그인       | 개별 Databricks 로그인 없음        |
| 적합한 용도         | 사용자별 권한 및 감사 속성                     | 공유 접근 및 비대화형 워크플로우          |

## U2M 커넥터 설정

U2M 설정에는 세 가지 역할이 관여합니다.

1. **Databricks 계정 관리자**: OAuth 앱 연결을 만들고 SQL 웨어하우스 세부 정보를 제공합니다.
2. **Replit 조직 관리자**: OAuth 자격 증명으로 커넥터를 구성합니다.
3. **빌더**: 자신의 Databricks 계정으로 로그인하고 구축을 시작합니다.

### U2M 사전 요구 사항

시작하기 전에 다음을 확인하세요.

* Databricks **계정 관리자**. 앱 연결은 워크스페이스 관리자 설정이 아닌 계정 콘솔에서 구성됩니다.
* Replit 조직 관리자.
* 커넥터를 사용할 모든 빌더의 Databricks 계정.
* SQL 웨어하우스에 대한 **사용 가능** 권한과 필요한 Unity Catalog 권한을 포함하여 모든 빌더의 워크스페이스 접근 권한.

### 1단계: OAuth 앱 연결 만들기

<Note>이 단계를 완료하려면 Databricks 계정 관리자여야 합니다.</Note>

Databricks 계정 관리자는 Replit을 OAuth 애플리케이션으로 등록합니다. 앱 연결은 Replit을 구성하는 데 사용되는 클라이언트 ID와 클라이언트 시크릿을 제공합니다.

<Steps>
  <Step title="Databricks 계정 콘솔 열기">
    Databricks 워크스페이스에서 오른쪽 상단의 워크스페이스 선택기를 열고 **계정 관리**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/manage-account-6374ed6bf0f2.png" alt="계정 관리가 표시된 Databricks 워크스페이스 선택기가 열려 있음" width="2000" height="1144" data-path="images/connectors/databricks/u2m/manage-account.png" />
    </Frame>
  </Step>

  <Step title="앱 연결 열기">
    계정 콘솔에서 **설정**을 선택한 다음 **앱 연결** 탭을 엽니다.

    <Frame>
      <img src="/assets/mirror/app-connections-96228e7f0f2e.png" alt="앱 연결 탭이 선택되고 연결 추가 버튼이 표시된 Databricks 계정 설정 페이지" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-connections.png" />
    </Frame>
  </Step>

  <Step title="Replit 연결 구성">
    **연결 추가**를 선택합니다. `replit-u2m`과 같이 Replit을 식별하는 애플리케이션 이름을 입력합니다.

    **리디렉션 URL**에 다음을 입력합니다.

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    **접근 범위**에서 **All APIs**를 선택합니다. 이렇게 하면 Agent가 Databricks SQL과 Databricks Apps를 구축하고 관리하는 데 필요한 Databricks API를 사용할 수 있습니다.

    **클라이언트 시크릿 생성**을 선택합니다. Databricks는 연결이 생성된 후에는 이 연결에 시크릿을 추가할 수 없습니다.

    조직의 보안 정책에 따라 토큰 수명을 설정합니다. 예시에서는 Databricks가 표시하는 최댓값인 **Access token TTL** `1440`분(24시간)과 **Refresh token TTL** `129600`분(90일)을 사용합니다. 리프레시 토큰 수명이 짧을수록 빌더가 더 자주 로그인해야 할 수 있습니다.

    **추가**를 선택합니다.

    <Warning>
      **All APIs**는 SQL 단독보다 더 광범위한 접근 권한을 부여합니다. 각 빌더의 Databricks 권한으로 커넥터의 실제 접근 범위를 제어하세요.
    </Warning>

    <Frame>
      <img src="/assets/mirror/app-configuration-6799b5769326.png" alt="Replit 애플리케이션 이름, 리디렉션 URL, All APIs 접근 권한, 클라이언트 시크릿 생성, 토큰 수명이 구성된 Databricks 연결 추가 양식" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-configuration.png" />
    </Frame>
  </Step>

  <Step title="OAuth 자격 증명 저장">
    **클라이언트 ID**와 **클라이언트 시크릿**을 복사한 다음 조직의 시크릿 관리자에 저장합니다.

    <Warning>
      Databricks는 클라이언트 시크릿을 한 번만 표시합니다. 만료일을 기록해 두고 시크릿이 만료되기 전에 앱 연결을 교체하세요.
    </Warning>

    <Frame>
      <img src="/assets/mirror/oauth-credentials-15b2e6c67309.png" alt="클라이언트 ID와 클라이언트 시크릿이 가려진 Databricks 연결 생성 완료 대화 상자와 일회성 시크릿 경고 및 만료일" width="2000" height="1144" data-path="images/connectors/databricks/u2m/oauth-credentials.png" />
    </Frame>
  </Step>
</Steps>

<Note>
  새로 만들거나 업데이트한 OAuth 앱 연결은 사용 가능해지기까지 최대 30분이 걸릴 수 있습니다.
</Note>

### 2단계: SQL 웨어하우스 세부 정보 공유

각 빌더는 U2M 커넥터를 승인할 때 SQL 웨어하우스 세부 정보를 입력합니다. 내부 온보딩 페이지 등 빌더가 접근할 수 있는 곳에 이 값들을 게시하세요.

<Steps>
  <Step title="SQL 웨어하우스 열기">
    Databricks 워크스페이스에서 **SQL 웨어하우스**를 선택하고 빌더가 사용할 웨어하우스를 엽니다.

    <Frame>
      <img src="/assets/mirror/sql-warehouses-cc178d18a33b.png" alt="사용 가능한 웨어하우스가 표시된 Databricks SQL 웨어하우스 페이지" width="3438" height="1984" data-path="images/connectors/databricks/sql-warehouses.png" />
    </Frame>
  </Step>

  <Step title="연결 세부 정보 복사">
    **연결 세부 정보**를 선택한 다음 **서버 호스트명**과 **HTTP 경로**를 복사합니다.

    <Frame>
      <img src="/assets/mirror/connection-details-938b970b98e6.png" alt="서버 호스트명과 HTTP 경로가 있는 Databricks SQL 웨어하우스 연결 세부 정보 페이지" width="3438" height="1984" data-path="images/connectors/databricks/connection-details.png" />
    </Frame>
  </Step>
</Steps>

### 3단계: Replit에서 U2M 활성화

<Note>커넥터를 구성하려면 Replit 조직 관리자여야 합니다.</Note>

<Steps>
  <Step title="U2M 커넥터 열고 활성화">
    Replit 계정 홈에서 **설정**을 연 다음 **통합**을 엽니다. `Databricks U2M`을 검색하여 \*\*Databricks for Databricks Apps(U2M)\*\*을 찾고 **활성화**를 선택합니다.

    Databricks 앱 연결에서 얻은 **클라이언트 ID**와 **클라이언트 시크릿**을 입력합니다.

    Replit에 표시된 리디렉션 URL이 Databricks에 구성된 URL과 일치하는지 확인합니다.

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    **커넥터 범위**에서 `all-apis`와 `offline_access`를 활성화합니다. `offline_access` 범위는 Replit에 장기 세션을 위한 리프레시 토큰을 제공합니다.

    **구성**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/enable-connector-39c1eeebd230.png" alt="Databricks U2M으로 필터링된 Replit 통합 설정과 리디렉션 URL, OAuth 자격 증명 필드, 커넥터 범위가 표시된 활성화 패널" width="2000" height="1144" data-path="images/connectors/databricks/u2m/enable-connector.png" />
    </Frame>
  </Step>

  <Step title="커넥터가 활성화되었는지 확인">
    **내 통합** 아래에 \*\*Databricks for Databricks Apps(U2M)\*\*이 표시되는지 확인합니다.
  </Step>
</Steps>

### 4단계: 빌더로 로그인

각 빌더는 커넥터를 사용하기 전에 자신의 Databricks 계정으로 로그인합니다. Replit은 리프레시 토큰이 만료될 때까지 세션을 갱신할 수 있습니다.

<Steps>
  <Step title="커넥터에 로그인">
    **통합** 페이지에서 \*\*Databricks for Databricks Apps(U2M)\*\*을 찾아 **로그인**을 선택합니다. 연결 세부 정보를 검토한 다음 **Databricks for Databricks Apps로 계속**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/connect-modal-8ae2c2569658.png" alt="리디렉션, 개인정보 보호, 권한 제어를 설명하는 Databricks for Databricks Apps 연결 모달" width="2000" height="1144" data-path="images/connectors/databricks/u2m/connect-modal.png" />
    </Frame>
  </Step>

  <Step title="SQL 웨어하우스 세부 정보 입력">
    Databricks 관리자가 제공한 SQL 웨어하우스 **HTTP 경로**를 입력한 다음 **다음**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/http-path-9e8a8a14b6ab.png" alt="2단계 중 1단계에서 SQL 웨어하우스 HTTP 경로를 요청하는 Databricks for Databricks Apps 연결 대화 상자" width="2000" height="1144" data-path="images/connectors/databricks/u2m/http-path.png" />
    </Frame>

    다음으로 Replit은 SQL 웨어하우스 **서버 호스트명**을 요청합니다. 이를 입력하고 Databricks로 계속 진행합니다. 메시지가 표시되면 로그인하고 요청된 접근 권한을 검토한 다음 요청을 승인합니다.

    이 연결을 통해 Agent가 실행하는 모든 쿼리는 사용자의 Databricks 권한을 사용하며 Databricks 감사 로그에 사용자로 귀속됩니다.

    승인 후 Databricks는 사용자를 Replit으로 돌려보내고 커넥터를 사용할 준비가 됩니다.
  </Step>
</Steps>

## 서비스 주체 커넥터 설정

서비스 주체 설정에는 세 가지 역할이 관여합니다.

1. **Databricks 관리자**: Databricks에서 서비스 주체를 만들고 권한을 부여합니다.
2. **Replit 조직 관리자**: Replit에서 커넥터와 접근 권한을 구성합니다.
3. **빌더**: 공유 Databricks ID로 구축을 시작합니다.

### 서비스 주체 사전 요구 사항

시작하기 전에 다음을 확인하세요.

* Databricks 계정 관리자 또는 워크스페이스 관리자 접근 권한.
* Replit 조직 관리자 접근 권한.

### 1단계: Databricks에서 서비스 주체 만들기

<Note>
  이 단계를 완료하려면 Databricks 계정 관리자 또는 워크스페이스 관리자여야 합니다.
</Note>

Databricks 관리자는 Replit이 Databricks에 연결하는 데 사용하는 [서비스 주체](https://docs.databricks.com/aws/en/admin/users-groups/service-principals)라는 머신 간 ID를 만듭니다.

<Steps>
  <Step title="설정 열기">
    Databricks에서 오른쪽 상단의 아바타를 선택한 다음 **설정**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/settings-menu-8f2dcd4dbee3.png" alt="설정이 선택된 Databricks 워크스페이스 메뉴" width="3438" height="1984" data-path="images/connectors/databricks/settings-menu.png" />
    </Frame>
  </Step>

  <Step title="ID 및 접근 선택">
    설정 사이드바에서 **ID 및 접근**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/settings-page-2a8bcd7c22a4.png" alt="사이드바에 ID 및 접근이 있는 Databricks 설정 페이지" width="3438" height="1984" data-path="images/connectors/databricks/settings-page.png" />
    </Frame>
  </Step>

  <Step title="서비스 주체 관리">
    **관리 및 권한** 아래에서 **서비스 주체**를 찾아 **관리**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/identity-and-access-0e79404ed30f.png" alt="서비스 주체 관리 버튼이 표시된 ID 및 접근 설정 페이지" width="3438" height="1984" data-path="images/connectors/databricks/identity-and-access.png" />
    </Frame>
  </Step>

  <Step title="새 서비스 주체 추가">
    **서비스 주체 추가**를 선택한 다음 **새로 추가**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/add-service-principal-ac5b52f21f4c.png" alt="새로 추가 버튼이 있는 서비스 주체 추가 대화 상자" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal.png" />
    </Frame>
  </Step>

  <Step title="서비스 주체 이름 지정">
    서비스 주체의 명확한 이름을 입력한 다음 **추가**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/add-service-principal-name-897df9e5f7ac.png" alt="서비스 주체 이름이 입력된 서비스 주체 추가 대화 상자" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal-name.png" />
    </Frame>
  </Step>

  <Step title="서비스 주체 세부 정보 확인">
    Databricks가 서비스 주체를 만든 후 활성 상태인지 확인합니다. Replit 커넥터를 구성하는 동안 서비스 주체 세부 정보가 필요한 경우 이 페이지를 열어 두세요.

    <Frame>
      <img src="/assets/mirror/service-principal-details-15a381d388bc.png" alt="Databricks 서비스 주체 세부 정보 페이지" width="3438" height="1984" data-path="images/connectors/databricks/service-principal-details.png" />
    </Frame>
  </Step>

  <Step title="접근 권한 부여">
    **권한** 탭을 열고, **접근 권한 부여**를 선택하고, 서비스 주체를 선택하고, 권한을 **관리**로 설정한 다음 **저장**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/grant-access-edbaa2541a7d.png" alt="관리 권한이 선택된 Databricks 서비스 주체 접근 권한 부여 대화 상자" width="3438" height="1984" data-path="images/connectors/databricks/grant-access.png" />
    </Frame>
  </Step>
</Steps>

<Steps>

    </Frame>
  </Step>

  <Step title="웨어하우스 선택 또는 생성">

  </Step>

  <Step title="연결 세부 정보 복사">
    웨어하우스를 열고 **연결 세부 정보**를 선택합니다. **서버 호스트명** 및 **HTTP 경로** 값을 찾습니다. Replit에서 Databricks 커넥터를 만들 때 이 값들이 필요합니다.

## Agent로 구축

두 연결 방법 중 하나로 연결한 후, 빌더는 Agent를 사용하여 Databricks 데이터를 활용하는 애플리케이션을 만들 수 있습니다.

<Steps>
  <Step title="배포용 Databricks App 템플릿 선택">
    완성된 앱을 Databricks 환경에 배포하려면 **Databricks App** 템플릿을 선택하세요. 구성된 커넥터로 Databricks 데이터와 자산에 접근하는 데는 이 템플릿이 필요하지 않습니다.

    Replit 홈페이지에서 템플릿 선택기를 열고 **Databricks App**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/databricks-template-cdfbbba1a2ab.png" alt="프롬프트 박스 위에 Databricks App 템플릿이 선택된 Replit 홈페이지" width="1200" height="400" data-path="images/connectors/databricks/u2m/databricks-template.png" />
    </Frame>
  </Step>

  <Step title="애플리케이션 설명">
    미리 채워진 지침 뒤에 프롬프트를 추가하세요. 영감을 얻으려면 [Databricks Dev Hub 템플릿](https://www.databricks.com/devhub/templates)을 살펴보세요.
  </Step>

  <Step title="검토 및 반복">
    Agent가 생성한 SQL, 쿼리하는 테이블, 애플리케이션 구조를 검토합니다. 자연어로 변경 사항을 요청하세요.
  </Step>
</Steps>

## 문제 해결

<AccordionGroup>
  <Accordion title="쿼리가 빈 결과를 반환함">
    쿼리를 실행하는 ID의 Databricks 권한을 확인합니다. U2M의 경우 개별
    빌더이고, 서비스 주체 커넥터의 경우 공유 서비스 주체입니다. 해당 ID에
    메타데이터 접근 권한은 있지만 데이터에 대한 읽기 권한이 없을 수 있습니다.
    필요한 카탈로그, 스키마 또는 테이블 권한을 부여하고 다시 시도하세요.
  </Accordion>

  <Accordion title="커넥터가 SQL 웨어하우스에 연결할 수 없음">
    **서버 호스트명**과 **HTTP 경로**가 Databricks의 SQL 웨어하우스
    연결 세부 정보와 일치하는지 확인합니다. U2M의 경우 영향을 받는 빌더가
    입력한 값을 확인하세요. 또한 웨어하우스가 실행 중이며 쿼리 ID에 이를
    사용할 권한이 있는지 확인하세요.
  </Accordion>

  <Accordion title="인증 실패">
    U2M의 경우 Databricks 앱 연결의 **리디렉션 URL**에
    `https://replit.com/connectors/oauth/callback`이 마지막에 슬래시 없이
    등록되어 있는지 확인하세요. 모든 빌더에서 인증이 실패하면 공유된
    클라이언트 ID와 클라이언트 시크릿을 확인하고, 시크릿이 만료되지
    않았는지 확인하고, Replit의 범위가 Databricks 앱 연결과 일치하는지
    확인하세요.

    서비스 주체 커넥터의 경우 Replit에 입력된 서비스 주체 세부 정보가
    Databricks에서 생성한 서비스 주체와 일치하는지 확인하세요. 자격 증명이
    교체된 경우 Replit에서 커넥터를 업데이트하세요.
  </Accordion>

  <Accordion title="커넥터가 다시 로그인을 요청함">
    이는 리프레시 토큰이 만료되거나 취소된 경우 U2M에서 발생할 수 있습니다.
    Databricks 인증 흐름을 다시 완료하세요. 보안 정책에서 요구하는 것보다
    빌더가 더 자주 다시 연결해야 하는 경우 앱 연결의 토큰 수명을 검토하세요.
  </Accordion>
</AccordionGroup>
