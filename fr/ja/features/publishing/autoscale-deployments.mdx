Les déploiements Autoscale s&#39;exécutent sur des ressources de calcul cloud qui montent ou descendent en charge afin de traiter efficacement le trafic réseau et la charge de travail de votre Replit App. Lorsque votre application est très sollicitée, l&#39;autoscaling ajoute des serveurs pour absorber la charge. Lorsqu&#39;elle est inactive, le nombre de serveurs est réduit jusqu&#39;à zéro pour réduire les coûts.

Les déploiements Autoscale conviennent parfaitement aux cas d&#39;usage suivants :

* Les applications web soumises à un trafic et à des charges de travail variables, comme les sites d&#39;e-commerce
* Les API et les services

<div id="section">
  ## Fonctionnalités
</div>

Les déploiements autoscale offrent les fonctionnalités suivantes :

* **Mise à l&#39;échelle automatique des ressources** : ajuste automatiquement les ressources selon les tendances de trafic afin d&#39;optimiser les coûts.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez l&#39;URL `<app-name>.replit.app` pour accéder à votre App.
* **Limites configurables** : définissez le nombre maximal d&#39;instances auquel votre application publiée peut monter en charge.
* **Puissance machine flexible** : choisissez la configuration CPU et RAM adaptée aux besoins de votre App.
* **Surveillance** : consultez les journaux et suivez l&#39;état de vos applications publiées.

<div id="section-2">
  ## Utilisation
</div>

Les déploiements Autoscale sont accessibles depuis l&#39;outil Publishing de l&#39;éditeur de projet.

<Accordion title="Comment accéder aux déploiements Autoscale">
  Depuis la **barre d&#39;outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône All tools" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils de l&#39;éditeur de projet.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Autoscale**, puis **Set up your published app**.

  Depuis la **barre de recherche** :

  1. Sélectionnez la loupe <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> en haut pour ouvrir l&#39;outil de recherche.
  2. Saisissez « Publishing » pour rechercher l&#39;outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l&#39;option **Autoscale**, puis **Set up your published app**.
</Accordion>

<div id="section-3">
  ## Puissance machine
</div>

Sélectionnez **Edit** pour consulter et configurer les options de puissance machine. Utilisez le curseur pour définir les paramètres de CPU et de RAM de chaque instance de serveur de l&#39;application publiée.

La ligne **Total per machine** indique le coût de votre configuration en **unités de calcul**.
L&#39;unité de calcul est une unité de mesure des ressources de cloud computing, basée sur les paramètres de mémoire et de CPU de la machine.

Pour savoir comment les coûts sont calculés à partir des unités de calcul, consultez [Unités de calcul](/fr/ja/billing/about-usage-based-billing#2-compute-units).

<div id="section-4">
  ## Nombre maximal de machines
</div>

Utilisez le curseur pour ajuster le nombre maximal de machines. Ce nombre correspond à la limite d&#39;instances de serveur que la fonctionnalité d&#39;autoscaling peut allouer lorsqu&#39;elle détecte que votre app est fortement sollicitée.

La ligne du dessous affiche l&#39;équivalent en unités de calcul, obtenu à partir de la formule suivante :

`Nombre de machines × unités de calcul par machine`
