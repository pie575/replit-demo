Vous trouverez ici des réponses aux questions fréquentes sur la gestion des projets et des fichiers. Consultez les ressources associées : [Secrets](/fr/ja/core-concepts/project-editor/app-setup/secrets), [checkpoints et restaurations](/fr/ja/features/version-control/checkpoints-and-rollbacks) et [présentation des intégrations](/fr/ja/features/integrations/overview).

<AccordionGroup>
  <Accordion title="Comment connecter Resend et d’autres services de messagerie à votre application Replit ?">
    Ouvrez le projet et accédez à **Tools → Connectors**, puis recherchez un service (tel que Resend) et connectez-le. Après l’authentification, la clé API est enregistrée dans les secrets du projet. Si vous configurez un domaine d’e-mail personnalisé, ajoutez auprès de votre fournisseur DNS les enregistrements DNS indiqués par le service.

    Pour connaître les connecteurs disponibles, consultez la [présentation des intégrations](/fr/ja/features/integrations/overview) et la page [Ajouter des intégrations](/fr/ja/build/add-integrations).
  </Accordion>

  <Accordion title="J’ai supprimé un projet par erreur ; puis-je le récupérer ?">
    Les projets supprimés peuvent être restaurés pendant une durée limitée. Ouvrez le Shell dans n’importe quel projet, puis exécutez la commande suivante :

    ```bash theme={null}
    trash view
    trash restore your-project-name
    ```

    Une fois la période de conservation écoulée, les projets supprimés sont définitivement supprimés. Si ce délai est dépassé, [contactez l’assistance Replit](https://replit.com/support).
  </Accordion>

  <Accordion title="Comment télécharger ou exporter un projet Replit ?">
    Sélectionnez le menu à trois points en haut de l’arborescence des fichiers, puis **Download as zip**. Pour les projets volumineux, le téléchargement peut prendre un peu de temps. En cas d’échec, ouvrez le Shell, exécutez `zip -r project.zip .`, puis téléchargez `project.zip` depuis l’arborescence des fichiers.
  </Accordion>

  <Accordion title="Comment partager un projet ou ajouter des collaborateurs ?">
    Vous avez 3 options :

    * **Lecture seule**—rendez le projet public afin que toute personne disposant du lien puisse le consulter.
    * **Accès en modification sur invitation**—sélectionnez **Invite**, puis saisissez un nom d’utilisateur ou une adresse e-mail et définissez le niveau d’autorisation.
    * **Lien de participation**—créez un lien de participation depuis **Invite** afin que toute personne disposant du lien puisse rejoindre le projet et le modifier.

    Core prend en charge jusqu’à 5 collaborateurs et Pro jusqu’à 15. Les collaborateurs n’ont pas besoin d’un forfait payant pour modifier les projets. Consultez les [espaces de travail](/fr/ja/features/collaboration/workspaces).
  </Accordion>

  <Accordion title="Comment connecter un dépôt GitHub à Replit ?">
    Associez votre compte GitHub dans les services connectés de votre compte, puis ouvrez les [outils Git](/fr/ja/features/workspace-tools/git-interface) du projet pour connecter un dépôt. Activez la synchronisation automatique dans le volet Git afin d’activer la synchronisation bidirectionnelle. Pour importer un dépôt existant, consultez [Importer depuis des fournisseurs](/fr/ja/build/import-from-providers).

    Si la synchronisation Git s’interrompt, reconnectez GitHub dans les services connectés. L’utilisation d’un jeton d’accès personnel à granularité fine permet d’établir une connexion plus stable.
  </Accordion>

  <Accordion title="Mon Repl est lent ou l’éditeur présente des ralentissements — que puis-je faire ?">
    En cas de lenteurs dans l’éditeur, essayez ce qui suit :

    * Effectuez un rechargement forcé avec `Cmd+Shift+R` sur Mac ou `Ctrl+Shift+R` sur Windows.
    * Fermez les onglets de fichiers inutilisés.
    * Ouvrez la palette de commandes avec `Cmd+K` sur Mac ou `Ctrl+K` sur Windows, puis recherchez et sélectionnez **Restart compute**.
    * Essayez un autre navigateur afin d’écarter les problèmes liés aux extensions.

    Si c’est l’exécution de votre code qui est lente, plutôt que l’éditeur, vérifiez la présence de boucles gourmandes ou de limites de mémoire. Vous pouvez consulter l’utilisation du processeur et de la mémoire dans le panneau des ressources situé en bas de l’éditeur.
  </Accordion>

  <Accordion title="Comment utiliser des variables d’environnement et des secrets dans un projet ?">
    Ouvrez l’outil **Secrets** (icône de clé), sélectionnez **+ New secret**, puis saisissez la clé et la valeur. Accédez-y dans votre code avec `process.env.API_KEY` (Node.js) ou `os.environ["API_KEY"]` (Python).

    Les secrets du volet [Secrets](/fr/ja/core-concepts/project-editor/app-setup/secrets) de développement ne peuvent être utilisés que dans l’éditeur. Pour les applications publiées, ajoutez la même clé aux secrets de déploiement : ils sont volontairement gérés séparément.
  </Accordion>

  <Accordion title="Comment utiliser les Secrets du compte（Vault） ?">
    Les [Secrets du compte](/fr/ja/core-concepts/project-editor/app-setup/secrets) sont disponibles dans tous les projets : ils sont pratiques pour les clés réutilisées. Ajoutez-les depuis les paramètres de votre compte afin de pouvoir les utiliser dans tous les projets dont vous êtes propriétaire. Si une même clé existe à la fois dans les Secrets du compte et dans le volet Secrets d’un projet, la valeur définie au niveau du projet prévaut.
  </Accordion>

  <Accordion title="Comment récupérer après des conflits de fusion ou un état Git corrompu ?">
    Ouvrez le Shell et exécutez `git status` pour vérifier s’il y a des conflits.

    <Warning>Les deux commandes suivantes suppriment les modifications non validées de manière irréversible. Copiez d’abord tout ce que vous souhaitez conserver, par exemple en copiant les fichiers modifiés hors du projet.</Warning>

    Pour supprimer les modifications locales et revenir au dernier état propre, exécutez `git checkout -- .`. Pour réinitialiser au dernier commit, exécutez `git reset --hard HEAD`.

    Si le dossier `.git` est corrompu et que les commandes Git échouent, ouvrez une nouvelle conversation avec Agent et collez l’erreur : Agent peut souvent réparer le dépôt. Consultez [Récupération après sinistre](/fr/ja/features/version-control/disaster-recovery).
  </Accordion>

  <Accordion title="Comment restaurer un projet à un point de contrôle précédent ?">
    Replit enregistre des checkpoints pendant le travail d’Agent. Dans le panneau Agent, repérez le message précédant les modifications que vous souhaitez annuler, puis sélectionnez l’option de restauration à côté de ce message et confirmez. Consultez les [checkpoints](/fr/ja/features/version-control/checkpoints-and-rollbacks) pour plus de détails.

    <Note>
      Replit ne prend plus en charge la restauration des applications publiées vers une version antérieure. Pour annuler les modifications apportées à une application publiée, restaurez le projet à un checkpoint précédent (comme expliqué ci-dessus), puis publiez-le de nouveau afin de redéployer cet état. Pour récupérer un seul fichier, ouvrez-le, sélectionnez son nom, puis utilisez **Show history** pour restaurer une version antérieure. Consultez l’[historique des fichiers](/fr/ja/features/version-control/file-history).
    </Note>
  </Accordion>

  <Accordion title="Comment transférer un projet vers un autre compte Replit ?">
    Vous ne pouvez pas transférer directement un projet, mais vous pouvez le copier. Le plus simple est de partager le projet avec le compte de destination, puis de le forker depuis ce compte. Vous pouvez également télécharger le projet au format ZIP et l’importer dans un nouveau Repl d’un autre compte.

    Après la copie, configurez les secrets, la base de données et les paramètres de déploiement dans le nouveau projet : ils ne sont pas inclus dans la copie. Pour des instructions détaillées, notamment sur la migration des données de la base de données, consultez [Copier manuellement des projets vers un autre espace de travail](/fr/ja/teams/identity-and-access-management/manually-copy-projects).
  </Accordion>
</AccordionGroup>
