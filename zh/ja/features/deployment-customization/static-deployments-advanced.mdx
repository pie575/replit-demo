<div id="section">
  ## 添加响应标头
</div>

使用自定义的**响应标头**，您可以为匹配特定路径的请求添加 HTTP 标头指令。
响应标头是由名称和值组成的键值对，用于指示浏览器应如何处理请求的内容。

例如，您可以指定 `Access-Control-Allow-Origin` 标头，以定义浏览器允许访问该页面的域名。
要创建此条目，请将以下内容添加到 Replit App 根目录中的 `.replit` 文件：

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

此响应标头包含以下参数：

* **path**：与请求资源匹配的 URL 路径模式
* **name**：HTTP 标头名称
* **value**：HTTP 标头值

您可以在 `.replit` 文件中添加多个 `deployment.responseHeaders` 条目。

要使更新后的配置生效，请重新发布 Replit App。

<div id="404">
  ## 创建自定义 404 页面
</div>

当用户请求的 URL 路径与已发布 App 中的任何文件或规则均不匹配时，系统会显示自定义 404 页面。

要添加自定义 404 页面，请在 Replit App 的根目录中创建一个名为 `404.html` 的文件，并在其中编写页面内容。

当用户尝试访问不存在的 URL 路径时，系统会显示自定义 404 页面的渲染后 HTML。

<div id="url">
  ## 定义 URL 路径重写
</div>

通过定义 URL 重写，您可以在 Replit App 处理请求前更改 URL 路径。
原始 URL 在浏览器中保持不变，但服务器会加载重写规则所指定的资源。

例如，您可以指定所有以 `/app` 开头的请求均加载 `/app/index.html` 文件的内容。
要创建此条目，请在 Replit App 根目录的 `.replit` 文件中添加以下内容：

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**: 与所请求资源匹配的 URL 路径模式
* **to**: 重写后的路径，对应静态部署中的文件。

你可以在 `.replit` 文件中添加多个 `deployment.rewrites` 条目。
服务器会按条目列出的顺序处理，并忽略重复项。

要使更新后的配置生效，必须重新发布 Replit App。

以下部分将介绍 URL 重写规则的限制。

<div id="section-3">
  ### 路径匹配
</div>

重写规则的 `from` 和 `to` 参数适用以下限制：

* 未使用 `*` 时，必须完全匹配
* `*` 匹配路径的其余部分
* `*` 仅可用于路径末尾
* 如果 `from` 参数中包含 `*`，则也可在 `to` 参数中使用 `*` 来表示匹配到的路径部分

例如，假设 `.replit` 文件包含以下重写规则：

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

当用户访问 `/v1/about-us.html` 时，重写规则会提供位于 `/v2/about-us.html` 的文件。

<div id="section-4">
  ### 遮蔽
</div>

当重写规则匹配的 URL 路径同时也匹配静态部署中的文件时，就会发生遮蔽。
在这种情况下，云服务器会忽略重写规则，直接提供该文件。

例如，假设已发布的应用包含以下文件：

* `index.html`
* `about.html`

`.replit` 文件包含以下重写规则：

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

当用户访问 `/register.html` 时，服务器会将请求重写为 `/index.html`，然后提供该文件。
但当用户访问 `/about.html` 时，由于该文件存在于静态部署中，服务器会忽略重写规则，直接提供 `about.html` 文件。

<div id="section-5">
  ### 域名限制
</div>

重写规则仅适用于发往静态部署主域名的请求，
且只能重定向到该静态部署中的文件。
