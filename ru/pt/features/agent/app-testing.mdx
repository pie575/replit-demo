App Testing позволяет Agent тестировать созданные им приложения в реальном браузере. Agent перемещается по приложению так же, как это делал бы настоящий пользователь: нажимает на элементы и проверяет работу функций. Такое самотестирование помогает убедиться, что приложение работает корректно, и позволяет Agent автоматически находить и устранять проблемы.

Когда App Testing включён, Agent периодически сам решает, нужно ли запускать тестирование, — если считает, что изменений накопилось достаточно. Agent тестирует не после каждого сообщения пользователя, а разумно определяет, когда тестирование принесёт наибольшую пользу.

<Note>
  На данный момент App Testing доступен для веб-приложений JavaScript Full Stack и веб-приложений Python Streamlit.
</Note>

<div id="principais-benefcios">
  ### Основные преимущества
</div>

* **Расширенная автономность**: Agent может работать дольше без участия человека
* **Более высокое качество**: приложения содержат меньше ошибок благодаря раннему выявлению и устранению проблем
* **Экономия средств**: не требуются дополнительные сессии отладки, так как проблемы обнаруживаются ещё в ходе разработки
* **Интерактивный разбор**: доступны видеозаписи и переход по разделам для детального анализа результатов

<div id="o-processo-de-teste">
  ### Процесс тестирования
</div>

Когда Agent решает провести тестирование, происходит следующее:

1. **Предпросмотр в браузере**: в панели Agent появится окно предпросмотра браузера
2. **Визуальное тестирование**: вы наблюдаете за курсором Agent, который кликает по приложению и проверяет функции
3. **Имитация реального пользователя**: Agent перемещается по приложению так же, как это делал бы реальный пользователь, и при необходимости вводит тестовые данные
4. **Автоматический анализ**: Agent анализирует результаты тестирования и выявляет проблемы
5. **Самостоятельное исправление**: Agent показывает сводку по тестам и автоматически устраняет найденные проблемы

<div id="principais-capacidades">
  ## Основные возможности
</div>

Agent разумно тестирует ваше приложение, перемещаясь по нему так, как это делал бы реальный пользователь, и охватывает:

* **Проверку пользовательского интерфейса**: кнопки, формы, навигацию и визуальные элементы
* **Проверку функциональности**: ключевые возможности и пользовательские сценарии
* **Тестирование интеграций**: вызовы API, взаимодействие с базой данных и сторонними сервисами
* **Производительность и доступность**: время загрузки, адаптивность и стандарты доступности

<div id="uso">
  ## Использование
</div>

App Testing находится в разделе **Расширенные настройки** в выпадающем меню настроек Agent рядом с полем ввода чата. Включите эту функцию при работе в режиме Economy или Power. В режиме Lite App Testing всегда отключён.

<div id="assumir-controle">
  ## Перехват управления
</div>

Иногда во время тестирования Agent сталкивается с препятствием и не может продолжить без вашей помощи. Чаще всего речь идёт о входе в учётную запись пользователя (например, Gmail). В таких случаях Agent покажет кнопку «Начать перехват управления».

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="Интерфейс перехвата управления в App Testing с кнопками «Пропустить» и «Начать перехват управления» и инструкциями по обработке ошибок и CAPTCHA" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

Нажав «Начать перехват управления», вы сможете взаимодействовать с тестовым предпросмотром, выполнить нужные шаги и вернуть управление Agent. Также можно нажать «Пропустить» и отказаться от перехвата управления — тогда App Testing завершится, если Agent не может продолжить без вашей помощи. Если вы не ответите в течение 10 минут, Agent продолжит так, как если бы вы нажали «Пропустить».

<div id="o-que-esperar">
  ### Чего ожидать
</div>

* **Возможность пропустить**: нажмите кнопку пропуска, чтобы при необходимости обойти тесты и продолжить разработку
* **Интерактивный видеоповтор**: после завершения тестов нажмите на видео, чтобы воспроизвести всю сессию тестирования
* **Навигация по разделам**: используйте ползунки внизу, чтобы перейти к нужным разделам теста

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

**Тесты неожиданно завершаются с ошибкой**

* Попробуйте пропустить тест и запросить тестирование заново
* Проверьте, нет ли динамического содержимого, которое может влиять на время выполнения тестов
* Проверьте тестовые сценарии на корректность

**Неполное покрытие тестами**

* Опишите функциональность вашего приложения подробнее
* Прямо укажите критически важные пользовательские сценарии, которые нужно протестировать

**App Testing не работает?**

* Пока что App Testing работает только с веб-приложениями[*](#how-app-testing-works)

<div id="preos-e-uso">
  ## Цены и использование
</div>

App Testing входит в модель оплаты Agent, основанную на затраченных усилиях, и имеет ряд важных особенностей в части стоимости:

* **Оплата по факту использования**: тестирование тарифицируется исходя из затраченных усилий (чем проще тесты, тем дешевле)
* **Затраты и выгода**: тестирование стоит денег, но в итоге помогает сэкономить: ошибки обнаруживаются раньше, а значит, не нужны дополнительные prompt и лишняя работа Agent
* **Эффективная разработка**: автоматизированный подход снижает потребность в ручной отладке и переделках

<Tip>
  **Экономичное тестирование**: хотя App Testing увеличивает расходы на использование, в целом он обычно позволяет сэкономить, избавляя от дополнительных сессий Agent для исправления проблем, которые можно было выявить ещё на этапе тестирования.
</Tip>
