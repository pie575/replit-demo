---

每个 Replit App 都会用到两个数据库。**开发数据库**供你和 Agent 在构建过程中自由试验。**生产数据库**则存放支撑已发布应用运行的真实数据，让你在持续构建的同时，确保真实数据安全无虞。

<div id="como-eles-se-comparam">
  ## 两者对比
</div>

| 方面        | 开发数据库               | 生产数据库           |
| --------- | ------------------- | --------------- |
| **用途**    | 试验与功能开发             | 服务真实用户并存储业务数据   |
| **数据**    | 测试数据、虚构记录、小型数据集     | 真实用户数据、业务关键信息   |
| **创建方式**  | 随每个 Replit App 自动创建 | 在发布应用时创建        |
| **Agent** | Agent 可以创建和修改数据表    | Agent 无法对其进行更改  |
| **变更**    | 频繁变更表结构，快速迭代        | 谨慎、有计划地变更，发布时生效 |
| **计费**    | 每个 Replit App 均免费包含 | 按用量计费           |

<Note>
  Agent 无法修改生产数据库。此限制旨在保障生产数据库的安全。

  Agent 可以更改你的开发数据库。发布时，你通过 Agent 对开发数据库结构所做的更改 (新增或删除列、表) 都会应用到生产数据库。

  你随时可以手动编辑生产数据：打开 **Database** 工具，选择生产数据库，打开 **My Data** 并启用 **Edit**。
</Note>

<div id="crie-um-banco-de-dados-de-produo-ao-publicar">
  ## 发布时创建生产数据库
</div>

已发布的应用会获得专属的生产数据库，与你在构建时使用的开发数据库彼此独立。

* **当前基础设施 (Helium)&#x20;**：发布过程中，Replit 会在需要时自动为你创建生产数据库，无需任何配置。
* **旧版 Neon 开发数据库**：需要你在发布设置中创建生产数据库。发布时打开 **Production database settings**，启用 **Create production database**；如需复制开发数据，还可选择启用 **Set up your production database with your current development data**。

<Frame caption="Publishing 中的生产数据库设置">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="发布设置中显示的 Create production database 选项" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  只有确认开发数据可安全用于生产应用时，才将其复制到生产环境。开发数据可能包含测试账户、示例记录或不完整的内容。
</Warning>

发布完成后，已发布的应用将使用生产数据库。而你的 Project Editor 仍使用开发数据库，因此后续的开发改动不会直接影响生产环境中的数据。

<div id="pooling-de-conexes">
  ## 连接池
</div>

默认情况下，生产数据库未启用连接池。应用会通过 `DATABASE_URL` 连接字符串直接连接数据库，因此大多数框架需要在客户端自行管理连接池。

<Note>
  每个 Neon 项目都会提供一个直连字符串和一个连接池字符串。直连字符串的形式如下：`postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`。

  若要使用连接池连接，请在主机名后添加 `-pooler`：`postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`。
</Note>

如果生产环境连接字符串已泄露，请[重新生成生产数据库的凭据](/zh/pt/features/data-and-storage/connection-details#regenerar-as-credenciais-do-banco-de-dados-de-produção)。

<div id="fazendo-alteraes-seguras-no-seu-banco-de-dados-de-produo">
  ## 安全地变更生产数据库
</div>

发布包含数据库变更的更新时，某些变更需要周密规划，以免造成停机或数据丢失。

<Info>
  在发布过程中，你可能会发现已发布的应用出现短暂停机。数据库变更有时需要临时停止应用，以便在应用变更时避免冲突并保护你的数据。
</Info>

以下类型的变更通常需要谨慎处理：

* **删除数据库列**，而应用代码仍在引用这些列
* **更改列的数据类型**，且现有代码无法处理新类型
* 向现有表**添加没有默认值的必填字段**
* **重命名表或列**，导致现有查询失效
* **修改约束**，可能导致现有应用逻辑被拒绝

<div id="teste-as-alteraes-com-uma-prvia-de-implantao">
  ### 使用部署预览测试更改
</div>

部署预览是生产环境的临时隔离副本，您可以在其中测试数据库更改和应用更新，避免影响真实用户。您可以用它来：

* 验证应用数据库更改后，您的应用在所有主要用户流程中仍能正常运行
* 确认现有数据已正确迁移，且新字段的值符合预期
* 留意查询响应时间是否出现性能回退

<div id="faturamento-e-uso-de-recursos">
  ## 计费与资源使用
</div>

生产数据库通过无服务器数据库提供商 Neon 按使用量计费。数据库闲置五分钟后进入休眠状态，暂停计算时间的计费；一旦收到查询即可立即恢复运行。

Database 工具的初始视图会显示你的 **Billing Period** 和 **Hours of Compute Used**。若要查看单个数据库的存储用量，请打开该数据库的 **Settings** 标签页。若要查看各个 Replit App 的使用情况，请依次打开 **Settings** → **Account** → **Account usage**，并展开 **PostgreSQL Storage** 和 **PostgreSQL Compute** 两行。

要了解 Replit 如何对数据库使用量计费，请参阅 [Deployments and Database Billing](/zh/pt/billing/about-usage-based-billing#databases)。

<div id="removendo-um-banco-de-dados-de-produo">
  ## 删除生产数据库
</div>

<Warning>
  删除操作在 7 天保留期结束后将无法撤销。请务必在继续操作前备份所有重要数据。数据库会进入为期 7 天的软删除状态，在此期间仍可恢复；如需协助，请联系支持团队。7 天后，数据库将被永久删除，无法找回。
</Warning>

<Accordion title="如何删除数据库">
  在 **Database** 工具中：

  1. 选择数据库，然后打开 **Settings** 标签页
  2. 选择 **Remove database**，再选择 **Yes, Remove database** 进行确认
</Accordion>

<div id="banco-de-dados-de-desenvolvimento-legado">
  ## 旧版开发数据库
</div>

在 2025 年 12 月 4 日之前，开发数据库托管在 <a href="https://neon.com/" target="_blank">Neon</a> 上。现在所有新建的开发数据库均托管在 Replit 自有基础设施 (Helium) 上。你可以在 **Settings** 标签页中查看应用使用的是哪种基础设施：`DATABASE_URL` 中包含 `neon.tech` 表示旧版 Neon；包含 `helium` 则表示当前基础设施。

| **功能**         | **Replit (当前)&#x20;**&#x20;                                                                   | **Neon (旧版)&#x20;**&#x20;                                                                             |
| -------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **托管**         | 托管在 Replit 自有基础设施上                                                                       | 托管在 Neon (第三方提供商) 上                                                                              |
| **计费**         | 每个 Replit App 免费附带                                                                       | 按使用量计费。详情请参阅 [Publishing and Database Billing](/zh/pt/billing/about-usage-based-billing#databases)。 |
| **恢复能力**       | 使用[回滚功能](/zh/pt/features/data-and-storage/data-recovery)将数据库恢复到任意 checkpoint                | 时间点恢复 (PITR) ——可恢复到备份保留期内的任意时间点。                                                                 |
| **连接安全性**      | 仅可从你的应用访问，绝不公开暴露。                                                                        | 使用完整的连接字符串。一旦泄露，任何人都可以访问并修改你的数据库。                                                                |
| **remix 时的行为** | [Remix](/zh/pt/features/projects-and-artifacts/remix-an-app) 会创建一个包含数据副本的新开发数据库，以实现隔离并保障安全。 | Remix 时所有副本共用同一个数据库，因此在 remix 中的改动可能会影响原始应用。                                                     |
| **数据库创建**      | 为每个 Replit App 自动创建。                                                                     | 需要手动显式配置。                                                                                        |
| **发布流程**       | 发布时会创建独立的生产数据库，实现环境之间的隔离。                                                                | 开发与生产共用同一个数据库，因此开发中的意外改动可能会影响生产环境中的应用。                                                           |

<div id="atualizao-da-infraestrutura-do-banco-de-dados">
  ## 数据库基础设施升级
</div>

Replit 正在将开发数据库从 Neon 升级到 **Helium**，即 Replit 自研并托管的 PostgreSQL 基础设施。升级会自动进行，每个应用在你于 Project Editor 中打开时执行一次，并完整保留你的所有数据。

变更内容：

* **更低延迟、更大存储**：你的数据库与应用一同运行在 Replit 的基础设施上，存储上限从 10 GB 提升至 20 GB。
* **数据库引擎不变**：Helium 使用 PostgreSQL 16，与 Neon 版本相同。你的查询、模式和数据的运作方式保持不变。
* **连接自动更新**：`DATABASE_URL` 会更新为指向 Helium。你此前的 Neon 连接字符串会以 `NEON_DATABASE_URL` 的形式保存在 Secrets 中，供你参考。
* **移除单独的 PG 变量**：`PGHOST`、`PGPORT`、`PGUSER` 和 `PGPASSWORD` 将被移除，请改用 `DATABASE_URL`。

升级期间，你会看到 **&quot;Upgrading your database&quot;** 进度界面。大型数据库可能需要几分钟到几小时；你可以关闭标签页，稍后再回来查看。如果升级过程中出现问题，系统会自动跳过，并在你下次打开应用时重试。完成后会出现确认对话框。

对大多数创作者而言，升级后无需执行任何操作。如果以下情况适用于你的应用，请予以检查：

* **硬编码的 Neon 连接字符串**：如果代码中直接引用了 `neon.tech` 连接字符串，请改为使用 `DATABASE_URL` 环境变量。
* **自定义 PostgreSQL 角色 (roles)&#x20;**：角色和权限会自动迁移，但角色密码无法复制。请在新数据库中重置所有自定义角色的密码。

<div id="erros-de-conexo-ssl-aps-a-atualizao">
  ### 升级后出现 SSL 连接错误
</div>

如果你看到类似 `The server does not support SSL connections` 的错误，说明你的连接代码强制发起了 SSL 握手。Neon 要求使用 SSL，而 Helium 与你的应用一起在本地运行，并不使用 SSL。请将 SSL 配置改为根据环境动态设置：

<CodeGroup>
  ```js JavaScript theme={null}
  // 升级前（升级后会失效）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // 升级后（开发环境和生产环境均可正常работать）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  如果你使用 Drizzle、Prisma 或 Sequelize 等 ORM，请查阅其文档，了解如何按条件配置 SSL 选项。原理相同：开发数据库禁用 SSL，生产环境启用 SSL。
</Tip>

<div id="apps-bifurcados-que-compartilhavam-um-banco-de-dados">
  ### 共享同一数据库的复刻应用
</div>

在旧版 Neon 系统中，复刻应用会复制原应用的 `DATABASE_URL`，因此应用及其已发布版本都会连接到同一个数据库。旧版共享数据库已于 **2026 年 6 月 8 日**停用。如果你已发布的应用无法正常运行或无法访问其数据，请参阅[修复使用共享数据库的已发布应用](/zh/pt/features/data-and-storage/shared-database-migration)或[联系支持团队](https://replit.com/support)。
