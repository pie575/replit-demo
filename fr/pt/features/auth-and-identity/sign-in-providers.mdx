---
title: "Fournisseurs de connexion"
description: "Configurez des identifiants OAuth personnalisés pour la connexion avec Google, GitHub, Apple et X dans les apps qui utilisent Clerk Auth."
---

Lorsque votre app utilise [Clerk Auth](/fr/pt/features/auth-and-identity/clerk-auth), les visiteurs peuvent se connecter via des fournisseurs sociaux. Replit fournit des identifiants partagés prêts à l&#39;emploi ; cette page explique comment utiliser vos **propres** identifiants OAuth pour chaque fournisseur, afin d&#39;afficher le nom et la marque de votre app sur l&#39;écran de connexion.

La procédure est la même pour tous les fournisseurs : créez une app OAuth dans la console du fournisseur, copiez les URL affichées par Replit, puis collez les identifiants obtenus dans le panneau d&#39;édition du fournisseur.

<Note>
  Les identifiants OAuth personnalisés ne sont disponibles que dans l&#39;environnement de **production** : votre app doit donc d&#39;abord être [publiée](/fr/pt/features/publishing/overview). Ouvrez le panneau d&#39;édition de chaque fournisseur dans l&#39;outil **Users &amp; Auth** : onglet **Configure**, section **SSO providers**, sélectionnez l&#39;environnement **Production**, puis sélectionnez **Edit** à côté du fournisseur. Pour la procédure complète, consultez [Configuration des identifiants OAuth pour un fournisseur SSO](/fr/pt/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
</Note>

<div id="google">
  ## Google
</div>

Ce guide vous explique comment créer une application OAuth Google dans la Google Cloud Console. Vous y récupérerez un **Client ID** et un **Client Secret**, et configurerez les origines JavaScript et les URI de redirection requis par Clerk.

Prérequis : un accès à la [Google Cloud Console](https://console.cloud.google.com/).

<div id="etapa-1-crie-um-app-oauth-do-google">
  ### Étape 1 : créez une application OAuth Google
</div>

Accédez à la [Google Cloud Console](https://console.cloud.google.com/) :

<div id="crie-ou-selecione-um-projeto">
  #### Créez ou sélectionnez un projet
</div>

1. Sélectionnez un projet existant ou créez-en un nouveau depuis le menu déroulant des projets
2. Vous êtes redirigé vers le tableau de bord de votre projet

<div id="configure-a-tela-de-consentimento-oauth">
  #### Configurer l&#39;écran de consentement OAuth
</div>

1. Dans la barre latérale gauche, sélectionnez l&#39;icône de menu (≡), puis **APIs &amp; Services**
2. Sélectionnez **OAuth consent screen**
3. Configurez l&#39;écran de consentement de votre app en renseignant les informations requises
4. Enregistrez vos modifications

<div id="crie-credenciais-oauth">
  #### Créez des identifiants OAuth
</div>

1. Dans **APIs &amp; Services**, sélectionnez **Credentials**
2. Sélectionnez **Create Credentials** en haut, puis **OAuth client ID**
3. Choisissez **Web application** comme type d&#39;application
4. Renseignez **Authorized JavaScript origins** et **Authorized redirect URIs** avec les valeurs exactes affichées dans **Provider setup**, sur le **panneau Auth**. Ajoutez toutes les valeurs listées : votre domaine publié comme vos éventuels domaines personnalisés en font partie. Consultez [Configurer des identifiants OAuth pour un fournisseur SSO](/fr/pt/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) pour savoir où les trouver.
5. Sélectionnez **Create**
6. Conservez vos **Client ID** et **Client Secret**

<Warning>
  Gardez votre Client Secret en lieu sûr et ne l&#39;ajoutez jamais au contrôle de version.
</Warning>

<Warning>
  La connexion Google ne fonctionne pas dans les navigateurs intégrés ni dans les webviews au sein des applications. Les utilisateurs doivent utiliser un navigateur web standard.
</Warning>

<div id="soluo-de-problemas">
  ### Dépannage
</div>

<div id="uri-de-redirecionamento-incompatvel-redirect-uri-mismatch">
  #### URI de redirection incompatible (Redirect URI mismatch)
</div>

* Vérifiez que l&#39;URI de redirection défini dans la Google Cloud Console correspond exactement à la valeur affichée dans **Provider setup**, dans le **panneau Auth**
* Assurez-vous qu&#39;il n&#39;y a ni barre oblique finale ni faute de frappe
* Patientez quelques minutes, le temps que la configuration Google se propage

<div id="cliente-invlido-invalid-client">
  #### Client invalide (Invalid client)
</div>

* Vérifiez que le Client ID et le Client Secret ont bien été copiés correctement
* Assurez-vous qu&#39;il n&#39;y a pas d&#39;espaces superflus
* Vérifiez que l&#39;écran de consentement OAuth est bien configuré

<div id="no-funciona-em-domnio-personalizado">
  #### Ne fonctionne pas sur un domaine personnalisé
</div>

* Ajoutez les entrées de domaine personnalisé indiquées dans **Provider setup** du **panneau Auth**, aussi bien dans Authorized JavaScript origins que dans Authorized redirect URIs

<div id="github">
  ## GitHub
</div>

Ce guide vous explique comment créer une application OAuth GitHub dans les Paramètres développeur de GitHub. Vous y récupérerez un **Client ID** et un **Client Secret** à saisir dans le **panneau Auth**.

Prérequis : un [compte GitHub](https://github.com).

<div id="etapa-1-crie-um-app-oauth-do-github">
  ### Étape 1 : Créez une application OAuth GitHub
</div>

1. Accédez aux [Paramètres développeur de GitHub](https://github.com/settings/developers)
2. Sélectionnez **OAuth Apps** dans la barre latérale
3. Sélectionnez **New OAuth App**
4. Renseignez les informations de l&#39;application :

**Application name :**

Saisissez un nom pour votre application.

**Homepage URL** et **Authorization callback URL :**

Renseignez ces deux champs avec les valeurs exactes affichées dans **Provider setup**, dans le **panneau Auth**. Consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/pt/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) pour savoir où les trouver.

5. Sélectionnez **Register application**

<div id="etapa-2-gere-as-credenciais-do-cliente">
  ### Étape 2 : générez les identifiants du client
</div>

1. Votre **Client ID** s&#39;affiche sur la page des paramètres de l&#39;application — copiez-le
2. Sélectionnez **Generate a new client secret**
3. Copiez immédiatement votre **Client Secret**

<Warning>
  Conservez votre Client Secret en lieu sûr. Vous ne pourrez plus le consulter après avoir quitté la page. Si vous le perdez, vous devrez en générer un nouveau.
</Warning>

<div id="soluo-de-problemas-2">
  ### Dépannage
</div>

<div id="uri-de-redirecionamento-incompatvel-redirect-uri-mismatch-2">
  #### URI de redirection incompatible (Redirect URI mismatch)
</div>

* Vérifiez que l&#39;Authorization callback URL correspond exactement à la valeur affichée dans **Provider setup**, dans le **panneau Auth**
* Recherchez d&#39;éventuelles fautes de frappe ou des protocoles incorrects
* Pas de barre oblique finale

<div id="cliente-invlido-invalid-client-2">
  #### Client invalide (Invalid client)
</div>

* Vérifiez que le Client ID et le Client Secret ont bien été copiés correctement
* Assurez-vous qu&#39;aucun espace superflu ne s&#39;est glissé lors du collage

<div id="no-funciona-em-domnio-personalizado-2">
  #### Ne fonctionne pas sur un domaine personnalisé
</div>

* Mettez à jour les champs Homepage URL et Authorization callback URL avec les valeurs du domaine personnalisé affichées sous **Provider setup**, dans le **panneau Auth**

<div id="apple">
  ## Apple
</div>

Ce guide vous explique comment créer l&#39;App ID Apple, le Services ID et la Private Key nécessaires à Sign in with Apple. Vous allez récupérer un **Team ID**, un **Services ID**, un **Key ID** et une **Private Key** à renseigner dans le **panneau Auth**.

Prérequis : un [compte Apple Developer](https://developer.apple.com/account) (l&#39;inscription à l&#39;Apple Developer Program est requise).

<div id="etapa-1-crie-um-apple-app-id">
  ### Étape 1 : Créez un Apple App ID
</div>

1. Accédez au [portail Apple Developer](https://developer.apple.com/account)
2. Rendez-vous dans **Certificates, IDs &amp; Profiles**, puis **Identifiers**
3. Sélectionnez **App IDs** dans le menu déroulant
4. Cliquez sur l&#39;icône **+** pour enregistrer un nouvel identifiant
5. Sélectionnez **App IDs**, puis **Continue**
6. Choisissez **App**, puis **Continue**
7. Renseignez :
   * **Description** : le nom de votre App ID
   * **Bundle ID** : votre identifiant unique
8. Activez **Sign In with Apple** dans Capabilities
9. Sélectionnez **Continue**, puis **Register**
10. **Notez votre App ID Prefix** (affiché en haut de la page) — il s&#39;agit de votre **Team ID**

<div id="etapa-2-crie-um-apple-services-id">
  ### Étape 2 : Créez un Apple Services ID
</div>

1. Sur la page Identifiers, sélectionnez **Services IDs** dans le menu déroulant
2. Sélectionnez **+** pour enregistrer un nouvel identifiant
3. Sélectionnez **Services IDs**, puis **Continue**
4. Renseignez les champs suivants :
   * **Description** : nom de votre Services ID
   * **Identifier** : votre identifiant unique (conservez-le, il s&#39;agit de votre **Services ID**)
5. Sélectionnez **Continue**, puis **Register**

<div id="configure-o-services-id">
  #### Configurer le Services ID
</div>

1. Sélectionnez le Services ID que vous venez de créer
2. Activez **Sign In with Apple**
3. Sélectionnez **Configure**
4. Renseignez les champs suivants :

   * **Primary App ID** : sélectionnez l&#39;App ID créé à l&#39;étape 1
   * **Domains and Subdomains** : copiez la valeur affichée dans **Provider setup**, dans le **panneau Auth** (sans le préfixe de protocole `https://`)
   * **Return URLs** : copiez la valeur affichée dans **Provider setup**, dans le **panneau Auth**

   Consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/pt/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) pour savoir où trouver ces valeurs.
5. Sélectionnez **Next**, puis **Done**, puis **Continue**, puis **Save**

<div id="etapa-3-crie-uma-apple-private-key">
  ### Étape 3 : créez une clé privée Apple
</div>

1. Dans la barre latérale du portail Apple Developer, sélectionnez **Keys**
2. Sélectionnez **+** pour enregistrer une nouvelle clé
3. Saisissez un **Key Name**
4. Activez **Sign In with Apple**
5. Sélectionnez **Configure**, puis choisissez l&#39;App ID créé à l&#39;étape 1
6. Sélectionnez **Save**, puis **Continue**, puis **Register**
7. **Notez le Key ID**
8. **Téléchargez** le fichier de clé privée (.p8)

<Warning>
  Vous ne pouvez télécharger la clé privée qu&#39;une seule fois. Conservez-la en lieu sûr — vous ne pourrez pas la télécharger de nouveau.
</Warning>

<div id="etapa-4-configure-o-apple-private-email-relay">
  ### Étape 4 : configurer Apple Private Email Relay
</div>

La fonctionnalité Hide My Email d&#39;Apple permet aux utilisateurs de se connecter sans révéler leur véritable adresse e-mail. Pour envoyer des e-mails à ces utilisateurs, enregistrez votre source d&#39;e-mail.

1. Dans la barre latérale du portail Apple Developer, sélectionnez **Services**
2. Sous **Sign in with Apple for Email Communication**, sélectionnez **Configure**
3. Sélectionnez **+** pour ajouter une Email Source
4. Saisissez la valeur Email Source affichée sous **Provider setup** dans le **panneau Auth**
5. Sélectionnez **Next**, puis **Register**, puis **Done**
6. Attendez la vérification DNS (icône verte de confirmation)

<Info>
  Dans certaines régions (Chine, Inde), les Apple ID peuvent être associés à un numéro de téléphone plutôt qu&#39;à une adresse e-mail. Si votre app exige une adresse e-mail pour tous les utilisateurs, Sign in with Apple risque d&#39;échouer pour les utilisateurs de ces régions.
</Info>

<div id="soluo-de-problemas-3">
  ### Dépannage
</div>

<div id="cliente-invlido-invalid-client-3">
  #### Client invalide (Invalid client)
</div>

* Vérifiez que tous les identifiants ont été saisis correctement
* Assurez-vous que la Private Key contient bien les lignes BEGIN et END
* Vérifiez que votre Services ID est correctement configuré

<div id="uri-de-redirecionamento-invlida-invalid-redirect-uri">
  #### URI de redirection non valide (Invalid redirect URI)
</div>

* Vérifiez que la Return URL définie dans la configuration de l&#39;Apple Services ID correspond exactement à la valeur affichée dans **Provider setup**, dans le **panneau Auth**
* Vérifiez que le domaine renseigné dans Domains and Subdomains correspond à votre domaine publié (sans `https://`)

<div id="email-relay-no-funciona">
  #### Le relais e-mail ne fonctionne pas
</div>

* Vérifiez que l&#39;Email Source affiche une coche verte de confirmation dans le portail Apple Developer
* Attendez la propagation DNS si l&#39;entrée a été ajoutée récemment

<div id="no-funciona-em-domnio-personalizado-3">
  #### Ne fonctionne pas sur un domaine personnalisé
</div>

* Ajoutez les entrées de domaine personnalisé indiquées dans **Provider setup** du **panneau Auth**, à la fois dans Domains and Subdomains (sans `https://`) et dans Return URLs

<div id="x-twitter">
  ## X (Twitter)
</div>

Ce guide vous explique comment créer une application OAuth X dans le X Developer Portal. Vous y récupérerez un **Client ID** et un **Client Secret** à saisir dans le **panneau Auth**.

Prérequis : un [compte développeur X](https://developer.twitter.com/) (offre gratuite disponible).

<div id="etapa-1-configure-o-app-de-desenvolvedor-do-x">
  ### Étape 1 : configurez l&#39;application développeur X
</div>

<div id="crie-uma-conta-de-desenvolvedor-se-necessrio">
  #### Créez un compte développeur (si nécessaire)
</div>

1. Rendez-vous sur le [X Developer Portal](https://developer.twitter.com/en/portal/dashboard)
2. Demandez un compte développeur si vous n&#39;en avez pas encore
3. Finalisez l&#39;inscription en décrivant votre cas d&#39;usage

<div id="crie-ou-selecione-um-app">
  #### Créez ou sélectionnez une app
</div>

1. Dans le X Developer Portal, rendez-vous dans **Projects &amp; Apps**
2. Utilisez une app existante ou sélectionnez **Add App**
3. Saisissez un nom pour l&#39;app, puis sélectionnez **Next**
4. Sélectionnez **App settings**

<div id="etapa-2-configure-a-autenticao">
  ### Étape 2 : configurez l&#39;authentification
</div>

1. Faites défiler jusqu&#39;à **User authentication settings**
2. Sélectionnez **Set up**

**App permissions :**

Sélectionnez le niveau d&#39;autorisation minimal :

* **Read** – Nécessaire pour le profil de l&#39;utilisateur (minimum)
* **Write** – Pour publier au nom des utilisateurs (facultatif)
* **Direct Messages** – Pour accéder aux messages privés (facultatif)

<Warning>
  Les autorisations doivent correspondre aux scopes demandés. Si votre app demande `tweet.write` alors que vous n&#39;avez activé que Read, l&#39;authentification échouera.
</Warning>

**Type of app :**

Sélectionnez **Web App, Automated App or Bot**

**App info :**

* **Callback URI / Redirect URL** : copiez la valeur affichée sous **Provider setup** dans le **panneau Auth**
* **Website URL** : copiez la valeur affichée sous **Provider setup** dans le **panneau Auth**

Consultez [Configurer des identifiants OAuth pour un fournisseur SSO](/fr/pt/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) pour savoir où trouver ces valeurs.

3. Sélectionnez **Save**
4. **Enregistrez votre Client ID et votre Client Secret**

<Warning>
  Conservez votre Client Secret en lieu sûr. Si vous le perdez, en générer un nouveau invalidera l&#39;ancien.
</Warning>

<div id="soluo-de-problemas-4">
  ### Dépannage
</div>

<div id="uri-de-redirecionamento-incompatvel-redirect-uri-mismatch-3">
  #### URI de redirection incompatible (Redirect URI mismatch)
</div>

* Vérifiez que le Callback URI correspond exactement à la valeur affichée sous **Provider setup** dans le **panneau Auth**
* Recherchez d&#39;éventuelles fautes de frappe ou protocoles incorrects
* Pas de barre oblique finale

<div id="cliente-invlido-invalid-client-4">
  #### Client invalide (Invalid client)
</div>

* Vérifiez à nouveau le Client ID et le Client Secret
* Assurez-vous qu&#39;il n&#39;y a pas d&#39;espaces superflus
* Vérifiez que vous utilisez bien des identifiants OAuth 2.0 (et non OAuth 1.0a)

<div id="erros-de-scopepermisso">
  #### Erreurs de scope/autorisation
</div>

* Vérifiez que les scopes correspondent aux autorisations activées dans le X Developer Portal
* Assurez-vous qu&#39;au minimum l&#39;autorisation Read est activée

<div id="app-em-modo-de-desenvolvimento">
  #### Application en mode développement
</div>

* Les applications X démarrent en mode développement, avec un nombre d&#39;utilisateurs limité
* Vous devrez peut-être demander un accès élevé pour une utilisation en production

<div id="no-funciona-em-domnio-personalizado-4">
  #### Ne fonctionne pas sur un domaine personnalisé
</div>

* Mettez à jour la Website URL et le Callback URI avec les valeurs du domaine personnalisé indiquées sous **Provider setup**, dans le **panneau Auth**
