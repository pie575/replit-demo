Les déploiements Reserved VM s&#39;exécutent sur des machines virtuelles (VM) qui fournissent des ressources de calcul dédiées à votre application. Ce type de déploiement offre des coûts et des performances prévisibles, sans interruption.

Ils conviennent aux cas d&#39;utilisation suivants :

* Tâches d&#39;arrière-plan gourmandes en mémoire
* Bots de chat devant rester connectés en permanence
* Serveurs API toujours actifs

<div id="section">
  ## Fonctionnalités
</div>

Les déploiements Reserved VM offrent les fonctionnalités suivantes.

* **Ressources dédiées** : bénéficiez de performances constantes pour votre application grâce à des ressources de calcul réservées.
* **Domaines personnalisés** : configurez un domaine personnalisé ou accédez à votre application via l’URL `<app-name>.replit.app`.
* **Options de ressources de calcul** : choisissez l’option de VM adaptée aux besoins de performances de votre application.
* **Mappage de ports configurable** : définissez les ports que votre application expose sur Internet.
* **Surveillance** : consultez les journaux et surveillez l’état de votre application publiée.

<div id="section-2">
  ## Utilisation
</div>

Vous pouvez accéder au déploiement Reserved VM depuis l’outil Publier de l’éditeur de projet.

<Accordion title="Accéder au déploiement Reserved VM">
  Dans le **dock d’outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="icône Tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **Tous les outils** pour afficher la liste des outils de l’éditeur de projet.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="icône Publier" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publier**.
  3. Sélectionnez l’option **Reserved VM**, puis **Configurer une application publiée**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut pour ouvrir l’outil de recherche.
  2. Saisissez « Publier » pour trouver l’outil, puis sélectionnez-le dans les résultats de recherche.
  3. Sélectionnez l’option **Reserved VM**, puis **Configurer une application publiée**.
</Accordion>

<div id="section-3">
  ### Configuration de la machine
</div>

Choisissez la configuration CPU et RAM de la machine qui hébergera le déploiement. Le coût de chaque option est affiché à côté de la taille de machine sélectionnée.

<div id="section-4">
  ### Domaine par défaut
</div>

Indiquez le sous-domaine de votre application publiée. Une fois votre application publiée, vous pourrez y accéder à l’adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Custom Domains](/fr/features/publishing/custom-domains).

<div id="private">
  ### Déploiement privé
</div>

<Info>
  La fonctionnalité d’application publiée privée est disponible dans les plans Pro et Enterprise.
</Info>

Les applications publiées privées permettent de limiter l’accès à votre application aux membres de votre workspace ou aux utilisateurs et groupes spécifiques que vous invitez.
Lors de la publication, vous pouvez choisir entre les accès **Public**, **Protégé par mot de passe**, **Workspace uniquement** et **Sur invitation uniquement**.

Pour savoir comment configurer un déploiement privé, consultez [Accès à l’application](/fr/features/publishing/private-deployments/).

<div id="section-5">
  ### Commande de build
</div>

Dans le champ **Commande de build**, saisissez une commande Shell pour compiler ou configurer l’application avant d’exécuter la commande de lancement.
Par exemple, pour optimiser une application JavaScript pour la production avec Vite, vous pouvez ajouter la commande `vite build`.

<div id="section-6">
  ### Commande d’exécution
</div>

Dans le champ **Commande d’exécution**, saisissez la commande Shell qui lance votre application. Cette commande doit être similaire à celle
utilisée dans votre workflow. Par exemple, pour démarrer une application Flask nommée « myApp », vous pouvez ajouter la commande `flask --app myApp run`.

<div id="section-7">
  ### Secrets des applications publiées
</div>

Pour ajouter les variables d&#39;environnement ou les secrets nécessaires au bon fonctionnement de votre application, sélectionnez **Ajouter un secret à l&#39;application publiée**.

Si votre application Replit comporte des variables d&#39;environnement ou des secrets, l&#39;outil Publier les ajoute automatiquement à la liste.

<div id="section-8">
  ### Options de type d’application
</div>

Sélectionnez l’une des options suivantes.

* **Serveur web** : sélectionnez cette option si vous publiez une application web ou une application accessible aux utilisateurs sur Internet.
* **Worker en arrière-plan** : sélectionnez cette option si votre application n’écoute aucun port et ne démarre pas de serveur.

En sélectionnant **Serveur web**, vous pouvez personnaliser le port à exposer en procédant comme suit :

1. Développez la section **Configuration des ports**.
2. Sélectionnez **Configurer via le panneau Réseau** pour ouvrir l’onglet **Réseau** et gérer les mappages de ports.

Pour en savoir plus sur la configuration des ports, consultez [Ports](/fr/ko/features/project-setup/ports/).
