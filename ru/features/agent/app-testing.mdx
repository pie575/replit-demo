App Testing позволяет Agent проверять созданные им приложения в настоящем браузере. Agent перемещается по приложению так же, как это делал бы реальный пользователь: нажимает на элементы и проверяет работу функций. Такая самопроверка помогает убедиться, что приложение работает корректно, и позволяет Agent автоматически находить и устранять проблемы.

Когда App Testing включён, Agent периодически проводит самопроверку — когда считает, что изменений накопилось достаточно. Agent тестирует не после каждого сообщения пользователя, а сам определяет, когда тестирование принесёт наибольшую пользу.

<Note>
  На данный момент App Testing доступен для веб-приложений на Full Stack JavaScript и Streamlit Python.
</Note>

<div id="key-benefits">
  ### Ключевые преимущества
</div>

* **Расширенная автономность**: Agent работает дольше без вмешательства человека
* **Более высокое качество**: приложения содержат меньше ошибок благодаря раннему выявлению и устранению проблем
* **Экономия средств**: проблемы обнаруживаются ещё на этапе разработки, поэтому дополнительные сеансы отладки не нужны
* **Интерактивный разбор**: видеозаписи и навигация по разделам для детального анализа результатов

<div id="the-testing-process">
  ### Как проходит тестирование
</div>

Когда Agent решает проверить свою работу, происходит следующее:

1. **Предпросмотр в браузере**: в панели Agent открывается окно предпросмотра браузера
2. **Визуальное тестирование**: вы видите, как курсор Agent кликает по элементам приложения и проверяет их работу
3. **Имитация реального пользователя**: Agent перемещается по приложению так же, как это делал бы настоящий пользователь, при необходимости вводя тестовые данные
4. **Автоматический анализ**: Agent анализирует результаты тестов и выявляет проблемы
5. **Самокоррекция**: Agent присылает сводку по проведённым тестам и автоматически устраняет обнаруженные проблемы

<div id="key-capabilities">
  ## Ключевые возможности
</div>

Agent грамотно тестирует ваше приложение, перемещаясь по нему так же, как это делал бы реальный пользователь, и охватывает:

* **Проверку пользовательского интерфейса**: кнопки, формы, навигацию и визуальные элементы
* **Проверку функциональности**: основные возможности и пользовательские сценарии
* **Тестирование интеграций**: вызовы API, взаимодействие с базой данных и сторонние сервисы
* **Производительность и доступность**: время загрузки, отзывчивость и соответствие стандартам доступности

<div id="usage">
  ## Использование
</div>

App Testing находится в разделе **Advanced settings** выпадающего меню настроек Agent в поле ввода Chat. Включайте эту функцию при работе в режиме Economy или Power. В режиме Lite функция App Testing отключена.

<Note>
  App Testing — часть автономных возможностей Agent наряду со встроенной проверкой кода. Подробнее о других [возможностях Agent](/ru/features/agent/overview).
</Note>

<div id="take-over">
  ## Передача управления
</div>

Иногда во время тестирования Agent сталкивается с препятствием, которое он не может преодолеть без вашей помощи. Чаще всего речь идёт о входе в учётную запись пользователя (например, Gmail). В таких случаях Agent покажет кнопку «Begin take over» («Начать передачу управления»).

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="Интерфейс передачи управления в App Testing с кнопками «Пропустить» и «Начать передачу управления» и инструкциями по обработке ошибок и CAPTCHA" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

Нажав «Начать передачу управления», вы сможете перейти в окно тестового предпросмотра, выполнить необходимые действия и затем вернуть управление Agent. Можно также нажать «Пропустить» и отказаться от передачи управления — тогда тестирование App Testing завершится, если Agent не сможет продолжить без вашей помощи. Если вы не отреагируете в течение 10 минут, Agent продолжит так, как если бы вы нажали «Пропустить».

<div id="what-to-expect">
  ### Чего ожидать
</div>

* **Возможность пропустить**: при необходимости нажмите кнопку пропуска, чтобы не проводить тестирование и продолжить разработку
* **Интерактивный повтор видео**: после тестирования нажмите на видео, чтобы воспроизвести весь сеанс тестирования
* **Навигация по разделам**: используйте ползунки внизу, чтобы перейти к нужному разделу теста

<div id="troubleshooting">
  ## Устранение неполадок
</div>

**Тесты неожиданно завершаются с ошибкой**

* Попробуйте пропустить шаг, а затем снова отправить prompt для тестирования
* Проверьте, нет ли динамического содержимого, которое может влиять на время выполнения теста
* Убедитесь в корректности тестовых сценариев

**Недостаточное покрытие тестами**

* Опишите функциональность вашего App подробнее
* Прямо укажите ключевые пользовательские сценарии, которые необходимо протестировать

**App Testing вообще не работает?**

* На данный момент App Testing работает только с веб-приложениями[*](#how-app-testing-works)

<div id="pricing-and-usage">
  ## Стоимость и использование
</div>

App Testing входит в модель тарификации Agent на основе затраченных усилий, и здесь важно учитывать несколько моментов:

* **Оплата по факту использования**: тестирование оплачивается исходя из затраченных усилий (более простые тесты обходятся дешевле)
* **Затраты и выгода**: тестирование стоит денег, но помогает сэкономить за счёт раннего выявления ошибок — не придётся отправлять дополнительные prompt и заново нагружать Agent работой
* **Эффективная разработка**: автоматизированный подход снижает потребность в ручной отладке и переделках

<Tip>
  **Выгодное тестирование**: хотя App Testing увеличивает расходы на использование, в целом оно чаще позволяет сэкономить, поскольку избавляет от дополнительных сессий Agent для исправления проблем, которые можно было выявить ещё на этапе тестирования.
</Tip>
