title: "开发和生产数据库"
description: "了解应用的两类数据库：用于构建的开发数据库，以及为已发布应用提供支持的生产数据库。"

每个 Replit App 都使用两个数据库。**开发数据库**供你和 Agent 在构建过程中进行试验。**生产数据库**存储为已发布应用提供支持的真实数据，即使你继续构建，也能确保这些数据安全无虞。

<div id="section">
  ## 两类数据库对比
</div>

| 方面        | 开发数据库                | 生产数据库             |
| --------- | -------------------- | ----------------- |
| **用途**    | 用于实验和功能开发            | 服务真实用户并存储业务数据     |
| **数据**    | 测试数据、虚拟记录和小型数据集      | 真实用户数据和对业务至关重要的信息 |
| **创建时机**  | 在所有 Replit App 中自动创建 | 发布 App 时          |
| **Agent** | Agent 可以创建和修改表       | Agent 无法访问        |
| **变更**    | 频繁变更架构并快速迭代          | 在发布时应用的审慎且经过规划的变更 |
| **计费**    | 所有 Replit App 均免费提供  | 按使用量计费            |

<Note>
  Agent 无法修改生产数据库。这项限制旨在确保生产数据库的安全。

  Agent 可以修改开发数据库。发布时，Agent 对开发数据库结构所做的所有变更 (添加或删除列/表) 也会应用到生产数据库。

  您可以随时打开 **数据库** 工具，选择生产数据库，然后打开 **My Data**，并切换 **Edit** 以手动编辑生产数据。
</Note>

<div id="section-2">
  ## 发布时创建生产数据库
</div>

已发布的应用会拥有独立的生产数据库，与构建时使用的开发数据库分开。

* **当前基础设施 (Helium)**：如有需要，Replit 会在发布过程中自动创建生产数据库，无需额外配置。
* **旧版 Neon 开发数据库**：请在发布设置中手动创建生产数据库。发布过程中，打开 **Production database settings** 并启用 **Create production database**。如需一并复制开发数据，请同时启用 **Set up your production database with your current development data**。

<Frame caption="Publishing 的生产数据库设置">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="显示 Create production database 选项的发布设置" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  仅当开发数据可安全用于线上应用时，才将其复制到生产环境。开发数据可能包含测试账户、示例记录或未完成的内容。
</Warning>

发布完成后，已发布的应用会使用生产数据库，而 Project Editor 会继续使用开发数据库，因此后续的开发更改不会直接修改线上数据。

<div id="section-3">
  ## 连接池
</div>

默认情况下，生产数据库未启用连接池。应用会使用 `DATABASE_URL` 连接字符串直接连接到数据库，因此大多数框架需要自行管理客户端连接池。

<Note>
  每个 Neon 项目都包含直连字符串和池化连接字符串。直连字符串的格式如下：`postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`。

  如需使用池化连接，请在主机名中添加 `-pooler`：`postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`。
</Note>

如果生产连接字符串已泄露，请[重新生成生产数据库凭据](/zh/ko/features/data-and-storage/connection-details#regenerate-production-database-credentials)。

<div id="section-4">
  ## 安全地更改生产数据库
</div>

发布包含数据库变更的更新时，某些变更需要谨慎规划，以避免停机或数据丢失。

<Info>
  发布期间，已发布的应用可能会短暂停机。为避免冲突并在应用数据库变更时保护数据，有时需要暂时停止应用。
</Info>

以下类型的变更通常需要特别注意：

* 删除应用程序代码仍在引用的**数据库列**
* 以现有代码无法处理的方式**更改列数据类型**
* 在现有表中添加没有默认值的**必填字段**
* **更改表名或列名**，导致现有查询失效
* **修改约束条件**，可能导致现有应用程序逻辑不再适用

<div id="section-5">
  ### 使用部署预览测试更改
</div>

部署预览是生产环境的临时隔离副本，让您可以在影响实际用户之前测试数据库更改和应用更新。您可以用它来：

* 验证应用在应用数据库更改后，是否仍能在关键用户流程中正常运行
* 确认现有数据已正确迁移，新字段中包含预期值
* 确认查询响应时间没有变慢

<div id="section-6">
  ## 账单和资源使用量
</div>

生产数据库通过无服务器数据库提供商 Neon 按使用量计费。数据库在 5 分钟内没有活动时会进入空闲状态，暂停计算时间计费；收到查询后会立即重新激活。

数据库 工具的首页会显示 **Billing Period** 和 **Hours of Compute Used**。要查看各数据库的存储空间使用量，请打开相应数据库的 **设置** 标签页。要查看所有 Replit App 的使用量，请依次打开 **设置** → **Account** → **Account usage**，然后展开 **PostgreSQL Storage** 和 **PostgreSQL Compute** 行。

要了解 Replit 如何针对数据库使用量收费，请参阅[部署和数据库费用](/zh/ko/billing/about-usage-based-billing#databases)。

<div id="section-7">
  ## 删除生产数据库
</div>

<Warning>
  删除操作在 7 天保留期结束后将无法撤销。继续前，请务必备份重要数据。数据库有 7 天的软删除期，在此期间可以恢复。如需帮助，请联系支持团队。7 天后，数据库将被永久删除，无法恢复。
</Warning>

<Accordion title="如何删除数据库">
  在 **数据库** 工具中：

  1. 选择数据库，然后打开 **设置** 选项卡
  2. 选择 **Remove database**，然后选择 **Yes, Remove database** 确认
</Accordion>

<div id="section-8">
  ## 旧版开发数据库
</div>

在 2025 年 12 月 4 日之前，开发数据库由 <a href="https://neon.com/" target="_blank">Neon</a> 托管。所有新的开发数据库均托管在 Replit 自有基础设施 (Helium) 上。你可以在 **设置** 标签页中查看应用使用的是哪一种。`DATABASE_URL` 中包含 `neon.tech` 表示使用旧版 Neon；包含 `helium` 则表示使用当前基础设施。

| **功能**       | **Replit (当前)&#x20;**&#x20;                                                             | **Neon (旧版)&#x20;**&#x20;                                                     |
| ------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **托管**       | 托管在 Replit 自有基础设施上                                                                 | 托管在 Neon (第三方服务商) 上                                                      |
| **计费**       | 所有 Replit App 均免费提供                                                                | 按使用量计费。详情请参阅[发布和数据库计费](/zh/ko/billing/about-usage-based-billing#databases)。 |
| **恢复功能**     | 使用[回滚功能](/zh/ko/features/data-and-storage/data-recovery)将数据库恢复到任意检查点                  | 时间点恢复 (PITR) ：可在备份保留期内恢复到任意时间点。                                          |
| **连接安全性**    | 仅可在应用内部访问，绝不会暴露到外部。                                                                | 使用完整连接字符串。一旦泄露，任何人都能访问和修改数据库。                                            |
| **Remix 行为** | [Remix](/zh/ko/features/projects-and-artifacts/remix-an-app)会创建一个复制数据的新开发数据库，以确保隔离和安全 | Remix 会在所有副本中复用同一数据库，因此在 Remix 中的更改可能会影响原始应用。                            |
| **数据库创建**    | 每个 Replit App 都会自动创建。                                                              | 需要显式配置。                                                                  |
| **发布工作流**    | 发布时会创建独立的生产数据库，以隔离不同环境。                                                            | 开发和生产环境共享同一数据库，因此意外的开发更改可能会影响生产应用。                                       |

<div id="section-9">
  ## 数据库基础设施升级
</div>

Replit 正在将开发数据库从 Neon 升级到 Replit 自建的托管 PostgreSQL 基础设施 **Helium**。升级会自动进行：当您在 Project Editor 中打开应用时，每个应用会执行一次，并保留所有数据。

以下内容将发生变化：

* **更低的延迟和更多存储空间**：数据库将与应用一同在 Replit 基础设施上运行，存储容量上限将从 10GB 增至 20GB。
* **相同的数据库引擎**：Helium 使用与 Neon 相同版本的 PostgreSQL 16。查询、模式和数据的行为保持不变。
* **连接将自动更新**：`DATABASE_URL` 将更新为指向 Helium。原有的 Neon 连接字符串将以 `NEON_DATABASE_URL` 的名称保存在 Secrets 中，供您参考。
* **移除单独的 PG 变量**：`PGHOST`、`PGPORT`、`PGUSER`、`PGPASSWORD` 将被移除。请改用 `DATABASE_URL`。

升级期间，您将看到 **&quot;Upgrading your database&quot;** 进度页面。大型数据库可能需要几分钟到数小时；您可以关闭标签页，稍后再回来。如果升级过程中出现问题，系统会自动跳过，并在您下次打开应用时重试。完成后将显示确认对话框。

大多数构建者无需采取任何额外操作。如果您符合以下任一情况，请进行检查。

* **硬编码的 Neon 连接字符串**：请更新引用 `neon.tech` 连接字符串的代码，改为使用 `DATABASE_URL` 环境变量。
* **自定义 PostgreSQL 角色**：角色和权限会自动迁移，但无法复制密码。请在新数据库中重置自定义角色的密码。

<div id="ssl">
  ### 升级后出现 SSL 连接错误
</div>

如果看到类似 `The server does not support SSL connections` 的错误，说明连接代码正在强制执行 SSL 握手。Neon 需要 SSL，而 Helium 会随应用在本地运行，不使用 SSL。请根据环境有条件地配置 SSL。

<CodeGroup>
  ```js JavaScript theme={null}
  // 升级前（升级后会失效）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // 升级后（在开发环境与生产环境中均可正常运行）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  如果使用 Drizzle、Prisma、Sequelize 等 ORM，请查阅相应文档，了解如何有条件地配置 SSL。同样的原则适用：在开发数据库中禁用 SSL，在生产环境中启用 SSL。
</Tip>

<div id="section-10">
  ### 共享数据库的分叉应用
</div>

在旧版 Neon 系统中，分叉应用会复制原应用的 `DATABASE_URL`，因此两个应用及其已发布版本都会连接到同一个数据库。共享的旧版数据库已于 **2026 年 6 月 8 日**停用。如果已发布的应用停止运行或无法访问数据，请参阅[修复使用共享数据库的已发布应用](/zh/ko/features/data-and-storage/shared-database-migration)或[联系支持团队](https://replit.com/support)。
