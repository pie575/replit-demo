导入功能可让你将现有代码或设计引入 Replit Apps，并继续使用 Agent 进行构建。

<div id="fontes-suportadas">
  ## 支持的来源
</div>

| 来源             | 你需要提供的内容                         | 适用场景                    |
| -------------- | -------------------------------- | ----------------------- |
| GitHub         | 仓库 URL 或仓库选择器                    | 导入公开和私有仓库               |
| Bitbucket      | 仓库 URL 或仓库选择器                    | 导入托管在 Bitbucket 上的仓库    |
| Vercel         | Vercel 项目所对应的 GitHub 仓库          | 迁移 Vercel 应用            |
| Figma          | frame URL                        | 将设计转化为 React 应用         |
| Claude         | 从 Claude 发送的设计                   | 将 Claude 设计转化为交互式应用     |
| Bolt           | 从 Bolt 导出的 GitHub 仓库             | 迁移 Bolt 项目              |
| Lovable        | 从 Lovable 导出的 GitHub 仓库          | 迁移 Lovable 项目           |
| Base44         | 从 Base44 导出的 GitHub 仓库           | 迁移 Base44 项目            |
| ZIP            | 上传 `.zip` 文件                     | 导入本地项目文件                |
| 电子表格           | `.xlsx`、`.csv` 文件或 Google 表格 URL | 基于表格数据构建应用              |
| 此前的 Agent 导出内容 | 从此前的 Agent 应用导出的 GitHub 仓库       | 重新导入此前的 Agent 应用        |
| 空白             | 无需任何内容                           | 希望获得不含 Agent 的空白项目的高级用户 |

<Note>Replit 会在导入开始前验证兼容性。</Note>

关于 Figma 设计，请参阅[将 Figma 设计导入 Replit Design](/zh/pt/design/import-figma-designs-into-replit-design)。

关于从 Claude 发送的设计，请参阅[将 Claude 设计导入 Replit Design](/zh/pt/design/import-claude-designs-into-replit-design)。

    ⏰ *预计用时：四分钟*

    先将 Lovable 项目导出到 GitHub，再导入该仓库，即可把项目迁移到 Replit。

    **开始之前**

    * 一个可供导出的 Lovable 项目
    * 一个已连接到 Lovable 的 GitHub 账户
    * 一个 Replit 账户

    **步骤**

    1. 将你的 Lovable 项目导出到 GitHub。
    2. 打开 [replit.com/import](https://replit.com/import)。
    3. 选择 **Lovable**。
    4. 连接你的 GitHub 账户。
    5. 选择导出的 Lovable 仓库。
    6. 选择**导入**。

    * **数据库架构**：表结构 (如有)

  <Tab title="GitHub">
    ⏰ *预计用时：两分钟*

    将 GitHub 仓库导入 Replit，更快地运行、测试并发布。

    **开始之前**

    * 一个 GitHub 仓库 URL
    * 仓库访问权限 (公开或私有)
    * 一个 Replit 账户

    **方式一：快速导入**

    快速导入适用于公开仓库。

    1. 复制 `github.com/` 之后的仓库路径。
    2. 打开 `https://replit.com/github.com/<owner>/<repo>`。
    3. 按 Enter 键开始导入。

    *示例*

    * GitHub URL：`https://github.com/exampleUser/my-app`
    * Replit 导入 URL：`https://replit.com/github.com/exampleUser/my-app`

    **方式二：引导式导入**

    引导式导入同时支持公开和私有仓库。

    1. 打开 [replit.com/import](https://replit.com/import)。
    2. 选择 **GitHub**。
    3. 连接你的 GitHub 账户。
    4. 选择一个仓库。
    5. 选择**导入**。

    **会导入哪些内容**

    * 仓库中的文件和文件夹
    * 依赖文件
    * 常见的运行和构建配置

    **不会导入哪些内容**

    * 已有的密钥和环境变量的值
    * 默认无法在 Replit 上运行的平台专属服务

    **排查 GitHub 连接问题**

    如果你看到 `Failed to get repository, please re-authenticate with GitHub`，或者仓库下拉菜单显示 `No repositories found`，这是因为 GitHub 导入流程所用的连接与**账户 → 已连接服务**页面中的连接是彼此独立的。仅在“已连接服务”中重新连接并不能解决导入流程的问题。

    <Steps>
      <Step title="在 Git 提供方中重新连接 GitHub">
        打开 Replit 账户设置中的 **Git 提供方**部分，断开 GitHub 连接后在同一界面重新连接。完成后，你的个人仓库应会出现在导入下拉菜单中。
      </Step>

      <Step title="为你的 GitHub 组织授权 Replit 应用">
        如果该仓库属于某个 GitHub 组织，请打开 [https://github.com/settings/applications](https://github.com/settings/applications)，找到 Replit 的 OAuth 应用，并在第三方应用访问设置中授予组织访问权限。如果你不是组织所有者，这一步可能需要由组织管理员完成。
      </Step>

      <Step title="重新尝试导入">
        打开 [replit.com/import](https://replit.com/import)，通过仓库下拉菜单或粘贴仓库 URL 再次尝试导入。
      </Step>
    </Steps>

    ⏰ *预计用时：三分钟*

    2. 选择 **ZIP**。

    4. 添加系统提示需要的密钥和环境变量。
    5. 选择 **导入**。

    **会导入的内容**

    * 项目文件和目录结构
    * 依赖文件
    * 适用于 Replit 的运行和构建默认设置

    **不会导入的内容**

    * 现有的环境变量值
    * 自定义域名
    * 需要手动配置的平台专属服务
    * 现有的数据库数据
    * 现有的第三方连接器配置

  ## 其他来源
</div>

<div id="bitbucket">
  ### Bitbucket
</div>

* 粘贴 Bitbucket 仓库 URL，或连接你的 Bitbucket 账号来搜索你的仓库。
* 与托管在 GitHub 上的项目相比，导入时 Agent 提供的支持可能较为有限。

<div id="planilha">
  ### 电子表格
</div>

* 上传 Excel 文件 (`.xlsx`) 或 CSV 文件，或粘贴 Google Sheets 的公开 URL。
* Agent 会读取电子表格的结构，构建一个 full-stack 应用，并将你的数据填充到数据库中。
* 应用自带界面，可用于查看、搜索和管理记录。

<div id="exportao-anterior-do-agent">
  ### 此前导出的 Agent 应用
</div>

* 从 GitHub 仓库重新导入此前导出的 Agent 应用。
* Replit 会保留 Agent 特有的结构 (代码、数据库架构、backend 功能) 。
* 数据库中的数据和密钥的值不会被导入。

<div id="vazio">
  ### 空白
</div>

* 从完全空白的项目开始——不使用 Agent，无需选择框架，也不生成任何脚手架代码。
* 适合希望完全掌控项目配置的高级用户。

<div id="limitaes">
  ## 限制
</div>

* 现有数据库中的数据不会被迁移。
* ZIP 上传大小上限为 200 MB。
* 某些复杂或专有的依赖项可能需要手动配置。
* 大型项目的处理时间可能较长。

<div id="boas-prticas">
  ## 最佳实践
</div>

* 导入前请移除敏感凭证。
* 保持源项目结构整洁。
* 导入后检查依赖项和运行命令。
* 发布前测试核心流程。

<div id="soluo-de-problemas">
  ## 故障排查
</div>

如果导入失败，请先从以下几个方面排查：

* **兼容性错误**：检查项目所需的文件以及受支持的框架。
* **访问错误**：确认仓库或来源的权限。
* **处理错误**：简化项目结构或缩减项目大小后重试。

如果问题仍未解决，请访问 [Replit Community Hub](https://replit.com/community) 或[联系支持团队](https://replit.com/support)。
