title: "Bases de données de développement et de production"
description: "Découvrez les deux bases de données de votre app : la base de données de développement utilisée lors de la création et la base de données de production qui alimente votre app publiée."
---

Chaque application Replit utilise deux bases de données. La **base de données de développement** est l’espace où vous et Agent expérimentez pendant la création de votre app. La **base de données de production** stocke les données réelles qui alimentent votre app publiée et les protège pendant que vous continuez à créer.

<div id="section">
  ## Comparaison des deux bases de données
</div>

| Aspect            | Base de données de développement                                 | Base de données de production                                                  |
| ----------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Objectif**      | Expérimentation et développement de fonctionnalités              | Gestion des utilisateurs réels et stockage des données métier                  |
| **Données**       | Données de test, enregistrements fictifs, petits jeux de données | Données d&#39;utilisateurs réels, informations essentielles à l&#39;entreprise |
| **Création**      | Créée automatiquement pour chaque application Replit             | Lors de la publication de l&#39;app                                            |
| **Agent**         | Agent peut créer et modifier des tables                          | Agent ne peut pas y accéder                                                    |
| **Modifications** | Modifications fréquentes du schéma, itérations rapides           | Modifications prudentes et planifiées appliquées lors de la publication        |
| **Facturation**   | Incluse gratuitement avec toutes les applications Replit         | Basée sur l&#39;utilisation                                                    |

<Note>
  Agent ne peut pas modifier la base de données de production. Cette restriction permet de préserver la sécurité de la base de données de production.

  Agent peut modifier la base de données de développement. Lors de la publication, toutes les modifications structurelles (ajout ou suppression de colonnes et de tables) apportées par Agent à la base de données de développement sont également appliquées à la base de données de production.

  Vous pouvez modifier manuellement les données de production à tout moment en ouvrant l&#39;outil **Database**, en sélectionnant la base de données de production, puis en ouvrant **My Data** et en activant **Edit**.
</Note>

<div id="section-2">
  ## Créer une base de données de production lors de la publication
</div>

Les applications publiées disposent de leur propre base de données de production, distincte de la base de données de développement utilisée lors de la création de l’application.

* **Infrastructure actuelle (Helium)** : Replit crée automatiquement une base de données de production si nécessaire lors de la publication. Aucune configuration supplémentaire n’est requise.
* **Ancienne base de données de développement Neon** : créez vous-même une base de données de production dans les paramètres de publication. Lors de la publication, ouvrez **Production database settings** et activez **Create production database**. Pour copier également les données de développement, activez **Set up your production database with your current development data**.

<Frame caption="Paramètres de la base de données de production dans Publishing">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="Paramètres de publication affichant l’option Create production database" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  Copiez les données de développement en production uniquement si elles peuvent être utilisées en toute sécurité dans l’application en ligne. Les données de développement peuvent inclure des comptes de test, des enregistrements d’exemple ou du contenu inachevé.
</Warning>

Une fois la publication terminée, l’application publiée utilise la base de données de production, tandis que Project Editor continue d’utiliser la base de données de développement. Les modifications apportées ultérieurement au développement ne modifient donc pas directement les données réelles.

<div id="section-3">
  ## Pool de connexions
</div>

Par défaut, le pool de connexions n’est pas activé pour les bases de données de production. Les applications se connectent directement à la base de données à l’aide de la chaîne de connexion `DATABASE_URL`. La plupart des frameworks doivent donc gérer leur propre pool de connexions côté client.

<Note>
  Chaque projet Neon inclut une chaîne de connexion directe et une chaîne de connexion avec pool. La chaîne de connexion directe se présente sous une forme telle que `postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`.

  Pour utiliser une connexion avec pool, ajoutez `-pooler` au nom d’hôte : `postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`.
</Note>

Si votre chaîne de connexion de production a été exposée, [régénérez les identifiants de votre base de données de production](/fr/ko/features/data-and-storage/connection-details#regenerate-production-database-credentials).

<div id="section-4">
  ## Modifier une base de données de production en toute sécurité
</div>

Lorsque vous publiez une mise à jour incluant des modifications de la base de données, certaines d’entre elles nécessitent une planification minutieuse afin d’éviter les interruptions de service ou la perte de données.

<Info>
  Une brève interruption de service peut survenir dans votre application publiée pendant la publication. Il est parfois nécessaire d’arrêter temporairement l’application afin d’éviter les conflits et de protéger les données lors de l’application des modifications de la base de données.
</Info>

Les types de modifications suivants nécessitent généralement une attention particulière :

* **Suppression de colonnes de la base de données** auxquelles le code de l’application fait encore référence
* **Modification du type de données d’une colonne** d’une manière que le code existant ne peut pas gérer
* **Ajout de champs obligatoires** sans valeur par défaut aux tables existantes
* **Modification du nom de tables ou de colonnes** qui rompt les requêtes existantes
* **Modification de contraintes** susceptibles d’être incompatibles avec la logique existante de l’application

<div id="section-5">
  ### Tester les modifications avec un aperçu de déploiement
</div>

Un aperçu de déploiement est une copie temporaire et isolée de l’environnement de production qui vous permet de tester les modifications apportées à la base de données et les mises à jour de l’application avant qu’elles n’affectent les utilisateurs. Utilisez-le pour :

* Vérifier que votre application continue de fonctionner correctement tout au long des principaux parcours utilisateur une fois les modifications de la base de données appliquées
* Vérifier que les données existantes ont été correctement migrées et que les nouveaux champs contiennent les valeurs attendues
* Vérifier l’absence de dégradation des performances des temps de réponse des requêtes

<div id="section-6">
  ## Facturation et utilisation des ressources
</div>

Les bases de données de production sont facturées à l&#39;utilisation via Neon, un fournisseur de bases de données serverless. Après 5 minutes d&#39;inactivité, elles passent en veille, ce qui suspend la facturation du temps de calcul, puis se réactivent instantanément dès qu&#39;elles reçoivent une requête.

La page d&#39;accueil de l&#39;outil Database affiche **Période de facturation** et **Heures de calcul utilisées**. Pour consulter l&#39;utilisation de l&#39;espace de stockage de chaque base de données, ouvrez l&#39;onglet **Paramètres** de cette base. Pour consulter l&#39;utilisation de toutes les applications Replit, ouvrez **Paramètres** → **Compte** → **Utilisation du compte**, puis développez les lignes **Stockage PostgreSQL** et **Calcul PostgreSQL**.

Pour en savoir plus sur la facturation de l&#39;utilisation des bases de données par Replit, consultez [Tarification des déploiements et des bases de données](/fr/ko/billing/about-usage-based-billing#databases).

<div id="section-7">
  ## Supprimer une base de données de production
</div>

<Warning>
  La suppression ne peut plus être annulée après la période de rétention de 7 jours. Veillez à sauvegarder les données importantes avant de continuer. La base de données est soumise à une période de suppression réversible de 7 jours, durant laquelle vous pouvez la restaurer. Contactez l’assistance si vous avez besoin d’aide. Après 7 jours, la base de données est définitivement supprimée et ne peut plus être restaurée.
</Warning>

<Accordion title="Comment supprimer une base de données">
  Dans l’outil **Database** :

  1. Sélectionnez la base de données, puis ouvrez l’onglet **paramètres**
  2. Sélectionnez **Remove database**, puis confirmez en sélectionnant **Yes, Remove database**
</Accordion>

<div id="section-8">
  ## Bases de données de développement héritées
</div>

Avant le 4 décembre 2025, les bases de données de développement étaient hébergées par <a href="https://neon.com/" target="_blank">Neon</a>. Toutes les nouvelles bases de données de développement sont hébergées sur l’infrastructure de Replit (Helium). Vous pouvez vérifier laquelle votre App utilise dans l’onglet **Paramètres**. Si `DATABASE_URL` contient `neon.tech`, il s’agit de l’ancienne infrastructure Neon ; s’il contient `helium`, il s’agit de l’infrastructure actuelle.

| **Fonctionnalité**               | **Replit (actuel)**                                                                                                                                                                    | **Neon (hérité)**                                                                                                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hébergement**                  | Hébergé sur l’infrastructure de Replit                                                                                                                                                 | Hébergé par Neon (fournisseur tiers)                                                                                                                                               |
| **Facturation**                  | Inclus gratuitement avec toutes les applications Replit                                                                                                                                         | Facturation à l’usage. Pour en savoir plus, consultez [la facturation de la publication et des bases de données](/fr/ko/billing/about-usage-based-billing#databases).                 |
| **Restauration**                 | Restaurez la base de données à n’importe quel point de contrôle à l’aide de la [fonctionnalité de restauration](/fr/ko/features/data-and-storage/data-recovery)                           | Restauration à un instant donné (PITR) : restauration à n’importe quel moment de la période de conservation des sauvegardes.                                                       |
| **Sécurité des connexions**      | Accessible uniquement depuis l’App et jamais exposée à l’extérieur.                                                                                                                    | Utilise la chaîne de connexion complète. Si elle est exposée, n’importe qui peut accéder à la base de données et la modifier.                                                      |
| **Comportement des remix**       | Le [remix](/fr/ko/features/projects-and-artifacts/remix-an-app) crée une nouvelle base de données de développement avec une copie des données afin de garantir l’isolation et la sécurité | Les remix réutilisent la même base de données dans toutes les copies, de sorte que les modifications apportées dans un remix peuvent affecter l’App d’origine.                     |
| **Création de bases de données** | Créée automatiquement pour chaque application Replit.                                                                                                                                          | Nécessite une configuration explicite.                                                                                                                                             |
| **Workflow de publication**      | La publication crée une base de données de production distincte afin d’isoler les environnements.                                                                                      | Le développement et la production partageaient la même base de données, ce qui pouvait entraîner l’impact de modifications de développement involontaires sur l’App de production. |

<div id="section-9">
  ## Mise à niveau de l&#39;infrastructure de base de données
</div>

Replit fait passer les bases de données de développement de Neon à **Helium**, sa propre infrastructure PostgreSQL managée. Cette mise à niveau est automatique : elle s&#39;exécute une fois par app, lorsque vous ouvrez celle-ci dans le Project Editor, et toutes les données sont conservées.

Voici ce qui change :

* **Latence réduite et espace de stockage accru** : votre base de données s&#39;exécute sur l&#39;infrastructure Replit aux côtés de votre app, et la limite de stockage passe de 10 Go à 20 Go.
* **Même moteur de base de données** : Helium utilise PostgreSQL 16, la même version que Neon. Vos requêtes, schémas et données fonctionnent à l&#39;identique.
* **Connexions mises à jour automatiquement** : `DATABASE_URL` est mis à jour pour pointer vers Helium. L&#39;ancienne chaîne de connexion Neon est conservée dans les Secrets sous le nom `NEON_DATABASE_URL`, à titre de référence.
* **Suppression des variables PG individuelles** : `PGHOST`, `PGPORT`, `PGUSER` et `PGPASSWORD` sont supprimées. Utilisez `DATABASE_URL` à la place.

Pendant la mise à niveau, un écran de progression **« Upgrading your database »** s&#39;affiche. Pour les bases de données volumineuses, l&#39;opération peut prendre de quelques minutes à plusieurs heures ; vous pouvez fermer l&#39;onglet et revenir plus tard. En cas de problème pendant la mise à niveau, celle-ci est automatiquement ignorée et une nouvelle tentative aura lieu à la prochaine ouverture de l&#39;app. Une boîte de dialogue de confirmation s&#39;affiche une fois l&#39;opération terminée.

Pour la plupart des builders, aucune action supplémentaire n&#39;est nécessaire. Vérifiez toutefois les points suivants s&#39;ils vous concernent :

* **Chaînes de connexion Neon codées en dur** : mettez à jour le code qui référence des chaînes de connexion `neon.tech` afin qu&#39;il utilise la variable d&#39;environnement `DATABASE_URL`.
* **Rôles PostgreSQL personnalisés** : les rôles et leurs permissions sont migrés automatiquement, mais les mots de passe ne peuvent pas être copiés. Réinitialisez les mots de passe de vos rôles personnalisés dans la nouvelle base de données.

<div id="ssl">
  ### Erreur de connexion SSL après la mise à niveau
</div>

Si une erreur telle que `The server does not support SSL connections` s&#39;affiche, c&#39;est que votre code de connexion force une négociation SSL. Neon nécessitait SSL, mais Helium s&#39;exécute localement avec votre application et n&#39;utilise pas SSL. Configurez les paramètres SSL de manière conditionnelle selon l&#39;environnement.

<CodeGroup>
  ```js JavaScript theme={null}
  // Avant (ne fonctionne plus après la mise à niveau)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // Après (fonctionne en développement comme en production)
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  Si vous utilisez un ORM comme Drizzle, Prisma ou Sequelize, consultez la documentation correspondante pour savoir comment configurer les paramètres SSL de manière conditionnelle. Le même principe s&#39;applique : désactivez SSL pour la base de données de développement et activez-le en production.
</Tip>

<div id="section-10">
  ### Applications forkées partageant une base de données
</div>

Dans l&#39;ancien système Neon, forker une application copiait la variable `DATABASE_URL` de l&#39;application d&#39;origine : les deux applications et leurs versions publiées étaient alors connectées à la même base de données. Les anciennes bases de données partagées ont été mises hors service le **8 juin 2026**. Si votre application publiée ne fonctionne plus ou n&#39;a plus accès aux données, consultez [Corriger les applications publiées qui utilisent une base de données partagée](/fr/ko/features/data-and-storage/shared-database-migration) ou [contactez l&#39;assistance](https://replit.com/support).
