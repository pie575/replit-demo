Un [projet](/fr/features/projects-and-artifacts/projects) est le conteneur de tout ce que vous créez sur Replit. Il regroupe vos designs, vos applications, vos présentations, vos données et l&#39;ensemble des contenus que vous produisez.
Les [artifacts](/fr/features/projects-and-artifacts/artifacts) sont les éléments publiables d&#39;un projet : web apps, applications mobiles, présentations et vidéos.

Lorsque vous créez plusieurs éléments, deux possibilités s&#39;offrent à vous :

* ajouter plusieurs artifacts à un même projet,
* ou créer des projets distincts.

Le bon choix dépend de la question suivante : vos applications partagent-elles des données, une logique et un même cycle de vie de deployment ? Ce guide explique quand regrouper vos artifacts dans un seul projet et quand créer des projets séparés.

<div id="what-artifacts-share-in-a-project">
  ## Ce que les artifacts partagent au sein d&#39;un projet
</div>

Lorsque des [artifacts](/fr/features/projects-and-artifacts/artifacts) se trouvent dans le même [projet](/fr/features/projects-and-artifacts/projects), ils partagent automatiquement :

* **Base de données** : un artifact écrit des données, les autres les lisent instantanément
* **Backend et API** : une logique serveur commune, sans code dupliqué
* **Stockage de fichiers** : images, documents et fichiers téléversés accessibles depuis tous les artifacts
* **Deployment** : la publication met tout en ligne simultanément

Vous n&#39;avez donc pas à configurer de connexions ni à dupliquer du code entre les artifacts. En contrepartie, vous ne pouvez pas publier un artifact sans publier les autres.

<div id="quick-guide">
  ## Guide rapide
</div>

Voici les principaux cas à examiner pour décider s&#39;il faut ajouter des artifacts à un projet existant ou en créer un distinct.

| **Utiliser plusieurs artifacts dans un même projet**                                                      | **Utiliser des projets distincts**                                                        |
| ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Les applications partagent les mêmes données et le même backend                                            | Les applications ne partagent ni logique ni données sous-jacentes                          |
| Vous souhaitez tout publier en même temps                                                                  | Vous avez besoin de cycles de publication indépendants                                     |
| Elles sont complémentaires (par exemple une application client et un tableau de bord d&#39;administration) | Ce sont des produits sans lien entre eux ou destinés à des clients différents              |
| Vous souhaitez que les modifications d&#39;un artifact se répercutent automatiquement sur les autres       | Le projet est éphémère, comme une page de destination de campagne ou un site événementiel |

<div id="examples">
  ## Exemples
</div>

<div id="same-project-web-app-mobile-app-for-one-product">
  ### Même projet : web app + application mobile pour un seul produit
</div>

Un restaurant crée une web app permettant aux clients de consulter la carte et une application mobile permettant au personnel de gérer les commandes. Les deux se connectent à la même base de données regroupant les plats de la carte, les commandes et les informations clients.

**Pourquoi un seul projet :** les applications partagent les mêmes données et le même backend. Lorsqu&#39;un client passe commande via la web app, le personnel la voit apparaître immédiatement dans l&#39;application mobile.

<div id="same-project-app-admin-dashboard-investor-pitch-deck">
  ### **Même projet** : application + tableau de bord d&#39;administration + présentation pour investisseurs
</div>

Une startup développe son produit principal, un panneau d&#39;administration interne pour gérer le contenu et une présentation destinée à lever des fonds — le tout dans un seul projet.
Une startup développe son produit principal, un panneau d&#39;administration interne pour gérer le contenu et une présentation destinée à lever des fonds — le tout dans un seul projet.

**Pourquoi un seul projet :** le tableau de bord d&#39;administration gère les mêmes données que celles affichées par l&#39;application, et la présentation peut s&#39;appuyer sur des indicateurs en temps réel issus du backend partagé.

<div id="separate-projects-two-unrelated-client-apps">
  ### **Projets distincts** : deux applications clientes sans lien entre elles
</div>

Un freelance crée une boutique en ligne pour un client et un système de réservation pour un autre.

**Pourquoi des projets distincts :** les applications ne partagent ni données ni logique. Chaque client a besoin d&#39;une publication indépendante et vous ne voulez pas que les modifications apportées à l&#39;une se répercutent sur l&#39;autre.

<div id="separate-projects-campaign-landing-page-alongside-a-main-product">
  ### **Projets distincts** : page de destination de campagne aux côtés d&#39;un produit principal
</div>

Vous avez une application en production qui tourne toute l&#39;année et une page de destination éphémère pour une campagne marketing.

**Pourquoi des projets distincts :** la page de campagne a son propre cycle de vie — vous allez la créer, la laisser en ligne quelques semaines, puis la retirer. La garder à part évite d&#39;encombrer votre produit principal et vous permet de la publier ou de la supprimer indépendamment.

<div id="frequently-asked-questions">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artifact vers un autre projet ?">
  Pas pour l&#39;instant. Si vous devez isoler un artifact, créez un nouveau [projet](/fr/features/projects-and-artifacts/projects) et demandez à Agent de le reconstruire à cet endroit.
</Accordion>

<Accordion title="Le nombre d'artifacts d'un projet est-il limité ?">
  Un projet peut contenir au maximum 7 artifacts. Cette limite existe car chaque artifact supplémentaire consomme davantage de mémoire, ce qui peut ralentir le Preview. Si vous avez besoin de plus d&#39;artifacts, démarrez un autre [projet](/fr/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artifact d'un projet ?">
  Pas pour l&#39;instant. Le Publishing met tout en ligne d&#39;un seul bloc. Si vous devez publier des éléments indépendamment les uns des autres, utilisez des projets distincts.
</Accordion>
