---
title: "Plusieurs artefacts ou projets distincts"
description: "Découvrez quand regrouper des artefacts dans un même projet et quand créer des projets distincts sur Replit."
---

Un [projet](/fr/pt/features/projects-and-artifacts/projects) est le conteneur de tout ce que vous créez sur Replit. Un projet regroupe vos designs, applications, diapositives, données et toutes les productions que vous créez.
Les [artefacts](/fr/pt/features/projects-and-artifacts/artifacts) sont les productions publiables au sein d&#39;un projet : applications web, applications mobiles, présentations de diapositives et vidéos.

Lorsque vous créez plusieurs éléments, deux options s&#39;offrent à vous :

* ajouter plusieurs artefacts à un même projet,
* ou créer des projets distincts.

Le bon choix dépend du fait que vos applications partagent ou non des données, une logique et un cycle de vie de déploiement. Ce guide explique quand conserver les artefacts dans un seul projet et quand créer des projets distincts.

<div id="o-que-os-artefatos-compartilham-em-um-projeto">
  ## Ce que les artefacts partagent au sein d&#39;un projet
</div>

Lorsque les [artefacts](/fr/pt/features/projects-and-artifacts/artifacts) se trouvent dans le même [projet](/fr/pt/features/projects-and-artifacts/projects), ils partagent automatiquement :

* **Base de données** : un artefact écrit des données, les autres les lisent instantanément
* **Backend et API** : logique serveur partagée, sans code dupliqué
* **Stockage de fichiers** : images, documents et fichiers importés accessibles d&#39;un artefact à l&#39;autre
* **Déploiement** : la publication déploie l&#39;ensemble de façon synchronisée

Vous n&#39;avez donc pas besoin de configurer des connexions ni de dupliquer du code entre les artefacts. En revanche, vous ne pouvez pas publier un artefact sans publier les autres.

<div id="guia-rpido">
  ## Guide rapide
</div>

Voici les principaux cas de figure à prendre en compte pour décider s&#39;il faut ajouter des artefacts à un projet existant ou en créer un distinct.

| **Utiliser plusieurs artefacts dans un projet**                                                            | **Utiliser des projets distincts**                                                        |
| ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Les applications partagent les mêmes données et le même backend                                            | Les applications ne partagent ni logique ni données sous-jacentes                         |
| Vous souhaitez que tout soit publié en même temps                                                          | Vous avez besoin de cycles de publication indépendants                                    |
| Elles sont complémentaires (par exemple une application client et un tableau de bord admin)                | Ce sont des produits sans lien entre eux ou destinés à des clients différents             |
| Vous souhaitez que les modifications apportées à un artefact se répercutent automatiquement sur les autres | Le projet est de courte durée, comme une landing page de campagne ou un site événementiel |

<div id="exemplos">
  ## Exemples
</div>

<div id="mesmo-projeto-aplicativo-web-aplicativo-mobile-para-um-produto">
  ### Même projet : application web + application mobile pour un produit
</div>

Un restaurant crée une application web permettant aux clients de consulter la carte et une application mobile permettant à l&#39;équipe de gérer les commandes. Les deux se connectent à la même base de données regroupant les articles de la carte, les commandes et les informations clients.

**Pourquoi un seul projet :** les applications partagent les mêmes données et le même backend. Lorsqu&#39;un client passe une commande depuis l&#39;application web, l&#39;équipe la voit immédiatement dans l&#39;application mobile.

<div id="mesmo-projeto-aplicativo-dashboard-admin-pitch-deck-para-investidores">
  ### **Même projet** : Application + tableau de bord admin + pitch deck pour investisseurs
</div>

Une startup développe son produit principal, un tableau de bord administratif interne pour gérer le contenu et une présentation de diapositives pour sa levée de fonds — le tout dans un seul projet.
Une startup développe son produit principal, un tableau de bord administratif interne pour gérer le contenu et une présentation de diapositives pour sa levée de fonds — le tout dans un seul projet.

**Pourquoi un seul projet :** le tableau de bord admin gère les mêmes données que celles affichées par l&#39;application, et la présentation peut faire référence à des métriques en temps réel issues du backend partagé.

<div id="projetos-separados-dois-aplicativos-de-clientes-no-relacionados">
  ### **Projets distincts** : deux applications clientes sans lien entre elles
</div>

Un freelance crée une boutique e-commerce pour un client et un système de réservation pour un autre.

**Pourquoi des projets distincts :** les applications ne partagent ni données ni logique. Chaque client a besoin d&#39;une publication indépendante, et vous ne voulez pas que les modifications apportées à l&#39;une affectent l&#39;autre.

<div id="projetos-separados-landing-page-de-campanha-ao-lado-de-um-produto-principal">
  ### **Projets distincts** : landing page de campagne à côté d&#39;un produit principal
</div>

Vous avez une application en production qui tourne toute l&#39;année et une landing page éphémère pour une campagne marketing.

**Pourquoi des projets distincts :** la page de campagne a son propre cycle de vie — vous allez la créer, la laisser tourner quelques semaines, puis l&#39;arrêter. La garder à part évite d&#39;encombrer votre produit principal et vous permet de la publier ou de la supprimer indépendamment.

<div id="perguntas-frequentes">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artefact vers un autre projet ?">
  Pas pour le moment. Si vous devez isoler un artefact, créez un nouveau [projet](/fr/pt/features/projects-and-artifacts/projects) et demandez à Agent de le reconstruire à cet endroit.
</Accordion>

<Accordion title="Le nombre d'artefacts par projet est-il limité ?">
  Un projet peut contenir au maximum 7 artefacts. Cette limite existe car chaque artefact supplémentaire consomme davantage de mémoire, ce qui peut ralentir l&#39;aperçu. Si vous avez besoin d&#39;artefacts supplémentaires, démarrez un autre [projet](/fr/pt/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artefact d'un projet ?">
  Pas pour le moment. La publication déploie l&#39;ensemble du projet en une seule fois. Si vous avez besoin de publier chaque élément séparément, utilisez des projets distincts.
</Accordion>
