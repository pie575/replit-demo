**Publish**를 선택하면 앱을 라이브로 전환하는 짧은 pipeline이 시작됩니다. 이 페이지에서는 게시 과정에서 어떤 일이 일어나는지, 앱을 어떻게 업데이트하는지, 라이브 상태가 된 앱을 어디에서 관리하는지 설명합니다.

<div id="the-publishing-stages">
  ## 게시 단계
</div>

Publishing은 다섯 단계로 진행되며 보통 1~2분 정도 걸립니다. Publishing 도구의 진행 표시줄로 진행 상황을 확인하거나, **View logs**를 선택해 자세한 내용을 보거나, **Cancel**을 선택해 진행 중인 게시를 중단할 수 있습니다.

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Provision 완료, Security checks 및 Build 진행 중, Bundle과 Promote 대기 중 상태를 보여주는 다섯 단계 진행 표시줄이 있는 Publishing 개요" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision**: Replit이 앱을 실행할 서버와 production database 같은 클라우드 리소스를 준비합니다.
2. **Security checks**: 앱이 라이브로 전환되기 전에 Replit이 안전하지 않은 dependencies나 노출된 secret 같은 보안 문제를 검사합니다.
3. **Build**: Replit이 project를 앱의 production 버전, 즉 웹에서 실행되도록 최적화된 형태로 변환합니다.
4. **Bundle**: 빌드된 앱이 바로 실행 가능한 하나의 단위로 패키징됩니다.
5. **Promote**: Replit이 현재 버전과 나란히 새 버전을 준비한 뒤, URL을 새 버전으로 전환합니다.

<Note>
  Publishing은 project 전체를 대상으로 합니다. 앱, slide deck, 문서 등 project 안의 모든 artifact가 함께 게시됩니다.
</Note>

<Accordion title="내부에서 일어나는 일">
  기술적인 흐름이 궁금한 builder를 위한 설명입니다. Provision은 선택한 deployment type과 리전에 맞는 deployment 인프라를 할당합니다. Security checks는 dependency 및 코드 검사를 실행하며, 보안 설정에 따라 심각한 취약점이 발견되면 게시를 차단할 수 있습니다. Build는 빌드 명령을 실행하고 production용 assets를 컴파일합니다. Bundle은 빌드 결과물을 배포 가능한 이미지로 패키징합니다. Promote는 전환 작업을 수행합니다. 새 버전이 여러분의 URL에서 요청을 serve하기 시작하며 이전 deployment를 대체합니다.
</Accordion>

모든 단계가 완료되면 앱이 라이브 상태가 됩니다. Publishing 도구에서 URL을 선택해 앱을 열어 보세요.

<div id="update-your-app">
  ## 앱 업데이트
</div>

변경 사항을 적용한 후 **Publish**를 다시 선택하세요. 앱은 동일한 URL에서 업데이트되며, 방문자는 다음에 접속할 때 최신 버전을 보게 됩니다. 새 링크를 공유할 필요가 전혀 없습니다.

<div id="manage-your-live-app">
  ## 라이브 앱 관리
</div>

Publishing 도구에서는 앱이 라이브 상태가 된 후의 관리도 할 수 있습니다:

* **상태 모니터링**: 앱이 온라인 상태인지 확인하고, 로그를 조회하며, 리소스 사용량을 점검하세요. [모니터링](/ko/features/publishing/monitoring-a-deployment)에 대해 자세히 알아보세요.
* **방문자 확인**: 요청 및 트래픽 차트는 [Monitoring](/ko/features/publishing/monitoring-a-deployment)에서, 방문자 및 사용자 인사이트는 **Growth** 창에서 확인할 수 있습니다.
* **접근 권한 변경**: 게시를 해제하고 다른 접근 옵션을 선택한 뒤 다시 게시하세요. [앱 접근 권한](/ko/features/publishing/private-deployments)에 대해 자세히 알아보세요.
* **도메인 연결**: 앱에 원하는 웹 주소를 지정하세요. [사용자 지정 도메인](/ko/features/publishing/custom-domains)에 대해 자세히 알아보세요.
