<div id="como-os-resultados-so-categorizados">
  ## 结果如何分类
</div>

两种扫描的结果都会显示在 Security 面板中，并按严重性级别分类：

* **Critical**：构成直接风险、必须在发布前处理的漏洞，例如远程代码执行、暴露端点上的 SQL 注入以及凭据泄露。
* **High**：在特定条件下可被利用的严重问题，例如跨站脚本 (XSS) 、不安全的身份验证流程，或存在已知利用方式且未打补丁的依赖项。
* **Medium**：存在潜在风险但不太容易被利用的问题，例如缺少安全标头或 CORS 配置过于宽松。
* **Low / Informational**：轻微问题或最佳实践建议，例如使用已弃用的 API，或在生产环境中输出详细的错误信息。

<div id="o-que-o-project-security-center">
  ## 什么是 Project Security Center？
</div>

Project Security Center 是项目的中央枢纽，帮助你在发布前发现并修复安全与隐私漏洞。在 Project 中打开 **Security** 面板，即可运行扫描、查看结果，并将已接受的问题发送给 Agent 进行修复。

Project Security Center 支持两种扫描类型：

1. **自动依赖项扫描**：免费的轻量级扫描，将项目的软件包与公共漏洞库进行比对
2. **Agent 安全扫描**：由 AI 辅助的审查，结合模型分析与静态代码分析工具，对整个代码库进行审计

两种扫描的结果都会显示在同一个 Security 面板中，并按严重程度排序，便于你优先处理影响最大的问题。

<div id="varreduras-automticas-de-dependncias">
  ## 自动依赖项扫描
</div>

自动依赖项扫描会将项目所依赖的软件包与公共漏洞库进行比对审计。此类扫描**免费**且自动运行。当有新的 Common Vulnerabilities and Exposures (CVE) 条目发布时，Replit 会将其与你的项目依赖进行比对，并在 **Security** 面板中显示所有匹配项——无需手动重新扫描。

依赖扫描支持 Node.js/npm、Python、Go、Rust、PHP 和 Ruby。例如，扫描可能会标记出 `express@4.18.2` 这类过时软件包中的已知漏洞。

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect 是对自动依赖项扫描的扩展。检测到匹配的漏洞时，Replit Agent 会准备并测试补丁，并通过电子邮件发送直达链接。Auto-Protect 仅覆盖依赖项的 CVE——如需排查应用代码自身的漏洞，请使用 [Agent 安全扫描](#agent-security-scans)。

每当出现与项目依赖项匹配的新漏洞时，Replit 会：

1. 发送一封电子邮件，其中包含摘要以及指向受影响项目 **Security** 面板的直达链接。
2. 提示 Replit Agent 准备并测试可修复该漏洞的补丁。
3. 将补丁置于 **Security** 面板中待审核。

选择 **Go to Task**，可在应用补丁前查看生成的更改。应用补丁后，该漏洞会显示为 **pending republish**，直到你发布新版本为止。

应用补丁后请务必重新发布，以确保生产环境中的应用安全无虞。

对于每个新漏洞，Replit 在每个 Workspace 中最多发送一封电子邮件，并在邮件中汇总该 Workspace 内所有受影响的项目。管理员可以设置触发 Auto-Protect 的最低严重性级别，例如仅在严重 (critical) 级别时触发。

<div id="ativar-o-auto-protect">
  #### 启用 Auto-Protect
</div>

Auto-Protect 的两项设置**默认均为关闭状态**。启用 Auto-Protect 需要完成两项配置：一项仅限管理员的设置，用于授权 Replit 准备补丁；另一项为个人设置，用于控制你是否接收新漏洞的邮件通知。

<Steps>
  <Step title="启用补丁准备（仅限管理员）">
    前往 **Settings** &gt; **Account** &gt; **Advanced**，选择 Replit 自动准备修复方案的最低严重级别 (low、medium、high 或 critical) 。阈值设得越高，Replit 就只会为越严重的漏洞准备补丁。
  </Step>

  <Step title="启用安全邮件通知">
    前往 **Settings** &gt; **Personalization** &gt; **Email Notifications**，选择你希望收到新安全问题通知的最低严重级别。通常选择 high 或 critical。
  </Step>
</Steps>

<Note>
  由 Agent 准备的修复方案会像其他 Agent 工作一样计费，即使是 Auto-Protect 主动
  准备的也不例外。
</Note>

<div id="varreduras-de-segurana-com-agent">
  ## 使用 Agent 进行安全扫描
</div>

Agent 安全扫描不止于依赖项检查，还会对整个代码库进行全面审计。Security Agent 将基于模型的审查与 [Semgrep](https://semgrep.dev/)、[HoundDog.ai](https://hounddog.ai) 等静态分析工具相结合，发现仅靠模式匹配无法检测到的漏洞。

所有 Replit 付费开发者均可使用 Agent 安全扫描。对于较大的项目，深度审计可能需要长达 15 分钟，以确保评估全面彻底。

<div id="o-que-o-security-agent-faz">
  ### Security Agent 的功能
</div>

当你启动 Agent 安全扫描时，Security Agent 会对你的代码库进行全面审查：

1. **梳理架构** —— 识别路由、API、数据流和入口点
2. **构建威胁模型** —— 为你的应用生成可自定义的威胁建模方案
3. **执行静态分析** —— 使用 Semgrep 和 HoundDog.ai 检查代码漏洞和隐私问题
4. **借助 AI 分析结果** —— 评估被标记的问题在你的应用场景中是否真的可被利用，从而大幅减少误报
5. **生成结果报告** —— 列出识别到的风险，供你审查

Agent 安全扫描涵盖多种漏洞类别：

* **静态分析问题 (SAST)&#x20;**：不安全的代码模式，例如 SQL 注入、跨站脚本 (XSS) 和跨站请求伪造 (CSRF)
* **隐私问题**：敏感数据流向存在风险的目标，例如日志、文件或第三方 API
* **架构层面的漏洞**：路由、API 和数据流的组织方式中存在的安全缺口

例如，审查可能会标记出未参数化的数据库查询：

```javascript theme={null}
const query = `SELECT * FROM users WHERE username = '${userInput}'`;
```

或者记录敏感用户数据的代码：

```javascript theme={null}
logger.info("New signup", {
  email: user.email,
  phoneNumber: user.phoneNumber,
  address: user.address,
});
```

</div>

  <Step>
    选择 **Run scan with Agent**。

    <Frame>
      <img src="/assets/mirror/run-scan-with-agent-f54820ac154a.png" alt="Project Security Center 中高亮显示的 Run scan with Agent 按钮" width="1440" height="900" data-path="images/project-security-center/run-scan-with-agent.png" />
    </Frame>
  </Step>

  <Step>
    你也可以自定义威胁建模 prompt，让扫描聚焦于应用的特定部分。

    <Frame>
      <img src="/assets/mirror/scan-options-c2cd398fa78b.png" alt="扫描选项弹出框，其中的 Add context 字段可将扫描限定在项目的特定区域" width="1440" height="900" data-path="images/project-security-center/scan-options.png" />
    </Frame>
  </Step>

  <Step>
    等待审查完成。通常需要几分钟，较大的项目最多可能需要 15 分钟。
  </Step>

审查完成后，Security Agent 会生成一份已识别风险的报告。你可以查看漏洞详情，忽略那些你已了解并接受的结果，也可以先审查结果，再将其提交修复。

审查完成后，把你确认的问题发送给 Replit Agent 进行修复。Security Agent 会将漏洞拆分成独立任务，方便 Agent 并行处理多项修复。修复应用完成后，再运行一次扫描，确认问题已解决。

修复第一批结果后，请再运行一次扫描。对于较大的项目，在解决高严重性问题后，可能还会发现新的问题。

<div id="limitaes-e-melhores-prticas">
  ## 限制与最佳实践
</div>

* **隐私与数据处理**：所有扫描均在 Replit 基础设施上运行。你的代码和数据不会发送给 Semgrep、HoundDog.ai 或任何第三方。扫描配置和结果始终与你的 Replit App 绑定。
* **语言支持**：
  * 依赖扫描支持众多主流生态系统 (包括 **Node.js/npm**、**Python**、**Go**、**Rust**、**PHP** 和 **Ruby**) 。
  * 依赖自动修复目前主要针对 **Node.js/npm**。
* **并非完整的安全审查**：请将扫描与代码审查、测试、依赖审查以及对运行中应用的检查结合使用。
* **变更后重新扫描**：出现以下情况时请重新执行扫描：
  * 添加或更新依赖后
  * 对代码进行重大改动后
  * 发布新版本之前

<div id="verificaes-de-publicao">
  ## 发布检查
</div>

**Block publishing of critical vulnerabilities** 设置位于 Deploy 标签页的高级设置中 (以及重新发布流程中) 。Replit 在发布前始终会执行一次安全扫描；此开关决定扫描发现严重 (critical) 级别问题时的处理方式：

* **开启** — 发布会被阻止，直到问题得到解决或被忽略。
* **关闭** — 发布照常进行，并显示扫描结果供你审查。

启用该设置可确保任何严重问题都不会未经你审查就发布上线。使用 Enterprise 方案的组织可以要求所有应用都启用此设置。

<Note>
  此设置以前名为“Security scan before publishing”，并带有 **Beta** 标签。现在它已结束 Beta 阶段，并已重命名，以便更清晰地体现其行为——扫描本身无论如何都会执行。
</Note>
