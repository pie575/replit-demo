---
title: "Mettre à jour les anciens projets pour prendre en charge plusieurs artefacts"
description: "Ajoutez un deuxième artefact aux anciens projets Replit grâce à une mise à jour structurelle unique qui préserve les URL, les données et les déploiements."
---

Si votre projet a été créé avant le 11 mars 2026, Agent devra peut-être effectuer une mise à jour structurelle unique avant d’ajouter un deuxième artefact. Cette page explique pourquoi, ce qui change et quels projets sont concernés.

<div id="section">
  ## Contexte
</div>

**Le 11 mars 2026**, Replit a lancé [Agent 4](/fr/ko/updates/2026/03/13/changelog). L’un des principaux changements de cette version était la **prise en charge de plusieurs artefacts**. Un même [projet](/fr/ko/features/projects-and-artifacts/projects) peut désormais contenir plusieurs [artefacts](/fr/ko/features/projects-and-artifacts/artifacts) (par exemple, des applications web, des applications mobiles ou des présentations) partageant la même base de données, le même backend, les mêmes secrets et les mêmes déploiements.

Avant le 11 mars 2026, chaque projet était créé avec une structure de fichiers différente, conçue autour d’une seule application. Cette ancienne structure ne permet pas la séparation nécessaire pour qu’un backend héberge plusieurs artefacts. C’est pourquoi les projets créés avant le 11 mars 2026 nécessitent une **mise à jour structurelle unique** avant qu’Agent puisse ajouter un deuxième artefact. Les projets créés après cette date utilisent déjà la nouvelle structure et ne nécessitent donc pas cette étape.

<div id="section-2">
  ## Ce que fait la mise à jour
</div>

Si vous demandez à Agent d’ajouter un deuxième artefact à un projet existant (par exemple, une application mobile à une application web existante), Agent réorganise d’abord le projet selon une nouvelle structure à plusieurs artefacts. Les URL, collaborateurs, secrets, bases de données et domaines restent inchangés. Seule la structure interne est modifiée.

<div id="section-3">
  ## Fonctionnement
</div>

<Steps>
  <Step title="Demander un nouvel artefact à partir d’un projet existant">
    Demandez à Agent, par exemple : « Crée un pitch deck pour mon site web. »
  </Step>

  <Step title="Examiner et approuver">
    Agent s’arrête avant de commencer les modifications et affiche une proposition dans le chat. Pour un maximum de deux projets éligibles, une offre unique de **5 $ de crédits** pour lancer la mise à jour du projet s’affiche également. Cliquez sur **Mettre à jour le projet** pour continuer ou sur **Plus tard** pour ignorer cette étape.

    </Frame>
  </Step>

  <Step title="Attendre la restructuration">
    Agent restructure votre projet selon la nouvelle structure à l’aide de tâches ; vous pouvez suivre la progression dans la liste des tâches. Votre application existante est sauvegardée avant toute modification afin que vous ne perdiez pas votre travail précédent en cas de problème.

    <Frame>

  </Step>

  <Step title="Recevoir le nouvel artefact demandé">
    Une fois l’application existante exécutée dans la nouvelle structure, Agent crée l’artefact que vous aviez initialement demandé.
  </Step>
</Steps>

<div id="section-4">
  ## Conditions d’éligibilité
</div>

À l’heure actuelle, tous les projets ne sont pas éligibles à la mise à jour. Votre projet doit appartenir à l’un des types suivants.

* **Application web** (JavaScript full-stack)
* **Maquette design-to-app**
* **Application mobile** (Expo)

Les autres types de projets créés avant le 11 mars 2026, comme les projets Python, Flask ou Streamlit, les stacks de jeux, les projets vidéo et les stacks Agent, ne sont pas pris en charge. Si vous avez besoin de plusieurs artefacts dans ce cas, [créez plutôt un nouveau projet](/fr/ko/features/projects-and-artifacts/projects).

Les ports et les workflows de votre projet doivent également correspondre à la configuration par défaut de ce type. Si vous avez modifié `.replit` manuellement, le message suivant s’affiche.

> *Ce projet ne peut pas être migré automatiquement : la configuration du workflow ne correspond pas à celle attendue.*

Pour résoudre ce problème, rétablissez les personnalisations des ports ou des workflows à leurs valeurs par défaut, puis réessayez.

<div id="section-5">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Pourquoi mon projet doit-il être mis à jour ?">
    Les projets créés avant le 11 mars 2026, date de sortie d’Agent 4, utilisaient une architecture à application unique. Avec la nouvelle structure d’espace de travail partagé, une application web, une application mobile et un tableau de bord d’administration peuvent coexister et partager la même base de données et le même backend. Cette mise à jour unique permet de passer à cette structure.
  </Accordion>

  <Accordion title="Que se passe-t-il si je ne souhaite pas effectuer la mise à jour ?">
    Cliquez sur **Plus tard**. Agent continuera de travailler avec la structure existante à artefact unique. Vous pourrez consulter à nouveau cette proposition ultérieurement si vos besoins changent.
  </Accordion>

  <Accordion title="Puis-je effectuer la mise à jour plusieurs fois ?">
    Non. Une fois votre projet passé à la nouvelle structure, aucune autre mise à jour n’est nécessaire. Les artefacts suivants seront ajoutés directement, sans étape de mise à jour supplémentaire.
  </Accordion>

  <Accordion title="Mon projet n’est pas éligible. Quelles sont mes options ?">
    Créez un projet distinct pour le nouvel artefact ou démarrez un nouveau projet prenant en charge plusieurs artefacts dès le départ.
  </Accordion>
</AccordionGroup>
