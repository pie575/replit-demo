Replit Agent 提供两种交互模式：**Plan 模式**和 **Build 模式**。将两者结合使用，先理清思路，再从容地动手实现。

<div id="plan">
  ## 什么是 Plan 模式？
</div>

[Plan 模式](/zh/ko/features/agent/plan-mode)让你无需修改代码，即可与 Agent 一起头脑风暴、提问并规划工作。你可以将其视为一个协作式规划会话，自由探索各种想法。

Plan 模式非常适合：

* **头脑风暴**：在确定方案前探索不同的思路
* **拆解复杂项目**：在构建前获得结构化的任务清单
* **学习与理解**：就技术、模式或代码库提出问题
* **架构规划**：在编写代码前设计应用结构

<Info>
  在 Plan 模式中，Agent 会读取你的项目并提供指导，但不会更改文件。准备开始实施时，请切换到 Build 模式，或批准计划以自动开始构建。
</Info>

<div id="build">
  ## 什么是 Build 模式？
</div>

Build 模式是 Agent 用于编写代码、修改文件并直接在项目中实现功能的主要模式。在这里，创意将变为现实。

准备执行以下操作时，请使用 Build 模式：

* **创建新功能**：让 Agent 为新功能编写代码
* **配置应用**：安装依赖项、配置数据库并连接服务
* **修复问题**：让 Agent 调试并解决代码库中的问题
* **重构代码**：改进现有代码的结构和组织

<div id="section">
  ## 两种模式配合使用
</div>

**Plan 模式与 Build 模式按顺序搭配使用时效果最佳。** 先制定计划理清思路，再朝着明确的方向构建。

<Steps>
  <Step title="从 Plan 模式开始">
    切换到 Plan 模式，描述你想要构建的内容。Agent 会在不改动代码的前提下，帮你梳理需求、提出实现方案并识别潜在难点。
  </Step>

  <Step title="生成任务列表">
    请 Agent 制定开发计划。它会将项目拆解为具体、可执行的任务，并明确优先级和依赖关系。

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="带有优先级和依赖关系的生成任务列表" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="检查并完善">
    检查生成的计划。你可以追问、要求修改，或探索其他实现方案。反复迭代，直到计划符合你的构想。
  </Step>

  <Step title="开始构建">
    对计划满意后，选择**开始构建**。Agent 会自动切换到 Build 模式，并开始实现已确认的任务。

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="显示 Plan 模式和 Build 模式选项的模式选择器" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="跟踪进度">
    在 Agent 推进任务列表的过程中监控进度。每完成一项任务都会创建一个检查点，便于你查看变更并在需要时回滚。
  </Step>
</Steps>

<div id="section-2">
  ## 何时使用各模式
</div>

<CardGroup cols={2}>
  <Card title="何时使用 Plan 模式" icon="lightbulb">
    * 开始新项目，需要明确方向时
    * 想探索不同方案时
    * 工作较复杂，需要拆解时
    * 想在实施前先了解相关内容时
    * 不确定哪种方案最佳时
  </Card>

  <Card title="何时使用 Build 模式" icon="hammer">
    * 明确知道自己想要什么时
    * 已有清晰且可直接执行的计划时
    * 进行快速修复或小幅改动时
    * 按照已批准的任务清单执行时
    * 实施速度优先时
  </Card>
</CardGroup>

<Tip>
  **不确定该选哪个？** 如果请求涉及多个功能或重大改动，请先从 Plan 模式开始。对于简单且定义明确的任务，可以直接进入 Build 模式。
</Tip>

<div id="section-3">
  ## 主要区别
</div>

| 功能       | Plan 模式      | Build 模式  |
| -------- | ------------ | --------- |
| **用途**   | 头脑风暴、规划和学习   | 实现和构建     |
| **代码更改** | 无 — 只读       | 创建和修改文件   |
| **输出**   | 想法、任务列表和指南   | 可运行的代码和功能 |
| **适用场景** | 复杂项目、探索      | 明确的任务、实现  |
| **切换方式** | 点击“开始构建”进行切换 | 已处于实现模式   |

<div id="section-4">
  ## 最佳实践
</div>

<div id="plan-2">
  ### 充分利用 Plan 模式
</div>

* **明确具体的需求**：提供的细节越多，生成的计划就越好。
* **提出后续问题**：对不理解的建议要追问清楚。
* **索取示例**：让 Agent 展示代码片段或实现模式。
* **讨论取舍**：权衡不同方案的优缺点。
* **反复打磨想法**：不断完善计划，直到满意为止。

<div id="section-5">
  ### 顺畅过渡
</div>

* **构建前先审查**：批准前务必仔细查看任务列表。
* **从小处着手**：如果整个计划让你感到不知所措，可以先从部分任务开始。
* **使用检查点**：Agent 在构建过程中会创建检查点，你可以随时回滚。
