Auth 是**身份验证**的简称，它让你的 App 拥有“用户”这一概念。没有 Auth，每位访客都是匿名的，你的 App 无法区分不同用户。有了 Auth，每位访客都能登录，你的 App 就能识别他们，并为每位用户保存专属数据：预订记录、已保存的车辆、偏好设置和进度。

集成 Auth 后，你可以：

* 按用户保存数据——预订记录、设置、内容和历史记录。
* 将功能设为仅登录后可用 (如结账流程、个人资料页面或管理员面板) 。
* 根据姓名、角色、plan 或过往行为提供个性化体验。
* 按个人而非会话跟踪活动和使用情况。

<div id="como-o-auth-funciona-em-um-app-do-replit">
  ## Replit 应用中的身份验证如何运作
</div>

Replit 提供两种内置身份验证选项。两者均由 Agent 自动配置——无需在仪表板中单独注册，也无需复制粘贴 OAuth 密钥。

* **[Replit Auth](/zh/pt/features/auth-and-identity/authentication)** — 用户可使用其**现有 Replit 账户**登录。登录页面采用 Replit 品牌标识。您只需让 Agent 添加即可，无需其他配置。
* **[Clerk Auth](/zh/pt/features/auth-and-identity/clerk-auth)** — 您的应用会获得专属的 **Clerk 租户**。用户在*您的*应用内创建账户，而非在 Replit 中。您可以控制品牌、登录方式和登录页面的外观。

这两种选项都会处理繁琐的工作——登录页面、会话、安全的密码管理和社交登录——因此您的应用代码只需询问“当前登录的是谁？”

<div id="replit-auth-vs-clerk-auth">
  ## Replit Auth 与 Clerk Auth
</div>

|            | Replit Auth                  | Clerk Auth                       |
| ---------- | ---------------------------- | -------------------------------- |
| **用户账户**   | 用户使用 Replit 账户登录             | 用户在自己的 App 中创建账户 (无需 Replit 账户)  |
| **品牌**     | 使用 Replit 品牌的登录页面            | 可完全自定义，包括 App 名称、图标和颜色           |
| **SSO 凭据** | 使用 Replit 共享的 OAuth 应用       | 针对每个提供方使用自己的 OAuth 凭据            |
| **环境**     | 单一环境                         | 独立的开发和生产环境                       |
| **适用于**    | 快速设置、原型，以及可接受 Replit 品牌的 App | 具有自有品牌的 App、专业及商业产品              |

如果您要创建原型或内部工具，Replit Auth 是最快的选择。如果您要打造自有品牌的产品，尤其是面向客户或商业用途的产品，Clerk Auth 是更好的选择。

<div id="adicione-auth-ao-seu-app">
  ## 为你的 App 添加身份验证
</div>

无需一开始就做出选择——你可以先使用其中一种，之后再迁移。最快的方法是告诉 Agent 使用哪一种：

* *“为我的 App 添加登录功能。使用 Replit Auth。”*
* *“为我的 App 添加登录功能。使用 Clerk Auth。”*
