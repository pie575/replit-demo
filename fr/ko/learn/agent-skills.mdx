<div id="section">
  ## Pourquoi les compétences sont importantes
</div>

Chaque fois que vous créez avec Agent, un contexte utile se constitue : solutions à des problèmes, décisions de conception, préférences de framework. Mais dès que la conversation se termine, ce contexte disparaît. Les compétences, elles, le conservent.

Une compétence d&#39;animation GSAP apprend à Agent à utiliser correctement une bibliothèque donnée. Une compétence de système de design lui fait appliquer des règles précises de couleurs et d&#39;espacement. Une compétence de correction de bogues consigne la solution pour qu&#39;Agent ne reproduise pas la même erreur. Des tâches jusque-là inconstantes deviennent fiables.

Les compétences reposent également sur un [standard ouvert](https://agentskills.io/specification). Elles fonctionnent avec tous les agents, y compris Replit Agent, ce qui vous permet de passer d&#39;un outil à l&#39;autre.

<div id="vs">
  ## Compétences proactives et compétences réactives
</div>

Voici un cadre de réflexion pour déterminer quand et comment créer une compétence. Comprendre ces deux approches vous permettra de les exploiter plus efficacement.

<div id="section-2">
  ### Compétences proactives
</div>

Les compétences proactives sont des compétences que vous ajoutez *avant* de commencer à développer. Recherchez les bibliothèques ou les modèles que vous souhaitez utiliser, trouvez ou créez des compétences, puis rédigez votre prompt.

**Exemple :** avant de développer un site portfolio avec des animations SVG dessinées à la main, vous recherchez des bibliothèques d’animation et trouvez GSAP. Après avoir installé la compétence GSAP React, vous demandez à Agent de créer les animations. Agent dispose dès le départ des connaissances spécialisées nécessaires : il comprend l’API de la bibliothèque, les bonnes pratiques et les modèles courants. Sans compétence, il pourrait produire un résultat générique ou incorrect.

Ce modèle fonctionne bien dans les cas suivants :

* Vous utilisez une bibliothèque populaire avec des modèles subtils qu’Agent ne pourra peut-être pas parfaitement maîtriser seul
* Vous souhaitez des choix de conception cohérents dans l’ensemble du projet (typographie, espacement, style d’animation)
* Vous connaissez déjà la direction technique à prendre au démarrage du projet

<div id="section-3">
  ### Compétences réactives
</div>

Les compétences réactives sont créées *après* avoir résolu un problème. Vous identifiez le problème, le déboguez avec Agent, le corrigez, puis consignez la solution pour éviter qu&#39;il ne se reproduise.

**Exemple :** lors de la création d&#39;un canevas pour une application mobile, vous remarquez que les bords des images deviennent irréguliers lors du zoom. En déboguant avec Agent, vous découvrez qu&#39;il s&#39;agit d&#39;un aliasing de minification — un problème de rendu qui s&#39;aggrave à mesure que l&#39;image est réduite. Après avoir appliqué le correctif, vous demandez à Agent de créer une compétence :

<AiPrompt>
  Créez une compétence qui rassemble ce que nous venons d&#39;apprendre sur la correction de l&#39;aliasing de minification. Incluez la cause profonde, la solution et les situations dans lesquelles ce problème survient généralement afin de pouvoir l&#39;éviter à l&#39;avenir.
</AiPrompt>

Agent utilise l&#39;historique de la conversation pour rédiger une compétence spécifique au projet. La prochaine fois que ce problème se produit, vous pouvez vous y référer au lieu de recommencer le débogage depuis le début.

Ce modèle fonctionne bien dans les cas suivants :

* Vous avez corrigé un bug difficile à identifier et souhaitez éviter qu&#39;il se reproduise
* Vous avez appris quelque chose sur l&#39;architecture de l&#39;application au cours d&#39;une session de débogage
* Vous souhaitez enregistrer une solution dont la découverte a demandé des efforts considérables

<div id="section-4">
  ## Choisir les compétences
</div>

Voyez les compétences comme des indications données à un ami pour trouver son chemin jusqu&#39;à un appartement. Une liste d&#39;instructions axée sur un objectif est efficace. Un classeur rempli de documents ne l&#39;est pas : personne n&#39;a le temps de le lire et les détails importants s&#39;y perdent.

Il en va de même pour Agent. Ajouter trop de compétences peut dérouter Agent. Choisissez avec soin les compétences à activer pour un projet donné et supprimez celles dont vous n&#39;avez plus besoin.

<Note>
  Les compétences sont plus efficaces lorsqu&#39;elles définissent des modèles précis et réutilisables plutôt que des instructions générales. Concentrez-vous sur des flux de travail spécifiques, des conventions établies et des solutions éprouvées.
</Note>

<div id="section-5">
  ## Bien rédiger des compétences
</div>

Les compétences peuvent être complexes et sophistiquées. Quelques principes permettent de préserver leur efficacité :

* **Décrivez la bonne approche.** Expliquez à Agent comment procéder correctement. Énumérer ce qu’il *ne faut pas faire* indique que l’approche globale doit être repensée.
* **Utilisez des scripts lorsque c’est possible.** Les scripts déterministes sont plus fiables que de demander à Agent de raisonner sur les mêmes étapes à chaque fois.
* **Utilisez des liens.** En structurant les compétences pour qu’elles renvoient vers d’autres fichiers Markdown, Agent ne récupère que ce dont il a besoin pour la tâche en cours.
* **Testez-les régulièrement.** Vous vérifierez ainsi que les compétences fonctionnent réellement, plutôt que de le supposer.
* **Rédigez-les vous-même.** L’objectif est de fournir un contexte concis et intentionnel, ce que vous obtenez en rédigeant vous-même les compétences. Agent peut vous aider à préparer un brouillon, mais peaufinez-le afin que chaque ligne ait un sens.
* **Gardez-les personnalisés.** Ne créez pas de compétences génériques pour la propreté du code ou la sécurité — elles sont déjà intégrées à Agent. Les compétences doivent refléter ce qui est propre à vous ou à votre organisation.

La plupart des échecs des compétences sont faciles à diagnostiquer :

* **La compétence se déclenche alors qu’elle ne devrait pas.** Sa description est trop large. Réduisez son périmètre et précisez quand elle *ne doit pas être utilisée* — « Ne s’applique pas aux articles de blog ni aux documents d’aide » est souvent plus utile qu’une instruction positive.
* **La compétence se déclenche, mais le résultat est incorrect.** Les instructions sont trop générales. Remplacez les conseils vagues tels que « rends-le professionnel » par des noms précis, des exigences concrètes et des éléments explicites à éviter.
* **Deux compétences entrent en conflit.** Modifiez les descriptions afin que les deux compétences ne se déclenchent pas pour la même tâche. Les conflits sont presque toujours des problèmes de périmètre, et non d’instructions.

Les compétences deviennent obsolètes ; traitez-les donc comme une documentation que vous maintenez réellement.

<div id="section-6">
  ## Étendre les compétences à l’ensemble de l’espace de travail
</div>

Tout ce qui précède s’applique aux compétences d’un seul projet. Avec Teams, vous pouvez également personnaliser Agent à l’échelle de votre espace de travail afin de partir des mêmes conventions dans tous les projets, sans avoir à les réexpliquer à chaque fois. La personnalisation de l’espace de travail comporte deux volets :

* **Instructions personnalisées** — Règles toujours actives, injectées dans le contexte d’Agent pour tous les projets et tous les messages avant que quelqu’un ne saisisse un prompt. Réservez-les à un petit nombre de règles réellement universelles, comme « Ne stockez pas les identifiants en texte brut. » Elles sont chargées à chaque tour ; chaque mot utilise donc une partie du budget de contexte d’Agent — restez concis.
* **Compétences d’espace de travail** — Les mêmes compétences que celles décrites ci-dessus, disponibles pour tous les membres de l’espace de travail et gérées de manière centralisée. Elles ne consomment quasiment aucune ressource tant qu’une tâche pertinente ne les sollicite pas, ce qui vous permet d’en proposer de nombreuses sans dégrader les résultats.

Voici un moyen simple de décider où placer chaque élément : si une règle doit s’appliquer quel que soit ce que quelqu’un crée, il s’agit d’une instruction personnalisée ; si elle n’est importante que pour certains types de tâches, il s’agit d’une compétence.

Pour savoir comment configurer les instructions personnalisées et les compétences d’espace de travail, ainsi que pour connaître les autorisations de gestion, consultez [Personnalisation d’Agent](/fr/ko/features/agent/agent-customization).

<div id="section-7">
  ## Considérations de sécurité
</div>

Les compétences du panneau des compétences de Replit ont été soumises à un examen de sécurité. Toutefois, les compétences peuvent être installées depuis n’importe où : elles sont proposées dans un [dépôt open source](https://github.com/vercel-labs/skills) auquel chacun peut contribuer.

Comme les compétences sont des instructions suivies par Agent, une compétence malveillante peut demander à Agent d’exfiltrer des données sensibles de votre projet. Avant d’installer une compétence depuis une source externe :

1. **Ouvrez les fichiers.** Les compétences sont au format Markdown. Lisez leur contenu dans `/.agents/skills/` avant de les utiliser.
2. **Vérifiez la source.** Assurez-vous que la compétence provient d’un dépôt ou d’un auteur de confiance.
3. **Examinez les instructions.** Assurez-vous que la compétence ne renvoie pas vers des URL externes suspectes et ne demande pas d’informations sensibles.

<Warning>
  Examinez toujours les compétences provenant de sources externes avant de les installer. Les compétences du panneau des compétences de Replit ont été examinées, mais celles installées via la CLI ou copiées depuis Internet ne l’ont pas été.
</Warning>

<div id="vs-mcp">
  ## Compétences vs serveurs MCP
</div>

Les compétences et les serveurs MCP constituent deux principaux moyens d’étendre l’agent, chacun ayant un objectif différent.

**Les compétences** utilisent efficacement le contexte. Seule une brève description est chargée jusqu’à ce qu’une compétence soit appelée. Utilisez des compétences pour :

* Les flux de travail et les conventions (« comment publier », « checklist de revue de code »)
* Les ressources de référence (modèles d’API, guides de style, systèmes de design)
* Les prompts réutilisables et les connaissances spécialisées (bibliothèques d’animation, modèles de frameworks)

**Les serveurs MCP** consomment davantage de contexte. Toutes les descriptions d’outils sont chargées dès le départ, et en ajouter trop peut réduire la qualité des résultats. Utilisez des serveurs MCP pour :

* Connecter des services externes (Notion, Linear, Figma)
* Les actions nécessitant un accès à une API
* Les outils qui *effectuent réellement des tâches*, plutôt que de simplement fournir des instructions

Différence essentielle : les compétences définissent *comment* l’agent doit travailler. Les serveurs MCP définissent *à quoi* l’agent peut accéder. Les deux fonctionnent avec Replit Agent et les agents que vous développez directement.
