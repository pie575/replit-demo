La surveillance des applications publiées vous permet de suivre les métriques de performance, de modifier les paramètres et de vous assurer que vos applications publiées fonctionnent de manière optimale.

## Fonctionnalités

* **Suivi en temps réel** : Consultez le statut, les analyses et les détails de configuration de votre application publiée
* **Analyses de performance** : Surveillez les pages vues, les temps de réponse et les métriques d'engagement des utilisateurs
* **Surveillance de l'application** : Vérifiez si votre application publiée est en ligne, avec une barre colorée affichant la disponibilité récente en un coup d'œil
* **Gestion de la configuration** : Mettez à jour les commandes, les secrets et les options d'application publiée en quelques clics

## Utilisation

Vous pouvez accéder aux outils de surveillance dans l'onglet Publication.

<Accordion title="Comment accéder à la Publication">
  Depuis le **dock d'outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône de tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **Tous les outils** pour afficher la liste des outils de l'Éditeur de projet.
  2. Sélectionnez Publication <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône de publication" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publication**.
  3. Sélectionnez **Vue d'ensemble** en haut.

  Depuis la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="icône loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut pour ouvrir l'outil de recherche
  2. Tapez « Publication » pour localiser l'outil et sélectionnez-le dans les résultats.
  3. Sélectionnez **Vue d'ensemble** en haut.
</Accordion>

### Onglet Vue d'ensemble

L'onglet **Vue d'ensemble** vous permet de suivre le statut et la configuration de votre application publiée. Il fournit les informations suivantes :

* **Statut** : Statut de l'application Replit publiée, fournissant des informations sur les différentes étapes du processus.
* **Domaine** : URL où vous pouvez accéder à votre application Replit
* **Type de déploiement** : Autoscale, Reserved VM, Statique ou Planifié

<Frame caption="Onglet Vue d'ensemble de l'application publiée">
  <img src="/assets/mirror/overview-tab-d2623c2e674a.png" alt="Onglet Vue d'ensemble de l'application publiée" width="1828" height="604" data-path="images/deployments/overview-tab.png" />
</Frame>

Vous pouvez effectuer les actions suivantes depuis l'onglet **Vue d'ensemble** :

* **Republier** : Remplacer votre application publiée actuelle par un nouvel instantané et de nouvelles options d'application publiée. Vous pouvez surveiller le statut de cette application publiée dans cet onglet.
* **Modifier les commandes et les secrets** : Modifier le répertoire public, la commande de build et les secrets de l'application publiée.
* **Voir les journaux de publication** : Accéder aux journaux de votre application publiée.
* **Voir l'application publiée** : Ouvrir votre application publiée dans un nouvel onglet de navigateur.
* **Code QR** : Générer un code QR que vous pouvez scanner avec votre appareil mobile pour accéder à l'application publiée.
* **Gérer** : Afficher ou mettre à jour les paramètres de l'application publiée.
* **Voir toute l'utilisation** : Afficher la page de facturation d'utilisation.

### Onglet Journaux

L'onglet **Journaux** fournit des journaux en temps réel pour votre application publiée. Replit conserve les journaux pendant 7 jours.

Vous pouvez filtrer les journaux selon les catégories suivantes :

* **Erreurs uniquement** : Afficher uniquement les journaux d'erreurs
* **Recherche** : Saisir une phrase à rechercher dans les journaux
* **Date** : Sélectionner une plage de dates

L'onglet **Ressources** fournit une vue détaillée de l'utilisation des ressources de votre application publiée. Il comprend les informations suivantes :

* **Utilisation du CPU** : Pourcentage d'utilisation du CPU au fil du temps
* **Utilisation de la mémoire** : Pourcentage d'utilisation de la mémoire au fil du temps

### Onglet Analyses

<Note>
  Les analyses sont disponibles pour les déploiements Autoscale, Statique et Reserved VM.
</Note>

L'onglet **Analyses** affiche des statistiques concernant les visites des pages web de votre application publiée.
Vous pouvez personnaliser la période en utilisant le sélecteur de dates en haut.
Les métriques d'analyse comprennent les éléments suivants :

* **Pages vues** : Nombre de requêtes HTTP que votre application Replit reçoit par heure
* **URL les plus consultées** : Chemins d'URL les plus fréquemment visités
* **Principales sources de trafic** : Sources de trafic dirigeant les utilisateurs vers votre site web
* **Statuts HTTP** : Codes de réponse HTTP servis par votre application Replit
* **Durées des requêtes** : Temps de chargement côté serveur
* **Principaux navigateurs** : Utilisation des navigateurs parmi vos utilisateurs
* **Principaux appareils** : Systèmes d'exploitation et appareils utilisés pour accéder à votre application Replit
* **Principaux pays** : Distribution géographique de vos utilisateurs

### Surveillance de l'application

<Note>
  La surveillance de l'application est disponible sur les plans Replit Core, Pro, Teams et Enterprise. Elle fonctionne pour tous les types de déploiement, à l'exception des déploiements planifiés. Le bouton **Activer la surveillance de l'application** apparaît dans la boîte de dialogue de publication lorsque votre application est éligible.
</Note>

La surveillance de l'application vous indique quand votre application publiée est en ligne. Replit vérifie votre application selon un calendrier régulier et enregistre chaque résultat. Les résultats apparaissent à deux endroits : dans la vue **Publication**, pour une vérification de l'état en un coup d'œil, et dans l'onglet **Analyses**, pour un historique plus long.

#### Activer la surveillance de l'application

Vous pouvez activer la surveillance de l'application sur un projet existant depuis la boîte de dialogue de publication dans l'outil **Publication**.

<Steps>
  <Step title="Ouvrir la boîte de dialogue de publication">
    Ouvrez l'outil **Publication** et démarrez une nouvelle publication ou republication de votre application.
  </Step>

  <Step title="Activer le bouton bascule">
    Sous **Outils de surveillance**, activez **Activer la surveillance de l'application**, puis publiez votre application.
  </Step>

  <Step title="Afficher votre disponibilité">
    Après la publication, votre disponibilité apparaît dans la vue **Publication** et dans l'onglet **Analyses** en quelques minutes.
  </Step>
</Steps>

#### Lire votre barre de disponibilité

Après la publication de votre application, la vue **Publication** affiche une barre de disponibilité compacte accompagnée du statut, de la visibilité, de la géographie et du type de déploiement de votre application publiée. Utilisez-la pour vérifier si votre application est actuellement hors ligne, ou si elle a rencontré des problèmes récemment — par exemple, pendant la nuit pendant que vous dormiez.

<Frame caption="Disponibilité récente dans la vue Publication, avec un bouton Analyser les pannes récentes avec l'Agent">
  <img src="/assets/mirror/app-monitoring-overview-ffdfc2d48fc2.png" alt="Vue Publication pour un déploiement en production affichant 95,0 % de disponibilité, une barre de disponibilité colorée de il y a 1 jour à maintenant, et un bouton Analyser les pannes récentes avec l'Agent" width="863" height="295" data-path="images/deployments/app-monitoring-overview.png" />
</Frame>

Pour un historique plus long, ouvrez l'onglet **Analyses**. L'onglet Analyses inclut un sélecteur de plage de temps, vous permettant de remonter plus loin dans le temps et de corréler les pannes avec d'autres signaux — tels que le volume de requêtes ou les pics de trafic — pour déterminer si le trafic des utilisateurs cause des problèmes avec la capacité provisionnée de votre application.

<Frame caption="Graphique de surveillance de la disponibilité dans l'onglet Analyses avec un sélecteur de plage de temps Dernier jour">
  <img src="/assets/mirror/app-monitoring-analytics-07a11e4c2039.png" alt="Vue de surveillance de la disponibilité dans l'onglet Analyses avec un sélecteur de plage de temps Dernier jour et une grande barre de disponibilité affichant 29,0 % de disponibilité" width="991" height="205" data-path="images/deployments/app-monitoring-analytics.png" />
</Frame>

La barre de disponibilité affiche jusqu'aux 15 dernières heures d'activité. La barre contient 90 segments, et chaque segment couvre 10 minutes.

Les couleurs des segments indiquent l'état de connexion de votre application :

* **Vert** signifie que votre application est disponible.
* **Jaune** signifie qu'il y a des erreurs intermittentes lors de la connexion à votre application.
* **Rouge** signifie que votre application est indisponible.
* **Gris** signifie qu'aucune donnée n'est encore disponible pour cette fenêtre.

Survolez un segment pour voir la plage horaire exacte.

#### Analyser les pannes avec l'Agent

Pour approfondir l'analyse, sélectionnez **Analyser les pannes récentes avec l'Agent** sous la barre de disponibilité. L'Agent lance une nouvelle tâche en arrière-plan, récupère les fenêtres temporelles affectées et travaille à identifier la cause principale — par exemple, en examinant les journaux, le code et l'état de la base de données, puis en proposant une solution.

#### Causes courantes des pannes

Les pannes d'application sont généralement causées par l'un des problèmes suivants :

* **Votre application a planté.** Ouvrez l'onglet **Journaux** et recherchez des erreurs proches du moment où le segment est devenu rouge.
* **Votre application a manqué de CPU ou de mémoire.** Ouvrez l'onglet **Ressources** pour vérifier les pics. Si l'utilisation était élevée, choisissez une machine plus puissante dans l'onglet **Gérer**.
* **Une publication récente a causé le problème.** Comparez le moment des segments rouges à votre historique de publications, puis republiez une version fonctionnelle si nécessaire.
* **Les requêtes étaient trop lentes.** Des temps de réponse longs peuvent faire échouer les vérifications. Consultez les **Durées des requêtes** dans l'onglet **Analyses**.
* **Un paramètre est incorrect.** Des secrets expirés, des variables d'environnement incorrectes ou une base de données inaccessible pour votre application peuvent la mettre hors ligne. Vérifiez votre configuration dans **Modifier les commandes et les secrets** dans l'onglet **Vue d'ensemble**.

Pour plus d'aide, consultez [Dépannage des déploiements](/fr/cloud-services/deployments/troubleshooting).

### Onglet Planification

<Note>Les planifications sont disponibles uniquement pour les déploiements planifiés.</Note>

L'onglet **Planification** vous permet de consulter l'historique d'exécution de l'application publiée et comprend les informations suivantes :

* Temps écoulé depuis la dernière exécution
* Date et heure de début de l'exécution
* Durée de l'exécution
* Statut de l'exécution

Vous pouvez effectuer les actions suivantes dans l'onglet **Planification** :

* **Voir les journaux** : Sélectionnez l'icône <img class="icon-svg" src="/assets/mirror/menu-a72ad731aff8.svg" alt="icône menu" width="16" height="16" data-path="images/icons/menu.svg" /> voir les journaux à côté de l'entrée pour afficher les messages du journal.
* **Annuler l'exécution** : Sélectionnez l'icône <img class="icon-svg" src="/assets/mirror/cancel-2145d3814f60.svg" alt="icône annuler" width="16" height="16" data-path="images/icons/cancel.svg" /> annuler à côté de l'entrée pour arrêter une exécution en cours.
* **Démarrer une exécution** : Sélectionnez **Exécuter maintenant** pour démarrer manuellement une exécution sans modifier la planification.
* **Actualiser** : Utilisez l'icône <img class="icon-svg" src="/assets/mirror/refresh-52703b8cfe91.svg" alt="icône actualiser" width="16" height="16" data-path="images/icons/refresh.svg" /> actualiser pour mettre à jour l'historique d'exécution.

### Onglet Domaines

<Note>
  L'onglet **Domaines** est disponible pour les déploiements Autoscale, Reserved VM et Statique.
  Les déploiements planifiés ne disposent pas d'onglet Domaines.
</Note>

L'onglet **Domaines** vous permet de connecter et de gérer des domaines personnalisés pour votre application publiée. Depuis cet onglet, vous pouvez :

* **Lier un domaine** : Connecter un domaine personnalisé que vous possédez déjà.
* **Acheter un domaine** : Acheter un nouveau domaine directement via Replit.
* **Voir le statut du domaine** : Voir le statut de vérification pour chaque domaine connecté.

Pour une configuration étape par étape, consultez [Domaines personnalisés](/fr/cloud-services/deployments/custom-domains).

### Onglet Gérer

L'onglet **Gérer** comprend les paramètres de configuration suivants pour l'application publiée :

* **Utilisation des ressources** : Afficher le CPU, la RAM et le coût d'utilisation de la machine pour votre application publiée.
* **Mettre en pause** : Arrêter temporairement votre application publiée. Cette action rend votre application publiée inaccessible, mais la facturation continue.
* **Changer le type de déploiement** : Passer d'un type de déploiement à un autre. Par exemple, si vous avez initialement choisi le déploiement statique, vous pouvez le remplacer par des déploiements Reserved VM.
* **Arrêter** : Supprimer votre application publiée et arrêter son cycle de facturation. Sélectionnez **Arrêter** pour arrêter définitivement votre application publiée actuelle.
