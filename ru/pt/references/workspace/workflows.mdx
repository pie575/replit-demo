Это многоразовая настраиваемая последовательность шагов, которую можно запускать в Replit App. Она может быть такой же простой, как запуск `python main.py`, или такой же сложной, как выполнение многоэтапной процедуры.

Примеры использования:

* Параллельный запуск нескольких сервисов (например, фронтенда и бэкенда)

Чтобы начать [создавать Workflows](#creating-workflows), откройте панель Workflows в меню боковой панели инструментов или найдите её с помощью `Command + K`.

<div id="tipos-de-tarefas-disponveis">
  ## Доступные типы задач
</div>

Доступны 3 типа задач: `Execute Shell Command`, `Install Packages` и `Run Workflow`.

<div id="execute-shell-command">
  ### Выполнение команды Shell
</div>

`Execute Shell Command` сохраняет команду оболочки и выполняет её в той же среде, что и панель Shell. Этот тип задачи подходит для самых разных сценариев, например для запуска отдельных файлов:

```text theme={null}
python main.py
```

вплоть до выполнения сложных команд для запросов к базе данных:

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Установка пакетов
</div>

`Install Packages` использует встроенную систему управления зависимостями Replit: она автоматически обнаруживает зависимости проекта и устанавливает необходимые пакеты. Подробнее о том, как UPM определяет, какие пакеты нужно установить в проекте, см. в разделе [Управление зависимостями](/ru/pt/references/workspace/dependency-management#the-universal-package-manager).

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow` позволяет запускать другой workflow из текущего. Это дает возможность повторно использовать workflows и комбинировать их для создания более сложных workflows.

Пример использования:

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

Используя этот тип задачи для создания зависимостей между workflows, вы можете редактировать один workflow, а другие workflows, которые на него ссылаются, будут автоматически использовать последние изменения. Обратите внимание: для вызовов глубоко вложенных workflows существует ограничение глубины.

<div id="modo-de-execuo-do-workflow">
  ## Режимы выполнения Workflow
</div>

Workflows поддерживают два режима выполнения: последовательный и параллельный.

<div id="sequencial">
  ### Последовательный
</div>

При последовательном выполнении задачи запускаются в заданном порядке: следующая начинается только после завершения предыдущей. Если какая-либо задача в workflow завершается с ошибкой, выполнение последовательности останавливается.

Этот режим удобно использовать для настройки логически связанных команд — например, команд Git для получения последних изменений из основной ветки, а затем ребейза текущей ветки на основную:

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="изображение" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="paralelo">
  ### Параллельный
</div>

В параллельном режиме каждая задача запускается и выполняется независимо от других задач в workflow. Сбой одной задачи не прерывает выполнение остальных.

Этот режим можно использовать, например, для запуска fullstack-проекта, в котором необходимо запустить и фронтенд-сервер, и бэкенд:

<div id="criando-workflows">
  ## Создание Workflows
</div>

Workflows можно создавать на панели workflows, нажав кнопку `+ New Workflow`. Сначала задайте своему workflow понятное название, выберите подходящий режим выполнения и добавьте задачи. Задачи можно менять местами, перетаскивая их в нужном порядке.

<div id="atribuir-workflow-ao-boto-run">
  ## Назначение Workflow кнопке Run
</div>

Workflow также можно назначить кнопке Run, чтобы изменить её стандартное поведение (см. [Настройка Replit App](/ru/pt/references/configuration/configuration)). Чтобы сохранить стандартную команду запуска, заданную в `.replit`, выберите в раскрывающемся меню вариант по умолчанию «Run Replit App».

Workflow, выбранный в раскрывающемся меню рядом с кнопкой Run, будет запускаться при нажатии этой кнопки. Чтобы изменить Workflow, запускаемый кнопкой Run, выберите нужный Workflow в раскрывающемся меню.
