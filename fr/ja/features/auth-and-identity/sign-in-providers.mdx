title: "Fournisseurs de connexion"
description: "Configurez des identifiants OAuth personnalisés pour la connexion avec Google, GitHub, Apple et X dans les apps utilisant Clerk Auth."
---

Si votre app utilise [Clerk Auth](/fr/ja/features/auth-and-identity/clerk-auth), les visiteurs peuvent se connecter via des fournisseurs sociaux. Replit fournit des identifiants partagés prêts à l’emploi, mais cette page explique comment utiliser vos **propres** identifiants OAuth pour chaque fournisseur. Cela vous permet d’afficher le nom et l’image de marque de votre app sur l’écran de connexion.

La procédure est la même pour tous les fournisseurs. Créez une app OAuth dans la console du fournisseur, copiez l’URL affichée par Replit, puis collez les identifiants générés dans le panneau de configuration du fournisseur.

<Note>
  Les identifiants OAuth personnalisés ne peuvent être utilisés que dans l’environnement **Production**. Vous devez donc [publier](/fr/ja/features/publishing/overview) votre app au préalable. Vous pouvez ouvrir le panneau de configuration de chaque fournisseur depuis la section **fournisseurs SSO** de l’onglet **Configure** de l’outil **Users &amp; Auth**. Sélectionnez l’environnement **Production**, puis **Edit** à côté du fournisseur. Pour connaître l’ensemble de la procédure, consultez [Configurer des identifiants OAuth pour un fournisseur SSO](/fr/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
</Note>

<div id="google">
  ## Google
</div>

Ce guide décrit la marche à suivre pour créer une application Google OAuth dans la Google Cloud Console. Vous y obtiendrez un **Client ID** et un **Client Secret**, et configurerez également les origines JavaScript et les URI de redirection requis par Clerk.

Prérequis : disposer d&#39;un accès à la [Google Cloud Console](https://console.cloud.google.com/).

<div id="1-google-oauth">
  ### Étape 1 : créer une application Google OAuth
</div>

Rendez-vous sur la [Google Cloud Console](https://console.cloud.google.com/).

<div id="section">
  #### Créer ou sélectionner un projet
</div>

1. Sélectionnez un projet existant dans le menu déroulant des projets ou créez-en un nouveau
2. Vous êtes redirigé vers le tableau de bord du projet

<div id="oauth">
  #### Configurer l&#39;écran de consentement OAuth
</div>

1. Dans la barre latérale de gauche, sélectionnez l&#39;icône de menu (≡), puis **APIs &amp; Services**
2. Sélectionnez **OAuth consent screen**
3. Configurez l&#39;écran de consentement de votre application avec les informations requises
4. Enregistrez vos modifications

<div id="oauth-2">
  #### Créer des identifiants OAuth
</div>

1. Dans **APIs &amp; Services**, sélectionnez **Credentials**
2. En haut, sélectionnez **Create Credentials**, puis **OAuth client ID**
3. Choisissez **Web application** comme type d&#39;application
4. Renseignez dans **Authorized JavaScript origins** et **Authorized redirect URIs** les valeurs exactes affichées dans **Provider setup** du **volet Auth**. Ajoutez toutes les valeurs listées, y compris le domaine de publication et les domaines personnalisés. Pour savoir où trouver ces valeurs, consultez [Configurer des identifiants OAuth pour un fournisseur SSO](/fr/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Sélectionnez **Create**
6. Enregistrez le **Client ID** et le **Client Secret**

<Warning>
  Conservez le Client Secret en lieu sûr et ne le validez jamais dans un système de gestion de versions.
</Warning>

<Warning>
  La connexion Google ne fonctionne pas dans les navigateurs intégrés ni dans les vues web in-app. Les utilisateurs doivent utiliser un navigateur web standard.
</Warning>

<div id="section-2">
  ### Dépannage
</div>

<div id="uri">
  #### URI de redirection non concordant
</div>

* Vérifiez que l&#39;URI de redirection défini dans la Google Cloud Console correspond exactement à la valeur affichée dans **Provider setup**, dans le **volet Auth**
* Assurez-vous qu&#39;il n&#39;y a pas de barre oblique finale ni de faute de frappe
* Patientez quelques minutes, le temps que la configuration Google soit prise en compte

<div id="section-3">
  #### Client non valide
</div>

* Vérifiez que le Client ID et le secret client ont été correctement copiés
* Vérifiez qu&#39;il n&#39;y a pas d&#39;espaces superflus
* Vérifiez que l&#39;écran de consentement OAuth est configuré

<div id="section-4">
  #### Ne fonctionne pas avec un domaine personnalisé
</div>

* Ajoutez les entrées de domaine personnalisé affichées dans **Provider setup** du **volet Auth** à la fois dans Authorized JavaScript origins et dans Authorized redirect URIs

<div id="github">
  ## GitHub
</div>

Ce guide explique comment créer une application OAuth GitHub dans les paramètres développeur de GitHub. Récupérez le **Client ID** et le **Client Secret**, puis saisissez-les dans le **volet Auth**.

Prérequis : un [compte GitHub](https://github.com).

<div id="1-github-oauth">
  ### Étape 1 : créer une application OAuth GitHub
</div>

1. Accédez à [GitHub Developer Settings](https://github.com/settings/developers)
2. Dans la barre latérale, sélectionnez **OAuth Apps**
3. Sélectionnez **New OAuth App**
4. Renseignez les informations de l’application.

**Application name :**

Saisissez le nom de l’application.

**Homepage URL** et **Authorization callback URL :**

Définissez ces deux valeurs exactement comme elles apparaissent dans la section **Provider setup** du **volet Auth**. Pour savoir comment trouver ces valeurs, consultez [Configurer des identifiants OAuth pour un fournisseur SSO](/fr/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

5. Sélectionnez **Register application**

<div id="2">
  ### Étape 2 : générer les identifiants client
</div>

1. Le **Client ID** s&#39;affiche sur la page de configuration de votre application : copiez-le
2. Sélectionnez **Generate a new client secret**
3. Copiez immédiatement le **Client Secret**

<Warning>
  Conservez le Client Secret en lieu sûr. Il ne sera plus affiché une fois que vous aurez quitté cette page. Si vous le perdez, vous devrez en générer un nouveau.
</Warning>

<div id="section-5">
  ### Dépannage
</div>

<div id="uri-2">
  #### URI de redirection non concordant
</div>

* Assurez-vous que l’URL de rappel d’autorisation correspond exactement à la valeur affichée dans **Provider setup** du **volet Auth**
* Vérifiez qu’elle ne contient aucune faute de frappe ni erreur de protocole
* N’ajoutez pas de barre oblique à la fin

<div id="section-6">
  #### Client non valide
</div>

* Vérifiez que le Client ID et le Client Secret ont bien été copiés correctement
* Assurez-vous qu&#39;aucun espace superflu ne s&#39;est glissé lors du collage

<div id="section-7">
  #### Ne fonctionne pas avec un domaine personnalisé
</div>

* Mettez à jour les champs Homepage URL et Authorization callback URL avec les valeurs du domaine personnalisé affichées dans **Provider setup**, dans le **volet Auth**

<div id="apple">
  ## Apple
</div>

Ce guide explique comment créer l’Apple App ID, le Services ID et la Private Key nécessaires pour Sign in with Apple. Récupérez les valeurs **Team ID**, **Services ID**, **Key ID** et **Private Key**, puis saisissez-les dans le **volet Auth**.

Prérequis : un [compte Apple Developer](https://developer.apple.com/account) (inscription à l’Apple Developer Program requise).

<div id="1-apple-app-id">
  ### Étape 1 : créer un App ID Apple
</div>

1. Rendez-vous sur le [portail Apple Developer](https://developer.apple.com/account)
2. Depuis **Certificates, IDs &amp; Profiles**, allez dans **Identifiers**
3. Sélectionnez **App IDs** dans la liste déroulante
4. Sélectionnez l&#39;icône **+** pour enregistrer un nouvel identifiant
5. Sélectionnez **App IDs**, puis **Continue**
6. Sélectionnez **App**, puis **Continue**
7. Saisissez les informations suivantes :
   * **Description** : le nom de l&#39;App ID
   * **Bundle ID** : un identifiant unique
8. Dans Capabilities, activez **Sign In with Apple**
9. Sélectionnez **Continue**, puis **Register**
10. Notez l&#39;**App ID Prefix** (affiché en haut de la page) : il s&#39;agit de votre **Team ID**

<div id="2-apple-services-id">
  ### Étape 2 : créer un Services ID Apple
</div>

1. Sur la page Identifiers, sélectionnez **Services IDs** dans la liste déroulante
2. Sélectionnez **+** pour enregistrer un nouvel identifiant
3. Sélectionnez **Services IDs**, puis **Continue**
4. Renseignez les informations suivantes :
   * **Description** : le nom du Services ID
   * **Identifier** : un identifiant unique (conservez-le, c&#39;est votre **Services ID**)
5. Sélectionnez **Continue**, puis **Register**

<div id="services-id">
  #### Configurer le Services ID
</div>

1. Sélectionnez le Services ID que vous avez créé
2. Activez **Sign In with Apple**
3. Sélectionnez **Configure**
4. Renseignez les éléments suivants :

   * **Primary App ID** : sélectionnez l&#39;App ID créé à l&#39;étape 1
   * **Domains and Subdomains** : copiez la valeur affichée sous **Provider setup** dans le **volet Auth** (sans le préfixe de protocole `https://`)
   * **Return URLs** : copiez la valeur affichée sous **Provider setup** dans le **volet Auth**

   Pour savoir où trouver ces valeurs, consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Sélectionnez **Next**, **Done**, **Continue**, puis **Save**

<div id="3-apple-private-key">
  ### Étape 3 : créer une clé privée Apple
</div>

1. Sélectionnez **Keys** dans la barre latérale du portail Apple Developer
2. Sélectionnez **+** pour créer une nouvelle clé
3. Saisissez le **Key Name**
4. Activez **Sign In with Apple**
5. Sélectionnez **Configure**, puis l’App ID créé à l’étape 1
6. Sélectionnez successivement **Save**, **Continue** et **Register**
7. Notez le **Key ID**
8. Téléchargez le fichier de clé privée (.p8) en sélectionnant **Download**

<Warning>
  La clé privée ne peut être téléchargée qu’une seule fois. Conservez-la en lieu sûr. Vous ne pourrez pas la télécharger à nouveau.
</Warning>

<div id="4-apple-private-email-relay">
  ### Étape 4 : configurer Apple Private Email Relay
</div>

La fonctionnalité Hide My Email d&#39;Apple permet aux utilisateurs de se connecter sans divulguer leur véritable adresse e-mail. Pour pouvoir envoyer des e-mails à ces utilisateurs, vous devez enregistrer une source d&#39;envoi.

1. Dans la barre latérale du portail Apple Developer, sélectionnez **Services**
2. Sous **Sign in with Apple for Email Communication**, sélectionnez **Configure**
3. Sélectionnez **+** pour ajouter une Email Source
4. Saisissez la valeur Email Source affichée dans **Provider setup** du **volet Auth**
5. Sélectionnez **Next**, **Register**, puis **Done**
6. Attendez la validation DNS (icône de coche verte)

<Info>
  Dans certaines régions (Chine, Inde, etc.), un identifiant Apple peut être associé à un numéro de téléphone plutôt qu&#39;à une adresse e-mail. Si votre application exige une adresse e-mail pour tous les utilisateurs, Sign in with Apple risque d&#39;échouer pour les utilisateurs de ces régions.
</Info>

<div id="section-8">
  ### Dépannage
</div>

<div id="section-9">
  #### Client non valide
</div>

* Vérifiez que toutes les informations d&#39;authentification sont saisies correctement
* Vérifiez que la Private Key contient bien les lignes BEGIN et END
* Vérifiez que le Services ID est correctement configuré

<div id="uri-3">
  #### URI de redirection non valide
</div>

* Vérifiez que l’URL de retour dans les paramètres de l’identifiant de service Apple correspond exactement à la valeur affichée dans la **Provider setup** du **volet Auth**
* Vérifiez que le domaine dans Domains and Subdomains correspond au domaine publié (sans `https://`)

<div id="section-10">
  #### Le relais d’e-mails ne fonctionne pas
</div>

* Dans le portail Apple Developer, vérifiez qu’une coche verte s’affiche pour Email Source
* Si vous l’avez ajouté récemment, attendez la propagation des DNS

<div id="section-11">
  #### Ne fonctionne pas avec un domaine personnalisé
</div>

* Ajoutez l’entrée correspondant au domaine personnalisé affichée dans **Provider setup** du **volet Auth** aux champs Domains and Subdomains (sans `https://`) et Return URLs

<div id="x-twitter">
  ## X (Twitter)
</div>

Ce guide explique comment créer une application OAuth X dans le portail développeur de X. Récupérez le **Client ID** et le **Client Secret**, puis saisissez-les dans le **volet Auth**.

Prérequis : un [compte développeur X](https://developer.twitter.com/) (offre gratuite disponible).

<div id="1-x-developer">
  ### Étape 1 : Configurer l’application X Developer
</div>

<div id="section-13">
  #### Créer un compte développeur (si nécessaire)
</div>

1. Accédez au [portail développeur de X](https://developer.twitter.com/en/portal/dashboard)
2. Si vous n&#39;avez pas encore de compte, demandez à créer un compte développeur
3. Remplissez le formulaire de demande en indiquant votre cas d&#39;utilisation

<div id="section-14">
  #### Créer ou sélectionner une application
</div>

1. Accédez à **Projects &amp; Apps** dans le portail développeur X
2. Utilisez une application existante ou sélectionnez **Add App**
3. Saisissez le nom de l’application, puis sélectionnez **Next**
4. Sélectionnez **App settings**

<div id="2-2">
  ### Étape 2 : Configurer l’authentification
</div>

1. Faites défiler jusqu’à **User authentication settings**
2. Sélectionnez **Set up**

**App permissions:**

Sélectionnez le niveau d’autorisation minimal.

* **Read** - nécessaire pour accéder au profil utilisateur (minimum)
* **Write** - si vous publiez au nom des utilisateurs (facultatif)
* **Direct Messages** - si vous avez besoin d’accéder aux messages privés (facultatif)

<Warning>
  Les autorisations doivent correspondre aux portées demandées. Si l’application demande `tweet.write`, mais que seul Read est activé, l’authentification échouera.
</Warning>

**Type of app:**

Sélectionnez **Web App, Automated App or Bot**

**App info:**

* **Callback URI / Redirect URL**: copiez la valeur affichée dans **Provider setup** du **volet Auth**
* **Website URL**: copiez la valeur affichée dans **Provider setup** du **volet Auth**

Pour savoir comment trouver ces valeurs, consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/ja/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

3. Sélectionnez **Save**
4. **Enregistrez le Client ID et le Client Secret**

<Warning>
  Conservez le Client Secret en lieu sûr. Si vous le perdez, sa régénération invalidera l’ancien.
</Warning>

<div id="section-15">
  ### Dépannage
</div>

<div id="uri-4">
  #### URI de redirection non concordant
</div>

* Vérifiez que l’URI de rappel correspond exactement à la valeur affichée dans **Provider setup** du **volet Auth**
* Vérifiez qu’il n’y a pas de faute de frappe ni d’erreur dans le protocole
* N’ajoutez pas de barre oblique finale

<div id="section-16">
  #### Client non valide
</div>

* Vérifiez à nouveau le Client ID et le Client Secret
* Vérifiez qu’ils ne contiennent pas d’espaces superflus
* Vérifiez que vous utilisez des identifiants OAuth 2.0 (et non OAuth 1.0a)

<div id="section-17">
  #### Erreurs de portée/d’autorisation
</div>

* Vérifiez que les portées correspondent aux autorisations activées dans le portail X Developer
* Vérifiez qu’au moins l’autorisation Read est activée

<div id="section-18">
  #### L’application est en mode développement
</div>

* Les applications X démarrent en mode développement avec un nombre limité d’utilisateurs
* Vous devrez peut-être demander un accès étendu pour une utilisation en production

<div id="section-19">
  #### Ne fonctionne pas avec un domaine personnalisé
</div>

* Remplacez l’URL du site web et l’URI de rappel par les valeurs du domaine personnalisé affichées dans **Provider setup** du **volet Auth**
