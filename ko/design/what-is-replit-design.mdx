Replit Design은 소프트웨어의 모양과 사용 경험을 다듬는 공간입니다. 원하는 바를 설명하면 Replit Design이 직접 살펴보고 다듬을 수 있는 인터랙티브 mockup을 생성합니다. 마음에 드는 결과가 나오면 같은 project 안에서 실제로 작동하는 app이 됩니다.

<div id="start-fresh-or-import-existing-designs">
  ## 새로 시작하거나 기존 디자인 가져오기
</div>

[Replit Design](https://replit.com/design)에서 시작하거나, workspace 홈의 생성 입력창 아래에 있는 **Design**을 선택하세요. 시작하는 방법은 네 가지입니다.

* **[프롬프트](/ko/design/design-your-first-screen)**: 원하는 내용을 설명해 첫 frame을 생성합니다.
* **[Templates](/ko/design/start-from-a-template)**: 미리 만들어진 landing page, 포스터, 소셜 게시물, 모바일 화면, 프로토타입으로 시작한 뒤 remix합니다.
* **[Import](/ko/design/import-figma-designs-into-replit-design)**: Figma나 [Claude](/ko/design/import-claude-designs-into-replit-design)에서 디자인을 가져오거나, [URL](/ko/design/import-a-website-into-replit-design) 또는 스크린샷으로 사이트를 재현합니다.
* **[Design system](/ko/design/design-systems-explained)**: 저장해 둔 시스템으로 시작하면 첫 frame부터 브랜드에 맞는 디자인이 나옵니다.

<div id="explore-variants">
  ## 변형 탐색하기
</div>

확정하기 전에 폭넓게 살펴보세요. 모든 결과가 새로운 frame으로 만들어지므로 어떤 direction도 사라지지 않습니다.

* **[Suggestions](/ko/design/explore-suggestions)**: frame을 선택하면 Replit Design이 다음에 시도해 볼 만한 것을 제안하며, 각각 클릭 한 번으로 적용됩니다.
* **[다른 model](/ko/design/explore-with-different-models)**: Design을 구동하는 model을 바꾼 뒤 동일한 brief를 보내 확연히 다른 direction을 얻어 보세요.

<div id="refine">
  ## 다듬기
</div>

가장 마음에 드는 결과물을 편한 방식으로 다듬어 보세요:

* **[Chat](/ko/design/chat-about-your-design)**: board 전체 또는 frame 하나씩, 직접 원하는 대로 Agent에게 brief를 전달하세요.
* **[Visual Editor](/ko/design/visual-editor)**: 원하는 요소를 클릭해 텍스트, 색상, spacing, 이미지를 직접 조정하세요. 간단한 편집은 credits 소모 없이 소스 코드에 바로 반영됩니다.
* **[Draw](/ko/design/toolbar#draw)**: 문제가 있는 부분에 동그라미를 치고, 가리키려는 요소에 화살표를 그리고, 메모를 남겨보세요. Agent가 이 표시를 읽어 들입니다.
* **[assets 생성](/ko/design/toolbar#generate)**: 디자인에 필요한 이미지, 동영상 클립, 벡터 그래픽을 만들어 보세요. 참조 자료를 첨부하면 project의 분위기에 맞게 생성됩니다.

<div id="build">
  ## Build
</div>

frame이 원하는 대로 완성됐다면 Agent에게 넘기세요. 여기서 Design은 단순한 그림이 아니라 실제 소프트웨어를 만드는 spec입니다.

* **[디자인 빌드하기](/ko/design/build-your-design)**: frame을 실제로 동작하는 새 앱으로 만듭니다.
* **[기존 앱 스타일 변경하기](/ko/design/frames#build)**: 이미 사용 중인 앱에 frame의 스타일을 적용합니다.

<div id="scale">
  ## 확장
</div>

다음 디자인은 이전보다 더 빠르게 만들어 보세요:

* **[design system 만들기](/ko/design/create-a-design-system)**: 마음에 드는 디자인에서 color, typography, token, 컴포넌트를 추출하거나 프롬프트로 처음부터 만들어 보세요.
* **이를 기반으로 새 작업 시작하기**: 새로운 artifact가 첫 frame부터 on brand하게 생성됩니다.
* **[기존 앱에 시스템 적용하기](/ko/design/apply-design-system)**: 이미 만들어 둔 앱의 스타일을 다시 구성해 전체를 통일하세요.
* **시스템 전환하기**: project마다 시스템을 선택하거나 변경할 수 있습니다.

여기서 여정은 다시 **시작**으로 이어지고, 이제 모든 디자인이 on brand하게 출발합니다.

<div id="when-to-start-in-design-vs-build">
  ## Design과 Build 중 어디서 시작할까
</div>

Design과 Build는 같은 project로 들어가는 두 가지 진입점입니다. Build는 Agent가 소프트웨어를 실제로 동작하게 만드는 곳이고, Design은 그 모습을 다듬는 곳입니다. Design에서 만든 결과물이 디자인 도구 안에 갇히는 일은 없습니다.

* 겉모습이 어려운 부분이라면 **Design**에서 시작하세요. 여러 direction을 먼저 살펴본 뒤, 가장 마음에 드는 것을 build하면 됩니다.
* 동작이 어려운 부분이라면 **Build**에서 시작하세요. 먼저 동작하게 만든 다음, Replit Design에서 스타일을 새로 입히면 됩니다.
