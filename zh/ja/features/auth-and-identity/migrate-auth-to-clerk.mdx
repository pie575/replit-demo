---
title: "从 Replit Auth 迁移到 Clerk"
description: "使用 Agent 将现有的 Replit Auth 应用迁移到 Clerk Auth，同时保留应用的用户数据。"
---

使用本指南，将现有的 [Replit Auth](/zh/ja/features/auth-and-identity/authentication) 应用迁移到 [Clerk Auth](/zh/ja/features/auth-and-identity/clerk-auth)。Agent 会处理应用迁移，因此现有用户仍可继续访问自己的数据。

<Note>
  此自动迁移适用于使用 Replit Auth 的应用。如果你的应用使用其他身份验证系统，请勿使用此流程。
</Note>

<div id="section">
  ## 开始迁移
</div>

Agent 迁移必须始终在新任务中执行。

你可以通过以下任一方式启动迁移：

<div id="section-2">
  ### 查看迁移方案
</div>

无论从哪种方式开始，Agent 都会创建一个 **Migrate from Replit Auth to Clerk** 任务并准备迁移方案。在该任务继续执行之前，请选择 **View plan** 查看方案。

<Frame caption="Migrate from Replit Auth to Clerk 任务会以 View plan 操作开始，便于你查看迁移手册。">
  <img src="/assets/mirror/replit-auth-to-clerk-task-998d61b55c3d.png" alt="名为 Migrate from Replit Auth to Clerk 的 Agent 任务，显示 View plan 按钮和迁移手册的审阅工作" width="575" height="900" data-path="images/workspace/auth/replit-auth-to-clerk-task.png" />
</Frame>

在 Agent 工作期间，请勿修改应用的认证代码或 Clerk 凭据。

<div id="agent-2">
  ## Agent 会做什么
</div>

Agent 会按以下顺序完成迁移：

1. 将 Replit Auth 的用户数据 (包括账户身份信息和受支持的登录凭据) 迁移到 Clerk。
2. 在修改应用之前，等待数据迁移完成。
3. 更新应用的登录和会话逻辑，重启应用，并运行可用的自动检查。

<div id="section-3">
  ## 应用数据将保持不变
</div>

Agent 仅会修改应用的认证代码。应用现有的数据库数据和架构不会被更新。表和关系将保持不变。

现有用户仍会关联到其已有的记录，包括个人资料、已保存的工作内容和权限等。

<div id="section-4">
  ## 所需时间
</div>

预计 Agent 完成这项工作需要 10 分钟到 1 小时。数据迁移本身，小型应用可能只需几分钟；而用户数量较多的应用最多可能需要数小时。在数据迁移完成之前，Agent 不会开始修改应用代码。

<div id="section-5">
  ## 迁移后
</div>

发布前，请在 Development 中测试更新后的应用。

1. 使用现有账户登录，并确认能够访问已保存的数据。
2. 登出后重新登录。
3. 创建新的测试账户，并确认能够按预期使用应用。
