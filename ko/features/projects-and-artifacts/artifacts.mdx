<div id="what-are-artifacts">
  ## artifact란?
</div>

artifact는 Replit에서 게시할 수 있는 결과물로, web apps, mobile apps, slide decks, 애니메이션, 데이터 앱, 3D 게임, designs 등이 여기에 해당합니다. 각 artifact는 그 자체로 완결된 독립 결과물이며, 게시하면 고유한 shareable URL이 생성됩니다.

project 안의 나머지 요소(파일, 이미지, CSV, 코드)는 artifact를 구성하는 데 쓰일 뿐, 단독으로는 게시할 수 없습니다.

<div id="getting-started">
  ## 시작하기
</div>

Replit 홈페이지에서 만드는 방법은 두 가지입니다.

* **설명하기**: &quot;레시피 앱을 만들어줘&quot; 또는 &quot;우리 스타트업 pitch deck을 만들어줘&quot;처럼 원하는 것을 입력하세요. Agent가 어떤 유형이 적합한지 판단해 만들어 줍니다.
* **유형 선택하기**: 아이디어를 설명하기 전에 원하는 artifact를 먼저 선택하세요. Web app, Mobile app, Data Visualization, Animation, 3D 게임 등 지원되는 유형 중에서 고를 수 있습니다.

기존 project에도 언제든지 chat에서 Agent에게 요청하거나 preview panel의 **+** 버튼을 클릭해 더 추가할 수 있습니다.

<div id="switching-between-artifacts">
  ## artifact 간 전환
</div>

project에 artifact가 여러 개 있으면 **preview panel** 또는 **Library sidebar**에서 서로 전환할 수 있습니다. Agent에게 &quot;mobile app을 보여줘&quot; 또는 &quot;slides로 전환해줘&quot;라고 요청해도 됩니다.

<div id="library-sidebar">
  ### Library sidebar
</div>

Library sidebar는 project 안의 모든 항목을 한곳에서 둘러볼 수 있는 공간입니다. artifact, Agent가 생성하거나 다운로드한 이미지, 그 밖의 project asset이 모두 표시됩니다. 왼쪽 패널에서 Library sidebar를 열면 project 전체의 asset을 찾아 재사용할 수 있습니다.

<div id="multiple-artifacts-in-one-project">
  ## 하나의 project에 여러 artifact 담기
</div>

하나의 project에는 최대 **artifact 7개**를 담을 수 있으며, **mobile app은 project당 최대 1개**까지 가능합니다. 예를 들어 고객용 web app, 팀을 위한 mobile app, 투자자용 slide deck을 모두 하나의 project 안에서 만들 수 있습니다.

<ArtifactGrid />

<div id="adding-artifacts-to-a-project">
  ### project에 artifact 추가하기
</div>

기존 project에 artifact를 추가하는 방법은 세 가지입니다:

* **Chat**: Agent에게 &quot;이 project에 mobile app을 추가해 줘&quot; 또는 &quot;투자 피치용 slide deck을 만들어 줘&quot;와 같이 요청하세요
* **더하기 버튼**: preview panel에서 **+** 버튼을 클릭한 후 만들 항목을 선택하세요
* **Library sidebar**: 기존 artifact, 이미지, 기타 asset을 둘러보고 여기에서 새 artifact를 추가하세요

<div id="shared-data-and-backend">
  ### 공유 데이터 및 backend
</div>

artifact가 같은 project 안에 있으면 데이터와 backend 로직이 자동으로 공유됩니다. 고객이 web app에서 주문을 넣으면 mobile app과 data dashboard에서도 그 주문이 그대로 보입니다. 별도로 연결을 설정하거나 코드를 중복해서 작성할 필요 없이 바로 작동합니다.

<Note>
  Publishing하면 project 전체가 한 번에 라이브로 전환됩니다. 모든 artifact가 함께 라이브 상태가 되므로 항상 동기화가 유지됩니다.
</Note>

<div id="example-combinations">
  ### 조합 예시
</div>

* **Web app + mobile app**: 고객용 web app과 직원용 mobile app을 모두 갖춘 레스토랑 — 두 앱 모두 동일한 API와 database에 연결
* **App + admin dashboard**: 콘텐츠, 사용자, 설정을 관리하는 내부 관리자 패널을 주요 제품과 함께 운영
* **App + slide deck**: 제품과 pitch deck을 같은 project에 두어 slides가 항상 최신 버전을 반영하도록 유지
* **Data dashboard + 동영상**: 실시간 data visualization과 핵심 내용을 짚어주는 애니메이션 동영상의 조합

<div id="publishing">
  ## Publishing
</div>

앱, 슬라이드, 비디오는 모두 게시하고 공유할 수 있습니다. 게시하면 각각 고유한 shareable URL이 생성됩니다.

artifact가 아닌 파일과 assets(예: CSV, 이미지, 마크다운 파일)는 단독으로 게시할 수 없습니다. 공유하려면 앱에 추가하거나 새 artifact를 만드세요.

<div id="frequently-asked-questions">
  ## 자주 묻는 질문
</div>

<Accordion title="한 project에 artifact를 여러 개 둘 수 있나요?">
  네. 하나의 project에는 **artifact를 최대 7개**까지 둘 수 있으며, **mobile app은 project당 1개**로 제한됩니다. project 내 모든 artifact는 동일한 backend와 데이터를 자동으로 공유합니다.

  mobile app 한도에 도달한 상태에서 두 번째 mobile app을 만들고 싶다면 새 project에서 생성하세요. artifact 7개 한도에 도달했다면 기존 artifact를 하나 삭제한 뒤 추가하거나, 작업을 여러 project로 나누세요.
</Accordion>

<Accordion title="시작하기 전에 유형을 먼저 선택해야 하나요?">
  아니요. 원하는 것을 설명하기만 하면 Agent가 알맞은 유형을 골라 줍니다. 원한다면 드롭다운에서 직접 유형을 선택할 수도 있습니다.
</Accordion>

<Accordion title="project에서 artifact 하나만 게시할 수 있나요?">
  현재는 불가능합니다. Publishing은 project 전체를 한 번에 라이브로 배포하므로 모든 artifact가 동기화된 상태로 유지됩니다. 개별적으로 게시해야 한다면 project를 분리하세요.
</Accordion>

<Accordion title="artifact끼리 데이터를 공유하나요?">
  네. project 내 모든 artifact는 동일한 database와 backend 서비스를 공유합니다. web app이 데이터를 기록하면 mobile app과 data dashboard에서 곧바로 그 데이터를 읽을 수 있습니다.
</Accordion>

<Accordion title="artifact와 파일의 차이는 무엇인가요?">
  artifact는 앱, slides, 동영상처럼 게시할 수 있는 결과물입니다. 파일(CSV, 이미지, 코드 등)은 artifact를 뒷받침하는 project 내 assets이지만 그 자체로는 게시할 수 없습니다.
</Accordion>

<Accordion title="mobile app에 web app의 기능 일부가 빠져 있습니다. 왜 그런가요?">
  Agent가 artifact 유형 간에 기능을 옮길 때 일부 요소는 완벽하게 반영되지 않을 수 있습니다. 특히 플랫폼마다 동작 방식이 다른 상호작용이나 layouts이 그렇습니다. chat에서 추가로 요청해 빠진 부분을 채울 수 있습니다.
</Accordion>
