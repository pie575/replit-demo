Тип развёртывания — это технология, с помощью которой Replit публикует ваше приложение. Выбрать его можно в инструменте Publishing, в разделе **Adjust settings**, в выпадающем списке **Deployment type**. Вариант **Autoscale** используется по умолчанию и является рекомендуемым — большинству авторов менять его не приходится.

<div id="comparar-tipos-de-deployment">
  ## Сравнение типов развёртывания
</div>

| Тип             | Подходит для                                        | Как работает                                                                | Как тарифицируется                               |
| :-------------- | :-------------------------------------------------- | :-------------------------------------------------------------------------- | :----------------------------------------------- |
| **Autoscale**   | Веб-приложения и API с переменным трафиком          | Добавляет серверы при высокой нагрузке и масштабируется до нуля при простое | Вы платите, пока обрабатываются запросы          |
| **Static**      | Лендинги, портфолио, сайты документации             | Отдаёт файлы с кеширующего облачного сервера, без бэкенда                   | Вы платите только за данные, которые отдаёт сайт |
| **Reserved VM** | Боты, фоновые задачи, всегда доступные API          | Выделенный сервер, который никогда не засыпает                              | Фиксированная ежемесячная стоимость              |
| **Scheduled**   | Периодические задачи: резервные копии и уведомления | Выполняет команду по расписанию и затем останавливается                     | Вы платите за длительность каждого запуска       |

<div id="autoscale">
  ## Autoscale
</div>

Развёртывания Autoscale работают на серверах, которые масштабируются вверх и вниз вместе с трафиком вашего приложения. Когда приложение под нагрузкой, Replit добавляет серверы, чтобы с ней справиться. Когда оно простаивает, их количество снижается вплоть до нуля, поэтому вы не платите за периоды затишья.

Идеально подходит для:

* веб-приложений с переменным трафиком, например интернет-магазинов;
* API и сервисов.

Настройки задаются в разделе **Adjust settings**: [мощность машины и максимальное количество серверов](/ru/pt/features/publishing/machine-configuration).

<div id="static">
  ## Static
</div>

Static Deployments размещают файлы вашего приложения — HTML, CSS и JavaScript — на облачном сервере, который кеширует контент и отдаёт его быстро и экономично. Бэкенд-сервера нет.

Идеально подходит для:

* маркетинговых лендингов
* сайтов-портфолио
* сайтов с документацией продуктов и API

<Note>
  Static Deployments не подходят для Replit Apps, созданных с помощью Agent. Agent создаёт полностековые приложения, которым нужен бэкенд-сервер, поэтому в таких случаях используйте Autoscale или Reserved VM.
</Note>

Конфигурация включает публичный каталог для раздачи и необязательную команду сборки. О заголовках ответа, перезаписи URL и перенаправлениях читайте в разделе [расширенная конфигурация Static](/ru/pt/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Развёртывания Reserved VM запускают ваше приложение на выделенной виртуальной машине, которая никогда не засыпает. Вы получаете стабильную производительность и фиксированную предсказуемую ежемесячную стоимость.

Идеально подходит для:

* фоновых задач, требовательных к памяти;
* чат-ботов, которым нужно постоянно оставаться на связи;
* всегда активных API-серверов.

Настройка включает [мощность машины](/ru/pt/features/publishing/machine-configuration), команды сборки и запуска, сопоставление портов, а также выбор режима работы приложения — веб-сервер или фоновый обработчик.

<div id="scheduled">
  ## Scheduled
</div>

Scheduled Deployments выполняют команду по расписанию в среде вашего приложения, а затем останавливаются до следующего запуска. Опишите расписание простым языком, например «каждый будний день в 9:00», и Replit автоматически превратит его в расписание. Если запуск завершится с ошибкой, вы получите оповещение.

Подходит для:

* проверок статуса и отчётов о работоспособности;
* отправки уведомлений;
* запуска резервного копирования.

Настройка включает расписание, таймаут задания, а также команды сборки и запуска. Scheduled Deployments не обслуживают веб-страницу, поэтому у них нет публичного URL.
