Un système de design fournit à Agent les informations nécessaires pour créer une UI conforme à votre marque dans tout ce que votre organisation crée sur Replit (applications web, applications mobiles, diapositives et autres artefacts). En configurant une bibliothèque de composants, des jetons de design, des ressources de marque et des règles d’utilisation dans le monorepo pnpm standard de Replit, Agent applique votre langage visuel dès le premier prompt.

<Note>
  Les systèmes de design sont disponibles uniquement avec le plan **Enterprise**. Seuls les administrateurs de l’organisation peuvent configurer et gérer les systèmes de design.
</Note>

<div id="section">
  ## Pourquoi configurer un système de design
</div>

Sans système de design, chaque créateur doit décrire manuellement à Agent la bibliothèque de composants, les jetons de couleur et les règles de mise en page. Configurer un système de design résout ce problème de la manière suivante :

* **Encodage des standards visuels** : Agent utilise les composants, couleurs et espacements exacts plutôt que des valeurs par défaut génériques.
* **Cohérence garantie** : toutes les applications suivent le même langage de design.
* **Intégration accélérée** : les nouveaux créateurs produisent immédiatement des résultats conformes à la marque.
* **Capture des connaissances implicites** : les décisions de design et les habitudes d&#39;utilisation des composants que les membres de l&#39;équipe ont en tête sont documentées à l&#39;intention d&#39;Agent.

<div id="section-2">
  ## Éléments nécessaires
</div>

* Une bibliothèque de composants de code frontend empaquetée dans un fichier tar ou un ensemble de fichiers tar
* Les polices et icônes utilisées dans le système de conception
* De la documentation IA sur le système de conception (MCP, Compétences Agent)

<div id="section-3">
  ## Éléments configurables
</div>

La configuration du système de design comprend trois parties :

1. **Instructions personnalisées**. Le fichier `custom_instruction/instructions.md` fournit à Agent les règles générales qui s&#39;appliquent à tous les projets : bibliothèque de composants à utiliser, jetons de design à référencer, modèles à suivre. Agent a toujours ce fichier en contexte.

2. **Compétences**. Les compétences placées dans `.agents/skills/` fournissent des ressources de référence détaillées qu&#39;Agent charge en fonction des besoins. Utilisez-les pour la documentation des API de composants, les guides de thème, les bibliothèques de modèles de mise en page et tout autre contenu de référence approfondi trop volumineux pour figurer dans le fichier d&#39;instructions principal.

3. **Ressources de design et de marque**. Placez les logos, icônes, polices et autres ressources de marque dans un dossier dédié (par exemple `src/assets/brand/`). Configurez des alias de chemin Vite afin de pouvoir les référencer par des imports clairs comme `@brand/logo.svg`, ce qui garantit des références cohérentes plutôt que des chemins relatifs fragiles.

<div id="section-4">
  ## Guide étape par étape
</div>

Ce guide vous explique comment configurer un système de design de bout en bout à partir d&#39;une bibliothèque de composants existante empaquetée dans un tarfile :

1. **Créez une nouvelle application Replit** et téléversez le tarfile.
2. **Demandez à Replit Agent d&#39;installer le package et d&#39;afficher tous les composants.** Agent configure le projet et effectue le rendu de la bibliothèque de composants.
3. **Examinez le résultat.** Vérifiez que tous les composants s&#39;affichent correctement et correspondent à vos attentes. Une fois que tout est conforme, passez à [Créer la compétence du système de design](#creating-the-design-system-skill).

<div id="section-5">
  ### Créer une compétence de système de design
</div>

Une fois vos composants prêts, la dernière étape consiste à créer une compétence de système de design pour permettre à Agent de référencer vos composants, jetons et modèles d’utilisation dans tous vos projets.

Copiez l’intégralité du prompt ci-dessous et collez-le dans Agent. Remplacez `<your-design-system-name>` par le nom de votre système de design :

````
Create a `<your-design-system-name>` design system skill from the components and packages in this project.

Use the file structure shown below with a `SKILL.md` at the root, a `references/` directory for guides and component docs, and a `packages/` directory containing all dependencies needed to function.

Go through every component in the project and document each one in its own file under `references/components/`, including its props, variants, and example usage.

Format `SKILL.md` as an index that links out to the guide and component reference files, with a "General Guidance" section and a "Components" section, following the example shown below.

File structure:

.agents/skills/your-design-system/
├── SKILL.md
├── references/
│   ├── guides/
│   │   ├── setup.md
│   │   ├── guardrails.md
│   │   ├── layout-and-spacing.md
│   │   └── ...
│   └── components/
│       ├── component-index.md
│       ├── button.md
│       ├── checkbox.md
│       └── ...
└── packages/
    └── (Tar files or code components)

The `SKILL.md` file acts as an index that links out to separate markdown files for guides and component references. Each linked file covers one topic in detail. Here is an example of what the generated `SKILL.md` looks like:

```markdown
---
name: your-design-system
description: Use when building or modifying any UI. Provides component API references, layout guidance, and visual style rules for your design system.
---

# Your Design System

## General Guidance

- [Setup](references/guides/setup.md) — Installation, project configuration, and provider setup
- [Guardrails](references/guides/guardrails.md) — Hard rules that must never be broken (banned patterns, required tokens, accessibility minimums)
- [Layout & Spacing](references/guides/layout-and-spacing.md) — Grid system, spacing scale, responsive breakpoints, and page templates
- ...

## Components

- [Component Index](references/components/component-index.md) — Full list of available components with status and category

Individual component references (props, variants, examples):

- [Button](references/components/button.md)
- [Checkbox](references/components/checkbox.md)
- ...
```

Guide files cover one topic each — setup and installation steps, best practices and rules, reference tables for token values, and short code examples showing correct usage.

Component files document a single component each, including the component name, a brief description, a props table, usage examples, and any guidelines or constraints. The more complete these files are, the better Agent's output will be.
````

<div id="agent">
  ### Connecter la compétence à Agent
</div>

Une fois la compétence créée, faites en sorte que `custom_instruction/instructions.md` oriente Agent vers celle-ci :

```markdown theme={null}
# Design System

Lisez et suivez la compétence design system située dans `.agents/skills/your-design-system/`.
Appliquez toujours le design system lors de la création ou de la modification de l'UI.
```

Enfin, préremplissez `replit.md` avec le contexte propre à votre système de design afin qu&#39;Agent comprenne vos standards visuels dès le départ. Incluez la présentation du projet, la bibliothèque de composants privilégiée, les principales préférences de design (échelle d&#39;espacement, exigences d&#39;accessibilité) et la pile technique.

<div id="section-6">
  ### Vérifier la configuration
</div>

Avant de déployer votre système de design, vérifiez les éléments essentiels suivants :

* que `custom_instruction/instructions.md` oriente Agent vers la compétence du système de design
* que `.agents/skills/` contient une compétence comprenant des références de composants, des guides et des packages
* que `replit.md` est prérempli avec une présentation du projet, des préférences et l’architecture
* qu’un fichier de tokens de design est inclus (`tokens.css` ou un fichier équivalent)
* que le package du système de design est déjà installé dans `package.json`
* créez une nouvelle application de test pour vérifier qu’Agent utilise correctement le système de design

<div id="section-7">
  ### Épingler un système de design à votre organisation
</div>

Une fois votre système de design prêt, épinglez-le afin que tous les membres de l’organisation puissent l’utiliser :

1. Accédez à l’application de système de design de votre organisation.
2. Ouvrez le menu d’actions de l’application (menu à trois points).
3. Sélectionnez **Pin to Agent input box**.

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Menu d’actions de l’application affichant l’option Pin to Agent input box" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Seuls les administrateurs de l’organisation (membres ayant le rôle `system_admins`) peuvent épingler ou désépingler des systèmes de design.
</Note>

Définissez l’accès des membres sur **Read-only** afin qu’ils puissent consulter et utiliser le système de design épinglé sans le modifier.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Boîte de dialogue d’invitation avec l’accès des membres défini sur Read-only" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Le système de design apparaît désormais sous forme de pastille sélectionnable sous le champ de saisie d’Agent pour tous les membres de l’organisation. Pour le retirer, ouvrez le même menu et sélectionnez **Unpin from Agent input box**.

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Système de design affiché sous forme de pastille sélectionnable dans le champ de saisie d’Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

<div id="section-8">
  ## Maintenir votre design system
</div>

Les design systems évoluent. Gardez le vôtre à jour :

* **Mettez à jour le fichier de tokens** : lorsque de nouvelles valeurs de couleur, d&#39;espacement ou de typographie sont ajoutées au design system
* **Mettez à jour les compétences** : lorsque de nouvelles props, variantes ou méthodes d&#39;utilisation sont ajoutées aux composants
* **Mettez à jour les consignes** : lorsque les principes ou les standards de design changent
* **Mettez à jour la version du paquet** : lors de la sortie d&#39;une nouvelle version du design system
* **Testez régulièrement** : créez de nouvelles applications et vérifiez qu&#39;Agent produit les bons résultats

<div id="vs">
  ## Systèmes de design vs. templates personnalisés
</div>

Les systèmes de design et les [templates personnalisés](/fr/ko/teams/custom-templates) répondent à des objectifs différents :

|                    | Systèmes de design                                                                                    | Templates personnalisés                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Objectif**       | Utiliser la pile front-end de l’équipe et des composants de code                                      | Remplacer entièrement la pile de base (par exemple : Rust, Go, C++)                                                            |
| **Pile**           | Fonctionnent dans le monorepo pnpm standard de Replit                                                 | Définissent une structure de projet entièrement personnalisée                                                                  |
| **Contenu fourni** | Règles de bibliothèque de composants, jetons de design, ressources de marque et compétences visuelles | Boilerplate complet incluant l’environnement d’exécution, la configuration de build, les dépendances et la structure du projet |
| **S’applique à**   | Applications web, applications mobiles, diapositives, artefacts — tout ce qu’Agent construit          | Uniquement les applications créées à partir de ce template spécifique                                                          |

Utilisez un système de design lorsque vous souhaitez qu’Agent respecte des normes visuelles dans toute l’expérience Replit. Utilisez un template personnalisé lorsque vous avez besoin d’une pile fondamentalement différente.
