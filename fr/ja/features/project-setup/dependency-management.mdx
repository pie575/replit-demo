Replit propose plusieurs méthodes pour installer et gérer les paquets de vos applications Replit. Vous pouvez installer des paquets depuis le [Shell](/fr/ja/features/workspace-tools/shell), confier cette tâche à l&#39;[Agent](/fr/ja/features/agent/overview/), ou laisser Replit détecter et installer automatiquement les dépendances manquantes lors de l&#39;exécution de votre application Replit.

<div id="shell">
  ## Installer des paquets avec le Shell
</div>

Ouvrez l&#39;outil **Shell** dans l&#39;éditeur de projet, puis exécutez la commande correspondant au gestionnaire de paquets du langage que vous utilisez :

<CodeGroup>
  ```bash Node.js (npm) theme={null}
  npm install <package-name>
  ```

  ```bash Node.js (pnpm) theme={null}
  pnpm add <package-name>
  ```

  ```bash Python (poetry) theme={null}
  poetry add <package-name>
  ```

  ```bash Python (pip) theme={null}
  pip install <package-name>
  ```

  ```bash Ruby theme={null}
  bundle add <gem-name>
  ```
</CodeGroup>

Vous pouvez également utiliser le [gestionnaire de paquets universel (UPM)](https://github.com/replit/upm/) de Replit pour installer des paquets dans tous les langages pris en charge :

```bash theme={null}
upm add <package-name>
```

Pour installer une version spécifique :

```bash theme={null}
upm add 'flask==2.3.3'
```

Pour connaître l&#39;ensemble des langages et gestionnaires de paquets pris en charge, consultez [UPM : langages pris en charge](https://github.com/replit/upm/#supported-languages).

<div id="agent">
  ## Installer des paquets avec Agent
</div>

Vous pouvez demander directement à [Agent](/fr/ja/features/agent/overview/) d&#39;installer des paquets depuis le chat. Par exemple :

* « Installe le paquet axios »
* « Ajoute Flask et SQLAlchemy au projet »
* « Configure TailwindCSS »

Agent installe les paquets avec le gestionnaire de paquets adapté à votre projet et met à jour les fichiers de configuration concernés.

<div id="section">
  ## Détection automatique des importations
</div>

Replit analyse automatiquement votre code chaque fois que vous sélectionnez **Run** afin de repérer les dépendances manquantes. Si votre code importe un paquet qui n&#39;est pas encore installé, Replit le détecte et en installe automatiquement la version la plus récente.

Par exemple, si vous ajoutez `import flask` dans `main.py`, un message s&#39;affichera dans la **Console** lors de votre prochaine sélection de **Run** pour indiquer que **Flask** est en cours d&#39;installation.

<Note>
  La détection automatique des importations se configure via le paramètre `packager.features.guessImports` du fichier [.replit](/fr/ja/features/project-setup/configuration#replit-file).
</Note>

<div id="section-2">
  ### Remplacer la détection automatique
</div>

Si le paquet détecté n&#39;est pas le bon ou si vous avez besoin d&#39;une version spécifique, exécutez la commande d&#39;installation appropriée dans le Shell. Par exemple :

```bash theme={null}
upm add 'flask==2.3.3'
```

<div id="python">
  ## Gestionnaire de paquets Python
</div>

Lorsque vous créez une application Replit Python, le gestionnaire de paquets par défaut est **poetry**. Autrement dit, `pip install` ne gère pas les dépendances. Utilisez plutôt `poetry add <package>` ou `upm add <package>` dans le Shell.

<div id="poetrypip">
  ### Passer de poetry à pip
</div>

Si vous préférez utiliser `pip`, suivez les étapes ci-dessous :

<Steps>
  <Step>
    Ouvrez le Shell et exécutez :

    Supprimez le fichier de verrouillage afin que l&#39;infrastructure de packaging bascule vers pip :

    ```bash theme={null}
    rm poetry.lock
    ```
  </Step>

  <Step title="Déplacer les dépendances">
    Déplacez les dépendances de la section `[tool.poetry.dependencies]` de `pyproject.toml` vers `requirements.txt`. Par exemple, `flask = "^3.0.2"` devient `flask>=3.0.2,<4`.
  </Step>

  <Step title="Nettoyer pyproject.toml">
    Supprimez les sections `[tool.poetry...]` de `pyproject.toml`.
  </Step>
</Steps>

Une fois ces modifications effectuées, l&#39;infrastructure de packaging utilisera `pip` pour toutes les opérations à venir, et la détection automatique des importations continuera de fonctionner comme prévu.

<div id="nixdependencies">
  ## Dépendances système avec Nix
</div>

Replit prend en charge tous les langages de programmation grâce à son intégration avec [Nix](https://nixos.org/). Si vous avez besoin de dépendances système qui vont au-delà des paquets de langage standards, vous pouvez les ajouter au fichier [replit.nix](/fr/ja/features/project-setup/configuration#replit-nix-file).

<div id="nix">
  ### Paquets Nix
</div>

Modifiez directement `replit.nix` pour ajouter des dépendances système. Vous pouvez rechercher les paquets disponibles sur [search.nixos.org](https://search.nixos.org/packages).

<div id="section-3">
  ### Modules
</div>

Les modules combinent la prise en charge des langages de programmation, des formateurs et des packagers. Ils constituent le socle d&#39;une application Replit. Lorsque vous créez une application Replit à partir d&#39;un modèle ou d&#39;un dépôt GitHub, Replit installe automatiquement les modules nécessaires.

Vous pouvez personnaliser les modules et les autres paramètres Nix à l&#39;aide du fichier [.replit](/fr/ja/features/project-setup/configuration#replit-file).

<div id="section-4">
  ## Configuration du packager
</div>

Le fichier [.replit](/fr/ja/features/project-setup/configuration#replit-file) permet d&#39;ajuster finement le comportement de la gestion des paquets :

| Paramètre                             | Description                                                                 | Valeur par défaut     |
| ------------------------------------- | --------------------------------------------------------------------------- | --------------------- |
| `packager.language`                   | Langage utilisé pour les opérations sur les paquets                         | Détection automatique |
| `packager.features.guessImports`      | Détecte et installe automatiquement les paquets manquants à l&#39;exécution | `true`                |
| `packager.features.packageSearch`     | Active la prise en charge de la recherche de paquets                        | `true`                |
| `packager.features.enabledForHosting` | Exige l&#39;installation des paquets lors de l&#39;hébergement              | `false`               |
| `packager.afterInstall`               | Commande à exécuter après l&#39;installation des paquets                    | —                     |
| `packager.ignoredPaths`               | Chemins à ignorer lors de la détection des imports                          | `[]`                  |
| `packager.ignoredPackages`            | Paquets à exclure de la détection automatique                               | `[]`                  |
