## General Agent란 무엇인가요?

General Agent는 Replit Agent와 작업하는 가장 유연한 방법입니다. 아티팩트 유형을 미리 선택하거나 특정한 무언가를 만들겠다고 미리 정할 필요가 없습니다. 그냥 대화를 시작하세요 — CSV를 만들거나, PDF를 생성하거나, 주제를 조사하거나, 준비가 되면 완전한 앱을 빌드할 수도 있습니다.

주요 개념:

* **사전 선택 불필요**: 아티팩트 유형을 미리 선택하지 않고 바로 작업을 시작
* **어떤 출력물이든**: 파일(CSV, PDF, 문서)을 생성하거나, 리서치를 하거나, 앱을 빌드
* **커넥터**: BigQuery, Linear, Slack, Notion, Amplitude, Segment, Hex 등 외부 서비스를 읽고 쓰기
* **점진적 확장**: 가벼운 채팅으로 시작해서 자연스럽게 완전한 앱 빌드로 확장

## General Agent 접근 방법

다음과 같은 여러 방법으로 General Agent에 접근할 수 있습니다:

1. **프롬프트를 작성하기 전에 "General" 선택** — Replit 홈페이지에서
2. **기존 프로젝트를 열고** Agent와 바로 대화 시작
3. **GitHub에서 [가져오기](/ko/build/import-from-providers)** — GitHub에서 가져온 프로젝트는 자동으로 General Agent를 사용합니다

## General Agent 사용 방법

### 바로 대화 시작하기

프로젝트를 열고 대화를 시작하세요. 특정한 것을 만들겠다고 미리 정할 필요는 없습니다 — Agent는 현재 프로젝트 컨텍스트 내에서 작동하며 무엇이든 처리할 수 있습니다.

**예시 프롬프트:**

* "이 문서의 핵심 내용을 요약해줘"
* "매출 기준 상위 100개 기업의 CSV를 만들어줘"
* "내 Linear 티켓 중 상위 5개는 뭐야?"
* "TypeScript로 Vue.js 프로젝트를 설정해줘"

Agent는 세션 중에 생성된 파일로 작업하고, 단일 파일 출력물을 생성하고, 추론 과정의 일부로 코드를 실행할 수 있습니다 — 무언가를 빌드하기로 결정하기 전에도요.

### 외부 서비스 연결하기

Agent가 데이터를 직접 읽고 쓸 수 있도록 도구를 연결하세요:

1. 프로젝트 설정에서 **커넥터**로 이동
2. 서비스 연결(BigQuery, Linear, Slack, Notion, Amplitude, Segment, Hex 등)
3. Agent에게 해당 서비스를 통해 데이터를 읽거나 쓰도록 요청

**커넥터를 활용한 예시 프롬프트:**

* "Linear에 열려 있는 티켓이 뭐야?"
* "오늘 #engineering의 Slack 메시지를 요약해줘"
* "BigQuery에서 지난달 매출 데이터를 가져와줘"
* "내 캘린더의 다가오는 일정을 보여줘"
* "온보딩 버그에 대한 새 티켓을 Linear에 만들어줘"
* "Slack의 #engineering에 요약본을 보내줘"

### 채팅에서 완전한 앱으로

빌드할 준비가 되면 그냥 말하세요. Agent는 가벼운 채팅에서 앱 빌드로 매끄럽게 전환됩니다 — 처음부터 다시 시작하거나 컨텍스트를 전환할 필요가 없습니다.

* "이걸 웹 앱으로 만들어줘"
* "이 데이터를 기반으로 앱을 만들어줘"
* "이 지표들을 위한 대시보드를 만들어줘"
* "Rust CLI 도구를 설정해줘"

가볍게 시작해서 — 주제를 조사하거나, 리포트를 생성하거나, 데이터를 탐색하고 — 적절한 순간에 완전한 애플리케이션 빌드로 확장할 수 있습니다.

## 만들 수 있는 것

* **지식 작업**: 앱을 빌드하지 않고 리서치, 요약, 분석 수행
* **단일 파일 출력물**: CSV, PDF, 문서, 데이터 내보내기, 서식이 있는 리포트
* **데이터 애플리케이션**: 연결된 서비스를 조회하고 결과를 대시보드로 시각화
* **어떤 프레임워크나 언어든**: Angular, Vue, Svelte, Rust, Go, C#, Python tkinter, Godot 게임, CLI 도구 등
* **풀스택 앱**: 준비가 되면 채팅 컨텍스트를 기반으로 완전한 애플리케이션을 빌드

## 예상할 수 있는 것

General Agent는 더 많은 힘과 유연성을 제공하며, 이는 어느 정도의 가변성을 동반합니다:

* **한 번의 설정**: Agent가 모든 것을 한 번에 구성하는 경우도 있습니다
* **반복적인 협업**: 복잡한 설정에는 여러 차례의 조정이 필요할 수 있습니다
* **기술적 제약**: 일부 기술은 Nix 환경에서 완전히 지원되지 않을 수 있습니다

<Note>
  사전 구성된 환경을 사용하는 표준 Agent와 달리, General Agent는 요청에 따라 자체 환경을 설정하고 명령을 실행합니다. 배포할 준비가 되면 게시(publishing) 설정을 요청해야 할 수도 있습니다.
</Note>

## 자주 묻는 질문

<Accordion title="에이전트가 제 다른 프로젝트를 볼 수 있나요?">
  아닙니다. 각 채팅은 하나의 프로젝트 안에 한정됩니다. 프로젝트 A와 프로젝트 B가 서로 대화하게 할 수는 없습니다.
</Accordion>

<Accordion title="왜 아직 제 외부 도구에 접근할 수 없나요?">
  먼저 커넥터를 통해 서비스를 연결해야 합니다. 연결이 되면 Agent가 해당 서비스를 읽고 쓸 수 있지만, 기본적으로는 접근 권한이 없습니다.
</Accordion>

<Accordion title="어떤 커넥터를 사용할 수 있나요?">
  현재 지원되는 커넥터: BigQuery, Linear, Slack, Notion, Amplitude, Segment, Hex 등. 추가 커넥터가 정기적으로 추가되고 있습니다.
</Accordion>

<Accordion title="General Agent를 사용하려면 커넥터가 필요한가요?">
  아닙니다. 커넥터는 선택 사항입니다. 외부 연결 없이도 General Agent를 지식 작업, 파일 생성, 앱 빌드에 사용할 수 있습니다.
</Accordion>
