</Info>

Коннекторы Databricks позволяют Replit Agent выполнять запросы к вашему workspace Databricks. Разработчики могут создавать дашборды, инструменты отчетности и приложения для работы с данными, используя естественный язык. Знание SQL не требуется.

Replit поддерживает два типа подключения к Databricks. Выберите подходящий в зависимости от того, от чьего имени должен выполняться каждый запрос.

<div id="escolher-um-tipo-de-conexo">
  ## Выберите тип подключения
</div>

|                            | **Пользователь — компьютер (U2M)**                         | **Сервисный принципал (M2M)**                      |
| -------------------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| Имя коннектора в Replit    | Databricks for Databricks Apps (U2M)                       | Databricks (Service Principal)                     |
| Кто выполняет запрос       | Отдельный разработчик                                      | Общий сервисный принципал                          |
| Права доступа Databricks   | Права доступа Unity Catalog каждого разработчика           | Права доступа сервисного принципала                |
| Атрибуция в журнале аудита | Разработчик, выполнивший запрос                            | Сервисный принципал                                |
| Вход разработчика          | Каждый разработчик входит в свою учётную запись Databricks | Индивидуальный вход в Databricks не требуется      |
| Лучше всего подходит для   | Прав доступа на уровне пользователей и аудита              | Общего доступа и неинтерактивных рабочих процессов |

<div id="configurar-o-conector-u2m">
  ## Настройка коннектора U2M
</div>

Для настройки U2M требуются три роли:

1. **Администратор учётной записи Databricks**: создаёт OAuth-подключение приложения и предоставляет сведения о SQL Warehouse.
2. **Администратор организации Replit**: настраивает коннектор с учётными данными OAuth.
3. **Разработчик**: входит в свою учётную запись Databricks и приступает к разработке.

<div id="pr-requisitos-do-u2m">
  ### Предварительные требования U2M
</div>

Перед началом убедитесь, что у вас есть:

* **Администратор учётной записи Databricks**. Подключения приложений настраиваются в консоли учётной записи, а не в настройках администратора workspace.
* Администратор организации Replit.
* Учётная запись Databricks для каждого разработчика, который будет использовать коннектор.
* Доступ к workspace для каждого разработчика, включая разрешение **Can use** для SQL Warehouse и необходимые разрешения Unity Catalog.

<div id="etapa-1-criar-uma-conexo-de-aplicativo-oauth">
  ### Шаг 1: Создайте подключение OAuth-приложения
</div>

<Note>Для выполнения этого шага необходимо быть администратором учётной записи Databricks.</Note>

Администратор учётной записи Databricks регистрирует Replit как OAuth-приложение. Это подключение предоставляет Client ID и Client Secret, необходимые для настройки Replit.

<Steps>
  <Step title="Откройте консоль учётной записи Databricks">
    В Workspace Databricks откройте переключатель Workspace в правом верхнем углу и выберите **Manage account**.

    <Frame>
      <img src="/assets/mirror/manage-account-6374ed6bf0f2.png" alt="Открытый переключатель Workspace Databricks с видимым пунктом Manage account" width="2000" height="1144" data-path="images/connectors/databricks/u2m/manage-account.png" />
    </Frame>
  </Step>

  <Step title="Откройте подключения приложений">
    В консоли учётной записи выберите **Settings**, затем откройте вкладку **App connections**.

    <Frame>
      <img src="/assets/mirror/app-connections-96228e7f0f2e.png" alt="Страница Settings учётной записи Databricks с выбранной вкладкой App connections и видимой кнопкой Add connection" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-connections.png" />
    </Frame>
  </Step>

  <Step title="Настройте подключение Replit">
    Выберите **Add connection**. Введите имя приложения, указывающее на Replit, например `replit-u2m`.

    В поле **Redirect URLs** введите:

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    В разделе **Access scopes** выберите **All APIs**. Это позволит Agent использовать Databricks SQL и API Databricks, необходимые для создания и управления Databricks Apps.

    Выберите **Generate a client secret**. После создания подключения Databricks не позволит добавить к нему секрет.

    Задайте сроки действия токенов в соответствии с политикой безопасности вашей организации. В примере указаны **Access token TTL** — `1440` минут (24 часа) и **Refresh token TTL** — `129600` минут (90 дней): это максимальные значения, отображаемые Databricks. При более коротком сроке действия refresh token разработчикам может потребоваться чаще входить в систему.

    Выберите **Add**.

    <Warning>
      **All APIs** предоставляет более широкий доступ, чем доступ только к SQL. Управляйте фактическим доступом коннектора с помощью разрешений Databricks, назначенных каждому разработчику.
    </Warning>

    <Frame>
      <img src="/assets/mirror/app-configuration-6799b5769326.png" alt="Форма Add connection в Databricks с указанными именем приложения Replit, URL перенаправления, доступом All APIs, созданием client secret и сроками действия токенов" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-configuration.png" />
    </Frame>
  </Step>

  <Step title="Сохраните учётные данные OAuth">
    Скопируйте **Client ID** и **Client Secret** и сохраните их в менеджере секретов вашей организации.

    <Warning>
      Databricks отображает client secret только один раз. Запишите дату истечения срока действия и замените подключение приложения до истечения срока действия секрета.
    </Warning>

    <Frame>
      <img src="/assets/mirror/oauth-credentials-15b2e6c67309.png" alt="Диалоговое окно Databricks Connection created со скрытыми client ID и client secret, предупреждением об однократном отображении секрета и датой истечения срока действия" width="2000" height="1144" data-path="images/connectors/databricks/u2m/oauth-credentials.png" />
    </Frame>
  </Step>
</Steps>

<Note>
  Новые или обновлённые подключения OAuth-приложений могут стать доступными
  в течение 30 минут.
</Note>

<div id="etapa-2-compartilhar-os-detalhes-do-sql-warehouse">
  ### Шаг 2: Предоставьте параметры SQL Warehouse
</div>

Каждый разработчик вводит параметры SQL Warehouse при авторизации коннектора U2M. Разместите эти значения в доступном для разработчиков месте, например на внутренней странице онбординга.

<Steps>
  <Step title="Откройте SQL Warehouses">
    В рабочем пространстве Databricks выберите **SQL Warehouses** и откройте SQL Warehouse, который должны использовать разработчики.

    <Frame>
      <img src="/assets/mirror/sql-warehouses-cc178d18a33b.png" alt="Страница SQL Warehouses в Databricks с доступными SQL Warehouse" width="3438" height="1984" data-path="images/connectors/databricks/sql-warehouses.png" />
    </Frame>
  </Step>

  <Step title="Скопируйте сведения о подключении">
    Выберите **Connection details** и скопируйте **Server hostname** и **HTTP path**.

    <Frame>
      <img src="/assets/mirror/connection-details-938b970b98e6.png" alt="Страница сведений о подключении SQL Warehouse в Databricks с именем хоста сервера и HTTP-путём" width="3438" height="1984" data-path="images/connectors/databricks/connection-details.png" />
    </Frame>
  </Step>
</Steps>

<div id="etapa-3-ativar-o-u2m-no-replit">
  ### Шаг 3: Включите U2M в Replit
</div>

<Note>Чтобы настроить коннекторы, вы должны быть администратором организации Replit.</Note>

<Steps>
  <Step title="Откройте и включите коннектор U2M">
    На главной странице своей учётной записи Replit откройте **Settings**, затем **Integrations**. Найдите `Databricks U2M`, выберите **Databricks for Databricks Apps (U2M)** и нажмите **Enable**.

    Введите **Client ID** и **Client Secret** для подключения приложения Databricks.

    Убедитесь, что URL перенаправления, отображаемый в Replit, соответствует URL, настроенному в Databricks:

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    В разделе **Connector Scopes** включите `all-apis` и `offline_access`. Область действия `offline_access` предоставляет Replit refresh token для длительных сеансов.

    Нажмите **Configure**.

    <Frame>
      <img src="/assets/mirror/enable-connector-39c1eeebd230.png" alt="Настройки интеграций Replit, отфильтрованные по Databricks U2M, с панелью включения, на которой отображаются URL перенаправления, поля учётных данных OAuth и области действия коннектора" width="2000" height="1144" data-path="images/connectors/databricks/u2m/enable-connector.png" />
    </Frame>
  </Step>

  <Step title="Убедитесь, что коннектор включён">
    Убедитесь, что **Databricks for Databricks Apps (U2M)** отображается в разделе **Your integrations**.
  </Step>
</Steps>

<div id="etapa-4-fazer-login-como-desenvolvedor">
  ### Шаг 4: Вход разработчика
</div>

Каждый разработчик входит в систему под своей учётной записью Databricks перед использованием коннектора. Replit может обновлять сеанс, пока не истечёт срок действия refresh token.

<Steps>
  <Step title="Войдите в коннектор">
    На странице **Integrations** найдите **Databricks for Databricks Apps (U2M)** и выберите **Sign in**. Проверьте сведения о подключении и выберите **Continue to Databricks for Databricks Apps**.

    <Frame>
      <img src="/assets/mirror/connect-modal-8ae2c2569658.png" alt="Модальное окно подключения Databricks for Databricks Apps с информацией о перенаправлении, конфиденциальности и настройках разрешений" width="2000" height="1144" data-path="images/connectors/databricks/u2m/connect-modal.png" />
    </Frame>
  </Step>

  <Step title="Введите данные SQL Warehouse">
    Введите **HTTP path** SQL Warehouse, предоставленный администратором Databricks, и выберите **Next**.

    <Frame>
      <img src="/assets/mirror/http-path-9e8a8a14b6ab.png" alt="Диалоговое окно подключения Databricks for Databricks Apps с запросом HTTP-пути SQL Warehouse на шаге 1 из 2" width="2000" height="1144" data-path="images/connectors/databricks/u2m/http-path.png" />
    </Frame>

    Затем Replit запросит **Server hostname** SQL Warehouse. Введите его и перейдите в Databricks. При появлении запроса войдите в систему, проверьте запрашиваемый доступ и подтвердите запрос.

    Каждый запрос, который Agent выполняет через это подключение, использует ваши разрешения Databricks и регистрируется в журналах аудита Databricks как выполненный вами.

    После подтверждения Databricks перенаправит вас обратно в Replit, и коннектор будет готов к использованию.
  </Step>
</Steps>

<div id="configurar-o-conector-de-service-principal">
  ## Настройка коннектора service principal
</div>

Настройка service principal включает три роли:

1. **Администратор Databricks**: создаёт service principal и предоставляет ему разрешения в Databricks.
2. **Администратор организации Replit**: настраивает коннектор и доступ в Replit.
3. **Разработчик**: начинает работу с общей учётной записью Databricks.

<div id="pr-requisitos-do-service-principal">
  ### Предварительные требования для service principal
</div>

Прежде чем начать, убедитесь, что у вас есть:

* Права администратора учётной записи Databricks или Workspace Databricks.
* Права администратора организации Replit.

<div id="etapa-1-criar-um-service-principal-no-databricks">
  ### Шаг 1. Создание субъекта-службы в Databricks
</div>

<Note>
  Для выполнения этого шага необходимо быть администратором учётной записи Databricks или workspace.
</Note>

Администратор Databricks создаёт машиночитаемую идентификационную запись, называемую субъектом-службой, которую Replit использует для подключения к Databricks.

<Steps>
  <Step title="Откройте Настройки">
    В Databricks выберите свой аватар в правом верхнем углу, а затем — **Настройки**.

    <Frame>
      <img src="/assets/mirror/settings-menu-8f2dcd4dbee3.png" alt="Меню workspace Databricks с выбранным пунктом Настройки" width="3438" height="1984" data-path="images/connectors/databricks/settings-menu.png" />
    </Frame>
  </Step>

  <Step title="Выберите Идентификация и доступ">
    На боковой панели Настроек выберите **Идентификация и доступ**.

    <Frame>
      <img src="/assets/mirror/settings-page-2a8bcd7c22a4.png" alt="Страница Настроек Databricks с пунктом Идентификация и доступ на боковой панели" width="3438" height="1984" data-path="images/connectors/databricks/settings-page.png" />
    </Frame>
  </Step>

  <Step title="Управление субъектами-службами">
    В разделе **Управление и разрешения** найдите **Субъекты-службы** и выберите **Управление**.

    <Frame>
      <img src="/assets/mirror/identity-and-access-0e79404ed30f.png" alt="Страница настроек Идентификация и доступ с кнопкой Управление для Субъектов-служб" width="3438" height="1984" data-path="images/connectors/databricks/identity-and-access.png" />
    </Frame>
  </Step>

  <Step title="Добавьте новый субъект-службу">
    Выберите **Добавить субъект-службу**, затем — **Добавить новый**.

    <Frame>
      <img src="/assets/mirror/add-service-principal-ac5b52f21f4c.png" alt="Диалоговое окно Добавить субъект-службу с кнопкой Добавить новый" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal.png" />
    </Frame>
  </Step>

  <Step title="Задайте имя субъекта-службы">
    Введите понятное имя субъекта-службы и выберите **Добавить**.

    <Frame>
      <img src="/assets/mirror/add-service-principal-name-897df9e5f7ac.png" alt="Диалоговое окно Добавить субъект-службу с введённым именем субъекта-службы" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal-name.png" />
    </Frame>
  </Step>

  <Step title="Проверьте сведения о субъекте-службе">
    После создания субъекта-службы в Databricks убедитесь, что он активен. Оставьте эту страницу открытой: сведения о субъекте-службе могут понадобиться при настройке коннектора Replit.

    <Frame>
      <img src="/assets/mirror/service-principal-details-15a381d388bc.png" alt="Страница сведений о субъекте-службе Databricks" width="3438" height="1984" data-path="images/connectors/databricks/service-principal-details.png" />
    </Frame>
  </Step>

  <Step title="Предоставьте доступ">
    Откройте вкладку **Разрешения**, выберите **Предоставить доступ**, выберите субъект-службу, установите разрешение **Управление** и нажмите **Сохранить**.

    <Frame>
      <img src="/assets/mirror/grant-access-edbaa2541a7d.png" alt="Диалоговое окно Предоставить доступ для субъекта-службы Databricks с выбранным разрешением Управление" width="3438" height="1984" data-path="images/connectors/databricks/grant-access.png" />
    </Frame>
  </Step>
</Steps>

<div id="etapa-2-obter-os-detalhes-de-conexo-do-sql-warehouse">
  ### Шаг 2: Получите параметры подключения к SQL Warehouse
</div>

Коннектору Replit нужны параметры подключения к Databricks SQL Warehouse, чтобы направлять запросы к нужному вычислительному ресурсу.

<Steps>
  <Step title="Откройте SQL Warehouses">
    На боковой панели Databricks выберите **SQL Warehouses**.

    <Frame>
      <img src="/assets/mirror/sql-warehouses-cc178d18a33b.png" alt="Страница Databricks SQL Warehouses с доступными хранилищами" width="3438" height="1984" data-path="images/connectors/databricks/sql-warehouses.png" />
    </Frame>
  </Step>

  <Step title="Выберите или создайте warehouse">
    Выберите SQL Warehouse, который будет использовать Replit Agent. Если его ещё нет, выберите **Создать SQL warehouse** и создайте новый warehouse.
  </Step>

  <Step title="Скопируйте параметры подключения">
    Откройте warehouse и выберите **Сведения о подключении**. Найдите значения **Имя хоста сервера** и **HTTP-путь**. Они понадобятся при создании коннектора Databricks в Replit.

    <Frame>
      <img src="/assets/mirror/connection-details-938b970b98e6.png" alt="Страница сведений о подключении Databricks SQL Warehouse с именем хоста сервера и HTTP-путём" width="3438" height="1984" data-path="images/connectors/databricks/connection-details.png" />
    </Frame>
  </Step>
</Steps>

<div id="etapa-3-criar-o-conector-databricks-no-replit">
  ### Шаг 3: Создайте коннектор Databricks в Replit
</div>

<Note>
  Для настройки коннекторов необходимо быть администратором организации Replit.
</Note>

Администратор Replit добавляет в Replit сведения о подключении к Databricks, чтобы разработчики могли использовать коннектор.

<Steps>
  <Step title="Перейдите в раздел «Интеграции»">
    На главной странице своей учётной записи Replit откройте раздел **Интеграции**. В разделе **Коннекторы** найдите **Databricks (Service Principal)** и выберите **Войти**.

    <Frame>
      <img src="/assets/mirror/integrations-databricks-signin-75d3367013da.png" alt="Страница интеграций Replit с фильтром Databricks, на которой показан коннектор Databricks (Service Principal) с кнопкой «Войти»" width="3436" height="1978" data-path="images/connectors/databricks/integrations-databricks-signin.png" />
    </Frame>
  </Step>

  <Step title="Подтвердите подключение">
    Перед перенаправлением в Databricks для аутентификации Replit отображает диалоговое окно подтверждения. Проверьте сведения и выберите **Продолжить в Databricks**.

    <Frame>
      <img src="/assets/mirror/connect-databricks-intro-e842722d93ea.png" alt="Диалоговое окно подключения Databricks с пояснениями о перенаправлении OAuth, использовании данных и разрешениях" width="3436" height="1978" data-path="images/connectors/databricks/connect-databricks-intro.png" />
    </Frame>
  </Step>

  <Step title="Введите HTTP-путь SQL Warehouse">
    Вставьте **HTTP-путь** из сведений о подключении к Databricks SQL Warehouse (например, `/sql/1.0/warehouses/abcdef1234567890`) и выберите **Далее**.

    <Frame>
      <img src="/assets/mirror/connector-http-path-5c8ae35516f8.png" alt="Диалоговое окно подключения Databricks, шаг 1 из 2, с запросом HTTP-пути SQL Warehouse" width="3436" height="1978" data-path="images/connectors/databricks/connector-http-path.png" />

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

<AccordionGroup>
  <Accordion title="Запросы возвращают пустые результаты">
    Проверьте разрешения Databricks для учётной записи, выполняющей
    запрос. При использовании U2M это учётная запись отдельного разработчика. При использовании
    коннектора service principal — общий service principal. У
    учётной записи может быть доступ к метаданным, но не быть разрешения на чтение
    данных. Предоставьте необходимые разрешения для каталога, схемы или таблицы и
    повторите попытку.
  </Accordion>

  <Accordion title="Коннектор не может подключиться к SQL Warehouse">
    Проверьте, что значения **Имя хоста сервера** и **Путь HTTP**
    соответствуют параметрам подключения SQL Warehouse в Databricks. Для
    U2M проверьте значения, введённые соответствующим разработчиком. Также убедитесь,
    что warehouse запущен и учётная запись, выполняющая запрос, имеет
    разрешение на его использование.
  </Accordion>

  <Accordion title="Сбой аутентификации">
    Для U2M убедитесь, что в настройках подключения приложения Databricks указан
    `https://replit.com/connectors/oauth/callback` в **Redirect URLs** без
    завершающей косой черты. Если аутентификация не удаётся у всех разработчиков,
    проверьте общие Client ID и Client Secret, убедитесь, что
    секрет не истёк, а области действия в Replit
    соответствуют настройкам подключения приложения Databricks.

    Для коннектора service principal убедитесь, что сведения о service
    principal, введённые в Replit, соответствуют service principal, созданному в
    Databricks. Если учётные данные были изменены, обновите коннектор в
    Replit.
  </Accordion>

  <Accordion title="Коннектор просит войти снова">
    Это может произойти при использовании U2M, если refresh token истёк или был отозван.
    Повторно пройдите процедуру авторизации Databricks. Если
    разработчикам приходится переподключаться чаще, чем того требует
    ваша политика безопасности, пересмотрите время жизни token в настройках подключения
    приложения.
  </Accordion>
</AccordionGroup>
