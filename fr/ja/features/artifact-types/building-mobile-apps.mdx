<div id="section-2">
  ## Prévisualiser dans un simulateur ou un émulateur
</div>

Avec Replit, vous pouvez utiliser Expo pour exécuter et tester des applications mobiles sur votre téléphone. Replit diffuse également un véritable **simulateur iOS** ou **émulateur Android** directement dans le panneau d&#39;aperçu. <div id="expo-go">
  ### Quand utiliser Expo Go à la place
</div>

Si vous devez tester des fonctionnalités qui dépendent du matériel réel, ou si vous souhaitez partager un aperçu avec des personnes qui ne sont pas devant leur ordinateur, utilisez Expo Go sur un appareil physique :

* Caméra, microphone, retour haptique et autres capteurs natifs
* Notifications push
* Géolocalisation GPS réelle
* Partage d&#39;aperçus de développement avec des coéquipiers, des testeurs ou des investisseurs

Pour Build votre application avec Expo Go, ouvrez votre projet sur [replit.com](https://replit.com), sélectionnez **Ouvrir dans Expo Go** dans le panneau d&#39;aperçu de l&#39;éditeur de projet, puis scannez le code QR avec l&#39;application [Expo Go](https://expo.dev/go) sur votre smartphone.

Depuis la carte d&#39;artefact mobile, sélectionnez **Autres actions** → **Ouvrir dans le simulateur iOS** ou **Ouvrir dans l&#39;émulateur Android** pour ouvrir le simulateur dans un onglet dédié et profiter d&#39;une zone d&#39;affichage plus grande.

<div id="section-6">
  ## Pourquoi créer une application mobile ?
</div>

Créez une application mobile lorsque vous avez besoin des éléments suivants :

* **Expérience native** : performances rapides, interactions fluides et interface conforme aux standards de la plateforme.
* **Fonctionnalités de l&#39;appareil** : appareil photo, notifications push, géolocalisation, etc.
* **Distribution sur l&#39;App Store** : une fiche partageable que les utilisateurs peuvent découvrir et installer, une fois le processus de validation d&#39;Apple terminé.

<div id="section-7">
  ## Fonctionnalités principales
</div>

* **Création axée sur l’IA** : décrivez votre application et Agent crée la structure d’une application mobile fonctionnelle.
* **Aperçu dans l’éditeur de projet** : testez-la dans le simulateur iOS ou l’émulateur Android sans quitter Replit, ou prévisualisez-la sur votre téléphone avec Expo Go.
* **Full stack par défaut** : ajoutez des routes côté serveur, une base de données, App Storage, des connecteurs et des intégrations d’IA à mesure que votre application évolue.
* **Soumission guidée** : préparez des builds pour TestFlight et l’App Store sans avoir à gérer une chaîne d’outils iOS locale.

<div id="section-8">
  ## Flux de développement
</div>

Il existe trois étapes pour accéder à votre app, chacune avec son public et ses fonctionnalités :

| Étape             | Qui peut y accéder               | Méthode d&#39;accès                                            | Idéal pour                                            |
| ----------------- | -------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------- |
| **Développement** | Vous                             | Simulateur de l&#39;éditeur de projet, ou code QR pour Expo Go | Créer et itérer                                       |
| **Déploiement**   | Testeurs disposant d&#39;Expo Go | URL publique avec code QR                                      | Aperçus de développement, prototypage, démonstrations |
| **App Store**     | Tout le monde                    | Téléchargement depuis l&#39;App Store après l&#39;App Review   | Mise en production                                    |

**Développement** : lorsque vous lancez votre app, vous pouvez la prévisualiser dans le **simulateur iOS** ou l&#39;**émulateur Android** de l&#39;éditeur de projet, ou scanner le code QR du panneau d&#39;aperçu pour l&#39;ouvrir dans Expo Go sur votre téléphone.

**Déploiement** : lorsque vous cliquez sur **Publier**, Replit crée une URL publique accompagnée d&#39;un code QR pour Expo Go. C&#39;est idéal pour les aperçus de développement et le prototypage : vous pouvez la montrer à des investisseurs, recueillir des retours ou la tester avec des amis avant de vous lancer dans le processus de l&#39;App Store.

**App Store** : lorsque vous soumettez votre app à l&#39;App Store, Apple la passe en revue, puis elle peut être téléchargée et installée depuis l&#39;App Store. Un compte Apple Developer est nécessaire.

<div id="section-9">
  ## Vue d&#39;ensemble de la publication
</div>

Lorsque vous préparez une version iOS, le processus se déroule généralement ainsi :

* Publiez depuis l&#39;éditeur de projet
* Soumettez la build à TestFlight
* Faites passer la build TestFlight vers l&#39;App Store depuis App Store Connect

<Note>
  Apple exige une adhésion à l&#39;Apple Developer Program pour soumettre des builds à TestFlight et à l&#39;App Store.
</Note>

Pour un guide complet, consultez le tutoriel [Créer et lancer une application mobile](/fr/ja/build/mobile-app).

<div id="section-10">
  ## Où créer des applications mobiles natives
</div>

L&#39;environnement Replit s&#39;exécute dans le cloud, et non sur votre machine locale. Pour créer une application mobile native, utilisez l&#39;éditeur de projet sur [replit.com](https://replit.com). Les workflows d&#39;applications mobiles — génération de la structure par Agent, aperçu avec Expo Go, tests sur simulateur et émulateur, builds TestFlight, soumission à l&#39;App Store — s&#39;exécutent tous dans l&#39;éditeur de projet.

Vous pouvez également travailler sur vos applications mobiles natives depuis l&#39;[application Replit pour Android](/fr/ja/features/platforms/mobile-app), qui est prise en charge. Si vous utilisez l&#39;application Replit pour iOS, ouvrez votre projet sur [replit.com](https://replit.com) pour créer, prévisualiser, compiler et soumettre vos applications mobiles natives.

Les applications mobiles reposent sur un ensemble de technologies qui fonctionnent de concert. Cette section explique ce qui fait fonctionner votre application et comment chaque élément s&#39;articule avec les autres.

<div id="section-12">
  ### La pile technologique
</div>

<MobileStackDiagram />

* **React Native** est un framework open source qui permet d&#39;écrire une seule base de code et de la compiler pour iOS, Android et le web. Plutôt que des vues web, il affiche les composants d&#39;interface natifs de chaque plateforme.
* **Expo** simplifie le développement avec React Native : il prend en charge les builds, gère les modules natifs et fournit des outils comme Expo Go pour la prévisualisation.
* **Expo Go** est une application gratuite à installer sur votre smartphone. Elle vous permet d&#39;exécuter des aperçus de développement sur un appareil réel, sans avoir à générer un binaire natif complet.

Lorsque vous lancez votre application, le bundler Metro compile votre code et l&#39;envoie sur l&#39;appareil. Faute de cache, le premier build prend du temps. Les suivants sont beaucoup plus rapides.

<div id="section-13">
  ### Architecture : serveur et client
</div>

Lorsque vous prévisualisez une application mobile ou que vous la préparez pour la distribution, vous manipulez deux éléments :

1. **Le serveur** : il s&#39;exécute sur Replit, dans le cloud. Il gère la base de données, les routes API, les intégrations d&#39;IA et la logique backend.
2. **L&#39;application cliente** : elle s&#39;exécute sur le smartphone de l&#39;utilisateur. Pendant le développement, elle est prévisualisée dans Expo Go ; après validation, il s&#39;agit d&#39;une application native distribuée via les app stores.

<MobileArchitectureDiagram />

Cette séparation apporte de la souplesse. Vous pouvez exécuter la logique complexe sur le serveur (avec accès à Database, Object Storage et aux connectors de Replit) tout en gardant le client léger. Au fil de votre développement, demandez-vous ce qui doit se passer sur le smartphone et ce qui doit se passer dans le cloud.

<div id="section-14">
  ## Points à prendre en compte
</div>

* **Conditions de publication** : Apple définit les exigences de TestFlight et de l&#39;App Store, et examine les apps iOS avant leur distribution.
* **Publication sur Android** : vous pouvez créer des apps multiplateformes pour iOS et Android. La publication sur Google Play n&#39;est pas encore prise en charge dans l&#39;expérience guidée, mais vous pouvez l&#39;effectuer manuellement.
* **Modifications natives** : les changements tels que l&#39;icône de l&#39;app ou les autorisations nécessitent généralement une nouvelle version destinée à la boutique.

<div id="section-17">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Qu’est-ce qu’Expo ?">
    Expo est l&#39;outil qu&#39;Agent utilise pour créer des applications mobiles sur Replit. Il s&#39;agit d&#39;une plateforme et d&#39;une chaîne d&#39;outils open source permettant de créer, exécuter et déployer des applications natives multiplateformes avec React Native. Pour en savoir plus, consultez [https://expo.dev.](https://expo.devをご覧ください。)
  </Accordion>

  <Accordion title="Qu’est-ce que React Native ?">
    React Native est le framework open source de Meta permettant de créer des applications natives iOS et Android avec React et JavaScript ou TypeScript. Comme il affiche les composants d&#39;interface natifs de la plateforme plutôt que des vues web, votre application offre l&#39;apparence et le comportement d&#39;une application native.
  </Accordion>

  <Accordion title="Qu’est-ce qu’Expo Go ?">
    Expo Go est une application gratuite à installer sur votre smartphone depuis l&#39;App Store ou Google Play. Elle vous permet de prévisualiser vos applications mobiles en cours de développement, sans avoir à générer un binaire natif complet. Lorsque vous scannez le code QR dans l&#39;éditeur de projet, Expo Go télécharge le code de l&#39;application et le Build.
  </Accordion>

  <Accordion title="Quelle est la différence entre Expo Go et les builds de développement ?">
    **Expo Go** est une application précompilée qui exécute votre code. Sa configuration est rapide, mais elle ne prend en charge que les modules inclus dans le SDK Expo.

    Une **build de développement** est un binaire natif personnalisé qui peut inclure n&#39;importe quel module natif. Elle demande davantage de configuration (EAS Build ou Xcode/Android Studio en local), mais offre plus de souplesse.

    Replit utilise Expo Go pour les aperçus de développement. Si vous avez besoin de modules natifs non pris en charge par Expo Go, envisagez éventuellement une build de développement en consultant la [documentation d&#39;Expo](https://docs.expo.dev/develop/development-builds/introduction/).
  </Accordion>

  <Accordion title="Quelle est la différence avec une application web responsive ?">
    Une application web responsive est un site web dont la mise en page s&#39;adapte au navigateur. Une application React Native, elle, est une application native installée sur l&#39;appareil : elle utilise les API de la plateforme (caméra, retour haptique, notifications push), offre un meilleur accès au matériel et aux fonctionnalités hors ligne, et se distribue via les boutiques d&#39;applications. Le web responsive l&#39;emporte sur la portée et l&#39;absence d&#39;installation, tandis que le natif s&#39;impose dès que vous avez besoin des capacités de l&#39;appareil, de performances ou d&#39;une distribution sur l&#39;App Store.
  </Accordion>

  <Accordion title="Ai-je besoin d’un Mac ou de Xcode ?">
    Non. Replit et Expo gèrent le processus de build dans le cloud.
  </Accordion>

  <Accordion title="Puis-je prévisualiser sans compte Apple Developer ?">
    Oui. Vous pouvez prévisualiser votre projet dans le simulateur iOS de l’éditeur de projet ou dans Expo Go sur votre smartphone. Vous n’avez besoin d’un compte Apple Developer que lorsque vous êtes prêt à soumettre votre App à TestFlight ou à l’App Store.
  </Accordion>

  <Accordion title="Android est-il pris en charge ?">
    Oui. Vous pouvez créer des applications multiplateformes pour iOS et Android à partir d&#39;une même base de code. L&#39;aperçu est possible dans l&#39;émulateur Android de l&#39;éditeur de projet ou sur un appareil Android via Expo Go. La publication sur Google Play peut se faire manuellement.
  </Accordion>

  <Accordion title="Qu’advient-il des serveurs et de la base de données ?">
    Utilisez PostgreSQL, l&#39;Object Storage, les connecteurs et les intégrations d&#39;IA intégrés à Replit — aucune infrastructure distincte n&#39;est nécessaire. Le serveur s&#39;exécute sur Replit, et l&#39;application mobile s&#39;y connecte.
  </Accordion>

  <Accordion title="Dois-je tester avec le simulateur de l’éditeur de projet ou sur un appareil réel ?">
    Utilisez les deux selon les situations. Le **simulateur iOS** et l&#39;**émulateur Android** de l&#39;éditeur de projet affichent la version native de votre application et couvrent la majorité des tests quotidiens (mise en page, navigation, composants natifs, style propre à chaque plateforme). Lorsque vous devez tester des fonctionnalités qui dépendent du matériel réel, comme l&#39;appareil photo, le retour haptique, les notifications push ou la localisation GPS, passez à un appareil physique avec **Expo Go**.
  </Accordion>
</AccordionGroup>
