Crie aplicativos com IA no Replit e publique-os diretamente no Microsoft Fabric, com governança e segurança de nível empresarial integradas. A integração com o Microsoft Fabric transforma dados empresariais governados em ferramentas internas, como dashboards, fluxos de trabalho e aplicativos de IA. As equipes passam do prompt à produção mais rapidamente, enquanto as políticas de autenticação e acesso permanecem dentro do ambiente Fabric em que já confiam.

## O que é um aplicativo de dados Fabric

Um aplicativo de dados Fabric é um aplicativo React estático que renderiza gráficos do Power BI executando consultas [Data Analysis Expressions (DAX)](https://learn.microsoft.com/pt-br/dax/) em um [modelo semântico do Power BI](https://learn.microsoft.com/pt-br/power-bi/connect-data/service-datasets-understand). Algumas características moldam como você o constrói:

* **Modelos semânticos do Power BI são a fonte de dados.** Os gráficos são alimentados por consultas DAX nos modelos semânticos (datasets) que você conecta.
* **Somente leitura por design.** O aplicativo lê dados com DAX `EVALUATE`; ele não grava de volta no Power BI. Se você precisar de estado gravável, use um banco de dados de aplicativo separado junto com o dashboard.
* **Renderizado pelo portal Fabric.** A camada de dados é executada dentro do portal do Microsoft Fabric, que executa suas consultas no modelo semântico e retorna os resultados ao aplicativo. Seus dados permanecem no seu ambiente Fabric.
* **Hospedado na infraestrutura da Microsoft.** Você pode publicar um aplicativo de dados finalizado na hospedagem da Microsoft para que ele seja executado junto com o restante do seu ambiente Fabric.

<Note>
  Os aplicativos de dados do Microsoft Fabric exigem acesso a um tenant do Microsoft Fabric com modelos semânticos do Power BI e — durante a pré-visualização — associação ao programa de testadores aprovados.
</Note>

Nos bastidores, o [Rayfin](https://github.com/microsoft/rayfin) (um SDK e CLI de código aberto para criar backends de aplicativos) permite que o Agent defina e publique aplicativos prontos para produção em cima dos seus dados Fabric.

Você permanece em um único fluxo de trabalho: descreva o aplicativo, deixe o Agent estruturá-lo, conecte-se aos dados Fabric governados e publique para executar no tenant Fabric da sua organização.

Este guia abrange o fluxo do construtor, como o aplicativo se conecta aos dados Fabric e as opções para equipes e automação. Para dashboards de dados gerais baseados em outros warehouses, consulte [Visualização de Dados](/pt/features/artifact-types/data-apps).

## Casos de uso

Para organizações já investidas no ecossistema de dados da Microsoft, este é um caminho muito mais rápido para software interno. Em vez de gastar semanas conectando autenticação, APIs, ferramentas de implantação e políticas de governança, as equipes descrevem o que querem e deixam o Agent construir.

Casos de uso comuns incluem:

* Ferramentas de produtividade específicas por departamento
* Dashboards operacionais
* Ferramentas de exploração de dados
* Aplicativos de automação de fluxo de trabalho
* Interfaces de relatórios

Para TI corporativa, governança, autenticação e segurança permanecem dentro do ambiente Fabric que sua organização já gerencia, portanto a criação rápida de aplicativos não tem o custo do controle centralizado.

## Criar um aplicativo de dados Fabric

O fluxo do construtor é conversacional. Você fica no Replit o tempo todo; autenticação e acesso a dados acontecem pela Microsoft quando solicitado.

<Steps>
  <Step title="Comece com o template Fabric">
    Na página inicial do Replit, abra o menu suspenso **Templates** e escolha **Microsoft Fabric App** em **Org templates**. Isso coloca o Agent no fluxo de trabalho de aplicativo de dados com as ferramentas Fabric pré-carregadas.

    <Frame caption="Selecionando o template de organização Microsoft Fabric App na página inicial do Replit (interface de pré-visualização privada).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Página inicial do Replit com o menu suspenso de Templates aberto, mostrando o Microsoft Fabric App destacado em Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Descreva o dashboard que você deseja">
    Digite um prompt descrevendo o dashboard ou ferramenta de relatórios a ser criado. Por exemplo: "Crie um dashboard de crescimento de vendas mês a mês a partir do nosso modelo de vendas Fabric." Você não precisa escrever DAX — o Agent gera as consultas.
  </Step>

  <Step title="Entre com a Microsoft">
    Quando solicitado, entre com o Microsoft OAuth no tenant que contém seus dados Fabric. Isso autoriza o Agent a ler os modelos semânticos aos quais você tem acesso. A identidade com a qual você entra deve ter acesso ao workspace Fabric que deseja usar.
  </Step>

  <Step title="Adicione suas fontes de dados">
    Quando o Agent pedir, compartilhe o modelo semântico do Power BI / Fabric que deseja usar. Você pode fornecer a URL completa do dataset no portal Fabric (por exemplo, `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) ou o ID do workspace mais o ID do dataset/item. O Agent usa essas informações para identificar o workspace e o modelo semântico a ser consultado.

    O modelo deve estar **publicado no serviço Power BI** — arquivos `.pbix` locais não podem ser usados.

    <Frame caption="O Agent solicitando o link do modelo semântico do Power BI / Fabric (interface de pré-visualização privada).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Painel do Agent solicitando ao construtor que compartilhe o modelo semântico do Power BI ou Fabric, como uma URL completa do portal Fabric ou um ID de workspace mais ID de dataset ou item, observando que arquivos .pbix locais não podem ser usados porque o modelo deve ser publicado no serviço Power BI" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Deixe o Agent criar e iterar">
    O Agent explora o schema do modelo semântico, escreve consultas DAX e monta o dashboard com gráficos apropriados. Revise o resultado e peça alterações em linguagem natural — adicione um filtro, mude um tipo de gráfico ou adicione outra métrica.
  </Step>

  <Step title="Publicar (opcional)">
    Quando o dashboard estiver pronto, você pode publicá-lo na hospedagem da Microsoft para que seja executado dentro do seu ambiente Fabric. A publicação é abordada separadamente; este guia se concentra na conexão a dados e na criação do aplicativo.
  </Step>
</Steps>

## Conectando-se aos dados Fabric

Para ler dados, o aplicativo precisa de uma conexão autorizada com o Microsoft Fabric. O Replit estabelece essa conexão de uma das duas maneiras.

### Login no Fabric no nível do aplicativo (visualizadores)

Os visualizadores de um aplicativo de dados publicado nunca configuram um conector. Eles se autenticam por meio do logon único do Microsoft Fabric integrado ao aplicativo, e o aplicativo lê dados como sua identidade pelo portal Fabric. Isso mantém o acesso governado pelas permissões Fabric existentes.

### O conector Microsoft Fabric (o caminho fácil para construtores)

Para construtores, o **conector Microsoft Fabric** é a maneira conveniente de autorizar o acesso a dados durante o desenvolvimento. É opcional — um caminho fácil, não um requisito.

* O primeiro construtor a configurá-lo completa um **OAuth único** com a Microsoft.
* Outros colaboradores **no mesmo projeto herdam** essa conexão.
* Um **workspace diferente** deve habilitar o conector e completar seu próprio OAuth.
* A identidade autenticada via OAuth deve ter acesso ao workspace Fabric de destino.

O conector usa o Microsoft Entra OAuth e tem escopo para seu tenant. Gerencie-o na página de [Integrações](/pt/features/integrations/overview) do seu projeto como qualquer outro conector Replit. Para conceitos mais amplos sobre conectores, consulte [Gerenciando seus conectores](/pt/replitai/managing-connectors).

<Note>
  Durante a pré-visualização privada, não há credenciais gerenciadas pelo Replit compartilhadas para o conector Microsoft Fabric. Os construtores se autorizam no próprio tenant do Microsoft Entra.
</Note>

## Equipes e automação

Para uso compartilhado em equipe ou ambientes não interativos (como CI), o OAuth interativo nem sempre é prático. Nesses casos, forneça um token de **entidade de serviço** pelas [Secrets](/pt/core-concepts/project-editor/app-setup/secrets) do seu projeto em vez de entrar interativamente. O aplicativo usa a identidade da entidade de serviço para ler os dados Fabric.

Esta é a analogia mais próxima de uma configuração máquina a máquina: uma identidade não humana, provisionada no Microsoft Entra e com acesso concedido ao workspace Fabric, autentica o aplicativo sem a intervenção de uma pessoa. Confirme que a entidade de serviço tem acesso aos workspaces e modelos semânticos que o aplicativo consulta.

## Solução de problemas

<AccordionGroup>
  <Accordion title="Os dados não carregam na pré-visualização do aplicativo">
    A camada de dados Fabric é executada pelo portal do Microsoft Fabric. Se os gráficos renderizarem vazios ou a pré-visualização do aplicativo não carregar dados, confirme que você concluiu o login da Microsoft e que a identidade conectada tem acesso ao workspace e ao modelo semântico vinculados.
  </Accordion>

  <Accordion title="O Agent não consegue encontrar seu modelo semântico">
    Certifique-se de ter colado o link do dataset do Power BI no portal Fabric e que sua identidade (ou entidade de serviço) tem pelo menos acesso de leitura a esse workspace. Compartilhe novamente o link do dataset se o Agent relatar que não consegue resolver o workspace ou o modelo.
  </Accordion>

  <Accordion title="O conector está travado ou solicita conexão repetidamente">
    Reautorize o conector Microsoft Fabric na página de [Integrações](/pt/features/integrations/overview) do projeto. Confirme que a identidade autenticada via OAuth tem acesso ao workspace Fabric. Para uso em equipe ou CI, prefira um token de entidade de serviço fornecido pelas Secrets.
  </Accordion>
</AccordionGroup>
