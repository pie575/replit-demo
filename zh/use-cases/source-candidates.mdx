Ashby 已经在筛选主动投递的申请。而这个工作流是主动出击：读取 Drive 中的职位描述，在 GitHub 上寻找匹配的工程师，跳过已在 Ashby 中的人选，并起草好由你发送的外联邮件。Agent 会将新发现的人标记为已寻访，并在候选人记录上附上简短的匹配理由和一份邮件草稿。你负责审阅和发送。请不要将其作为招聘决策的唯一依据。

<div id="best-for">
  ## 适用场景
</div>

* 主动投递量不足、需要主动寻访候选人名单的技术招聘人员。
* 想找到与 GitHub 数据匹配的工程师，又不愿整天泡在搜索里的招聘经理。

<div id="before-you-start">
  ## 开始之前
</div>

准备一份职位描述，明确区分必备条件和加分项。连接 Drive、GitHub 和 Ashby。说明工作地点、职级以及你希望获得的候选人数量。请勿将其作为招聘决策的唯一依据。

<div id="prompt-the-agent">
  ## 向 Agent 发送 prompt
</div>

<AiPrompt>
  创建一个 Routine，每周一 9:00 运行。根据这份职位描述
  [Drive 链接或直接粘贴]，在 GitHub 上找出 30 位符合必备条件的工程师，
  跳过已在 Ashby 中的人选。为每个人写一段 3 行的匹配理由，以及一封简短的
  外联邮件草稿。不要发送任何内容。将新人选以已寻访状态添加到 Ashby，并把理由说明和草稿
  附在候选人记录上。
</AiPrompt>

<div id="what-to-expect">
  ## 预期效果
</div>

Agent 会读取职位描述、在 GitHub 上搜索、跳过 Ashby 中已有的人选，并
返回一份附带草稿的候选名单。你负责审阅并发送。第一轮结果会比较杂乱，
看过之后再收紧必备条件。从名单中打开三个 GitHub 个人主页，核对是否
符合必备条件，并在发送任何内容前确认这些人尚未出现在 Ashby 中。

<div id="troubleshooting">
  ## 疑难解答
</div>

* **候选名单太杂：** 在第一轮筛选后，进一步收紧必备条件与加分项的界限。要求筛选出近期在特定语言或特定类型仓库有提交记录的人，并剔除疑似现有客户或竞争对手员工的人选。
* **已在 Ashby 中的人仍然出现：** 确认 Ashby 已连接到正确的 workspace，并且 Agent 是按邮箱或 GitHub 用户名匹配，而不只是按显示名称匹配。
* **外联邮件已经发出：** 该工作流只应负责起草。如果已有内容发出，请停止该 Routine，并告知 Agent 绝不要向候选人发送邮件或消息。
