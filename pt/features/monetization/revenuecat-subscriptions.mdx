## O que é o RevenueCat

O RevenueCat permite adicionar assinaturas no app ao seu [app mobile nativo](/pt/features/artifact-types/building-mobile-apps). Para começar, peça ao Agent para configurar uma assinatura, conecte sua conta RevenueCat, e o Agent cuida da lógica e fornece um ambiente de teste.

## Pré-requisitos

Antes de começar, você precisa de:

* Um projeto Replit criado com um **app mobile**
* Uma conta [RevenueCat](https://www.revenuecat.com) (são necessários apenas um e-mail e uma senha — não é preciso ter conta bancária nem configuração adicional)

<Note>
  Para trabalhar em um app mobile nativo, use o Project Editor em [replit.com](https://replit.com). O trabalho com apps mobile nativos também está disponível no app Replit para Android, onde suportado. Se você estiver usando o app Replit para iOS, abra o projeto em replit.com.
</Note>

## Teste as assinaturas

Os previews do Replit usam o **modo de teste** do RevenueCat. Ao testar uma compra no Expo Go, você vê uma caixa de diálogo de compra de teste em vez de um fluxo de pagamento real. Nenhum valor é cobrado.

<Frame>
  <img src="/assets/mirror/revenuecat-test-purchase-8414145a112e.png" alt="Caixa de diálogo de compra de teste em um dispositivo mobile mostrando os detalhes do pacote e botões de teste" width="683" height="1253" data-path="images/replitai/revenuecat-test-purchase.png" />
</Frame>

<Tip>
  As compras de teste são seguras para usar durante o desenvolvimento. Você pode testar tanto fluxos de compra bem-sucedidos quanto com falha, sem nenhuma cobrança real.
</Tip>

<Warning>
  Depois que a Apple aprovar seu app para distribuição na App Store, as compras passam a usar dinheiro real.
  Certifique-se de que seus produtos e preços no RevenueCat estejam corretos antes de enviar para
  a App Review.
</Warning>

## Sincronização com o App Store Connect

Para que as compras no app funcionem no TestFlight e na Apple App Store, [você precisará concordar
com o Paid Apps Agreement da Apple e conectar sua conta bancária](https://developer.apple.com/help/app-store-connect/manage-agreements/sign-and-update-agreements/).
Isso é feito através do App Store Connect. Você precisará de uma conta paga de Apple Developer antes de poder enviar seu app para a App Store.

Depois disso, você pode sincronizar suas configurações de compras no app do RevenueCat para o App Store Connect diretamente pelo Replit.

<Steps>
  <Step title="Vá até o painel Manage em Publishing">
    Você verá um botão para sincronizar o RevenueCat com o App Store Connect.

    <Tip>
      Esta seção só aparece depois que você enviar seu app para o TestFlight.

    Baixe o arquivo .p8 agora — você só pode baixá-lo uma vez. O nome do arquivo começa com `AuthKey_` e termina em `.p8`.

    Copie o **Key ID** e o **Issuer ID** mostrados nesta página.

## Perguntas frequentes

<AccordionGroup>
  <Accordion title="Eu preciso de uma conta bancária para usar o RevenueCat?">
    Não. Você só precisa de um e-mail e uma senha para criar uma conta RevenueCat. A configuração da
    conta bancária é feita separadamente através da Apple ou do Google quando você estiver
    pronto para receber pagamentos da App Store ou do Google Play.
  </Accordion>

  <Accordion title="As compras de teste são cobradas?">
    Não. Durante o desenvolvimento, os previews do Replit usam o modo de teste do RevenueCat.
    As compras são simuladas e nenhuma cobrança real é feita. Cobranças reais só
    se aplicam depois que a App Review da Apple aprovar seu app.
  </Accordion>

  <Accordion title="Posso usar o RevenueCat com um app web?">
    O RevenueCat foi projetado para apps mobile nativos. Para adicionar assinaturas a um app
    web, use a [integração com Stripe](/pt/features/monetization/stripe-payments)
    em vez disso.
  </Accordion>

  <Accordion title="O que posso configurar com o RevenueCat?">
    Você pode configurar assinaturas mensais ou anuais, definir preços, gerenciar
    entitlements e construir paywalls. Peça ao Agent para fazer as alterações — ele cuida tanto
    da configuração do RevenueCat quanto do código do seu app.
  </Accordion>
</AccordionGroup>
