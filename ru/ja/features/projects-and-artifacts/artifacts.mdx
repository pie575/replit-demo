<div id="section">
  ## Что такое артефакт?
</div>

Артефакт — это то, что можно опубликовать в Replit: например, веб-приложение, мобильное приложение, презентацию, анимацию, приложение для работы с данными, 3D-игру или дизайн. Это готовый самостоятельный результат, который после публикации получает собственный URL для совместного доступа.

Всё остальное в проекте — файлы, изображения, CSV и код — поддерживает артефакт, но не может быть опубликовано отдельно.

<div id="section-3">
  ## Начало работы
</div>

На домашней странице Replit создать проект можно двумя способами:

* **Описать**: введите, что вам нужно, — «Создай приложение с рецептами» или «Сделай презентацию для стартапа». Agent сам определит подходящий тип и создаст проект.
* **Выбрать тип**: прежде чем описывать идею, выберите нужный артефакт (веб-приложение, мобильное приложение, визуализацию данных, анимацию, 3D-игру или другой поддерживаемый тип).

Кроме того, вы в любой момент можете добавить их в существующий проект — попросите об этом Agent в чате или нажмите кнопку **+** на панели предпросмотра.

<div id="section-4">
  ## Переключение между артефактами
</div>

Если в проекте несколько артефактов, переключайтесь между ними на **панели предпросмотра** или в **боковой панели библиотеки**. Можно также попросить об этом Agent: «покажи мобильное приложение» или «переключись на слайды».

<div id="section-5">
  ### Боковая панель библиотеки
</div>

Боковая панель библиотеки — это единое место, где можно просмотреть всё содержимое проекта: артефакты, изображения, созданные или загруженные Agent, а также другие ресурсы проекта. Откройте боковую панель библиотеки из левой панели, чтобы находить и повторно использовать ресурсы всего проекта.

<div id="section-6">
  ## Несколько артефактов в одном проекте
</div>

Один проект может содержать до **7 артефактов**, из них **не более одного мобильного приложения**. Например, веб-приложение для клиентов, мобильное приложение для команды и презентацию для инвесторов можно создать в рамках одного проекта.

<div id="section-7">
  ### Добавление артефакта в проект
</div>

Добавить артефакт в существующий проект можно тремя способами:

* **Чат**: попросите Agent — «Добавь в этот проект мобильное приложение» или «Создай презентацию для инвесторов»
* **Кнопка «плюс»**: нажмите кнопку **+** на панели предпросмотра и выберите, что хотите создать
* **Боковая панель библиотеки**: просматривайте существующие артефакты, изображения и другие ресурсы и добавляйте новые артефакты прямо оттуда

<div id="section-8">
  ### Общие данные и бэкенд
</div>

Артефакты внутри одного проекта автоматически используют общие данные и общую логику бэкенда. Когда клиент оформляет заказ в веб-приложении, мобильное приложение и дашборд с данными сразу же видят этот заказ. Не нужно настраивать соединения или дублировать код — всё работает само собой.

<Note>
  При публикации проект развёртывается целиком. Все артефакты публикуются одновременно, поэтому они всегда синхронизированы.
</Note>

<div id="section-9">
  ### Примеры сочетаний
</div>

* **Веб-приложение + мобильное приложение**: ресторан с веб-приложением для клиентов и мобильным приложением для персонала — оба подключены к одному API и одной базе данных
* **Приложение + панель администратора**: основной продукт вместе с внутренней админ-панелью для управления контентом, пользователями и настройками
* **Приложение + презентация**: продукт и питч-презентация в одном проекте, чтобы слайды всегда отражали актуальную версию
* **Дашборд с данными + видео**: визуализация данных в реальном времени в сочетании с анимационным роликом, который поясняет ключевые моменты

<div id="section-10">
  ## Публикация
</div>

Приложения, презентации и видео можно публиковать и передавать другим. После развертывания каждый объект получает собственную ссылку для общего доступа.

Файлы и ресурсы, не являющиеся артефактами (например, CSV, изображения или файлы Markdown), нельзя опубликовать отдельно. Чтобы поделиться ими, добавьте их в приложение или создайте новый артефакт.

<div id="section-11">
  ## Часто задаваемые вопросы
</div>

<Accordion title="Можно ли иметь несколько артефактов в одном проекте?">
  Да. Один проект может содержать до **7 артефактов**, причём **мобильное приложение — только одно на проект**. Все артефакты внутри проекта автоматически используют общий бэкенд и общие данные.

  Если вы достигли лимита по мобильным приложениям и хотите создать второе, создайте его в новом проекте. Если исчерпан общий лимит в 7 артефактов, удалите один из существующих артефактов перед добавлением нового или разделите проект на несколько.
</Accordion>

<Accordion title="Нужно ли выбирать тип перед началом работы?">
  Нет. Просто опишите, что вам нужно, и Agent сам подберёт подходящий тип. При желании тип можно выбрать вручную из выпадающего списка.
</Accordion>

<Accordion title="Можно ли опубликовать только один артефакт из проекта?">
  Пока нет. При публикации весь проект разворачивается целиком, благодаря чему все артефакты остаются синхронизированными. Если нужны независимые развёртывания, используйте отдельные проекты.
</Accordion>

<Accordion title="Используют ли артефакты общие данные?">
  Да. Все артефакты внутри проекта используют одну и ту же базу данных и одни и те же сервисы бэкенда. Как только веб-приложение запишет данные, мобильное приложение и дашборд с данными смогут сразу же их прочитать.
</Accordion>

<Accordion title="Чем артефакт отличается от файла?">
  Артефакт — это то, что можно опубликовать: приложения, слайды, видео. Файлы (CSV, изображения, код и прочее) — это ресурсы внутри проекта, которые обеспечивают работу артефактов, но сами по себе не публикуются.
</Accordion>

<Accordion title="В мобильном приложении не хватает функции из веб-приложения. Что произошло?">
  Когда Agent переносит функции между типами артефактов, некоторые из них могут перенестись не полностью — особенно взаимодействия и элементы вёрстки, которые различаются на разных платформах. Недостающее можно доработать, продолжив диалог в чате.
</Accordion>
