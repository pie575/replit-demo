При публикации из Replit ваш project может начать получать реальный трафик. Инструменты безопасности Replit помогают находить уязвимости, устранять подтверждённые проблемы с помощью Agent и сохранять доказательства для аудита.

<div id="why-security-matters">
  ## Почему безопасность важна
</div>

* Опубликованные проекты доступны из открытого интернета, включая публичные маршруты и API.
* Современные проекты зависят от множества пакетов, а новые CVE могут появиться уже после публикации.
* Сгенерированный ИИ код всё равно нуждается в проверке безопасности, особенно в части аутентификации, запросов к базе данных, Secrets и обработки данных.
* Программы соответствия нормативным требованиям, как правило, требуют документального подтверждения инвентаризации зависимостей, отслеживания уязвимостей и их устранения.

<div id="where-to-start">
  ## С чего начать
</div>

* Устанавливаете пакеты? [Package Firewall](/ru/features/security/package-firewall) блокирует вредоносные зависимости на этапе установки и включён по умолчанию.
* Работаете в одном project? Используйте [Project Security Center](/ru/features/security/project-security-center).
* Проводите аудит всего workspace? Используйте [Workspace Security Center](/ru/features/security/workspace-security-center).
* Выбираете, где будут работать ресурсы разработки? Прочитайте [Workspace geography](/ru/features/collaboration/workspace-geography). Чтобы выбрать, где будет работать опубликованный Project, прочитайте [Project geography](/ru/features/publishing/project-geography).
* Нужно определение? Прочитайте [Основные понятия безопасности](/ru/features/security/concepts).

Инструменты безопасности Replit защищают разные этапы жизненного цикла приложения и дополняют друг друга:

* **На этапе установки**: [Package Firewall](/ru/features/security/package-firewall) блокирует вредоносные и скомпрометированные пакеты ещё до их загрузки.
* **После установки**: [автоматические проверки зависимостей](/ru/features/security/project-security-center#automatic-dependency-scans) выявляют недавно опубликованные CVE, а Auto-Protect может подготовить исправления силами Agent.
* **Перед публикацией**: [Security Agent](/ru/features/security/agent-security-scans) проверяет вашу кодовую базу на уязвимости в коде, зависимостях и в части конфиденциальности.

Большинство проверок строятся по одной и той же схеме: сканирование, просмотр findings, исправление с помощью Agent, повторная публикация и, при необходимости, экспорт доказательств.

<div id="where-security-lives-in-the-product">
  ## Где в продукте реализована безопасность
</div>

<div id="in-a-project">
  ### В project
</div>

На панели **Tools** вашего project выберите **Security Center**, чтобы просмотреть findings уровня project, запустить проверки безопасности Agent и изучить уязвимости зависимостей перед публикацией.

Для анализа исходного кода используйте [проверку безопасности Agent](/ru/features/security/agent-security-scans). Если нужно дополнительно протестировать работающее приложение извне, используйте [тест на проникновение методом «чёрного ящика» уровня Level 3](/ru/features/security/black-box-pen-tests).

<div id="in-your-workspace">
  ### В вашем workspace
</div>

Выберите **Security** в боковой панели главной страницы, чтобы просмотреть уязвимости по всем projects, расставить приоритеты findings по уровню риска и отслеживать историю сканирований на уровне workspace.

<div id="in-publishing-and-settings">
  ### В публикации и настройках
</div>

* В разделе **Publish** &gt; **Advanced** включите параметр **Block publishing of critical vulnerabilities**, чтобы критические findings не попадали в релиз.
* В разделе **Settings** &gt; **Account** &gt; **Advanced** задайте порог серьёзности Auto-Protect для подготовленных Agent исправлений зависимостей.
