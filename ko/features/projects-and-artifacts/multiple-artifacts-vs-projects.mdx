[프로젝트](/ko/features/projects-and-artifacts/projects)는 Replit에서 만드는 모든 것의 컨테이너입니다. 프로젝트에는 디자인, 앱, 슬라이드, 데이터, 그리고 만드는 모든 결과물이 포함됩니다.
[아티팩트](/ko/features/projects-and-artifacts/artifacts)는 프로젝트 안에 있는 게시 가능한 결과물입니다: 웹 앱, 모바일 앱, 슬라이드 덱, 영상 등입니다.

두 가지 이상을 만들 때는 두 가지 선택이 있습니다.

* 하나의 프로젝트에 여러 아티팩트를 추가하거나,
* 별도의 프로젝트를 만드는 것입니다.

올바른 선택은 앱들이 데이터, 로직, 배포 주기를 공유하는지에 따라 달라집니다. 이 가이드는 아티팩트를 하나의 프로젝트에 유지해야 할 때와 별도로 만들어야 할 때를 설명합니다.

## 프로젝트 안에서 아티팩트가 공유하는 것

[아티팩트](/ko/features/projects-and-artifacts/artifacts)가 같은 [프로젝트](/ko/features/projects-and-artifacts/projects) 안에 있으면 다음을 자동으로 공유합니다.

* **데이터베이스**: 한 아티팩트가 데이터를 기록하면 다른 아티팩트가 즉시 읽습니다
* **백엔드와 API**: 서버 로직을 공유하므로 코드를 중복할 필요가 없습니다
* **파일 스토리지**: 이미지, 문서, 업로드된 파일을 아티팩트 전체에서 접근할 수 있습니다
* **배포**: 게시하면 모든 것이 함께 동기화되어 라이브로 전환됩니다

즉, 아티팩트 간에 연결을 설정하거나 코드를 중복할 필요가 없습니다. 하지만 하나의 아티팩트만 게시하지 않고 나머지도 함께 게시해야 한다는 의미이기도 합니다.

## 빠른 가이드

기존 프로젝트에 아티팩트를 추가할지, 별도의 프로젝트를 만들지 결정할 때 고려해야 할 주요 상황은 다음과 같습니다.

| **하나의 프로젝트에 여러 아티팩트 사용**             | **별도의 프로젝트 사용**                    |
| ------------------------------------ | ---------------------------------- |
| 앱들이 같은 데이터와 백엔드를 공유함                 | 앱들이 기본 로직이나 데이터를 공유하지 않음           |
| 모든 것을 함께 게시하고 싶음                     | 독립적인 게시 주기가 필요함                    |
| 서로 보완적인 관계임(예: 고객용 앱과 관리자 대시보드)      | 서로 관련 없는 제품이거나 다른 클라이언트를 위한 것임     |
| 한 아티팩트의 변경 사항이 다른 아티팩트에 자동으로 반영되길 원함 | 프로젝트가 단기적임(예: 캠페인 랜딩 페이지나 이벤트 사이트) |

## 예시

### 같은 프로젝트: 한 제품을 위한 웹 앱 + 모바일 앱

한 레스토랑이 고객이 메뉴를 둘러볼 수 있는 웹 앱과 직원이 주문을 관리하는 모바일 앱을 만듭니다. 둘 다 메뉴 항목, 주문, 고객 정보의 같은 데이터베이스에 연결됩니다.

**하나의 프로젝트로 만드는 이유:** 앱들이 같은 데이터와 백엔드를 공유합니다. 고객이 웹 앱을 통해 주문하면 직원은 모바일 앱에서 즉시 이를 확인할 수 있습니다.

### **같은 프로젝트**: 앱 + 관리자 대시보드 + 투자자 피치 덱

한 스타트업이 주력 제품, 콘텐츠 관리를 위한 내부 관리자 패널, 그리고 자금 조달을 위한 슬라이드 덱을 모두 한 프로젝트 안에서 만듭니다.

**하나의 프로젝트로 만드는 이유:** 관리자 대시보드는 앱이 표시하는 것과 동일한 데이터를 관리하며, 피치 덱은 공유 백엔드에서 실시간 지표를 참조할 수 있습니다.

### **별도의 프로젝트**: 관련 없는 두 클라이언트 앱

한 프리랜서가 한 클라이언트를 위한 이커머스 스토어와 다른 클라이언트를 위한 예약 시스템을 만듭니다.

**별도의 프로젝트로 만드는 이유:** 앱들이 데이터나 로직을 공유하지 않습니다. 각 클라이언트는 독립적인 게시가 필요하며, 한 앱의 변경이 다른 앱에 영향을 미치는 것을 원하지 않습니다.

### **별도의 프로젝트**: 주력 제품과 함께 있는 캠페인 랜딩 페이지

연중 운영되는 프로덕션 앱과 마케팅 캠페인을 위한 단기적인 랜딩 페이지가 있습니다.

**별도의 프로젝트로 만드는 이유:** 캠페인 페이지는 자체적인 수명 주기를 가집니다 — 만들고, 몇 주간 운영한 뒤, 내리게 됩니다. 이를 별도로 유지하면 주력 제품을 복잡하게 만들지 않고 독립적으로 게시하거나 제거할 수 있습니다.

## 자주 묻는 질문

<Accordion title="아티팩트를 다른 프로젝트로 옮길 수 있나요?">
  현재는 불가능합니다. 아티팩트를 분리해야 한다면 새로운 [프로젝트](/ko/features/projects-and-artifacts/projects)를 만들고 Agent에게 그곳에서 다시 만들어 달라고 요청하세요.
</Accordion>

<Accordion title="하나의 프로젝트가 가질 수 있는 아티팩트 수에 제한이 있나요?">
  프로젝트는 최대 7개의 아티팩트를 가질 수 있습니다. 이 제한이 있는 이유는 아티팩트가 늘어날수록 더 많은 메모리를 사용하여 프리뷰 속도가 느려질 수 있기 때문입니다. 더 많은 아티팩트가 필요하다면 새로운 [프로젝트](/ko/features/projects-and-artifacts/projects)를 시작하세요.
</Accordion>

<Accordion title="프로젝트에서 아티팩트 하나만 게시할 수 있나요?">
  현재는 불가능합니다. 게시하면 모든 것이 함께 라이브로 전환됩니다. 독립적인 게시가 필요하다면 별도의 프로젝트를 사용하세요.
</Accordion>
