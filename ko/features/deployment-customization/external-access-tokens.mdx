외부 액세스 토큰은 특정 Replit App용으로 발급하는 bearer token입니다.
[Private Dev URL](/ko/features/publishing/private-deployments)이나
[Private Deployment](/ko/features/publishing/private-deployments)로 앱의 URL이 차단된 상태에서도
CI pipeline, webhook, status 확인용 ping 도구, Slack 봇, 내부 스크립트 등
자동화된 서비스가 앱에 접근할 수 있게 해줍니다.

토큰은 비밀번호처럼 취급하세요. 토큰이 만료되거나 직접 폐기하기 전까지는
토큰을 가진 사람은 누구나 앱에 접근할 수 있습니다.

<Note>
  외부 액세스 토큰은 deployment에 비공개 액세스를 선택하면 사용할 수 있습니다.
  workspace 차원의 별도 설정은 필요하지 않습니다. Enterprise workspace에서는
  workspace admin만 토큰을 관리할 수 있습니다.
</Note>

<div id="when-to-use-a-token">
  ## token을 사용해야 하는 경우
</div>

브라우저 *외부*의 무언가가 비공개 Replit App을 호출해야 할 때 외부 접근 token을 사용하세요. 대표적인 사례는 다음과 같습니다.

* commit할 때마다 개발 URL을 대상으로 스모크 테스트를 실행하는 GitHub Actions workflow
* published app의 상태 확인 엔드포인트를 호출하는 uptime 모니터(Better Stack, Pingdom, UptimeRobot)
* Private Deployment로 POST 요청을 보내는 webhook 수신자 — Stripe, Slack, GitHub
* 디버깅 중 팀원의 컴퓨터에서 보내는 `curl` 또는 `fetch` 호출

외부 접근 token은 브라우저에서 UI 페이지를 여는 용도가 아니라 **API 트래픽**을 위해 설계되었습니다. 단일 페이지 앱(Vite, Next.js 등)은 follow-up 요청으로 JavaScript 번들을 불러오는데, 이러한 요청에는 token이 실리지 않으므로 실패합니다. 인터랙티브하게 둘러보려면 평소대로 로그인하세요.

<div id="token-environments">
  ## 토큰 환경
</div>

각 토큰은 하나의 환경에만 연결됩니다.

| Environment   | 작동 범위                                             | 용도                             |
| :------------ | :------------------------------------------------ | :----------------------------- |
| `Development` | 앱의 workspace 개발 URL(`*.replit.dev`)               | 개발 중 실행 중인 Repl 호출             |
| `Production`  | 앱의 게시된 deployment(`*.replit.app` 및 custom domain) | 외부 서비스에서 Private Deployment 호출 |

`Production` 토큰은 새 버전 게시를 포함해 republish를 해도 그대로 유지됩니다.
다음의 경우 Replit이 토큰을 취소합니다.

* deployment 게시를 취소할 때
* deployment를 삭제할 때
* 앱의 접근 권한을 비공개에서 공개로 변경할 때

토큰이 만료되거나 사용자가 직접 취소한 경우에도 토큰은 더 이상 작동하지 않습니다.

<div id="create-an-external-access-token">
  ## 외부 액세스 토큰 생성
</div>

<Steps>
  <Step>
    외부에 노출하려는 앱을 연 다음 **Publishing** 도구를 엽니다.
  </Step>

  <Step>
    **Adjust settings**를 선택해 재배포 옵션을 펼칩니다.
  </Step>

  <Step>
    **Security** 섹션에서 **External access tokens**를 찾습니다.
  </Step>

  <Step>
    **Create access token**을 선택하고 다음 항목을 입력합니다.

    * **Label**(선택 사항): 나중에 토큰을 알아볼 수 있도록 지정하는 짧은 이름으로,
      `CI`나 `Stripe webhook` 등이 있습니다. 최대 120자입니다.
    * **Environment**: 호출하는 서비스가 앱에 접근해야 하는 환경에 따라
      `Development` 또는 `Production`을 선택합니다.
    * **Expires after**: 유효 기간을 선택합니다 — `1 hour`, `24 hours`, `7 days`,
      `30 days`, `3 months`, `1 year`, `5 years`. 해당 job에 필요한 최소한의 기간을
      선택하세요. &quot;만료되지 않음&quot; 옵션은 없습니다.
  </Step>

  <Step>
    **Create**를 선택합니다.
  </Step>
</Steps>

Replit은 토큰을 **한 번만** 표시합니다. 지금 복사해 두세요. 대화 상자를 닫으면
토큰을 다시 확인할 방법이 없습니다. 토큰을 분실했다면 해당 토큰을 취소하고
새로 발급하세요.

토큰 표시 화면에서는 두 가지 복사 방식을 제공합니다.

* **Copy query parameter** — URL 뒤에 붙일 수 있도록 `?project-protection-bypass=<token>`을 복사합니다. 간단한 `curl` 확인에 유용합니다.
* **Copy token only** — 토큰 값만 복사하므로 `Authorization: Bearer` 헤더에
  담아 보내기에 적합합니다.

<Info>
  첫 토큰을 생성하면 해당 앱의 외부 액세스가 꺼져 있던 경우 자동으로 켜집니다.
  보호가 적용되어 있지 않으면 토큰이 우회할 대상 자체가 없기 때문입니다.
</Info>

<div id="use-a-token">
  ## token 사용하기
</div>

다음 두 가지 방법 중 하나로 token을 전달하세요.

<div id="authorization-header-recommended">
  ### Authorization 헤더(권장)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

webhook, CI 스크립트, backend 간 호출 등 거의 모든 상황에서 가장 적합한 방식입니다.
token이 URL을 기록하는 logs에 남지 않고, 브라우저 방문 기록에도 남지 않습니다.

<div id="query-parameter">
  ### 쿼리 매개변수
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

쿼리 매개변수 방식은 headers를 설정할 수 없을 때만 사용하세요. 예를 들어 URL만 받는 서비스가 그렇습니다. token이 포함된 URL은 프록시 logs, shell 기록, 스크린샷에 그대로 남는 경우가 많으므로 가능하면 header 방식을 사용하세요.

<div id="manage-existing-tokens">
  ## 기존 토큰 관리
</div>

**External access tokens** 섹션에는 해당 앱에서 생성한 모든 token이 최신순으로 나열되며 label, environment, 생성 날짜, 만료일, 해지 상태가 함께 표시됩니다. 전체 값은 생성 시점에만 표시되므로, 토큰을 서로 구분할 수 있도록 각 행에 token의 마지막 몇 글자가 표시됩니다.

*본인*이 생성한 token만 볼 수 있습니다. 앱을 소유하고 있더라도 다른 공동 작업자의 token은 해당 사용자에게만 표시됩니다.

<div id="revoke-a-token">
  ## token 취소
</div>

token이 더 이상 필요하지 않거나 유출이 의심되면 즉시 해당 token을 취소하세요. 취소 방법은 다음과 같습니다.

<Steps>
  <Step>
    앱의 Publishing 설정에서 **External access tokens** 섹션을 엽니다.
  </Step>

  <Step>
    목록에서 해당 token을 찾아 휴지통 icon을 선택합니다.
  </Step>

  <Step>
    취소를 확인합니다.
  </Step>
</Steps>

취소는 **즉시 적용되며 되돌릴 수 없습니다**. 해당 token을 계속 사용하는 트래픽은 몇 초 안에 거부되기 시작합니다. 다시 접근해야 한다면 새 token을 발급하세요.

취소는 본인이 생성한 token에 대해서만 가능합니다. workspace에서 공동 작업자를 제거하면 해당 사용자가 그 앱에 대해 발급한 token은 자동으로 취소됩니다.

<div id="keep-your-tokens-safe">
  ## token 안전하게 관리하기
</div>

External access tokens는 자격 증명입니다. API key나 비밀번호와 동일한 수준으로
주의해서 다루세요.

<div id="do">
  ### 권장 사항
</div>

* **secret 관리 도구에 token을 저장하세요** — GitHub Actions secrets, 사용 중인 CI
  vendor의 vault, 클라우드 provider의 secret 저장소, 비밀번호 관리자 등을 활용하세요.
  절대로 저장소에 commit하지 마세요.
* 가능하면 **유효 기간을 짧게 설정하세요**. 일회성 integration에 쓰는 7일짜리 token이
  방치된 5년짜리 token보다 안전합니다.
* **모든 token에 label을 지정하세요.** 그래야 나중에 그 token의 용도와 아직
  사용 중인지 여부를 알 수 있습니다. label이 없는 token은 가장 먼저 유출되고 가장 늦게
  폐기됩니다.
* **사용 주체마다 별도의 token을 발급하세요.** CI job마다 하나, webhook 출처마다 하나,
  uptime 점검마다 하나씩입니다. 특정 token이 compromised되거나 해당 vendor가
  더 이상 필요 없어지면 그 token 하나만 폐기하면 됩니다.
* query parameter 대신 **`Authorization` header를 사용하세요.** 그래야 token이
  URL logs, 브라우저 기록, referer headers를 통해 유출되지 않습니다.
* token이 노출되었을 가능성이 있다면 **즉시 폐기하세요.** 유출된 로그,
  공개 저장소 commit, 화면 공유, 퇴사한 직원의 노트북 등이 이에 해당합니다.
  폐기는 곧바로 적용되며, 새 token은 그 후에 발급하세요.

<div id="dont">
  ### 하지 말아야 할 것
</div>

* **팀원이나 서비스 간에 token을 공유하지 마세요.** 두 시스템이 하나의 token을
  공유하면, 한쪽을 폐기하는 순간 다른 쪽도 함께 동작을 멈춥니다.
* **채팅, 이메일, 스크린샷, 이슈 트래커에 token을 붙여넣지 마세요.**
  이러한 채널은 예측할 수 없는 방식으로 보관되고, 색인되며, 공유됩니다.
* **클라이언트 측 코드에 token을 포함하지 마세요.** 브라우저 앱, mobile app,
  데스크톱 바이너리 등이 여기에 해당합니다. 사용자 기기로 전달되는 모든 것은
  공개된 것으로 간주해야 합니다.
* **브라우저 session에 token을 사용하지 마세요.** token은 API 호출에는 적합하지만,
  브라우저 tab에서 SPA를 로드하는 용도로는 적합하지 않습니다. 그럴 때는 일반적인 Replit 로그인을 사용하세요.
* **기본값으로 5년 만료를 선택하지 마세요.** 사용 주체가 실제로 접근이 필요한
  기간에 맞춰 유효 기간을 설정하세요.

<div id="troubleshooting">
  ## 문제 해결
</div>

<Accordion title="production 토큰이 갑자기 작동하지 않습니다">
  production 토큰은 일반적인 Republish 후에도 계속 유효합니다. 토큰이 만료되었는지,
  또는 직접 취소했는지 확인하세요. 앱의 게시를 해제했거나 deployment를 삭제하지는
  않았는지, 앱을 Private에서 공개로 변경하지는 않았는지도 확인하세요. 앱에
  더 이상 Private Deployment가 없다면 비공개로 Publish한 뒤 새 토큰을
  발급하세요. 만료되었거나 취소된 토큰은 되살릴 수 없습니다.
</Accordion>

<Accordion title="`curl`에서는 토큰이 작동하는데 브라우저에서는 여전히 로그인 페이지가 표시됩니다">
  External access tokens는 브라우저 session이 아니라 API 트래픽을 위한 것입니다.
  단일 페이지 앱이 브라우저에서 로드될 때 최초 HTML 요청은 query parameter로
  토큰을 전달할 수 있지만, 이후 이어지는 JavaScript 번들, CSS, API 호출 요청에는
  토큰이 포함되지 않아 거부됩니다. 앱을 인터랙티브하게 이용하려면
  Replit에 평소처럼 로그인하세요.
</Accordion>

<Accordion title="토큰을 분실했습니다 — 다시 볼 수 있나요?">
  아니요. Replit은 생성 시점에 토큰을 한 번만 표시합니다. 목록 화면에서는
  메타데이터(label, Environment, 만료일, 마지막 몇 글자)를 확인할 수 있지만 전체 토큰
  값은 절대 표시되지 않습니다. 토큰을 분실했다면 해당 토큰을 취소하고 새로
  만드세요.
</Accordion>
