Ce guide vous explique pas à pas comment créer une app OAuth Google dans la Google Cloud Console. Vous récupérerez un **Client ID** et un **Client Secret**, puis configurerez les origines JavaScript et les URI de redirection exigées par Clerk.

<Note>
  Cette page couvre uniquement la configuration côté fournisseur dans la Google Cloud Console. Pour le déroulement complet de Clerk Auth — y compris l&#39;activation de Google et la saisie des identifiants dans le **panneau Auth** — consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) dans la documentation de Clerk Auth.
</Note>

<div id="pr-requisitos">
  ## Prérequis
</div>

* Accès à la [Google Cloud Console](https://console.cloud.google.com/)
* Une [app Replit publiée](/fr/category/replit-deployments) — les identifiants OAuth personnalisés sont uniquement disponibles dans l’environnement de **Production**
* Le panneau de modification du fournisseur **Google** ouvert : **panneau Auth** → onglet **Configure** → section **fournisseur SSO** → sélectionnez l’environnement **Production** → sélectionnez **Edit** à côté de **Google**

<div id="passo-1-criar-um-app-oauth-do-google">
  ## Étape 1 : Créer une app OAuth Google
</div>

Accédez à la [Google Cloud Console](https://console.cloud.google.com/) :

<div id="criar-ou-selecionar-um-projeto">
  ### Créer ou sélectionner un projet
</div>

1. Sélectionnez un projet existant ou créez-en un dans le menu déroulant des projets.
2. Vous serez redirigé vers le tableau de bord de votre projet.

<div id="configurar-a-tela-de-consentimento-oauth">
  ### Configurer l&#39;écran de consentement OAuth
</div>

1. Dans la barre latérale de gauche, sélectionnez l&#39;icône de menu (≡), puis **APIs &amp; Services**
2. Sélectionnez **OAuth consent screen**
3. Configurez l&#39;écran de consentement de votre app avec les informations requises
4. Enregistrez vos modifications

<div id="criar-credenciais-oauth">
  ### Créer des identifiants OAuth
</div>

1. Dans **APIs &amp; Services**, sélectionnez **Credentials**
2. Sélectionnez **Create Credentials** en haut, puis **OAuth client ID**
3. Choisissez **Web application** comme type d&#39;application
4. Renseignez **Authorized JavaScript origins** et **Authorized redirect URIs** avec les valeurs exactes affichées dans **Provider setup**, dans le **panneau Auth**. Ajoutez toutes les valeurs listées : votre domaine publié et vos éventuels domaines personnalisés en font partie. Consultez [Configurer des identifiants OAuth pour un provider SSO](/fr/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) pour savoir où les trouver.
5. Sélectionnez **Create**
6. Enregistrez votre **Client ID** et votre **Client Secret**

<Warning>
  Conservez votre Client Secret en lieu sûr et ne l&#39;ajoutez jamais au contrôle de version.
</Warning>

<Warning>
  La connexion avec Google ne fonctionne pas dans les navigateurs intégrés ni dans les webviews au sein des apps. Les utilisateurs doivent utiliser un navigateur web standard.
</Warning>

<div id="soluo-de-problemas">
  ## Dépannage
</div>

<div id="incompatibilidade-de-uri-de-redirecionamento">
  ### Incompatibilité de l’URI de redirection
</div>

* Vérifiez que l’URI de redirection dans la Google Cloud Console correspond exactement à la valeur affichée dans **Provider setup** du **panneau Auth**
* Assurez-vous qu’il n’y a ni barre oblique finale ni faute de frappe
* Attendez quelques minutes que la configuration Google se propage

<div id="cliente-invlido">
  ### Client non valide
</div>

* Vérifiez que le Client ID et le Client Secret ont été correctement copiés
* Assurez-vous qu’il n’y a pas d’espaces superflus
* Vérifiez que l’écran de consentement OAuth est configuré

<div id="no-est-funcionando-no-domnio-personalizado">
  ### Ne fonctionne pas sur un domaine personnalisé
</div>

* Ajoutez les entrées de domaine personnalisé affichées dans **Provider setup** du **panneau Auth** aux champs Authorized JavaScript origins et Authorized redirect URIs
