<div id="como-o-replitmd-funciona">
  ## Comment fonctionne `replit.md`
</div>

L&#39;Agent commence par créer un fichier `replit.md` dans le répertoire racine de votre projet en s&#39;appuyant sur des bonnes pratiques éprouvées. Ce fichier contient :

* Les informations de base du projet
* Les standards de codage recommandés
* Les préférences courantes pour votre type de projet

<YouTubeEmbed videoId="kYv525W-vaU" title="Personnalisez la façon dont Replit Agent répond" />

Lorsque l&#39;Agent traite vos demandes, il lit automatiquement votre fichier `replit.md` et en utilise le contenu pour :

* Comprendre l&#39;architecture et les conventions de votre projet
* Respecter vos standards et votre style de codage préférés
* Utiliser les gestionnaires de paquets et les dépendances que vous avez indiqués

L&#39;Agent peut également mettre à jour votre fichier `replit.md` au fur et à mesure qu&#39;il en apprend davantage sur votre projet et apporte des modifications à votre application.

<Note>
  Vous pouvez modifier le fichier `replit.md` pour personnaliser le comportement de l&#39;Agent.
</Note>

<div id="configurando-o-replitmd">
  ## Configuration du fichier `replit.md`
</div>

<div id="gerao-automtica">
  ### Génération automatique
</div>

Lorsque vous créez un projet avec Agent, celui-ci génère automatiquement un fichier `replit.md` en s&#39;appuyant sur des bonnes pratiques éprouvées. Ce fichier apparaît dans le répertoire racine de votre projet et contient :

* Les informations de base du projet
* Les conventions de codage recommandées
* Les préférences courantes pour votre type de projet

<div id="criao-manual">
  ### Création manuelle
</div>

Vous pouvez créer votre propre fichier `replit.md` en ajoutant un nouveau fichier nommé `replit.md` dans le répertoire racine de votre projet. Agent le détectera et l&#39;utilisera automatiquement lors des conversations suivantes.

<Note>
  Le fichier `replit.md` doit se trouver dans le répertoire racine de votre projet pour fonctionner correctement.
</Note>

<div id="regenerando-o-replitmd">
  ### Régénérer le fichier `replit.md`
</div>

Si votre fichier `replit.md` est corrompu ou si vous souhaitez repartir de zéro :

1. Supprimez le fichier `replit.md` existant à la racine de votre projet
2. Démarrez une nouvelle conversation avec Agent
3. Agent générera automatiquement un nouveau fichier `replit.md` à partir de votre projet actuel

<div id="boas-prticas">
  ## Bonnes pratiques
</div>

<div id="seja-especfico-e-claro">
  ### Soyez précis et clair
</div>

Rédigez des instructions claires et précises qui permettent à Agent de comprendre exactement ce que vous souhaitez :

```markdown theme={null}
## Style de code

- Utilisez TypeScript pour tous les nouveaux fichiers JavaScript
- Privilégiez les composants fonctionnels avec des hooks plutôt que les composants de classe
- Utilisez Tailwind CSS pour le style, évitez les styles en ligne
- Indiquez toujours les types TypeScript des paramètres et des valeurs de retour des fonctions
```

Pour un guide plus détaillé sur la mise en forme des prompts, consultez le [guide d&#39;ingénierie des prompts d&#39;Anthropic](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags).

<div id="defina-preferncias-de-comunicao">
  ### Définissez vos préférences de communication
</div>

Indiquez à Agent comment vous préférez recevoir les informations et les mises à jour :

```markdown theme={null}
## Style de communication

- Avant d'apporter des modifications, expliquez ce que vous allez faire et pourquoi
- Découpez les tâches complexes en étapes claires
- Demandez des précisions si les besoins ne sont pas clairs
- Justifiez brièvement les décisions techniques
```

<div id="especifique-o-contexto-do-projeto">
  ### Précisez le contexte du projet
</div>

Aidez Agent à comprendre l&#39;objectif et les contraintes de votre projet :

```markdown theme={null}
## Contexte du projet

Il s'agit d'une application de réseau social destinée aux amoureux des livres, où les utilisateurs peuvent :
- Créer des listes de lecture et partager des recommandations de livres
- Suivre d'autres lecteurs et consulter leurs actualités
- Noter et commenter les livres qu'ils ont lus

Public cible : lecteurs occasionnels de 25 à 45 ans
Stack technique : frontend React, backend Node.js, base de données PostgreSQL
```

<div id="projeto-de-aplicao-web">
  ### Projet d&#39;application web
</div>

```markdown theme={null}
# Consignes du projet MyApp

## Présentation du projet
Une application web de gestion de tâches développée avec React et Express.js.

## Préférences technologiques
- Frontend : React avec TypeScript, Tailwind CSS
- Backend : Express.js avec TypeScript
- Base de données : Neon PostgreSQL avec l'ORM Drizzle
- Gestionnaire de paquets : npm (ni yarn ni pnpm)

## Normes de codage
- Utiliser des composants fonctionnels avec des hooks
- Mettre en place des error boundaries adaptées
- Respecter les conventions d'API REST pour les endpoints
- Utiliser des noms de variables et de fonctions explicites

## Style de communication
- Expliquer votre approche avant d'apporter des modifications
- Ajouter des commentaires de code pour la logique complexe
- Poser des questions si les exigences sont ambiguës
```

<div id="projeto-de-anlise-de-dados">
  ### Projet d&#39;analyse de données
</div>

```markdown theme={null}
# Consignes du projet d'analyse de données

## Contexte du projet
Analyse des données de comportement client afin d'identifier des tendances et d'en tirer des enseignements.

## Préférences technologiques
- Python avec Streamlit pour les applications web interactives
- pandas, numpy et matplotlib pour l'analyse de données

## Normes d'analyse
- Fournir une documentation claire pour chaque étape de l'analyse
- Créer des visualisations interactives avec les composants Streamlit
- Valider la qualité des données avant l'analyse
- Exporter les résultats au format CSV et les afficher dans des tableaux Streamlit

## Style de communication
- Expliquer les méthodes statistiques et les hypothèses retenues
- Replacer les constats et les recommandations dans leur contexte
- Employer un langage clair et non technique pour les enseignements métier
- Créer des tableaux de bord interactifs pour les présentations aux parties prenantes
```

<div id="projeto-de-desenvolvimento-de-api">
  ### Projet de développement d&#39;API
</div>

```markdown theme={null}
# Directives de développement d'API

## Présentation du projet
Développement d'une API RESTful pour le backend d'une application mobile.

## Pile technologique
- Node.js with Express.js
- MongoDB with Mongoose
- JWT pour l'authentification
- Gestionnaire de paquets : npm

## Standards d'API
- Utiliser des codes de statut HTTP sémantiques
- Mettre en place une validation rigoureuse des entrées
- Appliquer une limitation de débit sur les points de terminaison publics
- Suivre la spécification OpenAPI pour la documentation

## Exigences de sécurité
- Valider toutes les entrées utilisateur
- Utiliser des variables d'environnement pour les données sensibles
- Mettre en place des politiques CORS adaptées
- Journaliser les requêtes pour faciliter le débogage

## Approche de test
- Écrire des tests unitaires pour tous les points de terminaison
- Prévoir des tests d'intégration pour les flux critiques
- Utiliser Jest comme framework de test
```

<div id="combinando-pesquisa-na-web-com-o-replitmd">
  ## Combiner la recherche web avec le fichier `replit.md`
</div>

Agent peut effectuer des recherches sur le web pour trouver des informations, des bibliothèques et des solutions à jour. En le combinant avec votre fichier `replit.md`, vous bénéficiez à la fois de connaissances actualisées et de conseils propres à votre projet.

<div id="boas-prticas-para-integrao-de-pesquisa-na-web">
  ### Bonnes pratiques pour l&#39;intégration de la recherche web
</div>

**Soyez précis sur ce que vous souhaitez faire rechercher à l&#39;Agent :**

```markdown theme={null}
## Research Preferences
- Always check for the latest versions of dependencies before suggesting updates
- Research current best practices for security implementations
- Look up recent performance optimization techniques for our tech stack
```

**Indiquez à Agent comment exploiter les connaissances externes :**

```markdown theme={null}
## External Research Guidelines
- When suggesting new libraries, ensure compatibility with our existing stack
- Adapt external examples to match our coding standards and project structure  
- Verify that suggested solutions work with our publishing environment
```

**Exemple de requête combinant les deux :**
&quot;Research the latest React 18 performance optimization techniques and implement them following the component patterns defined in `replit.md`&quot;

Cette approche fournit des solutions à la fois à jour et adaptées aux besoins spécifiques de votre projet.

<div id="limitaes">
  ## Limitations
</div>

<div id="limites-de-tamanho-e-contedo-do-arquivo">
  ### Limites de taille et de contenu du fichier
</div>

Bien qu&#39;aucune limite stricte de caractères ne s&#39;applique au fichier `replit.md`, les fichiers très volumineux risquent de ne pas être traités intégralement. Veillez à garder votre `replit.md` ciblé et concis pour obtenir les meilleurs résultats.

<div id="requisito-de-diretrio-raiz">
  ### Exigence liée au répertoire racine
</div>

Le fichier `replit.md` doit se trouver dans le répertoire racine de votre projet. Agent ne détecte pas automatiquement les fichiers placés dans des sous-répertoires.

<div id="alcance-do-contexto">
  ### Portée du contexte
</div>

Le fichier `replit.md` fournit du contexte aux conversations avec Agent, mais il ne s&#39;applique pas automatiquement aux autres outils d&#39;IA.
