L'Auth — abréviation d'**authentification** — est ce qui donne à votre application le concept d'un « utilisateur ». Sans auth, chaque visiteur est anonyme et votre application ne peut pas distinguer une personne d'une autre. Avec l'auth, chaque visiteur se connecte, votre application sait qui il est et vous pouvez sauvegarder des données spécifiques à lui : ses réservations, ses voitures sauvegardées, ses préférences, sa progression.

Une fois l'auth intégrée, vous pouvez :

* Sauvegarder des données par utilisateur — réservations, paramètres, contenu, historique.
* Restreindre des fonctionnalités derrière une connexion (un paiement, une page de profil, un panneau d'administration).
* Personnaliser l'expérience par nom, rôle, plan ou comportement passé.
* Suivre l'activité et l'utilisation par individu plutôt que par session.

## Comment fonctionne l'auth dans une application Replit

Replit propose deux options d'auth intégrées. Les deux sont provisionnées par Agent — pas d'inscription séparée au tableau de bord, pas de copier-coller de clés OAuth.

* **[Replit Auth](/fr/features/auth-and-identity/authentication)** — vos utilisateurs se connectent avec leurs **comptes Replit** existants. La page de connexion est aux couleurs de Replit. Il n'y a aucune configuration au-delà de demander à Agent de l'ajouter.
* **[Clerk Auth](/fr/features/auth-and-identity/clerk-auth)** — votre application obtient son propre **locataire Clerk** dédié. Les utilisateurs créent des comptes dans *votre* application, pas Replit. Vous contrôlez la marque, les méthodes de connexion et l'apparence de l'écran de connexion.

Les deux options gèrent le travail lourd — pages de connexion, sessions, gestion sécurisée des mots de passe, connexions sociales — de sorte que votre code d'application n'a qu'à demander : « qui est l'utilisateur connecté ? »

## Replit Auth vs. Clerk Auth

|                         | Replit Auth                                                                       | Clerk Auth                                                                               |
| ----------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **Comptes utilisateur** | Les utilisateurs se connectent avec un compte Replit                              | Les utilisateurs créent des comptes dans votre application (pas besoin de compte Replit) |
| **Marque**              | Page de connexion aux couleurs de Replit                                          | Entièrement personnalisable — nom, icône et couleurs de votre application                |
| **Identifiants SSO**    | Utilise les applications OAuth partagées de Replit                                | Apportez vos propres identifiants OAuth par fournisseur                                  |
| **Environnements**      | Environnement unique                                                              | Environnements de développement et de production séparés                                 |
| **Idéal pour**          | Configuration rapide, prototypes, applications où la marque Replit est acceptable | Applications de marque, produits professionnels et commerciaux                           |

Si vous construisez un prototype ou un outil interne, Replit Auth est la voie la plus rapide. Si vous construisez quelque chose avec sa propre identité de marque, en particulier quelque chose destiné aux clients ou commercial, Clerk Auth est le meilleur choix.

## Ajouter l'auth à votre application

Vous n'avez pas à choisir à l'avance — vous pouvez commencer avec l'un et migrer plus tard. La voie la plus rapide est de dire à Agent lequel utiliser :

* *« Ajoute la connexion à mon application. Utilise Replit Auth. »*
* *« Ajoute la connexion à mon application. Utilise Clerk Auth. »*
