---
title: "Replit 责任共担模型"
description: "介绍在 Replit 上构建、发布和运行应用时，安全、合规与运维责任如何在 Replit 与用户之间分担。"
---

安全地构建和发布应用是双方共同的责任。Replit 负责保障运行客户工作负载的 Replit Agent、平台及基础设施的安全，以合理的控制措施和安全的默认配置运营这些组件，并提供可用于保护应用程序和数据的工具。用户则负责应用程序的内容，以及对 Replit 所提供工具的使用与配置。

这是一种有意为之的平衡。Replit 希望用户能构建出心中所想的任何东西，而这种自由意味着部分决定要交由用户自己来做。下表参照成熟的云与 AI 责任共担模式 ([Microsoft AI SRM](https://learn.microsoft.com/en-us/azure/security/fundamentals/shared-responsibility-ai)、[CSA AICM](https://cloudsecurityalliance.org/artifacts/ai-controls-matrix)) ，并依据 [ISO/IEC 42001](https://www.iso.org/standard/42001) 和 [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)，展示了 Replit 的责任共担模型：

<div id="section-5">
  ## 责任如何划分
</div>

表格中的大多数条目都遵循以下三种模式之一：

* **机制与配置。** Replit 提供各类控制手段：RBAC、可见性设置、MFA、SSO、数据驻留、保留期限。至于启用哪些、如何配置，则由用户决定。
* **检测与修复。** Replit 负责监控平台，并呈现平台可见的信息：存在漏洞的依赖项、滥用信号、平台异常。用户则负责监控和修复应用程序内部的问题，因为只有用户才清楚在自己应用的语境中「已修复」意味着什么。
* **第一方与第三方。** 经 Replit 审核的 skills、MCP 工具和 Connectors，由 Replit 负责审核。而用户自行连接、安装或接入的内容，则由用户负责审查、配置、轮换和撤销。

有些条目完全由用户负责：使用政策、访问控制、知识产权审查、面向最终用户的隐私声明、应用程序层面的渗透测试。它们都依赖于只有用户才掌握的上下文。另一些条目则由 Replit 负责：即应用得以构建和运行的平台本身。

这些模式反复出现，是有意为之。对于一个以「自由构建任何东西」为宗旨的平台而言，这是划分责任唯一诚实的方式。

<div id="replit-agent-2">
  ## 与 Replit Agent 协作
</div>

你拥有 Agent 生成的代码，并对其负责。具体来说，这意味着要养成以下几个习惯：

1. **发布前先审查。** Agent 能生成可运行的代码，但&quot;能运行&quot;不等于&quot;正确&quot;。请仔细阅读生成的代码，尤其是涉及身份验证、数据处理以及跨越信任边界的部分。让 Agent 编写测试并解释其推理过程，是在迭代中发现回归问题的好办法。
2. **不要把密钥写进提示词。** 请使用 Secrets 功能和 Connectors，不要把 API 密钥、令牌或凭据粘贴到聊天中。即使拿不到明文，Agent 也照样能使用它们；而一旦粘贴，受管理的密钥就变成了不受管理的密钥。
3. **说明业务逻辑和访问控制模型。** 告诉 Replit Agent 谁可以访问应用的哪些功能。如果你的应用并非面向所有人开放，请选择 Replit 的 Private 或 Password-protected 发布选项。
4. **有意识地批准敏感操作。** 当 Agent 提议发布应用、修改密钥或发起对外调用时，人在回路中的这一步由你把关。请把它当作一次真正的审查，而不是随手点过。

<div id="section-6">
  ## 合规与事件响应
</div>

您有责任遵守 [Replit 服务条款](https://replit.com/terms-of-service)，并了解自身适用的合规与法律要求。如需了解 Replit 在合规方面提供与不提供的内容 (SOC 2 Type II、子处理方、认证等) ，请访问 [replit.com/security](https://replit.com/security)。

如果您在 Replit 平台上发现漏洞，请按照 Replit 的[负责任披露](https://en.wikipedia.org/wiki/Coordinated_vulnerability_disclosure)流程报告至 [security@replit.com](mailto:security@replit.com)。如果漏洞出现在您自己构建的应用中，则由您自行进行分级处理。平台层面的事件将依据 Replit 的事件响应政策处理；源于您的应用、数据或最终用户账户的事件则由您主导处理。
