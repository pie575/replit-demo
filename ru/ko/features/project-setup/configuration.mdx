Replit App настраивается двумя файлами: `.replit` и `replit.nix`. Они определяют, как работает Replit App, — от запуска кода до инструментов разработки и языков программирования.

По умолчанию файлы конфигурации скрыты. Чтобы увидеть их в Replit App, выберите «Показать скрытые файлы» в меню дерева файлов.

<div id="replitnix">
  ## Файл `replit.nix`
</div>

Replit использует `Nix` для управления пакетами и окружением. Файл `replit.nix` служит для следующего:

**Указание системных зависимостей:** с помощью пакетного менеджера Nix вы точно определяете, какие программные пакеты нужны вашему Replit App.

**Создание воспроизводимого окружения:** среда разработки остаётся單 согласованной и воспроизводимой, что идеально подходит для совместных проектов и тестирования на разных системах.

Управлять пакетами Nix визуально можно с помощью инструмента `Dependencies`. Подробнее см. в руководстве [Системные зависимости](/ru/ko/features/project-setup/dependency-management#system-dependencies).

Чтобы настроить пакеты в файле `replit.nix`, перечислите [пакеты Nix](https://search.nixos.org/packages) в массиве `deps`, добавив к ним префикс `pkgs.`. Изменения синхронизируются после перезагрузки Shell.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="replit">
  ## Файл `.replit`
</div>

Файл `.replit` управляет поведением Replit App. Он использует [формат конфигурации](https://toml.io/en/) `toml`. Ниже перечислены основные параметры, которые можно настроить:

**Команда запуска:** задаёт команду, которая выполняется при нажатии кнопки Run. В каждом шаблоне есть команда запуска по умолчанию, чтобы вы могли сразу запустить код. Для более гибких и сложных приложений используйте [Workflows](/ru/ko/features/workspace-tools/workflows).

**Протокол языкового сервера (LSP):** предоставляет такие возможности, как автодополнение, навигация по коду, подсветка кода, линтинг в реальном времени и отображение ошибок.

**Переменные окружения:** позволяют задавать и настраивать переменные окружения, необходимые для корректной работы приложения.

**Зависимости и пакеты:** управляйте установкой и настройкой пакетов напрямую через файл `.replit`, чтобы при запуске Replit App все необходимые инструменты были готовы. Зависимостями также можно управлять наглядно — с помощью инструмента `Dependencies`. Подробнее см. руководство по [системным модулям](/ru/ko/features/project-setup/dependency-management#advanced-configuration).

Для приложения на Python файл `.replit` по умолчанию выглядит так:

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

Теперь, когда вы разобрались с основной конфигурацией файла `.replit`, в следующем разделе мы рассмотрим, как настраивать базовые и расширенные параметры Replit App.

<div id="section">
  ## Настройка основных параметров
</div>

<div id="entrypoint">
  ### Точка входа (Entrypoint)
</div>

Основной файл проекта. Если свойство `run` не задано, среда выполнения запускает файл, указанный в `entrypoint`.

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="run">
  ### Команда `Run`
</div>

Свойство `run` в файле `.replit` — это ключевая настройка, которая определяет, какая команда или последовательность команд выполняется первой при нажатии кнопки `Run` в окружении Replit. Команду `Run` можно задать строкой с командой либо массивом строк, где перечислены сама команда и её аргументы по отдельности.

Распространённые способы настройки команды `Run`:

* **Одна команда:**
  Позволяет напрямую выполнить одну команду в Replit App. Если добавить это в файл `.replit`, при нажатии кнопки `Run` в окне `Console` появится приветствие:
  **Пример:** `run = "echo 'Hello, Replit!'"`

* **Явные аргументы:**
  Иногда команду удобнее записать более явно, чтобы обойти разбор кавычек и правила подстановки в Shell. Пример выше можно переписать, разделив аргументы.
  Приветствие передаётся явно как первый и единственный аргумент `echo`, поэтому ни `'`, ни `"` не нужны:
  **Пример:** `run = ["echo", "Hello, Replit!"]`

* **Несколько команд:**
  Позволяет одновременно запустить несколько процессов, например фронтенд и бэкенд. Удобно при разработке Python-бэкенда и TypeScript-фронтенда, когда каждый сервер привязан к своему порту:
  **Пример:** `run = "python -m app & npm run start & wait"`

<div id="section-2">
  #### Управление процессами
</div>

С помощью `&` можно запускать несколько команд одновременно, но иногда логи разных сервисов удобнее разделить более чётко. Добавьте [системную зависимость](/ru/ko/features/project-setup/dependency-management#system-dependencies) вроде [`process-compose`](https://github.com/F1bonacc1/process-compose) — так управлять несколькими процессами будет намного удобнее.

<div id="build">
  #### Этап `Build`
</div>

Для компилируемых языков, таких как TypeScript, Golang и Java, или в случаях, когда перед следующим `run` нужно сбросить окружение, данные и конфигурацию, перед выполнением `run` может потребоваться отдельный этап компиляции.

* **Компиляция:**
  В репозитории TypeScript перед запуском кода может потребоваться сначала выполнить `tsc`.
  **Пример:**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="section-3">
  #### Передача переменных окружения
</div>

Чтобы передать сервису переменные окружения перед запуском, можно расширить свойство `run` до [таблицы](https://toml.io/en/v1.0.0#table).

Это более сложное изменение: возможно, потребуется переместить свойство `run = "..."` внутри файла `.replit`.

Следующий diff показывает, как передать команду через `args` в `[run]` и задать переменную `NAME` в `[run.env]`:

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# Новый раздел [run] должен находиться ниже всех свойств верхнего уровня, которые не начинаются с `[`!
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="section-4">
  #### Интерактивный запуск
</div>

Интерактивные программы также можно запускать кнопкой `Run` — это позволяет разделить окружение разработки и терминал, в котором выполняется программа.
Рассмотрим для примера следующий скрипт подсчёта:

**Пример**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="section-5">
  ## Расширенные параметры конфигурации
</div>

Ознакомьтесь с подробными параметрами конфигурации, доступными в Replit App. Вы можете настроить среду разработки, управлять командами запуска, интегрировать языковые сервисы и адаптировать обработку зависимостей.

| **Конфигурация** | **Ключ**                            | **Значение/пример**                         | **Описание**                                                                                     |
| ---------------- | ----------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| onBoot           | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Команда, выполняемая при загрузке Replit App.                                                    |
| compile          | <a name="compile" />`compile`       | (примера по умолчанию нет)                  | Команда, выполняемая перед командой `run`; используется для компилируемых языков, таких как C++. |
| language         | <a name="language" />`language`     | `language = "javascript"`                   | Указывает язык при импорте из GitHub или создании Replit App.                                    |
| entrypoint       | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | Главный файл, который запускается и открывается при запуске редактора.                           |
| hidden           | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | Файлы или папки, скрытые по умолчанию в дереве файлов.                                           |
| audio            | <a name="audio" />`audio`           | `audio = true`                              | При значении `true` включает системное аудио.                                                     |

<div id="section-6">
  ### Примечания о системном аудио
</div>

После установки `audio = true` в файле `.replit` может потребоваться перезапустить среду разработки. Откройте палитру команд с помощью `Cmd+K` (Mac) или `Ctrl+K` (Windows), найдите и выберите **Restart compute**.

При запуске графического приложения в правом нижнем углу окна `Output` появится значок наушников с флажком.
Из-за ограничений браузера эту функцию необходимо включать после каждого обновления страницы.

```toml theme={null}
# Разместите в самом начале файла `.replit`, вне секций, начинающихся с `[`
audio = true
```

<div id="section-7">
  ## Конфигурация packager
</div>

| **Конфигурация**  | **Ключ**                                          | **Значение/пример**                           | **Описание**                                                                           |
| ----------------- | ------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------- |
| packager          | <a name="language" />`language`                   | `packager.language = "python3"`               | Язык, используемый для работы с пакетами.                                              |
| packager features | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Автоматически определяет пакеты, которые нужно установить перед запуском Replit App. |
| packager features | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | При значении `true` включает поддержку packager.                                       |
| packager features | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Определяет, выполнять ли установку пакетов при хостинге Replit App.                   |
| packager          | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | Команда, выполняемая после установки нового пакета через packager.                    |
| packager          | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | Пути, которые игнорируются при обнаружении пакетов.                                   |
| packager          | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | Модули, которые не будут определяться автоматически при установке.                     |

<div id="replit-2">
  ### Пример настройки packager в `.replit`
</div>

```toml theme={null}
# Определение языка Replit App
packager.language = "python3"

# Включение функций автоматического управления пакетами
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# Команда, выполняемая после установки каждого пакета
packager.afterInstall = "echo 'Package installed successfully'"

# Определение путей и пакетов, которые менеджер пакетов должен игнорировать
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# Дополнительные настройки деплоя
[deployment]
run = ["python3", "app.py"]
```

<div id="section-8">
  ## Конфигурация деплоя
</div>

| **Конфигурация** | **Ключ**                              | **Значение/пример**                  | **Описание**                                                             |
| ---------------- | ------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------ |
| deployment       | <a name="run" />`run`                 | `deployment.run = "npm start"`       | Команда, выполняемая при запуске контейнера деплоя.                      |
| deployment       | <a name="build" />`build`             | `deployment.build = "npm run build"` | Команда, выполняемая перед запуском деплоя.                              |
| deployment       | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | Если `true`, для успешного деплоя не требуется проверка открытых портов. |

<div id="replit-3">
  ### Пример конфигурации `.replit` для деплоя
</div>

```toml theme={null}

# Указываем основную точку входа проекта
entrypoint = "app.js"

# Параметры конфигурации для деплоя приложения
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  **Настройка интерпретатора** устарела и больше не поддерживается в Replit. Вместо этого для настройки того, как скрипты и приложения запускаются в окружении Replit App, рекомендуется использовать команду `Run`.
</Note>

<div id="replit-app">
  ## Доступ к метаданным окружения Replit App
</div>

<div id="nodejs">
  ### Node.js
</div>

Чтобы получить доступ ко всем переменным окружения:

`console.log(process.env);`

Чтобы обратиться к отдельной переменной (REPL&#95;SLUG):

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

Чтобы получить доступ ко всем переменным окружения:

```python theme={null}
import os
print(os.environ)
```

Чтобы обратиться к одной переменной (REPL&#95;SLUG):

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

Чтобы получить доступ ко всем переменным окружения:

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

Чтобы обратиться к одной переменной (REPL&#95;SLUG):

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```
