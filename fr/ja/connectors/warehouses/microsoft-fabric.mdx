Créez des applications propulsées par l&#39;IA sur Replit et publiez-les directement sur Microsoft Fabric, avec une gouvernance et une sécurité de niveau entreprise intégrées dès le départ. L&#39;intégration Microsoft Fabric transforme vos données d&#39;entreprise gouvernées en outils internes : tableaux de bord, flux de travail, applications d&#39;IA, etc. Les équipes passent rapidement du prompt à la production, tandis que l&#39;authentification et les politiques d&#39;accès restent au sein de l&#39;environnement Fabric auquel vous faites déjà confiance.

<div id="fabric">
  ## Qu&#39;est-ce qu&#39;une app de données Fabric ?
</div>

Une app de données Fabric est une app React statique qui exécute des requêtes [DAX (Data Analysis Expressions)](https://learn.microsoft.com/en-us/dax/) sur des modèles sémantiques Power BI pour afficher des graphiques Power BI. Voici les caractéristiques à prendre en compte lors de la conception :

* **Les modèles sémantiques Power BI constituent la source de données.** Les graphiques sont alimentés par des requêtes DAX exécutées sur le modèle sémantique (jeu de données) auquel vous vous connectez.
* **Lecture seule par conception.** L&#39;app lit les données avec l&#39;instruction DAX `EVALUATE`. Elle n&#39;écrit rien en retour dans Power BI. Si vous avez besoin d&#39;un état modifiable, utilisez une base de données applicative distincte, en parallèle du tableau de bord.
* **Rendu via le portail Fabric.** La couche de données s&#39;exécute dans le portail Microsoft Fabric, interroge le modèle sémantique et renvoie les résultats à l&#39;app. Les données ne quittent pas l&#39;environnement Fabric.
* **Hébergement sur l&#39;infrastructure Microsoft.** Vous pouvez publier l&#39;app de données finalisée sur l&#39;hébergement Microsoft afin qu&#39;elle s&#39;exécute aux côtés du reste de votre environnement Fabric.

<Note>
  Les apps de données Microsoft Fabric nécessitent un accès à un locataire Microsoft Fabric disposant de modèles sémantiques Power BI et, pendant la préversion, la participation au programme de testeurs approuvés.
</Note>

En arrière-plan, [Rayfin](https://github.com/microsoft/rayfin) — un SDK et une CLI open source permettant de créer des backends applicatifs — permet à Agent de définir et de publier des apps prêtes pour la production à partir de vos données Fabric.

Tout se fait dans un flux de travail unique : décrivez votre app, laissez Agent en construire la structure, connectez-la à des données Fabric gouvernées, puis publiez-la pour qu&#39;elle s&#39;exécute dans le locataire Fabric de votre organisation.

Ce guide présente le flux de création, la manière dont l&#39;app se connecte aux données Fabric, ainsi que les options d&#39;équipe et d&#39;automatisation. Pour les tableaux de bord de données classiques reposant sur d&#39;autres entrepôts, consultez [Visualisation de données](/fr/ja/features/artifact-types/data-apps).

<div id="section">
  ## Cas d&#39;utilisation
</div>

Pour les organisations ayant déjà investi dans l&#39;écosystème de données Microsoft, c&#39;est un moyen bien plus rapide de créer des logiciels internes. Au lieu de passer des semaines à intégrer l&#39;authentification, les API, les outils de déploiement et les politiques de gouvernance, les équipes décrivent ce dont elles ont besoin et demandent à Agent de le créer.

Les cas d&#39;utilisation courants incluent :

* Outils de productivité propres à chaque service
* Tableaux de bord opérationnels
* Outils d&#39;exploration de données
* Applications d&#39;automatisation des flux de travail
* Interfaces de reporting

Pour l&#39;IT d&#39;entreprise, la gouvernance, l&#39;authentification et la sécurité restent dans l&#39;environnement Fabric existant qu&#39;elle gère déjà. La création rapide d&#39;applications ne se fait donc pas au détriment d&#39;une gestion centralisée.

<div id="fabric-2">
  ## Créer une application de données Fabric
</div>

Le flux de création est conversationnel. Vous restez dans Replit du début à la fin, tandis que l&#39;authentification et l&#39;accès aux données se font via Microsoft, en suivant les invites.

<Steps>
  <Step title="Partir du modèle Fabric">
    Sur la page d&#39;accueil de Replit, ouvrez le menu déroulant **Templates** et sélectionnez **Microsoft Fabric App** sous **Org templates**. Agent précharge alors les outils Fabric et démarre le flux de travail d&#39;application de données.

    <Frame caption="Sélection du modèle d'organisation Microsoft Fabric App sur la page d'accueil de Replit (interface en préversion privée).">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Page d'accueil de Replit avec le menu déroulant Templates ouvert et Microsoft Fabric App mis en évidence sous Org templates" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="Décrire le tableau de bord souhaité">
    Saisissez un prompt décrivant le tableau de bord ou l&#39;outil de reporting à créer. Par exemple : « Crée un tableau de bord de croissance des ventes en glissement mensuel à partir de mon modèle de ventes Fabric ». Nul besoin d&#39;écrire du DAX — Agent génère les requêtes.
  </Step>

  <Step title="Se connecter avec Microsoft">
    Lorsque vous y êtes invité, connectez-vous avec Microsoft OAuth sur le locataire qui héberge vos données Fabric. Agent obtient ainsi l&#39;autorisation de lire les modèles sémantiques accessibles. L&#39;identité utilisée pour la connexion doit avoir accès aux espaces de travail Fabric que vous souhaitez utiliser.
  </Step>

  <Step title="Ajouter votre source de données">
    Lorsque Agent vous le demande, indiquez le modèle sémantique Power BI / Fabric que vous souhaitez utiliser. Vous pouvez fournir l&#39;URL complète du jeu de données depuis le portail Microsoft Fabric (par exemple : `https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) ou l&#39;ID de l&#39;espace de travail et l&#39;ID du jeu de données/de l&#39;élément. Agent s&#39;en sert pour identifier l&#39;espace de travail et le modèle sémantique à interroger.

    Le modèle doit être **publié** sur le service Power BI — les fichiers `.pbix` locaux ne peuvent pas être utilisés.

    <Frame caption="Agent demande le lien du modèle sémantique Power BI / Fabric (interface en préversion privée).">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Panneau Agent demandant au créateur de partager un modèle sémantique Power BI ou Fabric sous forme d'URL complète du portail Microsoft Fabric ou d'ID d'espace de travail et d'ID de jeu de données/d'élément, avec une note indiquant que les fichiers .pbix locaux ne peuvent pas être utilisés car le modèle doit être publié sur le service Power BI" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="Laisser Agent créer et itérer">
    Agent explore le schéma du modèle sémantique, écrit les requêtes DAX et assemble un tableau de bord avec les graphiques appropriés. Passez les résultats en revue et demandez des modifications en langage naturel : ajouter un filtre, changer le type de graphique, ajouter une autre métrique, etc.
  </Step>

  <Step title="Publier (facultatif)">
    Une fois votre tableau de bord prêt, vous pouvez le publier sur l&#39;hébergement Microsoft pour qu&#39;il s&#39;exécute dans votre environnement Fabric. La publication fait l&#39;objet d&#39;une documentation distincte. Ce guide se concentre sur la connexion à vos données et la création de l&#39;application.
  </Step>
</Steps>

<div id="fabric-3">
  ## Connexion aux données Fabric
</div>

Pour lire des données, votre application doit disposer d&#39;une connexion authentifiée à Microsoft Fabric. Replit établit cette connexion de deux manières possibles.

<div id="fabric-4">
  ### Connexion à Fabric au niveau de l’application (pour les utilisateurs)
</div>

Les utilisateurs d’une application de données publiée n’ont pas besoin de configurer le connecteur. Ils s’authentifient via l’authentification unique Microsoft Fabric intégrée à l’application, qui accède aux données avec l’identité de l’utilisateur via le portail Microsoft Fabric. L’accès reste ainsi régi par les autorisations Fabric existantes.

<div id="microsoft-fabric">
  ### Connecteur Microsoft Fabric (un accès simplifié pour les créateurs)
</div>

Pour les créateurs, le **connecteur Microsoft Fabric** offre un moyen pratique d’autoriser l’accès aux données pendant le développement. Il est facultatif : il simplifie le processus, mais n’est pas requis.

* Le premier créateur à le configurer effectue une **authentification OAuth unique** auprès de Microsoft.
* **Les autres collaborateurs du même projet** héritent de cette connexion.
* **Les espaces de travail distincts** doivent activer le connecteur et effectuer leur propre authentification OAuth.
* L’identité authentifiée via OAuth doit disposer d’un accès à l’espace de travail Fabric cible.

Le connecteur utilise OAuth Microsoft Entra et est limité à un locataire. Comme les autres connecteurs Replit, vous le gérez depuis la page [Intégrations](/fr/ja/features/integrations/overview) du projet. Pour en savoir plus sur les connecteurs, consultez [Gérer les connecteurs](/fr/ja/replitai/managing-connectors).

<Note>
  Pendant la préversion privée, aucun identifiant partagé géré par Replit n’est disponible pour le connecteur Microsoft Fabric. Les créateurs autorisent l’accès à leur propre locataire Microsoft Entra.
</Note>

<div id="section-2">
  ## Équipes et automatisation
</div>

Pour un usage partagé au sein d’une équipe ou dans des environnements non interactifs (comme l’intégration continue), OAuth interactif n’est pas toujours pratique. Dans ce cas, au lieu de vous connecter de manière interactive, fournissez un jeton de **principal de service** via les [Secrets](/fr/ja/core-concepts/project-editor/app-setup/secrets) du projet. L’application lit les données Fabric à l’aide de l’identité du principal de service.

Il s’agit de l’équivalent le plus proche d’une configuration de machine à machine : une identité non humaine, provisionnée dans Microsoft Entra et autorisée à accéder à l’espace de travail Fabric, authentifie l’application sans intervention humaine. Assurez-vous que le principal de service a accès aux espaces de travail et aux modèles sémantiques interrogés par l’application.

<div id="section-3">
  ## Résolution des problèmes
</div>

<AccordionGroup>
  <Accordion title="Les données ne se chargent pas dans l’aperçu de l’application">
    La couche de données Fabric s’exécute via le portail Microsoft Fabric. Si les graphiques s’affichent vides ou si l’aperçu de l’application ne parvient pas à charger les données, vérifiez que vous avez terminé la connexion à Microsoft et que l’identité connectée a accès à l’espace de travail et au modèle sémantique associés.
  </Accordion>

  <Accordion title="Agent ne trouve pas le modèle sémantique">
    Collez le lien du jeu de données Power BI depuis le portail Microsoft Fabric et vérifiez que l’identité (ou le principal de service) dispose au minimum d’un accès en lecture à cet espace de travail. Si Agent indique qu’il ne parvient pas à résoudre l’espace de travail ou le modèle, partagez à nouveau le lien du jeu de données.
  </Accordion>

  <Accordion title="Le connecteur est bloqué ou les invites de connexion s’affichent de manière répétée">
    Réautorisez le connecteur Microsoft Fabric depuis la page [Intégrations](/fr/ja/features/integrations/overview) du projet. Vérifiez que l’identité autorisée via OAuth a accès à l’espace de travail Fabric. Pour une utilisation en équipe ou dans CI, privilégiez les jetons de principal de service fournis via des secrets.
  </Accordion>
</AccordionGroup>
