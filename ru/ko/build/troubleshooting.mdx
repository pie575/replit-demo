Деплой делает проект общедоступным приложением. Если деплой завершается ошибкой или общедоступный URL работает иначе, чем в Preview, устраняйте неполадки по порядку.

На этой странице приведены руководство по восстановлению сборки и справочная информация по устранению неполадок деплоя. Начните с самого простого вопроса: работает ли приложение в Preview?

<div id="section">
  ## Что вы узнаете
</div>

К концу этой страницы вы сможете определить, связана ли проблема с самим приложением, настройками деплоя, Secrets в продакшене, типом деплоя, конфигурацией портов или доступом к сети/DNS.

<div id="preview">
  ## Начните с Preview
</div>

Перед деплоем убедитесь, что приложение корректно работает в Project Editor.

В верхней части Project Editor выберите **Run** и откройте Preview. Если приложение не отображается в Preview по URL `replit.dev`, исправьте проблему перед деплоем.

Сначала попросите Agent диагностировать Preview.

<AiPrompt>
  Это приложение не работает в Preview.<br />
  Проверьте команду запуска, установку зависимостей, ошибки приложения, порты и отсутствующие Secrets.<br />
  Сначала устраните наиболее простую проблему и объясните, как убедиться, что Preview работает перед деплоем.
</AiPrompt>

Если Preview не работает, деплой этого не исправит.

<div id="preview-2">
  ## Если Preview работает, но деплой завершается с ошибкой
</div>

Если Preview работает, но деплой завершается с ошибкой, проверьте настройки конкретного деплоя.

<div id="section-2">
  ### Проверка логов
</div>

Откройте вкладку **Logs** в панели **Publishing**. Найдите трассировки стека, отсутствующие пакеты, сбои команд, отсутствующие переменные окружения или ошибки запуска.

Вставьте соответствующую ошибку в Agent.

<AiPrompt>
  Деплой завершился сбоем со следующим выводом логов: [вставьте ошибку].<br />
  Объясните наиболее вероятную причину.<br />
  Укажите, связана ли проблема с командой, зависимостью, Secret, портом, сборкой или ошибкой приложения.<br />
  Порекомендуйте минимальное исправление и способ его проверки.
</AiPrompt>

<div id="section-3">
  ### Проверьте команды запуска и сборки
</div>

Распространённые ошибки: опечатки, неверные флаги, неправильный входной файл или команды, работающие только локально.

Проверьте команды на панели **Publishing**. Если приложению нужны команда сборки и команда запуска, убедитесь, что обе указаны правильно.

<div id="secrets">
  ### Проверьте Secrets в продакшене
</div>

Secrets, настроенные в Project Editor, не передаются в приложение после деплоя автоматически. Добавьте все Secrets и переменные окружения для продакшена в панели **Publishing**.

Отсутствующие Secrets могут привести к ошибкам из-за неопределённых значений, сбоям API-вызовов, ошибкам подключения к базе данных, ошибкам входа или сбоям платежей.

См. [Secrets](/ru/ko/core-concepts/project-editor/app-setup/secrets).

<div id="section-4">
  ### Проверьте длительно работающие процессы
</div>

После деплоя программа должна работать непрерывно. Если она выполняется один раз и завершает работу, платформа автоматически перезапустит её.

Убедитесь, что приложение запускает длительно работающий процесс, например веб-сервер.

<div id="section-5">
  ### Проверка конфигурации хоста и порта
</div>

Если вы запускаете веб-сервер, деплой может автоматически определить порт, который использует сервер, но сервер должен принимать подключения на `0.0.0.0`. Если сервер принимает подключения только на `localhost` или `127.0.0.1`, приложение после деплоя не будет работать.

Если [в конфигурации `.replit` указан порт](/ru/ko/features/project-setup/configuration), автоматическое определение порта отключается. Чтобы пройти этап продвижения, необходимо указать порт, для которого `externalPort` задан как `80`. Убедитесь, что сервер принимает подключения на указанном `localPort`.

Попросите Agent тщательно всё проверить.

<AiPrompt>
  Проверьте, правильно ли это приложение настроено для деплоя.<br />
  Убедитесь, что сервер запускает долгосрочный процесс, принимает подключения на 0.0.0.0, использует ожидаемый порт и соответствует конфигурации портов .replit.<br />
  Не изменяйте поведение приложения, кроме исправлений для деплоя.
</AiPrompt>

<div id="section-6">
  ### Проверьте время выполнения проверки работоспособности
</div>

Перед тем как сделать приложение после деплоя доступным, Replit отправляет ему HTTP-запрос. Если главная страница отвечает дольше 5 секунд, проверка работоспособности может завершиться по тайм-ауту, и деплой завершится ошибкой на последнем этапе.

Если приложение запускается слишком долго, попросите Agent уменьшить объём задач при запуске, перенести ресурсоёмкие операции на время после действий пользователя или при необходимости кэшировать данные.

<div id="url">
  ## Деплой выполнен успешно, но общедоступный URL не работает
</div>

Если Preview работает и деплой выполнен успешно, но общедоступный URL не открывается, сравните поведение Preview и продакшена.

Проверьте следующее:

* Secrets и переменные окружения для продакшена.
* Настройки подключения к базе данных.
* URL обратного вызова или перенаправления для входа.
* Настройки вебхуков или перенаправления для платежей.
* Список разрешённых API или настройки CORS.
* Файлы, сохраняемые локально вместо базы данных или сервиса хранения.
* Различия в мобильной вёрстке и браузерах.

Попросите Agent сравнить окружения.

<AiPrompt>
  Приложение работает в Preview, но не работает по URL приложения после деплоя.<br />
  Помогите сравнить поведение Preview и продакшена.<br />
  Проверьте Secrets, настройки базы данных, вызовы API, перенаправления для входа, перенаправления для платежей, результаты сборки и логи.<br />
  Подскажите, что безопаснее всего проверить дальше.
</AiPrompt>

<div id="static">
  ## Проблемы со Static-деплоем
</div>

Static-деплой предоставляет статические файлы, такие как HTML, CSS и JavaScript.

Если приложение использует серверную логику, API-маршруты, колбэки аутентификации, обращения к базе данных с сервера или длительно выполняющуюся серверную логику, Static-деплой может не подойти. Вместо этого в панели **Publishing** измените тип деплоя на Autoscale.

Проблемы со Static-деплоем часто возникают из-за неверно указанной публичной директории или выбора Static для приложения, которому требуется сервер.

<div id="section-7">
  ## Ограничения на размер файлов
</div>

Деплои Reserved VM и Autoscale поддерживают Replit App размером до 8 ГБ. Статические деплои поддерживают приложения размером до 1 ГБ.

Чтобы уменьшить размер приложения, удалите ненужные файлы, не добавляйте в коммиты сгенерированные файлы и используйте внешнее хранилище для крупных ресурсов.

<Warning>
  Файловая система приложения после деплоя не является постоянной и сбрасывается при каждом деплое. Для постоянного хранения данных используйте базу данных, например [SQL Database](/ru/ko/features/data-and-storage/sql-database).
</Warning>

Если загруженные файлы или сгенерированные данные исчезают после деплоя, сохраняйте их в базе данных или службе хранения, а не в файловой системе приложения.

<div id="replitapp-replitdev-url">
  ## Проблемы с доступом к URL-адресам `replit.app` и `replit.dev`
</div>

Если у вас возникают проблемы с доступом к App по адресам в доменах `replit.app` или `replit.dev`, причиной могут быть веб-фильтры или сетевые ограничения.

Попробуйте использовать общедоступный DNS-резолвер, например Google DNS (`8.8.8.8`) или Cloudflare DNS (`1.1.1.1`).

<div id="dns">
  ### Изменение настроек DNS
</div>

<Tabs>
  <Tab title="Windows">
    1. Откройте **Панель управления**.
    2. Перейдите в **Центр управления сетями и общим доступом**.
    3. Слева выберите **Изменение параметров адаптера**.
    4. Щёлкните правой кнопкой мыши активное сетевое подключение и выберите **Свойства**.
    5. Выберите **Протокол Интернета версии 4 (TCP/IPv4)** и нажмите **Свойства**.
    6. Выберите **Использовать следующие адреса DNS-серверов**.
    7. Введите IP-адрес общедоступного DNS-сервера, например `8.8.8.8` для Google DNS или `1.1.1.1` для Cloudflare DNS.
    8. Нажмите **ОК**, чтобы сохранить изменения.

    Подробные инструкции см. в [руководстве Microsoft по настройке DNS](https://support.microsoft.com/en-us/windows/change-tcp-ip-settings-bd0a07af-15f5-cd6a-363f-ca2b6f391ace).
  </Tab>

  <Tab title="macOS">
    1. Откройте **Системные настройки**.
    2. Выберите **Сеть**.
    3. Выберите активное сетевое подключение слева.
    4. В правом нижнем углу выберите **Дополнительно**.
    5. Перейдите на вкладку **DNS**.
    6. Нажмите кнопку **+**, чтобы добавить DNS-сервер.
    7. Введите IP-адрес общедоступного DNS-сервера, например `8.8.8.8` для Google DNS или `1.1.1.1` для Cloudflare DNS.
    8. Нажмите **ОК**, затем **Применить**.

    Подробные инструкции см. в [руководстве Apple по настройке DNS](https://support.apple.com/guide/mac-help/change-dns-settings-on-mac-mh14127/mac).
  </Tab>

  <Tab title="Linux">
    1. Отредактируйте файл `/etc/resolv.conf`, чтобы добавить общедоступные DNS-серверы. Способ настройки зависит от дистрибутива.
    2. Добавьте следующие строки.

    ```bash theme={null}
    nameserver 8.8.8.8
    nameserver 1.1.1.1
    ```

    Подробнее о настройке DNS в различных дистрибутивах см. в [руководстве Debian Wiki по настройке сети](https://wiki.debian.org/NetworkConfiguration#Defining_the_.28DNS.29_Nameservers).
  </Tab>
</Tabs>

<div id="dns-2">
  ### Очистка кэша DNS
</div>

После изменения настроек DNS очистите кэш DNS, чтобы применить новую конфигурацию.

* **Windows**: выполните `ipconfig /flushdns` в командной строке.
* **macOS и Linux**: выполните `sudo systemctl restart NetworkManager` в терминале. Точная команда может отличаться в зависимости от дистрибутива.

<Note>
  Для повышения производительности и надежности в разных регионах URL `replit.dev` Replit App может иногда меняться во время миграции кластера. После завершения миграции URL будет оставаться неизменным примерно в течение года, если вы явно не запросите смену местоположения.
</Note>

<div id="streamlit">
  ## Деплой приложений Streamlit
</div>

Приложения Streamlit работают в деплоях Replit. Проще всего начать с [шаблона Streamlit](https://replit.com/@replit/Streamlit?v=1).

Также можно задать следующую команду запуска для деплоя.

```bash theme={null}
streamlit run --server.address 0.0.0.0 --server.headless true --server.enableCORS=false --server.enableWebsocketCompression=false main.py
```

Если приложение использует другой основной файл, замените `main.py` его именем.

<div id="section-8">
  ## Критерии готовности
</div>

* Preview работает.
* Деплой завершён.
* Общедоступный URL открывается.
* Основной сценарий приложения работает по общедоступному URL.
* Secrets для продакшена и настройки настроены.
* В логах нет скрытых ошибок при запуске.
