Replit에서 웹 앱을 게시하면 라이브 URL을 대상으로 검색 엔진 최적화(SEO) 감사가 자동으로 실행되고, Publishing 도구에 SEO 등급이 표시됩니다. 등급에 개선할 여지가 있다면 클릭 한 번으로 해당 문제들을 Agent에게 넘겨 몇 초 만에 수정할 수 있습니다.

대부분의 빌더에게 전체 워크플로우는 간단합니다. 앱을 게시하고, 등급을 확인한 뒤, Agent에게 &quot;내 SEO를 최적화해줘&quot;라고 요청하면 됩니다. 이 페이지에서는 그 이면에서 어떤 일이 일어나는지, 그리고 이를 최대한 활용하는 방법을 설명합니다.

<div id="what-is-seo-and-why-it-matters">
  ## SEO란 무엇이며 왜 중요한가
</div>

검색 엔진 최적화(SEO)는 Google과 같은 검색 엔진이 사이트를 찾고, 이해하고, 순위를 매길 수 있도록 사이트를 구축하는 작업입니다. SEO가 탄탄하면 광고비를 들이지 않고도, 사람들이 여러분이 제공하는 것을 검색할 때 앱이 검색 결과에 노출됩니다.

SEO 성과의 대부분은 몇 가지 요소가 좌우합니다. 명확한 페이지 제목과 설명, semantic HTML, 빠른 로딩 속도, 모바일 친화적인 layout, 이미지에 담긴 설명이 있는 alt text, 그리고 크롤링이 가능한 사이트 구조입니다. 검색 엔진은 사람과 기계 모두가 읽기 쉬운 사이트에 높은 점수를 줍니다.

landing page, 마케팅 사이트, 블로그, 디렉터리 등 검색 노출이 중요한 무언가를 launch한다면, SEO는 초기에 투자할 수 있는 가장 효과가 큰 요소 중 하나입니다.

<div id="how-replit-improves-your-seo-out-of-the-box">
  ## Replit이 기본으로 SEO를 개선하는 방식
</div>

Replit이 SEO의 기본 요소를 대부분 알아서 처리하므로, 여러분은 콘텐츠와 제품에만 집중할 수 있습니다:

* **빠르고 전 세계에 분산된 호스팅**: Replit Deployments는 속도에 최적화된 인프라에서 앱을 serve하며, [Project geography](/ko/features/publishing/project-geography)로 앱이 실행될 위치를 직접 선택할 수 있습니다.
* **기본 HTTPS 적용**: 모든 published app에는 Replit이 관리하는 TLS 인증서가 제공되며, 이는 검색 엔진의 기본적인 순위 신호입니다.
* **Custom Domains**: 보유한 도메인을 연결해 신뢰도와 브랜드 인지도를 높이세요. [Custom Domains](/ko/features/publishing/custom-domains)를 참고하세요.
* **콘텐츠 사이트를 위한 Static Deployments**: 마케팅 페이지, 블로그, 문서에는 [Static Deployments](/ko/features/publishing/deployment-types#static)가 검색 엔진이 쉽게 크롤링할 수 있는 사전 렌더링된 HTML을 제공합니다.
* **Agent가 SEO를 고려한 코드를 작성**: Agent는 페이지를 build할 때 기본적으로 semantic HTML, 접근성을 갖춘 마크업, meta tags를 생성합니다 — SEO 도구가 확인하는 바로 그 요소들입니다.
* **SEO rating**: 게시 후 자동으로 실행되는 audit으로 현재 상태를 항상 파악할 수 있고, 발견된 문제는 클릭 한 번으로 Agent에 handoff해 수정할 수 있습니다.

<div id="the-seo-rating">
  ## SEO rating
</div>

<div id="where-to-find-it">
  ### 확인 위치
</div>

게시된 앱에서 **Publishing** 도구를 엽니다. SEO rating은 다른 빌드 세부 정보와 함께 deployment 개요 화면에 표시됩니다. rating 위에 마우스를 올리면 Lighthouse가 각 페이지에서 발견한 구체적인 개선 항목을 확인할 수 있습니다.

<Note>
  SEO rating이 보이지 않는다면 앱이 비공개 상태이거나 최근에 게시되지 않았을 가능성이
  높습니다. 이 rating은 게시된 공개 웹 앱에서만 표시됩니다.
</Note>

<div id="how-to-read-your-rating">
  ### 평가 결과 읽는 방법
</div>

Replit은 Lighthouse audit 결과를 바탕으로 세 가지 평가 중 하나를 표시합니다:

| 평가         | 의미                                               |
| :--------- | :----------------------------------------------- |
| Healthy    | App이 SEO 모범 사례를 잘 따르고 있습니다. 큰 변경 후에는 다시 확인해 보세요. |
| Needs Work | 여러 issues 때문에 검색 엔진이 App을 제대로 이해하지 못하고 있습니다.     |
| Weak       | 중요한 SEO 기본 요소가 빠져 있습니다. 대부분 몇 분이면 수정할 수 있습니다.    |

App에 여러 페이지가 있는 경우, badge에는 Replit이 크롤링한 모든 URL 중 **가장 낮은** 평가가 표시됩니다. 평균으로 가려지지 않고 가장 문제가 많은 페이지가 먼저 드러나도록 하기 위해서입니다.

<div id="when-the-rating-is-calculated">
  ### 평가 점수가 계산되는 시점
</div>

audit은 게시에 성공할 때마다 자동으로 실행됩니다. 평가 점수는 보통 deployment가 라이브 상태가 된 후 1~2분 이내에 표시되며, 결과가 나오는 즉시 Publishing 도구가 badge를 갱신합니다.

<div id="supported-deployment-types">
  ### 지원되는 deployment type
</div>

SEO rating은 검색 엔진이 URL을 크롤링할 수 있는 공개 웹 deployment를 대상으로 계산됩니다.

* [Autoscale Deployments](/ko/features/publishing/deployment-types#autoscale)
* [Reserved VM Deployments](/ko/features/publishing/deployment-types#reserved-vm)
* [Static Deployments](/ko/features/publishing/deployment-types#static)

Scheduled deployment과 private deployment은 공개 웹 트래픽을 serve하지 않으므로 SEO rating이 생성되지 않습니다.

<div id="optimize-seo-with-agent">
  ## Optimize SEO with Agent
</div>

평가 옆에 **Optimize SEO with Agent** 버튼이 나타납니다. 이 버튼을 선택하면 Growth pane에서 [SEO Agent](/ko/features/publishing/seo-agent)가 열리며, 여기서 기술 SEO audit를 실행하고 발견된 issues를 검토한 뒤 원클릭으로 수정을 적용할 수 있습니다.

<Tip>
  버튼을 쓰지 않아도 됩니다. Agent를 열고 **&quot;optimize my
  SEO&quot;**라고 입력하면 Agent가 최신 결과를 가져와 하나씩 처리하기
  시작합니다.
</Tip>

Agent가 changes를 마치면 앱을 republish하세요. SEO rating은 새 build를 기준으로 다시 계산되고 badge도 자동으로 업데이트됩니다.

Agent가 적용하는 대표적인 수정 사항은 다음과 같습니다.

* 누락되었거나 일반적인 `<title>` 태그를 추가하거나 다시 작성해 각 페이지에 고유하고 설명적인 제목 부여
* 모든 페이지에 meta description 추가
* 이미지에 설명적인 `alt` 텍스트 추가
* `<html>` 요소에 `lang` 속성 설정
* 링크에 식별 가능한 텍스트가 있는지 확인(&quot;click here&quot;나 빈 앵커 사용 금지)
* `robots.txt`와 `sitemap.xml` 추가
* 모바일 렌더링을 위한 viewport meta 태그 추가
* accessibility 검사를 통과하지 못한 텍스트의 색상 대비 개선
* 소셜 플랫폼에서 앱 링크가 보기 좋게 표시되도록 Open Graph 및 Twitter card meta tags 추가

<div id="best-practices-for-an-seo-optimized-site-on-replit">
  ## Replit에서 SEO에 최적화된 사이트를 만드는 모범 사례
</div>

Agent에게 맡기든 직접 작성하든, Replit으로 만든 앱에서 가장 큰 효과를 내는 항목은 다음과 같습니다.

* **모든 페이지에 고유한 title과 meta description을 지정하세요.** title은 60자 미만, description은 150~160자 정도를 목표로 하세요.
* **semantic HTML을 사용하세요.** layout을 `<main>`, `<header>`, `<nav>`, `<footer>`로 감싸세요. `<h1>`은 페이지당 한 번만 사용하고, 제목 수준은 순서대로 단계적으로 내려가도록 하세요.
* **모든 이미지에 alt text를 추가하세요.** 이미지가 무엇인지에 그치지 말고, 무엇을 보여주는지 설명하세요.
* **`sitemap.xml`과 `robots.txt`를 생성하세요.** 검색 엔진이 무엇을 크롤링해야 할지 알 수 있도록 Agent에게 둘 다 만들어 달라고 요청하세요.
* **Open Graph 및 Twitter card 태그를 추가하세요.** 소셜 미디어에 공유될 때 앱이 어떻게 보일지 제어할 수 있습니다.
* **custom domain을 사용하세요.** 브랜드가 담긴 도메인은 방문자와 검색 엔진 모두에게 신뢰를 줍니다. [Custom Domains](/ko/features/publishing/custom-domains)를 참조하세요.
* **알맞은 deployment type을 선택하세요.** 콘텐츠가 많은 사이트라면 [Static Deployments](/ko/features/publishing/deployment-types#static)가 검색 엔진이 즉시 해석할 수 있는 사전 렌더링된 HTML을 제공합니다.
* **구조화된 데이터를 추가하세요.** JSON-LD 마크업을 사용하면 검색 엔진이 상품, 기사, FAQ, 이벤트에 대한 리치 결과를 표시할 수 있습니다.
* **앱을 빠르게 유지하세요.** 이미지를 최적화하고, 렌더링을 차단하는 스크립트를 피하며, Replit의 호스팅을 활용해 응답 시간을 낮게 유지하세요.

이 대부분을 한 번에 적용하는 간단한 방법은 다음과 같습니다.

<AiPrompt>
  내 사이트를 SEO 모범 사례 기준으로 audit하고 수정 사항을 적용해 줘. sitemap,
  robots.txt, Open Graph 태그를 추가하고, 적절한 곳에는 구조화된 데이터를 넣고,
  모든 페이지에 고유한 title과 meta description이 있는지 확인해 줘.
</AiPrompt>
