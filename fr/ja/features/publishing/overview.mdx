title: "Publication"

---

L&#39;outil Publishing vous permet de mettre votre app en production et de gérer son fonctionnement sur le Web. Un seul panneau regroupe les paramètres qui contrôlent l&#39;adresse Web de votre app, les personnes autorisées à y accéder, la base de données de production, la surveillance, la sécurité et le mode d&#39;hébergement.

Pour l&#39;ouvrir, sélectionnez **Publishing** sous **Replit Cloud** dans le panneau **Tools**, ou **Publier** en haut à droite du Project Editor.

<div id="section">
  ## Publier votre application
</div>

Le panneau principal vous guide pas à pas à travers tout ce qui est nécessaire pour mettre votre application en production. Une fois chaque section vérifiée, sélectionnez **Publish**.

<Frame>
  <img src="/assets/mirror/publish-your-app-851815208b8a.png" alt="Panneau Publish your app affichant le champ Domain, l'application à publier, les paramètres d'accès, les paramètres de base de données, le monitoring, la sécurité et les outils d'engagement au-dessus du bouton Publish" width="578" height="980" data-path="images/deployments/publish-pane/publish-your-app.png" />
</Frame>

* **Domain** : l&#39;adresse web de votre application. Replit propose un nom en `.replit.app` et vérifie sa disponibilité. Vous pouvez modifier ce nom, et connecter un [domaine personnalisé](/fr/ja/features/publishing/custom-domains) après la publication.
* **What you&#39;re publishing** : un aperçu de l&#39;application qui passe en production et de son URL.
* **Who can access your app** : choisissez entre **Public**, **Password protected**, **Workspace uniquement** et **Sur invitation uniquement**. Les options privées réservent l&#39;utilisation de l&#39;application aux membres de votre workspace, ou aux personnes et groupes que vous invitez. Pour en savoir plus, consultez [Accès à l&#39;application](/fr/ja/features/publishing/private-deployments).
* **Database settings** : gérez la manière dont la base de données de production de votre application est créée et alimentée en données lors de la publication. Pour en savoir plus, consultez [Base de données de production](/fr/ja/features/data-and-storage/development-and-production).
* **Monitoring tools** : activez le monitoring de votre application pour être le premier informé en cas de panne. Replit vérifie en continu que votre application est en ligne et vous envoie un e-mail dès qu&#39;un problème survient. Pour en savoir plus, consultez [Surveiller une application](/fr/ja/features/publishing/monitoring-a-deployment).
* **Security tools** : lancez une analyse de sécurité approfondie avant la publication. Le Security Agent combine l&#39;IA et les principaux outils d&#39;analyse statique pour détecter les failles de sécurité de votre projet. Pour en savoir plus, consultez le [Centre de sécurité du projet](/fr/ja/features/security/project-security-center).
* **Engagement tools** : activez le widget de retours pour ajouter un bouton de feedback dans un coin de votre application publiée. Vous pouvez consulter les messages reçus dans votre boîte de réception et les transmettre à Agent pour correction.

<div id="section-2">
  ## Ajuster les paramètres
</div>

En sélectionnant **Adjust settings**, vous pouvez configurer manuellement le mode d&#39;hébergement de votre app. La plupart des créateurs n&#39;ont pas besoin de modifier ces paramètres : Replit choisit des valeurs par défaut adaptées.

<Frame>
  <img src="/assets/mirror/adjust-settings-d6e124b2249f.png" alt="Section Adjust settings affichant le type de déploiement, la configuration de la machine, les secrets de déploiement, la géographie du déploiement et le bouton bascule permettant de bloquer la publication en cas de failles de sécurité critiques" width="574" height="794" data-path="images/deployments/publish-pane/adjust-settings.png" />
</Frame>

* **Deployment type** : la technologie utilisée pour publier votre app. **Autoscale** est recommandé pour la plupart des apps, car il s&#39;adapte de zéro à n&#39;importe quel niveau de demande. Comparez les [types de déploiement](/fr/ja/features/publishing/deployment-types).
* **Machine configuration** : la puissance du serveur qui exécute votre app. Sélectionnez **Edit** pour modifier le CPU, la mémoire et le nombre maximal de machines. Le panneau affiche le coût par machine ainsi que le coût en cas de trafic maximal. Pour en savoir plus, consultez [Configuration de la machine](/fr/ja/features/publishing/machine-configuration).
* **Deployment secrets** : les clés secrètes que votre app utilise pour accéder aux API et aux services (un espace de stockage sécurisé et privé où sont conservées les informations sensibles telles que les clés API). Les secrets sont automatiquement synchronisés de votre environnement de développement vers l&#39;app publiée. Pour en savoir plus, consultez [Secrets](/fr/ja/core-concepts/project-editor/app-setup/secrets).
* **Deployment geography** : l&#39;emplacement où votre app est hébergée. Choisir une région proche de vos utilisateurs permet de réduire la latence. Une fois l&#39;app publiée, elle et ses ressources restent rattachées à cette région. Pour en changer ultérieurement, remixez votre app. Pour en savoir plus, consultez [Région du projet](/fr/ja/features/publishing/project-geography).
* **Block publishing of critical vulnerabilities** : Replit exécute systématiquement une analyse de sécurité avant la publication. Ce paramètre détermine si la publication doit être bloquée lorsqu&#39;une faille de sécurité critique est détectée. Pour en savoir plus, consultez le [Centre de sécurité du projet](/fr/ja/features/security/project-security-center).
