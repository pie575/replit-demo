Un **projet** est le conteneur de tout ce que vous créez sur Replit. Les **artefacts** sont les réalisations publiables qu&#39;il contient — applications web, applications mobiles, diaporamas, animations, visualisations de données, jeux 3D et designs.

Si vous créez plusieurs éléments, deux options s&#39;offrent à vous : ajouter plusieurs artefacts à un même projet ou créer des projets distincts. Le bon choix dépend de la façon dont vos applications partagent — ou non — les mêmes données, la même logique et le même cycle de vie de déploiement. Cette page détaille les deux notions et indique quand regrouper des artefacts dans un seul projet et quand créer des projets distincts.

<div id="section">
  ## Qu&#39;est-ce qu&#39;un projet ?
</div>

Un projet est le conteneur qui regroupe le code, les données et tous les artefacts que vous créez. Lorsque vous indiquez à Agent ce que vous souhaitez créer, un projet est configuré et les artefacts y sont créés.

Un projet, c&#39;est un peu comme un plan de travail sur un bureau : tout est réuni au même endroit et partage les mêmes informations, mais chaque élément remplit une fonction différente.

Par exemple, si vous demandez à Agent de créer une application de suivi d&#39;activité physique, un projet est créé avec un artefact d&#39;application mobile, ainsi que le backend, la base de données et le stockage nécessaires à son fonctionnement.

Concepts clés :

* **Projet** : le conteneur qui regroupe tout — le code, les données et l&#39;ensemble des artefacts.
* **Artefact** : un livrable publiable au sein d&#39;un projet (application web, diaporama, vidéo, etc.).
* **Ressources** : chaque artefact bénéficie automatiquement d&#39;un accès au backend, à la base de données et au stockage de fichiers — sans aucune configuration.

Pour découvrir tout ce que vous pouvez faire avec les projets (gestion, filtrage, épinglage, tri, etc.), consultez [Projets](/fr/ja/features/projects-and-artifacts/projects).

<div id="section-2">
  ## Qu’est-ce qu’un artefact ?
</div>

Les artefacts sont des éléments que vous pouvez publier sur Replit. Chacun constitue un résultat complet et autonome et reçoit une URL partageable une fois publié.

Les autres éléments de votre projet — fichiers, images, CSV et code — prennent en charge vos artefacts, mais ne peuvent pas être publiés seuls.

<div id="section-3">
  ## Ce que les artefacts partagent au sein d&#39;un projet
</div>

Lorsque des [artefacts](/fr/ja/features/projects-and-artifacts/artifacts) appartiennent au même [projet](/fr/ja/features/projects-and-artifacts/projects), ils partagent automatiquement les éléments suivants :

* **Base de données** : dès qu&#39;un artefact écrit des données, les autres peuvent les lire immédiatement.
* **Backend et API** : une logique serveur partagée, sans duplication de code.
* **Stockage de fichiers** : images, documents et fichiers téléversés accessibles depuis tous les artefacts.
* **Déploiement** : à la publication, tout est déployé de façon synchronisée.

Autrement dit, vous n&#39;avez pas besoin de configurer des connexions entre les artefacts ni de dupliquer du code. En revanche, vous ne pouvez pas publier un artefact sans publier les autres.

<div id="section-4">
  ## Guide rapide
</div>

Voici les principaux cas de figure à prendre en compte pour décider si vous devez ajouter un artefact à un projet existant ou créer un projet distinct.

| **Plusieurs artefacts dans un même projet**                                                          | **Projets distincts**                                                                 |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Les applications partagent les mêmes données et le même backend                                      | Les applications ne partagent ni logique sous-jacente ni données                      |
| Vous souhaitez tout déployer ensemble                                                                | Des cycles de déploiement indépendants sont nécessaires                               |
| Elles sont complémentaires (application client et tableau de bord d&#39;administration, par exemple) | Produits sans lien entre eux ou destinés à des clients différents                     |
| Vous voulez que les modifications d&#39;un artefact se répercutent automatiquement sur les autres    | Les projets sont éphémères (page de destination de campagne, site événementiel, etc.) |

<div id="section-5">
  ## Exemple
</div>

<div id="1">
  ### Même projet : application web + application mobile pour un seul produit
</div>

Un restaurant crée une application web permettant aux clients de consulter le menu et une application mobile permettant au personnel de gérer les commandes. Les deux se connectent à la même base de données, qui regroupe les plats du menu, les commandes et les informations clients.

**Pourquoi un seul projet :** les applications partagent les mêmes données et le même backend. Lorsqu&#39;un client passe commande sur l&#39;application web, le personnel la voit immédiatement dans l&#39;application mobile.

<div id="section-6">
  ### Même projet : application + tableau de bord d&#39;administration + diaporama pour investisseurs
</div>

Une startup développe son produit principal, un panneau d&#39;administration interne pour gérer le contenu et un diaporama destiné à une levée de fonds — le tout dans un seul projet.

**Pourquoi un seul projet :** le tableau de bord d&#39;administration gère les mêmes données que celles affichées par l&#39;application, et la présentation peut afficher des métriques en temps réel issues du backend partagé.

<div id="2">
  ### Projets distincts : deux applications clientes sans lien entre elles
</div>

Un freelance développe une boutique e-commerce pour un client et un système de réservation pour un autre.

**Pourquoi des projets distincts :** les applications ne partagent ni données ni logique. Chaque client a besoin d&#39;un déploiement indépendant, afin que les modifications apportées à l&#39;une n&#39;affectent pas l&#39;autre.

<div id="section-7">
  ### Projets distincts : page de destination de campagne en parallèle du produit principal
</div>

Vous avez une application en production qui tourne toute l&#39;année, ainsi qu&#39;une page de destination éphémère dédiée à une campagne marketing.

**Pourquoi des projets distincts :** la page de campagne suit son propre cycle de vie — vous la lancez, vous l&#39;exploitez quelques semaines, puis vous l&#39;arrêtez. Les séparer permet de garder votre produit principal bien organisé et de publier ou supprimer la page de manière indépendante.

<div id="section-8">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artefact vers un autre projet ?">
  Ce n&#39;est pas possible pour le moment. Si vous devez isoler un artefact, créez un nouveau [projet](/fr/ja/features/projects-and-artifacts/projects) et demandez à Agent de le reconstruire à cet endroit.
</Accordion>

<Accordion title="Le nombre d'artefacts par projet est-il limité ?">
  Un projet peut contenir jusqu&#39;à sept artefacts, avec une limite d&#39;**une application mobile par projet**. Cette limite existe car les artefacts supplémentaires consomment davantage de mémoire et peuvent ralentir les aperçus. Si vous avez besoin d&#39;artefacts supplémentaires, démarrez un autre [projet](/fr/ja/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artefact d'un projet ?">
  Ce n&#39;est pas possible pour le moment. Lors de la publication, tout est déployé ensemble. Si vous avez besoin de déploiements indépendants, utilisez des projets distincts.
</Accordion>

<Accordion title="Les artefacts partagent-ils des données entre eux ?">
  Oui. Tous les artefacts d&#39;un projet partagent la même base de données et les mêmes services backend. Lorsqu&#39;une application web écrit des données, l&#39;application mobile et le tableau de bord de données peuvent les lire immédiatement.
</Accordion>

<Accordion title="Quelle est la différence entre un artefact et un fichier ?">
  Un artefact est un élément publiable : une application, des diapositives, une vidéo, etc. Les fichiers (CSV, images, code, etc.) sont des ressources au sein du projet : ils servent de support aux artefacts, mais ne peuvent pas être publiés seuls.
</Accordion>
