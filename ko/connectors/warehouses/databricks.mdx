Databricks connector를 사용하면 Replit Agent가 Databricks workspace에 쿼리를 실행할 수 있습니다. builder는 자연어만으로 dashboard, 리포팅 도구, 데이터 애플리케이션을 만들 수 있으며, SQL 전문 지식은 필요하지 않습니다.

Replit은 두 가지 Databricks 연결 유형을 지원합니다. 각 쿼리를 실행할 주체(ID)에 따라 알맞은 유형을 선택하세요.

<div id="choose-a-connection-type">
  ## 연결 유형 선택
</div>

|                      | **사용자 대 머신(U2M)**                    | **서비스 주체(M2M)**                |
| -------------------- | ------------------------------------ | ------------------------------ |
| Replit의 connector 이름 | Databricks for Databricks Apps (U2M) | Databricks (Service Principal) |
| 쿼리 실행 주체             | 개별 builder                           | 공유 service principal           |
| Databricks 권한        | 각 builder의 Unity Catalog 권한          | service principal의 권한          |
| audit 기록 주체          | 쿼리를 실행한 builder                      | service principal              |
| builder 로그인          | 각 builder가 자신의 Databricks 계정으로 로그인   | 개별 Databricks 로그인 불필요          |
| 권장 사용 사례             | 사용자별 권한 관리와 audit 기록이 필요한 경우         | 공유 접근과 비대화형 workflows          |

<div id="set-up-the-u2m-connector">
  ## U2M connector 설정
</div>

U2M 설정에는 세 가지 역할이 필요합니다:

1. **Databricks account admin**: OAuth app connection을 생성하고 SQL Warehouse 세부 정보를 제공합니다.
2. **Replit organization admin**: OAuth 자격 증명으로 connector를 구성합니다.
3. **Builder**: 자신의 Databricks 계정으로 로그인한 후 빌드를 시작합니다.

<div id="u2m-prerequisites">
  ### U2M 사전 요구사항
</div>

시작하기 전에 다음 사항을 확인하세요:

* Databricks **account admin** 권한. app connection은 workspace admin 설정이 아니라 계정 콘솔에서 구성합니다.
* Replit organization admin 권한.
* connector를 사용할 모든 builder의 Databricks 계정.
* 모든 builder의 workspace 접근 권한. 여기에는 SQL Warehouse에 대한 **Can use** permission과 필요한 Unity Catalog permissions가 포함됩니다.

<div id="step-1-create-an-oauth-app-connection">
  ### 1단계: OAuth app connection 생성
</div>

<Note>이 단계를 완료하려면 Databricks account admin이어야 합니다.</Note>

Databricks account admin이 Replit을 OAuth 애플리케이션으로 등록합니다. 이 app connection에서 Replit 구성에 사용할 client ID와 client secret을 얻을 수 있습니다.

<Steps>
  <Step title="Databricks 계정 콘솔 열기">
    Databricks workspace의 오른쪽 상단에서 workspace 선택기를 열고 **Manage account**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/manage-account-6374ed6bf0f2.png" alt="Manage account가 표시된 상태로 열린 Databricks workspace 선택기" width="2000" height="1144" data-path="images/connectors/databricks/u2m/manage-account.png" />
    </Frame>
  </Step>

  <Step title="App connections 열기">
    계정 콘솔에서 **Settings**를 선택한 다음 **App connections** 탭을 엽니다.

    <Frame>
      <img src="/assets/mirror/app-connections-96228e7f0f2e.png" alt="App connections 탭이 선택되고 Add connection 버튼이 보이는 Databricks 계정 Settings 페이지" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-connections.png" />
    </Frame>
  </Step>

  <Step title="Replit 연결 구성">
    **Add connection**을 선택합니다. `replit-u2m`처럼 Replit임을 알 수 있는 애플리케이션 이름을 입력합니다.

    **Redirect URLs**에 다음을 입력합니다:

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    **Access scopes**에서 **All APIs**를 선택합니다. 이렇게 하면 Agent가 Databricks Apps를 빌드하고 관리하는 데 필요한 Databricks SQL과 Databricks API를 사용할 수 있습니다.

    **Generate a client secret**을 선택합니다. 연결을 만든 뒤에는 Databricks에서 이 연결에 secret을 추가할 수 없습니다.

    조직의 보안 정책에 맞게 token 수명을 설정합니다. 예시에서는 Databricks가 표시하는 최댓값인 **Access token TTL** `1440`분(24시간)과 **Refresh token TTL** `129600`분(90일)을 사용합니다. refresh token 수명을 짧게 설정하면 builder가 더 자주 로그인해야 할 수 있습니다.

    **Add**를 선택합니다.

    <Warning>
      **All APIs**는 SQL만 허용하는 경우보다 더 광범위한 접근 권한을 부여합니다. connector의 실제 접근 범위는 각 builder의 Databricks permissions로 제어하세요.
    </Warning>

    <Frame>
      <img src="/assets/mirror/app-configuration-6799b5769326.png" alt="Replit 애플리케이션 이름, redirect URL, All APIs 접근, client secret 생성, token 수명이 구성된 Databricks Add connection 양식" width="2000" height="1144" data-path="images/connectors/databricks/u2m/app-configuration.png" />
    </Frame>
  </Step>

  <Step title="OAuth 자격 증명 저장">
    **Client ID**와 **Client Secret**을 복사한 다음 조직의 secret 관리 도구에 저장합니다.

    <Warning>
      Databricks는 client secret을 한 번만 표시합니다. 만료일을 기록해 두고 secret이 만료되기 전에 app connection을 교체하세요.
    </Warning>

    <Frame>
      <img src="/assets/mirror/oauth-credentials-15b2e6c67309.png" alt="client ID와 client secret이 가려진 Databricks Connection created 대화 상자와 일회성 secret 경고 및 만료일" width="2000" height="1144" data-path="images/connectors/databricks/u2m/oauth-credentials.png" />
    </Frame>
  </Step>
</Steps>

<Note>
  새로 만들거나 업데이트한 OAuth app connection은 사용할 수 있게 되기까지 최대 30분이
  걸릴 수 있습니다.
</Note>

<div id="step-2-share-the-sql-warehouse-details">
  ### 2단계: SQL Warehouse 세부 정보 공유
</div>

각 builder는 U2M connector를 승인할 때 SQL Warehouse 세부 정보를 입력합니다. 내부 온보딩 페이지처럼 builder가 확인할 수 있는 곳에 이 값들을 게시하세요.

<Steps>
  <Step title="SQL Warehouses 열기">
    Databricks workspace에서 **SQL Warehouses**를 선택한 후, builder가 사용할 웨어하우스를 엽니다.

    <Frame>
      <img src="/assets/mirror/sql-warehouses-cc178d18a33b.png" alt="사용 가능한 웨어하우스를 보여주는 Databricks SQL Warehouses 페이지" width="3438" height="1984" data-path="images/connectors/databricks/sql-warehouses.png" />
    </Frame>
  </Step>

  <Step title="연결 세부 정보 복사">
    **Connection details**를 선택한 다음 **Server hostname**과 **HTTP path**를 복사합니다.

    <Frame>
      <img src="/assets/mirror/connection-details-938b970b98e6.png" alt="서버 호스트 이름과 HTTP 경로가 표시된 Databricks SQL Warehouse 연결 세부 정보 페이지" width="3438" height="1984" data-path="images/connectors/databricks/connection-details.png" />
    </Frame>
  </Step>
</Steps>

<div id="step-3-enable-u2m-in-replit">
  ### 3단계: Replit에서 U2M 활성화
</div>

<Note>connector를 구성하려면 Replit 조직 관리자여야 합니다.</Note>

<Steps>
  <Step title="U2M connector 열고 활성화하기">
    Replit 계정 홈에서 **Settings**를 연 다음 **Integrations**로 이동합니다. `Databricks U2M`을 검색해 **Databricks for Databricks Apps (U2M)**를 찾은 뒤 **Enable**을 선택합니다.

    Databricks app connection에서 확인한 **Client ID**와 **Client Secret**을 입력합니다.

    Replit에 표시된 리디렉션 URL이 Databricks에 구성한 URL과 일치하는지 확인합니다.

    ```text theme={null}
    https://replit.com/connectors/oauth/callback
    ```

    **Connector Scopes**에서 `all-apis`와 `offline_access`를 활성화합니다. `offline_access` scope를 사용하면 Replit이 장기 session에 필요한 refresh token을 받습니다.

    **Configure**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/enable-connector-39c1eeebd230.png" alt="리디렉션 URL, OAuth 자격 증명 필드, connector scope가 표시된 활성화 패널과 함께 Databricks U2M으로 필터링된 Replit Integrations 설정" width="2000" height="1144" data-path="images/connectors/databricks/u2m/enable-connector.png" />
    </Frame>
  </Step>

  <Step title="connector 활성화 여부 확인하기">
    **Databricks for Databricks Apps (U2M)**가 **Your integrations** 아래에 표시되는지 확인합니다.
  </Step>
</Steps>

<div id="step-4-sign-in-as-a-builder">
  ### 4단계: builder로 로그인
</div>

각 builder는 connector를 사용하기 전에 자신의 Databricks 계정으로 로그인합니다. Replit은 refresh token이 만료될 때까지 session을 갱신할 수 있습니다.

<Steps>
  <Step title="connector에 로그인">
    **Integrations** 페이지에서 **Databricks for Databricks Apps (U2M)**을 찾아 **Sign in**을 선택하세요. Connection details를 확인한 다음 **Continue to Databricks for Databricks Apps**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/connect-modal-8ae2c2569658.png" alt="리디렉션, 개인정보 보호 및 권한 제어를 설명하는 Connect Databricks for Databricks Apps 모달" width="2000" height="1144" data-path="images/connectors/databricks/u2m/connect-modal.png" />
    </Frame>
  </Step>

  <Step title="SQL Warehouse 세부 정보 입력">
    Databricks 관리자에게 받은 SQL Warehouse **HTTP path**를 입력한 다음 **Next**를 선택하세요.

    <Frame>
      <img src="/assets/mirror/http-path-9e8a8a14b6ab.png" alt="2단계 중 1단계에서 SQL Warehouse HTTP path를 입력하도록 요청하는 Connect Databricks for Databricks Apps 대화 상자" width="2000" height="1144" data-path="images/connectors/databricks/u2m/http-path.png" />
    </Frame>

    이어서 Replit이 SQL Warehouse **Server hostname**을 요청합니다. 값을 입력하고 Databricks로 계속 진행하세요. 로그인 화면이 나타나면 로그인한 뒤, 요청된 접근 권한을 확인하고 승인합니다.

    Agent가 이 연결을 통해 실행하는 모든 쿼리에는 사용자의 Databricks permissions가 적용되며, Databricks audit logs에 사용자 본인의 활동으로 기록됩니다.

    승인이 완료되면 Databricks가 다시 Replit으로 이동시키며, 이때부터 connector를 사용할 수 있습니다.
  </Step>
</Steps>

<div id="set-up-the-service-principal-connector">
  ## service principal connector 설정
</div>

service principal 설정에는 다음 세 가지 역할이 필요합니다:

1. **Databricks 관리자**: Databricks에서 service principal을 생성하고 permissions을 부여합니다.
2. **Replit Organization Admin**: Replit에서 connector와 액세스 권한을 구성합니다.
3. **Builder**: 공유된 Databricks 자격 증명으로 building을 시작합니다.

<div id="service-principal-prerequisites">
  ### service principal 사전 요구 사항
</div>

시작하기 전에 다음 항목을 확인하세요.

* Databricks account admin 또는 workspace admin 액세스 권한
* Replit Organization Admin 액세스 권한

<div id="step-1-create-a-service-principal-in-databricks">
  ### 1단계: Databricks에서 service principal 만들기
</div>

<Note>
  이 단계를 완료하려면 Databricks account admin 또는 workspace admin이어야 합니다.
</Note>

Databricks 관리자는 Replit이 Databricks에 연결할 때 사용하는 머신 대 머신 ID인 [service principal](https://docs.databricks.com/aws/en/admin/users-groups/service-principals)을 생성합니다.

<Steps>
  <Step title="Settings 열기">
    Databricks에서 오른쪽 상단의 아바타를 선택한 다음 **Settings**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/settings-menu-8f2dcd4dbee3.png" alt="Settings가 선택된 Databricks workspace 메뉴" width="3438" height="1984" data-path="images/connectors/databricks/settings-menu.png" />
    </Frame>
  </Step>

  <Step title="Identity and access 선택">
    Settings 사이드바에서 **Identity and access**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/settings-page-2a8bcd7c22a4.png" alt="사이드바에 Identity and access가 표시된 Databricks Settings 페이지" width="3438" height="1984" data-path="images/connectors/databricks/settings-page.png" />
    </Frame>
  </Step>

  <Step title="service principal 관리">
    **Management and permissions** 아래에서 **Service principals**를 찾아 **Manage**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/identity-and-access-0e79404ed30f.png" alt="Service principals의 Manage 버튼이 표시된 Identity and access 설정 페이지" width="3438" height="1984" data-path="images/connectors/databricks/identity-and-access.png" />
    </Frame>
  </Step>

  <Step title="새 service principal 추가">
    **Add service principal**을 선택한 다음 **Add new**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/add-service-principal-ac5b52f21f4c.png" alt="Add new 버튼이 있는 Add service principal 대화 상자" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal.png" />
    </Frame>
  </Step>

  <Step title="service principal 이름 지정">
    service principal의 이름을 알아보기 쉽게 입력한 다음 **Add**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/add-service-principal-name-897df9e5f7ac.png" alt="service principal 이름이 입력된 Add service principal 대화 상자" width="3438" height="1984" data-path="images/connectors/databricks/add-service-principal-name.png" />
    </Frame>
  </Step>

  <Step title="service principal 세부 정보 확인">
    Databricks가 service principal을 생성한 후 활성 상태인지 확인합니다. Replit connector를 구성하는 동안 service principal 세부 정보가 필요하다면 이 페이지를 열어 두세요.

    <Frame>
      <img src="/assets/mirror/service-principal-details-15a381d388bc.png" alt="Databricks service principal 세부 정보 페이지" width="3438" height="1984" data-path="images/connectors/databricks/service-principal-details.png" />
    </Frame>
  </Step>

  <Step title="접근 권한 부여">
    **Permissions** tab을 열고 **Grant access**를 선택한 후 service principal을 선택하고, permission을 **Manage**로 설정한 다음 **Save**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/grant-access-edbaa2541a7d.png" alt="Manage permission이 선택된 Databricks service principal의 Grant access 대화 상자" width="3438" height="1984" data-path="images/connectors/databricks/grant-access.png" />
    </Frame>
  </Step>
</Steps>

<div id="step-2-get-your-sql-warehouse-connection-details">
  ### 2단계: SQL Warehouse 연결 정보 확인

Replit connector가 쿼리를 올바른 컴퓨팅 리소스로 라우팅하려면 Databricks SQL Warehouse 연결 정보가 필요합니다.

<Steps>
  <Step title="SQL Warehouses 열기">
    Databricks 사이드바에서 **SQL Warehouses**를 선택합니다.

    <Frame>

  <Step title="웨어하우스 선택 또는 생성">
    Replit Agent가 사용할 SQL Warehouse를 선택합니다. 아직 없다면 **Create SQL warehouse**를 선택해 새 웨어하우스를 생성합니다.

  <Step title="연결 정보 복사">
    해당 웨어하우스를 열고 **Connection details**를 선택합니다. **Server hostname**과 **HTTP path** 값을 확인하세요. Replit에서 Databricks connector를 생성할 때 이 값들이 필요합니다.

    <Frame>
      <img src="/assets/mirror/connection-details-938b970b98e6.png" alt="서버 호스트 이름과 HTTP 경로가 표시된 Databricks SQL Warehouse 연결 정보 페이지" width="3438" height="1984" data-path="images/connectors/databricks/connection-details.png" />

  </Step>

<div id="step-3-create-the-databricks-connector-in-replit">
  ### 3단계: Replit에서 Databricks connector 만들기
</div>

<Note>connector를 구성하려면 Replit 조직 관리자여야 합니다.</Note>

Replit 관리자가 Databricks 연결 정보를 Replit에 추가하면 builder가 해당 connector를 사용할 수 있습니다.

<Steps>
  <Step title="Integrations로 이동">
    Replit 계정 홈에서 **Integrations** 페이지를 엽니다. **Connectors** 아래에서 **Databricks (Service Principal)**를 찾아 **Sign in**을 선택합니다.

    <Frame>
      <img src="/assets/mirror/integrations-databricks-signin-75d3367013da.png" alt="Databricks로 필터링된 Replit Integrations 페이지에 Sign in 버튼과 함께 Databricks (Service Principal) connector가 표시된 모습" width="3436" height="1978" data-path="images/connectors/databricks/integrations-databricks-signin.png" />
    </Frame>
  </Step>

  <Step title="연결 확인">
    Replit은 authentication을 위해 Databricks로 이동하기 전에 확인 대화 상자를 표시합니다. 세부 정보를 확인한 후 **Continue to Databricks**를 선택합니다.

    </Frame>
  </Step>

  <Step title="SQL Warehouse HTTP 경로 입력">
    Databricks SQL Warehouse의 Connection details에서 **HTTP path**를 붙여넣은 다음(예: `/sql/1.0/warehouses/abcdef1234567890`) **Next**를 선택합니다.

    <Frame>
      <img src="/assets/mirror/connector-http-path-5c8ae35516f8.png" alt="SQL Warehouse HTTP 경로 입력을 요청하는 Connect Databricks 대화 상자 2단계 중 1단계" width="3436" height="1978" data-path="images/connectors/databricks/connector-http-path.png" />
    </Frame>
  </Step>

  <Step title="SQL Warehouse 서버 호스트 이름 입력">
    동일한 Connection details에서 **Server hostname**을 붙여넣은 다음(예: `abc-12345678-wxyz.cloud.databricks.com`) **Continue to Databricks**를 선택해 authentication을 완료합니다.

    </Frame>
  </Step>

  <Step title="접근 권한 구성">
    역할 기반 access control을 사용해 조직 내에서 이 connector를 사용할 수 있는 Members 또는 groups를 선택합니다.
  </Step>

  <Step title="connector 활성화 확인">

  </Step>

<Steps>
  <Step title="배포용 Databricks App 템플릿 선택하기">
    완성된 앱을 Databricks 환경에 배포하려면 **Databricks App** 템플릿을 선택하세요. 구성된 connector로 Databricks 데이터와 asset에 접근할 때는 이 템플릿이 필요하지 않습니다.

    Replit 홈페이지에서 템플릿 선택기를 열고 **Databricks App**을 선택하세요.

    <Frame>
      <img src="/assets/mirror/databricks-template-cdfbbba1a2ab.png" alt="prompt box 위에 Databricks App 템플릿이 선택된 Replit 홈페이지" width="1200" height="400" data-path="images/connectors/databricks/u2m/databricks-template.png" />
    </Frame>
  </Step>

  <Step title="애플리케이션 설명하기">
    미리 입력된 지침 뒤에 prompt를 추가하세요. 아이디어가 필요하다면 [Databricks Dev Hub 템플릿](https://www.databricks.com/devhub/templates)을 둘러보세요.

  </Step>
</Steps>

<div id="troubleshooting">
  ## 문제 해결
</div>

<AccordionGroup>
  <Accordion title="쿼리가 빈 결과를 반환합니다">
    쿼리를 실행하는 ID의 Databricks permissions를 확인하세요. U2M에서는 개별
    builder가 해당 ID이고, service principal connector에서는 공유 service
    principal이 해당 ID입니다. 해당 ID에 메타데이터 접근 권한은 있어도 데이터
    읽기 권한은 없을 수 있습니다. 필요한 카탈로그, schema 또는 테이블 권한을
    부여한 후 다시 시도하세요.
  </Accordion>

  <Accordion title="connector가 SQL Warehouse에 연결하지 못합니다">
    **Server hostname**과 **HTTP path**가 Databricks의 SQL Warehouse
    Connection details와 일치하는지 확인하세요. U2M의 경우 문제가 발생한
    builder가 입력한 값을 확인하세요. 또한 warehouse가 실행 중인지, 쿼리를
    실행하는 ID에 사용 권한이 있는지도 확인하세요.
  </Accordion>

  <Accordion title="authentication이 실패합니다">
    U2M의 경우, Databricks app connection의 **Redirect URLs** 항목에
    `https://replit.com/connectors/oauth/callback`이 후행 슬래시 없이
    등록되어 있는지 확인하세요. 모든 builder에서 authentication이 실패한다면
    공유 Client ID와 Client Secret을 확인하고, secret이 만료되지 않았는지
    점검한 뒤, Replit의 scopes가 Databricks app connection과 일치하는지
    확인하세요.

    service principal connector의 경우, Replit에 입력한 service principal
    정보가 Databricks에서 생성한 service principal과 일치하는지 확인하세요.
    자격 증명을 교체했다면 Replit에서 connector를 업데이트하세요.
  </Accordion>

  <Accordion title="connector가 다시 로그인하라고 요청합니다">
    U2M에서 refresh token이 만료되거나 취소되면 이런 현상이 발생할 수 있습니다.
    Databricks 승인 flow를 다시 완료하세요. 보안 정책에서 요구하는 것보다
    builder가 더 자주 재연결해야 한다면 app connection의 token 수명을
    검토하세요.
  </Accordion>
</AccordionGroup>
