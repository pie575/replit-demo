---
title: "数据恢复"
description: "将开发数据库还原到检查点，或将生产数据库回滚到特定时间点。"
---

失误在所难免：错误的架构变更、误删的数据行，或者跑偏了的 Agent 会话。Replit 为每种数据库都提供了恢复方式。

| 数据库 | 恢复方式       | 适用范围                                                 |
| --- | ---------- | ---------------------------------------------------- |
| 开发  | 检查点回滚      | 所有套餐                                                 |
| 生产  | 时间点恢复及计划备份 | Core：最多 7 天的历史记录。Pro 和 Enterprise：最多 28 天 (默认 7 天) 。 |

<div id="section">
  ## 恢复开发数据库
</div>

你可以使用[回滚功能](/zh/ko/features/version-control/checkpoints-and-rollbacks/)将应用和开发数据库还原到之前的状态。借助该功能，你可以将数据库恢复到 Agent 创建的任意检查点。

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="显示回滚选项的检查点回滚界面" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

<Info>
  恢复到某个检查点状态时，需要在“更多回滚选项”下选择“Database”。这样数据库就会恢复到该检查点创建时的状态。
</Info>

<div id="section-2">
  ## 恢复生产数据库
</div>

对于生产数据库，你可以使用时间点恢复功能将数据库恢复到特定时间点。

<Frame>
  <img src="/assets/mirror/database-rollbacks-f13dd20874ae.jpg" alt="显示回滚选项的数据库回滚界面" width="1082" height="708" data-path="images/databases/database-rollbacks.jpg" />
</Frame>

可恢复的时间范围因套餐而异。Core 套餐最多保留 7 天的历史记录，Pro 和 Enterprise 套餐最多保留 28 天。所有套餐的初始保留期均为 7 天，你可以在生产数据库设置中更改保留期限。保留期限越长，占用的存储空间越多，因此延长保留期限会增加使用成本。若从 Pro 降级到 Core，保留期限将缩短为 7 天。

<Warning>
  恢复数据库不会恢复应用的代码，回滚应用也不会恢复数据库。若要将两者都还原到同一时间点，请先恢复数据库，然后[回滚到相应的检查点](/zh/ko/features/version-control/checkpoints-and-rollbacks/)并重新发布应用。
</Warning>

<div id="section-3">
  ## 为生产数据库设置计划备份
</div>

计划备份每天创建一个完整的恢复点。启用或更新计划后，Replit 会按浏览器当前时区在午夜前后执行备份。

1. 打开 **Database** 工具并选择生产数据库。
2. 打开 **Settings**，然后在 **Advanced** 下展开 **Scheduled backups**。
3. 若要启用计划备份，请在 **Keep backups for** 中选择保留期限。

可选的保留期限因套餐而异：Core 最长支持 7 天，Pro 和 Enterprise 最长支持 28 天。

<div id="section-4">
  ### 存储费用
</div>

Replit 会对生产数据库的各类存储分别计量：

| 存储类别            | 每 GiB 每月费用 |
| --------------- | ---------: |
| 逻辑数据库存储         |      $0.35 |
| 时间点恢复 (PITR) 存储 |      $0.20 |
| 计划备份存储          |      $0.09 |

<Note>数据库存储费用目前享受 100% 折扣。</Note>

无论使用 PITR、计划备份还是两者兼用，都会收取 $0.35 的逻辑存储费用。计划备份存储每 GiB 的费用低于 PITR 存储。如果每天一个恢复点即可满足需求，可以缩短 PITR 期限并改用计划备份，从而降低恢复存储的费用。备份总费用取决于所存储的备份容量和保留期限。

PITR 可在其期限内提供更多恢复点，而计划备份每天只提供一个恢复点，请根据实际需要选择合适的恢复方式。

<Note>
  此计划以当前 UTC 偏移为基准。受夏令时变更影响，在您更新计划之前，备份时间可能会偏移一小时。偏移量以分钟为单位的时区将使用最接近的整点时间。
</Note>

<div id="section-5">
  ### 恢复计划备份
</div>

1. 在生产数据库设置中打开 **Scheduled backups**。
2. 选择 **View all backups**。
3. 为所需的恢复点选择 **Restore**。
4. 输入 `restore`，然后选择 **Continue**。

恢复后，数据库将切换为所选备份中的数据。当前数据不会被删除，但已连接的服务可能会短暂重连。

<div id="section-6">
  ## 排查发布失败问题
</div>

如果因数据库问题导致发布失败：

1. **查看发布日志**，确认数据库连接或架构冲突的具体错误信息
2. **检查最近的架构变更**，排查其与现有应用代码之间可能存在的冲突
3. 在重新发布之前，**先在部署预览中测试变更**
