---
title: "Replit 共同责任模型"
description: "了解在 Replit 上创建、发布和运行应用时，Replit 与您如何分担安全、合规和运营责任。"
---

安全地构建和发布应用是一项共同责任。Replit 负责 Replit Agent、平台以及运行客户工作负载的基础设施的安全。Replit 采取合理的控制措施并遵循安全标准运营这些服务，同时提供工具供您保护应用和数据。您负责应用内容，并负责使用和配置 Replit 提供的工具。

这是有意为之的平衡。Replit 希望您构建任何能想到的内容，而这种自由意味着某些决策需要由您来做。下表介绍了 Replit 的共同责任模型，其框架遵循成熟的云和 AI 共同责任模型 ([Microsoft AI SRM](https://learn.microsoft.com/en-us/azure/security/fundamentals/shared-responsibility-ai)、[CSA AICM](https://cloudsecurityalliance.org/artifacts/ai-controls-matrix)) ，并以 [ISO/IEC 42001](https://www.iso.org/standard/42001) 和 [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) 为基础：

<div id="como-a-responsabilidade-dividida">
  ## 责任如何划分
</div>

表中的大多数条目遵循以下三种模式之一：

* **机制与配置。** Replit 提供各项控制措施：RBAC、可见性设置、MFA、SSO、数据驻留和数据保留。您决定启用哪些措施以及如何配置。
* **检测与修复。** Replit 监控平台，并公开其所能发现的问题：存在漏洞的依赖项、滥用迹象和平台异常。您负责监控和修复应用内的问题，因为只有您知道在您的上下文中“已修复”意味着什么。
* **第一方与第三方。** 经 Replit 验证的 skills、MCP 工具和 Connectors 均由 Replit 审核。您自行连接、安装或配置的任何内容，都需由您负责评估、配置、轮换和撤销。

有些条目完全由您负责：使用政策、访问控制、知识产权审查、面向最终用户的隐私声明，以及应用级渗透测试。这些事项依赖于只有您才具备的上下文。其他条目则由 Replit 负责：它们构成您的应用构建和运行所依赖的平台。

这些模式是有意重复的。在一个以自由构建任何内容为核心的平台上，这是唯一诚实的责任划分方式。

<div id="trabalhando-com-o-replit-agent">
  ## 使用 Replit Agent
</div>

您拥有 Agent 生成的代码，并对其负责。实践中，这意味着要养成以下习惯：

1. **发布前先审查。** Agent 能生成可运行的代码，但“可运行”不等于“正确”。请阅读它编写的内容，尤其是涉及身份验证、数据处理以及任何跨越信任边界的部分。让 Agent 编写测试并解释其推理过程，有助于您在迭代过程中发现回归问题。
2. **不要在提示词中包含密钥。** 请使用 Secrets 和 Connectors。不要在 Chat 中粘贴 API 密钥、令牌或凭证：Agent 无需以明文形式获取这些信息即可使用它们，而粘贴这些信息会将受管理的密钥变为未受管理的密钥。
3. **说明您的业务逻辑和访问控制模型。** 告诉 Replit Agent，哪些人应能访问您应用的哪些功能。如果您的应用不希望向全世界所有人公开，请选择 Replit 的“私有”或“密码保护”发布选项。
4. **审慎批准敏感操作。** 当 Agent 建议发布应用、修改密钥或发起外部调用时，人工审核环节由您把关。请将其视为真正的审查，而非机械地点一下。

<div id="conformidade-e-resposta-a-incidentes">
  ## 合规与事件响应
</div>

您有责任遵守 [Replit 服务条款](https://replit.com/terms-of-service)，也有责任了解自身的合规和法律要求。如需了解 Replit 在合规方面提供或未提供的支持 (如 SOC 2 Type II、子处理方、认证等) ，请访问 [replit.com/security](https://replit.com/security)。

如果您发现 Replit 平台中的漏洞，请按照 Replit 的[负责任披露](https://en.wikipedia.org/wiki/Coordinated_vulnerability_disclosure)流程报告至 [security@replit.com](mailto:security@replit.com)。如果您在自己构建的应用中发现漏洞，则由您负责分级处置。平台事件将按照 Replit 的事件响应政策处理；源自您的应用、数据或最终用户账户的事件，则由您负责牵头处理。
