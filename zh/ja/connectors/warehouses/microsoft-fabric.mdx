在 Replit 中构建 AI 驱动的应用，并将其直接发布到 Microsoft Fabric，同时内置企业级治理和安全性。Microsoft Fabric 集成可将受治理的企业数据转化为控制台、工作流、AI 应用等内部工具。团队可以从提示词快速推进到生产环境，而认证和访问策略始终保留在已受信任的 Fabric 环境中。

<div id="fabric">
  ## 什么是 Fabric 数据应用
</div>

Fabric 数据应用是静态 React 应用，可针对 Power BI 语义模型运行 [DAX (数据分析表达式) ](https://learn.microsoft.com/en-us/dax/) 查询并渲染 Power BI 图表。构建时需注意以下特性：

* **Power BI 语义模型是数据源。** 图表由针对所连接语义模型 (数据集) 执行的 DAX 查询驱动。
* **按设计为只读。** 应用使用 DAX 的 `EVALUATE` 读取数据，不会将数据写回 Power BI。如果需要可写状态，请在控制台之外使用独立的应用数据库。
* **通过 Fabric 门户渲染。** 数据层在 Microsoft Fabric 门户中运行，针对语义模型执行查询并将结果返回给应用。数据始终保留在 Fabric 环境中。
* **托管在 Microsoft 基础设施上。** 您可以将完成的数据应用发布到 Microsoft 托管服务，使其与 Fabric 环境的其余部分一同运行。

<Note>
  Microsoft Fabric 数据应用需要访问包含 Power BI 语义模型的 Microsoft Fabric 租户；在预览期间，还需加入获批准的测试者计划。
</Note>

在后台，[Rayfin](https://github.com/microsoft/rayfin) (用于构建应用后端的开源 SDK 和 CLI) 让 Agent 能够基于 Fabric 数据定义和发布可用于生产环境的应用。

您可以在单个工作流中完成整个过程：描述您的应用，让 Agent 搭建脚手架，连接受治理的 Fabric 数据，并将应用发布到组织的 Fabric 租户中运行。

本指南介绍构建者工作流程、应用连接 Fabric 数据的方式，以及团队协作和自动化选项。有关基于其他数据仓库的通用数据仪表板，请参阅[数据可视化](/zh/ja/features/artifact-types/data-apps)。

<div id="section">
  ## 使用场景
</div>

对于已投入 Microsoft 数据生态系统的组织而言，这为构建内部软件提供了更快捷的途径。团队无需花费数周时间集成认证、API、部署工具和治理策略，只需描述所需内容，让 Agent 来构建。

常见使用场景包括：

* 部门专用的生产力工具
* 运营控制台
* 数据探索工具
* 工作流自动化应用
* 报告界面

对于企业 IT 而言，治理、认证和安全性都保留在其已管理的现有 Fabric 环境中，因此快速创建应用无需以牺牲集中管理为代价。

<div id="fabric-2">
  ## 构建 Fabric 数据应用
</div>

构建过程采用对话式交互。认证和数据访问会根据提示词通过 Microsoft 完成，您始终无需离开 Replit。

<Steps>
  <Step title="从 Fabric 模板开始">
    在 Replit 主页打开 **模板** 下拉菜单，然后从 **Org templates** 下选择 **Microsoft Fabric App**。这会让 Agent 预加载 Fabric 工具，并进入数据应用工作流。

    <Frame caption="在 Replit 主页选择 Microsoft Fabric App 组织模板（私密预览界面）。">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Replit 主页打开了 模板 下拉菜单，Microsoft Fabric App 在 Org templates 下高亮显示" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="描述您想要的控制台">
    输入提示词，描述您想构建的控制台或报表工具。例如：“根据 Fabric 销售模型构建一个环比销售增长控制台”。无需编写 DAX，Agent 会生成查询。
  </Step>

  <Step title="使用 Microsoft 登录">
    出现提示时，使用拥有 Fabric 数据的租户的 Microsoft OAuth 登录。这将授予 Agent 读取您有权访问的语义模型的权限。您登录时使用的身份必须拥有所用 Fabric 工作区的访问权限。
  </Step>

  <Step title="添加数据源">
    Agent 提示时，请分享您想使用的 Power BI / Fabric 语义模型。您可以提供 Fabric 门户中的完整数据集 URL (例如：`https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) ，或提供工作区 ID 和数据集/项目 ID。Agent 会利用这些信息识别要查询的工作区和语义模型。

    模型必须已发布到 Power BI 服务，不能使用本地 `.pbix` 文件。

    <Frame caption="Agent 请求 Power BI / Fabric 语义模型链接（私密预览界面）。">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Agent 面板要求构建者通过 Fabric 门户中的完整 URL，或工作区 ID 和数据集/项目 ID 分享 Power BI 或 Fabric 语义模型，并注明本地 .pbix 文件不可用，因为模型必须已发布到 Power BI 服务" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="让 Agent 构建并迭代">
    Agent 会探索语义模型的架构、编写 DAX 查询，并使用合适的图表搭建控制台。查看结果后，可以用自然语言请求修改，例如添加筛选器、更改图表类型或添加其他指标。
  </Step>

  <Step title="发布（可选）">
    控制台准备就绪后，您可以将其发布到 Microsoft 托管服务，并在 Fabric 环境中运行。发布流程将在其他文档中说明。本指南重点介绍如何连接数据并构建应用。
  </Step>
</Steps>

<div id="fabric-3">
  ## 连接到 Fabric 数据
</div>

要读取数据，您的应用需要连接到 Microsoft Fabric 并完成认证。Replit 会通过以下两种方式之一建立连接。

<div id="fabric-4">
  ### 应用级 Fabric 登录 (面向查看者)
</div>

已发布数据应用的查看者无需配置连接器。他们可通过嵌入应用的 Microsoft Fabric 单点登录完成认证，应用将通过 Fabric 门户以查看者身份读取数据。这样，访问权限仍由现有的 Fabric 权限控制。

<div id="microsoft-fabric">
  ### Microsoft Fabric 连接器 (为构建者提供的简便途径)
</div>

对于构建者来说，**Microsoft Fabric 连接器**可便捷地授权开发过程中的数据访问。它是可选的简便途径，并非必需条件。

* 首位完成设置的构建者只需完成一次与 Microsoft 的 **OAuth 授权**。
* **同一项目中的其他协作者**会继承此连接。
* **不同工作区**需要启用连接器，并各自完成 OAuth 授权。
* 已通过 OAuth 授权的身份必须拥有目标 Fabric 工作区的访问权限。

该连接器使用 Microsoft Entra OAuth，并受限于特定租户。与其他 Replit 连接器一样，你可以在项目的[集成](/zh/ja/features/integrations/overview)页面中管理它。有关连接器的一般概念，请参阅[管理连接器](/zh/ja/replitai/managing-connectors)。

<Note>
  在私有预览期间，Microsoft Fabric 连接器不提供由 Replit 管理的共享凭据。构建者需使用自己的 Microsoft Entra 租户进行授权。
</Note>

<div id="section-2">
  ## 团队与自动化
</div>

对于团队共享使用或非交互式环境 (例如 CI) ，交互式 OAuth 并不总是切实可行。在这种情况下，请通过项目的 [Secrets](/zh/ja/core-concepts/project-editor/app-setup/secrets) 提供**服务主体**令牌，而非以交互方式登录。应用将使用服务主体的身份读取 Fabric 数据。

这是最接近机器对机器配置的方式：在 Microsoft Entra 中预配并授予 Fabric 工作区访问权限的非人类身份，可在无需人工干预的情况下对应用进行认证。请确保服务主体拥有对应用所查询工作区和语义模型的访问权限。

<div id="section-3">
  ## 故障排除
</div>

<AccordionGroup>
  <Accordion title="应用预览中无法加载数据">
    Fabric 数据层通过 Microsoft Fabric 门户运行。如果图表显示为空，或应用预览无法加载数据，请确认你已完成 Microsoft 登录，并且当前登录的身份有权访问所关联的工作区和语义模型。
  </Accordion>

  <Accordion title="Agent 找不到语义模型">
    请从 Fabric 门户粘贴 Power BI 数据集链接，并确认你的身份 (或服务主体) 至少拥有该工作区的读取权限。如果 Agent 提示无法解析工作区或模型，请重新分享数据集链接。
  </Accordion>

  <Accordion title="连接器卡住或反复显示连接提示">
    请在项目的[集成](/zh/ja/features/integrations/overview)页面重新授权 Microsoft Fabric 连接器。确认已通过 OAuth 授权的身份拥有 Fabric 工作区的访问权限。对于团队或 CI 使用场景，建议优先使用通过 Secrets 提供的服务主体令牌。
  </Accordion>
</AccordionGroup>
