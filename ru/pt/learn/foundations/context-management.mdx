Контекст — это информация, на основе которой модель ИИ формирует следующий ответ. Управление контекстом — это умение передать модели нужную информацию в нужный момент.

Это важно, потому что ИИ опирается не на ваши намерения, а на текст, файлы, скриншоты, логи, примеры и историю переписки, доступные в его окне контекста.

<div id="o-que-uma-janela-de-contexto">
  ## Что такое контекстное окно?
</div>

У ИИ-модели есть ограничение на объём информации, который она может учитывать одновременно. Это ограничение называется контекстным окном.

В контекстное окно может входить:

* Ваш промпт
* Предыдущие сообщения в диалоге
* Файлы и код, доступные модели
* Сообщения об ошибках и логи
* Скриншоты, изображения или дизайн-референсы
* Инструкции проекта, например `replit.md`
* Результаты работы инструментов на предыдущих шагах

На основе этого контекста модель решает, что сгенерировать дальше.

<div id="por-que-as-janelas-de-contexto-so-importantes">
  ## Почему окна контекста важны
</div>

Если важных деталей нет в контексте, модель начнёт додумывать. А если в контексте слишком много посторонней информации, модель может сосредоточиться не на том.

Например, этот промпт даёт слишком мало контекста:

```text theme={null}
Улучшите страницу регистрации.
```

Этот промпт даёт полезный context:

```text theme={null}
Улучши страницу регистрации для начинающих основателей, которые решают, стоит ли записываться в лист ожидания.
Сохрани текущие поля. Сделай ценностное предложение над формой более понятным.
Не меняй раздел с ценами.
```

Второй промпт сообщает модели, для кого предназначена страница, что улучшить, что сохранить и что выходит за рамки задачи.

<div id="os-tamanhos-das-janelas-de-contexto-variam">
  ## Размеры контекстных окон различаются
</div>

Разные модели ИИ могут обрабатывать разный объём контекста. Более крупные контекстные окна позволяют учитывать больше текста за один раз, но больше — не всегда лучше. Релевантный контекст всё равно важнее, чем загружать в диалог все детали.

Примеры публично заявленных размеров контекстных окон:

| Семейство моделей | Пример размера контекстного окна |
| ----------------- | -------------------------------- |
| GPT-4.1           | До 1 миллиона токенов            |
| Claude Sonnet 4.5 | До 200 000 токенов               |
| Gemini 2.5 Pro    | До 1 миллиона токенов            |

Эти показатели со временем меняются и не гарантируют, что каждый продукт предоставляет полный лимит модели. Практический вывод остаётся неизменным: важная информация должна быть ясной и сфокусированной.

<div id="tipos-de-contexto">
  ## Типы контекста
</div>

| Тип контекста              | Пример                                                                      |
| -------------------------- | --------------------------------------------------------------------------- |
| **Цель**                   | «Эта landing page должна собирать заявки в список ожидания».                |
| **Аудитория**              | «Это для занятых владельцев ресторанов».                                    |
| **Ограничения**            | «Сохраните текущую цветовую палитру и поля формы».                          |
| **Чего делать не нужно**   | «Пока не добавляйте платежи».                                               |
| **Примеры**                | Скриншот, макет, примеры данных или страница конкурента.                    |
| **Состояние проекта**      | Текущий файл, компонент, сообщение об ошибке или пользовательский сценарий. |
| **Определение готовности** | «Посетитель может отправить форму и увидеть сообщение с благодарностью».    |

<div id="contexto-fresco-e-contexto-persistente">
  ## Свежий контекст и постоянный контекст
</div>

Часть контекста относится к текущему диалогу. Используйте его, когда просите внести конкретное изменение, разбираетесь с ошибкой или даёте обратную связь по недавнему результату.

Другой контекст должен сохраняться на протяжении всего проекта. Постоянный контекст используйте для стиля кода, брендбука, соглашений об именовании, многократно применяемых правил продукта и ограничений, которые Agent должен помнить между рабочими сессиями. В Replit файл [replit.md](/ru/pt/features/project-setup/replit-dot-md) — один из способов передать Agent постоянный контекст проекта.

<div id="quando-o-contexto-fica-ruidoso">
  ## Когда контекст становится шумным
</div>

Длинные разговоры могут уходить в сторону. Если в thread смешалось много не связанных между собой решений, Agent может опираться на старый контекст, который уже неактуален.

Начинайте новый thread, когда:

* вы переключаетесь на не связанную с текущей задачей функцию;
* в разговоре накопилось много брошенных направлений;
* Agent продолжает применять устаревшие ограничения;
* вам нужен чистый план для новой области.

Начиная с нуля, кратко изложите важный контекст, а не рассчитывайте на то, что Agent помнит, что всё ещё имеет значение.

```text theme={null}
Контекст: этот проект — app со списком ожидания для местных персональных тренеров.
Основной сценарий: landing page → форма регистрации → сообщение с подтверждением.
В рамках этого thread улучши только сообщение с подтверждением и текст последующего письма.
```

<div id="equvocos-comuns">
  ## Распространённые заблуждения
</div>

* **«Чем больше контекста, тем лучше».** Лучше не больше, а релевантнее. Избыток посторонней информации только отвлекает модель.
* **«Модель всё запоминает идеально».** ИИ опирается на доступный контекст, но важные ограничения стоит повторять, когда они действительно имеют значение.
* **«Контекст — это только текст».** Скриншоты, файлы, данные, дизайны, логи и примеры тоже могут служить контекстом.
