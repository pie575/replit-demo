# Replit Auth

> Replit Auth로 앱에 사용자 인증을 추가하는 방법을 알아보세요 — 사용자는 자신의 Replit 계정으로 로그인하며, 별도의 설정이 필요하지 않습니다.

Replit Auth를 사용하면 앱에서 개인화된 사용자 경험을 만들 수 있습니다. 사용자 계정을 통해 사용자 환경설정을 저장하고, 맞춤 대시보드를 만들고, 소셜 기능을 구축하고, 프리미엄 콘텐츠 접근을 제어하고, 사용자 활동을 추적할 수 있습니다 — 앱을 매력적이고 가치 있게 만드는 모든 기능입니다.

Replit Auth는 Replit 자체 로그인 시스템을 사용합니다 — 누군가가 앱에 로그인하면, 그들은 기존 **Replit 계정**을 사용하거나 새로 만드는 것입니다. 로그인 페이지는 Replit 브랜드로 표시되며, 로그인 흐름은 replit.com 전체에서 사용되는 것과 동일합니다.

<Note>
  **Replit Auth와 Clerk Auth 비교** — Replit은 두 가지 인증 옵션을 제공합니다. **Replit Auth**(이 페이지)는 Replit 자체 로그인 시스템을 사용하므로, 앱의 사용자는 Replit 계정으로 로그인하고 Replit 브랜드의 로그인 페이지를 보게 됩니다. \*\*[Clerk Auth](/ko/features/auth-and-identity/clerk-auth)\*\*는 앱에 전용 인증 테넌트를 제공하며, Clerk가 이를 구동합니다. 완전히 커스터마이즈 가능한 브랜딩과 Replit과는 독립적인 사용자 계정을 사용할 수 있습니다. 로그인 경험에 자체 브랜드를 적용하고 싶거나 Replit과 연결되지 않은 사용자 계정이 필요하다면 Clerk Auth를 선택하세요.

  앱이 이미 Replit Auth를 사용하고 있다면, 자동화된 마이그레이션 흐름과 기존 앱 데이터 접근을 유지하기 위한 테스트 단계는 [Replit Auth에서 Clerk로 마이그레이션하기](/ko/features/auth-and-identity/migrate-auth-to-clerk)를 참고하세요.
</Note>

인증을 처음부터 구축하는 데 몇 달을 쏟는 대신, Replit Auth는 단 하나의 Agent 프롬프트로 엔터프라이즈급 기능을 제공합니다. Firebase, Google Cloud Identity Platform, reCAPTCHA, Stytch, Clearout 등 포춘 500대 기업과 동일한 인프라를 기반으로 하여, 전문가 수준의 보안, 부정 사용 방지, 글로벌 확장성이 기본으로 제공됩니다.

## Replit Auth를 사용하는 이유

인증은 기업 전체가 전담하여 해결하는 어려운 문제입니다. 앱의 주요 목적은 대개 인증이 아니라, 여러분이 구축하고 있는 고유한 아이디어나 솔루션일 것입니다.

Replit Auth가 제공하는 것:

* **설정 불필요** — Agent에 프롬프트 한 번만 입력하면 인증이 추가됩니다
* **Replit 계정 통합** — 사용자는 기존 Replit 계정으로 로그인하므로 별도의 계정 생성 단계가 필요 없습니다
* **내장 보안** — 일반적인 공격에 대한 보호 기능이 포함된 Replit 인프라를 사용합니다
* **사용자 관리** — Auth 패널을 통한 간소화된 사용자 관리
* **데이터베이스 통합** — 데이터베이스에 사용자 항목이 자동으로 생성됩니다
* **커스터마이즈 가능한 로그인 페이지** — 앱의 로그인 경험을 개인화할 수 있습니다(Replit 브랜딩 포함)
* **비밀번호 재설정** — Replit이 비밀번호 재설정 이메일을 대신 보내주므로 자체 이메일 전송 제공자를 설정할 필요가 없습니다
* **추천 프로그램** — Replit Auth로 가입한 사용자는 대기 중인 Replit Referrals에 추가됩니다
* **개발 및 게시된 앱** — Replit Auth는 개발(replit.dev)과 게시된 앱(replit.app 및 커스텀 도메인) 모두에서 원활하게 작동합니다

## 엔터프라이즈급 인프라

Replit Auth는 단순한 사용자 관리 그 이상입니다 — 엔터프라이즈급 인프라 위에 구축된 완전 관리형 인증 솔루션입니다. 이 강력한 조합은 포춘 500대 기업이 사용하는 것과 동일한 인증 기능을 앱에 제공합니다.

* **Firebase 및 Google Cloud Identity Platform** - Google의 검증된 인증 인프라와 엔터프라이즈급 SLA
* **고급 보안 스캐닝** - reCAPTCHA 통합을 통한 봇 및 악의적 행위자에 대한 자동 보호
* **부정 사용 방지** - Clearout이 제공하는 이메일 인증 및 검증으로 가짜 계정 방지
* **다중 인증(MFA)** - Stytch의 엔터프라이즈 인증 플랫폼이 지원하는 안전한 로그인 옵션
* **글로벌 확장성** - 자동 확장과 안정성을 바탕으로 수백만 명의 사용자를 처리할 수 있도록 설계됨

이 엔터프라이즈 기반 덕분에, 수십억 달러 규모 기업을 보호하는 것과 동일한 인프라가 인증을 담당한다는 사실을 알면서 앱만의 고유한 기능을 구축하는 데 집중할 수 있습니다. 여러 서비스를 통합하는 데 몇 달을 쏟는 대신, 단 하나의 Agent 프롬프트로 이 모든 기능을 얻을 수 있습니다.

## Replit Auth 시작하기

Replit Auth를 구현하는 유일한 방법은 Agent를 사용하는 것입니다. 프롬프트에 Replit Auth 요청을 포함하기만 하면 됩니다.

```
[여러분의 앱 아이디어]를 만들고 Replit Auth 기능을 포함하는 앱을 만들어 주세요.
```

Agent는 인증에 필요한 모든 코드와 구성을 설정합니다. 수동 구현은 지원되지 않으며, Agent가 모든 복잡한 작업을 대신 처리합니다.

앱의 브랜딩에 맞게 로그인 페이지를 커스터마이즈할 수 있습니다.

1. Project Editor에서 Auth 패널로 이동합니다
2. **Configure**를 클릭합니다
3. 다음 요소를 커스터마이즈합니다:
   * 앱 이름
   * 앱 아이콘
   * 로그인 방법(Google, GitHub, X, Apple, Email)

변경 사항은 앱의 로그인 페이지에 즉시 반영됩니다.

## 사용자 데이터를 데이터베이스와 연결하기

Replit Auth는 데이터베이스에 사용자 항목을 자동으로 생성합니다. 이를 통해 사용자별 데이터를 손쉽게 저장할 수 있습니다. Agent가 사용자 데이터를 데이터베이스와 올바르게 연결하는 방법을 안내해 줍니다.

## 보안 고려 사항

Replit Auth는 Replit의 인프라를 활용하여 일반적인 보안 위협에 대한 내장 보호 기능을 제공합니다. 그러나 다음의 모범 사례는 계속 따라야 합니다.

* 민감한 작업을 수행하기 전에는 항상 서버 측에서 사용자 인증을 검증하세요
* 비밀번호와 같은 민감한 정보를 코드에 저장하지 마세요
* API 키나 시크릿에는 환경 변수를 사용하세요
* 사용자 데이터에 대한 적절한 접근 제어를 구현하세요

## 추천

Replit에 대해 알리는 애플리케이션을 장려하기 위해, Replit Auth로 가입하는 모든 사용자는 자동으로 여러분의 대기 중인 Replit Referrals에 추가됩니다. 이들이 나중에 Replit Core로 업그레이드하면, 현재 추천 프로그램 약관에 따라 받을 자격이 있는 추천 보너스를 받게 됩니다.

## 문제 해결

### 일반적인 문제

1. **로그인 후 사용자가 인식되지 않음**
   * 문제가 발생하면 [Replit Agent](/ko/features/agent/overview)에게 인증 구현을 디버깅하는 데 도움을 요청하세요.

2. **커스텀 아이콘이 표시되지 않음**
   * 아이콘 URL에 접근할 수 있고 지원되는 형식(PNG 또는 JPG)인지 확인하세요.

3. **새로 연결한 커스텀 도메인이 작동하지 않음**
   * 도메인 목록(REPLIT\_DOMAINS 환경 변수)을 새로 고치려면 다시 게시하세요.
