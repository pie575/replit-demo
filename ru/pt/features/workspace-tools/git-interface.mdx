Панель Git в Replit предоставляет визуальный интерфейс для работы с Git, избавляя от необходимости использовать команды Git в командной строке. Благодаря этой функции контроль версий доступен начинающим и при этом остаётся мощным инструментом для опытных разработчиков.

<div id="recursos">
  ## Возможности
</div>

Панель Git предоставляет полноценные инструменты контроля версий прямо в редакторе проектов. Интуитивно понятный интерфейс упрощает сложные операции Git.

* **Управление репозиториями**: инициализируйте, подключайте и управляйте Git-репозиториями с интеграцией GitHub
* **Отслеживание коммитов**: добавляйте изменения в индекс (stage), создавайте коммиты и просматривайте изменения во всех файлах
* **Операции с ветками**: визуально создавайте, переключайте и сливайте ветки
* **Разрешение конфликтов**: выявляйте и устраняйте конфликты слияния с помощью визуальных средств
* **Интеграция с Shell**: синхронизация команд Git, выполненных в Shell, с панелью Git

  ## Использование

<div id="configurao-do-repositrio">
  ### Настройка репозитория
</div>

<Accordion title="Как открыть панель Git">
  1. Перейдите в раздел Tools в Replit App
  2. Нажмите значок **+**, чтобы добавить новые инструменты
  3. Выберите **Git** в списке доступных инструментов
</Accordion>

Панель Git позволяет настроить и подключить репозиторий:

* **Инициализировать репозиторий**: создайте новый репозиторий Git для Replit App
* **Connect to a Git provider**: подключите репозиторий к поддерживаемому провайдеру Git — облачному или самостоятельно развёрнутому — для резервного копирования и совместной работы
* **Configure remote**: настройте подключение к удалённому репозиторию и управляйте им

<Note>
  **Поддержка самостоятельно развёрнутого Git**: Replit поддерживает GitHub Enterprise Server, GitLab Self-Managed и Bitbucket Data Center на тарифе Enterprise. [Свяжитесь с отделом продаж Replit](https://replit.com/enterprise), чтобы получить рекомендации по интеграции, настройке провайдера и устранению неполадок с подключением. Также можно [настроить удалённый репозиторий с помощью команд Git в Shell](#usando-comandos-git-no-shell).
</Note>

<div id="gerenciamento-de-alteraes">
  ### Управление изменениями
</div>

<Accordion title="Как просмотреть изменения">
  1. Внесите изменения в любой файл своего Replit App
  2. Откройте панель Git в разделе Tools
  3. Просмотрите изменения в разделе **Review Changes**
</Accordion>

Панель Git предоставляет инструменты для управления изменениями в коде:

* **Review changes**: просматривайте изменённые файлы с выделенными добавлениями и удалениями
* **Добавление файлов в индекс**: выберите файлы, которые нужно включить в следующий коммит
* **Создание коммита**: сохраните изменения с понятным сообщением
* **Push updates**: отправьте коммиты в удалённый репозиторий одним щелчком

<div id="gerenciamento-de-branches">
  ### Управление ветками
</div>

<Accordion title="Как управлять ветками">
  1. Откройте панель Git в разделе Tools
  2. Откройте раскрывающееся меню веток рядом с названием текущей ветки
  3. Создайте новую ветку или выберите существующую
</Accordion>

Панель Git упрощает работу с несколькими версиями кода:

* **Создание веток**: создавайте новые ветки для независимой разработки функций
* **Переключение веток**: переключайтесь между разными версиями кода
* **Публикация веток**: отправляйте свои ветки в провайдер Git
* **Получение изменений**: синхронизируйте изменения с удалёнными обновлениями от соавторов

<div id="resoluo-de-conflitos-de-merge">
  ### Разрешение конфликтов при слиянии
</div>

<Accordion title="Как разрешить конфликты при слиянии">
  1. При возникновении конфликтов попробуйте выполнить pull изменений
  2. На панели Git будут выделены конфликтующие файлы
  3. Откройте каждый конфликтующий файл, чтобы просмотреть и разрешить конфликты
  4. Сохраните файлы после разрешения конфликтов
  5. Завершите слияние, выбрав **Pull**
</Accordion>

Когда изменения кода из разных источников конфликтуют, панель Git помогает:

* **Выявлять конфликты**: точно определять, какие файлы содержат конфликты
* **Просматривать различия**: сравнивать две версии конфликтующего кода
* **Разрешать конфликты**: выбирать, какой код сохранить, или вручную редактировать конфликтующие участки
* **Завершать слияния**: завершать процесс слияния после разрешения конфликтов

После разрешения конфликтов в файле можно удалить маркеры конфликта: удалите строки, начинающиеся с символов конфликта, и сохраните файл.

<div id="usando-comandos-git-no-shell">
  ### Использование команд Git в Shell
</div>

<Accordion title="Как открыть Shell">
  1. Выберите **All tools** в Tool dock слева
  2. Выберите **Shell** среди доступных инструментов
</Accordion>

<Tip>
  Хотя панель Git имеет интуитивно понятный интерфейс, опытные пользователи могут выполнять в Shell стандартные команды Git для более сложных операций. Изменения, внесённые любым из этих способов, будут отражаться в обоих местах.
</Tip>

Если вы предпочитаете работать с Git через командную строку:

* **Синхронизация команд**: любая команда Git, выполненная в Shell, автоматически синхронизируется с панелью Git
* **Полная функциональность Git**: доступ к расширенным возможностям Git, недоступным в панели Git
* **Удобное переключение**: при необходимости переключайтесь между командами Shell и панелью Git

<Info>
  **Поддержка CLI GitHub и GitLab**: помимо стандартных команд Git, в Shell можно использовать [CLI GitHub](https://docs.github.com/en/github-cli) (`gh`) и [CLI GitLab](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) для управления внешними Git-репозиториями и подключения к ним. Эти инструменты предоставляют расширенные возможности для работы с репозиториями GitHub и GitLab, включая pull requests, issues и другие функции, характерные для этих платформ.
</Info>

<div id="operaes-de-repositrio">
  #### Операции с репозиторием
</div>

* **Клонировать репозиторий**: `git clone <url-to-repository>`
* **Инициализировать репозиторий**: `git init`
* **Добавить удалённый репозиторий**: `git remote add origin <url-to-repository>`

<div id="fazendo-alteraes">
  #### Внесение изменений
</div>

* **Проверка статуса**: `git status` (показывает изменённые, добавленные и удалённые файлы)
* **Добавление файлов в индекс**: `git add <filename>` или `git add .` (для всех файлов)
* **Создание коммита**: `git commit -m "your commit message"`
* **Отправка изменений**: `git push origin <branch-name>`
* **Получение изменений**: `git pull origin <branch-name>`

<div id="autenticao">
  #### Аутентификация
</div>

При работе с приватными репозиториями необходимо пройти аутентификацию:

* Для репозиториев GitHub.com используйте персональный токен доступа вместо пароля
* Чтобы не вводить учётные данные повторно, сохраните их в Replit Secrets:
  1. Создайте новый secret с ключом `GIT_URL`
  2. Укажите значение `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Используйте `git push $GIT_URL`, чтобы отправить изменения без ввода учётных данных

<Note>
  При использовании secrets с учётными данными любой пользователь, имеющий доступ к вашему Replit App, потенциально может получить доступ к вашим учётным данным Git. Для конфиденциальных репозиториев вводите учётные данные вручную при каждом использовании.
</Note>
