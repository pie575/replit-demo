    if (typeof window === "undefined" || typeof document === "undefined") {
      return Promise.resolve(null);

    if (window.Typewriter) {
      return Promise.resolve(window.Typewriter);

<div id="define-the-mobile-flow">
  ## 모바일 flow 정의하기
</div>

Build하기 전에 사용자가 휴대폰에서 무엇을 하게 될지 정하세요.

Pace Mobile의 경우:

* **대상 사용자**: 러닝 기록을 빠르게 남기고 싶은 러너.
* **주요 flow**: 러닝 유형 선택 → 거리와 시간 입력 → 러닝 저장 → 오늘의 요약 확인.
* **모바일 제약**: 핵심 동작은 한 손 엄지로 쉽게 닿을 수 있어야 합니다.
* **첫 번째 버전**: 계정 없음, 소셜 피드 없음, Advanced analytics 없음.

이렇게 하면 첫 모바일 slice를 테스트하기에 충분히 작은 규모로 유지할 수 있습니다.

  <img src="/assets/mirror/workspace-dda0f81e6b83.png" alt="mobile app 미리보기와 모바일 기기에서 미리 보기 옵션을 보여주는 Replit Project Editor" width="1440" height="900" data-path="images/native-mobile-apps/workspace.png" />
</Frame>

다음 항목을 확인하세요:

* 오류 없이 앱이 실행되는지
* 러닝 유형을 선택할 수 있는지
* 거리와 시간을 입력할 수 있는지
* 러닝 기록을 저장할 수 있는지
* 오늘의 요약이 업데이트되는지
* 막히는 곳 없이 화면을 이동할 수 있는지
* 확대하지 않고도 텍스트를 읽을 수 있는지

<div id="test-on-your-phone">
  ## 휴대폰에서 테스트하기
</div>

시뮬레이터 테스트도 유용하지만, 앱의 사용감이 실제로 괜찮은지는 휴대폰에서 확인해야 알 수 있습니다.

모바일 기기 preview panel을 열고 휴대폰으로 QR 코드를 스캔하세요. Expo Go에서 앱이 열립니다.

<Frame>
  <img src="/assets/mirror/mobile-screen-e5685fc26793.png" alt="Preview on device 패널과 Expo Go용 QR 코드가 표시된 Replit Project Editor Preview에서 실행 중인 mobile app" width="1440" height="900" data-path="images/native-mobile-apps/mobile-screen.png" />
</Frame>

휴대폰에서 다음을 확인하세요:

* 한 손으로 주요 flow를 끝까지 진행할 수 있나요?
* 버튼과 입력 요소가 탭하기에 충분히 큰가요?
* 주요 동작에 손가락이 쉽게 닿나요?
* 키보드가 중요한 입력 필드를 가리지는 않나요?
* 작은 화면에서도 앱의 내용이 잘 파악되나요?

어색한 부분이 있다면 앱 전체를 다시 디자인하지 말고 해당 부분만 수정하도록 Agent에게 요청하세요.

<AiPrompt>
  Pace Mobile을 한 손으로 사용하기 편하도록 개선해 주세요.

  <br />

  Save Run 버튼에 더 쉽게 손이 닿도록 하고, 필요한 곳의 tap targets를 키우고,
  기록 입력 폼은 단순하게 유지해 주세요.

  <br />

  새로운 기능은 추가하지 마세요.

  <br />

  변경 후에는 기록을 저장했을 때 오늘의 요약이 정상적으로 업데이트되는지 테스트해 주세요.
</AiPrompt>

<div id="share-for-feedback">
  ## 피드백을 위한 공유
</div>

휴대폰에서 flow가 잘 동작하면 앱을 게시해 초기 피드백을 받을 수 있는 공유용 Expo Go 버전을 만드세요.

명확한 task 하나를 함께 전달하며 공유하세요:

> 휴대폰에서 Pace Mobile을 열고 기록 하나를 저장한 다음, 탭하거나 읽거나 이해하기에 어색했던 점을 알려주세요.

이렇게 초점이 분명한 피드백은 두루뭉술한 의견보다 활용하기 쉽습니다. 피드백이 하나의 명확한 문제를 가리킨다면, Agent에게 가장 간단한 수정을 요청한 뒤 휴대폰에서 앱을 다시 테스트해 보세요.

<div id="publish-to-the-app-store">
  ## App Store에 게시하기
</div>

시뮬레이터와 Expo Go를 사용해 실제 휴대폰에서 Pace Mobile을 테스트했다면, 같은 앱을 TestFlight와 App Store로 배포할 수 있습니다. 이 과정을 진행하려면 2단계 인증이 설정된 **Apple Developer Program** 멤버십이 필요합니다. 가입 절차, 개인 계정과 Organization 계정의 차이, TestFlight와 App Store 심사, 외부 테스트에 대한 자세한 내용은 [모바일 앱 빌드 및 출시](/ko/build/mobile-app)를 참고하세요.

<Steps>
  <Step title="Publishing 탭에서 App Store 게시 시작하기">
    Expo Go preview가 실행 중이면 **Publishing** 탭을 엽니다. **Production** 아래에 **Ready to publish Pace to the App Store?** 카드가 표시됩니다. **Start publishing to the App Store**를 선택하세요.

    <Frame>
      <img src="/assets/mirror/app-store-02-start-publishing-190eb7841bcf.png" alt="Production 상태와 Ready to publish Pace to the App Store? 카드, Start publishing to the App Store 버튼이 표시된 Project Editor의 Publishing 탭" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-02-start-publishing.png" />
    </Frame>
  </Step>

  <Step title="Expo project 선택하기">
    Replit이 **Launch**를 엽니다. Replit에 내장된 Expo flow입니다. Expo project 이름과 슬러그를 입력하거나 확인한 뒤 **Continue**를 선택하세요. 이미 Expo project가 있다면 **Use existing**을 선택하면 됩니다.

    <Frame>
      <img src="/assets/mirror/app-store-03-choose-expo-project-4707fafffafe.png" alt="Choose Expo project 단계가 활성화된 Launch 대화 상자 — Pace로 미리 채워진 Project name 및 Project slug 필드, Continue 버튼, Use existing 옵션" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-03-choose-expo-project.png" />
    </Frame>
  </Step>

  <Step title="Sign in with Apple">
    App Store listing을 소유할 Apple Developer 계정을 연결하세요. 해당 계정은 Apple Developer Program에 등록되어 있어야 하며, Apple은 two-factor authentication을 필수로 요구하므로 신뢰할 수 있는 기기에서 인증 코드를 승인할 준비를 해두세요.

    <Frame>
      <img src="/assets/mirror/app-store-04-sign-in-apple-459dfc9b84ba.png" alt="Sign in with Apple 단계의 Launch 대화 상자 — Apple Developer 이메일 또는 전화번호와 비밀번호 필드, 비밀번호가 기기를 벗어나지 않으며 계정이 Apple Developer Program에 등록되어 있어야 한다는 안내" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-04-sign-in-apple.png" />
    </Frame>
  </Step>

  <Step title="Apple 앱 선택 또는 생성하기">
    App Store에 표시될 **App name**과 **Bundle ID**(예: `app.replit.pace`)를 입력하세요. 번들 식별자는 첫 build 이후에는 변경할 수 없으므로 신중하게 정하세요.

    <Frame>
      <img src="/assets/mirror/app-store-05-choose-apple-app-3971aea62f14.png" alt="Choose Apple app 단계의 Launch 대화 상자 — App name은 Pace, Bundle ID는 app.replit.pace로 설정되어 있고, 번들 식별자를 나중에 변경할 수 없다는 안내와 Creating app… 버튼" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-05-choose-apple-app.png" />
    </Frame>
  </Step>

  <Step title="App Store로 launch하기">
    Replit이 사용자를 대신해 Apple 인증서를 구성합니다. **Ready for launch** 단계가 활성화되면 **Launch to App Store**를 선택하세요. Replit이 클라우드에서 네이티브 앱을 build한 뒤, TestFlight 베타 review를 위해 해당 build를 App Store Connect에 제출합니다.

    <Frame>
      <img src="/assets/mirror/app-store-06-ready-for-launch-ab02659ee0bb.png" alt="Choose Apple app과 Configure Apple certificates가 완료로 표시된 Ready for launch 단계의 Launch 대화 상자, Launch to App Store 버튼과 Optional launch parameters" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-06-ready-for-launch.png" />
    </Frame>

    Launch가 완료되면 앱이 App Store를 대상으로 설정되었다는 확인 메시지가 표시되고, 이어서 대화 상자가 닫히며 Project Editor로 돌아갑니다.

    <Frame>
      <img src="/assets/mirror/app-store-targeting-f8797071c9e0.png" alt="Targeting App Store가 완료로 표시되고 Redirecting back to Replit 메시지가 나타난 Launch 대화 상자 — Launch to App Store를 선택한 후의 확인 상태" width="3452" height="1988" data-path="images/native-mobile-apps/app-store-targeting.png" />
    </Frame>
  </Step>
</Steps>

<Note>
  버전의 첫 번째 빌드는 일반적으로 테스터가 설치하기 전에 TestFlight 베타 심사를
  거쳐야 합니다. 승인 후에는 이후 빌드가 대체로 더 빠르게 테스터에게 전달됩니다.
  외부 테스터와 공유하거나 App Store 출시를 위해 제출하려면 **App Store Connect**에서
  리스팅을 완성하세요. 전체 App Store Connect 체크리스트는 [모바일 앱 빌드 및 출시](/ko/build/mobile-app)를
  참고하세요.
</Note>

<div id="youre-done-when">
  ## 완료 기준
</div>

* iOS Simulator 또는 Android Emulator에서 앱이 실행됩니다.
* Expo Go로 휴대폰에서 앱이 실행됩니다.
* 주요 모바일 flow를 끝까지 진행할 수 있습니다.
* 텍스트, 버튼, 내비게이션이 휴대폰에서 쓰기에 불편하지 않습니다.
* 테스트할 수 있는 모바일 버전을 Publish하거나 공유했습니다.
* 최소 한 명이 앱을 사용해 보고 피드백을 줄 수 있습니다.
* (선택 사항) App Store 플로우를 통해 앱을 TestFlight에 제출했습니다.

<div id="need-further-help">
  ## 추가 도움이 필요하신가요?
</div>

* **Agent가 web app을 대신 만든 경우:** 처음부터 다시 시작해 빌드 전에 앱 유형으로 **Mobile app**을 선택하세요.
* **Expo Go 미리보기가 이전 상태로 보이는 경우:** 휴대폰을 흔들어 개발자 메뉴를 연 다음 **Refresh**를 선택하세요.
* **tap targets가 너무 작게 느껴지는 경우:** 터치 영역을 키우고 주요 동작을 엄지가 닿는 범위에 배치해 달라고 Agent에게 요청하세요.
* **내비게이션이 복잡하게 느껴지는 경우:** 주요 flow에 꼭 필요한 최소한의 화면으로 앱을 줄여 달라고 Agent에게 요청하세요.
* **시뮬레이터에서는 작동하지만 휴대폰에서는 작동하지 않는 경우:** 하드웨어와 관련된 동작은 실제 기기에서 테스트하고 [네이티브 모바일 앱](/ko/features/artifact-types/building-mobile-apps)를 참고하세요.
* **Publishing이 실패하는 경우:** [모바일 앱 문제 해결](/ko/features/troubleshooting/mobile-app)을 참고하세요.
