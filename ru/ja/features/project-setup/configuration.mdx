Replit App настраивается двумя файлами: `.replit` и `replit.nix`. Они влияют на то, как работает Replit App, — от запуска кода до инструментов разработки и языков программирования.

По умолчанию эти файлы конфигурации скрыты. Чтобы они отображались в Replit App, выберите «Show hidden files» в меню дерева файлов.

<div id="replitnix">
  ## Файл `replit.nix`
</div>

Replit использует `Nix` для управления пакетами и окружением. Файл `replit.nix` служит для следующих целей:

**Указание системных зависимостей:** точно определяет программные пакеты, необходимые вашему Replit App, которыми управляет менеджер пакетов Nix.

**Создание воспроизводимого окружения:** обеспечивает единообразие и воспроизводимость среды разработки, что идеально подходит для совместных проектов и тестирования на разных системах.

Управлять пакетами Nix можно визуально с помощью инструмента `Dependencies`. Подробнее см. в руководстве [Системные зависимости](/ru/ja/features/project-setup/dependency-management#system-dependencies).

Чтобы настроить пакеты в файле `replit.nix`, перечислите [пакеты Nix](https://search.nixos.org/packages) в массиве `deps` с префиксом `pkgs.`. Изменения синхронизируются после перезагрузки оболочки.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="replit">
  ## Файл `.replit`
</div>

Файл `.replit` управляет работой Replit App. В нём используется [формат конфигурации](https://toml.io/en/) `toml`. Ниже перечислены основные настраиваемые параметры:

**Команда запуска:** задаёт команду, выполняемую при нажатии кнопки Run. Каждый шаблон содержит команду запуска по умолчанию, которая позволяет сразу запустить код. Для более сложных приложений используйте [Workflows](/ru/ja/features/workspace-tools/workflows).

**Language Server Protocol (LSP):** предоставляет такие возможности, как автодополнение, навигация по коду, подсветка синтаксиса, а также линтинг и отображение ошибок в реальном времени.

**Переменные среды:** настройте переменные среды, необходимые для корректной работы приложения, и управляйте ими.

**Зависимости и пакеты:** управляйте установкой и настройкой пакетов напрямую через файл `.replit`, чтобы при запуске Replit App могло подготовить все необходимые инструменты. Зависимостями также можно управлять визуально с помощью инструмента `Dependencies`. Подробнее см. в руководстве по [системным модулям](/ru/ja/features/project-setup/dependency-management#advanced-configuration).

Файл `.replit` по умолчанию для приложений Python выглядит следующим образом:

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

<div id="section">
  ## Настройка базовых параметров
</div>

<div id="section-2">
  ### Точка входа
</div>

Это главный файл проекта. Если свойство `run` не задано, среда выполнения запустит файл, указанный в `entrypoint`.

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="run">
  ### Команда `Run`
</div>

Свойство `run` в файле `.replit` определяет первую команду или последовательность команд, которые выполняются при нажатии кнопки `Run` в среде Replit. Команду `Run` можно задать строкой с выполняемой командой или массивом строк, содержащим команду и её аргументы.

Распространённые способы настройки команды `Run`:

* **Одна команда:**
  Этот пример показывает, как указать одну команду для запуска непосредственно в Replit App. При нажатии кнопки `Run` с такой настройкой в панели `Console` появится приветствие:
  **Пример:** `run = "echo 'Hello, Replit!'"`

* **Явные аргументы:**
  Иногда полезно задать аргументы более явно, чтобы избежать обработки кавычек или правил подстановки в оболочке. Можно переписать приведённый выше пример, указав аргументы отдельно.
  Поскольку приветствие явно передаётся как единственный аргумент `echo`, символы `'` и `"` больше не нужны:
  **Пример:** `run = ["echo", "Hello, Replit!"]`

* **Несколько команд:**
  Этот пример показывает, как одновременно запускать несколько процессов, например фронтенд и бэкенд. Это полезно при разработке Python-бэкенда и TypeScript-фронтенда, где каждый сервер привязывается к отдельному порту:
  **Пример:** `run = "python -m app & npm run start & wait"`

<div id="section-3">
  #### Управление процессами
</div>

С помощью `&` можно запускать несколько команд одновременно, но иногда удобнее иметь возможность различать логи отдельных сервисов. Для этого можно [добавить системные зависимости](/ru/ja/features/project-setup/dependency-management#system-dependencies) и организовать оркестрацию нескольких процессов с помощью таких инструментов, как [`process-compose`](https://github.com/F1bonacc1/process-compose).

<div id="build">
  #### Фаза `Build`
</div>

В некоторых языках и средах выполнения перед выполнением кода командой `run` предусмотрена отдельная фаза компиляции. Она предназначена для компилируемых языков, таких как TypeScript, Golang и Java, а также предоставляет параметры для сброса окружения, данных и настроек перед следующим запуском `run`.

* **Компиляция:**
  В репозиториях на TypeScript перед запуском кода может потребоваться выполнить `tsc`.
  **Пример:**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="section-4">
  #### Настройка переменных окружения
</div>

Чтобы передать сервису переменные окружения перед запуском, свойство `run` можно развернуть в [таблицу](https://toml.io/en/v1.0.0#table).

Это более сложное изменение: возможно, потребуется переместить свойство `run = "..."` в файле `.replit`.

Приведённый ниже diff показывает, как указать команду в поле `args` секции `[run]`, а переменную `NAME` — в `[run.env]`:

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# Новую секцию [run] нужно переместить ниже всех
+# свойств верхнего уровня, которые не начинаются с `[`!
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="section-5">
  #### Интерактивность
</div>

Интерактивные программы также можно запускать кнопкой `Run` — это позволяет отделить терминал, в котором выполняется программа, от среды разработки.
Рассмотрим следующий скрипт со счётчиком:

**Пример**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="section-6">
  ## Расширенные параметры конфигурации
</div>

Ознакомьтесь с расширенными параметрами конфигурации, доступными в Replit App. Они позволяют настраивать среду разработки, управлять командами запуска, интегрировать языковые сервисы и работать с зависимостями.

| **Настройка** | **Ключ**                            | **Значение/пример**                         | **Описание**                                                                                     |
| ------------- | ----------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| onBoot        | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Команда, выполняемая при запуске Replit App.                                              |
| compile       | <a name="compile" />`compile`       |  (Пример по умолчанию отсутствует)          | Команда, выполняемая перед командой `run`. Используется для компилируемых языков, таких как C++. |
| language      | <a name="language" />`language`     | `language = "javascript"`                   | Указывает язык при импорте из GitHub или создании Replit App.                             |
| entrypoint    | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | Основной файл, который запускается и отображается при открытии редактора.                        |
| hidden        | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | Файлы или папки, которые по умолчанию скрыты в боковой панели файлов.                            |
| audio         | <a name="audio" />`audio`           | `audio = true`                              | При значении `true` включает общесистемный звук.                                                 |

<div id="section-7">
  ### Примечание о системном звуке
</div>

Если вы указываете `audio = true` в файле `.replit`, может потребоваться перезапустить среду разработки. Откройте палитру команд сочетанием `Cmd+K` на Mac или `Ctrl+K` в Windows, найдите и выберите **Restart compute**.

При запуске графических приложений в правом нижнем углу панели `Output` появляется значок наушников с флажком.
Из-за ограничений браузера его приходится включать заново после каждого обновления страницы.

```toml theme={null}
# Убедитесь, что эта строка находится в начале файла `.replit`, вне разделов, заключённых в квадратные скобки `[`
audio = true
```

<div id="section-8">
  ## Настройки packager
</div>

| **Настройка**    | **Ключ**                                          | **Значение/пример**                           | **Описание**                                                                                |
| ---------------- | ------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| packager         | <a name="language" />`language`                   | `packager.language = "python3"`               | Язык, используемый для работы с пакетами.                                                   |
| функции packager | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Автоматически определяет пакеты, которые нужно установить перед запуском Replit App. |
| функции packager | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | При значении `true` включает поддержку packager.                                            |
| функции packager | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Указывает, требуется ли запуск установки пакетов для хостинга Replit App.            |
| packager         | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | Команда, выполняемая после установки нового пакета через packager.                          |
| packager         | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | Пути, игнорируемые при определении пакетов.                                                 |
| packager         | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | Модули, для которых при установке не выполняется определение пакетов.                       |

<div id="replit-2">
  ### Пример настройки packager в `.replit`
</div>

```toml theme={null}
# Задаём язык для Replit App
packager.language = "python3"

# Включаем функции автоматического управления пакетами
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# Команда, выполняемая после установки каждого пакета
packager.afterInstall = "echo 'Package installed successfully'"

# Указываем пути и пакеты, которые менеджер пакетов должен игнорировать
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# Дополнительные настройки развёртывания
[deployment]
run = ["python3", "app.py"]
```

<div id="section-9">
  ## Настройки деплоя
</div>

| **Настройка** | **Ключ**                              | **Значение/пример**                  | **Описание**                                                                  |
| ------------- | ------------------------------------- | ------------------------------------ | ----------------------------------------------------------------------------- |
| deployment    | <a name="run" />`run`                 | `deployment.run = "npm start"`       | Команда, выполняемая при запуске контейнера деплоя.                      |

<div id="replit-3">
  ### Пример настроек деплоя в файле `.replit`
</div>

```toml theme={null}

# Задает основную точку входа проекта
entrypoint = "app.js"

# Параметры конфигурации для деплоя приложения
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  **Настройка интерпретатора** устарела и больше недоступна в Replit. Вместо неё рекомендуем использовать команду `Run`, чтобы задать, как скрипты и приложения будут запускаться в среде Replit App.
</Note>

<div id="replit-5">
  ## Доступ к метаданным среды Replit App
</div>

<div id="nodejs">
  ### Node.js
</div>

Чтобы получить доступ ко всем переменным окружения:

`console.log(process.env);`

Чтобы получить доступ к отдельной переменной (REPL&#95;SLUG):

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

Чтобы получить доступ ко всем переменным окружения:

```python theme={null}
import os
print(os.environ)
```

Чтобы получить доступ к одной переменной (REPL&#95;SLUG):

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

Чтобы получить доступ ко всем переменным окружения:

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

Чтобы получить доступ к одной переменной (REPL&#95;SLUG):

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```
