<Note>
  Admin API находится в стадии **бета-тестирования**. Доступные endpoints и их поведение могут измениться.
</Note>

Admin API предоставляет администраторам аккаунтов Enterprise программный доступ с учетом областей действия к аналитике аккаунта и функциям администрирования. Используйте API для создания внутренней отчетности, операционных workflows и интеграций для аккаунта Enterprise.

<div id="who-can-access-the-admin-api">
  ## Кто может получить доступ к Admin API
</div>

Admin API доступен только **администраторам Account** в аккаунтах Enterprise. Администраторы Account могут создавать API-ключи и управлять ими. Администраторы рабочего пространства и другие участники Account не могут получить доступ к Admin API или создавать ключи для него.

Подробнее о ролях администраторов Enterprise см. в разделе [Администраторы Account и рабочего пространства](/ru/teams/identity-and-access-management/account-and-workspace-admins).

<div id="create-an-api-key">
  ## Создайте API-ключ
</div>

<Steps>
  <Step title="Откройте настройки Developer">
    Откройте **Settings**. В разделе **Account** выберите **Developer**.
  </Step>

  <Step title="Создайте API-ключ">
    Выберите **Create API key** и укажите доступ только для чтения либо для чтения и записи.
  </Step>

  <Step title="Безопасно храните ключ">
    Скопируйте ключ, начинающийся с `rpl_`, и сохраните его в надёжном менеджере секретов. Относитесь к нему как к паролю и никому не передавайте.
  </Step>

  <Step title="Аутентифицируйте интеграцию">
    Передавайте ключ как Bearer token в API-запросах.
  </Step>
</Steps>

<div id="what-you-can-do">
  ## Что можно делать
</div>

Admin API использует области действия, чтобы определять возможности каждого ключа. Области действия для чтения предоставляют данные аккаунта для отчётности, а отдельные области действия для записи позволяют выполнять такие действия, как обновление бюджетов.

* **Использование:** Просматривайте потребление аккаунта и общую стоимость по главной книге, фильтруйте или группируйте данные по рабочему пространству, участнику, проекту или периоду времени.
* **Рабочие пространства:** Просматривайте списки рабочих пространств и сведения о них, включая количество участников и проектов, администраторов и время создания.
* **Участники:** Просматривайте сведения о членстве в аккаунте и рабочем пространстве, фильтруйте по роли или ищите по имени, имени пользователя либо адресу электронной почты.
* **Проекты:** Просматривайте проекты в командных рабочих пространствах, фильтруйте по видимости или статусу deployment либо ищите по названию, slug или описанию.
* **Бюджеты:** Просматривайте бюджеты аккаунта и используйте область действия `write:budgets` для их обновления.

Ответы API поддерживают постраничную навигацию с помощью курсора и содержат заголовки ограничений частоты запросов, а также `X-Request-Id` для отслеживания запросов.

<div id="build-reports-and-workflows">
  ## Отчёты и Workflows для Build
</div>

Используйте данные Admin API там, где вы уже отслеживаете операции: например, на внутреннем дашборде, в оповещениях Slack или ежемесячном финансовом отчёте. Например, сгруппируйте данные об использовании по рабочему пространству, чтобы отслеживать расходы для каждого рабочего пространства.

<div id="building-with-replit-agent">
  ## Создание приложения с Replit Agent
</div>

Вы можете попросить Replit Agent создать пользовательский дашборд с помощью Admin API. Опишите данные аккаунта, которые хотите отслеживать, например использование по рабочему пространству или расходы по проектам, — и Agent создаст дашборд и интеграцию с API.

<Steps>
  <Step title="Откройте выбор навыков">
    В проекте Replit нажмите кнопку **+** рядом с полем ввода чата и выберите **Use a skill**.
  </Step>

  <Step title="Выберите навык Admin API">
    В разделе **Replit skills** выберите **Admin API**, чтобы предоставить Agent контекст API и рекомендации по интеграции.
  </Step>

  <Step title="Опишите дашборд">
    Сообщите Agent, что вы хотите отслеживать и как хотите просматривать эти данные. Например, попросите Agent создать дашборд, показывающий использование по рабочему пространству и расходы по проектам.
  </Step>

  <Step title="Безопасно добавьте API-ключ">
    Когда Agent потребуется выполнять API-запросы, добавьте ключ Admin API в Secrets проекта. Не вставляйте ключ в чат и не добавляйте его в коммиты проекта.
  </Step>
</Steps>
