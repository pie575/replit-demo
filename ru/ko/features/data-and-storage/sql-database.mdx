База данных Replit позволяет добавить постоянное хранилище данных в Replit App прямо из Project Editor с помощью полностью управляемой SQL-базы данных.

<Note>
  Быстрее всего начать — попросить **Agent** добавить базу данных в ваше приложение. Agent настроит интеграцию, создаст схему базы данных и обновит приложение, чтобы оно могло сохранять и получать данные.
</Note>

<div id="section">
  ## Возможности
</div>

Инструмент базы данных Replit предоставляет следующие возможности.

* **Инструмент базы данных**: выполняйте запросы с помощью встроенного SQL-инструмента, управляйте схемой базы данных и визуализируйте данные
* **Путешествие во времени**: восстанавливайте базу данных до состояния любого чекпоинта **Agent**. Подробнее см. в разделе [Восстановление данных](/ru/ko/features/data-and-storage/data-recovery)
* **Бесплатное хранилище**: каждая Replit App включает 20 ГБ бесплатного дискового пространства.
* **Переменные окружения**: используйте переменные окружения для безопасного доступа к базе данных из Replit App

<Info>
  До 4 декабря 2025 года базы данных для разработки размещались на Neon и имели несколько существенных отличий.
  Подробнее см. в разделе [Разработка и продакшен](/ru/ko/features/data-and-storage/development-and-production#legacy-development-database).
</Info>

<div id="section-2">
  ## Использование
</div>

<YouTubeEmbed videoId="zbyRuoPNIc8" title="Как работать с базами данных в Replit" />

Доступ к инструментам баз данных Replit можно получить прямо из Project Editor.
В следующих разделах рассказывается, как настраивать базы данных и управлять ими.

<Accordion title="Как открыть инструменты баз данных">
  1. Откройте панель **Tools** и в разделе **Replit Cloud** выберите **Database**.
  2. На стартовой странице отображается список баз данных. Выберите и откройте базу данных, например **Development Database**.
</Accordion>

Инструмент Database организован вокруг списка баз данных. На стартовой странице для каждой базы данных отображаются использование хранилища, а также текущие значения **Billing Period** и **Hours of Compute Used**. После открытия базы данных доступны три вкладки.

* **Overview**: таблицы базы данных
* **My Data**: просмотр и редактирование строк, а также выполнение SQL-запросов
* **Settings**: строка подключения, использование хранилища и сведения о подключении

<div id="section-3">
  ### Добавление базы данных
</div>

Каждое Replit App по умолчанию включает базу данных. Чтобы получить к ней доступ, в Project Editor выберите инструмент <img class="icon-svg" src="/assets/mirror/postgres-c4cb2a1e2de3.svg" alt="Иконка базы данных PostgresSQL" width="24" height="24" data-path="images/icons/postgres.svg" /> **База данных**.

Попросите **Agent** добавить базу данных PostgreSQL в ваше Replit App и укажите, какие данные должно хранить приложение. Agent интегрирует базу данных в приложение, создаст её схему и обновит приложение для работы с базой данных.

<div id="section-4">
  ### Функции безопасности
</div>

При добавлении интеграции с базой данных с помощью **Agent** также добавляется ORM (Object-Relational Mapper) со встроенными
функциями безопасности, которая обеспечивает всё взаимодействие с базой данных.

Этот уровень ORM в сочетании с реализацией Agent передовых практик безопасности защищает приложение от различных атак благодаря следующим функциям.

* **Проверка схемы**: проверяет, что данные соответствуют ожидаемому формату
* **Очистка данных (Sanitization)**: автоматически очищает ввод разработчика, чтобы предотвратить SQL-инъекции

<div id="section-5">
  ## Следующие шаги
</div>

До 4 декабря 2025 года базы данных для разработки размещались в <a href="https://neon.com/" target="_blank">Neon</a>.
Теперь эти базы данных считаются устаревшими (deprecated), а все новые базы данных для разработки размещаются в собственной инфраструктуре Replit.

Проверьте [переменную окружения](#view-connection-credentials-and-usage) `DATABASE_URL`, чтобы узнать, размещается ли ваша база данных для разработки в Neon.

<Info>
  Если `DATABASE_URL` содержит `neon.tech/neondb`, ваша база данных для разработки всё ещё размещается в Neon.
  Если она содержит `helium/heliumdb`, ваша база данных для разработки теперь размещается в Replit.
</Info>

Ниже приведены основные различия между устаревшими базами данных для разработки Neon и новыми базами данных для разработки Replit.

| **Функция**                    | **Replit (текущая)**                                                                                                                                           | **Neon (устаревшая)**                                                                                                                           |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Хостинг**                    | Размещается в собственной инфраструктуре Replit                                                                                                                | Размещается в Neon (сторонний поставщик)                                                                                                        |
| **Платёж**                     | Бесплатно включено для всех Replit App                                                                                                                         | Оплата по мере использования. Подробнее см. [оплату за публикацию и базы данных](/ru/ko/billing/about-usage-based-billing#databases).              |
| **Восстановление**             | Восстановление базы данных до любого чекпоинта с помощью [отката](/ru/ko/features/version-control/checkpoints-and-rollbacks/)                                     | Восстановление на определённый момент времени (PITR) — до любого момента в пределах срока хранения резервных копий.                             |
| **Безопасность подключения**   | Доступна только внутри приложения и никогда не раскрывается внешним пользователям.                                                                             | Используется полная строка подключения — при её раскрытии любой пользователь может получить доступ к базе данных и изменить её.                 |
| **Поведение ремиксов**         | [Ремикс](/ru/ko/features/projects-and-artifacts/remix-an-app) создаёт новую базу данных для разработки с копией данных для изоляции и безопасности                | Во всех копиях ремиксы повторно используют одну базу данных, поэтому изменения в ремиксе могут повлиять на исходное приложение.                 |
| **Создание базы данных**       | Автоматически создаётся для каждого Replit App.                                                                                                                | Требуется явная настройка.                                                                                                                      |
| **Рабочий процесс публикации** | Чтобы выполнить деплой или публикацию, необходимо создать [продакшен-базу данных](/ru/ko/features/data-and-storage/development-and-production) для изоляции сред. | Разработка и продакшен использовали одну базу данных, поэтому непреднамеренные изменения при разработке могли повлиять на продакшен-приложение. |

<Warning>
  Если приложение было форкнуто или ремикшировано, пока оно использовало устаревшую базу данных Neon, опубликованное приложение всё ещё может ссылаться на URL базы данных исходного приложения. После [обновления базы данных](/ru/ko/features/data-and-storage/development-and-production) это общее подключение перестанет работать. О том, как обновить опубликованное приложение, см. [изменение опубликованного приложения, использующего общую базу данных](/ru/ko/features/data-and-storage/shared-database-migration).
</Warning>
