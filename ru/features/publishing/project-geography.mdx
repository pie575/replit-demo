География Project — это регион публикации Project. Вы выбираете её при публикации, и она определяет, где размещаются вычислительные ресурсы и хранилище опубликованного Project.

<Note>
  География Project и [география
  Workspace](/ru/features/collaboration/workspace-geography) могут различаться. География Workspace
  определяет, где размещаются ресурсы разработки для новых Project в Workspace.
</Note>

<div id="what-project-geography-controls">
  ## Что определяет география Project
</div>

По умолчанию Replit рекомендует ближайшую к вам географию. Это помогает снизить задержку для посетителей вашего приложения и соблюсти требования к месту хранения данных.

При выборе географии все опубликованные artifact вашего Project — например, вычислительные ресурсы, база данных и Object Storage — автоматически размещаются в одном регионе. Кроме того, привязанный к географии прокси помогает снизить задержку для посетителей вашего приложения.

<div id="select-a-project-geography">
  ## Выбор географии Project
</div>

Чтобы выбрать географию, отличную от рекомендуемой:

<Steps>
  <Step>Откройте инструмент **Publishing** в своём Replit Project.</Step>
  <Step>Разверните настройки **Advanced**.</Step>
  <Step>Выберите нужную географию в выпадающем списке **Geography**.</Step>

  <Step>
    Нажмите **Publish**, чтобы опубликовать Project в выбранной географии.
  </Step>
</Steps>

<div id="enforce-a-geography-on-published-projects">
  ## Обязательный регион для публикуемых Projects
</div>

Администраторы Enterprise могут задать обязательный регион публикации для всех Projects в организации. Если такая политика включена, разработчики организации публикуют проекты только в заданном регионе. Политика действует лишь на те Projects, которые ещё не публиковались. Projects, уже опубликованные в другом регионе, изменения не затрагивают.

<Note>
  Обязательный регион публикации — функция Enterprise. Подробнее о планах
  Enterprise см. в разделе [Тарифы](https://replit.com/pricing/).
</Note>

<Steps>
  <Step>Перейдите в **Настройки аккаунта**.</Step>
  <Step>Выберите **Дополнительно**.</Step>

  <Step>
    Выберите регион, который должны использовать все Projects при первой
    публикации.
  </Step>
</Steps>

<div id="availability-and-limits">
  ## Доступность и ограничения
</div>

| География            | Выбор региона при публикации Project |
| :------------------- | :----------------------------------- |
| **Северная Америка** | Да                                   |
| **Европа (ЕС)**      | Да                                   |
| **Азия**             | Да                                   |
| **Южная Америка**    | Да                                   |
| **Австралия**        | Да                                   |

<Note>
  Выбор географии Project доступен клиентам с тарифами Core, Pro и Enterprise.
  Пользователи бесплатного тарифа публикуют приложения в Северной Америке по умолчанию.
</Note>

Прежде чем выбрать географию Project, учтите следующие ограничения:

* **После публикации географию изменить нельзя.** Как только вы опубликуете Project в выбранной географии, изменить этот выбор будет невозможно. Перенести опубликованный Project в другую географию нельзя.
* **Регион разработки и регион публикации могут различаться.** Такие ресурсы, как Object Storage, могут быть созданы до публикации и не совпадать с географией вашего Project.
