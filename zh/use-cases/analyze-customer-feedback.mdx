从 Zendesk 获取支持工单，将问题分类并识别趋势，然后
在 Notion 仪表板中更新热门主题、与上周相比的工单量及建议的后续行动。
如果出现新主题或工单量激增，请在 Slack 中通知团队，以便团队能在其被纳入

<div id="before-you-start">
  ## 开始前
</div>

连接 Zendesk、Slack 和 Notion，并告诉 Agent 要包含哪些产品或标签。

<div id="prompt-the-agent">
  ## 向 Agent 发出提示
</div>

<AiPrompt>
  创建一个每周一 9:00 运行的 Routine。从 Zendesk 获取上周的工单。对问题进行分类、识别趋势，并更新 Notion 仪表板，
  包括主要主题、与上周相比的工单量以及建议的后续行动。如果出现新主题或工单量激增，则在 Slack 中通知。
</AiPrompt>

<div id="what-to-expect">
  ## 预期情况
</div>

Agent 会将工单按主题聚类，统计工单量，并简要说明“该怎么做”。每个主题抽查
几张工单，核对标签是否准确。第一周后，调高或调低判定为激增的阈值，以确保 Slack 仍然实用。针对排名靠前的每个主题，在 Zendesk 中打开两张工单并确认
标签是否合适。如果 Slack 发出了提醒，检查工单量是否确实较上周激增。

<div id="make-it-work-for-you">
  ## 让它为你所用
</div>

<AiPrompt>
  将错误、账单问题和功能请求分开。按出现频率对功能请求排序。
</AiPrompt>

<AiPrompt>
  为本周最热门的主题起草客户回复模板。
</AiPrompt>

<div id="troubleshooting">
  ## 故障排除
</div>

* **主题过于模糊或混杂了无关工单：**告诉 Agent 要包含哪些产品或标签，并要求它将错误、账单问题和功能请求分开。每个主题抽样查看几张工单，确认标签是否正确。
* **Slack 因每次细微变更都发送提醒：**提高触发门槛：仅当出现新主题，或工单量按你指定的百分比激增时才提醒。
* **工单来自错误的 workspace：**将 Zendesk 连接到正确的 workspace，并说明要包含哪些产品或标签。
