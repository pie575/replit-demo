Import를 사용하면 기존 코드나 디자인을 Replit Apps로 가져와 Agent와 함께 계속 개발할 수 있습니다.

<div id="supported-sources">
  ## 지원되는 소스
</div>

| 소스            | 제공해야 하는 항목                              | 적합한 용도                              |
| ------------- | --------------------------------------- | ----------------------------------- |
| GitHub        | 저장소 URL 또는 저장소 선택기                      | 공개 및 비공개 저장소 가져오기                   |
| Bitbucket     | 저장소 URL 또는 저장소 선택기                      | Bitbucket에서 호스팅되는 저장소 가져오기          |
| Vercel        | Vercel 프로젝트와 연결된 GitHub 저장소             | Vercel 앱 마이그레이션                     |
| Figma         | frame URL                               | 디자인을 React apps로 전환                 |
| Claude        | Claude에서 보낸 디자인                         | Claude 디자인을 인터랙티브 앱으로 전환            |
| Bolt          | Bolt에서 내보낸 GitHub 저장소                   | Bolt 프로젝트 마이그레이션                    |
| Lovable       | Lovable에서 내보낸 GitHub 저장소                | Lovable 프로젝트 마이그레이션                 |
| Base44        | Base44에서 내보낸 GitHub 저장소                 | Base44 프로젝트 마이그레이션                  |
| ZIP           | `.zip` 파일 업로드                           | 로컬 프로젝트 아카이브 가져오기                   |
| 스프레드시트        | `.xlsx`, `.csv` 파일 또는 Google Sheets URL | 스프레드시트 데이터로 앱 만들기                   |
| 이전 Agent 내보내기 | 이전 Agent App에서 내보낸 GitHub 저장소           | 이전 Agent App 다시 가져오기                |
| 빈 프로젝트        | 없음                                      | Agent 없이 빈 project로 시작하려는 Power 사용자 |

<Note>Replit은 가져오기를 시작하기 전에 호환성을 검증합니다.</Note>

Figma 디자인은 [Figma 디자인을 Replit Design으로 가져오기](/ko/design/import-figma-designs-into-replit-design)를 참조하세요.

Claude에서 보낸 디자인은 [Claude 디자인을 Replit Design으로 가져오기](/ko/design/import-claude-designs-into-replit-design)를 참조하세요.

    </div>

  <Tab title="GitHub">
    ⏰ *예상 소요 시간: 2분*

    GitHub 저장소를 Replit으로 가져와 더 빠르게 실행하고, 테스트하고, 게시하세요.

    **시작하기 전에**

    * GitHub 저장소 URL
    * 저장소 접근 권한(공개 또는 비공개)
    * Replit account

    **옵션 1: 빠른 가져오기**

    빠른 가져오기는 공개 저장소에서 사용할 수 있습니다.

    1. `github.com/` 뒤의 저장소 경로를 복사합니다.
    2. `https://replit.com/github.com/<owner>/<repo>`를 엽니다.
    3. Enter를 눌러 가져오기를 시작합니다.

    *예시*

    * GitHub URL: `https://github.com/exampleUser/my-app`
    * Replit 가져오기 URL: `https://replit.com/github.com/exampleUser/my-app`

    **옵션 2: 안내형 가져오기**

    안내형 가져오기는 공개 저장소와 비공개 저장소를 모두 지원합니다.

    1. [replit.com/import](https://replit.com/import)를 엽니다.
    2. **GitHub**를 선택합니다.
    3. GitHub 계정을 연결합니다.
    4. 저장소를 선택합니다.
    5. **Import**를 선택합니다.

    **가져오는 항목**

    * 저장소 파일 및 폴더
    * dependency 파일
    * 일반적인 실행 및 빌드 config

    **가져오지 않는 항목**

    * 기존 secret 값 및 environment variables 값
    * 기본적으로 Replit에서 실행되지 않는 플랫폼 전용 서비스

    **GitHub 연결 문제 해결**

    `Failed to get repository, please re-authenticate with GitHub`가 표시되거나 저장소 드롭다운에 `No repositories found`가 표시된다면, GitHub 가져오기 flow가 **Account → Connected Services** 페이지의 연결과는 별개의 연결을 사용하기 때문입니다. Connected Services에서만 다시 연결해서는 가져오기 flow 문제가 해결되지 않습니다.

    <Steps>
      <Step title="Git Providers에서 GitHub 다시 연결하기">
        Replit account Settings에서 **Git Providers** 섹션을 열어 GitHub 연결을 해제한 뒤, 같은 화면에서 다시 연결하세요. 그러면 개인 저장소가 가져오기 드롭다운에 표시됩니다.
      </Step>

      <Step title="GitHub Organization에 Replit 앱 승인하기">
        저장소가 GitHub Organization 소유라면 [https://github.com/settings/applications](https://github.com/settings/applications)를 열고 Replit OAuth app을 찾은 뒤, 서드파티 애플리케이션 접근 설정에서 해당 Organization에 대한 접근 권한을 부여하세요. 본인이 조직 소유자가 아니라면 Organization Admin이 이 단계를 대신 수행해야 할 수 있습니다.
      </Step>

      <Step title="가져오기 재시도">
        [replit.com/import](https://replit.com/import)를 열고 저장소 드롭다운에서 선택하는 방법과 저장소 URL을 붙여넣는 방법으로 각각 가져오기를 다시 시도하세요.
      </Step>
    </Steps>
  </Tab>

  <Tab title="ZIP">
    ⏰ *예상 소요 시간: 3분*

    `.zip` 파일을 업로드해 로컬 project를 가져옵니다.

    **시작하기 전에**

    * project가 담긴 200MB 이하의 `.zip` 파일
    * 아카이브 내 명확한 project 루트 폴더
    * Replit account

    zip 파일이 200MB를 초과하면 가져오기 양식에서 거부됩니다. `node_modules`, `.venv`, `build` 같은 dependency 및 빌드 폴더는 제외해 크기를 줄이세요. dependencies는 가져오는 동안 Replit이 다시 설치합니다.

    **단계**

    1. [replit.com/import](https://replit.com/import)을 엽니다.
    2. **ZIP**을 선택합니다.
    3. `.zip` 파일을 업로드합니다.
    4. 요청되는 secret과 environment variables를 추가합니다.
    5. **Import**를 선택합니다.

    **가져오는 항목**

    * Project files 및 디렉터리 구조
    * Dependency 파일
    * Replit용 실행 및 빌드 기본값

    **가져오지 않는 항목**

    * 기존 environment variable 값
    * Custom domains
    * 수동 설정이 필요한 플랫폼별 서비스
    * 기존 database 데이터
    * 기존 서드파티 connector 구성

    * **[Secrets](/ko/core-concepts/project-editor/app-setup/secrets)**: API keys와 environment variables를 추가합니다

<div id="other-sources">
  ## 기타 소스
</div>

<div id="bitbucket">
  ### Bitbucket
</div>

* Bitbucket 저장소 URL을 붙여넣거나, Bitbucket 계정을 연결해 저장소를 검색하세요.
* import 과정에서의 Agent 지원은 GitHub에 호스팅된 project에 비해 제한적일 수 있습니다.

<div id="spreadsheet">
  ### 스프레드시트
</div>

* Excel(`.xlsx`) 또는 CSV 파일을 업로드하거나 공개된 Google Sheets URL을 붙여넣으세요.
* Agent가 스프레드시트 구조를 분석해 여러분의 데이터가 채워진 database를 갖춘 full-stack 앱을 만듭니다.
* 레코드를 조회, 검색, 관리할 수 있는 UI가 포함됩니다.

<div id="previous-agent-export">
  ### 이전에 내보낸 Agent App
</div>

* 이전에 내보낸 Agent App을 GitHub 저장소에서 다시 가져옵니다.
* Replit은 Agent 고유의 구조(코드, database schema, backend 기능)를 그대로 유지합니다.
* database 값과 secret 값은 가져오지 않습니다.

<div id="empty">
  ### Empty
</div>

* 완전히 빈 project로 시작합니다. Agent도, 프레임워크 선택도, 스캐폴딩도 없습니다.
* project 설정을 처음부터 직접 제어하려는 파워 유저에게 적합합니다.

<div id="limitations">
  ## 제한 사항
</div>

* 기존 database 데이터는 마이그레이션되지 않습니다.
* ZIP upload은 200MB로 제한됩니다.
* 일부 복잡하거나 독점적인 dependencies는 수동으로 설정해야 할 수 있습니다.
* 규모가 큰 projects는 처리하는 데 시간이 더 오래 걸릴 수 있습니다.

<div id="best-practices">
  ## 모범 사례
</div>

* import하기 전에 민감한 자격 증명을 제거하세요.
* 소스 project 구조를 깔끔하게 유지하세요.
* import한 후 dependencies와 Run command를 확인하세요.
* publishing하기 전에 핵심 flow를 테스트하세요.

<div id="troubleshooting">
  ## 문제 해결
</div>

가져오기에 실패하면 다음 항목을 먼저 확인하세요.

* **호환성 오류**: 필수 프로젝트 파일과 지원되는 프레임워크를 확인하세요.
* **접근 오류**: 저장소 또는 소스에 대한 권한을 확인하세요.
* **처리 오류**: 프로젝트 구조를 단순화하거나 크기를 줄인 후 다시 시도하세요.

문제가 계속되면 [Replit Community Hub](https://replit.com/community)를 방문하거나 [지원팀에 문의](https://replit.com/support)하세요.
