能够同时处理多项工作，是优秀构建者与卓越构建者之间的重要差异。本页面将教你如何安全地同时构建多个功能，即使你此前从未采用过这种工作方式。

<div id="a-new-way-to-work-with-agent">
  ## 使用 Agent 的新方式
</div>

到目前为止，你可能一直像与坐在身边的伙伴合作一样使用 Agent：你提出需求、观察过程、作出回应。并行构建则是一种不同的协作方式。你将一项功能作为**任务**交给 Agent，它会在后台完成构建，而你可以同时处理其他事情。

你在日常生活中早已习惯这种方式。你不会一直站在洗衣机前等它洗完。启动洗衣机后，你就去做饭。任务也是如此：启动一项任务后，在它运行期间，你可以再启动另一项任务、审查其他内容，或者继续在主 Conversation 中与 Agent 聊天。

这改变了你的角色。你不再是观看单次构建过程的旁观者，而是统筹多个构建的指挥者。

<div id="your-app-is-safe-while-tasks-run">
  ## 任务运行期间，你的应用始终安全
</div>

大家最常问的问题是：*后台任务会不会在我没注意时弄坏我的应用？*

不会。每个任务都在你项目的**副本**上运行。在你审查任务的工作并选择应用之前，你的应用不会发生任何变化。

每个任务也都有自己的 Agent，并继承完整的项目背景，因此你无需重复说明。任务彼此独立：第一个任务一开始运行，你就可以立即启动下一个。

<div id="build-in-parallel">
  ## 并行构建
</div>

<Steps>
  <Step title="打开你的 project 并固定侧边栏">
    从默认的 Build 布局开始：左侧为 Agent chat，右侧为 Preview。展开并固定全局侧边栏，以便始终查看项目的任务控制项和状态更新。
  </Step>

  <Step title="从项目创建 task">
    在侧边栏中展开项目，然后点击项目名称旁的 **+** 按钮。这是启动后台任务最快的方式。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-new-task-sidebar-9a67150bc66c.jpg" width="700" height="578" data-path="images/replitai/build-in-parallel-new-task-sidebar.jpg" />
    </Frame>

    另一种创建任务的方式是将鼠标悬停在项目旁的看板图标上，然后选择 **新建任务**。你还可以从同一菜单中打开看板，并使用底部的 **规划新任务…**。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-board-shortcuts-267b99f4d424.jpg" alt="项目看板快捷菜单，包含看板、打开和新建任务操作" width="720" height="420" data-path="images/replitai/build-in-parallel-board-shortcuts.jpg" />
    </Frame>
  </Step>

  <Step title="描述一个明确的预期成果">
    为任务设定一个明确的结果，然后发送。Agent 会检查项目并提出计划，不会更改主版本。
  </Step>

  <Step title="审查并批准套餐">
    检查范围、实施步骤、完成标准、相关文件和 Agent 模式。仅当计划符合你的意图时，才选择**开始构建**。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-plan-review-2a2e1322ab59.jpg" alt="等待批准“开始构建”的后台任务计划" width="1393" height="868" data-path="images/replitai/build-in-parallel-plan-review.jpg" />
    </Frame>

    选择**开始构建**后，任务会在后台开始执行，同时你仍可继续使用主版本。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-task-active-c991ee7b52ee.jpg" alt="已获批准的任务开始构建，任务 Conversation 位于 Preview 旁边" width="1393" height="868" data-path="images/replitai/build-in-parallel-task-active.jpg" />
    </Frame>
  </Step>

  <Step title="创建并批准剩余任务">
    每次按流程处理一个任务。为相互独立的工作设定不同的成果。描述存在依赖关系的工作时，请说明其所需的功能或项目结构，以便 Agent 能识别前置条件。

    当新任务需要其他任务仍在构建的内容时，Agent 会在其计划中列出前置条件，并将新任务安排在该工作完成并获批准后开始。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-dependent-plan-232d5472df15.jpg" alt="Agent 的计划列出了前置任务，并安排新任务在其完成后开始" width="1393" height="868" data-path="images/replitai/build-in-parallel-dependent-plan.jpg" />
    </Frame>
  </Step>

  <Step title="让 Agent 安排任务">
    打开看板，查看**草稿**、**进行中**、**已就绪**和**已完成**任务。独立任务会在有可用容量时运行。存在依赖关系的任务会显示阻塞原因，并在前置任务应用完成前保持排队状态。
  </Step>

  <Step title="审核并应用已就绪的工作">
    逐一打开已就绪的任务，查看其工作内容和测试结果，并在 Preview 中试用功能。确认符合预期后，选择**应用**。应用前置任务会自动解锁依赖于该任务的其他任务。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-board-ready-71e960b13e34.jpg" alt="任务看板中一项已完成的前置任务处于已就绪状态，并显示“应用”和“审核”操作" width="650" height="270" data-path="images/replitai/build-in-parallel-board-ready.jpg" />
    </Frame>

    应用前置任务后，其依赖任务会自动转为进行中。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-board-unlocked-0ffa3861a9f2.jpg" alt="应用任务一后，任务看板中其依赖任务自动转为进行中" width="1393" height="868" data-path="images/replitai/build-in-parallel-board-unlocked.jpg" />
    </Frame>
  </Step>

  <Step title="确认主版本">
    每次应用更改后，都会返回默认的 Build 视图。使用 Preview 在主版本中试用结果，并在 Agent chat 中查看实现摘要、检查结果、警告信息以及任何仍需关注的事项。

    <Frame>
      <img src="/assets/mirror/build-in-parallel-verify-main-version-62016529b118.jpg" alt="默认 Build 视图，Agent chat 位于主咖啡馆网站 Preview 旁" width="1393" height="868" data-path="images/replitai/build-in-parallel-verify-main-version.jpg" />
    </Frame>
  </Step>
</Steps>

重复执行审查、应用和验证流程，直到所有已批准的任务均处于 **Done** 状态。

  <img src="/assets/mirror/build-in-parallel-board-done-a4ef1c2f1e59.jpg" alt="任务看板中所有四项已批准任务均处于 Done 状态" width="1393" height="868" data-path="images/replitai/build-in-parallel-board-done.jpg" />
</Frame>

<div id="a-worked-example-four-features-at-once">
  ## 示例：同时推进四项功能
</div>

假设你正在搭建一个咖啡馆开业网站，想要进行四项针对性改进：

* 添加无障碍跳转链接和稳定的地标 ID
* 使用这些 ID 的紧凑型分区导航
* 基于无障碍基础优化新闻通讯表单反馈
* 仅修改文档头部的 Open Graph 元数据

关键在于确定各项工作之间的依赖关系。元数据任务只涉及文档头部，与另外三项互不关联，因此可以立即运行。导航和新闻通讯任务都依赖地标任务提供的稳定 ID 和页面结构，因此必须等待该任务完成——只要根据这一结构描述任务，Agent 就会自行识别前置条件。

无需你自行跟踪这一安排：被阻塞的卡片会在面板上标明其前置条件，而不相关的工作则会以进行中状态运行。

<div id="slice-your-work-small">
  ## 将工作拆分成小块
</div>

让并行构建真正发挥作用的 skill，在于将功能拆分为小而独立的 任务。小 任务 完成更快、更易于审查，也更不容易相互干扰。

一条实用原则：**如果你的 任务 描述中包含“和”，就考虑将它拆分。**

* 合适：“添加活动页面”“添加联系表单”
* 太大：“添加活动、报名、电子邮件通知和管理界面”

较大的版本并没有错，但它会迫使一个 Agent 按顺序完成所有工作。四个小 任务 则让 Agent 可以同时执行它们。

考考自己：以下哪些可以并行执行？

1. 添加深色模式切换开关
2. 添加客户评价板块
3. 让客户回复评价
4. 将 App 翻译成法语

<Accordion title="答案">
  任务 1、2 和 4 相互独立，可以同时执行。任务 3 依赖于 任务 2：在有评价之前，没有可供回复的内容。你无需自己发现这一点。Agent 会检测依赖关系，并为你按顺序安排这两个 任务。
</Accordion>

<div id="apply-changes-safely">
  ## 安全应用更改
</div>

每项任务都会在项目的隔离副本中进行。当你应用某项任务时，主版本会随之更改，而其他任务可能仍基于较早的版本。

<Tip>
  应用多个任务的更改时，Agent 会自动处理冲突。每次应用后，请检查生成的 App。如果发现异常，请让 Agent 在任务线程或主 Conversation 中修复。
</Tip>

当两个任务修改同一文件时，选择 **应用** 后，已就绪卡片可能会暂时显示 **正在解决冲突**。请等待 Agent 完成合并并重新检查结果；无需手动解决文件冲突。

<div id="review-like-a-manager">
  ## 像管理者一样审查
</div>

并行构建让你成为管理者，而管理者常犯的错误就是批准未经检查的工作。遵循这个简单的循环，每次处理一个 任务：

<Steps>
  <Step title="测试 任务 的成果">
    打开已完成的 任务 并试用该功能，像用户一样逐项点击体验。
  </Step>

  <Step title="应用">
    满意吗？将更改应用到你的主 App。
  </Step>

  <Step title="检查主版本">
    确认已应用的功能能与 App 中已有的更改正常配合运行。
  </Step>

  <Step title="重复">
    测试并应用下一个已就绪的 任务，直到所有 任务 都已合入。
  </Step>
</Steps>

切勿批量批准。一次应用三个未经审查的功能，意味着一旦出现问题，就有三个可疑对象。

<div id="when-to-stay-sequential">
  ## 何时应按顺序进行
</div>

并行构建是一种工具，而非规则。遇到以下情况时，请留在主 Conversation中，一次处理一件事：

* **两个想法会影响同一界面。**“重新设计主页”和“更改导航”会相互冲突。请按顺序完成。
* **你正在探索。**在设计工作中，一次尝试的结果会改变你接下来想做什么。探索是一场对话，而不是一项待办工作。
* **你无法用一句话描述任务。**如果无法简单说明，就说明你还没准备好将其委派出去。

<div id="work-within-your-limits">
  ## 在能力范围内工作
</div>

你的套餐决定可同时运行多少个后台任务。额外任务会进入队列，并在有空位时启动。有关当前限制，请参阅[任务系统](/zh/core-concepts/agent/task-system#availability)。

你的注意力也是有限的。先从两个任务开始。如果觉得审查起来还算轻松，再尝试三个。你无需监督每一步，但在应用每项结果前，仍需进行测试。
