<div id="verificaes-automticas-de-dependncias">
  ## 自动依赖项检查
</div>

自动依赖项检查会将项目中的包与公开漏洞数据库进行比对。这些检查免费且会自动运行。当新的 Common Vulnerabilities and Exposures (CVE) 条目发布后，Replit 会自动将其与您项目的依赖项进行比对，并在 **Security** 面板中显示匹配结果，无需再次手动检查。

依赖项检查支持 Node.js/npm、Python、Go、Rust、PHP 和 Ruby。

自动修复依赖项功能目前仅适用于 Node.js/npm。

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect 是自动依赖项检查的扩展功能。当 Replit 检测到相关漏洞时，Agent 会准备并测试修复方案，同时向你发送一封包含直达链接的电子邮件。该修复会在 **Security** 面板中保持待处理状态，等待你审阅。应用修复后，请重新发布应用，使生产版本包含该修复。

Auto-Protect 仅覆盖依赖项的 CVE。若要审查应用代码，请使用 [Agent 安全扫描](/zh/pt/features/security/agent-security-scans)。

Auto-Protect 的两项设置默认均为关闭：

<Steps>
  <Step title="启用修复准备">
    Workspace 管理员进入 **Settings** &gt; **Account** &gt;
    **Advanced**，选择 Replit 从哪个最低严重性 (低、中、高或
    严重) 开始准备修复。
  </Step>

  <Step title="启用安全邮件通知">
    进入 **Settings** &gt; **Personalization** &gt; **Email Notifications**，
    选择你希望从哪个最低严重性开始接收
    通知。
  </Step>
</Steps>

对于每个新漏洞，Replit 在每个 Workspace 中最多发送一封电子邮件，汇总所有受影响的项目。选择 **Go to Task** 即可在应用修复前查看 Agent 准备好的修复方案。应用修复后，该漏洞会显示为 **pending republish**，直到你发布新版本为止。

<Note>
  Agent 准备的修复与其他 Agent
  工作一样计费，即使是 Auto-Protect 主动准备的也不例外。
</Note>

<div id="revisar-achados">
  ## 审查发现
</div>

安全检查结果会显示在 **Security** 面板中，并按严重性分组：

| 严重性    | 说明               |
| ------ | ---------------- |
| 严重     | 必须在发布前修复的紧急风险    |
| 高      | 在特定条件下可能被利用的严重问题 |
| 中      | 被利用可能性较低的潜在风险    |
| 低 / 信息 | 次要问题和最佳实践建议      |

在接受、审查或忽略每项发现前，请先仔细审查。将已接受的问题交给 Agent 修复，然后在应用修复后再次运行相关检查。

  ## 开发和部署过程中的安全检查
</div>

<div id="verificao-de-segurana-enquanto-voc-constri">
  ### 构建过程中的安全扫描
</div>

当你使用 Agent 构建应用时，Replit 会自动检查 Agent 修改过的文件，查找常见的不安全代码模式和硬编码的密钥。这是 Agent 工作流中的一次轻量级初步检查，而非对整个代码库的全面审查。检查结果不会以单独报告的形式显示在 **Security** 面板中。

<div id="verificaes-de-publicao">
  ### 部署检查
</div>

Replit 还会在部署前执行安全扫描。**Block publishing of critical vulnerabilities** 设置决定安全扫描发现严重问题时的处理方式：

* **已启用**：部署将被阻止，直至问题得到解决或被忽略。
* **已禁用**：部署将继续，且发现的问题仍可供审核。

Enterprise 组织可以要求所有应用启用此设置。

这些检查是对完整的 [Agent 安全扫描](/zh/pt/features/security/agent-security-scans) 或 [第 3 级检查](/zh/pt/features/security/black-box-pen-tests)的补充，而非替代。
