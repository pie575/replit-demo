## 시뮬레이터나 에뮬레이터에서 미리보기

Replit은 Expo를 사용해 휴대폰에서 모바일 앱을 실행하고 테스트할 수 있게 해줍니다. 또는 Replit이 실제 **iOS Simulator**나 **Android Emulator**를 Preview 패널로 바로 스트리밍합니다. Agent로 만든 변경 사항은 실제 기기에서처럼 시뮬레이터에서도 즉시 반영됩니다(hot-reload).

<Note>
  iOS Simulator와 Android Emulator 프리뷰는 Core, Pro, Enterprise 플랜 빌더가 사용할 수 있습니다. 모바일 앱에만 해당됩니다 — 웹 전용 프로젝트에서는 이 옵션이 표시되지 않습니다.
</Note>

### 시뮬레이터 여는 방법

<Steps>
  <Step title="모바일 프로젝트 열기">
    모바일 아티팩트가 있는 프로젝트를 여세요.
  </Step>

  <Step title="기기 선택하기">
    Preview 패널 상단의 기기 선택기에서 **iOS Simulator** 또는 **Android Emulator**를 선택하세요. 웹 프리뷰 대신 시뮬레이터가 부팅됩니다.
  </Step>

  <Step title="실제 기기처럼 상호작용하기">
    마우스와 키보드로 탭, 스와이프, 입력, 탐색을 하세요. 시뮬레이터를 재시작하지 않고 앱을 다시 로드하려면 툴바에서 **Restart**를 선택하세요.
  </Step>
</Steps>

<Tip>
  시뮬레이터는 클라우드에서 실행되어 브라우저로 스트리밍되므로 다운로드하거나 설정할 것이 없습니다. 프로젝트 파일은 Replit에 그대로 남아 있습니다.
</Tip>

### 브라우저 지원

* **Chrome**, **Safari**, Chromium 기반 브라우저는 완전히 지원됩니다.
* **Firefox**는 지원되지 않습니다. Firefox에서 Replit을 열면 iOS와 Android 옵션이 "Firefox not supported"라는 표시와 함께 비활성화된 상태로 나타납니다. 이는 시뮬레이터를 구동하는 스트리밍 기술의 제약입니다.

### Expo Go를 대신 사용해야 할 때

실제 하드웨어에 의존하는 기능을 테스트해야 하거나, 컴퓨터 앞에 없는 사람과 프리뷰를 공유하고 싶을 때 실제 휴대폰에서 Expo Go를 사용하세요:

* 카메라, 마이크, 햅틱, 기타 네이티브 센서
* 푸시 알림
* 실제 GPS 위치
* 팀원, 테스터, 투자자와 개발 프리뷰 공유

Expo Go에서 앱을 열려면 [replit.com](https://replit.com)에서 프로젝트를 열고, Project Editor의 Preview 패널에서 **Open in Expo Go**를 선택한 다음, 휴대폰의 [Expo Go](https://expo.dev/go) 앱으로 QR 코드를 스캔하세요.

### 전체 화면 시뮬레이터

모바일 아티팩트 카드에서 **More actions** → **Open in iOS Simulator** 또는 **Open in Android Emulator**를 선택하면 더 큰 화면으로 시뮬레이터를 별도 탭에서 열 수 있습니다.

## 왜 모바일 앱을 빌드해야 할까요?

다음이 필요할 때 모바일 앱을 빌드하세요:

* **네이티브 경험**: 빠른 성능, 부드러운 상호작용, 플랫폼 네이티브 UI.
* **기기 기능**: 카메라, 푸시 알림, 위치 등.
* **App Store 배포**: Apple의 App Review 절차를 거친 후 사람들이 발견하고 설치할 수 있는 공유 가능한 목록.

## 주요 기능

* **AI 기반 생성**: 앱을 설명하면 Agent가 작동하는 모바일 앱의 뼈대를 만듭니다.
* **Project Editor 프리뷰**: Replit을 벗어나지 않고 iOS Simulator나 Android Emulator에서 테스트하거나, Expo Go로 휴대폰에서 미리보기.
* **기본적으로 풀스택**: 앱이 성장하면서 서버 라우트, Database, App Storage, Connectors, AI 통합을 추가하세요.
* **가이드가 있는 제출**: 로컬 iOS 툴체인을 관리하지 않고도 TestFlight와 App Store 제출을 위한 빌드를 준비하세요.

## 개발 워크플로

앱에 접근하는 방식에는 세 가지 단계가 있으며, 각각 다른 대상과 기능을 가집니다:

| 단계              | 접근 가능한 대상         | 접근 방법                                  | 적합한 용도             |
| --------------- | ----------------- | -------------------------------------- | ------------------ |
| **Development** | 나 자신              | Project Editor 시뮬레이터 또는 Expo Go용 QR 코드 | 빌드 및 반복 개선         |
| **Deploy**      | Expo Go를 사용하는 테스터 | QR 코드가 있는 공개 URL                       | 개발 프리뷰, 프로토타이핑, 데모 |
| **App Store**   | 누구나               | App Review 후 App Store에서 다운로드          | 프로덕션 릴리스           |

**Development**: 앱을 시작하면 Project Editor의 **iOS Simulator** 또는 **Android Emulator**에서 미리보거나, Preview 패널에서 QR 코드를 스캔해 휴대폰의 Expo Go에서 열 수 있습니다.

**Deploy**: **Publish**를 클릭하면 Replit이 Expo Go용 QR 코드가 포함된 공개 URL을 만들어 줍니다. 이는 App Store 절차를 시작하기 전에 투자자에게 보여주거나, 피드백을 모으거나, 친구들과 테스트하기에 이상적인 개발 프리뷰와 프로토타이핑용입니다.

**App Store**: App Store에 제출하면 Apple이 앱을 검토합니다. 승인 후에는 사람들이 App Store에서 다운로드하고 설치할 수 있습니다. 이를 위해서는 Apple Developer 계정이 필요합니다.

## 게시 개요

iOS 릴리스를 준비할 때 일반적인 흐름은 다음과 같습니다:

* Project Editor에서 게시
* TestFlight에 빌드 제출
* App Store Connect에서 TestFlight 빌드를 App Store로 승격

<Note>
  TestFlight와 App Store에 빌드를 제출하려면 Apple Developer Program 멤버십이 필요합니다.
</Note>

전체 진행 방법은 [모바일 앱 빌드 및 출시](/ko/build/mobile-app) 튜토리얼을 참고하세요.

## 네이티브 모바일 앱을 빌드할 수 있는 곳

Replit 환경은 로컬 머신이 아니라 클라우드에서 실행됩니다. 네이티브 모바일 앱을 빌드하려면 [replit.com](https://replit.com)의 Project Editor를 사용하세요. Agent 스캐폴딩, Expo Go 프리뷰, 시뮬레이터/에뮬레이터 테스트, TestFlight 빌드, App Store 제출로 이어지는 모바일 앱 워크플로는 Project Editor에서 실행됩니다.

네이티브 모바일 앱 작업은 지원되는 경우 [Replit Android 앱](/ko/features/platforms/mobile-app)에서도 이용할 수 있습니다. Replit iOS 앱을 사용하고 있다면, [replit.com](https://replit.com)에서 프로젝트를 열어 네이티브 모바일 앱을 만들거나, 미리보거나, 빌드하거나, 제출하세요.

## 기술 작동 방식

모바일 앱은 함께 작동하는 여러 기술 스택으로 빌드됩니다. 이 섹션에서는 앱을 구동하는 요소와 각 부분이 어떻게 맞물리는지 설명합니다.

### 기술 스택

<MobileStackDiagram />

* **React Native**는 하나의 코드베이스를 작성해 iOS, Android, 웹으로 컴파일할 수 있게 해주는 오픈소스 프레임워크입니다. 웹뷰가 아니라 플랫폼 네이티브 UI 컴포넌트를 렌더링합니다.
* **Expo**는 빌드 처리, 네이티브 모듈 관리, Expo Go 같은 프리뷰 도구 제공을 통해 React Native 개발을 단순화합니다.
* **Expo Go**는 휴대폰에 설치하는 무료 앱입니다. 개발 프리뷰를 실행하므로 완전한 네이티브 바이너리를 빌드하지 않고도 실제 기기에서 테스트할 수 있습니다.

앱을 실행하면 Metro 번들러가 코드를 컴파일해 기기로 전송합니다. 첫 빌드는 캐시가 없어 더 오래 걸립니다. 이후 빌드는 더 빠릅니다.

### 아키텍처: 서버와 클라이언트

모바일 앱을 프리뷰나 배포용으로 준비할 때는 두 가지를 다루게 됩니다:

1. Replit에서 클라우드로 실행되는 **서버**. 데이터베이스, API 라우트, AI 통합, 백엔드 로직을 처리합니다.
2. 사람의 휴대폰에서 실행되는 **클라이언트 앱**. 개발 중에는 Expo Go에서 미리보고, 검토 후에는 앱스토어를 통해 배포되는 네이티브 앱입니다.

<MobileArchitectureDiagram />

이러한 분리는 유연성을 제공합니다. 복잡한 로직은 서버에서 실행할 수 있고(Replit의 Database, Object Storage, Connectors에 접근 가능), 클라이언트는 가볍게 유지할 수 있습니다. 빌드하는 동안 무엇을 휴대폰에서 처리하고 무엇을 클라우드에서 처리해야 할지 고민해 보세요.

## 고려 사항

* **게시 요구 사항**: Apple이 TestFlight와 App Store의 요구 사항을 정하며, 배포 전 iOS 앱을 검토합니다.
* **Android 게시**: iOS와 Android를 위한 크로스 플랫폼 앱을 빌드할 수 있습니다. Google Play에 게시하는 가이드 경험은 아직 지원되지 않지만 수동으로 진행할 수 있습니다.
* **네이티브 변경**: 앱 아이콘이나 권한 같은 변경 사항은 보통 새로운 스토어 빌드가 필요합니다.

## FAQ

<AccordionGroup>
  <Accordion title="Expo란 무엇인가요?">
    Expo는 Agent가 Replit에서 모바일 앱을 빌드할 때 사용하는 도구입니다. React Native로 크로스 플랫폼 네이티브 앱을 빌드, 실행, 배포하기 위한 오픈소스 플랫폼이자 툴체인입니다. 자세한 내용은 [https://expo.dev](https://expo.dev) 에서 확인하세요.
  </Accordion>

  <Accordion title="React Native란 무엇인가요?">
    React Native는 React와 JavaScript 또는 TypeScript를 사용해 네이티브 iOS 및 Android 앱을 빌드하기 위한 Meta의 오픈소스 프레임워크입니다. 플랫폼 네이티브 UI 컴포넌트를 렌더링하므로(웹뷰가 아님), 앱이 진짜 네이티브처럼 보이고 느껴집니다.
  </Accordion>

  <Accordion title="Expo Go란 무엇인가요?">
    Expo Go는 App Store나 Google Play에서 휴대폰에 설치하는 무료 앱입니다. 완전한 네이티브 바이너리를 빌드하지 않고도 개발 중인 모바일 앱을 미리볼 수 있게 해줍니다. Project Editor에서 QR 코드를 스캔하면 Expo Go가 앱 코드를 다운로드하고 실행합니다.
  </Accordion>

  <Accordion title="Expo Go와 개발 빌드(dev build)의 차이는 무엇인가요?">
    **Expo Go**는 코드를 실행하는 미리 빌드된 앱입니다. 설정이 빠르지만 Expo SDK에 포함된 모듈만 지원합니다.

    **개발 빌드**는 어떤 네이티브 모듈도 포함할 수 있는 커스텀 네이티브 바이너리입니다. 더 많은 설정(EAS Build 또는 로컬 Xcode/Android Studio)이 필요하지만 더 큰 유연성을 제공합니다.

    Replit은 개발 프리뷰에 Expo Go를 사용합니다. Expo Go에서 지원되지 않는 네이티브 모듈이 필요하다면 [Expo의 문서](https://docs.expo.dev/develop/development-builds/introduction/)에서 개발 빌드를 살펴봐야 할 수 있습니다.
  </Accordion>

  <Accordion title="이건 모바일 반응형 웹 앱과 어떻게 다른가요?">
    모바일 반응형 웹 앱은 브라우저에서 레이아웃을 조정하는 웹사이트입니다. React Native 앱은 기기에 설치되는 네이티브 애플리케이션으로, 플랫폼 API(카메라, 햅틱, 푸시 알림)를 사용하고, 하드웨어와 오프라인 기능에 더 잘 접근할 수 있으며, 앱스토어를 통해 배포됩니다. 반응형 웹은 도달 범위와 설치 없는 접근성 측면에서 훌륭하고, 네이티브는 기기 기능, 성능, App Store 배포가 필요할 때 최선입니다.
  </Accordion>

  <Accordion title="Mac이나 Xcode가 필요한가요?">
    아닙니다. Replit과 Expo가 클라우드에서 빌드 과정을 대신 관리해 줍니다.
  </Accordion>

  <Accordion title="Apple Developer 계정 없이 미리볼 수 있나요?">
    네. Project Editor의 iOS Simulator나 휴대폰의 Expo Go에서 미리볼 수 있습니다. TestFlight나 App Store에 제출할 준비가 될 때만 Apple Developer 계정이 필요합니다.
  </Accordion>

  <Accordion title="Android도 지원되나요?">
    네. 동일한 코드베이스에서 iOS와 Android를 위한 크로스 플랫폼 앱을 빌드할 수 있습니다. Project Editor의 Android Emulator나 Expo Go가 설치된 Android 기기에서 미리보세요. Google Play 게시는 수동으로 할 수 있습니다.
  </Accordion>

  <Accordion title="서버와 데이터베이스는 어떻게 되나요?">
    별도의 인프라 없이 Replit에 내장된 PostgreSQL, Object Storage, Connectors, AI 통합을 사용하세요. 서버는 Replit에서 실행되고 모바일 앱이 이에 연결됩니다.
  </Accordion>

  <Accordion title="Project Editor 시뮬레이터와 실제 휴대폰 중 어디서 테스트해야 하나요?">
    상황에 따라 둘 다 사용하세요. Project Editor의 **iOS Simulator**와 **Android Emulator**는 앱의 네이티브 버전을 보여주며 레이아웃, 탐색, 네이티브 컴포넌트, 플랫폼 스타일링 등 대부분의 일상적인 테스트를 다룹니다. 카메라, 햅틱, 푸시 알림, GPS 위치처럼 실제 하드웨어에 의존하는 기능을 테스트할 때는 **Expo Go**로 실제 휴대폰으로 전환하세요.
  </Accordion>
