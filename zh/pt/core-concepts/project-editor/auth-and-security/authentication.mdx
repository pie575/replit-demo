Replit Auth 让你能在应用中为用户打造个性化体验。有了用户账户，你就可以保存用户偏好、创建个性化仪表板、构建社交功能、控制付费内容的访问权限、追踪用户活动 —— 正是这些功能让应用更具吸引力和价值。

Replit Auth 使用 Replit 自有的登录系统 —— 当有人登录你的应用时，他们创建或使用的是 **Replit 账户**。登录页面带有 Replit 品牌标识，登录流程也与 replit.com 全站保持一致。

<Note>
  **Replit Auth 与 Clerk Auth 的区别** —— Replit 提供两种身份验证方案。**Replit Auth** (即本页介绍的方案) 使用 Replit 自有的登录系统，因此你的应用用户会使用 Replit 账户登录，并看到带有 Replit 品牌标识的登录页面。**[Clerk Auth](/zh/pt/core-concepts/project-editor/auth-and-security/clerk-auth)** 则为你的应用提供基于 Clerk 的专属身份验证租户，品牌标识可完全自定义，用户账户也独立于 Replit。如果你需要在登录体验中使用自己的品牌，或希望用户账户不与 Replit 绑定，请选择 Clerk Auth。
</Note>

不必花费数月从零构建身份验证，只需在 Agent 中输入一句 prompt，Replit Auth 就能带来企业级能力。它构建在财富 500 强企业同样在用的基础设施之上 —— Firebase、Google Cloud Identity Platform、reCAPTCHA、Stytch 和 Clearout —— 让你开箱即得专业级安全性、欺诈防护和全球化扩展能力。

<div id="por-que-usar-o-replit-auth">
  ## 为什么使用 Replit Auth
</div>

身份验证是一道颇具挑战的难题，甚至有整家公司专门致力于解决它。你的 App 的核心价值多半不在于身份验证，而在于你正在构建的那个独特创意或解决方案。

Replit Auth 提供：

* **零配置** —— 在 Agent 中用一句 prompt 即可添加身份验证
* **打通 Replit 账户** —— 用户直接使用已有的 Replit 账户登录，无需单独注册
* **内置安全防护** —— 基于 Replit 的基础设施，可抵御常见攻击
* **用户管理** —— 通过 Auth 面板轻松管理用户
* **数据库集成** —— 自动在你的数据库中写入用户记录
* **可自定义的登录页面** —— 为你的 App 定制登录体验 (带 Replit 品牌标识)
* **密码重置** —— Replit 代你发送密码重置邮件，无需自行配置邮件投递服务商
* **推荐计划** —— 通过 Replit Auth 注册的用户会计入你待处理的 Replit 推荐名单
* **开发中的 App 与已部署 App** —— Replit Auth 在开发环境 (replit.dev) 和已部署 App (replit.app 及自定义域名) 中均可无缝运行

<div id="infraestrutura-de-nvel-enterprise">
  ## 企业级基础设施
</div>

Replit Auth 不只是简单的用户管理——它是一套构建在企业级基础设施之上的全托管身份验证解决方案。这一强大组合让你的 App 拥有与《财富》500 强企业同等的身份验证能力：

* **Firebase 与 Google Cloud Identity Platform** - 企业级 SLA，依托 Google 久经考验的身份验证基础设施
* **高级安全扫描** - 集成 reCAPTCHA，自动防范机器人与恶意攻击者
* **欺诈防范** - 基于 Clearout 的邮箱验证与校验，杜绝虚假账户
* **多因素身份验证** - 由 Stytch 企业级身份验证平台支持的安全登录选项
* **全球规模** - 具备自动扩缩容与高可靠性，可支撑数百万用户

有了这一企业级基础，你可以专心打造 App 的独特功能，因为你的身份验证建立在守护着数十亿美元规模企业的同一套基础设施之上。无需耗费数月时间集成各种服务，只需在 Agent 中输入一个 prompt，即可获得上述全部能力。

<div id="primeiros-passos-com-o-replit-auth">
  ## Replit Auth 入门
</div>

实现 Replit Auth 的唯一方式是使用 Agent。只需在 prompt 中提出使用 Replit Auth 的要求即可：

```
帮我创建一个 App，功能是[你的 App 想法]，并且需要包含 Replit Auth。
```

Agent 会为你配置身份验证所需的全部代码和设置。由于 Agent 已代你处理了所有复杂环节，因此不支持手动实现。

<div id="personalizando-a-pgina-de-login">
  ## 自定义登录页面
</div>

<Frame>
  <img src="/assets/mirror/auth-login-1ee0460c3780.jpg" alt="身份验证配置" width="1920" height="1080" data-path="images/workspace/auth/auth-login.jpg" />
</Frame>

你可以自定义登录页面，使其与应用的品牌视觉保持一致：

1. 在 Project Editor 中进入 Auth 面板
2. 点击 **Configure**
3. 自定义以下元素：
   * 应用名称
   * 应用图标
   * 登录方式 (Google、GitHub、X、Apple、Email)

更改会立即显示在应用的登录页面上。

<div id="consideraes-de-segurana">
  ## 安全注意事项
</div>

Replit Auth 依托 Replit 的基础设施，内置了针对常见安全威胁的防护。不过，你仍应遵循以下最佳实践：

* 执行敏感操作前，务必在服务器端校验用户的登录状态
* 切勿将密码等敏感信息硬编码在代码中
* 使用环境变量保存 API 密钥或 Secrets
* 为用户数据设置适当的访问控制

有关安全的更多信息，请参阅：

* [Replit 内置安全功能](/zh/tutorials/vibe-code-securely)
* [vibe coding 安全检查清单](/zh/tutorials/vibe-code-security-checklist)
* [Secrets 管理](/zh/pt/core-concepts/project-editor/app-setup/secrets)

  ## 推荐

为了鼓励大家开发能向他人推广 Replit 的应用，任何通过 Replit Auth 注册的用户都会自动计入你待生效的 Replit 推荐名单。如果他们之后升级到 Replit Core，你将根据推荐计划的现行条款获得相应的推荐奖励。

<div id="soluo-de-problemas">
  ## 故障排查
</div>

<div id="problemas-comuns">
  ### 常见问题
</div>

1. **登录后无法识别用户**
   * 如果遇到问题，可以请 [Replit Agent](/zh/pt/core-concepts/agent) 帮你调试身份验证的实现。

2. **自定义图标不显示**
   * 请确认图标 URL 可正常访问，且格式受支持 (PNG 或 JPG) 。

3. **新绑定的自定义域名无法使用**
   * 重新发布应用以更新域名列表 (REPLIT&#95;DOMAINS 环境变量) 。
