Панель Git в Replit предоставляет визуальный интерфейс для работы с Git, избавляя от необходимости использовать команды Git в командной строке. Эта функция делает контроль версий доступным для начинающих и при этом остаётся мощным инструментом для опытных разработчиков.

<div id="features">
  ## Возможности
</div>

Панель Git предоставляет полный набор возможностей для контроля версий прямо в Project Editor, а удобный интерфейс упрощает сложные операции Git.

* **Управление репозиториями**: Инициализируйте, подключайте и управляйте Git-репозиториями с интеграцией GitHub
* **Отслеживание коммитов**: Добавляйте изменения в индекс, создавайте коммиты и просматривайте изменения во всех файлах
* **Операции с ветками**: Визуально создавайте ветки, переключайтесь между ними и объединяйте их
* **Разрешение конфликтов**: Выявляйте и разрешайте конфликты слияния с помощью визуальных инструментов
* **Интеграция с Shell**: Синхронизация между командами Git, запущенными в Shell, и панелью Git

  ## Использование

<div id="repository-setup">
  ### Настройка репозитория
</div>

<Accordion title="Как открыть панель Git">
  1. Перейдите в раздел Tools вашего Replit App
  2. Нажмите **+**, чтобы добавить новые инструменты
  3. Выберите **Git** из списка доступных инструментов
</Accordion>

Панель Git позволяет настроить и подключить репозиторий:

* **Инициализировать репозиторий**: создайте новый Git-репозиторий для вашего Replit App
* **Подключиться к Git-провайдеру**: свяжите репозиторий с поддерживаемым облачным или локально развёрнутым Git-провайдером для резервного копирования и совместной работы
* **Настроить remote**: настройте подключение к удалённому репозиторию и управляйте им

<Note>
  **Поддержка локально развёрнутого Git**: Replit поддерживает GitHub Enterprise Server, GitLab Self-Managed и Bitbucket Data Center в тарифе Enterprise. [Свяжитесь с отделом продаж Replit](https://replit.com/enterprise), чтобы получить рекомендации по подключению, настройке Git-провайдера и устранению неполадок с подключением. Также можно [настроить remote с помощью команд Git в Shell](#using-git-commands-in-shell).
</Note>

<div id="change-management">
  ### Управление изменениями
</div>

<Accordion title="Как просматривать изменения">
  1. Внесите изменения в любые файлы своего Replit App
  2. Откройте панель Git в разделе Tools
  3. Просмотрите изменения в разделе **Review Changes**
</Accordion>

Панель Git предоставляет инструменты для управления изменениями в коде:

* **Просмотр изменений**: Просматривайте изменённые файлы с выделенными добавлениями и удалениями
* **Добавить в индекс файлы**: Выберите файлы, которые нужно включить в следующий коммит
* **Создать коммит изменений**: Сохраняйте изменения с понятными сообщениями
* **Отправка обновлений**: Отправляйте коммиты в удалённый репозиторий одним нажатием

<div id="branch-management">
  ### Управление ветками
</div>

<Accordion title="Как управлять ветками">
  1. Откройте панель Git в разделе Tools
  2. Нажмите раскрывающееся меню рядом с названием ветки
  3. Создайте новую ветку или выберите существующую
</Accordion>

Панель Git упрощает работу с несколькими версиями кода:

* **Создание веток**: Создавайте новые ветки для изолированной разработки функций
* **Переключение веток**: Переходите между разными версиями кода
* **Публикация веток**: Публикуйте ветки у своего Git-провайдера
* **Получение изменений**: Синхронизируйтесь с удалёнными изменениями от соавторов

<div id="merge-conflict-resolution">
  ### Разрешение конфликтов при слиянии
</div>

<Accordion title="Как разрешить конфликты при слиянии">
  1. Попробуйте получить изменения при наличии конфликтов
  2. На панели Git будут выделены конфликтующие файлы
  3. Откройте каждый конфликтующий файл, чтобы просмотреть и разрешить конфликты
  4. Сохраните файлы после разрешения конфликтов
  5. Завершите слияние, выбрав **Pull**
</Accordion>

Если код из разных источников конфликтует, панель Git помогает:

* **Выявлять конфликты**: точно определять, в каких файлах есть конфликты
* **Сравнивать различия**: просматривать обе версии конфликтующего кода
* **Разрешать конфликты**: выбирать, какой код сохранить, или вручную редактировать конфликтующие участки
* **Завершать слияние**: завершать процесс слияния после разрешения конфликтов

После разрешения конфликта в файле удалите маркеры конфликта, удалив строки, начинающиеся с символов конфликта, и сохраните файл.

<div id="using-git-commands-in-shell">
  ### Использование команд Git в Shell
</div>

<Accordion title="Как открыть Shell">
  1. Выберите **All tools** на левой панели инструментов
  2. Выберите **Shell** из списка доступных инструментов
</Accordion>

<Tip>
  Панель Git предлагает удобный интерфейс, но опытные пользователи могут выполнять более сложные операции с помощью стандартных команд Git в Shell. Изменения, внесённые любым из этих способов, будут отображаться в обоих местах.
</Tip>

Если вы предпочитаете работать с Git через командную строку:

* **Синхронизация команд**: Все команды Git, выполненные в Shell, автоматически синхронизируются с панелью Git
* **Полная функциональность Git**: Используйте расширенные возможности Git, недоступные на панели Git
* **Удобное переключение**: При необходимости переключайтесь между командами Shell и панелью Git

<Info>
  **Поддержка GitHub CLI и GitLab CLI**: Помимо стандартных команд Git, в Shell можно использовать [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) и [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) для управления внешними Git-репозиториями и подключения к ним. Эти инструменты расширяют возможности работы с репозиториями GitHub и GitLab, включая pull request, issues и другие функции, специфичные для этих платформ.
</Info>

<div id="repository-operations">
  #### Операции с репозиторием
</div>

* **Клонировать репозиторий**: `git clone <url-to-repository>`
* **Инициализировать репозиторий**: `git init`
* **Добавить удалённый репозиторий**: `git remote add origin <url-to-repository>`

<div id="making-changes">
  #### Внесение изменений
</div>

* **Проверка статуса**: `git status` (показывает изменённые, добавленные и удалённые файлы)
* **Добавление файлов в индекс**: `git add <filename>` или `git add .` (для всех файлов)
* **Создание коммита**: `git commit -m "your commit message"`
* **Отправка изменений**: `git push origin <branch-name>`
* **Получение изменений**: `git pull origin <branch-name>`

<div id="authentication">
  #### Аутентификация
</div>

При работе с приватными репозиториями необходимо пройти аутентификацию:

* Для репозиториев GitHub.com используйте персональный токен доступа вместо пароля
* Чтобы не вводить учетные данные повторно, сохраните их в Replit Secrets:
  1. Создайте новый секрет с ключом `GIT_URL`
  2. Задайте значение `https://<username>:<token>@<git-host>/<owner>/<repository>`
  3. Используйте `git push $GIT_URL`, чтобы отправлять изменения без ввода учетных данных

<Note>
  При использовании секретов с учетными данными любой пользователь, имеющий доступ к вашему Replit App, потенциально может получить доступ к вашим учетным данным Git. Для конфиденциальных репозиториев рекомендуется каждый раз вводить учетные данные вручную.
</Note>
