Replit 数据库采用完全托管的 SQL 数据库，你可以直接在项目编辑器中为 Replit App 添加持久化数据存储。

<Note>
  最简单的上手方式是让 **Agent** 为你的应用添加数据库。Agent 会配置集成、创建数据库架构，并更新应用代码以实现数据的存储与读取。
</Note>

<div id="section">
  ## 功能
</div>

Replit 数据库工具提供以下功能：

* **数据库工具**：使用内置 SQL 工具执行查询、管理数据库架构并可视化数据
* **时间旅行**：将数据库恢复到任意 **Agent** 检查点。详情请参阅[数据恢复](/zh/ja/features/data-and-storage/data-recovery)
* **免费存储**：每个 Replit App 均包含 20GB 免费存储空间
* **环境变量**：在 Replit App 中通过环境变量安全访问数据库

<Info>
  在 2025 年 12 月 4 日之前，开发数据库托管在 Neon 上，存在若干重要差异。
  详情请参阅[开发环境与生产环境](/zh/ja/features/data-and-storage/development-and-production#legacy-development-database)。
</Info>

<div id="section-2">
  ## 使用方法
</div>

<YouTubeEmbed videoId="zbyRuoPNIc8" title="如何在 Replit 中使用数据库" />

你可以直接在项目编辑器中打开 Replit 数据库工具。
以下各节介绍如何设置和管理数据库。

<Accordion title="如何打开数据库工具">
  1. 打开 **Tools** 面板，选择 **Replit Cloud** 下的 **Database**。
  2. 首页视图中会列出所有数据库。选择 **Development Database** 等条目即可打开。
</Accordion>

数据库工具围绕数据库列表进行组织。首页视图中会显示各个数据库的存储用量，以及当前的 **Billing Period** 和 **Hours of Compute Used**。打开某个数据库后，会看到三个选项卡：

* **Overview**：数据库中的表。
* **My Data**：浏览和编辑数据行，或运行 SQL 查询。
* **Settings**：连接字符串、存储用量和连接详情。

<div id="section-3">
  ### 添加数据库
</div>

每个 Replit App 默认都自带一个数据库。在项目编辑器中选择 <img class="icon-svg" src="/assets/mirror/postgres-c4cb2a1e2de3.svg" alt="PostgreSQL 数据库图标" width="24" height="24" data-path="images/icons/postgres.svg" /> **数据库**工具即可访问。

你可以让 **Agent** 为你的 Replit App 添加 PostgreSQL 数据库，并说明应用需要存储哪些数据，从而完成数据库集成。Agent 会创建数据库架构，并更新应用代码以与数据库通信。

<div id="section-4">
  ### 安全功能
</div>

使用 **Agent** 添加数据库集成时，会一并添加对象关系映射器 (ORM) ，由它通过内置的安全机制处理数据库通信。

借助这一 ORM 层，以及 Agent 对安全最佳实践的落实，你的应用可通过以下功能抵御攻击：

* **模式校验**：验证数据是否符合预期格式
* **数据清洗**：自动清理构建者输入的内容，防止 SQL 注入攻击

<div id="section-5">
  ## 后续步骤
</div>

在 2025 年 12 月 4 日之前，开发数据库托管在 <a href="https://neon.com/" target="_blank">Neon</a> 上。
该数据库已停用，所有新的开发数据库均托管在 Replit 自有的数据库基础设施上。

你可以查看 `DATABASE_URL` [环境变量](#view-connection-credentials-and-usage)，确认开发数据库是否托管在 Neon 上。

<Info>
  如果 `DATABASE_URL` 中包含 `neon.tech/neondb`，说明开发数据库仍托管在 Neon 上。
  如果包含 `helium/heliumdb`，则说明开发数据库已托管在 Replit 上。
</Info>

以下是旧版 Neon 开发数据库与新版 Replit 开发数据库的主要区别：

| **功能**    | **Replit (当前)&#x20;**&#x20;                                                                  | **Neon (旧版)&#x20;**&#x20;                                                    |
| --------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **托管**    | 托管在 Replit 自有基础设施上                                                                      | 托管在 Neon (第三方服务商) 上                                                     |
| **计费**    | 所有 Replit App 免费包含                                                                      | 按用量计费。详情请参阅[发布与数据库计费](/zh/ja/billing/about-usage-based-billing#databases)。 |
| **恢复功能**  | 可使用[回滚功能](/zh/ja/features/version-control/checkpoints-and-rollbacks/)将数据库恢复到任意检查点  | 时间点恢复 (PITR) —— 可恢复到备份保留期内的任意时间点。                                       |
| **连接安全**  | 仅可从应用内部访问，不会对外暴露。                                                                       | 使用完整连接字符串 —— 一旦泄露，任何人都可以访问并修改数据库。                                       |
| **重混行为**  | [重混](/zh/ja/features/projects-and-artifacts/remix-an-app)时会创建一个新的开发数据库并复制数据，以实现隔离与安全。      | 所有副本重混后共用同一个数据库，因此重混中的改动可能影响原应用。                                        |
| **数据库创建** | 为每个 Replit App 自动创建。                                                                    | 需要手动显式设置。                                                               |
| **发布工作流** | 部署或发布时需要创建[生产数据库](/zh/ja/features/data-and-storage/development-and-production)，以实现环境之间的隔离。 | 开发与生产共用同一个数据库，无意的开发改动可能影响生产应用。                                          |

<Warning>
  如果你的应用是在使用旧版 Neon 数据库期间被复刻或重混的，那么发布后的应用可能仍在引用原应用的数据库 URL。完成[数据库升级](/zh/ja/features/data-and-storage/development-and-production)后，这种共享连接将无法继续使用。关于如何更新已发布的应用，请参阅[修复使用共享数据库的已发布应用](/zh/ja/features/data-and-storage/shared-database-migration)。
</Warning>
