title: "Ports"
description: "Découvrez comment configurer et gérer les ports réseau dans vos applications Replit."
---

Replit exécute vos projets dans un environnement cloud : les ports s&#39;y comportent donc différemment de ce que vous connaissez sur votre ordinateur local. (Si vous avez besoin d&#39;une explication de base sur ce qu&#39;est un port TCP, [commencez ici](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

Sur votre ordinateur, il n&#39;existe qu&#39;une seule couche de gestion des ports : un programme définit le port sur lequel il écoute et, lorsque du trafic provenant d&#39;Internet atteint ce port, il est acheminé vers le processus approprié.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="Ordinateur" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

La partie `0.0.0.0` correspond à l&#39;adresse, ou hôte. Lorsqu&#39;un processus écoute sur `0.0.0.0`, cela signifie qu&#39;il écoute sur toutes les interfaces réseau. Autrement dit, si un autre ordinateur (sur Internet) envoie une requête à l&#39;adresse IP de votre ordinateur, il la verra. Écouter sur 0.0.0.0 signifie donc que ces processus sont accessibles depuis l&#39;Internet public (si votre ordinateur est connecté).

La plupart des frameworks de programmation n&#39;écoutent &#95;pas&#95; sur `0.0.0.0` pendant le développement, car, pour des raisons de confidentialité et de sécurité, vous ne souhaitez pas forcément rendre votre travail public tant qu&#39;il est en cours. Ils écoutent plutôt sur une autre adresse (`127.0.0.1`, également appelée `localhost`) : seul cet ordinateur peut alors envoyer des requêtes vers ce port.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Les ports localhost ne sont visibles que depuis l'ordinateur qui les héberge." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

Sur Replit, pour rendre un processus en cours d&#39;exécution accessible depuis la vue Web ou depuis des requêtes externes, vous devez définir un **port externe**. En effet, le « port interne » qu&#39;un processus utilise habituellement n&#39;est visible que depuis l&#39;intérieur de l&#39;environnement cloud isolé fourni par Replit. Ce port interne doit être relié à un port accessible de l&#39;extérieur afin d&#39;acheminer le bon trafic vers votre programme. Même si votre processus écoute sur un port pouvant être exposé publiquement, comme 0.0.0.0, il doit être lié à un port externe.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Les ports externes transfèrent le trafic vers les ports internes, sur lesquels votre programme écoute." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Pour ce faire, Replit lie un port externe à un port interne donné. Par exemple, dans le schéma ci-dessus, le port externe `:80` est lié au port interne `:3000`. Autrement dit, le trafic reçu par votre application Replit sur le port 80 est dirigé vers le port interne 3000.

Cette configuration est enregistrée dans la section [[ports]] du fichier de configuration .replit.

Par défaut, Replit lie le premier port ouvert au port externe par défaut 80. Le processus concerné est ainsi accessible via un domaine sans numéro de port (par exemple, customdomain.com/ au lieu de customdomain.com:3000/). Les ports internes ouverts par la suite sont liés aux autres ports externes disponibles (voir la liste complète ci-dessous).

<div id="section-2">
  ## Port par défaut
</div>

Le port 80 étant le « port par défaut » du trafic http, tout trafic http envoyé au domaine racine est automatiquement acheminé vers le port 80. C&#39;est pourquoi les URL utilisant le port 80 n&#39;affichent pas de numéro de port. Les ports autres que `:80` apparaissent, eux, dans le chemin du domaine (par exemple : customdomain.com:4200/). (Comme Replit fournit TLS par défaut, il s&#39;agit techniquement du port 443, le port par défaut de https. En pratique, vous pouvez les considérer comme interchangeables.)

<div id="section-4">
  ## Publication
</div>

Les déploiements Autoscale et Reserved VM ne prennent en charge l&#39;exposition que d&#39;un seul port externe, et le port interne correspondant ne peut pas utiliser `localhost`. Exposer plusieurs ports, ou exposer un port unique sur localhost, entraînera l&#39;échec de l&#39;application publiée. Pour garantir le bon fonctionnement de votre déploiement Autoscale, le plus simple consiste à supprimer de votre configuration toutes les entrées `externalPort`, à l&#39;exception de celle du service avec lequel vous souhaitez interagir depuis Internet.

<div id="section-5">
  ## Débogage
</div>

Une cause fréquente de fonctionnement inattendu : la configuration des ports semble correcte, mais le programme écoute en réalité un autre port. Par exemple, si la configuration est la suivante :

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Le trafic Internet arrivant sur le port 80 est redirigé vers le port interne 3000. Toutefois, si votre programme écoute en réalité sur un autre port que le 3000 (8080, par exemple), le trafic semblera ne pas passer. Cela peut arriver si vous avez changé le port dans votre code sans modifier le port correspondant dans la configuration, ou si vous avez copié-collé la configuration d&#39;un projet à un autre.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Les programmes peuvent changer le port sur lequel ils écoutent." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

Chaque framework a son propre port par défaut. Par exemple, Flask utilise le port 5000, react le port 3000 et laravel le port 8000. Vérifiez que le bon port est configuré !

<div id="section-6">
  ## Configuration
</div>

Lorsqu&#39;un port est ouvert dans une app Replit, Replit le lie automatiquement à un port externe disponible et enregistre cette liaison dans le fichier de configuration .replit.

Ce n&#39;est toutefois pas le cas par défaut pour les ports internes ouverts sur localhost. En effet, les services qui s&#39;exécutent sur localhost partent généralement du principe qu&#39;ils ne sont accessibles que depuis l&#39;ordinateur qui exécute le processus (les ports localhost ne sont visibles que sur cette même machine). Ces services sont donc souvent moins sécurisés que ceux conçus pour être accessibles depuis l&#39;internet public.

Vous pouvez toujours passer outre ce comportement en définissant l&#39;option de configuration `exposeLocalhost` sur `true` pour le port que vous souhaitez exposer.

Si vous souhaitez exposer &#95;systématiquement&#95; les ports localhost par défaut, définissez le paramètre « Transfert automatique des ports » de l&#39;outil User Settings sur « Tous les ports ».

Si vous préférez contrôler manuellement la configuration des ports de toutes vos apps Replit et ne créer &#95;aucune&#95; configuration pour les ports ouverts, définissez-le sur « Jamais ».

<div id="section-7">
  ## Ports pris en charge
</div>

Les applications Replit définissent par défaut le port externe 80 à l&#39;ouverture du premier port. Elles peuvent exposer les ports 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080 et 8081 comme ports externes supplémentaires.

Les ports 22 et 8283 sont utilisés en interne et ne peuvent donc pas être redirigés.

<div id="ports-replit">
  ## Configuration `[[ports]]` du fichier .replit
</div>

Type : `{localPort, externalPort, exposeLocalhost}`

La configuration `[[ports]]` vous permet de définir les ports HTTP à exposer dans la sortie web. Par défaut, les ports HTTP exposés sur l&#39;hôte 0.0.0.0 sont publiés en tant que sortie web de l&#39;application Replit.

Pour proposer des ports supplémentaires sans remplacer le port par défaut, ajoutez une nouvelle entrée [[ports]] dans le fichier .replit. Vous devez indiquer à la fois les entrées localPort et externalPort. Vous pouvez ajouter plusieurs ports supplémentaires en ajoutant plusieurs entrées [[ports]] dans le fichier .replit, comme indiqué ci-dessous.

<div id="localport">
  ### localPort
</div>

Détermine le port que Replit relie à un port externe.

<div id="externalport">
  ### externalPort
</div>

Détermine le port exposé publiquement pour ce port local.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Si vous ne souhaitez &#95;pas du tout&#95; exposer un port donné, il vous suffit de conserver le paramètre `localPort` sans ajouter `externalPort` :

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Détermine si un port interne utilisant `localhost` peut être lié à un port externe. La valeur peut être `true`, `false` ou nulle.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
