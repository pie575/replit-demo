  const AGENT_INPUT_START_DELAY = 500;
  const getAgentInputTypewriterLoader = () => {
    if (typeof window === "undefined") {
      return null;
    }
    if (!window.__replitDocsAgentInputTypewriterLoader) {
      window.__replitDocsAgentInputTypewriterLoader = {};
    }
    return window.__replitDocsAgentInputTypewriterLoader;
  };
  const ensureAgentInputTypewriterCore = () => {
    if (typeof window === "undefined" || typeof document === "undefined") {
      return Promise.resolve(null);
    }
    if (window.Typewriter) {
      return Promise.resolve(window.Typewriter);
    }
    const loader = getAgentInputTypewriterLoader();
    if (loader.promise) {
      return loader.promise;
    }
    loader.promise = new Promise((resolve, reject) => {
      const handleLoad = () => {
        if (window.Typewriter) {
          resolve(window.Typewriter);
          return;
        }
        loader.promise = null;
        reject(new Error("Typewriter core loaded without a global Typewriter export."));
      };
      const handleError = () => {
        loader.promise = null;
        reject(new Error("Failed to load typewriter core."));
      };
      const existingScript = document.getElementById(AGENT_INPUT_TYPEWRITER_SCRIPT_ID);
      if (existingScript) {
        existingScript.addEventListener("load", handleLoad, {
          once: true
        });
        existingScript.addEventListener("error", handleError, {
          once: true
        });
        return;

      const script = document.createElement("script");

      script.src = AGENT_INPUT_TYPEWRITER_SRC;
      script.async = true;
      script.addEventListener("load", handleLoad, {
        once: true
      });
      script.addEventListener("error", handleError, {
        once: true
      });
      document.head.appendChild(script);
    });
    return loader.promise;
  };

      return null;

    startButton: container?.querySelector?.('[data-agent-input-role="start-button"]') || null,
    pillsContainer: container?.querySelector?.('[data-agent-input-role="pills"]') || null

    return textarea?.value?.trim() || "";

  const updateAgentInputButtonState = container => {

    if (!startButton) {
      return;

    const hasText = getAgentInputPromptValue(container).length > 0;
    startButton.style.opacity = hasText ? "1" : "0.4";
    startButton.style.cursor = hasText ? "pointer" : "not-allowed";
  };
  const stopAgentInputTypewriter = (textarea, {placeholder, clearDemo = false} = {}) => {
    if (typeof window === "undefined" || !textarea) {
      return;
    }
    const registry = getAgentInputTypewriterRegistry();
    const record = registry?.get(textarea);
    if (!record) {
      if (placeholder) {
        textarea.setAttribute("placeholder", placeholder);
      }
      return;
    }
    record.stopped = true;
    if (record.startTimer) {
      window.clearTimeout(record.startTimer);
    }
    if (record.writeFrame) {
      window.cancelAnimationFrame(record.writeFrame);
    }
    if (record.typewriter?.stop) {
      record.typewriter.stop();
    }

    textarea.removeEventListener("pointerdown", record.handlePointerDown);
    textarea.removeEventListener("input", record.handleInput);

      textarea.value = "";

[Vibe coding 101](/zh/ja/learn/foundations/vibe-coding-101) 介绍这种思维方式，本页说明如何在实际工作中与 Agent 协作。[有效提示词](/zh/ja/learn/effective-prompting) 讲解如何编写更清晰的指令。

将 Agent 视为场上的四分卫：它会解读局势、选择前进路线并推动工作进展。你则是教练：制定策略、布置战术、复盘结果，并决定下一步行动。

Agent 能做很多事，但当你主导流程时，它的表现最佳：明确说明需求、规划工作、补充上下文、审查并测试，以及在需要恢复时使用检查点。

1. 清晰说明需求。

3. 提供上下文。

5. 使用检查点。

<div id="section">
  ## 明确说明需求
</div>

Agent 可以处理复杂任务，但需要明确的方向。

有效的请求会说明你想要什么、哪些内容最重要，以及哪些内容不能更改。你无需解释每个实现细节，但需要提供足够的指引，让 Agent 能够做出恰当的决策。

不要这样说：

<AiPrompt>
  让我的 App 变得更好。
</AiPrompt>

可以尝试这样说：

<AiPrompt>
  改进注册页面，让访客在创建账户前了解产品的用途。<br />
  保持当前的配色方案和表单字段不变，并让主按钮更加醒目。
</AiPrompt>

第二个提示词为 Agent 提供了目标、重点和约束条件。

如果你的请求包含多个部分，请说明最重要的部分。

<AiPrompt>
  添加一个用于管理餐饮请求的简单管理视图。<br />
  最重要的是能够查看新请求、将其标记为已联系，并按状态筛选。<br />
  首个版本请保持简单。
</AiPrompt>

Agent 可以将任务拆分为多个步骤，但你的指引决定了成功的标准。

有关更具体指示的更多示例，请参阅[有效提示词](/zh/ja/learn/effective-prompting)。

* 它是否解决了正确的问题？
* 是否遗漏了什么？
* 是否有任何内容被列为范围外？
* 是否有可以先构建的更小版本？
* 是否说明了应如何测试结果？

<AiPrompt>

* 用户能否完成主要操作？
* 是否完成了你要求的更改？
* 应用在移动设备上是否也能正常运行？
* 是否有重要功能被破坏？
* Agent 是否更改了不相关的内容？
* 结果是否足以继续构建？

如果发现问题，请说明你看到的情况。

不要这样说：

<AiPrompt>
  修复表单。
</AiPrompt>

试着这样说：

<AiPrompt>
  当我提交餐饮请求表单时，会显示成功消息，但表单仍显示旧文本。<br />
  提交后清空表单，并保持成功消息可见。
</AiPrompt>

具体的反馈能帮助 Agent 修复正确的问题。

<div id="section-5">
  ## 使用检查点
</div>

当更改偏离预期时，检查点可帮助你恢复。

如果结果已接近预期，请提供有针对性的反馈：

<AiPrompt>
  已经很接近了，但表单现在太长了。<br />
  保留新的视觉风格，移除可选备注字段，并让取件日期更易于查看。
</AiPrompt>

如果应用变得比之前更糟、重要功能损坏，或者 Agent 的改动超出预期，请使用检查点。

在 Agent 面板中打开 History 查看检查点。每个检查点都会显示发生了哪些更改，并提供**回滚到此处**和**更改**控件。

<Frame>
  <img src="/assets/mirror/agent-checkpoints-history-c33b3b0dd592.png" alt="Agent History 面板显示一个标有“从规划转到构建模式”的检查点，包含“回滚到此处”和“更改”按钮" width="720" height="450" data-path="images/fitstart/work-with-agent/agent-checkpoints-history.png" />
</Frame>

选择**回滚到此处**后，Agent 会在执行回滚前确认将恢复哪些内容。

<Frame>
  <img src="/assets/mirror/agent-checkpoints-rollback-dialog-28de278b44da.png" alt="回滚到检查点的确认对话框，列出了目标检查点和受影响的内容（文件、Agent 记忆、任务、数据库复选框）" width="900" height="880" data-path="images/fitstart/work-with-agent/agent-checkpoints-rollback-dialog.png" />
</Frame>

如果你不确定应前向修复还是回滚，请让 Agent 帮你比较。

<AiPrompt>
  上一次更改让应用变得更糟。<br />
  将当前版本与之前正常工作的版本进行比较。<br />
  告诉我是前向修复还是回滚更安全，并解释原因。
</AiPrompt>

偏离预期是正常的。检查点让你可以大胆探索，同时保留回到更安全版本的能力。

如需更多恢复相关指导，请参阅[检查点和回滚](/zh/ja/features/version-control/checkpoints-and-rollbacks)。

<div id="agent">
  ## 如何与 Agent 高效协作
</div>

以下情况表明你正朝着正确的方向推进：

* 请求清晰说明了目标和约束条件
* Agent 的计划足够清晰，便于审阅
* 当文字不足以说明时，添加了截图、文件和 Canvas 注释
* 变更后测试了关键流程
* 如果出现问题，提供了有针对性的反馈
* 使用检查点，而不是无休止地修补不理想的变更
