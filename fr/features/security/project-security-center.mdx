Le Centre de sécurité du projet est le point central pour détecter et corriger les vulnérabilités de sécurité et de confidentialité d&#39;une Replit App. Dans le volet **Tools** de votre projet, sélectionnez **Security Center** pour lancer des analyses, examiner les constats et transmettre à Agent les problèmes acceptés en vue de leur remédiation.

<Note>
  Vous débutez avec la sécurité des dépendances ? Consultez les [concepts de
  sécurité](/fr/features/security/concepts) pour les définitions de CVE, SBOM, exposition,
  Fix with Agent, Republish et Auto-Protect.
</Note>

<div id="automatic-dependency-scans">
  ## Analyses automatiques des dépendances
</div>

Les analyses automatiques des dépendances confrontent les paquets du projet aux bases publiques de vulnérabilités. Elles sont gratuites et s&#39;exécutent automatiquement. Lorsqu&#39;une nouvelle entrée CVE (Common Vulnerabilities and Exposures) est publiée, Replit la compare aux dépendances de votre projet et signale les correspondances dans le volet **Sécurité**, sans qu&#39;une nouvelle analyse manuelle soit nécessaire.

L&#39;analyse des dépendances prend en charge Node.js/npm, Python, Go, Rust, PHP et Ruby.

La correction automatique des dépendances est pour l&#39;instant limitée à Node.js/npm.

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect étend l’analyse automatique des dépendances. Lorsque Replit détecte une vulnérabilité correspondante, Agent prépare et teste un correctif, puis vous envoie un lien direct par e-mail. Le correctif reste en attente dans le volet **Sécurité** pour que vous puissiez l’examiner. Après l’avoir appliqué, republiez l’application afin que la version de production inclue le correctif.

Auto-Protect couvre uniquement les CVE des dépendances. Utilisez une [analyse de sécurité Agent](/fr/features/security/agent-security-scans) pour examiner le code de l’application.

Les deux paramètres d’Auto-Protect sont désactivés par défaut :

<Steps>
  <Step title="Activer la préparation des correctifs">
    Un administrateur du Workspace accède à **Settings** &gt; **Account** &gt; **Advanced**, puis
    sélectionne le niveau de gravité minimal (faible, moyen, élevé ou critique) à partir duquel
    Replit doit préparer des remédiations.
  </Step>

  <Step title="Activer les e-mails de sécurité">
    Accédez à **Settings** &gt; **Personalization** &gt; **Email Notifications**, puis
    sélectionnez le niveau de gravité minimal à partir duquel vous souhaitez recevoir des notifications.
  </Step>
</Steps>

Pour chaque nouvelle vulnérabilité, Replit envoie au maximum un e-mail par Workspace récapitulant tous les projets concernés. Sélectionnez **Go to Task** pour examiner un correctif préparé par Agent avant de l’appliquer. Après avoir appliqué le correctif, la vulnérabilité apparaît comme **pending republish** jusqu’à ce que vous publiiez une nouvelle version.

<Note>
  Les remédiations préparées par Agent sont facturées comme les autres tâches Agent, y compris lorsque
  Auto-Protect les prépare de manière proactive.
</Note>

<div id="review-findings">
  ## Examiner les constats
</div>

Les résultats de sécurité s&#39;affichent dans le volet **Sécurité** et sont regroupés par niveau de gravité :

| Gravité                 | Recommandation                                                                |
| ----------------------- | ----------------------------------------------------------------------------- |
| Critique                | Risques immédiats à traiter avant la publication                              |
| Élevée                  | Problèmes sérieux susceptibles d&#39;être exploités dans certaines conditions |
| Moyenne                 | Risques potentiels moins susceptibles d&#39;être exploités                    |
| Faible / Informationnel | Problèmes mineurs et recommandations de bonnes pratiques                      |

Examinez chaque constat avant de l&#39;accepter, de le corriger ou de l&#39;écarter. Transmettez les problèmes acceptés à Agent pour remédiation, puis relancez l&#39;analyse concernée une fois les correctifs appliqués.

<div id="security-checks-during-development-and-publishing">
  ## Contrôles de sécurité pendant le développement et la publication
</div>

<div id="security-scan-while-you-build">
  ### Analyse de sécurité pendant le développement
</div>

Lorsque vous développez avec Agent, Replit analyse automatiquement les fichiers modifiés par Agent afin de détecter les schémas d’insécurité courants et les secrets codés en dur. Il s’agit d’une vérification précoce et légère du flux de travail Agent, plutôt que d’un examen complet de la base de code. Ses résultats n’apparaissent pas dans un rapport distinct du volet **Sécurité**.

<div id="publish-checks">
  ### Contrôles de publication
</div>

Replit exécute également une analyse de sécurité avant la publication. Le paramètre **Bloquer la publication en cas de vulnérabilités critiques** détermine ce qui se passe lorsque l&#39;analyse détecte un problème critique :

* **Activé** : la publication est bloquée tant que le problème n&#39;est pas résolu ou ignoré.
* **Désactivé** : la publication se poursuit et le résultat reste consultable.

Les organisations Enterprise peuvent imposer ce paramètre à toutes les apps.

Ces contrôles complètent une [analyse de sécurité Agent](/fr/features/security/agent-security-scans) ou une [analyse Level 3](/fr/features/security/black-box-pen-tests) complète, sans s&#39;y substituer.
