여기서는 Agent 사용과 관련된 내용을 다룹니다. 자세한 내용은 [Agent 개요](/ko/features/agent/overview), [Agent 모드](/ko/features/agent/agent-modes), [AI 청구](/ko/billing/ai-billing)를 참고하세요.

<AccordionGroup>
  <Accordion title="Agent가 멈추거나 계속 연결이 끊길 때 어떻게 해결하나요?">
    1. `Cmd+K`(Mac) 또는 `Ctrl+K`(Windows)로 명령 팔레트를 엽니다.
    2. **Restart compute**를 검색한 후 선택해 개발 환경을 다시 시작합니다.
    3. 새 Agent chat을 열고 task를 다시 설명해 작업을 이어갑니다.

    Agent가 멈춘 것처럼 보일 때는 메시지를 더 보내지 마세요. 메시지를 추가로 보내면 서로 충돌하는 지시가 전달됩니다. Agent가 같은 task에서 계속 멈춘다면 작업을 더 작고 명확한 prompt로 나누어 요청하세요.
  </Accordion>

  <Accordion title="Agent가 같은 단계를 계속 반복할 때 어떻게 중지하나요?">
    1. Agent 패널에서 **Stop**을 선택해 즉시 중단합니다.
    2. `Cmd+K`(Mac) 또는 `Ctrl+K`(Windows)로 명령 팔레트를 열고 **Restart compute**를 검색해 선택합니다.
    3. 새 Agent chat을 열고 task를 더 구체적으로 다시 작성합니다.

    loop를 방지하려면:

    * 큰 task는 작은 prompt로 나누세요. 메시지 하나에 목표 하나만 담습니다.
    * Agent가 빌드를 시작하기 전에 [Plan mode](/ko/features/agent/plan-mode)로 작업 범위를 정하세요.
    * [지출 관리](/ko/billing/managing-spend)에서 usage limit을 설정해 loop로 인해 요금이 크게 늘어나지 않도록 하세요.
  </Accordion>

  <Accordion title="Agent 비용을 줄이려면 어떤 설정이 실제로 도움이 되나요?">
    다음 선택이 가장 큰 차이를 만듭니다:

    * **[Free Mode](/ko/features/agent/agent-modes)**—요금제에 포함된 allowance 범위 내에서 무료로 처리하는 일상적인 Agent 작업.
    * **[Power mode](/ko/features/agent/agent-modes)**—필요할 때 합리적인 가격으로 더 높은 성능을 제공합니다.
    * **[Plan mode](/ko/features/agent/plan-mode)**—Agent가 빌드하기 전에 작업 범위를 정하고 승인하므로, 원하지 않은 변경에 비용을 지불하지 않습니다.
    * **usage limit 및 예산**—[지출 관리](/ko/billing/managing-spend)에서 상한을 설정하세요.

    작업을 전환할 때 새 Agent chat을 시작하는 것도 도움이 됩니다. usage dashboard에서 어떤 task에 비용이 가장 많이 드는지 확인해 보세요.
  </Accordion>

  <Accordion title="Agent 모드에는 어떤 것이 있으며, 어떻게 다른가요?">
    Agent에는 세 가지 최상위 모드가 있으며, 유료 모드 안에는 **Auto** 설정이 추가로 있습니다. 자세한 안내는 [Free Mode](/ko/help/free-agent-mode)를 참고하세요.

    * **Free Mode**—요금제의 제공량 범위 내에서 무료로 이용하는 일상적인 Agent 작업입니다. Core와 Pro의 제공량은 5시간마다 초기화되며 주간 한도가 있습니다. Starter 등급은 기존 한도를 그대로 유지합니다. 사용량은 **Settings → Usage**에서 확인하세요.
    * **Auto**—Core와 Pro에서 Power 또는 Max로 진행하는 유료 작업에 사용할 모델을 자동으로 선택합니다.
    * **Power**—강력한 모델을 합리적인 가격에 제공하는 유료 중간 등급 모드입니다.
    * **Max**—가장 까다로운 작업을 위해 최고 수준의 프런티어 모델을 제공하는 유료 최상위 모드입니다.

    유료 모드의 이름이 변경되었습니다. **Economy는 이제 Power**이며, 기존에 **Power로 불리던 모드는 이제 Max**입니다. 기존 모드 설정은 새 이름으로 그대로 유지됩니다. 요청에 Free Mode 이상의 성능이 필요한 경우, Agent가 유료 **Allow once** 옵션을 제안할 수 있습니다. Replit은 유료 작업을 시작하기 전에 확인을 요청하며, 작업이 끝나면 Agent는 다시 Free Mode로 돌아갑니다.

    이와 별개로, [Plan mode](/ko/features/agent/plan-mode)에서는 Agent가 변경 사항을 적용하기 전에 작업 범위를 정할 수 있고, Build mode는 변경 사항을 바로 적용합니다. [Plan vs. Build mode](/ko/learn/plan-vs-build-mode)를 참고하세요.
  </Accordion>

  <Accordion title="Agent가 원치 않는 변경을 했습니다. 어떻게 되돌리나요?">
    Replit은 Agent가 작업하는 동안 [체크포인트](/ko/features/version-control/checkpoints-and-rollbacks)를 저장합니다. Agent chat에서 되돌리려는 변경 사항 직전의 메시지를 찾아 그 옆의 롤백 옵션을 선택하면 프로젝트를 해당 시점으로 복원할 수 있습니다.

    특정 파일 복구를 비롯한 전체 롤백 옵션은 [체크포인트 및 롤백](/ko/features/version-control/checkpoints-and-rollbacks)을 참조하세요.
  </Accordion>

  <Accordion title="Agent가 인터넷이나 외부 API에 액세스할 수 없다고 하는데, 정상인가요?">
    빌드 및 편집 단계에서 Agent는 아웃바운드 접근이 제한된 sandbox 환경에서 작동합니다. published app은 실행될 때 외부 API를 정상적으로 호출할 수 있습니다. sandbox는 Agent의 편집 환경에만 적용되고, 실행 중인 앱에는 적용되지 않습니다.

    실행 중인 앱에서 API 호출이 실패하면 [Secrets](/ko/core-concepts/project-editor/app-setup/secrets) pane에 키가 저장되어 있는지 확인한 다음, provider의 status 페이지를 확인하세요. 회사나 학교 네트워크에서는 앱의 아웃바운드 연결이 차단될 수 있으므로 네트워크 관리자에게 문의하세요.
  </Accordion>

  <Accordion title="Agent에서 자체 API 키를 사용할 수 있나요?">
    네. [Secrets](/ko/core-concepts/project-editor/app-setup/secrets) pane에 키를 추가하면 앱이 API 호출에 해당 키를 사용합니다. **Secrets** 도구를 열고 **+ New secret**을 선택한 후 이름(예: `OPENAI_API_KEY`)과 값을 입력하세요.

    앱이 호출하는 model에는 [직접 보유한 AI provider 키를 사용할 수 있습니다](/ko/features/integrations/replit-ai-integrations). 다만 Agent 환경 자체를 구동하는 model은 Replit 인프라에서 실행되므로 교체할 수 없습니다.
  </Accordion>

  <Accordion title="Agent가 요청하지 않은 기능을 계속 추가합니다. 어떻게 하면 더 정확하게 동작하도록 할 수 있나요?">
    더 구체적인 prompt로 Agent의 작업 범위를 좁혀보세요.

    * *Only*라는 단어로 시작하세요. 예를 들어 &quot;Only add a delete button to the user card. Don&#39;t change anything else.&quot;와 같이 작성합니다.
    * [Plan mode](/ko/features/agent/plan-mode)를 먼저 사용해 Agent가 무엇을 하려는지 변경 전에 확인하세요.
    * Agent가 원하지 않는 변경을 했다면, 같은 대화 안에서 바로 해당 변경을 되돌려 달라고 요청하세요.

    자세한 내용은 [효과적인 prompt 작성법](/ko/learn/effective-prompting)을 참고하세요.
  </Accordion>
</AccordionGroup>
