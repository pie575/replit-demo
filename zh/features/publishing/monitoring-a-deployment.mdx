监控工具可以回答关于已发布应用的三个问题：是否在线、运行表现如何、占用了哪些资源。在 **Tools** 面板的 **Replit Cloud** 下打开 **Monitoring**。

应用发布后，监控才会开始工作。在此之前，该工具会显示 **尚无部署** 提示。

<Note>
  想了解访客和用户数据？请在 **Growth** 面板中打开 [Project
  Analytics](/zh/features/publishing/project-analytics)。
</Note>

<div id="application-monitoring">
  ## 应用监控
</div>

应用监控展示你的应用在访客眼中的实际运行状况。在顶部选择时间范围，即可放大或缩小查看粒度。

<Frame>
  <img src="/assets/mirror/application-monitoring-475523d92a9b.png" alt="应用监控视图，显示 uptime 监控、包含唯一 IP 地址的请求图表、HTTP 状态码以及请求耗时" width="2000" height="1656" data-path="images/deployments/monitoring/application-monitoring.png" />
</Frame>

* **Uptime Monitoring**：显示应用处于在线状态的时间百分比，并以彩色条形展示近期历史。Replit 会按固定周期检查你的应用，一旦宕机就会发邮件通知你。
* **Requests**：应用在一段时间内承载的流量，以及访问它的唯一 IP 地址数量。
* **HTTP Statuses**：应用对近期请求的响应情况。成功响应说明运行正常；错误数量激增则说明需要排查。可以把错误激增的时间段粘贴到 Agent 对话中，让它检查日志。
* **Request Durations**：应用的响应耗时，按区间分组展示。如果大多数请求落在最慢的区间，说明应用可能存在问题，或者需要[更强的机器配置](/zh/features/publishing/machine-configuration)。

<div id="turn-on-uptime-monitoring">
  ### 开启 uptime 监控
</div>

uptime 检查在发布设置中进行控制。

<Steps>
  <Step title="打开发布设置">
    打开 **Publishing** 工具，新建发布或重新发布你的应用。
  </Step>

  <Step title="启用开关">
    在 **Monitoring tools** 下打开 **Enable app monitoring**，然后发布应用。
  </Step>

  <Step title="查看 uptime">
    发布完成后，几分钟内即可在 Monitoring 工具中看到 uptime 数据。
  </Step>
</Steps>

<Note>
  uptime 监控适用于 Replit Core、Pro 和 Enterprise 方案，支持除 Scheduled Deployments 以外的所有部署类型 (后者不提供网页服务) 。
</Note>

<div id="infrastructure-monitoring">
  ## 基础设施监控
</div>

基础设施监控展示应用在后台消耗的资源情况。

<Frame>
  <img src="/assets/mirror/infrastructure-monitoring-edad0d8d26fc.png" alt="基础设施监控视图，显示过去一小时的 CPU 使用率和内存使用率图表" width="2000" height="1513" data-path="images/deployments/monitoring/infrastructure-monitoring.png" />
</Frame>

* **CPU Utilization**：应用占用的处理能力。
* **Memory Utilization**：应用占用的内存量。

偶尔出现峰值属于正常现象。如果任一图表长期居高不下，应用在高负载下可能响应缓慢，建议考虑[性能更强的机器配置](/zh/features/publishing/machine-configuration)。

<div id="logs">
  ## 日志
</div>

日志实时展示应用的运行情况，包括应用运行时输出的错误和消息。Replit 会将部署日志保留 30 天。

你可以使用以下筛选条件缩小日志范围：

* **Errors only**：仅查看错误日志。
* **Search**：输入要在日志中查找的关键词。
* **Date**：选择日期范围。

<Tip>
  如果应用出现异常，你不必自己翻阅日志。让 Agent 去排查，它会替你读取日志。
</Tip>
