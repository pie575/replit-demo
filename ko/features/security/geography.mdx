데이터 레지던시 요건을 충족하고 지연 시간을 줄일 수 있도록 workspace와 게시된 앱 인프라를 호스팅할 위치를 선택하세요. Replit은 지역 설정을 개별적으로 제공하므로 개발 환경과 게시된 앱의 위치를 독립적으로 관리할 수 있습니다.

<div id="compare-workspace-and-publishing-geography">
  ## workspace 지역와 publishing 지역 비교
</div>

| 항목              | Workspace 지역    | Publishing 지역        |
| :-------------- | :--------------------- | :-------------------------- |
| **제어 대상**       | workspace의 개발 리소스      | 게시된 앱의 컴퓨팅 및 스토리지   |
| **설정 시점**       | workspace 생성 시         | project를 publish할 때         |
| **위치 적용 결과**    | 새 project와 리소스의 리전을 지정 | 게시된 artifacts를 한 리전에 모아서 배치 |
| **이후 변경 가능 여부** | 불가                     | 불가                          |

workspace 지역와 publishing 지역는 서로 일치하지 않아도 됩니다.

Workspace를 생성할 때 개발 리전을 선택하는 방법은 [Workspace 지역](/ko/features/collaboration/workspace-geography)에서 자세히 확인하세요.

<div id="publishing-geography">
  ## Publishing 지역
</div>

project를 게시할 때 publishing 지역를 설정하세요. 기본적으로 Replit은 사용자와 가장 가까운 지역를 추천합니다. 이렇게 하면 앱 방문자의 지연 시간을 줄이고 데이터 레지던시 요건도 충족할 수 있습니다.

지역를 선택하면 project의 게시된 artifacts(컴퓨팅, database, Object Storage 등)가 모두 자동으로 같은 리전에 함께 배치됩니다. 또한 지역별 프록시가 앱 방문자의 지연 시간을 줄여 줍니다.

<div id="select-a-publishing-geography">
  ### publishing 지역 선택
</div>

권장 지역 대신 다른 지역을 선택하려면 다음과 같이 진행하세요:

<Steps>
  <Step>
    Replit project에서 **Publishing** 도구를 엽니다.
  </Step>

  <Step>
    **Advanced** 설정을 펼칩니다.
  </Step>

  <Step>
    **Geography** 드롭다운에서 원하는 지역를 선택합니다.
  </Step>

  <Step>
    **Publish**를 선택해 선택한 지역에 project를 게시합니다.
  </Step>
</Steps>

<div id="enforce-a-geography-on-published-projects">
  ### 게시된 project에 지역 강제 적용하기
</div>

Enterprise 관리자는 조직 내 모든 project에 publishing 지역를 강제 적용할 수 있습니다. 정책이 설정되면 조직의 builder는 지정된 지역에 게시하게 됩니다. 이 정책은 아직 게시되지 않은 project에만 적용되며, 이미 다른 지역에 게시된 project는 영향을 받지 않습니다.

<Note>
  publishing 지역 강제 적용은 Enterprise 기능입니다. Enterprise plan에 대해 자세히 알아보려면 [Pricing](https://replit.com/pricing/)을 참조하세요.
</Note>

<Steps>
  <Step>
    **Account settings**로 이동합니다.
  </Step>

  <Step>
    **Advanced**를 선택합니다.
  </Step>

  <Step>
    처음 게시되는 모든 project가 사용할 지역를 선택합니다.
  </Step>
</Steps>

<div id="publishing-geography-limitations">
  ### Publishing 지역 제한 사항
</div>

Publishing 지역를 선택하기 전에 다음 제한 사항을 염두에 두세요.

* **게시 후에는 지역를 변경할 수 없습니다.** project를 특정 지역에 게시하면 해당 선택은 영구적으로 유지됩니다. 게시된 project를 다른 지역로 이전할 수 없습니다.
* **Development 위치와 게시 위치가 다를 수 있습니다.** Object Storage와 같은 리소스는 게시 전에 생성할 수 있으므로, 게시된 지역와 일치하지 않을 수 있습니다.

<div id="available-geographies">
  ## 사용 가능한 지역
</div>

Workspace 지역와 publishing 지역는 선택할 수 있는 리전이 서로 다릅니다.

| Geography  | Workspace 선택 가능 | Publishing 선택 가능 |
| :--------- | :-------------- | :--------------- |
| **북미**     | 예               | 예                |
| **유럽(EU)** | 예               | 예                |
| **아시아**    | 예               | 예                |
| **남미**     | 아니요             | 예                |
| **호주**     | 아니요             | 예                |

<Note>
  Workspace 지역 선택은 Pro 고객만 사용할 수 있습니다.
  Publishing 지역 선택은 Core, Pro, Enterprise 고객이 사용할 수 있습니다.
  무료 고객은 기본적으로 북미에 게시됩니다.
</Note>
