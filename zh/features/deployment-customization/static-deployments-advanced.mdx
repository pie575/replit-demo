<div id="add-response-headers">
  ## 添加响应标头
</div>

自定义**响应标头**可让你为匹配特定路径的请求添加 HTTP 标头指令。
响应标头是由名称和值组成的一对字段，用于指示浏览器如何处理请求的内容。

例如，你可以指定 `Access-Control-Allow-Origin` 标头，定义浏览器可以从哪些域访问该页面。
要创建此条目，请将以下内容添加到 Replit App 项目根目录中的 `.replit` 文件：

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

此响应标头包含以下参数：

* **path**：与所请求资源匹配的 URL 路径模式
* **name**：HTTP 标头名称
* **value**：HTTP 标头的值

你可以在 `.replit` 文件中添加多个 `deployment.responseHeaders` 条目。

要应用更新后的配置，请重新发布你的 Replit App。

<div id="reserved-headers">
  #### 保留标头
</div>

Replit 保留以下 HTTP 标头，无法对其进行配置。

```text [expandable] theme={null}
Accept-Ranges
Age
Allow
Alt-Svc
Connection
Content-Encoding
Content-Length
Content-Range
Date
Location
Server
Set-Cookie
Trailer

Upgrade
```

<div id="create-a-custom-404-page">
  ## 创建自定义 404 页面
</div>

当用户请求的 URL 路径与已发布 App 中的任何文件或规则均不匹配时，将显示自定义 404 页面。

要添加自定义 404 页面，请在 Replit App 的项目根目录中创建名为 `404.html` 的文件，并在其中编写页面内容。

当用户尝试访问不存在的 URL 路径时，将看到自定义 404 页面的渲染结果。

<div id="define-url-path-rewrites">
  ## 定义 URL 路径重写
</div>

您可以定义 URL 重写规则，在 Replit App 处理请求前更改请求的 URL 路径。
浏览器中仍会显示原始 URL，但服务器会加载重写规则指定的资源。

例如，您可以指定所有以 `/app` 开头的请求都加载 `/app/index.html` 文件的内容。
要创建此条目，请将以下内容添加到 Replit App 项目根目录中的 `.replit` 文件：

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**：与请求资源匹配的 URL 路径模式
* **to**：重写后的路径，对应于 Static Deployment 中的文件。

你可以在 `.replit` 文件中添加多个 `deployment.rewrites` 条目。
服务器会按照列出的顺序解析这些条目，并忽略重复项。

要使配置更新生效，必须重新发布你的 Replit App。

以下各节介绍 URL 重写规则的限制。

<div id="path-matching">
  ### 路径匹配
</div>

重写规则中的 `from` 和 `to` 参数需遵循以下限制：

* 除非包含 `*`，否则必须完全匹配
* `*` 匹配路径的剩余部分
* `*` 只能出现在路径末尾
* 如果在 `from` 参数中使用 `*`，也可以在 `to` 参数中使用它来表示路径中匹配的部分

例如，如果你的 `.replit` 文件包含以下重写规则：

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

当用户访问路径 `/v1/about-us.html` 时，重写规则会返回位于 `/v2/about-us.html` 的文件。

<div id="shadowing">
  ### 路径遮蔽
</div>

当重写规则匹配的 URL 路径同时也对应 Static Deployment 中的文件时，就会发生路径遮蔽。
发生这种情况时，云服务器会忽略该重写规则，直接提供该文件。

例如，假设你发布的 App 包含以下文件：

* `index.html`
* `about.html`

`.replit` 文件包含以下重写规则：

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

当用户访问 `/register.html` 时，服务器会将请求重写为 `/index.html`，并返回该文件。
不过，如果用户访问 `/about.html`，由于你的 Static Deployment 中存在 `about.html` 文件，服务器会忽略重写规则并返回该文件。

<div id="domain-restrictions">
  ### 域名限制
</div>

重写规则仅适用于发往 Static Deployment 主域名的请求，且只能重定向到该 Static Deployment 中的文件。
