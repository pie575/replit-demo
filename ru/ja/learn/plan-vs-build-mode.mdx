Replit Agent предлагает два режима взаимодействия: **режим Plan** и **режим Build**. Сочетайте их, чтобы сначала тщательно продумать идею, а затем уверенно воплотить её в жизнь.

<div id="plan">
  ## Что такое режим Plan?
</div>

В [режиме Plan](/ru/ja/features/agent/plan-mode) можно обсуждать идеи с Agent, задавать вопросы и планировать работу, не внося изменений в код. Это совместная сессия планирования, в которой можно свободно исследовать идеи.

Режим Plan особенно полезен, когда нужно:

* **Провести мозговой штурм**: изучить разные подходы, прежде чем выбрать один из них
* **Разбить сложный проект на задачи**: составить структурированный список задач до начала разработки
* **Разобраться и узнать больше**: задать вопросы о технологиях, паттернах или кодовой базе
* **Спланировать архитектуру**: спроектировать структуру приложения до написания кода

<Info>
  В режиме Plan Agent изучает ваш проект и предоставляет рекомендации, но не вносит изменений в файлы. Когда будете готовы к реализации, переключитесь в режим Build или утвердите план, чтобы автоматически начать разработку.
</Info>

<div id="build">
  ## Что такое режим Build?
</div>

Режим Build — режим по умолчанию, в котором Agent пишет код, изменяет файлы и напрямую добавляет функциональность в проект. Здесь идеи становятся реальностью.

Когда следует использовать режим Build:

* **Создание новых функций**: поручите Agent написать код для новых функций
* **Настройка приложения**: установка зависимостей, настройка базы данных и подключение сервисов
* **Исправление проблем**: поручите Agent отладить и устранить проблемы в кодовой базе
* **Рефакторинг кода**: улучшение существующей структуры и организации кода

<div id="section">
  ## Используйте оба режима вместе
</div>

**Режимы Plan и Build наиболее эффективны при последовательном использовании.** Сначала составьте план и проясните свои идеи, а затем приступайте к разработке, имея чёткое направление.

<Steps>
  <Step title="Начните с режима Plan">
    Переключитесь в режим Plan и опишите, что хотите создать. Agent поможет продумать требования, предложить подход и выявить потенциальные проблемы — без изменений в коде.
  </Step>

  <Step title="Создайте список задач">
    Попросите Agent составить план разработки. Он разобьёт проект на конкретные выполнимые задачи с чёткими приоритетами и зависимостями.

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="Созданный список задач с приоритетами и зависимостями" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="Проверьте и доработайте">
    Просмотрите предложенный план. Вы можете задать уточняющие вопросы, запросить изменения или рассмотреть другие подходы. Дорабатывайте план, пока он не будет соответствовать вашему видению.
  </Step>

  <Step title="Начните разработку">
    Когда план вас устроит, выберите **Start building (Начать разработку)**. Agent автоматически переключится в режим Build и начнёт выполнять утверждённые задачи.

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="Переключатель режимов с вариантами Plan и Build" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="Отслеживайте прогресс">
    Отслеживайте ход выполнения задач, пока Agent работает со списком задач. Каждая завершённая задача создаёт контрольную точку, поэтому вы можете просматривать изменения и при необходимости откатывать их.
  </Step>
</Steps>

<div id="section-2">
  ## Когда использовать каждый режим
</div>

<CardGroup cols={2}>
  <Card title="Когда использовать режим Plan" icon="lightbulb">
    * Когда начинаете новый проект и нужно определить направление
    * Когда хотите рассмотреть разные подходы
    * Когда задача сложная и её нужно разбить на части
    * Когда хотите разобраться в вопросе до начала реализации
    * Когда не знаете, какое решение будет оптимальным
  </Card>

  <Card title="Когда использовать режим Build" icon="hammer">
    * Когда точно знаете, что хотите получить
    * Когда у вас есть чёткий план, готовый к выполнению
    * Когда нужно быстро исправить что-то или внести небольшие изменения
    * Когда следуете утверждённому списку задач
    * Когда важна скорость реализации
  </Card>
</CardGroup>

<Tip>
  **Не знаете, что выбрать?** Если ваш запрос включает несколько функций или крупные изменения, начните с режима Plan. Для простых, чётко определённых задач сразу переходите в режим Build.
</Tip>

<div id="section-3">
  ## Основные различия
</div>

| Функция            | Режим Plan                                      | Режим Build                          |
| ------------------ | ----------------------------------------------- | ------------------------------------ |
| **Назначение**     | Мозговой штурм, планирование, обучение          | Реализация и разработка              |
| **Изменение кода** | Нет — только для чтения                         | Запись и изменение файлов            |
| **Результат**      | Идеи, список задач, рекомендации                | Рабочий код и функции                |
| **Оптимально для** | Сложных проектов, исследования                  | Чётко определённых задач, реализации |
| **Переход**        | Нажмите «Start building», чтобы перейти в Build | Уже в режиме реализации              |

<div id="section-4">
  ## Рекомендации
</div>

<div id="plan-2">
  ### Используйте режим Plan по максимуму
</div>

* **Чётко формулируйте требования**：чем больше деталей вы укажете, тем лучше получится план
* **Задавайте уточняющие вопросы**：проясняйте непонятные предложения
* **Просите примеры**：попросите Agent показать фрагменты кода или примеры паттернов
* **Обсуждайте компромиссы**：рассматривайте преимущества и недостатки разных подходов
* **Итеративно развивайте идеи**：улучшайте план, пока он не будет соответствовать вашим ожиданиям

<div id="section-5">
  ### Плавный переход
</div>

* **Проверяйте перед сборкой**: всегда просматривайте список задач перед подтверждением
* **Начинайте с малого**: если полный план кажется слишком объёмным, начните с части задач
* **Используйте контрольные точки**: Agent создаёт контрольные точки в процессе сборки, поэтому вы всегда можете откатиться к предыдущей версии
