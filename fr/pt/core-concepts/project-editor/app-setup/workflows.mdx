Il s&#39;agit d&#39;une séquence d&#39;étapes réutilisable et personnalisable, exécutable dans votre App Replit. Elle peut être aussi simple que l&#39;exécution de `python main.py` ou aussi complexe qu&#39;une procédure en plusieurs étapes.

Exemples de cas d&#39;utilisation :

* Exécuter plusieurs services en parallèle (par exemple, frontend + backend)
* Exécuter des fichiers ou des commandes de manière séquentielle (par exemple, exécuter le linter → exécuter les tests, compiler → exécuter le code)

Pour commencer à [créer des workflows](#creating-workflows), accédez au panneau Workflows depuis le menu de la barre d&#39;outils latérale ou recherchez-le avec `Command + K`.

<div id="tipos-de-tarefas-disponveis">
  ## Types de tâches disponibles
</div>

Trois types de tâches sont actuellement disponibles : `Execute Shell Command`, `Install Packages` et `Run Workflow`.

<div id="execute-shell-command">
  ### Exécuter une commande Shell
</div>

`Execute Shell Command` enregistre une commande shell et l’exécute dans le même environnement que le panneau Shell. Ce type de tâche offre de nombreux cas d’utilisation, notamment l’exécution de fichiers individuels :

```text theme={null}
python main.py
```

jusqu’à l’exécution de requêtes complexes sur des bases de données stockées :

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Install Packages
</div>

`Install Packages` utilise le gestionnaire de dépendances intégré de Replit pour détecter automatiquement les dépendances de votre projet et installer les paquets nécessaires. Consultez [Gestion des dépendances](/fr/pt/core-concepts/project-editor/app-setup/dependency-management#the-universal-package-manager) pour en savoir plus sur la façon dont l’UPM détecte en arrière-plan les paquets à installer pour votre projet.

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow` permet d’exécuter un autre workflow depuis le workflow actuel. Vous pouvez ainsi réutiliser et combiner des workflows pour en créer de plus complexes.

Exemple de cas d’utilisation :

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="image" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

En utilisant ce type de tâche pour créer des dépendances entre les workflows, vous pouvez modifier un workflow afin que les autres workflows qui y font référence utilisent automatiquement les dernières modifications. Notez qu’il existe une limite de profondeur pour les appels de workflows très imbriqués.

<div id="modo-de-execuo-do-workflow">
  ## Mode d’exécution des workflows
</div>

Les workflows proposent deux modes d’exécution : séquentiel et parallèle.

<div id="sequencial">
  ### Séquentiel
</div>

L’exécution séquentielle exécute chaque tâche dans l’ordre défini, en attendant la fin de chacune avant de passer à l’étape suivante. L’exécution de la séquence s’arrête si une tâche du workflow échoue.

Ce mode permet par exemple de définir des commandes logiquement liées, telles que des commandes Git pour récupérer les dernières modifications de votre branche principale, puis effectuer un rebase de votre branche actuelle sur celle-ci :

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="image" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="paralelo">
  ### Parallèle
</div>

L’exécution parallèle lance chaque tâche indépendamment des autres tâches du workflow. L’échec d’une tâche n’interrompt pas l’exécution des autres.

Ce mode permet par exemple d’exécuter un projet full stack qui doit démarrer à la fois le frontend et le serveur backend :

<div id="criando-workflows">
  ## Création de workflows
</div>

Vous pouvez créer des workflows depuis le panneau dédié en cliquant sur le bouton `+ New Workflow`. Commencez par donner un nom descriptif à votre workflow, choisissez un mode d’exécution adapté, puis ajoutez des tâches. Vous pouvez réorganiser les tâches par glisser-déposer dans l’ordre souhaité.

<div id="atribuir-workflow-ao-boto-run">
  ## Associer un workflow au bouton Run
</div>

Vous pouvez également associer un workflow au bouton Run afin de remplacer son comportement par défaut (consultez [Configurer une Replit App](/fr/pt/core-concepts/project-editor/app-setup/configuration)). Pour conserver la commande run par défaut configurée dans `.replit`, sélectionnez l’option « Run Replit App » dans le menu déroulant.

Le workflow sélectionné dans le menu déroulant à côté du bouton Run s’exécute lorsque vous cliquez sur ce bouton. Pour modifier le workflow exécuté par le bouton Run, cliquez sur le workflow souhaité dans le menu déroulant.
