<div id="section">
  ## Что такое система задач?
</div>

**Задача** — это единица работы, которую Agent может спланировать и выполнить. Задачи позволяют Agent разбивать крупные цели на небольшие части, каждую из которых можно проверить, прежде чем она будет применена к приложению.

Agent работает в двух местах: в **основном потоке** и в **фоновых задачах**. Основной поток — это диалог, в котором вы описываете, что хотите получить, корректируете направление работы и решаете, что применить к основной версии. Фоновые задачи — это отдельные потоки, в которых Agent работает самостоятельно на изолированной копии проекта.

Используйте основной поток, чтобы задавать направление и принимать решения. Фоновые задачи используйте для исполнительной работы, которую можно вести параллельно. Фоновые задачи не изменяют основную версию, пока вы не проверите их и не примените изменения.

Система задач — это то, как Agent организует такую работу. Когда вы описываете, что хотите собрать, Agent может разбить запрос на отдельные задачи и разместить их на доске со столбцами **Черновики**, **В работе**, **Готово к проверке** и **Завершено**.

<Frame>
  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="Task board showing tasks organized in Drafts, Active, Ready, and Done columns" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />
</Frame>

По мере выполнения каждая задача перемещается слева направо, поэтому вы с одного взгляда видите, что запланировано, над чем Agent работает сейчас, что готово к проверке и что уже завершено. Фоновые задачи автоматически попадают в очередь согласно плану, поэтому работа идёт непрерывно и не перегружает основной поток.

Когда задача завершена, вы можете проверить изменения и применить их к основной версии либо отменить, если результат не соответствует вашим ожиданиям.

<div id="section-2">
  ## Как работают фоновые задачи
</div>

<Steps>
  <Step title="Планирование задач">
    Начните диалог в основном потоке или создайте новый поток и планируйте в нём. Agent изучит проект, определит, что даст наибольший эффект, и составит подробный план по каждой задаче: какие действия будут выполнены и что считать «выполненным».

    <Frame>
      <img src="/assets/mirror/task-describe-idea-555338f515fd.png" alt="Describing what to build in the main thread, with Agent proposing and running tasks" width="3430" height="1986" data-path="images/replitai/task-describe-idea.png" />
    </Frame>
  </Step>

  <Step title="Проверка и принятие">
    Agent предлагает набор задач с заголовком, описанием и подробным планом, который можно изучить через **Просмотреть план**. Просмотрите весь список и выберите:

    * **Принять задачи**: запустить все задачи и отправить их в фон
    * **Изменить план**: попросить Agent скорректировать задачи перед запуском

    <Frame>
      <img src="/assets/mirror/task-accept-plans-d70b85ce3421.png" alt="Task plans created dialog showing four proposed tasks with Accept tasks and Revise plan options" width="3430" height="1986" data-path="images/replitai/task-accept-plans.png" />
    </Frame>
  </Step>

  <Step title="Запуск выполнения задач">
    После принятия задачи начинают выполняться в изолированной копии проекта. На плане Core одновременно выполняется 1 фоновая задача, на Pro — до 10 параллельных фоновых задач. Основная версия остаётся неизменной, пока вы не решите применить изменения. Отслеживать прогресс можно двумя способами:

    * **Просмотр потоков**: каждая задача выполняется в собственном потоке с индикатором состояния в реальном времени, поэтому вы можете следить за ходом работы или подключиться к диалогу

    <Frame>
      <img src="/assets/mirror/task-plan-sidebar-ecab81b06bb0.png" alt="Thread view showing multiple tasks running in parallel with status indicators" width="3430" height="1986" data-path="images/replitai/task-plan-sidebar.png" />
    </Frame>

    * **Просмотр доски**: доска со столбцами, где все задачи сгруппированы по состоянию: **Черновики**, **В работе**, **Готовый к проверке**, **Завершено**

    <Frame>
      <img src="/assets/mirror/task-board-active-355ecd390c49.png" alt="Board view showing tasks organized in Drafts, Active, Ready, and Done columns" width="3430" height="1986" data-path="images/replitai/task-board-active.png" />
    </Frame>
  </Step>

  <Step title="Проверка и применение">
    Когда задача завершена, Agent показывает журнал работы, результаты тестов и живой предпросмотр изменений. Решите, что делать дальше:

    * **Применить изменения к основной версии**: перенести результат задачи в проект
    * **Отменить**: отклонить изменения, если результат вас не устраивает

    Agent автоматически разрешает конфликты при применении изменений из нескольких задач.

    <Frame>
      <img src="/assets/mirror/task-review-apply-3ef379c7e976.png" alt="Task review screen showing Agent's work log, test results, and Apply changes button" width="3456" height="1984" data-path="images/replitai/task-review-apply.png" />
    </Frame>
  </Step>
</Steps>

<div id="section-4">
  ## Что можно создать
</div>

Система задач подходит для любого проекта. Особенно хорошо работают несколько сценариев:

* **Выпуск крупных функций по частям**: разделите аутентификацию, дашборд и слой API на отдельные задачи, чтобы Agent справлялся с ними аккуратно
* **Планирование сложных проектов**: разбейте крупную функцию на чётко описанные задачи с зависимостями и уверенно выполняйте их
* **Сравнение разных вариантов дизайна**: с помощью отдельных задач опробуйте несколько подходов к интерфейсу и выберите лучший результат

<div id="section-5">
  ## Часто задаваемые вопросы
</div>

<Accordion title="Нужно ли менять подход к разработке?">
  Нет. Основной поток работает так же, как и раньше. Agent автоматически создаёт фоновые задачи, когда это полезно. Вы также можете использовать [режим Plan](/ru/ko/features/agent/plan-mode), чтобы явно просматривать задачи и управлять ими.
</Accordion>

<Accordion title="Почему задачи выполняются по одной?">
  Core выполняет одновременно 1 фоновую задачу. Pro поддерживает до 10 одновременных фоновых задач. При достижении лимита тарифа дополнительные задачи попадают в очередь и запускаются, как только освободится слот.
</Accordion>

<Accordion title="Как Agent разрешает конфликты при применении фоновых задач?">
  Agent разрешает конфликты с помощью ИИ. Он понимает, чего должна была достичь каждая задача, и применяет изменения осмысленно. Если что-то выглядит странно, попросите Agent исправить это прямо в потоке.
</Accordion>

<Accordion title="Могут ли задачи зависеть друг от друга?">
  Да. Agent определяет зависимости автоматически. Например, задача по созданию панели управления зависит от задачи, создающей схему базы данных. Зависимые задачи ждут, пока не будут выполнены предварительные условия.
</Accordion>

<Accordion title="В чём разница между архивированием и отменой задачи?">
  **Архивирование** применяется к сессиям планирования — черновикам, разработка которых ещё не началась. Архивированные сессии планирования сохраняются, и их можно восстановить в столбце **Завершено**.

  **Отмена** применяется к задачам, которые уже перешли из планирования в разработку. При отмене задача останавливается, а проделанная работа отбрасывается; отменённые задачи восстановить нельзя. Вместо этого запустите новую задачу.
</Accordion>
