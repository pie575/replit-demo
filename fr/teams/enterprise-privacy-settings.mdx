En tant qu&#39;administrateur Enterprise, vous pouvez configurer des paramètres applicables à toute l&#39;organisation, qui déterminent la façon dont les membres de l&#39;équipe interagissent avec le code, les déploiements et les plateformes externes. Ces paramètres vous aident à maintenir vos standards de sécurité, à protéger la propriété intellectuelle et à assurer la conformité aux politiques de l&#39;entreprise.

<div id="accessing-privacy-settings">
  ## Accéder aux paramètres de confidentialité
</div>

<Accordion title="Comment accéder aux paramètres de confidentialité">
  1. Rendez-vous dans votre workspace Enterprise
  2. Sélectionnez **Settings**
  3. Sélectionnez **Advanced** pour afficher tous les paramètres disponibles
</Accordion>

<div id="privacy-settings">
  ## Paramètres de confidentialité
</div>

Les paramètres de confidentialité déterminent la façon dont les apps sont publiées et accessibles au sein de votre organisation.

<CardGroup cols={2}>
  <Card title="Déploiements privés" icon="lock">
    Exigez que toutes les nouvelles apps soient publiées en privé, afin de réserver l&#39;accès aux seuls membres de l&#39;équipe authentifiés
  </Card>

  <Card title="Deployments protégés par mot de passe" icon="key">
    Autorisez les membres de l&#39;équipe à protéger leurs apps publiées par un mot de passe
  </Card>

  <Card title="URL de développement privées" icon="shield-halved">
    Exigez une authentification pour toutes les URL de développement des apps, y compris le SSO pour les organisations utilisant SAML
  </Card>
</CardGroup>

<div id="private-deployments">
  ### Déploiements privés
</div>

Lorsque ce paramètre est activé, toutes les nouvelles apps doivent être publiées en mode privé. Les apps privées sont accessibles uniquement aux membres authentifiés de votre organisation.

**Quand utiliser ce paramètre :**
**Quand utiliser ce paramètre :**

* L&#39;organisation traite des données sensibles ou des applications propriétaires
* Vous devez éviter que des apps soient rendues publiques par inadvertance
* Des exigences de conformité imposent un accès restreint aux applications publiées
* Vous devez éviter que des apps soient rendues publiques par inadvertance
* Des exigences de conformité imposent un accès restreint aux applications publiées

<Note>
  Ce paramètre s&#39;applique uniquement aux apps nouvellement publiées. Les apps déjà publiées conservent leurs paramètres de visibilité actuels.
</Note>

<div id="password-protected-deployments">
  ### Deployments protégés par mot de passe
</div>

Déterminez si les membres de l&#39;équipe peuvent créer des deployments protégés par mot de passe. Lorsque cette option est activée, les créateurs peuvent ajouter un niveau de sécurité supplémentaire en exigeant un mot de passe pour accéder à leurs apps publiées.

**Quand utiliser ce paramètre :**

* Vous souhaitez partager des apps avec des parties prenantes externes sans les rendre entièrement publiques
* Les équipes doivent présenter des applications à des clients avant une diffusion plus large
* Vous avez besoin d&#39;un contrôle d&#39;accès précis, au-delà de la simple appartenance à l&#39;organisation

<div id="require-private-development-urls">
  ### Exiger des URL de développement privées
</div>

Lorsque ce paramètre est activé, toutes les URL de développement des apps nécessitent une authentification. Si votre organisation a activé SAML, les URL de développement nécessitent une authentification SSO.

**Quand utiliser ce paramètre :**
**Quand utiliser ce paramètre :**

* Vous devez empêcher tout accès non autorisé aux applications en cours de développement
* Vos politiques de sécurité exigent que tous les environnements de développement soient protégés
* Vous souhaitez garantir que seuls les membres authentifiés de l&#39;équipe puissent consulter les aperçus de développement
* Votre politique de sécurité exige que tous les environnements de développement soient protégés
* Vous souhaitez garantir que seuls les membres authentifiés de l&#39;équipe puissent consulter les aperçus de développement

<Warning>
  Ce paramètre s&#39;applique rétroactivement à toutes les apps existantes de votre organisation.
</Warning>

<div id="ban-source-code-export">
  ### Interdire l&#39;exportation du code source
</div>

Lorsque ce paramètre est activé, les membres de l&#39;équipe ne peuvent pas exporter le code source des apps sous forme de fichier zip. Cela empêche le téléchargement et le partage du code en dehors de la plateforme Replit.

**Quand utiliser ce paramètre :**
**Quand utiliser ce paramètre :**

* Vous devez garder un contrôle strict sur l&#39;emplacement du code source
* Vos politiques de sécurité interdisent les copies locales du code
* Vous souhaitez que tout le développement se déroule dans des environnements gérés
* Votre politique de sécurité interdit les copies locales du code
* Vous souhaitez que tout le développement se déroule dans votre environnement géré

<div id="security-settings">
  ## Paramètres de sécurité
</div>

Les paramètres de sécurité vous permettent d&#39;imposer l&#39;analyse des vulnérabilités et d&#39;autres mesures de protection.

<div id="require-security-scan">
  ### Exiger une analyse de sécurité
</div>

Indiquez si toutes les apps doivent réussir une analyse de sécurité avant d’être publiées. Les analyses de sécurité détectent les vulnérabilités, les Secrets exposés et d’autres problèmes de sécurité dans votre code.

Options disponibles :

| Paramètre     | Description                                                                   |
| ------------- | ----------------------------------------------------------------------------- |
| **Désactivé** | Les analyses de sécurité sont facultatives                                    |
| **Exiger**    | Toutes les apps doivent réussir une analyse de sécurité avant d’être publiées |

**Quand utiliser ce paramètre :**
**Quand utiliser ce paramètre :**

* Des exigences de conformité en matière de sécurité doivent être respectées
* Vous souhaitez empêcher l’exposition accidentelle de clés API ou de secrets
* Vous devez garantir des standards de sécurité cohérents dans toutes les apps publiées
* Vous souhaitez empêcher l’exposition accidentelle de clés API ou de secrets
* Vous devez garantir des standards de sécurité cohérents dans toutes les apps publiées

<Note>
  Ce paramètre ne s’applique pas aux apps publiées avant son activation.
</Note>

<div id="source-control-settings">
  ## Paramètres de gestion du code source
</div>

Les paramètres de gestion du code source vous permettent d&#39;imposer des pratiques de contrôle de version et de protéger les dépôts de code de votre organisation.

<div id="require-git-remote">
  ### Exiger un dépôt Git distant
</div>

Lorsque ce paramètre est activé, toutes les Apps doivent avoir poussé leurs modifications locales vers un dépôt Git distant avant la publication. Cela garantit que toutes les modifications de code sont suivies dans le système de contrôle de version de votre organisation.

**Quand utiliser ce paramètre :**
**Quand utiliser ce paramètre :**

* Tout le code doit être sauvegardé dans Git
* Vous avez besoin d&#39;une piste d&#39;audit de toutes les modifications de code
* Les workflows exigent une revue de code avant la publication
* Vous avez besoin d&#39;une piste d&#39;audit de toutes les modifications de code
* Votre workflow exige une revue de code avant la publication

<Note>
  Ce paramètre ne s&#39;applique pas aux Apps publiées avant son activation.
</Note>

<div id="private-remotes">
  ### Dépôts distants privés
</div>

Déterminez si les membres de l&#39;équipe peuvent utiliser des dépôts Git publics. Lorsque les dépôts distants privés sont exigés, les membres de l&#39;équipe ne peuvent pousser leur code que vers des dépôts privés, sur des plateformes comme GitHub.

Options disponibles :

| Paramètre                               | Description                                                                                   |
| --------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Désactivé**                           | Les membres de l&#39;équipe peuvent utiliser des dépôts publics ou privés                     |
| **Exiger pour les non-administrateurs** | Les membres de l&#39;équipe non administrateurs doivent utiliser des dépôts privés            |
| **Exiger pour tous**                    | Tous les membres de l&#39;équipe, administrateurs compris, doivent utiliser des dépôts privés |

**Quand utiliser ce paramètre :**
**Quand utiliser ce paramètre :**

* Les dépôts de code publics sont interdits
* Vous devez éviter que du code propriétaire soit poussé par erreur vers des dépôts publics
* Des exigences de conformité imposent un contrôle de version privé
* Vous devez éviter que du code propriétaire soit poussé par erreur vers des dépôts publics
* Des exigences de conformité imposent un contrôle de version privé

<div id="best-practices">
  ## Bonnes pratiques
</div>

<AccordionGroup>
  <Accordion title="Commencez par le mode privé par défaut" icon="shield">
    Activez les **Déploiements privés** pour que toutes les nouvelles applications publiées soient privées. Vous évitez ainsi d&#39;exposer accidentellement des applications sensibles.
  </Accordion>

  <Accordion title="Imposez l'analyse de sécurité" icon="magnifying-glass">
    Activez l&#39;option **Exiger une analyse de sécurité** afin de détecter les vulnérabilités avant la mise en ligne des applications. Vous maintenez ainsi des standards de sécurité homogènes dans toute votre organisation.
  </Accordion>

  <Accordion title="Protégez les environnements de développement" icon="code">
    Activez l&#39;option **Exiger des URL de développement privées** pour protéger même les travaux en cours. C&#39;est particulièrement important pour les organisations qui manipulent des données sensibles.
  </Accordion>

  <Accordion title="Contrôlez l'accès au code source" icon="code-branch">
    Combinez **Interdire l&#39;exportation du code source** avec l&#39;exigence de **Dépôts distants privés** pour garder un contrôle total sur l&#39;emplacement du code et les accès à celui-ci.
  </Accordion>
</AccordionGroup>
