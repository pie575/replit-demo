# Utiliser le panneau Git

> Découvrez comment utiliser le panneau Git pour le contrôle de version, la gestion des branches et la collaboration dans l'éditeur de projet.

Le panneau Git de Replit fournit une interface visuelle pour les opérations Git, éliminant ainsi le besoin d'utiliser des commandes Git en ligne de commande. Cette fonctionnalité rend le contrôle de version accessible aux débutants tout en restant puissante pour les développeurs expérimentés.

## Fonctionnalités

Le panneau Git offre des capacités complètes de contrôle de version directement dans l'éditeur de projet, avec une interface conviviale qui simplifie les opérations Git complexes.

* **Gestion du dépôt** : Initialisez, connectez et gérez des dépôts Git avec l'intégration GitHub
* **Suivi des commits** : Indexez, validez et consultez les modifications dans tous vos fichiers
* **Opérations sur les branches** : Créez, basculez entre les branches et fusionnez-les visuellement
* **Résolution des conflits** : Identifiez et résolvez les conflits de fusion avec une assistance visuelle
* **Intégration Shell** : Synchronisation entre les commandes Git exécutées dans le Shell et le panneau Git

## Utilisation

### Configuration du dépôt

<Accordion title="Comment accéder au panneau Git">
  1. Accédez à la section Outils dans votre Application Replit
  2. Sélectionnez le signe **+** pour ajouter de nouveaux outils
  3. Sélectionnez **Git** dans la liste des outils disponibles
</Accordion>

Le panneau Git vous aide à configurer et connecter votre dépôt :

* **Initialiser le dépôt** : Créez un nouveau dépôt Git pour votre Application Replit
* **Se connecter à un fournisseur Git** : Liez votre dépôt à un fournisseur hébergé ou auto-hébergé pris en charge pour la sauvegarde et la collaboration
* **Configurer le dépôt distant** : Configurez et gérez la connexion à votre dépôt distant

<Note>
  **Prise en charge de Git auto-hébergé** : Replit prend en charge GitHub Enterprise Server, GitLab Self-Managed et Bitbucket Data Center sur le plan Enterprise. [Contactez l'équipe commerciale de Replit](https://replit.com/enterprise) pour obtenir des conseils d'intégration, de la configuration des fournisseurs et du débogage de connexion. Vous pouvez également [configurer un dépôt distant avec des commandes Git dans le Shell](#utiliser-les-commandes-git-dans-le-shell).
</Note>

### Gestion des modifications

<Accordion title="Comment consulter les modifications">
  1. Apportez des modifications à n'importe quels fichiers dans votre Application Replit
  2. Ouvrez le panneau Git depuis la section Outils
  3. Examinez les modifications dans la section **Examiner les modifications**
</Accordion>

Le panneau Git fournit des outils pour gérer vos modifications de code :

* **Examiner les modifications** : Consultez les fichiers modifiés avec les ajouts et suppressions mis en évidence
* **Indexer les fichiers** : Sélectionnez des fichiers spécifiques à inclure dans votre prochain commit
* **Valider les modifications** : Enregistrez vos modifications avec des messages descriptifs
* **Pousser les mises à jour** : Envoyez vos commits vers votre dépôt distant en un seul clic

<Note>
  Vous pouvez utiliser Replit AI pour générer des messages de commit qui décrivent précisément vos modifications.

### Gestion des branches

<Accordion title="Comment gérer les branches">
  1. Ouvrez le panneau Git depuis la section Outils
  2. Sélectionnez la liste déroulante des branches à côté du nom de la branche
  3. Créez une nouvelle branche ou sélectionnez-en une existante
</Accordion>

Le panneau Git simplifie le travail avec plusieurs versions de votre code :

* **Créer des branches** : Créez de nouvelles branches pour développer des fonctionnalités séparément
* **Basculer entre les branches** : Passez d'une version à l'autre de votre code
* **Publier des branches** : Partagez vos branches avec votre fournisseur Git
* **Tirer les modifications** : Synchronisez avec les mises à jour distantes des collaborateurs

### Résolution des conflits de fusion

<Accordion title="Comment résoudre les conflits de fusion">
  1. Tentez de tirer des modifications lorsque des conflits existent
  2. Le panneau Git mettra en évidence les fichiers en conflit
  3. Ouvrez chaque fichier en conflit pour voir et résoudre les conflits
  4. Enregistrez les fichiers après avoir résolu les conflits
  5. Terminez la fusion en sélectionnant **Tirer**
</Accordion>

Lorsque du code provenant de sources différentes entre en conflit, le panneau Git vous aide à :

* **Identifier les conflits** : Voir exactement quels fichiers contiennent des conflits
* **Visualiser les différences** : Examiner les deux versions du code en conflit
* **Résoudre les problèmes** : Choisir quel code conserver ou modifier manuellement les conflits
* **Finaliser les fusions** : Compléter le processus de fusion après avoir résolu les conflits

<Frame>
  <img src="https://mintcdn.com/replit/rBzGsKp9NcWJ7sib/images/gh/pane/11-merge-conflict.png?fit=max&auto=format&n=rBzGsKp9NcWJ7sib&q=85&s=f02773231068c03053c9c80d75ded53f" alt="Éditeur de code affichant les marqueurs de conflit de fusion" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

Après avoir résolu un fichier en conflit, vous pouvez supprimer les marqueurs de conflit en supprimant les lignes commençant par des symboles de conflit et en enregistrant le fichier.

### Utiliser les commandes Git dans le Shell

<Accordion title="Comment accéder au Shell">
  1. Sélectionnez **Tous les outils** depuis le dock d'outils à gauche
  2. Sélectionnez **Shell** dans les outils disponibles
</Accordion>

<Tip>
  Bien que le panneau Git fournisse une interface conviviale, les utilisateurs avancés peuvent utiliser des commandes Git standard dans le Shell pour des opérations plus complexes. Les modifications effectuées par l'une ou l'autre méthode seront reflétées dans les deux endroits.
</Tip>

Si vous préférez utiliser Git via la ligne de commande :

* **Synchronisation des commandes** : Toutes les commandes Git exécutées dans le Shell se synchroniseront automatiquement avec le panneau Git
* **Fonctionnalité Git complète** : Accédez aux fonctionnalités Git avancées non disponibles dans le panneau Git
* **Basculement transparent** : Passez librement entre l'utilisation des commandes Shell et du panneau Git

<Info>
  **Prise en charge de GitHub CLI et GitLab CLI** : En plus des commandes Git standard, vous pouvez également utiliser le [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) et le [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) dans le Shell pour gérer et vous connecter à des dépôts Git externes. Ces outils offrent des fonctionnalités améliorées pour travailler avec des dépôts GitHub et GitLab, notamment les pull requests, les issues et d'autres fonctionnalités spécifiques à la plateforme.
</Info>

#### Opérations sur le dépôt

* **Cloner un dépôt** : `git clone <url-du-dépôt>`
* **Initialiser un dépôt** : `git init`
* **Ajouter un dépôt distant** : `git remote add origin <url-du-dépôt>`

#### Effectuer des modifications

* **Vérifier l'état** : `git status` (affiche les fichiers modifiés, ajoutés et supprimés)
* **Indexer les fichiers** : `git add <nom-du-fichier>` ou `git add .` (pour tous les fichiers)
* **Valider les modifications** : `git commit -m "votre message de commit"`
* **Pousser les modifications** : `git push origin <nom-de-branche>`
* **Tirer les modifications** : `git pull origin <nom-de-branche>`

#### Authentification

Lorsque vous travaillez avec des dépôts privés, vous devez vous authentifier :

* Pour les dépôts GitHub.com, utilisez un jeton d'accès personnel au lieu de votre mot de passe
* Pour éviter de ressaisir vos identifiants, vous pouvez les stocker en utilisant les Secrets Replit :
  1. Créez un nouveau secret avec la clé `GIT_URL`
  2. Définissez la valeur sur `https://<nom-utilisateur>:<jeton>@<hôte-git>/<propriétaire>/<dépôt>`
  3. Utilisez `git push $GIT_URL` pour pousser sans saisir vos identifiants

<Note>
  Lorsque vous utilisez des secrets d'identifiants, toute personne ayant accès à votre Application Replit peut potentiellement accéder à vos identifiants Git. Pour les dépôts sensibles, envisagez de saisir manuellement vos identifiants à chaque fois.
</Note>
