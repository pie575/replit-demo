В этом руководстве собран подробный чек-лист по безопасности, который поможет привести приложения, созданные в подходе vibe coding, в соответствие с лучшими практиками безопасности.

Replit предоставляет множество средств защиты [«из коробки»](/ru/features/security/overview), но не менее важно понимать и применять дополнительные меры с учётом особенностей вашего приложения.

<div id="front-end-security">
  ## Безопасность фронтенда
</div>

<AccordionGroup>
  <Accordion title="HTTPS везде" icon="lock">
    Replit по умолчанию использует HTTPS для всех приложений, так что об этом можно не беспокоиться!
  </Accordion>

  <Accordion title="Проверка и очистка входных данных" icon="shield-check">
    Всегда проверяйте и очищайте пользовательский ввод, чтобы предотвратить атаки межсайтового скриптинга (XSS):

    ```javascript theme={null}
    // Плохо: прямое использование пользовательского ввода
    element.innerHTML = userInput;

    // Хорошо: очистить ввод перед использованием
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    Попросите Agent:

    ```
    Help me validate and sanitize inputs to protect against XSS attacks
    ```
  </Accordion>

  <Accordion title="Не держите конфиденциальные данные в браузере" icon="eye-slash">
    Для хранения конфиденциальной информации, например ключей API, используйте Replit Secrets.

    Не передавайте секреты на клиентскую сторону и не размещайте их в следующих местах:

    * Локальное хранилище
    * Хранилище сессии
    * Клиентский JavaScript
    * Файлы cookie без надлежащих атрибутов безопасности

    Попросите Agent:

    ```
    Help me keep sensitive data out of the browser. Am I doing this correctly?
    ```
  </Accordion>

  <Accordion title="Защита от CSRF" icon="shield">
    Реализуйте защиту форм от межсайтовой подделки запросов (CSRF):

    ```javascript theme={null}
    // Пример реализации CSRF-токена
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    Попросите Agent:

    ```
    Help me implement CSRF tokens for forms
    ```
  </Accordion>
</AccordionGroup>

<div id="back-end-security">
  ## Безопасность серверной части
</div>

<AccordionGroup>
  <Accordion title="Основы аутентификации" icon="key">
    При реализации аутентификации:

    * По возможности используйте Replit Auth
    * Если создаёте собственную аутентификацию, используйте проверенные библиотеки
    * Никогда не храните пароли в открытом виде

    Попросите Agent:

    ```
    Help me implement authentication for my application with Replit Auth
    ```
  </Accordion>

  <Accordion title="Проверка прав доступа" icon="user-lock">
    Всегда проверяйте права доступа перед выполнением действий:

    ```javascript theme={null}
    // Пример проверки авторизации
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    Попросите Agent:

    ```
    Help me implement authorization checks for my application
    ```
  </Accordion>

  <Accordion title="Защита конечных точек API" icon="shield">
    Защитите конечные точки API:

    * Добавьте аутентификацию для конечных точек с конфиденциальными данными
    * Настройте корректные параметры CORS
    * Рассмотрите ограничение частоты запросов

    Попросите Agent:

    ```
    How do I properly authenticate endpoints in my app?
    ```
  </Accordion>

  <Accordion title="Предотвращение SQL-инъекций" icon="database">
    Agent по умолчанию использует ORM, что помогает предотвратить SQL-инъекции. Если вы пишете собственные запросы к базе данных:

    ```javascript theme={null}
    // Плохо: конкатенация строк в запросах
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // Хорошо: параметризованные запросы с ORM
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="Заголовки безопасности" icon="code">
    Добавьте в приложение важные заголовки безопасности:

    ```html theme={null}
    <!-- В index.html или через серверную часть -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    Проверить сайт и получить рекомендации можно на [securityheaders.com](https://securityheaders.com).

    Попросите Agent:

    ```
    Can you add the security headers to my application?
    ```
  </Accordion>
</AccordionGroup>

<div id="ongoing-security-practices">
  ## Регулярные практики безопасности
</div>

<AccordionGroup>
  <Accordion title="Обновляйте зависимости" icon="arrow-rotate-right">
    Регулярно проверяйте, нет ли устаревших пакетов с уязвимостями:

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="Корректная обработка ошибок" icon="exclamation">
    Не раскрывайте конфиденциальную информацию в сообщениях об ошибках:

    ```javascript theme={null}
    // Плохо: раскрытие конфиденциальных деталей
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // Хорошо: общее сообщение об ошибке
    catch (err) {
      console.error(err); // Логируем внутри системы
      res.status(500).send('An error occurred');
    }
    ```

    Попросите Agent:

    ```
    Help me implement proper error handling for my application
    ```
  </Accordion>

  <Accordion title="Безопасные файлы cookie" icon="cookie">
    При использовании файлов cookie:

    * Устанавливайте флаг HttpOnly, чтобы запретить доступ из JavaScript
    * Используйте атрибут Secure, чтобы требовать HTTPS
    * Применяйте атрибут SameSite для защиты от CSRF

    Попросите Agent:

    ```
    Help me secure my cookies for my application
    ```
  </Accordion>

  <Accordion title="Безопасность загрузки файлов" icon="upload">
    Если ваше приложение позволяет загружать файлы:

    * Ограничивайте типы и размеры файлов
    * По возможности проверяйте файлы на вредоносное ПО
    * Храните файлы в объектном хранилище Replit
    * Генерируйте новые имена файлов вместо того, чтобы использовать заданные пользователем

    Попросите Agent:

    ```
    Help me secure my file uploads for my application
    ```
  </Accordion>

  <Accordion title="Ограничение частоты запросов" icon="clock">
    Реализуйте ограничение частоты запросов для API-эндпоинтов, особенно связанных с аутентификацией:

    ```javascript theme={null}
    // Пример middleware для ограничения частоты запросов
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 минут
      max: 100 // ограничение: 100 запросов с одного IP за windowMs
    });

    app.use('/api/', limiter);
    ```

    Попросите Agent:

    ```
    Help me implement rate limiting for my application
    ```
  </Accordion>
</AccordionGroup>

<div id="front-end-security-2">
  ## Безопасность фронтенда
</div>

|   | Мера безопасности                             | Описание                                                                     |
| - | --------------------------------------------- | ---------------------------------------------------------------------------- |
| ☐ | Используйте HTTPS повсеместно                 | Защищает от простого перехвата трафика и атак типа «человек посередине»      |
| ☐ | Проверка и очистка входных данных             | Предотвращает XSS-атаки за счёт проверки всех данных, вводимых пользователем |
| ☐ | Не храните конфиденциальные данные в браузере | Никаких секретов в локальном хранилище или клиентском коде                   |
| ☐ | Защита от CSRF                                | Используйте анти-CSRF-токены для форм и запросов, изменяющих состояние       |
| ☐ | Никогда не раскрывайте ключи API во фронтенде | Учётные данные API всегда должны оставаться на стороне сервера               |

<div id="back-end-security-2">
  ## Безопасность серверной части
</div>

|   | Мера безопасности              | Описание                                                                                                  |
| - | ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| ☐ | Основы аутентификации          | Используйте проверенные библиотеки и надёжное хранение паролей (хеширование + соль)                       |
| ☐ | Проверка прав доступа          | Всегда проверяйте разрешения перед выполнением действий                                                   |
| ☐ | Защита конечных точек API      | Настройте полноценную аутентификацию для каждой конечной точки API                                        |
| ☐ | Защита от SQL-инъекций         | Используйте параметризованные запросы или ORM и никогда не подставляйте пользовательский ввод в сырой SQL |
| ☐ | Базовые заголовки безопасности | Настройте X-Frame-Options, X-Content-Type-Options и HSTS                                                  |
| ☐ | Защита от DDoS                 | Используйте CDN или облачный сервис со встроенными средствами защиты от DDoS                              |
