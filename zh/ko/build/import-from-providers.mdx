使用导入功能，你可以将现有代码或设计导入 Replit Apps，并借助 Agent 继续构建。

<div id="section">
  ## 支持的来源
</div>

| 来源          | 提供的内容                                 | 最佳使用场景                      |
| ----------- | ------------------------------------- | --------------------------- |
| GitHub      | 仓库 URL 或仓库选择器                         | 导入公开和私有仓库                   |
| Bitbucket   | 仓库 URL 或仓库选择器                         | 导入 Bitbucket 托管的仓库          |
| Vercel      | Vercel 项目对应的 GitHub 仓库                | 迁移 Vercel 应用                |
| Figma       | 框架 URL                                | 将设计转换为 React 应用             |
| Claude      | 从 Claude 发送的设计                        | 将 Claude 设计转换为交互式应用         |
| Bolt        | 从 Bolt 导出的 GitHub 仓库                  | 迁移 Bolt 项目                  |
| Lovable     | 从 Lovable 导出的 GitHub 仓库               | 迁移 Lovable 项目               |
| Base44      | 从 Base44 导出的 GitHub 仓库                | 迁移 Base44 项目                |
| ZIP         | 上传 `.zip` 文件                          | 导入本地项目归档                    |
| 电子表格        | `.xlsx`、`.csv` 文件，或 Google Sheets URL | 用电子表格数据构建应用                 |
| 旧版 Agent 导出 | 从旧版 Agent App 导出的 GitHub 仓库           | 重新导入旧版 Agent App            |
| 空项目         | 无                                     | 希望在不使用 Agent 的情况下创建空项目的高级用户 |

<Note>Replit 会在开始导入前验证兼容性。</Note>

如需导入 Figma 设计，请参阅[将 Figma 设计导入 Replit Design](/zh/ko/design/import-figma-designs-into-replit-design)。

如需导入从 Claude 发送的设计，请参阅[将 Claude 设计导入 Replit Design](/zh/ko/design/import-claude-designs-into-replit-design)。

    ⏰ *预计用时：2 分钟*

    将 GitHub 仓库导入 Replit，更快地运行、测试和发布。

    **开始之前**

    * GitHub 仓库 URL

    快速导入适用于公开仓库。

    3. 按 Enter 开始导入。

    *示例*

    * GitHub URL：`https://github.com/exampleUser/my-app`
    * Replit 导入 URL：`https://replit.com/github.com/exampleUser/my-app`

    **选项 2：引导式导入**

    引导式导入同时支持公开和私有仓库。

    1. 打开 [replit.com/import](https://replit.com/import)。
    2. 选择 **GitHub**。
    3. 连接你的 GitHub 账户。
    4. 选择仓库。
    5. 选择 **Import**。

    **会导入的内容**

    * 仓库文件和文件夹
    * 依赖文件
    * 常见的运行和构建配置

    **不会导入的内容**

    * 已有的 Secrets 值和环境变量值
    * 在 Replit 上默认无法运行的特定平台服务

    **排查 GitHub 连接问题**

    如果出现 `Failed to get repository, please re-authenticate with GitHub` 错误，或仓库下拉列表中显示 `No repositories found`，这是因为 GitHub 导入流程所用的连接与 **Account → Connected Services** 页面中的连接相互独立。仅在 Connected Services 中重新连接并不能解决导入流程的问题。

    <Steps>
      <Step title="在 Git Providers 中重新连接 GitHub">
        打开 Replit 账户设置中的 **Git Providers** 部分，断开 GitHub 连接，然后在同一界面重新连接。之后，你的个人仓库应会出现在导入下拉列表中。

      <Step title="为 GitHub 组织授权 Replit 应用">
        如果仓库归 GitHub 组织所有，请打开 [https://github.com/settings/applications](https://github.com/settings/applications)，找到 Replit OAuth 应用，并在第三方应用访问设置中授予对该组织的访问权限。如果你不是组织所有者，可能需要由组织管理员来完成这一步。
      </Step>

      <Step title="重试导入">
        打开 [replit.com/import](https://replit.com/import)，分别通过仓库下拉列表和粘贴仓库 URL 两种方式重试导入。

<div id="section-3">
  ## 其他来源
</div>

<div id="bitbucket">
  ### Bitbucket
</div>

* 粘贴 Bitbucket 仓库 URL，或连接您的 Bitbucket 账户以搜索仓库。
* 与 GitHub 托管的项目相比，导入时 Agent 支持可能有所限制。

<div id="section-4">
  ### 电子表格
</div>

* 上传 Excel(`.xlsx`) 或 CSV 文件，或粘贴公开的 Google Sheets URL。
* Agent 会读取电子表格结构，构建包含由数据初始化的数据库的全栈应用。
* 包含用于查看、搜索和管理记录的界面。

<div id="agent">
  ### 导入先前导出的 Agent
</div>

* 从 GitHub 仓库重新导入之前导出的 Agent App。
* Replit 会保留 Agent 专用结构 (代码、数据库架构和后端功能) 。
* 不会导入数据库中的值和 Secret 值。

<div id="section-5">
  ### 空白项目
</div>

* 不使用 Agent、不选择框架，也不进行脚手架搭建，从零开始创建项目。
* 最适合希望完全掌控项目配置的高级用户。

<div id="section-6">
  ## 限制
</div>

* 不会迁移现有数据库中的数据。
* ZIP 上传文件大小限制为 200MB。
* 某些复杂或专有依赖项可能需要手动配置。
* 大型项目的处理时间可能更长。

<div id="section-7">
  ## 最佳实践
</div>

* 导入前请移除敏感凭据。
* 保持源项目结构整洁。
* 导入后确认依赖项和运行命令。
* 发布前测试核心流程。

<div id="section-8">
  ## 故障排查
</div>

如果导入失败，请先检查以下几个方面：

* **兼容性错误**：确认项目所需文件是否齐全、框架是否受支持。
* **访问错误**：检查仓库或来源的访问权限。
* **处理错误**：简化项目结构或缩减项目大小后重试。

如果问题仍未解决，请访问 [Replit Community Hub](https://replit.com/community) 或[联系支持团队](https://replit.com/support)。
