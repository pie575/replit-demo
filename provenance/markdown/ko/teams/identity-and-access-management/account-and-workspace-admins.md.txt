# 계정 관리자 및 워크스페이스 관리자

> 계정 관리자와 워크스페이스 관리자는 별개의 역할입니다. 계정 관리자는 청구와 계정 아래의 모든 워크스페이스를 관리하고, 워크스페이스 관리자는 자신이 속한 워크스페이스만 관리합니다.

<Info>
  **이 페이지는 Enterprise 플랜에만 적용됩니다.** 별도의 계정 관리자와 워크스페이스 관리자 역할은 Enterprise에서만 존재합니다.

  **Core** 및 **Pro** 플랜에서는 계정에 단일 **계정 관리자**(일반적으로 계정 소유자)가 있고 별도의 워크스페이스 관리자 역할이 없습니다. Core 또는 Pro를 사용 중이라면 [멤버 관리](/ko/teams/identity-and-access-management/managing-members)와 [역할, 그룹 및 액세스](/ko/teams/identity-and-access-management/groups-and-permissions)를 대신 참조하세요 — 거기서 설명된 **Admin** 역할이 계정 관리자입니다.
</Info>

Enterprise 플랜에서 Replit은 관리 책임을 두 가지 별개의 역할로 분리합니다: **계정 관리자**와 **워크스페이스 관리자**. 역할을 분리하면 청구와 계정 전체 제어권을 넘기지 않고도 특정 워크스페이스에 대한 완전한 제어권을 누군가에게 줄 수 있습니다. 이 페이지에서는 각 역할이 하는 것, 차이점, 설정 방법을 설명합니다.

## 두 역할의 관계

Replit **계정**은 구독, 시트, 하나 이상의 **워크스페이스**(조직)를 소유하는 청구 엔티티입니다 — Enterprise 계정에는 두 개 이상이 있을 수 있습니다. 두 관리자 역할은 이 두 가지 범위에 매핑됩니다:

* **계정 관리자**는 전체 계정을 관장합니다. 청구를 제어하고 계정 아래의 모든 워크스페이스에 대한 관리자 액세스 권한을 갖습니다.
* **워크스페이스 관리자**는 자신이 속한 특정 워크스페이스(또는 워크스페이스들)만 관장합니다. 청구 액세스 권한이 없고 다른 워크스페이스를 제어할 수 없습니다.

모든 계정 관리자는 계정 아래의 모든 워크스페이스에서 자동으로 관리자가 되므로 계정 관리자는 사실상 워크스페이스 관리자의 상위 집합입니다. 워크스페이스 관리자는 계정 관리자가 아니며 청구나 다른 워크스페이스를 관리할 수 없습니다.

  <Card title="계정 관리자" icon="building-shield">
    계정 전체. 청구, 시트, 보안 설정, 계정 아래의 모든 워크스페이스를 관리합니다.
  </Card>

  </Card>

## 각 역할이 할 수 있는 것

두 역할 모두 워크스페이스를 관리합니다 — 차이는 *어떤* 워크스페이스를 관리하느냐입니다. 계정 관리자는 계정 아래의 모든 워크스페이스를 관리하고, 워크스페이스 관리자는 자신이 속한 워크스페이스만 관리합니다.

| 기능                             | 계정 관리자 | 워크스페이스 관리자 |
| ------------------------------ | :----: | :--------: |
| 자신이 관리하는 워크스페이스의 멤버 관리         |    예   |      예     |
| 자신이 관리하는 워크스페이스의 앱, 그룹, 리소스 관리 |    예   |      예     |
| 청구, 결제 방법, 청구서 보기 및 편집         |    예   |     아니오    |
| 구독 편집, 취소 또는 복원                |    예   |     아니오    |
| 시트 추가, 제거, 할당                  |    예   |     아니오    |
| 지출 및 사용 한도 설정                  |    예   |     아니오    |
| 새 워크스페이스 생성                    |    예   |     아니오    |
| 다른 계정 관리자 관리                   |    예   |     아니오    |
| 계정 아래의 모든 워크스페이스 관리            |    예   |     아니오    |
| SAML, SCIM, 감사 로그, 보안 연락처 설정   |    예   |     아니오    |

워크스페이스 관리자는 자신의 워크스페이스에 범위가 지정된 관리 권한을 갖고, 계정 관리자는 전체 계정에 걸쳐 모든 관리 권한을 갖습니다.

<Note>
  청구, 시트 관리, 구독 변경, 계정 전체 보안 제어는 계정 관리자가 필요합니다. 워크스페이스 관리자는 자신의 워크스페이스 내에서도 이러한 작업을 수행할 수 없습니다.
</Note>

## 계정 관리자 설정

계정 관리자는 설정의 **Seats** 탭에서 관리합니다. 계정 관리자를 추가하면 계정 전체 관리자 액세스가 부여되고 자동으로 계정 아래의 모든 워크스페이스에서 관리자가 됩니다.

### 멤버를 계정 관리자로 승격

<Steps>
  <Step title="Seats 탭 열기">
    설정에서 **Seats** 탭을 엽니다. 이 탭에는 계정의 구성원과 현재 역할이 나열됩니다.
  </Step>

  <Step title="멤버 승격">
    승격할 멤버를 찾아 작업 메뉴를 열고 **Promote to account admin**을 선택합니다. 변경 사항은 즉시 적용됩니다.
  </Step>
</Steps>

### 계정 관리자 강등

계정 관리자를 강등하면 계정 전체 및 청구 액세스가 제거됩니다. 기본적으로 강등해도 워크스페이스에서 제거되지 않습니다 — 계정 관리자 상태와 독립적으로 워크스페이스 액세스를 유지합니다.

<Steps>
  <Step title="Seats 탭 열기">
    설정에서 **Seats** 탭을 엽니다.
  </Step>

  <Step title="계정 관리자 강등">
    계정 관리자를 찾아 작업 메뉴를 열고 **Demote from account admin**을 선택합니다. 변경 사항은 즉시 적용됩니다.
  </Step>
</Steps>

계정이 관리자 액세스를 잃지 않도록 보호하는 몇 가지 규칙이 있습니다:

* 자기 자신을 강등할 수 없습니다.
* 마지막 계정 관리자를 제거할 수 없습니다. 계정에는 항상 최소 한 명이 있어야 합니다.
* 개인 계정의 소유자를 강등할 수 없습니다.

### SCIM으로 프로비저닝된 관리자

[SCIM](/ko/teams/identity-and-access-management/scim)으로 사용자를 프로비저닝하는 경우, ID 공급업체에서 **Admin** 역할을 할당받은 사용자는 **계정 관리자**가 됩니다. 워크스페이스 범위의 관리자를 만들려면 ID 공급업체가 아닌 Replit에서 **Workspace admin** 역할을 할당하세요.

## 워크스페이스 관리자 설정

계정 전체 또는 청구 액세스를 부여하지 않고 특정 워크스페이스에 대한 완전한 관리 제어권을 부여하려면 워크스페이스 관리자 역할을 할당합니다. 팀 리드가 구독이나 다른 팀을 관리하지 않고 자체 워크스페이스를 운영해야 할 때 유용합니다.

<Steps>
  <Step title="워크스페이스 멤버 목록 열기">
    관리자를 할당할 워크스페이스를 열고 **Members** 페이지로 이동합니다.
  </Step>

  <Step title="멤버 역할을 Workspace admin으로 설정">
    멤버를 찾아 역할 선택기를 열고 **Workspace admin**을 선택합니다. 멤버는 해당 워크스페이스에만 범위가 지정된 관리자 액세스를 얻습니다.
  </Step>
</Steps>

<Note>
  워크스페이스 관리자의 액세스는 자신이 속한 워크스페이스에서 멈춥니다. 청구 액세스, 시트 관리, 다른 워크스페이스 관리는 불가합니다 — 이러한 작업에는 계정 관리자가 필요합니다.
</Note>

## 올바른 역할 선택

* **계정 관리자**는 청구를 소유하거나, 구독과 시트를 관리하거나, 보안 설정을 구성하거나, 모든 워크스페이스를 감독해야 하는 사람에게 할당합니다.
* **워크스페이스 관리자**는 단일 팀 또는 워크스페이스를 운영하고 청구나 다른 워크스페이스를 건드리지 않고 멤버와 리소스를 관리해야 하는 사람에게 할당합니다.
