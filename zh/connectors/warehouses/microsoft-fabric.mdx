在 Replit 中构建 AI 驱动的应用，并直接发布到 Microsoft Fabric，内置企业级治理与安全能力。借助 Microsoft Fabric 集成，你可以将受治理的企业数据转化为仪表板、工作流、AI 应用等内部工具。团队从 prompt 到上线的速度更快，而身份验证与访问策略始终留在他们早已信赖的 Fabric 环境中。

<div id="what-a-fabric-data-app-is">
  ## 什么是 Fabric 数据应用
</div>

Fabric 数据应用是一个静态 React 应用，它通过针对 [Power BI 语义模型](https://learn.microsoft.com/en-us/power-bi/connect-data/service-datasets-understand)运行[数据分析表达式 (DAX) ](https://learn.microsoft.com/en-us/dax/)查询来渲染 Power BI 图表。它有以下几个特点，会影响你的构建方式：

* **以 Power BI 语义模型作为数据源。** 图表 由针对你所连接的语义模型 (数据集) 的 DAX 查询驱动。
* **设计上只读。** 应用通过 DAX `EVALUATE` 读取数据，不会回写到 Power BI。如果需要可写状态，请在仪表板之外单独使用一个应用数据库。
* **通过 Fabric 门户渲染。** 数据层运行在 Microsoft Fabric 门户内，由门户针对语义模型执行查询并将结果返回给应用。你的数据始终保留在 Fabric 环境中。
* **托管在 Microsoft 基础设施上。** 你可以将完成的数据应用发布到 Microsoft 托管服务，使其与 Fabric 环境中的其他部分一同运行。

<Note>
  Microsoft Fabric 数据应用需要访问包含 Power BI 语义模型的 Microsoft Fabric 租户；在预览期间，还需要拥有已获批测试者计划的会员资格。
</Note>

在幕后，[Rayfin](https://github.com/microsoft/rayfin) (一个用于构建应用 backend 的开源 SDK 和 CLI) 让 Agent 能够基于你的 Fabric 数据定义并发布可用于生产的应用。

整个过程都在同一个工作流中完成：描述应用，让 Agent 搭建脚手架，连接受治理的 Fabric 数据，然后发布并在你所在组织的 Fabric 租户内运行。

本指南介绍 builder 流程、应用如何连接 Fabric 数据，以及面向团队和自动化的选项。若要了解由其他数据仓库支持的通用数据仪表板，请参阅 [Data Visualization](/zh/features/artifact-types/data-apps)。

<div id="use-cases">
  ## 使用场景
</div>

对于已经深度投入 Microsoft 数据生态的组织来说，这是一条更快构建内部软件的路径。团队无需花费数周时间去拼接身份验证、API、部署工具和治理策略，只需描述需求，交给 Agent 来构建。

常见使用场景包括：

* 面向特定部门的效率工具
* 运营仪表板
* 数据探索工具
* 工作流自动化应用
* 报表界面

对于企业 IT 而言，治理、身份验证和安全性始终保留在组织已有的 Fabric 环境中，因此快速创建应用不会以牺牲集中管控为代价。

<div id="build-a-fabric-data-app">
  ## 构建 Fabric 数据应用
</div>

构建流程以对话形式进行。你始终在 Replit 中操作；需要进行身份验证或访问数据时，会通过 Microsoft 完成。

<Steps>
  <Step title="从 Fabric 模板开始">
    在 Replit 主页上，打开 **模板** 下拉菜单，然后在 **组织模板** 下选择 **Microsoft Fabric App**。这会让 Agent 进入数据应用工作流，并预加载 Fabric 工具。

    <Frame caption="在 Replit 主页上选择 Microsoft Fabric App 组织模板（私有预览界面）。">
      <img src="/assets/mirror/fabric-template-selector-d3f975e2e1d0.png" alt="Replit 主页上已打开模板下拉菜单，其中组织模板下的 Microsoft Fabric App 处于高亮状态" width="872" height="406" data-path="images/connectors/microsoft-fabric/fabric-template-selector.png" />
    </Frame>
  </Step>

  <Step title="描述你想要的仪表板">
    输入 prompt，描述要构建的仪表板或报表工具。例如：“根据我们的 Fabric 销售模型构建一个环比销售增长仪表板。”你无需编写 DAX，Agent 会生成查询。
  </Step>

  <Step title="使用 Microsoft 登录">
    出现提示时，使用拥有 Fabric 数据的租户通过 Microsoft OAuth 登录。这将授权 Agent 读取你有权访问的语义模型。你用于登录的身份必须有权访问要使用的 Fabric 工作区。
  </Step>

  <Step title="添加数据源">
    当 Agent 询问时，分享你想使用的 Power BI / Fabric 语义模型。你可以提供 Fabric 门户中的完整数据集 URL (例如，`https://app.powerbi.com/groups/<workspaceId>/datasets/<datasetId>/...`) ，也可以提供工作区 ID 以及数据集/项目 ID。Agent 会使用这些信息确定要查询的工作区和语义模型。

    该模型必须**发布到 Power BI 服务**，不能使用本地 `.pbix` 文件。

    <Frame caption="Agent 请求提供 Power BI / Fabric 语义模型链接（私有预览界面）。">
      <img src="/assets/mirror/fabric-agent-semantic-model-prompt-732ce9c4a29d.png" alt="Agent 面板要求构建者分享 Power BI 或 Fabric 语义模型，可提供完整的 Fabric 门户 URL，或工作区 ID 加数据集或项目 ID，并说明模型必须发布到 Power BI 服务，因此不能使用本地 .pbix 文件" width="1316" height="650" data-path="images/connectors/microsoft-fabric/fabric-agent-semantic-model-prompt.png" />
    </Frame>
  </Step>

  <Step title="让 Agent 构建并迭代">
    Agent 会分析语义模型的架构、编写 DAX 查询，并使用合适的图表构建仪表板。查看结果后，可使用自然语言请求修改，例如添加筛选器、更改图表类型或添加其他指标。
  </Step>

  <Step title="Publish（可选）">
    仪表板准备就绪后，你可以将其发布到 Microsoft 的托管服务，使其在 Fabric 环境中运行。发布相关内容将在其他文档中介绍；本指南重点说明如何连接数据并构建应用。
  </Step>
</Steps>

<div id="connecting-to-fabric-data">
  ## 连接到 Fabric 数据
</div>

要读取数据，App 需要与 Microsoft Fabric 建立经过授权的连接。Replit 可通过以下两种方式之一建立该连接。

<div id="app-level-fabric-sign-in-viewers">
  ### 应用级 Fabric 登录 (Viewer)
</div>

已发布数据应用的 Viewer 无需配置任何连接器。他们通过应用内嵌的 Microsoft Fabric 单点登录完成身份验证，应用则以其身份通过 Fabric 门户读取数据。这样，访问权限始终由你现有的 Fabric 权限来管控。

<div id="the-microsoft-fabric-connector-the-easy-path-for-builders">
  ### Microsoft Fabric 连接器 (面向构建者的便捷路径)
</div>

对构建者而言，**Microsoft Fabric 连接器** 是在开发过程中授权数据访问的便捷方式。它是可选的——只是一条便捷路径，而非必需项。

* 首位完成设置的构建者需与 Microsoft 完成**一次性 OAuth** 授权。
* **同一项目中**的其他协作者会**继承**该连接。
* **其他工作区** 需自行启用该连接器并完成各自的 OAuth 授权。
* 完成 OAuth 授权的身份必须拥有对目标 Fabric 工作区的访问权限。

该连接器使用 Microsoft Entra OAuth，且限定在你的租户范围内。你可以像管理其他 Replit 连接器一样，在项目的[集成](/zh/features/integrations/overview)页面中进行管理。若想了解更通用的连接器概念，请参阅[管理你的连接器](/zh/replitai/managing-connectors)。

<Note>
  在私有预览期间，Microsoft Fabric 连接器没有 Replit 托管的共享凭据。构建者需针对自己的 Microsoft Entra 租户进行授权。
</Note>

<div id="teams-and-automation">
  ## Teams 和自动化
</div>

对于团队共享使用或非交互式环境 (例如 CI) ，交互式 OAuth 并不总是可行。在这种情况下，请通过项目的 [Secrets](/zh/core-concepts/project-editor/app-setup/secrets) 提供**服务主体** token，而非进行交互式登录。App 会使用服务主体的身份读取 Fabric 数据。

这与机器对机器的配置最为接近：在 Microsoft Entra 中预配并获授 Fabric 工作区访问权限的非人类身份，可在无需人工参与的情况下对 App 进行身份验证。请确认服务主体可访问 App 要查询的工作区和语义模型。

<div id="troubleshooting">
  ## 故障排查
</div>

<AccordionGroup>
  <Accordion title="应用预览中数据无法加载">
    Fabric 数据层通过 Microsoft Fabric 门户运行。如果图表显示为空，或应用预览无法加载数据，请确认你已完成 Microsoft 登录，且所登录的身份有权访问你关联的工作区和语义模型。
  </Accordion>

  <Accordion title="Agent 找不到你的语义模型">
    请确保你粘贴的是来自 Fabric 门户的 Power BI 数据集链接，并且你的身份 (或服务主体) 对该工作区至少拥有读取权限。如果 Agent 提示无法解析工作区或模型，请重新共享数据集链接。
  </Accordion>

  <Accordion title="连接器卡住或反复提示连接">
    在项目的 [集成](/zh/features/integrations/overview) 页面重新授权 Microsoft Fabric 连接器，并确认完成 OAuth 授权的身份具有 Fabric 工作区访问权限。团队或 CI 场景下，建议使用通过 Secrets 提供的服务主体令牌。
  </Accordion>
</AccordionGroup>
