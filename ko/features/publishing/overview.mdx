게시 도구는 앱을 실제로 배포하고 웹에서 어떻게 실행되는지 관리하는 곳입니다. 앱의 웹 주소, 사용 권한, 프로덕션 데이터베이스, 모니터링, 보안, 그리고 호스팅 방식을 제어하는 설정을 하나의 패널에 모아서 제공합니다.

이 패널을 열려면 **Tools** 패널에서 **Replit Cloud** 아래의 **Publishing**을 선택하거나, Project Editor 우측 상단의 **Publish**를 선택하세요.

## 앱 게시하기

메인 패널은 앱을 게시하는 데 필요한 모든 항목을 안내합니다. 각 섹션을 검토한 다음 **Publish**를 선택하세요.

<Frame>
  <img src="/assets/mirror/publish-your-app-851815208b8a.png" alt="Domain 필드, 게시될 앱, 액세스 설정, 데이터베이스 설정, 모니터링, 보안, Publish 버튼 위에 표시되는 참여 유도 도구를 보여주는 Publish your app 패널" width="578" height="980" data-path="images/deployments/publish-pane/publish-your-app.png" />
</Frame>

* **Domain**: 앱의 웹 주소입니다. Replit이 `.replit.app` 이름을 제안하고 사용 가능한지 확인합니다. 게시 후에는 이 주소를 변경하거나 [커스텀 도메인](/ko/features/publishing/custom-domains)을 연결할 수 있습니다.
* **What you're publishing**: 게시될 앱의 미리보기와 사용될 URL을 보여줍니다.
* **Who can access your app**: **Public**, **Password protected**, **Workspace only**, **Invite only** 중에서 선택합니다. 비공개 옵션은 앱 사용을 워크스페이스 내부 또는 초대한 사용자나 그룹으로 제한합니다. [앱 액세스](/ko/features/publishing/private-deployments)에 대해 자세히 알아보세요.
* **Database settings**: 게시 시 앱의 프로덕션 데이터베이스가 생성되고 데이터로 채워지는 방식을 관리합니다. [프로덕션 데이터베이스](/ko/features/data-and-storage/development-and-production)에 대해 자세히 알아보세요.
* **Monitoring tools**: 앱 모니터링을 활성화하면 앱이 다운되었을 때 가장 먼저 알 수 있습니다. Replit은 앱이 온라인 상태인지 지속적으로 확인하고 문제가 발생하면 이메일로 알려드립니다. [앱 모니터링](/ko/features/publishing/monitoring-a-deployment)에 대해 자세히 알아보세요.
* **Security tools**: 게시 전에 심층 보안 스캔을 실행합니다. Security Agent는 AI와 최고 수준의 정적 분석 도구를 결합하여 프로젝트의 취약점을 확인합니다. [Project Security Center](/ko/features/security/project-security-center)에서 자세히 알아보세요.
* **Engagement tools**: 피드백 위젯을 활성화하면 게시된 앱의 모서리에 피드백 버튼이 추가됩니다. 인박스에서 제출된 피드백을 검토하고 수정을 위해 Agent에게 전달할 수 있습니다.

## 설정 조정하기

**Adjust settings**를 선택하면 앱이 호스팅되는 방식을 직접 구성할 수 있습니다. 대부분의 빌더는 이 설정을 변경할 필요가 없습니다. Replit이 합리적인 기본값을 선택해 줍니다.

<Frame>
  <img src="/assets/mirror/adjust-settings-d6e124b2249f.png" alt="배포 유형, 머신 구성, 배포 시크릿, 배포 지역, 그리고 심각한 취약점 게시 차단 토글을 보여주는 Adjust settings 섹션" width="574" height="794" data-path="images/deployments/publish-pane/adjust-settings.png" />
</Frame>

* **Deployment type**: 앱을 게시하는 데 사용되는 기술입니다. **Autoscale**은 트래픽이 없는 상태부터 어떤 수준의 수요에도 대응하도록 확장되므로 대부분의 앱에 권장됩니다. [배포 유형](/ko/features/publishing/deployment-types)을 비교해 보세요.
* **Machine configuration**: 앱을 실행하는 서버의 성능입니다. **Edit**을 선택하면 CPU, 메모리, 최대 머신 수를 변경할 수 있습니다. 패널에는 머신당 비용과 최대 트래픽 시의 비용이 표시됩니다. [머신 구성](/ko/features/publishing/machine-configuration)에 대해 자세히 알아보세요.
* **Deployment secrets**: 앱이 API 및 서비스에 액세스하는 데 사용하는 비공개 키입니다(API 키와 같은 민감한 값을 위한 안전하고 숨겨진 저장 공간). 시크릿은 개발 환경에서 게시된 앱으로 자동으로 동기화됩니다. [Secrets](/ko/core-concepts/project-editor/app-setup/secrets)에 대해 자세히 알아보세요.
* **Deployment geography**: 앱이 호스팅되는 위치입니다. 사용자와 더 가까운 리전을 선택하면 지연 시간이 줄어듭니다. 게시하면 앱과 관련 리소스가 해당 리전에 고정됩니다. 이후에 리전을 변경하려면 앱을 리믹스해야 합니다. [프로젝트 지역](/ko/features/publishing/project-geography)에 대해 자세히 알아보세요.
* **Block publishing of critical vulnerabilities**: Replit은 게시 전에 항상 보안 스캔을 실행합니다. 이 설정은 심각한 취약점이 발견되었을 때 게시를 차단할지 여부를 제어합니다. [Project Security Center](/ko/features/security/project-security-center)에서 자세히 알아보세요.
