В разделе [Добавление входа](/ru/ko/build/add-login) вы добавили вход в Velocity. Однако автомобили в списке и созданные клиентами бронирования исчезают при обновлении страницы — ведь они существуют только в браузере. Добавьте базу данных, чтобы всё сохранялось.

<div id="agent">
  ## Попросите Agent сохранять данные
</div>

Velocity использует Neon — управляемую Replit базу данных Postgres. Neon надёжно обрабатывает одновременные бронирования, масштабируется под реальный клиентский трафик, а Agent автоматически подготавливает отдельные окружения для разработки и продакшена. Вам не нужно регистрироваться в панели Neon или вставлять ключи.

<AiPrompt>
  Сохраняйте данные Velocity в базе данных, чтобы автомобили, доступность и бронирования не исчезали при обновлении страницы.<br />
  Используйте Neon (Postgres).<br />
  Сохраняйте: каждый автомобиль (производитель, модель, год выпуска, дневной тариф, фото, местоположение), календарь доступности каждого автомобиля, каждое бронирование (дата получения, дата возврата, автомобиль, клиент).<br />
  Свяжите каждое бронирование с вошедшим в систему клиентом, чтобы каждый видел только свои бронирования.<br />
  Не позволяйте бронировать один и тот же автомобиль дважды, если даты пересекаются.<br />
  Сообщите, что нужно протестировать после изменений.
</AiPrompt>

Agent подготавливает базу данных Neon, переносит список автомобилей и бронирования из данных в памяти в базу данных и добавляет проверку, чтобы один и тот же Lamborghini нельзя было забронировать дважды.

<div id="section">
  ## Проверьте, что всё сохраняется
</div>

1. Войдите в Velocity в Preview и забронируйте автомобиль на ближайшую субботу.
2. Обновите страницу. Бронирование должно остаться в разделе &quot;My bookings&quot;.
3. Перезапустите приложение через чат Agent. Список автомобилей и все бронирования должны сохраниться.
4. Попробуйте забронировать тот же автомобиль на ту же субботу из второй учётной записи. Velocity должен сообщить, что автомобиль недоступен, и предложить другую дату или автомобиль.
5. Выйдите из учётной записи и войдите снова. Бронирование должно остаться.

Если на каком-либо этапе бронирование исчезнет, снова сообщите Agent точные симптомы.

<AiPrompt>
  Я забронировал автомобиль в Velocity, но после обновления страницы бронирование исчезает.<br />
  Проверьте, сохраняется ли бронирование в базе данных или только на странице.<br />
  Исправьте минимальную проблему и расскажите, как это проверить.
</AiPrompt>

Также можно попросить Agent создать простой административный интерфейс для просмотра содержимого базы данных.

<AiPrompt>
  Создайте в Velocity простую административную страницу со списком всех автомобилей и бронирований из базы данных, сгруппированных по автомобилям.<br />
  Показывайте её только мне как владельцу проекта.
</AiPrompt>

<div id="url">
  ## Выполните деплой и проверьте приложение по публичному URL
</div>

Настройка Neon в Agent по умолчанию предоставляет Velocity отдельные окружения для разработки и продакшена. Повторно задеплойте Velocity через чат Agent или плитку Publishing, затем откройте публичный URL в новой вкладке. Replit автоматически подключит к задеплоенному приложению учетные данные Neon для продакшена — создайте бронирование по публичному URL, обновите страницу и убедитесь, что оно сохранилось.

Теперь Velocity запоминает все автомобили, доступные даты и бронирования. Они не исчезнут и после следующего обновления страницы.

<div id="section-3">
  ## Нужна дополнительная помощь?
</div>

* **Бронирования сохраняются в Preview, но не по публичному URL:** Попросите Agent проверить, подключены ли к задеплоенному приложению учетные данные продакшен Neon.
* **Сложно проверить данные:** Попросите Agent добавить простой административный интерфейс со всем содержимым базы данных.
* **Хотите заполнить список автомобилей начальными данными:** Попросите Agent добавить одноразовый скрипт для загрузки реальных автомобилей в базу данных.
* **Нужна база данных без настройки для быстрого прототипирования:** Вместо этого используйте [Replit Database](/ru/ko/features/data-and-storage/sql-database) — она встроена в каждый Repl и не требует отдельного выделения ресурсов.
