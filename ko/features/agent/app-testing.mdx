App Testing을 사용하면 Agent가 직접 만든 앱을 실제 브라우저에서 테스트할 수 있습니다. Agent는 실제 사용자처럼 애플리케이션을 돌아다니며 이곳저곳 클릭하고 기능이 제대로 동작하는지 확인합니다. 이러한 자체 테스트 기능 덕분에 앱이 올바르게 작동하는지 확인할 수 있고, Agent가 문제를 자동으로 찾아 수정할 수 있습니다.

</div>

App Testing을 활성화하면 Agent는 테스트가 필요할 만큼 변경 사항이 쌓였다고 판단할 때마다 주기적으로 스스로 테스트를 실행합니다. 모든 사용자 메시지마다 테스트하는 것이 아니라, 테스트가 가장 효과적인 시점을 지능적으로 판단합니다.

<Note>
  현재 App Testing은 풀스택 JavaScript 및 Streamlit Python web app에서 사용할 수 있습니다.
</Note>

<div id="key-benefits">
  ### 주요 이점
</div>

* **자율성 확장**: Agent가 사람의 개입 없이 더 오랜 시간 동안 작업할 수 있습니다
* **높은 품질**: 문제를 조기에 발견하고 해결해 오류가 적은 앱을 만듭니다
* **비용 효율성**: 개발 단계에서 문제를 잡아내 별도의 디버깅 세션이 필요 없도록 합니다
* **인터랙티브 검토**: video replay와 구간별 탐색 기능을 제공해 결과를 꼼꼼하게 분석할 수 있습니다

<div id="the-testing-process">
  ### 테스트 진행 과정
</div>

Agent가 스스로 테스트하기로 결정하면 다음과 같이 진행됩니다.

1. **브라우저 Preview**: Agent pane 안에 브라우저 Preview가 표시됩니다
2. **시각적 테스트**: Agent의 커서가 앱 곳곳을 클릭하며 기능을 테스트하는 모습을 볼 수 있습니다
3. **실제 사용자 시뮬레이션**: Agent가 실제 사용자처럼 애플리케이션을 둘러보며, 필요한 경우 가상 데이터를 입력합니다
4. **자동 분석**: Agent가 테스트 결과를 분석해 문제점을 찾아냅니다
5. **자체 수정**: Agent가 테스트 요약을 알려주고, 발견된 문제를 자동으로 수정합니다

<div id="key-capabilities">
  ## 주요 기능
</div>

Agent는 실제 사용자처럼 애플리케이션을 탐색하며 지능적으로 테스트하고, 다음 항목을 다룹니다.

* **사용자 인터페이스 검증**: 버튼, 양식, 내비게이션 및 시각적 요소
* **기능 확인**: 핵심 기능과 사용자 workflows
* **integration 테스트**: API 호출, database 상호작용 및 서드파티 서비스
* **성능 및 accessibility**: 로딩 시간, 응답성, accessibility 표준

<div id="usage">
  ## Usage
</div>

App Testing은 채팅 입력창의 Agent settings 드롭다운 안 **Advanced settings**에서 찾을 수 있습니다. Economy 또는 Power 모드를 사용할 때 켜 주세요. Lite 모드에서는 App Testing이 항상 꺼져 있습니다.

<Note>
  App Testing은 내장 코드 리뷰와 함께 Agent의 자율 기능 중 하나입니다. 다른 [Agent
  기능](/ko/features/agent/overview)도 자세히 알아보세요.
</Note>

<div id="take-over">
  ## Take over
</div>

테스트 도중 Agent가 스스로 해결할 수 없어 여러분의 도움이 필요한 상황에 부딪히는 경우가 있습니다. 가장 흔한 사례는 사용자 계정(예: Gmail) 로그인입니다. 이럴 때 Agent는 &quot;Begin take over&quot; 버튼을 띄웁니다.

  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="오류와 CAPTCHA 처리 방법에 대한 안내와 함께 Skip 및 Begin take over 버튼이 표시된 App Testing 제어권 인계 인터페이스" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

&quot;Begin take over&quot;를 누르면 테스트 preview를 직접 클릭해 필요한 단계를 완료한 뒤, Agent가 이어서 진행하도록 할 수 있습니다. &quot;Skip&quot;을 눌러 제어권 인계를 건너뛸 수도 있는데, 여러분의 도움 없이는 Agent가 진행할 수 없는 경우 App Testing이 종료됩니다. 10분 이내에 응답하지 않으면 Agent는 &quot;Skip&quot;을 누른 것으로 간주하고 진행합니다.

<div id="what-to-expect">
  ### 예상되는 동작
</div>

* **건너뛰기 옵션**: 필요한 경우 건너뛰기 버튼으로 테스트를 생략하고 개발을 계속 진행할 수 있습니다
* **대화형 video replay**: 테스트가 끝난 후 영상을 클릭하면 전체 testing 세션을 다시 재생할 수 있습니다
* **구간 이동**: 하단의 슬라이더를 사용해 테스트의 특정 구간으로 바로 이동할 수 있습니다

<div id="troubleshooting">
  ## 문제 해결
</div>

**테스트가 예기치 않게 실패하는 경우**

* 테스트를 건너뛴 후 다시 prompt를 입력해 실행해 보세요
* 테스트 타이밍에 영향을 줄 수 있는 동적 콘텐츠가 있는지 확인하세요
* 테스트 시나리오가 정확한지 검토하세요

**테스트 범위가 누락된 경우**

* 앱 기능을 더 자세히 설명해 주세요
* 반드시 테스트해야 하는 핵심 사용자 flow를 명확히 언급하세요

**App Testing이 전혀 작동하지 않나요?**

* 현재 App Testing은 web app[*](#how-app-testing-works)에서만 작동합니다

<div id="pricing-and-usage">
  ## 요금 및 사용량
</div>

App Testing은 Agent의 effort-based pricing 모델에 포함되며, 비용 측면에서 다음 사항을 고려해야 합니다:

* **사용량 기반**: 테스트는 소요된 Effort에 따라 요금이 부과됩니다(테스트가 단순할수록 비용이 낮아집니다)
* **비용 대비 효과**: 테스트에도 비용이 들지만, 오류를 일찍 발견해 추가 prompt와 Agent의 부가 작업을 줄임으로써 오히려 비용을 아낄 수 있습니다
* **효율적인 Development**: 자동화된 방식이므로 수동 디버깅과 재작업이 줄어듭니다

<Tip>
  **비용 효율적인 테스트**: App Testing은 usage 비용을 늘리지만, 테스트 단계에서 잡을 수 있었던 issues를 나중에 고치려고 Agent 세션을 추가로 사용하는 일을 막아 주므로 전체적으로는 비용을 아끼는 경우가 많습니다.
</Tip>

<div id="next-steps">
  ## 다음 단계
</div>

프로젝트에 App Testing을 사용할 준비가 되셨나요?

1. **빌드 시작**: Agent로 앱을 만들면 테스트가 자동으로 활성화됩니다
2. **결과 검토**: 테스트 보고서를 살펴보고 제안된 개선 사항을 적용하세요
3. **반복 개선**: 테스트 피드백을 활용해 애플리케이션을 다듬으세요
4. **확장**: 더 크고 복잡한 프로젝트에도 App Testing을 적용하세요
