Un **projet** est le conteneur de tout ce que vous créez sur Replit. Les **artefacts** sont les résultats publiables qu&#39;il contient : applications web, applications mobiles, présentations, animations, visualisations de données, jeux 3D et designs.

Lorsque vous créez plusieurs éléments, deux options s&#39;offrent à vous : ajouter plusieurs artefacts à un même projet ou créer des projets distincts. Le bon choix dépend du fait que vos applications partagent ou non des données, une logique et un même cycle de vie de déploiement. Cette page détaille ces deux notions et indique quand regrouper des artefacts dans un seul projet plutôt que de créer des projets séparés.

<div id="o-que-um-projeto">
  ## Qu’est-ce qu’un projet ?
</div>

Un projet est l’espace qui regroupe votre code, vos données et tous les artefacts que vous créez. Lorsque vous indiquez à Agent ce que vous souhaitez, il configure un projet et y crée les artefacts.

Considérez un projet comme un espace de travail sur votre bureau. Tout reste au même endroit et peut partager les mêmes informations, mais chaque élément a un rôle différent.

Par exemple, si vous demandez à Agent de créer une application de suivi de l’activité physique, il crée un projet avec un artefact d’application mobile, ainsi que le backend, la base de données et le stockage nécessaires à son fonctionnement.

Concepts clés :

* **Projet** : L’espace qui regroupe tout — votre code, vos données et tous vos artefacts.
* **Artefact** : Un résultat publiable au sein d’un projet (une application web, un jeu de diapositives, une vidéo, etc.).
* **Ressources** : Chaque artefact a automatiquement accès à un backend, une base de données et un stockage de fichiers — sans configuration requise.

Pour découvrir tout ce que vous pouvez faire avec un projet — gérer, filtrer, épingler, trier — consultez [Projets](/fr/pt/features/projects-and-artifacts/projects).

<div id="o-que-um-artefato">
  ## Qu&#39;est-ce qu&#39;un artefact ?
</div>

Les artefacts sont les éléments que vous pouvez publier sur Replit. Chacun est une production complète et autonome qui reçoit sa propre URL partageable au moment de la publication.

Tout le reste dans votre projet — fichiers, images, CSV, code — vient alimenter vos artefacts, mais ne peut pas être publié de façon indépendante.

<div id="o-que-os-artefatos-compartilham-em-um-projeto">
  ## Ce que les artefacts partagent au sein d&#39;un projet
</div>

Lorsque les [artefacts](/fr/pt/features/projects-and-artifacts/artifacts) résident dans le même [projet](/fr/pt/features/projects-and-artifacts/projects), ils partagent automatiquement :

* **Base de données** : un artefact écrit des données, les autres les lisent instantanément.
* **Backend et API** : une logique serveur commune, sans code dupliqué.
* **Stockage de fichiers** : images, documents et fichiers téléversés accessibles depuis tous les artefacts.
* **Déploiement** : la publication déploie l&#39;ensemble en une seule fois, de façon synchronisée.

Vous n&#39;avez donc pas à configurer de connexions ni à dupliquer du code d&#39;un artefact à l&#39;autre. En revanche, vous ne pouvez pas publier un artefact sans publier les autres.

<div id="guia-rpido">
  ## Guide rapide
</div>

Voici les principaux scénarios à prendre en compte pour décider s’il vaut mieux ajouter des artefacts à un projet existant ou créer un projet distinct.

| **Utilisez plusieurs artefacts dans un projet**                                                         | **Utilisez des projets distincts**                                                  |
| ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Les apps partagent les mêmes données et le même backend                                                 | Les apps ne partagent ni la même logique ni les mêmes données sous-jacentes         |
| Vous voulez que tout soit déployé ensemble                                                              | Vous avez besoin de cycles de deployment indépendants                               |
| Les apps sont complémentaires (comme une app client et un panneau d’administration)                     | Ce sont des produits sans lien entre eux ou destinés à différents clients           |
| Vous voulez que les modifications apportées à un artefact se répercutent automatiquement sur les autres | Le projet est temporaire, comme une landing page de campagne ou un site d’événement |

<div id="exemplos">
  ## Exemples
</div>

<div id="mesmo-projeto-web-app-app-mvel-para-um-produto">
  ### Même projet : web app + app mobile pour un produit
</div>

Un restaurant crée une web app permettant aux clients de consulter le menu et une app mobile permettant à l&#39;équipe de gérer les commandes. Les deux se connectent à la même base de données regroupant les articles du menu, les commandes et les informations client.

**Pourquoi un seul projet :** les apps partagent les mêmes données et le même backend. Lorsqu&#39;un client passe une commande depuis la web app, l&#39;équipe la voit immédiatement dans l&#39;app mobile.

<div id="mesmo-projeto-app-painel-de-administrador-deck-de-pitch-para-investidores">
  ### Même projet : app + panneau d&#39;administration + pitch deck pour investisseurs
</div>

Une startup développe son produit principal, un panneau d&#39;administration interne pour gérer le contenu et une présentation de slides pour une levée de fonds — le tout dans un seul projet.

**Pourquoi un seul projet :** le panneau d&#39;administration gère les mêmes données que celles affichées par l&#39;app, et le pitch deck peut s&#39;appuyer sur les métriques en temps réel du backend partagé.

<div id="projetos-separados-dois-apps-de-clientes-no-relacionados">
  ### Projets distincts : deux apps de clients sans lien entre eux
</div>

Un freelance développe une boutique e-commerce pour un client et un système de réservation pour un autre.

**Pourquoi des projets distincts :** les apps ne partagent ni données ni logique. Chaque client a besoin d&#39;un deployment indépendant et vous ne voulez pas que les modifications apportées à l&#39;un affectent l&#39;autre.

<div id="projetos-separados-landing-page-de-campanha-ao-lado-de-um-produto-principal">
  ### Projets séparés : landing page de campagne à côté d&#39;un produit principal
</div>

Vous avez une app en production qui tourne toute l&#39;année et une landing page temporaire pour une campagne marketing.

**Pourquoi des projets séparés :** la page de campagne a son propre cycle de vie — vous allez la mettre en ligne, la laisser tourner quelques semaines, puis la retirer. La garder à part évite d&#39;encombrer votre produit principal et vous permet de la publier ou de la supprimer indépendamment.

<div id="perguntas-frequentes">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artefact vers un autre projet ?">
  Pas pour le moment. Si vous devez séparer un artefact, créez un nouveau [projet](/fr/pt/features/projects-and-artifacts/projects) et demandez à Agent de le recréer dans ce projet.
</Accordion>

<Accordion title="Y a-t-il une limite au nombre d’artefacts qu’un projet peut contenir ?">
  Un projet peut contenir au maximum 7 artefacts, avec une limite de **1 application mobile par projet**. Cette limite existe parce que les artefacts supplémentaires consomment davantage de mémoire, ce qui peut ralentir l’aperçu. Si vous avez besoin de plus d’artefacts, créez un autre [projet](/fr/pt/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artefact d’un projet ?">
  Pas pour le moment. La publication déploie l’ensemble. Si vous avez besoin de déploiements indépendants, utilisez des projets distincts.
</Accordion>

<Accordion title="Les artefacts partagent-ils des données entre eux ?">
  Oui. Tous les artefacts d’un projet partagent la même base de données et les mêmes services backend. Si votre web app écrit des données, votre application mobile et votre tableau de bord de données peuvent les lire immédiatement.
</Accordion>

<Accordion title="Quelle est la différence entre un artefact et un fichier ?">
  Les artefacts sont des éléments que vous pouvez publier — applications, diapositives, vidéos, etc. Les fichiers (comme les CSV, les images ou le code) sont des ressources de votre projet qui prennent en charge vos artefacts, mais ne peuvent pas être publiés seuls.
</Accordion>
