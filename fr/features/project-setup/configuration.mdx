Les Replit Apps se configurent au moyen de deux fichiers : `.replit` et `replit.nix`. Ils déterminent le comportement de votre Replit App, de l&#39;exécution du code aux outils de développement et aux langages.

Ces fichiers de configuration sont masqués par défaut. Pour les afficher dans votre Replit App, sélectionnez « Afficher les fichiers masqués » dans le menu de l&#39;arborescence des fichiers.

<div id="replitnix-file">
  ## Fichier `replit.nix`
</div>

Replit utilise `Nix` pour gérer les paquets et les environnements. Le fichier `replit.nix` sert à :

**Spécifier les dépendances système :** définissez précisément les paquets logiciels requis par votre Replit App, gérés via Nix, un gestionnaire de paquets.

**Créer des environnements reproductibles :** garantissez la cohérence et la reproductibilité de votre environnement de développement, idéal pour les projets collaboratifs et les tests sur plusieurs systèmes.

Vous pouvez gérer les paquets Nix de façon visuelle avec l&#39;outil `Dependencies`. Pour en savoir plus, consultez le guide [Dépendances système](/fr/features/project-setup/dependency-management#system-dependencies).

Pour configurer des paquets avec le fichier `replit.nix`, listez les [paquets Nix](https://search.nixos.org/packages) souhaités dans le tableau `deps`, en les préfixant par `pkgs.`. Toute modification sera synchronisée après le rechargement de votre Shell.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="replit-file">
  ## Fichier `.replit`
</div>

Le fichier `.replit` contrôle le comportement de votre Replit App. Il utilise le [format de configuration](https://toml.io/en/) `toml`. Voici quelques-uns des principaux aspects configurables :

**Commande Run :** spécifiez la commande qui s&#39;exécute lorsque vous sélectionnez le bouton Run. Chaque modèle dispose d&#39;une commande Run par défaut permettant de lancer le code immédiatement. Pour des apps plus complexes et personnalisées, utilisez les [Workflows](/fr/features/workspace-tools/workflows).

**Language Server Protocol (LSP)** : fournit des fonctionnalités telles que l&#39;autocomplétion, la navigation dans le code, la coloration syntaxique, ainsi que l&#39;analyse et la détection d&#39;erreurs en temps réel.

**Variables d&#39;environnement :** définissez et gérez les variables d&#39;environnement indispensables au bon fonctionnement de vos applications.

**Dépendances et paquets :** gérez les installations et les configurations de paquets directement depuis le fichier `.replit`, afin que votre Replit App dispose de tous les outils nécessaires dès son démarrage. Vous pouvez également gérer les dépendances de manière visuelle grâce à l&#39;outil `Dependencies`. Pour en savoir plus, consultez le guide [System Modules](/fr/features/project-setup/dependency-management#advanced-configuration).

Pour les applications Python, le fichier `.replit` par défaut ressemble à ceci :

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

| **Clé de configuration**                        | **Valeur/Exemple**                     | **Description**                                                                                                                                                                                                                               |
| ----------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a name="entrypoint" />`entrypoint`             | `main.py`                              | Indique le fichier principal à exécuter et à afficher par défaut à l&#39;ouverture de l&#39;éditeur. Vous pouvez renommer ce fichier selon votre application.                                                                                 |
| <a name="modules" />`modules`                   | `["python-3.10:v18-20230807-322e88b"]` | Définit les versions spécifiques des langages de programmation ou d&#39;autres dépendances majeures prises en charge par Replit.                                                                                                              |
| <a name="nix" />`[nix]`                         |                                        | Définit les paramètres d&#39;utilisation de Nix, un gestionnaire de paquets, pour gérer les dépendances système. Consultez le document [Gestion des dépendances](/fr/features/project-setup/dependency-management) pour plus d&#39;informations. |
| <a name="channel" />`channel`                   | `stable-23_05`                         | Indique le canal Nix à utiliser, ce qui détermine les versions des dépendances système disponibles.                                                                                                                                           |
| <a name="packages" />`packages`                 | `["cowsay", "htop"]`                   | Indique les paquets Nix à installer. Pour un contrôle plus fin, vous pouvez également utiliser `replit.nix`.                                                                                                                                  |
| <a name="unitTest" />`[unitTest]`               |                                        | Configure les paramètres liés aux tests unitaires au sein de la Replit App.                                                                                                                                                                   |
| <a name="language" />`language`                 | `python3`                              | Indique le langage utilisé pour les tests unitaires, précisant ici que Python 3 sert à écrire les tests.                                                                                                                                      |
| <a name="gitHubImport" />`[gitHubImport]`       |                                        | Paramètres qui déterminent la façon dont les projets sont importés depuis GitHub, en particulier les fichiers qui doivent être inclus.                                                                                                        |
| <a name="requiredFiles" />`requiredFiles`       | `[".replit", "replit.nix"]`            | Liste les fichiers qui doivent être présents lors de l&#39;importation du projet pour garantir son bon fonctionnement.                                                                                                                        |
| <a name="deployment" />`[deployment]`           |                                        | Contient les paramètres de déploiement de l&#39;application depuis la Replit App vers un environnement en production.                                                                                                                         |

| <a name="deploymentTarget" />`deploymentTarget` | `cloudrun`                             | Indique la plateforme cible de déploiement pour l&#39;hébergement de l&#39;application.                                                                                                                                                       |

Maintenant que vous avez un aperçu des configurations par défaut du fichier `.replit`, consultez les sections suivantes pour découvrir comment configurer les paramètres de base et avancés de votre Replit App.

<div id="configuring-basic-settings">
  ## Configuration des paramètres de base
</div>

<div id="entrypoint">
  ### Entrypoint
</div>

Il s&#39;agit du fichier principal de votre projet. Si vous ne définissez pas de propriété `run`, `entrypoint` désigne le fichier exécuté par le runtime.

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="run-command">
  ### Commande `Run`
</div>

La propriété `run` du fichier `.replit` est une fonctionnalité essentielle qui détermine la commande initiale, ou la série de commandes, exécutée lorsque vous sélectionnez le bouton `Run` dans un environnement Replit. La commande `Run` peut être spécifiée soit sous forme de chaîne représentant la commande à exécuter, soit sous forme de tableau de chaînes représentant la commande et chacun de ses arguments.

Quelques manières courantes de configurer la commande `Run` :

* **Commande unique :**
  Cet exemple montre comment transmettre une seule commande à exécuter directement dans la Replit App. Avec ceci dans votre fichier `.replit`, un clic sur le bouton `Run` affiche un message d&#39;accueil dans le volet `Console` :
  **Exemple :** `run = "echo 'Hello, Replit!'"`

* **Arguments explicites :**
  Dans certains cas, il peut être préférable d&#39;être plus explicite, afin d&#39;éviter d&#39;avoir à gérer l&#39;analyse des guillemets ou les règles d&#39;interpolation du Shell. Vous pouvez réécrire l&#39;exemple ci-dessus en séparant les arguments.
  Notez que `'` et `"` ne sont plus tous deux nécessaires, puisque vous transmettez explicitement le message d&#39;accueil comme premier et unique argument de `echo` :
  **Exemple :** `run = ["echo", "Hello, Replit!"]`

* **Commandes multiples :**
  Cet exemple montre comment exécuter plusieurs processus simultanément, par exemple un frontend et un backend. C&#39;est utile si vous développez un backend en python et un frontend en typescript, où chaque serveur écoute sur un port différent :
  **Exemple :** `run = "python -m app & npm run start & wait"`

<div id="process-management">
  #### Gestion des processus
</div>

Bien que plusieurs commandes puissent être exécutées simultanément avec `&`, vous souhaiterez peut-être distinguer plus facilement les journaux des différents services. Vous pouvez [ajouter des dépendances système](/fr/features/project-setup/dependency-management#system-dependencies) telles que [`process-compose`](https://github.com/F1bonacc1/process-compose) pour mieux orchestrer plusieurs processus.

<div id="build-phase">
  #### Phase `Build`
</div>

Pour certains langages ou environnements d&#39;exécution, une phase de compilation distincte est nécessaire avant de pouvoir exécuter (`run`) le code. Cela concerne aussi bien les langages compilés comme TypeScript, Golang ou Java que la possibilité d&#39;utiliser un paramètre pour réinitialiser votre environnement, vos données ou votre configuration avant le prochain `run`.

* **Compilation :**
  Dans un dépôt TypeScript, vous devrez peut-être exécuter `tsc` avant de lancer votre code.
  **Exemple :**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="including-environment-variables">
  #### Inclure des variables d&#39;environnement
</div>

Pour transmettre des variables d&#39;environnement à votre service avant son exécution, vous pouvez développer la propriété `run` sous forme de [table](https://toml.io/en/v1.0.0#table).

Il s&#39;agit d&#39;une modification plus conséquente, qui nécessite probablement de déplacer la propriété `run = "..."` dans votre fichier `.replit`.

Le diff suivant montre comment transmettre la commande via l&#39;argument `args` de `[run]`, ainsi que la variable `NAME` définie dans `[run.env]` :

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# Nous devons déplacer notre nouveau [run] sous toutes les
+# propriétés de premier niveau qui ne commencent pas par un `[` !
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="interactivity">
  #### Interactivité
</div>

Les programmes interactifs peuvent également être lancés depuis le bouton `Run`, ce qui permet de distinguer votre environnement de développement du terminal dans lequel s&#39;exécute votre programme.
Prenons l&#39;exemple du script de comptage suivant :

**Exemple**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="advanced-configuration-options">
  ## Options de configuration avancées
</div>

Découvrez les options de configuration détaillées disponibles pour votre Replit App. Vous pouvez personnaliser votre environnement de développement, gérer les commandes d&#39;exécution, intégrer des services de langage et gérer les dépendances.

| **Configuration** | **Clé**                             | **Valeur/Exemple**                          | **Description**                                                                              |
| ----------------- | ----------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------- |
| onBoot            | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Commande exécutée au démarrage de la Replit App.                                             |
| compile           | <a name="compile" />`compile`       | (Aucun exemple par défaut)                  | Commande exécutée avant la commande `run`, utilisée pour les langages compilés comme le C++. |
| language          | <a name="language" />`language`     | `language = "javascript"`                   | Indique le langage lors d&#39;un import GitHub ou de la création d&#39;une Replit App.       |
| entrypoint        | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | Fichier principal à exécuter et à afficher à l&#39;ouverture de l&#39;éditeur.               |
| hidden            | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | Fichiers ou dossiers masqués par défaut dans l&#39;arborescence latérale des fichiers.       |
| audio             | <a name="audio" />`audio`           | `audio = true`                              | Active l&#39;audio système lorsque la valeur est `true`.                                     |

<div id="notes-about-system-wide-audio">
  ### Remarques sur l&#39;audio système
</div>

Lorsque vous définissez `audio = true` dans votre fichier `.replit`, il peut être nécessaire de redémarrer l&#39;environnement de développement. Ouvrez la palette de commandes avec `Cmd+K` (Mac) ou `Ctrl+K` (Windows), recherchez **Restart compute**, puis sélectionnez cette option.

Lorsque vous exécutez une application graphique, une icône de casque audio accompagnée d&#39;une case à cocher apparaît en bas à droite du volet `Output`.
En raison des restrictions du navigateur, vous devrez l&#39;activer à chaque actualisation de la page.

```toml theme={null}
# Veillez à placer cette ligne en haut de votre fichier `.replit`, en dehors de toute section entre crochets `[`
audio = true
```

<div id="packager-configuration">
  ## Configuration du packager
</div>

| **Configuration** | **Clé**                                           | **Valeur/Exemple**                            | **Description**                                                                                            |
| ----------------- | ------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| packager          | <a name="language" />`language`                   | `packager.language = "python3"`               | Langage utilisé pour les opérations sur les paquets.                                                       |
| packager features | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Détecte automatiquement les paquets à installer avant l&#39;exécution de la Replit App.                    |
| packager features | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | Active la prise en charge du packager lorsque la valeur est `true`.                                        |
| packager features | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Définit si l&#39;hébergement de la Replit App nécessite l&#39;exécution d&#39;une installation de paquets. |
| packager          | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | Commande exécutée après l&#39;installation d&#39;un nouveau paquet via le packager.                        |
| packager          | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | Chemins à ignorer lors de la détection automatique des paquets.                                            |
| packager          | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | Modules pour lesquels aucune détection de paquet ne doit être tentée lors de l&#39;installation.           |

<div id="example-replit-configuration-for-packager-configuration">
  ### Exemple de fichier `.replit` pour la configuration du packager
</div>

```toml theme={null}
# Définir le langage de la Replit App
packager.language = "python3"

# Activer les fonctionnalités de gestion automatique des paquets
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# Commande à exécuter après chaque installation de paquet
packager.afterInstall = "echo 'Package installed successfully'"

# Définir les chemins et les paquets à ignorer par le gestionnaire de paquets
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# Paramètres de déploiement supplémentaires
[deployment]
run = ["python3", "app.py"]
```

<div id="deployment-configuration">
  ## Configuration du deployment
</div>

| **Configuration** | **Clé**                               | **Valeur/Exemple**                   | **Description**                                                                      |
| ----------------- | ------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------ |
| deployment        | <a name="run" />`run`                 | `deployment.run = "npm start"`       | Commande exécutée au démarrage d&#39;un conteneur de Deployment.                     |
| deployment        | <a name="build" />`build`             | `deployment.build = "npm run build"` | Commande exécutée avant le lancement d&#39;un Deployment.                            |
| deployment        | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | Si `true`, la réussite du deployment n&#39;exige pas de vérification de port ouvert. |

<div id="example-replit-configuration-for-deployment-configuration">
  ### Exemple de fichier `.replit` pour la configuration du deployment
</div>

```toml theme={null}

# Spécifie le point d'entrée principal du projet
entrypoint = "app.js"

# Paramètres de configuration pour le déploiement de l'application
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  **La configuration de l&#39;interpréteur** est obsolète et n&#39;est plus disponible dans Replit. Nous vous invitons plutôt à utiliser les commandes `Run` pour définir la manière dont les scripts et les applications s&#39;exécutent dans l&#39;environnement de votre Replit App.
</Note>


<div id="accessing-replit-app-environment-metadata">
  ## Accéder aux métadonnées d&#39;environnement d&#39;une Replit App
</div>

<div id="nodejs">
  ### Node.js
</div>

Pour accéder à toutes les variables d&#39;environnement :

`console.log(process.env);`

Pour accéder à une seule variable (REPL&#95;SLUG) :

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

Pour accéder à toutes les variables d&#39;environnement :

```python theme={null}
import os
print(os.environ)
```

Pour accéder à une seule variable (REPL&#95;SLUG) :

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

Pour accéder à toutes les variables d&#39;environnement :

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

Pour accéder à une seule variable (REPL&#95;SLUG) :

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```
