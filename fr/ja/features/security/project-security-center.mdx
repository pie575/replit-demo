Le Centre de sécurité du projet centralise la détection et la correction des vulnérabilités de sécurité et de confidentialité de votre Replit App. Sélectionnez **Security Center** dans le volet **Tools** de votre projet pour lancer des analyses, examiner les résultats et transmettre à l&#39;Agent les problèmes que vous avez validés sous forme de demandes de correction.

<Note>
  Si vous débutez avec la sécurité des dépendances, consultez les [concepts de sécurité](/fr/ja/features/security/concepts) pour les définitions de CVE, SBOM, exposition, correction par l&#39;Agent, republication et Auto-Protect.
</Note>

<div id="section-2">
  ## Analyse automatique des dépendances
</div>

L&#39;analyse automatique des dépendances compare les paquets de votre projet aux enregistrements de vulnérabilités publiés. Ces analyses sont gratuites et s&#39;exécutent automatiquement. Lorsqu&#39;une nouvelle entrée CVE (Common Vulnerabilities and Exposures) est publiée, Replit la confronte aux dépendances de votre projet et affiche les correspondances dans le volet **Security**, sans nouvelle analyse manuelle.

L&#39;analyse des dépendances prend en charge Node.js/npm, Python, Go, Rust, PHP et Ruby.

La correction automatique des dépendances se limite actuellement à Node.js/npm.

<div id="auto-protect">
  ### Auto-Protect
</div>

Auto-Protect étend l&#39;analyse automatique des dépendances. Lorsqu&#39;une vulnérabilité correspondante est détectée, Agent prépare et teste un correctif, puis vous envoie un e-mail contenant un lien direct. Le correctif reste en attente de revue dans le volet **Security**. Une fois appliqué, republiez votre app afin que le correctif soit intégré à la version de production.

Auto-Protect ne couvre que les CVE des dépendances. Pour analyser le code de votre application, utilisez les [analyses de sécurité Agent](/fr/ja/features/security/agent-security-scans).

Les deux paramètres d&#39;Auto-Protect sont désactivés par défaut :

<Steps>
  <Step title="Activer la préparation des correctifs">
    Un administrateur du workspace accède à **Settings** &gt; **Account** &gt; **Advanced**, puis
    sélectionne la gravité minimale (faible, moyenne, élevée ou critique) pour laquelle
    Replit doit préparer des correctifs.
  </Step>

  <Step title="Activer les e-mails de sécurité">
    Accédez à **Settings** &gt; **Personalization** &gt; **Email Notifications**, puis
    sélectionnez la gravité minimale pour laquelle vous souhaitez être notifié.
  </Step>
</Steps>

Pour chaque nouvelle vulnérabilité, Replit envoie au maximum un e-mail par workspace, récapitulant l&#39;ensemble des projets concernés. Sélectionnez **Go to Task** pour examiner le correctif préparé par Agent avant de l&#39;appliquer. Une fois le correctif appliqué, la vulnérabilité reste signalée comme **en attente de republication** jusqu&#39;à ce que vous publiiez une nouvelle version.

<Note>
  Les correctifs préparés par Agent sont facturés comme tout autre travail d&#39;Agent, même lorsqu&#39;ils sont préparés de manière proactive par Auto-Protect.
</Note>

<div id="section-3">
  ## Examiner les résultats de détection
</div>

Les résultats de sécurité s&#39;affichent dans le volet **Security**, regroupés par niveau de gravité :

| Gravité       | Recommandations                                                   |
| ------------- | ----------------------------------------------------------------- |
| Critique      | Risques immédiats à traiter avant la publication                  |
| Élevée        | Problèmes graves pouvant être exploités dans certaines conditions |
| Moyenne       | Risques potentiels peu susceptibles d&#39;être exploités          |
| Faible / Info | Problèmes mineurs ou recommandations de bonnes pratiques          |

Examinez chaque résultat avant de l&#39;approuver, de le corriger ou de le rejeter. Envoyez les problèmes approuvés à Agent sous forme de demandes de correction, puis relancez l&#39;analyse concernée une fois les correctifs appliqués.

<div id="section-4">
  ## Contrôles de sécurité pendant le développement et lors de la publication
</div>

<div id="section-5">
  ### Analyse de sécurité pendant la création
</div>

Lorsque vous créez une application avec Agent, Replit analyse automatiquement les fichiers modifiés par Agent afin d&#39;y détecter les schémas non sécurisés courants et les informations sensibles codées en dur. Il s&#39;agit d&#39;une vérification légère effectuée en amont dans le flux de travail d&#39;Agent, et non d&#39;une revue complète de la base de code. Ces résultats n&#39;apparaissent pas sous forme de rapport distinct dans le volet **Security**.

<div id="section-6">
  ### Vérifications à la publication
</div>

Replit exécute également une analyse de sécurité avant la publication. Le paramètre **Block publishing of critical vulnerabilities** détermine ce qui se passe lorsque l&#39;analyse détecte un problème critique :

* **Activé** : la publication est bloquée jusqu&#39;à ce que le problème soit résolu ou ignoré.
* **Désactivé** : la publication se poursuit et les résultats restent affichés pour examen.

Les organisations Enterprise peuvent rendre ce paramètre obligatoire pour toutes les apps.

Ces vérifications ne remplacent pas les [analyses de sécurité Agent](/fr/ja/features/security/agent-security-scans) complètes ni les [analyses Level 3](/fr/ja/features/security/black-box-pen-tests) : elles les complètent.
