<div id="adicionar-cabealhos-de-resposta">
  ## Добавление заголовков ответа
</div>

Пользовательские **заголовки ответа** позволяют добавлять HTTP-заголовки к запросам, которые соответствуют определённым путям.
Заголовок ответа — это пара «имя — значение», которая сообщает браузеру, как
работать с запрошенным содержимым.

Например, вы можете указать заголовок `Access-Control-Allow-Origin`, чтобы определить, к каким доменам браузер может обращаться для этой страницы.
Чтобы создать такую запись, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

Этот заголовок ответа включает следующие параметры:

* **path**: шаблон пути URL, которому соответствуют запрашиваемые ресурсы
* **name**: имя HTTP-заголовка
* **value**: значение HTTP-заголовка

В файл `.replit` можно добавить несколько записей `deployment.responseHeaders`.

Чтобы изменения конфигурации вступили в силу, опубликуйте ваше Replit App заново.

<div id="criar-uma-pgina-404-personalizada">
  ## Создание собственной страницы 404
</div>

Собственная страница 404 отображается, когда пользователи запрашивают URL-пути, которым не соответствует ни один файл или правило в вашем опубликованном приложении.

Чтобы добавить собственную страницу 404, поместите её содержимое в файл `404.html` в корневом каталоге вашего Replit App.

При переходе по несуществующему URL-пути пользователи увидят отрендеренный HTML вашей страницы 404.

<div id="definir-reescritas-de-caminho-de-url">
  ## Настройка перезаписи путей URL
</div>

Вы можете настроить перезапись URL, чтобы изменять путь URL запроса до того, как его обработает ваш Replit App.
Исходный URL остаётся видимым в браузере, но сервер загружает ресурс, указанный в правиле перезаписи.

Например, вы можете указать, что для всех запросов, начинающихся с `/app`, загружается содержимое файла `/app/index.html`.
Чтобы создать такую запись, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**: шаблон пути URL, которому соответствуют запрашиваемые ресурсы
* **to**: переписанный путь, указывающий на файл в вашем Static Deployment.

В файл `.replit` можно добавить несколько записей `deployment.rewrites`.
Сервер обрабатывает записи в указанном порядке и игнорирует дубликаты.

Чтобы изменения конфигурации вступили в силу, опубликуйте свой Replit App заново.

В следующих разделах описаны ограничения правил переписывания URL.

<div id="correspondncia-de-caminho">
  ### Сопоставление путей
</div>

К параметрам `from` и `to` в правилах перезаписи применяются следующие ограничения:

* Совпадение должно быть точным, если не указан символ `*`
* Символ `*` соответствует оставшейся части пути
* Символ `*` допустим только в конце пути
* Если вы указали `*` в параметре `from`, вы можете использовать его и в параметре `to`, чтобы подставить совпавшую часть пути

Например, если ваш файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

Когда пользователь обращается к пути `/v1/about-us.html`, правило перезаписи возвращает файл, расположенный по пути `/v2/about-us.html`.

<div id="sombreamento">
  ### Затенение
</div>

Затенение возникает, когда правило перезаписи совпадает с путём URL, которому также соответствует файл в вашем Static Deployment.
В этом случае облачный сервер игнорирует перезапись и отдаёт файл напрямую.

Например, предположим, что ваше опубликованное приложение содержит следующие файлы:

* `index.html`
* `about.html`

Файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

Когда пользователь заходит на `/register.html`, сервер переписывает запрос на `/index.html` и отдаёт этот файл.
Однако если пользователь откроет `/about.html`, сервер проигнорирует правило перезаписи и отдаст файл `about.html`, поскольку он существует в вашем Static Deployment.

<div id="restries-de-domnio">
  ### Ограничения домена
</div>

Правила перезаписи работают только для запросов к основному домену вашего Static Deployment и могут
перенаправлять только на файлы внутри этого Static Deployment.
