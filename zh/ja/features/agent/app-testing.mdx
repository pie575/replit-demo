借助应用测试，Agent 可以在真实浏览器中测试其构建的应用。Agent 会像真实用户一样在应用中浏览和点击，验证各项功能。借助这项自测功能，您可以确保应用正常运行，并让 Agent 自动发现和修复问题。

</div>

启用应用测试后，Agent 会在判断应用发生了足够多的更改时定期自测。Agent 不会在每条用户消息后都进行测试，而是会智能判断何时测试最有价值。

<Note>
  目前，应用测试适用于全栈 JavaScript 和 Streamlit Python Web 应用。
</Note>

<div id="section-2">
  ### 主要优势
</div>

* **更强的自主性**：Agent 无需人工干预即可长时间持续работа工作
* **更高的质量**：及早发现并解决问题，构建出缺陷更少的应用
* **成本效益**：在开发阶段就发现问题，避免额外的调试环节
* **交互式回顾**：提供视频回放和分段导航，便于深入分析结果

<div id="section-3">
  ### 测试流程
</div>

Agent 进行自测时的流程如下：

1. **浏览器预览**：Agent 面板中会显示浏览器预览
2. **可视化测试**：你可以看到 Agent 的光标在应用中点击，逐项测试功能
3. **真实用户模拟**：Agent 会像真实用户一样在应用中操作，并按需填入模拟数据
4. **自动分析**：Agent 会分析测试结果并定位问题
5. **自我修复**：Agent 会汇报测试结果摘要，并自动修复发现的问题

<div id="section-4">
  ## 主要功能
</div>

Agent 会像真实用户一样浏览应用并进行智能测试，涵盖以下方面：

* **用户界面验证**：按钮、表单、导航和视觉元素
* **功能验证**：核心功能与用户工作流
* **集成测试**：API 调用、数据库操作、第三方服务
* **性能与无障碍**：加载速度、响应性、无障碍标准

<div id="section-5">
  ## 使用方法
</div>

应用测试位于聊天输入框中 Agent 设置下拉菜单的**高级设置**内。使用 Economy 或 Power 模式时，请将其开启；在 Lite 模式下，应用测试将始终保持关闭。

<Note>
  应用测试与内置代码审查同属 Agent 的自主功能。了解更多 [Agent 功能](/zh/ja/features/agent/overview)。
</Note>

<div id="section-6">
  ## 接管
</div>

在测试过程中，Agent 有时会遇到需要你协助才能继续的阻碍。最常见的情况是需要登录用户账户 (例如 Gmail) 。遇到这种情况时，Agent 会弹出“开始接管”按钮。

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="应用测试的接管界面，显示“跳过”和“开始接管”按钮以及处理错误和 CAPTCHA 的操作步骤" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

按下“开始接管”后，你可以点击测试预览并完成所需步骤，让 Agent 继续执行。你也可以按“跳过”来跳过接管；如果 Agent 在没有你协助的情况下无法继续，应用测试将结束。若你在 10 分钟内未作响应，Agent 会视同你按下了“跳过”并继续执行。

<div id="section-7">
  ### 你可以期待什么
</div>

* **跳过选项**：可根据需要跳过测试，继续进行开发
* **交互式视频回放**：测试结束后，点击视频即可回看整个测试会话
* **分段导航**：使用底部的滑块跳转到测试的特定环节

<div id="section-8">
  ## 故障排查
</div>

**测试意外失败**

* 尝试跳过该测试，然后重新输入提示词再测试一次
* 检查是否有动态内容影响了测试时序
* 重新检查测试场景是否准确

**测试覆盖率不足**

* 提供更详细的应用功能说明
* 明确指出需要测试的关键用户流程

**应用测试完全无法运行**

* 应用测试目前仅支持 Web 应用[*](#アプリテストの仕組み)

<div id="section-9">
  ## 价格与用量
</div>

应用测试已纳入 Agent 的按工作量计费模式，其中有几项重要的成本考量：

* **按用量计费**：测试根据所花费的工作量收费 (测试越简单，费用越低)
* **权衡成本与收益**：测试虽会产生成本，但尽早发现问题可以省去额外的提示词和 Agent 的多余工作，从而节省开支
* **高效开发**：自动化方式减少了手动调试和返工

<Tip>
  **高性价比的测试**：应用测试会增加使用成本，但它能避免你为修复本可通过测试发现的问题而额外开启 Agent 会话，因此整体上往往更省钱。
</Tip>

<div id="section-10">
  ## 后续步骤
</div>

准备好在项目中使用应用测试了吗？

1. **开始构建**：使用 Agent 创建应用，等待测试自动启动
2. **查看结果**：查看测试报告，并落实建议的改进
3. **迭代优化**：根据测试反馈完善你的应用
4. **扩大规模**：将应用测试应用于更大、更复杂的项目
