Тип деплоя — это технология, которую Replit использует для публикации вашего App. Выберите его в раскрывающемся списке **Deployment type** в разделе **Adjust settings** инструмента Publishing. **Autoscale** — вариант по умолчанию и рекомендуемый вариант; большинству разработчиков менять его не нужно.

<div id="section">
  ## Сравнение типов деплоя
</div>

| Тип             | Лучше всего подходит для                                        | Принцип работы                                                            | Способ оплаты                                      |
| :-------------- | :-------------------------------------------------------------- | :------------------------------------------------------------------------ | :------------------------------------------------- |
| **Autoscale**   | Веб-приложений и API с переменной нагрузкой                     | Добавляет серверы при высокой нагрузке и масштабируется до нуля в простое | Оплата только за время обработки запросов          |
| **Static**      | Лендингов, портфолио и сайтов документации                      | Раздаёт файлы с кэшированных облачных серверов без бэкенда                | Оплата только за объём данных, передаваемых сайтом |
| **Reserved VM** | Ботов, фоновых задач и постоянно работающих API                 | Один выделенный сервер, который не переходит в спящий режим               | Фиксированная ежемесячная стоимость                |
| **Scheduled**   | Регулярных задач, таких как резервное копирование и уведомления | Выполняет команду по расписанию, затем останавливается                    | Оплата за время выполнения                         |

<div id="autoscale">
  ## Autoscale
</div>

Деплои Autoscale работают на серверах, автоматически масштабируемых в зависимости от трафика App. При высокой нагрузке Replit добавляет серверы, чтобы справиться с ней. В периоды простоя количество серверов сокращается вплоть до нуля, поэтому за время без обращений плата не взимается.

Оптимально подходит для:

* Веб-приложений с меняющимся трафиком, например интернет-магазинов
* API и сервисов

Настройки доступны в **Adjust settings**: [производительность машины и максимальное количество серверов](/ru/ja/features/publishing/machine-configuration).

<div id="static">
  ## Статическое развёртывание
</div>

Статическое развёртывание размещает файлы приложения, такие как HTML, CSS и JavaScript, на облачных серверах, которые быстро и экономично доставляют контент с помощью кеширования. Бэкенд отсутствует.

Оптимально для:

* Маркетинговых лендингов
* Сайтов-портфолио
* Сайтов документации для продуктов и API

<Note>
  Статическое развёртывание несовместимо с Replit App, созданными с помощью Agent. Agent создаёт полностековые приложения, которым требуется бэкенд, поэтому в этом случае используйте Autoscale или Reserved VM.
</Note>

Настройка включает общедоступный каталог для публикации и необязательную команду сборки. Подробнее о заголовках ответов, перезаписи URL и перенаправлениях см. в разделе [Дополнительные настройки статического развёртывания](/ru/ja/features/deployment-customization/static-deployments-advanced).

<div id="reserved-vm">
  ## Reserved VM
</div>

Деплои Reserved VM запускают App на выделенной виртуальной машине, которая не переходит в спящий режим. Они обеспечивают стабильную производительность и предсказуемые фиксированные ежемесячные расходы.

Лучше всего подходит для:

* Фоновых задач с высоким потреблением памяти
* Чат-ботов, которым необходимо постоянно поддерживать соединение
* Постоянно работающих API-серверов

Настройки включают [производительность машины](/ru/ja/features/publishing/machine-configuration), команды сборки и запуска, сопоставление портов, а также запуск App в качестве веб-сервера или фонового воркера.

<div id="scheduled">
  ## Запланированные
</div>

Запланированные деплои выполняют команды в среде App по расписанию, а затем останавливаются до следующего запуска. Опишите расписание естественным языком, например «каждый будний день в 9:00», и Replit автоматически преобразует его в расписание. В случае сбоя вы получите оповещение.

Лучше всего подходят для:

* Проверки состояния и отчётов о работоспособности
* Отправки уведомлений
* Запуска резервного копирования

В настройках указываются расписание, тайм-аут задачи, а также команды сборки и запуска. Запланированные деплои не обслуживают веб-страницы, поэтому у них нет общедоступного URL-адреса.
