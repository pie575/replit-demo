Replit Apps настраиваются с помощью двух файлов: `.replit` и `replit.nix`. Они определяют поведение вашего Replit App — от запуска кода до инструментов разработки и языков программирования.

По умолчанию эти файлы конфигурации скрыты. Чтобы отобразить их в своём Replit App, выберите «Show hidden files» в меню дерева файлов.

<div id="arquivo-replitnix">
  ## Файл `replit.nix`
</div>

Replit использует `Nix` для управления пакетами и средами. Файл `replit.nix` нужен, чтобы:

**Указать системные зависимости:** задайте, какие именно программные пакеты требуются вашему Replit App; управление ими осуществляется через пакетный менеджер Nix.

**Создать воспроизводимые среды:** обеспечьте единообразие и воспроизводимость среды разработки — это идеально подходит для совместных проектов и тестирования в разных системах.

Управлять пакетами Nix можно визуально с помощью инструмента `Dependencies`. Подробнее — в руководстве по [системным зависимостям](/ru/pt/features/project-setup/dependency-management#system-dependencies).

Чтобы настроить пакеты через файл `replit.nix`, перечислите [пакеты Nix](https://search.nixos.org/packages) в массиве `deps` с префиксом `pkgs.`. Все изменения синхронизируются после перезапуска Shell.

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="arquivo-replit">
  ## Файл `.replit`
</div>

Файл `.replit` управляет поведением вашего Replit App. Он использует [формат конфигурации](https://toml.io/en/) `toml`. Ниже перечислены основные параметры, которые можно настроить:

**Команда запуска (Run):** укажите команду, которая выполняется при нажатии кнопки Run. У каждого шаблона есть команда запуска по умолчанию, чтобы код можно было запустить сразу. Для более сложных и нестандартных приложений используйте [Workflows](/ru/pt/features/workspace-tools/workflows).

**Language Server Protocol (LSP)**: предоставляет такие возможности, как автодополнение, навигация по коду, подсветка синтаксиса, а также линтинг и отображение ошибок в реальном времени.

**Переменные окружения:** задавайте переменные окружения, необходимые для корректной работы ваших приложений, и управляйте ими.

**Зависимости и пакеты:** управляйте установкой и настройкой пакетов напрямую через файл `.replit` — так ваш Replit App при запуске получит все необходимые инструменты. Управлять зависимостями можно и визуально, с помощью инструмента `Dependencies`. Подробнее — в руководстве по [системным модулям](/ru/pt/features/project-setup/dependency-management#advanced-configuration).

Для приложений на Python файл `.replit` по умолчанию выглядит так:

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

| ----------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| <a name="modules" />`modules`                   | `["python-3.10:v18-20230807-322e88b"]` | Задаёт конкретные версии языков программирования или других важных зависимостей, поддерживаемых Replit.                                                                                                    |
| <a name="nix" />`[nix]`                         |                                        | Задаёт настройки для использования Nix — менеджера пакетов — для управления системными зависимостями. Подробнее см. документ [Управление зависимостями](/ru/pt/features/project-setup/dependency-management). |
| <a name="channel" />`channel`                   | `stable-23_05`                         | Указывает используемый канал Nix, от которого зависят доступные версии системных зависимостей.                                                                                                             |

| <a name="language" />`language`                 | `python3`                              | Указывает язык, используемый для модульных тестов; в данном случае тесты пишутся на Python 3.                                                                                                              |
| <a name="gitHubImport" />`[gitHubImport]`       |                                        | Настройки, влияющие на то, как проекты импортируются из GitHub, — в частности, какие файлы должны быть включены.                                                                                           |
| <a name="requiredFiles" />`requiredFiles`       | `[".replit", "replit.nix"]`            | Перечисляет файлы, которые должны присутствовать при импорте проекта, чтобы он работал корректно.                                                                                                          |
| <a name="deployment" />`[deployment]`           |                                        | Содержит настройки для публикации приложения Replit App в рабочей среде.                                                                                                                                   |
| <a name="run" />`run`                           | `["python3", "main.py"]`               | Команда, выполняемая для запуска приложения при публикации.                                                                                                                                                |
| <a name="deploymentTarget" />`deploymentTarget` | `cloudrun`                             | Указывает целевую платформу публикации для размещения приложения.                                                                                                                                          |

Теперь, когда вы получили представление о стандартных настройках файла `.replit`, воспользуйтесь следующими разделами, чтобы разобраться, как задавать базовые и расширенные параметры вашего Replit App.

<div id="configurando-ajustes-bsicos">
  ## Настройка основных параметров
</div>

<div id="entrypoint">
  ### Точка входа
</div>

Это главный файл вашего проекта. Если вы не зададите свойство `run`, среда выполнения запустит файл, указанный в `entrypoint`.

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="comando-run">
  ### Команда `Run`
</div>

Свойство `run` в файле `.replit` — ключевой параметр, определяющий начальную команду или последовательность команд, которые выполняются при нажатии кнопки `Run` в среде Replit. Команду `Run` можно задать в виде строки с самой командой либо в виде массива строк, где указаны команда и её отдельные аргументы.

Несколько распространённых способов настроить команду `Run`:

* **Одна команда:**
  В этом примере показано, как передать одну команду для непосредственного выполнения в Replit App. С такой записью в файле `.replit` нажатие кнопки `Run` выведет приветствие на панели `Console`:
  **Пример:** `run = "echo 'Hello, Replit!'"`

* **Явные аргументы:**
  Иногда удобнее задать всё явно, чтобы не разбираться с кавычками и правилами интерполяции в shell. Приведённый выше пример можно переписать, разделив аргументы.
  Обратите внимание: символы `'` и `"` больше не нужны, поскольку приветствие явно передаётся как первый и единственный аргумент команды `echo`:
  **Пример:** `run = ["echo", "Hello, Replit!"]`

* **Несколько команд:**
  В этом примере показано, как одновременно запустить несколько процессов, например фронтенд и бэкенд. Это может пригодиться, если вы разрабатываете бэкенд на python и фронтенд на typescript, где каждый сервер привязан к своему порту:
  **Пример:** `run = "python -m app & npm run start & wait"`

<div id="gerenciamento-de-processos">
  #### Управление процессами
</div>

Хотя несколько команд можно запускать одновременно с помощью `&`, вам может понадобиться более удобный способ различать логи разных сервисов. Вы можете [добавить системные зависимости](/ru/pt/features/project-setup/dependency-management#system-dependencies), например [`process-compose`](https://github.com/F1bonacc1/process-compose), чтобы эффективнее оркестрировать несколько процессов.

<div id="fase-de-build">
  #### Этап `Build`
</div>

Для некоторых языков и сред выполнения перед запуском кода (`run`) требуется отдельный этап сборки. Это относится как к компилируемым языкам — TypeScript, Golang или Java, — так и даёт вам параметр, с помощью которого можно сбросить окружение, данные или конфигурацию перед следующим вызовом `run`.

* **Компиляция:**
  В репозитории TypeScript вам может потребоваться выполнить `tsc` перед запуском кода.
  **Пример:**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="incluindo-variveis-de-ambiente">
  #### Добавление переменных окружения
</div>

Чтобы передать переменные окружения вашему сервису перед запуском, можно развернуть свойство `run` в [таблицу](https://toml.io/en/v1.0.0#table).

Это более серьёзное изменение, и, скорее всего, потребуется перенести свойство `run = "..."` в другое место файла `.replit`.

В следующем diff показано, как задать команду через `args` в разделе `[run]`, а также переменную `NAME` в `[run.env]`:

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# Наш новый [run] нужно переместить после всех свойств
+# верхнего уровня, которые не начинаются с `[`!
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="interatividade">
  #### Интерактивность
</div>

Интерактивные программы также можно запускать кнопкой `Run` — это позволяет отделить среду разработки от терминала, в котором выполняется ваша программа.
Рассмотрим следующий скрипт обратного отсчёта:

**Пример**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="opes-de-configurao-avanada">
  ## Расширенные параметры конфигурации
</div>

Ознакомьтесь с подробными параметрами конфигурации, доступными для вашего Replit App. Вы можете настроить среду разработки, управлять командами запуска, подключать языковые службы и работать с зависимостями.

| **Параметр** | **Ключ**                            | **Значение/Пример**                         | **Описание**                                                                                   |
| ------------ | ----------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| onBoot       | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Команда, выполняемая при запуске Replit App.                                                   |
| compile      | <a name="compile" />`compile`       | (Пример по умолчанию отсутствует)           | Команда, выполняемая перед командой `run`; используется в компилируемых языках, таких как C++. |
| language     | <a name="language" />`language`     | `language = "javascript"`                   | Указывает язык при импорте из GitHub или при создании Replit App.                              |
| entrypoint   | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | Точка входа — основной файл, который запускается и открывается при входе в редактор.          |
| hidden       | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | Файлы или папки, скрытые по умолчанию в боковом дереве файлов.                                 |
| audio        | <a name="audio" />`audio`           | `audio = true`                              | Включает системное аудио, если задано значение `true`.                                         |

<div id="notas-sobre-o-udio-do-sistema">
  ### Примечания о системном аудио
</div>

После установки `audio = true` в файле `.replit` может потребоваться перезапуск среды разработки. Откройте палитру команд с помощью `Cmd+K` (Mac) или `Ctrl+K` (Windows), найдите пункт **Restart compute** и выберите его.

При запуске графического приложения в правом нижнем углу панели `Output` появится значок наушников с флажком.
Из-за ограничений браузера его придётся включать заново после каждого обновления страницы.

```toml theme={null}
# Убедитесь, что эта строка находится в начале файла `.replit`, вне любых разделов, начинающихся с `[`
audio = true
```

<div id="configurao-do-packager">
  ## Настройка packager
</div>

| **Настройка**     | **Ключ**                                          | **Значение/Пример**                           | **Описание**                                                                    |
| ----------------- | ------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------- |
| packager          | <a name="language" />`language`                   | `packager.language = "python3"`               | Язык, используемый для операций с пакетами.                                     |
| packager features | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | Автоматически определяет пакеты для установки перед запуском Replit App.        |
| packager features | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | Включает поддержку packager, если задано значение `true`.                       |
| packager features | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | Определяет, требуется ли для хостинга Replit App выполнять установку пакетов.   |
| packager          | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | Команда, выполняемая после установки нового пакета через packager.              |
| packager          | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | Пути, которые следует игнорировать при попытке определить пакеты.               |
| packager          | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | Модули, для которых никогда не следует пытаться определить пакет при установке. |

<div id="exemplo-de-configurao-replit-para-configurao-do-packager">
  ### Пример конфигурации `.replit` для настройки packager
</div>

```toml theme={null}
# Задаёт язык для Replit App
packager.language = "python3"

# Включает функции автоматического управления пакетами
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# Команда, выполняемая после каждой установки пакета
packager.afterInstall = "echo 'Package installed successfully'"

# Задаёт пути и пакеты, которые менеджер пакетов должен игнорировать
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# Дополнительные настройки публикации
[deployment]
run = ["python3", "app.py"]
```

<div id="configurao-de-publicao-deployment">
  ## Настройка публикации (deployment)
</div>

| **Настройка** | **Ключ**                              | **Значение/Пример**                  | **Описание**                                                                |
| ------------- | ------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------- |
| deployment    | <a name="run" />`run`                 | `deployment.run = "npm start"`       | Команда, выполняемая при запуске контейнера деплоймента.                    |
| deployment    | <a name="build" />`build`             | `deployment.build = "npm run build"` | Команда, выполняемая перед запуском деплоймента.                            |
| deployment    | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | Если `true`, для успешной публикации не требуется проверка открытого порта. |

<div id="exemplo-de-configurao-replit-para-configurao-de-publicao">
  ### Пример файла `.replit` для настройки публикации
</div>

```toml theme={null}

# Указывает главную точку входа проекта
entrypoint = "app.js"

# Настройки публикации приложения
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  **Настройка interpreter** устарела и больше не доступна в Replit. Вместо неё рекомендуется использовать команды `Run` — с их помощью вы задаёте, как скрипты и приложения запускаются в среде вашего Replit App.
</Note>

<div id="acessando-os-metadados-do-ambiente-do-replit-app">
  ## Доступ к метаданным среды Replit App
</div>

<div id="nodejs">
  ### Node.js
</div>

Чтобы получить доступ ко всем переменным окружения:

`console.log(process.env);`

Чтобы обратиться к отдельной переменной (REPL&#95;SLUG):

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

Чтобы получить доступ ко всем переменным окружения:

```python theme={null}
import os
print(os.environ)
```

Чтобы получить доступ к одной переменной (REPL&#95;SLUG):

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

Чтобы получить доступ ко всем переменным окружения:

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

Чтобы получить одну переменную (REPL&#95;SLUG):

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```

<div id="variveis-de-ambiente">
  ## Переменные окружения
</div>

Ниже перечислены переменные окружения, доступные внутри вашего Replit App:

| ключ                                              | описание                                                                                                                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a name="REPL_OWNER" />`REPL_OWNER`               | Имя пользователя владельца Replit App. Если ваш Replit App текстовый и не имеет веб-сервера, `REPL_OWNER` будет содержать имя текущего пользователя, обращающегося к Replit App |
| <a name="REPL_ID" />`REPL_ID`                     | Уникальная UUID-строка вашего Replit App                                                                                                                                        |
| <a name="HOME" />`HOME`                           | Домашний каталог вашего Replit App                                                                                                                                              |
| <a name="system" />`system`                       | Операционная система, на которой работает ваш Replit App                                                                                                                        |
