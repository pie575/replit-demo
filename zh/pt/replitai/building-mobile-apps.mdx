  ## 在模拟器或仿真器中预览
</div>

Replit 支持你使用 Expo 在手机上运行和测试移动应用。或者，Replit 可将真实的 **iOS 模拟器** 或 **Android 模拟器** 直接串流到预览面板。通过 Agent 所做的更改会在模拟器中热重载，就像在真实设备上一样。

<div id="suporte-a-navegadores">
  ### 浏览器支持
</div>

* **Chrome**、**Safari** 及基于 Chromium 的浏览器均受完全支持。
* **Firefox** 不受支持。在 Firefox 中打开 Replit 时，iOS 和 Android 选项会显示为已禁用，并标注“Firefox not supported”。这是由于为模拟器提供支持的流式传输技术存在限制。

<div id="quando-usar-o-expo-go-em-vez-disso">
  ### 何时改用 Expo Go
</div>

当你需要测试依赖真实硬件的功能，或想与不在电脑旁的人分享预览时，请在真机上使用 Expo Go：

* 相机、麦克风、触觉反馈或其他原生传感器
* 推送通知
* 真实 GPS 定位
* 与团队成员、测试人员或投资者分享开发预览

要在 Expo Go 中打开你的应用，请在 [replit.com](https://replit.com) 打开项目，在 Project Editor 的预览面板中选择 **Open in Expo Go**，然后使用手机上的 [Expo Go](https://expo.dev/go) 应用扫描二维码。

<div id="simulador-em-tela-cheia">
  ### 全屏模拟器
</div>

在移动应用产物卡片中，选择 **More actions** → **Open in iOS Simulator** 或 **Open in Android Emulator**，即可在单独的标签页中打开模拟器，获得更大的预览区域。

<div id="por-que-criar-um-aplicativo-mobile">
  ## 为什么要创建移动应用？
</div>

如果你希望实现以下目标，可以创建移动应用：

* **原生体验**：性能出色、交互流畅，并提供平台原生界面。
* **设备功能**：相机、推送通知、定位等。
* **在 App Store 上分发**：通过 Apple 应用审核流程后，用户可发现并安装的可分享 App Store 页面。

<div id="recursos-principais">
  ## 核心功能
</div>

* **AI 优先构建**：描述您的应用，Agent 即可创建功能完善的移动应用。
* **在 Project Editor 中预览**：无需离开 Replit，即可在 iOS 模拟器或 Android 模拟器中测试，或通过 Expo Go 在手机上预览。
* **默认全栈**：随着应用不断发展，可添加服务器路由、数据库、App Storage、连接器和 AI 集成。
* **引导式发布**：无需管理本地 iOS 工具链，即可准备 TestFlight 构建并提交至 App Store。

<div id="fluxo-de-trabalho-de-desenvolvimento">
  ## 开发工作流程
</div>

访问应用分为三个阶段，每个阶段的受众和功能各不相同：

| 阶段            | 谁可以访问            | 如何访问                            | 最适合用于        |
| ------------- | ---------------- | ------------------------------- | ------------ |
| **开发**        | 您                | Project Editor 模拟器或 Expo Go 二维码 | 创建和迭代        |
| **部署**        | 使用 Expo Go 的测试人员 | 带二维码的公开 URL                     | 开发预览、原型设计和演示 |
| **App Store** | 任何人              | App 审核通过后从 App Store 下载         | 正式发布         |

**开发**：启动应用后，您可以在 Project Editor 的 **iOS 模拟器**或 **Android 模拟器**中预览应用，也可以扫描预览面板中的二维码，在手机上的 Expo Go 中打开应用。

**部署**：点击 **Publish** 后，Replit 会创建一个带有 Expo Go 二维码的公开 URL。这非常适合开发预览和原型设计——在进入 App Store 流程前，您可以向投资者展示、收集反馈，或与朋友一起测试。

**App Store**：将应用提交到 App Store 后，Apple 会对其进行审核。审核通过后，任何人都可以从 App Store 下载并安装应用。这需要 Apple Developer 账户。

<div id="viso-geral-de-publicao">
  ## 部署概览
</div>

准备发布 iOS 版本时，通常需要：

* 在 Project Editor 中部署
* 将构建版本上传到 TestFlight
* 在 App Store Connect 中将 TestFlight 构建版本发布到 App Store

<Note>
  要将构建版本上传到 TestFlight 和 App Store，Apple 要求您加入 Apple Developer Program。
</Note>

如需完整指南，请参阅教程[构建并发布移动应用](/zh/pt/tutorials/build-and-launch-a-mobile-app)。

<div id="onde-criar-aplicativos-mobile-nativos">
  ## 在哪里创建原生移动应用
</div>

您的 Replit 环境运行在云端，而非本地计算机。要创建原生移动应用，请使用 [replit.com](https://replit.com) 上的 Project Editor。移动应用工作流程——使用 Agent 创建、通过 Expo Go 预览、在模拟器和仿真器中测试、构建 TestFlight 版本，以及提交至 App Store——均在 Project Editor 中完成。

在支持的情况下，您也可以在 [Android 版 Replit 应用](/zh/platforms/mobile-app)中开发原生移动应用。如果您使用 iOS 版 Replit 应用，请在 [replit.com](https://replit.com) 中打开项目，以创建、预览、构建或提交原生移动应用。

<div id="como-a-tecnologia-funciona">
  ## 技术原理
</div>

您的移动应用基于一套相互协作的技术栈构建。本节将介绍为应用提供支持的技术，以及各组成部分如何协同运作。

<div id="a-pilha-de-tecnologia">
  ### 技术栈
</div>

<MobileStackDiagram />

* **React Native** 是一个开源框架，让你可以编写一套代码，并将其编译为 iOS、Android 和 Web 应用。它渲染的是平台原生界面组件，而不是 webview。
* **Expo** 通过管理构建和原生模块，并提供 Expo Go 等预览工具，简化了 React Native 开发。
* **Expo Go** 是一款可免费安装到手机上的应用。它运行开发预览，让你无需创建完整的原生二进制文件，也能在真实设备上进行测试。

运行应用时，Metro 打包器会编译代码并将其发送到设备。由于没有缓存，首次编译耗时较长，后续编译会更快。

<div id="arquitetura-servidor-e-cliente">
  ### 架构：服务器与客户端
</div>

当你准备预览或分发移动应用时，需要处理两个部分：

1. **服务器**，在云端的 Replit 上运行，负责管理数据库、API 路由、AI 集成和后端逻辑。
2. **客户端应用**，在用户手机上运行。开发期间，你会在 Expo Go 中预览这款原生应用；审核通过后，则可通过应用商店分发。

<MobileArchitectureDiagram />

这种分离方式带来了灵活性。你可以在服务器上运行复杂逻辑 (可访问 Replit 数据库、对象存储和连接器) ，同时让客户端保持轻量。构建时，请考虑哪些操作应在手机上完成，哪些应在云端完成。

<div id="consideraes">
  ## 注意事项
</div>

* **部署要求**：Apple 制定了 TestFlight 和 App Store 的要求，并会在分发前审核 iOS App。
* **发布到 Android**：你可以创建同时支持 iOS 和 Android 的跨平台 App。目前尚不支持通过引导式流程部署到 Google Play，但可以手动完成。
* **原生更改**：更改 App 图标或权限等内容通常需要重新构建，才能发布到商店。

<div id="perguntas-frequentes">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="什么是 Expo？">
    Expo 是 Agent 用来在 Replit 上创建移动应用的工具。它是一个开源平台和工具链，可使用 React Native 创建、运行和部署跨平台原生应用。请访问 [https://expo.dev](https://expo.dev) 了解更多。
  </Accordion>

  <Accordion title="什么是 React Native？">
    React Native 是 Meta 推出的开源框架，可使用 React 以及 JavaScript 或 TypeScript 创建原生 iOS 和 Android 应用。它渲染平台原生 UI 组件 (而非 webview) ，因此你的应用在外观和使用体验上都与原生应用一致。
  </Accordion>

  <Accordion title="什么是 Expo Go？">
    Expo Go 是一款免费应用，可从 App Store 或 Google Play 安装到手机上。它让你无需创建完整的原生二进制文件，即可在开发期间预览移动应用。当你在 Project Editor 中扫描二维码时，Expo Go 会下载并运行你的应用代码。
  </Accordion>

  <Accordion title="Expo Go 与 dev build 有什么区别？">
    **Expo Go** 是一款可运行你代码的预构建应用。它配置快捷，但仅支持 Expo SDK 中包含的模块。

    **Dev builds** 是可包含任意原生模块的自定义原生二进制文件。它们需要更多配置 (EAS Build 或本地 Xcode/Android Studio) ，但灵活性更高。

    Replit 使用 Expo Go 进行开发预览。如果你需要 Expo Go 不支持的原生模块，可能需要通过 [Expo 文档](https://docs.expo.dev/develop/development-builds/introduction/)了解 dev builds。
  </Accordion>

  <Accordion title="这与适配移动端的响应式 Web 应用有何不同？">
    适配移动端的响应式 Web 应用是会在浏览器中调整布局的网站。React Native 应用则是安装在设备上的原生应用，它使用平台 API (相机、触觉反馈、推送通知) ，能更好地访问硬件并支持离线功能，且通过应用商店分发。响应式 Web 应用很适合扩大覆盖范围且无需安装；当你需要设备功能、性能或通过 App Store 分发时，原生应用是更好的选择。
  </Accordion>

  <Accordion title="我需要 Mac 或 Xcode 吗？">
    不需要。Replit 和 Expo 会在云端为你管理构建流程。
  </Accordion>

  <Accordion title="没有 Apple Developer 账户也能预览吗？">
    可以。你可以在 Project Editor 的 iOS 模拟器中预览，也可以使用手机上的 Expo Go。只有在准备提交到 TestFlight 或 App Store 时，才需要 Apple Developer 账户。
  </Accordion>

  <Accordion title="支持 Android 吗？">
    支持。你可以通过同一套源代码创建适用于 iOS 和 Android 的跨平台应用。可在 Project Editor 中的 Android 模拟器上预览，也可在 Android 设备上使用 Expo Go 预览。发布到 Google Play 可手动完成。
  </Accordion>

  <Accordion title="服务器和数据库呢？">
    使用 Replit 内置的 PostgreSQL、对象存储、连接器和 AI 集成，无需单独配置基础设施。你的服务器在 Replit 上运行，移动应用会连接到它。
  </Accordion>

  <Accordion title="我应该在 Project Editor 的模拟器中测试，还是使用真机？">
    两者都应在不同阶段使用。Project Editor 中的 **iOS 模拟器**和 **Android 模拟器**可显示应用的原生版本，并满足大多数日常测试需求，包括布局、导航、原生组件和平台样式。当你需要测试依赖真实硬件的功能 (如相机、触觉反馈、推送通知或 GPS 定位) 时，请使用安装了 **Expo Go** 的真机。
  </Accordion>
</AccordionGroup>
