Comme Replit exécute les projets dans un environnement cloud, les ports fonctionnent différemment de ceux de votre ordinateur local. (Si vous avez besoin d’une explication plus élémentaire de ce qu’est un port TCP, [commencez ici](https://www.reddit.com/r/explainlikeimfive/comments/1t9s5a/eli5_what_are_ports_ex_tcp_port/).)

Sur un ordinateur, il n’existe qu’une seule couche de gestion des ports. Autrement dit, lorsqu’un programme définit le port sur lequel il écoute, le trafic provenant d’Internet et destiné à ce port est acheminé vers le processus approprié.

<Frame>
  <img src="/assets/mirror/computer-2bc67ea92696.png" alt="Ordinateur" width="1323" height="786" data-path="images/ports/computer.png" />
</Frame>

`0.0.0.0` est l’adresse, c’est-à-dire l’hôte. Lorsqu’un processus écoute sur `0.0.0.0`, cela signifie qu’il écoute sur toutes les interfaces réseau. Autrement dit, si un autre ordinateur sur Internet envoie une requête à l’adresse IP de votre ordinateur, le processus peut la recevoir. Ainsi, écouter sur 0.0.0.0 signifie que, si l’ordinateur est connecté à Internet, le processus est accessible depuis l’Internet public.

La plupart des frameworks de programmation n’écoutent *pas* sur `0.0.0.0` pendant le développement, afin de protéger votre confidentialité et votre sécurité. Vous ne souhaitez pas nécessairement exposer votre travail à l’extérieur. À la place, ils écoutent sur une autre adresse, `127.0.0.1`, souvent appelée `localhost`. Cela signifie que seules les requêtes provenant du même ordinateur peuvent être envoyées à ce port.

<Frame>
  <img src="/assets/mirror/computer-localhost-564f03349bfb.png" alt="Les ports localhost ne sont visibles que depuis l’ordinateur qui les héberge." width="1467" height="786" data-path="images/ports/computer-localhost.png" />
</Frame>

Dans Replit, un **port externe** doit être défini pour qu’un processus en cours d’exécution soit accessible via une webview ou par des requêtes externes. En effet, le « port interne » habituellement utilisé par le processus n’est visible qu’à l’intérieur de l’environnement cloud isolé fourni par Replit. Pour acheminer le trafic vers votre programme, vous devez connecter ce port interne à un port accessible de l’extérieur. Même si le processus écoute sur une adresse telle que 0.0.0.0, habituellement exposée publiquement, il doit tout de même être lié à un port externe.

<Frame>
  <img src="/assets/mirror/replit-de4de1b9386f.png" alt="Les ports externes transmettent le trafic vers le port interne sur lequel le programme écoute." width="1641" height="870" data-path="images/ports/replit.png" />
</Frame>

Replit gère cela en liant un port externe à un port interne spécifique. Par exemple, dans le diagramme ci-dessus, le port externe `:80` est lié au port interne `:3000`. Autrement dit, tout le trafic que cette application Replit reçoit sur le port 80 est transmis au port interne 3000.

Cette configuration est enregistrée dans la section [[ports]] du fichier de configuration .replit.

Par défaut, Replit lie le premier port ouvert au port externe par défaut 80 afin que le processus soit accessible sur le domaine sans indiquer de port (par exemple, customdomain.com/ au lieu de customdomain.com:3000/). Les ports internes supplémentaires ouverts par la suite sont liés à d’autres ports externes disponibles (consultez la liste complète ci-dessous).

<div id="section-2">
  ## Port par défaut
</div>

Le port :80 est le « port par défaut » du trafic HTTP. Le trafic HTTP envoyé vers le domaine racine est donc automatiquement acheminé vers le port 80. C&#39;est pourquoi le port 80 n&#39;apparaît pas dans l&#39;URL. Les ports autres que :`80` apparaissent dans le chemin de domaine (par exemple, customdomain.com:4200/). (Replit fournit TLS par défaut. Le trafic est donc en réalité transmis via le port 443, le port par défaut du HTTPS. En pratique, vous pouvez considérer que ces deux ports sont interchangeables.)

<div id="section-4">
  ## Publication
</div>

Les déploiements Autoscale et Reserved VM ne prennent en charge que l’exposition d’un seul port externe, et le port interne correspondant ne doit pas utiliser localhost. Exposer plusieurs ports ou un seul port sur localhost entraînera l’échec de votre application publiée. Pour garantir le bon fonctionnement d’un déploiement Autoscale, supprimez de la configuration toutes les entrées `externalPort`, à l’exception de celle du service auquel vous souhaitez accéder depuis Internet.

<div id="section-5">
  ## Débogage
</div>

L’une des causes fréquentes d’un comportement inattendu est une configuration de ports qui semble correcte, alors que le programme écoute en réalité sur un autre port. Par exemple, si la configuration est la suivante :

```
[[ports]]
internalPort = 3000
externalPort = 80
```

Le trafic Internet entrant sur le port 80 est acheminé vers le port interne 3000. Toutefois, si votre programme écoute en réalité sur un autre port (par exemple, 8080) plutôt que sur le port 3000, il peut sembler qu&#39;aucun trafic ne passe. Cela peut se produire si vous modifiez le port dans votre code sans mettre à jour le port correspondant dans la configuration, ou si vous copiez-collez la configuration d&#39;un projet dans un autre.

<Frame>
  <img src="/assets/mirror/replit-wrong_port-cbef0be60e43.png" alt="Les programmes peuvent changer le port sur lequel ils écoutent." width="1641" height="870" data-path="images/ports/replit-wrong_port.png" />
</Frame>

Chaque framework écoute par défaut sur un port différent. Par exemple, Flask utilise le port 5000, React le port 3000 et Laravel le port 8000. Assurez-vous que le bon port est configuré !

<div id="section-6">
  ## Configuration
</div>

Lorsqu’un port s’ouvre dans une Replit App, Replit le lie automatiquement à un port externe disponible et enregistre cette liaison dans le fichier de configuration .replit.

Cependant, ce comportement ne s’applique pas par défaut aux ports internes ouverts sur localhost. En effet, les services exécutés sur localhost sont généralement supposés être accessibles uniquement depuis l’ordinateur sur lequel le processus s’exécute (les ports localhost ne sont visibles que depuis l’ordinateur exécutant ce processus). Autrement dit, ces services présentent souvent un niveau de sécurité inférieur à celui des services conçus pour être exposés sur l’Internet public.

Vous pouvez modifier ce comportement à tout moment en définissant l’option de configuration `exposeLocalhost` sur `true` pour le port que vous souhaitez exposer.

Si vous souhaitez *toujours* exposer les ports localhost par défaut, vous pouvez définir le paramètre « Transfert automatique de ports » sur « Tous les ports » dans les paramètres utilisateur.

Si vous ne souhaitez *jamais* créer automatiquement de configuration pour les ports ouverts et préférez gérer vous-même toutes les configurations de ports de votre Replit App, vous pouvez définir cette option sur « Aucun ».

<div id="section-7">
  ## Ports pris en charge
</div>

Par défaut, une Replit App attribue le port 80 comme port externe lorsqu&#39;un premier port est ouvert. Une Replit App peut exposer les ports 3000, 3001, 3002, 3003, 4200, 5000, 5173, 6000, 6800, 8000, 8008, 8080 et 8081 comme ports externes supplémentaires.

Les ports 22 et 8283 sont utilisés en interne et ne peuvent donc pas être redirigés.

<div id="ports-replit">
  ## Configuration de `[[ports]]` dans .replit
</div>

Type : `{localPort, externalPort, exposeLocalhost}`

La configuration `[[ports]]` vous permet de définir les ports HTTP à exposer dans la sortie web. Par défaut, tous les ports HTTP exposés dont l’hôte est 0.0.0.0 sont accessibles dans la sortie web de votre Replit App.

Pour servir des ports supplémentaires sans remplacer le port par défaut, ajoutez une entrée [[ports]] à votre fichier .replit. Vous devez spécifier les champs localPort et externalPort. Vous pouvez ajouter plusieurs ports supplémentaires en ajoutant plusieurs entrées [[ports]] à votre fichier .replit, comme indiqué ci-dessous.

<div id="localport">
  ### localPort
</div>

Détermine le port que Replit doit associer au port externe.

<div id="externalport">
  ### externalPort
</div>

Détermine le port à exposer publiquement pour ce port local.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
```

Si vous ne souhaitez *absolument pas* exposer un port spécifique, conservez la configuration `localPort` sans ajouter `externalPort`.

```toml theme={null}
[[ports]]
localPort = 3000
```

<div id="exposelocalhost">
  ### exposeLocalhost
</div>

Détermine si les ports internes utilisant `localhost` peuvent être associés à des ports externes. Les valeurs possibles sont `true`, `false` ou null.

```toml theme={null}
[[ports]]
localPort = 3000
externalPort = 80
exposeLocalhost = true
```
