<div id="seo-agentseo">
  ## Оптимизируйте SEO с помощью SEO Agent
</div>

[SEO Agent](/ru/ja/features/publishing/seo-agent) проводит технический SEO-аудит опубликованных приложений и позволяет исправить каждую выявленную проблему одним нажатием. Он доступен в панели **Growth** в Project Editor пользователям платных тарифов. Чтобы просканировать приложение и применить исправления, выполните следующие действия.

<Steps>
  <Step title="Опубликуйте приложение и откройте возможности Growth">
    SEO Agent работает с опубликованными приложениями. Пока приложение не опубликовано, панель **Growth** заблокирована и отображается подсказка **Go to Publishing**. После публикации через чат Agent или инструмент Publishing вернитесь на панель Growth.

    <Frame caption="До публикации панель Growth заблокирована, и отображается подсказка Go to Publishing">
      <img src="/assets/mirror/01-growth-locked-b05c24711f10.png" alt="Заблокированная панель Growth с заголовком «Опубликуйте приложение, чтобы разблокировать инструменты Growth» и кнопкой Go to Publishing" width="1657" height="947" data-path="images/deployments/seo-agent/01-growth-locked.png" />
    </Frame>
  </Step>

  <Step title="Запустите сканирование с помощью Agent">
    Откройте панель **Growth** и найдите карточку **SEO Rating**. Выберите **Run scan with Agent**, чтобы запустить технический SEO-аудит проекта. Обычно сканирование занимает несколько минут.

    <Frame caption="Выберите Run scan with Agent на карточке SEO Rating, чтобы начать аудит">
      <img src="/assets/mirror/02-run-scan-94a2b8918fe9.png" alt="Увеличенный вид карточки SEO Rating с выделенной кнопкой Run scan with Agent" width="1656" height="946" data-path="images/deployments/seo-agent/02-run-scan.png" />
    </Frame>
  </Step>

  <Step title="Исправить с помощью Agent или исправить всё с помощью Agent">
    После завершения сканирования проблемы отображаются в таблице со столбцами **Severity** (Low, Medium, High) и **Status** (Unresolved) и группируются по категориям, таким как **AI Readiness**, **Crawlability &amp; Discovery**, **Landing Page Rendering &amp; Metadata** и **Performance Proxies**. Разверните любую проблему, чтобы ознакомиться с тем, что обнаружил SEO Agent.

    Вы можете применять исправления с нужной степенью детализации:

    * **Fix with Agent** для отдельной проблемы отправляет Agent только эту проблему.
    * **Fix with Agent** для категории исправляет все проблемы в этой группе.
    * **Fix all with Agent** отправляет Agent все проблемы одновременно. Кнопка **Fix all issues** в чате выполняет то же действие.

    <Frame caption="После сканирования исправляйте проблемы по отдельности, по категориям или все сразу с помощью Fix all with Agent">
      <img src="/assets/mirror/03-fix-with-agent-c5b9e642818e.png" alt="Таблица результатов сканирования, сгруппированных по категориям, со столбцами серьезности и статуса. Выделены кнопка Fix all with Agent и кнопки Fix with Agent для каждой категории" width="1657" height="947" data-path="images/deployments/seo-agent/03-fix-with-agent.png" />
    </Frame>
  </Step>

  <Step title="Agent вносит исправления">
    Agent запускает задачи по устранению каждой проблемы и выполняет их в фоновом режиме, поэтому вы можете продолжать работу над приложением. В строке появляется статус **Fix in progress**, а ссылка **Go to task** позволяет в любой момент открыть задачу и проверить ход выполнения.

    <Frame caption="Agent запускает задачи по устранению проблем: в строках с проблемами отображаются статус Fix in progress и ссылка Go to task">
      <img src="/assets/mirror/04-fixes-in-progress-e05dd10c05b3.png" alt="Таблица результатов сканирования со статусом Fix in progress и ссылкой Go to task в строках проблем, над устранением которых работает Agent" width="1657" height="947" data-path="images/deployments/seo-agent/04-fixes-in-progress.png" />
    </Frame>
  </Step>

  <Step title="Применить изменения к основной версии">
    После завершения исправлений задача получит статус **Ready for review**. Проверьте изменения и нажмите зелёную кнопку **Apply changes to main version**, чтобы объединить исправления с основной версией приложения. Выполните повторную публикацию, чтобы обновить SEO Rating для новой сборки.

    <Frame caption="Проверьте каждое исправление и выберите Apply changes to main version, чтобы объединить изменения">

    </Frame>
  </Step>
</Steps>

<Tip>
  Вы также можете пропустить интерфейс сканирования. Откройте Agent и скажите**«Оптимизируй SEO»** — Agent получит актуальные результаты и приступит к работе.
</Tip>

Типичные исправления, которые вносит Agent:

* Добавляет или переписывает отсутствующие либо слишком общие теги `<title>`, чтобы у каждой страницы был уникальный и информативный заголовок.
* Добавляет метаописания ко всем страницам.
* Добавляет изображениям описательный текст `alt`.
* Задаёт атрибут `lang` для элемента `<html>`.
* Добавляет ссылкам понятный текст (не использует «нажмите здесь» или пустые ссылки).
* Добавляет `robots.txt` и `sitemap.xml`.
* Добавляет метатег viewport для мобильных устройств.
* Улучшает цветовой контраст текста, не соответствующего требованиям доступности.
* Добавляет метатеги Open Graph и карточек Twitter, чтобы оптимизировать предпросмотр ссылок в социальных сетях.

<div id="seo">
  ## Лучшие практики SEO-оптимизации приложений
</div>

Независимо от того, поручаете ли вы это Agent или делаете сами, наиболее эффективны следующие меры:

* **Добавьте уникальные заголовки и метаописания для каждой страницы.** Заголовки должны быть не длиннее 60 символов, а описания — примерно 150–160 символов.
* **Используйте семантический HTML.** Оборачивайте макет в `<main>`, `<header>`, `<nav>` и `<footer>`. Используйте `<h1>` только один раз на странице и соблюдайте последовательность уровней заголовков.
* **Добавьте alt-текст ко всем изображениям.** Описывайте содержание изображения — не то, что это за изображение, а то, что на нём показано.
* **Создайте `sitemap.xml` и `robots.txt`.** Попросите Agent создать оба файла, чтобы поисковые системы понимали, какие страницы нужно сканировать.
* **Добавьте теги Open Graph и Twitter Cards.** Управляйте тем, как ваше приложение будет выглядеть при публикации в социальных сетях.
* **Используйте пользовательский домен.** Фирменный домен повышает доверие как посетителей, так и поисковых систем. См. [Добавление пользовательского домена](/ru/ja/build/add-custom-domain).
* **Выберите подходящий тип развёртывания.** Для сайтов с большим количеством контента лучше всего подходит [статическое развёртывание](/ru/ja/features/publishing/deployment-types#static). Поисковые системы смогут сразу анализировать предварительно отрендеренный HTML.
* **Добавьте структурированные данные.** Разметка JSON-LD позволяет поисковым системам показывать расширенные результаты для товаров, статей, FAQ и мероприятий.
* **Поддерживайте высокую скорость приложения.** Оптимизируйте изображения, избегайте скриптов, блокирующих рендеринг, и используйте хостинг Replit, чтобы сократить время отклика.

Простой способ применить большинство этих рекомендаций одновременно:

<AiPrompt>
  Проверь мой сайт на соответствие лучшим практикам SEO и внеси необходимые исправления. Добавь карту сайта,
  robots.txt, теги Open Graph, структурированные данные там, где это уместно, и
  убедись, что у каждой страницы есть уникальные заголовок и метаописание.
</AiPrompt>

<div id="section-2">
  ## Если вам нужна дополнительная помощь
</div>

* **Если оценка не обновляется после повторной публикации:** Подождите 1–2 минуты — проверка выполняется асинхронно после публикации развертывания, а значок обновляется после появления результатов.
* **Если оценка не меняется после изменений, внесённых Agent:** Проверьте, какие именно пункты Lighthouse должен был исправить Agent, и посмотрите во всплывающей подсказке значка, какие из них всё ещё отмечены.
* **Если на некоторых страницах оценка низкая:** Значок показывает самую низкую оценку среди всех просканированных URL. Попросите Agent сосредоточиться на конкретных страницах, отмеченных Lighthouse.
* **Если оценка не отображается для опубликованного приложения:** SEO-оценки рассчитываются только для опубликованных веб-развертываний типов Autoscale, Reserved VM и Static. Запланированные и приватные развертывания не получают оценок.
