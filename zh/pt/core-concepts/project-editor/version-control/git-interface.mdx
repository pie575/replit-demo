Replit 的 Git Pane 为 Git 操作提供了可视化界面，无需在命令行中输入 Git 命令。这一功能让初学者也能轻松上手版本控制，同时对经验丰富的开发者来说依然足够强大。

<div id="recursos">
  ## 功能
</div>

Git Pane 直接在 Project Editor 中提供全面的版本控制能力，界面友好，让复杂的 Git 操作变得简单。

* **仓库管理**：初始化、连接和管理 Git 仓库，并支持 GitHub 集成
* **提交跟踪**：暂存、提交并查看所有文件的更改
* **分支操作**：以可视化方式创建、切换和合并分支
* **冲突解决**：借助可视化辅助识别并解决合并冲突
* **Shell 集成**：在 Shell 中执行的 Git 命令与 Git Pane 保持同步

<div id="uso">
  ## 使用方法
</div>

<div id="configurao-do-repositrio">
  ### 仓库配置
</div>

<Accordion title="如何打开 Git Pane">
  1. 在 Replit App 中前往 Tools 面板
  2. 点击 **+** 号添加新工具
  3. 从可用工具列表中选择 **Git**
</Accordion>

Git Pane 可帮助你配置并连接仓库：

* **初始化仓库**：为你的 Replit App 新建一个 Git 仓库
* **连接到 GitHub**：将仓库关联到 GitHub，以便备份和协作
* **配置远程仓库**：设置并管理与 GitHub 仓库的连接

<div id="gerenciamento-de-alteraes">
  ### 更改管理
</div>

<Accordion title="如何查看更改">
  1. 在你的 Replit App 中修改任意文件
  2. 在 Tools 部分打开 Git Pane
  3. 在 **Review Changes** 部分查看更改
</Accordion>

Git Pane 提供了管理代码更改的各种工具：

* **查看更改**：查看已修改的文件，新增和删除的内容会高亮显示
* **暂存文件**：选择要包含在下次提交中的特定文件
* **提交更改**：用描述性的提交信息保存你的更改
* **推送更新**：一键将提交推送到 GitHub

<Note>
  你可以借助 Replit AI 生成准确描述更改内容的提交信息。

<div id="gerenciamento-de-branches">
  ### 分支管理
</div>

<Accordion title="如何管理分支">
  1. 在 Tools 部分打开 Git Pane
  2. 点击分支名称旁边的分支下拉菜单
  3. 创建新分支或选择已有分支
</Accordion>

Git Pane 让你更轻松地管理代码的多个版本：

* **创建分支**：新建分支，独立开发功能
* **切换分支**：在代码的不同版本之间切换
* **发布分支**：将分支共享到 GitHub
* **拉取更改**：同步协作者推送的远程更新

<div id="resoluo-de-conflitos-de-merge">
  ### 解决合并冲突
</div>

<Accordion title="如何解决合并冲突">
  1. 发生冲突时，尝试拉取更改
  2. Git Pane 会突出显示存在冲突的文件
  3. 打开每个冲突文件，查看并解决冲突
  4. 解决冲突后保存文件
  5. 选择 **Pull** 完成合并
</Accordion>

当来自不同来源的代码发生冲突时，Git Pane 可帮助您：

* **识别冲突**：准确查看哪些文件存在冲突
* **查看差异**：查看冲突代码的两个版本
* **解决问题**：选择要保留的代码，或手动编辑冲突内容
* **完成合并**：解决冲突后完成合并流程

解决冲突文件后，删除以冲突标记开头的行并保存文件，即可移除冲突标记。

<div id="usando-comandos-git-no-shell">
  ### 在 Shell 中使用 Git 命令
</div>

<Accordion title="如何访问 Shell">
  1. 在左侧工具栏中选择 **All tools**
  2. 在可用工具中选择 **Shell**
</Accordion>

<Tip>
  虽然 Git Pane 提供了易用的图形界面，但高级用户可以在 Shell 中使用标准 Git 命令完成更复杂的操作。无论使用哪种方式，所做的更改都会在两处同步体现。
</Tip>

如果你更习惯通过命令行使用 Git：

* **命令同步**：在 Shell 中执行的任何 Git 命令都会自动同步到 Git Pane
* **完整的 Git 功能**：可使用 Git Pane 中未提供的高级功能
* **无缝切换**：可根据需要随时在 Shell 命令与 Git Pane 之间切换

<Info>
  **GitHub 与 GitLab CLI 支持**：除标准 Git 命令外，你还可以在 Shell 中使用 [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) 和 [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) 来管理和连接外部 Git 仓库。这些工具增强了与 GitHub 和 GitLab 仓库协作的能力，包括 pull request、issue 以及其他平台特有的功能。
</Info>

<div id="operaes-de-repositrio">
  #### 仓库操作
</div>

* **克隆仓库**：`git clone <url-do-repositório>`
* **初始化仓库**：`git init`
* **添加远程仓库**：`git remote add origin <url-do-repositório>`

<div id="fazendo-alteraes">
  #### 进行更改
</div>

* **查看状态**：`git status` (显示已修改、已添加和已删除的文件) 
* **暂存文件**：`git add <文件名>` 或 `git add .` (暂存所有文件) 
* **提交更改**：`git commit -m "你的提交信息"`
* **推送更改**：`git push origin <分支名>`
* **拉取更改**：`git pull origin <分支名>`

<div id="autenticao">
  #### 身份验证
</div>

使用私有仓库时，你需要进行身份验证：

* 对于 GitHub 仓库，请使用个人访问 token，而不是密码
* 为避免反复输入凭证，你可以使用 Replit Secrets 来保存它们：
  1. 新建一个键为 `GIT_URL` 的 secret
  2. 将其值设置为 `https://<用户名>:<token>@github.com/<用户或组织>/<仓库>`
  3. 使用 `git push $GIT_URL` 推送，无需输入凭证

<Note>
  使用凭证 secret 时，任何能访问你的 Replit App 的人都有可能获取你的 Git 凭证。对于敏感仓库，建议每次手动输入凭证。
</Note>
