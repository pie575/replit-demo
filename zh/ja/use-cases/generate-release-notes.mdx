每周从 GitHub 和 Linear 拉取变更内容，按新功能、改进和修复分类，生成面向客户的
发布说明并发布到 Notion。自动跳过仅限内部的工作，并为可能存在破坏性变更的内容
标注提醒，让产品、支持团队和客户始终掌握一致的信息。

  ## 适用场景
</div>

* 无需等待版本标签、希望每周了解变更日志的产品经理。
* 需要与客户掌握相同信息的产品营销和支持人员。

<div id="section-4">
  ## 给 Agent 的指令
</div>

<AiPrompt>
  创建一个每周一 9:00 运行的例程。从 GitHub 和 Linear 获取上周的变更内容，
  生成面向客户的发布说明，按新功能、改进和修复分组，并发布到 Notion。
  跳过仅限内部的工作，并标记出疑似破坏性变更的内容。
</AiPrompt>

<div id="section-5">
  ## 预期效果
</div>

Agent 会根据拉取请求和问题整理出上周的发布说明，并生成一个 Notion 页面。发送给客户之前，请先润色文风。看起来属于内部事务的内容会被跳过，破坏性变更会排在最前面。发布之前，请将页面内容与上周合并的拉取请求逐一核对。

<div id="section-6">
  ## 按需定制
</div>

<AiPrompt>
  创建两个版本：面向客户的版本和用于内部变更日志的版本，并将它们放在同一个 Notion
  页面中。
</AiPrompt>

<AiPrompt>
  在 #ship 频道发一条 Slack 消息，附上 Notion 页面链接和三个亮点。
</AiPrompt>

<div id="section-7">
  ## 故障排查
</div>

* **内部工作混入了发布说明：** 向 Agent 指明正确的仓库和 Linear 团队，并再次要求它跳过不面向客户的工作。
* **破坏性变更被淹没：** 告诉 Agent 你所定义的“破坏性”是指什么 (登录、计费、必需的迁移等) ，并要求把这些条目标记出来并置于最前面。
* **Notion 页面不正确：** 提供准确的页面或数据库链接，并指定是覆盖上周的发布说明，还是每次运行都新建一个页面。
