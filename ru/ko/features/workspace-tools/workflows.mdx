<div id="section">
  ## Доступные типы задач
</div>

В настоящее время доступны три типа задач: `Execute Shell Command`, `Install Packages` и `Run Workflow`.

<div id="execute-shell-command">
  ### Выполнение команд Shell
</div>

`Execute Shell Command` сохраняет и выполняет команды оболочки в той же среде, что и в окне Shell. Этот тип задачи подходит для всего: от запуска отдельных файлов до

```text theme={null}
python main.py
```

Поддерживает широкий спектр сценариев использования, включая выполнение сложных сохранённых запросов к базе данных:

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Установка пакетов
</div>

`Install Packages` автоматически определяет зависимости проекта и устанавливает необходимые пакеты с помощью встроенной системы управления зависимостями Replit. Подробнее о том, как UPM определяет, какие пакеты нужно установить в проекте, см. в разделе [Управление зависимостями](/ru/ko/features/project-setup/dependency-management#the-universal-package-manager).

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow` позволяет запускать другой воркфлоу из текущего. Это позволяет повторно использовать и комбинировать воркфлоу для создания более сложных процессов.

Пример использования:

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="Изображение" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

Создавая зависимости между воркфлоу с помощью этого типа действия, вы обеспечиваете, что при редактировании одного воркфлоу другие воркфлоу, ссылающиеся на него, автоматически используют последние изменения. Обратите внимание, что для вызовов с глубокой вложенностью действует ограничение глубины.

<div id="section-2">
  ## Режимы выполнения Workflows
</div>

Workflows поддерживает два режима выполнения: последовательный и параллельный.

<div id="section-3">
  ### Последовательное выполнение
</div>

При последовательном выполнении задачи запускаются в заданном порядке: система ждёт завершения каждой задачи, прежде чем перейти к следующей, и прекращает выполнение последовательности, если какая-либо задача в рабочем процессе завершается с ошибкой.

Этот режим подходит, например, для определения логически связанных команд: сначала получить последние изменения из основной ветки, а затем выполнить ребейз текущей ветки поверх основной ветки:

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="Изображение" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="section-4">
  ### Параллельное выполнение
</div>

В режиме параллельного выполнения каждая задача запускается и выполняется независимо от других задач в рабочем процессе. Сбой одной задачи не останавливает выполнение остальных.

Этот режим полезен, например, при запуске full-stack проекта, в котором необходимо запустить и фронтенд-, и бэкенд-серверы:

<div id="section-5">
  ## Создание рабочего процесса
</div>

Нажмите кнопку `+ New Workflow`, чтобы создать рабочий процесс в окне Workflows. Укажите понятное название рабочего процесса, выберите подходящий режим запуска и добавьте задачи. Задачи можно перетаскивать, чтобы изменить их порядок.

<div id="run">
  ## Назначение Workflows кнопке Run
</div>

Вы можете назначить Workflows кнопке Run, чтобы заменить её стандартное действие (см. [Настройка Replit App](/ru/ko/features/project-setup/configuration)). Чтобы сохранить стандартную команду запуска, заданную в `.replit`, выберите в раскрывающемся списке вариант по умолчанию «Run Replit App».

При нажатии кнопки Run запускается выбранный в раскрывающемся меню Workflows. Чтобы изменить Workflows, запускаемый кнопкой Run, выберите нужный вариант в раскрывающемся меню.
