<div id="section-2">
  ### Analyse de sécurité pendant le build
</div>

Dans le cadre de la revue de code, Agent recherche désormais les problèmes de sécurité courants dans les fichiers qu&#39;il modifie. Cette analyse Semgrep automatique détecte les schémas à risque et les secrets codés en dur, afin qu&#39;Agent puisse corriger les problèmes identifiés avant de terminer son travail.

Pour en savoir plus, consultez [Analyse de sécurité pendant le build](/fr/ko/features/security/project-security-center#security-scan-while-you-build).

<div id="section-4">
  ### Régénération des identifiants de la base de données de production
</div>

Vous pouvez désormais régénérer les identifiants des bases de données de production éligibles depuis l&#39;outil **Database**. Replit met à jour les identifiants et, si votre app dispose d&#39;un déploiement actif pris en charge, lance un redéploiement afin que les nouveaux identifiants restent utilisables. Les outils externes qui utilisent l&#39;ancienne chaîne de connexion doivent être mis à jour.

<div id="sso">
  ### Créer avec le SSO
</div>

Les builders Pro peuvent désormais configurer le SSO Enterprise pour les Replit Apps utilisant [Clerk Auth](/fr/ko/features/auth-and-identity/clerk-auth). Demandez à Agent d&#39;effectuer les modifications d&#39;authentification nécessaires : il vous guidera jusqu&#39;au Clerk Dashboard. Vous pourrez y connecter Okta ou Microsoft Entra ID via OIDC ou SAML. Les connexions SSO Enterprise sont gratuites jusqu&#39;au 1er octobre 2026. Passé cette date, la tarification à l&#39;usage de Clerk s&#39;applique. La prise en charge Enterprise arrive bientôt.

</Frame>

Pour en savoir plus, consultez [Créer avec le SSO](/fr/features/auth-and-identity/single-sign-on).

<div id="section-5">
  ### Déplacement de projets entre workspaces
</div>

Vous pouvez désormais déplacer des projets entre les workspaces d&#39;équipe d&#39;un même compte de facturation depuis la liste **Projects**. Le transfert s&#39;exécute en arrière-plan et ne peut pas être annulé. Les secrets des comptes connectés ne suivent pas le projet : vous devrez donc les reconnecter dans le workspace de destination.

  <img src="/assets/mirror/transfer-project-to-workspace-menu-f3accf37a0d6.png" alt="Menu de la carte de projet avec l'action Transférer vers un workspace" width="1218" height="1146" data-path="images/teams/transfer-project-to-workspace-menu.png" />
</Frame>

Pour en savoir plus, consultez [Transférer des projets entre workspaces d&#39;équipe](/fr/ko/teams/identity-and-access-management/transfer-app-to-teams#transfer-between-team-workspaces).
