---
title: "外部访问令牌"
description: "让 CI 流水线、Webhook 及其他自动化服务无需登录即可访问你的私有 Replit App。"
---

外部访问令牌是你为特定 Replit App 创建的 bearer 令牌。
即使应用的 URL 已被 [私有 Dev URL](/zh/pt/features/publishing/private-deployments) 或
[Private Deployment](/zh/pt/features/publishing/private-deployments) 限制访问，
这些令牌仍能让自动化服务 (CI 流水线、Webhook、uptime 状态检查器、Slack 机器人、
内部脚本) 正常访问该应用。

请像对待密码一样对待每个令牌：在令牌过期或被吊销之前，任何持有它的人都能访问你的应用。

<Note>
  为 deployment 选择私有访问后，即可使用外部访问令牌，无需 workspace 额外开通。
  在 Enterprise workspace 中，只有 workspace 管理员可以管理令牌。
</Note>

<div id="quando-usar-um-token">
  ## 何时使用令牌
</div>

当浏览器*之外*的某个环节需要调用你的私有 Replit App 时，请使用外部访问令牌。常见场景包括：

* GitHub Actions 工作流在每次提交时对你的开发 URL 执行冒烟测试。
* uptime 监控服务 (Better Stack、Pingdom、UptimeRobot) 访问你已发布应用的健康检查端点。
* webhook 接收方——Stripe、Slack、GitHub——向 Private Deployment 发送 POST 请求。
* 调试期间，团队成员从自己的机器上发起的 `curl` 或 `fetch` 调用。

外部访问令牌专为 **API 流量**设计，并不适合在浏览器中打开界面页面。单页应用 (Vite、Next.js 等) 会在后续请求中加载 JavaScript 包，而这些请求不会携带你的令牌，因此会请求失败。若需交互式浏览，请正常登录。

<div id="ambientes-de-tokens">
  ## 令牌环境
</div>

每个令牌都与一个环境绑定：

| 环境            | 生效范围                                       | 用途                         |
| :------------ | :----------------------------------------- | :------------------------- |
| `Development` | 应用的 workspace 开发 URL (`*.replit.dev`)      | 在开发过程中访问正在运行的 Repl         |
| `Production`  | 应用已发布的 deployment (`*.replit.app` 和自定义域名)  | 从外部服务访问 Private Deployment |

`Production` 令牌在重新发布 (包括发布新版本) 后仍然有效。出现以下情况时，Replit 会撤销该令牌：

* 取消发布该 deployment。
* 删除该 deployment。
* 将应用的访问权限从私有改为公开。

此外，令牌过期或被你撤销后也会失效。

<div id="criar-um-token-de-acesso-externo">
  ## 创建外部访问令牌
</div>

<Steps>
  <Step>
    打开你想要对外开放的应用，然后打开 **Publishing** 工具。
  </Step>

  <Step>
    选择 **Adjust settings**，展开重新发布选项。
  </Step>

  <Step>
    在 **Security** 部分找到 **External access tokens**。
  </Step>

  <Step>
    选择 **Create access token** 并填写：

    * **Label** (可选) ：便于日后识别该令牌的简短名称，
      例如 `CI` 或 `Stripe webhook`。最多 120 个字符。
    * **Environment**：根据调用方服务需要访问应用的环境，选择 `Development` 或 `Production`。
    * **Expires after**：选择有效期——`1 hour`、`24 hours`、`7 days`、
      `30 days`、`3 months`、`1 year` 或 `5 years`。请选择能满足需求的最短时长。没有“永不过期”选项。
  </Step>

  <Step>
    选择 **Create**。
  </Step>
</Steps>

Replit **只会显示一次**该令牌。请立即复制——关闭对话框后就无法再次查看。如果令牌丢失，请撤销它并重新创建一个。

显示界面提供两种复制方式：

* **Copy query parameter** —— 复制 `?project-protection-bypass=<token>`，
  可直接附加到 URL 上。适合用 `curl` 做快速验证。
* **Copy token only** —— 复制原始令牌，适合放在
  `Authorization: Bearer` 请求头中发送。

<Info>
  如果应用尚未启用外部访问，创建第一个令牌时会自动启用。
  否则没有保护机制，令牌也就无从绕过。
</Info>

<div id="usar-um-token">
  ## 使用令牌
</div>

可通过以下两种方式之一提交令牌：

<div id="cabealho-authorization-recomendado">
  ### Authorization 请求头 (推荐)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

几乎所有场景下，这都是首选方案——webhook、CI 脚本、后端之间的调用。令牌不会出现在记录 URL 的日志中，也不会留在浏览器历史记录里。

<div id="parmetro-de-consulta">
  ### 查询参数
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

仅在无法设置请求头时才使用查询参数形式——例如某个只接受 URL 的服务。包含令牌的 URL 往往会残留在代理日志、Shell 历史记录和屏幕截图中，因此请尽可能优先使用请求头。

<div id="gerenciar-tokens-existentes">
  ## 管理现有令牌
</div>

**External access tokens** 部分会按从新到旧的顺序，列出你为该应用创建的所有令牌，并显示标签、环境、创建日期、有效期和吊销状态。每一行还会显示令牌的末尾几位字符，方便你加以区分，因为完整的令牌值只在创建时显示一次。

你只能看到*你自己*创建的令牌。其他协作者的令牌仅对其本人可见，即使你是该应用的所有者也无法查看。

<div id="revogar-um-token">
  ## 吊销令牌
</div>

一旦某个令牌不再需要，或你怀疑它可能已泄露，请立即将其吊销。吊销步骤：

<Steps>
  <Step>
    在应用的发布设置中打开 **External access tokens** 部分。
  </Step>

  <Step>
    在列表中找到该令牌，然后点击垃圾桶图标。
  </Step>

  <Step>
    确认吊销。
  </Step>
</Steps>

吊销**立即生效且不可撤销**。仍在使用该令牌的流量会在几秒内开始被拒绝。如需重新获得访问权限，请创建新的令牌。

你只能吊销自己创建的令牌。将协作者移出 workspace 时，其为该应用创建的令牌会被自动吊销。

<div id="mantenha-seus-tokens-seguros">
  ## 妥善保管你的令牌
</div>

外部访问令牌属于凭据。请像对待 API 密钥或密码一样谨慎处理。

<div id="o-que-fazer">
  ### 应该怎么做
</div>

* **将令牌存放在 secrets 管理工具中** —— GitHub Actions 的 secrets、你所用 CI
  服务商的密钥保管库、云服务商的 secrets 存储，或者密码管理器。
  切勿将其提交到代码仓库。
* 尽可能**缩短有效期**。为一次性集成签发一个 7 天有效期的令牌，
  远比留下一个 5 年有效期的令牌安全。
* **为每个令牌加上标签**，这样你才清楚它的用途以及是否仍在使用。没有标签的令牌往往最先泄露，也最后才被吊销。
* **为每个使用方单独创建令牌。** 一个 CI 任务一个令牌，一个 webhook
  来源一个令牌，一项 uptime 检查一个令牌。一旦发生泄露——或者
  某个服务商不再需要——只吊销那一个即可。
* **优先使用 `Authorization` 请求头**，而不是查询参数，以免令牌
  通过 URL 日志、浏览器历史记录或 referer 请求头泄露。
* 如果令牌可能已经暴露——日志外泄、
  误提交到公开仓库、被录屏拍到、前员工的笔记本电脑——请**立即吊销**。
  吊销即时生效；之后再创建替代令牌即可。

<div id="o-que-no-fazer">
  ### 不要这样做
</div>

* **不要在团队成员或服务之间共用同一个令牌。** 如果两个系统共用
  一个令牌，你就无法在吊销其中之一时不影响另一个。
* **不要把令牌粘贴到聊天、电子邮件、截图或问题追踪工具中。**
  这些渠道会以你无法预料的方式被归档、索引和传播。
* **不要把令牌嵌入客户端代码** —— 浏览器应用、移动应用、
  桌面端二进制文件。任何分发到用户设备上的内容都应视为公开信息。
* **不要用令牌来维持浏览器会话。** 令牌适用于 API 调用，
  而不适用于在浏览器标签页中加载 SPA。这种场景请使用常规的 Replit 登录。
* **不要默认选择 5 年有效期。** 请按使用方实际需要访问的时长
  来设置有效期。

<div id="soluo-de-problemas">
  ## 故障排查
</div>

<Accordion title="我的生产环境令牌突然失效了">
  正常的重新发布不会影响生产环境令牌的有效性。请检查令牌是否已过期，或是否被你撤销。同时确认你是否取消了发布、删除了 deployment，或将应用从私有改为了公开。
  如果应用已不再是私有 deployment，请将其重新发布为私有，然后创建新令牌。已过期或已撤销的令牌无法恢复。
</Accordion>

<Accordion title="我的令牌在 `curl` 中可用，但浏览器仍然显示登录页面">
  外部访问令牌用于 API 流量，而非浏览器会话。单页应用在浏览器中加载时，初始的 HTML 请求可以通过查询参数携带令牌，但后续对 JavaScript 包、CSS 的请求以及 API 调用不会包含令牌，因而会被拒绝。若要以交互方式浏览应用，请照常登录 Replit。
</Accordion>

<Accordion title="我把令牌弄丢了——还能再看到它吗？">
  不能。Replit 只在创建时显示一次令牌。列表视图会显示元数据 (标签、环境、有效期、末尾几位字符) ，但绝不会显示完整的令牌值。如果令牌丢失，请撤销该令牌并创建一个新令牌。
</Accordion>
