</div>

<div id="expo-go">
  ### 何时应改用 Expo Go
</div>

当你需要测试依赖真实硬件的功能，或者想把预览分享给不在电脑前的人时，请在真机上使用 Expo Go：

* 摄像头、麦克风、触感反馈及其他原生传感器
* 推送通知
* 真实的 GPS 定位
* 与团队成员、测试人员或投资人分享开发预览

若要在 Expo Go 中打开应用，请在 [replit.com](https://replit.com) 上打开 project，在 Project Editor 的 Preview 面板中选择 **Open in Expo Go**，然后用手机上的 [Expo Go](https://expo.dev/go) 应用扫描二维码。

<div id="section-6">
  ## 为什么要构建移动应用？
</div>

当你有以下需求时，不妨构建一个移动应用：

* **原生体验**：性能出色、交互流畅，UI 与平台原生一致。
* **设备功能**：摄像头、推送通知、定位等。
* **App Store 发布**：通过 Apple 的 App Review 审核后，即可获得可分享的应用页面，供用户发现并安装。

<div id="section-7">
  ## 主要功能
</div>

* **AI 驱动生成**：描述你的应用，Agent 就会搭建出一个可运行的移动应用框架。
* **Project Editor 预览**：无需离开 Replit，即可在 iOS Simulator 或 Android Emulator 中测试，或通过 Expo Go 在手机上预览。
* **默认全栈**：随着应用不断迭代，可添加服务器路由、Database、App Storage、Connectors 和 AI 集成。
* **引导式提交**：无需管理本地 iOS 工具链，即可准备好用于 TestFlight 和 App Store 提交的构建版本。

<div id="section-8">
  ## 开发工作流
</div>

访问应用的方式分为三个阶段，每个阶段面向的人群和功能各不相同：

| 阶段              | 可访问的人群          | 访问方式                            | 适用场景         |
| --------------- | --------------- | ------------------------------- | ------------ |
| **Development** | 仅你自己            | Project Editor 模拟器或 Expo Go 二维码 | 构建与迭代        |
| **Deploy**      | 使用 Expo Go 的测试者 | 带二维码的公开 URL                     | 开发预览、原型验证、演示 |
| **App Store**   | 所有人             | 通过 App Review 后在 App Store 下载   | 正式发布         |

**Development**：启动应用后，你可以在 Project Editor 的 **iOS Simulator** 或 **Android Emulator** 中预览，也可以在 Preview 面板中扫描二维码，在手机的 Expo Go 中打开。

**Deploy**：点击 **Publish** 后，Replit 会生成一个包含 Expo Go 二维码的公开 URL。在启动 App Store 流程之前，它非常适合用于开发预览和原型验证，比如向投资人展示、收集反馈或与朋友一起测试。

**App Store**：提交到 App Store 后，Apple 会审核你的应用。审核通过后，任何人都可以在 App Store 下载并安装。这需要一个 Apple Developer 账户。

<div id="section-9">
  ## 发布概览
</div>

准备 iOS 版本发布时，通常的流程如下：

* 在 Project Editor 中发布
* 将构建版本提交到 TestFlight
* 在 App Store Connect 中将 TestFlight 构建版本升级为 App Store 版本

<Note>
  向 TestFlight 和 App Store 提交构建版本需要具备 Apple Developer Program 会员资格。
</Note>

完整操作步骤请参阅[构建并上线移动应用](/zh/ko/build/mobile-app)教程。

<div id="section-10">
  ## 在哪里构建原生移动应用
</div>

Replit 环境运行在云端，而非本地机器上。若要构建原生移动应用，请使用 [replit.com](https://replit.com) 上的 Project Editor。从 Agent 搭建项目骨架、Expo Go 预览、模拟器/仿真器测试、TestFlight 构建到 App Store 提交，整个移动应用工作流都在 Project Editor 中完成。

在受支持的情况下，你也可以在 [Replit Android 应用](/zh/ko/features/platforms/mobile-app)中进行原生移动应用的开发工作。如果你使用的是 Replit iOS 应用，请在 [replit.com](https://replit.com) 上打开项目，以创建、预览、构建或提交原生移动应用。

<div id="section-11">
  ## 技术原理
</div>

移动应用由多个协同运作的技术栈构建而成。本节将介绍驱动应用的各项技术，以及它们之间如何相互配合。

<div id="section-12">
  ### 技术栈
</div>

<MobileStackDiagram />

* **React Native** 是一个开源框架，让你只需编写一套代码库，即可编译到 iOS、Android 和 Web。它渲染的是平台原生 UI 组件，而不是 WebView。
* **Expo** 负责处理构建、管理原生模块并提供 Expo Go 等预览工具，从而简化 React Native 开发。
* **Expo Go** 是安装在手机上的免费应用。它可运行开发预览，因此你无需构建完整的原生二进制文件，就能在真机上测试。

运行应用时，Metro 打包器会编译代码并发送到设备。首次构建因为没有缓存，耗时较长，之后的构建会更快。

<div id="section-13">
  ### 架构：服务器与客户端
</div>

在准备移动应用的预览或部署时，你需要关注两个部分：

1. 在 Replit 云端运行的**服务器**，负责数据库、API 路由、AI 集成和后端逻辑。
2. 在用户手机上运行的**客户端应用**：开发阶段可在 Expo Go 中预览，审核通过后则作为原生应用通过应用商店发布。

<MobileArchitectureDiagram />

这种分离带来了灵活性：复杂逻辑可以放在服务器端运行 (可访问 Replit 的 Database、Object Storage 和 Connectors) ，客户端则保持轻量。构建过程中，不妨想一想哪些工作应该由手机处理，哪些应该交给云端。

<div id="section-14">
  ## 注意事项
</div>

* **发布要求**：TestFlight 和 App Store 的要求由 Apple 制定，iOS 应用在发布前须经 Apple 审核。
* **Android 发布**：你可以构建同时支持 iOS 和 Android 的跨平台应用。目前还没有发布到 Google Play 的引导式流程，但你可以手动发布。
* **原生变更**：修改应用图标、权限等内容通常需要重新构建并提交到应用商店。

<div id="faq">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="什么是 Expo？">
    Expo 是 Agent 在 Replit 上构建移动应用时使用的工具。它是一个开源平台和工具链，用于基于 React Native 构建、运行和部署跨平台原生应用。详情请访问 [https://expo.dev](https://expo.dev)。
  </Accordion>

  <Accordion title="什么是 React Native？">
    React Native 是 Meta 推出的开源框架，用于使用 React 搭配 JavaScript 或 TypeScript 构建原生 iOS 和 Android 应用。它渲染的是平台原生 UI 组件 (而非网页视图) ，因此应用看起来和用起来都像真正的原生应用。
  </Accordion>

  <Accordion title="什么是 Expo Go？">
    Expo Go 是一款免费应用，可从 App Store 或 Google Play 安装到手机上。有了它，你无需构建完整的原生二进制文件即可预览开发中的移动应用。在 Project Editor 中扫描二维码后，Expo Go 会下载并运行你的应用代码。
  </Accordion>

  <Accordion title="Expo Go 与开发构建（dev build）有什么区别？">
    **Expo Go** 是一款预先构建好的应用，用于运行你的代码。它配置起来很快，但仅支持 Expo SDK 中包含的模块。

    **开发构建**是可以包含任意原生模块的自定义原生二进制文件。它需要更多配置 (EAS Build 或本地 Xcode/Android Studio) ，但灵活性更高。

    Replit 在开发预览中使用 Expo Go。如果你需要 Expo Go 不支持的原生模块，可以在 [Expo 的文档](https://docs.expo.dev/develop/development-builds/introduction/)中了解开发构建。
  </Accordion>

  <Accordion title="这与移动端响应式网页应用有什么不同？">
    移动端响应式网页应用本质上是能在浏览器中自适应布局的网站。React Native 应用则是安装到设备上的原生应用程序，可调用平台 API (相机、触感反馈、推送通知) ，能更好地访问硬件和离线功能，并通过应用商店分发。响应式网页胜在触达范围广、无需安装即可访问；而当你需要设备功能、性能和 App Store 分发时，原生应用是最佳选择。
  </Accordion>

  <Accordion title="需要 Mac 或 Xcode 吗？">
    不需要。Replit 和 Expo 会在云端替你完成构建。
  </Accordion>

  <Accordion title="没有 Apple Developer 账号也能预览吗？">
    可以。你可以在 Project Editor 的 iOS Simulator 中预览，或在手机上通过 Expo Go 预览。只有在准备提交到 TestFlight 或 App Store 时，才需要 Apple Developer 账号。
  </Accordion>

  <Accordion title="也支持 Android 吗？">
    支持。你可以用同一套代码库构建面向 iOS 和 Android 的跨平台应用。可在 Project Editor 的 Android Emulator 中预览，或在安装了 Expo Go 的 Android 设备上预览。发布到 Google Play 可手动完成。
  </Accordion>

  <Accordion title="服务器和数据库怎么办？">
    无需额外的基础设施，直接使用 Replit 内置的 PostgreSQL、Object Storage、Connectors 和 AI 集成即可。服务器在 Replit 上运行，移动应用连接到它即可。
  </Accordion>

  <Accordion title="应该在 Project Editor 的模拟器上测试，还是在真机上测试？">
    视情况而定，两者都可以用。Project Editor 中的 **iOS Simulator** 和 **Android Emulator** 会呈现应用的原生版本，足以覆盖大部分日常测试，如布局、导航、原生组件和平台样式。当需要测试相机、触感反馈、推送通知、GPS 定位等依赖真实硬件的功能时，请通过 **Expo Go** 切换到真机测试。
  </Accordion>
</AccordionGroup>
