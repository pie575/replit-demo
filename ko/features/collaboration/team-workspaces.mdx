<div id="personal-vs-team-workspaces">
  ## 개인 workspace와 팀 workspace 비교
</div>

**workspace**는 apps, 멤버, settings, billing을 담는 구조입니다. Replit에는 두 가지 유형이 있습니다:

* 개인 workspace
* 팀 workspace

개인 workspace와 팀 workspace의 차이점은 다음과 같습니다:

|             | 개인 workspace             | 팀 workspace                         |
| ----------- | ------------------------ | ----------------------------------- |
| **역할**      | Admin, 프로젝트 수준 guests | Admin, 멤버, 프로젝트 수준 guests   |
| **접근 방식**   | 개별 프로젝트에 guests를 초대  | 멤버가 workspace의 모든 프로젝트에 접근 |
| **billing** | 본인 계정                    | admin 계정의 공유 크레딧            |
| **멤버 관리**   | 프로젝트별(참여 링크)          | workspace Settings에서 중앙 관리          |

**개인 workspace**는 혼자 작업하거나 개별 프로젝트를 다른 사람과 공유할 때 가장 적합합니다. 본인이 유일한 admin이며, 다른 사람은 프로젝트 수준 guests로 초대받은 특정 프로젝트에만 접근할 수 있습니다.

**팀 workspace**는 스타트업 팀, 수업, 여러 참여자가 있는 클라이언트 프로젝트처럼 고정된 그룹과 함께 build할 때 가장 적합합니다. 멤버는 workspace의 모든 프로젝트에 접근할 수 있으므로 프로젝트마다 일일이 초대할 필요가 없습니다. 멤버는 **Settings**에서 한곳에서 관리합니다.

<div id="when-to-invite-to-your-workspace-vs-to-a-project">
  ### workspace에 초대할지, 프로젝트에 초대할지
</div>

| 상황                                  | 대응 방법                                  |
| ----------------------------------- | -------------------------------------- |
| 모든 리소스에 접근해야 하는 상시 협업자              | workspace에 초대                          |
| 프로젝트 하나에만 접근하면 되는 외주 인력 또는 Guest | [프로젝트에 초대](/ko/build/invite-teammates) |
| 회사에 새로 합류한 팀원                       | workspace에 초대                          |
| 특정 App 디버깅을 도와주는 친구                 | [프로젝트에 초대](/ko/build/invite-teammates) |

<div id="create-a-team-workspace">
  ## 팀 workspace 만들기
</div>

<Frame>
  <img src="/assets/mirror/create-team-workspace-e89eaefd9168.png" alt="기본 workspace 이름과 팀원 초대용 빈 입력란이 있는 새 workspace 만들기 양식" width="784" height="300" data-path="images/workspace/create-team-workspace.png" />
</Frame>

<Steps>
  <Step title="workspace 전환기 열기">
    홈 페이지 왼쪽 상단에서 workspace 이름을 클릭합니다.
  </Step>

  <Step title="새 workspace 만들기">
    **Create workspace**를 선택한 후 팀 workspace의 이름을 정합니다.
  </Step>

  <Step title="멤버 초대하기">
    초대 입력란에 이메일 주소를 하나 이상 쉼표로 구분해 입력합니다. 초대받은 사람에게 초대장이 전송되며, 초대를 수락하면 해당 workspace의 모든 프로젝트에 접근할 수 있습니다.
  </Step>
</Steps>

<div id="managing-members">
  ## 멤버 관리
</div>

설정 과정에서 멤버를 초대하지 않았거나 나중에 멤버를 더 추가하려면, 팀 workspace에서 **Settings &gt; Workspace collaborators**로 이동해 이메일 또는 Replit 사용자 이름으로 멤버를 초대하세요.

<Frame>
  <img src="/assets/mirror/invite-workspace-members-6e3fda413196.jpg" alt="이메일 주소를 입력하는 빈 필드가 있는 사용자 초대 대화 상자" width="510" height="244" data-path="images/workspace/invite-workspace-members.jpg" />
</Frame>

**Settings** 페이지에서는 다음 작업도 할 수 있습니다.

* **멤버 제거** — 모든 workspace 프로젝트에 대한 접근 권한을 회수합니다
* **프로젝트 이전** — 개인 workspace의 프로젝트를 팀 workspace로 옮깁니다. [Transfer app to teams](/ko/teams/identity-and-access-management/transfer-app-to-teams)를 참고하세요

  <Warning>
    workspace 간 프로젝트 이전은 일시적으로 중단되었습니다. 현재는 새 이전을 시작할 수 없습니다.
  </Warning>

고급 ID 관리, 역할 기반 접근, 그룹 permissions에 대해서는 [Pro and Enterprise](/ko/category/teams)를 참고하세요.
