La gestion de versions de Replit vous permet de suivre, de gérer et de faire évoluer votre base de code en toute confiance. Grâce à l&#39;intégration Git native et à la connexion GitHub, vous pouvez :

* suivre les modifications du code et conserver un historique de votre travail de développement ;
* collaborer avec les membres de votre équipe sans conflits de code ni perte de travail ;
* importer, modifier et pousser du code entre Replit et GitHub ;
* tester de nouvelles fonctionnalités en toute sécurité à l&#39;aide de branches.

<div id="section">
  ## Qu&#39;est-ce que la gestion de versions ?
</div>

La gestion de versions est un système qui enregistre les modifications apportées aux fichiers au fil du temps, afin de pouvoir revenir ultérieurement à une version précise. Sur Replit, elle repose sur Git, l&#39;outil de référence du secteur pour suivre les modifications de code, avec une interface visuelle intuitive qui ne nécessite aucune connaissance de la ligne de commande.

<div id="replitn">
  ### Comment fonctionne le contrôle de version dans Replit
</div>

Les quatre options de contrôle de version reposent toutes sur le même dépôt Git sous-jacent :

1. Les **checkpoints d&#39;Agent** créent automatiquement des commits aux étapes clés lorsque vous développez avec [Replit Agent](/fr/ja/features/agent/overview). [En savoir plus sur les checkpoints et les retours en arrière](/fr/ja/features/version-control/checkpoints-and-rollbacks).
2. Le **volet Git** offre un accès visuel au dépôt Git complet
3. La **CLI Git** donne un accès en ligne de commande à toutes les fonctionnalités de Git
4. L&#39;**historique des fichiers** suit les modifications détaillées au sein de chaque fichier

Choisissez l&#39;interface qui correspond le mieux à vos besoins, en toute sérénité : tout repose sur Git, un système de contrôle de version éprouvé.

| Fonctionnalité             | Checkpoints d&#39;Agent                     | Commits Git                          | Historique des fichiers              |
| -------------------------- | ------------------------------------------- | ------------------------------------ | ------------------------------------ |
| **Création**               | Automatique aux points logiques             | Manuelle ou planifiée                | Automatique                          |
| **Granularité**            | Modifications au niveau des fonctionnalités | Modifications de toute taille        | Modifications au niveau du caractère |
| **Description**            | Résumé généré par l&#39;IA                  | Message rédigé par l&#39;utilisateur | Horodatage automatique               |
| **Retour en arrière**      | Restauration en un clic                     | Nécessite des connaissances Git      | Restauration en un clic              |
| **Fonctionnalités Git**    | Fonctionnalités Git complètes               | Fonctionnalités Git complètes        | Aucune fonctionnalité Git            |
| **Synchronisation GitHub** | Synchronisation GitHub complète             | Synchronisation GitHub complète      | Aucune synchronisation GitHub        |

<div id="section-2">
  ## Prise en main
</div>

Ajoutez l&#39;outil Git au Project Editor pour accéder à la gestion de versions dans votre application Replit :

1. Rendez-vous dans la section Tools de votre application Replit
2. Sélectionnez le signe **+** pour ajouter un nouvel outil
3. Choisissez **Git** dans la liste des outils disponibles

Pour importer un projet existant depuis GitHub, consultez [Importer depuis GitHub](/fr/ja/build/import-from-providers).

<div id="section-4">
  ### Gestion de versions automatique
</div>

<Accordion title="Checkpoints d'Agent">
  Instantanés créés automatiquement pendant le développement assisté par IA avec [Replit Agent](/fr/ja/features/agent/overview).

  **Idéal pour** : le développement avec Replit Agent

  **Fonctionnalités principales** :

  * Création automatique à chaque jalon logique
  * Restauration en un clic
  * Instantanés au niveau des fonctionnalités
  * Suivi de la progression
  * Aucune configuration requise
  * Chronologie visuelle de l&#39;avancement du développement

  Les checkpoints d&#39;Agent sont enregistrés dans Git et accessibles depuis le volet Git ou la CLI Git. Vous pouvez également visualiser l&#39;ensemble des checkpoints d&#39;Agent grâce à la fonctionnalité History :

  * Visualisation chronologique des checkpoints d&#39;Agent
  * Descriptions détaillées des checkpoints d&#39;Agent
  * Accès direct à l&#39;état d&#39;un checkpoint d&#39;Agent
  * Restauration en un clic vers n&#39;importe quel checkpoint d&#39;Agent
</Accordion>

<Accordion title="Historique des fichiers">
  Suivi automatique des versions, fichier par fichier, pour les modifications effectuées directement dans l&#39;éditeur en dehors de l&#39;Agent.

  **Idéal pour** : récupérer rapidement des modifications récentes d&#39;un fichier

  **Fonctionnalités principales** :

  * Focalisation sur un seul fichier
  * Modifications au niveau du caractère
  * Comparaison visuelle
  * Historique sur 30 jours
  * Fonction de relecture

  L&#39;historique des fichiers dispose de sa propre interface, mais les modifications sous-jacentes font partie de l&#39;historique Git. Pour en savoir plus, consultez [Historique des fichiers](/fr/ja/features/version-control/file-history).
</Accordion>

<div id="git">
  ### Interfaces basées sur Git
</div>

<Accordion title="Volet Git">
  Interface visuelle pour les opérations Git, qui permet de gérer le contrôle de version sans connaître la ligne de commande.

  **Idéal pour** : la plupart des projets nécessitant une intégration GitHub et des flux de travail visuels

  **Fonctionnalités principales** :

  * Suivi de l&#39;ensemble du dépôt
  * Gestion des branches
  * Affichage visuel des différences
  * Synchronisation GitHub en un clic
  * Collaboration en équipe

  Pour en savoir plus sur l&#39;utilisation du volet Git, consultez [Utiliser le volet Git](/fr/ja/features/workspace-tools/git-interface).
</Accordion>

<Accordion title="Git CLI">
  Accès complet à Git en ligne de commande via le [Shell](/fr/ja/features/workspace-tools/shell) pour les opérations avancées.

  **Idéal pour** : les utilisateurs expérimentés ayant besoin de toutes les fonctionnalités de Git

  **Fonctionnalités principales** :

  * Jeu complet de commandes Git
  * Stratégies de branches avancées
  * Flux de travail personnalisés
  * Automatisation par scripts
  * Contrôle total du dépôt

  Pour les commandes Git courantes et leur utilisation, consultez [Utiliser le volet Git](/fr/ja/features/workspace-tools/git-interface#using-git-commands-in-shell).
</Accordion>

<div id="section-5">
  ## Fonctionnalités principales
</div>

* **Interface Git visuelle** : gérez vos dépôts, commits et branches sans saisir la moindre commande Git
* **Intégration GitHub** : connectez-vous à des dépôts GitHub pour la sauvegarde et la collaboration
* **Importer depuis GitHub** : [convertissez un dépôt GitHub en application Replit](/fr/ja/build/import-from-providers) en quelques clics
* **Gestion des branches** : créez, changez et fusionnez des branches directement depuis le Project Editor
* **Résolution des conflits** : identifiez et résolvez les conflits de fusion avec une assistance visuelle

<div id="section-6">
  ## Cas d&#39;usage
</div>

**Suivi des projets personnels**

Suivez les modifications apportées à votre code au fil du développement et revenez à une version antérieure si nécessaire. Le [volet Git](/fr/ja/features/workspace-tools/git-interface) affiche visuellement les modifications et facilite la validation des mises à jour pertinentes.

**Collaboration en équipe**

Plusieurs développeurs travaillent sur la même base de code sans écraser les modifications des autres. Créez une branche pour chaque nouvelle fonctionnalité, puis fusionnez-la lorsqu&#39;elle est prête. Pour en savoir plus, consultez [Inviter des coéquipiers](/fr/ja/build/invite-teammates).

<div id="agent">
  ## Checkpoints de l&#39;Agent
</div>

Lorsque vous créez des applications avec [Replit Agent](/fr/ja/features/agent/overview), vous bénéficiez d&#39;une couche supplémentaire de gestion de versions grâce aux checkpoints. À chaque moment clé du développement assisté par l&#39;IA, les checkpoints capturent automatiquement l&#39;état complet de votre projet : contenu du projet, contexte des conversations avec l&#39;IA et bases de données connectées.

<div id="section-7">
  ### Fonctionnement des checkpoints
</div>

Les checkpoints d&#39;Agent constituent un instantané complet de l&#39;état global de l&#39;application Replit :

* **Création automatique** : Agent crée des checkpoints d&#39;Agent à des étapes logiques du développement
* **Capture complète de l&#39;état** : chaque checkpoint d&#39;Agent enregistre le contenu du projet, la mémoire de l&#39;IA et l&#39;état de la base de données
* **Plan d&#39;implémentation** : avant d&#39;apporter des modifications, Agent vous soumet un Plan pour examen
* **Suivi des tâches complexes** : plusieurs checkpoints d&#39;Agent peuvent être créés pour les tâches d&#39;envergure

<div id="ai">
  ### Les avantages du développement assisté par l&#39;IA
</div>

Les checkpoints d&#39;Agent offrent des avantages uniques lorsque vous créez avec l&#39;IA :

* **Filet de sécurité** : expérimentez en toute confiance, en sachant que vous pouvez facilement restaurer un état antérieur dans l&#39;ensemble de votre environnement de développement
* **Suivi de la progression** : visualisez étape par étape la façon dont Agent a construit votre application
* **Jalons logiques** : les checkpoints représentent des fonctionnalités abouties, et non des points de sauvegarde arbitraires
* **Retour arrière immédiat** : revenez à n&#39;importe quel état antérieur en un clic, avec restauration de la base de données et du contexte de l&#39;IA

<Info>
  Pour en savoir plus sur ce que capturent les checkpoints et sur les fonctionnalités complètes de retour arrière, consultez [Checkpoints et retours arrière](/fr/ja/features/version-control/checkpoints-and-rollbacks).
</Info>

<Tip>
  Les checkpoints d&#39;Agent sont très efficaces pour le développement assisté par l&#39;IA, mais privilégiez les commits Git pour le suivi des versions sur le long terme et la collaboration, en particulier lorsque vous travaillez avec des dépôts externes.
</Tip>
