Lorsque vous sélectionnez **Publish**, un court pipeline se met en route pour mettre votre application en ligne. Cette page décrit ce qui se passe pendant la publication, comment mettre à jour votre application et où la gérer une fois qu&#39;elle est en ligne.

<div id="section">
  ## Étapes de publication
</div>

La publication se déroule en cinq étapes et prend généralement 1~2 minutes. Consultez la barre de progression dans l’outil Publishing, sélectionnez **View logs** pour afficher les détails ou **Cancel** pour annuler une publication en cours.

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Vue d’ensemble de Publishing montrant une barre de progression en cinq étapes, avec Provision terminé, Security checks et Build en cours, et Bundle et Promote en attente" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision**: Replit prépare les ressources cloud sur lesquelles l’application s’exécutera, notamment les serveurs et la base de données de production.
2. **Security checks**: Replit vérifie les problèmes de sécurité, tels que des dépendances non sécurisées ou des secrets exposés, avant de mettre l’application en ligne.
3. **Build**: Replit transforme le projet en version de production, c’est-à-dire une version optimisée pour s’exécuter sur le Web.
4. **Bundle**: L’application compilée est empaquetée dans une unité unique prête à être exécutée.
5. **Promote**: Replit prépare la nouvelle version parallèlement à la version actuelle, puis redirige l’URL vers la nouvelle version.

<Note>
  La publication concerne l’ensemble du projet : tous les artefacts inclus dans le projet, tels que l’application, le jeu de diapositives et les documents, sont publiés ensemble.
</Note>

<Accordion title="Ce qui se passe en interne">
  Pour les créateurs souhaitant des détails techniques : Provision alloue l’infrastructure de déploiement adaptée au type de déploiement et à la région sélectionnés. Security checks analyse les dépendances et le code, et peut bloquer la publication si des vulnérabilités graves sont détectées, selon vos paramètres de sécurité. Build exécute la commande de compilation et compile les ressources pour la production. Bundle empaquette le résultat de la compilation dans une image déployable. Promote effectue l’opération de bascule : la nouvelle version commence à répondre à l’URL et remplace le déploiement précédent.
</Accordion>

Une fois les étapes terminées, votre application est en ligne. Sélectionnez l’URL dans l’outil Publishing pour ouvrir votre application.

<div id="section-2">
  ## Mettre à jour votre application
</div>

Une fois vos modifications effectuées, sélectionnez de nouveau **Publish**. Votre application est mise à jour à la même URL et les visiteurs obtiennent la dernière version au prochain chargement de la page. Inutile de partager un nouveau lien.

<div id="section-3">
  ## Gérer une application en ligne
</div>

Les outils de Publishing servent aussi à gérer votre application une fois qu&#39;elle est en ligne :

* **Surveiller l&#39;état** : vérifiez que votre application est bien accessible, consultez les journaux et suivez l&#39;utilisation des ressources. En savoir plus sur la [surveillance](/fr/ko/features/publishing/monitoring-a-deployment).
* **Suivre les visiteurs** : les graphiques de requêtes et de trafic se trouvent dans la [surveillance](/fr/ko/features/publishing/monitoring-a-deployment), tandis que les données sur les visiteurs et les utilisateurs sont disponibles dans le panneau **Growth**.
* **Modifier les droits d&#39;accès** : dépubliez l&#39;application, choisissez une autre option d&#39;accès, puis republiez-la. En savoir plus sur l&#39;[accès aux applications](/fr/ko/features/publishing/private-deployments).
* **Connecter un domaine** : attribuez une adresse web personnalisée à votre application. En savoir plus sur les [domaines personnalisés](/fr/ko/features/publishing/custom-domains).
