完成本指南后，已发布应用在搜索引擎中的排名将得到提升，Publishing 工具中的 SEO 评分也会反映这一结果。

每次成功发布后，Replit 都会运行 SEO 审核并显示 SEO 评分。如果评分仍有提升空间，你可以一键将具体问题发送给 Agent。多数情况下，流程很简单：**发布 → 查看评分 → 请 Agent 进行优化**。

如需详细了解评分的计算方式 (Lighthouse 审核、各项评分的含义及适用的部署类型) ，请参阅 [SEO 评分](/zh/ja/features/publishing/seo-rating)。

<div id="seo-agentseo">
  ## 使用 SEO Agent 优化 SEO
</div>

[SEO Agent](/zh/ja/features/publishing/seo-agent)可对已发布应用进行技术 SEO 审核，并支持一键修复发现的每项问题。它位于 Project Editor 的 **Growth** 面板中，付费套餐的构建者可使用。请按照以下步骤扫描应用并应用修复。

<Steps>
  <Step title="发布应用，解锁 Growth">
    SEO Agent适用于已发布的应用。发布前，**Growth** 面板会被锁定，并显示前往 **Go to Publishing** 的提示。通过 Agent 聊天或 Publishing 工具发布后，请返回 Growth 面板。

    <Frame caption="发布前，Growth 面板会显示 Go to Publishing 提示并保持锁定">
      <img src="/assets/mirror/01-growth-locked-b05c24711f10.png" alt="锁定的 Growth 面板，包含“发布应用以解锁 Growth 工具”标题和 Go to Publishing 按钮" width="1657" height="947" data-path="images/deployments/seo-agent/01-growth-locked.png" />
    </Frame>
  </Step>

  <Step title="使用 Agent 执行扫描">
    打开 **Growth** 面板，找到 **SEO 评级** 卡片。选择 **Run scan with Agent**，开始对项目进行技术 SEO 审核。扫描通常需要几分钟。

    <Frame caption="在 SEO 评级卡片中选择 Run scan with Agent，开始审核">
      <img src="/assets/mirror/02-run-scan-94a2b8918fe9.png" alt="突出显示 Run scan with Agent 按钮的 SEO 评级卡片放大图" width="1656" height="946" data-path="images/deployments/seo-agent/02-run-scan.png" />

  </Step>

  <Step title="使用 Agent 修复，或使用 Agent 全部修复">

    您可以按不同粒度应用修复：

    * 对单个问题使用 **Fix with Agent**，只会将该问题发送给 Agent。
    * 对类别使用 **Fix with Agent**，会修复该组中的所有问题。
    * **Fix all with Agent** 会一次性将所有问题发送给 Agent。聊天中的 **Fix all issues** 按钮也能执行相同操作。

    <Frame caption="扫描后，使用 Fix all with Agent 按问题、类别或一次性修复所有问题">

  <Step title="Agent 着手修复">
    Agent 会为每个问题启动修复 task 并在后台处理，您可以继续构建。相应行会更新为 **Fix in progress**，您可以随时通过 **Go to task** 链接打开任意 task 并查看进度。

<Tip>
  您也可以跳过扫描界面。打开 Agent 并告诉它**“优化 SEO”**，Agent 就会获取最新结果并开始处理。
</Tip>

Agent 常见的修复内容：

* 添加或重写缺失或过于通用的 `<title>` 标签，确保每个页面都有唯一且描述性明确的标题。
* 为所有页面添加元描述。
* 为图片添加描述性的 `alt` 文本。
* 为 `<html>` 元素设置 `lang` 属性。
* 为链接添加可识别的文本 (不要使用“点击这里”或空锚点) 。
* 添加 `robots.txt` 和 `sitemap.xml`。
* 添加适用于移动设备显示的 viewport 元标签。
* 改善未通过无障碍检查的文本颜色对比度。
* 添加 Open Graph 和 Twitter 卡片元标签，以优化社交平台上的链接预览。

<div id="seo">
  ## SEO 优化应用的最佳实践
</div>

无论是让 Agent 处理还是自行创建，以下做法都很有效：

* **为每个页面设置唯一的标题和元描述。** 标题应控制在 60 个字符以内，元描述建议为 150 至 160 个字符。
* **使用语义化 HTML。** 使用 `<main>`、`<header>`、`<nav>` 和 `<footer>` 组织页面布局。每个页面只使用一次 `<h1>`，并按顺序使用标题层级。
* **为所有图片添加替代文本。** 描述图片中呈现的内容，而非图片本身是什么。
* **生成 `sitemap.xml` 和 `robots.txt`。** 请 Agent 创建这两个文件，以便搜索引擎了解应抓取哪些内容。
* **添加 Open Graph 和 Twitter 卡片标签。** 控制应用在社交媒体上被分享时的显示方式。
* **使用自定义域名。** 品牌域名可提升访客和搜索引擎的信任度。请参阅[添加自定义域名](/zh/ja/build/add-custom-domain)。
* **选择合适的部署类型。** 对于内容丰富的网站，[静态部署](/zh/ja/features/publishing/deployment-types#static)是最佳选择。搜索引擎可以立即解析预渲染的 HTML。
* **添加结构化数据。** JSON-LD 标记可让搜索引擎显示商品、文章、常见问题和活动的富媒体搜索结果。
* **保持应用快速运行。** 优化图片，避免使用阻塞渲染的脚本，并利用 Replit 托管服务将响应时间维持在较低水平。

<div id="section-2">
  ## 如需进一步帮助
</div>

* **重新发布后分数未更新：** 请等待约 1～2 分钟——审核会在部署发布后异步执行，结果出来后徽章会随之更新。
* **Agent 更改后分数仍未变化：** 请确认 Agent 已处理相应的 Lighthouse 具体问题，并通过徽章提示查看哪些项目仍被标记。
* **某些页面分数较低：** 徽章会显示所有已抓取 URL 中的最低分数。请让 Agent 专注处理 Lighthouse 标记的特定页面。
* **已发布应用未显示分数：** SEO 评分仅适用于已发布的 Web 部署类型 (Autoscale、Reserved VM、静态部署) 。计划部署和私有部署不会生成分数。
