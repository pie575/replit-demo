使用 Replit，无需担心丢失工作成果。

Replit 的检查点和回滚系统为整个开发环境提供全面的版本控制和状态管理。

使用 Replit Agent 时，检查点会自动保存项目的完整状态。这不仅包括代码更改，还包括项目文件、AI 对话上下文和已连接的数据库。

<div id="section">
  ## 什么是检查点？
</div>

**检查点**是 Agent 在关键开发阶段自动创建的 Replit 应用完整状态快照。不同于仅跟踪代码变更的传统版本控制，Replit 检查点会捕获整个开发上下文。

可以把检查点想象成视频游戏中的存档点。你随时都可以恢复到应用正常运行的版本。

  <img src="/assets/mirror/agent-checkpoint-8e5b8b315c02.png" alt="显示回滚选项的 Agent 检查点界面" width="1554" height="876" data-path="images/replitai/agent-checkpoint.png" />
</Frame>

<div id="section-2">
  ### 完整状态捕获
</div>

每个检查点都会保留：

* **项目文件**：所有文件、目录、已安装的软件包和项目配置
* **AI 对话上下文**：导致当前状态的完整对话记录和上下文
* **环境配置**：运行时设置和发布配置
* **Agent 记忆**：AI 对项目架构、偏好和模式的理解
* **数据库内容**：创建检查点时的数据库数据和架构

这种全面的方法让您可以放心地试验各种更改，因为您知道不仅能恢复代码，还能恢复整个开发上下文。

<div id="section-3">
  ## 回滚如何运作
</div>

使用**回滚**功能，只需点击一下，即可将 Replit 应用恢复到之前的检查点状态。这比传统的 Git revert 操作强大得多。

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="显示回滚选项的检查点回滚界面" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

回滚经过精心设计，既安全又可预测：

* **非破坏性预览**：在某些界面中，你可以在回滚前预览检查点状态
* **清晰的边界**：每个检查点代表一个逻辑开发阶段
* **对话连续性**：AI 上下文会被保留，因此你可以从恢复后的状态继续构建
* **即时生效**：回滚会立即应用于整个开发环境

<div id="section-4">
  ### 执行回滚
</div>

回滚到之前的检查点会将项目恢复到之前的状态，包括：

1. **整个项目状态**：所有项目文件都会恢复到所选检查点时的确切状态
2. **AI 对话上下文**：Agent 对话会恢复到检查点时的状态，以保持上下文的连续性
3. **项目配置**：依赖项、软件包和运行时配置
4. **开发环境**：工具配置和 Project Editor 设置
5. **数据库内容 (可选)&#x20;**：如果选择此项，数据库将恢复到检查点时的状态

<Info>
  默认情况下，回滚不会更改数据库。要在回滚中包含开发数据库，请在“其他回滚选项”中选择“数据库”。

  请注意，**[生产数据库](/zh/ko/features/data-and-storage/development-and-production)**不会通过此回滚功能自动恢复。
  如需了解如何将生产数据库恢复到之前的时间点，请参阅[有关执行时间点恢复的文档](/zh/ko/features/data-and-storage/development-and-production)。
</Info>

<Warning>
  使用回滚功能会将 Replit 应用恢复到之前的状态。这会移除该时间点之后所做的所有更改，包括代码编辑。如果选择恢复数据库，数据库中的更改也会被撤销。
</Warning>

<div id="section-5">
  ### 前滚
</div>

Replit 的检查点支持双向操作——你可以在项目历史记录中向前或向后移动。
这让你能够自由探索开发时间线，无需担心丢失工作内容。

如果回滚过多，或想恢复后续检查点中的更改，可以使用**前滚**在检查点历史记录中向前移动。这样你便可以自由探索项目时间线，而不会丢失工作内容。

要前滚，请点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" />，访问 Agent 标签页中的历史记录视图，然后选择当前所在位置之后的检查点。

<Info>
  只有当前所在位置之后存在检查点时，才能前滚。如果你在回滚后进行了新更改，后续检查点将成为另一条历史分支的一部分。
</Info>

这种双向浏览功能让你能够完全掌控项目时间线，确保工作内容始终可以恢复。

<div id="section-6">
  ## 创建 检查点
</div>

在开发过程中，Replit 的 AI 工具会在关键时机自动创建 检查点。

<div id="agent">
  ### Agent 检查点
</div>

[Replit Agent](/zh/ko/features/agent/overview)会在以下情况下创建检查点：

* **功能完成**：成功实现所需功能后
* **重要里程碑**：复杂任务取得显著进展时
* **稳定状态**：对已实现的更改完成测试和验证后
* **错误恢复**：尝试修复严重问题之前

<div id="section-7">
  ### 检查点特性
</div>

每个检查点包含以下信息：

* **AI 生成的说明**：清晰概述已完成的工作
* **时间戳信息**：准确的创建时间，便于识别
* **变更范围**：标明修改过的文件、功能或系统
* **计费信息**：对于 Agent，按检查点透明追踪费用

<div id="section-8">
  ## 使用检查点和回滚
</div>

<div id="section-9">
  ### 查找检查点
</div>

检查点会显示在 Project Editor 的多个位置：

**Agent 选项卡**：查看 Agent 创建的所有检查点，包括说明和回滚选项
**Git 窗口**：将检查点显示为 Git 提交，并提供完整的版本控制集成
**历史记录视图**：在 Agent 聊天中点击历史记录图标 <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="历史记录图标" width="24" height="24" data-path="images/icons/history.svg" />，即可查看所有检查点及其变更进度的完整时间线

<div id="section-10">
  ### 执行回滚
</div>

回滚流程会因起始位置不同而略有差异：

<div id="agent-2">
  #### 在 Agent 标签页中
</div>

<Steps>
  <Step title="前往 Agent">
    在 Project Editor 中打开 **Agent** 标签页，查看 Agent 创建的所有检查点。
  </Step>

  <Step title="选择检查点">
    找到要恢复的检查点，然后选择 **回滚至此处**。
  </Step>

  <Step title="确认回滚">
    查看并确认回滚警告，将应用恢复到所选状态。
  </Step>

  <Step title="确认恢复">
    确认项目文件、数据库和 AI 上下文与恢复后的检查点状态一致。
  </Step>
</Steps>

<div id="section-11">
  ### 最佳实践
</div>

**策略性地使用检查点**：

* 在每个重要检查点后测试应用，确认其稳定性
* 除自动检查点外，还应创建手动 Git 提交，以便长期跟踪版本
* 查看检查点说明，了解具体变更内容

**回滚时的注意事项**：

* 回滚前务必确认变更范围
* 考虑对数据库和外部集成的影响
* 将回滚情况告知协作者，确保团队成员及时知情

**迭代开发**：

* 逐步构建，充分利用频繁创建的检查点
* 使用回滚安全地探索不同的实现方式
* 利用 AI 上下文保留功能，在回滚后继续 Conversation

<div id="section-12">
  ## 与版本控制集成
</div>

检查点可与 Replit 更广泛的版本控制生态系统无缝配合：

<div id="git">
  ### Git 集成
</div>

* **创建 Git 提交**：每个检查点都会创建相应的 Git 提交
* **分支兼容性**：检查点会遵循分支结构和合并工作流
* **远程同步**：GitHub 集成可保持检查点同步
* **命令行访问**：您仍可结合检查点使用完整的 Git 功能

<div id="section-13">
  ### 协作功能
</div>

* **团队可见性**：所有项目协作者都能看到检查点
* **减少合并冲突**：合理设置检查点可降低冲突风险
* **共享上下文**：AI 对话上下文可帮助团队成员了解变更内容
* **实时更新**：协作者可以实时看到检查点的创建

<div id="section-14">
  ## 高级功能
</div>

<div id="section-15">
  ### 检查点预览
</div>

部分界面支持检查点预览：

* **直观比较**：查看应用在不同检查点状态下的效果
* **非破坏性探索**：无需实际回滚即可预览
* **进度跟踪**：了解应用如何随时间演进
* **迭代比较**：比较不同的实现方式

<div id="section-16">
  ### 跨会话回滚
</div>

面向高级构建者和团队管理员的功能：

* **扩展历史记录**：可访问跨多个开发会话的检查点
* **管理员控制**：团队管理员可跨用户会话执行回滚
* **审计追踪**：完整记录检查点的创建和回滚操作

<div id="section-17">
  ## 使用场景
</div>

<div id="section-18">
  ### 实验性开发
</div>

检查点让你能够放心地进行实验：

* 知道可以轻松回退后，放心尝试新功能
* 测试不同的架构方案
* 探索替代的界面设计或用户流程
* 借助安全网实现复杂集成

<div id="section-19">
  ### 调试与恢复
</div>

出现问题时，检查点可帮助你可靠地恢复：

* 出现错误时回滚到可正常运行的状态
* 比较检查点状态，定位问题
* 数据损坏后恢复数据库完整性
* 从误删或误修改中恢复

<div id="section-20">
  ### 学习与迭代
</div>

检查点助力学习型开发：

* 比较不同的实现策略
* 通过检查点的演进了解 AI 的决策过程
* 探索功能如何演进，逐步加深理解
* 在可安全回滚的前提下练习新技术
