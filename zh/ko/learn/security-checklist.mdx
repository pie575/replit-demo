本指南提供了一份全面的安全检查清单，帮助您的 Vibe Coding 应用遵循最佳安全实践。

虽然 Replit [默认提供](/zh/ko/features/security/overview)许多安全功能，但了解并实施满足特定应用需求的额外安全措施同样重要。

<div id="section-2">
  ## 前端安全
</div>

<AccordionGroup>
  <Accordion title="全程使用 HTTPS" icon="lock">
    Replit 默认会为所有应用启用 HTTPS，无需担心！
  </Accordion>

  <Accordion title="验证并清理输入" icon="shield-check">
    为防范跨站脚本 (XSS) 攻击，请始终验证并清理用户输入：

    ```javascript theme={null}
    // 错误示例：直接使用用户输入
    element.innerHTML = userInput;

    // 正确示例：使用前清理输入
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    询问 Agent：

    ```
    请帮我验证并清理输入，以防范 XSS 攻击
    ```
  </Accordion>

  <Accordion title="不要在浏览器中存放敏感数据" icon="eye-slash">
    如需存储 API 密钥等敏感信息，应使用 Replit 密钥。

    请勿在以下位置传递或存储密钥：

    * 本地存储
    * 会话存储
    * 客户端 JavaScript
    * 未设置适当安全属性的 Cookie

    询问 Agent：

    ```
    请帮我确保敏感数据不会暴露在浏览器中。我的做法正确吗？
    ```
  </Accordion>

  <Accordion title="CSRF 防护" icon="shield">
    在表单中实施跨站请求伪造 (CSRF) 防护：

    ```javascript theme={null}
    // CSRF 令牌实现示例
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    询问 Agent：

    ```
    请帮我在表单中实现 CSRF 令牌
    ```
  </Accordion>
</AccordionGroup>

<div id="section-3">
  ## 后端安全
</div>

<AccordionGroup>
  <Accordion title="身份验证基础" icon="key">
    实现身份验证时：

    * 尽可能使用 Replit Auth
    * 如需构建自定义身份验证，请使用经过验证的库
    * 不要以明文存储密码

    询问 Agent：

    ```
    请帮助我使用 Replit Auth 为我的应用实现身份验证
    ```
  </Accordion>

  <Accordion title="授权检查" icon="user-lock">
    执行操作前，务必检查权限：

    ```javascript theme={null}
    // 授权检查示例
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    询问 Agent：

    ```
    请帮助我为我的应用实现授权检查
    ```
  </Accordion>

  <Accordion title="保护 API 端点" icon="shield">
    确保 API 端点安全：

    * 为敏感端点添加身份验证
    * 配置适当的 CORS
    * 考虑实施速率限制

    询问 Agent：

    ```
    如何在我的应用中正确验证端点？
    ```
  </Accordion>

  <Accordion title="防范 SQL 注入" icon="database">
    Agent 默认使用 ORM 来防范 SQL 注入。如果您要编写自定义数据库查询：

    ```javascript theme={null}
    // 错误示例：在查询中拼接字符串
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // 正确示例：使用 ORM 的参数化查询
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="安全标头" icon="code">
    为应用添加重要的安全标头：

    ```html theme={null}
    <!-- 通过 index.html 或后端添加 -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    您可以在 [securityheaders.com](https://securityheaders.com) 扫描网站，获取建议。

    询问 Agent：

    ```
    可以帮我为应用添加安全标头吗？
    ```
  </Accordion>
</AccordionGroup>

<div id="section-4">
  ## 持续落实安全最佳实践
</div>

<AccordionGroup>
  <Accordion title="保持依赖项更新" icon="arrow-rotate-right">
    定期检查过时的软件包是否存在漏洞：

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="妥善处理错误" icon="exclamation">
    请勿在错误消息中泄露敏感信息：

    ```javascript theme={null}
    // 错误示例：泄露敏感详细信息
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // 正确示例：通用错误消息
    catch (err) {
      console.error(err); // 在内部记录日志
      res.status(500).send('An error occurred');
    }
    ```

    询问 Agent：

    ```
    请帮助我为应用实现妥善的错误处理
    ```
  </Accordion>

  <Accordion title="安全 Cookie" icon="cookie">
    使用 Cookie 时：

    * 设置 HttpOnly 标志，防止 JavaScript 访问
    * 使用 Secure 属性，确保仅通过 HTTPS 传输
    * 设置 SameSite 属性，防范 CSRF

    询问 Agent：

    ```
    请帮助我保护应用中的 Cookie 安全
    ```
  </Accordion>

  <Accordion title="文件上传安全" icon="upload">
    如果你的应用允许上传文件：

    * 限制文件类型和大小
    * 尽可能进行恶意软件扫描
    * 将文件存储在 Replit 的对象存储中
    * 使用新生成的文件名，而非用户提供的名称

    询问 Agent：

    ```
    请帮助我保护应用中的文件上传安全
    ```
  </Accordion>

  <Accordion title="速率限制" icon="clock">
    实施速率限制，尤其是针对身份验证相关的 API 端点：

    ```javascript theme={null}
    // 速率限制中间件示例
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 分钟
      max: 100 // 将每个 IP 在每个 windowMs 内限制为 100 个请求
    });

    app.use('/api/', limiter);
    ```

    询问 Agent：

    ```
    请帮助我为应用实现速率限制
    ```
  </Accordion>
</AccordionGroup>

<div id="section-5">
  ## 检查清单
</div>

我们将上述内容整理成一份检查清单，帮助你落实安全最佳实践。

<div id="section-6">
  ## 前端安全
</div>

|   | 安全措施          | 说明                     |
| - | ------------- | ---------------------- |
| ☐ | 全程使用 HTTPS    | 防范基本的窃听和中间人攻击          |
| ☐ | 验证并清理输入       | 验证所有用户输入，防范 XSS 攻击     |
| ☐ | 不在浏览器中存储敏感数据  | 不在本地存储或客户端代码中存放密钥      |
| ☐ | CSRF 防护       | 为表单和状态变更请求实施 CSRF 防护令牌 |
| ☐ | 不在前端暴露 API 密钥 | 始终将 API 凭据保留在服务器端      |

<div id="section-7">
  ## 后端安全
</div>

|   | 安全措施      | 说明                                             |
| - | --------- | ---------------------------------------------- |
| ☐ | 身份验证基础  | 使用经过验证的库，并妥善存储密码 (哈希+加盐)                       |
| ☐ | 授权检查      | 执行操作前始终检查权限                                    |
| ☐ | 保护 API 端点 | 为所有 API 端点实施适当的身份验证                            |
| ☐ | 防范 SQL 注入 | 使用参数化查询或 ORM，禁止在原始 SQL 中直接使用用户输入               |
| ☐ | 基本安全标头    | 实施 X-Frame-Options、X-Content-Type-Options、HSTS |
| ☐ | DDoS 防护   | 使用具备基本 DDoS 缓解功能的 CDN 或云服务                     |

<div id="section-8">
  ## 实用的安全实践
</div>

|   | 安全措施      | 说明                             |
| - | --------- | ------------------------------ |
| ☐ | 保持依赖项更新   | 大多数漏洞来自过时的库                    |
| ☐ | 妥善处理错误    | 不要在错误消息中泄露敏感信息                 |
| ☐ | 安全 Cookie | 设置 HttpOnly、Secure、SameSite 属性 |
| ☐ | 文件上传安全    | 验证文件类型和大小，并扫描恶意内容              |
| ☐ | 速率限制      | 在所有 API 端点上实施，尤其是与身份验证相关的端点    |
