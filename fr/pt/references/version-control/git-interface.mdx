Le panneau Git de Replit offre une interface visuelle pour les opérations Git, sans avoir à utiliser de commandes Git dans la ligne de commande. Cette fonctionnalité rend le contrôle de version accessible aux débutants tout en restant performante pour les développeurs expérimentés.

<div id="recursos">
  ## Fonctionnalités
</div>

Le panneau Git offre des fonctionnalités complètes de contrôle de version directement dans le Project Editor, avec une interface conviviale qui simplifie les opérations Git complexes.

* **Gestion des dépôts** : Initialisez, connectez et gérez des dépôts Git grâce à l’intégration GitHub
* **Suivi des commits** : Ajoutez les modifications à l’index, effectuez des commits et visualisez les changements dans tous vos fichiers
* **Opérations sur les branches** : Créez des branches, passez de l’une à l’autre et fusionnez-les visuellement
* **Résolution des conflits** : Identifiez et résolvez les conflits de fusion avec une assistance visuelle
* **Intégration avec le Shell** : Synchronisation entre les commandes Git exécutées dans le Shell et le panneau Git

<div id="uso">
  ## Utilisation
</div>

<div id="configurao-do-repositrio">
  ### Configuration du dépôt
</div>

<Accordion title="Comment accéder au panneau Git">
  1. Accédez à la section Tools de votre Replit App
  2. Sélectionnez le signe **+** pour ajouter de nouveaux outils
  3. Sélectionnez **Git** dans la liste des outils disponibles
</Accordion>

Le panneau Git vous aide à configurer et à connecter votre dépôt :

* **Initialize repository** : créez un dépôt Git pour votre Replit App
* **Connect to GitHub** : reliez votre dépôt à GitHub pour la sauvegarde et la collaboration
* **Configure remote** : paramétrez et gérez la connexion à votre dépôt GitHub

<div id="gerenciamento-de-alteraes">
  ### Gestion des modifications
</div>

<Accordion title="Comment visualiser les modifications">
  1. Modifiez n&#39;importe quel fichier de votre Replit App
  2. Ouvrez le Git Pane dans la section Tools
  3. Passez en revue les modifications dans la section **Review Changes**
</Accordion>

Le Git Pane offre des outils pour gérer les modifications de votre code :

* **Review changes** : consultez les fichiers modifiés, ajouts et suppressions mis en évidence
* **Stage files** : sélectionnez les fichiers à inclure dans votre prochain commit
* **Commit changes** : enregistrez vos modifications accompagnées de messages descriptifs
* **Push updates** : envoyez vos commits vers GitHub en un seul clic

<Note>
  Vous pouvez faire appel à Replit AI pour générer des messages de commit qui décrivent précisément vos modifications.
</Note>

<div id="gerenciamento-de-branches">
  ### Gestion des branches
</div>

<Accordion title="Comment gérer les branches">
  1. Ouvrez le Git Pane dans la section Tools
  2. Sélectionnez le menu déroulant des branches à côté du nom de la branche
  3. Créez une nouvelle branche ou sélectionnez-en une existante
</Accordion>

Le Git Pane facilite le travail sur plusieurs versions de votre code :

* **Create branches** : créez de nouvelles branches pour développer des fonctionnalités de façon isolée
* **Switch branches** : passez d&#39;une version de votre code à une autre
* **Publish branches** : partagez vos branches sur GitHub
* **Pull changes** : récupérez les mises à jour distantes de vos collaborateurs

<div id="resoluo-de-conflitos-de-merge">
  ### Résolution des conflits de fusion
</div>

<Accordion title="Comment résoudre les conflits de fusion">
  1. Lancez un pull en présence de conflits
  2. Le panneau Git met en évidence les fichiers en conflit
  3. Ouvrez chaque fichier en conflit pour visualiser et résoudre les conflits
  4. Enregistrez les fichiers une fois les conflits résolus
  5. Finalisez la fusion en sélectionnant **Pull**
</Accordion>

Lorsque du code provenant de différentes sources entre en conflit, le panneau Git vous permet de :

* **Identify conflicts** : identifier précisément les fichiers qui contiennent des conflits
* **Visualize differences** : comparer les deux versions du code en conflit
* **Resolve issues** : choisir le code à conserver ou modifier manuellement les conflits
* **Finalize merges** : achever le processus de fusion une fois les conflits résolus

<Frame>
  <img src="/assets/mirror/11-merge-conflict-17b314f0e231.png" alt="Éditeur de code affichant des marqueurs de conflit de fusion" width="526" height="108" data-path="images/gh/pane/11-merge-conflict.png" />

Une fois un fichier en conflit résolu, vous pouvez supprimer les marqueurs de conflit en effaçant les lignes commençant par des symboles de conflit, puis enregistrer le fichier.

<div id="usando-comandos-git-no-shell">
  ### Utiliser les commandes Git dans le Shell
</div>

<Accordion title="Accéder au Shell">
  1. Sélectionnez **All tools** dans le dock d’outils situé à gauche
  2. Sélectionnez **Shell** parmi les outils disponibles
</Accordion>

<Tip>
  Bien que le panneau Git propose une interface conviviale, les utilisateurs avancés peuvent utiliser les commandes Git standard dans le Shell pour effectuer des opérations plus complexes. Les modifications apportées par l’une ou l’autre méthode seront répercutées dans les deux emplacements.
</Tip>

Si vous préférez utiliser Git en ligne de commande :

* **Synchronisation des commandes** : toutes les commandes Git exécutées dans le Shell sont automatiquement synchronisées avec le panneau Git
* **Fonctionnalités Git complètes** : accédez à des fonctionnalités Git avancées qui ne sont pas disponibles dans le panneau Git
* **Basculement fluide** : passez des commandes du Shell au panneau Git selon vos besoins

<Info>
  **Prise en charge des interfaces de ligne de commande GitHub et GitLab** : en plus des commandes Git standard, vous pouvez également utiliser la [GitHub CLI](https://docs.github.com/en/github-cli) (`gh`) et la [GitLab CLI](https://docs.gitlab.com/ee/editor_extensions/gitlab_cli/) (`glab`) dans le Shell pour gérer des dépôts Git externes et vous y connecter. Ces outils offrent des fonctionnalités avancées pour travailler avec des dépôts GitHub et GitLab, notamment les pull requests, les issues et d’autres fonctionnalités propres à ces plateformes.
</Info>

<div id="operaes-de-repositrio">
  #### Opérations sur les dépôts
</div>

* **Cloner un dépôt** : `git clone <url-du-depot>`
* **Initialiser un dépôt** : `git init`
* **Ajouter un dépôt distant** : `git remote add origin <url-du-depot>`

<div id="fazendo-alteraes">
  #### Effectuer des modifications
</div>

* **Vérifier l&#39;état** : `git status` (affiche les fichiers modifiés, ajoutés et supprimés)
* **Indexer des fichiers** : `git add <nom-du-fichier>` ou `git add .` (pour tous les fichiers)
* **Valider les modifications (commit)** : `git commit -m "votre message de commit"`
* **Envoyer les modifications (push)** : `git push origin <nom-de-la-branche>`
* **Récupérer les modifications (pull)** : `git pull origin <nom-de-la-branche>`

<div id="autenticao">
  #### Authentification
</div>

Lorsque vous travaillez avec des dépôts privés, vous devez vous authentifier :

* Pour les dépôts GitHub, utilisez un jeton d&#39;accès personnel au lieu de votre mot de passe
* Pour éviter de ressaisir vos identifiants, vous pouvez les stocker à l&#39;aide des Secrets de Replit :
  1. Créez un nouveau secret avec la clé `GIT_URL`
  2. Définissez la valeur sur `https://<usuario>:<token>@github.com/<usuario-ou-org>/<repositorio>`
  3. Utilisez `git push $GIT_URL` pour pousser vos modifications sans saisir d&#39;identifiants

<Note>
  Lorsque vous stockez vos identifiants dans des secrets, toute personne ayant accès à votre Replit App peut potentiellement accéder à vos identifiants Git. Pour les dépôts sensibles, envisagez de saisir les identifiants manuellement à chaque fois.
</Note>
