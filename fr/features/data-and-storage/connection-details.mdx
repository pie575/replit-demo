Votre app se connecte à sa base de données à l&#39;aide d&#39;identifiants gérés par Replit pour vous. Vous les trouverez dans l&#39;outil **Database** : sélectionnez une base de données, puis ouvrez l&#39;onglet **Settings**. Celui-ci affiche la chaîne de connexion, l&#39;utilisation du stockage et les détails de connexion avancés.

<div id="environment-variables">
  ## Variables d&#39;environnement
</div>

La variable d&#39;environnement suivante est disponible pour vous connecter à votre base de données de développement :

* `DATABASE_URL` : comment se connecter et s&#39;authentifier à la base de données

Votre application l&#39;utilise automatiquement. Comme `DATABASE_URL` est limitée à votre application, votre base de données de développement ne peut pas être consultée par d&#39;autres applications, même celles qui vous appartiennent, ni par des visualiseurs de bases de données externes. Même en cas de fuite, personne d&#39;autre ne pourrait s&#39;en servir pour accéder à votre base de données et la modifier.

<Info>
  Si votre base de données de développement repose encore sur [l&#39;ancienne infrastructure Neon](/fr/features/data-and-storage/development-and-production#legacy-development-database), les variables supplémentaires `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` et `PGPORT` sont également disponibles. Elles ne sont **pas** fournies pour les bases de données hébergées sur l&#39;infrastructure actuelle de Replit ; utilisez plutôt `DATABASE_URL`.
</Info>

<Warning>
  Si vous utilisez encore l&#39;ancienne base de données de développement Neon, ne partagez pas votre `DATABASE_URL`. Elle contient les identifiants de votre base de données, que n&#39;importe qui pourrait utiliser pour y accéder et la modifier. Ne la collez jamais dans des espaces publics ni dans des tickets d&#39;assistance.
</Warning>

<div id="connect-an-external-tool">
  ## Connecter un outil externe
</div>

Vous pouvez vous connecter à votre base de données de **production** depuis n&#39;importe quel client SQL compatible PostgreSQL, à l&#39;aide de la chaîne de connexion disponible dans l&#39;onglet **Settings** de la base de données de production.

<div id="security">
  ## Sécurité
</div>

Lorsque vous ajoutez une intégration de base de données via Agent, celui-ci met en place un ORM (Object-Relational Mapper) qui gère l&#39;ensemble des communications avec la base de données et intègre des mécanismes de sécurité :

* **Validation du schéma** : vérifie que les données sont conformes aux formats attendus
* **Assainissement des données** : nettoie automatiquement les entrées du builder afin de prévenir les attaques par injection SQL

<div id="regenerate-production-database-credentials">
  ## Régénérer les identifiants de la base de données de production
</div>

Si une chaîne de connexion de production a été exposée, régénérez ses identifiants dans l&#39;outil Database. Cette action crée un nouveau mot de passe pour la base de données de production Neon. Les chaînes de connexion de production existantes cessent immédiatement de fonctionner.

Vous pouvez régénérer les identifiants si toutes ces conditions sont réunies :

* Votre app dispose d&#39;une base de données de production Neon.
* Vous êtes le propriétaire de l&#39;app ou un administrateur du workspace propriétaire.
* Vous utilisez Replit dans un navigateur web.
* Aucun deployment n&#39;est en cours.
* Si votre app possède un deployment en ligne, son dernier build s&#39;est terminé avec succès et utilise [Autoscale ou une Reserved VM](/fr/features/publishing/deployment-types).

<Warning>
  Cette action est irréversible. Les chaînes de connexion existantes cessent
  immédiatement de fonctionner. Si votre app possède un deployment en ligne, celui-ci peut être brièvement indisponible
  pendant le redéploiement.
</Warning>

<div id="regenerate-the-credentials">
  ### Régénérer les identifiants
</div>

1. Dans le volet Outils, sélectionnez **Database**.

2. Sélectionnez **Base de données de production**, puis l&#39;onglet **Settings**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-settings-827c7718a25f.webp" alt="L'onglet Settings de la base de données de production affichant la chaîne de connexion, l'utilisation du stockage et la section Advanced avec la ligne Regenerate credentials." width="2314" height="1608" data-path="images/databases/database-regenerate-credentials-settings.webp" />
   </Frame>

3. Sous **Advanced**, développez la ligne **Regenerate credentials**.

4. Sélectionnez le bouton **Regenerate credentials**.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-button-ab9631f21b85.webp" alt="La ligne Regenerate credentials développée dans la section Advanced, affichant le bouton Regenerate credentials." width="2206" height="1876" data-path="images/databases/database-regenerate-credentials-button.webp" />
   </Frame>

5. Dans la boîte de dialogue de confirmation, sélectionnez **Regenerate credentials** pour confirmer.

   <Frame>
     <img src="/assets/mirror/database-regenerate-credentials-dialog-2477fc96f82b.webp" alt="La boîte de dialogue de confirmation Regenerate credentials avertissant que l'action est irréversible et que les chaînes de connexion existantes cessent immédiatement de fonctionner." width="1364" height="638" data-path="images/databases/database-regenerate-credentials-dialog.webp" />
   </Frame>

6. Sélectionnez **Refresh** pour charger la nouvelle chaîne de connexion.

7. Si votre app dispose d&#39;un deployment en ligne, ouvrez **Publishing** et suivez le redéploiement.

8. Remplacez toutes les chaînes de connexion que vous avez copiées dans des outils externes ou des integrations personnalisées.

<div id="what-changes">
  ### Ce qui change
</div>

La régénération des identifiants crée un nouveau mot de passe pour la base de données de production. Seule la partie mot de passe de la chaîne de connexion change : l&#39;hôte, le nom de la base de données et le rôle restent inchangés.

Pour un deployment en ligne pris en charge, Replit redéploie le dernier build réussi avec la chaîne de connexion mise à jour.
