Replit Agent 提供两种交互模式：**Plan 模式**和 **Build 模式**。将二者结合使用，先理清思路，再放心动手实现。

<div id="what-is-plan-mode">
  ## 什么是 Plan Mode？
</div>

[Plan Mode](/zh/features/agent/plan-mode) 让你可以与 Agent 一起头脑风暴、提问并规划工作，而不会改动任何代码。你可以把它看作一次协作式的规划会议，在其中自由地探索各种想法。

Plan Mode 非常适合：

* **头脑风暴**：在确定方案之前先探索不同思路
* **拆解复杂项目**：在动手构建之前得到一份结构化的任务清单
* **学习与理解**：就相关技术、模式或你的代码库提出问题
* **规划架构**：在编写代码之前设计好应用的结构

<Info>
  在 Plan Mode 下，Agent 会读取你的项目并提供建议，但不会对文件做任何更改。准备好动手实现时，切换到 Build Mode 或批准某个计划，即可自动开始构建。
</Info>

<div id="what-is-build-mode">
  ## 什么是 Build 模式？
</div>

Build 模式是默认模式，Agent 会在此模式下编写代码、修改文件，并直接在你的项目中实现功能。创意正是在这里变为现实。

当你准备好做以下事情时，就可以使用 Build 模式：

* **创建新功能**：让 Agent 为你的下一个功能编写代码
* **搭建应用**：安装依赖项、配置数据库并连接服务
* **修复问题**：让 Agent 调试并解决代码库中的问题
* **重构代码**：优化现有代码的结构与组织方式

<div id="using-both-modes-together">
  ## 结合使用两种模式
</div>

**Plan Mode 和 Build Mode 按先后顺序配合使用效果最佳。** 先通过规划理清思路，再带着明确的方向开始构建。

<Steps>
  <Step title="从 Plan Mode 开始">
    切换到 Plan Mode，描述你想构建的内容。Agent 会帮你梳理需求、提出实现思路并指出潜在难点——整个过程完全不会改动你的代码。
  </Step>

  <Step title="生成任务清单">
    让 Agent 制定一份开发计划。它会将你的项目拆解为具体、可执行的任务，并标明优先级和依赖关系。

    <Frame>
      <img src="/assets/mirror/plan-mode-task-list-6adcdd56f689.png" alt="带优先级和依赖关系的生成任务清单" width="924" height="1180" data-path="images/replitai/plan-mode-task-list.png" />
    </Frame>
  </Step>

  <Step title="审阅并完善">
    审阅生成的计划。你可以追问、要求修改，或探索其他实现方案。反复迭代，直到计划符合你的设想。
  </Step>

  <Step title="开始构建">
    对计划满意后，选择 **Start building**。Agent 会自动切换到 Build Mode，开始实现已确认的任务。

    <Frame>
      <img src="/assets/mirror/plan-mode-selector-a4f6b14596fa.png" alt="显示 Plan mode 和 Build mode 选项的模式选择器" width="918" height="224" data-path="images/replitai/plan-mode-selector.png" />
    </Frame>
  </Step>

  <Step title="跟踪进度">
    在 Agent 逐项完成任务清单的过程中关注其进度。每完成一项任务都会创建一个 checkpoint，方便你审阅改动，必要时回滚。
  </Step>
</Steps>

<div id="when-to-use-each-mode">
  ## 何时使用哪种模式
</div>

<CardGroup cols={2}>
  <Card title="适合使用 Plan 模式的场景" icon="lightbulb">
    * 你正要启动一个新的项目，需要明确方向
    * 你想尝试不同的实现思路
    * 任务较为复杂，需要拆解
    * 你希望先弄清楚再动手
    * 你还不确定哪种方案最合适
  </Card>

  <Card title="适合使用 Build 模式的场景" icon="hammer">
    * 你非常清楚自己想要什么
    * 你已经有了可直接执行的明确计划
    * 你要做快速修复或小幅改动
    * 你正在按已确认的任务清单推进
    * 实现速度是第一优先
  </Card>
</CardGroup>

<Tip>
  **不确定该选哪个？** 如果你的需求涉及多项功能或较大改动，请从 Plan 模式开始；对于简单、明确的任务，直接用 Build 模式即可。
</Tip>

<div id="key-differences">
  ## 主要区别
</div>

| 特性       | Plan 模式      | Build 模式   |
| -------- | ------------ | ---------- |
| **用途**   | 头脑风暴、规划与学习   | 实现与构建      |
| **代码变更** | 无——只读        | 写入并修改文件    |
| **产出**   | 想法、任务清单、指导   | 可运行的代码与功能  |
| **适用场景** | 复杂项目、探索阶段    | 明确的任务、具体实现 |
| **切换方式** | 点击“开始构建”即可切换 | 已处于实现模式    |

<div id="best-practices">
  ## 最佳实践
</div>

<div id="getting-the-most-from-plan-mode">
  ### 充分利用 Plan 模式
</div>

* **明确说明需求**：提供的细节越多，生成的计划就越好
* **主动追问**：对不理解的建议及时求证
* **索要示例**：让 Agent 展示代码片段或实现模式
* **讨论取舍**：权衡不同方案的优缺点
* **反复打磨思路**：不断优化计划，直到满意为止

<div id="seamless-transitions">
  ### 无缝衔接
</div>

* **构建前先审查**：批准前务必先查看任务清单
* **从小处着手**：如果完整计划让你感到难以下手，可以先从其中一部分任务做起
* **善用 checkpoint**：Agent 在构建过程中会自动创建 checkpoint，你随时可以回滚
