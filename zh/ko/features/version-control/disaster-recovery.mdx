---
title: "Git 灾难恢复"
description: "了解如何使用 Replit 的自动备份系统恢复 Git 历史记录和代码。"
---

Replit 会自动备份 Git 仓库，帮助你从 `.git` 文件夹损坏或提交记录丢失等问题中恢复。备份系统会在后台运行，无需额外操作即可保护你的工作。

<div id="section">
  ## 工作原理
</div>

每个 Replit 应用都会保留 Git 仓库的安全备份。每当 Replit Agent 修改代码或你发布应用时，这些更改都会自动同步到该备份。如果本地 Git 仓库损坏或不可用，你可以从备份中恢复完整的提交历史。

<Info>
  备份远程仓库名为 `gitsafe-backup`，由 Replit 自动管理。无需额外配置，它已在后台运行。
</Info>

<div id="section-2">
  ## 查看备份历史记录
</div>

查看提交历史记录最简单的方法是使用 [Git 窗口](/zh/ko/features/workspace-tools/git-interface)。在 Project Editor 的 Tools 部分打开 Git 窗口后，即可查看完整的提交历史记录，其中包括所有 Agent 检查点。大多数情况下，无需运行命令即可完成操作。

如果需要直接查看 gitsafe-backup 远程仓库，可以使用 Shell：

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

这样会显示完整的提交历史记录，包括所有 Agent 检查点和手动提交。您可以借此确认工作是否已备份，或查找要恢复到的特定提交。

<div id="git">
  ## 从 Git 问题中恢复
</div>

如果遇到 Git 错误或仓库损坏，请先使用 [Git 窗口](/zh/ko/features/workspace-tools/git-interface)。无需使用 Shell 命令，即可解决大多数常见问题，例如重置到之前的提交或从远程拉取。

如果无法通过 Git 窗口解决问题 (例如 `.git` 文件夹完全损坏) ，请使用以下基于 Shell 的步骤。

<div id="section-3">
  ### 检查是否有可用备份
</div>

首先，确认备份远程仓库是否存在：

```bash theme={null}
git remote -v
```

在输出中查找 `gitsafe-backup`。如果存在该项，您就可以进行恢复。

<div id="section-4">
  ### 恢复仓库
</div>

<Warning>
  此过程会用备份版本替换当前的 `.git` 文件夹。工作文件不会受到影响，但本地 Git 历史记录将被替换为备份中的历史记录。
</Warning>

<Steps>
  <Step title="保存当前 Git 配置">
    请备份 Git 配置文件，以保留任何自定义设置：

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="克隆备份仓库">
    从备份创建一个临时裸克隆：

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="替换 Git 文件夹">
    将损坏的 `.git` 文件夹移到一旁，再用备份替换它：

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="恢复配置">
    将 Git 配置文件复制回原处：

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

完成这些步骤后，运行 `git status`，确认仓库是否正常工作。

<div id="section-5">
  ## 常见故障排查
</div>

<div id="fatal-repository-not-found">
  ### “fatal: repository not found”或缺少备份远程仓库
</div>

旧项目可能未启用备份系统。如需协助恢复旧项目，请联系支持团队。

<div id="section-6">
  ### 恢复不包含最近的提交
</div>

每次 Agent 提交后，备份都会同步。如果你进行了更改但未提交，这些更改将不会包含在备份中。请检查工作目录中是否存在未提交的文件。

<div id="git-2">
  ### Git 操作缓慢或卡住
</div>

如果 Git 操作无响应，可能是存在过期的锁定文件。您可以安全地将其删除：

```bash theme={null}
rm -f .git/index.lock
```

<div id="section-7">
  ## 防止数据丢失
</div>

备份系统会自动保护 Git 历史记录，但您还可以采取以下措施进一步保护工作成果：

* **频繁提交**：创建小而频繁的提交，确保进度持续得到备份
* **使用检查点**：使用 [Replit Agent](/zh/ko/features/agent/overview) 时，检查点会在每个关键步骤自动创建提交
* **连接 GitHub**：对于重要项目，请[将应用连接到 GitHub](/zh/ko/build/import-from-providers)，以增加一层备份保障
