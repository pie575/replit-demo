<div id="how-the-task-board-works">
  ## Task board 작동 방식
</div>

Task board는 Agent task를 한곳에서 검토하고, 시작하고, 모니터링하고, 적용할 수 있게 해줍니다. Agent가 큰 요청을 여러 갈래로 나눌 때, 작업을 백그라운드에서 실행하고 싶을 때, 또는 project에서 이미 변경된 내용을 파악해야 할 때 활용하세요.

  <img src="/assets/mirror/task-board-progress-f4d3b5e7e93e.png" alt="Drafts, Active, Ready, Done 열로 정리된 task를 보여주는 task board" width="3456" height="1984" data-path="images/replitai/task-board-progress.png" />

Task는 상태에 따라 열로 정리됩니다. Board에는 Agent가 계획한 작업, 실행 중인 작업, 검토할 준비가 된 작업, 이미 적용된 작업이 표시됩니다.

각 task는 진행 상황에 따라 왼쪽에서 오른쪽으로 이동합니다.

* **Drafts**: Agent가 계획했지만 아직 시작하지 않은 task
* **Active**: Agent가 현재 building 중인 task로, 활성 task limit에 걸려 대기 중인 task 포함
* **Ready**: Agent가 완료하여 검토를 기다리는 task
* **Done**: 완료, 보관 또는 취소된 task

<div id="drafts">
  ## Drafts
</div>

**Drafts**는 Agent가 아직 빌드를 시작하지 않은 계획 단계의 task입니다. 각 Draft에는 제목, 설명, 단계별 계획이 포함됩니다.

작업을 시작하기 전에 Agent가 제안한 접근 방식을 검토하고 싶다면 Drafts를 활용하세요. 계획을 살펴보고 Agent에게 수정을 요청하거나, 준비가 되면 task를 시작할 수 있습니다.

Drafts는 백그라운드 작업을 확정하기 전에 규모가 큰 기능을 미리 계획하고 싶을 때 유용합니다. 예를 들어 Agent는 온보딩 project를 authentication, 프로필 설정, dashboard UI, deployment 마무리 작업처럼 여러 개의 Draft로 나눌 수 있습니다.

task의 building이 끝나면 **Ready** 상태로 이동합니다. 작업은 완료되었지만 메인 버전에는 아직 아무 변경도 반영되지 않았다는 뜻입니다.

changes를 적용하는 방법은 두 가지입니다.

* **스레드에서**: task의 스레드를 열고 **Apply changes to main version**을 선택해 작업을 project에 반영하거나, **Dismiss**를 선택해 폐기합니다
* **board에서**: Ready 상태의 task 카드에서 three-dot menu를 선택한 뒤 **Apply changes**를 선택합니다

<TaskReviewDrawer />

Ready 상태의 task는 적용하기 전에 반드시 검토하세요. 작업 로그, 테스트 출력, Preview를 확인하면 Agent가 무엇을 변경했는지 파악할 수 있습니다.

<div id="done">
  ## Done
</div>

적용이 완료되면 task 카드가 **Done** 열로 이동합니다.

Done 열에는 보관된 계획 세션과 취소된 task도 함께 표시됩니다. 완료된 작업이 Drafts나 Active로 다시 섞여 들어가지 않으면서도 그동안의 진행 내역을 확인할 수 있습니다.

여러 task의 변경 사항을 적용할 때는 Agent가 충돌을 자동으로 처리합니다. 결과가 이상해 보이면 Agent에게 수정을 요청하세요.

<div id="find-and-filter-tasks">
  ## task 찾기 및 필터링
</div>

프로젝트에 진행 중인 task가 많을 때는 Task board를 사용하세요. task 제목이나 task 번호로 검색하고, 초안을 필터링하고, 편집 모드에서 여러 task을 한 번에 관리할 수 있습니다.

예를 들어 누군가 스레드, 리뷰 또는 Slack 대화에서 특정 task을 언급했다면 task 번호로 검색하세요. 진행 중이거나 완료된 task을 일일이 훑어보지 않고 계획된 작업에만 집중하고 싶다면 초안을 필터링하세요.

추천 후속 task에 대해서는 [후속 task](/ko/features/agent/follow-up-tasks)을 참조하세요.

<div id="rename-a-task">
  ## task 이름 변경
</div>

scope가 바뀌다 보면 길게 이어진 task list는 한눈에 파악하기 어려워집니다. task 이름을 변경하려면 해당 카드(task list 사이드바 또는 task board)의 three-dot menu를 열고 **Rename**을 선택하세요. 더 명확한 제목을 입력한 뒤 **Save**를 선택합니다.

task 이름을 변경하면 여러분과 팀원에게 보이는 이름만 바뀝니다. Agent가 이미 수행한 작업, task 기록, 대기 중인 changes는 그대로 유지됩니다.

<div id="settings-on-each-task">
  ## 각 task별 설정
</div>

모든 task에는 제목 옆에 전용 설정 드롭다운이 있습니다. 이 메뉴에서 Agent가 task를 마무리하는 방식과 결과가 project에 반영되는 방식을 지정할 수 있습니다:

* **Auto-apply changes** (Drafts 및 Active): task가 준비되면 review를 거치지 않고 곧바로 메인 버전에 적용합니다.
* **Auto-approve plan** (Drafts): Agent가 task에 대한 plan을 제안하면 자동으로 수락하고 building을 시작합니다.
* **Apply changes** (Ready): 완료된 작업을 메인 버전에 적용합니다.
* **Rename**: 카드에 표시되는 제목을 변경합니다.
* **Review changes** (Ready): 준비된 task의 diff로 바로 이동합니다.
* **Cancel**: task를 중지하거나 draft를 삭제합니다.

auto-apply와 auto-approve는 한 번만 선택하는 빠른 동작이며, 켜 둔 상태로 유지되는 토글이 아닙니다. 메뉴 너비는 항상 일정하게 유지되므로 여러 task를 번갈아 열어도 label 위치가 흔들리지 않습니다.
