<div id="adicionar-cabealhos-de-resposta">
  ## Добавление заголовков ответа
</div>

Пользовательские **заголовки ответа** позволяют добавлять инструкции HTTP-заголовков к запросам, соответствующим определённым путям.
Заголовок ответа — это пара «имя — значение», содержащая инструкции для браузера о том, как
взаимодействовать с запрошенным содержимым.

Например, можно указать заголовок `Access-Control-Allow-Origin`, чтобы определить, к каким доменам браузер может обращаться с этой страницы.
Чтобы создать эту запись, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.responseHeaders]]
path = "/*"
name = "Access-Control-Allow-Origin"
value = "origin"
```

Этот заголовок ответа включает следующие параметры:

* **path**: Шаблон URL-пути, соответствующий запрашиваемым ресурсам
* **name**: Имя HTTP-заголовка
* **value**: Значение HTTP-заголовка

В файл `.replit` можно добавить несколько записей `deployment.responseHeaders`.

Чтобы применить изменения конфигурации, повторно опубликуйте App в Replit.

<div id="criar-uma-pgina-404-personalizada">
  ## Создание пользовательской страницы 404
</div>

Пользовательская страница 404 отображается, когда пользователи запрашивают URL-пути, не соответствующие ни одному файлу или правилу в опубликованном приложении.

Чтобы добавить пользовательскую страницу 404, создайте её содержимое в файле `404.html` в корневом каталоге вашего Replit App.

Когда пользователи пытаются открыть несуществующий URL-путь, они видят отрисованную пользовательскую страницу 404.

<div id="definir-reescritas-de-caminho-de-url">
  ## Настройка правил перезаписи URL-путей
</div>

Вы можете настроить правила перезаписи URL, чтобы изменить URL-путь запроса до того, как его обработает ваш Replit App.
Исходный URL остаётся видимым в браузере, но сервер загружает ресурс, указанный в правиле перезаписи.

Например, можно указать, чтобы все запросы, начинающиеся с `/app`, загружали содержимое файла `/app/index.html`.
Чтобы создать это правило, добавьте следующее в файл `.replit` в корневом каталоге вашего Replit App:

```
[[deployment.rewrites]]
from = "/app/*"
to = "/app/index.html"
```

* **from**: Шаблон URL-пути, соответствующий запрошенным ресурсам
* **to**: Перезаписанный путь, соответствующий файлу в вашем статическом развёртывании.

В файл `.replit` можно добавить несколько записей `deployment.rewrites`.
Сервер обрабатывает записи в указанном порядке и игнорирует дубликаты.

Чтобы применить изменения конфигурации, необходимо повторно опубликовать Replit App.

В следующих разделах описаны ограничения для правил перезаписи URL.

<div id="correspondncia-de-caminho">
  ### Сопоставление путей
</div>

К параметрам `from` и `to` в правилах перезаписи применяются следующие ограничения:

* Сопоставления должны быть точными, если только не используется `*`
* `*` соответствует оставшейся части пути
* `*` допустим только в конце пути
* Если в параметре `from` используется `*`, его можно указать и в параметре `to`, чтобы представить соответствующую часть пути

Например, если ваш файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/v1/*"
to = "/v2/*"
```

Когда пользователь переходит по пути `/v1/about-us.html`, правило перезаписи отдаёт файл из `/v2/about-us.html`.

<div id="sombreamento">
  ### Затенение
</div>

Затенение возникает, когда правило перезаписи совпадает с URL-путём, который также соответствует файлу в вашем статическом развёртывании.
В этом случае облачный сервер игнорирует правило перезаписи и отдаёт файл напрямую.

Например, предположим, что ваше опубликованное приложение содержит следующие файлы:

* `index.html`
* `about.html`

Файл `.replit` содержит следующее правило перезаписи:

```
[[deployment.rewrites]]
from = "/*"
to = "/index.html"
```

Когда пользователь переходит по адресу `/register.html`, сервер перенаправляет запрос на `/index.html` и отдаёт этот файл.
Однако если пользователь переходит по адресу `/about.html`, сервер игнорирует правило перезаписи и отдаёт файл `about.html`, поскольку он существует в вашем статическом развёртывании.

<div id="restries-de-domnio">
  ### Ограничения домена
</div>

Правила перезаписи работают только для запросов к основному домену вашего статического развёртывания и могут
перенаправлять только к файлам в его пределах.
