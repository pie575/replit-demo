---
title: "Переход с Replit Auth на Clerk"
description: "Используйте Agent, чтобы перевести существующее приложение с Replit Auth на Clerk Auth, сохранив данные пользователей приложения."
---

Воспользуйтесь этим руководством, чтобы перевести существующее приложение с [Replit Auth](/ru/pt/features/auth-and-identity/authentication) на [Clerk Auth](/ru/pt/features/auth-and-identity/clerk-auth). Для подходящих приложений миграцию выполняет Agent, поэтому вернувшиеся пользователи сохраняют доступ к своим данным.

<Note>
  Эта автоматическая миграция предназначена для приложений, использующих Replit Auth. Если в вашем приложении применяется другая система аутентификации, не используйте этот процесс.
</Note>

<div id="inicie-a-migrao">
  ## Запустите миграцию
</div>

Миграции Agent всегда следует запускать в новой задаче.

Запустить миграцию можно одним из следующих способов:

<div id="iniciar-a-partir-do-agent">

</div>

<Steps>
  <Step title="Создайте новую задачу">

  ### Проверьте план миграции
</div>

Каким бы способом вы ни начали, Agent создаёт задачу **Migrate from Replit Auth to Clerk** и готовит план миграции. Нажмите **View plan** и просмотрите план, прежде чем задача продолжится.

Пока Agent работает, не изменяйте код аутентификации вашего приложения и учётные данные Clerk.

<div id="o-que-o-agent-faz">
  ## Что делает Agent
</div>

Agent выполняет миграцию в следующем порядке:

1. Переносит данные пользователей из Replit Auth в Clerk, включая идентификационные сведения об учётной записи и поддерживаемые учётные данные для входа.
2. Дожидается завершения переноса данных и только затем вносит изменения в ваше приложение.
3. Обновляет логику входа и сессий в вашем приложении, перезапускает его и выполняет доступные автоматические проверки.

<div id="os-dados-do-seu-app-permanecem-no-lugar">
  ## Данные вашего приложения остаются на месте
</div>

Agent изменяет только код аутентификации приложения. Он не трогает существующие данные и схему базы данных. Ваши таблицы и связи между ними остаются нетронутыми.

Существующие пользователи по-прежнему связаны со своими записями: профилями, сохранённой работой и правами доступа.

<div id="quanto-tempo-leva">
  ## Сколько времени это займёт
</div>

Будьте готовы к тому, что Agent будет работать от 10 минут до часа. Сама миграция данных может занять несколько минут для небольших приложений и до нескольких часов для приложений с большим числом пользователей. Agent не начнёт вносить изменения в код вашего приложения, пока эта миграция не завершится.

<div id="depois-da-migrao">
  ## После миграции
</div>

Перед публикацией протестируйте обновлённое приложение в среде разработки:

1. Войдите в существующую учётную запись и убедитесь, что сохранённые данные на месте.
2. Выйдите и войдите снова.
3. Создайте новую тестовую учётную запись и убедитесь, что с ней приложение работает как ожидается.
