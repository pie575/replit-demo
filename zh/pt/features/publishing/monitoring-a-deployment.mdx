Monitoring 工具可以回答关于已发布应用的三个问题：它是否在线？运行表现如何？消耗了哪些资源？在 **Tools** 面板的 **Replit Cloud** 中打开 **Monitoring**。

应用发布之后，监控才会开始。在此之前，该工具会显示 **No deployment yet** 提示。

<Note>
  想了解访客和用户的相关信息？请在 **Growth** 面板中打开 [Project
  Analytics](/zh/pt/features/publishing/project-analytics)。
</Note>

<div id="application-monitoring">
  ## Application monitoring
</div>

Application monitoring 会从访问者的视角展示你的应用运行状况。在顶部选择时间范围，即可放大或缩小查看粒度。

<Frame>
  <img src="/assets/mirror/application-monitoring-475523d92a9b.png" alt="Application monitoring 视图，展示 uptime 监控、包含唯一 IP 地址的请求图表、HTTP 状态和请求时长" width="2000" height="1656" data-path="images/deployments/monitoring/application-monitoring.png" />
</Frame>

* **Uptime Monitoring**：显示应用的在线时间百分比，并用彩色条展示近期记录。Replit 会定期检查你的应用，一旦宕机就发送邮件通知。
* **Requests**：应用的流量随时间的变化情况，以及访问应用的唯一 IP 地址数量。
* **HTTP Statuses**：应用对近期请求的响应情况。成功响应说明运行正常；错误激增则是需要排查的信号。把错误激增的时间段粘贴到 Agent 的 Chat 中，让它检查日志。
* **Request Durations**：应用的响应耗时，按区间分组。如果大部分请求都落在较慢的区间，说明你的应用可能需要优化，或需要[配置更强的机器](/zh/pt/features/publishing/machine-configuration)。

<div id="ative-o-monitoramento-de-uptime">
  ### 启用 uptime 监控
</div>

uptime 检查通过发布设置进行控制。

<Steps>
  <Step title="打开发布设置">
    打开 **Publishing** 工具，新建一次发布或重新发布你的应用。
  </Step>

  <Step title="打开开关">
    在 **Monitoring tools** 中启用 **Enable app monitoring**，然后发布你的应用。
  </Step>

  <Step title="查看 uptime">
    发布完成后，几分钟内你的 uptime 就会显示在 Monitoring 工具中。
  </Step>
</Steps>

<Note>
  uptime 监控适用于 Replit Core、Pro 和 Enterprise 计划，支持所有类型的部署，但 Scheduled Deployments 除外，因为它们不提供网页服务。
</Note>

<div id="infrastructure-monitoring">
  ## Infrastructure monitoring
</div>

Infrastructure monitoring 显示应用在后台消耗了哪些资源。

<Frame>
  <img src="/assets/mirror/infrastructure-monitoring-edad0d8d26fc.png" alt="Infrastructure monitoring 视图，显示过去一小时的 CPU 和内存使用率图表" width="2000" height="1513" data-path="images/deployments/monitoring/infrastructure-monitoring.png" />
</Frame>

* **CPU Utilization**：应用正在占用的处理能力。
* **Memory Utilization**：应用正在占用的内存量。

偶尔出现峰值是正常的。如果其中任一图表长时间处于高位，应用在高负载下可能响应缓慢，此时可考虑升级到[性能更强的机器配置](/zh/pt/features/publishing/machine-configuration)。

<div id="logs">
  ## 日志
</div>

日志会实时显示应用正在执行的操作，包括应用运行时输出的错误和消息。Replit 会将部署日志保留 30 天。

你可以使用以下选项筛选日志：

* **Errors only**：仅查看错误日志。
* **Search**：输入要在日志中查找的短语。
* **Date**：选择日期范围。

<Tip>
  如果应用出现异常，你不必自己逐条翻阅日志。可以让 Agent 去排查，它会替你阅读日志。
</Tip>
