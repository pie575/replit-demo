---
title: "Миграция с Replit Auth на Clerk"
description: "С помощью Agent перенесите существующее приложение с Replit Auth на Clerk Auth, сохранив данные пользователей."
---

Используйте это руководство, чтобы перенести существующее приложение с [Replit Auth](/ru/ko/features/auth-and-identity/authentication) на [Clerk Auth](/ru/ko/features/auth-and-identity/clerk-auth). Для подходящих приложений миграцию выполняет Agent, поэтому существующие пользователи не теряют доступ к своим данным.

<Note>
  Эта автоматическая миграция предназначена для приложений, использующих Replit Auth. Если ваше приложение использует другую систему аутентификации, не применяйте этот сценарий.
</Note>

<div id="section">
  ## Начало миграции
</div>

Миграцию Agent всегда следует запускать в новой задаче.

Начать миграцию можно одним из двух способов.

<div id="section-2">
  ### Проверка плана миграции
</div>

Каким бы способом вы ни начали, Agent создаёт задачу **Migrate from Replit Auth to Clerk** и готовит план миграции. Прежде чем задача пойдёт дальше, выберите **View plan** и просмотрите план.

<div id="agent-2">
  ## Что делает Agent
</div>

Agent выполняет миграцию в следующем порядке:

1. Переносит данные пользователей Replit Auth в Clerk, включая идентификационные данные аккаунтов и поддерживаемые учётные данные для входа.
2. Дожидается завершения миграции данных, прежде чем вносить изменения в приложение.
3. Обновляет логику входа и сессий в приложении, перезапускает его и выполняет доступные автоматические проверки.

<div id="section-3">
  ## Данные приложения остаются без изменений
</div>

Agent изменяет только код аутентификации приложения. Существующие данные и схема базы данных не затрагиваются. Таблицы и связи между ними сохраняются в прежнем виде.

Существующие пользователи по-прежнему связаны с уже принадлежащими им записями: профилями, сохранёнными результатами работы, правами доступа и т. д.

<div id="section-4">
  ## Сколько времени это займёт
</div>

Рассчитывайте, что работа Agent займёт от 10 минут до часа. Сама миграция данных может занять несколько минут в случае небольших приложений и до нескольких часов, если у приложения много пользователей. Agent не начнёт вносить изменения в код приложения, пока миграция не завершится.

<div id="section-5">
  ## После миграции
</div>

Перед публикацией протестируйте обновлённое приложение в среде Development.

1. Войдите в существующую учётную запись и убедитесь, что сохранённые данные доступны.
2. Выйдите из учётной записи, а затем войдите снова.
3. Создайте новую тестовую учётную запись и убедитесь, что приложение работает как ожидается.
