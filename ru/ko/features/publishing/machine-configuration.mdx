description: "Настройте производительность и расходы сервера, на котором работает опубликованное App: ЦП, память и максимальное количество машин."

Конфигурация машины определяет производительность сервера, на котором работает опубликованное App. Replit выбирает подходящие значения по умолчанию, поэтому большинству разработчиков не нужно их менять. Выберите более мощную конфигурацию, если App замедляется под нагрузкой или обрабатывает большие объёмы данных в памяти.

Чтобы внести изменения, откройте инструмент Publishing, выберите **Adjust settings**, затем **Edit** рядом с **Machine configuration**.

<div id="section">
  ## Параметры конфигурации
</div>

* **CPU**: объём работы, который каждый сервер может обрабатывать одновременно. Чем больше vCPU, тем лучше App справляется с одновременным использованием большим числом пользователей.
* **Память (RAM)**: объём данных, который App может хранить в памяти. Чем больше RAM, тем лучше для крупных файлов, медиа и задач с интенсивной обработкой данных.
* **Максимальное количество машин**: применяется только к Autoscale. Это максимальное число серверов, которые Replit может добавить при высокой нагрузке на App. App не будет масштабироваться сверх этого значения, поэтому максимальный расход ограничен.

<div id="section-2">
  ## Расходы
</div>

При настройке на панели отображаются два значения.

* **На машину**: почасовой расход на работу одного сервера с выбранной конфигурацией.
* **При максимальной нагрузке**: почасовой расход, когда App настолько загружено, что задействует максимальное количество машин.

Расходы измеряются в вычислительных единицах — единицах облачных вычислений, определяемых выбранными CPU и объёмом памяти. Актуальные тарифы и порядок тарификации по факту использования см. в разделе [Платежи на основе использования](/ru/ko/billing/about-usage-based-billing#2-compute-units).

<div id="section-3">
  ## Различия в тарификации в зависимости от типа деплоя
</div>

Даже при одинаковой конфигурации тарификация различается в зависимости от [типа деплоя](/ru/ko/features/publishing/deployment-types).

* **Autoscale**: расходы начисляются только во время обработки запросов. Когда App простаивает, оно масштабируется до 0, поэтому расходы на выполнение не начисляются.
* **Reserved VM**: поскольку сервер всегда включён, вы платите фиксированную ежемесячную сумму за выбранную конфигурацию.
* **Static**: поскольку для работы сайта не требуется машина, конфигурация машины не применяется.
* **Scheduled**: расходы на машинные ресурсы начисляются при каждом запланированном запуске.

<div id="section-4">
  ## Применение изменений
</div>
