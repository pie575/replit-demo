应用测试让 Agent 能够在真实浏览器中测试其构建的应用。Agent 会像真实用户一样浏览您的应用，点击并验证各项功能。这种自动测试功能有助于确保您的应用正常运行，并让 Agent 自动检测和修复问题。

启用应用测试后，Agent 会定期判断是否需要测试——当它认为改动足够多、值得测试时便会执行。Agent 并不会在每条用户消息之后都进行测试，而是智能判断何时测试最有价值。

<Note>
  目前，应用测试适用于 JavaScript 全栈 Web 应用和 Python Streamlit Web 应用。
</Note>

<div id="principais-benefcios">
  ### 主要优势
</div>

* **延长自主运行时间**：让 Agent 无需人工干预即可工作更长时间
* **更高质量**：通过及早发现并解决问题，减少应用中的错误
* **成本效益**：在开发过程中发现问题，避免额外的调试会话
* **交互式审查**：提供视频回放和分节导航，方便详细分析结果

<div id="o-processo-de-teste">
  ### 测试流程
</div>

当 Agent 决定进行测试时，会执行以下操作：

1. **浏览器预览**：你会在 Agent 面板中看到应用的浏览器预览
2. **视觉测试**：观察 Agent 的光标在应用中点击，测试各项功能
3. **模拟真实用户**：Agent 会像真实用户一样操作应用，并在需要时输入模拟数据
4. **自动分析**：Agent 会分析测试结果并识别问题
5. **自动修复**：Agent 会提供测试摘要，并自动修复发现的问题

<div id="principais-capacidades">
  ## 主要功能
</div>

Agent 会像真实用户一样浏览您的应用，并智能地对其进行测试，涵盖：

* **用户界面验证**：按钮、表单、导航和视觉元素
* **功能检查**：核心功能和用户流程
* **集成测试**：API 调用、数据库交互和第三方服务
* **性能和无障碍访问**：加载时间、响应速度和无障碍标准

<div id="uso">
  ## 使用
</div>

应用测试位于 Chat 输入框中 Agent 设置下拉菜单的**高级设置**内。使用 Economy 或 Power 模式时可将其启用。Lite 模式下，应用测试始终处于关闭状态。

<Note>
  应用测试是 Agent 自主能力的一部分。进一步了解[代码优化](/zh/pt/core-concepts/agent/code-optimizations)和其他 [Agent 功能](/zh/pt/core-concepts/agent)。
</Note>

<div id="assumir-controle">
  ## 接管操作
</div>

有时，Agent 会在测试过程中遇到需要你协助才能继续的问题。大多数情况下，这涉及登录用户账户 (例如 Gmail) 。此时，Agent 会显示“开始接管操作”按钮。

<Frame>
  <img src="/assets/mirror/app-testing-takeover-6e0b0b56f4d0.png" alt="应用测试接管操作界面，显示“跳过”和“开始接管操作”按钮，以及处理错误和 CAPTCHA 的说明" width="924" height="358" data-path="images/replitai/app-testing-takeover.png" />
</Frame>

点击“开始接管操作”后，你可以在测试预览中进行操作，完成所需步骤，然后让 Agent 继续。你也可以点击“跳过”以跳过接管；如果 Agent 无法在没有你协助的情况下继续，应用测试将结束。如果你在 10 分钟内未响应，Agent 将视同你已点击“跳过”并继续。

<div id="o-que-esperar">
  ### 预期内容
</div>

* **跳过选项**：如有需要，可使用“跳过”按钮跳过测试并继续开发
* **交互式视频回放**：测试结束后，点击视频即可回看整个测试过程
* **分段导航**：使用底部的滑块跳转到测试的特定部分

<div id="soluo-de-problemas">
  ## 故障排除
</div>

**测试意外失败**

* 尝试跳过后重新请求测试
* 检查是否有可能影响测试时长的动态内容
* 检查测试场景是否准确

**缺少测试覆盖**

* 更详细地描述应用的功能
* 明确说明必须测试的关键用户流程

**应用测试无法正常工作？**

* 应用测试目前仅适用于 Web 应用[*](#how-app-testing-works)

<div id="preos-e-uso">
  ## 定价与使用
</div>

应用测试包含在 Agent 基于工作量的定价模型中，但有几点重要的成本注意事项：

* **按用量计费**：测试按实际投入的工作量计费 (越简单的测试费用越低)
* **成本与收益**：测试虽然会产生费用，但能更早发现错误，从而省去额外的提示词和 Agent 的额外工作，反而节省成本
* **高效开发**：自动化方式减少了手动调试和返工

<Tip>
  **经济高效的测试**：应用测试虽然会增加你的使用成本，但总体上通常更省钱，因为它免去了为修复本可在测试中发现的问题而额外启动 Agent 会话。
</Tip>

<div id="prximos-passos">
  ## 后续步骤
</div>

准备好在项目中使用应用测试了吗？

1. **开始构建**：使用 Agent 创建应用，让测试自动运行
2. **查看结果**：查看测试报告并落实建议的改进
3. **迭代优化**：利用测试反馈完善应用
4. **扩展应用**：将应用测试用于更大、更复杂的项目
