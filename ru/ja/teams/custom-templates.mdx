<div id="section">
  ## Введение
</div>

Replit — облачная среда разработки, в которой можно писать и запускать приложения с любыми фреймворками и стеками. Для создания пользовательских шаблонов есть два рекомендуемых способа:

1. **[Импорт из Git-провайдера](https://replit.com/import)** — импортируйте существующий стартовый Stack (или другой подходящий вариант) из GitHub, GitLab или Bitbucket.
2. **Форк шаблона Blank** — создайте форк [шаблона Blank](https://replit.com/@replit/Nothing?v=1), чтобы начать с нуля в полностью пустой среде разработки.

Пользователи успешно создают шаблоны для Rust, Python, Java, C++ и множества других стеков: если что-то можно запустить, это можно запустить и в Replit.

<Tip>
  При создании первого шаблона рекомендуем обратиться к **команде полевых инженеров** Replit. У неё обширный опыт настройки пользовательских шаблонов для самых разных стеков, и она может оказать необходимую поддержку. Обратитесь к своему менеджеру по работе с клиентами, чтобы он связал вас с этой командой.
</Tip>

Пользовательские шаблоны позволяют администраторам Enterprise создавать предварительно настроенные отправные точки, которые отображаются непосредственно в поле ввода Agent у всех участников организации. Когда разработчик выбирает пользовательский шаблон, Agent создаёт его форк и использует конфигурацию, инструкции и навыки шаблона для всей последующей работы. Дополнительная настройка не требуется.

<Note>
  Пользовательские шаблоны доступны только в плане **Enterprise**. Только администраторы организации могут закреплять шаблоны и управлять ими.
</Note>

<div id="section-2">
  ## Как работают пользовательские шаблоны
</div>

Пользовательские шаблоны — это стандартные Replit App организации, **закреплённые в поле ввода Agent**. Когда разработчик выбирает шаблон:

1. Agent форкает шаблон и создаёт New App (копируются все файлы)
2. Agent пропускает этап планирования и сразу переходит в режим сборки
3. Файл шаблона `custom_instruction/instructions.md` добавляется в контекст Agent
4. Пользовательские [навыки](/ru/ja/features/agent/skills) из `.agents/skills/` обнаруживаются и становятся доступными
5. Файл [`replit.md`](/ru/ja/features/project-setup/replit-dot-md) предоставляет постоянный контекст проекта

Благодаря этому стандарты, шаблоны и инструменты организации учитываются уже при первом взаимодействии.

<div id="section-3">
  ## Структура файлов шаблона
</div>

Рекомендуемая структура пользовательского шаблона:

```
my-template/
├── .replit                              # Конфигурация App (команды запуска, порты, модули)
├── replit.md                            # Память Agent: обзор и настройки проекта
├── custom_instruction/
│   └── instructions.md                  # Инструкции компании, добавляемые в prompt Agent
├── .agents/
│   └── skills/
│       └── my-skill/
│           └── SKILL.md                 # Пользовательские навыки, которые Agent может вызывать по мере необходимости
└── ...                                  # Остальная структура репозитория
```

Каждый файл выполняет свою роль. В следующих разделах описано, как настроить каждый из них.

<div id="section-4">
  ## Настройка пользовательского шаблона
</div>

<div id="app">
  ### Создание базового App
</div>

Создайте New Replit App в своей организации. Разработчик подготовит проект со всеми необходимыми для старта файлами, зависимостями и конфигурацией. Это включает:

* Каркас исходного кода (компоненты, утилиты и файлы конфигурации)
* Предустановленные зависимости (`package.json`, `requirements.txt` и т. д.)
* Конфигурацию среды в [файле `.replit`](/ru/replit-app/configuration)

<div id="secret">
  ### Настройка общих Secrets
</div>

Если шаблон использует API-ключи, токены или другие учетные данные, добавьте их в **Secrets** шаблона (на панели инструментов) перед закреплением. Когда разработчик создает New App на основе шаблона, все Secrets автоматически копируются в новый App, поэтому он может сразу приступить к работе без необходимости настраивать учетные данные самостоятельно.

Задокументируйте все Secrets в `custom_instruction/instructions.md` (или отдельном skill), чтобы разработчик знал, какие Secrets доступны и для чего используется каждый ключ.

<Warning>
  Secrets копируются при форке и не синхронизируются автоматически. Если вы меняете ключи в шаблоне или добавляете новые Secrets, уже созданные через форк App не обновятся. Разработчикам потребуется вручную добавить или обновить Secrets в этих App.
</Warning>

<div id="instructions">
  ### Создание пользовательских инструкций
</div>

Создайте файл `custom_instruction/instructions.md` в корне проекта. Это самый важный файл шаблона: он объясняет Agent, как ваша организация разрабатывает программное обеспечение.

<Warning>
  Имя папки — `custom_instruction` (в единственном числе), а не `custom_instructions`.
</Warning>

Agent напрямую добавляет этот файл в системный промпт вместе с преамбулой и представляет его как рекомендации компании. Оформите его в Markdown и включите следующее:

* **Архитектурные паттерны**: как структурировать App
* **Стандарты написания кода**: соглашения об именовании, правила организации файлов и требования к линтингу
* **Использование компонентов**: какие библиотеки и компоненты использовать, а каких избегать
* **Паттерны API**: как вызывать серверные сервисы, обрабатывать аутентификацию и управлять ошибками
* **Требования к тестированию**: какие тесты должны быть и как их запускать
* **Рекомендации по развёртыванию**: настройки для конкретных сред и процессы развёртывания

````markdown theme={null}
# Company Engineering Standards

## Architecture
All web applications use React with TypeScript. Use functional components
with hooks exclusively. State management uses Zustand for local state
and React Query for server state.

## Component Library
Use our internal design system package `@acme/ui`. Never use raw HTML
elements for buttons, inputs, forms, or modals — always use the
corresponding component from `@acme/ui`.

Import components like this:
```tsx
import { Button, TextField, Modal } from '@acme/ui';
```

## API Integration
All API calls go through the `@acme/api-client` package. Never use
raw fetch or axios directly. Authentication is handled automatically
by the client.

## Testing
Every component must have a corresponding test file. Use Vitest
for unit tests and Playwright for integration tests.
````

**Ограничение размера**: Для содержимого действует мягкое ограничение около 25 КБ. Содержимое, превышающее этот лимит, может постепенно обрезаться. Если инструкции становятся слишком объёмными, перенесите подробные справочные материалы в [навыки](/ru/ja/features/agent/skills) в `.agents/skills/`, а не храните всё в `instructions.md`. Навыки загружаются по запросу, когда это необходимо, поэтому не учитываются в ограничении размера инструкции и позволяют сосредоточить основные инструкции на правилах высокого уровня.

<div id="section-5">
  ### Добавление пользовательских навыков
</div>

Создавайте навыки в каталоге `.agents/skills/` для специализированных рабочих процессов, которым должен следовать Agent. Каждый навык — это каталог с файлом `SKILL.md`, содержащим YAML-фронтматтер.

```
.agents/skills/
├── use-design-system/
│   └── SKILL.md
├── api-integration/
│   └── SKILL.md
└── run-tests/
    └── SKILL.md
```

Во Frontmatter каждого `SKILL.md` должны быть указаны `name` и `description`:

```markdown theme={null}
---
name: use-design-system
description: Use when building UI components. Provides component patterns, theming rules, and accessibility requirements for the Acme design system.
---

# Acme Design System

## Available components

- `Button` — Primary, secondary, and ghost variants
- `TextField` — Text input with validation support
- `Modal` — Dialog overlay with focus trapping
...
```

| Поле          | Обязательно | Подробности                                                                |
| ------------- | ----------- | -------------------------------------------------------------------------- |
| `name`        | Да          | До 64 символов. Только строчные латинские буквы, цифры и дефисы.           |
| `description` | Да          | До 1 024 символов. Описывает назначение навыка и случаи его использования. |
| `enabled`     | Нет         | По умолчанию — `true`. Установите `false`, чтобы отключить без удаления.   |

**Как загружаются навыки**: Agent распознаёт в промпте только `name` и `description`. Если навык связан с текущей задачей, Agent по запросу загружает полное содержимое `SKILL.md`. Поэтому `description` особенно важен: сформулируйте его так, чтобы он соответствовал сценариям, в которых Agent должен использовать навык.

Вместе с `SKILL.md` навыки также могут включать вспомогательные файлы:

```
.agents/skills/use-design-system/
├── SKILL.md
├── references/
│   └── component-api.md
└── assets/
    └── theme-tokens.json
```

Подробнее см. в разделах [Навыки Agent](/ru/ja/features/agent/skills) и [Использование навыков](/ru/ja/build/use-agent-skills).

<div id="replitmd">
  ### Настройка replit.md
</div>

Заранее добавьте в `replit.md` в корне проекта описание архитектуры шаблона. Этот файл всегда загружается в контекст Agent и служит постоянной памятью проекта.

Файл должен содержать следующие четыре раздела:

```markdown theme={null}
# Обзор
Приложение для управления задачами, созданное с использованием React, TypeScript и дизайн-системы Acme. Использует бэкенд на Express.js с PostgreSQL.

# Настройки пользователя
- Использовать TypeScript для всех файлов
- Предпочитать функциональные компоненты с хуками
- Следовать стандартам разработки Acme

# Архитектура системы
- Фронтенд: React + TypeScript + @acme/ui
- Бэкенд: Express.js + TypeScript
- База данных: PostgreSQL с Drizzle ORM
- Аутентификация: Acme SSO через @acme/auth

# Внешние зависимости
- @acme/ui: внутренняя дизайн-система
- @acme/api-client: слой интеграции API
- @acme/auth: SDK для аутентификации
```

Agent обновляет `replit.md` по мере развития проекта. Когда файл превышает примерно 4 000 токенов, Agent автоматически сокращает его до сводной версии, сохраняя фокус и полезность.

Подробнее см. [replit.md](/ru/ja/features/project-setup/replit-dot-md).

<div id="section-6">
  ### Закрепление шаблона для организации
</div>

Когда шаблон будет готов:

1. Перейдите к шаблону App в организации
2. Откройте меню действий App (меню с тремя точками)
3. Выберите **Закрепить в поле ввода Agent**

<img src="/assets/mirror/custom-templates-pin-to-agent-b733d3eb9a80.png" alt="Меню действий App с опцией «Закрепить в поле ввода Agent»" width="984" height="856" data-path="images/teams/custom-templates-pin-to-agent.png" />

<Note>
  Закреплять и откреплять шаблоны могут только администраторы организации (участники с ролью `system_admins`).
</Note>

Установите для доступа участников значение **Только чтение**, чтобы они могли просматривать и использовать закреплённый шаблон, но не редактировать его.

<img src="/assets/mirror/custom-templates-members-read-only-cf6aa160c8ef.png" alt="Диалог приглашения, показывающий, что доступ участников установлен в режим «Только чтение»" width="954" height="1064" data-path="images/teams/custom-templates-members-read-only.png" />

Шаблон будет отображаться в виде выбираемой плашки под полем ввода Agent у всех участников организации. Чтобы удалить его, откройте то же меню и выберите **Открепить от поля ввода Agent**.

<div id="section-7">
  ### Управление доступом к шаблонам
</div>

Закреплённые шаблоны видны всем участникам Org. Чтобы предоставить доступ только определённым пользователям, воспользуйтесь кнопкой **Invite** в App шаблона и поделитесь им с конкретными [группами или отдельными пользователями](/ru/ja/teams/identity-and-access-management/groups-and-permissions). Так можно ограничить круг команд или пользователей, которые могут просматривать и форкать шаблон, не закрепляя его в поле ввода для всей Org.

<div id="section-8">
  ## Что происходит, когда разработчик выбирает шаблон
</div>

<img src="/assets/mirror/custom-templates-input-box-553384ac7dd0.png" alt="Шаблоны, отображаемые в виде выбираемых плашек в поле ввода Agent" width="1746" height="726" data-path="images/teams/custom-templates-input-box.png" />

Когда участник организации выбирает закреплённый шаблон в поле ввода Agent:

1. **Форк**: создаётся новое App — копия шаблона со всеми файлами
2. **Пропуск этапа планирования**: Agent пропускает начальный диалог планирования и сразу переходит в режим сборки
3. **Загрузка инструкций**: `custom_instruction/instructions.md` загружается и добавляется в системный промпт Agent как рекомендации компании
4. **Обнаружение навыков**: навыки из `.agents/skills/` обнаруживаются и добавляются в контекст Agent для загрузки по запросу
5. **Загрузка контекста проекта**: `replit.md` загружается и добавляется в контекст Agent; если файла нет, он создаётся автоматически
6. **Наследование конфигурации**: файл `.replit`, зависимости и все файлы шаблона переносятся в новое App

Разработчик может сразу задавать Agent конкретные требования в промптах, а Agent будет работать в рамках ограничений, заданных шаблоном.

<div id="section-9">
  ## Как взаимодействуют файлы
</div>

Каждый файл конфигурации выполняет свою роль:

| Файл                                 | Назначение                                    | Когда Agent загружает файл              | Может ли Agent изменять                 |
| ------------------------------------ | --------------------------------------------- | --------------------------------------- | --------------------------------------- |
| `custom_instruction/instructions.md` | Организационные стандарты и правила           | Всегда (добавляется в системный промпт) | Нет                                     |
| `.agents/skills/*/SKILL.md`          | Специализированные рабочие процессы и шаблоны | По запросу (при необходимости)          | Да (Agent также может создавать навыки) |
| `replit.md`                          | Обзор и настройки проекта                     | Всегда (добавляется в системный промпт) | Да (Agent обновляет его со временем)    |
| `.replit`                            | Конфигурация среды выполнения                 | При настройке App                       | Да                                      |

**Ключевое различие**: `custom_instruction/instructions.md` — статичный и авторитетный источник информации об организационных стандартах. `replit.md` — живой документ, который Agent поддерживает по мере развития проекта. Навыки — справочные материалы, загружаемые по запросу для конкретных рабочих процессов.

<div id="section-10">
  ## Рекомендации
</div>

<div id="instructions-2">
  ### Сохраняйте фокус на инструкции
</div>

`custom_instruction/instructions.md` должен описывать наиболее важные паттерны. Сосредоточьтесь на следующем:

* Решения, которые сложно отменить (архитектура, модель данных)
* Паттерны, которые должны быть единообразными (использование компонентов, соглашения API)
* Стандарты, о которых разработчики могут не знать (внутренние библиотеки, соглашения команды)

Не добавляйте журнал изменений, детали реализации или информацию, которая часто меняется.

<div id="description">
  ### Напишите понятное для Agent описание навыка
</div>

Поле Description в Frontmatter `SKILL.md` используется Agent, чтобы определять, когда загружать навык. Напишите Description, соответствующее задачам, для которых предназначен навык:

```yaml theme={null}
# Хороший пример — поясняет, когда его использовать
description: フォームのビルドやユーザー入力の処理時に使用します。Acmeデザインシステムのバリデーションパターン、エラー表示規約、アクセシブルなフォームレイアウトを提供します。

# Менее удачный пример — слишком расплывчато
description: フォームのユーティリティとヘルパー。
```

<div id="section-11">
  ### Организуйте навыки по рабочим процессам
</div>

Группируйте навыки по рабочим процессам, а не по техническим категориям:

| Подход                      | Примеры                                    |
| --------------------------- | ------------------------------------------ |
| **По рабочим процессам**    | `build-a-form`、`connect-to-api`、`add-auth` |
| **По техническим областям** | `react-utils`、`api-helpers`、`auth-config`  |

Такой подход позволяет Agent находить нужные навыки в нужный момент.

<div id="section-12">
  ### Постоянно улучшайте шаблоны
</div>

Шаблоны становятся лучше по мере использования. Когда команда начнёт создавать проекты на основе шаблона:

1. Отслеживайте ситуации, в которых Agent допускает ошибки, и добавляйте их в `instructions.md`
2. Если Agent успешно решает проблему, создайте новый навык и зафиксируйте решение
3. Обновляйте базовые зависимости и конфигурацию по мере развития стека
4. Тестируйте изменения, создавая новое App из шаблона и проверяя весь процесс

<div id="app-2">
  ### Обновление шаблона и существующие App
</div>

Изменения в шаблоне App применяются к **новым** App, созданным на его основе. Существующие App, ранее созданные путём форка шаблона, являются независимыми копиями и не получают обновлений.
