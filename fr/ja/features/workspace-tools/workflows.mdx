Il s&#39;agit d&#39;une série d&#39;étapes réutilisables et personnalisables que vous pouvez exécuter dans votre application Replit. Vous pouvez en créer de très simples, qui se contentent d&#39;exécuter `python main.py`, comme de plus complexes, qui déroulent des procédures en plusieurs étapes.

  <img src="/assets/mirror/workflows-pane-e7d5e4251006.png" alt="Image du volet Workflows" width="525" height="622" data-path="images/workflows/workflows-pane.png" />

Exemples d&#39;utilisation :

* Exécuter plusieurs services en parallèle (par exemple : frontend + backend)
* Exécuter des fichiers ou des commandes dans un ordre précis (par exemple : lancer le linter → lancer les tests, compiler → exécuter le code)

Pour commencer à [créer des workflows](#creating-workflows), utilisez le menu de la barre latérale des outils ou recherchez le volet Workflows avec `Command + K`.

<div id="section">
  ## Types de tâches disponibles
</div>

Trois types de tâches sont actuellement disponibles : `Execute Shell Command`, `Install Packages` et `Run Workflow`.

<div id="execute-shell-command">
  ### Execute Shell Command
</div>

`Execute Shell Command` enregistre une commande shell et l&#39;exécute dans le même environnement que le volet Shell. Ce type de tâche se prête à de nombreux usages, par exemple l&#39;exécution de fichiers individuels :

```text theme={null}
python main.py
```

jusqu&#39;à l&#39;exécution de requêtes complexes en base de données :

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Install Packages
</div>

`Install Packages` s&#39;appuie sur le système de gestion des dépendances intégré à Replit pour détecter automatiquement les dépendances de votre projet et installer les packages nécessaires. Pour en savoir plus sur la manière dont UPM déduit les packages à installer dans un projet, consultez la [gestion des dépendances](/fr/ja/features/project-setup/dependency-management#the-universal-package-manager).

<div id="run-workflow">
  ### Run Workflow
</div>

`Run Workflow` vous permet de lancer un autre workflow depuis le workflow en cours. Vous pouvez ainsi réutiliser des workflows ou les combiner pour en créer de plus complexes.

Exemple d&#39;utilisation :

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="Exemple d'exécution de workflow" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

En créant des dépendances entre workflows avec ce type de tâche, la modification d&#39;un workflow fait que tous les autres workflows qui le référencent utilisent automatiquement les dernières modifications. Notez qu&#39;une limite de profondeur s&#39;applique aux appels de workflows fortement imbriqués.

<div id="section-2">
  ## Modes d&#39;exécution des workflows
</div>

Workflows propose deux modes d&#39;exécution distincts : séquentiel et parallèle.

<div id="section-3">
  ### Séquentiel
</div>

L&#39;exécution séquentielle lance les tâches dans l&#39;ordre défini, attend la fin de chaque tâche avant de passer à l&#39;étape suivante et interrompt l&#39;exécution si une tâche du workflow échoue.

Ce mode s&#39;avère utile, par exemple, pour définir des commandes logiquement enchaînées, comme les commandes Git qui récupèrent les dernières modifications de la branche principale et rebasent la branche actuelle sur celle-ci :

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="Exemple de workflow séquentiel" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="section-4">
  ### Parallèle
</div>

L&#39;exécution parallèle lance toutes les tâches simultanément : chacune démarre et s&#39;exécute indépendamment des autres tâches du workflow. L&#39;échec d&#39;une tâche n&#39;interrompt pas l&#39;exécution des autres.

Ce mode est utile, par exemple, pour exécuter un projet full-stack qui doit démarrer à la fois le serveur frontend et le serveur backend :

<div id="section-5">
  ## Création d&#39;un workflow
</div>

Vous pouvez créer un workflow en cliquant sur le bouton `+ New Workflow` du volet Workflows. Commencez par donner un nom descriptif à votre workflow, choisissez le mode d&#39;exécution approprié, puis ajoutez des tâches. Vous pouvez réorganiser les tâches dans l&#39;ordre souhaité par glisser-déposer.

<div id="run">
  ## Associer un workflow au bouton Run
</div>

Vous pouvez associer un workflow au bouton Run pour remplacer son comportement par défaut (consultez [la configuration de votre App Replit](/fr/ja/features/project-setup/configuration)). Pour conserver la commande d&#39;exécution par défaut configurée dans `.replit`, sélectionnez l&#39;option « Run Replit App » dans le menu déroulant.

Le workflow sélectionné dans le menu déroulant à côté du bouton Run s&#39;exécute lorsque vous cliquez sur ce bouton. Pour modifier le workflow exécuté par le bouton Run, sélectionnez le workflow souhaité dans le menu déroulant.
