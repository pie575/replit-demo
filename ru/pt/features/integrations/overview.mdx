Agent поддерживает четыре типа интеграций, чтобы вы могли быстро пройти путь от идеи до готового приложения:

* **Управляемые Replit**: встроенные интеграции, которые работают автоматически. Создайте приложение — и Agent сразу сможет их использовать.
* **Коннекторы**: собственные интеграции с поддержкой Replit. Достаточно войти один раз. Agent сможет читать и записывать данные в этих сервисах прямо из чата — получать данные, создавать записи, отправлять сообщения — и использовать их во всех ваших приложениях.
* **Внешние интеграции**: надёжные сторонние сервисы, на основе которых вы можете строить приложения. Попросите Agent настроить их; ключи API нужно будет предоставить вам.
* **Сервисы Agent**: платные сторонние API, которые Agent использует «под капотом» — ключи API не нужны. Использование оплачивается вашими кредитами Replit.

<Note>
  **Доступность по тарифам**: для большинства коннекторов требуется подписка Core, Pro или Enterprise, часть из них доступна и на бесплатном тарифе. В каталоге коннекторов в вашем workspace показано, какие коннекторы доступны на вашем текущем тарифе. Разработчикам бесплатного тарифа всегда доступны интеграции, управляемые Replit: базы данных, аутентификация и многое другое.
</Note>

  ## Первые шаги
</div>

Чтобы воспользоваться интеграцией, укажите нужный сервис или возможность. Например:

<div id="deixe-o-agent-sugerir-um-conector">
  ### Позвольте Agent предложить коннектор
</div>

Иногда одну и ту же задачу — например, хранение файлов или отправку писем — могут решать несколько сервисов. Если вы описываете нужную функцию, не указывая конкретного провайдера, Agent покажет короткий список подходящих коннекторов. Выберите тот, который вам нужен.

Укажите провайдера и войдите один раз, чтобы подключить свою учётную запись. Agent будет учитывать ваш выбор при разработке. Можно также сразу назвать нужный сервис по имени, чтобы пропустить этот шаг.

<div id="conectores">
  ## Коннекторы
</div>

Коннекторы позволяют Agent напрямую читать и записывать данные в ваших сервисах. Это собственные интеграции с поддержкой от Replit. Достаточно один раз войти в сервис на странице коннекторов в Project Editor — и эти подключения можно использовать во всех приложениях.

<Note>
  Подключения привязаны к вашей учётной записи Replit и доступны во всех ваших приложениях. Подключите сервис один раз и используйте его в любом создаваемом приложении.
</Note>

<div id="configurando-um-app-oauth-com-o-replit">
  ### Настройка приложения OAuth в Replit
</div>

<Note>
  **Только Enterprise**: для настройки собственного приложения OAuth нужна подписка Enterprise.
</Note>

На тарифе Enterprise вы можете подключить к коннектору собственное приложение OAuth вместо стандартного приложения Replit. Так ваша организация становится владельцем клиента OAuth, показывает свой бренд на экране согласия и контролирует, какие именно разрешения могут запрашивать ваши разработчики.

Чтобы настроить коннектор с собственным приложением OAuth, вам понадобятся три вещи от провайдера: **Client ID**, **Client Secret** и **разрешения (scopes)**, которые вы хотите авторизовать. Кроме того, нужно зарегистрировать у провайдера URL обратного вызова Replit, иначе аутентификацию не удастся завершить.

<Frame>
  <img src="/assets/mirror/connector-oauth-configuration-100911ce0c48.png" alt="Диалог настройки OAuth для коннектора с полями Client ID, Client Secret и Scopes, а также URL перенаправления https://replit.com/connectors/oauth/callback" width="1112" height="1218" data-path="images/replitai/connector-oauth-configuration.png" />
</Frame>

<Steps>
  <Step title="Создайте приложение OAuth у своего провайдера">
    Войдите в консоль разработчика или в настройки администратора провайдера и создайте новое приложение OAuth 2.0. Провайдеры называют этот шаг по-разному — ищите пункты вроде **Create OAuth app**, **Register application** или **Create client credentials**.
  </Step>

  <Step title="Укажите URL перенаправления">
    Когда провайдер запросит **авторизованный URI перенаправления** (иногда его называют **Callback URL** или **Redirect URL**), введите:

    ```
    https://replit.com/connectors/oauth/callback
    ```

    По этому адресу провайдер возвращает разработчиков в Replit после авторизации приложения. Он должен совпадать в точности — важны завершающие слэши, протокол и поддомен. Если вы добавляете несколько URI перенаправления, этот должен быть среди них.
  </Step>

  <Step title="Скопируйте Client ID и Client Secret">
    После создания приложения провайдер покажет **Client ID** и **Client Secret**.

    * **Client ID**: публичный идентификатор вашего приложения OAuth. Его можно без опаски показывать в URL и в клиентском коде.
    * **Client Secret**: конфиденциальное значение, которое подтверждает, что запрос исходит от вашего приложения. Обращайтесь с ним как с паролем — никогда не коммитьте его в репозиторий и не публикуйте. Replit надёжно хранит его за вас.

    Некоторые провайдеры показывают client secret только один раз — в момент создания. Скопируйте его сразу и храните в безопасном месте, пока не вставите в Replit.
  </Step>

  <Step title="Выберите разрешения">
    **Разрешения (scopes)** — это права доступа, определяющие, что ваше приложение OAuth может читать или записывать от имени разработчика. Каждый провайдер публикует собственный список разрешений в документации к своему API.

    При настройке коннектора в Replit введённые разрешения должны **точно совпадать** (символ в символ, включая любые префиксы URL) с разрешениями, зарегистрированными у провайдера. Частые причины ошибок несоответствия:

    * Отсутствие полного префикса URL (например, `https://www.googleapis.com/auth/drive.file` вместо `drive.file`).
    * Лишние пробелы или запятые в конце.
    * Запрос в Replit разрешения, которое не включено в приложении провайдера.

    Начните с минимального набора разрешений, необходимых вашим разработчикам, и при необходимости добавьте остальные позже — большинство провайдеров позволяют изменять разрешения без пересоздания приложения.
  </Step>

  <Step title="Настройте коннектор в Replit">
    На странице **Connectors** вашей организации выберите **Add new integration**, укажите сервис и вставьте **Client ID**, **Client Secret** и **Scopes**, полученные от провайдера. Нажмите **Configure**, чтобы сохранить.
  </Step>
</Steps>

  Если после настройки аутентификация не работает, ещё раз проверьте, что URL перенаправления, указанный у провайдера, в точности совпадает с `https://replit.com/connectors/oauth/callback`, а каждое разрешение, добавленное в Replit, разрешено и в приложении провайдера.
</Note>

<div id="reconectando-integraes">
  ## Переподключение интеграций
</div>

Если подключённый сервис перестал работать — например, истёк срок сессии входа или изменились разрешения — Replit покажет в Project Editor уведомление о необходимости переподключения. Нажмите на него, чтобы переподключить интеграцию сразу, не покидая редактор.

<div id="depurando-conectores">
  ## Отладка коннекторов
</div>

Возникли проблемы с подключением сервиса? В этих руководствах разобраны самые частые ошибки и способы их устранения.

<AccordionGroup>
  <Accordion title="Google Workspace: &#x22;This app is blocked&#x22;">
    Если при подключении Google Drive, Docs, Sheets, Calendar или Gmail вы видите сообщение **«This app is blocked»**, скорее всего, Google Workspace вашей организации ограничивает сторонние OAuth-приложения. Полное руководство по решению этой проблемы см. по ссылке ниже.

    [Как устранить ошибку «This app is blocked» для коннекторов Google](/ru/pt/features/troubleshooting/debugging-google-connectors)
  </Accordion>

  <Accordion title="Salesforce: &#x22;Connection Expired&#x22;">
    Если ваш коннектор Salesforce перестал работать с ошибкой **«Connection Expired»**, скорее всего, политика refresh token вашей организации в Salesforce настроена так, что токены истекают через определённый период. Полное руководство по обновлению настроек Connected App см. по ссылке ниже.

    [Как исправить ошибки истёкшего подключения Salesforce](/ru/pt/features/troubleshooting/debugging-salesforce-connectors)
  </Accordion>
</AccordionGroup>
