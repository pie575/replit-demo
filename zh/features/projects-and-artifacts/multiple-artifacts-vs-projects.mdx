[project](/zh/features/projects-and-artifacts/projects) 是你在 Replit 上构建的一切内容的容器，其中包含你的设计、应用、幻灯片、数据以及你创建的所有输出成果。
[Artifact](/zh/features/projects-and-artifacts/artifacts) 则是 project 内可发布的输出成果：web app、移动应用、幻灯片和视频。

当你要同时构建多个东西时，有两种选择：

* 在同一个 project 中添加多个 artifact，
* 或者创建多个独立的 project。

具体如何选择，取决于这些应用是否共享数据、逻辑和 deployment 生命周期。本指南将介绍何时把多个 artifact 放在同一个 project 中，何时又该分别创建 project。

<div id="what-artifacts-share-in-a-project">
  ## project 中 artifact 共享的内容
</div>

当多个 [artifact](/zh/features/projects-and-artifacts/artifacts) 位于同一个 [project](/zh/features/projects-and-artifacts/projects) 中时，它们会自动共享：

* **数据库**：一个 artifact 写入数据，其他 artifact 可立即读取
* **后端与 API**：共用服务器逻辑，无需重复编写代码
* **文件存储**：图片、文档和上传的文件可跨 artifact 访问
* **deployment**：Publishing 会将所有内容同步上线

也就是说，你无需在 artifact 之间建立连接或重复编写代码；但与此同时，你也无法只发布其中一个 artifact 而不发布其他 artifact。

<div id="quick-guide">
  ## 快速指南
</div>

在决定是将 artifact 添加到现有 project，还是新建一个 project 时，可以参考以下关键场景。

| **在一个 project 中使用多个 artifact**     | **使用独立的 project**               |
| ---------------------------------- | ------------------------------- |
| 应用共享同一套数据和后端                       | 应用之间不共享底层逻辑或数据                  |
| 你希望所有内容一起发布                        | 你需要相互独立的发布周期                    |
| 它们相辅相成 (例如面向客户的应用和管理后台)            | 它们是互不相关的产品，或面向不同的客户             |
| 你希望某个 artifact 的改动自动同步到其他 artifact | 该 project 是短期使用的，例如营销活动落地页或活动站点 |

<div id="examples">
  ## 示例
</div>

<div id="same-project-web-app-mobile-app-for-one-product">
  ### 同一个 project：同一产品的 web app + 移动应用
</div>

一家餐厅构建了一个 web app，供顾客浏览菜单；同时构建了一个移动应用，供员工管理订单。两者连接同一个数据库，其中存放菜品、订单和顾客信息。

**为什么放在同一个 project 中：** 这两个应用共享同一套数据和后端。顾客通过 web app 下单后，员工立即就能在移动应用上看到该订单。

<div id="same-project-app-admin-dashboard-investor-pitch-deck">
  ### **同一个 project**：应用 + 管理后台 + 投资人路演文稿
</div>

一家初创公司把主打产品、用于内容管理的内部管理面板，以及用于融资的幻灯片，全部放在同一个 project 中构建。
一家初创公司把主打产品、用于内容管理的内部管理面板，以及用于融资的幻灯片，全部放在同一个 project 中构建。

**为什么放在一个 project 里：** 管理后台所管理的，正是应用展示的那份数据，而路演文稿可以直接引用共享后端的实时指标。

<div id="separate-projects-two-unrelated-client-apps">
  ### **独立的 project**：两个互不相关的客户应用
</div>

一位自由职业者为一个客户搭建电商商城，为另一个客户搭建预订系统。

**为什么要分开建 project：** 这两个应用没有共享的数据或逻辑。每个客户都需要独立发布，而且你也不希望改动其中一个会影响到另一个。

<div id="separate-projects-campaign-landing-page-alongside-a-main-product">
  ### **独立 project**：与主产品并存的营销活动落地页
</div>

你有一个全年运行的生产应用，还有一个为营销活动准备的短期落地页。

**为什么要分成独立的 project：** 活动页有自己的生命周期——你会先把它搭起来，运行几周，然后下线。单独放置既能避免主产品变得杂乱，也方便你独立发布或移除它。

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<Accordion title="我可以把 artifact 移动到其他 project 吗？">
  目前还不支持。如果需要将某个 artifact 单独拆分出来，请新建一个 [project](/zh/features/projects-and-artifacts/projects)，并让 Agent 在其中重新构建。
</Accordion>

<Accordion title="一个 project 能包含的 artifact 数量有上限吗？">
  一个 project 最多可包含 7 个 artifact。之所以有此上限，是因为 artifact 越多占用内存越大，可能会拖慢 Preview 的速度。如果需要更多 artifact，请另建一个 [project](/zh/features/projects-and-artifacts/projects)。
</Accordion>

<Accordion title="我可以只发布 project 中的某一个 artifact 吗？">
  目前还不支持。Publishing 会将全部内容一并上线。如果需要单独发布，请使用不同的 project。
</Accordion>
