<AccordionGroup>
  <Accordion title="Le point de terminaison de la base de données a été désactivé — comment corriger l’erreur « endpoint has been disabled » ?">
    Cette erreur indique que le point de terminaison de calcul de la base de données est suspendu. Pour le réactiver :

    1. Ouvrez le volet **Database** et sélectionnez **Development** dans le menu déroulant.
    2. Lorsque le bouton **Unpause database** apparaît, sélectionnez-le.
    3. Basculez le menu déroulant sur **Production**, puis sélectionnez de nouveau **Unpause database** lorsqu’il apparaît.

    Si le bouton n’apparaît pas, un Secret `DATABASE_URL` en conflit peut le masquer. Ouvrez le volet **Secrets** et comparez l’entrée `DATABASE_URL` à la chaîne de connexion du volet **Database**, puis mettez à jour ou supprimez le Secret en conflit pour qu’ils correspondent.

    Les causes fréquentes sont une facture impayée (réglez-la pour éviter que le problème se reproduise) ou une suspension temporaire lors de la publication (résolue en suivant les étapes de réactivation ci-dessus). Consultez [les bases de données de production](/fr/ko/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="La page d’état indique une panne de la base de données de production : dois-je envoyer un ticket ?">
    Non. Si une panne est déjà répertoriée sur [status.replit.com](https://status.replit.com), l&#39;équipe travaille déjà à sa résolution et l&#39;envoi d&#39;un ticket n&#39;accélérera pas le processus. Consultez l&#39;incident actif et abonnez-vous aux mises à jour pour recevoir des notifications sur son avancement.

    Si le problème de base de données n&#39;est pas répertorié sur la page d&#39;état, [contactez l&#39;assistance Replit](https://replit.com/support).
  </Accordion>

  <Accordion title="Comment restaurer une table de base de données supprimée ?">
    Replit prend en charge la restauration des bases de données de production à un instant précis. La période de restauration varie selon le plan : [Core](/fr/ko/billing/plans/replit-core) offre 7 jours et [Pro](/fr/ko/billing/plans/replit-pro), 28 jours.

    Pour restaurer une base de données, ouvrez la fenêtre **Database**, accédez à la base de données, puis ouvrez les paramètres de restauration, sélectionnez l’horodatage souhaité et confirmez. Si la période de restauration est dépassée, [contactez l’assistance Replit](https://replit.com/support). Consultez [les bases de données de production](/fr/ko/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="La base de données est suspendue et le bouton Unpause n’apparaît pas">
    Une URL de base de données en conflit masque généralement le bouton **Unpause**. Ouvrez la fenêtre **Secrets**, recherchez l’entrée `DATABASE_URL` et comparez-la à la chaîne de connexion affichée dans la fenêtre **Database**. Si elles diffèrent, le secret remplace l’URL correcte — supprimez-le, actualisez la page, puis vérifiez à nouveau la fenêtre **Database**.

    Si le bouton n’apparaît toujours pas après avoir supprimé le secret en conflit, [contactez l’assistance Replit](https://replit.com/support) en indiquant l’URL du projet.
  </Accordion>

  <Accordion title="Votre application affiche l’erreur « connection pool exhausted » — qu’est-ce que cela signifie ?">
    Votre application ouvre simultanément plus de connexions à la base de données que ne le permet votre forfait. Causes courantes :

    * les connexions ne sont pas fermées après chaque requête
    * un pic de trafic
    * des requêtes lentes qui maintiennent les connexions ouvertes trop longtemps

    La plupart des frameworks utilisent un pool de connexions partagé plutôt que d’ouvrir une nouvelle connexion pour chaque requête.

    Pour résoudre le problème au plus vite, ouvrez une nouvelle conversation Agent, décrivez l’erreur et demandez à Agent de vérifier comment votre application gère ses connexions à la base de données.
  </Accordion>

  <Accordion title="Comment migrer une base de données de développement vers la production ?">
    Replit sépare les bases de données de développement et de production afin que les modifications de test n’affectent pas les données en production. Pour exécuter des migrations en production, ajoutez une commande de migration à l’étape de build ou de pré-déploiement afin qu’elle soit exécutée à chaque déploiement. Par exemple, avec Drizzle, utilisez `drizzle-kit migrate`. Vous pouvez également exécuter manuellement des migrations depuis le Shell de l’environnement de production.

    Consultez [Créer une base de données de production lors de la publication](/fr/ko/features/data-and-storage/development-and-production).
  </Accordion>

  <Accordion title="« endpoint disabled » s’affiche dans la base de données alors que le paiement fonctionne correctement">
    Cela peut parfois se produire sans lien avec la facturation. Essayez de la réactiver manuellement : ouvrez la fenêtre **Database**, sélectionnez **Development**, puis, si le bouton apparaît, sélectionnez **Unpause database**. Répétez l’opération pour **Production**.

    Si le bouton n’apparaît pas ou si le problème persiste, [contactez l’assistance Replit](https://replit.com/support) en indiquant l’URL du projet — une réactivation manuelle peut être nécessaire. Consultez [les bases de données de production](/fr/ko/features/data-and-storage/development-and-production).
  </Accordion>
</AccordionGroup>
