Аналитика проекта показывает, как пользователи находят ваше опубликованное веб-приложение и работают с ним. Откройте панель **Growth**, чтобы посмотреть динамику посещений, источники трафика и пользовательские события.

Replit собирает базовые метрики трафика для поддерживаемых опубликованных приложений. На платном тарифе Agent может добавлять пользовательские события и отвечать на вопросы по вашей аналитике.

<div id="before-you-start">
  ## Прежде чем начать
</div>

Для работы Аналитики проекта требуется:

* **Опубликованный сайт.** Аналитика поддерживает [artifacts](/ru/features/projects-and-artifacts/artifacts) типа «сайт». События из мобильных приложений и artifacts других типов не собираются.
* **Поддерживаемый deployment.** Аналитика проекта работает с deployment типов [Autoscale](/ru/features/publishing/deployment-types#autoscale), [Reserved VM](/ru/features/publishing/deployment-types#reserved-vm) и [Static](/ru/features/publishing/deployment-types#static).
* **Платный тариф для расширенной аналитики.** Пользовательские события и аналитические запросы через Agent доступны на платных тарифах.
* **Включённая аналитика в следующем релизе.** Replit начинает собирать события после того, как вы включите параметр **Enable analytics** и опубликуете или переопубликуете приложение.

<div id="open-project-analytics">
  ## Открытие аналитики проекта
</div>

1. Откройте проект в Project Editor.
2. Выберите **Tools**.
3. В разделе **Replit Cloud** выберите **Growth**.

<Note>
  Панель **Growth** остаётся заблокированной, пока вы не опубликуете приложение. До этого она предлагает нажать **Go to Publishing**.
</Note>

Данные аналитики появляются после того, как опубликованное приложение начинает получать трафик. У новых приложений графики могут оставаться пустыми, пока их никто не посетит.

<div id="review-default-analytics">
  ## Просмотр стандартной аналитики
</div>

Стандартная аналитика использует данные о трафике по IP и показывает следующие метрики:

* **Visitors**: приблизительное количество уникальных посетителей за выбранный период.
* **Visitors over time (hour)** или **Visitors over time (day)**: как менялась активность посетителей в течение выбранного периода.
* **Top Pages**: страницы с наибольшим трафиком.
* **Top Referrers**: сайты, которые направляют трафик в ваше приложение.
* **Top Countries**: предполагаемые страны ваших посетителей.
* **Top Browsers**: браузеры, которыми пользуются посетители.
* **Top Devices**: типы устройств, которыми пользуются посетители.

С помощью меню диапазона времени можно просматривать периоды от шести часов до 30 дней. Общее число посетителей за каждый период сравнивается с предыдущим периодом такой же длительности.

Если ваше приложение использует [Replit Auth](/ru/features/auth-and-identity/authentication), на панели также отображается показатель **Unique Logged in Users** за выбранный период.

<Note>
  Количество посетителей является приблизительным. Оно рассчитывается по сетевым
  и браузерным данным, поэтому один человек может учитываться как несколько посетителей на разных устройствах или в разные календарные месяцы.
</Note>

<div id="add-custom-events-with-agent">
  ## Добавление пользовательских событий с помощью Agent
</div>

Пользовательские события измеряют действия, важные для вашего приложения. Например: завершённые регистрации, выбранные тарифы, отправленные формы и совершённые покупки.

<Steps>
  <Step title="Добавьте метрики с помощью Agent">
    Откройте **Growth**. В разделе **Расширенная аналитика** выберите **Добавить метрики с помощью
    Agent**. Опишите Agent, какие действия вы хотите измерять. Agent добавит
    отслеживание событий в нужных местах приложения.
  </Step>

  <Step title="Включите аналитику и опубликуйте приложение">
    Откройте **Publishing** и запустите публикацию или повторную публикацию. В разделе **Suggested
    add-ons** включите **Enable analytics**. Затем опубликуйте приложение. Начиная с этого
    выпуска Replit начнёт собирать просмотры страниц и пользовательские события.
  </Step>
</Steps>

<Tip>
  Настроить аналитику также можно, просто попросив об этом Agent в Chat. Вы можете
  в любой момент попросить Agent добавить или обновить события, если приложение или цели измерений изменились.
</Tip>

Replit сам добавляет трекер аналитики в опубликованное приложение. Вам не нужно добавлять скрипт отслеживания, идентификатор сайта или переменную окружения для аналитики.

<Warning>
  Не указывайте секреты, персональные данные или произвольный контент посетителей в названиях
  или свойствах пользовательских событий.
</Warning>

<div id="ask-agent-about-your-analytics">
  ## Спросите Agent о вашей аналитике
</div>

После того как приложение соберёт данные, используйте подсказки в разделе **Расширенная аналитика**:

* **Кратко изложить мою аналитику**: Agent подготовит сводку аналитики вашего project за последние семь дней.
* **Предложить улучшения проекта**: Agent проанализирует вашу аналитику и порекомендует, что улучшить в project.

Вы также можете задать Agent конкретный вопрос.

<AiPrompt>
  Сравни посетителей и завершённые регистрации за последние семь дней. Покажи
  динамику по дням и определи страницы с самой высокой конверсией.
</AiPrompt>

Agent может анализировать просмотры страниц, источники трафика, пользовательские события, свойства событий и воронки. Он использует данные аналитики вашего project и возвращает агрегированные результаты.
