title: "Déploiements Reserved VM"
description: "Découvrez comment publier votre application sur un serveur cloud toujours actif avec les déploiements Reserved VM."
---

Un déploiement Reserved VM s’exécute sur une machine virtuelle (VM) qui fournit des ressources de calcul dédiées à
votre application. Ce type de déploiement offre des coûts et des performances prévisibles, sans interruption.

Les déploiements Reserved VM sont idéaux pour les cas d’utilisation suivants :

* Tâches en arrière-plan gourmandes en mémoire
* Bots de chat qui doivent rester connectés
* Serveurs API toujours actifs

<div id="recursos">
  ## Ressources
</div>

Les déploiements Reserved VM incluent les ressources suivantes :

* **Ressources dédiées** : Bénéficiez de performances constantes pour votre App grâce à des ressources de calcul réservées.
* **Domaines personnalisés** : Configurez un domaine personnalisé ou utilisez une URL `<nome-do-app>.replit.app` pour accéder à votre App.
* **Options de ressources de calcul** : Choisissez l’option de VM qui répond aux besoins de performances de votre App.
* **Mappages de ports configurables** : Définissez les ports que votre App expose sur Internet.
* **Surveillance** : Consultez les logs et suivez l’état de votre App déployée.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder aux déploiements Reserved VM depuis l’outil Publishing du Project Editor.

<Accordion title="Comment accéder aux déploiements Reserved VM">
  Dans le **dock d’outils** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône All tools" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l’option **Reserved VM**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez l’<img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="Icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> icône de loupe en haut de l’écran pour ouvrir l’outil de recherche.
  2. Saisissez « Publishing » pour trouver l’outil, puis sélectionnez-le dans les résultats.
  3. Sélectionnez l’option **Reserved VM**, puis **Set up your published app**.
</Accordion>

<div id="configurao-da-mquina">
  ### Configuration de la machine
</div>

Sélectionnez la configuration CPU et RAM de la machine qui héberge votre déploiement. Le coût de l’option s’affiche à côté de la taille de machine sélectionnée.

<div id="domnio-principal">
  ### Domaine principal
</div>

Indiquez la partie correspondant au sous-domaine du nom d’hôte de votre app publiée. Après la publication, votre app sera accessible à l’adresse `https://<subdomain>.replit.app`.

Pour savoir comment utiliser un domaine personnalisé, consultez [Domaines personnalisés](/fr/features/publishing/custom-domains).

<div id="deployment-privado">
  ### Déploiement privé
</div>

<Info>
  La fonctionnalité d&#39;app privée publiée est disponible avec les plans Pro et Enterprise.
</Info>

Les apps privées publiées donnent accès à votre app uniquement aux membres de votre workspace, ou aux utilisateurs et groupes spécifiques que vous invitez.
Lors de la publication, vous pouvez choisir entre les options d&#39;accès **Public**, **Protégé par mot de passe**, **Workspace uniquement** ou **Sur invitation uniquement**.

Pour savoir comment configurer un déploiement privé, consultez [Accès à l&#39;app](/fr/features/publishing/private-deployments/).

<div id="build-command">
  ### Commande de build
</div>

Dans le champ **Build command**, saisissez la commande Shell qui compile ou configure votre App avant l’exécution de la Run command.
Par exemple, pour optimiser votre App JavaScript pour un environnement de production avec Vite, vous pouvez ajouter la commande `vite build`.

<div id="run-command">
  ### Run command
</div>

Saisissez dans le champ **Run command** la commande shell qui lance votre tâche. Cette commande doit être similaire à
celle que vous utilisez habituellement dans votre flux de travail. Par exemple, pour lancer une app Flask appelée « myApp », vous pouvez ajouter la commande `flask --app myApp run`.

<div id="secrets-do-app-publicado">
  ### Secrets de l’app publiée
</div>

Sélectionnez **Add published app secret** pour ajouter les variables d’environnement ou secrets dont votre app a besoin pour s’exécuter en toute sécurité.

Si votre Replit App contient des variables d’environnement ou des secrets, l’outil Publishing les ajoute automatiquement à la liste.

<div id="opes-de-tipo-de-app">
  ### Options de type d’application
</div>

Sélectionnez l’une des options suivantes :

* **Serveur web** : sélectionnez cette option lorsque vous publiez une application web ou une application à laquelle les utilisateurs peuvent se connecter sur Internet.
* **Tâche d’arrière-plan** : sélectionnez cette option si votre application n’écoute pas sur un port ou ne démarre pas de serveur.

Lorsque vous sélectionnez **Serveur web**, vous pouvez personnaliser les ports à exposer en procédant comme suit :

1. Développez la section **Port configuration**.
2. Sélectionnez **Networking pane to configure** pour ouvrir l’onglet **Networking**, où vous pouvez gérer les mappages de ports.

Pour en savoir plus sur la configuration des ports, consultez [Ports](/fr/pt/core-concepts/project-editor/app-setup/ports/).
