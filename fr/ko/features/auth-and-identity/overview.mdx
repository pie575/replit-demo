---

L’outil Users &amp; Auth permet de gérer les personnes qui utilisent votre application et leur mode de connexion. Dans le panneau **Tools**, ouvrez **Users &amp; Auth** sous **Replit Cloud**.

Cet outil comporte deux onglets :

* **Users** : affiche tous les utilisateurs connectés à votre application, ainsi que leur nom et la date de leur dernière connexion. Vous pouvez rechercher un utilisateur précis dans la liste.
* **Configure** : permet de configurer l’expérience de connexion de votre application : le nom et l’icône de l’écran de connexion, les fournisseurs de connexion proposés par votre application et le secret de session.

<Note>
  Cet outil gère les utilisateurs de votre **application**, c’est-à-dire les personnes qui s’inscrivent et se connectent à l’application que vous avez créée. Pour contrôler qui peut ouvrir votre application publiée, consultez [qui peut accéder à votre application](/fr/ko/features/publishing/private-deployments).
</Note>

<div id="section">
  ## Choisir un système d’authentification
</div>

* **[Replit Auth](/fr/ko/features/auth-and-identity/authentication)** : une option sans configuration. Demandez à Agent d’ajouter Replit Auth pour intégrer immédiatement à votre app une page de connexion prête à l’emploi, la gestion des utilisateurs et des sessions sécurisées.
* **[Clerk](/fr/ko/features/auth-and-identity/clerk-auth)** : un service d’authentification complet destiné aux apps qui nécessitent davantage de contrôle, notamment des flux de connexion personnalisés ou une image de marque OAuth personnalisée. Configurez des [fournisseurs de connexion personnalisés](/fr/ko/features/auth-and-identity/sign-in-providers) pour Google, GitHub, Apple et X.

<div id="section-2">
  ## Étapes suivantes
</div>

* [Replit Auth](/fr/ko/features/auth-and-identity/authentication) : une solution de connexion sans configuration pour votre application.
* [Clerk Auth](/fr/ko/features/auth-and-identity/clerk-auth) : une authentification complète.
* [Fournisseurs de connexion](/fr/ko/features/auth-and-identity/sign-in-providers) : utilisez vos propres identifiants OAuth.
