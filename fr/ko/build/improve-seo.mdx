Après une publication réussie, Replit effectue un audit SEO et affiche un score SEO. Si ce score peut être amélioré, transmettez des problèmes précis à Agent en un clic. Pour la plupart des créateurs, le flux de travail est simple : **publier → vérifier le score → demander à Agent d’optimiser**.

<div id="seo-agent">
  ## Optimiser avec SEO Agent
</div>

[SEO Agent](/fr/ko/features/publishing/seo-agent) effectue un audit SEO technique de votre application déployée et transforme chaque constat en correction en un clic. Il se trouve dans le panneau **Growth** du Project Editor et est disponible pour les builders disposant d&#39;un plan payant. Suivez ces étapes pour analyser votre application et appliquer les corrections.

<Steps>
  <Step title="Déployez votre application pour débloquer Growth">
    SEO Agent fonctionne sur les applications déployées. Avant le déploiement, le panneau **Growth** est verrouillé et vous invite à cliquer sur **Go to Publishing**. Déployez votre application depuis le chat Agent ou l’outil **Publishing**, puis revenez au panneau Growth.

    </Frame>
  </Step>

  <Step title="Lancer une analyse avec Agent">
    Ouvrez le panneau **Growth** et repérez la carte **Score SEO**. Sélectionnez **Run scan with Agent** pour lancer un audit SEO technique de votre projet. L’analyse prend généralement quelques minutes.

    <Frame caption="Sélectionnez Run scan with Agent dans la carte Score SEO pour lancer l’audit">

  <Step title="Modifier avec Agent ou tout modifier avec Agent">

Développez chaque problème pour voir ce que SEO Agent a détecté.

    * Sélectionnez **Fix all with Agent** pour transmettre tous les problèmes à Agent en une seule fois. Le bouton **Fix all issues** du chat offre la même fonctionnalité.

<Tip>
  Vous pouvez même ignorer entièrement l’interface d’analyse. Ouvrez Agent et dites-lui **&quot;optimise mon
  SEO&quot;** ; Agent récupérera les résultats les plus récents et se mettra au travail.
</Tip>

Modifications courantes appliquées par Agent :

* Ajout ou réécriture des balises `<title>` manquantes ou génériques afin que chaque page ait un titre unique et descriptif.
* Ajout de méta-descriptions à toutes les pages.
* Ajout d’un texte `alt` descriptif aux images.
* Définition de l’attribut `lang` sur l’élément `<html>`.
* Vérification que les liens comportent un texte identifiable (pas de « cliquez ici » ni d’ancres vides).
* Ajout de `robots.txt` et de `sitemap.xml`.
* Ajout d’une balise méta viewport pour l’affichage sur mobile.
* Amélioration du contraste des couleurs du texte qui échoue aux vérifications d’accessibilité.
* Ajout de balises méta Open Graph et Twitter Card afin que les liens vers l’application s’affichent correctement en aperçu sur les plateformes sociales.

<div id="seo">
  ## Bonnes pratiques pour optimiser le SEO de votre application
</div>

Que vous demandiez à Agent de s’en charger ou que vous le fassiez vous-même, voici les éléments les plus importants.

* **Attribuez à chaque page un titre et une méta-description uniques.** Visez des titres de moins de 60 caractères et des descriptions de 150~160 caractères.
* **Utilisez du HTML sémantique.** Structurez la mise en page avec `<main>`, `<header>`, `<nav>`, `<footer>`. Utilisez un seul `<h1>` par page et respectez l’ordre des niveaux de titre.
* **Ajoutez un texte alternatif à toutes les images.** Décrivez ce que montre l’image, et non ce qu’elle est.
* **Créez `sitemap.xml` et `robots.txt`.** Demandez à Agent de créer les deux afin que les moteurs de recherche sachent quoi explorer.
* **Ajoutez les balises Open Graph et les Twitter Cards.** Elles contrôlent l’apparence de votre application lorsqu’elle est partagée sur les réseaux sociaux.
* **Utilisez un domaine personnalisé.** Un domaine associé à votre marque renforce la confiance des visiteurs et des moteurs de recherche. Consultez [Ajouter un domaine personnalisé](/fr/ko/build/add-custom-domain).
* **Choisissez le bon type de déploiement.** Pour les sites riches en contenu, un [déploiement Static](/fr/ko/features/publishing/deployment-types#static) fournit du HTML pré-rendu que les moteurs de recherche analysent immédiatement.
* **Ajoutez des données structurées.** Le balisage JSON-LD aide les moteurs de recherche à afficher des résultats enrichis pour les produits, les articles, les FAQ et les événements.
* **Maintenez votre application rapide.** Optimisez les images, évitez les scripts qui bloquent le rendu et tirez parti de l’hébergement Replit pour réduire les temps de réponse.

Voici un moyen simple d’appliquer la plupart de ces éléments en une seule fois :

</AiPrompt>

<div id="section-2">
  ## Besoin d’aide supplémentaire ?
</div>

* **Le score ne se met pas à jour après un redéploiement :** attendez 1~2 minutes — les audits s’exécutent de manière asynchrone une fois le déploiement terminé, et le badge s’actualise lorsque les résultats sont disponibles.
* **Le score reste identique après des modifications effectuées par Agent :** demandez à Agent quels éléments Lighthouse spécifiques il a traités et vérifiez ceux qui figurent encore dans l’infobulle du badge.
* **Le score de certaines pages est inférieur à celui d’autres pages :** le badge affiche le score le plus bas parmi toutes les URL explorées. Demandez à Agent de se concentrer sur la page précise signalée par Lighthouse.
* **Aucun score ne s’affiche pour une application déployée :** les scores SEO ne sont calculés que pour les types de déploiement publics accessibles sur le Web (Autoscale, Reserved VM, Static). Les déploiements planifiés et privés ne génèrent pas de score.
