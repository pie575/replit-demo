title: "Analyse de sécurité d’Agent"
description: "Effectuez une revue de sécurité du code source, évaluez les résultats de l’analyse, corrigez les vulnérabilités avec Agent et vérifiez les corrections."
---

L’analyse de sécurité d’Agent examine l’ensemble de votre base de code afin d’identifier les vulnérabilités de sécurité et de confidentialité. Security Agent combine une analyse basée sur des modèles et des outils d’analyse statique tels que [Semgrep](https://semgrep.dev/) et [HoundDog.ai](https://hounddog.ai), puis présente les résultats dans le Centre de sécurité du projet.

L’analyse de sécurité d’Agent est disponible pour tous les utilisateurs payants de Replit. Pour les projets volumineux, un audit approfondi peut prendre jusqu’à 15 minutes.

<div id="security-agent">
  ## Ce que Security Agent examine
</div>

Lorsque vous lancez une analyse, Security Agent effectue les actions suivantes :

1. Il cartographie les routes, les API, les flux de données et les points d’entrée.
2. Il élabore un modèle de menace pour l’application.
3. Il exécute une analyse statique sur l’ensemble de la base de code.
4. Il évalue les résultats de l’analyse dans le contexte de l’application.
5. Il génère un rapport des résultats à examiner.

Cette analyse peut identifier des pratiques de code non sécurisées, telles que l’injection SQL, le cross-site scripting et la falsification de requêtes intersites, des problèmes de confidentialité, comme des données sensibles transmises aux journaux ou à des API tierces, ainsi que des vulnérabilités architecturales dans les routes, les API et les flux de données.

<div id="agent">
  ## Lancer une analyse de sécurité d’Agent
</div>

<Steps>
  <Step title="Ouvrir le Security Center">
    Dans le volet **Tools** du projet, sélectionnez **Security Center**. Vous pouvez également sélectionner **Review security** dans le flux Publish.

    <Frame>
      <img src="/assets/mirror/review-security-button-9331149c28f7.png" alt="Action « Review security » dans le flux Publish" width="1440" height="900" data-path="images/project-security-center/review-security-button.png" />
    </Frame>
  </Step>

  <Step title="Lancer l’analyse">
    Sélectionnez **Run scan with Agent**.

    <Frame>
      <img src="/assets/mirror/run-scan-with-agent-f54820ac154a.png" alt="Action « Run scan with Agent » dans le Centre de sécurité du projet" width="1440" height="900" data-path="images/project-security-center/run-scan-with-agent.png" />
    </Frame>
  </Step>

  <Step title="Ajouter du contexte si nécessaire">
    Ajoutez du contexte si nécessaire afin de cibler le modèle de menace sur des parties spécifiques de votre application avant de lancer l’analyse de sécurité.

    <Frame>
      <img src="/assets/mirror/scan-options-c2cd398fa78b.png" alt="Options d’analyse de sécurité incluant le champ « Add context » et l’action « Start security scan »" width="1440" height="900" data-path="images/project-security-center/scan-options.png" />
    </Frame>
  </Step>

  <Step title="Attendre la fin de l’examen">
    Attendez que Security Agent termine son examen. Cela prend généralement quelques minutes, mais peut prendre jusqu’à 15 minutes pour les grands projets.
  </Step>
</Steps>

<div id="section">
  ## Examiner et corriger les résultats d’analyse
</div>

<Steps>
  <Step title="Examiner le rapport">
    Consultez chaque résultat d’analyse et son niveau de gravité dans le
    **Security Center**. Rejetez les résultats que vous comprenez et acceptez,
    ou corrigez-les avant de les envoyer pour correction.
  </Step>

  <Step title="Corriger les résultats approuvés avec Agent">
    Envoyez les problèmes approuvés à Agent. Security Agent organise les vulnérabilités en tâches
    distinctes, ce qui permet à Agent de traiter plusieurs corrections en parallèle.
  </Step>

  <Step title="Relancer l’analyse">
    Une fois les corrections appliquées par Agent, exécutez une autre analyse pour vérifier que les problèmes ont été résolus.
    Dans les grands projets, des problèmes supplémentaires peuvent apparaître après la correction des résultats d’analyse
    les plus graves.
  </Step>
</Steps>

<div id="level-3">
  ## Quand utiliser Level 3
</div>

L’analyse de sécurité d’Agent examine le code source. Si vous devez également vérifier une application en cours d’exécution par le biais de ses interactions avec le navigateur et le réseau, utilisez les [tests d’intrusion en boîte noire de Level 3](/fr/ja/features/security/black-box-pen-tests). Level 3 exécute simultanément des tests en boîte noire et une revue du code source.

<div id="section-2">
  ## Limites et bonnes pratiques
</div>

* Les analyses sont effectuées sur l’infrastructure de Replit. Replit n’envoie ni votre code ni vos données à Semgrep, HoundDog.ai ou à d’autres tiers.
* La configuration et les résultats des analyses restent associés à votre App Replit.
* Les analyses ne remplacent pas un examen de sécurité complet. Utilisez-les conjointement avec des revues de code, des tests, des revues des dépendances et des vérifications de l’application en cours d’exécution.
* Relancez les analyses après avoir apporté des modifications importantes au code, ajouté ou mis à jour des dépendances, et avant de publier une nouvelle version.
