每个 Replit App 都配有两个数据库。**开发数据库**供你和 Agent 在构建过程中进行试验。**生产数据库**存储支撑已发布应用的线上数据，让你在持续构建的同时确保真实数据的安全。

<div id="how-they-compare">
  ## 两者对比
</div>

| 方面        | 开发数据库               | 生产数据库            |
| --------- | ------------------- | ---------------- |
| **用途**    | 实验与功能开发             | 服务真实用户、存储业务数据    |
| **数据**    | 测试数据、虚拟记录、小型数据集     | 真实用户数据、业务关键信息    |
| **创建时机**  | 随每个 Replit App 自动创建 | 发布应用时创建          |
| **Agent** | Agent 可以创建和修改数据表    | Agent 无法操作       |
| **变更**    | 架构频繁变更、快速迭代         | 谨慎、有计划的变更，在发布时生效 |
| **计费**    | 每个 Replit App 免费包含  | 按用量计费            |

<Note>
  Agent 无法修改生产数据库。设置此限制是为了保障生产数据库的安全。

  Agent 可以编辑你的开发数据库。发布时，你通过 Agent 对开发数据库结构所做的更改 (新增或删除列、表) 都会应用到生产数据库。

  你随时可以手动编辑生产数据：打开 **Database** 工具，选择生产数据库，打开 **My Data**，然后切换 **Edit**。
</Note>

<div id="create-a-production-database-when-you-publish">
  ## 发布时创建生产数据库
</div>

已发布的应用会拥有自己的生产数据库，与你在构建过程中使用的开发数据库彼此独立。

* **当前基础设施 (Helium)&#x20;**：发布过程中如有需要，Replit 会自动为你创建生产数据库，无需任何设置。
* **旧版 Neon 开发数据库**：需要你在发布设置中创建生产数据库。发布时打开 **Production database settings**，开启 **Create production database**；如需将开发数据一并复制过去，还可开启 **Set up your production database with your current development data**。

<Frame caption="Publishing 中的生产数据库设置">
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="显示 Create production database 选项的发布设置" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  只有确认开发数据可以安全地用于线上应用时，才将其复制到生产环境。开发数据可能包含测试账户、示例记录或不完整的内容。
</Warning>

发布后，已发布的应用会使用生产数据库，而 Project Editor 仍继续使用开发数据库，因此后续的开发改动不会直接影响线上数据。

<div id="connection-pooling">
  ## 连接池
</div>

默认情况下，生产数据库不会启用连接池。你的应用通过 `DATABASE_URL` 连接字符串直接连接数据库，因此大多数框架都应自行管理客户端连接池。

<Note>
  每个 Neon project 都提供一个直连连接字符串和一个连接池连接字符串。直连连接字符串的格式类似于 `postgresql://neondb_owner:<password>@<host>.<region>.neon.tech/<db>?sslmode=require`。

  若要使用连接池连接，请在主机名后加上 `-pooler`：`postgresql://neondb_owner:<password>@<host>-pooler.<region>.neon.tech/<db>?sslmode=require`。
</Note>

如果生产环境的连接字符串已泄露，请[重新生成生产数据库凭据](/zh/features/data-and-storage/connection-details#regenerate-production-database-credentials)。

<div id="making-safe-changes-to-your-production-database">
  ## 安全地变更生产数据库
</div>

发布包含数据库变更的更新时，某些变更需要仔细规划，以免造成停机或数据丢失。

<Info>
  在发布过程中，已发布的应用可能会出现短暂停机。数据库变更有时需要临时停止应用，以避免冲突并在变更应用期间保护你的数据。
</Info>

以下类型的变更通常需要谨慎处理：

* **删除数据库列**，而应用代码仍在引用这些列
* **更改列的数据类型**，且现有代码无法处理新类型
* 向现有表**添加没有默认值的必填字段**
* **重命名表或列**，导致现有查询失效
* **修改约束**，可能导致现有应用逻辑被拒绝

<div id="test-changes-with-a-deployment-preview">
  ### 使用部署预览测试变更
</div>

部署预览是生产环境的临时隔离副本，可让你在数据库变更和应用更新影响真实用户之前进行测试。你可以用它来：

* 验证应用在应用数据库变更后，各主要用户流程仍能正常运行
* 确认现有数据已正确迁移，且新字段包含预期值
* 留意查询响应时间是否出现性能回退

<div id="billing-and-resource-usage">
  ## 计费与资源用量
</div>

生产数据库通过无服务器数据库服务商 Neon 按用量计费。数据库在无活动五分钟后进入空闲状态，此时暂停计算时间计费；一旦收到查询会立即恢复运行。

Database 工具的首页视图会显示你的 **Billing Period** (计费周期) 和 **Hours of Compute Used** (已使用的计算小时数) 。若要查看单个数据库的存储用量，请打开该数据库的 **Settings** 选项卡。若要查看所有 Replit App 的用量，请依次打开 **Settings** → **Account** → **Account usage**，并展开 **PostgreSQL Storage** 和 **PostgreSQL Compute** 两行。

如需了解 Replit 如何对数据库用量收费，请参阅 [Deployments and Database Billing](/zh/billing/about-usage-based-billing#databases)。

<div id="removing-a-production-database">
  ## 移除生产数据库
</div>

<Warning>
  移除操作在 7 天保留期结束后将无法撤销。请务必在操作前备份所有重要数据。数据库有 7 天的软删除期，在此期间仍可恢复；如需帮助，请联系支持团队。7 天后，数据库将被彻底删除，无法恢复。
</Warning>

<Accordion title="如何移除数据库">
  在 **Database** 工具中：

  1. 选择数据库，然后打开 **Settings** 选项卡
  2. 选择 **Remove database**，然后选择 **Yes, Remove database** 进行确认
</Accordion>

<div id="legacy-development-database">
  ## 旧版开发数据库
</div>

在 2025 年 12 月 4 日之前，开发数据库托管在 <a href="https://neon.com/" target="_blank">Neon</a> 上。现在所有新建的开发数据库都托管在 Replit 自有基础设施 (Helium) 上。你可以在 **Settings** 选项卡中查看应用使用的是哪一种：`DATABASE_URL` 中包含 `neon.tech` 表示旧版 Neon；包含 `helium` 则表示当前基础设施。

| **功能**       | **Replit (当前)&#x20;**&#x20;                                                 | **Neon (旧版)&#x20;**&#x20;                                              |
| ------------ | ---------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **托管**       | 托管在 Replit 自有基础设施上                                                     | 托管在 Neon (第三方服务商) 上                                               |
| **计费**       | 每个 Replit App 均免费包含                                                    | 按用量计费。详见[发布与数据库计费](/zh/billing/about-usage-based-billing#databases)。 |
| **恢复能力**     | 通过[回滚功能](/zh/features/data-and-storage/data-recovery)将数据库恢复到任意 checkpoint | 时间点恢复 (PITR) ：可恢复到备份保留窗口内的任意时间点。                                  |
| **连接安全性**    | 仅能从应用内部访问，不会对外公开暴露。                                                    | 使用完整的连接字符串。一旦泄露，任何人都可以访问并修改你的数据库。                                 |
| **Remix 行为** | [Remix](/zh/build/remix-an-app) 会创建一个新的开发数据库并复制数据，从而实现隔离与安全。              | Remix 后所有副本共用同一个数据库，因此副本中的改动可能影响原始应用。                             |
| **数据库创建**    | 为每个 Replit App 自动创建。                                                   | 需要手动设置。                                                           |
| **发布流程**     | 发布时会创建独立的生产数据库，实现环境之间的隔离。                                              | 开发环境与生产环境共用同一个数据库，因此开发中的误操作可能影响生产应用。                              |

<div id="database-infrastructure-upgrade">
  ## 数据库基础设施升级
</div>

Replit 正在将开发数据库从 Neon 升级到 **Helium**——Replit 自研的托管 PostgreSQL 基础设施。升级自动进行，每个应用在你于 Project Editor 中首次打开时执行一次，并完整保留你的所有数据。

变更内容：

* **更低延迟、更大存储**：你的数据库与应用一同运行在 Replit 基础设施上，存储上限从 10 GB 提升到 20 GB。
* **数据库引擎不变**：Helium 使用 PostgreSQL 16，与 Neon 的版本相同。你的查询、模式和数据的使用方式完全一致。
* **连接自动更新**：`DATABASE_URL` 会自动更新为指向 Helium。原有的 Neon 连接字符串会以 `NEON_DATABASE_URL` 保存在 Secrets 中，供你参考。
* **移除单独的 PG 变量**：`PGHOST`、`PGPORT`、`PGUSER` 和 `PGPASSWORD` 将被移除，请改用 `DATABASE_URL`。

升级期间你会看到 **“正在升级你的数据库”** 进度界面。视数据库大小，耗时从几分钟到几小时不等；你可以关闭标签页，稍后再回来。如果升级遇到问题，系统会自动跳过，并在你下次打开应用时重试。升级完成后会弹出确认对话框。

对大多数构建者来说，升级后无需做任何操作。若涉及以下情况，请注意处理：

* **硬编码的 Neon 连接字符串**：请将引用 `neon.tech` 连接字符串的代码改为使用 `DATABASE_URL` 环境变量。
* **自定义 PostgreSQL 角色**：角色和权限会自动迁移，但角色密码无法复制。请在新数据库上为自定义角色重置密码。

<div id="ssl-connection-errors-after-the-upgrade">
  ### 升级后出现 SSL 连接错误
</div>

如果你看到类似 `The server does not support SSL connections` 的错误，说明连接代码强制要求进行 SSL 握手。Neon 要求使用 SSL；而 Helium 与你的应用在本地一同运行，并不使用 SSL。请将 SSL 设置改为根据环境动态启用：

<CodeGroup>
  ```js JavaScript theme={null}
  // 修改前（升级后会出错）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl: { rejectUnauthorized: false },
  });

  // 修改后（开发和生产环境均可正常运行）
  const pool = new Pool({
    connectionString: process.env.DATABASE_URL,
    ssl:
      process.env.NODE_ENV === "production"
        ? { rejectUnauthorized: false }
        : false,
  });
  ```
</CodeGroup>

<Tip>
  如果你使用 Drizzle、Prisma 或 Sequelize 等 ORM，请查阅其文档，了解如何按环境配置 SSL。原理相同：开发数据库禁用 SSL，生产环境启用 SSL。
</Tip>

<div id="forked-apps-that-shared-a-database">
  ### 共用同一数据库的分叉应用
</div>

在旧版 Neon 系统中，分叉应用时会复制原应用的 `DATABASE_URL`，因此两个应用及其已发布版本会连接到同一个数据库。共用的旧版数据库已于 **2026 年 6 月 8 日**停止运行。如果你已发布的应用无法正常运行或无法访问其数据，请参阅[修复使用共享数据库的已发布应用](/zh/features/data-and-storage/shared-database-migration)或[联系支持团队](https://replit.com/support)。
