В этом руководстве представлен подробный контрольный список безопасности, который поможет вашим приложениям, созданным методом vibe coding, соответствовать рекомендациям по безопасности.

Хотя Replit предоставляет множество встроенных функций безопасности [из коробки](/ru/pt/features/security/overview), важно понимать и внедрять дополнительные меры безопасности с учетом конкретных потребностей вашего приложения.

<div id="segurana-no-front-end">
  ## Безопасность на фронтенде
</div>

<AccordionGroup>
  <Accordion title="HTTPS повсюду" icon="lock">
    Replit по умолчанию использует HTTPS для всех приложений, поэтому вам не нужно об этом беспокоиться!
  </Accordion>

  <Accordion title="Проверка и очистка входных данных" icon="shield-check">
    Всегда проверяйте и очищайте пользовательский ввод, чтобы предотвратить атаки межсайтового скриптинга (XSS):

    ```javascript theme={null}
    // Плохо: прямое использование пользовательского ввода
    element.innerHTML = userInput;

    // Хорошо: очистите ввод перед использованием
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    Спросите Agent:

    ```
    Помоги мне проверять и очищать входные данные для защиты от XSS-атак
    ```
  </Accordion>

  <Accordion title="Не храните конфиденциальные данные в браузере" icon="eye-slash">
    Для хранения конфиденциальной информации, например ключей API, используйте Secrets в Replit.

    Не передавайте секреты на стороне клиента и не храните их в следующих местах:

    * Локальное хранилище
    * Хранилище сессии
    * JavaScript на стороне клиента
    * Файлы cookie без соответствующих атрибутов безопасности

    Спросите Agent:

    ```
    Помоги мне не хранить конфиденциальные данные в браузере. Всё ли я делаю правильно?
    ```
  </Accordion>

  <Accordion title="Защита от CSRF" icon="shield">
    Реализуйте защиту от межсайтовой подделки запросов (CSRF) для форм:

    ```javascript theme={null}
    // Пример реализации CSRF-токена
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    Спросите Agent:

    ```
    Помоги мне реализовать CSRF-токены для форм
    ```
  </Accordion>
</AccordionGroup>

<div id="segurana-no-back-end">
  ## Безопасность серверной части
</div>

<AccordionGroup>
  <Accordion title="Основы аутентификации" icon="key">
    При реализации аутентификации:

    * По возможности используйте Replit Auth
    * Если вы создаёте собственную систему аутентификации, используйте проверенные библиотеки
    * Никогда не храните пароли в открытом виде

    Спросите Agent:

    ```
    Help me implement authentication for my application with Replit Auth
    ```
  </Accordion>

  <Accordion title="Проверка авторизации" icon="user-lock">
    Всегда проверяйте права доступа перед выполнением действий:

    ```javascript theme={null}
    // Пример проверки авторизации
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    Спросите Agent:

    ```
    Help me implement authorization checks for my application
    ```
  </Accordion>

  <Accordion title="Защита API-эндпоинтов" icon="shield">
    Защитите API-эндпоинты:

    * Добавьте аутентификацию для чувствительных эндпоинтов
    * Правильно настройте CORS
    * Рассмотрите возможность ограничения частоты запросов

    Спросите Agent:

    ```
    How do I properly authenticate endpoints in my app?
    ```
  </Accordion>

  <Accordion title="Предотвращение SQL-инъекций" icon="database">
    Agent по умолчанию использует ORM, что помогает предотвратить SQL-инъекции. Если вы пишете собственные запросы к базе данных:

    ```javascript theme={null}
    // Плохо: конкатенация строк в запросах
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // Хорошо: параметризованные запросы с ORM
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="Заголовки безопасности" icon="code">
    Добавьте в приложение важные заголовки безопасности:

    ```html theme={null}
    <!-- В index.html или через серверную часть -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    Проверьте свой сайт на [securityheaders.com](https://securityheaders.com), чтобы получить рекомендации.

    Спросите Agent:

    ```
    Can you add the security headers to my application?
    ```
  </Accordion>
</AccordionGroup>

<div id="prticas-contnuas-de-segurana">
  ## Постоянные меры безопасности
</div>

<AccordionGroup>
  <Accordion title="Поддерживайте зависимости в актуальном состоянии" icon="arrow-rotate-right">
    Регулярно проверяйте наличие устаревших пакетов с возможными уязвимостями:

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="Правильная обработка ошибок" icon="exclamation">
    Не раскрывайте конфиденциальную информацию в сообщениях об ошибках:

    ```javascript theme={null}
    // Плохо: раскрываются конфиденциальные данные
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // Хорошо: общее сообщение об ошибке
    catch (err) {
      console.error(err); // Внутренний журнал
      res.status(500).send('An error occurred');
    }
    ```

    Спросите Agent:

    ```
    Помоги мне реализовать правильную обработку ошибок в моем приложении
    ```
  </Accordion>

  <Accordion title="Безопасные файлы cookie" icon="cookie">
    При использовании файлов cookie:

    * Установите флаг HttpOnly, чтобы предотвратить доступ через JavaScript
    * Используйте атрибут Secure, чтобы требовать HTTPS
    * Используйте атрибут SameSite для защиты от CSRF

    Спросите Agent:

    ```
    Помоги мне защитить файлы cookie в моем приложении
    ```
  </Accordion>

  <Accordion title="Безопасная загрузка файлов" icon="upload">
    Если ваше приложение позволяет загружать файлы:

    * Ограничьте типы и размеры файлов
    * По возможности проверяйте их на наличие вредоносного ПО
    * Храните файлы в объектном хранилище Replit
    * Генерируйте новые имена файлов вместо использования имен, заданных пользователем

    Спросите Agent:

    ```
    Помоги мне защитить загрузку файлов в моем приложении
    ```
  </Accordion>

  <Accordion title="Ограничение частоты запросов" icon="clock">
    Настройте ограничение частоты запросов для API-эндпоинтов, особенно связанных с аутентификацией:

    ```javascript theme={null}
    // Пример middleware для ограничения частоты запросов
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15 минут
      max: 100 // не более 100 запросов с одного IP-адреса за windowMs
    });

    app.use('/api/', limiter);
    ```

    Спросите Agent:

    ```
    Помоги мне реализовать ограничение частоты запросов для моего приложения
    ```
  </Accordion>
</AccordionGroup>

<div id="segurana-no-front-end-2">
  ## Безопасность фронтенда
</div>

|   | Мера безопасности                             | Описание                                                                     |
| - | --------------------------------------------- | ---------------------------------------------------------------------------- |
| ☐ | Используйте HTTPS везде                       | Предотвращает перехват данных и атаки «человек посередине»                   |
| ☐ | Проверка и очистка входных данных             | Предотвращает XSS-атаки за счёт проверки всех данных, вводимых пользователем |
| ☐ | Не храните конфиденциальные данные в браузере | Не храните секреты в локальном хранилище или клиентском коде                 |
| ☐ | Защита от CSRF                                | Используйте анти-CSRF-токены для форм и запросов, изменяющих состояние       |
| ☐ | Никогда не раскрывайте API-ключи во фронтенде | Учётные данные API всегда должны оставаться на стороне сервера               |

| ☐ | Предотвращение SQL-инъекций     | Используйте параметризованные запросы или ORM; никогда не используйте необработанный SQL с пользовательским вводом |
| ☐ | Основные заголовки безопасности | Реализуйте X-Frame-Options, X-Content-Type-Options и HSTS                                                          |
