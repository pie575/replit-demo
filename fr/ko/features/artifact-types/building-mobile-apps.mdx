<div id="section-2">
  ## Aperçu dans un simulateur ou un émulateur
</div>

Replit vous permet d&#39;exécuter et de tester votre application mobile sur votre téléphone grâce à Expo. Replit peut aussi diffuser un véritable **iOS Simulator** ou **Android Emulator** directement dans le panneau Preview. Les modifications effectuées par Agent sont répercutées immédiatement dans le simulateur, comme sur un appareil réel (hot-reload).

<Note>
  Les aperçus iOS Simulator et Android Emulator sont accessibles aux builders des plans Core, Pro et Enterprise. Ils concernent uniquement les applications mobiles — cette option n&#39;apparaît pas dans les projets exclusivement web.
</Note>

  ### Prise en charge des navigateurs
</div>

* **Chrome**, **Safari** et les navigateurs basés sur Chromium sont entièrement pris en charge.

<div id="expo-go">
  ### Quand utiliser plutôt Expo Go
</div>

Utilisez Expo Go sur un vrai téléphone lorsque vous devez tester des fonctionnalités qui dépendent du matériel réel, ou lorsque vous souhaitez partager un aperçu avec une personne qui n&#39;est pas devant son ordinateur :

* Appareil photo, microphone, retour haptique et autres capteurs natifs
* Notifications push
* Position GPS réelle
* Partage d&#39;un aperçu de développement avec des coéquipiers, des testeurs ou des investisseurs

Pour ouvrir votre app dans Expo Go, ouvrez votre projet sur [replit.com](https://replit.com), sélectionnez **Open in Expo Go** dans le panneau Preview du Project Editor, puis scannez le code QR avec l&#39;app [Expo Go](https://expo.dev/go) sur votre téléphone.

<div id="section-6">
  ## Pourquoi créer une application mobile ?
</div>

Créez une application mobile lorsque vous avez besoin de :

* **Expérience native** : des performances rapides, des interactions fluides et une interface native à la plateforme.
* **Fonctionnalités de l&#39;appareil** : appareil photo, notifications push, localisation, etc.
* **Distribution sur l&#39;App Store** : une fiche partageable que les utilisateurs peuvent découvrir et installer, une fois le processus d&#39;App Review d&#39;Apple validé.

<div id="section-7">
  ## Fonctionnalités principales
</div>

* **Génération par IA** : décrivez votre application et Agent crée la structure de base d&#39;une application mobile fonctionnelle.
* **Aperçu dans le Project Editor** : testez dans le simulateur iOS ou l&#39;émulateur Android sans quitter Replit, ou prévisualisez sur votre téléphone avec Expo Go.
* **Full stack par défaut** : ajoutez des routes serveur, Database, App Storage, Connectors et des intégrations d&#39;IA à mesure que votre application évolue.
* **Soumission guidée** : préparez vos builds pour la soumission sur TestFlight et l&#39;App Store sans avoir à gérer de chaîne d&#39;outils iOS en local.

<div id="section-8">
  ## Workflow de développement
</div>

Votre application est accessible à trois étapes, chacune destinée à un public et à des usages différents :

| Étape             | Accessible à               | Méthode d’accès                                      | Idéal pour                                  |
| ----------------- | -------------------------- | ---------------------------------------------------- | ------------------------------------------- |
| **Développement** | Vous-même                  | Simulateur du Project Editor ou code QR pour Expo Go | Création et itération                       |
| **Déploiement**   | Testeurs utilisant Expo Go | URL publique avec code QR                            | Aperçu de développement, prototypage, démos |
| **App Store**     | Tout le monde              | Téléchargement depuis l’App Store après l’App Review | Version de production                       |

**Développement** : lorsque vous lancez l’application, vous pouvez l’afficher dans l’**iOS Simulator** ou l’**Android Emulator** du Project Editor, ou scanner le code QR dans le panneau Preview pour l’ouvrir dans Expo Go sur votre téléphone.

**Déploiement** : lorsque vous cliquez sur **Publish**, Replit crée une URL publique contenant un code QR pour Expo Go. Cette option est idéale pour les aperçus de développement et le prototypage, afin de présenter votre application à des investisseurs, recueillir des retours ou la tester avec des amis avant d’entamer le processus de publication sur l’App Store.

**App Store** : lorsque vous soumettez votre application à l’App Store, Apple l’examine. Après approbation, les utilisateurs peuvent la télécharger et l’installer depuis l’App Store. Un compte Apple Developer est requis.

<div id="section-10">
  ## Où créer des applications mobiles natives
</div>

L&#39;environnement Replit s&#39;exécute dans le cloud, et non sur votre machine locale. Pour créer des applications mobiles natives, utilisez le Project Editor sur [replit.com](https://replit.com). Tout le flux de travail mobile — génération de la structure par Agent, aperçu avec Expo Go, tests sur simulateur/émulateur, builds TestFlight et soumission à l&#39;App Store — se déroule dans le Project Editor.

Le travail sur les applications mobiles natives est également possible depuis l&#39;[application Replit pour Android](/fr/ko/features/platforms/mobile-app), lorsque celle-ci le prend en charge. Si vous utilisez l&#39;application Replit pour iOS, ouvrez votre projet sur [replit.com](https://replit.com) pour créer, prévisualiser, compiler ou soumettre des applications mobiles natives.

<div id="section-11">
  ## Fonctionnement technique
</div>

Les applications mobiles reposent sur plusieurs piles technologiques qui fonctionnent de concert. Cette section explique ce qui fait tourner votre application et comment chaque élément s&#39;imbrique aux autres.

<div id="section-12">
  ### Stack technique
</div>

<MobileStackDiagram />

* **React Native** est un framework open source qui permet d&#39;écrire une seule base de code et de la compiler pour iOS, Android et le web. Il affiche des composants d&#39;interface natifs à la plateforme, et non une vue web.
* **Expo** simplifie le développement React Native en prenant en charge la compilation, en gérant les modules natifs et en fournissant des outils d&#39;aperçu comme Expo Go.
* **Expo Go** est une application gratuite que vous installez sur votre téléphone. Elle exécute des aperçus de développement, ce qui vous permet de tester sur un appareil réel sans avoir à compiler un binaire natif complet.

Lorsque vous lancez votre application, le bundler Metro compile le code et l&#39;envoie à l&#39;appareil. La première compilation est plus longue, car aucun cache n&#39;existe encore. Les compilations suivantes sont plus rapides.

<div id="section-13">
  ### Architecture : serveur et client
</div>

Lorsque vous préparez une application mobile pour la prévisualisation ou le déploiement, deux éléments entrent en jeu :

1. Le **serveur**, exécuté dans le cloud sur Replit. Il gère la base de données, les routes d&#39;API, les intégrations d&#39;IA et la logique backend.
2. L&#39;**application cliente**, exécutée sur le téléphone de l&#39;utilisateur. Pendant le développement, vous la prévisualisez dans Expo Go ; après validation, elle est distribuée sous forme d&#39;application native via les app stores.

<MobileArchitectureDiagram />

Cette séparation offre une grande souplesse. Vous pouvez exécuter la logique complexe côté serveur (avec accès à Database, Object Storage et aux Connectors de Replit) tout en gardant le client léger. Au fil du développement, demandez-vous ce qui doit être traité sur le téléphone et ce qui relève du cloud.

<div id="section-14">
  ## Points à prendre en compte
</div>

* **Exigences de publication** : Apple définit les exigences de TestFlight et de l&#39;App Store, et examine les apps iOS avant leur déploiement.
* **Publication sur Android** : vous pouvez créer des apps multiplateformes pour iOS et Android. L&#39;expérience guidée de publication sur Google Play n&#39;est pas encore prise en charge, mais vous pouvez procéder manuellement.
* **Modifications natives** : les changements tels que l&#39;icône de l&#39;app ou les autorisations nécessitent généralement un nouveau build destiné aux stores.

  ## FAQ

<AccordionGroup>
  <Accordion title="Qu'est-ce qu'Expo ?">
    Expo est l&#39;outil utilisé par Agent pour créer des applications mobiles sur Replit. Il s&#39;agit d&#39;une plateforme et d&#39;une chaîne d&#39;outils open source permettant de créer, exécuter et déployer des applications natives multiplateformes avec React Native. Pour en savoir plus, consultez [https://expo.dev](https://expo.dev).
  </Accordion>

  <Accordion title="Qu'est-ce que React Native ?">
    React Native est un framework open source de Meta permettant de créer des applications natives iOS et Android avec React et JavaScript ou TypeScript. Il affiche les composants d&#39;interface natifs de la plateforme (et non des vues web) : votre application a donc vraiment l&#39;apparence et le comportement d&#39;une application native.
  </Accordion>

  <Accordion title="Qu'est-ce qu'Expo Go ?">
    Expo Go est une application gratuite que vous installez sur votre téléphone depuis l&#39;App Store ou Google Play. Elle vous permet de prévisualiser l&#39;application mobile que vous développez sans avoir à créer un binaire natif complet. Lorsque vous scannez le QR code depuis le Project Editor, Expo Go télécharge et exécute le code de votre application.
  </Accordion>

  <Accordion title="Quelle est la différence entre Expo Go et un build de développement (dev build) ?">
    **Expo Go** est une application préconstruite qui exécute votre code. La configuration est rapide, mais seuls les modules inclus dans le SDK Expo sont pris en charge.

    Un **build de développement** est un binaire natif personnalisé pouvant inclure n&#39;importe quel module natif. Il demande davantage de configuration (EAS Build ou Xcode/Android Studio en local), mais offre une plus grande flexibilité.

    Replit utilise Expo Go pour les aperçus de développement. Si vous avez besoin de modules natifs non pris en charge par Expo Go, vous devrez peut-être vous tourner vers les builds de développement, décrits dans [la documentation d&#39;Expo](https://docs.expo.dev/develop/development-builds/introduction/).
  </Accordion>

  <Accordion title="En quoi est-ce différent d'une application web adaptée au mobile ?">
    Une application web adaptée au mobile est un site web dont la mise en page s&#39;ajuste dans le navigateur. Une application React Native est une application native installée sur l&#39;appareil : elle utilise les API de la plateforme (caméra, retour haptique, notifications push), accède plus facilement au matériel et aux fonctionnalités hors ligne, et se distribue via les magasins d&#39;applications. Le web adaptatif est idéal pour la portée et l&#39;accès sans installation ; le natif s&#39;impose lorsque vous avez besoin des fonctionnalités de l&#39;appareil, de performances ou d&#39;une distribution sur l&#39;App Store.
  </Accordion>

  <Accordion title="Ai-je besoin d'un Mac ou de Xcode ?">
    Non. Replit et Expo gèrent le processus de build à votre place, dans le cloud.
  </Accordion>

  <Accordion title="Puis-je prévisualiser sans compte Apple Developer ?">
    Oui. Vous pouvez prévisualiser dans le simulateur iOS du Project Editor ou dans Expo Go sur votre téléphone. Un compte Apple Developer n&#39;est nécessaire que lorsque vous êtes prêt à soumettre l&#39;application à TestFlight ou à l&#39;App Store.
  </Accordion>

  <Accordion title="Android est-il également pris en charge ?">
    Oui. Vous pouvez créer des applications multiplateformes pour iOS et Android à partir d&#39;une même base de code. Prévisualisez dans l&#39;émulateur Android du Project Editor ou sur un appareil Android équipé d&#39;Expo Go. La publication sur Google Play peut se faire manuellement.
  </Accordion>

  <Accordion title="Qu'en est-il des serveurs et des bases de données ?">
    Utilisez PostgreSQL, Object Storage, les Connectors et les intégrations d&#39;IA intégrés à Replit, sans infrastructure supplémentaire. Le serveur s&#39;exécute sur Replit et l&#39;application mobile s&#39;y connecte.
  </Accordion>

  <Accordion title="Dois-je tester dans le simulateur du Project Editor ou sur un vrai téléphone ?">
    Utilisez les deux, selon les cas. Le **simulateur iOS** et l&#39;**émulateur Android** du Project Editor affichent la version native de votre application et couvrent la plupart des tests quotidiens : mise en page, navigation, composants natifs et styles propres à la plateforme. Passez à un vrai téléphone avec **Expo Go** pour tester les fonctionnalités qui dépendent du matériel réel, comme la caméra, le retour haptique, les notifications push ou la localisation GPS.
  </Accordion>
</AccordionGroup>
