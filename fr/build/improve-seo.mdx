Au terme de ce guide, votre app publiée sera mieux classée dans les moteurs de recherche — et le SEO Rating de l&#39;outil Publishing le reflétera.

Après chaque publication réussie, Replit lance un audit SEO et affiche un SEO Rating. Si la note peut encore progresser, un simple clic transmet les problèmes identifiés à Agent. Pour la plupart des créateurs, le processus se résume à ceci : **publier → consulter la note → demander à Agent d&#39;optimiser**.

Pour savoir comment la note est calculée (audit Lighthouse, signification de chaque note, types de déploiement pris en charge), consultez [SEO Rating](/fr/features/publishing/seo-rating).

<div id="optimize-with-seo-agent">
  ## Optimiser avec SEO Agent
</div>

[SEO Agent](/fr/features/publishing/seo-agent) réalise un audit SEO technique de votre app publiée et transforme chaque constat en correction applicable en un clic. Il se trouve dans le volet **Growth** du Project Editor et est accessible aux créateurs disposant d&#39;un plan payant. Suivez ces étapes pour analyser votre app et appliquer les corrections.

<Steps>
  <Step title="Publiez votre app pour débloquer Growth">
    SEO Agent fonctionne sur une app publiée. Tant que vous n&#39;avez pas publié, le volet **Growth** reste verrouillé et vous invite à sélectionner **Go to Publishing**. Publiez depuis le chat Agent ou l&#39;outil **Publishing**, puis revenez au volet Growth.

    <Frame caption="Avant la publication, le volet Growth est verrouillé et affiche une invitation Go to Publishing">
      <img src="/assets/mirror/01-growth-locked-b05c24711f10.png" alt="Le volet Growth affichant l'état verrouillé avec le titre Publish your app to unlock Growth tools et un bouton Go to Publishing" width="1657" height="947" data-path="images/deployments/seo-agent/01-growth-locked.png" />
    </Frame>
  </Step>

  <Step title="Lancez l'analyse avec Agent">
    Ouvrez le volet **Growth** et repérez la carte **SEO Rating**. Sélectionnez **Run scan with Agent** pour lancer un audit SEO technique de votre project. L&#39;analyse prend généralement quelques minutes.

    <Frame caption="Sélectionnez Run scan with Agent dans la carte SEO Rating pour lancer l'audit">
      <img src="/assets/mirror/02-run-scan-94a2b8918fe9.png" alt="Vue rapprochée de la carte SEO Rating avec un rectangle rouge mettant en évidence le bouton Run scan with Agent" width="1656" height="946" data-path="images/deployments/seo-agent/02-run-scan.png" />
    </Frame>
  </Step>

  <Step title="Fix with Agent ou Fix all with Agent">
    Une fois l&#39;analyse terminée, les problèmes apparaissent dans un tableau comportant les colonnes **Severity** (Low, Medium ou High) et **Status** (Unresolved), regroupés en catégories telles que **AI Readiness**, **Crawlability &amp; Discovery**, **Landing Page Rendering &amp; Metadata** et **Performance Proxies**. Développez un problème pour lire ce que SEO Agent a détecté.

    Appliquez les corrections au niveau de granularité de votre choix :

    * **Fix with Agent** sur un problème isolé confie uniquement cet élément à Agent.
    * **Fix with Agent** sur une catégorie corrige tous les problèmes de ce groupe.
    * **Fix all with Agent** envoie tous les problèmes à Agent en une seule fois. Le bouton **Fix all issues** du chat produit le même résultat.

    <Frame caption="Après l'analyse, corrigez les problèmes un par un, par catégorie ou tous à la fois avec Fix all with Agent">
      <img src="/assets/mirror/03-fix-with-agent-c5b9e642818e.png" alt="Le tableau des résultats d'analyse regroupés par catégorie avec les colonnes de gravité et de statut, un rectangle rouge mettant en évidence le bouton Fix all with Agent et les boutons Fix with Agent par catégorie" width="1657" height="947" data-path="images/deployments/seo-agent/03-fix-with-agent.png" />
    </Frame>
  </Step>

  <Step title="Agent traite les corrections">
    Agent crée une tâche de correction pour chaque problème et les traite en arrière-plan, ce qui vous permet de continuer à construire. Les lignes passent à **Fix in progress**, et un lien **Go to task** vous permet d&#39;ouvrir n&#39;importe quelle tâche pour en suivre l&#39;avancement.

    <Frame caption="Agent crée des tâches de correction ; les lignes des problèmes affichent Fix in progress avec un lien Go to task">
      <img src="/assets/mirror/04-fixes-in-progress-e05dd10c05b3.png" alt="Le tableau des résultats d'analyse avec des lignes de problèmes affichant désormais le statut Fix in progress et des liens Go to task pendant qu'Agent travaille" width="1657" height="947" data-path="images/deployments/seo-agent/04-fixes-in-progress.png" />
    </Frame>
  </Step>

  <Step title="Appliquez les modifications à la version principale">
    Lorsqu&#39;une correction est prête, la tâche affiche l&#39;état **Ready for review**. Examinez les modifications, puis sélectionnez le bouton vert **Apply changes to main version** pour fusionner la correction dans votre app. Republiez pour actualiser votre SEO Rating sur la base du nouveau build.

    <Frame caption="Examinez chaque correction et sélectionnez Apply changes to main version pour la fusionner">
      <img src="/assets/mirror/05-apply-changes-7d167b6bb93a.png" alt="Vue rapprochée du pied de page de la tâche Ready for review avec un rectangle rouge mettant en évidence le bouton vert Apply changes to main version" width="1656" height="946" data-path="images/deployments/seo-agent/05-apply-changes.png" />
    </Frame>
  </Step>
</Steps>

<Tip>
  Vous pouvez aussi vous passer complètement de l&#39;UI d&#39;analyse. Ouvrez Agent et
  demandez-lui d&#39;**« optimiser mon SEO »** : Agent récupérera vos derniers
  résultats et se mettra au travail.
</Tip>

Correctifs courants appliqués par Agent :

* Ajouter ou réécrire les balises `<title>` manquantes ou génériques afin que chaque page ait un titre unique et descriptif.
* Ajouter une méta-description à chaque page.
* Ajouter un texte `alt` descriptif aux images.
* Définir l&#39;attribut `lang` sur l&#39;élément `<html>`.
* S&#39;assurer que les liens ont un texte explicite (pas de « cliquez ici » ni d&#39;ancres vides).
* Ajouter un fichier `robots.txt` et un `sitemap.xml`.
* Ajouter une balise méta viewport pour le rendu mobile.
* Améliorer le contraste des couleurs sur les textes qui échouent aux contrôles d&#39;accessibilité.
* Ajouter des balises méta Open Graph et Twitter Card pour que les liens vers votre app s&#39;affichent correctement sur les réseaux sociaux.

<div id="best-practices-for-an-seo-optimized-app">
  ## Bonnes pratiques pour une application optimisée pour le SEO
</div>

Que vous demandiez à Agent de s&#39;en charger ou que vous les écriviez vous-même, voici les éléments les plus déterminants à soigner :

* **Attribuez à chaque page un titre et une méta-description uniques.** Visez des titres de moins de 60 caractères et des descriptions d&#39;environ 150 à 160 caractères.
* **Utilisez du HTML sémantique.** Encadrez votre mise en page avec `<main>`, `<header>`, `<nav>` et `<footer>`. N&#39;utilisez `<h1>` qu&#39;une seule fois par page et respectez l&#39;ordre des niveaux de titres.
* **Ajoutez un texte alternatif à chaque image.** Décrivez ce que montre l&#39;image, et pas seulement ce qu&#39;elle est.
* **Générez un `sitemap.xml` et un `robots.txt`.** Demandez à Agent de créer les deux afin que les moteurs de recherche sachent quoi explorer.
* **Ajoutez des balises Open Graph et Twitter card.** Maîtrisez l&#39;apparence de votre application lorsqu&#39;elle est partagée sur les réseaux sociaux.
* **Utilisez un domaine personnalisé.** Un domaine à votre image inspire confiance aux visiteurs comme aux moteurs de recherche. Consultez [Ajouter un domaine personnalisé](/fr/build/add-custom-domain).
* **Choisissez le bon type de déploiement.** Pour les sites riches en contenu, les [déploiements statiques](/fr/features/publishing/deployment-types#static) servent un HTML pré-rendu que les moteurs de recherche analysent instantanément.
* **Ajoutez des données structurées.** Le balisage JSON-LD aide les moteurs de recherche à afficher des résultats enrichis pour les produits, les articles, les FAQ et les événements.
* **Veillez à la rapidité de votre application.** Optimisez les images, évitez les scripts bloquant le rendu et appuyez-vous sur l&#39;hébergement de Replit pour maintenir des temps de réponse faibles.

Une manière simple d&#39;appliquer la plupart de ces conseils en une seule fois :

<AiPrompt>
  Audite mon site selon les bonnes pratiques SEO et applique les correctifs. Ajoute un sitemap,
  un robots.txt, des balises Open Graph, des données structurées là où c&#39;est pertinent, et
  assure-toi que chaque page a un titre et une méta-description uniques.
</AiPrompt>

<div id="need-further-help">
  ## Besoin d&#39;aide supplémentaire ?
</div>

* **La note n&#39;a pas été mise à jour après une nouvelle publication :** patientez une minute ou deux — l&#39;audit s&#39;exécute de façon asynchrone une fois le deployment en ligne, et le badge se met à jour dès que les résultats sont disponibles.
* **La note reste identique après les modifications d&#39;Agent :** demandez à Agent quels éléments Lighthouse précis il a corrigés, puis consultez l&#39;infobulle du badge pour voir ceux qui sont encore signalés.
* **Certaines pages ont une note plus basse que d&#39;autres :** le badge affiche la note la plus basse parmi toutes les URL explorées. Demandez à Agent de se concentrer sur la page précise signalée par Lighthouse.
* **Vous ne voyez pas de note sur une app publiée :** les SEO Ratings ne s&#39;exécutent que pour les types de déploiement web publics (Autoscale, Reserved VM, Static). Les deployments programmés et privés ne génèrent pas de note.
