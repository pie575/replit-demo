编写有效的提示词，关键在于向强大的助手提供清晰的指令。善用 [**Agent**](/zh/pt/core-concepts/agent)，即可快速将想法变为应用。

<div id="exemplos-rpidos">
  ## 快速示例
</div>

看看模糊的 提示词 与高效的 提示词 之间的区别：

<AccordionGroup>
  <Accordion title="修复代码" icon="bug">
    **模糊：**&quot;修复我的代码。&quot;

    **高效：**&quot;我的脚本在处理用户输入时失败了。错误似乎出在验证函数里。你能帮忙调试 `validate_input` 这部分吗？以下是错误信息：[详情]&quot;

    高效的 提示词 指明了问题所在的区域、可疑的函数，并提供了上下文。
  </Accordion>

  <Accordion title="开发功能" icon="hammer">
    **模糊：**&quot;做一个网站。&quot;

    **高效：**&quot;创建一个简单的作品集网站，包含首页、关于我和联系表单几个板块。使用现代、简洁的设计主题，并配上示例内容。&quot;

    高效的 提示词 定义了用途、核心功能和期望的视觉风格。
  </Accordion>

  <Accordion title="性能优化" icon="gauge-high">
    **模糊：**&quot;别让它变慢。&quot;

    **高效：**&quot;重构数据处理函数，让它更高效地处理更大的输入。我们能不能换一种算法或数据结构？&quot;

    告诉 Agent 该*如何*改进，而不是使用否定式的限制条件。
  </Accordion>

  <Accordion title="界面调整" icon="paintbrush">
    **模糊：**&quot;加个动画。&quot;

    **高效：**&quot;为首页的主图添加动画，让它在页面首次加载时以淡入效果平滑显现，营造出温馨的欢迎感。&quot;

    指明具体元素、期望的效果、时机以及想要达成的体验。
  </Accordion>

  <Accordion title="复杂系统" icon="server">
    **模糊：**&quot;构建 backend。&quot;

    **高效：**&quot;配置服务端逻辑。实现用户认证 (注册/登录) ，并创建一个 API 端点，用于安全地获取用户资料数据。&quot;

    将大任务拆解为具体的功能点。
  </Accordion>
</AccordionGroup>

<div id="planeje-primeiro">
  ### 先做规划
</div>

<Tip>在编写 提示词 之前，先梳理清楚应用的功能和用户流程。规划越清晰，提示词 就越有针对性。</Tip>

像产品经理那样思考应用的结构，把整体目标拆解成合乎逻辑的步骤。

**不要这样写：**&quot;创建一个任务管理应用。&quot;

**试试这样写：**&quot;1. 创建包含输入框和任务清单的基础 HTML 结构。2. 添加用于新增任务的 JavaScript。3. 使用数据库存储任务。4. 添加将任务标记为已完成的功能。&quot;

然后针对每个步骤，分别为 Agent 编写 提示词。

<div id="construa-incrementalmente">
  ### 循序渐进地构建
</div>

使用 [**checkpoint**](/zh/pt/core-concepts/agent#checkpoints) 在每个步骤成功完成后保存进度。如果出现问题，你可以回退到正常运行的状态，再换一种思路尝试。

**不要这样写：**“构建一个完整的电商平台。”

**试试这样写：**“为一个电商网站搭建基础的 full-stack 项目，并使用 Replit Auth 实现用户注册和登录。”随后再用后续 提示词 依次添加商品列表、购物车和结账功能。

<div id="seja-especfico">
  ### 描述要具体
</div>

明确说明你的需求：输出格式、限制条件、边缘情况。

**不要这样说：** “添加一个联系表单。”

**试试这样说：** “在 `/contact` 创建一个联系表单页面，包含以下字段：

* 姓名 (必填)
* 电子邮件 (必填，须为有效格式)
* 留言 (必填，至少 10 个字符)

提交后，将表单数据发送至 `contact@mydomain.com`。”

<div id="use-linguagem-positiva">
  ### 使用正面表述
</div>

说出你*想要*什么，而不是要避免什么。

**不要这样写：** “别把用户资料页做得乱七八糟。”

**试试这样写：** “创建一个简洁的用户资料页。突出显示用户名，其后依次是邮箱和注册日期。加入一个‘编辑资料’按钮。”

<div id="mantenha-a-simplicidade">
  ### 保持简洁
</div>

使用清晰、直接的语言。把复杂的需求拆成要点列出。

**不要这样写：** &quot;实现必要的服务器端基础设施，以支持用户生成内容制品的动态生成与检索。&quot;

**可以这样写：** &quot;在 backend 中实现一个功能，让用户可以提交博客文章。用户需要输入标题和正文内容，文章保存到数据库中。&quot;

<div id="trabalhando-com-contexto">
  ## 使用上下文
</div>

<div id="fornea-arquivos-relevantes">
  ### 提供相关文件
</div>

请指定具体文件，而不是附上整个项目。

**不要这样做：** (附上所有内容) “根据我们的设计系统实现用户个人资料页面。”

**可以这样做：**“创建用户个人资料页面。从服务器端点获取用户数据。根据 [设计文档 URL] 进行样式设计，并与此模型图保持一致：[附上 `profile_mockup.jpg`]。”

<Tip>切换到无关任务时，请开启新的对话。这样可以避免上下文不断累积而造成混乱。</Tip>

<div id="mostre-exemplos">
  ### 提供示例
</div>

提供具体示例 (如代码片段、示例数据或屏幕截图) ，以减少歧义。

**不要这样说：**“改进产品卡片的外观。”

**可以这样说：**“重新设计商店页面上的产品卡片。每张卡片应显示产品图片、名称、价格，以及一个‘加入购物车’按钮，布局类似这样：[附上屏幕截图]。使用浅灰色边框。”

<div id="depurao-eficaz">
  ## 高效调试
</div>

出现错误时，请提供：

* **完整准确的**错误信息
* 相关代码片段
* 报错所在的文件名
* 你当时想要实现的目标
* 你已经尝试过的排查步骤

**不要这样说：**&quot;我的登录页面坏了。&quot;

**试试这样说：&quot;**在 `/login` 页面用正确的凭据登录时，浏览器控制台报出 &#39;User not found&#39; 错误。数据库校验似乎没有生效。以下是 `auth.js` 中的登录处理代码。&quot;

<div id="pea-orientao">
  ## 寻求建议
</div>

<Tip>在动手构建之前，切换到 Plan 模式来探索不同方案。可以向 Agent 询问相关的库、实现思路以及各自的利弊权衡。</Tip>

**不要这样说：**“添加支付功能。”

**试试这样说：**“在 Replit 上构建的 Web 应用中，接受信用卡付款有哪些不错的方案？我需要相对容易集成的那种。”

<div id="itere-nos-seus-prompts">
  ## 反复打磨你的 提示词
</div>

第一个 提示词 不完美很正常。如果结果不理想，可以尝试：

* 补充更多细节
* 提供一个示例
* 简化指令
* 换一种表达方式

**初始版本：**“为我的网站创建一个页头。”

**优化版本：**“创建一个固定页头组件，左侧显示网站徽标，右侧是导航链接 (首页、关于、联系) 。”

<div id="resumo">
  ## 总结
</div>

高效编写 提示词 的关键在于：

* 在创建 提示词 前先**规划**
* 利用 Checkpoint **逐步构建**
* **明确说明**需求
* 通过示例和相关文件**提供上下文**
* 当结果不完全符合预期时**迭代调整**

掌握这些原则，你就能借助 Agent 更快地构建应用。
