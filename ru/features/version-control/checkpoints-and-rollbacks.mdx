С Replit вам не нужно беспокоиться о потере результатов работы.

Система checkpoint и отката в Replit обеспечивает полноценный контроль версий и управление состоянием всей среды разработки.

При работе с Replit Agent checkpoint автоматически фиксируют полное состояние проекта — не только изменения в коде, но и файлы проекта, контекст диалога с ИИ и подключённые базы данных.

<div id="what-are-checkpoints">
  ## Что такое checkpoints?
</div>

**Checkpoint** — это полный снимок состояния вашего Replit App, который Agent создаёт автоматически на ключевых этапах разработки. В отличие от традиционных систем контроля версий, отслеживающих только изменения в коде, checkpoints в Replit сохраняют весь контекст разработки.

Представляйте checkpoints как точки сохранения в видеоигре — вы всегда можете вернуться к работающей версии своего приложения.

  <img src="/assets/mirror/agent-checkpoint-8e5b8b315c02.png" alt="Интерфейс checkpoint в Agent с вариантами отката" width="1554" height="876" data-path="images/replitai/agent-checkpoint.png" />
</Frame>

<div id="complete-state-capture">
  ### Полный снимок состояния
</div>

Каждый checkpoint сохраняет:

* **Файлы проекта**: все файлы, каталоги, установленные packages и конфигурацию проекта
* **Контекст диалога с ИИ**: полную историю диалога и контекст, приведший к текущему состоянию
* **Конфигурацию окружения**: настройки среды выполнения и конфигурации публикации
* **Память Agent**: представление ИИ об архитектуре вашего проекта, ваших предпочтениях и подходах
* **Содержимое базы данных**: данные и схему базы данных на момент создания checkpoint

Благодаря такому комплексному подходу вы можете спокойно экспериментировать с изменениями: восстановить получится не только код, но и весь контекст разработки.

<div id="how-rollbacks-work">
  ## Как работают откаты
</div>

Функция **Откат** позволяет одним щелчком восстановить Replit App до состояния любого предыдущего checkpoint. Это гораздо мощнее традиционных операций Git revert.

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="Интерфейс отката checkpoint с доступными вариантами" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

Откаты безопасны и предсказуемы:

* **Предпросмотр без внесения изменений**: В некоторых интерфейсах можно выполнить предпросмотр состояния checkpoint перед откатом
* **Чёткие границы**: Каждый checkpoint представляет собой логически завершённый этап разработки
* **Непрерывность Conversation**: Контекст ИИ сохраняется, поэтому вы можете продолжить разработку с восстановленного состояния
* **Мгновенный эффект**: Откаты мгновенно применяются во всей среде разработки

<div id="rolling-back">
  ### Откат
</div>

При откате к предыдущему checkpoint проект возвращается к более раннему состоянию, включая:

1. **Полное состояние проекта**: Все файлы проекта возвращаются в состояние на момент выбранного checkpoint
2. **Контекст диалога с ИИ**: Диалоги с Agent восстанавливаются до момента checkpoint с сохранением непрерывности контекста
3. **Конфигурация проекта**: Зависимости, пакеты и конфигурации среды выполнения
4. **Среда разработки**: Конфигурации инструментов и настройки Project Editor
5. **Содержимое базы данных (необязательно)**: Если выбрать этот параметр, база данных будет восстановлена до состояния на момент создания checkpoint

<Info>
  По умолчанию откат не изменяет базу данных. Чтобы включить базу данных для разработки в откат, выберите «База данных» в разделе «Дополнительные параметры отката».

  Обратите внимание: восстановление **[продакшен-базы данных](/ru/features/data-and-storage/development-and-production)** не выполняется автоматически с помощью функции отката.
  Чтобы узнать, как восстановить продакшен-базу данных до более раннего момента времени, ознакомьтесь с [документацией по восстановлению на определённый момент времени](/ru/features/data-and-storage/development-and-production).
</Info>

<Warning>
  При использовании функции отката Replit App восстанавливается до предыдущего состояния. При этом удаляются все изменения, внесённые после этого момента, включая изменения кода. Если вы выберете восстановление базы данных, изменения в ней также будут отменены.
</Warning>

<div id="rolling-forward">
  ### Переход вперёд
</div>

Checkpoint-ы в Replit работают в обе стороны — по истории проекта можно перемещаться как назад, так и вперёд.
Это даёт полную свободу навигации по таймлайну разработки без риска потерять работу.

Если вы откатились слишком далеко или хотите вернуть изменения из более позднего checkpoint, вы можете **перейти вперёд** по истории checkpoint-ов. Это позволяет свободно перемещаться по таймлайну проекта, не теряя наработки.

Чтобы перейти вперёд, откройте историю на вкладке Agent, нажав иконку истории <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="иконка истории" width="24" height="24" data-path="images/icons/history.svg" />, и выберите checkpoint, следующий за вашей текущей позицией.

<Info>
  Переход вперёд возможен, только если в таймлайне есть checkpoint-ы после вашей текущей позиции. Как только вы внесёте новые изменения после отката, эти будущие checkpoint-ы станут частью альтернативной ветки истории.
</Info>

Такая двусторонняя навигация даёт вам полный контроль над таймлайном проекта и гарантирует, что вашу работу всегда можно восстановить.

<div id="checkpoint-creation">
  ## Создание checkpoint
</div>

Checkpoint создаются автоматически ИИ-инструментами Replit в ключевые моменты разработки.

<div id="agent-checkpoints">
  ### Checkpoint&#39;ы Agent
</div>

[Replit Agent](/ru/features/agent/overview) создаёт checkpoint&#39;ы в следующих случаях:

* **Завершение функции**: после успешной реализации запрошенной функции или возможности
* **Ключевые этапы**: при достижении существенного прогресса в сложных task&#39;ах
* **Стабильные состояния**: после тестирования и проверки внесённых изменений
* **Восстановление после ошибок**: перед попыткой исправить критические проблемы

<div id="checkpoint-characteristics">
  ### Характеристики checkpoint
</div>

Каждый checkpoint включает:

* **Описания, созданные ИИ**: понятные и наглядные сводки о том, что было сделано
* **Отметка времени**: точное время создания — так проще найти нужный checkpoint
* **Область изменений**: перечень изменённых файлов, функций или систем
* **Информация о биллинге**: для Agent — прозрачный учёт стоимости каждого checkpoint

<div id="using-checkpoints-and-rollbacks">
  ## Использование checkpoint и откатов
</div>

<div id="finding-checkpoints">
  ### Поиск checkpoint&#39;ов
</div>

Checkpoint&#39;ы отображаются в нескольких местах Project Editor:

**Вкладка Agent**: просмотр всех checkpoint&#39;ов, созданных Agent, с описаниями и возможностью отката
**Git pane**: checkpoint&#39;ы показаны как коммиты Git с полной интеграцией с системой контроля версий
**Просмотр истории**: в чате с Agent нажмите иконку истории <img class="icon-svg" src="/assets/mirror/history-51e5b63ccff4.svg" alt="иконка истории" width="24" height="24" data-path="images/icons/history.svg" />, чтобы открыть полный таймлайн всех checkpoint&#39;ов и их последовательности

<div id="performing-rollbacks">
  ### Выполнение отката
</div>

Процесс отката немного различается в зависимости от того, откуда вы его запускаете:

<div id="from-agent-tab">
  #### Из вкладки Agent
</div>

<Steps>
  <Step title="Перейдите к Agent">
    Откройте вкладку **Agent** в Project Editor, чтобы увидеть все checkpoint, созданные Agent.
  </Step>

  <Step title="Выберите checkpoint">
    Найдите checkpoint, к которому хотите вернуться, и выберите **Откат к этому состоянию**.
  </Step>

  <Step title="Подтвердите откат">
    Прочитайте предупреждение об откате и подтвердите восстановление приложения до выбранного состояния.
  </Step>

  <Step title="Проверьте восстановление">
    Убедитесь, что файлы проекта, база данных и контекст ИИ соответствуют состоянию восстановленного checkpoint.
  </Step>
</Steps>

<div id="best-practices">
  ### Рекомендации
</div>

**Используйте checkpoint&#39;ы осознанно**:

* Тестируйте приложение после каждого крупного checkpoint&#39;а, чтобы убедиться в его стабильности
* Помимо автоматических checkpoint&#39;ов, создавайте вручную коммиты Git — они пригодятся для долгосрочного отслеживания версий
* Просматривайте описания checkpoint&#39;ов, чтобы понимать, что именно изменилось

**Что учитывать при откате**:

* Всегда проверяйте объём изменений перед откатом
* Оценивайте влияние на базу данных и внешние интеграции
* Сообщайте об откатах соавторам, чтобы команда была в курсе

**Итеративная разработка**:

* Разрабатывайте небольшими шагами — так вы получите больше пользы от частых checkpoint&#39;ов
* Используйте откаты, чтобы безопасно пробовать разные подходы к реализации
* Пользуйтесь сохранением контекста ИИ, чтобы продолжать диалог после откатов

<div id="integration-with-version-control">
  ## Интеграция с системой контроля версий
</div>

Checkpoint&#39;ы органично вписываются в общую экосистему контроля версий Replit:

<div id="git-integration">
  ### Интеграция с Git
</div>

* **Создание коммитов Git**: для каждого checkpoint создаётся соответствующий коммит Git
* **Совместимость с ветками**: checkpoint учитывают структуру веток и процессы слияния
* **Синхронизация с удалённым репозиторием**: интеграция с GitHub поддерживает синхронизацию checkpoint
* **Доступ из командной строки**: все возможности Git по-прежнему доступны наряду с checkpoint

<div id="collaboration-features">
  ### Возможности совместной работы
</div>

* **Видимость для команды**: checkpoint&#39;ы видны всем участникам проекта
* **Предотвращение конфликтов слияния**: моменты создания checkpoint&#39;ов подобраны так, чтобы снизить вероятность конфликтов
* **Общий контекст**: контекст диалога с ИИ помогает участникам команды разобраться в изменениях
* **Обновления в реальном времени**: участники сразу видят, что создан новый checkpoint

<div id="advanced-features">
  ## Расширенные возможности
</div>

<div id="checkpoint-previews">
  ### Предпросмотр для checkpoint
</div>

Некоторые интерфейсы поддерживают функцию предпросмотра для checkpoint:

* **Визуальное сравнение**: посмотрите, как выглядело приложение в разных состояниях checkpoint
* **Безопасный просмотр**: используйте предпросмотр без фактического отката
* **Отслеживание прогресса**: проследите, как приложение менялось со временем
* **Сравнение итераций**: сравните разные подходы к реализации

<div id="cross-session-rollbacks">
  ### Откаты между сессиями
</div>

Для опытных разработчиков и администраторов команд:

* **Расширенная история**: Доступ к checkpoint из нескольких сеансов разработки
* **Административный контроль**: Администраторы команд могут выполнять откаты между сеансами пользователей
* **Журналы аудита**: Полная история создания checkpoint и операций отката

* Выявляйте проблемы, сравнивая состояния checkpoint
* Восстанавливайте целостность базы данных после повреждения данных
* Восстанавливайте случайно удалённые или изменённые данные

* Углубляйте понимание, изучая, как развивались функции
* Отрабатывайте новые приёмы, зная, что всегда можно сделать откат
