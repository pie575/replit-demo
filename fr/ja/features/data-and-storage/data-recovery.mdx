---
title: "Récupération des données"
description: "Découvrez comment restaurer une base de données de développement à un point de contrôle ou ramener une base de données de production à un instant précis."
---

Les erreurs arrivent : une modification de schéma qui tourne mal, des lignes supprimées ou une session Agent qui prend une direction inattendue. Replit propose une méthode de restauration adaptée à chaque base de données.

| Base de données | Méthode de restauration                                    | Plans disponibles                                                                                           |
| --------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Développement   | Retour à un point de contrôle                              | Tous les plans                                                                                              |
| Production      | Restauration à un instant précis et sauvegardes planifiées | Core : jusqu&#39;à 7 jours d&#39;historique. Pro et Enterprise : jusqu&#39;à 28 jours (7 jours par défaut). |

<div id="section">
  ## Restaurer la base de données de développement
</div>

Grâce à la [fonctionnalité de rollback](/fr/ja/features/version-control/checkpoints-and-rollbacks/), vous pouvez ramener votre app et votre base de données de développement à un état antérieur. La base de données est alors restaurée dans l&#39;état correspondant à n&#39;importe quel checkpoint créé par Agent.

<Frame>
  <img src="/assets/mirror/checkpoint-rollback-476fde84864b.png" alt="Interface de rollback d'un checkpoint affichant les options de restauration" width="3154" height="2366" data-path="images/replitai/checkpoint-rollback.png" />
</Frame>

<Info>
  Lorsque vous restaurez l&#39;état d&#39;un checkpoint, veillez à toujours sélectionner « Database » sous « Additional rollback options ». La base de données est ainsi restaurée dans l&#39;état où elle se trouvait au moment de la création du checkpoint.
</Info>

<div id="section-2">
  ## Restaurer une base de données de production
</div>

Pour les bases de données de production, la restauration à un instant précis vous permet de revenir à un instant précis.

<Frame>
  <img src="/assets/mirror/database-rollbacks-f13dd20874ae.jpg" alt="Interface de restauration de base de données affichant les options de retour en arrière" width="1082" height="708" data-path="images/databases/database-rollbacks.jpg" />
</Frame>

La période sur laquelle vous pouvez remonter dépend de votre plan et de vos paramètres de conservation. Core conserve jusqu&#39;à 7 jours d&#39;historique, tandis que Pro et Enterprise en conservent jusqu&#39;à 28 jours. Tous les plans démarrent à 7 jours, et vous pouvez modifier cette durée dans les paramètres de votre base de données de production. Allonger la durée de conservation augmente l&#39;utilisation du stockage, et donc vos frais d&#39;utilisation. Si vous passez de Pro à Core, la durée de conservation est ramenée à 7 jours.

<Warning>
  Restaurer une base de données ne restaure pas le code de votre application, et effectuer un rollback de votre application ne restaure pas la base de données. Pour ramener les deux au même instant, restaurez la base de données, puis [effectuez un rollback vers le checkpoint correspondant](/fr/ja/features/version-control/checkpoints-and-rollbacks/) avant de republier votre application.
</Warning>

<div id="section-3">
  ## Planifier les sauvegardes de la base de données de production
</div>

Les sauvegardes planifiées créent un point de restauration complet par jour. Lorsque vous activez ou modifiez une planification, Replit programme la sauvegarde aux alentours de minuit, dans le fuseau horaire actuel de votre navigateur.

1. Ouvrez l&#39;outil **Database**, puis sélectionnez votre base de données de production.
2. Ouvrez **Settings**, puis développez **Scheduled backups** sous **Advanced**.
3. Pour activer les sauvegardes planifiées, choisissez une durée de conservation sous **Keep backups for**.

Les durées de conservation disponibles varient selon le plan : Core prend en charge jusqu&#39;à 7 jours, tandis que Pro et Enterprise vont jusqu&#39;à 28 jours.

<div id="section-4">
  ### Coûts de stockage
</div>

Replit mesure l&#39;utilisation séparément pour chaque catégorie de stockage des bases de données de production :

| Catégorie de stockage                             | Tarif mensuel par Gio |
| ------------------------------------------------- | --------------------: |
| Stockage logique de la base de données            |                 $0,35 |
| Stockage de la restauration à un instant précis (PITR) |                 $0,20 |
| Stockage des sauvegardes planifiées               |                 $0,09 |

<Note>Les coûts de stockage des bases de données bénéficient actuellement d&#39;une remise de 100 %.</Note>

Le tarif de stockage logique de $0,35 s&#39;applique dès lors que vous utilisez la PITR, les sauvegardes planifiées ou les deux. Le stockage des sauvegardes planifiées coûte moins cher par Gio que le stockage PITR. Si des points de restauration quotidiens vous suffisent, vous pouvez réduire vos coûts de stockage de restauration en raccourcissant la fenêtre PITR et en vous appuyant sur les sauvegardes planifiées. Le coût total des sauvegardes dépend du volume de sauvegardes conservées et de leur durée de conservation.

La PITR offre davantage de points de restauration au sein de sa fenêtre, tandis que les sauvegardes planifiées n&#39;en fournissent qu&#39;un par jour : choisissez la méthode de restauration adaptée à vos besoins.

<Note>
  Les planifications utilisent le décalage UTC en vigueur. Lors du passage à l&#39;heure d&#39;été, l&#39;heure des sauvegardes peut être décalée d&#39;une heure tant que vous n&#39;avez pas mis la planification à jour. Pour les fuseaux horaires à décalage fractionnaire, l&#39;heure la plus proche est utilisée.
</Note>

<div id="section-5">
  ### Restaurer une sauvegarde planifiée
</div>

1. Dans les paramètres de votre base de données de production, ouvrez **Scheduled backups**.
2. Sélectionnez **View all backups**.
3. Sélectionnez **Restore** en regard du point de restauration souhaité.
4. Saisissez `restore`, puis sélectionnez **Continue**.

Une fois la restauration lancée, la base de données bascule sur les données de la sauvegarde sélectionnée. Les données actuelles ne sont pas supprimées, mais les services connectés peuvent devoir se reconnecter temporairement.

<div id="section-6">
  ## Résoudre les échecs de publication
</div>

Si la publication échoue en raison d&#39;un problème de base de données :

1. **Consultez les journaux de publication** pour repérer les messages d&#39;erreur précis concernant la connexion à la base de données ou les conflits de schéma
2. **Vérifiez les modifications de schéma récentes** afin d&#39;identifier d&#39;éventuels conflits avec le code applicatif existant
3. **Testez vos modifications dans l&#39;aperçu du déploiement** avant de tenter une nouvelle publication
