title: "Reprise après sinistre Git"

---

Replit sauvegarde automatiquement vos dépôts Git afin que vous puissiez récupérer vos données en cas de problème, par exemple une corruption du dossier `.git` ou une perte de l&#39;historique des commits. Ce système de sauvegarde fonctionne en arrière-plan : votre travail est donc protégé sans aucune manipulation particulière de votre part.

<div id="section">
  ## Fonctionnement
</div>

Chaque Replit App conserve une sauvegarde sécurisée de son dépôt Git. Lorsque Replit Agent modifie votre code ou que vous déployez votre application, les modifications sont automatiquement synchronisées avec cette sauvegarde. Si votre dépôt Git local est corrompu ou devient inutilisable, vous pouvez restaurer l&#39;intégralité de l&#39;historique des commits à partir de la sauvegarde.

<Info>
  Le dépôt distant de sauvegarde s&#39;appelle `gitsafe-backup` et Replit le gère automatiquement. Vous n&#39;avez rien à configurer : il fonctionne déjà en arrière-plan.
</Info>

<div id="section-2">
  ## Afficher l&#39;historique des sauvegardes
</div>

Le moyen le plus simple de consulter l&#39;historique des commits est d&#39;utiliser le [volet Git](/fr/ja/features/workspace-tools/git-interface). En l&#39;ouvrant depuis la section Tools de l&#39;éditeur de projet, vous accédez à l&#39;historique complet des commits, y compris tous les points de contrôle d&#39;Agent. Cette méthode convient dans la plupart des cas et ne nécessite aucune commande.

Si vous devez consulter directement le dépôt distant gitsafe-backup, vous pouvez utiliser le Shell :

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

L&#39;historique complet des commits s&#39;affiche alors, y compris tous les points de contrôle Agent et les commits manuels. Vous pouvez ainsi vérifier que votre travail est bien sauvegardé ou retrouver un commit précis à restaurer.

<div id="git">
  ## Récupérer après un problème Git
</div>

En cas d&#39;erreur Git ou de dépôt corrompu, commencez par essayer le [volet Git](/fr/ja/features/workspace-tools/git-interface). Il permet de résoudre la plupart des problèmes courants sans passer par des commandes Shell, comme réinitialiser vers un commit antérieur ou récupérer les modifications depuis le dépôt distant.

Si le volet Git ne suffit pas (par exemple lorsque le dossier `.git` est entièrement corrompu), suivez les procédures basées sur le Shell ci-dessous.

<div id="section-3">
  ### Vérifier qu&#39;une sauvegarde est disponible
</div>

Commencez par vérifier l&#39;existence d&#39;un dépôt distant de sauvegarde :

```bash theme={null}
git remote -v
```

Si `gitsafe-backup` apparaît dans la sortie, vous pouvez procéder à la récupération.

<div id="section-4">
  ### Restaurer le dépôt
</div>

<Warning>
  Ce processus remplace le dossier `.git` actuel par la version sauvegardée. Vos fichiers de travail restent inchangés, mais l&#39;historique Git local est remplacé par celui de la sauvegarde.
</Warning>

<Steps>
  <Step title="Enregistrer la configuration Git actuelle">
    Sauvegardez le fichier de configuration Git, au cas où vous auriez des réglages personnalisés :

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="Cloner le dépôt de sauvegarde">
    Créez un clone temporaire à partir de la sauvegarde :

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="Remplacer le dossier Git">
    Déplacez le dossier `.git` corrompu ailleurs, puis remplacez-le par la sauvegarde :

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="Restaurer la configuration">
    Recopiez la configuration Git :

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

Une fois ces étapes terminées, exécutez `git status` pour vérifier que le dépôt fonctionne correctement.

<div id="section-5">
  ## Résolution des problèmes courants
</div>

<div id="fatal-repository-not-found">
  ### « fatal: repository not found » ou dépôt distant de sauvegarde introuvable
</div>

Il est possible que le système de sauvegarde ne soit pas activé sur les anciens projets. Si vous avez besoin d&#39;aide pour récupérer un ancien projet, contactez le support.

<div id="section-6">
  ### Les commits récents ne sont pas inclus dans la restauration
</div>

Les sauvegardes sont synchronisées à chaque commit d&#39;Agent. Si vous avez effectué des modifications sans les commiter, elles ne figurent pas dans la sauvegarde. Vérifiez votre répertoire de travail pour repérer les fichiers non commités.

<div id="git-2">
  ### Les opérations Git sont lentes ou ne répondent plus
</div>

Si les opérations Git ne répondent plus, un fichier de verrouillage obsolète subsiste peut-être. Vous pouvez le supprimer sans risque :

```bash theme={null}
rm -f .git/index.lock
```

<div id="section-7">
  ## Prévenir la perte de données
</div>

Le système de sauvegarde protège automatiquement l&#39;historique Git, mais vous pouvez prendre des mesures supplémentaires pour mieux protéger votre travail :

* **Committez souvent** : réalisez des commits petits et fréquents pour que votre progression soit sauvegardée en continu
* **Tirez parti des points de contrôle** : lorsque vous travaillez avec [Replit Agent](/fr/ja/features/agent/overview), les points de contrôle créent automatiquement des commits aux étapes clés
* **Connectez-vous à GitHub** : pour les projets importants, [connectez votre app à GitHub](/fr/ja/build/import-from-providers) afin de disposer d&#39;une couche de sauvegarde supplémentaire
