作为 Enterprise 管理员，您可以配置组织范围的设置，控制团队成员使用代码、部署和外部平台的方式。这些设置有助于维持安全标准、保护知识产权，并确保符合企业政策。

<div id="acessando-as-configuraes-de-privacidade">
  ## 访问隐私设置
</div>

<Accordion title="如何访问隐私设置">
  1. 进入你的 Enterprise workspace
  2. 选择 **设置**
  3. 选择 **高级**，查看所有可用设置
</Accordion>

<div id="configuraes-de-privacidade">
  ## 隐私设置
</div>

隐私设置用于控制组织内 App 的部署和访问方式。

<CardGroup cols={2}>
  <Card title="私有部署" icon="lock">
    要求所有新 App 均以私有方式部署，仅允许已通过身份验证的团队成员访问
  </Card>

  <Card title="密码保护的部署" icon="key">
    允许团队成员为自己的已部署 App 添加密码保护
  </Card>

  <Card title="私有开发 URL" icon="shield-halved">
    要求所有 App 开发 URL 都经过身份验证，并为启用 SAML 的组织提供 SSO
  </Card>
</CardGroup>

<div id="deployments-privados">
  ### 私有部署
</div>

启用后，所有新 App 都必须以私有方式部署。私有 App 仅限组织内已通过身份验证的成员访问。

**何时使用此设置：**

* 组织需要处理敏感数据或专有应用
* 你需要确保 App 不会被意外公开
* 合规要求规定必须限制对已部署应用的访问

<Note>
  此设置仅适用于新部署的 App。现有的已部署 App 将保留其当前的可见性设置。
</Note>

<div id="deployments-protegidos-por-senha">
  ### 密码保护的部署
</div>

控制团队成员是否可以创建受密码保护的部署。启用后，开发者可以为已部署 App 设置访问密码，增加一层额外的安全防护。

**何时使用此设置：**

* 你希望与外部相关方共享 App，但又不想完全公开
* 团队需要在正式发布前向客户演示应用
* 你需要在组织成员身份之外实现更精细的访问控制

<div id="exigir-urls-de-desenvolvimento-privadas">
  ### 要求使用私有开发 URL
</div>

启用后，所有 App 的开发 URL 均需进行身份验证。如果您的组织启用了 SAML，开发 URL 则需要通过 SSO 进行身份验证。

**何时使用此设置：**

* 您需要防止他人未经授权访问正在开发的应用
* 安全策略要求保护所有开发环境
* 您希望确保只有已通过身份验证的团队成员才能查看开发预览

<Warning>
  此设置会追溯应用于您组织中的所有现有 App。
</Warning>

<div id="proibir-exportao-de-cdigo-fonte">
  ### 禁止导出源代码
</div>

启用后，团队成员无法将应用的源代码导出为 zip 文件，从而防止代码被下载并分享到 Replit 平台之外。

**适用场景：**

* 你需要严格控制源代码的存放位置
* 安全策略禁止在本地保存代码副本
* 你希望确保所有开发工作都在受管环境中进行

<div id="configuraes-de-segurana">
  ## 安全设置
</div>

安全设置可帮助你强制执行漏洞检查等防护措施。

<div id="exigir-verificao-de-segurana">
  ### 要求安全扫描
</div>

设置所有 App 在部署前是否必须通过安全扫描。安全扫描会检测代码中的漏洞、泄露的密钥以及其他安全问题。

可用选项：

| 设置      | 说明                   |
| ------- | -------------------- |
| **已停用** | 安全扫描为可选项             |
| **要求**  | 所有 App 在部署前都必须通过安全扫描 |

**何时使用此设置：**

* 需要满足安全合规要求
* 你希望避免意外泄露 API 密钥或其他密钥
* 你需要确保所有已部署 App 遵循一致的安全标准

<Note>
  此设置不适用于在启用之前已部署的 App。
</Note>

<div id="configuraes-de-controle-de-cdigo-fonte">
  ## 源代码管理设置
</div>

源代码管理设置可帮助你强制执行版本控制规范，并保护组织的代码仓库。

<div id="exigir-repositrio-git-remoto">
  ### 要求使用远程 Git 仓库
</div>

启用后，所有 App 必须先将本地更改推送到远程 Git 仓库，才能进行部署。这可确保所有代码更改都在贵组织的版本控制系统中得到跟踪。

**何时使用此设置：**

* 所有代码都必须备份到 Git
* 您需要所有代码更改的审计记录
* 工作流程要求在部署前进行代码审查

<Note>
  此设置不适用于在启用该设置之前已部署的 App。
</Note>

<div id="repositrios-privados">
  ### 私有仓库
</div>

控制团队成员能否使用公共 Git 仓库。设置为要求使用私有仓库后,团队成员只能推送到 GitHub 等平台上的私有仓库。

可用选项:

| 设置          | 说明                      |
| ----------- | ----------------------- |
| **关闭**      | 团队成员可以使用公共或私有仓库         |
| **对非管理员强制** | 非管理员团队成员必须使用私有仓库        |
| **对所有人强制**  | 包括管理员在内的所有团队成员都必须使用私有仓库 |

**何时使用此设置:**

* 禁止使用公共代码仓库
* 你需要确保专有代码不会被意外推送到公共仓库
* 合规要求规定必须使用私有版本控制

<div id="melhores-prticas">
  ## 最佳实践
</div>

<AccordionGroup>
  <Accordion title="默认设为私有" icon="shield">
    启用**私有部署**，确保所有新部署的 App 默认为私有。这有助于避免敏感应用被意外暴露。
  </Accordion>

  <Accordion title="强制执行安全扫描" icon="magnifying-glass">
    设置**要求安全扫描**，在 App 进入生产环境之前发现漏洞。这有助于在整个组织中保持一致的安全标准。
  </Accordion>

  <Accordion title="保护开发环境" icon="code">
    启用**要求使用私有开发 URL**，确保即使是进行中的工作也受到保护。对于处理敏感数据的组织而言，这一点尤为重要。
  </Accordion>

  <Accordion title="控制源代码访问" icon="code-branch">
    将**禁止导出源代码**与**私有仓库**要求结合使用，全面掌控代码的存放位置与访问权限。
  </Accordion>
</AccordionGroup>
