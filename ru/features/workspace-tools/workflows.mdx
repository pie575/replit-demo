<div id="available-task-types">
  ## Доступные типы задач
</div>

Сейчас доступны 3 типа задач: `Execute Shell Command`, `Install Packages` и `Run Workflow`.

<div id="execute-shell-command">
  ### Выполнение команды Shell
</div>

`Execute Shell Command` сохраняет команду оболочки и выполняет её в той же среде, что и панель Shell. Этот тип задачи подходит для самых разных сценариев, включая запуск отдельных файлов:

```text theme={null}
python main.py
```

к выполнению сложных команд запросов к базе данных:

```text theme={null}
psql -h 0.0.0.0 -U your_username -d your_database -c "SELECT * FROM your_table;"
```

<div id="install-packages">
  ### Установка пакетов
</div>

`Install Packages` использует встроенную систему управления зависимостями Replit: она автоматически определяет зависимости проекта и устанавливает необходимые пакеты. Подробнее о том, как UPM определяет, какие пакеты нужно установить для проекта, см. в разделе [Управление зависимостями](/ru/features/project-setup/dependency-management#the-universal-package-manager).

<div id="run-workflow">
  ### Запуск Workflow
</div>

`Run Workflow` позволяет запускать другой workflow из текущего. Это позволяет повторно использовать и комбинировать workflow для создания более сложных процессов.

Пример использования:

<Frame>
  <img src="/assets/mirror/example-run-workflow-62f93cd1bf00.webp" alt="изображение" width="720" height="678" data-path="images/workflows/example-run-workflow.webp" />
</Frame>

Используя этот тип задачи для создания зависимостей между workflow, вы можете редактировать один workflow, и другие workflow, ссылающиеся на него, будут автоматически использовать последние изменения. Обратите внимание: для глубоко вложенных вызовов workflow установлено ограничение глубины.

<div id="workflow-execution-mode">
  ## Режим выполнения Workflow
</div>

В Workflow доступны два режима выполнения: последовательный и параллельный.

<div id="sequential">
  ### Последовательный
</div>

В последовательном режиме задачи выполняются в заданном порядке: следующая задача запускается только после завершения предыдущей. Если задача в рабочем процессе завершается с ошибкой, выполнение последовательности прекращается.

Этот режим можно использовать, например, для определения логически связанных команд — таких как команды Git для получения последних изменений из основной ветки и последующего перебазирования текущей ветки на основную:

<Frame>
  <img src="/assets/mirror/example-sequential-workflow-62ae8a64038f.png" alt="изображение" width="721" height="654" data-path="images/workflows/example-sequential-workflow.png" />
</Frame>

<div id="parallel">
  ### Параллельный
</div>

В режиме параллельного выполнения каждая задача запускается и выполняется независимо от других задач в workflow. Сбой одной задачи не останавливает выполнение остальных.

Этот режим, например, используется для запуска fullstack-проекта, в котором нужно запустить и фронтенд, и бэкенд-сервер:

<div id="creating-workflows">
  ## Создание Workflows
</div>

Workflows можно создавать на панели workflows, нажав кнопку `+ New Workflow`. Сначала задайте workflow понятное название, выберите подходящий режим выполнения и добавьте задачи. Порядок задач можно изменять, перетаскивая их в нужное место.

<div id="assign-workflow-to-run-button">
  ## Назначение Workflow кнопке Run
</div>

Workflow также можно назначить кнопке Run, чтобы заменить её стандартное поведение (см. [Настройка Replit App](/ru/features/project-setup/configuration)). Чтобы сохранить стандартную команду запуска, настроенную в `.replit`, выберите в раскрывающемся списке вариант по умолчанию «Run Replit App».

При нажатии кнопки Run будет запускаться Workflow, выбранный в раскрывающемся меню рядом с ней. Чтобы изменить Workflow, запускаемый кнопкой Run, выберите нужный Workflow в этом меню.
