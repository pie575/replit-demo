Replit App 通过两个文件进行配置：`.replit` 和 `replit.nix`。它们决定了 Replit App 的行为方式，从代码运行到开发工具和语言均受其影响。

这些配置文件默认处于隐藏状态。在文件树菜单中选择“Show hidden files”，即可在 Replit App 中显示它们。

<div id="arquivo-replitnix">
  ## `replit.nix` 文件
</div>

Replit 使用 `Nix` 管理包和环境。`replit.nix` 文件的用途包括：

**指定系统依赖：** 明确定义 Replit App 所需的包，这些包由包管理器 Nix 统一管理。

**创建可复现的环境：** 确保开发环境一致且可复现，非常适合协作项目以及跨多个系统的测试。

你也可以通过 `Dependencies` 工具以可视化方式管理 Nix 包。详情请参阅[系统依赖](/zh/pt/features/project-setup/dependency-management#system-dependencies)指南。

若要通过 `replit.nix` 文件配置包，可在 `deps` 数组中列出 [Nix 包](https://search.nixos.org/packages)，并为其添加 `pkgs.` 前缀。所有更改会在 shell 重新加载后同步生效。

```nix theme={null}
{ pkgs }: {
  deps = [
    pkgs.nodejs-19_x
    pkgs.nodePackages.typescript-language-server
    pkgs.yarn
    pkgs.replitPackages.jest
  ];
}
```

<div id="arquivo-replit">
  ## `.replit` 文件
</div>

`.replit` 文件控制 Replit App 的行为，采用 `toml` [配置格式](https://toml.io/en/)。以下是一些可配置的主要方面：

**运行命令 (Run) ：** 指定点击 Run 按钮时执行的命令。每个模板都自带默认的运行命令，让代码可以立即运行。对于更复杂、需要自定义的应用，请使用 [Workflows](/zh/pt/features/workspace-tools/workflows)。

**Language Server Protocol (LSP)**：提供自动补全、代码导航、语法高亮以及实时 linting 和错误提示等功能。

**环境变量：** 定义并管理应用正常运行所必需的环境变量。

**依赖与包：** 直接通过 `.replit` 文件管理包的安装与配置，确保 Replit App 启动时就具备所有必需的工具。你也可以使用 `Dependencies` 工具以可视化方式管理依赖。详见[系统模块](/zh/pt/features/project-setup/dependency-management#advanced-configuration)指南。

对于 Python 应用，默认的 `.replit` 文件如下所示：

```toml theme={null}
entrypoint = "main.py"
modules = ["python-3.10:v18-20230807-322e88b"]

[nix]
channel = "stable-23_05"

[unitTest]
language = "python3"

[gitHubImport]
requiredFiles = [".replit", "replit.nix"]

[deployment]
run = ["python3", "main.py"]
deploymentTarget = "cloudrun"
```

下表概述了 `.replit` 文件中的各项配置，说明每项配置的作用及其对 Replit App 环境的影响。

| **配置键**                                         | **值/示例**                               | **说明**                                                                                       |
| ----------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------- |
| <a name="entrypoint" />`entrypoint`             | `main.py`                              | 指定打开编辑器时默认运行并显示的主文件。你可以根据自己的应用重命名该文件。                                                        |
| <a name="modules" />`modules`                   | `["python-3.10:v18-20230807-322e88b"]` | 定义 Replit 支持的编程语言或其他重要依赖项的特定版本。                                                              |
| <a name="nix" />`[nix]`                         |                                        | 指定使用包管理器 Nix 管理系统依赖项的相关配置。更多信息请参阅[依赖管理](/zh/pt/features/project-setup/dependency-management)文档。 |
| <a name="channel" />`channel`                   | `stable-23_05`                         | 指明要使用的 Nix 频道，它会影响可用的系统依赖项版本。                                                                |
| <a name="packages" />`packages`                 | `["cowsay", "htop"]`                   | 指定要安装的若干 Nix 包。如需更精细的控制，你也可以使用 `replit.nix`。                                                 |
| <a name="unitTest" />`[unitTest]`               |                                        | 配置 Replit App 中与单元测试相关的设置。                                                                   |
| <a name="language" />`language`                 | `python3`                              | 指定用于单元测试的语言，此处表示使用 Python 3 编写测试。                                                            |
| <a name="gitHubImport" />`[gitHubImport]`       |                                        | 影响从 GitHub 导入项目方式的配置，具体指必须包含哪些文件。                                                            |
| <a name="requiredFiles" />`requiredFiles`       | `[".replit", "replit.nix"]`            | 列出导入项目时必须存在的文件，以确保项目能够正常运行。                                                                  |
| <a name="deployment" />`[deployment]`           |                                        | 包含将 Replit App 应用发布到线上环境的配置。                                                                 |
| <a name="run" />`run`                           | `["python3", "main.py"]`               | 部署时用于启动应用的命令。                                                                                |
| <a name="deploymentTarget" />`deploymentTarget` | `cloudrun`                             | 指定托管该应用的部署目标平台。                                                                              |

现在你已经大致了解 `.replit` 文件的默认配置，接下来可以通过以下章节了解如何为你的 Replit App 配置基础和高级设置。

<div id="configurando-ajustes-bsicos">
  ## 配置基本设置
</div>

<div id="entrypoint">
  ### Entrypoint
</div>

这是项目的主文件。如果未设置 `run` 属性，运行时将执行 `entrypoint` 指定的文件。

```toml theme={null}
entrypoint = "<file-name>.py"
```

<div id="comando-run">
  ### `Run` 命令
</div>

`.replit` 文件中的 `run` 属性是一项核心配置，它决定了在 Replit 环境中点击 `Run` 按钮时执行的初始命令或一系列命令。`Run` 命令既可以写成字符串，表示要执行的命令；也可以写成字符串数组，分别表示该命令及其各个参数。

配置 `Run` 命令的几种常见方式：

* **单个命令：**
  该示例展示如何传入单个命令，直接在 Replit App 中执行。在 `.replit` 文件中写入以下内容后，点击 `Run` 按钮就会在 `Console` 面板中输出一句问候语：
  **示例：** `run = "echo 'Hello, Replit!'"`

* **显式参数：**
  在某些情况下，写得更明确会更有好处，可以省去处理引号或 shell 插值规则的麻烦。你可以把上面的示例改写成参数分离的形式。
  注意，此时不再需要 `'` 和 `"`，因为你已经显式地将问候语作为 `echo` 的第一个也是唯一一个参数传入：
  **示例：** `run = ["echo", "Hello, Replit!"]`

* **多个命令：**
  该示例展示如何同时运行多个进程，例如前端和后端。如果你正在开发 python 后端和 typescript 前端，且两个服务器分别绑定在不同端口上，这种方式会很有用：
  **示例：** `run = "python -m app & npm run start & wait"`

<div id="gerenciamento-de-processos">
  #### 进程管理
</div>

虽然可以用 `&` 同时运行多个命令，但你可能希望更清晰地区分各个服务的日志。你可以[添加系统依赖](/zh/pt/features/project-setup/dependency-management#system-dependencies)，例如 [`process-compose`](https://github.com/F1bonacc1/process-compose)，从而更好地编排多个进程。

<div id="fase-de-build">
  #### `Build` 阶段
</div>

对于某些语言或运行时，代码在运行 (`run`) 之前需要经过一个独立的编译阶段。这既涵盖了 TypeScript、Golang、Java 等编译型语言，也提供了一个参数，让你可以在下一次调用 `run` 之前重置环境、数据或配置。

* **编译：**
  在 TypeScript 仓库中，你可能需要先执行 `tsc`，然后再运行代码。
  **示例：**

```toml theme={null}
build = "tsc app.ts"
run = "node app.js"
```

<div id="incluindo-variveis-de-ambiente">
  #### 包含环境变量
</div>

若要在运行前为服务提供环境变量，可以将 `run` 属性扩展为一个[表](https://toml.io/en/v1.0.0#table)。

这项改动较为复杂，通常需要调整 `run = "..."` 属性在 `.replit` 文件中的位置。

以下 diff 展示了如何通过 `[run]` 中的 `args` 提供运行命令，并在 `[run.env]` 中提供 `NAME` 变量：

```diff theme={null}
-run = ["bash", "-c", "echo \"Hello, $NAME!\""]

 modules = ["nodejs-20"]

 hidden = [".pythonlibs"]

+# 我们需要把新增的 [run] 移到所有不以 `[` 开头的
+# 顶层属性之后！
+[run]
+args = ["bash", "-c", "echo \"Hello, $NAME!\""]
+
+[run.env]
+NAME="Replit"

 [nix]
 channel = "stable-23_11"
```

<div id="interatividade">
  #### 交互性
</div>

交互式程序同样可以通过 `Run` 按钮启动，这样便于将开发环境与运行程序的终端区分开来。
请看下面这个计数脚本：

**示例**

```toml theme={null}
[run]
args = ["bash", "-c", """
count=0
while read -p "$PROMPT" -r next && [ -n "$next" ]; do
    count=$((count+next))
done
echo "The numbers you entered sum to $count!"
"""]

[run.env]
PROMPT = "Next number ([Enter] to end): "
```

<div id="opes-de-configurao-avanada">
  ## 高级配置选项
</div>

了解 Replit App 提供的各项详细配置选项。你可以自定义开发环境、管理运行命令、集成语言服务并处理依赖项。

| **配置**     | **键**                               | **值/示例**                                    | **说明**                             |
| ---------- | ----------------------------------- | ------------------------------------------- | ---------------------------------- |
| onBoot     | <a name="onBoot" />`onBoot`         | `onBoot = "npm install"`                    | Replit App 启动时执行的命令。               |
| compile    | <a name="compile" />`compile`       |  (无默认示例)                                    | 在 `run` 命令之前执行的命令，用于 C++ 等编译型语言。   |
| language   | <a name="language" />`language`     | `language = "javascript"`                   | 从 GitHub 导入或创建 Replit App 时指定所用语言。 |
| entrypoint | <a name="entrypoint" />`entrypoint` | `entrypoint = "index.js"`                   | 打开编辑器时运行并显示的主文件。                   |
| hidden     | <a name="hidden" />`hidden`         | `hidden = [".config", "package-lock.json"]` | 在侧边文件树中默认隐藏的文件或文件夹。                |
| audio      | <a name="audio" />`audio`           | `audio = true`                              | 设为 `true` 时启用系统音频。                 |

<div id="notas-sobre-o-udio-do-sistema">
  ### 系统音频说明
</div>

在 `.replit` 文件中设置 `audio = true` 后，可能需要重启开发环境。用 `Cmd+K` (Mac) 或 `Ctrl+K` (Windows) 打开命令面板，搜索 **Restart compute** 并选择该命令。

运行图形化应用时，你会在 `Output` 面板右下角看到一个带复选框的耳机图标。
受浏览器限制，每次刷新页面后都需要重新启用。

```toml theme={null}
# 请确保这一行位于 `.replit` 文件顶部，且不在任何以 `[` 开头的区块内
audio = true
```

<div id="configurao-do-packager">
  ## packager 配置
</div>

| **配置**            | **键**                                             | **值/示例**                                      | **说明**                       |
| ----------------- | ------------------------------------------------- | --------------------------------------------- | ---------------------------- |
| packager          | <a name="language" />`language`                   | `packager.language = "python3"`               | 执行包操作时使用的语言。                 |
| packager features | <a name="guessImports" />`guessImports`           | `packager.features.guessImports = true`       | 在运行 Replit App 之前自动检测需要安装的包。 |
| packager features | <a name="packageSearch" />`packageSearch`         | `packager.features.packageSearch = true`      | 设置为 `true` 时启用 packager 支持。  |
| packager features | <a name="enabledForHosting" />`enabledForHosting` | `packager.features.enabledForHosting = false` | 指定托管 Replit App 时是否需要执行包安装。  |
| packager          | <a name="afterInstall" />`afterInstall`           | `afterInstall = "echo 'package installed'"`   | 通过 packager 安装新包后执行的命令。      |
| packager          | <a name="ignoredPaths" />`ignoredPaths`           | `ignoredPaths = [".git"]`                     | 检测包时需要忽略的路径。                 |
| packager          | <a name="ignoredPackages" />`ignoredPackages`     | `ignoredPackages = ["twitter", "discord"]`    | 安装过程中不应为其检测包的模块。             |

<div id="exemplo-de-configurao-replit-para-configurao-do-packager">
  ### packager 配置的 `.replit` 示例
</div>

```toml theme={null}
# 指定 Replit App 使用的语言
packager.language = "python3"

# 启用自动包管理功能
[packager.features]
guessImports = true
packageSearch = true
enabledForHosting = false

# 每次安装包后执行的命令
packager.afterInstall = "echo 'Package installed successfully'"

# 指定包管理器需要忽略的路径和包
packager.ignoredPaths = [".git", "node_modules"]
packager.ignoredPackages = ["twitter", "discord"]

# 其他发布配置
[deployment]
run = ["python3", "app.py"]
```

<div id="configurao-de-publicao-deployment">
  ## 部署 (deployment) 配置
</div>

| **配置项**    | **键**                                 | **值/示例**                             | **说明**                    |
| ---------- | ------------------------------------- | ------------------------------------ | ------------------------- |
| deployment | <a name="run" />`run`                 | `deployment.run = "npm start"`       | 启动部署容器时执行的命令。             |
| deployment | <a name="build" />`build`             | `deployment.build = "npm run build"` | 运行部署之前执行的命令。              |
| deployment | <a name="ignorePorts" />`ignorePorts` | `deployment.ignorePorts = true`      | 若为 `true`，部署成功无需通过开放端口检查。 |

<div id="exemplo-de-configurao-replit-para-configurao-de-publicao">
  ### 部署配置的 `.replit` 示例
</div>

```toml theme={null}

# 指定项目的主入口文件
entrypoint = "app.js"

# 发布应用的相关配置
[deployment]
run = "npm start"
build = "npm run build"
ignorePorts = true
```

<Note>
  **interpreter 配置**已弃用，Replit 中不再提供该功能。建议改用 `Run` 命令来配置脚本和应用在 Replit App 环境中的运行方式。
</Note>

<div id="acessando-os-metadados-do-ambiente-do-replit-app">
  ## 访问 Replit App 的环境元数据
</div>

<div id="nodejs">
  ### Node.js
</div>

要访问所有环境变量：

`console.log(process.env);`

要访问单个变量 (REPL&#95;SLUG) ：

`console.log(process.env.REPL_SLUG);`

<div id="python">
  ### Python
</div>

要访问所有环境变量：

```python theme={null}
import os
print(os.environ)
```

要访问单个变量 (REPL&#95;SLUG) ：

```python theme={null}
import os
variable = os.environ.get('REPL_SLUG')
print(variable)
```

<div id="rust">
  ### Rust
</div>

要访问所有环境变量：

```rust theme={null}
use std::env;
fn main() {
    for (key, value) in env::vars() {
        println!("{}: {}", key, value);
    }
}
```

要访问单个变量 (REPL&#95;SLUG) ：

```rust theme={null}
use std::env;
fn main() {
    let variable = env::var("REPL_SLUG").unwrap();
    println!("{}", variable);
}
```
