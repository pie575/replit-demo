이 가이드에서는 바이브 코딩으로 만든 애플리케이션이 보안 모범 사례를 따르도록 도와주는 종합 보안 체크리스트를 소개합니다.

Replit은 [기본적으로](/ko/features/security/overview) 다양한 보안 기능을 제공하지만, 애플리케이션별 요구 사항에 맞는 추가 보안 조치를 이해하고 적용하는 것이 중요합니다.

<div id="prerequisites">
  ## 사전 준비 사항
</div>

* Replit 계정
* 사용하려는 프로그래밍 언어에 대한 기본적인 이해
* Project Editor 사용 경험
* Replit에서 개발 중인 애플리케이션

<div id="front-end-security">
  ## 프런트엔드 보안
</div>

<AccordionGroup>
  <Accordion title="모든 곳에 HTTPS 적용" icon="lock">
    Replit은 모든 애플리케이션에 기본적으로 HTTPS를 사용합니다. 따로 신경 쓸 필요가 없습니다!
  </Accordion>

  <Accordion title="입력값 검증 및 정제" icon="shield-check">
    크로스 사이트 스크립팅(XSS) 공격을 방지하려면 항상 사용자 입력을 검증하고 정제하세요:

    ```javascript theme={null}
    // 나쁜 예: 사용자 입력을 그대로 사용
    element.innerHTML = userInput;

    // 좋은 예: 사용하기 전에 입력값 정제
    import { sanitize } from 'some-sanitizer-library';
    element.innerHTML = sanitize(userInput);
    ```

    Agent에게 이렇게 요청하세요:

    ```
    Help me validate and sanitize inputs to protect against XSS attacks
    ```
  </Accordion>

  <Accordion title="민감한 데이터를 브라우저에 두지 않기" icon="eye-slash">
    API 키와 같은 민감한 정보는 Replit Secrets에 저장하세요.

    secret을 클라이언트 측에 전달하거나 다음 위치에 저장하지 않도록 주의하세요:

    * 로컬 스토리지
    * 세션 스토리지
    * 클라이언트 측 JavaScript
    * 적절한 보안 속성이 없는 쿠키

    Agent에게 이렇게 요청하세요:

    ```
    Help me keep sensitive data out of the browser. Am I doing this correctly?
    ```
  </Accordion>

  <Accordion title="CSRF 보호" icon="shield">
    폼에 크로스 사이트 요청 위조(CSRF) 보호를 구현하세요:

    ```javascript theme={null}
    // CSRF token 구현 예시
    const csrfToken = generateToken();
    session.csrfToken = csrfToken;
    ```

    Agent에게 이렇게 요청하세요:

    ```
    Help me implement CSRF tokens for forms
    ```
  </Accordion>
</AccordionGroup>

<div id="back-end-security">
  ## 백엔드 보안
</div>

<AccordionGroup>
  <Accordion title="인증 기본 사항" icon="key">
    인증을 구현할 때:

    * 가능하면 Replit Auth를 사용하세요
    * 직접 인증을 구현한다면 검증된 라이브러리를 사용하세요
    * 비밀번호를 평문으로 저장하지 마세요

    Agent에게 요청하세요:

    ```
    Replit Auth로 내 애플리케이션에 인증을 구현하도록 도와줘
    ```
  </Accordion>

  <Accordion title="권한 검사" icon="user-lock">
    작업을 수행하기 전에 항상 권한을 확인하세요:

    ```javascript theme={null}
    // 권한 검사 예시
    if (!user.canAccess(resource)) {
      return res.status(403).send('Access denied');
    }
    ```

    Agent에게 요청하세요:

    ```
    내 애플리케이션에 권한 검사를 구현하도록 도와줘
    ```
  </Accordion>

  <Accordion title="API 엔드포인트 보호" icon="shield">
    API 엔드포인트를 안전하게 보호하세요:

    * 민감한 엔드포인트에 인증을 추가하세요
    * 적절한 CORS 설정을 구현하세요
    * 요청 속도 제한(rate limiting)을 고려하세요

    Agent에게 요청하세요:

    ```
    내 앱의 엔드포인트를 제대로 인증하려면 어떻게 해야 해?
    ```
  </Accordion>

  <Accordion title="SQL 인젝션 방지" icon="database">
    Agent는 기본적으로 ORM을 사용하므로 SQL 인젝션 방지에 도움이 됩니다. 데이터베이스 쿼리를 직접 작성하는 경우:

    ```javascript theme={null}
    // 나쁜 예: 쿼리에서 문자열 연결 사용
    db.query(`SELECT * FROM users WHERE username = '${username}'`);

    // 좋은 예: ORM을 사용한 파라미터화된 쿼리
    db.query('SELECT * FROM users WHERE username = ?', [username]);
    ```
  </Accordion>

  <Accordion title="보안 헤더" icon="code">
    애플리케이션에 중요한 보안 헤더를 추가하세요:

    ```html theme={null}
    <!-- index.html 또는 백엔드를 통해 -->
    <meta http-equiv="X-Frame-Options" content="DENY">
    <meta http-equiv="X-Content-Type-Options" content="nosniff">
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
    ```

    [securityheaders.com](https://securityheaders.com)에서 사이트를 검사해 권장 사항을 확인할 수 있습니다.

    Agent에게 요청하세요:

    ```
    내 애플리케이션에 보안 헤더를 추가해 줄래?
    ```
  </Accordion>
</AccordionGroup>

<div id="ongoing-security-practices">
  ## 지속적인 보안 관행
</div>

<AccordionGroup>
  <Accordion title="의존성 최신 상태 유지" icon="arrow-rotate-right">
    취약점이 있을 수 있는 오래된 packages가 없는지 정기적으로 확인하세요:

    ```bash theme={null}
    npm audit
    ```
  </Accordion>

  <Accordion title="적절한 오류 처리" icon="exclamation">
    오류 메시지에 민감한 정보를 노출하지 마세요:

    ```javascript theme={null}
    // 나쁜 예: 민감한 세부 정보 노출
    catch (err) {
      res.status(500).send(`Database error: ${err.message}`);
    }

    // 좋은 예: 일반적인 오류 메시지
    catch (err) {
      console.error(err); // 내부적으로 기록
      res.status(500).send('An error occurred');
    }
    ```

    Agent에게 요청하세요:

    ```
    Help me implement proper error handling for my application
    ```
  </Accordion>

  <Accordion title="안전한 쿠키" icon="cookie">
    쿠키를 사용할 때는 다음을 지키세요:

    * JavaScript 접근을 막도록 HttpOnly 플래그를 설정하세요
    * HTTPS를 강제하도록 Secure 속성을 사용하세요
    * CSRF를 방지하도록 SameSite 속성을 적용하세요

    Agent에게 요청하세요:

    ```
    Help me secure my cookies for my application
    ```
  </Accordion>

  <Accordion title="파일 업로드 보안" icon="upload">
    애플리케이션에서 파일 upload를 허용한다면:

    * 파일 형식과 크기를 제한하세요
    * 가능하다면 malware 검사를 수행하세요
    * 파일은 Replit의 Object Storage에 저장하세요
    * 사용자가 제공한 이름을 그대로 쓰지 말고 새 파일 이름을 생성하세요

    Agent에게 요청하세요:

    ```
    Help me secure my file uploads for my application
    ```
  </Accordion>

  <Accordion title="요청 속도 제한" icon="clock">
    API 엔드포인트, 특히 authentication 관련 endpoints에는 요청 속도 제한을 적용하세요:

    ```javascript theme={null}
    // rate limiting middleware 예시
    const rateLimit = require('express-rate-limit');

    const limiter = rateLimit({
      windowMs: 15 * 60 * 1000, // 15분
      max: 100 // IP별로 windowMs당 100회 요청으로 제한
    });

    app.use('/api/', limiter);
    ```

    Agent에게 요청하세요:

    ```
    Help me implement rate limiting for my application
    ```
  </Accordion>
</AccordionGroup>

  ## 체크리스트

보안 수칙을 빠짐없이 지킬 수 있도록 위 내용을 체크리스트로 정리했습니다.

<div id="front-end-security-2">
  ## 프런트엔드 보안
</div>

|   | 보안 조치                         | 설명                                   |
| - | ----------------------------- | ------------------------------------ |
| ☐ | 모든 곳에서 HTTPS 사용               | 기본적인 도청 및 중간자 공격을 방지합니다              |
| ☐ | 입력값 검증 및 정제                   | 모든 사용자 입력을 검증하여 XSS 공격을 방지합니다        |
| ☐ | 브라우저에 민감한 데이터를 저장하지 않기        | 로컬 스토리지나 클라이언트 측 코드에 secret을 두지 않습니다 |
| ☐ | CSRF 보호                       | 폼 및 상태 변경 요청에 anti-CSRF token을 적용합니다 |
| ☐ | frontend에 API key를 절대 노출하지 않기 | API 자격 증명은 항상 서버 측에만 두어야 합니다         |

  ## 백엔드 보안

|   | 보안 조치        | 설명                                               |

| ☐ | SQL 인젝션 방지   | 매개변수화된 쿼리나 ORM 사용, 사용자 입력이 포함된 원시 SQL은 절대 사용 금지  |
| ☐ | 기본 보안 헤더     | X-Frame-Options, X-Content-Type-Options, HSTS 구현 |
| ☐ | DDoS 방어      | DDoS 완화 기능이 내장된 CDN 또는 클라우드 서비스 사용               |

  ## 실용적인 보안 습관

|   | 보안 조치        | 설명                                   |

| ☐ | 의존성 최신 상태 유지 | 대부분의 취약점은 오래된 라이브러리에서 발생합니다          |

| ☐ | 파일 업로드 보안    | 파일 형식과 크기를 검증하고 악성 콘텐츠를 검사하세요        |
| ☐ | 요청 속도 제한    | 모든 API 엔드포인트, 특히 인증 관련 엔드포인트에 적용하세요  |
