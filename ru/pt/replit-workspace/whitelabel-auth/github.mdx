В этом руководстве приведены пошаговые инструкции по созданию OAuth-приложения GitHub в настройках разработчика GitHub. Вы получите **Client ID** и **Client Secret**, которые нужно указать в **панели Auth**.

<Note>
  На этой странице рассматривается только настройка на стороне провайдера в настройках разработчика GitHub. Общий процесс настройки Clerk Auth, включая включение GitHub и ввод учетных данных в **панели Auth**, см. в разделе [Настройка учетных данных OAuth для провайдера SSO](/ru/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider) документации Clerk Auth.
</Note>

<div id="pr-requisitos">
  ## Предварительные требования
</div>

* Учётная запись [GitHub](https://github.com)
* Опубликованный [app Replit](/ru/category/replit-deployments) — пользовательские учётные данные OAuth доступны только в среде **Production**
* Открыта панель редактирования провайдера **GitHub**: **панель Auth** → вкладка **Configure** → раздел **SSO providers** → выберите среду **Production** → выберите **Edit** рядом с **GitHub**

<div id="passo-1-criar-um-app-oauth-do-github">
  ## Шаг 1: Создайте OAuth-приложение GitHub
</div>

1. Перейдите в [настройки разработчика GitHub](https://github.com/settings/developers)
2. На боковой панели выберите **OAuth Apps**
3. Выберите **New OAuth App**
4. Заполните данные приложения:

**Application name:**

Введите название приложения.

**Homepage URL** и **Authorization callback URL:**

Укажите в обоих полях точные значения из раздела **Provider setup** на **панели Auth**. Подробнее о том, как их найти, см. в статье [Настройка учетных данных OAuth для провайдера SSO](/ru/pt/core-concepts/project-editor/auth-and-security/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

5. Выберите **Register application**

<div id="passo-2-gerar-as-credenciais-do-cliente">
  ## Шаг 2: Создание учетных данных клиента
</div>

1. На странице настроек App вы увидите свой **Client ID** — скопируйте его.
2. Выберите **Generate a new client secret**.
3. Сразу скопируйте свой **Client Secret**.

<Warning>
  Храните Client Secret в безопасном месте. После ухода со страницы его нельзя будет просмотреть повторно. Если он будет утерян, потребуется создать новый.
</Warning>

<div id="soluo-de-problemas">
  ## Устранение неполадок
</div>

<div id="incompatibilidade-de-uri-de-redirecionamento">
  ### Несоответствие URI перенаправления
</div>

* Убедитесь, что Authorization callback URL точно соответствует значению, указанному в **Provider setup** на **панели Auth**
* Проверьте, нет ли опечаток или неверно указанных протоколов
* Не используйте завершающие косые черты

<div id="cliente-invlido">
  ### Недопустимый клиент
</div>

* Ещё раз проверьте, правильно ли скопированы Client ID и Client Secret
* Убедитесь, что при вставке нет лишних пробелов

<div id="no-est-funcionando-no-domnio-personalizado">
  ### Не работает на пользовательском домене
</div>

* Обновите Homepage URL и Authorization callback URL, указав значения пользовательского домена, приведённые в разделе **Provider setup** на **панели Auth**
