本文解答已部署应用中可能出现的错误。如需更全面的排查方法，请参阅[部署问题排查](/zh/ko/build/troubleshooting)。

<AccordionGroup>
  <Accordion title="已部署的应用返回 403 Forbidden 错误，如何修复？">
    已部署应用出现 403 错误，通常由以下原因之一造成：

    * **请求头过大**——Cookie 过多会导致请求头体积过大，从而在边缘节点被拒绝。请清除该域名下的浏览器 Cookie 后重新测试。
    * **缺少身份验证**——请求中未包含所需的登录 token 或会话。
    * **访问受限**——应用可能被配置为阻止部分流量。请参阅[私有部署](/zh/ko/features/publishing/private-deployments)和[外部访问 token](/zh/ko/features/deployment-customization/external-access-tokens)。

    如需更详细的诊断，请将部署日志粘贴到新的 Agent 聊天中。
  </Accordion>

  <Accordion title="App 显示“Application failed to respond”——这是什么意思？">
    应用进程未在 Replit 预期的端口上监听。Replit 会通过 `PORT` 环境变量传入正确的端口，请使用该变量进行绑定，不要写死端口值：

    ```js theme={null}
    const PORT = process.env.PORT || 3000;
    ```

    ```python theme={null}
    port = int(os.environ.get("PORT", 3000))
    ```

    应用也可能在绑定之前就已崩溃——请在部署日志中查看启动错误。对于 [Autoscale 部署](/zh/ko/features/publishing/deployment-types#autoscale)，在一段时间无请求之后，首次请求可能需要几秒钟才能响应 (冷启动) ，这属于正常现象。
  </Accordion>

  <Accordion title="如何修复已部署的 Replit 应用中的 CORS 错误？">
    CORS 错误表示前端和后端的源不同，且后端未配置为允许该源。如果它们属于同一应用，请使用相对 URL (例如 `/api/endpoint`) 来彻底避免 CORS。

    否则，请将后端配置为允许前端源。以 Express 为例：

    ```js theme={null}
    const cors = require("cors");
    app.use(cors({ origin: "https://your-frontend.replit.app" }));
    ```

    发布前请仅允许必需的源 (origin) 。请参阅[部署问题排查](/zh/ko/build/troubleshooting)。
  </Accordion>

  <Accordion title="应用在本地运行正常，但部署后出现网络错误">
    当生产环境与本地配置不一致时，已部署的 App 可能会无法正常运行。请检查以下三项：

    1. **硬编码的 localhost URL**—将 `localhost:3000` 或 `127.0.0.1` 替换为相对路径或基于环境的 URL，然后重新部署。
    2. **缺少生产环境密钥**—确认部署 Secrets 中已设置所有必需的密钥。请参阅[Secrets](/zh/ko/core-concepts/project-editor/app-setup/secrets)。
    3. **未在生产环境中执行的迁移**—在发布前，对生产数据库执行所有待处理的迁移。

    如果问题仍然存在，请[联系 Replit 支持团队](https://replit.com/support)，并附上错误信息和已尝试的步骤。
  </Accordion>

  <Accordion title="如何调试已部署应用中出现的 502 Bad Gateway 错误？">
    502 通常表示应用进程已崩溃，或服务器返回了无效响应。请查看部署日志，排查 502 发生前的崩溃错误——未处理的 Promise 拒绝和未捕获的异常可能会导致 Node.js 进程自动崩溃。

    添加可捕获崩溃的处理程序：

    ```js theme={null}
    process.on("uncaughtException", (err) => console.error("Uncaught:", err));
    ```

    如果你能在日志中找到根本错误，可以将其粘贴到新的 Agent 聊天中，让它帮你修复。
  </Accordion>

  <Accordion title="应用无法向外部 API 发出请求——该检查什么？">
    首先确认请求是被拦截了，而不是在代码中执行失败。打开部署日志，查找有关出站请求被拦截或被重定向的消息。

    常见原因及解决方法：

    * **自引用 URL**——如果后端调用了自身的公开 URL (例如 `fetch("https://myapp.replit.app/api/...")`) ，请改用相对路径 `fetch("/api/...")`。
    * **构建阶段发起的请求**——请在运行时发起出站调用，不要在构建期间执行。
    * **网络限制**——公司或学校网络可能会拦截出站连接。请与网络管理员确认。

    如果以上情况都不适用，而请求仍被拦截，请附上相关日志行并[联系 Replit 支持团队](https://replit.com/support)。
  </Accordion>

  <Accordion title="重新发布后，应用 URL 变了——我可以找回之前的子域名吗？">
    `.replit.app` 子域名由项目名称派生而来，取消发布后再重新发布时不保证保持不变，尤其是在项目名称有过更改的情况下。

    一劳永逸的做法是使用[自定义域名](/zh/ko/features/publishing/custom-domains)，它在重新部署后依然保持不变。若要找回之前的子域名，请确认项目名称与原名称一致 (必要时改回原名) ，然后重新发布——Replit 无法手动重新分配已释放的子域名。请参阅[项目地理位置](/zh/ko/features/publishing/project-geography)。
  </Accordion>
</AccordionGroup>
