<div id="como-o-replitmd-funciona">
  ## Comment fonctionne `replit.md`
</div>

Agent crée d’abord un fichier `replit.md` dans le répertoire racine de votre projet en s’appuyant sur des bonnes pratiques éprouvées. Ce fichier comprend :

* Des informations de base sur le projet
* Des conventions de codage recommandées
* Des préférences courantes pour votre type de projet

<YouTubeEmbed videoId="kYv525W-vaU" title="Personnaliser les réponses de Replit Agent" />

Lorsque Agent traite vos demandes, il lit automatiquement le fichier `replit.md` et utilise son contenu pour :

* Comprendre l’architecture et les conventions de votre projet
* Respecter vos conventions et styles de codage préférés
* Utiliser les gestionnaires de paquets et les dépendances spécifiés

Agent peut également mettre à jour le fichier `replit.md` à mesure qu’il en apprend davantage sur votre projet et apporte des modifications à votre application.

<Note>
  Vous pouvez modifier le fichier `replit.md` pour personnaliser le comportement d’Agent.
</Note>

<div id="configurando-o-replitmd">
  ## Configuration de `replit.md`
</div>

<div id="gerao-automtica">
  ### Génération automatique
</div>

Lorsque vous créez un projet avec Agent, celui-ci génère automatiquement un fichier `replit.md` fondé sur des bonnes pratiques éprouvées. Ce fichier se trouve dans le répertoire racine de votre projet et contient :

* Des informations de base sur le projet
* Des conventions de codage recommandées
* Des préférences courantes pour votre type de projet

<div id="criao-manual">
  ### Création manuelle
</div>

Vous pouvez créer votre propre fichier `replit.md` en ajoutant un fichier nommé `replit.md` dans le répertoire racine de votre projet. Agent détectera et utilisera automatiquement ce fichier lors de vos prochaines conversations.

<Note>
  Le fichier `replit.md` doit se trouver dans le répertoire racine de votre projet pour fonctionner correctement.
</Note>

<div id="regenerando-o-replitmd">
  ### Régénérer le `replit.md`
</div>

Si le fichier `replit.md` est corrompu ou si vous souhaitez repartir de zéro :

1. Supprimez le fichier `replit.md` existant du répertoire racine de votre projet
2. Démarrez une nouvelle conversation avec l’Agent
3. L’Agent générera automatiquement un nouveau fichier `replit.md` à partir de votre projet actuel

  ## Bonnes pratiques
</div>

<div id="seja-especfico-e-claro">
  ### Soyez précis et clair
</div>

Rédigez des instructions claires et précises qui permettront à Agent de comprendre exactement ce que vous voulez :

```markdown theme={null}
## Style de code

- Utilisez TypeScript pour tous les nouveaux fichiers JavaScript
- Préférez les composants fonctionnels avec des hooks plutôt que les composants de classe
- Utilisez Tailwind CSS pour le style, évitez les styles en ligne
- Incluez toujours des types TypeScript pour les paramètres des fonctions et les valeurs de retour
```

Pour en savoir plus sur la mise en forme des prompts, consultez le [guide d’Anthropic sur l’ingénierie des prompts](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/use-xml-tags).

```markdown theme={null}
## Contexte du projet

Il s’agit d’un réseau social destiné aux amateurs de livres, où les utilisateurs peuvent :
- Créer des listes de lecture et partager des recommandations de livres
- Suivre d’autres lecteurs et consulter leurs actualités
- Noter les livres qu’ils ont lus et rédiger des avis

Public cible : lecteurs occasionnels de 25 à 45 ans
Stack technologique : frontend React, backend Node.js, base de données PostgreSQL
```

<div id="projeto-de-aplicao-web">
  ### Projet d’application web
</div>

```markdown theme={null}
# Directives du projet MyApp

## Présentation du projet
Une application web de gestion des tâches développée avec React et Express.js.

## Préférences technologiques
- Frontend : React avec TypeScript et Tailwind CSS
- Backend : Express.js avec TypeScript
- Base de données : Neon PostgreSQL avec Drizzle ORM
- Gestionnaire de paquets : npm (et non yarn ou pnpm)

## Normes de codage
- Utilisez des composants fonctionnels avec des hooks
- Implémentez des limites d’erreur appropriées
- Respectez les conventions des API REST pour les points de terminaison
- Utilisez des noms descriptifs pour les variables et les fonctions

## Style de communication
- Expliquez votre approche avant d’apporter des modifications
- Ajoutez des commentaires dans le code pour la logique complexe
- Posez des questions si les exigences sont ambiguës
```

<div id="projeto-de-anlise-de-dados">
  ### Projet d’analyse de données
</div>

```markdown theme={null}
# Directives pour les projets d’analyse de données

## Contexte du projet
Analysez les données relatives au comportement des clients afin d’identifier les tendances et d’en tirer des enseignements.

## Préférences technologiques
- Python avec Streamlit pour créer des applications web interactives
- pandas, numpy et matplotlib pour l’analyse de données

## Normes d’analyse
- Documentez clairement toutes les étapes de l’analyse
- Créez des visualisations interactives avec les composants Streamlit
- Vérifiez la qualité des données avant l’analyse
- Exportez les résultats au format CSV et affichez-les dans des tableaux Streamlit

## Style de communication
- Expliquez les méthodes et hypothèses statistiques
- Donnez du contexte aux observations et recommandations
- Utilisez un langage clair et non technique pour présenter les enseignements métier
- Créez des tableaux de bord interactifs pour les présentations aux parties prenantes
```

<div id="projeto-de-desenvolvimento-de-api">
  ### Projet de développement d&#39;API
</div>

```markdown theme={null}
# Directives de développement d’API

## Vue d’ensemble du projet
Création d’une API RESTful pour le backend d’une application mobile.

## Stack technologique
- Node.js avec Express.js
- MongoDB avec Mongoose
- JWT pour l’authentification
- Gestionnaire de paquets : npm

## Normes API
- Utiliser des codes d’état HTTP sémantiques
- Mettre en œuvre une validation appropriée des entrées
- Inclure une limitation du débit sur les points de terminaison publics
- Suivre la spécification OpenAPI pour la documentation

## Exigences de sécurité
- Valider toutes les entrées utilisateur
- Utiliser des variables d’environnement pour les données sensibles
- Mettre en œuvre des politiques CORS appropriées
- Inclure la journalisation des requêtes pour le débogage

## Approche de test
- Écrire des tests unitaires pour tous les points de terminaison
- Inclure des tests d’intégration pour les flux critiques
- Utiliser Jest comme framework de test
```

<div id="combinando-pesquisa-na-web-com-replitmd">
  ## Combiner la recherche web avec `replit.md`
</div>

Agent peut effectuer des recherches sur le web pour trouver des informations récentes, des bibliothèques et des solutions. Associé au fichier `replit.md`, il vous apporte à la fois des connaissances à jour et des conseils propres au projet.

<div id="prticas-recomendadas-para-integrao-com-pesquisa-na-web">
  ### Bonnes pratiques pour l&#39;intégration de la recherche web
</div>

**Précisez ce que vous souhaitez qu&#39;Agent recherche :**

```markdown theme={null}
## Préférences de recherche
- Vérifiez toujours les dernières versions des dépendances avant de suggérer des mises à jour
- Recherchez les bonnes pratiques actuelles pour les implémentations de sécurité
- Recherchez des techniques récentes d'optimisation des performances pour notre stack technique
```

**Indiquez à Agent comment appliquer les connaissances externes :**

```markdown theme={null}
## Consignes de recherche externe
- Lorsque vous suggérez de nouvelles bibliothèques, assurez-vous de leur compatibilité avec notre stack existante
- Adaptez les exemples externes à nos normes de codage et à la structure de notre projet  
- Vérifiez que les solutions proposées fonctionnent avec notre environnement de publication
```

**Exemple de demande tirant parti des deux :**
&quot;Recherchez les techniques les plus récentes d’optimisation des performances de React 18 et implémentez-les en suivant les modèles de composants définis dans `replit.md`&quot;

Cette approche permet d’obtenir des solutions à la fois à jour et adaptées aux besoins spécifiques de votre projet.

<div id="limitaes">
  ## Limites
</div>

<div id="limites-de-tamanho-e-contedo-do-arquivo">
  ### Limites de taille et de contenu du fichier
</div>

Bien qu’il n’existe pas de limite stricte quant au nombre de caractères de `replit.md`, les fichiers très volumineux risquent de ne pas être entièrement traités. Veillez à ce que `replit.md` reste ciblé et concis pour de meilleurs résultats.

<div id="requisito-de-diretrio-raiz">
  ### Exigence relative au répertoire racine
</div>

Le fichier `replit.md` doit se trouver dans le répertoire racine de votre projet. Agent ne détecte pas automatiquement les fichiers situés dans des sous-répertoires.

<div id="escopo-do-contexto">
  ### Portée du contexte
</div>

Le fichier `replit.md` fournit du contexte aux conversations avec l&#39;Agent, mais il ne s&#39;applique pas automatiquement aux autres outils d&#39;IA.

<div id="prximos-passos">
  ## Prochaines étapes
</div>

Prêt à personnaliser Agent pour votre projet ?

1. **Commencez simplement** : créez un `replit.md` de base avec vos principales préférences
2. **Itérez et améliorez** : mettez à jour le `replit.md` à mesure que vous travaillez avec Agent
3. **Partagez les bonnes pratiques** : utilisez des configurations `replit.md` efficaces dans des projets similaires
4. **Surveillez l’efficacité** : observez dans quelle mesure Agent suit vos instructions et ajustez-les si nécessaire

**Enterprise** : préconfigurez le `replit.md` dans des [templates personnalisés](/fr/pt/teams/custom-templates) afin de fournir à tous les créateurs de votre organisation un contexte initial cohérent. Pour des conseils spécifiques sur le design, consultez [comment configurer un design system](/fr/pt/teams/custom-design-system).
