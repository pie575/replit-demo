外部访问令牌是你为特定 Replit App 生成的 Bearer 令牌。
即使应用的 URL 已被[私有开发 URL](/zh/features/publishing/private-deployments)或[私有部署](/zh/features/publishing/private-deployments)限制访问，这些令牌也能让 CI 流水线、Webhook、状态检查探测器、Slack 机器人、内部脚本等自动化服务照常访问该应用。

请像对待密码一样对待每个令牌：在令牌过期或被你吊销之前，任何持有它的人都能访问你的应用。

<Note>
  只要为某个部署选择私有访问，即可使用外部访问令牌，无需在 workspace 中额外开启。在 Enterprise workspace 中，只有 workspace 管理员可以管理令牌。
</Note>

<div id="when-to-use-a-token">
  ## 何时使用令牌
</div>

当浏览器*之外*的程序需要调用你的私有 Replit App 时，就该使用外部访问令牌了。常见场景包括：

* GitHub Actions 工作流在每次提交时针对你的开发 URL 运行冒烟测试。
* uptime 监控服务 (Better Stack、Pingdom、UptimeRobot) 访问你已发布应用的健康检查端点。
* Webhook 接收方——Stripe、Slack、GitHub——向私有部署发送 POST 请求。
* 队友调试时从自己机器发起的 `curl` 或 `fetch` 调用。

外部访问令牌是为 **API 流量**设计的，并不适用于在浏览器中打开界面页面。单页应用 (Vite、Next.js 等) 会在后续请求中加载 JavaScript 包，而这些请求不会携带你的令牌，因此会失败。如需交互式浏览，请照常登录。

<div id="token-environments">
  ## 令牌环境
</div>

每个令牌都绑定到一个环境：

| 环境            | 适用范围                                       | 用途                   |
| :------------ | :----------------------------------------- | :------------------- |
| `Development` | 应用的 workspace 开发 URL (`*.replit.dev`)      | 在开发过程中访问正在运行的 Repl   |
| `Production`  | 应用已发布的部署 (`*.replit.app` 及自定义域名)  | 从外部服务访问私有部署 |

`Production` 令牌在重新发布 (包括发布新版本) 后仍然有效。
出现以下情况时，Replit 会吊销该令牌：

* 取消发布该部署。
* 删除该部署。
* 将应用的访问权限从私有改为公开。

令牌过期或被你吊销后同样会失效。

<div id="create-an-external-access-token">
  ## 创建外部访问令牌
</div>

<Steps>
  <Step>
    打开你要对外开放的应用，然后打开 **Publishing** 工具。
  </Step>

  <Step>
    选择 **Adjust settings**，展开重新部署选项。
  </Step>

  <Step>
    在 **Security** 部分找到 **外部访问令牌**。
  </Step>

  <Step>
    选择 **Create access token** 并填写以下内容：

    * **Label** (可选) ：一个简短的名称，便于你日后识别该令牌，
      例如 `CI` 或 `Stripe webhook`。最多 120 个字符。
    * **Environment**：根据调用方服务需要访问应用的环境，选择 `Development` 或 `Production`。
    * **Expires after**：选择有效期 —— `1 hour`、`24 hours`、`7 days`、
      `30 days`、`3 months`、`1 year` 或 `5 years`。请选择满足需求的最短时限。
      没有“永不过期”选项。
  </Step>

  <Step>
    选择 **Create**。
  </Step>
</Steps>

Replit 只会显示令牌**一次**。请立即复制 —— 关闭对话框后就
再也无法查看该令牌。如果丢失，请撤销该令牌并重新生成
一个新令牌。

令牌显示界面提供两种复制方式：

* **Copy 查询参数** —— 复制 `?project-protection-bypass=<token>`，可附加到 URL 后面。适合快速执行 `curl` 检查。
* **Copy token only** —— 复制原始令牌，适合放在
  `Authorization: Bearer` 请求头中发送。

<Info>
  如果应用尚未开启外部访问，创建第一个令牌时会自动为其开启。
  没有防护屏蔽，令牌也就无从绕过。
</Info>

<div id="use-a-token">
  ## 使用令牌
</div>

可通过以下两种方式之一提供令牌：

<div id="authorization-header-recommended">
  ### Authorization 请求头 (推荐)
</div>

```bash theme={null}
curl -H "Authorization: Bearer <token>" https://your-app.replit.app/health
```

几乎在所有场景下，这都是首选方式——Webhook、CI 脚本、后端之间的调用。令牌不会出现在记录 URL 的日志中，也不会留存在浏览器历史记录里。

<div id="query-parameter">
  ### 查询参数
</div>

```bash theme={null}
curl "https://your-app.replit.app/health?project-protection-bypass=<token>"
```

只有在无法设置请求头时才使用查询参数形式——例如某个服务只接受 URL。带令牌的 URL 常常会出现在代理日志、Shell 历史记录和截图中，因此只要条件允许，请优先使用请求头形式。

<div id="manage-existing-tokens">
  ## 管理现有令牌
</div>

**外部访问令牌**部分会列出你为该应用创建的所有令牌 (最新的排在最前) ，并显示各令牌的标签、环境、创建日期、过期时间和吊销状态。每一行都会显示令牌的末尾几个字符，方便你区分不同的令牌，因为完整值仅在创建时显示一次。

你只能看到*你自己*创建的令牌。其他协作者的令牌仅对其本人可见，即使应用归你所有也是如此。

<div id="revoke-a-token">
  ## 吊销令牌
</div>

当令牌不再需要，或一旦怀疑它可能已泄露，请及时吊销。吊销步骤：

<Steps>
  <Step>
    在应用的发布设置中打开 **外部访问令牌** 部分。
  </Step>

  <Step>
    在列表中找到该令牌，然后点击垃圾桶图标。
  </Step>

  <Step>
    确认吊销。
  </Step>
</Steps>

吊销**立即生效且不可撤销**。仍在使用该令牌的流量会在几秒内开始被拒绝。如需重新获得访问权限，请生成新令牌。

你只能吊销自己创建的令牌。将协作者从 workspace 中移除时，系统会自动吊销其为该应用生成的令牌。

<div id="keep-your-tokens-safe">
  ## 妥善保管你的令牌
</div>

外部访问令牌属于凭据，请像对待 API 密钥或密码一样谨慎处理。

<div id="do">
  ### 应该做的
</div>

* **将令牌存储在密钥管理工具中** —— GitHub Actions secrets、你所用 CI
  厂商的保险库、云服务商的密钥存储，或密码管理器。
  切勿将其提交到代码仓库。
* 尽可能**使用较短的有效期**。为一次性 integration 签发有效期 7 天的令牌，
  远比留下一个 5 年期令牌无人问津要安全。
* **为每个令牌加上标签**，这样日后你才知道它的用途以及是否
  仍在使用。没有标签的令牌往往最先泄露，也最晚被吊销。
* **为每个使用方单独签发令牌。** 每个 CI 作业一个，每个
  webhook 来源一个，每项 uptime 检查一个。一旦某处被攻破，或者
  某个厂商不再需要，你只需吊销那一个即可。
* **优先使用 `Authorization` 请求头**而非查询参数，这样令牌
  就不会通过 URL 日志、浏览器历史记录或 referer 请求头泄露。
* 一旦令牌可能已经暴露，就**立即吊销** —— 无论是日志外泄、
  提交到公开仓库、屏幕共享，还是前员工的笔记本电脑。
  吊销会立即生效；之后再签发一个新令牌替代即可。

<div id="dont">
  ### 不要这样做
</div>

* **不要在团队成员或服务之间共用同一个令牌。** 如果两个系统共用一个令牌，撤销令牌就必然会同时影响另一个系统。
* **不要把令牌粘贴到聊天、邮件、截图或问题跟踪系统中。** 这些渠道会被归档、索引，并以你无法预料的方式扩散。
* **不要把令牌嵌入客户端代码** —— 包括浏览器应用、移动应用和桌面程序。凡是分发到用户设备上的内容，都应视为公开信息。
* **不要用令牌来维持浏览器会话。** 令牌适用于 API 调用，而不适用于在浏览器标签页中加载 SPA。这类场景请使用常规的 Replit 登录方式。
* **不要默认选择 5 年的有效期。** 应根据使用方实际需要访问的时长来设定有效期。

<div id="troubleshooting">
  ## 疑难解答
</div>

<Accordion title="我的生产环境令牌突然失效了">
  生产环境令牌在正常重新发布后仍然有效。请检查令牌是否已过期或被你撤销，也请检查你是否取消发布或删除了该部署，或者将应用从私有改为了公开。如果应用不再具有私有部署，请将其以私有方式发布，然后生成新令牌。已过期或已撤销的令牌无法恢复。
</Accordion>

<Accordion title="令牌在 `curl` 中可用，但浏览器仍显示登录页面">
  外部访问令牌用于 API 流量，而非浏览器会话。单页应用在浏览器中加载时，初始 HTML 请求可以通过查询参数携带令牌，但后续请求 JavaScript 包、CSS 以及调用 API 时不会携带令牌，因而会被拒绝。若要以交互方式浏览应用，请正常登录 Replit。
</Accordion>

<Accordion title="我弄丢了令牌 —— 还能再次查看吗？">
  不能。Replit 仅在创建时显示一次令牌。列表视图会显示元数据 (标签、环境、有效期、末尾几位字符) ，但绝不会显示完整的令牌值。如果令牌丢失，请撤销该令牌并重新创建一个。
</Accordion>
