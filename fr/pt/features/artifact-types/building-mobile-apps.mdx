<div id="visualizao-em-um-simulador-ou-emulador">
  ## Aperçu dans un simulateur ou un émulateur
</div>

Replit vous permet d&#39;exécuter et de tester vos applications mobiles sur votre téléphone avec Expo. Replit peut aussi diffuser un véritable **iOS Simulator** ou **Android Emulator** directement dans le panneau d&#39;aperçu. Les modifications que vous effectuez avec l&#39;Agent sont rechargées automatiquement (hot-reload) dans le simulateur, exactement comme sur un appareil réel.

<Note>
  Les aperçus iOS Simulator et Android Emulator sont disponibles pour les créateurs des plans Core, Pro et Enterprise. Uniquement pour les applications mobiles — l&#39;option est masquée pour les projets exclusivement web.

<div id="quando-usar-o-expo-go-em-vez-disso">
  ### Quand utiliser Expo Go à la place
</div>

Utilisez Expo Go sur un vrai téléphone lorsque vous devez tester des fonctionnalités qui dépendent du matériel réel ou lorsque vous souhaitez partager un aperçu avec quelqu&#39;un qui n&#39;est pas devant votre ordinateur :

* Appareil photo, microphone, retour haptique ou autres capteurs natifs
* Notifications push
* Géolocalisation GPS en conditions réelles
* Partage d&#39;un aperçu de développement avec un coéquipier, un testeur ou un investisseur

Pour ouvrir votre application dans Expo Go, ouvrez le project sur [replit.com](https://replit.com), sélectionnez **Open in Expo Go** dans le panneau d&#39;aperçu du Project Editor, puis scannez le QR code avec l&#39;application [Expo Go](https://expo.dev/go) sur votre téléphone.

<div id="simulador-em-tela-cheia">

</div>

Sur la carte d&#39;un artefact mobile, sélectionnez **More actions** → **Open in iOS Simulator** ou **Open in Android Emulator** pour ouvrir le simulateur dans un onglet dédié, avec une zone d&#39;affichage plus grande.

<div id="por-que-construir-um-aplicativo-mobile">
  ## Pourquoi créer une application mobile ?
</div>

Créez une application mobile lorsque vous souhaitez :

* **Une expérience native** : des performances rapides, des interactions fluides et une interface native à la plateforme.
* **Les fonctionnalités de l&#39;appareil** : appareil photo, notifications push, géolocalisation et bien plus encore.
* **Une distribution sur l&#39;App Store** : une fiche partageable que les utilisateurs peuvent découvrir et installer une fois le processus d&#39;App Review d&#39;Apple terminé.

<div id="principais-recursos">
  ## Fonctionnalités principales
</div>

* **Création axée sur l&#39;IA** : décrivez votre application et Agent génère une application mobile fonctionnelle.
* **Aperçu dans le Project Editor** : testez dans un iOS Simulator ou un Android Emulator sans quitter Replit, ou prévisualisez sur votre téléphone avec Expo Go.
* **Full-stack par défaut** : ajoutez des routes serveur, une Database, App Storage, des Connectors et des intégrations d&#39;IA à mesure que votre application se développe.
* **Publication guidée** : préparez des builds pour TestFlight et pour la soumission à l&#39;App Store sans avoir à gérer de toolchains iOS en local.

<div id="fluxo-de-desenvolvimento">
  ## Flux de développement
</div>

Il existe trois étapes pour accéder à votre application, chacune avec des publics et des capacités différents :

| Étape             | Qui peut y accéder    | Comment y accéder                                            | Idéal pour                                              |
| ----------------- | --------------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| **Développement** | Vous                  | Simulateur du Project Editor, ou QR code pour Expo Go        | Construire et itérer                                    |
| **Déploiement**   | Testeurs avec Expo Go | URL publique avec QR code                                    | Aperçus de développement, prototypage et démonstrations |
| **App Store**     | Tout le monde         | Téléchargement depuis l&#39;App Store après l&#39;App Review | Lancement en production                                 |

**Développement** : lorsque vous démarrez votre application, vous pouvez la visualiser dans l&#39;**iOS Simulator** ou l&#39;**Android Emulator** du Project Editor, ou scanner un QR code dans le panneau d&#39;aperçu pour l&#39;ouvrir dans Expo Go sur votre téléphone.

**Déploiement** : lorsque vous cliquez sur **Publish**, Replit crée une URL publique avec un QR code pour Expo Go. C&#39;est la solution idéale pour les aperçus de développement et le prototypage : montrez votre application à des investisseurs, recueillez des retours ou faites-la tester par des amis avant de vous lancer dans le processus de l&#39;App Store.

**App Store** : lorsque vous soumettez votre application à l&#39;App Store, Apple l&#39;examine. Une fois approuvée, tout le monde peut la télécharger et l&#39;installer depuis l&#39;App Store. Cette étape nécessite un compte Apple Developer.

<div id="viso-geral-da-publicao">
  ## Aperçu de la publication
</div>

Lorsque vous préparez un lancement sur iOS, le processus se déroule généralement ainsi :

* Publier depuis le Project Editor
* Envoyer un build vers TestFlight
* Promouvoir un build de TestFlight vers l&#39;App Store dans App Store Connect

<Note>
  Pour envoyer des builds vers TestFlight et l&#39;App Store, Apple exige un abonnement à l&#39;Apple Developer Program.
</Note>

Pour une procédure détaillée, consultez le tutoriel [Créer et lancer une application mobile](/fr/pt/build/mobile-app).

<div id="onde-construir-aplicativos-mobile-nativos">
  ## Où créer des applications mobiles natives
</div>

Votre environnement Replit s&#39;exécute dans le cloud, et non sur votre machine locale. Pour créer une application mobile native, utilisez le Project Editor sur [replit.com](https://replit.com). Tout le flux de travail des applications mobiles — création par l&#39;Agent, aperçus dans Expo Go, tests sur simulateur et émulateur, builds TestFlight et soumission à l&#39;App Store — se déroule dans le Project Editor.

Le travail sur les applications mobiles natives est également possible depuis l&#39;[application Android de Replit](/fr/pt/features/platforms/mobile-app), là où elle est prise en charge. Si vous utilisez l&#39;application iOS de Replit, ouvrez le projet sur [replit.com](https://replit.com) pour créer, prévisualiser, compiler ou soumettre des applications mobiles natives.

  ### La pile technologique
</div>

<MobileStackDiagram />

* **React Native** est un framework open source qui permet d&#39;écrire une seule base de code et de la compiler pour iOS, Android et le web. Il affiche des composants d&#39;interface natifs de la plateforme, et non une webview.
* **Expo** simplifie le développement React Native en prenant en charge les builds, en gérant les modules natifs et en fournissant des outils comme Expo Go pour les aperçus.
* **Expo Go** est une application gratuite que vous installez sur votre téléphone. Elle exécute votre aperçu de développement afin que vous puissiez tester sur un appareil réel sans avoir à générer un binaire natif complet.

Lorsque vous exécutez votre application, le bundler Metro compile votre code et l&#39;envoie à votre appareil. Le premier build est plus long, faute de cache. Les builds suivants sont plus rapides.

<div id="arquitetura-servidor-e-cliente">
  ### Architecture : serveur et client
</div>

Lorsque vous préparez une application mobile pour l&#39;aperçu ou la distribution, vous manipulez deux éléments :

1. **Un serveur** qui s&#39;exécute sur Replit, dans le cloud. Il gère votre base de données, les routes d&#39;API, les intégrations d&#39;IA et la logique backend.
2. **Une application cliente** qui s&#39;exécute sur le téléphone de l&#39;utilisateur. Il s&#39;agit de l&#39;application native que vous prévisualisez dans Expo Go pendant le développement, puis distribuée via les boutiques d&#39;applications après validation.

<MobileArchitectureDiagram />

Cette séparation apporte de la souplesse. Vous pouvez exécuter la logique complexe côté serveur (où vous avez accès à Database, à Object Storage et aux Connectors de Replit) et garder le client léger. Au fil du développement, demandez-vous ce qui doit se passer sur le téléphone et ce qui doit se passer dans le cloud.

<div id="consideraes">
  ## Points à considérer
</div>

* **Exigences de publication** : Apple définit les exigences pour TestFlight et l&#39;App Store, et examine les applications iOS avant leur distribution.
* **Publication sur Android** : vous pouvez créer des applications multiplateformes pour iOS et Android. La publication sur Google Play ne bénéficie pas encore d&#39;une expérience guidée, mais elle peut se faire manuellement.
* **Modifications natives** : les modifications telles que les icônes de l&#39;application ou les autorisations nécessitent généralement un nouveau build destiné à la boutique.

<div id="perguntas-frequentes">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Qu'est-ce qu'Expo ?">
    Expo est l&#39;outil qu&#39;utilise Agent pour créer votre application mobile dans Replit. Il s&#39;agit d&#39;une plateforme et d&#39;une chaîne d&#39;outils open source permettant de créer, exécuter et déployer des applications natives multiplateformes avec React Native. Pour en savoir plus, consultez [https://expo.dev](https://expo.dev).
  </Accordion>

  <Accordion title="Qu'est-ce que React Native ?">
    React Native est un framework open source de Meta permettant de créer des applications iOS et Android natives avec React et JavaScript ou TypeScript. Il affiche des composants d&#39;interface natifs de la plateforme (et non une webview) : votre application a donc l&#39;apparence et le comportement d&#39;une application native.
  </Accordion>

  <Accordion title="Qu'est-ce qu'Expo Go ?">
    Expo Go est une application gratuite que vous installez sur votre téléphone depuis l&#39;App Store ou Google Play. Elle vous permet de prévisualiser votre application mobile pendant le développement, sans avoir à créer un binaire natif complet. Lorsque vous scannez le QR code dans le Project Editor, Expo Go télécharge et exécute le code de votre application.
  </Accordion>

  <Accordion title="Quelle est la différence entre Expo Go et un dev build ?">
    **Expo Go** est une application préconstruite qui exécute votre code. Sa configuration est rapide, mais elle ne prend en charge que les modules inclus dans le SDK Expo.

    Les **dev builds** sont des binaires natifs personnalisés qui peuvent inclure n&#39;importe quel module natif. Ils demandent davantage de configuration (EAS Build ou Xcode/Android Studio en local), mais offrent plus de souplesse.

    Replit utilise Expo Go pour les aperçus de développement. Si vous avez besoin de modules natifs non pris en charge par Expo Go, vous devrez peut-être vous tourner vers les dev builds en suivant la [documentation Expo](https://docs.expo.dev/develop/development-builds/introduction/).
  </Accordion>

  <Accordion title="Quelle est la différence avec une application web responsive pour mobile ?">
    Une application web responsive pour mobile est un site qui adapte sa mise en page dans le navigateur. Une application React Native est une application native installée sur l&#39;appareil : elle utilise les API de la plateforme (caméra, retour haptique, notifications push), offre un meilleur accès au matériel et aux fonctionnalités hors ligne, et se distribue via les boutiques d&#39;applications. Le web responsive est idéal pour la portée et l&#39;absence d&#39;installation ; le natif s&#39;impose lorsque vous avez besoin des fonctionnalités de l&#39;appareil, de performances ou d&#39;une distribution sur l&#39;App Store.
  </Accordion>

  <Accordion title="Ai-je besoin d'un Mac ou de Xcode ?">
    Non. Replit et Expo gèrent le processus de build pour vous dans le cloud.
  </Accordion>

  <Accordion title="Puis-je prévisualiser sans compte Apple Developer ?">
    Oui. Vous pouvez prévisualiser dans l&#39;iOS Simulator du Project Editor ou avec Expo Go sur votre téléphone. Un compte Apple Developer n&#39;est nécessaire que lorsque vous êtes prêt à publier sur TestFlight ou l&#39;App Store.
  </Accordion>

  <Accordion title="Android est-il pris en charge ?">
    Oui. Vous pouvez créer des applications multiplateformes pour iOS et Android à partir de la même base de code. Prévisualisez dans un Android Emulator du Project Editor ou sur un appareil Android avec Expo Go. La publication sur Google Play peut se faire manuellement.
  </Accordion>

  <Accordion title="Qu'en est-il des serveurs et des bases de données ?">
    Utilisez le PostgreSQL intégré de Replit, l&#39;Object Storage, les Connectors et les intégrations d&#39;IA — aucune infrastructure distincte n&#39;est nécessaire. Votre serveur s&#39;exécute sur Replit et votre application mobile s&#39;y connecte.
  </Accordion>

  <Accordion title="Dois-je tester dans le simulateur du Project Editor ou sur un vrai téléphone ?">
    Utilisez les deux, à des moments différents. L&#39;**iOS Simulator** et l&#39;**Android Emulator** du Project Editor affichent la version native de votre application et couvrent l&#39;essentiel des tests quotidiens : mise en page, navigation, composants natifs et style propre à la plateforme. Passez à un vrai téléphone avec **Expo Go** lorsque vous devez tester des fonctionnalités qui dépendent du matériel réel, comme la caméra, le retour haptique, les notifications push ou la localisation GPS.
  </Accordion>
</AccordionGroup>
