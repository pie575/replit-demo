⏰ *Durée : 10 minutes*

À la fin de ce guide, vous disposerez d’une petite application publiée et accessible via une URL partageable.

<Frame>
  <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="Le modèle sélectionné transformé en site web et ouvert via une URL Replit publiée" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
</Frame>

Partez d’un modèle soigné, transformez-le en site web fonctionnel, puis publiez-le. Les modèles disponibles peuvent évoluer : choisissez celui qui correspond à ce que vous souhaitez créer.

<div id="section">
  ## Avant de commencer
</div>

Vous avez besoin d&#39;un [compte Replit](https://replit.com). Pour créer une application à partir d&#39;une frame Design, vous avez besoin d&#39;un forfait Core ou Pro. Pour en savoir plus, consultez [Créer votre design](/fr/ja/design/build-your-design) et la [facturation](/fr/ja/billing/ai-billing).

L&#39;objectif est de réaliser un cycle complet :

* choisissez un modèle dans [Replit Design](https://replit.com/design),
* transformez-le en application avec [Agent](/fr/ja/features/agent/overview),
* testez l&#39;application,
* publiez-la et partagez-la.

Agent est l&#39;assistant IA de Replit pour créer des applications. Décrivez ce que vous souhaitez créer, et Agent vous aide à créer, expliquer et modifier votre application.

<div id="section-2">
  ## Choisir un modèle, créer et publier
</div>

<Steps>
  <Step title="Parcourir les modèles de conception">
    Ouvrez [replit.com/design](https://replit.com/design). Parcourez les modèles à la une ou filtrez-les par type, par exemple **Landing Pages**, **Mobile** ou **Prototypes**.

    <Frame>
      <img src="/assets/mirror/01-design-gallery-5303cf1cf6d2.jpg" alt="Galerie Replit Design affichant des modèles à la une et des filtres par type" width="1280" height="720" data-path="images/first-app-template/01-design-gallery.jpg" />
    </Frame>
  </Step>

  <Step title="Prévisualiser et utiliser un modèle">
    Sélectionnez un template pour l’examiner, puis cliquez sur **Utiliser le template**. Replit crée un projet et place le template sur le Canvas de Design. Si vous avez commencé depuis la page de présentation d’un template, consultez [Commencer avec un template](/fr/ja/design/start-from-a-template) pour découvrir le processus de remix.

    <Frame>
      <img src="/assets/mirror/02-template-preview-facda2e40956.jpg" alt="Aperçu d’un template Replit Design avec le bouton Utiliser le template" width="1280" height="720" data-path="images/first-app-template/02-template-preview.jpg" />
    </Frame>

    Le template remixé s’ouvre sur le Canvas de Design du nouveau projet.

    <Frame>
      <img src="/assets/mirror/03-remixed-design-35b051544510.jpg" alt="Template sélectionné et remixé sur le Canvas de Design d’un nouveau projet Replit" width="1280" height="720" data-path="images/first-app-template/03-remixed-design.jpg" />
    </Frame>
  </Step>

  <Step title="Transformez votre design en site web">
    Les modèles commencent par une maquette dans Design. Avant de publier, passez à **Build** et demandez à Agent de transformer le Design sélectionné en site web fonctionnel. Par exemple :

    > Transformez ce modèle sélectionné en site web fonctionnel. Conservez le design visuel et assurez le bon fonctionnement de la navigation et des actions de contact.

    Agent crée un artefact de site web dans le même projet, à partir du Design sélectionné.

    <Note>
      Le bouton **Publier** s’affiche également dans Design. Si votre projet ne contient qu’une maquette dans Design, Publishing indique qu’il n’y a encore rien à déployer et vous invite à demander à Agent de créer l’application. Une fois l’artefact de site web créé, vous pouvez le publier depuis Design ou Build.
    </Note>

    <Frame>
      <img src="/assets/mirror/04-build-request-d5a5a3428361.jpg" alt="Espace de travail Build avec un Design de portfolio sélectionné joint, demande de Build dans le chat Agent et Publishing expliquant qu’un projet contenant uniquement un Design n’a encore rien à déployer" width="1280" height="720" data-path="images/first-app-template/04-build-request.jpg" />
    </Frame>
  </Step>

  <Step title="Vérifier le bon fonctionnement de l’application dans Preview">
    Une fois qu’Agent a terminé, ouvrez la [Preview](/fr/ja/features/editor/preview) et testez votre application comme le ferait un visiteur. La Preview vous permet de tester votre application en cours de développement avant de la publier.

    Vérifiez les points suivants :

    * Vous pouvez naviguer dans le menu principal.
    * Vous pouvez utiliser les boutons et les formulaires du template.
    * Des messages clairs de réussite ou de validation s’affichent après vos actions.
    * Le site reste utilisable après avoir actualisé la page.
    * Vous pouvez redimensionner la Preview à la largeur d’un téléphone.

    Si quelque chose ne fonctionne pas, décrivez le problème à Agent. Vous n’avez pas besoin de diagnostiquer le code vous-même.

    <Frame>
      <img src="/assets/mirror/05-preview-d5702e9d9ac8.jpg" alt="Site web basé sur un template en cours d’exécution dans la Preview de l’éditeur de projet" width="1280" height="720" data-path="images/first-app-template/05-preview.jpg" />
    </Frame>

    <Tip>
      Vous souhaitez explorer des variantes visuelles avant de publier ? Consultez [Explorer les suggestions](/fr/ja/design/explore-suggestions) pour générer plusieurs apparences alternatives côte à côte et appliquer celle que vous préférez.
    </Tip>
  </Step>

  <Step title="Publier une application">
    Lorsque Preview fonctionne correctement, sélectionnez **Publier**. Vérifiez le sous-domaine généré, choisissez qui peut accéder à votre application et vérifiez les paramètres de sécurité. Sélectionnez ensuite **Publier** dans la boîte de dialogue.

    La publication crée une version publique de votre application, accessible via une URL que vous pouvez partager.

    <Frame>
      <img src="/assets/mirror/06-publish-dialog-2f79654c6dfb.jpg" alt="Boîte de dialogue Publier affichant le sous-domaine généré, les paramètres d’accès et le bouton Publier" width="1280" height="720" data-path="images/first-app-template/06-publish-dialog.jpg" />
    </Frame>
  </Step>

  <Step title="Ouvrir l’application publiée">
    Ouvrez l’URL publique dans un nouvel onglet du navigateur et répétez les mêmes vérifications. Avant de la partager, assurez-vous que l’application fonctionne également en dehors de l’éditeur de projet.

    Si l’application publiée se comporte différemment de Preview, vérifiez les logs de publication et les paramètres de production requis par l’application. Pour connaître les problèmes de publication courants, consultez le [guide de dépannage de la publication](/fr/ja/build/troubleshooting).

    <Frame>
      <img src="/assets/mirror/07-published-site-8fe719004e5a.jpg" alt="Site web finalisé basé sur un template, ouvert à l’aide d’une URL Replit publiée" width="1274" height="717" data-path="images/first-app-template/07-published-site.jpg" />
    </Frame>
  </Step>
</Steps>

<div id="section-3">
  ## 🎉 Félicitations — vous avez publié votre première application
</div>

Vous êtes parti d’un modèle de design pour créer une URL en direct que vous pouvez partager. Au cours du processus :

* Vous avez sélectionné et remixé un modèle dans Replit Design.
* Vous avez demandé à Agent de transformer le design sélectionné en site web fonctionnel.
* Vous avez testé le résultat dans Preview.
* Vous avez publié l’application et l’avez ouverte via son URL publique.

C’est le workflow complet de Replit — choisir un point de départ, créer, tester, améliorer et publier.
