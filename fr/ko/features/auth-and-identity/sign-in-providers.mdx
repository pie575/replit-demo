---
title: "Fournisseurs de connexion"
description: "Découvrez comment configurer des identifiants OAuth personnalisés pour la connexion avec Google, GitHub, Apple et X dans les applications utilisant Clerk Auth."
---

Lorsque votre application utilise [Clerk Auth](/fr/ko/features/auth-and-identity/clerk-auth), les visiteurs peuvent se connecter via un fournisseur social. Replit fournit des identifiants partagés par défaut. Cette page explique comment obtenir **vos propres** identifiants OAuth pour chaque fournisseur, afin d&#39;afficher le nom et l&#39;identité visuelle de votre application sur l&#39;écran de connexion.

Le processus est identique pour tous les fournisseurs : créez une application OAuth dans la console du fournisseur, copiez les URL affichées par Replit, puis collez les identifiants générés dans le panneau d&#39;édition du fournisseur.

<Note>
  Les identifiants OAuth personnalisés ne sont disponibles que dans l&#39;environnement **Production** : vous devez donc d&#39;abord [publier](/fr/ko/features/publishing/overview) votre application. Le panneau d&#39;édition de chaque fournisseur s&#39;ouvre depuis l&#39;outil **Users &amp; Auth** : dans l&#39;onglet **Configure**, section **SSO providers**, sélectionnez l&#39;environnement **Production**, puis cliquez sur **Edit** à côté du fournisseur. Pour le processus complet, consultez [Configurer les identifiants OAuth d&#39;un fournisseur SSO](/fr/ko/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
</Note>

<div id="google">
  ## Google
</div>

Ce guide vous explique comment créer une application OAuth Google dans Google Cloud Console. Vous y récupérerez le **Client ID** et le **Client Secret**, puis configurerez les origines JavaScript et l’URI de redirection exigées par Clerk.

Prérequis : disposer d’un accès à [Google Cloud Console](https://console.cloud.google.com/).

<div id="1-google-oauth">
  ### Étape 1 : créer une application OAuth Google
</div>

Rendez-vous sur la [Google Cloud Console](https://console.cloud.google.com/).

<div id="section">
  #### Créer ou sélectionner un projet
</div>

1. Dans le menu déroulant des projets, sélectionnez un projet existant ou créez-en un nouveau
2. Vous êtes redirigé vers le Dashboard du projet

<div id="oauth">
  #### Configurer l&#39;écran de consentement OAuth
</div>

1. Dans la barre latérale gauche, sélectionnez l&#39;icône de menu (≡), puis **APIs &amp; Services**
2. Sélectionnez **OAuth consent screen**
3. Configurez l&#39;écran de consentement de l&#39;application avec les informations requises
4. Enregistrez les modifications

<div id="oauth-2">
  #### Créer des identifiants OAuth
</div>

1. Dans **APIs &amp; Services**, sélectionnez **Credentials**
2. En haut, sélectionnez **Create Credentials**, puis **OAuth client ID**
3. Choisissez **Web application** comme type d&#39;application
4. Renseignez **Authorized JavaScript origins** et **Authorized redirect URIs** avec les valeurs exactes affichées dans **Configuration du fournisseur**, dans le **panneau Auth**. Ajoutez toutes les valeurs listées — elles comprennent à la fois le domaine publié et le domaine personnalisé. Pour savoir où trouver ces valeurs, consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/ko/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Sélectionnez **Create**
6. Enregistrez le **Client ID** et le **Client Secret**

<Warning>
  Conservez le Client Secret en lieu sûr et ne le committez jamais dans un système de gestion de versions.
</Warning>

<Warning>
  La connexion Google ne fonctionne pas dans les navigateurs intégrés ni dans les webviews in-app. Les utilisateurs doivent passer par un navigateur web standard.
</Warning>

<div id="section-2">
  ### Dépannage
</div>

<div id="redirect-uri-mismatch">
  #### Redirect URI mismatch
</div>

* Vérifiez que l’URI de redirection dans Google Cloud Console correspond exactement à la valeur affichée dans **Configuration du fournisseur** du **panneau Auth**
* Vérifiez qu’il n’y a pas de barre oblique finale ni de faute de frappe
* Attendez quelques minutes que la configuration Google soit prise en compte

<div id="invalid-client">
  #### Client invalide
</div>

* Vérifiez à nouveau que le Client ID et le Client Secret ont bien été copiés correctement
* Assurez-vous qu&#39;il n&#39;y a pas d&#39;espaces superflus
* Vérifiez que l&#39;écran de consentement OAuth est bien configuré

<div id="section-3">
  #### Ne fonctionne pas sur un domaine personnalisé
</div>

* Ajoutez les entrées de domaine personnalisé affichées dans **Configuration du fournisseur**, au sein du **panneau Auth**, à la fois aux Authorized JavaScript origins et aux Authorized redirect URIs

<div id="github">
  ## GitHub
</div>

Ce guide vous accompagne dans la création d&#39;une application OAuth GitHub depuis les paramètres développeur de GitHub. Vous y récupérerez le **Client ID** et le **Client Secret**, que vous saisirez ensuite dans le **panneau Auth**.

Prérequis : un [compte GitHub](https://github.com).

<div id="1-github-oauth">
  ### Étape 1 : créer une application OAuth GitHub
</div>

1. Rendez-vous dans les [paramètres développeur GitHub](https://github.com/settings/developers)
2. Dans la barre latérale, sélectionnez **OAuth Apps**
3. Sélectionnez **New OAuth App**
4. Saisissez les informations de l&#39;application :

**Application name :**

Saisissez le nom de l&#39;application.

**Homepage URL** et **Authorization callback URL :**

Renseignez ces deux valeurs exactement telles qu&#39;elles apparaissent dans la section **Configuration du fournisseur** du **panneau Auth**. Pour savoir où les trouver, consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/ko/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

5. Sélectionnez **Register application**

<div id="2">
  ### Étape 2 : générer les identifiants client
</div>

1. Sur la page des paramètres de votre application, le **Client ID** s&#39;affiche : copiez-le
2. Sélectionnez **Generate a new client secret**
3. Copiez immédiatement le **Client Secret**

<Warning>
  Conservez le Client Secret en lieu sûr. Vous ne pourrez plus le consulter une fois la page quittée. Si vous le perdez, vous devrez en générer un nouveau.
</Warning>

<div id="section-4">
  ### Dépannage
</div>

<div id="redirect-uri-mismatch-2">
  #### Redirect URI mismatch
</div>

* Vérifiez que l&#39;Authorization callback URL correspond exactement à la valeur affichée dans **Configuration du fournisseur**, dans le **panneau Auth**
* Assurez-vous qu&#39;il n&#39;y a aucune faute de frappe ni de protocole incorrect
* Aucune barre oblique finale ne doit être présente

<div id="invalid-client-2">
  #### Client invalide
</div>

* Vérifiez à nouveau que le Client ID et le Client Secret ont bien été copiés correctement
* Assurez-vous qu&#39;aucun espace superflu ne s&#39;est glissé lors du collage

<div id="section-5">
  #### Ne fonctionne pas avec un domaine personnalisé
</div>

* Mettez à jour l’URL de la page d’accueil et l’URL de rappel d’autorisation avec la valeur du domaine personnalisé indiquée dans **Configuration du fournisseur** du **panneau Auth**

<div id="apple">
  ## Apple
</div>

Ce guide vous accompagne dans la création de l&#39;App ID Apple, du Services ID et de la Private Key nécessaires à Sign in with Apple. Vous allez recueillir le **Team ID**, le **Services ID**, le **Key ID** et la **Private Key**, puis les saisir dans le **panneau Auth**.

Prérequis : un [compte Apple Developer](https://developer.apple.com/account) (l&#39;inscription à l&#39;Apple Developer Program est requise).

<div id="1-apple-app-id">
  ### Étape 1 : créer un App ID Apple
</div>

1. Rendez-vous sur le [portail Apple Developer](https://developer.apple.com/account)
2. Accédez à **Certificates, IDs &amp; Profiles**, puis sélectionnez **Identifiers**
3. Sélectionnez **App IDs** dans la liste déroulante
4. Sélectionnez l&#39;icône **+** pour enregistrer un nouvel identifiant
5. Sélectionnez **App IDs**, puis **Continue**
6. Sélectionnez **App**, puis **Continue**
7. Renseignez les champs suivants :
   * **Description** : le nom de l&#39;App ID
   * **Bundle ID** : un identifiant unique
8. Dans Capabilities, activez **Sign In with Apple**
9. Sélectionnez **Continue**, puis **Register**
10. **Notez l&#39;App ID Prefix** (affiché en haut) : il s&#39;agit de votre **Team ID**

<div id="2-apple-services-id">
  ### Étape 2 : créer un Services ID Apple
</div>

1. Sur la page Identifiers, sélectionnez **Services IDs** dans le menu déroulant
2. Sélectionnez **+** pour enregistrer un nouvel identifiant
3. Sélectionnez **Services IDs**, puis **Continue**
4. Renseignez les champs suivants :
   * **Description** : le nom du Services ID
   * **Identifier** : un identifiant unique (conservez-le, car il s&#39;agit de votre **Services ID**)
5. Sélectionnez **Continue**, puis **Register**

<div id="services-id">
  #### Configurer le Services ID
</div>

1. Sélectionnez le Services ID que vous venez de créer
2. Activez **Sign In with Apple**
3. Sélectionnez **Configure**
4. Renseignez les éléments suivants :

   * **Primary App ID** : sélectionnez l&#39;App ID créé à l&#39;étape 1
   * **Domains and Subdomains** : copiez la valeur affichée dans **Configuration du fournisseur**, dans le **panneau Auth** (sans le préfixe de protocole `https://`)
   * **Return URLs** : copiez la valeur affichée dans **Configuration du fournisseur**, dans le **panneau Auth**

   Pour savoir où trouver ces valeurs, consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/ko/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).
5. Sélectionnez **Next**, puis **Done**, **Continue** et **Save**, dans cet ordre

<div id="3-apple-private-key">
  ### Étape 3 : créer une Private Key Apple
</div>

1. Dans la barre latérale du portail Apple Developer, sélectionnez **Keys**
2. Sélectionnez **+** pour enregistrer une nouvelle clé
3. Saisissez un **Key Name**
4. Activez **Sign In with Apple**
5. Sélectionnez **Configure**, puis choisissez l&#39;App ID créé à l&#39;étape 1
6. Sélectionnez **Save**, puis **Continue** et enfin **Register**
7. **Conservez le Key ID**
8. **Téléchargez** le fichier de clé privée (.p8)

<Warning>
  La clé privée ne peut être téléchargée qu&#39;une seule fois. Conservez-la en lieu sûr — il sera impossible de la télécharger à nouveau.
</Warning>

<div id="4-apple-private-email-relay">
  ### Étape 4 : configurer Apple Private Email Relay
</div>

La fonctionnalité Hide My Email d&#39;Apple permet aux utilisateurs de se connecter sans divulguer leur véritable adresse e-mail. Pour envoyer des e-mails à ces utilisateurs, vous devez enregistrer une source d&#39;e-mail.

1. Dans la barre latérale du portail Apple Developer, sélectionnez **Services**
2. Sous **Sign in with Apple for Email Communication**, sélectionnez **Configure**
3. Sélectionnez **+** pour ajouter une Email Source
4. Saisissez la valeur Email Source affichée dans **Configuration du fournisseur**, dans le **panneau Auth**
5. Sélectionnez **Next**, puis **Register** et enfin **Done**
6. Attendez la vérification DNS (icône de coche verte)

<Info>
  Dans certaines régions (Chine, Inde), l&#39;identifiant Apple peut être associé à un numéro de téléphone plutôt qu&#39;à une adresse e-mail. Si votre application exige une adresse e-mail pour tous les utilisateurs, Sign in with Apple risque d&#39;échouer pour les utilisateurs de ces régions.
</Info>

<div id="section-6">
  ### Dépannage
</div>

<div id="invalid-client-3">
  #### Client invalide
</div>

* Vérifiez que toutes les informations d&#39;identification ont été saisies correctement
* Vérifiez que la clé privée contient bien les lignes BEGIN et END
* Vérifiez que le Services ID est correctement configuré

<div id="invalid-redirect-uri">
  #### Invalid redirect URI
</div>

* Vérifiez que l&#39;URL de retour (Return URL) configurée dans votre Services ID Apple correspond exactement à la valeur affichée dans **Configuration du fournisseur**, au sein du **panneau Auth**
* Vérifiez que le domaine renseigné dans Domains and Subdomains correspond à votre domaine publié (sans `https://`)

<div id="section-7">
  #### Le relais d’e-mails ne fonctionne pas
</div>

* Vérifiez qu’une coche verte apparaît à côté de Email Source dans le portail Apple Developer
* Si vous l’avez ajouté récemment, attendez la propagation des DNS

<div id="section-8">
  #### Ne fonctionne pas sur un domaine personnalisé
</div>

* Ajoutez le domaine personnalisé indiqué dans **Configuration du fournisseur** du **panneau Auth** aux champs Domains and Subdomains (sans `https://`) et Return URLs

<div id="section-9">
  ### Ressources supplémentaires
</div>

* [Guide du service Private Email Relay](https://developer.apple.com/help/account/configure-app-capabilities/configure-private-email-relay-service)

<div id="x-twitter">
  ## X (Twitter)
</div>

Ce guide vous explique comment créer une application OAuth X dans le portail développeur X. Vous récupérerez le **Client ID** et le **Client Secret** pour les saisir dans le **panneau Auth**.

Prérequis : un [compte développeur X](https://developer.twitter.com/) (offre gratuite disponible).

<div id="1-x-developer">
  ### Étape 1 : Configurer l’application développeur X
</div>

<div id="section-10">
  #### Créer un compte développeur (si nécessaire)
</div>

1. Accédez au [portail développeur X](https://developer.twitter.com/en/portal/dashboard)
2. Si vous n’avez pas de compte développeur, faites-en la demande
3. Remplissez le formulaire de demande en décrivant votre cas d’utilisation

<div id="section-11">
  #### Créer ou sélectionner une application
</div>

1. Accédez à **Projects &amp; Apps** dans le portail développeur de X
2. Utilisez une application existante ou sélectionnez **Add App**
3. Saisissez le nom de l’application, puis sélectionnez **Next**
4. Sélectionnez **App settings**

<div id="2-2">
  ### Étape 2 : Configurer l’authentification
</div>

1. Faites défiler jusqu’à **User authentication settings**
2. Sélectionnez **Set up**

**App permissions :**

Sélectionnez le niveau d’autorisation minimal.

* **Read** - requis pour le profil utilisateur (exigence minimale)
* **Write** - requis pour publier au nom de l’utilisateur (facultatif)
* **Direct Messages** - requis pour accéder aux messages privés (facultatif)

<Warning>
  Les autorisations doivent correspondre aux scopes demandés. Si votre application demande `tweet.write` mais que seule l’autorisation Read est activée, l’authentification échouera.
</Warning>

**Type of app :**

Sélectionnez **Web App, Automated App or Bot**

**App info :**

* **Callback URI / Redirect URL** : copiez la valeur affichée dans **Configuration du fournisseur** du **panneau Auth**
* **Website URL** : copiez la valeur affichée dans **Configuration du fournisseur** du **panneau Auth**

Pour savoir comment trouver ces valeurs, consultez [Configurer les identifiants OAuth pour un fournisseur SSO](/fr/ko/features/auth-and-identity/clerk-auth#configuring-oauth-credentials-for-an-sso-provider).

3. Sélectionnez **Save**
4. **Enregistrez le Client ID et le Client Secret**

<Warning>
  Conservez votre Client Secret en lieu sûr. Si vous le perdez, sa régénération invalidera la valeur existante.
</Warning>

<div id="section-12">
  ### Résolution des problèmes
</div>

<div id="redirect-uri-mismatch-3">
  #### Redirect URI mismatch
</div>

* Vérifiez que l’URI de rappel correspond exactement à la valeur affichée dans **Configuration du fournisseur** du **panneau Auth**
* Vérifiez l’absence de fautes de frappe ou de protocole incorrect
* Vérifiez qu’il n’y a pas de barre oblique finale

<div id="invalid-client-4">
  #### client invalide
</div>

* Vérifiez de nouveau le Client ID et le Client Secret
* Vérifiez qu&#39;il n&#39;y a pas d&#39;espaces superflus
* Vérifiez que vous utilisez des identifiants OAuth 2.0, et non OAuth 1.0a

<div id="scopepermission">
  #### Erreur de scope/d&#39;autorisation
</div>

* Vérifiez que les scopes correspondent aux autorisations activées dans le portail développeur X
* Vérifiez qu&#39;au moins l&#39;autorisation Read est activée

<div id="section-13">
  #### Applications en mode développement
</div>

* Les applications X démarrent en mode développement avec un nombre limité d’utilisateurs.
* Pour une utilisation en production, vous devrez peut-être demander des autorisations d’accès étendues.

<div id="section-14">
  #### Ne fonctionne pas avec un domaine personnalisé
</div>

* Remplacez l’URL du site web et l’URI de rappel par la valeur du domaine personnalisé affichée dans **Configuration du fournisseur** du **panneau Auth**
