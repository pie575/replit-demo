Les Autoscale Deployments s&#39;exécutent sur des ressources de calcul cloud dont la capacité augmente ou diminue automatiquement afin de gérer efficacement le trafic réseau et la charge de travail de votre Replit App. Lorsque votre app est sollicitée, la mise à l&#39;échelle automatique ajoute des serveurs pour gérer la charge. Lorsqu&#39;elle est inactive, elle réduit le nombre de serveurs jusqu&#39;à zéro afin de réduire les coûts.

Les Autoscale Deployments sont idéaux dans les cas suivants :

* Applications web confrontées à des charges de travail et à un trafic variables, comme les sites d&#39;e-commerce
* API et services

<div id="recursos">
  ## Ressources
</div>

Les Autoscale Deployments incluent les fonctionnalités suivantes :

* **Mise à l’échelle automatique des ressources** : ajuste automatiquement les ressources en fonction du trafic afin d’optimiser les coûts.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez une URL `<nome-do-app>.replit.app` pour accéder à votre App.
* **Limites configurables** : définissez le nombre maximal d’instances auxquelles votre App publiée peut s’adapter.
* **Capacité machine flexible** : choisissez la configuration de processeur et de RAM adaptée aux besoins de votre App.
* **Surveillance** : consultez les journaux et surveillez l’état de votre App publiée.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder à Autoscale Deployment depuis l&#39;outil Publishing du Project Editor.

<Accordion title="Comment accéder à Autoscale Deployment">
  Dans le **Tool dock** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="All tools icon" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Publishing icon" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Autoscale**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="magnifying glass icon" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut pour ouvrir l&#39;outil de recherche

<div id="capacidade-da-mquina">
  ## Puissance de la machine
</div>

Sélectionnez **Edit** pour afficher et définir les options de puissance de la machine. Utilisez les curseurs pour choisir la configuration du CPU et de la RAM de chaque instance de serveur de l&#39;app publiée.

Le coût en **compute units** de cette configuration s&#39;affiche sur la ligne **Total per machine**.
Une compute unit est une unité de mesure des ressources de calcul en nuage, basée sur la configuration mémoire et CPU de la machine.

Pour en savoir plus sur le calcul du coût à partir des Compute Units, consultez [Compute Units](/fr/pt/billing/about-usage-based-billing#2-compute-units).

<div id="nmero-mximo-de-mquinas">
  ## Nombre maximal de machines
</div>

Utilisez le curseur pour définir le nombre maximal de machines. Ce nombre correspond au nombre maximal d&#39;instances de serveur que la fonctionnalité de mise à l’échelle automatique peut attribuer lorsqu&#39;elle détermine que votre app est sollicitée.

La ligne du bas affiche les compute units équivalentes, calculées selon la formule suivante :

`Nombre de machines * compute units par machine`
