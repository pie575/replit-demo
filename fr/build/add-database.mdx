Vous avez ajouté la connexion à Velocity dans [Ajouter la connexion](/fr/build/add-login). Mais les voitures de la flotte et les réservations effectuées par les clients disparaissent toujours lorsque la page est actualisée : elles ne sont stockées que dans le navigateur. Ajoutez une base de données pour que tout soit conservé.

<div id="tell-agent-to-save-the-data">
  ## Demandez à Agent d’enregistrer les données
</div>

Pour Velocity, utilisez Neon — la base de données Postgres gérée par Replit. Neon gère parfaitement les réservations simultanées, s’adapte au trafic réel des clients et Agent la provisionne automatiquement dans des environnements développement et Production distincts. Aucune inscription au tableau de bord Neon ni aucune clé à coller n’est nécessaire.

<AiPrompt>
  Enregistre les données de Velocity dans une base de données afin que les voitures, les disponibilités et les réservations ne disparaissent pas lors de l’actualisation.<br />
  Utilise Neon (Postgres).<br />
  Enregistre : chaque voiture (marque, modèle, année, tarif journalier, photo, emplacement), le calendrier de disponibilité de chaque voiture et chaque réservation (date de prise en charge, date de retour, voiture, client).<br />
  Associe chaque réservation au client connecté afin que chaque personne ne voie que les siennes.<br />
  Empêche qu’une même voiture soit réservée à des dates qui se chevauchent.<br />
  Indique-moi ce que je dois tester après la modification.
</AiPrompt>

Agent provisionnera une base de données Neon, y transférera la flotte et les réservations actuellement stockées en mémoire, et ajoutera la vérification des chevauchements afin qu’une même Lamborghini ne puisse pas être réservée deux fois.

<div id="test-that-everything-sticks">
  ## Vérifiez que tout est bien enregistré
</div>

1. Connectez-vous à Velocity dans Preview et réservez une voiture pour samedi prochain.
2. Actualisez la page. La réservation devrait toujours apparaître dans « My bookings ».
3. Redémarrez l’application depuis le Chat Agent. La flotte et la réservation devraient toujours être présentes.
4. Essayez de réserver la même voiture le même samedi avec un deuxième compte. Velocity devrait indiquer que la voiture n’est pas disponible et proposer une autre date ou une autre voiture.
5. Déconnectez-vous, puis reconnectez-vous. Votre réservation devrait toujours être présente.

Si une réservation disparaît à n’importe quelle étape, collez le symptôme exact dans Agent :

<AiPrompt>
  J’ai réservé une voiture dans Velocity, mais la réservation disparaît après l’actualisation.<br />
  Vérifie si la réservation est enregistrée dans la base de données ou si elle est uniquement stockée dans la page.<br />
  Corrige le problème le plus mineur et indique-moi comment le vérifier.
</AiPrompt>

Vous pouvez également demander à Agent une page d’administration simple pour voir le contenu de la base de données :

<AiPrompt>
  Montre-moi une page d’administration simple dans Velocity qui liste chaque voiture et chaque réservation de la base de données, regroupées par voiture.<br />
  Affiche-la uniquement pour moi, en tant que propriétaire du Project.
</AiPrompt>

<div id="publish-and-confirm-on-the-public-url">
  ## Publiez et vérifiez sur l’URL publique
</div>

La configuration Neon d’Agent crée automatiquement pour Velocity des environnements de développement et de production distincts. Publiez à nouveau Velocity depuis le Chat Agent ou la vignette Publishing, puis ouvrez l’URL publique dans un nouvel onglet. Replit associe automatiquement les identifiants Neon de production au déploiement publié : effectuez une réservation sur l’URL publique, actualisez la page et vérifiez qu’elle est toujours présente.

Velocity mémorise désormais chaque voiture, chaque date disponible et chaque réservation. La prochaine actualisation ne fera disparaître aucune réservation.

<div id="need-further-help">
  ## Besoin d&#39;aide supplémentaire ?
</div>

* **Les réservations sont enregistrées dans Preview, mais pas sur l&#39;URL publique :** demandez à Agent de vérifier que les identifiants Neon de production sont bien utilisés dans le déploiement publié.
* **Les données sont difficiles à examiner :** demandez à Agent d&#39;ajouter une vue d&#39;administration simple qui répertorie tout le contenu de la base de données.
* **Vous souhaitez préremplir la flotte :** demandez à Agent d&#39;ajouter un script ponctuel qui importe vos vraies voitures dans la base de données.
* **Vous voulez une base de données sans configuration pour un prototype rapide :** utilisez plutôt [Replit Database](/fr/features/data-and-storage/sql-database) : elle est intégrée à chaque Repl, sans provisionnement distinct.
