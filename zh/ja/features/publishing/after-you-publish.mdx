选择 **Publish** 后，会启动一条简短的流程，将你的应用上线。本页将介绍发布过程中会发生什么、如何更新应用，以及应用上线后在哪里进行管理。

<div id="section">
  ## 发布阶段
</div>

发布过程分为五个阶段，通常需要 1 到 2 分钟。你可以在 Publishing 工具中查看进度条，选择 **View logs** 查看详细信息，或选择 **Cancel** 停止正在进行的发布。

<Frame>
  <img src="/assets/mirror/publishing-stages-dd963be330d5.png" alt="Publishing 概览，显示五阶段进度条：Provision 已完成，Security checks 和 Build 进行中，Bundle 和 Promote 待处理" width="2000" height="465" data-path="images/deployments/publish-pane/publishing-stages.png" />
</Frame>

1. **Provision**：Replit 准备运行应用所需的云资源，例如服务器和生产数据库。
2. **Security checks**：在上线之前，Replit 会扫描不安全的依赖项、泄露的密钥等安全问题。
3. **Build**：Replit 将项目转换为生产版本，即可在 Web 上运行的优化形态。
4. **Bundle**：构建好的应用会被打包成一个可直接运行的整体。
5. **Promote**：Replit 会在当前版本之外准备好新版本，并将 URL 切换到新版本。

<Note>
  发布针对的是整个项目。项目中的所有产物，包括应用、幻灯片、文档等，都会一起发布。
</Note>

<Accordion title="幕后发生了什么">
  面向想了解技术细节的构建者：Provision 会根据所选的部署类型和区域分配部署基础设施。Security checks 会对依赖项和代码进行扫描，根据安全设置的不同，发现严重漏洞时可能会阻止发布。Build 会执行构建命令，并为生产环境编译资源。Bundle 会将构建输出打包为可部署的镜像。Promote 则执行切换：新版本开始在该 URL 上提供服务，替换之前的部署。
</Accordion>

所有阶段完成后，应用即已上线。在 Publishing 工具中选择 URL 即可打开它。

<div id="section-2">
  ## 更新应用
</div>

修改完成后，再次选择 **Publish**。应用会在同一 URL 上更新，访问者下次加载时即可获取最新版本，无需再分享新链接。

<div id="section-3">
  ## 管理已上线的应用
</div>

Publishing 工具也是应用上线后的管理中心：

* **监控状态**：确认应用是否在线、查看日志并检查资源使用情况。详细了解[监控](/zh/ja/features/publishing/monitoring-a-deployment)。
* **查看访客**：请求和流量图表位于[监控](/zh/ja/features/publishing/monitoring-a-deployment)中，访客和用户相关的分析数据则在 **Growth** 面板中。
* **更改访问权限**：停止发布，选择其他访问选项，然后重新发布。详细了解[应用访问](/zh/ja/features/publishing/private-deployments)。
* **连接域名**：为应用设置自定义网址。详细了解[自定义域名](/zh/ja/features/publishing/custom-domains)。
