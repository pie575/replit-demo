Auth — сокращение от **аутентификации (authentication)** — добавляет в приложение понятие &quot;пользователя&quot;. Без Auth все посетители анонимны, и приложение не может отличить одного человека от другого. С Auth каждый посетитель может войти в систему, приложение понимает, кто это, и может хранить данные, относящиеся именно к нему: бронирования, сохранённые автомобили, настройки, прогресс.

После подключения Auth вы можете:

* Хранить данные для каждого пользователя — бронирования, настройки, контент, историю.
* Ограничивать доступ к функциям после входа в систему (платежи, страницы профиля, панели администратора).
* Персонализировать интерфейс на основе имени, роли, тарифа или прошлых действий.
* Отслеживать активность и Usage каждого пользователя, а не только сеансы.

<div id="replit-auth">
  ## Как работает Auth в Replit App
</div>

Replit предлагает два встроенных варианта Auth. Оба предоставляет Agent — не нужно отдельно регистрироваться в панели управления или копировать и вставлять ключи OAuth.

* **[Replit Auth](/ru/ko/features/auth-and-identity/authentication)** — пользователи входят с помощью существующей **учётной записи Replit**. Страница входа оформлена в стиле Replit. Никакая настройка не требуется — достаточно попросить Agent добавить её.
* **[Clerk Auth](/ru/ko/features/auth-and-identity/clerk-auth)** — для приложения создаётся выделенный **тенант Clerk**. Пользователи создают учётные записи в *вашем* приложении, а не в Replit. Вы можете управлять брендингом, способами входа и внешним видом экрана входа.

Оба варианта берут на себя всю сложную работу — страницы входа, сеансы, безопасную обработку паролей, вход через социальные сети — поэтому коду приложения остаётся лишь определить, какой пользователь вошёл в систему.

<div id="replit-auth-vs-clerk-auth">
  ## Replit Auth vs. Clerk Auth
</div>

|                                  | Replit Auth                                                             | Clerk Auth                                                                              |
| -------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **Учётные записи пользователей** | Пользователи входят под своей учётной записью Replit                    | Пользователи создают учётные записи прямо в приложении (учётная запись Replit не нужна) |
| **Брендинг**                     | Страница входа с брендингом Replit                                      | Полностью настраивается — название, значок и цвета вашего приложения                    |
| **Учётные данные SSO**           | Используется общее приложение OAuth от Replit                           | Собственные учётные данные OAuth для каждого провайдера                                 |
| **Окружения**                    | Одно окружение                                                          | Отдельные окружения для разработки и продакшена                                         |
| **Лучше всего подходит для**     | Быстрого запуска, прототипов и приложений, где допустим брендинг Replit | Брендированных приложений, профессиональных и коммерческих продуктов                    |

Если вы создаёте прототип или внутренний инструмент, Replit Auth — самый быстрый путь. Если же вы создаёте продукт с собственным брендом, особенно клиентский или коммерческий, лучше подойдёт Clerk Auth.

<div id="auth">
  ## Добавление Auth в приложение
</div>

Выбирать заранее не обязательно — можно начать с одного варианта, а позже перейти на другой. Быстрее всего просто сказать Agent, что использовать:

* *«Добавь вход в моё приложение. Используй Replit Auth».*
* *«Добавь вход в моё приложение. Используй Clerk Auth».*
