Clerk Auth 由 [Clerk](https://clerk.com) 提供支持，为你的应用提供专属的身份验证系统。[Replit Auth](/zh/pt/features/auth-and-identity/authentication) 使用 Replit 的登录系统并创建 Replit 账户，而 Clerk Auth 则不同，它会为你的应用单独预配一个 **Clerk 租户**。你的应用用户直接在应用内创建账户，而非 Replit 账户，你也可以完全掌控品牌、登录方式和登录体验。

  <video autoPlay muted loop playsInline src="/assets/mirror/auth-vid-e89aaccd245e.mp4" />
</Frame>

<Note>
  **Clerk Auth 与 Replit Auth 的区别** —— 使用 **Clerk Auth** (即本页介绍的方案) 时，你的应用会获得专属的身份验证租户，品牌可完全自定义，用户账户独立于 Replit。使用 **[Replit Auth](/zh/pt/features/auth-and-identity/authentication)** 时，用户以 Replit 账户登录，看到的是带有 Replit 品牌的登录页面。如果你希望登录体验展示自己的品牌，或需要独立于 Replit 的用户账户，请选择 Clerk Auth。
</Note>

<div id="clerk-auth-vs-replit-auth-em-resumo">
  ## Clerk Auth 与 Replit Auth 速览
</div>

|            | Clerk Auth                   | Replit Auth            |
| ---------- | ---------------------------- | ---------------------- |
| **用户账户**   | 用户在你的应用内创建账户 (无需 Replit 账户)  | 用户使用 Replit 账户登录       |
| **品牌形象**   | 完全可自定义——你的应用名称、图标和配色         | 带有 Replit 品牌的登录页面      |
| **SSO 凭据** | 按提供商自带 OAuth 凭据              | 使用 Replit 共享的 OAuth 应用 |
| **环境**     | 开发环境与生产环境相互独立                | 单一环境                   |
| **推荐奖励**   | 不与 Replit 推荐奖励集成             | 注册可计入 Replit 推荐奖励      |
| **适用场景**   | 自有品牌应用、专业/商业产品               | 快速上手、可接受 Replit 品牌的应用  |

<div id="comeando">
  ## 开始使用
</div>

要为你的应用添加 Clerk Auth，请在给 Agent 的 prompt 中说明这一点：

```
帮我创建一个应用，功能是[你的应用创意]，并且需要使用 Clerk Auth。
```

Agent 会全程代劳——创建 Clerk 租户、存储凭据、配置路由并添加中间件。你无需拥有 Clerk 账户，也不需要任何手动配置。

<div id="como-o-clerk-auth-funciona-com-o-replit">
  ## Clerk Auth 如何与 Replit 协同工作
</div>

当 Agent 为你的应用配置 Clerk Auth 时，它会：

1. **创建专用的 Clerk 租户** —— 你的应用会获得独立的 Clerk 应用，并拥有相互隔离的开发环境和生产环境
2. **预置凭据** —— API 密钥和密钥信息以环境变量的形式存储
3. **配置代理** —— 身份验证可在你已发布的域名上无缝运行
4. **设置登录和注册路由** —— 将 Clerk 预构建的 React 组件添加到你的应用中
5. **添加服务端中间件** —— 使用 Clerk 的 Express 中间件保护你的 API 路由

<Note>
  你无需创建 Clerk 账户，也无需管理任何基础设施。这一切都由 Replit 自动为你处理。
</Note>

<div id="capacidades">
  ## 功能特性
</div>

<div id="o-que-suportado">
  ### 支持哪些功能
</div>

Clerk Auth 为你的应用提供：

* **独立的用户账户** —— 你的应用用户不是 Replit 用户；他们仅存在于你应用的 Clerk 租户中
* **完全自有品牌的登录页面** —— 登录和注册页面上的应用名称、logo、配色、字体和文案均在你的应用代码中配置
* **自定义品牌的 SSO** —— 为各个提供方配置你自己的 OAuth 凭证，让提供方的 OAuth 授权页面显示你的应用名称和品牌，而不是通用的默认内容
* **邮箱密码认证** —— 内置注册和登录，并支持邮箱验证
* **社交登录 (SSO)&#x20;**&#x20;—— 让用户使用 Google、GitHub、Apple 或 X (Twitter) 登录
* **用户管理** —— 在 Auth 面板中查看、搜索和管理用户
* **会话管理** —— 自动管理的安全会话令牌
* **开发和生产环境** —— 发布前先在开发环境中测试认证

<Note>
  你可以在项目编辑器的 **Auth** 工具中完成 Clerk Auth 的大部分配置 —— 无需 Clerk 账户，也无需访问 Clerk 面板。
</Note>

<div id="o-que-no-suportado">
  ### 不支持的功能
</div>

以下功能目前在 Clerk Auth 中不可用 (与你自行配置的外部 Clerk 应用相比) 。完整对比请参阅[此常见问题](#how-does-clerk-auth-compare-to-external-clerk)。

* **手机号登录** — 基于短信的登录与验证
* **MFA 支持** — 面向终端用户的多因素认证
* **完整的 SSO 身份提供方支持** — 目前仅支持 Google、GitHub、Apple 和 X
* **组织租户** — Clerk 的组织与团队成员功能

<div id="ambientes-de-desenvolvimento-e-produo">
  ## 开发环境与生产环境
</div>

每个使用 Clerk Auth 的应用都会获得两个完全独立的 Clerk 环境：**开发**环境用于支撑你在构建过程中的开发/预览应用，**生产**环境则用于支撑已发布的应用。这两个环境在设计上就彼此隔离——各自拥有独立的 API 密钥和用户库。

<div id="chaves-de-api-separadas">
  ### 独立的 API 密钥
</div>

每个环境都有各自的可发布密钥 (publishable key) 和私密密钥 (secret key) 。应用所使用的密钥会根据它运行在开发环境还是生产环境自动切换：

* 在你的 workspace 中，`CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY` 这两个 secrets 保存的是指向开发环境的**测试密钥** (`pk_test...` 和 `sk_test...`) 。

<Frame>
  <img src="/assets/mirror/clerk-check-dev-keys-5a23f6b7dd0c.png" alt="Workspace 中的 Secrets 工具，显示带有 sk_test_ 和 pk_test_ 前缀的 CLERK_SECRET_KEY 与 CLERK_PUBLISHABLE_KEY" width="1946" height="402" data-path="images/workspace/auth/clerk-check-dev-keys.png" />
</Frame>

* 当你发布应用后，已发布的部署会使用指向生产环境的**正式密钥** (`pk_live...` 和 `sk_live...`) 运行。要确认前缀，请打开 **Publishing → Overview → Adjust settings**，查看 `CLERK_PUBLISHABLE_KEY` 和 `CLERK_SECRET_KEY`。

<Frame>
  <img src="/assets/mirror/clerk-check-prod-keys-acccd7f68da1.png" alt="Publishing Overview 显示生产环境应用的 secrets，其中 CLERK_SECRET_KEY 与 CLERK_PUBLISHABLE_KEY 使用 sk_live_ 和 pk_live_ 前缀" width="1924" height="1664" data-path="images/workspace/auth/clerk-check-prod-keys.png" />
</Frame>

<Note>
  切换环境无需你做任何操作——Replit 会自动管理开发和生产环境的密钥。你只管开发、测试、发布，其余的都已就绪。
</Note>

<Warning>
  请不要把测试密钥替换成正式密钥，不要在 Secrets 面板中编辑它们，也不要在 Clerk 控制台中手动配置任何内容。这样做会破坏开发/生产环境之间的自动切换，且 Replit 托管的 Clerk Auth 不支持此类操作。
</Warning>

<div id="bases-de-usurios-separadas">
  ### 相互独立的用户库
</div>

每个环境都有各自独立的用户库。在开发环境中注册的账户**不会**存在于生产环境中，反之亦然：

* 在开发/预览应用中测试时注册的用户，只会创建在开发环境的用户库中。
* 在已发布应用中注册的用户，只会创建在生产环境的用户库中。
* 会话、用户元数据，以及你与 Clerk `userId` 关联的任何数据，同样仅限于该账户所在的环境。

这属于预期行为。若要查看各环境中的用户，请在 Workspace 中打开 **Auth 面板**，然后在 **Users** 标签页使用环境切换器在开发环境和生产环境之间切换。

<Note>
  开发环境用于试验和构建，生产环境则面向线上应用的真实用户。两者是有意隔离的，因此在开发环境中创建的账户和数据不会出现在生产环境中。
</Note>

<div id="gerenciando-usurios">
  ## 管理用户
</div>

项目编辑器中的 **Auth 面板**可让你全面了解已认证用户的情况。由于 Clerk Auth 会为你的应用创建独立的用户库，这里列出的用户是你应用中的账户，而非 Replit 账户。

<Frame>
  <img src="/assets/mirror/clerk-users-4940ed365605.png" alt="Clerk Auth 用户选项卡，在 Auth 面板中显示已认证的用户" width="2136" height="794" data-path="images/workspace/auth/clerk-users.png" />
</Frame>

在 **Users** 选项卡中，你可以：

* **查看所有用户**，包括电子邮件、姓名、最后登录时间和账户创建日期等详细信息
* **搜索和筛选**，快速找到特定用户
* **封禁或解封用户**，控制对应用的访问权限
* **排序用户**，按不同条件排列
* **切换环境** — 在开发环境和生产环境之间切换，分别管理各自的用户

<div id="personalizando-sua-pgina-de-login">
  ## 自定义登录页面
</div>

登录和注册页面的视觉品牌元素——应用名称、logo、颜色、字体和文案——在应用代码中配置，而不是在 Auth 面板中。如需修改，可以这样告诉 Agent：

```
更新我的登录页面，用 [你的应用名称] 作为标题，[描述
你的 logo]，并与我网站的配色保持一致。
```

在底层，这由传递给 `<ClerkProvider>` 的 `appearance` 和 `localization` 属性以及应用 `public/` 目录中的 logo 文件控制。Agent 会让这些内容与应用的其余主题保持同步。

<Note>
  在 **Google、Apple、GitHub 或 X 自身的授权同意页面** (用户点击“Sign in with Google”等按钮后出现的页面) 上显示的应用名称是独立的——它来自在该身份提供方处注册的 OAuth 应用，**不会**因编辑登录页面代码而改变。若要修改，请为该身份提供方配置[自定义 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
</Note>

<div id="configurando-provedores-de-login">
  ## 配置登录身份提供方
</div>

Clerk Auth 支持将 Google、GitHub、Apple 和 X 作为社交登录身份提供方。在 Auth 面板的 **Configure** 标签页中，你可以控制哪些身份提供方显示在登录页面上；在生产环境中，还可以决定每个身份提供方是使用 Replit 托管的 OAuth 凭据，还是使用你自己的自定义凭据以实现自有品牌登录。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" alt="Configure 标签页，侧边栏显示 SSO 身份提供方，已选择 Production，身份提供方列表显示启用开关和 Edit 操作" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

打开 **Configure** 标签页。在侧边栏的 **SSO providers** 下，选择 **Development** 或 **Production**——**Development** 用于 Workspace 中的开发/预览应用，**Production** 用于已发布的应用。每个环境在主面板中都有各自的列表。在这里，你可以：

* **启用或禁用某个身份提供方**——使用开关控制该身份提供方是否显示在登录页面上。已禁用的身份提供方对用户不可见。
* **配置自定义 OAuth 凭据 (仅限生产环境)&#x20;**——参见下方的[为 SSO 身份提供方配置 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。

<div id="configurando-credenciais-oauth-para-um-provedor-sso">
  ### 为 SSO 身份提供方配置 OAuth 凭据
</div>

默认情况下，身份提供方使用 **Replit 托管的凭据**——无需任何配置即可完成登录，但 OAuth 授权同意页面显示的是 Replit 的品牌标识。切换到 **Custom credentials**，即可使用你在身份提供方开发者控制台中创建的 OAuth 客户端，让授权同意页面显示你自己应用的名称和品牌。

1. 在项目编辑器中打开 **Auth 面板**。切换到 **Configure** 标签页，然后在侧边栏的 **SSO providers** 下选择 **Production**。

<Frame>
  <img src="/assets/mirror/clerk-configure-60169c473d64.png" width="923" height="378" data-path="images/workspace/auth/clerk-configure.png" />
</Frame>

2. 选择你要配置的身份提供方旁边的 **Edit** 图标。默认选中的是 **Replit-managed credentials**。

<Frame>
  <img src="/assets/mirror/clerk-sso-default-credentials-525090775408.png" alt="身份提供方编辑面板，显示 Replit-managed credentials 和 Custom credentials 选项" width="1468" height="960" data-path="images/workspace/auth/clerk-sso-default-credentials.png" />
</Frame>

3. 选择 **Custom credentials**。面板会展开，显示凭据字段以及一份 **Provider setup** 清单，其中列出了你需要在身份提供方一侧注册的值。

<Frame>
  <img src="/assets/mirror/clerk-sso-custom-credentials-f24112a5cf07.png" alt="自定义凭据面板，显示 OAuth client ID 和 secret 字段，以及包含重定向回调 URL 和 JavaScript 来源的 Provider setup 清单" width="1468" height="2246" data-path="images/workspace/auth/clerk-sso-custom-credentials.png" />
</Frame>

4. 按照说明完成配置。说明中包含指向控制台和相关帮助文档的直达链接。你也可以在[更多资源](#additional-resources)中找到对应身份提供方的这些帮助文档。
5. 填写所有必填的凭据值。
6. 在身份提供方的开发者控制台中，将 **Provider setup** 清单中列出的每一项注册到身份提供方的开发者门户。使用复制图标逐项精确复制各个值，完成一项就勾选一项，也可以在全部完成后选择 **Mark all as done**。
7. 选择 **Save changes**。

<div id="revalidando-a-configurao-aps-alteraes-de-domnio">
  ### 域名变更后重新验证配置
</div>

与域名相关的操作——例如绑定新的外部域名或[通过 Replit 购买域名](/zh/pt/build/domain-purchasing)——可能会更改应用的重定向回调 URL 和 JavaScript 来源。出现这种情况时，凡是使用自定义凭据配置的身份提供方，都可能需要在其开发者控制台中登记新的值。

域名变更后，请返回 **Configure** 选项卡。配置提醒会以警告图标的形式显示在该选项卡、侧边栏中，以及 **SSO providers** 列表中各身份提供方的旁边。若某个身份提供方旁出现警告图标和 **setup steps remaining**，说明该身份提供方的 **Provider setup** 清单中有新的待办项。

<Frame>
  <img src="/assets/mirror/clerk-sso-setup-reminders-a5b092846006.png" alt="Configure 选项卡和侧边栏显示配置警告，域名变更后 SSO providers 列表中某个身份提供方旁显示警告图标和“setup steps remaining”" width="923" height="378" data-path="images/workspace/auth/clerk-sso-setup-reminders.png" />
</Frame>

打开该身份提供方的编辑面板，复制 **Provider setup** 中更新后的值，在该身份提供方的开发者控制台中完成登记，然后选择 **Mark all as done**。

<div id="configurao-de-domnio-para-verificao-de-e-mail">
  ## 邮箱验证的域名配置
</div>

如果你的应用提供**邮箱与密码注册**，Clerk 会向每位新用户的收件箱发送验证码。为邮件发送配置你的域名，可以确保这些验证码从你应用的 URL 发出，避免被垃圾邮件过滤器延迟投递或拦截。

<div id="quando-voc-precisa-dessa-configurao">
  ### 何时需要此配置
</div>

只有当你的应用绑定**由其他服务商管理的外部域名** (例如你在 Cloudflare、GoDaddy、Namecheap 等平台注册的域名) 时，才需要配置 DNS 记录。

如果你的应用通过以下地址提供服务，则无需任何配置：

* `.replit.app` 子域名
* [通过 Replit 购买](/zh/pt/build/domain-purchasing)的域名

这两种情况下，Replit 都会为你管理 DNS 记录。

<div id="adicione-registros-dns-para-o-envio-de-e-mail">
  ### 添加用于发送邮件的 DNS 记录
</div>

要授权你的应用从你的外部域名发送验证邮件，请在你的域名提供商处添加一组 DNS 记录。

1. 在项目编辑器中打开 **Publishing**。
2. 选择 **Domains**。
3. 找到已关联的外部域名，选择 **Manage**。
4. 在 **Authentication DNS setup required** 下，复制 Replit 显示的 CNAME 记录——这些正是 Clerk 从你的域名发送验证邮件所需的记录。
5. 登录你的 DNS 提供商 (Cloudflare、GoDaddy、Namecheap 等) ，严格按照显示的内容逐条添加记录。

<Frame>
  <img src="/assets/mirror/clerk-domain-8797ea9f41fc.png" alt="域名的 Manage 面板，显示 Authentication DNS setup required 部分中用于 Clerk 邮件发送的 CNAME 记录" width="1156" height="1524" data-path="images/workspace/auth/clerk-domain.png" />
</Frame>

DNS 更改最多可能需要 48 小时才能生效。记录生效后，邮箱和密码注册流程会自动从你的域名发送验证码——无需在 Auth 面板中执行任何额外操作。

<div id="soluo-de-problemas">
  ### 故障排除
</div>

* **收不到验证邮件** —— 请确认每条记录都与 Manage 面板中显示的内容完全一致,如果您的 DNS 提供商有要求,还需在末尾加上点号。另请检查收件人的垃圾邮件文件夹。
* **记录仍未被检测到** —— 请等待 DNS 生效(最长 48 小时),然后在 Manage 面板中重新检查仍标记为缺失的记录。

<div id="melhores-prticas-de-segurana">
  ## 安全最佳实践
</div>

* **始终在服务器端校验** —— 在 API 路由中检查身份验证，而不能只在界面上做检查
* **使用环境变量** —— 切勿将密钥或凭据硬编码在代码中
* **让代理中间件保持在最前面** —— 在 Express 应用中，Clerk 代理必须挂载在 body parser 之前
* **不要将首页重定向到登录页** —— 让未登录的访客也能访问你的着陆页

<div id="faq">
  ## 常见问题
</div>

<div id="preciso-de-uma-conta-clerk-para-usar-o-clerk-auth">
  ### 使用 Clerk Auth 需要 Clerk 账户吗？
</div>

不需要。Agent 为你的应用完成配置时，Replit 会自动创建并管理 Clerk Auth 背后的 Clerk 租户——你无需注册 Clerk，也不必自行管理任何 Clerk 基础设施。

<div id="posso-acessar-o-painel-do-clerk-para-a-instncia-clerk-gerenciada-pelo-replit">
  ### 我可以访问 Replit 托管的 Clerk 实例的 Clerk 控制台吗？
</div>

不可以。Replit 托管的 Clerk 实例不会通过 Clerk 控制台开放访问。请在项目编辑器的 **Auth** 工具中进行管理——在那里可以配置身份提供方、查看用户，并在开发环境和生产环境之间切换。

<div id="minha-chave-publicvel-do-clerk-comea-com-pk_test-como-eu-troco-para-uma-chave-ativa">
  ### 我的 Clerk 可发布密钥以 `pk_test` 开头，该如何切换到正式密钥？
</div>

无需切换。你在 workspace 的 Secrets 面板中看到的 `pk_test...` 和 `sk_test...` 密钥属于应用的 Clerk **开发**环境，仅在构建阶段使用。发布应用后，部署会自动使用生产环境的 `pk_live...` 和 `sk_live...` 密钥运行。若要确认，请在 Workspace 中打开 **Publishing → Overview → Adjust settings**，查看已发布应用的 `CLERK_PUBLISHABLE_KEY` 值——它会以 `pk_live` 开头。请勿手动修改这些密钥。完整说明请参阅[开发环境与生产环境](#development-and-production-environments)。

<div id="por-que-no-consigo-fazer-login-no-meu-app-publicado-com-a-conta-que-criei-durante-o-desenvolvimento">
  ### 为什么无法用开发阶段创建的账户登录已发布的应用？
</div>

Clerk Auth 的**开发**环境和**生产**环境各自拥有独立的用户库。你在开发/预览应用中创建的账户仅存在于开发环境，发布时不会被复制到生产环境——你需要在已发布的应用中重新注册。与 Clerk `userId` 关联的任何数据同样如此。在 Workspace 中打开 **Auth 面板**，在 **Users** 标签页使用环境切换器，即可分别查看各环境中的用户。详情请参阅[独立的用户库](#separate-user-stores)。

<div id="o-clerk-auth-gratuito">
  ### Clerk Auth 是免费的吗？
</div>

Clerk Auth 目前免费。后续可能会推出按用量计费的价格方案，与 Replit 其他按用量计费的服务保持一致。未来产生的任何费用都会计入您现有的 Replit 账单——您无需另行准备 Clerk 的账单或支付方式。

<div id="o-clerk-auth-tem-um-limite-de-mau-como-os-planos-externos-do-clerk">
  ### Clerk Auth 是否像 Clerk 的外部套餐一样有 MAU 限制？
</div>

没有。Clerk Auth 不限制月活跃用户数 (MAU) ，而 Clerk 的外部套餐会按套餐层级限制 MAU 数量。

<div id="como-o-clerk-auth-se-compara-ao-clerk-externo">
  ### Clerk Auth 与外部 Clerk 有何区别？
</div>

Clerk Auth 背后是由 Replit 托管的 Clerk 租户，与你在自己的 Clerk 账户中创建的 Clerk 应用 (**外部 Clerk**) 相比有一些不同之处。下表列出了两者目前的差异——这反映的是 Clerk Auth 的当前状态，其支持的功能范围仍会持续演进。

|                | Clerk Auth                       | 外部 Clerk        |
| -------------- | -------------------------------- | --------------- |
| **设置**         | 由 Replit 自动预配                    | 由你自行设置          |
| **Clerk 租户归属** | 由 Replit 托管，归属于你的应用              | 归属于你的 Clerk 账户  |
| **计费模式**       | 当前免费 (未来计划采用按量付费)                | 订阅 + 按量付费       |
| **账单**         | 由 Replit 出账 (当前免费)               | 在你的 Clerk 账户中结算 |
| **月活用户数上限**    | 无限制                              | 按套餐分级限制         |
| **代理与域名配置**    | replit.app 和已购买域名自动完成，已关联域名需手动配置 | 手动              |
| **SSO 身份提供方**    | 支持指定身份提供方：Google、Apple、GitHub、X    | 支持更多身份提供方         |
| **用户管理入口**     | 项目编辑器中的 Auth 工具                  | Clerk 应用控制面板    |
| **短信**         | 不支持                              | 支持              |
| **多因素认证**      | 不支持                              | 支持              |
| **组织租户**       | 不支持                              | 支持              |

<div id="que-configurao-comum-do-clerk-auth-eu-preciso-tratar-manualmente">
  ### 哪些常见的 Clerk Auth 配置需要我手动处理？
</div>

Clerk Auth 的大部分配置都已自动完成，但有些配置需要你在 **Auth** 工具之外进行操作：

* **SSO 身份提供方的自定义 OAuth 凭据** — 如果你希望身份提供方的授权同意页面显示你的应用名称和品牌 (而不是 Replit 的默认信息) ，请在该身份提供方的开发者控制台中注册一个 OAuth 应用，并将凭据粘贴回 Auth 面板。参见[为 SSO 身份提供方配置 OAuth 凭据](#configuring-oauth-credentials-for-an-sso-provider)。
* **外部域名邮件验证所需的 DNS 记录** — 如果你的应用绑定了由其他服务商管理的外部域名，你需要添加 DNS 记录，验证邮件才能从你的域名发出。参见[邮件验证的域名配置](#domain-setup-for-email-verification)。

<div id="posso-usar-meu-prprio-app-clerk-em-vez-do-gerenciado-pelo-replit">
  ### 我可以使用自己的 Clerk 应用，而不用 Replit 托管的应用吗？
</div>

可以。如果你的应用已经预置了 Replit 托管的 Clerk 应用，请先将其删除，再连接你自己的外部 Clerk 应用：

1. 在项目编辑器中打开 **Auth** 面板。
2. 切换到 **Configure** 标签页。
3. 滚动到页面底部，点击 **Delete Clerk app**。

删除 Clerk 应用会移除 Replit 托管的 Clerk 租户，并释放与其绑定的所有域名，之后你就可以连接自己的 Clerk 应用并复用这些域名。如果你的应用尚未配置 Replit 托管的 Clerk 应用，则可跳过这一步，直接集成你的外部 Clerk 应用。
