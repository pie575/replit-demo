上下文是指 AI 模型用来生成下一条回复的信息。上下文管理则是在恰当的时机为模型提供恰当信息的实践。

这一点之所以重要，是因为 AI 无法仅凭你的意图运作，而是依赖上下文窗口中可用的文本、文件、截图、日志、示例以及对话历史。

<div id="section">
  ## 什么是上下文窗口？
</div>

AI 模型一次能处理的信息量是有限的，这个上限就称为上下文窗口。

上下文窗口可以包含以下内容：

* 你的提示词
* 对话中的历史消息
* 模型可以查看的文件或代码
* 错误信息和日志
* 屏幕截图、图片或设计参考
* `replit.md` 等项目说明
* 之前步骤产生的工具执行结果

模型会依据这些上下文来决定接下来生成什么内容。

<div id="section-2">
  ## 上下文窗口为何重要
</div>

如果关键细节不在上下文中，模型可能会靠猜测作答；如果上下文中充斥着无关信息，模型又可能把注意力放错地方。

例如，下面这条提示词几乎没有提供任何上下文：

```text theme={null}
请改进注册页面。
```

这条提示词提供了有用的上下文：

```text theme={null}
请针对正在考虑加入候补名单的首次创业者，改进注册页面。
保持现有字段不变。让表单上方的价值主张更加清晰。
不要改动价格部分。
```

第二个提示词则告诉模型：这个页面面向谁、要改进什么、要保留什么，以及哪些内容不在范围之内。

<div id="section-3">
  ## 上下文窗口大小各不相同
</div>

不同的 AI 模型所能处理的上下文量各不相同。上下文窗口越大，一次能纳入考虑的文本就越多，但并非越大越好。与其把所有细节一股脑塞进对话，不如提供真正相关的上下文，这一点始终更重要。

公开的上下文窗口大小示例：

| 模型系列              | 上下文窗口示例    |
| ----------------- | ---------- |
| GPT-4.1           | 最多 100 万词元 |
| Claude Sonnet 4.5 | 最多 20 万词元  |
| Gemini 2.5 Pro    | 最多 100 万词元 |

这些数字会随时间变化，而且并非所有产品都会公开完整的模型限制。但实用的经验始终不变：让重要信息保持清晰、聚焦。

<div id="section-4">
  ## 上下文类型
</div>

| 上下文类型    | 示例                    |
| -------- | --------------------- |
| **目标**   | “这个落地页需要收集候补名单的注册信息。” |
| **受众**   | “面向忙碌的餐厅老板。”          |
| **约束**   | “请保留当前的配色方案和表单字段。”    |
| **非目标**  | “暂时不要添加支付功能。”         |
| **示例**   | 截图、原型图、示例数据或竞品页面。     |
| **项目状态** | 当前的文件、组件、错误信息或用户流程。   |
| **完成标准** | “访问者可以提交表单并看到感谢提示。”   |

<div id="section-5">
  ## 临时上下文与持久上下文
</div>

有些上下文只属于当前对话。当你请求某项具体修改、调试某个问题，或对最近的结果给出反馈时，就会用到这类上下文。

另一些上下文则应该在整个项目中持续生效。编码风格、品牌规范、命名约定、可复用的产品规则，以及 Agent 需要跨工作会话记住的各种约束，都应放入持久上下文。在 Replit 中，[replit.md](/zh/ja/features/project-setup/replit-dot-md) 就是为 Agent 提供持久项目上下文的一种方式。

<div id="section-6">
  ## 上下文变得嘈杂时
</div>

冗长的对话容易跑题。当一个会话线程中混杂了大量无关的决策时，Agent 可能会关注那些早已不再重要的旧上下文。

出现以下情况时，请开启新的会话线程：

* 切换到不相关的功能时
* 对话中留下了许多被放弃的方向时
* Agent 反复套用过时的约束时
* 你希望针对新领域获得一份清晰的方案时

重新开始时，请先梳理并概括关键上下文，不要默认 Agent 仍然知道哪些内容重要。

```text theme={null}
上下文：本项目是一款面向本地健身教练的候补名单应用。
主要流程为：落地页 → 注册表单 → 确认消息。
在本对话中，请仅优化确认消息和后续跟进文案。
```

<div id="section-7">
  ## 常见误解
</div>

* **“上下文越多越好”** —— 其实是上下文越相关越好。无关内容太多反而会分散模型的注意力。
* **“模型能完美记住一切”** —— AI 会利用现有的上下文，但遇到关键约束时，仍应再次说明。
* **“上下文只能是文本”** —— 截图、文件、数据、设计稿、日志和示例都可以作为上下文。
