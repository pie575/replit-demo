以下解答涵盖 Agent 的使用方法。完整参考资料请查看 [Agent 概述](/zh/ko/features/agent/overview)、[Agent 模式](/zh/ko/features/agent/agent-modes)和 [AI 计费](/zh/ko/billing/ai-billing)。

<AccordionGroup>
  <Accordion title="Agent 停止响应或频繁断开连接，该怎么办？">
    1. 使用 `Cmd+K` (Mac) 或 `Ctrl+K` (Windows) 打开命令面板。
    2. 搜索并选择 **Restart compute**，重启开发环境。
    3. 打开新的 Agent 聊天，重新描述任务以继续。

    当 Agent 看起来卡住时，请不要发送消息。额外的消息会产生相互冲突的指令。如果 Agent 总是卡在同一个任务上，请将该任务拆分成更小、更聚焦的提示词。
  </Accordion>

  <Accordion title="Agent 不断重复相同步骤或陷入循环。如何让它停止？">
    1. 在 Agent 面板中选择**停止**，立即中断。
    2. 按 `Cmd+K` (Mac) 或 `Ctrl+K` (Windows) 打开命令面板，搜索并选择 **Restart compute**。
    3. 打开新的 Agent 聊天，用更具体的表述重新描述任务。

    避免陷入循环的方法：

    * 把大任务拆分成更小的提示词，每条消息只聚焦一个目标。
    * 使用 [Plan 模式](/zh/ko/features/agent/plan-mode)，让 Agent 在构建前先划定任务范围。
    * 在[支出管理](/zh/ko/billing/managing-spend)中设置用量上限，避免因循环产生过高费用。
  </Accordion>

  <Accordion title="如何降低 Agent 费用？哪些设置确实有帮助？">
    以下几项选择带来的影响最大：

    * **[Free 模式](/zh/ko/features/agent/agent-modes)**——面向 Core 和 Pro 订阅用户，在配额范围内处理日常 Agent 任务，不产生费用。
    * **[Power 模式](/zh/ko/features/agent/agent-modes)**——当任务需要更强算力时，以合理的价格提供更高性能。
    * **[Plan 模式](/zh/ko/features/agent/plan-mode)**——在 Agent 开始构建前先界定任务范围并确认，避免为多余的改动付费。
    * **用量上限和预算**——在[支出管理](/zh/ko/billing/managing-spend)中设置硬性上限。

    切换任务时另起一个新的 Agent 聊天也很有帮助。查看用量控制面板，了解哪些任务花费最多。
  </Accordion>

  <Accordion title="什么是 Agent 模式？它们之间有何区别？">
    Agent 有三种顶层模式。完整说明请参阅 [Free 模式](/zh/ko/help/free-agent-mode)。

    * **Free 模式**——面向 Core 和 Pro 订阅用户的日常 Agent 使用，在每 5 小时重置一次、并设有每周上限的配额范围内不产生费用。Starter 等级沿用现有限额。要查看使用量，请前往 **设置 → 使用量**。
    * **Power**——付费中级模式，以合理的价格提供强大的模型。
    * **Max**——付费顶级模式，为最具挑战性的任务提供最强的前沿模型。
    * **Turbo**——仅在 Max 中可用的高级设置可选开关。

    付费模式已更名：**Economy 现更名为 Power**，此前称为 **Power 的模式现更名为 Max**。已有的模式设置保持不变，仅名称更新。如果你的请求所需性能超出 Free 模式，Agent 可能会提供付费的**允许一次**选项。Replit 会在付费任务开始前请求确认，任务结束后 Agent 将回到 Free 模式。

    此外，[Plan 模式](/zh/ko/features/agent/plan-mode)让 Agent 在改动前先梳理工作范围，而 Build 模式则直接应用更改。请参阅 [Plan 模式与 Build 模式对比](/zh/ko/learn/plan-vs-build-mode)。
  </Accordion>

  <Accordion title="Agent 做了不需要的更改。如何回滚？">
    Replit 会在 Agent 工作期间保存 [checkpoint](/zh/ko/features/version-control/checkpoints-and-rollbacks)。在 Agent 聊天中找到你想撤销的更改之前的那条消息，选择消息旁边的回滚选项，即可将项目恢复到该时间点的状态。

    如需了解完整的回滚选项 (包括恢复特定文件) ，请参阅 [Checkpoint 与回滚](/zh/ko/features/version-control/checkpoints-and-rollbacks)。
  </Accordion>

  <Accordion title="Agent 无法访问互联网或外部 API，这正常吗？">
    在构建和编辑阶段，Agent 运行在出站访问受限的沙箱环境中。已发布的应用在运行时可以发起外部 API 调用。沙箱只作用于 Agent 的编辑环境，不影响正在运行的应用。

    如果正在运行的应用中 API 调用失败，请确认密钥已保存在 [Secrets](/zh/ko/core-concepts/project-editor/app-setup/secrets) 面板中，并查看服务提供商的状态页面。公司或学校网络可能会阻止应用的出站连接，如遇此情况请联系网络管理员。
  </Accordion>

  <Accordion title="可以在 Agent 中使用自己的 API 密钥吗？">
    可以。在 [Secrets](/zh/ko/core-concepts/project-editor/app-setup/secrets) 面板中添加密钥后，应用即可在 API 调用中使用该密钥。打开 **Secrets** 工具，选择 **+ 新建 Secret**，然后输入名称 (例如 `OPENAI_API_KEY`) 和值。

    对于应用调用的模型，你可以[使用自己的 AI 提供商密钥](/zh/ko/features/integrations/replit-ai-integrations)。但驱动 Agent 体验的模型本身运行在 Replit 的基础设施上，无法替换。
  </Accordion>

  <Accordion title="Agent 不断添加我未请求的功能。如何让它更准确地按我的要求执行？">
    使用更明确的提示词，让 Agent 专注于任务：

    * 以 *Only* 开头。例如：&quot;Only add a delete button to the user card. Don&#39;t change anything else.&quot;
    * 先使用 [Plan 模式](/zh/ko/features/agent/plan-mode) 查看 Agent 将执行哪些操作，再让它进行修改。
    * 如果 Agent 做出了你不需要的更改，请立即在同一聊天中要求它撤销这些更改。

    有关详细信息，请参阅[有效提示词编写](/zh/ko/learn/effective-prompting)。
  </Accordion>
</AccordionGroup>
