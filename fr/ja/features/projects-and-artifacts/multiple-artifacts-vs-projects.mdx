title: "Plusieurs artifacts et projets distincts"

---

Un [projet](/fr/ja/features/projects-and-artifacts/projects) est le conteneur qui rassemble tout ce que vous créez sur Replit : designs, applications, diapositives, données et l&#39;ensemble des résultats que vous produisez.
Un [artifact](/fr/ja/features/projects-and-artifacts/artifacts) est un résultat publiable au sein d&#39;un projet : application web, application mobile, présentation, vidéo, etc.

Lorsque vous créez plusieurs éléments, deux options s&#39;offrent à vous :

* ajouter plusieurs artifacts à un même projet ;
* ou créer des projets distincts.

Le bon choix dépend de la question suivante : vos applications partagent-elles les mêmes données, la même logique et le même cycle de vie de déploiement ? Ce guide explique quand regrouper vos artifacts dans un seul projet et quand les créer séparément.

<div id="section">
  ## Ce que les artifacts partagent au sein d&#39;un projet
</div>

Lorsque des [artifacts](/fr/ja/features/projects-and-artifacts/artifacts) appartiennent au même [projet](/fr/ja/features/projects-and-artifacts/projects), ils partagent automatiquement les éléments suivants :

* **Base de données** : dès qu&#39;un artifact écrit des données, les autres peuvent les lire immédiatement
* **Backend et API** : une logique serveur partagée, sans duplication de code
* **Stockage de fichiers** : images, documents et fichiers téléversés accessibles à tous les artifacts
* **Déploiement** : à la publication, l&#39;ensemble est déployé d&#39;un seul tenant

Autrement dit, vous n&#39;avez pas besoin de configurer des connexions entre les artifacts ni de dupliquer du code. En revanche, vous ne pouvez pas publier un artifact sans publier les autres.

<div id="section-2">
  ## Guide rapide
</div>

Voici les principaux scénarios à considérer pour décider s&#39;il vaut mieux ajouter un artifact à un projet existant ou créer un projet distinct.

| **Plusieurs artifacts dans un seul projet**                                                          | **Projets distincts**                                                                    |
| ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Vos applications partagent les mêmes données et le même backend                                      | Vos applications ne partagent ni logique sous-jacente ni données                         |
| Vous souhaitez tout déployer en une seule fois                                                       | Vous avez besoin de cycles de déploiement indépendants                                   |
| Elles sont complémentaires (application client et tableau de bord d&#39;administration, par exemple) | Il s&#39;agit de produits sans lien entre eux, ou destinés à des clients différents      |
| Vous voulez que les modifications d&#39;un artifact se répercutent automatiquement sur les autres    | Les projets sont éphémères (page de destination de campagne, site d&#39;événement, etc.) |

<div id="section-3">
  ## Exemple
</div>

<div id="1">
  ### Même projet : une application web et une application mobile pour un seul produit
</div>

Un restaurant développe une application web permettant aux clients de consulter le menu et une application mobile permettant au personnel de gérer les commandes. Les deux applications se connectent à la même base de données contenant les articles du menu, les commandes et les informations clients.

**Pourquoi un seul projet :** les applications partagent les mêmes données et le même backend. Lorsqu&#39;un client passe une commande depuis l&#39;application web, le personnel la voit immédiatement dans l&#39;application mobile.

<div id="section-4">
  ### **Même projet** : application + tableau de bord d&#39;administration + présentation pour investisseurs
</div>

Une startup développe son produit principal, un panneau d&#39;administration interne pour gérer le contenu et un diaporama destiné à lever des fonds, le tout dans un seul projet.

**Pourquoi un seul projet :** le tableau de bord d&#39;administration gère les mêmes données que celles affichées par l&#39;application, et la présentation peut afficher des indicateurs en temps réel issus du backend partagé.

<div id="2">
  ### **Projets distincts** : deux applications clientes sans lien entre elles
</div>

Un freelance développe une boutique en ligne pour un client et un système de réservation pour un autre.

**Pourquoi opter pour des projets distincts :** les applications ne partagent ni données ni logique. Chaque client a besoin d&#39;un déploiement indépendant, et les modifications apportées à l&#39;une ne doivent pas affecter l&#39;autre.

<div id="section-5">
  ### **Projets distincts** : une landing page de campagne en parallèle du produit principal
</div>

Vous avez une application en production qui tourne toute l&#39;année, ainsi qu&#39;une landing page éphémère dédiée à une campagne marketing.

**Pourquoi les séparer :** la page de campagne a son propre cycle de vie. Vous la lancez, la laissez en ligne quelques semaines, puis vous l&#39;arrêtez. En la gardant à part, votre produit principal reste exempt d&#39;éléments superflus et vous pouvez publier ou supprimer la page indépendamment.

<div id="section-6">
  ## Questions fréquentes
</div>

<Accordion title="Puis-je déplacer un artifact vers un autre projet ?">
  Ce n&#39;est pas possible pour le moment. Si vous devez isoler un artifact, créez un nouveau [projet](/fr/ja/features/projects-and-artifacts/projects) et demandez à Agent de le reconstruire à cet endroit.
</Accordion>

<Accordion title="Le nombre d'artifacts dans un projet est-il limité ?">
  Un projet peut contenir jusqu&#39;à 7 artifacts. Cette limite existe car plus il y a d&#39;artifacts, plus la consommation de mémoire est élevée et plus l&#39;aperçu risque d&#39;être lent. Si vous avez besoin d&#39;artifacts supplémentaires, démarrez un autre [projet](/fr/ja/features/projects-and-artifacts/projects).
</Accordion>

<Accordion title="Puis-je publier un seul artifact d'un projet ?">
  Ce n&#39;est pas possible pour le moment. Lors de la publication, tout est déployé en bloc. Si vous avez besoin de déploiements indépendants, utilisez des projets distincts.
</Accordion>
