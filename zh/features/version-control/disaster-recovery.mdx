Replit 会自动备份你的 Git 仓库，帮助你在 `.git` 文件夹损坏或提交历史丢失等情况下恢复数据。该备份系统在后台运行，无需任何额外操作即可保护你的工作成果。

<div id="how-it-works">
  ## 工作原理
</div>

每个 Replit App 都会为你的 Git 仓库保留一份安全备份。当 Replit Agent 修改代码，或你 Publish 应用时，这些更改都会自动同步到该备份。如果本地 Git 仓库损坏或无法使用，你可以从备份中恢复完整的提交历史。

<Info>
  该备份 remote 名为 `gitsafe-backup`，由 Replit 自动管理。你无需做任何配置——它已在后台运行。
</Info>

<div id="viewing-your-backup-history">
  ## 查看备份历史
</div>

查看提交历史最简单的方式是使用 [Git pane](/zh/features/workspace-tools/git-interface)。在 Project Editor 的 Tools section 中打开它，即可看到完整的提交历史，其中包括所有 Agent checkpoint。这种方式适用于大多数情况，而且无需执行任何命令。

如果需要直接查看 gitsafe-backup remote，可以使用 Shell：

```bash theme={null}
git fetch gitsafe-backup main
git log gitsafe-backup/main
```

这里会显示完整的提交历史，包括所有 Agent checkpoint 和手动提交。你可以借此确认工作是否已备份，或找到需要恢复的特定提交。

<div id="recovering-from-git-issues">
  ## 从 Git 问题中恢复
</div>

如果你遇到 Git 错误或仓库损坏，请先尝试使用 [Git pane](/zh/features/workspace-tools/git-interface)。它无需 Shell 命令即可解决大多数常见问题，例如重置到之前的提交或从 remote 拉取。

如果 Git pane 也无能为力 (例如 `.git` 文件夹完全损坏) ，请按照下面基于 Shell 的步骤操作。

<div id="check-if-backup-is-available">
  ### 检查备份是否可用
</div>

首先，确认备份 remote 是否存在：

```bash theme={null}
git remote -v
```

在输出中查找 `gitsafe-backup`。如果存在，即可继续执行恢复操作。

<div id="restore-your-repository">
  ### 恢复仓库
</div>

<Warning>
  此过程会用备份版本替换当前的 `.git` 文件夹。工作文件保持不变，但本地 Git 历史记录将被备份内容覆盖。
</Warning>

<Steps>
  <Step title="保存当前的 Git 配置">
    如果你有自定义设置，请先备份 Git 配置文件：

    ```bash theme={null}
    cp .git/config .git_config_backup
    ```
  </Step>

  <Step title="克隆备份仓库">
    从备份创建一个临时克隆：

    ```bash theme={null}
    git clone --bare git://gitsafe:5418/backup.git /tmp/gitsafe-restore
    ```
  </Step>

  <Step title="替换 Git 文件夹">
    将损坏的 `.git` 文件夹重命名保留，再用备份替换它：

    ```bash theme={null}
    mv .git .git_corrupted_backup
    mv /tmp/gitsafe-restore/ .git
    ```
  </Step>

  <Step title="恢复配置">
    将 Git 配置复制回原位：

    ```bash theme={null}
    mv .git_config_backup .git/config
    ```
  </Step>
</Steps>

完成以上步骤后，运行 `git status` 确认仓库工作正常。

<div id="troubleshooting-common-issues">
  ## 常见问题排查
</div>

<div id="fatal-repository-not-found-or-backup-remote-missing">
  ### &quot;fatal: repository not found&quot; 或备份 remote 缺失
</div>

较早创建的项目可能未启用备份系统。如需恢复较早的项目，请联系支持团队获取帮助。

<div id="recovery-didnt-include-recent-commits">
  ### 恢复的内容不包含最近的提交
</div>

备份会在每次 Agent 提交后同步。如果你修改了内容但未提交，这些更改就不会出现在备份中。请检查工作目录中是否存在未提交的文件。

<div id="git-operations-are-slow-or-hanging">
  ### Git 操作缓慢或卡住
</div>

如果 Git 操作失去响应，可能是存在残留的锁文件。你可以安全地将其删除：

```bash theme={null}
rm -f .git/index.lock
```

<div id="preventing-data-loss">
  ## 防止数据丢失
</div>

备份系统会自动保护你的 Git 历史记录，但你还可以采取以下额外措施来保护工作成果：

* **频繁提交**：小步、高频地提交，让进度持续得到备份
* **使用 checkpoint**：使用 [Replit Agent](/zh/features/agent/overview) 时，checkpoint 会在关键节点自动创建提交
* **连接到 GitHub**：对于重要项目，可以[将应用连接到 GitHub](/zh/build/import-from-providers)，多获得一层备份保障
