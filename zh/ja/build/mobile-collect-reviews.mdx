评价越多，应用排名越高，也越能赢得新用户的信任。两个应用商店都提供了
用于此目的的原生提示：直接在应用内请求用户评价的弹窗。

<div id="section">
  ## 在恰当的时机请求评价
</div>

在玩家获胜、刷新最高分或升级后请求评价。时机比请求频率更
重要。

  {reviewPrompt}
</AiPrompt>

iOS 的 StoreKit 和 Android 的 Google Play In-App Review API 都会限制实际显示频率，无论代码请求得多么
频繁。

<Note>
  请勿通过仅在用户给出五星评价后才解锁游戏等方式，收买或强迫用户评价。
  Apple 和 Google 都禁止激励性评价，违规可能导致 PixelGames 被拒绝或
  下架。
</Note>

<div id="section-2">
  ## 故障排除
</div>

* **未显示提示：** 这是偶尔会出现的预期行为。无论代码调用 API 多少次，
  两个平台都会限制系统显示提示的频率。
* **测试期间每次都会显示提示：** 这在 TestFlight 和 Internal Testing 构建中属于正常行为。
  年度频率限制仅适用于实际的正式版安装。
* **频繁询问玩家会引发投诉：** 请确保调用的是原生 API，
  而不是在每次启动时显示自定义弹窗。自定义弹窗会绕过内置的频率限制。
