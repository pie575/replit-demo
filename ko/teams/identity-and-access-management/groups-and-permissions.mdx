기본 역할과 custom group을 기반으로 하는 체계적인 시스템으로 Organization의 리소스와 애플리케이션에 대한 접근 권한을 관리하세요. 이 방식을 사용하면 조직의 보안과 구조를 유지하면서 누가 무엇에 접근할 수 있는지 세밀하게 제어할 수 있습니다.

<div id="features">
  ## 기능
</div>

Replit Enterprise는 서로를 보완하는 두 가지 시스템을 통해 조직 전반의 접근 권한을 관리할 수 있는 포괄적인 access control을 제공합니다.

<CardGroup cols={2}>
  <Card title="Admin" icon="shield-check">
    조직 Settings와 모든 리소스에 대한 전체 관리자 권한
  </Card>

  <Card title="Member" icon="users">
    다른 모든 구성원을 확인하고 Apps와 Projects를 생성할 수 있음
  </Card>

  <Card title="Guest" icon="user-plus">
    공유된 apps와 리소스에만 제한적으로 접근 가능
  </Card>

  <Card title="Viewer" icon="eye">
    apps와 deployments에 대한 읽기 전용 접근
  </Card>
</CardGroup>

주요 기능은 다음과 같습니다.

* **기본 역할**: 모든 조직 구성원에게 기본적인 access control을 제공하는 네 가지 기본 제공 접근 수준
* **Custom groups** *(Enterprise 전용)*: 기본 역할의 제약을 넘어 세분화된 access control이 가능하도록 전용 groups 생성
* **유연한 access control**: 역할과 groups를 활용해 Apps와 리소스별로 필요한 만큼의 접근 권한 부여
* **간편한 구성원 관리**: 간단한 관리 도구로 구성원을 추가·제거하거나 groups 간에 이동

<div id="usage">
  ## 사용량
</div>

<div id="roles">
  ### 역할
</div>

모든 조직 구성원은 조직 내에서의 기본 접근 수준을 정의하는 역할을 가지고 있어야 합니다. 관리자는 새 구성원을 추가할 때 역할을 지정하여 처음부터 적절한 access control이 이루어지도록 합니다.

네 가지 기본 역할은 각각 다른 수준의 접근 권한을 제공합니다:

* **Admins**: 조직 설정, billing, 구성원 관리를 포함해 조직에서 수행 가능한 모든 작업에 접근할 수 있습니다
* **Members**: Replit Apps를 만들고 편집할 수 있고 다른 모든 조직 구성원을 볼 수 있지만, 민감한 관리 작업은 수행할 수 없습니다
* **Guests**: 접근 수준이 가장 낮으며, 자신에게 직접 공유된 apps만 편집할 수 있습니다. 이 역할은 외부 협업자(예: 외부 계약자)를 위한 것입니다. [SSO](/ko/teams/identity-and-access-management/saml)가 활성화된 Enterprise 조직에서는 Guests가 SSO 도메인 외부의 이메일을 사용해야 합니다. 내부 사용자는 대신 members 또는 admins로 추가하세요
* **Viewers**: apps와 deployments에 읽기 전용으로 접근할 수 있어, 편집 권한 없이 확인만 필요한 이해관계자에게 적합합니다

<Note>
  Enterprise에서는 Guest의 역할이 고정됩니다. 한 번 추가된 Guest는 Member나 Admin으로 승격하거나 Viewer로 변경할 수 없으므로, 원하는 역할로 지정하려면 해당 Guest를 제거한 후 다시 초대하세요. SCIM으로 관리되는 workspaces의 Guests는 identity provider를 통해 관리됩니다.
</Note>

<Info>
  **Enterprise 전용:** Enterprise에서는 Admin 역할이 **account admin**(billing 및 계정 전체 제어)과 **workspace admin**(소속된 workspaces로 범위 제한)의 두 가지로 나뉩니다. 두 역할의 차이와 설정 방법은 [Account and Workspace Admins](/ko/teams/identity-and-access-management/account-and-workspace-admins)를 참조하세요. Core와 Pro에서는 단일 Admin(계정의 account admin)만 존재합니다.
</Info>

<div id="custom-groups">
  ### 커스텀 그룹
</div>

<Info>
  커스텀 그룹은 **Enterprise** plan에서만 사용할 수 있습니다.
</Info>

커스텀 그룹을 사용하면 기본 역할만으로는 부족한 access control을 보완할 수 있습니다. 그룹을 만들어 선택한 Organization 구성원에게 기본 역할 권한을 그대로 유지한 채 특정 액세스 권한을 부여하세요.

<Note>
  대량 사용자 액세스 관리를 간소화하기 위해 IdP 그룹을 Replit에 동기화하는 방법은 [SCIM](https://docs.replit.com/teams/identity-and-access-management/scim)을 참조하세요.
</Note>

그룹 목록은 사이드바의 &quot;Groups&quot; tab에서 확인할 수 있습니다. 각 그룹 카드에는 그룹 이름, 색상이 적용된 icon, 그룹 구성원 수가 표시됩니다. 구성원에게는 최소 Viewer 이상의 액세스 권한을 가진 그룹만 표시됩니다.

<div id="creating-a-group">
  #### 그룹 만들기
</div>

Admin은 groups 페이지에서 custom group을 무제한으로 만들 수 있습니다. 오른쪽 상단의 **Add** 버튼을 선택하면 생성 모달이 열리며, 여기에서 다음 작업을 할 수 있습니다.

* **그룹 이름 지정**: 그룹 이름은 유일한 필수 입력 항목입니다
* **시각적 식별 요소 추가**: color와 icon을 선택해 그룹을 구분합니다
* **멤버 할당**: Organization 멤버를 개별 또는 일괄로 그룹에 추가합니다
* **접근 권한 부여**: 그룹에는 이후 각 App의 **Invite** 버튼을 통해 특정 App에 대한 접근 권한을 부여할 수 있습니다

<Frame>
  <img src="/assets/mirror/creating-a-custom-group-12741b699c41.png" alt="이름 입력란과 색상 선택기가 있는 custom group 생성 모달" width="2992" height="1696" data-path="images/teams/identity-and-access-management/creating-a-custom-group.png" />
</Frame>

그룹을 만들면 그룹 상세 보기가 열리며, 여기에서 멤버를 추가하고 조직 permissions를 설정할 수 있습니다.

<div id="managing-groups">
  #### 그룹 관리
</div>

그룹 카드를 선택하면 해당 그룹의 관리 화면으로 이동합니다. 그룹 관리에서는 멤버 추가와 제거, permissions 설정을 할 수 있습니다.

<Frame>
  <img src="/assets/mirror/group-members-view-1ca06f5bdac3.png" alt="그룹 멤버 보기" width="2992" height="1696" data-path="images/teams/identity-and-access-management/group-members-view.png" />
</Frame>

**그룹에 멤버 추가하기:**

그룹에 멤버를 추가하려면 오른쪽 상단의 **Add** 버튼을 선택하세요. 추가하려는 사람이 Organization에 속해 있지 않고 사용 가능한 좌석도 부족한 경우에는 이 버튼이 비활성화됩니다.

<Frame>
  <img src="/assets/mirror/adding-a-group-member-670c216b2806.png" alt="사용자 이름 또는 이메일 검색 필드가 있는 그룹 멤버 추가 대화 상자" width="2992" height="1696" data-path="images/teams/identity-and-access-management/adding-a-group-member.png" />
</Frame>

사용자 이름 또는 이메일로 새 멤버를 검색할 수 있습니다. 새 멤버가 Organization에 속해 있지 않으면 작업을 확인하는 경고가 표시됩니다.

<Frame>
  <img src="/assets/mirror/non-member-warning-a6d5df22c6c3.png" alt="Organization 외부 멤버를 그룹에 추가할 때 표시되는 경고 대화 상자" width="2992" height="1696" data-path="images/teams/identity-and-access-management/non-member-warning.png" />
</Frame>

새 멤버를 추가하면 그룹 멤버 목록에 표시되며, 해당 그룹에서 사용할 수 있는 Replit Apps와 기타 리소스에 즉시 접근할 수 있습니다.

**그룹에서 멤버 제거하기:**

그룹 멤버를 제거하려면 멤버 행 오른쪽의 휴지통 icon을 선택하세요. 점 세 개 버튼으로 작업 메뉴를 열고 **Remove from group**을 선택해도 됩니다. 그러면 확인 모달이 열립니다.

<Frame>
  <img src="/assets/mirror/removing-a-group-member-8d88a7b24f2e.png" alt="그룹 멤버 제거 확인 대화 상자" width="2992" height="1696" data-path="images/teams/identity-and-access-management/removing-a-group-member.png" />
</Frame>

Custom group에서 멤버를 제거하면 기본 역할에 따른 접근 권한은 그대로 유지되지만, 그룹에 한정된 접근 권한은 사라집니다.

<div id="setting-group-permissions">
  #### 그룹 permissions 설정
</div>

group에 조직 permissions를 할당하여 group 구성원이 조직 내에서 가져야 할 접근 수준을 정의합니다. 그룹 permissions를 설정하려면 생성한 group을 선택한 다음, 왼쪽 탐색 메뉴에서 **permissions** tab을 선택하세요.

설정할 수 있는 permissions 수준은 다음과 같습니다.

* **Owner**: Organization 삭제를 포함한 모든 조직 작업을 수행할 수 있습니다
* **Billing manager**: Organization의 결제 정보를 업데이트하고, 좌석을 추가 및 제거하며, 지출 limit을 설정할 수 있습니다
* **Manager**: group을 생성 및 관리하고, 조직 Member를 추가 및 제거하며, Billing 정보를 확인할 수 있습니다
* **Editor**: 새 App을 만들고 Usage 정보를 확인할 수 있습니다
* **Viewer**: Organization에 대한 기본 정보를 확인할 수 있습니다

이러한 그룹 permissions는 앱별 접근 권한과는 별개이며, 앱별 접근 권한은 Access 기능을 통해 개별 apps에서 관리합니다.

group을 선택하면 해당 group이 접근할 수 있는 apps를 확인할 수 있습니다. 왼쪽 탐색 메뉴에서 **permissions**를 선택한 다음 **Apps**로 이동하세요.

<div id="app-access-control">
  ### 앱 접근 제어
</div>

Replit의 Access 기능으로 앱에 접근하고 협업할 수 있는 사용자를 제어하세요. 역할과 그룹에 접근 권한을 할당하면 조직 전반의 보안을 유지하면서 특정 앱을 적합한 멤버와 공유할 수 있습니다.

<div id="setting-app-access">
  #### 앱 접근 권한 설정
</div>

<Accordion title="앱 접근 권한 관리 방법">
  앱 화면 오른쪽 상단(**Publish** 왼쪽)에서 **Invite**를 선택하면 액세스 패널이 열립니다.
</Accordion>

액세스 패널에는 사용 가능한 모든 역할이 표시되며, custom group을 검색할 수 있습니다:

* **기본 역할**: Admin, Members, Guests, Viewers가 액세스 패널에 자동으로 표시됩니다
* **Custom groups**: 검색 기능으로 특정 custom group을 찾아 앱 접근 권한을 부여합니다

<div id="access-levels">
  #### 접근 수준
</div>

세분화된 제어를 위해 각 역할과 그룹에 서로 다른 접근 수준을 지정할 수 있습니다.

* **Owner**: 앱 삭제와 관리 제어를 포함한 전체 접근 권한
* **Publisher**: 코드 편집, 앱 재게시, 앱 리소스 및 Settings 관리 가능
* **Editor**: 코드 편집과 앱 리소스 조회는 가능하지만 게시 권한은 없음
* **Viewer**: 코드에 대한 읽기 전용 접근 권한과 개인 용도로 앱을 fork할 수 있는 권한
* **None**: 앱을 검색, 조회, 편집할 수 없음

협업 요건과 보안 요구 사항에 맞춰 각 역할 또는 그룹에 적절한 접근 수준을 선택하세요.
