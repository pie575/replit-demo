<div id="browser-support">
  ### Prise en charge des navigateurs
</div>

* **Chrome**, **Safari** et les navigateurs basés sur Chromium sont entièrement pris en charge.
* **Firefox** n&#39;est pas pris en charge. Lorsque vous ouvrez Replit dans Firefox, les options iOS et Android apparaissent désactivées, avec la mention « Firefox not supported ». Il s&#39;agit d&#39;une limitation de la technologie de streaming sur laquelle repose le simulateur.

<div id="when-to-use-expo-go-instead">
  ### Quand utiliser Expo Go à la place
</div>

Utilisez Expo Go sur un véritable téléphone lorsque vous devez tester des fonctionnalités qui reposent sur du matériel réel ou lorsque vous souhaitez partager un aperçu avec une personne qui n&#39;est pas devant votre ordinateur :

* Appareil photo, microphone, retour haptique ou autres capteurs natifs
* Notifications push
* Localisation GPS en conditions réelles
* Partage d&#39;un aperçu de développement avec un collègue, un testeur ou un investisseur

Pour ouvrir votre app dans Expo Go, ouvrez le projet sur [replit.com](https://replit.com), sélectionnez **Open in Expo Go** dans le panneau Preview du Project Editor, puis scannez le QR code avec l&#39;application [Expo Go](https://expo.dev/go) depuis votre téléphone.

<div id="fullscreen-simulator">
  ### Simulateur en plein écran
</div>

Depuis une carte d&#39;artifact mobile, sélectionnez **More actions** → **Open in iOS Simulator** ou **Open in Android Emulator** pour ouvrir le simulateur dans un onglet dédié et profiter d&#39;une zone d&#39;affichage plus grande.

<div id="why-build-a-mobile-app">
  ## Pourquoi créer une application mobile ?
</div>

Créez une application mobile lorsque vous recherchez :

* **Une expérience native** : des performances rapides, des interactions fluides et une interface conforme aux standards de la plateforme.
* **Les fonctionnalités de l&#39;appareil** : appareil photo, notifications push, géolocalisation et bien plus.
* **Une distribution sur l&#39;App Store** : une fiche partageable que les utilisateurs peuvent découvrir et installer à l&#39;issue du processus de validation d&#39;Apple (App Review).

<div id="key-features">
  ## Fonctionnalités clés
</div>

* **Création orientée IA** : décrivez votre app, et Agent génère la structure d&#39;une app mobile fonctionnelle.
* **Aperçu dans le Project Editor** : testez sur un iOS Simulator ou un Android Emulator sans quitter Replit, ou prévisualisez sur votre téléphone avec Expo Go.
* **Full-stack par défaut** : ajoutez des routes serveur, une Database, App Storage, des Connectors et des intégrations d&#39;IA à mesure que votre app évolue.
* **Soumission guidée** : préparez vos builds pour TestFlight et la soumission à l&#39;App Store sans avoir à gérer de chaînes d&#39;outils iOS en local.

<div id="development-workflow">
  ## Flux de développement
</div>

L&#39;accès à votre app se fait en trois étapes, chacune avec ses publics et ses possibilités :

| Étape             | Qui peut y accéder    | Comment y accéder                                            | Idéal pour                                              |
| ----------------- | --------------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| **Développement** | Vous                  | Simulateur du Project Editor, ou code QR pour Expo Go        | Développer et itérer                                    |
| **Déploiement**   | Testeurs avec Expo Go | URL publique avec code QR                                    | Aperçus de développement, prototypage et démonstrations |
| **App Store**     | Tout le monde         | Téléchargement depuis l&#39;App Store après l&#39;App Review | Mise en production                                      |

**Développement** : au démarrage de votre app, vous pouvez la prévisualiser dans l&#39;**iOS Simulator** ou l&#39;**Android Emulator** du Project Editor, ou scanner un code QR depuis le panneau Preview pour l&#39;ouvrir dans Expo Go sur votre téléphone.

**Déploiement** : lorsque vous cliquez sur **Publish**, Replit crée une URL publique avec un code QR pour Expo Go. C&#39;est la solution idéale pour les aperçus de développement et le prototypage : présentez votre app à des investisseurs, recueillez des retours ou testez-la avec vos proches avant de vous lancer dans le processus de l&#39;App Store.

**App Store** : lorsque vous soumettez votre app à l&#39;App Store, Apple l&#39;examine. Une fois l&#39;app approuvée, chacun peut la télécharger et l&#39;installer depuis l&#39;App Store. Un compte Apple Developer est nécessaire.

<div id="publishing-overview">
  ## Aperçu de la publication
</div>

Lorsque vous préparez une version iOS, le processus se déroule généralement ainsi :

* Publier depuis le Project Editor
* Soumettre un build à TestFlight
* Promouvoir un build TestFlight vers l&#39;App Store dans App Store Connect

<Note>
  Pour soumettre des builds à TestFlight et à l&#39;App Store, Apple exige une adhésion à l&#39;Apple Developer Program.
</Note>

Pour une procédure complète, consultez le tutoriel [Créer et lancer une application mobile](/fr/build/mobile-app).

<div id="where-to-build-native-mobile-apps">
  ## Où créer des applications mobiles natives
</div>

Votre environnement Replit s&#39;exécute dans le cloud, et non sur votre machine locale. Pour créer une application mobile native, utilisez le Project Editor sur [replit.com](https://replit.com). L&#39;ensemble du workflow mobile — génération de la structure par Agent, aperçus Expo Go, tests sur simulateur et émulateur, builds TestFlight et soumission à l&#39;App Store — se déroule dans le Project Editor.

Le développement d&#39;applications mobiles natives est également possible dans l&#39;[application Replit pour Android](/fr/features/platforms/mobile-app), là où il est pris en charge. Si vous utilisez l&#39;application Replit pour iOS, ouvrez le projet sur [replit.com](https://replit.com) pour créer, prévisualiser, compiler ou soumettre des applications mobiles natives.

* **React Native** est un framework open source qui vous permet d&#39;écrire une seule base de code et de la compiler pour iOS, Android et le web. Il affiche des composants d&#39;interface natifs à chaque plateforme, et non une webview.
* **Expo** simplifie le développement React Native en gérant les builds et les modules natifs, et en fournissant des outils comme Expo Go pour les aperçus.
* **Expo Go** est une application gratuite à installer sur votre téléphone. Elle exécute l&#39;aperçu de développement de votre application, ce qui vous permet de la tester sur un appareil réel sans générer de binaire natif complet.

Lorsque vous lancez votre application, le bundler Metro compile votre code et l&#39;envoie sur votre appareil. Le premier build est plus long, faute de cache. Les builds suivants sont plus rapides.

<div id="architecture-server-and-client">
  ### Architecture : serveur et client
</div>

Lorsque vous préparez une application mobile pour la prévisualisation ou la distribution, vous manipulez deux éléments :

1. **Un serveur** qui s&#39;exécute sur Replit, dans le cloud. Il gère votre base de données, vos routes API, vos intégrations d&#39;IA et votre logique backend.
2. **Une application cliente** qui s&#39;exécute sur le téléphone de l&#39;utilisateur. Il s&#39;agit de l&#39;application native prévisualisée dans Expo Go pendant le développement, puis distribuée via les magasins d&#39;applications après validation.

<MobileArchitectureDiagram />

Cette séparation vous apporte de la souplesse. Vous pouvez exécuter la logique complexe côté serveur (où vous avez accès à Database, Object Storage et Connectors de Replit) et garder le client léger. Au fil du développement, demandez-vous ce qui doit se passer sur le téléphone et ce qui relève du cloud.

<div id="considerations">
  ## Points à prendre en compte
</div>

* **Exigences de publication** : Apple définit les exigences applicables à TestFlight et à l&#39;App Store, et examine les applications iOS avant leur distribution.
* **Publication sur Android** : vous pouvez créer des applications multiplateformes pour iOS et Android. La publication sur Google Play ne fait pas encore l&#39;objet d&#39;un parcours guidé, mais elle reste possible manuellement.
* **Modifications natives** : les changements tels que les icônes d&#39;application ou les autorisations nécessitent généralement une nouvelle build destinée aux magasins d&#39;applications.

<div id="faqs">
  ## FAQ

<AccordionGroup>
  <Accordion title="Qu'est-ce qu'Expo ?">
    Expo est l&#39;outil qu&#39;Agent utilise pour créer votre application mobile sur Replit. Il s&#39;agit d&#39;une plateforme et d&#39;une chaîne d&#39;outils open source permettant de créer, d&#39;exécuter et de déployer des applications natives multiplateformes avec React Native. Pour en savoir plus, consultez [https://expo.dev](https://expo.dev).
  </Accordion>

  <Accordion title="Qu'est-ce que React Native ?">
    React Native est un framework open source de Meta permettant de créer des applications natives iOS et Android avec React et JavaScript ou TypeScript. Il affiche des composants d&#39;interface natifs de la plateforme (et non une webview), afin que votre application ait vraiment l&#39;apparence et le comportement d&#39;une application native.
  </Accordion>

  <Accordion title="Qu'est-ce qu'Expo Go ?">
    Expo Go est une application gratuite que vous installez sur votre téléphone depuis l&#39;App Store ou Google Play. Elle vous permet de prévisualiser votre application mobile pendant le développement, sans créer de binaire natif complet. Lorsque vous scannez le QR code dans le Project Editor, Expo Go télécharge et exécute le code de votre application.
  </Accordion>

  <Accordion title="Quelle est la différence entre Expo Go et une version de développement ?">
    **Expo Go** est une application préconstruite qui exécute votre code. Sa configuration est rapide, mais elle ne prend en charge que les modules inclus dans le SDK Expo.

    Les **versions de développement** sont des binaires natifs personnalisés qui peuvent inclure n&#39;importe quel module natif. Elles demandent davantage de configuration (EAS Build ou Xcode/Android Studio en local), mais offrent plus de souplesse.

    Replit utilise Expo Go pour les aperçus de développement. Si vous avez besoin de modules natifs non pris en charge par Expo Go, vous devrez peut-être vous tourner vers les versions de développement en consultant [la documentation d&#39;Expo](https://docs.expo.dev/develop/development-builds/introduction/).
  </Accordion>

  <Accordion title="En quoi est-ce différent d'une web app adaptée au mobile ?">
    Une web app adaptée au mobile est un site web qui ajuste sa mise en page dans le navigateur. Une application React Native est une application native installée sur l&#39;appareil : elle utilise les API de la plateforme (appareil photo, retour haptique, notifications push), offre un meilleur accès au matériel et aux fonctionnalités hors ligne, et se distribue via les magasins d&#39;applications. Le web adaptatif est idéal pour toucher un large public sans installation ; le natif s&#39;impose lorsque vous avez besoin des fonctionnalités de l&#39;appareil, de performances ou d&#39;une distribution sur l&#39;App Store.
  </Accordion>

  <Accordion title="Ai-je besoin d'un Mac ou de Xcode ?">
    Non. Replit et Expo gèrent le processus de build pour vous dans le cloud.
  </Accordion>

  <Accordion title="Puis-je prévisualiser sans compte Apple Developer ?">
    Oui. Vous pouvez prévisualiser dans l&#39;iOS Simulator du Project Editor ou avec Expo Go sur votre téléphone. Un compte Apple Developer n&#39;est nécessaire que lorsque vous êtes prêt à soumettre votre application à TestFlight ou à l&#39;App Store.
  </Accordion>

  <Accordion title="Android est-il pris en charge ?">
    Oui. Vous pouvez créer des applications multiplateformes pour iOS et Android à partir du même code source. Prévisualisez sur un Android Emulator dans le Project Editor ou sur un appareil Android avec Expo Go. La publication sur Google Play peut se faire manuellement.
  </Accordion>

  <Accordion title="Qu'en est-il des serveurs et des bases de données ?">
    Utilisez les fonctionnalités intégrées de Replit : PostgreSQL, Object Storage, Connectors et intégrations d&#39;IA — aucune infrastructure distincte n&#39;est nécessaire. Votre serveur s&#39;exécute sur Replit et votre application mobile s&#39;y connecte.
  </Accordion>

  <Accordion title="Vaut-il mieux tester dans le simulateur du Project Editor ou sur un vrai téléphone ?">
    Utilisez les deux, selon les cas. L&#39;**iOS Simulator** et l&#39;**Android Emulator** du Project Editor affichent la version native de votre application et couvrent l&#39;essentiel des tests quotidiens : mise en page, navigation, composants natifs et styles propres à la plateforme. Passez à un vrai téléphone avec **Expo Go** lorsque vous devez tester des fonctionnalités qui dépendent du matériel, comme l&#39;appareil photo, le retour haptique, les notifications push ou la géolocalisation GPS.
  </Accordion>
</AccordionGroup>
