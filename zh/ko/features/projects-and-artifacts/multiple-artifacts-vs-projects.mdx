---
title: "多个 构件 还是多个独立 项目？"
description: "了解在 Replit 中何时应将多个 构件 放在同一个 项目 中，何时应创建独立的 项目。"
---

[项目](/zh/ko/features/projects-and-artifacts/projects) 是你在 Replit 中创建的所有内容的容器，可以容纳设计、应用、幻灯片、数据以及你创作的各种成果。
[构件](/zh/ko/features/projects-and-artifacts/artifacts) 则是 项目 内可发布的成果：Web 应用、移动应用、幻灯片、视频等等。

当你要创建两个以上的成果时，有两种选择：

* 在同一个 项目 中添加多个 构件，
* 或者分别创建独立的 项目。

如何选择，取决于这些应用是否共享数据、逻辑和部署周期。本指南将说明何时应把 构件 放在同一个 项目 中，何时应分开创建。

<div id="section">
  ## 项目 内 构件 共享的内容
</div>

当多个 [构件](/zh/ko/features/projects-and-artifacts/artifacts) 位于同一个 [项目](/zh/ko/features/projects-and-artifacts/projects) 中时，它们会自动共享以下内容：

* **数据库**：一个 构件 写入数据后，其他 构件 可立即读取
* **后端与 API**：共享服务器逻辑，无需重复编写代码
* **文件存储**：图片、文档和上传的文件可在所有 构件 中访问
* **部署**：发布时，所有内容会一起同步上线

也就是说，你无需在 构件 之间建立连接，也不必重复编写代码。但这同时意味着，你无法只发布其中一个 构件，其余的也会一并发布。

<div id="section-2">
  ## 快速指南
</div>

在决定是将构件添加到现有项目，还是新建一个单独的项目时，可参考以下主要情形。

| **在一个项目中使用多个构件**           | **使用单独的项目**              |
| -------------------------- | ------------------------ |
| 各应用共享同一套数据和后端              | 各应用之间不共享核心逻辑或数据          |
| 希望将所有内容一并发布                | 需要各自独立的发布周期              |
| 彼此互为补充 (例如面向客户的应用与管理员仪表板)  | 属于互不相关的产品，或服务于不同的客户端     |
| 希望某个构件的改动自动同步到其他构件         | 项目是短期的 (例如营销活动落地页或活动网站)  |

<div id="section-3">
  ## 示例
</div>

<div id="section-4">
  ### 同一项目：一个产品的 Web 应用 + 移动应用
</div>

某家餐厅创建了一个供顾客浏览菜单的 Web 应用，以及一个供员工管理订单的移动应用。两者都连接到同一个数据库，其中存放菜单项、订单和顾客信息。

**为什么放在一个项目中：** 这些应用共享同一套数据和后端。顾客通过 Web 应用下单后，员工可以立即在移动应用中看到该订单。

<div id="section-5">
  ### **同一个项目**：应用 + 管理后台 + 投资人路演文稿
</div>

一家初创公司在同一个项目中构建主打产品、用于内容管理的内部管理面板，以及用于融资的路演文稿。

**为什么放在一个项目里：** 管理后台所管理的，正是应用对外展示的同一份数据；而路演文稿可以直接引用共享后端中的实时指标。

<div id="section-6">
  ### **独立项目**：两个互不相关的客户应用
</div>

一位自由职业者为一个客户搭建电商商店，为另一个客户搭建预约系统。

**为什么要拆成独立项目：** 这两个应用不共享数据和逻辑。每个客户都需要独立发布，你也不希望改动其中一个应用会波及另一个。

<div id="section-7">
  ### **独立项目**：与主打产品并行的营销活动落地页
</div>

你有一个全年运行的生产应用，同时还需要一个服务于营销活动的短期落地页。

**为什么要单独建一个项目：** 活动页面有自己的生命周期——创建、上线运行几周，然后下线。把它独立出来，你就可以单独发布或下线，而不会让主打产品变得臃肿复杂。

<div id="section-8">
  ## 常见问题
</div>

<Accordion title="可以把 构件 移动到其他 项目 吗？">
  目前还不支持。如果需要将 构件 独立出来，请新建一个 [项目](/zh/ko/features/projects-and-artifacts/projects)，并让 Agent 在其中重新创建。
</Accordion>

<Accordion title="一个 项目 中的 构件 数量有上限吗？">
  一个 项目 最多可包含 7 个 构件。设置该上限是因为 构件 越多占用的内存越大，可能导致预览变慢。如果需要更多 构件，请新建一个 [项目](/zh/ko/features/projects-and-artifacts/projects)。
</Accordion>

<Accordion title="可以只发布 项目 中的某一个 构件 吗？">
  目前还不支持。发布时所有内容会一起上线。如果需要单独发布，请使用独立的 项目。
</Accordion>
