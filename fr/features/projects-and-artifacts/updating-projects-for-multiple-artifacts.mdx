Si votre projet a été créé avant le 11 mars 2026, Agent devra peut-être effectuer une mise à jour structurelle unique avant de pouvoir y ajouter un second artifact. Cette page explique pourquoi, ce qui change et quels projets sont éligibles.

<div id="background">
  ## Contexte
</div>

Le **11 mars 2026**, Replit a lancé [Agent 4](/fr/updates/2026/03/13/changelog). L&#39;une des évolutions majeures de cette version était la **prise en charge de plusieurs artifacts** : un même [projet](/fr/features/projects-and-artifacts/projects) peut désormais contenir plusieurs [artifacts](/fr/features/projects-and-artifacts/artifacts) (par exemple, une web app, une application mobile et une présentation) qui partagent la même base de données, le même backend, les mêmes secrets et le même deployment.

Avant le 11 mars 2026, chaque projet s&#39;articulait autour d&#39;une seule application, avec une organisation de fichiers différente. Cette ancienne structure n&#39;offre pas la séparation dont le backend a besoin pour héberger plusieurs artifacts. En raison de ces différences, les projets créés avant le 11 mars 2026 nécessitent une **mise à jour structurelle unique** avant qu&#39;Agent puisse y ajouter un second artifact. Les projets créés à partir de cette date utilisent déjà la nouvelle organisation et n&#39;ont pas besoin de cette étape.

<div id="what-the-update-does">
  ## Ce que fait la mise à jour
</div>

Lorsque vous demandez à Agent d&#39;ajouter un second artifact à un ancien projet (par exemple, ajouter une application mobile à une web app existante), Agent commence par réorganiser votre projet selon la nouvelle structure multi-artifacts. Votre URL, vos collaborateurs, vos secrets, votre base de données et vos domaines sont tous conservés. Seule la structure interne change.

<div id="how-it-works">
  ## Fonctionnement
</div>

<Steps>
  <Step title="Demandez un nouvel artifact dans un ancien projet">
    Demandez à Agent quelque chose comme : « Crée un deck de présentation pour mon site web. »
  </Step>

  <Step title="Examinez et approuvez">
    Agent s&#39;interrompt avant d&#39;apporter la moindre modification et vous présente une proposition dans le chat. Pour deux projets éligibles au maximum, vous verrez également une offre unique de **5 $ de crédit** pour vous lancer dans la mise à jour du projet. Cliquez sur **Update projet** pour continuer, ou sur **Not now** pour ignorer.

    <Frame>
      <img src="/assets/mirror/multi-artifact-update-approval-f6fa8b70a100.png" alt="Panneau de chat d'Agent affichant la carte d'approbation « Update projet to create mobile app » avec une offre de 5 $ de crédit et les boutons Not now / Update projet." width="991" height="589" data-path="images/replitai/multi-artifact-update-approval.png" />
    </Frame>
  </Step>

  <Step title="Attendez la restructuration">
    Agent réorganise votre projet selon la nouvelle structure au sein d&#39;une tâche — vous pouvez en suivre la progression dans la liste des tâches. Votre app d&#39;origine est sauvegardée avant toute modification : vous ne perdrez donc aucun travail antérieur en cas de problème.

    <Frame>
      <img src="/assets/mirror/multi-artifact-update-task-progress-825057a11685.png" alt="Panneau de chat d'Agent affichant la tâche « Updating your projet » en cours, avec la sous-tâche « Port existing coffee website » active." width="989" height="587" data-path="images/replitai/multi-artifact-update-task-progress.png" />

  </Step>

  <Step title="Obtenez le nouvel artifact demandé">
    Une fois votre app d&#39;origine opérationnelle dans la nouvelle structure, Agent crée l&#39;artifact que vous aviez demandé au départ.
  </Step>
</Steps>

<div id="eligibility">
  ## Éligibilité
</div>

Tous les projets ne peuvent pas être mis à jour pour le moment. Votre projet doit être de l&#39;un de ces types :

* **Web App** (JavaScript fullstack)
* **Maquettes Design-to-app**
* **Mobile App** (Expo)

Les autres types de projets créés avant le 11 mars 2026, notamment Python, Flask, Streamlit, les stacks de jeu, les projets vidéo et les stacks d&#39;agent, ne sont pas pris en charge. Dans ces cas-là, si vous avez besoin de plusieurs artifacts, [créez plutôt un nouveau projet](/fr/features/projects-and-artifacts/projects).

Les ports et les workflows de votre projet doivent également correspondre à la configuration par défaut de son type. Si vous avez modifié manuellement `.replit`, ce message s&#39;affichera :

> *This project cannot be migrated automatically: workflow config does not match expected.*

Pour résoudre ce problème, rétablissez les valeurs par défaut de vos ports et workflows personnalisés, puis réessayez.

<div id="frequently-asked-questions">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Pourquoi mon projet a-t-il besoin d'une mise à jour ?">
    Les projets créés avant le 11 mars 2026 (date du lancement d&#39;Agent 4) reposaient sur une structure à application unique. La nouvelle structure de workspace partagé permet à une web app, une application mobile et un tableau de bord d&#39;administration de coexister en partageant la même base de données et le même backend. La mise à jour est une étape unique qui permet d&#39;adopter cette structure.
  </Accordion>

  <Accordion title="Et si je ne souhaite pas faire la mise à jour ?">
    Cliquez sur **Pas maintenant**. Agent continue de développer dans la structure actuelle à artifact unique. Vous pourrez revenir sur cette proposition plus tard si vos besoins évoluent.
  </Accordion>

  <Accordion title="Puis-je faire la mise à jour plusieurs fois ?">
    Non. Une fois votre projet passé à la nouvelle structure, aucune autre mise à jour n&#39;est nécessaire. Les futurs artifacts sont ajoutés directement, sans étape de mise à jour supplémentaire.
  </Accordion>

  <Accordion title="Mon projet n'est pas éligible. Quelles sont mes options ?">
    Créez un projet distinct pour le nouvel artifact, ou démarrez un nouveau projet qui prend en charge plusieurs artifacts dès le départ.
  </Accordion>
</AccordionGroup>
