Публикуя приложение, вы сами решаете, кто сможет его открыть. Выберите нужный вариант в разделе **Кто может открывать ваше приложение** в настройках публикации. Replit сам покажет экран входа и проверит права доступа — менять код не нужно.

Ограничение доступа пригодится для таких приложений, как:

* Внутренние инструменты
* Приложения на этапе бета-тестирования
* Приложения, работающие с конфиденциальной информацией

<div id="access-options">
  ## Варианты доступа
</div>

* **Public**: любой пользователь интернета, у которого есть ссылка, может пользоваться вашим приложением.
* **Password protected**: любой пользователь интернета, знающий пароль, может пользоваться вашим приложением. Посетители вводят общий пароль. Учётная запись Replit им не нужна.
* **Workspace only**: все администраторы, участники и наблюдатели в вашем workspace. Replit помечает этот вариант как **Private**.
* **только по приглашению**: только вы, администраторы, приглашённые группы и приглашённые пользователи. Replit помечает этот вариант как **Private**. Это самый строгий вариант.

Значение по умолчанию зависит от того, где вы работаете: для приложений в личном workspace по умолчанию установлен вариант **Public**, а для приложений в workspace организации — один из приватных вариантов.

<Note>
  В обоих вариантах **Private** посетителям без доступа сначала предлагается войти через Replit, и только затем они смогут открыть приложение. В личном workspace, где вы единственный участник, **Workspace only** и **только по приглашению** работают одинаково. Разница проявляется, когда вы работаете в общем workspace с другими участниками.
</Note>

<div id="choose-access-when-you-publish">
  ## Выберите уровень доступа при публикации
</div>

1. Нажмите **Publish** в правом верхнем углу Project Editor или откройте **Publishing** в разделе **Replit Cloud** на панели **Tools**.
2. В разделе **Кто может открывать ваше приложение** выберите **Public**, **Password protected**, **Workspace only** или **только по приглашению**.
3. Нажмите **Publish**.

<Info>
  У Scheduled Deployments нет параметров доступа, так как они не отдают веб-страницу.
</Info>

<div id="change-access-for-a-live-app">
  ## Изменение доступа к опубликованному приложению
</div>

<Note>
  Чтобы изменить доступ, сначала нужно отменить публикацию приложения. Сделайте это в инструменте Publishing, выберите другой вариант в разделе **Кто может открывать ваше приложение** и опубликуйте приложение заново.
</Note>

<div id="manage-whos-invited">
  ## Управление списком приглашённых
</div>

В режиме **Только по приглашению** вы предоставляете доступ отдельным пользователям или группам в разделе управления доступом вашего workspace. У администраторов workspace доступ есть всегда. Подробнее об [управлении доступом](/ru/teams/identity-and-access-management/repl-access-management).

<Note>
  Администраторы workspace могут ограничить варианты доступа для своей организации, в том числе отключить публикацию с защитой паролем.
</Note>
