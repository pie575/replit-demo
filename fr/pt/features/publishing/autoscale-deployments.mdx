Les déploiements Autoscale s&#39;exécutent sur des ressources de calcul cloud qui s&#39;adaptent à la hausse comme à la baisse pour gérer efficacement le trafic réseau et la charge de travail de votre Replit App. Lorsque votre app est très sollicitée, l&#39;autoscaling ajoute des serveurs pour absorber la charge. Lorsqu&#39;elle est inactive, il réduit le nombre de serveurs jusqu&#39;à zéro afin de réduire vos coûts.

Les déploiements Autoscale conviennent particulièrement aux cas d&#39;usage suivants :

* Applications web soumises à des charges de travail et à un trafic variables, comme les sites d&#39;e-commerce
* API et services

<div id="recursos">
  ## Fonctionnalités
</div>

Le déploiement Autoscale inclut les fonctionnalités suivantes :

* **Mise à l&#39;échelle automatique des ressources** : ajuste automatiquement les ressources en fonction du trafic afin d&#39;optimiser les coûts.
* **Domaines personnalisés** : configurez un domaine personnalisé ou utilisez une URL `<nom-de-l-app>.replit.app` pour accéder à votre app.
* **Limites configurables** : définissez le nombre maximal d&#39;instances jusqu&#39;auquel votre app publiée peut monter en charge.
* **Capacité machine flexible** : choisissez la configuration de CPU et de RAM adaptée aux besoins de votre app.
* **Surveillance** : consultez les logs et suivez l&#39;état de votre app publiée.

<div id="uso">
  ## Utilisation
</div>

Vous pouvez accéder au déploiement Autoscale depuis l&#39;outil Publishing du Project Editor.

<Accordion title="Comment accéder au déploiement Autoscale">
  Dans le **Tool dock** à gauche :

  1. Sélectionnez <img class="icon-svg" src="/assets/mirror/workspace-all-tools-button-7e378364e0b4.svg" alt="Icône de tous les outils" width="16" height="16" data-path="images/icons/workspace-all-tools-button.svg" /> **All tools** pour afficher la liste des outils du Project Editor.
  2. Sélectionnez <img class="icon-svg" src="/assets/mirror/deploy-icon-7dec74bde1ff.svg" alt="Icône de Publishing" width="16" height="16" data-path="images/icons/deploy-icon.svg" /> **Publishing**.
  3. Sélectionnez l&#39;option **Autoscale**, puis **Set up your published app**.

  Dans la **barre de recherche** :

  1. Sélectionnez la <img class="icon-svg" src="/assets/mirror/workspace-search-icon-d20ee3e562fb.svg" alt="icône de loupe" width="16" height="16" data-path="images/icons/workspace-search-icon.svg" /> loupe en haut pour ouvrir l&#39;outil de recherche

<div id="capacidade-da-mquina">
  ## Capacité de la machine
</div>

Sélectionnez **Edit** pour afficher et définir les options de capacité de la machine. Utilisez les curseurs pour choisir la configuration de CPU et de RAM
de chaque instance de serveur de l&#39;app publiée.

Le coût en **compute units** de la configuration s&#39;affiche sur la ligne **Total per machine**.
Une compute unit est une unité de mesure des ressources de calcul en nuage, basée sur la configuration de mémoire et de CPU de la machine.

Pour en savoir plus sur le calcul du coût à partir des compute units, consultez [Compute Units](/fr/pt/billing/about-usage-based-billing#2-compute-units).

<div id="nmero-mximo-de-mquinas">
  ## Nombre maximal de machines
</div>

Utilisez le curseur pour ajuster le nombre maximal de machines. Ce nombre constitue la limite supérieure d&#39;instances
de serveur que l&#39;autoscaling peut allouer lorsqu&#39;il détermine que votre app est fortement sollicitée.

La ligne du dessous affiche l&#39;équivalent en compute units, calculé selon la formule suivante :

`Nombre de machines * compute units par machine`
