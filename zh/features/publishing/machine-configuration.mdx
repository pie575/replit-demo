机器配置决定了运行已发布应用的服务器性能。Replit 会选用合理的默认值，因此大多数用户无需改动。如果应用在高负载下响应变慢，或需要在内存中处理大量数据，可以考虑使用性能更高的配置。

如需更改，请打开 Publishing 工具，选择 **Adjust settings**，然后点击 **Machine configuration** 旁的 **Edit**。

<div id="the-settings">
  ## 各项设置
</div>

* **CPU**：每台服务器能同时处理的工作量。当很多人同时使用你的应用时，vCPU 越多越有帮助。
* **内存 (RAM)**：应用可在内存中保存的数据量。处理大文件、媒体或数据密集型任务时，内存越大越有帮助。
* **最大机器数**：仅适用于 Autoscale。应用繁忙时 Replit 最多可添加的服务器数量。应用的扩容永远不会超过这一数量，因此也就限定了你的费用上限。

<div id="what-it-costs">
  ## 费用说明
</div>

配置时，该面板会显示两个数值：

* **每台机器**：按你所选配置计算的单台服务器每小时费用。
* **流量峰值时**：当应用繁忙到用满上限数量的所有机器时，每小时的费用。

费用以计算单元衡量，这是一种基于你所选 CPU 和内存的云计算资源单位。要查看当前费率及用量的计费方式，请参阅[按用量计费](/zh/billing/about-usage-based-billing#2-compute-units)。

<div id="how-billing-differs-by-deployment-type">
  ## 不同部署类型的计费差异
</div>

同样的配置，在不同 [部署类型](/zh/features/publishing/deployment-types) 下计费方式也不同：

* **Autoscale**：仅在处理请求期间计费。应用空闲时会缩容到零，不产生运行费用。
* **Reserved VM**：服务器始终在线，因此你按所选配置支付固定的月度费用。
* **Static**：没有机器运行你的站点，因此不涉及机器配置。
* **Scheduled**：仅在每次计划运行期间为机器付费。

<div id="apply-your-changes">
  ## 应用你的更改
</div>

更改配置后，请再次发布你的应用。新的机器设置将在新的部署中生效。
