---
title: "修复使用共享数据库的已发布应用"
description: "分步说明：如何更新仍在使用最初为其他应用创建的数据库的已发布应用。"
---

部分较早发布的应用可能仍连接着最初为另一个应用创建的开发数据库。

这种情况多见于在 Replit 上 fork 或 remix 而来的较早应用。在旧版 Neon 系统中，fork 出来的应用会继续沿用原应用的数据库连接。随着 Replit 全面隔离开发数据库与生产数据库，较早的共享开发数据库正在被移除，已发布的应用需要迁移到各自的生产数据库。

如果你的已发布应用出现数据库连接错误，或者 Secrets 面板中的 `DATABASE_URL` 仍指向 `neon.tech`，请参考本指南。

<Warning>
  较早的共享数据库将于 **2026 年 6 月 8 日**停用。请在该日期前更新你的已发布应用，以免出现停机或永久性数据丢失。
</Warning>

<div id="antes-de-comear">
  ## 开始之前
</div>

已发布的应用需要有自己的**生产数据库**。**Database** 面板中显示的开发数据库不应直接供已发布的应用使用。

<Frame>
  <img src="/assets/mirror/dev-database-5c024a6c134e.png" alt="显示开发数据库的数据库面板" width="955" height="767" data-path="images/databases/shared-database-migration/dev-database.png" />
</Frame>

要解决这个问题，请先确认你属于以下哪种情况：

* **情况 1：**你需要的数据已经在应用 **Database** 面板显示的数据库中。
* **情况 2：****Database** 面板没有显示你需要的数据，因为已发布的应用仍在使用较旧的共享开发数据库。

<div id="como-saber-se-o-seu-app-publicado-est-usando-um-banco-de-dados-compartilhado">
  ## 如何判断你已发布的应用是否在使用共享数据库？
</div>

如果符合以下任一情况，说明你已发布的应用受到了影响：

* 数据库更新后，你已发布的应用出现数据库连接错误
* 你的应用是在 **2026 年 1 月 9 日之前**从另一个带有数据库的应用 Remix 而来的

<div id="como-verificar-se-o-seu-app-publicado-est-usando-o-banco-de-dados-compartilhado-do-app-de-origem">
  ## 如何检查已发布的应用是否在使用源应用的共享数据库？
</div>

<div id="passo-1-abra-o-painel-database-no-app-de-origem">
  ### 第 1 步：在源应用中打开 Database 面板
</div>

<Frame>
  <img src="/assets/mirror/secret-pane-showing-secrets-763dd4c4845f.png" alt="显示 DATABASE_URL 的 Secrets 面板" width="792" height="418" data-path="images/databases/shared-database-migration/secret-pane-showing-secrets.png" />
</Frame>

获取 `NEON_DATABASE_URL` 的值；如果没有 `NEON_DATABASE_URL`，则获取 `DATABASE_URL` 的值。

<Info>
  并非每个受影响的应用都有 `NEON_DATABASE_URL`。如果缺少该值，通常意味着你应使用已发布应用的 Secrets 中当前的 `DATABASE_URL`，前提是它仍指向 `neon.tech`。
</Info>

<div id="passo-2-abra-o-painel-publish-no-app-publicado">
  ### 第 2 步：在已发布的应用中打开 Publish 面板
</div>

<Frame>
  <img src="/assets/mirror/production-app-secrets-e4da45c53e36.png" alt="已发布应用的 Secrets 中显示 DATABASE_URL" width="1385" height="1225" data-path="images/databases/shared-database-migration/production-app-secrets.png" />
</Frame>

要查看已发布应用的数据库 URL：

1. 在 Replit 中打开你的应用
2. 打开 **Publishing** 面板
3. 打开 **Adjust Settings**
4. 打开 **Secrets**
5. 查找 `DATABASE_URL`

<div id="passo-3-compare-a-url-do-banco-de-dados-do-app-de-origem-no-passo-1-com-a-do-app-remixado-no-passo-2">
  ### 步骤 3：将步骤 1 中源应用的数据库 URL 与步骤 2 中 Remix 应用的数据库 URL 进行对比
</div>

如果两者相同，说明你已发布的应用正在使用源应用共享的 Neon 开发数据库。

<div id="como-copiar-dados-do-app-de-origem-para-o-app-publicado">
  ## 如何将数据从源应用复制到已发布的应用？
</div>

确认已发布的应用正在使用源应用的共享开发数据库后，下一步就是将所需数据迁移到已发布的应用中。这里有两种情况：

* 情况 1：已发布应用的 Database 面板中已有所需数据。
* 情况 2：已发布应用的 Database 面板中没有所需数据。

<div id="caso-1-o-painel-database-j-mostra-os-dados-que-voc-precisa">
  ### 情况 1：Database 面板已显示你需要的数据
</div>

如果你需要的数据已经显示在应用的 **Database** 面板中，那么这是最简单的方式。

<div id="passo-1-confirme-que-os-dados-esto-presentes">
  #### 第 1 步：确认数据已存在
</div>

<Frame>
  <img src="/assets/mirror/my-data-12834f2ebfd6.png" alt="数据库面板中显示 my data 的数据行" width="865" height="454" data-path="images/databases/shared-database-migration/my-data.png" />
</Frame>

在已发布的应用中打开 **Database** 面板，确认所需的表和数据都在其中。

如果在 Database 面板中看不到所需的数据，请就此停下。你需要按照[情况 2](#caso-2-o-painel-database-no-app-publicado-não-mostra-os-dados-que-você-precisa) 的步骤来正确迁移数据。

<div id="passo-2-publique-ou-republique-com-um-banco-de-dados-de-produo">
  #### 第 2 步：使用生产数据库发布或重新发布
</div>

1. 在 Project Editor 中打开你的应用
2. 选择 **Publish** 或 **Republish**
3. 启用 **Create production database**
4. 启用 **Set up your production database with your current development data**
5. 完成发布流程

发布时会创建已发布应用的新版本，并自动将其 `DATABASE_URL` 指向新的生产数据库。在此流程中，你无需手动更新该 secret。

<Frame>
  <img src="/assets/mirror/production-database-settings-8855bf453da9.png" alt="显示 Create production database 选项的发布设置" width="1406" height="1207" data-path="images/databases/shared-database-migration/production-database-settings.png" />
</Frame>

<Warning>
  复制到生产环境会覆盖已有的生产数据。有关恢复或管理生产数据库的更多详情，请参阅 [Production
  Databases](/zh/pt/features/data-and-storage/development-and-production)。
</Warning>

<div id="passo-3-verifique-o-app-publicado">
  #### 第 3 步：验证已发布的应用
</div>

打开已发布的应用，确认数据可以正常访问、应用运行正常。

<div id="caso-2-o-painel-database-no-app-publicado-no-mostra-os-dados-que-voc-precisa">
  ### 情况 2：已发布应用的 Database 面板中未显示你需要的数据
</div>

如果在已发布应用的 **Database** 面板中看不到所需数据，请按以下步骤导出数据。

如果你的已发布应用仍连接着另一个应用的数据库，Database 面板中会显示 &quot;external database detected&quot; 提示。

<Frame>
  <img src="/assets/mirror/external-database-detected-489d99632e74.png" alt="数据库面板显示 external database detected" width="1403" height="1208" data-path="images/databases/shared-database-migration/external-database-detected.png" />
</Frame>

<Warning>
  如果仍有用户在使用你的应用并保存新数据，请在导出数据前安排一个短暂的维护窗口。
</Warning>

<div id="passo-1-exporte-os-dados-do-banco-de-dados-antigo">
  #### 第 1 步：从旧数据库导出数据
</div>

<Frame>
  <img src="/assets/mirror/pg-dump-example-54c6c790ccb1.png" alt="pg_dump 示例" width="1252" height="450" data-path="images/databases/shared-database-migration/pg-dump-example.png" />
</Frame>

在 Project Editor 中打开 **Shell** 并运行以下命令：

```bash theme={null}
pg_dump -Fc "database_url" --no-owner --no-privileges -f backup.dump
```

`database_url` 是你在[步骤 1：在源应用中打开 Database 面板](#passo-1-abra-o-painel-database-no-app-de-origem)中获取的数据库 URL。

<div id="passo-2-remova-o-database_url-antigo-dos-secrets-do-seu-app">
  ### 第 2 步：从应用的 Secrets 中删除旧的 `DATABASE_URL`
</div>

<Frame>
  <img src="/assets/mirror/secret-pane-eb253120f8a6.png" alt="Secrets 面板示例" width="1410" height="1184" data-path="images/databases/shared-database-migration/secret-pane.png" />
</Frame>

1. 在 Project Editor 中打开 **Secrets** 工具
2. 找到旧的 `DATABASE_URL`
3. 将其删除
4. 刷新页面或重新打开 **Database** 面板

完成后，你的应用就不会再指向旧的共享数据库，而是重新使用当前的开发数据库。

<div id="passo-3-importe-os-dados-para-o-banco-de-dados-de-desenvolvimento-atual-do-seu-app">
  ### 第 3 步：将数据导入应用当前的开发数据库
</div>

<Frame>
  <img src="/assets/mirror/pg-restore-example-409ae4d7bf09.png" alt="pg_restore 示例" width="802" height="426" data-path="images/databases/shared-database-migration/pg-restore-example.png" />
</Frame>

删除旧的 `DATABASE_URL` secret 后，应用当前的开发数据库应会在 Project Editor 中重新以 `$DATABASE_URL` 的形式提供。

返回 Project Editor 中的 **Shell**，运行：

```bash theme={null}
pg_restore --clean --if-exists --single-transaction --no-owner --no-privileges --exit-on-error -d "$DATABASE_URL" backup.dump
```

这会将导出的数据加载到您应用当前的开发数据库中。

<div id="passo-5-siga-o-caso-1-para-publicar-ou-republicar-com-um-banco-de-dados-de-produo">
  ### 步骤 5：按照情况 1 使用生产数据库发布或重新发布
</div>

当 **Database** 面板显示正确的数据后，请按照[情况 1](#caso-1-o-painel-database-já-mostra-os-dados-que-você-precisa) 的说明，使用 **Create production database** 发布或重新发布，并将这些数据复制到生产环境。

<div id="passo-6-verifique-o-app-publicado">
  ### 第 6 步：验证已发布的应用
</div>

<Frame>
  <img src="/assets/mirror/successful-export-bfb997304cc1.png" alt="导出成功" width="965" height="554" data-path="images/databases/shared-database-migration/successful-export.png" />
</Frame>

打开已发布的应用，确认数据可以正常访问，且应用运行正常。

<div id="soluo-de-problemas">
  ## 故障排查
</div>

<div id="a-importao-falha-porque-as-tabelas-j-existem">
  ### 导入失败：表已存在
</div>

上述 `pg_restore --clean --if-exists` 命令会在恢复之前，先删除并重新创建转储文件中对应的对象。

<div id="a-importao-falha-com-erros-de-funo-role-ou-poltica">
  ### 导入失败并报角色 (role) 或策略错误
</div>

如果你的数据库使用了自定义 PostgreSQL 角色 (roles) 或基于角色的策略，导入可能会失败，因为这些角色在新数据库中尚不存在。

Replit 迁移到 Helium 的自动流程会在恢复前尝试重建角色存根，而上述手动流程不会。如果你在执行 `pg_restore` 时遇到与角色相关的错误，请[联系支持团队](https://replit.com/support)寻求帮助。

<div id="eu-j-corrigi-o-app">
  ### 我已经修复了应用
</div>

如果你已发布的应用拥有自己的生产数据库且运行正常，则无需再做任何操作。

<div id="precisa-de-mais-ajuda">
  ## 需要更多帮助？
</div>

如果你不确定自己的应用属于哪种情况，或在迁移过程中遇到问题，请[联系支持团队](https://replit.com/support)。
